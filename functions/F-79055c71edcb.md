# F-79055c71edcb

## Purpose

F-79055c71edcb attempts to obtain a 20-byte object, acquire two subordinate values, and perform two ordered operations using those values and the first two caller-supplied arguments. It stores the third argument in the object and returns the object’s address only if every explicitly checked prerequisite succeeds.

The fourth argument is forwarded twice to the initial acquisition dependency. It is not directly stored in the object by this function.

The established success criterion is entirely return-value based: the initial acquisition and each of four subsequent checked dependency calls must return a nonzero value. Failure of the initial acquisition takes a reporting path. Failure after acquisition takes a cleanup path. Both paths return zero if their invoked dependencies return normally.

The apparent intent is a constructor-like operation with rollback on partial failure. That interpretation does not establish allocation ownership, initialization semantics, subordinate-resource ownership, or cleanup completeness.

The body does not directly dereference these caller-supplied arguments. It does not validate their ranges, interpret their signedness, or establish whether they represent addresses, handles, flags, or ordinary scalar values. Dependencies may impose additional requirements.

### Output

The result is represented as a 32-bit integer:

- **Zero:** the initial acquisition returned zero, or a later checked dependency returned zero and the failure path completed.
- **Nonzero:** the original nonzero result from F-43da6b23bd44, after the success-path store at offset 12.

The nonzero result is used as an address within this function. A caller treating it as an integer must preserve its full 32-bit representation; the body does not require a positive signed result.

No distinct error code is returned for different failure stages.

## Behavior

### Initial acquisition

The first observable dependency invocation is F-43da6b23bd44 with five arguments, in this order:

1. The value 20.
2. Zero.
3. Zero.
4. The fourth caller argument.
5. The fourth caller argument again.

The two final arguments contain identical 32-bit values. Their semantic roles are unknown.

If the result is zero, F-79055c71edcb invokes F-4fc89ec41a6d with the five values 3, 102, 65, 0, and 0, in that order. It then returns zero if that dependency returns normally. It does not invoke the post-acquisition external operation, acquire subordinate values, or invoke F-3eadc90e0ec1 on this path.

A nonzero acquisition result is retained as the object address for subsequent direct accesses, cleanup, and the successful return.

### External operation before field construction

Immediately after a successful acquisition, the function invokes an external dependency with the object address and the value 20.

Its return value is not checked or otherwise used. The supplied material does not establish that this operation clears memory, initializes fields, or preserves the acquired region’s contents. Those effects must not be assumed from its position or argument shape.

For reference, this specification labels that dependency **F-external-01**. This is a document-local opaque label; no authoritative dependency ID was supplied for it.

### First subordinate value

After the external operation returns, F-7d962cda8fd4 is called without explicit arguments.

Its 32-bit result is written to the object at byte offset 4. The write occurs even when the result is zero. The function then checks that returned value.

If it is zero, the function invokes F-3eadc90e0ec1 with the original object address and returns zero if cleanup returns normally. No second F-7d962cda8fd4 call occurs on this path.

### Second subordinate value

If the first subordinate result is nonzero, F-7d962cda8fd4 is called a second time, again without explicit arguments.

Its 32-bit result is written to the object at byte offset 8, including when that result is zero. The function checks this returned value.

If it is zero, the function invokes F-3eadc90e0ec1 with the original object address and returns zero if cleanup returns normally. Neither F-cec6695e396c call occurs on this path.

The success check for the first subordinate value is not repeated after the second acquisition. In particular, the second acquisition’s success does not establish that the field at offset 4 still contains the original first result.

### Ordered subordinate operations

If both subordinate acquisitions returned nonzero, the function reads the 32-bit word currently stored at object offset 4. It passes that loaded value and the first caller argument to F-cec6695e396c.

If this call returns zero, the function skips the second F-cec6695e396c call, invokes F-3eadc90e0ec1 with the object address, and returns zero if cleanup returns normally.

If the first call returns nonzero, the function then reads the 32-bit word currently stored at object offset 8. It passes that loaded value and the second caller argument to F-cec6695e396c.

If this second call returns zero, the function invokes F-3eadc90e0ec1 with the object address and returns zero if cleanup returns normally.

These argument reads are consequential:

- The first operation receives the field value read **after** the second subordinate acquisition.
- The second operation receives the field value read **after** the first operation.
- Neither field is revalidated for nonzero at the point of use.
- A dependency that changes either field through shared state or another alias can therefore affect the value passed onward.

A contract that always substitutes the originally returned subordinate values would be stronger than the supplied evidence supports.

### Successful completion

Only after both F-cec6695e396c calls return nonzero does the function write the third caller argument to object offset 12.

It then returns the original object address. There is no subsequent dependency call or explicit cleanup on this path.

The final store is unconditional once that point is reached. It writes all 32 bits, including a zero value, and replaces whatever value previously occupied that field.

### Arithmetic and checks

The function uses fixed address displacements of 4, 8, and 12 bytes. It performs no caller-controlled size arithmetic, length multiplication, or indexed traversal.

All checked dependency results are tested only for equality or inequality with zero. No positive-range requirement or interpretation of a nonzero result as a particular error code is established.

## Side effects

The established direct memory effects are the ordered 32-bit stores at offsets 4 and 8, followed conditionally by the store at offset 12. The corresponding reloads at offsets 4 and 8 occur only when their operation stages are reached.

The function also invokes dependencies that may have additional memory, resource, global-state, reporting, or control-flow effects. Their internals are not supplied. In particular:

- The initial acquisition is not proven to be a heap allocation.
- The external operation is not proven to zero the object.
- The subordinate acquisitions are not proven to allocate independently owned resources.
- F-cec6695e396c is not proven to copy, retain, consume, or release either argument.
- F-3eadc90e0ec1 is not proven to free the object or release subordinate resources.
- F-4fc89ec41a6d is not proven to be a returning diagnostic rather than a terminating error mechanism.

On a post-acquisition failure, cleanup is invoked once with the original object address, irrespective of how far construction progressed. The visible body performs no separate subordinate-release calls and no explicit restoration of earlier field values.

On success, the absence of a cleanup call establishes only this function’s control flow. It does not independently establish an ownership-transfer protocol or the validity duration of the returned address.

## Acceptance examples

These are conditional acceptance scenarios derived from static evidence, not runtime test results.

1. **Initial acquisition fails.**  
   If F-43da6b23bd44 returns zero, the reporting dependency receives exactly 3, 102, 65, 0, 0. If it returns normally, the function returns zero. No cleanup dependency is called.

2. **First subordinate acquisition fails.**  
   If initial acquisition succeeds and the first F-7d962cda8fd4 result is zero, zero is written at offset 4 before cleanup is invoked. There is no second subordinate acquisition and no F-cec6695e396c call.

3. **Second subordinate acquisition fails.**  
   If the first subordinate result is nonzero and the second is zero, the first result has already been written at offset 4, and zero is written at offset 8. Cleanup follows. Offset 12 is not directly written by this function.

4. **First subordinate operation rejects its inputs.**  
   If both acquisitions succeed but the first F-cec6695e396c call returns zero, the second operation is omitted. Cleanup follows, and the function returns zero if cleanup returns.

5. **Second subordinate operation rejects its inputs.**  
   If the first operation succeeds and the second returns zero, both operations have occurred in order. The success-field store at offset 12 does not occur; cleanup follows.

6. **Complete success without intervening field mutation.**  
   If the acquisitions yield an object and two nonzero subordinate values, all dependencies return normally, neither relevant field changes between its store and reload, and both operations return nonzero, the operations receive the corresponding subordinate values and caller arguments. The third argument is then stored at offset 12, and the original object address is returned.

7. **Intervening mutation changes an operation argument.**  
   If the second subordinate acquisition changes offset 4, the first operation receives the changed field value. If the first operation changes offset 8 and returns nonzero, the second operation receives that changed value. This remains true even if the changed value is zero.

8. **Zero third argument on success.**  
   A zero third argument does not cause failure. After both operations succeed, zero is stored at offset 12 and the nonzero object address is returned.
