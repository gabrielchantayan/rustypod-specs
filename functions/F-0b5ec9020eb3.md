## Behavior

### Established operation order

The following sequence is visible:

1. Store the one-byte value 1 at **P + 13**.
2. Read the four-byte value at **P** and use it as an address.
3. Read an integer from that address and use it as the base for dispatch lookup.
4. Read the callable target from storage at that base plus 304 bytes.
5. Invoke the resolved target.
6. Return if the invocation returns normally.

The byte write precedes the reads used to resolve the target. The supplied representation does not show those reads being cached before the write.

There are two levels of data indirection before the callable-pointer lookup: the value at **P** identifies storage containing the dispatch base; it is not itself used directly as that base.

### Byte update

The store sets the destination byte to exactly 1. It does not visibly inspect the previous value, preserve selected bits, increment it, or condition the store on its contents.

The same byte value is written whether the previous byte was zero, one, or another value. No early return based on that byte is visible. An already-set byte therefore does not suppress dispatch.

The direct write is one byte wide. No direct write to neighboring bytes appears. This does not constrain writes performed by the invoked target.

### Dispatch and invocation
