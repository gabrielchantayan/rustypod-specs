# F-b11d9c4161cd

## Purpose

F-b11d9c4161cd performs an ordered sequence of preparation, value acquisition, value transformation, object acquisition, and two indirect operations.

The first indirect operation receives the acquired object reference even when that reference is null. The second indirect operation occurs only when the acquired reference is non-null and is dispatched through that reference.

The established behavior is the ordering and argument flow described below. Interpreting the sequence as registration followed by release, attachment followed by cleanup, or any other lifecycle protocol would require dependency contracts that are not supplied.

### Receiver dispatch

After object acquisition returns, the function performs an indirect operation through a receiver obtained from global state.

The receiver-base global is consulted at this stage, rather than before the acquisition sequence. Therefore, mutations to that global by any earlier dependency can affect this dispatch.

The visible receiver layout is:

- Read a base address from the receiver-base global.
- Access the receiver-reference field at base address plus **4 bytes**.
- Obtain a dispatch-table address from the receiver’s first field.
- Obtain the indirect target from dispatch-table offset **48 bytes**.

The indirect operation receives:

1. The receiver reference.
2. The acquired object reference.

**This operation is attempted before the acquired object is checked for null.** Null is therefore a possible second argument. There is no alternate local path that skips the receiver operation merely because acquisition returned null.

The expression supplying this call refers to the receiver state both to select the target and to supply the receiver argument. The supplied material does not establish an ordering between those reads or guarantee that they are a single cached read. In a stable, non-concurrently modified memory state, they identify the same receiver. Stronger behavior under concurrent mutation is not established.

### Null branch and object dispatch

After the receiver operation returns, the retained acquired reference is compared with null.

- **If null:** the function returns normally without attempting dispatch through the acquired object.
- **If non-null:** the function obtains a dispatch-table address from the object’s first field, selects the callable entry at byte offset **4**, and invokes it with the acquired reference as its sole explicit argument. If that operation returns normally, this function returns.

The null check concerns the retained reference. It is not a check of the receiver operation’s result, nor does it validate the referenced memory.

The receiver operation may have modified the acquired object or other reachable state. The final dispatch reads the object’s dispatch information only after that operation returns. There is no visible snapshot of the object’s dispatch table taken before the receiver operation.
