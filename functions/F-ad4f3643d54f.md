# F-ad4f3643d54f

## Purpose

F-ad4f3643d54f coordinates repeated subordinate operations using a forward-moving address while recording descriptors in a backward-growing area of a caller-supplied region. On selected exit paths, it also issues four trailer stores.

Established behavior includes:

- Rejecting specified entry conditions with status 3.
- Checking a caller-supplied cancellation byte before each admitted operation.
- Supplying a writable 32-bit quantity to the subordinate operation.
- Emitting two descriptors after a zero-status operation, irrespective of the reported quantity.
- Conditionally emitting zero, one, or two descriptors after a nonzero-status operation.
- Omitting trailer generation when entry is rejected or the subordinate operation returns status 3.
- Returning the original region-address value and final status in one 64-bit result.

The descriptors appear intended to identify fixed-size units and associate them with position-like values. This interpretation is inferred; the meanings of the units, quantities, and position-like values are not established.

The contract distinguishes **stores issued by this function** from **memory contents retained at return**. Dependencies have unspecified memory effects. In particular, the final dependency call occurs after three trailer stores and may alter those words or earlier descriptors.

## Interface

### Inputs

The function takes five inputs:

| Input | Width and interpretation | Use |
|---|---|---|
| Context address | 32-bit address | Locates repeatedly read context fields |
| Region address | 32-bit address value | Initial forward address, output-layout base, and upper half of the return value |
| Extent | Signed 32-bit integer | Endpoint calculation and initial remaining-capacity calculation |
| Gate | 32-bit integer | Must equal zero for processing to begin |
| Cancellation-byte address | Address of a readable byte | Read at the start of each admitted iteration |

The context fields accessed directly are:

| Byte offset | Width | Observed use |
|---|---:|---|
| 0x10 | 32 bits | Loop threshold, descriptor size, second-unit address displacement, and quantity comparisons |
| 0x14 | 32 bits | Displacement added to an iteration’s position-like value |
| 0x24 | 32 bits | Argument to F-1bba37aa477e and F-4e5f0df266e7 |

These are separate reads at their respective execution points, not one immutable context snapshot. The field at offset 0x10 is interpreted as unsigned for the first error-path quantity comparison, but participates in signed-looking multiplication and addition elsewhere.

### Return value

The result is 64 bits:

| Bits | Contents |
|---|---|
| 63–32 | Original region-address value |
| 31–0 | Final 32-bit status |

The upper half is retained even on rejection or subordinate failure.

Status sources are:

- **0:** initial status and subordinate success.
- **2:** cancellation when the checked byte equals exactly 1.
- **3:** entry rejection or a subordinate result of 3.
- **Other nonzero values:** subordinate results propagated without remapping.

A returned status alone does not identify the path taken. For example, subordinate status 2 and cancellation both return 2 but have different preceding calls and possible descriptor stores.

## Behavior

### Entry validation

The function initializes its descriptor count, status, and writable subordinate quantity to zero. The quantity is initialized once, not before every subordinate call.

Entry checks short-circuit in this order:

1. A zero region address rejects entry.
2. Otherwise, a nonzero gate rejects entry.
3. Otherwise, the function reads context offset 0x24 and calls F-1bba37aa477e with that 32-bit value.
4. A zero dependency result rejects entry; any nonzero result permits processing.

Entry rejection returns status 3 without this function’s descriptor or trailer stores. Rejection by either of the first two checks also prevents the validation call.

The validation dependency’s own effects are unknown.

### Endpoint and initial state

After validation succeeds, the logical endpoint is:

**Region address + 4 × truncation-toward-zero(extent ÷ 4).**

For nonnegative extents, this discards the final zero to three bytes of the extent. It does not align the region address independently.

For negative extents, division truncates toward zero rather than toward negative infinity. Negative extents are not rejected.

The initial descriptor position-word address is endpoint minus 20 bytes. The four trailer words occupy endpoint minus 16 through endpoint minus 1.

The function then freshly reads context offset 0x24 and calls F-4e5f0df266e7. Its 32-bit result is retained as the baseline.

The forward address starts at the original region address. The remaining-capacity quantity is unsigned 32-bit storage initialized from extent minus 16. The signed subtraction’s overflow limits remain relevant before conversion to that unsigned quantity.

### Loop admission

Before each iteration, the function rereads context offset 0x10 and forms a threshold from twice that field plus 24.

An iteration is admitted only when:

**Unsigned remaining quantity > threshold.**

Equality prevents entry. No cancellation-byte read occurs when the condition fails.

The threshold’s addition and comparison are unsigned, but its multiplication is expressed using a signed 32-bit field. The supplied representation does not establish portable behavior when that multiplication overflows.

### Cancellation and operation calls

At the start of an admitted iteration, the function reads one byte from the cancellation-byte address:

- Exactly 1 sets status 2 and exits the loop.
- Every other byte permits the operation to proceed.

Cancellation prevents both dependency calls belonging to that iteration. It does not prevent trailer generation. There is no additional cancellation check during the operation or immediately before the trailer.

For an uncancelled iteration, the function:

1. Freshly reads context offset 0x24.
2. Calls F-4e5f0df266e7 and retains its result as the iteration’s position-like value.
3. Calls F-def720e163a5 with the context address, current forward address, and address of the writable 32-bit subordinate quantity.
4. Uses that call’s return value as status.

The writable quantity is not reset between calls. If a call leaves it unchanged, decisions use its retained value. No quantity constraint is enforced for a zero-status result.

### Descriptor layout

Each descriptor consists of three 32-bit words:

| Offset within descriptor | Contents |
|---|---|
| 0 | Associated forward address |
| 4 | Freshly read context field at offset 0x10 |
| 8 | Position-like value |

Stores within each descriptor occur in reverse address order: position-like word, size word, then address word.

For each emitted pair:

- The first descriptor occupies the higher-addressed slot.
- The second occupies the immediately preceding 12-byte slot.
- Increasing-address traversal therefore encounters the second descriptor first.

For the first pair, the first descriptor spans endpoint minus 28 through endpoint minus 17. The second spans endpoint minus 40 through endpoint minus 29.

These placements describe this function’s accesses. They do not prove that the region is large enough, that forward writes by dependencies cannot overlap descriptors, or that descriptor contents remain unchanged afterward.

### Zero-status operation

A zero subordinate status unconditionally causes two descriptor emissions.

The ordered stores are:

1. First descriptor’s position-like word: the saved iteration value.
2. First descriptor’s size word: a fresh read of context offset 0x10.
3. First descriptor’s address word: the current forward address.
4. Second descriptor’s position-like word: the saved iteration value plus a fresh read of context offset 0x14.
5. Second descriptor’s size word: another read of context offset 0x10.
6. Second descriptor’s address word: the current forward address plus another read of context offset 0x10.

The descriptor count increases by two after the first position-like store and before the first size store.

The descriptor cursor then moves backward by 24 bytes. The forward address advances by the subordinate quantity, not by the recorded descriptor sizes.

At the iteration update, the unsigned remaining quantity is reduced first by the subordinate quantity and then by 24. These unsigned subtractions wrap modulo \(2^{32}\). The next loop admission rereads the size field.

Consequently, a zero-status operation reporting zero quantity still emits two descriptors and subtracts 24 from remaining-capacity accounting. An excessive quantity can wrap that accounting rather than terminate processing safely.

### Nonzero-status operation

For a nonzero subordinate result, the function first freshly reads context offset 0x10 and compares it with the subordinate quantity as unsigned 32-bit values.

- If the quantity is smaller, no descriptor is emitted.
- Otherwise, the first descriptor is emitted and the resulting count increases by one.

The first descriptor’s store order and values match the first descriptor on the success path. Its size is read again after its position-like store; it need not equal the field value used for admission.

After those first-descriptor stores, the function freshly reads context offset 0x10 and tests whether twice that value equals the subordinate quantity.

If equal, it emits the second descriptor using the same ordered values as on the success path, and the resulting count increases by two in total. The multiplication has the same unresolved signed-overflow concern as other doubled-field expressions.

A quantity greater than twice a stable size does not cause additional descriptors. Exact equality, not a greater-than-or-equal test, controls the second descriptor.

After descriptor handling:

- Status 3 returns immediately, with no trailer generation and no final F-4e5f0df266e7 call.
- Every other nonzero status exits the loop and proceeds to trailer generation.

This path does not perform the success-path cursor movement, forward-address advance, or remaining-capacity decrement.

### Trailer generation

Trailer generation is reached after:

- A failed loop-admission condition, including before the first iteration.
- Cancellation.
- A subordinate result other than zero or 3.

The ordered actions are:

| Order | Action |
|---:|---|
| 1 | Store 32-bit zero at endpoint minus 4 |
| 2 | Store the 32-bit descriptor count at endpoint minus 8 |
| 3 | Store the saved 32-bit baseline at endpoint minus 12 |
| 4 | Freshly read context offset 0x24 |
| 5 | Call F-4e5f0df266e7 |
| 6 | Store its result minus the saved baseline at endpoint minus 16 |

The final subtraction is expressed using signed 32-bit values and stored as a 32-bit word. Behavior outside the representable signed range is not settled by the supplied representation.

There is no separate success check on the final query result.

Crucially, steps 1–3 do not guarantee corresponding final memory contents: the dependency call in step 5 may overwrite them, alter earlier descriptors, or otherwise affect accessible storage. If execution reaches step 6, this function subsequently issues the difference store, but does not restore the preceding three trailer words or any descriptors.

## Side effects

Direct effects consist of dependency calls, context and cancellation reads, descriptor stores, trailer stores, and exposing the address of the writable quantity to F-def720e163a5.

No direct context-field assignment is shown. Nevertheless, context fields may change through dependency effects or aliasing with output stores. Such changes can affect later reads within the same descriptor emission or trailer sequence.

The function does not clear unused descriptor space or directly initialize the forward payload area. Any payload production by the subordinate operation is dependency behavior, not established here.

Failure is not atomic:

- A subordinate status of 3 can follow descriptor stores while leaving the trailer untouched by this function.
- Other nonzero statuses can follow descriptor stores and then trigger trailer generation.
- No rollback is shown.

A claim that a trailer or descriptor “contains” particular values at return requires assumptions about valid storage, aliasing, intervening dependency writes, and external mutation. Without those assumptions, only the specified calls and ordered direct stores are established.

## Acceptance examples

These are conditional static acceptance cases, not runtime observations.

Unless stated otherwise, numerical cases assume valid disjoint storage, stable context fields, no external mutation, and arithmetic within the applicable signed ranges. **Examples asserting retained output contents additionally assume that every dependency preserves descriptor and trailer storage, including the final F-4e5f0df266e7 call.** Without that preservation assumption, the examples specify this function’s ordered stores, not guaranteed final contents.

1. **Zero-address rejection.** With region address zero, the returned upper half is zero and status is 3. No dependency is called, and this function issues no descriptor or trailer stores.

2. **Gate rejection.** With a nonzero region address and nonzero gate, the upper return half is the original address and status is 3. The validation dependency is not called.

3. **Validation rejection.** With a nonzero region address, zero gate, and a zero validation result, status is 3. No baseline query, iteration, or trailer generation follows. The validation call may itself have effects.

4. **Strict boundary.** With size 8 and extent 56, initial remaining capacity is 40 and the threshold is 40. No iteration or cancellation read occurs. The function issues trailer stores for zero, count zero, baseline, and final difference in the specified order. Under output preservation, those are the retained trailer values; status is 0.

5. **Immediate cancellation.** With size 8 and extent 128, the first iteration is admitted. A cancellation byte of 1 prevents its position query and subordinate call. Status is 2. Trailer generation issues a count-zero store; a retained count of zero additionally depends on the stated preservation assumption.

6. **One successful pair.** Let size be 8, secondary offset 100, extent 80, and cancellation byte 0. Let the baseline be 1000, iteration value 1010, subordinate status zero, and quantity 16. The function emits descriptors for the original address and original address plus 8, each of size 8, with position-like values 1010 and 1110 respectively. Remaining capacity becomes 24, preventing another iteration. If the final query returns 1025, trailer stores supply difference 25, baseline 1000, count 2, and zero. These descriptors and trailer contents are retained only under the output-preservation assumption.

7. **Partial error record.** With stable size 8, subordinate status 5, and quantity 8, one descriptor is emitted. Trailer generation issues a count-one store and status 5 is returned. The final query can otherwise overwrite that count; retained count one is conditional on preservation.

8. **Status 3 after descriptors.** With stable size 8, subordinate status 3, and quantity 16, two descriptors are emitted before returning status 3. This function performs no trailer stores and no final query on that path. It does not guarantee that dependencies left any preexisting trailer unchanged.

9. **Retained quantity.** If a successful call writes quantity 16 and a later subordinate call leaves it unchanged, with no intervening modification of that quantity, the later decision uses 16 rather than zero.

10. **Final-query overwrite.** Suppose trailer generation stores count 2, then the final F-4e5f0df266e7 call overwrites that count word with 9 and returns normally. With no subsequent overlapping write, the function does not restore 2. Its final direct trailer action writes only the difference word. This behavior is consistent with the established store order.
