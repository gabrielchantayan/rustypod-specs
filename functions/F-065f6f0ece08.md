# F-065f6f0ece08

## Purpose

F-065f6f0ece08 distributes a consecutive sequence of four-byte source words among seven destination regions described by an ordered descriptor table.

Each descriptor supplies a destination address and a signed element count. Source consumption continues across descriptors; it does not restart for each destination. A descriptor with a nonpositive count consumes no source words.

The operation is an ordered sequence of individual reads and writes, not an atomic transfer or a snapshot-based copy. Aliasing can affect subsequent source values, descriptor fields, and loop termination.

This purpose is inferred from the visible transfer pattern. No higher-level meaning for the words or destination regions is established.

## Behavior

### Base acquisition

The descriptor-table base is read first. The source base is read second. Both are retained for the rest of the invocation.

Subsequent overwriting of either global storage location does not visibly cause its base value to be reloaded. Such an overwrite can nevertheless affect other accesses if the same storage also serves as source data or descriptor data.

The function starts with no source words consumed and processes descriptor positions in increasing order.

### Descriptor traversal

Exactly seven descriptor positions are selected during normal completion, regardless of how many words earlier descriptors transfer.

On reaching a descriptor, the function reads its destination-address field once. That value remains the destination base for that descriptor. Later changes to the field do not redirect transfers already being performed for that descriptor.

The descriptor’s count is handled differently: it is read when evaluating each continuation condition. It is not captured as one fixed value on descriptor entry.

Consequently:

- The count is read even when the descriptor transfers no words.
- A stable count of zero or less causes the descriptor to be skipped.
- A stable positive count of \(n\) causes \(n\) transfers.
- A write that changes the current count can shorten or extend that descriptor’s remaining work.
- A write that changes a later descriptor can affect that descriptor when it is reached.

For a normally completed descriptor that transfers \(m\) words, its count field is read \(m+1\) times: once before each transfer and once for the final unsuccessful continuation check.

### Source consumption and destination placement

For each transfer:

- The destination position advances by one four-byte word within the current destination region.
- The source position advances by one four-byte word within the single shared source stream.
- The source word is read before its corresponding destination word is written.

The logical source-consumption counter is advanced before that transfer’s source read and destination write, but the addresses for the transfer use the preceding source position. This counter is internal; no separate externally visible progress record is shown.

Source consumption does not restart between descriptors. Destination indexing does restart at the beginning of each descriptor’s destination region.

When descriptor counts remain unchanged and all accesses complete normally, define the effective count of a descriptor as its count when positive, otherwise zero. Then:

- Descriptor 0 receives the first effective-count words.
- Descriptor 1 receives the next effective-count words.
- Each following descriptor receives the next portion of the same source sequence.
- The total number of transferred words is the sum of the seven effective counts.

This fixed-count description is conditional. It does not apply unchanged when execution modifies counts that will be read again.

### Observable access order

The visible memory-access sequence is:

1. Read the descriptor-table base.
2. Read the source base.
3. Read the current descriptor’s destination address.
4. Read that descriptor’s count.
5. If the continuation condition succeeds, read one source word and then write one destination word.
6. Read the count again before deciding whether to transfer another word.
7. After the current descriptor terminates, read the next descriptor’s destination address.

There is no visible bulk prefetch of descriptors or source words.

This order matters when regions overlap. It describes the supplied static representation; it does not establish hardware atomicity, synchronization, memory barriers, or behavior under unsynchronized concurrent modification.

### Overlap and aliasing

No overlap check or temporary buffer is visible. Earlier writes can change later reads.

Relevant cases include:

- **Destination overlaps later source words:** a later transfer can read a value written by an earlier transfer.
- **Destination overlaps the current count:** the next continuation check uses the updated count.
- **Destination overlaps the current destination-address field:** that descriptor continues using its already captured destination base.
- **Destination overlaps a later descriptor:** the later descriptor uses the fields present when it reaches the corresponding reads.
- **Destination regions overlap each other:** later transfers overwrite earlier results according to traversal order.

Thus, this operation does not provide general snapshot-copy or overlap-preserving semantics.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, addresses and arithmetic are valid, counts remain stable, and the source, destinations, table, and global storage do not overlap.

### 1. Distribution across several descriptors

Given source words \(A,B,C,D,E,F\) and descriptor counts:

\(2,0,3,-1,1,0,0\)

normal completion must produce:

- First destination: \(A,B\).
- Third destination: \(C,D,E\).
- Fifth destination: \(F\).
- No destination writes for the other descriptors.

Exactly six source words are consumed. The zero and negative counts create no gap in source consumption.

### 2. All descriptors skipped

Given seven nonpositive counts:

- All seven destination-address fields are still read.
- Each count field is read once.
- No source words are read.
- No destination words are written.

An unusable destination address does not itself cause a destination access when its count fails the initial continuation condition. Its address field must still be readable.

### 3. Source consumption continues across destinations

Given counts \(1,1,0,0,0,0,0\) and initial source words \(P,Q\):

- The first destination receives \(P\).
- The second destination receives \(Q\).

Both destinations receiving \(P\) would violate the continuous-source behavior.

### 4. Forward overlap propagates an earlier word

Given source words \(A,B,C,D\), a first-descriptor count of three, and a destination beginning one word after the source base:

- The first transfer writes \(A\) over the original \(B\).
- The second reads that newly written \(A\) and writes it over \(C\).
- The third reads the propagated \(A\) and writes it over \(D\).

The resulting four-word region is \(A,A,A,A\). Snapshot-copy behavior producing \(A,A,B,C\) would not match the visible access order.

### 5. A write shortens the current descriptor

Given:

- The current descriptor initially has count two.
- Its destination points to its own count field.
- The first source word has the signed-count representation zero.
- The access is otherwise valid.

The first transfer changes the count to zero. The next continuation check observes zero, so only one word is transferred for that descriptor.

### 6. A later descriptor is read after earlier writes

If an earlier transfer overwrites a later descriptor’s count with zero, that later descriptor must be skipped when reached, provided no intervening write changes the count again.

Using an earlier snapshot of that later count would violate the visible read timing.

### 7. Failure does not imply rollback

If a later destination write cannot complete after an earlier write succeeded, no rollback behavior is established. Acceptance criteria must not require restoration of the earlier destination contents.
