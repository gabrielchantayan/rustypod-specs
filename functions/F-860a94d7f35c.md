# F-860a94d7f35c

## Purpose

F-860a94d7f35c conditionally invokes preliminary operations associated with a supplied object, then updates accounting associated with that object’s preceding metadata and passes the metadata to a dependency.

The established behavior is a sequence of conditional calls, metadata checks, accounting writes, and further calls. The apparent intent is object release with allocation-accounting maintenance. Actual destruction, deallocation, synchronization, and ownership transfer are not established by the available evidence.

A null input is a complete no-op. A non-null input reaches a nonreturning dependency if its first metadata word is zero or has its least significant bit set. Other non-null inputs proceed without any additional visible validation.

## Interface

### Input

One 32-bit value, **P**, is used as an address.

- **P = 0:** returns without reading object memory, modifying memory, or invoking dependencies.
- **P ≠ 0:** object-relative addresses and metadata preceding P are accessed.

No length, explicit context, error-output pointer, or ownership flag is supplied.

### Output

There is no explicit return value.

Normal completion occurs after the final dependency returns. A detected metadata failure invokes F-a817d8d58c10, which is represented as nonreturning. No recoverable error result is exposed.

### Referenced layout

The visible operation uses the following object-relative locations:

| Location | Width | Interpretation established by use |
|---|---:|---|
| P + 4 | 32 bits | First nonzero/zero condition for a preliminary call |
| P + D | 32 bits | Second nonzero/zero condition for the same preliminary dependency |
| P − 8 | 32 bits | Metadata word containing validity bits and an accounting magnitude |
| P − 4 | 16 bits, unsigned | First accounting-table index |
| P − 2 | 16 bits, unsigned | Second accounting-table index |

**D** denotes an unresolved displacement represented by a symbolic value in the supplied evidence. Its numeric value, relationship to the other fields, and whether its value can vary are unknown.

A context address, **C**, is obtained through a global reference after the preliminary operations. The following locations are then used:

| Context-relative location | Width | Update |
|---|---:|---|
| C + 0x224 + 4 × first index | 32 bits | Subtract captured magnitude |
| C + 0x30c | 32 bits | Subtract captured magnitude |
| C + 0xe0 + 4 × second index | 32 bits | Subtract captured magnitude |
| C + 0x220 | 32 bits | Subtract captured magnitude |
| C + 0x310 + 4 × dependency-selected index | 32 bits | Decrement by one |
| C + 0x390 | 32 bits | Decrement by one |
| C + 8 | 32 bits | Subtract a freshly read masked metadata magnitude |

These are access locations, not proof of disjoint fields or valid table extents. Aliasing between locations is not excluded.

### Preconditions for ordinary completion

The caller and surrounding state must provide readable and writable storage for every address actually reached. In particular:

- The two preliminary condition fields must be readable.
- Metadata must be readable before P.
- The global context reference must be readable.
- Each derived accounting address must support its required read and write.
- Dependencies must satisfy their own undocumented preconditions.

No visible bounds, alignment, context-null, overflow, or counter-underflow checks enforce these conditions.

## Behavior

### 1. Null handling

If P is zero, the operation returns immediately.

The later body contains another non-null condition, but there is no visible reassignment of the local input value between the two checks. For an execution continuing beyond the initial check, that condition does not introduce a separate ordinary path.

### 2. Preliminary conditional calls

For non-null P, the operation:

1. Reads the 32-bit field at P + 4.
2. Calls F-1137792fba7d if that value is nonzero.
3. Subsequently reads the 32-bit field at P + D.
4. Calls F-1137792fba7d again if that second value is nonzero.

Both calls show no explicit arguments.

The second condition is evaluated after the first call, if that call occurs. It is not a condition captured in advance. A dependency-induced change to memory used by the second condition can therefore affect whether the second call occurs.

Two calls are possible even though both target the same dependency. No visible rule combines the conditions or limits the dependency to one invocation.

### 3. Preparation and context capture

After the conditional calls, F-2fd8826557a4 is invoked with no explicit arguments.

Only after that dependency returns does the operation read the context address C from a global reference. Consequently, a context change made by any preceding dependency can affect the context selected for accounting.

Once captured, C is retained for the remaining visible accounting and context-argument calls. The operation does not visibly reload C from the global reference.

### 4. Metadata validation

The metadata address is P − 8.

The operation first tests whether the 32-bit metadata word is zero. If it is not zero, it additionally tests whether bit 0 is set. These are distinct source-level evaluations; the evidence does not establish one shared snapshot for both tests.

Either of the following conditions invokes F-a817d8d58c10:

- The first zero test observes zero.
- The subsequent bit test observes bit 0 set.

That dependency is represented as nonreturning. No accounting writes described below precede this failure call. Preliminary dependencies and the context read have already occurred.

No other metadata bits are rejected by the visible check.

### 5. Context dependency before accounting

After validation succeeds, F-c0fc6d033caa is invoked with C as its sole visible argument.

The accounting magnitude and table indices are not captured before this call. They are read afterward. Validation therefore does not establish that the metadata used for accounting is unchanged: this dependency may modify relevant memory, and the caller performs no visible revalidation.

### 6. First four accounting updates

After F-c0fc6d033caa returns:

1. The unsigned 16-bit first index is read from P − 4.
2. The corresponding address beginning at C + 0x224 is derived using a four-byte stride.
3. The 32-bit word at P − 8 is read and masked with 0x3ffffffc to obtain a magnitude, **S**.
4. The first indexed accounting value is read, reduced by S, and written back.
5. The value at C + 0x30c is read, reduced by the same S, and written back.
6. The unsigned 16-bit second index is read from P − 2.
7. The corresponding value beginning at C + 0xe0, again using a four-byte stride, is read, reduced by S, and written back.
8. The value at C + 0x220 is read, reduced by S, and written back.

S is captured once for these four subtractions. It is not recalculated between them.

The second index is read after the first two accounting writes. If those writes alias its storage, or an external actor changes it, the later index read can observe the resulting value. Likewise, later counter reads observe earlier writes when their addresses coincide.

### 7. Count updates

F-09dcb55e8e0a is invoked with no explicit arguments. Its return value selects a four-byte-stride location beginning at C + 0x310.

The selected 32-bit value is read, decremented by one, and written back. The 32-bit value at C + 0x390 is then read, decremented by one, and written back.

No visible range check constrains the dependency-selected index. The evidence represents its return as a signed integer; whether negative or large values are possible or valid is unknown.

### 8. Final accounting update and dependency calls

After both count updates, the operation reads the metadata word at P − 8 again and masks it with 0x3ffffffc.

This newly obtained magnitude, **T**, is subtracted from the 32-bit value at C + 8. T is not required by the visible logic to equal S. In particular, F-09dcb55e8e0a executes between their reads, and intervening writes may also alias metadata.

The operation then invokes:

1. F-cc6c9b4a0f68 with C and the metadata address P − 8.
2. F-e586bff64fb7 with C.

Normal return follows the second call. No further direct access to the object or its metadata is visible after F-cc6c9b4a0f68 returns.

### Arithmetic and widths

The mask 0x3ffffffc retains bits 2 through 29. A masked magnitude is therefore a multiple of four in the inclusive range 0 through 0x3ffffffc. Bits 0, 1, 30, and 31 do not contribute to that magnitude.

Both metadata indices are unsigned 16-bit values. Their multiplication by four produces offsets from 0 through 262140, or 0x3fffc. This range alone does not establish that corresponding tables are that large.

Accounting storage and the metadata word are 32 bits. The visible arithmetic has no saturation or explicit failure branch. Interpreted as 32-bit stored bit-pattern arithmetic, subtracting from an insufficient counter wraps modulo 2³²; decrementing zero stores 0xffffffff. Signed-overflow behavior at a higher-level language boundary is not established.

Pointer additions are consistent with a 32-bit address model. Address-wrap validity and resulting memory-access behavior remain platform-dependent and undocumented.

## Side effects

### Direct effects

On a normal non-null path, seven accounting read-modify-write operations occur:

- Four magnitude subtractions using S.
- Two decrements by one.
- One magnitude subtraction using T.

These are seven ordered operations, not necessarily seven distinct destinations.

No visible write clears P, marks the object released, resets its fields, or invalidates the caller’s copy of its address.

### Dependency effects

The preliminary and subsequent dependencies may have additional side effects. Their bodies are unavailable. In particular, this contract does not assume that they:

- Preserve globals or object metadata.
- Preserve accounting storage.
- Acquire or release a lock.
- Free or retain memory.
- Transfer ownership.
- Return normally, except that F-a817d8d58c10 is expressly represented as nonreturning.

The visible updates are not transactional. No rollback is shown if a later dependency fails or an access faults after earlier changes.

### Ownership and concurrency

Passing P − 8 to F-cc6c9b4a0f68 is established; transferring ownership is not. Whether P remains usable after completion is undocumented.

No direct synchronization primitive is established. The positions of the context dependencies may suggest a protected accounting region, but their semantics are unknown. Concurrent mutation safety cannot be claimed.

## Acceptance examples

These are conditional behavioral criteria, not executed tests. Except where an example addresses mutation or aliasing, assume valid, distinct storage and dependencies that return normally without changing relevant state.

### Null input

Given P = 0, the operation returns without invoking any dependency and without reading object metadata or accounting state.

### Both preliminary conditions are true

Given nonzero P and nonzero observations at both P + 4 and P + D, F-1137792fba7d is called twice, in condition-evaluation order, before F-2fd8826557a4.

If the first call changes the second condition field to zero before it is read, only the first call occurs.

### Metadata rejection

If the first metadata test observes zero, F-a817d8d58c10 is invoked. If the zero test passes but the subsequent bit test observes an odd value, the same failure dependency is invoked.

In either case, F-c0fc6d033caa and the seven accounting updates are not reached through the represented control flow.

### Ordinary accounting

Suppose both magnitude reads observe 0x00000102. Its least significant bit is clear, and masking yields 0x100, or 256.

If the four magnitude counters initially hold 1000, 2000, 3000, and 4000, their resulting values are respectively 744, 1744, 2744, and 3744.

If the selected count and the count at C + 0x390 initially hold 9 and 12, they become 8 and 11. If C + 8 initially holds 5000, it becomes 4744.

### Valid check with zero magnitude

A metadata word of 0x00000002 passes the visible validation but produces a masked magnitude of zero.

The magnitude updates still execute as reads and writes. Their numerical values remain unchanged under the stated assumptions, while both count values are decremented.

### Different final magnitude

Suppose S is 256, and F-09dcb55e8e0a changes the metadata so that the later mask yields T = 512.

The first four magnitude subtractions use 256. The subtraction at C + 8 uses 512. No visible consistency check rejects this difference.

### Counter underflow

If a magnitude counter contains 8 and S is 16, the resulting 32-bit stored bit pattern is 0xfffffff8 under modulo-2³² arithmetic. A count decremented from zero similarly becomes 0xffffffff. Neither condition has a visible dedicated error branch.
