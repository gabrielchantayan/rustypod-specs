# F-7fb0b5d30157

## Purpose

F-7fb0b5d30157 selects and scales a quantity, publishes it through an object-associated context, obtains or reuses an associated record, and publishes a dependency-derived value. When the scaled quantity is signed-positive, it also configures a selected record and may perform link-publication writes.

The fields and calls suggest scheduling or activation behavior. These are **inferred intent**, not established domain semantics. Time units, callback semantics, synchronization, and numeric ordering are not established.

The link-publication sequence does not unconditionally insert a record into a list. Existing membership, storage aliasing, and dependency-induced changes can invalidate that interpretation. In particular, a zero marker does not prove that the record is absent from the list: a record already at the head can acquire a self-link.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Entry and result

The function accepts one 32-bit value used as the address of a primary object. The supplied representation declares no return value. Observable outcomes are dependency calls, memory reads and writes, early returns, and a possible final indirect invocation.

There is no explicit address validation. Normal execution requires every reached access to address valid storage of the required width. Dependencies must return for execution to continue beyond them. An early return avoids later direct accesses but says nothing about accesses performed inside dependencies.

## Behavior

### 1. Initial calls and zero-result return

F-7e4f952e879e is called first, followed by F-6aa70fefe2a1. Neither has explicit arguments shown.

The second result is interpreted as an unsigned 32-bit quantity. If it is zero, the function returns immediately. No direct primary-object access, context write, allocation, or later dependency call occurs on this path. The initial dependencies may themselves have side effects.

### 2. Quantity selection and scaling

For a nonzero initial result, the selector byte is read.

- A zero selector retains the initial quantity.
- A nonzero selector causes a context-address read, followed by an unsigned override read at context offset `0x8C8`.
- Only on the nonzero-selector path is an override below two replaced by two.

The initial zero check occurs before override selection. A positive override cannot bypass that return.

The selected unsigned quantity is multiplied by 1000, retaining a 32-bit result. F-979606fd565e receives the primary-object address and that scaled result.

After the call returns, the context address is read again from primary-object offset `0x13C`. The scaled result is written to this context’s offset `0x8CC`. This context address is retained; subsequent dependencies are not followed by another read of the primary object’s context address.

Consequently, the override may come from one context while the scaled-value write targets another.

### 3. Record availability

The retained context’s record slot at `0x8DC` is read.

If it contains zero:

1. F-8157a180d901 receives an allocation-size argument of 44.
2. Its returned 32-bit address is written into the retained context’s record slot, even if zero.
3. A zero result causes immediate return.
4. A nonzero result is passed to F-861a66c91b48 together with the retained context address and two zero arguments.

If the slot initially contains a nonzero address, F-936a8728139d is called instead. No allocation or initialization call occurs on that branch.

Allocation failure does not undo the earlier dependency call or scaled-value write. No explicit error result is returned.

The allocation result is published before initialization. There is no subsequent validation that initialization preserves the context slot, initializes particular record fields, or keeps the allocation valid.

### 4. Derived-value publication and signed test

After successful allocation handling or existing-record handling, F-870c4fcf7295 receives the scaled value plus 500 and the constant 1000. Its 32-bit result is passed to F-64940e1c31fb together with the retained context address.

A rounded conversion is plausible intent, but neither division nor rounding is established by the supplied evidence.

Only afterward is the scaled value tested as signed. A value below one causes return. Record handling and derived-value publication therefore occur even when the scaled bit pattern is zero or signed-negative, provided earlier execution reaches this point.

### 5. Positive-value configuration

For a signed-positive scaled value, the following order is established:

1. Read the retained context’s record slot and pass that address, with 1000, to F-6904f7699031.
2. Read the context’s record slot again and retain the resulting record address.
3. Call F-936a8728139d.
4. Read the callback-value global and write it at retained-record offset `0x20`.
5. Read the marker at retained-record offset `0x1C`.

The two record-slot reads can select different records. After the second read, subsequent record operations use the retained address, not a refreshed context-slot value.

A nonzero marker causes immediate return. Configuration and the callback-field write have already occurred; preparation, traversal, completion, and the final indirect decision do not occur.

### 6. Preparation and calculated-field writes

For a zero marker, the current gate-global value is passed to F-338d16f9ce72. F-add44d4e9aaa then receives the retained record address.

After both calls, the record field at `0x04` is read and retained.

If it is zero, calculation and traversal are skipped. This branch performs no direct writes to the comparison field, snapshot field, marker, or next link. It nevertheless proceeds to completion and the final decision.

For a nonzero field:

1. F-unmapped-01 is called without explicit arguments shown.
2. The head-slot address is read from the list-anchor global and retained.
3. The call result plus 1000 times the previously captured record field is written at record offset `0x08`.
4. The snapshot global is read and copied to record offset `0x18`.
5. The head address is read through the captured head-slot address.

The arithmetic operand is captured before F-unmapped-01. Changes to its storage during that call do not change the retained operand.

The head is read after the calculated-field and snapshot writes. If storage aliases, those writes can affect what the later head read observes. The supplied representation does not establish disjoint storage.

### 7. Traversal and link publication

Traversal starts with the head address just read and no retained predecessor.

For each nonnull current address, F-0d70d6f9010c receives, in order:

- The address of the current record’s field at `0x08`.
- The address of the retained record’s field at `0x08`.

A nonzero result stops traversal at the current address. A zero result causes the current record’s link at `0x00` to be read **after** the comparator returns. That current record becomes the retained predecessor, and the newly read link becomes the next current address.

A null current address ends traversal without a comparison for that address. The stopping address is the retained traversal address, not a refreshed head-slot value.

After traversal, these writes occur in order:

1. Write the retained record address through the captured head slot if no predecessor exists; otherwise write it to the retained predecessor’s link at `0x00`.
2. Write one at retained-record offset `0x1C`.
3. Write the stopping address, possibly null, at retained-record offset `0x00`.

These are address-directed writes. They do not independently establish insertion, reachability, or a well-formed list. The comparator can change the global anchor, the captured head slot, or links; it can detach a retained predecessor. The function neither refreshes the anchor nor checks predecessor reachability before publishing.

Existing membership is also unchecked. If the retained record is already the head and the first comparison returns nonzero, the first write leaves the head address unchanged and the final write makes the record point to itself.

A structural insertion interpretation is valid only under additional assumptions, not established by this function:

- The captured slot remains the relevant head slot.
- The starting structure is a well-formed, finite list of valid records.
- The retained record is not already reachable in that list.
- The head slot, node objects, and participating fields occupy the distinct, non-overlapping storage needed for their roles.
- Dependencies and other actors preserve the relevant structure and storage during calculation, traversal, and publication.

Under those assumptions, the writes place the previously absent record before the stopping node, or at the end when the stopping address is null. They still publish the incoming link before writing the record’s final next link; the sequence is not evidence of atomic insertion.

No numeric ordering or equality policy is established without the comparator’s contract.

### 8. Completion and final indirect decision

After either the zero-operand branch or the completed link-write branch, F-5bcae2eff9a7 receives the current completion-global value.

After it returns:

1. The gate global is read again.
2. The resulting address is dereferenced to obtain an intermediate pointer.
3. If that pointer is nonnull, its first 32-bit word is read.
4. If both the intermediate pointer and that word are nonzero, F-unmapped-02 is invoked through the indirect-target global.

The address obtained directly from the gate global is not checked before dereference. The final decision uses post-completion memory, not the value previously passed to F-338d16f9ce72.

No explicit arguments are shown for the indirect invocation. Its full calling convention and whether it returns normally are unresolved.

## Side effects

Direct writes can affect the retained context’s scaled quantity and record slot; the selected record’s callback-like, calculated, snapshot, marker, and link fields; and either a captured head slot or a retained predecessor’s link.

These destinations are not guaranteed to be independent. Without non-aliasing preconditions, a write described under one role may change storage subsequently accessed under another role. Write order remains significant.

The marker is written after link publication and before the final next-link write. A value of one does not independently prove membership in the current global list, and a value of zero does not prove absence.

There is no explicit deallocation, rollback, address-recovery path, duplicate-membership check, or cycle detection. Publishing an allocation result establishes a reference at that moment, not an ownership transfer or lifetime guarantee. Dependencies may mutate globals, replace addresses, or release storage; no preservation is assumed.

Traversal requires eventual null or a nonzero comparator result to terminate. Cycles, self-links, or changing links can prevent termination.

### Widths and arithmetic

Addresses, ordinary fields, quantities, and retained arithmetic values are represented as 32 bits. The selector is 8 bits.

Initial selection and the override minimum use unsigned interpretation. Scaling multiplies the unsigned quantity by 1000 and retains the low 32 bits. The result is then treated as signed for the positivity test, so a positive selected quantity can produce zero or a signed-negative result.

The addition of 500 and the later calculated-field multiplication and addition are represented as signed arithmetic. Their executable overflow behavior remains **documented_only**; portable signed wraparound is not assumed. Address-overflow and alignment behavior are likewise not established.

## Acceptance examples

These are conditional static expectations, not executed tests. They assume returning dependencies, valid reached accesses, and defined arithmetic except where a specific case says otherwise. Statements about independent fields additionally require non-overlapping storage. Structural claims require all the conditions in Section 7.

1. **Initial result is zero.**  
   Only the two initial dependencies are called directly. No primary-object read or later direct write occurs.

2. **Override below the minimum.**  
   With a nonzero initial result and nonzero selector, override values zero, one, and two all select two and scale to 2000.

3. **No override; initial quantity three.**  
   F-979606fd565e receives 3000. The post-call selected context receives 3000 at `0x8CC`. If record handling succeeds, F-870c4fcf7295 receives 3500 and 1000. Its result is unspecified.

4. **Allocation failure.**  
   The scaled-value write has occurred. The allocation result zero is written to the record slot, then execution returns without initialization or derived publication.

5. **Unsigned scaling produces zero.**  
   With no override and initial quantity `0x20000000`, scaling retains zero. If record handling succeeds, derived publication uses arguments 500 and 1000; positive-value configuration is then skipped.

6. **Configuration replaces the record slot.**  
   If F-6904f7699031 changes the retained context’s slot to another valid record, the second slot read selects that record. Later callback and marker accesses use its retained address.

7. **Nonzero marker.**  
   Configuration and callback-field replacement occur before return. Preparation, completion, and the final indirect decision are skipped.

8. **Zero operand after preparation.**  
   If offset `0x04` reads as zero after F-add44d4e9aaa, calculation and traversal are skipped, but completion and the final decision remain reachable.

9. **Empty captured head.**  
   With a nonzero operand and null head, no comparison occurs. The captured head slot receives the record address, then the marker receives one, then the next link receives null. This is insertion into the relevant list only under the structural preconditions, including distinct storage and absence of the record from that list.

10. **Already the head, despite a zero marker.**  
    Suppose the head equals the retained record, preparation leaves its operand nonzero, storage is otherwise distinct, and the comparator returns nonzero without mutation. The head remains unchanged, the marker becomes one, and the record’s next link becomes its own address. No insertion of a previously absent record has occurred.

11. **Detached predecessor.**  
    If a later comparator detaches a retained predecessor before stopping, publication still targets that predecessor’s link. The subsequent marker and next-link writes do not restore reachability.

12. **Comparator changes a link and continues.**  
    A zero comparator result causes traversal to follow the current link as read after the call, including a replacement link.

13. **Completion changes the gate.**  
    The final decision uses the replacement gate value. A valid gate address containing a null intermediate pointer skips the indirect invocation; a null gate address itself is not guarded.
