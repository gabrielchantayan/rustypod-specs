# F-a218181bd008

## Purpose

F-a218181bd008 derives a 32-bit unsigned value from an opaque input and stores that value in a selected four-byte slot relative to a base supplied by a dependency.

A preliminary dependency determines whether to request a value. If that preliminary result is nonzero, a second dependency receives writable access to an initially zero 32-bit temporary. The resulting temporary is shifted right by ten bits using an unsigned shift. If the preliminary result is zero, the value selected for storage is zero.

The destination base is obtained after the value has been selected. The function then performs one explicit 32-bit destination write.

This is the established behavior visible in the supplied static evidence. Interpreting the shift as a unit conversion, the opaque input as a resource handle, or the destination as a particular application table would be inferred intent, not an established contract.

### Destination layout

**base + 16 bytes + 4 × slot selector**

Consequently:

- Selector zero addresses the four-byte word beginning 16 bytes after the returned base.
- Selector one addresses the word beginning 20 bytes after the returned base.
- Consecutive selectors designate locations four bytes apart.
- A negative selector moves the address before the selector-zero location, subject to target address-arithmetic behavior.

The 16-byte displacement establishes an offset, not the meaning or contents of the preceding bytes. The evidence does not establish a declared array, its length, a containing structure, or valid selector bounds.

## Behavior

### 1. Initialize the intermediate value

The function starts with a writable 32-bit unsigned temporary set to zero.

This initialization matters when the value-producing dependency is skipped and when it returns without replacing the temporary. It does not imply that incomplete or failed dependency operations are recognized as errors.

### 2. Evaluate the preliminary dependency

F-bd3e46af741a is called with:

1. The opaque input, unchanged.
2. A zero-valued argument.

Its result is tested for equality with zero. The distinction is strictly **zero versus nonzero**.

A negative result, if represented by the dependency’s signed result type, selects the same path as any other nonzero result. The function does not distinguish positive success codes from negative error codes.

If this call does not return normally, subsequent behavior is not established by the normal-return sequence.

### 3. Conditionally obtain and scale a value

If the preliminary result is zero:

- F-101126b06926 is not called.
- The value selected for the destination remains zero.

If the preliminary result is nonzero, F-101126b06926 is called with:

1. The same opaque input.
2. The address of the initialized 32-bit temporary.
3. A zero-valued argument.

The supplied evidence does not consume a return result from this dependency. The subsequent value is determined by the contents of the temporary after the call returns, not by a returned status.

The temporary is then shifted right by ten bits as an unsigned 32-bit quantity. This operation:

- Discards the ten least significant bits.
- Introduces zero bits at the high end.
- Produces the same numerical result as division by 1,024 with the fractional part discarded.
- Produces a result between zero and 4,194,303 inclusive.

No rounding adjustment, saturation, or sign extension is performed. For example, a value with its highest bit set is treated as an unsigned value rather than as a negative quantity.

If the dependency leaves the temporary unchanged at zero and returns normally, the selected value is zero. If it writes only some bytes, the function applies the shift to the resulting complete 32-bit contents; the meaning of such a partial update depends on the dependency’s actual writes and the target byte order.

### 4. Fix the value before obtaining the destination

The value to be stored is selected before calling F-93fd250aa9bf. That dependency is called without explicit arguments.

This ordering is part of the contract:

- Any conditional value-producing call finishes first.
- Any applicable right shift finishes next.
- The destination-base dependency is called afterward.
- The destination write occurs only after that dependency returns.

The final store uses the value selected before the destination-base call. It does not reread the earlier writable temporary after that call.

This distinction can matter if F-101126b06926 retained an alias to the temporary and some later operation could modify it. Retaining or later using that address is not established as a valid dependency behavior; the evidence nevertheless shows that the selected scalar value precedes the base lookup.

### 5. Write the selected destination

After F-93fd250aa9bf returns, the function forms the destination from its result, the selector’s four-byte stride, and the 16-byte displacement.

It writes the selected value as a complete 32-bit unsigned word. It does not explicitly read the previous destination contents, merge bit fields, accumulate a prior value, or condition the write on whether the value changed.

The write occurs on both normal-return branches:

- Preliminary result zero: write zero.
- Preliminary result nonzero: write the shifted temporary.

Thus, a zero preliminary result does not leave the destination unchanged.
