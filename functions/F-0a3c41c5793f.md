# F-0a3c41c5793f

## Purpose

F-0a3c41c5793f transforms one 32-bit input through an ordered sequence of dependencies, applies two early range checks to an intermediate 32-bit word, and otherwise constructs a 32-bit integer result from a later word.

The established behavior is a word-level transformation with signed and unsigned comparisons, saturation results, and a status-dependent exceptional continuation. Interpreting some intermediate words as binary32 floating-point representations explains much of the bit manipulation, but that interpretation is inferred intent, not an independently established interface contract.

The exceptional continuation is not fully resolved by the supplied evidence. Its target is derived from an incoming link-register value, and its result becomes this function’s result if it returns normally.

## Interface

**Input:** one 32-bit word, presented as a signed 32-bit integer.

**Output:** one unsigned 32-bit word. Some return values represent signed integers in two’s-complement form:

| Returned word | Signed interpretation |
|---|---:|
| `0x7FFFFFFF` | 2,147,483,647 |
| `0x80000000` | −2,147,483,648 |
| `0x00000000` | 0 |

A negative mathematical result is returned as its corresponding 32-bit bit pattern, not through a separate signed return channel.

**Additional execution inputs:**

- A readable 32-bit comparison threshold.
- A readable 32-bit status/control word.
- Three readable 32-bit data words used by exceptional branches: one default result word and two continuation payload words.
- An incoming link-register value used to derive an indirect continuation target.

These are descriptive roles, not source identifiers. Their values, initialization, volatility, and external ownership are not supplied.

**Width conventions:**

- Word arithmetic and bitwise operations are 32-bit unless expressly identified as operating on the 64-bit dependency result.
- Unsigned multiplication, left shifts with valid counts, and unsigned negation retain the low 32 bits.
- Signed comparisons reinterpret the same 32-bit patterns as signed integers.
- The displayed signed right shifts are treated as arithmetic right shifts for the static behavior described below. Portability to an execution environment with different signed-shift semantics is not established.
- Variable right-shift behavior for counts of 32 or greater is unresolved; the function does not visibly normalize those counts to five bits or check them against 31.

No pointer argument, caller-provided output buffer, allocation request, or explicit ownership transfer is visible.

## Behavior

### 1. Ordered dependency processing

The following calls occur in order, before any early return:

1. F-b3a54d881220 receives the negation of the signed input and produces a 64-bit result.
2. F-9f634613286e receives three arguments:
   - The low 32 bits of that result.
   - The high 32 bits of that result.
   - The word `0xFFFFFFF0`.
3. F-f040c60c1676 is called with no explicit arguments.
4. F-da275d1ce8ce is called with no explicit arguments and produces a 32-bit intermediate word.

The two halves passed to F-9f634613286e are shown as signed 32-bit argument values. Their bit patterns are preserved. This is a logical low-half/high-half split; it does not establish an in-memory byte order.

No result from F-9f634613286e or F-f040c60c1676 is explicitly consumed by the visible body. Their effects must not be treated as absent: they may establish state used by later dependencies or change readable global data.

Negating the input `0x80000000` cannot produce a representable signed 32-bit mathematical value. Whether the actual executable wraps to the same word or relies on another machine-level behavior is **documented_only**. A language-level implementation must not silently assume that signed negation is defined for this input.

### 2. Early checks on the intermediate word

The comparison threshold is read after the four calls above.

First, the intermediate word is interpreted as signed. If the signed threshold is less than or equal to that signed value, the function returns `0x7FFFFFFF` immediately.

Only if that check fails does the function compare the intermediate word as unsigned against `0xC6FFFFFF`. If it is strictly greater, the function returns `0x80000000`.

These checks have different signedness and a fixed precedence:

- Equality with the signed threshold takes the first return.
- Equality with `0xC6FFFFFF` does not take the second return.
- `0xC7000000` does take the second return, provided the first check failed.
- If both predicates would hold, the first return wins.

The threshold’s actual value is unavailable. Consequently, the overall set of intermediate words reaching later processing cannot be specified numerically without a condition on that threshold.

### 3. Acquisition and decomposition of the conversion word

If neither early check returns, F-f2b8ff34d9f0 is called with the intermediate word and the literal argument `0x10`. Its 32-bit result is the conversion word.

The subsequent decomposition uses:

- A 32-bit arithmetic right shift of the conversion word by 23.
- A fraction-like word formed by shifting the conversion word left by eight bits, retaining only 32 bits.
- An insertion of `0x80000000` into that fraction-like word whenever the arithmetic-shift result is nonzero.

The arithmetic-shift result retains sign extension. For a conversion word with its high bit set, it is a negative signed value represented in an unsigned word. Its low byte corresponds to bits 23 through 30 of the conversion word.

### 4. Direct negative-result path

When the arithmetic-shift result is negative, the function considers a direct negative conversion only if the conversion word is unsigned-less-than `0xCF000001`. Equality does not qualify.

Within this path:

- If the low byte of the arithmetic-shift result is zero, the high bit of the fraction-like word is cleared.
- The right-shift count is the low eight bits of the difference between `0x9E` and that low byte.
- The fraction-like word is logically shifted right by that count.
- The shifted unsigned result is negated modulo \(2^{32}\) and returned.

For conversion words satisfying this branch’s range condition, the count can range from 0 through 158. Counts of 32 or more therefore remain relevant, not merely theoretical.

The exact behavior of those large shifts is **documented_only**. The supplied evidence does not justify replacing them with zero, masking them to five bits, or relying on any particular processor’s register-shift convention.

### 5. Direct nonnegative-result path

When the arithmetic-shift result is nonnegative, a direct result is returned only when that result is less than `0x9F` and is not `0x9E`.

Equivalently, the admitted values are 0 through 157 inclusive. The right-shift count is the low eight bits of `0x9E` minus that value, yielding counts from 158 down to 1.

The fraction-like word is logically shifted right by that count and returned without negation.

The excluded value 158 is significant: it does not use a zero-count direct shift. It falls through to saturation or exceptional handling.

As on the negative path, counts greater than 31 require an execution-environment rule that is not established here.

### 6. Saturation versus exceptional handling

If no direct result was returned, the conversion word is doubled modulo \(2^{32}\).

If this doubled word is less than or equal to `0xFF000000`, the function returns a sign-selected endpoint:

- Conversion word high bit clear: `0x7FFFFFFF`.
- Conversion word high bit set: `0x80000000`.

The supplied representation distinguishes equality with `0xFF000000` from smaller values, but both branches return the same sign-selected result. There is no visible behavioral difference between those two cases.

Only a doubled word strictly greater than `0xFF000000` reaches the status-dependent continuation logic.

Under a binary32 interpretation, this last predicate identifies words with an all-ones exponent and a nonzero fraction, while the equality case includes infinities. That classification is inferred from the encoding; no dependency’s floating-point semantics are established by its interface here.

### 7. Status-dependent continuation

On entering this logic, the low four bits of the status/control word are read to select a mode. Later status references are additional reads; the function does not visibly snapshot the entire word once for all decisions.

The indirect target is the incoming link-register value with its low two bits cleared. The following argument lists are those explicitly visible, not a guarantee of a complete recovered calling convention.

**Mode 9**

A subsequent status read tests bit `0x00100000`.

- If clear, invoke the continuation with one explicit argument: zero.
- If set, invoke it with two explicit arguments:
  - `8`.
  - A value computed from a subsequent status read by shifting left 15 bits, complementing all 32 bits, and shifting left one more bit, retaining 32 bits.

This second payload is equivalently the 32-bit complement of the status word shifted left 16 bits, with its least significant bit cleared. It is not a full-width complement of the original status word.

**Mode 10**

Read the default result word, then read status bit `0x40`.

- If the bit is clear, pass the previously read default word as the sole explicit argument.
- If set, pass `0x80000000` instead.

The default word is visibly read even when the status bit subsequently causes it to be discarded.

**Mode 8**

Read status bit `0x40`.

- If set, invoke the continuation with two zero arguments.
- If clear:
  1. Read the first continuation payload word.
  2. Read status bit `0x10`.
  3. If that bit is clear, invoke the continuation with the first payload word and the doubled conversion word.
  4. If that bit is set, discard the first payload value, read the second continuation payload word, and invoke the continuation with zero and that second payload word.

The first payload word is read even when the later `0x10` test causes its value to be discarded.

**All other modes**

Invoke the continuation with no explicit arguments.

For every mode, if the continuation returns normally, its returned 32-bit word becomes the result of F-0a3c41c5793f without further visible transformation.

## Acceptance examples

These are conditional static acceptance cases, not runtime test results. Cases involving a conversion word assume the initial dependency sequence returns normally and both early checks fail.

1. **Threshold equality:** If the intermediate word’s signed value equals the signed threshold, return `0x7FFFFFFF`; do not call F-f2b8ff34d9f0.

2. **Second-check boundary:** If the first check fails and the intermediate word is `0xC7000000`, return `0x80000000`. If it is `0xC6FFFFFF`, that second check alone does not return.

3. **Positive unit pattern:** A conversion word of `0x3F800000` produces a shift count of 31 and returns `0x00000001`.

4. **Negative unit pattern:** A conversion word of `0xBF800000` produces a shift count of 31 and returns `0xFFFFFFFF`.

5. **Positive upper boundary:** A conversion word of `0x4F000000` bypasses the direct nonnegative path and returns `0x7FFFFFFF`.

6. **Negative lower boundary:** A conversion word of `0xCF000000` qualifies for the direct negative path, uses a zero-count shift, and returns `0x80000000`.

7. **Immediately beyond the negative boundary:** A conversion word of `0xCF000001` does not qualify for that direct path and returns `0x80000000` through saturation.

8. **Infinity-shaped words:** Conversion words `0x7F800000` and `0xFF800000` return `0x7FFFFFFF` and `0x80000000`, respectively, without reading the exceptional status mode.

9. **Exceptional mode 8:** For conversion word `0x7FC00001`, the doubled word is `0xFF800002`. If mode 8 is selected and subsequent reads find both `0x40` and `0x10` clear, the continuation receives the first payload word and `0xFF800002`.

10. **Exceptional mode 10 read ordering:** If mode 10 is selected and the subsequent `0x40` test is set, the default result word is still read before the continuation receives `0x80000000`.

11. **Large-shift limitation:** A zero conversion word reaches a direct shift with count 158. A zero result is not an unconditional acceptance requirement without an established target rule for that shift count.
