# F-7103344f7722

## Purpose

F-7103344f7722 updates two adjacent state words using a selector derived from its second input. Its established structure is a read–modify–write of the first word followed by a read–modify–write of the second word. Both updates combine the existing word with a shift-derived value using bitwise OR.

The apparent intent is to record a selected flag without clearing previously recorded flags. That interpretation is well supported for effective selectors from 0 through 30 under a 32-bit integer model. It is not a complete specification for all inputs: the supplied representation contains shifts whose results are not defined by ordinary 32-bit signed-integer rules.

Two apparent special selector mappings are unreachable because the selector is masked before those comparisons. They must not be described as working special cases.

This contract separates the directly visible normalization and memory-update structure from unresolved integer and machine-level semantics.

## Behavior

### Selector normalization

The selector is first restricted to its least significant seven bits. The resulting value is therefore between 0 and 127 inclusive.

Normalization then behaves as follows:

| Seven-bit value | Effective selector |
|---|---:|
| 0 through 47 | Unchanged |
| 48 through 127 | 0 |

The representation also contains comparisons against `0x98` and `0x8C`, apparently associated with replacement values `0x30` and `0x31`. Neither comparison can succeed: after the seven-bit mask, the compared value cannot exceed `0x7F`.

Consequently:

- The effective selector never becomes 48 or 49 through those mappings.
- An original selector of `0x98` becomes `0x18`, or 24.
- An original selector of `0x8C` becomes `0x0C`, or 12.
- A seven-bit selector greater than 47 falls back to selector 0; it is not rejected and does not become a no-op.

Inputs differing only in bits above bit 6 have identical selector normalization.

### Shift-derived values

The first update combines the first word with a value formed by shifting the integer literal one left by the effective selector.

The second update combines the second word with a value formed by taking that same kind of left-shift expression and then shifting its result right by 31 positions.

These expressions do **not** establish a conventional two-word, 64-bit flag operation. In particular, the representation does not visibly select one word for selectors below 32 and the other word for selectors above 31. Nor does it visibly use a 64-bit left-shift operand.

Under ordinary rules with a 32-bit signed integer literal:

- Effective selectors 0 through 30 produce representable positive left-shift results.
- Effective selector 31 attempts to produce a value outside the positive range of a signed 32-bit integer.
- Effective selectors 32 through 47 use shift counts at least as large as the operand width.

The latter two categories do not have a defined portable result under ordinary C-style signed-shift rules. A particular target may exhibit stable instruction-level behavior, but that behavior is not established by the supplied representation.

For effective selectors 0 through 30, the first mask is the corresponding single bit, and the second mask is zero.

For unresolved selectors, the eventual right shift also requires care: its immediate left operand is represented as a signed-integer expression. An unsigned destination does not, by itself, establish that this earlier right shift is logical rather than arithmetic.

### Observable memory-update order

For an execution in which the arithmetic and memory operations are valid, the represented order is:

1. Read the first word at offset `0x180`.
2. Write that word with its existing value ORed with the first shift-derived value.
3. Read the second word at offset `0x184`.
4. Write that word with its existing value ORed with the second shift-derived value.
5. Return without an explicit result.

This is the abstract access order visible in the supplied representation, not a guarantee of particular physical bus transactions. The accesses are not marked volatile or atomic. Optimization and the target memory model may affect which physical reads and writes occur, especially when the second OR operand is known to be zero.

The relative evaluation order of an address calculation, a shift expression, and the memory read within an individual assignment is not established. No helper call intervenes.

### Established result for effective selectors 0 through 30

Under the 32-bit model and valid memory preconditions:

- The selected bit in the first word becomes set.
- Every other bit in the first word retains its prior value.
- The second word retains its prior value.
- The represented operation still includes a second-word read–modify–write, even though its added mask is zero.

These cases include all original inputs whose seven-bit value is 48 through 127, because those values fall back to effective selector 0.

## Side effects

The only explicit state effects are the two word updates.

For defined shift results, OR does not clear existing bits. Repeating the operation with the same selector is therefore value-idempotent in ordinary, exclusively accessed memory. This does not make the operation atomic, transactionally idempotent, or safe for device registers.

The function does not visibly:

- Allocate or release memory.
- Acquire or release ownership of the state.
- Retain the supplied address.
- Call a callback or other function.
- Update an error channel.
- Acquire a lock or perform an atomic operation.

Memory ownership remains an external responsibility.

The two updates are not represented as a transaction. If an execution environment permits a fault during the second access after the first update has completed, partial state modification is a risk; no rollback is visible. Exact fault behavior is environment-dependent.

Concurrent callers can lose updates because each update reads a word and later writes a derived value. No concurrency guarantee is established.
