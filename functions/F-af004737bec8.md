# F-af004737bec8

## Purpose

F-af004737bec8 obtains a state object, selects either a cached 32-bit quantity or a newly computed quantity, and returns that quantity multiplied by an unsigned 16-bit factor from the object.

The refresh decision depends on an object flag, the cached quantity, and—only when the flag and cache are both nonzero—a value returned by F-d7be9cfb4000. Refreshing uses either a dedicated computation dependency or an indexed traversal, depending on a 16-bit discriminator.

**Established behavior:** selection, traversal, counting, cache storage, and multiplication are visible in the supplied static evidence.

**Inferred intent:** the routine appears to calculate a scaled quantity while reusing a cache when an external comparison permits it. The meanings of the quantity, factor, discriminator, and comparison are not established.

## Interface

### Inputs

The recovered interface has no explicit parameters.

There is, however, an incoming 32-bit machine-register value that is copied into a local scratch slot at entry. That slot is subsequently passed by address to F-c9f1dc723c52 during indexed traversal. It must not be treated as initially zero or as an ordinary documented parameter. Its entry value and calling convention are unknown.

The principal object pointer is obtained by calling F-18bc1d07eb44.

### Output

The routine returns a 32-bit result:

- Zero if F-18bc1d07eb44 returns a null pointer.
- Zero if any invoked F-c9f1dc723c52 call returns zero.
- Otherwise, the low 32 bits of the selected quantity multiplied by the object’s unsigned 16-bit factor.

The recovered return type is signed 32-bit, while the multiplication uses unsigned 32-bit arithmetic. Consequently, a result with its top bit set can appear negative to a caller using the recovered signed interface. It is not evidence of a separate error code.

Zero is ambiguous: it can represent an early failure, a zero quantity, a zero factor, or multiplication that wraps to zero.

### Object layout used by this routine

Offsets are byte offsets from the pointer returned by F-18bc1d07eb44.

## Behavior

### 1. Acquire the object

The routine initializes its running quantity to zero and initializes the scratch slot from the incoming machine-register value. It then calls F-18bc1d07eb44 once.

If that dependency returns null, the routine returns zero immediately. No field of the absent object is accessed, and none of the other listed dependencies is called.

Otherwise, the returned object pointer remains the pointer used by this invocation. The routine does not reacquire it after subsequent dependency calls.

### 2. Decide whether to reuse the cache

The routine reads the 16-bit flag at offset 0x1cc.

- **Flag zero:** refresh is required. The existing cache is not read for this decision, and F-d7be9cfb4000 is not called.
- **Flag nonzero:** the routine reads the 32-bit cached quantity at offset 0x1f4.
  - If that quantity is zero, refresh is required, without calling F-d7be9cfb4000.
  - If that quantity is nonzero, the routine reads the 32-bit argument at offset 0x1d8 and calls F-d7be9cfb4000 with that value.

The comparison with F-d7be9cfb4000’s result is unsigned and 32-bit:

- A returned value strictly less than the previously loaded cache requires refresh.
- A returned value equal to or greater than that cache preserves the cached path.

On the preserved path, the selected quantity is the cache value loaded **before** the dependency call. The routine does not reread the cache afterward. Thus, a cache mutation performed by F-d7be9cfb4000 does not change this invocation’s selected quantity on that path.

The flag likewise is not reread after F-d7be9cfb4000. Changes to it during that call do not restart or revise the decision.

### 3. Refresh the quantity, when required

Only a refresh path reads the discriminator at offset 0x6c. If cache validation invoked F-d7be9cfb4000, this discriminator read occurs after that call and can observe changes made by it.

#### Discriminator equal to 8

The routine calls F-3d36a2127c2b with the acquired object pointer.

Its returned 32-bit value becomes the new quantity. There is no separate success test and no special treatment of zero or high-bit-set values. The routine then follows the cache-store and multiplication behavior below.

This branch does not invoke F-c9f1dc723c52 or read the traversal bound directly.

#### Discriminator other than 8

The routine traverses unsigned indices beginning at 2.

Before each potential visit, it reads the current 32-bit bound at offset 0x7c and compares the current index against that bound using unsigned ordering. A visit occurs only when the index is less than or equal to the currently read bound.

For each visit, the routine calls F-c9f1dc723c52 with:

1. The acquired object pointer.
2. The current 32-bit unsigned index.
3. The address of the same local 32-bit scratch slot used throughout the traversal.

If the dependency returns zero, the routine immediately returns zero. It does not perform its final cache store or read the multiplier. Any effects already performed by dependencies remain outside that early-return rule; there is no visible rollback.

If the dependency returns nonzero, the index advances by one using 32-bit unsigned arithmetic. The routine then reads the scratch slot:

- A zero scratch value increments the running quantity by one.
- A nonzero scratch value leaves the running quantity unchanged.

The scratch slot is not reset before successive calls. If a dependency invocation leaves it unchanged, the next count decision uses its retained value. For the first visit, that can be the incoming machine-register value copied at entry.

After a successful visit and count decision, the routine rereads the bound for the next loop condition. It does not snapshot the bound at traversal start.

With an unchanged bound:

- Bounds 0 and 1 produce no visits and a new quantity of zero.
- Bounds from 2 through 0xfffffffe produce visits for indices 2 through the bound, inclusive, unless a dependency returns zero.
- A bound of 0xffffffff does not, by itself, terminate traversal. After index 0xffffffff, the index wraps to zero and still satisfies the unsigned comparison.

The running quantity also uses 32-bit unsigned arithmetic and wraps on overflow.

### 4. Store a refreshed quantity

After either refresh branch completes normally, the routine writes the new 32-bit quantity to offset 0x1f4.

This write occurs even if the new quantity is zero or equals the existing cache. The routine does not directly update the flag, discriminator, bound, or factor.

An indexed-traversal failure bypasses this final write. A dependency may nevertheless have changed the cache independently.

### 5. Multiply and return

On both a preserved-cache path and a successful refresh path, the routine reads the unsigned 16-bit factor at offset 0x64 and multiplies it by the selected 32-bit quantity.

The factor read occurs after all dependencies invoked on that path and, on refresh paths, after the cache write. It can therefore observe changes made by those dependencies.

The result is reduced modulo 2³². There is no saturation, overflow error, or wider returned product.

## Side effects

### Direct effects

The only direct object write established by the supplied body is a 32-bit cache write at offset 0x1f4 following successful refresh.

The routine also maintains a local scratch slot and exposes its address to F-c9f1dc723c52. The slot is local storage; no allocation or ownership transfer is shown. Retention or later use of that address by the dependency is not established as valid.

The routine does not directly allocate memory, release memory, or release the acquired object.

### Dependency effects and lifetime

No supplied dependency body establishes that it preserves global state, leaves object fields unchanged, or preserves the object’s lifetime. Those properties must not be assumed.

In particular:

- F-d7be9cfb4000 can affect fields read later, but the cache comparison still uses the pre-call cache value.
- F-c9f1dc723c52 can affect the next traversal bound because the bound is reread.
- Changes to the discriminator during traversal do not switch the current refresh operation to the dedicated computation branch.
- A dependency can affect the final multiplier because it is read late.
- If a dependency invalidates the acquired object, subsequent accesses have no defined safety guarantee in the supplied evidence.

There is no visible transaction, rollback, locking, or atomicity protocol. The specified read order does not establish thread safety.

## Acceptance examples

These are conditional contract examples, not executed tests. Except where a change is explicitly described, assume valid storage and no dependency mutation of relevant fields.

1. **Missing object.**  
   F-18bc1d07eb44 returns null. The result is zero. No other dependency is invoked and no object field is accessed.

2. **Equal comparison preserves cache.**  
   The flag is nonzero, the cache is 7, F-d7be9cfb4000 returns 7, and the factor is 3. The result is 21. Neither refresh dependency is invoked, and this routine performs no cache write.

3. **Strictly smaller comparison refreshes.**  
   The flag is nonzero, the cache is 7, and F-d7be9cfb4000 returns 6. The discriminator is 8, F-3d36a2127c2b returns 4, and the factor is 3. The cache is written as 4, then the result is 12.

4. **Zero flag bypasses validation.**  
   The flag is zero, regardless of the existing cache. F-d7be9cfb4000 is not called. With discriminator 8, a dedicated result of zero, and factor 9, the routine writes zero to the cache and returns zero.

5. **Zero cache also bypasses validation.**  
   The flag is nonzero and the cache is zero. F-d7be9cfb4000 is not called; refresh proceeds.

6. **Traversal counts zero scratch outcomes.**  
   Refresh is required, the discriminator is not 8, and the bound remains 4. Calls visit indices 2, 3, and 4. All return nonzero and leave scratch values of zero, nonzero, and zero respectively. The cache becomes 2. With factor 5, the result is 10.

7. **Empty traversal still writes the cache.**  
   Refresh is required, the discriminator is not 8, and the bound is 1. No indexed dependency is called. The cache is written as zero, the factor is read, and the result is zero.

8. **Traversal failure skips finalization.**  
   A visited index causes F-c9f1dc723c52 to return zero. The result is immediately zero. This routine neither performs the final cache write nor reads the factor, even if earlier visits had accumulated a nonzero quantity.

9. **Scratch persistence matters.**  
   The first successful indexed call writes scratch as zero. The second successful call leaves scratch unchanged. Both visits increment the quantity. A contract requiring a fresh scratch value on every visit would not match this routine.

10. **A changed bound affects the next visit.**  
    The initial bound is 4. During the successful visit at index 2, F-c9f1dc723c52 changes it to 2. After counting that visit, the next condition reads 2 and terminates traversal before index 3.

11. **Cache mutation during validation is not a reload.**  
    The loaded cache is 7. F-d7be9cfb4000 changes the stored cache to 100 but returns 7. With factor 3, this invocation returns 21 and does not overwrite the stored 100.

12. **Multiplication wraps.**  
    The selected quantity is 0x80000000 and the factor is 2. The returned 32-bit value is zero. With selected quantity 0xffffffff and factor 1, the returned bit pattern is 0xffffffff, interpreted as −1 by a signed 32-bit caller.
