# F-e97908f97bd2

## Purpose

F-e97908f97bd2 coordinates three operations over storage addressed as four-byte words:

1. A preparation pass over an initial prefix.
2. A forward scan of a subsequent interval, conditionally invoking a modifying dependency.
3. A reduction pass over progressively shorter versions of the initial prefix.

**Established static behavior:** the routine reads words, invokes a caller-supplied callback, and delegates potential storage changes to two dependencies. It has no explicit word-storage assignment of its own and returns no value.

**Inferred intent:** this structure is consistent with building a heap over a retained prefix, selecting candidates from the remaining interval, and ordering the retained prefix afterward. Heap properties, selection guarantees, and final ordering are not established without the dependency contracts and callback semantics.

## Interface

The routine accepts five arguments, described here by behavioral role:

| Argument | Representation | Role |
|---|---|---|
| Base | Pointer to four-byte words | Beginning of the initial prefix; also the address of the root word used during scanning |
| Prefix end | Pointer to four-byte words | Exclusive end of the initial prefix and initial cursor for the subsequent scan |
| Scan end | Pointer to four-byte words | Exclusive upper bound for the forward scan |
| Auxiliary word | Opaque 32-bit value | Forwarded to preparation calls only |
| Callback | Callable address | Receives two word values and supplies a result tested for zero |

These role names describe this contract, not source identifiers.

The initial prefix is the half-open interval from base to prefix end. The scanned interval is the half-open interval from prefix end to scan end when the cursor is initially below scan end.

### Widths and layout

Each addressed element occupies four bytes. Advancing or retreating a word pointer by one changes its address by four bytes. No element fields, tags, signedness, or pointer interpretation are established: elements are opaque 32-bit values.

The initial element count is formed by converting the two prefix pointers to signed integers, subtracting their converted values, and shifting the difference right by two bits. The reduction pass uses the same kind of count expression against its current endpoint.

For an aligned, nonnegative byte difference that is representable by the signed arithmetic, this produces the byte distance divided by four. That ordinary case supports the element-count descriptions below. The excerpt does not establish reliable behavior for overflowing subtraction, lossy pointer conversion, or negative signed shifts.

The callback result is represented as an integer and tested only for equality with zero. A negative result is treated the same as any other nonzero result. The excerpt does not independently establish the native callback ABI or the signed-integer width; the four-byte element width is explicit.

### Preconditions for ordinary range behavior

A caller seeking the ordinary interval interpretation must provide:

- Suitably aligned, readable storage for every word that the routine reads directly.
- Pointer values for which the represented comparisons, conversions, subtraction, and pointer arithmetic are valid.
- A callable callback with a compatible argument and return convention.
- Storage and other conditions satisfying both dependencies’ requirements.

Additional write permissions, callback consistency requirements, and dependency-specific bounds are **documented_only** because their contracts are unavailable.

An empty initial prefix does not automatically make a nonempty scan safe: each executed scan iteration reads the base word.

## Behavior

The three phases occur in the order described below. Later activity observes storage as it exists after earlier calls; the routine does not retain an initial snapshot of the words.

### 1. Preparation of the initial prefix

The routine computes the initial prefix count once for this phase.

If that count is at most one, preparation makes no dependency calls.

If the count exceeds one, the routine invokes F-a20bc54143b2 at successively decreasing indices. The first index is the integer quotient of the count minus two divided by two. The sequence includes index zero and stops after the call at zero.

Each invocation supplies, in this positional order:

1. Base.
2. The current index.
3. The initial prefix count.
4. The word read at base plus that index.
5. Callback.
6. Auxiliary word.

The indexed word is read for that invocation, not captured before preparation begins. Consequently, changes made by an earlier dependency call can affect the word supplied to a later call.

The first invocation occurs even when the first index is zero. For example, a two-word prefix produces one preparation call, at index zero.

No return value from F-a20bc54143b2 is inspected. Its normal return is followed by either the next lower-index call or the scan phase.

### 2. Forward candidate scan

The scan cursor begins at the original prefix end. The prefix end remains unchanged throughout this phase.

Before each iteration, the routine tests whether the cursor is below scan end. If it is not, scanning ends. Otherwise, the routine reads:

- The word at the cursor.
- The word at base.

Those values are passed to the callback in that order: candidate value first, base value second. The relative evaluation order of the two memory reads is not established.

If the callback result is zero, no F-47690a93d536 call is made for that iteration.

If the result is nonzero, the routine invokes F-47690a93d536 with:

1. Base.
2. The original prefix end.
3. The current cursor.
4. A new read of the word at that cursor.
5. Callback.
6. A literal zero.

The fourth argument is not necessarily the candidate value previously passed to the callback. The callback may have changed the cursor word before returning. It may also have changed the base word or other storage.

After the callback and any conditional dependency call return, the cursor advances by one four-byte word. The next comparison then occurs.

This phase does not directly advance the prefix end, enlarge the prefix, copy a candidate, or restore any changed word. Any selection or replacement effect belongs to the callback or dependency behavior.

The auxiliary word is not forwarded by this routine during scanning. The final argument of every scan-triggered F-47690a93d536 call is zero, regardless of the auxiliary word’s value.

### 3. Reduction of the initial prefix

After scanning, the routine operates on a local endpoint initially equal to the original prefix end.

Before each iteration, it computes the represented word count between base and that endpoint. While the count exceeds one, it checks whether base and the endpoint differ.

If they differ, it invokes F-47690a93d536 with:

1. Base.
2. The address one word before the current endpoint.
3. That same address one word before the current endpoint.
4. The word read at that address.
5. Callback.
6. A literal zero.

Thus, the second and third arguments are equal during every such invocation. The second argument is the shortened endpoint, not the pre-iteration endpoint.

After the conditional invocation, the local endpoint retreats by one four-byte word. The count condition is evaluated again.

For an ordinary aligned prefix of \(n>1\) words, this phase makes exactly \(n-1\) dependency calls. Their shared second-and-third addresses proceed from the last original prefix word backward through the word immediately after base. The one-word prefix remaining at the end causes no further call.

The address-inequality guard is explicit. In an ordinary valid positive-length prefix whose count exceeds one, it is necessarily satisfied. Behavior for unusual pointer-conversion cases cannot safely be generalized from that ordinary case.

The routine returns without producing a result value after reduction finishes.

## Side effects

### Directly observable activity

The routine directly performs:

- Indexed word reads during preparation.
- Candidate and base word reads for each executed scan callback.
- A second candidate read when that callback returns nonzero.
- A trailing-word read for each executed reduction dependency call.
- Callback and dependency invocations in the phase order described above.

It contains no explicit assignment to the addressed word storage. Changes to that storage, or to other externally visible state, can nevertheless occur through the calls.

### Ordering and mutation visibility

Calls are sequential: an invoked function must return normally before the routine advances to its next operation.

The routine does not roll back dependency effects, preserve a copy of the prefix, or restore callback-visible state. A later read may therefore observe a change made by any preceding call.

Argument position does not establish a read order within a single call expression. In particular, the two reads used for a scan callback must not be specified as candidate-first or base-first memory accesses.

There is no basis for assuming the callback or dependencies preserve globals, avoid external effects, or retain storage validity.

### Ownership and lifetime

The routine does not explicitly allocate, release, or transfer ownership of storage.

That does not establish an ownership contract for its callees. Their allocation, retention, and release behavior is unknown. To complete normally, the required storage must remain usable for subsequent reads and calls. A callee that invalidates storage needed later can prevent defined completion.

### Errors and abnormal completion

No explicit validation, error return, retry, or recovery path is present. Dependency results are not checked. Only the callback result controls a branch.

The routine supplies no local handling for failed memory accesses, invalid calls, nonreturning callees, or other abnormal dependency behavior. Their exact consequences depend on the execution environment and callee contracts.

## Dependencies

### F-a20bc54143b2

Used exclusively during preparation.

Observed argument roles are:

- Base address.
- Descending index.
- Initial prefix count.
- Current word at the indexed position.
- Callback.
- Auxiliary word.

Its return value is ignored.

**Unknown:** whether it constructs or repairs a heap, which addresses it reads or writes, whether it invokes the callback, whether it uses the auxiliary word as state, and whether it affects ownership or global state.

### F-47690a93d536

Used both for nonzero scan results and during reduction.

During scanning, it receives the unchanged original prefix end, the current candidate address, and a freshly read candidate value.

During reduction, its second and third arguments are the same trailing-word address, accompanied by the value read there.

Its final argument is always zero in this routine. Its return value is ignored.

**Unknown:** whether it exchanges elements, repairs an ordering structure, copies values, releases resources, or interprets the two address arguments as bounds, destinations, or another abstraction.

### Caller-supplied callback

The routine directly calls it once per executed scan iteration, with candidate value followed by base value.

Zero suppresses the scan-triggered dependency call. Every nonzero result enables that call.

Preparation and reduction dependencies also receive the callback address. Their additional callback use is unknown; direct scan-call counts are therefore not total callback counts.

## Acceptance examples

These examples assume valid aligned ranges, representable count arithmetic, compatible calls, and normal returns. Dependency activity is otherwise unconstrained.

### Two-word prefix, empty scan

For a prefix containing two words with scan end equal to prefix end:

- Preparation invokes F-a20bc54143b2 once, at index zero, with count two.
- No direct scan callback occurs.
- Reduction invokes F-47690a93d536 once.
- The reduction call’s second and third arguments both address the second prefix word.
- Its value argument is read after preparation has returned.

The final word values cannot be specified without the dependencies.

### Four-word prefix and two scanned words

For a four-word prefix followed by two scan words:

- Preparation indices are one, then zero.
- Direct scan callbacks address the two subsequent words in increasing address order.
- Each callback receives that iteration’s candidate value before its base-value argument.
- Each nonzero result causes one immediate F-47690a93d536 call before the next scan iteration.
- Reduction addresses the fourth, third, and second original prefix words, in that order.

No final sortedness claim follows from this sequence alone.

### Nonzero callback results

If a scan callback returns either a negative integer or a positive integer, the conditional dependency call occurs. The routine does not distinguish sign or magnitude.

If it returns zero after modifying storage, the conditional call is skipped, but those modifications are not undone.

### Candidate changed by the callback

Suppose a candidate read supplies value A to the callback. If the callback changes that same word to B and returns nonzero, the subsequent dependency receives B as its value argument, provided no intervening external change occurs.

If the callback instead returns zero, no second candidate read for a dependency argument is required by that iteration.

### One-word prefix

For a one-word prefix:

- Preparation is skipped.
- Reduction is skipped.
- A nonempty subsequent interval is still scanned.
- Every executed scan callback reads the base word.
- Nonzero results still invoke F-47690a93d536 with the original prefix end.

### Empty initial prefix

If base, prefix end, and scan end are equal, no preparation call, scan callback, or reduction call occurs.

If base equals prefix end but is below scan end, scanning still begins. The first callback reads the same addressed word for both argument positions, though the read order is unspecified. This case is not rejected locally; its safety and dependency meaning remain contractual prerequisites.
