# F-355a27319908

## Purpose

F-355a27319908 obtains a state address, converts an opaque value token to a signed 32-bit integer, and dispatches a property update according to a selector.

Established outcomes are:

- Immediate return when state lookup yields zero.
- Invocation of a dependency marked non-returning for either of two early-stop properties.
- A single direct state write for an accepted update.
- Invocation of a reporting dependency for an unsupported selector, property, or converted value.

The apparent intent is to translate externally represented properties into compact internal encodings. Property meanings and the meanings of those encodings are not established.

External comparison storage is evaluated at distinct points. The function does not establish an entry-time snapshot of those values.

## Interface

### Arguments and result

| Input | Representation | Role |
|---|---|---|
| Selector | Signed 32-bit integer | Selects the property namespace |
| Property | Signed 32-bit integer | Determines routing and destination |
| Value token | Opaque 32-bit quantity | Passed unchanged to F-c9e0501fef5b |

F-c9e0501fef5b supplies the signed 32-bit converted value used for comparisons and updates. Ordering comparisons are signed.

F-355a27319908 has no explicit return value or success indicator. Reporting is an observable dependency call, not a returned error code.

### External comparison storage

The following contract labels identify external storage, not constants:

| Label | Use |
|---|---|
| α | Routing through α + `0x11`; group A/B comparisons |
| β | Routing boundary and property selecting a four-byte update |

The arithmetic and comparison uses of α through ζ operate in the represented signed 32-bit integer domain. η is captured and forwarded as a four-byte quantity; its signedness has no demonstrated behavioral significance.

Separate evaluations are not assumed to agree. Physical load behavior, volatility, and concurrency guarantees remain unspecified.

### State layout and addressing

F-7fba0909c452 supplies either zero or a state address. The represented state-address arithmetic is 32-bit; a wider pointer model is not established.

For a successful update:

- A signed 32-bit current-record index is read at state offset `0x24C`.
- The addressing origin is state offset `0x944`.
- The index contributes a displacement of index × `0x24` bytes.
- The selected field adds the relative offset below.

Thus, within representable arithmetic, a destination is the original state address plus `0x944`, plus index × `0x24`, plus its relative field offset.

| Relative offset | Width | Update |
|---|---:|---|
| `0x25` | 1 byte | Property `0x2200` |
| `0x26` | 1 byte | Property `0x8571` |
| `0x27` | 1 byte | Property `0x8572` |
| Property-dependent | 1 byte | Groups A–D |
| `0x34` | 4 bytes | Property matching β |
| `0x38` | 4 bytes | Normally unreachable `0x0D1C` continuation |
| `0x42` | 1 byte | Boolean normalization |

The stride does not establish record size. Several relative offsets exceed `0x24`. Allocation size, valid indices, and logical record boundaries are unknown.

## Behavior

### Entry precedence and conversion

F-7fba0909c452 is called first, without explicit arguments. A zero result causes immediate return. No property arithmetic, conversion, early-stop call, or reporting follows that result.

With available state, the function checks for early-stop properties. For every property other than `0x0D1C`, it first evaluates property − `0x8500`. Within representable arithmetic, the early-stop properties are:

- `0x0D1C`
- `0x8573`

Either invokes F-e4e2db384d33, which is marked non-returning. This check precedes conversion and selector dispatch, including dispatch for unsupported selectors.

Otherwise, F-c9e0501fef5b is called once with the unchanged value token. The original state address is retained; state lookup is not repeated after conversion. The state-relative origin at `0x944` is formed after conversion and before selector dispatch.

Successful updates read the current-record index after conversion and after the value-selection comparisons that lead to the write. Consequently, a conversion dependency that changes the index can affect the destination. No preservation of state memory or external comparison storage is assumed.

### Selector `0x2300`: routing

Routing is ordered. A property is not independently tested against every possible mapping.

First, the property is compared for equality with a freshly evaluated α + `0x11`. Equality selects group B immediately.

If equality fails, α is evaluated again for a property-less-than-α + `0x11` comparison.

| Result of second α comparison | Subsequent decisions |
|---|---|
| True | Compare the property with a fresh β value for equality. Equality selects the four-byte update at `0x34`. Otherwise, evaluate β again and test whether β is less than the property. A true result admits only `0x8580`, `0x8581`, and `0x8582` to group A. A false result enters lower-property dispatch. |
| False | Compare the property with a fresh ζ value for equality. Equality selects group C. Otherwise, evaluate ζ again and test whether the property is less than ζ. A true result admits `0x8589` and `0x858A` to group B, or `0x8590` and `0x8591` to group C. A false result admits only `0x8598`, `0x8599`, and `0x859A` to group D. |

The literal-property admission checks in the ζ-less-than branch include reached evaluations of property − `0x8500`. Their simplified property sets above are conditional on representable arithmetic.

A property not admitted by its selected route reports with `0x500`. Failure within a selected mapping also reports with `0x500`; it does not resume routing elsewhere.

The first α-derived equality has precedence over all β, ζ, and literal-property routes. With changing external values, routing cannot generally be replaced by inequalities against one snapshot. Conversely, observing different values during separate evaluations does not prove that the resulting route is impossible with stable values.

The four-byte update at `0x34` stores the converted integer directly, without enumeration reduction.

### Lower-property dispatch

Lower-property dispatch first recognizes `0x0D1C`, with a continuation that stores the converted integer at `0x38`. This continuation is unreachable if the earlier non-returning annotation holds. Its presence does not establish supported behavior after an unexpected return from F-e4e2db384d33.

Property `0x2200` is handled next.

Only after both properties have been excluded does the function read δ and capture δ + `0x8D`. This capture precedes the checks for properties `0x8571` and `0x8572`. An unsupported property reaching this point therefore still causes the δ evaluation and addition before reporting.

The captured threshold is reused rather than recomputed.

#### Property `0x2200`

The destination is the byte at relative offset `0x25`.

| Selection stage | Ordered matches and stored bytes |
|---|---|
| First comparison | `0x2100` → 4 |
| Otherwise, converted value below `0x2101` | `0x0104` → 3; `0x0BE2` → 2; fresh γ → 1 |
| Otherwise | `0x2101` → 0; `0x8570` → 5 |

Only comparisons in the selected branch are eligible. γ is evaluated only if both preceding matches in the lower branch fail. An unmatched value reports with `0x500`.

This property does not perform the lower-dispatch δ threshold capture, including when its value is rejected.

#### Property `0x8571`

The destination is the byte at relative offset `0x26`. Threshold references below mean the previously captured δ + `0x8D`.

| Converted-value relationship to threshold | Ordered matches and stored bytes |
|---|---|
| Equal | Store 3 |
| Greater | `0x8575` → 4; `0x86AE` → 6; `0x86AF` → 7 |
| Less | `0x0104` → 2; fresh γ → 0; `0x2100` → 1; fresh δ → 5 |

The last δ comparison uses a new evaluation, not the value used to construct the threshold. Earlier matches prevent later external evaluations. Unmatched values report with `0x500`.

#### Property `0x8572`

The destination is the byte at relative offset `0x27`.

First, the converted value is compared with a fresh δ value. Equality stores 5.

If equality fails, δ is evaluated again to determine whether δ is less than the converted value.

| Ordering result | Ordered matches and stored bytes |
|---|---|
| True | Captured threshold → 3; `0x8575` → 4 |
| False | `0x0104` → 2; fresh γ → 0; `0x2100` → 1 |

The threshold remains the value captured before property selection. No new δ + `0x8D` is calculated here.

With stable δ evaluations, the false ordering branch implies a converted value below δ because equality already failed. Without stability, only the failed later ordering comparison is established.

Unmatched values report with `0x500`. No explicit encodings 6 or 7 exist for this property.

### Mapping groups A–D

Each group applies the following comparisons in order. The first match determines the stored byte.

| Group | Relative destination | Ordered mappings |
|---|---|---|
| A | `0x28` + (property − `0x8580`) | `0x1702` → 0; fresh α − 1 → 1; fresh α → 2; `0x8578` → 3 |
| B | `0x2B` + (property − `0x8588`) | `0x1702` → 0; fresh α − 1 → 1; fresh α → 2; `0x8578` → 3 |
| C | `0x2E` + (property − `0x8590`) | `0x0300` → 0; `0x0301` → 1; fresh ε − 1 → 2; fresh ε → 3 |
| D | `0x31` + (property − `0x8598`) | Fresh ε − 1 → 2; fresh ε → 3 |

The plain α or ε comparison uses a separate evaluation from the preceding subtraction comparison. Neither occurs if an earlier literal match succeeds.

Groups A, B, and C calculate their property-relative displacement before testing converted values. Their first-literal destinations use a differently arranged address expression from later matches. The table gives algebraically equivalent destinations only within representable arithmetic; it does not assert identical intermediate overflow behavior.

Ordinary literal-property routes produce these relative offsets:

- Group A: `0x28`–`0x2A`.
- Group B through `0x8589` or `0x858A`: `0x2C`–`0x2D`.
- Group C through `0x8590` or `0x8591`: `0x2E`–`0x2F`.
- Group D: `0x31`–`0x33`.

Group B also accepts the property matching the first α-derived boundary. Group C also accepts the property matching ζ. These external-equality routes need not produce offsets within the ordinary ranges. No destination-range validation is established.

Every matching group update writes one byte and returns. An unmatched converted value reports with `0x500`.

### Selector `0x8861`

After conversion and origin formation, η is read and captured before the property check.

For property `0x8862`, the byte at relative offset `0x42` receives:

- 0 for converted zero.
- 1 for any nonzero converted value, including negative values.

The function then returns. The η evaluation still occurs on this successful path, although its captured value is not used for reporting.

Every other property surviving the entry checks invokes F-375c8199e7c2 with the original state address and captured η.

### Other selectors and reporting

Any selector other than `0x2300` or `0x8861` invokes F-375c8199e7c2 with the original state address and `0x500`, after entry checks and conversion.

All rejected selector-`0x2300` paths use the same reporting argument.

If reporting returns normally, the function returns without a subsequent direct destination write. The diagnostic meanings of `0x500` and η are unknown.

## Side effects

A successful update performs exactly one explicit destination write: either one byte or four bytes. The current-record index is not explicitly modified by this function.

An unsuccessful dispatch performs no direct destination write before reporting. This does not establish unchanged memory: dependencies may mutate state, external storage, or other memory.

Reached reads and arithmetic matter even on paths without an update:

- Non-`0x0D1C` properties undergo entry subtraction before conversion.
- Routing separately evaluates external boundaries.
- Unsupported lower-dispatch properties can trigger δ threshold capture.
- Selector `0x8861` evaluates η even for a successful Boolean update.

No allocation, release, reference-count operation, or ownership transfer is explicit. Forwarding the value token does not establish transfer of ownership. Passing the state address to reporting does not establish whether reporting retains, modifies, or releases it.

Successful storage requires the retained state address to remain usable, the index location to remain readable, and the selected destination to be writable. No index bounds check, destination bounds check, lifetime revalidation, or alignment repair is established.

Arithmetic constraints apply to every reached calculation, not just successful updates. Relevant calculations include property subtraction, α + `0x11`, δ + `0x8D`, α − 1, ε − 1, group displacements, index multiplication, and address formation. Signed overflow and address overflow are not assigned wraparound semantics by this contract.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Update examples require normally returning preceding dependencies, representable reached arithmetic, a valid retained state address, and readable/writable addressed storage.

1. **Absent state.** A zero lookup result causes immediate return for any selector, property, and token. No downstream dependency is invoked.

2. **Early-stop precedence.** With available state and property `0x8573`, F-e4e2db384d33 is invoked before conversion, even with an unsupported selector.

3. **Direct four-byte update.** For selector `0x2300`, assume stable α and β, a non-early-stop property equal to β, and that property below α + `0x11`. The converted integer is written at relative offset `0x34`, without enumeration mapping.

4. **Group A offset.** If routing admits property `0x8581` to group A and conversion yields `0x1702`, byte 0 is written at relative offset `0x29`.

5. **Literal-match precedence.** With group A selected and converted value `0x1702`, byte 0 is written without evaluating α for that group's value mapping. This remains true even if α − 1 would also equal `0x1702`.

6. **Unsupported lower property.** If property `0x2201` reaches lower-property dispatch, δ is evaluated and δ + `0x8D` is captured before reporting with `0x500`. No destination write occurs.

7. **Captured threshold despite later changes.** For lower-dispatch property `0x8572`, let the threshold-producing δ evaluation be `0x100`, making the threshold `0x18D`. Let conversion yield `0x18D`, and let both subsequent δ evaluations yield `0x101`. Initial equality fails, the ordering test succeeds, and the captured threshold matches. Byte 3 is written at `0x27`; a replacement threshold of `0x18E` is not used.

8. **Different evaluations, same possible route.** For property `0x8581`, let the first α evaluation yield `0x8000` and the second yield `0x9000`. Boundary equality fails and the later less-than comparison succeeds. With both β evaluations equal to `0x8500`, group A is selected. A stable α of `0x9000` would produce the same routing decisions: `0x8581` is unequal to and below `0x9011`. The example distinguishes evaluation histories, not routes uniquely requiring changing α.

9. **Boolean normalization.** Selector `0x8861`, property `0x8862`, and converted value −1 cause an η evaluation followed by byte 1 at `0x42`. Converted zero instead produces byte 0.

10. **Post-conversion index.** If conversion changes the current-record index while preserving usable state storage, a successful update reads and uses the changed index.

11. **Rejected group D value.** If group D is selected and both reached ε-derived comparisons fail, reporting receives `0x500`; no group-D field is written.

12. **Unsupported selector.** With available state and neither early-stop property, an unsupported selector still performs conversion before reporting with `0x500`.

## Uncertainties

The following remain **documented_only**:

- External values, domain meanings, volatility, synchronization, and possible asynchronous changes.
- Dependency implementations, conversion failures, ownership behavior, and memory/global effects.
- Valid indices, allocation extent, alignment requirements, and logical record boundaries.
- Endianness and behavior outside representable integer or address ranges.
- Behavior after the dependency marked non-returning unexpectedly returns.

Distinct source-level evaluations establish neither physical access instructions nor a concurrency model. Stable-value descriptions are conditional simplifications. Different evaluation histories can produce the same observable route and destination.

The lower-dispatch threshold capture can introduce arithmetic uncertainty before reporting an unsupported property. That uncertainty is not limited to successful mappings.
