# F-b86df740454d

## Purpose

F-b86df740454d selects a 52-byte state record, replaces its occupancy-like field, initializes its index, and conditionally drains its pending-entry list. Entry processing unlinks the entry, clears one flag bit, conditionally inserts the entry into a shared list, replaces associated state, and optionally transfers payload data into record storage.

The drain is entered only when the record’s saved, pre-replacement occupancy equals a capacity-like value read after an optional dependency call. Once entered, the drain has no explicit capacity-based stopping condition: it continues while the pending-list head is nonnull.

After skipping or completing the drain, the function conditionally invokes one finalization dependency and unconditionally invokes another. Normal completion returns the 32-bit value zero.

“Occupancy,” “capacity,” “notification,” and “shared list” describe observed field usage. They do not establish the subsystem’s intended abstractions, ownership rules, or concurrency model.

## Behavior

### Record selection and initial updates

The function reads the selector-context word at offset 12 and computes the selected-record address. It then:

1. Reads and retains the record’s occupancy at offset 16.
2. Writes the replacement value to that occupancy field.
3. Reads capacity at offset 8 and writes capacity minus one to index offset 12.
4. Reads the notification condition at offset 36.
5. Calls F-6ad030b1b8cc if that condition is nonzero.
6. Reads capacity again and retains this second value.

The first capacity read controls the initial index write. The second controls drain entry and subsequent index-wrap comparisons. These reads are not interchangeable: the intervening dependency may change the record.

If saved occupancy differs from retained capacity, the function skips all pending-entry processing. The occupancy replacement, index initialization, and possible initial notification have nevertheless already occurred.

### Drain entry and cached values

If saved occupancy equals retained capacity, the function:

1. Reads the notification condition at offset 40.
2. Calls F-6ad030b1b8cc if that condition is nonzero.
3. Reads and caches the transfer-width selector at offset 4.
4. Repeatedly reads the pending-list head at offset 20, processing entries while that head is nonnull.

The retained capacity is not refreshed after the offset-40 call. The transfer width is read after that call and remains cached throughout the drain. Changes to the width field during processing therefore do not change the selected transfer branch for later entries.

The pending head, in contrast, is read afresh at every iteration.

### Entry removal and flags

For each nonnull pending head, the function first reads that entry’s successor pointer and writes it into the record’s pending-head field.

If the saved successor is nonnull, the representation then rereads the removed entry’s next field to locate the successor backlink. It writes the address of the record’s pending-head field into the successor’s offset-4 field. This is the address of record offset 20, not the record base or the removed entry.

The distinction between the saved successor and the reread next field matters if memory aliases or changes between accesses. The usual linked-list interpretation requires those accesses to identify the same successor; that invariant is not checked.

Next, the function reads the removed entry’s flags, clears only bit `0x80`, and stores the resulting 32-bit word.

If the resulting word is zero, it prepends the entry to the shared list:

1. Read the shared-list head at context offset 8.
2. Write that old head into the entry’s next field.
3. Write the entry’s address into the shared-list head.

If any flag other than `0x80` remains set, these insertion writes are skipped.

Shared-list insertion does not finish entry processing. The function continues to access the entry and its associated objects.

### Conditional dependency and associated-state replacement

The function reads the entry’s offset-8 field.

- If nonzero, it calls F-f46257aeeddc and, after that call returns, writes the replacement value to the field.
- If zero, it neither calls that dependency nor writes that field at this step.

It then reads the intermediate-object pointer from entry offset 16, reads the associated-object pointer from intermediate-object offset 4, and writes the replacement value to associated-object offset 4.

This pointer traversal occurs after the conditional dependency. The function therefore uses whatever object chain is present then. No dependency contract establishes that the entry, pointer fields, or pointed-to objects are preserved.

### Occupancy and index advancement

The function increments the record’s current occupancy by one. This increment uses the field’s value at that point, not the saved occupancy used for drain entry.

It then reads the current index, adds one, and writes the incremented index. If that incremented value equals retained capacity, it writes the replacement value into the index field. It subsequently rereads the index for payload addressing.

Wrapping is equality-based. It is not a general modulo operation, and the wrap destination is not necessarily zero. An index already above capacity is not corrected merely for being out of range.

### Payload transfer

The cached transfer width selects one of five behaviors:

| Cached width | Visible payload behavior |
|---|---|
| 0 | No payload-source or destination-storage transfer. |
| 1 | Read the source pointer at associated-object offset 16; transfer one byte to storage base plus index. |
| 2 | Read that source pointer; transfer one 16-bit value to storage base plus twice the index. |
| 4 | Read that source pointer; transfer one 32-bit value to storage base plus four times the index. |
| Any other value | Call F-2489d48d501c with destination address, storage base plus width multiplied by index, and the source pointer from associated-object offset 16. |

For nonzero widths, the destination-storage base is obtained from record offset 0 during that iteration; it is not established as a loop-wide cached value.

Only two explicit inputs to F-2489d48d501c are established: the computed destination and source pointer. The supplied representation does not establish a transfer-length argument or prove that the dependency copies exactly the cached width.

For direct transfers, the payload source is read before the payload destination is written. The representation does not establish a complete machine-level ordering among the address-operand reads within a transfer expression.

Width zero suppresses only the payload branch. Entry removal, associated-object traversal, associated-state replacement, occupancy and index updates, statistics, and applicable notifications still occur.

### Statistics and occupancy-one notification

After the payload branch, the function:

1. Increments the processing counter at record offset 44.
2. Reads current occupancy.
3. Reads the high-water value at offset 48.
4. Writes the observed occupancy to the high-water field if it is greater under an unsigned 32-bit comparison.
5. If that observed occupancy equals one, reads the notification condition at offset 32.
6. Calls F-6ad030b1b8cc if that condition is nonzero.

The occupancy read occurs after the payload branch. A generic-transfer dependency that changes occupancy can therefore affect both high-water handling and the occupancy-one notification.

The next iteration begins by reading the pending head again. There is no explicit occupancy limit, capacity check, iteration count limit, or cycle detection inside the drain.

### Finalization

After either skipping or completing the drain, the function reads the shared-list head at context offset 8.

- **Nonzero head:** call D-01 with that head value. The comparison-context fields and context byte are not read by this branch.
- **Zero head:** read comparison-context offsets 8 and 12.
  - If unequal, call D-01 with the value read from offset 8.
  - If equal, read the unsigned byte at shared-list-context offset 1.
    - If nonzero, call D-01 with the byte zero-extended to 32 bits.
    - If zero, skip D-01.

The function then calls D-02 unconditionally. If execution returns normally, F-b86df740454d returns zero.

No explicit allocation or deallocation is established. Shared-list insertion does not prove ownership transfer, reclamation, or release. In particular, an inserted entry must remain accessible for the later operations visible in this function.

A normal valid-memory execution requires all actually accessed objects to remain suitably accessible, including after dependency calls. Source storage is required only on a nonzero-width path; sufficient destination storage is required for the selected direct operation or for whatever the generic dependency actually performs.

The representation uses 32-bit values for counters, indices, widths, and address calculations. It shows no overflow checks. Exact wraparound, signed-overflow, alignment, and fault semantics require machine-level evidence; the contract does not assume arbitrary-precision arithmetic or portable signed-overflow behavior.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless a case states otherwise, assume valid, nonaliasing objects; returning dependencies that do not mutate relevant state; and arithmetic within range.

1. **Unequal saved occupancy skips the drain.**  
   With saved occupancy three, capacity four at both capacity reads, and replacement zero, occupancy becomes zero and index becomes three. Even a nonempty pending list is not processed. The offset-36 notification remains eligible, and finalization still occurs.

2. **One byte-wide entry from a full record.**  
   With saved occupancy four, capacity four at both reads, replacement zero, cached width one, and one initially pending entry whose successor is null, initialization sets occupancy zero and index three. Entry processing sets occupancy one, wraps index to zero, transfers the source byte to the storage base, and increments the processing counter once.

3. **Flag clearing controls shared-list insertion.**  
   Flags `0x80` become zero and permit insertion at the shared-list head. Flags `0x81` become one and suppress insertion. In both cases, the entry continues through associated-state and payload processing.

4. **Successor backlink targets the head field.**  
   For an initial two-entry pending list, removing the first entry makes the second the pending head. The second entry’s backlink is written with the address of record offset 20.

5. **Zero width still processes state.**  
   A processed entry with cached width zero requires the associated-object chain but does not require a payload-source read. No payload is transferred. Occupancy, index, processing counter, high-water handling, and applicable notifications still proceed.

6. **Nonzero replacement controls occupancy and wrap destination.**  
   With saved occupancy four, capacity four at both reads, replacement seven, and one pending entry, initialization writes occupancy seven and index three. Processing increments occupancy to eight and wraps index to seven. That iteration does not qualify for the occupancy-one notification.

7. **Capacity does not limit an entered drain.**  
   With saved occupancy two, capacity two at both reads, replacement zero, and an initial finite, acyclic three-entry pending list whose third entry has a null successor, the drain is entered. All three entries are processed, despite capacity being two. With no relevant dependency mutations, occupancy progresses through one, two, and three; index progresses through zero, one, and zero. The processing counter increases three times, and the final pending head is null.

8. **Initial notification can change drain eligibility.**  
   With saved occupancy three and first-read capacity four, initialization writes index three. If the offset-36 notification dependency changes capacity to three, the retained capacity becomes three and the drain is entered. Eligibility uses the second capacity read, not the value used to initialize the index.

9. **Finalization branch selection.**  
   With shared-list head zero, equal comparison words, and context byte zero, D-01 is skipped and D-02 is called. Changing only the context byte to five makes D-01 receive five before D-02. A nonzero shared-list head instead makes D-01 receive that head without reading the comparison words or context byte.
