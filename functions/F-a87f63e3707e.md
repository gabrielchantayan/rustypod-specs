# F-a87f63e3707e

## Purpose

The available static representation describes a routine that sequences 27 indirect calls, issues seven coprocessor-transfer operations, derives arguments through shifts and masks, and finally attempts a 16-bit memory write. Its visible control flow ends at an invalid-instruction boundary rather than a normal return.

No application-level purpose is established. In particular, the coprocessor operations do not by themselves establish a cache, translation, synchronization, graphics, or device-management role.

This contract distinguishes:

- **Established static evidence:** operations, argument relationships, and ordering explicitly represented in the supplied material.
- **Inferred intent:** interpretations that may explain the sequence but are not contractual guarantees.
- **Unknowns — documented_only:** behavior requiring unavailable instruction, ABI, callee, memory-map, or runtime information.

The supplied representation explicitly warns about invalid instruction data. Accordingly, this is a contract for the represented execution path, conditional on that path accurately describing executable instructions. No runtime tests have been performed.

### 6. Final store address and termination

Let \(W\) denote the unsigned 64-bit result of F-000000000023. Define:

\[
q = W \mathbin{\gg} 52
\]

Thus \(q\) consists of the top 12 bits of that result, and:

\[
0 \le q \le 4095
\]

The represented store address reduces to:

\[
A = q + \left\lfloor q/4 \right\rfloor
\]

The intermediate right shift by 41 produces at most a 23-bit value. Its subsequent conversion to a signed 32-bit value cannot make it negative. The following signed right shift by 11 therefore introduces no sign-extension ambiguity for the address calculation.

The routine attempts to store the 16-bit value `0x00cd` at address \(A\).

Consequences:

- The address lies between 0 and 5118 inclusive.
- Only the top 12 bits of \(W\) determine the address.
- Different values of \(q\) produce different addresses.
- Not every address in that interval is generated; each group of four generated addresses is followed by a one-address gap.
- Both aligned and unaligned addresses can occur.

No address validation, null check, alignment adjustment, or permission check is visible before the store.

After the store, the represented path terminates at an invalid-instruction marker.
