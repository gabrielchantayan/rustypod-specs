## Behavior

### Ordering and aliasing

The visible body is straight-line until the terminal invocation. No loops, conditional branches, bounds checks, or early failure returns are shown.

The ordering below is significant:

- Overwritten writes remain distinct effects.
- A read followed by a write-back remains an access pair.
- Separate reads of the same field are separate observations.
- Previously saved values are not interchangeable with later reloads.
- Address roles need not denote distinct storage.

Earlier byte writes can affect later word reads. Consequently, an implementation cannot snapshot the reachable graph on entry or collapse the operation into independent final-field assignments.

The following phases organize the visible effects without assigning a higher-level data-structure meaning.

### Entry anchoring and initial links

The first visible operation stores the entry payload as a word at entry-anchor offset `0x34`. This precedes both initial link reads.

The function then reads the **selected record** from the second explicit input at `0x74`, followed by the **entry-linked record** from entry-record offset `0x14`.

The selected record receives the entry record at `0x54` and the entry payload at `0x44`. Between those stores, the entry-linked record receives its own address at `0x54`. The entry record’s byte at `0x09` receives the selected address’s low byte.

A chain follows selected-record offset `0x64`, then offset `0x14`. Its resulting address receives two consecutive byte stores at `0x09`: first the entry-linked address’s low byte, then the intermediate link’s low byte.

Next, the early global word is sampled. A word from entry-payload offset `0x14` supplies a derived address-like value formed by adding `0x20`.

A further nested destination, reached from the chain result through `0x64` and then addressed at `0x14`, receives the selected address as a word. The entry payload receives the derived value’s low byte at `0x11`.

Selected-record offset `0x44` is then read twice: one observation is saved as data, and the other is used as an address. They remain distinct observations even if they ordinarily match.

### Shift-derived byte and payload updates

A byte is read at twice the earlier chain-result address. It is interpreted as signed, promoted, shifted right by the chain-result address’s low eight bits, and truncated to eight bits.

The result is written at offset `0x08` of the address obtained by the second `0x44` observation. The first saved `0x44` observation is then written to selected-record offset `0x74`, followed by the shift-derived byte at selected-record offset `0x11`.

Entry-payload offset `0x54` receives the derived link-plus-`0x20` value and then the early global word. Its byte at `0x19` receives the derived value’s low byte. The addressed record’s `0x44` field receives the selected address, and the original payload-linked record’s `0x74` receives the derived value.

The addressed record’s `0x14` link is subsequently read. Selected-record byte `0x11` is overwritten with the early global word’s low byte, and a reached byte at `0x15` receives a low-byte observation of selected-record offset `0x14`.

The signed shift is not fully specified by portable arithmetic. In particular, counts of 32 or more and right shifts of negative promoted values require target-level evidence.

### Computed-address stores and terminal invocation

The terminal access order is:

1. Read the first global address seed, then principal `0x74`.
2. Store that link’s low 16 bits at the sum of the link and principal address.
3. Store the first seed’s low 16 bits at twice the final decimal-100 group’s reached-record address.
4. Read a signed byte at the sum of a previously saved link and the principal address.
5. Store the principal-`0x74` link’s low 16 bits at the sum of the first seed and that link; repeat the halfword store at link-plus-principal.
6. Convert the signed byte to a 32-bit unsigned value and store word `0x45` at that base plus `0x45`.
7. Read the second global address seed, the late global data word, and principal `0x44`, in that order.
8. Store byte `0x44` at the signed-byte-derived base plus `0x44`.
9. Store the late global data word at twice the second seed.
10. Store the second seed’s low 16 bits at the sum of that seed and a previously saved linked address.

The terminal invocation then receives:

- The signed-byte-derived unsigned value bitwise ORed with `0x44`.
- The second global address seed.
- The saved principal-`0x44` word.

The first argument uses bitwise OR; the nearby store destinations use addition. These expressions are **not generally interchangeable, but can produce the same value**. In particular, a terminal byte of zero makes both the first argument and the byte-store destination equal `0x44`; the word-store destination is `0x45`.

## Acceptance examples

These examples are conditional static criteria, not executed tests.

1. **Initial ordering.** Given valid storage, entry-anchor offset `0x34` receives the entry payload before either initial link read.

2. **Truncation.** If the selected address’s low byte is `0xab`, the initial entry-record byte store at `0x09` stores `0xab`.

3. **Repeated stores.** With nonaliasing destinations, the initial chain-derived byte at `0x09` receives both specified values in order, even though only the second remains.

4. **Access width.** The reached word store of `0x74` at `0x10` affects four bytes. A byte-only replacement is unacceptable; individual byte values depend on byte order.

5. **Signed terminal byte.** A terminal byte interpreted as −1 converts to `0xffffffff`. Its first invocation argument remains `0xffffffff` after OR with `0x44`. Zero-extension to `0x000000ff` is incorrect.

6. **Coincident expressions.** A terminal byte of zero produces first argument `0x44`, byte-store destination `0x44`, and word-store destination `0x45`, conditional on those accesses succeeding.

7. **Noninterchangeable expressions.** A terminal byte of positive `0x44` produces first argument `0x44`, byte-store destination `0x88`, and word-store destination `0x89`. Replacing OR with addition changes the argument.

8. **Aliasing.** If an earlier byte destination overlaps a later link read, that read uses the updated storage, not an entry snapshot.

9. **Invalid memory.** A failing nested read provides no basis for returning a failure code or continuing with a null substitute.

10. **Returning dependency.** If the terminal target returns normally, no further body-level memory operations or visible propagation of its result precede the void return.
