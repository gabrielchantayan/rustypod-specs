# F-2ccb2732aa06

## Purpose

F-2ccb2732aa06 places the low 16 bits of its second input into two one-byte fields reached through a shared base-address value, then returns a 32-bit zero.

The byte at offset 12 receives bits 0–7. The byte at offset 13 receives bits 8–15. The remaining bits of the second input do not contribute to either byte. The first input has no established effect.

This is a description of the supplied static evidence, not a verified runtime specification. In particular, the evidence does not establish that the shared address remains stable during the operation, that either destination is valid, or that the two writes form an atomic update.

The second input is interpreted as a 32-bit bit pattern when selecting its upper output byte. An unsigned right shift by eight positions selects bits 8–15 for the second byte-sized conversion. ## Behavior

### Address selection and operation order

The supplied representation establishes the following ordered operations:

1. Obtain the shared base-address value and retain it for the later write.
2. Use the shared base-address value as expressed again at the first write, and write one byte at offset 12.
3. Use the retained value from the initial read, and write one byte at offset 13.
4. Return zero.

This distinction between the two address uses matters. The retained address supplies the second destination, while the first destination is expressed through another use of the shared address.

If the shared address is stable, both writes target adjacent bytes in the same region. If the shared address can change between its initial capture and its use for the first write, the supplied representation allows the two destinations to come from different base values.

The evidence does not establish whether those two source-level uses produce two physical loads in the executable. It also does not establish volatile access semantics, synchronization, or any concurrency contract. Accordingly, a guarantee that both destinations always use one common address snapshot would exceed the evidence.

### Value selection

Only the low two bytes of the second input affect the stored values:

- Bits 0–7 determine the byte at offset 12.
- Bits 8–15 determine the byte at offset 13.
- Bits 16–31 are discarded for these writes.

There is no carry, saturation, sign extension into a destination field, or range-dependent branch. There is no read-modify-write of an existing destination value in the supplied representation.

When both destinations share the same base, their order corresponds to a low-byte-first representation of the low 16 input bits. That ordering follows from explicit byte selection and separate byte stores; it does not require assuming the machine’s native ordering for a multi-byte store.
