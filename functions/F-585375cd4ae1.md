# F-585375cd4ae1

## Purpose

F-585375cd4ae1 selects between delegated processing and local object-mediated processing. The local path configures either one or two destinations, calculates a signed quantity from a descriptor, prepares the destinations, and requests transfers from a shared source object.

The established normal-return outcomes are:

| Origin and condition | Return value | Notification issued by this function |
|---|---:|---|
| Delegated processing returns zero | 0 | Status 0 |
| All required local transfers report the exact requested quantity | 0 | Status 0 |
| Local source acquisition returns null, or a required local transfer reports a different quantity | 1 | Status 2 |
| A required local destination is null, or a required destination preparation returns zero | 2 | Status 1 |
| Delegated processing returns **any nonzero value**, including 1 or 2 | The delegated result, unchanged | None after delegation |

Consequently, return values 1 and 2 alone do not identify the path taken or establish that a notification occurred. The status-2 and status-1 associations apply only to the locally generated outcomes.

These categories describe control flow. Application-level interpretations such as success, resource exhaustion, or allocation failure are not independently established.

### Quantity calculation

Let the signed 32-bit fields at byte offsets 0, 4, and 8 be the first, second, and third arithmetic fields respectively.

- **One destination:** the quantity is the product of the first and second fields, plus that product divided by 2.

The arithmetic uses signed 32-bit operands and intermediate values in the supplied representation. Signed division truncates toward zero for representable calculations. No widening, saturation, range validation, or nonnegative check is visible.

The one-destination expression references the product twice. The exact machine-level count and order of descriptor-field reads, and behavior under concurrent descriptor mutation, are not established by this representation. The formulas describe stable field values and representable arithmetic.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. They assume valid objects, stable arithmetic fields during calculation, representable arithmetic, and normally returning dependencies.

1. **Delegated return 1.** The selector byte is 1 and F-d2b426bf6b65 returns 1. The function returns 1 immediately. It does not issue status 2 or any other subsequent notification.

2. **Delegated return 2.** The selector byte is 1 and delegation returns 2. The function returns 2 immediately, without the status-1 notification associated with a locally generated return 2.

3. **Other delegated results.** A delegated result of −7 is returned unchanged without subsequent notification. A delegated result of zero instead causes a fresh lookup, status-0 notification, and return 0.

4. **One destination, exact transfer.** The selector is not 1, the discriminator is not −15326, and descriptor fields at offsets 0 and 4 are 4 and 3. The quantity is 18. Successful acquisition, nonzero preparation, and a transfer result of 18 produce status 0 and return 0.

7. **Missing first destination in two-destination mode.** Index 0 returns null. Index 1 is still requested. After both requests, status 1 and locally generated return 2 follow, without the offset-36 context invocation.

8. **Preparation short-circuit.** Both destinations exist, but destination 0’s preparation returns zero. Destination 1 is not prepared. A fresh context lookup and offset-36 invocation precede status 1 and return 2. No source operation or transfer occurs.

9. **Second preparation failure.** Destination 0 prepares successfully and destination 1 returns zero. The same preparation-failure exit occurs. No rollback of destination 0’s preparation is established.

10. **First transfer mismatch.** Both destinations prepare successfully, but destination 0’s transfer result differs from the quantity. Destination 1’s transfer is skipped. Status 2 and return 1 follow without the offset-36 invocation.

11. **Zero quantity.** If preparation returns nonzero and every required transfer returns zero, status 0 and return 0 follow. Zero quantity is not independently a failure.

12. **Negative quantity.** In one-destination mode, fields −3 and 1 produce product −3, truncated half −1, and quantity −4. Nonzero preparation and a transfer result of −4 satisfy the local exact-match condition.
