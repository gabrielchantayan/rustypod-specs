## Behavior

### 1. Capture the source words

The function reads the eight global source words and places them in the local record.

The reads occur in record order:

1. Source word 0 becomes record word 0.
2. Source word 1 becomes record word 1.
3. This continues through source word 7 becoming record word 7.

All eight source reads occur before any dependency call.

This is an ordered sequence of reads, not an established atomic snapshot. If another execution context can modify the sources, the wrapper provides no visible synchronization ensuring that all eight values belong to one consistent external state.

The wrapper does not write the source globals.

### 2. Transform the local record

Each record word is shifted right by one bit as an unsigned 32-bit value. The words are processed in descending address order: word 7 first, then words 6 through 0.

For each word, the transformation discards the least significant bit and introduces a zero in the most significant bit. Numerically, it produces the original unsigned value divided by two, rounded down.

After all eight shifts have completed, record word 7 receives an additional mask retaining only its low 24 bits. Thus:

- Words 0 through 6 contain their original values shifted right by one.
- Word 7 contains its original value shifted right by one, then masked with `0x00FFFFFF`.

The final mask is a separate write to word 7 after the shift of word 0. The operation does not shift bits between adjacent words. It is not a right shift of a single 256-bit quantity.

For words 0 through 6, the transformed value lies between `0x00000000` and `0x7FFFFFFF`, inclusive. For word 7, it lies between `0x00000000` and `0x00FFFFFF`, inclusive.

No addition, multiplication, signed shift, or carry propagation is involved in this transformation.

### 3. Invoke the dependencies

After preparing the record, the function invokes these dependencies in order:

1. **F-e7c5183babcf**
   - First argument: the workspace address.
   - Second argument: the fixed address described under Interface.
   - No return value is used by this wrapper.

2. **F-42999360227b**
   - First argument: the same workspace address.
   - Second argument: the record base address.
   - No return value is used by this wrapper.

3. **F-f20739aca2fe**
   - First argument: the same workspace address.
   - Second argument: the numeric value zero.
   - Its one-byte result is retained for the final store.

There is no visible conditional branch between these calls. If each dependency returns normally, all three calls occur exactly once in that order.

The arguments establish shared storage across the calls, but do not establish what the dependencies do with it. In particular, the available evidence does not show whether they initialize a descriptor, construct a name, register an object, perform a lookup, or carry out another operation.

The record transformation is complete before the first call. The wrapper performs no further explicit record writes afterward. Dependency side effects remain unknown; the specification does not assume that a dependency preserves globals or other accessible state.

### 4. Store the result

This ordering matters: the destination base is obtained after the dependency sequence, not captured alongside the eight source words. If a dependency changes the global destination base, the final store uses the value available when that final destination expression is evaluated.

The wrapper then returns without an explicit result.

## Acceptance examples

These are conditional contract examples derived from static evidence. They have not been executed.

### Zero-valued source words

Given all eight source words equal to `0x00000000`, the wrapper’s transformation leaves all eight record words equal to zero.

If the dependencies return normally, the call order remains F-e7c5183babcf, F-42999360227b, then F-f20739aca2fe. Zero record contents do not cause a visible early return.

### Unsigned treatment of the high bit

Given source word 2 equal to `0x80000000`, the transformed word 2 is `0x40000000`.

A result of `0xC0000000` would violate the established unsigned, zero-filling shift.

### Maximum source values

Given every source word equal to `0xFFFFFFFF`, the completed local transformation produces:

- Words 0 through 6: `0x7FFFFFFF`.
- Word 7: `0x00FFFFFF`.

Applying the 24-bit mask to every word would not match the contract.

### Masking occurs after shifting

Given source word 7 equal to `0x02000000`, its shift produces `0x01000000`, and the subsequent mask produces zero.

Given the same value in word 0, its transformed value remains `0x01000000`, because word 0 receives no 24-bit mask.

### No carry between words

Given source word 1 equal to one and source word 0 equal to zero, both transformed words are zero.

The low bit discarded from word 1 does not become the high bit of word 0 or any other word.

### Odd values round downward

Given source word 4 equal to seven, transformed word 4 equals three. The discarded low bit is not retained elsewhere by the wrapper.

### Destination changes during a dependency

Suppose the destination-base global initially identifies region A, a dependency changes it to region B, and the final dependency returns normally with byte `0xA5`.

If region B plus 33 is writable, the wrapper stores `0xA5` there. It does not use region A merely because A was the destination before the calls.

### Result bytes are not normalized

If F-f20739aca2fe returns `0x00`, the final byte store contains `0x00`. If it returns `0xFE`, the store contains `0xFE`.

The wrapper does not convert nonzero values to one or suppress a store based on the result value.
