# F-855e5285ebdd

## Purpose

F-855e5285ebdd configures a selected entry in a memory-mapped register block and performs a final control-register write on every successful returning path. Entry zero, exact token zero, and exact token `0x80` receive distinct handling.

Established behavior includes ordered register reads and writes, conditional context updates, reads of stored register offsets, and calls to opaque dependencies. A zero-index request whose unsigned length exceeds 64 returns status `0xffffffff`; all other normally returning paths return status zero.

The layout and arithmetic suggest transfer configuration. Peripheral identity, transfer protocol, and the operational meaning of individual register fields are not established.

## Interface

### Inputs

The supplied representation uses four 32-bit inputs:

| Input | Established use |
|---|---|
| Context address | Base address for conditional 32-bit state writes. |
| Selection token | Integer encoding used to select a bank and entry and to make full-value equality comparisons. It is not dereferenced as an incoming pointer. |
| Buffer word | Stored unchanged in one context path; otherwise written to a register with bit 31 cleared. |
| Length | Unsigned 32-bit value used in validation, dependency arguments, configuration encoding, and context-update conditions. |

The **entry index** is the selection token masked with `0x7f`, giving a range of 0–127.

The bank is selected by token bit 7:

| Bank | Selection condition | Entry control-register address | Entry configuration-register address |
|---|---|---|---|
| A | Bit 7 clear | `0x38400b00 + 0x20 × index` | `0x38400b10 + 0x20 × index` |
| B | Bit 7 set | `0x38400900 + 0x20 × index` | `0x38400910 + 0x20 × index` |

Bits above bit 7 do not change the bank or index. They do affect comparisons against exact token zero and exact token `0x80`.

The **initial control snapshot** is the 32-bit value read from the selected control register before any validation or dependency call.

### Output

The represented result is a 64-bit construction with:

- A low 32-bit status word.
- A high 32-bit path-dependent word.

The high word is not uniformly a status, token, or address. Its value is specified for each returning path below. Whether an external ABI exposes this construction as one scalar or as separate register results remains documented_only.

### Preconditions

Every reached access must be valid for its width and direction. In particular:

- The selected control register must be readable even for a request that will be rejected.
- Reached context fields must be writable.
- Stored-offset locations and reached shared-state pointer storage must be readable.
- Computed register destinations and reached shared-state fields must be writable.
- Each invoked dependency’s undisclosed preconditions must hold.

There is no explicit validation of context nullness, buffer-word address validity, transfer-unit zero, stored-offset values, or shared-state pointer validity. The buffer word itself is not dereferenced by this function.

Normal completion also requires reached dependencies to return and memory accesses not to fault. Neither is guaranteed by the supplied evidence.

## Behavior

### Initial read and rejection

The function selects the bank and index and reads the selected control register.

If the index is zero and the unsigned length exceeds 64, it returns immediately:

- Low result word: `0xffffffff`.
- High result word: the original selection token.

No subsequent explicit write or dependency call occurs on this path. The initial register read can itself have hardware-defined effects that are not described here.

This limit applies to every token decoding to index zero, including tokens with nonzero higher bits. Nonzero indices have no corresponding local length limit.

### Exact token zero

For exact token zero and an accepted length:

1. If length is nonzero, write length to the context word at offset `0xa0`.
2. Then, under the same condition, write the full buffer word to the context word at offset `0xa4`.
3. Write the initial control snapshot OR `0x04000000` to Bank A entry zero.
4. Read Bank B entry zero.
5. Write that newly read value back to Bank B entry zero.

For length zero, the two context writes are omitted. The register accesses still occur.

Both result words are zero. No listed dependency is called, and none of the general configuration, stored-offset, or Bank B context processing described below occurs.

### Transfer-unit selection on the general path

Every other accepted token enters the general path.

For index zero and a nonzero token:

1. Call F-8f180221fee0 with no explicit arguments shown.
2. Store its 32-bit result at context offset `0x80`.
3. Use 64 as the transfer unit.

This includes token `0x100`, which selects Bank A entry zero but is not exact token zero.

For a nonzero index, use the low 11 bits of the initial control snapshot as the transfer unit. That value can be zero. No local rejection or substitute value is established.

### Configuration word

For zero length, the count-like value is one, without a count dependency call.

For nonzero length:

1. Call F-d7be9cfb4000 with unsigned length minus one and the transfer unit.
2. Interpret its primary result as the represented 32-bit signed count value and increment it by one.

The length subtraction is reached only when length is nonzero, so it does not underflow.

The function writes a 32-bit word to the selected configuration register. Its represented components are combined by bitwise OR:

- The original, unmasked length.
- The count-like value shifted left by 19.
- `0x20000000`.

No field-isolating length mask is present. Overlapping set bits remain combined. The source representation’s signed increment and shift do not independently establish portable behavior for overflow or other non-representable signed operations; those cases remain documented_only.

### Stored-offset reads and buffer-word write

The following sequence occurs after the configuration-word write, on every general path:

1. Read the 32-bit stored offset at `0x08107cf8`.
2. On Bank A paths only, read the 32-bit stored offset at `0x08107cf4`, replacing the value obtained in step 1.
3. Write the buffer word masked with `0x7fffffff` to the address formed from `0x38400000`, the retained stored offset, and `0x20 × index`.

Consequently:

- Bank B uses the value read from `0x08107cf8`.
- Bank A uses the value read from `0x08107cf4`, but still performs the preceding read from `0x08107cf8`.
- The configuration write precedes both offset reads.
- Both required offset reads precede the buffer-word write.

The actual stored values are not supplied, so the exact buffer-register destinations remain documented_only. The reads obtain the values present at this point in execution; no dependency is assumed to preserve either location. In particular, values that existed before F-8f180221fee0 or F-d7be9cfb4000 cannot be substituted for these reads.

No offset validation, alignment check, or destination-range check is established.

### Additional Bank B processing

Bank A proceeds directly to final processing. Bank B first performs the following operations.

Call F-d7be9cfb4000 with the original length and transfer unit, including when length is zero. Ignore its primary result and use its secondary 32-bit output.

Add three to that secondary output using unsigned 32-bit arithmetic, then mask with `0xfffffffc`. Write the result to the context word at offset:

`0x38 + 4 × index`

If this result is zero and the original length is nonzero, perform a second write to the same field containing the transfer unit. The first zero write is not omitted, even when the replacement is also zero.

The largest possible field start offset is `0x234`, for index 127.

After these writes, obtain the shared-state base through the stored pointer at `0x08107cfc` and read one byte at shared-state offset `0x04`. No dependency is assumed to preserve the pointer storage or pointed-to state.

### Special shared-state route

The special route is taken only if:

- The shared-state byte is zero; and
- The initial control snapshot masked with `0x03cc0000` equals `0x000c0000`.

Its explicit sequence is:

1. Obtain the shared-state base again from `0x08107cfc` for the following access.
2. Write the original selection token as a 32-bit word at shared-state offset `0x18`.
3. Write the 32-bit value `0x39` to `0x38400810`.
4. Write the initial control snapshot OR `0x04000000` to the selected Bank B control register.
5. Read Bank B entry zero.
6. Write that read value back to Bank B entry zero.

The pointer used for the token write is not contractually required to equal the pointer used for the flag read.

The function returns:

- Low word: zero.
- High word: the selected Bank B control-register address.

For index zero, the selected control register and Bank B entry zero are the same address. Their initial read, selected-register write, later read, and final write remain distinct accesses.

This route bypasses notification and all remaining token-specific processing.

### Conditional notification

If the special route is not taken, test bits 18 and 19 of the initial control snapshot.

If both are set, call F-9c06a5856a0f with:

- Bits 22–25 of the initial snapshot, as an unsigned value from 0 through 15.
- Zero as the second argument.

Otherwise omit the call.

The condition and argument use the initial snapshot, not a fresh control-register read. No preservation of globals, register state, context, or memory ownership is assumed across this dependency.

### Final processing except exact token `0x80`

For every general-path token other than exact `0x80`, unless the special route already returned:

1. Write the initial control snapshot OR `0x84000000` to the originally selected control register.
2. Read Bank B entry zero.
3. Write that read value back to Bank B entry zero.

The low result word is zero. The high word is the original selection token masked with `0x80`, yielding either zero or `0x80`.

### Final processing for exact token `0x80`

Exact token `0x80` does not perform the preceding snapshot-based selected-register write.

Instead:

1. Read the configuration register at `0x38400b10` and extract bits 29–30.
2. Read Bank B entry zero.

If the extracted field is not three, write the Bank B value back unchanged. Return the extracted field as the high word.

If the first field is three:

1. Read `0x38400b10` again and extract bits 29–30 again.
2. Read Bank B entry zero again.
3. Form that newly read Bank B value OR `0x84000000`.

If the second field is three, write that modified value to Bank B entry zero and return high word three.

If the second field is not three, read Bank B entry zero a third time. Write this latest value OR `0x8c000000` to Bank B entry zero and return the same modified value as the high word.

The low result word is zero in every case. Each repeated read is significant; a cached value is not an equivalent replacement.

## Side effects

All explicitly described word accesses are 32 bits. The shared-state flag read is eight bits.

Explicit writes can affect:

- Context offsets `0x80`, `0xa0`, and `0xa4`.
- Context offset `0x38 + 4 × index`.
- The selected configuration and control registers.
- The buffer-register destination calculated from a freshly read stored offset.
- Shared-state offset `0x18`.
- Address `0x38400810`.
- Bank B entry zero on every successful returning path.

The function also explicitly reads the stored offsets at `0x08107cf8` and, on Bank A general paths, `0x08107cf4`. The first read remains observable on Bank A even though its value is replaced.

Several control writes reuse the initial snapshot after dependency calls. They can overwrite intervening changes rather than preserving them through a fresh read-modify-write.

No explicit allocation, release, buffer-content access, or ownership transfer is established. Storing a buffer word or selection token does not establish ownership semantics. Dependency-side retention, release, allocation, and other effects remain unknown.

No non-aliasing guarantee is supplied for context, shared state, stored-offset locations, or computed destinations. Statements about explicit access targets do not guarantee that other logical fields remain unchanged when addresses alias.

The specified sequence is the order represented by the supplied static evidence. Hardware barriers, interrupt exclusion, concurrent-access rules, and architecture-level ordering guarantees are not established. No rollback is visible after partial side effects.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. They assume valid reached accesses, normally returning dependencies, and no unspecified aliasing or concurrent modification unless the example explicitly introduces changing reads.

1. **Rejected zero-index request.** Token `0x80`, length 65: read Bank B entry zero, then return low word `0xffffffff` and high word `0x80`, without a subsequent explicit write or dependency call.

2. **Exact-zero empty request.** Token zero, length zero: omit the context writes at `0xa0` and `0xa4`; write the initial Bank A snapshot OR `0x04000000`; then read and write back Bank B entry zero. Both result words are zero.

3. **Buffer-word masking.** With exact token zero and accepted nonzero length, buffer word `0x80000005` is stored as `0x80000005` at context offset `0xa4`. On a general path, the explicit buffer-register write instead contains `0x00000005`.

4. **Higher token bits affect routing.** Token `0x100` selects Bank A entry zero but takes the general path. For length at most 64, call F-8f180221fee0, store its result at context offset `0x80`, and use transfer unit 64.

5. **Bank A offset-read order.** On a general Bank A path, after the configuration write, read `0x08107cf8` first and `0x08107cf4` second. Use the second read’s value for the buffer destination. If a preceding dependency changed that second location, use its post-call value.

6. **Bank B offset-read order.** On a general Bank B path, after the configuration write, read `0x08107cf8` and use that value for the buffer destination. No read of `0x08107cf4` is required by this path.

7. **No nonzero-index length limit.** Token one with length 65 reaches general configuration rather than the zero-index rejection, subject to dependency and access preconditions.

8. **Alignment and replacement.** On Bank B, secondary output five produces a context write of eight. Secondary output zero with nonzero length produces a zero write followed by a transfer-unit write.

9. **Alignment wraparound.** Secondary output `0xfffffffe` plus three wraps to one; masking produces zero. With nonzero length, the replacement write follows.

10. **Special-route precedence.** A zero shared-state byte and a matching snapshot mask cause the shared-state token write and `0x39` register write. Notification and exact-`0x80` final processing are bypassed.

11. **Changing exact-`0x80` field.** If the first configuration-field read yields three and the second yields two, perform the third Bank B entry-zero read. Both the final written value and high result word equal that third value OR `0x8c000000`.
