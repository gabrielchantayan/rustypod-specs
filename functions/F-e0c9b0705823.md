# F-e0c9b0705823

## Purpose

The supplied static representation describes an operation that interleaves indirect calls with direct, address-derived memory writes. It copies two supplied 32-bit values into computed locations, clears several byte and word locations, installs scaled values into other locations, and performs repeated byte updates through addresses selected by unsigned byte reads.

A higher-level purpose—such as initialization, device programming, serialization, or object construction—is not established. The apparent repetition does not establish that the indirect calls implement a common operation.

The visible path ends at an invalid-instruction boundary rather than an established normal return. This contract therefore describes the observable prefix represented by the supplied material, conditional on execution reaching each operation. It does not assert that the representation is a valid, complete executable function.

## Interface

### Explicit inputs

The apparent interface accepts three 32-bit quantities:

- **Input A:** no explicit use is visible.
- **Input B:** copied unchanged into the first directly written 32-bit location.
- **Input C:** copied unchanged into two later directly written 32-bit locations.

These quantities have no established signedness, pointer meaning, ownership, or validation requirements. In particular, Input A cannot be classified as irrelevant to actual machine execution merely because the supplied representation does not explicitly consume it.

### Ambient inputs

The visible operation also depends on machine state outside the apparent parameter list:

- A 32-bit value used, after a logical right shift by three, as the first indirect call’s argument.
- A value used to derive an early word-store address by multiplication by 524,288.
- A return-link-like value used to determine the first indirect-call target.
- A secondary register result exposed by a later indirect call.
- Memory bytes and words read from computed addresses.
- Results returned by numerous unresolved indirect calls.

These are necessary parts of the represented behavior, not established optional inputs.

### Output and termination

No explicit return value is established. Observable outputs consist of direct memory writes, calls and their arguments, and whatever effects those calls produce.

The supplied path terminates at an invalid-instruction boundary. Whether actual execution traps, transfers control elsewhere, or differs because the recovered control flow is inaccurate is **documented_only**.

### Width and address conventions

For the descriptions below:

- A **word** is 32 bits; a **byte** is 8 bits.
- Byte reads are unsigned and yield values from 0 through 255.
- A byte store retains only the low eight bits of its source.
- Masking and logical shifts explicitly applied to unsigned values have their usual fixed-width meaning.
- Products and left shifts describe the apparent 32-bit address or argument bit pattern. They do not imply an unbounded integer calculation.

Several calculations are rendered using signed intermediates. Overflow, signed left shifts, and conversion back to addresses cannot be assigned portable language semantics from this material. Arithmetic wrapping is therefore conditional on the actual machine’s behavior, not an independently established guarantee.

No alignment, endianness, mapped-memory, or address-space validity guarantee is supplied.

## Behavior

### Ordering model

The following phases preserve the order of visible calls, reads, and writes. A call described as having “no explicit arguments” has none in the supplied representation; that is not proof that the actual callee consumes no register or stack inputs.

For brevity, a **four-call result sequence** means four consecutive indirect calls with no explicit arguments, with only the fourth result used by the described operation. Earlier calls can still have side effects.

Names introduced below denote retained values for this contract, not implementation identifiers. They do not imply that any pointed-to memory is stable across calls.

### 1. Initial input installation

The first indirect call receives the ambient unsigned value logically shifted right by three. Three further calls have no explicit arguments. A fifth call, also with no explicit arguments, supplies an index.

The operation then:

- Writes Input B as a word at address `4 × index + 20`.
- Calls an unresolved dependency with `4 × index`.

A four-call result sequence follows. Its final result is retained as **primary value**.

Next, Input C is written as a word at the address obtained by multiplying the second ambient value by 524,288 and adding 36.

Two derived values are retained:

- **Primary base:** `16 × primary value`.
- **Reduced value:** the primary value masked to its low 30 bits, then logically shifted right by one.

### 2. Second installation of Input C

A call receives the primary base and `4 × primary value`. Four calls with no explicit arguments follow; their results are not explicitly used.

Input C is then written as a word at primary base plus 36.

A word is read at primary base plus 116, and its value is passed to the next call. A four-call result sequence follows. Its final result is retained as **shift seed**.

### 3. First byte-selected update and clear

A byte is read at primary base plus one. Its unsigned value selects the absolute destination address obtained by adding 17.

At that destination, the operation writes the low byte of the primary value’s masked low 30 bits shifted right by 20. Thus the written byte represents bits 20 through 27 of the primary value; bits 28 and 29 do not survive the byte store.

A call then receives `4 × shift seed`. The next call has no explicit arguments and supplies a word that is forwarded to another call.

A four-call result sequence follows. Its result is multiplied by four and used as a later call argument.

Before that argument is delivered, the byte at primary base plus one is read again, and zero is written to the newly selected address plus 17. This is a fresh selection; intervening dependencies may have changed the selector.

The call receiving the scaled result occurs next, followed by four calls with no explicit arguments.

### 4. Reduced-value clears and shifted arguments

Zero is written as a byte at reduced value plus 15.

A new base, **reduced base**, is formed as `1,024 × reduced value`. The byte at reduced base plus one is read, and zero is written at that byte’s unsigned value plus 17.

The next call receives four arguments:

- `shift seed` shifted left by 23;
- the same value;
- the same value again;
- `shift seed` shifted left by 25.

A no-explicit-argument call supplies a word that is forwarded into the next call. A four-call result sequence follows.

The byte at reduced base plus one is then read again and retained as **saved selector**. Zero is written at saved selector plus 17.

A call receives four times the result of the preceding four-call sequence. Four calls with no explicit arguments follow.

### 5. First word clears

Zero is written as a word at saved selector plus 68. The saved byte is reused without another selector read, despite the intervening calls.

Zero is then written as a word at absolute address 36.

A call receives the four arguments zero, 152, reduced base, and 152.

The next no-explicit-argument call returns a word, which is forwarded to another call. A further no-explicit-argument call supplies another word, which is likewise forwarded. A four-call result sequence follows.

Using that sequence’s final result as an index, the operation:

- Writes a zero word at `4 × index + 68`.
- Writes a zero word at absolute address 36.
- Calls a dependency with `4 × index`.

### 6. Split-result clearing

A four-call result sequence follows, except that the fourth result is represented as 64 bits.

The low 32-bit half, multiplied by four, is passed to the next call. After that call:

- Zero is written as a word at `2 × high 32-bit half + 68`.
- Zero is written as a word at absolute address 36.

The next call receives zero, the secondary register result associated with the preceding call, and four times that secondary result.

One call with no explicit arguments follows.

### 7. Reduced-value argument and repeated clears

Define **packed value** as the reduced value masked to its low 22 bits.

A call receives packed value shifted left by seven. A four-call result sequence follows.

Using its final result as an index:

- Zero is written as a word at `4 × index + 68`.
- Zero is written as a word at absolute address 36.
- A call receives `4 × index`.

Another four-call result sequence follows. Its final result, multiplied by four, is passed to another dependency. That dependency’s own result supplies a new index.

Zero is written as a word at `4 × new index + 20`.

The next call receives the new index three times, followed by packed value shifted left by seven.

### 8. Zero installation and scaled linkage

A four-call result sequence follows. Its final result supplies an index for a zero-word write at `4 × index + 20`. A call then receives `4 × index`.

Another four-call result sequence supplies a new index. The operation retains four times that index as **link value** and writes link value as a word at `16 × index + 20`.

A call receives link value. A four-call result sequence supplies another index, and link value is written as a word at `4 × that index + 20`.

A call receives four times that latter index. Another four-call result sequence supplies a further index.

At `16 × further index + 20`, the operation writes four times the further index. A call then receives both four times and sixteen times that index.

These stores establish only numeric relationships. They do not prove that the stored values are valid pointers or object links.

### 9. Packed-value installation

A call with no explicit arguments supplies a word. The next call receives that word and packed value shifted left by four.

A four-call result sequence supplies an index. At `4 × index + 20`, the operation writes packed value multiplied by 128.

A call then receives `4 × index`.

Packed value has at most 22 bits. Its multiplication by 128 therefore fits within 29 bits; its shift left by four fits within 26 bits.

### 10. Final byte-update series

A four-call result sequence supplies **first late value**.

A **late base** is formed as reduced value multiplied by 67,108,864. Under a 32-bit modular interpretation, only the reduced value’s low six bits affect this base; the actual overflow semantics remain subject to the arithmetic uncertainty above.

The byte at late base plus one is read. At its unsigned value plus 17, the operation writes the low byte of four times first late value.

A call receives four times first late value. A no-explicit-argument call supplies a word that is forwarded to another call.

A four-call result sequence follows. The byte at late base plus one is read again. At its unsigned value plus 17, the operation writes bits 20 through 27 of first late value.

A call receives four times the result of that preceding four-call sequence.

Another four-call result sequence supplies **second late value**. The byte at late base plus one is read and retained as **late selector**. The operation writes the low byte of four times second late value at late selector plus 17.

A call then receives late selector itself, zero-extended from eight bits—not four times the selector and not its destination address.

A no-explicit-argument call supplies a word that is forwarded to another call. A four-call result sequence follows.

The byte at `8 × second late value + 1` is read. At its unsigned value plus 17, the operation writes bits 20 through 27 of second late value.

A call receives four times the result of the preceding four-call sequence. Four calls with no explicit arguments follow. The represented path then reaches its invalid-instruction boundary.

## Side effects

### Direct memory effects

The visible direct accesses consist of:

- 32-bit reads and writes at computed addresses.
- Unsigned 8-bit selector reads.
- 8-bit writes to addresses selected by those reads.
- Four distinct 32-bit zero writes to absolute address 36.

A byte-selected destination lies between absolute addresses 17 and 272 inclusive. A word destination derived from saved selector plus 68 begins between addresses 68 and 323 inclusive. Neither range establishes that these are ordinary RAM rather than special-purpose locations.

Writes can alias each other, selector storage, or other computed locations. No separation guarantee is visible. Consequently, earlier writes may affect later reads even without dependency side effects.

There is no evidence of atomicity. Access width alone does not establish atomic behavior.

## Acceptance examples

These examples are conditional static expectations, not reports of execution. They assume the relevant prefix is reachable, dependencies return as described, accesses are valid, and arithmetic has the stated interpretation.

1. **Initial word copy.** If the fifth call supplies index 3, the first direct store writes Input B unchanged as a 32-bit word at address 32. The following call receives 12.

2. **Independent Input C destinations.** If the ambient address-driving value is 2 and primary value is 3, Input C is first written at address 1,048,612 and later at address 84. These are separate ordered stores even if another input combination makes the destinations coincide.

3. **Unsigned selector.** If a selector read returns 255, the associated byte destination is address 272. Interpreting that byte as negative would violate the visible unsigned selection.

4. **Extraction truncation.** If primary value is hexadecimal `0x3AB00000`, its first extraction-based byte store writes hexadecimal `0xAB`. The masked-and-shifted intermediate is wider than one byte; the upper two bits are discarded by storage.

5. **Selector reread.** If an intervening dependency changes the byte at primary base plus one from 4 to 9, the first update targets address 21 and the later clear targets address 26. The clear is not required to undo the first update.

6. **Saved-selector reuse.** If saved selector is 7, the later word clear begins at address 75 even if dependencies subsequently modify the original selector location. This phase uses the retained byte, unlike the rereading phases.

7. **Packed-value bound.** If reduced value’s low 22 bits are all one, packed value multiplied by 128 is hexadecimal `0x1FFFFF80`. Higher reduced-value bits do not contribute to that stored value.

8. **Partial execution.** If the call immediately after the first word copy never returns, that copy has already occurred. Completion of later Input C stores or zeroing operations is not implied.

9. **No success-return expectation.** Reaching all visible calls does not establish normal completion: the supplied path still ends at an invalid-instruction boundary.
