# F-db210a381d39

## Purpose

F-db210a381d39 exposes a sequence of indirect dependency calls interleaved with byte and 32-bit memory updates. Its first explicit input supplies several address indices and packed values; its third explicit input is written twice. Subsequent updates depend heavily on dependency results, including a recovered two-word result and an implicit secondary result.

The established behavior is the ordering of these operations, not a demonstrated application-level purpose. The repeated zero stores and scaled-index stores could represent state initialization or reconfiguration, but that interpretation is **inferred intent**, not an established contract.

The supplied representation ends at an invalid-instruction boundary. It does not establish a normal return, successful completion status, or recoverable error path.

## Behavior

The following phases describe the visible ordering. Dependency IDs identify invocation occurrences, not proven distinct functions. Their numbering preserves invocation order across the phases.

Dependency calls remain observable even when no explicit argument or consumed result is shown. Such calls cannot be treated as inert.

### 1. Initial stores and input-derived byte update

Before any visible dependency call, the function writes the third input as a 32-bit word to the address formed by multiplying the implicit incoming register by 524,288 and adding offset `0x24`.

It then invokes F-dep-001 with Quarter index and Input. F-dep-002 through F-dep-005 follow, with no explicit arguments shown.

Next, the function:

1. Writes the third input as a 32-bit word at Quarter index plus `0x24`.
2. Reads a 32-bit word at Quarter index plus `0x74` and supplies it to F-dep-006.
3. Invokes F-dep-007 through F-dep-010 without explicit arguments.
4. Retains the word result of F-dep-010 as the **first retained result**.
5. Reads one byte at Quarter index plus one.
6. Adds `0x11` to that unsigned byte value and writes one byte there.

The byte payload is the low eight bits of Input logically shifted right by 22. Thus it carries original input bits 22 through 29; original bits 30 and 31 do not survive the byte store.

The destination of that byte store lies in the numerical address range `0x11` through `0x110`. The byte read is used directly as a small address component, not as an index multiplied by a record size.

### 2. First clearing sequence

F-dep-011 receives the first retained result shifted left by two bits. F-dep-012 returns a word passed directly to F-dep-013. F-dep-014 through F-dep-017 then execute, with the result of F-dep-017 retained for the next call.

The byte at Quarter index plus one is read again. The function writes zero to the newly selected address obtained by adding `0x11` to that byte. It does not reuse the earlier selector.

F-dep-018 receives the result of F-dep-017 shifted left by two. F-dep-019 through F-dep-022 follow.

Two byte writes then occur, in order:

1. Zero at Group index plus `0x0f`.
2. Zero at the address selected by reading the byte at Scaled group plus one and adding `0x11`.

### 3. Group-selected clearing and the first absolute reset

F-dep-023 receives four explicit arguments:

- The first retained result shifted left by 23 bits, repeated three times.
- The first retained result shifted left by 25 bits.

F-dep-024 returns a word passed to F-dep-025. F-dep-026 through F-dep-029 follow, with the result of F-dep-029 retained.

The function reads the byte at Scaled group plus one. It retains this selector, writes zero to the selector plus `0x11`, and invokes F-dep-030 with the result of F-dep-029 shifted left by two.

After F-dep-031 through F-dep-034, it performs two 32-bit stores:

1. Zero at the retained selector plus `0x44`.
2. Zero at absolute address `0x24`.

The selector used for the word store is the byte retained before these calls. There is no intervening refresh of that selector.

### 4. Dependency-selected word clears

F-dep-035 receives zero, `0x98`, Scaled group, and `0x98`.

F-dep-036 returns a word passed to F-dep-037. F-dep-038 returns a word passed to F-dep-039. F-dep-040 through F-dep-043 then execute.

F-dep-044 receives four times that same index. F-dep-045 through F-dep-048 follow.

F-dep-048 is represented as producing a 64-bit result:

F-dep-050 then receives zero, an implicit secondary register result associated with the preceding call, and that secondary value shifted left by two. The secondary value must not be substituted with either half of the earlier 64-bit result without additional evidence.

F-dep-102 receives the result of F-dep-101 shifted left by two. F-dep-103 through F-dep-106 follow. The unsigned result of F-dep-106 becomes the **second final word**.

The function reads and retains the byte at Wide group plus one. It writes the low eight bits of four times the second final word at the retained selector plus `0x11`.

The function then reads a byte at eight times the second final word plus one. At that selector plus `0x11`, it writes bits 20 through 27 of the second final word.

Finally, F-dep-114 receives the result of F-dep-113 shifted left by two. F-dep-115 through F-dep-118 execute without explicit arguments. The visible path then reaches the invalid-instruction boundary.

## Side effects

### Direct memory effects

The visible body contains:

- Two 32-bit writes of the third input.
- Four explicit zero-word writes to absolute address `0x24`.
- Other zero-word writes at selector-derived or dependency-result-derived destinations.
- Word writes publishing scaled dependency results and a masked input-derived value.
- Byte writes of zero and truncated input- or result-derived values.
- Byte-selector reads and one explicit 32-bit argument read.

These accesses are ordered as described. They are not shown as atomic transactions.

### Aliasing and repeated accesses

No disjointness guarantees are established. Initial stores, selector locations, result-derived destinations, and absolute address `0x24` can potentially overlap.

For example, when Input is zero, the second initial word store targets `0x24`, which is also explicitly zeroed later. Dependencies or faults may prevent those later stores from being reached.

Repeated selector reads must remain distinct observations. Dependencies can alter memory between them. Conversely, retained selector values remain the source of later addresses where explicitly described.

### Ownership and dependency effects

No allocation, release, ownership transfer, or lifetime guarantee is established by the visible body.

Dependencies may modify memory or global state, perform external effects, fail, or not return. Their effects are unknown, not absent. Explicit arguments cannot safely be classified as handles, pointers, owned objects, or scalar identifiers beyond their observed widths.

No visible rollback restores earlier stores after a failed access or dependency.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Initial write ordering.** If the first store succeeds, the third input has already been written to the implicit-register-derived address before F-dep-001 is invoked. A dependency failure cannot undo that store through any visible recovery path.

2. **Input-derived byte truncation.** If Input is `0xffc00000`, the first input-derived byte payload is `0xff`, not `0x3ff`. The destination still depends on the byte read at Quarter index plus one.

3. **Selector refresh.** If the first selector read returns 5, its byte destination is `0x16`. If intervening dependencies change the selector to 9 before the next read, the following clear targets `0x1a`, not `0x16`.

4. **Retained selector.** If the selector retained in phase 3 is 7, its subsequent word clear targets `0x4b`, even if dependencies change the source selector meanwhile. Whether that unaligned word address is supported is unknown.

5. **Masked input contribution.** If Masked group equals one, the phase-5 shifted argument and phase-7 stored payload are both 128. The phase-7 second explicit argument is 16.

6. **Separate halves of a result.** If F-dep-048 yields low word 3 and high word 5, F-dep-049 receives 12, and the subsequent zero-word store targets `0x4e`, subject to access validity.

7. **Final byte truncation.** If the first final word is `0x12345678`, its first byte publication is `0xe0`; its later upper-part publication is `0x23`. Distinct selector reads can send those bytes to different destinations.

8. **Interrupted execution.** If a dependency does not return, later visible writes and calls are not reached along this path. There is no established completion notification or error result.
