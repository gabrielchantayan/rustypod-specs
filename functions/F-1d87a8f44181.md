The distinguished input is −1. Its result is the all-ones unsigned value, and its evaluation does not require the external lookup state. Every other input participates in selecting a byte.

The established behavior does not identify the storage as a character table, assign an encoding, or explain the application meaning of −1. It also does not establish that every other input is valid. This contract is based exclusively on static evidence. No runtime tests have been performed.

## Behavior

### Distinguished-result guarantee

For input −1, the required result is the all-ones unsigned value. In the recovered 32-bit model, that value is 4,294,967,295.

This result is independent of both the external base value and the contents of lookup storage. The supplied operation does not obtain the base value or read a selected byte on this path. Lookup-storage readability is therefore not a precondition for the distinguished-result behavior.

That guarantee is limited to the lookup dependencies. It does not promise successful invocation in an otherwise unusable execution environment.

No application-level meaning is established for the distinguished result. Describing it as end-of-input, an error, an invalid character, or a missing value would require evidence beyond this fragment.

### Byte-result guarantee

Every input other than −1 uses the lookup behavior. This includes zero, positive values, and all other negative values.

A normally completed lookup returns the unsigned numerical value of the selected byte. The byte’s high bit does not cause sign extension. Neighboring bytes do not contribute to the returned value.

The visible selection depends on the external base-bearing datum and the argument. There is no visible range restriction, boundary check, clamping operation, search, or recovery result. In particular:

- Negative values other than −1 are not converted into the distinguished result.
- A selected byte containing 255 remains an ordinary byte result.
- An invalid lookup is not visibly replaced by the distinguished result.
- No storage length is consulted before the byte access.

These are limits of the implementation’s visible protections, not permissions to access invalid storage.

- The width of the base value or of an address.
- The arithmetic type used during selection.

- Whether any arithmetic wraps.

A negative non-sentinel argument can therefore be valid under a compatible model with a suitable interior base. Conversely, a nonnegative argument—including zero—is not inherently safe.
