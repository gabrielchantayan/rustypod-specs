# F-6e6e41110cd6

## Purpose

The apparent intent is to produce an unused temporary name. That intent is inferred from the control flow and the descriptive labels associated with embedded data. The supplied evidence does not establish the exact pathname format, character alphabet, filesystem semantics, randomness guarantees, or reservation of the resulting name.

The function has two ordinary return values:

- **0:** construction reached a final probe that returned zero.
- **1:** the selected location failed a preliminary size comparison.

A separate dependency is represented as nonreturning and is invoked when a field in the first argument does not equal 256. Other invalid inputs, dependency failures, and memory faults have no established recovery behavior.

### 2. Candidate evaluation

Candidates are considered in order: entry zero, then entry one.

For each entry, evaluation proceeds through short-circuit conditions:

1. Read the candidate entry. A zero entry is rejected without calling either candidate-related dependency.
2. For a nonzero entry, call F-ade29969e5e2 with:
   - the candidate value read for that call;
   - the address of the local query word;
   - a zero third argument.
3. If that call returns nonzero, reject the candidate. Neither the low-byte condition nor the following probe is required for that candidate.
4. If that call returns zero, inspect the low eight bits of the local query word. A zero low byte rejects the candidate.
5. If the low byte is nonzero, call F-f20739aca2fe with the candidate value and a zero second argument.
6. A zero result rejects the candidate. A nonzero result accepts it.

On acceptance, the selected location is read from the current candidate slot. If both entries are rejected, the embedded default remains selected.

The query word is initialized only once. It is not reset between candidates. Consequently, any modification made during the first query remains available to the second query. A first query that returns nonzero may still have modified this word.

Candidate entries are also not snapshotted into a stable local value across dependency calls. The slot can be read separately for the null check, query call, probe call, and final selection. If a dependency changes a table entry, later operations can use a different value. The static evidence supplies no guarantee that these dependencies preserve the table or related globals.

The acceptance rule uses only zero versus nonzero for dependency results. No particular nonzero magnitude has special meaning in the shown logic.

### 3. Preliminary size decision

After selection, the function calls F-1cb585febd84 on the selected location.

Let the returned 32-bit quantity be the location-length result. The function adds 24 using unsigned 32-bit arithmetic and compares the wrapped sum with the unsigned capacity.

Construction is permitted only when:

**the wrapped location-length result plus 24 is strictly less than capacity.**

If this comparison is false, the function returns 1.

For ordinary, nonwrapping lengths, capacity must therefore be at least the location length plus 25. Equality with location length plus 24 is insufficient.

This decision occurs before the context-field check and before the shown output-construction calls. It does not reverse the earlier global-table update or any effects of candidate evaluation.

The size calculation is not an overflow-safe validation. With sufficiently large length results, addition wraps modulo 2³² and can admit a capacity that would not pass an unbounded-integer comparison.
