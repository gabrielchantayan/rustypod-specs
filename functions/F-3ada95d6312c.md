# F-3ada95d6312c

## Purpose

F-3ada95d6312c validates and records a 32-bit selection value in a caller-supplied object. It supports two paths:

- An ordinary selection, accepted only when its signed interpretation is nonnegative and its unsigned value is below a bound supplied by F-edaebf7a95e5.
- A distinguished selection value, `0xFFFFFFFF`, accepted without consulting that bound.

After acceptance, the function records the selection, performs a path-specific operation, and invokes two common dependencies in a fixed order. Its normal return is either `0x00000000` for a completed accepted path or `0xFFFFFFCE` for a rejected selection.

“Selection,” “bound,” and “object” are descriptive terms. Their application-level meanings are not established. In particular, the distinguished value might represent a cleared or inactive selection, but that interpretation is inferred intent, not a demonstrated contract.

## Interface

### Inputs

The function receives two 32-bit arguments:

1. **Object address.** A value used as a base address for direct writes and for constructing arguments to dependencies.
2. **Selection value.** An unsigned 32-bit value. Its bit pattern is also interpreted as a signed 32-bit integer during validation.

No object length, allocation metadata, ownership flag, or explicit error-output location is supplied.

### Return value

The return is a 32-bit result:

| Result | Established meaning |
|---|---|
| `0x00000000` | The accepted path reached its final return after the path-specific operation and both common dependency calls returned. |
| `0xFFFFFFCE` | The selection failed this function’s validation. |

`0xFFFFFFCE` corresponds to −50 under a signed 32-bit interpretation. No particular error-code namespace is established.

A zero result does not independently prove that a dependency achieved its intended effect. The function does not inspect the results of its path-specific or common post-processing calls.

### Relevant storage layout

Only these object-relative locations are exposed by the supplied representation:

| Offset or address rule | Use |
|---|---|
| Object base + `0x20` | Destination of a 32-bit selection write on every accepted path. |
| Object base + `0xA2C` | Address passed as the third argument to F-876535e132c4 on the ordinary-selection path. |
| Object base + `0xEC8` | Address passed to F-edaebf7a95e5 during ordinary-selection validation. |
| Object base + a global-derived offset | Destination of a 16-bit zero write on the distinguished-value path. |

The sizes and structures of the regions beginning at `0xA2C` and `0xEC8` are unknown. Passing those addresses does not establish a particular field type or minimum extent.

The global-derived offset is not provided as a known constant. It must not be replaced with a guessed field location.

### Preconditions

The function performs no explicit null, bounds, alignment, or object-lifetime checks. For defined execution, the caller must provide addresses and storage valid for the operations actually reached, including dependency-specific accesses.

Address construction uses a 32-bit base value and offsets in the supplied representation. Behavior at address-space boundaries, including wrapping or invalid resulting addresses, is not independently established. A portable contract must not promise safe handling of such inputs.

## Behavior

### Validation

Validation distinguishes `0xFFFFFFFF` before applying the ordinary signed-value restriction.

For `0xFFFFFFFF`:

- The selection is accepted without calling F-edaebf7a95e5.
- Its negative signed interpretation does not cause rejection.
- Processing proceeds to the distinguished-value path.

For every other value:

1. The selection’s 32-bit bit pattern is interpreted as signed.
2. If that interpretation is negative, the function immediately returns `0xFFFFFFCE`.
3. Otherwise, the function calls F-edaebf7a95e5 with the object base plus `0xEC8`.
4. The low 32 bits of that dependency’s result are compared with the selection as unsigned values.
5. If the returned low word is less than or equal to the selection, the function returns `0xFFFFFFCE`.
6. If the returned low word is strictly greater than the selection, processing continues on the ordinary-selection path.

Consequently:

- Values from `0x80000000` through `0xFFFFFFFE`, inclusive, are rejected without calling any listed dependency.
- Values from `0x00000000` through `0x7FFFFFFF`, inclusive, require the bound query.
- Equality with the returned bound is rejected.
- `0xFFFFFFFF` is a distinct case, not an ordinary index checked against the bound.

The bound comparison is unsigned. A returned low word with its top bit set can therefore admit an ordinary selection as large as `0x7FFFFFFF`.

Only the low 32 bits of the bound dependency’s result affect acceptance. Any higher portion represented in the supplied expression has no established effect on the function’s accepted ordinary path.

### Distinguished-value path

For the selection `0xFFFFFFFF`, the function performs the following ordered operations:

1. Obtains a global-derived value used as the object-relative offset for a later write.
2. Writes the 32-bit value `0xFFFFFFFF` at object offset `0x20`.
3. Writes a 16-bit zero at the object base plus the previously obtained offset.
4. Calls F-a96742fec78e with the object base.
5. Calls F-087700124fe9 with the object base.
6. Returns `0x00000000`, provided execution reaches that return.

Neither F-edaebf7a95e5 nor F-876535e132c4 is called by this path.

The global-derived offset is obtained before the 32-bit selection write. The contract does not establish that the offset is positive, aligned, within the object, or disjoint from offset `0x20`.

If the 16-bit destination overlaps the earlier 32-bit selection destination, the zero write follows and may partially overwrite the recorded selection. The subsequent dependencies may modify it again. Therefore, acceptance of the distinguished value does not by itself guarantee that the final contents at offset `0x20` remain `0xFFFFFFFF`.

### Ordinary-selection path

After a nonnegative ordinary selection passes the bound comparison, the function:

1. Writes the selection as a 32-bit value at object offset `0x20`.
2. Calls F-876535e132c4 with three arguments, in this order:
   - The object base.
   - The original selection value.
   - The object base plus `0xA2C`.
3. Calls F-a96742fec78e with the object base.
4. Calls F-087700124fe9 with the object base.
5. Returns `0x00000000`, provided execution reaches that return.

There is no intervening branch based on the result of F-876535e132c4 or either common dependency. The function does not re-read the stored selection to construct these call arguments.

### Rejection and interruption

For a signed-negative value other than `0xFFFFFFFF`, rejection occurs before any explicit object write, global-derived offset read, or dependency call shown here.

For a nonnegative value rejected by the bound comparison, F-edaebf7a95e5 has already executed. The function then returns without its own selection write and without invoking the other three dependencies.

These are different side-effect cases. Bound-based rejection must not be described as globally side-effect-free, because the bound dependency’s behavior is unknown.

The representation establishes no recovery or cleanup path for faults, nonlocal exits, or dependencies that do not return. Later operations and the normal return are conditional on earlier operations completing.

## Side effects

### Directly established effects

The function itself performs:

- One 32-bit write at object offset `0x20` on every accepted path.
- One additional 16-bit zero write on the distinguished-value path.
- A read of a global-derived offset on the distinguished-value path.
- Dependency calls in the order specified above.

There is no direct allocation, deallocation, ownership transfer, or explicit synchronization operation shown.

### Dependency-mediated effects

Dependency calls may read or modify the object, other reachable storage, or global state. Their preservation properties are not supplied.

In particular, the contract does not establish that:

- The bound query is pure or preserves the object.
- F-876535e132c4 writes only through its third argument.
- Either common dependency preserves the selection field.
- Any dependency preserves the global value used by the distinguished-value path.
- Dependencies retain or do not retain supplied addresses.
- Dependencies allocate, release, or preserve ownership of referenced memory.

On the ordinary path, the explicit selection write occurs after the bound query returns. On both accepted paths, the common dependencies execute after the path-specific operation. These orderings remain meaningful even when dependencies have additional unknown effects.

The order described is execution order in the supplied representation, not a claim about atomicity, concurrent visibility, or cross-thread memory ordering.

## Acceptance examples

These examples are conditional acceptance criteria derived from static evidence. They have not been executed. Unless an example concerns early rejection, assume valid storage and that every reached dependency returns normally.

### Ordinary selection below the bound

Given selection `3` and a low-word result of `4` from F-edaebf7a95e5:

- The bound dependency receives object base + `0xEC8`.
- A 32-bit `3` is then written at object offset `0x20`.
- F-876535e132c4 receives the object base, `3`, and object base + `0xA2C`.
- F-a96742fec78e runs next, followed by F-087700124fe9.
- The function returns zero.

The final contents of the selection field depend on the called functions’ behavior.

### Selection equal to the bound

Given selection `4` and a low-word bound result of `4`:

- The bound dependency executes.
- The function returns `0xFFFFFFCE`.
- No direct selection write or later dependency call occurs.

Effects already performed by the bound dependency are not undone.

### Empty bound

Given selection `0` and a low-word bound result of `0`, the function rejects the selection. Zero is not accepted when the exclusive upper bound is zero.

### Unsigned high bound

Given selection `0x7FFFFFFF` and a low-word bound result of `0x80000000`, validation succeeds. The bound is compared as unsigned, despite its negative signed interpretation.

### Negative ordinary value

Given selection `0x80000000` or `0xFFFFFFFE`:

- The function returns `0xFFFFFFCE`.
- No listed dependency is called.
- No direct object write shown in this function occurs.

A large returned bound cannot make either value acceptable, because the bound query is never reached.

### Distinguished value

Given selection `0xFFFFFFFF`:

- No bound query occurs.
- The global-derived offset is obtained.
- The 32-bit distinguished value is recorded.
- The 16-bit zero write occurs at the global-derived destination.
- F-a96742fec78e and then F-087700124fe9 execute.
- The function returns zero.

If the two write regions overlap, acceptance requires preserving their stated order, not preserving the first write’s complete value.
