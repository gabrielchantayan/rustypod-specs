# F-2a0a793390b7

## Purpose

F-2a0a793390b7 conditionally performs a sequence of state updates and delegated operations on a caller-supplied context.

A zero second input disables the entire sequence. A nonzero second input enables:

1. An optional context-state update and call to F-d894690ab67a, controlled by a one-byte context field.
2. An optional call to F-fc9444c74c1d, controlled by a subsequently read 32-bit context field.
3. A call to F-ab545ff44214.

The established behavior is this sequence, its arguments, and its direct memory accesses. The higher-level purpose of the context fields and delegated operations is unknown. In particular, the evidence does not establish that the final dependency performs cleanup, that any field represents an owned resource, or that any call releases memory.

## Behavior

### Inactive path

If the activation value equals zero, the function returns without:

- Reading any of the listed context fields.
- Writing context storage.
- Calling any of the three dependencies.

The auxiliary inputs do not affect this decision.

### Optional preparation phase

If the activation value is nonzero, the function first reads the byte at context offset `0xD8`.

If that byte is zero, this phase performs no copy, no clearing write, and no call to F-d894690ab67a.

If that byte is nonzero, the following operations occur in order:

1. Read the 32-bit word at offset `0xD4` and write that word to offset `0xB8`.
2. Write a 32-bit zero to offset `0xB4`.
3. Call F-d894690ab67a with six arguments:
   - The context address.
   - The constant `0x2D`, numerically 45.
   - Auxiliary word A.
   - Auxiliary word B.
   - Auxiliary word A again.
   - Auxiliary word B again.

The copy preserves the source word’s bits; no numeric conversion or interpretation is shown. The zero write clears all 32 bits at `0xB4`, not merely its low byte.

Both writes precede the dependency call. However, the function does not restore those values afterward. F-d894690ab67a may alter them or other state; no preservation guarantee is available.

The control byte is tested once by this body. A dependency changing it later does not cause this phase to repeat.

### Conditional delegated operation

After the optional preparation phase has completed, including a normal return from F-d894690ab67a if called, the function reads the 32-bit field at context offset `0xB0` and compares it with zero.

If the field is zero, F-fc9444c74c1d is not called.

If the field is nonzero, the function calls F-fc9444c74c1d with six arguments:

| Position | Value |
|---:|---|
| 1 | A fresh 32-bit read from context offset `0xB0`. |
| 2 | A 32-bit read from context offset `0xB4`, masked with `0xFF`. |
| 3 | The original activation value, unchanged. |
| 4 | Zero. |
| 5 | Zero. |
| 6 | Zero. |

The mask restricts the second argument to the range 0 through 255. It selects the low eight bits of the loaded 32-bit value; it is not evidence of a one-byte memory read. For example, a loaded value of `0x123456AB` produces an argument of `0xAB`, numerically 171.

The field at `0xB0` is not captured once and reused throughout this phase: the supplied representation shows a condition read followed by an argument read. No intervening local write or dependency call is shown, but external changes could matter in an environment that permits them. The evidence supplies no concurrency or volatile-memory contract.

The ordering between the two argument-producing reads, at `0xB0` and `0xB4`, is not established. Both supply arguments before F-fc9444c74c1d is entered.

Crucially, this phase uses context state read after F-d894690ab67a returns. It does not necessarily use the state present at function entry. In particular:

- F-d894690ab67a can affect whether the `0xB0` test succeeds.
- Clearing `0xB4` earlier does not guarantee a zero second argument if F-d894690ab67a subsequently changes that field.
