## Behavior

### Initial local state

Before copying any source bytes, the function initializes a 32-bit local word.

Its bit pattern consists of:

- Bits 0–7: the first input.
- Bits 8–31: bits 8–31 of the third input’s unsigned 32-bit representation.

Thus, the low byte of the numerical source address is discarded from this initial word, while its upper three bytes are retained.

The representation identifies a one-byte local region followed by a three-byte local region within this initialized word. The copy destination begins at the three-byte region, one byte after the beginning of the word.

On a little-endian target, the initialized byte layout is:

| Offset from the word’s beginning | Initial contents |
|---|---|
| 0 | First input |
| 1 | Source-address bits 8–15 |
| 2 | Source-address bits 16–23 |
| 3 | Source-address bits 24–31 |

On a big-endian target, storing the same numerical word gives a different byte layout. In that case, the first byte at the submitted pointer is not established to be the first input. The intended selector-and-payload interpretation therefore requires a target-layout assumption; it is not established by the concatenation operation alone.

After initializing this word, the function assigns the fourth input to a separate 32-bit local word. This assignment precedes the copy loop.

### Byte copying

The loop counter starts at zero. An iteration occurs only while the counter is less than the signed second input.

For a positive count, iterations proceed in increasing offset order, from zero through one less than the count. Each iteration:

- Reads one byte at the source address plus the current offset.
- Writes that byte to the local copy destination plus the same offset.
- Advances the counter by one.

The source read supplies the byte written during that iteration. The operation is a forward byte copy, not an atomic snapshot and not an established overlap-safe move.

The copy starts one byte after the beginning of the initialized local word. On the little-endian interpretation, it preserves the selector at offset zero while replacing the address-derived bytes beginning at offset one.

For a count of one, only the first address-derived byte is replaced. For a count of two, the first two are replaced. For a count of three, all three address-derived bytes are replaced.

A count greater than three writes beyond the three-byte local region explicitly identified as the copy destination. The available representation does not establish a suitably sized message array. It therefore does not establish a safe maximum payload greater than three bytes.

The separate 32-bit local word may occupy nearby stack storage, but its exact byte offset, padding, and suitability as additional message capacity must not be assumed from the displayed local declarations alone. In particular, the fourth input must not be treated as a deliberate trailing message field.

### Zero and negative counts

- No source bytes are read by this loop.
- No copy-destination bytes are written by this loop.
- The dependency invocation is still reached, provided the preceding local initialization completes normally.
