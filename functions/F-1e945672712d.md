# F-1e945672712d

## Purpose

F-1e945672712d conditionally changes an object's state and dispatches an indirect callback. Its behavior depends on a zero/nonzero selector, a two-bit state field captured on entry, and, for one transition, the state of a related object.

Two paths can reach the callback:

- A zero selector invokes dependency F-0f9e751358c3 with mask `0x600`, then dispatches callback argument `0` only if the object's entry state, masked by `0x600`, was `0x200`.
- A nonzero selector requires the object's entry state, masked by `0x600`, to be `0x600`. If a related object exists and its masked state is `0x200`, the function invokes F-0f9e751358c3 with mask `0x200`, then dispatches callback argument `1`. Otherwise, it directly replaces the object's masked state with `0x400` and returns.

These are established control-flow facts. Interpreting the states as activation, visibility, selection, or another application concept would be inferred intent, not an established contract.

## Interface

**Inputs**

1. **Object address.** An address used to access a word-oriented object representation.
2. **Selector.** An integer tested only for equality with zero. All nonzero values take the same branch; the original selector value is not forwarded to either dependency.

**Output**

There is no explicit result value. Observable results consist of dependency calls, an optional direct state write, callback dispatch, and any effects caused by those callees.

**Relevant object layout**

The supplied representation uses 32-bit integer words. The following byte offsets follow from that representation:

| Offset | Role | Access |
|---|---|---|
| `0x00` | Address of an indirect-dispatch table | Read only when dispatch is reached, after F-0f9e751358c3 returns |
| `0x34` | Related-object address | Read only on the eligible nonzero-selector path |
| `0x48` | Object state word | Read on entry; read again and written on the direct-update path |

A related object is inspected at its own offset `0x48`, as a 32-bit unsigned state word.

The dispatch table contains a callable address at byte offset `0xC8`, equivalent to decimal offset 200. The callback receives the original object address and an integer argument of either `0` or `1`.

**Widths and representation limits**

The state operations are 32-bit operations. The mask `0x600` selects bits 9 and 10, counting the least significant bit as bit 0. The complement mask used for the direct update is `0xFFFFF9FF`.

The supplied representation carries object and table addresses through 32-bit-looking fields. A 32-bit address model is therefore indicated, but the target ABI, address alignment rules, callable-pointer representation, and callback calling convention are not independently established. The offsets above describe the supplied layout, not a portable host-language structure.

The object address must permit the initial state read. Each subsequently reached access must also be valid:

- A related-object address must permit its state read when nonnull and inspected.
- The direct-update path requires a writable object state word.
- A dispatch path requires a readable table-address field, a readable callback entry, and a callable target after the helper returns.
- F-0f9e751358c3 must accept the object and supplied mask for execution to proceed normally.

The function does not validate the main object address, dispatch-table address, or callback address.

## Behavior

### Entry snapshot

Before testing the selector, the function reads the object's 32-bit state word at offset `0x48`. This value is the **entry snapshot**.

Eligibility checks against the object's state use this snapshot. In particular, the zero-selector branch does not recompute callback eligibility after the helper call.

For branch decisions, the relevant masked states are:

| Masked value | Bits 10 and 9 |
|---|---|
| `0x000` | Both clear |
| `0x200` | Bit 9 set, bit 10 clear |
| `0x400` | Bit 10 set, bit 9 clear |
| `0x600` | Both set |

Bits outside `0x600` do not affect these comparisons.

### Zero selector

When the selector is zero:

1. F-0f9e751358c3 is invoked with the original object address and mask `0x600`.
2. After that call returns, the function tests the entry snapshot masked by `0x600`.
3. If the masked snapshot is not `0x200`, the function returns without dispatching the callback.
4. If it is `0x200`, the function obtains the object's dispatch-table address, obtains the callback address at table offset `0xC8`, and invokes it with the original object address and argument `0`.

The helper call is unconditional within this branch. A zero selector with an ineligible entry state therefore still has helper-mediated effects.

The related-object field is not consulted on this branch.

The callback target is resolved after the helper returns. It is not saved before the helper call. Consequently, any helper-induced change to the dispatch-table field or table entry may affect the callback selected, provided those accesses remain valid.

### Nonzero selector: initial eligibility

When the selector is nonzero, the function first compares the masked entry snapshot with `0x600`.

If it differs, the function returns immediately. This path performs no related-object inspection, no direct state write, no helper call, and no callback dispatch.

If the masked entry snapshot is `0x600`, execution proceeds to the related-object test.

### Nonzero selector: related-object test

The related-object test succeeds only when both conditions hold:

- The related-object address at offset `0x34` is nonzero.
- The related object's 32-bit state at offset `0x48`, masked by `0x600`, equals `0x200`.

A zero related-object address short-circuits the test: no related-object state access is required in that case.

The supplied expression refers to the related-object field for the null check and again for the state access. It does not establish an atomic pointer-and-state snapshot or synchronization against concurrent mutation.

### Nonzero selector: failed related-object test

If the related-object test fails, the function directly changes the original object's state.

The replacement uses the state word read at the time of this update, not the entry snapshot:

- Clear bits 9 and 10 with `0xFFFFF9FF`.
- Set bit 10 with `0x400`.
- Write the resulting 32-bit word back to offset `0x48`.

Thus, the written value has masked state `0x400`, while every bit outside `0x600` matches the state word used for this update.

The function then returns. It does not call F-0f9e751358c3 or dispatch the callback on this path.

This is the only direct object write visible in F-1e945672712d itself.

### Nonzero selector: successful related-object test

If the related-object test succeeds:

1. F-0f9e751358c3 is invoked with the original object address and mask `0x200`.
2. After the helper returns, the function obtains the object's dispatch-table address and the callback entry at table offset `0xC8`.
3. The callback is invoked with the original object address and argument `1`.

The function does not recheck either object's state after the helper call. A helper-induced change to either state does not, by itself, cancel the already-selected dispatch path.

### Ordering and completion

On either callback path, the helper precedes callback-target resolution, which precedes callback invocation. There is no subsequent explicit state update.

Normal completion assumes that invoked callees return normally and leave subsequent required accesses valid. No recovery path is visible for a failed access, invalid indirect target, or nonreturning callee.

- The failed related-object path directly rewrites the original object's state as described above.
