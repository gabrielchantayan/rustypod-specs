# F-a938d9f3232b

## Purpose

F-a938d9f3232b accepts three represented 32-bit arguments, executes a long sequence of indirect invocations, performs ordered memory reads and mutations, and supplies four arguments to an unresolved final indirect target.

The supplied static representation establishes data transformations and access ordering, but not an application-level purpose. Formatting, serialization, initialization, device control, and object construction are not established interpretations.

The behavioral boundary includes intermediate calls, reads, overlapping accesses, and repeated writes. Matching only the final memory contents is insufficient where memory accesses or dependencies have observable effects.

This contract separates established static evidence from conditional arithmetic interpretation and unresolved behavior. No runtime tests have been performed.

### Arithmetic and widths

Explicit memory operations distinguish bytes, halfwords, and words:

- Byte stores retain eight bits.
- Halfword stores write 16 bits.
- Word stores write 32 bits.
- Explicit unsigned-byte reads become values from 0 through 255 when expanded to words.
- Represented paired results contain two 32-bit halves.

Where this contract describes modular arithmetic, it means retaining the low 32 bits after each 32-bit operation. This is a conditional machine-width interpretation, not an independently verified architectural rule for every signed-looking expression.

Under that interpretation:

- A left shift by eight followed by an unsigned right shift by eight retains the original low 24 bits.
- Successive left shifts can lose information before a later transformation.
- Two successive left shifts by 28 yield zero.
- Shifting left by 16 and then masking to 16 bits yields zero.
- Masking before a shift is not generally equivalent to masking afterward.
- Unsigned right shifts are logical.

A terminal right shift uses the low eight bits of an address-like value as its count. Counts can exceed 31. Oversized-count behavior, and the architectural treatment of the signed operand, remain **documented_only**.

The opening mutation group writes Saved-base as a word at Result-high + 0x14. Two byte writes to Saved-base + 9 surround a word write of Scaled-base at 256 × Result-low + 0x54. The first byte uses Result-high’s low byte; the second uses Saved-base’s low byte.

Next, a zero word at Scaled-base + 0x14 precedes an unsigned-byte read at Scaled-base + 5. A zero word at Small-base + 0x14 precedes expansion of that byte into a word at Scaled-base + 0x34. The function then captures the word at Scaled-base + 0x14, writes another zero word at Small-base + 0x14, and writes the captured word’s low byte twice at Small-base + 0x15.

### Low-address global and initial traversal

After those two byte writes, the named global associated with address 0x05 is evaluated and converted to unsigned 32 bits. Call the converted value **Global-derived-base**.

Its declaration is absent. Unlike an explicit unsigned-byte dereference, this expression does not establish an eight-bit read or zero-extension from an unsigned byte. Its source width and signedness are **documented_only**. Global-derived-base is not established to lie between 0 and 255.

The subsequent byte write at absolute address 0x01 uses Small-base’s low byte. The following derived mutations include:

- Small-field’s low byte at Global-derived-base + 0x15.
- Saved-word’s low byte at Scaled-base + 0x11.
- Saved-word as a word at the previously captured word + 0x54.
- Zero as a byte at Scaled-base + 0x11.

Only after these effects does the function capture a word at Global-derived-base + 0x54 and replace that location with the earlier captured word. Call the newly captured value **Loaded-word**. Small-field is subsequently written as a word at Small-base + 0x34.

A word read at Scaled-base + 0x74 becomes another destination base. Its offset 0x54 receives twice Scaled-base under modular interpretation. Separately, the word at Small-base + 0x74 occurs twice in one nested read/write expression: one occurrence supplies a destination base and the other supplies the stored value. The representation does not justify merging these into one cached read or establishing an order between those two operand reads.

Terminal captures are interleaved with mutations; they do not all precede the first terminal write.

First, the function captures a 32-bit word from absolute address 0xA9 and another word from twice Traversal-base + 0x74. It then writes a byte at absolute address 0x3A containing the low eight bits of eight times Adjusted-base plus 0x30.

**After that absolute byte write**, it captures a word at Traversal-base + 0x14 and a word at Region-base + 4. The former is retained for the third terminal argument.

The next mutations include byte writes at Traversal-base + 0x0D and Region-base offsets 8, 0x0D, and 9. Offset 8 receives 0x6C. Traversal-base + 0x54 receives Traversal-base as a word.

The 0xA9 capture remains separately available as a full word for a later store at Region-base + 0x44.

### Absolute-write placement

If Loaded-word is 0x12345678, the absolute word write at 0x54 supplies 0x2468ACF0 under modular interpretation. It occurs between the Small-base + 0x14 write of twice Scaled-base and the subsequent writes of Loaded-word there.

The absolute byte write at 0x15 uses Small-base’s low byte, after the two derived offset 0x15 writes and before the following Quad-base + 0x54 write.

### Captured global base

If the absolute 0x60 write changes storage holding the separately named global base, later repeated groups still use the value captured before that write. Reloading the global for each group would change the contract.

### Terminal aliasing

If an intervening derived write changes address 0x67, a later Region-base + 9 store uses the subsequently read byte, not necessarily the low byte captured from 0xA9.

If the 0x3A write aliases either terminal capture location read afterward, those captures must reflect the later access, not a pre-mutation snapshot.

### Unknown global declaration

A model that always restricts Global-derived-base to 0–255 is unsupported. Acceptance requires the missing declaration or an explicit environmental assumption before imposing that range.

### Partial completion

If a derived destination is inaccessible, normal completion is not promised. Earlier writes need not be undone. Consecutive identical writes remain distinct candidate observable events.
