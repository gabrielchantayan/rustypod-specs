# F-fea7669eb646

## Purpose

F-fea7669eb646 writes two adjacent 32-bit fields in caller-supplied storage. The field at byte offset 4 receives the supplied 32-bit argument. The field at byte offset 0 receives a value captured from a fixed global source before either write.

The established order is significant: capture the global value, write the second field, then write the first field. If the second-field write overlaps the global source, the first field still receives the value captured before that write.

The global source may also overlap destination storage. Consequently, existing destination contents can be an input: when a destination field supplies the global read, its previous contents influence the result. There is no separate read through the destination argument.

An interpretation such as initializing a two-field record is plausible intent, not an established object model. Neither field’s semantic meaning is known.

## Behavior

### Ordered accesses

The static representation establishes the following sequence:

1. Capture one 32-bit value from the global source.
2. Write the supplied 32-bit value to destination byte offset 4.
3. Write the captured global value to destination byte offset 0.
4. Return without a declared result.

No branch, loop, or callable dependency is visible.

The global source is not reread between the two destination writes. Changing that source after the initial read does not substitute a different value for the captured value used by the first-field write.

This sequence describes the supplied static representation. It does not establish a synchronization protocol or guarantee how concurrent observers perceive the accesses.

### Existing destination contents

There is no separate destination-content read beyond the global-source read. In particular, the function does not inspect either field through the destination argument before overwriting it.

That does **not** mean destination contents can never be read:

- If the global source is disjoint from both fields, neither field’s previous contents supplies the global input.
- If the global source is the first field, the initial read captures that field’s previous value.
- If the global source is the second field, the initial read captures that field’s previous value, which subsequently becomes the first field’s stored value.
- If a valid partial overlap exists, overlapping destination bytes may contribute to the captured input. Their interpretation depends on the environment’s layout and access rules.

Independence from previous destination contents therefore applies only to contents that do not contribute to the global-source read. Equivalently, for executions with the same captured global value and supplied value, changing other prior destination contents does not change the two stored values.

There is no visible release, destruction, or ownership-management action for overwritten contents. Reading an aliased old value as the global input does not establish any resource-management semantics for it.

### Exact aliasing

The supplied representation does not state a disjointness requirement between the global source and destination storage.

**Global source equals the second field:** The previous second-field value is captured first. The second field is then replaced by the supplied value, and the first field receives the previous second-field value.

**Global source equals the first field:** The previous first-field value is captured first. The second field receives the supplied value, after which the captured value is written back to the first field. Equality of the first field’s initial and final values does not remove the final write from the represented sequence.

These outcomes are conditional on the overlapping accesses being valid in the execution environment. The evidence does not establish broader language-level aliasing permissions.

### Partial overlap

No dedicated overlap-handling path is visible. The function performs the same initial read and two writes.

A partial overlap can make prior destination bytes part of the global input, and a destination write can modify bytes belonging to the global source. Exact byte-level outcomes require byte order, alignment, and memory-access semantics not supplied here.

The captured value remains the input to the final first-field write; it is not recomputed from storage after the second-field write.

## Side effects

The global source has no separate explicit write. Nevertheless, either destination write can change its storage through overlap. A claim that the global source remains unchanged is valid only when destination writes do not overlap it and no external actor changes it.

No explicit allocation, deallocation, resource acquisition, reference-count operation, callback, or ownership transfer is visible. The function uses caller-supplied destination storage without establishing its lifetime or returning replacement storage.
