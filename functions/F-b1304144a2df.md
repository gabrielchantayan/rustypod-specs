# F-b1304144a2df

## Purpose

F-b1304144a2df conditionally updates two fields in a caller-supplied memory region. It compares a stored 32-bit value and, only when that value matches, a stored unsigned byte against two requested values.

If either comparison fails, it invokes an external dependency with an address inside the same region and an externally supplied datum. After that dependency returns normally, it stores the requested 32-bit value and the low eight bits of the other requested value.

**Established behavior:** the second requested value is compared at its full 32-bit width but stored at an eight-bit width. Consequently, requests above 255 cannot be recognized as already satisfied by the stored byte.

**Inferred intent:** the two stored fields appear to act as a change-detection key for an associated region beginning immediately after them. Neither the meaning of that key nor the purpose of the associated region is established.

## Behavior

### Comparison and branch selection

The first direct memory access is a four-byte read at offset 8. Its unsigned 32-bit value is compared with the requested word.

If those values differ, the function selects the update path immediately. It does **not** directly read the byte at offset 12 before invoking the dependency.

If the word values match, the function reads the byte at offset 12. That byte is interpreted as unsigned and widened to a value in the range 0 through 255. The widened value is compared with the entire unsigned 32-bit requested byte candidate.

Only the following conjunction selects the unchanged path:

- The stored word equals the requested word.
- The stored byte, interpreted as a number from 0 through 255, equals the full requested byte candidate.

When both comparisons succeed, the function returns without invoking the dependency and without directly writing either field.

This comparison is not a comparison against the candidate’s low eight bits. A requested byte candidate of 256 does not match a stored byte of 0. A candidate of 511 does not match a stored byte of 255.

### Update path

If either comparison fails, the function invokes the dependency identified here as **F-unresolved-1**. This is a document-local opaque identifier; no canonical dependency ID was supplied.

The invocation receives:

1. The address obtained by advancing 13 bytes from the input region address.
2. A datum referenced from external storage in the supplied evidence.

The function does not pass the requested word or requested byte candidate as separate explicit arguments to that dependency.

Only after the dependency returns normally does F-b1304144a2df perform its two direct stores:

1. It writes the requested word to the four-byte field at offset 8.
2. It writes the low eight bits of the requested byte candidate to the byte at offset 12.

It then returns.

The comparison results are not revalidated after the dependency returns. In particular, dependency-side changes to the compared fields do not suppress the subsequent stores.

### Width and arithmetic rules

The word comparison and word store use 32-bit unsigned values.

The byte comparison uses a zero-extended eight-bit stored value against a full 32-bit unsigned input. The byte store retains the candidate modulo 256.

There is no visible arithmetic on the requested word. The only reduction of the requested byte candidate occurs when writing the byte.

Address calculations use the input address plus fixed byte offsets. The evidence does not establish defined handling of address overflow or invalid derived addresses; callers must not rely on wraparound to obtain a valid object.

### Repeated calls

For a requested byte candidate from 0 through 255, a completed update leaves the two fields equal to the requested values. A later invocation with the same arguments takes the unchanged path if no intervening activity changes those fields.

For a requested byte candidate above 255, a completed update cannot make the stored byte equal to that full candidate. A later invocation with the same arguments therefore selects the update path again, assuming the field reads remain valid and the word still matches.

This repeated update behavior follows from the comparison and storage widths. It must not be replaced in the contract with normalized-byte equality.

## Side effects

### Direct memory effects

On the unchanged path, the function performs no direct writes and makes no visible dependency call.

On the update path, it directly writes exactly the two identified fields after normal dependency return. It does not directly write offsets 0–7 or any byte at or beyond offset 13 in the supplied evidence.

These limits describe this function’s own accesses, not the dependency’s effects.

### Ordering

The established execution order is:

- Read the word.
- Read the byte only if the word matches.
- Invoke the dependency if either comparison fails.
- After normal dependency return, store the word.
- Store the byte.
- Return.

The dependency is therefore invoked before this function commits either requested field value. Its own actions may nevertheless alter those fields before or during its execution.

These ordered operations do not establish atomic publication, synchronization, or a transaction visible to concurrent observers. No lock, barrier, rollback, or concurrency protocol is shown.

### Ownership and lifetime

No direct allocation or deallocation appears in F-b1304144a2df. The function passes an interior address into caller-supplied storage to the dependency.

The dependency’s ownership and lifetime behavior is unknown. It must not be assumed to preserve the region, preserve global state, avoid retaining the interior address, or avoid releasing memory.

Normal completion requires the destination fields to remain valid for the post-call stores. Whether the actual dependency guarantees that condition is documented_only.

### Failure behavior

There is no visible local error-handling branch.

If the dependency does not return normally, the subsequent direct stores are not reached through the ordinary control flow. Any effects already caused by the dependency are not visibly rolled back.

Invalid memory access behavior, dependency-specific failures, and asynchronous interruption behavior are not defined by the supplied evidence.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, memory accesses are valid and the dependency returns normally.

1. **Exact match**

   Given a stored word of 42, a stored byte of 7, and requested values 42 and 7:

   - The word is read, then the byte.
   - F-unresolved-1 is not invoked.
   - Neither field is directly written.

2. **Word mismatch**

   Given a stored word of 41 and requested values 42 and 7:

   - The word read selects the update path.
   - This function does not directly read the stored byte before the dependency call.
   - The dependency receives the interior address at offset 13.
   - After return, the function stores word 42, then byte 7.

   The dependency may independently access the byte; that is outside this function’s established direct-read sequence.

3. **Byte mismatch**

   Given a stored word of 42, a stored byte of 6, and requested values 42 and 7:

   - Both fields are read in word-then-byte order.
   - The dependency is invoked once by this execution.
   - After return, the word is written even though it already compared equal.
   - The byte is then written as 7.

4. **Candidate outside the byte range**

   Given a stored word of 42, a stored byte of 0, and requested values 42 and 256:

   - The byte comparison fails because 0 is not 256.
   - The dependency is invoked.
   - The resulting direct stores are word 42 and byte 0.
   - Repeating the request still selects the update path.

5. **Largest unsigned candidate**

   With requested byte candidate 4,294,967,295:

   - No stored unsigned byte can satisfy the full-width comparison.
   - The update path is selected regardless of the stored byte.
   - After normal dependency return, the byte store produces 255.

6. **Dependency modifies the compared fields**

   If an update is selected and the dependency writes different values to offsets 8 and 12 before returning, this function subsequently overwrites those fields with the requested word and the candidate’s low eight bits. It performs no intervening comparison.

7. **Dependency does not return normally**

   If the dependency terminates or transfers control without an ordinary return, the contract does not promise either subsequent direct store. It also does not promise rollback of dependency effects.
