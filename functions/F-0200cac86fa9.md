# F-0200cac86fa9

## Purpose

F-0200cac86fa9 scans a count-bounded collection starting at a supplied unsigned index. Each examined entry supplies three 16-bit values and a 16-bit descriptor. A descriptor of 65,535 causes the scan to continue; any other descriptor causes success.

The routine publishes the three values from every examined entry, including skipped entries. Only an accepted entry causes it to publish an accepted index and a resolved reference address.

Failure therefore does not necessarily preserve the object. An immediately out-of-range request performs no result writes, but exhaustion after one or more skipped entries leaves the last examined entry’s three values published without updating the accepted index or resolved reference.

The semantic meanings of the three values and the referenced resource are unknown. “Skipped” and “accepted” describe demonstrated control flow, not an independently established format interpretation.

## Interface

### Arguments

The routine takes two arguments:

- **Object address:** a 32-bit address representation identifying an object with the readable and writable fields listed below.
- **Starting index:** an unsigned 32-bit integer identifying the first entry to examine.

No separate buffer length, error-output argument, or ownership flag is supplied.

### Object layout

Offsets are byte offsets from the object address. Every listed object-field access has a width of 32 bits.

| Offset | Access | Established role |
|---|---|---|
| `0x10` | Read | Backing-storage address, loaded separately for each examined entry |
| `0x20` | Read | Unsigned entry count, captured once before the first bounds decision |
| `0x24` | Write on success | Accepted index |
| `0x28` | Write for each examined entry | Zero-extended second decoded value |
| `0x2C` | Write for each examined entry | Zero-extended first decoded value |
| `0x30` | Write for each examined entry | Zero-extended third decoded value |
| `0x34` | Write on success | Resolved reference address, or zero |

There are **five result fields**: `0x24`, `0x28`, `0x2C`, `0x30`, and `0x34`. The backing-address and count fields are inputs, not additional result destinations.

### Return value

The return is a 32-bit bit pattern:

| Result | Meaning |
|---|---|
| `0x00000000` | An entry with a descriptor other than 65,535 was accepted |
| `0xFFFFFFFF` | The current index reached or exceeded the captured count |

The failure value may be interpreted by a caller as signed −1 or unsigned 4,294,967,295. The supplied evidence does not establish the caller’s interpretation.

There is no distinct return value for an invalid address, inaccessible storage, or an invalid referenced resource.

### Storage preconditions

For ordinary defined execution:

- The object’s count field must be readable, even if the starting index is out of range.
- Each examined entry requires a readable backing-address field and readable bytes at all four calculated two-byte locations.
- The three decoded-value fields must be writable whenever an entry is examined.
- The accepted-index and resolved-reference fields must be writable when an entry is accepted.
- Object-field accesses must satisfy the target’s alignment and address-validity requirements.
- Address calculations must identify valid storage under the target’s arithmetic and pointer rules.

No null checks, storage-length checks, alignment checks, or explicit overflow rejection are established.

## Behavior

### Count capture and bounds decisions

The routine first reads the unsigned 32-bit count from object offset `0x20`. Call this captured count **N**.

The starting index becomes the current unsigned 32-bit index, **k**. Before examining an entry, the routine compares k with N using unsigned ordering:

- If k is at least N, return `0xFFFFFFFF`.
- Otherwise, examine entry k.

Every later bounds decision uses the same captured N. The count field is not reread during the scan.

An initial count of zero always causes immediate failure. An initially out-of-range index causes no backing-address read, encoded-data read, or result-field write.

### Encoded locations

For each in-range entry, the routine reads the backing address from object offset `0x10`. Call that iteration’s loaded address **B**.

For valid, non-overflowing calculations, the four two-byte quantities begin at:

| Quantity | Address |
|---|---|
| First value | B + 14 + 2k |
| Second value | B + 16 + 2N + 2k |
| Third value | B + 16 + 4N + 2k |
| Descriptor | B + 16 + 6N + 2k |

These addresses use byte displacements.

The two-byte difference between the first sequence’s origin and the later sequences’ origins is significant. In particular, the second value begins at B + 16 + 2N + 2k, not B + 14 + 2N + 2k. A consumer must not normalize this into four uninterrupted, equally spaced arrays without preserving that difference.

Within an iteration, all four locations derive from the backing address loaded for that iteration. The routine does not reload the backing-address field between the three value writes.

### Decoding and publication order

Each two-byte quantity is decoded with the byte at the lower address providing the high-order eight bits and the following byte providing the low-order eight bits. For bytes with numeric values **H** and **L**, the decoded value is 256H + L.

This establishes the encoded byte significance independently of the target’s native byte order for 32-bit object fields. It does not establish the execution order of the two individual byte loads within a decoded pair.

For each examined entry, the observable memory-operation groups occur in this order:

1. Read the backing address from `0x10`.
2. Read and decode the first value.
3. Write the first value to `0x2C`.
4. Read and decode the second value.
5. Write the second value to `0x28`.
6. Read and decode the third value.
7. Write the third value to `0x30`.
8. Read and decode the descriptor.
9. Decide whether to skip or accept the entry.

Each decoded value lies in the inclusive range 0–65,535 and is widened to 32 bits without sign extension. The pair `80 00`, for example, produces `0x00008000`, not a negative value. The third value is likewise published as a nonnegative 16-bit value widened to 32 bits.

Only the descriptor controls skipping. A value field containing `FF FF` is published as 65,535 and does not itself cause the entry to be skipped.

### Descriptor 65,535: continue scanning

If the decoded descriptor equals 65,535:

- The three value writes remain in effect.
- The current index increases by one.
- The routine repeats the bounds decision against the captured N.
- Neither `0x24` nor `0x34` is written for that entry.

If all entries from the starting index through N − 1 have this descriptor, the scan reaches k = N and returns `0xFFFFFFFF`. The three published values then come from the last examined entry. The accepted-index and resolved-reference fields retain their previous contents, subject to any storage aliasing.

The index increment does not wrap in this bounded scan. An increment occurs only while k < N. Since N is at most `0xFFFFFFFF`, the largest index that can be incremented is `0xFFFFFFFE`, which becomes `0xFFFFFFFF` and fails the next bounds decision.

### Other descriptors: accept the entry

Every descriptor other than 65,535 is accepted, including zero.

- **Descriptor zero:** the resolved reference is zero.
- **Descriptor 1–65,534:** the resolved reference is the address of the descriptor’s first byte plus the descriptor’s numeric value.

The positive descriptor is therefore a forward byte displacement relative to its own location. It is not relative to the backing-storage base, the first value, or the byte immediately after the descriptor.

After calculating the resolved reference, the routine performs these operations in order:

1. Write k to object offset `0x24`.
2. Write the resolved reference to object offset `0x34`.
3. Return `0x00000000`.

The routine does not read from, validate, or determine the extent of the resolved reference’s destination. A successful return establishes acceptance of the descriptor, not the validity of a resource at that address.

### Widths and arithmetic limits

The supplied representation uses 32-bit count, index, scalar address values, result fields, and return values. Encoded values and descriptors contain 16 bits.

The address formulas above describe calculations whose intermediates and resulting addresses are valid under the target’s rules. They are not promises of unbounded mathematical arithmetic.

Large counts can affect address calculations even when the starting index is small, because later sequences use count-dependent displacements. Large backing addresses, indices, and positive descriptors can also make calculations exceed the available address range.

No explicit arithmetic-validity check is visible. Overflowing inputs are not established to return ordinary failure, and the evidence does not establish portable behavior for every overflowing expression. Valid address arithmetic remains a precondition rather than an additional checked error case.

## Side effects

The routine explicitly writes only the **five listed result fields**. The conditional write sequences are:

| Outcome | Explicit result writes |
|---|---|
| Initially out of range | None |
| Skipped entry | `0x2C`, then `0x28`, then `0x30` |
| Accepted entry | `0x2C`, then `0x28`, then `0x30`, then `0x24`, then `0x34` |
| Exhaustion after skips | Three value writes for each examined entry; no accepted-index or reference write |

The operation is not an atomic replacement of all result fields. In particular, failure after scanning can leave a mixture of newly published values and previously stored selection information.

No explicit allocation, release, backing-storage copy, or ownership transfer occurs. Publishing a derived address does not establish ownership of the referenced storage, extend its lifetime, or authorize its release.

The routine does not explicitly write the count or backing-address fields. However, it does not check whether encoded storage overlaps result fields. If storage overlaps, a result write can change bytes that a later decode reads. The descriptor is read only after all three value writes; the entry is not captured as an immutable snapshot before publication.

Likewise, the backing address is loaded again on each new iteration, but the count remains captured. No synchronization or concurrency guarantees are established. The stated operation order does not imply atomicity or a cross-thread publication guarantee.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless specified otherwise, assume valid, non-overlapping storage and valid, non-overflowing arithmetic.

### Initially out-of-range index

Given N = 3 and starting index 3:

- Return `0xFFFFFFFF`.
- Leave all five result fields unchanged.
- Do not read the backing-address field or encoded bytes.

Any larger unsigned starting index has the same outcome. With N = 0, every starting index is out of range.

### Zero descriptor succeeds

Given N = 3, starting index 1, and backing address B, the four pair locations are:

| Quantity | Address | Bytes |
|---|---|---|
| First value | B + 16 | `12 34` |
| Second value | B + 24 | `80 00` |
| Third value | B + 30 | `FF FF` |
| Descriptor | B + 36 | `00 00` |

The required result is:

- Write 4,660 to `0x2C`.
- Write 32,768 to `0x28`.
- Write 65,535 to `0x30`.
- Write 1 to `0x24`.
- Write zero to `0x34`.
- Return zero.

These writes occur in the listed order. The all-one third value does not trigger skipping.

### Positive displacement uses the descriptor’s address

Under the same count and index, a descriptor of `00 04` at B + 36 requires:

- Acceptance of index 1.
- A resolved reference of B + 40.
- Return zero without reading memory at B + 40.

A descriptor of `FF FE` is also accepted; it resolves to the descriptor address plus 65,534, provided that calculation is valid. It must not be confused with the skip descriptor `FF FF`.

### Skip followed by acceptance

Given N = 3 and starting index 1, suppose entry 1 has descriptor `FF FF` and entry 2 has descriptor zero:

- Publish all three values for entry 1.
- Do not write the accepted index or reference for entry 1.
- Reload the backing address for entry 2.
- Publish all three values for entry 2.
- Write accepted index 2 and reference zero.
- Return zero.

The final values describe entry 2, but the intermediate writes for entry 1 remain part of the required behavior.

### Exhaustion preserves older selection fields

Given N = 3 and starting index 2, suppose entry 2 has descriptor `FF FF`:

- Publish entry 2’s three values.
- Advance the working index to 3.
- Return `0xFFFFFFFF`.
- Preserve the prior contents of `0x24` and `0x34`.

Failure must not be interpreted as preserving every result field.
