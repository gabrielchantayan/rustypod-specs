# F-85040fb2d872

## Purpose

F-85040fb2d872 conditionally invokes F-9ad23bf5b97e for two 32-bit state fields associated with a caller-supplied object. It processes the field at offset `0xD8` before the field at offset `0xD4`. For each field observed to be nonzero, it calls the dependency and then writes zero to that field if the call returns normally.

The fields control whether calls occur; their values are not passed as arguments. Each dependency argument is instead a 32-bit value read through a global pointer.

**Established static behavior:** ordered field checks, conditional dependency calls, and post-call zero writes.

**Inferred intent:** the function may be clearing two pending states or performing conditional cleanup. Neither interpretation establishes resource ownership, a release operation, or the meaning of either field.

## Interface

### Input

The function accepts one input representing the base address of an object.

The supplied representation expresses this input as a 32-bit integer used for address-based accesses. It provides no separate object length, type tag, or validity indicator. The relevant object layout is:

| Offset from object base | Width | Access | Role |
|---|---:|---|---|
| `0xD4` | 4 bytes | Read; conditionally written | Second state field processed |
| `0xD8` | 4 bytes | Read; conditionally written | First state field processed |

The function compares each field with zero. Every nonzero 32-bit pattern satisfies that comparison, including patterns that would represent negative signed integers. There is no requirement in the visible behavior that an active field equal one.

The visible writes replace the entire four-byte field with zero. They do not decrement a count, clear only a selected bit, or preserve part of a nonzero value.

### Global input

An unnamed global location supplies a pointer to storage containing a 32-bit dependency argument. There are two distinct objects here:

- The global pointer-bearing location.
- The argument-bearing storage to which that pointer refers.

The function retains the pointer obtained from the global location at entry. The first conditional call obtains its argument through a separate read of the global pointer. The second conditional call obtains its argument through the retained entry pointer.

### Output

There is no explicit return value. Observable results consist of dependency calls, object-field writes, and whatever effects the dependency itself produces.

## Behavior

### Entry pointer capture

Before examining either state field, the function reads the global pointer-bearing location and retains the resulting pointer.

This initial capture does not itself require reading the 32-bit argument stored at that pointer. If neither conditional call is selected, the captured pointer is never dereferenced by the visible body.

### First field: offset `0xD8`

The function reads the four-byte field at offset `0xD8`.

If the observed value is zero:

- No dependency call is made for this field.
- No write is made to this field.
- Processing proceeds to the field at offset `0xD4`.

If the observed value is nonzero:

- The function reads the global pointer-bearing location again.
- It reads a 32-bit argument through the pointer obtained by that read.
- It calls F-9ad23bf5b97e with that argument.
- After normal return, it writes four-byte zero to the field at offset `0xD8`.

The dependency therefore runs before this function clears the first field. The visible body does not temporarily clear the field before calling out.

The post-call zero write is unconditional once this branch has been selected and the call returns normally. It is not guarded by a second read of the field. If the dependency changes the first field to another nonzero value, the subsequent zero write replaces that value, provided the storage remains valid.

### Second field: offset `0xD4`

The second field is read only after first-field processing has completed. If the first dependency call occurred and returned normally, its effects precede this read, as does the zero write to offset `0xD8`.

If the value now observed at offset `0xD4` is zero, the function returns without a second dependency call or a write to this field.

If the observed value is nonzero:

- The function reads a 32-bit argument through the pointer retained at entry.
- It calls F-9ad23bf5b97e with that argument.
- After normal return, it writes four-byte zero to the field at offset `0xD4`.
- It returns.

The second field is not snapshotted at entry. A first dependency call can therefore affect whether the second call occurs.

### Pointer retention versus argument retention

The function retains a pointer, not a copy of the 32-bit argument stored through that pointer.

Consequently:

- Changing the global pointer during the first dependency call does not redirect the second call’s argument read.
- Changing the contents of the entry-selected argument storage can change the second call’s argument.
- Invalidating the entry-selected argument storage can make a later second argument read invalid.
- With no relevant intervening mutation, both calls read the same argument storage, but the function does not independently guarantee equal argument values.

### Normal-return guarantees

On a normal return:

- The field at offset `0xD4` is zero. It was either observed as zero and left unwritten, or it was cleared after the second call.
- The field at offset `0xD8` is not unconditionally guaranteed to remain zero. Although a selected first call is followed by a zero write, a later second dependency call can modify that field, and this function does not revisit it.
- This invocation directly makes zero, one, or two dependency calls.

These guarantees concern the visible execution without additional interference after the relevant observations or writes. They do not establish concurrency safety.

## Side effects

### Direct memory effects

The visible body directly writes only the two state fields:

- Offset `0xD8`, after its selected dependency call returns normally.
- Offset `0xD4`, after its selected dependency call returns normally.

A field observed as zero is not explicitly rewritten to zero.

The visible body reads the global pointer and argument storage but does not explicitly write either. Effects performed by F-9ad23bf5b97e must be considered separately.

### Ordering and failure exposure

Each selected dependency call precedes its associated zero write. There is no visible rollback, recovery handler, or alternate status result.

If a dependency call does not return normally, the subsequent clear and later processing are not established. In particular:

- Failure to return from the first call prevents the visible first-field clear and second-field processing.
- Failure to return from the second call prevents the visible second-field clear.

The function does not visibly inspect a dependency result or choose a failure branch based on one.

### Ownership and reentrancy

No direct allocation, release, ownership transfer, or reference-count adjustment is established. The 32-bit dependency argument is not proven to be a pointer or resource handle.

The dependency must not be assumed to preserve globals, object fields, argument storage, or storage lifetimes. If it invalidates storage used afterward, the remaining accesses are not made safe by this function.

No reentrancy guard is visible. Since a selected field remains uncleared until its dependency call returns, a reentrant invocation could observe it as nonzero. The consequences depend on behavior outside the supplied evidence.

## Acceptance examples

These are conditional acceptance scenarios derived from static evidence, not runtime results. Unless stated otherwise, storage remains valid, dependency calls return normally, and the dependency does not modify relevant state.

### Both fields are zero

Given zero at both offsets, the function makes no dependency calls and performs no field writes. It captures the global pointer but does not dereference argument storage.

### Only the first field is nonzero

Given nonzero at `0xD8` and zero at `0xD4`, the function makes one call using an argument read through the first branch’s global-pointer selection. It clears `0xD8` after the call, then observes zero at `0xD4` and returns.

### Only the second field is nonzero

Given zero at `0xD8` and nonzero at `0xD4`, the function makes one call using the entry-retained pointer. It then clears `0xD4`.

### Both fields are nonzero

The function calls the dependency, clears `0xD8`, reads `0xD4`, calls the dependency again, and clears `0xD4`. The calls occur in that order. Their arguments are equal only if the relevant pointer selections and stored values make them equal.

### The first call disables second-field processing

Given both fields initially nonzero, if the first dependency call writes zero to `0xD4`, the subsequent second-field check observes zero. No second call occurs.

### The first call enables second-field processing

Given `0xD8` nonzero and `0xD4` initially zero, if the first dependency call writes a nonzero value to `0xD4`, the subsequent check selects the second call. Initial zero does not suppress this later observation.

### The first call changes global argument selection

Suppose the entry pointer selects storage A. During the first call, the dependency changes the global pointer to storage B and changes the value in A. If second-field processing selects a call, its argument comes from the updated contents of A, not from B, provided A remains valid.

### The second call reactivates the first field

If the second dependency call writes nonzero to `0xD8`, normal completion clears `0xD4` but does not clear `0xD8` again. Both fields being zero on return is therefore not a general acceptance requirement.

### Non-Boolean state values

A value such as `0x80000000` selects its field’s call just as a value of one does. After normal return from that call, the associated field receives four-byte zero.
