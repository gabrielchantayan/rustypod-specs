# F-90174bf7d6e5

## Purpose

F-90174bf7d6e5 initializes a four-byte prefix and two byte-sized status fields in a structure supplied by a dependency, then processes consecutive zero-based indices through a second dependency.

Processing ends when either:

- The next index reaches a signed bound captured before processing begins.
- Both status fields are nonzero at the start of an otherwise eligible iteration.

The function returns an address four bytes before the address supplied by the initialization dependency.

The apparent intent is to record whether processing has produced both negative and positive outcomes. That interpretation is inferred from the sign-based status updates. The stronger established behavior is the ordered sequence of memory accesses, dependency calls, and conditional writes described below. In particular, the processing dependency’s effects on shared memory are unknown, so the status fields cannot unconditionally be treated as monotonic outcome accumulators.

## Behavior

### 1. Obtain the working address

F-663b186301f2 is called exactly once with the input argument increased by four.

Its return value determines B. The function then derives and retains the return address B − 4. There is no visible validation of the dependency result before memory access.

### 2. Initialize the prefix and status fields

After F-663b186301f2 returns, the function performs these direct writes in order:

1. Write the value of an external four-byte datum to B − 4.
2. Write zero to the first status byte at B + 16.
3. Write zero to the second status byte at B + 17.

The numeric value and semantic meaning of the external datum are unavailable. It is not established as a type tag, ownership marker, or immutable constant.

These initialization writes occur even when the processing bound will later be zero or negative. Existing status bytes are overwritten, not merged with their previous values.

The source of the prefix value is accessed after the first dependency returns. The available evidence therefore does not justify using a value assumed to have existed before that call.

### 3. Capture the processing bound

After the initialization writes, the function reads the four-byte signed value at B + 4.

This value is captured once for loop control. The function does not reread that location after processing calls.

Consequently:

- A later change to the bound field does not alter this invocation’s captured limit.
- A later mutation of that field can still remain visible in memory.
- A zero or negative captured bound prevents all processing calls.
- Initialization is already complete when the bound is examined.

The function does not itself write the bound field.

### 4. Decide whether another index is eligible

Processing begins with index zero.

At each iteration boundary, the function first compares the current index with the captured bound using signed comparison. If the index is greater than or equal to that bound, it immediately returns B − 4.

This bound test precedes both status-byte reads. Once the bound is exhausted, the function does not perform a final status check.

If the index remains below the captured bound, it checks the status fields:

1. Read the first status byte at B + 16.
2. Only if that byte is nonzero, read the second status byte at B + 17.
3. If both observed values are nonzero, return B − 4 without processing the current index.

A zero first status byte therefore suppresses the second status-byte read on that iteration. This is an observable distinction where reads themselves matter.

Any nonzero byte value satisfies the corresponding status test; the value need not be exactly one.

### 5. Process one index

If neither termination condition applies, the function calls F-93ea0dab0e54 with:

- B as its first argument.
- The current zero-based index as its second argument.

Its result is interpreted as a signed integer:

| Result | Direct action after the call returns |
|---|---|
| Negative | Write one to the first status byte at B + 16 |
| Zero | Write neither status byte |
| Positive | Write one to the second status byte at B + 17 |

A negative result does not directly clear or set the second status byte. A positive result does not directly clear or set the first status byte. A zero result does not restore either field.

These statements describe this function’s own writes. They do not constrain changes made inside F-93ea0dab0e54.

After the conditional write, the index increases by one and control returns to the bound test.

### 6. Terminate and return

There are two normal termination conditions:

- The current index is at least the captured bound.
- The current index is below the bound, but both status bytes read as nonzero.

Both return the same retained address, B − 4.

There is no visible finalization call, status normalization, prefix restoration, bound restoration, or explicit deallocation before return.

For a positive captured bound N, processing calls, if they return normally, use a consecutive prefix of indices from 0 through N − 1. No index is skipped or repeated by this function.

Under valid memory access, returning dependencies, and no independent external mutation between initialization and the first iteration, a positive bound causes at least one processing call: both status fields have just been cleared.

## Acceptance examples

These are conditional static acceptance scenarios, not executed tests. Unless stated otherwise, assume valid storage, normally returning dependencies, and no independent concurrent mutations.

### Nonpositive bound

If the captured bound is zero or negative:

- The prefix and both status bytes are initialized.
- The bound is read.
- F-93ea0dab0e54 is never called.
- No loop status-byte read occurs.
- The return value is B − 4.

### Bound of one with a positive result

If the captured bound is one and the processing dependency leaves the fields unchanged before returning a positive result:

- Exactly one processing call occurs, with index zero.
- The first status byte remains zero.
- The second status byte becomes one.
- The next bound test terminates processing before another status read.

### Negative result followed by positive result

If the captured bound is at least three, the first two processing results are negative and positive, and the dependency does not modify the status fields:

- Calls occur at indices zero and one.
- After the first call, the first status byte is one.
- After the second call, the second status byte is one.
- At index two, the bound still permits processing, but both status bytes are nonzero.
- No processing call occurs at index two.

### Only one sign appears

If the bound is positive, all results are negative, and the dependency leaves the status fields unchanged, every eligible index is processed. The first status byte becomes one, but the second remains zero, so the status condition never terminates the loop.

The corresponding all-positive case also processes every eligible index.

### All results are zero

If every processing result is zero and the dependency does not modify the status fields, both fields remain zero and every index below the captured bound is processed.

### Stored bound changes during processing

If the captured bound is three and the first processing call changes the stored bound to zero, that write does not shorten the captured limit. Absent status-based termination, calls still occur at indices zero, one, and two.

### Dependency clears a prior status

If a negative result has set the first status byte, and a later call clears that byte before returning a positive result, the caller sets only the second status byte. Both fields are not necessarily nonzero afterward. Early termination cannot be inferred merely from the history of return signs.

### Dependency sets both statuses

If an index-zero call sets both status bytes nonzero and returns zero, the caller performs no status write. With a captured bound greater than one, the next eligible iteration terminates on the status check. With a bound of one, termination instead occurs at the bound test without reading those bytes again.
