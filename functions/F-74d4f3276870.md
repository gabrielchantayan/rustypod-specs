**global base + index × 396 bytes**

Consequently, multiplication by the entry stride does not itself require 16-bit truncation or signed 32-bit overflow. Whether adding the displacement to the global base is valid remains dependent on the base value and the target’s arithmetic and address rules.

There is no represented bounds check. In particular:

### Destination selection

The destination is 2120 bytes beyond the address represented by that value. The 396-byte table stride and the 2120-byte destination offset serve different purposes: the first selects an entry; the second selects a location in separately addressed storage.

The selected address-bearing value is not checked for nullness, range, object membership, or destination capacity. The representation also does not establish that adding 2120 produces a valid address without overflow or address-space wrapping.

The stored integer’s byte order depends on the target. The evidence establishes a four-byte integer store of 1, not an environment-independent sequence of bytes in ascending address order.

## Acceptance examples

These examples are conditional behavioral expectations, not executed tests. Each assumes valid address calculations, readable selection storage, and writable destination storage unless stated otherwise.

Given an index of zero and a selected field containing address A, the function reads the field at the global base and writes the four-byte integer 1 at A + 2120.

It does not write at global base + 2120 merely because the index is zero.
