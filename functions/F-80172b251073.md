# F-80172b251073

## Purpose

F-80172b251073 selects one of two dependencies using a 32-bit field in a caller-supplied record. If the selected dependency returns a nonzero result, the function invokes an external operation with that result and two caller-supplied values, then updates four fields in the record.

The established return convention is:

- **25**, represented as `0x19`, when the selected dependency returns zero.
- **0** after the external operation returns normally and the record updates complete.

The function’s shape suggests obtaining or replacing a resource, operating on it, and recording its resulting state. That interpretation is **inferred intent**, not an established allocation, resizing, or copying contract. In particular, the external operation’s semantics are unavailable.

## Behavior

### 1. Select and invoke a dependency

The function first reads the 32-bit field at record offset +8 and compares it with zero.

If that read yields zero, it invokes **F-638beded7699** with two arguments, in this order:

1. The request argument, unchanged.
2. A zero constant.

If the initial read yields a nonzero value, it invokes **F-e74413f3255f** with four arguments, in this order:

1. The 32-bit value obtained from another read of record offset +8.
2. The request argument, unchanged.
3. A zero constant.
4. A one constant.

The nonzero branch contains a second read of the +8 field in the supplied representation. The initial read determines the branch; the later read supplies the first argument to F-e74413f3255f. Under stable-memory conditions, both reads yield the same value. This contract does not guarantee that equivalence in the presence of concurrent or asynchronous modification.

These are source-level access observations, not a promise of two physical bus transactions or volatile-load semantics.

Exactly one of the two selector dependencies is invoked on a normal path through this stage.

### 2. Classify the selected dependency’s result

The selected dependency’s result is treated as a 32-bit value and compared with zero.

If it is zero:

- The function returns 25.
- The external operation is not invoked.
- None of the four explicit record stores is performed.

There is no special handling for any other result pattern. A result with its high bit set is nonzero and therefore takes the success path. The wrapper does not perform a signed positivity check, a range check, or a separate validity check.

Returning 25 does **not** establish that the record or other state remains unchanged. The selected dependency has already executed, and its side effects are unknown.

### 3. Invoke the external operation

For a nonzero result, the function invokes an external dependency, designated **F-unmapped-01** in this document, with:

1. The selected dependency’s nonzero result.
2. The operation argument, unchanged.
3. The request argument, unchanged.

The function does not inspect an output or status from this call before proceeding. Therefore, the wrapper’s return value cannot be described as reporting the external operation’s success unless that dependency’s separate contract establishes such a relationship.

The external operation occurs **before all four explicit record stores**. If it does not return normally, the supplied body establishes no subsequent field updates or normal return.

| Order | Destination | Width | Stored value |

The store at +24 is byte-sized. It does not itself clear or replace the neighboring bytes at +25 through +27.

The supplied representation establishes this sequence of explicit stores. It does not establish atomic publication of the record, synchronization with other threads, or any memory-ordering guarantee.
