# F-3265ef162d31

## Purpose

The procedure interleaves indirect calls with byte and 32-bit memory accesses. Its visible effects include extracting bit fields, constructing scaled addresses, copying the low byte of a word, writing through byte-valued selectors, and replacing previously written fields.

No application-level purpose is established. Initialization, serialization, allocation, device control, and object construction are not justified interpretations.

The supplied static representation reports invalid instruction data and ends at an invalid-instruction termination marker. The sequence below describes represented operations and their ordering, conditional on execution reaching them. It does not establish that an actual invocation can traverse the entire sequence.

Additional entry state supplies:

There is no established completion status, exception type, state-restoration guarantee, or rollback behavior. A dependency may prevent later operations from being reached.

### Width and notation

A **word** is 32 bits. A **low byte** is the least significant eight bits; byte narrowing discards higher bits without saturation. A paired result is represented as 64 bits, with a low 32-bit half and a high 32-bit half.

Let:

- \(P\) denote the fourth argument.
- \(S=(P\mathbin{\&}\text{0x3FFFFF})\ll8\), called the **scaled argument**.

Arithmetic expressions below use a conditional **32-bit bit-vector interpretation**: additions, multiplications, and left shifts retain their low 32 bits. Right shifts of identified unsigned words are logical. The representation also contains signed-looking arithmetic; this interpretation is not a claim about portable signed-overflow semantics or proof of the actual instruction behavior.

A **selector write using base \(B\)** means two ordered memory operations:

1. Read an unsigned byte at \(B+1\).
2. Write the specified byte at the zero-extended selector value plus 17.

Thus selector-write destinations range from address 17 through 272. The selector is not a full-width pointer.

The following identities matter throughout:

| Expression | Value under the 32-bit interpretation |
|---|---|
| \(S\times524288\) | \((P\mathbin{\&}31)\ll27\) |
| \(S\times1048576\) | \((P\mathbin{\&}15)\ll28\) |
| \((S\mathbin{\&}\text{0x1FFF})\ll17\) | \((P\mathbin{\&}31)\ll25\) |
| \((S\mathbin{\&}\text{0xFFF})\ll18\) | \((P\mathbin{\&}15)\ll26\) |
| \((S\times1048576)\gg24\) | \((P\mathbin{\&}15)\ll4\) |

None is universally zero.

Byte order, word alignment requirements, and the mapping of numerical addresses are unknown.

## Behavior

Calls described as having no displayed arguments may still consume implicit state. Every call count below excludes any separately described preceding or following call.

### 1. Entry calls and initial selector write

The first indirect call receives the second explicit argument. Four further calls follow; the fourth supplies a word result.

The procedure then reads a selector at the additional entry address plus 1 and writes bits 22–29 of the additional entry word at selector plus 17.

The retained call result shifted left by 2 is passed to another dependency. Four calls follow; the fourth supplies the **initial word** used next.

### 2. Fourth-argument stores and first scaled-base selector write

In order:

1. Write the low byte of initial word shifted left by 2 at \(P+15\).
2. Read a selector at \(P\times1024+1\).
3. Write that same byte at selector plus 17.
4. Retain the scaled argument \(S\).
5. Make three calls, retaining the third result.
6. Read the selector at \(P\times1024+1\) again.
7. Write the low byte of initial word masked to 30 bits and shifted right by 20 at selector plus 17.
8. Pass the latest call result shifted left by 2 to another dependency.
9. Make four calls.

Next, perform a zero selector write using base \(S\times524288\). Its selector-read address is therefore \(((P\mathbin{\&}31)\ll27)+1\), not invariably address 1.

A dependency then receives four displayed arguments: \(S\ll3\), \(S\ll3\), \(S\), and zero.

### 3. Retained selector and word-to-byte copies

Exactly **four** calls follow that four-argument call. The fourth supplies a word.

Read a selector at \(S\times524288+1\), retain it, and write zero at selector plus 17. Pass the latest word shifted left by 2 to a dependency, then make four calls.

Read a word at retained selector plus 116 and write its low byte at retained selector plus 1.

A dependency receives, in order:

- \(S\times1048576\).
- \(S\).
- \((S\mathbin{\&}\text{0x1FFF})\ll17\).
- The retained selector.

The first and third arguments can be nonzero; their simplified values are given in the interface table.

The next call returns a paired result. Another dependency receives its low half, high half, low half again, and \((S\mathbin{\&}\text{0xFFF})\ll18\). The fourth argument can also be nonzero.

Four calls follow. Four times the fourth result becomes a **copy base**. Read a word at copy base plus 116, write its low byte at copy base plus 1, pass the copy base to a dependency, and make four calls.

### 4. Secondary output and record selection

Define the retained **large selector base** as \(S\times1048576\).

Perform a zero selector write using that base. Its selector is read at \(((P\mathbin{\&}15)\ll28)+1\).

A dependency receives an unresolved secondary-register output. The next call produces the **record source**, which is passed to another dependency. Four calls follow, retaining the fourth result.

Read a fresh selector at large selector base plus 1. Write the byte obtained by shifting large selector base right by 24 at selector plus 17. That byte is \((P\mathbin{\&}15)\ll4\), not necessarily zero.

Pass the latest result shifted left by 2 to a dependency. Four calls follow; four times the fourth result becomes the **record base**.

Then:

1. Read a word at record source plus 4 as the **selected address**.
2. Perform a zero selector write using selected address.
3. Call a dependency with record base repeated three times.
4. Make four calls, retaining the fourth result.
5. Read a selector at selected address logically shifted right by 2, plus 1.
6. Retain this new selector and write zero at selector plus 17.
7. Pass the latest result shifted left by 2 to a dependency.
8. Make four calls, retaining the fourth result.

The two selector reads use different base expressions.

### 5. Field extraction and indexed stores

Read a word at record base plus 4 as the **field word**. Next, read a word at the latest retained selector plus 116 as the **payload word**, then write its low byte at selector plus 1.

Call a dependency with:

- Payload word.
- Record base shifted left by 19.
- Record base shifted left by 19 again.
- The latest call result shifted left by 2.

The next call returns an opaque word. Retain field word logically shifted right by 22 as the **field fragment**, ranging from 0 through 1023. Call another dependency with the opaque word and payload word logically shifted right by 2.

Four calls follow. Four times the fourth result becomes a new copy base. Read a full word at that base plus 116, retain it, write its low byte at base plus 1, pass the base to a dependency, and make four calls.

Write the retained full word at four times an unresolved secondary-register result, plus 20. Pass that secondary result to a dependency.

The next call returns an opaque word. Another dependency receives that word and, twice, the low nine bits of field fragment shifted left by 21.

Four calls follow, producing an index. Write field fragment shifted left by 23 at index multiplied by 4, plus 20; pass index multiplied by 4 to a dependency. Only the low nine fragment bits survive that 32-bit shift.

### 6. Indexed records and replacement

After four calls, let the fourth result define:

- **Stored scale:** the original result multiplied by 4.
- **Masked index:** the original result masked to 30 bits.
- **Reduced index:** masked index logically shifted right by 2.

Write stored scale at the original result multiplied by 16, plus 20. Pass masked index to a dependency.

After four calls, the fourth result becomes the **record index**. Write masked index at record index multiplied by 4, plus 20, and pass that scaled address to a dependency.

After four calls, the fourth result becomes the **link word**. Then:

1. Write the low byte of record index multiplied by 8 at payload word plus 1.
2. Write link word shifted left by 2 at record index multiplied by 8, plus 52.
3. Pass link word shifted left by 2 to a dependency.
4. Call another dependency, then pass its opaque result to a further dependency.
5. Make four calls, the fourth returning a paired result.
6. Write the low byte of record index multiplied by 8 at link word masked to 30 bits, plus 1.
7. Replace the word at record index multiplied by 8, plus 52 with the paired result’s high half.
8. Pass its low half shifted left by 2 to a dependency.

Both writes to the field at displacement 52 are part of the visible contract.

### 7. Byte fields and fixed address 17

After four calls:

1. Write the low byte of record index multiplied by 16 at link word masked to 30 bits and shifted right by 20, plus 17.
2. Write the low byte of stored scale at record index multiplied by 16, plus 13.
3. Call a dependency with the latest result shifted left by 2 twice.
4. Call another dependency, then pass its word result and that word logically shifted right by 3 to a further dependency.
5. Make four calls.
6. Write the low byte of record index multiplied by 16 directly at address 17.
7. Repeat the stored-scale byte write at record index multiplied by 16, plus 13.
8. Pass the latest result shifted left by 2 to a dependency.

After four more calls, write stored scale as a word at masked link word plus 20. Then write the low byte of twice masked link word at masked link word plus 13.

The first store in this phase uses an address calculated directly from a bit field; it does not read a selector.

### 8. Small-address fields and fresh selector reads

The latest call result defines:

- **Wide base:** result multiplied by 32.
- **Wide value:** result shifted left by 7.
- **Small field:** its low 27 bits logically shifted right by 17, ranging from 0 through 1023.

Make three calls; the third supplies the **shift source**. Write wide value at wide base plus 20, then write the low byte of shift source shifted left by 2 at wide base plus 13.

Pass shift source shifted left by 2 to a dependency and make four calls.

Then:

1. Write the low byte of reduced index shifted left by 1 at small field plus 7.
2. Perform a selector write using wide base, storing the low byte of small field.
3. Call a dependency with shift source shifted left by 21 repeated three times.
4. Call another dependency, retaining its word as the **retained result**, and pass it to a further dependency.
5. Make four calls, retaining the fourth result.
6. Read and retain a fresh selector at wide base plus 1.
7. Write zero at retained selector plus 17.
8. Pass the latest result shifted left by 2 to a dependency.
9. Make four calls.

### 9. Fixed address 13 and later fields

Write the low byte of retained result logically shifted right by 3 at wide base plus 13. Then write the retained selector directly at address 13.

Call a dependency with twice retained selector, 152, and 608. Make another call, then pass an unresolved unsigned secondary-register output logically shifted right by 3 to a dependency.

Make four calls. A further dependency consumes the latest result shifted left by 2 and returns a word.

Write the same retained-result byte at twice retained selector plus 13. Then replace address 13 with byte value 192. Pass the latest dependency result shifted left by 2 to another dependency.

After four calls, the fourth result becomes the **later index**. Write later index shifted left by 2 at twice retained selector plus 36. Then read a word at twice retained selector plus 116 as the **later base**.

Call a dependency with later base, twice later base, later index shifted left by 5, and later base masked to 31 bits then logically shifted right by 2.

After four calls, write later index shifted left by 5 at later base plus 36. Read a word at later base plus 116 and pass it to a dependency. Four calls follow, the fourth returning a paired result.

### 10. Final indexed stores and termination

The paired result’s low half shifted left by 2 becomes the **final payload**. Write retained result logically shifted right by 3 as a full word at the paired result’s high half multiplied by 4, plus 20.

Call a dependency with final payload repeated three times and that high half logically shifted right by 3. The next call returns another paired result. A subsequent dependency receives its low half, high half, low half again, and high half logically shifted right by 3.

After four calls, write final payload at the fourth result multiplied by 4, plus 20. Pass that scaled address to a dependency.

After four calls, the fourth result becomes the **terminal word**:

1. Perform a selector write using later base, storing the low byte of terminal word shifted left by 2.
2. Make three calls, retaining the third result.
3. Read the selector at later base plus 1 again and write the low byte of terminal word masked to 30 bits and shifted right by 20.
4. Pass the latest result shifted left by 2 to a dependency.
5. Make four calls, retaining the fourth result.
6. Perform a zero selector write using base \((\text{terminal word}\ll2)\times1024\).
7. Call a dependency with terminal word shifted left by 5 twice, terminal word shifted left by 2, and the latest result shifted left by 2.
8. Make exactly **four** calls.
9. Repeat the zero selector write using the same computed base.
10. Pass the fourth call’s result shifted left by 2 to a dependency, then make four final calls.

The representation then ends at its invalid-instruction marker.

## Side effects

Explicit stores are either one byte or one 32-bit word. Each specified word-to-byte copy reads the entire word before storing its low byte.

No visible bounds, null, alignment, permission, or executable-target checks protect the accesses. Traversal requires every reached memory access and indirect target to be valid in the actual environment.

Repeated reads are fresh observations. Repeated stores remain distinct even when they target the same location. Dependencies may observe or modify memory between them. Aliasing may also make an earlier store affect a later read.

No explicit allocation, release, ownership transfer, synchronization, or rollback operation is identifiable. Dependency behavior may include any of these; it is unknown. The procedure establishes no ownership guarantee for passed values or addressed memory.

## Acceptance examples

These are conditional static acceptance checks, not executed tests.

- **Nonzero scaled bases:** For \(P=1\), \(S=256\). The phase-2 and phase-3 selector reads using \(S\times524288\) occur at address 0x08000001. Phase-4 selector reads using \(S\times1048576\) occur at address 0x10000001. The later phase-4 selector store writes byte 0x10.
- **Nonzero dependency arguments:** For \(P=1\), the phase-3 four-argument call receives 0x10000000, 256, 0x02000000, and the retained selector. The subsequent paired-result forwarding call’s fourth argument is 0x04000000.
- **Zero-base boundary:** For \(P=32\), both scaled selector bases are zero under the stated arithmetic interpretation, so their selector reads occur at address 1. This is a conditional case, not a universal rule.
- **Byte narrowing:** If initial word is 255, its shifted-left-by-2 byte is 252. Both initial stores of that byte write 252 if reached.
- **Selector width:** A selector value of 255 directs its store to address 272.
- **Fresh reads:** If the selector at a repeated location changes from 3 to 9 between observations, the corresponding stores target addresses 20 and 26.
- **Call boundaries:** In phase 3, the selector read follows the fourth call after the preceding four-argument call. The same four-call boundary applies before the repeated zero selector write near termination.
- **Full-word replacement:** If phase 6 reaches both stores at record index multiplied by 8 plus 52, the shifted link word is stored first and the paired high half later.
- **Fixed-address replacement:** If phase 9 reaches both direct stores at address 13, the retained selector is stored before 192. Aliasing or intervening dependencies may introduce additional changes.
- **No completion guarantee:** A nonreturning dependency prevents all subsequent operations from being reached.
