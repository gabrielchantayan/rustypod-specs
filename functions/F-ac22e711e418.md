## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **All final predicates satisfied.** If `0xA0` contains `1` at the final decision and all five checked fields are nonzero, the byte at `0xE8` becomes `0`.

2. **Zero or signed-negative controlling value.** If `0xA0` contains `0`, `0x80000000`, or `0xFFFFFFFF`, the byte becomes `1`, regardless of the other five fields.

3. **A zero among otherwise nonzero values.** With signed-positive `0xA0`, a zero at `0xB4` produces indicator `1`. The decision does not require reading `0xB8` or `0xBC`.

4. **Full-width nonzero check.** With signed-positive `0xA0`, five values of `0x00000100` satisfy the nonzero condition and produce indicator `0`.

5. **Dependency-modified input field.** Suppose A2 is positive and A3 through A7 are nonzero, but a dependency changes `0xA0` to zero before the final decision. The resulting indicator is `1`; the original argument values do not override current object contents.

6. **Nonpositive fill count.** With a retained fill count of zero or a negative value and valid returned buffers, each resource iteration writes one word containing `0x000000FF` before its three post-fill calls.

7. **Positive fill count.** With retained count `3`, each buffer receives that word at offsets `0`, `4`, and `8`. The fill loop performs no fourth write.

8. **Handle mutation between calls.** If F-db32df6fb53e replaces the current slot value, F-abe00673b80c receives the replacement. If the second dependency replaces it again, F-c7d624095a7d receives that newer value.

9. **Stable base value.** With a stable base value `0x1000`, `0x10C` receives `0x1000` and `0x108` receives `0x13C0`, assuming ordinary valid arithmetic and storage.
