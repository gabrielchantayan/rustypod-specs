# F-9897db1fc137

## Purpose

F-9897db1fc137 selects a source location and passes it, together with its first argument, to F-67a6a52fe86f.

Selection has two stages:

1. When the original fourth argument is nonzero, perform a preferred-selection sequence. A nonzero result from resolving the resulting local candidate selects that candidate’s location immediately.
2. Otherwise, traverse a collection associated with the second argument. Select the first visited index whose resolved object’s indirect operation returns nonzero.

If traversal exhausts without a match, the function selects the local candidate’s location. A traversal match instead selects a collection-entry location recalculated after the successful indirect operation.

“Candidate,” “collection,” “resolution,” and “predicate” describe operational roles. Their application-level meanings and ownership semantics are not established.

### Locations and layouts

- **Candidate slot:** a four-byte local slot initially containing the preference value.
- **Temporary slot:** a four-byte local slot initially containing the query value.
- **Collection field:** the location at the container address plus 16 bytes. It is passed to the bound dependency and directly read as a four-byte base value.
- **Entry location:** an address formed from the current collection base and a four-byte-scaled traversal index.
- **Resolved object:** the address returned when F-6e90825b1a9f resolves an entry.
- **Dispatch table:** addressed by the first four-byte word of a resolved traversal object. The indirect callable is read at byte offset 20 within that table.

These accesses establish particular field widths and offsets, not complete structure definitions. Four-byte entry spacing does not establish the full size of the objects represented by entries.

### Preconditions

Ordinary completion requires every reached access and dependency invocation to be valid. Specifically:

- Dependencies receiving local-slot addresses must accept those locations and their current contents.
- A reached collection field must be suitable both for F-840e4f605666 and for the direct four-byte reads.
- Every visited entry location must be acceptable to F-6e90825b1a9f.
- Every resolved traversal object must support the object-word and dispatch-table accesses described above.
- The output argument and selected source location must satisfy F-67a6a52fe86f’s requirements.

The function does not visibly validate these conditions. A zero traversal-resolution result is not treated as an ordinary nonmatch.

No contract is established for retaining local-slot addresses beyond their valid lifetime.

## Behavior

### Preparation

Before making any dependency call, the function writes the original query value into the temporary slot, then writes the original preference value into the candidate slot.

It then calls F-bd4a91a0cf4e with the candidate-slot address and two zero arguments.

The candidate’s initial contents are available to that dependency if it reads them. Whether the call initializes, replaces, interprets, or otherwise transforms those contents is unknown.

The preferred-selection decision subsequently examines the original preference argument, not the candidate slot’s possibly changed contents.

The temporary slot is initialized on every path. If the original preference is zero, this function does not subsequently pass that slot to a dependency or explicitly perform a final operation on it.

### Preferred selection

An original preference of zero skips this stage.

For a nonzero original preference, the dependency sequence is:

| Order | Dependency | Arguments |
|---:|---|---|
| 1 | F-39c5bfb94148 | Temporary-slot address, container argument, original preference value |
| 2 | F-e87d68d56ac0 | Candidate-slot address, temporary-slot address |
| 3 | F-176c75806347 | Temporary-slot address |
| 4 | F-6e90825b1a9f | Candidate-slot address |

The represented 32-bit result of the fourth call determines the next action:

- **Nonzero:** select the candidate-slot address and proceed directly to output.
- **Zero:** begin collection traversal.

The function does not directly branch on the return value of F-39c5bfb94148 or on the temporary slot’s contents.

The temporary-slot operation precedes candidate resolution. No ownership transfer, reference retention, or state-preservation guarantee can be inferred merely from this ordering. Those guarantees would require dependency contracts.

### Traversal bounds and termination

Traversal starts with an unsigned 32-bit index of zero.

Before each possible iteration, F-840e4f605666 receives the collection-field address. Its result is treated as an unsigned 32-bit bound. An iteration proceeds only when the current index is strictly less than that result.

The observable consequences are:

- A bound call occurs before the first entry access.
- A zero initial bound causes immediate exhaustion without entry resolution or predicate dispatch.
- Each completed nonmatching iteration is followed by another bound call.
- Bounds are obtained anew rather than cached.
- A matching predicate exits traversal immediately, without another bound call.
- A failed bound comparison selects the candidate-slot address.

The bound call precedes that iteration’s direct collection-base read. A change made by the bound dependency can therefore affect the entry location used immediately afterward.

Traversal can terminate early on a match. A stable bound does not, by itself, require every in-range index to be visited.

### Entry resolution and predicate dispatch

For each index that passes its bound check, the function performs the following observable sequence:

1. Reads the four-byte base value from the collection field.
2. Forms the entry location using that base and the current index with four-byte spacing.
3. Calls F-6e90825b1a9f with the entry location.
4. Uses its returned value as an object address.
5. Reads the object’s first four-byte word as a dispatch-table address.
6. Reads the callable target at byte offset 20 in that dispatch table.
7. Calls that target with the resolved object address and the original query value.

The predicate result is represented as 32 bits. Zero means continue scanning. Any nonzero value means select the current index; success is not restricted to the value one.

Every predicate receives the original query argument. Changes to the temporary slot during preferred selection do not replace that argument.

There is no explicit zero check between traversal resolution and dispatch access. A zero resolution result therefore proceeds to an attempted dispatch access using that result. The function does not specify a controlled null-entry outcome.

After a zero predicate result, the index increases by one before the next bound call.

### Selecting a matched entry

A successful traversal predicate selects an entry location, not the resolved object address.

After the predicate returns nonzero, the function rereads the four-byte collection base and recalculates the entry location using the same index. That recalculated location becomes the source passed to F-67a6a52fe86f.

The function does not:

- Reuse the entry location used for the earlier resolution.
- Repeat the bound check.
- Resolve the newly calculated entry.
- Invoke its predicate again.

Consequently, if the predicate changes the collection base, the tested object and the selected output source can correspond to different backing regions.

### Widths and arithmetic

The traversal index and bound are unsigned 32-bit quantities. Their comparison is unsigned.

For a stable bound of \(N\), traversal can visit only indices from zero through \(N-1\). It visits the entire range only if traversal is reached, every predicate in that range returns zero, and all accesses and calls complete normally. If a predicate returns nonzero at index \(k\), traversal visits only indices zero through \(k\).

For example, a stable bound of two with a match at index zero visits only index zero. It does not visit index one or obtain another bound.

With a stable bound of \(2^{32}-1\), index \(2^{32}-2\) is the last visited index only if traversal exhausts without a match. In that case, its nonmatching result advances the index to \(2^{32}-1\), and the following comparison fails. An earlier match terminates sooner. Neither case wraps the traversal index.

More generally, an iteration cannot pass the unsigned comparison when the index is \(2^{32}-1\), because no unsigned 32-bit bound exceeds that value. Thus, normal traversal control does not increment the index through wraparound, even if bound results change.

The four-byte index scaling uses unsigned 32-bit arithmetic and wraps modulo \(2^{32}\). Adding the represented base for entry selection likewise occurs in that unsigned arithmetic domain. Distinct large indices can therefore produce the same calculated entry address. There is no overflow check.

These arithmetic facts do not establish address validity. The container-field address and dispatch-address expressions also lack visible validity checks. Portable behavior for overflowing signed address expressions, invalid integer-to-address interpretations, or invalid accesses remains unresolved.

### Output and final candidate operation

Exactly one source is selected on an ordinary completed path:

| Outcome | Source supplied to F-67a6a52fe86f |
|---|---|
| Preferred resolution is nonzero | Candidate-slot address |
| Traversal predicate is nonzero | Entry location recalculated after that predicate |
| Traversal exhausts without a match | Candidate-slot address |

F-67a6a52fe86f receives the original output argument and the selected source address.

After that call returns, F-176c75806347 receives the candidate-slot address. The function then returns without an explicit result.

Neither exhaustion nor zero preferred resolution causes an explicit reset of the candidate. Neither outcome proves that the candidate contains zero or represents an empty value.

## Acceptance examples

These are conditional static expectations, not executed tests. Each assumes valid reached accesses and normal dependency returns. Stability or mutation conditions stated in an example are explicit assumptions, not general guarantees about dependencies.

### Zero preference and empty traversal

Given zero preference and a first bound result of zero:

- Preferred selection is skipped.
- The bound dependency is called once.
- No entry resolution or predicate dispatch occurs.
- Output receives the candidate-slot address.
- The final candidate operation follows output.

The candidate and output contents are not established as null.

### Preferred success

Given nonzero preference and nonzero preferred resolution:

- The preferred dependencies run in their specified order.
- The temporary-slot operation precedes candidate resolution.
- No traversal-bound call occurs.
- Output receives the candidate-slot address.
- The final candidate operation occurs afterward.

### Match at the first index with a stable bound of two

Given zero preference, a stable bound of two, and a nonzero predicate result at index zero:

- One bound call, one entry resolution, and one predicate call occur.
- Only index zero is visited.
- Output receives the index-zero location calculated from the base read after the predicate.
- Index one is not visited.
- No second bound call occurs.

This distinguishes early matching from exhaustion under the same bound.

### Preferred failure followed by a second-entry match

Given zero preferred resolution, bounds permitting indices zero and one, and predicate results zero then nonzero:

- Traversal starts at index zero.
- Each visited index has a preceding bound call.
- Both predicates receive the original query.
- Output receives the index-one entry location calculated after the successful predicate.
- Index two is not visited.

### Exhaustion with a stable bound of two

Given zero preference, a stable bound of two, and zero predicate results at both visited indices:

- Bound calls occur before indices zero and one, and again when the index reaches two.
- Exactly two entry resolutions and predicate calls occur.
- The final comparison fails.
- Output receives the candidate-slot address.

### Maximum bound and early termination

Given a stable bound of \(2^{32}-1\):

- A match at index zero terminates after visiting only index zero.
- Only if all permitted predicates return zero does traversal reach index \(2^{32}-2\), then fail its next comparison at \(2^{32}-1\).
- Neither outcome wraps the traversal index.

This example describes control flow only; it does not assert that the corresponding addresses are valid.

### Base mutation during a successful predicate

Given an entry resolved using one base and a predicate that replaces the collection base with another valid base before returning nonzero:

- Predicate dispatch uses the object resolved from the earlier base.
- Output uses the later base at the same index.
- No renewed bound check or entry resolution intervenes.

### Zero traversal resolution

Given a visited entry whose resolution returns zero:

- The function does not classify it as a nonmatch.
- It proceeds to the dispatch access using that result.
- No controlled error outcome is established.

### Output mutation through another dependency

Given another dependency that can reach and write output-accessible storage, this function provides no visible isolation preventing that write. Final output contents cannot be derived from argument forwarding alone.
