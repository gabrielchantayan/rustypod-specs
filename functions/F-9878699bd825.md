# F-9878699bd825

## Purpose

F-9878699bd825 compares two records by a 32-bit length field and, when those fields are equal, by unsigned payload bytes.

The established behavior is **length-first**, not conventional lexicographic ordering of variable-length strings:

- Unequal length fields determine the result without accessing payload-pointer fields or payload contents.
- Equal lengths cause payload comparison in increasing byte-offset order.
- The first unequal byte determines the payload-comparison result.
- Embedded zero bytes are ordinary data, not terminators.

For suitably aligned payloads, four-byte comparisons skip equal regions. Numerical ordering of the four-byte values never determines the return value. A differing region is reconsidered byte by byte.

An efficient comparator for length-bearing binary records is the inferred intent. The records’ application-level meaning, ownership, and intended consumers are not established.

### Output

The result is a signed 32-bit integer with three cases:

| Condition | Result |
|---|---|
| Length fields differ | Their left-minus-right difference modulo \(2^{32}\), represented as a signed 32-bit result |
| Length fields match and all compared payload bytes match | Zero |
| Length fields match and a payload byte differs | First unequal left byte minus its corresponding right byte, treating both as unsigned values |

A byte-derived result is between −255 and 255. A length-derived result can have any signed 32-bit value.

For ordinary small lengths, the sign of the length-derived result agrees with increasing length. This does not hold over the entire unsigned 32-bit domain. The function does not establish a conventional unsigned-length total order for arbitrary length patterns.

## Behavior

### Length comparison and early return

The left length field is read first. The right length field is then read for subtraction.

The subtraction is performed over 32 bits. A nonzero result returns immediately. On that path:

- Neither payload-pointer field is read.
- No payload byte or four-byte region is read.
- Payload alignment and contents do not affect the result.

A zero subtraction means that the two 32-bit length patterns are identical. There is no distinct unequal-length case that wraps to zero.

The returned sign must not be interpreted as universally reliable unsigned-length ordering. For example, a left length of `0xffffffff` and a right length of zero produce the result pattern `0xffffffff`, represented as −1 in the supported signed machine model.

### Equal-length pointer acquisition

When the length fields match, the right payload-pointer field is read, followed by the left payload-pointer field.

Both reads precede the zero-length return. Consequently, empty records may contain null or otherwise nondereferenceable payload addresses, but the fields storing those addresses must remain readable.

The function does not replace either pointer field or return a payload address.

### Conditions for four-byte comparison

Four-byte payload comparison is selected exactly when:

1. The common unsigned length is at least four; and
2. Both payload addresses are divisible by four.

Alignment of only one address is insufficient. Record-address alignment does not select this path; it is the stored payload addresses that are checked.

Lengths zero through three never select four-byte payload comparison. A length of exactly four still requires both payload addresses to be aligned.

### Equal-region skipping and mismatch recovery

On the four-byte path, the function compares corresponding four-byte regions beginning at the current payload positions.

An equal region advances both comparison positions by four and reduces the remaining count by four. Another four-byte comparison occurs only while at least four bytes remain.

A differing region does not reduce the remaining count. Comparison resumes bytewise from the beginning of that region, so the first unequal byte—not the numerical relationship between the word values—determines the result.

This preserves increasing-byte-offset comparison under stable-memory assumptions, regardless of the numerical ordering imposed on four-byte values by the environment.

The final four-byte pair is evaluated for equality again after the scanning loop exits. That repeated evaluation occurs whether the exit resulted from:

- A differing four-byte pair; or
- An equal pair leaving fewer than four bytes remaining.

For stable memory, this repetition does not change the result. For changing or read-sensitive memory, it can affect subsequent control flow. The stable-memory contract must not be extended to such storage without additional assumptions.

The representation does not establish which operand of a four-byte equality expression is read first. Repeated expressions also do not establish a required count of physical loads in an optimized executable.

### Bytewise comparison

The byte phase examines the remaining payload in increasing offset order.

Each compared byte is interpreted as an unsigned value from 0 through 255. The first unequal pair returns the left value minus the right value. Subsequent byte comparisons do not occur.

If all remaining bytes match, the result is zero.

The byte phase groups comparisons in pairs, with a separate entry arrangement for an odd remaining count. This organization does not change the logical payload range:

- An even positive count starts with the first comparison of a pair.
- An odd count starts with a single comparison of the first remaining byte, then continues through paired comparisons if needed.
- No initial byte is skipped for an odd count.
- The odd-count adjustment does not authorize an extra payload read.

For each byte comparison, the represented left-byte read precedes the corresponding right-byte read.

A byte mismatch can be detected after the encompassing four-byte region has already been read. Thus, stopping at the first mismatch does not guarantee that no later byte within that same four-byte region was previously fetched.

### Zero length and counter boundaries

Equal zero lengths return zero after both payload-pointer fields have been read, without any payload dereference.

High-bit-set lengths are not rejected or interpreted as negative remaining counts. Remaining-length comparisons and updates use unsigned 32-bit behavior.

For an odd remaining count of `0xffffffff`, the odd-count adjustment wraps to zero. This does not cause immediate successful completion: the initial byte pair is still compared. If it matches, the subsequent decrement produces `0xfffffffe`, and comparison continues.

That observation establishes counter behavior only. It does not establish that a payload of such a length can be validly traversed in the represented address space. Address wraparound and inaccessible storage have no defined recovery path here.
