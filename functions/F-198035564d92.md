# F-198035564d92

## Purpose

F-198035564d92 performs a sequence of memory writes, optionally obtains its write operands by traversing linked records, invokes an unresolved call target, and then reaches a breakpoint and an invalid-instruction termination marker in the supplied representation.

The established behavior is a low-16-bit write to an object-relative address, selection of three 32-bit output words and an unsigned address selector, three consecutive word writes, and a further selector-derived 16-bit write. The function is not established to return normally.

A higher-level purpose cannot be established. The address calculations and terminal control flow might reflect hardware-facing behavior, incomplete recovery of executable instructions, or another context absent from the supplied material. None of those interpretations is part of this contract.

## Behavior

### 1. Initial object-relative write

The first represented memory effect is a 16-bit write at the object address plus 18 bytes. The written value is the low 16 bits of the original value word.

This happens before traversal and before the later output writes. In particular:

- The write occurs in both control branches.
- A value subsequently loaded during traversal does not replace the value already written here.
- If the destination overlaps records or other later-read memory, the initial write can affect subsequent behavior.
- If this access faults, no later operation is established to occur.

The ambient selector source is logically shifted right by 18 bits to form the initial unsigned selector. Its possible range is therefore `0` through `0x3FFF`.

### 2. Optional record traversal

When the control input is nonzero, traversal is skipped. The initial selector and ambient payload remain the sources for the later operations, and the original value word remains the first output word.

When the control input is zero, traversal uses records with the following observed fields:

| Byte offset | Width | Role |
|---:|---:|---|
| 4 | 32 bits | First output word, read from the selected record. |
| 8 | 32 bits | Flags word; bit 21 controls continued traversal. |
| 12 | 32 bits | Replacement unsigned selector. |
| 16 | 32 bits | Next-record address during traversal; later also read as the third output word from the selected record. |

No complete record size or meaning for unlisted bytes is established.

Each traversal iteration has an important read order:

1. The address of the current record’s flags word is retained.
2. The next-record address is read from the current record at byte offset 16, and traversal advances to that address.
3. The flags word is read from the record that was current before the advance.
4. Traversal repeats if bit 21 of that flags word is set.

Thus, the stop condition concerns the predecessor record, while the final selected record is its successor.

At least one next-record read and one flags read occur on the zero-control path. Even if bit 21 is clear in the initial record, the initial record is not selected for the subsequent three data loads: its successor is selected.

After traversal stops, the function reads these fields from the selected record, in this represented order:

1. Offset 4: replacement first output word.
2. Offset 12: replacement selector.
3. Offset 16: replacement third output word.

The selected record’s flags are not checked merely because it was selected. Its flags are checked only if another traversal iteration reaches them.

There is no shown null check, cycle detection, traversal bound, or error return. A chain whose tested flags always have bit 21 set can continue indefinitely, assuming its accesses remain possible.

### 3. Three-word output write

Using the selected unsigned selector, the output base address is:

**8192 × floor(selector / 16).**

The function then performs three 32-bit stores in ascending address order:

| Address | Stored value |
|---|---|
| Output base | Original value word on the nonzero-control path; selected-record word at offset 4 on the zero-control path. |
| Output base + 4 | Stack-derived word. |
| Output base + 8 | Ambient payload on the nonzero-control path; selected-record word at offset 16 on the zero-control path. |

These are three separate represented stores, not an established atomic transaction.

On the nonzero-control path, the selector is at most `0x3FFF`; consequently, the output base ranges from zero through `0x7FE000`, in increments of `0x2000`. Its calculation does not overflow a 32-bit unsigned value.

On the zero-control path, the loaded selector may use all 32 bits. The mathematical product can require 41 bits. Under a 32-bit wrapping interpretation, the output base depends only on selector bits 4 through 22; bits 0 through 3 are discarded before multiplication, and bits 23 through 31 are lost through overflow.

The output address is derived directly from the selector, not from the object address or record address. No allocation or destination-capacity check is shown.

### 4. Selector-derived halfword write

The selected selector is then logically shifted right by eight bits. Call this resulting value the **reduced selector**.

A 16-bit value is written at the address equal to the reduced selector plus 10 bytes. The stored value is the low 16 bits of the reduced selector shifted left by 12 bits. Equivalently, only the reduced selector’s low four bits contribute: they become bits 12 through 15 of the stored halfword; bits 0 through 11 are zero.

This write follows all three output-word stores. If it overlaps an earlier destination, it can overwrite part of the earlier result. The representation supplies no non-aliasing guarantee.

On the nonzero-control path:

- The reduced selector equals the ambient selector source logically shifted right by 26 bits.
- Its range is zero through 63.
- The halfword destination therefore ranges from address 10 through address 73.

On the zero-control path, the reduced selector ranges from zero through `0xFFFFFF`; the destination ranges from 10 through `0x1000009`.

These unusually low possible addresses are consequences of the supplied expressions, not evidence that the addresses are valid in the execution environment.

### 5. Unresolved call and terminal operations

After the halfword write, the function invokes an unresolved call target with four represented 32-bit arguments:

1. The reduced selector shifted left by 24 bits.
2. The same shifted value.
3. The stack-derived word.
4. The constant `0x010E8000`.

At 32-bit width, each of the first two arguments retains only the reduced selector’s low eight bits, placed in the highest byte. Equivalently, it depends on bits 8 through 15 of the selected selector.

The call’s result is not used in the supplied representation.

If the call returns normally, the next represented operation is the breakpoint with immediate `0xB4`. An invalid-instruction termination marker follows. Whether a real execution reaches, resumes past, traps at, or terminates on either operation is not established.

- The selected selector is `0x10`.
- The three output words are written at `0x2000`, `0x2004`, and `0x2008`.
- Their values are the original value word, the stack-derived word, and the ambient payload, respectively.
- The reduced selector is zero, so the later halfword write targets address 10 and writes zero.
- The unresolved call’s first two arguments are zero.

No traversal-field read is required by this branch.

### A clear flag selects the successor

Given zero control, an initial record A whose bit 21 is clear, and A’s next field pointing to B:

- A’s next field is read before A’s flags.
- B supplies the fields at offsets 4, 12, and 16.
- A does not supply those three fields.
- B’s flags need not be read.

If B’s selector is `0x00001234`, the output base is `0x246000`, the reduced selector is `0x12`, the later halfword destination is `0x1C`, and the halfword value is `0x2000`. The call’s first two arguments are each `0x12000000`.

### A set flag continues from the successor
