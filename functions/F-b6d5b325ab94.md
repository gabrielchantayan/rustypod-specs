## Behavior

### Sign handling

Numerator sign handling occurs first. A negative numerator requests a negative result and is replaced by its arithmetic negation.

Denominator sign handling occurs second. If the denominator word is negative under signed interpretation:

- Its value is replaced by unsigned modular negation.
- The pending result sign is toggled.

For representable normalized magnitudes, exactly one negative operand requests a negative result. Zero or two negative operands request a nonnegative result.

The two normalization operations have different arithmetic implications:

- Negating an unsigned denominator is modular. Denominator word `0x80000000` remains `0x80000000`, representing magnitude \(2^{31}\) after normalization.
- Negating numerator −2,147,483,648 requires positive 2,147,483,648, which is not representable in a 32-bit signed integer.

Consequently, minimum-signed-numerator inputs do not have an unconditional numeric contract from this representation.

For the remaining discussion, \(A\) denotes the normalized numerator magnitude and \(B\) the normalized denominator magnitude, where normalization is established or explicitly assumed.

### Route selection

Routing uses the denominator leading-zero count minus the numerator leading-zero count. Call this difference \(d\).

- If \(d\) is nonnegative, execution takes the unresolved computed-transfer path.
- If \(d\) is negative, execution enters the visible fractional calculation.
