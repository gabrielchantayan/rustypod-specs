# F-4a5b04c3d333

## Purpose

F-4a5b04c3d333 performs a signed-index lookup through a table located indirectly from a dependency-supplied base address. It returns the selected table entry as a 32-bit result, or zero when the index fails the observed bounds condition.

The established bounds condition is an inclusive lower bound of zero and an exclusive upper bound supplied by a signed 32-bit field. Index zero is therefore eligible when that field is positive. Negative indices are rejected without reading the field.

Interpreting the field as an entry count and the selected value as a pointer is consistent with the observed access pattern. Those semantic roles are inferred intent, not independently established object definitions.

## Interface

### Input

One signed 32-bit integer, referred to here as the **index**.

The index is used both in a signed bounds comparison and, when accepted, to select a four-byte table slot. There is no separate table, length, context, or output-buffer argument.

### Output

One 32-bit result containing either:

- Zero, for an index rejected by the bounds condition.
- The complete 32-bit value read from the selected table slot, for an accepted index.

The recovered representation treats the selected value as pointer-shaped and returns it through an integer-shaped interface. The observable contract is the returned bit pattern. A value with its highest bit set must not be interpreted automatically as an error: it may be a selected table value represented as a negative signed integer.

A zero result does not distinguish an invalid index from an accepted index whose selected slot contains zero.

### Dependency result

F-ecd921e533b1 is called without explicit arguments and supplies a 64-bit result. This function uses the low 32 bits as an address base. The high 32 bits do not affect the established return value or memory-access decisions.

The base is captured from this dependency result. No additional call is made to refresh it during the lookup.

### Relevant layout

The following locations are relative to the captured base:

| Location | Width | Established use |
|---|---:|---|
| Base plus 0x48 | 32 bits | Loaded as the table address, only for an accepted index |
| Base plus 0x4C | 32 bits | Loaded and interpreted as the signed upper bound, for every nonnegative index |

Byte order is not independently established by the supplied evidence. The fields are accessed as native 32-bit values in the represented execution environment.

## Behavior

### Dependency call and negative-index rejection

The dependency call occurs before any index-based rejection. A caller cannot rely on a negative or otherwise invalid index to avoid dependency execution.

For a negative index, the function returns zero without directly reading either of the two base-relative fields or any table entry.

This distinction limits memory-access preconditions for that path. If the dependency returns normally, the function does not itself require its returned low 32 bits to identify readable storage when the index is negative. The dependency may have its own requirements and effects.

### Nonnegative-index bounds check

For every nonnegative index, the function first reads the signed 32-bit field at base plus 0x4C.

The index is accepted exactly when it is strictly less than that field. Equality is rejected. A larger index is also rejected.

Consequently:

- A positive upper bound permits indices from zero through one less than the bound.
- A zero upper bound permits no indices.
- A negative upper bound permits no indices.

A negative upper bound is not treated as a large unsigned capacity. Both operands participate in a signed comparison.

The function does not separately validate the upper bound. Its sign and value affect acceptance through the same comparison used for ordinary positive bounds.

### Accepted lookup

After an index is accepted, the function reads the 32-bit table address from base plus 0x48. It then reads one 32-bit entry at the table address displaced by four times the index.

The selected entry is returned without further dereferencing. The function does not inspect an object at that entry’s value, verify that the entry identifies readable memory, or reject a zero entry.

The accepted path therefore has this direct-read order:

1. The upper-bound field.
2. The table-address field.
3. The selected table entry.

The table-address field is not loaded before the bounds check. Rejected nonnegative indices do not cause a direct table-address or table-entry read.

### Arithmetic and addressing

The recovered interface and addressing operations use 32-bit quantities. Table entries occupy four bytes, and the index displacement is four times the index. The low 32 bits of the dependency result supply the base; the full 64-bit dependency result is not used as a wider address.

Bounds acceptance alone does not prove that address arithmetic is representable or that the selected slot is accessible. In particular, a large positive upper bound can admit an index whose four-byte displacement does not fit a signed 32-bit value.

The evidence contains no explicit overflow check, address-range check, or recovery path for such a case. A portable checked-overflow policy cannot be derived from it. Successful, defined lookups require the relevant address calculations and memory accesses to be valid under the actual execution environment.

### Errors and abnormal execution

There is no explicit error channel other than the zero result used for rejected indices. There is no observed diagnostic, exception handler, retry, or fallback table.

A nonnegative index requires the upper-bound location to be readable. An accepted index additionally requires the table-address location and selected slot to be readable. Invalid storage may prevent normal completion; the evidence does not establish a particular fault or language-level failure mode.

A null base or null table address is not explicitly checked. Neither is assigned a special meaning by this function.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They are not reports of executed tests. Each example assumes the dependency returns normally and any required accesses and address calculations are valid.

### Negative index

For index −1:

- F-ecd921e533b1 is called once.
- Neither base-relative field is directly read.
- No table entry is directly read.
- The result is zero.

The same direct behavior applies to the minimum signed 32-bit index.

### First entry in a nonempty table

For index zero and an upper bound of three:

- The upper-bound field is read first.
- The table-address field is read next.
- The first four-byte table slot is read.
- Its exact 32-bit value is returned.

Zero is not rejected merely because it is zero.

### Last eligible entry

For index two and an upper bound of three, the selected slot is eight bytes after the table address. Its 32-bit value is returned.

### Index equal to the bound

For index three and an upper bound of three:

- The upper-bound field is read.
- The result is zero.
- Neither the table-address field nor any table entry is directly read.

### Index greater than the bound

For index four and an upper bound of three, the result and direct-read behavior match the equality-rejection case.

### Nonpositive upper bound

For index zero and an upper bound of zero or −1, the result is zero after reading the upper-bound field. No table-address or table-entry read follows.

### Zero-valued selected entry

For an accepted index whose selected slot contains zero, the result is zero after all three required reads. This result is indistinguishable from rejection by return value alone.

### High-bit selected value

For an accepted index whose selected slot contains 0x80000000, that exact 32-bit pattern is returned. A signed interpretation may display −2147483648; the function does not convert it into a separate error.

### Different dependency high halves

If two dependency results have identical low 32 bits but different high halves, and all relevant memory and dependency effects are otherwise equivalent, this function performs the same direct reads and returns the same result.
