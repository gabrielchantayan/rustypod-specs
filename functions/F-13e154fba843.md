# F-13e154fba843

## Purpose

F-13e154fba843 positions a mutable context relative to a requested value and reports a comparison or positioning result separately from its status return.

The supplied representation establishes two search paths:

- A record-decoding path that compares a decoded, two-word value against the requested value.
- A materialization-and-comparison path that obtains record data, sometimes through temporary storage, and delegates comparison.

The function can also follow a reference selected from the search result and repeat the search against a newly selected descriptor. This is consistent with traversal of a multilevel search structure, but the structure’s application-level meaning is inferred, not established.

A zero status does not imply an exact match. Exact matches, nonmatching positions, and certain bypass conditions can all return zero. Callers must interpret the separate result output and the resulting context state.

## Interface

### Arguments and return

The interface has eight arguments. The supplied representation uses 32-bit integers and addresses.

| Position | Contract role |
|---|---|
| 1 | Address of a mutable context. |
| 2 | A 32-bit auxiliary value passed to key preparation and later tested to decide whether to invoke a cleanup dependency. |
| 3 | A 32-bit search-key value or handle. A zero value can trigger preparation of a replacement key. Its precise type is unknown. |
| 4 | An opaque 32-bit argument. It is retained in the supplied representation but has no established subsequent use. |
| 5 | Low 32 bits of the requested two-word value. |
| 6 | High 32 bits of that value, interpreted as signed for ordering. |
| 7 | Initial-position selector: zero selects the middle record; any nonzero value selects the last record. |
| 8 | Address of a 32-bit signed result output. It is conditionally nullable, not universally optional. |

The return is a 32-bit status. Explicitly generated statuses are zero, 7, and 11. Nonzero statuses from initialization, record loading, and reference selection can also be propagated.

The result output receives:

- `0` on an exact match;
- `-1` on certain bypasses;
- otherwise the final comparison result.

A delegated comparison result need not be limited to `-1`, `0`, or `1`; the function branches on its sign and can return its magnitude unchanged.

Some paths return an error without writing the result output.

## Behavior

### Entry fast paths

Before initialization, the function reads the context byte at `0x43`.

Only when that byte equals exactly one does it examine the cache fast path. It then reads the byte at `0x42`; if that is nonzero, it reads the descriptor address and the descriptor byte at offset 3.

If both flags permit cached-value use:

1. The cached high word is compared with the requested high word.
2. If equal, the cached low word is compared with the requested low word.
3. If both match, the function writes zero through the result pointer and returns zero immediately.

That write has no null check.

If the cached value differs, the function reads the context byte at `0x41`. When that byte is nonzero and the cached value is less than the request, it writes `-1` through the result pointer and returns zero. This write also has no null check.

The ordering is signed across the high word and unsigned across the low word. Equivalently, it compares the values as signed 64-bit two-word integers. The supplied arithmetic accounts for low-word borrow and signed overflow; it is not merely a signed comparison of a wrapped subtraction.

Neither early return invokes initialization or the final cleanup dependency.

### Initialization and search gating

Absent an early return, the function calls F-7f3971a6513c with the context. A nonzero return is propagated immediately, without the common cleanup call and without a guaranteed result-output write.

After successful initialization, the context byte at `0x43` is read again. A zero value causes an unconditional write of `-1` through the result pointer and a zero status return.

A nonzero value permits searching. This condition is broader than the entry fast-path condition, which requires exactly one.

The descriptor byte at offset 3 is then inspected. If it is zero and the current search-key argument is also zero, F-14b94d129a16 is invoked with:

- the context field at `0x10`;
- the requested low word;
- the auxiliary argument;
- the address of a 200-byte local scratch area;
- the capacity 200.

Its return replaces the current search-key value. A zero return produces status 7 immediately, without the common cleanup call.

A nonzero descriptor byte at offset 3 permits searching without a nonzero search key.

### Search initialization

Each search or reference-following restart reloads the descriptor address from the context and reads its unsigned 16-bit record count.

The initial lower bound is zero. The upper bound is the record count minus one, computed as a signed 32-bit value. Therefore:

- a zero count gives an upper bound of `-1`;
- the maximum count, 65,535, gives an upper bound of 65,534.

The provisional comparison result is `-1`.

If both the descriptor mode byte and current search-key value are zero, the function exits through common cleanup with status 11.

Otherwise, the context index is set to:

- the upper bound divided by two when the initial-position selector is zero;
- the upper bound when that selector is nonzero.

For a zero record count, the search loop is skipped. With signed division truncating toward zero, the middle-selection expression gives zero for an upper bound of `-1`; last-record selection gives `-1`. Subsequent reference processing may replace this index.

### Probe ordering and delegated comparison

Before every actual record probe, the function writes:

1. zero to the context’s 16-bit field at `0x3e`;
2. one to the context byte at `0x42`.

In delegated-comparison mode, F-fbe5678d9048 receives the context, an address for a 32-bit probe value, and zero. The function then snapshots the context words at `0x28` and `0x2c`.

It sign-extends the 32-bit probe value to a two-word value and compares that against the snapshot.

If the sign-extended probe value is greater than or equal to the snapshot, F-f32ae16436e9 is called with the snapshot’s low word, the return from F-fbe5678d9048, and the current search key.

Otherwise:

1. F-391e3d30e634 is called with the snapshot’s low word.
2. A zero return produces status 7 through common cleanup.
3. A nonzero return is passed to F-d03652a548f9 together with the context, zero, and the snapshot’s low word.
4. F-f32ae16436e9 is called using that same returned value and the search key.
5. F-94cb53877c15 is called on the returned value.
6. Only then is the status from F-d03652a548f9 checked and, if nonzero, propagated.

Consequently, comparison and release occur even when the preceding load operation reports an error. No independent null or validity check protects that comparison.

### Direct record decoding

In direct-decoding mode, the current record’s table entry is located using:

- the unsigned 16-bit table-start offset;
- twice the current index;
- the descriptor’s storage base.

The two-byte table entry supplies a big-endian offset relative to the storage base. The descriptor byte at offset 9 is then added to obtain the comparison payload address.

If the descriptor byte at offset 7 is nonzero, a prefix is consumed:

- a first byte below 128 supplies a one-byte prefix;
- otherwise F-887200f76f20 determines the prefix value and consumed-byte count.

The payload address advances by that consumed count. The visible function imposes no check on the returned count.

F-174052de586c then receives the payload address and an output address. Subsequent logic uses two 32-bit words as the decoded comparison value. The exact extent of this dependency’s writes is not established by the supplied representation; this matters particularly for the high word.

An exact two-word match produces comparison result zero. Otherwise, the same signed-high/unsigned-low ordering produces `-1` or `1`.

### Bounds, cache updates, and exact matches

A negative comparison advances the lower bound to one past the current context index. A positive comparison moves the upper bound to one before that index.

If the resulting bounds still overlap, the context index becomes their integer midpoint and probing continues.

On exhaustion after a probe, the last candidate’s low and high words are written to context offsets `0x28` and `0x2c`, in that order.

On an exact match, those same cache writes occur immediately. Then:

- If descriptor byte 6 is nonzero and byte 4 is zero, the selected reference index is the current context index, and reference processing follows.
- Otherwise, a nonnull result pointer receives zero, and the function proceeds to successful cleanup.

A zero-count search does not perform these candidate-cache writes.

### Reference selection and restart

Following a non-exact termination, reference processing occurs only when descriptor byte 4 is zero.

If the selected reference index is less than the record count, its big-endian table entry identifies a location relative to the storage base. Unlike comparison-payload addressing, this location does not add descriptor byte 9.

Otherwise, the location is the storage base plus descriptor byte 8 plus eight.

F-d1e995cfb2d3 is called with this location.

If it returns zero, no restart occurs. A nonnull result pointer receives the current comparison result, and successful cleanup follows.

If it returns nonzero, the function writes, in order:

1. the selected reference index to context offset `0x1c`;
2. zero to the 16-bit field at `0x3e`;
3. zero to the byte at `0x42`.

It then invokes F-f5f7d8715f96 with the context and returned reference. A nonzero status exits through common cleanup. A zero status restarts search initialization, including reloading the descriptor.

The visible function supplies no traversal-depth limit, cycle detection, or progress check.

## Side effects

The function mutates the context during searching, including on paths that later return an error. No rollback is visible.

The result pointer is mandatory for entry-cache returns and the post-initialization disabled-search return. It may be null for normal terminal search results and ordinary exact matches. Callers requiring safety independent of path should supply a valid writable 32-bit destination.

Common cleanup calls F-9444ff86c269 with the current search-key value whenever the auxiliary argument is nonzero. This includes successfully completed direct-decoding searches, even if key preparation never occurred.

It does not include every return: entry bypasses, initialization errors, the disabled-search return, and initial key-preparation failure bypass common cleanup.

This conditional cleanup is an observed call rule, not proof of ownership. The auxiliary argument’s nonzero value does not, by itself, establish that the original or replacement key is owned by this function.

Temporary materialization explicitly pairs a nonzero result from F-391e3d30e634 with F-94cb53877c15 before checking the loading status. Other dependency ownership effects are unknown.

No dependency is assumed to preserve global state or unmentioned context fields.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Cached equality:** With context byte `0x43` equal to one, byte `0x42` nonzero, descriptor byte 3 nonzero, and both cached words equal to the request, expect result zero and status zero. Initialization and common cleanup are not called.

2. **Cached lower value:** Under the same cache conditions, with byte `0x41` nonzero and cached value less than the request, expect result `-1` and status zero without initialization.

3. **Signed ordering boundary:** A candidate with high word `0xffffffff` orders below a request with high word zero, regardless of their low words. Equal high words require unsigned low-word ordering.

4. **Initialization failure:** If F-7f3971a6513c returns a nonzero status, expect that status directly. No result-output write or final key cleanup is guaranteed.

5. **Disabled after initialization:** If initialization succeeds and context byte `0x43` is then zero, expect an unconditional result write of `-1` and status zero.

6. **Temporary-load failure:** If temporary acquisition succeeds but F-d03652a548f9 fails, expect comparison followed by release before the loading error is returned.

7. **Ordinary exact match:** With a valid decoded candidate equal to the request and no required reference traversal, expect cache writes, result zero if the pointer is nonnull, and successful common cleanup.

8. **Exact match requiring traversal:** With descriptor byte 6 nonzero and byte 4 zero, equality does not itself terminate. A nonzero extracted reference triggers context transition and another search.

9. **Empty descriptor:** With zero records and a permitted search mode, expect no record probe. Reference processing may still occur when descriptor byte 4 is zero. Without a nonzero reference, the reported comparison is `-1`.

10. **Non-unit delegated comparison:** If the terminal delegated comparison returns a positive value such as 4, no reference is followed, and the output pointer is nonnull, expect 4 rather than a normalized `1`.
