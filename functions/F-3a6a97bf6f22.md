# F-3a6a97bf6f22

## Purpose

F-3a6a97bf6f22 repeatedly removes the head of a context-associated linked list, updates each removed record, transfers an associated value into indexed storage when the configured width is nonzero, and updates counters. Once the list is empty, it conditionally invokes a final dependency, invokes an unconditional final dependency, and returns a 32-bit zero if execution returns normally.

**Established static evidence:** list removal, flag clearing, conditional record relinking, indirect state writes, indexed transfers, counter updates, and final-call selection are visible.

**Inferred intent:** the context resembles a bounded queue or ring buffer, and the removed records resemble pending transfer requests. The counters resemble occupancy, total-transfer count, and peak occupancy. These interpretations are descriptive only; the contract below uses the actual field operations.

**Unknown:** the source does not establish the complete calling convention, synchronization model, allocation ownership, dependency behavior, or whether the apparent ring-buffer invariants hold.

## Behavior

### Preconditions and arithmetic model

Normal execution requires every address actually accessed to be valid for the corresponding read or write width. No null, bounds, capacity, alignment, or overflow checks are visible beyond the pending-head termination test and the branches described below.

The visible representation uses 32-bit words and address calculations. No widening arithmetic is shown. Counter and address overflow are not explicitly handled. Acceptance examples involving increments or scaled addresses assume representable results unless stated otherwise.

The high-water comparison is unsigned. Index-reset comparison is equality, not a range check. The source does not establish portable overflow behavior for every recovered integer expression; callers must not rely on an overflow case without further machine-level evidence.

### Pending-list processing

The function repeatedly reads the context’s pending head. A zero head ends processing. Otherwise, that head identifies the current record.

For each current record, the following operations occur in this order:

1. Read the record’s next-link word and write it to the context’s pending head.
2. If that next-link value was nonzero, reread the current record’s next-link word and write the address of the context’s pending-head field into offset 4 of the resulting successor.
3. Read the record’s flags word, clear bit `0x80`, and write the result back.
4. If the resulting flags word is exactly zero:
   - Read the auxiliary list head.
   - Write that head into the current record’s next-link word.
   - Write the current record’s address into the auxiliary list head.
5. Read the record’s offset-8 field. If it is nonzero:
   - Invoke F-f46257aeeddc.
   - After that invocation returns, write the replacement value into the record’s offset-8 field.
6. Follow the record’s offset-16 pointer and then read the referenced object’s offset-4 word to obtain the target address.
7. Write the replacement value into target offset 4.
8. Read and increment the context’s offset-16 count.
9. Read and increment the context’s current index. Write the incremented value back. If that value equals the index limit, write the replacement value as the current index.
10. Reread the current index for destination selection.
11. Perform the width-dependent transfer described below.
12. Increment the context’s offset-44 counter.
13. Read the context’s offset-16 count and its offset-48 high-water field. If the count is unsigned-greater than the high-water field, write the count into the high-water field.
14. If the count read for this comparison equals one, read context offset 32. If that field is nonzero, invoke F-6ad030b1b8cc.
15. Return to the pending-head read.

The loop is driven by the current pending-head field, not by an initial list snapshot. Dependency mutations can therefore affect subsequent iterations.

The successor’s backlink receives the **address of the head field**, not the context address and not the removed record’s address.

Clearing bit `0x80` does not itself guarantee auxiliary-list insertion. Insertion occurs only when **all** flag bits are zero afterward.

### Indexed transfer

Destination selection uses the index after incrementing it and after any equality-triggered reset.

- **Width zero:** no direct transfer and no invocation of F-2489d48d501c occur. The record processing and counters still advance.
- **Width one:** read the target’s offset-16 source pointer, read one byte from that source, and write one byte at destination base plus current index.
- **Width two:** read the source pointer, read a 16-bit value, and write a 16-bit value at destination base plus twice the current index.
- **Width four:** read the source pointer, read a 32-bit value, and write a 32-bit value at destination base plus four times the current index.
- **Any other nonzero width:** invoke F-2489d48d501c with the computed destination address and the source pointer.

For the dependency-mediated case, the destination is base plus transfer width multiplied by current index. Only the destination and source arguments are explicit in the supplied call. A transfer-length argument, implicit length convention, and exact copy semantics are not established.

For the direct cases, the source value is read before its destination write. The source data is not visibly advanced afterward. No overlap handling or alignment adaptation is shown.

The index reset is not a modulo operation. A value that is already beyond the limit is not brought back into range merely because it exceeds that limit. The reset value is the implicit replacement value, not an established constant zero.

### Final decision and completion

After the pending head is observed as zero, the function reads the auxiliary list head.

- If that head is nonzero, invoke D-01 with that head value. The cursor pair and flag byte are not read on this path.
- If that head is zero, read the cursor object’s words at offsets 8 and 12.
  - If they differ, invoke D-01 with the offset-8 word. The flag byte is not read.
  - If they are equal, read the auxiliary object’s offset-1 byte.
    - If the byte is nonzero, invoke D-01 with its zero-extended value.
    - If the byte is zero, omit D-01.

Next, invoke D-02 unconditionally, provided preceding execution reaches this point. Return zero if D-02 returns normally.

No rollback is visible if a dependency fails to return or an access faults.

## Acceptance examples

These are conditional static examples, not executed tests. Unless specified otherwise, they assume valid, non-overlapping storage, ordinary stable memory, representable arithmetic, and dependencies that return without changing relevant state.

1. **Empty list with no final trigger.**  
   Pending head and auxiliary head are zero, the two cursor words are equal, and the flag byte is zero. No per-record operation occurs. D-01 is omitted, D-02 is called, and the result is zero.

2. **Nonempty auxiliary list takes precedence.**  
   Pending head is zero and auxiliary head is nonzero. D-01 receives the auxiliary head. Neither cursor word nor the flag byte is read by the final-decision path.

3. **Unequal cursors select the first cursor value.**  
   Auxiliary head is zero and cursor words differ. D-01 receives the offset-8 cursor word, even if that word is zero. The flag byte is not read.

4. **Equal cursors permit the byte trigger.**  
   Auxiliary head is zero, cursor words match, and the flag byte is `0x80`. D-01 receives the 32-bit value `128`.

5. **Only the cleared flag remains.**  
   A processed record initially has flags `0x80`. Its resulting flags are zero, so it is prepended to the auxiliary list. Its next link becomes the previous auxiliary head.

6. **Another flag prevents insertion.**  
   A processed record initially has flags `0x81`. The stored flags become `0x01`; the auxiliary-list insertion branch is omitted.

7. **Transfer uses the incremented index.**  
   Current index is two, index limit is eight, and width is two. The direct transfer writes two bytes at destination base plus six, not plus four.

8. **Equality reset uses the replacement value.**  
   Current index is seven, limit is eight, replacement value is three, and width is four. The index becomes three before transfer; the destination is base plus twelve.

9. **Zero width still processes the record.**  
   Width is zero. No payload transfer occurs, but unlinking, applicable field replacement, index advancement, counters, high-water update, and conditional notification remain applicable.

10. **High-water equality does not trigger a write.**  
    The updated count equals the stored high-water field. The strict unsigned comparison does not write that field.

11. **A successor receives the head-field address.**  
    A removed record has a nonzero successor. The successor’s offset-4 field receives the address of context offset 20 before the removed record’s flags are processed.
