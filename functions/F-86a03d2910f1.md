# F-86a03d2910f1

## Purpose

F-86a03d2910f1 transfers two consecutive four-byte values from a source region into two consecutive four-byte fields of a destination object. The destination fields begin at byte offsets 28 and 32 from the supplied destination base.

The defining behavior is the access order: the second source value is read first, then the first source value is read and written to the first destination field, and finally the previously captured second value is written to the second destination field. This ordering matters when source and destination storage overlap.

The supplied static evidence establishes a fixed-size transfer, not a general-purpose copy operation. The meaning of the values and the surrounding destination object is unknown.

## Behavior

### Ordered transfer

The established access sequence is:

1. Read the four-byte value beginning at source offset 4 and retain that value for the final write.
2. Read the four-byte value beginning at source offset 0.
3. Write the value from the second read to destination offset 28.
4. Write the value retained from the first read to destination offset 32.
5. Return without an explicit result.

Both source reads therefore precede both destination writes. The second source value is not reread after the first destination write.

For stable, accessible storage, normal completion produces:

| Destination field | Result |
|---|---|
| Offset 28 | Bit pattern obtained from source offset 0 |
| Offset 32 | Bit pattern obtained from source offset 4 |

There is no conditional branch based on either value. Zero, all-one, high-bit-set, and other 32-bit patterns receive the same treatment.

### Overlap

Overlap does not introduce an additional source read. In particular, overwriting the original location of the second source value with the first destination write does not change the value used for the final write: that value has already been captured.

For ordinary stable memory, this gives the resulting pair the values read before either destination write. It does not establish a general memory-copy API, support arbitrary lengths, or guarantee atomicity of the pair.

A destination write can also modify storage that serves as source storage. Such a change is an effect of aliasing, not an additional source-directed write.

### Scope of the transfer

The function does not read destination fields before overwriting them. No merge with existing destination contents is visible.

No length, count, terminator, tag, or discriminator is inspected. The operation always attempts the same two reads and two writes on a normally executing path.

The function contains no explicit access to other destination fields. For ordinary memory, bytes outside the two destination access ranges remain unchanged by this function’s direct stores.

### Invalid accesses and interruption

If an access fails, behavior depends on the execution environment. The supplied evidence does not define fault delivery or whether an individual failing four-byte access can partially take effect.

The operation is not established as transactional. In particular, the first destination write precedes the second, so the implementation provides no visible mechanism for undoing the first write if execution cannot complete the second.
