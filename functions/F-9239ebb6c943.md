# F-9239ebb6c943

## Purpose

F-9239ebb6c943 performs an initial delegated numeric conversion, then conditionally interprets the delegated result as a radix for a second conversion introduced by the byte `0x23` (`#`).

Established behavior:

- F-d2e82eeae580 receives the caller’s cursor slot, the supplied end address, and the integer 10.
- If the cursor left by that call is at or beyond the end, or points to a byte other than `#`, the delegated result is returned.
- A recognized `#` is consumed before the function checks whether a second conversion can proceed.
- The second conversion accepts a radix from 2 through 36, an optional immediate sign, and digit values supplied by signed-byte table lookups.
- Each candidate that passes the preliminary byte filter causes a fresh read of the global table-base value followed by an indexed entry read.
- The cursor effects distinguish several zero-result paths, including an empty payload, a sign-only payload, and rejection during digit scanning.

**Inferred intent:** this resembles a radix-prefixed integer syntax. That interpretation does not establish the delegated conversion’s grammar, conventional digit mappings, or an overflow policy.

The cursor slot, input bytes, global address-bearing location, and selected table entries have separate access roles. Their storage is not established to be disjoint.

### Output

The function returns a signed 32-bit integer:

- The delegated result when no marker is recognized.
- Zero when a marker is recognized but second-conversion eligibility fails.
- Zero for a recognized sign immediately followed by the end address.
- Otherwise, the accumulated digit value, negated when a minus sign was recognized.

There is no separate success indicator. Zero can represent successful conversion, rejection before any accepted digit, missing payload, or an ineligible radix.

## Behavior

### Initial delegated conversion

The first established operation is one call to F-d2e82eeae580, supplied with:

- The original cursor-slot address.
- The original end address.
- The integer 10.

After normal return, F-9239ebb6c943 retains the delegated signed result and reads the cursor from the slot. It does not use a saved pre-call cursor for subsequent scanning.

If that cursor is at or beyond the end, the delegated result is returned without a direct input-byte read.

Otherwise, the byte at the cursor is read. If it is not `0x23`, the delegated result is returned without an additional cursor write by this function.

These paths do not reach the function’s table lookup. They do not constrain accesses performed inside the dependency.

### Marker consumption and eligibility

When the inspected byte is `#`, the function writes the address immediately following that marker into the cursor slot, then reloads the cursor from the slot.

This write is committed before eligibility is checked. It is not rolled back if the function subsequently returns zero. If the slot overlaps other relevant storage, the write may change that storage before any later read.

Second-conversion eligibility requires both:

- The reloaded cursor is unequal to the end address.
- The delegated result is greater than 1 and less than 37.

The permitted radix is therefore exactly 2–36.

The post-marker comparison tests inequality, not whether the cursor remains below the end. With ordinary valid interval arithmetic and no disruptive aliasing or mutation, advancing a cursor previously below the end reaches either another byte or the end. Behavior outside those assumptions must not be replaced with an assumed bounds guarantee.

If eligibility fails, the function returns zero. Its visible body performs no payload-byte read or table lookup on that path.

### Optional sign

For an eligible second conversion, the first payload byte is read and compared with `0x2D` (`-`).

- If the read identifies minus, the local scanning position advances by one byte and final negation is requested.
- Otherwise, the byte at the same address is read again and compared with `0x2B` (`+`).
- If that second read identifies plus, the local position advances by one byte without requesting negation.
- Otherwise, scanning begins at the existing position.

Thus a non-minus payload causes two sign-related reads at the same address. The function does not establish that repeated reads necessarily observe the same value.

Only one immediate sign is recognized. There is no visible whitespace-skipping phase.

If a recognized sign advances the local position exactly to the end, the function returns zero without publishing that advancement. Under stable cursor storage, the slot still contains the post-marker address, which points to the sign.

If digit scanning is reached, sign advancement is included in the final cursor write even if no digit is accepted.

### Preliminary byte filter

Each digit-loop iteration first requires the local scanning address to be below the end. The function then reads the current byte as an unsigned 8-bit value.

The following values terminate scanning before a global base read or entry read:

| Byte values | Classification |
|---|---|
| `0x00` | Zero byte |
| `0x09` | Horizontal tab |
| `0x0A` | Line feed |
| `0x0C` | Form feed |
| `0x0D` | Carriage return |
| `0x20` | Space |
| `0x80`–`0xFF` | High-bit bytes |

Every other value from `0x01` through `0x7F` reaches lookup. In particular, `0x0B`, vertical tab, is not rejected by this filter.

This is a specific byte classification, not a general whitespace or locale rule.

### Table lookup and digit acceptance

For each candidate that passes the preliminary filter, the established access sequence is:

1. Read the global address-bearing value used as the table base.
2. Form an entry address using that value plus the candidate byte masked to seven bits.
3. Read one signed 8-bit entry at the selected address.
4. Extend and compare the entry.

The entry is accepted only if it is nonnegative and strictly less than the selected radix. A negative entry or an entry equal to or greater than the radix terminates scanning without consuming the candidate.

An entry-based rejection still performs both the global base read and the selected entry read. A preliminary-filter rejection performs neither.

Because high-bit candidates are rejected first, the seven-bit mask does not make them aliases of lower-valued input bytes.

No mapping is established. Decimal-looking characters need not have their conventional values; letters need not be accepted; case equivalence is not established.

A new base read occurs for every lookup. Neither a fixed base nor stable entries may be assumed. The global address-bearing location and selected entry storage describe access roles, not necessarily separate storage. Either may overlap the cursor slot, and the selected entry may overlap the base-bearing location itself.

### Accumulation and completion

The accumulator starts at zero. Each accepted entry updates it to:

**previous accumulator × selected radix + accepted entry value**

After acceptance, the scanning address advances by one byte.

Scanning stops when the position is no longer below the end or when a candidate is rejected. Under ordinary valid interval progression, reaching the limit leaves the position equal to the end. A rejected candidate remains unconsumed.

On the digit-scanning completion path:

1. The accumulator is negated if minus was recognized.
2. The final scanning address is written to the cursor slot.
3. The signed result is returned.

The final write occurs even when no digit was accepted. It may affect overlapping input, global-base, or entry storage after scanning and result computation.

There is no minimum digit-count requirement, rollback, explicit overflow check, or error object. Multiplication, addition, and final negation have no established wraparound, saturation, trapping, or other overflow policy.

## Side effects

| Path | Cursor-slot writes |
|---|---|

| Inspected byte is not `#` | None |

These are conditional consequences of overlap, not assertions that overlap occurs.

1. Read the cursor slot.
2. Compare the cursor with the end.

4. If the marker matches, write the incremented address and reload the slot.

7. If digit scanning is reached, read each candidate byte.
