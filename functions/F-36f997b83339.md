# F-36f997b83339

## Purpose

F-36f997b83339 performs mode-dependent object processing, evaluates a common state predicate, selects a follow-up action or virtual notification, and forwards the original inputs to a final dependency.

Zero mode enables two descriptor-driven lookup sequences. Nonzero mode replaces those sequences with an object virtual operation. Both modes subsequently enter the common state-dependent processing.

The supplied static representation establishes branch conditions, explicit arguments, storage reuse, field accesses, and call ordering. It does not establish the application meanings of descriptors, lookup results, status values, or the object flag. “Construction,” “lookup,” “wrapper,” and “post-use operation” describe observed roles, not verified ownership or domain semantics.

## Interface

### Inputs and result

The function accepts:

1. **Object address:** a 32-bit address used for virtual dispatch and interior-field addressing.
2. **Mode:** a 32-bit integer. Zero selects descriptor processing; every nonzero value selects the alternative virtual operation.

The original object address and original mode are passed to F-fd7437c09f27 on normal completion. The mode is not normalized to a Boolean.

There is no explicit return value.

## Behavior

### 1. Initialization and retained state

First, F-979606fd565e receives the object address and initialization argument.

After it returns, the external descriptor base is read and retained. Two invocation-local conditions are initialized to zero:

- **Secondary-action condition:** later records whether the second descriptor enables its action.
- **Late-status condition:** later receives a status result in zero mode; remains zero in nonzero mode.

The descriptor base is captured even on the nonzero-mode path, although that path performs no descriptor-field processing.

### 2. Zero mode: first descriptor

The first descriptor’s primary construction proceeds as follows:

1. Read the external descriptor base again and read its 32-bit field at offset `4`.
2. Call F-9b9c1c7483f4 with the primary destination, that field value, and the primary scratch area.
3. After construction returns, read and retain the external lookup context.
4. Read the external lookup context again for the explicit context argument to F-8094c3d72052. Its other argument is the construction result.
5. Call F-8a5aadac202f with the primary destination.
6. Branch on the saved lookup result.

The context capture and the context argument to this first lookup are separate external reads. No intervening dependency call is shown, but the representation does not replace the second read with the retained value.

If the lookup result is zero, no first-descriptor secondary construction or action occurs.

If it is nonzero:

1. Read the 32-bit field at offset `4` through the retained descriptor base.
2. Call F-9b9c1c7483f4 with the secondary destination, that field value, and the secondary scratch area.
3. Call F-cf946f91e683 with the retained lookup context and the construction result.
4. Call F-8a5aadac202f with the secondary destination.
5. If the saved secondary result is zero, call F-6a21f4f07f67, then F-7a7a20db82de, then F-8a3da6f5f0f8.

F-8a3da6f5f0f8 receives the original object address, the result of F-7a7a20db82de, `1`, and `0xFFFFFFFF`, in that order.

The result of F-6a21f4f07f67 is not explicitly used here. Its call remains observable and cannot be omitted on the assumption that it has no effects.

This first-descriptor action does not set the secondary-action condition.

### 3. Zero mode: second descriptor

Read the 32-bit field at offset `8` through the retained descriptor base. Construct through F-9b9c1c7483f4 using the **same primary destination and primary scratch addresses used for the first descriptor’s primary construction**.

Call F-8094c3d72052 with the retained lookup context and construction result, then call F-8a5aadac202f with the primary destination before testing the saved lookup result.

If the result is zero:

- Skip the second descriptor’s secondary construction, action, and final descriptor operation.
- Leave the secondary-action condition false.

If the result is nonzero:

1. Reread the offset-`8` field through the retained descriptor base.
2. Construct through F-9b9c1c7483f4 using the secondary destination and secondary scratch.
3. Call F-cf946f91e683 with the retained context and construction result.
4. Call F-8a5aadac202f with the secondary destination.
5. Set the secondary-action condition according to whether the saved secondary result is zero.

This secondary construction reuses the same destination/scratch pair as the first descriptor’s secondary construction, if that earlier construction occurred. If it did not occur, the pair has not previously been supplied to a construction by this function.

When the secondary-action condition is true, perform this ordered sequence:

1. Call F-6a21f4f07f67, without explicitly using its result.
2. Call F-7a7a20db82de and retain its result.
3. Call F-eb24201e389b with the separate wrapper destination and the input object’s interior address at offset `180`.
4. Call F-7d964f24a044 with the wrapper destination to obtain an object address.
5. Read the obtained object’s virtual table and invoke its entry at offset `556`. The explicit arguments are the 24-byte result area, the obtained object address, and the retained result of F-7a7a20db82de.
6. Call F-24edd96d1422 with the wrapper destination.
7. Call F-794d66f15c1d.
8. Call F-1bea98cfcfdf with that result and the 24-byte result area.
9. Call F-4e292a3dd745 with the 24-byte result area.

No null check on the object obtained from F-7d964f24a044 is shown.

After the optional action, every nonzero second primary lookup result causes a final descriptor operation:

1. Reread the offset-`8` field through the retained descriptor base.
2. Construct through F-9b9c1c7483f4 using the **same secondary destination and secondary scratch** just used for the secondary construction.
3. Call F-9b88f53e652a with the retained context and construction result.
4. Call F-8a5aadac202f with the secondary destination.

The final construction therefore reuses that pair regardless of whether the optional wrapper action occurred. It is gated by the second primary lookup result, not by the secondary-action condition.

## Side effects

### Explicit object write

The only explicit modification of the input object is the one-byte zero write at offset `208`. It occurs only after a zero common predicate result, a nonzero flag condition, and a nonnull F-6a21f4f07f67 result.

The write precedes the returned object’s offset-`144` dispatch. No adjacent-byte clear is shown. Dependencies may independently modify the object or other memory.

### Read timing

- The retained descriptor base is captured after initialization.
- The first primary descriptor access rereads the external base; later descriptor accesses use the retained base.
- Descriptor fields are reread for each construction. Earlier field values must not substitute for those later reads.
- The lookup context is captured after the first primary construction. The first primary lookup uses a separate external read; later lookups use the captured value.
- The flag condition is evaluated after the common predicate call.
- Virtual-table addresses and entries are obtained at their respective dispatch sites.

Dependencies are not assumed to preserve globals, object fields, descriptor contents, or dispatch tables.

### Storage identity, lifetime, and ownership

Primary construction storage is reused across the two descriptors. Secondary construction storage is reused across up to three constructions. No explicit scratch initialization or reset separates those uses.

Therefore, a dependency that writes scratch contents or retains supplied addresses can observe these identity relationships. Calling a post-use dependency does not justify modeling the next construction as receiving fresh storage.

The wrapper’s four-byte area is separate from both construction pairs. The 24-byte area is also separate. Neither is explicitly initialized before its first receiving dependency.

No established ownership transfer, allocation, release, reference counting, or permission to retain these addresses follows from the call names or ordering. Whether any dependency actually retains an address, and whether such retention is valid after return, remains unresolved.

No rollback or general abnormal-completion cleanup is shown.

## Acceptance examples

These are conditional static scenarios, not executed tests. Unless specified otherwise, memory is valid and dependencies return normally.

1. **Nonzero mode, zero predicate, zero flag.**  
   Offset-`280` dispatch precedes the predicate. No descriptor processing occurs. F-313c333d6185 is absent. The two-call completion sequence and final forwarding occur, preserving the original nonzero mode.

2. **Any mode, nonzero predicate.**  
   Offset-`184` dispatch receives `16`. This branch performs no flag test or explicit flag clear and skips the two-call predicate-zero completion sequence.

3. **Both primary lookups return zero.**  
   Only the two primary constructions occur. They receive identical destination addresses and identical scratch addresses. No secondary construction or final second-descriptor operation occurs. Late status is still acquired.

4. **Scratch modification during the first primary construction.**  
   If an opaque dependency writes the primary scratch area, the second primary construction receives that same area without an intervening explicit reset by this function. A requirement that the second construction receive independent or zeroed scratch would contradict the observed storage reuse.

5. **All secondary constructions are reached.**  
   The first descriptor’s secondary construction, second descriptor’s secondary construction, and final second-descriptor construction receive one shared destination/scratch pair. That pair is distinct from the primary pair and wrapper area. No explicit scratch reset occurs between uses.

6. **First action enabled, second action disabled, late status zero.**  
   F-8a3da6f5f0f8 receives `1` and `0xFFFFFFFF`. With a later zero predicate and zero flag, that first action alone does not cause F-313c333d6185.

7. **Second primary lookup nonzero, secondary result nonzero.**  
   The wrapper and 24-byte processing sequence is absent. The final second-descriptor construction and F-9b88f53e652a still occur, reusing the secondary pair.

8. **Second secondary result zero.**  
   The wrapper, offset-`556` dispatch, wrapper post-use operation, and 24-byte processing occur in order, followed by the final descriptor operation. A later zero predicate and zero flag cause F-313c333d6185 even if late status is zero.

9. **Zero predicate, nonzero flag, nonnull provider.**  
   The single-byte clear precedes offset-`144` dispatch. F-313c333d6185 is absent from this branch.

10. **Zero predicate, nonzero flag, null provider.**  
    F-a817d8d58c10 is reached before the explicit clear. Under its non-returning annotation, neither the clear nor final forwarding occurs.
