# F-7309ce4ca4c7

## Purpose

F-7309ce4ca4c7 performs a sequence of indirect calls, publishes values into several memory regions, branches on an implicit selector, and may repeatedly process dependency-supplied state. Two visible return paths construct a 64-bit result from separately derived 32-bit halves.

An application-level purpose is **documented_only**. The supplied representation does not establish that this operation initializes an object, parses data, manages resources, or implements another particular domain operation.

This contract distinguishes:

- **Established static evidence:** accesses, calculations, calls, and control-flow relationships visible in the supplied representation.
- **Inferred intent:** possible interpretations that are not behavioral requirements.
- **Unknowns:** matters requiring additional dependency contracts, instruction-level evidence, or runtime observation.

The representation reports invalid instruction data, truncated recovery on one branch, and overlapping global symbols. The behavior below is therefore a conditional static contract, not proof that every represented path is executable.

## Behavior

### Widths and arithmetic

Byte and halfword stores retain the low eight and sixteen bits respectively. Pair-valued results are separated into low and high 32-bit words; combining the return halves does not establish their byte order in memory.

Right shifts of signed values by nine or twenty are represented as arithmetic shifts. The initial loop argument derived from a pair’s low word uses an unsigned right shift by twenty-five.

Signed additions, subtractions, multiplications, and left shifts can exceed a signed 32-bit range. The contract preserves the displayed operand widths and operation ordering without asserting portable signed-language semantics. 3. Invoke U-02.
4. Write U-02’s byte-sized result at the first hidden address plus one.

### Selector other than four

When the hidden selector differs from four, the accesses occur in this order:

1. Read a global-held base value.
2. Read a 32-bit offset from memory at that base plus 100.
3. Read a character from the third argument plus that offset.
4. Convert the character to a 16-bit value.
5. Store the halfword at byte offset 72 from the destination used for the initial three-word publication.

The global-held base read is an additional read after the earlier global capture. It is not interchangeable with that capture, and the offset is obtained by dereferencing the base-plus-100 address, not by adding 100 directly to a previously captured offset.

Recovery terminates after the halfword store because of bad instruction data. This does not establish an intentional halt, exception, or error return. Continuation and output on this branch are **documented_only**.

The character’s signedness is unresolved. For bytes with the top bit set, sign extension and zero extension yield different halfwords.

### Selector-four setup

The subsequent order is:

1. Read the byte at absolute address one and zero-extend it to form an address value.
2. Read a 32-bit context word at the helper result plus 100.
3. Perform a coprocessor transfer involving that context word and incoming coprocessor state.
4. Read a 32-bit word at the context address plus 20.
5. Invoke U-04 with the helper result and the word just read.

After U-04 returns, the routine writes the low byte of the earlier captured global word at the sum of the byte-derived address and the context word.

It then writes four consecutive 32-bit words starting at the byte-derived address:

1. U-04’s result.
2. The byte-derived address itself.
3. The second hidden address.

The byte-derived base is between zero and 255. It must not be interpreted as an ordinary allocated pointer without additional evidence. If the byte store overlaps these word stores, the later word stores determine the subsequent contents according to their order and the environment’s byte order.

### Initial pair-valued decision

Before invoking U-05, the routine saves the result of this comparison: the unsigned interpretation of U-04’s result arithmetically shifted right by nine is greater than `0xFFFFFFBE`.

U-05 receives:

- U-04’s result.
- That result arithmetically shifted right by nine, then increased by 65.
- The fourth argument reduced by 60, then arithmetically shifted right by twenty.

The saved comparison is used after U-05; it is not recomputed from mutable state. Under 32-bit arithmetic-right-shift semantics, it is true exactly for signed U-04 results from −33,280 through −1.

U-05 supplies a low/high pair.

If the saved condition is false, control reaches common processing directly.

If it is true, the routine first stores the context word’s low sixteen bits at the pair’s low word plus 42. It then compares two Boolean values:

- Whether the context word is negative.
- Whether signed subtraction of 47 from the pair’s high word overflows.

Equal Boolean values select common processing directly. Unequal values select loop-specific processing. This is not an ordinary comparison of the high word against 47.

On the initial entry into loop-specific processing:

- The first retained call argument is the unsigned low word shifted right by twenty-five.
- The retained second value is the high word.
- The retained arithmetic state is a hidden operand minus the context word.
- U-06 selects its **initial-entry destination**.

2. Stores the retained arithmetic state as a 32-bit word at the old second value plus 62.

If the test is true, the routine returns using U-07’s low word for the return’s lower-half construction. The offset-62 store precedes that return. No subsequent loop halfword store or common-processing call occurs on this exit.

Otherwise, the following sequence occurs:

1. Store U-07’s low sixteen bits at its high word plus 60.
2. Invoke U-08.
3. Invoke U-09.
4. Store the halfword value 38 at U-09’s result plus two.
5. Multiply the incremented value by `0x10000000`, then arithmetically shift the 32-bit intermediate right by nine.
6. Add the incremented value to that shifted intermediate.

8. Invoke U-10 with U-09’s result shifted left by one, and the incremented value multiplied by 65,536 then reduced by 81.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Additional indirection on the selector-not-four path.**  
   Suppose the branch-specific global read supplies base 4,096, memory at 4,196 contains offset seven, and the third argument is 8,192. The character is read at 8,199. This follows the earlier global capture and precedes the destination-plus-72 halfword store. No normal return is established.

2. **Saved comparison boundaries.**  
   With 32-bit arithmetic right shifts, U-04 results −33,280 and −1 satisfy the saved condition; −33,281 and zero do not. The latter values bypass the context halfword store at offset 42.

3. **Overflow remains a separate condition.**  
   If the context word is nonnegative and U-05’s high word is zero, subtracting 47 does not overflow. The Boolean values match, selecting common processing directly and U-13’s direct-entry destination.

4. **Distinct U-06 routing.**  
   If the initial decision selects loop-specific processing, its first U-06 invocation uses the initial-entry destination. If common processing later observes a nonzero continuation selector, the next U-06 invocation uses the different re-entry destination.

5. **Distinct U-13 routing.**  
   Either initial route directly into common processing selects U-13’s direct-entry destination. Completing loop-specific processing without taking its early return selects U-13’s post-loop destination.

6. **Early return follows a write.**  
   With retained second value 32,758, adding ten gives 32,768. Assuming low-32-bit multiplication, multiplication by 65,536 produces the sign-bit pattern. The offset-62 word store occurs before return; the offset-60 halfword store does not occur.

7. **Late global state controls continuation.**  
   If U-15 changes the continuation selector to zero and returns normally, the subsequent read selects return, regardless of an earlier nonzero value.

8. **Return-time upper half.**  
   If the return global contains 100 when read, the upper half is 16. The earlier captured global is not substituted.
