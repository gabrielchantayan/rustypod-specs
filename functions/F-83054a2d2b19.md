# F-83054a2d2b19

## Purpose

F-83054a2d2b19 coordinates a state-dependent action on a mutable receiver. It first issues a notification, then either handles a pending action immediately or acquires temporary state and selects a shuffle transition, a chapter-art transition, or a fallback action.

The established contract concerns direct memory accesses, dependency arguments, call order, branch selection, and normal-return finalization. The transition names suggest layout navigation; actual navigation behavior is not established without the dependency implementations.

Every visible normal return produces the 32-bit value **1**. This result does not identify the selected path, report resource availability, or establish that a requested transition succeeded.

## Behavior

### Initial notification and pending shortcut

The first observable dependency call is F-936a8728139d, receiving the value freshly read from receiver offset `0xB8`.

Only after that call returns does the function read the pending slot and test its 8-bit character conversion. The test therefore observes post-notification receiver state. Entry-state pending information alone does not determine the branch if the notification changes the receiver.

When the converted value is nonzero:

- One byte at receiver offset `0xBC` is written to zero.
- The receiver callback at dispatch-table offset `0x138` is invoked.
- The function returns 1.

The byte clear precedes callback dispatch. The callback may subsequently modify that byte or other state. No temporary-state preparation or finalization occurs on this path.

When the converted value is zero, execution continues with state acquisition.

- Its 32-bit returned value is passed to F-97dbacdc5cbc together with the receiver.

After the wrapper-finalization call returns, resource resolution proceeds in this exact order:

2. Call F-938c950e5046.
3. After that call returns, read the current 32-bit value of G2.

## Side effects

- A one-byte zero store at `0xBC` on the pending shortcut.
- A 32-bit store at `0xD8` after nonzero shuffle resource lookup and subsequent processing.

The only explicit global reads identified here are G1 followed later by G2 during shuffle resource resolution. There is no direct write to either global in this function.

This does not establish global or receiver preservation across dependencies. Any reached dependency or virtual method may modify accessible state unless its separate contract says otherwise. In particular:

- The pending callback may undo the preceding clear.
- A path without a direct `0xD8` store need not preserve that field.
- The secondary notification uses a new `0xB8` read.

No explicit allocation or release of the resource result or dispatch objects is visible. Their ownership and required lifetime are documented_only.

### Errors and partial effects

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Each assumes valid reached accesses and normal return from every reached call.

1. **Pending action after notification.** If the converted pending value is nonzero after F-936a8728139d, the byte clear precedes the receiver callback. No state preparation or finalization occurs; the return is 1.

2. **Notification changes branch selection.** If the entry pending value is nonzero but the initial notification makes the tested value zero, the function proceeds to state acquisition rather than taking the shortcut.

3. **Primary short-circuit.** If F-d1b4663968a8 returns nonzero, the remaining primary predicates, F-af667771d6ce, and F-5867216c913f are skipped. Secondary processing begins with a fresh `0xB8` read.

4. **Shuffle selection.** If all four primary predicates and F-5867216c913f return zero, the shuffle request occurs. No secondary notification or secondary predicates run.

5. **Global changes between reads.** Suppose G1 contains 7 and G2 contains 9 after wrapper finalization. If F-938c950e5046 changes G1 to 11 and G2 to 13, F-9e50c66a96dd receives 13 as its second argument, while F-682adfd5a561 receives captured K1 equal to 7 as its second argument.

6. **Global change during resource resolution.** If F-9e50c66a96dd changes G1 after K1 was captured, F-682adfd5a561 still receives the captured value. No fresh G1 read occurs.

7. **Zero resource result.** If F-682adfd5a561 returns zero, mode dispatch and the direct `0xD8` store are skipped. The shuffle request remains earlier in the trace, and common finalization follows without secondary processing.

8. **Mode boundaries.** With a nonzero resource result, dispatch results 1 and 2 produce modes 1 and 2 respectively. Any other 32-bit result, including zero or a negative signed interpretation, produces mode 0.

9. **Zero stored result.** If F-eadf6abacb1d returns zero, zero is written to `0xD8`; the function still finalizes state and returns 1.

10. **Chapter-art selection.** Three nonzero secondary predicate results cause the chapter-art request. No fallback sequence or direct global resource reads occur.

11. **Fallback short-circuit and probe.** A zero secondary predicate skips later secondary predicates. A zero fallback probe then invokes the receiver callback after one F-ac356e5603c7 call; a nonzero probe instead causes the second call, F-23de0cf8cdd0, and F-23da0e04cbd8.
