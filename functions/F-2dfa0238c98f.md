# F-2dfa0238c98f

## Purpose

F-2dfa0238c98f performs conditional setup, applies two eligibility gates, optionally prepares a shared object and its linked members, and selects between returning, submitting a request, or attempting activation.

The established behavior is a sequence of calls, memory accesses, and conditional branches. Terms such as “guard,” “registration,” “initialization,” “submission,” “activation,” and “attachment” describe apparent roles, not verified dependency semantics.

Earlier operations are not transactional. A later return does not cause this routine to roll back its own writes or calls. This absence of local rollback does **not** guarantee preservation: intervening dependencies may overwrite fields, change globals, or otherwise alter earlier effects.

## Behavior

### 1. Initial guarded calls

The routine loads the initial guard-bearing object from global storage and tests bit 0 of its 32-bit word at `0x20`.

A set bit skips this guarded sequence. For a clear bit, a separately stored global guard operand is loaded and passed to F-b255b26284e6. A zero result also skips the sequence.

A nonzero result leads to these calls, in order:

1. F-1058afc38c04 receives the currently loaded global context, `12`, `0`, and a globally loaded registration operand.
2. F-804adc29bbfb receives that result and two registration operands loaded for this call.
3. F-d08d3ca17b81 receives a fresh load from the global guard-operand storage.

The final guard operand is not retained from the predicate call. Intervening dependencies may change that global storage, so the two calls need not receive equal operands.

Registration operands are likewise global loads, not established constants. The representation establishes ordering between calls, but not the relative evaluation order of multiple global arguments within one call. No direct write by this routine sets the initial guard bit.

### 2. Eligibility gates and retained state address

F-aa672b15efb7 receives a newly loaded global context, the second explicit input, and `0`. The context is not a retained copy from the earlier producer call.

A zero result ends the routine. Earlier calls may already have occurred; there is no local rollback and no guarantee that their effects survived subsequent dependencies.

For a nonzero result:

1. F-6ac70711bbb5 is called with `1`.
2. The state-object address is captured from global storage.
3. The returned eligibility record’s byte at `0x69` is read.

A zero byte ends the routine. Any nonzero byte permits continuation.

The state address is captured after F-6ac70711bbb5 returns but before the eligibility-byte test. Later accesses described as using the **retained state address** use this captured value, even if global state-pointer storage changes.

### 3. Secondary guarded calls

The routine loads the current global state address and tests bit 0 of its 32-bit word at `0x14`.

If clear, it loads the global state address again and passes the address of its `0x14` field to F-b255b26284e6. Thus, the word test and predicate argument are not established as referring to the same object.

For a nonzero predicate result:

1. F-f99b15cea102 receives a main-object address loaded from global storage at that call site.
2. F-804adc29bbfb receives the producer result and two globally loaded registration operands.
3. F-d08d3ca17b81 receives the address at `0x14` relative to the **retained state address**.

The finalization address can therefore differ from the predicate’s address. Matching guard identities, pointer stability, and lock-release semantics are not established.

### 4. Optional initialization

F-bb58811af262 is called after the secondary guard stage regardless of whether its guarded calls ran. Its result is retained for a possible later external call.

The main-object address is then captured from global storage. This is the **initialization object**. The routine reads byte `0x02` through the retained state address.

A nonzero byte skips initialization. A zero byte selects this order:

1. Call F-a6b82b58e9b2 without explicit arguments.
2. Call F-a9f18648147b with its result, `0`, and the initialization object.
3. Load the global initialization value and write all 32 bits to the initialization object at `0x1c`.
4. Call F-2b20f2572237 with the initialization object and `1`.
5. Traverse from the initialization object, writing byte `0` at `0x3c` of each visited member.
6. Write byte `1` at `0x02` through the retained state address.

The initialization value is loaded after F-a9f18648147b returns. A dependency’s change to that global value can therefore affect the subsequent write. Conversely, F-2b20f2572237 can alter storage after the `0x1c` write; that write is an established operation, not a promise about the field’s later value.

Each traversal iteration writes the current member’s byte before reading its 32-bit link at `0x40`. A newly read zero link or a link equal to the traversal’s starting address ends the traversal. Otherwise, the newly read address becomes the next member.

The state-byte write occurs only after traversal completion. Failure or nontermination before that point prevents this routine from reaching the marking operation. No rollback is performed.

### 5. Two independent status observations

After optional initialization, the routine makes two status observations:

1. Load the global status pointer, read the addressed 32-bit word, and retain bit 0.
2. Load the global status pointer again, read the addressed 32-bit word, and test bit 1.

The two observations do not share a retained status address. Their addresses, word values, or both may differ if those changes are observed. This establishes neither a concurrency model nor guarantees about atomicity, volatility, or visibility.

Only retained bit 0 from the first observation and bit 1 from the second determine this branch selection. Higher bits do not affect it.

| First observation: bit 0 | Second observation: bit 1 | Selection |
|---|---|---|
| Clear | Clear | Return |
| Set | Clear | Request submission |
| Clear | Set | Activation attempt; write `0` at `0x3e` |
| Set | Set | Activation attempt; write `2` at `0x3e` |

### 6. Request submission

When submission is selected:

1. F-d33f6d597e5d receives `24`.
2. An unmapped external initializer receives the returned address and `24`.
3. The routine writes the 32-bit value `500` at request offset `0x10`.
4. It writes the 32-bit value `2` at request offset `0x14`.
5. An indirect target loaded from global target storage receives `2`, the request address, `5`, and `0`.
6. The routine returns.

The initializer’s behavior is unknown; zero-filling other request bytes is not established. There is no local result validation, release, or ownership-transfer confirmation. The submission target may change request contents or lifetime during its call.

### 7. Activation attempt and object reloads

When activation is selected, the routine first writes the complete byte at `0x3e` of the initialization object: `0` or `2`, according to retained status bit 0.

It then performs two distinct global main-object address reads:

1. One address is retained as the **activation object** for callbacks, field tests, and final traversal.
2. Another supplies the object whose 32-bit field at `0x48` is read and retained as the **attachment value**.

Neither address is established as equal to the initialization object or to the other address.

An unmapped external dependency receives the retained result of F-bb58811af262. Another unmapped external dependency is then called without explicit arguments to obtain an activation result.

If the activation result is zero, this routine returns without executing the subsequent callbacks, attachment sequence, or final traversal. The earlier `0x3e` assignment and any initialization operations **already occurred**, and this routine performs no local rollback. Either intervening external dependency may nevertheless have overwritten that byte or modified initialization effects. Their preservation is not guaranteed.

For a nonzero activation result:

1. F-e7094617a462 receives the activation result and activation object.
2. F-c1c76d9cc652 receives the activation result.
3. The activation object’s current byte at `0x3e` is read.
4. If bit 1 of that byte is set, F-e282dcfd746e receives `500` and `2`.
5. A nonzero retained attachment value selects the attachment sequence.
6. A final traversal writes byte `1` at `0x3d` of visited members, starting from the activation object.
7. The routine returns.

The fresh `0x3e` test is independent of the earlier status selection: it can concern a different object, and dependencies can change the byte before it is tested.

### 8. Optional attachment and final traversal

For a nonzero retained attachment value:

1. F-66c822b72d41 receives the activation result and retained attachment value.
2. The activation object’s 32-bit field at `0x44` is read and retained.
3. The external target previously called with the retained F-bb58811af262 result is called without explicit arguments.
4. Another unmapped external dependency receives that call’s result, `1`, the retained attachment value, and the retained `0x44` value.

The attachment argument is not reloaded from `0x48`. The `0x44` value is read after F-66c822b72d41 returns and before the no-explicit-argument external call.

The final traversal uses the same write-before-link-read rule and zero-or-start termination condition as initialization. Its starting address is the activation object; its write is byte `1` at `0x3d`.

## Acceptance examples

These are conditional static expectations, not executed tests. Calls return normally and required storage remains accessible unless otherwise stated.

1. **First gate rejects.** If F-aa672b15efb7 returns zero, no eligibility-record lookup or later stage occurs. Initial guarded calls may already have executed. This return performs no local rollback and makes no preservation claim about their effects.

2. **Eligibility byte rejects.** If the first gate succeeds but byte `0x69` is zero, the state address has already been captured. The secondary guard stage and subsequent stages are not reached.

3. **Guard operand changes.** If the initial predicate succeeds and an intervening dependency replaces the global guard operand, F-d08d3ca17b81 receives the replacement value loaded at its call site.

4. **Producer changes registration data.** If a producer changes global registration operands, the following F-804adc29bbfb call uses its call-site loads rather than an assumed earlier snapshot.

5. **Initialization value changes.** If F-a9f18648147b changes the global initialization value, the subsequent `0x1c` write uses that post-call value. A later dependency may change the destination again.

6. **Already initialized, no action.** With nonzero retained state byte `0x02` and both selected status bits clear, F-bb58811af262 still runs. Initialization, submission, and activation are skipped.

7. **Initialization precedes no-action return.** For a stable two-member null-terminated initialization chain, the routine writes `0` to both `0x3c` bytes before writing `1` to the state byte. A later no-action return adds no rollback operation.

8. **Different status addresses.** If the first status load observes bit 0 set at one address and the second observes bit 1 clear at another, submission is selected. This is conditional on the stated observations, not a visibility guarantee.

9. **Request writes.** Submission requests 24 bytes, invokes the initializer, writes `500` and `2` into the final eight bytes, then calls the target with `2`, request address, `5`, `0`. Other bytes and post-call contents are unspecified.

10. **Activation unavailable.** If the activation-result producer returns zero, the earlier `0x3e` assignment and any initialization operations have occurred, but either external call preceding the test may have modified their effects. This routine returns without local rollback, subsequent activation callbacks, attachment, or final traversal.

11. **Independent activation addresses.** If the activation-object capture reads one address and the following global read supplies another, callbacks and final traversal use the first; the attachment value comes from the second.

12. **Fresh versus retained fields.** If a callback clears bit 1 of the activation object’s `0x3e` byte before its test, F-e282dcfd746e is skipped despite an earlier assignment of `2`. A later change to `0x48` does not replace the retained attachment argument. The `0x44` argument is read after F-66c822b72d41.

13. **Traversal boundaries.** With stable links, a self-link causes one traversal write. A finite ring returning to its start visits each member once. A reachable cycle excluding the start has no represented termination condition while those links remain unchanged.
