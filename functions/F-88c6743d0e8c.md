## Behavior

### Entry and saved-word writeback

The first operation is an indirect call receiving the first declared argument. Its target is derived from inherited control-transfer state.

Two subsequent producer results are each forwarded to another call. Further calls occur before the first explicit memory effect: a four-byte store of the inherited value at the inherited address plus 20. The next call receives four times a result produced before that store.

After additional calls, another producer result determines two distinct addresses:

- Four times the result is stored at sixteen times the result plus 20.
- An unsigned 32-bit word is then read from four times the result plus 20.

The first store precedes the load. The two addresses are not necessarily equal.

Immediately after the load, a dependency receives the same four-times-result value in both argument positions. Further calls follow, including two producer-to-consumer forwarding pairs and additional calls culminating in another result. Only then is the saved loaded word logically shifted right by eight and written back to its original load address.

Thus the repeated two-argument value belongs to the result that determined the load address, not the later result. The writeback uses the saved load, even if intervening dependencies change that memory.

The next call receives four times the latest producer result.

### Word writes and the first context-dependent forwarding sequence

Following further calls, a new result produces a four-byte store of four times that result at sixteen times that result plus 20.

The next dependency receives the inherited context logically shifted right by 16 as its sole explicit argument. Three intervening calls and a further result-producing call precede a second store associated with the same saved result: four times that saved result is written at four times that saved result plus 20.

A call then receives four times the most recently produced result. After more calls, another result establishes a new destination at sixteen times that result plus 20, where four times the result is stored.

The following ordered call relationships occur before that destination is written again:

1. A dependency receives the sixteen-times-result address contribution.
2. A producer result is forwarded to another dependency.
3. A further producer result is forwarded as the first argument of a two-argument call whose second argument is the context shifted right by 16.
4. Additional calls produce another result.

The earlier destination is then written again with the same saved four-times-result value. The repeated store is explicit; intervening calls make it observably distinct from the first store.

### Context-selected destination transition

The next call receives four times the latest result. Further calls produce a new result, whose four-times value is saved and stored at sixteen times that result plus 20.

The routine also forms a context-derived address contribution: eight times the context logically shifted right by eight. This is multiplication after shifting, not an eight-bit extraction. Its range is 0–134,217,720.

The subsequent sequence is significant:

- A two-argument dependency receives the saved four-times-result value first and the context-derived address contribution second.
- A producer result is forwarded to another dependency.
- Another producer result is forwarded to a two-argument dependency whose second argument is the context shifted right by 16.
- Additional calls produce a new result.
- The saved four-times-result value is stored at the context-derived address contribution plus 20.

This is the first write to that context-selected destination.

A dependency then receives four times the most recent result. Three intervening calls and another result-producing call lead to a different word write: four times this newly produced result is stored at sixteen times that result plus 20.

Next, a four-argument dependency receives, in order:

1. The context-derived address contribution.
2. The same context-derived address contribution.
3. The context shifted right by 16.
4. The original third declared argument shifted right by 21.

Three intervening calls and another result-producing call follow. The context-selected destination is then written a second time, now with the context-derived address contribution itself.

The two writes therefore have the same destination but different represented value sources:

- First: the saved four-times-dependency-result value.
- Second: the context-derived address contribution.

Between them are observable calls, the separate word write at a producer-derived destination, and the four-argument call. They must not be collapsed into one initialization. Their numeric values may happen to coincide, but equality is not required.

The two forwarding calls using the context shifted right by 16 are also distinct: one precedes the repeated producer-derived store in the preceding stage; the other precedes the first context-selected store.

### Secondary-result scaling and later word writes

After the second context-selected store, a dependency receives four times the latest ordinary result. Further calls expose a secondary result.

That secondary result supplies:

- A stored value equal to itself multiplied by 16,777,216.
- A destination equal to itself multiplied by 67,108,864, plus 20.

The scaled value is then passed to a dependency. After further calls produce an ordinary result, the saved scaled value is stored again, this time at four times that ordinary result plus 20. The next call receives that four-times-result address contribution.

Both large multiplications can exceed 32 bits. Under wrapping, only the secondary result’s low eight bits influence the stored scaled value, and only its low six bits influence the scaled destination before adding 20.

2. Calls include passing that retained value, followed by two producer-to-consumer forwarding pairs and additional calls. A newly produced result selects a destination at four times itself plus 20, where the retained value is stored.

### First byte selector and derived byte stores

The retained four-times value from the third step above is treated as unsigned, masked to clear its top bit, and logically shifted right by seven. The resulting selector index is in 0–16,777,215.

A selector access reads one unsigned byte at that index plus one. The loaded byte, plus 17, is the destination address for a subsequent one-byte store. Consequently, selected destinations are in 17–272 inclusive. No wider pointer load is represented.

After further calls, an unsigned result supplies two byte values:

- The first selected store receives the low byte of four times the result.
- A dependency then receives that four-times value in all three argument positions.
- Additional calls include a producer-to-consumer forwarding pair and further calls.
- A fresh selector read determines the destination for a second store.

The second stored byte comes from masking the original unsigned result with 1,073,741,823, logically shifting right by 20, and retaining the low byte. It therefore selects original bits 20–27. Bits 28–29 are discarded by byte truncation; bits 30–31 are removed by the mask.

Selector values are not cached across these stores.

### Direct byte store, clearing, and second selector

Further calls produce another unsigned result. Four times this result supplies a direct byte store at the context shifted right by 31, plus 28. The destination is address 28 or 29; the stored byte is a multiple of four.

Immediately afterward, with no intervening dependency call, the first selector is read again and its selected destination is cleared to zero. The direct store can therefore affect the following selector read if the addresses alias.

Subsequent dependency arguments include:

- The context shifted right by 31.
- The latest unsigned result masked with 1,073,741,823 and logically shifted right by six.

After additional calls, another fresh read of the first selector determines a destination that is cleared again.

The four-times value used for the direct byte store is also retained for a second selector address: 1,024 times that value, plus one. A byte read there selects another destination by adding 17.

Under 32-bit wrapping, the second selector address is the underlying unsigned result multiplied by 4,096, plus one. Arithmetic validity without that assumption remains `documented_only`.

### Terminal loop

A later unsigned result is masked with 1,073,741,823 and shifted right by 25, yielding 0–31. The second selector is read and its selected destination cleared.

A preparatory dependency receives twice the extracted value, in 0–62. Another dependency supplies the initial carried word.

Each loop iteration then:

- Calls a dependency with the carried word and the current unsigned loop state shifted right by eight.
- Performs further calls, ending with a result-producing call.
- Re-reads the second selector and clears its selected destination.
- Passes four times the recent result to another dependency.
- Performs further calls, ending with a result that supplies the next carried word and loop state.

The initial loop state is the extraction in 0–31, so the first leading call’s second argument is zero.

At later iteration boundaries, the next carried word is represented as the final result shifted left by two; the next loop state is that result shifted left by 26. Under 32-bit wrapping, the next leading call’s second argument is the final result’s low six bits multiplied by 262,144.

The represented leading-call target construction differs between initial entry and subsequent iterations; identical callee identity is not established.

There is no represented exit condition. The second selector address remains derived from the retained pre-loop value, but its byte is re-read on every clearing operation.
