# F-1e325be23969

## Purpose

F-1e325be23969 performs an ordered membership check against an object obtained from F-9bcc5688e733. It compares the supplied integer with the first integer exposed by each indexed-access result. If a match is encountered, it returns without invoking the terminal operation. If the captured search bound is exhausted without a match, it invokes a separate operation on the same object, passing the address of a temporary copy of the supplied integer.

This establishes a **search-then-conditionally-invoke** contract. The terminal operation may be intended to insert an absent value, but insertion, uniqueness enforcement, and collection ownership are not established by the supplied evidence.

The function has no explicit result value. Observable outcomes consist of dependency calls, memory reads, any effects of those dependencies, and whether the terminal operation is invoked.

## Behavior

### Entry and object acquisition

The supplied integer is first copied into temporary storage belonging to this invocation. F-9bcc5688e733 is then called without explicit arguments.

After that dependency returns, the function retains its returned object address and reads the object’s second integer-sized slot once. That read establishes the bound for the entire search. The index starts at zero.

The function does not obtain a replacement object from F-9bcc5688e733 later in the invocation.

### Bound interpretation

Before any indexed-access call, and again after each unsuccessful comparison, the function compares the index against the captured bound using signed ordering.

If the bound is zero or negative, the search contains no indexed-access calls. The terminal operation is selected immediately after the initial bound check.

If the bound is positive, the function requests indices in ascending order beginning at zero. It never intentionally requests an index equal to the captured bound.

Under the signed 32-bit model, the loop increment does not require signed overflow. Even for a bound of 2,147,483,647, the greatest requested index is 2,147,483,646. After an unsuccessful comparison at that index, the index becomes 2,147,483,647 and the next bound check ends the search.

### Indexed comparison

For each index within the captured bound, the function:

- Reads the dispatch-table address from the retained object.
- Resolves the operation at dispatch-table byte offset `+0x40`.
- Calls that operation with the retained object and current index.
- Reads the first integer at the returned address.
- Compares that integer with the temporary copy of the supplied value.

A match causes an immediate return. No later index is requested, and the terminal operation is not invoked.

An unequal value advances the index by one and leads to the next bound check.

The indexed-access result is not retained across iterations. This function does not explicitly write through it or release it.

### Exhaustion and terminal invocation

If the captured bound is reached without a match, the function reads the retained object’s current dispatch-table address and resolves the operation at byte offset `+0x1c`.

It invokes that operation with:

1. The retained object as the receiver.
2. The address of the temporary integer copy as the second argument.

If that operation returns normally, F-1e325be23969 returns immediately afterward. It does not inspect a return value or recheck the object.

The terminal operation is called at most once per invocation. It is not called after a matching comparison.

### Mutation-sensitive behavior

The search bound is a snapshot, but dispatch resolution is not:

- Changes to the bound field after its initial read do not change the remaining index range.
- The dispatch-table address is read again for every indirect call.
- The comparison integer is read after the indexed-access dependency returns.
- The terminal dispatch is resolved after the search has ended, rather than cached before the search.

Consequently, a dependency that changes the object’s dispatch table can affect a later call target. A dependency that changes the collection or its storage can affect later comparison values or invalidate later accesses.

The function contains no retry, restart, synchronization, or consistency check. Concurrent mutation is not established as safe.
