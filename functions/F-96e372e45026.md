# F-96e372e45026

## Purpose

F-96e372e45026 creates an object through one of two construction paths, optionally applies two four-byte attributes obtained through a lookup service, and transfers selected configuration state into the object’s flags.

The function also modifies its caller-supplied configuration record. In particular, it derives two high-order configuration flags from two mode fields and collapses the simultaneous presence of those flags into a separate combined flag.

**Established behavior:** construction-path selection, dependency calls, byte extraction, flag operations, configuration mutation, and return of the constructed-object pointer are visible in the supplied static evidence.

**Inferred intent:** the four-byte attributes appear to represent opaque RGB colors. The two mode fields and their associated flags appear to describe two related settings, but their domain meaning is not established.

### 2. Obtain an optional lookup context

After construction, F-283eda65a14c is called with `0x80`.

If it returns null, the lookup-context value is zero.

If it returns nonnull, the function resolves a virtual operation through the returned object’s first word, using table byte offset `0x14`. That operation receives the service-object pointer and the integer `5`; its return value becomes the lookup context.

No null validation is performed on the table pointer or operation pointer. A zero lookup context does not suppress either later lookup.

After this stage, one 32-bit global lookup-key value is saved for the second optional lookup. The first lookup instead uses the global key as referenced at its own call site.

The contents and meaning of this global are not provided. The saved value must not be replaced conceptually with a later reload: intervening dependencies may change global state.

### 3. Apply the first optional attribute

The configuration word at `0x5C` is read after construction and context acquisition. If it is zero, this entire attribute stage is skipped.

Otherwise, F-5710a8628cba is called with the lookup context and the global lookup key. A null result skips the remainder of this stage without reporting an error.

For a nonnull result, a temporary four-byte attribute is assembled:

- Byte 0 receives bits 16–23 of a 32-bit word read through the returned address.
- Byte 1 receives bits 8–15 of a word read through that address.
- Byte 2 receives bits 0–7 of a word read through that address.
- Byte 3 is set to `0xFF`.

The three component expressions are separate accesses in the supplied representation, ordered from byte 0 through byte 2. A single stable packed value is a sufficient condition for treating them as components of one word; stability is not independently guaranteed.

The temporary attribute is then passed to F-ef50e5510dd5 with a first global comparison reference:

- A nonzero result selects flag mask `0x00010000`.
- A zero result causes a second call to F-ef50e5510dd5 with a second global comparison reference.
- A nonzero result from that second call selects `0x00008000`.
- A zero result from both calls selects `0x00038000`.

The selected mask is ORed into the object’s 32-bit flags at `0x48`. Existing flags are not cleared.

The four temporary bytes are then copied individually into object offsets `0x90`, `0x91`, `0x92`, and `0x93`, in that order. These writes occur after the flag update.

The comparison dependency receives the temporary’s address. Its preservation of those bytes is unknown. Consequently, the bytes finally stored are the temporary’s contents after the comparison calls, not unconditionally the initially extracted components and `0xFF`.

### 4. Apply the second optional attribute

The configuration word at `0x60` is read after the first optional stage finishes.

If nonzero, F-5710a8628cba is called with the lookup context and the previously saved lookup key. This is a separate lookup; the first lookup result is not reused.

A null result skips the remaining work in this stage.

For a nonnull result, a four-byte temporary is formed by the same ordered component extraction and `0xFF` assignment described above. The function then resolves the constructed object’s virtual operation at table byte offset `0x114` and invokes it with:

- The constructed-object pointer.
- The temporary attribute’s address.

This stage does not directly copy the attribute to object offsets `0x90`–`0x93`, nor does it directly select the first stage’s comparison masks. Any additional effects belong to the virtual operation and are unknown.

### 5. Normalize configuration flags

After both optional stages, the function processes configuration state in this order:

1. Read the 32-bit field at `0x78`. If it equals `3`, read the current flags at `0x88`, OR in `0x40000000`, and write the result back.
2. Read the 32-bit field at `0x7C`. If it equals `3`, read the current flags at `0x88`, OR in `0x80000000`, and write the result back.
3. Read the flags at `0x88` to determine whether both `0x40000000` and `0x80000000` are set.
4. If both are set, update the configuration flags by retaining bits 0–29, clearing bits 30–31, and setting `0x02000000`.

Thus, the combined case produces `0x02000000` in place of the two high flags. Other lower bits survive, including an already-set combined flag.

The combination check applies to the current flags regardless of how the high bits became set. It is not conditional on both mode fields equaling `3`.

No step clears either individual high flag merely because its corresponding mode field is not `3`.

### 6. Propagate selected flags to the object

The function then makes three separate checks of the current configuration flags at `0x88`, in this order:

1. If `0x02000000` is set, OR `0x02000000` into object flags at `0x48`.
2. If `0x40000000` is set, OR `0x40000000` into object flags at `0x48`.
3. If `0x80000000` is set, OR `0x80000000` into object flags at `0x48`.

These are selective transfers, not a copy of the full configuration flags word. No corresponding object flag is cleared when a configuration bit is absent.

Finally, the byte at configuration offset `0x64` is read. Only the exact value `0x01` causes object flag `0x08000000` to be ORed in. Other nonzero byte values do not satisfy this condition.

The constructed-object pointer is then returned.

## Acceptance examples

These are conditional static acceptance cases, not runtime observations. Unless stated otherwise, assume valid objects, ordinary non-overlapping storage, stable packed lookup data, and dependencies that do not mutate unrelated state.

1. **Zero construction selector.** With configuration `0x6C` equal to zero, the preparation dependency is F-030ef64e3402, the size argument is `0x164`, and construction uses F-8bddbcf282bd. The other construction path is not taken.

2. **Nonzero construction selector.** A selector of `1` or `0xFFFFFFFF` selects F-232a16c1b8bd, size `0x1AC`, and F-db91b59cae65. Selection does not require a particular positive value.

3. **Missing service object.** If F-283eda65a14c returns null and the first enable field is nonzero, the first lookup still occurs, with context zero.

4. **Failed first lookup.** If the first lookup returns null, no comparison call, first-stage flag update, or direct four-byte attribute write occurs. Later stages still execute.

5. **Component extraction.** For a stable lookup word `0xAB123456`, the initial temporary bytes are `0x12`, `0x34`, `0x56`, and `0xFF`. The top byte `0xAB` is discarded.

6. **Comparison precedence.** If the first comparison returns nonzero, `0x00010000` is ORed into the object flags and the second comparison is not called. If only the second returns nonzero, the selected mask is `0x00008000`. If both return zero, it is `0x00038000`.

7. **Combined configuration state.** Starting with flags `0x00000004` and both mode fields equal to `3`, normalization produces configuration flags `0x02000004`. The combined bit is propagated to the object; the two high bits are not propagated from this normalized configuration.

8. **Preexisting high flags.** Starting with configuration flags `0xC0000004`, normalization produces `0x02000004` even if neither mode field equals `3`.

9. **Object flags are cumulative.** If the object already has `0x40000000` and normalization produces only configuration bit `0x02000000`, propagation adds the combined bit without removing the existing object high bit.

10. **Exact byte condition.** Configuration byte `0x01` adds object flag `0x08000000`; byte `0x02` does not.
