# F-8314c7f570cd

## Purpose

F-8314c7f570cd performs address-derived memory writes, conditionally invokes a dependency, and enters an unbounded call-and-update process. No ordinary return is represented.

An application-level purpose is not established. Some destinations have interrupt- or reset-associated labels, but those labels do not establish device behavior. The represented operations include low-address accesses, overlapping stores, dependencies on incoming machine state, and arithmetic whose execution semantics are unresolved.

This contract describes the supplied static representation. It does not establish that the apparent function boundary is valid, that every represented access is executable, or that any complete path runs without interruption.

## Behavior

### Entry effects

The first two effects are 16-bit stores of the incoming machine-state value. Their destinations are the third argument multiplied by 32 and that destination plus 14 bytes.

The next effect is a 16-bit store of 16. Its destination is formed by clearing the fourth argument’s highest bit and shifting the remaining value right by one.

The storage address of the fifth argument then determines:

- An initial read pointer, formed by shifting that storage address left by four.
- A low-eight-bit value assigned to the global location represented as 0x0000000B, obtained from the storage address shifted right by twelve.
- A destination for a 16-bit store of 0xED38, at that right-shifted address plus six.

The declaration of the symbol at 0x0000000B is not supplied; the assigned value is explicitly narrowed to eight bits.

The routine next reads the fixed-location value represented as 0x0897EDE0 into a signed 32-bit working snapshot. It subsequently assigns the address 0x97ED3800 to the global at that location. These effects precede the optional dependency call.

Changing the fifth argument’s storage address can therefore alter observable behavior even if all five incoming argument values remain unchanged.

### Conditional setup

The conditional path is taken exactly when the fourth argument’s low fifteen bits are nonzero.

If those bits are zero, setup retains:

| State | Selected value |

| Address factor | Zero |
| Shifted address factor | Fourth argument shifted left by fourteen |

If those bits are nonzero, the following effects occur in order:

1. Assign 16 to the global represented as 0x225FB880.
2. Assign 24 to an interrupt-associated global whose numeric address and declaration are not supplied.
3. Read the global represented as 0x0897EDE0 again, and use its current value as the byte offset from 0x97ED3800 for an explicit eight-bit store of 0xCE.
4. Read the global represented as 0x0CE00026 and convert its value to the unsigned 32-bit working word.
5. Assign zero to the global represented as 0x0CE00000.
6. Invoke F-000000000001.

The second read of 0x0897EDE0 is distinct from the earlier snapshot. Intervening writes may matter if storage overlaps or has device semantics.

The access width and signedness of the read at 0x0CE00026 are **documented_only**. Its conversion to the working word may consequently depend on unavailable type information; it is not an established halfword load.

### Common setup

Both paths perform these ordered writes:

1. Store the shifted address factor’s low sixteen bits at that factor plus 48.
2. Store the address factor multiplied by 0x02000000 as a 32-bit value at that product plus 64.
3. Store an eight-bit zero at the selected control-block base.
4. Store the working word as 32 bits at the same base.
5. Store 64 at base offset 40.
6. Store the base address at base offset 44.

The byte and word stores at the base are separate ordered effects. The wider store does not erase the earlier effect from the behavioral contract.

The working word is then masked by the selected address value to initialize an accumulator. A separate arithmetic word becomes eight times the selected address value minus two.

Next, the routine reads the fifth argument variable’s **then-current stored pointer value**. It adds that value, the current read pointer, and eight, then stores the resulting 32-bit value at twice its numeric value.

### Outer output entry

Each arrival at the outer output entry performs:

1. An eight-bit zero store through the first output pointer.
2. A 16-bit store of the arithmetic word’s low sixteen bits at the same address.
3. A 32-bit store of the outer-entry word at that address.
4. Addition of the transfer word to the accumulator.
5. A 32-bit store of the updated accumulator through the second output pointer.

On the initial arrival, both output pointers are equal, so the final store overlaps all three preceding stores.

A later explicit re-entry sets the first output pointer to zero. This is not a termination condition: it requests the same three ordered stores at address zero.

### Call-and-update processing

After the outer output entry, the call-processing loop initializes the argument for F-000000000002 to zero.

Each processing cycle captures the current transfer word’s low byte before invoking F-000000000002. The dependency target depends on retained target-selection state; the initial target differs from targets used after subsequent paths.

The apparent result supplies:

- A low 32-bit component used as the destination of a 16-bit store containing that component’s low sixteen bits.
- A high 32-bit component used as the base of an indirect 32-bit pointer read at offset 80.

Between those operations, the routine:

- Stores the arithmetic word multiplied by 64 as a 32-bit value at that product’s own address.
- Reads a 32-bit word through the current read pointer, replacing the transfer word.
- Stores a 16-bit value at arithmetic-word offset four. The value is the previous read pointer narrowed to sixteen bits, plus four, with the final store narrowed to sixteen bits.
- Replaces the read pointer using the dependency-result high component plus 80.

The routine then calls F-000000000003 and F-000000000004 with no explicit arguments, F-000000000005 with the word read through the previous read pointer, and F-000000000006 with that word unsigned-shifted right by three.

For F-000000000006’s apparent result:

- The high component becomes the candidate output pointer.
- The low component is multiplied by 32 to produce a 32-bit scaled word.
- The scaled word is stored at its own numeric address.
- An unsigned comparison checks whether it is below 20.

If the comparison succeeds, control leaves the current inner processing loop and reaches the enclosing infinite loop. That loop resets the next F-000000000002 argument to **zero**. This path does not revisit the outer output writes and does not preserve a nonzero call argument assigned earlier in the cycle.

### Extended updates

If the scaled word is at least 20, processing continues:

- Store the arithmetic word at scaled-word offset 88.
- Store the read pointer’s low sixteen bits at arithmetic-word offset fourteen.
- Replace the transfer word with four times the arithmetic word.
- Assign the byte captured before F-000000000002 to the reset-associated global.
- Call F-000000000007 with the read pointer unsigned-shifted right by two.
- Call F-000000000008 with no explicit arguments.

The reset-associated assignment uses the captured byte, not necessarily the low byte of the subsequently loaded word or the newly computed transfer word.

F-000000000008’s high result component immediately replaces the **second output pointer**. The ensuing effects are ordered:

1. Store the captured byte at twice the result’s low-component address.
2. Store the low byte of the high component at the low-component address plus eight.
3. Store the candidate output pointer as 32 bits at twice the current accumulator.
4. Store the complete 64-bit result at its low-component address.

The accumulator is then replaced by **four times the candidate output pointer**. The arithmetic word becomes the read pointer shifted left by eight.

Three successive 32-bit stores at candidate-output offsets zero, four, and eight receive:

- The transfer word, which is four times the earlier arithmetic word.
- The newly computed arithmetic word.
- The read pointer.

The outer-entry word becomes **256 times the transfer word**: 256 times the previously computed fourfold arithmetic value. This value determines a later outer-entry word store and the breakpoint-path argument calculation.

### Re-entry and breakpoint continuation

The next branch uses an expression that converts the read pointer to signed 32 bits, shifts left by 31, shifts right by 32, converts to unsigned 32 bits, and shifts right by twenty.

Its result is not established. The signed left shift and the right shift by the apparent operand width prevent a portable interpretation.

If the result is zero, the first output pointer becomes zero and control returns to the outer output entry. The second output pointer remains the high component returned by F-000000000008; the accumulator, transfer word, arithmetic word, and outer-entry word have the updated values described above.

If the result is nonzero:

- Store that result as 32 bits at outer-entry-word offset 32.
- Select the breakpoint-continuation target state.
- Set the next F-000000000002 argument from the outer-entry word interpreted as signed 32 bits and shifted right by 29.
- Invoke software breakpoint number 4.

If execution resumes and reaches the next represented assignment, the arithmetic word becomes the second output pointer interpreted as signed 32 bits and shifted right by eighteen. Processing then continues within the inner loop, **without resetting the call argument to zero**.

This differs from the below-20 path. The resumed-breakpoint argument comes from the signed right shift assigned before the breakpoint; the below-20 argument is reset by the enclosing loop.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Skipped conditional path.** If the fourth argument’s low fifteen bits are zero, F-000000000001 is skipped and the control-block base is 0x000000A1. Entry writes still occur.

2. **Taken path with zero first argument.** If those bits equal one, the conditional path executes, but F-000000000001 receives zero as its first argument.

3. **Mutable fifth argument storage.** If an earlier permitted write or F-000000000001 changes that storage, the common-setup sum uses the changed pointer value. Using the original value is acceptable only under an explicit preservation assumption.

4. **Unknown global conversion.** The working word obtained from 0x0CE00026 cannot be required to equal a zero-extended 16-bit value without additional declaration evidence.

5. **Below-20 restart.** If the scaled word is zero, the routine attempts its self-addressed word store at zero, then resets the next F-000000000002 argument to zero. It does not perform another outer output entry on that transition.

6. **Extended-path selection.** If F-000000000006’s low component is one and multiplication produces 32, the extended path follows the self-addressed store.

7. **Updated outer state.** If the ambiguous branch evaluates to zero, outer re-entry writes the updated outer-entry word at zero and writes the updated accumulator through F-000000000008’s high-component address.

8. **Resumed breakpoint.** If the ambiguous branch is nonzero and breakpoint execution resumes normally, the next first-call argument is the pre-breakpoint signed-right-shift result, not the enclosing loop’s zero initialization.

9. **Interrupted access.** If a required access faults without resumption, subsequent described effects are not guaranteed.
