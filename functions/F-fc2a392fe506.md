# F-fc2a392fe506

## Purpose

F-fc2a392fe506 invokes a long, ordered chain of indirect dependencies, transforms dependency results and implicit machine-state values, performs mixed-width memory accesses, and finishes with an unresolved four-argument indirect transfer.

No application-level purpose is established. The evidence does not justify classifying the operation as parsing, allocation, initialization, serialization, or manipulation of a particular container.

Its behavioral contract includes the **access trace**, not just final memory contents. Computed destinations may overlap fixed addresses, and repeated reads may return different values after intervening writes.

Evidence classifications used below:

- **Established:** explicitly represented operations, widths, and ordering.
- **[INFERENCE]:** conclusions conditional on stated execution-model assumptions.
- **documented_only:** behavior not resolved by the supplied evidence.

## Interface

### Inputs and outputs

The represented interface declares no explicit parameters and no result. Execution nevertheless consumes:

- Incoming control-link state used to derive the first invocation target.
- An incoming 32-bit machine-state value passed onward after a left shift of 23 bits.
- Dependency results represented as 32-bit values or 64-bit containers.
- Auxiliary post-call machine-state values whose dependency contracts are unavailable.
- Bytes and words from fixed and computed addresses.
- An unresolved final transfer target.

There is no established returned object, success flag, error code, output length, or ownership-transfer result. Observable outputs are dependency invocations, memory accesses, memory changes, and the final control transfer.

Completion requires every reached dependency to return control and every reached memory access to be supported for its width and access mode. The function does not locally check these conditions.

## Behavior

### Dependency phase and arithmetic

The first indirect target is derived by adding 4094 to incoming control-link state. Later targets are predominantly derived by adding the same displacement to embedded code-reference values.

The represented path is straight-line: no explicit conditional branch, retry, validation failure, or early-return check appears. Every later operation is conditional on earlier invocations returning.

Invocations have zero through four explicit argument positions. Arguments include shifted dependency results, lower and upper portions of 64-bit results, equal arguments derived from one retained value, explicit zeros, masked subfields, and values retained across intervening invocations. Recurring argument shapes do not establish a shared callee. Ignored results do not establish effect-free calls.

The transformations select fields including 24, 22, 21, 20, 19, 18, 17, 16, 15, 14, 13, 12, and 11 bits. For example:

- Selecting the low 20 bits and logically shifting right by ten yields 0 through 1023.
- Selecting the low 24 bits and logically shifting right by twenty yields 0 through 15.

**[INFERENCE]** With 32-bit bit-vector arithmetic, left shifts and power-of-two multiplication discard bits above bit 31. Successive left shifts by 25 and eight therefore produce zero. Unbounded arithmetic would not preserve this behavior.

Several expressions involve signed quantities. Portable signed-overflow and signed-shift semantics are not established. Address arithmetic overflow is likewise not assigned an unconditional mathematical interpretation.

### Direct-memory boundary

The following semantic labels describe retained values, not source identifiers:

| Label | Meaning |
|---|---|
| Final pair | Last represented 64-bit dependency result before direct writes |
| Link base | Earlier dependency result shifted left by 25 |
| Large base | Another dependency result multiplied by 33,554,432 |
| Narrow index | Earlier result shifted left by eight, masked to 15 bits, then logically shifted right by six |
| Small base | Twice the narrow index |

**[INFERENCE]** Under 32-bit bit-vector semantics, the narrow index is a multiple of four from 0 through 508; the small base is a multiple of eight from 0 through 1016. Neither is established to denote allocated storage.

The opening writes publish the link base as a word at the final pair’s upper-word address plus 0x14, then write the upper word’s low byte at link-base offset 9. A word store at 256 times the lower word plus 0x54 publishes the large base. A second byte store at link-base offset 9 then writes the link base’s low byte.

Next, large-base offset 0x14 receives a zero word, followed by a byte read at large-base offset 5. Small-base offset 0x14 receives a zero word before that saved byte is zero-extended into a word at large-base offset 0x34. The function then reads the word at large-base offset 0x14, writes another zero word at small-base offset 0x14, and makes two byte stores at small-base offset 0x15 using the loaded word’s low byte.

These are distinct, ordered accesses. In particular, the loaded word is not unconditionally zero: preceding writes may overlap its storage, and ordinary-memory behavior is not established.

### Fixed-address accesses within computed updates

The next fixed-address access is an unsigned byte read at **0x05**. Its value becomes a computed address base. Immediately afterward, a byte store at **0x01** writes the small base’s low byte.

Computed updates then include:

- A byte store at the byte-derived base plus 0x15.
- A byte store of the retained word at large-base offset 0x11.
- A word store of the retained word through the previously loaded large-base-offset-0x14 value, at offset 0x54.
- A zero byte store at large-base offset 0x11.
- A word read and subsequent replacement at the byte-derived base plus 0x54.

Call the word captured by that last read the **saved link word**.

Further computed accesses load links at offset 0x74, write through those links at offset 0x54, and repeat self-derived word stores and byte stores. One expression contains two word reads at small-base offset 0x74; their intra-expression evaluation order is not independently established.

The fixed word store at **0x54** occurs later, specifically **between** a word store at small-base offset 0x14 using the earlier large-base-producing result shifted left by 26, and two subsequent word stores at that same computed offset using the saved link word. The fixed store writes twice the saved link word.

After those computed word stores, two byte stores at small-base offset 0x15 write the low byte of four times the saved link word. Only then does a fixed byte store at **0x15** write the small base’s low byte. That fixed store precedes the next word store at four times the saved link word plus 0x54.

These placements prohibit treating fixed-address effects as a separate batch.

### Linked accesses and constant stores

The intervening computed-memory phase uses offsets including 4, 5, 9, 0x0D, 0x14, 0x15, 0x24, 0x34, 0x44, 0x54, 0x64, and 0x74.

Its observable features include self-address publication, repeated stores, scaling loaded words by two, four, and eight, and fresh reads after earlier writes. A byte read at a derived offset 5 supplies an address base for a word read at offset 0x74. No check establishes that such a byte-derived address is valid.

For the later phases, define:

- **Quadruple base:** four times the saved link word.
- **Adjusted base:** quadruple base minus 150.
- **Publication address:** four times the adjusted base.
- **Selected link:** the later word loaded at a byte-derived base plus 0x74.
- **Twice-link base:** twice the selected link.
- **Publication payload:** four times the selected link.

The selected link is captured before three stores of numeric 0x3A: a byte at four times the selected link, a halfword at eight times the selected link, and a word at publication-payload offset 0x20.

Publication-address offset 0x20 then receives, in order, word values 0x20, 0x2F, a zero-extended byte freshly read at publication-address offset 4, and 0x20 again. Intermediate writes remain part of the trace.

### Publication phase

After those stores, a word read at fixed address **0x087FBBBC** captures the **publication base**. The next memory effect is a fixed word store of **0x20 at 0x60**, before the first computed publication group.

Each publication group contains an ordered word store at a scaled destination plus 0x54, a byte store at publication-base offset 0x19, a byte store at publication-address offset 0x11, and a word store at publication-base offset 0x34.

The byte values are captured low bytes of the publication address and publication base. The publication base itself is retained, not reloaded for each group.

The first group uses eight times the saved link word for its scaled destination and final word value. Subsequent repeated groups instead use eight times the adjusted base. Their initial word stores publish the publication payload.

No index advancement or data-dependent termination is represented. Exact repetition multiplicity is **documented_only in this contract**; the summary does not authorize coalescing repeated accesses.

### The three fresh reads at 0x67

The function next writes the fixed saved word’s low byte to **0x67**. This is an initial store, not a promise that subsequent reads return that byte.

A word read at twice-link-base offset 0x44 intervenes before a **fresh byte read at 0x67** supplies the byte written to **0x21**.

The captured offset-0x44 word then supplies a byte store at publication-address offset 0x10 and a word store at publication-base offset 0x54. A byte store at twice-link-base offset 1 uses its signed right shift by the publication address’s low eight bits. Publication-base offset 0x54 subsequently receives the publication address as a word.

Before the next fixed byte read, the function also:

- Reads a word at publication-address offset 0x40.
- Stores the saved publication word at publication-base offset 0x74.
- Stores the newly read word at publication-address offset 0x10, after the earlier byte store there.
- Stores the twice-link base at publication-base offset 0x44.

A **second fresh byte read at 0x67** supplies the next byte store at publication-address offset 9.

Further intervening accesses write the publication address’s low byte at twice-link-base offset 9, write the fixed saved word at publication-address offset 0x44, and read a word at publication-address offset 0x54. Call that word the **late destination**.

A **third fresh byte read at 0x67** then supplies another byte store at publication-address offset 9.

Thus the bytes written to 0x21 and to these two offset-9 destinations are sampled separately. Computed writes between samples may alias 0x67. No equality among the three sampled bytes is guaranteed.

For the signed variable shift, counts of 32 or greater remain **documented_only**; neither count masking nor a zero result is established.

### Final updates and transfer

The payload word’s low byte is written at late-destination offset 0x0D. Twice-link-base offset 0x54 is restored from the saved return word.

A fresh word read at publication-address offset 0x14 is retained for a later byte store. The function also writes the payload word’s low byte at twice-link-base offset 0x11, the late destination’s low byte at publication-address offset 9, and the late destination as a word at publication-address offset 0x44.

A word read at twice-link-base offset 4 supplies another base. A halfword store of 0x65 occurs at twice that base **before** a word read at its offset 0x64 captures a later link.

The retained publication-address-offset-0x14 word supplies a byte store at late-destination offset 0x11; late-destination offset 0x54 then receives word value 100. A fresh word read at the newly loaded base plus 0x74 supplies the final argument word.

Finally, the function reads a destination link at twice-link-base offset 0x64, writes a byte at twice-link-base offset 9, writes the later link through the destination link at offset 0x54, and writes the destination link as a word at twice the later link.

The final unresolved invocation receives, in order:

1. Numeric 0x72.
2. The later link captured from offset 0x64.
3. The saved return word captured before the 0x67 sequence.
4. The later word captured from offset 0x74.

## Acceptance examples

These are conditional static obligations, not executed tests.

1. **Unsigned promotion.** If large-base offset 5 yields 0xE7, the subsequent word store at large-base offset 0x34 receives 231, not a sign-extended value.

2. **Fixed-store placement.** The word write at 0x54 remains between the specified small-base-offset-0x14 stores. Moving it after them changes the required trace, even if disjoint ordinary memory would have the same final contents.

3. **Publication ordering.** The fixed publication-base read precedes the word write of 0x20 at 0x60, which precedes the first computed publication group.

4. **Late capture ordering.** The word read at 0xA9 precedes the payload-word read; the byte write at 0x3A follows both but precedes the saved-return-word and saved-publication-word reads.

5. **Fresh fixed-byte sampling.** If the initial 0x67 store writes 0xA5 but an intervening aliased access changes that byte to 0x3C, a subsequent fresh read must not be replaced by saved 0xA5. Each of the three reads has its own sampling point.

6. **Saved full word.** The initial byte store at 0x67 does not narrow the retained fixed saved word. Its later word store still uses the captured 32-bit value.

7. **Width boundary.** Under 32-bit bit-vector semantics, successive left shifts of 1 by 25 and eight yield zero. A wider nonzero result does not match that interpretation.

8. **Repeated effects.** Where individual accesses are observable, collapsing repeated equal-value writes changes behavior.

9. **Unresolved shift.** A variable shift count of 40 must not silently become eight, zero, or a rejected input.

10. **Interrupted execution.** An early non-returning dependency does not require later direct-memory effects. No local fallback is established.
