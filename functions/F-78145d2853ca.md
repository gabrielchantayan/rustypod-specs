# F-78145d2853ca

## Purpose

F-78145d2853ca performs an ordered sequence of initialization-like dependency calls against regions of a caller-supplied object. It then invokes a status-producing dependency and, only when that dependency returns zero, requests a 16-byte block and installs its address in the object.

The established behavior is the sequence of calls, address calculations, status handling, and explicit memory writes described below. The interpretation of the earlier calls as cache initialization is inferred from descriptive labels in the supplied material. Their internal effects are not established.

This function is not demonstrably transactional. Earlier dependency calls occur before either reported failure path, and no rollback or release operation is visible.

### Status gate

- Second argument: decimal 100.

If that call returns a nonzero value, the function immediately returns that same value.

### Block request and address installation

If the status gate returns zero, the function invokes F-858f5b8d5984 with a size argument of `0x10`, decimal 16.

It then writes the returned address into the 32-bit field at object offset `0x48`, regardless of whether the returned address is null.

For a null result:

- Object offset `0x48` receives zero.
- No block-field writes occur.
- The function returns `-108`.

For a nonnull result:

1. The returned address is first stored at object offset `0x48`.
2. One 32-bit global value is read and written to offset zero of the returned block.
3. The installed address at object offset `0x48` is read to locate the destination for the 32-bit value `0x30` at block offset `0x04`.
4. The installed address is read again to locate the destination for the 32-bit value 100 at block offset `0x08`.
5. The function returns zero.

The global value is obtained after F-858f5b8d5984 returns, not from a snapshot taken before the dependencies execute. Its earlier value must not be substituted on the assumption that callees preserve globals.

The first block write uses the address returned by F-858f5b8d5984. The subsequent two destination calculations use the address field stored in the object. Under ordinary non-overlapping storage these identify the same block. Without a non-aliasing precondition, that equivalence is not guaranteed: an earlier write could affect the stored address or the global source. The explicit access order therefore matters.

## Side effects
