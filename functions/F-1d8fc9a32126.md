# F-1d8fc9a32126

## Purpose

F-1d8fc9a32126 routes an input record through a sequence of callbacks associated with a receiver. It conditionally performs a preliminary notification, optionally invokes an early callback, invokes exactly one main callback if execution reaches that stage, and optionally invokes a final callback.

The observable result is the first nonzero result from a result-bearing callback in this sequence. If no such callback returns a nonzero result, the function returns zero. The preliminary notification does not participate in this result selection.

The routing decisions use record fields and receiver fields that are read at different points in execution. They are not a snapshot taken on entry. Changes made by a callback can therefore affect later routing, callback selection, and field comparisons.

These behaviors are established by the supplied static representation. The interpretation of the input as an event or message, and of nonzero results as “handled,” is inferred intent rather than an established API meaning.

## Interface

### Inputs

The function takes two arguments:

- **Receiver:** An address used to access a dispatch-table pointer and receiver state.
- **Input record:** An address used to access a record discriminator and a type-dependent value or payload address.

Neither argument is checked for nullness, alignment, accessibility, object lifetime, or structural validity.

### Accessed layout

The supplied representation uses four-byte integer accesses and four-byte table entries. The following offsets are byte offsets.

| Structure | Offset | Access and role |
|---|---:|---|
| Receiver | `0x00` | Dispatch-table address, read when an indirect callback is selected |
| Receiver | `0x50` | Four-byte value used by the final-stage comparison |
| Receiver | `0x108` | Four-byte value narrowed to a character-sized argument for the preliminary notification |
| Input record | `0x04` | Four-byte discriminator, read separately at multiple stages |
| Input record | `0x08` | Four-byte payload address for discriminator `0x16`; four-byte comparison value for discriminator `0x0F` |

The payload address is obtained from the input record; it is not an inline payload beginning at offset `0x08`.

The receiver field at `0x108` is read as a full four-byte integer before narrowing. Its storage must therefore support that full read even if only its narrowed value is relevant to the dependency.

The integer and address usage is consistent with a 32-bit target. Exact ABI details, including byte order, pointer representation, and character signedness, are not independently established by the excerpt.

### Outputs

The return value is an integer represented as 32 bits in the supplied material:

- A nonzero early-callback result is returned unchanged.
- Otherwise, a nonzero main-callback result is returned unchanged.
- Otherwise, a nonzero final-callback result is returned unchanged.
- If none of those conditions applies, the function returns zero.

No distinction among positive and negative nonzero results is made.

- For each payload access, the currently read payload address must support a four-byte read at offset `0x04`.
- Dependencies that return normally must leave any state subsequently accessed in a usable condition if normal completion is expected.

There is no local validation or recovery for violations of these requirements.

## Behavior

### 1. Preliminary notification

The function first reads the input discriminator at offset `0x04`.

If it is not `0x16`, this stage ends without reading the payload.

If it is `0x16`, the function reads the payload address from input offset `0x08`, then reads the payload subtype at offset `0x04`. The supplied representation subtracts `0x2500` from that subtype and checks whether the result equals two.

When that condition holds, the function:

1. Reads the receiver’s four-byte field at offset `0x108`.
2. Narrows that value to a character-sized argument.
3. Calls F-a93c920e9dbe with the receiver and that narrowed argument.

For the ordinary representable value `0x2502`, the condition holds without an overflow question. The exact semantics of the intermediate subtraction for extreme integer values are not established independently of the supplied representation.

No result from F-a93c920e9dbe is tested or returned. If it returns normally, routing continues. The function does not restore receiver or input state after the call.

### 2. Optional early callback

After the preliminary stage, the function reads the input discriminator again. It does not reuse the earlier discriminator or subtype.

If this current discriminator is `0x16`, it reads the current payload address and the subtype at payload offset `0x04`.

If the current subtype is zero, the function:

1. Reads the dispatch-table address from receiver offset `0x00`.
2. Obtains the callback at table offset `0x124`.
3. Calls it with the original receiver address and input-record address.

If that callback returns nonzero, its result becomes the function’s return value immediately. Neither main dispatch nor the final-stage comparison then occurs.

If the callback returns zero, execution continues. If the discriminator or subtype did not match, no early callback is invoked.

Mutations by F-a93c920e9dbe can therefore enable or disable the early callback.

### 3. Main callback selection and invocation

If execution has not already returned, the function reads the input discriminator again.

For a current discriminator of `0x16`, it reads the current payload address and then the subtype at payload offset `0x04`.

It selects:

- Dispatch-table offset `0x10C` if the current discriminator is `0x16` and the current subtype is `0x2A`.
- Dispatch-table offset `0x110` in every other case.

For a discriminator other than `0x16`, this selection does not require a payload read.

The function obtains the current dispatch-table address from the receiver and invokes the selected callback with the receiver and input-record addresses.

Exactly one of these two main callbacks is invoked on every normally progressing path that reaches this stage. The function does not invoke the other main callback as a fallback.

A nonzero main-callback result is returned immediately. A zero result permits the final stage.

Mutations by the preliminary notification or a zero-returning early callback can change the selected main callback. In particular, the dispatch-table address itself is fetched after those calls; it is not cached across them.

### 4. Optional final callback

Following a zero main-callback result, the function reads the input discriminator once more.

If the discriminator is not `0x0F`, it returns zero without performing the final comparison.

If the discriminator is `0x0F`, it reads:

1. The input’s four-byte value at offset `0x08`.
2. The receiver’s four-byte value at offset `0x50`.

These are compared as integer values. This stage does not dereference the input value at offset `0x08`.

If they differ, the function returns zero.

If they match, the function reads the receiver’s current dispatch-table address and invokes the callback at table offset `0xE0`, passing the receiver and input-record addresses.

A nonzero callback result is returned unchanged. A zero result leads to the final zero return.

Because these reads follow main dispatch, a main callback that returns zero can enable or disable this stage by changing the discriminator or either comparison value.

### Read-order and mutation guarantees

The established ordering is:

1. Preliminary discriminator and, conditionally, payload reads.
2. Conditional receiver-field read and preliminary notification.
3. Fresh early-stage discriminator and conditional payload reads.
4. Conditional early callback and result check.
5. Fresh main-stage discriminator and conditional payload reads.
6. Main callback and result check.
7. Fresh final-stage discriminator and conditional comparison reads.
8. Conditional final callback and result check.

The function passes the same two argument addresses to every indirect callback. It does not copy the input record or receiver into a stable local object.

These separate reads do not establish thread synchronization, atomicity, or support for concurrent mutation.

## Side effects

The function contains no explicit writes to receiver fields, input fields, payload fields, or dispatch-table entries. It also contains no explicit allocation or deallocation.

Its externally visible effects arise from:

- Ordered reads of the structures described above.
- Calls to F-a93c920e9dbe and selected indirect dependencies.
- Propagation of the selected nonzero callback result.

The absence of direct stores is not a promise that the overall operation is read-only. Dependencies receive addresses through which they may modify state.

Ownership is not transferred by any explicit operation in this function. Whether a dependency retains, consumes, releases, or otherwise changes the lifetime of an argument is unknown. In particular, the function supplies no protection against a dependency invalidating memory that a later stage accesses.

The function does not save and restore global state around dependencies. No assumption that they preserve globals is justified.

Invalid memory, invalid callback targets, dependency exceptions or faults, and failure to return normally have no local handling shown here.
