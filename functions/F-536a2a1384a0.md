# F-536a2a1384a0

## Purpose

F-536a2a1384a0 dispatches an operation according to a one-byte descriptor tag.

Two tag values receive further processing:

- Tag **1** invokes a resolver that can replace a locally held record pointer. A nonzero resolver result selects a sequence involving two record fields, several dependencies, and an external operation. A zero result delegates the original request to a fallback dependency.
- Tag **2** delegates the original request only when a descriptor field at byte offset 24 is nonzero.
- All other tag values return without calling a dependency or explicitly writing caller-visible memory.

The apparent intent of the successful tag-1 sequence is to replace a resource associated with a record and populate it from the original record argument. That interpretation is **inferred**, not established: the dependencies’ allocation, release, synchronization, and transfer semantics are not provided.

This contract specifies the visible control flow and explicit accesses. It does not assume that dependencies preserve memory, preserve global state, succeed, or return normally.

## Interface

The function takes five arguments and has no returned value:

| Position | Contract name | Representation and use |
|---|---|---|
| 1 | Descriptor | Pointer to memory. Byte offset 0 supplies the dispatch tag. Tag 1 also uses a four-byte field at offset 4. Tag 2 uses an integer field at offset 24. |
| 2 | Context A | Opaque four-byte value forwarded to selected dependencies. |
| 3 | Context B | Opaque four-byte value forwarded to selected dependencies; supplied twice in the resolver call. |
| 4 | Original record | Pointer to four-byte entries. Its pointer value initializes a local working-record pointer. It is also forwarded unchanged as an argument to selected dependencies. |
| 5 | Extent | Opaque four-byte value forwarded to selected dependencies and stored in the first entry of the working record on successful tag-1 processing. |

“Extent” is a descriptive name, not an established size interpretation. No signedness, unit, valid range, or relationship to accessible memory is established for that argument.

Pointer width, byte order, alignment requirements, and object packing are not independently established. Field offsets are byte offsets; record entries are four bytes apart.

### Preconditions

The descriptor must support the accesses required by the selected path:

- Every invocation requires a readable tag byte.
- Tag 1 requires a readable four-byte field at offset 4 when each corresponding load occurs.
- Tag 2 requires a readable integer field at offset 24.
- Other tag values do not require either later field to be read by this function.

The original record need not be locally dereferenced on every path. On the successful tag-1 path, however, the current working record must support the explicit reads and writes described below. Dependencies may impose additional requirements, including requirements on the original record and Extent.

No null checks, bounds checks, alignment checks, or object-validity checks are present. Invalid accesses do not produce a defined error result under this contract.

## Behavior

### Dispatch

The function initializes a local working-record pointer from Original record, then inspects the descriptor tag.

A tag other than 1 or 2 causes an immediate return. There is no default delegation.

The tag-1 branch takes precedence over the tag-2 branch. Once tag-1 processing begins, later changes to the descriptor tag do not cause redispatch.

### Tag 1: resolution

The function loads the four-byte descriptor field at offset 4 and calls **F-148a31e02bc5** with five arguments, in this positional order:

1. The loaded descriptor field.
2. Context A.
3. Context B.
4. The address of the local working-record pointer.
5. Context B again.

The fourth argument permits the resolver to replace the local pointer. This is not an explicit write to the caller’s argument variable, nor is it necessarily a write to the original record’s contents.

The resolver’s result is tested only for zero versus nonzero. No particular nonzero value is singled out. If its result is represented as a signed integer, negative values also select the nonzero branch.

#### Zero resolver result

A zero result causes a call to **F-7656802f08c9** with the five original arguments, in their original positions. The function then returns.

A resolver replacement of the working-record pointer does not change the record pointer passed to this fallback: the fallback receives Original record.

There is no rollback of resolver side effects. There are no explicit record-field writes by F-536a2a1384a0 on this branch.

#### Nonzero resolver result

A nonzero result selects the following ordered sequence, assuming each dependency returns normally:

1. Read the four-byte entry at offset 4 from the current working record.
2. Call **F-8349c252c168** with that entry and the constant **25**.
3. Call **F-638beded7699** with Extent and the constant **25**. Retain its four-byte result as the replacement value.
4. Call **F-14590d82970d** with no explicit arguments.
5. Call **F-UNMAPPED-1** with:
   - the replacement value;
   - Original record;
   - Extent.
6. Write the replacement value to offset 4 of the current working record.
7. Write Extent to offset 0 of the current working record.
8. Load the descriptor field at offset 4 again.
9. Call **F-1488711eb836** with that newly loaded field, Context A, and Context B.
10. Return.

**F-UNMAPPED-1** is a document-local opaque identifier for the external dependency whose identifier was not supplied in the dependency map.

The replacement value is not checked for zero, validity, capacity, or any other property. The later sequence proceeds with whatever four-byte value F-638beded7699 returns.

The external call in step 5 receives Original record, not the resolver-selected working record. Consequently, if the resolver selects a different record, the external operation and the explicit record writes concern different pointer values.

The two explicit record writes occur after the external call, in this order: offset 4 first, offset 0 second. They are not established as atomic or transactional.

The descriptor field used for finalization is reloaded after the dependencies and record writes. It is not guaranteed to equal the field supplied to the resolver. This matters if dependencies modify the descriptor or if the descriptor aliases memory written during the sequence.

The working-record pointer is also not guaranteed to remain equal to Original record. Beyond the resolver’s direct opportunity to replace it, the supplied body does not establish that dependencies cannot retain or use an alias to that local pointer during subsequent calls. The accesses above therefore concern the working pointer’s value when each access occurs, not an assumed immutable snapshot.

### Tag 2: guarded delegation

For tag 2, the function reads the descriptor’s integer field at byte offset 24.

- If the field is zero, the function returns without a dependency call.
- If the field is nonzero, the function calls **F-e94cc6a7a41a** with all five original arguments, then returns.

The local predicate is strictly zero versus nonzero. It does not distinguish positive and negative values.

### Errors and interrupted execution

The function reports no explicit success or failure status.

It contains no local error branch for:

- Invalid pointers.
- Resolver-selected invalid records.
- A zero replacement value.
- Failure of the external operation.
- Failure of finalization.

Dependency return values other than the resolver result and replacement value are not used to make decisions.

If a dependency fails to return normally, the supplied body establishes no recovery, compensating action, or completion guarantee. In particular, the successful tag-1 sequence must not be treated as all-or-nothing.

## Side effects

The only explicit caller-visible writes in the body occur on the nonzero tag-1 path:

1. Replacement value to working-record offset 4.
2. Extent to working-record offset 0.

The resolver additionally receives a writable address for the local working-record pointer. All dependencies may have side effects not established here.

The ordering of dependency calls and explicit writes is significant. The first dependency receives the old offset-4 entry before the replacement-producing dependency is called. The no-argument dependency and external operation both occur before the record fields are updated. Finalization occurs after both writes.

The source does not establish ownership transfer:

- F-8349c252c168 might release or otherwise process the old value, but release semantics are unknown.
- F-638beded7699 might create or acquire a resource, but allocation and ownership semantics are unknown.
- F-UNMAPPED-1 might perform a transfer involving the replacement value and Original record, but copy direction, byte count, overlap handling, and memory ownership are unknown.
- No dependency is assumed to preserve globals or unrelated memory.

No local arithmetic computes a size, adjusts Extent, or validates capacity. Extent is forwarded and stored as a four-byte value without a local range check. The constant 25 is a dependency argument, not an established byte count or resource category.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

1. **Unrecognized tag.** Given a readable descriptor tag of 0 or 3, the function returns without calling a listed dependency or explicitly accessing the later descriptor fields.

2. **Tag 2, disabled field.** Given tag 2 and a zero integer at offset 24, the function returns without calling F-e94cc6a7a41a. The field at offset 4 is not locally read.

3. **Tag 2, enabled field.** Given tag 2 and any nonzero value at offset 24, F-e94cc6a7a41a receives all five original arguments exactly once, assuming normal execution.

4. **Resolver declines.** Given tag 1 and a zero resolver result, F-7656802f08c9 receives the original arguments. No subsequent replacement-path dependency is called by this invocation.

5. **Resolver redirects the record.** Given a resolver that changes the working pointer to a distinct valid record and returns nonzero, the old offset-4 value is read from that selected record. Assuming later dependencies do not redirect the working pointer, the two explicit writes also target that record. F-UNMAPPED-1 still receives Original record.

6. **Replacement value is zero.** Given normal dependency returns and a zero result from F-638beded7699, zero is passed to F-UNMAPPED-1 and subsequently written to working-record offset 4. No local failure branch intervenes.

7. **Descriptor changes during processing.** If the descriptor field at offset 4 changes after resolution but before finalization, finalization receives the value present at its later load, assuming that load remains valid.

8. **Observation before record update.** If F-UNMAPPED-1 observes the working record and no preceding dependency has modified it, it runs before this function’s replacement and Extent writes. Finalization runs after those writes.
