# F-70e13ef9fc28

## Purpose

F-70e13ef9fc28 conditionally updates two 32-bit fields in an associated object. Its behavior is selected by a one-byte mode in a controlling object.

The three behavioral families are:

- **Mode 1:** derive an interval from dependency results and a configured span, subject to an unsigned eligibility check.
- **Mode 2:** accept, derive, or leave unresolved two endpoint values, optionally invoke an adjustment dependency, and then store endpoints.
- **All other modes:** derive an interval around a dependency-provided position, constrained by two stored bounds.

“Interval,” “position,” “span,” and “bound” are descriptive interpretations of the arithmetic and field usage. Their application-level meaning is not established. In particular, the supplied material does not establish that the resulting endpoints are always ordered, nonnegative, or within both bounds.

The return value is branch-dependent. It is not a uniform success indicator, endpoint, or object reference.

## Interface

### Inputs

The function receives three machine-word inputs:

| Input | Established use |
|---|---|
| Controller reference | Address of an object containing the mode, an associated-object reference, and two numeric configuration fields. |
| First endpoint input | A 32-bit value used only in mode 2. The bit pattern representing signed −1 is a sentinel. |
| Second endpoint input | A 32-bit value used only in mode 2. Signed −1 is a sentinel. |

The supplied representation uses 32-bit integer-valued addresses and 32-bit scalar fields. A wider-address implementation would need to preserve the observed distinction between address returns and numeric returns rather than treating every return as an endpoint.

### Referenced layouts

Offsets below are byte offsets relative to the indicated object. They describe accessed fields, not complete object layouts.

**Controller object**

| Offset | Width | Role |
|---|---:|---|
| +4 | 32 bits | Associated-object reference |
| +32 | 32 bits | Span used by mode 1 and the default mode |
| +36 | 8 bits | Mode selector |
| +56 | 32 bits | Grouping scale used by automatic mode-2 calculations |

**Associated object**

| Offset | Width | Role |
|---|---:|---|

For readability, the fields at +64 and +68 are called the **upper endpoint** and **lower endpoint** respectively. Those names do not assert an invariant that the first is numerically greater than or equal to the second.

### Output

The return is one 32-bit word. Depending on the path, it contains:

- An associated-object reference.
- The lower endpoint calculated or supplied in mode 2.
- The lower endpoint calculated on certain default-mode paths.
- The second endpoint input on the mode-2 early-return path.

### Preconditions

Normal execution requires all references actually dereferenced on the selected path to designate accessible storage of the necessary size and alignment. Writes require writable endpoint fields.

Additional requirements imposed by dependencies are unknown. In particular:

- No divisor-like scale is validated locally.
- Negative spans and scales are not rejected locally.
- Bound ordering is not checked.
- There is no local null-reference handling.
- There is no established protection against concurrent or reentrant changes to the controller or associated object.

## Behavior

### Numeric model

Fields and intermediate results are 32-bit quantities. Signed comparisons are used except for the explicitly unsigned mode-1 eligibility comparison.

The default mode halves the signed span using a right shift by one. The supplied representation does not by itself establish portable behavior for negative operands; the target’s signed-shift behavior matters.

Several additions, subtractions, and multiplications can exceed signed 32-bit range. The supplied material does not justify treating these calculations as unbounded mathematical integers. The formulas below describe the operations for inputs whose intermediates are representable. Overflow behavior is documented_only pending instruction-level or ABI evidence.

No arithmetic meaning is assumed for F-d7be9cfb4000 or F-870c4fcf7295 beyond their arguments and returned word.

### Mode selection

The mode byte is tested for equality with 1 first. If that test fails, it is tested for equality with 2. Every other value, including zero, selects the default behavior.

The supplied representation contains separate mode-byte accesses. It does not establish an atomic snapshot across both tests.

### Mode 1: calculated interval with an eligibility gate

First, F-d4307b71d8ac is called with the currently referenced associated object. Its result is interpreted as unsigned for comparison with the associated object’s +60 field, also interpreted as unsigned.

If the result exceeds that field:

- No endpoint write is directly performed by this function.
- The function returns the associated-object reference read at return time.
- Dependency effects already incurred are not undone.

Otherwise, the interval calculation proceeds in this order:

1. F-b2eb34d24bb8 is called at a site whose argument is not represented.
2. The controller’s +32 span is read.
3. F-d7be9cfb4000 receives the sum of the preceding dependency result and the eligibility result, followed by that span.
4. F-b2eb34d24bb8 is called again, this time with the currently referenced associated object.
5. A lower endpoint is formed as the F-d7be9cfb4000 result multiplied by the previously captured span, minus the second F-b2eb34d24bb8 result.
6. The associated object’s +60 bound is read as signed. The controller span is read again.
7. An upper candidate is formed as lower endpoint plus the newly read span minus one. If the signed bound is smaller, the bound replaces the candidate.

The function writes the upper endpoint at +64 first. It then rereads the associated-object reference, writes the calculated lower endpoint at +68, and returns the reference used for this second write.

Consequences:

- The eligibility check permits equality.
- The span used in multiplication and the span used to construct the upper candidate need not be equal if intervening calls change controller state.
- There is no lower-bound clamp on the calculated lower endpoint.
- The first F-b2eb34d24bb8 invocation must not be silently treated as receiving the associated object; its argument is unresolved.

### Mode 2: sentinel-controlled endpoint processing

A signed −1 marks an unspecified endpoint.

#### Both inputs specified

If the first endpoint input is not −1 and the second endpoint input is not −1, the function immediately returns the second input.

It does not call the mode-2 adjustment dependency and does not directly write either endpoint field. Thus two supplied values are not locally committed by this path.

#### Exactly one input unspecified

If exactly one input equals −1, automatic endpoint calculation is skipped. Execution proceeds to the adjustment dependency and final writes described below.

There is no local rejection of the remaining sentinel and no local completion formula on these paths.

#### Both inputs unspecified

When both inputs equal −1, the function obtains three results in order:

1. F-d4307b71d8ac with the associated object.
2. F-b2eb34d24bb8 with the associated object.
3. F-d4307b71d8ac with the associated object.

The associated-object reference is then captured. Its upper endpoint is compared, signed, with the third result.

**If the stored upper endpoint is less than the third result:**

- The controller’s +56 scale is captured.
- F-870c4fcf7295 receives the sum of the first two results and that scale.
- F-b2eb34d24bb8 receives the captured associated-object reference.
- The second endpoint input is replaced by: one more than the F-870c4fcf7295 result, multiplied by the captured scale, minus the final dependency result, minus one.
- The first endpoint input remains −1 before the adjustment call.

**Otherwise:**

- F-d4307b71d8ac is called with the captured associated-object reference.
- The lower endpoint of the then-current associated object is read.
- If that lower endpoint is less than or equal to the latest dependency result, the function returns the then-current associated-object reference without directly writing endpoints or invoking the adjustment dependency.

If that early-return condition does not hold:

- F-d4307b71d8ac is called at a site whose argument is not represented.
- F-b2eb34d24bb8 is called with the currently referenced associated object.
- The controller’s +56 scale is captured.
- F-870c4fcf7295 receives the sum of those two dependency results and the captured scale.
- F-b2eb34d24bb8 is called again with the currently referenced associated object.
- The first endpoint input is replaced by the F-870c4fcf7295 result multiplied by the captured scale, minus the final dependency result.
- The second endpoint input remains −1 before adjustment.

Repeated calls are distinct observations. Their results must not be assumed identical.

#### Adjustment and final writes

Every mode-2 path reaching this stage calls F-e7359f0adc7d with:

- The controller reference.
- Two addresses of stack-resident locations.

The supplied material does not establish how those two locations alias the endpoint inputs. Consequently, whether this call fills an unspecified endpoint or modifies either endpoint later written is unresolved.

After the call returns:

- The second endpoint value is stored at +64 of the currently referenced associated object.
- The first endpoint value is stored at +68, using another read of the associated-object reference.
- The first endpoint value is returned.

No post-adjustment validation is visible. The two writes are not presented as an atomic operation.

### Default mode: bound-aware interval construction

F-d4307b71d8ac is first called with the associated object. Its result supplies the position for this branch.

After that call, the function captures the current associated-object reference and its lower bound. It reads the controller span and shifts it right by one to obtain a half-span.

For ordinary nonnegative spans, an odd span therefore contributes twice its truncated half, rather than the original span, to the endpoint difference.

The branch decisions are:

**Position is below lower bound plus half-span**

- The lower endpoint becomes the lower bound.
- The upper endpoint becomes the signed minimum of the upper bound and lower bound plus twice the half-span.
- The upper endpoint is written through the captured associated-object reference.
- The associated-object reference is reread; the lower endpoint is written through that reference.
- That reread reference is returned.

Equality does not take this path.

**Position is at least lower bound plus half-span, and position plus half-span does not exceed the upper bound**

- The upper endpoint becomes position plus half-span.
- The lower endpoint becomes position minus half-span.
- The upper endpoint is written first, followed by the lower endpoint through a reread reference.
- The numeric lower endpoint is returned.

**Position is at least lower bound plus half-span, but position plus half-span exceeds the upper bound**

- The upper endpoint becomes the upper bound.
- The lower endpoint becomes the signed maximum of the lower bound and upper bound minus twice the half-span.
- Writes occur upper first, then lower through a reread reference.
- The numeric lower endpoint is returned.

There is no independent check that the stored bounds are ordered or that a negative span produces a meaningful interval.

## Side effects

Direct persistent writes are confined, in the supplied representation, to associated-object offsets +64 and +68. Whenever both are written, +64 is written first.

The function does not directly allocate, release, or transfer ownership of memory. Passing an object reference to a dependency does not establish whether that dependency retains it, releases it, or modifies its contents.

Dependencies may have additional effects. No preservation guarantee is supplied for global state, controller fields, associated-object fields, or ownership.

This matters because the function mixes captured references and fresh reads. A dependency-induced change to the controller’s associated-object reference can affect subsequent calculations, write destinations, or returned references. No rollback is visible if a dependency fails to return normally or if a later memory access fails.

No explicit error status, exception translation, logging, or recovery behavior is established.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests. Unless stated otherwise, dependencies return normally, references remain stable, memory is accessible, and arithmetic is representable.

1. **Mode-1 eligibility rejection.** If the first dependency result is unsigned 11 and the +60 field is unsigned 10, no direct endpoint writes occur. The return is the associated-object reference.

2. **Unsigned eligibility distinction.** A first result with all 32 bits set is larger than an unsigned bound of 100, even though the same result would represent signed −1. The mode-1 calculation is skipped.

3. **Mode-1 calculation and clipping.** Suppose the eligibility result is 7, the first F-b2eb34d24bb8 result is 3, both span reads are 4, F-d7be9cfb4000 returns 3 for its arguments, and the second F-b2eb34d24bb8 result is 2. The lower endpoint is 10. With bound 12, the upper candidate 13 is clipped to 12. Writes are 12 at +64, then 10 at +68; the return is an object reference.

4. **Mode-2 fully specified inputs.** With first input 10 and second input 20, mode 2 returns 20 without directly changing either endpoint or calling F-e7359f0adc7d.

5. **Mode-2 forward automatic calculation.** With both inputs unspecified, initial dependency results 7 and 3, a third result exceeding the stored upper endpoint, scale 4, F-870c4fcf7295 result 2, and final F-b2eb34d24bb8 result 1, the second endpoint becomes 10 before adjustment. The first remains −1 before adjustment. Final stored values depend on the unresolved adjustment aliasing contract.

6. **Mode-2 contained-position early return.** With both inputs unspecified, if the upper-endpoint comparison does not select forward calculation and the later lower endpoint is at most the next F-d4307b71d8ac result, the function returns an object reference without adjustment or direct endpoint writes.

7. **Default centered interval.** With lower bound 0, upper bound 100, span 10, and position 40, the endpoints become 45 and 35. The return is numeric 35.

8. **Default upper-edge interval.** With the same bounds and span but position 98, the endpoints become 100 and 90. The return is numeric 90.

9. **Default lower-edge interval.** With those bounds and span but position 2, the endpoints become 10 and 0. The return is an object reference, not numeric zero.

10. **Default odd span.** With bounds 0 and 100, span 5, and position 40, the half-span is 2. The endpoints become 42 and 38; the endpoint difference is 4.

## Uncertainties

The following are **documented_only**:

- Application meaning and units of all numeric fields.
- Complete object layouts and lifetime rules.
- Dependency implementations, effects, and error behavior.
- Arguments at the two call sites where no argument is represented.
- Aliasing between the mode-2 stack locations and endpoint values.
- Exact overflow and negative-right-shift behavior.
- Valid span, scale, bound, and input ranges.
- Thread-safety, reentrancy, and asynchronous mutation guarantees.
- Whether mixed numeric/reference returns are intentional interface design.
- Behavior outside the supplied reachable representation.

The repeated boundary calculations suggest interval selection or positioning intent. That inference does not authorize substituting conventional rounding functions, caching dependency results, filling sentinel values independently, or making return values uniform.
