# F-ec2eab618733

## Purpose

F-ec2eab618733 traverses mutable sequence state, collects length and location entries, conditionally writes three-word output records, and ordinarily passes the collected arrays to F-aeee487fad33. It then writes a four-word trailer and commits a selected sequence cursor.

The visible behavior is not transactional. Cancellation and dependency failures can leave state changes and output records in place. Some exits bypass F-aeee487fad33 but still produce the trailer; the immediate capacity-failure exit does neither.

“Sequence,” “duration,” “interval,” and “source location” are inferred descriptions of field roles. The supplied listing does not establish the external data format or what F-aeee487fad33 does with the collected entries.

## Interface

### Arguments and result

| Argument | Visible contract |
|---|---|
| Context | A 32-bit address representation for an object containing a subordinate-state pointer at byte offset `0x1b8`. |
| Output | Caller-supplied output address. Zero selects result `3`. |
| Capacity | Signed 32-bit value controlling initial budget, capacity comparison, record placement, and trailer placement. |
| Cancellation | Address of a readable byte. Only the exact value `1` is recognized as cancellation. |
| Mode | Signed 32-bit value. Nonzero can select a collection budget of `65536`; it is not preserved as the active-path result. |

The result is a 32-bit integer:

- `3`: Output, the entry subordinate pointer, or that subordinate object’s word at `0x08` is zero.
- `4`: the first collected length plus `28` exceeds Capacity in the visible signed comparison.
- `2`: a direct cancellation branch is taken, or the final cancellation read equals `1`.
- `1`: a checked dependency returns nonzero, unless final cancellation overrides it.
- Otherwise, ordinary completion returns its local termination indicator, `0` or `1`, unless F-aeee487fad33 returns nonzero; that nonzero value replaces the indicator.

These numbers have no established external error names.

### Storage and arithmetic requirements

Active execution requires valid storage for all accessed context fields, subordinate objects, descriptors, arrays, output writes, and cancellation reads. There is no general pointer, alignment, capacity, index, or overflow validation.

Two local arrays each hold `1536` 32-bit entries: collected lengths and locations. Records contain three 32-bit words; the trailer contains four. Descriptors expose these layouts:

| Subordinate offset | Observed descriptor fields |
|---|---|
| `0x0c` | `+0x00`: constant length; `+0x04`: endpoint; `+0x08`: array base index; `+0x0c`: length-array address. |
| `0x10` | `+0x04`: base index; `+0x08`: address of four-byte location entries. |
| `0x14` | `+0x00`: count-like limit; `+0x04`: base index; `+0x08`: address of 12-byte entries. |
| `0x18` | `+0x08`: address of eight-byte entries, each containing a run threshold and signed duration. |
| `0x1c` | A nonzero address enables interval processing; its first word supplies a count-like limit. |

Most arithmetic is 32-bit. Paired additions explicitly propagate low-word carry; duration additions sign-extend a 32-bit duration. Other arithmetic has no visible overflow protection. Acceptance examples below assume representable arithmetic and valid addresses.

## Behavior

### Entry, budget, and initial conversion

A zero Output returns `3` without accessing subordinate state or producing a trailer. Otherwise, the subordinate pointer is captured from Context at `0x1b8`. A zero captured pointer, or zero at its offset `0x08`, also returns `3`.

The budget initially equals Capacity. If Mode is nonzero and Context’s word at `0x48` is nonzero, the budget becomes `65536`. Capacity itself is unchanged.

Initial bookkeeping consists of accounted size `16`, array count zero, record count zero, admitted-length total zero, and ordinary termination indicator zero.

The first record address is Output plus four times the signed quotient of Capacity minus `28`, divided by four. Signed division truncates toward zero; this is not general downward address alignment.

Before reading the sequence cursor, the function calls F-1e0edc6e0bc9 using the captured entry subordinate object:

- The pair at `0x88`/`0x8c` is multiplied by `1000` into two 32-bit argument words.
- The signed divisor at `0x7c` is supplied with its sign extension.
- The returned 32-bit value is retained as the initial converted time.

Only after this call does the function read the cursor at `0x68`, and that read still uses the subordinate pointer captured at entry. Replacing Context’s subordinate pointer during conversion does not redirect this cursor read. Mutating the captured object’s `0x68` can affect it.

Most subsequent state accesses obtain the currently installed subordinate pointer afresh.

### Candidate length and first-length capacity check

A candidate is attempted only while accounted size is below budget and array count is below `1536`, both through signed comparisons.

The current length descriptor is consulted:

- If its first word is nonzero, that word is stored as the array length. A separate subsequent read supplies the working length used for accounting and record decisions.
- Otherwise, cancellation is checked.
- If the cursor exceeds the descriptor endpoint, the stored length becomes `-1`, but the working length remains zero.
- Otherwise, the function obtains the indexed length.

For the indexed case, direct access requires cursor minus one to lie from the descriptor base through base plus `32767`, inclusive. Otherwise F-5e3dde636ee5 is called with Context and cursor minus one. Nonzero selects the checked-failure path; zero leads to a length read through subsequently obtained state.

The indexed length address is the backing array plus four times cursor minus base minus one.

Every candidate reaching the capacity check compares Capacity against the first stored array length plus `28`, not the current candidate’s length. If Capacity is smaller, the function immediately returns `4`. This bypasses F-aeee487fad33, trailer generation, final cursor commitment, and the final cancellation override. Earlier effects are not rolled back.

### Interval admission

Without an interval descriptor, a candidate is admitted and its proposed accounting contribution is working length plus `12`.

With an interval descriptor, an unresolved marker is recognized when both `0xa8` and `0xac` are all ones. While that condition holds, the function:

1. Adds the pair at `0xb8`/`0xbc` to `0x88`/`0x8c`, carrying from the low word.
2. Increments `0xa4`.
3. Calls F-a71330230cfd with Context and the then-current subordinate pointer.

The condition is reread. There is no visible iteration bound or cancellation check within this loop.

Eligibility compares the signed 32-bit word at `0x90`, sign-extended to 64 bits, against the paired interval bounds. Admission requires lower bound `0xa8`/`0xac` inclusive and upper bound `0xb0`/`0xb4` exclusive. The existing high word at `0x94` is not used in this eligibility comparison.

An excluded candidate has zero accounting contribution and zero working length. Its original stored length remains available until later consumption.

### Table checks and fit

The 12-byte-entry cursor at `0x6c` is checked against the descriptor at `0x14`. Direct use requires a cursor at least its base and strictly below base plus `32767`. Otherwise F-cef02eaf8f8c is called with Context.

A nonzero result takes the checked-failure path. This check occurs before the fit decision, including for an excluded candidate.

The proposed accounted size is the existing accounted size plus the candidate contribution. If it exceeds budget, collection stops without the subsequent consumption updates.

If it fits, the location cursor at `0x70` is checked against the descriptor at `0x10`. Direct access requires cursor minus one from base through base plus `16383`, inclusive. Otherwise F-291cabdf1ebc is called with Context and location cursor minus one.

After success or an in-window check, the selected location base is read through current state. Cancellation is then checked again. Next, if the sequence cursor exceeds the length descriptor’s endpoint, ordinary termination indicator `1` is selected without consuming that candidate.

### Consumption and run transitions

For a candidate that continues, the following order is established:

1. Read the current eight-byte entry’s first word using index `0xa0`, and compare it with the old position at `0x84`. If the old position is smaller, increment `0x84`. Otherwise write `1` to `0x84` and increment `0xa0`. Subsequent duration reads use the resulting index, not necessarily the entry used for this comparison.
2. Increment the within-group counter at `0x74`.
3. Compare that counter against the second word of the current 12-byte entry. If the counter is greater, increment location cursor `0x70`. Check its new window, calling F-291cabdf1ebc if necessary with Context and the old location cursor. On success, reload the location base, write zero to `0x78`, then write one to `0x74`.
4. Consider the next 12-byte entry only if `0x6c` is less than the descriptor’s first word minus one. If additionally the next entry’s first word is no greater than `0x70`, increment `0x6c`. Check the new cursor’s window and call F-cef02eaf8f8c if required.
5. Read the signed duration from the second word of the eight-byte entry selected by the resulting `0xa0`. Add it to `0x90`/`0x94` with sign extension and carry.
6. Store the local location entry as the current `0x78` plus the selected location base.
7. Add the original stored candidate length to `0x78`.

Failures during steps 3 or 4 preserve preceding changes.

### Admitted-time snapshot and interval completion

For an admitted candidate, the function next captures:

- The currently installed subordinate pointer.
- That object’s accumulator words at `0x88`/`0x8c`.
- Its divisor at `0x7c` and the divisor’s sign extension.

It calls F-1e0edc6e0bc9 on the scaled captured accumulator and retains the result for a possible record.

After the call, duration is fetched through the retained subordinate pointer, using that object’s then-current `0x18` table pointer and `0xa0` index. The captured accumulator plus that duration is written back through the retained pointer.

Thus the write need not target the subordinate object now installed in Context. It can also overwrite accumulator changes made by the dependency. The duration can differ from the one previously added to `0x90`/`0x94`.

The admitted-length total then increases by the stored candidate length. For an excluded candidate, this conversion and accumulator write are skipped, and its local length entry becomes `-1`.

Interval completion is checked through freshly obtained subordinate state. Unlike eligibility, this comparison uses the full `0x90`/`0x94` pair with unsigned high-word ordering. At or beyond the endpoint:

- Increment `0xa4`.
- Set termination indicator `1` if the interval descriptor’s first word is no greater than the new index.
- Call F-a71330230cfd with Context.

The dependency’s result is ignored.

### Records, counts, and ordinary exit

Only a strictly positive working length emits a record. In order, its words are:

1. Output plus admitted-length total minus working length.
2. Working length.
3. The converted value captured for this admitted candidate.

The record count increases, and the next record address moves backward by `12` bytes. Accounted size becomes the proposed accounted size only when such a record is emitted.

Normally, each consumed iteration increments the array count and selects the successor sequence cursor. Important exceptions are:

- A consumed terminating candidate increments the count before exit only if it emits a positive-length record.
- Exact-budget completion performs an additional count increment and clears the termination indicator.
- If positive-record interval termination and exact-budget completion coincide, both increments occur. The count can therefore exceed the number of initialized entries; at the array limit it can become `1537`.

No deduplication or normalization of these count rules is visible.

Ordinary exit calls F-aeee487fad33 with Context, Output, collected count, local length array, local location array, and Cancellation. Zero preserves the termination indicator; nonzero replaces it.

### Failure cursor selection and finalization

Checked dependency failures select result `1` and bypass F-aeee487fad33. Direct cancellation branches select `2` and also bypass it. The cursor committed during finalization depends on the branch:

| Exit location | Selected sequence cursor |
|---|---|
| F-5e3dde636ee5 failure | Current candidate |
| Initial F-cef02eaf8f8c failure, before fit | Successor |
| Pre-consumption F-291cabdf1ebc failure | Current candidate |
| F-291cabdf1ebc failure after incrementing `0x70` | Successor |
| F-cef02eaf8f8c failure after incrementing `0x6c` | Successor |
| Either direct cancellation branch | Current candidate |

A fit rejection or endpoint stop selects the unconsumed current candidate. Successful consumption ordinarily selects its successor.

The trailer end is Output plus four times Capacity divided by four, with signed truncation toward zero. Writes occur in this order:

| Address relative to trailer end | Value |
|---|---|
| `-4` | Zero |
| `-8` | Record count |
| `-12` | Initial converted time |

The function then obtains current subordinate state and calls F-1e0edc6e0bc9 on its scaled `0x88`/`0x8c` accumulator and sign-extended divisor. Afterward it writes the returned value minus initial converted time at trailer end minus `16`.

Finally, the selected cursor is written to `0x68` through the subordinate pointer installed after that conversion. A final cancellation read equal to `1` overrides the result with `2`.

## Side effects

Visible direct effects include sequence, run, group, location-offset, interval-index, and accumulator updates; backward-growing records; trailer writes; and final cursor commitment.

No rollback is performed. A failure can leave partial current-candidate changes, and immediate result `4` does not undo effects of earlier candidates or dependencies.

Output and Cancellation are caller-supplied storage. No direct allocation or release appears in this function. That does not establish ownership retention, lifetime preservation, or absence of releases by dependencies. Their actual memory effects are unknown.

Local arrays are passed to F-aeee487fad33. The listing does not establish whether it retains their addresses. Any compatible dependency contract must account for their local lifetime.

Aliasing, concurrency, and reentrancy are not validated. Retained pointers and captured values coexist with fresh state reads; dependency mutation therefore cannot be modeled as either universally preserved state or universally refreshed state.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Unavailable output:** Output zero yields `3`, without a trailer or dependency call.

2. **Entry pointer replaced during conversion:** Entry subordinate object A is captured. If the initial conversion installs object B in Context, the subsequent initial cursor still comes from A’s `0x68`; later fresh accesses can use B.

3. **Capacity rejection:** Capacity `100` and first stored length `80` produce result `4` because `100 < 108`. No trailer or final cursor commit follows.

4. **Single exact fit:** With stable state, Capacity and budget `48`, no interval filtering, working and stored length `20`, and no termination event, accounted size reaches `48`. One record begins at Output plus `20`; the trailer occupies offsets `32`–`47`. F-aeee487fad33 receives count `1`. Its zero result and clear cancellation produce `0`.

5. **Conversion overwrites captured state:** An admitted conversion captures object A’s accumulator as `100`. If the dependency changes A’s accumulator to `900`, installs object B, and leaves A’s subsequently selected duration as `7`, the post-call accumulator write targets A with `107`, not A with `907` or B with `107`.

6. **Run boundary:** Old `0x84` equal to the selected run threshold resets `0x84` to one and increments `0xa0`. Later duration reads use the resulting index.

7. **Failure cursor distinction:** Failure of the initial 12-byte-window dependency commits the successor. Failure of the pre-consumption location-window dependency commits the current candidate. Both still take the trailer path.

8. **Excluded candidate:** A consumed excluded candidate advances run, location, and `0x90`/`0x94` state, stores local length `-1`, and emits no record. It skips the admitted accumulator conversion.

9. **Coincident termination and exact fit:** A positive-record candidate that both triggers interval termination and exactly fills budget causes two count increments and clears the ordinary termination indicator.

10. **Cancellation precedence:** Final cancellation byte `1` forces result `2`, including after a nonzero F-aeee487fad33 result. Byte `2` does not trigger the visible cancellation comparisons.
