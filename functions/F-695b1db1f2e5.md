# F-695b1db1f2e5

## Purpose

F-695b1db1f2e5 submits a scaled request to F-eb8708ae5ace and conditionally records the outcome in caller-provided storage.

The dependency receives two existing record values and a third value equal to the request multiplied by decimal 20. A nonzero dependency result authorizes a local update: the record receives the **original request**, followed by the dependency result. A zero result suppresses both local writes.

This is a conditional record-update contract. The evidence does not establish allocation, resizing, successful resource acquisition, or ownership transfer. In particular, “nonzero” describes the update condition, not a proven application-level success condition.

**Inferred intent:** The scale factor and paired record fields are compatible with managing a quantity of 20-byte units. Neither that interpretation nor the meaning of any field is established.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless an example states otherwise, assume defined arithmetic, valid accesses, normal dependency return, values representable in the destination fields, and no dependency mutation of the record.

### Unscaled request retained

For a request of 3, the dependency’s third argument is 60. If its result is 4,096, the resulting request field at offset 16 is 3 and the result field at offset 20 is 4,096.

Under the no-mutation assumption, both destination fields retain their previous values. Without that assumption, unchanged field contents are not required.

### Zero request

A request of zero still causes a dependency call with zero in the third argument position.

### Product boundary

### Dependency mutation
