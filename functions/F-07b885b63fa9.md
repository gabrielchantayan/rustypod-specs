# F-07b885b63fa9

## Purpose

F-07b885b63fa9 operates on a writable handle containing a 32-bit address of header-backed byte storage. Its **inferred intent** is to replace a destination range with a selected source range, reusing destination storage when permitted and otherwise obtaining replacement storage.

The **established behavior** consists of count calculations, diagnostic calls, storage-path selection, conditional transfer-like calls, explicit memory updates, and a packed 64-bit return value. Complete replacement contents are not established: several transfer calls have only two explicit arguments, and their dependency contracts are unavailable.

This contract distinguishes static evidence from inferred purpose and **documented_only** unknowns. No runtime tests have been performed.

## Interface

### Inputs

The function receives seven inputs:

| Input | Width and established use |
|---|---|
| Destination handle | Address of a writable 32-bit cell containing the destination data address. |
| Destination offset | Unsigned 32-bit value used in range calculations, transfer addresses, and the return value. |
| Requested removal count | Unsigned 32-bit bound on effective removal; also used directly in suffix-source address calculations. |
| Source base | Unsigned 32-bit address value used in the reuse predicate and insertion-source address. |
| Source limit | Unsigned 32-bit value from which the source offset is subtracted. |
| Source offset | Unsigned 32-bit value added to the source base and subtracted from the source limit. |
| Requested insertion count | Unsigned 32-bit bound on the insertion count. |

The source limit is not dereferenced. Its interpretation as a source length or extent is inferred from its arithmetic use.

### Destination layout

For a destination data address, the function accesses these fields:

| Relative location | Width | Established role |
|---|---:|---|
| 12 bytes before data | 32 bits | State word tested for reuse eligibility. |
| 8 bytes before data | 32 bits | Capacity compared against the working new length. |
| 4 bytes before data | 32 bits | Current length. |
| Data region | Bytes | Addresses passed to transfer-like dependencies. |
| Data address plus working new length | 8 bits | Explicit zero-byte write on the reuse path. |

The state word is not established to be a reference count or ownership flag. Reuse accepts exactly `0x00000000` and `0xFFFFFFFF`, because adding one modulo \(2^{32}\) must produce an unsigned value below two.

The replacement-storage dependency returns an address treated as 12 bytes before the replacement data. Header and terminator initialization on that path are not locally established.

### Return value

The result is a 64-bit concatenation of two 32-bit words:

- **Low word:** the final address read through the destination handle plus the original destination offset, modulo \(2^{32}\).
- **High word:** normally the destination offset, but replaced by a diagnostic-related value when specified below.

This is not established to be merely a returned pointer. A returning diagnostic can change the high word while leaving the low-word formula unchanged.

### Preconditions and arithmetic

The handle and initially addressed length field must be readable. The initial data address is not checked for zero before the length read. Each subsequent access requires its actual target to be valid and, for writes, writable.

Address calculations, count subtraction, growth sums, threshold subtraction, and length arithmetic have 32-bit modular behavior. Count-selection, threshold, capacity, and source-base comparisons are unsigned. Right shifts used for growth are unsigned.

A suffix count whose high bit is set still satisfies the nonzero transfer condition. There is no separate nonnegative or valid-range check.

These local calculations do not prove that any transfer range is accessible, that storage is physically sufficient, or that dependencies accept the resulting arguments.

## Behavior

### Initial checks and return-high-word selection

The function first reads the destination address through the handle, then reads the length four bytes before that address.

If both of the following hold, the prospective return high word is the destination offset:

- Initial length is at least the destination offset.
- Source limit is at least the source offset.

Otherwise, the prospective high word becomes the unsigned maximum of the initial destination length and source limit. F-5829ec5988c0 is then called with:

- Category 9.
- The same fixed opaque metadata address in two argument positions.
- A numeric argument selected as follows:
  - Destination offset if it exceeds the initial destination length.
  - Source offset otherwise.

When both offsets are invalid, the destination offset takes precedence as the numeric diagnostic argument.

There is no local early return after this call. Whether it returns, throws, terminates execution, or modifies relevant memory is **documented_only**.

### Effective removal and insertion

After the possible category-9 call, the function rereads the destination address and length.

The effective removal count is the unsigned minimum of:

- Requested removal count.
- Reloaded length minus destination offset, modulo \(2^{32}\).

The insertion count is the unsigned minimum of:

- Requested insertion count.
- Source limit minus source offset, modulo \(2^{32}\).

A returning diagnostic does not repair an invalid offset. For example, a source offset greater than the source limit can yield a large wrapped availability value rather than zero.

### Result-size diagnostic

The function again reads the destination address and length. It subtracts the previously determined effective removal count to obtain the retained length used for this check.

The threshold is:

\[
(\texttt{0xFFFFFFF1}-\text{insertion count})\bmod 2^{32}.
\]

If the retained length exceeds this threshold under unsigned comparison:

1. The prospective return high word becomes the threshold, replacing any earlier value.
2. F-5829ec5988c0 is called with category 8, the duplicated fixed opaque metadata address, and the retained length.

If both diagnostic conditions occur and both calls return, category 9 precedes category 8.

This check does not establish a final-length bound of `0xFFFFFFF1`. The threshold subtraction can wrap, and a returning dependency may change the destination state.

### Working lengths

After the diagnostic checks, the function reloads the destination address and its length.

It computes:

- Working retained length: reloaded length minus effective removal, modulo \(2^{32}\).
- Working new length: working retained length plus insertion count, modulo \(2^{32}\).

The effective removal and insertion counts are not recomputed after the category-8 call. Thus, if that call changes the destination state, these counts can reflect earlier observations than the working length does.

### Empty-result path

If the working new length is zero:

1. F-8a5aadac202f receives the destination handle.
2. After that call returns, the function reads a 32-bit value from a fixed global location.
3. It writes that value into the destination handle.
4. It rereads the handle to assemble the return low word.

The global value’s interpretation as an empty-buffer address is **inferred intent**, not an established ownership or representation contract. Its read occurs after the dependency call; it is not a cached pre-call value.

No local header initialization or terminator write occurs on this path. A zero modular result selects it even when the inputs do not describe conventional complete removal.

### Reuse decision

For a nonzero working new length, the suffix count is the working retained length minus the destination offset, modulo \(2^{32}\).

Reuse requires all of the following, evaluated using the cached destination address loaded after the diagnostics:

1. State word plus one, modulo \(2^{32}\), is unsigned-less-than two.
2. Working new length does not exceed the stored capacity.
3. At least one source-base condition holds:
   - Source base is zero.
   - Source base is below the cached destination data address.
   - Source base is at least the modular sum of the cached destination data address and the stored length.

The checks short-circuit. The capacity read follows a successful state test. The endpoint length read is needed only when the state and capacity tests pass and the source base is both nonzero and not below the destination start.

This predicate tests the **source base**, not the selected insertion address or the entire source interval. Passing it does not establish nonoverlap.

For a source base equal to a nonzero destination start, the zero and below-start alternatives fail. The remaining alternative permits reuse when the modular endpoint is less than or equal to that start. Therefore:

- Equal bases with an endpoint strictly above the destination start fail the source-base condition.
- Equal bases with a wrapping endpoint below the destination start pass it.
- A zero source base passes its explicit special case.

State and capacity requirements still apply.

### Reuse operations

When reuse is selected, operations occur in this order:

1. If suffix count is nonzero, call F-external-01 with three explicit arguments:
   - Destination: cached destination start plus destination offset plus insertion count.
   - Source: cached destination start plus destination offset plus **requested removal count**.
   - Count: suffix count.
2. If insertion count is nonzero, call F-external-01 with two explicit arguments:
   - Destination: an address freshly read through the handle plus destination offset.
   - Source: source base plus source offset.
3. Reread the destination address and write the 32-bit working new length four bytes before it.
4. Reread the destination address and write one zero byte at that address plus working new length.
5. Reread the handle for the return low word.

Both suffix-transfer addresses are based on the cached **destination** address. The separate source base is used for insertion.

The suffix-source address uses requested removal, not effective removal. The suffix count nevertheless derives from effective removal.

The function does not explicitly replace the handle on this path. Dependencies are not assumed to preserve it: later address reloads can therefore select storage different from the cached storage used by the suffix call.

### Replacement-storage operations

If reuse is disallowed, the function reloads the current destination address and length for capacity selection.

It calculates:

- Current length plus one-half of that length plus one-eighth of that length, using unsigned right shifts and modular addition.
- Current length plus 128, modulo \(2^{32}\).

Requested capacity is the unsigned maximum of those two wrapped values and the previously calculated working new length. Wrapped growth candidates need not exceed the old length.

Operations then occur in this order:

1. Call F-fe78e25e82ff with the destination handle, requested capacity, and working new length.
2. Treat its returned address plus 12, modulo \(2^{32}\), as the replacement data address.
3. If destination offset is nonzero, call F-external-02 with two explicit arguments:
   - Replacement data address.
   - Destination data address currently read through the handle.
4. If insertion count is nonzero, call F-external-02 with two explicit arguments:
   - Replacement data address plus destination offset.
   - Source base plus source offset.
5. If suffix count is nonzero, call F-external-02 with three explicit arguments:
   - Replacement data address plus destination offset plus insertion count.
   - Destination data address freshly read through the handle plus destination offset plus requested removal count.
   - Suffix count.
6. Call F-8a5aadac202f with the destination handle.
7. Write the replacement data address into the handle.
8. Reread the handle for the return low word.

There is no explicit null-result check after F-fe78e25e82ff. There is no local replacement-header or terminator write.

The old-data addresses used by prefix and suffix calls depend on handle observations after intervening calls. They are not guaranteed to equal the initial destination address. The final handle write uses the replacement address derived from the allocation-like dependency’s return, regardless of any intervening handle changes.

## Side effects

Established local effects include:

- Repeated reads of the destination handle and selected header fields.
- Up to two diagnostic calls.
- Conditional transfer-like calls.
- A 32-bit length write followed by an 8-bit zero write on reuse.
- A post-dependency global read and handle write on the empty path.
- A handle write after transfer calls and F-8a5aadac202f on replacement.

Source base zero does not disable insertion. If insertion count is nonzero, the insertion call still receives source base plus source offset.

Allocation, deallocation, reference-count changes, ownership transfer, and global mutation are dependency-controlled. F-8a5aadac202f has an inferred release-like role, but its name in this contract does not establish that it frees storage or preserves the handle.

No local rollback is visible. If a dependency does not return, later local operations are not reached. Completed dependency side effects and resulting ownership remain unknown.

## Acceptance examples

These are conditional static consequences, not executed tests. Unless stated otherwise, dependencies return without changing relevant state, and all accessed locations are valid.

1. **Ordinary reuse with a suffix.**  
   Destination length is 10, destination offset 3, requested removal 2, source limit 8, source offset 1, and requested insertion 4. If reuse is permitted, the suffix call receives **cached destination start plus 7, cached destination start plus 5, and count 5**. The insertion call follows, using source base plus 1. Local writes set length to 12 and write zero at data offset 12. Return high word is 3.

2. **Clamped removal without suffix transfer.**  
   Destination length is 10, destination offset 8, requested removal 9, and insertion count zero, with valid initial offsets. Effective removal is 2, working new length is 8, and suffix count is zero. No suffix call occurs. The requested-removal address expression involving destination offset 17 is therefore not used for a suffix transfer. On reuse, length becomes 8 and byte 8 becomes zero.

3. **Complete removal.**  
   Destination length is 6, destination offset zero, requested removal 6, and insertion count zero. The empty path calls F-8a5aadac202f, then reads the designated global and installs that value in the handle. No local terminator write occurs.

4. **Equal bases with a nonwrapping endpoint.**  
   Destination start and source base are both `0x00001000`; stored length is 10. The endpoint is `0x0000100A`. For a nonzero working new length, equal bases fail the source-base predicate, so replacement is selected even if state and capacity permit reuse.

5. **Equal bases with a wrapping endpoint.**  
   Destination start and source base are both `0x00001000`; stored length is `0xFFFFFFF0`. The endpoint wraps to `0x00000FF0`, so equal bases pass the source-base predicate. Destination offset zero, requested removal `0xFFFFFFF0`, source limit 1, source offset zero, and requested insertion 1 produce working new length 1 and suffix count zero. With an accepted state and capacity at least 1, reuse is selected. An insertion call precedes the local length and terminator writes. Complete insertion contents remain dependency-controlled.

6. **Invalid source offset with a returning diagnostic.**  
   Initial destination length is 10, destination offset 2, source limit 3, source offset 5, and requested insertion 4. Category 9 receives numeric argument 5; the prospective return high word becomes 10. Source availability wraps to `0xFFFFFFFE`, so insertion count becomes 4, not zero. A subsequent category-8 diagnostic, if triggered, would replace that high word again.

7. **Result-size diagnostic.**  
   Retained length for the check is `0xFFFFFFF0` and insertion count is 2. The threshold is `0xFFFFFFEF`. Category 8 receives `0xFFFFFFF0`, and the return high word becomes `0xFFFFFFEF` if execution reaches return. This does not establish safe allocation or transfer.
