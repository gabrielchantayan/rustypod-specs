# F-93c705790509

## Purpose

F-93c705790509 appends characters from a source region to the end of an existing null-terminated destination string. An integer argument limits the number of non-null source characters appended when that argument is nonnegative.

The function first locates the destination’s existing terminator. It then copies source characters in forward order until either:

- The remaining count is zero, in which case it writes a destination terminator without reading another source character.
- A copied source character is null, in which case that copied character terminates the result.

The count limits appended characters, not total destination size. The function does not receive a destination capacity and does not check available storage.

This is an append operation with bounded copying for nonnegative counts. Negative counts do not provide a meaningful storage bound: they permit copying to continue while the count remains nonzero, subject to the arithmetic uncertainties described below.

## Interface

### Inputs

The function receives three arguments:

1. **Destination pointer.** A character pointer identifying the beginning of an existing null-terminated string. The function scans from this address to find the append position and writes from that position onward.
2. **Source pointer.** A character pointer identifying characters to append. Source characters are read only after the destination scan and only when the remaining count is nonzero.
3. **Count.** A signed integer used as a remaining-character counter. Zero stops copying immediately after the destination scan. Each copied non-null character consumes one count unit.

Both pointer parameters have mutable character-pointer types in the supplied representation. The body contains no writes through the source pointer itself. Source storage may nevertheless be modified if it overlaps the destination write region.

### Output

The function has no return value. Its result is expressed through destination-memory writes.

There is no returned destination pointer, appended-character count, truncation indicator, or error status.

### Widths and units

Characters are transferred one character-sized storage unit at a time. The supplied representation uses a character type, so each transfer occupies one language-level byte. It does not establish the number of bits in that byte or a text encoding. An eight-bit character width is therefore not an unconditional part of this contract.

The count has signed integer type. Its exact width and signed-overflow behavior are not established by the supplied function alone. In particular, a 32-bit counter must not be assumed solely from the function’s identifier or presentation.

Pointer width is also unspecified. Pointer advancement is by one character element, not by one integer-sized element.

Null is the zero-valued character. No other character value receives special treatment.

### Preconditions for a defined, completing operation

The destination must support a readable forward scan through an existing null character, even when the count is zero.

For a nonnegative count, the destination must additionally provide writable storage for every appended character and a final terminator. For disjoint, stable source storage, the number of required writes is one more than the lesser of:

- The count.
- The number of non-null source characters before the first source terminator.

If copying stops because the count is exhausted, the source need only be readable for the copied characters. The function does not require or inspect a source terminator beyond that bounded prefix.

When the initial count is zero, the body performs no source read. A valid destination is still required.

For a negative count, successful completion requires reaching a source null before an invalid memory access or unresolved counter-arithmetic boundary. No finite copy limit follows from the negative argument.

## Behavior

### Destination scan

The first observable memory activity is a forward scan of the destination.

The function reads successive destination characters until it encounters null. It does not inspect source storage during this scan and does not write destination storage before finding that terminator.

This ordering applies to every count value, including zero and negative values. A zero count does not bypass destination validation by access: an unterminated or unreadable destination can fail before the count affects execution.

The address of the first destination null becomes the append position. Under ordinary non-overlapping use, all characters preceding that position remain unchanged.

### Count check and termination

At each append position, the function checks whether the remaining count equals zero before reading a source character.

If the count is zero, it writes null at the current append position and returns. This write occurs even if that location already contains null.

Consequences include:

- With an initial count of zero, the existing destination terminator is written again.
- After exactly the permitted number of non-null characters has been appended, the next destination position receives null.
- The source character immediately beyond an exhausted bound is not read.
- A source terminator beyond the bound is unnecessary for that bounded operation.

The count check tests equality to zero. It is not a test for a positive count. Negative values therefore enter the copying path.

### Character copying

When the remaining count is nonzero, the function reads the current source character and then writes that character at the current destination position.

It checks the copied character for null after the destination write.

If the character is null, the function returns immediately. The copied null is the result’s terminator; there is no additional terminator write after it.

If the character is non-null, the function decreases the remaining count by one and advances both working pointers by one character. It then repeats the count check.

The argument variables themselves are passed by value. Their internal advancement and decrement do not update pointer or integer objects belonging to the caller.

### Nonnegative-count result

For valid, disjoint, stable storage and a nonnegative count:

- The original destination contents precede the appended text.
- The appended text is the source prefix ending at the first null or at the count limit, whichever comes first.
- The resulting destination is null-terminated.
- No destination characters beyond the resulting terminator are intentionally written.

If the source terminates before the count is exhausted, its terminator is read and copied. If the count is exhausted first, the destination terminator is generated without reading the next source position.

This distinction matters for readable-memory requirements and observable access ordering, even where the final strings are identical.

### Negative counts and arithmetic boundaries

An initial negative count is not rejected or converted to zero.

For example, a count of negative one permits a source read and copy. After a non-null character, the count decreases to negative two. A sufficiently short, null-terminated source can therefore be appended despite the negative count.

The supplied representation does not establish the behavior of decrementing the least representable signed integer. Under ordinary signed-language arithmetic, that operation is outside the defined range. A particular machine implementation might instead wrap, but that behavior is not established here.

Accordingly, this contract does not promise that a negative count eventually becomes zero or acts as a large unsigned bound.

### Overlapping storage

The body does not detect overlap and does not take a snapshot of the source.

Its visible ordering is a source-character read followed by a destination-character write for each iteration. Later source reads may therefore observe earlier destination writes if the regions overlap.

The original destination terminator can be overwritten before a later source read reaches it. In that situation, copying need not stop at the source terminator that existed when the function was called.

Finite, bounded overlapping cases can be described from the visible access sequence. General overlap safety, preservation of the original source string, and applicability of this behavior to every underlying language or memory model are not established.

## Side effects

### Memory reads

The function reads:

- Every destination character from the supplied destination address through its first null character.
- One source character for each copying iteration whose starting count is nonzero.

It does not intentionally read source characters after encountering a copied null or after exhausting a nonnegative count.

### Memory writes

The function writes:

- Each character copied from the source, including a source null when encountered.
- A generated null when the remaining count is zero.

For normal non-overlapping use, writes begin at the destination’s original terminator and proceed forward. Existing destination-prefix characters are not rewritten.

Writes are not transactional. There is no rollback path if a later access cannot complete. The supplied function does not establish what execution environment handles an invalid access or which effects remain observable afterward.

- The three source letters and their null terminator are copied.
- The resulting destination text is “catnip”.
- No additional destination terminator is written after the copied null.

- The result is “catni”.
- The source characters “n” and “i” are read.
- The next source character, “p”, is not read.

The source need not contain a readable terminator beyond those two readable characters for this operation to complete.

### Zero count

Given destination text “cat” and count zero:

- The destination is scanned through its terminator.
- That terminator is written again.
- No source character is read.
- The resulting destination text remains “cat”.

This remains a destination-memory operation, not an access-free no-op.

### Empty source

- The first source character read is null.
- That null is written over the destination’s existing terminator.
- The resulting text remains “cat”.
- No non-null character is appended.

### Empty destination

- The visible sequence copies “B”, then “C”, then the source null.

### Source and destination begin at the same address

- The first two copied characters are “a” and “b”.
- The third source read reaches the location where the first appended “a” has replaced the original null.

This requires room for six character units and does not imply unrestricted overlap safety.

### Missing destination terminator
