# F-6954a6427152

## Purpose

F-6954a6427152 specifies an indefinitely repeating sequence of indirect calls, memory accesses, arithmetic transformations, and a software breakpoint. The supplied representation contains no normal return path.

The established behavior is an ordered manipulation of externally supplied state. It does not establish a recognizable application-level operation. An initialization or state-processing purpose is plausible but **documented_only**, not an acceptance requirement.

The contract distinguishes:

- **Established static evidence:** visible call-target relationships, call order, access widths, arithmetic, stores, and control flow.
- **Inferred intent:** possible application meanings that are not required behavior.
- **Unknowns:** dependency semantics, execution conventions, and reconstruction ambiguities not resolved by the supplied representation.

All continuation statements are conditional on earlier calls returning, memory accesses completing, and breakpoint execution resuming. No runtime tests have been performed.

### 1. Initial calls and small-field stores

Each iteration establishes a zero byte and invokes:

1. **D-01**, with two explicit zero arguments.
2. **D-02**, with no explicit arguments shown.
3. **D-03**, with no explicit arguments shown.

The zero byte used in the later D-06 argument calculation is established after D-01 and before D-02.

After D-03, the function reads the first external address-bearing word and captures it as **A**. It then invokes:

4. **D-04**.
5. **D-05**, consuming a paired result.
6. **D-06**, with two explicit word arguments: the low word of the D-05 result, and the sum of its high word, low word, and the zero-valued byte term.

D-05 and D-06 have equal numerical targets despite these different visible argument and result uses. The second argument’s signed addition semantics are not independently established if overflow occurs.

After D-06, a byte from its secondary result channel is written at `A + 0x11`.

The function calls **D-07**, then writes a zero byte at `A + 0x15`.

**D-08** supplies a halfword result and a secondary address-bearing result. The halfword is written at offset `0x0c` from that secondary address.

The first external address is not visibly reloaded for the two A-relative stores. Dependencies may change the external storage or addressed memory, but these stores use the captured address.

### 2. Paired-result extraction and frame-relative accesses

**D-09** supplies a paired result. Let **T** be its low word and **P** its high word.

The ordered operations are:

1. Write a zero halfword at `P + 0x2c`.
2. Write the unsigned value `T shifted right by 26` as a word at `B + 0x26c`.
3. Call **D-10**.
4. Read an address-bearing word at `B + 0x320`; capture it as **C**.
5. Call **D-11**.
6. Call **D-12**.
7. Write `T shifted left by 2`, retaining 32 bits, at `C + 0x54`.

The right-shifted value is between 0 and 63 inclusive. The later left shift uses T itself, not the six-bit extraction.

The function next calls **D-13**, **D-14**, **D-15**, **D-16**, and **D-17**, in that order. No explicit arguments or consumed primary results are shown for these sites.

D-13 has the same numerical target as D-09. Its result is not visibly substituted for the captured D-09 result.

### 3. Fixed-base read, breakpoint, and halfword stores

The function reads an unsigned halfword at `K + 0x34`; call its zero-extended value **U**.

It then:

1. Calls **D-18**.
2. Reads a word at `B + 0x280`.
3. Passes that word as the explicit argument to **D-19**.
4. Executes a software breakpoint with immediate value `0x92`.

The breakpoint is an observable control event. Nothing after it is guaranteed to execute unless execution resumes.

After resumption, the D-19 word result is shifted left by two to form a scaled offset. Because this is represented as a signed shift, overflow-sensitive behavior remains unresolved.

The function establishes J and reads an address-bearing word at `U + 0x44`; capture that word as **Q**. U is the zero-extended halfword itself. K is not added back to U.

Next:

1. Call **D-20**.
2. Call **D-21**, capturing its word result.
3. Read a word at `U + 4`.
4. Call **D-22** with the D-21 result and that memory word.

After D-22, the function reads the second external address-bearing word; call it **R**. It calls **D-23**, then writes the low 16 bits of R at the address formed by adding R to the scaled D-19 result.

It calls **D-24**, whose numerical target equals D-17’s, and then reads a word at `J + 0x54`, numerically `0x2218`. Capture that word as **S**.

**D-25** returns an address-bearing word. The function writes the halfword `0x21c4` at offset `4` from that returned address.

Both halfword stores truncate their sources. In particular, the R-derived store does not write a complete 32-bit address-bearing value.

### 4. Final paired result and frame-base adjustment

The function calls **D-26** and **D-27**, then reads an unsigned halfword at `S + 0x34`. Let its zero-extended value be **V**.

**D-28** supplies a paired result. Let **X** be its low word and **Y** its high word.

The ordered operations are:

1. Write X as a word at `B + 0x258`.
2. Read an unsigned halfword at `Y + 0x14`; call its zero-extended value **W**.
3. Form X shifted left by six.
4. Form Y multiplied by four.
5. Change the represented frame-like base from B to `B − 0xf4`.
6. Form `4 × V`.
7. Write X as a word at `(4 × V) + 0x74`.

The X shift and Y multiplication use signed intermediates in the supplied representation. Their overflow behavior is unresolved. In contrast, V is an unsigned, zero-extended halfword; `4 × V` fits in 32 bits.

The store at `B + 0x258` precedes the base adjustment and uses the old base.

The adjustment is explicit static evidence. Whether it describes a persistent machine-state change, a frame reconstruction artifact, or another execution convention is **documented_only**. Under the literal persistent-base interpretation, subsequent iterations use the adjusted base.

### 5. Final updates and repetition

The remaining order is:

1. Call **D-29**.
2. Write W as a 32-bit word at `Q + 0x54`.
3. Call **D-30**.
4. Write W as a 32-bit word at `Q + 0x64`.
5. Call **D-31**.
6. Write the low 16 bits of Q at the address formed from X shifted left six bits plus D-31’s secondary address-bearing result.
7. Call **D-32**.
8. Call **D-33**.
9. Read a byte at `V + (4 × V)`, exactly `5 × V`.
10. Call **D-34**.
11. Write the captured byte at `W + G + 0x19`.
12. Call **D-35**.
13. Write the scaled value `4 × Y` as a word at `Q + 0x44`.
14. Call **D-36**.
15. Read a word at `(4 × Y) + 0x44`.
16. Pass that word to **D-37**.
17. Repeat if D-37 returns.

D-31 has the same numerical target as D-19. Here, its secondary address-bearing result is consumed; no primary result is visibly used.

D-32 has the same numerical target as D-25. No result from D-32 is visibly consumed.

W is zero-extended, so both W stores write a 32-bit value between 0 and 65535. V is also at most 65535; `5 × V` is at most 327675 and does not overflow a 32-bit unsigned quantity.

D-34 separates the byte read from the byte write. The write uses the captured byte, not a new source read.

Immediately before D-37, the represented link-related state is assigned a fixed value. Consequently, the next iteration’s D-01 target calculation uses that fixed represented state rather than the unspecified entry value. The first and later D-01 invocations are not required to have equal numerical targets.

## Side effects

### Direct memory effects

An iteration reaching every direct store performs exactly:

- **Three byte writes:** `A + 0x11`, `A + 0x15`, and `W + G + 0x19`.
- **Five halfword writes:** D-08’s secondary address plus `0x0c`; `P + 0x2c`; R plus the scaled D-19 result; D-25’s result plus `4`; and the address derived from shifted X plus D-31’s secondary result.
- **Seven word writes:** `B + 0x26c`, `C + 0x54`, `B + 0x258`, `(4 × V) + 0x74`, `Q + 0x54`, `Q + 0x64`, and `Q + 0x44`.

These are counts of visible write operations, not necessarily distinct addresses. Aliasing may cause overlap. Dependency-internal writes are unknown and do not add to the direct count.

The operations are not a transaction. Calls and the breakpoint separate stores; no rollback, locking, or cleanup path is visible.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Unsigned extraction and shift.** If T is `0xfc000003`, the word written at `B + 0x26c` is 63. The unsigned 32-bit left shift written at `C + 0x54` is `0xf000000c`.

2. **Unsigned halfword address input.** If U is `0xffff`, the Q read occurs at numerical address `0x10043`. Treating U as signed −1, or adding K back to U, would contradict the visible calculation.

3. **Truncated R store.** If R is `0x12345678`, its halfword store writes `0x5678`. Its destination still uses the full captured R plus the scaled D-19 result, subject to the unresolved arithmetic model.

4. **Full-width W stores.** If W is `0xffff`, the stores at `Q + 0x54` and `Q + 0x64` each write the 32-bit value `0x0000ffff`, not a sign-extended word or a halfword.

5. **Capture across a dependency.** If the byte read at `5 × V` is `0xa6` and D-34 changes that source byte to `0x19`, the later byte store still uses `0xa6`, provided the represented captured-value dataflow remains valid.

6. **Breakpoint boundary.** If execution terminates at the breakpoint, the earlier stores may already have occurred, but none of the subsequent stores occurs during that iteration.

7. **Equal targets with different uses.** A target trace consistent with the supplied arithmetic must show D-05 and D-06 reaching the same numerical target. Different visible arguments do not justify assigning different targets. The same equality requirement applies to the other four established pairs.

8. **Direct-write accounting.** If every store is reached, the visible trace contains seven word-write operations even if dependencies perform additional writes or multiple direct writes alias.

9. **Conditional repeated base adjustment.** Under the literal persistent-base interpretation, the next iteration starts with base `B − 0xf4`. This example does not resolve whether that interpretation matches actual machine execution.
