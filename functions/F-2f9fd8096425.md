The supplied representation supports a contract for operation order, argument construction, memory-write widths, and result extraction. It does not establish a higher-level purpose such as initialization, reset, device control, or memory management.

This document distinguishes:

- **Conditional interpretation:** numerical behavior under a 32-bit machine-address interpretation, assuming accesses complete and dependencies return.
- **documented_only unknowns:** details not established by the representation.

## Behavior

### Widths and arithmetic interpretation

The address and argument calculations involve represented 32-bit quantities. For the numerical formulas and examples below, **32-bit machine interpretation** means retaining the low 32 bits after arithmetic that exceeds that width and using logical right shifts where the representation explicitly uses unsigned values.

This interpretation describes bit-level behavior conditionally. It is not a claim that signed overflowing additions, signed left shifts, or pointer conversions have portable source-language semantics.

A 16-bit store writes two bytes; a 32-bit store writes four bytes. Byte order, alignment requirements, atomicity, and memory-access attributes are not established.

Duplicate stores remain separate represented operations. Their presence must not be reduced to a single final-memory-state requirement.

### 1. Entry-derived writes

Before the first visible call, the sequence performs these writes in order:

1. Extract the low 16 bits of the entry pointer and write that value at the entry pointer.
2. Write the same 16-bit value at the same address again.
3. Write the same 16-bit value at the address obtained by multiplying the entry pointer’s 32-bit address value by two.
4. Write the 32-bit store payload at the store base plus 20 bytes.

The doubled address is a numerical transformation of the pointer value. It is not evidence of array indexing, a related allocation, or a valid second object.

The payload for the three 16-bit writes is derived from the pointer value, not loaded from the pointed-to memory. No explicit memory load is shown for these operations.

### 2. F-D01

The first call uses a target formed from the link value plus 4,094, or 0x0FFE.

Its three visible arguments, in order, are:

1. The entry pointer’s 32-bit value shifted left by five positions.
2. The second explicit input, unchanged.
3. The sum of the entry pointer’s 32-bit value and the link value.

Under the conditional 32-bit interpretation, the first and third arguments retain their low 32 bits.

No result from F-D01 is explicitly consumed. Its identity, execution mode, memory effects, state preservation, and ownership behavior are unknown.

### 3. F-D02 and the first result-derived writes

After F-D01 returns, F-D02 is invoked with no explicit arguments shown.

Its target is formed from **0x08910353 plus 4,094**, or 0x0FFE. The fixed base is established; uncertainty about target interpretation does not make that constant unknown.

For F-D02’s represented 64-bit result, distinguish its low and high 32-bit halves.

The first derived address is obtained by masking the low half with 0x07FFFFFF and then shifting right by three. It therefore lies between zero and 0x00FFFFFF inclusive.

The first derived 16-bit payload is obtained by:

- Shifting the low 32-bit half left by five, retaining 32 bits.
- Logically shifting that 32-bit quantity right by eight.
- Retaining the low 16 bits.

Under these widths, this payload equals the low 16 bits of the first derived address. Equivalently, it consists of result bits 3 through 18.

The sequence then performs, in order:

1. A 16-bit write of the first derived payload at the first derived address.
2. An identical second 16-bit write there.
3. An assignment of zero to the zeroed location.
4. A 32-bit write of the store payload at the store base plus 20 bytes.

The zero assignment’s storage width is not supplied. It must not be assumed to be 8, 16, 32, or 64 bits.

The repeated 32-bit write uses the same represented base and payload as the earlier write. This does not imply that the destination retained its contents across the intervening calls or that those calls preserve arbitrary machine state.

### 5. F-D04 and the second result-derived writes

Its target is formed from **0x089103BB plus 4,094**, or 0x0FFE.

For F-D04’s represented 64-bit result:

- The second derived 16-bit payload is obtained by shifting the **entire represented 64-bit result** logically right by eight, then retaining the low 16 bits.
