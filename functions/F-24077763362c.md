# F-24077763362c

## Purpose

F-24077763362c conditionally obtains a 32-bit value from one of two dependencies, records that value and an associated unsigned 32-bit quantity in a caller-supplied object, and returns the object’s recorded value.

The decision depends on the object’s quantity field:

- If the recorded quantity is zero, invoke F-638beded7699, including when the requested quantity is also zero.
- If the recorded quantity is nonzero and the request is greater than it under unsigned comparison, invoke F-e74413f3255f.
- Otherwise, return the recorded value without invoking either dependency or explicitly updating either field.

**Inferred intent:** the two fields may describe a storage address and its capacity, with the dependencies providing initial allocation and growth. Neither the field meanings nor the dependencies’ allocation semantics are established by the supplied evidence. The behavioral contract therefore uses **recorded value** and **recorded quantity**, rather than assuming a buffer-management API.

## Interface

### Inputs

The function takes two inputs:

1. **Object location.** An address-like input identifying an object containing the fields described below. The source represents this input as an integer used for address calculations. A complete object type, address-space model, and object extent are not provided.
2. **Requested quantity.** An unsigned 32-bit integer, with representable values from 0 through 4,294,967,295.

The object fields accessed directly by this function are:

| Offset from object location | Width | Role in this contract |
|---|---:|---|
| `0x94` | 32 bits | Recorded value, returned to the caller and passed to F-e74413f3255f on its branch |
| `0x98` | 32 bits | Recorded quantity, read as unsigned for branch selection and replaced after a dependency returns |

The fields occupy adjacent, non-overlapping four-byte regions. The supplied evidence does not establish the layout or meaning of any other object contents.

### Output

The function returns the 32-bit contents of the recorded-value field, read at the function’s return point.

On either dependency branch, the dependency’s 32-bit result is written into that field before the return read. On the branch that invokes no dependency, the function simply returns the field’s contents without validating them.

The result is an opaque 32-bit value. Its interpretation as an address, handle, status, or another representation is not established.

### Preconditions

For normal completion:

- The object location must permit the required 32-bit field reads.
- On either dependency branch, both fields must permit 32-bit writes.
- The object and its field storage must remain valid through the final return read, including across any dependency call.
- Any additional requirements imposed by the selected dependency must hold.

Alignment requirements, address-calculation overflow behavior, and invalid-memory behavior are not established. There is no visible object-location validation.

## Behavior

### Branch selection

The function first reads the unsigned recorded quantity at offset `0x98`.

**When this first read yields zero**, the function invokes F-638beded7699 with two arguments, in this order:

1. The requested quantity.
2. Zero.

There is no comparison between the request and a nonzero threshold on this branch. A zero request still causes the call.

**When the first read yields a nonzero value**, the function reads the recorded quantity again and compares the request against that second value using unsigned 32-bit ordering:

- If the request is less than or equal to the second value, neither dependency is invoked.
- If the request is greater than the second value, the function invokes F-e74413f3255f.

The two quantity reads are distinct accesses in the supplied representation. For a stable object they observe the same value. The evidence does not provide synchronization or a guarantee that separately observed values remain equal.

### F-e74413f3255f branch

For a request greater than the quantity observed by the comparison, the function reads the recorded-value field and supplies four arguments to F-e74413f3255f:

1. The 32-bit recorded value.
2. The requested quantity.
3. Zero.
4. One.

The existing recorded value is passed without a visible validity check. In particular, a zero recorded value does not prevent this call if the quantity-based branch condition selects it.

The quantity field, not the recorded-value field, controls which dependency is selected. A nonzero recorded value with a zero quantity selects F-638beded7699, not F-e74413f3255f.

### Completion after either dependency returns

If the selected dependency returns normally, the function performs these explicit object accesses in order:

1. Write the dependency’s 32-bit result to the recorded-value field at offset `0x94`.
2. Write the requested quantity to the recorded-quantity field at offset `0x98`.
3. Read the recorded-value field at offset `0x94` and return that read value.

The requested quantity is stored exactly as supplied. The function does not independently verify that the dependency result represents a resource of that size.

The return is expressed as a field read, rather than merely forwarding the dependency result. With valid, stable ordinary memory and no intervening modification, the returned bits equal the dependency’s result. That equality must not be generalized to unsupported concurrent or externally mutable storage.

### Completion without a dependency call

If the first quantity read is nonzero and the request is no greater than the quantity observed by the comparison:

- Neither dependency is called.
- The function performs no explicit write to either object field.
- The function reads and returns the recorded value.

For stable fields, this means that equal or smaller requests preserve the stored quantity. A zero request does not reset a nonzero quantity and does not visibly release anything.

### Widths and arithmetic

The requested and recorded quantities are compared as unsigned 32-bit values. Consequently, values with the high bit set are not treated as negative.

There is no visible quantity increment, multiplication, rounding, or growth-factor calculation. On an update branch, the new recorded quantity is exactly the request—not a derived capacity.

The only visible address calculations locate the two object fields at fixed offsets. The evidence does not define the behavior of invalid or overflowing address calculations.

## Side effects

### Direct effects

The function directly reads the two identified fields and, on a dependency branch that returns normally, writes both fields.

The write ordering is significant: the recorded value is replaced before the recorded quantity. There is no visible atomic pair update, rollback mechanism, or synchronization. The contract does not promise that an observer can see only the old pair or the new pair.

On the branch that calls no dependency, this function itself makes no explicit object writes.

### Dependency-mediated effects

Both dependencies are opaque. Their effects on memory, global state, resources, callbacks, or the supplied object are unknown.

The contract does not assume that a dependency:

- Preserves either object field.
- Preserves unrelated memory or global state.
- Allocates, resizes, copies, or frees storage.
- Retains or relinquishes ownership of the old recorded value.
- Returns a usable resource.
- Returns normally.

If a dependency changes the two fields and then returns normally while the object remains valid, this function subsequently overwrites those fields in the stated order.

### Errors and ownership

No explicit dependency-error test is visible. In particular, if a dependency returns a zero 32-bit value normally, the function still stores zero in the recorded-value field and stores the requested quantity in the quantity field.

There is no separate status result, visible retry, or restoration of the previous field values.

No direct release operation is visible in this function. Resource ownership and lifetime cannot be inferred from the replacement of the recorded value. Whether an old resource survives replacement, is consumed by a dependency, or requires another operation is **documented_only**.

If a dependency does not return normally, the subsequent field writes and return read are not reached along the shown control flow. Resulting error propagation and any partial dependency side effects are unknown.

## Acceptance examples

These examples are conditional specifications, not executed tests. Unless stated otherwise, assume valid, stable object storage, no concurrent modification, normal dependency return, and no dependency side effects that invalidate the object.

1. **Zero recorded quantity, positive request.**  
   Given recorded quantity 0 and request 64, invoke F-638beded7699 with arguments 64 and 0. If it returns value V, store V, then store quantity 64, then return V. The preexisting recorded value does not select the branch.

2. **Zero recorded quantity, zero request.**  
   Given recorded quantity 0 and request 0, invoke F-638beded7699 with arguments 0 and 0. If it returns V, record V and quantity 0, then return V. A subsequent call still encounters a zero recorded quantity and therefore again selects F-638beded7699, assuming no intervening change.

3. **Equal request.**  
   Given recorded quantity 64, recorded value V, and request 64, invoke neither dependency, write neither field, and return V.

4. **Smaller request, including zero.**  
   Given recorded quantity 64 and recorded value V, a request of 8 or 0 invokes neither dependency. The recorded quantity remains 64, and the function returns V.

5. **Larger request.**  
   Given recorded quantity 64, recorded value V, and request 65, invoke F-e74413f3255f with V, 65, 0, and 1. If it returns W, store W before storing quantity 65, then return W.

6. **Unsigned boundary.**  
   Given recorded quantity 2,147,483,647 and request 2,147,483,648, select F-e74413f3255f. Reversing those two quantities selects the no-dependency branch. Signed comparison would not satisfy this contract.

7. **Maximum recorded quantity.**  
   Given stable recorded quantity 4,294,967,295, every representable request selects the no-dependency branch. No larger unsigned 32-bit request exists.

8. **Zero dependency result.**  
   Given recorded quantity 4 and request 9, if F-e74413f3255f returns zero normally, record value zero and quantity 9, then return zero. A subsequent stable-state request of 9 invokes neither dependency and returns zero; this function does not repair or reject that state.

9. **Zero recorded value with nonzero quantity.**  
   Given recorded value zero, quantity 4, and request 5, invoke F-e74413f3255f with zero as its first argument. Do not substitute F-638beded7699 based on the recorded value.
