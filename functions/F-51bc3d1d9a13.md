# F-51bc3d1d9a13

The supplied representation establishes several conditional behaviors:

- Four zero-byte stores at offsets initialized to 15–12, in descending order.

It does not establish a complete input-to-output transformation for any concrete argument tuple. Global contents are unavailable, and those contents determine dispatch, arithmetic, progression, and termination.

### Four-byte field operation

When selected, this operation samples a global transformation factor once, narrowing it to one byte before any of its four stores.

It then performs four one-byte stores in this order:

1. At the current field base plus the offset initialized to 8.
2. At that base plus the offset initialized to 9.
3. At that base plus the offset initialized to 10.
4. At that base plus the offset initialized to 11.

The first three stored bytes use bits 24–31, 16–23, and 8–15 of the retained field quantity, respectively. Each selected byte is multiplied by the sampled factor and by −99, with only the low eight bits stored.

The fourth stored byte is the low byte of a separate unsigned working quantity multiplied by −99. It does not directly extract bits 0–7 from the field quantity. Another operation can set this working quantity from the first scaled quantity multiplied by 161, but other operations can overwrite it.

For stored-byte purposes, multiplication by −99 is multiplication by 157 modulo 256. Signed versus unsigned interpretation of the narrowed byte operands does not change these low-eight-bit results.

Only after all four stores does the operation read its next-state global. Consequently:

- A store overlapping the transformation-factor global does not change the factor already sampled for this group.
- A store overlapping the next-state global can affect the state read after the group.
- Neither effect requires concurrent activity.

The operation cannot unconditionally be described as writing an ordinary big-endian integer.
