# F-7932dc6d89c6

## Purpose

The supplied static representation describes a routine that invokes a computed execution target and then selects one of two paths using an overflow-condition value:

- A zero condition leads to a one-byte memory read and a second computed invocation.
- A nonzero condition leads to two software interrupts, a global-value read, a status-byte read, and a four-byte write, followed by a loop or an unresolved instruction boundary.

No application-level purpose is established. The material does not establish that this is a valid callable API, a complete function, or an accurately recovered instruction stream.

### Zero-condition path

If the tested condition is zero:

1. The primary input word is logically shifted right by two.
2. One byte is read at the address equal to that shifted value plus one.
3. **F-DYN-02** is invoked at the internal execution anchor plus 0x82 bytes.

The represented arguments are:

| Position | Payload |
|---|---|
| First | The byte read from the derived address |
| Second | The opaque four-byte secondary output associated with F-DYN-01 |
| Third | The primary input word shifted right by two |

The byte-read address ranges from 1 through 0x40000000. This address calculation does not wrap within the represented 32-bit unsigned domain. No accessibility check or alignment adjustment precedes the read.

The read precedes F-DYN-02. No observable ordering among preparation of its other arguments is established.

If F-DYN-02 returns, this path reaches an unresolved invalid-instruction boundary. It does not proceed to the two software interrupts, the global address-base read, the status-byte read, or the four-byte write.

### Nonzero-condition path: interrupts and arithmetic

If the tested condition is nonzero, the routine issues:

1. **F-SVC-01**, software interrupt immediate 0xB6.
2. **F-SVC-02**, software interrupt immediate 0xD2.

Each later operation requires continuation from the preceding invocation. Their service meanings, arguments, results, privilege requirements, and state changes are unknown.

After both interrupts, the representation derives:

- The primary input word shifted right by two, then increased by seven.
- A signed 32-bit overflow indication for adding 0xC6 to the secondary input word shifted right by eleven.

The primary-derived sum ranges from 7 through 0x40000006 and cannot wrap as a 32-bit unsigned value.

The shifted secondary value ranges from 0 through 0x001FFFFF. Adding 0xC6 yields at most 0x002000C5, below the maximum signed 32-bit value. Consequently, the represented signed-overflow indication is false for every possible 32-bit secondary input.

These arithmetic relationships describe the recovered values. They do not independently establish how entry registers survive the preceding external invocations.

### Global read and status-byte read

After both interrupts and before the conditional overflow branch, the routine:

1. Reads the address-base value from its global storage location.
2. Uses that value to form an address at offset 0x18.
3. Reads one status byte from the resulting address.

The global read and the status-byte read are separate memory operations. A readable status address alone is insufficient: accessing the global storage must also succeed.

The value used is the global’s value when this read occurs, not a guaranteed entry-time snapshot. F-DYN-01, F-SVC-01, and F-SVC-02 may change that global before it is read. No preservation assumption is permitted.

The excerpt does not establish the global storage width, the base value’s precise type, or the address arithmetic’s overflow rules. Offset 0x18 is established; unrestricted address arithmetic is not.

### Write-address conversion

Before writing, the stack-related base undergoes these represented conversions and operations:

- Conversion to signed `int`.
- Addition of 0x180 to that integer.
- Conversion of the sum to a pointer used for a four-byte unsigned-word access.

The surrounding model uses 32-bit words. Interpreting its `int` as signed 32-bit is consistent with that model, but the excerpt does not independently supply the target ABI or complete conversion rules.

Under a signed 32-bit interpretation:

- The base-to-integer conversion may lose information or lack a portable result when the base is not representable.
- For a successfully converted integer, adding 0x180 is representable only when that integer is at most 0x7FFFFE7F. Adding this positive offset cannot cause signed underflow.
- A signed addition outside that range must not be assigned unsigned wraparound semantics without additional evidence.
- Converting the resulting integer to a pointer does not establish that the pointer is valid, aligned, writable, or equivalent to ordinary pointer arithmetic on the original base.

Accordingly, write-location examples require a defined base conversion, representable addition under the applicable integer model, and a usable resulting pointer. The representation does not establish the behavior when those prerequisites fail.

### Four-byte write and subsequent control flow

The routine logically shifts the primary-derived sum right by 23 bits and writes the result as a 32-bit unsigned word through the constructed pointer.

The stored value ranges from 0 through 128:

- Primary inputs from 0 through 0x01FFFFE3 produce zero.
- Primary inputs from 0x01FFFFE4 through 0xFFFFFFFF produce a nonzero value.
- Primary input 0xFFFFFFFF produces 128.

The upper 24 bits of every stored value are zero. Byte order is unresolved.

The write follows the status-byte read and precedes the zero/nonzero selection on the shifted value.

If the shifted value is zero, the recovered control flow loops while the overflow indication is false. That indication is always false under the represented arithmetic, so this path is unbounded in the recovered model. No repeated memory read, write, call, or interrupt is represented inside the loop.

If the shifted value is nonzero, the routine tests the retained status byte. Both zero and nonzero status values lead to unresolved invalid-instruction boundaries. No successful completion or distinct error result is established.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **First target calculation.**  
   An incoming address word of 0x1003 produces target 0x12B0. An incoming word of 0xFFFFFFFC produces 0x000002AC under 32-bit unsigned wrapping. Neither address is thereby established as executable.

2. **Zero-condition arguments.**  
   With a zero condition and primary value 0x20, the shifted value is 8. If F-DYN-01 returns and address 9 is readable, the routine reads one byte there and passes its payload to F-DYN-02, followed by the opaque secondary output and two arguments equal to 8.

3. **Global mutation before observation.**  
   Suppose the global contains one address base at entry, but F-SVC-02 replaces it with another before returning. If the nonzero path continues normally, the status-byte address is derived from the replacement value read after F-SVC-02, not the entry value.

4. **Separate read failures.**  
   If the global storage cannot be read, the represented status-byte read has not yet occurred. If the global read succeeds but the resulting address plus 0x18 is inaccessible, the status-byte read cannot complete and the later write is not reached through normal continuation.

5. **Last zero-result primary value.**  
   Primary value 0x01FFFFE3 produces intermediate value 0x007FFFFF. Given a nonzero condition, continuing dependencies, successful reads, and a valid write-address conversion, the routine writes zero and enters the represented unbounded loop.

6. **First nonzero result.**  
   Primary value 0x01FFFFE4 produces intermediate value 0x00800000. Under the same prerequisites, it writes 1, then reaches an unresolved boundary for either retained status-byte value.

7. **Maximum inputs.**  
   Primary value 0xFFFFFFFF produces intermediate value 0x40000006 and stored value 128. Secondary value 0xFFFFFFFF produces shifted value 0x001FFFFF; adding 0xC6 does not cause signed 32-bit overflow. The stack-redirection branch remains unselected.

8. **Integer-address boundary.**  
   If the base converts to signed 32-bit value 0x7FFFFE7F, adding 0x180 yields 0x7FFFFFFF without signed overflow; pointer validity remains unresolved. If it converts to 0x7FFFFE80, the sum exceeds the signed 32-bit range. This contract does not replace that case with a guaranteed wrapping address or successful write.
