## Behavior

### Initial update and callback

The first observable memory operation is a byte write of zero to offset `0xA5`. It occurs before the optional callback and before the mode test.

The function then reads the 32-bit value at offset `0x94`.

- If that value is zero, it skips the callback.
- If it is nonzero, it uses that value as the callback-object pointer and resolves an indirect target through the object’s dispatch table at offset `0x68`.

The callback receives two arguments:

1. The callback-object pointer obtained from offset `0x94`.
2. The 32-bit value read from offset `0x4C`.

The value at `0x4C` is forwarded without an explicit interpretation as an integer, pointer, handle, or other application value. The source does not establish the relative evaluation order of the callback-target lookup and the second-argument read. Both are needed for the call.

No callback return value is used. The function does not recheck the pointer at `0x94` or repeat the callback, even if the callback changes that field.

The callback precedes all mode-dependent operations. Consequently, the mode test observes the value present after the callback returns, not necessarily the value present on entry.

### Mode selection

The function reads the byte at offset `0x90` and compares it with exactly 1.

If the byte is any other value, the function performs no direct accesses to the six entries and makes no calls to F-0892220f5e23. It also makes no direct writes to offsets `0xA2`, `0x9E`, or `0x98`. It returns zero.

If the byte equals 1, the function proceeds in this order:

1. Writes the byte value 1 to offset `0xA2`.
2. Establishes a local “nonzero dependency result observed” condition, initially false.
3. Writes the byte value 1 to offset `0x9E`.
4. Examines the six entries.

The two byte writes are distinct and ordered: `0xA2` precedes `0x9E`, and both precede the first entry read.

The mode byte is not checked again during the scan. A later dependency-induced mode change does not, by itself, terminate or disable an already-entered scan.

### Six-entry scan

The six entries are visited in ascending address order, from offset `0x00` through offset `0x14`, at four-byte intervals.

For each entry:

- Its 32-bit value is read when that entry is visited.
- If the value is zero, no dependency call is made for that entry.
- If the value is nonzero, F-0892220f5e23 is called with no explicit arguments.
- Any nonzero 32-bit return from that call establishes the local “observed” condition.

The entry value is not passed as an explicit argument. Its visible role is solely to decide whether a call occurs.

All six entries are considered if execution continues normally. A nonzero dependency result does not end the scan, and later zero results do not clear the local condition. Depending on the values observed during the scan, the function makes between zero and six calls to F-0892220f5e23.

Entry reads are not a snapshot taken before the calls. An earlier call may change a later entry, affecting whether that later entry causes another call. An already visited entry is not revisited.

The scan uses six bounded positions. The index progression and four-byte spacing introduce no counter overflow within that range. Validity of the resulting addresses remains a precondition; there are no address-wrap checks.

### Result update and return

After the scan:

- If at least one F-0892220f5e23 invocation returned nonzero, the function writes byte value 1 to offset `0x98`.
- Otherwise, it makes no direct write to offset `0x98`.

In particular, this function never directly clears `0x98`. A preexisting nonzero value may survive a scan with no qualifying result, provided the dependencies do not change it.

The function then returns the 32-bit value zero.

## Side effects

The direct effects are limited to the listed reads, up to four byte writes, the optional callback, and up to six calls to F-0892220f5e23.

The distinction between a direct write and a final memory value matters:

- Offset `0xA5` is cleared before the callback. Either dependency may subsequently change it.
- Offsets `0xA2` and `0x9E` are set before the entry scan. Later calls may overwrite them; this function does not restore them.
- Offset `0x98` is set after the scan only when a nonzero result was observed. That final direct write follows all scan calls.

## Acceptance examples

These examples are conditional deductions from the supplied source, not runtime observations. Unless a case says otherwise, assume valid memory, dependencies that return normally, and no dependency-induced memory changes.

1. **Callback absent; mode zero.**  
   With `0x94` equal to zero and `0x90` equal to zero, the function clears `0xA5`, skips both dependency mechanisms, leaves the other listed writable bytes unchanged, and returns zero.

2. **Mode is nonzero but not 1.**  
   A mode byte of 2 or `0xFF` does not enable the scan. The condition is equality with 1, not a general truth test.

3. **Callback enables the scan.**  
   With a valid callback object and an initial mode other than 1, a callback that changes the mode to 1 causes the scan branch to run. The mode read follows the callback.

4. **Callback disables the scan.**  
   An initial mode of 1 does not guarantee a scan if the callback changes it to another value before returning.

5. **All entries zero.**  
   With mode 1 and all six entries zero, the function writes 1 to `0xA2` and `0x9E`, makes no calls to F-0892220f5e23, and does not directly change `0x98`.

6. **Several eligible entries; all results zero.**  
   If only the first and sixth entries are nonzero and both dependency calls return zero, exactly two calls occur. Offset `0x98` receives no direct write, even if it was already 1.

7. **An early nonzero result does not stop scanning.**  
   If all six entries are nonzero and the first dependency call returns nonzero, all six calls still occur. After the scan, the function writes 1 to `0x98`, regardless of the remaining five return values.

8. **A dependency changes a future entry.**  
   If the first call clears the sixth entry before that entry is visited, the sixth entry causes no call. Conversely, making a previously zero future entry nonzero can cause an additional call.

9. **A dependency overwrites an earlier flag.**  
   If a scan call clears `0xA2`, the function does not restore it. If a nonzero result was observed, it still writes 1 to `0x98` after the scan.
