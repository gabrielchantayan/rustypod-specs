# F-08741ff22c05

## Purpose

F-08741ff22c05 transfers a fixed horizontal band of 32-bit source elements into a destination buffer over a caller-selected range of rows. Every transferred element has its upper eight bits forced to one; its lower 24 bits are preserved.

Two destination layouts are selected by an integer mode:

- Modes **2 and 3** use a transposed layout in which increasing source row numbers decreases the destination element index.
- All other mode values use a row-oriented layout incorporating an entry-time value read from global storage.

The source layout is identical in both branches: rows have a stride of **160 elements**, and only columns **6 through 153 inclusive** are read. Each selected row therefore transfers **148 elements**.

An image-copy operation with an opaque-alpha adjustment is a plausible interpretation. The established behavior is a 32-bit element transfer and bitwise mask; pixel format, channel ordering, and display orientation are not established.

## Interface

The function receives six arguments and has no explicit return value.

| Argument | Established role |
|---|---|
| First | A 32-bit value that is not used by the supplied body. |
| Second | A signed 32-bit mode selector. Exactly 2 and 3 select the transposed destination layout. |
| Third | Source base address, represented by a recovered 32-bit integer argument. Accesses through this base read 32-bit elements. |
| Fourth | Destination base address, represented by a recovered 32-bit integer argument. Accesses through this base write 32-bit elements. |
| Fifth | Signed 32-bit starting row, inclusive. |
| Sixth | Signed 32-bit ending row, exclusive. |

The function also reads one global value, treated as a signed 32-bit destination element offset. This document calls it the **entry offset**. Its address, initialization, permitted values, and relationship to any larger object are not provided.

The interface has no explicit buffer lengths, strides, error result, allocation handle, or ownership-transfer indicator. The strides and selected columns are fixed by the function.

## Behavior

### Entry and range selection

The supplied body first reads the global entry offset into local state, before choosing the mode branch or checking whether the row range is empty.

Consequently, an empty row range does not eliminate this global read in the supplied representation. This establishes the body’s logical access order, not a guarantee about an externally observable hardware load after optimization.

The second argument then selects the destination layout:

- **2 or 3:** transposed layout.
- **Every other signed 32-bit value:** row-oriented layout.

For either layout, transfer occurs only when the starting row is strictly less than the ending row, using signed comparison.

If the starting row is equal to or greater than the ending row:

- No source element is read.
- No destination element is written.
- The function returns without an explicit result.
- The entry-offset read described above still appears before this decision.

There is no clamping, range normalization, or reversal of a descending interval.

### Shared source traversal and value transformation

For a nonempty interval, rows are processed in increasing order, beginning at the starting row and stopping before the ending row.

Within each row, columns are processed in this exact order:

**6, 7, …, 153.**

For row \(r\) and column \(c\), the source element index is:

\[
S(r,c)=160r+c.
\]

The corresponding byte address is the source base plus \(4S(r,c)\).

Each source value is read as a 32-bit word. The value written is:

\[
V_{\mathrm{out}}=V_{\mathrm{in}}\mathbin{\mathrm{OR}}\text{0xFF000000}.
\]

Thus:

- Bits 0 through 23 retain their source values.
- Bits 24 through 31 become one.
- A source value whose upper byte is already `FF` is unchanged.
- The transformation is not arithmetic addition, blending, or channel rearrangement.

The mask applies to the numerical 32-bit word. Its byte-level appearance depends on target endianness; endianness is not established here.

Each iteration reads its source word before storing the transformed destination word. The body does not first collect an entire row or the entire selected region.

### Row-oriented destination layout

For every mode other than 2 or 3, let \(g\) be the entry offset captured at function entry. The destination element index is:

\[
D_{\mathrm{row}}(r,c)=g+180r+c+10.
\]

The byte address is the destination base plus \(4D_{\mathrm{row}}(r,c)\).

For a particular row, the selected columns therefore write the contiguous destination interval:

\[
[g+180r+16,\;g+180r+163].
\]

The destination row stride is **180 elements**, or **720 bytes**, whereas the source row stride is **160 elements**, or **640 bytes**.

For successive columns within one row, destination addresses increase by four bytes. For the same column in successive rows, destination addresses increase by 720 bytes.

The entry offset is used as an **element offset**, not directly as a byte offset. Its contribution to the byte address is four times its value.

Only the captured entry value is used. The body contains no subsequent read of this global during the transfer. If a destination write aliases the global’s storage, that write does not cause later iterations to use a newly loaded offset.

### Transposed destination layout

For modes 2 and 3, the destination element index is:

\[
D_{\mathrm{transposed}}(r,c)=180(c+10)+169-r.
\]

Equivalently, the byte address is the destination base plus:

\[
4\bigl((180-r)+180(c+10)\bigr)-44.
\]

The equivalence holds under mathematical arithmetic without overflow.

This branch does not use the entry offset in its address calculations, although the supplied body reads that global before branch selection.

For a fixed source row:

- The first selected column, 6, writes destination element \(3049-r\).
- The last selected column, 153, writes destination element \(29509-r\).
- Successive selected columns advance the destination by **180 elements**, or **720 bytes**.

For a fixed source column, increasing the source row by one decreases the destination index by one element, or four bytes.

The layout therefore exchanges the roles of source row and column in destination addressing, with the source-row contribution reversed. Describing this as a particular clockwise or counterclockwise image rotation would require coordinate and storage conventions not supplied here.

### Completion and operation counts

On ordinary completion, every selected row has been processed, and the function returns without an explicit result.

For a nonempty interval, let \(N\) be the mathematical difference between ending and starting row. The body performs:

- \(148N\) source-word reads.
- \(148N\) destination-word writes.
- One entry-offset read in the supplied representation.

For an empty or descending interval, source and destination access counts are zero.

The difference \(N\) is a mathematical description, not a subtraction performed by the body. For signed 32-bit endpoints, a positive mathematical difference can exceed the maximum signed 32-bit value; the access-count formula does not imply that the function stores this count in such a value.

## Side effects

### Destination mutation

The function overwrites exactly the destination addresses generated by the selected layout, provided execution completes and the arithmetic and memory accesses are valid.

It does not explicitly clear padding, fill an entire destination row, or modify destination elements outside those generated addresses.

The body contains no direct write to the global entry offset. Nevertheless, a caller-selected destination range could alias that global or other storage. Such aliasing is not checked.

### Source and destination overlap

No nonoverlap check, staging buffer, or overlap-safe copy mechanism appears.

A destination write can overwrite a source word that a later iteration will read. In that case, the later transfer uses the value present at the time of that later read, not necessarily the value that existed when the function was entered.

Read/write ordering is therefore part of the behavior:

1. Rows ascend.
2. Columns ascend within each row.
3. The current source word is read.
4. Its masked value is written to the current destination address.

The function must not be described as an atomic snapshot transfer or as generally safe for overlapping regions.

There is no explicit error reporting or recovery path. Invalid addresses, unsupported alignment, concurrent mutation, or arithmetic overflow are not detected by this body. Whether any such condition traps, corrupts memory, or has another result depends on target and execution details not provided.

## Acceptance examples

These examples are conditional behavioral criteria derived from static evidence. They are not reports of executed tests. Address examples assume valid memory and nonoverflowing arithmetic.

### Empty and descending ranges

With starting row 5 and ending row 5, either layout performs no source reads or destination writes.

With starting row 8 and ending row 3, the result is likewise an empty transfer. The function does not process rows in reverse.

In both cases, the entry-offset read remains present in the supplied body.

### One row in the row-oriented layout

Given:

- Mode 0.
- Entry offset 0.
- Starting row 0.
- Ending row 1.

The function reads source elements 6 through 153, in ascending order, and writes destination elements 16 through 163, in ascending order.

For example, source element 6 containing `0x12345678` produces `0xFF345678` at destination element 16.

Exactly 148 elements are transferred.

### Effect of the entry offset

Given row-oriented mode, entry offset 7, and the single selected row 1:

- Source elements are 166 through 313.
- Destination elements are 203 through 350.

The entry offset shifts the destination positions by seven elements, or 28 bytes, relative to entry offset zero. It does not change source positions.

### One row in the transposed layout

Given mode 2 and the single selected row 0:

- Source element 6 maps to destination element 3049.
- Source element 7 maps to destination element 3229.
- Source element 153 maps to destination element 29509.

The entry offset does not alter these positions.

Mode 3 must select the same mapping as mode 2.

### Successive rows in the transposed layout

Given mode 3 and rows 0 and 1:

- Source row 0, column 6 writes destination element 3049.
- Source row 1, column 6 writes destination element 3048.

All 148 columns of row 0 are processed before any column of row 1.

### Other mode values

Modes −1, 0, 1, and 4 all select the row-oriented layout. The supplied condition assigns no separate meaning to any of these values.

### Overlap changes a later read

Assume row-oriented mode, entry offset zero, a single selected row 0, and identical source and destination bases.

The transfer of column 6 writes destination element 16 using source element 6. When the traversal later reaches column 16, its source element has already been overwritten.

The later transfer consequently uses the masked value originating from source element 6, rather than the entry-time contents of source element 16. Snapshot-copy behavior would not satisfy this contract.
