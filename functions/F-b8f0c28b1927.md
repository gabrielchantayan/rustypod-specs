# F-b8f0c28b1927

## Purpose

F-b8f0c28b1927 performs an ordered, partially direct transfer between two caller-supplied memory locations. It transfers three consecutive 32-bit units directly, then invokes F-46f0b3cb316e twice on corresponding regions at higher offsets. If execution reaches the normal return, the result is the original destination address.

The established behavior is narrower than a general-purpose copy operation. The direct transfers are interleaved reads and writes, not a source snapshot. The two delegated operations have unknown contracts. Consequently, this function does not establish whole-object equality, overlap safety, resource independence, or preservation of the directly written values after the delegated operations.

An inferred intent is to copy or assign a composite object containing a directly transferable prefix and two separately handled regions. That interpretation is not necessary to the contract and does not establish the type, extent, or ownership rules of those regions.

## Interface

The function takes two address-valued inputs:

- **Destination:** the base address used for direct writes and as the first argument to both delegated operations.
- **Source:** the base address used for direct reads and as the second argument to both delegated operations.

The visible representation treats each input as addressing a sequence of 32-bit units. The directly accessed units are located at byte offsets 0, 4, and 8 from each base.

The normal return value is the original destination address. It is not an address returned by either dependency and is not advanced past the transferred regions.

## Behavior

### Ordered direct transfers

The first phase has the following observable ordering:

1. Read the 32-bit unit at source offset 0 and write that value at destination offset 0.
2. Read the 32-bit unit at source offset 4 and write that value at destination offset 4.
3. Read the 32-bit unit at source offset 8 and write that value at destination offset 8.

Each source read precedes its corresponding destination write. Each completed destination write precedes the next listed source read.

The function does not first collect all three source units into an independent snapshot. This distinction matters when a destination write changes storage that a later source read will access.

After the third direct write, and before either dependency call, the destination prefix contains the values observed by those three reads. For nonoverlapping, stable source storage, these are the source’s original three units. For overlapping storage, later observed values may instead reflect earlier writes.

These are intermediate-state guarantees. They are not unconditional guarantees about memory after normal return, because the dependencies may modify the same storage.

### Delegated operations

After the direct phase completes, F-46f0b3cb316e is invoked with these argument addresses:

- First argument: destination plus 12 bytes.
- Second argument: source plus 12 bytes.

If that invocation returns normally, the same dependency is invoked again with:

- First argument: destination plus 20 bytes.
- Second argument: source plus 20 bytes.

The second call occurs after the first returns. There is no visible validation, rollback, or additional direct data transfer between them. Any result values produced by these calls are unused.

The argument roles describe their order, not their permissions. The supplied evidence does not establish that the dependency only writes through its first argument or only reads through its second. It also does not establish that either call is confined to a region beginning at the supplied address.

Because the first call precedes the second, changes made by the first may affect what the second observes. Such changes could involve argument-reachable memory, other memory, or global state. No preservation guarantee for any of these is available.

### Completion and interruption

There is no visible status output, error-code branch, cleanup path, or restoration of previous destination contents. If a direct access cannot complete, the later operations are not established to occur. If the first delegated call does not return normally, the second call and normal return are not reached through the visible sequence.

The precise mechanism for faults, exceptions, termination, or other abnormal behavior is unknown. The function provides no visible transactional guarantee: writes and dependency side effects may already have occurred before execution is interrupted.

## Side effects

The function directly performs three 32-bit destination writes. It also directly performs three source reads, each occurring immediately before its associated write.

Overlapping inputs can make these direct writes change storage also designated as source storage. The source is therefore not unconditionally unchanged, even before considering dependency behavior.

The function contains no visible allocation, deallocation, reference-count adjustment, or resource acquisition of its own. This observation does not extend to F-46f0b3cb316e. Either delegated call may have ownership or lifetime effects that are not documented here.

No directly visible global read or write appears in the supplied body. Global preservation remains unknown because the dependencies’ behavior is unavailable.

There is no established transfer of ownership for either base address. Likewise, the returned destination address is not evidence of a newly allocated object or an independently owned copy.
