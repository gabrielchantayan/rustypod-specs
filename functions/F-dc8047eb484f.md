# F-dc8047eb484f

## Purpose

F-dc8047eb484f marks a bounded prefix of a linked structure, gathers structurally qualifying nodes into a temporary array, passes that array to an ordering dependency, and selects at most seven entries according to their subsequently observed fields.

For each selection, it writes an address derived from a caller-supplied base into the node and allocates a two-word record that it prepends to a receiving list. It then performs metadata-based accounting and passes the temporary allocation to a release-like dependency.

These are structural descriptions. Application meanings, ordering policy, and allocator ownership rules are not established.

This contract distinguishes direct operations from outcomes that require dependencies to preserve memory. A dependency returning normally does not, by itself, establish preservation of flags, array contents, list links, metadata, or globals.

## Interface

### Inputs and result

The function receives:

- **Region base:** a 32-bit value used in address arithmetic.
- **Container address:** a 32-bit pointer to a structure containing chain, allocation-context, receiving-list, and bound fields.

No explicit return value is provided. Results are communicated through memory changes and dependency calls. A metadata-validation failure invokes a dependency identified in the supplied material as nonreturning.

### Widths and layouts

Words and pointer representations are 32 bits. The discriminator is eight bits; two cleanup indices are obtained using 16-bit values. All offsets below are byte offsets.

| Container offset | Access | Role |
|---|---|---|
| `+0x04` | Read | Pointer to an object whose first word supplies the record-allocation context argument. |
| `+0x10` | Read | Main-chain head. |
| `+0x1c` | Read/write | Receiving-list head. |
| `+0x24` | Read | Bound for the initial marking pass. |

| Node offset | Access | Role |
|---|---|---|
| `+0x00` | Read | Next main-chain node. |
| `+0x04` | Read | Associated-node pointer. |
| `+0x08` | Write | Assigned address. |
| `+0x20` | Conditional byte read | Selection discriminator. |
| `+0x24` | Read/write | Flags: marking bit `0x00020000`, assignment bit `0x00010000`. |

Each record allocation requests eight bytes:

| Record offset | Written value |
|---|---|
| `+0x00` | Receiving-list head observed after allocation returns. |
| `+0x04` | Selected node address. |

The function does not initialize the receiving-list head or clear existing node flags.

### Preconditions and limits

Normal completion requires readable and writable storage for every access actually performed, including associated nodes that receive marking writes, temporary-array entries, record allocations, allocation metadata, and accounting fields.

The unbounded traversals require eventual null termination. No cycle detection exists. Structural stability across counting and gathering is required to avoid count/fill mismatches, but stability alone does not prevent later dependencies from changing the gathered array or selection fields.

Allocation results are used without failure recovery. A null temporary allocation is unsafe when filling or scanning requires entries; a null record allocation is immediately used as writable storage.

The region base is not dereferenced directly. This function establishes no validity guarantee for later consumers of the addresses written into nodes.

Unsigned 32-bit counts, allocation-size arithmetic, and assignment-address arithmetic wrap modulo \(2^{32}\). Portable semantics of the signed-looking accounting decrements and address expressions are not fully established by the supplied representation.

## Behavior

### Bounded marking

The function reads the main-chain head and begins with a zero counter. For every non-null current node, it rereads the container’s bound before deciding whether the counter is below that bound.

For each permitted node, the observable sequence is:

1. Advance the counter by one.
2. Read and rewrite the node’s flags with `0x00020000` set.
3. Read its associated-node pointer.
4. If that pointer is non-null and differs from the current node, read and rewrite the associated node’s flags with the same bit set.
5. Read the current node’s next pointer.

Each flag update preserves the other bits in the word read for that update. A self-association does not cause a second marking operation. A distinct associated node need not belong to the main chain.

A zero bound prevents marking. Null termination stops the pass even if the bound permits more nodes. The bound applies to this pass only.

These describe immediate writes, not a guarantee that marking persists through subsequent dependency calls. Aliasing or concurrent mutation can also affect later reads; neither is controlled by this function.

### Counting and gathering

The function rereads the main-chain head and counts nodes whose associated pointer is null or self-referential. Neither flags nor the discriminator participate in this structural predicate.

The counting access sequence is significant:

- Read the association field for comparison with the current node.
- Read the current node’s next pointer.
- Read the former node’s association field again for the null comparison.
- Increment the count if the second observation is null or the first observation was self-referential.

Thus, under mutation, this is not necessarily a predicate evaluated from one association snapshot.

The count is unsigned 32-bit and has no overflow check. F-d33f6d597e5d receives the count shifted left by two bits, producing a 32-bit byte request. Allocation-size wrap is unchecked.

After allocation, the function rereads the main-chain head and gathers qualifying node addresses in traversal order. Here, it first tests association for null and, if non-null, reads it again for comparison with the current node. A qualifying node contributes one 32-bit address.

The function neither records the actual filled length nor verifies it against the earlier count. Dependency-induced changes between passes, concurrent changes, or aliasing can produce too many writes or too few initialized entries. Count overflow and allocation-size wrap can independently invalidate the storage assumptions.

### Ordering boundary

F-4d426a8054f4 receives:

- The temporary-array pointer.
- The previously counted entry count.
- Element width four.
- A fixed comparator callback.

The call occurs even for count zero. The comparator’s body and opaque identity are not supplied. Ordering, tie handling, stability, array preservation, and other side effects remain unknown.

“Ordered entries” below means the entries observed after this call, not a guaranteed permutation of the gathered nodes unless the dependency supplies that guarantee.

### Selection and record publication

The scan begins at array index zero with zero selections. It examines no entries beyond the counted length and stops after the seventh completed selection.

For each examined entry, the function reads the node address from the array, then reads the node’s flags:

- If marking bit `0x00020000` is set at that read, it skips the entry without reading the discriminator.
- Otherwise, it reads the discriminator byte at `+0x20`.
- A nonzero discriminator skips the entry.
- A zero discriminator permits selection.

For a selected node, it:

1. Rereads the flags and writes them with assignment bit `0x00010000` set.
2. Writes the calculated assigned address at `+0x08`.
3. Increments the selection count.
4. Reads the container’s allocation-context pointer and that object’s first word.
5. Calls F-08f20a63bf27 with the context word and size eight.
6. Writes the selected node address at the returned record’s `+0x04`.
7. Reads the receiving-list head.
8. Writes that observed head at the record’s `+0x00`.
9. Writes the record address as the receiving-list head.

For zero-based selection ordinal \(k\), the assigned address is:

\[
(\text{region base} + 0x84 + k \times 0x1c) \bmod 2^{32}.
\]

The seven possible offsets are `0x84`, `0xa0`, `0xbc`, `0xd8`, `0xf4`, `0x110`, and `0x12c`. Skipped entries consume no assignment position.

The assignment bit is not an exclusion criterion. If the marking bit is clear and the discriminator is zero when examined, an already-assigned node can be selected again.

Each publication links to the head observed **after** its allocation call. Final reverse selection order follows only if allocations return distinct, non-overlapping record storage and intervening dependencies preserve the receiving-list head and previously published links. Allocation may otherwise change which list is extended. Similarly, assignment and flag writes may be changed by subsequent calls.

### Temporary-allocation cleanup

A null temporary-array pointer causes an immediate return after scanning. This does not protect earlier array accesses.

For a non-null pointer, the function calls F-187ab9ba4eb6, tests the same retained pointer again, and calls F-2fd8826557a4. It then reads the global accounting-context pointer and retains that context address for the remaining operations. Later changes to that global do not cause a context reload.

Let the temporary-array address be the reference point for the following offsets.

**Validation before the accounting dependency:**

- Read the 32-bit header at `−0x08` to test for zero.
- If nonzero, read the header again to test bit zero.
- A zero first observation or an odd second observation reaches F-a817d8d58c10, identified as nonreturning.
- Otherwise, call F-c0fc6d033caa with the captured accounting context.

The validation need not use one header snapshot. More importantly, its observations are not reused as the subsequent accounting size.

**Sampling and updates after F-c0fc6d033caa returns:**

1. Read the 32-bit metadata word at `−0x04`; retain its numeric low 16 bits as the first index.
2. Reread the header at `−0x08` and mask it with `0x3ffffffc`. This is the size used for the next four accounting subtractions.
3. Subtract that size from the word at context `+0x224 + 4 × first index`.
4. Subtract it from context `+0x30c`.
5. Read the 16-bit value at `−0x02` as the second index.
6. Subtract the retained size from context `+0xe0 + 4 × second index`.
7. Subtract it from context `+0x220`.

The second index is sampled after the first two writes. It is not necessarily equivalent to a particular half of the earlier metadata-word observation: byte order, intervening writes, and aliasing matter.

Next, F-09dcb55e8e0a supplies an index. The function decrements the word at context `+0x310 + 4 × returned index`, then decrements context `+0x390`.

After those operations, the function **rereads** the header at `−0x08`, masks it with `0x3ffffffc`, and subtracts this newly sampled size from context `+0x08`. This size can differ from the size used for the earlier four subtractions.

Finally, it calls F-cc6c9b4a0f68 with the captured context and address `array − 0x08`, then calls F-e586bff64fb7 with the same context.

There is no revalidation after F-c0fc6d033caa or F-09dcb55e8e0a, no index-range check, and no explicit underflow protection. The four size subtractions and final masked-size subtraction use unsigned 32-bit arithmetic.

## Side effects

Direct effects include marking writes, temporary-array writes, assignment writes, record allocation and publication, accounting updates, and dependency calls.

No direct write initializes a region slot. The function stores calculated addresses in nodes.

It does not directly unlink selected nodes, clear either flag, reset the receiving list, or roll back earlier writes after failure.

The temporary allocation reaches a release-like dependency sequence. Actual ownership transfer and release are not established. Published records are not explicitly released by the function. Neither are the container, main nodes, associated nodes, or region. Unknown dependency effects prevent a stronger non-release guarantee.

Overlapping allocations or aliasing between structures and accounting storage can change later observations. Durable flags, durable assignments, and a conventional list shape require preservation and non-overlap assumptions beyond normal dependency return.

## Acceptance examples

These are conditional static expectations, not executed tests. All require valid storage and defined arithmetic for the accesses reached. Traversal examples additionally require a stable finite chain without destructive aliasing.

1. **Zero bound and one candidate.**  
   With bound zero, no marking write occurs. If gathering produces one null-associated node, ordering preserves that entry, and its marking bit is clear and discriminator zero when scanned, the function writes region base plus `0x84` and performs one record-publication sequence.

2. **Marking exclusion requires preservation.**  
   With bound one and one null-associated node, the initial pass sets its marking bit. If allocation and ordering preserve that bit and the array references the same node, selection skips it without reading its discriminator. If either dependency clears the bit, the initial marking alone does not establish exclusion.

3. **Distinct associated node.**  
   A processed node whose observed association points to another valid node receives a marking write, as does that associated node. If the association remains distinct and non-null during counting and gathering, the main-chain node contributes no array entry.

4. **Skipped entries leave no assignment gaps.**  
   Suppose the array observations yield a marked node, an unmarked node with nonzero discriminator, then two eligible nodes. Provided the first record-allocation call preserves the later relevant entry and fields, the eligible nodes receive offsets `0x84` and `0xa0`.

5. **Seven completed selections.**  
   If nine entries remain valid and eligible when reached, with intervening calls preserving the required future entries and fields, only seven are selected. The scan does not read entries eight and nine after completing the seventh publication.

6. **Reverse receiving-list prefix.**  
   If nodes A, B, and C are selected in that order, allocations return distinct non-overlapping records, and dependencies preserve the list head and published links, the final prefix references C, B, A before the original list. Without those preservation conditions, only each individual link-and-head write is guaranteed.

7. **Different cleanup size samples.**  
   Suppose validation observes a nonzero even header. If F-c0fc6d033caa changes it so its masked value is `0x40`, the first four subtractions use `0x40`. If F-09dcb55e8e0a later changes its masked value to `0x60`, and intervening writes leave it unchanged, the subtraction at context `+0x08` uses `0x60`. No second validation intervenes.

8. **Invalid cleanup header.**  
   A zero first validation observation, or a nonzero first observation followed by an odd second observation, reaches F-a817d8d58c10. Earlier marking, assignments, and publications have no rollback path.
