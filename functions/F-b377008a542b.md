# F-b377008a542b

## Behavior

### Input selection

Null replacement occurs before sequence processing begins. Both inputs use the same fallback address when replacement is needed.

There is no explicit examination of fallback contents during selection. Its bytes are consumed through the same transformation and comparison process as bytes from a non-null input.

Pointer identity is not used as an equality shortcut. Equal input addresses, including the two fallback addresses selected by two null inputs, still lead to separate dependency invocations.

### Observable processing order

At each position, the function performs these ordered operations:

1. It loads the byte at the current left cursor.
2. It invokes F-e873bc705e5d with that byte.
3. It retains only the low eight bits of the returned value.
4. It loads the byte at the current right cursor.
5. It invokes F-e873bc705e5d with that byte.
6. It compares the retained left value against the low eight bits of the right result.

The right-side byte load occurs after the left-side dependency invocation has returned. This ordering matters if that invocation changes storage visible through the right cursor.

Both dependency invocations occur before deciding whether the pair is unequal or terminating. In particular, a left transformed value of zero does not suppress the right load or the right dependency call.

The left transformed comparison value is retained across the right dependency invocation. It is not recomputed afterward.

### Unequal transformed values

If the transformed values differ, the function immediately returns their difference, with the arithmetic qualification stated in the interface section.

Neither cursor advances for that mismatching pair. No subsequent byte is explicitly read by this function.

Mismatch takes precedence over termination. A pair containing one transformed zero and one transformed nonzero value produces a mismatch result; it does not produce an equality result.

### Equal transformed values

If the transformed values are equal, both private cursors advance by one byte.

The function then examines the retained left transformed value:

- If it is nonzero, processing continues at the next pair of addresses.
- If it is zero, the function returns zero.

Consequently, cursor advancement also occurs for the terminating equal-zero pair, although no next-position byte is loaded on that path.

The function does not compare original bytes directly. Different raw bytes may compare equal if the dependency maps them to the same low-eight-bit value.

### Termination implications

A raw zero byte has no special treatment before transformation. Its effect depends entirely on the dependency result:

- A raw zero transformed to a nonzero value does not terminate an otherwise equal comparison.
- A nonzero raw byte transformed to zero can participate in successful termination.
- A dependency result whose low eight bits are zero is a terminating value when matched by the other side, even if its higher bits are nonzero.

There is no explicit iteration limit. Without a mismatch or equal transformed-zero pair, the function continues attempting reads and dependency calls.
