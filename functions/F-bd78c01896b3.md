# F-bd78c01896b3

## Purpose

F-bd78c01896b3 conditionally dispatches an operation on a supplied receiver using a four-word bounds record and a second four-word record containing half of the bounds’ extents. It then reports whether a receiver state field is nonzero.

The established behavior has two principal paths:

- If an initial lookup produces no record, or the record’s second word is zero, invoke a fallback dependency with the receiver and the value 100, then return 0.
- Otherwise, obtain bounds and an optional auxiliary object, perform any applicable auxiliary processing, dispatch the receiver operation, and inspect the receiver’s state. Return 1 if that state is nonzero; otherwise invoke a second receiver operation and return 0.

Interpreting the bounds as a rectangle, or the main dispatch as a positioning or layout operation, is inferred intent. Neither interpretation is required to describe the observed data flow.

## Interface

**Input:** one receiver reference.

**Output:** a 32-bit result whose established values are 0 and 1.

The available representation uses 32-bit words and pointers. The receiver is used as an object with:

| Byte offset 0 | Reference to a dispatch table |
| Dispatch-table byte offset `0x128` | Main operation, receiving the receiver, two temporary-record addresses, and the initial lookup record |

The successful-lookup path eventually requires a readable dispatch-table reference, callable entries, and a readable state field.

## Behavior

The result of F-5710a8628cba is treated as a record reference:

- A zero result selects the fallback path without dereferencing that result.
- A nonzero result causes a 32-bit read at byte offset `0x04`.
- A zero word at that offset also selects the fallback path.
- Any nonzero word selects the main path. No distinction between positive and negative values is made.

The eligibility word is not forwarded separately. Its established role is solely the zero/nonzero decision. The record reference itself is retained for the later main receiver operation.

On the fallback path, F-979606fd565e receives the original receiver and the integer 100. Its return value is ignored. F-bd78c01896b3 returns 0 after that call, provided the dependency returns normally. It does not subsequently inspect the receiver state or invoke either receiver dispatch entry.

### Main-path object resolution

2. Call F-9e50c66a96dd with the context and a first global key.
3. Call F-682adfd5a561 with that result and the previously loaded selector. Retain its result as the optional auxiliary object.

### Bounds selection and snapshot

A zero bounds-object result selects these four signed 32-bit words:

| Word | Value |
|---|---:|
| First | 0 |
| Second | 0 |
| Third | 240 |
| Fourth | 320 |

A nonzero bounds-object result selects the four consecutive signed 32-bit words beginning at its byte offset `0x80`.

In either case, the four selected words are copied into a separate temporary record before any auxiliary-object dispatch. They are read in ascending word order. This is a sequence of reads, not an established atomic snapshot.

For the remainder of this contract, call the copied values the first, second, third, and fourth bounds words. These names do not imply a validated coordinate system. No check establishes that the third word is at least the first, or that the fourth is at least the second.

Once copied, these temporary values are the inputs to the later half-extent calculations and the bounds record supplied to the main receiver operation. Mutations of the original bounds storage during subsequent dependency calls do not cause the function to recopy it.

### Optional auxiliary processing

If the auxiliary-object reference is zero, this stage is skipped.

Otherwise, the function:

1. Resolves and invokes the auxiliary object’s dispatch entry at byte offset `0x114`, passing that object as receiver.
2. Reads the auxiliary object’s 32-bit word at byte offset `0xAC`.
3. Subtracts that word from the dispatch operation’s integer result.
4. Calls F-43ed3b67358d with the auxiliary object, the computed difference, and the address of a four-word temporary region.

The field read follows the dispatch call. If the dispatch operation changes the field, the subtraction uses the subsequently read value.

No initialized contents are established for the temporary region supplied to F-43ed3b67358d. The helper’s input/output expectations for that region are unknown. Its return value is ignored.

After the helper returns, the function overwrites all four words of that region before supplying it to the main receiver operation. Consequently, the helper’s writes to those four words do not determine the record passed onward. This does not make the helper behaviorally irrelevant: its other side effects remain possible and are not characterized here.

### Main receiver operation

The function computes two signed half-extents:

- The first is the third bounds word minus the first bounds word, divided by 2.
- The second is the fourth bounds word minus the second bounds word, divided by 2.

For representable signed differences, division truncates toward zero. There is no absolute-value operation, saturation, rounding upward, or correction for reversed bounds.

The four-word record used earlier as auxiliary scratch is then fully set to:

| Word | Value |
|---|---|
| First | 0 |
| Second | 0 |
| Third | First half-extent |
| Fourth | Second half-extent |

The function invokes the receiver’s dispatch entry at byte offset `0x128`, passing, in order:

1. The receiver.
2. The address of the zero-origin, half-extent record.
3. The address of the copied four-word bounds record.
4. The original successful lookup record reference.

The receiver dispatch-table reference is obtained for this operation after the earlier dependency calls. No earlier table reference is cached for reuse here.

The main operation’s return value is ignored.

### State-dependent completion

After the main operation returns, the function reads the receiver’s 32-bit field at byte offset `0xB0`.

- If the field is nonzero, return 1 immediately.
- If the field is zero, resolve and invoke the receiver’s dispatch entry at byte offset `0x12C`, then return 0.

The follow-up dispatch uses the receiver’s dispatch-table reference as obtained after the main operation. A table change made by the main operation can therefore affect this subsequent dispatch.

The state field is not tested again after the follow-up operation. Even if that operation sets it to a nonzero value, the function still returns 0.

## Acceptance examples

These examples are conditional expectations derived from static evidence, not executed tests. They assume valid accessible objects, normal dependency returns, and representable signed arithmetic unless otherwise stated.

1. **Missing initial record.** If F-5710a8628cba returns zero, F-979606fd565e receives the original receiver and 100. No main-path resolution or receiver dispatch occurs. The result is 0.

2. **Present but ineligible record.** If the initial record exists and its word at byte offset `0x04` is zero, the same fallback behavior applies. Other record contents do not alter this decision.

3. **Default bounds and nonzero final state.** If eligibility succeeds and the bounds resolution returns zero, the bounds record passed to the main operation is `(0, 0, 240, 320)`. The other record is `(0, 0, 120, 160)`. If the subsequent receiver state read is nonzero, the result is 1 and the follow-up dispatch does not run.

4. **Non-origin bounds.** For copied bounds `(10, 20, 111, 223)`, the main operation receives those bounds unchanged and a second record `(0, 0, 50, 101)`. The half-extents derive from differences, not from halving the third and fourth words independently.

5. **Negative odd difference.** For bounds `(5, 8, 2, 7)`, the computed differences are −3 and −1. The half-extent record is `(0, 0, −1, 0)` under signed truncation toward zero.

6. **Auxiliary mutation before subtraction.** If the auxiliary dispatch returns 25 and leaves the field at byte offset `0xAC` equal to 9, F-43ed3b67358d receives 16. A different value stored there before the dispatch is not the value used.

7. **Zero state followed by state mutation.** If the state read after the main operation yields zero, the follow-up dispatch runs. If that follow-up changes the state to 7, the result remains 0.

8. **Bounds changed after copying.** If auxiliary processing changes the original bounds object after its four words have been copied, the main operation still receives the earlier copied values, subject to no separate corruption or invalidation of the temporary storage.
