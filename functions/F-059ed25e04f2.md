# F-059ed25e04f2

## Purpose

F-059ed25e04f2 processes a mutable stream of 32-bit operation records, updates a packed bitmap, and invokes dependencies operating on an opaque object. Encountering a zero operation word initiates a comparison between bitmap bits and dependency results. A separate operation-result condition can stop processing without comparison.

Established behavior includes resource acquisition, in-place stream mutation, single-bit bitmap updates, conditional object calls, unconditional final calls, and a packed 64-bit return.

**Inferred intent:** the bitmap and opaque object appear to represent corresponding Boolean states for positions numbered from 1 through a supplied bound. This interpretation does not establish initialization, position-selection semantics, ownership, or dependency noninterference.

The working storage used during operation processing is reused as the comparison position. Its address can escape to a dependency. Consequently, ordinary sequential comparison behavior requires an explicit assumption that dependencies do not subsequently modify that storage.

## Interface

The function receives four 32-bit arguments and returns 64 bits.

| Input | Established use |
|---|---|
| Signed bound | Participates in storage-size arithmetic, is passed to position selection, and is the signed upper limit for comparison. |
| Stream-address word | Supplies the address of mutable 32-bit records. Its original bit pattern becomes the upper return half. |
| Initial working word | Initializes addressable 32-bit working storage. It can affect a general operation unless a dependency replaces it. |
| Fourth word | Initially stored, then overwritten by the object-acquisition result before subsequent use. Its original value has no established behavioral effect. |

The return layout is:

| Bits | Meaning |
|---|---|
| 63–32 | Original stream-address word. |
| 31–0 | Result word: initially `0xffffffff`, or a comparison result as described below. |

No separate status flag is returned. A result word alone does not distinguish all paths: dependency sums and comparison-position bit patterns can coincide with other result values.

### Record layouts

Each word occupies four bytes.

| Operation word | Layout | Nominal advance |
|---|---|---|
| 0 | Terminator word only | Enters comparison |
| 1, 2, or 5 | Operation, counter, sequence, increment | Four words |
| Any other nonzero word | Operation, counter | Two words |

No stream length is supplied. Every reached operation word must be readable. Every processed nonzero record requires a readable and writable counter. Four-word records additionally require a readable and writable sequence field and a readable increment field.

Bitmap storage must support every byte access actually reached. Neither sufficient capacity nor a valid selected position is checked locally. The stream, bitmap, and dependency-managed memory are not established to be disjoint.

All arithmetic quantities described below are 32-bit unless stated otherwise. Signed comparisons, arithmetic right shifts, and unsigned bit operations must be distinguished. Overflow at signed arithmetic boundaries is not given a portable language-level contract by the supplied representation.

## Behavior

### Acquisition and initialization

F-094b96da48ec is called without explicit arguments. Its 32-bit result becomes the opaque object handle.

A storage-size word is then calculated from the signed bound. The calculation adds seven to the bound, applies a correction of seven when that intermediate value is negative, shifts the corrected value right arithmetically by three, and adds one.

Where the additions remain representable, this equals truncation toward zero of the bound-plus-seven divided by eight, followed by addition of one. For a nonnegative bound without overflow, it equals the bound rounded upward to a multiple-of-eight byte count, plus one byte. This nonnegative interpretation must not be applied unconditionally to negative bounds.

F-391e3d30e634 receives the calculated size and produces the storage-address word. This call occurs even if object acquisition returned zero.

The result word is initialized to `0xffffffff`. If either acquisition result is zero, initialization, stream processing, and comparison are skipped.

If both results are nonzero, an unidentified external dependency receives the storage address and calculated size before the first stream read. Its behavior is not supplied. In particular, zero-initialized bitmap contents are not established.

### Record preparation and mutation

Processing begins at word offset zero. Each iteration reads the operation word at the current offset.

A zero word transfers directly to comparison. It does not cause a counter decrement.

For operation 1, 2, or 5:

- The sequence field is read, and its value minus one is placed in the working storage.
- The sequence field is read again for an update that also reads the increment field.
- Their sum is written to the sequence field.

Thus the working value is based on the sequence value observed before that update, not on the newly written value. The representation establishes both sequence reads; it does not require an observable ordering between the two operands of the subsequent addition.

For any other nonzero operation, F-e219d7c81ff5 receives the literal size 4 and the address of the working storage. Its effect on that storage is unknown. The supplied evidence does not prohibit it from retaining the address.

After either preparation path, the counter is read, decremented by one, and written back. The decremented value is interpreted as signed:

- A strictly positive value leaves the next record offset unchanged.
- Otherwise, the offset advances by the record’s nominal length.

The offset is updated before position selection and bitmap modification. Updating it does not itself read another record.

A counter initially zero or negative is not rejected. The record still receives a decrement and an operation application. Signed-boundary arithmetic remains subject to the uncertainty described below.

The operation word already read determines this application’s layout and operation branch. Changes to the stream’s operation field during intervening dependency calls do not constitute a fresh operation read for that application. If processing continues, the next iteration reads the operation at the then-current offset afresh.

### Position selection and bitmap update

F-870c4fcf7295 receives the working word with bit 31 cleared and the bound. The primary return is unused. A secondary 32-bit result supplies the selection value and replaces the working word.

**Inferred intent:** this secondary result may be a remainder or bounded index. Neither its meaning nor its range is established.

The selected position is the secondary result plus one in 32-bit arithmetic. Its bitmap location is:

- Byte displacement: the position interpreted as signed, shifted right arithmetically by three.
- Bit index: the position’s low three bits.
- Mask: a single set bit at that index, reduced to eight bits.

A secondary result of zero therefore selects bit 1 of byte 0. No local bounds check precedes the byte access. A negative signed position can produce a negative byte displacement.

The current application’s operation parity determines the byte update:

- Even: read the byte, clear the selected bit, and write the byte.
- Odd: read the byte, set the selected bit, and write the byte.

Other bits are preserved relative to the byte value read for that update. This is not a guarantee that later calls preserve the resulting byte.

After an even operation, F-16d1285c814f receives the object handle and selected position. Its result is ignored, and processing continues.

After an odd operation:

- Operation 5 continues without calling F-469a239057a8.
- Every other odd operation calls F-469a239057a8 with the object handle and selected position.
- A zero result continues processing.
- A nonzero result stops processing without entering comparison.

On that stopping path, the low return word remains `0xffffffff`. The direct sequence, counter, and bitmap writes precede the stopping call. There is no local rollback, but the stopping call and final calls are not established to preserve those writes.

### Comparison after a zero operation

Three calls to F-811a25bdbe21 occur in this order:

1. Explicit arguments zero and zero.
2. The object handle and the bound plus one.
3. The object handle and zero.

Their three 32-bit results are retained. The working storage is then assigned the value 1 and becomes the comparison-position storage.

At each comparison-condition evaluation, the result word is first assigned the 32-bit sum of the three retained results. The current position is interpreted as signed and compared with the bound.

If the position exceeds the bound, comparison finishes with the sum as the low return word.

Otherwise, F-811a25bdbe21 is called again. Only the object handle is explicitly established as an argument for this per-position call. The complete argument contract, including any implicit traversal mechanism, is unknown.

After that call returns:

- The current contents of the position storage are copied into the result word.
- The bitmap byte is read using the current position storage.
- The selected bit is converted to exactly zero or one.
- The dependency’s full 32-bit result is compared with that Boolean value.

A mismatch ends comparison. A match increments the position storage by one and repeats the condition evaluation.

The per-position dependency call precedes both the result-word assignment and bitmap access. There is **no intervening bound recheck**.

### Escaped working storage and comparison guarantees

The position storage is the same storage whose address can previously have been passed to F-e219d7c81ff5. The supplied dependency contracts do not exclude retained-pointer writes or communication of that pointer to other dependencies.

Consequently, a per-position F-811a25bdbe21 call may change the position after the signed bound check but before the result assignment and bitmap read. If it does:

- The checked position and accessed position may differ.
- A mismatch can return a position outside the originally checked range.
- The matching branch increments the post-call position, not necessarily the checked value.
- Positions may be skipped or revisited.
- Completion after visiting positions 1 through the bound is not guaranteed.

Bitmap contents may also change during the call, and comparison uses the byte read afterward.

**Conditional ordinary traversal:** if dependencies do not modify the position storage during comparison, positions proceed from 1 upward. For a nonnegative bound below the signed maximum, exact matches at every visited position lead to completion with the three-result sum. A mismatch returns the visited position. A dependency result other than exactly 0 or 1 cannot match a bitmap bit.

This sequential-traversal description requires the stated noninterference condition. At the maximum positive signed bound, even noninterfering traversal reaches an increment across the signed boundary; ordinary finite-range completion is not established there.

### Final calls and return

All locally represented exit paths call:

1. F-94cb53877c15 with the storage-acquisition result.
2. F-05434e19c03a with the object-acquisition result.

Neither call is guarded by a nonzero check. Acquisition failures therefore still cause both calls, with zero supplied where applicable.

The function returns the original stream-address word in the upper half and the selected result word in the lower half. No local rollback of stream or bitmap writes occurs before return.

## Side effects

Established direct memory effects are:

- Sequence updates for operations 1, 2, and 5.
- Counter decrements for every processed nonzero record.
- Single-byte bitmap read-modify-write operations.
- Writes to the addressable working storage, later reused for comparison position.

Dependency effects are additional and unknown. In particular, F-e219d7c81ff5 receives a writable address; subsequent dependency calls are not established to leave that storage, stream fields, or bitmap bytes unchanged.

Aliasing can make a bitmap update alter stream fields that a later iteration reads. It can also make stream writes affect bitmap contents. The contract therefore distinguishes direct writes from persistence of their effects across subsequent writes and calls.

The function does not directly release or replace the stream address. Passing the acquired object and storage to final dependencies suggests resource finalization, but actual release, ownership transfer, pointer retention, and null handling remain unestablished.

## Acceptance examples

These are conditional static criteria, not executed tests. Memory accesses must be valid, dependencies must return normally, and arithmetic must remain within the stated interpretation.

1. **Failed object acquisition.** If F-094b96da48ec returns zero, F-391e3d30e634 is still called. Initialization, stream processing, and comparison are skipped. Both final calls occur in order, and the low return word is `0xffffffff`.

2. **Failed storage acquisition.** If storage acquisition returns zero, initialization and stream processing are skipped. F-94cb53877c15 receives zero, followed by F-05434e19c03a receiving the object result.

3. **Repeated four-word record, with noninterference.** Suppose operation 1 has counter 2. Assume the bitmap does not overlap the record, dependencies do not modify its operation, counter, sequence, or increment fields, and the first F-469a239057a8 result is zero. The first application writes counter 1 and retains the offset. The same record is then read again; its sequence is updated again, counter becomes zero, and the offset advances four words. Without those assumptions, the second record contents and counter transition are not guaranteed.

4. **Operation 5 bypass.** An application read as operation 5 performs its sequence and counter writes, sets the selected bitmap bit, and skips F-469a239057a8 for that application. Persistence of those writes across later calls is not implied.

5. **Even general operation.** For an application read as operation 4, F-e219d7c81ff5 is called before the counter decrement. The selected bit is cleared, then F-16d1285c814f is called. Its return value does not control continuation.

6. **Early odd-operation stop.** If an operation 1 application obtains a nonzero F-469a239057a8 result, its direct sequence, counter, and set-bit writes occurred before that call. Comparison is skipped and the low return word is `0xffffffff`. To assert that those written values remain observable at return additionally requires non-aliasing with subsequent writes and noninterference by the stopping and final dependencies. Without those conditions, only the writes and absence of local rollback are established.

7. **Exact mismatch under stable position storage.** With bound at least 1, suppose the per-position call leaves position 1 unchanged, returns 2, and the subsequently read bitmap bit is set. Comparison stops with low return word 1. Two nonzero values do not count as equal here.

8. **Complete ordinary comparison.** With bound 2, assume dependencies leave position storage unchanged and both post-call bitmap observations exactly match their corresponding results. If the three retained results are 3, 4, and 5, the low return word is 12.

9. **Post-check position modification.** Suppose position 1 passes a bound check against 2. If the subsequent per-position call changes the escaped position storage to 9, returns zero, and bit 9 is validly readable and set, comparison reads bit 9 without rechecking the bound and returns low word 9.

10. **Empty signed comparison range.** With bound zero, successful acquisitions, and an immediate terminator, all three preliminary comparison calls occur. Position is then assigned 1, so no per-position call occurs. The low return word is the three-result sum.

Every example returns the original stream-address word in the upper half.

## Uncertainties

The following remain **documented_only**:

- Initializer writes and initial bitmap contents.
- Position-selection semantics and valid secondary-result range.
- The complete per-position F-811a25bdbe21 argument contract.
- Retained-pointer behavior and dependency-induced changes to comparison position.
- Dependency ownership, release, global effects, and memory preservation.
- Safety for invalid addresses, insufficient storage, negative sizes, or overlapping regions.
- Termination without a reachable terminator, and comparison termination under interference.
- Signed-overflow semantics at extreme bounds, counters, sequence values, offsets, and increments.

The displayed widths establish 32-bit quantities, not saturation or checked arithmetic. Selection addition, bound-plus-one, size calculation, record-address arithmetic, comparison increments, and result sums require their respective signed or unsigned interpretation. No validation, repair, or overflow-reporting path is established.

## Evidence

This contract uses only the supplied static function representation and opaque dependency mapping. The prior draft and reviewer feedback are not independent behavioral evidence.

Established observations are the visible call ordering, argument preparation, record accesses, direct writes, branch conditions, bit operations, return packing, and reuse of the address-exposed working storage as comparison position.

The state-consistency and resource-finalization interpretations are inferred intent. Dependency noninterference and sequential comparison are explicitly conditional, not established guarantees.
