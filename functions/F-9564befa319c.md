## Behavior

### Widths and arithmetic

Unsigned word shifts are logical, with 32-bit inputs. Important ranges are:

- Third argument shifted right by 23: 0–511.
- Unsigned word shifted right by 22: 0–1023.
- Unsigned word masked with `0x1fffffff`, then shifted right by 19: 0–1023.
- Unsigned word masked with `0x3fffffff`, then shifted right by 21: 0–511.
- Unsigned word masked with `0x3fffffff`, then shifted right by seven: 0–`0x007fffff`.

Byte stores retain the low eight bits. Copying the low byte of a numeric word does not establish the endianness of its source memory.

Calculations explicitly using unsigned 32-bit operands, including the shared secondary word’s multiplication by four, have unsigned 32-bit arithmetic in the representation. Several other indices are represented as signed integers. Negative signed shifts and signed overflow are not assigned portable semantics by this contract.

Interpreting every signed-looking calculation as wrapping 32-bit machine arithmetic is a possible architectural interpretation, not independently established evidence.

These are conditional static obligations, not executed tests. Each assumes execution reaches the relevant operation with valid accesses and the stated retained values.

3. **Lookup indirection and truncation.** A captured phase-two word of `0xffffffff` shifts right by 22 to 1023. If the selected lookup byte is 7, the function writes `0xff` at address 24.

4. **Refreshed global byte.** If the two G-byte reads return 4 and 9 respectively, their zero stores target addresses 21 and 26. The later retained numeric base is 9.

5. **Captured global base.** If G-base is captured as `0x1000` and a dependency subsequently changes it to `0x2000`, the later word read still targets `0x1014`.

6. **Distinct strides.** Index 3 targets address 68 in the stride-16 store and address 32 in a four-byte-scaled word store.

7. **Repeated copy uses a fresh read.** If the retained copy base is unchanged but its source word changes from `0x12345678` to `0xabcdef90` between copies, the two byte writes are `0x78` and `0x90`, both at that retained base plus one.
