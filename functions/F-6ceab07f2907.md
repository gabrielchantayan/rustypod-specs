# F-6ceab07f2907

## Purpose

F-6ceab07f2907 transfers two four-byte values from a selected pair of source fields into two adjacent fields of an indexed destination record.

Two distinct interpretations of the third input control the operation:

- Its full-width value selects the source pair: zero selects one pair; every nonzero value selects the other.
- Its signed low 16 bits select the destination record, using a record stride of 392 bytes.

These interpretations are not interchangeable. A nonzero selector whose low 16 bits are zero selects the nonzero source pair but writes into destination record zero.

The two transfers occur sequentially. The second source value is read only after the first destination write. Consequently, overlapping source and destination storage can affect the second value transferred.

The field meanings and the larger purpose of the surrounding records are unknown. Describing this operation as a two-field transfer is established by the supplied representation; assigning semantic names to those fields would be inferred intent.

## Behavior

### Source selection

The source-pair decision uses the complete selector/index input, not its narrowed index value:

- N = 0 selects source offsets +4 and +12.
- N ≠ 0 selects source offsets +8 and +16.

Negative values select the nonzero pair. Positive values other than one also select the nonzero pair. No Boolean normalization or range restriction is visible.

### Destination indexing and arithmetic widths

The destination index is obtained by narrowing N to a signed 16-bit value before multiplication.

Within the target-width interpretation used here:

- A low-16-bit value from 0 through 32,767 yields the corresponding nonnegative index.
- A low-16-bit value from 32,768 through 65,535 yields an index from −32,768 through −1.
- Bits above the low 16 affect the zero/nonzero source decision but do not affect the destination index.

The index is multiplied by 392 bytes. The resulting mathematical displacement ranges from −12,845,056 through +12,844,664 bytes. Thus the multiplication itself fits within a signed 32-bit integer.

Adding that displacement to B, and then adding the destination field offsets, can still cross the valid address range or the bounds of an allocation. The supplied representation provides no bounds enforcement and does not establish a portable guarantee of address wrapping. The normal-completion contract therefore applies only where the resulting address operations are valid.

Negative indexing is not rejected. A negative I selects storage before B.

### Observable memory-access order

For normally executing ordinary memory, the represented order is:

1. Read four bytes from the first selected source field.
2. Write that value to D + 36.
3. Read four bytes from the second selected source field.
4. Write that value to D + 40.

The first value is retained between its read and its write. The second value is not captured together with the first.

No arithmetic transformation, masking, byte-order conversion, or interpretation of either transferred value is visible. Each transfer preserves the four-byte field value. The operation does not establish whether that value represents an integer, address, flags, or another payload.

The two destination fields are adjacent and do not overlap each other in valid, nonwrapping address arithmetic.

### Aliasing

No non-overlap requirement is enforced by the function. Source and destination storage may alias if the caller’s memory model otherwise permits the accesses.

The access order is material:

- If the first destination write overlaps the second selected source field, the second read observes the storage after that write.
- If the first destination write overlaps the first selected source field, the first value has already been read.
- If the second destination write overlaps source storage, both source reads have already occurred.
- Partial overlap can change only part of a subsequently read field. Its exact resulting value depends on the overlapping byte ranges and the target representation.

This is not a snapshot copy of two source fields. Callers requiring both values as they existed before either write must ensure that the first write cannot alter the second selected source field.

### Completion and errors

After the second write, the function returns without a visible additional action.

There is no explicit error return, exception handling, rollback, or recovery path. Invalid addresses, inaccessible memory, unsuitable alignment, and invalid arithmetic are not converted into a reported status by the represented function.

The function is not transactional. If an execution environment allows the first write to complete and then reports a fault during a later access, no restoration of the earlier write is shown. Exact fault behavior is environment-dependent and is not established here.
