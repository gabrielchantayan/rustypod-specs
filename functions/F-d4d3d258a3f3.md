# F-d4d3d258a3f3

## Purpose

F-d4d3d258a3f3 dispatches a supplied event token and a 32-bit payload to at most one action dependency. Dispatch is determined by an ordered sequence of comparisons against fixed event-name operands.

Two separate decisions govern the result:

- **Recognition:** A comparison returns zero, selecting a branch.
- **Action eligibility:** The payload differs from the sentinel associated with that branch.

A recognized event returns the 32-bit value **1**, including when its action is suppressed by a sentinel comparison. Reaching the end of the comparison sequence without recognition returns **0**.

The event labels suggest selection, highlighting, playback, queue addition, and contextual-menu operations. Those meanings are inferred intent, not established effects of this function. The established behavior is comparison, conditional dispatch, and a recognition result.

The payload has no established unit, range, or application-level meaning. It is not validated other than by equality with a sentinel. In particular, the function does not independently reject zero, negative values, large positive values, or values that might represent addresses.

## Behavior

For this contract, a comparison **recognizes** an event when its result is zero. A nonzero result causes evaluation to continue to the next candidate.

### First remote-playback candidate

The function first invokes the comparison operation with the event token and the first remote-playback operand.

If the result is zero:

1. The payload is compared with a sentinel stored at a location distinct from the common sentinel used by the remaining branches.
2. If unequal, the function invokes the receiver’s indirect action.
3. If equal, it invokes no action.
4. It returns 1.

No later event-name comparison occurs on this path.

For the indirect call, the receiver’s first word supplies the dispatch-table base. The callable entry at byte offset 0x128 is then used with the receiver and payload as arguments.

The target is therefore determined from receiver state at dispatch time, after the first comparison and the payload eligibility check. The evidence does not justify treating it as a fixed implementation.

### Common sentinel and selection candidate

If the first comparison returns nonzero, the function compares the token against `HandleSelect`.

After that comparison returns, the supplied representation captures the common sentinel into a retained value, before branching on the comparison result.

If selection is recognized, the payload is checked against a direct reference to the common sentinel. When unequal, F-5ff4771492d5 receives the receiver and payload. When equal, no action is invoked. The function returns 1 in either case.

The representation distinguishes the retained common-sentinel value from the direct sentinel reference used by the selection branch. It does not establish whether these correspond to distinct physical memory reads in the executable. A contract must not silently replace this distinction with a guarantee that every branch uses one immutable entry-time sentinel.

### Remaining candidates

If selection is not recognized, later branches compare the payload against the retained common-sentinel value captured after the selection comparison.

The subsequent candidates are evaluated in the table’s order:

- A zero result for `HandleHilite` selects F-e7680695fe4c.
- Otherwise, a zero result for `HandlePlayPause` selects F-8ecf431a0d7f.
- Otherwise, a zero result for `HandleAddToOTG` selects F-cb5d084192f5.
- Otherwise, a zero result for the second remote-playback operand selects the indirect receiver action.
- Otherwise, a zero result for `HandleShowContextualMenu` selects F-5e39cda56b97.

For each recognized branch:

- Payload unequal to the retained sentinel: invoke the selected action once.
- Payload equal to the retained sentinel: invoke no action.
- Return 1 after the action returns normally, or immediately when no action is invoked.

A recognized but suppressed action does **not** fall through to another candidate.

If the final comparison returns nonzero, the function returns 0 without invoking an action.

### Ordering and dependency-visible state

Comparison calls occur sequentially. Once one returns zero, no later comparison is made. At most seven comparison calls occur in a normal invocation.

The common sentinel is captured only after the selection comparison returns. Consequently:

- State changes made by the first two comparison calls can precede that capture.
- State changes made by later comparison calls do not replace the retained sentinel used by later branches.
- The first remote-playback branch does not use this retained common sentinel.

Unknown dependencies must not be assumed to preserve globals. These timing distinctions matter if comparison operations alter sentinel storage or other shared state.

At most one action dependency is invoked directly by this function. This does not constrain work, nested dispatch, or callbacks performed inside that dependency.
