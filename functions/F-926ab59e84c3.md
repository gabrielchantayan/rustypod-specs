# F-926ab59e84c3

## Purpose

F-926ab59e84c3 stores a supplied four-byte value into a memory location at byte offset 64 from a supplied base address.

The established behavior is a single memory update. There is no visible validation, conditional selection, allocation, ownership transfer, or call to another function. On a normal return, the destination contains the supplied value.

The inferred intent is to assign a field in an existing object or record. That interpretation is not required by the evidence: the containing object’s type, the field’s meaning, and the larger operation in which this function participates are unknown.

| Stored value | A four-byte value without an established semantic type | Supplies the complete value written to the destination |

The destination starts 64 bytes after the base address. The displacement is a byte displacement, not an index scaled by the size of the stored value.

The function returns without providing a result value. Its output is the memory side effect, not a returned copy of the stored value or a success indicator.

### Preconditions for normal completion

The caller must supply an address for which adding the 64-byte displacement produces a valid destination under the target execution environment. The resulting four-byte region must be writable and suitable for the represented four-byte access.

The evidence does not establish an exact alignment requirement. It also does not establish a portable rule for overflowing address arithmetic. Consequently, this contract does not promise normal completion for addresses that overflow during address formation, identify inaccessible memory, or violate the target’s access requirements.

No requirement to initialize the destination’s previous contents is visible. The operation replaces those contents rather than using them as an input.

## Behavior

For a call satisfying the memory-access preconditions, the function performs the following observable behavior:

1. Forms the destination address using the supplied base address and a positive displacement of 64 bytes.
2. Writes the supplied four-byte value at that destination.
3. Returns with no explicit result value.

There is no visible branch affecting whether the write occurs. Every invocation that reaches the memory operation attempts the same kind of assignment, regardless of the stored value’s bit pattern.

The old destination value does not participate in the update. In particular, the function does not visibly compare the old and new values, combine them, increment the old value, preserve selected bits, or conditionally suppress an unchanged assignment.

The operation replaces all 32 bits of the destination value. It is not a one-byte update, a partial-bit update, or a write to the beginning of the supplied base region.

## Acceptance examples

These examples are conditional behavioral checks, not reports of executed tests.

### Ordinary replacement

Given a valid writable region extending through base-relative offset 67, and a supplied 32-bit pattern of `0x12345678`, normal completion leaves the four-byte destination at offset 64 representing `0x12345678`.

The expected increasing-address byte sequence depends on the target’s byte order.

### Existing contents are discarded

Given the same valid destination initially representing `0xAAAAAAAA`, supplying `0x55555555` replaces the entire destination value with `0x55555555`.

An implementation that combines the two patterns or preserves part of the old destination would not match the established behavior.

### Zero is stored normally

### Repeated calls

Given a destination that remains valid between two normally completing calls with the same base, the second call replaces the value written by the first.

For example, a first supplied value of one followed by a second supplied value of two leaves the destination representing two. No accumulation is visible.

### Destination boundaries

For ordinary writable memory, the explicit assignment covers offsets 64 through 67. It does not specify writes to offsets 63 or 68, or to the first four bytes at the base address.

This statement describes the visible store footprint; it is not a guarantee about device-specific side effects if the address identifies special memory.

### Invalid destination
