# F-03a092ad5b78

## Purpose

F-03a092ad5b78 performs ordered dispatch for an object and a descriptor. It first offers certain descriptors to one of two specialized handlers. If no specialized handler is selected, or the selected handler returns zero, it invokes an object-associated primary callback. If that callback also returns zero, a narrowly gated secondary callback may run.

The first nonzero result terminates processing and is returned unchanged. If all applicable stages return zero, the function returns zero.

This dispatch behavior is established by the supplied static representation. The application-level meanings of the descriptor tags, comparison values, and callback slots are unknown. In particular, zero is a continuation result within this function; the evidence does not establish that zero means application-level success or failure.

## Interface

### Inputs

The function has three supplied arguments:

1. **Object reference.** A pointer to storage whose first word identifies a callback table. A further object word, at byte offset `0x50`, participates in the secondary-callback eligibility check.
2. **Descriptor reference.** An address used to access a tag at byte offset `0x04` and, conditionally, another word at byte offset `0x08`.
3. **Additional integer.** This argument has no effect on the established dispatch behavior. On the only path that compares against its working storage, that storage has first been replaced with a global comparison value. Its incoming value is therefore ignored.

The supplied representation uses 32-bit integer words and address-bearing words. The contract below describes that recovered 32-bit model. Equality tests compare complete 32-bit values; no signed ordering, narrowing, or sign-extension behavior affects the decisions shown.

### Output

The result is a 32-bit integer:

- A nonzero result from the selected specialized handler, primary callback, or secondary callback is returned without conversion.
- Otherwise, the result is zero.
- The return value of the preparation dependency does not control dispatch.

Both positive and negative nonzero values are terminal results.

### Preconditions

Every access that is reached must refer to readable storage of the required width. In particular:

- The descriptor tag must be readable at entry.
- A tag of `0x16` requires a readable address-bearing word at descriptor offset `0x08` and a readable discriminator at offset `0x04` in the referenced record.
- Reaching a primary callback requires a readable object table reference and a valid callable entry in the selected slot.
- Reaching the secondary callback requires a readable object word at `0x50` and a valid callable entry at table offset `0x0E0`.

The function does not validate null pointers, storage bounds, alignment, or callback addresses. These requirements are path-dependent: a specialized handler returning nonzero prevents this function from reaching its own object-table accesses.

## Behavior

### 1. Initial classification

The function first reads the descriptor tag at offset `0x04`.

If the tag is not `0x16`, it bypasses specialized handling. It does not read the nested-record discriminator or either global comparison word during this initial classification. Processing continues to primary callback dispatch, which performs a fresh tag read.

If the tag is `0x16`, the function:

1. Reads the nested-record address from descriptor offset `0x08`.
2. Reads that record’s discriminator at offset `0x04`.
3. Reads comparison A.
4. Compares the discriminator with comparison A.

A match selects the first specialized path. A mismatch causes a second classification:

1. The nested-record address is read again from descriptor offset `0x08`.
2. The nested discriminator is read again.
3. Comparison B is read.
4. The newly read discriminator is compared with comparison B.

A match in this second comparison selects the second specialized path. A mismatch bypasses specialized handling.

The initial descriptor tag is not reread between the two specialized comparisons. The nested address and discriminator are reread. Consequently, this contract does not collapse the two discriminator reads into one retained value.

Comparison A has priority. If the first comparison matches, comparison B is not consulted. This remains true when the two global comparison words have equal values.

### 2. Specialized handling

The first specialized path invokes:

1. F-eea3e31f6354.
2. F-5fbc54ccb97e.

The second specialized path invokes:

1. F-eea3e31f6354.
2. F-abfda56c9f67.

The supplied representation shows no explicit arguments for these dependency calls. Their complete machine-level calling contracts are not established here.

The preparation dependency’s result is not used. It does not provide a visible veto between preparation and the selected specialized handler.

After the selected handler returns:

- A nonzero result is returned immediately.
- A zero result causes processing to continue to primary callback dispatch.

A zero result from the first specialized handler does **not** cause the second specialized handler to be tried. The choice between specialized handlers is made before either handler runs, not as a chain of handler-result fallbacks.

Calls may change descriptor contents, object contents, callback tables, globals, or storage lifetime. The function makes fresh reads at later stages rather than guaranteeing that its original classification still applies.

### 3. Primary callback dispatch

This stage is reached when specialized handling was bypassed or a selected specialized handler returned zero.

The function rereads the descriptor tag at offset `0x04`.

- If the current tag is `0x16`, it reads the current nested-record address and then the current nested discriminator.
- For any other current tag, it does not read the nested discriminator during this stage.

It selects the callback-table offset as follows:

- `0x10C` when the current tag is `0x16` and the current discriminator equals `0x2A`.
- `0x110` otherwise.

Only after this classification does it read the object’s callback-table reference and the selected callback address. It invokes that callback with the original object reference and original descriptor reference, in that order.

If the callback returns nonzero, the function returns that result immediately. If it returns zero, processing continues to the secondary eligibility check.

The `0x2A` decision is independent of comparison A and comparison B. It uses a newly read discriminator, not a value retained from specialized classification.

### 4. Secondary callback eligibility

After a zero primary-callback result, the function rereads the descriptor tag.

If the current tag is not `0x0F`, it returns zero without reading the descriptor payload or the object’s comparison word for this check.

If the current tag is `0x0F`, it:

1. Reads the descriptor word at offset `0x08`.
2. Reads the object word at offset `0x50`.
3. Compares the two complete 32-bit words.

If they differ, the function returns zero.

If they are equal, it rereads the object’s callback-table reference, reads the callback address at table offset `0x0E0`, and invokes that callback with the original object and descriptor references.

A nonzero secondary result is returned unchanged. A zero secondary result produces the final result zero. No further dispatch stage is shown.

### Read freshness

The following decisions deliberately use later reads:

- The second specialized comparison rereads the nested address and discriminator.
- Primary callback selection rereads the descriptor classification after specialized handling.
- Secondary eligibility rereads the tag after the primary callback.
- The secondary callback lookup rereads the object’s callback-table reference.

Thus, a primary callback may change a descriptor into or out of secondary eligibility before returning zero. Likewise, specialized handling may change which primary callback slot is subsequently selected.

The evidence supplies no synchronization or concurrent-access guarantees.
