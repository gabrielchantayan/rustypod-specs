# F-26223c98f73e

## Purpose

F-26223c98f73e conditionally retrieves a 32-bit value through an object reference supplied by its second argument.

The second argument exclusively controls whether retrieval occurs. When it is zero, the function returns zero without dereferencing either argument. When it is nonzero, the function reads an address-bearing field at byte offset `0x244` within the referenced object. If that field is nonzero, the function returns the 32-bit field at byte offset `0x10` within the resulting referenced object. Otherwise, it returns zero.

The first argument does not affect the returned value or determine any memory access in the supplied representation. In particular, it is not a fallback reference when the second argument is zero or when the intermediate field is zero.

This is an access contract, not a semantic classification of the retrieved value. The evidence does not establish whether that value represents a number, flags, a handle, an address, or some other four-byte payload.

## Behavior

### Retrieval selection

The function first distinguishes a zero second argument from a nonzero second argument.

For a zero second argument, the result is zero. No object field is read. This remains true even when the first argument is nonzero and could otherwise designate readable memory.

For a nonzero second argument, the function obtains the intermediate reference from offset 580 in the starting object. The first argument's supplied value has no influence on the subsequent decision.

### Conditional final access

The intermediate reference is tested against zero.

If it is zero, the function returns zero without attempting an access at offset 16.

If it is nonzero, the function reads the four-byte field at offset 16 from the object designated by that reference. The retrieved four-byte value becomes the return value.

There is no visible additional condition on the final value. A final field containing zero is returned as zero; a final field with its most significant bit set is returned with that bit preserved.

### Observable access order

The supplied representation establishes this order for the data-memory reads involved in retrieval:

1. The intermediate-reference field is read from the starting object.
2. If the retrieved reference is nonzero, the final field is read from the referenced object.
3. The selected 32-bit result is returned.

The second read depends on the value produced by the first. No second object-field read is shown when that value is zero.

At the level represented by the supplied evidence, the function performs:

- No retrieval-related data-memory reads when the second argument is zero.
- One four-byte field read when the second argument is nonzero and the intermediate reference is zero.
- Two four-byte field reads when both references are nonzero.

These counts describe the explicit field accesses, not instruction fetching, stack activity, speculative execution, or machine-level bus transactions.

### Width and address arithmetic

Both field offsets are byte offsets. They are not element counts and are not scaled by the width of the accessed field.

The additions of 580 and 16 have no visible bounds or overflow checks. The contract therefore makes no promise of safe behavior for values whose effective addresses cannot be represented or accessed correctly in the target environment.
