# F-3684fd08b97d

## Purpose

F-3684fd08b97d requests an object associated with an embedded region of a caller-supplied record. It clears the record’s object-pointer slot, selects construction parameters using a classification result, calls a construction dependency, and stores the returned pointer.

The local success condition is narrow: construction must return a non-null pointer, and the object’s 32-bit field at byte offset 24 must differ from 0xFFFFFFFF. A null pointer produces failure. A non-null object with the sentinel field invokes an indirect callback before the record slot is cleared and failure is reported.

On normal return, the 64-bit result contains a status in its low 32 bits and the first selected configuration word in its high 32 bits. Success therefore does not necessarily produce a numerically zero 64-bit result.

The supplied representation establishes these operations, not their resource-level meaning. Describing the dependencies as classification and construction identifies their roles in this function; it does not establish their complete contracts. Ownership of the record, intermediate value, and resulting object is unknown.

|---|---|

## Behavior

### Entry and classification

The first visible operation is a four-byte zero write to the record’s object-pointer slot at offset 8.

The function does not first read or release the slot’s previous value. If the slot held an object pointer, that reference is overwritten without visible processing. Whether this loses an ownership reference depends on an unavailable surrounding contract.

After clearing the slot, the function calls F-7a47d707217e with the address of the embedded region at offset 12.

Only whether the classification result is zero matters locally. All nonzero results select the same branch; no separate handling of negative or particular positive values is established.

### Configuration selection

Both branches call F-8157a180d901 once with the value 84, equivalently 0x54. Its 32-bit result is retained as the first construction argument.

The selected parameters are:

| Classification result | Mode | First configuration word | Second configuration word |
|---|---:|---|---|
| Zero | 0 | Record word at offset 268 | Record word at offset 272 |
| Nonzero | 4 | 1024, or 0x400 | 1 |

On the zero-classification path, the visible order is:

1. F-8157a180d901 returns.
2. The word at record offset 268 is read.
3. The word at record offset 272 is read.

These reads occur after classification as well. They capture the values present at those later read points, not values saved at entry. Changes made through aliases or accessible state by either earlier dependency can therefore affect the selected configuration.

On the nonzero-classification path, this function does not directly read either configuration field. This is not a guarantee that the dependencies avoid those fields.

The meaning of 84 is unknown. Its use as an argument alone does not establish an allocation size, resource identifier, or byte count.

### Null construction result

- The construction-result store writes zero to the record slot.
- No object field is read.
- No indirect object callback is invoked.
- The low return word is three.
- The high return word is the selected first configuration word.

The initial slot clearing and the later null-result store are distinct writes in the supplied representation, even though both write zero.

There is no visible separate release of the intermediate value returned by F-8157a180d901. Its disposition inside construction is unknown.

### Accepted non-null result

For a non-null construction result, the function reads the 32-bit field at object offset 24.

If that field differs from 0xFFFFFFFF:

- The low return word is zero.
- The high return word is the selected first configuration word.
- No indirect callback is made.
- This function performs no further write to the record slot after publishing the construction result.

This establishes only local acceptance. It does not establish the object’s type, ownership, lifetime, readiness for other operations, or validity under an unavailable external contract.

### Rejected non-null result

If the acceptance field equals 0xFFFFFFFF, the function performs these operations in order:

1. Reads the dispatch-table address from object offset 0.
2. Reads the callable entry at dispatch-table offset 4.
3. Invokes that target.
4. If the invocation returns normally, writes zero to record offset 8.
5. Returns with status three and the selected first configuration word.

No explicit arguments are shown for the indirect invocation. This does not establish that the target has no inputs: implicit calling-convention state and any receiver convention remain unknown.

The rejected pointer has already been published before this callback. If no intervening behavior changes the slot, a callback able to reach the record can observe that pointer there.

If the callback changes the record slot and returns normally, the following zero write overwrites its change. If it releases or invalidates the record storage, the subsequent write may no longer be valid; normal completion requires that write to remain permissible.

If the callback does not return normally, neither the final clearing nor the normal failure return is established.

## Side effects

### Direct memory operations

The direct record writes are:

- An unconditional four-byte zero write at offset 8 before classification.
- A four-byte construction-result write at offset 8 after construction returns.
- A further four-byte zero write at offset 8 after a sentinel-rejection callback returns normally.

Direct record configuration reads occur only on the zero-classification path, at offsets 268 and 272, in that order.

Direct object reads are conditional:

- Offset 24 is read only for a non-null result.
- Offset 0 and dispatch-table offset 4 are read only after sentinel rejection.

These are the function’s visible accesses, not a complete bound on all memory traffic during the operation. Dependencies and the indirect target may access or modify additional memory, globals, external resources, or the record itself.

### Ownership and lifetime

Record ownership is unknown. The function’s access through the supplied address establishes neither caller ownership nor transfer of record ownership.

No direct operation releases the previous slot value. No separate release of the intermediate dependency result is visible. The indirect callback may perform cleanup, but identifying it as a destructor or asserting that it frees the rejected object would exceed the evidence.

Likewise, storing an accepted pointer does not by itself establish whether the record owns it, borrows it, or shares it. Those distinctions remain documented_only.

### Synchronization and abnormal completion

No locking, atomic publication protocol, rollback, explicit exception handling, or synchronization is visible. The publication of an object before local acceptance is an ordering fact, not a thread-safety guarantee.

The function does not visibly restore the previous slot value on any path. A dependency fault, nonlocal exit, or nontermination may leave only an earlier prefix of the described writes completed. Such cases have no established normal return value.
