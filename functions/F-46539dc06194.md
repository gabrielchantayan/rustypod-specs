# F-46539dc06194

## Purpose

F-46539dc06194 performs up to two ordered checks against an object. Each route first checks a supplied selector against a shared descriptor. If that check returns nonzero, the function calls a preparation dependency and then checks a local two-word payload against an object-specific descriptor.

First-route success writes byte value `1` at object offset `0x61` and returns the 32-bit value `1`. Second-route success writes byte value `1` at object offset `0x62` and returns `1`. Otherwise, the function returns the 32-bit value `0`.

The second route is considered only after the first route fails, and only if the byte at object offset `0x61` is nonzero when subsequently read.

The shared-base global is evaluated twice before the first dependency call. The first evaluation supplies a saved base for the second route; the second evaluation supplies the base for the first route. Equality of these two values is not an unconditional part of this contract.

“Selector,” “descriptor,” “payload,” and “route” describe call-site roles. Their domain meanings are not established.

### Shared-base evaluations and layout

A shared global supplies address values. The function evaluates that global twice:

| Evaluation | Timing | Use |
|---|---|---|
| First | Before either payload word is initialized | Saved for a possible second-route descriptor read at offset `0x34`. |
| Second | After both payload words are initialized, before the first dependency call | Used for the first-route descriptor read at offset `0x30`. |

Each descriptor read is four bytes wide.

The two evaluations are distinct in the supplied representation. No dependency call occurs between them. Under an explicit assumption that the global remains stable across this interval, they yield the same base. Without that assumption, the contract does not equate them.

The second route uses the saved first value. It does not reevaluate the global when that route is reached.

All results from F-a1e68ae27737 are interpreted solely as zero or nonzero. Their magnitude and sign are not propagated. A negative result therefore takes the same branch as any other nonzero result.

There is no explicit validation, error return distinct from `0`, rollback, or recovery path. A dependency error represented by a nonzero result is treated as nonzero; a dependency error represented by zero is treated as zero. Actual dependency error conventions are unknown.

## Behavior

### Entry ordering

Before the first dependency call, the established order is:

1. Evaluate the shared-base global and retain its value for the possible second route.
2. Initialize the first local payload word from the third argument.
3. Initialize the second local payload word from the fourth argument.
4. Evaluate the shared-base global again.
5. Read the four-byte descriptor at offset `0x30` from the base obtained by that second evaluation.
6. Invoke the first selector check.

This distinction matters independently of whether the two global evaluations happen to return equal values. The saved first value is not the source of the first descriptor’s base.

The payload is initialized once. No later route restores its words from the original arguments.

### First route

F-a1e68ae27737 receives:

- The original selector as its first argument.
- The descriptor loaded from offset `0x30` of the second global-evaluation value as its second argument.

If this call returns zero, the first route stops without a preparation or payload-check call.

If it returns nonzero, F-1ece76539767 receives, in order:

- The local payload address.
- The object address.
- The integer literal `1`.

No return value from F-1ece76539767 is inspected.

After preparation returns, the function reads the four-byte descriptor at object offset `0x68`. It then invokes F-a1e68ae27737 with the local payload address and that descriptor.

The descriptor read occurs after preparation, not before it. Consequently, a preparation-induced change to this object field can affect the payload check.

A nonzero payload-check result causes a one-byte write of `1` at object offset `0x61`, followed immediately by return value `1`. The second-route gate and second-route checks are not reached.

A zero payload-check result transfers control to the second-route gate without undoing dependency effects.

### Second-route gate

After either kind of first-route failure, the function reads the byte at object offset `0x61`.

- Zero causes return value `0`.
- Any nonzero byte permits the second route.

The test does not require the byte to equal `1`. Whether the byte is interpreted as signed or unsigned does not change this zero/nonzero decision.

This is a post-failure read, not a saved entry value. Any preceding dependency effects on that byte can affect eligibility.

### Second route

When the gate passes, the function reads the four-byte descriptor at offset `0x34` from the base saved by the first global evaluation.

This read occurs at second-route execution time. The base is retained, but the descriptor contents are not an entry-time snapshot. Changes to the contents at that saved address can therefore affect the check. Merely changing the global does not redirect the read.

F-a1e68ae27737 receives the original selector and this descriptor. A zero result returns `0` without a second-route preparation call.

A nonzero result causes F-1ece76539767 to receive the local payload address, object address, and integer literal `1`, as in the first route.

The dependency receives the payload’s current contents. There is no reinitialization between attempts. Any changes made during earlier calls remain unless another dependency changes them.

After this preparation returns, the function reads object offset `0x68` again and invokes F-a1e68ae27737 with the local payload address and the newly read descriptor.

- Nonzero causes a one-byte write of `1` at object offset `0x62`, followed by return value `1`.
- Zero causes return value `0`.

Second-route success does not itself write object offset `0x61`.

### Work and arithmetic bounds

There are no loops or retries. Assuming normal dependency returns, an invocation makes:

- One to four calls to F-a1e68ae27737.
- Zero to two calls to F-1ece76539767.

The longest dependency sequence is first selector check, first preparation, first payload check, second selector check, second preparation, second payload check.

The function performs no visible arithmetic on payload contents and no accumulation of dependency results. Address formation uses fixed byte offsets. The supplied evidence does not establish a portable overflow rule for invalid address values; these accesses are contracted only for valid addressed storage.

## Side effects

### Direct writes

The function directly writes:

- The two local 32-bit payload words during initialization.
- Byte value `1` at object offset `0x61` on first-route success.
- Byte value `1` at object offset `0x62` on second-route success.

Neither state byte is directly cleared. Neither shared descriptor nor the object descriptor is directly written by this function.

Only one direct success write can occur in an invocation because either success returns immediately. This does not constrain writes performed by dependencies.

Return value `0` establishes that neither direct success write was reached. It does not establish that object state, payload contents, shared state, or other memory remained unchanged.

Likewise, first-route success imposes no final value on offset `0x62`, and second-route success imposes no final value on offset `0x61`, beyond effects already caused by existing state and dependencies.

## Acceptance examples

These are conditional deductions, not executed tests. Each assumes valid reached accesses and normally returning dependencies. Any absence of dependency mutation stated below is an explicit scenario assumption, not a general dependency guarantee.

1. **First-route success.**  
   The first selector and first payload checks both return nonzero. The function makes one preparation call, writes byte `1` at `0x61`, and returns `1`. It does not read the second-route gate or load the second-route descriptor.

2. **Immediate failure with a closed gate.**  
   The first selector check returns zero, and the subsequently read gate byte is zero. The function returns `0`, makes no preparation calls, and performs neither direct success write. Both initial global evaluations have nevertheless occurred.

3. **Second-route success without first preparation.**  
   The first selector check returns zero, the gate byte is nonzero, and both second-route checks return nonzero. The function makes one preparation call, writes byte `1` at `0x62`, and returns `1`.

4. **Payload reuse after first payload failure.**  
   The first selector check returns nonzero. First preparation changes a payload word, and the first payload check returns zero without undoing that change. If the gate and second selector permit continuation, second preparation receives the changed payload, not a fresh copy of the input words.

5. **Gate changed by a dependency.**  
   The gate byte starts at zero. A reached first-route dependency changes it to a nonzero value, and the first route fails. The later read permits the second route. Conversely, if dependencies leave it zero at that read, the second route is skipped.

6. **Object descriptor changed during preparation.**  
   Preparation changes the four-byte field at `0x68`. The following payload check receives the value loaded after that change, assuming no intervening external mutation.

7. **Stable initial global.**  
   If the shared-base global is stable across its two initial evaluations and yields address A, the first-route descriptor comes from A plus `0x30`, and any second-route descriptor comes from A plus `0x34`. Their contents are still read at different times.

8. **Different initial evaluation values.**  
   Conditional on an execution model permitting the first global evaluation to yield A and the second to yield B, the first-route descriptor comes from B plus `0x30`; a reached second-route descriptor comes from A plus `0x34`. The supplied evidence does not establish how such differing observations could arise.

9. **Global replaced during a dependency call.**  
   After both initial evaluations, a dependency replaces the global with address C. A reached second-route descriptor still uses the saved first value, not C. Changes to descriptor contents at the saved address can affect that later read.

10. **Negative result and failed-check side effects.**  
    A negative check result takes the nonzero branch. A zero result does not trigger rollback: dependency mutations remain even if the function ultimately returns `0`.
