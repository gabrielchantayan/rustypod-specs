# F-b869f0786795

## Purpose

F-b869f0786795 chooses a record associated with a captured context. It either reuses a record reached through the context’s linked list or initializes the record designated separately by that context. It then invokes F-d4c4416ace75 with the context and chosen record, returning the chosen address if the dependency returns normally.

Selection is order-sensitive. Matching keys are necessary but insufficient: eligibility, a truncated distance, a strict acceptance bound, early termination, and a final reuse condition also apply. The behavior is therefore not equivalent to finding the nearest matching record or preferring every exact match over every approximate match.

An incoming processor condition affects target preparation and can cause a byte write before context acquisition.

**Established:** These selection, initialization, and invocation effects are visible in the supplied static material.

**Inferred intent:** The routine appears to reuse a suitable record or prepare a designated alternative. Allocation, cache management, ownership transfer, and application-level scheduling are not established.

## Behavior

### Target preparation and context acquisition

When the incoming zero condition is set, the effective target is the unadjusted target argument. There is no initial byte write.

When that condition is clear, the effective target is the target argument advanced by 3,068 bytes. The function writes a zero byte at the original target address before reading the context binding.

Selection uses the effective target as an address-valued numerical quantity. It does not use the contents of the cleared byte.

This order is observable under aliasing. The initial write can change the context binding, a context field, a record field, or later classification input if the addresses overlap. Subsequent reads observe storage after that write.

After preparation, the context address is captured and its list head is read. Selection starts with no candidate and the external initial acceptance bound.

### Traversal and eligibility

Records are visited in next-link order. Field access is conditional:

- The first key is examined before the second.
- The second key is read only when the first matches.
- The eligibility field is read only when both keys match.

The eligibility check treats the 16-bit position field as signed and rejects exactly negative one, the bit pattern `0xFFFF`. It does not reject every pattern with the high bit set.

A record that passes this check undergoes another 16-bit read of the same field, this time widened without sign extension for target comparison and ranking. With stable storage, eligible positions therefore range from zero through 65,534. For example, `0xFFFE` is eligible and ranks as 65,534, not as negative two.

The two position reads are distinct. The function does not establish a snapshot or synchronization protocol. If storage changes between them, the ranking read can differ from the eligibility read; it could even produce 65,535 after the earlier read passed.

Whenever processing continues to another record, the next address is read from the current record’s offset 0. An exact-match exit or an accepted distance-one exit bypasses that next-link read. Consequently, a next-link access is not required merely because other fields in that record were inspected.

### Selection and ranking

A reached eligible position that equals the effective target is selected immediately. Traversal ends, and the distance used by the final reuse decision is zero. Exact selection does not depend on the acceptance bound.

For a nonexact position, ranking retains only the low 16 bits of the computed difference. Under ordinary numerical address ordering and representable subtraction, this is the absolute difference between position and target, reduced modulo 65,536. It is not a full-width distance.

The supplied material compares address-valued quantities and forms the difference through 32-bit integer expressions. A portable language-level interpretation at overflow or address-space boundaries is not established. The modulo-distance description applies subject to those arithmetic qualifications.

A nonexact record replaces the current candidate only if its reduced distance is strictly smaller than the current bound. Replacement also lowers the bound to that distance.

This has several consequences:

- Equality with the bound is rejection.
- Equal-distance nonexact ties preserve the earlier accepted record.
- A nonexact record can have reduced distance zero.
- Once zero is accepted, no later nonexact distance can improve the bound.
- Exact selection remains independent of the bound, if an exact position is subsequently reached.
- An accepted distance of one ends traversal immediately.
- A rejected distance of one does not end traversal.
- An accepted nonexact distance of zero does not itself end traversal.

The distance-one exit makes list order significant beyond tie-breaking. It can prevent examination of a later exact match or a later record whose truncated distance would be zero.

With stable eligible fields, exact equality is possible only for effective targets from zero through 65,534. Larger targets may still obtain small reduced distances through truncation.

### Reuse versus initialization

Finding a candidate does not guarantee reuse.

At ordinary list exhaustion, the final comparison distance is the current acceptance bound. An exact-match exit supplies zero instead; an accepted distance-one exit supplies one.

Initialization is chosen if no candidate exists. If a candidate exists, initialization is also chosen when the effective target is strictly less than the final comparison distance.

Otherwise, the candidate is reused. Equality between target and final distance permits reuse.

The no-candidate case takes precedence: initialization does not require a target comparison when selection found nothing. A bound that rejects every nonexact record therefore leads to initialization unless a reached exact match is selected.

### Initialization and classification

Initialization uses the address read from context offset 8. No distinctness requirement is checked between that destination and the context, traversed records, target storage, or first-key-derived classification storage.

Before classification, the destination receives these writes in the following observable order:

| Order | Destination offset | Width | Value |
|---:|---:|---:|---|
| 1 | 8 | 32 bits | First key |
| 2 | 24 | 32 bits | Second key |
| 3 | 12 | 16 bits | Zero |
| 4 | 28 | 32 bits | Zero |
| 5 | 32 | 16 bits | Zero |
| 6 | 36 | 32 bits | Second key |
| 7 | 40 | 16 bits | Zero |

Only afterward is the 16-bit classification input read from the first-key address plus two. The destination’s offset 34 then receives the 16-bit value one if that input equals `0x482B`, or zero otherwise.

The signed interpretation of the classification read does not alter this equality: `0x482B` is representable as a positive signed 16-bit value.

Classification observes memory after all seven preceding writes. It must not be specified as a read of the entry-time contents when aliasing is possible. The classification output is written after the classification input has been read.

There is no visible allocation, linkage update, or rollback. If execution cannot complete a later access, earlier writes have already occurred; the function does not establish transactional initialization.

### Dependency invocation and return

Both reuse and initialization converge on one invocation of F-d4c4416ace75. Its arguments are the captured context address and the chosen record address.

The dependency’s result is not used. If it returns normally, F-b869f0786795 returns the chosen address without rereading the context binding or checking the record’s contents or lifetime.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, assume valid storage, stable fields, no interfering aliasing, a set incoming zero condition, ordinary numerical address ordering, representable arithmetic, and a normally returning dependency. “Qualifying” means both keys match and eligibility passes.

1. **Empty list.** A zero list head causes initialization at the address designated by context offset 8. That address is passed to the dependency and returned.

2. **Exact match bypasses the bound.** With effective target 200, a reached qualifying position of 200 is selected even when the initial bound is zero.

3. **Early exit hides an exact match.** With target 200 and initial bound greater than one, qualifying positions 199 followed by 200 select the first record. Its accepted distance one ends traversal before the second record is inspected.

4. **Eligibility is not a general negativity test.** A stable position of `0xFFFF` is excluded. A stable position of `0xFFFE` passes and is ranked as 65,534.

5. **Strict threshold and ties.** With target 100 and bound 10, position 90 is rejected. With a bound greater than 10, positions 90 followed by 110 retain the first record because the second has an equal distance.

6. **Rejected distance one continues.** With target 100 and bound one, position 99 is rejected without terminating traversal. A subsequent position of 100 can be selected exactly.

7. **Accepted candidate can still be discarded.** With target 2, an initial bound greater than eight, and only a qualifying position of 10, the candidate is accepted at distance eight. Initialization nevertheless follows because two is less than eight.

8. **Final equality permits reuse.** With target one and bound greater than one, position zero is accepted at distance one. The final comparison permits reuse.

9. **Truncated zero does not terminate traversal.** Target 65,636 and position 100 differ by 65,536. A positive bound accepts the reduced distance zero, but traversal continues. A later nonexact zero-distance record cannot replace it.

10. **Clear incoming condition.** With target argument address 1,000, the initial byte write occurs at address 1,000 and the effective target is 4,068.

11. **Classification follows initialization writes.** A classification input of `0x482B` produces one at destination offset 34; every other readable 16-bit value produces zero. If the input overlaps an earlier initialization write, its expected value is determined after that write.

12. **Early exit avoids the next-link access.** A reached exact record is selected without reading its next-link field. This does not remove the need for its previously accessed fields to be readable.
