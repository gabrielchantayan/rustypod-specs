# F-e16c86f74c14

## Purpose

F-e16c86f74c14 performs an ordered chain of indirect invocations, transforms primary and secondary results, modifies memory through computed and literal addresses, and finishes with an unresolved four-argument indirect invocation.

**Established static evidence:** the represented operation is stateful. Observable effects include dependency invocations, retained intermediate values, byte and word reads, 8-, 16-, and 32-bit stores, repeated writes, overlapping access ranges, and accesses to low numeric addresses.

**[INFERENCE] Intent:** recurring offsets and pointer-like words suggest updates to related state records. They do not establish an object model, allocation scheme, protocol, or application purpose.

**Contract status:** unresolved behavior is documented_only. In particular, this document does not turn unknown dependency effects or target-specific arithmetic into assumed preservation guarantees or portable execution rules.

## Behavior

Most subsequent represented targets are constructed from successive code-location values plus 4094 bytes. This construction does not establish dependency identity.

Invocation arguments include:

Arithmetic deductions and acceptance examples use a **conditional 32-bit bit-vector model**: additions, multiplication, and left shifts retain the low 32 bits; unsigned right shifts insert zeros. This does not establish portable semantics for overflowing signed expressions.

A late signed right shift uses a count derived from an address’s low byte. Negative operands and counts of at least 32 require target-specific interpretation. No count normalization is established.

### Opening memory effects and zero readback

The last invocation in the chain produces a represented pair. Its upper word supplies an address whose offset 0x14 receives the link base. The upper word’s low byte is stored at link-base offset 0x09. The packed base is stored as a word at an address formed from the final lower word multiplied by 256, plus 0x54. Link-base offset 0x09 then receives the link base’s low byte.

Packed-base offset 0x14 is cleared as a word before the byte at packed-base offset 0x05 is captured. Narrow-base offset 0x14 is then cleared. The captured byte is widened unsigned and stored as a word at packed-base offset 0x34, before the word readback at packed-base offset 0x14.

**Under the 32-bit bit-vector model and ordinary byte-addressable memory without external modification, this readback is zero.** The intervening narrow-base store writes only zero bytes, even if it overlaps the cleared word. The four-byte ranges at packed-base offsets 0x14 and 0x34 are disjoint, including with modular address arithmetic. Those represented stores cannot produce an alias-driven nonzero readback.

Device-backed read behavior, address mirroring, or external modification is documented_only and is not part of that ordinary-memory deduction.

After the readback, narrow-base offset 0x14 is cleared again, followed by two byte stores of the readback’s low byte at narrow-base offset 0x15. Under the ordinary-memory model, both byte stores write zero.

Only then is numeric address 0x05 read to obtain the low-derived base. Numeric address 0x01 receives the narrow base’s low byte, and low-derived-base offset 0x15 receives the narrow field’s low byte.

## Acceptance examples

These are conditional static deductions, not executed tests.

### Input truncation

With third input 1 and 32-bit bit-vector shifts, the initial scaled value is 8 and its ten-position left shift is 8192. With only original bit 29 set, the initial three-position shift yields zero.

### Narrow-base boundary

A narrow-field producer of 1 yields narrow field 4 and narrow base 8. A producer whose low seven bits are all set yields narrow base 1016. Moving the mask before the shift is not equivalent.

### Opening zero readback

Assume ordinary byte-addressable memory, modular 32-bit addresses, successful accesses, and no external modification. Even if narrow-base offset 0x14 overlaps packed-base offset 0x14, the opening readback is zero: both relevant clears write zeros, and the packed-base offset-0x34 store is disjoint.

The subsequent working-word store through that readback targets numeric address 0x54. A nonzero readback requires behavior outside these assumptions, not merely aliasing among the represented intervening stores.

### Unsigned widening

A byte 0xFE captured at packed-base offset 0x05 supplies word value 254 at offset 0x34, not a sign-extended negative value.

### Global capture timing

If the numeric-0x60 word store overlaps the global storage, the repeated block still uses the base captured before that store.

### Intervening-store precedence

Suppose repeated-block-base offset 0x74 and adjusted-base offset 0x10 designate the same word. Let the retained offset-0x04 capture be 0x11223344 and the captured offset-0x40 word be 0x55667788. Under ordinary memory, immediately after the offset-0x10 store that word contains 0x55667788. Reversing the stores would instead leave 0x11223344.

### Capture boundary and fresh reads

If doubled-terminal-base offset 0x14 overlaps numeric address 0x3A, its capture reflects the preceding byte mutation according to target byte order. The 0xA9 and scaled-terminal captures have already occurred.

If computed stores later change numeric address 0x67, subsequent copies use the freshly read bytes, not an immutable initial assignment.

### Literal-100 overlap

If late-destination-base offset 0x54 equals late-source-base offset 0x74, ordinary memory without intervening modification yields final argument four equal to 100.
