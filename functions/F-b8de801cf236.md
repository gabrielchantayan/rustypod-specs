# F-b8de801cf236

## Purpose

The established behavior is the call order and argument relationship. The first and last dependency calls receive a value derived from the first input by adding 328. The middle dependency receives all three original inputs.

The arrangement is consistent with entering and leaving a protected region, but that interpretation is **inferred intent**, not an established synchronization contract. The available evidence does not identify the auxiliary operations as locking, reference management, initialization, or any other specific mechanism.

## Behavior

3. After F-aux-A returns normally, invoke F-c987c48e35de with the original first, second, and third input values, in that order.
4. Retain the 32-bit result returned by F-c987c48e35de.
5. Invoke F-aux-B with the first input plus 328.
6. After F-aux-B returns normally, return the retained result.

Each dependency is called once on this normal path. There is no visible loop, retry, conditional dispatch, or alternative return path.
