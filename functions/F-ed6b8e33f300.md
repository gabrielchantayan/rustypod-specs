# F-ed6b8e33f300

## Purpose

F-ed6b8e33f300 performs a long ordered sequence of indirect calls, constructs arguments from call-produced values, and then mutates memory through fixed and computed addresses before a final unresolved transfer.

No application-level purpose is established. Repeated offsets do not establish an object schema; character-like constants do not establish text output. Allocation, initialization, collection management, and device control are not proven roles.

This contract distinguishes:

- **Established static evidence:** represented operations, operand widths, value dependencies, and ordering.
- **[INFERENCE]:** interpretations that are not acceptance requirements.
- **documented_only:** unresolved behavior requiring information absent from the supplied material.

Execution requirements are conditional on the static representation accurately describing the executable and on execution reaching each operation.

## Interface

### Inputs and outputs

The represented interface has no explicit parameters and no explicit return value.

Implicit inputs include incoming control state, indirect-call results, additional call-produced machine-state words, computed-address memory, and named global state associated with fixed addresses. Dependencies may modify memory before subsequent reads; there is no entry-time snapshot guarantee.

Observable effects include:

## Behavior

### Indirect calls and argument construction

The call phase is straight-line in the supplied representation. No represented conditional branch selects a shorter call sequence.

The initial target derives from incoming control state plus 0xffe. Later targets derive from represented control-location values using the same displacement. Their identities and complete interfaces remain unresolved.

Discarded results do not make calls removable. An empty represented argument list does not prove that a dependency consumes no machine state. Calls cannot be merged or treated as pure without an independent dependency contract.

Argument construction includes:

- Left shifts of returned words, frequently by eight bits.
- Separation of combined results into low and high words.
- Forwarding a high word unchanged alongside shifted low-word forms.
- Several shifted forms of one captured result.
- Explicit zeros alongside fresh and retained results.
- Masking before shifts.
- Reuse of older values after intervening calls.
- Arguments obtained from additional call-produced machine-state words rather than the explicitly captured scalar result.

Values from different call occurrences are not interchangeable. Reinvoking a dependency does not reproduce an earlier capture.

### Arithmetic rules and limits

Represented words are 32 bits. Unsigned word operations must not silently retain high bits from wider intermediates. Explicit unsigned right shifts are logical.

Masks select fields including 24, 22, 21, 20, 19, 18, 17, 16, 15, 14, 13, 12, 11, and one bit. Masking before a shift is not generally equivalent to shifting first.

Logical extraction from a combined result at positions 34, 36, and 44 corresponds to logical right shifts of its high word by 2, 4, and 12. Some such extractions use an older retained result, not the latest combined result.

Explicitly zeroed local words remain zero through the represented shifts. This establishes no preservation guarantee for globals or dependency-accessible memory.

Many left shifts, additions, and multiplications have signed 32-bit operands. Portable overflow behavior is not established. Examples that depend on truncating machine arithmetic state that assumption explicitly.

A late signed right shift uses the adjusted base’s low eight bits as its count. Negative-operand behavior and counts of 32 or more remain **documented_only**; no automatic count masking is assumed.

### Opening memory mutations

At the end of the call phase, retained values include a final combined result, an earlier word shifted left by eight, a call result multiplied by 2²⁵, another retained result shifted left by 25, and a small index obtained by masking a shifted word to 15 bits and logically shifting right by six.

The opening ordered effects are:

1. A 32-bit store at the final high word plus 0x14, containing the retained 25-bit-shifted value.
2. An 8-bit store at that retained shifted value plus 0x09, containing the final high word’s low byte.
3. A 32-bit store at 256 times the final low word plus 0x54, containing the separately retained 2²⁵-scaled result.
4. Another 8-bit store at the same offset-0x09 destination, containing the retained shifted value’s low byte.

The two byte stores have different source expressions, not necessarily different byte values. Their destination is not the earlier eight-bit-shifted word.

The 2²⁵-scaled base’s offset-0x14 word is cleared. An explicit unsigned 8-bit read at its offset 0x05 is captured, a word at twice the small index plus 0x14 is cleared, and the captured byte is zero-extended into a 32-bit store at scaled-base offset 0x34.

The previously cleared scaled-base word is read back before another clear at twice-index offset 0x14. Its returned value supplies later destinations and two consecutive byte stores at twice-index offset 0x15. That read is not replaceable with assumed zero without memory and aliasing guarantees.

### Fixed-state capture and linked updates

After those consecutive byte stores, named state associated with address 0x05 is read and converted to an unsigned 32-bit captured value. **This capture precedes the assignment to named state at 0x01.**

The source declaration at 0x05 is unavailable. Neither an 8-bit access nor zero-extension is established. The captured value is therefore not generally constrained to 0–255.

After the 0x01 assignment, the captured value supplies a base for an explicit byte store at offset 0x15. Several other computed-address stores occur before a 32-bit read at captured-base offset 0x54. That loaded word is retained before the same location is overwritten with the earlier scaled-base readback.

The capture must not be replaced by a later global read, nor moved after the 0x01 assignment.

The linked region then interleaves:

- Word reads at offsets 0x54 and 0x74 with accesses through their results.
- Self-referential word stores at offsets 0x14, 0x24, and 0x54.
- Two-, four-, and eight-times scaling of loaded words.
- Repeated byte stores at offsets 0x09 and 0x15.
- Byte stores at offsets 0x0d and 0x11.
- Word accesses at offsets 0x04, 0x34, 0x44, and 0x64.
- Assignments to named state at 0x54 and 0x15, whose memory widths remain unresolved.

Explicit unsigned byte reads at computed offset 0x05 are distinct from the named-global read associated with fixed address 0x05. The computed reads do establish eight-bit values, and those values supply bases for word reads at offset 0x74.

Repeated reads remain separate operations. This includes an expression that reads twice from a linked offset-0x74 location while constructing a self-store; equality of the two observations and their within-expression evaluation order are not established. A later byte-derived access chain is also evaluated again rather than replaced with an earlier captured result.

For the remaining description, the **adjusted quantity** is that subtraction result; the **adjusted base** is four times that result. These are descriptive roles, not source identifiers or object types.

Four ordered 32-bit stores target adjusted-base offset 0x20:

- 0x2f.
- The zero-extended result of an explicit unsigned byte read at adjusted-base offset 0x04.

The separately stored global base is captured **after all four stores and before** the assignment of 0x20 to named state at 0x60.

The receiving base value is 32 bits. Its global access width is unresolved. The assignment at 0x60 likewise does not independently establish a 32-bit store. Neither uncertainty weakens the established ordering.

### Repeated-transfer region

The captured late base is reused throughout this region; it is not reloaded for each group.

Every represented group has four ordered computed-address stores:

| Order | Width | Effect |
|---:|---:|---|
| First | 32 bits | Store the four-times-scaled linked word at an eight-times-scaled destination plus 0x54 |
| Second | 8 bits | Store the adjusted base’s low byte at captured-base offset 0x19 |
| Third | 8 bits | Store the captured base’s low byte at adjusted-base offset 0x11 |
| Fourth | 32 bits | Store an eight-times-scaled quantity at captured-base offset 0x34 |

The first group uses the earlier retained linked word for the first destination’s eight-times-scaled base and for the fourth store’s payload.

Subsequent groups instead use the adjusted quantity in both positions. Their first-store payload remains the same four-times-scaled linked word associated with the preceding 0x3a stores.

The final visible group is complete: its fourth store follows both byte stores and precedes the next global read associated with address 0xa9.

Repetition cannot be reduced to final memory contents. Exact numerical multiplicity is **documented_only** in this contract; the first-group distinction, group-internal order, and complete final group are established.

### Final mutations and transfer

After the repeated groups, named state at 0xa9 is captured into a 32-bit value. The underlying global read width remains unresolved. A separate explicit word read at offset 0x74 from the four-times-scaled linked word is also captured.

Named state at 0x3a is then assigned an expression formed from an eight-bit character conversion of the adjusted quantity, multiplication by eight, and addition of 0x30. The arithmetic expression and its placement are established; an eight-bit global store is not. Simplifying it to a modulo-256 byte result requires additional type and assignment assumptions.

Two explicit words are saved: one from offset 0x14 of an earlier twice-scaled linked base, and one from adjusted-base offset 0x04.

The following phases preserve these ordering relationships:

- Computed byte stores update the earlier linked base’s offset 0x0d and adjusted-base offsets 0x08, 0x0d, and 0x09. Offset 0x08 receives 0x6c.
- A word self-store updates the earlier linked base’s offset 0x54.
- Named state at 0x67 receives an explicitly eight-bit-reduced form of the captured 0xa9 value.
- A linked offset-0x44 word is read before named state at 0x21 is assigned a fresh read of state at 0x67.
- Adjusted-base offset 0x10 receives an explicit byte store, then later a word store sourced from an explicit word read at adjusted-base offset 0x40.
- Captured-base offset 0x54 is written first with a loaded linked value and then with the adjusted base, with the signed-shift-derived byte store between them.
- The saved adjusted-base-offset-0x04 word is forwarded to captured-base offset 0x74.

Subsequent reads of named state at 0x67 separately feed explicit byte stores at adjusted-base offset 0x09. These destination accesses are eight bits; the source global reads’ widths are not established. They must not automatically be replaced with the earlier assigned value.

Later updates restore the saved offset-0x14 word to the earlier linked base’s offset 0x54, forward the captured 0xa9 value through a computed word store, and use further word loads to establish the final linked destinations.

A late word loaded from offset 0x04 of the earlier twice-scaled linked base supplies:

- The base for explicit word reads at offsets 0x64 and 0x74.
- A destination at twice that value for a 16-bit store of 0x65.

Other final effects include an explicit word store of decimal 100 at another loaded base’s offset 0x54 and a linked word store through twice the offset-0x64 result.

The final transfer receives, in order:

1. 0x72.
2. The late offset-0x64 word.
3. The earlier saved offset-0x14 word.
4. The late offset-0x74 word.

These arguments were captured at different times. They are not a final-state snapshot.

## Acceptance examples

These are conditional static examples, not executed tests.

### Word-width arithmetic

Assuming truncating 32-bit arithmetic, shifting 0x12345678 left by eight produces 0x34567800. Passing 0x1234567800 instead would change the represented width and value.

For an unsigned high word of 0x80000008, logical right shift by three produces 0x10000001. Sign propagation is not interchangeable.

### Mask precedence

Masking 0xff123456 to 24 bits and shifting left by six produces 0x048d1580. Under 32-bit truncation, shifting the unmasked value instead produces 0xc48d1580.

### Conditional fixed-state interpretation

**If** the missing declaration for named state at 0x05 specifies an unsigned eight-bit object, and its read returns 0xff, conversion to the captured unsigned 32-bit base yields 0x000000ff. Computed offsets 0x15 and 0x54 then address 0x114 and 0x153.

Without that declaration, this example does not establish a byte read, zero-extension, or a 255 maximum. The capture-before-0x01-assignment ordering remains required independently.

### Assignment conversion versus access width

The value assigned to named state at 0x67 is explicitly reduced to eight bits. A trace requirement that its global write must therefore be exactly one byte is unsupported without its declaration.

By contrast, a computed-address byte destination receiving a later read from that state does establish an eight-bit destination access.

### Retained captures and complete groups

The late stored-base capture follows the fourth adjusted-base-offset-0x20 store and precedes the 0x60 assignment. Moving it across either boundary requires additional memory guarantees.

The final repeated group includes both byte stores followed by its offset-0x34 word store before the 0xa9 capture. Omitting that fourth store changes the established sequence.

### Equal stores and invalid memory

The opening offset-0x09 stores may contain equal bytes despite different sources. Both remain represented.

If a dependency supplies inaccessible storage, successful completion is not required. A skipped write, clean error return, or rollback must not be invented.
