# F-6f7a7331db36

## Purpose

F-6f7a7331db36 conditionally assigns a one-byte field in caller-supplied storage. It accepts exactly two selector values:

- Selector **0** assigns byte value **3**.
- Selector **9** assigns byte value **4**.

Either accepted selector produces a 32-bit return value of **0** after the assignment. Every other selector produces a 32-bit return value of **14**, without accessing the destination field.

The established behavior is this selector-to-byte mapping and its return convention. The semantic meaning of the selector, stored byte, and return values is not established. Describing the destination as a mode, status, or enumeration field would be inferred intent rather than a demonstrated contract.

The destination is the single byte at **storage base + 40 bytes**, equivalently offset **0x28**.

The function does not receive a storage length, an explicit destination pointer separate from the base, or a description of the surrounding object. It does not establish that the base denotes a particular structure type.

### Output

There is no visible null check, bounds check, object-type check, or permission check. The return value 14 reports an unsupported selector; it is not a general invalid-address result.

## Behavior

### Selector decision

The function first determines whether the selector is zero.

If it is zero, the function selects the byte value 3 for the subsequent store.

Otherwise, it determines whether the selector is nine. If it is nine, the function selects the byte value 4. If it is not nine, the function returns 14 immediately.

Acceptance uses the full selector value, not merely its low byte. A nonzero value whose low byte is zero does not qualify as selector 0. Similarly, a value whose low byte is nine but whose remaining bits are nonzero does not qualify as selector 9.

### Destination assignment

On an accepted path, the function assigns the selected value to exactly one byte at offset 40 from the supplied base.

The destination’s previous value is not read. The assignment therefore does not depend on whether that byte previously contained 3, 4, or another value. An accepted call still specifies a store when the destination already contains the selected value; there is no visible equality check that skips it.

The store is an overwrite, not a bitwise update. The function does not preserve selected bits within the destination byte, merge the new value with the old value, or inspect neighboring bytes.

After the store, the function returns 0.

### Observable ordering

The established abstract ordering is:

1. Classify the selector.
2. For an unsupported selector, return 14 without a destination access.
3. For a supported selector, store the corresponding byte.
4. Return 0 after that store completes.

There is no explicit destination-memory read on either accepted path, and no explicit destination-memory read or write on the rejected path.
