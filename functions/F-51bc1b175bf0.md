# F-51bc1b175bf0

## Purpose

F-51bc1b175bf0 repeatedly performs an ordered sequence of indirect calls, byte accesses, and 32-bit memory accesses. A late dependency result supplies the next iteration’s second argument, third argument, and additional entry-state word. The fourth argument is changed to zero before the first iteration finishes.

The represented body has no termination test or normal return path. Continued execution nevertheless depends on every intervening call returning and every memory access completing.

No application-level purpose is established. The addressed storage is not established to contain objects, device registers, allocator metadata, or a particular serialized format.

This contract describes the supplied static representation. It does not establish executable behavior beyond that representation or assign semantics to unresolved dependencies.

## Interface

### Explicit arguments and result

| Argument position | Width | Established use |
|---|---:|---|
| First | 32 bits | No direct use in the represented body. |
| Second | 32 bits | Supplied twice to the first dependency and written to memory. Replaced at the iteration boundary. |
| Third | 32 bits | Supplied as the third explicit operand of the first dependency. Replaced at the iteration boundary. |
| Fourth | 32 bits | Its low eight bits supply four direct byte stores per iteration. Its local value becomes zero late in the iteration. |

No result is returned through a normal return path. Dependency failure, nonreturn, or nonlocal control transfer is unresolved.

### Additional execution state

The explicit arguments do not fully determine execution. The body also consumes:

- An additional 32-bit entry-state word, used to calculate the first iteration’s byte-access base.
- A return-link-like entry value, used to select the first indirect call target.
- An auxiliary register value supplied to a later dependency, without a fully represented producing relationship.

The entry-state word is replaced at each completed iteration boundary. The return-link-like value is also replaced, so later iterations do not select their first call target from the original entry value.

### Widths, addressing, and notation

A **word** is 32 bits; a **byte** is eight bits. A paired result is represented as 64 bits, with distinct low and high 32-bit halves.

For concise address descriptions:

- **Word slot at scale \(s\), selected by \(x\)** means address \(20+s x\), holding a 32-bit access.
- **Selector write through base \(b\)** means an unsigned byte read at \(b+1\), followed by a byte write at address \(17+\text{read byte}\).
- **Low byte** means truncation to eight bits.
- A **scaled** or **shifted** word denotes a 32-bit result under the conditional bit-vector interpretation below.

A selector write does not write at \(b+17\). Its byte-write destination is numerically between 17 and 272, inclusive. A word store using a cached selector instead targets \(20+\text{cached byte}\), numerically between 20 and 275.

Arithmetic examples use modulo-\(2^{32}\) word operations. This interpretation is conditional: several represented expressions have signed types, and their overflow and left-shift behavior is not established as portable language-level behavior. Unsigned right shifts are logical. Address validity, alignment, endianness, and conversion of computed values into machine addresses remain environmental prerequisites.

## Dependencies

D001–D146 are unresolved indirect call occurrences. Their targets are formed from an entry or internal continuation value and a displacement. Repeated call patterns do not establish identical targets or interchangeable behavior.

The body explicitly consumes four paired results:

- D051 and D078: low and high halves used separately.
- D082 and D118: low and high halves supplied to the following call.

D105 also consumes an auxiliary register value whose producer and meaning are unresolved.

No dependency is established to preserve globals, selector storage, heap storage, ownership, or other machine state. None is established to be pure, total, nonthrowing, or guaranteed to return.

Consequently, fresh reads must remain distinct from cached values. Calls cannot be reordered across accesses merely because their explicit operands appear unrelated. Unknown dependency behavior also prevents treating repeated writes as redundant.

## Acceptance examples

These are conditional static expectations, not executed tests. Arithmetic examples assume 32-bit bit-vector semantics and successful preceding operations.

1. **Initialization-byte truncation.** A fourth argument of `0x123456AB` supplies `0xAB` to all four direct initialization stores in the first iteration. Other stores or dependencies may subsequently overwrite those locations.

2. **Later-iteration initialization.** If execution reaches the next iteration, its four direct initialization stores write zero because the local fourth argument was cleared before D137.

3. **Selector addressing.** A selector read yielding 7 selects byte-write address 24, not selector base plus 17.

4. **Cached selection.** If phase 3 caches selector 7 and D042–D046 change the original selector location to 9, the cached-selector word store still targets address 27. A later fresh selector read may obtain 9.

5. **Packed-address boundaries.** Initial packed value zero selects word-read address 20. An initial packed value with all low 30 bits set selects address 1043. No rounding or alignment adjustment is represented.

6. **Top-bit store.** The phase-2 value derived from D005 is zero when that result is even and `0x80000000` when it is odd.

7. **Repeated D127 operands.** If the late result is 3, the late scaled value is 12. D127’s first two explicit operands are both 12288; its third is 49152.

8. **Iteration state.** If D146 returns 3, the final word store targets address 68 and writes 12. The next iteration’s second argument, third argument, and additional entry-state word are all 12.

9. **Partial execution.** If D006 does not return, the first word store has already occurred. None of the four direct initialization byte stores has yet occurred.

10. **Occurrence counts.** An iteration reaching its boundary has performed 13 direct word stores and 14 direct byte stores, regardless of address aliasing. Dependency accesses are outside those counts.
