# F-4dd54bd09231

## Purpose

F-4dd54bd09231 writes a destination header, obtains an address from a dependency, and conditionally modifies linked state and drains a work list. It returns a 64-bit value composed of a mutable 32-bit working word and a 32-bit state-base address.

The conditional work is controlled by a selected-record slot read after state discovery. If that read is zero, this function does not inspect or drain the work list.

The established behavior is structural. Prepending a selected record to a chain and processing detached work records are inferred purposes. The meanings of the header, records, dependency arguments, and packed result are not established. In particular, the two calls per work record do not establish payload release or record deallocation.

These are two 32-bit bit patterns, not a conventional single-pointer result established by the evidence. A negative initial integer contributes its 32-bit representation to the high half; it does not sign-extend over the low half.

## Behavior

### Header initialization and state discovery

The function obtains a 4-byte value from a global data location and writes it to the destination. The global value itself is not supplied. This header operation precedes state discovery.

It initializes three distinct working words from the second, third, and fourth inputs. Their roles are upper-result, auxiliary, and callback working storage.

F-fd7c65715716 is called once with destination +32 bytes. Its returned value becomes Anchor. The function derives the state-slot addresses from that value; it does not establish that State base equals the destination or belongs to the same object.

The Selected-record slot is then read to choose the conditional path. Dependency effects before this read can influence the branch. No preservation of destination storage or global state by F-fd7c65715716 is established.

### Zero selected-record path

If the branch read yields zero:

- F-3e95f52e82a5 is not called.
- No chain insertion is performed by this function.
- The Work-head slot is not examined by this function.
- No F-ff1bdc376dcd call is made by this function.
- The upper-result working word retains the second input’s bit pattern.

The result combines that word with State base. An existing nonempty work list does not cause draining on this path.

These statements describe this function’s own actions. They do not exclude effects performed inside F-fd7c65715716.

### Nonzero selected-record preparation

If the branch read is nonzero, the function performs further accesses rather than using a single selected-record snapshot:

1. It reads the Selected-record slot again and obtains the 4-byte field at offset +8 from the resulting address.
2. That field replaces the auxiliary working word.
3. It reads the Selected-record slot again and copies that address into the upper-result working word.

The branch read, the address used for the +8 field access, and the address copied into the upper-result word are distinct reads. Their equality requires appropriate state stability; the evidence supplies no synchronization guarantee.

F-3e95f52e82a5 is then called with these arguments, in order:

| Argument position | Passed address |
|---|---|
| First | Callback working word |
| Second | Work-head slot |
| Third | Auxiliary working word |
| Fourth | Upper-result working word |

The dependency receives addresses of writable storage, not copies of the words alone. Its return value is not used.

Changes to the upper-result working word can affect the eventual high half of the return. Changes to the work head can affect subsequent draining. The supplied body does not constrain other dependency effects.

### Chain insertion

After F-3e95f52e82a5 returns normally, the function:

1. Reads the Selected-record slot to obtain the record address used for insertion.
2. Reads the current Chain-head slot.
3. Writes that chain-head value to the captured record address +12.
4. Writes the captured record address to the Chain-head slot.

There is no additional nonzero check before the record-field write.

The insertion address is obtained after the callback. It need not equal either the earlier selected-record values or the current upper-result working word. Once captured, that insertion address is used for both insertion writes; a slot change caused by the first write does not cause another selected-record read before the second.

The two writes are ordered, but their logical effects depend on aliasing. For example:

- If selected record +12 is the Work-head slot, the first write can populate or replace the work list.
- If selected record +12 is the Chain-head slot, the second write overwrites the same location with the captured record address.
- If either destination overlaps other relevant record storage, subsequent processing observes the resulting contents.

Thus “the selected record now points to the old chain head” is only a stable postcondition when the later write and subsequent effects do not overwrite that field.

The function contains no dedicated operation clearing the Selected-record slot. That does not establish that the slot remains unchanged: aliasing or dependency effects can alter it.

### Work-list draining

Draining begins only after both insertion writes.

Each iteration reads the live Work-head slot. Zero ends the loop. A nonzero value is captured as the current work-record address.

For each captured record, the observable sequence is:

1. Read its 4-byte next-address field at offset +0.
2. Write that value to the Work-head slot.
3. Obtain the record’s +8 and +4 field values for a dependency call.
4. Call F-ff1bdc376dcd with the +8 value, the +4 value, and zero.
5. If that call returns normally, call F-ff1bdc376dcd with the captured record address, one, and zero.
6. Read the live Work-head slot again for the next iteration.

The head update precedes the payload-field accesses and both calls. If that update aliases a payload field, the subsequent argument access observes the overwritten storage. The relative access order between the +8 and +4 argument fields is not established.

There is no guard suppressing the first call when either field value is zero. Both calls are scheduled for each detached record, subject to execution reaching them normally.

No explicit record-field access occurs between the first and second calls. The second call uses the captured address even if the first call has affected the record’s storage. Whether that address remains acceptable is a dependency-contract and lifetime question.

The loop does not traverse a privately preserved remainder. Either dependency call can affect later iterations by changing the live Work-head slot, directly or through other reachable state.

### Result formation

On normal completion, the low result half uses the original Anchor minus 32 bytes. F-fd7c65715716 is not called again.

The high half uses the upper-result working word at result formation. On the nonzero path, this word first receives a selected-record address and is then exposed by address to F-3e95f52e82a5.

Its value immediately after that callback is not necessarily its final value. A dependency can retain the address and make it available to subsequent calls. Use of that address while this invocation’s local storage remains live does not inherently exceed its lifetime. Use after this invocation returns requires a separate lifetime justification not supplied here.

## Side effects

Established direct effects are:

- A global 4-byte value read and destination-header write.
- Conditional reads of selected-record state and record fields.
- On the nonzero path, an ordered selected-record +12 write and Chain-head write.
- A Work-head update before each pair of per-record calls.
- Dependency calls in the order described above.

Direct writes may affect other logical fields through aliasing. The contract does not assume that state storage, record storage, and destination storage are disjoint.

F-3e95f52e82a5 receives addresses of three local working words and one state slot. Retention, sharing, mutation, and ownership rules for these addresses are unknown. Later dependency calls may affect a still-live working word through a retained address; no preservation guarantee is established.

There is no explicit allocation operation or independently established deallocation operation. F-ff1bdc376dcd must not be treated as proof that payload or record storage is released.

No explicit validation, locking, cycle detection, bounds check, error-code interpretation, or rollback is present. Apart from the Anchor-producing return, dependency return values are ignored.

If execution is interrupted, earlier writes are not visibly reversed. In particular, a work record is detached before its first dependency call. No defined error result is established for invalid storage or abnormal dependency completion.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not runtime observations. Each assumes valid nonwrapping addresses, valid storage for every performed access, and normal dependency returns unless stated otherwise.

### Zero selected-record slot

Assume F-fd7c65715716 returns Anchor `0x00002020`, the branch read of the Selected-record slot yields zero, and the second input is `0x89ABCDEF`.

### Nonzero selected record, empty work list

Assume:

- The selected-record reads consistently yield address S.
- S +8 contains V, Chain-head contains C, and Work-head contains zero.
- S +12, Chain-head, and Work-head are mutually nonoverlapping 4-byte locations.
- Record accesses and state storage remain valid.
- F-3e95f52e82a5 does not change the relevant state or working words.

The callback receives an auxiliary word containing V and an upper-result word containing S. After insertion, S +12 contains C, Chain-head contains S, and Work-head remains zero. No F-ff1bdc376dcd call occurs. The result’s high half is S.

The explicit nonoverlap condition matters: an empty work head before insertion alone does not establish that draining will be skipped.

### Callback changes the selected record and upper-result word

Assume F-3e95f52e82a5 changes the Selected-record slot from S to T and writes U to the upper-result working word.

If the post-callback selected-record read yields T, insertion uses T. The upper-result word contains U immediately after the callback.

To require that the returned high half is U, additionally assume that the word remains U until result formation, including during any F-ff1bdc376dcd calls. This condition excludes later writes through a retained working-word address and other overlapping writes. Without it, the returned high half is whatever value is present at result formation.

### Two work records after insertion

Assume that, after both insertion writes:

- Work-head contains P, P +0 contains Q, and Q +0 contains zero.
- The work-head slot and relevant fields of P and Q are nonoverlapping.
- Both records remain accessible through their respective processing.
- Neither dependency call changes the work head or any field needed for this traversal.

Calls occur in this order:

1. F-ff1bdc376dcd with P’s +8 value, P’s +4 value, and zero.
2. F-ff1bdc376dcd with P, one, and zero.
3. F-ff1bdc376dcd with Q’s +8 value, Q’s +4 value, and zero.
4. F-ff1bdc376dcd with Q, one, and zero.

Work-head becomes Q before the first call and zero before the third. Establishing the list after insertion avoids assuming that insertion leaves an earlier list unchanged.

### Insertion populates an initially empty work head

Assume the captured insertion address is S, S +12 aliases Work-head, Chain-head is a separate location, and the chain-head read yields nonzero C. Assume all ensuing accesses are valid.

The first insertion write places C in Work-head. The second writes S to Chain-head. The loop then reads C as its head and begins processing that record. An initially empty Work-head does not suppress these calls.

### Selected-record field aliases Chain-head

Assume S +12 and Chain-head are the same 4-byte location, and the captured insertion address is S.

The first insertion write stores the previously read chain-head value to that location. The second overwrites it with S. Immediately afterward, absent other changes, both logical views contain S, not independently S and the previous chain head.

### Selected record becomes zero

Assume the initial nonzero branch is taken, but the post-callback Selected-record read yields zero.

The function attempts the record-field write at offset +12 from that value without another check. If that address is invalid, successful completion cannot be required. The evidence establishes neither a defined error result nor rollback.
