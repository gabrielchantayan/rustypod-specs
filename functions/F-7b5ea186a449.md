# F-7b5ea186a449

## Purpose

F-7b5ea186a449 recognizes either of two selector tokens and conditionally dispatches an operation through an object’s indirect dispatch table. Its normal return value reports **recognition**, not whether an operation was invoked or succeeded.

The first selector has priority. If it is recognized, the second selector is not examined. Each recognized selector has a corresponding external comparison value. Equality with that value suppresses dispatch but does not change the recognized return value.

The source annotations associate the selectors with “HandleLeaveAlarm” and “HandleSelect.” These names suggest event handling, but neither that interpretation nor the exact selector bytes is established by the supplied function body.

## Interface

### Inputs

The function has three inputs, described here by their roles:

| Input | Representation established by the supplied source | Use |
|---|---|---|
| Object reference | Pointer represented as pointing to an integer-sized object word | Supplies the dispatch-table reference and is passed as the first argument to a selected operation |
| Selector value | Opaque 32-bit value | Passed unchanged to the selector-comparison dependency |
| Event value | 32-bit integer | Compared with a branch-specific external value and, when dispatch occurs, passed unchanged to the selected operation |

The selector value is not established to be a string pointer. The comparison dependency receives it together with a reference to a fixed selector token. Whether the dependency interprets the value as an address, handle, identifier, or another representation is unknown.

The event value is not used for arithmetic. Its relevant operations are equality comparison and argument forwarding. No sign-based comparison, narrowing conversion, range check, or normalization is visible.

### Output

The normal result is a 32-bit value:

- **1:** Either selector was recognized, including when dispatch was suppressed.
- **0:** Neither selector was recognized.

No other normal return value is visible. A return of 1 does not establish that an indirect operation ran, completed useful work, or reported success.

The function also relies on:

- A second fixed selector-token reference.

The two external comparison values are separate logical inputs. Their storage annotations are consistent with 32-bit integer comparison, but their declarations and initialization are not supplied.

## Behavior

### Recognition order

F-7b5ea186a449 first invokes F-01 with the selector value and the first fixed selector-token reference.

A zero result is interpreted as recognition. Any nonzero result is interpreted as nonrecognition; its sign and magnitude are otherwise irrelevant.

If the first result is zero, the function handles only the first branch. It does not invoke the second selector comparison, regardless of whether dispatch is suppressed.

If the first result is nonzero, the function invokes F-01 again with the same selector value and the second fixed selector-token reference. A zero result recognizes the second branch. A nonzero result causes a normal return of 0.

The first selector therefore has priority even if F-01 could report a match for both tokens.

### First recognized branch

After F-01 recognizes the first selector, the function reads the first external comparison value and compares it with the event value.

- If they are equal, the function performs no visible indirect dispatch and returns 1.
- If they differ, the function obtains an indirect operation from the object’s dispatch table at byte offset **308**, equivalently **0x134**, and invokes it with the object reference followed by the event value. If that invocation returns normally, F-7b5ea186a449 returns 1.

The external comparison value is read after the first selector comparison has returned. It is not established to be a value captured at function entry.

### Second recognized branch

This branch is reachable only after the first selector comparison returned nonzero and the second returned zero.

The function then reads the second external comparison value and compares it with the event value.

- If they are equal, the function performs no visible indirect dispatch and returns 1.
- If they differ, the function obtains an indirect operation from the object’s dispatch table at byte offset **300**, equivalently **0x12C**, and invokes it with the object reference followed by the event value. If that invocation returns normally, F-7b5ea186a449 returns 1.

The first external comparison value is not visibly read on this branch.

### Unrecognized selector

If both selector comparisons return nonzero, the function returns 0.

On this path, its visible body does not read either external comparison value, resolve either dispatch-table entry, or invoke either indirect operation.

### Dispatch layout and widths

The object is treated as beginning with a word that supplies the dispatch-table reference. The selected callable is obtained from that table using a byte offset:

| Recognized branch | Dispatch-table byte offset |
|---|---:|
| First selector | 308 / 0x134 |
| Second selector | 300 / 0x12C |

These are byte offsets, not slot numbers or offsets into the object itself. The entries begin eight bytes apart. The supplied representation does not justify inferring an entry width or the contents of the intervening table region.

The first object word is represented as an integer-sized value used as a table address. This supports an apparent 32-bit address-bearing layout, but the complete pointer width, callable representation, alignment requirements, and calling convention remain documented_only.

No event-value arithmetic, offset scaling by the event value, or bounds calculation is visible. The only address offsets explicitly used for dispatch are the two fixed values above.

### Observable ordering

The visible control flow establishes these dependencies:

1. The first F-01 call completes before the function decides whether to attempt the second comparison.
2. The successful comparison call completes before the corresponding external comparison value is read.
3. The event-value comparison determines whether dispatch-table resolution occurs.
4. On a dispatching path, the object’s table reference and selected callable are resolved before the indirect invocation.
5. The selected operation must return normally before the function returns 1.

This ordering matters if F-01 changes external state. A recognized branch uses the corresponding comparison value after the recognition call, not a guaranteed entry-time snapshot.
