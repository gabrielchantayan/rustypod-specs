# F-06ca3003b5b9

## Purpose

F-06ca3003b5b9 invokes an object-associated indirect operation and, if its result matches a requested value, performs a signed-bound loop that writes three-word records while decrementing a mutable destination cursor.

The indirect operation receives a receiver, a base value, a requested value, and literal 2. Its returned 32-bit value must equal the requested value exactly before record processing begins. The requested value does not control the loop; a separate signed 32-bit bound does.

Normal return values are:

- **0:** the equality check passed and the loop completed, including when no iterations were required.
- **1:** the equality check failed.

These statuses describe the visible control flow, not independently verified success of the dependencies. No helper result is checked for an error.

Backward construction of fixed-size descriptors is an inferred intent. The established behavior is narrower: three 32-bit destination stores per completed iteration, followed by a 12-byte decrement of a freshly read cursor.

## Behavior

### Initial indirect operation

Before considering the loop bound, the function obtains the receiver through context offset +4, follows its dispatch-table reference, and invokes the entry at table offset +16.

This unresolved dependency is designated **F-indirect-01**, a document-local opaque identifier. Its explicit arguments, in order, are:

1. Receiver address.
2. Base value.
3. Requested value.
4. Literal 2.

The result is compared with the requested value for exact 32-bit equality.

If they differ, the function returns 1. It performs no loop-body destination stores, mapped helper calls, or explicit cursor decrement on that path.

F-indirect-01 has nevertheless executed. Its effects are not undone, so a mismatch does not establish that the context, cursor, destination memory, or other state is unchanged.

The representation establishes the dispatch relationship and argument positions. It does not establish a total order among all operand reads within the call expression, or a guarantee that the receiver reference is loaded only once.

### Loop admission and termination

Following a matching result, a signed 32-bit index begins at zero. An iteration runs while that index is less than the signed iteration bound.

- A zero or negative bound produces no iterations and a normal return of 0.
- A positive bound \(N\) produces indices \(0\) through \(N-1\), provided execution completes normally.
- The index increases by one after each completed body.

The initial indirect operation occurs even when the bound is nonpositive.

For a positive signed 32-bit bound, the loop-control increment need not overflow: its final value is the bound, after which the comparison fails. This observation does not resolve overflow in body arithmetic.

No validation relates the requested value to the iteration bound, destination capacity, stride, or base value. Passing the equality check is not proof that the destinations are valid.

### First destination store

The function forms the base value plus the current index multiplied by the stride read from context offset +36. It writes the resulting 32-bit value through the cursor at context offset +44.

This store precedes the second destination store and every mapped helper call in the iteration.

The expression identifies the required operands, but does not establish a total order between all reads used to evaluate them.

### Second destination store

The function reads the stride and cursor again, then writes the stride as a 32-bit value at cursor offset +4.

The first store may have changed either field through aliasing. The second store therefore need not use the same stride or cursor as the first.

There is no established cached-stride or common-record guarantee.

### Third destination store

After F-baa332e06e32 returns, the function adds its 32-bit result to the adjustment read from context offset +48. It stores the sum as a 32-bit value at offset +8 from the cursor evaluated for this store.

The cursor and adjustment are observed after the helper sequence. Earlier destination stores or dependencies may have changed either.

This store may overlap context fields, including the cursor field itself. Such overlap affects the immediately following cursor update.

### Cursor update

After the third destination store, the function reads context offset +44 again, subtracts 12, and writes the result back to that field.

The decrement applies to the cursor field’s value **after the third store**, not necessarily the cursor used to address that store.

If the third store overwrites the cursor field, the value just stored becomes the decrement’s input. A third-store address based on cursor \(Q\) therefore does not, by itself, imply a final cursor of \(Q-12\).

The update occurs on every completed iteration, including the last. After the last iteration, this function performs no further record access through the resulting cursor.

### Conditional regular-record behavior

If all of the following hold:

- The initial equality check passes.
- The bound is positive.
- Dependencies preserve the relevant context fields.
- Destination stores do not overlap those fields.
- All arithmetic and accesses remain valid.

Then iteration \(k\) writes its three words at offsets 0, 4, and 8 from \(P-12k\), where \(P\) is the loop-entry cursor. For bound \(N\), the final cursor is \(P-12N\).

This is a conditional consequence, not an unconditional layout promise.

## Side effects

### Explicit memory effects

Each completed iteration performs, in order:

1. A 32-bit destination store at cursor offset +0.
2. A 32-bit destination store at a newly evaluated cursor offset +4.
3. The ordered helper sequence.
4. A 32-bit destination store at a newly evaluated cursor offset +8.
5. A 32-bit cursor-field write using its post-store value minus 12.

Only the cursor field is explicitly assigned as a context field. Destination stores can nevertheless modify other context fields through aliasing.

The third destination store and cursor update are distinct writes even when both target the cursor field.

### Dependency effects and abnormal completion

F-indirect-01 runs before every normal return. The mapped helper sequence runs only within admitted loop iterations.

No dependency is established to preserve globals, context fields, destinations, ownership, or implicit state. Absence of explicit arguments does not imply absence of inputs or side effects.

There is no visible rollback or exception handling. Status 1 represents an equality mismatch, not a general memory-fault or helper-failure result. If an access faults or a dependency fails to return, earlier effects may already have occurred.

### Memory requirements

Reached accesses include context-field reads and writes, receiver and dispatch-table accesses, and destination-word writes.

The external operands used by F-c4b34006a13c introduce additional unresolved access requirements. Their evaluation must be valid under their actual declarations and call interface, but the supplied evidence does not establish access widths, alignment, required byte ranges, or whether their values identify further storage.

Ordinary stable, nonaliasing use requires writable storage for the backward sequence of three-word records. No capacity check enforces this.

The final cursor value is written even when no subsequent destination access uses it.

## Acceptance examples

These are conditional expectations from static evidence, not executed tests. Each requires valid reached accesses, valid dependency interactions, and arithmetic within representable ranges.

### Initial mismatch

If the requested value is 8 and F-indirect-01 returns 7:

- Return status is 1.
- No loop-body stores or mapped helper calls occur.
- No explicit cursor update occurs.
- Effects of F-indirect-01 remain possible.

The iteration bound does not change this outcome.

### Matching result with no iterations

If F-indirect-01 returns the requested value and the bound is 0 or −2:

- Return status is 0.
- No loop-body stores or mapped helper calls occur.
- No explicit cursor update occurs.

The indirect call still runs and may change the context.

### One stable iteration

Assume a matching result, bound 1, base 1000, stride 16, adjustment 5, and loop-entry cursor \(P\). Dependencies preserve these fields, destination writes do not overlap them, and F-baa332e06e32 returns 7.

The destination stores are:

- 1000 at \(P\).
- 16 at \(P+4\).
- 12 at \(P+8\).

The final cursor is \(P-12\), and return status is 0. The second F-1c7710595b35 call receives zero because the index is zero.

No expected type or width for external operands A and B is implied by this example; their evaluation and use must independently be valid.

### Two stable iterations

Under the same stability and nonaliasing conditions, with bound 2:

- Record addresses are \(P\) and \(P-12\).
- First words are 1000 and 1016.
- Second words are both 16.
- Final cursor is \(P-24\).
- Return status is 0.

The third words depend on the corresponding final helper results and adjustment. Base and stride alone do not determine them.

### A dependency changes the stride

Suppose the first F-1c7710595b35 call in the iteration with index 1 changes the stride from 16 to 24.

The second F-1c7710595b35 call receives 24. The first two destination stores have already occurred and are not recomputed using the changed stride.

### A dependency changes the cursor without overlap

Suppose a helper changes the cursor to \(Q\), no later dependency changes it, and the third destination store does not overlap the cursor field.

The third store targets \(Q+8\). The subsequent cursor reload obtains \(Q\), so the update stores \(Q-12\).

### The third store overwrites the cursor

Let the context address be \(C\). Suppose a helper sets the cursor to \(Q=C+36\), and no later dependency changes it. The third store targets \(Q+8=C+44\), exactly the cursor field.

If the final helper result plus adjustment is 1000:

- The third store writes 1000 into the cursor field.
- The cursor update reloads 1000.
- The update writes 988 into the cursor field.

The result is not \(Q-12\). With bound 1, no subsequent record access through 988 occurs before return.
