# F-89546999e804

## Purpose

F-89546999e804 selects between two behaviors using fields in a record reached indirectly through its fourth argument.

On the eligible path, it passes a local 32-bit mutable slot to a dependency, performs two ordered 16-bit destination writes using that slot, and passes the slot to a final dependency. On the ineligible path, it calls an alternate dependency with the destination and two fixed numeric arguments.

The destination comes from a dependency invoked before the eligibility checks. The mutable slot initially contains the fourth argument’s address value, not the record address stored at that address.

The eligible path is not unconditionally equivalent to copying a previously captured 32-bit value. The function reads the source for the second destination write after completing the first write. If the first write changes that source storage, the second write uses the changed contents.

This contract describes static evidence from the supplied source representation. Resource-management intent, dependency behavior, and target-specific memory semantics remain unresolved. No runtime tests have been performed.

### Eligibility evaluation

The first condition obtains a record address through the fourth argument and reads the byte at record offset two.

If that byte is nonzero, the function takes the ineligible path. It does not evaluate the second field access.

If the first byte is zero, the second condition obtains a record address through the fourth argument again and reads the byte at offset three. At the source-expression level, the record address is not explicitly captured once and reused for both checks.

The second byte is interpreted as unsigned. Eligibility requires it to be strictly greater than eleven, so accepted values are twelve through 255 inclusive.

Accordingly:

- A nonzero first byte rejects the record without a second-field read.
- A zero first byte and second byte from zero through eleven reject the record.
- A zero first byte and second byte from twelve through 255 select the eligible path.

The signedness of the first byte does not affect its comparison with zero. The unsigned interpretation of the second byte is significant: values 128 through 255 satisfy the threshold.

There is no dependency call between the two conditions. Nevertheless, the source provides no synchronization or atomic-snapshot guarantee. It does not establish how concurrent changes would behave, nor does it prove that two distinct machine-level outer-slot loads must occur after compilation.

### Eligible path: sequential destination writes

After F-069900d25634 returns, the function performs these operations in order:

1. It obtains the current 32-bit local-slot value and narrows it to 16 bits.
2. It writes that 16-bit value at destination offset zero.
3. After the first write, it reads the two-byte portion at local-slot offset two.
4. It writes that portion at destination offset two.

The second source portion is not established as a snapshot taken before the first destination write. Its timing matters if destination storage overlaps the local slot or another permitted mechanism changes that portion between the accesses.

On a conventional little-endian 32-bit representation, the two bytes at local-slot offset two represent the numeric upper 16 bits. If those bytes retain their post-processing contents until the second source read, the writes place the low half followed by the upper half into destination storage. Under those conditions, the destination represents the post-processing 32-bit value.

Little-endian layout alone is insufficient for that reconstruction claim. The first write must not alter the upper two source bytes, and no other intervening effect may change them before they are read.

For example, under an address model permitting the overlap, a destination beginning two bytes into the local slot would make the first destination write overwrite the source bytes used by the second write. The second write would then use those overwritten bytes. This is a conditional consequence of the access order, not evidence that such an address relationship occurs in normal use or is valid under every target’s memory rules.

These are two ordered 16-bit writes, not an established atomic 32-bit update. An environment permitting observation between them may expose a partially updated destination.
