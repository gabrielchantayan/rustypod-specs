## Behavior

### Target selection

The wrapper derives its target from the contents of memory at invocation time. It does not visibly use a constant target, consult a name registry, or choose between explicit fallback branches.

The first relevant address is the input base displaced by `0x430`. The contents there identify a second readable location. The contents at the beginning of that location supply the base used for the final displacement, `0xEC`. The callable address stored at that final location is the selected target.

These are dependent reads: the address needed for each subsequent read comes from the preceding read. The final target therefore depends on all three stored values, not merely on the input address.

The supplied representation shows one target selection and one indirect invocation per execution that reaches the invocation. It shows no retry, repeated dispatch, or second attempt after an invalid reference.

These are conditional acceptance scenarios, not executed tests.

1. **Successful dispatch through valid storage.**  
   Given readable fields at all three required locations, a compatible callable entry at dispatch-region offset `0xEC`, and a target that returns normally, the wrapper invokes that target once and then completes without an explicit result.

2. **Changing the selected entry.**  
   Given two separate invocations with otherwise unchanged, valid storage, replacing the callable entry at offset `0xEC` before the second invocation changes the selected target accordingly. This assumes no intervening writer changes the relevant storage during either invocation.

3. **Changing the intermediate reference.**  
   If the field at input offset `0x430` is changed to reference another valid record whose first word identifies another dispatch region, selection follows that new chain. The wrapper does not visibly retain a target from an earlier invocation.

4. **Unreadable intermediate storage.**  
   If the first field is readable but refers to unreadable storage, the prerequisites for successful dispatch are not met. Acceptance must not require a null result, fallback target, or wrapper-generated diagnostic.

5. **Target-produced mutation.**  
   If the selected target changes global state and returns normally, those changes are not contradicted by this contract. The absence of explicit wrapper writes is not a preservation guarantee.

6. **Target that does not return.**  
   If the target terminates execution or transfers control elsewhere, normal wrapper completion is not required. No represented recovery path restores ordinary completion.
