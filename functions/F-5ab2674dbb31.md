# F-5ab2674dbb31

## Purpose

F-5ab2674dbb31 conditionally dispatches an operation through a function address obtained from an associated object.

Two conditions suppress dispatch:

- A byte at offset `0x70` from the input address is nonzero.
- That byte is zero, but the associated-object pointer at offset `0x48` is null.

Otherwise, the function obtains an indirect target through the associated object and invokes it with three arguments: the associated-object pointer, followed by two values with the 32-bit bit pattern `0xFFFFFFFF`.

The established behavior is a guarded dispatch. Interpreting the guard as a disabled flag, the associated object as an interface instance, or the two constant arguments as sentinel values is inferred intent, not an established semantic contract.

## Behavior

### Guard evaluation

The first explicit data access reads the byte at input offset `0x70`.

If the byte is nonzero, the function returns immediately. On this path, it does not explicitly read the associated-object field, inspect an object or table, or invoke a dependency.

Every nonzero byte value has the same branch effect. The function does not require a particular enabled or disabled encoding beyond the zero/nonzero distinction.

If the byte is zero, processing continues.

### Associated-object selection

The next explicit data access reads the pointer at input offset `0x48`.

If this pointer is null, the function returns immediately. It does not explicitly read an object header or dispatch table, and it does not invoke a dependency.

If the pointer is nonnull, that value becomes both the object used to resolve the target and the first argument supplied to that target.

There is no second read of the suppression byte before dispatch. There is also no explicit reread of the associated-object field after selection.

### Target resolution and dispatch

The function reads a table pointer from the beginning of the selected object. It then reads an indirect function pointer at byte offset `0x38` within that table.

It dispatches to that target with these argument values, in logical argument order:

1. The selected associated-object pointer.
2. `0xFFFFFFFF`.
3. `0xFFFFFFFF`.

Both constant arguments have all 32 bits set. If interpreted as signed 32-bit integers, they represent negative one; if interpreted as unsigned 32-bit integers, they represent 4,294,967,295. The caller-side evidence does not select either interpretation or establish what the values mean to the target.

There is one explicit indirect dispatch and no explicit loop or retry. The dependency may itself perform further calls, including reentrant calls; that behavior is outside the established body.

That does not make the dispatching path side-effect-free. The indirect target may modify memory, alter globals, acquire or release resources, change execution state, or fail to return. None of those effects can be excluded from the supplied evidence.

### Nonzero suppression byte

Given a readable suppression byte whose value is any nonzero value, the accepted behavior is an immediate return with no indirect dispatch.

The associated-object field need not be readable for this path. An implementation that reads it before honoring the nonzero byte would introduce an access absent from the established behavior.

### Zero suppression byte and null association

No object-header or table-entry access is required or permitted by the established path.

### Successful dispatch

The first argument must be the object pointer selected from the containing record. The next two arguments must each carry the 32-bit pattern `0xFFFFFFFF`. The containing-record address is not substituted for the object argument.
