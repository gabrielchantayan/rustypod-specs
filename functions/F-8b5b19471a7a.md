### Arithmetic boundaries

Under the conditional bit-vector model:

- Left shifting a word by eight and then logically right shifting by eight retains only the original low 24 bits.
- Successive left shifts by 28 and 28 discard every original bit.
- Successive left shifts by 31 and 30 likewise produce zero.
- Multiplication by 33,554,432 retains only seven input bits.
- A 24-bit mask followed by a six-bit left shift fits within 30 bits.
- A 22-bit mask followed by an eight-bit left shift also fits within 30 bits.

These consequences apply to the particular retained values, not to later invocation outputs.

A late byte store takes the low byte of a signed word shifted right by the low eight bits of an address-like value. The represented count can range from 0 through 255. Neither count reduction nor behavior for counts above 31 is established. A replacement must not silently impose its implementation language’s shift rules.

## Acceptance examples

These are conditional analytical criteria, not executed tests.

### Truncation

Given produced word 0xAB123456, an eight-bit left shift followed by an unsigned eight-bit right shift yields 0x00123456 under 32-bit bit-vector semantics. Restoring the discarded high byte is incorrect.

### Combined-result extraction

Given a combined result with high word 0x12345678, a logical right shift of the full 64-bit value by 36 yields 0x01234567. A shift applied only after word truncation is not equivalent.

### Unsigned byte widening

If the relevant offset-5 byte is 0xFE, the widened word is 254, not −2.

### Publication-base capture

If the publication-base read observes one address and the subsequent write to fixed address 96 changes what a later read would observe, publication still uses the earlier captured address. Reading the base after the fixed-address write violates the represented order.

### Fresh reads at address 103

If the read used for the copy to address 33 observes 0x11, the first later read observes 0x22, and the second later read observes 0x33, the corresponding byte stores use 0x11, 0x22, and 0x33. Caching the initial assignment or either preceding read is incorrect.

In particular, if an intervening paired-base-plus-9 store changes the value observable at fixed address 103, the second later read must reflect that changed state under the applicable memory semantics.

### Intermediate writes

An observer of arithmetic base plus 32 must retain the separate writes of 32, 47, the freshly widened byte, and 32. A final-state-only description is insufficient where access events are observable.

### Partial execution and final dispatch

A dependency that does not return prevents later direct accesses. A later fault provides no rollback guarantee. If final dispatch is reached, its first argument is 114 and its third argument is the earlier retained offset-20 word, not a fresh read of that location.
