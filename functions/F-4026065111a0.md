### 2. Default the four-byte field only when it is zero

After the indirect operation returns, the function examines the four-byte field at object + 28.

- If that field equals zero, the function writes the four-byte integer value 8 to the same location.
- If it is nonzero, this stage leaves it unchanged.

The decision uses the value present after the indirect operation, not necessarily the value present at function entry. There is no range check, sign check, or clamping. Negative and positive nonzero values both bypass the default write.

1. The opaque four-byte context value.

1. A conditional four-byte write of 8 to object + 28.
2. A four-byte write to destination + 8.
3. A character-sized write to destination + 12.

These examples are conditional behavioral expectations, not executed tests. Each assumes valid storage and normally returning dependencies unless stated otherwise.

### Zero field receives the default

If the indirect callable leaves object + 28 equal to zero, the function writes 8 there before invoking F-b9acea4b06ad.

If that dependency leaves the field unchanged and returns a nonoverlapping valid destination, destination + 8 receives 8.

### A nonzero field bypasses defaulting

If F-b9acea4b06ad preserves that field, destination + 8 receives the four-byte representation of −3 under the applicable integer model.

Conversely, if the field initially equals zero but the callable changes it to 25, the function does not perform the default write.

### Dependency changes override the earlier default for copying

If it equals 300, a target with eight-bit low-bit narrowing stores a byte value of 44. That result is conditional on the target conversion rules, not a platform-independent guarantee.

The first destination store replaces object + 32 with the value read from object + 28. The final conversion therefore uses that replacement value.

### Invalid results are not converted into handled errors
