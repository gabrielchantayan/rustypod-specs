# F-9392096d9f13

## Purpose

F-9392096d9f13 searches a linked structure, optionally checks an existing candidate, and publishes either a candidate value or a result obtained through F-391a10e7bae2.

The directly written output consists of:

- A four-byte value at byte offset 0.
- A one-byte discriminator at byte offset 4.

Discriminator **zero** means that the final comparison returned zero and the routine published the candidate slot’s value. Discriminator **one** means that F-391a10e7bae2 returned normally and the routine published its result slot’s value.

Discriminator one identifies a control-flow path. It does not independently establish successful insertion, allocation, or structural modification.

**Inferred intent:** the linked structure resembles an ordered tree with a header; candidate adjustment resembles predecessor selection; zero mode resembles duplicate suppression. These interpretations are not established without dependency contracts and structural invariants.

## Behavior

### Initial state and descent

The comparison state starts at the nonzero value one.

The routine reads the container’s header address and then that header’s offset-4 address to obtain the initial search record. It separately rereads the container’s header address to initialize a retained traversal position.

These are distinct header reads. Their values are not established to be equal if the underlying storage changes between accesses.

For each non-null search record:

1. Both result slots are set to four-byte zero.
2. F-b61726ba491f is called with:
   - The container address plus 0x19.
   - The original argument.
   - The current search-record address plus 0x10.
3. The current record becomes the retained traversal position.
4. The next search address is read from the current record:
   - Offset 0x0c when the comparison result is zero.
   - Offset 8 when the comparison result is nonzero.

Only zero versus nonzero matters. Positive and negative nonzero comparison results take the same branch.

The selected link is read after the comparison call returns. Changes to that link during the call can therefore affect traversal.

Descent ends upon a null search address. The retained position is the last compared record, or the separately read header address if no record was compared. Empty descent leaves the comparison state at one and does not initialize either result slot.

### Mode selection

After descent, the routine reads the container’s byte at offset 0x18.

- A nonzero byte selects common insertion directly.
- A zero byte selects candidate checking.

The mode is not captured before descent. A change during a descent comparison can affect the subsequently selected path.

### Candidate setup and boundary processing

In zero mode, the candidate slot is initialized from the retained traversal position.

If the last descent comparison was zero, the routine skips boundary processing and structural adjustment.

If the comparison state is nonzero—including after empty descent—the routine:

1. Reloads the header address from container offset 0x10.
2. Reads the four-byte value at that header’s offset 8 into the boundary/common-result slot.
3. Calls F-ae31a5744f21 with the candidate-slot address followed by the boundary/common-result-slot address.

Neither slot is guaranteed to retain its pre-call contents.

A nonzero boundary result selects immediate insertion. That path uses the immediate-result slot and the retained traversal position from descent. It performs neither candidate extraction nor final comparison.

A zero boundary result selects structural adjustment using the candidate slot’s contents after the boundary call.

The exposed boundary/common-result slot also remains relevant if execution later reaches common insertion. Its boundary value is only an earlier assignment: later extraction or comparison calls may modify that slot through an address retained by the boundary dependency. An unchanged value on return from the boundary call alone does not establish preservation until insertion.

### Structural adjustment

Adjustment occurs only after a nonzero descent comparison state and a zero boundary result.

The routine first reads the byte at candidate offset 0.

If that byte is zero, it follows two offset-4 addresses: one from the candidate and another from the referenced record. If the resulting address equals the candidate, the routine replaces the candidate with its offset-0x0c address and completes adjustment.

If the byte was nonzero, or the two-link check did not return the candidate, adjustment takes the offset-8 route.

#### Offset-8 route

The routine reads and saves the candidate’s offset-8 address. It then separately rereads the same field to choose a branch.

The second read determines the branch; the first saved value supplies traversal on the non-null branch. The two accesses cannot be collapsed without a field-stability assumption.

**When the second read is null:**

- The saved first value is discarded.
- The candidate’s offset-4 address becomes the prospective parent.
- At each upward step, the routine reads the prospective parent’s offset-8 address and compares it with the current candidate.
- It then replaces the candidate with the prospective parent, regardless of the comparison result.
- Equality causes another step through the promoted record’s offset-4 address. Inequality ends adjustment.

The terminating step also promotes its prospective parent. The result is the first promoted record whose offset-8 address did not equal the preceding candidate.

**When the second read is non-null:**

- Traversal starts from the first saved offset-8 address.
- Each iteration places that saved address in the candidate slot.
- The routine reads and saves the candidate’s offset-0x0c address.
- It separately rereads offset 0x0c to decide whether to continue.
- A null second read ends adjustment at the current candidate.
- A non-null second read continues with the first saved offset-0x0c value.

Consequently, a non-null branch-condition read does not establish that the saved traversal address is non-null. Conversely, a null branch-condition read can stop traversal despite a non-null saved address. With stable fields, this downward route follows offset 0x0c until null; without stability, the separate-read behavior governs.

### Candidate extraction and final comparison

Unless immediate insertion was selected, zero mode proceeds to candidate checking:

1. A separate local four-byte scratch slot is set to zero. No subsequent use of its value is established.
2. The candidate slot’s current value is passed to F-90d8d778f48e.
3. Its four-byte return value is passed to F-b61726ba491f with:
   - The container address plus 0x19.
   - The extracted value.
   - The original argument.

This comparison argument order differs from descent: descent supplies the original argument second and a record-data address third.

A nonzero final comparison selects common insertion.

A zero final comparison selects existing-result publication. The routine rereads the candidate slot after extraction and final comparison, writes that four-byte value to the output, and then writes discriminator zero.

Where the boundary dependency received the candidate-slot address, later dependencies are not established to preserve that slot. The published value can therefore differ from the value passed to extraction or the value produced by structural adjustment.

### Insertion and publication

Both insertion paths call F-391a10e7bae2 with five arguments:

1. The selected four-byte result-slot address.
2. The container address.
3. A zero-valued argument.
4. The retained traversal position from descent.
5. The original argument.

Structural adjustment does not replace the retained insertion-position argument.

| Path | Result slot | Established earlier assignment |
|---|---|---|
| Immediate insertion after nonempty descent | Immediate-result | Zero at the start of the final descent iteration |
| Immediate insertion after empty descent | Immediate-result | None established |
| Common insertion after nonempty descent without boundary processing | Boundary/common-result | Zero at the start of the final descent iteration |
| Common insertion after empty descent with nonzero mode | Boundary/common-result | None established |
| Common insertion after boundary processing | Boundary/common-result | Header boundary value before the boundary call |

These are assignments at specified points, not unconditional guarantees about contents when insertion begins.

In particular, after boundary processing, preservation of the loaded boundary value requires preservation through the boundary call and every intervening dependency call. Extraction and final comparison may modify the exposed slot before common insertion, even if the boundary call initially left it unchanged.

After F-391a10e7bae2 returns normally, the routine reads the selected result slot, writes its four-byte contents to output offset 0, and then writes discriminator one to output offset 4. It performs no result validation.

Insertion need not write the result slot on every path to produce a defined output: it may leave a previously defined value unchanged. Nevertheless, paths without established initialization require an additional guarantee that the slot has defined contents before publication.

## Acceptance examples

These examples are conditional consequences of static control flow, not executed tests.

1. **Existing result without boundary processing.**  
   Given terminating nonempty descent, zero mode, a zero last descent comparison, valid extraction, and a zero final comparison, neither boundary processing nor insertion occurs. The published value is the candidate slot’s value read after final comparison, with discriminator zero.

2. **Mode bypasses candidate checking.**  
   Given nonzero mode when read, common insertion receives the retained traversal position. No boundary or extraction call occurs. If nonempty descent initialized the common-result slot and that zero value remains unchanged through publication, the output is zero with discriminator one. Empty descent provides no such initialization.

3. **Boundary selects immediate insertion.**  
   Given zero mode, nonzero comparison state, and a nonzero boundary result, insertion uses the immediate-result slot. A boundary-induced candidate change does not replace the retained insertion position. Nonempty descent assigned zero to this result slot; empty descent did not initialize it.

4. **Adjusted candidate under preservation.**  
   Given zero mode, a zero boundary result, valid terminating adjustment, a zero final comparison, and preservation of the candidate slot from adjustment through publication, the adjusted candidate is published with discriminator zero.

5. **Candidate changed after extraction.**  
   Suppose extraction receives candidate A and a later dependency changes the previously exposed candidate slot to B before final comparison returns zero. Publication uses B. This requires the stated dependency behavior; address retention itself is not established.

6. **Different offset-8 reads.**  
   If the first offset-8 read saves A and the second reads non-null B, downward traversal starts from A. If the second read is null, upward traversal is selected regardless of A. Every actually dereferenced address must remain valid.

7. **Different offset-0x0c reads.**  
   If a downward iteration saves A but its second offset-0x0c read is null, adjustment stops at the current candidate. A non-null second read instead continues using A, even if A is null and the resulting next dereference would be invalid.

8. **Boundary value preserved through common insertion.**  
   Suppose the boundary/common-result slot receives B, the boundary call returns zero, final comparison selects common insertion, and B is preserved through the boundary call, extraction, final comparison, insertion, and the subsequent result-slot read. The routine publishes B with discriminator one. Merely leaving B unchanged when the boundary call returns is insufficient: a later dependency may modify the exposed slot.

9. **Boundary value changed before insertion.**  
   Suppose the boundary call initially leaves B unchanged, but extraction or final comparison changes the exposed common-result slot to C. If common insertion leaves C unchanged through the subsequent slot read, publication uses C, not B.

10. **Empty descent in zero mode.**  
    No descent comparison occurs; the comparison state remains one. Boundary processing therefore occurs. A nonzero boundary result selects an immediate-result slot without established initialization. A zero result leaves the common-result slot with a prior boundary assignment, subject to subsequent dependency effects.

11. **Output extent and order.**  
    Given valid writable output and defined selected contents, normal completion directly writes four value bytes followed by one discriminator byte. It does not directly clear bytes 5–7.
