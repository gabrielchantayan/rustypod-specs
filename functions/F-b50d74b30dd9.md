# F-b50d74b30dd9

## Purpose

F-b50d74b30dd9 prepares storage associated with one indexed entry of a context, publishes a pointer to that storage, initializes selected 32-bit fields, and returns the published pointer.

The storage request consists of a fixed 128-byte region, an additional eight bytes per descriptor-selected element, and an optional 96-byte region. These are established size calculations, not proof of the regions’ application-level meanings.

The function can invalidate an existing entry before attempting to prepare replacement storage. A nonzero status from the storage-preparation dependency produces a null return; the function does not restore the previous entry.

The exact allocation, release, and bulk-initialization behavior belongs to dependencies whose implementations are unavailable. In particular, this contract does not assume that the external operation clears memory or that either dependency preserves context fields.

## Interface

### Inputs

The function accepts five inputs:

| Input | Representation in the supplied evidence | Role |
|---|---|---|
| Context address | 32-bit address carried in an integer-width argument | Locates a pointer table and record-selection metadata. |
| Entry index | 32-bit integer | Selects a table slot and participates in reverse record selection. |
| Descriptor address | Address of byte-oriented storage | Supplies a tag byte and, for two recognized tags, a 32-bit element count. |
| Caller value | 32-bit integer | Written unchanged to an output field on success. |
| Extra-region flag | 32-bit integer | Any nonzero value requests the additional 96-byte region and its pointer field. |

A negative extra-region flag is enabled, not rejected.

### Return value

The return value is a pointer to 32-bit words, or null.

- If F-05077d384bfe returns zero, the function obtains the return pointer from the selected record’s field at byte offset 20 and follows the success path.
- If F-05077d384bfe returns any nonzero value, the function returns null.
- No independent error code distinguishes preparation failure from other invalid conditions.
- There is no explicit null check on the pointer obtained after a zero status.

The returned pointer is captured before the external operation and subsequent explicit field writes. Later changes to the selected record’s storage-pointer field do not change the pointer returned by this function.

## Behavior

### 1. Select the record

Before invoking any dependency, the function reads the context’s record-selection metadata and calculates the selected record address using the 40-byte stride.

That calculated address is retained across later calls. If a dependency changes the context’s record-selection value or record-array base, this invocation does not recompute the selected record address.

The evidence does not establish an observable ordering between the individual metadata loads within this address expression.

### 2. Derive the count and requested size

The element count starts at zero.

The function reads the descriptor’s tag byte. If the tag is `b` or `p`, it reads the 32-bit value at descriptor offset 8 and uses that value as the element count. For every other tag, the count remains zero and the offset-8 field is not read.

The requested size is:

128 + 8 × element count + optional extension,

where the optional extension is 96 when the extra-region flag is nonzero and zero otherwise.

The count and requested size are computed before either mapped dependency is called. Later descriptor changes do not cause them to be recomputed.

The function does not require the count to be positive. A negative nonzero count still enables the later element-region pointer write.

### 3. Inspect and conditionally invalidate the table entry

The function reads the table address from context offset 48, then reads the four-byte table entry selected by the index.

If that entry is zero:

- F-92c72994fd48 is not called.
- No table-clearing store occurs at this stage.

If that entry is nonzero:

1. The function calls F-92c72994fd48 with the context address.
2. After the call returns, it reloads the table address from context offset 48.
3. It writes zero to the indexed entry in that currently referenced table.

The clearing store is therefore not necessarily directed to the same table object examined before the call. If the dependency replaces the context’s table pointer, the replacement table receives the explicit zero store.

The old entry value is not passed to the dependency. No direct release of that value is visible in this function.

### 4. Request storage preparation

The function calls F-05077d384bfe with:

1. The previously calculated selected-record address.
2. The previously calculated requested size.
3. A zero-valued third argument.

The function treats a zero return as success and every nonzero return as failure.

On failure, it returns null without executing the success-path publication, external operation, or explicit output-field writes. Earlier dependency effects and any table-clearing store remain observable. There is no rollback.

### 5. Publish the successful pointer

After a zero preparation status, the function:

1. Reads the address at selected-record offset 20 and captures it as the result pointer.
2. Reloads the context’s table address.
3. Stores the captured result pointer into the indexed table entry.

Publication occurs before the external operation and before all explicit output-field writes described below.

There is no explicit requirement that this pointer equal a value that existed in the record before preparation.

### 6. Invoke the external operation

After publishing the result pointer, the function rereads the selected record’s field at offset 20 and passes that address, together with the requested size, to an external operation.

The supplied evidence does not identify that operation’s semantics. Its return value, if any, is not used.

This call must not be specified as zero-filling, copying, allocation, validation, or deallocation without additional evidence.

The address passed to this operation comes from a fresh record-field read, not directly from the captured result pointer.

### 7. Perform explicit field writes

After the external operation returns normally, the function writes fields through the captured result pointer in this order:

1. Write the element count at offset 80.
2. Write the caller value at offset 4.
3. If the element count is nonzero, reread the selected record’s storage-pointer field, add 128, and write that address at result offset 112.
4. If the extra-region flag is nonzero, reread the selected record’s storage-pointer field, add 128 plus eight times the element count, and write that address at result offset 0.

The optional pointer calculations use record-field values read after the external operation. They are not necessarily relative to the captured result pointer.

The two optional calculations also use separate reads. If aliasing or an earlier write changes the record’s storage-pointer field, the later calculation can observe a different value.

When the count is zero, the function does not explicitly write offset 112. When the extra-region flag is zero, it does not explicitly write offset 0. The final contents of these omitted fields depend on prior memory contents and dependency effects; they are not established as zero.

### 8. Return

After the successful-path writes, the function returns the captured result pointer.

There is no further check that the table still contains that pointer or that the selected record still refers to it.

## Acceptance examples

These examples are conditional static acceptance criteria, not runtime test results. Unless otherwise stated, assume valid aligned storage, representable arithmetic, normal dependency returns, and no dependency-induced alias changes.

### Unrecognized tag, no extra region

Given an unrecognized descriptor tag and a zero extra-region flag:

- The count is zero.
- The requested size is 128 bytes.
- Descriptor offset 8 is not read.
- On preparation success, result offset 80 receives zero and offset 4 receives the caller value.
- Neither optional pointer field is explicitly written.

### Recognized tag with three elements

Given tag `b`, count 3, and a zero extra-region flag:

- The requested size is 152 bytes.
- On success, result offset 80 receives 3.
- Result offset 112 receives the selected record’s then-current storage address plus 128.
- Result offset 0 receives no explicit write from this function.

Tag `p` with the same count follows the same count and size behavior.

### Three elements and an extra region

Given count 3 and any nonzero extra-region flag:

- The requested size is 248 bytes.
- The element-region address is based at offset 128.
- The extra-region address is based at offset 152.
- With an unchanged record storage address, those calculated regions occupy the requested extent without overlap: 24 element bytes followed by 96 extra bytes.

That region interpretation is conditional on the dependencies supplying storage with the requested extent.

### Zero elements with an extra region

Given count zero and an enabled extra region:

- The requested size is 224 bytes.
- Result offset 112 is not explicitly written.
- Result offset 0 receives the then-current record storage address plus 128.

### Existing entry followed by preparation failure

Given an initially nonzero table entry:

- F-92c72994fd48 is called first.
- The table address is reloaded and its indexed entry is explicitly cleared.
- F-05077d384bfe is then called.
- If preparation returns nonzero, the function returns null.
- No success-path field writes or external operation occur.

The previous table value is not restored.

### Table replacement during invalidation

If F-92c72994fd48 replaces the context’s table address, the subsequent zero store targets the replacement table. The original table is not explicitly cleared through a saved table address.

### Record-pointer change during the external operation

If the external operation changes the selected record’s storage-pointer field from one valid address to another:

- The return pointer remains the value captured before that operation.
- Explicit result-field writes still target the captured pointer.
- Enabled optional pointer values are calculated from subsequent record-field reads and can therefore reference the replacement address.

### Negative count

This demonstrates missing validation, not an accepted application-level use of a negative count.
