# F-92f1741886c7

## Purpose

F-92f1741886c7 classifies an input object, obtains and converts a value for two recognized classifications, and conditionally invokes operations on a separate context object. It returns a 32-bit status restricted to zero or one on ordinary completion.

The established behavior has two processing routes:

- Classification **1** accepts conversion results **6, 7, 8, and 9**. Results 6 and 8 additionally invoke a context operation.
- Classification **3** accepts conversion result **3** and invokes three ordered context operations.

Every other classification or conversion result produces status zero. After processing, a non-null input object receives an indirect callback, including on unsuccessful processing paths.

The meanings of the classifications, conversion results, context operations, and final callback are not established. Interpreting them as particular application events, properties, or resource-management operations would be inferred intent, not part of this contract.

- **8:** Invoke **F-5bcae2eff9a7** with the context address plus 0x60; retain status one.

### 3. Process classification 3

For classification 3, the function invokes **F-b3bed2dfc5ec** using:

- A value read from the same shared global storage location used by classification 1.
- A value read from a different, classification-3-specific global storage location.
- The 32-bit all-ones value, **0xffffffff**.

As on the classification-1 route, a zero lookup result invokes the unidentified failure-path dependency. If it returns, the subsequent conversion receives zero. A nonzero lookup result is passed through to the conversion dependency.

This route uses **F-6b065a9b9915**, not F-118693b436a8.

If its conversion result is anything other than **3**, status is zero and none of the three route-specific context operations occurs.

If its conversion result is **3**, status is one and the following sequence is required:

1. Invoke **F-338d16f9ce72** with the context address plus 0x58.
2. After that invocation returns, read the 32-bit word at context offset 0x6c.
3. Invoke **F-b8a325ddd21b** with the value just read.

The second operation receives the stored word’s value, not the address of the word.

The read at offset 0x6c occurs after F-338d16f9ce72. Therefore, if that dependency changes the word, the later operation receives the changed value. Reading or caching this field before the first operation would not preserve the established behavior.

Return values from these three operations are ignored. There is no explicit rollback or compensating operation if a dependency fails to return normally.

### 4. Handle other classifications

For any classification other than 1 or 3:

- No lookup is performed.
- Neither conversion dependency is invoked.
- No route-specific context operation is invoked.
- Status remains zero.

The final callback stage still applies.

### 5. Perform the final callback

After the selected processing route completes, the function checks whether the input-object address is non-null.

For a non-null input:

1. Read its first 32-bit word as a callback-table base.
2. Read the callback target from offset 4 relative to that base.
3. Invoke that target with the original input-object address as its argument.

For a null input, skip this stage.

The callback target is obtained at this late stage. Earlier dependencies must not be assumed to preserve the input object’s first word or the callback-table entry. An implementation that caches the target before processing could call a different target from the one established here.

The callback’s return value is ignored. If it returns normally, the previously determined status is returned without further classification or context work.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, assume valid memory and normally returning dependencies.

1. **Unrecognized classification:** If classification returns 2, neither lookup nor conversion occurs. A non-null input receives its final callback, and the function returns zero.

2. **Classification 1, result 6:** A nonzero lookup result is converted to 6. F-5bcae2eff9a7 receives context plus 0x60 before the final callback. The function returns one.

4. **Classification 1, result 7 or 9:** The function invokes no route-specific context operation, still performs the final callback for a non-null input, and returns one.

6. **Zero lookup with accepted conversion:** On classification 1, lookup returns zero, the unidentified failure-path dependency returns normally, and F-118693b436a8 maps zero to 8. The context operation occurs and the function returns one. Lookup failure alone does not force rejection.

7. **Accepted classification 3 with mutation:** F-6b065a9b9915 returns 3. F-338d16f9ce72 changes the word at context offset 0x6c from one value to another. F-b8a325ddd21b must receive the replacement value, followed by F-1333331b2da1.

8. **Rejected classification 3:** Conversion returns 6. None of the three classification-3 context operations occurs, and the function returns zero after the final callback.

9. **Late callback-table change:** An earlier dependency changes the input’s callback-table base or the applicable entry. The final callback lookup uses the then-current contents, not an entry cached before processing.

10. **Null input with permissive classifier:** If classification accepts null and returns an unrecognized classification, the function skips the final callback and returns zero. This does not establish null safety for classification results 1 or 3, because those routes also call lookup.

11. **Non-returning dependency:** If a route-specific operation does not return, subsequent operations, the final callback, and an ordinary function return are not guaranteed.
