# F-0c7af4e898b8

## Purpose

F-0c7af4e898b8 conditionally handles a two-case request associated with a mutable object. It first compares a request word with an object word. A mismatch produces a zero result without invoking any dependency.

For a matching request, another request word and two external constants select between:

- Obtaining a three-word record, conditionally invoking object-state operations, and submitting a calculated difference to a dependency.
- Invoking two object-oriented dependencies in sequence.

The normal return is a 32-bit zero or one. One indicates that a recognized branch reached its end; it does not establish that any called operation succeeded.

**Inferred intent:** the record-backed branch appears to reconcile object state before applying a relative adjustment. The other recognized branch appears to perform a different state operation. The supplied evidence does not establish domain meanings for either branch, the record fields, or the object fields.

Three externally stored values are referenced. This contract names them **K₁**, **K₂**, and **S**:

Their values, mutability, and wider meanings are not supplied.

### Return value

The function returns:

- **0** if the initial object/request comparison fails.
- **0** if neither branch-selection condition matches.
- **0** if the record-backed branch is selected and F-5710a8628cba returns a null address.
- **1** after either recognized branch completes normally.

There is no separate status for whether the record matched the current object fields, whether indirect calls were needed, or whether a dependency reported an error. No dependency return value is checked as a success indicator.

### Preconditions and ownership

No explicit address validation is visible.

The object must support the initial read at +0x44, and the request must support the read at +0x0c. Further storage and callable-table requirements depend on the branch taken. In particular, the indirect-call table is not accessed on a rejected request or on a record match.

A non-null record returned by F-5710a8628cba must support reads of three consecutive four-byte words at offsets +0x00, +0x04, and +0x08 whenever the selected path reaches those reads.

No direct allocation, deallocation, or ownership transfer is visible. That observation does not establish that any dependency preserves, retains, transfers, or releases memory.

## Behavior

### 1. Initial eligibility comparison

The function first reads the object word at +0x44, then reads the request word at +0x0c and compares them.

If they differ:

- The request word at +0x08 is not read.
- No branch-selection lookup occurs.
- No dependency is called.
- The result is zero.

The comparison is an equality comparison of the loaded word values. No ordering relationship or range check is involved.

### 2. Branch selection

After the initial comparison succeeds, the function reads the request word at +0x08 and adds K₁. Call the resulting value **A**.

Branch selection is ordered:

1. If A is zero, take the record-backed branch.
2. Otherwise, add K₂ to A. If that result is zero, take the alternate branch.
3. Otherwise, return zero.

The second condition is therefore based on the result of the first addition, not on an independent addition of K₂ to the request word.

K₂ is not needed when A is zero. In particular, if both conditions could identify the same request value, the record-backed branch takes precedence.

The evidence shows signed integer expressions without checked-arithmetic handling. Exact overflow semantics are not established by the supplied representation; boundary expectations must not silently assume mathematical, saturating, or modular arithmetic. The acceptance examples below use representable arithmetic unless stated otherwise.

### 3. Record-backed branch: lookup

The function invokes F-5710a8628cba with:

1. The object word at +0x38.
2. S.

A null return immediately produces a zero result. No record comparisons, indirect calls, adjustment calculation, or adjustment submission follow that null return.

For a non-null return, the record layout is:

| Record offset | Contract name | Observed use |
|---|---|---|
| +0x00 | R₀ | First operand in the final difference |
| +0x04 | R₁ | Compared with object +0xac; later read again for the final difference |
| +0x08 | R₂ | Compared with object +0xb0 when R₁ matches; passed to an indirect call on mismatch |

These are positional names, not assertions of semantic meaning.

### 4. Record-backed branch: conditional object operations

After lookup returns a non-null record, the function reads the object word at +0xac and compares it with R₁.

If they differ, the record is treated as mismatching without comparing object +0xb0 with R₂.

If they match, the function then reads the object word at +0xb0 and R₂ and compares them. A difference also makes the record mismatching.

Thus:

- Agreement on both comparisons skips the conditional object operations.
- Disagreement on either comparison invokes those operations.
- The second comparison is short-circuited when the first fails.

On mismatch, the following calls occur in order:

1. An indirect call through the table entry at byte offset +0x11c, with the object as its sole explicit argument.
2. An indirect call through the table entry at byte offset +0x120, with the object and a read of R₂ as its explicit arguments.
3. F-9d69574111ff with the object.

This document labels the two unresolved indirect dependencies **F-unknown-1** and **F-unknown-2**, respectively. These are documentation-only identifiers, not resolved identities.

The second indirect call reads R₂ after the first indirect call returns. It is not specified to receive a value cached from the earlier comparison. If the first indirect call changes the record while leaving it valid, the second call can therefore receive the changed value.

The second indirect dispatch also obtains its table reference after the first indirect call returns. The function does not visibly preserve one table reference across both calls. A table change by F-unknown-1 can affect the second dispatch.

No ordering between the second call’s argument evaluation and its dispatch-target evaluation is established beyond both occurring after the first call and before the second call executes.

The object fields used in the mismatch decision are not checked again after these calls.

### 5. Record-backed branch: adjustment calculation and submission

Both the matching and mismatching record paths converge on the same calculation.

After any conditional calls have completed, the function reads:

1. R₀.
2. R₁.

It then invokes F-30ee4f4bfdfc with the object. Denote its integer result by **Q**.

The adjustment is the left-associated difference:

**D = (R₀ − R₁) − Q**

The values of R₀ and R₁ used here are read after the conditional object operations, not necessarily the values present immediately after lookup. Conversely, they are read before F-30ee4f4bfdfc is called. Changes to the record during that dependency do not alter the already captured operands.

The function then invokes F-a4d024505709 with four arguments:

1. The object.
2. D.
3. Zero.
4. Zero.

The return value of F-a4d024505709 is not used. If it returns normally, F-0c7af4e898b8 returns one.

There is no visible nonnegativity check, clamp, or range restriction on D. Negative differences are not explicitly rejected. Overflow behavior remains a documented uncertainty.

### 6. Alternate branch

When A is nonzero and A + K₂ is zero, the function invokes:

1. F-9d69574111ff with the object.
2. F-8988241ebca4 with the object.

The second call occurs after the first returns. Neither result is checked. Normal completion returns one.

This branch performs no record lookup and makes no direct record accesses or indirect-table calls.

## Side effects

The function contains no explicit write to object storage, request storage, record storage, or the external constants. Its directly visible effects are reads, calls, and the return value.

Indirect effects are not bounded by the supplied evidence:

- Any dependency receiving the object may mutate it or affect other storage.
- F-5710a8628cba may perform side effects while obtaining the record.
- F-unknown-1 may affect both the later record argument and the second indirect dispatch target.
- F-9d69574111ff may affect the record words subsequently used in the adjustment if aliasing or other shared state permits.
- F-30ee4f4bfdfc may mutate state, even though its returned value is used as a calculation operand.

The function retains the record address across several possible calls and dereferences it afterward. Safe execution therefore requires that those later accesses remain valid. The supplied evidence does not establish who ensures that lifetime.

There is no visible exception handling, rollback, synchronization, retry, or recovery from invalid addresses or failing indirect dispatches.

## Acceptance examples

These are conditional behavioral expectations, not executed tests. All referenced addresses and call targets are assumed valid, dependencies return normally, and arithmetic is assumed representable.

### Initial mismatch

Given different values at object +0x44 and request +0x0c:

- Result: zero.
- No dependencies are invoked.
- Request +0x08 is not accessed.

### Unrecognized selector

Given matching eligibility words, A ≠ 0, and A + K₂ ≠ 0:

- Result: zero.
- No dependencies are invoked.

### Missing record

Given matching eligibility words and A = 0, with F-5710a8628cba returning null:

- The lookup receives object +0x38 and S.
- Result: zero.
- No later dependency is invoked.

### Matching record

Given A = 0, a non-null record, object +0xac equal to R₁, and object +0xb0 equal to R₂:

- Neither indirect dependency nor F-9d69574111ff is invoked.
- R₀ and R₁ are read before F-30ee4f4bfdfc.
- If those reads yield 100 and 30, and F-30ee4f4bfdfc returns 12, F-a4d024505709 receives the object, 58, zero, and zero.
- Result: one after normal completion.

### First comparison mismatch

Given a non-null record whose R₁ differs from object +0xac:

- The object +0xb0 comparison is skipped.
- F-unknown-1, F-unknown-2, and F-9d69574111ff execute in that order.
- R₂ is still read for F-unknown-2.
- The adjustment path then executes.

### Mutation during the mismatch operations

Suppose F-unknown-1 changes R₂ from 7 to 9 while keeping the record valid:

- F-unknown-2 receives 9 if no intervening action changes that word again.
- No requirement exists to reuse the earlier value 7.

If the completed mismatch operations leave R₀ = 200 and R₁ = 40, and F-30ee4f4bfdfc returns 10:

- F-a4d024505709 receives an adjustment of 150.

### Mutation during the integer-returning dependency

Suppose the final record reads yield R₀ = 80 and R₁ = 20. F-30ee4f4bfdfc then changes those record words and returns 5:

- The adjustment remains 55.
- The changed record words are not reread for that calculation.

### Alternate branch and branch precedence

Given A ≠ 0 and A + K₂ = 0:

- Calls occur in the order F-9d69574111ff, then F-8988241ebca4.
- Result: one.
- No lookup occurs.

Given A = 0 and K₂ = 0:

- The record-backed branch takes precedence.
- The alternate branch is not selected.
