# F-fc6790129708

## Purpose

F-fc6790129708 conditionally copies one 32-bit word from an indexed location within a caller-supplied memory region to a caller-supplied output location.

The decision uses a signed comparison between two 32-bit fields in the memory region. If the first field is strictly less than the second, the function obtains an index from the first field, reads the corresponding word, writes it to the output, and returns status 0. Otherwise, it returns status 3 without accessing the output location.

**Inferred intent:** The fields resemble a current index and an upper bound, and the indexed locations resemble entries with an 80-byte stride. This interpretation is not required for the observed behavior. The function does not advance an index, establish that an entry exists, or validate either argument.

## Interface

### Inputs

The function receives two arguments:

1. **Base address:** An address identifying the memory region containing the comparison fields and indexed data. The supplied representation treats this argument as a 32-bit integer used in address calculations; the behavioral role is an address.
2. **Output address:** An address at which one 32-bit word is written when the signed comparison succeeds.

The relevant memory layout is:

| Offset from base | Access width | Interpretation and use |
|---|---:|---|
| `0x1078` | 32 bits | Signed comparison operand; read again as the index on the successful branch |
| `0x1080` | 32 bits | Signed comparison operand acting as the upper bound |
| `0x1250 + 0x50 × index` | 32 bits | Word copied to the output on the successful branch |

The entry stride, `0x50`, is 80 bytes. The fixed data offset, `0x1250`, is 4,688 bytes. Only one 4-byte word is accessed at each selected entry location; the function does not copy or inspect an entire 80-byte entry.

The comparison fields are at byte offsets 4,216 and 4,224, respectively.

### Output and return value

The function has two normal return statuses:

| Status | Condition | Output effect |
|---:|---|---|
| 0 | The first signed field is strictly less than the second | Writes the selected 32-bit word |
| 3 | The first signed field is greater than or equal to the second | Does not access the output |

The return representation is 32 bits. No signed interpretation of the return type is needed to distinguish the two observed values.

The transferred word is opaque. Its bits are copied without numeric conversion, byte swapping, masking, or interpretation as an address.

### Preconditions

For a normal return, the two comparison fields must be readable.

For the successful branch, the repeated index read and selected 4-byte source read must also be valid, and the output must support a 4-byte write. The address calculation must resolve to a valid source location under the target execution model.

The function performs no explicit checks for null addresses, allocation size, alignment, negative indices, or writable output storage. Invalid accesses are not converted into status 3.

## Behavior

### Comparison and branch selection

The function reads the 32-bit fields at base offsets `0x1078` and `0x1080` and compares them as signed integers.

The relative evaluation order of these two initial reads is not established by the supplied evidence. Both feed the branch decision.

Strict signed inequality controls the branch:

- A smaller first value selects the copy operation.
- Equal values select status 3.
- A greater first value selects status 3.

The comparison is not unsigned. A negative first value can therefore select the successful branch even when the second value is zero.

### Successful branch

After the comparison succeeds, the function reads the field at offset `0x1078` again to obtain the index used for addressing.

This repeated read is significant. The supplied representation does not establish that the index used in the address calculation is the same value previously used in the comparison. If an external agent can change that field between reads, the selected address may be based on a different value. The bound is not read again, and there is no second comparison.

The source word is located by adding the fixed data offset and an index-dependent displacement to the base address:

- Fixed offset: `0x1250` bytes.
- Per-index displacement: index multiplied by `0x50` bytes.
- Read width: 4 bytes.

After reading that word, the function stores its 32-bit value at the output address and returns 0.

No separate write updates the index, the bound, the selected entry, or any cursor-like state.

### Unsuccessful branch

If the signed comparison does not succeed, the function returns 3.

On this branch, it does not:

- Read the index a second time.
- Read the indexed data location.
- Read or write the output location.
- Clear an existing output value.

Consequently, the output address need not designate accessible storage for this branch, provided execution can validly evaluate the comparison and take the branch.

### Arithmetic boundaries

The supplied representation uses 32-bit signed fields and a 32-bit integer-like base argument. It does not establish a portable rule for multiplication overflow or address wraparound.

The signed comparison alone does not make the subsequent address calculation safe. A successful comparison can admit:

- A negative index.
- An index too large for the backing allocation.
- A value whose multiplication by 80 exceeds the signed 32-bit range.
- A displacement that produces an invalid address when combined with the base.

No explicit arithmetic-overflow or address-validity check is present. Behavior outside valid, representable address calculations remains documented_only rather than being assigned an invented wrapping or error convention.

## Side effects

The only explicit memory write is the successful branch’s 4-byte output store. The source location is read before this store.

No distinct input and output allocations are required by the visible operation. If the output aliases the source word or another part of the base region, the successful store affects that aliased storage. In particular, output aliasing either comparison field can change that field after the comparison and source read. This is an output-write consequence, not a separate state-management operation.

The function does not allocate, release, retain, or transfer ownership of storage. Both addresses remain caller-supplied storage references.

No synchronization, atomicity guarantee, retry, logging, callback, or explicit global-state access is shown. The function itself does not stabilize the fields against concurrent changes. The legality and visibility of such changes depend on execution rules not supplied here.

## Acceptance examples

These are conditional contract examples, not results of runtime tests. Unless stated otherwise, assume stable fields, valid addressing arithmetic, and accessible storage for every required access.

### First entry

Given a first field of 0 and a bound of 1, the comparison succeeds.

The function copies the 32-bit word at base offset `0x1250` to the output and returns 0. If the output is disjoint from the input region, neither comparison field changes.

### Later entry

Given an index of 2 and a bound of 5, the selected source offset is `0x12F0`: the fixed offset plus 160 bytes.

If that location contains the bit pattern `0x89ABCDEF`, the output receives that same bit pattern and the function returns 0.

### Equality

Given both comparison fields equal to 5, the function returns 3 and does not access the output. A sentinel already stored there remains unchanged.

### First field above the bound

Given a first field of 6 and a bound of 5, the function returns 3 without reading indexed data or accessing the output.

### Negative index

Given a first field of −1 and a bound of 0, the signed comparison succeeds.

If the resulting source address is valid, the function reads at base offset `0x1200`, which is 80 bytes before the index-zero location, writes that word to the output, and returns 0. There is no separate rejection of negative indices.

### Output aliases a comparison field

Given a successful comparison, suppose the output addresses the first comparison field.

The function reads the selected source word before overwriting that field. It returns 0 after the store. The final field value is the copied word, not an incremented index.

### Invalid output on the unsuccessful branch

Given equal readable comparison fields, an inaccessible output address does not cause an output access in the shown behavior. The function returns 3.

This does not imply that an inaccessible output is acceptable when the comparison succeeds.
