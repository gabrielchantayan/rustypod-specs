# F-09075a0731b6

## Purpose

F-09075a0731b6 has no established application-level purpose. The supplied static representation describes an operation that combines indirect calls, reads from computed addresses, four-word initialization, bit extraction, low-address memory writes, and a final state-update sequence. Several paths end at explicit invalid-instruction boundaries.

The contract below captures the observable operations supported by that representation. It does not identify the operation as a loader, decoder, allocator, validator, or serializer. Such interpretations would require evidence not supplied here.

The representation explicitly warns of invalid instruction data and truncated control flow. Consequently, this is a **conditional static contract**, not a claim that the entire represented path is executable. Normal completion, meaningful error reporting, and a conventional callable interface are not established.

## Behavior

### Entry and initial observations

The first visible action is an indirect call, identified here as F-000000000001. Its target depends on the incoming link-related value. The represented call supplies no explicit arguments and produces a composite 64-bit result.

The low half of that result becomes a destination address. The high half is retained for a subsequent call. Neither allocation nor ownership transfer is established by this return value.

Next, the function:

1. Reads an unsigned 16-bit value from the address base plus the incoming displacement.
2. Doubles that value and reads one unsigned byte from the resulting address.
3. Reads the same 16-bit source location again.
4. Invokes F-000000000002 with that second halfword value, the saved high result half, and a fixed address-valued constant.

The two halfword reads are distinct observations. They must not be merged into one cached read when describing the represented behavior. Their values need not agree if the memory is volatile, externally modified, or otherwise unstable.

The byte read uses twice the first halfword value. Its possible address range is 0 through 131070, inclusive, restricted to even addresses.

After F-000000000002, the function reads one byte from twice the signed control word, then issues software interrupt number 230. Continuation past that interrupt is a prerequisite for the following writes.

### Initial destination layout

| Byte offset | Stored value |
|---|---|
| 0 | Signed control word shifted right arithmetically by 20 bits. |
| 4 | Incoming stack word. |
| 8 | The previously read byte, zero-extended to 32 bits. |
| 12 | Incoming context word shifted left by 31 bits. Under a 32-bit bit-vector interpretation, only its least significant bit remains, in bit 31. |

The layout covers 16 bytes. No bounds check or null check precedes these writes. The source does not establish that the returned destination points to an object of that size.

The branch check occurs **after** all four stores. It examines whether four times the signed control word, minus 52, is negative. If so, F-000000000003 is called with no explicit arguments, followed by an invalid-instruction boundary if that call returns.

Within the range where this arithmetic does not overflow, control words at most 12 take that branch and control words at least 13 do not. This is not a universally valid simplification for all 32-bit inputs.

## Acceptance examples

These examples are conditional static expectations, not executed tests. All require the preceding calls, memory accesses, and interrupt to permit continuation.

### Distinct initial observations

If the first halfword read yields 3 and the byte at address 6 is 171, the initial destination’s offset-8 word receives 171.

If the second halfword read instead yields 5, F-000000000002 receives 5 as its first visible argument. The difference does not change the saved byte or the later halfword-store address, which remains 342.

### Branch boundary without overflow

For a signed control word of 12, the branch expression is −4. The four destination stores precede F-000000000003.

For a signed control word of 13, the expression is 0, so the long continuation is selected. Neither case implies that earlier address accesses succeed.

### Single-bit selection

A high result half of hexadecimal `10000000` produces one at the bit-28 extraction. A high half of hexadecimal `20000000` produces zero there because bit 29 is removed by the mask.

A bit-29-selected byte read accesses address 16 when that bit is zero and address 17 when it is one.

### Count boundary

A saved count of 9 still permits the state-base offset-104 store before reaching the count-rejection boundary.

A saved count of 8 selects the accepted path. If F-000000000006 returns, the byte written at state-base offset 15 is 8 and the address-derived halfword is written at address 48.

### Modular subtraction

If a composite high half is zero, unsigned subtraction of seven produces hexadecimal `fffffff9`; extracting its top bit yields one. This illustrates why that operation must not be replaced by an unrestricted signed comparison.
