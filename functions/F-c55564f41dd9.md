# F-c55564f41dd9

## Purpose

F-c55564f41dd9 directly writes 16-bit results derived from neighboring source positions, then reads an externally stored indirect-call target and invokes it with two destination-relative pointers and a width-derived count.

For width and height both at least two, the direct processing generates a rectangle of width elements and height minus one rows. Each nonfinal column combines an upper-right source element with a lower-left source element, favoring the upper-right element. The final column instead uses a single, equally weighted packed average.

The arithmetic is consistent with independently averaging three packed fields of widths 5, 6, and 5 bits. An RGB565 interpretation is **inferred intent**, not an established requirement.

The final call’s arguments are consistent with copying the last generated row into the following row. That operation is not established: the indirect dependency’s identity and behavior remain unknown.

## Behavior

### Packed averaging rule

For two unsigned 16-bit values, the packed average is the sum of:

- Their bitwise common bits.
- Half their exclusive-or contribution, after clearing bits selected out by the 32-bit mask `0xFFFFF7DF`.

The shift is a logical right shift of an unsigned quantity. The mask clears bit 5 and bit 11 before shifting. For stable 16-bit operands, the operation independently computes the rounded-down average of these fields:

| Field | Bit positions | Width |
|---|---|---:|
| Low | 0–4 | 5 bits |
| Middle | 5–10 | 6 bits |
| High | 11–15 | 5 bits |

The result fits in 16 bits. There is no saturation operation.

The intermediate average used for a nonfinal column is additionally masked with `0xFFFEFFFF`, clearing bit 16. For stable 16-bit inputs, that bit is already zero, so this extra mask does not change the value.

The field-average interpretation does not apply without qualification when one operand is the full, address-derived 32-bit retained state described below.

### Ordinary rectangular processing

Number source and destination elements from zero. For width at least two and height at least two, generated rows run from zero through height minus two, in increasing order.

For generated row \(r\), each nonfinal column \(c\), from zero through width minus two, uses:

- Upper input: source element \(r \times \text{width} + c + 1\).
- Lower input: source element \((r+1) \times \text{width} + c\).

The function first takes their packed average, then takes the packed average of the upper input and that intermediate result. It stores the result at destination element \(r \times \text{width} + c\).

For stable source values, each packed field therefore equals the rounded-down value of three times the upper field plus the lower field, divided by four. The two-stage packed arithmetic remains the primary definition.

The final column differs:

- Its upper input is the value captured during the preceding inner iteration: source element \(r \times \text{width} + \text{width} - 1\).
- Its lower input is source element \((r+1) \times \text{width} + \text{width} - 1\).
- The result is one packed average of those inputs.
- The destination is element \(r \times \text{width} + \text{width} - 1\).

The final column neither uses the preceding intermediate average nor applies the three-to-one weighting.

The first source element of the first row is not directly read on this path. Both source regions advance by one width between generated rows.

### Source-read and destination-write ordering

For each nonfinal output, the upper source value is captured before evaluating the result expression. The lower source location is referenced twice within the intermediate-average expression. The destination store occurs after the reads needed for that result and before processing the next output.

The supplied representation does not establish a physical-load count or an ordering between the repeated lower-source references. Stable-value formulas assume those references observe the same value.

For the final output of a row, the upper value is retained from the preceding inner iteration rather than reread from source storage. The final lower source location is again referenced twice before the store.

Rows and destination stores proceed sequentially. There is no entry-time source snapshot. With overlapping buffers, earlier destination stores can affect source values read later. The indexed formulas identify source locations; they do not guarantee those locations retain their entry-time contents.

### Widths of one or less

When the evaluated width-minus-one comparison is defined and fails, the inner loop is skipped. If the outer loop executes, each outer iteration nevertheless performs one direct destination store.

Before the first such iteration, the retained 32-bit state is initialized from the numerical destination pointer address, not from destination contents.

For each iteration:

- The directly used lower source position starts at source plus width and advances by one element per iteration.
- Its unsigned 16-bit value is combined with the retained 32-bit state using common bits plus the masked, right-shifted exclusive-or contribution.
- The mask is `0xFFFFF7DF`.
- The full 32-bit result becomes the retained state.
- Its low 16-bit representation is stored in the next destination element.

The retained state is not truncated to 16 bits between iterations. Direct results can consequently depend on the numerical destination address.

A separate source cursor advances without being dereferenced by this narrow-width calculation. Its pointer arithmetic still requires valid execution conditions.

### Final target read and invocation

After all direct destination stores, the function evaluates its final indirect-call expression. **The externally stored function pointer is read at this point, not captured at function entry.**

Let the current destination cursor denote the position immediately after the last directly written element. The selected target receives:

1. That current destination cursor.
2. That cursor minus width elements.
3. Width shifted left by one.

For the ordinary rectangular path, these arguments correspond to:

- Destination element \((\text{height}-1) \times \text{width}\).
- Destination element \((\text{height}-2) \times \text{width}\).
- A count numerically equal to twice width.

For a defined no-loop path, the pointer arguments are instead the original destination and that destination minus width elements.

For width one or less with outer iterations, the current destination advances by one element per outer iteration, not by width.

The target read occurs after the direct stores. The representation does not establish a relative evaluation order between that read and the final argument expressions.

No entry-time target stability may be assumed. Where otherwise permitted by the execution model, writes affecting the target’s storage during direct processing can change which dependency is invoked. In particular, destination storage overlapping the target’s storage can make direct stores affect the subsequently read target representation. Such overlap is not guaranteed to leave a valid callable target.

This timing does not establish synchronization or defined behavior for concurrent modification.

The count numerically equals a row’s byte size for ordinary positive widths. Its interpretation as a byte count remains unknown. Any result from the dependency is not exposed as this function’s return value. Normal return requires the dependency to return normally.
