# F-29357cfdfd40

## Purpose

F-29357cfdfd40 resolves an object, performs three probes, and selects between two processing paths using mutable context flags.

- **Ordinary path:** normalizes a context latch, selects a signed 16-bit mode, traverses associated objects, and performs special paired processing or mode-dependent ordinary processing.
- **Alternate path:** conditionally prepares the initially resolved object, repeats the probes with different arguments, optionally constructs and submits an object, and processes the initially resolved object.

These are descriptive roles, not established application semantics. This contract distinguishes direct operations from dependency effects: no called function is assumed to preserve globals, reachable memory, or ownership.

All behavior below is based on static evidence. No runtime tests have been performed.

## Interface

### Arguments and result

The interface has seven argument positions and a 32-bit return value.

| Position | Contract name | Established use |
|---|---|---|
| 1 | Context | Address of mutable state; forwarded to dependencies. |
| 2 | Auxiliary word | 32-bit value copied into temporary storage, with no subsequent observed use. |
| 3 | Descriptor | Address supplying a 32-bit field at `+0x04` and signed 16-bit fallback mode at `+0x10`. |
| 4 | Variant word | Unsigned 32-bit value forwarded unchanged and, elsewhere, XORed with `1`. |
| 5 | Unused word | No observed use. |
| 6 | Mode selector | 32-bit value; zero bypasses the initial virtual mode query. |
| 7 | Submission flag | 32-bit value tested only for zero versus nonzero. |

The pending return value begins as zero. Certain calls to F-733bb498002f replace it. It is not an accumulated status: a later replacement may overwrite any earlier value, including with zero.

Addresses and pointer-bearing fields are represented as 32-bit quantities in the supplied representation. No wider-address interpretation is established.

### Accessed storage

Offsets are byte offsets, not complete structure definitions.

| Storage | Accessed fields |
|---|---|
| Context | 32-bit fields `+0x20`, `+0x24`; address `+0x88`; byte fields `+0xA0`, `+0xA2`, `+0xA4`, `+0xA6`, `+0xCC`. |
| Descriptor | 32-bit `+0x04`; signed 16-bit `+0x10`. |
| Objects | Dispatch-table pointer `+0x00`; 32-bit flags `+0x1C`; 32-bit link `+0x34`; 32-bit operation fields `+0x58`, `+0x64`, `+0x70`, `+0x7C`. |

The function also supplies a four-byte temporary output area during initial resolution and an eight-byte temporary traversal state to traversal dependencies.

Five global storage locations supply 32-bit values, labeled **A**, **B**, **C**, **D**, and **E** here. These labels identify storage roles, not immutable constants. Their values need not be pairwise distinct.

Valid storage, sufficient lifetime, alignment, and permitted writes are preconditions wherever an access occurs without a preceding check.

## Behavior

### Initial resolution and preparation

F-23c46a4f09c5 receives the context, the descriptor’s `+0x04` value, and the four-byte output area. Its output-area contents are not subsequently consumed by this function.

A null returned object ends processing with result zero.

For a non-null object, its `+0x34` link is passed to F-682adfd5a561 with type token `0x1180`. A null result invokes F-a817d8d58c10, represented as non-returning. No normal error result is established for this case.

The context byte `+0xA4` is then read. Byte `+0xA6` is read only if `+0xA4` is zero. If either flag is nonzero, the type-resolved structure’s `+0xE8` byte is checked. A value of `0x80` causes F-b82f111644ab to receive the context and initial object.

### Initial probes and global-value timing

Three calls to F-da4db27112a2 follow in A, B, C order. Each receives the context, a fresh context `+0x20` value, the initial object, the descriptor, the corresponding global-derived value, and final argument `1`.

The global reads are temporally significant:

- A is read for the first call.
- B is read after the first call returns, for the second call.
- After the second call returns, C is read into a saved 32-bit value. The third initial call also obtains its token argument from C’s global storage before invocation; no dependency call intervenes between the saved read and that argument read.
- The saved C value remains available for the alternate path.

The three 32-bit probe results are combined by bitwise OR into a saved mask. Later decisions use that mask, not a new global read or repeated probe result.

The context flags are then read again, with the same short-circuit rule: read `+0xA4`, and read `+0xA6` only if `+0xA4` is zero. Both zero select the ordinary path. Otherwise the alternate path applies. Dependencies executed before this decision may have changed those flags.

### Ordinary path: latch and mode

Context byte `+0xA2` is overwritten with exactly `1` if its old value was nonzero or the saved mask contains both `0x02` and `0x08`. Otherwise it is overwritten with zero.

This normalizes any nonzero old value. It does not guarantee that later calls preserve the byte; later arguments using it are freshly loaded.

The selected mode is interpreted as signed 16-bit, with `-1` as the fallback sentinel:

- A nonzero mode selector causes virtual slot `+0x110` on the initial object to be called with that selector.
- If that query is bypassed or its signed 16-bit result is `-1`, the descriptor’s signed 16-bit `+0x10` field is read.
- If that field is `-1`, slot `+0x110` is called with zero.
- If this final query also yields `-1`, the selected mode becomes zero.

An earlier non-sentinel choice prevents subsequent fallback reads or calls.

F-583dc5fa4d66 receives the initial object. Its result is passed to F-8ca21d3a8cca to initialize traversal state. F-b38a3aba0e18 repeatedly advances that state and supplies an object pointer; zero ends traversal.

Each supplied object first goes to F-3fac671648b8. Zero skips the object. Otherwise F-682adfd5a561 receives the object and type token `0x1100`.

### Construction and submission operation

Where specified below, a **D submission** or **E submission** means this ordered operation:

1. F-0a77364c41cc receives size `12`.
2. After that call returns, the designated D or E global storage is read.
3. F-4e95b66bff0e receives the allocation result, the freshly read value, and zero.
4. F-8e50f265e4fa receives the context, the construction result, and zero.

There is no visible allocation-failure check. The global value is not cached before allocation. Repeated submissions may therefore use different values even for the same designated storage; D and E may also hold equal values.

### Special-object processing

A successful `0x1100` resolution takes this path only until a paired operation has completed. Type resolution still occurs on later traversal objects after that condition becomes true.

F-8af95ee92f68 receives the special resolved structure. Null skips the object entirely; it does not fall through to ordinary-object processing.

Otherwise F-733bb498002f receives the context, the returned special-path object, and zero. Its result replaces the pending return value.

If mask bit `0x08` is clear, enabled submission produces D followed by E. Traversal then continues without marking a pair complete. Multiple special objects can therefore follow this route.

If bit `0x08` is set, paired processing proceeds:

- Context byte `+0xCC` is directly written to `1`.
- Virtual slot `+0xFC` is invoked on the special-path object.
- If it returns null, F-d0d3f100effc finalizes traversal and the pending result is returned immediately. Mode-`14` postprocessing is bypassed.

The write to `+0xCC` precedes both the virtual call and finalization. Neither dependency is established to preserve that byte or other earlier effects. The function performs no explicit rollback; final reachable state is dependency-dependent.

For a non-null related object:

1. Its virtual slots `+0xC0` and `+0xA0` are called, in that order, each with argument `1`.
2. F-6b96c9e5bbe4 receives that object and the address of context `+0x88`.
3. Its `+0x34` link is followed, then the linked structure’s `+0x34` field supplies the paired related structure. That structure’s `+0x8C` word is saved.

The following operations retain this order:

- F-19fde5f06ccc is called with no explicit argument shown. Its result goes to F-278e2fa4b10f with the context, paired related structure, fresh descriptor `+0x04` value, original variant word, and `1`.
- F-19fde5f06ccc is called with the special structure’s `+0x80` address. Its result goes to F-a5146f308c64 with the context, special structure, variant XOR `1`, saved `+0x8C` word, and fresh context `+0xA2` byte.
- If submission is enabled, a D submission occurs.
- F-ffe0d92c57b7 receives the paired related structure; its result is unused. F-4048ace17dbb runs. F-ffe0d92c57b7 is called again for that structure, and byte `+0xEE` in this second result is cleared.
- F-9a608cfde6ff receives the context and fresh context `+0x20` and `+0x24` values. F-6b96c9e5bbe4 then receives the special-path object and that result.
- If enabled, an E submission occurs.
- The same two-call F-ffe0d92c57b7 sequence, with F-4048ace17dbb between calls and a subsequent `+0xEE` clear, runs for the special structure.

Next, for the paired related structure and then the special structure, F-ffe0d92c57b7 supplies a source. Its `+0xC4`, `+0xC8`, and `+0xCC` words are read and saved in that order. Another call supplies a destination. The saved words are written to corresponding destination fields in order, followed by the saved related-structure `+0x8C` value at destination `+0xD0`.

Successive calls need not return the same address or preserve memory. These operations are not established self-assignments.

If mask bit `0x02` is set, F-e26e0a89296e receives the context, paired related structure, special structure, and zero. Only afterward is the internal completed-pair condition set. Traversal continues.

### Ordinary-object processing

An object enters this processing if its `0x1100` resolution failed or a pair has already completed. Virtual slot `+0xFC` is called first; null skips the object.

For **mode `11`**, the 32-bit object flags at `+0x1C` are captured. Four bits independently select operations in this order:

| Flag | Object and related-object offset | Selector |
|---|---|---|
| `0x10` | `+0x58` | `5` |
| `0x20` | `+0x64` | `6` |
| `0x40` | `+0x70` | `7` |
| `0x80` | `+0x7C` | `8` |

Each selected operation reads the object field before another `+0xFC` call, reads the related field from that call’s result, and calls F-5496a92b382f with context, object, related value, saved object value, and selector.

Selection uses captured flags, even if earlier dependencies change them. Field values are loaded separately for each operation. If any selected bit was captured, the entire `+0x1C` word is cleared afterward, including unrelated bits. Otherwise it is not written. No mask-based ordinary processing follows for mode `11`.

For **other modes**, mask bit `0x02` enables a difference comparison. One fresh `+0xFC` result supplies related `+0x7C`; another supplies related `+0x64`. After the second call, object `+0x7C` is saved. The compared differences are related `+0x7C` minus related `+0x64`, and object `+0x7C` minus object `+0x64`.

If unequal, another virtual call supplies fresh related `+0x7C`. F-5c570586456d receives context, object, fresh related value, saved object value, selector `8`, and fresh context `+0xA2`. Nonzero skips the remainder for this object.

If not skipped and mask bit `0x20` is set, object `+0x64` is saved before another virtual call. F-c91b799b2c61 receives context, object, that call’s related `+0x64`, saved object value, zero, and fresh context `+0xA2`.

Repeated virtual results after the initial null check are dereferenced without further null checks.

On normal exhaustion, traversal is finalized. For selected mode `14`, F-5e0df028a8e0 then receives context, initial object, `4`, `1`, `1`; afterward context byte `+0xA0` is written to `1`.

### Alternate path

The original type-resolved structure’s `+0xE8` byte is read again. If it is `0x80`, F-39509ed7bd5a receives the initial object, followed by F-6f5b09ccd01c receiving context and that object.

Three further F-da4db27112a2 calls occur with final argument zero:

- The first reads A again.
- After it returns, the second reads B again.
- The third uses the C value saved before the third initial probe, not a fresh C read.

Each call uses a fresh context `+0x20` load. Their results are ignored. Earlier probes or intervening preparation may change global storage; that can affect the new A and B arguments but does not replace saved C.

Enabled submission produces only E. Finally, F-733bb498002f receives context, initial object, and zero; its result is returned.

This path performs no traversal initialization, mode selection, or direct `+0xA2` write.

## Side effects

Direct writes comprise context bytes, traversal/output temporaries, mode-`11` flag clearing, paired destination fields, and the specified `+0xEE` clears.

There is no explicit rollback. This describes the function’s own operations, not preservation of their effects across dependencies.

Initialized traversal is explicitly finalized on normal exhaustion and the identified null-related-object early return. No general cleanup behavior is established for dependency failures or nonlocal exits.

No explicit release of resolved objects or size-12 construction results is visible. Allocation ownership, submission ownership transfer, reference counting, and release behavior remain **documented_only** unknowns. Dependencies may mutate globals and reachable state.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Unresolved input:** A null initial resolution returns zero without probes or traversal.

2. **Required type failure:** Null initial `0x1180` resolution invokes F-a817d8d58c10; normal zero return is not a substitute.

3. **Mutable probe globals:** If the first probe changes B, the second initial probe receives the changed B value. If C later changes during alternate preparation, the third alternate probe still receives saved C. Alternate A and B are newly read.

4. **Post-allocation construction value:** If allocation changes D from `5` to `9`, a D submission reads `9` after allocation. Two D submissions may receive different values. Equal D and E values are permitted.

5. **Latch normalization:** On ordinary entry, old latch `7` and mask zero cause a direct write of `1`. Old latch zero with mask `0x02` causes zero; mask `0x0A` causes `1`.

6. **Mode fallback:** A nonzero-selector query yielding signed 16-bit `-1`, followed by descriptor mode `14`, selects `14` without the zero-selector query. Normal exhaustion performs mode-`14` postprocessing.

7. **Repeated special processing:** With bit `0x08` clear, two eligible special objects may both replace the return value and each produce D then E when submission is enabled.

8. **Paired early return:** With bit `0x08` set and null related-object lookup, the direct `+0xCC = 1` write precedes the lookup; traversal finalization precedes return; mode-`14` postprocessing is absent. Final `+0xCC` is not constrained to remain `1`.

9. **Mode-11 clearing:** Captured flags `0x110` select only selector `5`, then cause the whole flags word to be cleared. Captured `0x100` causes neither a selected operation nor that clear.

10. **Suppression and arithmetic:** Outside mode `11`, unequal non-overflowing differences invoke F-5c570586456d when bit `0x02` is set. Its nonzero result suppresses bit-`0x20` processing. Variant `2` is forwarded as `2` and XORed as `3`, not logically negated.
