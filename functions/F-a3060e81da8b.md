# F-a3060e81da8b

## Purpose

F-a3060e81da8b performs a conditional bulk operation or a repeated per-element operation over state associated with a supplied context. It writes a 32-bit result to caller-provided storage and returns a separate 64-bit value assembled from two 32-bit components.

The established control structure has two paths:

- A shortcut selected by two nonzero dependency results and a nonzero context field. This path invokes one dependency, resets several context-associated fields, and writes the resulting header address to the output.
- A general loop that compares two supplied values, advances mutable cursor storage, and invokes a per-element dependency until the comparison returns exactly 1.

The field layout and reset pattern suggest a container with a sentinel header, an element count, and a range-removal operation. That interpretation is **inferred intent**, not an established semantic contract for the dependencies.

### Return value

The return is a 64-bit bitwise concatenation:

- Upper 32 bits: the current value of a local context/result slot.
- Lower 32 bits: the current value of a local candidate slot.

This is a value-level packing rule, not a claim about byte order in memory.

The two slots begin with:

- Context/result slot: the original context value.
- Candidate slot: the original output address.

The per-element dependency receives both slots by address and may change them.

On the shortcut path, the upper half is instead explicitly set to the final header address written to the output, while the lower half remains the original output address.

## Behavior

### Initial output and comparison

The first observable operation is a 32-bit write to the output address. Its value is read from context +0x10.

The function then reads context +0x10 again and reads the 32-bit value at offset +0x08 from that header. It copies this value into a temporary slot.

The separate header read matters: if the initial output write aliases context +0x10, it can affect the following access. The behavior must not be specified as using a single immutable header snapshot throughout the function.

After initializing its local context/result and candidate slots, the function calls F-54610eed0112 with:

1. The cursor address.
2. The address of the temporary containing the initial header +0x08 value.

Any **nonzero** result enables the next shortcut check. A zero result skips that check and proceeds directly to the general loop.

The temporary is passed by address. The dependency can modify it, but the function does not subsequently consume its value.

### Second shortcut check

If the first comparison returns nonzero, the function reloads context +0x10 into another temporary and calls F-54610eed0112 with:

1. The endpoint value.
2. The address of that temporary header value.

Again, the dependency receives an address to a copied value, not the address of context +0x10 itself.

If this call returns zero, the function enters the general loop without reading context +0x14 for the shortcut decision.

If it returns nonzero, the function reads context +0x14. The shortcut is taken only if that field is also nonzero.

Thus both comparison results are tested for nonzero on this path. Neither must equal exactly 1.

### Shortcut operation and reset

Once the shortcut is selected, the function reads the current header through context +0x10 and obtains the 32-bit value at header +0x04. It calls F-71a2a5023986 with:

1. The original context value.
2. That header +0x04 value.

The dependency’s return value, if any, is not consumed.

After the call returns, the function performs these direct writes in sequence:

1. Set header +0x08 to the current header address.
2. Set header +0x04 to zero.
3. Set header +0x0C to the current header address.
4. Set context +0x14 to zero.

These accesses use fresh reads of context +0x10 rather than relying on the header value obtained before the dependency call. Consequently, a dependency change to context +0x10 affects which header receives the reset.

Each listed assignment is ordered before the next. The supplied evidence does not establish the relative machine-level ordering of multiple reads within an individual assignment.

Finally, the function reloads context +0x10, writes that value to the output address, and returns:

- Upper 32 bits: that reloaded header value.
- Lower 32 bits: the original output address.

It does not execute the general loop after this return.

### General loop

The general path repeatedly calls F-54610eed0112 with:

1. The original cursor address.
2. The original endpoint value.

The stopping condition is specifically a return value of **1**.

A return of zero, a negative value, or any nonzero value other than 1 causes an iteration. This differs from the nonzero tests used by the shortcut checks.

For each iteration, the function:

1. Reads the first 32-bit word from cursor storage and retains that value.
2. Calls F-0ff2c000bc5c with the cursor address.
3. Places the previously retained value into the local candidate slot.
4. Calls F-d03fddffbc6d with:
   - The address of the local context/result slot.
   - The original context value.
   - The address of the local candidate slot.
5. Writes the current local context/result value to the output address.

The candidate therefore comes from the cursor **before** advancement, while F-d03fddffbc6d is invoked **after** advancement.

The local context/result slot is not reinitialized between iterations. The candidate slot is overwritten from the newly captured cursor value on every iteration before being passed to F-d03fddffbc6d.

Neither dependency’s ordinary return value is used. Changes made through the two slot addresses supplied to F-d03fddffbc6d can affect the output write and final packed return.

Once comparison returns exactly 1, the function returns the current local context/result value in the upper half and the current candidate value in the lower half. There is no additional output write at loop termination.

If the first loop comparison returns 1, there are no advancement or per-element calls. In that case, the packed return contains the original context in the upper half and the original output address in the lower half.

### Arithmetic and termination

The function performs fixed-offset address accesses and 32-bit value transfers. It does not directly increment, decrement, or otherwise arithmetically update the field at context +0x14.

No explicit overflow handling accompanies the address offsets. Valid address calculation is a precondition rather than a checked outcome.

The loop has no independent iteration limit. Termination depends on dependency behavior eventually causing F-54610eed0112 to return exactly 1.

## Side effects

### Direct writes

The function directly writes:

- The output word at entry.
- Header fields and context +0x14 on the shortcut path.
- The output word after every completed general-loop iteration.
- The output word again immediately before shortcut return.

The initial output write happens before either comparison dependency is called. It remains observable even if a later dependency does not return normally.

On the general path, output can change the storage inspected by later comparisons if it aliases cursor or context state. The function does not isolate these regions.

Behavior after a dependency fails to return, faults, or performs a nonlocal transfer is unknown. Direct writes already completed are not undone by any visible logic.
