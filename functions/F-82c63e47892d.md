# F-82c63e47892d

## Purpose

F-82c63e47892d computes an integer result using a caller-supplied operand, a factor obtained through an indirect dependency, and an adjustment observed in caller-supplied storage after that dependency returns.

The supplied operand normally remains the operand for the calculation. The distinguished value **2,147,483,647** enables conditional substitution from the supplied storage. Substitution requires a strictly positive eligibility observation.

The dependency invocation is part of the behavior, not merely a means of obtaining a numeric factor. It remains required when the selected operand is zero. Its effects can influence the current result because the adjustment is observed after the call.

No application-level interpretation of the operand, factor, adjustment, or distinguished value is established. A default-selection interpretation is plausible but is not a contractual meaning.

## Behavior

### Operand-selection requirements

For every supplied operand other than **2,147,483,647**, the selected operand equals the supplied operand. The function does not directly consult the second element for selection on that path. This does not restrict accesses made by the dependency.

For the distinguished operand, the selection outcome depends on the second element:

| Eligibility observation | Selected operand |
|---|---|
| Zero or negative | The distinguished value remains selected |
| Strictly positive | One less than a subsequent observation of the second element |

Eligibility and replacement are separate evaluations. With stable observations, a stored value of six selects five, and a stored value of one selects zero. A stored value of zero does not select negative one because it fails the eligibility requirement.

Separate evaluations do not establish two physical loads, atomic access, synchronization, or a valid mechanism for concurrent mutation. If the execution environment validly permits the evaluations to observe different values, the replacement observation determines the substituted operand.

A positive eligibility observation therefore does not, by itself, prove that the replacement decrement is valid. For example, a different replacement observation at the signed minimum would make subtraction of one unrepresentable under arithmetic rules that prohibit signed overflow.

Selection is complete before dispatch resolution and dependency entry. Changes to selection storage during the dependency call do not revise the operand already selected for the current invocation.
