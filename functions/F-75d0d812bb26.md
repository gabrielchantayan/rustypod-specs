# F-75d0d812bb26

## Purpose

F-75d0d812bb26 constructs a shared, text-like result using a signed selector and a contextual value, publishes a dependency-produced 32-bit value through an inherited output address, and returns the 32-bit value 1 on every visible normal exit.

A negative selector at the branch-test read selects direct formatting into the shared destination. A nonnegative selector at that read selects indirect dispatch followed by status-dependent processing. Status values 0 and 1 select distinct descriptors; other values select a general-status formatting path.

The selector, contextual value, status, and shared-destination reference are not uniformly captured at entry. Their separate read points are behaviorally significant. In particular, the selector passed to dispatch need not equal the selector used for branch selection, and the status passed to general-status formatting need not equal the status that selected that path.

Text construction, descriptor lookup, and object cleanup are inferred roles. Exact text, dependency semantics, ownership, and lifetime are not established.

## Behavior

### Initial operation and selector reads

F-5b24edfb22c0 first receives the working-object address. Only after it returns is the selector read from its frame location and interpreted as signed:

- A value below zero selects direct shared formatting.
- A value of zero or above selects status initialization and indirect dispatch.

An entry selector alone therefore does not unconditionally determine the branch. That conclusion requires the initial operation to leave the selector storage unchanged.

The selector has a second read on the dispatch path, after F-e38e6836b640 returns. The value supplied to the indirect operation is the value at this later read, not a guaranteed copy of the branch-test value. A nonnegative branch-test value does not guarantee that dispatch receives the same value, or even a nonnegative value.

### Negative branch

When the branch-test read is negative, F-1f62160dfd52 receives these arguments in order:

1. The shared destination obtained for this formatting operation.
2. A fixed negative-case descriptor address.
3. The contextual value read from frame storage for this call.

The contextual read follows F-5b24edfb22c0. It is not guaranteed to equal the entry contextual value unless the intervening operation preserves that storage.

This branch does not initialize status, obtain the dispatch receiver, invoke the indirect operation, or perform status-specific descriptor lookup. It proceeds to the common publication sequence.

The negative-case descriptor’s contents and formatting rules are unavailable.

### Nonnegative branch and dispatch

When the branch-test read is nonnegative:

1. The inherited seed is written to the 32-bit status location.
2. F-e38e6836b640 receives the object-related base advanced by 24 bytes.
3. The returned receiver and its dispatch structure are used to obtain the target at byte offset 384.
4. The target is invoked with the receiver, the later-read selector value, and the status address.

The indirect operation’s return value is ignored. Its status write, if any, is not checked separately.

Status initialization occurs before object lookup. Consequently, both object lookup and the indirect operation occur between initialization and subsequent status selection. Neither is established to preserve status storage. The seed remains the effective selection value only if no intervening operation changes that storage.

There is no visible local rejection based on the selector’s upper bound. Nor is there a second sign check on the value supplied to dispatch.

### Status selection

After indirect dispatch returns, the status location is read for comparison with 0. If that comparison fails, it is read for comparison with 1. No dependency call appears between these comparisons.

**Zero case:** F-9d0ecc5f6adf is called without explicit arguments. After it returns, the status-zero descriptor reference is read. F-c0b020cd3882 receives the returned value and that descriptor. F-151ab4bfe553 then receives the working-object address and the lookup result.

**One case:** The same sequence occurs using the distinct status-one descriptor.

**General case:** If neither comparison matches, the function:

1. Calls F-9d0ecc5f6adf.
2. Reads the general-status descriptor reference and supplies it, with the preceding result, to F-c0b020cd3882.
3. Passes the temporary-object address and lookup result to F-7afe554bcf62.
4. Passes the temporary-object address to F-44362605ab79.
5. Reads status again for the formatting argument.
6. Calls F-1f62160dfd52 with the working-object address, the temporary conversion result, and that later status value.
7. Calls F-289ec4311c64 on the temporary-object address.

The general branch is selected using the comparison reads. Its formatting argument is read only after F-9d0ecc5f6adf, F-c0b020cd3882, F-7afe554bcf62, and F-44362605ab79 have executed. None has an established status-preservation contract.

Thus a value other than 0 or 1 can select the general branch while a later value of 0, 1, or anything else is supplied to formatting. There is no branch reselection after that later read.

## Acceptance examples

These are conditional static-contract examples, not executed tests. They assume valid reached storage and normally returning dependencies.

### Negative selector at the branch read

If the selector read after F-5b24edfb22c0 is −1, direct shared formatting occurs and no dispatch lookup occurs. The same applies to −2,147,483,648.

The formatting call receives the contextual value present after setup. Final shared conversion supplies the published value; the output store precedes working cleanup; return is 1.

An entry selector of −1 establishes this scenario only if setup preserves the selector storage.

### Zero selector preserved through lookup

If the branch-test selector is 0 and F-e38e6836b640 leaves that storage unchanged, dispatch receives 0.

If the subsequent zero comparison matches, the status-zero descriptor path executes without temporary-object operations. Shared formatting receives the converted working result before the current contextual value in argument order.

### Selector changes before dispatch

If the branch-test selector is 5 but object lookup changes the selector storage to −3, dispatch receives −3. The function does not reconsider the negative branch.

Likewise, a branch-test value of 2,147,483,647 reaches object lookup without local upper-bound rejection. Dispatch receives that same maximum value only if the selector storage remains unchanged.

### Status one

If the zero comparison fails and the following comparison reads 1, the status-one descriptor path executes. Later status changes do not cause the general-status branch to be selected.

### General-status selection and later mutation

If the status comparisons read −7, the general-status branch executes. Temporary conversion precedes working-result formatting, and temporary cleanup follows that formatting.

The formatting argument is −7 only if the intervening calls preserve status storage. If those calls instead leave 1 in that storage, formatting receives 1 while remaining on the already-selected general branch. No displayed numeric rendering is established.

### Seed retention

If the seed is 1 and object lookup plus indirect dispatch leave status storage unchanged, the status-one path is selected. A write by the indirect operation is not required.

### Contextual-value mutation

If a nonnegative-path dependency changes contextual storage before the outer formatting call, that call receives the changed value. It is not required to receive the entry value.

### Shared-reference mutation

If shared formatting targets one object and an intervening dependency changes the shared reference before final conversion, final conversion receives the later referenced object. Equality of the two destinations is not guaranteed.
