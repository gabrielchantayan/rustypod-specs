# F-0882173e5b5b

## Purpose

F-0882173e5b5b searches an indexed source backward for the numeric marker `0x23`. The search stops unsuccessfully if it encounters `0x5C`, `0x2F`, or `0x3A` before finding that marker.

When a marker qualifies, the function requests processing of two ranges, in this order:

1. The range after the marker, using the third argument as the destination-like value.
2. The range before the marker, using the second argument as the destination-like value.

If the value immediately before the marker is `0x5C`, that one position is excluded from the second range. This preceding-position check happens after the first range’s processing and finalization calls.

The function returns a 32-bit `1` when the marker branch completes, or a 32-bit `0` when the search ends without entering that branch. These results identify completed control-flow paths, not verified success of the destination operations.

Interpreting the numeric values as `#`, backslash, slash, and colon suggests separation of a marker-qualified suffix from a path-like prefix. That interpretation is inferred intent. The numeric comparisons, range arguments, call ordering, and return values are established static behavior.

## Behavior

### Initialization and scan bound

The function first initializes the two temporary words from the third and fourth arguments.

It then reads the source’s 32-bit field at byte offset `+4` and passes that field value to F-d8cbf9aa79a9. The returned signed 32-bit value becomes the scan bound, called **N** here.

The function uses this result directly in index and range arithmetic. It does not separately validate the result or check that it matches an actual source extent. Calling **N** a length is an interpretation, not an established dependency contract.

### Reverse search

The first candidate index is **N − 1**. Each subsequent candidate is one less than the preceding candidate. A candidate is accessed only if it is nonnegative.

At each accessed candidate, F-08e2860e8e52 receives the original source reference and the candidate index. Its signed 32-bit result is compared directly with numeric constants; no explicit narrowing to an 8-bit character is visible.

The following results stop the search and lead to return value `0`:

- `0x5C`
- `0x2F`
- `0x3A`

If none of those stopping values matches, the result is compared with `0x23`. That value enters the marker branch. Every other value causes the search to continue at the preceding index.

Thus, among positions actually searched, the highest-index marker qualifies. A stopping value encountered first prevents examination of all earlier positions. The function does not treat a backslash immediately before a marker as an escape that suppresses the marker: the marker is encountered first, and its preceding position is considered later.

For **N = 0**, the initial candidate is `−1`, so no indexed-access call occurs and the function returns `0`. For a negative **N** other than the minimum signed 32-bit value, the initial candidate is also negative and the same no-access result follows. Whether negative bounds are valid under F-d8cbf9aa79a9’s contract remains unknown.

### Suffix-side processing

Let **K** be the nonnegative index where indexed access returned `0x23`.

Before examining the position preceding the marker, the function completes these calls in order:

| Dependency | Arguments |
|---|---|
| F-ed33cfb647fe | Temporary address, original source reference, start **K + 1**, count **N − K − 1** |
| F-46f0b3cb316e | Original third argument, temporary address |
| F-289ec4311c64 | Temporary address |

For a marker reached through the ordinary positive-bound scan, **0 ≤ K < N**. Consequently, the suffix start lies between `1` and **N**, and the suffix count lies between `0` and **N − 1**. These expressions remain within signed 32-bit range when **N** is a positive signed 32-bit value.

A marker at the final position produces a zero-count suffix request with start **N**. The function issues that request; whether the dependency accepts such an empty range is not established.

### Prefix selection and processing

After the suffix sequence returns normally, the function determines the prefix count:

- When **K = 0**, it performs no preceding-position access and selects count zero.
- When **K > 0**, it calls F-08e2860e8e52 with the original source reference and index **K − 1**.
- If that later result equals `0x5C`, it selects count **K − 1**.
- Otherwise, it selects count **K**.

Only one preceding position can be excluded. There is no repeated trimming. A preceding `0x2F` or `0x3A` is not excluded.

The function then completes these calls:

| Dependency | Arguments |
|---|---|
| F-ed33cfb647fe | Same temporary address, original source reference, start zero, selected prefix count |
| F-46f0b3cb316e | Original second argument, temporary address |
| F-289ec4311c64 | Temporary address |

It then returns `1`.

The prefix count is nonnegative on the ordinary marker path. A marker at index zero, or a marker at index one preceded by `0x5C`, produces a zero-count prefix request.

### Temporal consistency

The function does not establish a source snapshot.

The preceding-position access occurs after all three suffix-side calls. If any of those dependencies changes the source, releases relevant resources, or changes state used by indexed access, the prefix decision can reflect that changed state.

The prefix range request also occurs after suffix destination processing. Source–destination aliasing can therefore affect the data available to the prefix operation. The function does not recompute the scan bound or rescan for the marker after those calls.

## Side effects

3. Call F-d8cbf9aa79a9.
4. Call F-08e2860e8e52 at descending nonnegative indices until search termination.

6. If the marker index is positive, perform the preceding-position access.

Additional acceptance conditions:

- **One preceding backslash:** `name\#tag` qualifies. The prefix request covers `name`; the immediately preceding backslash is excluded.
- **Two preceding backslashes:** `name\\#tag` qualifies. Exactly one backslash is excluded; the earlier one remains in the prefix request.
- **Preceding slash or colon:** `name/#tag` retains the slash in the prefix request. `name:#tag` retains the colon.
- **Backslash after the marker:** `name#tag\rest` returns `0` because reverse scanning encounters the backslash before the marker.
- **Negative bound:** For bound `−1`, the first candidate is `−2`; no indexed access occurs and the return is `0`. No such prediction is established for the minimum signed 32-bit bound.
- **Used dependency results:** A scan-bound result of zero prevents indexed access. An indexed result of `0x2F` terminates scanning; an indexed result of `0x23` selects the marker branch.
- **Ignored processing status:** If a range-processing dependency reports failure through its return value but returns normally, that value does not prevent the next destination-processing call.
- **Aliased destinations:** Both destination calls occur in the established order. Their final shared-object state is documented_only.
- **Mutation before prefix selection:** If suffix processing changes the value at **K − 1**, trimming follows the later indexed result, not a saved earlier value.
