# F-e4753b656f0b

## Purpose

F-e4753b656f0b searches a zero-terminated character sequence for the first occurrence of a requested character.

The search includes the terminating zero character. A request for zero therefore succeeds at the terminator rather than reporting absence. A request for any other character fails if the search encounters zero before finding that character.

A successful result identifies the matching character in the original storage. The function does not construct or return a copy.

This contract describes static behavior established by the supplied function body. It does not establish that arbitrary integer values are usable addresses, that an unterminated region can be searched safely, or that a particular platform’s integer and pointer representations are interchangeable.

## Interface

### Inputs

The function has two inputs:

1. **An integer-encoded starting address.**  
   The declared input type is a signed integer, not a pointer. The function derives a character pointer from this value. For a supported call, that derivation must identify the first character of readable storage under the applicable implementation’s address-conversion rules.

2. **A character to find.**  
   The declared input type is a plain character type. The search compares this value with each character read from storage. A zero value requests the sequence terminator.

There is no length argument, end-address argument, encoding argument, or separate indication of storage capacity.

### Output

The result is a character pointer with one of two meanings:

- **Match:** a pointer to the first character equal to the requested character.
- **Absence:** a null pointer, returned when a zero character is encountered without matching the requested character.

A successful pointer aliases the supplied storage. It is not newly allocated memory, and returning it does not transfer ownership.

The return type does not impose read-only access. Nevertheless, the function establishes neither that the underlying storage is writable nor that a caller may modify it.

### Widths and representation

The supplied declaration does not explicitly specify the bit widths of the signed integer, plain character, or pointer types.

Established properties are:

- Address preparation includes signed-integer subtraction before conversion to a pointer.
- Scanning advances in units of one character object.
- Each comparison uses a character value read from the current position.
- Zero is the termination value.
- No fixed-width length or counter limits the scan.

An 8-bit character and a 32-bit integer or pointer are not independently established by this body. Such widths may be platform facts, but they require evidence outside this function.

The signedness of plain characters is also unspecified here. Both the search character and each loaded character have the same declared character type, so the body does not introduce an explicit signed-versus-unsigned conversion between them. Callers supplying values outside the representable range of that type must account for the platform’s argument-conversion rules.

## Behavior

### Search domain and preconditions

For normal completion, the starting address must be meaningful under the target implementation, and every character position reached by the scan must be readable.

The readable region must contain either:

- the requested character; or
- a zero character that stops the search.

A zero terminator is not required beyond an earlier matching character, because the function does not continue past a match. Conversely, merely having a terminator somewhere in memory is insufficient if reaching it requires an invalid read.

There is no validation of the supplied address, readable extent, alignment, or lifetime. The function does not explicitly handle a null or otherwise invalid starting address.

Address preparation also has implementation-sensitive constraints. The integer address is reduced by one before pointer conversion. If this subtraction is evaluated as ordinary signed-integer arithmetic, the minimum representable input cannot undergo that subtraction without signed overflow. No wraparound guarantee is established.

The intermediate pointer corresponds to a position preceding the intended first read. The portability of subsequently advancing that pointer depends on the implementation’s pointer and object model. The body alone does not establish a universally valid, strictly portable integer-to-pointer construction, even for an integer numerically resembling a valid address.

### Read order and stopping conditions

The first character read is the character at the intended starting address. The preceding position used during address preparation is not dereferenced.

Subsequent reads proceed toward increasing character positions, one position at a time. At each position, the function reads a character and determines whether that character is either:

- equal to the requested character; or
- zero.

The first position satisfying either condition ends the scan.

If the character at that stopping position equals the requested character, the function returns a pointer to that position. Otherwise, it returns a null pointer.

Consequently:

- A match at the starting position requires only the initial character read.
- An initial zero stops the scan immediately.
- A requested zero matches the first zero encountered.
- A nonzero request cannot match any character located after the first zero.
- If a requested character appears multiple times before zero, only its earliest occurrence matters.
- The function performs no further source-level character reads after reaching a stopping position.

These are properties of the supplied body’s access sequence. They are not guarantees about machine-level speculation, memory-mapped I/O, or synchronization with concurrent writers.

### Character interpretation

The function performs character-value equality comparisons. It does not perform case folding, locale-sensitive matching, normalization, decoding, or multicharacter matching.

Where text uses an encoding composed of multiple character-storage units, the function still searches individual stored character values. The body supplies no basis for treating an encoded sequence as one logical character.

Zero has structural significance regardless of the intended encoding. Once encountered, it prevents the search from considering later storage positions.

### Failure and abnormal execution

Absence is represented solely by a null pointer. There is no distinct error result, diagnostic, exception-handling path, or explicit error-state update.

A null result therefore means that normal execution encountered zero before a nonzero requested character. It does not report that an invalid address was detected.

If the scan reaches unreadable storage, or if address preparation or pointer advancement is invalid under the execution model, the supplied body establishes no defined recovery behavior. A fault, nontermination, or another consequence cannot be selected as the guaranteed outcome from static evidence alone.

## Side effects

The established data accesses are reads from consecutive character positions until the stopping condition is met.

The function body contains no writes to the searched storage, no explicit writes to global state, and no calls to other functions. It contains no allocation, release, ownership-registration, or reference-counting operation.

The returned pointer remains dependent on the original storage’s lifetime. This function does not extend that lifetime or make a snapshot. Later changes to the storage can therefore change the character observed through a previously returned pointer.

The body contains no synchronization. Behavior under concurrent modification, volatile storage, memory-mapped devices, or other externally changing memory is not established by this contract.
