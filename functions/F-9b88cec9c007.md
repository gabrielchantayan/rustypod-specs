# F-9b88cec9c007

## Purpose

F-9b88cec9c007 compares two byte sequences using zero-valued bytes as terminators and returns one of three 32-bit results.

The comparison has two distinct ordering rules:

- At the first unequal pair of **nonzero** bytes, the sequence containing the larger unsigned byte receives the positive result.
- If one sequence terminates after an otherwise equal prefix, the **shorter** sequence receives the positive result.

These rules are not ordinary ascending lexicographic string ordering. In particular, termination is ordered above any nonzero byte, while nonzero bytes are ordered by their unsigned numeric values.

The supplied body establishes the comparison and its return values. A likely intent is to provide a three-way ordering operation, but no caller, application meaning, or required interpretation of that ordering is supplied.

## Behavior

### Comparison position

The comparison starts at the first byte of each input. It advances both positions together only when the current bytes are equal and nonzero.

Consequently, every position reached after the initial position has an equal, nonzero prefix preceding it. No position is skipped, and neither input advances independently of the other.

### Termination takes precedence

At each reached position, the first input is checked for a zero byte before the ordinary unequal-byte comparison is considered.

If the first input is zero:

- A zero byte in the second input produces `0x00000000`.
- A nonzero byte in the second input produces `0x00000001`.

If the first input is nonzero and the second input is zero, the result is `0xFFFFFFFF`.

This means an empty first sequence compares positively against any nonempty second sequence. A nonempty first sequence compares negatively against an empty second sequence. The same rule applies after any equal nonzero prefix.

For example, a sequence consisting of byte 65 followed by a terminator compares positively against a sequence consisting of bytes 65 and 66 followed by a terminator. The reverse comparison produces the all-one result.

### Unequal nonzero bytes

When both current bytes are nonzero, their values are compared.

If they differ:

- A larger first byte produces `0x00000001`.
- A smaller first byte produces `0xFFFFFFFF`.

The ordering is unsigned. A byte value of 128 is larger than 127, and 255 is larger than 1. There is no signed-character interpretation in the supplied comparison.

The first decisive position determines the result. Later bytes do not contribute.

### Equal nonzero bytes

If both current bytes are the same nonzero value, both positions advance by one byte and the comparison continues.

Equality is returned only when both sequences reach zero at the same position. Matching nonzero prefixes alone do not produce equality.
