# F-0033bb05e7ad

## Purpose

The established behavior is a fixed-order sequence of indirect calls, register-derived calculations, memory transfers, and global updates. The displayed interface has no explicit return value.

The application-level purpose is **documented_only**. The supplied static representation does not establish whether the accessed storage represents ordinary objects, hardware registers, executable vectors, or another structure. Scaling and repeated offsets establish addressing rules, not an object model.

This contract covers the displayed straight-line path, conditional on each preceding operation completing. It does not establish that execution can safely reach the end.

### Widths, layout, and notation

A **four-stride field** is at four times the specified value plus byte offset `0x14`. A **selected status destination** is obtained by reading one unsigned byte at a specified selector address and adding `0x11` to that byte value.

Explicit accesses comprise 8-bit reads and writes, 16-bit writes, 24-bit global-value reads, and 32-bit reads and writes. Pair-shaped results contain low and high 32-bit halves. Retaining a low byte means retaining the least significant eight bits of the value, not reading an arbitrarily chosen byte of its storage representation.

Unsigned right shifts are logical. Unsigned 32-bit arithmetic retains the low 32 bits when necessary. Several other address calculations and left shifts are expressed using signed 32-bit quantities. Their behavior outside representable, valid-address cases is **documented_only**; this contract does not silently replace them with unsigned arithmetic.

Multi-byte byte order, alignment requirements, address validity, and access atomicity are not established.

## Side effects

Every explicit read and write above is a potential observable memory operation. Destinations may alias each other, global storage, dependency-owned storage, or later sources.

Important ordering and retention constraints include:

- The first payload-field write uses stride 16; the later payload-field write uses stride four.
- Word-to-byte propagation reads a full word before writing its numeric low byte.
- The repeated transfer through the earlier transfer base performs a new word read.
- Captured payload, small base, pointer base, and pointer-based word are reused without implicit refreshes.
- The pair-derived field write precedes capture of the pointer-base global.
- The later field write precedes the read through that captured base.
- The final pointer-zero write precedes the three-byte global read and control-word write.
- The final halfword write follows the control-word write and may alias earlier destinations.

There is no explicit allocation, release, lock, exception handler, error result, or rollback path in this body. This is not a guarantee about dependencies. Unknown dependencies may allocate, release, overwrite, restore, fail, or not return.

The routine establishes no ownership transfer for accessed memory. Stored pointer-like or scaled values do not prove allocation, borrowing, retention, or release semantics.

No displayed conditional branch validates addresses or selects an error path. Outcomes of invalid calls, inaccessible memory, misalignment, arithmetic outside established semantics, or dependency failures are **documented_only**.

## Acceptance examples

These are conditional static criteria, not executed tests. Each assumes valid memory, returning dependencies, and defined arithmetic for the values involved.

1. **Initial call order.** After F-U003, F-U004, F-U005, and F-U006 must occur before F-U007. After F-U008, exactly F-U009–F-U012 precede the register-derived zero write.

2. **Unsigned input extraction.** Input C equal to `0xffffffff` produces a stored word of `0x1ff` and selector address 512. Input C below `0x00800000` produces zero and selector address 1.

3. **Byte selection and truncation.** A selector byte of `0xff` selects destination `0x110`. If the first captured word is `0xffffffff`, shifting it right by 22 yields `0x3ff`; the status write stores `0xff`.

4. **Payload width and stride.** A payload of `0x123456ab` produces an immediate byte write of `0xab`, while both redistribution writes retain `0x123456ab`. For an index of 3, the 16-stride destination is `0x44`; the four-stride destination is `0x20`.

5. **Captured versus refreshed storage.** If the captured small base is 7 and a later dependency changes the byte at address 1 to 9, its later transfer still reads at `7 + 0x74` and writes at `7 + 1`.

6. **Repeated transfer.** If a dependency between the two earlier-base transfers changes the source word’s low byte, the second transfer writes the changed value. Reusing the first read would not satisfy the contract.

7. **Later call counts.** Following F-U087, F-U101, and F-U123, respectively, exactly three intervening calls precede the corresponding index-producing call: F-U091, F-U105, and F-U127.

8. **Final construction and aliasing.** If the three-byte read yields `0x123456` and F-U137 yields `0xab`, the control word is `0x123456ab`. If the preceding pointer-zero write aliases that three-byte storage, the read must reflect the intervening write under the applicable memory model.

9. **Failure and restoration.** A dependency that restores an earlier destination before failing is not excluded. The established limitation is absence of an explicit rollback path in this routine.

10. **No guaranteed return.** If address zero is not callable, normal return is not established even when all preceding operations completed.
