# F-55225046b56d

## Purpose

F-55225046b56d searches forward from a caller-supplied cursor through a linked structure. A node qualifies only when an indirect operation returns the value 2 and a subsequent 32-bit field read equals the requested target.

The search is destructive with respect to the cursor: each rejected candidate causes the function to replace the cursor with the link obtained from the then-current node. A successful search stops without advancing past the match. Reaching a null cursor returns failure.

This description of a “search” is inferred intent. The established behavior is the sequence of cursor reads, indirect calls, conditional field reads, cursor writes, and return values described below. In particular, an indirect call may change the cursor or the referenced memory. The implementation does not preserve a node snapshot across that call.

## Interface

The function has three inputs:

| Input | Established role |
|---|---|
| First argument | An opaque 32-bit value. The function body does not inspect it or explicitly forward it. |
| Cursor address | Address of a writable 32-bit cell containing the current node address, or zero to indicate the end. |
| Target | A 32-bit integer compared for equality against a node field after an indirect result of 2. |

The supplied representation uses 32-bit integers to hold node addresses and perform address calculations. This contract therefore describes a 32-bit address model. A different pointer width or ABI is not established by the evidence.

The target comparison is equality between two 32-bit integer values. It is not a range, ordering, string, or pointer-identity comparison.

### Output

The function returns a 32-bit value:

- **0:** an iteration observes a zero cursor before dispatching an indirect call.
- **1:** an indirect call returns 2, and the subsequently selected node field equals the target.

No other normal return value is present in the supplied body. An invalid memory access, a nonreturning dependency, or an endless traversal does not have a specified normal return value.

### Referenced layout

The body accesses these fields relative to a node address:

| Byte offset | Width | Use |
|---|---:|---|
| 0 | 32 bits | Address of a dispatch structure |
| 4 | 32 bits | Address of the next node, or zero |
| 8 | 32 bits | Value compared with the target, conditionally |

Within the dispatch structure, the field at byte offset 8 supplies the indirect call target.

These are accessed offsets, not a complete declaration of either object. The evidence does not establish allocation sizes, additional fields, packing rules beyond these accesses, or whether all nodes share the same dispatch structure.

### Preconditions for defined normal execution

The cursor address must identify readable storage throughout execution and writable storage whenever advancement occurs. A null cursor **value** is supported; a null or otherwise invalid cursor **address** is not checked.

Each nonzero node address used for dispatch must support the node-offset-0 read. Its dispatch structure must support the offset-8 function-address read, and that address must be callable under the actual ABI.

After the indirect call returns, any node selected by a fresh cursor read must support the field access required by the chosen branch:

- Offset 8 when the indirect result is 2.
- Offset 4 when the candidate is rejected.

The body performs no explicit alignment, bounds, lifetime, or address-validity checks.

## Behavior

### Entry and empty state

The function first reads the cursor cell.

If the value is zero, it returns 0 immediately. This path performs no node dereference, invokes no indirect operation, and makes no direct cursor write.

The function does not independently initialize or restore the cursor.

### Indirect dispatch

For a nonzero cursor, the function obtains the current node’s dispatch-structure address from offset 0. It then obtains a callable address from offset 8 of that structure and invokes it.

The supplied call site contains no explicit arguments. It does not establish that the node, target, first argument, or cursor address is passed to the dependency. Any implicit receiver convention, register-carried context, or ABI-specific argument behavior is unknown.

The returned value is treated as a 32-bit integer and tested for exact equality with 2. Other nonzero values do not qualify merely because they are nonzero.

### Conditional match

If the indirect result equals 2, the function reads the cursor again and obtains the 32-bit field at offset 8 of the node identified by that read. It compares that field with the target.

If the values are equal, the function returns 1. The body makes no advancement write on this path.

The dispatching node and the node supplying the compared field need not be the same if the dependency changes the cursor. There is no intervening null check after the dependency returns. Consequently, a dependency that clears the cursor before returning 2 can cause an invalid field access rather than a normal failure return.

If the indirect result is not 2, the offset-8 comparison field is not read by this body for that candidate.

### Rejection and advancement

A candidate is rejected when either:

- The indirect result is not 2; or
- The indirect result is 2, but the subsequently read comparison field differs from the target.

On rejection, the function reads the cursor again, reads the link at offset 4 of the selected node, and writes that link value into the cursor cell. The next iteration begins by checking the cursor for zero.

Advancement therefore uses the cursor’s value at the time of advancement, not a node address saved before dispatch. If the dependency redirects the cursor, the function follows the redirected node’s link.

When a rejected node has a zero link, that zero is written to the cursor. The next iteration returns 0 without further dispatch.

### Repetition and termination

The function has no traversal bound, visited-node tracking, or cycle detection.

Normal completion requires either an observed zero cursor at an iteration boundary or a qualifying match. A cycle with no qualifying match can cause indefinite repetition. The same is true if dependency side effects continually prevent either terminating condition.

The evidence does not establish concurrency safety. The access order above describes the body’s logical operations, not atomicity, synchronization, volatile semantics, or a guaranteed machine-instruction trace.

## Side effects

### Direct effects

The direct state mutation is advancement of the caller’s cursor cell. Each rejected candidate causes one cursor assignment in the supplied body.

Subject to dependency effects:

- A successful search leaves the cursor at the matching node.
- An exhausted search leaves the cursor zero.
- A cursor that is initially zero remains zero.
- Nodes preceding the match are not restored as the cursor position.

The function body contains no explicit allocation, deallocation, node-field update, reference-count adjustment, or resource release.

These observations do **not** establish that the overall operation is allocation-free, preserves node contents, or retains every referenced object: the indirect dependency may have its own effects.

### Ownership and lifetime

No ownership transfer is established. The function consumes addresses as references and updates the cursor cell, but the supplied body does not define who owns the cell, nodes, dispatch structures, or callable objects.

The caller must not rely on the body to retain nodes across the indirect call. If that call invalidates storage subsequently accessed by the function, there is no visible protection or recovery mechanism.

### Errors

The function exposes no separate error channel. Return value 0 means only that a zero cursor was observed at an iteration boundary; it does not encode a validated memory error or dependency failure.

No explicit exception handling, fault recovery, or rollback is present. Dependency errors, abnormal control transfer, and memory-access failures have no specified recovery behavior here.

## Acceptance examples

The following are conditional consequences of the supplied body, not executed tests. Except where stated otherwise, they assume valid memory, normal dependency returns, and no dependency mutation of the cursor or referenced structures.

1. **Initially empty cursor.**  
   Given a zero cursor value, the result is 0. There is no indirect call and no direct cursor write.

2. **Immediate match.**  
   Given a nonzero cursor, an indirect result of 2, and an offset-8 field equal to the target, the result is 1. The body does not advance the cursor.

3. **Matching field with a nonqualifying result.**  
   Given an indirect result of 1, the node is rejected even if its offset-8 field would equal the target. That comparison field is not read by this body. The cursor is replaced by the offset-4 link.

4. **Qualifying result with a different field.**  
   Given an indirect result of 2 and a comparison field unequal to the target, the cursor advances. A zero link leads to result 0 on the next iteration.

5. **Match after rejection.**  
   Given a first node that is rejected and links to a second node that qualifies, the result is 1 and the cursor identifies the second node. The original cursor position is not restored.

6. **Target-width boundary.**  
   Given a target of −1 and a comparison field representing the same 32-bit integer, the comparison succeeds when the dependency returns 2. No positivity requirement or narrowing conversion is visible.

7. **Dependency redirects before comparison.**  
   Suppose dispatch occurs through node A, but the dependency changes the cursor to valid node B and returns 2. The comparison uses B’s offset-8 field. If it matches, the function returns 1 without directly advancing B.

8. **Dependency redirects before advancement.**  
   Suppose dispatch occurs through A, but the dependency changes the cursor to valid B and returns a value other than 2. The function writes B’s offset-4 link into the cursor. It does not necessarily follow A’s link.

9. **Dependency clears the cursor.**  
   If the dependency clears the cursor and returns normally, the body attempts a subsequent node-field access without first checking that new zero value. A clean result of 0 is not guaranteed.

10. **Nonmatching cycle.**  
    Given a stable cycle of valid nodes whose indirect calls return normally but never produce a qualifying match, no terminating condition is reached. The function has no visible cycle escape.
