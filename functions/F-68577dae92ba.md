# F-68577dae92ba

## Purpose

The distinction between the two selected references is established. Their apparent association with three-card and four-card “About” navigation is inferred from descriptive labels in the supplied material. The referenced bytes and the implementation of either navigation action are not supplied. This contract therefore calls them the **zero-case reference** and the **nonzero-case reference**, without asserting their exact contents.

The function does not visibly report whether navigation, allocation, dispatch, or cleanup succeeded. Its return value is unconditional on every path that reaches its final return.

## Behavior

### Ordered execution

The following sequence is established by the visible body:

1. The third argument is copied into a local 32-bit slot.
2. The fourth argument is copied into a separate local 32-bit slot.
3. The function resolves the indirect query operation through the global-root chain described above and invokes it.
4. The query result is compared with zero.
5. A zero result selects the zero-case reference. Any nonzero result selects the nonzero-case reference.
6. F-9b9c1c7483f4 is invoked with three explicit arguments, in this order:

8. The receiver’s dispatch operation is resolved through its first word and table offset `0x11c`.

10. F-8a5aadac202f is invoked with the address of the same local slot that was initialized from the fourth argument.
11. The function returns 1.

### Branch semantics

The selection is an equality-to-zero decision, not a positive-versus-negative decision.

Accordingly:

- A query result of zero selects the zero-case reference.
- A query result of 1 selects the nonzero-case reference.
- A query result with only the high bit set also selects the nonzero-case reference.
- No range validation or normalization is visible.

Only the selected reference changes between the two branches. Both branches then use the same dependency sequence and return the same value on ordinary completion.

### Local-slot semantics

Both local slots exist and contain their copied argument values before the query operation is invoked.

F-9b9c1c7483f4 receives addresses of both slots. Its implementation is unavailable, so it cannot be assumed to leave either slot unchanged. In particular, the slot initialized from the fourth argument may hold a different value by the time F-8a5aadac202f receives its address.

The later call uses the **same slot address**, not a freshly initialized copy of the fourth argument. Consequently, any mutation of that slot by F-9b9c1c7483f4 is relevant to the later operation.

After F-9b9c1c7483f4 returns, the visible body does not explicitly read the slot initialized from the third argument again. This does not establish that the dependency ignores it or that objects reachable through its value remain unchanged.
