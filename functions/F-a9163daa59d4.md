# F-a9163daa59d4

## Purpose

F-a9163daa59d4 performs an ordered sequence of reads and writes through two implicit address-bearing inputs, follows stored links, replaces several of those links, accesses additional computed addresses, and transfers control through an unresolved indirect target.

**Established static behavior:** memory mutation and indirect control transfer. The supplied representation does not establish allocation, initialization, serialization, validation, or a particular data structure.

**Inferred intent:** self-address stores and repeated link traversal suggest structured state manipulation. This interpretation supplies no additional behavioral guarantees.

This contract describes the represented path, including intermediate effects. It does not establish that a real reachable state permits the entire path to execute successfully.

## Interface

| First argument | 32 bits | Written at offset `0x30` through Context A’s entry `0x74` link. |
| Second argument | 8 bits | Written at offset `0x09` through Context B’s initially read `0x14` link. |

### Implicit inputs

These names describe roles, not recovered types or ownership.

Three statically addressed, 32-bit storage locations are read:

- **G2:** contributes computed addresses, a narrowed store value, and an indirect-call argument.
- **G3:** supplies a word stored at twice the captured G2 value.

The indirect target’s identity and origin are unresolved.

## Behavior

### Ordering and captured values

The following phases preserve the represented access order. Names such as “linked region” and “retained parent” denote captured address values; they do not imply object types.

A fresh read is distinct from an earlier captured value. Writes may alias later read locations, including global storage. Consequently, replacing reloads with snapshots, removing repeated writes, or grouping effects by destination can change behavior.

### 1. Entry effects

The function reads Context A’s `0x74` word and then replaces that word with Context B’s address. The first argument is written at `0x30` of the address captured before replacement.

It reads Context B’s `0x14` link and writes the second argument at `0x09` of that region. Context A’s `0x54` word then receives Context A’s own address.

The third argument produces a separate word write: the destination is its value minus `0x20`, and the stored value is its value minus `0x74`.

Next, traversal follows the initially reached region’s `0x14` link. The fourth argument is written at Context B’s `0x11` byte. Context B’s `0x14` word is then reloaded; call this captured value the **early B-link snapshot**. Its low byte is written at `0x15` of the traversed region.

### 2. Initial stamping and link replacement

Context B’s `0x14` word is read again, producing the **linked region**. This address need not equal the early B-link snapshot.

Context A’s `0x64` word is read and written back unchanged. Call the captured value the **initial scalar**. The linked region receives byte `0x73` at `0x0C`, followed by the initial scalar’s low byte at Context A’s `0x15`. Context B’s `0x34` word receives the early B-link snapshot.

The linked region’s `0x74` word is read, producing the **first saved link**. Its `0x54` word is then set to its own address. Context B’s `0x0D` receives Context A’s low address byte.

Context B’s `0x54` word receives the early B-link snapshot. **Next, Context B’s `0x14` word receives the linked-region address.** This is an explicit word write, not an assumed no-op: intervening writes may have changed that field through aliasing.

Only after that write is Context A’s `0x64` word reloaded, producing the **refreshed scalar**. The following effects retain their order:

- The linked region receives byte `0x74` at `0x10`.
- Context A’s `0x54` receives word `0x74`.
- The linked region receives word `0x74` at `0x10`.
- Its `0x74` word is read again, producing the **second saved link**.
- Context B’s `0x54` receives Context B’s own address.
- The linked region receives word `0x74` at `0x30`.
- Context A’s `0x01` receives the initial scalar’s low byte.

The initial scalar is also used as an address: its `0x09` byte receives the refreshed scalar’s low byte. Context A’s `0x74` word then receives the refreshed scalar.

Context A’s `0x11` byte receives `0x74` **before** the linked region’s `0x60` word is read. After that read, Context A’s `0x11` receives the initial scalar’s low byte, and its `0x34` word receives the refreshed scalar. Finally, the linked region’s `0x10` byte receives the low byte captured from its `0x60` word.

### 3. Constant stamping and two distinct Context B overwrites

Context A’s `0x14` link is read. Context B’s `0x11` receives the first saved link’s low byte. Context A’s `0x44` word then receives Context B’s address, followed by the refreshed scalar’s low byte at Context A’s `0x11`.

Context A’s `0x74` word is read and retained as an **earlier A-link snapshot**. Context A’s `0x0D` receives Context B’s low address byte.

Through the captured Context A `0x14` link, the function writes word `0x66` at `0x10`. Context A’s `0x44` again receives Context B’s address. The linked destination then receives byte `0x66` at `0x10`; Context A’s `0x54` receives word `0x66`; and the destination’s `0x60` receives word `0x66`.

Context A’s `0x74` is read again, yielding the **captured A-link region**, then replaced with Context B’s address. The captured region receives word `0x66` at `0x40`. Context A’s `0x0D` receives the earlier A-link snapshot’s low byte.

The captured A-link region’s `0x44` word is read. Context A’s `0x54` is set to its own address, and the second saved link’s `0x54` word is likewise set to that saved address itself.

The captured A-link region’s `0x14` link is then followed. **After this traversal, Context B’s `0x11` receives the low byte captured from the region’s `0x44` word.** This is separate from the earlier overwrite sourced from the first saved link.

A fresh Context B `0x14` read then supplies the low byte written at `0x15` of the traversed region.

### 4. Propagation through further links

A fresh Context B `0x14` read supplies the **propagation region**. Context A’s `0x64` word is read, producing the **first propagation scalar**. The propagation region receives word `0x73` at `0x20`. Only afterward is Context A’s `0x64` read again, producing the **second propagation scalar**, whose low byte is written at the propagation region’s `0x09`.

Following that region’s `0x74` link reaches another region. In order, it receives Context A’s low address byte at `0x0D`, has its `0x54` word read and written back, and receives byte `0x74` at `0x09`. Context A’s `0x44` receives the first propagation scalar; the reached region’s `0x34` then receives Context A’s address.

Following its `0x04` link reaches the **scalar-source region**. Its `0x24` word receives the second propagation scalar, and Context A’s `0x19` receives the first propagation scalar’s low byte.

The scalar-source region’s `0x74` word is captured as the **retained link**, followed by its `0x04` word as the **replacement scalar**.

Context A’s `0x74` is now reloaded, yielding the **retained root**. Following that root’s `0x14` link selects a destination whose `0x54` receives the retained link. The root’s `0x04` link is then read and captured as a word-stamp destination.

Context A’s `0x0D` receives the second propagation scalar’s low byte twice consecutively. **Both byte writes precede** replacement of Context A’s `0x64` word with the replacement scalar. **After that replacement**, the captured word-stamp destination receives word `0x74` at `0x30`.

### 5. Replacement of Context A’s links

The retained root’s `0x04` link is read again and followed through `0x74`, producing the **retained parent**. This traversal is fresh; it does not reuse the preceding word-stamp destination.

Context A’s now-current `0x64` word is read, and its low byte is retained as the **fresh scalar byte**. Context A’s `0x1D` receives that byte.

Next, Context A’s `0x44` word is read as an address and followed through `0x14`, producing the **replacement link destination**. **Only after this traversal** does the retained parent’s `0x34` receive the retained link.

Context A’s `0x14` word receives the replacement link destination. Its `0x54` word is then read and saved, **before** Context A’s low address byte is written at the destination’s `0x09`.

The retained parent’s `0x04` link is read and followed through `0x74`, producing the **newly traversed region**. Its `0x15` receives the retained link’s low byte.

Context A’s `0x54` is restored to its own address. Immediately afterward, Context A’s `0x11` receives the retained parent’s low address byte. The newly traversed region’s `0x11` receives the low byte saved from Context A’s previous `0x54` word.

The newly traversed region’s `0x64` word is read, producing the **final propagated value**. Immediately after that read, Context A’s `0x09` receives the fresh scalar byte captured earlier in this phase.

### 6. Final linked-region mutations

The retained parent’s `0x04` link is read again, producing the **byte-target region**. Its `0x09` receives Context A’s low address byte. Its `0x50` word is read; then its `0x11` receives the final propagated value’s low byte, and its `0x09` again receives Context A’s low address byte.

Context A’s `0x14` word receives the final propagated value. Context A’s `0x0D` receives the byte-target region’s low address byte. The byte-target region’s offset-zero byte receives the low byte captured from its `0x50` word.

The retained parent’s `0x74` link is read and saved as the **final indexed link**. Its `0x14` link is read next, producing the **intermediate region**. The byte-target region’s `0x54` receives its own address.

The intermediate region’s `0x04` link supplies the **decimal-100 destination**. That destination receives byte decimal 100 at `0x10`; Context A’s `0x54` receives word decimal 100; and the destination receives word decimal 100 at `0x40`.

Context A’s `0x0D` then receives the final propagated value’s low byte. The intermediate region’s `0x09` receives the decimal-100 destination’s low address byte. Context A’s `0x24` receives the final propagated value, followed by Context A’s low address byte at the intermediate region’s `0x11`.

### 7. Computed accesses and indirect transfer

G1 is read before Context A’s `0x74` word is reloaded. Call the latter captured word the **final A-link**.

The final A-link’s low 16 bits are written at the sum of the final A-link and Context A’s address. G1’s low 16 bits are then written at twice the decimal-100 destination’s address.

A byte is read at the sum of the final indexed link and Context A’s address. The represented conversion passes through plain character type before producing a 32-bit unsigned value, called **Index**. Plain-character signedness is unresolved.

The remaining accesses occur in this order:

1. Write the final A-link’s low 16 bits at G1 plus the final A-link.
2. Repeat the halfword write at Context A plus the final A-link.
3. Write word `0x45` at Index plus `0x45`.
4. Read G2, then G3, then Context A’s `0x44` word.
5. Write byte `0x44` at Index plus `0x44`.
6. Write the captured G3 word at twice the captured G2 value.
7. Write G2’s low 16 bits at the retained link plus G2.

The unresolved indirect target receives three represented arguments, in order: Index bitwise-OR `0x44`, captured G2, and the captured Context A `0x44` word.

## Acceptance examples

These are conditional static examples, not executed tests.

- **Entry capture:** If Context A’s entry `0x74` addresses a valid region and the first argument is `0x12345678`, that region receives the word at `0x30` after Context A’s `0x74` has been assigned Context B’s address.

- **Third argument:** For third-argument value `0x1000`, the separate word write targets `0x0FE0` and stores `0x0F8C`, assuming valid addressing and access.

- **Distinct B-link snapshots:** If the early B-link snapshot differs from the later linked-region address, Context B’s phase-2 `0x34` and temporary `0x54` stores use the earlier snapshot; its explicit `0x14` store uses the later address.

- **Observable reload:** If an aliased propagation-region `0x20` write changes Context A’s `0x64`, the first propagation scalar reflects the earlier read and the second reflects the later read. They must not be merged.

- **Overwrite order:** Context A’s `0x11` receives byte `0x74` before the linked-region `0x60` read, then the initial scalar’s low byte, and later the refreshed scalar’s low byte after the first Context A `0x44` assignment to Context B.

- **Narrowing:** A word `0x123456AB` contributes byte `0xAB` or halfword `0x56AB` when narrowed. The remaining source bits are not part of that individual write.

- **Character extension:** For indexed byte `0x80`, unsigned plain-character interpretation yields Index `0x00000080`; signed interpretation followed by unsigned conversion yields `0xFFFFFF80`. Address validity and overflow behavior remain separate conditions.

- **Failure boundary:** If the entry read fails, no subsequent effect is established. If a later access fails, no represented mechanism undoes earlier completed writes.
