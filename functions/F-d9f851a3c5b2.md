# F-d9f851a3c5b2

## Purpose

F-d9f851a3c5b2 selects between two operations using its fourth argument:

- A nonzero selector delegates to F-23e0911a650c and returns that dependency’s result unchanged.
- A zero selector obtains a byte buffer through F-207d45b9b900, omits its first byte from scanning and output, and submits selected spans through F-8d1c9f620c59. Recognized slash boundaries are excluded from those spans and ordinarily cause a fixed two-byte separator to be submitted.

Under conventional unsigned 8-bit byte semantics and integer promotion, the first byte tested after a slash is **not restricted to uppercase letters**. It qualifies when its value is between `0x00` and `0x5A`, inclusive. A marker then requires either an immediately following `=` or an uppercase ASCII byte followed by `=`.

This distinction affects both output and memory requirements. Digits can qualify in the first position. A zero byte can also qualify, causing inspection beyond the logical string terminator.

**Inferred intent:** local mode appears to reformat a generated representation by omitting an initial byte and substituting separators for selected slashes. The application-level format, reason for omitting the first byte, and separator contents are not established.

### Buffer layout and accessibility

The producer’s result is immediately interpreted as the address of byte storage. No null check precedes the first read.

The visible layout is a contiguous byte sequence:

- Offset zero is checked for immediate termination.
- For a nonempty sequence, scanning and the first output span begin at offset one.

A stable, accessible zero-terminated sequence is **not by itself sufficient** to guarantee readable marker lookahead:

- A scanned slash causes a read of the following byte.
- If that byte is in `0x00`–`0x5A`, the next byte is read, even when the qualifying byte was the terminator.
- If that next byte is not `=`, it is read again for the second-position classification.
- If its classified value is uppercase ASCII, one further byte is read to test for `=`.

Thus a scanned slash immediately before the terminator requires at least one readable byte beyond that terminator. If that extra byte is uppercase ASCII, a second byte beyond the terminator is also read.

For ordinary processing, storage must remain readable at every address actually inspected or submitted. No safe failure behavior is established for invalid storage.

The first byte of every nonempty buffer is therefore omitted regardless of its value. It is not examined as a possible marker.

### Marker recognition

For a stable buffer, a scanned slash qualifies as a boundary when the bytes following it satisfy either pattern:

- One byte in `0x00`–`0x5A`, followed by `=`.
- One byte in `0x00`–`0x5A`, followed by an uppercase ASCII byte in `0x41`–`0x5A`, followed by `=`.

These are prefix tests. Bytes following the tested `=` are unconstrained.

The arithmetic establishing the two ranges differs:

- The first byte is interpreted as unsigned 8-bit and promoted to signed integer arithmetic. Subtracting `0x41` produces values from `-65` through `190`. Comparing that result with `26` accepts every original byte at or below `0x5A`, including zero, punctuation, and digits.
- For the second-position range test, the subtraction result is first converted to an unsigned 32-bit value. Values below `0x41` consequently become large unsigned values and fail the comparison. This test accepts only `0x41`–`0x5A`.

The second-position byte has a separate direct `=` test before that range classification. If the direct test fails, the byte is read again for classification. The third-position byte is read only when the classified second-position byte is uppercase ASCII.

No locale or Unicode classification is involved. Bytes from `0x5B` through `0xFF` fail the first-position predicate.

Recognition does not advance directly past a complete marker. After successful handling of a slash, scanning advances only one byte. The remaining marker bytes are scanned in turn; another slash among them can therefore be recognized independently.

A zero byte at the scanning position is also a boundary. For stable storage, non-boundary positions advance scanning by one byte.

### Span submission

At a boundary, the function computes the distance from the pending span’s start to the boundary address. It calls F-8d1c9f620c59 with:

1. The original first argument.
2. The pending span’s source address.
3. That distance as a signed 32-bit count.

The boundary byte is excluded from the requested span.

The returned signed 32-bit count must equal the requested count exactly. A shorter count, a larger count, or any other unequal result is a failure. There is no visible retry or partial-count continuation.

Zero-length requests are issued. A boundary at the pending span’s start therefore requires an output result of exactly zero.

After an exact count match, the pending span’s start advances by the requested distance plus one. Under ordinary nonoverflowing address arithmetic, it then points immediately after the boundary.

### Separator submission and termination

After the successful source-span call and span-start advance, the function reads the boundary byte again.

- If it is nonzero, F-8d1c9f620c59 is called with the original first argument, a fixed static-data address, and count `2`.
- If it is zero, that separator call is skipped.

The separator call must return exactly `2`. Its two source bytes are not supplied by the available evidence.

After either skipping the separator or receiving an exact separator count, the function reads the boundary byte again:

- Zero selects successful finalization and return.
- Nonzero causes scanning to continue one byte later.

For stable storage, a recognized slash produces a separator and scanning continues. A terminator produces no separator and ends processing.

These decisions are based on separate reads. A dependency that changes the boundary byte can change separator submission or termination after the original boundary was recognized. In particular, skipping the separator because one read was zero does not eliminate the final termination read.

### Stable-buffer output interpretation

Provided storage remains unchanged and arithmetic is valid:

- The initial byte is omitted.
- Each recognized slash is omitted from source spans.
- One fixed two-byte separator is requested for each recognized slash.
- Marker bytes after the slash remain eligible for later source spans.
- The final span excludes the terminating zero byte.

The last point also applies when marker recognition looked beyond that terminator. Those lookahead bytes do not become output merely because they were read.

### Success and mismatch handling

Successful local completion calls F-5990a26eaaa3 with the original producer-returned address and returns `1`.

Any output-count mismatch causes the following sequence:

### Width and arithmetic constraints

Span-distance calculation uses signed integer representations of addresses. Its ordinary interpretation requires representable address conversions and subtraction without signed overflow. Span advancement must also avoid invalid pointer arithmetic.

No explicit check enforces these requirements. The supplied representation does not establish modular wraparound behavior as a safe alternative. In particular, it does not justify a supported maximum buffer size or safe handling of spans exceeding the positive signed 32-bit range.
