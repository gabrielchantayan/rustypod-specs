# F-6273ba4f83f6

## Purpose

F-6273ba4f83f6 compares two bounded sequences of 16-bit unsigned input units after applying a shared table-based transformation. It returns equality or an ordering result based on the first pair of unequal transformed values.

The transformation has an important asymmetry:

- An input below 256 produces a comparison value immediately, including when its table entry is zero.
- An input of at least 256 can produce zero through a secondary lookup. Such a zero is skipped, and scanning continues on the same sequence until another value is produced or that sequence’s count reaches zero.

Exhaustion produces a comparison value of zero. Equal zero values terminate the comparison successfully. Therefore, the operation is not necessarily an ordinary lexicographic comparison of the original input units, nor a conventional zero-terminated string comparison.

**Inferred intent:** the shared table may implement a character-weighting or normalization scheme with ignorable entries. The supplied evidence does not establish an encoding, locale, collation standard, or character semantics.

## Interface

The interface has four arguments, in this order:

| Argument | Established representation | Meaning |
|---|---|---|
| First sequence address | Address of 16-bit unsigned units | Initial position in the left sequence |
| First count | 32-bit signed integer in the supplied representation | Remaining left-side input units |
| Second sequence address | Address of 16-bit unsigned units | Initial position in the right sequence |
| Second count | 32-bit signed integer in the supplied representation | Remaining right-side input units |

Each input advancement moves by one 16-bit unit, or two bytes. Counts measure input units, not bytes and not produced comparison values.

The result occupies 32 bits and has exactly three established bit patterns on normal return:

| Result bits | Meaning |
|---|---|
| `0x00000000` | Equal under this operation’s termination rules |
| `0x00000001` | Left comparison value is greater at the first mismatch |
| `0xFFFFFFFF` | Left comparison value is smaller at the first mismatch |

The last pattern represents −1 when interpreted as a signed 32-bit integer. The evidence does not establish the caller’s declared return type, so the bit pattern is the definitive interface property.

There are no output parameters. Input positions and remaining counts advance only within the invocation; their final values are not returned.

### Required accessible state

The function depends on a shared table base, denoted here as **B**. Table elements are 16-bit unsigned values. Addresses below are byte offsets relative to B:

- Direct mapping for input value \(x < 256\): offset \(2x - 512\).
- Directory entry for a high byte \(h\): offset \(2h\).
- Secondary mapping for directory value \(d\) and low byte \(l\): offset \(2(d+l)\).

For a valid execution, every input and table location actually reached must be readable. The function performs no visible bounds, alignment, pointer-validity, or table-consistency validation.

Nonnegative counts are the supported, straightforward bounded-input interpretation. Negative counts are not rejected, but their behavior has arithmetic and memory-safety qualifications described under **Uncertainties**.

## Behavior

### Comparison rounds

Each round obtains a left comparison value first, then a right comparison value. Both candidate values start at zero for that round.

After obtaining both values:

1. If they differ, the function returns the ordering result immediately.
2. If both are zero, it returns equality immediately.
3. If they are equal and nonzero, another round begins at the input positions and counts left by the preceding round.

There is no length-based preliminary ordering. Equal transformed nonzero values can require different numbers of original input units to obtain.

### Obtaining one comparison value

The two sides implement the same value-selection behavior.

If the remaining count is zero, the selected value is zero and no input unit is read.

Otherwise, the function reads the current 16-bit input unit, consumes one unit of the count, and advances its internal position by two bytes. The selected value is determined as follows.

#### Inputs below 256

For an input \(x\) in the range 0 through 255, the function reads the 16-bit table entry at:

\[
B - 512 + 2x
\]

That entry is the selected comparison value for this round.

Selection ends even if the entry is zero. It does not skip additional input units on that side in the same round.

Consequences:

- A raw zero input is not intrinsically a terminator. Its direct table entry determines its value.
- A nonzero input can produce a zero comparison value.
- A direct-table zero can stop comparison with equality if the opposite side also produces zero, even when unread input remains on either side.

#### Inputs of at least 256

For an input \(x\) from 256 through 65535, let \(h\) be its high byte and \(l\) its low byte.

The function reads a directory entry \(d\) at:

\[
B + 2h
\]

The resulting behavior is:

- If \(d = 0\), the original unsigned input value \(x\) is selected. No secondary mapping is read.
- If \(d \ne 0\), the function reads the entry at \(B + 2(d+l)\).
  - A nonzero entry becomes the selected comparison value.
  - A zero entry is discarded. Selection continues with the next input unit on the same side.

If skipping such entries exhausts the count, the selected value is zero.

A zero directory entry therefore means “retain the original value,” not “discard this input.”

### Ordering and widths

Input units, directory entries, and mapping entries are all 16-bit unsigned quantities. Their values are promoted without sign extension for comparison and table indexing.

Comparison values are consequently within 0 through 65535. Ordering is unsigned numerical ordering of those values.

The secondary index \(d+l\) is calculated after promotion; it is not truncated to 16 bits. Its maximum is:

\[
65535 + 255 = 65790
\]

The corresponding maximum secondary byte offset is 131580. A replacement that wraps this index to 16 bits would change behavior.

The direct-table byte offsets range from −512 through −2. Directory reads for inputs of at least 256 use high-byte indices 1 through 255, giving offsets 2 through 510.

### Observable read order

The established logical access order within a round is:

1. Read and transform enough left-side input to select its value or exhaust its count.
2. Read and transform enough right-side input to select its value or exhaust its count.
3. Compare the selected values.

The function does not stop immediately upon obtaining a left-side zero. It still selects the right-side value before deciding whether to return.

For an input of at least 256, the supplied representation includes a second read of the current input unit to obtain its high byte before reading the directory entry. The secondary index, if needed, uses the low byte of the initially read value. For stable ordinary memory, the two reads agree. Concurrently changing or device-backed input requires additional qualification; this evidence does not establish an atomic snapshot.

No input beyond a decisive mismatch or an equal-zero termination is consumed.

## Acceptance examples

These examples are conditional behavioral requirements, not runtime observations. Each assumes valid readable storage, stable contents, and the stated table entries.

### Both counts are zero

With both counts zero, the function returns `0x00000000`.

Neither input address is dereferenced, and no table lookup is needed.

### Exhausted left side versus a positive right value

The left count is zero. The right has one input whose transformation selects 7.

The function obtains left value zero, reads and transforms the right input, and returns `0xFFFFFFFF`.

Reversing the sides returns `0x00000001`.

### Ordering follows mapped values

The left contains a below-256 input whose direct entry is 40. The right contains a below-256 input whose direct entry is 12.

The function returns `0x00000001`, irrespective of the numerical ordering of the original input units.

No later units affect the result.

### Equal nonzero values advance to another round

The first selected value on each side is 9. The next selected values are respectively 2 and 3.

The function returns `0xFFFFFFFF` based on the second pair. It does not return equality after the first equal pair.

### A zero direct mapping is not skipped

The left sequence begins with a below-256 input mapped directly to zero, followed by an input mapped to 99. The right count is zero.

The function returns equality immediately. The left input mapped to 99 is not read.

If the right instead selects 5, the result is `0xFFFFFFFF`; the function still does not proceed to the left input mapped to 99.

### A zero secondary mapping is skipped

The left begins with an input of at least 256 whose directory entry is nonzero and whose secondary mapping is zero. Its next input selects 8.

The right selects 8, and both sides then have count zero.

The function consumes both left inputs, matches 8 against 8, and returns equality in the following exhausted round.

### A zero directory preserves the raw input

The left input is `0x1234`, and its high-byte directory entry is zero. The right selects `0x1233`.

The left comparison value remains `0x1234`, and the function returns `0x00000001`. There is no secondary lookup for the left input.

### Skipped entries can make a nonempty sequence equal to exhaustion

Every left input is at least 256, has a nonzero directory entry, and maps through the secondary table to zero. The right count is zero.

The function consumes all left inputs and returns equality. The original sequence lengths do not by themselves determine inequality.

### Raw zero can be ordinary comparison data

The direct entry for input zero is 6. Each sequence contains one raw zero input.

The first round compares 6 with 6. Equality is returned only in the next round, when both counts are exhausted.

### Secondary indexing does not wrap

An input has low byte 255 and a directory value of 65535.

Its secondary mapping is read at index 65790 relative to B, or byte offset 131580. Reading an entry at a wrapped 16-bit index is not equivalent.
