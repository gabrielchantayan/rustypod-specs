# F-79946efb9e4f

## Purpose

F-79946efb9e4f selects one of three 64-bit results:

- The numeric value **8**.
- The numeric value **16**.
- A 64-bit value formed from the bit patterns of its first two inputs.

Selection depends on a signed selector, an incoming gate value, and eight externally stored configuration values. Some paths replace the incoming gate with an arithmetic result before testing it. Other paths return without consulting the gate.

**Established static evidence:** the supplied representation contains arithmetic, comparisons, references to external configuration, and returns. It contains no explicit calls, memory writes, allocation, or release.

**Inferred intent:** this appears to be a configurable selector or status classifier with a caller-supplied fallback result. No application meaning for the selector, configuration, or numeric results is established.

The behavioral rules below distinguish stable-configuration behavior from unresolved details concerning external reads and arithmetic overflow.

### Output

The return value is 64 bits wide.

The **fallback result** is the concatenation of the high result word above the low result word. Concatenation preserves both input bit patterns; it does not sign-extend either word.

For example, a high result word of `0x11223344` and a low result word of `0xAABBCCDD` produce the fallback result `0x11223344AABBCCDD`. This describes bit significance, not byte order in memory.

The numeric returns 8 and 16 occupy the complete 64-bit result, with zero upper bits.

The three outcomes need not be numerically distinct: caller-provided words can themselves form 8 or 16.

## Behavior

### Interpretation of the rules

The branch rules below assume that each external configuration value remains stable throughout an invocation and that the relevant arithmetic is representable without signed overflow.

Those assumptions make the control flow describable using one value per configuration entry. They are not established guarantees of the surrounding program.

A **gate decision** means:

- If the applicable gate is zero, return 8.
- Otherwise, return the fallback result.

Only zero versus nonzero matters for a gate decision. A negative gate is nonzero.

### Initial difference and primary equality

The function first forms the difference between the selector and the primary boundary.

It then compares the selector with the primary boundary:

- If they are equal, return 8.
- Otherwise, compare the selector with the primary boundary to select the lower or upper region.

The initial subtraction precedes the equality branch in the supplied representation. The equality result does not depend on the incoming gate or either result word.

### Lower region: selector below the primary boundary

Within this region, compare the selector with the secondary boundary.

#### Equality with the secondary boundary

If the selector equals the secondary boundary, return the fallback result immediately.

This path does not test the incoming gate. It applies only after the selector has entered the region below the primary boundary. If the two boundaries are equal under stable configuration, primary equality returns 8 before secondary equality can be considered.

#### Selector below the secondary boundary

If the selector is below the secondary boundary, form a replacement gate by adding the lower adjustment directly to the selector.

Apply the gate decision to that replacement:

- A zero sum returns 8.
- A nonzero sum returns the fallback result.

The incoming gate is irrelevant on this path.

#### Selector above the secondary boundary

If the selector is above the secondary boundary while still below the primary boundary, form the middle result by:

1. Subtracting the secondary boundary from the selector.
2. Adding the middle adjustment to that difference.

Then:

- If the middle result is zero, return 16 immediately.
- Otherwise, compare the middle result with the middle match.
- If they differ, return the fallback result immediately.
- If they are equal, apply the gate decision to the **incoming gate**.

The zero test takes precedence over the middle-match comparison. In particular, a zero middle result returns 16 even if the middle match is also zero.

A nonzero middle result equal to the middle match does not itself become the gate. That path retains the caller’s incoming gate.

### Upper region: selector above the primary boundary

Use the initial difference between the selector and the primary boundary.

#### Difference equals the upper displacement

If the initial difference equals the upper displacement, apply the gate decision to the incoming gate.

Neither upper adjustment is used on this path.

#### Difference below the upper displacement

If the initial difference differs from, and is below, the upper displacement, form a replacement gate by adding the near-upper adjustment to the initial difference.

Apply the gate decision to that replacement. The incoming gate is irrelevant.

#### Difference above the upper displacement

Otherwise, subtract the upper displacement from the initial difference.

- If the residual equals **`0x00ED0008`**, return the fallback result immediately.
- Otherwise, form a replacement gate by adding the far-upper adjustment to the residual, then apply the gate decision to that replacement.

The exceptional residual comparison occurs before the far-upper addition. An exceptional residual therefore returns the fallback result regardless of the incoming gate or the result that a far-upper addition might otherwise produce.

### Boundary ordering

No check establishes that the secondary boundary is below the primary boundary. No check establishes that the upper displacement or any adjustment is positive.

The branch conditions, rather than an assumed ordered range table, determine behavior. For example, if the secondary boundary is above the primary boundary, every selector that enters the lower region is also below the secondary boundary under stable configuration. The middle-result path is then unreachable.

### Arithmetic limits

Signed comparisons determine branch direction. Equality tests compare represented integer values or bit patterns without introducing a separate unsigned ordering.

The supplied representation does not establish portable behavior when signed arithmetic overflows. It is not sufficient evidence to require either:

- Unbounded mathematical arithmetic; or
- Modulo-\(2^{32}\) wrapping for every addition and subtraction.

Overflow-sensitive outcomes are therefore **documented_only**. The branch contract is established for executions whose evaluated arithmetic remains within the represented signed range. A machine-level specification would be required to extend it confidently to overflow cases.

## Side effects

### External reads and their order

The supplied representation references configuration in the following control-dependent sequence:

1. The primary boundary is referenced for the initial subtraction.
2. It is referenced for the primary equality comparison.
3. If unequal, it is referenced for the comparison selecting the lower or upper region.
4. In the lower region, the secondary boundary is referenced for equality and, if necessary, ordering.
5. The lower adjustment is referenced only on the below-secondary path.
6. On the middle-result path, the secondary boundary and middle adjustment participate in the arithmetic. The middle match is referenced only if the result is nonzero.
7. In the upper region, the upper displacement is referenced for equality and, if necessary, ordering.
8. The near-upper adjustment is referenced only on the below-displacement path.
9. On the far-upper path, the upper displacement participates in the exceptional-residual check and appears again in the later arithmetic if that check does not return. The far-upper adjustment is used only for that later arithmetic.

These are **source-level references**, not a verified physical load trace. The representation does not establish volatility, atomicity, caching, load coalescing, or evaluation order between operands within an arithmetic expression.

If configuration can change during execution, repeated references cannot safely be treated as one snapshot. In particular, the primary boundary used in the initial difference need not be assumed identical to a later observed boundary. The stable-configuration rules must not be extended to such executions without an external consistency guarantee.
