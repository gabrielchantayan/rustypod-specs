# F-360d49b83f75

## Purpose

F-360d49b83f75 initializes a caller-supplied output region, delegates construction of part of that region, and optionally invokes one of two additional dependencies before adjusting the leading field.

The third argument selects between two distinct layouts and update rules:

- **Zero mode:** byte-oriented initialization and a final single-byte update based on a value at output offset 6.
- **Nonzero mode:** 16-bit initialization and a final 16-bit update based on the first signed 16-bit value of the optional input.

Both modes pass output offset 2 to the same dependency before initializing the field at offset 6. The optional input is checked for null only after those operations.

**Inferred intent:** the leading field may represent a size or count initialized to 6, with subsequent dependencies contributing additional content. The supplied evidence does not establish that interpretation, the meaning of the mode value, or the format of any delegated content.

## Behavior

### Common sequencing

Every normal path first initializes the leading field and then calls F-946cac4b59bc with:

1. The original context value.
2. A pointer to output offset 2.

After that call returns, the function clears a field beginning at offset 6. The width of this clear depends on the mode.

Only then does it test whether the optional input is null. A null optional input therefore does **not** suppress the common dependency call or the preceding output writes.

The dependencies’ effects are not assumed to be confined to the addresses passed to them. In particular, a dependency may change memory that this function subsequently reads. The final arithmetic uses post-call values, not saved copies of the initially written value 6.

### Zero mode

When the mode is exactly zero, the established order is:

1. Write the byte value 6 at output offset 0.
2. Write the byte value 0 at output offset 1.
3. Invoke F-946cac4b59bc with the context value and output offset 2.
4. Write the byte value 0 at output offset 6.
5. Test the optional input for null.

The first two writes establish the byte sequence `06 00` independently of byte order. They are separate byte writes, not evidence of an atomic 16-bit initialization.

The clear at offset 6 does not directly change offset 7. Consequently, the 16-bit field beginning at offset 6 is not necessarily zero after this step.

If the optional input is null, the function returns immediately. It makes no final adjustment to the leading field.

If the optional input is non-null:

1. Invoke F-4c45257d6cf7 with the optional input and output offset 6.
2. After that call returns, obtain the 16-bit value at output offset 0 and the 16-bit value at output offset 6.
3. Convert each value to the represented plain-character type, add the converted values using integer promotion, and convert the result for storage as a single byte.
4. Write that byte at output offset 0.

The representation does not establish a relative evaluation order for the two operand reads in the final expression. Both occur after F-4c45257d6cf7 returns and before the resulting byte is stored.

The final write affects only offset 0. Offset 1 retains whatever value it has at that point, which need not still be zero if a dependency changed it.

There is no direct read of the optional input’s first element in this branch outside its use by F-4c45257d6cf7.

**Width consequence:** the final update is not a general 16-bit addition. On a target where narrowing preserves the low eight bits, the byte stored at offset 0 is the low eight bits of the sum of the two post-call 16-bit values. That target rule is required for this simplified description; signed-character narrowing behavior is not independently established.

### Nonzero mode

For every nonzero mode, the established order is:

1. Write the 16-bit numeric value 6 at output offset 0.
2. Invoke F-946cac4b59bc with the context value and output offset 2.
3. Write the 16-bit numeric value 0 at output offset 6.
4. Test the optional input for null.

Unlike zero mode, initialization here is expressed as a 16-bit store. The corresponding byte sequence depends on target byte order.

If the optional input is null, the function returns immediately. No second dependency is called and no final adjustment occurs.

If the optional input is non-null:

1. Invoke F-f6d6f6d14101 with the optional input, output offset 6, and the original nonzero mode.
2. After that call returns, read the signed 16-bit leading output value and the first signed 16-bit optional-input value.
3. Form the leading output value plus twice the input value.
4. Convert that result to the 16-bit output field and store it at output offset 0.

The representation does not establish which of the two operand reads occurs first. Both are after the optional dependency returns.

The first input element is read **after** F-f6d6f6d14101, so a change to that element during the call affects the adjustment. Likewise, a change to the leading output field during either dependency call affects the base value used in the addition.

There is no direct final read of the field at output offset 6 in this branch.
