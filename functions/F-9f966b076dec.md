# F-9f966b076dec

## Purpose

F-9f966b076dec combines two unsigned packed values using complementary weights derived from a signed third argument. It relocates one six-bit field before weighting, biases and scales the two contributions separately, applies a shared selection mask to their sum, and folds the selected bits into a 16-bit result.

The established behavior is integer arithmetic and bit manipulation. The structure suggests interpolation of packed fields, but no particular pixel format, channel meaning, saturation policy, or application-level weight range is established.

This contract distinguishes:

- **Established static evidence:** behavior directly supported by the supplied function.
- **Conditional arithmetic contract:** precise behavior under the explicitly stated 32-bit interpretation.
- **Inferred intent:** a possible application-level interpretation, not an additional requirement.
- **documented_only:** properties unresolved by the supplied material.

No runtime tests have been performed.

## Behavior

### Packed fields and upper-bit participation

For each packed input, bits 5 through 10 are removed from their original positions and represented at positions 21 through 26. Bit numbering starts at zero for the least significant bit.

Every other bit remains in its original position. In particular:

- Bits 0 through 4 remain unchanged.
- Bits 11 through 15 remain unchanged.
- Input bits above bit 15 are not generally discarded.
- Original bits 21 through 26 remain present and can coincide with relocated bits.

When an original upper bit and a relocated bit occupy the same position, their combination is bitwise OR. Two set bits at the same destination do not create a carry or count twice.

This is a transformation of the entire unsigned input, not an implicit conversion to a 16-bit packed format. A caller restriction to 16-bit inputs would narrow the possible cases, but no such restriction is enforced in the supplied function.

### Weight interpretation

The signed weight input is right-shifted by 11 positions to obtain the effective weight for the second packed value. The first packed value receives the complementary weight relative to 32.

For nonnegative inputs, this groups consecutive blocks of 2,048 input values into the same effective weight. Inputs from 0 through 2,047 select weight zero; inputs from 2,048 through 4,095 select weight one.

Two nominal endpoints follow:

- Effective weight zero gives the first packed value weight 32 and the second weight zero.
- Effective weight 32 gives the second packed value weight 32 and the first weight zero.

These are weighting endpoints, not unconditional identity guarantees. Bias, masking, overflow, and final packing still apply.

There is no visible clamping or rejection. Effective weights outside 0 through 32 continue into the arithmetic. Negative weight inputs also continue without an explicit error path.

Negative signed right-shift behavior is unresolved. If the environment uses arithmetic right shift, negative inputs are rounded toward negative infinity when divided by 2,048. A different signed-shift rule can produce different effective weights. This uncertainty must not be replaced by an assumed nonnegative caller range.

Under the stated 32-bit interpretation, the shift reduces the effective weight sufficiently that forming its complement relative to 32 does not overflow the signed weight type.

### Contribution arithmetic and precision

Each transformed packed value is weighted independently. Under the 32-bit model, the unsigned packed operand causes the corresponding signed weight to participate as a 32-bit unsigned value.

A negative effective weight therefore does not produce a signed negative contribution. Its unsigned representation enters modular multiplication.

Each contribution receives the shared bias independently and is then reduced by an unsigned right shift of five positions. This has several observable requirements:

- Multiplication retains only the low 32 bits before scaling.
- Adding the bias also retains only the low 32 bits before scaling.
- Discarded overflow bits cannot reappear during the later right shift.
- Each contribution loses its own low five bits before the contributions are added.
- The bias is applied twice overall, once to each contribution.
- There is no saturation.

Using wider products and postponing truncation can change the result. Combining the products before shifting can also change the result, because low bits discarded separately cannot carry between contributions.

A nominal weight of zero does not necessarily eliminate its contribution. The separately added bias can survive the five-bit reduction even when the weighted product is zero.

Each reduced contribution is at most 0x07FFFFFF. Their sum is therefore at most 0x0FFFFFFE and does not overflow a 32-bit unsigned integer.

### Selection and final packing

The selection word filters the sum of the two reduced contributions. A clear selection bit removes the corresponding sum bit; a set selection bit retains it.

The mask applies to the sum, including carries created by adding the contributions. Masking either contribution independently is not generally equivalent.

The selected intermediate is packed by combining its lower and upper 16-bit halves using bitwise OR. Each bit in the lower half retains its output position; each bit in the upper half contributes to the output position 16 places lower.

If corresponding positions in both halves are set, the output contains one set bit at that position. There is no addition or carry between the halves.

Consequently, selected upper-half bits can affect the return value even when the selected lower half is zero.

## Acceptance examples

These examples are analytically derived conditions, not observed executions.

Unless overridden, each assumes 32-bit integers as described above, stable shared words, bias zero, and selection word 0xFFFFFFFF.

### Zero inputs

With both packed values zero and weight input zero, the return value is zero.

### First nominal endpoint

With first packed value 0x000007E0, second packed value zero, and weight input zero, the return value is 0x07E0.

The six-bit field is relocated for arithmetic and reaches the output through the upper-half fold.

### Second nominal endpoint

With first packed value zero, second packed value 0x000007E0, and weight input 65,536, the return value is 0x07E0.

The effective weight is 32. This endpoint result depends on the stated bias and selection values.

### Midpoint of one relocated bit

With first packed value zero, second packed value 0x00000020, and weight input 32,768, the return value is 0x0010.

The effective weights are both 16. The second value’s relocated bit produces an upper-half contribution that folds into output bit 4.

### Quantized weights

For fixed packed arguments and stable shared words:

- Weight inputs 0 and 2,047 produce the same result.
- Weight inputs 2,048 and 4,095 produce the same result.

These equivalences establish weight quantization, not equivalence between the two different intervals.

### Retained upper input bits

With first packed value 0x00010000, second packed value zero, and weight input zero, the return value is 0x0001.

An input bit above bit 15 can therefore affect the output.

### Overlapping relocation uses OR

With first packed value 0x00200020, second packed value zero, and weight input zero, the return value is 0x0020.

The original bit 21 and relocated bit 5 occupy the same arithmetic position. They do not add to form the next bit.

### Product overflow precedes scaling

With first packed value 0x08000000, second packed value zero, and weight input zero, the return value is zero.

Multiplying the retained input bit by 32 produces a value whose low 32 bits are zero. A wider calculation that retained the overflow bit through scaling would not satisfy this case.

### Separate contribution truncation

With both packed values equal to 1 and weight input 32,768, the return value is zero.

Each contribution has a weighted value of 16, which is discarded by its own five-bit reduction. Combining the weighted values before reduction would instead retain a nonzero result and would violate this behavior.

### Bias applies twice

Override the bias to 32. With both packed values zero and weight input zero, the return value is 2.

Each separately biased contribution becomes 1 after reduction.

### Selection follows addition

Set both packed values to 1, weight input to 32,768, bias to 16, and selection word to 1. The return value is zero.

Each reduced contribution is 1, so their sum is 2. The selection word removes that sum bit. Masking the contributions separately before adding would produce a different result.

### Zero selection word

With selection word zero, every argument combination whose evaluation otherwise completes returns zero, regardless of the bias.
