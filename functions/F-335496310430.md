# F-335496310430

## Purpose

F-335496310430 performs two key-directed traversals of a linked structure, constructs two cursor-like endpoints, counts advances between those endpoints, and then invokes a range-processing dependency. Its returned result is the number of advances performed before that final invocation.

**Inferred intent:** this resembles locating and removing a key-associated range while returning its size. That interpretation is not established by the supplied body alone. In particular, endpoint selection saves selected **child links**, not the current nodes, and the final dependency’s implementation is unavailable. The contract therefore describes the observed traversal and calls without promising conventional lookup or erasure semantics.

## Interface

### Inputs

The function receives two arguments:

- **Context address:** an integer-valued address used to locate a structure header and an embedded comparison-state region.
- **Query value:** an opaque 32-bit value passed unchanged to the comparison dependency. It may encode an address or another value; the supplied evidence does not establish its type or ownership.

The context is accessed using these byte offsets:

| Offset from context | Observed use |
|---|---|
| +16 | A 32-bit address identifying a header |
| +25 | Address passed as comparison state; the function itself does not read a field there |

The header and linked nodes are accessed through this layout:

| Object | Offset | Observed use |
|---|---:|---|
| Header | +4 | A 32-bit address used as the initial node for each traversal |
| Node | +8 | A 32-bit child link |
| Node | +12 | A second 32-bit child link |
| Node | +16 | Address passed to the comparator as the node-associated operand |

The supplied representation uses 32-bit integer and address-bearing fields. It does not independently establish the machine’s complete ABI, byte order, alignment requirements, or the size of the node-associated value beginning at offset +16.

### Output

The function returns an integer counter initialized to zero and incremented once for every call it makes to the cursor-advance dependency.

This is not necessarily:

- The number of comparisons.
- The number of nodes visited during either initial traversal.
- The number of objects changed by the final dependency.
- A conventional equal-key count.

Those interpretations require additional dependency and structure contracts.

### Preconditions

For ordinary completion, the following conditions are required:

- Each executed context, header, and node access must refer to valid storage.
- Every nonzero node address reached by a traversal must support the fields actually accessed.
- Comparison and cursor dependencies must accept the supplied arguments.
- Both node traversals and the cursor loop must terminate.
- The final dependency must accept the endpoint representations produced by the preceding calls.
- The advance count must remain representable if a defined signed integer result is required.

There are no explicit checks for null context, null header, malformed links, cyclic structures, invalid cursor ranges, or dependency failure.

## Behavior

### First traversal

The function first reads the header address at context offset +16, then reads that header’s field at offset +4 to obtain the initial node. It separately reads context offset +16 again to initialize the first saved endpoint.

Consequently, the initial node and the initial saved endpoint are not obtained from one cached header read. If the underlying storage changes between these reads, they need not correspond to the same header.

While the current node address is nonzero, the function calls F-257a89ed2c43 with these operands, in order:

1. The address at context offset +25.
2. The address at current-node offset +16.
3. The original query value.

The comparison result is interpreted only as zero versus nonzero:

- **Zero:** the function reads the current node’s +8 link, makes that link the next current node, and saves the same link as the first endpoint.
- **Nonzero:** the function reads the current node’s +12 link and makes it the next current node. The first saved endpoint is unchanged.

The selected child link is read **after** the comparison call. Any changes the dependency makes to that link before returning can therefore affect traversal.

A crucial boundary rule is that a zero-result step saves the child address it follows, not the address of the node being compared. If that selected child is zero, the first saved endpoint becomes zero.

The traversal stops when the current node address is zero. If it never takes a zero-result branch, its saved endpoint remains the header address read during initialization.

### Second traversal

After the first traversal completes, the function starts a separate traversal. It again reads the header through context offset +16 and then reads its +4 field for the initial node. It separately rereads context offset +16 to initialize the second saved endpoint.

It does not reuse the first traversal’s root or header values.

For each nonzero current node, it calls F-257a89ed2c43 with:

1. The address at context offset +25.
2. The original query value.
3. The address at current-node offset +16.

The node-associated operand and query operand have exchanged positions relative to the first traversal.

The result controls traversal as follows:

- **Zero:** follow the current node’s +12 link; leave the second saved endpoint unchanged.
- **Nonzero:** follow the current node’s +8 link and save that child address as the second endpoint.

These selected links are also read after the comparison call. A nonzero-result branch can therefore save a zero endpoint when its +8 link is zero.

No ordering, strictness, antisymmetry, or consistency property is established for F-257a89ed2c43. The two traversals must not be replaced in this contract by assumed lower-bound and upper-bound operations.

### Cursor construction and counting

After both traversals, the function constructs a local four-word cursor representation:

| Byte offset within cursor | Initial 32-bit value |
|---:|---|
| 0 | First saved endpoint |
| 4 | Zero |
| 8 | Zero |
| 12 | First saved endpoint |

It also initializes a separate one-word endpoint with the second saved endpoint.

A count starts at zero. The function repeatedly calls F-cb011f129d08 with the address of the four-word cursor and the address of the separate endpoint.

- A return value of **exactly 1** ends the loop.
- Any other return value causes the count to increase by one, followed by a call to F-a030ebc6bb58 with the four-word cursor’s address.
- The comparison is then attempted again.

A nonzero result other than 1 does **not** terminate the loop.

The counter increases before the advance call. There is no observed check that an advance succeeds, changes the cursor, or moves toward the endpoint. A dependency that fails to establish eventual termination can cause an unbounded loop.

The cursor and endpoint are passed by address. The supplied body does not establish that F-cb011f129d08 is read-only. Changes it makes to either argument can affect subsequent iterations and the final call.

### Final range-processing call

Once F-cb011f129d08 returns exactly 1, the function:

1. Copies the separate endpoint’s current word into a new local word.
2. Copies the cursor’s current word at byte offset +12 into another local word.
3. Calls F-da1b2f2cbf9f with:
   - An address of four bytes of local scratch storage.
   - The original context address.
   - The address of the copied cursor word.
   - The address of the copied endpoint word.

The cursor word is the third argument even though the endpoint word is copied first.

The copied cursor word is taken from the cursor’s **final** +12 field, not from an independently preserved copy of the first saved endpoint. Its value depends on any mutations performed by the cursor dependencies.

The four-byte scratch storage has no explicit initialization before this call. Its contents are not inspected afterward. No return value from F-da1b2f2cbf9f is used.

After that dependency returns normally, F-335496310430 returns the previously accumulated count.

## Side effects

The function’s direct writes are to local storage: traversal bookkeeping, the cursor representation, endpoint words, the counter, and final-call argument storage. No explicit write through the context, header, or node addresses appears in the supplied body.

This does **not** establish that the overall operation leaves the structure unchanged:

- F-257a89ed2c43 receives an address inside the context and a node-associated address.
- Cursor dependencies receive writable local addresses.
- F-da1b2f2cbf9f receives the context and endpoint addresses.
- Any dependency may affect external state under its own contract.

The function contains no explicit allocation or release operation. Ownership transfer, destruction, unlinking, and reclamation by dependencies remain unknown. In particular, the final call must not be described as freeing nodes without additional evidence.

Local addresses supplied to dependencies are valid during their calls. Retaining those addresses for later use would require an external lifetime guarantee not supplied here.

There is no explicit error-result path. Invalid accesses, nontermination, dependency failures, and arithmetic overflow are not converted into a documented status value.

## Acceptance examples

These examples are conditional behavioral checks derived from static evidence. They are not reports of executed tests.

### Stable empty structure and immediate termination

Given a stable header address H whose +4 field is zero:

- Neither traversal calls F-257a89ed2c43.
- Both saved endpoints initialize to H.
- The initial cursor words are H, zero, zero, H.
- The separate endpoint word is H.

If F-cb011f129d08 immediately returns 1 without modifying its arguments, there are no advance calls, the final dependency receives copies of H and H as its endpoint values, and the function returns zero.

The final dependency is still called in this case.

### First traversal saves a null child

Given a nonzero initial node whose +8 link is zero, if the first comparison returns zero:

- The first traversal ends after following that zero link.
- Its saved endpoint is zero, not the compared node.

Any interpretation requiring the saved endpoint to be a nonzero matching node would disagree with the supplied body.

### Second traversal saves a null child

Given a nonzero initial node whose +8 link is zero, if the second traversal’s comparison returns nonzero:

- The second saved endpoint becomes zero.
- The traversal ends.

A zero comparison in this traversal instead follows +12 and does not update that saved endpoint.

### Exact termination value

If successive F-cb011f129d08 results are 0, 2, and 1, and every call returns normally:

- F-a030ebc6bb58 is called twice.
- The returned count is two.
- Result 2 is treated as continuation, not successful termination.
- The final dependency is called after the third check.

### Mutated cursor endpoint

If a cursor dependency changes the cursor’s +12 word to X before the terminating check completes, and the separate endpoint’s current word is Y, the final dependency receives copied values X and Y. The function does not restore the original saved endpoints.

### Links changed during comparison

If F-257a89ed2c43 changes the child link selected by its own result, the traversal reads the changed link after the call. A contract that snapshots both child links before comparison would not match this behavior.
