# F-80406399b513

## Purpose

F-80406399b513 performs an ordered series of memory updates using implicit entry-state values, then invokes an unresolved indirect dependency with four arguments. Its observable behavior is primarily memory mutation; no explicit return value is supplied.

The supplied static representation establishes repeated writes, mixed-width accesses, reads whose values are retained across later overwrites, and a final indirect invocation. It does not establish a higher-level purpose such as object initialization, device configuration, or graph linking. Those interpretations would require evidence beyond the supplied material.

This contract describes the represented behavior without treating comments, apparent field boundaries, or conventional calling assumptions as authoritative. In particular, repeated writes and overlapping accesses must not be reduced to their apparent final values when describing observable behavior.

## Behavior

### Arithmetic and observation rules

All word values in this contract are 32-bit quantities. Byte stores retain eight bits; the halfword store retains sixteen bits.

Unsigned arithmetic involving A has 32-bit wraparound in the represented arithmetic model. Arithmetic involving signed inputs or signed loaded values requires more care: doubling or adding offsets can exceed the signed 32-bit range. The representation alone does not establish the machine-level outcome of every such case. Acceptance examples involving these expressions therefore assume representable arithmetic unless explicitly discussing an uncertainty.

Memory reads and writes below are ordered as represented. This is not a claim about hardware barriers, bus transactions, or atomicity. It is also not permission to discard repeated writes: whether a location is ordinary memory, shared storage, or device-visible storage is unknown.

### Initial publication and repeated updates

The first visible action is a word write of B to A+0x20. Only afterward is P loaded from its global source. Consequently, if that first destination overlaps the global source, the loaded P can reflect the write.

A word value of 0x20 is then written at fixed address 0x60. The doubled value of C is formed and used as the payload for the following word writes.

The initial update group has this observable order:

| Order | Access |
|---|---|
| 1 | Write doubled C as a word at 2D+0x54 |
| 2 | Write the low byte of A at P+0x19 |
| 3 | Write the low byte of P at A+0x11 |
| 4 | Write doubled D as a word at P+0x34 |

A fixed, explicitly repeated region follows. Each repetition writes doubled C at 2A+0x54, then the low byte of A at P+0x19, then the low byte of P at A+0x11, then doubled A at P+0x34.

This region does not advance an address or consume an input-dependent count. Its writes repeatedly target the same expressions. The exact repetition count is **documented_only** here; it has not been independently certified. That limitation affects exact access-count acceptance, not the identified destinations, values, or order within each repetition.

P and both low-byte values remain retained values throughout this region. Overwriting their source memory does not itself cause them to be reloaded.

### Retained reads and byte publication

After the repeated region:

1. A word is read from fixed address 0xA9 and retained.
2. A word is read from 2C+0x74 and retained.
3. A byte is written at fixed address 0x3A. Its bit pattern is the low eight bits of twice the low byte of A plus 0x30.
4. A word is read from C+0x14 and retained.
5. A word is read from A+0x04 and retained.

The next updates publish the low byte of A at C+0x0D, the constant byte 0x6C at A+0x08, and the low byte of P first at A+0x0D and then at A+0x09. A word containing C is then written at C+0x54.

The low byte of the retained word from 0xA9 is written at fixed address 0x67.

These retained values are significant: later overwrites of their original locations do not replace the values already read.

### Shift-derived update and overlapping field replacement

A word is read from C+0x44. Its low byte is written at A+0x10.

Before that A-based write, the byte at fixed address 0x67 is read and copied to fixed address 0x21. Thus this copy uses an actual byte read, not an unconditional substitution of the previously retained word’s low byte.

The full word read from C+0x44 is written at P+0x54. Next, a byte derived from its signed right shift is written at C+0x01. The shift amount is the low byte of A.

The word at P+0x54 is then overwritten with A. Both word writes are part of the visible sequence, even when their values happen to match.

The shift expression has unresolved boundary behavior. In particular, the supplied representation does not establish the result for shift counts of 32 through 255, or fully establish right-shift semantics for a negative signed operand.

A word is then read from A+0x40. The retained word previously read from A+0x04 is written at P+0x74, followed by a word write of the newly read A+0x40 value at A+0x10.

That word write spans A+0x10 through A+0x13. It therefore overlaps the earlier byte writes at A+0x10 and A+0x11. Their final byte values depend on the word representation and any additional aliases; they cannot be described as independent persistent fields.

### Linked-address updates

The following progression preserves both explicit reads and intervening writes:

| Phase | Ordered observable effects |
|---|---|
| Publish C and retained global data | Write C as a word at P+0x44; read the byte at 0x67 and write it at A+0x09; write the low byte of A at C+0x09; write the retained word originally read from 0xA9 at A+0x44 |
| Obtain a target | Read a word from A+0x54; call this retained address-like value Q |
| Publish through Q | Read the byte at 0x67 again and write it at A+0x09; write the low byte of the retained word from 2C+0x74 at Q+0x0D |
| Restore a retained word | Write the earlier retained value from C+0x14 as a word at C+0x54 |
| Obtain another payload | Read a word from A+0x14; call this retained value V |
| Publish retained bytes and Q | Write the low byte of the retained word from 2C+0x74 at C+0x11; write the low byte of Q at A+0x09; write Q as a word at A+0x44 |

The two reads of fixed address 0x67 in this phase are distinct reads. If preceding writes alias that byte, or the environment changes it, the two published bytes need not match.

Likewise, Q is the value read after earlier updates, not necessarily the entry-state word at A+0x54.

### Final memory operations and indirect invocation

A word is read from C+0x04; call the retained value R. A halfword containing 0x0065 is then written at address 2R.

Only after that halfword write is a word read from R+0x64; call the retained value S. If those access ranges overlap, the halfword write can affect S.

The remaining sequence is:

- Write the low byte of V at Q+0x11.
- Write the word value 100, decimal, at Q+0x54.
- Read a word from R+0x74 and retain it as T.
- Read a word from C+0x64 and retain it as U.
- Write the low byte of R at C+0x09.
- Write S as a word at U+0x54.
- Write U as a word at address 2S.

The indirect dependency is then invoked with these arguments, in order:

| Position | Value |
|---|---|
| 1 | 0x72 |
| 2 | S |
| 3 | The word retained earlier from C+0x14 |
| 4 | T |

The fourth argument is the later read from R+0x74, not the earlier word from fixed address 0xA9.

## Side effects

The function directly changes caller-associated memory, fixed-address storage, and locations reached through loaded words. It does not validate those locations before use.

No allocation, deallocation, explicit ownership transfer, locking, or rollback is visible before the indirect invocation. Writing an address-like value does not establish ownership of the referenced storage.

The dependency may have further effects. There is no basis for claiming that it preserves globals, preserves any previously written memory, releases memory, retains arguments, or returns normally.

There is no explicit error code or recoverable-error branch. If a read, write, or control transfer fails, earlier writes may already be externally visible. Atomic completion and restoration of prior state are not established.

Even absent concurrent modification, aliases can change later input reads. Final-state reasoning must therefore follow access order rather than combine independent-looking field assignments.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

### Ordinary disjoint storage

Assume all accessed ranges are valid, suitably supported, disjoint except for the explicitly overlapping A-based fields, and unaffected by external writers. Also assume all signed arithmetic is representable and the shift count is supported.

At the point immediately before the indirect invocation:

- A+0x20 contains B.
- Fixed address 0x60 contains the word 0x20.
- The repeated selector updates leave doubled A at P+0x34.
- P+0x54 contains A, despite its earlier write of another word.
- C+0x54 contains the value retained from C+0x14, despite its earlier write of C.
- A+0x44 contains Q, despite its earlier write of the word from 0xA9.
- Q+0x54 contains the word 100.
- The dependency arguments are 0x72, S, the retained C+0x14 value, and T.

These observations do not assert what remains after the dependency executes.

### Byte truncation

Assume the low byte of A is 0xE3 and the relevant destinations do not alias other writes. Publication of that byte stores 0xE3, not an extended signed value.

The byte written at fixed address 0x3A is 0xF6, the low eight bits of twice 0xE3 plus 0x30. This does not establish a character encoding or numeric-formatting purpose.

### Early write affecting P

Assume A+0x20 designates the global word that supplies P. The first write occurs before P is loaded. P consequently obtains B under ordinary memory semantics. A contract that always uses the global’s entry-state value would be incorrect.

### Repeated accesses to observable storage

Assume P+0x19 is device-visible storage that records each byte write. Acceptance requires preserving the repeated writes and their interleaving with the other repeated-region accesses. Replacing them with one final byte write is not justified by this contract. Exact-count acceptance remains **documented_only** pending certification of the repetition count.

### Read after overlapping halfword write

Assume the halfword at 2R overlaps the word at R+0x64 and the memory model supports those accesses. S must be obtained after the halfword update. Its value cannot be unconditionally taken from entry-state memory.

### Unsupported shift or invalid target

If the low byte of A is at least 32, this contract supplies no expected shifted byte. If a computed address or the indirect target is invalid, it likewise supplies no successful-completion guarantee or recovery behavior.
