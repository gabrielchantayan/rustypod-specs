# F-e13609684351

## Purpose

F-e13609684351 invokes object-directed callbacks, forwards a nonzero selector, and, when that selector matches a global value, refreshes object state. It then conditionally prepares and inserts an embedded record into a global singly linked list.

Insertion depends on a registration indicator observed **after** a refresh dependency returns and the refresh-field write completes. The indicator’s entry-time value does not determine whether preparation occurs.

A scheduling or timeout purpose is plausible but unestablished. The contract specifies key calculation, comparison outcomes, and insertion order without assigning time units or an ordering relation.

Evidence classifications used here:

- **Established:** directly supported by the supplied static representation.
- **Inferred intent:** plausible interpretation, not an acceptance requirement.
- **documented_only:** unresolved behavior requiring dependency contracts or other evidence.

No runtime tests have been performed.

## Behavior

### Initial callback sequence

The function first invokes F-U01 through object dispatch-table offset `0x05C`, passing the object pointer.

It then calls F-b2366138325f without represented explicit arguments and tests its result against zero.

- A zero result skips the repeated callback and F-6dd3097a8880.
- A nonzero result causes another F-U01 invocation with the object pointer, followed by F-6dd3097a8880 without represented explicit arguments.

The repeated invocation performs a fresh dispatch-table lookup. It need not resolve to the same target as the first invocation if intervening calls change dispatch state.

Next, the function reads the subordinate-object pointer at `0x0EC` and invokes F-U02 through that object’s dispatch-table offset `0x174`. No explicit receiver argument is established for this invocation.

If F-U02 returns nonzero, F-U03 is invoked through the main object’s dispatch-table offset `0x198`, with the object pointer.

The function then invokes F-U04 through the main object’s dispatch-table offset `0x190`, passing, in order:

1. Object pointer.
2. Payload.
3. Context.

The selector is not forwarded to F-U04. This entire initial sequence occurs before the selector-zero check. Results from F-U01, F-U03, and F-U04 are not consumed by the visible caller.

### Selector handling

After F-U04 returns:

- A zero selector causes an immediate return.
- A nonzero selector is passed, alongside the object pointer, to F-U05 through object dispatch-table offset `0x1D8`.

After F-U05 returns, the function reads the distinguished selector value from global storage and compares it with the supplied selector. A mismatch causes a return.

The global comparison value is therefore not an entry-time snapshot. F-U05 and earlier dependencies are not assumed to preserve it.

A zero selector cannot reach refresh processing, even when the distinguished global value is also zero.

### Refresh and registration decision

For a matching nonzero selector, the function establishes the embedded-record address at object offset `0x1AC`. It then performs these operations in order:

1. Calls F-936a8728139d.
2. Reads the 32-bit refresh value from global storage.
3. Writes that value to object offset `0x1CC`.
4. Reads the registration indicator at object offset `0x1C8`.
5. Branches on that observed indicator.

The refresh-field write occurs regardless of the indicator’s value.

If the indicator **read at step 4** is nonzero, the function returns. It does not directly normalize the indicator, run preparation, calculate a key, insert the record, or perform the post-registration sequence.

If that observed indicator is zero, preparation proceeds.

The entry-time indicator does not control this decision. In particular:

- An entry-time nonzero indicator does not suppress preparation if dependencies leave it zero at the branch.
- An entry-time zero indicator does not enable preparation if dependencies leave it nonzero at the branch.
- The function itself performs no direct indicator write before this decision.

### Preparation

When the indicator observed at the branch is zero:

1. The function reads a global value and passes it to F-338d16f9ce72.
2. It calls F-add44d4e9aaa with the embedded-record address.
3. It reads the 32-bit registration amount from object offset `0x1B0`.

The amount is read after both preparation dependencies return. Neither dependency is assumed to preserve it, the indicator, list state, or globals.

There is no second indicator check after preparation. A preparation dependency changing the indicator does not introduce an additional visible guard.

If the amount is zero, direct key calculation and insertion are skipped. The function still performs the post-registration sequence.

### Key calculation

For a nonzero amount, the function:

1. Calls F-U06, obtaining an integer result represented as 32 bits.
2. Reads and captures a global pointer to the list-head storage cell.
3. Writes the key at object offset `0x1B4`, using the external result plus the previously read amount multiplied by 1000.
4. Reads a 32-bit auxiliary global value and writes it to object offset `0x1C4`.
5. Reads the current head pointer from the captured list-head storage cell.

The amount used in the calculation is the value read before F-U06. A change to the amount field during F-U06 does not replace that captured operand.

The captured list-head storage pointer and auxiliary value are obtained after F-U06 returns. The head pointer is read after the key and auxiliary writes.

The calculation and destination are represented at 32-bit width. Exact original-language overflow semantics are documented_only; this contract does not promise checked arithmetic, saturation, or a particular result for overflowing inputs. No positivity check exists: a negative nonzero amount, under the represented signed interpretation, enters this path.

The factor 1000 does not establish any unit conversion or prove that F-U06 supplies a clock value.

### List traversal

Traversal begins with the current head and no predecessor.

For each nonnull current node, F-0d70d6f9010c receives:

1. The address eight bytes into the current node.
2. The object’s comparison-key address at `0x1B4`.

A nonzero result stops traversal at that node. A zero result causes the function to read that node’s next link **after the comparison call returns**, retain the node as predecessor, and continue with the link just read.

Thus insertion occurs before the first node yielding a nonzero comparison result, or at the end if every visited node yields zero.

No less-than, greater-than, equality, or chronological meaning is established for the comparator result. The comparison receives addresses, not immutable key snapshots. Its preservation of either key or any list link is unknown.

There is no visible cycle detection or traversal bound. Cycles or dependency-driven link changes can prevent termination.

### Insertion writes

Once traversal stops, direct writes occur in this order:

1. Publish the embedded-record address:
   - To the captured list-head storage cell if there is no predecessor.
   - Otherwise, to the predecessor’s next-link field.
2. Write the 32-bit value one to object offset `0x1C8`.
3. Write the stopping node’s address, or null at the end, to the embedded next link at `0x1AC`.

The new record’s final next link is not initialized before its address is published. This is the represented write order, not a claim of atomicity, synchronization, or cross-thread memory ordering.

There is no explicit duplicate-membership check beyond the earlier indicator decision. The function does not validate that the embedded record is absent from the list.

### Post-registration sequence

This sequence runs after either a zero-amount insertion skip or completed insertion. It does not run when the indicator observed after refresh was nonzero.

The function:

1. Reads another global value and passes it to F-5bcae2eff9a7.
2. After that call returns, reads the global pointer used as the earlier argument source for F-338d16f9ce72.
3. Dereferences that pointer to obtain a further pointer.
4. If the resulting pointer is nonnull, reads its first 32-bit word.
5. If both the resulting pointer and that word are nonzero, invokes F-U07 through a global indirect target.
6. Returns.

The null check applies to the **pointer obtained by dereferencing the global pointer**, not to the global pointer before that dereference. The latter must already be valid.

No explicit arguments or consumed return value are represented for F-U07. The terminal pointer reads and target selection occur after F-5bcae2eff9a7; earlier global values are not substituted.

## Side effects

Directly established writes are:

- `0x1CC`: refreshed on every matching-nonzero-selector path.
- `0x1B4` and `0x1C4`: written when the amount observed after preparation is nonzero.
- List-head storage or a predecessor link: updated during insertion.
- `0x1C8`: set to one during insertion.
- `0x1AC`: set to the stopping node or null during insertion.

These direct effects are distinct from dependency effects. For example, a branch observing a nonzero indicator performs no direct indicator write, but dependencies may already have changed that field.

The function performs no explicit allocation or deallocation. It publishes an address inside the object rather than allocating a separate node. Removal, ownership transfer, and lifetime management are not shown. Dependencies are not assumed to acquire or release ownership.

No explicit error result, rollback, exception translation, or recovery mechanism is represented. If a dependency fails to return normally, subsequent operations are not established to occur. Invalid accesses and nonterminating traversal have no represented recovery path.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. They assume valid storage and normally returning dependencies. Any stated stability of dependency-controlled state is an additional condition of that example.

1. **Zero selector.** The initial callback sequence and payload/context callback occur. No selector callback, refresh processing, or registration processing follows.

2. **Nonzero selector with mismatch after forwarding.** F-U05 receives the object and selector. If the distinguished global read after its return differs, the function returns without its direct refresh-field write.

3. **Distinguished global equals zero.** A zero selector still returns before selector forwarding and equality-controlled processing. Equality alone does not enable refresh.

4. **Indicator observed as seven after refresh.** On a matching-selector path, F-936a8728139d returns and the function completes its direct write to `0x1CC`. If the subsequent read of `0x1C8` yields seven, preparation and the post-registration sequence are skipped. The function does not directly rewrite that seven. Its entry-time value is irrelevant: dependencies may have changed it before the read.

5. **Indicator observed as zero; zero amount after preparation.** If the indicator read after F-936a8728139d and the refresh-field write yields zero, both preparation dependencies run. If the amount read after them is zero, there are no direct key, auxiliary, insertion-link, or indicator writes on this path. F-5bcae2eff9a7 and the terminal checks still occur. Dependencies may independently alter those fields or list state.

6. **Entry-time indicator changed before the decision.** An entry-time seven changed to zero by F-936a8728139d permits preparation if zero is subsequently observed. Conversely, an entry-time zero changed to seven suppresses preparation if seven is observed. Both cases still include the direct refresh-field write.

7. **Empty list and nonzero amount.** If the captured head cell contains null when read, no comparator is called. The direct insertion writes publish the embedded record as head, set the indicator to one, and set the embedded next link to null, in that order.

8. **First comparison is nonzero.** For a stable existing head, the new record is published as head and its next link is subsequently set to the node whose comparison stopped traversal.

9. **Two zero comparisons, then nonzero.** With links stable across those calls, insertion publishes the record through the second visited node’s next link and ultimately links the record to the third visited node.

10. **Nonoverflowing arithmetic.** If the captured amount is two and F-U06 returns 300, the key write stores 2300. No units are implied.

11. **Terminal gating.** After F-5bcae2eff9a7, a valid global pointer that yields a null pointer suppresses the first-word read and F-U07. A nonnull resulting pointer whose first word is zero suppresses F-U07. A nonnull pointer with a nonzero first word enables it.
