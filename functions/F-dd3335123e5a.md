# F-dd3335123e5a

## Purpose

F-dd3335123e5a reports one selected bit from an externally stored word. A selector determines a bank offset and a position within that bank. The function reads the selected word, extracts bit 21, and returns that bit as an unsigned value of either 0 or 1.

The established behavior is a bit query, not a write, acknowledgement, reset, or state transition. The fixed-address access is consistent with a hardware status query, but the supplied evidence does not establish the nature of the backing storage. In particular, it does not establish whether reading that storage has device-specific effects.

The function accepts two arguments. Only the second participates in the shown computation.

## Interface

### Inputs

1. **First argument:** an opaque four-byte value.
   - The supplied body does not inspect, dereference, copy to external storage, or otherwise use this argument.
   - It does not contribute to address selection or the returned value.
   - No pointer validity, ownership, or lifetime requirement for this argument is established by the body.

2. **Selector:** an unsigned integer, interpreted here as a 32-bit value.
   - Bits 0–6 select a position from 0 through 127.
   - Bit 7 selects between two bank offsets.
   - Bits 8–31 do not affect the shown computation.
   - Every possible combination of the low eight bits is accepted by the body. There is no explicit range check or rejected selector.

### Output

The result is an unsigned integer, interpreted here as 32 bits, whose only possible values after a successful read are:

- **0:** bit 21 of the selected word was clear.
- **1:** bit 21 of the selected word was set.

The function does not return the original bit mask, the complete word, or the selected address. Other bits in the selected word do not influence the result.

The supplied representation explicitly identifies the first argument as four bytes and represents the selector, loaded word, and return value using an unsigned integer type. The contract uses the conventional 32-bit interpretation of that type. An independent type declaration or target ABI is not supplied, so that width interpretation is not independently verified.

## Behavior

### Selection

The low seven selector bits produce a position \(i\) in the inclusive range 0–127:

\(i = \text{selector} \mathbin{\&} 0x7F\).

Bit 7 chooses an offset:

| Selector bit 7 | Selected bank offset |
|---|---:|
| Clear | `0xB00` |
| Set | `0x900` |

Thus, setting bit 7 chooses the numerically lower offset. It does not add `0x80` to the position or choose the higher-address bank.

The position contributes an additional offset of \(i \times 0x20\). Consequently, under a byte-addressed interpretation, consecutive positions are separated by 32 bytes. The function reads one word at the selected position; it does not scan the interval between positions.

### Address formation and layout

The access is anchored at the fixed address `0x38400000`. Under the byte-addressed interpretation of the supplied address expression, the selected word address is:

\(0x38400000 + \text{bank offset} + i \times 0x20\).

That interpretation gives these endpoints:

| Selector bit 7 | Position 0 | Position 127 |
|---|---:|---:|
| Clear | `0x38400B00` | `0x38401AE0` |
| Set | `0x38400900` | `0x384018E0` |

These are addresses of selected words, not declarations that every intervening byte is accessed or valid.

The fixed-address object’s declaration is absent. Therefore, the exact byte scaling of the address expression is **documented_only** rather than independently established. The numeric byte addresses and 32-byte stride above are conditional on that object providing byte-granular address arithmetic.

The two apparent banks overlap under this interpretation. Their starting offsets differ by `0x200`, equal to sixteen position strides. Therefore, a position in the clear-bit-7 bank selects the same address as position sixteen greater in the set-bit-7 bank, whenever both positions are in range.

For example, selectors `0x00` and `0x90` select the same address. The body does not distinguish such aliases after forming the address. The overlap must not be “corrected” by an implementation claiming to preserve this behavior.

### Read and extraction

After selection and address formation, the supplied body contains one unsigned-word read from the selected address.

The returned value is obtained by retaining only mask `0x00200000` and shifting that retained bit right by 21 places. Bit numbering is zero-based: the least significant bit is bit 0.

Consequences include:

- A selected word of zero returns 0.
- A selected word containing only `0x00200000` returns 1.
- Setting any combination of other bits cannot change the result while bit 21 remains unchanged.
- A selected word with every bit set returns 1.

There is no second read to confirm the value, no retry, and no comparison against an earlier observation.

### Ordering and arithmetic

The observable operation in the supplied body is the selected-word read. Bank selection and offset arithmetic precede that read; bit extraction follows it.

On the stated 32-bit interpretation:

- The position is at most 127.
- The position contribution is at most `0xFE0`.
- The largest combined bank-and-position offset is `0x1AE0`.
- Under byte-addressed interpretation, the largest resulting address is `0x38401AE0`.

These calculations do not require unsigned wraparound. Bits above selector bit 7 cannot enlarge the offset because they are excluded before the position multiplication and are not used in bank selection.

The evidence does not establish processor-level ordering, memory barriers, cache behavior, or the physical bus transaction sequence.

Additional acceptance conditions:

- **Unused argument:** changing only the first argument must not change the selected address or extraction rule. Equal returned values additionally require equal observed values of bit 21.
- **Ignored high selector bits:** selectors `0x00000080` and `0xFFFFFF80` must select the same location. They need not return equal values if that location changes between reads.
- **Overlapping selections:** selectors `0x00` and `0x90` must select the same location. If the backing word remains unchanged and reading it has no relevant side effect, both calls return the same result.
- **No normalization beyond extraction:** if the selected word is `0x00400000`, return 0. A nonzero word is not sufficient for a result of 1.
- **Read failure:** if the selected location cannot be read, no ordinary fallback result is specified. Returning 0 as an invented error convention would not follow from the evidence.
