## Acceptance examples

These are conditional static acceptance examples, not results of executed tests.

1. **Input forwarding.** If the function is entered with opaque input 0x89abcdef and the initial target resolves successfully, F-A01 receives that exact 32-bit pattern. No interpretation as a signed number or pointer is required.

2. **Truncated seed shift.** If F-A13 produces 0x00000001, the third argument to F-B07 is 0x10000000 under 32-bit truncating shifts. The first argument to F-B13 remains zero because its cumulative left shift exceeds the word width.

3. **Signed reconstruction.** If F-B29 produces 0x04000000, its left shift by 5 bits yields 0x80000000. With arithmetic right shift, the second F-C05 argument is 0xfc000000, not 0x04000000.

4. **Discarded F-C10 bits.** If F-C10 produces any 32-bit value, its retained left-shift-by-27 result has no set bits below position 27. Therefore the second F-C26 argument is zero under the fixed-width interpretation.

5. **Zero write address.** If the top 12 bits of the F-C38 result are zero, the attempted 16-bit write address is zero. The contract does not substitute a safe destination or suppress the operation.

6. **Maximum selector.** If the top 12 bits of the F-C38 result are 0xfff, the write address is 4095 plus 1023, or 5118.

7. **Potential alignment fault.** If that selector is one, the write address is one. Whether the 16-bit write succeeds, faults, or has architecture-specific behavior is documented_only.

8. **Early failure.** If a dependency does not return, later calls and the final write are not required to occur. The visible sequence supplies no recovery path.
