# F-c94a03902c10

## Purpose

F-c94a03902c10 processes one selected collection of fixed-size records. It classifies records, groups compatible records into circular membership lists, assigns each member a group back-reference, and derives group flags and relationships from those members.

The established behavior is structural. The supplied evidence does not establish application-level meanings for the records, coordinates, categories, or relationships. Terms such as “group,” “coordinate,” “primary relation,” and “secondary relation” below describe observed roles, not a confirmed domain model.

The operation is incremental and not transactional. An error can leave classification flags, group-management state, and previously processed membership lists modified.

## Interface

### Inputs and result

The function accepts:

- A pointer to a context represented as 32-bit words.
- A signed 32-bit selector identifying the collection to process.

It returns a signed 32-bit status:

- A nonzero result from F-ed69baa5ffc4 is returned immediately.
- A nonzero result from F-f95622508985 is returned immediately.
- Otherwise, the normal result is zero.

No null-pointer, selector-range, allocation-capacity, or list-integrity validation is visible.

### Preconditions

For a defined successful execution, all accessed storage must be valid, correctly aligned for the observed accesses, and large enough for its selected layout.

Additional structural requirements include:

- Input array bounds and address arithmetic must not wrap.
- Classification chains must reach their designated terminal nodes.
- Group membership lists must be circular and return to their designated first member.
- Related records must provide valid group back-references whenever those references are consulted.
- Dependency results and dependency-written state must satisfy the assumptions made by subsequent accesses.

The selector has inconsistent width treatment: most context indexing uses the full 32-bit selector, while the separate table lookup uses its signed 16-bit narrowing. A selector outside the intended range can therefore select unrelated structures. No reconciliation is visible.

## Behavior

### 1. Initial classification and early error

Before calling F-ed69baa5ffc4, the function reads the selected input array address and count and computes its end address using the 48-byte stride.

If F-ed69baa5ffc4 returns nonzero, that status is returned. No classification or later grouping work is then performed by this function. Side effects of the dependency itself are not established.

If it returns zero, the function traverses the previously captured input range in ascending record-address order.

For each record:

1. It reads the initial classification-node pointer and that node’s 16-bit value.
2. It clears only bit 0 of the record’s flags, preserving the other seven bits.
3. It follows the node chain toward the terminal pointer.
4. It stops early if two consecutively examined nodes both have zero in their low two bits.
5. Otherwise, when a traversal step reaches the terminal node, it sets record flag bit 0.

The break condition has precedence over setting the flag. If the pair ending at the terminal node has zero low-two-bit values on both nodes, the record remains unmarked.

If the initial and terminal pointers are equal, the traversal body does not execute and bit 0 remains cleared, regardless of the initial node’s low bits.

### 2. Preparation and grouping threshold

After classification, F-5f99824054ed is called with the context and full selector. Its return value is not used.

The function then:

- Captures context word 0.
- Reloads the selected input array and count.
- Computes a new end address.
- Resets the selected group count to zero.
- Captures the scaling argument from context word 1 or word 3 according to whether the full selector equals zero.

Consequently, the records classified before F-5f99824054ed need not be the same range subsequently grouped if that dependency changes the context.

To obtain the grouping threshold, the function passes the separate table entry’s offset-240 field and the captured scaling argument to F-74efb2674226.

- If the signed result is less than 17, the threshold is obtained by rereading the entry’s offset-240 field.
- Otherwise, the threshold is the result of F-73d099a86adb with arguments 16 and the captured scaling argument.

The first branch does not use the conversion result as its threshold. The reread also means a dependency modification of that table field can affect the threshold.

### 3. Selecting an existing group

Input records are processed in ascending address order over the second captured range.

For each record, the function scans the currently available group array from its first entry upward. The group count and group array address are read from the context during this scan.

A group is considered only if its category equals the input record’s category. Coordinate differences are calculated after sign-extending both 16-bit coordinates to 32 bits. Their absolute difference lies between 0 and 65,535, so this subtraction and absolute-value operation do not overflow signed 32-bit arithmetic.

A candidate must have a coordinate difference strictly less than both:

- The grouping threshold.
- The best accepted difference so far.

The initial best-difference value comes from an external global whose value is not supplied. That value can reject even the first category-compatible candidate.

Equal-distance candidates do not replace an already selected candidate.

An additional compatibility check applies when the input record’s primary related-record pointer is nonzero. The function walks the candidate group’s entire circular member list. For each member with a nonzero primary related-record pointer, it compares the coordinates of the two related records.

The candidate is rejected if any such difference is greater than or equal to the grouping threshold. Members without a primary related record do not themselves reject the candidate.

If the candidate survives, its coordinate difference becomes the new best difference and it becomes the selected group.

### 4. Creating or extending a group

If no existing group is selected, F-f95622508985 is called with:

- The address of the selected context substructure beginning at word \(7s+12\).
- The input record’s signed coordinate, widened to 32 bits.
- The previously captured context word-0 value.
- An output location for a group-record pointer.

A nonzero status is returned immediately. There is no rollback.

On success, an unmapped external dependency is invoked with the returned group pointer and a size of 48. Its exact initialization behavior is not established by the supplied evidence.

The function then explicitly:

- Sets the group’s first and last member pointers to the input record.
- Copies the input coordinate into the group.
- Calls F-74efb2674226 with that signed coordinate and the captured scaling argument.
- Stores the same returned 32-bit value at group offsets 8 and 4, in that order.
- Makes the input record’s next-member pointer point to itself.
- Copies the input category into the group.

The visible function does not explicitly initialize the group relation pointers at offsets 24 and 28. Their initial values depend on external behavior.

If an existing group is selected instead, the function appends the input record by:

1. Setting its next pointer to the group’s first member.
2. Setting the old last member’s next pointer to the new record.
3. Updating the group’s last-member pointer.

An existing group’s representative coordinate, category, and converted fields are not updated during append.

### 5. Assigning member back-references

After all records have been grouped, the function captures the group array start and end using the current group count.

It traverses each group’s circular membership list and writes that group’s address into every member’s offset-8 back-reference.

This entire pass precedes relation derivation. Thus relations between records grouped during this operation can use the newly assigned group back-references.

A zero first-member pointer is skipped in this pass. The later relation pass does not provide an equivalent empty-group guard.

### 6. Deriving relations and group flags

Groups are then processed in ascending group-array order.

For each group, the function counts members with record flag bit 0 set and members with it clear.

Each member contributes at most one relationship candidate:

- If its secondary related record exists and belongs to a different group, that record is used for the secondary group relation.
- Otherwise, if its primary related record exists, that record is used for the primary group relation.
- Otherwise, no relation is considered.

A same-group secondary relation does not block consideration of a primary relation.

For the selected relation slot:

- An empty slot adopts the related record’s group.
- A nonempty slot is replaced only if the coordinate distance between the current member and the selected related record is strictly less than the coordinate distance between the current group and the group already stored in that slot.
- Equal distances retain the existing relation.

These are deliberately different measurements: the proposed relation uses record coordinates; the retained relation uses group coordinates.

Whenever a secondary relation is processed, bit 1 is set in the chosen target group’s flags, including when the existing target is retained.

After processing all members, the current group’s entire flag byte is overwritten:

- It becomes 1 if at least one member is marked and marked members are at least as numerous as unmarked members.
- Otherwise, it becomes 0.

This whole-byte write can erase bit 1 previously set by another group. Conversely, a later group can set bit 1 on a group whose own processing has already completed.

Finally, if both primary and secondary relation pointers are nonzero, the secondary pointer is cleared. The primary pointer remains. Any earlier flag changes to the secondary target are not undone.

## Side effects

Direct writes include:

- Input flag bit 0 during classification.
- Selected group count reset to zero.
- New-group fields and circular membership links.
- Existing groups’ last-member pointers and membership links.
- Every grouped record’s group back-reference.
- Group relation pointers and flag bytes.

The function does not visibly release storage. Storage acquisition, array growth, group-count advancement, and ownership transfer depend on F-f95622508985 or other dependencies.

On a group-creation error, earlier groups may already be linked, but the final back-reference and relation passes have not occurred. Callers must not treat a nonzero return as an unchanged-context guarantee.

There is no established synchronization or reentrancy protection. Dependency calls occur between context reads; only explicitly captured values can be described as retained across those calls.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Early dependency error.** If F-ed69baa5ffc4 returns 7, the function returns 7 without performing its own classification or grouping writes. Dependency-originated writes remain possible.

2. **Single-node classification.** If a record’s initial and terminal classification pointers are equal, its flag bit 0 is cleared and not reset.

3. **Terminal zero pair.** If traversal reaches the terminal node through two consecutive nodes whose low two bits are both zero, the record remains unmarked.

4. **Strict threshold boundary.** With threshold 10 and a sufficiently large initial best-distance value, a category-compatible group at distance 9 may qualify; one at distance 10 does not.

5. **Stable equal-distance selection.** If two qualifying groups both have distance 3 and neither is rejected by related-record checks, the earlier group remains selected.

6. **Compatibility veto.** With threshold 8, an otherwise suitable group is rejected if any member’s primary related-record coordinate differs from the incoming record’s primary related-record coordinate by 8 or more.

7. **First creation failure.** If no group qualifies and F-f95622508985 returns a nonzero status, that status is returned without running final back-reference assignment or relation derivation.

8. **Marked-member tie.** A group containing two marked and two unmarked members receives flag byte 1 during its own finalization. A group containing no marked members receives flag byte 0.

9. **Both relation kinds present.** If finalization leaves both relation pointers nonzero, the secondary pointer is cleared. A target flag set while considering that secondary relation is not reverted.

10. **Order-sensitive target flag.** A secondary-target bit set on a not-yet-processed group can be erased by that group’s later whole-byte flag assignment. A bit set on an already processed group can remain set at return.

Although an empty input range skips grouping, it still invokes preparation and threshold-related dependencies. Normal zero return for that case additionally requires those dependencies to return normally and leave a valid empty group state.
