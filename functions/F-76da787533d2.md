# F-76da787533d2

## Purpose

F-76da787533d2 expands a packed unsigned value into four consecutive output bytes. Three five-bit fields become eight-bit component values through bit replication. A one-bit field becomes either zero or 255.

The established behavior is a packed-bit conversion. Interpreting the output as red, green, blue, and alpha is a plausible intent, but the supplied evidence does not independently establish color-space semantics, alpha-compositing rules, or a surrounding image format. This contract therefore names the outputs component 0, component 1, component 2, and flag.

The function does not return a status or an output pointer. Its result is the four-byte destination update.

The supplied representation uses a byte type and an unsigned integer type. The behavioral model here treats each output byte as eight bits. ## Behavior

### Field extraction and expansion

Each component is interpreted as an unsigned five-bit quantity between 0 and 31.

For a component value \(x\), its eight-bit expansion is:

\[
E(x)=8x+\left\lfloor x/4\right\rfloor
\]

Equivalently, the five original bits occupy output bits 7–3, and the original component’s top three bits occupy output bits 2–0.

These two portions do not overlap, so combining them by bitwise OR produces the same result as addition. The result is always between 0 and 255, inclusive.

This is bit replication, not an independently specified rounding operation for scaling by \(255/31\). Consumers requiring a particular normalized-value rounding rule must not replace the established rule without checking equivalence for every component value.

### Flag expansion

The least significant input bit determines the fourth output byte:

- Input bit 0 clear: output byte 3 is 0.
- Input bit 0 set: output byte 3 is 255.

No other flag output value is produced during a successful execution.

The flag does not modify, suppress, or scale the three component outputs. A clear flag can accompany nonzero components.
