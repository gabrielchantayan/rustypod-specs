# F-bd089bb30718

## Purpose

The available static representation describes a procedure that interleaves numerous unresolved indirect calls with 32-bit and 8-bit memory writes. It propagates the second and third explicit inputs into derived locations, stores scaled call results, repeatedly clears selected fields, and writes truncated bit fields through byte-selected addresses.

No application-level purpose is established. Interpreting this procedure as an allocator, initializer, serializer, or hardware driver would exceed the evidence.

The represented path is straight-line: no explicit conditional branch or loop appears. It ends at an invalid-instruction boundary, not an established normal return. The supplied representation also reports unreliable instruction decoding and overlapping global storage. Consequently, this contract distinguishes the operations actually represented from assumptions needed to execute them meaningfully.

### Arithmetic and memory notation

For this contract:

- **Word** means 32 bits.
- **Byte** means 8 bits.
- Derived addresses and word-sized products are interpreted as 32-bit machine arithmetic, retaining the low 32 bits. This is a machine-level interpretation, not a claim that signed source-language overflow would be defined.
- Right shifts applied to unsigned words are logical.
- A byte store retains the low eight bits of its value.
- A byte selector is zero-extended before adding an address offset.

The following descriptive formulas summarize recurring calculations:

| Description | Formula for a word \(x\) |
|---|---|
| Fourfold value | \(4x\), modulo \(2^{32}\) |
| Sixteenfold value | \(16x\), modulo \(2^{32}\) |

Word byte order and alignment rules are not established.

## Behavior

### Indirect-call sequences

To describe ordering without inventing callee semantics, this contract uses two call-sequence descriptions:

- **Five-call sequence:** one indirect call with the listed explicit arguments, followed by four indirect calls with no explicit arguments shown. Where a result is needed, it is the represented result of the fifth call.
- **Seven-call forwarding sequence:** one indirect call with the listed arguments; one call with no explicit arguments; one call receiving that preceding result; then four calls with no explicit arguments. Where a result is needed, it is the represented result of the last call.

These descriptions identify call order only. They do not imply that any calls share a target, implement a common service, or lack implicit arguments. “No explicit arguments” does not mean the machine registers contain no usable arguments.

Every call can affect memory before subsequent reads. Unless specifically described as retained, a selector is read again when used again.

## Acceptance examples

These examples are conditional static obligations, not executed tests. Each assumes execution reaches the relevant event and all necessary calls and memory accesses are valid.

1. **Second-input preservation.** If the first index is 3 and the second input is `0x11223344`, the first direct word store targets address `0x20` and stores `0x11223344`. The second input has already been passed to the initial call.

2. **Distinct scaled addresses.** If the fourth index is 2, the early base is 8. The associated store targets `0x34`, while the subsequent word read targets `0x1c`. Those accesses must not be conflated.

3. **Upper-fragment truncation.** If the principal word is `0x3ff00000`, its masked shift by 20 is `0x3ff`; the byte written is `0xff`, not a ten-bit value.

4. **Selector mutation across calls.** If the principal-base selector is initially 5, the first selected byte write targets `0x16`. If intervening calls change that selector to 9, the later clearing byte write targets `0x1a`; clearing `0x16` instead is not equivalent.

5. **Retained selector.** If the saved selector is 7 and subsequent calls alter its source byte, the saved-selector word clear still targets `0x4b`. A fresh read would change the represented behavior.

6. **Unsigned word shift.** If the early-base word read yields `0x80000000`, its right shift by three supplies `0x10000000` to the next call.

7. **Low-byte scaling.** If the first late word is `0x41`, its fourfold value is `0x104`; the selected byte write stores `0x04`. A following call still receives the full fourfold word.

8. **No proven successful return.** Reaching the last represented call does not establish success. The next represented event is the invalid-instruction boundary.
