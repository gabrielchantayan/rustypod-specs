# F-cb140e939ea2

## Purpose

F-cb140e939ea2 performs an ordered sequence of operations on a caller-supplied object: it invokes two dependencies around a one-byte state update, supplies a two-word descriptor to another dependency, processes an embedded region, and selects a continuation based on a four-byte field.

The supplied static representation establishes the sequence and address relationships. It does not establish the higher-level purpose of the object or its dependencies. In particular, interpreting the first two calls as locking and unlocking, the byte write as cancellation, or the final calls as destruction would require evidence not supplied here.

The ordinary path has no explicit return value. A separate branch invokes two no-argument dependencies, the second of which is annotated as non-returning in the supplied representation. That annotation is evidence of the represented control flow, not runtime proof of termination.

## Behavior

### Initial sequence

The function first initializes the two local descriptor words from the third and fourth arguments. Both words are subsequently replaced before their address is passed to a dependency.

It then invokes **F-unmapped-01**, an opaque label used in this document for the first dependency whose published ID was not supplied. Its sole explicit argument is the object address plus `0x114`.

After that call returns, the function writes the one-byte value `1` at object offset `0x16c`.

It next invokes **F-unmapped-02**, the second dependency lacking a supplied published ID, also with the object address plus `0x114`.

The established call-boundary ordering is therefore:

1. F-unmapped-01 completes.
2. The byte write at offset `0x16c` occurs.
3. F-unmapped-02 is invoked.

No atomicity, synchronization, or cross-thread visibility guarantee follows from this sequence alone. Either dependency may have effects beyond the explicitly passed address.

### Descriptor preparation and submission

After F-unmapped-02 returns, the function replaces the descriptor’s second word with zero. It then reads the global four-byte value and places it in the first word.

It invokes F-8e09c1ebc410 with:

- The object address.
- The address of the local two-word descriptor.

The global value is read at this stage, not captured at function entry. If an earlier dependency changes that global location, the later value is the one available to this read.

The descriptor does not retain the incoming third or fourth argument at the call boundary. There is no explicit inspection of a result from F-8e09c1ebc410.

The descriptor storage is local to this invocation. Passing its address does not establish that the dependency copies its contents, refrains from retaining the pointer, or takes ownership. Any retained-pointer contract would require additional evidence about storage lifetime and subsequent use.

### Embedded-region processing and branch selection

After F-8e09c1ebc410 returns, the function invokes F-c80ddf4b1ba5 with the object address plus `0x130`.

Only after that call returns does the function read the four-byte field at offset `0x10c` and compare it with zero.

This timing is material. The branch depends on the field’s value after all preceding calls, not necessarily its entry value. There is no visible cached entry-time read. Earlier dependencies may change the field, other object storage, or globals; preservation must not be assumed.
