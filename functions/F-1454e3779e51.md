# F-1454e3779e51

## Purpose

F-1454e3779e51 maps an unsigned selector to one of three results:

- Zero when the selector has its high bit set.
- An address-like value identifying one of eight fixed-stride inline records.
- A 32-bit value fetched from an indirectly referenced table for larger nonnegative selectors, or zero when the table’s root reference is null.

The function performs selection and lookup, not validation of the referenced storage. In particular, the dynamic-table path contains no visible length check.

The established behavior is the branching, arithmetic, and memory access sequence in the supplied static representation. Interpreting the two result-producing paths as a unified record lookup is inferred intent: the inline path computes an address-like result, whereas the dynamic path returns a loaded integer without establishing what that integer represents.

## Interface

### Input

One unsigned integer selector, interpreted under the recovered 32-bit integer model.

The selector’s bits are also interpreted as a signed integer for the first decision. Consequently:

| Selector range | Selected behavior |
|---|---|
| `0x00000000` through `0x00000007` | Compute an inline-record result |
| `0x00000008` through `0x7FFFFFFF` | Consult the dynamic root and possibly fetch a table entry |
| `0x80000000` through `0xFFFFFFFF` | Return zero immediately |

The signed-negative check precedes the unsigned comparison against seven. High-bit-set selectors therefore never reach the dynamic lookup, despite being large unsigned values.

### Output

One signed integer result in the recovered 32-bit model:

- Literal zero for a rejected selector.
- Literal zero when a dynamic lookup encounters a null root reference.
- The inline base plus a selector-dependent displacement for selectors zero through seven.
- The exact 32-bit integer loaded from the selected dynamic-table entry otherwise.

The return interface does not tag the result’s origin. A zero table entry is indistinguishable from the explicit zero-return cases. A computed inline result could also be zero if the configured base and target address arithmetic permit it; the function does not prohibit or distinguish that outcome.

A nonzero result is not independently validated as an address, handle, or record identifier. Negative values loaded from the dynamic table are returned without rejection.

### Referenced state

This contract uses the following descriptive names, not implementation identifiers:

- **Inline base:** the base value used to compute results for selectors zero through seven.
- **Root-reference cell:** a memory cell whose contents provide the dynamic root reference.
- **Dynamic root:** the nonzero reference obtained from that cell.
- **Table-base field:** the 32-bit field located four bytes beyond the dynamic root.
- **Dynamic table:** the storage addressed by the value loaded from the table-base field.

No explicit array length, capacity, record count, or ownership metadata is consulted.

## Behavior

### 1. Reject selectors with the high bit set

The function first tests whether the selector is negative when viewed as a signed integer.

Under the recovered 32-bit model, selectors from `0x80000000` through `0xFFFFFFFF` return zero immediately. This path does not consult the dynamic root or dynamic table.

The rejection is a bit-pattern decision, not an ordinary signed-input interface. For example, an unsigned selector of `0xFFFFFFFF` takes this path.

### 2. Compute an inline result for selectors zero through seven

For each selector in the inclusive range zero through seven, the result is the inline base plus a displacement of 28 bytes per selector.

The eight displacements are:

| Selector | Displacement |
|---|---:|
| 0 | 0 bytes |
| 1 | 28 bytes |
| 2 | 56 bytes |
| 3 | 84 bytes |
| 4 | 112 bytes |
| 5 | 140 bytes |
| 6 | 168 bytes |
| 7 | 196 bytes |

This path does not read the contents of the selected inline record. It returns the computed value itself.

The stride supports an interpretation of eight records with 28-byte spacing, but does not establish their internal layout. No field within an inline record is accessed by this function.

The displacement calculation cannot overflow 32 bits for these selectors. Whether adding the displacement to the inline base crosses the address-space boundary depends on the base and target arithmetic semantics.

### 3. Resolve the dynamic root for selectors eight through `0x7FFFFFFF`

For a selector in this range, the function reads the root-reference cell and tests the loaded reference against zero.

If the reference is zero, the function returns zero. It does not proceed to read the table-base field or a table entry.

If the reference is nonzero, the supplied representation contains a second evaluation of the root-reference cell in the lookup expression. The first read’s nonzero value is not explicitly retained for the later address calculation.

Accordingly, the source-level access sequence is:

1. Read the root-reference cell for the null check.
2. If that value is nonzero, read the root-reference cell again.
3. Use the second root value to locate and read the table-base field.
4. Use the loaded table base and selector-derived displacement to read the result.

This distinction matters if the root-reference cell can change between reads. A nonzero first value does not establish that the second value is nonzero or equal to the first. The static representation does not establish volatile semantics or exact machine-load counts.

### 4. Fetch a dynamic-table entry

The table-base field is located four bytes beyond the root used for the lookup. Its loaded value supplies the base address of a table whose entries are accessed at four-byte spacing.

The dynamic-table index is the selector minus eight:

- Selector eight selects entry zero.
- Selector nine selects entry one.
- Selector fifteen selects entry seven.

The function loads one signed 32-bit integer from the selected entry and returns it unchanged. It does not dereference the returned value.

There is no visible check that:

- The second root reference is nonzero.
- The root references readable storage.
- The table-base field contains a nonzero or valid address.
- The selector-derived entry exists.
- The entry value is nonzero or points to valid storage.

### 5. Account for arithmetic width

Under 32-bit unsigned arithmetic, subtracting eight is safe for every selector admitted to the dynamic path. Multiplication by four can nevertheless wrap.

For example:

- Selector `0x40000007` produces a byte displacement of `0xFFFFFFFC`.
- Selector `0x40000008` produces a byte displacement of zero after 32-bit wrapping.
- Selector `0x7FFFFFFF` produces a byte displacement of `0xFFFFFFDC` after 32-bit wrapping.

Thus, the signed-negative rejection does not prevent displacement wraparound. In the recovered arithmetic model, selector `0x40000008` uses the same entry displacement as selector eight.

The address calculation combines the loaded table-base value with unsigned displacement arithmetic. It must not be silently replaced by unbounded arithmetic, a checked multiplication, or a length-validated lookup when describing the supplied behavior. Exact behavior on invalid resulting addresses remains target-dependent.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Rejected high-bit selector.**  
   Given selector `0x80000000`, expect zero without consulting the dynamic root or table. Selector `0xFFFFFFFF` has the same outcome.

2. **First inline record.**  
   Given selector zero and inline base `B`, expect `B`. No inline-record contents are read.

3. **Last inline record.**  
   Given selector seven and inline base `B`, expect `B + 196`, subject to target address arithmetic. The dynamic root is not consulted.

4. **Null dynamic root.**  
   Given selector eight and a root-reference read of zero, expect zero without a table-base or entry read.

5. **First dynamic entry.**  
   Given selector eight, a stable nonzero root, a valid table base, and first entry value `0x12345678`, expect that value.

6. **Later dynamic entry.**  
   Given selector eleven and stable valid storage, expect the signed 32-bit value in dynamic-table entry three, at a byte displacement of twelve from the loaded table base.

7. **Negative entry value.**  
   Given a valid selected entry containing `0xFFFFFFFF`, expect the returned signed integer to be negative one. The input rejection rule does not apply to loaded results.

8. **Zero-valued entry.**  
   Given a valid selected entry containing zero, expect zero, with no distinct indication that the lookup succeeded.

9. **Wrapped displacement.**  
   Under the recovered 32-bit wrapping model, given selector `0x40000008` and stable valid root and table state, expect selection at displacement zero, just as for selector eight. No intervening entries need to be read.

10. **Root changes between evaluations.**  
    If the first root-reference read is nonzero but the second supplies a different root, the lookup expression uses the second root. If that root is invalid, successful return is not guaranteed.
