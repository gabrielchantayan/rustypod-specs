# F-fb409197afa6

## Purpose

F-fb409197afa6 stores the low byte of an integer input in receiver storage, invokes an indirectly selected operation, and conditionally clears a second receiver byte before invoking another indirectly selected operation.

The conditional action requires both:

- The original, full-width integer input equals one.
- The receiver byte at offset 99 equals one when read after the first operation returns.

The meanings of the fields and operations are not established. Terms such as “setting,” “pending flag,” or “notification” would describe inferred intent, not required behavior.

## Behavior

### Initial byte write

The routine’s first explicit receiver access writes one byte at offset 101.

The stored value is the low eight bits of the integer input. This conversion affects the stored byte only; it does not narrow the original integer used by the later equality test.

Consequences in the recovered representation include:

- Input one stores byte value one.
- Input 257 also stores byte value one.
- Input −1 stores byte pattern 255.

Only the first of those inputs equals one in the later full-width comparison.

The routine does not read offset 99 before this write.

### First indirect invocation

After the initial byte write, the routine invokes the target selected through the receiver’s dispatch-table reference and the table entry at byte offset 20.

The logical arguments are:

1. The original receiver reference.
2. A value obtained from the first opaque global source.
3. Integer zero.

The global-sourced value’s semantic type and meaning are unknown. It is not established to be an event identifier, pointer, string, ownership token, or fixed constant.

This invocation is unconditional with respect to the integer input and offset 99. Every path that completes the preceding accesses and reaches the invocation performs it.

The initial store is ordered before the invocation. This guarantees that the routine has written offset 101 before transferring control, not that the byte remains unchanged thereafter. The operation may modify offset 101, offset 99, dispatch information, globals, or other state.

The first operation’s result has no effect on the branch outcome:

- For integer input one, the later byte read supplies the value tested against one.
- For every other integer input, the required integer-equality condition is false regardless of the operation’s result.

### Post-operation condition

After the first operation returns normally, the original full-width integer determines whether this routine reads offset 99.

If the input is not exactly one:

- The routine performs no explicit read of offset 99.
- The routine performs no explicit write to offset 99.
- No second invocation occurs.

These restrictions apply to this routine’s own accesses, not to accesses performed inside the first operation.

If the input is exactly one, the routine reads the byte at offset 99 and interprets it as an unsigned value from zero through 255.

This is a post-operation observation. The byte’s entry value is not sufficient to predict the branch because the first operation may have changed it.

Only a byte value of exactly one qualifies. Any other value, including two or 255, suppresses the conditional clear and second invocation.

### Conditional clear and second invocation

When the integer input equals one and the post-operation byte also equals one, the routine writes zero to offset 99 and then invokes the target selected through dispatch-table offset 20 again.

The second invocation receives:

1. The original receiver reference.
2. A value obtained from the second opaque global source.
3. Integer zero.

The two opaque argument sources are distinct. Their values are not known to differ. The second argument is obtained for the second invocation; it is not established as an entry-time snapshot. The first operation’s possible effects on that source cannot be disregarded.

The receiver’s dispatch-table reference and the selected target are resolved again for the second invocation. The second call therefore need not reach the same target as the first. A replacement table or changed slot installed by the first operation can affect the later selection.

The zero store precedes the second invocation. No further direct receiver write is shown afterward. The second operation may nevertheless change either receiver byte, so the clear does not establish an unconditional final value of zero.

The established sequence is:

1. Write the low input byte at offset 101.
2. Perform the first indirect invocation.
3. If the full-width input equals one, read offset 99.
4. If that read yields one, clear offset 99.
5. Perform the conditional second invocation.

- The second invocation occurs after that clear.
