# F-94d3fda99b32

## Purpose

F-94d3fda99b32 writes configuration and resource values into a destination block, constructs packed descriptors, enumerates additional resources into that block, invokes a synchronization dependency, conditionally invokes resource callbacks, and performs final cleanup.

**Established static behavior:** accesses use the evidenced 32-bit object layout, with narrower reads for descriptor fields. Selected values have bit 31 cleared. Normal completion returns the 32-bit value zero, including after the synchronization-error branch.

**Inferred intent:** the destination resembles a register or command-control block, and several values resemble addresses. Hardware identity, address-space interpretation, synchronization guarantees, and ownership conventions are not established.

A critical distinction is that one global location is read **twice** before the initial write to destination offset `0x118`. The first observation is saved for possible restoration; the second supplies the initial write. Their equality is not guaranteed.

## Interface

### Arguments and return value

The function accepts three pointers in an evidenced 32-bit layout:

| Argument | Relevant contents |
|---|---|
| Context | Dispatch-table pointer, configuration, destination and descriptor pointers, descriptor count, and embedded input records |
| Primary resource | Dispatch-table pointer and 32-bit fields at `0x74`, `0x7C`, and `0x80` |
| Alternate resource | Same relevant layout as the primary resource |

The primary resource is read unconditionally. The alternate resource is read initially only if the initial mode check selects it. A later, independent mode check can select it for callbacks.

The return value is zero whenever execution reaches the normal return. No distinct return value reports synchronization failure, enumeration termination, or cleanup results.

## Behavior

### 1. Capture configuration and resource snapshots

The function first reads the configuration values at context offsets `0x174` and `0x178`, in that order. Call these the **first configuration** and **second configuration**.

It calls F-X01 with `(0x20000, 0, 1)`.

It then reads the primary resource’s fields in this order:

1. `0x7C`;
2. `0x74`;
3. `0x80`.

Next it reads the context mode. Zero selects the primary resource; nonzero selects the alternate resource. It reads the selected resource at `0x74`, `0x7C`, and `0x80`, in that order.

In primary mode, the two resource snapshots therefore come from the same object but are separate observations. They need not match if that object changes between reads.

The context’s dispatch-table entry at byte offset `0x48`, designated F-I01, is then invoked with the context pointer.

The captured configuration values and both captured triples remain the values used by later writes. Other context fields are read later and are not established as invariant across this callback.

### 2. Write destination configuration and observe the restoration global

The following table gives the ordered destination writes. Each masked update reads the existing destination word before writing its replacement. Arithmetic and shifts below describe 32-bit results.

| Offset | Replacement value |
|---|---|
| `0xD8` | Current context field `0x0C` |
| `0xE0` | Existing word AND `0xFFFFC0FF`, OR second configuration shifted left 8 |
| `0xE0` | Existing word AND `0xFFFFFFC0`, OR first configuration |
| `0xE8` | Existing word AND `0xFFFFF001`, OR low 32 bits of second configuration × first configuration × 2 |
| `0xDC` | Current context field `0x1C` |
| `0xE4` | Existing word AND `0xFE00FFFF`, OR current context field `0x184` shifted left 16 |
| `0xE4` | Existing word AND `0xFFFFFC00`, OR current context field `0x188` |
| `0xCC` | Captured primary field `0x74`, AND `0x7FFFFFFF` |
| `0xD0` | Captured primary field `0x7C`, AND `0x7FFFFFFF` |
| `0xD4` | Captured primary field `0x80`, AND `0x7FFFFFFF` |

The function then makes **two distinct 32-bit reads of the same global location**, in this order:

1. The first observation is saved for the possible restoration near the end of the function.
2. The second observation supplies the value written to destination `0x118`.

These observations are not merged into one snapshot. Even without an intervening explicit dependency call, the supplied body does not establish that they must be equal. The saved first observation is not replaced by the second observation or by subsequent global changes.

After the initial `0x118` write, the function checks the current context mode again. If nonzero, it writes:

| Offset | Value |
|---|---|
| `0x120` | Captured selected-resource field `0x74`, AND `0x7FFFFFFF` |
| `0x124` | Captured selected-resource field `0x7C`, AND `0x7FFFFFFF` |
| `0x128` | Captured selected-resource field `0x80`, AND `0x7FFFFFFF` |
| `0x12C` | One |

If the mode is zero, these four writes do not occur; existing contents are not explicitly cleared.

The selection used for the captured triple predates F-I01. The decision to write that triple into the alternate slots follows F-I01. A callback-induced mode change can therefore make the triple’s origin differ from the current mode.

The destination pointer is obtained through the context during these accesses, rather than being captured once for this whole phase. Exact operand-evaluation order inside individual compound expressions is not established.

The OR operands are not restricted to the apparent field widths. Large configuration values can set bits outside the regions cleared by the masks.

### 3. Construct descriptors

The function captures the descriptor-buffer pointer from context `0x1C`, then calls F-X02 with that pointer and `0x140`. The meaning of that operation is unknown.

Starting at index zero, it generates descriptors while the signed index is less than the current signed count at `0x1E4`. The count is read again for each loop condition; it is not a single entry snapshot.

Each input record has a 24-byte stride. Each output descriptor has eight 32-bit words, written in increasing word order:

| Word | Construction from the current record |
|---|---|
| 0 | Byte `+1` shifted 21, OR unsigned halfword `+2` shifted 10, OR byte `+4` shifted 6, OR byte `+5` |
| 1 | Byte `+6` shifted 15, OR byte `+7` shifted 14, OR byte `+8` shifted 10, OR byte `+9` shifted 8, OR low nibble of byte `+10` shifted 4, OR low nibble of byte `+11` |
| 2 | A fresh 32-bit read from a second global location |
| 3 | Zero |
| 4 | Byte `+20`, zero-extended |
| 5 | Current context field `0x14` plus record word `+12`, reduced to 32 bits, then AND `0x7FFFFFFF` |
| 6 | Record word `+16` |
| 7 | Zero |

Byte and halfword fields are unsigned. Only the two nibble fields are explicitly masked before packing. Other contributions can overlap; they are combined by OR, not addition.

After each descriptor, the output cursor advances 32 bytes. The captured buffer pointer remains the basis for generation even if F-X02 changes context `0x1C`.

Zero or negative counts produce no descriptors, but F-X02 has already been called. No loop limit is derived from `0x140`: ten descriptors occupy that many bytes, but larger counts are not rejected.

The global supplying word 2 is read per descriptor and need not remain constant. Context `0x14` and record contents are likewise observed during generation rather than snapshotted for the entire loop.

### 4. Enumerate additional resource triples

The function captures the current destination pointer and starts enumeration at index zero.

F-aeebbea1ac53 receives an output-pointer location, the current index, and zero. A zero return enters the successful-result path:

1. Increment the index.
2. Read returned-object field `0x74`, clear bit 31, and write the current destination word.
3. Read field `0x7C`, clear bit 31, and write the next word.
4. Read field `0x80`, clear bit 31, and write the following word.
5. Advance the output cursor by 12 bytes.

The first triple starts at destination offset zero. Reads and writes are interleaved as listed; the triple is not captured in full before its first write.

The first nonzero return terminates enumeration. Its output pointer is not consumed, and different nonzero results are not distinguished.

No capacity or iteration bound is visible. Enumeration may overwrite destination fields used elsewhere if sufficiently many results are returned. Its cursor continues from the captured destination base even if a dependency changes context `0x38`.

### 5. Publish count and check synchronization

Using the destination pointer obtained through the context again, the function performs two updates at `0xE8`:

1. Existing word AND `0xF800FFFF`, OR current context count shifted left 16.
2. Existing word OR `0x88003001`.

The count is not masked to the apparent 11-bit field before insertion. Negative counts still participate in this update even when they produced no descriptors.

F-74dc25ee05bf is called with a value read from a third global location and `0x84`.

If its return is exactly `−1`, the function invokes F-I01 with the context and then F-X01 with `(0x20000, 0, 0)`. The status read described next is skipped.

For every other return value, destination `0xF4` is read. If any bit from 18 through 28 inclusive is set, the same callback and F-X01 sequence occurs. Other status bits do not select this branch.

There is no rollback, early return, or distinct final result for this branch.

### 6. Conditionally invoke resource callbacks

The function reads the context word at `0x1E8` and tests its low eight bits.

If those bits are nonzero, this phase is skipped.

Otherwise it reads the current mode and selects the primary resource for zero or the alternate resource for nonzero. It invokes that resource’s dispatch-table entry at offset `0x00`, designated F-I02, passing the resource pointer.

It then calls F-52cde97767d1 with the same selected resource pointer and zero. The first callback’s return value is unused. A mode change during F-I02 does not cause a fresh selection for F-52cde97767d1.

No ownership or lifetime guarantee follows from these calls. In particular, the evidence does not establish that F-I02 preserves the resource’s validity before the subsequent call.

### 7. Conditionally restore and finish cleanup

The function captures the current destination pointer and reads its status word at `0xF4`.

- If bit 29 is set, it skips both the `0xF0` read and restoration.
- If bit 29 is clear, it reads `0xF0`. If that word’s bit 0 is set, it writes the **saved first global observation** to `0x118`.

The restoration does not reread the global. It need not reproduce the value used by the initial `0x118` write, which came from the second observation. It can also target a different destination block if context `0x38` changed meanwhile.

F-X01 is then called unconditionally with `(0x20000, 0, 0)`. The error branch can therefore cause this tuple to be issued twice.

Finally, F-30a72d971f0e receives zero. If its result is nonzero:

1. F-c1150714b337 receives an output-pointer location and zero.
2. F-df2c7f3bb9d4 receives zero.
3. The resulting object’s dispatch-table entry at `0x04`, designated F-I03, is invoked with no explicit arguments shown.

No success check is visible before consuming that output pointer. Normal completion returns zero.

## Side effects

Direct effects comprise the ordered reads, destination writes, descriptor writes, and dependency invocations above.

Pointer snapshots differ by phase:

- Descriptor generation retains its pre-F-X02 buffer pointer.
- Enumeration retains its pre-enumeration destination pointer.
- Count publication and later checks obtain the destination pointer again.
- Restoration retains the destination pointer captured at the start of its own phase.

The restoration value has a separate lifetime: it is the first of two global observations after the primary triple writes, retained across all subsequent dependency calls.

No direct allocation or deallocation is visible. Dependencies may affect globals, context fields, resource validity, ownership, or external state; none of those effects can be assumed absent.

Invalid memory, invalid dispatch targets, nonterminating enumeration, and unusable dependency outputs have no visible recovery path.

## Acceptance examples

These are conditional static consequences, not executed tests. They assume valid storage and no unspecified interference except where explicitly stated.

1. **Distinct global observations.** If the first read of the restoration global yields `0x11111111` and the second yields `0x22222222`, the initial `0x118` write uses `0x22222222`. If restoration qualifies, it writes `0x11111111`. A later global value of `0x33333333` changes neither saved observation.

2. **Stable-global special case.** If both observations yield the same value, initial writing and restoration use equal values. That equality follows from the stated stability condition, not from a single shared read.

3. **Mode transition.** Initial mode zero followed by nonzero mode after F-I01 causes a primary-derived selected triple to be written at `0x120`–`0x128`, followed by one at `0x12C`. A later unsuppressed callback phase selects the alternate resource if mode remains nonzero.

4. **Bit clearing and descriptor arithmetic.** A resource field `0x92345678` becomes `0x12345678`. A descriptor base of `0x7FFFFFF0` plus record offset `0x30` produces word 5 equal to `0x00000020`.

5. **Packing.** Word-0 contributors `1`, `2`, `3`, and `4`, in table order, produce `0x002008C4`.

6. **Nonpositive count.** A stable count of zero or `−1` produces no descriptors but does not skip F-X02, enumeration, or count publication. A count of `−1` contributes `0xFFFF0000` after the 32-bit left shift during publication.

7. **Synchronization failure.** A return of `−1` causes F-I01 and an early shutdown call without the branch’s status read. Assuming normal continuation, the unconditional shutdown call also occurs, and the function returns zero.

8. **Restoration gate.** Status bit 29 clear and `0xF0` bit 0 set cause restoration of the first observation. Status bit 29 set prevents both the `0xF0` read and restoration.

9. **Suppression width.** A context word of `0x00000100` does not suppress callbacks because its low eight bits are zero. A value of `0x00000001` suppresses them.
