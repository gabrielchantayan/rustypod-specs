### 5. Mode-dependent byte updates

After writing the decremented counter, the routine reads the byte at offset `0x90`.

If that read equals zero:

1. It reads the first byte of the selected record and writes it to offset `0x54`.
2. It reads the second byte of the selected record and writes it to offset `0x55`.

The first read/write pair precedes the second pair. There is no visible preliminary snapshot of both source bytes. This ordering matters if source and destination storage overlap.

If the first mode read is nonzero, the routine reads offset `0x90` again and compares that second observation with `1`.

- If the second observation equals `1`, it reads the third byte of the selected record and writes it to offset `0x56`.
- Otherwise, no record byte is copied.

Thus, with stable memory, mode zero updates two destination bytes, mode one updates one destination byte, and every other mode updates none. With changing memory, the second comparison need not observe the value seen by the first comparison.

Regardless of which mode path is taken, successful completion of the nonzero-counter block ends by writing the single byte `1` to offset `0x24`.

The routine does not visibly clear that byte on the zero-counter path.
