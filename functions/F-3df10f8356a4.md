# F-3df10f8356a4

## Purpose

F-3df10f8356a4 conditionally invokes up to three destination-facing operations. It constructs a temporary value, obtains comparison results, optionally adjusts a scalar, and selects operations using signed comparisons and four flag bits.

The established behavior is the sequence of calls, field accesses, arithmetic, and gates described below. Geometric interpretations of the temporaries, fixed-point interpretations of the scalar, and accumulation semantics for the destination are inferred intent only.

The function has no explicit return value. Observable results arise through dependency calls and any effects those calls produce. One threshold branch returns before scalar adjustment or destination-facing operations.

## Behavior

### Initial construction and preparation

The first dependency call is F-a12ab64dd090, receiving, in order:

1. The first 12-byte temporary’s address.
2. The construction argument.
3. The primary-state address plus `0x30`.

F-6610e066ba3f then receives the first temporary as both arguments. Its signed 32-bit result is retained as the **initial comparison result**.

Next, F-b19479256fec is called without explicit arguments. Its returned 32-bit word is passed second to F-be1254801757, with the first temporary passed first.

The initial comparison therefore precedes F-be1254801757. Later uses of the temporary occur after that call. The initial comparison result must not be treated as a fresh measurement of the temporary’s later contents.

A provisional 64-bit value is then formed with low word `0x00010000` and an auxiliary high word associated with the preceding call boundary. The source does not establish the auxiliary word’s meaning or a reliable numerical value.

### Threshold gate and scalar source

The function reads the signed field at primary-state offset `0x68`.

If it equals `0x00b40000`, threshold processing is bypassed. The provisional low word remains `0x00010000`; the high word remains unresolved.

Otherwise:

1. F-6610e066ba3f receives the working temporary and the address at primary-state offset `0x40`.
2. Its signed 32-bit result is negated.
3. That negated result is compared with the signed 32-bit threshold at offset `0x6c`.
4. If the negated result is strictly less than the threshold, the function returns immediately.
5. Otherwise, D-01 receives the negated result first and the opaque word at offset `0x64` second. Its represented two-word result replaces the provisional value.

Threshold equality permits continuation.

The most-negative signed 32-bit comparison result is a separate unresolved negation case. Neither wrapping nor trapping behavior for its negation is established.

After this gate, the low 32 bits of the selected two-word value become the **current scalar**. The high 32 bits remain relevant if computed adjustment is selected.

### Optional scalar adjustment

The function reads flag bit 3, mask `0x08`, at offset `0xa0`.

If set, the word at offset `0xa4` becomes the adjustment operand. The field at `0x3c` and the computed-adjustment arithmetic are skipped.

If bit 3 is clear, the signed field at offset `0x3c` is read:

- Zero: skip adjustment entirely.
- Nonzero: compute an adjustment operand.

The computed path calls F-6caa6aca66a2 with the initial comparison result first and the high word of the selected two-word value, interpreted as a signed 32-bit value, second.

Its signed 32-bit result is multiplied by the signed field at `0x5c`, producing a signed 64-bit product. Separately, the initial comparison result is multiplied by the signed field at `0x60`, producing another signed 64-bit product. Products of two signed 32-bit values fit in signed 64-bit storage.

For each product, the represented bit manipulation selects bits 16 through 47 as a 32-bit word. This is bit extraction, not an established rounded or saturating conversion.

**Both extracted expressions have unsigned 32-bit type.** Each combines its pieces with a bitwise OR containing an unsigned operand. Consequently:

- The field read at `0x58` participates in the addition after conversion to unsigned 32-bit representation.
- Both additions are unsigned 32-bit additions.
- The sum is reduced modulo `2^32`.
- These additions are not unresolved signed-overflow cases.

F-dc13818ac82a receives that resulting 32-bit quantity and supplies the adjustment operand.

The representation uses signed left shifts when assembling the extracted words. Their portable signed-language semantics are not established; that issue is distinct from the established unsigned type and modulo behavior of the subsequent additions.

Whenever an adjustment operand is selected or computed, F-e713aa9f4f3b receives the current scalar first and the adjustment operand second. Its returned 32-bit word replaces the current scalar.

Adjustment precedes all destination-operation gates. It can occur even when every destination operation is disabled.

### First destination operation

If clear, F-b7c53ba6f3b7 receives:

1. The destination argument.
2. The primary-state address plus `0x70`.

Only two explicit arguments are established at this call site. No explicit scalar argument is shown.

### Outer gate for the remaining operations

The next condition reads flag bit 1, mask `0x02`.

- If bit 1 is clear, the flag condition succeeds without reading bit 2 for this particular condition.
- If bit 1 is set, flag bit 2, mask `0x04`, is read separately. The flag condition succeeds only if bit 2 is clear.

If both tested disable bits are set, no further comparison or destination operation occurs.

Otherwise, F-6610e066ba3f receives the comparison argument first and the working temporary second. Only a strictly positive signed 32-bit result permits entry into the remaining processing. Zero and negative results skip both remaining operations.

These are conditional reads, not a single entry-time flags snapshot.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless a case states otherwise, assume valid storage, normal dependency returns, and no dependency mutation of relevant fields or flags.

1. **Threshold rejection.**  
   The field at `0x68` differs from `0x00b40000`; the threshold comparison returns `5`; the threshold at `0x6c` is `-4`. Negation gives `-5`, which is strictly less than `-4`. Initial construction and preparation occur, but adjustment and all destination calls are skipped.

2. **Threshold equality.**  
   With the same comparison result and threshold `-5`, processing continues. D-01 receives `-5` and the word at primary-state offset `0x64`.

3. **Sentinel bypass.**  
   The field at `0x68` equals `0x00b40000`. The threshold comparison, threshold-field read, and threshold-site D-01 call are skipped. The scalar low word starts as `0x00010000`; its accompanying high word is not established.

4. **Unsigned adjustment wrap.**  
   Computed adjustment is enabled. F-6caa6aca66a2 returns `65536`, the field at `0x5c` is `1`, the field at `0x60` is `0`, and the field at `0x58` is `-1`. The extracted product words are `1` and `0`. Adding unsigned `0xffffffff` yields `0` modulo `2^32`. F-dc13818ac82a receives the zero word; this is not a signed-addition overflow case.

5. **Everything disabled without adjustment.**  
   Flags are `0x07`, and the field at `0x3c` is zero. After any accepted threshold processing, adjustment and all destination operations are skipped. No comparison using the comparison argument occurs.

6. **Adjustment despite disabled destinations.**  
   Flags are `0x0f`. The explicit operand at `0xa4` is read, and F-e713aa9f4f3b is called before all destination operations are skipped.

7. **Nonpositive outer comparison.**  
   All destination-disable bits are clear. The first operation occurs. An outer comparison result of zero or a negative value prevents the second operation and all derived-value processing.

8. **Nonpositive inner comparison.**  
   All destination-disable bits are clear, and the outer comparison is positive. The first and second operations occur, followed by construction and processing of the second temporary. A nonpositive inner comparison prevents the secondary-state field read, final D-01 call, and third operation.

9. **Full path.**  
   All destination-disable bits are clear, the threshold gate permits continuation, and both later comparisons are positive. All three destination calls occur in order. Only the third has an established explicit scalar argument.

10. **Flags changed by an earlier call.**  
    The first destination call changes bit 1 from clear to set while bit 2 remains clear. The outer flag gate still permits comparison through its separate bit-2 test. If that comparison is positive and bit 1 remains set, the second destination operation is skipped. An entry-time flags snapshot would not reproduce this behavior.
