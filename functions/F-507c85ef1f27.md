# F-507c85ef1f27

## Purpose

F-507c85ef1f27 constructs a multiword square from an input sequence of unsigned 32-bit words. It first writes each word’s unsigned 64-bit square into successive output slots, then accumulates doubled products between distinct input words.

**Established behavior:** the routine operates on a 16-bit input count, input words, an output word buffer, and a 16-bit output count. It does not allocate storage, return a status, or check buffer capacity.

**Inferred intent:** on a little-endian target, with stable, nonoverlapping storage and an input count below 32,768, the input represents a nonnegative integer in least-significant-word-first order. The output represents its square in the same order.

The distinction matters. The supplied implementation accepts all 16-bit input counts, but its final output-address and count calculations discard bit 15 of that count. Consequently, the conventional squaring interpretation does not provide a safe general contract for counts of 32,768 or greater.

## Behavior

### Empty input

The function reads the input count once.

If that count is zero, it writes zero to the output count and returns. It does not initialize, clear, or inspect the output buffer. A preexisting output buffer and its contents therefore remain untouched on this branch.

### Diagonal initialization

For a nonzero count, the function loads the input buffer address, then the output buffer address.

It traverses the input words in increasing index order. For each word, it forms an unsigned 32-by-32-bit product of the word with itself and stores the resulting 64-bit value into the corresponding consecutive 8-byte output slot.

Thus, before any cross-product accumulation, the entire nominal \(8n\)-byte output region has been written. Previous output-buffer contents are not used to seed the result.

On a little-endian target, this establishes:

- The low half of input word \(i\)’s square at output word \(2i\).
- The high half at output word \(2i+1\).

The 64-bit store layout is significant. The subsequent accumulation uses 32-bit accesses, so a different ordering of the two halves would not support the same mathematical interpretation.

### Cross-product accumulation

After diagonal initialization, the function reloads the input buffer address for an increasing traversal of rows.

For each input index \(i\) from zero through \(n-2\):

1. It reads input word \(i\) as the fixed multiplicand for that row.
2. It clears the row’s carry state.
3. It reloads the input and output buffer addresses used to establish that row’s traversals.
4. It visits input indices \(j=i+1\) through \(n-1\), in increasing order.
5. For each such pair, it adds twice the unsigned product of input words \(i\) and \(j\), together with the incoming carry, beginning at output word \(i+j\).
6. It propagates any remaining carry through increasing output-word addresses.

Under the stable-memory preconditions, this accounts for each distinct pair exactly once, with the factor of two required by squaring:

\[
\left(\sum_{i=0}^{n-1} a_i B^i\right)^2
=
\sum_{i=0}^{n-1} a_i^2 B^{2i}
+
\sum_{0\le i<j<n} 2a_i a_j B^{i+j},
\qquad B=2^{32}.
\]

This identity describes the aggregate behavior, not an additional normalization step.

### Arithmetic widths and carries

Input-word multiplication is unsigned and produces a full 64-bit product. Doubling such a product can require 65 bits. The implementation retains that extra information through explicit carry handling rather than by keeping only a doubled 64-bit product.

For stable memory, one cross-product step can be described by:

\[
T=W+C+2P,
\]

where:

- \(W\) is the current unsigned 32-bit output word.
- \(C\) is the incoming carry represented by two 32-bit components.
- \(P\) is the unsigned 64-bit product for the current pair.

The step writes \(T \bmod 2^{32}\) and carries \(\lfloor T/2^{32}\rfloor\) forward.

The implementation uses 32-bit modular additions, explicit addition-carry indicators, and corrections derived from the top bits of the product halves. Those corrections preserve the bits lost when the halves are doubled. Although signed temporary values appear in the supplied representation, the product is not a signed multiplication and negative input limbs are not part of the interface.

After the last product in a row, carry propagation adds the carry’s low component to the next output word, writes that word, and advances. The carry’s upper component and any addition overflow form the next carry. Propagation stops only when both carry components are zero.

The propagation phase performs at least one output-word read and write per row, even if the incoming carry is already zero.

For valid, stable inputs under the intended representation, the square fits within \(2n\) words. The routine does not independently enforce an output boundary during propagation.

### Loop-index masking

The traversal counters are updated using a mask that clears bit 16. For the 16-bit input counts and ordinary terminating traversals shown here, this does not restrict processing to the lower 15 bits.

In particular, a count of 32,768 does not cause the diagonal and cross-product phases to process zero words. The loss of bit 15 occurs later, in finalization.

### Final output word and count

After accumulation, the function computes:

\[
m=n \mathbin{\&} 32767.
\]

It then accesses a 32-bit word at output-buffer byte offset:

\[
8m-4.
\]

It adds the remaining low carry component to that word and writes the word back. On an ordinarily completed path, this carry is zero: it was initially zero and every row’s propagation terminates only after clearing it. The final access is therefore still an observable read and write even when it does not change the value.

The initial output-count bit pattern is \(2m\). If \(m\ne0\) and the just-written word equals zero, the count is reduced by one. The resulting 16-bit pattern is stored in the output descriptor.

For \(1\le n<32{,}768\), this means:

- The examined word is output word \(2n-1\).
- The stored count is \(2n\) when that word is nonzero.
- The stored count is \(2n-1\) when that word is zero.

Only one word is trimmed. The function does not scan backward for the highest nonzero word.

Consequently, an all-zero nonempty input produces a zero-valued buffer but a nonzero output count of \(2n-1\). A nonempty input containing leading zero words is likewise not fully normalized.

For larger counts:

- At \(n=32{,}768\), finalization accesses the 32-bit word immediately before the output buffer and stores a count of zero.
- At \(n>32{,}768\), finalization examines an earlier word selected by \(m\), not the highest word written during diagonal initialization.

These are established consequences of the address calculation, not supported large-input semantics.

## Side effects

The routine writes directly into caller-owned storage.

For nonempty input, observable operations occur in this order:

1. Read the input count.
2. Load the initial input and output buffer addresses.
3. Write all diagonal 64-bit slots in increasing address order.
4. Perform increasing cross-product rows, with increasing product indices and increasing carry-propagation addresses within each row.
5. Reload the output buffer address for finalization.
6. Read and rewrite the final selected 32-bit word.
7. Write the output count last.

The output count is not an in-progress indicator. Its previous value remains present while buffer construction proceeds.

No allocation, deallocation, ownership transfer, callback, or explicit global-state access is present in the supplied body. No memory is released.

There is no explicit error reporting or recovery. Invalid pointers, insufficient capacity, unsuitable alignment, or invalid address arithmetic may cause target-dependent faults or corruption. No particular fault behavior is established.

The descriptors and input data must not be treated as atomically snapshotted. Buffer addresses are reloaded at several stages. The supplied representation also contains repeated reads of some input and destination words while constructing products and carries. Concurrent modification, volatile storage, and memory-mapped I/O are outside the established mathematical contract; exact physical load counts are not established.

Overlapping buffers are not protected. In particular, diagonal output writes can overwrite input words needed later. No overlap detection or temporary copy is present.

## Acceptance examples

These examples are conditional static expectations. **No runtime tests have been performed.**

Unless stated otherwise, examples assume little-endian word layout, stable nonoverlapping buffers, valid alignment, sufficient capacity, and least-significant-word-first input.

### Empty input leaves buffer contents alone

Given an input count of zero:

- The output count becomes zero.
- Neither buffer pointer is loaded.
- Output-buffer contents are unchanged.

### One-word square with a zero high half

Given input words \([3]\):

- Output words become \([9,0]\).
- The output count becomes 1.
- The high output word is still written, even though it is excluded by the count.

### One-word square requiring both output words

Given input words \([4{,}294{,}967{,}295]\):

- Output words become \([1,4{,}294{,}967{,}294]\).
- The output count becomes 2.

This exercises a full-width unsigned product.

### Cross-product placement

Given input words \([1,1]\), representing \(1+2^{32}\):

- Output words become \([1,2,1,0]\).
- The output count becomes 3.

The doubled cross product appears at output word 1, between the two diagonal contributions.

### Carry propagation

Given two input words both equal to \(4{,}294{,}967{,}295\), representing \(2^{64}-1\):

- Output words become \([1,0,4{,}294{,}967{,}294,4{,}294{,}967{,}295]\).
- The output count becomes 4.

The expected value is \(2^{128}-2^{65}+1\).

### No complete zero normalization

Given input words \([0,0]\):

- All four output words become zero.
- The output count becomes 3, not zero.

Given input words \([1,0]\):

- Output words become \([1,0,0,0]\).
- The output count again becomes 3, not 1.

### Count representation boundary

Given \(n=16{,}384\):

- If the highest output word is nonzero, the count field receives the bit pattern 32,768.
- If it is zero, the count field receives 32,767.

The former is negative when interpreted as a signed 16-bit value. Consumers must not assume every result count is a positive signed value.

### Large-count finalization hazard

Given \(n=32{,}768\), and assuming execution reaches finalization:

- The routine reads and writes four bytes immediately before the output buffer.
- The output count is set to zero.

A contract that merely supplies \(8n\) writable output bytes does not make this case safe.
