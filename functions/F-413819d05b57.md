# F-413819d05b57

## Purpose

F-413819d05b57 attempts to obtain an entry associated with a caller-supplied context, checks a one-byte entry discriminator, and conditionally publishes a four-byte value and an entry handle through two output destinations.

An accepted entry has two distinct handling paths:

- A zero secondary byte selects additional processing, propagates a dependency’s four-byte result, and writes zero to the handle output.
- A nonzero secondary byte selects direct handle publication and returns zero.

A missing entry produces return value 39. An entry whose discriminator is not exactly 1 produces return value 26.

These are established branch outcomes, not established meanings of a larger error-code system. Describing the entry as a queued item, resource, message, or owned object would require evidence not supplied here.

### Preconditions

For defined execution, each memory access actually reached must be valid at the moment it occurs. In particular:

- The discriminator byte must remain readable after the first nonnull-path dependency returns.
- On an accepted entry, the four-byte field at offset 12 and the value destination must support the corresponding read and write.

## Behavior

### Lookup and null outcome

The first observable dependency invocation is F-a37cf1fc8c44, receiving:

1. The context.
2. The context plus 156.

Its result is interpreted as an entry pointer.

If that result is null, the function immediately returns 39. It makes no direct entry reads or output writes and does not invoke the subsequent dependencies.

The lookup’s internal memory accesses and side effects are unknown. The null outcome therefore does not imply that the entire call is side-effect-free.

### Nonnull entry and preliminary dependency

For a nonnull entry, the function prepares a default return value of zero and invokes F-U01. No arguments are explicitly supplied to F-U01 in the visible call.

Only after F-U01 returns does the function read the entry’s discriminator byte at offset 0. The contract therefore depends on the entry state at that later read, not necessarily its state when the lookup returned.

F-U01 is a local opaque identifier for an otherwise unmapped dependency. Its name here does not establish a role such as locking, reference acquisition, or initialization.

### Rejected discriminator

If the discriminator is anything other than exactly 1:

- The pending return value becomes 26.
- The function does not directly read the secondary byte or the four-byte value field.
- It makes no direct write through either output destination.
- It invokes F-U02 with the context.
- On normal return from F-U02, it returns 26.

This is an exact byte comparison, not a general nonzero test. For example, discriminator values 2 and 255 take this rejection path.

### Accepted discriminator and value publication

If the discriminator equals 1, the function reads four bytes at entry offset 12 and writes that value through the value destination.

The secondary byte at offset 1 is read **after** this output write. This ordering is observable when storage overlaps or when another agent can modify the entry.

In particular, the branch is not selected from a previously captured copy of the secondary byte. If the value destination overlaps the entry’s secondary byte, the just-written value can affect which path is taken. Whether such overlap is valid under the original program’s language and ABI rules is not established; the visible operation order remains significant.

### Zero-secondary-byte path

If the secondary byte is zero when read, the function performs these observable actions in order:

1. Invokes F-029f0df8d35a with the selected entry.
2. After that call returns, invokes F-2db98b0446c5 with the context, the context plus 56, and the same selected entry pointer.
3. Adopts the four-byte result of F-2db98b0446c5 as its pending return value.
4. Writes four-byte zero through the handle destination.
5. Invokes F-U02 with the context.
6. Returns the pending result if F-U02 returns normally.

The zero handle write occurs regardless of whether the result from F-2db98b0446c5 is zero or nonzero.

The same pointer value is supplied to both entry-processing dependencies. There is no visible refresh or replacement of that pointer between calls. The first dependency’s ownership and lifetime effects are unknown; it must not be assumed to free the entry, preserve it, or transfer it to a particular owner.

### Nonzero-secondary-byte path

If the secondary byte is nonzero when read:

- The selected entry’s pointer representation is written through the four-byte handle destination.
- Neither F-029f0df8d35a nor F-2db98b0446c5 is invoked.
- The pending return value remains zero.
- F-U02 is invoked with the context.
- The function returns zero if that dependency returns normally.

Every nonzero secondary-byte value selects this path. No further classification is visible.

### Abnormal execution

The established return and sequencing rules assume the invoked dependencies return normally and the required memory accesses succeed.

There is no visible recovery, rollback, exception handling, or guaranteed final invocation of F-U02 after an earlier abnormal exit. In particular, the value output may already have been written before a later operation fails.

- The zero-secondary-byte path leaves zero there before F-U02 runs.
- The nonzero-secondary-byte path leaves the entry pointer representation there before F-U02 runs.

There is no direct entry-memory write shown, except that an output destination may alias entry storage. Such effects may occur inside dependencies but cannot be assigned to them from this evidence alone.

## Acceptance examples

These are conditional contract examples derived from static evidence. They are not reports of executed tests. Unless stated otherwise, assume valid accesses, ordinary disjoint storage, normally returning dependencies, and no dependency modification of the relevant outputs or entry fields.

1. **Missing entry.** If F-a37cf1fc8c44 returns null, the result is 39. Neither output is directly written, and no later dependency is invoked.

2. **Discriminator is zero.** If the lookup returns an entry and its discriminator is zero after F-U01 returns, the result is 26. F-U02 is invoked; neither processing dependency is invoked.

3. **Discriminator is nonzero but not accepted.** A discriminator of 2 still returns 26. Acceptance requires exactly 1.

4. **Accepted entry with a nonzero secondary byte.** If the discriminator is 1, the secondary byte is 7, and the field at offset 12 holds 0x12345678, the value destination receives 0x12345678 and the handle destination receives the selected entry pointer representation. The result is zero.

5. **Accepted entry with successful processing.** If the discriminator is 1, the secondary byte is zero, and F-2db98b0446c5 returns zero, the value field is published first, both processing dependencies run in their specified order, the handle destination receives zero, and the result is zero.

6. **Processing returns a nonzero result.** Under the preceding conditions, if F-2db98b0446c5 returns 0x80000005, that exact four-byte result is returned. The handle destination is still written with zero.

7. **Identical output destinations.** If both output parameters designate the same valid four-byte location, the value publication is subsequently overwritten by the handle publication or zero write. This assumes that location does not also affect the entry’s secondary byte.

8. **Entry changed by the preliminary dependency.** If the lookup returns an entry whose discriminator initially equals 1, but F-U01 changes it to 2 before returning, the subsequent visible test rejects it and selects return value 26.
