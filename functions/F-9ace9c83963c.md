# F-9ace9c83963c

## Purpose

The supplied static representation establishes the accesses and their dependencies, not an application-level purpose. Graph manipulation is a plausible interpretation, not an established invariant.

### Computed-address tail

G1 is read as a represented 32-bit signed integer. Primary-node `0x74` is then read as the **tail address value**.

At the sum of the tail address value and primary-node address, a halfword containing the tail address value’s low 16 bits is written. At twice the final-child address, a halfword containing G1’s low 16 bits is written.

One byte is then read at the sum of the final link and primary-node address. It is interpreted as a plain character and converted to a **32-bit unsigned integer**, called the **converted byte value** below.

At the sum of G1 and the tail address value, the tail address value’s low halfword is written. The earlier halfword store at tail address value plus primary-node address repeats.

A word containing `0x00000045` is written at the numeric address obtained by adding `0x45` to the converted byte value. **This addition uses unsigned 32-bit arithmetic, modulo \(2^{32}\).** That arithmetic rule is established independently of whether the resulting address permits a word access.

G2 is read as a represented 32-bit signed integer, then G3 as a word, then primary-node `0x44` as a word.

A byte containing `0x44` is written at the converted byte value plus `0x44`. **This addition also uses unsigned 32-bit arithmetic, modulo \(2^{32}\).**

At twice G2, the complete captured G3 word is written. At retained link plus G2, G2’s low halfword is written.

The dependency is then invoked with:

- The converted byte value bitwise-ORed with `0x44`, as a 32-bit unsigned value.

The unsigned additions above must not be conflated with the other tail expressions. The address sums involving represented signed integers, the signed doublings, and conversion of numeric results to usable addresses have separate uncertainties.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

- **Input truncation:** For second input `0x12345678`, explicit byte extractions yield `0x78`; full-width stores retain `0x12345678` at the time of those stores. Later overlap can change the stored bytes.

- **Overlapping widths:** If A-at-`0x50` is captured as `0x11223344`, its subsequent word store at A-at-`0x10` replaces four bytes, including the earlier byte at `0x11`. The resulting byte at `0x11` depends on endianness.

- **Transient fourth input:** With nonoverlapping relevant regions, the fourth input is written at secondary-node `0x11` and subsequently replaced. Its absence from final memory does not establish absence of the intermediate write.

- **Repeated accesses:** A transaction-level interpretation retains both consecutive writes to primary-node `0x0d` during deep traversal. Whether an executable exposes them as separate externally observable transactions depends on the memory and execution model.

- **Unsigned plain-character case:** If the tail byte is `0xff` and plain character is unsigned, the converted byte value is `0x000000ff`. The word-store numeric address is `0x00000144`; the byte-store numeric address is `0x00000143`; the first dependency argument is `0x000000ff`.

- **Signed plain-character wraparound:** If the tail byte is `0xff` and plain character is signed, it represents negative one before unsigned conversion. The converted value is `0xffffffff`. Modulo-\(2^{32}\) addition produces word-store numeric address `0x00000044` and byte-store numeric address `0x00000043`. The first dependency argument is `0xffffffff`. The arithmetic results are established under this signed-character condition; accessibility of those addresses is not.

- **Signed plain-character without wraparound:** Under signed plain-character interpretation, tail byte `0x80` converts to `0xffffff80`. Its word- and byte-store numeric addresses are `0xffffffc5` and `0xffffffc4`. Under unsigned interpretation they are `0x000000c5` and `0x000000c4`.

- **Late invalid destination:** If the last computed halfword destination is inaccessible, earlier accesses may already have modified memory. No visible rule requires rollback or invocation of the dependency after that failure.
