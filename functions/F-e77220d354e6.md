# F-e77220d354e6

## Purpose

F-e77220d354e6 reads a 32-bit word from a designated global data location and writes the value read to the beginning of caller-supplied storage. It then obtains a reference address through a dependency and, conditionally, prepares state, updates two links, and processes a pointer-linked chain.

The global’s location is fixed in the supplied representation; its contents are not established as constant. Different invocations can therefore write different values to the caller’s storage.

The function returns a packed 64-bit result. The lower 32 bits encode an address derived from the reference-acquisition dependency’s result. The upper 32 bits come from a local scratch word initially populated with the second input and potentially overwritten on the conditional path.

These are established operations, not evidence that the function is a constructor, destructor, allocator, or ownership-transfer operation. In particular, the chain-processing calls do not establish that any storage is released.

## Behavior

### Global read, initial write, and reference acquisition

The first visible data access is a 32-bit read from the designated global data location. The function then writes that read value to offset zero of the first input’s storage.

This order matters:

1. The global value is read.
2. The value read is written to the caller’s storage.
3. Separate scratch words are initialized from the second, third, and fourth inputs.
4. F-fd7c65715716 is called.

The first write is therefore not the first observable operation. It follows a global read, and both occur before scratch initialization or the dependency call.

The stored value is the value obtained by that read. There is no visible second global read supplying the store, no numeric constant established for the value, and no guarantee that the global remains unchanged afterward. If the destination aliases the source location, the source read still precedes the destination write; alias legality is otherwise unresolved.

F-fd7c65715716 receives the first input’s address plus 32 bytes. It receives an address, not the contents at that offset.

Its return value becomes the reference address for all subsequent relative accesses and the lower return component. The function does not check that result for zero or any other validity condition before deriving addresses from it.

The dependency executes after the initial write and may observe or modify accessible state. The supplied representation provides no dependency preservation guarantee.

### Conditional-path selection

The function reads the selected-record slot at reference address minus 12 bytes.

If that word is zero, the function bypasses the entire conditional path:

- F-3e95f52e82a5 is not called.
- No link update is performed.
- The chain-head slot is not read or drained by this function.
- F-ff1bdc376dcd is not called.
- The upper return word is the original second input.
- The lower return word is the reference address minus 32 bytes.

A nonzero chain head does not independently trigger processing. The initial selected-record test controls whether chain processing is reached.

### Scratch preparation

If the initial selected-record test is nonzero, the function reads that slot again. It uses the resulting address to read the record’s 32-bit word at offset +8 and stores that word in the scratch storage initially populated from the third input.

The selected-record slot is then read once more. This address-valued word replaces the scratch value initially populated from the second input.

Consequently, immediately before preparation:

- The original third input has been replaced by a selected record’s +8 word.
- The original second input has been replaced by a selected-record address.
- The scratch word initialized from the fourth input has not been directly overwritten.

With stable memory, both record-related values correspond to the same selected record. The repeated reads do not establish an atomic snapshot. If the selected-record slot changes between accesses, the +8 value and the copied address can come from different selections. No intervening nonzero check protects the dereference used for the +8 read.

### Preparation call

F-3e95f52e82a5 receives four addresses, in this order:

1. Address of the scratch word initialized from the fourth input.
2. Address of the chain-head slot.
3. Address of the scratch word now holding the selected record’s +8 value.
4. Address of the scratch word now holding a selected-record address.

The three scratch addresses expose local storage for the current invocation. The chain-head address identifies the actual referenced slot.

No return value from this call is visibly used. The dependency’s effects are unknown: it may modify the supplied scratch words, the chain head, or other accessible state. No preservation of the selected-record or secondary-link slots is established.

The final contents of the fourth argument’s target are especially significant: that scratch word later supplies the upper return word. The other two scratch words do not directly contribute to the packed result.

### Link update

After preparation returns, the selected-record slot is read again. The newly obtained address is retained for the following update:

1. Read the current secondary-link word.
2. Write that word to offset +12 of the newly selected record.
3. Write the newly selected record’s address into the secondary-link slot.

The record-field write precedes the slot write.

This uses the post-preparation selection, not necessarily the record used to prepare the scratch arguments. The function does not test the reloaded selection for zero. If preparation clears the selected-record slot, the function still attempts the derived +12 access.

With valid, stable, nonoverlapping storage, the update resembles inserting the selected record at the front of a linked structure. That is inferred intent; the established behavior is the ordered read and two writes.

Aliasing can affect the resulting contents. The representation does not establish that the record field and referenced slots occupy distinct storage.

### Chain processing

After the link update, the function repeatedly reads the chain-head slot. A zero word ends processing. A nonzero word becomes the current element address.

For each current element, the function:

1. Reads its next-element word at offset +0.
2. Writes that word into the chain-head slot.
3. Reads its words at offsets +8 and +4 for a dependency call.
4. Calls F-ff1bdc376dcd with the +8 word, the +4 word, and zero.
5. Calls F-ff1bdc376dcd with the remembered current element address, one, and zero.
6. Reads the chain-head slot again to determine continuation.

The current element is removed from the head before either processing call. Both field values are obtained before the first call, but their relative read order is not established.

The second call uses the remembered element address, not a newly loaded chain head. No element-field dereference is visible between the two calls.

Either dependency call may affect accessible state. Continuation therefore follows the chain-head slot as read after both calls, not necessarily the successor written before them.

There is no visible iteration bound or cycle detection. Termination requires dependency calls to return and the chain-head slot eventually to read as zero.

### Result assembly

After bypassing or completing the conditional path, the function concatenates the final second-input scratch word with the reference address reduced by 32 bytes.

It does not reload the selected-record or secondary-link slot to obtain the upper result. The retained reference address supplies the lower component even if a dependency has changed related memory.

## Side effects

### Direct accesses and writes

The unconditional opening effects are:

- A 32-bit read from the designated global data location.
- A 32-bit write of that read value to the first input’s storage.
- Initialization of three local scratch words.
- One call to F-fd7c65715716.

The function has no separate explicit write to the global source. However, the initial destination may alias it, and dependency effects are unknown.

On the initially nonzero selected-record path, direct effects also include:

- Overwriting two scratch words.
- Passing writable scratch and chain-head addresses to preparation.
- Writing the selected record’s +12 field.
- Writing the secondary-link slot.
- Replacing the chain-head word once per processed element.

### Ownership and lifetime

The paired processing calls are compatible with resource cleanup followed by element disposal, but that interpretation does not establish release behavior. Neither call may be specified as freeing memory without additional evidence.

The local scratch words exist during this invocation. Passing their addresses does not establish a valid right for a dependency to retain and dereference those addresses after their lifetime ends.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Each assumes valid accesses, returning dependencies, and no unmentioned interference or aliasing.

### Global contents vary between invocations

Suppose the designated global holds 0x11223344 when one invocation performs its opening read. That invocation writes 0x11223344 to the first input’s storage before scratch initialization and reference acquisition.

If the global instead holds 0x55667788 when another invocation performs its opening read, that invocation writes 0x55667788. A contract requiring the same numeric value on both invocations would be unsupported.

### Preparation replaces the selected record

### One chain element

Suppose the chain head identifies one element with a zero next word, a +4 word of 7, and a +8 word of 0x2000. Neither processing call changes the head.

The function first writes zero to the head. It then calls F-ff1bdc376dcd with 0x2000, 7, and zero, followed by a call with the element address, one, and zero. The next head read ends processing.

### Processing replaces continuation

An implementation that follows only a previously cached successor would not match this behavior.
