# F-8c16999c4aaa

## Purpose

F-8c16999c4aaa performs a conditionally selected bulk operation or a repeated advance-and-process operation on a 32-bit-addressed structure.

Established behavior includes:

- Writing a context-associated address to a caller-provided output location before invoking any dependency.
- Testing two boundary-like values through F-d5d901ed9cd8.
- Taking a bulk path only when both preliminary tests return nonzero and a context state word is nonzero.
- Otherwise repeatedly capturing a word from an iterator-like input, advancing that input, invoking F-d1bb3c5047e2, and updating the output location.
- Returning a 64-bit value composed from two 32-bit words. The meanings of those words differ between the bulk and iterative paths.

The apparent intent is to process a range, with an optimization for a complete nonempty range. The context-associated object resembles a sentinel or header because the bulk path clears one of its fields and makes two others self-referential. These interpretations are inferred, not requirements established by the available evidence.

## Interface

### Inputs

The function receives four arguments:

| Argument | Established representation | Required accessibility |
|---|---|---|
| Output location | Address of a writable 32-bit word | Written immediately and subsequently on some paths |
| Context | 32-bit address | Fields at byte offsets `0x10` and, conditionally, `0x14` are accessed |
| First position | Address of a 32-bit word, also passed to dependencies | Directly read on each iterative-path pass; dependencies may read or modify it |
| Second position | Opaque 32-bit argument | Forwarded to F-d5d901ed9cd8; its interpretation is unknown |

The argument names above describe their observed roles, not a recovered public API.

The first position is not passed identically to every dependency. F-d5d901ed9cd8 receives its address; F-2b3097eaee8e also receives that address; F-d1bb3c5047e2 instead receives the address of a temporary containing the word captured from it.

All listed fields are four bytes wide.

**Context**

| Byte offset | Observed use |
|---|---|
| `0x10` | Address of an associated header-like object |
| `0x14` | Nonzero gate for the bulk path; explicitly cleared on that path |

**Header-like object**

| Byte offset | Observed use |
|---|---|

A tree root, leftmost link, rightmost link, and element count are plausible interpretations of these fields. Their semantic types are not established.

### Result

The result is a 64-bit concatenation:

- Bits 63–32 contain a selected 32-bit result word.
- Bits 31–0 contain a carried 32-bit address-like word.

This is bit concatenation, not arithmetic addition. No sign extension is part of the observed construction, and no memory byte order for a stored result is established.

The function also communicates through the caller’s output location. The 64-bit return must not be replaced by that single output word: the two interfaces carry different information.

### Preconditions

Valid execution requires that every memory location actually accessed on the selected path be accessible with the required permissions. Dependency-specific preconditions are unknown.

No null checks, bounds checks, object-lifetime checks, or alias checks are established. Distinct input regions are not explicitly required, but aliasing can change later observations because writes precede some reads.

## Behavior

### 1. Initial output and boundary snapshot

Before any dependency call, the function:

1. Reads the header address from context offset `0x10`.
2. Writes that address to the output location.
3. Reads context offset `0x10` again.
4. Reads the 32-bit field at offset `0x08` from the address obtained by that second context read.
5. Saves that field in a temporary.

The second context read is significant. The function does not establish that the header address used for the snapshot equals the address initially written to the output. In particular, aliasing between the output location and context storage can affect the second read.

The function also initializes two carried words:

- A context/result word initially containing the context address.
- An address-like word initially containing the output-location address.

It saves the first-position address in another temporary, although that temporary is overwritten before its address is used.

### 2. Preliminary first-position test

F-d5d901ed9cd8 is called with:

1. The first-position address.
2. The address of the temporary holding the header’s offset-`0x08` snapshot.

Any nonzero return permits the second preliminary test. A zero return bypasses that test and proceeds to the iterative path.

The dependency receives writable-address-shaped arguments. Its mutation behavior is unknown; this contract does not assume that the snapshot, first position, context, or other reachable state remains unchanged.

### 3. Preliminary second-position test

When the first preliminary result is nonzero, the function reloads context offset `0x10` into a temporary and calls F-d5d901ed9cd8 with:

1. The second-position argument.
2. The address of that temporary.

If this call returns zero, the function proceeds to the iterative path without reading context offset `0x14` for the bulk-path gate.

If it returns nonzero, the function reads context offset `0x14`. A zero field value selects the iterative path; any nonzero field value selects the bulk path.

These preliminary decisions use **nonzero**, not **exactly one**. This differs from the iterative termination rule.

### 4. Bulk path

The bulk path is selected only after both preliminary calls return nonzero and the subsequently read context state word is nonzero.

First, F-a19f2f4d8aef is called with:

1. The context address.
2. The 32-bit value at offset `0x04` of the header currently obtained from context offset `0x10`.

Its return value is not used.

After that call returns, the function performs these direct writes in order:

1. Set the current header’s offset-`0x08` field to a header address read from context offset `0x10`.
2. Clear the current header’s offset-`0x04` field.
3. Set the current header’s offset-`0x0c` field to a header address read from context offset `0x10`.
4. Clear context offset `0x14`.
5. Reload context offset `0x10` and write that value to the output location.

The header is not retained in one pre-call snapshot for these operations. Context offset `0x10` is read again after the dependency call and across the subsequent assignments. Therefore, a contract must not require these writes to target the original header when the dependency or aliasing changes that field.

The relative evaluation order of the address and value reads within an individual assignment is not separately established.

The function then returns:

- High word: the final header address loaded for the output write.
- Low word: the saved output-location address.

No iterative-path dependency is invoked after this branch is selected.

### 5. Iterative path

The function calls F-d5d901ed9cd8 with the first-position address and the second-position argument.

A result of **exactly `1`** terminates the loop immediately. Every other 32-bit result, including zero and other nonzero values, executes another iteration.

Each iteration has this order:

1. Read the current 32-bit word at the first-position address.
2. Preserve that word for the later processing call.
3. Call F-2b3097eaee8e with the first-position address.
4. Set the carried address-like temporary to the previously captured word.
5. Call F-d1bb3c5047e2 with:
   - The address of the carried context/result word.
   - The original context argument.
   - The address of the carried address-like word.
6. Write the current context/result word to the output location.
7. Repeat the comparison.

The captured word is taken **before** F-2b3097eaee8e runs. Changes made to the first position by that dependency do not replace the captured value used to initialize the third argument’s temporary for F-d1bb3c5047e2.

Both temporary addresses supplied to F-d1bb3c5047e2 are potentially writable. Its changes to them matter:

- The context/result word supplies the subsequent output write and the final return’s high word.
- The address-like word supplies the final return’s low word.
- On a later iteration, the address-like word is replaced by the next pre-advance captured word before the processing call.
- The context/result word is not reinitialized to the context address on each iteration.

The return values of F-2b3097eaee8e and F-d1bb3c5047e2 are not used.

### 6. Iterative return and zero-iteration case

When the iterative comparison returns exactly `1`, the function returns:

- High word: the current context/result word.
- Low word: the current carried address-like word.

If no iteration ran, these words remain initialized to the context address and output-location address, respectively. The function’s only direct output write in that case is the initial header-address write.

Consequently, the zero-iteration return’s high word is the context address, not necessarily the header address stored in the output location.

## Side effects

### Direct memory effects

The function directly writes:

- The output word at entry.
- The output word after each completed iterative processing call.
- The output word at the end of the bulk path.
- Three header fields and one context field on the bulk path.
- Temporary storage whose addresses are passed to dependencies.

The iterative path does not itself directly clear the context state word or header links. Any such changes on that path must come from dependencies or aliasing.

### Ownership and lifetime

No allocation or release primitive is directly identified.

F-a19f2f4d8aef receives the header’s offset-`0x04` value, and F-d1bb3c5047e2 receives a captured position-like value by reference. Either may have ownership effects, but destruction, deallocation, transfer, or retention is not established.

The function supplies addresses of temporary storage to dependencies. Whether those dependencies retain such addresses is unknown. Their contracts are required to assess lifetime safety.

### Errors and termination

There is no explicit error-status return or error-recovery branch.

The observed interface does not establish:

- Handling for invalid addresses.
- Recovery from dependency failure.
- Rollback after partial mutation.
- A bound on iteration count.
- Guaranteed progress toward a comparison result of exactly `1`.

If a dependency does not return normally, later writes and the final result are not established by this function. The initial output write may already have occurred.

## Acceptance examples

These are conditional static acceptance cases, not reports of executed tests. Unless stated otherwise, their memory regions do not overlap, and dependencies preserve memory except for the explicitly described changes.

### Immediate iterative termination

Suppose the context’s header address is `H`, the output-location address is `O`, and the context address is `C`.

If the first preliminary call returns zero and the first iterative comparison returns `1`:

- The output receives `H`.
- Neither F-2b3097eaee8e nor F-d1bb3c5047e2 runs.
- The return has high word `C` and low word `O`.

### Bulk reset

Suppose both preliminary calls return nonzero, the context state word is nonzero, and F-a19f2f4d8aef preserves the context’s header address `H`.

After normal completion:

- Header offset `0x08` contains `H`.
- Header offset `0x04` contains zero.
- Header offset `0x0c` contains `H`.
- Context offset `0x14` contains zero.
- The output contains `H`.
- The return has high word `H` and low word equal to the output-location address.

### Zero state does not itself complete the operation

If both preliminary tests return nonzero but context offset `0x14` is zero, the bulk helper is not called.

The function still performs an iterative comparison. A zero state word is not, by itself, a return condition.

### Non-one comparison result

If an iterative comparison returns `2`, one iteration executes.

This remains true even though a return of `2` would count as a successful nonzero result in either preliminary test.

### Capture before advancement

Suppose the first-position word initially contains `A`, and F-2b3097eaee8e changes it to `B`.

F-d1bb3c5047e2 receives a temporary initially containing `A`, not `B`. If it changes that temporary to `D`, changes the context/result temporary to `R`, and the next comparison returns `1`, the output contains `R` and the return consists of high word `R`, low word `D`.

### Header replacement during the bulk helper

If F-a19f2f4d8aef changes context offset `0x10` from `H₁` to valid header address `H₂`, and that field remains stable afterward, the subsequent header writes target `H₂`. The final output and return high word are `H₂`, not `H₁`.
