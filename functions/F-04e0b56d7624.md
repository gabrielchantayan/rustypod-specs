# F-04e0b56d7624

## Purpose

F-04e0b56d7624 selectively initializes a globally selected state block. It masks the initial header, chooses a mode from an external byte, calls F-001430fff24e with a mode-dependent argument, and then initializes a fixed set of state fields.

This is not a whole-block clear. Some fields receive constants, some receive externally supplied values, and one control word retains its upper bits. Gaps between written fields remain outside this function’s explicit initialization.

**Inferred intent:** the operation appears to reset or prepare structured subsystem state. The subsystem, field meanings, units, and significance of the two modes are not established.

## Behavior

### Target capture and initial header update

The function captures the selected state-block base before the dependency call. Subsequent indexed state writes use this captured base.

Before reading the mode byte, the function updates the initial header through the global state selector. The stored value is the previous header word bitwise-ANDed with `0x00000002`:

- Bit 1 is retained.
- Every other bit is cleared.
- The resulting value is either zero or `0x00000002`.

The initial header operation refers directly to the global selector rather than exclusively to the captured base. With a stable selector, both identify the same block. The supplied representation does not establish a consistent target if that selector changes during these initial accesses.

### Mode selection and dependency call

After the header update, the function reads the byte at offset `0x02` in the selected mode region.

| Observed mode byte | Value written at state offset `0x00C` | Argument to F-001430fff24e |
|---|---:|---:|
| Exactly `0x01` | `5` | `2` |
| Any other byte | `6` | `1` |

The state-mode write precedes the dependency call. The comparison is exact equality, not a nonzero test. Values such as `0x02`, `0x7F`, and `0xFF` select the second branch.

If the mode region overlaps the updated header, the mode read occurs after that header update. It must not be treated as an unconditional observation of entry-state memory.

F-001430fff24e is then called once. No result from the call is consumed.

### Target after the call

If the dependency returns, the remaining explicit state writes use the base captured before the call. A dependency-time change to the global state selector does not redirect those writes.

This retained target does not establish retained ownership or lifetime. If the dependency invalidates the captured storage, the supplied body provides no recovery mechanism.

### Control-word semantics

The two updates at `0x180` are separate read-modify-write operations. The first clears bits 0 through 4. The second rereads the word and sets bit 4.

Without an intervening change, the net result replaces the low five bits with `0x10` while preserving bits 5 through 31. Those preserved bits come from the word present when this post-call update begins, not necessarily from function entry.

The intermediate stored value has all five low bits clear. A single final-value write does not reproduce the explicit two-update sequence.

If another actor changes the word between the operations, the second operation uses its new read; it is not specified to reuse the first operation’s original value.

### K08 sampling and arithmetic

K08 is sampled twice after the write at `0x214` and before the write at `0x218`:

- The **first sample** is retained for the later derived value at `0x238`.
- The **second sample** supplies the value stored at `0x218`.

No explicit state write or dependency call occurs between these two samples. Nevertheless, the supplied representation contains two source reads, not one shared sample. Equality of their values requires a stability assumption.

The write at `0x238` neither rereads K08 nor reloads `0x218`. Consequently, it is not unconditionally four times the value stored at `0x218`.

Under the 32-bit unsigned model, the derived result is four times the first sample modulo `2³²`. Bits shifted beyond bit 31 are discarded. There is no visible saturation, overflow report, range validation, or carry storage.

### External-value timing and aliasing

All twenty K-source reads occur after the dependency returns. They are not an entry-time snapshot.

Therefore:

- Dependency changes to source locations can affect later copied values.
- Earlier state writes can affect later source reads if the locations overlap.
- K08’s first retained sample is unaffected by later changes to its source or to `0x218`.
- K08’s second sample is independently obtained, even though it immediately follows the first in the supplied representation.

No disjointness guarantee is established among the state block, mode region, value sources, or global selectors. The explicit read sequence does not independently establish volatile semantics or the number of physical machine or device transactions.

## Acceptance examples

These are conditional contract examples, not executed tests. Except where a change is explicitly described, they assume valid storage, stable selectors and sources, normal dependency return, and no interfering mutation.

### Exact mode selection

An observed mode byte of `0x01` produces a write of `5` at `0x00C`, followed by a call to F-001430fff24e with argument `2`.

An observed byte of `0x02` produces a write of `6`, followed by argument `1`. Nonzero alone is insufficient to select the first branch.

### Initial header mask

An initial header of `0xFFFFFFFF` produces a pre-call header write of `0x00000002`.

An initial header of `0x00000001` produces a pre-call header write of zero.

These are final header values only if no subsequent effect changes that storage.

### Dependency-time selector change

Suppose the captured target is block A. The dependency changes the global state selector to block B but leaves A valid.

The post-call writes still target A. They do not follow the selector to B.

### Control-word intermediate value

If `0x180` contains `0xABCDEFED` when its update begins, the first write stores `0xABCDEFE0`, and the second stores `0xABCDEFF0`.

If the dependency changed that word before returning, its changed value supplies the starting point.

### Stable K08 samples

If both K08 reads yield `0x00000003`, `0x218` receives `0x00000003`, and `0x238` receives `0x0000000C`.

This relationship depends on equal samples; it is not a universal relationship between the two destination words.

### Different K08 samples

If the first K08 read yields `0x00000003` and the second yields `0x00000009`, then:

- `0x218` receives `0x00000009`.
- `0x238` receives `0x0000000C`, derived from the first sample.

This example is conditional on the source actually yielding different values. The body contains no explicit write to K08 between those reads.

### Shift overflow

If the first K08 sample is `0xC0000001`, the result stored at `0x238` is `0x00000004` under the 32-bit model.

If the second sample is `0x00000007`, that separate value is stored at `0x218`. It does not replace the retained first sample.

### Selective initialization

A sentinel at `0x014` has no explicit write replacing it. With a nonmutating dependency and no relevant aliasing or interference, it remains unchanged.

In contrast, all 24 words from `0x100` through `0x15C`, inclusive at four-byte spacing, receive zero.

### Nonreturning dependency

If F-001430fff24e does not return, the header update and selected-mode write have already occurred. This invocation has not yet performed the listed post-call updates or any K-source reads.
