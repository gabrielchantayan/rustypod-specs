# F-3e8d55893797

## Purpose

F-3e8d55893797 performs an ordered sequence of address-derived memory writes, then enters an apparently unbounded loop that issues a coprocessor operation.

The supplied static representation establishes neither a conventional application purpose nor a complete callable interface. Several addresses depend on incoming machine state absent from the displayed parameter list. The representation also carries warnings about invalid instruction data, removed unreachable regions, and overlapping global symbols. Consequently, this contract distinguishes the behavior shown in that representation from behavior that would require validation against executable instructions.

**Established static behavior:** eight memory stores precede the loop. Six stores are one byte wide; two are four bytes wide. Some stores depend on intervening four-byte reads. The loop’s first explicit numeric payload is 78; subsequent payloads are zero.

**Inferred intent:** the writes may initialize or manipulate machine-specific state, and the loop may transfer control or data through a hardware facility. Neither interpretation is established.

**Unknown:** whether the represented operations are a faithful executable path, whether the coprocessor operation returns, and whether any addressed region is ordinary memory, memory-mapped hardware, or invalid.

## Behavior

### Ordered memory prefix

The following order is established by the supplied representation, subject to execution reaching each operation.

1. **Write the low byte of the third input near its own address.**

   Interpret the third input as an address base, add two bytes, and store one byte there. The stored value is the low eight bits of that same input.

   No read from the destination is shown.

2. **Write address seed B near its own address.**

   At the address given by address seed B plus 80 bytes, store the four-byte value of address seed B.

   Byte order is not established by the supplied material. The contract specifies a four-byte value store, not an independently established sequence of four byte stores.

3. **Clear the explicit byte destination.**

   Store one zero byte at the address supplied by the second input.

4. **Copy the low byte of a four-byte read within a scaled region.**

   Form a region base by multiplying address seed C by \(2^{20}\), using 32-bit unsigned arithmetic.

   Read four bytes at that base plus 100 bytes. Convert the resulting four-byte value to its low eight bits, and write that byte at the same region base plus three bytes.

   The source read is four bytes wide even though only one byte of its value is retained. It must not be replaced in this contract by a one-byte read. Endianness can affect which addressed source byte contributes the retained low-order bits.

5. **Clear a byte through a masked pointer-table lookup.**

   Retain the low 22 bits of address seed A, multiply that value by 16, and add 60 bytes. Read a four-byte address value from the resulting location.

   Add two bytes to the address just read and store one zero byte there.

   The table-location arithmetic ranges from 60 through 67,108,908 before any interpretation as an address. Masking and scaling do not themselves validate the loaded destination pointer.

6. **Clear a four-byte field through the global base slot.**

   Read the current four-byte value of the global base slot. At that base plus 44 bytes, store a four-byte zero value.

   This global value is read at this point in the sequence. The representation does not justify taking an earlier snapshot and reusing it, particularly if preceding writes alias the slot.

7. **Clear a byte at a second scaled address.**

   Multiply address seed C by \(2^{30}\), reducing the result modulo \(2^{32}\), and store one zero byte at that address.

   The resulting address depends only on the low two bits of address seed C. The four possible numeric addresses are zero, 1,073,741,824, 2,147,483,648, and 3,221,225,472.

   A zero result is not skipped.

8. **Write a marker through a two-stage address calculation.**

   Retain the low two bits of address seed C. Multiply that value by \(2^{18}\), then add 104 bytes. Read a four-byte address value from that table location.

   At the loaded address plus 96 bytes, read a four-byte unsigned value. Shift that value right by two bits, then add four bytes to obtain the final destination address.

   Store the one-byte value 158, hexadecimal 0x9E, at that destination.

   The shift is a logical right shift of an unsigned 32-bit value. Its result lies between zero and 1,073,741,823; adding four therefore yields a numeric destination between four and 1,073,741,827 without 32-bit unsigned overflow.

### Repeated coprocessor operation

After the eight-store prefix, execution enters a loop with no visible exit.

The operation is represented as a coprocessor move-to operation with fixed selectors 8, 5, and 4, an explicit numeric payload, and the incoming coprocessor state X and Y.

The payload sequence is:

- First invocation: 78, hexadecimal 0x4E.
- Every later invocation: zero.

The first value results from a logical right shift of hexadecimal 0x27798 by 11 bits. The loop’s retained numeric state is set to zero before the first invocation.

If an invocation returns normally, execution proceeds to another iteration. There is no visible return, completion status, or exit condition. Whether the operation returns, blocks, traps, or changes machine state is not established.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

### Low-byte store

Given a third input of hexadecimal 0x00001234, a writable byte at hexadecimal 0x00001236, and execution reaching the first store, that byte receives hexadecimal 0x34.

This condition establishes only the first store. It does not establish that later addresses are valid or that the routine completes its prefix.

### Four-byte read followed by byte truncation

Suppose the scaled region’s four-byte source read produces the numeric value hexadecimal 0x123456AB. The byte stored three bytes into that region is hexadecimal 0xAB.

A substitute implementation that reads only one source byte is not justified by this example: the represented access is four bytes wide, with potentially different validity and device effects.

### Masked table selection

If address seed A differs only in bits above its low 22 bits, the fifth operation selects the same pointer-table location, provided earlier memory effects are otherwise identical.

This does not imply that the loaded pointer is valid or that the destination byte lies within a bounded object.

### Zero-address write

If address seed C has its low two bits clear, the seventh operation attempts a zero-byte store at numeric address zero.

A contract that silently omits that access, returns an error beforehand, or redirects it elsewhere would not match the visible behavior.

### Marker destination

If the second four-byte read in the eighth operation yields hexadecimal 0x00000103, shifting right by two yields hexadecimal 0x40. Adding four selects destination hexadecimal 0x44, where the routine writes hexadecimal 0x9E.

The low two bits of the read value are discarded; they do not affect that destination.

### Aliasing affects later reads

If an earlier store overlaps a pointer-table entry used by a later operation, the later operation uses the entry’s then-current value, not an assumed entry-time snapshot.

The resulting pointer depends on the overlap, stored bytes, and target endianness.

### Loop payloads

If all prefix accesses complete and three successive coprocessor operations return normally, their explicit payloads are 78, zero, and zero, in that order. Execution then attempts another iteration rather than returning normally.
