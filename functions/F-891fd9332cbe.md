# F-891fd9332cbe

## Purpose

An enabled object reaches dispatch exactly when:

**0 ≤ signed requested value < signed stored bound.**

Zero is therefore accepted whenever the signed bound is positive.

The established normal-return outcomes are:

- **35** if the object address is zero or the enablement bit is clear.
- **6** if enablement succeeds but the requested value fails the signed range check.
- **0** if the range check succeeds, the resolved target address is zero, and F-1a1e9d85ae73 returns normally.
- **The indirect target’s returned 32-bit value** if the range check succeeds and the resolved target address is nonzero.

These numbers are not established symbolic error or success categories. In particular, a dependency may return a number that is also used by an early-return path.

## Behavior

### Enablement

A zero object address returns 35 without dereferencing the object or invoking a dependency. Neither other input changes this result.

For a nonzero object address, the function first reads the 32-bit word at byte offset 8. If mask 2 is clear, it returns 35 without reading the bound or dispatch chain.

Only bit 1 matters to this decision. Other bits do not independently enable or disable dispatch.

The incoming additional value does not provide an alternative enablement word. For a nonnull object, the memory read supplies that word. For a null object, rejection occurs regardless of the additional value.

### Signed range interpretation

After enablement succeeds, the requested value’s 32-bit pattern is interpreted as signed:

- 0x00000000 through 0x7fffffff represent values from 0 through 2,147,483,647.
- 0x80000000 through 0xffffffff represent negative values.

A negative requested value returns 6 without reading the stored bound.

For every nonnegative requested value, including zero, the function reads the 32-bit bound at object offset 28. The complete 32-bit values are compared for equality; ordering uses signed 32-bit interpretation.

The resulting dispatch condition is:

**The requested value is nonnegative, differs from the bound, and is no greater than the bound.**

Equivalently:

**0 ≤ signed requested value < signed stored bound.**

The bound-equality decision controls the nonnegative case. An earlier distinction between zero and nonzero requested values does not independently reject zero after the bound has been read.

Consequences:

- Requested value zero is accepted when the signed bound is positive.
- Requested value zero is rejected when the signed bound is zero or negative.
- A signed bound of 1 admits exactly requested value zero.
- A nonpositive signed bound admits no requested values.
- Equality with the bound returns 6.
- A requested value greater than the signed bound returns 6.
- A bound whose high bit is set is negative and admits no requested values.
- Requested value 2,147,483,646 is accepted with bound 2,147,483,647.
- Requested value 2,147,483,647 cannot be accepted because no greater signed 32-bit bound exists.

The range decision does not require arithmetic on the requested value or bound. No increment, decrement, subtraction, multiplication, or arithmetic wraparound is established within that decision.

A failed range check returns 6 without resolving the target.

1. Read the first dispatch address from object offset 96.
2. Read the second dispatch address from offset 20 relative to the first address.
3. Read the target address from offset 92 relative to the second address.
