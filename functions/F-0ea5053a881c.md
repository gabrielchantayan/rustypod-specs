## Behavior

### Lookup and invocation order

On a normally progressing execution, the visible operations occur in this dependency order:

1. Read the address-bearing field at byte offset 8 from the entry context address.
2. Use the value just read as the base for a function-pointer read at byte offset 12.
3. Invoke the function pointer obtained by that second read.
4. If the invocation returns normally, return from F-0ea5053a881c.

The first field therefore identifies the base of another memory region. The function does not directly invoke the first loaded value. Likewise, it does not invoke the address of the second slot; it invokes the pointer stored in that slot.

There is one visible indirect invocation. There is no visible loop, retry, alternate slot, or second invocation after normal return.

- One invocation occurs.
- If the target returns normally, F-0ea5053a881c returns afterward.

### Different intermediate address

### Different selected slot contents

### Invalid first or second lookup

### Target mutation or non-return

If the target never returns normally, normal return from F-0ea5053a881c is not an acceptance requirement for that execution.
