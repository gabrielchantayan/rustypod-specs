# F-0739a774ccb8

## Purpose

F-0739a774ccb8 transfers a requested number of bytes between two addresses. Its direction selection and transfer construction support an **inferred intent of overlap-safe copying**.

Under the accessibility, address-arithmetic, byte-order, and ordinary-memory preconditions below, the intended final effect is:

- Every destination byte equals the corresponding source byte as it existed before the operation.
- Exactly the requested destination interval is written.
- Source reads may extend outside the requested source interval.

The supplied representation establishes directional transfers, alignment handling, access widths, access ordering, and a result containing two cursor values. It does not establish compatibility with a named library interface or a return value equal to the original destination.

All access sequences below describe the supplied static representation. They are not independently verified machine-level execution traces.

## Interface

### Inputs and widths

| Input | Meaning | Width |
|---|---|---|
| **D** | Initial destination byte address | 32 bits |
| **S** | Initial source byte address | 32 bits |
| **N** | Requested byte count | Unsigned 32 bits |

Neither address must initially be four-byte aligned. Alignment affects the selected transfer path and its actual read footprint.

Address comparisons used for direction selection are unsigned. Address calculations and count arithmetic use 32-bit values. Subtracting a block size from an insufficient remaining count can deliberately produce an unsigned wrapped value; subsequent low-bit tests identify the actual remainder. Such intermediate values do not request enormous additional transfers.

### Result layout

The represented result is 64 bits:

| Result bits | Contents |
|---|---|
| 63–32 | Final represented source cursor |
| 31–0 | Final represented destination cursor |

For a completed **forward** transfer, these halves contain S + N and D + N, respectively.

For a completed **backward** transfer, define:

- **P = 0** when N is at most three.
- Otherwise, **P = (D + N) modulo 4**, the number of initial backward alignment bytes.
- **R = (N − P) modulo 4**.

The returned halves contain:

- High half: S + (R modulo 2).
- Low half: D + (R modulo 2).

The backward cursors therefore finish at either the original addresses or one byte above them. The final optional single-byte store does not decrement those returned cursors.

These results describe the representation. Their external calling-convention interpretation remains unresolved.

### Preconditions for the byte-copy interpretation

1. The nominal source and destination intervals must have meaningful, nonwrapping address ranges.
2. Every destination byte must be writable.
3. Every actual source access must be readable, including complete word accesses extending beyond the nominal source interval.
4. Alignment-adjusted and surrounding accesses must also have valid addresses; nominal interval validity alone is insufficient.
5. Memory must use little-endian byte layout for the stated word reconstruction and low-byte extraction.
6. The environment must support the unaligned 32-bit loads present on some forward paths.
7. Memory must behave as stable ordinary storage. Concurrent modification and device-specific read/write effects are outside the successful-copy interpretation.

No ownership transfer is expressed. The caller supplies the storage and remains responsible for its validity and lifetime.

## Behavior

### Direction selection

Backward transfer is selected exactly when:

- S ≤ D, and
- the unsigned distance D − S is strictly less than N.

Otherwise, transfer is forward.

Consequences include:

- Equal addresses with a nonzero count select backward transfer.
- Equal addresses with a zero count select forward transfer.
- A destination exactly N bytes above the source selects forward transfer.
- A destination below the source selects forward transfer, including when the intervals overlap.

There is no nonempty equal-address shortcut. Such calls still perform reads and writes.

### Forward transfer: destination alignment

For N at most three, the operation goes directly to the final small transfer.

For larger counts, an unaligned destination receives a byte prefix sufficient to reach the next four-byte boundary:

| Initial D modulo 4 | Prefix length |
|---|---:|
| 0 | 0 bytes |
| 1 | 3 bytes |
| 2 | 2 bytes |
| 3 | 1 byte |

The prefix has the following represented memory-access order:

- First, a 32-bit word is read at S; its low byte supplies the first destination byte.
- For a two- or three-byte prefix, a byte is then read at S + 1, before the first destination write.
- The first destination byte is written.
- For a three-byte prefix, a 32-bit word is then read at S + 2; its low byte supplies the third destination byte.
- The remaining prefix bytes are written in increasing address order.

Thus, a three-byte prefix does not read all its source values before its first write. Its later word read occurs between the first and second destination writes.

Both logical cursors advance by the prefix length, and that length is removed from the remaining count. Prefix word reads can be unaligned and can cover bytes beyond the prefix.

### Forward transfer: aligned source

After destination alignment, a four-byte-aligned source uses word transfers.

The main unit is 32 bytes. Relative to the source and destination cursors at the start of a unit, its first half has this access order:

- Read source words at byte offsets 4, 8, and 12, in that order.
- Read the source word at offset 0, then write destination offset 0.
- Write destination offsets 4, 8, and 12, in that order.

For the second half:

- Read source words at offsets 16, 20, 24, and 28, in increasing order.
- Write the corresponding destination words in increasing order.

The next unit starts 32 bytes higher.

Remaining whole words are handled by optional groups of 16, 8, and 4 bytes, in that order:

- A 16-byte group reads four words in increasing address order before writing them in increasing order.
- An 8-byte group reads both words in increasing order before writing either, then writes in increasing order.
- A 4-byte group reads one word and writes it.

All these destination stores are 32 bits wide and remain within the requested destination interval.

### Forward transfer: unaligned source

If the source cursor is unaligned and at least four bytes remain, aligned source words are combined to produce each destination word.

The first read is a 32-bit load at the current source cursor rounded down to a four-byte boundary. Before each destination word is written, the next higher aligned source word is read. That newly read word is retained for the next reconstruction.

| Source cursor modulo 4 | Bytes used from lower word | Bytes used from next word |
|---|---:|---:|
| 1 | 3 | 1 |
| 2 | 2 | 2 |
| 3 | 1 | 3 |

These byte relationships assume little-endian layout. Destination word stores proceed in increasing address order.

The first load can include bytes before the logical source cursor. The last newly loaded word can include bytes after the whole-word portion being transferred. After that portion, the source cursor is restored to its exact logical byte boundary before any final small transfer.

If fewer than four bytes remain after destination alignment, this reconstruction phase performs no aligned-word preload.

### Forward transfer: final zero to three bytes

All final-tail reads precede all final-tail writes.

| Tail length | Source reads, in order |
|---|---|
| 0 | None |
| 1 | 32-bit load at the current source cursor |
| 2 | 32-bit load at the current source cursor; byte load one byte higher |
| 3 | 32-bit load at the current source cursor; 32-bit load one byte higher; byte load two bytes higher |

Only the low byte of each word load supplies a destination byte.

The writes are byte stores in increasing address order. Both returned cursors advance by the tail length.

These word reads can be unaligned and can extend past the requested source interval. A zero-length call performs no source or destination memory access.

### Backward transfer: destination-end alignment

Backward transfer first forms end cursors D + N and S + N.

When N exceeds three, it transfers enough individual bytes to align the destination end cursor to four bytes. At most three bytes are transferred.

Each alignment byte is read immediately below the current source cursor and then written immediately below the current destination cursor. Both cursors move backward by one. Reads and writes alternate for these bytes, proceeding from higher addresses toward lower addresses.

When N is at most three, this alignment phase is skipped.

### Backward transfer: aligned source end

When the source end cursor is four-byte aligned, the main unit is 16 bytes.

Let **E** be the source end cursor and **T** the destination end cursor at the start of one such unit. The represented memory accesses are:

| Phase | Address order | Width |
|---|---|---|
| Source reads | E − 8, E − 12, E − 16, E − 4 | 32 bits each |
| Destination writes | T − 4, T − 8, T − 12, T − 16 | 32 bits each |

The source reads are **not** in descending address order. The highest-address word, at E − 4, is read last, as the value for the first destination store. The other three source words have already been read. Consequently, all four source reads precede every destination write in that unit.

After the unit, both cursors are 16 bytes lower.

Remaining whole words are handled as follows:

- An 8-byte group reads the higher source word and then the lower source word before either store. It then stores the higher destination word followed by the lower one.
- A 4-byte group reads one word immediately below the source cursor and then writes the corresponding word immediately below the destination cursor.
- Any remaining one to three bytes use the backward tail.

### Backward transfer: unaligned source end

When at least four bytes remain and the source end cursor is unaligned, words are reconstructed from aligned loads.

The first read is the aligned word containing the source end cursor. Because that cursor denotes the exclusive end of the remaining source bytes, this load can include bytes at or beyond that end.

For every destination word, the preceding aligned source word is read before the destination word is stored. The preceding word is retained for the next reconstruction.

| Source-end cursor modulo 4 | Bytes used from higher word | Bytes used from preceding word |
|---|---:|---:|
| 1 | 1 | 3 |
| 2 | 2 | 2 |
| 3 | 3 | 1 |

Destination words are written in descending address order. The logical source cursor is restored to the exact boundary above the remaining low-address bytes.

Aligned reads can extend beyond either side of the nominal source interval. If fewer than four bytes remain, this phase performs no aligned-word preload.

### Backward transfer: final zero to three bytes

The backward tail uses byte loads exclusively:

- One remaining byte: read the byte immediately below the source cursor.
- Two remaining bytes: read the highest byte, then the next lower byte.
- Three remaining bytes: read those same two bytes, then the lowest byte.

All tail reads occur before all tail writes. Writes proceed from higher addresses toward lower addresses.

The two-byte portion decrements both represented cursors by two. An optional final single-byte store addresses one byte below the resulting destination cursor without decrementing either returned cursor. This explains the backward result formula.

## Side effects

The visible effects are source-memory reads, destination-memory writes, and production of the packed cursor result.

For completed calls satisfying the stated assumptions:

- Exactly N destination bytes are written, each once.
- No bytes outside the destination interval are written.
- Source bytes can change where the destination overlaps them.
- Equal-address nonempty calls still access memory.
- Read footprints can exceed the requested source interval.
- Byte and word accesses are mixed according to the selected path.

No explicit global-state access, allocation, release, external call, error-status production, validation branch, or rollback is visible.

If an access faults, the representation establishes no recovery contract. Earlier stores may already have occurred. Within a backward aligned 16-byte unit, none of that unit’s stores precedes its four source reads; previous units or alignment bytes may already have been written.

The represented ordering does not independently establish hardware atomicity, memory barriers, concurrency semantics, or suitability for memory-mapped devices.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, assume ordinary little-endian storage, supported accesses, sufficient surrounding readable memory, and nonwrapping address calculations.

1. **Zero count.**  
   With N = 0, no memory access occurs, regardless of address alignment or equality. The high result half is S; the low half is D.

2. **Forward overlap.**  
   With D = S − 1 and N = 5, transfer is forward. If the five original source bytes are A, B, C, D, and E, those five values occupy the destination interval afterward. The result halves are S + 5 and D + 5.

3. **Backward overlap with a byte tail.**  
   With four-byte-aligned S, D = S + 1, and N = 5, the destination end has residue two. Two initial backward byte transfers leave three tail bytes. The destination receives the original five source bytes. The result halves are S + 1 and D + 1.

4. **Touching intervals.**  
   With D = S + N and N greater than zero, transfer is forward. The strict distance comparison excludes backward transfer.

5. **Equal addresses with alignment work.**  
   With aligned D = S and N = 5, transfer is backward. One byte is transferred first, followed by one word. Contents remain unchanged, but accesses occur. Both result halves contain the original address.

6. **Forward one-byte footprint.**  
   With N = 1 on a forward path, there is one 32-bit source load and one byte destination store. Readability of only the requested source byte does not satisfy the actual access precondition.

7. **Backward one-byte result.**  
   With D = S and N = 1, one byte is read and written using byte accesses. The returned halves contain S + 1 and D + 1.

8. **Forward reconstructed word.**  
   With aligned D, source residue one, N = 4, and forward selection, source word reads occur at S − 1 and S + 3 before the destination word store. Exactly four destination bytes are written. Readability limited to S through S + 3 is insufficient.

9. **Backward aligned main-unit ordering.**  
   With S = 0x1000, D = 0x1004, and N = 16, backward transfer is selected without alignment-byte transfers. Source word reads occur at 0x1008, 0x1004, 0x1000, and 0x100C, in that order. Destination word writes then occur at 0x1010, 0x100C, 0x1008, and 0x1004. The returned source and destination cursors are 0x1000 and 0x1004.
