# F-5dc946244541

## Purpose

F-5dc946244541 dispatches selectors 1, 8, 32, 128, and 256 using a context, an event word, and shared storage. Unsupported selectors return zero after the entry-time global reads, without branch-specific calls or writes.

The supported branches enumerate work, update counters, process entry transitions, propagate numeric values, or conditionally submit notifications. These are descriptions of observable operations, not established domain meanings.

This contract distinguishes directly established static behavior from inferred intent and unresolved dependency behavior. No runtime tests have been performed.

## Interface

### Inputs and return value

| Input | Representation and use |
|---|---|
| Context | 32-bit address-like value, forwarded to dependencies and, for selector 32, dereferenced at offset 0x2C8. |
| Selector | Signed 32-bit integer, matched against exact supported values. |
| Event word | Unsigned 32-bit value. Some branches use the full word; others use its low byte. |

The result is a 32-bit word:

- Selectors 8, 32, and 256 return zero on normal completion.
- Selector 1 returns zero or the most recently saved F-256e8a77aa59 result.
- Selector 128 returns zero or the F-43ce968102ca result.
- Explicit failure paths invoke F-a817d8d58c10, represented as nonreturning.

There is no general address-validity, bounds, or object-validity check.

### Storage layout and entry captures

At entry, the function reads and retains, in order:

1. A counter-region base.
2. A shared-block pointer.
3. A 32-bit initialization word.
4. An entry-status base.
5. A separately read status base, from which it subtracts three to form a preceding-status base.

Relevant layouts are:

| Storage | Accessed fields |
|---|---|
| Context | 32-bit word at offset 0x2C8. |
| Identifier table | Two 32-bit entries, indices 0 and 1. |
| Counter region | Counter bytes at indices 0 and 1; guard bytes at base minus two plus the same index. |
| Entry-status region | Bytes at indices 0–2. |
| Preceding-status region | Bytes at indices 0–2 relative to its separately captured base. |
| Shared mode | Byte at captured entry-status base minus two. |
| Per-entry word table | Four-byte entries. |
| Shared block | Leading byte; four-byte numeric field at 0x34; four-byte handle at 0x5C. |
| Activity array | Bytes at indices 1 and 2. |
| Record table | Records with stride 0x14; leading byte and four-byte field at offset 4. |

When the two status-base reads produce the same value, shared mode aliases preceding-status index 1. Their separate acquisition remains significant: this equality is not an unconditional requirement.

Captured addresses do not follow later global-pointer changes. Explicit later reloads can select different storage.

### Preconditions and ownership

Every reached address must support the indicated access width and indexing. Dependencies must accept the supplied arguments.

Several dependencies receive addresses of local words or a local record. Those objects exist during this invocation. Whether dependencies retain those addresses, mutate the objects through retained addresses, copy their contents, or acquire ownership is unresolved. In particular, selector-1 transition words must not be treated as immutable after their initial output call.

No allocation, release, reference-counting, or asynchronous-use guarantee follows from call placement alone.

## Behavior

### Selector 32: enumeration or counter processing

Compare the full event word with the context’s 32-bit word at offset 0x2C8.

**Equal words: enumeration**

Initialize a persistent local work word to zero. Before each F-e08f888de5db call, initialize its second output word to the captured initialization word, its first output word to 0x7FFFFFFF, and its third output word to the captured initialization word.

Call F-e08f888de5db with context and addresses of the first, second, third, and persistent work words.

- A nonzero result terminates enumeration and returns zero.
- A zero result causes F-2e6e863c6f56 to receive context, the full first output word, the low 16 bits of each other output word, and the current persistent work word. Enumeration then repeats.

The persistent work word is not reset between iterations. No iteration limit is established.

**Unequal words: counter processing**

Search identifier indices 0 and 1 in order for the full event word. Reload the identifier-table global for each comparison. No match returns zero.

For a matching index:

1. Read the counter byte through a fresh counter-base read.
2. Add one modulo 256.
3. Reload the counter base and retain the guard address at base minus two plus index.
4. Store the incremented byte through another counter-base read.
5. Read the guard through the retained guard address.
6. Return zero if the guard is nonzero; otherwise return zero if the incremented byte exceeds 2.
7. Call F-352a899fb784 with context, index, and zero.
8. Rewrite the saved incremented byte through the counter base captured at function entry.
9. Call F-d2eae028ceec with context and index, then return zero.

Thus the initial increment and later rewrite need not target the same region.

### Selector 8: direct and associated-entry processing

Acquire a provider through U-01. Query F-62d1a359629f using provider offset 4 and the original event word; save the metadata.

Acquire another provider and call F-40c28640bfd1 with that provider and the original event word; save its associated-entry result. Call F-c29926bd9908 with context, original event word, selector 8, and the saved original metadata.

If the saved association is zero, return zero. Otherwise:

1. Acquire another provider.
2. Query F-62d1a359629f at provider offset 4 for the saved associated entry.
3. Call F-da3be2b0546d with context, associated entry, and its metadata.
4. Call F-c29926bd9908 with context, associated entry, selector 8, and that same metadata.
5. Return zero.

The original propagation occurs even without an association. Neither entry value is restricted here to indices 0–2.

### Selector 1: live transition-word processing

Initialize two local 32-bit words to 0xFFFFFFFF. Acquire a provider and pass both word addresses to F-ca2888499290.

In this section, **A** and **B** designate the low bytes of the first and second address-exposed words **at each stated read**, not values captured once after that call. Their upper 24 bits do not affect the transition tests. Their semantic direction is unknown.

Immediately compare their low bytes. Equality returns zero. Otherwise visit indices 0, 1, and 2 in order. At each index, acquire a fresh provider and call F-c1e400b68436 at provider offset 4. Only a result exactly equal to 0x13 participates.

Maintain a saved return word, initially zero. Each completed F-256e8a77aa59 call replaces it; entry boundaries do not reset it.

#### Initial notification decision

For each participating entry, reread B for the short-circuit decision whether it equals 1 or 2.

If that decision succeeds, skip the initial notification and cable stages and proceed to the cleanup decision below.

Otherwise acquire an associated value through F-b37968c9f644 and a property through F-1bc5bcdc9cca, each using a separately acquired provider at offset 4.

Test the property against 0x46. Only if it equals 0x46, read A for the exception test against 3. Suppress the initial notification only when both tests succeed.

If not suppressed:

1. Read A again and store its zero-extended byte value in a local 32-bit payload word.
2. Assign 32-bit value 1 to separate local storage also used in notification-record preparation.
3. Call F-cd7e1905512f with the saved associated value, zero, zero, operation 0x23, and the payload-word address.
4. A zero result invokes F-a817d8d58c10.
5. Otherwise call F-256e8a77aa59 with that result and 1, saving its return value.

The separate assignment of 1 is established local data flow, not an established additional call argument.

#### Post-notification decisions and cable stage

After the initial-notification decision and any resulting calls, reread B.

- If B is not 3, proceed to the cleanup decision.
- If B is 3, reread A.
  - If A is not 4, bypass the cleanup decision and proceed directly to the later A=3 decision.
  - If A is 4, perform the following cable stage, then proceed to the cleanup decision.

Call F-7afe554bcf62 with a local-object-word address and an embedded constant.

Use F-4a6c0bf0740c to compare the separate payload word against `"Apple Component AV Cable"`. Only if the comparison is nonzero, compare it against `"Apple Composite AV Cable"`.

An additional notification is required if:

- both comparisons are nonzero; or
- otherwise, F-76ed42657cca for the current index returns nonzero; or
- otherwise, the index is not 1.

This ordering short-circuits. Two nonzero comparisons bypass F-76ed42657cca; otherwise that dependency runs before the index test.

When required, assign 32-bit zero to the separate notification-related storage, then call F-cd7e1905512f with the saved associated value, two zeros, operation zero, and a null final argument. A zero result invokes F-a817d8d58c10. Otherwise call F-256e8a77aa59 with that result and 1, replacing the saved return word.

After either normal cable-stage outcome, assign another embedded constant to the local-object word and pass its address to F-22abefe7f288.

The relationship between the payload word and the object passed to F-7afe554bcf62 is unresolved. The later F-22abefe7f288 call does not independently establish destruction or ownership semantics.

#### Cleanup decision

Whenever control reaches this decision, reread A. An earlier A=4 observation does not replace this read.

If A is 4:

1. Call F-2c4fc5b4a966 with context, index, and zero.
2. Reload the per-entry word-table base.
3. Clear the indexed preceding-status byte through its captured base.
4. Clear the indexed entry-status byte through its captured base.
5. Clear the indexed four-byte word through the reloaded word-table base.
6. Acquire a provider and save F-40c28640bfd1’s association for the current index.
7. Acquire another provider and call F-ebd9fed2fee8 for the current index.
8. If the saved association is exactly 1 or 2, acquire another provider and call F-ebd9fed2fee8 for it.
9. Call F-704f99fd5e22 twice for the current index, first with operation word 0x14, then 0x17. Before each call, set its companion word to the captured initialization word. Pass both word addresses and a null final argument.

The association test uses unsigned 32-bit subtraction by one and comparison with two; only 1 and 2 qualify.

#### Later A=3 decision

After the applicable preceding stages, reread A independently. If it equals 3:

1. Acquire a provider and call F-39405f5827ef at provider offset 4 for the current index.
2. Acquire another provider and call F-4944ce526800 at provider offset 4 with index and two zeros.

Cleanup and this processing are not necessarily mutually exclusive: dependencies called during cleanup may affect the address-exposed transition word.

After all three indices, return the saved return word.

### Selector 128: numeric update and propagation

Truncate the event word to eight bits, then interpret that byte as signed. Denote the resulting value, from −128 through 127, by **N**.

Read the shared-block global afresh, read its handle at 0x5C, and pass that handle to U-02. Subsequent numeric-field operations use the shared-block pointer captured at entry.

**N below 16**

This includes all negative values.

Initialize three local operation words to the captured initialization word, 0x36, and zero. Store N as a signed four-byte integer at captured shared-block offset 0x34. Call F-704f99fd5e22 with context, entry 1, and the three word addresses.

Scan captured preceding-status indices 1 and 2 in order. At the first byte below 2:

1. Write 1 to captured shared mode.
2. Read an additional global 32-bit word into notification-related local storage.
3. Call F-43ce968102ca with context, entry 1, the current low 16 bits of the first two operation words, and the current four-byte numeric field.
4. Save its result and stop scanning.

The operation words may have changed during F-704f99fd5e22. The extra global read is not an established additional argument.

After scanning, reread the numeric field as signed 32-bit. If it exceeds 15, skip propagation; otherwise propagate.

**N equal to 100**

Write byte 100 at shared-block offset 0x34. Reload the word-table base. Write zero bytes at offsets 0x35, 0x36, and 0x37, in order.

Clear captured shared mode, captured entry-status byte 1, and word-table entry 1 through the reloaded base. Skip propagation. The numeric interpretation of this explicit byte sequence depends on target byte order.

**Other N values**

For values 16–127 except 100, write 0xFF at offsets 0x34, 0x35, 0x36, and 0x37, in order. Then propagate.

**Propagation**

Only when propagation is entered, capture the record-table base and then the activity-array base. Reuse both across indices 1 and 2, including across dependency calls.

For each index, read its activity byte.

- **If nonzero:**
  1. Initialize operation words to the captured initialization word and 0x38.
  2. Call F-704f99fd5e22 with context, index, both word addresses, and null.
  3. Read that record’s leading byte.
  4. If it is not 0x0F, copy the current four-byte numeric field to record offset 4, then call F-c6c589453fa8 with zero, zero, record address, and size 0x14.
- **Regardless of activity:** call F-88707f7d96dd with context and index.

An inactive entry receives no record-leading-byte read, numeric-field copy, or F-c6c589453fa8 call from this path.

**Normal exit**

Read the handle anew at offset 0x5C through the entry-captured shared-block pointer and pass it to U-03. Return the saved F-43ce968102ca result, or zero if that call did not occur.

U-02 and U-03 need not receive the same handle or handles from the same block.

### Selector 256: leading-byte update and notification

Read the old leading byte through a fresh shared-block-global read. Store the event word’s low byte through another global-pointer read.

If the stored input byte is at least 2, invoke F-a817d8d58c10 after the store.

Otherwise call F-1b4119123795, then read and save the leading byte through the entry-captured shared-block pointer.

Return zero if that saved byte equals the old byte. Otherwise read captured shared mode and return zero unless it is at least 4. Only after this gate, require the saved byte to be 0 or 1; another value invokes F-a817d8d58c10.

For either accepted byte:

1. Acquire an interface through F-0f05ec40e005 and invoke U-04 at dispatch offset 0x30. Return zero if its result is zero.
2. Acquire another interface and invoke U-05 at offset 0x4C. Return zero unless result bit 0 is set.
3. Acquire another interface and invoke U-06 at offset 0x28.
4. Prepare a local record: assign the final 32-bit result, then the saved post-hook byte to its designated byte field, then another byte to zero, another to 0x12, another to zero, and a 16-bit field to zero.
5. Pass the record address to F-f08fddbb2560 and return zero.

The payload byte is not refreshed after interface calls. Complete record offsets, contiguity, and padding contents are unresolved.

## Side effects

Direct writes include counter increments and rewrites, status and word-table clears, numeric-field updates, conditional record copies, the leading-byte store, and local payload preparation.

There is no rollback. Failure can follow writes, completed notifications, or processing of earlier entries. U-03 is established only on selector-128 normal exit; exception-safe balancing is not shown.

Dependencies may modify globals or referenced memory. Captured pointer values remain fixed, but their pointed-to contents need not. Repeated provider and interface acquisitions are distinct calls, not guaranteed equivalent objects.

## Dependencies

Mapped dependencies are identified by their opaque F-IDs at their points of use. Described roles express observed use, not independent semantic guarantees.

Additional opaque dependency references are:

- **U-01:** provider acquisition.
- **U-02:** receives the selector-128 entry-side handle.
- **U-03:** receives the selector-128 normal-exit handle.
- **U-04, U-05, U-06:** indirect interface calls at offsets 0x30, 0x4C, and 0x28.

The positioning of U-02 and U-03 suggests paired access control, but lock semantics are inferred, not established. F-a817d8d58c10 is represented as nonreturning.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Unsupported selector:** Selector 7 returns zero after entry captures, without branch-specific calls or writes.
2. **Enumeration termination:** An immediate nonzero F-e08f888de5db result produces no F-2e6e863c6f56 call.
3. **Counter wrap:** Counter 255 increments to zero. With a zero guard, both processing dependencies run, with the saved zero rewritten between them.
4. **Counter threshold:** Counter 2 becomes 3 before returning without either processing dependency.
5. **Missing association:** Selector 8 propagates the original event even when its saved association is zero.
6. **Initial byte equality:** Selector 1 returns immediately when the transition words’ low bytes are equal, even if their upper bits differ.
7. **Live initial decision:** If a participating entry’s provider or query calls change B to 1 through its previously exposed address, its initial-notification decision uses that current byte, not the byte observed after F-ca2888499290.
8. **Live post-notification decision:** If B becomes 3 and A becomes 4 during initial-notification dependencies, the subsequent decisions can enter the cable stage. If A then changes before the cleanup decision, cleanup uses the new A.
9. **Conditional exception:** With the transition words unchanged throughout the entry, A=3 and property 0x46 suppress operation 0x23; the later A=3 processing still occurs.
10. **Conditional cleanup and processing:** If cleanup is entered with A=4 and a cleanup dependency subsequently changes A to 3, the later A=3 processing can also occur.
11. **Signed input:** Selector 128 with event low byte 0xFF begins the N-below-16 path with N=−1.
12. **Inactive propagation entry:** With activity byte 1 equal to zero, entry 1 receives only F-88707f7d96dd from the propagation loop; its record is not inspected or copied.
13. **Active excluded record:** With nonzero activity and record-leading byte 0x0F after F-704f99fd5e22, that operation call and F-88707f7d96dd occur, but the record copy and F-c6c589453fa8 do not.
14. **Propagation capture:** Redirecting the record-table global during entry 1 does not redirect entry 2’s record address.
15. **Special 100:** The explicit byte writes and clears occur; propagation and its base captures are skipped; U-03 still occurs on normal exit.
16. **Post-hook byte:** Selector 256 gates and prepares its payload using the saved captured-block byte after F-1b4119123795, not necessarily the byte just stored through the global.
17. **Invalid input:** Selector 256 with low byte 2 stores that byte before nonreturning failure.
