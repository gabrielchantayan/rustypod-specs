# F-0978a08b3015

## Purpose

F-0978a08b3015 performs an ordered series of mixed-width memory mutations, follows addresses obtained from mutable memory, and concludes with an unresolved indirect invocation.

No application-level purpose is established. The supplied representation does not justify identifying the operation as construction, allocation, parsing, collection maintenance, or text processing. Constants that coincide with character codes are specified as numeric values.

Its observable behavior comprises memory accesses, changes to stored values and pointer reachability, and the terminal dependency’s effects. No direct return value is represented.

Visible accesses have widths of 8, 16, or 32 bits. Address-bearing values are represented as 32 bits.

A byte store replaces one byte; a halfword store replaces two bytes. Neither clears the remainder of an overlapping word. Narrowing an address to a byte or halfword retains its low eight or sixteen bits.

Unsigned comparisons and carry detection use 32-bit values. The representation does not independently establish executable semantics for every signed-looking overflow, doubled address, or wrapped address sum.

Character-typed loads introduce unresolved signedness and conversion behavior. Byte order, alignment requirements, and fault behavior are also unspecified.

## Behavior

### Initial observations and arithmetic

Before the first store, the operation saves an ambient comparison word and a distinct ambient word whose low halfword will later contribute to a sum.

The ambient arithmetic source has three distinct evaluation roles:

1. An initial reference supplies a value that is added to the incoming carry. This sum is saved for the fourth initial store’s address.
2. A later reference supplies the value tested as unsigned-greater-than `0xFFFFFFA6`.
3. Only if that threshold comparison is false, another reference supplies the value used in carry detection: add `0x59` at the represented 32-bit width, then test whether adding the incoming carry to that result produces unsigned carry.

The resulting one-bit contribution is one when the threshold comparison is true or the conditional carry test is true; otherwise it is zero. The threshold test short-circuits the carry calculation.

These are distinct source-level evaluation boundaries, not a claim about the number of physical machine loads. If the source can change between references, the saved address sum, threshold result, and conditional carry result need not derive from the same value. In particular, the fourth initial store’s address is not recomputed from the value used by the threshold or carry evaluation.

An initial offset adds the second argument, one hidden register value, and that one-bit contribution. A combined offset additionally incorporates the other hidden register value.

Before the stores, the latter hidden register is also compared unsigned-less-than-or-equal to a fresh reference to the ambient comparison source. This comparison supplies a later byte addend. The comparison need not use the same value as the earlier saved comparison word.

### First stores and late ambient reads

The first four stores occur in this order:

1. Store the initial offset’s low halfword at the third argument plus that offset.
2. Store the combined offset’s low halfword at the third argument plus the combined offset.
3. Store the saved ambient comparison word’s low halfword at twice the second argument.
4. Store byte `0x45` at the previously saved arithmetic sum plus `0x9E`.

Only afterward does the operation read an ambient address base, followed by an additional ambient halfword addend. The order is base first, addend second.

Consequently, any initial store that aliases either later-read ambient location can affect its observed value. The earlier saved addend remains the earlier value even if its backing storage is modified.

### Repeated computed-offset accesses

The operation next reads a full word at the third argument plus the combined offset. Treating that word as an address, it stores byte `0x45` at displacement `0x45`.

It then repeats the combined-offset halfword store.

At displacement `0x45` from the saved ambient base, it stores a halfword equal to the low sixteen bits of:

- The early saved addend.
- The additional addend read after the initial stores.
- One if the unresolved target compares below address `0x46`, otherwise zero.

This comparison does not invoke or validate the target.

The computed-offset location is then read again as a full word. At displacement `0x45` from this second loaded address, the operation stores word `0x45`.

Finally, the saved ambient base receives a byte at displacement `0x45`: the low eight bits of the fourth argument plus `0x53` plus the earlier unsigned-less-than-or-equal comparison result.

The two full-word reads are distinct events. Intervening partial stores and indirect stores may change the second result. The final byte store may overlap the preceding ambient-base halfword store while leaving its other byte intact.

### Initial address graph

For describing traversal, a **node** means only an address used as a field-access base; it implies no object type or ownership.

After the arithmetic byte store, the operation:

- Reads a node address from the third argument’s `0x14` field; call this the **initial node**.
- Stores that address at displacement `0x34` from the combined offset, used here as an independent address base.
- Reads a **principal node** through displacement `0x74` from the saved ambient base.
- Reads another node through displacement `0x14` from the second computed-offset word.
- Stores that second computed-offset address in the principal node’s `0x54` field.
- Self-links the other node through its `0x54` field.
- Stores the initial node’s address in the principal node’s `0x44` field.
- Stores the principal node address’s low byte at displacement `0x09` from the second computed-offset address.

The combined offset is therefore used both relative to the third argument and as a standalone address base.

The principal node’s `0x64` field supplies another address. A read through that address’s `0x14` field supplies a further destination. Two consecutive stores target the destination’s byte at `0x09`: first the self-linked node address’s low byte, then the address obtained from the principal node’s `0x64` field, narrowed to a byte.

### Absolute-address snapshot

Immediately after those two byte stores, the operation reads the 32-bit word beginning at absolute address `0xDB`.

The next represented memory read obtains an address through the initial node’s `0x14` field. The absolute-address read is therefore neither an entry snapshot nor deferred until after the ensuing traversal mutations.

If either preceding byte store overlaps that word, the saved word reflects the modification according to target byte order. Later writes to `0xDB` do not change the saved value.

That captured word is subsequently stored into multiple word fields and narrowed into byte fields.

### Derived byte and intermediate overwrites

The address read through the initial node’s `0x14` field also supplies an address incremented by `0x20`. The operation stores this derived address into fields and narrows it into bytes.

A character-typed byte is separately read at twice the address obtained through the principal-node traversal described above. It is converted to an integer, right-shifted by that address’s low eight bits, and narrowed to a byte.

The resulting byte is stored at displacement `0x08` from a separately loaded node and at displacement `0x11` from the principal node. Shift counts may range from zero through 255; executable behavior is not established for every count. Character signedness and right-shifting negative values remain unresolved.

### Terminal accesses and invocation

After the late decimal-100 group, further byte and word stores precede an ambient word read. The operation then reads the current word in the anchor’s `0x74` field.

The remaining order is:

1. Store that current word’s low halfword at its sum with the anchor address.
2. Store the ambient word’s low halfword at twice the node address used for the late decimal-100 byte store.
3. Read a character-typed byte at the sum of the anchor address and another previously saved traversal address; convert it to a represented 32-bit value.
4. Store the previously selected halfword at the ambient word plus the current `0x74` word; repeat the halfword store at the anchor-address sum.
5. Store word `0x45` at displacement `0x45` from the character-derived value.
6. Read another ambient address word, then an ambient data word, then the anchor’s current `0x44` word.
7. Store byte `0x44` at displacement `0x44` from the character-derived value.
8. Store the ambient data word at twice the newly read ambient address.
9. Store that ambient address’s low halfword at its sum with another previously saved traversal address.

The terminal invocation receives three represented 32-bit arguments:

- The character-derived value bitwise-ORed with `0x44`.
- The final ambient address word.
- The saved anchor `0x44` word.

The third argument is not reread after the final stores. No explicit memory operation follows the invocation if it returns normally.

## Acceptance examples

These are conditional static criteria, not executed tests. Each assumes execution reaches the relevant events.

1. **Stable-source carry boundary.** If all evaluated references to the initial arithmetic source have value `0xFFFFFFA6`, incoming carry zero produces contribution zero; incoming carry one produces contribution one. With a stable value of `0xFFFFFFA7`, the threshold is true and the conditional carry calculation is skipped.

2. **Distinct arithmetic observations.** If the address-calculation reference yields `0x1000`, incoming carry is zero, and the threshold reference yields `0xFFFFFFA7`, the fourth initial store targets `0x109E`, while the initial offset receives contribution one. The conditional carry reference is not evaluated.

3. **Conditional third reference.** If the threshold reference yields zero, the conditional carry expression is evaluated. If its arithmetic-source reference yields `0xFFFFFFA6` and incoming carry is one, the contribution is one regardless of the earlier address-calculation reference.

4. **Late ambient reads.** An initial store that changes the ambient base or additional addend affects the subsequent read of that location. The base is read first. Changing the early addend’s backing storage does not replace its saved value.

5. **Absolute-address timing.** If the second consecutive `0x09` byte store overlaps address `0xDB`, the following absolute word read incorporates that modification according to target byte order. Reading the word before those byte stores would violate the represented sequence.

6. **Byte arithmetic.** With fourth-argument byte `0xFF` and comparison contribution one, the arithmetic byte store writes `0x53` after narrowing. This specifies that event, not a final value protected from later aliasing.

7. **Constant-event ordering.** If all relevant stores complete, the first decimal-100 group precedes the `0x0C` byte store of `0x73`; that byte store precedes the `0x74` group; the `0x66` group precedes the later `0x20` word store of `0x73`.

8. **Saved terminal argument.** If a final store aliases the anchor’s previously read `0x44` field, the third terminal argument remains the saved word rather than the field’s new contents.

9. **Failure and completion.** An invalid intermediate address may prevent invocation without undoing earlier writes. If all accesses succeed and F-INDIRECT-01 returns normally, no further explicit store occurs.
