# F-232987963725

## Purpose

F-232987963725 searches a linked sequence for an entry whose associated record contains a requested 32-bit value. An optional caller-supplied slot serves both as a continuation position and as the location where a matching entry is reported.

The established behavior distinguishes three outcomes:

- A null container causes an immediate return without accessing the continuation slot.
- A matching entry causes an unresolved indirect transfer with the associated record address as its argument.
- Exhaustion causes an unresolved indirect transfer with zero as its argument.

The indirect transfers are material limitations of this contract. Their destinations, calling conventions, return behavior, and additional effects are not established. In particular, the function must not be described as returning the matching record through an ordinary return value.

The apparent intent is a resumable search: an empty continuation slot starts from the container’s first entry, while an occupied slot resumes after the entry it identifies. That interpretation is supported by the visible accesses, but does not establish container ownership, synchronization requirements, or a broader iterator API.

## Interface

### Inputs

| Input | Role | Established representation |
|---|---|---|
| Container address | Identifies storage containing the initial entry address | Address-bearing 32-bit value; zero selects the immediate-return case |
| Requested value | Value compared with each candidate’s associated record | 32-bit integer value |
| Optional continuation-slot address | Identifies a readable and writable location containing an entry address | Nullable address to a 32-bit slot |

The supplied representation uses 32-bit integer accesses for values that also serve as addresses. This contract follows that represented layout; it does not establish compatibility with a wider-pointer environment.

Equality is the only visible operation on the requested value. There is no visible ordering comparison, range check, conversion, masking, or arithmetic involving that value. Its signed interpretation therefore does not affect equality between identical 32-bit representations.

### Relevant layouts

Offsets are byte offsets from the respective base address.

| Storage | Offset | Field |
|---|---:|---|
| Container | `0x9C` | Initial entry address |
| Entry | `0x04` | Successor entry address |
| Entry | `0x08` | Associated record address |
| Associated record | `0x18` | Search value |
| Continuation slot | `0x00` | Entry address or zero |

Each listed field is accessed as a 32-bit quantity in the supplied representation. These offsets describe only the accessed fields, not complete object sizes, allocation layouts, or alignment guarantees.

### Outputs

There is no established ordinary return value.

The continuation slot, when supplied for a nonnull container, is explicitly cleared before the candidate search. On a match, it is subsequently assigned the matching **entry address**, not the associated record address.

The indirect match transfer receives the associated record address. The exhaustion transfer receives zero. No further arguments are established by the supplied representation.

### Preconditions

For defined operation along a particular path:

- Every field read on that path must be accessible with the required width.
- A nonnull continuation-slot address must identify storage that supports the required reads and writes.
- Every candidate examined must provide an accessible associated-record-address field and an accessible search-value field at the resulting record-relative address.
- Every successor field actually followed must be readable.
- The unresolved indirect transfer must have a valid destination and a compatible execution context.

The function visibly performs no validation that establishes these conditions.

## Behavior

### Null-container case

The container address is tested before any represented memory access.

If it is zero, the function returns immediately. It does not read or clear the continuation slot, even if a nonnull continuation-slot address was supplied. No search or indirect transfer is represented on this path.

Thus, a null container does not report exhaustion through the same mechanism as an empty nonnull container.

### Selecting the initial candidate

For a nonnull container, the first represented memory access loads the initial entry address from container offset `0x9C`.

This read occurs even when a supplied continuation slot will override that starting position. A valid occupied continuation slot therefore does not eliminate the requirement that the container’s initial-entry field be readable.

If no continuation slot is supplied, the loaded initial entry is the starting candidate.

If a continuation slot is supplied:

1. Its contents are read to determine whether they are zero.
2. When that observation is nonzero, the slot is read again to obtain an entry address, and that entry’s successor at offset `0x04` becomes the starting candidate.
3. The slot is written with zero before the candidate search proceeds.

The repeated slot reads are visible in the supplied representation. They are not evidence of an atomic snapshot or a concurrency guarantee. Under stable memory, they observe the same value. If another agent changes the slot between those reads, the representation does not establish a consistent continuation position.

An occupied continuation slot is not checked for membership in the container’s sequence. Its designated entry is not itself tested for a match: searching begins at its successor.

### Candidate examination

A zero candidate denotes exhaustion and takes the exhaustion path without reading candidate fields.

For each nonzero candidate, the visible examination order is:

- Read the associated record address from entry offset `0x08`.
- Read the search value from associated record offset `0x18`.
- Compare that 32-bit value with the requested value.

If the values differ, the successor address is read from the current entry at offset `0x04`. That successor becomes the next candidate.

If the values are equal, traversal stops at that entry. The matching entry’s successor is not read by the visible search path.

Consequently, under stable memory, the selected entry is the first match in traversal order from the chosen starting candidate. There is no evidence of indexing, sorting, backward traversal, duplicate elimination, or examination of entries before that starting point.

### Match handling

When a match is found:

- If a continuation slot was supplied, the matching entry address is written to it.
- The represented indirect match transfer follows, with the previously obtained associated record address as its sole visible argument.
- The supplied representation shows a return after that transfer.

The slot write precedes the transfer. This establishes the slot contents immediately before transfer, not necessarily after the entire invocation. The unknown destination may overwrite that slot, modify the container, change globals, release storage, or fail to return.

The record address used for the transfer is the one already read during candidate examination. It is not visibly reloaded after writing the continuation slot.

### Exhaustion handling

Exhaustion occurs when the selected starting candidate is zero or when a successor followed after a mismatch is zero.

The represented exhaustion transfer receives zero. No additional continuation-slot write occurs at exhaustion: for a supplied slot, the earlier clearing write remains the last explicit slot write by the visible function body.

The supplied representation shows a return after this transfer. Whether the actual indirect control flow returns normally is unresolved.

### Aliasing, mutation, and termination

No non-aliasing restriction is visibly enforced. If the continuation slot overlaps a field used by traversal, clearing or updating the slot changes that underlying storage.

The initial container field is read before the slot is cleared. A candidate address already selected by that read remains selected even if clearing the slot also clears the container’s initial-entry field.

Conversely, if the slot overlaps a successor or record-address field that is read later, the clearing write can affect traversal or record access. The function does not visibly snapshot the sequence.

There is no cycle detection or traversal bound. Under stable memory, a cycle containing no matching value can prevent termination. A cycle containing a reachable match can still terminate at the first encountered match.

No synchronization, locking, atomic operation, or mutation detection is represented.

## Side effects

### Explicit memory effects

For a nonnull container and nonnull continuation-slot address:

- One zero write occurs after start-position selection.
- A second write occurs only if a match is found, storing the matching entry address.

These writes may store a value already present; the supplied representation still expresses the accesses.

No explicit writes to the container, entries, or associated records are shown, except where the continuation slot aliases such storage.

### Ownership and lifetime

The visible body contains no allocation or explicit release operation.

That does not establish that an entire invocation preserves ownership or object lifetime. The unresolved destinations may acquire, retain, modify, or release storage. The contract therefore provides no ownership-transfer guarantee for the container, entries, records, or continuation slot.

### Errors

No explicit error result, diagnostic, exception handling, or recovery path is shown.

Malformed addresses, inaccessible fields, incompatible indirect destinations, concurrent mutation, and nonterminating traversal are not converted into reported search failures by the visible behavior. Their exact runtime consequences are outside the available evidence.

## Acceptance examples

These examples are conditional static expectations, not runtime test results. Except where aliasing is the subject, assume stable memory, distinct storage, accessible fields, and valid indirect destinations. Slot observations refer to the point immediately before the indirect transfer.

### 1. Null container preserves the supplied slot

Given a zero container address and a nonnull continuation slot containing an entry address:

- The slot is neither read nor written.
- No candidate is examined.
- Neither unresolved dependency site is reached.
- The function returns through the visible early-return path.

### 2. Empty nonnull container reports exhaustion

Given a readable nonnull container whose initial-entry field is zero, and a supplied slot containing zero:

- The container field is read first.
- The slot is read and then written with zero.
- No entry or record field is read.
- F-UNKNOWN-02 is reached with zero.

### 3. Search without a continuation slot

Given a chain of three entries with record values `10`, `20`, and `20`, and a requested value of `20`:

- The first two entries’ record values are examined in order.
- The first entry’s successor is followed.
- The second entry is selected.
- Its associated record address is passed to F-UNKNOWN-01.
- The third entry is not examined.

### 4. Continuation skips the designated entry

Given a slot containing the first entry’s address, a matching first entry, and a nonmatching second entry whose successor is zero:

- Search begins at the second entry.
- The first entry’s record value is not examined.
- The slot is cleared.
- Exhaustion reaches F-UNKNOWN-02 with zero.

The earlier matching entry does not satisfy this resumed search.

### 5. Successful continuation records an entry, not a record

Given a slot identifying an earlier entry and a reachable later match:

- The slot is cleared before candidate examination.
- On success, the slot receives the matching entry address.
- F-UNKNOWN-01 receives that entry’s associated record address.

The two output addresses have different roles even if some particular memory arrangement makes their numeric values equal.

### 6. Container-field aliasing preserves the selected start

Given an empty continuation slot that aliases the container’s initial-entry field:

- Because that shared field is zero, the selected starting candidate is zero.
- Clearing the slot leaves the same field zero.
- Exhaustion is reported through F-UNKNOWN-02.

If the shared field instead contains a nonzero entry address, it is treated as an occupied continuation slot: the start is that entry’s successor, not the entry itself. Clearing then changes the container field but does not replace the already selected candidate.

### 7. Exact-width equality

Given a requested value whose 32-bit representation is `0xFFFFFFFF`, a candidate with the same represented search value matches. A candidate containing `0x7FFFFFFF` does not.

No signed ordering interpretation is needed for either result.

### 8. A successor field is unnecessary after a match

Given a readable candidate record whose value matches, the visible search path does not read that candidate’s successor field. Accessibility of that field is not required by the local match path, though the unknown dependency may impose additional requirements.
