# F-99b1a0876d5f

## Purpose

F-99b1a0876d5f conditionally returns one 32-bit entry from a table associated with an acquired object. The lookup requires an initial eligibility result, an embedded-object continuation result, a feature result, and an unsigned index bound to permit progress.

Two settings control table selection and index direction. They are initially derived from object bytes, then exposed to a dependency through pointers to local 32-bit storage. Table preparation is attempted when the first selected table-pointer read yields zero.

The table selector is not frozen for the duration of resolution. The function reevaluates it for the initial table-pointer read, any post-preparation check, and the final table-pointer read used to address the entry. Unknown dependencies may affect later selector evaluations through a retained pointer.

The returned word has no established interpretation as a pointer, identifier, handle, or status. Zero represents both explicit rejection and a successfully retrieved zero entry.

“Eligibility,” “feature,” “reversal,” and “table preparation” describe inferred roles. The access sequence, widths, conditions, and result selection below are established by the supplied static representation.

## Interface

### Inputs and result

There are no explicit parameters.

Effective inputs include dependency results, dependency side effects, an acquired object, two indirectly dispatched methods, associated object fields, a 16-bit count, local selection settings exposed to a dependency, and table contents.

The result is one uninterpreted 32-bit word:

- Zero on the explicit rejection paths described below.
- A selected 32-bit table entry when entry access is reached.

There is no separate error channel. Invalid memory accesses or failed indirect calls are not specified as zero-result cases.

### Widths and layout

The supplied representation uses 32-bit pointers, 32-bit words, and byte-addressed offsets. The lookup index is treated as unsigned 32-bit. The count is read as unsigned 16-bit and widened to 32 bits. The selector occupies a signed 32-bit local word; the reversal setting occupies a 32-bit local word.

Multi-byte values use the represented target’s native layout. Byte order is not independently established.

Let the acquired object be the **base object**:

| Location | Observed use |
|---|---|
| Base object + 0x00 | 32-bit dispatch-table pointer |
| Base object + 0x60 | Embedded-object address; its first word is a dispatch-table pointer |
| Base object + 0x64 | 32-bit associated-data pointer |
| Base dispatch table + 0x158 | Indirect index-producing method |
| Embedded dispatch table + 0x0C | Indirect continuation-checking method |

The associated data object provides:

| Location | Observed use |
|---|---|
| Data + 0x18D | One-byte source for initial reversal setting |
| Data + 0x18C | One-byte source for initial selector |
| Data + 0x40 | 32-bit pointer to count-bearing object |
| Count-bearing object + 0x2E | Unsigned 16-bit count |
| Data + 0x3AC + 4 × current selector | 32-bit table-pointer slot |
| Selected table + 0x10 + 4 × effective index | Returned 32-bit word |

The first 0x10 bytes of each selected table are skipped. Their meaning is unknown.

### Preconditions

Each reached read, indirect call, and dependency call requires the memory and calling conditions needed for that operation. The function does not generally validate object pointers, dispatch pointers, method targets, table capacities, or selector ranges.

The acquired pointer is not explicitly checked for null before the embedded-object address is passed to the eligibility dependency. Whether that dependency can safely reject an invalid acquired object is unknown.

The associated-data pointer must support the flag reads before the later count expression is reached. A later zero-pointer count alternative does not make a null associated-data pointer safe.

For a valid entry retrieval, every selector evaluation used in addressing must identify readable storage, and the final table must contain the addressed entry. No ownership, lifetime, or stability guarantees are established by these access requirements.

## Behavior

### Preliminary calls and eligibility

The function calls the following dependencies in order:

1. F-93eb550dc612.
2. F-7b8e584345d2.
3. F-87be4aa684d1, whose result supplies the base-object pointer.
4. F-b7abcf60c990, with the address at base + 0x60.

The first two results are unused by the visible decision logic. Their side effects remain unknown.

If F-b7abcf60c990 returns zero, the function returns zero. Neither indirect method nor any associated-data field is accessed by the subsequent lookup logic.

### Index acquisition and embedded-object continuation

After a nonzero eligibility result, the function:

- Reads the base object’s dispatch pointer.
- Calls the method at dispatch offset 0x158 with the base object as receiver.
- Retains its result as an unsigned 32-bit index.
- Reads the embedded object’s dispatch pointer.
- Calls the method at dispatch offset 0x0C with base + 0x60 as receiver.

A zero result from the second method causes a zero return. The index-producing method has already run.

Only after the second method returns nonzero does the function load the associated-data pointer from base + 0x64. Changes to that field made by either indirect method can therefore affect the subsequent lookup.

The identities and broader contracts of both indirect methods are unknown.

### Initial settings and feature condition

The function reads associated-data bytes in this order:

1. Data + 0x18D.
2. Data + 0x18C.

Bit 2 of the first byte determines the initial reversal setting: zero when clear, one when set. No other bit affects that initial setting.

Bit 0 of the second byte determines the initial selector:

- Clear: selector 1.
- Set: selector 2.

Other bits do not affect the initial selector.

A copy of the original index is also written to a local 32-bit word. The visible lookup logic does not subsequently read that copy.

The function then calls F-3b037d560480 with no explicit arguments. A zero result causes a zero return without reading the count or invoking the adjustment dependency.

The visible condition also requires a nonzero selector value. The locally assigned initial selector is always 1 or 2; no explicit selector-adjustment call has occurred at this stage. Thus the initial assignment does not itself introduce another rejection case. The feature dependency’s broader behavior is not established.

The flags are not reread after the feature call. Changes to their underlying bytes during that call do not, by themselves, recompute the already derived local settings.

### Count and unsigned bound

On the continuing feature path:

- A zero associated-data pointer selects count zero in the count expression.
- Otherwise, the function reads the pointer at data + 0x40, then reads the unsigned 16-bit count at that object + 0x2E.

The zero-pointer alternative occurs after the flag dereferences and is not a general null-object safeguard. The count-bearing pointer is not separately checked for null.

The count is widened without sign extension. Lookup continues only if the unsigned 32-bit index is strictly less than that count.

Consequences:

- Count zero rejects every index.
- An index equal to the count is rejected.
- A result interpreted as a large unsigned index is rejected, even if the same bit pattern could represent a negative signed number.
- The largest possible count is 65,535, so the largest accepted index is 65,534.
- Rejection occurs before adjustment, table-pointer inspection, or table preparation.

### Adjustment and effective index

After a successful bound check, F-3dfc1640191e receives:

- The captured associated-data pointer.
- A pointer to the local 32-bit selector.
- A pointer to the local 32-bit reversal setting.

Its result is unused. The function consumes the settings as they stand after the call.

The selector, reversal setting, and saved index copy occupy successive 32-bit local words in the supplied representation. Only the selector and reversal addresses are explicit arguments. Their adjacency does not establish an aggregate argument, authorization to access neighboring storage, or any retention contract.

Only the low eight bits of the post-adjustment reversal setting control reversal:

- Zero low byte: retain the original index.
- Nonzero low byte: use captured count minus original index minus one.

For an index that passed the bound, reversal produces a value from zero through captured count minus one. This subtraction has no underflow on that path.

The count is not reloaded, and the bound is not repeated. Changes to the count-bearing object during adjustment do not replace the captured count used by reversal.

Once the effective index has been computed, table preparation does not trigger another reversal-setting check. A later change to the reversal local alone therefore does not recompute the effective index.

### Table resolution with selector reevaluation

For each table-pointer access, the slot address is formed from the captured data pointer and the selector value evaluated for that access:

**data + 0x3AC + 4 × current selector**

Selectors 1 and 2 identify data + 0x3B0 and data + 0x3B4 respectively. Adjustment may produce other values; no range validation follows it.

The observable resolution sequence is:

1. Evaluate the selector and read the corresponding table-pointer slot.
2. If that pointer is nonzero, skip table preparation and the post-preparation check.
3. If it is zero, call F-60950fd9e511 with the captured associated-data pointer.
4. After that call, reevaluate the selector and read the slot identified by its then-current value.
5. If this post-preparation pointer is zero, return zero.
6. Following either successful pointer check, reevaluate the selector again and read the corresponding table pointer again.
7. Use that final pointer to read and return the 32-bit word at table + 0x10 + 4 × effective index.

Neither the slot address nor the table pointer from a successful check is guaranteed to be reused for entry addressing.

This distinction matters because F-3dfc1640191e receives the selector’s address. Its retention behavior is unknown. F-60950fd9e511 is therefore not assumed to preserve the selector merely because its explicit argument list lacks that address. It could reach a retained selector pointer through other state.

For example, the initial read may inspect selector 1’s empty slot, preparation may change the selector to 2, and the post-preparation check and final access may then use selector 2’s slot.

The function has no explicit fallback to an earlier selector. An unknown dependency could nevertheless restore that selector through an escaped pointer.

A successful pointer check is not a validity guarantee for the final read: the final selector or table-pointer value may differ. In particular, a final pointer that becomes zero is not checked again before entry addressing.

There is at most one explicit preparation call. The function does not loop until a table appears, validate the final table’s capacity, or repeat the index bound.

### Address arithmetic

Entry scaling uses the effective unsigned 32-bit index. Its established bound limits 4 × effective index to at most 262,136; adding the 0x10 entry prefix yields at most 262,152. These offset calculations fit within 32 bits.

Adding an offset to a table base can still leave valid addressable storage. Likewise, multiplying an arbitrary adjusted signed selector by four or combining it with the data address may exceed the ordinary valid range. The supplied representation does not establish a portable overflow or address-wrap contract for such cases. They are not defined rejection paths.

## Side effects

The function visibly writes local state, including selection settings and a saved index copy. It performs no direct store to the base object, associated data, count-bearing object, or selected table.

External state may change through any dependency or indirect method:

- Preliminary dependencies execute before object acquisition.
- Both indirect methods execute before the associated-data pointer is loaded.
- The feature dependency executes after the flag reads but before the count read.
- Adjustment can modify the local settings through the supplied pointers and may have other unknown effects.
- Preparation runs only after the initial table-pointer read yields zero and may affect later selector evaluations and table reads.

No explicit allocation, deallocation, reference-count operation, or ownership transfer is visible. This does not establish that dependencies avoid such operations.

Passing local addresses does not establish that a dependency releases or retains them. A retained selector pointer can be relevant during a later call within this invocation; no valid use after the local storage ceases to exist is promised.

No locking, atomic operation, or synchronization guarantee is visible. Repeated reads must not be described as one atomic lookup.

## Acceptance examples

These are conditional deductions from static evidence, not executed tests. Each assumes all reached accesses and calls are valid and unspecified dependencies return normally.

1. **Eligibility rejection.** If F-b7abcf60c990 returns zero, the result is zero. Both preliminary calls and object acquisition have occurred; neither indirect method runs.

2. **Embedded rejection.** If eligibility succeeds but the embedded method returns zero, the result is zero. Index acquisition has occurred; associated-data flags and the feature call are not reached.

3. **Feature rejection.** If both earlier conditions succeed but F-3b037d560480 returns zero, the result is zero. Both flag bytes were read first; count inspection and adjustment do not occur.

4. **Unsigned boundary.** With count 5, index 5 is rejected before adjustment. Index 4 passes. With count 65,535, index 65,535 is rejected, as is index 0xFFFFFFFF.

5. **Forward retrieval.** With count 5, index 1, a selector that remains 1 throughout resolution, reversal low byte zero, and a stable nonzero table pointer at data + 0x3B0, the returned word is at table + 0x14.

6. **Reverse retrieval.** With count 5 and index 1, a nonzero reversal low byte produces effective index 3. A valid final table resolution returns the word at table + 0x1C.

7. **Reversal width.** A reversal setting of 0x00000100 does not reverse. A setting of 0x00000101 does.

8. **Adjusted selector without further mutation.** If adjustment changes selector 1 to 2 and it remains 2, all reached table-slot reads use data + 0x3B4. The function performs no explicit fallback. This does not prohibit a dependency from subsequently restoring selector 1.

9. **Selector changed during preparation.** Suppose adjustment retains the selector address and leaves selector 1. If its slot initially contains zero, preparation runs. If preparation writes selector 2 through the retained pointer and supplies a nonzero pointer in selector 2’s slot, the subsequent check uses selector 2. If both remain stable, the final entry access also uses selector 2’s table; selector 1’s slot need not be populated.

10. **Preparation still unsuccessful.** If the first pointer read is zero and the slot selected after preparation also contains zero, the function returns zero. Preparation runs once, even when the two reads select different slots.

11. **Fresh final pointer.** If a checked slot contains one nonzero table pointer but the final read obtains another valid pointer, entry retrieval uses the latter. No guarantee ties the returned entry to the checked table.

12. **Zero entry.** A valid selected entry containing zero produces zero despite all conditions succeeding.
