# F-4f70513ee9fc

## Purpose

F-4f70513ee9fc passes a selected context-relative record to one dependency, conditionally passes three record addresses to another dependency, updates a control field, and advances a record-selection field.

The established behavior is an ordered sequence of dependency calls and 32-bit field accesses. The record layout and control transitions suggest a small rolling-record mechanism, but that interpretation is inferred intent, not an established semantic meaning.

The function does not validate the context address, the selected record, or either control field. Its return carries no explicit result or status.

The function accepts two arguments:

| Argument | Established representation | Use |
|---|---|---|
| Context | A 32-bit integer used as an address base | Locates control fields and record addresses; also forwarded to both dependencies |
| Payload | An uninterpreted 32-bit value | Forwarded unchanged to F-148f046b5d07 |

The payload is not directly dereferenced, decoded, or stored by this function. Its interpretation by F-148f046b5d07 is unknown.

### Context-relative layout

Offsets are in bytes from the context address.

| Offset | Width | Established use |
|---|---:|---|
| `0xAB0` | 4 bytes | Control state, read after the first dependency returns and sometimes overwritten |
| `0xAB4` | 4 bytes | Record selector, read at multiple distinct times and incremented near return |
| `0xB54` | Not established | Beginning of the address sequence used for records |

Record addresses have a stride of `0x94` bytes, or 148 bytes. For a selector value \(j\), the address expression is:

\[
R(j)=\text{context}+0xB54+148j.
\]

This establishes address spacing, not the complete layout, size, validity, or ownership of a record. The function itself does not read or write record contents.

## Behavior

### 1. Select a record and invoke the first dependency

Before reading the control state, the function reads the 32-bit selector at offset `0xAB4` and computes its corresponding record address.

It calls F-148f046b5d07 with these arguments, in order:

1. The context.
2. The original 32-bit payload.
3. The selected record address.

This call occurs on every normal execution path, regardless of the control-state value.

The selector used to form this first record address is read before the call. It is not necessarily the selector used later. F-148f046b5d07 may modify the context; the caller makes no protective copy of either control field.

The selector is treated as signed in this initial address expression. Behavior for values that overflow the signed arithmetic is not established independently of the target execution model.

### 2. Read and dispatch on the post-call state

After F-148f046b5d07 returns, the function reads the 32-bit state at offset `0xAB0`.

The branch is chosen from this newly read value, not from any state that existed before the dependency call.

| State read | Call F-3678c8e0bd6c? | State write after that call, if any |
|---:|---|---|
| 0 | No | Write 1 |
| 1 | No | Write 2 |
| 2 | Yes, with the ordering specified below | Write 3 |
| 3 | Yes, with the ordering specified below | Write 2 |
| Any other 32-bit pattern | No | No direct state write |

For states 2 and 3, the function reads the selector again after reading the state. That selector is interpreted as an unsigned 32-bit value for the predecessor calculations.

### 3. Compute predecessor selectors when required

Let \(u\) be the unsigned selector read for the state-2 or state-3 branch.

The two derived selectors are:

| Condition | First predecessor \(P(u)\) | Second predecessor \(Q(u)\) |
|---|---:|---:|
| \(u=0\) | 2 | 1 |
| \(u=1\) | 0 | 2 |
| \(u\geq2\) | \(u-1\) | \(u-2\) |

These results arise from 32-bit unsigned subtraction and unsigned comparisons that detect subtraction wrapping. They are not general modulo-three normalization.

In particular:

- Selector 0 produces predecessors 2 and 1.
- Selector 1 produces predecessors 0 and 2.
- Selector 2 produces predecessors 1 and 0.
- Selector 3 produces predecessors 2 and 1 while retaining 3 as the current selector.

For larger selectors, both predecessor values continue decreasing arithmetically from the supplied value. No bound limits the selector to three records.

### 4. Invoke the second dependency with state-dependent ordering

For state 3, the function calls F-3678c8e0bd6c with:

1. The context.
2. \(R(P(u))\).
3. \(R(Q(u))\).
4. \(R(u)\).

After that dependency returns, the function writes 2 to the state field.

For state 2, the function calls F-3678c8e0bd6c with:

1. The context.
2. \(R(Q(u))\).
3. \(R(P(u))\).
4. \(R(u)\).

After that dependency returns, the function writes 3 to the state field.

Thus, states 2 and 3 exchange the order of the first two record-address arguments. The final record-address argument remains the record selected by \(u\).

The selector used for all three addresses comes from the same branch-local read. Mutations performed during F-3678c8e0bd6c cannot retroactively change the addresses already passed to that call.

The state write after the call is unconditional within the selected branch. If F-3678c8e0bd6c changes the state and returns normally, this function subsequently overwrites that change with 3 or 2, according to the branch chosen earlier. It does not reread the state to choose a different branch.

### 5. Advance the selector

After state handling, the function reads the selector at offset `0xAB4` again, adds one, and writes the result back to that field.

If the incremented result is exactly 3, it performs a second write, replacing 3 with 1.

For ordinary non-overflowing values:

| Selector at final read | Selector writes, in order | Final selector |
|---:|---|---:|
| -1 | 0 | 0 |
| 0 | 1 | 1 |
| 1 | 2 | 2 |
| 2 | 3, then 1 | 1 |
| 3 | 4 | 4 |

The wrap condition is equality with 3 after incrementing. It is not a range check, a saturation rule, or a general modulo operation.

The final read occurs after any second dependency call and after the direct state write. Consequently, selector changes made by either dependency may affect the final increment. The function does not necessarily advance the selector originally used for the first call.

The final increment is represented as signed 32-bit arithmetic. Its overflow case is not assigned a portable outcome by this contract.

## Side effects

### Direct field accesses

On a normal path, the direct accesses occur in this order:

1. Read the selector to form the record address for F-148f046b5d07.
2. Invoke F-148f046b5d07.
3. Read the state.
4. For state 2 or 3 only, read the selector and invoke F-3678c8e0bd6c.
5. Write the state when required by the selected branch.
6. Read the selector for advancement.
7. Write the incremented selector.
8. If that result equals 3, write selector 1.

For states outside 0 through 3, step 5 is absent. For states 0 and 1, step 4 is absent.
