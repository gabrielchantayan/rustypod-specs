# F-4665e635ff07

## Purpose

F-4665e635ff07 performs a gated search for a candidate whose two 32-bit fields exactly match two caller-supplied values.

The established behavior is:

- Invoke a prerequisite dependency.
- Search only if that dependency returns nonzero and at least one requested field value is nonzero.
- Obtain an initial candidate using the first argument.
- Examine candidates in the order supplied by two traversal dependencies.
- Return the first candidate whose fields at byte offsets `0x114` and `0x110` match the fourth and third arguments, respectively.
- Return zero when the gate rejects the operation, both requested values are zero, or traversal reaches a zero candidate before finding a match.

The second argument has no visible use.

**Inferred intent:** this resembles lookup within a dependency-defined collection using a two-component key. The available evidence does not establish the collection type, field meanings, or ownership model.

## Behavior

### 1. Evaluate the prerequisite

F-06f4ceb6a4f2 is invoked once, with no explicit arguments, before any decision about the requested pair.

A zero result causes an immediate zero return. Neither candidate-producing dependency is invoked, and the visible body performs no candidate-field reads.

Any nonzero result permits evaluation of whether the requested pair is eligible for searching. No distinction among nonzero prerequisite results is visible.

This call still occurs when the third and fourth arguments are both zero. Consequently, an all-zero request is not necessarily free of externally observable effects: the prerequisite dependency may have effects of its own.

### 2. Suppress an all-zero request

If the prerequisite result is nonzero but both requested values are zero, the function returns zero without beginning traversal.

If either requested value is nonzero, traversal begins. In particular:

- Third argument zero, fourth argument nonzero: search for that exact pair.
- Third argument nonzero, fourth argument zero: search for that exact pair.
- Both arguments nonzero: search for that exact pair.
- Both arguments zero: do not search, even if a candidate with two zero fields exists.

### 3. Obtain the initial candidate

For an eligible request, invoke F-4da55ebc4716 once, passing the first argument unchanged.

If its result is zero, return zero. No candidate fields are read, and F-978f92135a50 is not invoked.

If its result is nonzero, treat that result as the current candidate and evaluate it.

### 4. Evaluate a candidate

For each current nonzero candidate:

1. Read the 32-bit field at byte offset `0x114` and compare it with the fourth argument.
2. If those values differ, reject the candidate without reading its field at `0x110`.
3. If those values are equal, read the 32-bit field at byte offset `0x110` and compare it with the third argument.
4. If both comparisons succeed, return the current candidate immediately.

A successful match is the first matching candidate in the dependency-produced traversal order. The function does not inspect later candidates, perform duplicate detection, or verify uniqueness.

The comparisons are exact. No ordering comparison, normalization, masking, range test, or partial-match rule is visible.

### 5. Advance after a mismatch

After either comparison rejects a candidate, invoke F-978f92135a50 with that rejected candidate as its sole explicit argument.

Its result replaces the current candidate:

- Zero ends traversal and produces a zero return.
- Nonzero causes evaluation of the returned candidate using the same field-read order.

The first argument is not explicitly passed to this advancement dependency. The advancement dependency is not invoked for a matching candidate or for a zero candidate.
