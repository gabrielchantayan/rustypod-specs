# F-028ccf4c9466

## Purpose

- A specific pair of primary-object query results selects an early dispatch and bypasses all secondary-object processing.
- Otherwise, the function conditionally dispatches another primary-object operation, obtains a secondary object, and, when that object is non-null, performs an ordered sequence of object calls, temporary-value operations, and recipient notification.

The supplied static representation suggests media-controller behavior, but that interpretation does not establish playback, navigation, presentation, or ownership semantics. The contract below describes calls, values, memory relationships, and ordering rather than assigning those operations application-level meanings.

## Behavior

### Primary-object acquisition

The function first calls F-b7af80e829ec with no explicit arguments.

If that dependency returns a non-null pointer, the function subtracts 20 bytes from it and uses the resulting address as the primary object. This is an address adjustment, not an established copy, allocation, or ownership transfer.

If the dependency returns null, the adjustment is skipped, but execution still proceeds to primary-object dispatch. There is no explicit null-result recovery path. A null result therefore does not select a normal no-op return.

For every primary-object dispatch shown, the object’s current table pointer is read to locate the entry. The representation does not establish that earlier dependencies preserve the table or any associated global state.

### Early-dispatch selection

The function calls the primary-object entry at byte offset `0x1c0`, passing the primary object as its explicit argument.

Only if that call returns exactly 1 does the function call the primary-object entry at byte offset `0x1a4`, again passing the primary object.

The early path is selected only when:

- the `0x1c0` result is exactly 1; and
- the subsequently obtained `0x1a4` result is exactly 0.

On that path, the function dispatches through the primary-object entry at byte offset `0xf0`, with the primary object as the explicit argument. The supplied representation then shows a return.

Consequently, this path does not visibly obtain a secondary object, prepare either temporary region, invoke recipient notification, or execute the later cleanup calls.

A nonzero result other than 1 from `0x1c0` does not qualify for the early path and does not trigger the `0x1a4` query.

### Remaining primary-object preparation

If the early path is not selected, the function calls the primary-object entry at byte offset `0x190`, passing the primary object. This is the same offset represented by decimal 400 in the supplied material.

If that result is nonzero, the function calls the primary-object entry at byte offset `0xec`, passing the primary object. A zero result skips only this `0xec` call; it does not skip secondary-object acquisition.

No returned value from `0xec` is visibly used.

## Acceptance examples

These are conditional static acceptance criteria, not reports of executed tests.

1. **Exact early-path match.** Given valid dispatchable objects and normally returning calls, results of 1 from primary `0x1c0` and 0 from primary `0x1a4` must select primary `0xf0`. No secondary-object acquisition or recipient notification is then visible.

2. **Noncanonical true-like value.** If primary `0x1c0` returns 2, primary `0x1a4` must be skipped. Processing proceeds to primary `0x190`; treating every nonzero first result as early-path eligibility would change the behavior.

3. **Second query rejects the early path.** If primary `0x1c0` returns 1 and `0x1a4` returns any nonzero value, processing must continue through `0x190`, not `0xf0`.

4. **Conditional preparatory dispatch.** A zero result from primary `0x190` skips `0xec` but still reaches F-be45cd43f92d with zero. A nonzero result adds the `0xec` call before that dependency.

5. **Null secondary object.** If F-be45cd43f92d returns null, the next visible branch action is F-a817d8d58c10. The normal secondary-object sequence, recipient dispatch, and cleanup sequence are not selected.

6. **Successful fallthrough ordering.** For a non-null secondary object and normally completing calls, recipient `0xd0` occurs after F-a3642b19087c and before F-c1466ea05103. F-54033250428c follows F-c1466ea05103 and receives a pointer-slot address, not merely the secondary-object value.

7. **Null primary result.** A null result from F-b7af80e829ec must not be modeled as a successful early return. The next visible action attempts dispatch through the null primary-object address; the environment-specific outcome is undocumented.

8. **Aliased textual arguments.** F-a3642b19087c receives identical addresses for its second and third arguments, not merely separately stored strings with equal contents.
