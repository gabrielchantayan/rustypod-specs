# F-21db160d8c99

## Purpose

F-21db160d8c99 writes a fixed-layout, five-byte region supplied by its caller. It places the current value of a global 32-bit datum at byte offset 0, then places a caller-supplied eight-bit value at byte offset 4.

The established behavior is two ordered assignments. The supplied evidence does not establish what the global value represents or what meaning the trailing byte carries. Initialization of a small record is a plausible intent, but neither a record type nor a particular application-level interpretation is established.

This contract describes the supplied static representation. No runtime tests have been performed.

## Interface

The function receives two inputs:

| Input | Established representation | Role |
|---|---|---|
| Destination | Pointer to a four-byte storage unit | Identifies the beginning of the region to modify. |
| Trailing value | One-byte value, eight bits wide | Supplies the value written at byte offset 4. |

The function also reads one global datum represented as four bytes, or 32 bits. Its value is not established by the supplied evidence. It is a runtime source of data, not an established literal constant.

The function returns no value. It provides no explicit success indicator, error code, previous contents, or destination pointer as an output. Its observable result is the destination-memory modification.

### Destination layout

Offsets are measured in bytes from the supplied destination address.

| Offset | Width | Assigned content |
|---|---:|---|
| 0–3 | Four bytes | The 32-bit value obtained from the global datum |
| 4 | One byte | The supplied trailing value |

The second write is at byte offset 4, not byte offset 1. The pointer arithmetic in the supplied representation advances by one four-byte storage unit before selecting the byte to write.

Five bytes is the extent directly modified on an ordinary completed invocation. It is not evidence that a containing object has a total size of five bytes. A larger object may include additional fields or padding that this function does not explicitly modify.

## Behavior

### Ordered assignments

On the normal path, the function performs the following effects in order:

1. It obtains the 32-bit value of the global datum and assigns that value to the destination region beginning at offset 0.
2. It assigns the eight-bit trailing input to the destination byte at offset 4.
3. It returns without a result value.

The global value must be obtained before it can be assigned to the destination. The second assignment follows the first in the supplied representation.

There is no conditional branch, loop, explicit function call, or alternative normal path. Neither the destination’s previous contents nor the trailing value selects different behavior.

### Width and value handling

The first assignment transfers a 32-bit value. The supplied representation does not perform arithmetic, masking, sign conversion, or application-level interpretation on that value.

The trailing input is already one byte wide at this interface. Every eight-bit pattern is handled by the same assignment. There is no established special treatment for zero, the high bit, or an all-ones byte. If a caller starts with a wider value, the conversion to this interface’s one-byte input occurs outside the behavior established here.

The function does not construct or assign a combined 40-bit scalar. It performs a four-byte assignment and a separate one-byte assignment. Consequently, the evidence does not support treating the entire five-byte update as a single atomic operation.

### Existing contents

The function does not explicitly read the destination’s old contents. On successful completion, the previous values at offsets 0 through 4 have been replaced.

The function contains no explicit write before offset 0 or after offset 4. In an ordinary memory region without concurrent writers or special access semantics, bytes outside the five-byte region remain unchanged by this function.

That boundary does not establish a broader guarantee about memory-mapped devices, write-triggered hardware behavior, or other agents accessing the same storage.

### Aliasing

The supplied representation contains no explicit check or prohibition against overlap between the destination and the global datum. If the destination aliases that datum, the destination writes may also modify the global storage through the alias.

Where such accesses are valid, the value used for the first assignment is obtained before that assignment changes overlapping storage. The trailing-byte assignment occurs afterward and can modify a byte of the global datum if offset 4 overlaps it.

This is not a general promise that every overlapping address arrangement is valid. Alignment, object-access rules, mapped-memory behavior, and the actual execution environment remain relevant.

## Acceptance examples

The following are conditional acceptance criteria, not observed test results.

### Ordinary completion

Given valid writable destination storage, a stable readable global datum, and no interfering access:

- Destination offsets 0 through 3 must contain the 32-bit global value used by the invocation, represented according to the target’s byte order.
- Destination offset 4 must contain the supplied eight-bit value.
- The function must return without a result value.
- There must be no explicit destination write outside offsets 0 through 4.

### Distinct trailing-byte patterns

Under the same valid-memory conditions, trailing inputs of zero, a value with only its highest bit set, and an all-ones byte must each be stored at offset 4 without selecting a different path.

These cases distinguish direct byte assignment from an unsupported interpretation such as Boolean normalization or signed-value rejection.

### Changing global value between invocations

If the global datum is changed between two invocations, remains stable during each invocation, and does not alias either destination, each invocation must use the global value available to that invocation. The first field must not be treated as a fixed literal merely because a particular execution happens to observe the same value repeatedly.

### Larger destination region

If a caller supplies a larger ordinary writable region, bytes after offset 4 must not be explicitly initialized or cleared by this function. For example, a byte at offset 5 retains its previous value in the absence of other effects.

### Byte-order-dependent representation

If the global value is `0x11223344` and the trailing input is `0xA5`, the five-byte result is conditional on target byte order:

- On a little-endian target: `44 33 22 11 A5`.
- On a big-endian target: `11 22 33 44 A5`.

The supplied evidence does not select either target.

### Insufficient destination storage

A destination that permits the first four-byte assignment but not the byte at offset 4 does not satisfy the preconditions. A clean failure result, unchanged destination, or automatic rollback is not an acceptance requirement. The exact outcome is documented_only.
