# F-638154d9f918

## Purpose

F-638154d9f918 produces six destination byte streams from eight source byte streams. At each processed position, it copies one source byte unchanged and computes five weighted, fixed-point results, each saturated to the byte range.

Source traversal advances by five units per group; destination traversal advances by six. A five-to-six resampling operation is **inferred intent**, not an established format contract. The supplied representation does not establish image dimensions, channel meanings, coefficient values, or the physical arrangement of the streams.

This contract distinguishes:

- **Established static evidence:** accesses, calls, arithmetic, and sequencing visible in the supplied representation.
- **Inferred intent:** interpretations consistent with those operations but not independently established.
- **documented_only:** unresolved behavior requiring dependency implementations, coefficient contents, or execution semantics not supplied here.

No runtime tests have been performed.

## Interface

### Arguments and result

The function receives two address-bearing arguments in a 32-bit representation:

1. **Source descriptor address.** A 32-bit field at byte offset 4 is read and passed to F-d7be9cfb4000.
2. **Destination descriptor address.** A signed 32-bit field at byte offset 0 supplies the number of byte positions processed within each group.

The function has no explicit return value or status result. Its direct outputs are destination byte writes and changes to invocation-local traversal records. Dependency calls may have additional effects.

“Source” and “destination” describe their visible uses; they do not establish complete descriptor types or ownership.

### Storage preconditions

Successful execution requires readable descriptor fields, readable coefficient locations, and source and destination storage sufficient for every scheduled byte access. The descriptors must also satisfy the unknown requirements of F-0910cb70418c.

The function performs no visible null, bounds, overlap, selector-validity, or dependency-result checks. It does not establish buffer sizes from the destination count.

Fourteen distinct invocation-local traversal records are supplied to dependencies: eight source records and six destination records. Their visible arrangement supports four consecutive 32-bit words per record:

| Byte offset | Visible use |
|---:|---|
| 0 | Updated after each executed group |
| 4 | Not directly inspected or changed by this function |
| 8 | Not directly inspected or changed by this function |
| 12 | Read as a signed 32-bit advance factor after each group |

This supports a 16-byte visible record layout, not a complete dependency contract. Initialization requirements, additional dependency accesses, and retained references are **documented_only**.

## Behavior

### Establishing traversal parameters

The function first reads a signed 32-bit coefficient, designated A, and retains that value for the entire invocation.

It then reads the source descriptor’s 32-bit field at offset 4 and calls F-d7be9cfb4000 with that field and the integer 5.

Let the returned 64-bit quantity be \(R\). Two quantities are derived from it:

- \(q\): the low 32 bits interpreted as signed.
- \(s\): the unsigned result of logically shifting \(R\) right by 33 bits.

Thus \(s\) has at most 31 significant bits. The outer-loop limit is the signed 32-bit expression \(L=5q\), subject to the overflow qualifications below.

After the dependency returns, the function reads and retains the destination descriptor’s signed 32-bit field at offset 0. Call this count \(W\). Subsequent descriptor changes do not cause \(W\) to be reread.

The packed return value’s meaning is unknown. Neither division semantics nor a conventional quotient/remainder interpretation is established.

### Initializing records

F-0910cb70418c receives fourteen calls in this order:

| Records | Descriptor | Fixed argument | Selectors in call order |
|---|---|---:|---|
| Eight source records | Source descriptor | 2 | \(s-1,s,s+1,s+2,s+3,s+4,s+5,s+6\) |
| Six destination records | Destination descriptor | 2 | \(0,1,2,3,4,5\) |

Each call also receives the address of its distinct traversal record. Return values are not used.

Source-selector arithmetic is unsigned 32-bit arithmetic. In particular, \(s=0\) produces \(2^{32}-1\) for the first selector. No local boundary correction or rejection occurs.

All fourteen initialization calls precede the outer-loop condition. They therefore occur even when no groups will execute or when \(W\leq0\). Initialization calls can affect descriptors, globals, or earlier records to the extent permitted by their unknown implementation; this function does not establish preservation guarantees.

### Group traversal and address acquisition

A signed 32-bit progress value starts at zero. A group executes while progress is less than \(L\), and progress increases by 5 after each completed group.

When \(5q\) is representable:

- Positive \(q\) produces exactly \(q\) groups.
- Zero or negative \(q\) produces no groups.

At the beginning of each group, F-33d55115462b is called for all eight source records in initialization order, followed by all six destination records in initialization order. Each result becomes that stream’s byte-address base for the group.

All fourteen calls complete before the function’s explicit source-byte reads or destination-byte writes for that group. These calls are not established to be pure lookups. Later calls may change records, coefficients, descriptors, or storage associated with earlier results.

### Per-position reads and writes

Within each group, positions are processed in ascending order from 0 through \(W-1\). No positions are processed when \(W\leq0\).

Let \(x_0,\ldots,x_7\) denote the eight source bytes at the current position, indexed by source-record order. Each has the numerical range 0 through 255.

Their explicit read order is:

\[
x_0,\ x_2,\ x_1,\ x_3,\ x_4,\ x_5,\ x_6,\ x_7.
\]

All eight reads precede the first destination store. The retained byte values supply all six outputs for that position.

The destination stores occur in destination-record order:

\[
y_0,\ y_1,\ y_2,\ y_3,\ y_4,\ y_5.
\]

Each is one byte at its destination base plus the current position.

Consequently:

- A destination store cannot alter the already-retained source values for the same position.
- It can alter future source reads if storage overlaps.
- If destination addresses overlap, later stores occur after earlier stores; no overlap-specific handling exists.
- A destination store can affect later coefficient reads if the addressed storage aliases coefficient storage.

### Coefficient identities, widths, and read instances

A through I are contract labels for nine coefficient locations, not external symbols.

Distinct reads of one location must not be merged merely because they usually return equal values. In particular, E, D, and F each have a retained snapshot and a separate expression read at the same position.

| Location | Interpretation and read instances |
|---|---|
| A | Signed 32-bit value, read once before the first dependency call; retained throughout the invocation |
| B | Signed 16-bit coefficient used in \(y_1\) |
| C | Low 16 bits interpreted as signed for \(y_1\); a separate full 32-bit read used in \(y_5\) |
| D | 32-bit snapshot \(D_{\mathrm{snap}}\) retained for \(y_5\); separate 32-bit read \(D_{\mathrm{expr}}\) for \(y_1\) |
| E | 32-bit snapshot \(E_{\mathrm{snap}}\) retained for \(y_5\); separate 32-bit read \(E_{\mathrm{expr}}\) for \(y_1\) |
| F | 32-bit snapshot \(F_{\mathrm{snap}}\) retained for \(y_4\); separate 32-bit read \(F_{\mathrm{expr}}\) for \(y_2\) |
| G | 32-bit read used in \(y_3\) |
| H | 32-bit read used in \(y_3\) |
| I | 32-bit read used in \(y_5\) |

The first use of C narrows its value to signed 16 bits. This narrowing does not establish that the underlying physical memory transaction is necessarily a 16-bit load.

The established coefficient and store boundaries at each position are:

1. Store \(y_0\).
2. Read and retain \(E_{\mathrm{snap}}\), then read and retain \(D_{\mathrm{snap}}\).
3. Evaluate \(y_1\), including **new reads** \(E_{\mathrm{expr}}\) and \(D_{\mathrm{expr}}\), plus B and the narrowed C value.
4. Store \(y_1\).
5. Read and retain \(F_{\mathrm{snap}}\).
6. Evaluate \(y_2\), including a **new read** \(F_{\mathrm{expr}}\).
7. Store \(y_2\).
8. Evaluate \(y_3\) using G and H, then store it.
9. Evaluate \(y_4\) using the retained \(F_{\mathrm{snap}}\), then store it.
10. Evaluate \(y_5\) using retained \(D_{\mathrm{snap}}\) and \(E_{\mathrm{snap}}\), together with separate full-width C and I reads, then store it.

A total read order among operands within an individual expression is not established. For example, the E and D expression reads for \(y_1\) must not be assigned an order solely from the expression’s textual arrangement.

The equalities

\[
E_{\mathrm{snap}}=E_{\mathrm{expr}},\quad
D_{\mathrm{snap}}=D_{\mathrm{expr}},\quad
F_{\mathrm{snap}}=F_{\mathrm{expr}}
\]

require an explicit stability assumption covering their respective read intervals. They are not unconditional properties of this function.

### Arithmetic width

The formulas identify contributions, not permission to use arbitrary-precision accumulators.

The weighted expressions mix 32-bit coefficients with unsigned, zero-extended byte operands. Their unsigned operations use low-32-bit arithmetic. The completed 32-bit accumulator is interpreted as signed for saturation. Saturation therefore applies after the represented 32-bit arithmetic, not to an unlimited-precision sum.

For representable intermediate arithmetic, the formulas have their ordinary integer meaning. Where unsigned operations wrap, widening the expression and clamping only afterward can produce different results.

The signed B and narrowed-C products in \(y_1\), including the factor 64, fit within signed 32-bit range for all byte inputs and signed 16-bit coefficients. This does not establish that the entire accumulator is representable as an ordinary signed sum.

Overflow-sensitive signed operations elsewhere include limit formation, traversal-record advances, and address calculations. Exact behavior for those cases remains **documented_only** without executable semantics. No language-level signed-overflow rule is imposed here.

### Advancing records

After every executed group, including one with no processed positions, the function advances records in this order:

1. All eight source records, in initialization order.
2. All six destination records, in initialization order.

For each source record, its first 32-bit word is increased by 20 times its current signed word at offset 12. For each destination record, its first word is increased by 24 times its current signed word at offset 12.

These are literal scales of 20 and 24. They do not establish the element type or layout of the external byte streams.

The advance factors are read from the records after group processing. Mutations by dependencies or aliased writes can therefore affect them; original factors are not independently retained.

All fourteen advances occur even after the final group. The outer progress increment follows them.

## Side effects

Directly established effects include:

- Eight source-byte reads and six destination-byte stores per processed position.
- Coefficient reads with the distinct snapshot and expression-read lifetimes specified above.
- Descriptor-field reads.
- Fourteen initialization calls.
- Fourteen address-acquisition calls per executed group.
- Updates to the first word of every traversal record after each executed group.

No allocation, deallocation, ownership transfer, or finalization operation is directly visible. The traversal records occupy invocation-local storage.

This does not establish that dependencies allocate nothing, release nothing, retain no addresses, or preserve globals. Dependency ownership and lifetime effects remain **documented_only**.

There is no visible recovery or rollback. Invalid storage, failed dependencies, or unsupported selectors are not converted into a defined function-level error. An interruption after processing begins may leave partial destination results and partially advanced records.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Arithmetic examples assume execution reaches the relevant operations and no unspecified overflow invalidates the stated calculation.

1. **No groups.** If \(q=0\), all fourteen initialization calls occur. No address-acquisition calls, explicit source-byte reads, destination-byte stores, or record advances follow.

2. **Nonpositive position count.** If \(q=1\) and \(W\leq0\), one group executes. It performs fourteen address-acquisition calls and fourteen record advances, but no per-position byte processing.

3. **One group, two positions.** If \(q=1\) and \(W=2\), sixteen source-byte reads and twelve destination-byte stores occur through the explicit processing path. Each record advances once afterward.

4. **Copied byte.** If \(x_1=231\), \(y_0=231\), independent of coefficient values, provided that store is reached.

5. **Truncation and saturation.** Completed signed accumulators \(2^{20}-1\), \(2^{20}\), \(-1\), \(255\cdot2^{20}\), and \(255\cdot2^{20}+1\) produce 0, 1, 0, 255, and 255 respectively.

6. **Signed narrowing.** If the first C observation has low 16 bits equal to 65535, \(C_{16}=-1\). This neither fixes the later \(C_{32}\) observation nor makes its interpretation signed 16-bit.

7. **Separate E observations.** Conditional on a permitted execution observing \(E_{\mathrm{snap}}=2^{20}\) and \(E_{\mathrm{expr}}=0\), let \(x_3=x_4=1\), all other source bytes be zero, and all other relevant coefficient observations be zero. Then \(y_1=0\) and \(y_5=1\). Reusing the expression read for \(y_5\), or the snapshot for \(y_1\), violates the specified read distinction.

8. **Separate F observations.** Conditional on observing \(F_{\mathrm{snap}}=2^{20}\) and \(F_{\mathrm{expr}}=0\), let \(x_1=x_6=1\), all other source bytes be zero, and all other relevant coefficient observations be zero. Then \(y_2=0\) and \(y_4=1\). This example does not establish that unsynchronized concurrent modification is supported.

9. **Selector boundary.** If \(s=0\), the first source initializer receives \(2^{32}-1\). Its validity is determined by the unknown dependency contract.

10. **Aliased source and destination.** A \(y_0\) store overlapping a current-position source byte cannot change that position’s retained inputs. It can affect later positions. A store overlapping coefficient storage can affect coefficient reads that follow it.
