# F-20e21ec9b4c5

## Purpose

F-20e21ec9b4c5 conditionally copies a 32-bit value from a caller-supplied record into a location selected by that record, then clears the record’s location selector.

The established behavior is a conditional write followed by a reset. If the selector is initially zero, the function does not perform either write. If it is nonzero, the function writes the record’s first 32-bit field at byte offset `0x18C` from the address represented by the selector, then writes zero to the selector field.

A possible intent is to transfer a stored value into another object and detach the record from that object. That interpretation is inferred, not established. The evidence does not identify the value’s meaning, the destination object’s type, or any ownership relationship.

## Interface

**Input:** One pointer to a record accessed as consecutive 32-bit fields.

| Byte offset | Width | Role |
|---|---:|---|
| `0x00` | 32 bits | Value copied when the selector is nonzero |
| `0x04` | 32 bits | Zero/nonzero selector; when nonzero, also supplies the destination base address |

The source value is treated as an uninterpreted 32-bit quantity. No signed comparison, arithmetic transformation, validation, or conversion is shown for that value.

The selector is tested against zero. Every nonzero bit pattern follows the write path; no additional validity test is shown.

**Output:** No return value. Observable results are memory effects, subject to valid accesses and normal completion.

**Access preconditions:**

- The input pointer must permit reading the 32-bit selector at offset `0x04`, including when the selector is zero.
- On the nonzero path, the first 32-bit field must also be readable.
- The selector field must be writable on the nonzero path.
- The destination address formed from the nonzero selector and byte offset `0x18C` must permit a 32-bit write.
- Accesses must meet the execution environment’s alignment and memory-access requirements.

The evidence does not establish a null-input exception, an alignment-repair mechanism, or a recoverable error result. These are access requirements, not checks performed by the function.

The displayed record accesses cover two four-byte fields. They do not establish the complete size or type of the caller’s allocation.

## Behavior

### Zero selector

The function first examines the 32-bit field at input offset `0x04`.

If that field is zero:

- The destination-writing operation is skipped.
- The first field is not read by the shown operation.
- Neither input field is written.
- The function returns without a result value.

The zero case does not access a destination derived from address zero. In particular, it does not write to address `0x18C`.

### Nonzero selector

If the selector is nonzero, the function performs two ordered memory updates:

1. It writes the 32-bit value from input offset `0x00` to the address designated by the selector plus `0x18C` bytes.
2. It writes the 32-bit value zero to input offset `0x04`.

The displacement is 396 bytes. It is not 396 elements and is not scaled by the size of a 32-bit field.

The copied value is not added to the destination’s existing contents. The destination is overwritten with the source value. The operation does not require reading the destination’s previous contents in the supplied representation.

The destination write precedes the selector reset. The function therefore does not establish a clear-first protocol. If execution cannot complete the destination write, the evidence does not establish that the selector will nevertheless be cleared.

### Read ordering and stability

The supplied representation references the selector both for the initial condition and for destination-address formation. It does not show a separately retained selector snapshot.

For ordinary stable memory, the selector used to choose the branch and the selector used to form the address have the same value. A stronger guarantee under concurrent modification, volatile storage, or memory-mapped I/O is not established.

Within the destination assignment, both the source value and destination address must be obtained before the write can complete. The evidence does not establish a total observable ordering between the source-value read and the selector access used to form that address. It also does not establish physical load counts, atomicity, or memory barriers.

### Aliasing

No non-aliasing check appears.

If the destination overlaps the selector field, the destination write occurs first and the explicit zero write follows. Under valid ordinary memory semantics, the selector field ends as zero; the copied value is not its final value.

If the destination is exactly the first field, the copy writes that field’s own value back to itself, followed by clearing the selector. The function does not otherwise explicitly clear the first field.

Partial overlaps are not rejected by any shown validation. Their legality and detailed consequences depend on the target’s alignment and memory semantics. The contract does not assume that the input record and destination belong to separate allocations.

### Address arithmetic and width

Both accessed record fields and both writes are 32 bits wide.

The selector stores only a 32-bit quantity. The representation uses that quantity as an address base and adds the constant byte displacement. It does not establish a wider-address extension rule, checked addition, or an overflow branch.

Consequently, address behavior near the representable limit is not specified here as either wrapping or trapping. An accepted ordinary-memory invocation requires a valid destination under the actual target’s address arithmetic.

## Side effects

On the nonzero path, normal completion performs:

- One 32-bit write at the selected base plus `0x18C`.
- One subsequent 32-bit zero write to the selector field.

No ownership transfer or memory release is established. Clearing the selector changes the record’s contents; it does not demonstrate destruction, reference-count adjustment, or release of the selected storage.

The function supplies no status distinguishing a successful destination write from an access failure. Fault handling, partial effects after an invalid access, and recovery behavior are outside the supplied evidence.

## Acceptance examples

These examples are conditional specifications, not executed tests. Except where stated otherwise, assume stable ordinary memory, valid accesses, and no unintended overlap.

### Zero selector leaves memory unchanged

Given a record whose first field contains any 32-bit value and whose selector is zero, normal execution leaves both fields unchanged. No destination write is attempted.

This remains the expected behavior regardless of the first field’s value because that field is not needed on the zero path.

### Nonzero selector copies and clears

Given a first field of `0x12345678` and a selector designating a valid base address:

- The four-byte destination at base plus `0x18C` becomes `0x12345678`.
- The selector becomes `0x00000000`.
- The first field remains `0x12345678` if the destination does not overlap it.

The destination’s previous value is irrelevant to the copied result.

### Zero is a valid copied value

Given a first field of zero and a nonzero valid selector, the function still takes the write path. It writes zero to the destination and then zero to the selector.

The condition concerns the selector, not the value being copied.

### Repeated invocation

After a normally completed nonzero invocation, a second invocation on the same unchanged record observes a zero selector and performs no write.

This example assumes no intervening modification and ordinary storage in which the selector reset persists.

### Destination aliases the selector

If valid target address arithmetic makes the destination coincide exactly with the selector field, the function first stores the source value there and then stores zero there. The final selector value is zero.

The example establishes the order of the two writes, not whether a particular memory layout can safely realize that alias.

### Invalid destination is not validated

A nonzero selector alone is insufficient for a valid invocation. If its derived destination is inaccessible, the function provides no shown validation or error-return path. No successful copy, selector reset, or normal return may be promised for that case.
