# F-352a899fb784

## Purpose

F-352a899fb784 performs a selector-specific reset for one of two supported slots, updates associated state through dependencies, and optionally performs an additional sequence ending in a notification-like call.

The established behavior consists of explicit memory writes and ordered dependency invocations. “Reset,” “slot,” and “notification-like” describe the apparent intent; they do not establish the application meaning of the affected fields or calls.

Selectors other than 0 and 1 cause an early return. The supplied representation nevertheless reads one global base value before testing the selector.

## Interface

### Inputs

| Input | Width and interpretation | Established use |
|---|---|---|
| Context token | Opaque 32-bit value | Passed to F-b9d333145f3e only when the optional branch is taken. |
| Selector | Unsigned 32-bit integer | Accepted only when equal to 0 or 1; selects table entries, state fields, and a record. |
| Optional-action control | 32-bit integer | Zero skips the optional branch. Every nonzero value takes it, including negative values under a signed interpretation. |

No return value is specified. Successful completion and rejection of an unsupported selector both return without an explicit result.

### Referenced storage

The following labels describe storage roles, not source symbols or public API names:

- **State base:** a global address value used for two arrays of 32-bit fields and two arrays of byte fields.
- **Handle-table base:** a global address value used to read one 32-bit entry per accepted selector.
- **Record-array base:** a global address value used to select a record with a stride of `0x124`, or 292 bytes.

The record stride is established. A complete record type, allocation extent, or ownership model is not.

### Preconditions

For a supported selector, normal completion requires:

- Valid writable destinations for every explicit state and record write.
- A valid readable handle-table entry.
- Dependency calls that return normally and satisfy any requirements imposed by later dependencies.
- An address model in which the described address calculations identify the intended storage without invalid wraparound.
- Valid storage associated with dependency results whenever those results are subsequently used.

There is no local pointer validation, capacity check, synchronization, or error recovery.

An unsupported selector avoids the selected storage accesses, but it does not avoid the initial read of the state-base global.

## Behavior

### 1. Capture a base and validate the selector

The function first captures the state-base value.

It then compares the selector as an unsigned 32-bit quantity against 1. If the selector is greater than 1, it returns immediately.

Consequently:

- 0 and 1 are accepted.
- 2 is rejected.
- The all-ones 32-bit selector, `0xffffffff`, is rejected rather than treated as a negative index.
- No dependency call or explicit memory write occurs on this early-return path.
- The initial state-base read still occurs.

### 2. Reset selected scalar state

For an accepted selector \(s\), four writes occur in this order:

| Order | Destination | Width | Value |
|---|---|---:|---:|
| 1 | Current state base + \(4s\) | 32 bits | 0 |
| 2 | Captured state base + 8 + \(4s\) | 32 bits | 0 |
| 3 | Captured state base − `0x4a` + \(s\) | 8 bits | 0 |
| 4 | Captured state base − `0x48` + \(s\) | 8 bits | 0 |

The first write uses a state-base access appearing after validation; the remaining three use the value captured before validation. They must not be described as necessarily using the same base if external mutation of the global is possible.

The 32-bit writes store zero as a complete word. The byte writes affect only their addressed bytes.

### 3. Invoke the initial context/handle dependency

An unresolved dependency is called without an explicit argument in the supplied representation. Its returned 32-bit value becomes the first argument to F-23aadb16b673.

After that producer returns, the function reads the selected 32-bit handle-table entry at:

- Handle-table base + \(4s\).

F-23aadb16b673 receives:

1. The producer’s returned value.
2. The selected handle-table value.

The return value of F-23aadb16b673, if any, is not used.

This call occurs before the record-array base is obtained for the following reset. Any effect of these dependencies on global bases is therefore potentially relevant. The function does not establish that they preserve those globals.

### 4. Reset selected record fields

The selected record displacement is \(292s\). The supplied representation converts the selector to a signed 16-bit value before this multiplication. Since only 0 and 1 reach this point, the conversion cannot change the selected value.

The record-base global is accessed after F-23aadb16b673 returns. The representation captures a base for subsequent writes and separately accesses the base for the first record-byte write. Without an external mutation, both accesses identify the same selected record. Atomicity or snapshot consistency is not established.

The following writes occur in order, with offsets relative to the selected record:

| Order | Offset or offsets | Width per write | Value |
|---|---|---:|---:|
| 1 | `0x00` | 8 bits | `0x00` |
| 2 | `0x46` | 8 bits | `0xff` |
| 3 | `0x47` | 8 bits | `0xff` |
| 4 | `0x48` | 8 bits | `0xff` |
| 5–17 | `0x4a`, `0x4c`, …, `0x62`, ascending | 16 bits | `0xffff` |
| 18 | `0x40` | 8 bits | `0xff` |
| 19 | `0x41` | 8 bits | `0xff` |
| 20 | `0x42` | 8 bits | `0xff` |
| 21 | `0x43` | 8 bits | `0xff` |
| 22 | `0x44` | 8 bits | `0xff` |
| 23 | `0x45` | 8 bits | `0xff` |
| 24 | `0x64` | 8 bits | `0x00` |
| 25 | `0xa4` | 8 bits | `0x00` |
| 26 | `0xe4` | 8 bits | `0x00` |

There are exactly thirteen 16-bit writes. They occupy bytes `0x4a` through `0x63`, inclusive. Storing `0xffff` produces two all-ones bytes regardless of byte order.

The `0x64` offset is 100 decimal.

This is a partial record reset, not a full-record clear:

- The function has no explicit write to offset `0x49`.
- The function has no explicit write to the other unlisted record locations.
- Dependencies or aliasing may nevertheless affect those locations; preservation is not guaranteed globally.

The all-ones values are established bit patterns. Their interpretation as invalid identifiers, empty entries, or other sentinels is inferred intent only.

### 5. Resolve an associated object and conditionally invoke another dependency

After all explicit record writes:

1. F-c5cf4e75bd67 is called with the selector.
2. F-b9d333145f3e is called through a thunk, with no explicit argument shown.
3. Four address units are added to the latter result.
4. F-b37968c9f644 is called with that adjusted result as its first argument and the saved result from F-c5cf4e75bd67 as its second argument.
5. If F-b37968c9f644 returns nonzero, F-382ffcbbd77a is called with:
   - That nonzero result.
   - The constant `0x400`, or 1024 decimal.

If the lookup result is zero, F-382ffcbbd77a is skipped. Execution continues to the optional-action decision.

The meaning of `0x400` is unknown. It must not be specified as a byte count, allocation size, or flag mask without an additional dependency contract.

### 6. Perform the optional sequence

If the optional-action control is zero, the function returns after the preceding phase.

Otherwise, the following sequence occurs:

1. F-c5cf4e75bd67 is called again with the selector. Its result is obtained afresh, rather than reusing the earlier result.
2. The first byte of a four-byte automatic buffer is set to `0x06`.
3. F-b9d333145f3e is called with the context token.
4. F-1bc5bcdc9cca is called with:
   - The preceding result plus 4.
   - The result from the second F-c5cf4e75bd67 call.
5. F-b9d333145f3e is called again, this time with no explicit argument shown.
6. F-62d1a359629f is called with:
   - This newest result plus 4.
   - The same saved result from the second F-c5cf4e75bd67 call.
7. F-ad25141e1a92 is called with the address of the automatic buffer.
8. The function returns.

The two accessor results in this branch are independently obtained. The contract does not assume that they are equal or that intervening dependencies preserve related global state.

Only the buffer’s first byte is explicitly initialized. The remaining three bytes have no established values. No length is supplied to F-ad25141e1a92 in the visible call.

## Side effects

### Direct memory effects

On an accepted selector, the function performs:

- Two 32-bit zero writes to selected state fields.
- Two 8-bit zero writes to selected state fields.
- Twenty-six record writes: thirteen 16-bit writes and thirteen 8-bit writes.
- One automatic-buffer byte write when the optional branch is taken.

These are individual writes in the listed source-visible order. The evidence does not establish that the sequence is atomic, synchronized, or implemented using volatile accesses.

### Dependency-mediated effects

Dependencies may modify memory, global bases, external resources, or other state. Their bodies and contracts are not supplied. Accordingly:

- A final-state guarantee cannot disregard dependency effects.
- A zero lookup result suppresses only F-382ffcbbd77a; it does not roll back earlier changes.
- No status-based rollback or compensating operation is visible.
- The function does not inspect return values from the reset-like and optional-action dependencies.

### Ownership and lifetime

The function contains no explicit allocation or deallocation operation.

That does not establish that dependencies allocate nothing or release nothing. Passing an address, handle, or token does not independently establish ownership transfer.

The automatic buffer exists only during this invocation. The source does not establish whether F-ad25141e1a92 copies it, consumes it synchronously, retains its address, or reads beyond its initialized first byte. Safe retention or deferred use cannot be promised by this function alone.

## Acceptance examples

These are conditional static acceptance scenarios, not executed tests.

### Unsupported selector

Given selector 2, or any unsigned value greater than 1:

- The initial state-base read occurs.
- No explicit destination write occurs.
- No dependency is invoked.
- The context token and optional-action control do not alter this outcome.

### Selector 0, optional action disabled

Given valid storage, normally returning dependencies, stable nonaliasing bases, selector 0, and control 0:

- State writes select displacements 0 and 8 for the word fields, and −`0x4a` and −`0x48` for the byte fields.
- The record displacement is zero.
- All listed record writes occur before F-c5cf4e75bd67.
- The optional dependencies are not invoked.
- The context token is not forwarded to a dependency.

### Selector 1, optional action enabled

Under the same validity assumptions, with selector 1 and any nonzero control:

- State writes select word displacements 4 and 12, and byte displacements −`0x49` and −`0x47`.
- The handle-table displacement is 4.
- The record displacement is `0x124`.
- F-c5cf4e75bd67 is invoked twice.
- F-1bc5bcdc9cca precedes F-62d1a359629f.
- F-ad25141e1a92 receives a buffer whose first byte was set to `0x06`; the other bytes remain unspecified by this function.

### Zero versus nonzero lookup result

If F-b37968c9f644 returns zero, F-382ffcbbd77a is skipped.

If it returns a nonzero value \(r\), F-382ffcbbd77a receives \(r\) and `0x400` exactly once.

Neither outcome independently suppresses the optional sequence.

### Changed dependency results

If the two F-c5cf4e75bd67 calls return different values, the initial lookup uses the first value, while both optional operations use the second.

If the optional F-b9d333145f3e calls return different values, each optional operation uses its corresponding freshly obtained result plus 4.

## Uncertainties

The following remain documented_only:

- Application meaning of the reset fields, all-ones patterns, handle values, selector-derived values, and notification byte.
- Full storage layouts, allocation sizes, aliasing relationships, and concurrency rules.
- Actual dependency signatures, especially the differing visible argument forms for F-b9d333145f3e.
- Whether dependencies preserve global bases or modify previously written fields.
- Ownership and lifetime requirements of dependency inputs and results.
- Whether the automatic-buffer consumer reads only one byte.
- Error behavior, exceptions, nonlocal exits, and dependency failure reporting.
- Target address arithmetic and overflow behavior beyond the 32-bit scalar representation supplied.

Accepted selector arithmetic itself is bounded: \(4s\) is at most 4 and \(292s\) is at most 292. Adding those displacements, subtracting the negative state offsets, and adding 4 to dependency results still require valid addresses. No local check enforces that requirement.
