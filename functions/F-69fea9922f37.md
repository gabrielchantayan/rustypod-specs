# F-69fea9922f37

## Purpose

F-69fea9922f37 selects paths using a packed control word, an initial input byte, and a signed comparison derived from the context address. It calls unresolved dependencies and accesses byte, halfword, and word storage through context-relative, global, absolute, computed, and stack-related addresses.

Its application purpose is **documented_only**. The available static representation does not establish a parser, loader, formatter, or other recognizable public operation. Testing one byte for zero does not establish a terminated-string interface.

This contract describes displayed behavior, not a guarantee that every represented path is executable. The evidence includes invalid-instruction endpoints, omitted control-flow regions, overlapping global storage, and an unresolved indirect transfer. Execution also depends on machine state outside the explicit interface.

One path explicitly returns if an unresolved indirect transfer returns. All other displayed terminal paths encounter invalid instruction data.

## Behavior

### Entry selection

The routine separately derives packed-control bit 15 and the unsigned upper 16 bits.

If the upper half is zero, execution reaches an invalid-instruction endpoint. Bit 15 cannot bypass this condition.

Otherwise, the initial input byte is read:

- A zero byte bypasses context processing and enters the common dependency sequence.
- A nonzero byte enables the early path when bit 15 is set; otherwise, context processing follows directly.

No additional byte scan is displayed.

### Early indirect-transfer path

For a nonzero initial byte and set bit 15, a dependency is called at a target derived from the incoming return-address-like value plus `0xCCC`.

After its return, the routine isolates bit 29 of the incoming register-like word, scales that unsigned word by eight with 32-bit wrapping, and stores the dependency’s 32-bit result at context offset `0x10`. It then clears the current control quantity and replaces the current input address with zero.

The result store precedes the result-dependent branch.

For a nonzero result, another dependency is called. An unresolved indirect transfer then receives:

1. That dependency’s result.
2. A zero-extended byte read at the scaled register-like address plus one.
3. The auxiliary value arithmetically shifted right by three, then decreased by `0x55`.
4. A separate byte read at the same address, zero-extended and shifted left by 30 within a 32-bit unsigned quantity.

The two byte accesses are distinct; their relative argument-evaluation order is not established. They need not return equal values. The fourth argument retains only the contribution permitted by its 32-bit shift, not an unrestricted product.

If the indirect transfer returns normally, the routine explicitly returns without a represented result.

For a zero early result, the displayed loop does not repeat because the control quantity has been cleared. Context processing continues with input address zero. Its later halfword read therefore targets absolute address `0x10`, not the original input region.

### Context processing

A nonzero initial byte that reaches context processing causes these displayed operations:

1. Form the signed context address plus `0x12`.
2. Store the auxiliary value’s low byte at context offset `0x99`.
3. Read and sign-extend a 16-bit value at current-input offset `0x10`.
4. Compare the context-derived signed value with `0xD1`.

The byte store precedes the halfword read; aliasing can affect the read.

This is an address-derived comparison, not an established length or capacity check. Signed overflow in forming the compared value remains unresolved.

### Higher comparison path

When the context-derived value exceeds `0xD1`, the routine performs an ordered prefix consisting of:

- A dependency call receiving context offset `0x90` and the read stack word.
- A global store of `0x7E`.
- Another dependency call, then a global store of `0x3F0`.
- A byte read at a secondary-result-derived address plus the context-derived value.
- Global stores of the context-derived value and signed input halfword.
- Another dependency call.

It then reads and saves a 32-bit object address from a global. This saved address remains distinct from later reads of that global.

A signed 32-bit word at context offset `0x36` is read and arithmetically shifted right by 13. The result supplies a word-array address. Three 32-bit words are read in this order:

| Array byte offset | Role |
|---|---|
| `0` | Later dependency argument |
| `8` | Shared halfword-store index and later address displacement |
| `4` | Operand multiplied by four for computed addressing |

These offset-based names avoid confusing read order with array position.

The word from offset `4` is multiplied by four, and the result is assigned to a signed 32-bit destination. The loaded operand has an unspecified four-byte type. Consequently, the evidence does **not** establish that the multiplication itself is signed. Operand interpretation, multiplication semantics, and conversion into the signed destination remain distinct uncertainties.

The subsequent predicate is established: execution reaches invalid instruction data when the signed destination is nonzero and its signed-negative predicate equals the signed-overflow indicator for auxiliary value plus `0x10`. - The other supplies the stored value.

The following effects occur in order:

## Acceptance examples

These are conditional static obligations, not runtime test results. Each assumes the relevant path is reached and accesses and dependencies permit continuation.

1. **Upper-half rejection.** Packed control `0x00008000` reaches invalid instruction data before reading the input byte. Bit 15 does not override the zero upper half.

2. **Zero initial byte.** With packed control `0x00010000` and an initial zero byte, context processing is skipped. The shared halfword store, if reached, targets address zero. The table operand `0x10` produces table address `0xFF` after unsigned subtraction and shifting.

3. **Early result handling.** For a nonzero initial byte and set bit 15, early result five is stored at context offset `0x10` before selecting the indirect-transfer path. Early result zero is also stored, but continuation reads the context-stage input halfword from absolute `0x10`.

4. **Byte truncation.** Auxiliary value `0x12345678` supplies byte `0x78` to context offset `0x99`; its upper bits remain available to other operations.

5. **Computed halfword address.** On the higher path, an array word of zero at offset `4` yields a zero product and does not satisfy the product-dependent invalid-instruction condition. The computed halfword store uses address `0x14A` and value `0x00A5`: add `0xA5`, double for the address, but do not double the stored value.

6. **Product predicate.** If the product has been validly converted to signed destination value four, its negative predicate is false. A false auxiliary-addition overflow indicator therefore selects the invalid-instruction endpoint; a true indicator does not. This example does not settle multiplication semantics for other operand values.

7. **Distinct object-global observations.** If the original saved object address is `0x1000`, the later destination-base read yields `0x2000`, and the stored-value read yields `0x3000`, the word store writes `0x3000` at `0x2010`. No relative order is assigned to the two later reads.

8. **Original address retained.** In that example, the later object-address halfword store uses `0x1000`. If the array word from offset `8` is `0x20`, the later object-relative read targets `0x1020`, even if the global has changed.

9. **Lower-path arithmetic.** Auxiliary value `0x10` shifts to `0x40`; unsigned subtraction of `0x33` gives `0x0D`, producing table address zero. A signed input halfword `0xFFFF` supplies index −1; under 32-bit wrapping address conversion, its doubled store address is `0xFFFFFFFE`.

10. **Saved final state.** A dependency changing the final base global does not change the saved-base-relative destination. A saved selector of eight selects the below-nine path even if the intervening store overwrites selector storage; nine skips it.

11. **Stack-state selection.** Final stack-relative stores use the replacement state on the higher path and incoming state on the other two paths.
