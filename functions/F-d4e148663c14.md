The supplied static representation does not establish a domain-level purpose. It does not demonstrate object initialization, array processing, stream decoding, or a device protocol. Repeated scaling establishes arithmetic relationships, not an element size or storage layout.

**Evidence boundary:** the representation reports invalid instruction data and ends at an unresolved execution boundary. This contract describes the represented behavior, conditional on execution reaching each operation. ## Behavior

- Three consecutive calls show no explicit arguments and have no locally consumed results.

### Opening exchanges and first write

After these exchanges, three calls with no explicit arguments shown precede a call producing an unsigned 32-bit selection result.

The first write uses a selected intermediate value:

| Condition on the unscaled selection result | Selected intermediate value |
|---|---|
| Bit 30 is set | Selection result shifted left by two bits |
| Bit 30 is clear | Incoming address-selection value shifted left by ten bits |

The store precedes F-U005. Its address is doubled relative to each argument; the arguments are not generally copies of the write address.

Under the conditional 32-bit interpretation:

- The bit-30-set branch writes at eight times the selection result, modulo \(2^{32}\).
- The bit-30-clear branch writes at the incoming address-selection value shifted left by eleven bits, modulo \(2^{32}\).

The branch condition uses the unshifted unsigned result. Testing its shifted value instead is not equivalent: shifting left by two discards the original bit 30 under this interpretation.

These are conditional acceptance criteria, not runtime observations. Numeric examples assume 32-bit bit-vector arithmetic, valid execution targets, writable computed addresses, and all preceding operations completing.

4. **Single-byte zero store.**

5. **Unchanged forwarding.**  
   A forwarding result of `0xFFFFFFFF` is passed unchanged. Each earlier forwarding consumer receives one copy; F-U010 receives two copies. No error interpretation or arithmetic scaling is represented for these transfers.

6. **Write-before-call visibility.**  
   Each store’s immediately associated consumer executes after that store completes. Moving the store after its consumer would violate the represented order if the consumer reads the addressed byte.

7. **Four-call terminal suffix.**  
   After the ninth final scaled-result exchange, the required call events are F-U011, F-U012, F-U013, and F-U014, in that order, before the terminal boundary. A sequence containing only the first three does not satisfy this contract.

9. **Aliased zero stores.**  
   If the third and fourth stores address the same byte, both remain required ordered events. An intervening dependency may observe or modify the location, so the two stores cannot be collapsed based solely on equal stored values.
