# F-1bfc23b6b704

## Purpose

F-1bfc23b6b704 conditionally updates a one-byte field in a caller-supplied memory region. It compares the field’s current unsigned byte value against a full-width unsigned input. If they differ, it optionally writes a marker byte and then stores the low eight bits of the input into the field.

The comparison and storage have different widths. The comparison uses the full unsigned input; storage retains only one byte. Consequently, an input greater than 255 always selects the update path, even if its low byte already equals the stored field.

A plausible intent is to update a compact state value and optionally mark a change. The meanings of the field and marker are not established by the supplied evidence.

## Behavior

### Comparison

The function reads the byte at offset +5 before making any memory modification. That byte’s unsigned value is compared against the requested value.

The requested value is **not narrowed to a byte before comparison**. Under the apparent 32-bit unsigned interpretation, equality is possible only when the requested value lies between 0 and 255, inclusive, and exactly matches the stored byte.

If the values are equal, the function returns without writing either documented byte. Marker control has no effect on this path, including when it is nonzero.

### Unequal values

If the comparison reports a difference:

- When marker control is nonzero, the function first writes 1 to offset +6.
- When marker control is zero, it does not access offset +6.
- It then writes the low eight bits of the requested value to offset +5.
- It returns without a result value.

The store at offset +5 occurs on every unequal path. It is not suppressed merely because the replacement byte has the same bit pattern as the byte previously read.

For example, a stored byte of 7 and a requested value of 263 are unequal at comparison time. The replacement byte is nevertheless 7, because 263 modulo 256 is 7. If marker control is nonzero, the marker is also written.

### Marker behavior

The marker is conditional on both a comparison difference and nonzero marker control. It is not an unconditional record of invocation.

The function never clears the marker. It also does not read the marker before writing it. An existing marker value of 0, 1, or any other byte value does not affect the decision to update.

When no marker write occurs, this function leaves the marker unchanged. When a marker write does occur, it writes 1 even if the marker already contains 1.

### Ordering and completion

The established access order is:

1. Read the current field at offset +5.
2. On an unequal comparison with nonzero marker control, write the marker at offset +6.
3. On an unequal comparison, write the replacement field at offset +5.

Thus, on the path that writes both bytes, the marker write precedes the field write in the supplied operation sequence. This does not establish atomic publication, inter-thread synchronization, hardware visibility order, or protection against interruption between writes.

The function contains no retry, rollback, or error-reporting path.
