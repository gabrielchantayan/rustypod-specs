# F-6b7ad7f482a3

## Purpose

F-6b7ad7f482a3 updates a signed position-like field in a caller-supplied object, constrains the result using two stored bounds, and compares a derived value with a value obtained through an associated object's virtual interface.

If the values differ, it performs a sequence of temporary-object operations and notifications, then writes the previously selected position back to the object. Its Boolean result records the comparison outcome, not whether every downstream operation succeeded.

The position, bounds, and notification terminology describes inferred intent. The established behavior is the field access, arithmetic, comparison, call order, and conditional writes specified below.

The function receives:

### Output

On normal return, the result is:

- **False** when the initial virtual-query result equals twenty times the integer returned by F-870c4fcf7295.
- **True** when those values differ and the conditional sequence completes normally.

The result does not indicate whether the stored position changed. A false result can accompany a changed position. A true result can occur even when the selected position equals the original position.

## Behavior

### 1. Select and immediately store a position

The function reads the position at offset `0x78`, adds the adjustment, and retains the resulting candidate as a local value.

It next reads the lower-bound-like field at offset `0x7C`.

- If the candidate is less than that field, it selects that lower field's value. The upper-bound-like field is not read by this selection.
- Otherwise, it reads the upper-bound-like field at offset `0x80`. If that value is less than the candidate, it selects the upper field's value.
- Otherwise, it retains the candidate.

Comparisons are signed. Equality with either bound does not trigger replacement by that bound, although the resulting numeric value is the same.

For normally ordered bounds, this is a bounded adjustment. For reversed bounds, the lower comparison has priority. There is no second pass to ensure that a value selected from the lower bound also satisfies the upper bound.

The function writes the selected value to offset `0x78` **before calling any dependency**. This write occurs even if the selected value equals the existing value.

The selected value is also retained locally for possible use near the end of the conditional path. Later dependency mutations of the object's position do not change that retained value.

### 2. Obtain the comparison operands

The function invokes F-870c4fcf7295 with:

1. The selected position.
2. The integer constant `20`.

It retains that dependency's integer return value. Nothing in the supplied body establishes that the operation is division, rounding, quantization, or conversion.

Next, it reads the associated-object address at offset `0x1C`, obtains that object's dispatch table, and invokes the entry at table byte offset `0xB8`. This target is designated F-UNMAPPED-01.

The displayed call exposes no explicit arguments. It does not establish whether an implicit receiver or other calling-convention state is supplied. The function uses the returned integer as the query result.

This lookup occurs after F-870c4fcf7295 returns. Consequently, this function does not guarantee use of the associated-object address that existed on entry.

The comparison target is the retained return from F-870c4fcf7295 multiplied by `20`. The function compares the query result against that target and retains the inequality as its Boolean result.

If the values are equal, the function returns false immediately. It performs none of the temporary-object operations or notifications below.

### 3. Execute the mismatch-only sequence

1. Passes a 16-byte local storage region to F-b07efd113d9d.
2. Calls F-b7af80e829ec with no displayed arguments and retains its returned object address.
3. Invokes the returned object's virtual entry at table byte offset `0xE4`, passing that object address and the 16-byte local region. This target is designated F-UNMAPPED-02.
4. Calls F-bcefe54b4f94 with a separate 24-byte local region, the 16-byte region, and the integer constant zero, in that order.
5. Calls F-953474669c33 with the 24-byte region and an integer derived from the retained return of F-870c4fcf7295.
6. Calls F-UNMAPPED-03 with the original adjustment, not the selected position and not the derived comparison target.
7. Invokes the input object's virtual entry at table byte offset `0x58`, passing the input object, G-A, and G-B. This target is designated F-UNMAPPED-04.
8. Writes the locally retained selected position to offset `0x78` again.

The input object's virtual table used in step 7 is obtained at that stage of execution. The function does not cache the entry before preceding dependencies execute.

## Side effects

### Object mutation

The selected position is written once on every normally progressing execution. The mismatch path writes it a second time after the virtual notification.

No explicit write to either bound or the associated-object field appears in this function. Dependencies may nevertheless mutate those fields or other reachable state; preservation is not established.

The initial write is not rolled back when the comparison is equal. It also precedes every downstream call that could fail or leave normally executing control flow.

### Temporary storage and ownership

Two distinct local storage regions are used:

- A 16-byte region passed to F-b07efd113d9d, F-UNMAPPED-02, and F-bcefe54b4f94.
- A 24-byte region passed to F-bcefe54b4f94, F-953474669c33, and F-4e292a3dd745.

The supplied body does not explicitly initialize either region before its first dependency call. Initialization is therefore a dependency responsibility if required.

F-4e292a3dd745 is cleanup-shaped by its position in the sequence, but its actual semantics are unknown. No separate cleanup call for the 16-byte region is visible.

The function contains no explicit heap allocation or direct memory release. This does not establish that its dependencies allocate nothing or release nothing. Nor does passing an address establish ownership transfer or permission to retain that address beyond the local region's lifetime.

### Errors and exceptional exits

In particular:
