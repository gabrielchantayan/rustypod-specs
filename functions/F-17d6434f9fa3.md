# F-17d6434f9fa3

## Purpose

F-17d6434f9fa3 publishes a packed 32-bit value to a destination selected by an external base value. The packed value combines:

- A 16-bit field taken from bits 3–18 of the first input.
- A 3-bit field taken from bits 0–2 of the first input.
- An 8-bit field derived from the second input, with two special interpretations controlled by the third input.

The function returns a 32-bit zero after the store completes. Its return value does not report whether a device, consumer, or other external agent accepted the stored value.

The field layout and special mappings are established by the supplied static representation. Interpreting the fields as an address, command, channel, or device selector would be inferred intent, not established behavior.

## Behavior

### Low-byte selection

The special mapping depends on the **entire 32-bit second input**, not merely its low byte.

| Full second input | Third input | Selected low byte |
|---|---|---|
| Exactly 1 | Exactly 0 | 0x0E |
| Exactly 1 | Exactly 1 | 0x0F |
| Exactly 1 | Any other value | 0x01 |
| Any value other than 1 | Any value | Bits 0–7 of the second input |

This distinction matters for values whose low byte is 1 but whose upper bits are nonzero. For example, a second input of 0x00000101 does not activate either special mapping. Its selected low byte is 0x01 regardless of the third input.

Outside the special mappings, bits 8–31 of the second input are discarded. They do not occupy other fields in the stored word.

The third input has no effect when the second input is not exactly 1.

### Packed destination layout

The destination receives the following logical 32-bit word:

| Destination bits | Contents |
|---|---|
| 31–16 | First-input bits 18–3, preserving their order |
| 15–11 | Zero |
| 10–8 | First-input bits 2–0 |
| 7–0 | Selected low byte |

The fields do not overlap. The low-byte selection cannot set bits 8 or above, and the first input cannot alter the low byte.

Bits 19–31 of the first input are discarded. In particular, the function does not preserve every bit remaining after shifting the first input right by three positions. The subsequent placement into a 32-bit word retains only the 16 bits that fit in destination bits 16–31.

The maximum possible stored word is 0xFFFF07FF. Destination bits 11–15 remain zero for every input combination.

### Width and arithmetic rules

The first-input shifts operate on an unsigned 32-bit value. The right shift therefore introduces zeros rather than sign bits. Placement into the upper half of the word is also a 32-bit operation: source bits that would extend beyond bit 31 do not survive.

There is no signed arithmetic involving the first or second input. A first input with bit 31 set is not treated as a negative value.

The packed integer specifies bit positions, not the byte order used by the platform to store that integer in memory. The supplied material does not establish endianness.

### Destination update and completion

Every represented normal path reaches one 32-bit destination assignment, including paths where the resulting word is zero or equals the destination’s previous contents.

The assignment replaces the entire represented 32-bit word. It is not a read-modify-write operation:

- Existing destination bits are not incorporated into the result.
- Existing ones in destination bits 11–15 are replaced by zeros.
- No comparison against the previous destination value is shown.

The destination assignment precedes the normal return of zero.

The representation does not establish an evaluation order among independent input calculations and resolution of the external base. It establishes no additional observable interaction between those computations.
