# F-7e444e204b7b

## Purpose

F-7e444e204b7b coordinates operations on a caller-supplied memory object, optionally delegates to a header-sensitive handler, and otherwise applies an identity-gated release rule.

The established behavior includes:

- An unconditional call concerning the embedded region at byte offset +4.
- A conditional call concerning the embedded region at byte offset +32.
- An optional handler whose nonzero result terminates processing.
- A comparison between a stored 32-bit identity and a dependency-supplied identity.
- Either a 16-bit count decrement or immediate clearing of the count and identity fields.
- A final dependency call on the embedded region at byte offset +24 when the release condition is met.

A lock-like release or reference-release purpose is an inference from the identity comparison, count handling, and final call. The supplied evidence does not establish the object’s public type, the meanings of its mode values, or the resource semantics of any dependency.

The result is one of:

- A nonzero result returned by F-621dae46a146.
- `5` when the stored identity differs from the identity returned by F-196812b4b122.

## Behavior

### 1. Initial dependency calls

The function first invokes an unmapped dependency with the address at object offset +4. No result from this call is tested in the supplied body.

After that call returns, the function reads the byte at object offset +0.

- If the byte equals exactly `1`, it invokes F-a9c62fb9dbee with the address at offset +32.
- For every other byte value, it skips that call.

The ordering is significant. The +0 byte is read after the initial dependency returns, not before it. Changes made by that dependency can therefore affect selection of F-a9c62fb9dbee.

No preservation of object fields, globals, or externally visible state is established for either dependency.

### 2. Derived-address branch

After the initial calls, the function tests whether the address derived at object offset +4 is null.

If that comparison succeeds, the function returns `26` without executing the header-sensitive handler or the identity/count logic.

For an ordinary valid object allocation, an interior address at +4 is nonnull. The supplied evidence does not establish a valid, defined input that reaches this branch. In particular, passing a null object address does not safely select it.

### 3. Header-sensitive handler

On the nonnull derived-address branch, the function reads the 32-bit field at offset +4 and compares it with a global discriminator.

The comparison uses the object field and global value as observed at this point, after the earlier dependency calls.

If the values differ, F-621dae46a146 is not invoked.

If they match, F-621dae46a146 is invoked with:

1. The address at object offset +4.
2. A zero-valued argument.
3. The explicit third argument.
4. The explicit fourth argument.
5. The ambient value described in the interface.

A nonzero result is returned immediately. In that case, this function does not proceed to the mode read, identity query, count update, or final dependency call.

A zero result does not terminate processing. Normal processing continues using subsequent observations of the object. The function does not restore any state changed by the handler.

### 4. Mode snapshot and identity comparison

The function next reads the unsigned 16-bit field at offset +18 and retains that value for the later mode decision.

It then invokes F-196812b4b122 without explicit arguments.

After that dependency returns, the function reads the 32-bit stored identity at offset +8 and compares it with the returned identity.

If the identities differ:

- The result is `5`.
- This function performs no count read, count decrement, local field clearing, or F-259d2fe281b0 call.

Earlier dependency effects remain possible. A mismatch does not imply that the whole invocation was side-effect free.

If the identities match, processing continues to the release rule.

The mode and identity are not one atomic snapshot. The mode is read before F-196812b4b122; the stored identity is read after it. A change to the mode during that dependency does not alter the retained mode value used by this invocation.

### 5. Release rule

The count-sensitive mode is selected exactly when bits 5 and 4 of the retained mode value are `1` and `0`, respectively.

All other bits are irrelevant to this local decision. In particular:

- The low four bits do not affect it.
- Bits 6 through 15 do not affect it.
- The complete mode value need not equal `32`.

When those two bits do not select the count-sensitive mode, the function immediately takes the release path. It does not first read or decrement the existing count.

When those bits do select the count-sensitive mode, the function:

- Reads the signed 16-bit count at offset +22.
- Subtracts one.
- Stores the narrowed 16-bit result back at that offset.
- Tests whether the signed 16-bit narrowed result is zero.

If the new count is nonzero, the function returns `0` without locally clearing the identity and without calling F-259d2fe281b0.

If the new count is zero, the function takes the release path.

The zero condition is based on the count after decrement. For representable ordinary values, an initial count of `1` therefore releases, while an initial count of `2` becomes `1` and does not release.

There is no validation that the old count is positive. An initial zero is decremented to `−1` and does not release. The signed 16-bit lower boundary involves narrowing an out-of-range intermediate value; the evidence and uncertainty sections distinguish that case from ordinary arithmetic.

### 6. Release path

On the release path, the function performs these local writes in the displayed order:

1. Zero the byte at offset +22.
2. Zero the byte at offset +23.
3. Zero the byte at offset +8.
4. Zero the byte at offset +9.
5. Zero the byte at offset +10.
6. Zero the byte at offset +11.

It then invokes F-259d2fe281b0 with the address at offset +24 and returns that dependency’s result.

Thus, on entry to F-259d2fe281b0, the local count and stored identity fields have been cleared, unless some external or concurrent agent changes them.

In count-sensitive mode, the decrement write precedes these byte-clearing writes. When decrement reaches zero, the count is consequently written once by the decrement operation and then explicitly cleared byte by byte.

There is no local restoration of the cleared fields if F-259d2fe281b0 returns a value interpreted by a caller as an error. The function returns the dependency result directly. The dependency itself may also mutate the object; its post-call state is unknown.

## Side effects

Established direct side effects are confined to the count and identity fields:

- The count-sensitive path with matching identity writes the 16-bit decremented count.
- The release path clears the count bytes and then the identity bytes.
- Other paths perform no direct object writes in the supplied body.

Dependency effects are separate and unconstrained by the provided evidence. In particular:

- The unconditional initial call may affect later reads.
- F-a9c62fb9dbee may affect the header comparison and later state.
- F-621dae46a146 may mutate state even if it returns zero.
- F-196812b4b122 may affect state between the mode snapshot and identity read.
- F-259d2fe281b0 receives control only after the local clearing operations.

No allocation, deallocation, ownership transfer, or lifetime extension is directly established. Passing an embedded address does not by itself establish whether a dependency borrows, retains, releases, or invalidates the containing object.

The displayed read/write order is a static behavioral description, not a guarantee of atomicity or a synchronization protocol. The evidence does not establish safe concurrent access.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Unless stated otherwise, assume valid storage, normal dependency returns, a nonnull derived address, no asynchronous mutation, and no relevant mutations by earlier dependencies.

1. **Optional embedded operation.** If the byte at +0 is `1` after the initial dependency returns, F-a9c62fb9dbee is invoked with the address at +32. If the initial dependency changes that byte from `1` to `0`, the optional call is skipped.

2. **Handler terminates processing.** If the header equals the discriminator and F-621dae46a146 returns `−7`, the function returns `−7`. No mode read, identity-query call, or local release-path write follows.

3. **Handler permits continuation.** If the header matches and F-621dae46a146 returns zero, the function proceeds to read the mode and invoke F-196812b4b122. It does not return merely because the handler returned zero.

4. **Identity mismatch.** If the mode snapshot has been taken and the stored identity subsequently differs from the dependency result, the function returns `5`. It leaves the count untouched by local code and does not invoke F-259d2fe281b0.

5. **Immediate-release mode.** With matching identities and mode `0`, the count is cleared without being read or decremented. The identity is then cleared, F-259d2fe281b0 is invoked, and its result is returned.

6. **Count reaches zero.** With matching identities, mode `32`, and count `1`, the count is decremented to zero, the release-path byte writes occur, and F-259d2fe281b0 is invoked.

7. **Count remains positive.** With matching identities, mode `47`, and count `2`, the count becomes `1`, the stored identity is not locally cleared, the final dependency is not invoked, and the result is `0`. Mode `47` qualifies because its relevant two bits match those of mode `32`.

8. **Zero is not a release trigger before decrement.** With matching identities, count-sensitive mode, and count `0`, the count becomes `−1`. The function returns `0` without invoking the final dependency.

9. **Mode changes during identity query.** If the retained mode is count-sensitive but F-196812b4b122 changes the stored mode to an immediate-release value, this invocation still uses the retained count-sensitive value. It reads the identity after that dependency returns.

10. **Final dependency returns an error-like value.** If the release path is selected and F-259d2fe281b0 returns `9`, the function returns `9`. Its own earlier clearing writes are not rolled back.

The supplied representation shows 8-bit byte accesses, 16-bit short fields, and 32-bit integer fields and values. At a count of `−32768`, subtraction produces an intermediate `−32769` before narrowing to 16 bits. Under conventional low-16-bit narrowing, the stored result is `32767` and is nonzero, so no release occurs. That boundary behavior depends on the target’s signed-narrowing semantics and is not independently verified here.
