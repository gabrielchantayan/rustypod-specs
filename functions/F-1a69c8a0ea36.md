# F-1a69c8a0ea36

## Purpose

F-1a69c8a0ea36 mutates existing storage through an ordered sequence of direct writes, read-modify-write updates, and selection-dependent two-byte writes. An initial indirect write uses the entry state before that state is cleared. Later destination selection depends on a retained observation of another storage location.

The represented path terminates at an invalid-instruction boundary. It does not establish normal return, a completion value, or a particular exception outcome.

Initialization of low-address control storage is **inferred intent**, not an established architectural purpose. Neither a processor-specific table format nor a valid memory map is part of this contract.

Evidence classifications used below:

- **Established:** directly supported by the supplied static representation.
- **Conditional:** a consequence requiring explicitly stated environmental or arithmetic assumptions.
- **documented_only:** unresolved by the available evidence.

The contract covers the represented path, not behaviors potentially omitted by incomplete static recovery.

## Behavior

### Ordering and observation rules

The ordering of separate operations is observable contract information. A mask consumes the value available when that update occurs; an earlier clear does not guarantee that the later observation is zero.

Repeated clears and repeated two-byte writes remain separate represented operations. Whether an implementation or device exposes separate physical transactions is **documented_only**.

Two operations have unresolved internal observation ordering:

- The opening store uses entry state for both destination formation and payload formation.
- The first selection-dependent store uses the same byte address for destination selection and payload formation.

The evidence does not establish a physical read count or ordering between the source uses within either operation. Equal source addresses therefore do not establish equal observed values under interference or special memory semantics.

If an access prevents progress, subsequent operations are not reached on the represented path. No restoration of earlier mutations is established.

### Opening mutation

Entry state is consumed before preparation clears it. Destination formation and payload formation both pass through the represented signed general-integer type. The store width is that type’s width.

With stable entry contents, lossless relevant conversions, and compatible address interpretation, the operation writes a numeric address value into storage at that address. This is a **conditional consequence**, not an unconditional self-pointer invariant. Different observations, truncation, signed conversion, or address interpretation can invalidate that description.

### Preparation footprint

Preparation occurs after the opening mutation and before selection capture. The following regions of the preparation trace have strict precedence from top to bottom.

| Preparation region | Required footprint and ordering constraints |
|---|---|
| Initial clearing | Data state is cleared before address `0x34`. The sixteen starts from `0x40` through `0x7C`, spaced four bytes apart, are then cleared in ascending order. |
| Entry and service preparation | Entry state, secondary state, and service state are cleared in that order. Clears at `0x0A` and `0x0B`, in that order, precede the service-state mask `0xFFFFFF`. |
| Selection preparation | Selection state is cleared. Address `0x0F` receives two consecutive clears before the selection-state mask `0xFFFFFF`. |
| Data preparation | The alternate data view receives two consecutive clears before data state is masked with `0xFF`. Three consecutive clears at `0x12` precede two consecutive clears at `0x13`. |
| Reserved and interrupt preparation | Reserved state is cleared before `0x15`; `0x16` then receives three consecutive clears. Clearing interrupt state completes preparation. |

Every listed clear assigns zero at the applicable destination width. Every listed mask is a read-modify-write operation, not an interchangeable spelling of a clear.

This footprint does not establish a contiguous zero-filled region. Unknown access widths, overlap, device behavior, and intervening changes remain relevant.

### Retained selection

Selection state is sampled after the interrupt-state clear.

Two retained values govern the later destination set:

- The **wide selector** is the sampled value shifted right by eight bits and then converted to the represented unsigned general-integer type.
- The **octet selector** is the lowest eight bits of the wide selector, with numerical range 0–255.

The shift precedes unsigned conversion. Selection-state signedness and the treatment of a negative value during right shift are **documented_only**.

The selectors are not recaptured during the remaining sequence. Later changes to selection storage do not themselves alter these retained values. A zero sample produces two zero selectors, but preparation alone does not guarantee that sample in every environment.

### First selection-dependent write

The byte-source address is the octet selector multiplied by 4,096, plus `0x1F`, subject to the arithmetic and address model.

One unsigned byte observation selects a destination two bytes above that observed value. Another source use supplies a payload widened to unsigned 16-bit form.

Consequently:

- Destination starts range from 2 through 257.
- Payload values range from 0 through 255.
- A write starting at 257 spans addresses 257 and 258.
- An odd destination-selecting observation produces an odd destination.

The two observations are not required to agree. A contract that retains one byte and requires both uses to share it would impose an unsupported consistency guarantee.

## Acceptance examples

These are conditional acceptance criteria, not executed tests. Each assumes that preceding operations permit the stated observations.

### Entry state is consumed before clearing

Assume stable entry contents `0x1000`, compatible 32-bit signed-integer and address conversions, and writable destination storage. The opening mutation writes `0x1000` at address `0x1000` using four bytes.

Clearing entry state before consuming it would violate the required order.

### Zero selection does not determine the first payload

Assume both retained selectors are zero and both byte observations at `0x1F` yield 7. The first selection-dependent write starts at address 9 and carries the 16-bit value 7.

This does not assert that ordinary memory necessarily retains 7 at `0x1F` after preparation, or that later overlapping writes preserve the result.

### Same-address observations can differ

Assume the destination-selecting observation yields 4 and the payload observation yields 9. The first selection-dependent write starts at address 6 with value 9.

Either observation order remains admissible. Requiring the payload to equal the destination minus two would add an unsupported agreement requirement.

### Duplicate destination accesses remain distinct

For any retained octet selector, its 262,144-scaled destination at offset `0x08` receives two consecutive zero-valued two-byte writes.

An execution model exposing every represented access must preserve both. Two physical transactions are not guaranteed in all environments.

### A later mask consumes current state

If the interrupt-state update observes `0xABCD1234` under a 32-bit object model, its result is `0xABCD0000`.

The earlier interrupt-state clear does not justify replacing this later update with another clear.

### Narrowing and address wrapping are independent

Assume a wide selector of `0x10`, unsigned 32-bit arithmetic, and signed-16-bit conversion that retains the low 16 bits. The octet selector is also `0x10`.

Both nonconstant address-derived payloads narrow from `0x10000` to zero. Independently, multiplying the wide selector by 268,435,456 wraps to zero. The repeated destinations for that scale at offset `0x10` therefore start at address `0x10`.

### Alignment failure can expose partial progress

A destination-selecting byte observation of 1 produces destination address 3. An environment rejecting unaligned two-byte writes may stop progress at that write, after preparation has already mutated storage.

No adjustment, retry, rollback, or continuation is established.
