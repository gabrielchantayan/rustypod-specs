# F-5d01188e4589

## Purpose

F-5d01188e4589 adds two variable-length sequences of unsigned 32-bit words, storing the result through the second descriptor. Words are processed in increasing position order, with carry propagating toward higher positions. Interpreting position zero as the least-significant word gives unsigned multiword addition.

The first descriptor supplies one operand. The second descriptor supplies the other operand, identifies destination storage, and receives the result’s 16-bit word count.

The operation does not allocate destination space, check capacity, remove leading zero words, or report errors through a return value. Correct arithmetic on the operands present at entry requires sufficient accessible storage and overlap that does not overwrite unread input.

This contract describes supplied static evidence. No runtime tests have been performed.

## Interface

### Arguments and return

The function accepts two descriptor addresses:

- **First descriptor:** input count and input word-storage pointer.
- **Second descriptor:** input count, input/destination word-storage pointer, and output count.

It returns no value. No separate success, failure, or carry result is exposed.

| Byte offset | Accessed field | Interpretation |
|---|---|---|

Neither descriptor’s pointer field is explicitly updated. The first count is not explicitly written. The second count is written at completion.

### Arithmetic result

Let the initial first and second counts be \(a\) and \(b\), and let \(m=\max(a,b)\). Both counts range from 0 through 65,535.

For valid storage without destructive overlap:

- Positions below \(m\) receive the low \(m\) words of the sum.
- If the sum produces a carry beyond those positions, position \(m\) receives the 32-bit value 1.
- The second descriptor receives count \(m\), or \(m+1\) when a final carry exists, reduced modulo 65,536.

The stored count is not normalized. High zero-valued words remain included.

### Storage preconditions

The operation requires:

- Readable count and pointer fields in both descriptors.
- A writable count field in the second descriptor.
- Readable first-operand storage for \(a\) words.
- Readable second-operand storage for \(b\) words.
- Writable destination storage for every word produced.
- Valid addresses and alignment appropriate to the accesses.

Both pointer fields are read even when their corresponding counts are zero. A zero count prevents word access for that operand; it does not remove the descriptor-field readability requirement.

The second count is an active-word count, not a capacity declaration. Destination capacity may need to exceed it:

- At least \(m\) writable words are needed for the main result.
- A final carry requires one additional writable word.
- Capacity of \(m+1\) words covers either arithmetic outcome.

The body contains no checks for null pointers, insufficient capacity, inaccessible memory, or inconsistent descriptors. It provides no defined error result for violations.

These access requirements do not establish ownership. Ownership and lifetime protocols for both descriptors and both word-storage regions are outside the supplied evidence.

## Behavior

### Initial descriptor observations

The body reads descriptor fields in this order:

1. First descriptor’s 16-bit count.
2. Second descriptor’s 16-bit count.
3. First descriptor’s storage pointer.
4. Second descriptor’s storage pointer.

The operation retains these values for traversal. It does not reload the descriptor counts or pointer fields after word writes begin.

Carry initially equals zero.

These are source-level access relationships. The evidence does not establish hardware transaction ordering, synchronization, or an atomic snapshot in the presence of concurrent mutation.

### Common positions

For each position below \(\min(a,b)\), processing advances from the lowest position upward. The memory-access order at each position is:

1. Read the first operand word.
2. Read the second operand word.
3. Write the result word to the second operand’s storage.

Thus, both inputs at a position are read before that position is overwritten.

For unsigned 32-bit input words \(x\) and \(y\), and incoming carry \(c\), the stored word is

\[
(x+y+c)\bmod 2^{32}.
\]

Carry detection accounts separately for overflow in \(x+y\) and overflow when adding the incoming carry to that wrapped sum.

The carry is represented using 32-bit arithmetic, but its reachable values are only 0 and 1. With \(c\in\{0,1\}\), the full sum is at most \(2^{33}-1\). The two overflow indicators therefore cannot produce a reachable outgoing carry of 2.

### Remaining positions when the second operand is longer

If \(a<b\), positions from \(a\) through \(b-1\) use only the existing second-operand word and the incoming carry.

At each such position, the operation:

- Reads the destination’s existing 32-bit word.
- Writes that word plus carry, modulo \(2^{32}\).
- Propagates any overflow to the next position.

All remaining positions are processed even if carry becomes zero. There is no early termination when propagation ends. Consequently, a zero first count with a nonzero second count causes every active destination word to be read and rewritten unchanged.

### Remaining positions when the first operand is longer

If \(a>b\), positions from \(b\) through \(a-1\) use only the first-operand word and incoming carry.

At each such position, the operation:

- Reads the first operand’s 32-bit word.
- Writes that word plus carry to the destination, modulo \(2^{32}\).
- Propagates any overflow.

The old destination contents at these positions are not read. They need writable capacity but need not contain initialized operand words.

When the second count is zero, this phase copies the first operand’s active words into the destination: the incoming carry is zero and remains zero.

### Equal and empty counts

Equal nonzero counts require only the common-position phase.

If both counts are zero:

- Both descriptor pointer fields are still read.
- No pointed-to word is read or written.
- No carry word is produced.
- The second descriptor’s count is written as zero.

No zero-count case bypasses the final count write.

### Final carry and count

After all \(m\) positions have been processed:

- With zero carry, no word at position \(m\) is written.
- With nonzero carry, position \(m\) is written with the 32-bit value 1.

The second descriptor’s count is written after every result-word write, including an optional carry word.

Count arithmetic is 16-bit. If \(m=65{,}535\) and a final carry occurs, the operation:

- Writes the carry word at position 65,535.
- Stores zero in the second descriptor’s count because 65,536 wraps modulo 65,536.

There is no saturation, rejection, or special error indication at this boundary. The storage can contain a 65,536-word arithmetic result while the updated descriptor reports zero active words.

### Aliasing and overlap

No explicit overlap check appears.

Exact coincidence of the two word-storage pointers is compatible with the per-position read order: both words at a position are read before that destination position is written. With equal counts and sufficient capacity, this permits in-place doubling, provided descriptor overlap does not interfere.

Partial overlap can change the arithmetic inputs. A destination write at an earlier position may overwrite a first-operand word that has not yet been read. Subsequent processing then reads the modified word, not its entry value. Neither operand is snapshotted.

Word storage may also overlap descriptor memory. In that case:

- Word writes can indirectly alter descriptor fields.
- Traversal still uses the counts and pointers already captured.
- Reads of later operand words observe any earlier writes to their locations.
- The final second-count write can overwrite bytes that also belong to word storage.

Accordingly, the ordinary entry-value addition interpretation requires non-destructive overlap. The literal access sequence remains relevant when that condition is not met, but a correct standalone result representation is not guaranteed.
