# F-697c7be54039

## Purpose

F-697c7be54039 queries two 32-bit values, conditionally performs a sequence of notifications and shared-state operations, and records the low byte of each queried value.

A zero dispatch gate enables the conditional work. A nonzero gate suppresses that work but does not suppress either query or the final byte stores.

The established behavior comprises ordered dependency calls, comparisons of two-bit fields, conditional resource-slot updates, and a mode-dependent latched action. “Query,” “resource,” and “latch” describe observable roles; their application-level meanings are inferred rather than established.

This is a static behavioral contract. No runtime tests have been performed.

## Interface

### Inputs and output

The function accepts four inputs:

| Input | Width | Interpretation |
|---|---:|---|
| Dispatch gate | 32 bits | Exactly zero enables the dispatch branch. Every nonzero value skips it. |
| Auxiliary value | 32 bits | Opaque value copied into addressable local storage for a conditional dependency call. |
| Packed value | 32 bits, unsigned | Copied into addressable local storage and supplied to the second query. Selected low-byte bits govern resource operations and comparisons. |
| Control value | 32 bits, unsigned | Copied into addressable local storage and supplied to the first query. Selected low-byte bits govern notifications and comparisons. |

There is no explicit return value or caller-provided output buffer. Observable outputs are dependency calls and shared-memory writes.

The three copied inputs are local values, not references to the caller’s argument storage. Dependencies receive addresses of these local copies where specified. Modification through such an address does not itself modify the caller’s original storage.

Because addresses escape to dependencies, this contract does not assume that a queried local remains unchanged throughout the invocation. References below to a local control, packed, or auxiliary value mean its value when the relevant operation evaluates it.

### Shared-state layout

After both initial queries return, the function captures the base address held in a global shared-state reference.

| Offset from base | Access width | Observable role |
|---|---:|---|
| +1 | 8 bits | Cleared when the mode-specific auxiliary condition succeeds. |
| +2 | 8 bits | Mode discriminator; the distinguished value is 3. |
| +3 | 8 bits | Previous packed byte, later overwritten. |
| +4 | 8 bits | Previous control byte, later overwritten. |
| +12 | 32 bits | Nonzero enables an additional control-dependent notification. |
| +16 | 32 bits | Resource slot; zero denotes absence for this function’s decisions. |
| +24 | 32 bits | Latch; zero permits the action sequence. |

These accesses do not establish a complete structure definition. The byte at +1 is not established as Boolean, and the resource slot is not established as a pointer rather than another 32-bit token.

Correct execution requires the global reference and the storage accessed on the selected path to be valid. The evidence does not establish initialization, alignment guarantees, lifetime management, or behavior for invalid addresses.

## Behavior

### Initial queries and state selection

Before testing the dispatch gate, the function calls F-ff01e173816f twice:

1. Selector 6, with the address of the local control value.
2. Selector 5, with the address of the local packed value.

Both calls occur for every gate value. Their return values are not used.

Only after these calls return does the function capture the shared-state base. A change to the global reference during either query therefore affects which base is captured.

If the gate is nonzero, execution proceeds directly to the final byte stores. If the gate is zero, the following dispatch operations occur in order.

### Initial control comparison

F-6bd9dee8da0b receives:

- Selector 0.
- The local control value masked with `0x03`.
- The previous control byte masked with `0x03`.

Both extracted values are in the range 0–3. Equality does not suppress the call.

For this call alone, the previous byte is fetched at offset +4 through a fresh use of the global shared-state reference. Subsequent field accesses use the captured base. There is no intervening dependency call between base capture and this access, but the source does not establish synchronization that would prevent an external change to the global reference.

The relative evaluation order of the call’s argument expressions is not established here. Their evaluation precedes entry into the dependency.

### Additional control notification

After the initial comparison returns, the function reads the 32-bit field at captured-base offset +12.

If that field is nonzero, it examines the low control byte. F-fede798223e7 is called with argument 0 only if at least one of control bits 0 and 1 is set.

A change to the +12 field during the initial comparison can affect this decision. No call occurs when the field is zero, regardless of the control bits.

### Resource acquisition and initialization

The function reads the 32-bit resource slot at +16 and tests it for zero.

If the slot is zero and the local packed value has any bit selected by `0x55`, the function:

- Calls F-EXT-01 without explicit arguments.
- Stores its 32-bit result into the resource slot.
- Calls F-EXT-02 with that result, then 250, 0, and 67.

The mask selects bit positions 0, 2, 4, and 6. Bits above bit 7 do not contribute.

There is no visible validation of the result. A zero result is still stored and passed to F-EXT-02. The first argument to F-EXT-02 is the acquisition result, not a new read of the slot.

F-EXT-02 runs after the slot store and before the release decision. Its behavior is unknown. In particular, it is not assumed to preserve the resource slot.

### Conditional resource release

The function next tests whether the local packed value has any bit selected by `0xAA`, covering positions 1, 3, 5, and 7.

Only if that mask matches does it read the resource slot for the release decision. If the value read is nonzero, it:

1. Calls F-EXT-03 without explicit arguments.
2. Reads the resource slot again and passes that value to F-EXT-04.
3. Writes zero to the resource slot after F-EXT-04 returns.

A nonzero acquisition result does **not** guarantee release. Release depends on the slot value read after initialization, and F-EXT-02 may have cleared or replaced that value. It also depends on the packed mask at the release decision.

The value passed to F-EXT-04 need not be the nonzero value that enabled the sequence. F-EXT-03 may change the slot, including setting it to zero. There is no second nonzero check before F-EXT-04.

The final zero store occurs after F-EXT-04 returns and overwrites any value that dependency may have placed in the slot.

Acquisition and release can therefore occur in one invocation, but only when the independently evaluated conditions permit both.

### Mode-specific auxiliary action

The function reads the mode byte at +2. If it equals 3, F-3fef37c526f8 is called with the address of the local auxiliary value.

After that call returns, the function checks the auxiliary value’s low eight bits:

- If they are zero, this part performs no explicit state write and no additional call.
- If they are nonzero, the function first clears the byte at +1, then reads the 32-bit latch at +24.

When the latch read is zero, the function writes 1 to it and then calls, in order:

1. F-EXT-05 with 60.
2. F-EXT-06 with 63.
3. F-7050a97a065a without explicit arguments.

A nonzero latch suppresses the latch write and these three calls, but does not suppress the earlier byte clear.

The mode is not rechecked between the auxiliary call and processing its result. A mode change during F-3fef37c526f8 therefore does not cancel this processing.

The latch is written before the action dependencies run. Those dependencies can observe that ordering, but their preservation of the latch is unknown. This is not established as an atomic or concurrency-safe once-only mechanism.

### Packed-field comparisons

After the mode-specific work, the function tests control bit 5, represented by mask `0x20`.

If that bit is clear, it does not read the mode for this decision and makes no packed-field comparison calls.

If the bit is set, it reads the mode byte at +2 again. If that byte is not 3, it calls F-6bd9dee8da0b four times:

| Selector, in call order | New field from local packed value | Previous field from byte +3 |
|---|---|---|
| 1 | Bits 0–1 | Bits 0–1 |
| 2 | Bits 2–3 | Bits 2–3 |
| 3 | Bits 4–5 | Bits 4–5 |
| 4 | Bits 6–7 | Bits 6–7 |

Each field is an unsigned value from 0 through 3. The final extraction uses only the low packed byte before shifting; upper packed bits cannot enter selector 4’s argument.

Each call evaluates its own previous-byte read. There is no common snapshot across all four calls. An earlier comparison dependency can alter the previous byte used by a later comparison. Likewise, preservation of the address-exposed local packed value is not guaranteed by the supplied body.

Once this sequence begins, there is no further control-bit or mode check between its four calls. Changes to those conditions during an earlier comparison do not by themselves cancel the remaining calls.

### Final recording

On normal completion, including a nonzero-gate path, the function explicitly stores:

1. The low eight bits of the local control value at captured-base offset +4.
2. The low eight bits of the local packed value at captured-base offset +3.

Both stores use the captured base, not a fresh global-reference lookup. No dependency call occurs between these two stores.

These are the local values at the stores, not necessarily the original arguments or immutable results of the initial queries.

## Side effects

The function’s explicit shared-memory writes are limited to:

- Storing the acquisition result at +16.
- Clearing +16 after F-EXT-04 returns.
- Clearing the byte at +1.
- Setting the latch at +24 to 1.
- Recording the control byte at +4.
- Recording the packed byte at +3.

The final two writes occur on every normally completing path. The others are conditional.

Dependencies may independently modify shared state, the global reference, resource-related objects, or address-exposed local storage. No general preservation guarantee is established.

Passing a local address does not establish ownership transfer or permission to use it after the invocation ends. Retention of these addresses by dependencies is documented_only.

The acquisition and release call pattern does not establish allocation type, exclusive ownership, a failure convention, or actual destruction semantics. Zero has only the branch meanings explicitly described.

There is no explicit error result, rollback, retry, exception handling, or synchronization. If a dependency fails to return normally, later operations—including final recording—are not established to occur. Earlier writes may already have happened.

## Acceptance examples

These are conditional static examples, not executed tests. All dependencies in an example return normally. Unless an example states otherwise, address-exposed local values remain stable after the initial queries. Shared-field preservation is assumed only where explicitly required.

1. **Dispatch disabled, recording retained.**  
   With a nonzero gate, control `0x123456A5`, and packed value `0x89ABCDEF` after the queries, the function performs query 6 then query 5, makes no dispatch calls, and stores `0xA5` at +4 followed by `0xEF` at +3.

2. **Equality does not suppress comparison.**  
   With a zero gate and both relevant control fields equal to 2, F-6bd9dee8da0b receives selector 0 and values 2 and 2.

3. **Notification requires both conditions.**  
   If the +12 read is nonzero but the control low two bits are zero, F-fede798223e7 is not called. If the field is nonzero and those bits are nonzero, it receives 0.

4. **Zero acquisition result is still initialized.**  
   With an empty slot and packed value `0x01`, acquisition occurs. If F-EXT-01 returns zero, zero is stored and F-EXT-02 receives zero, 250, 0, and 67.

5. **Acquisition and release are independently conditional.**  
   With an empty slot and packed value `0x03`, acquisition and initialization occur. If the slot is nonzero when the subsequent release check reads it, the release sequence follows. A nonzero acquisition result alone is insufficient.

6. **Initialization can prevent release.**  
   Under the same packed value, suppose acquisition returns a nonzero value but F-EXT-02 clears the slot and leaves it zero until the release check. Neither F-EXT-03 nor F-EXT-04 is called on that release path.

7. **Release argument is reread.**  
   If the release check observes a nonzero slot and F-EXT-03 changes it to zero, F-EXT-04 receives zero. After F-EXT-04 returns, the function explicitly clears the slot.

8. **Existing latch still permits the byte clear.**  
   If the mode read is 3, the auxiliary call leaves a nonzero low byte, and the latch read is 7, the byte at +1 is cleared. There is no explicit latch update or three-call action sequence.

9. **Packed fields are compared low to high.**  
   With control bit 5 set, mode not 3, packed byte `0xE4`, and previous packed byte `0x1B`, selectors 1–4 receive new fields 0, 1, 2, 3 and previous fields 3, 2, 1, 0, provided each earlier comparison preserves the previous packed byte.

10. **The mode decisions are separate.**  
    If the first mode read is 3 but a dependency changes it to another value before the later mode read, the auxiliary processing and all four packed comparisons can occur in the same invocation when their other conditions hold.
