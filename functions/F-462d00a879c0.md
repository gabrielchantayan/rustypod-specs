## Behavior

### Ordering model

The visible body contains no conditional branch or loop. It presents one ordered path, interrupted by many opaque calls.

The stages below preserve the order of the visible data accesses and material dependency arguments. Between those accesses are dependency calls, including calls with no explicit arguments in the representation. They remain observable barriers: they may access memory, change global storage, produce secondary outputs, fail, or not return. The contract does not treat them as pure or removable.

Values described as **captured** are values already read or returned at the relevant stage. A later reuse of a captured value is not a fresh read of its original memory location.

### 1. Initial indexed stores and bit extraction

After four initial indirect calls, a dependency-provided index selects a word destination at its four-scaled value plus 20. The incoming payload is stored there.

The function then reads a word from the incoming address plus 20. This read follows the payload store, so aliasing between these locations can affect the captured word.

A dependency receives the four-scaled index. After further calls:

- The incoming bit-source value is shifted right by 22, producing a value from 0 through 1023.
- The captured word is shifted right by 23, producing a value from 0 through 511.
- The first extracted value is stored at a word destination formed from a secondary dependency output, scaled by four, plus 20.
- A dependency is called with that secondary output twice, followed by the captured-word extraction and the incoming-value extraction.

A following dependency result is passed to another dependency. The captured-word extraction is also shifted right by another 23 bits and retained. Because its input is at most 511, this second extraction is necessarily zero under the represented unsigned 32-bit operations.

### 2. Repeated word preparation and first byte-directed write

Following another call group, the incoming-value extraction is stored at another dependency-selected four-scaled index plus 20. A subsequent call receives the corresponding scaled index.

After further calls, a different secondary output selects another four-scaled word destination plus 20. Zero is stored there. That secondary output is then passed to a dependency, followed by another result-forwarding pair of calls.

A later dependency-selected word destination receives the twice-shifted captured-word value. This store is therefore a word-sized zero store.

The function next reads a word at the address formed by:

- Masking the earlier secondary output with `0x1fffffff`.
- Shifting the masked value right by 19.
- Adding 20.

The resulting address lies between 20 and 1043 inclusive. It need not be word-aligned.

After additional calls, the newly captured word is shifted right by 22. The function then:

1. Reads a byte at address 1, because the previously retained twice-shifted extraction is zero.
2. Adds 17 to that byte’s unsigned value.
3. Stores the low byte of the new right-shifted word at the resulting destination.

The byte store destination is therefore between 17 and 272 inclusive.

A dependency is then invoked with three copies of a secondary word output and a fourth argument of zero. After another call, a dependency receives a zero-valued argument.

### 3. Byte clearing and capture of a shift source

After another dependency group, the function reads a byte at four times the latest right-by-22 extraction plus 1. Because that extraction is at most 1023, the byte-read address is between 1 and 4093 inclusive.

It adds 17 to the loaded byte and stores zero at that destination. A dependency then receives a newly returned index shifted left by two.

Further calls obtain another index and pass its two-bit-left-shifted form twice to a dependency. A later word result is captured, forwarded to another dependency, and retained for a subsequent right-by-23 argument.

The function next:

1. Reads the byte at address 1.
2. Stores zero at that byte’s unsigned value plus 17.
3. Captures a secondary dependency output for later left shifts.
4. Calls a dependency with three copies of that secondary output.

A following result-forwarding call receives both a new word result and the earlier retained word shifted right by 23.

### 4. Global publication and low-byte projection

After additional calls, the byte at address 1 is read again. Its unsigned value is captured as a base, and zero is stored at that base plus 17.

This is a fresh read of address 1; it is not required to equal the earlier reads.

Following more dependency calls, a new returned word is captured and stored in G-A. That same captured word is subsequently passed to a dependency.

After another call, the function reads a word at the captured byte-derived base plus 116, then stores that word’s low byte at the same base plus 1.

Next:

- A dependency receives the saved secondary output shifted left by 11.
- Another dependency returns a paired result.
- A following call receives its low half, its high half, and the captured G-A publication value shifted right by 23.

Further calls yield another index. Its four-scaled value becomes a new base. The function reads a word at that base plus 116 and writes its low byte at that base plus 1.

After another call group returns a different index, the function retains that new index’s two-bit-left-shifted value. Before using it, it repeats the word-read/byte-write operation at the **previous** base: word at plus 116, low byte stored at plus 1. This is a fresh word read, not reuse of the first word.

A dependency then receives:

- The saved secondary output shifted left by 12.
- Two copies of the newly retained scaled index.
- The new unscaled index shifted left by 18.

### 5. Full-word propagation and link-like stores

After result-forwarding calls and another dependency group, a new four-scaled base is selected.

The function reads a full word at that base plus 116 and captures it. It immediately writes that word’s low byte at the base plus 1. Unlike the preceding projection stages, this full word is also retained for later stores.

Following further calls, the captured full word is stored at a destination formed from a new dependency index multiplied by 16, plus 20. This stride differs from the four-byte stride used elsewhere.

A dependency then receives the retained scaled index shifted right by two and subsequently left by 16. The right shift acts on the already formed 32-bit scaled value. It must not be replaced with the original index without proving that the earlier left shift discarded no relevant bits.

After more result forwarding and calls:

- The captured full word is stored at another dependency-selected four-scaled index plus 20.
- A dependency receives that scaled index.
- A later returned index is shifted left by two.
- That shifted value is stored at the retained scaled index, masked with `0xfffffffc`, plus 20.
- A dependency receives two copies of the newly shifted value.

The retained scaled index already has two zero low bits under the represented bit operations. The mask does not recover any high bits discarded when it was formed.

### 6. Zeroing, paired-result linkage, and global-based read

After another result-forwarding chain, zero is stored at a dependency-selected four-scaled index plus 20. A following call receives the corresponding scaled index.

Another call group returns a paired result. The low half is shifted left by two and captured; the high half selects a four-scaled word destination plus 20. The shifted low half is stored there.

The function then reads G-B and captures its address value **before** the next dependency call. That call receives, in order:

- The shifted low half.
- The high half.
- Two further copies of the shifted low half.

After intervening calls return another index, the same shifted low half is stored at that index’s four-scaled value plus 20. Only then does the function read a word at the previously captured G-B address plus 20.

Consequently, a dependency changing G-B after its capture does not change the base used by this read. It may still change the memory at that base.

### 7. Final byte-directed writes and termination

A subsequent call group returns another paired result. Its low half is retained for later addressing.

The function:

1. Shifts the previously captured full word from the propagation stage right by 23.
2. Reads a byte at that result plus 1.
3. Adds 17 to the loaded byte.
4. Stores the low byte of the word read through captured G-B at that destination.

A dependency then receives three copies of the paired result’s high half and the low half shifted left by two.

After additional calls, another byte-directed write occurs:

- The retained low half is masked with `0x3fffffff`, shifted right by 21, and incremented by 1 to select a byte read.
- Seventeen is added to the loaded byte.
- The stored byte is the low eight bits of the G-B-derived word shifted right by 22.

The byte-read address is between 1 and 512 inclusive.

Further calls include one receiving a returned index shifted left by two, another receiving two copies of a shifted index, and a result-forwarding sequence ending in a byte result.

The final visible effects are ordered as follows:

1. Store zero through a secondary-output byte pointer.
2. Update G-A by combining the returned byte as its low eight bits with three bytes read from a global region beginning at address 9.
3. Store a zero halfword at the retained low paired-result half, masked with `0x3fffffff`, then shifted right by 7.
4. Invoke address zero with three explicit zero arguments.

The halfword address ranges from zero through `0x007fffff`; alignment is not guaranteed.

The three-byte global read occurs after the pointer-directed zero store. If those locations alias, the zero store can affect the reconstructed G-A value.

## Side effects

## Acceptance examples

These examples are conditional static consequences, not executed tests.

1. **Unsigned extraction boundary.** If the incoming bit-source word is `0xffffffff`, its right-by-22 extraction is 1023. The corresponding word stores and argument use 1023, not a sign-extended value.

2. **Double extraction produces zero.** If the initial captured word is `0xffffffff`, its right-by-23 extraction is 511. Shifting that result right by 23 yields zero. The later associated word store is zero, and the first associated byte selector reads address 1.

3. **Byte truncation after extraction.** If the word loaded from the masked secondary-output address is `0xffc00000`, its right-by-22 result is 1023. The first byte-directed store writes 255, while the later selector read uses address 4093.

4. **Read-before-write aliasing.** If the initial payload store targets the incoming address plus 20, the following word read observes the stored payload, assuming ordinary coherent memory and no intervening modification.

5. **Repeated reads remain distinct.** If a dependency changes the word at a retained base plus 116 between its two projection stages, the second byte store reflects the new word’s low byte.

6. **Captured global address.** If G-B contains address A when captured and a subsequent dependency changes G-B to B, the later word read still uses A plus 20. Its contents may nevertheless have changed.

7. **Byte-directed destination.** If a selector byte is 255, the destination formed by adding 17 is address 272. The addition is not truncated back to a byte.

8. **Final halfword destination.** If the retained low paired-result half is `0xffffffff`, the final halfword address is `0x007fffff`. Successful execution requires support for that potentially unaligned store.

9. **Terminal call failure.** If execution reaches the final call and address zero is not executable, normal return is not established. Earlier writes are not rolled back by any visible mechanism.
