# F-118f3b0c1b9a

## Purpose

F-118f3b0c1b9a is a read-only predicate over an address-like input. A zero input is rejected. For a nonzero input, the function reads a 32-bit field at byte offset `0x40` and compares it with values obtained from two global reference slots.

With valid memory and stable reference slots, the result is exactly:

- `1` if the field equals either reference value.
- `0` otherwise.

The apparent intent is a two-value membership check. The supplied material does not establish what the containing object represents, what the field means, or why those two reference values are accepted.

Repeated appearances of the first reference slot matter when describing the supplied expression structure. The stable-value membership rule must not be treated as a synchronization guarantee or a complete specification for concurrent mutation.

## Interface

**Input**

One integer-valued argument, interpreted as an address when nonzero.

The supplied representation uses a 32-bit integer model for the argument and the loaded field. It does not expose a typed object parameter, a length, or an accessible-memory bound.

For a nonzero input:

- The function derives an address by adding `0x40`, or 64 bytes.
- It reads one 32-bit value beginning at that address.
- Successful execution therefore requires that this four-byte field be readable under the target’s addressing and alignment rules.
- No other field of the addressed object is visibly accessed.

An ordinary contiguous object satisfying this access would extend through byte offset `0x43`, inclusive. That is an access requirement, not evidence that the function validates a 68-byte object or knows its allocation size.

**Output**

A four-byte return value with only two visible normal outcomes:

| Value | Meaning |
|---|---|
| `1` | The comparison logic accepts the field. |
| `0` | The input is zero, or the comparison logic rejects the field. |

The result is a Boolean encoded as a four-byte value. There is no visible negative error code, returned pointer, output parameter, or separate diagnostic result.

**Reference slots**

For this contract:

- **Reference A** denotes the first global reference slot.
- **Reference B** denotes the second global reference slot.

These are descriptive labels, not claims about the application-level identities of those globals. Both participate as 32-bit comparison values. The function does not dereference their contents as addresses.

## Behavior

### Zero input

A zero input returns `0`.

This path does not read the field at offset `0x40` and does not evaluate either reference slot. In particular, the function does not attempt to read address `0x40` merely because the input is zero.

### Nonzero input: field acquisition

The field is read before the reference-comparison sequence.

The field value is acquired once in the supplied representation and reused throughout the comparisons. There is no visible second read of the object field. A later change to the field therefore does not, by itself, alter the already-acquired value used by this invocation.

This statement describes the supplied representation. It does not establish atomicity, a memory barrier, or a concurrent-access guarantee.

### Nonzero input: reference selection

The reference-selection sequence has two distinct uses of Reference A:

1. An initial value from Reference A is retained as a comparison candidate.
2. The acquired field is compared with Reference A in a subsequent expression evaluation.

If that comparison is unequal, the retained candidate is replaced with a value read from Reference B.

If that comparison is equal, Reference B is not evaluated on this path, and the retained candidate remains the initial value obtained from Reference A.

Consequently, the initial Reference A value and the value used by the selection comparison are conceptually distinct observations in the supplied expression structure. They are equal when the slot remains stable, but the evidence does not justify declaring them inseparable under all execution conditions.

### Nonzero input: final decision

After candidate selection, the function evaluates a final comparison between the acquired field and Reference A.

- If this comparison is equal, the function returns `1`.
- Otherwise, it compares the acquired field with the retained candidate.
- If that comparison is equal, it returns `1`.
- If both final comparisons are unequal, it returns `0`.

The final decision is short-circuited: equality with Reference A is sufficient for acceptance, without needing the candidate comparison to decide the result.

### Stable-reference interpretation

When both reference slots remain unchanged during the call:

- Equality with Reference A produces `1`.
- Otherwise, Reference B becomes the candidate, and equality with it produces `1`.
- A field unequal to both produces `0`.

If both references contain the same value, that value is accepted and every different value is rejected.

All 32-bit bit patterns can participate in equality comparisons. Zero is special only for the input address-like argument. A zero field or a zero reference value is not separately rejected.

### Width and address arithmetic

The offset is 64 bytes, not 64 elements. The only visible arithmetic is the address derivation for the field access.

There is no visible overflow check, range check, alignment check, or recovery path around that derivation. The supplied material does not establish whether an extreme input causes wrapping address arithmetic, an invalid access, or another target-specific outcome. This contract therefore does not promise modular address wrapping.

No arithmetic is performed on the field or reference values. Signedness does not change equality between values represented at the same 32-bit width.
