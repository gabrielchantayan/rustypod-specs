# F-328f589c6721

## Purpose

F-328f589c6721 coordinates a state-dependent retrieval operation on an object. It selects one of two virtual retrieval operations, extracts three 32-bit record fields on success, and reports a 32-bit status. The ordinary retrieval path additionally updates an object-side cache and derives two output flag bits.

A separate prerequisite operation runs when an object state byte is nonzero. Failure of that prerequisite prevents retrieval.

**Established behavior:** the function distinguishes an exact incoming flags value of `0x00000056` from every other value. It returns zero on either successful retrieval path and one on the explicit failure paths shown.

**Inferred intent:** the two virtual operations appear to provide alternative representations of a retrieved item. The object state bytes appear to track a prerequisite requirement and a pending notification. Their application-level meanings are not established.

This contract describes the supplied static representation. It does not establish runtime behavior of dependencies or validate the inferred intent.

## Behavior

### Initial setup

Before inspecting the object state byte, the function performs these operations in order:

1. Invokes F-2c088c92fdf7 with a local 16-byte work area.
2. Writes a fixed global-derived word into the first word of a separate local five-word work area.
3. Invokes an initialization dependency with a global-derived argument. No opaque ID was supplied for this dependency.

Only the first word of the five-word area is explicitly initialized by the function before that initialization dependency. The remaining words have no established initial values.

These calls occur even when the later prerequisite or retrieval operation fails. Their effects are not assumed to be limited to the local work areas.

### Prerequisite state handling

After setup, the function reads the byte at object offset `0x1BE`.

- If the byte is zero, retrieval selection follows immediately.
- If the byte is nonzero, the function calls F-276921bae885 with:
  - the current word at object offset `0x004`;
  - the request value;
  - the local 16-byte work area.

If F-276921bae885 returns zero, the function writes zero to object byte `0x1BE` and proceeds to retrieval selection.

If it returns nonzero:

1. The first field output is written with zero.
2. The second field output is written with zero.
3. The function selects return status one.
4. Common finalization runs.

On this failure path, there is no explicit write to the third field output or flags output. There is also no explicit clearing of object byte `0x1BE`; dependency effects remain possible.

### Retrieval selection

The function reads the current flags output word after any prerequisite call and its successful state-byte clearing.

- Exactly `0x00000056` selects the virtual operation at table offset `0x28`.
- Every other 32-bit value selects the virtual operation at table offset `0x24`.

This is an exact full-word comparison, not a bit test. For example, `0x00000156` selects the ordinary operation.

The word read at this point is not necessarily the value originally supplied by the caller: earlier dependencies may have changed reachable storage, and caller-provided addresses may alias object storage.

### Ordinary retrieval: table offset `0x24`

The selected operation receives the object, request value, local 16-byte work area, and zero.

After it returns, the function performs two writes before testing its result:

1. Writes one to object byte `0x1BE`.
2. Writes zero to the flags output word.

These writes occur whether retrieval succeeded or failed.

If retrieval returned nonzero, the function writes zero to the first field output, then zero to the second field output, and selects return status one. It does not explicitly write the third field output or object cache on this failure path.

If retrieval returned zero, ordinary success processing follows.

#### Ordinary success extraction and cache update

F-0a14bde72a48 receives the local 16-byte work area and a location into which it supplies a record address.

The function then performs the following accesses in order:

1. Reads the record word at `+0x04`, then writes it to the first field output.
2. Reads the record word at `+0x00`, then writes it to the second field output.
3. Reads the record word at `+0x08`.
4. Writes that third word to the third field output.
5. Writes the same captured third word to object offset `0x1C0`.

The record words are not all read before output writes begin. Aliasing can therefore affect later record reads.

#### Ordinary success flag processing

After updating the cache, the function reads object byte `0x1BD`.

If that byte is nonzero:

1. It reads the current flags output word and writes back that word with bit `0x2` set.
2. It writes zero to object byte `0x1BD`.

If the byte is zero, neither operation occurs.

The function then calls F-3a00245f0bc0 with:

- the current word at object offset `0x004`;
- the request value;
- an address for a local 32-bit result.

Only the low 32 bits of this dependency’s represented return are used as a success indicator. If those bits are zero, the function compares the current third field output word with the local result written by the dependency. If their 32-bit values are equal, it reads the current flags output word and writes back that word with bit `0x1` set.

If the dependency’s low 32 return bits are nonzero, no comparison-dependent flag write occurs.

This dependency’s failure does **not** turn successful retrieval into function failure. The function selects return status zero regardless of whether bit `0x1` is set.

### Alternate retrieval: table offset `0x28`

2. Writes zero to the flags output word.

2. Reads record word `+0x00` and writes the second field output.

### Aliasing and access order

No non-aliasing guarantee is established. The access order above is observable if output addresses overlap each other, the object, or a returned record.

Consequences include:

- Overlapping first and second outputs receive sequential writes; the second write is later.
- Output writes can change record words not yet read.
- Clearing the flags word can overwrite other reachable storage if it aliases that storage.
- The ordinary-path equality check rereads the third output after F-3a00245f0bc0 returns. It does not compare an immutable saved copy of the extracted value.
- Pending-byte clearing occurs after setting flags bit `0x2`; overlapping storage can affect the resulting bits.

The ordinary-success cache write uses the captured third record word even if the immediately preceding third-output write changes aliased record storage.
