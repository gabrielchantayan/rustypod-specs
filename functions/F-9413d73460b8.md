# F-9413d73460b8

## Purpose

F-9413d73460b8 coordinates preparation of a statement-like object from input text and a mutable context. It checks entry-associated locks, chooses direct or copied input, invokes an input-processing dependency, reconciles status and schema state, optionally configures metadata and attaches text, and conditionally publishes an object.

“Statement,” “schema,” “parser,” and “retained text” are inferred roles. The established contract is the visible sequence of reads, writes, calls, and branches; it does not include undocumented behavior of dependencies.

A critical distinction is maintained between the **captured status**, used for eventual publication decisions and reporting, and the **current work-region status**, read separately when deciding whether to configure metadata. Likewise, the produced-object field is not one stable object reference throughout execution.

### Preconditions and arithmetic

The required output must support the initial write. A nonzero tail-output address must support its conditional write. Context, entry, input, and produced-object storage must support every access reached.

For every nonnegative extent, input selection reads the byte at input plus extent minus one before checking the copied-input limit. Extent zero therefore reads the byte immediately preceding input. Negative extents avoid this probe.

Addresses and pointer differences are represented with 32-bit quantities. The copied-tail translation uses 32-bit unsigned arithmetic. There is no explicit overflow, bounds, or tail-range validation. Signed extent and entry-index expressions do not establish portable behavior for overflow. Invalid addresses, wraparound into invalid storage, or disruptive aliasing are outside the established safe-input contract.

Output aliasing is not rejected. Where an output write changes relevant work or context storage, subsequent reads observe that change according to the ordering below. Examples assume non-disruptive aliasing unless stated otherwise.

## Behavior

### 1. Clear the output and inspect entry locks

After zeroing the diagnostic slot, the function explicitly writes zero to the object-output destination.

The entry scan begins at index zero and compares the index against the signed context count on each iteration. A zero or negative count skips the scan. Neither the count nor array base is established as an immutable snapshot.

For each entry, the function reads its handle. A zero handle causes no handle-dependency calls. For a nonzero handle, it performs these calls in order:

1. F-0b4658e20c99 with the handle.
2. F-20c927c36211 with the same captured handle and integer arguments 1 and 1.
3. F-96dd78c4ca33 with that handle.

The inquiry’s zero/nonzero result is retained across the third call. A nonzero result then selects the lock-failure path. The entry-array base and the entry’s first word are read after those calls for diagnostic reporting. F-a061acf353ed receives the context, status 6, a schema-lock diagnostic, and that first word. The function returns 6.

This path performs no explicit tail-output write, work-region initialization, parsing, or common-path status normalization. Its only explicit object-output write is the initial clear; dependencies are not assumed to preserve that destination.

### 2. Initialize work storage and select input

After the scan, the initializer receives the private region and size 424. The function then writes the context address at work offset 0. The initializer’s actual contents are unknown.

Input selection is:

- Negative extent: use the original input directly, without a final-byte probe.
- Nonnegative extent with a zero probed byte: use the original input directly.
- Nonnegative extent with a nonzero probed byte: take the bounded-copy route.

On the direct route, F-ec7e4df6b93d receives the work-region address, original input, and diagnostic-slot address. The tail field is read after that call. The copied-input extent limit is not checked on this route.

On the bounded-copy route, the signed context limit is compared with the signed extent. If the limit is smaller, F-a061acf353ed receives status 18 and the diagnostic “statement too long,” and the function returns 18. No parser call or explicit tail-output write occurs. There is no further explicit object-output write after the initial clear; its actual value at return depends on intervening dependency effects.

Otherwise, F-7129d6a8d912 receives the context, original input, and extent:

- A zero result skips parsing and selects input plus extent as the candidate tail.
- A nonzero result is passed to F-ec7e4df6b93d. F-94cb53877c15 is then called with that temporary address. Only after this call does the function read the work-region tail and translate it into the original input address space.

The translation adds the original input address to the difference between the then-current tail and the captured temporary address. Thus, a dependency-induced change to the tail during F-94cb53877c15 affects the translation. No temporary-buffer byte read is shown during translation.

The candidate tail is written into the work-region tail field on both input routes. A zero copy result does not itself cause an explicit failure-status assignment.

### 3. Reconcile failure and schema state

The function reads context byte 30:

- Nonzero forces work status 7.
- Zero permits status 101 to become zero.
- Other statuses remain unchanged at this checkpoint.

It then reads the schema-check indicator. If zero, F-a77a3d5c108b is skipped. If nonzero, that dependency receives the context.

A zero inquiry result explicitly sets work status 17 and selects F-aacdb1821b51. Otherwise, including when the inquiry was skipped, the current work status is tested; status 17 selects the same dependency. F-aacdb1821b51 receives the context and zero.

The failure byte is read again after schema processing. Nonzero again forces work status 7.

The work status is then captured for later publication control, diagnostics, and final normalization. This capture precedes the optional tail-output write.

If the tail-output address is nonzero, the current work-region tail is written there, regardless of captured status. This write may affect later reads if the destination aliases relevant storage.

### 4. Configure metadata using current work state

The metadata-stage entry test reads the work-region status **after** the optional tail-output write. It does not test the earlier captured status.

When that current status is zero, the produced-object field is read. If nonzero, the metadata-mode byte is read and captured; otherwise the effective mode is zero. Metadata proceeds only if a further object-field read is nonzero and the captured mode is nonzero.

The mode is not refreshed during configuration. The object address, however, is reread separately for the column-count call and every label-setting call.

For captured mode 2:

- F-6f2595a8254b receives the current object and count 3.
- F-b3011fb31d40 receives indices 0, 1, and 2, in order.
- The visible labels are “order” at index 0 and “detail” at index 2. The middle label’s bytes are unavailable.

For every other nonzero captured mode:

- F-6f2595a8254b receives the current object and count 8.
- F-b3011fb31d40 receives indices 0 through 7, in order.
- “opcode” is supplied at index 1 and “comment” at index 7. Other label bytes are unavailable.

Each label call also receives zero and the 32-bit value 4,294,967,294. Its ownership or sentinel meaning is unknown.

Returns are not checked. Once the sequence begins, it does not repeat the status, mode, or nonzero-object eligibility checks between calls. A dependency that changes the object field redirects subsequent calls, including to address zero.

### 5. Attach text to a captured object

When the retain-text flag is nonzero, the function captures the then-current produced-object address and reads the current tail field. The tail read has no established role in the allocation arguments.

If the captured object is nonzero, its first word and the original input address are visibly supplied to F-7129d6a8d912. No extent argument is established for this invocation.

The returned 32-bit value, including zero, is written at offset 328 of the **captured object**. Changing the work-region object field during the dependency does not redirect this write.

This stage is independent of captured status and metadata eligibility. No explicit release of an earlier value at offset 328 occurs.

### 6. Publish or enter the nonpublication path

If captured status is zero, context byte 30 is read again.

When both captured status and this failure byte are zero, the function reads the current produced-object field and writes it to the object output. A zero object is allowed. This address may differ from objects used for metadata or retained text.

Otherwise, F-f0392a59c9a9 is called with no explicit arguments established by the supplied representation. Its target and cleanup effects are unknown.

A failure flag raised during metadata or text attachment can therefore prevent explicit publication while later reporting still uses captured status zero. Conversely, changing only the work status after its capture does not change that captured status.

### 7. Report diagnostics and normalize the return

The diagnostic slot is tested after publication or the nonpublication call.

- If zero, F-a061acf353ed receives context, captured status, and a zero diagnostic argument.
- If nonzero, F-a061acf353ed receives context, captured status, and an opaque static diagnostic argument.

In the nonzero branch, the diagnostic slot is read **again after** F-a061acf353ed returns. That newly read value is passed to F-94cb53877c15, even if it differs from the branch-selecting value or is now zero. The initial nonzero value is not preserved for this call.

Finally, F-15a13295fe3c receives context and captured status, and its result is returned unchanged.

There is no explicit object-output clear following publication. Later dependencies may nevertheless change reachable output storage, and normalization may return nonzero after an object was explicitly published.

## Side effects

Established explicit writes comprise diagnostic-slot initialization, the initial object-output clear, work-region updates, the optional tail-output write, retained-text-result storage, and conditional object publication. Dependencies may perform additional writes.

The temporary input address is passed to F-94cb53877c15 after parsing and before tail translation. On the nonzero-diagnostic branch, that dependency instead receives the diagnostic-slot value reread after reporting, not necessarily a nonzero or original value.

These calls do not establish allocator compatibility, successful release, or ownership transfer. The original input is not explicitly written or passed as the temporary-release argument.

Metadata calls can target multiple objects because each call rereads the object field. Retained-text storage targets its separately captured object. Publication reads the field again.

A published object becomes caller-accessible, but ownership, lifetime, and disposal obligations remain documented_only. No dependency is assumed to preserve globals, context, work storage, outputs, or other reachable memory.

## Acceptance examples

These are conditional static expectations, not executed tests. Storage is valid, dependencies return normally, and relevant storage is preserved except where a mutation is expressly stated.

1. **Lock inquiry reports nonzero.** The three handle calls occur in order before reporting status 6 and returning 6. There is no explicit tail-output write.

2. **Excessive extent, nonzero final byte.** The probe precedes the limit check. Status 18 is reported and returned without parsing. The object output remains zero only if intervening dependencies preserve its initial clear.

3. **Excessive extent, zero final byte.** Direct processing occurs without the copied-input limit check. A negative extent also selects direct processing, but performs no final-byte probe.

4. **Zero extent.** The preceding input byte is probed. A zero byte selects direct processing; a nonzero byte selects the bounded route and its signed limit comparison.

5. **Copied tail twelve bytes into temporary storage.** If the tail remains unchanged through F-94cb53877c15, translation selects original input plus twelve. A change during that dependency affects the translated result.

6. **Copy returns zero.** Parsing is skipped and the candidate tail is input plus extent. No failure status follows solely from this result.

7. **Schema inquiry returns zero.** Status 17 is assigned and F-aacdb1821b51 is called. A subsequently observed failure flag overrides status to 7.

8. **Tail-output alias changes work status.** If captured status is nonzero but the tail write changes current work status to zero, metadata may run. Later reporting still uses the nonzero captured status. The reverse change can suppress metadata despite captured status zero.

9. **Metadata redirects the object.** With captured mode 2, suppose the count call changes the object field from one valid object to another. Index 0 uses the second object. If that call then sets the field to zero, the remaining label calls receive zero; the sequence is not abandoned.

10. **Retention changes the work object field.** If retention captures object A and its allocation dependency changes the field to object B, the result is stored at A plus 328. With captured status zero and a clear final failure flag, publication subsequently reads B.

11. **Diagnostic reporting replaces the slot.** A nonzero slot selects the diagnostic branch. If reporting changes it to zero, F-94cb53877c15 receives zero. If reporting replaces it with another address, that replacement is supplied.

12. **Attachment raises the failure flag.** With captured status zero, publication is bypassed and F-f0392a59c9a9 is invoked. Reporting and normalization still receive captured status zero.
