# F-71bf6a927832

## Purpose

F-71bf6a927832 performs a fixed sequence of computed-address memory writes and indirect dependency calls, followed by an unconditional repeating tail. Its application-level purpose is not established. The supplied evidence does not justify identifying it as initialization, serialization, allocation, device control, or cleanup.

This is a **documented_only static behavioral contract**. It describes the operations represented in the supplied material, conditional on correct decoding and reachability. Warnings about invalid instruction data and removed unreachable regions prevent treating that representation as a complete, independently validated executable specification.

## Interface

### Inputs and entry state

The explicit interface contains one 32-bit integer argument, called the **input word**.

Additional entry-state dependencies are visible:

- A 32-bit unsigned incoming register value, called the **seed word**, is consumed without appearing in the explicit argument list.
- An incoming link-register value participates in forming the first indirect call target.
- A further 32-bit register value is consumed after the second call group. This document calls it the **secondary word**. Its producer, lifetime, and calling-convention meaning are unresolved. It must not be equated with the ordinary result of the preceding call.

The explicit argument alone therefore does not establish the complete invocation contract.

### Outputs and completion

No explicit return value is represented. Observable outputs consist of memory effects and dependency interactions.

The visible control flow has no normal return. Once the repeating tail is reached, it has no represented exit condition. Successful memory accesses and returning dependencies therefore lead to continued iteration, not normal completion.

This does not establish that every actual invocation reaches that tail. A dependency may not return, an access may fault, or the damaged representation may omit relevant control flow.

### Widths and arithmetic

The represented operations use 32-bit words, unsigned masks and logical right shifts, and 8-bit memory accesses. An unsigned byte read produces a value from 0 through 255. A byte write retains only the low eight bits of its value.

Computed-address width is not independently established. Arithmetic involving signed values includes operations whose overflow or shift behavior cannot safely be inferred from a source-language interpretation.

Where needed, this contract uses a conditional **32-bit machine-word model**: multiplication, addition, and left shifting retain the low 32 bits. Numerical examples involving overflow depend on that model. They do not establish defined signed arithmetic at a higher-level interface.

### Memory preconditions and layout

Normal progress requires every computed address to permit its indicated access width. Indirect call targets must be executable under the actual architecture and calling convention.

No bounds checking, null checking, alignment validation, access-failure recovery, buffer length, or ownership-bearing pointer parameter is represented. Integers are used directly in address calculations.

Several word destinations use a displacement of 20, but differing multipliers prevent assuming one uniform indexed structure. Endianness, alignment requirements, valid mappings, and any object layout remain undocumented.

## Behavior

### Dependency notation

D-01 through D-20 are opaque dependency call-site family IDs. They identify positions in the represented sequence, not proven distinct function identities.

A **five-call group** consists of five consecutive indirect calls. Unless stated otherwise:

- The first call receives the explicit arguments specified for that group.
- The remaining four calls have no explicit arguments shown.
- The **group result** is the explicit result of the fifth call.

“No explicit arguments shown” does not mean that a dependency has no register, stack, global, or memory inputs. Unused explicit results do not imply an absence of side effects.

### Entry and first two call groups

Before any represented dependency call, the routine writes the input word as a 32-bit value at:

**4 × input word + 20**

It derives an **initial scaled word**, eight times the seed word, and a **shifted seed**, the seed word logically shifted right by eight.

D-01 is a five-call group whose first argument is the initial scaled word. Its first target depends on the incoming link-register value.

After D-01, the routine writes the initial scaled word at:

**initial scaled word + 20**

D-02 is a five-call group whose first argument is four times D-01’s result. The secondary word is consumed after this group; no ordinary D-02 result is used in its place.

### Remaining word-store sequence

The following stores continue the sequence. Their numbering includes the two entry-stage stores. Intervening calls are part of the ordering; the stores are not an atomic batch.

| Word store | Computed address | Value written |
|---|---|---|
| 3 | 67,108,864 × secondary word + 20 | 16,777,216 × secondary word |
| 4 | 4 × D-03 result + 20 | 16,777,216 × secondary word |
| 5 | 16 × D-04 result + 20 | 4 × D-04 result |
| 6 | 4 × D-06 result + 20 | 4 × D-04 result |
| 7 | 16 × D-07 result + 20 | 4 × D-07 result |
| 8 | 4 × D-09 result + 20 | seed word logically shifted right by 16 |
| 9 | 16 × D-10 result + 20 | 4 × D-10 result |
| 10 | 16 × D-10 result + 20 | 16 × D-10 result |

The dependency ordering and argument flow are:

- **D-03**, after store 3: five calls; first argument is 16,777,216 times the secondary word. Its result determines store 4’s address.
- **D-04**, after store 4: five calls; first argument is four times D-03’s result. Its result determines store 5.
- **D-05**, after store 5: four calls. The first receives four times D-04’s result. The second returns a 32-bit word passed to the third. The fourth returns a further word.
- **D-06**, after D-05: five calls; first argument is D-05’s fourth-call result. Its result determines store 6’s address.
- **D-07**, after store 6: five calls; first argument is four times D-06’s result. Its result determines store 7.
- **D-08**, after store 7: four calls. The first receives four times D-07’s result. The second returns a word passed to the third. The fourth returns a further word.
- **D-09**, after D-08: five calls; first argument is D-08’s fourth-call result. Its result determines store 8’s address.
- **D-10**, after store 8: five calls; first argument is four times D-09’s result. Its result determines store 9.
- **D-11**, between stores 9 and 10: five calls, with three explicit arguments on its first call.

For D-11, define the **scaled destination** as sixteen times D-10’s result. Its first call receives, in order:

1. The scaled destination.
2. The same scaled destination.
3. The shifted seed logically shifted right by seven, equivalent to the seed word logically shifted right by fifteen.

Stores 9 and 10 use the same computed address, **scaled destination + 20**. Store 9 writes four times D-10’s result; store 10 writes the scaled destination itself. D-11 separates these writes and may observe or alter memory between them.

D-12 follows store 10. It is a five-call group whose first argument is four times D-11’s result.

### First selector family

The **first selector address** is derived from the retained value four times D-07’s result:

**((retained value AND 2,147,483,647) logically shifted right by 7) + 1**

Each use reads an unsigned byte at this address. That byte plus 17 becomes the destination address for a byte store. The selector is reread for every such store; neither its previous value nor its previously selected destination is reused.

After D-12, the first selector-family store writes the low eight bits of four times D-12’s result.

D-13 then makes two calls. Its first call receives three identical explicit arguments, each four times D-12’s result. Its second call supplies a word result.

D-14 is a five-call group whose first argument is D-13’s second-call result.

After D-14, another read of the first selector address selects the destination for a byte store whose value is the low eight bits of:

**(D-12 result AND 1,073,741,823) logically shifted right by 20**

This value depends on the retained D-12 result, not D-14’s result.

### Direct byte store and first-selector zero stores

D-15 is a five-call group whose first argument is four times D-14’s result.

The routine then performs, in order:

1. A direct byte store at **(seed word logically shifted right by 23) + 28**, writing the low eight bits of four times D-15’s result.
2. A fresh read of the first selector address.
3. A zero-byte store at that selector byte’s unsigned value plus 17.

The direct store precedes the selector read. If those addresses alias, its effect can change the selected destination.

D-16 consists of two calls. Its first call receives the seed word logically shifted right by 23. No explicit result from its second call is subsequently consumed.

D-17 is a five-call group whose first argument is:

**(D-15 result AND 1,073,741,823) logically shifted right by 6**

After D-17, the routine rereads the first selector address and writes zero at the resulting unsigned byte value plus 17.

D-18 is a five-call group whose first argument is four times D-17’s result.

### Second selector family and loop entry

The **second selector address** is derived from the retained value four times D-15’s result:

**1,024 × retained value + 1**

After D-18, the routine derives an initial **loop field**:

**(D-18 result AND 1,073,741,823) logically shifted right by 25**

This field ranges from 0 through 31.

The routine reads an unsigned byte at the second selector address and writes zero at that byte’s value plus 17.

D-19 consists of two calls. Its first call receives twice the initial loop field, ranging from 0 through 62. Its second call supplies the initial **carried result** for the repeating tail.

### Repeating tail

Each iteration contains two five-call groups, collectively identified as D-20.

The first group’s first call receives:

- The current carried result.
- The current loop field logically shifted right by eight.

On initial entry, the second argument is zero because the initial loop field is at most 31.

After the first group, the routine rereads the second selector address and writes zero at the selected unsigned byte value plus 17.

The second group’s first call receives four times the first group’s result.

The second group’s result determines the next iteration’s state:

- The next carried result is four times that result.
- The next loop field is that result shifted left by 26.

Under the conditional 32-bit model, the next iteration’s second explicit argument is the preceding second-group result’s low six bits shifted left by 18.

The represented first-call target of the first group differs between initial loop entry and subsequent iterations. These cases must not be assumed to invoke an identical target.

No exit condition or normal return is represented.

## Side effects

### Memory effects and ordering

The finite prefix contains **ten 32-bit stores and six byte stores**. The six byte stores, in order, are:

| Byte store | Destination family | Value |
|---|---|---|
| 1 | First selector | Low eight bits of 4 × D-12 result |
| 2 | First selector | Low eight bits of masked D-12 result shifted right by 20 |
| 3 | Direct seed-derived address | Low eight bits of 4 × D-15 result |
| 4 | First selector | Zero |
| 5 | First selector | Zero |
| 6 | Second selector | Zero |

Thus, the prefix has four stores through the first selector family, one direct store, and one store through the second selector family. Each completed loop iteration adds one further byte store through the second selector family.

There are five selector-byte reads in the prefix: four from the first selector address and one from the second. Each completed loop iteration adds one read from the second selector address.

Each selector read precedes its corresponding destination write. Calls, earlier writes, or external activity may change a selector’s contents, so a stable selector address does not imply a stable destination.

Every selector-derived destination lies between addresses 17 and 272 inclusive. This range is not evidence that those addresses are mapped or constitute an array.

Under the conditional 32-bit model:

- The first selector address lies between 1 and 16,777,216.
- The direct seed-derived byte address lies between 28 and 539.
- Arithmetic forming the second selector address may wrap.

Computed addresses may alias each other or memory accessed by dependencies. No non-aliasing guarantee is established.

The ordering described here is the order in the static representation. Atomicity, volatile semantics, barriers, processor memory ordering, device-memory behavior, and concurrent-observer guarantees are undocumented.

## Acceptance examples

These are conditional static acceptance cases, not runtime observations. They assume the relevant operations are reached, accesses succeed, and preceding dependencies return.

### Entry write

For input word 3, the first word store writes 3 at address 32. It precedes every represented dependency call.

### Seed-derived values

For seed word 0x12345678:

- Word store 8 writes 0x1234.
- D-11’s third explicit argument is 0x2468.
- The direct byte-store address is 64.
- D-16’s first explicit argument is 36.

These expectations concern represented retained values, not an assumption that dependencies preserve all registers or memory.

### Repeated word destination

If D-10’s result is 5, word store 9 writes 20 at address 100. After D-11, word store 10 writes 80 at address 100.

Collapsing these stores into one would discard an intermediate state that D-11 may observe.

### Selector rereading and truncation

If the first two reads of the first selector address return 2 and 7, the corresponding destination addresses are 19 and 24.

If D-12’s result is 65, the first of those stores writes 4: four times 65 is 260, whose low eight bits are 4.

If the direct seed-derived store changes the first selector byte, the following zero store must use the newly read selector value rather than an earlier cached value.

### Prefix and iteration counts

If the complete prefix executes, its visible stores total ten words and six bytes, excluding dependency-internal effects.

If one complete tail iteration then executes, the cumulative visible byte-store count becomes seven. Each further complete iteration adds one. Partial execution or dependency-internal stores do not satisfy this counting premise.

### Loop arguments and nontermination

For every possible D-18 result, the initial first-group second argument is zero.

Under the conditional 32-bit model, if a later second-group result has low six bits equal to 3, the next iteration’s corresponding argument is 786,432.

If all accesses succeed and all dependencies return, the tail continues without normal completion. A fixed iteration limit would introduce an exit absent from the representation.
