### Arithmetic constraints

The representation uses 32-bit working words and 64-bit result containers. Address-related arithmetic includes multiplication by 2, 4, 8, 256, and 2²⁵, subtraction by 0x96, and many left shifts.

For acceptance examples using machine-word arithmetic, **32-bit wraparound must be an explicit condition**, not an assumed property of all signed expressions. Several expressions are represented with signed operands; the supplied material does not independently establish their overflow and shift semantics.

Under a 32-bit bit-vector interpretation:

- Left-shifted bits above position 31 are discarded.
- A word shifted left by 28 and then again by 28 becomes zero.
- A word shifted left by eight and then logically right by eight retains its original low 24 bits.
- Masking to 24 bits before shifting left by six produces at most 30 significant bits.
- Replacing a shift-then-mask operation with a mask-then-shift operation may change the result.

Unsigned right shifts are zero-filling in the represented expressions. The late right shift of a signed word by a count derived from another value’s low byte is documented_only for negative operands or counts outside the supported machine range. A portable mathematical interpretation is not established.

## Acceptance examples

The following are **conditional static acceptance examples**, not executed tests.

1. **Input preservation.** Given input 0x89abcdef and a valid initial target, its first represented argument is 0x89abcdef. No byte narrowing occurs first.

2. **Result splitting.** Given a represented 64-bit result of 0x1122334455667788, its lower word is 0x55667788 and upper word is 0x11223344. Under 32-bit wrapping arithmetic, shifting the lower word left by eight gives 0x66778800.

3. **Narrow-store behavior.** Given a source word 0x123456ab, an 8-bit store records 0xab. It does not record the full word or convert it into text.

4. **Unsigned byte addressing.** Given a byte read of 0xfe, a subsequent base derived directly from that byte is 254, not −2. A read at that base +0x74 addresses 0x172, subject to address validity.

5. **Repeated-write observation.** Given an observer that records writes, consecutive identical stores remain separate events. Matching final memory alone does not establish matching behavior.

6. **Aliased readback.** If an intervening store overlaps the word later read at scaled base +0x14, the read must reflect the actual memory state at that point. It cannot be replaced by the value of an earlier zero store.

7. **No ownership assumption.** If an intermediate dependency invalidates storage used later, this contract supplies no lifetime extension or automatic recovery.

8. **Final continuation.** If the final indirect target returns normally, the represented continuation returns without an explicit result. If it does not return, an ordinary function return is not required.
