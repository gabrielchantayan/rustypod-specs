# F-24dd9761d12c

## Purpose

F-24dd9761d12c processes a caller-supplied source and destination using a repeated search-like dependency. Search begins at candidate position **1** and continues until a dependency returns the signed 32-bit value **−1**. The candidate supplied to that terminal invocation determines subsequent processing; the terminal return value itself does not become the construction position.

For a nonzero terminal candidate, the function reads a source field, obtains a measurement-like result, subtracts the candidate, and delegates destination construction. A separate branch directly writes two destination words when the candidate is zero, although that branch is unreachable through the displayed search recurrence under defined ordinary arithmetic.

Before invoking any dependency, the function performs **two separate reads of the same global 32-bit word**:

- The first read supplies a retained value for the explicit destination-writing branch.
- The second read initializes the first word of a local two-word temporary.

These are distinct observations. Their values are equal only if the global remains stable between the reads, or otherwise happens to yield the same value. The supplied body does not establish that stability.

After either result-processing branch completes normally, the function passes the temporary’s address to a final dependency.

“Search,” “measurement,” “construction,” and “finalization” describe inferred roles. The dependencies’ actual semantics, resource effects, and search-token contents are not established.

## Behavior

### Ordered initial observations

Before any dependency call, the function performs these operations in the displayed order:

1. Reads the global 32-bit word and retains that first observed value.
2. Reads the same global word again and stores this second observed value into the temporary’s first word.
3. Initializes the temporary’s second word to zero.
4. Initializes the search state to zero.

The retained first observation is used only by the explicit destination-writing branch. The second observation supplies the temporary’s initial first word.

No dependency is invoked between the two global reads. That fact does not prove equal values: the supplied body establishes neither synchronization nor immunity to external modification of the global.

After these initial reads, the wrapper does not visibly read the global again. Later dependency changes to that global do not cause the wrapper to refresh either captured value. This does not guarantee that dependencies cannot affect storage containing those values through other means.

### Search protocol

The function always invokes F-a21141daa905 at least once.

Each invocation receives:

1. The original source value.
2. The address of a fixed search-token storage location.
3. A signed candidate position.

The first candidate is 1 because the initial search state is zero and the candidate is formed by adding 1.

After each call:

- A return value of exactly −1 terminates iteration.
- Every other return value becomes the state used to calculate the next candidate.
- The next candidate is that nonterminal return value plus 1.

The wrapper does not validate that a returned value is nonnegative, increasing, within the source, or meaningful to the dependency.

The token address is unchanged across calls. Its contents are neither read nor copied directly by this wrapper. A constant address does not imply constant contents: the dependencies’ effects on that storage are unknown.

When search terminates, the retained candidate is the candidate passed to the invocation that returned −1. It is not replaced by −1 and is not recomputed from that return value.

### Explicit zero-candidate branch

If the retained candidate equals zero, the wrapper:

1. Writes the value from the **first** global read to destination offset 0.
2. Writes zero to destination offset 4.
3. Skips measurement and delegated construction.

The temporary remains separately initialized from the **second** global read, subject to any intervening effects not established by the supplied body.

Consequently, the value written to the destination’s first word and the value initially stored in the temporary’s first word need not be equal.

### Nonzero-candidate branch

If the retained candidate is nonzero, the wrapper:

1. Reads a 32-bit word from source offset 4.
2. Passes that word as the sole argument to F-d8cbf9aa79a9.
3. Subtracts the retained candidate from the dependency’s signed 32-bit result.
4. Calls F-ed33cfb647fe with the original destination, original source, retained candidate, and computed difference, in that order.

There is no visible clamp, bounds check, normalization, or rejection of a negative extent.

The source field is read only after search terminates. If search changes that field, the measurement dependency receives the value observed after those search calls, not an entry-time snapshot.

The wrapper does not directly initialize the destination before delegated construction. Any destination changes in this branch depend on dependency behavior.

### Zero-candidate reachability

Under ordinary defined 32-bit integer arithmetic, the zero-candidate branch is not reachable through the displayed recurrence.

The first candidate is 1. Each later candidate is a nonterminal search return plus 1. For that sum to be zero, the preceding return would have to be −1, but that value terminates iteration before another candidate is calculated.

The same conclusion holds for straightforward 32-bit wrapping addition: only the all-ones value increments to zero, and that bit pattern is the terminal signed value −1.

The branch is nevertheless present, so its conditional writes are part of the static contract. Its presence does not establish an ordinary input that selects it or justify interpreting it as an empty-input case.

### Final dependency and return

After either result branch completes normally, the wrapper calls F-289ec4311c64 with the temporary’s address, then returns without an explicit value.

The temporary was initialized using the second global observation and zero. The body shows no later direct writes to it before this call. That observation does not prove that unknown dependencies cannot affect its contents.

“Finalization” identifies this dependency’s position in the call sequence. It does not establish destruction, deallocation, reference counting, or any other ownership operation.

## Side effects

The established wrapper-level sequence is:

1. Read the global word for the retained explicit-branch value.
2. Read the same global word again for the temporary’s first word.
3. Initialize the temporary’s second word to zero and the search state to zero.
4. Invoke F-a21141daa905 one or more times.
5. Perform one selected result path:
   - Write the first global observation to destination offset 0, then zero to offset 4; or
   - Read source offset 4, invoke F-d8cbf9aa79a9, and invoke F-ed33cfb647fe.
6. Invoke F-289ec4311c64 with the temporary’s address.

This is the order visible in the supplied body, not a hardware memory-ordering or synchronization guarantee.

There are no explicit global writes in the wrapper. Dependencies may have additional effects, including changes to globals, source-related memory, destination storage, or token storage. Their preservation of any such state is not established.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, they assume valid storage, normally returning dependencies, and representable arithmetic.

### Distinct initial global observations

Suppose the first global read yields 17 and the second yields 23.

The retained explicit-branch value is 17. The temporary is initialized with first word 23 and second word zero. Neither value is substituted for the other.

If the zero-candidate branch were reached, its first destination write would be 17, not 23. The final dependency would receive the temporary’s address, whose initial first word was 23. Contents at the time of that call remain subject to intervening dependency effects.

This example specifies the two reads’ separate consumers; it does not assert that ordinary search results can reach the zero branch.

### Stable global

Suppose the global yields 31 on both initial reads.

The retained value and temporary’s initial first word are both 31. This equality follows from the example’s observations, not from an implementation guarantee that one captured value serves both purposes.

### Immediate search termination

Suppose the first search returns −1 and measurement returns 9.

- Search is invoked once with candidate 1.
- The retained candidate is 1.
- Source offset 4 is read after search.
- Construction receives candidate 1 and extent 8.
- Finalization follows normal construction completion.

The wrapper performs no direct destination initialization in this path.

### Several search results

Suppose search returns 3, then 7, then −1, and measurement returns 12.

The search candidates are 1, 4, and 8. Construction receives candidate 8 and extent 4.

The construction position is the last supplied candidate, not the last nonterminal return of 7.

### Negative extent

Suppose search immediately returns −1 and measurement returns 0.

Construction receives candidate 1 and extent −1. The wrapper neither rejects nor clamps the extent. Its acceptability is dependency-defined.

### Nonterminal negative return

Suppose search returns −2, then −1, and measurement returns 5.

The search candidates are 1 and −1. Construction receives candidate −1 and extent 6.

A negative candidate does not itself terminate iteration; only a search return equal to −1 does.

### Repeated nonterminal return

Suppose every search invocation returns 0.

Every candidate is 1. Search continues indefinitely, and the wrapper never reaches measurement, construction, or finalization.

### Source mutation during search

Suppose a search invocation changes source offset 4, and search subsequently terminates.

Measurement receives the field value read after termination. The wrapper does not preserve an earlier copy of that field.
