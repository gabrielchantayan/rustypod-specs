# F-6f3fb12114ac

## Purpose

F-6f3fb12114ac performs an ordered sequence of memory publications, retained reads, overlapping updates, and address-derived writes, followed by an unresolved indirect transfer carrying four arguments.

The supplied static representation establishes these operations but not their application-level meaning. It does not establish that the accessed regions are objects, that the offsets identify conventional fields, or that the final transfer invokes a particular service.

This contract distinguishes:

- **Established static evidence:** access widths, operand types, ordering, and value relationships visible in the supplied representation.
- **Inferred intent:** possible interpretations that impose no acceptance requirements.
- **documented_only:** behavior for which the supplied material does not support a definitive guarantee.

All behavior below is source-facing. No runtime tests have been performed.

## Behavior

### Arithmetic, truncation, and retained values

**Context A uses unsigned 32-bit arithmetic throughout its address calculations.** Every direct offset addition to Context A is reduced modulo \(2^{32}\). This includes +0x04, +0x08, +0x09, +0x0D, +0x10, +0x11, +0x14, +0x40, +0x44, and +0x54.

Doubling Context A is also unsigned 32-bit arithmetic. Define the **doubled context** as twice Context A, reduced modulo \(2^{32}\). Adding +0x54 to that result is another unsigned 32-bit calculation, again reduced modulo \(2^{32}\). Crossing the signed 32-bit boundary in any of these calculations creates no signed-overflow uncertainty.

The signedness of a memory access’s stored or loaded value does not change the arithmetic used to calculate its address. In particular, a word interpreted as signed when loaded from Context A +0x54 still comes from an address calculated using unsigned Context A arithmetic.

In contrast, offsets applied to Value, Destination, Context B, Context C, and the signed address-bearing values loaded later are represented using signed 32-bit arithmetic. Doubling the second loaded base and doubling the final link are likewise signed calculations. Behavior at signed-overflow boundaries for these expressions is **documented_only**; this contract does not substitute unsigned wrapping.

“Low byte” means the least significant eight bits of a value. Byte writes retain those bits rather than the full word. Word reads retained for later use are snapshots: later changes to the source location do not retroactively change the retained value. Separate reads of absolute address 0x67 remain distinct observations.

### Initial publication

The first visible memory effect is a word write of Value at Destination +0x54.

The initial publication then writes the low byte of Context A at Context B +0x19, followed by the low byte of Context B at Context A +0x11. Destination is subsequently written as a word at Context B +0x34.

A finite repeated publication region follows. Within each repeated group, the ordering is:

- Value is written as a word at doubled context +0x54.
- Context B +0x19 receives the low byte of Context A.
- Context A +0x11 receives the low byte of Context B.
- Context B +0x34 receives the doubled context as a word.

The representation shows repeated groups, not a data-dependent loop or advancing sequence of destinations. This contract leaves their exact numerical multiplicity **documented_only**. It does not permit treating the region as unbounded or replacing all repeated events with a single final-state update.

The initial write of Destination at Context B +0x34 precedes the repeated writes of the doubled context there. They remain separate events even when their values match.

### Snapshot acquisition and first updates

After the repeated publication region, the function reads a word at absolute address 0xA9, retained as the **absolute snapshot**, and then a word at Value +0x74, retained as the **payload snapshot**.

The next effect is a byte write at absolute address 0x3A. Its value is the low eight bits of twice the low byte of Context A plus 0x30. This describes the stored bits without requiring a particular signed interpretation of an intermediate character value.

The function then reads Context C +0x14 as the **saved context word**, followed by Context A +0x04 as the **link snapshot**. The latter address is an unsigned, modulo-\(2^{32}\) offset calculation.

The ensuing writes first place the low byte of Context A at Context C +0x0D and byte 0x6C at Context A +0x08. The low byte of Context B is written at Context A +0x0D and then at Context A +0x09. Next, Context C is written as a word at Context C +0x54, and the low byte of the absolute snapshot is written at absolute address 0x67.

Only after those writes does the function read Context C +0x44, interpreting the word as the signed 32-bit **shift source**.

### Shift-related and overlapping updates

The current byte at absolute address 0x67 is read and written to absolute address 0x21. This is a memory read, not an unconditional reuse of the retained absolute snapshot.

The low byte of the shift source is then written at Context A +0x10, followed by a complete word write of the shift source at Context B +0x54.

Context C +0x01 next receives the low byte of the result of right-shifting the signed shift source by the low byte of Context A. The count therefore ranges from 0 through 255. Counts of 32 or greater are **documented_only**, as is right shift of a negative signed source. Hardware count masking is not established.

After that byte write, Context B +0x54 is overwritten with the complete 32-bit Context A value.

The function reads Context A +0x40 as the **replacement word**. It then writes the retained link snapshot at Context B +0x74 and the replacement word at Context A +0x10. This word write overlaps the earlier byte write at +0x10 and the publication byte at +0x11, replacing their stored contents unless other aliases or intervening effects determine otherwise.

Next, Context B +0x44 receives Context C. A fresh read of absolute byte 0x67 supplies a write at Context A +0x09. The low byte of Context A is then written at Context C +0x09, followed by the absolute snapshot as a word at Context A +0x44.

### Loaded-address updates

A word read at Context A +0x54 supplies the signed 32-bit **first loaded base**. Its source address uses unsigned Context A arithmetic; subsequent offsets from the loaded value use signed arithmetic.

After this read, the current byte at absolute address 0x67 is again copied to Context A +0x09. The low byte of the payload snapshot is then written at first loaded base +0x0D, and the saved context word is written at Context C +0x54, replacing the earlier self-address write there.

The next read, at Context A +0x14, supplies the **secondary snapshot**. The low byte of the payload snapshot is then written at Context C +0x11. Context A +0x09 receives the low byte of the first loaded base, and Context A +0x44 receives the complete first loaded base.

These reads occur after the preceding writes. An aliased write can therefore affect a later loaded value; the contract does not assume an unchanged initial object state.

### Final updates and transfer

A signed word read at Context C +0x04 supplies the **second loaded base**. The function writes the 16-bit value 0x0065 at twice this base. This is a two-byte store, not a one-byte character write. Its address calculation is signed; overflowing the signed doubling remains **documented_only**.

A signed word read at second loaded base +0x64 supplies the **final link**. The function then writes the low byte of the secondary snapshot at first loaded base +0x11 and the word value 100 at first loaded base +0x54.

After these writes, a word read at second loaded base +0x74 supplies the **transfer snapshot**. A signed word read at Context C +0x64 then supplies the **third loaded base**.

The final visible memory effects, in order, are a byte write of the low byte of the second loaded base at Context C +0x09, a word write of the final link at third loaded base +0x54, and a word write of the third loaded base at twice the final link. The last address uses signed doubling, not the unsigned arithmetic associated with Context A.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

### Unsigned direct-offset wraparound

Assume Context A is 0xFFFFFFF0 and execution reaches the initial Context A +0x11 byte write after all preceding accesses succeed. That byte write addresses 0x00000001 and stores the low byte of Context B.

The address follows from unsigned 32-bit addition. It is not an unresolved signed-overflow case. This example does not establish that address 0x00000001 is writable or that later execution succeeds.

For the same Context A value, Context A +0x54 calculates to 0x00000044. The doubled context is 0xFFFFFFE0, and doubled context +0x54 calculates to 0x00000034.

### Crossing the signed boundary

Assume Context A is 0x7FFFFFF0. Its +0x11 address is 0x80000001, and its +0x40 address is 0x80000030. Both calculations are defined unsigned calculations; neither becomes uncertain merely because the result exceeds the largest signed 32-bit value.

This does not resolve analogous boundary behavior for signed Context B, Context C, or signed loaded bases.

### Disjoint, valid execution

Assume all relevant address ranges are valid and mutually non-overlapping except for the explicit within-region overlaps, signed calculations remain within range, the shift has defined behavior, and the transfer is reached.

Immediately before the dependency executes:

- Destination +0x54 contains Value.
- Context B +0x34 contains the doubled context.
- Context B +0x54 contains Context A, replacing the shift source.
- Context B +0x74 contains the link snapshot.
- Context C +0x54 contains the saved context word.
- First loaded base +0x54 contains the word value 100.
- Twice the second loaded base has received the halfword value 0x0065.

These observations are not guarantees after the dependency executes.

### Byte truncation and snapshots

If Context A has low byte 0xF0, the byte written at absolute address 0x3A is 0x10.

If the payload snapshot is 0x123456AB, both payload-derived byte writes use 0xAB, even if the memory at Value +0x74 changes after acquisition.

If an intervening aliased write changes absolute byte 0x67, a subsequent copy from that address uses its then-current value, not necessarily the originally published byte.

### Unresolved operations and partial completion

If Context A has low byte 0x40, this contract does not predict the shifted byte or prescribe count masking or an error.

If the word read at Value +0x74 faults, the publication region has already been reached and may have produced observable writes. Acceptance must not require rollback or invocation of F-unknown-01.
