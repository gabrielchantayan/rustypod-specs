# F-733d9a72d1aa

## Purpose

F-733d9a72d1aa searches an object-associated directory for the first record whose 32-bit identifier equals the requested identifier and whose final 32-bit field is nonzero. It returns that record’s address. If traversal exhausts the directory, it returns a null pointer.

A matching identifier with a zero final field does not qualify. Search continues, so a later duplicate identifier can be selected.

The established behavior is a bounded, ordered directory search with conditional calls to F-4457a9a44a68. Interpreting those calls as diagnostic reporting is inferred intent. The meanings of the identifier and final record field are not established.

## Interface

### Inputs

| Input | Representation in the supplied evidence | Role |
|---|---|---|
| Object address | 32-bit integer carrying an address | Supplies the directory metadata location. |
| Requested identifier | 32-bit integer | Compared with each candidate’s identifier; also supplies four byte-derived arguments for the optional entry call. |

The object address is used without a null check or validation. Relevant object storage is:

| Byte offset | Width in the represented layout | Meaning |
|---|---:|---|
| `0x98` | 16 bits, unsigned | Directory record count. |
| `0x9C` | 32-bit address slot | Directory base address. |

The records are contiguous, with a 16-byte stride:

| Record byte offset | Width | Use |
|---|---:|---|
| `0x00` | 32 bits | Identifier. |
| `0x04` | 32 bits | Not read by this function. |
| `0x08` | 32 bits | Not read by this function. |
| `0x0C` | 32 bits | Eligibility field: zero rejects, nonzero qualifies when the identifier matches. |

These sizes describe the represented target layout. They must not be replaced with native pointer widths or structure alignment from another platform. The original ABI is not independently established.

### Output and ownership

The result is either the address of the selected record’s first field or a null pointer.

The function does not return the final field’s value and does not dereference that value as an address. Selection requires only that its 32-bit value be nonzero.

The returned address aliases existing directory storage. The function does not copy a record, allocate replacement storage, extend its lifetime, or establish ownership transfer. Permission to release or modify that storage is not established.

A nonnull return does not itself guarantee that the selected storage remains live after the optional outcome call.

### Preconditions

For the ordinary lookup behavior described below:

- Both reads of the global diagnostic-state pointer must be possible.
- The address obtained by the second global-pointer read must support the entry threshold read at offset `0x48`.
- The address retained from the first global-pointer read must support the later outcome threshold read at offset `0x48`.
- The object must support the directory-base and count reads.
- The directory must support every identifier read reached by traversal and every final-field read required after an identifier match.
- Address arithmetic and ordering must be meaningful for the represented target.
- Any called dependency must return and leave the storage needed for subsequent operations accessible.

The function does not enforce these preconditions. In particular, normal null-result behavior is not an error-recovery guarantee for invalid storage.

## Behavior

### Two distinct global-pointer reads

Before accessing directory metadata, the function performs these accesses in order:

1. It reads the global diagnostic-state pointer and retains that address for the eventual outcome threshold check.
2. It reads the same global pointer again, obtaining the address used for the entry threshold check.
3. It reads a signed 32-bit threshold at byte offset `0x48` from the address obtained by the second read.

The two pointer values are not unconditionally identical. Equality requires the global pointer to remain unchanged between the reads. No synchronization or consistency check is visible.

The second pointer is used to decide whether entry reporting occurs. The first, retained pointer is used later to decide whether success or failure reporting occurs. The function does not obtain the outcome-check address by rereading the global pointer after the search.

Even if both pointer reads produce the same address, the entry and outcome decisions involve separate threshold reads at different times.

### Entry reporting

Entry reporting is enabled only when the signed threshold read through the second pointer is strictly greater than 3. A threshold of 3, zero, or any negative value disables that call.

When enabled, F-4457a9a44a68 receives six arguments:

1. A fixed entry-diagnostic address.
2. The object-address value.
3. An integer derived from identifier bits 31–24.
4. An integer derived from identifier bits 23–16.
5. An integer derived from identifier bits 15–8.
6. An integer derived from identifier bits 7–0.

The byte positions are supplied most-significant first. This ordering is derived from shifts and conversion of the identifier value, not from reading its in-memory bytes.

The first three byte-derived arguments use signed shift operations in the supplied representation. The middle two include left shifts before right shifts. The final argument uses conversion to a character type followed by promotion to an integer.

Under arithmetic signed-right-shift behavior, the first three arguments have sign-extended byte values. Under signed eight-bit-character behavior, the final argument does too. Thus a component containing `0x80` can be passed as −128, not 128.

These signed results are conditional on target semantics. The evidence does not justify replacing the arguments unconditionally with unsigned values from 0 through 255. Nor does it establish portable source-language behavior for every signed left shift shown in the representation.

Any return value from F-4457a9a44a68 is ignored.

### Directory acquisition

After the entry decision and any entry call that returns, the function reads:

1. The directory base address from object offset `0x9C`.
2. The unsigned 16-bit count from object offset `0x98`.

It then derives an exclusive end address by advancing the base by 16 bytes per record.

The metadata reads occur after the optional dependency call. Therefore, if that call changes the object’s directory base or count, the subsequent reads observe the resulting metadata, subject to ordinary access validity.

The count ranges from 0 through 65,535. The maximum byte span is 1,048,560 bytes. The count scaling fits within 32 bits, but adding the span to a base address may still exceed the address range or the bounds of valid storage. No overflow or bounds guard is visible.

The acquired base and derived end govern traversal. The object’s metadata is not reloaded for each record.

### Traversal and selection

Traversal begins at the acquired base address.

Before accessing each candidate, the function compares its address with the exclusive end. If the end is less than or equal to the candidate under the represented pointer ordering, traversal is exhausted.

Otherwise:

- The candidate’s 32-bit identifier at offset `0x00` is read.
- If it does not equal the requested identifier, the final field is not read.
- If it matches, the 32-bit field at offset `0x0C` is read.
- A nonzero final field selects the candidate immediately.
- A zero final field rejects the candidate.

After rejection, traversal advances by 16 bytes. The middle eight bytes of a record are not read by this function.

The earliest qualifying record wins. The function does not inspect later records after selection, enforce identifier uniqueness, or prefer one nonzero final value over another.

The eligibility condition is nonzero, not positivity. A final field with all bits set qualifies when the identifier matches.

### Exhaustion and successful selection

On exhaustion, the function reads the signed 32-bit threshold at offset `0x48` through the address retained from the **first** global-pointer read.

If that threshold exceeds 3, it calls F-4457a9a44a68 with one fixed failure-diagnostic address. If execution returns from that call, the function returns null. With reporting disabled, it returns null directly.

After successful selection, it reads the threshold through that same retained first address. If the threshold exceeds 3, it calls F-4457a9a44a68 with one fixed success-diagnostic address. It then returns the selected record’s address.

Neither outcome call receives the object address or identifier in the supplied representation. Any returned value is ignored.

Selection is not repeated after success reporting. The record’s identifier and final field are not rechecked, and the directory metadata is not reacquired.

### State identity and changing values

Three distinctions are observable:

- A change to the global pointer between its first and second reads can make entry and outcome checks use different state objects.
- A change to the global pointer after the second read does not redirect the retained outcome-check address.
- A change to the threshold within the retained state object can change the outcome decision.

Consequently, entry and outcome reporting need not occur together. This remains true even if both pointer reads initially produce the same address.

## Side effects

The function’s own explicit operations are memory reads, address calculations, comparisons, and optional dependency calls. No explicit memory writes, allocations, releases, or directory updates appear in the supplied body.

There are at most two explicit dependency calls:

- One optional entry call before directory acquisition.
- One optional outcome call after either selection or exhaustion.

The dependency’s effects are not bounded by the supplied evidence. It must not be assumed to preserve the global pointer, diagnostic-state objects, input object, directory contents, or storage lifetimes.

If the entry call invalidates metadata storage, later metadata reads are not protected. If an outcome call invalidates the retained diagnostic state after its threshold has been read, this function performs no subsequent threshold read on that path.

If the success call modifies or releases the selected record’s storage, the function still retains the previously selected address as its return value. Safe use of that address requires an external lifetime guarantee.

No explicit error result distinguishes invalid addresses, inaccessible memory, arithmetic problems, or dependency failure. Null is the established result of ordinary search exhaustion, not a universal failure result.

No locking, atomic snapshot, or retry mechanism is visible.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless stated otherwise, assume valid storage, nonwrapping addresses, normal dependency returns, and no relevant external mutation.

### Empty directory

With count zero, the base and derived end coincide. No record identifier or final field is read, and the result is null.

Both global-pointer reads, the entry threshold read, metadata reads, and the outcome threshold read still occur. A zero count does not establish that arbitrary invalid addresses are safe under all target pointer rules.

### Identifier mismatch

With one record whose identifier differs from the request, the function returns null. The record’s final field is not read, regardless of its stored value.

### Matching but ineligible record

With one matching record whose final field is zero, the function returns null. Identifier equality alone is insufficient.

### Later eligible duplicate

Given three records in order:

- A nonmatching identifier.
- A matching identifier with final field zero.
- A matching identifier with final field nonzero.

The result is the third record’s address, 32 bytes beyond the base.

### First qualifying duplicate

With two matching records whose final fields are nonzero, the first record is returned. The second record is not examined.

### Signedness of eligibility

A matching record with final-field bit pattern `0xFFFFFFFF` qualifies. No positive-value requirement applies.

### Stable threshold boundary

If both global-pointer reads yield the same state address and its threshold remains 3, neither call occurs.

If both reads yield the same address and its threshold remains 4, entry reporting and the applicable outcome reporting occur. Lookup selection is unchanged only if the dependency has no relevant effects.

### Different addresses from the two global reads

Suppose the first global-pointer read returns one state address, then the global slot changes before the second read. The second read returns a different state address.

If the first state’s outcome threshold is 4 and the second state’s entry threshold is 3, there is no entry call, but there is an outcome call.

If those threshold values are reversed, there is an entry call but no outcome call, provided the first state’s threshold remains 3. These cases do not require the two pointers to identify the same object.

### Entry-call mutation

If the entry call changes the directory base or count, the search uses the metadata read after that call.

If it changes only the global diagnostic-state pointer, the outcome threshold still uses the first pointer retained before the call. If it changes the threshold in the retained state object, that changed threshold can affect outcome reporting.

### Diagnostic byte values

For an identifier whose most-significant-first bytes are `80 FF 7F 00`, arithmetic signed-right-shift behavior and signed eight-bit-character behavior yield arguments −128, −1, 127, and 0.

This is conditional on those target semantics. Record selection still compares the entire 32-bit identifier.

### Mutation after selection

If the success call changes the selected record’s final field to zero, the function returns the already selected address without rechecking it.

If that call releases the storage, the returned address is not thereby made safe to dereference.
