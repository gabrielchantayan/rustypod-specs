# F-c1d3336af135

## Purpose

The supplied static representation establishes a memory-mutating operation followed by an unresolved indirect invocation. It does not establish an application-level purpose.

Observable effects include partial-width writes, address-derived payloads, repeated external-memory reads, carry-dependent address calculations, linked-memory mutations, and a terminal transfer. Interpreting the operation as a conventional initializer, list operation, serializer, or text operation would add unsupported meaning.

This is a **partial behavioral contract**:

- The opening operations, computed-address region, identifiable external reads, and terminal suffix are specified below.
- The intervening linked-memory region has documented landmarks but is **documented_only at event-complete granularity**. Its full address-dependency and access-order contract is not supplied here.
- That coverage limitation is distinct from uncertainty about executable semantics. The supplied representation contains additional identifiable operations in that interval; they must not be treated as absent or unconstrained implementation choices.

All acceptance examples are conditional static obligations. No runtime tests have been performed.

## Behavior

### Ordering and arithmetic rules

The displayed flow is predominantly straight-line. Comparisons produce arithmetic bits; they are not general validation branches. The explicit logical-OR carry expressions do have short-circuit evaluation.

Earlier stores can affect subsequent loads through aliasing, including loads from named external locations. Consequently:

- Repeated external reads cannot be replaced with one stable capture.
- A saved value is not interchangeable with a later load.
- Partial-width and repeated writes are separate observable events.
- Apparently unchanged write-backs cannot automatically be removed.

Unsigned 32-bit arithmetic retains its low 32 bits; explicit carry calculations detect overflow at the 32-bit boundary. Comparisons used arithmetically contribute zero or one.

Some recovered expressions instead involve signed integers, pointer-like arithmetic, or code-associated addresses. Their executable overflow and address semantics remain unresolved. The mathematical address descriptions below do not establish permission to replace those expressions with arbitrary wider arithmetic.

The operation then:

1. Captures Root’s unsigned byte at `0x05`.
2. Reads Root’s word at `0x50` and copies it to `0x20`.
3. Obtains Link A and then Link B.
4. Reads Root’s byte at `0x05` again and copies that second reading to `0x11`.

An unsigned byte read from Link A plus `0x05` supplies a new numerical base between zero and 255. In order, the following effects occur:

### Repeated external reads and carry-dependent destinations

The following order is established:

1. Capture the word at `0x087fc710`.
2. Read `0x087fc710` again and store the retained `0x087fc5e4` low halfword at that fresh value plus `0x54`.
3. Capture `0x087fc6f8`.
4. Capture `0x087fc6e8`.

The halfword store can alias any external storage. Its address uses the second `0x087fc710` reading, while the arithmetic below uses the first.

Let **doubling carry** be the carry from doubling the first `0x087fc710` capture and adding the bit for Arithmetic operand being no greater than second derived address. The representation forms this as a short-circuit OR of two carry conditions.

Let **doubled external** be the corresponding low-32-bit sum.

Code-associated storage at `0x087fc6e4` is then read separately for these purposes:

- One reading, plus doubling carry, supplies a retained address component.
- A subsequent reading is compared unsigned with `0xffffffa6`.
- Only if that comparison is false is another reading used in the carry test for adding `0x59` and doubling carry.

Thus the comparison and conditional carry calculation need not use equal values. Short-circuiting also determines whether the last read occurs.

The resulting carry bit is added to retained `0x087fc5e4` plus doubled external to form another derived value. A **fresh** read of `0x087fc6f8` then determines the comparison bit for Arithmetic operand being no greater than that fresh value. This comparison does not use the earlier capture.

In order, the operation:

- Stores the new derived value’s low halfword at second derived address plus that value.
- Adds Arithmetic operand to the derived value and performs another corresponding halfword store.
- Stores the earlier `0x087fc6f8` capture’s low halfword at twice doubled external.
- Stores byte `0x45` at the retained `0x087fc6e4`-derived component plus `0x9e`.
- Captures code-associated words at `0x087fc73c` and then `0x087fc688`.

## Side effects

The operation mutates externally reachable memory at byte, halfword, and word widths. Some word destinations, including offset `0x45`, may be unaligned.

There is no explicit allocation, release, I/O operation, synchronization, validation result, rollback, or status return in the displayed body. This does not constrain Target’s behavior.

Ownership, retention, release, and global preservation are unknown. Pointer-like stores do not establish ownership transfer. The indirect target must not be assumed to preserve globals or leave referenced storage alive.

Successful completion requires each reached access to be valid at its actual width and access mode. A fault may occur after earlier writes. No recovery or transactional guarantee is represented.

## Acceptance examples

These examples assume the stated accesses are reached and valid. They are not runtime observations.

### Partial overwrite

If the opening halfword payload is `0xabcd` and the fourth argument’s low byte is `0xef`, the halfword store precedes the byte overwrite at the same starting address.

With ordinary storage and no intervening aliasing:

- Little-endian final halfword: `0xabef`.
- Big-endian final halfword: `0xefcd`.

Both writes remain part of the represented access order.

### Distinct external captures

If the first `0x087fc710` reading is `0x1000` and the second is `0x2000`, the halfword destination is `0x2054`, while the later doubling calculation uses `0x1000`.

Using one capture for both obligations changes the specified dependencies.

### Short-circuit external read

If the comparison reading from `0x087fc6e4` exceeds `0xffffffa6`, the carry expression’s following read of that location is skipped. The earlier reading used for the retained address component still occurs.

If the comparison is false, the conditional carry calculation performs another read; equality with either earlier reading is not guaranteed.

### Carry boundary

For a captured doubling operand of `0x80000000` and an added comparison bit of zero, the low-32-bit doubled result is zero and doubling carry is one. Wider arithmetic must not lose that 32-bit carry distinction.

### Final repeated halfword destination

If Final link is `0x1200` and Primary record is `0x3000`, the terminal sequence writes halfword `0x1200` at `0x4200`, performs the intervening operations, then writes that halfword at `0x4200` again.

An implementation retaining only the second write does not preserve the represented event order.

### Signed final byte and captured invocation argument

A final source byte of `0x80` represents −128, converts to `0xffffff80`, and yields first invocation argument `0xffffffc4`.

This does not guarantee execution reaches Target: the intervening stores through Final byte base must succeed.

If a final store aliases Primary record plus `0x44`, the third invocation argument nevertheless remains the value captured before that store.
