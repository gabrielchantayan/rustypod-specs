# F-603151340958

Its visible operations include capturing arguments, obtaining a word-sized result from F-5e11a17b9827, using that result as a record address, invoking F-e785903f1f3b with ten arguments, and publishing a transformed integer result.

**Established static evidence:** the dispatch alternatives, argument transformations, record offsets, dependency argument positions, and return mechanism are visible.

**Inferred intent:** the wrapper appears intended to perform a lookup, forward selected record fields and caller arguments to another operation, and encode that operation’s result.

**Unknown:** the actual entry route, successful route, failure route, constants, and dependency semantics. No runtime tests have been performed.

## Behavior

### Dispatch and retained state

Before dispatch begins, the function initializes its saved return value, working integer values, retained opaque arguments, and lookup-result slot to zero. It reads the entry selector to establish the initial selector.

Each dispatch iteration visibly reads Factor Y and then Factor X into per-iteration snapshots before choosing an alternative. Selection uses the current selector plus the dispatch bias. These factor reads occur even on an iteration that immediately returns.

The recognized keys are 0 through 7. Any other key returns the current saved return value.

The selector and the saved return value are separate. Changing the selector does not itself change the eventual return value.

### Argument capture: key 5

This alternative captures all eight caller arguments:

- The working lookup input becomes Factor Y multiplied by A1.
- The retained input derived from A3 becomes Factor Y multiplied by A3.
- A7 is retained unchanged.
- A2, A4, A5, A6, and A8 are retained as opaque words in their respective forwarding positions.
- The selector becomes the capture successor.

Factor Y is visibly referenced for each of the two multiplications. These references are separate from the per-iteration snapshot.

This alternative does not reset the saved return value, lookup-result slot, or candidate result. If dispatch revisits key 5, it refreshes the captured arguments but does not restore all state to its entry condition.

### Lookup: key 0

The working lookup input is multiplied by the lookup multiplier. The function then calls F-5e11a17b9827 with:

1. The scaled working lookup input.
2. The lookup auxiliary word.

The returned integer replaces the lookup-result slot. Zero and nonzero results select different successor expressions.

If the lookup route base remains stable during expression evaluation and arithmetic is representable:

- A nonzero result installs the lookup route base as the selector.
- A zero result installs the lookup route base plus five.

The dispatch bias is added only when the next dispatch alternative is selected. Thus, neither selector value directly identifies a key without the bias.

The lookup route base is read after the dependency returns. A dependency-side update to that cell can affect the next route. The visible expression contains multiple references to that cell; the evidence does not establish a synchronization or concurrent-update model.

A nonzero lookup result is not independently checked for alignment, bounds, accessibility, or record type.
