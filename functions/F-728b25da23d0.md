# F-728b25da23d0

## Purpose

F-728b25da23d0 coordinates indirect submissions and repeated processing against a caller-supplied context. It prepares a context-referenced buffer through a copy-like dependency, submits that buffer, then selects either general processing or a special path.

The established contract consists of field accesses, call arguments, arithmetic, branching, and explicit return values. Descriptions such as “submission,” “copy,” and “clear” identify apparent roles; the supplied evidence does not establish the corresponding dependencies’ full semantics.

The general path can return `1` or `0`. The special path has only explicit normal returns of `0` and can call a dependency marked non-returning. Neither path implements rollback.

## Behavior

### Initial query and cached position

First, the function resolves and invokes interface dispatch entry `0x2c`. The representation supplies no explicit arguments to this call, including no explicit interface-object argument.

The 32-bit result is cached as the **query value** for the remainder of the invocation. The function then reads the initial position from `0x41c` and starts an initial-phase counter at zero.

### Header preparation and route selection

Every initial-loop test freshly reads mode `0x42c`. Mode `32` selects a limit of two; every other value selects a limit of one. A signed comparison determines whether the counter has reached that limit.

If the limit has been reached, execution enters general processing. Otherwise:

1. The copy-like dependency receives the current header-buffer value plus `0x5a`, an evaluation of source expression A, and length `0x1a4`.
2. Dispatch entry `0x08` is resolved and invoked with five explicit arguments: the current interface object, the cached submission position, a fresh header-buffer value, `1`, and `0`.
3. A nonzero submission result returns `0` immediately.
4. Following a zero result, mode `0x42c` is reread.

If this latter mode read equals `32`, the special path begins immediately. Otherwise, the counter and cached submission position each increase by one, and the loop repeats.

Thus header preparation and submission need not use the same header-buffer value: the copy-like dependency can change `0x450` before submission arguments are evaluated.

With stable non-`32` mode, exactly one header submission precedes general processing. With stable mode `32`, exactly one precedes the special path. Mode changes can permit a second header submission, but the loop does not require two submissions merely because a loop test observes `32`.

### Special path

This path retains the initial phase’s cached submission position and query value.

First, dispatch entry `0x08` receives the current interface object, cached position plus one, the current `0x454` value, `1`, and `0`. A nonzero result returns `0`.

After a zero result:

1. F-fab3799b3190 receives the query value.
2. A zero result returns `0`.
3. For a nonzero result, that result is cached and passed to the clear-like dependency together with the query value.
4. The copy-like dependency receives the cached result, an evaluation of source expression B, and length `512`.
5. After that call returns, dispatch entry `0x08` is resolved again. Its arguments are the current interface object, cached position plus two, a **new evaluation of source expression B**, `1`, and `0`.

The two evaluations of source expression B are distinct. The copy-like dependency may mutate global state; the evidence does not establish equal values or equal addresses across these evaluations. The final submission does not explicitly use the cached F-fab3799b3190 result as its buffer argument. Accidental equality is neither required nor excluded.

If the final submission returns zero, F-feee9156a257 receives the cached F-fab3799b3190 result. The supplied representation marks this call non-returning.

If the final submission returns nonzero, the function returns `0` without that call. No successful normal return of `1` is established for this path.

### General-path setup

F-870c4fcf7295 then receives the current `0x440` value and the cached query value. Its result is added to the product of fresh `0x428` and `0x430` values, producing a cached **destination-like value**.

The outer counter is set to zero, and the four-byte state cell is initialized to zero.

1. The context address.
2. The current general starting position.

4. Decimal `32`.

6. The cached destination-like value.

- F-3bab1f05f325 receives the context, next-chunk position, a fresh `0x458` value, the chunk argument, the shared state-cell address, and the cached destination-like value.

## Side effects

No direct context-field assignment appears in the function body. Its direct local writes concern counters, positions, cached values, and state-cell initialization. Dependencies receive addresses through which they may modify context, automatic storage, referenced buffers, globals, or interface state.

Observable dependency order is significant:

- The initial query precedes initial position capture.
- Header preparation precedes header submission.
- Special-path clearing precedes copying; copying precedes the second evaluation of source expression B used for final submission.
- General-path save and clear calls follow the first successful group call.
- Restoration follows all successful remaining-chunk calls.

Failure does not undo earlier effects. A remaining-chunk failure skips restoration. A failed later submission does not undo earlier submissions. Several special-path exits following a nonzero F-fab3799b3190 result do not call F-feee9156a257.

These facts do not establish a memory leak, an allocation protocol, or successful preservation of a buffer. Such conclusions require dependency semantics.

Safe execution requires valid directly dereferenced context fields, interface objects, dispatch tables, and header-field storage. If the primitives implement ordinary byte copying and clearing, their supplied addresses require adequate readable or writable spans. The general clear-size argument is the 32-bit query value shifted left by five, not necessarily `512`. The special-path clear argument is the unshifted query value.
