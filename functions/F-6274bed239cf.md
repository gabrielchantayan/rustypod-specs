# F-6274bed239cf

## Purpose

The supplied static representation describes a routine that interleaves indirect calls with byte-sized and 32-bit memory updates. Its visible operations include scaling returned values, extracting bit fields, writing through computed addresses, clearing selected locations, and repeatedly clearing the 32-bit location at address `0x24`.

A higher-level purpose—such as initialization, serialization, device control, or object construction—is not established. The repeated field-like offsets do not establish an object layout.

This contract describes the visible execution prefix. The representation ends at an invalid-instruction boundary, not a demonstrated normal return. It also carries warnings about unreliable control-flow recovery and overlapping global symbols. Consequently, the behavior below is conditional on the represented operations accurately reflecting executable behavior.

No runtime tests have been performed.

### Width and address conventions

For the behavioral ledger:

- A **word** is 32 bits.
- A **byte** is 8 bits.
- `word[address]` and `byte[address]` denote accesses of those widths.
- `low8(value)` denotes the least significant eight bits.
- Logical right shifts apply to explicitly unsigned values.
- Scaled addresses and left shifts are described using their low 32-bit result.

The last convention is a machine-oriented interpretation, not proof that signed arithmetic in the recovered representation has portable language semantics. Several intermediate expressions are represented as signed integers. Overflow, pointer validity, alignment, and actual target-machine behavior remain qualification points.

Endianness is not established. Where byte and word accesses overlap, they cannot be modeled as independent fields.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Unsigned input shift.** If the initial destination is writable and Argument 4 is `0xffffffff`, the first direct word write carries `0x1fffffff`.

2. **Byte truncation.** If first seed is `0x12345678`, the first seed-derived byte write carries `0xe0`. Its later masked-high-field byte write carries `0x23`, possibly to a different destination because the selector is re-read.

3. **Selector changes across calls.** If the initial ambient selector is 7 and the later read produces 9, the first byte destination is `0x18`; the later destination is `0x1a`. The subsequent saved-selector word destination is `0x38`.

4. **Different scaling means different locations.** If seventh index is 2, row 10 writes at `0x34`, while row 11 reads at `0x1c`. Acceptance must not assume the read retrieves the preceding write.

5. **Mask width matters.** If layout seed is `0xffffffff`, layout quotient is `0x1fffffff`; masked quotient is `0x003fffff`. The later quotient-derived word value is `0x1fffff80`.

6. **Potentially unaligned reset.** If reset selector is 1, row 18 attempts a 32-bit write at `0x45`, followed by the write at `0x24`. Whether the first access succeeds is platform-dependent.

7. **No final-zero invariant.** An intervening callee may change `word[0x24]`. The contract requires the four explicit zero-write events, not continuous zero state or a guaranteed zero value at the truncation boundary.
