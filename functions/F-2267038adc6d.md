# F-2267038adc6d

## Purpose

F-2267038adc6d conditionally initializes a context-associated table, obtains a 32-bit value from a dependency, and either extends the last active table entry or appends a new entry followed by a zero terminator.

The table behaves like a sequence of two-word records. The first word participates in an adjacency comparison with the third argument; the second word is both the value extended during a merge and the marker used to find the end of the sequence.

**Inferred intent:** the records describe ranges, with a starting position and an extent, and adjacent ranges are coalesced. This interpretation explains the arithmetic but is not required to describe the observed behavior. In particular, the supplied evidence does not establish that extents are positive, that starts are ordered, or that the dependency’s result is a length.

The function returns no explicit result or status. Initialization failure and a null return from the storage dependency cause distinct early-exit behaviors, without an error value being returned to the caller.

## Interface

### Arguments

The function receives four arguments, in order:

1. **Dependency context:** a four-byte opaque value passed to the initialization and value-producing dependencies. The function does not otherwise interpret it.
2. **Mutable context address:** an address through which the function reads a pointer chain and accesses a table-address field.
3. **Position:** a 32-bit integer passed to the value-producing dependency, compared with the sum of the final record’s two words, and stored as the first word of a newly appended record.
4. **Auxiliary value:** a four-byte opaque value. It is copied into temporary storage; both the address of that copy and the original value are supplied to the value-producing dependency.

The supplied representation uses four-byte integer words and four-byte pointer-bearing fields. These are the widths governing this contract. Broader portability to a different pointer width is not established.

### Context layout accessed by this function

Offsets below are byte offsets:

| Location | Interpretation and use |
|---|---|
| Mutable context + 0 | Address of a first related object |
| First related object + 4 | Address of a second related object |
| Second related object + 28 | A 32-bit initialization-control word |
| Mutable context + 32 | A four-byte table-address field, read and conditionally overwritten |

The control word is tested for zero versus nonzero. Its remaining meaning is unknown.

The pointer chain leading to the control word is traversed before the table-address field is considered for initialization. A nonzero table address does not bypass that traversal.

### Table layout

Each record occupies eight bytes:

| Record-relative offset | Meaning established by use |
|---|---|
| +0 | First 32-bit word: stored position and adjacency operand |
| +4 | Second 32-bit word: value to accumulate and end-of-sequence marker |

An active sequence ends at the first record whose second word is zero. The first word of that record is irrelevant to termination.

A newly written terminator has both words set to zero. Existing terminators are not required by this function to have a zero first word.

### Preconditions

For defined successful operation:

- The mutable context and the full pointer chain to the control word must be readable.
- The table-address field must be readable and writable when the selected path accesses or updates it.
- The table ultimately selected after value production must support sequential reads of record second words through a terminating zero.
- A merge requires the last active record’s words to be readable and its second word writable.
- An append requires the storage dependency’s nonzero result to identify writable storage for the requested number of bytes.
- Record indexing, requested-size arithmetic, and the relevant integer additions must be valid in the execution model.

There are no explicit checks for these conditions. Invalid pointers, missing terminators, or arithmetic outside the supported domain are not converted into reported errors.

## Behavior

### 1. Inspect initialization state

The function first follows the context’s pointer chain and reads the initialization-control word.

If that word is zero, it skips the initialization dependency. The table-address field is not tested as part of this condition.

If the control word is nonzero, the function reads the table-address field:

- If the field is nonzero, initialization is skipped.
- If the field is zero, F-56c9e29af49d is called with the dependency context.

The initialization dependency’s returned 32-bit value is written to the table-address field, including when that result is zero.

If this returned value is zero, the function returns immediately. It does not call the value-producing or storage dependency, and it does not scan or modify table records on this path.

A zero control word does **not** make a null table address safe. It only suppresses initialization.

### 2. Obtain the value to incorporate

Unless initialization returned zero, the function calls F-1fbd80476b73 with:

1. The dependency context.
2. The supplied position.
3. The address of the temporary four-byte copy of the auxiliary value.
4. The original auxiliary value.

The temporary initially contains the same four-byte value as the fourth argument. The dependency can access that temporary through the supplied address. The enclosing function does not subsequently use its contents.

The returned 32-bit integer becomes the value to merge or append. The function does not reject zero or negative results.

Only after this call does the function read the context’s table-address field for the table scan. Consequently, the table being scanned is the one selected by that field after value production. It is not necessarily the table present before the dependency call.

No assumption is made that the dependency preserves context fields, table contents, globals, or other reachable state.

### 3. Find the first terminating record

Beginning at record index zero, the function reads the second word of each successive eight-byte record.

- A nonzero second word advances the scan by one record.
- A zero second word ends the scan.

The resulting count is the number of active records preceding the first terminator.

There is no separate capacity field, length argument, or scan bound in the supplied evidence. The scan does not inspect record first words to decide whether to continue.

### 4. Attempt to extend the final active record

If the active-record count is positive, the function reads the two words of the last active record and adds them. It compares that sum with the supplied position.

If they compare equal:

- The last active record’s second word is increased by the value returned from F-1fbd80476b73.
- The function returns immediately.

On this path, the function does not call F-dbea69bb52a6, append a record, rewrite the terminator, or explicitly update the table-address field.

The function examines only the last active record for this merge. An earlier matching record does not affect the decision.

No positivity condition is imposed on either addend or on the returned value. A merge may therefore leave the second word unchanged, decrease it, or make it zero, where the arithmetic is defined. Making it zero changes where subsequent scans will terminate.

### 5. Request storage and append

The append path is taken when:

- The active sequence is empty; or
- The final active record’s word sum does not equal the supplied position.

F-dbea69bb52a6 receives:

1. The table address used for the scan.
2. A requested byte count of eight times the active-record count plus two records.

Equivalently, for an active-record count of \(n\), the requested size is \(8(n+2)\) bytes. This allows for the existing active records, one new record, and one terminator. It does not establish whether the dependency allocates, resizes, copies, or releases anything.

The returned address is written to the context’s table-address field **before** it is tested for zero.

If the returned address is zero, the function returns without writing new record contents. It does not restore the previous table address. Whether the old storage remains allocated or otherwise recoverable depends on the dependency.

If the returned address is nonzero, the function performs these four 32-bit writes in order:

1. At record index \(n\), write the supplied position into the first word.
2. At record index \(n\), write the produced value into the second word.
3. At record index \(n+1\), write zero into the first word.
4. At record index \(n+1\), write zero into the second word.

The function then returns.

There is no explicit copying of existing records in this function. Any preservation of earlier entries across the storage call must come from F-dbea69bb52a6.

## Side effects

### Direct state changes

The function may:

- Overwrite the context’s table-address field with an initialization result.
- Overwrite that field with a storage result, including zero.
- Update the second word of the final active record.
- Write a new two-word record and a following two-word zero terminator.

The function does not directly write the initialization-control word or either pointer in the chain leading to it.

### Observable ordering

The material ordering established by the supplied evidence is:

1. Read the pointer chain and initialization-control word.
2. If required, read the table-address field, call initialization, and store its result.
3. Unless initialization returned zero, call the value-producing dependency.
4. Read the table-address field used for scanning.
5. Scan second words through the first zero.
6. If nonempty, perform the final-record adjacency test.
7. Either update the final record and return, or call the storage dependency.
8. Store the storage result into the context.
9. If nonzero, write the new record and terminator in the order listed above.

This describes the supplied operation sequence, not a synchronization guarantee. Thread safety, reentrant mutation, and hardware-level memory ordering are not established.

### Ownership and lifetime

The table-address field is treated as mutable state, not as an immutable borrowed pointer.

The storage call receives the current table address, but the evidence does not establish an ownership transfer. In particular:

- A zero storage result overwrites the context field, but does not prove that previous storage was freed.
- A nonzero result does not prove that the original allocation survived.
- Preservation of earlier records cannot be assumed without the dependency’s contract.

The auxiliary-value copy is temporary storage. No lifetime beyond this invocation is established for the address passed to F-1fbd80476b73.

### Errors and unchecked cases

There is no explicit status result, exception mechanism, diagnostic, or recovery path shown.

Initialization returning zero stops processing before value production. Storage returning zero stops processing after value production and scanning, and after the table-address field has been set to zero.

A null table address reaching the scan is not handled as an empty table.

## Acceptance examples

These are conditional behavioral examples, not runtime test results. Unless stated otherwise, addresses are valid, arithmetic is representable, dependencies return normally, and no dependency changes relevant state beyond the effects specified in the example.

### Initialization failure

Given a nonzero control word and a zero table-address field, if F-56c9e29af49d returns zero:

- The field is written with zero.
- Neither other dependency is called.
- No table scan occurs.

### Initialization skipped despite a null table field

Given a zero control word and a zero table-address field:

- F-56c9e29af49d is not called.
- F-1fbd80476b73 is called.
- If the table field remains zero afterward, the function attempts to scan using that address.

This is not a successful empty-table case.

### Adjacent final record

Given active records whose final record is \((100,20)\), a position of 120, and a produced value of 7:

- The final record becomes \((100,27)\).
- The storage dependency is not called.
- The existing terminator is not rewritten.

### Only the final record is considered

Given active records \((10,5)\) and \((100,20)\), a position of 15, and a produced value of 3:

- The earlier record’s adjacency does not trigger a merge.
- The final record does not match.
- Storage is requested for four records: 32 bytes.
- On a suitable nonzero storage result, \((15,3)\) is written at index two and \((0,0)\) at index three.

### Empty sequence

Given a table whose first record has a zero second word, a position of 40, and a produced value of 6:

- The active count is zero, regardless of the first record’s first word.
- Storage is requested for 16 bytes.
- On success, the first two records become \((40,6)\) and \((0,0)\).

### Zero produced value on append

Given an append decision, a position of 40, and a produced value of zero, successful storage results in a new record \((40,0)\), followed by \((0,0)\).

The newly written record itself satisfies the scan’s termination condition. The function does not force it to become an active record.

### Merge creates a terminator

Given a final active record \((100,20)\), a position of 120, and a produced value of −20, the merge writes zero to that record’s second word.

A later scan under the same layout will stop at that record. No explicit record removal or terminator normalization occurs during the merge.

### Storage failure

Given an append decision, if F-dbea69bb52a6 returns zero:

- The context’s table-address field becomes zero.
- No new record or terminator is written by this function.
- Earlier dependency effects remain unreversed.
- The fate of the previous table storage remains dependency-defined.
