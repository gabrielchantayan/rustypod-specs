## Acceptance examples

These are conditional contract examples, not runtime observations.

1. **Second-input truncation.** If the second input is 15, F-000001 receives 1 as its fourth argument. If it is 16, that argument is 2. Inputs from zero through seven all produce zero.

2. **Independent result halves.** If F-000002 returns a 64-bit value whose high half is 24 and low half is 5, F-000003 receives 5, 24, 5, and 3, in that order.

3. **Word-store ordering.** If F-000007 returns 3, the routine writes the first input at address 32 before invoking F-000008 with 12. This example requires address 32 to permit a 32-bit write.

4. **Changed ambient selector.** Suppose F-000012 returns 0x0AB00015. The first derived byte is 0x54 and the second is 0xAB. If the ambient selector is initially 2, the first byte goes to address 19. If an intervening dependency changes that selector to 9, the second byte goes to address 26, not address 19.

5. **Repeated calculated selector.** Under 32-bit arithmetic, an F-000012 result of 1 yields a scaled value of 4 and a calculated selector-read address of 4,097. If the selector reads return 7 and then 8, the two zero writes target addresses 24 and 25 respectively.

6. **Upper-bound unsigned shift.** A second input of 0xFFFFFFFF produces a fourth argument of 0x1FFFFFFF for F-000001. The shift is logical, not sign-extending.

7. **Early interruption.** If F-000015 does not return, neither the second ambient-selector byte write nor F-000016 is reached through the visible sequence. Earlier effects are not undone.
