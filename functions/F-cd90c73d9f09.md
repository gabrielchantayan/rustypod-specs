# F-cd90c73d9f09

## Purpose

F-cd90c73d9f09 produces an opaque 32-bit result through one of two paths selected by a 32-bit field in a caller-supplied object.

The zero-selector path derives its result from a temporary two-word argument area. Every nonzero-selector path selects an opaque value, obtains another value from a dependency, and supplies both to a result-producing dependency.

Both paths share an initial call and a final call operating on the temporary argument area. Their names, resource semantics, and intended lifecycle are not established. Calling them “initialization” and “cleanup” would be an interpretation, not a demonstrated ownership contract.

This specification describes the supplied static representation. It does not establish the behavior of the dependencies, the meaning of the opaque global values, or runtime validity of any input.

## Interface

### Inputs

The function accepts four argument positions:

| Position | Represented input | Established use |
|---|---|---|
| First | An address-bearing value represented as a 32-bit integer | Used to locate a 32-bit selector at byte offset 108 (`0x6c`). |
| Second | An opaque 32-bit word | No explicit use in the function body. |
| Third | An opaque 32-bit word | Copied into the first word of a temporary argument area. |
| Fourth | An opaque 32-bit word | Copied into the second word of that area. |

The second argument is not forwarded by any explicit call. Its presence does not imply that it affects the result. Conversely, this observation does not establish anything about external calling-convention machinery outside the supplied body.

The third and fourth inputs are treated as raw words. The function does not itself interpret them as pointers, lengths, flags, signed quantities, or resource handles.

### Temporary layout

The supplied representation places the temporary words at adjacent four-byte positions:

| Offset from temporary-area address | Initial contents |
|---|---|
| 0 | Third input, 32 bits |
| 4 | Fourth input, 32 bits |

The function passes the address of the first word to dependencies. The initial transfer is a word copy; it is not evidence of copying any object that an input might reference.

The representation supports an eight-byte, two-word argument area. It does not establish byte order, a stronger alignment guarantee, or a larger valid storage extent. Dependencies’ permitted accesses beyond these two words are unknown.

### Output

The normal return is an opaque 32-bit word:

- For selector zero, it is the result of F-44362605ab79.
- For a nonzero selector, it is the result of F-5710a8628cba.

No success indicator, error encoding, pointer interpretation, or ownership transfer is established for this word.

### Preconditions and validity limits

For a defined execution of the explicit object access, the first argument must allow a valid four-byte read beginning at byte offset 108 when that read occurs. Importantly, that read occurs **after** the initial dependency call, not at function entry.

The body contains no null check, bounds check, object-type check, or address-overflow check. The supplied material does not specify what happens if the first argument is invalid or if adding the offset does not yield a valid address.

The dependencies may impose additional preconditions on the temporary words and other arguments. Those preconditions are documented_only unknowns.

## Behavior

### 1. Prepare and expose the temporary words

The function copies the third and fourth inputs into the two temporary word positions. It then calls F-5b24edfb22c0 with the temporary-area address.

No result from this call is used explicitly.

Because the dependency receives an address, later users of the area must be understood as receiving its post-call contents, not necessarily the original input words. Whether F-5b24edfb22c0 changes either word is unknown.

The selector is not read until this call returns normally. Consequently, branch selection is based on the object state at that later point. The contract does not assume that the dependency preserves the object or any global state.

### 2. Read the selector once

The function reads a 32-bit selector from the first input’s address plus 108 bytes. This is the only explicit read of that selector in the body.

Branching uses this captured value. A later change to the object field does not cause the function to reselect a path.

The representation presents the selector as an integer. Its observed uses are equality comparisons against zero, two, three, and four. Thus, the distinction between signed and unsigned ordering does not affect the listed cases. There is no range check.

### 3. Handle selector zero

If the captured selector is zero, the function calls F-44362605ab79 with the temporary-area address and retains its 32-bit result.

This path does not explicitly call F-9d0ecc5f6adf or F-5710a8628cba. It also does not explicitly read the nonzero-path selection globals or the common global argument described below.

F-44362605ab79 can observe the temporary area after F-5b24edfb22c0 has returned. Whether it reads, modifies, retains, or interprets that area is outside the supplied evidence.

### 4. Handle every nonzero selector

For a nonzero selector, the function selects a 32-bit value from one of four distinct global slots:

| Captured selector | Selected global slot |
|---|---|
| 2 | Selector-two slot |
| 3 | Selector-three slot |
| 4 | Selector-four slot |
| Any other nonzero value | Default-nonzero slot |

“Any other nonzero value” includes 1, values above 4, and negative values under a signed interpretation. Such values are not rejected.

The slots are distinct storage locations; their stored values need not be distinct.

The selection logic has an observable read order beyond the final mapping:

1. The selector-two slot is read for every nonzero selector.
2. If the selector is not 2, the selector-three slot is then read.
3. If the selector is neither 2 nor 3, the default-nonzero slot is then read.
4. If the selector is 4, the selector-four slot is then read and supplies the final selected value.

Thus, selector 4 causes reads of all four selection slots in that order. An ordinary fallback selector causes reads of the selector-two, selector-three, and default-nonzero slots. Earlier values can be overwritten locally before any dependency receives the final selected word.

After selecting and retaining that word, the function calls F-9d0ecc5f6adf without explicit arguments and retains its 32-bit result.

It then calls F-5710a8628cba with three arguments, in these positions:

1. The result from F-9d0ecc5f6adf.
2. The 32-bit value obtained from a separate common global slot.
3. The retained selected word.

The common global read belongs to the preparation of this latter call, after F-9d0ecc5f6adf returns. Therefore, the contract does not substitute a common-global value captured before that dependency call.

In contrast, the selected word has already been captured. A change by F-9d0ecc5f6adf to a selection slot does not, by itself, cause that word to be reloaded.

The result of F-5710a8628cba becomes the retained function result.

### 5. Make the final temporary-area call and return

After either result-producing path returns normally, the function calls F-289ec4311c64 with the temporary-area address.

The retained result is returned only after that call returns normally. The final dependency’s return value is not used explicitly.

There is no explicit error-dependent branch that skips this final call after a result-producing dependency returns a particular word. A zero result or an apparent error-shaped result follows the same local sequence as any other word.

This establishes normal control flow only. It does not establish that the final call runs after a dependency faults, terminates execution, performs a nonlocal transfer, or fails to return.

## Side effects

### Explicit effects

The function itself:

- Writes the two input words into temporary storage.
- Reads the object’s selector once, after the initial dependency call.
- On the nonzero path, reads selection globals in the conditional order above.
- On the nonzero path, reads the common global after F-9d0ecc5f6adf returns.
- Calls dependencies in the path-specific order described above.

There is no explicit write to the caller’s object or to the global slots in the supplied body.

### Dependency-mediated effects

The absence of direct writes does not imply that the function is externally read-only. Dependencies may mutate memory or global state, acquire or release resources, or perform other observable actions. Their implementations are not supplied.

In particular:

- The first and final dependencies receive an address into temporary storage.
- The zero-selector result dependency receives that same address.
- The nonzero result dependency receives three opaque words whose pointer or handle interpretations are unknown.

The wrapper makes no explicit heap allocation or deallocation. This does not establish that its dependencies allocate nothing or release nothing.

### Lifetime and ownership

The temporary area is local to this invocation. The body provides no persistent copy of it and no supported post-return access mechanism.

Passing its address is not evidence that a dependency owns the storage or may retain the address after return. Likewise, copying the third and fourth words into it is not evidence of acquiring ownership of anything those words might designate.

The final temporary-area call may suggest a lifecycle operation, but destruction, release, reference counting, and restoration are all unestablished interpretations.

## Acceptance examples

These are conditional contract examples, not executed tests. They assume valid accesses and normally returning dependencies.

1. **Zero selector after the initial call.**  
   If the selector read produces zero, the call sequence is F-5b24edfb22c0, F-44362605ab79, then F-289ec4311c64. If F-44362605ab79 returns a particular 32-bit word, that word is returned after the final call.

2. **Selector changed before it is read.**  
   If the field contains zero on entry but an effect of F-5b24edfb22c0 changes it to 2 before returning, the function takes the selector-two nonzero path. Entry-time field contents do not determine the branch independently of that intervening call.

3. **Selector two.**  
   Only the selector-two selection slot is explicitly read. Its value becomes the third argument to F-5710a8628cba. The selector-three, default-nonzero, and selector-four slots are not explicitly read.

4. **Selector three.**  
   The selector-two slot is read first, followed by the selector-three slot. The second value is retained for the result-producing call.

5. **Selector four.**  
   All four selection slots are read in order: selector-two, selector-three, default-nonzero, selector-four. The selector-four value is the one supplied downstream.

6. **Other nonzero selector.**  
   For selector 1, or a negative selector under the represented signed interpretation, the selected word comes from the default-nonzero slot. There is no explicit invalid-selector response.

7. **Global changes during F-9d0ecc5f6adf.**  
   If this dependency changes both the selected slot and the common global, F-5710a8628cba receives the already captured selected word and the common-global value read afterward.

8. **Modified temporary contents.**  
   If F-5b24edfb22c0 changes a temporary word and the selector is zero, F-44362605ab79 receives the address of the modified area. The wrapper does not restore the original input words before that call.

9. **Opaque result, including zero.**  
   If either result-producing dependency returns zero, the final temporary-area call still occurs on normal control flow, and zero is then returned. No local success or failure interpretation is applied.

- The meanings and runtime contents of the five global slots.
- The object’s full layout, size, ownership, and selector semantics.

Inferred intent is limited to a selector-driven choice between two result-construction paths. More specific domain or lifecycle interpretations are unsupported.

## Evidence

Established behavior comes solely from the supplied static function representation: four input positions, two adjacent temporary words, one selector read at byte offset 108, conditional global reads, dependency argument positions, normal call order, and an opaque 32-bit return.

The specification preserves the distinction between reads needed only as intermediate selection steps and the value ultimately passed downstream. It also distinguishes selection values captured before F-9d0ecc5f6adf from the common global read afterward.

No implementation access, dependency inspection, runtime execution, or tests have been performed. The acceptance examples are conditional consequences of the static representation, not observations.
