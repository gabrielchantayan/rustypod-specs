# F-c8ad746e916a

## Purpose

F-c8ad746e916a resolves indices for six ordered descriptor slots associated with an input object, then issues selected rearrangement requests.

The operation has two passes:

1. **Resolution:** examine slots zero through five, accepting a validated cached index or obtaining a fallback result for each active descriptor.
2. **Rearrangement:** examine the six remembered results in the same order, requesting movement when a result is greater than its slot number under signed 32-bit ordering. After each request returns, adjust qualifying results for later slots.

The apparent intent is to bring selected collection entries into leading positions while accounting for shifts caused by earlier moves. This interpretation is inferred. The caller neither verifies the final collection order nor checks whether a rearrangement request succeeds.

## Interface

**Input:** one 32-bit address-valued object argument, represented as a signed 32-bit value in the supplied body.

**Output:** no explicit return value. Observable behavior consists of addressed reads, dependency calls, and effects produced by those dependencies.

### Descriptor locations

For each slot, F-4286044f4c6c receives the input object and returns an address. The descriptor locations for that slot are derived from this returned address plus twelve times the slot number.

| Offset from the slot-adjusted address | Width | Established use |
|---|---:|---|

The activity field is read as signed, but only zero versus nonzero matters.

The descriptor-base dependency is called separately for every slot. Its six results need not be equal. The caller does not reacquire a slot’s descriptor base after intervening dependencies.

### Cached-entry layout and addressing

An entry supplies two 32-bit words:

- The first word is the comparison key.
- The numerical low eight bits of the second word supply the comparison discriminator.

The entry-selection arithmetic is **unsigned 32-bit arithmetic**. The cached index is multiplied by eight modulo \(2^{32}\). The loaded table-base value participates in the addition as an unsigned 32-bit value, and that addition also occurs modulo \(2^{32}\), before conversion of the resulting value to a pointer.

Thus, the selected address is the low 32 bits of the table-base value plus eight times the cached index. This is not an unbounded mathematical eight-byte offset:

- Cached index `0x20000000` produces a zero byte offset.
- Different indices can select the same address.
- Addition can wrap even when the multiplication does not.

The unsigned count comparison does not prevent these effects. Nonwrapping arithmetic is **not** an additional caller precondition for this calculation. Accessibility of the resulting address remains necessary for the subsequent reads.

Selection of the discriminator concerns numerical bits of the second word, not a specified addressed byte. Target byte order is not established.

### Private and shared state

The caller maintains six private 32-bit remembered indices and one separate temporary 32-bit fallback-result location. The remembered-index sentinel is `0xffffffff`.

Shared expressions supply:

- A guard reference, which is dereferenced for a low-bit test.
- A resource reference.
- Two additional initialization arguments.
- A context value obtained through an explicit dereference.

Their declarations are absent. Their complete types, dereference widths, and status as immutable references versus mutable-storage loads are not established. Separate evaluations must not be assumed equal.

## Behavior

### Entry and descriptor activity

F-875e056ead2c is called once, without arguments, before any remembered index is initialized or descriptor examined. Its result is not consumed.

Slots are processed in ascending order. For each slot, the caller:

- Initializes that slot’s remembered index to `0xffffffff`.
- Calls F-4286044f4c6c with the object.
- Derives the slot’s descriptor locations.
- Reads the 16-bit activity field.

If activity is zero, the slot receives no count lookup, cached validation, or fallback calls. Its remembered index remains the sentinel.

A normally completing invocation makes six descriptor-base calls, including when every observed activity field is zero.

### Cached-index validation

For an active slot, F-3952b8ae1dfd receives the address at object offset 12. Its result is interpreted as an unsigned 32-bit count.

The cached index is read **after** this call returns. Validation proceeds to table access only when the index is strictly less than the count under unsigned ordering. Equality fails.

For an in-range index, the caller reads the table-base value from object offset 12 and computes the selected address using the modulo-\(2^{32}\) arithmetic specified above. A wrapped address is used as calculated; the caller does not reject wrapping or verify that the address lies within an allocation.

The caller then:

- Reads the selected entry’s first 32-bit word.
- Reads the descriptor key and compares the two values.
- Only if they match, reads the entry’s second 32-bit word, selects its numerical low eight bits, reads the descriptor’s 8-bit discriminator, and compares those values.

A key mismatch skips the second-word and descriptor-discriminator reads used by this validation. Matching both values causes the cached index to be remembered and bypasses fallback entirely.

The descriptor addresses were derived before the count call. Changes made by that dependency do not cause the caller to refresh those addresses. Conversely, the cached-index read and table-base read occur after the count call and can observe changes it makes to their contents.

### Guarded initialization before fallback

Fallback occurs for an active descriptor when the cached index is out of range or either comparison fails.

The caller evaluates the guard-reference expression and tests the low bit of the dereferenced value. The dereference width is unknown; a byte-wide access is not established.

If the low bit is set, acquisition and initialization are skipped. Otherwise, F-b255b26284e6 receives a separate evaluation of the guard-reference expression.

A zero acquisition result skips initialization. A nonzero result causes these calls, in order:

1. F-1fbcf28c587c receives an evaluation of the resource-reference expression and the numeric value 512.
2. F-804adc29bbfb receives the preceding call’s result and evaluations of two additional shared expressions.
3. F-d08d3ca17b81 receives another evaluation of the guard-reference expression.

Neither the two additional arguments nor the repeated guard and resource references are established to be immutable. Intervening dependencies may affect later evaluations. The caller does not visibly assign to the guard or enforce equal guard identity across these uses.

One-time initialization and synchronization are not established by this body.

### Fallback resolution

After guard handling, F-3f12fb57a2c4 receives:

- The context value obtained through the explicit shared dereference.
- The already-derived descriptor-key address.
- A fresh evaluation of the resource-reference expression.

This resource evaluation is separate from any used during initialization.

After F-3f12fb57a2c4 returns, F-c4fb8fbff3d6 receives:

- The input object.
- The signed 32-bit value read at object offset 4, minus one.
- The same derived descriptor-key address.
- Another evaluation of the resource-reference expression.
- The address of the private temporary 32-bit result location.

The object-field read and this resource evaluation occur after F-3f12fb57a2c4 returns. Their relative evaluation order within argument preparation is not established. That dependency can therefore affect values subsequently observed by F-c4fb8fbff3d6; the caller does not reuse an earlier captured resource value.

Neither fallback dependency’s ordinary return value is consumed. After F-c4fb8fbff3d6 returns, the temporary result is copied into the current remembered index without validation.

The caller does not initialize the temporary result location before fallback. If the first fallback fails to write it, no caller-established value exists to copy. If a later fallback fails to write it, previously stored contents can remain. There is no missing-write detection.

The signed subtract-one operation is distinct from the established unsigned cached-entry arithmetic. Behavior at the signed minimum boundary is unresolved; this contract does not assign it a wraparound policy.

### Rearrangement pass

Rearrangement begins only after resolution of all six slots.

For each slot in ascending order, its remembered index qualifies for F-4798901297a4 only if:

- It is not `0xffffffff`.
- Its signed 32-bit interpretation is strictly greater than the slot number.

The comparison is signed. Values `0x80000000` through `0xfffffffe` do not qualify, despite being large unsigned values. An index equal to or below the target slot also produces no request.

For a qualifying slot, F-4798901297a4 receives the object, remembered source index, and current slot number as target.

After that call returns, the caller examines only later remembered indices. A later index is incremented by one exactly when its signed 32-bit interpretation is:

- Greater than or equal to the current target slot.
- Strictly less than the current slot’s remembered source index.

The lower endpoint is included; the upper endpoint is excluded. The current slot’s remembered source is not replaced by the target. Later turns use adjusted values.

These qualifying increments cannot overflow signed 32-bit range: the old value is nonnegative and strictly below a source no greater than `0x7fffffff`.

No success result is checked before adjustment. Normal return from the rearrangement dependency is sufficient, even if it did not perform the presumed movement. No descriptor, count, or cached-entry validation is repeated during this pass.

## Side effects

The caller directly writes its private remembered-index storage. It supplies the temporary result address to a dependency and subsequently reads that storage. It does not visibly assign to object fields, descriptor fields, cached indices, collection entries, or shared state.

Dependencies may modify any accessible state; preservation is not established.

Material ordering guarantees include:

- The entry call precedes descriptor processing.
- Each active slot’s count call precedes its cached-index read.
- The unsigned range check precedes cached-entry addressing and reads.
- A matching key gates the discriminator reads.
- Guard handling precedes fallback resolution.
- F-3f12fb57a2c4 returns before the object-field read and resource evaluation used for F-c4fb8fbff3d6.
- Every resolution slot completes before any rearrangement request.
- Each rearrangement request returns before its later-index adjustments.

No ownership transfer, allocation, release, or retention guarantee is established. The value 512 does not itself prove allocation size or ownership. Passing descriptor-key addresses does not establish read-only access.

The fallback output address refers to caller-temporary storage whose lifetime ends with the invocation. Whether a dependency retains it is unknown; no safe post-return use is established.

There is no explicit error return, rollback, exception handler, or recovery path. A dependency that does not return normally prevents completion of the remaining visible sequence.

## Acceptance examples

These are conditional static expectations, not executed tests. They assume normally returning dependencies and accessible storage for the reads actually performed. They do **not** require the unsigned cached-entry arithmetic to avoid wrapping.

1. **All descriptors inactive.** If all six observed activity fields are zero, the entry call occurs once and the descriptor-base call six times. No count, fallback, or rearrangement call occurs.

2. **Cached match.** An active slot whose cached index is below the unsigned count and whose selected entry matches both descriptor values remembers that index without guard handling or fallback.

3. **Index equals count.** Equality fails validation without reading a cached entry. Fallback follows.

4. **Wrapped multiplication.** With cached index `0x20000000` and count `0x20000001`, the range check passes. Multiplication by eight yields zero modulo \(2^{32}\), so the first entry word is read at the loaded table-base address. Matching key and discriminator accept the original index `0x20000000`, not zero. It remains eligible for rearrangement because its signed interpretation is positive and exceeds every slot number.

5. **Wrapped addition.** With table-base value `0xfffffffc`, cached index 1, and count greater than 1, the selected address is `0x00000004`. The caller uses that wrapped address if execution can access the required storage; it does not reject arithmetic wrapping.

6. **Key mismatch.** An in-range index selecting a different key causes fallback without reading the second entry word or descriptor discriminator for this validation.

7. **Numerical discriminator.** With matching keys, second word `0x123456ab` matches descriptor discriminator `0xab`. The upper 24 bits do not affect acceptance.

8. **Guard paths.** An observed set low bit skips acquisition and initialization. An observed clear low bit followed by a zero acquisition result skips only initialization. Both paths still perform the two fallback calls.

9. **Changing shared references.** If mutable storage supplies the resource reference and F-3f12fb57a2c4 changes that storage, F-c4fb8fbff3d6 receives the later evaluation. Similarly, initialization dependencies may affect the guard reference later passed to F-d08d3ca17b81. Such mutable storage is conditional, not established.

10. **Sentinel and negative results.** Fallback result `0xffffffff` is skipped. Result `0x80000000` also produces no rearrangement because its signed interpretation is negative.

11. **At or before target.** At slot 3, remembered indices 3 and 2 produce no request. The caller does not request movement in the opposite direction.

12. **Adjustment boundaries.** When slot 1 requests source 4 to target 1, later remembered values 1, 2, and 3 become 2, 3, and 4. Values 0, 4, and `0xffffffff` remain unchanged. Duplicate source value 4 is excluded from adjustment.

13. **Normal return without movement.** If F-4798901297a4 returns without changing the collection, the same remembered-index adjustments occur. The caller does not detect the discrepancy.

## Uncertainties

The following remain **documented_only**:

- Complete object, descriptor, and collection layouts; allocation extents; alignment; and accessible address ranges.
- Meanings of keys, discriminators, and nonzero activity values.
- Guard dereference width and complete shared declarations.
- Whether repeated shared expressions produce immutable addresses or load mutable storage.
- Equality of separately evaluated guard or resource references.
- Complete type and width of the explicitly dereferenced context.
- Dependency mutations, ownership, retention, concurrency, and error behavior.
- Guaranteed fallback output writes, valid index ranges, uniqueness, and successful resolution.
- Exact rearrangement semantics and final collection order.
- Target byte order.
- Overflow behavior of signed address calculations and the signed subtract-one argument.

These uncertainties do not extend to the cached-index multiplication and table-base addition: both are established unsigned 32-bit operations modulo \(2^{32}\). Their wrapping is defined arithmetic behavior, not an unresolved signed-overflow case.

Other address calculations have no visible overflow or validity protection. This body does not establish behavior when those signed calculations exceed their representable domain. Nor does defined unsigned wrapping guarantee that its resulting pointer is valid to dereference.
