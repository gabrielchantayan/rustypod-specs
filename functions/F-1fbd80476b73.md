# F-1fbd80476b73

## Purpose

F-1fbd80476b73 repeatedly obtains a 32-bit value from F-c9f1dc723c52, using a mutable current index and a caller-supplied initial working value. It counts certain consecutive-index transitions, bypasses mode-specific marker values, and stops on a discontinuity, a capacity condition, a terminal-value condition, or dependency failure.

The function returns a count and separately writes an output word. Those two results have different meanings:

- A nonzero return is the accumulated count, initially one.
- The output word is either the value obtained from the dependency or the current index, depending on the stopping condition.
- A zero return indicates an initial rejection or a dependency-reported failure. It does not establish a general guarantee that the output remains unchanged or becomes zero.

**Inferred intent:** the behavior resembles traversal of an indexed chain while measuring a consecutive portion. The supplied evidence does not establish the underlying data format or the domain meaning of its markers.

## Interface

The interface has four arguments and an unsigned 32-bit return value.

| Argument | Contract |
|---|---|
| Context address | Address represented by a 32-bit input word. The function reads fields at byte offsets `0x7c` and `0x6c`, subject to the guards below, and passes the address to F-c9f1dc723c52. |
| Initial index | Unsigned 32-bit starting index. Values zero and one are rejected. Larger values are checked against the context’s limit field. |
| Output address | Address of a writable 32-bit word. It is not accessed directly on initial rejection, but is written after successful validation. |
| Initial working value | Unsigned 32-bit value copied into a private working word. That word is passed by address to the dependency on every iteration. |

The relevant context layout is:

| Byte offset | Observed field |
|---|---|
| `0x6c` | Signed 16-bit mode field. Only values 3, 4, and 8 are accepted. |
| `0x7c` | Unsigned 32-bit initial-index limit. Equality with the initial index is accepted. |

The function also reads two external threshold values, called the **primary threshold** and **secondary threshold** in this contract. Their numeric values are not supplied. They participate in unsigned 32-bit comparisons.

Two additional values are fixed:

- Marker: `0x0ffffff7`, decimal 268,435,447.
- Boundary immediately below that marker: `0x0ffffff6`, decimal 268,435,446.

These are 28-bit-sized values carried in 32-bit words, not `0xfffffff7` and `0xfffffff6`.

### Preconditions

For an invocation that proceeds beyond its guards:

- The context fields actually accessed must be readable with the required widths.
- The output word must be writable when a direct output write occurs.
- F-c9f1dc723c52 must be callable with the supplied context, current index, and address of a writable 32-bit working word.
- The caller must satisfy any additional requirements of that dependency; those requirements are not established here.

There are no explicit null, alignment, or general pointer-validity checks. An invalid address is not converted into a defined zero-return error.

## Behavior

### Initial validation and initialization

Observable access order is significant:

1. If the initial index is zero or one, the function returns zero without directly reading the context or writing the output.
2. Otherwise, it reads the 32-bit limit at context offset `0x7c`.
3. If the initial index exceeds that limit, it returns zero without reading the mode or directly writing the output.
4. It reads the signed 16-bit mode at context offset `0x6c`.
5. If the mode is not 3, 4, or 8, it returns zero without directly writing the output.
6. For an accepted mode, it initializes the count to one, writes zero to the output word, and initializes its private working word from the fourth argument.

The accepted mode is retained internally. The function does not reread the context mode after dependency calls. Likewise, the context limit is used only for initial validation; later index changes are not checked against it.

Consequently, if the output aliases either context field, the initial field reads occur before the output-zeroing write.

### Repeated dependency calls

Each iteration calls F-c9f1dc723c52 with:

- The original context address.
- The current index.
- The address of the same private 32-bit working word.

The working word is initialized only once. Subsequent calls receive the value left by the preceding call and subsequent control flow; it is not reset to the original fourth argument.

If the dependency returns zero, F-1fbd80476b73 immediately returns zero. It does not publish the current working value through a direct output write on that path.

Any nonzero dependency return permits classification of the working word. The exact nonzero value is otherwise ignored. There is no additional validation that the dependency wrote the working word.

### Ordered classification

Classification uses the dependency-produced working value. The following cases are considered in order; later cases do not override an earlier match.

| First matching condition | Result |
|---|---|
| Working value equals the primary threshold | Mode 3 takes a marker bypass. Modes 4 and 8 take ordinary extension processing. |
| Otherwise, working value equals the secondary threshold | Mode 4 takes a marker bypass. Modes 3 and 8 proceed to terminal eligibility. |
| Otherwise, working value equals `0x0ffffff7` | Mode 8 takes a marker bypass. Modes 3 and 4 proceed to terminal eligibility. |
| Otherwise, working value is at most a freshly read primary threshold | Ordinary extension processing. |
| None of the above | Terminal eligibility. |

This precedence matters if thresholds coincide with each other or with the fixed marker. For example, equality with the primary threshold takes precedence over equality with the secondary threshold.

The primary threshold used for the final inequality is read separately from the primary threshold used for the first equality check. The contract does not treat the thresholds as a single per-iteration snapshot.

### Marker bypass

A marker bypass:

- Increments the current index by one using unsigned 32-bit arithmetic.
- Does not increment the count.
- Does not check the capacity.
- Does not directly write the output.
- Calls the dependency again.

The working word retains the marker value unless the dependency subsequently changes it.

A marker therefore advances the index without increasing the reported count. Repeated marker bypasses are not bounded by the fourth argument or by the initially read context limit.

### Terminal eligibility

A value routed to terminal eligibility stops traversal under these conditions:

- In mode 3, it always stops.
- In mode 4, it stops only if a fresh secondary-threshold read is strictly less than the working value.
- In mode 8, it stops only if both:
  - A fresh secondary-threshold read is strictly less than the working value.
  - The working value is strictly greater than `0x0ffffff6`.

On such a stop, the function replaces the working word with the current index, writes that index to the output word, and returns the current count. It does not increment the index or count first.

If terminal eligibility does not stop traversal, processing continues as ordinary extension.

The secondary threshold is not read in this terminal check for mode 3. In modes 4 and 8, this read is separate from the earlier secondary-threshold equality check.

### Ordinary extension and capacity

Ordinary extension first increments the current index by one, modulo \(2^{32}\).

It then stops if either:

- The incremented index differs from the working value; or
- The original fourth argument is less than or equal to the current count, using an unsigned comparison.

On this stop, the output receives the working value, and the function returns the current count.

Otherwise, the function increments the count by one and makes another dependency call.

Important consequences:

- Capacity is tested after the index increment.
- A discontinuity stops traversal regardless of capacity.
- Zero capacity does not reject the invocation. After validation, the dependency is still called with an initial count of one.
- Capacity one likewise permits the first call, but prevents a consecutive first result from increasing the count.
- The fourth argument has two roles: initial working value and fixed capacity comparator. Changes to the private working word do not change the capacity.
- Marker bypasses can advance the current index multiple times while the count remains unchanged.

### Arithmetic and termination

Index increments use unsigned 32-bit wraparound. In particular, incrementing `0xffffffff` produces zero; there is no overflow rejection.

The count starts at one. It is incremented only when the unsigned capacity is strictly greater than the count. Since capacity is itself a 32-bit unsigned value, this rule prevents count overflow: a count of `0xffffffff` cannot be incremented by this path.

No finite overall iteration bound is established. An unending sequence of applicable markers can continue indefinitely, including across index wraparound.

## Side effects

Directly established effects are:

- Conditional reads of the context limit and mode, in that order.
- Repeated threshold reads as required by classification.
- One initial zero write to the output after validation.
- One final output write on a nonzero-return stopping path.
- Repeated calls to F-c9f1dc723c52.
- Updates to a private working word, current index, and count.

No direct context writes, allocations, deallocations, or external-resource releases are visible.

These observations do not constrain the dependency’s effects. In particular:

- The dependency may alter globals, including thresholds.
- The dependency may alter memory reachable through the context.
- Aliasing may allow dependency effects to reach the output word.
- Dependency failure does not undo any earlier effects.

Thus, “output is zero on dependency failure” is only conditional: the function directly wrote zero before the first call and makes no later direct output write on that failure path, but dependency effects or aliasing may change the observed word.

The private working-word address is passed to the dependency during the invocation. No ownership transfer or permission to retain that address is established. Its validity after F-1fbd80476b73 returns is not established.

## Acceptance examples

These examples are conditional specifications, not executed tests. Unless stated otherwise, assume:

- Valid readable and writable storage.
- Context limit 1,000.
- Initial index 10.
- Stable primary threshold 100 and secondary threshold 200.
- The dependency returns nonzero and supplies the listed working values.
- No dependency side effects change the output, context, or thresholds.

| Scenario | Required result |
|---|---|
| Initial index is one | Return zero; no direct context read, output write, or dependency call. |
| Initial index is 1,001 | Read the limit, then return zero; do not read the mode or directly write the output. |
| Mode is 5 | After limit validation and the mode read, return zero without directly writing the output. |
| Mode 3, capacity 4, values 11, 12, 40 | Consecutive values increase the count to three. The discontinuity at 40 returns three and writes 40. Calls use indices 10, 11, and 12. |
| Mode 3, capacity 1, first value 11 | Increment the index to 11, stop because capacity is at most the count, return one, and write 11. |
| Mode 3, capacity 0, first value 11 | Still make the dependency call; return one and write 11. |
| Mode 3, capacity 4, values 100, 12, 50 | The first value bypasses to index 11 without changing the count. Value 12 increases the count to two. Value 50 stops traversal; return two and write 50. |
| Mode 4, values 200, then 20 | The first value bypasses to index 11. The second is a discontinuity after incrementing to 12; return one and write 20. |
| Mode 4, first value 201 | Terminal eligibility succeeds because 200 is less than 201. Return one and write the current index, 10. |
| Mode 8, first value 201 | Although 201 exceeds the secondary threshold, it does not exceed `0x0ffffff6`. Ordinary extension stops on discontinuity; return one and write 201. |
| Mode 8, first value `0x0ffffff8` | Both terminal conditions hold. Return one and write 10. |
| Mode 8, values `0x0ffffff7`, then 20 | The fixed marker bypasses to index 11 without increasing the count. The next value stops on discontinuity; return one and write 20. |
| First dependency call returns zero | Return zero after the initial output-zeroing write. The final output remains zero only under the stated no-side-effect assumptions. |

For a separate precedence example, suppose both thresholds equal 200. In mode 4, a working value of 200 takes ordinary extension because primary-threshold equality is considered first; it does not take the mode-4 secondary-marker bypass.

For a wraparound example, suppose the current index is `0xffffffff` and the obtained value is routed to ordinary extension with value zero. The incremented index becomes zero. If capacity exceeds the count, traversal continues and increases the count; wraparound alone is not an error.
