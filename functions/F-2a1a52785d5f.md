## Behavior

### Entry and early transfers

The first visible operation reads one byte at the incoming address-like value plus one. It then stores the incoming 8-bit payload at address 17 plus that selector. This store precedes the first indirect call carrying the second explicit input.

An early indirect call receives the incoming address-like value logically shifted right by 11. After intervening calls, the function reads a byte again from the original selector-source address. That newly read selector controls a store whose payload is obtained by clearing the top bit of the other incoming 32-bit value, shifting right by 21, and retaining eight bits. The payload consequently contains original bits 21–28.

The second read is not a reuse of the first selector. Calls can change the memory between them. Conversely, where a selector is saved and later passed as an argument, its saved value is used rather than an implicit fresh read.

Early and later calls frequently receive results shifted left by two. Argument position is significant: a saved selector sometimes follows a shifted result and sometimes precedes it.

- A derived value shifted right by 9, 11, 12, or 21, plus one.

Some source calculations reduce to address 1 because their contributing state is explicitly zero. Other reductions depend on the correctness of the represented arithmetic widths.
