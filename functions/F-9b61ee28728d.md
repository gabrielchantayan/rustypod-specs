# F-9b61ee28728d

## Purpose

F-9b61ee28728d selects an entry from a bounded sequence of length-bearing records using an unsigned position obtained from dependency F-7071f254f784. On success, it writes an accumulated lower boundary, the selected entry’s associated 32-bit value, and an accumulated upper boundary.

Two record interpretations are supported. A 16-bit context field selects either:

- A maximum of three entries, with lengths restricted to their low 16 bits and boundary accumulation subject to a bit-clearing rule.
- A maximum of eight entries, with full 32-bit lengths and modulo-\(2^{32}\) boundary accumulation.

A zero effective length terminates the search with failure. Exhausting the applicable entry limit also fails.

**Established behavior:** this is an ordered, bounded search using strict unsigned comparison and subtraction.

**Inferred intent:** the entries likely describe consecutive extents or ranges, and the associated value likely identifies the selected extent. The source does not establish those meanings. In particular, returned boundaries are not guaranteed to be ordered numerically.

## Interface

| Input | Role |
|---|---|
| Context address | Base address for a 16-bit mode field and a 32-bit dependency argument. |
| Record-table address | Base address for the entry lengths and associated values. |
| Dependency input A | Opaque 32-bit value passed to F-7071f254f784. |
| Dependency input B | Opaque 32-bit value passed to F-7071f254f784. |
| Lower-bound output address | Destination for one 32-bit accumulated boundary. |
| Associated-value output address | Destination for the selected entry’s 32-bit associated value. |
| Upper-bound output address | Destination for one 32-bit accumulated boundary. |

The result statuses are:

| Status | Meaning |
|---|---|
| `0x00000000` | An entry was selected and the three output stores were performed. |
| `0x00000010` | A zero effective length was encountered, or the search exhausted its entry limit. |

These are the only explicit return values. No separate status is provided for invalid addresses, memory-access failures, dependency failure, or arithmetic wraparound.

### Context layout

| Offset | Width | Use |
|---|---:|---|
| `0x02` | 16 bits | Compared with `0x4244` after the dependency returns. Equality selects the three-entry interpretation. |
| `0x160` | 32 bits | Read before the dependency call and supplied as its third argument. |

The context is not otherwise directly read or written by this function.

### Record-table layout

Entry numbering starts at zero. Entries have an eight-byte stride.

| Field | Byte offset from table base | Width |
|---|---|---:|
| Associated value for entry \(i\) | `0x2C + 8i` | 32 bits |
| Length word for entry \(i\) | `0x30 + 8i` | 32 bits |

The first `0x2C` bytes are not directly inspected. Associated values of entries that are skipped are not directly read.

For the three-entry interpretation, the possible associated-value offsets are `0x2C`, `0x34`, and `0x3C`; the possible length offsets are `0x30`, `0x38`, and `0x40`.

For the eight-entry interpretation, the final possible associated-value offset is `0x64`, and the final possible length offset is `0x68`.

Even when only 16 length bits are significant, the source performs a **32-bit length read**, then discards the upper 16 bits.

## Behavior

### Dependency evaluation and mode selection

Before examining the mode or any record, the function reads the 32-bit context field at offset `0x160`.

It calls F-7071f254f784 with four arguments, in this logical order:

1. Dependency input A.
2. Dependency input B.
3. The context word just read.
4. A 32-bit zero.

The dependency’s returned value is used as an unsigned 32-bit search position. No return value is reserved as a dependency error: every possible returned bit pattern participates in the subsequent search.

Only after that call returns does this function read the context’s 16-bit mode field at offset `0x02`.

Consequently:

- The dependency runs even if the first effective length will be zero.
- The dependency runs even if no entry can contain the returned position.
- A dependency change to the mode field can affect the interpretation chosen afterward.
- A dependency change to table contents can affect the subsequent search.
- The context word passed to the dependency is the value read before that call, not a later reread.

The source does not establish that the dependency preserves any accessible memory or global state.

### Search rules common to both interpretations

The search starts at entry zero with an accumulated boundary of zero. It maintains a residual position, initially equal to the dependency result.

For each visited entry, the function first reads and interprets that entry’s length word.

If the effective length is zero, it immediately returns `0x00000010`. It does not inspect later entries, read that entry’s associated value, or perform any explicit output store.

For a nonzero effective length:

- A residual position **strictly less than** the length selects the current entry.
- A residual position equal to the length does not select that entry.
- If the entry is not selected, its length is subtracted from the residual position, its length is accumulated into the boundary, and the search advances.

The subtraction occurs only when the residual position is at least the effective length. Therefore, residual subtraction does not underflow.

Boundary accumulation is a separate operation with interpretation-specific arithmetic. Its wraparound does not alter the residual-position subtraction or the selection comparison.

If every permitted entry is skipped, the function returns `0x00000010`. It does not read an additional entry beyond the applicable limit.

### Three-entry interpretation

This interpretation applies exactly when the post-dependency 16-bit mode field equals `0x4244`.

At most three entries are visited.

Each effective length is the low 16 bits of the corresponding 32-bit length word. Its range is therefore 0 through 65,535. The upper 16 bits do not affect selection, zero detection, subtraction, or accumulation.

For example, a stored length word of `0xABCD0000` has effective length zero and terminates the search with failure.

Whenever a length is accumulated, the operation is:

1. Form the 32-bit unsigned sum of the current boundary and effective length.
2. Apply the mask `0xFFFEFFFF`.

That mask clears bit 16, counting the least significant bit as bit zero. It does not generally clear every bit above bit 15.

However, the reachable boundary values in this function are narrower than an arbitrary masked 32-bit value. The boundary starts at zero, and every effective length is at most 65,535. After each accumulation, the boundary remains in the range 0 through 65,535. For these reachable values, the operation is equivalent to accumulation modulo 65,536.

The residual search position is still a full unsigned 32-bit value. It is **not** truncated to 16 bits. A dependency result greater than 65,535 can therefore select a later entry if the preceding effective lengths consume enough of that position.

### Eight-entry interpretation

Every mode value other than `0x4244` selects this interpretation.

At most eight entries are visited. Each effective length is the entire unsigned 32-bit length word.

Boundary addition uses 32-bit unsigned arithmetic, wrapping modulo \(2^{32}\). There is no additional mask.

Selection depends on the residual position rather than on a direct comparison with the accumulated boundaries. Consequently, a wrapped upper boundary does not make selection fail, and success does not guarantee that the returned upper boundary exceeds the returned lower boundary.

### Successful output sequence

On selecting an entry, the function performs these explicit memory operations in order:

1. Writes the current accumulated boundary to the lower-bound output.
2. Reads the selected entry’s associated value.
3. Writes that value to the associated-value output.
4. Writes the accumulated boundary after including the selected length to the upper-bound output.
5. Returns `0x00000000`.

The selected length was already read before the first output store. It is not reread during this success sequence.

The three outputs do not report the residual position or the offset within the selected entry.

## Side effects

### Direct effects

On a normal successful return, exactly three explicit 32-bit output stores occur, in the order described above.

On an explicit failure return, this function performs no direct output stores. It may already have read multiple length words and called the dependency.

“Outputs unchanged on failure” is therefore only a conditional guarantee: it holds when the dependency and any external actors do not modify the output storage. The supplied evidence does not justify attributing that preservation guarantee to the dependency.

No direct writes to the context or record table are designated by their roles. Output aliasing can nevertheless cause such writes.

### Aliasing

The function does not reject overlapping inputs and outputs.

If the lower-bound output overlaps the selected associated-value field, the lower-bound store occurs before that field is read. The associated-value output can therefore receive the newly stored boundary instead of the field’s earlier contents.

If an output overlaps the selected length field, the selected length remains the value already loaded before the success stores. The function does not reread it.

If the output destinations are the same aligned 32-bit location, the later stores replace earlier stores. With all three outputs at that location, its final value is the upper boundary.

Partially overlapping destinations have ordered writes, but their final byte representation depends on target byte order and access behavior, which are not established here.

The mode is not reread after selection, so success-path output writes that overlap the context mode field do not change the already chosen interpretation.

### Exceptional execution

The source supplies no local recovery mechanism for invalid memory access or a dependency that does not return normally. A memory failure during the success sequence may leave earlier output stores visible. The contract does not promise transactional or all-or-nothing updates.

These are conditional acceptance cases derived from static evidence. They are not reported runtime observations. Unless stated otherwise, assume valid memory, distinct output destinations, no relevant dependency side effects, and the specified dependency result.

1. **First entry selected**

3. **Zero stops the search**

   Let the first effective length be zero. The result is `0x00000010`, regardless of later lengths. The dependency has already been called, but this function performs no explicit output store and does not read the first associated value.

4. **Upper length bits are ignored only in the three-entry interpretation**

   Let the first stored length word be `0x00010000`, and let the dependency return zero. With mode `0x4244`, the effective length is zero and the function fails. With any other mode, the effective length is 65,536 and the first entry is selected, producing boundaries 0 and 65,536.

   With mode `0x4244`, let the first two effective lengths be 65,535 and 2. If the dependency returns 65,536, the second entry is selected. Its lower boundary is 65,535 and its upper boundary is 1. The associated-value output comes from the second entry.

6. **Three-entry limit is binding**

   With mode `0x4244`, let the first three effective lengths all be 1 and the dependency return 3. The function fails after skipping those three entries. A fourth record cannot change the result because it is not read.

7. **Full-width accumulation wraps**

   In the eight-entry interpretation, let the first two lengths be `0xFFFFFFFF` and 2. If the dependency returns `0xFFFFFFFF`, the first entry is skipped and the second is selected. The returned lower boundary is `0xFFFFFFFF`, and the upper boundary is 1.

8. **Associated-value alias affects the returned value**

   Suppose the first entry is selected and the lower-bound output points to that entry’s associated-value field. The first output store writes zero there. The subsequent associated-value read obtains zero, so the associated-value output receives zero rather than the field’s previous contents.
