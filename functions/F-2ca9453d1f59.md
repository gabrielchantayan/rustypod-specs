# F-2ca9453d1f59

## Purpose

F-2ca9453d1f59 conditionally delegates an operation on a selected object. It first rejects a zero third argument, then obtains a candidate through F-f8ec0897aceb. For a nonzero candidate, it examines one byte in an indirectly referenced object. A byte value of exactly 1 permits a call to F-32b90d7f6546; any other value produces a fixed rejection result.

If selection returns zero, the function returns the current contents of a separate 32-bit global result location rather than a fixed constant.

These are established control-flow properties. The application meaning of the selection, discriminator byte, delegated operation, and result values is not established. Descriptions such as “lookup,” “candidate,” and “operation” identify structural roles, not confirmed domain semantics.

## Interface

The interface has three arguments and a 32-bit result.

| Item | Width and treatment | Established role |
|---|---|---|
| First argument | 32-bit value used as a memory address | Base address from which a 32-bit field at byte offset `0xF50` is read, unless the third argument is zero. |
| Second argument | Opaque 32-bit value | Forwarded unchanged as the fourth argument to F-f8ec0897aceb. |
| Third argument | 32-bit value | Tested for equality with zero. If nonzero and the selected object passes the byte check, forwarded unchanged as the second argument to F-32b90d7f6546. |

The fixed rejection patterns are:

- `0xFFFFFFCE`, equivalent to −50 under signed 32-bit interpretation.
- `0xFFFFFFD5`, equivalent to −43 under signed 32-bit interpretation.

The interface does not establish a signed-result convention. A consumer interpreting the result as unsigned instead observes 4,294,967,246 and 4,294,967,253 respectively. The bit patterns are the contract; symbolic error names are unknown.

The third argument is not established to be a pointer, handle, size, or enumeration. Only its zero/nonzero distinction and its forwarding behavior are visible. In particular, a value with its high bit set is not rejected merely because it would be negative under signed interpretation.

### Required memory layout

For a nonzero third argument, the first argument must support a 32-bit read at byte offset `0xF50`, which is 3920 decimal. The resulting field is passed to F-f8ec0897aceb without interpretation or local validation.

If F-f8ec0897aceb returns a nonzero candidate address, that candidate must support a 32-bit pointer-sized read at byte offset `0x20`, which is 32 decimal. The pointer obtained from this field must support a one-byte read at byte offset `0x16`, which is 22 decimal.

The target representation shown is 32-bit. Offset additions are byte-address calculations, not scaled array indexing. Successful operation requires the relevant effective addresses to be valid for the reads and calls made. ## Behavior

### Early rejection

The third argument is examined before any object-field access or dependency call shown in the function.

When it is zero:

- The result is `0xFFFFFFCE`.
- F-f8ec0897aceb is not called.
- F-32b90d7f6546 is not called.
- The first argument is not dereferenced by this function.
- The global result location is not read by this function.

Thus, an unusable first argument does not itself prevent this particular early-return path. This does not establish that an invalid calling convention or an invalid execution environment is tolerated.

### Candidate selection

When the third argument is nonzero, the function reads the 32-bit field at the first argument plus `0xF50`.

It then calls F-f8ec0897aceb with four arguments, in this positional order:

1. The field value just read.
2. The value 1.
3. The value 0.
4. The original second argument, unchanged.

The result is tested only for equality with zero. No separate validity check is visible. A nonzero result is subsequently treated as a candidate address.

The zero/nonzero test is not a positive/negative test. A nonzero 32-bit result whose signed interpretation is negative still enters the candidate-inspection path, subject to the address being usable.

### Selection returns zero

If F-f8ec0897aceb returns zero, the function reads a separate global 32-bit result location and returns that value.

This global read occurs after F-f8ec0897aceb returns. The function does not capture the global value before making the call. Consequently, any change that F-f8ec0897aceb makes to that location can affect the returned result.

The global value is not translated, normalized, or constrained by this function. In particular:

- It need not equal either fixed rejection pattern.
- It can be zero.
- Its signed interpretation is not established.

A zero overall result therefore does not, by itself, prove that F-32b90d7f6546 was called.

### Candidate inspection

For a nonzero candidate, the function reads the pointer-sized field at candidate byte offset `0x20`. It then reads one byte at offset `0x16` from the referenced object.

Only an exact byte value of `0x01` permits the delegated operation. Every other byte value, including `0x00`, `0x02`, and `0xFF`, produces `0xFFFFFFD5`.

Whether the byte is interpreted as signed or unsigned does not change this equality check: only the bit pattern `0x01` passes.

If the byte does not equal 1:

- F-32b90d7f6546 is not called.
- The global result location is not read by this function.
- The fixed result `0xFFFFFFD5` is returned.

There is no visible null check on the pointer read from candidate offset `0x20`.

### Delegated operation

If the discriminator byte equals 1, the function reads the pointer-sized field at candidate offset `0x20` again. It forms an address at byte offset `0xC0` from this second pointer value and calls F-32b90d7f6546 with:

1. That derived address.
2. The original third argument, unchanged.

The second pointer-field access is part of the visible behavior. The supplied representation does not establish a single cached pointer shared between the byte check and the delegated call. With stable memory, both reads yield the same value. The function itself provides no synchronization or validation establishing such stability.

The wrapper forms the `0xC0`-offset address; it does not itself read a field at that offset before the call.

After F-32b90d7f6546 returns normally, F-2ca9453d1f59 returns zero. No returned value from F-32b90d7f6546 is used to choose that result.

This zero result establishes normal return from the delegated call, not independently verified success of the underlying operation.
