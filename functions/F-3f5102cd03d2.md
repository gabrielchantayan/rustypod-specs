# F-3f5102cd03d2

## Purpose

F-3f5102cd03d2 updates a caller-owned state object from two 16-bit quantities and an associated configuration object. It optionally recalculates six 32-bit values, selects a dominant dimension, computes two ratio-like results, and marks the state valid.

The established success condition is that both inspected 16-bit quantities are nonzero. Success returns the 32-bit value `0`; failure returns `0x00000097`. The function clears a one-byte validity marker before invoking any dependency and sets it to `1` only after completing the successful path.

The apparent intent is dimension normalization with optional scaling and quantization. That interpretation is inferred from operand relationships and constants, not established dependency semantics. In particular, this contract does not assert that the arithmetic dependencies perform multiplication or division.

## Interface

The function takes one pointer to writable state. The supplied representation uses 32-bit pointer and word accesses, 16-bit halfword accesses, and 8-bit byte accesses.

The return value is a 32-bit status:

| Value | Meaning established by this function |
|---|---|
| `0x00000000` | Both checked quantities were nonzero, and the successful path reached its final validity write. |

## Behavior

### Entry and external call

The function performs these operations in order:

1. Writes `0` to the validity byte at state offset `0x6C`.
2. Reads and retains the configuration address from state offset `0x00`.
3. Calls an external dependency with three arguments: the address at state offset `0x2C`, the address at state offset `0x0C`, and the integer `0x1C`.

The argument pattern suggests a 28-byte transfer from `0x0C` to `0x2C`, but the external dependency’s implementation is unavailable. A copy operation, its direction, its exact write extent, and its return convention are therefore not established.

All subsequent quantity checks occur after this call. Entry values at `0x2C` and `0x2E` are not necessarily the values used.

### Zero-quantity rejection

The function reads the first quantity as an unsigned 16-bit value.

- If the first quantity is zero, it returns `0x00000097` without explicitly reading the second quantity.
- Otherwise, it reads the second quantity as an unsigned 16-bit value. If that value is zero, it returns `0x00000097`.

On either rejection path, the function performs no further explicit state writes after the external call. The earlier validity clear and any external side effects are not rolled back.

The supplied representation contains an unexplained register-derived value on the first-quantity-zero path. It does not affect this branch’s result: a zero first quantity prevents entry into the successful path regardless of that value.

### Optional recalculation

When both initial checks pass, the function reads the configuration flag halfword at offset `0xB0`.

If bit `0x0008` is clear, it skips recalculation. In that case, the values subsequently selected from state offsets `0x30` or `0x34` are existing values, including any changes made by the external dependency.

If bit `0x0008` is set, the following dependency calls and state writes occur in order:

1. F-73d099a86adb receives the initially checked first quantity multiplied by 64 and the current configuration halfword at `0x44`. Its 32-bit result is stored at state offset `0x30`.
2. The function rereads the second quantity at `0x2E` and the configuration halfword at `0x44`. F-73d099a86adb receives that quantity multiplied by 64 and that configuration value. Its result is stored at state offset `0x34`.
3. F-74efb2674226 receives the sign-extended configuration value at `0x46` and the return value from the immediately preceding scaling call. The quantized result is stored at state offset `0x38`.
4. F-74efb2674226 receives the sign-extended configuration value at `0x48` and the currently stored state word at `0x34`. The quantized result is stored at `0x3C`.
5. F-74efb2674226 receives the sign-extended configuration value at `0x4A` and the currently stored state word at `0x34`. The quantized result is stored at `0x40`.
6. F-74efb2674226 receives the sign-extended configuration value at `0x4C` and the currently stored state word at `0x30`. The quantized result is stored at `0x44`.

The distinction between a retained return value and a later state read matters if dependencies can mutate the state.

Each quantity shifted by six is first treated as unsigned. Its possible range is `0` through `4,194,240`; the shift does not overflow 32 bits.

For each quantized result, the function takes the dependency’s 32-bit result, adds `32` modulo \(2^{32}\), then clears the low six bits. This is a bit-level operation. It produces a multiple-of-64 bit pattern, but does not establish saturation or mathematically unbounded rounding. For example, an input result of `0xFFFFFFE0` becomes `0x00000000`.

### Dominant-dimension selection

After optional recalculation, the function rereads both 16-bit quantities and retains those values for the branch and normalization arguments. These are not necessarily the quantities that passed the initial checks.

The comparison is unsigned.

If the first quantity is strictly smaller than the second:

1. Copies the current 32-bit state value at `0x34` to `0x58`.
2. Writes the retained second quantity to the 16-bit field at `0x50`.
3. Calls F-8f41f510c86c with the retained first quantity, `0x00010000`, and the retained second quantity.
4. Stores the dependency result at `0x48`.
5. Writes `0x00010000` at `0x4C`.

Otherwise, including equality:

1. Copies the current 32-bit state value at `0x30` to `0x58`.
2. Writes the retained first quantity to the 16-bit field at `0x50`.
3. Writes `0x00010000` at `0x48`.
4. Calls F-8f41f510c86c with the retained second quantity, `0x00010000`, and the retained first quantity.
5. Stores the dependency result at `0x4C`.

Thus equality selects the first dimension. Only the selected dimension’s normalization word is explicitly assigned the constant. The other word receives an opaque dependency result, even when both quantities are equal.

Finally, the function writes `1` to the validity byte at `0x6C` and returns `0`.

## Side effects

The function directly mutates the supplied state. No allocation, deallocation, ownership transfer, global access, or resource release is visible in its own operations.

Those observations do not constrain dependency behavior. Dependencies may have additional effects, and no preservation of globals or pointed-to memory may be assumed.

Important visibility and failure properties:

- The validity clear precedes the first dependency call.
- Updates are incremental, not transactional.
- The selected value and dominant quantity are written before the normalization dependency is called.
- In the equality-or-first-larger branch, the constant normalization word is also written before that call.
- The final validity write occurs only after all successful-path dependency calls return.
- A dependency fault or non-return can leave partially updated state. There is no visible recovery path.
- A zero-quantity return does not undo external effects or guarantee that the validity byte remains zero if the external dependency changed it.

The caller must provide accessible storage for every executed access and satisfy each dependency’s own requirements. Without dependency contracts, complete bounds, aliasing, concurrency, and ownership preconditions remain unknown.

## Acceptance examples

These are conditional static acceptance cases, not runtime results. Except where stated otherwise, they assume dependencies return normally and do not modify state beyond the effects specified in the example.

### First quantity is zero

After the external dependency returns, let the first quantity be `0`.

Expected behavior: return `0x97`; do not explicitly read the second quantity; do not call the three mapped arithmetic dependencies; do not perform the final validity write.

### Second quantity is zero

Let the checked quantities be `12` and `0`.

Expected behavior: return `0x97` after reading both quantities, without inspecting the recalculation flag or performing normalization.

### First quantity is smaller, recalculation disabled

Let the quantities remain `3` and `5`, and let configuration bit `0x0008` be clear.

Expected behavior:

- Select the existing state word at `0x34` into `0x58`.
- Write `5` as a 16-bit value at `0x50`.
- Call F-8f41f510c86c with `(3, 65536, 5)`.
- Store its result at `0x48`, write `65536` at `0x4C`, set validity to `1`, and return `0`.

No numerical value is required for the opaque result without that dependency’s contract.

### Equal quantities

Let both retained quantities be `7`.

Expected behavior: select the word at `0x30`, write dominant quantity `7`, write `65536` at `0x48`, and call F-8f41f510c86c with `(7, 65536, 7)` for the word at `0x4C`. Equality does not skip the call.

### Quantization boundaries

Expected behavior: the later comparison uses those zeros, takes the equality branch, and calls F-8f41f510c86c with `(0, 65536, 0)`. There is no second nonzero validation. Whether that call returns successfully is documented_only.
