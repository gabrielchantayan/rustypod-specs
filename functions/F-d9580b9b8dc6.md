# F-d9580b9b8dc6

## Purpose

F-d9580b9b8dc6 scans a caller-supplied table of eight-byte records and returns a 16-bit result while writing an associated 32-bit value through an output address.

The supplied static representation establishes two stopping conditions:

- A record contains a zero 32-bit comparison value.
- A record contains a nonzero comparison value greater than or equal to the unsigned query.

At the second stopping condition, the function initially selects the current record. If that record’s 16-bit result is zero, it substitutes the immediately preceding record. At a zero comparison value, it selects the immediately preceding record directly.

**Inferred intent:** the table may encode ordered boundaries with associated identifiers. Neither ordering nor that interpretation is enforced by the function. Its observable behavior is the forward scan and one-step fallback described below.

This contract describes the supplied static evidence. It is not a runtime-validated guarantee.

## Interface

2. **Query**

3. **Output address**

   - The function does not validate this address.

### Return value

The declared return type is a signed 16-bit integer. The returned bit pattern comes from a 16-bit table field.

Under that signed interpretation:

- Patterns from 0x0000 through 0x7FFF represent 0 through 32,767.
- Patterns from 0x8000 through 0xFFFF represent −32,768 through −1.

The internal fallback decision distinguishes only zero from nonzero. A negative 16-bit result is nonzero and does not trigger fallback.

A zero return is possible and does not, by itself, establish an error.

## Behavior

### Forward scan

The scan begins at record position zero, with an internally retained 16-bit result initialized to zero.

At each position, the function:

- Reads the table address from container offset 12.
- Reads the current record’s 32-bit comparison field.
- Tests that field for zero before performing the unsigned query comparison.

If the comparison field is nonzero and less than the query, scanning advances by one eight-byte record. The result field of a skipped record is not read during that visit, and the output location is not written.

There is no sorting check. In an unsorted table, the function still stops at the first encountered zero comparison field or first encountered nonzero field greater than or equal to the query.

### Stop on a nonzero qualifying comparison value

When the current comparison field is nonzero and the query is less than or equal to it, the function performs these observable accesses in order:

1. Reads the table address again.
2. Reads the current record’s 32-bit payload field.
3. Writes that value to the output location.
4. Reads the table address again.
5. Reads the current record’s 16-bit result field.

If the fetched result is nonzero, the function returns it without another output write.

The payload is re-read rather than copied from the value used for the stopping decision. Consequently, if memory changes between those reads, the written value need not equal the value that caused the scan to stop.

If the fetched result is zero, the function performs the one-step fallback below.

### Stop on a zero comparison value

A zero comparison field stops scanning regardless of the query.

On this path, the current record’s result field is not read. Its zero comparison field is not first written to the output location.

Instead, because the retained result is still zero, the function immediately performs the one-step fallback.

### One-step fallback

Fallback selects the record immediately preceding the stopping position. It performs these observable accesses in order:

1. Reads the table address again.
2. Reads the preceding record’s 32-bit payload field.
3. Writes that value to the output location.
4. Reads the table address again.
5. Reads the preceding record’s 16-bit result field.
6. Returns that result.

The preceding payload lies four bytes before the current record’s start. The preceding result lies eight bytes before the current record’s start.

Fallback happens **at most once**. A zero result in the preceding record is returned directly. The function does not continue searching backward for a nonzero result.

If fallback follows an initially selected record with a zero result, the output location is written twice: first with the current record’s payload, then with the preceding record’s payload.

### First-position fallback

Two cases cause fallback before the table’s nominal first record:

- The first comparison field is zero.
- The first comparison field is nonzero and qualifies, but the subsequently fetched first result is zero.

In either case, the fallback payload is read at table address minus four, and the fallback result is read at table address minus eight.

The function contains no guard for either case. Whether those accesses are valid depends on caller-provided storage and the execution environment.

### Arithmetic boundaries

Record traversal uses an integer position and eight-byte spacing. The supplied representation shows a signed 32-bit position increment, but does not establish behavior after that position overflows or address calculations exceed the representable address range.

This contract does not assume wrapping traversal. Such cases are documented only, not defined as accepted inputs.

## Side effects

### Writes and access order

The only explicit writes are 32-bit writes through the output address.

For stable, nonoverlapping memory:

- A qualifying record with a nonzero result produces one write.
- A qualifying record with a zero result produces two writes.
- A zero comparison field produces one fallback write.

These writes occur before the corresponding result-field reads. A result-field access failure can therefore occur after output storage has already changed. There is no rollback.

### Aliasing

The shown function contains no overlap check. The output address may, at the address level, overlap the container or table, but such overlap can change later behavior.

In particular:

- Writing over the container’s table-address field can redirect the next table access.
- Writing over a result field can change the result fetched after the write.
- A first output write can affect the later fallback accesses.

The repeated table-address reads are therefore significant. A model that takes one immutable table snapshot is equivalent only under an additional stability and noninterference assumption.

The supplied evidence does not establish language-level legality for every overlapping arrangement.

The function accesses caller-provided storage and does not explicitly retain its addresses after returning. This does not establish a broader ownership protocol for the container, table, or output object.

### Errors

Invalid addresses, inaccessible fields, incompatible alignment, and traversal beyond valid storage have no defined function-level error result in the supplied evidence. The function neither converts them into a status code nor guarantees that the output remains unchanged.
