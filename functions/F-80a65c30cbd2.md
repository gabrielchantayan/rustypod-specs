# F-80a65c30cbd2

## Purpose

F-80a65c30cbd2 coordinates preparation and operation dispatch using a descriptor, a count record, an output record, and caller-supplied controls. It initializes or checks descriptor-associated range information, performs common preparation, dispatches according to a captured discriminator byte, and conditionally issues two final operations.

There is no explicit return value. Observable behavior consists of record reads and writes, ordered dependency calls, and effects produced by those dependencies.

“Context,” “range,” “temporary,” and “token” describe how values are used. They do not establish instruction semantics, resource types, allocation, ownership, or release behavior.

## Behavior

### Entry capture and inactive context

The initial reads have a fixed order:

1. Read the context reference from Owner +12.
2. Read the descriptor operand from Descriptor +4.
3. Read the discriminator byte from Descriptor +0.

If the captured context reference is zero, return without further work. The descriptor reads therefore occur even for an inactive context.

The context reference, descriptor operand, and discriminator remain the captured values throughout this invocation. Later dependency effects on their original record fields do not cause these values to be refreshed.

### Preparation decision

For an active context, determine whether additional preparation is enabled:

- A negative Preparation selector disables it without reading Count record +0 for this decision.
- A nonnegative Preparation selector causes a signed four-byte read at Count record +0. Additional preparation is enabled exactly when that observation is positive.

If Mode is zero and additional preparation is disabled, call F-94896a18642d with the captured context, Output record, and Preparation operand.

This call precedes effective-count selection and cache validation. A later return caused by a cache mismatch does not undo it.

### Effective count and cache handling

If Explicit count is positive, it is the effective count. Otherwise, obtain the effective count through a new signed four-byte read at Count record +0. A count read used for the earlier preparation decision is not reused here.

Read Descriptor +8:

- If it is zero, call F-cb297b788d6f with Owner and the effective count. Write its four-byte result to Descriptor +8, then write the effective count to Descriptor +12.
- If it is nonzero, read Descriptor +12 and compare it with the effective count. A mismatch returns immediately.

After initialization or a successful comparison, read Descriptor +8 again to capture the range base used by subsequent calls.

There is no check that the initializer returns a nonzero value. A zero result is written and used in the current invocation. Because zero is also the initialization marker, a later invocation may initialize again.

There is no local positivity requirement for an effective count obtained from the Count record. Negative and zero values can reach initialization and later dependencies.

### Range and additional preparation

For nonpositive Explicit count, call F-c7c2b54bfe66 with Owner, Count record, and the captured range base, except when the captured discriminator is 3. Discriminator 3 skips only this call.

For positive Explicit count, make one F-2ea344827b50 call for each index from zero through Explicit count minus one, in ascending order. Each call receives five arguments:

- Captured context.
- Operation number 3.
- Element operand.
- Current index.
- Range base plus current index.

The addition has unit stride; no element-size multiplication is shown. These values are dependency arguments, not direct memory writes by F-80a65c30cbd2. Original-machine overflow behavior for the base-plus-index calculation remains unresolved. The loop index itself need not exceed the positive signed 32-bit Explicit count.

If additional preparation was enabled, next call F-3c0493079287 with Owner, Preparation selector, Preparation operand, effective count, and range base.

When Mode is zero, immediately follow that call with F-94896a18642d. At this call site, the supplied representation displays only the captured context and Output record as arguments. The earlier call displays three arguments. The complete ABI of this dependency is therefore unresolved; no missing argument value is specified here.

### Dispatch gate

Read Count record +0 again and call F-9f0c21b197c2 with Owner, Descriptor, and that newly observed four-byte count.

A nonzero result returns immediately, skipping discriminator dispatch and final operations. All preceding calls and writes remain performed. A zero result permits dispatch.

The gate does not refresh the captured discriminator, descriptor operand, context, effective count, or range base.

1. Call F-887ba2404a49 with context, operation number 41, the observed value, and **0xffffffff**.

## Side effects

The placement of F-65af7db35d2d after temporary uses does not establish release or ownership transfer. Cache initialization likewise does not prove allocation. No explicit local error result, rollback, or abnormal-termination cleanup is present.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Referenced accesses must be valid and dependencies must return normally unless an example specifies a gate return.

1. **Inactive context:** If Owner +12 is zero, Descriptor +4 and Descriptor +0 are still read, in that order after the context read. No dependency call or direct write follows.

2. **Mismatch after an earlier effect:** With zero Mode, negative Preparation selector, positive Explicit count, and a nonzero cached base whose cached count differs, F-94896a18642d runs before the mismatch return. No range-preparation, gate, dispatch, or final call follows.

3. **Negative effective count:** With nonpositive Explicit count, a negative effective-count observation, and a zero cached base, that negative count reaches F-cb297b788d6f unchanged. It is not normalized or rejected locally.

4. **Distinct count observations:** With nonnegative Preparation selector and nonpositive Explicit count, a positive first count can enable additional preparation while a later count supplies a different effective count. The gate receives another fresh observation.

5. **Explicit elements under discriminator 3:** With Explicit count 2, the two element calls receive respectively **context, 3, Element operand, 0, range base** and **context, 3, Element operand, 1, range base plus 1**. Each has five arguments. After a zero gate result, dispatch emits **(47, 1, captured descriptor operand, 0)**.

6. **Zero initializer result:** A zero initialization result is stored before the cached count and then reread as the range base. There is no local failure return solely because it is zero.

7. **Gate stop:** A nonzero gate result prevents discriminator-specific byte writes and final operations without reversing preceding cache writes or calls.

8. **Discriminator 7 with nonzero Mode:** The token call precedes the lookup and byte write. F-26bb19274724 follows the write. Token finalization follows that dependency and uses a newly read Context +12. No zero-Mode temporary sequence occurs.

9. **Changed final field:** With zero Mode and an initially nonnegative Output record +52, both final calls occur. If the first call changes the field to a negative value, the second receives that new value without sign revalidation.

10. **Unlisted discriminator:** After successful common processing and a zero gate result, an unlisted discriminator proceeds to final handling without a discriminator-specific call.
