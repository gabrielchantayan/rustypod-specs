# F-e4b6b1c96417

## Purpose

This routine performs an ordered sequence of memory updates and three indirect calls, derives additional addresses from pointer values and memory contents, and reaches a reported invalid-instruction boundary. The supplied static representation does not establish a reliable application-level purpose.

The contract is therefore conditional: it describes effects if execution reaches each operation and the environment permits that operation. It does not promise successful initialization, valid allocation, ordinary return, or recovery from an invalid address.

The representation includes warnings about invalid instruction data, removed unreachable regions, and overlapping global symbols. Those warnings limit confidence in recovered control flow and global layouts. A platform-control purpose is possible inferred intent, not an acceptance requirement.

## Interface

### Explicit inputs

| Input | Represented form | Established use |
|---|---|---|
| A | Signed 32-bit integer | Multiplied by 2²⁸ for the first Q-relative store. |
| B | 32-bit value | No explicit use in the visible body. |
| P | Pointer with a 32-bit representation | Used as a memory base, numeric data, and an address-calculation input. |
| Q | Pointer with a 32-bit representation | Receives five consecutive 32-bit stores near entry. |

These labels identify interface roles, not implementation identifiers.

The explicit P-relative accesses are:

| Byte offset | Access |
|---:|---|
| 0 | 16-bit store, later 32-bit pointer store |
| 4 | 32-bit pointer store, later overlapping 16-bit zero store |
| 8 | 32-bit constant store |
| 24 | Independently conditional unsigned 16-bit read and 16-bit store |
| 30 | 16-bit store |
| 44 | 16-bit store |

The furthest explicit P-relative access covers bytes 44–45. No direct access to bytes 46–47 is established. Passing or storing addresses such as P+12 does not itself access their destinations. Dependencies may access additional storage of unknown extent.

Q receives 32-bit stores at offsets 0, 4, 8, 12, and 16. This establishes a 20-byte direct output span, not an exclusive or permanently stable result region.

### Additional inputs

Behavior also depends on:

- An incoming register-derived address used for a 16-bit store at that address plus 14.
- Another incoming register-derived value written at Q+16.
- Existing fixed-address and global-associated memory.
- Two vector-associated global values used in address calculations.
- Dependency results and dependency-induced changes.

Neither incoming register-derived value is supplied by the explicit interface.

### Width and arithmetic rules

All offsets here are bytes. Pointer scaling has been resolved into byte offsets.

Explicit destination pointer types establish the widths of the corresponding indirect stores. A bare assignment to a global whose declaration is absent does **not** establish its physical store width. Likewise, converting a global value to 32 bits does not establish a 32-bit physical read.

Consequently, every bare global assignment described below has unresolved physical access width, even where its assigned expression has a known 8-, 16-, or 32-bit value. The same distinction applies to global reads.

Unsigned 32-bit calculations use their represented low-32-bit semantics. Signed overflow, overflowing signed shifts, address wrapping, implementation-dependent signed conversions, and excessive shift counts require target semantics not supplied here.

### Results, errors, and ownership

No ordinary return value or normal return path is represented. The visible path terminates at an invalid-instruction boundary.

There are no visible null checks, bounds checks, dependency-success checks, or recovery branches. Each access requires an environment that permits its address, width, and alignment. No allocation, release, ownership transfer, retained-reference guarantee, or lifetime guarantee is established.

## Behavior

### 1. Entry writes

The first operation assigns numeric P multiplied by 2²¹ to the global associated with `0xffffffcc`. The expression uses signed 32-bit arithmetic; the physical global store width is unresolved.

Five ordered 32-bit stores then occur:

1. A multiplied by 2²⁸ at Q+0.
2. Numeric P at Q+4.
3. The value obtained from a subsequent reference to the global at `0xffffffcc`, converted for the 32-bit destination, at Q+8.
4. Numeric P at Q+12.
5. The second hidden incoming value at Q+16.

The third store must not be modeled as using a saved copy of the first product. Its source-global reference occurs after the preceding Q stores. Aliasing, mapped-memory semantics, or external changes can affect the value obtained. Its physical source-read width is unresolved.

A 16-bit zero is then stored at the first hidden incoming address plus 14.

### 2. Initial P-related and fixed-address effects

The following operations occur in order:

- Assign the low 16 bits of P to the global associated with address 6. Its store width is unresolved.
- Read that global again and store the value, converted to 16 bits, at P+0. The source-global read width is unresolved.
- Store an 8-bit value at the address formed by shifting signed numeric P left by seven. The stored low eight bits correspond to the low byte of P multiplied by 64.
- Store `0x0898033c` as 32 bits at P+8.
- Assign `0x86` to the global associated with `0x8a`, with unresolved store width.
- Store `0x86` as 32 bits at the address obtained by arithmetic-right-shifting signed P by 16, multiplying by 512, and adding 8.

The assignment at address 6 and the subsequent read are separate effects. Equality of the assigned and read-back values requires suitable memory behavior; it is not an unconditional guarantee.

### 3. Captured control and composite value

A reference to the global associated with `0x089801dc` is converted to an unsigned 32-bit value and captured. Call this the **captured control**. Its retained width is established; its physical source-memory read width is not.

A separate 32-bit composite is formed from references to globals associated with addresses 2, 4, and 5:

- The address-2 component contributes 16 bits in positions 0–15.
- The address-4 component contributes 8 bits in positions 16–23.
- The address-5 component contributes 8 bits in positions 24–31.

These are expression-component widths. They do not establish the physical read widths of those globals, their general memory layout, or a target-wide byte-order rule. The evaluation order of the component reads is unresolved.

The routine next performs these ordered operations:

1. Assign 4 to the global associated with `0xffffffc0`.
2. Assign 4 to the global associated with `0xffffffc8`.
3. Assign the composite to the global associated with `0xffffffc4`.
4. Assign P to the global associated with `0xffffffd0`.
5. Read the global associated with `0xffffffcc`, add 48, and store 4 as 32 bits at the resulting address.
6. Store numeric P as a 32-bit pointer representation at P+0.

The physical widths of the first four assignments and the scratch-global read in the fifth operation are unresolved. The fifth and sixth destination stores are explicitly 32 bits. The sixth replaces the earlier P-relative halfword and covers bytes 0–3.

### 4. Low-address state and vector-derived store

Establish a working address P+4. Then:

- Assign 4 to the global associated with address 4.
- Assign zero to the global associated with address 5.
- Store the working address as 32 bits at the original composite plus 20.
- Store an 8-bit zero at twice the captured control.
- Arithmetic-right-shift the signed composite by the low eight bits of the captured control.

The two global assignment widths are unresolved. The multiplication by two is a represented unsigned 32-bit calculation. Shift counts outside 0–31 require target-specific semantics.

Next:

1. Assign zero to a reset-associated global.
2. Assign zero to the global associated with address 2.
3. Assign the shifted composite to the global associated with `0x20`.

All three physical store widths are unresolved. In particular, the 32-bit shifted value does not prove a 32-bit store at `0x20`.

A subsequent explicit 32-bit store uses two references to one vector-associated global. One reference forms the destination by adding 32; another supplies the value converted to unsigned 32 bits. The representation does not capture one shared sample.

Their evaluation order, physical read widths, number of physical reads, and equality are unresolved. Stable ordinary memory may make their values equal, but that is an additional condition.

Finally, the global associated with address 6 receives a composition whose upper halfword is 8 and whose lower halfword comes from a fresh reference to that global. The composed value is 32 bits; the source-global read width and destination-global store width remain unresolved.

### 5. First dependency

Before F-opaque-01, the routine performs:

1. A 32-bit store of P+12 at P+4.
2. A 16-bit store of 8 at P+30.
3. A 16-bit zero store at P+4.

The last store overwrites two bytes of the pointer representation. It does not establish a null 32-bit pointer; the remaining representation depends on byte order.

F-opaque-01 receives eight represented arguments:

| Position | Value |
|---:|---|
| 1 | 8 |
| 2 | P+8 |
| 3 | 0 |
| 4 | 32 |
| 5 | P+4 |
| 6 | Captured control |
| 7 | Shifted composite |
| 8 | 0 |

Its represented unsigned 32-bit result is immediately used as both the destination address and data of a 32-bit store. There is no intervening validity check.

The result is then bitwise-ANDed with numeric P+4. Call this the **masked result**. Its low 16 bits are stored at P+44.

### 6. Second dependency and independent conditions

F-opaque-02 receives `0x08980358` and `0x089802e0`. Its represented 32-bit result supplies the base and data for three ordered stores:

1. The result itself as 32 bits at result+68.
2. The result itself as 32 bits at result+0.
3. P+4 as 32 bits at result+4.

The masked result becomes the current working value. Two independent conditions follow:

- If the masked result interpreted as signed 32 bits is nonnegative, an unsigned 16-bit read at P+24 replaces the current value, zero-extended to 32 bits.
- If the captured control interpreted as signed 32 bits and arithmetic-right-shifted by 12 is nonnegative, the current value’s low 16 bits are stored at P+24.

The first condition does not govern the second. A read can occur without a write, and a write can occur without a read. Under ordinary arithmetic-right-shift semantics, the second condition is equivalent to the captured control’s top bit being clear.

### 7. Further state updates

The routine stores a 16-bit zero at the address obtained by multiplying the current unsigned 32-bit value by 2²⁹.

It then performs these ordered global assignments:

1. Zero to the earlier reset-associated global.
2. To the address-2 global, a value formed by unsigned 32-bit left shift by 21, logical right shift by 16, and conversion to 16 bits.
3. 4 to the address-4 global.
4. Zero to the address-5 global.
5. 4 to the global associated with `0x04000000`.
6. 4 to the global associated with `0x04000004`.

Every destination-global access width in this list is unresolved. In particular, neither assignment at `0x04000000` or `0x04000004` establishes a halfword store.

The value assigned in the second operation equals the low eleven bits of the current value shifted left by five. That value computation does not establish the global’s physical store width.

Next, two references to the global associated with `0x30` supply:

- An address through unsigned 32-bit conversion.
- Data converted for an explicit unsigned 16-bit destination store.

Only the destination store width is established. The global’s read widths, sampling order, number of physical reads, and equality of the evaluated values remain unresolved.

### 8. Third dependency and derived-base accesses

F-opaque-03 receives `0x089803d8` and produces a represented 64-bit result.

The routine then:

1. Stores the result’s upper 32 bits as four bytes beginning at address `0x0a`.
2. Interprets the lower portion as signed 32 bits and multiplies it by four to derive a base.
3. Stores the base’s low 16 bits at base+2.
4. Stores 4 as 16 bits at the same destination.
5. Reads an unsigned 16-bit value at base+32.

Signed multiplication overflow in deriving the base requires target semantics. The two stores at base+2 are distinct ordered effects, even when ordinary memory retains only the latter value.

### 9. Final effects and termination

Zero-extend the last halfword read to 32 bits. Store that value:

1. As 16 bits at value+32.
2. As 32 bits at four times value+20.
3. As 16 bits at value+4.

A reference to another vector-associated global is converted to unsigned 32 bits and multiplied by four. This destination is captured and reused. Its underlying global read width is unresolved.

The captured destination receives two ordered 16-bit stores:

1. `0x03d8`.
2. The low 16 bits of the destination address itself.

The final represented effects are:

- Assign 1 to a reset-associated global. Its width is unresolved; identity with the earlier reset-associated destination is not established.
- Store `0x0a` as 32 bits at `0x0a20`.
- Assign 3 to the global associated with address 5, with unresolved width.
- Assign `0x8c` to the global associated with address 4, with unresolved width.
- Store one byte at `0x08980d8c`, derived from the signed 32-bit conversion of a reference to the global associated with `0x08980420`, arithmetic-right-shifted by 31.

The last source-global read width is unresolved. The signed 32-bit conversion establishes the width of the sign computation, not the physical read. Under ordinary arithmetic-right-shift semantics and low-byte conversion, the stored byte is zero for a nonnegative converted value and `0xff` for a negative one.

The represented path then reaches invalid instruction data, without an ordinary return.

## Side effects

Effects reach caller-provided regions, fixed-address globals, hidden-input-derived addresses, dependency-result-derived addresses, and addresses derived from memory contents.

No non-aliasing guarantee exists. Earlier stores may affect later reads. Dependencies may change globals or pointed-to storage. Captured values remain conceptually distinct from later references to their original sources.

Separate operations retain their represented order. Multiple references within one expression do not establish an internal sampling order.

No rollback is represented. Repeated stores cannot be collapsed merely because the final ordinary-memory value would match; hardware or other observers may distinguish them.

## Acceptance examples

These are conditional static consequences, not executed tests.

1. **Initial output under explicit arithmetic assumptions.** With A=3, P=`0x1000`, wrapping 32-bit product behavior, scratch-global storage that preserves the assigned 32-bit value, and no relevant aliasing, the first four Q words are `0x30000000`, `0x00001000`, zero, and `0x00001000`. The fifth comes from the hidden incoming value.

2. **Global widths remain unresolved.** Reaching the assignments at `0xffffffc0`, `0xffffffc8`, `0x20`, `0x04000000`, and `0x04000004` requires the stated values and ordering. This contract does not select halfword or word accesses for them.

3. **Captured width is not read width.** If the converted control value is `0x80000000`, the later signed shift by 12 is negative, so the conditional P+24 store is skipped. This says nothing about the physical width used to obtain the control global.

4. **Explicit region boundary.** The P+44 store affects bytes 44–45. It does not establish accesses at P+46 or P+47, or prove sufficient storage for dependency behavior.

5. **Separate vector references.** If the destination-forming evaluation yields `0x1000` and the data-forming evaluation yields `0x2000`, the explicit 32-bit store targets `0x1020` with data `0x2000`, assuming the represented address arithmetic.

6. **Zero dependency result.** If F-opaque-01 returns zero, the next represented operation is a 32-bit zero store at address zero. There is no visible failure branch.

7. **Independent halfword conditions.** If the masked result is nonnegative and P+24 reads as `0xbeef`, the current value becomes `0x0000beef`. A captured control of `0x80000000` independently prevents the conditional store back.

8. **Final sign conversion.** If the final global reference converts to signed 32-bit `−1`, the final explicit byte store writes `0xff` under ordinary arithmetic-shift semantics, regardless of the unresolved physical source-read width.
