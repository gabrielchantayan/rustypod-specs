# F-646d64bbe501

## Purpose

F-646d64bbe501 performs an ordered update involving a primary service object, a shared state record, and a secondary service object. It consumes pending state associated with a supplied 32-bit key and conditionally invokes additional service operations.

The established behavior includes:

- Capturing six primary-object values before invoking the main update dependency.
- Conditionally disabling a separately queried primary-object state.
- Processing six key-qualified pending entries against those captured values.
- Updating a secondary object according to a shared mode and the third argument.
- Optionally evaluating a two-output query and notifying another object.
- Applying three further key-qualified byte-valued operations.

“Pending,” “mode,” and “notification” are descriptive labels, not established application semantics. The source does not establish whether this concerns rendering, input, configuration, or another subsystem.

## Behavior

The function calls F-cdd33263ee89 and treats its result as the primary object. There is no null check before dispatching through it.

It invokes six operations in the following order, preserving their results as 32-bit unsigned values:

| Capture order | Operation offset |
|---:|---:|
| 1 | 0xD0 |
| 2 | 0xC8 |
| 3 | 0xC0 |
| 4 | 0xF0 |
| 5 | 0x100 |

These are snapshots. Later decisions use the saved results rather than invoking these operations again.

Next, it invokes the primary operation at 0x84. If that returns a nonzero 32-bit value, it invokes the primary operation at 0x80 with an additional argument of zero. A zero result skips the 0x80 operation.

All six captures precede this query and conditional operation.

### 2. Invoke the main update dependency

Only after that call returns does it obtain the shared-record pointer. Thus, a shared-pointer change made by this dependency can affect which record the function processes.

The primary-object reference and six captured values remain those obtained before this call. They are not refreshed even if the dependency changes service state.

### 3. Process six pending entries

The entries are processed in the table order:

| Entry | Pending flag | Comparison byte | Associated key | Saved result from | Conditional operation |
|---:|---:|---:|---:|---:|---:|
| 1 | 0x01 | 0x0E | 0x38 | 0xD0 | 0xCC |
| 2 | 0x02 | 0x0F | 0x3C | 0xC8 | 0xC4 |
| 3 | 0x03 | 0x10 | 0x40 | 0xC0 | 0xBC |
| 4 | 0x04 | 0x11 | 0x44 | 0xF0 | 0xEC |
| 5 | 0x05 | 0x12 | 0x48 | 0x100 | 0xFC |
| 6 | 0x06 | 0x13 | 0x4C | 0xF8 | 0xF4 |

For each entry:

- A zero pending flag skips the entry without reading its associated key or comparison byte.
- A nonzero flag causes the associated 32-bit key to be compared with the input key.
- A key mismatch skips the entry without clearing its flag.
- A key match causes the saved 32-bit result to be compared with the entry’s comparison byte, interpreted as an unsigned value from 0 through 255.
- If unequal, the listed conditional operation is invoked on the primary object, with no additional explicit argument.
- After a matching entry’s comparison and any conditional call complete, its pending flag is written to zero.

A matching entry is therefore consumed even when the comparison is equal and no object operation is needed.

The comparison does not mask the saved result to eight bits. A saved result of 0x00000101 differs from a comparison byte of 0x01.

The first entry’s condition is expressed through the global pointer location, while its flag clear and subsequent entries use the retained record pointer. No intervening call is visible between retaining the pointer and evaluating that first condition. Concurrent replacement of the global pointer is not covered by a synchronization contract.

Calls made for earlier entries occur before later entries’ fields are evaluated. The function does not snapshot all pending flags, keys, or comparison bytes in advance.
