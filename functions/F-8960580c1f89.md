# F-8960580c1f89

## Purpose

F-8960580c1f89 conditionally creates and attaches an object using a supplied descriptor, an operation selector, and a two-word temporary context.

The established behavior has two normal-return outcomes:

- **Not completed:** return a 64-bit value whose upper 32 bits contain the operation selector and whose lower 32 bits are zero.
- **Completed:** return a 64-bit value whose upper 32 bits contain the original third argument’s bit pattern and whose lower 32 bits equal one.

Completion requires both an entry predicate and a nonzero result from F-d0d9c9d6a6d3. On that path, the function processes the temporary context, passes it to a destination within the resulting object, invokes a further operation on the temporary context, clears two object bytes, and calls F-7c3e30682ee7.

“Creates,” “attaches,” and “context” describe inferred roles, not established ownership or lifecycle guarantees. The directly established contract is the access sequence, dependency calls, explicit writes, and return encoding below.

## Interface

### Arguments

The interface has four 32-bit arguments, in this order:

| Position | Contract name | Established use |
|---|---|---|
| First | Owner address | Used as an address for a one-byte read at offset 8; passed to two dependencies. |
| Second | Selector | Interpreted as an unsigned 32-bit value; compared with zero and four; passed to a dependency; encoded in the non-completed return. |
| Third | Context word | Tested for zero; copied into the first word of a temporary context; encoded in the completed return. |
| Fourth | Descriptor address | Used as an address for a one-byte read at offset 16; copied into the second word of the temporary context; passed to F-d0d9c9d6a6d3. |

The first, third, and fourth arguments are represented as 32-bit signed integers in the supplied interface. Their uses do not establish signed arithmetic semantics beyond that representation. In particular:

- The third argument is compared only with zero.
- The first and fourth arguments are used as addresses.
- The third argument’s completed-return contribution is its 32-bit bit pattern, not a sign-extended 64-bit value.

No richer type, object layout, string interpretation, or handle ownership is established for these arguments.

### Return value

The return occupies 64 bits and is most precisely described as two 32-bit fields:

| Normal-return outcome | Upper 32 bits | Lower 32 bits |
|---|---|---|
| Entry predicate fails | Selector | 0 |
| Entry predicate passes, but F-d0d9c9d6a6d3 returns zero | Selector | 0 |
| Full visible sequence completes | Original context word | 1 |

This is a bit-level contract. If a caller interprets the result as a signed 64-bit integer, the upper field can make the numerical result negative. That interpretation does not change the field contents.

The result is not a standalone Boolean. A non-completed result can be numerically nonzero when the selector is nonzero. Conversely, the completed marker is specifically the lower 32-bit field equal to one.

### Direct memory requirements

For a defined execution through the initial predicate, the descriptor address must support a one-byte read at offset 16. The function performs this read before checking whether the context word or selector would otherwise disqualify the request.

If F-d0d9c9d6a6d3 returns nonzero, the owner address must additionally support a one-byte read at offset 8 when that read occurs.

The nonzero result from F-d0d9c9d6a6d3 must support:

- Passing its address plus 4 to F-46f0b3cb316e.
- A one-byte write at offset 12.
- A one-byte write at offset 13.
- Whatever access F-7c3e30682ee7 requires.

Dependency-specific preconditions are unknown. These direct requirements do not establish that the whole object is valid, that all dependencies accept the arguments, or that the calls terminate normally.

## Behavior

### 1. Evaluate the entry predicate

The function first reads one byte at descriptor offset 16 and compares it with seven.

Only if that comparison succeeds does the remaining predicate matter. The request qualifies when all of the following hold:

- The descriptor byte equals seven.
- The context word is nonzero.
- The selector is nonzero.
- The selector is not four.

The selector is unsigned and 32 bits wide. No range restriction beyond excluding zero and four is visible.

If the predicate fails, the function makes none of the six listed dependency calls and performs no explicit memory write. It returns the selector in the upper 32 bits with a zero lower field.

A zero context word or an excluded selector does not protect an invalid descriptor address: the descriptor byte is read first.

### 2. Initialize a two-word temporary context

When the predicate passes, the function creates a temporary context with this established layout:

| Byte offset | Width | Initial content |
|---|---|---|
| 0 | 4 bytes | Original context word |
| 4 | 4 bytes | Original descriptor address |

The visible temporary region is eight bytes consisting of two adjacent 32-bit words. No additional header, length, tag, or terminator is established.

This initialization precedes the first dependency call. Consequently, the temporary begins with the original argument values even if a later dependency changes descriptor memory or other shared state.

### 3. Request a resource and initialize an object

The function calls F-8157a180d901 with the numeric argument 32.

It then calls F-d0d9c9d6a6d3 with:

1. The 32-bit result from F-8157a180d901.
2. The original descriptor address.

There is no visible check on the first dependency’s result. In particular, a zero result is still forwarded to F-d0d9c9d6a6d3.

The role of F-8157a180d901 as an allocator is inferred from its use, not established by its body. The argument 32 is established; a guarantee that 32 usable bytes are returned is not.

If F-d0d9c9d6a6d3 returns zero, the function immediately takes the non-completed return path. It does not visibly:

- Invoke either temporary-context operation.
- Clear either object byte.
- Call F-7c3e30682ee7.
- Release the resource returned by F-8157a180d901.

Whether either dependency performs internal cleanup is unknown. The absence of a visible release does not, by itself, establish a leak.

### 4. Process the temporary context

When F-d0d9c9d6a6d3 returns nonzero, that result becomes the object address for the remaining sequence.

The function reads one byte at owner offset 8 and calls F-b5f4a3351c2f with:

1. The address of the temporary context.
2. The selector.
3. The owner address.
4. The byte read from owner offset 8.

The owner byte is sampled after F-8157a180d901 and F-d0d9c9d6a6d3 have returned. It is not an entry-time snapshot. Changes made by those dependencies can therefore affect the byte supplied to F-b5f4a3351c2f.

The temporary context is passed by address. It must not be assumed to retain its initial two words after this call.

### 5. Pass the temporary to the object, then invoke its final temporary operation

The function next calls F-46f0b3cb316e with:

1. The object address plus 4.
2. The address of the same temporary context.

After that call returns, it calls F-289ec4311c64 with the address of the same temporary context.

The order is fixed: F-b5f4a3351c2f precedes F-46f0b3cb316e, which precedes F-289ec4311c64.

The temporary’s contents supplied to each later dependency are whatever the preceding calls have left there. The function does not restore the initial context words between these calls.

The visible call shape is consistent with assigning or transferring a temporary value and then destroying or releasing it, but those meanings are not established. Copying, ownership transfer, reference counting, and resource release remain unknown.

### 6. Clear two bytes and invoke the final dependency

After F-289ec4311c64 returns, the function performs two explicit one-byte writes:

1. Zero to object offset 12.
2. Zero to object offset 13.

These are separate writes in that order. The visible operation is not a wider clear, and no adjacent byte is explicitly cleared.

The function then calls F-7c3e30682ee7 with the owner address and object address.

The explicit zeroing occurs after all three temporary-context calls and before F-7c3e30682ee7. The final dependency can potentially modify those bytes again; zero values on function return are therefore not guaranteed by this function alone.

If all calls return normally, the function returns the original context word in the upper 32 bits and one in the lower 32 bits. No additional success result from the final dependency is tested.

## Side effects

### Direct effects

The function directly performs the following externally relevant accesses, in order when the full path is taken:

1. Read one byte at descriptor offset 16.
2. After the first two dependency calls, read one byte at owner offset 8.
3. After the three temporary-context calls, write zero at object offset 12.
4. Write zero at object offset 13.

Temporary initialization is local, but its storage is exposed by address to three dependencies.

The function performs no explicit write through the owner or descriptor arguments. This does not imply that their referenced memory remains unchanged: dependencies receive these addresses, directly or through the temporary.

### Indirect effects and ownership

Every dependency may have additional effects not described by the supplied body. No dependency is assumed to preserve global state, avoid callbacks, leave aliased memory untouched, or preserve object contents.

The function does not establish:

- Whether the resource from F-8157a180d901 is newly allocated.
- Whether F-d0d9c9d6a6d3 returns that same address or another object.
- Who owns either result on success or failure.
- Whether F-46f0b3cb316e retains the temporary address or copies its contents.
- Whether F-289ec4311c64 releases anything.
- Whether F-7c3e30682ee7 takes ownership of the object.

The temporary has function-local lifetime. Retaining its address beyond this invocation would require an external contract not present in the evidence.

No explicit error reporting, retry, rollback, or exception handling is visible. A failure to access required memory or an abnormal dependency exit is outside the documented normal-return outcomes.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not reports of executed tests.

### Descriptor mismatch

Given a readable descriptor byte other than seven and selector nine:

- No dependency is called.
- The owner byte is not read.
- The return is `0x0000000900000000`.

The context word does not affect this outcome.

### Excluded selector

Given descriptor byte seven and a nonzero context word:

- Selector zero returns `0x0000000000000000`.
- Selector four returns `0x0000000400000000`.
- Neither case calls a dependency.

### Zero context word

Given descriptor byte seven, selector five, and context word zero:

- No dependency is called.
- The return is `0x0000000500000000`.

### Initialization returns zero

Given a passing predicate and selector five, if F-d0d9c9d6a6d3 returns zero:

- Only the first two dependencies are called.
- The owner byte is not read.
- Neither object-byte write occurs.
- The return is `0x0000000500000000`.

This remains true if F-8157a180d901 returned zero; that result is forwarded rather than independently rejected.

### Completed path with a high-bit context word

Given a passing predicate, context-word bit pattern `0x80000001`, and a nonzero object result, with every subsequent call returning normally:

- All six calls occur in the specified order.
- The two explicit byte writes occur before the final call.
- The return is `0x8000000100000001`.

The upper word is not replaced by the selector and is not sign-extended across the entire return.

### Dependency changes the owner byte

If the owner byte initially equals two but a preceding dependency changes it to nine before the owner-byte read, F-b5f4a3351c2f receives nine.

### Final dependency changes a cleared byte

If F-7c3e30682ee7 writes a nonzero value to object offset 12, the function can still return the completed encoding. Acceptance requires the earlier explicit zero write, not a guaranteed final zero value.
