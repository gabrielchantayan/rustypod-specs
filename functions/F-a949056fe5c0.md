# F-a949056fe5c0

## Purpose

F-a949056fe5c0 evaluates a condition associated with a receiver object and selects one of two observable actions:

- If an initial predicate returns zero and a secondary predicate returns nonzero, it invokes a receiver method with a helper-produced value, performs helper cleanup, and then clears a context byte.
- Otherwise, it sets that context byte and invokes a different receiver method with the value 16.

It subsequently performs common cleanup and returns the 32-bit value 1.

The embedded data suggests a keyboard-hiding operation, but this is **inferred intent**, not an established description of the dependency behavior. In particular, neither a successful keyboard transition nor a specific meaning for the context byte can be established from the available body.

This contract describes the function’s own reads, writes, calls, and ordering. The internal behavior of its dependencies remains unspecified unless explicitly described below.

## Behavior

It then performs the following externally relevant operations in order:

1. Reads the context reference from receiver offset 188.
2. Calls **F-5710a8628cba** with:

   - a separate embedded datum whose interpretation is not established here.
3. Calls **F-398e0e9a318a** with the address of the third-argument temporary and the value returned by F-5710a8628cba.
4. Calls **F-6d70e45e29c9** with the address of that same third-argument temporary.

The result from F-6d70e45e29c9 is tested as a 32-bit integer for equality to zero:

- A nonzero result selects the byte-setting branch immediately.
- A zero result permits a second predicate call.

Only when the first predicate returns zero does the function read the context reference again from receiver offset 188 and call **F-d53862ada031** with that reference.

The second result is also tested as a 32-bit integer:

- Nonzero selects the byte-clearing branch.
- Zero selects the byte-setting branch.

There is no requirement that a true result equal 1. Any nonzero 32-bit result satisfies a nonzero comparison.

### Byte-clearing branch

This branch is selected exactly when:

- F-6d70e45e29c9 returns zero; and
- the subsequently called F-d53862ada031 returns nonzero.

The function then:

1. Calls **F-9b9c1c7483f4**, passing:
   - the address of the second-argument temporary;
   - a reference four bytes into the embedded data region used earlier;
   - the address of the local receiver copy.
2. Reads the receiver’s dispatch-table reference and calls the entry at table offset 284, passing:
   - the receiver;
   - the value returned by F-9b9c1c7483f4.
3. Calls **F-8a5aadac202f** with the address of the second-argument temporary.
4. Reads the context reference from receiver offset 188 again.
5. Stores the one-byte value **0** at offset 24 of that context.

The zero-byte store occurs **after** both the receiver method and F-8a5aadac202f return normally.

Consequently, the function does not clear the byte before invoking that receiver method. Any value the method observes there depends on earlier state and dependency effects.

The value returned by the receiver method is not used by this body.

### Byte-setting branch

This branch is selected when either:

- F-6d70e45e29c9 returns nonzero; or
- F-6d70e45e29c9 returns zero and F-d53862ada031 returns zero.

The function then:

1. Reads the context reference from receiver offset 188.
2. Stores the one-byte value **1** at offset 24 of that context.
3. Reads the receiver’s dispatch-table reference.
4. Calls the entry at table offset 184, passing:
   - the receiver;
   - the 32-bit value **16**.

Unlike the byte-clearing branch, this branch performs its byte store **before** invoking its receiver method.

The value returned by that method is not used.

This branch does not call F-9b9c1c7483f4 or F-8a5aadac202f.

### Common completion

It then returns 1.

### Context reference changes during a dependency

Suppose the initial context reference is A, but an intervening dependency changes the receiver’s context field to B before the branch store.

The store targets B plus 24, not necessarily A plus 24. If another change occurs before the conditional predicate call, that predicate likewise receives the reference read at its own call site.

An implementation that caches the first context reference for all later operations would not preserve the established read behavior.

### Observing the byte from receiver methods

Assume all dependencies preserve the context reference and do not otherwise modify the byte:

- The offset-284 method runs before the function’s write of 0, so it may observe the prior byte value.

Without those preservation assumptions, neither observation is guaranteed.
