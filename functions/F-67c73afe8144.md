# F-67c73afe8144

## Purpose

The established behavior is a sequence of byte and 32-bit accesses and dependency calls. Descriptions such as “preparation,” “synchronization,” and “result” are inferred intent, not guarantees about the underlying subsystem.

The function has no explicit return value. Its observable results are object mutations, dependency calls, possible indirect dispatch, and whether execution returns or remains in the polling loop.

## Behavior

### Entry gate and initial mutation

The first operation is a byte read at the object base plus the unresolved gate offset.

If that byte is not exactly 1, the function returns immediately. In this case it makes no dependency call and performs none of its explicit writes.

If the byte equals 1, the function writes the byte value 1 at `0x245`. This write precedes the status-dependent preparation and every explicit dependency call.

The gate is not explicitly checked again.

### Status-dependent preparation

After writing `0x245`, the function reads the status byte at `0x264`.

If the status is nonzero, it skips the preparation described in this subsection and proceeds to F-338d16f9ce72.

If the status is zero, it calls F-da4eaf4d3b69 with the object base. The dependency’s result is tested only for equality to zero. No more specific interpretation of its return values is established.

#### Zero dependency result

When F-da4eaf4d3b69 returns zero, the function rereads the status byte.

If the reread is nonzero, it performs no further preparation calls and proceeds to F-338d16f9ce72.

If the reread remains zero, it examines the 32-bit word at `0x260`. Its range decision is equivalent to adding `0x99FFFFFC` modulo \(2^{32}\) and comparing the resulting unsigned value with 3.

Consequently:

- Values from `0x66000004` through `0x66000007`, inclusive, are retained.
- Every other 32-bit bit pattern causes the field to be overwritten with the unresolved replacement value.

This is a modular unsigned check, not a signed range check. For example, zero does not pass merely because it is small.

After any required replacement, the function obtains the word at `0x260` and passes it by value to F-d073470bb2d6. It then calls F-da37df53eacd with the object base and the value 1.

There is no explicit status recheck between those two calls. If F-d073470bb2d6 changes the status or other shared state, that alone does not suppress the subsequent call to F-da37df53eacd.

#### Nonzero dependency result

When F-da4eaf4d3b69 returns any nonzero value, the function also rereads the status byte.

If that byte remains zero, it reads the 32-bit word at `0x258` and passes that value to F-d073470bb2d6. This branch does not explicitly normalize `0x260` and does not call F-da37df53eacd.

If the status has become nonzero, neither of those preparation calls occurs.

The repeated status reads are behaviorally significant: the status observed before F-da4eaf4d3b69 is not reused as a substitute for the status after it.

### Synchronization and polling

Every entry-accepted path that reaches this stage calls F-338d16f9ce72 with the address of the object field at `0x230`.

After that call returns, the function captures the external base address. Earlier dependency calls can therefore affect which external address is captured. Once captured, that address is reused during this invocation; the supplied representation does not explicitly reload the external base inside the loop.

The function compares:

- The object byte at `0x22C`.
- The byte at external offset `0x1C`.

Both operands are needed for each comparison. The representation does not establish a strict evaluation order between the two operand reads.

If the bytes differ, the function reads the status byte:

- If status is nonzero, polling ends immediately and the alternate selection described below is used.
- If status is zero, F-162a41bac6a7 is called with the address at `0x238`, after which the comparison is repeated.

A status change made by F-162a41bac6a7 does not bypass the next byte comparison. The loop first reevaluates the comparison, then checks status if the bytes still differ.

The function contains no explicit timeout, iteration bound, delay, cancellation return, or error result. If the compared bytes continue to differ and every relevant status read yields zero, it can call F-162a41bac6a7 indefinitely.

The bytes at the captured external address remain live inputs. Capturing the address does not snapshot their contents.

### Output-byte selection

There are two ways to leave polling:

1. **The compared bytes are equal.** The function reads status again. Zero selects the byte at external offset `0x1E`; nonzero selects the byte at external offset `0x1F`.
2. **The compared bytes differ and status is nonzero.** The function selects the byte at external offset `0x1F` without a further explicit status check.

The selected byte is copied to object offset `0x22D`.

Thus equality by itself does not guarantee selection of `0x1E`. The status read following equality must also yield zero.

### Final dependency and conditional dispatch

After writing `0x22D`, the function calls F-b8a325ddd21b with the address at `0x238`.

Only after that call returns does it read the 32-bit pointer field at `0x230`. Changes made to that field by F-b8a325ddd21b can therefore affect the final dispatch decision.

The final decision is:

- A null pointer suppresses dispatch.
- A nonnull pointer is dereferenced for its first 32-bit word.
- A zero first word suppresses dispatch.
- A nonzero first word permits the indirect invocation.

The first word is a condition, not the established dispatch address. The indirect target comes from a separate unresolved location.

The representation shows no explicit source-level arguments for the indirect invocation. Its actual calling convention, implicit machine-state inputs, and target behavior are unknown. If it returns normally, F-67c73afe8144 then returns without another explicit operation.

These writes are not transactional. For example, `0x245` is already set if execution later remains in polling indefinitely.
