# F-2b7ea5004358

## Purpose

F-2b7ea5004358 is a single-target indirect-call wrapper. It obtains a table address from caller-supplied storage, selects the callable entry at byte displacement **296** from that address, invokes the selected target, and returns normally if that invocation returns normally.

The established behavior is dispatch, not a particular operation performed by the selected target. The supplied evidence does not identify what the target does, whether it modifies an object, or whether it returns a meaningful value.

A method-dispatch interpretation is plausible because the callable address is selected through an address stored in the input object. That interpretation is **inferred intent**, not an established object model. The contract does not require a named class, a complete virtual table, or any entries other than the one actually accessed.

The first integer-sized value at that location is used as the base address for a second access. The wrapper does not directly read additional fields from the input storage.

- Its address identifies the location of the first read.
- The value obtained by that read identifies the base from which the callable entry is selected.

These roles must not be conflated. The input pointer itself is not directly used as the dispatch-table base.

## Behavior

### Address resolution and dispatch

On the ordinary, valid execution path, the wrapper performs these observable actions in dependency order:

1. Reads the integer-represented base address from the beginning of the input storage.
2. Forms an entry address by adding 296 to that loaded value.
3. Reads a callable address from the resulting entry location.
4. Invokes that callable address once.
5. Returns if the invocation returns normally.

There is no evidenced alternative target, conditional branch, retry, or fallback invocation.

The second address depends on the value obtained by the first read. The selected target depends on the value obtained by the second read. Thus, choosing the target requires both reads; an implementation cannot replace this behavior with a fixed target unless equivalence is established outside this evidence.

No repeated read of the input storage or selected entry is shown after the target returns. In particular, the wrapper does not visibly redispatch because the target changed either location.

### Arithmetic constraints

The entry address is formed by adding the constant 296 to the loaded integer-represented base.

The evidence does not establish whether all possible input bit patterns produce meaningful addresses. It also does not establish:

- The exact width of the addition.
- Whether overflow wraps, traps, or lies outside the valid execution domain.
- How an integer value is extended or converted into an address.
- Whether address formation has architecture-specific constraints.

Consequently, the valid-input contract requires that the base and displacement produce an accessible entry address under the actual execution environment. Boundary behavior must not be specified by assuming unverified 32-bit wrapping or unrestricted pointer arithmetic.

### Conditions for normal execution

Normal completion requires, at minimum:

- The first read is permitted and yields a usable base representation.
- Adding the displacement produces an address suitable for the callable-address read.
- That second read is permitted.
- The resulting value identifies a callable target compatible with the invocation.
- The target returns normally.

These are execution preconditions, not checks performed by the wrapper.

The wrapper does not visibly validate the input pointer, table base, entry bounds, callable address, or target signature. It does not verify that the table has other entries or that the input belongs to a particular object type.
