# F-07a442f63e69

## Purpose

F-07a442f63e69 extracts three or four 32-bit words from a record selected by a signed index and a one-byte format discriminator. It writes the extracted words to caller-provided destinations and returns a 32-bit status.

Two formats are recognized:

- Format zero selects records with a 12-byte stride and writes three output words.
- Format one selects records with a 16-byte stride and writes four output words.

After writing the selected words, the function reads the second output as an unsigned 32-bit value. It returns status `3` if that value exceeds `0x00080000`; otherwise it returns status `0`. An unrecognized format also returns `3`, but without the record-output writes.

The supplied evidence establishes extraction, write ordering, and this post-write threshold check. It does not establish the semantic meanings of the records, their fields, or the threshold.

## Behavior

### Address basis

Before testing the discriminator, the function computes an address basis from the descriptor.

Let:

- **A** be the 32-bit field at descriptor offset `0x14`.
- **U** be the unsigned 32-bit field at descriptor offset `0x18`.
- **B** be the result of adding **A** to **U** with its low two bits cleared.

Clearing the low two bits uses the mask `0xfffffffc`. This affects only the contribution from **U**. It does not prove that **B**, or any eventual record address, is four-byte aligned: **A** may contribute nonzero low bits.

The two descriptor fields are read before discriminator-based rejection. The supplied expression does not establish which of these two field reads occurs first.

The recovered types indicate a 32-bit arithmetic model. Because the masked operand is unsigned, the addition has unsigned 32-bit characteristics before its result is held as a signed integer address intermediate. Exact behavior when that intermediate is outside the signed range, or when the resulting value is converted into a pointer, depends on implementation details not supplied here.

### Format selection

The discriminator is read and compared with zero.

- If that read yields zero, the function takes the three-word path.
- Otherwise, the supplied control flow contains another discriminator read and compares it with one.
- If that second read is not one, the function returns `3`.
- If that second read is one, the function takes the four-word path.

For stable descriptor memory, this recognizes exactly discriminator values zero and one.

The two discriminator evaluations must not be silently replaced in the contract with one immutable observation. The supplied source does not mark the descriptor volatile or provide synchronization, so actual load behavior and concurrent mutation semantics are not established.

### Format-zero record selection

For a signed index **n**, the displayed address calculation subtracts four times the signed quotient of `(12 × n + 28)` divided by four from **B**.

Where the signed intermediate arithmetic is representable, the numerator is a multiple of four. The record address is therefore:

**B − (12 × n + 28)**.

For example, under valid, representable arithmetic:

- Index zero selects the address 28 bytes before **B**.
- Index one selects the address 40 bytes before **B**.
- Index negative one selects the address 16 bytes before **B**.

The function then performs these ordered transfers:

1. Read the 32-bit word at the selected address and write it to the first output.
2. Read the 32-bit word four bytes after that address and write it to the second output.
3. Read the 32-bit word eight bytes after that address and write it to the third output.

There is no explicit access to the fourth output on this path.

### Format-one record selection

For a signed index **n**, the displayed address calculation subtracts four times the signed quotient of `(16 × n + 32)` divided by four from **B**.

Where the signed intermediate arithmetic is representable, this gives:

**B − (16 × n + 32)**.

For example, under valid, representable arithmetic:

- Index zero selects the address 32 bytes before **B**.
- Index one selects the address 48 bytes before **B**.
- Index negative one selects the address 16 bytes before **B**.

The function performs these ordered transfers:

1. Read the 32-bit word at the selected address and write it to the first output.
2. Read the 32-bit word four bytes after that address and write it to the second output.
3. Read the 32-bit word eight bytes after that address and write it to the third output.
4. Read the 32-bit word twelve bytes after that address and write it to the fourth output.

### Threshold decision

After all output transfers for the selected format, the function reads the second output destination.

This is a read of the destination’s current contents, not an established comparison against a separately retained copy of the second source word.

The comparison is unsigned and strictly greater than `0x00080000`:

- `0x00080000` is accepted.
- `0x00080001` is rejected.
- Values with the high bit set, including `0xffffffff`, are rejected.

A threshold rejection does not undo any completed output writes.

### Index and arithmetic boundaries

No explicit restriction to nonnegative indices is present. A negative index participates in the same arithmetic and can select an address nearer to, at, or beyond **B**.

This does not establish that such an address belongs to a valid allocation.

The simplified address formulas apply only where their signed intermediate operations are representable. Large positive or negative indices can exceed signed 32-bit limits during multiplication, addition, or the subsequent arithmetic. The evidence does not justify treating every such case as safe wraparound record indexing.

## Side effects

### Output mutation

For stable, valid, nonoverlapping memory:

- Format zero writes three 32-bit outputs.
- Format one writes four 32-bit outputs.
- An unsupported format writes none of them.
- A threshold failure occurs after the applicable writes.

Callers must therefore not interpret return value `3` as “outputs unchanged.”

### Aliasing and overlapping storage

No overlap checks are visible.

Output destinations may designate the same writable 32-bit object where the environment’s access rules permit it. In that case, later writes overwrite earlier writes. If the second output aliases a destination written later, the threshold check observes the later value.

Record reads and output writes are interleaved rather than visibly staged as a complete record snapshot. If an output store modifies a record word that has not yet been read, a later transfer can observe the modified word.

The address basis and record pointer are calculated before the output transfers. Overwriting descriptor fields during those transfers does not cause a visible recalculation of the selected record address.

These aliasing consequences are conditional on the relevant accesses being valid. The evidence does not establish supported semantics for arbitrary partial-byte overlaps, misaligned pointers, concurrent mutation, or accesses that violate the environment’s memory rules.

### Ownership and persistent state

No allocation, release, ownership transfer, callback, or named global-state access is visible.

The function accesses memory through the descriptor, derived record address, and output pointers. That memory can belong to caller-managed persistent state; the function does not identify its ownership.

The first argument has no visible effect.

## Acceptance examples

These are conditional acceptance criteria derived from the supplied static evidence, not executed tests.

### Three-word success at the inclusive threshold

Given a stable format-zero descriptor, a valid index, representable address arithmetic, and separate output destinations, suppose the selected record contains:

- First word: `0x11223344`
- Second word: `0x00080000`
- Third word: `0xaabbccdd`

The function writes those three values in order and returns `0`. It performs no explicit fourth-output access.

### Four-word success

Given format one and a valid selected record whose second word is `7`, the function writes all four source words to their respective separate destinations before returning `0`.

The fourth word is transferred but is not independently threshold-checked.

### Threshold failure preserves writes

Given either recognized format, separate outputs, and a second source word of `0x00080001`, all applicable output transfers occur. The function then returns `3`. The transferred outputs remain written.

### Unsupported format still requires descriptor-field reads

Given a stable discriminator of `2`, valid descriptor-field accesses, and address arithmetic that completes, the function returns `3` without selecting or reading record words and without writing outputs.

This path still reads the descriptor fields at offsets `0x14` and `0x18` before rejecting the format. An unsupported discriminator does not by itself make an otherwise unreadable descriptor safe.

### Later output alias changes the checked value

Given format zero, let the second and third output destinations be the same valid 32-bit object. Let the source’s second word be `0x00080001` and third word be `1`, with source storage otherwise unaffected by the output writes.

The shared output first receives `0x00080001`, then receives `1`. The final threshold read sees `1`, so the function returns `0`.

Conversely, a small second source word followed by a third source word of `0x00080001` at the same shared destination produces return value `3`.

### Masked descriptor bits

For two otherwise identical executions, changing only the low two bits of the descriptor field at offset `0x18` leaves its masked contribution unchanged. Subject to stable memory and valid arithmetic, the selected record address is unchanged.

### Negative index

For format one and index negative one, the record begins 16 bytes before **B**, provided the arithmetic is representable and that location is readable. There is no separate rejection merely because the index is negative.
