# F-590cfb250a48

## Purpose

F-590cfb250a48 performs conditional shared-object initialization before classifying a request by a family discriminator and selector.

For a matching family, it calls two export-related dependencies and stores the second dependency’s 32-bit result through the caller’s output pointer. Six recognized selectors additionally select an embedded data reference and trigger a preparation-related call sequence. Other selectors skip that sequence but still reach the export-related calls.

The Boolean return indicates family-and-selector recognition on normal completion. It does not indicate whether initialization occurred, whether an output was written, or whether a dependency succeeded.

Formatting and text-to-value conversion are inferred purposes of the dependency calls. The supplied representation does not establish that any dependency writes the shared buffer, reads its contents, or derives the output value from those contents.

## Behavior

### Initialization precedes family classification

The function first obtains the shared guard reference and tests bit zero of the referenced value.

If that bit is set, it skips the acquisition call, initialization-related argument reads, object writes, initializer call, and completion call.

If the bit is clear, it calls F-b255b26284e6 with the guard reference read for that call. After the call returns, it reads the 32-bit initialization argument and captures the shared object reference, in that order. These two reads occur even when the acquisition result is zero.

A zero acquisition result suppresses the initialization writes and the two remaining initialization calls. Request classification still follows.

A nonzero acquisition result permits these effects, in order:

1. A 32-bit write of the initialization word at offset zero through the shared object reference read for that write.
2. A 32-bit zero write at offset four through the previously captured object reference.
3. A call to F-804adc29bbfb with the captured object reference, the initialization reference, and the captured 32-bit argument.
4. A call to F-d08d3ca17b81 with the shared guard reference read after F-804adc29bbfb returns.

The first object write uses a shared-reference access distinct from the earlier capture. No dependency call intervenes between that capture and the two writes, but the excerpt supplies no concurrency contract that would make externally changing shared references safe.

The guard reference is not retained as an invocation-wide snapshot. In particular, F-804adc29bbfb may change the shared guard reference. F-d08d3ca17b81 then receives its newly read value, not necessarily the reference previously passed to F-b255b26284e6 or used for the initial bit test.

The initializer’s return value is not tested. Its normal return is followed by the completion call without a local success condition.

This resembles guarded one-time initialization. Locking, publication, memory ordering, and the dependencies’ guard mutations are not established.

### Family mismatch

Only after initialization handling does the function compare the supplied family discriminator with the embedded four-byte value.

A mismatch causes a false return without:

- Selector-specific preparation calls.
- Prefix handling.
- Export-related calls.
- A direct write through the output destination.

Initialization effects may already have occurred. The absence of a direct output write is not a guarantee that earlier dependencies could not modify aliased output storage.

### Recognized-selector preparation

For a matching family, each of the six recognized selectors chooses a distinct embedded data reference. Recognition establishes the Boolean result as true.

The following calls then occur in order:

| Order | Dependency | Arguments |
|---|---|---|
| 1 | F-9d0ecc5f6adf | No explicit arguments |
| 2 | F-682adfd5a561 | The preceding result and `0x80` |
| 3 | F-9b45bb70831a | No explicit arguments |
| 4 | F-5f48d80484be | Shared buffer reference, `0x32`, selected embedded reference, context plus `0x18`, and the preceding result |

The result of F-682adfd5a561 is unused. The result of F-5f48d80484be is also unused. Neither controls the recognition Boolean or gates subsequent export-related calls.

The buffer reference supplied to F-5f48d80484be is read after the preceding preparation calls. It is not necessarily the value present at function entry.

The literal `0x32` is decimal 50. Its position suggests a size-related argument, but no bound, termination, truncation, or buffer-write guarantee is established. Likewise, `0x80` is an established argument, not an established flag meaning.

An unsupported selector leaves recognition false and skips all four calls. It does not skip the remaining matching-family processing.

### Prefix-dependent pointer selection

After the optional preparation sequence, the function obtains the shared text-buffer reference for use as a downstream argument.

For selector `0x2D01` or `0x2D05`, it checks whether the first byte at the shared buffer reference is ASCII `'0'`. If so, the downstream text pointer is the buffer reference advanced by one byte. Otherwise, the unadvanced pointer is used.

This is a pointer adjustment, not a direct buffer edit:

- A leading pair of zero characters causes only the first to be skipped.
- A zero character followed by a terminator causes the adjusted pointer to address that terminator.
- A leading space, sign, terminator, or other nonzero character does not trigger adjustment.
- The other four recognized selectors retain the unadvanced pointer.
- Unsupported selectors retain the unadvanced pointer where the represented arithmetic is defined.

The buffer reference is accessed again after the optional preparation calls. F-5f48d80484be need not preserve it. The excerpt also contains separate shared-reference accesses for obtaining the downstream pointer, testing the first byte, and forming the adjusted pointer. Without a concurrency contract, these must not be treated as an atomic snapshot.

For selectors other than `0x2D05`, the condition includes a represented signed subtraction of `0x2D00` from the selector. Where that arithmetic is defined, equality to one identifies `0x2D01`. Selector `0x2D05` bypasses that subtraction.

Every matching-family path that reaches this stage performs:

1. F-151ab4bfe553 with the shared object reference and selected text pointer.
2. F-44362605ab79 with the shared object reference read for this later call.
3. A 32-bit store of F-44362605ab79’s result through the output destination.

The two object arguments need not be identical. F-151ab4bfe553 may change the shared object reference, and the later call uses the subsequently read reference.

For an unsupported selector, no selector-specific preparation call occurs, but the current buffer reference is still passed downstream. This does not establish that either export-related dependency examines that buffer or that the stored result depends on its contents.

### Integer arithmetic

Context plus `0x18` is evaluated only for recognized selectors. The selector subtraction is evaluated for every matching-family selector except `0x2D05`, including unsupported selectors.

Both are represented as signed integer arithmetic. No portable wraparound guarantee is established. At arithmetic extremes, the excerpt is insufficient to promise the subsequent calls, write, or return.

## Acceptance examples

These are conditional criteria from static evidence, not executed tests. Unless otherwise stated, memory accesses are valid, relevant arithmetic is defined, dependencies return normally, and shared references remain stable except for explicitly described changes.

1. **Family mismatch with initialization skipped.**  
   If guard bit zero is set and the family mismatches, the function returns false, calls none of the listed dependencies, and performs no direct output write.

2. **Initialization before rejection.**  
   If the guard bit is clear and acquisition returns nonzero, the two object writes, initializer call, and completion call precede rejection of a nonmatching family.

3. **Zero acquisition result.**  
   If acquisition returns zero, the initialization argument and object reference are nevertheless read. The object writes, initializer, and completion call are skipped. Family handling continues.

4. **Guard-reference replacement.**  
   If the initializer replaces the shared guard reference, the completion call receives the replacement reference. Acceptance must not require reuse of the acquisition argument.

5. **Recognized selector without prefix adjustment.**  
   With a matching family and selector `0x2D02`, the four preparation calls occur in order. If the buffer begins with `"012"` at export preparation, F-151ab4bfe553 receives the unadvanced pointer. Normal completion stores the later dependency result and returns true. This criterion does not require F-5f48d80484be to have written those bytes.

6. **Exactly one zero skipped.**  
   With a matching family, selector `0x2D01`, and buffer bytes representing `"007"` at the prefix check, the downstream pointer addresses the second zero, not the seven. The function itself does not rewrite those bytes.

7. **Zero followed by a terminator.**  
   With a matching family, selector `0x2D05`, and a zero character immediately followed by a terminator, the downstream pointer addresses the terminator. No particular interpretation of that pointer’s contents is required of F-151ab4bfe553.

8. **Unsupported selector still reaches export.**  
   With a matching family and selector `0x2D07`, the four preparation calls are skipped. The unadvanced buffer pointer is passed to F-151ab4bfe553, the subsequent 32-bit result is stored, and the function returns false. No relationship between buffer contents and that result is asserted.

9. **Object-reference replacement during export.**  
   If F-151ab4bfe553 replaces the shared object reference, F-44362605ab79 receives the replacement. Its result is the value stored through the output destination.
