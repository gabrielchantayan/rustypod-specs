## Behavior

The represented body contains no explicit conditional branch or loop. Its input-dependent calculations select addresses and arguments rather than alternative visible paths.

1. Payload writes 1 through 12.
2. The two-byte sample.
3. Payload writes 13 and 14.
4. The four-byte replacement at the storage address.
5. Payload writes 15 through 18.

Dependency interactions occur before the first write, between the numbered writes, and after the last write. The direct-memory ordering is not permission to omit or move those interactions.

The sequence does not guarantee progress. An invocation may not return; an access or control transfer may prevent subsequent effects. No rollback or compensation is established.

### Payload destinations

Every numbered payload write supplies the same represented eight-bit entry payload. A primary result used to select a destination is not substituted for that payload.

There are three destination rules:

- Write 1 uses the storage-address number multiplied by 256.
- Write 8 uses the retained word multiplied by 2,048.
- Each other write uses its own selected primary result multiplied by eight.

The calculations produce numerical addresses, not offsets relative to the storage address. None requires reading the contents at the storage address.

Write 8 is exceptional: the result of the interaction immediately before it is not its destination selector. The earlier retained word remains the selected source.

The separate primary results need not be equal. Conversely, neither their different origins nor their event numbers guarantee different destinations.

### Arguments associated with payload writes

For most payload writes, the immediately following interaction receives two equal explicit arguments:

- After write 1, each argument is the storage-address number multiplied by 524,288.
- After write 8, each argument is the retained word multiplied by 4,194,304.
- After writes 2–5, 7, 9–11, 15, 16, and 18, each argument is that write’s selected primary result multiplied by 16,384.

These argument values are calculated from the identified selectors. They are not obtained by reading back the payload destinations.

The exceptions are behaviorally significant:

- After writes 6, 13, and 17, the next interaction has no explicit arguments represented.
- After write 12, the two-byte sample supplies the next interaction’s single explicit argument.
- After write 14 and the four-byte replacement, the next interaction receives three equal copies of the saved product.

### Retained state and other forwarding

The retained word is captured during dependency processing after write 1. It later selects write 8’s destination and the equal argument pair following that write.

It also supplies the unscaled second argument of four mixed-argument interactions: one between writes 8 and 9, one between 9 and 10, one between 10 and 11, and one between 11 and 12. Each first argument is four times a separately selected primary result.

The retained word is not explicitly refreshed from the storage address before these uses. A newer primary result or auxiliary word must not replace it merely because that value was produced more recently. No further use of the retained word is established after the fourth mixed interaction.

Other dependency interactions repeatedly forward four times selected primary results, ordinarily as a single explicit argument. Such forwarding occurs both before the first payload write and after the eighteenth.

Seven separate interactions forward an associated opaque four-byte auxiliary word as one explicit argument. They occur between writes 1–2, 2–3, 3–4, 4–5, 7–8, 15–16, and 16–17. The seven words are not established to be equal, and they must not be conflated with primary results or the retained word.
