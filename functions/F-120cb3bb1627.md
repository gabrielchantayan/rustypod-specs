# F-120cb3bb1627

## Purpose

F-120cb3bb1627 conditionally calls two dependencies, writes the second dependency’s four-byte result to a retained destination, and returns a four-byte value read from that destination.

The branch decision and destination selection derive from **separate evaluations of a global expression**. Their derivations are not interchangeable:

- The first global value is assigned to a signed integer local. The **retained base** is the value **after that assignment and any conversion it entails**.
- The second global value participates directly in the expression used to locate the initial zero test.

An unchanged global does **not**, by itself, establish that the test and destination addresses coincide. That conclusion additionally requires value preservation through the first assignment and equivalent address calculations, including the meaning of adding 4 and converting the results to addresses.

If the initial test reads zero, the function calls F-8157a180d901 and then F-17b7a7305420, stores the latter’s four-byte result through the retained base, and reads the destination for return. Otherwise, it skips both calls and the store but still reads the retained destination for return.

**Inferred intent:** when the two address derivations identify the same field, this resembles lazy initialization. It is not an established initialize-once mechanism: zero results are stored, no synchronization is visible, and the test and destination need not coincide.

## Behavior

### Selection of the test and destination

The first global evaluation is assigned to signed integer storage. All subsequent destination accesses derive from the resulting retained value, not necessarily from the original global value before conversion.

The global expression is then evaluated again to derive the test address. This derivation does not pass through the retained local.

The function reads the test field and selects its path according to whether that read equals zero. There is no comparison between the two global values, no comparison between their derived addresses, and no check that the first assignment preserved the original value.

Thus, even when the global does not change, equivalence of the test and retained locations remains conditional on conversion and address arithmetic. Conversely, address coincidence is possible without proving that the two original global evaluations were identical.

### Nonzero-test path

When the initial test reads nonzero:

- Neither dependency is called.
- No direct field store is performed.
- A four-byte read is made from the retained address.
- That final read supplies the return payload.

The test result is not itself returned.

If the two access regions differ, a nonzero test can be followed by a zero return. Even if they coincide, the test and final return remain distinct source-level reads. The representation does not establish whether external changes between those reads are supported or observable.

The retained field is not required to contain a nonzero value merely because the function takes this path.

### Zero-test path

When the initial test reads zero, F-8157a180d901 is called with 160. If it returns normally, F-17b7a7305420 is called with no explicit arguments.

After the second dependency returns normally, its four-byte result is written to the retained address. A subsequent four-byte read from that address supplies the normal return.

No result from F-8157a180d901 is consumed by this function. This does not establish whether that dependency has a meaningful return value elsewhere.

There is no second test before the store. A dependency’s intervening change to either field does not cause this function to reconsider its branch or skip its direct write.

Every four-byte result from F-17b7a7305420, including zero, is stored without a visible success check, normalization, or replacement.

The destination is not refreshed from the global after either call. Changing the global alone therefore does not redirect this invocation’s store or final read. However, a dependency may still change, release, invalidate, or otherwise affect memory reached through the retained value; no preservation guarantee is available.

The retained field need not initially be zero. A zero test through one address can cause a nonzero value at a different retained address to be overwritten.
