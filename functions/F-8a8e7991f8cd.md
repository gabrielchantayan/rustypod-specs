# F-8a8e7991f8cd

## Purpose

F-8a8e7991f8cd configures a selected record in one of two banks. It classifies two endpoint operands through F-afd2ad8e8485, writes direct or table-resolved endpoint values, optionally populates an auxiliary record, writes an auxiliary link, updates a control word, and publishes status.

Established behavior includes two accepted bank selectors, four accepted classifications, success result 0, and rejection result 19. Classification determines which operands are direct values and which are table indices.

**Inferred intent:** the function appears to configure endpoint pairs and optionally construct a self-referencing descriptor. The resource type, hardware semantics, and meanings of individual control bits are not established.

## Interface

| Position | Contract name | Representation and use |
|---|---|---|
| 1 | First endpoint | Unsigned 32-bit operand; interpreted as a direct value or table index according to classification. |
| 2 | Second endpoint | Unsigned 32-bit operand; interpreted independently as a direct value or table index. |
| 3 | Requested control value | Unsigned 32-bit value. Its only retained contribution is an initially computed logical right shift, subsequently masked to 12 bits. |
| 4 | Auxiliary-enable flag | Signed 32-bit value; zero disables preparation, every nonzero value enables it. |

The 32-bit return value is:

- **0:** the accepted path completes its final status write.
- **19**, or **0x13:** unsupported bank selector or unsupported classification.

There is no explicit error result for inaccessible memory, invalid indices, misalignment, or arithmetic overflow.

## Behavior

### Bank selection and initial control contribution

Selectors other than 1 or 2 return 19 before the selected-record accesses or dependency call.

For an accepted selector, the function forms the selected endpoint and metadata addresses and captures the selected status base. It reads the selected control word and extracts bits 21–23:

\[
s=(\text{initial control}\mathbin{\&}\text{0x00E00000})\gg21
\]

The resulting shift count is between 0 and 7. Before calling the dependency, it computes:

\[
q=\text{requested control value}\gg s
\]

This is an unsigned logical shift. The final update uses only \(q\mathbin{\&}\text{0xFFF}\).

The original requested control value never survives as a separate, unmasked contribution on an accepted path. That separate contribution is replaced by either zero or 0x08000000. Later control changes do not cause \(q\) to be recomputed.

### Classification and base-capture schedule

F-afd2ad8e8485 is called once with the original first and second endpoint operands, in that order.

Only classifications 0x0000, 0x0800, 0x1000, and 0x1800 are accepted. Rejection is not immediate upon return from the dependency: several global base reads occur first.

The following notation distinguishes independently observed base values:

- \(V_{\mathrm{early}}\): the value-table base captured immediately after the dependency returns.
- \(T_{\mathrm{default}}\): the next attribute-table base capture, used to derive the default-attribute address.
- \(T_{\mathrm{second}}\): a separate attribute-table base capture on every nonzero classification.
- \(T_{\mathrm{first}}\): another attribute-table base capture on every nonzero classification except 0x0800.

For bank selector \(b\), these captures establish the attribute addresses:

\[
D=T_{\mathrm{default}}+4b+\text{0xDC}
\]

\[
S=T_{\mathrm{second}}+8(\text{second endpoint})+4b-4
\]

\[
F=T_{\mathrm{first}}+8(\text{first endpoint})+4b-4
\]

The capture sequence is:

| Classification | Ordered post-dependency base captures |
|---|---|
| 0x0000 | \(V_{\mathrm{early}}, T_{\mathrm{default}}\) |
| 0x0800 | \(V_{\mathrm{early}}, T_{\mathrm{default}}, T_{\mathrm{second}}\) |
| 0x1000 | \(V_{\mathrm{early}}, T_{\mathrm{default}}, T_{\mathrm{second}}, T_{\mathrm{first}}\) |
| 0x1800 | \(V_{\mathrm{early}}, T_{\mathrm{default}}, T_{\mathrm{second}}, T_{\mathrm{first}}\) |
| Any unsupported classification | \(V_{\mathrm{early}}, T_{\mathrm{default}}, T_{\mathrm{second}}, T_{\mathrm{first}}\), then return 19 |

Every unsupported classification is nonzero, because zero is accepted.

These are **base reads and address derivations**, not attribute-entry loads. All listed attribute-base captures occur before endpoint writes. Some derived addresses are never dereferenced: classification 0x1000, for example, derives \(S\) but does not load its entry.

An unsupported classification performs no endpoint-value or attribute-entry loads and no configuration writes from this body. It nevertheless performs the listed base-global reads. Dependency side effects are not rolled back.

### Endpoint writes and table snapshots

A direct endpoint is the original operand with bit 31 cleared. A resolved endpoint is the complete 32-bit value loaded from its selected value-table entry; resolved values are not masked.

Every accepted classification writes the first endpoint before the second.

| Classification | First endpoint written | Second endpoint written |
|---|---|---|
| 0x0000 | First operand AND 0x7FFFFFFF | Second operand AND 0x7FFFFFFF |
| 0x0800 | First operand AND 0x7FFFFFFF | Resolved second endpoint |
| 0x1000 | Resolved first endpoint | Second operand AND 0x7FFFFFFF |
| 0x1800 | Resolved first endpoint | Resolved second endpoint |

The value-table base used by each resolution is significant:

- **0x0000:** no value-table entry is loaded. \(V_{\mathrm{early}}\) is still captured.
- **0x0800:** after writing the first endpoint, the function reads the value-table base global again. The second endpoint is loaded from that fresh base plus four times the original second operand. \(V_{\mathrm{early}}\) is unused.
- **0x1000:** before writing the first endpoint, the function reads the value-table base global again. The first endpoint is loaded from that fresh base plus four times the original first operand. The direct second endpoint is then written. \(V_{\mathrm{early}}\) is unused.
- **0x1800:** the first endpoint uses a fresh value-table base read, followed by its table-entry load and endpoint write. The second endpoint then uses \(V_{\mathrm{early}}\), not another fresh base read.

These distinctions remain relevant if an endpoint write aliases the value-table base global. The indexing operand is the original unsigned 32-bit endpoint operand; clearing bit 31 applies only to direct endpoint values, not to table indices.

### Attribute loads and control contributions

Attribute-entry loads occur after both endpoint writes. Their order and reuse are:

| Classification | Attribute-entry load order | First status attribute | Second status attribute |
|---|---|---|---|
| 0x0000 | \(D\), once | Loaded default | Same loaded default |
| 0x0800 | \(D\), then \(S\) | Default | Second endpoint attribute |
| 0x1000 | \(F\), then \(D\) | First endpoint attribute | Default |
| 0x1800 | \(F\), then \(S\) | First endpoint attribute | Second endpoint attribute |

The base captures underlying \(D\), \(S\), and \(F\) may differ. An endpoint write that changes an attribute-base global does not retarget these already-derived addresses. An endpoint write that changes an attribute entry can affect the subsequent entry load.

The selected control contributions are:

| Classification | Mode contribution | Separate fixed contribution |
|---|---|---|
| 0x0000 | 0x04000000 | 0x08000000 |
| 0x0800 | 0x04000000 | 0 |
| 0x1000 | 0 | 0x08000000 |
| 0x1800 | 0 | 0 |

Only the low four bits of each loaded attribute contribute to final status.

### Optional auxiliary preparation

A zero auxiliary-enable flag skips auxiliary preparation. Every nonzero value, including a negative value, enables it.

After the endpoint writes and attribute-entry loads, the enabled path reads the auxiliary base and forms:

\[
A=\text{auxiliary base}+128(b-1)+16j
\]

The record occupies four 32-bit fields:

| Offset from \(A\) | Stored value |
|---|---|
| +0 | First endpoint read back from selected endpoint storage |
| +4 | Second endpoint read back from selected endpoint storage |
| +8 | Address \(A\), represented in a 32-bit address-bearing field |
| +12 | Selected control word read before the final update |

The explicit preparation order is:

1. Read the selected control word and write it at \(A+12\).
2. Read the second endpoint word and write it at \(A+4\).
3. Read the first endpoint word and write it at \(A\).
4. Write \(A\) at \(A+8\).

These are storage readbacks, not reuse of previously calculated endpoint values. Earlier writes, aliasing, or external mutation can affect the copied data. The auxiliary control snapshot can differ from the initial control used to compute \(q\).

When disabled, the auxiliary base is not needed by this path and no auxiliary-record words are written.

### Link, control, and status publication

After optional preparation, the function writes the selected auxiliary-link word:

- \(A\), when enabled.
- Zero, when disabled.

It then rereads the selected control word and reads the global preservation mask for the final control update:

\[
\begin{aligned}
\text{new control}={}&
(\text{current control}\mathbin{\&}\text{preservation mask})\\
&\mathbin{|}(q\mathbin{\&}\text{0xFFF})\\
&\mathbin{|}\text{mode contribution}\\
&\mathbin{|}\text{separate fixed contribution}
\end{aligned}
\]

The relative order of the current-control and mask reads within this expression is not established. Both belong to the update after the link write.

There is no independent clearing of the low 12 bits. If the preservation mask retains low bits, those bits remain set through the OR operation even where the shifted request contributes zero.

The final explicit write is the selected status word:

\[
\text{status}=
\text{classification}
\mathbin{|}((\text{second attribute}\mathbin{\&}15)\ll6)
\mathbin{|}((\text{first attribute}\mathbin{\&}15)\ll1)
\mathbin{|}\text{0x8001}
\]

This uses the original accepted classification, not its substituted control contribution. The function then returns 0.

## Side effects

On an accepted classification, the explicit write order is:

1. First endpoint.
2. Second endpoint.
3. Auxiliary offsets +12, +4, +0, and +8, if enabled.
4. Auxiliary link.
5. Control.
6. Status.

This is the supplied body’s ordering, not a verified processor- or bus-level trace.

No allocation, release, bulk clearing, locking, retry, rollback, or recovery is visible. Storing the auxiliary address as a self-reference and link does not establish ownership transfer or authorize deallocation.

The dependency may have additional side effects. No assumption is made that it preserves globals, maintains storage validity, or owns or releases memory.

Aliasing is not excluded. Consequently, earlier writes can affect later table loads, endpoint readbacks, control reads, or global-base reads. The function does not establish atomic publication of the record as a whole or synchronization with concurrent observers.
