# F-8bd6630341c0

## Purpose

F-8bd6630341c0 classifies a 32-bit input using binary32-style sign and exponent fields. For positive, finite, nonzero inputs, it constructs two result words through a fixed sequence of dependency calls and writes both results to caller-provided destinations. For all other inputs, it writes one result word and returns a different status.

The established contract is a bit-level classification, dependency-call, and output-store contract. The dependency implementations and two referenced data words are unavailable. A complete numerical interpretation is therefore not established.

The input decomposition and paired outputs suggest a numerical reduction routine, but that interpretation is inferred intent, not a substitute for the observable behavior below.

## Behavior

### 1. Initial classification

Classification is performed on the input word’s bits, before any numerical conversion is established.

The relevant fields are:

- Sign: bit 31.
- Exponent field: bits 30 through 23.
- Fraction field: bits 22 through 0.
- Magnitude bits: the low 31 bits.

The function checks these classes in order:

1. Exponent field all ones, except the exact word `0xFF800000`.
2. Either signed zero.
3. Positive, finite, nonzero values.
4. Remaining negative values, including `0xFF800000`.

Under the conventional binary32 interpretation, the first class contains positive infinity and all NaN encodings of either sign. Negative infinity is deliberately excluded from that first class.

This interpretation does not establish that signaling and quiet NaNs are treated differently. The visible branch does not distinguish them.

### 2. All-ones exponent, excluding negative infinity

3. Store that word through the first output destination.

The second dependency argument is the integer word `0x00000001`, not the binary32 representation of 1.0.

### 4. Positive, finite, nonzero input

This path is entered when the input is neither in the first exceptional class nor zero, and its sign bit is clear.

#### Exponent extraction and optional normalization

Extract the exponent field from the current input word as an unsigned 32-bit quantity.

If that field is nonzero, retain the input word unchanged and use the extracted exponent as the exponent working value.

If that field is zero:

1. Call **F-f2b8ff34d9f0** with the original input word and the integer word **32**, represented as `0x00000020`.
2. Replace the working input word with the dependency’s returned word.
3. Extract the exponent field from this replacement word.
4. Subtract 32 using unsigned 32-bit arithmetic to obtain the exponent working value.

No visible validation confirms that the replacement word is positive, finite, nonzero, or normalized. Subsequent operations use its bits as returned.

For a conventional binary32 input, this optional call is reached by positive subnormals. Whether the dependency actually performs the normalization suggested by this structure remains unknown.

#### Construction of dependency arguments

- Retaining the current input word’s low 30 bits.
- Setting every bit selected by `0x3F800000`.

The resulting word has sign zero, exponent field 127, and the current input word’s low 23 fraction bits. Under binary32 interpretation, it lies in the interval from 1.0 inclusive to 2.0 exclusive.

Next, subtract 127 from the exponent working value using unsigned 32-bit arithmetic. Pass that resulting 32-bit word to **F-1c7710595b35**.

The arithmetic is significant: subtraction can wrap modulo \(2^{32}\). For an ordinary input whose exponent field is 126, the word passed is `0xFFFFFFFF`, not an established signed mathematical argument of −1. A signed interpretation may be intended by the dependency, but is not proven here.
