# F-c5e54c1c1864

## Purpose

F-c5e54c1c1864 provides a mode-dependent operation with two distinct behaviors:

- In the ordinary mode, it checks whether an unsigned input selects an enabled entry in a 256-byte table. If enabled, it writes the input value as one byte to the supplied destination and returns the 32-bit value `0x00000001`. Otherwise, it returns `0xffffffff` without performing that destination write.
- When a control byte is exactly `0x01`, it calls a dynamically computed executable address with the three original arguments and returns that call’s 32-bit result.

The ordinary branch resembles byte validation or filtering. That purpose is inferred from the table lookup and one-byte output; the available evidence does not establish an encoding, character set, or application-level meaning.

This contract describes static behavior only. No runtime tests have been performed.

## Behavior

### Common entry sequence

Every invocation begins by calling F-2a4c402ba617 without arguments.

After that call returns, F-c5e54c1c1864 reads the 32-bit word at the returned address and uses its value as the base address. It then reads the byte at base offset `0x101`.

These operations precede the ordinary input range check. Consequently, an out-of-range input does not bypass the dependency call, the base-word read, or the mode-byte read.

The function does not visibly validate either the dependency’s returned address or the base address obtained from it.

### Delegated mode

A mode-byte value of exactly `0x01` selects delegation. Other nonzero values do not select it.

In this mode, the function reads the four-byte displacement at base offset `0x107` and computes an executable address from:

- The base address.
- The signed 32-bit displacement.
- An additional offset of `0x107`.
- A final mask of `0xfffffffc`, which clears the lowest two address bits.

Where the recovered signed additions are defined, the resulting address is the 32-bit sum of those components with its lowest two bits cleared. Thus, the final operation aligns the computed address downward to a four-byte boundary.

The computation identifies the executable address itself. It does **not** establish a further read of a stored function pointer at that computed address.

The function calls this address with the destination, input, and auxiliary value, in their original order and without a visible transformation. It returns the callback’s result without applying the ordinary-mode success or rejection rules.

In particular, delegated mode:

- Does not apply the ordinary `input < 256` restriction.
- Does not perform the ordinary eligibility-table read.
- Does not visibly perform the ordinary destination-byte write.
- Does not constrain the callback’s returned bit pattern.

Any destination access, global mutation, resource operation, or error behavior performed by the callback remains behavior of that unknown dependency.

The displacement read starts at offset `0x107`, which is not itself a multiple of four. Whether the actual access is aligned depends on the base address. The supplied representation does not establish alignment enforcement or fault handling.

### Ordinary mode

Any mode-byte value other than `0x01` selects the ordinary branch.

The function first compares the unsigned 32-bit input against `0x100`.

If the input is `0x100` or greater:

- It does not read an eligibility-table entry.
- It does not perform the destination-byte write.
- It returns `0xffffffff`.

If the input is less than `0x100`, it reads the byte at the base address plus the input.

A zero table byte causes rejection:

- No destination-byte write is performed.
- The return value is `0xffffffff`.

Any nonzero table byte causes success:

- The input is stored as one byte at the destination.
- The return value is `0x00000001`.

The table byte is a Boolean eligibility value, not an output translation value. For example, an input of `0x41` with a table entry of `0x7e` produces an output byte of `0x41`, not `0x7e`.

All ordinary-mode accepted inputs are already within the range `0x00` through `0xff`. No higher input bits are discarded to make an otherwise out-of-range input acceptable.

### Observable access order

Excluding effects internal to dependencies, the established order is:

1. Call F-2a4c402ba617.
2. Read the base-address word through its returned address.
3. Read the mode byte.
4. Perform the selected branch:
   - Delegated: read the displacement, call the computed address, and return its result.
   - Ordinary with out-of-range input: return rejection.
   - Ordinary with in-range input: read the selected table byte, then either reject or write the destination byte and return success.

The base word is not visibly reread after the mode-byte access. The mode byte is not visibly reread after a table lookup or callback call.

This sequence is not a synchronization guarantee. Atomicity, volatile-access behavior, and concurrent mutation semantics are not established.

## Side effects

### Direct effects

The only explicit memory write in the visible ordinary branch is the successful one-byte destination write.

The function does not visibly:

- Clear the destination on rejection.
- Write a string terminator.
- Update the eligibility table or mode field separately from the destination write.
- Allocate or release memory.
- Retain an argument in persistent storage.

The destination is not checked for nullness or writability before ordinary-mode success. A valid writable byte is therefore a precondition for defined successful execution.

On an ordinary rejection path, the visible function body does not dereference the destination. This is narrower than a guarantee that an invalid destination is safe for every invocation: delegated mode forwards it to unknown code, and the entry dependency has independently unknown effects.

### Aliasing

No non-aliasing restriction is established.

If the destination overlaps the table, mode byte, base-address word, or other writable storage, ordinary success writes that overlapping byte. The table and mode reads needed for the current decision have already occurred before the write.

Such an aliasing write may affect later invocations. There is no visible restoration step.

### Ownership and dependency effects

No ownership transfer is explicit in the ordinary branch. The base storage is read but not visibly released.

Effects of F-2a4c402ba617 and the computed callback are not bounded by the visible body. They must not be assumed to preserve globals, avoid allocation, preserve pointed-to storage, or refrain from acquiring or releasing resources.

## Uncertainties

- **Byte order:** A four-byte displacement read is established; its byte-level endianness is not independently established.
- **Memory faults:** No local recovery is visible for invalid base storage, invalid table storage, an unwritable destination, or an invalid callback target.
- **Concurrency:** There is no established lock, atomic snapshot, or protection against storage changing during execution.
- **Dependency behavior:** Neither dependency may be assumed pure, non-failing, or ownership-neutral.
- **Application meaning:** The table’s purpose and the auxiliary value’s interpretation remain unknown.
- **Runtime fidelity:** The supplied static representation supports the branch contract above, but no execution trace confirms it.
