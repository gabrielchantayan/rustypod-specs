# F-91002fde2c6d

## Purpose

F-91002fde2c6d dispatches three selector values against shared state organized into three groups:

- **4:** invoke a preliminary notification, then attempt a group reset.
- **8:** attempt a group reset without the preliminary notification.
- **32:** qualify an operand against stored tokens; on the primary-token match, inspect active records and choose a final notification.

Every explicit normal return produces the 32-bit value **0**. The return value does not distinguish ignored input, an out-of-range group, a completed reset, or a completed token-qualified operation.

“Reset,” “notification,” and “time-like coordinates” are descriptive interpretations. The established contract consists of the accesses, calls, ordering, and conditions below. Dependency internals and application-level meanings remain unspecified.

## Behavior

### Entry and dispatch

The function captures the control-region base at entry. The matching selector-32 path later uses this entry-captured address for its final token read.

Selectors other than **4**, **8**, and **32** return zero without dependency calls or explicit shared writes. The entry base capture still occurs.

Selector 4 performs its preliminary notification before checking whether the operand is a valid group. Selector 8 proceeds directly to reset preparation.

### Selector 4: preliminary notification

The function calls F-15643c36365d to obtain an object address. It reads the object’s dispatch-table address and invokes dependency D-03 through dispatch-table offset **0x34**.

The invocation receives, in order:

1. The returned object address.
2. A 32-bit value read through a shared argument pointer.

There is no visible success check. After normal return, execution enters the common reset path. Shared configuration used by that path is read after this notification; preservation of globals by either dependency is not assumed.

### Selectors 4 and 8: reset setup

The reset path first reads a shared 32-bit initial value, then captures the control-region base for reset use. These reads occur even when the operand is out of range.

If the operand is not unsigned-less-than **3**, the function returns zero without the reset writes or subsequent reset dependencies.

For a valid group, three one-byte zero writes occur in this order:

1. Offset **group**, using a further read of the shared control-region base.
2. Offset **3 + group**, using the reset-path captured base.
3. Offset **6 + group**, using that same captured base.

No dependency call intervenes between these writes. The first write’s base read is nevertheless distinct from the earlier capture.

### Reset preparation and classification

Before each call to F-704f99fd5e22, both local coordinate areas are independently assigned the previously captured initial value. The dependency receives:

1. Context.
2. Group.
3. Address of the area used elsewhere as the second coordinate.
4. Address of the area used elsewhere as the first coordinate.
5. Address of the four-byte buffer.

A zero result repeats this initialization and call. Any nonzero result exits the loop. There is no retry limit or delay. The buffer is not explicitly initialized by this function, and the visible reset continuation does not consume these local outputs.

After the first nonzero result:

1. D-01 supplies a classification-context value.
2. F-c1e400b68436 receives that value advanced by **4 bytes**, followed by the group.

Only classification result **1** changes subsequent iteration bounds. Other results are not interpreted as errors.

### Reset-byte writes: two base reads

After classification, the reset-byte shared base is read twice:

- The **first read** is retained for the write at group-relative offset **0**.
- The **second read** is combined with **group × 8** and supplies the address for the other seven writes.

The writes are single-byte zero stores in this order:

| Write order | Group-relative offset | Base source |
|---:|---:|---|
| 1 | 5 | Second read |
| 2 | 7 | Second read |
| 3 | 1 | Second read |
| 4 | 2 | Second read |
| 5 | 0 | First read |
| 6 | 3 | Second read |

The two base values are not required to agree by this body. Describing these operations as one atomic eight-byte clear, or necessarily as eight writes into one region, would exceed the evidence.

### Selector 32: token qualification

The operand is compared with the 32-bit token at offset **0x18**, using a fresh read of the shared control-region base rather than necessarily the entry-captured base.

If the primary token differs, the function reads the alternate token at context offset **0x2c8**.

If the alternate token equals the operand, F-e08f888de5db receives these ordered arguments:

1. Context.
2. Address of the local area used elsewhere as the **second coordinate**.
3. Address of the local area used elsewhere as the **first coordinate**.
4. Address of the **four-byte buffer**.
5. Address of the separate **32-bit storage used elsewhere for the local object**.

The function then returns zero. These argument positions are established; their output meanings are not. This path does not initialize the local object, scan records, issue the scan’s final notification, or finalize the local object.

If neither token matches, F-a817d8d58c10 is invoked without explicit arguments. The supplied representation treats it as nonreturning. No normal continuation is established for this case.

### Selector 32: coordinate production and configuration capture

For a primary-token match:

1. F-7a117b899bf6 receives the address of the 32-bit local object storage.
2. D-04 is invoked through the callable location at byte offset **0x0c** from the value held in that storage. Its arguments are the local object-storage address and the first-coordinate-area address.
3. The shared group-stride scalar is read.
4. The shared record-table base is read.

The stride capture therefore precedes the table-base capture, and both follow the indirect coordinate-producing call.

The scan consumes both local coordinate areas. Only the first-coordinate-area address is explicitly passed to D-04. Whether D-04 writes a larger aggregate that also supplies the second coordinate is unknown. Deterministic coordinate-based behavior is conditional on both areas containing valid values.

### Selector 32: candidate traversal

Groups are processed in order **0, 1, 2**. For each group, D-01 is called anew, then F-c1e400b68436 receives its result advanced by four bytes and the group.

Classification result exactly **1** starts candidate iteration at **1**. Every other result starts it at **0**. Candidate indices increase through **5**, inclusive.

Each candidate address combines:

- The captured table base.
- Captured stride × group × **4**.
- Candidate index × **12**.

The **32-bit active word at +8 is read first**. Zero skips all coordinate work for that candidate. Any nonzero value is active.

For an active candidate:

1. Read its first coordinate and subtract it from the local first coordinate.
2. Read its second coordinate and subtract it from the local second coordinate.
3. Normalize a negative second difference as described below.
4. Evaluate the retention predicate.

The table base and stride remain captured across callbacks. Record contents are read as traversal reaches them, not copied into an initial table snapshot. A classification or action dependency may therefore affect later record observations.

### Normalization and retention

While the signed second difference is negative, each iteration proceeds in this order:

1. Decrement the first difference by one.
2. Read the shared interval unit.
3. Multiply that read value by **5** and add the product to the second difference.
4. Recheck whether the second difference is negative.

The interval unit is read separately on every entered iteration. No immutable interval snapshot is established.

After normalization, retention is evaluated with short-circuit behavior:

- First test whether the first difference equals **0**.
- **Only if it equals 0**, read the shared interval unit again and test whether the second difference is signed-less-than that threshold.

Thus the retention-threshold read is distinct from all normalization reads. If the first difference is nonzero, there is no threshold read for that candidate.

No normalization of a nonnegative second difference is performed. In particular, large positive values are not reduced modulo five interval units.

A retained candidate sets a local flag that remains set throughout the rest of the scan. A nonretained active candidate causes F-541a3af1ee79 to receive group, candidate index narrowed to one byte, and zero. This body does not explicitly clear that candidate’s active word.

Coordinate differences, decrement, interval multiplication, and accumulation are represented with 32-bit quantities. Signed comparisons are significant; overflow semantics are not resolved by the supplied material.

### Final notification and finalization

- Otherwise, call D-02, then F-23aadb16b673.

The selected notification receives:

2. The 32-bit token read at offset **0x18** from the **entry-captured control-region base**.

That token read occurs after D-02 returns. It is not the earlier comparison value and need not equal the operand.

F-ec22bd8215d3 then receives the local object-storage address. After normal return, the function returns zero.

## Acceptance examples

These are conditional static examples, not executed tests. Unless stated otherwise, reached memory is valid, dependencies return normally, and arithmetic intermediates are representable.

1. **Unsupported selector:** Selector 7 returns zero after the entry base capture, without dependency calls or explicit shared writes.

2. **Invalid group:** Selector 8 with operand 3 performs the reset setup reads but no reset writes. Selector 4 with operand 3 additionally performs its preliminary notification before those reads.

3. **Retry behavior:** If F-704f99fd5e22 returns zero twice and nonzero on its third call, it is called three times. Both coordinate areas are restored to the captured initial value before every attempt.

4. **Distinct reset bases:** If the two reset-byte base reads produce different valid addresses, offset 0 is cleared relative to the first address. Offsets 5, 7, 1, 2, 3, 4, and 6 are cleared relative to the second, in the specified interleaved order.

5. **Classification:** Result 1 omits reset action 0 and scan candidate 0. Result 2 does neither. Reset indices 1 and 9 issue no calls in either case.

6. **Alternate token:** A primary mismatch and alternate match invokes F-e08f888de5db with context, second-coordinate address, first-coordinate address, buffer address, and object-storage address, in that order, then returns zero without scanning.

7. **No active records:** If every inspected active word is zero, the scan reads no candidate coordinates, performs no normalization or retention-threshold reads, and chooses F-23aadb16b673 before finalization.

8. **Retention boundary:** With a stable interval unit of 10, differences **0, 9** retain a candidate; differences **0, 10** do not. Both read the retention threshold, and neither enters normalization.

9. **Borrow normalization:** With interval unit 10, differences **1, −45** first decrement the first difference to 0, then read the interval and add 50, producing **0, 5**. A separate threshold read follows; the candidate is retained if that read also yields 10.

10. **Short-circuited threshold:** Differences **2, −1**, with normalization interval 10, become **1, 49**. Because the first difference is nonzero, no retention-threshold read occurs, and the candidate is not retained.

11. **Late token:** If D-02 changes the token at the entry-captured control address before returning, the final notification receives that changed token. Changing only the global control-region base does not redirect this final read.
