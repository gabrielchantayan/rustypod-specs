### Capture timing and aliasing

The order of reads and writes is part of the behavior. No non-aliasing condition is established.

The first captured word is obtained after the initial 16-bit write. If that write overlaps the later 32-bit read, the read can observe bytes changed by the write.

The dispatch word is obtained after both writes through the secondary address. If either write overlaps its read location, the dispatch word reflects memory at the later read, not necessarily memory at entry.

The second captured word is obtained after the dispatch word and before the byte write through the tertiary address. That subsequent byte write does not cause either captured value to be reread.

Likewise, the final two 32-bit writes use values already captured. Even if those writes overwrite the original read locations, their data and the indirect invocation’s represented arguments remain based on the earlier reads.

An earlier write can therefore affect a later read through aliasing. A later write cannot retroactively change a value already captured by the visible body.

### Arithmetic and narrowing

- Twice the first captured word for the final 32-bit write.

Neither operation is established as indexing a typed array. The difference in access width at those two destinations is intentional in this contract: the first write is 16 bits, while the final write is 32 bits.

The address calculations include doubling and adding offsets to values represented as 32-bit integers. The supplied evidence does not independently establish overflow behavior, address extension, or the effective address width. Defined acceptance cases should use values for which these calculations produce unambiguous, valid addresses. For an ordinary truncating target interpretation, this is the low eight bits of the primary address value; exact language-level conversion and target representation at the signed-byte boundary are not independently established.

These are conditional static acceptance examples, not executed tests. They assume valid, suitably aligned memory and unambiguous address arithmetic unless stated otherwise.

### Earlier write affects a later read

Suppose the secondary address plus 84 equals the tertiary address plus 100, and no intervening access changes those four bytes.

The second captured word is then 100, because its read follows the 32-bit write of 100. The next 32-bit write targets address 184 and writes the first captured word there. The final 32-bit write uses 100 as its data.

An implementation that obtains the second captured word before the secondary-address write would not preserve the specified access order.

### Later writes do not refresh captured arguments

Suppose the write at the second captured word plus 84 overwrites the location from which the dispatch word was read.

The fourth indirect argument remains the dispatch word captured earlier. Reading that location again for the invocation would introduce behavior not present in the visible body.

### Distinct write widths

Suppose the first explicit input is `0xBEEF`. The initial operation writes two bytes, not four.

Acceptance must check the affected byte range rather than assume the byte order. The final doubled-address write remains a four-byte operation, even if its stored value could fit in fewer bytes.

### Failure before invocation

No successful invocation or normal return is required by the available evidence. Earlier writes have no specified rollback. A particular exception, signal, or diagnostic is not an established outcome.
