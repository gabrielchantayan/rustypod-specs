# F-4a46423b0bb4

## Purpose

F-4a46423b0bb4 conditionally rewrites a selected-node reference and several address-bearing words associated with a supplied node.

The established behavior is a pointer-identity check followed, when the references differ, by an ordered sequence of memory updates. The updates resemble removing a node from one linkage position and placing it before a previously selected node. That interpretation is **inferred intent**, not a guarantee that the resulting structure satisfies a conventional linked-list invariant.

In particular, one node word is used as a destination address during removal, while the final update places the supplied node’s address into the corresponding word of the previously selected node. The contract preserves those operations without assuming that these words consistently represent ordinary predecessor pointers or pointer-to-pointer links.

There is no explicit return value, allocation, deallocation, dependency call, validation, or error-reporting mechanism.

## Interface

### Inputs

The function receives two arguments:

| Argument | Interpretation |
|---|---|
| Container address | An address-bearing integer identifying memory with accessible words at byte offsets 12 and 16. |
| Supplied-node address | A pointer to memory containing at least two accessible 32-bit words, at byte offsets 0 and 4. |

The following names describe roles in this contract, not source identifiers:

| Location | Contract name | Established use |
|---|---|---|
| Container + 12 | Selected reference | Read initially; replaced with the supplied-node address on the unequal path. |
| Container + 16 | Terminal reference | Written only when a later read of the supplied node’s first word is zero. |
| Supplied node + 0 | Forward word | Read as a stored value, tested against zero, sometimes used as an address, and eventually replaced with the initially selected reference. |
| Supplied node + 4 | Link word | Used as an address for an indirect write, copied elsewhere, and eventually cleared. |

The names “forward,” “link,” and “terminal” are descriptive conveniences. They do not establish a complete data-structure model.

### Widths and address representation

The supplied representation establishes a layout using 32-bit integer words and four-byte spacing between the node’s two words. Pointer values are stored in, and recovered from, these address-bearing words.

This contract therefore describes a 32-bit address-bearing model consistent with those operations. It does not establish portability to an environment with wider pointers, different integer widths, or different alignment requirements.

The relevant address displacements are:

- 12 bytes and 16 bytes from the container address;
- 4 bytes from a node address.

No element count, length, payload arithmetic, or numeric range conversion is present. Signed-overflow behavior, address wraparound, and invalid pointer conversions are not defined by this contract; valid execution requires representable, usable addresses for the accesses actually reached.

### Output and ownership

There is no explicit return value. Results are observable through memory changes.

The function does not explicitly acquire or release ownership. It neither allocates nor frees storage. The caller must provide storage with sufficient lifetime and access permissions for the executed path.

The initially selected reference is retained for later use, but retaining it does not extend the lifetime of its referent.

## Behavior

### Initial selection check

The first established memory operation is a read of the selected reference at container offset 12. Call the value obtained by this read the **initial selection**.

The function compares the initial selection with the supplied-node address.

If they are equal, the function returns without an explicit memory write. On this path:

- the supplied node’s contents are not read;
- the terminal reference is not accessed;
- no indirect destination is accessed;
- no node linkage is modified.

Thus, equality is an address-identity condition, not a comparison of node contents.

### Unequal-reference update

If the two addresses differ, the function performs the following stages in the stated source-level order. Later reads are not assumed to reproduce earlier values when intervening writes can alias their locations.

1. **Publish the supplied node as selected.**  
   The selected reference at container offset 12 is overwritten with the supplied-node address.

2. **Perform the indirect removal write.**  
   The current forward word is written to the memory location whose address is held in the current link word.

   This is a write through the link word, not merely a replacement of that word. Both node words supply operands to this operation. Their relative read order within this individual assignment is not established.

3. **Read the forward word again and choose a branch.**  
   The decision uses the forward word as it exists after the preceding indirect write.

   - If this read is zero, the terminal reference at container offset 16 receives the then-current link word.
   - Otherwise, the then-current link word is written at byte offset 4 from the address obtained through the forward word.

   On the nonzero branch, the forward word is read again to obtain the destination address. The zero test therefore does not, by itself, establish that a separately obtained destination value remains nonzero under concurrent mutation.

4. **Clear the supplied node’s link word.**  
   The word at supplied-node offset 4 is set to zero.

5. **Replace the supplied node’s forward word.**  
   The word at supplied-node offset 0 receives the initial selection retained from the first read.

6. **Update the initially selected node.**  
   The supplied-node address is written at byte offset 4 from the initial selection.

The function then returns.

The final destination is derived from the initial selection, not from a fresh read of the container’s selected reference.

### Aliasing and repeated reads

The routine contains no alias checks. It is not established that the container, supplied node, initial selection, indirect destination, and forward-linked destination occupy disjoint storage.

Consequently, an early write can change a later read:

- Publishing the supplied-node address can affect subsequent node-word reads if the selected-reference field overlaps the node.
- The indirect removal write can change the forward word before its zero test.
- That write can also change the link word before it is copied into the terminal reference or another node.
- A branch-specific write can overlap storage subsequently cleared or replaced.

The retained initial selection is different: later memory writes do not replace that saved value.

For overlapping layouts, the ordered accesses—not a simplified “move node” description—define the supported static behavior. This contract does not add snapshot semantics for the node’s original words.

### Preconditions and failure boundaries

There is no explicit null check or structural validation.

For the equality path, the container’s selected-reference word must be readable. The supplied-node address is only compared, so this path does not require dereferencing it. In particular, equality between a zero initial selection and a zero supplied-node address reaches the no-write return, provided the container read itself is valid.

For a normal unequal execution:

- the selected-reference field must be writable;
- both supplied-node words must support their executed reads and writes;
- the address obtained from the link word must designate writable storage;
- the selected branch’s destination must be writable;
- the initial selection must support a write at byte offset 4.

A zero initial selection on the unequal path is not treated as an empty-structure case. The final operation still attempts the offset-4 write derived from it.

Likewise, a zero link word does not skip the indirect removal write. Whether an access to any such address faults is platform-dependent and not established here.

There is no rollback. If an access fails after the first update, earlier writes may already have changed the structure.

## Side effects

On a valid unequal path, the function executes six word-write operations:

1. selected-reference replacement;
2. indirect removal write;
3. one branch-specific write;
4. supplied-node link-word clear;
5. supplied-node forward-word replacement;
6. initial-selection link-word replacement.

These are six operations, not necessarily six distinct destinations. Aliasing can cause multiple writes to the same word or overwrite an earlier result.

No payload fields beyond the described words are explicitly accessed. However, because destinations are obtained from caller-provided address-bearing values, the writes are not independently constrained to a verified node allocation.

No synchronization, atomicity, or memory-ordering mechanism is established. The source-level operation sequence is not a promise of atomic visibility to other threads. Concurrent modification and observation are outside the established contract.

## Dependencies

No external function calls appear in the supplied body. No additional opaque function IDs are required.

Execution depends on the surrounding memory environment:

- a compatible integer and pointer representation;
- live, suitably aligned storage where required;
- valid permissions for each reached access;
- caller-maintained structural relationships sufficient to make the writes meaningful.

There is no called dependency whose ownership or global-state behavior needs to be assumed.

## Acceptance examples

These examples are conditional static acceptance cases, not runtime test results. Unless stated otherwise, relevant locations are disjoint, valid, and not concurrently modified.

### Already selected

Given a readable container whose selected reference equals the supplied-node address:

- the selected reference remains unchanged;
- no node word is read;
- no memory write occurs.

This remains the established path even when that shared address is zero.

### Unequal selection with a zero forward word

Suppose the initial selection identifies node A, the supplied node is B, B’s forward word is zero, and B’s link word identifies writable word R.

After a valid execution:

- the container selects B;
- R contains zero;
- the terminal reference contains the address of R;
- B’s link word is zero;
- B’s forward word contains A’s address;
- A’s offset-4 word contains B’s address.

The terminal update occurs because the forward-word read after the indirect write is zero.

### Unequal selection with a nonzero forward word

Suppose the initial selection identifies A, supplied node B has forward word C, and B’s link word identifies writable word R.

With C nonzero and all destinations valid:

- R receives C’s address;
- C’s offset-4 word receives the address of R;
- B’s link word becomes zero;
- B’s forward word becomes A’s address;
- A’s offset-4 word becomes B’s address;
- the terminal reference is not explicitly written.

The container selects B before these linkage updates complete.

### Removal write changes the branch decision

Suppose B’s link word points to B’s own forward-word storage, and B’s forward word is initially nonzero.

The indirect write stores that forward value back into the same word. The subsequent branch test reads the resulting word; it is not based on a separately retained original-forward snapshot.

More generally, acceptance for an overlapping layout requires tracing each write before evaluating subsequent reads. Disjoint-node postconditions must not be applied automatically.

### Invalid initial selection

Suppose the initial selection is zero and differs from B.

There is no early empty-selection return. Execution can modify the container and other reachable storage before attempting the final write at byte offset 4 from the zero initial selection. No successful completion or particular fault result is promised.

The updates resemble unlinking a node and placing it before an initially selected node. The terminal-reference branch resembles maintenance of an end-of-chain reference. Neither interpretation establishes a standard list representation.
