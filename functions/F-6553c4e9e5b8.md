# F-6553c4e9e5b8

## Purpose

F-6553c4e9e5b8 selects a 32-bit result from a cache entry or an indirect callback, passes that result and the caller’s key reference to an association dependency, and returns the retained result.

Two context masks control cache selection and callback classification. The higher-priority mask takes precedence. A selected cache can be probed twice before creation is attempted. After callback-based creation, a conditional sequence invokes additional dependencies and decrements a word in the originally selected cache.

“Cache,” “creation,” “association,” and “diagnostic” describe apparent roles. The established behavior is the sequence of accesses, branches, arguments, and calls below; successful insertion, allocation, reporting, or ownership transfer is not established.

## Interface

### Inputs and result

| Input | Representation | Established role |
|---|---|---|
| Context reference | Pointer to a four-byte word interpreted as a context address | Supplies context fields; the original reference pointer is passed to the final association call. |
| Key reference | Pointer to an unsigned 32-bit word | Supplies an index separately for each reached cache probe; the original pointer is passed to association calls. |
| Miss permission | Signed 32-bit integer | Zero causes a diagnostic call after the initial lookup fails to produce a result. Any nonzero value skips that call. |
| Selection mask | Unsigned 32-bit value | Controls cache selection, callback classification, callback-data selection, and the initial contents of a local temporary. |
| Tagged callback | Unsigned 32-bit value | Supplies the indirect target after its lowest two bits are cleared. |

The function returns a signed 32-bit result. Its bit pattern comes from either a nonzero four-byte cache entry or the callback’s 32-bit return value. The callback result may be zero; there is no rejection or retry for that value.

The final association dependency’s return value is not used as this function’s result.

### Directly accessed layout

Offsets are in bytes. Every field listed below is four bytes wide.

| Base | Offset | Use |
|---|---:|---|
| Context | 0 | Address of the callback-data table |
| Context | 16 | Lower-priority classification mask |
| Context | 20 | Higher-priority classification mask |
| Selected cache | 8 | Address of an array of four-byte entries; this field’s address is passed to growth |
| Selected cache | 12 | Unsigned bound used for index checks |
| Selected cache | 28 | Word decremented during conditional temporary association |
| Shared selection object | 8 | Cache address used when neither context mask overlaps |
| Shared selection object | 12 | Cache address used when the lower-priority mask alone overlaps |

Callback-data selection considers table indices 0 through 5. Only the chosen entry is read. This access range does **not** establish the table’s actual extent, a maximum of six entries, or the validity of entries that are not accessed.

A separate fixed address supplies default callback data. Its contents, storage extent, mutability, and lifetime are unknown.

### Preconditions

There is no general pointer, extent, or callback validation. Defined completion requires validity of every reached access and call, including:

- The context reference and the context fields actually read.
- The key reference whenever a probe reads it.
- The shared selection state when cache selection uses it.
- Selected-cache fields and the indexed array entry.
- Any table-base and selected table-entry reads.
- Storage accessed after a returning growth call.
- The masked indirect target when creation is reached.
- All otherwise unknown dependency preconditions.

A null selected-cache address is handled by skipping cache operations. That does not imply that null context references, null context addresses, null table bases, or null callback targets are accepted.

No explicit non-aliasing condition is enforced. Dependencies receive original caller pointers and, on some paths, a local address; their mutations cannot be dismissed by assuming unrelated storage.

## Behavior

### 1. Select and retain the cache address

The higher-priority context mask is tested against the selection mask first.

- A nonzero overlap selects no cache.
- Otherwise, the lower-priority context mask is tested.
  - A nonzero overlap selects the cache address at offset 12 of the shared selection object.
  - No overlap selects the cache address at offset 8.

A zero address obtained from shared selection state also means no cache.

The higher-priority test suppresses both the lower-priority decision and shared cache selection when it matches. Initial selection accesses the context through the caller’s reference; the source does not establish an atomic context-and-mask snapshot.

The selected cache address is retained for the rest of this invocation. Later calls may change shared selection state or the context reference, but the function does not select a replacement cache.

### 2. Initialize the local temporary

Immediately after cache selection, and before any probe, the function assigns the selection mask to a four-byte local temporary.

This is significant incoming state, not an unused initialization:

- Without a reached growth branch, the last explicit assignment before temporary association is the selection mask.
- Every reached growth branch explicitly overwrites the temporary with zero.
- The first probe’s growth call receives the temporary’s address and may change its contents.
- A later second-probe growth branch overwrites any earlier contents with zero before making its call.
- There is no unconditional zeroing immediately before the first temporary-association dependency.

Dependency-mediated changes remain subject to unknown dependency contracts. In particular, exposing the address to the first growth call does not establish that the address cannot be retained or used subsequently.

### 3. Perform the first cache probe

If the retained cache address is nonzero, the first probe:

1. Reads the unsigned key through the key reference.
2. Reads the cache’s unsigned bound.
3. Requests growth if the bound is less than or equal to the captured key.
4. Reads the current array address from cache offset 8.
5. Reads the four-byte entry indexed by the captured key.

A growth request is preceded by zeroing the local temporary. The first growth call to F-992b83e9731d explicitly supplies, in order:

1. The address of the selected cache’s array-address field.
2. The captured key plus one, in unsigned 32-bit arithmetic.
3. The address of the zeroed temporary.

The array address is read after the growth call, so replacement backing storage can be observed. The key is not reread for this probe’s entry access.

No growth return value is checked. There is no second bound check or visible local recovery if growth fails to leave the indexed entry accessible.

A nonzero entry is a hit. It becomes the retained result and proceeds directly to final association, bypassing the diagnostic, second probe, callback, and temporary-association sequence.

### 4. Handle the initial miss and probe again

An initial miss means either that no cache was selected or that the first entry read was zero.

If miss permission is zero, F-5829ec5988c0 is called with the value 4. The function contains no explicit termination after that call. If it returns normally, execution continues. Whether the dependency reports, throws, aborts, or changes state is unknown.

If a cache was selected, the function then probes that same retained cache again. This happens even when miss permission was nonzero and no diagnostic was called.

The second probe rereads the key and bound. Its index can therefore differ from the first probe’s index. It again requests growth when the unsigned bound is less than or equal to the newly captured key.

Before second-probe growth, the temporary is explicitly reset to zero. This call to F-992b83e9731d explicitly supplies the array-field address and wrapped key-plus-one value. No third argument is explicit at this call site. A uniform three-argument growth interface is therefore not established.

The array address is read after any growth call, and the entry access uses the key captured for this second probe. A nonzero entry becomes the result and proceeds directly to final association.

### 5. Classify creation and choose callback data

If neither probe produces a nonzero entry, the function rereads the context address through the original context reference. It uses that captured context address for creation classification and table selection.

| Condition | Classification | Callback data |
|---|---:|---|
| Higher-priority mask overlaps | 2 | Selected table entry, if one of the six considered bits is set; otherwise the fixed default address |
| Higher-priority mask does not overlap, lower-priority mask overlaps | 1 | Fixed default address |
| Neither mask overlaps | 0 | Fixed default address |

For classification 2, selection-mask bits are considered in this order:

| Bit value | Table index |
|---:|---:|
| 16 | 0 |
| 32 | 1 |
| 64 | 2 |
| 128 | 3 |
| 256 | 4 |
| 512 | 5 |

The first set bit wins. Higher-position considered bits do not override an earlier match. Bits outside this set can contribute to mask overlap but do not select a table entry.

When a bit matches, the table address is read from context offset 0 and only the selected four-byte entry is read. The entry value is forwarded as callback data without a nonzero check. When none matches, the fixed default address remains selected; no table entry is needed.

Creation classification can differ from initial cache policy if an intervening dependency changes the context reference or relevant fields.

### 6. Invoke the callback

The indirect target is the tagged callback with its lowest two bits cleared. Those bits are not forwarded separately.

The callback receives:

1. Classification, as a 32-bit value of 0, 1, or 2.
2. The selected callback-data address.
3. Zero.

Its 32-bit return value becomes the retained result. There is no target validation, zero-result check, retry, or explicit error translation.

### 7. Conditionally perform temporary association

After callback return, the function rereads the context reference only if a nonzero cache was originally selected. It performs the following sequence if that current context address differs from the retained selected-cache address:

1. Call F-e9b26c5975b5 with the temporary’s address and the retained cache address.
2. Call F-ae730a9506ec with the same temporary’s address, the retained callback result, and the original key-reference pointer.
3. Explicitly overwrite the temporary with zero.
4. Read the selected cache’s offset-28 word, subtract one, and write the four-byte result back.
5. Call F-07fef63861ea with the address of the now-explicitly-zeroed temporary.

The incoming temporary for step 1 is **not necessarily zero**. Its last explicit assignment may be the selection mask or a growth-branch reset, and the first growth dependency may have written through its exposed address. F-e9b26c5975b5’s unknown behavior does not justify omitting this incoming state.

The decrement reads the cache word after both preceding calls. It does not decrement a value captured before those calls. The originally retained cache address is still used.

A zero callback result does not suppress this sequence. Equality between the post-callback context address and the selected cache suppresses the entire sequence, including the decrement.

### 8. Perform final association and return

Every ordinary returning path calls F-ae730a9506ec with:

1. The original context-reference pointer.
2. The retained result.
3. The original key-reference pointer.

This applies to both cache hits and callback results, including zero. The function then returns the retained result, not the association call’s return value.

No claim of ordinary completion applies if a reached access is invalid or a dependency fails to return normally.

## Side effects

Directly established effects include conditional context, shared-selection, cache, and callback-table reads; writes to the local temporary; the conditional cache-word decrement; and the ordered calls described above.

The function makes no direct assignment through the context reference or key reference. Both pointers are passed to dependencies, so this is not a preservation guarantee.

The temporary’s initial selection-mask value, growth resets, possible growth-mediated mutation, and later explicit zeroing are distinct state transitions. Only the first growth call explicitly receives its address; both temporary-association calls and the final cleanup-like call on that path also receive it.

Allocation, cache insertion, context replacement, ownership transfer, diagnostics, and resource release may occur inside dependencies, but their occurrence is not established merely by the calls. No ownership balance or permission to retain a stack-local address is specified.

### Widths and arithmetic boundaries

- Masks, keys, bounds, callback values, entries, and the temporary are four-byte quantities.
- Bound comparisons are unsigned.
- Requested growth size is key plus one modulo \(2^{32}\). A key of 4,294,967,295 produces a requested value of zero.
- Entry addressing scales the captured key by four. No multiplication-overflow or address-range guard is visible; a mathematical offset must not be assumed representable or accessible.
- The offset-28 update has no underflow or saturation check. At the four-byte bit-pattern level, decrementing zero yields all ones. The source does not establish that zero is a valid incoming value for this update.
- Signed interpretation of a returned entry does not affect hit detection: every nonzero four-byte entry is accepted, including values with the highest bit set.

These observations describe unchecked arithmetic, not supported input ranges.

## Acceptance examples

These are conditional static expectations, not observed test results. Each assumes valid reached accesses and normally returning dependencies unless stated otherwise.

1. **First-probe hit with zero miss permission.**  
   A selected cache has bound greater than key 3 and a nonzero entry at index 3. That entry is passed to final association and returned. No diagnostic, second probe, or callback occurs.

2. **Higher-priority overlap dominates.**  
   Both masks overlap. No cache is selected. If the higher-priority overlap still holds at creation, classification is 2. Zero miss permission causes the diagnostic before creation.

3. **Diagnostic changes the second lookup.**  
   The first entry is zero. A returning diagnostic changes the key or cache so that the second probe reads a nonzero entry. That entry is associated and returned without callback creation.

4. **Key equals bound.**  
   Key and bound are both 7. Growth is requested with value 8 before entry 7 is read. Continued execution requires that entry to be accessible; no post-growth bound validation occurs.

5. **Multiple callback-selection bits.**  
   Classification is 2, bit 16 is clear, and bits 32 and 256 are set. Table entry 1 supplies callback data. If bit 16 is instead set, entry 0 wins.

6. **Overlap outside the considered table bits.**  
   Classification is 2, but none of 16, 32, 64, 128, 256, or 512 is set. The fixed default callback-data address is used.

7. **Nonzero incoming temporary without growth.**  
   A nonzero selection mask selects a cache; both probes miss without growth; creation returns; the post-callback context differs from that cache. Assuming no dependency-mediated change to the temporary, F-e9b26c5975b5 receives its address while it still contains the selection mask.

8. **First growth changes temporary contents.**  
   First-probe growth writes a value through the temporary address. Both probes miss, second-probe growth is not reached, and temporary association is required. If intervening dependencies leave that storage unchanged, the written value is the incoming value for F-e9b26c5975b5—not an assumed zero.

9. **Second growth resets earlier state.**  
   First-probe growth changes the temporary, and second-probe growth is later reached. Before that second call, the function explicitly replaces the earlier contents with zero. No third argument is explicit at the second call site.

10. **Zero callback result.**  
    A callback returns zero. Applicable temporary association and final association receive zero, and ordinary completion returns zero without retry.

11. **Callback changes context to selected cache.**  
    A cache was selected and creation occurs. The post-callback context read equals that retained cache address. Temporary association and the decrement are skipped; final association still occurs.

12. **Tagged callback equivalence.**  
    Callback values differing only in their lowest two bits identify the same masked target. No separate callback argument conveys those bits.

## Uncertainties

The following remain **documented_only**:

- Application-level identities of contexts, keys, caches, classifications, and results.
- Complete dependency signatures, especially the differing explicit growth arguments.
- Whether the diagnostic returns in supported executions.
- Growth guarantees, allocation failure handling, entry initialization, and bound maintenance.
- The callback-data table’s actual extent and the fixed default data’s contents and lifetime.
- Ownership, retention, reference counting, destruction, and storage-release rules.
- Dependency effects on globals, caller references, cache contents, and exposed temporary storage.
- Supported ranges for keys, masks, counters, and callback values.
- Concurrency, reentrancy, synchronization, and asynchronous mutation guarantees.
- Error propagation and ABI details beyond the visible four-byte operations and arguments.

The decrement and surrounding calls suggest lifetime management; that is inferred intent, not an ownership contract. The repeated probe suggests accommodation of state changes; the rereads are established, but their design rationale is not.
