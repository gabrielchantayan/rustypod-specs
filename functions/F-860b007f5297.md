# F-860b007f5297

## Purpose

F-860b007f5297 repeatedly performs indirect calls, fixed-width memory transfers, address calculations, and software breakpoint `0x92`. The supplied static representation contains an unconditional loop, with no normal return or explicit successful-completion condition.

No application-level purpose is established. The accesses may represent state propagation or table updates, but those interpretations do not establish object types, valid storage, or ownership.

This contract describes the visible operations and their ordering. Progress through any iteration depends on calls returning, memory accesses completing, and the execution environment permitting continuation after the breakpoint.

**Implicit inputs:**

- An incoming link-like value determining the first indirect call target.
- A frame-like base used for word accesses and explicitly adjusted during each iteration.
- An incoming register-derived base used for a late byte write.

The nominal parameter list therefore does not constitute a complete machine-level calling convention.

**Widths and arithmetic:**

- Three call results are represented as 64-bit quantities, each separated into low and high 32-bit words.
- The three selector reads are unsigned 16-bit reads, zero-extended when used in subsequent arithmetic or word writes.
- Byte and halfword stores retain the low 8 and 16 bits of their supplied values.
- Pointer-like quantities and address calculations are represented at 32-bit width.
- The second pair’s low-word right shift is unsigned.
- Left shifts, scaling, and additions below describe low-32-bit results. This is a bit-pattern description of the supplied representation, not a claim about original-language signed-overflow rules.

- **First pair, second pair, third pair:** the three split 64-bit results.
- **Fixed base:** `0x21C48960`.
- **First selector:** the unsigned halfword read from fixed base + `0x34`.

- **Second selector:** the unsigned halfword read from intermediate base + `0x34`.

These roles identify dataflow, not allocated objects or validated pointers.

### Opening calls and first-pair transfers

### Breakpoint and indexed halfword store

Immediately after F-D19 returns, software breakpoint `0x92` is issued. No later operation is guaranteed to execute. The environment may stop execution, transfer control to a handler, resume, or apply another platform-specific behavior.

If execution continues as represented:

- F-D19’s 32-bit result is scaled by four.
- The fixed base is shifted right by 18 bits and multiplied by four, producing `0x21C4`.
- The destination base is read as a word at zero-extended first selector + `0x44`.

The first selector is therefore used directly as an address component, not as an index into an independently established array.

F-D20 executes, followed by F-D21, which supplies a 32-bit result. F-D22 receives that result and a word read from first selector + `0x04`.

After F-D22, the table base is captured from the second global location. F-D23 executes before a halfword store to:

**table base + four times F-D19’s result**, with the represented 32-bit address arithmetic.

The stored halfword is the low 16 bits of the captured table base itself. A dependency changing the global after capture does not introduce a reload into the represented operation.

### Intermediate transfers and third-pair processing

F-D25 supplies a pointer-like result. The halfword `0x21C4` is stored at that result + `0x04`.

F-D26 and F-D27 execute before the second selector is read as an unsigned halfword at intermediate base + `0x34`.

F-D28 supplies the third pair. Before F-D29:

- The third pair’s low word is stored at current frame-like base + `0x258`.
- The late selector is read from third-pair high word + `0x14`.
- The third pair’s low word is scaled by 64, retaining its low 32 bits.

### Late transfers and iteration transition

F-D29 executes before the zero-extended late selector is stored as a word at destination base + `0x54`.

F-D30 executes before the same captured selector is stored as a word at destination base + `0x64`. There is no intervening selector reread.

F-D31 executes and shares F-D19’s represented target. A halfword containing the low 16 bits of the destination base is then stored at:

**third-pair low word scaled by 64 + F-D31’s secondary pointer-like output.**

F-D35 executes before the third pair’s scaled high word is stored as a word at destination base + `0x44`.

F-D36 executes. The link-like working value is assigned `0x08712031`; a word read from scaled third-pair high word + `0x44` supplies F-D37’s explicit argument.

If F-D37 returns and execution continues as represented, the next iteration begins. No loop exit, explicit status result, or cleanup branch is shown.
