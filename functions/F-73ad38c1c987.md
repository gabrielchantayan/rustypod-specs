## Behavior

### Address acquisition and write order

The supplied representation establishes this sequence:

1. Read the base source and retain that value for the later writes at offsets `0x08` and `0x10`.
2. Evaluate the base source again for the write at offset `0xF0`.
3. Write four zero bytes’ worth of value at that second base plus `0xF0`.
4. Calculate the input-derived value and write it at the retained base plus `0x08`.
5. Obtain the payload-source value and write it at the retained base plus `0x10`.
6. Return without a result value.

The distinction between the retained base and the separately evaluated base matters. The evidence does not justify replacing them with one unconditional base-source observation in the behavioral contract.

If both base-source evaluations produce the same address, all three writes target the same base-relative layout. If they produce different addresses, the clear uses the second address, while both subsequent writes use the first.

This is the access sequence expressed by the supplied representation. It is not proof of a particular number of physical memory transactions, compiler barriers, volatile accesses, or processor-level ordering guarantees.

### Derived value

Under the 32-bit interpretation, the derived field is formed through these arithmetic stages:

- Multiply the signed input by `64000`.
- Convert the multiplication result to an unsigned 32-bit value.
- Shift that unsigned value right by 13 bits.
- Add `0x41000`, which is decimal `266240`.
- Store the resulting four-byte value.

For inputs whose signed product is representable, the conversion to unsigned is well-defined under the corresponding source-language interpretation. Negative products become their congruent unsigned values modulo \(2^{32}\). The right shift therefore inserts zero bits; it does not preserve a negative sign.

For a nonnegative, representable product, the result is:

\[
266240+\left\lfloor\frac{64000x}{8192}\right\rfloor
=
266240+\left\lfloor\frac{125x}{16}\right\rfloor,
\]

where \(x\) is the input value.

This simplified expression is valid for that restricted case. It must not be applied indiscriminately to negative inputs or overflowing signed products.

Once a 32-bit unsigned intermediate exists, shifting right by 13 produces a value from `0` through `0x7FFFF`. Adding `0x41000` therefore produces a value from `0x41000` through `0xC0FFF`. That addition cannot overflow a 32-bit unsigned destination.

The multiplication is the unresolved arithmetic boundary. In signed 32-bit arithmetic, its result is representable exactly for inputs from `-33554` through `33554`, inclusive. The subsequent unsigned conversion does not, by itself, make an earlier overflowing signed multiplication defined.

If independent target evidence establishes low-32-bit wrapping multiplication, the broader calculation can instead be described as:

\[
266240+
\left\lfloor
\frac{(64000x)\bmod 2^{32}}{8192}
\right\rfloor.
\]

That broader rule is conditional, not established for overflowing inputs by the supplied representation alone.
