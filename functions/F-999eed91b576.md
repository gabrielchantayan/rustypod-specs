# F-999eed91b576

## Purpose

F-999eed91b576 prepares source descriptors and conditionally rebuilds a statement’s result-expression list by expanding wildcard-shaped expressions into column references.

Established behavior includes source lookup or construction, an immediate successful return upon encountering an already-resolved source, statement processing through a dependency, wildcard expansion, diagnostic reporting, and a final result-column-limit check. Mutations are not transactional: failures can leave prepared sources, changed descriptor counters, or a partial replacement list.

The apparent intent is SQL result-list preparation. “Wildcard,” “qualifier,” and “column reference” are semantic interpretations of the observed expression kinds and metadata accesses. The numeric predicates and field operations below are established by the supplied static representation.

## Interface

### Arguments and return value

The function receives two pointers in an observed 32-bit address model:

1. **Preparation context:** required for the initial read of its engine-state pointer.
2. **Statement:** nullable.

The return value is 32 bits:

| Value | Established conditions |
|---|---|
| 0 | A source has a nonzero resolved descriptor when inspected, or final processing completes with no locally recorded error and a clear final engine failure byte. |
| 1 | An entry condition fails, a checked dependency fails, or final processing completes with a locally recorded error and a clear final failure byte. |
| 7 | Processing reaches the final check and the initially captured engine state’s failure byte is nonzero. |

Return 0 does not imply wildcard processing occurred. Return 1 does not imply rollback. The final failure-byte override applies only to paths reaching that check.

## Behavior

### Entry and source preparation

The engine-state pointer is captured from the context first. If the statement is nonnull, its source-list pointer is captured.

A null statement, null source list, or nonzero initial failure byte returns 1 before preparation dependencies are called. The failure byte is tested only after the statement and source-list conditions permit it.

On the continuing path, the statement’s result-list pointer is captured before F-787923a5a4df receives the context. Later scanning and rebuilding use this captured list even if dependencies change the statement’s result-list field.

Source traversal uses the captured source list. Its signed 16-bit count is reread for each loop condition; source entries advance by 48 bytes.

Each entry’s resolved-descriptor field is inspected before its other preparation branches. If nonzero at that inspection point, the function immediately returns 0. Earlier dependency effects remain; later sources, statement processing, wildcard handling, the column-limit check, and the final failure-byte check are skipped.

For an unresolved source whose named-source identifier is zero:

- If its name field is zero, F-1983453691c7 receives the initially captured engine state, an embedded format value, and the derived-source object. Its result is stored in the source name field.
- F-892de4fc8469 receives the context, the source’s then-current name, and derived-source object.
- Its result is stored in the resolved-descriptor field before being tested.
- Zero returns 1. Otherwise, byte +53 of the returned descriptor is set to 1.

There is no local rejection of a null synthesized name.

For an unresolved source with a nonzero named-source identifier:

- F-3747d6ba198f receives the context, zero, the identifier, and source-entry field +0.
- Its result is installed as the resolved descriptor. Zero returns 1.
- The returned descriptor’s counter at +28 is incremented.
- Its +24 auxiliary field is inspected. Only if that field is zero is byte +57 needed to decide whether auxiliary processing is required.
- If either is nonzero, F-382bffe8f3c1 receives the context and returned descriptor. A nonzero result returns 1.
- Within that auxiliary-processing branch, if the source’s derived-source field is then zero, F-5f042ee1ac4e receives the initially captured engine state and the retained descriptor’s then-current +24 field. Its result is stored in the source’s derived-source field without a null-result check.

The descriptor returned by lookup is retained for these operations; dependencies are not assumed to preserve the source entry’s descriptor field.

### Statement processing and wildcard detection

After source traversal, F-516a8b658c4b receives the context and statement. A nonzero result returns 1 without the final failure-byte check.

Otherwise, detection scans the previously captured result list:

- Its signed 32-bit expression count is captured once as the detection bound.
- Its element-array pointer is loaded for each inspected element rather than captured for the whole scan.
- Scanning stops at the first triggering expression or upon reaching the captured bound.

A trigger is either:

- Kind 107; or
- Kind 112 with a nonnull +12 child of kind 107 and a nonnull +8 child of kind 23.

Without a trigger, this function makes no explicit result-list replacement. That does **not** establish that the statement still points to the captured list: prior dependencies may have replaced its result-list field. The final limit check uses the statement’s current pointer.

### Rebuilding and ordinary-expression transfer

When a trigger exists, the captured original list’s element-array pointer is captured once for rebuilding. All original-element accesses during rebuilding use that retained array base. The original list’s signed expression count is nevertheless reread for every rebuild-loop condition.

A replacement-list pointer starts at zero. The naming policy is captured once from the engine state reached through the context at this time: option bit 0x20 must be set and bit 0x40 clear. This need not be the engine-state object captured at entry. Operations explicitly described as using the initially captured engine continue to use that earlier pointer.

During rebuilding, an expression is expandable if it is kind 107, or kind 112 with a nonnull +12 child of kind 107. The detection requirement that the +8 child be kind 23 is not repeated.

Every other expression is passed to F-a9dcd3e71f90 with **four arguments**, in order: context, current replacement-list pointer, expression pointer, zero. The return replaces the replacement-list pointer.

- A zero return sets the local error result to 1.
- For a nonzero return, the function reads that returned list’s then-current count and array pointer. It writes the original element’s then-current result-name value to the address formed as returned array base plus 12 times returned count, minus 8.
- The original element’s expression and result-name fields are then cleared, including after a zero append result.

Calling that write a write to a “newly appended element” would require an undocumented dependency guarantee. No local check establishes a positive returned count or valid destination storage. The original result-name value is read after the append dependency returns; it is not preserved across that call.

After the rebuild loop, F-e5380ae57ea1 receives the captured original list. Only after that call returns does the function explicitly replace the statement’s result-list field with the replacement pointer, which may be zero. This write can overwrite a statement-field change made by that dependency.

### Wildcard source matching

For an expandable kind-112 expression with a nonnull +8 child, F-e7c4e7dd076d receives the initially captured engine state and the address at child +20. Its result is retained as the qualifier. All other expandable expressions use zero. A zero extraction result therefore produces unqualified matching.

For each source, in source-list order, the function loads its descriptor and chooses a candidate-name pointer:

- Use the source’s alias/synthetic name if nonnull and nonempty.
- Otherwise, use the descriptor’s +0 fallback name.

A zero qualifier selects every source. A nonzero qualifier selects only a source with a nonnull, nonempty candidate name for which F-e6db2171781a returns zero.

The descriptor and candidate-name pointer are retained for that source’s processing, including across the comparison dependency. This retains pointer values, not immutable pointed-to contents.

A match is recorded before column traversal. Zero eligible columns, or failure to construct a column expression, does not undo that match.

Source-loop conditions reread the captured source list’s signed count. Replacing the statement’s source-list pointer does not redirect traversal.

### Column selection and construction

For each selected source, the retained descriptor’s signed column count is reread at every column-loop condition. Its column-array pointer is loaded again for column metadata accesses rather than captured once.

For each index, the column-name value is captured before exclusion and suppression decisions. That value is retained across suppression dependencies and used in subsequent construction, even if dependencies mutate column metadata.

A nonzero exclusion byte omits the column. Otherwise:

- For the first source, neither duplicate-suppression dependency is called.
- For later sources, if the current source’s flag byte has bit 0x04 set, F-d6a5d01d0abb receives the preceding source’s descriptor and captured column name. A nonnegative result suppresses the column.
- If not already suppressed, F-ddd9d804c52f receives the current source’s membership object and captured column name. A nonnegative result suppresses the column. This check also applies when bit 0x04 is clear.

For each included column, F-df6b90a68c3a receives the context, kind 23, and three zero arguments. A zero result stops only this source’s column loop. Otherwise, F-8038671120b6 receives the context, the new expression’s +20 address, and captured column name.

The expression remains unqualified if the retained candidate-name pointer is null, or if the captured naming policy is disabled and the source list’s then-current signed count is less than two. For that form:

1. Expression +32 receives expression +24 with bit 0 cleared.
2. Expression +28 receives expression +20.

Otherwise:

1. Another kind-23 expression is requested with three zero construction operands.
2. A kind-112 expression is requested with that result, the column expression, and zero as its construction operands.
3. A zero kind-112 result stops this source’s column loop.
4. F-8038671120b6 initializes the qualifier expression’s +20 field from the retained candidate-name pointer.
5. F-1983453691c7 receives the initially captured engine state, an embedded format value, candidate name, and captured column name.
6. F-1e9f983b2eb1 receives the kind-112 expression’s +28 address and formatted result.
7. Bit 0 of the kind-112 expression’s +32 field is set; its +20 field, then +24 field, are cleared.

The qualifier-expression constructor’s result is not independently checked before use.

Each completed expression is passed to F-a9dcd3e71f90 with **three arguments**: context, current replacement-list pointer, expression. The return replaces the replacement pointer. Unlike ordinary-expression transfer, a zero return does not directly set the local error result or stop traversal.

Original wildcard element fields are not explicitly cleared by this path.

### Diagnostics and completion

If no source matched a wildcard, F-2022b0f73f3b receives the context and either a no-sources diagnostic or an unknown-source diagnostic carrying the nonzero qualifier. The local error becomes 1.

After each wildcard, F-94cb53877c15 receives the qualifier, including zero.

After optional rebuilding, the statement’s current result-list field is checked. If nonnull, its signed 32-bit count is compared with the initially captured engine state’s signed 32-bit limit. A strictly greater count invokes F-2022b0f73f3b for excessive result columns and sets the local error to 1. Equality is accepted; a null list skips this comparison.

Finally, a nonzero failure byte in the initially captured engine state returns 7. Otherwise, the local result, initially zero, is returned.

## Acceptance examples

These are conditional static cases, not executed tests. All reached memory accesses must be valid.

1. **Null statement:** A readable context and null statement produce 1 without preparation calls.

2. **Existing first descriptor:** If the first source’s descriptor is nonzero when inspected **after** F-787923a5a4df, return 0 follows immediately. Later processing is skipped regardless of the final failure byte.

3. **Existing later descriptor:** If an earlier source is prepared and the next source has a nonzero descriptor at its actual inspection point, return 0 follows. No rollback is performed; dependency effects remain unconstrained.

4. **Lookup failure:** A zero named-source lookup result is stored in the descriptor field before return 1.

5. **No trigger with preserved relevant state:** If dependencies preserve the statement’s result-list pointer and relevant list contents, statement processing succeeds, no trigger exists, the count is within the limit, and the final failure byte is clear, the same list remains installed and return is 0.

6. **No trigger after replacement by a dependency:** If statement processing changes the statement’s list from the captured list to another valid list, detection still scans the captured list. With no trigger there, this function makes no replacement; the limit check examines the other list.

7. **Traversal mutation:** During rebuilding, a dependency’s change to the original count affects the next loop condition. Changing the original array pointer does not redirect rebuilding, because its array base was captured once. Column traversal instead reloads the retained descriptor’s count and array pointer as described above.

8. **Ordinary append destination:** If an ordinary append returns a valid list with count 3 and array base B, the result-name write targets B + 28. This follows from the address calculation, without assuming the dependency actually appended an element.

9. **Expansion ordering:** With relevant traversal state preserved, generated expressions follow original result order, then source order, then eligible column order.

10. **Matched but empty:** A selected source with zero columns or only excluded columns counts as matched and does not itself cause an unmatched-wildcard diagnostic.

11. **Unknown qualifier:** A nonzero qualifier matching no source causes a diagnostic and local error 1, then is passed to F-94cb53877c15.

12. **Final precedence:** Count equal to the limit causes no limit diagnostic; a greater count does. If the final failure byte is nonzero, return 7 overrides either local result. Early-return paths do not apply this override.
