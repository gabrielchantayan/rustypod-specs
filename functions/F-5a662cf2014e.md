# F-5a662cf2014e

## Purpose

F-5a662cf2014e searches a count-indexed collection in descending index order. For each visited entry, it obtains an entry address through F-a583137ba13d and examines a 32-bit unsigned key at byte offset 4.

An entry qualifies when its key equals the requested key. If the fourth argument is zero, an entry also qualifies when its key is strictly less than the requested key. The first qualifying entry in descending index order is returned. An optional output location receives that entry’s index.

This is an index-order search, not an established “closest key” operation. Without an additional collection-ordering invariant, it does not necessarily return the numerically greatest qualifying key.

The description below is based on supplied static evidence. No runtime tests have been performed.

## Behavior

### Initial count read

The function first reads the signed 32-bit count from byte offset 4 of the collection.

That field is read once by this function. The resulting value controls traversal even if the dependency later changes the count stored in the collection. Other possible dependency effects are not constrained by this function.

A zero count causes an immediate zero return, with:

- No dependency call.
- No candidate-key read.
- No output-index write.

### Descending traversal

For a positive count \(N\), the candidate indices are:

\[
N-1,\;N-2,\;\ldots,\;1,\;0.
\]

The decrement occurs before each index is tested for traversal eligibility. Consequently, index \(N\) is never visited.

At each visited index, the function:

1. Calls F-a583137ba13d with the collection reference and that index.
2. Treats the result as the candidate entry address.
3. Reads the unsigned 32-bit key at byte offset 4 of that address.
4. Determines whether the candidate qualifies.
5. Either returns immediately or continues toward the next lower index.

The function neither skips a candidate based on a null dependency result nor requests an alternate candidate after a failed field access. Validity of dependency results is an external precondition.

Traversal stops at the first qualifying index. Lower indices are not visited after a match.

For a positive count and no qualifying candidate, there are exactly \(N\) dependency calls, followed by a zero return. This count assumes execution reaches completion without invalid memory access or other external disruption.

### Qualification and read order

The first key read is compared with the requested key for equality.

If that comparison succeeds, the candidate qualifies regardless of the fourth argument. There is no second key read for this candidate.

If equality fails, the function reads the candidate key field again. This second value is compared with the requested key using unsigned 32-bit ordering. A candidate qualifies through this path only if:

- The second key value is strictly less than the requested key; and
- The fourth argument is zero.

The second key read is therefore part of the displayed behavior even when the fourth argument is nonzero. Equality failure alone leads to the second field evaluation; the mode selector does not guard that read.

There is no intervening dependency call between these two key reads. Nevertheless, the evidence does not establish that the field is immutable, synchronized, or free of externally observable read effects. The two reads must not be described as necessarily returning the same value.

When the field is stable during a visit, the qualification rules simplify to:

| Fourth argument | Qualifying stable key |
|---|---|
| Zero | Key less than or equal to the requested key |
| Nonzero | Key equal to the requested key |

All key ordering is unsigned. A key with its high bit set is not treated as negative.

### Successful return and optional output

Once a candidate qualifies:

- If the fifth argument is nonnull, the current index is written to the pointed-to 32-bit location.
- The candidate address returned by F-a583137ba13d is then returned unchanged.

The output write occurs after the qualifying key reads and before the function returns. No further dependency calls or candidate-key reads occur after that write.

The function does not retain or report the candidate’s key separately.

If the output location aliases collection or candidate storage, the successful output write can modify that storage. No non-aliasing requirement is shown. Any such aliasing must still satisfy the underlying execution environment’s memory-access requirements.

### Unsuccessful return

If traversal finds no qualifying candidate, the function returns zero without writing the optional index output.

A caller must not interpret the output location as having been initialized by an unsuccessful search. Any earlier value remains unchanged by this function’s direct actions. A dependency could independently modify aliased storage; its effects are unknown.

The minimum signed 32-bit count, \(-2{,}147{,}483{,}648\), is different: decrementing it exceeds the signed 32-bit range. 8. **Requested key zero.** With zero mode and stable keys, only key zero can qualify. No unsigned 32-bit key is strictly less than zero.

10. **Null output does not suppress searching.** With a qualifying entry and a null fifth argument, the function still returns the candidate address; it simply omits the index write.
