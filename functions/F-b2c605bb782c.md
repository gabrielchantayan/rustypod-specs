# F-b2c605bb782c

## Purpose

F-b2c605bb782c performs initialization, repeatedly services an application-level work cycle until a polled status requests exit, and then conditionally invokes two cleanup operations.

An optional setup path runs when either of two entry-time byte flags is nonzero. That path constructs a configuration record, obtains an object and an associated resource, and enables an additional operation at the end of each completed work cycle.

**Established behavior:** dependency-call order, explicit record writes, branch conditions, polling behavior, indirect dispatch, and conditional cleanup are visible in the supplied static material.

**Inferred intent:** the routine resembles an application or presentation loop with an optional auxiliary output resource. Names such as “configuration,” “work cycle,” and “cleanup” describe structural roles; they do not establish the dependencies’ internal semantics.

## Behavior

### Initial setup

The following operations occur in order:

1. F-50934d32ec63 is called with argument 1. Its 32-bit result is retained as the main handle.
2. F-6ac70711bbb5 is called. Its result is retained as the main dispatch object.
3. F-a58556c22b6f receives the 44-byte context address, two zero arguments, and the main handle.
4. F-6904f7699031 receives the context address and value 33.
5. F-ec4cfa552cce receives the context address.

Only after these calls does the routine inspect the optional-setup flags. Changes made by those dependencies can therefore affect which setup path is selected.

The optional resource value, optional owner handle, and optional object are initially zero.

### Optional-setup decision

Two byte-sized global flags control this decision:

- The first flag is always read.
- The second flag is read only if the first flag is zero.
- Optional setup runs if the first flag is nonzero, or if the first flag is zero and the second flag is nonzero.
- If both read values are zero, optional setup is skipped.

The read of the second flag is short-circuited. It must not be modeled as an unconditional read.

These flags are not explicitly read again by this routine.

### Optional setup

When selected, optional setup proceeds in this order:

1. F-abc658b0bf5e receives the configuration-record address.
2. F-bb50a072e902 is called with argument 0.
3. Its result is passed to F-5b4ae75440ab together with argument 4. The returned value becomes the optional owner handle.
4. The routine explicitly overwrites the following configuration fields, in the order listed:

| Write order | Byte offset | Width | Value |
|---:|---:|---:|---:|
| 1 | 0 | 8 bits | 2 |
| 2 | 1 | 8 bits | 0 |
| 3 | 40 | 32 bits | 0 |
| 4 | 20 | 32 bits | 320 |
| 5 | 24 | 32 bits | 8 |
| 6 | 36 | 32 bits | 0 |
| 7 | 4 | 32 bits | 0 |
| 8 | 8 | 32 bits | 232 |
| 9 | 12 | 32 bits | 320 |
| 10 | 16 | 32 bits | 8 |
| 11 | 48 | 16 bits | 0 |
| 12 | 45 | 8 bits | 0 |

Fields and gaps not listed are not explicitly overwritten here. Their contents depend on the initializer and any relevant storage state; they must not be described as necessarily zero.

The routine then:

5. Calls F-dcb90cca1e28 with the optional owner handle and configuration-record address.
6. Calls F-c9bd3b9286da with the optional owner handle and argument 1.
7. Calls F-34db8a407b53 with the optional owner handle and retains its result as the optional object.
8. Calls F-6d4e5f4e1b57 with the optional object and argument 4, retaining its result as the optional resource.
9. Calls F-8ff0260f6859 with the optional resource, 5120, and 255.

There are no intervening null checks or error-result branches in this sequence. In particular, the final three-argument call occurs even if the optional resource is zero.

The constants 320 and 5120 are supplied independently. This routine performs no multiplication or range calculation that establishes a relationship between them. A buffer-fill or image-layout interpretation requires dependency evidence.

### Polling and exit

Every potential work cycle begins with polling:

- F-16cf98b2bc95 receives argument 0 and the address of the 32-bit polling-status storage.
- Any nonzero return causes an immediate polling retry.
- A nonzero return does not cause a status-byte exit check or any work-cycle operations.
- Once the dependency returns zero, the low eight bits of the status storage are examined.
- A nonzero low byte exits the loop.
- A zero low byte enters one work cycle.

The upper 24 status bits do not affect this exit decision.

The routine does not explicitly initialize the status before every polling call. On the optional path, an earlier write placed 8 in the same storage, but subsequent dependencies receive addresses through which that storage may be modified. On the non-optional path, no explicit caller-side initialization of this status is shown before the first polling call.

Correct status interpretation therefore depends on the polling dependency’s output contract. A zero return must not be assumed to mean that the dependency necessarily wrote the status unless that behavior is established separately.

There is no retry bound. A dependency that continually returns nonzero prevents work and normal cleanup indefinitely.

### Work cycle

When the accepted polling result has a zero low status byte, the routine performs these operations:

1. Reads the main object’s dispatch-table reference, selects its first callable entry, and invokes it with the main object as the receiver.
2. Calls F-d8deec1d50bf with the main handle and addresses of the two per-cycle output regions.
3. Calls F-ec4cfa552cce with the 44-byte context address.
4. Reads a separate global work-suppression value.

If that global value is zero, the conditional work block below runs. If it is nonzero, the entire block is skipped.

#### Conditional work block

The following sequence is ordered:

1. F-c082dad756a2 receives the temporary conversion region’s address.
2. F-11922d899a44 receives that same address.
3. F-7b22b6f7ba9b receives the current global target value and the preceding dependency’s result.
4. F-7a89f2f7fd9a is called.
5. F-c674000b11df is called.
6. F-f6afb94a2031 is called with 0.
7. F-77db9bc02223 is called.
8. F-f6afb94a2031 is called with 1.
9. F-c0c0b8633623 is called.
10. F-bc4e8f603b51 is called.

The global target is read for step 3, after the first two calls. It must not be treated as an entry-time snapshot.

If the result of F-bc4e8f603b51 is zero, four additional calls occur in order:

1. F-bb50a072e902 with 0.
2. F-5032ac6bc151 with no explicit arguments.
3. F-bb50a072e902 with 1.
4. F-5032ac6bc151 with no explicit arguments.

If that result is nonzero, all four calls are skipped.

The paired arguments 0 and 1 are established; their meanings are not. In particular, the routine does not prove that the second call restores all state changed by the first.

#### Unconditional end-of-cycle operations

After the conditional block, or immediately after bypassing it:

1. F-fdd8589eca2d is called.
2. F-1f1085236108 is called.
3. F-ad249102164e is called.

Then the optional resource is examined:

- If it is zero, no optional end-of-cycle operation occurs.
- If it is nonzero, F-a4d0e9dc80fd is called with that resource and 320.
- If that call returns nonzero, F-1d891874186d is called with the optional owner handle and optional object.
- If it returns zero, the latter call is skipped.

The routine then returns to polling. The optional operation is independent of whether the conditional work block ran.

### Normal exit and cleanup

A nonzero low status byte following a zero polling return exits before any work-cycle operation for that polling result.

Cleanup then occurs in this order:

1. If the optional object is nonzero, its dispatch-table reference is read, the callable entry at byte offset 4 is selected, and that entry is invoked with the optional object as receiver.
2. If the optional owner handle is nonzero, F-ae23f27a31f9 is called with that handle.
3. The routine returns.

The two conditions are independent. An absent optional object does not suppress cleanup of a nonzero owner handle.

No explicit cleanup of the main handle, main dispatch object, 44-byte context, or optional resource is visible here. Their lifetimes may be managed elsewhere, but that is not established by this routine.

## Acceptance examples

These are conditional contract examples, not executed tests. They assume valid objects and dependencies that return normally unless stated otherwise.

1. **Optional setup skipped; immediate exit.**  
   Both setup flags read as zero. The first polling call returns zero and writes status 1. Initial setup occurs, optional setup does not, and no work-cycle indirect dispatch occurs. Both optional cleanup conditions are false.

2. **Short-circuited flag read.**  
   The first setup flag is nonzero. Optional setup runs without reading the second setup flag.

3. **Retry does not accept an exit status.**  
   A polling call returns nonzero while status has a nonzero low byte. The routine polls again rather than exiting. Exit becomes possible only on a polling return of zero.

4. **Only the low byte controls exit.**  
   A zero polling return with status 256 enters a work cycle. A zero polling return with status 257 exits. The differing upper bits do not change this rule.

5. **Suppressed central work.**  
   After the main indirect call, per-cycle output call, and context service, the suppression value is nonzero. The entire conditional block is skipped. All three unconditional end-of-cycle calls still occur, followed by the optional resource check.

6. **Conditional paired operations.**  
   The suppression value is zero. If F-bc4e8f603b51 returns zero, the ordered selector/operation pairs for 0 and 1 occur. If it returns nonzero, neither pair occurs.

7. **Optional resource gate.**  
   A nonzero optional resource causes one F-a4d0e9dc80fd call per completed cycle. A zero result skips F-1d891874186d; a nonzero result invokes it with the stored owner and object.

8. **Independent cleanup gates.**  
   On normal exit, a zero optional object and nonzero owner handle cause only F-ae23f27a31f9. If both are nonzero, indirect object cleanup precedes owner cleanup.

9. **Unbounded polling.**  
   If every polling call returns nonzero, the routine remains in polling. No subsequent work cycle or normal cleanup is reached.
