# F-747c6ec61c11

## Purpose

F-747c6ec61c11 follows a chain of memory records, selects the successor of the first record whose designated flag is clear, and uses fields from that selected successor to construct a three-word memory update and a separate two-byte update. It then invokes an external dependency, issues a software breakpoint, and reaches an invalid-instruction termination boundary in the supplied representation.

This is a source-facing contract for the behavior visible in the supplied static material. It is not a claim that the material accurately reconstructs every executable instruction. The supplied representation explicitly reports problematic instruction decoding and removal of an apparently unreachable region.

The operational purpose of the records, the destination memory, the external operation, and the breakpoint is unknown. Describing the routine as an allocator, dispatcher, serializer, or hardware-control operation would go beyond the available evidence.

## Interface

### Inputs

The declared interface has no explicit parameters and no ordinary return value. Nevertheless, the visible behavior consumes two implicit inputs:

- **An incoming record address.** An incoming machine-register value supplies the initial address for chain traversal. Its initialization, validity, and calling convention are not shown.
- **An incoming 32-bit stack value.** A four-byte value is taken from the stack location represented as an offset of 184 bytes. The relevant stack origin and relationship to any caller-owned frame are not established. This value is copied to destination memory and supplied as an external-call argument.

The stack value is represented as an incoming value rather than an explicit, ordered memory-load operation. Its exact physical load time cannot be established from this material.

| Offset | Width | Use |
|---|---:|---|

Bit numbering in this contract starts at zero at the least significant bit. Traversal tests **bit 21** of the flag word, corresponding to mask **0x00200000**.

### Width and address model

The visible unsigned arithmetic is 32-bit. Right shifts are logical right shifts. Multiplication and left shifts used to construct 32-bit values retain only the low 32 bits.

Record-link accesses are four bytes wide. Subsequent interpretation of those values as addresses is consistent with a 32-bit address model. The supplied material does not independently establish the machine ABI, byte order, address-space mapping, or alignment rules.

## Behavior

### Chain traversal and record selection

Traversal begins at the incoming record address. Each iteration has the following visible ordering:

1. The address of the current record’s flag word is formed.
2. The current record’s four-byte next-record field at offset 16 is read, and traversal advances to that address.
3. The flag word of the **previous** record is read, and bit 21 is tested.

If bit 21 is set, traversal repeats from the newly obtained address. If bit 21 is clear, traversal stops, leaving the newly obtained address as the selected record.

The distinction between the tested record and the selected record is essential:

- The clear flag belongs to the record being left.
- The selected record is that record’s successor.
- The selected record’s flag is not tested merely because it becomes selected.

Consequently, the routine always follows at least one next-record link. It does not process the initial record directly, even when the initial record’s tested flag is clear.

There is no visible null check, cycle check, iteration limit, sentinel-address check, or record-boundary validation. A chain that never presents a clear tested bit does not reach the later operations under an otherwise stable, readable-memory model.

The next-record read precedes the flag-word read within each iteration. This order matters if the memory is volatile, device-backed, concurrently modified, or capable of faulting. The representation supplies no synchronization or snapshot guarantee.

### Selected-record reads

After traversal stops, the selected record supplies three values:

- Its descriptor at offset 12.
- Its four-byte value at offset 16.
- Its payload at offset 4.

The descriptor is read first, followed by the value at offset 16. The payload at offset 4 is read later, immediately for the first destination write.

The selected record’s offset-16 value is copied as data. It is not followed as another traversal link at this stage.

### Three-word destination update

Let **D** denote the selected descriptor interpreted as an unsigned 32-bit value. The destination address is:

**A = ((D shifted right by 4) × 8192) modulo 2³².**

This operation must not be interpreted as an unbounded integer multiplication. High bits can be discarded.

Equivalent bit-level consequences are:

- The destination is a multiple of 8192 under the 32-bit model.
- Only descriptor bits 4 through 22 affect the destination.
- Descriptor bits 0 through 3 and 23 through 31 do not affect it.
- A zero destination is possible.

The routine then performs these writes in order:

| Destination | Width | Written value |
|---|---:|---|
| A | 32 bits | Selected record’s payload at offset 4 |
| A + 4 | 32 bits | Incoming stack value |
| A + 8 | 32 bits | Previously read selected-record value at offset 16 |

Address addition is subject to the target address model. Under the represented 32-bit model, address arithmetic wraps at 2³²; that does not imply that the resulting addresses are mapped or writable.

The first write occurs after the payload read. The second and third writes use already represented values; the third write does not reread the selected record’s offset-16 field.

### Two-byte descriptor-derived update

After the three word writes, the routine derives:

**Q = D shifted right by 8.**

It then writes two bytes at address:

**B = Q + 10.**

The stored 16-bit pattern is the low 16 bits of **Q shifted left by 12**. Equivalently, it is:

**(Q modulo 16) × 4096.**

Thus:

- The stored pattern’s low 12 bits are zero.
- Its high four bits come from descriptor bits 8 through 11.
- The signed interpretation of the two-byte store does not change its bit pattern.
- Q ranges from 0 through 0x00FFFFFF.
- B therefore ranges from 10 through 0x01000009, without 32-bit overflow.

The address is not based on A. The three-word destination and this two-byte destination are separately derived from the descriptor.

No non-aliasing guarantee is visible. The two-byte write may overlap the earlier output area, a source record, or unrelated memory if the descriptor and memory layout cause that overlap. Where overlap occurs, the later two-byte write takes precedence for the overlapping bytes. Exact byte placement depends on target byte order.

### External call

After all four writes, the routine invokes **F-external-01**, a local opaque identifier for the external call target whose identity is not supplied.

The represented arguments, in order, are:

1. The low 32 bits of Q shifted left by 24.
2. The same value as argument 1.
3. The incoming stack value.
4. The constant **0x010E8000**.

The first two argument values depend only on descriptor bits 8 through 15. Those eight bits occupy the high byte of each 32-bit argument; the low 24 bits are zero.

The material establishes the arguments presented by this routine, not the dependency’s actual parameter types, signedness, calling convention, or interpretation of the fourth value. In particular, the fourth value must not be assumed to be an address merely because it has an address-like magnitude.

### Breakpoint and termination boundary

If F-external-01 returns control normally to the represented continuation, the routine next issues a software breakpoint with immediate value **0xB4**.

The representation then ends at an invalid-instruction termination boundary. It does not show a normal return.

The runtime consequences are environment-dependent. A breakpoint handler might terminate execution, transfer control elsewhere, or permit resumption. Invalid-instruction handling is likewise not specified. The static material does not justify promising process termination, a particular signal, or a particular exception type.

## Acceptance examples

These examples are conditional static acceptance cases, not executed tests. Unless otherwise stated, they assume valid accesses, stable source memory, sufficient alignment for the target, and no unexpected interruption.

### Clear flag selects the successor

Suppose an initial record links to a second record and has bit 21 clear.

Expected behavior:

- Read the initial record’s link.
- Read and test the initial record’s flag.
- Select the second record.
- Obtain the descriptor, copied link value, and payload from the second record.

Processing the initial record’s payload instead would violate the visible selection rule.

### Set flag advances traversal

Suppose a first record links to a second and has bit 21 set. The second links to a third and has bit 21 clear.

Expected behavior:

- Test the first record after reading its link.
- Continue to the second.
- Read the second record’s link before testing its flag.
- Select the third record.
- Do not test the third record’s flag as part of this terminating traversal step.

### Concrete descriptor transformation

For selected descriptor **0x00001234**:

| Derived item | Expected value |
|---|---:|
| Descriptor shifted right by 4 | 0x00000123 |
| Three-word destination A | 0x00246000 |
| Q | 0x00000012 |
| Two-byte destination B | 0x0000001C |
| Stored 16-bit pattern | 0x2000 |
| First external argument | 0x12000000 |
| Second external argument | 0x12000000 |

The three word writes occur before the two-byte write. The external call occurs after all four writes, provided execution reaches it.

### Descriptor high-bit truncation

Descriptors **0x00000010** and **0x80000010** both produce destination **0x00002000** under the 32-bit arithmetic model.

They do not produce identical two-byte destination addresses:

- The former produces Q equal to zero and B equal to 10.
- The latter produces Q equal to 0x00800000 and B equal to 0x0080000A.

Matching three-word destinations therefore do not imply matching complete behavior.

### Clear flag with an invalid successor

If the initial record’s flag is clear but its next-record value is zero, the routine still selects address zero. It attempts selected-record reads relative to that address.

There is no visible special handling for a null successor. The resulting runtime behavior depends on whether those addresses are accessible.

### No terminating flag

For a stable cycle in which every visited record has bit 21 set, traversal repeats without reaching the output writes. No cycle error or timeout is produced by the visible routine.

### External nonreturn

If F-external-01 does not return, the visible breakpoint is not reached through the represented continuation. The local writes have already occurred, but the dependency may subsequently alter their contents.
