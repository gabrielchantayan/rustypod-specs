# F-55961b0fa776

## Purpose

F-55961b0fa776 updates caller-supplied destination storage using one of two paths selected by a 32-bit status field:

- The sentinel path invokes F-46f0b3cb316e using a globally referenced source address, then copies a separate 32-bit field from an earlier captured source address.
- The non-sentinel path invokes an object-associated indirect dependency using initialized temporary storage, invokes F-46f0b3cb316e using that storage, writes a field to the destination, and invokes F-ee5919ca4be6.

Both paths explicitly write a 32-bit word at destination byte offset 12. Both call F-46f0b3cb316e with destination byte offset 4 as its first argument. The operation and access extent of that dependency are unknown.

The sentinel path uses **two distinct reads of the same global reference**. The first supplies the address for the later explicit field read. The second supplies the address used to construct F-46f0b3cb316e’s source argument. The two reads are not established to return equal values.

The function returns a 64-bit composite formed from two words in temporary storage. That result is distinct from the destination update.

These are established mechanics. The application-level meanings of the object, status, source data, and return value remain unknown.

## Behavior

### Preparation and selection

The function first reads the global reference and captures its address value.

It then initializes the temporary words from the four inputs, in input order. After initialization, it reads the subordinate address at object byte offset 64 and then the status word at subordinate byte offset 20.

The sentinel condition is equality with the 32-bit pattern `0xFFFFFFFF`, represented as −1. Every other status selects the non-sentinel path. Zero and negative values other than −1 have no separate visible handling.

There is no explicit null check, alignment check, bounds check, or destination-capacity check before the corresponding accesses.

### Sentinel path

When the status is `0xFFFFFFFF`, the established sequence is:

1. Read the global reference again.
2. Invoke F-46f0b3cb316e with:
   - The original destination address plus 4.
   - The address obtained from the second global-reference read plus 4.
3. After that dependency returns normally, read four bytes at offset 12 from the address captured by the **initial** global-reference read.
4. Write that word to the original destination address plus 12.
5. Form the 64-bit return from the current temporary words at offsets 0 and 4.

The second global read is not replaced by the initially captured value. Conversely, the explicit source-field read is not redirected to the address obtained by the second read.

Consequently, if the initial global read yields one source address and the second yields another, F-46f0b3cb316e receives an address into the second source while the explicit field read accesses the first source.

The explicit offset-12 source read occurs after F-46f0b3cb316e. It therefore observes that field at the later read point, not as a snapshot taken during preparation. A dependency modification to the initially captured source can affect the explicit destination write.

Changes to the global reference during F-46f0b3cb316e do not themselves redirect either address already selected for this invocation. There is no third explicit global-reference read.

Neither the indirect dependency nor F-ee5919ca4be6 is invoked on this path.

No temporary-region address is explicitly passed to the dependency on this path. If the temporary words are not otherwise modified, the return contains the original object-address bits in its low half and the original destination-address bits in its high half. The caller alone does not establish unconditional preservation against all dependency-accessible aliases or other effects.

### Non-sentinel path

For every other status, the established sequence is:

1. Read the table address from the first object word and obtain the indirect-call target at table byte offset 332.
2. Invoke that target with the temporary-region base address and the original object address.
3. After normal completion, invoke F-46f0b3cb316e with the original destination address plus 4 and the temporary-region address plus 4.
4. After normal completion, read the temporary word at byte offset 12.
5. Write that word to the original destination address plus 12.
6. Invoke F-ee5919ca4be6 with the temporary-region base address.
7. After normal completion, assemble the return from the current temporary words at offsets 0 and 4.

There is no second explicit global-reference read on this path.

The destination addresses remain based on the original second input. Changing temporary offset 4 does not redirect either destination operation.

The explicit destination field comes from temporary offset 12 after F-46f0b3cb316e returns. It is not necessarily the original fourth input or the value left by the indirect dependency.

F-ee5919ca4be6 runs after the explicit destination write but before return assembly. Its changes to temporary offsets 0 or 4 therefore affect the return. Its unknown effects could also modify destination storage; the explicit write is not a guarantee of final destination contents after all dependency effects.

The direct return values of all dependencies are unused in the supplied representation.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. They assume valid required accesses and normal dependency completion unless stated otherwise.

- F-46f0b3cb316e receives destination plus 4 and that source plus 4.
- The explicit field read uses that source plus 12 after the dependency returns.
- Neither the indirect dependency nor F-ee5919ca4be6 runs.

### Different global observations

- F-46f0b3cb316e receives source B plus 4.
- The subsequent explicit field read uses source A plus 12.

If A’s offset-12 word is `0x11111111` at the explicit read and B’s is `0x22222222`, the explicit destination write uses `0x11111111`. Using B’s field merely because B supplied the dependency argument would violate the represented behavior.

### Post-call field observation

This remains true whether the dependency’s source argument points into A or a different source B.

### Global replacement during the dependency
