# F-98a2c6875ccd

## Purpose

F-98a2c6875ccd performs a guarded dispatch and records a status value through a location obtained from a dependency.

The established behavior is:

- Reject a null second argument.
- Otherwise, compare a 32-bit unsigned field in the referenced object against a global 32-bit unsigned threshold.
- Reject a field value greater than or equal to that threshold.
- For an eligible object, call a preliminary dependency. Only a zero result permits an indirect callback.
- Report success only if both the preliminary dependency and the callback return zero.
- On every normally completing path, obtain a status-storage address, write the selected 32-bit status there, and return a separate 32-bit success or failure value.

The first argument has no observable use in the supplied evidence.

The apparent intent is to validate an object’s numeric field before invoking a service and to publish an error-like status afterward. The meanings of the field, threshold, service, and status storage are not established.

## Behavior

### Eligibility and direct rejection

For a null second argument, the function does not read the object field or the threshold. It selects failure with status 26 and proceeds to status publication.

For a non-null second argument, the observable direct-read order is:

1. Read the 32-bit unsigned field at object byte offset 4.
2. Read the global 32-bit unsigned threshold.
3. Compare the captured values using unsigned ordering.

Eligibility requires the field to be strictly less than the threshold. Equality is rejection.

An ineligible object produces failure with status 26. Neither F-eb5289d344f1 nor the indirect callback is invoked on that path.

There is no visible subtraction, scaling, or range normalization in the comparison. Values with the high bit set remain unsigned values for eligibility; they are not treated as negative.

### Preliminary dependency

For an eligible object, F-eb5289d344f1 is called with a single zero argument.

Its result is interpreted as a 32-bit status:

- Zero permits indirect dispatch.
- Any nonzero result prevents indirect dispatch and becomes the status published at the end.

A nonzero preliminary result produces `0xFFFFFFFF` as the function’s return value regardless of the result’s sign or magnitude. The status retains the dependency’s result rather than being replaced with a generic failure code.

The object field and threshold are not read again after this call. Consequently, mutations performed by the dependency do not cause this function to repeat its eligibility test.

### Indirect dispatch

The indirect callback is invoked only after eligibility succeeds and F-eb5289d344f1 returns zero.

The callback target is resolved through a global dispatch reference and the function-pointer entry at byte offset 16 from the referenced location. This lookup occurs after the preliminary call. The evidence does not support assuming that the preliminary dependency preserves this global state.

The callback receives three arguments, in order:

1. Zero.
2. The original second argument, unchanged.
3. Zero.

The first argument supplied to F-98a2c6875ccd is not used as a callback argument.

The callback result determines both the selected status and the success/failure classification:

- Zero selects return value `0x00000000` and status zero.
- Any nonzero result selects return value `0xFFFFFFFF` and that nonzero status.

There is no visible retry, fallback callback, secondary eligibility check, or callback-result translation.

### Final status publication

After the path-specific status and return value have been selected, F-4af36158f863 is called without arguments. The function then writes the selected status as a 32-bit value at the returned address.

This step occurs on every path that reaches normal completion, including success.

The order matters:

- Direct rejection is followed by F-4af36158f863 and then the status store.
- Preliminary failure is followed by F-4af36158f863 and then the status store.
- A callback result is followed by F-4af36158f863 and then the status store.

The final store therefore occurs after any side effects of F-4af36158f863. It can overwrite an earlier value that a dependency placed at the same location.

The return value and status have already been selected before this final dependency is called. The function does not visibly reread the threshold, object field, or dispatch reference afterward.

### Integer and address semantics

Dependency results and the final status store have 32-bit representation. Only zero versus nonzero affects success. No arithmetic is performed on dependency results, so a negative signed status is neither negated nor converted to its absolute value.
