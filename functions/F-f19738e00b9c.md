# F-f19738e00b9c

## Purpose

F-f19738e00b9c selects an opaque 32-bit value, installs it into a shared state record, optionally obtains a replacement through two dependencies, and writes a one-byte state indicator.

Two request values are supported:

- **0:** install a designated baseline value and write indicator **0**.
- **1:** select a designated value according to a selector byte, install it, optionally perform two dependent calls, and write indicator **1**.

Other requests, and rejected selector observations for request 1, produce the 32-bit all-ones return pattern without direct record writes.

The installation destination and the destination of later accesses are not necessarily identical. The function captures the shared record reference at entry, but both requests perform their initial 32-bit installation through the shared reference rather than the captured reference. Later control-byte reads, transformation-input reads, transformed-result writes, and indicator writes use the captured reference.

An application-level interpretation such as “enable” or “disable” is **inferred intent**, not established behavior.

## Behavior

### Entry and reference handling

Before request dispatch, the function captures the shared state-record reference.

The function subsequently uses references as follows:

| Operation | Reference used |
|---|---|
| Request 0 baseline installation | Shared reference used at installation |
| Request 1 selector comparisons | Shared reference used for each comparison |
| Request 1 selected-value installation | Shared reference used at installation |
| Request 1 transformation-control read | Entry-captured reference |
| Request 1 transformation-input read | Entry-captured reference |
| Request 1 transformed-result write | Entry-captured reference |
| Final indicator write for either supported request | Entry-captured reference |

With a stable shared reference, these accesses concern the same record. Otherwise, selector observations, initial installation, and later operations need not concern the same record.

This distinction does not establish that concurrent mutation is supported or well-defined. It identifies the source-level destinations and operands. No synchronization mechanism is shown.

### Request 0

For request 0, the function:

1. Installs the designated baseline value into the four-byte field at offset 24 through the shared reference.
2. Writes indicator byte 0 at offset 0 through the entry-captured reference.
3. Returns 0x00000000.

The baseline installation precedes the indicator write.

This path does not explicitly read the selector or transformation-control byte and calls neither dependency. Their values do not affect request acceptance.

If the installation destination differs from the captured record, one record receives the baseline value and the captured record receives indicator 0. The function does not separately install the baseline into the captured record.

### Unsupported requests

A request unequal to both 0 and 1 returns 0xFFFFFFFF.

The shared reference has already been captured, but this path performs no explicit record-field access, no direct record write, and no dependency call. It does not consult selector or control bytes.

Capturing the reference is not itself a dereference of the record.

### Request 1: selection

Selection uses exact byte comparisons and short-circuit evaluation:

- The selector-0 candidate is obtained before the first selector comparison.
- If the first selector observation equals 0, the selector-0 candidate is chosen.
- Otherwise, the selector-1 candidate is obtained and another selector comparison is performed.
- If the second selector observation equals 1, the selector-1 candidate is chosen.
- Otherwise, the request returns 0xFFFFFFFF.

Each selector comparison addresses offset 2 through the shared reference. There is no single saved selector snapshot.

With a stable reference and stable selector, only selector values 0 and 1 are accepted. If observations differ, acceptance follows the comparisons actually reached. For example, a first observation of 2 followed by a second observation of 1 selects the selector-1 candidate. A first observation of 1 followed by a second observation of 0 rejects the request.

These are source-expression sequencing facts, not guarantees of machine-level load counts or hardware ordering.

On selector rejection, the function performs no initial installation, does not read the captured record’s control byte, calls neither dependency, and does not write the indicator.

### Request 1: initial installation and control decision

After selection succeeds, the function installs the selected 32-bit candidate at offset 24 **through the shared reference used at installation**.

Only after this installation does it read the transformation-control byte at offset 1 **through the entry-captured reference**.

If the control byte is not exactly 1:

- Neither dependency is called.
- Indicator byte 1 is written through the captured reference.
- The function returns 0x00000000.

The control byte is not interpreted as a general nonzero Boolean. Values 0, 2, and 255 all bypass transformation.

If the installation destination differs from the captured record, this path does not directly update the captured record’s four-byte field. It still reads that record’s control byte and writes that record’s indicator.

### Request 1: transformation

If the captured record’s control byte equals exactly 1, the function performs this sequence:

1. Reads the four-byte field at offset 24 from the captured record.
2. Calls F-f2b8ff34d9f0 with that read value and the numeric literal 2.
3. After the first call returns, calls F-450415463608 with the first result and the designated ambient 32-bit argument.
4. Stores the second result into the captured record’s four-byte field.
5. Writes indicator byte 1 into the captured record.
6. Returns 0x00000000.

The first dependency receives a fresh read from the captured record, not a retained copy of the selected candidate.

That input equals the newly installed candidate only when the installation destination is the captured record and no intervening effect changes the relevant field. Absence of mutation between installation and the input read is insufficient if installation targeted a different record.

The ambient argument for the second call is obtained after the first dependency returns. The function does not establish that the first dependency preserves its storage or value.

The transformation-control byte is not re-read after either dependency call. The shared reference is not used to redirect the final transformed-result or indicator writes: both target the entry-captured record.

## Side effects

### Direct writes and ordering

| Path | Ordered direct writes |
|---|---|
| Request 0 | Baseline value through the shared reference; indicator 0 through the captured reference |
| Request 1, accepted selector, control not 1 | Selected value through the shared reference; indicator 1 through the captured reference |
| Request 1, accepted selector, control 1 | Selected value through the shared reference; second dependency result through the captured reference; indicator 1 through the captured reference |
| Rejected request or selector | None |

Value writes address offset 24 and occupy four bytes. Indicator writes address offset 0 and occupy one byte. This function does not directly write the selector or control bytes.

The initial installation occurs before the function’s final indicator write and, on the transformation path, before either dependency call. The record receiving that intermediate installation is the installation destination, which need not be the captured record.

A dependency able to access the installation destination may observe the installed candidate. A dependency examining the captured record is not guaranteed to observe that candidate unless both references designate the same record and the field has not subsequently changed.

Dependency side effects may introduce additional reads and writes. They are not constrained by the table.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. Unless an example says otherwise, assume accessible memory, a stable shared reference, no external mutation, no relevant ambient aliasing, and normal dependency return.

1. **Baseline request ignores selector and control.**  
   Request 0 installs the baseline at offset 24, writes indicator 0, and returns 0x00000000. Arbitrary selector and control values do not cause dependency calls.

2. **Selector 0 without transformation.**  
   Request 1 with selector 0 and control 0 installs the selector-0 value, writes indicator 1, and returns 0x00000000 without calls.

3. **Nonzero control does not necessarily transform.**  
   Request 1 with selector 1 and control 2 installs the selector-1 value and writes indicator 1 without calls. Control 255 has the same branch outcome.

4. **Transformation with a common destination.**  
   When installation targets the captured record, control is 1, and the field remains unchanged before the transformation-input read, F-f2b8ff34d9f0 receives the selected candidate and 2. If the dependencies return values A and B respectively, F-450415463608 receives A, B is stored into that record, and indicator 1 is written afterward.

5. **Different installation and captured records without transformation.**  
   Suppose entry captures record A, but the shared reference used for installation designates record B. With accepted selection and A’s control byte not 1, B receives the selected candidate and A receives indicator 1. This function makes no direct write to A’s four-byte field on that path.

6. **Different records change the transformation input.**  
   Under the same reference divergence, let A’s control byte be 1 and A’s field contain X at the input read. B receives the selected candidate, but F-f2b8ff34d9f0 receives X and 2. The second dependency’s result is stored in A, followed by A’s indicator write. B’s installation does not imply that X equals the candidate.

7. **Baseline installation can also split destinations.**  
   If entry captures A and the baseline installation uses B, request 0 writes the baseline into B and indicator 0 into A. It does not directly overwrite A’s four-byte field.

8. **Dependency sentinel values do not cause local rejection.**  
   A normal second-dependency return of 0xFFFFFFFF is stored into the captured record. The function still writes indicator 1 and returns 0x00000000.

9. **Unsupported selector rejects without writes.**  
   With request 1 and a stable selector of 2 or 255, the return is 0xFFFFFFFF. No control-byte read, dependency call, installation, or indicator write occurs.

10. **Unsupported request bypasses record fields.**  
    A request unequal to 0 and 1 returns 0xFFFFFFFF after reference capture, without explicit record-field access.

11. **Dependency changes do not redirect final destinations.**  
    If a dependency changes the shared reference while leaving the captured record valid, the final result and indicator writes still target the captured record. The dependency’s own effects remain unconstrained.
