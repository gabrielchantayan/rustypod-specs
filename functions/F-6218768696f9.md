# F-6218768696f9

## Purpose

F-6218768696f9 performs a fixed sequence of unsigned, multiword arithmetic operations using four explicit 32-bit inputs, two additional machine-state words, and a byte-valued lookup table. It constructs a sign field and an extended arithmetic result, then either:

- Returns the sign field directly when the final upper accumulator has its most significant bit set; or
- Transfers control through an entry-state-derived target, passing four constructed 32-bit arguments, and returns that target’s result.

**Inferred intent:** The reciprocal approximation, repeated product subtraction, remainder corrections, sign extraction, and exponent-like adjustment are consistent with a software numeric division operation. The supplied material does not establish a complete numeric representation, rounding mode, or public arithmetic API. This contract therefore specifies the observable machine-word behavior without asserting correctly rounded division or conformance to a floating-point standard.

## Interface

### Explicit inputs

The visible interface accepts four unsigned 32-bit words, designated here by argument position:

| Input | Established use |
|---|---|
| First argument | Supplies one sign bit and a low-24-bit field used in the eventual indirect-call arguments. |
| Second argument | Supplies arithmetic data, including its upper 16 bits, a right-shifted value, and its least significant bit. |
| Third argument | Supplies arithmetic data through a right shift and a separate least-significant-bit contribution. |
| Fourth argument | Supplies the other sign bit and a low-24-bit field used in the eventual indirect-call arguments. |

For the first and fourth arguments, bits 24–30 do not participate in the visible computation. Their bit 31 values participate only in sign construction; their low 24 bits participate only in the final indirect-call field adjustment.

### Additional entry-state inputs

The four explicit arguments are not sufficient to reproduce the behavior. Three additional entry-state values are used:

- A 32-bit word held in entry register R4.
- A 32-bit word held in entry register R5.
- An entry link-register value used to derive an indirect control-transfer target.

The R4 and R5 words are each split into unsigned upper and lower 16-bit halves for partial-product arithmetic. Their combined use is consistent with a two-word divisor, with R4 supplying the more significant word and R5 the less significant word. That divisor interpretation is inferred; the use of both words and their halves is established.

### Output

The visible return value is one unsigned 32-bit word:

- On the direct-return path, it is either `0x00000000` or `0x80000000`.
- On the indirect-transfer path, it is the 32-bit result returned by dependency **F-UNKNOWN-01**, if that dependency returns normally.

The available interface does not establish any additional return registers, output buffers, status values, or exception flags.

For execution to complete through the indirect-transfer path:

## Behavior

### Word arithmetic

Except where the final signed condition is evaluated, the visible arithmetic is unsigned and 32 bits wide.

- Addition, subtraction, multiplication, and left-shift results retain only the low 32 bits.
- Right shifts of unsigned values introduce zeros.
- A multiplication followed by a right shift uses the wrapped 32-bit product, not an implicitly widened product.
- Byte extraction retains eight bits.
- Upper- and lower-half decomposition retains sixteen bits per half.
- Carry predicates report overflow beyond bit 31 of an unsigned addition.
- Boolean values contribute integer zero or one when included in arithmetic.

These width rules are essential. An implementation that silently promotes every product to 64 bits before shifting can produce a different result.

The upper accumulator is ultimately tested by its sign bit. The nonnegative branch is taken when that bit is clear, including when the entire upper accumulator is zero.

### Sign and initial data alignment

The sign field is `0x80000000` exactly when the first and fourth arguments have different bit-31 values. Otherwise it is zero.

The second and third arguments are aligned across word boundaries for the subsequent arithmetic. The construction preserves:

- The second argument shifted right by one.
- A middle word containing the third argument shifted right by one, with the second argument’s least significant bit moved into bit 31.
- A lower-word contribution containing the third argument’s least significant bit in bit 31.

The last contribution is zero when the third argument is even and `0x80000000` when it is odd. Discarding either low input bit before this alignment changes the arithmetic.

### Lookup and reciprocal-like estimate

The first explicit data-memory access is a single unsigned byte read from the table based at `0x0803726c`. The index is the high byte of entry R4.

Consequently:

- The index is between 0 and 255.
- The selected address is between `0x0803726c` and `0x0803736b`.
- The lookup does not depend on entry R5 or any explicit argument.
- The table contents are inputs to the behavior, not constants recoverable from the supplied material.

The byte is used with the upper half of entry R4 to form an initial estimate. This estimate is refined using entry R4 shifted right by 13 bits and fixed scaling constants. The refinement uses 32-bit wraparound arithmetic throughout, including subtraction from fixed powers of two and wrapped products before right shifts.

This is a fixed computation. There is no visible convergence test, retry, or data-dependent iteration count.

### Quotient-like accumulation and residual updates

The arithmetic proceeds through a fixed series of estimate-and-subtract stages.

The stages combine:

- The reciprocal-like estimate.
- Selected upper portions of the current residual.
- Upper and lower 16-bit halves of the two entry-state arithmetic words.
- Explicit carry and borrow conditions.

An initial contribution is estimated from the upper half of the second argument. A further contribution is estimated from a shifted residual. Later contributions repeat this pattern using updated residuals.

The partial products are applied at several fixed alignments, including 16-bit, 19-bit, and 3-bit offsets. Residual fields are also repacked using six-bit and eighteen-bit right shifts paired with corresponding left shifts of neighboring fields. These operations preserve selected cross-word information; they are not independent calculations on isolated words.

Carry and borrow propagation is observable through its effect on the final result. In particular:

- Low-word comparisons determine whether a higher-word subtraction must include an additional one.
- Some comparisons are conditional on whether an earlier subtraction can proceed without borrowing.
- The calculation explicitly accumulates carries from separately constructed result contributions.
- Replacing this sequence with ordinary integer division is not established as equivalent.

The resulting arithmetic state contains an upper accumulator, a middle accumulator, and a lower accumulator, together with residual information used for final corrections.

### Final corrections and sticky information

After the estimate-based stages, the routine performs three fixed correction decisions against the two-word quantity assembled from entry R4 and entry R5.

The first decision conditionally subtracts that quantity from the current retained residual. Two subsequent decisions double retained residual information, propagate carry contributions, and conditionally subtract again.

Each decision contributes one binary outcome. The three outcomes are assembled into a three-bit correction field occupying bits 28–30 of a 32-bit contribution. This contribution is added to an existing lower accumulator, with carry propagated into the middle and upper accumulators.

A separate sticky indication is also formed:

- After the two doubling-and-correction steps, the routine checks two retained residual words.
- If either word is nonzero, bit 0 of an existing lower contribution is set.
- If both are zero, that operation leaves bit 0 unchanged.

This is specifically a check of the retained residual words visible at that point. The supplied material does not establish that this test is equivalent to testing an unlimited-precision mathematical remainder.

### Final branch and transfer arguments

The upper accumulator combines the earlier estimate contributions and carries from lower accumulators. Its bit 31 selects the terminal behavior.

**Upper accumulator with bit 31 set:**  
The function returns the sign field directly. It does not invoke F-UNKNOWN-01.

**Upper accumulator with bit 31 clear:**  
The function invokes F-UNKNOWN-01 at the address obtained by clearing the entry link register’s lowest two bits. The four visible arguments are:

1. The sign field.
2. The upper word of the three-word accumulator after a one-bit left shift with carry propagated from the lower words.
3. The middle word of that same shifted accumulator, including the carry from doubling the lower word.
4. The first argument’s low 24 bits, minus the fourth argument’s low 24 bits, plus `0x3ffe`, reduced modulo \(2^{32}\).

Only the upper and middle words of the shifted accumulator are explicitly passed in this visible interface. The available material does not justify adding an implicit fifth argument containing its lower word.

If F-UNKNOWN-01 returns normally, its result is returned unchanged.

## Acceptance examples

These examples are conditional static acceptance criteria, not results of runtime tests.

### Sign-only direct return

Given any inputs and table byte that produce an upper accumulator with bit 31 set:

- Matching sign bits in the first and fourth arguments require a return of `0x00000000`.
- Different sign bits require a return of `0x80000000`.
- F-UNKNOWN-01 must not be invoked.

Other computed accumulator fields do not replace the sign-only result on this branch.

### Equal low-24-bit fields

If the first and fourth arguments have equal low-24-bit fields and execution reaches F-UNKNOWN-01, its fourth argument must be `0x00003ffe`.

This remains true if those arguments differ in bits 24–31. Differences in bit 31 can independently change the first transfer argument.

### Ignored explicit-input bits

With all other inputs and external state fixed, changing only bits 24–30 of the first or fourth argument must not change the visible arithmetic, branch selection, or constructed transfer arguments.

Effects originating inside a runtime-selected dependency remain subject to that dependency’s own unknown behavior.

### Lookup boundaries

An entry R4 high byte of `0x00` selects the byte at the table base. A high byte of `0xff` selects the byte 255 positions after that base.

Changing lower bits of R4 while preserving its high byte preserves the selected lookup address, but need not preserve the arithmetic result.

### Wrapped field subtraction

If the first argument’s low 24 bits are zero and the fourth argument’s low 24 bits are `0x004000`, then the fourth transfer argument, if a transfer occurs, is `0xfffffffe`.

The subtraction is modular, not clamped to zero and not rejected as an invalid exponent.

### Sticky contribution

If either retained residual word is nonzero at the final residual check, the lower contribution must have bit 0 set before the correction contribution is added.

If both retained words are zero, the check must not force bit 0 to one. It does not independently clear a bit that was already set.

### Indirect return propagation

If the upper accumulator has bit 31 clear, the selected dependency returns normally, and its returned word is `0x12345678`, then F-6218768696f9 must return `0x12345678`.

There is no visible post-call sign insertion or additional rounding step in this function.
