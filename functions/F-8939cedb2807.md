# F-8939cedb2807

## Purpose

F-8939cedb2807 classifies a 32-bit input after clearing bit 13, whose mask is `0x00002000`. It returns one of seven 32-bit values: `0`, `1`, `2`, `4`, `8`, `0x10`, or `0x20`.

The classification depends on two externally supplied values, described here as **boundary A** and **boundary B**. These are data dependencies, not function dependencies. Their contents are not supplied, so the function cannot be specified accurately as a single unconditional table of input constants.

**Established behavior:** the function performs normalization, equality checks, signed ordering checks, and selected constant comparisons. It contains no explicit memory writes and invokes no other functions.

**Inferred intent:** it appears to translate encoded identifiers into a smaller set of category values, while ignoring one input flag bit. Neither the meaning of the identifiers nor the meaning of the returned categories is established.

## Behavior

### Normalization and numeric interpretation

The normalized value is the input with bit 13 forced to zero.

Consequently, inputs that differ only in bit 13 follow the same classification path when the external values observed during their executions are the same. For example, inputs `0x00000001` and `0x00002001` both normalize to `0x00000001`.

Normalization does not constrain the value to a positive signed range. A normalized value whose bit 31 remains set is negative for the ordering checks.

All constants used as return values are small positive values. Signedness therefore does not change the numeric interpretation of any possible result.

### First boundary: equality has priority

The function first compares the normalized value with boundary A.

If they are equal, the result is `0x10`. No boundary-B check or constant-specific classification is reached.

This equality check takes priority even when the normalized value is also one of the constants assigned a different result in another region. For example, if boundary A equals `1`, an input normalizing to `1` returns `0x10`, not `1`.

If the equality check fails, the function compares the normalized value with boundary A using signed 32-bit ordering.

### Region below boundary A

If the normalized value is signed-less-than boundary A at the ordering check, the function classifies it using the following table:

| Normalized value | Result |
|---|---:|
| `0x00000001` | `1` |
| `0x00000002` | `2` |
| `0x00000004` | `4` |
| `0x00000008` | `8` |
| `0x00000064` | `8` |
| `0x00000065` | `0x10` |
| Any other value in this region | `0` |

Within this region, the visible comparison order is:

1. Equality with `8`.
2. Signed ordering relative to `8`, if unequal.
3. On the side greater than `8`, equality with `0x64`, then equality with `0x65` when needed.
4. On the side less than `8`, equality with `1`, then `2`, then `4` when needed.

These internal checks do not read further external state. Their ordering therefore does not add another state dependency.

Boundary B is not read on this path.

### Second boundary: equality also has priority

If the normalized value was unequal to boundary A and was not signed-less-than boundary A, the function compares it with boundary B.

Equality with boundary B returns `0x10`.

If unequal, the function performs a signed 32-bit ordering comparison with boundary B. That comparison selects one of the two remaining classification regions.

### Region below boundary B

When execution has reached boundary B, failed its equality check, and found the normalized value signed-less-than boundary B, the classification is:

| Normalized value | Result |
|---|---:|
| `0x00000565` | `0x10` |
| `0x00001444` | `0x10` |
| `0x00001888` | `0x20` |
| Any other value in this region | `0` |

The check for `0x1444` is represented indirectly: subtracting `0x1400` in byte units and comparing the result with `0x44`. Under the represented 32-bit numeric model, this identifies `0x1444`. It does not read memory at that value.

The subtraction is skipped when the normalized value is `0x565`. The `0x1888` comparison is reached only if neither of the first two values matched.

### Region not below boundary B

When execution has reached boundary B, failed its equality check, and found the normalized value not signed-less-than boundary B, the classification is:

| Normalized value | Result |
|---|---:|
| `0x0000C422` | `0x10` |
| `0x0000D444` | `0x20` |
| Any other value in this region | `0` |

With stable boundaries, this region is strictly above boundary B because equality has already returned. If external values can change between checks, the operative condition is instead the outcome of each individual read and comparison.

### Boundary relationships and reachability

The supplied evidence does not establish that boundary A is less than boundary B.

No implementation of this contract may silently reorder the boundaries, enforce their ordering, or assume every region is reachable.

For stable boundaries, the regions are:

- Equality with boundary A: immediate `0x10`.
- Signed-less-than boundary A: the small-value table.
- Otherwise, equality with boundary B: `0x10`.
- Otherwise, signed-less-than boundary B: the `0x565`, `0x1444`, and `0x1888` table.
- Otherwise: the `0xC422` and `0xD444` table.

If boundary A exceeds boundary B in signed ordering, the region below boundary B after passing boundary A may be unreachable. That is a consequence of the comparisons, not a separate error condition.

Because normalization always clears bit 13, a boundary whose bit 13 is set cannot equal any normalized input. Such a boundary still participates in signed ordering.
