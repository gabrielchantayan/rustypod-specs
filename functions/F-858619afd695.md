# F-858619afd695

## Purpose

F-858619afd695 selects between two behaviors using the low bit of a byte in its input object:

- **Bit clear:** search an owner-associated singly linked list for the input object, unlink the first matching occurrence, and return the remaining head. If the post-search head is null and the third argument is nonzero, invoke two dependencies using a temporary record and return the record’s resulting first word.
- **Bit set:** return the input object unchanged if the second argument is zero. Otherwise, apply eligibility and index checks, optionally decrement an indexed counter, and conditionally update an accumulator and an entry marker.

These behaviors are established by the supplied static representation. Terms such as “owner,” “context,” “counter,” and “entry” identify structural roles; they do not establish application-level types, ownership, or lifecycle semantics.

No runtime tests have been performed.

## Behavior

### Selection and bypass

The function reads the byte at input offset `0x1D` and tests only bit `0x01`.

If that bit is set and the second argument is zero, the function immediately returns the input pointer. It makes no dependency call and performs no explicit write. The third argument has no effect on this path.

### Bit clear: list search and removal

The second argument is unused.

The function reads the owner pointer from input offset `0x20`, then reads the owner’s head at offset `0x24`. It traverses by pointer identity while retaining the preceding node:

- A null current pointer ends the search.
- A current pointer equal to the input pointer causes removal.
- Otherwise, the current node’s next pointer supplies the next node.

For a match, the matching node’s next pointer is read before the replacement write:

- A head match replaces the owner’s head.
- An interior match replaces the preceding node’s next pointer.

Only that occurrence is processed. There is no traversal beyond the match, no explicit clearing of the input object’s next field, and no explicit deallocation.

If traversal reaches null without a match, no list link is explicitly changed.

After search termination or removal, the function reads the owner’s head again. If this read is nonnull, the head field is read again to obtain the return value. Under stable memory, the remaining head is returned; the separate reads matter if external mutation is possible.

If the post-search head is null:

- A zero third argument returns null.
- A nonzero third argument enables the dependency sequence below.

A successful removal is not required for that sequence. An initially empty list also qualifies.

### Empty-list dependency sequence

Before calling either dependency, the function reads and saves the owner’s word at offset `0x00`. That saved value supplies the first argument to F-3182ac1ca82f even if intervening dependency activity changes the owner’s storage.

At the first dependency call, a 16-byte temporary region contains:

| Record offset | Initial content |
|---|---|
| `0x00` | Owner pointer |
| `0x04` | Traversal endpoint: null after an unsuccessful search, or the input pointer after a match |
| `0x08` | Full third-argument value |
| `0x0C` | Owner pointer |

The observable dependency sequence is:

1. F-c67cb20988a1 receives the temporary region’s address and the length value `0x10`.
2. After that call returns, the temporary region’s first word is explicitly restored to the saved owner pointer.
3. The global argument-source value is read while preparing the second call.
4. F-3182ac1ca82f receives the saved owner word, the newly loaded global value, and the address of the temporary region’s first word.
5. After the second call returns, the function reads and returns the temporary region’s first word.

Neither dependency’s direct return value determines this function’s result.

The global read occurs **after both the first dependency’s return and the first-word restoration**. F-c67cb20988a1 may modify that global. Its pre-call value therefore cannot be substituted for the value loaded for F-3182ac1ca82f. The loaded value’s semantics remain unknown.

Changes made by the first dependency to the temporary record’s first word are overwritten before the second call. No corresponding restoration is shown for the other three words.

There is no subsequent list-head check. Dependency changes to the head do not make the head the return source.

### Bit set: eligibility

With a nonzero second argument, the function reads the signed index from input offset `0x28`, then the context pointer from input offset `0x00`. Both are saved before F-0aff6a5050f5 is called without explicit arguments.

The gate dependency may change memory. Subsequent processing uses the saved index and context pointer, but reads the context fields after the call.

Eligibility proceeds in this order:

1. A zero gate result returns `0xFFFFFFCE`; context status and flags are not explicitly read.
2. Otherwise, the context status at `0xFC` is read. A nonzero value returns `0xFFFFFFCE`, without reading the flags.
3. Otherwise, the flag word at `0xD0` is read. Flag bit `0x40` being set returns `0xFFFFFFCE`.

With eligibility satisfied, an index of zero returns null without reading the maximum index or either table.

For a nonzero index:

- A negative index returns `0xFFFFFFCE`, without reading the maximum.
- A positive index causes the signed maximum at `0xE8` to be read.
- An index greater than that maximum returns `0xFFFFFFCE`.
- Otherwise, the index is accepted.

Thus, zero is a special successful no-update case, not an index subjected to the positive-index bound.

### Bit set: counter and entry processing

The already-read flag word controls counter handling.

If flag bit `0x01` is clear, no counter-table access occurs and entry processing proceeds directly.

If flag bit `0x01` is set, the function:

- Reads the context’s counter-table indirection pointer.
- Reads the table base through that pointer.
- Reads the selected 32-bit counter.
- Subtracts one and writes the result to the same counter.
- Continues to entry processing only if the stored result is exactly zero.

A nonzero result returns null after the decrement, without an explicit entry or accumulator update. Negative counters are not rejected, and zero is not protected against decrement.

When entry processing proceeds, the function resolves the entry-table base through context offset `0xD4`. It then reads the accumulator and selected entry’s second word, writes their sum to the accumulator, and writes `0x80000001` to the selected entry’s first word.

The relative order of the two addition-operand reads is not established by the supplied expression. The accumulator write precedes the marker write. The entry’s second word is not explicitly changed.

The function then returns null.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless otherwise stated, assume valid, noninterfering memory and dependencies that return normally.

1. **Head removal with a successor.**  
   With the selection bit clear and a list consisting of input → successor → null, the owner’s head becomes the successor and that head is returned. The input’s next field is not cleared.

2. **Interior removal.**  
   For head → predecessor → input → successor, the predecessor’s next pointer becomes the successor. The existing head is returned.

3. **Absent input.**  
   A terminating nonempty list containing no input-pointer match produces no explicit link write and returns its head.

4. **Removal leaves no nodes.**  
   If the input is the sole node and the third argument is zero, the owner’s head becomes null and null is returned without either empty-list dependency.

5. **Initially empty list.**  
   With a third argument of −7, the temporary record initially contains the 32-bit representation of −7 in its third word. Both empty-list dependencies run.

6. **First dependency changes the global.**  
   Suppose the global initially contains value A and F-c67cb20988a1 changes it to B. If no later mutation intervenes, F-3182ac1ca82f receives B as its second argument—not A and not the global’s address.

7. **Saved owner word versus restored record.**  
   If the first dependency changes the owner’s first word and the record’s first word, the second call still receives the previously saved owner word as its first argument, while the record’s first word has been restored to the saved owner pointer.

8. **Dependency-produced result.**  
   If F-3182ac1ca82f leaves value R in the record’s first word, R is returned without rechecking the list head.

9. **Bit-set bypass.**  
   A zero second argument returns the exact input pointer without reading the index or context pointer.

10. **Eligibility and bounds failures.**  
    A zero gate result, nonzero status, set flag bit `0x40`, negative index, or positive index above the signed maximum produces `0xFFFFFFCE` at its respective check.

11. **Zero index.**  
    After successful eligibility, zero returns null without a maximum-index read or table update.

12. **Counter transition.**  
    With an accepted positive index and counter mode enabled, one becomes zero and permits entry processing; two becomes one and returns null without entry processing.

13. **Counter mode disabled.**  
    An accepted positive index proceeds to entry processing without reading the counter table. With accumulator 10 and entry second word 7, the accumulator becomes 17 before the entry’s first word becomes `0x80000001`.
