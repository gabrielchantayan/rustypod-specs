# F-85e566545ec7

## Purpose

F-85e566545ec7 attempts to identify one item at a mutable input cursor and describe it using a start address, an end address, and a one-byte category.

The established behavior distinguishes three cases:

- An item beginning with `(` is delegated to F-03e9c84a7328 and assigned category 2.
- An item beginning with `[` or `{` is processed by a same-delimiter nesting loop and assigned category 3.
- Any other initial byte is delegated to F-739b66c266c2 and assigned category 1.

F-1fe3b1afff2c runs before this classification and before each nesting-loop inspection. Its actual transformation is unknown; this contract does not assume it merely skips whitespace.

The likely intent is to produce a borrowed span for a token or grouped expression. That interpretation is inferred. The observable contract is the sequence of state accesses, dependency calls, cursor updates, and output writes described below.

## Interface

### Arguments and result

The function has four arguments:

1. **State reference:** a writable structure containing four-byte fields.
2. **Output reference:** a writable record containing two four-byte address fields and a one-byte category.
3. **Opaque four-byte value:** no observable use is established.
4. **Pointer-valued argument:** assigned to temporary local storage, then overwritten before its value is used for scanning. No dereference or externally observable use is established.

There is no explicit return value. Results are communicated through the output record and the state cursor.

### State layout

The visible accesses establish these offsets:

| Byte offset | Width | Meaning established by use |
|---|---:|---|
| 0 | 4 bytes | Current input address; read and written |
| 4 | 4 bytes | Not directly accessed by this function |
| 8 | 4 bytes | Address supplied to F-1fe3b1afff2c; subsequently captured as a stopping boundary |
| 12 | 4 bytes | Status tested for zero versus nonzero on selected paths |

“Boundary” and “status” are descriptive names, not claims about dependency semantics. In particular, this function does not establish that the status is an error code, that the boundary remains fixed, or that dependencies preserve either field.

### Output layout

| Byte offset | Width | Meaning |
|---|---:|---|
| 0 | 4 bytes | Item start address |
| 4 | 4 bytes | Item end address |
| 8 | 1 byte | Category: 0, 1, 2, or 3 |

The visible function writes only one byte at offset 8. It does not clear or otherwise directly write bytes 9–11.

For successful bracket or brace processing, the end address is immediately after the matching closing byte. For other categories, the end is the address produced by the relevant dependency, subject to the acceptance conditions below. A uniform interpretation of every result as a half-open token span is plausible but depends on those dependencies.

### Preconditions and ownership

Normal execution requires valid storage for all accesses taken by the selected path, including the output fields, state fields, and every inspected input byte. Pointer comparisons and increments must also be meaningful in the execution environment.

The routine performs no visible allocation, release, or input-byte modification. Its output addresses refer to existing storage; it does not create an owned copy. Input lifetime, output lifetime, and any ownership transfers performed by dependencies are undocumented.

No non-aliasing check is present. If the output overlaps the state or input, the initialization and subsequent writes can alter later reads. The ordinary behavioral descriptions and acceptance examples assume disjoint state, output, and input storage unless stated otherwise.

## Behavior

### 1. Initialize output and prepare the cursor

The initial output writes occur in this order:

1. Write category 0 at output offset 8.
2. Write zero to the start field.
3. Write zero to the end field.

The function then calls F-1fe3b1afff2c with the state reference and the address currently read from state offset 8.

After that call, it reads:

1. The current address from state offset 0.
2. The boundary address from state offset 8.

The second of these becomes the **captured boundary** for subsequent comparisons in this invocation.

If the current address is at or beyond the captured boundary, the function returns immediately. On this path:

- No input byte is inspected.
- No status check is performed.
- No final cursor write is performed by this function.
- With disjoint storage and no dependency interference with the output, the output remains empty.

The early return does not run the later output-normalization step.

### 2. Classify the first byte

If the current address precedes the captured boundary, one byte at that address is read.

The first-byte cases are `(`, `[`, `{`, and all other values. No visible check of the status field precedes this classification. Thus a nonzero status already present after the initial preparation call does not, by itself, prevent entry into any branch.

### 3. Parenthesis case

For an initial `(`, the function:

1. Writes category 2.
2. Writes the current address as the output start.
3. Calls F-03e9c84a7328 with a reference to a local cursor and the captured boundary.

This dependency receives a reference to temporary cursor storage, not the state reference.

After the dependency returns, its resulting local cursor is compared with the captured boundary:

- If the cursor precedes the boundary, it is written as the output end.
- If the cursor is at or beyond the boundary, this branch does not write an end.

There is no visible status-field check on this path. There is also no explicit check that the returned cursor advanced, lies after the start, or points to a matching delimiter.

The branch then proceeds to common completion. A cursor exactly equal to the boundary is not accepted here, even though the bracket and brace branch can accept such an endpoint.

### 4. Ordinary-item case

For any initial byte other than `(`, `[`, or `{`, the function:

1. Writes the current address as the output start.
2. Writes category 1.
3. Calls F-739b66c266c2 with the state reference.
4. Reads the current address back from state offset 0.
5. Reads the status at state offset 12.

If the status is zero, the returned current address is written as the output end. Otherwise, this branch does not write an end.

No comparison against the captured boundary occurs after this dependency call. Consequently, a zero-status result can be accepted even when its returned cursor equals or exceeds that boundary. No explicit progress or start/end ordering requirement is enforced.

### 5. Bracket and brace cases

For `[` the closing byte is `]`; for `{` it is `}`. Both cases receive category 3.

The function then:

1. Reads the byte at the current address again and retains it as the opening byte used for nesting comparisons.
2. Writes the current address as the output start.
3. Initializes a nesting count to one.
4. Advances the local cursor by one byte.
5. Writes that advanced cursor to state offset 0.

Each loop iteration begins by calling F-1fe3b1afff2c. Unlike the fixed captured boundary, the boundary argument for this call is reread from state offset 8 on every iteration.

After the call, the function reads the current address from state offset 0 and evaluates these stopping conditions in order:

1. If the cursor is at or beyond the captured boundary, leave the loop.
2. Otherwise, if the status at state offset 12 is nonzero, leave the loop.

The status read is bypassed when the boundary condition already holds.

If neither condition holds, the byte at the current address is examined:

- If it equals the retained opening byte, increment the nesting count.
- Otherwise, if it equals the chosen closing byte, decrement the count.
- If that decrement produces a count below one, advance the local cursor by one byte, write that address as the output end, and finish the scan.

For every iteration that does not finish this way, the function writes the local cursor to state offset 0 and calls F-739b66c266c2. The next iteration then begins with another F-1fe3b1afff2c call.

This is not visibly a byte-by-byte scan. Advancement between inspected positions is delegated. The function itself advances past the initial opener and past an accepted final closer, but does not independently advance past other inspected bytes.

Only the active delimiter pair affects the visible nesting count. A brace encountered during a bracket scan, for example, does not directly change that count. Whether delegated scanning skips or recursively processes mixed delimiters, quoted text, or comments is unknown.

Leaving the loop through the boundary or status conditions does not directly write an output end.

### 6. Common completion

Except for the initial empty-input return, every path reaches common completion:

1. Read the output end field.
2. If it is zero, clear the output start field and then write category 0.
3. Write the local cursor to state offset 0.

The end field is used as a zero/nonzero completion marker. A zero endpoint therefore cannot represent a successful result through this completion logic.

Normalization does not restore the entry cursor or clear the state status. Failed recognition can consume input, leave the cursor at the boundary or beyond it, or retain other dependency-induced state changes.

The completion decision depends on the end field’s value at that moment. This function initially zeros that field, but aliasing or dependency side effects could alter it. It does not maintain a separate private success flag.

## Side effects

### Directly established effects

- Initializes the output before invoking any dependency.
- Writes category and start fields during classification.
- Writes an end field only on the branch-specific acceptance paths.
- Clears start and category at common completion when the observed end is zero.
- Updates the state cursor during bracket/brace processing and at common completion.
- Reads input bytes for classification and nesting comparisons.
- Does not directly write the boundary or status fields.
- Does not directly allocate, free, or modify input contents.

The function’s direct writes are not transactional. An unsuccessful result does not roll back state or dependency effects.

### Error representation and termination

There is no explicit returned error code and no visible diagnostic emission. Under ordinary disjoint-storage conditions, an unsuccessful attempt is represented by a zero start, zero end, and category 0.

Status handling is asymmetric:

- Initial preparation: status is not checked before classification.
- Parenthesis scan: status is not checked.
- Ordinary-item scan: status is checked after F-739b66c266c2.
- Bracket/brace scan: status is checked after each loop preparation call, provided the cursor remains below the captured boundary.

Termination of the nesting loop depends partly on dependency behavior. If the dependencies repeatedly leave the cursor below the captured boundary with zero status and no effective progress, the visible routine has no general iteration limit.

## Acceptance examples

These are conditional static examples, not runtime observations. They assume valid addresses, disjoint storage, and no dependency writes to the output.

1. **Preparation reaches the boundary.**  
   If the initial F-1fe3b1afff2c call leaves the cursor equal to the subsequently captured boundary, the function returns with an empty output. It does not inspect an input byte or perform its common final cursor write.

2. **Ordinary item succeeds.**  
   If the first byte is `x`, F-739b66c266c2 returns a nonzero cursor with zero status, and no other relevant side effect intervenes, the output has category 1, the initial classified address as start, and the returned cursor as end. Equality with the captured boundary does not prevent acceptance.

3. **Ordinary item reports nonzero status.**  
   With the same initial byte, if F-739b66c266c2 leaves nonzero status, the output is normalized to empty. The returned cursor is nevertheless written back to the state.

4. **Parenthesis result at the boundary.**  
   If F-03e9c84a7328 returns a cursor exactly at the captured boundary, no end is written and the result becomes empty. Returning a nonzero cursor strictly before the boundary instead permits category 2.

5. **Empty bracket pair ending at the boundary.**  
   For `[]`, if the loop preparation leaves the cursor on `]` with zero status, that closer reduces the count to zero. The accepted end is one byte after `]`, even if that equals the captured boundary. Category 3 is retained.

6. **Nested same-kind delimiters.**  
   For an input shaped like `[[]]`, if dependencies expose each delimiter in order, the inner opener raises the count, the inner closer lowers it without completing, and the outer closer completes the span.

7. **Unclosed group.**  
   If a bracket scan reaches the captured boundary before accepting its closing byte, it produces an empty output while retaining the reached cursor as the final state cursor.

8. **Nonzero status before a visible closer.**  
   If preparation leaves the cursor below the boundary on a closing byte but leaves nonzero status, the loop exits without inspecting that closer.
