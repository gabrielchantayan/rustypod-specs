## Behavior

It then checks the destination.

If the destination is null:

- Neither dependency is called.
- The adjustment pointers are not dereferenced by this function.
- No destination storage is accessed.
- The function returns without an explicit result.

Consequently, a null destination is not an unconditional no-access path: the initial Scale read still occurs. The evidence does not establish that this read can fault in the actual environment, but a replacement must not assume null handling precedes every global access.

### First dependency

1. The original 32-bit input token.
2. The Scale global value used for this call.

The supplied representation contains a Scale reference for the initial capture and another for the call argument. It does not prove that the executable performs two distinct physical memory reads. In a stable environment, both references denote the same value. Concurrent modification, volatile access semantics, and compiler-level read coalescing are outside the established evidence.

The upper half is therefore selected logically, without sign extension from the complete 64-bit result. Conversion of an extracted half whose highest bit is set remains subject to the target’s signed-conversion semantics.

### Scalar derivation

After F-d7be9cfb4000 returns, the function obtains the positive and negative adjustment values through their global pointers.

The arithmetic has the following structure:

1. Add the positive adjustment to the signed interpretation of the low half.
2. Subtract the negative adjustment.
3. Multiply that adjusted quantity by the Scale value captured at entry.
4. Add the signed interpretation of the high half.

This structure matters when overflow or type promotion is relevant. A mathematically equivalent expression evaluated with a wider intermediate type need not have identical target behavior.

The visible working Scale value and explicit half conversions are 32-bit signed quantities. The global adjustment declarations are missing, so their exact widths, signedness, and effect on intermediate expression types cannot be fully established. No explicit widening to a 64-bit arithmetic intermediate is shown for this calculation.

For values that keep every intermediate within the applicable signed 32-bit range, and where both adjustment operands participate as signed 32-bit values, the scalar is unambiguous: captured Scale multiplied by the adjusted low half, plus the signed high half.

Outside that range, this contract does not impose either checked overflow or modulo-\(2^{32}\) wrapping. The fragment contains no explicit overflow check, clamp, or reported arithmetic error, but that absence alone does not establish portable signed-overflow semantics.
