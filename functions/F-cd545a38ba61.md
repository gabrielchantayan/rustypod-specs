# F-cd545a38ba61

## Purpose

F-cd545a38ba61 performs comparison-driven dispatch using a shared table. Depending on the comparison results and object-relative state, it:

- Calls F-d82d61c5d5f8 with a selected destination and a selector from 0 through 4.
- Assigns the integer value one through a shared output reference.
- Returns without either action or fallback.
- Calls F-bd120056260a with the original first and second arguments.

The established behavior is routing, not an application-level interpretation of the requests. The meanings of the table entries, selectors, object flag, destinations, and shared output are unknown.

The routine has no explicit return value. Its observable outcomes are dependency calls, reached memory accesses, the possible shared-output assignment, and whether fallback occurs.

## Behavior

### Primary recognition

The routine first captures the shared table base. It then calls F-3805a25164a0 with the primary comparison value and individual table entries in this order:

1. Index 0.
2. Index 1.
3. Index 2.
4. Index 3.
5. Index 4.
6. Index 6, only if all five earlier comparisons returned nonzero.

For each call, the comparison value is the first argument and the four-byte table entry is the second.

A zero result accepts the current entry. Any nonzero result rejects it; positive and negative results are not distinguished.

The first accepted entry ends primary recognition. Accepted indices 0 through 4 select their corresponding selector values. Acceptance at index 6 selects category 6. No selector 5 is produced.

If all six comparisons return nonzero, F-bd120056260a is called with the original object-handle address and fallback context. The routine then returns without destination selection or secondary comparison.

The captured table base is not a snapshot of the entries. Each entry is read when its comparison is reached. Earlier dependency calls may therefore affect values read later from that base. Conversely, changing the global reference that originally supplied the base does not itself replace the already captured base.

### Destination selection

Every accepted primary category enters destination selection, including category 6.

The visible access and call order is:

1. Read the object address from the object-handle slot and form a candidate destination at offset `0x54`.
2. Read the object address from the slot again and read its byte at offset `0x70`.
3. If that byte is nonzero, call F-eea3e31f6354 and replace the candidate destination with its returned value plus `0x4ec`.
4. Continue with the recognized category’s branch.

The two object-address reads are separate. The candidate destination need not be based on the same object address as the flag test if the slot changes between those accesses.

Destination selection precedes all secondary comparisons. An ordinary-category secondary comparison does not cause the selected destination to be recomputed, even if that dependency changes the object-handle slot or object flag.

Category 6 does not ultimately pass the destination to another dependency. Nevertheless, the destination-selection reads and any call to F-eea3e31f6354 remain part of its behavior.

### Categories 0 through 4

For an accepted selector from 0 through 4, the routine compares the secondary comparison value with table index 7 through F-3805a25164a0.

- If the result is zero, it calls F-d82d61c5d5f8 with the previously selected destination and selector, then returns.

- If that second result is zero, it calls F-d82d61c5d5f8 with the same selected destination and selector, then returns.
- If both secondary results are nonzero, it calls F-bd120056260a with the original first and second arguments, then returns.

Index 8 is short-circuited: neither its table read nor its comparison occurs when index 7 is accepted.

The selector passed to F-d82d61c5d5f8 is a 32-bit value. Any result from that dependency is unused locally.

### Category 6

After destination selection, category 6 reads the object address from the object-handle slot again and tests its byte at offset `0x70` again.

If this second flag test is zero, the routine calls F-bd120056260a with the original first and second arguments, then returns. No secondary comparison occurs.

If this second flag test is nonzero, the routine compares the secondary comparison value with table index 7:

- A zero result leads to assignment of the integer value one through the shared output reference.
- A nonzero result causes no direct shared-output assignment.
- Both results lead to return without fallback.

Category 6 never compares against table index 8 and never calls F-d82d61c5d5f8.

The second flag test is independent of the first. In particular, F-eea3e31f6354 may run between them and may change the slot or object state. The earlier nonzero flag result does not guarantee a later nonzero result.

### Shared-output target timing

This differs from the table base, which is captured before the comparison sequence. No early capture of the output destination is visible.
