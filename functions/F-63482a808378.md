# F-63482a808378

## Purpose

F-63482a808378 coordinates a transfer from a source object into destination-managed storage, then submits that storage through a destination-object operation.

Two paths are established:

- Requests of at most 128 units use an inline, slot-oriented transfer loop.
- Requests above 128 units delegate to F-412d643fa30e and propagate a two-field result.

The inline path combines a destination-provided scale, source reads, a copy-like external operation, slot metadata updates, and submission. “Unit,” “slot,” “scale,” and “submission” are descriptive terms, not established application-level types.

The supplied representation leaves important calling-convention details unresolved, particularly an auxiliary result used to select slots. This contract distinguishes visible operations from those unresolved semantics.

## Interface

| Argument | Displayed width and role |

### Preconditions

The visible implementation performs no null, size, bounds, alignment, or virtual-table validation. Valid execution therefore requires:

- Accessible destination and source objects with callable entries at the observed virtual-table offsets.
- Valid storage for every selected slot.
- A writable result destination returned by F-603a53835f04 whenever a path writes through it.
- Valid source, destination, descriptor, and temporary-storage arguments for the dependencies actually invoked.
- Arithmetic and helper behavior that permit the transfer loops to make progress if termination is required.

The function does not establish these conditions itself.

## Behavior

### Initialization and path selection

The function first calls F-603a53835f04 with the result context followed by three zero-valued arguments. Its return becomes the result destination used by later error reporting and delegated-result propagation.

It then calls the destination object’s virtual operation at table byte offset `0x24`. No explicit arguments appear in the supplied representation.

The returned 32-bit value is multiplied by the requested count to initialize the inline path’s remaining quantity. A separate running copy-position accumulator starts at zero.

Only then does the function compare the requested count with 128. Consequently, result initialization and the first destination virtual call occur even for zero-count requests and requests that will delegate.

The multiplication feeds an unsigned 32-bit quantity. A mathematical product larger than 32 bits cannot be assumed to remain intact. Likewise, later destination-scale calls are distinct calls: the source does not establish that they return the same value.

### Inline path: requested count from zero through 128

The inline path repeats while the remaining quantity is nonzero.

#### Slot selection and prior-slot handling

Each iteration begins with these operations:

1. Read the destination selection counter.
2. Store its incremented value.
3. Call F-d7be9cfb4000 with the old counter and the destination word at `0x468`.
4. Save the auxiliary slot index associated with this operation for one later failure-cleanup path.

The ordinary return from this particular F-d7be9cfb4000 call is not used. A separately represented auxiliary result supplies subsequent slot indexing. Its precise production and lifetime are unresolved.

The selected slot’s flag is then read as one byte. If, and only if, it equals one:

- F-fceaba74ea88 receives the value from the slot’s `0x49C` field.
- After that call returns, the slot flag is written to zero.

A nonzero flag other than one does not trigger this operation. The visible code does not establish that F-fceaba74ea88 frees memory, releases a handle, waits for completion, or cancels work.

#### Chunk sizing and metadata

The function obtains another destination scale through virtual offset `0x24` and compares the remaining quantity with that value shifted left by seven bits.

- If the unsigned shifted value is greater than the remaining quantity, the chunk quantity is the remaining quantity.
- Otherwise, the scale operation is called again, and the chunk quantity is that new return shifted left by seven.

Thus the value used to choose the branch and the value used to construct the chunk need not agree if the virtual operation is stateful.

The current position is written into the selected slot’s `0x470` field.

Another destination-scale call supplies the second argument to F-d7be9cfb4000; the chunk quantity is its first argument. The helper’s 32-bit return is stored in the slot’s `0x47C` field.

Division is a plausible interpretation of this helper, but it is not established by the supplied body. The stored value must therefore be described as a helper result rather than unconditionally as a quotient.

#### Source reads and copying

While the chunk quantity is nonzero, the function:

- Reads the four destination words at offsets `0x030` through `0x03C` into a contiguous, four-word temporary descriptor.
- Chooses the smaller, under unsigned comparison, of the chunk quantity and the destination word at `0x034`.
- Calls the source object’s virtual operation at table byte offset `0x0C`, passing the source object, that chosen read quantity, and the descriptor’s address.

The source operation’s return is interpreted as an unsigned 32-bit count.

If the returned count differs from the requested read quantity, the function calls F-7f008c1060db with:

- The result destination.
- `0x22`.
- `0x0B`.
- Zero.

It then returns immediately. There is no retry, partial-copy step, slot submission, or visible rollback on this branch.

For an exact-count read, the function next:

- Rereads the destination word at `0x030`.
- Reads the selected slot’s `0x48C` field.
- Calls the destination-scale virtual operation.
- Calls an unmapped external copy-like operation with the computed destination, the reread `0x030` value, and the returned read count.

The computed destination is the slot address-like value plus the running copy-position accumulator multiplied by the newly returned scale.

The descriptor is not used as the copy source after the read. In particular, a descriptor change made by the source operation is not visibly consulted for that argument; the destination structure’s `0x030` word is reread instead.

After the copy-like operation, another destination-scale call is made. F-d7be9cfb4000 then receives the returned read count and that scale. Its return is added to the running copy-position accumulator.

Finally, the read count is subtracted from the chunk quantity.

The accumulator is initialized once for the whole inline path, not once per slot.

#### Submission and progress

After the chunk is exhausted, the function captures the destination object pointer for submission. It calls F-d7d8ec990094 with a 12-byte temporary area and the address of the selected slot’s `0x48C` field.

Before submission, temporary storage is also populated with:

- The slot value at `0x49C`.
- The address of the slot field at `0x4A0`.
- A zero word.

The destination virtual operation at table byte offset `0x0C` is then called with the captured object pointer, the result from F-d7d8ec990094, the slot position, and the slot count masked with `0xFFFF`.

The mask is an observable truncation: only the low 16 bits of the stored count are passed in that displayed argument.

If submission returns nonzero:

1. F-7f008c1060db is called with the result destination, `0x22`, zero, and zero.
2. The flag belonging to the previously saved slot index is written to zero.
3. The function returns.

The error-reporting call precedes the flag write.

If submission returns zero:

1. The selected slot flag is written to one.
2. The current position is advanced by the slot’s stored count.
3. The destination-scale virtual operation is called again.
4. The remaining quantity is reduced by the product of that scale and the slot’s stored count.

If the remaining quantity becomes zero, the function returns. No explicit final success write through the result destination is visible on this path.

### Delegated path: requested count above 128

For requested counts of 129 or greater, the inline loop is bypassed.

Temporary storage is prepared with the requested count and a zero word. The displayed call to F-412d643fa30e passes a temporary result-record address, the destination state, the source object, and the current position. Whether the additional prepared words form hidden or stack-passed arguments is unresolved.

After the dependency returns, the function:

1. Copies the first 16-bit temporary result field to the first 16-bit field at the result destination.
2. Copies the second 16-bit temporary result field to the next 16-bit field.
3. Calls F-9b718979506d with the temporary result-record address.
4. Returns.

The copied result is four bytes in two ordered 16-bit writes. No wider result copy is established.

## Side effects

Visible direct mutations include the selection counter, slot positions, slot counts, slot flags, and delegated result fields. The copy-like operation is given a computed destination, but its exact memory and overlap semantics are not established.

Failures are not transactional:

- A source-read mismatch may occur after counter advancement, prior-slot handling, metadata writes, and earlier successful copies.
- Submission failure occurs after the chunk’s read and copy activity.
- Neither failure path visibly restores prior state.
- A read mismatch does not perform the submission-failure flag clear.

Temporary descriptors, the 12-byte conversion area, and the delegated result record have automatic lifetime. Their addresses are passed to dependencies. Retention, ownership transfer, and asynchronous use are not established.

No dependency may be assumed to preserve destination fields or global state. Several values are deliberately reread after calls; those reads must not be replaced in the contract by assumptions of stability.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Zero requested count.** Assuming initialization and the first destination-scale call return normally, the initial remaining quantity is zero. No inline slot selection, source read, or submission occurs.

2. **Threshold boundary.** A request of 128 uses the inline path; a request of 129 uses F-412d643fa30e. Both first perform result initialization and the initial scale call.

3. **Exact flag comparison.** A selected flag of one causes F-fceaba74ea88 to be called before the flag is cleared. A flag of two does not cause that call.

4. **Short source result.** If a read requests 16 and returns 15, the error tuple is `(0x22, 0x0B, 0)`. That read is not followed by the copy-like operation or submission.

5. **Oversized source result.** If a read requests 16 and returns 17, it takes the same mismatch branch. The condition is inequality, not merely a short-read check.

6. **Submission failure.** If the destination submission returns nonzero, error reporting uses `(0x22, 0, 0)`, followed by clearing the saved slot’s flag. Position advancement and the next remaining-quantity reduction do not occur.

7. **Count truncation.** If a slot’s stored count is `0x00010002` at argument evaluation, submission receives two in the masked count argument. Other visible uses of the stored field are not correspondingly masked.

8. **Delegated result ordering.** If delegation produces two valid 16-bit fields, those fields are copied in order before F-9b718979506d receives the temporary record.

## Uncertainties

The following remain **documented_only**:

- The auxiliary slot index’s precise calling-convention source, lifetime, and stability across intervening calls.
- Whether F-d7be9cfb4000 performs division, remainder calculation, or another operation.
- Hidden arguments suggested by temporary storage around submission and delegation.
- Exact signed-overflow and left-shift behavior for arithmetic represented using signed 32-bit intermediates.
- The application units represented by counts, positions, and scale values.
- Copy overlap rules, buffer ownership, resource ownership, asynchronous retention, and dependency mutation of shared state.
- The success representation established by F-603a53835f04.

Termination is conditional. Zero-sized reads can succeed without reducing a nonzero chunk. Zero progress products can leave the outer remaining quantity unchanged. Unsigned subtraction can wrap instead of approaching zero. The body contains no explicit protection against these cases.
