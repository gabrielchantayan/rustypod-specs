## Behavior

The first direct read of record storage is the 16-bit gate at byte offset 12.

A nonzero value ends the operation with return value 4. This path does not directly read the record’s first word, obtain an object, read a dispatch table, invoke the indirect target, or call F-dece790ddc92.

A zero value selects the active path. This function does not reread the gate. A later change to the field cannot change the branch already selected, although a dependency may independently inspect that field.

### Capture and temporary state

On the active path, the function captures the 32-bit value at record offset 0 before calling F-b7af80e829ec.

An invocation-local 32-bit temporary is then initialized from the fourth argument. After the indirect operation returns, its result replaces that temporary’s contents. The temporary supplied to the final dependency therefore contains the indirect result, not merely the fourth argument’s initial value.

These are represented data-flow relationships. They do not establish a physical stack layout, register assignment, or exact machine instruction sequence.

### Object acquisition and indirect selection

The lookup has two distinct memory accesses:

1. A represented 32-bit integer is read at object byte offset 0.
2. That integer is used to form an address displaced by 64 bytes, at which a callable pointer is read.

The second access is a callable-pointer access, not another established 32-bit integer access. Its width is unresolved. The 32-bit integer representation of the first access does not determine the width of the second access or of the resulting code address.
