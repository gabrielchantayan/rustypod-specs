# F-79845591166a

## Purpose

F-79845591166a obtains a candidate value from one dependency, passes that candidate and two caller-supplied values to another dependency, and compares the returned result with the candidate.

If the two values are equal, the function stores the candidate in caller-provided output storage. If they differ, it invokes a third dependency with the first caller-supplied value and the candidate, then stores zero in the output storage. On either normally completing path, it returns the result of the second dependency.

This establishes a comparison-based protocol, not a general success/failure convention. The candidate’s meaning, the result’s meaning, and the purpose of the mismatch-only dependency are not established. In particular, the evidence does not establish allocation, resource acquisition, validation, or release semantics.

## Acceptance examples

These are conditional contract examples, not executed tests. Each assumes a valid output destination, normally returning dependencies, and no external interference with the final output observation.

1. **Equal nonzero values.** If F-e4b8d56f2a5d returns 23 and F-5b0efb10ef8c returns 23, the output becomes 23, F-65af7db35d2d is not called, and the function returns 23.

2. **Unequal nonzero values.** If the candidate is 23 and the result is 41, the mismatch-only dependency receives the first input and 23. After it returns, the output becomes zero. The function returns 41.

3. **Zero candidate and zero result.** The equality path is taken. The output becomes zero, no mismatch-only call occurs, and the function returns zero. A zero output therefore does not identify the mismatch path.

4. **Nonzero candidate and zero result.** The mismatch path is taken. After the mismatch-only call returns, the output becomes zero and the function returns zero. This has the same final output and return values as the preceding example, but a different dependency-call history.

5. **Zero candidate and nonzero result.** The mismatch-only dependency is still called, with zero as its second argument. There is no candidate-zero exemption. The output becomes zero after that call returns.

6. **Equal negative values.** If both acquired integers are −1, equality selects the direct store path. The output and return value are −1. No sign-based rejection occurs.

7. **Mismatch dependency observes output.** If the output initially contains 99 and the mismatch-only dependency can inspect that object through an independent route, this function has not yet cleared it when that call begins. Any earlier dependency effects remain relevant.

8. **Mismatch dependency does not return.** If that call terminates execution or otherwise fails to return normally, the contract does not promise the final zero store or a normal function return.
