# F-993b9434eb73

## Purpose

F-993b9434eb73 initializes a status field, rejects either of two nonzero option values, and otherwise constructs or acquires an object through dependencies. It then configures the object, publishes a pointer through an output slot, performs reference-count-like bookkeeping, and releases a temporary reference.

The reference-count and ownership interpretation is **inferred intent**. The supplied evidence establishes field accesses, arithmetic, calls, and ordering, but does not establish the dependencies’ ownership contracts, synchronization guarantees, or allocation behavior.

The routine has two visibly different return conventions:

- Rejected options: a 64-bit value assembled from two 32-bit pointer representations.
- Ordinary completion of the main path: zero.

The output-slot write and the return value must therefore be treated as separate observable results.

## Interface

### Inputs

The interface has four inputs:

1. **Output-slot address:** a pointer to writable storage for one 32-bit word.
2. **Context address:** a pointer to a word-addressed context.
3. **First option:** a 32-bit integer.
4. **Second option:** a 32-bit integer.

The established layout uses four-byte words and 32-bit pointer representations.

The context is accessed at these byte offsets:

| Offset | Established use |
|---|---|
| +4 | Status word, written directly by this routine. |
| +24 | Address passed to F-e541a293a856. |
| +64 | Address passed to F-b9acea4b06ad. |

The evidence does not establish the sizes or complete layouts of the regions beginning at +24 and +64. Their extent and validity requirements depend on the receiving dependencies.

### Output and return value

The return value is 64 bits.

When either option is nonzero, the routine returns a value whose:

- Low 32 bits are the representation of the output-slot address.
- High 32 bits are the current temporary context/object pointer.

That temporary pointer is initially the context address. Because a dependency runs before the return, preservation of its value is not an independent dependency guarantee.

On ordinary completion of the main path, the return value is zero. The output slot has previously been written with the temporary object pointer.

### Temporary storage

The routine maintains a temporary pointer initially equal to the context address. It also initializes a 32-bit scratch word from the first option and an adjacent 32-bit word from the second option.

Dependencies receive addresses of the temporary pointer and scratch word at different stages. These are writable call-visible locations, not immutable copies. In particular, the routine later rereads the temporary pointer rather than treating it as permanently equal to the original context address.

No dependency may retain these temporary addresses beyond the routine’s lifetime unless its external contract provides a valid mechanism for doing so. Such a mechanism is not established here.

### Object layout used by the main path

A nonnull temporary object pointer is interpreted as addressing at least these words:

| Offset | Established use |
|---|---|
| +0 | A 32-bit pointer-like value, later also tested as a destruction-related condition. |
| +4 | A 32-bit counter incremented and decremented. |
| +8 | A 32-bit field whose nonzero value enables auxiliary calls. |

The word at offset +0 is also interpreted as a pointer to readable storage. Its first 32-bit word is passed to F-3475b4980949.

### Preconditions

For defined ordinary execution:

- The context’s status word must be writable immediately on entry.
- Every dependency argument must satisfy that dependency’s own requirements.
- At the configuration stage, the temporary pointer and the pointer stored in its first word must both be valid for the required reads.
- The output slot must be writable when publication occurs.
- Counter operations and auxiliary calls must be valid for the object’s current state.

There is no established null-context, null-output, or null-object error return. In particular, the main path contains an unconditional read through a derived pointer before its later null checks.

No nonaliasing contract is supplied. Aliasing among the output slot, context, object fields, and dependency-accessible storage can affect subsequent reads and must not be assumed harmless.

## Behavior

### 1. Initialize status and temporary state

The first observable memory operation is a 32-bit zero write to the context status word at offset +4.

The temporary pointer is then initialized to the context address. The two option values are placed in the temporary scratch area.

A nonzero option does not bypass the initial status write.

### 2. Reject unsupported option values

If either option is nonzero:

1. The status word is overwritten with the 32-bit representation of −5.
2. F-daedc77d3db6 is called with the output-slot address and two zero arguments.
3. The routine returns the packed 64-bit value described in the interface.

This path does not visibly call the allocation-like, construction, configuration, or counter-management dependencies used by the main path.

The routine does not itself write the output slot on this path; it passes that address to F-daedc77d3db6. Whether that dependency clears, replaces, releases, or otherwise modifies the slot is unknown.

The status is set before the dependency call. Its value at return is not guaranteed to remain −5 if the dependency can modify that storage.

### 3. Obtain a handle and prepare the object

When both options are zero, the following operations occur in order:

1. F-8157a180d901 is called with the numeric value 12. Its returned 32-bit value is retained.
2. F-b9acea4b06ad receives the address of the scratch word and the context address plus 64 bytes.
3. F-e5099eaf0347 receives the retained value, the scratch address, the value 1, and the value 0.
4. F-daedc77d3db6 receives the address of the temporary pointer, the return value from F-e5099eaf0347, and zero.

The argument 12 is established. Its interpretation as an allocation size is inferred, not guaranteed.

The fourth call can replace the temporary pointer because it receives that pointer’s address. No explicit success check, null check, or cleanup branch intervenes between these calls.

### 4. Perform shared-state preparation

The scratch word is replaced with a 32-bit value read from a global location. F-22abefe7f288 is then called with the scratch address.

This is followed by F-e541a293a856, called with the context address plus 24 bytes and zero.

The purpose of the global value and the scratch-processing call is unknown. They must not be specified as locking, initialization, or ownership operations without an independent contract.

### 5. Configure through a two-level read

The 32-bit result from F-e541a293a856 is used as an integer value.

The routine selects an inner pointer as follows:

- If the current temporary pointer is nonnull, it reads the first word of that object and uses that word as the inner pointer.
- If the temporary pointer is null, it selects a null inner pointer.

It then unconditionally reads the first 32-bit word at the selected inner pointer and passes that value to F-3475b4980949.

Consequently, a null temporary pointer does **not** produce a clean early exit at this stage. Under ordinary memory semantics, it leads to an invalid read. A nonnull temporary pointer whose first word is null has the same problem.

F-3475b4980949 receives four arguments:

1. The word read through the inner pointer.
2. The sign-fill word of the result from F-e541a293a856.
3. The result itself.
4. The same sign-fill word.

The displayed operation is an arithmetic right shift by 31 bits. Under that interpretation, each sign-fill argument is zero for nonnegative values and all ones for negative values. The low 32-bit value is passed without an observed scale or truncation beyond its existing width.

No interpretation of the four arguments as a particular wider numeric API is established.

### 6. Publish and increment

After configuration returns, the routine captures the current temporary pointer and writes that pointer’s 32-bit representation to the output slot.

It then tests the current temporary pointer for null. If nonnull:

1. It reads the field at offset +8.
2. If that field is nonzero, it calls F-338d16f9ce72.
3. It reads and increments the counter at offset +4 on the captured object pointer.
4. It rereads the offset +8 field on that captured object.
5. If that field is nonzero, it calls F-1333331b2da1.

Publication therefore occurs before the increment and before either auxiliary call in this phase.

The two offset +8 tests are separate reads. The first auxiliary call may affect the second test or the counter read. Its effects cannot be replaced by an assumed no-op.

Likewise, output-slot aliasing matters: the output write happens before the object-field reads. The evidence does not justify describing publication and retention as an atomic operation.

### 7. Release the temporary reference

The temporary pointer is tested again. If it is null at this point, the routine returns zero.

Otherwise:

1. F-25197b74a768 is called.
2. The routine rereads the current temporary pointer and its counter.
3. It subtracts one from the counter and stores the result.
4. It branches on whether the stored result is zero.

For a nonzero result, F-8a8c41f7d667 is called with no explicit argument shown, and the routine returns zero if that call returns.

For a zero result:

- If the object’s first word is nonzero, F-78645499736b is called, followed by a call to F-feee9156a257 shown as nonreturning.
- If the first word is zero, F-8a8c41f7d667 is called with the current temporary pointer.
- After that call, the temporary pointer is reread and captured.
- If it is nonnull and its offset +8 field is nonzero, F-a600efb7b035 is called, followed by a nonreturning F-feee9156a257 call receiving the captured object’s offset +8 value.
- If the reread pointer is nonnull and that field is zero, F-feee9156a257 is called with the current temporary pointer and is shown as nonreturning.
- If the reread temporary pointer is null, execution reaches the final zero return.

The nonreturning annotations describe the supplied static evidence. The behavior of an unexpected return from those calls is not established.

### Counter arithmetic

The counter is a 32-bit field. The visible arithmetic adds one during publication and subtracts one during release. There is no visible saturation, overflow check, underflow check, or rejection of an initially invalid count.

A net-zero counter change is only a conditional consequence when the same object is used throughout, dependencies preserve the relevant state, no aliasing interferes, and arithmetic remains valid. It is not an unconditional postcondition.

The evidence does not resolve language-level signed-overflow behavior or the intended validity range of the counter.

## Side effects

Established direct effects include:

- Writing zero to the context status word on every entry.
- Writing −5 to that word on the rejected-option path.
- Reading one global 32-bit value on the main path.
- Writing the temporary pointer to the output slot on the main path.
- Reading the object’s first three words and a further word through its first word.
- Incrementing and decrementing a 32-bit object counter.
- Invoking dependencies in the order described above.

Dependency effects may be broader. No callee is established to preserve globals, object fields, output storage, or memory ownership.

The visible sequence resembles transfer of a retained reference to the output slot followed by release of a temporary reference. This is inferred intent only. The evidence does not establish:

- Who owns the original context.
- Whether the construction dependencies allocate or retain.
- Whether replacement releases an old value.
- Whether any cleanup dependency destroys an object, frees storage, or terminates execution.
- Whether the auxiliary calls provide synchronization.

There is no visible rollback path for a failure inside construction or configuration.

## Acceptance examples

These examples are conditional static expectations, not executed tests.

1. **First option is nonzero.** With a valid context, the status receives zero and then −5. F-daedc77d3db6 is called with the output-slot address and two zeros. The construction dependencies are not reached.

2. **Only the second option is nonzero.** The same rejection behavior applies. The rejection test is not limited to the first option.

3. **Ordinary object path with stable dependencies.** Suppose both options are zero, construction provides a valid two-level pointer chain, all relevant calls return, the offset +8 field remains zero, and a counter of 1 is preserved except for this routine’s updates. The output slot receives the object pointer; the count becomes 2 and then 1; neither increment-phase auxiliary call runs; the nonzero-release branch calls F-8a8c41f7d667; the routine returns zero.

4. **Negative configuration result.** If F-e541a293a856 returns −1, the third argument to F-3475b4980949 has all 32 bits set, and its second and fourth arguments are also all ones under the displayed arithmetic-shift interpretation.

5. **Null construction result.** If the temporary pointer is null at the configuration stage, the routine attempts a read through a null inner pointer before reaching its later null-return branch. A graceful null-result contract would contradict the visible access order.

6. **Zero count after decrement.** If the decremented count is zero and the first object word is nonzero, F-78645499736b precedes the nonreturning F-feee9156a257 call. An ordinary zero return is not established for that branch.

7. **Dependency changes state between reads.** If the pre-increment auxiliary call changes the offset +8 field to zero, the subsequent test observes the changed field and can skip the post-increment auxiliary call. The two conditions must not be collapsed into one cached test.
