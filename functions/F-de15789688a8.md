# F-de15789688a8

## Purpose

F-de15789688a8 modifies several potentially overlapping memory regions, updates global storage, constructs linked record-like layouts, and transfers control through a memory-derived target.

The supplied representation establishes an ordered memory-manipulation operation, not a reliable higher-level purpose. Numeric markers, self-references, and linked fields suggest record or execution-state construction; that interpretation is **inferred intent**, not an acceptance guarantee.

Successful execution requires more than valid ordinary arguments. The body uses inherited addresses, recovered stack locations, low numerical addresses, global-selected pointers, and a writable region relative to its eventual transfer target. Some pointer checks follow accesses through those pointers. They are not protective validation.

All behavior below is conditional on preceding accesses succeeding. No runtime tests have been performed.

## Behavior

2. Store input 3, input 4, entry context, and entry owner as words at entry-region offsets +0x00, +0x04, +0x08, and +0x0c.
3. Read entry context +0x44 as the **first link**.
4. Store the first link’s low byte at entry region +0x19.
5. Form entry region +0x10, double that numerical address, and store the undoubled address’s low halfword at the doubled address.
6. Store input 3 at input 7 +0x54.
7. Read the byte at input 7 +0x05 and zero-extend it as the **small base**.
8. Read a word at first link +0x44; store its low byte at small base +0x09.
9. Read a word at input 6 +0x14.
10. Store input 3 at input 7 +0x14 and then entry region +0x10.
11. Store the word read in step 9 at entry region +0x14.
12. Store the small base and input 7 at entry region +0x18 and +0x1c.

The small base is used directly as an address, not as an index into an established array. Its byte destination ranges from 0x09 through 0x108.

The word store at entry region +0x18 overlaps the earlier byte at +0x19. Both writes remain part of the sequence, including any intervening alias effects.

### 2. Secondary links

Continue in order:

1. Read small base +0x44 as the **second link**.
2. Store its low byte at entry region +0x29.
3. Store input 3 at entry region +0x34.
4. Read entry region +0x54 and retain that word.
5. Read second link +0x54; store its low byte at input 7 +0x11.
6. Repeat the low-byte store of the second link at entry region +0x29.
7. Store the retained entry-region word’s low byte at second link +0x0d.
8. Read the byte at second link +0x09. Zero-extend it, add 0x14, and read a word there as the **work record** address.
9. Store input 3 at input 7 +0x14.
10. Store input 3, work record, second link, and input 7 at entry-region offsets +0x20, +0x24, +0x28, and +0x2c.

The work-record lookup address ranges from 0x14 through 0x113. The earlier small-base +0x44 lookup instead ranges from 0x44 through 0x143.

The word at entry region +0x28 overlaps both preceding byte stores at +0x29.

### 3. Global-selected setup

2. Store word 0x6e at selected record +0x70.
3. Store input 11 in the global value slot.
4. Read selected record +0x64 as the **linked record**.
5. Store input 9 at selected record +0x40.
6. Store byte 0x61 at selected record +0x0c.
7. Select the first stack cursor.
8. Store input 3 at input 15 +0x54.
9. Read linked record +0x14 as the **saved link**.
10. Store the work-record address at linked record +0x14.
11. Store the selected-record address at linked record +0x44.

Only then test whether the selected-record address is zero. The preceding relative accesses occur even when it is zero.

### 4. Selected-record branches

**Nonzero selected record:**

2. Read input 14 +0x14 as the replacement work record.
3. Store input 3 at saved link +0x14.
4. Write input 3, replacement work record, linked record, and saved link at selected-record offsets +0x00 through +0x0c.
5. Store word 0x2e at selected record +0x70.
6. Read linked record +0x44 twice. Retain the first result’s low byte; use the second result as the new linked-record address.
7. Store the new linked-record address’s low byte at selected record +0x19.
8. Store byte 0x2e at selected record +0x1c.
9. Store the retained first-read byte at selected record +0x21.

The two reads in step 6 are distinct. Equality is not guaranteed for externally changing or otherwise unusual memory.

Test the computed address selected record +0x10.

If it is nonzero:

2. Choose selected record +0x1c as the shared destination.
3. Store that destination at saved link +0x14.
4. Store linked record at selected record +0x5c.
5. Store word 0x6e at selected record +0x8c.
6. Select the second stack cursor, which is first stack cursor +0x10.
7. Read incoming stack record +0x74 as the replacement work record.
8. Store the incoming stack-record pointer’s low byte at linked record +0x09.

2. Write five work-record words at +0x00 through +0x10: 0x6e, the word just read from continuation region +0x44, continuation region, linked record, and saved link.

## Acceptance examples

These are conditional static obligations, not executed tests.

1. **Byte-derived addresses:** If input 7 +0x05 contains 0xff, the small base is 255. Its byte destination is 0x108 and its subsequent +0x44 word lookup is at 0x143. The separate byte-derived work-record lookup never exceeds 0x113.

2. **Truncation:** With input 3 equal to 0x123456ab, its word stores use all 32 bits and its marker-relative byte store uses 0xab. Later stores use a replacement word if the late lookup executes.

3. **Zero selected record:** Given valid low-address memory, selected record zero still causes accesses at selected-record offsets before branching. The shared destination is zero, marker is 0x7a, and continuation region is 0x10—not zero.

4. **First-cursor reread:** On the zero-selected-record path, suppose intervening writes change the word at first stack cursor +0x08. The later saved-link load must observe that slot’s then-current contents, not automatically reuse the incoming stack-record pointer. After advancement, the final first argument comes from the second cursor’s original location; the final destination comes from first cursor +0x18.

5. **Second-cursor path:** For an ordinary nonzero selected record with selected record +0x10 nonzero, the shared destination is selected record +0x1c and continuation region is selected record +0x2c. The selected cursor is first cursor +0x10. Its distant read is at first cursor +0x320, its later saved-link read is at first cursor +0x18, and after advancement its final argument and destination reads are at first cursor +0x20 and +0x28.

6. **Overlapping construction:** The byte stores at entry region +0x29 precede the word store at +0x28. All remain required; final bytes depend on byte order and later alias effects.

7. **Writable transfer target:** Before dispatch, target +0x40 receives the current linked-record address. A valid executable target alone is insufficient if this preceding write cannot succeed.
