# F-a7d0f4365c39

## Purpose

F-a7d0f4365c39 determines whether a candidate byte string matches a pattern byte string. A nonzero mode enables two wildcard bytes: an asterisk matches a sequence of zero or more bytes, and a question mark matches exactly one nonterminating byte. A zero mode treats both bytes literally.

Matching covers the entire candidate, not merely a prefix or substring. Literal comparisons use F-b09a805215af, whose actual transformation and first-call input are not established by the supplied evidence. Case-insensitive matching is therefore a possible intent, not an established contract.

The routine also modifies its pattern: whenever an invocation receives exactly the three-byte pattern “asterisk, period, asterisk,” followed by a zero terminator, it replaces the period with a zero byte. This normalization occurs in either mode and before the candidate’s leading-byte rejection check.

These conclusions are based on static evidence only. No runtime tests have been performed.

## Interface

### Inputs

The interface has three inputs:

1. **Pattern address.** A pointer to a zero-terminated byte sequence. The sequence must be writable when it has the exact normalization form described above. Recursive invocations receive suffix addresses within this same storage.
2. **Candidate address.** A pointer to a zero-terminated byte sequence. The routine itself only reads this sequence.
3. **Mode.** An integer interpreted solely by whether it is zero. Every nonzero value enables wildcard behavior; negative values are not treated differently from positive nonzero values.

There are no supplied lengths, capacity arguments, encoding indicators, allocator arguments, or explicit context objects.

### Output

The declared return type is an unsigned integer. Every explicit nonrecursive outcome is either zero or one. Wildcard recursion combines returned values using bitwise OR, so every normally completed invocation also returns zero or one.

- **One:** the invocation accepts the candidate.
- **Zero:** the invocation rejects the candidate.

No separate error result is established. Invalid pointers, unavailable writable storage, unterminated input, excessive recursion, or index overflow have no defined recovery path in the supplied evidence.

### Widths and byte interpretation

The interface uses plain character elements, signed integer indices and mode, and an unsigned integer return type. The supplied representation does not independently establish their storage widths. Treating the integers as 32-bit and characters as 8-bit may fit the apparent environment, but those widths remain **documented_only** rather than a portable guarantee.

All pattern syntax is byte-oriented. There is no established Unicode decoding or multibyte-character handling.

One candidate check compares the first character with the numeric value negative twenty-seven. If character elements are signed 8-bit values, this rejects a leading byte with unsigned value 229, hexadecimal E5. If plain characters are unsigned, that comparison does not reject byte 229. Signedness is therefore behaviorally significant and is not to be silently normalized away.

For defined execution:

Disjoint buffers are not an explicit precondition. If the pattern and candidate overlap, normalization can change candidate bytes before they are inspected.

## Behavior

### Entry inspection and pattern normalization

Each invocation first reads the pattern’s initial byte. Further normalization-related reads are conditional:

- The second byte is inspected only if the first byte is an asterisk.
- The third byte is inspected only if the first two bytes are asterisk and period.
- The fourth byte is inspected only if the first three bytes are asterisk, period, and asterisk.

If the fourth byte is zero, the routine writes zero into the second byte. The original third byte and original terminator are not erased. The visible pattern becomes a single asterisk.

Consequences:

- Normalization is not restricted to wildcard-enabled operation.
- A longer pattern beginning with those three nonzero bytes is not normalized at entry.
- A recursive suffix can independently satisfy the normalization condition even when the outer pattern did not.
- Pattern storage can change even when the match subsequently fails.
- A normalization write precedes the first candidate-byte read.

After normalization, the routine checks the candidate’s initial character against negative twenty-seven. Equality causes immediate rejection without scanning the pattern or calling F-b09a805215af. This check is repeated at the start of every recursive invocation.

### Ordinary scan

Absent leading-byte rejection, pattern and candidate positions both begin at their respective first bytes.

The pattern is scanned until its zero terminator, a mismatch, an exhausted-candidate outcome, or a wildcard branch returns a result.

For each nonzero pattern byte, processing has this precedence:

1. An asterisk in nonzero mode enters recursive wildcard matching.
2. Otherwise, a zero candidate byte causes rejection, subject to the narrow terminal-asterisk check described below.
3. A question mark in nonzero mode accepts the current nonzero candidate byte without a dependency call.
4. Every other case performs a dependency-mediated comparison.

After an accepted non-asterisk comparison, both positions advance by one byte.

When the pattern reaches its terminator, acceptance requires the candidate at its current position also to be zero. Remaining candidate bytes cause rejection.

An empty pattern therefore accepts an empty candidate and rejects a nonempty candidate, subject to the entry rejection check.

### Literal comparison

A literal comparison makes two calls to F-b09a805215af, in this order:

1. A call for which the supplied representation shows no explicit argument.
2. A call with the current candidate character as an explicit argument.

The returned integer values are compared. Inequality immediately rejects the match; equality permits both positions to advance.

The first call’s effective input is unresolved. In particular, the supplied evidence does not establish that the current pattern character is passed to it. A contract must not substitute a familiar character-folding operation for this missing information.

The candidate character used for the second call is read after the first call returns. If the dependency can modify candidate-accessible storage, that modification can affect the argument supplied to the second call.

With mode zero, both asterisk and question mark use this same literal-comparison path. They do not receive a special raw-byte equality rule.

### Candidate exhaustion

Except for the enabled-asterisk branch, a nonzero pattern byte confronted with a zero candidate byte causes rejection before any literal-comparison calls.

There is an additional check for a final asterisk: if the current pattern byte is an asterisk and the following byte is zero, the result is one for nonzero mode and zero for zero mode. Under stable input storage, the enabled-asterisk branch has already handled the nonzero-mode case, so this check does not introduce another ordinary matching rule.

In particular:

- A question mark cannot match a zero terminator.
- An ordinary remaining pattern byte cannot match an exhausted candidate.
- A literal asterisk in zero mode cannot match an exhausted candidate.

### Enabled asterisk

An asterisk in nonzero mode evaluates the remainder of the pattern against every candidate suffix, starting at the current candidate position.

The order is:

- First, the suffix that consumes no additional candidate bytes.
- Then successive suffixes obtained by advancing one candidate byte at a time.
- Finally, the empty suffix at the candidate’s zero terminator.

For each suffix, F-a7d0f4365c39 is invoked recursively with the pattern position immediately after the asterisk and the unchanged mode value.

Results are accumulated with bitwise OR. A successful recursive result does **not** stop later attempts. Every remaining suffix is still evaluated unless execution fails or storage changes alter traversal.

After the final empty-suffix invocation returns, the current invocation returns the accumulated result. It does not resume its ordinary scan after the asterisk.

This establishes zero-or-more-byte wildcard behavior under stable inputs, but not short-circuit behavior. Failed and successful later branches may still perform normalization writes and dependency calls.

### Recursive state and mutable storage

Each recursive invocation has its own local pattern position, candidate position, and result accumulator. Pattern and candidate storage are shared.

A recursive normalization write persists after the child returns. Later suffix attempts receive the same pattern-suffix address and observe the modified bytes.

Candidate suffix iteration is also based on live storage. The current candidate byte is tested before a child call; after that child returns, the position advances, and the next loop condition reads storage again. There is no copied candidate snapshot.

Consequently, the familiar description “try every suffix” assumes stable candidate storage. The observable implementation uses repeated reads, and dependency behavior or aliasing can invalidate that assumption.

## Side effects

### Established direct effects

The only explicit write to caller-provided storage is the normalization write to the second byte of a recognized pattern or recursive pattern suffix.

The routine does not explicitly allocate, free, retain, or transfer ownership of either buffer. Recursive calls borrow addresses into existing storage.

No explicit global read or global write appears in the supplied body. This does not establish that called functions preserve global state.

### Observable sequencing

The following ordering is established:

- Normalization reads and any normalization write occur before the candidate’s leading-character check.
- The leading-character check occurs before ordinary matching.
- During a literal comparison, the argument-unspecified dependency call completes before the candidate character is read for the explicitly argument-bearing call.
- A recursive wildcard attempt completes before the parent advances to the next suffix.
- A successful recursive result does not suppress later attempts.
- The final empty-candidate attempt occurs after all preceding suffix attempts.

Return values alone do not capture the full behavior. Two executions can both accept while differing in dependency-call count, recursion, and persistent pattern mutation.

### Resource and failure exposure

Consecutive or repeated enabled asterisks can produce a large branching search with repeated subproblems. No memoization, recursion limit, allocation-backed work queue, or early-success exit is established.

The indices use signed integer arithmetic. No overflow checks are present. Inputs requiring increments outside the index type’s range have no defined outcome established here.

No explicit protection exists against null pointers, inaccessible memory, read-only normalized patterns, concurrent mutation, or exhaustion of recursion resources.
