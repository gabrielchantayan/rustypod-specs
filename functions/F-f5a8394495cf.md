# F-f5a8394495cf

## Purpose

F-f5a8394495cf constructs or updates a caller-supplied two-word result using a selection value, context state, and an opaque selector.

The function has three observable outcomes:

- An inadmissible selection uses a globally designated fallback source.
- An admissible selection normally uses a source returned by F-e1d0a9f8dcb0.
- An admissible selection combined with selector value `0x6D1A` uses a separate conversion sequence and a different result discriminator.

Every normally completing path returns the supplied result address. The function does not return a separate success or failure indicator.

These are established control-flow properties. Interpreting the two result words as a type discriminator and managed payload is inferred intent; their broader representation and lifecycle are not established.

## Interface

The recovered interface has four arguments:

| Argument | Contract role |
|---|---|
| Result address | Address of the caller-supplied destination. The function directly accesses a 32-bit word at offset 0 and, on most paths, a 32-bit word at offset 4. |
| Context address | Address used to read a 32-bit bound at byte offset `0x70` and to form an embedded-object address at byte offset `0x6C`. |
| Selector | Pointer-shaped opaque value compared with `0x6D1A`. This function does not dereference it. |
| Selection | Pointer-shaped value classified by signed comparison. This function does not dereference it. |

The result is the original result address.

### Width and layout requirements

The supplied representation uses 32-bit words and signed integer interpretations of pointer-shaped values. The behavioral contract therefore distinguishes:

- The selection’s 32-bit bit pattern.
- Its signed 32-bit interpretation.
- The context bound’s signed 32-bit interpretation.

A high-bit-set selection is negative for this classification. An unsigned comparison is not equivalent.

Known directly accessed layouts are:

| Storage | Byte offset | Access |
|---|---:|---|
| Context | `0x70` | Read one 32-bit bound |
| Result | 0 | Write one 32-bit discriminator |
| Result | 4 | Usually write zero before a dependency call |
| Chosen ordinary source | 4 | Read one 32-bit value when source and result addresses differ |
| Source returned on the special path | 9 | Read one byte and test whether it is zero |

The address at context offset `0x6C` is passed to F-e1d0a9f8dcb0. This function does not directly read a field at that offset.

The two destination words occupy eight bytes, but that does not establish a complete eight-byte object layout: dependencies may require or access additional storage.

### Preconditions

Normal completion requires valid storage for every access actually reached, and satisfaction of the called dependencies’ preconditions.

In particular:

- The result must permit the discriminator write on every path.
- A nonnegative selection requires the context-bound read.
- An admissible selection requires a valid call to F-e1d0a9f8dcb0.
- The special path requires its returned source to support the byte read at offset 9.
- An ordinary path with distinct source and destination requires a readable source word at offset 4.

No explicit null, alignment, capacity, or address-overflow checks are shown. A negative selection avoids the direct context access; it does not avoid destination access or possible use of the fallback source.

## Behavior

### 1. Selection classification

The function first classifies the selection using its signed 32-bit interpretation.

If the selection is negative:

- The context bound is not read.
- The selection is inadmissible.
- The globally designated fallback source is chosen.

If the selection is nonnegative:

1. Read the 32-bit bound from context offset `0x70`.
2. Compare the selection and bound using signed ordering.
3. Treat equality as inadmissible.
4. Treat a selection greater than the bound as inadmissible.
5. Treat a selection strictly less than the bound as admissible.

Thus admissibility is exactly:

**The signed selection is nonnegative and strictly less than the signed context bound.**

Zero is not independently rejected. A zero selection with a positive bound is admissible; a zero selection with a zero bound is not.

If the bound is negative, no nonnegative selection is admissible. The function nevertheless reads that bound before making this determination.

### 2. Source acquisition

For an inadmissible selection, the function uses the globally designated fallback-source address. It does not call F-e1d0a9f8dcb0, even if the selector equals `0x6D1A`.

For an admissible selection, the function calls F-e1d0a9f8dcb0 with the address at context offset `0x6C`. Its returned address becomes the source.

This dependency is called before deciding whether to take the selector-specific construction path. The selector is not passed to it, and neither the selection nor the bound is passed as an explicit argument.

The selection therefore gates acquisition, but the shown function does not use the selection to index storage or otherwise identify an individual source element.

### 3. Special construction

This path is taken only when both conditions hold:

- The selection is admissible.
- The selector equals `0x6D1A`.

After F-e1d0a9f8dcb0 returns a source address, the function performs the following externally relevant sequence:

1. Obtain a signed 32-bit parameter from a global location.
2. Read the byte at source offset 9.
3. If the byte is nonzero, use the global parameter minus five instead. The supplied expression references the global parameter again on this branch.
4. Call F-9d0ecc5f6adf with no explicit arguments.
5. Call F-c0b020cd3882 with the value returned by F-9d0ecc5f6adf and the selected signed parameter.
6. Write the special discriminator to result offset 0.
7. Write zero to result offset 4.
8. Call F-151ab4bfe553 with the result address and the value returned by F-c0b020cd3882.
9. Return the original result address.

All nonzero flag-byte values select the same adjustment. The flag’s numerical magnitude and signedness do not otherwise affect this function.

The special discriminator is fetched for the destination write after the two conversion-related dependency calls. It is not established that those dependencies preserve the corresponding global storage.

There is no source/destination equality shortcut on this path. If the source returned by F-e1d0a9f8dcb0 equals the result address, the offset-9 flag read still precedes both destination writes, and F-151ab4bfe553 is still called.

### 4. Ordinary construction

This path covers:

- Every inadmissible selection, regardless of selector.
- Every admissible selection whose selector differs from `0x6D1A`.

The chosen source is either the global fallback source or the address returned by F-e1d0a9f8dcb0.

The function first writes the ordinary discriminator to result offset 0. It then compares the result address with the chosen source address.

If the addresses are equal:

- It does not explicitly zero result offset 4.
- It does not read the source word at offset 4.
- It does not call F-151ab4bfe553.
- It returns the result address.

The discriminator write is not skipped by this equality case.

If the addresses differ:

1. Write zero to result offset 4.
2. Read the 32-bit value at chosen-source offset 4.
3. Call F-151ab4bfe553 with the result address and that value.
4. Return the result address.

The source value is not captured before the destination writes. For overlapping but unequal storage, the value supplied to F-151ab4bfe553 is therefore the value visible after those writes. No general overlap protection is present.

## Side effects

### Direct writes

Every normal path writes one discriminator word at result offset 0.

A direct zero write at result offset 4 occurs on:

- Every special-construction path.
- Every ordinary-construction path whose source address differs from the result address.

The exact-address ordinary case leaves the second result word without an explicit write by this function.

The discriminator values are read from two distinct global locations, one for ordinary construction and one for special construction. Their numerical values, and whether they are necessarily different, are not supplied.

### Dependency effects and ordering

F-e1d0a9f8dcb0 may execute before any destination write. On the special path, F-9d0ecc5f6adf and F-c0b020cd3882 also execute before the destination writes.

F-151ab4bfe553 is called only after the function has written the discriminator and zeroed the second word. Its return value is not used by this function.

Unknown callees must not be assumed to preserve globals, preserve the destination, refrain from allocation, or avoid modifying reachable objects. In particular, the final second word cannot be specified as zero merely because this function writes zero before calling F-151ab4bfe553.

### Ownership and lifecycle

No direct allocation or release operation is established in this function.

The fallback source and the source returned by F-e1d0a9f8dcb0 are not explicitly released here. That does not establish ownership transfer, permanent borrowing, or absence of indirect release inside a dependency.

Likewise, the preexisting destination payload is not explicitly released before being overwritten or cleared. The available evidence does not establish whether callers must provide uninitialized storage, an empty object, or an already valid object.

### Errors and abnormal completion

There is no explicit error result, recovery branch, or dependency-result validation.

A null source returned by F-e1d0a9f8dcb0 is not checked before the relevant source access. The global fallback source is also used without a validity check.

Invalid memory, dependency failures, arithmetic faults, or nonlocal exits have no specified recovery behavior here. The guarantee to return the original result address applies only to normal completion.

## Acceptance examples

These examples are conditional static acceptance criteria, not reports of execution. Except where stated otherwise, assume valid reached storage, completing dependencies, and stable global values during the example.

### Negative selection

For selection bit pattern `0xFFFFFFFF`:

- Interpret the selection as negative.
- Do not read the context bound.
- Choose the fallback source.
- Write the ordinary discriminator.
- Perform ordinary construction, including its exact-address shortcut.
- Do not invoke the special conversion sequence, even with selector `0x6D1A`.

### Zero below a positive bound

With selection zero and bound one:

- Read the bound.
- Classify the selection as admissible.
- Call F-e1d0a9f8dcb0 with context offset `0x6C`.

The selector then determines special versus ordinary construction. Zero must not be rejected merely because its pointer-shaped representation is null.

### Equal to the bound

With selection seven and bound seven:

- Choose the fallback source.
- Do not call F-e1d0a9f8dcb0.
- Use ordinary construction regardless of selector.

An implementation accepting equality would violate the strict upper bound.

### Nonnegative selection with a negative bound

With selection zero and bound bit pattern `0xFFFFFFFF`:

- Read the bound.
- Interpret it as negative.
- Reject the selection and choose the fallback.

Unsigned bound comparison would produce different behavior and is not acceptable.

### Special selector and zero flag

With an admissible selection, selector `0x6D1A`, global parameter 20, and a zero source flag byte:

- Call F-9d0ecc5f6adf.
- Pass its result and 20 to F-c0b020cd3882.
- Write the special discriminator, then zero the second result word.
- Pass the conversion result to F-151ab4bfe553.

### Special selector and nonzero flag

Under the same conditions, but with source flag byte `0x80`:

- Pass 15, rather than 20, as the second argument to F-c0b020cd3882.

The nonzero test must not become a positive-only test.

### Ordinary exact-address source

If ordinary construction selects the result address itself:

- Write the ordinary discriminator.
- Preserve the second word from direct writes by this function.
- Do not call F-151ab4bfe553.

If an earlier dependency supplied that source, its independent effects remain outside this preservation statement.

### Overlapping unequal source

If an otherwise valid ordinary source begins four bytes before the result:

- Its second word occupies result offset 0.
- The ordinary discriminator write occurs before that source word is read.
- The value passed to F-151ab4bfe553 is consequently the discriminator value just written, absent intervening external mutation.

This distinguishes the established ordering from an implementation that snapshots the source payload first.

The recovered notation supports the access widths and branch relationships described above. It does not establish volatile semantics or a concurrency-safe physical load count for global reads.
