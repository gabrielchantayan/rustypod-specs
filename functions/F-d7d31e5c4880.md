# F-d7d31e5c4880

## Purpose

F-d7d31e5c4880 searches a context-associated sequence backward for a record whose type byte equals a metadata-selected target byte. It conditionally passes nonmatching records to a processing dependency.

If a match is found, the function performs a count-dependent sequence of calls to F-6f6709bb269a, passes selected return values to F-593b94f57438, evaluates a gate, and conditionally invokes a type-specific handler. **Removal or stack unwinding is inferred intent:** the supplied body establishes these calls, not their effects on the sequence.

If no match is found, the function either returns immediately or constructs and reports a diagnostic, according to a byte in the context’s associated object.

Tag matching, string searching, and object destruction are interpretations of the visible operations. The established contract consists of address calculations, reads, comparisons, dependency calls, local writes, and normal-return cleanup ordering.

## Behavior

### Target selection and reverse traversal

The function retains a matching-table base for later nonmatch-flag lookups. It separately selects a target entry by reading the incoming type, reading that type’s selector at entry `+0x0e`, and applying the selector’s 16-byte stride to the matching table.

The retained target is an **entry address**, not a saved target-byte value. Its byte at `+0` is read during candidate comparisons.

The initial count is read from context `+8`. Each search iteration proceeds in this order:

1. Capture the current diagnostic-table base.
2. Decrement the local signed traversal counter.
3. If the counter is negative, enter the unmatched path.
4. Otherwise, call F-292da82dde20 with the sequence-subobject address and current index.
5. Treat its result as a candidate address and compare the candidate type byte with the selected target entry’s byte.
6. On equality, leave the search immediately.
7. On inequality, use the candidate type to read matching-table entry `+0x0d`, using the retained matching-table base. Unless that byte is exactly `1`, call F-bd120056260a with the context and candidate addresses.

For a stable nonnegative count, lookup indices descend from count minus one through zero. Matching is decided before the nonmatch flag is tested; that flag cannot suppress acceptance of an equal type.

The traversal counter is local and is not refreshed after F-bd120056260a. Dependencies may nevertheless change the context, sequence, record bytes, metadata storage, or global table references. Such changes can affect subsequent accesses without changing the local index schedule. In particular, mutation of the selected entry’s comparison byte can change later matching results.

### Unmatched path and diagnostic suppression

After exhaustion, the function reads the associated-object address from context `+0` and then reads its byte at `+0x39`.

- A nonzero byte causes immediate return.
- A zero byte starts diagnostic construction.

This suppression test occurs after processing all visited nonmatching candidates. A suppressed diagnostic therefore does not imply a side-effect-free search.

### Post-match sequence calls

After finding a match, the function rereads context `+8` into a separate local counter.

It decrements that counter before each comparison with the saved matched index. Whenever the decremented counter is greater than the matched index:

1. Call F-6f6709bb269a with the sequence-subobject address.
2. Pass its return value to F-593b94f57438, together with the context address and a third argument of zero.

After this loop, it calls F-6f6709bb269a once more with the sequence-subobject address and ignores the result.

For an ordinary stable count, the paired calls correspond numerically to the positions above the match, followed by one additional F-6f6709bb269a call. This numerical correspondence does **not** establish that any call removes, retrieves, frees, or invalidates an entry.

The loop counter does not track count changes made by these dependencies. Even when the reread count permits no paired calls, the final unpaired F-6f6709bb269a call still occurs.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Empty sequence, suppressed diagnostic.** With count zero and a valid associated object whose suppression byte is nonzero, no candidate lookup, post-match sequence call, gate evaluation, or diagnostic construction occurs.

2. **Empty sequence, enabled diagnostic.** With count zero and a zero suppression byte, diagnostic construction occurs. No post-match sequence call or handler occurs.

3. **Topmost match.** With stable count and storage, a match at the first lookup produces no F-bd120056260a call and no F-593b94f57438 call. One F-6f6709bb269a call precedes the gate. Its effect on sequence contents remains unspecified.

4. **Two positions above a match.** With the reread count exactly three greater than the matched index, two F-6f6709bb269a/F-593b94f57438 pairs occur, followed by one unpaired F-6f6709bb269a call. Removal is not an acceptance requirement established by this body.

5. **Exact nonmatch flag.** A nonmatching candidate with flag `1` bypasses F-bd120056260a; flags `0`, `2`, and `255` permit that call.

6. **Gate rejection.** Result `-1` suppresses handlers and is followed by gate-object finalization. Earlier sequence calls have already occurred. No particular final sequence state is guaranteed.

7. **Other negative gate result.** Result `-2` permits dispatch. Types `6` and `8` select the same handler; type `200` selects none.

8. **Diagnostic type changes.** If the first primary-construction call changes the incoming type, the entry-`+8` test uses the changed type with the exhaustion iteration’s captured diagnostic-table base.

9. **Diagnostic context changes.** If primary representation extraction or output initialization changes context `+0`, F-e8e529026c43 receives the subsequently reloaded address, not necessarily the suppression-test address.

10. **Late diagnostic field and cleanup.** If transformed-representation extraction changes incoming `+4`, formatting uses the later field value. When the optional branch executes normally, its populated component is finalized before its auxiliary object.
