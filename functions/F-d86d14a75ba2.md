# F-d86d14a75ba2

## Purpose

F-d86d14a75ba2 obtains a selector through F-79e7676a2ca1 and, when that operation succeeds, uses the selector’s least significant eight bits to choose one of three integer results:

- The supplied base value.
- The base value plus 16.
- The base value plus 32.

The selected value is written to caller-designated storage. The function returns a status indicating success or failure.

There are two distinct failure behaviors. A nonzero dependency status causes an immediate failure return without an explicit write by this function to the output destination. A successful dependency call followed by an unsupported selector causes this function to write zero to the output destination and then return failure.

The base value may represent an address, offset, or other numeric quantity. Its semantic role is not established by the supplied evidence. This contract therefore treats it as an integer, not as a pointer that this function dereferences.

### Dependency failure

The function first checks whether the dependency’s returned status is zero.

If the status is nonzero:

- The function returns 1 immediately.
- It does not normalize or dispatch on the temporary selector’s value.
- It performs no explicit write through the output destination.

Any selector changes made by the dependency are irrelevant to this function’s result on that path.

### Selector normalization

If the dependency returns zero, the function uses the temporary word as it exists after the dependency call. It retains only the least significant eight bits.

The resulting selector is therefore in the range 0 through 255. The upper 24 bits do not affect selection after a successful dependency return.

This rule applies equally when the dependency modifies the temporary word and when it leaves the word unchanged. In the latter case, selection uses the least significant eight bits of the caller’s initial selector word.

The selector is a numeric bit-field extraction, not an evidenced byte load from a particular memory address. No byte-order assumption is needed to describe it.

|---|---|---|

| 1 | Base value plus 16 | 0 |
| 2 | Base value plus 32 | 0 |
