# F-a2d1320ee317

## Purpose

F-a2d1320ee317 accepts four 32-bit words and returns one 32-bit word. Its established behavior has three outcomes:

- Return the first input word unchanged.
- Produce a condition-bit result from comparisons of the input words and an implicit incoming byte.
- Dispatch through an implicit, aligned control-transfer address, using arguments selected from the inputs, shared state, and shared data.

The input layout and classification thresholds resemble two binary64 values split into low and high words. That interpretation is **inferred intent**, not a sufficient behavioral specification: many inputs that would ordinarily require numerical comparison instead return the first word unchanged. The contract below preserves that distinction.

No runtime tests have been performed.

### Arithmetic conventions

All word arithmetic wraps modulo \(2^{32}\). High-word doubling discards overflow. Signed tests interpret the same 32 bits as a two’s-complement signed integer.

An unsigned comparison and a signed comparison are distinct operations. In particular, neither the raw high-word comparisons nor their direction should be replaced by a general floating-point comparison.

## Behavior

### 1. Input classification and unchanged return

For each pair, define its **doubled high word** as its high word multiplied by two, retaining only 32 bits.

The initial decision is equivalent to the following classification:

- If **both** doubled high words are unsigned-less-than `0xffe00000`, return the first low word immediately.
- Otherwise, proceed to the next classification.

This is a simplification of the supplied signed tests and overflow checks, not an assumption about floating-point semantics.

For a binary64 interpretation, the unchanged-return path includes pairs whose exponent fields are not all ones. The low words do not affect this initial decision.

Consequences:

- Ordinary finite-looking inputs do not necessarily yield a packed comparison result.
- Different inputs can return the same value solely because their first low words match.
- Shared selector and shared data are not visibly read on this early-return path.
- The incoming condition byte does not affect this result.

### 2. Classification before comparison or dispatch

A word pair is **comparison-admissible** when either:

- Its doubled high word is unsigned-less-than `0xffe00000`; or
- Its doubled high word equals `0xffe00000` and its low word is zero.

If both pairs are comparison-admissible, proceed to packed comparison.

Otherwise, proceed to shared-state dispatch.

Because the initial unchanged-return decision has already excluded the case where both doubled high words are below the threshold, entry into packed comparison requires at least one pair whose doubled high word equals the threshold and whose low word is zero.

Under the inferred binary64 interpretation, this separates infinity-like encodings from NaN-like encodings. That terminology does not establish signaling-NaN handling, floating-point exceptions, or IEEE comparison behavior.

### 3. Packed comparison when either high word has its top bit set

This branch is selected when the bitwise OR of the two high words has bit 31 set.

Define:

- **Equal:** both high words match and both low words match.
- **Carry condition:** the first high word is unsigned-less-than-or-equal-to the second high word; if the high words are equal, use first low word unsigned-less-than-or-equal-to second low word instead.

The result is built as follows:

- Start with the incoming condition byte.
- OR in bit 3 when Equal is true.
- OR in bit 2 when the Carry condition is true.
- Retain only byte bits selected by mask `0x0d`.
- Shift those retained bits left by 27.
- Set result bit 31 when the Carry condition is false.

Thus:

- Result bits 0–26 are zero.
- Result bit 28 is zero.
- Result bit 27 preserves incoming condition-byte bit 0.
- Result bit 29 is set by either incoming byte bit 2 or the Carry condition.
- Result bit 30 is set by either incoming byte bit 3 or Equal.
- Result bit 31 is the inverse of the Carry condition.

Incoming condition bits can therefore keep bits 29 or 30 set even when the corresponding comparison predicate is false.

This branch also applies to mixed-sign pairs. It does not first establish that both operands are negative.

### 4. Packed comparison when neither high word has its top bit set

This branch selects a single 32-bit subtraction:

- If the high words differ, subtract the second high word from the first high word.
- If the high words match, subtract the second low word from the first low word.

For that selected subtraction, define:

- **Difference:** the wrapped 32-bit subtraction result.
- **Carry condition:** the first selected word is unsigned-greater-than-or-equal-to the second selected word.
- **Overflow:** signed subtraction overflow.
- **Equal:** both complete word pairs match.

The generated flag predicates are:

| Condition | Generated negative flag | Generated zero flag | Generated carry flag |
|---|---|---|---|
| No signed overflow | Signed Difference is negative | Equal | Carry condition |
| Signed overflow | Inverse of Carry condition | False | Carry condition |

The function ORs the incoming condition byte with:

- Bit 4 for the generated negative flag.
- Bit 3 for the generated zero flag.
- Bit 2 for the generated carry flag.

The byte-sized result is then shifted left by 27 with a 32-bit result.

Only incoming byte bits 0–4 survive that shift:

- Bit 0 maps to result bit 27.
- Bit 1 maps to result bit 28.
- Bit 2 maps to result bit 29.
- Bit 3 maps to result bit 30.
- Bit 4 maps to result bit 31.

Unlike the previous branch, this branch does not clear incoming byte bits 1 and 4 before shifting. A caller must not assume those incoming bits are absent or harmless.

### 5. Shared-state dispatch

Dispatch begins only when the initial unchanged-return path was bypassed and at least one pair is not comparison-admissible.

All indirect destinations are formed by clearing the incoming transfer word’s bottom two bits. The destination is described below as **F-000000000001**, an opaque identifier assigned for this contract. Its actual identity is unknown.

#### Selector mask `0x000d0000` is clear

The selector’s low nibble controls an initial dispatch choice.

| Low nibble | Established action |
|---|---|
| `10` | Invoke F-000000000001 with two visible arguments: first `0x80000000` if selector bit `0x40` is set, otherwise zero; second shared datum K. Return its result. |
| `8`, with selector bit `0x40` set | Invoke F-000000000001 with visible arguments zero and zero. Return its result. |
| `8`, with selector bit `0x40` clear | Initially select shared datum A and shared datum K as the two arguments. If selector bit `0x10` is set, replace them with zero and shared datum B. Invoke F-000000000001 and return its result. |
| `9` | Replace the working first low word with `8` and the working first high word with shared datum K, then continue to the remaining selector tests. |
| Any other value | Transfer to F-000000000001 with no explicit arguments shown. Return its attributed result. |

“No explicit arguments shown” does not establish that the destination receives no meaningful machine-register state.

#### Remaining selector tests

These tests are reached when the initial `0x000d0000` mask is nonzero, or after the low-nibble-9 replacement above.

1. If selector bit `0x00100000` is clear, invoke F-000000000001 with one visible argument, zero, and return its result.

2. Otherwise, if selector mask `0x00070000` is clear, invoke F-000000000001 with three visible arguments:
   - `0x30000000`;
   - The working first high word;
   - `0x30000000` OR incoming condition-byte bit 0 shifted to bit 27.

3. Otherwise, invoke F-000000000001 with two visible arguments:
   - The working first low word;
   - The selector transformed by shifting left 15, complementing the 32-bit result, and shifting left once more.

The second argument in the final case is equivalently:

\[
\bigl(\mathop{\sim}(\text{selector}\ll16)\bigr)\mathbin{\&}\texttt{0xfffffffe}
\]

with all intermediate and final values limited to 32 bits.

The low-nibble-9 replacements affect subsequent dispatch arguments only. They are not writes back to the caller’s inputs or to shared data.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Packed-result examples assume the incoming condition byte is zero unless stated otherwise.

1. **Unchanged return for two below-threshold high words.**  
   First pair: low `0x12345678`, high `0x3ff00000`. Second pair: low zero, high `0x40000000`. Both doubled high words are below `0xffe00000`. Expected result: `0x12345678`, without visible shared-state dispatch.

2. **Equal positive infinity-like pairs.**  
   Both pairs have low zero and high `0x7ff00000`. Packed comparison is selected, with equality and carry set. Expected result: `0x60000000`.

3. **Positive infinity-like first pair and smaller nonnegative second pair.**  
   First pair: low zero, high `0x7ff00000`. Second pair: low zero, high `0x3ff00000`. Expected result: `0x20000000`.

4. **Equal negative infinity-like pairs.**  
   Both pairs have low zero and high `0xfff00000`. The top-bit-set comparison branch produces `0x60000000`.

5. **Mixed signs retain raw-word behavior.**  
   First pair: low zero, high `0x7ff00000`. Second pair: low zero, high `0xfff00000`. The top-bit-set branch uses the unsigned high-word relation, producing `0x20000000`. Reversing the pairs produces `0x80000000`.

6. **Incoming condition bits affect an unequal result.**  
   Use example 3 with incoming condition byte `0x08`. Its incoming bit 3 sets result bit 30 even though the pairs differ. Expected result: `0x60000000`.

7. **NaN-like low-word payload reaches dispatch.**  
   First pair: low `1`, high `0x7ff00000`. Second pair: low zero, high zero. The first pair is not comparison-admissible. If selector reads consistently yield `0x0000000a`, the visible transfer arguments are zero and shared datum K.

8. **Low-nibble-9 replacement reaches the three-argument transfer.**  
   For the dispatch-triggering inputs in example 7, suppose selector reads consistently yield `0x00100009` and the incoming condition byte’s bit 0 is set. The visible transfer arguments are `0x30000000`, shared datum K, and `0x38000000`.

9. **Final selector transformation uses 32-bit truncation.**  
   For a dispatch-triggering input and consistent selector value `0x00110000`, the initial mask is nonzero, bit `0x00100000` is set, and mask `0x00070000` is nonzero. The final transfer receives the original first low word and `0xfffffffe`.
