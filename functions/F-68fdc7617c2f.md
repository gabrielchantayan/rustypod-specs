# F-68fdc7617c2f

## Purpose

F-68fdc7617c2f conditionally transfers a caller-specified quantity of data into an existing destination, either through a direct transfer dependency or through a replacement dependency selected by a size-like comparison.

The established behavior is narrower than that interpretation: the function checks a destination marker, obtains a 16-bit selection value, computes and compares two unsigned 32-bit values, and dispatches one of two update paths. The meanings of the compared values and the dependencies’ actual data-management behavior are not established by the supplied material.

The function returns a 32-bit zero on every explicit return path. A separate one-byte output records whether execution reached the end of an update path. That byte is not an independently verified indication that a dependency completed its intended operation successfully.

## Behavior

### 1. Initialize the completion indication

The first visible operation writes zero to the completion byte.

The function then reads the destination’s one-byte marker at offset 8. Processing continues only when this marker compares equal to signed negative one, corresponding to byte representation `0xFF` in the apparent environment.

If the marker does not match, the function returns zero without calling any dependency.

The marker is not visibly checked again later.

### 2. Obtain a selection value

For an eligible marker, the function calls F-8a92d5d60703 with:

- The context address.
- The destination address.
- The incoming payload address, 28 bytes beyond the incoming-object base.
- The address of local storage from which a 16-bit selection value is subsequently read.

A zero result causes the function to return zero without proceeding to either update path. Any nonzero result permits continuation.

The supplied material does not establish how much local storage the dependency writes, what the selection denotes, or whether the dependency has already modified other state. Subsequent processing requires the first 16-bit selection value to be usable.

### 3. Derive the first comparison input

After the eligibility dependency returns nonzero, the function reads the context’s 32-bit flags field at offset 48 and tests bit value 2.

If that bit is clear:

- Read the payload’s first byte as an unsigned value.
- Add one using 32-bit arithmetic.

If that bit is set:

- Read the payload’s first 16 bits as an unsigned value.
- Add two using 32-bit arithmetic.

Call the result the **augmented prefix value**. Its range is 1 through 256 in byte mode and 2 through 65,537 in 16-bit mode.

The function then clears bit 16 using mask `0xFFFEFFFF`. Call the resulting 32-bit value the **masked extent**.

This operation is not a general truncation to 16 bits. For the ranges reachable here, it has these notable effects:

- Byte-mode values are unchanged.
- An augmented prefix value of 65,536 becomes zero.
- An augmented prefix value of 65,537 becomes one.

The function calls F-3803ab006ceb with the masked extent and the transfer parameter. Its returned value is treated as an unsigned 32-bit comparison value.

Next, the function calls F-c4c1afdb3fb3 with the context, destination, and the 16-bit selection value. Its returned value is also treated as an unsigned 32-bit comparison value.

The two dependencies execute in that order. Their results are retained for the branch decision; they are not recomputed after later calls.

### 4. Equal-comparison path

If the two comparison values are equal, the function prepares a direct-transfer address.

When the augmented prefix value is odd, the masked extent is increased by one and masked again with `0xFFFEFFFF`. When the augmented prefix value is even, the masked extent is unchanged.

For the reachable input ranges, this adjustment produces an even displacement. It must not be described as an unrestricted “round up to even,” because the earlier bit-clearing operation can collapse large values to zero or one.

The function obtains a signed displacement through a 16-bit table read. The table-entry address is formed from:

- The destination base.
- The context’s unsigned 16-bit field at offset 28.
- Minus twice the unsigned 16-bit selection value.
- Minus two.

The 16-bit value read from that address is interpreted as signed, so values with the high bit set contribute negative displacements.

The final transfer address is the destination base plus that signed displacement plus the adjusted masked extent. Address calculations use the apparent 32-bit address domain; no overflow or range rejection is visible.

The function calls F-70a021fc7c24 with:

1. The 32-bit value read from the transfer-address slot.
2. The computed transfer address.
3. The transfer parameter.

No result from this dependency is inspected. After it returns normally, the function writes one to the completion byte and returns zero.

The table calculation and transfer-address-slot read occur after both comparison dependencies have returned. The supplied representation does not establish their relative evaluation order within the final call’s argument preparation.

### 5. Unequal-comparison path

If the comparison values differ, the function calls F-8cb9e658d14d with the context and destination.

Its result is added to the retained value returned by F-c4c1afdb3fb3. The addition and subsequent comparison are unsigned 32-bit operations. A negative signed representation of the new result therefore participates through its corresponding 32-bit unsigned value.

If this wrapped sum is less than the value returned by F-3803ab006ceb, the function immediately returns zero. Neither update dependency is called on that path.

Otherwise, the function calls F-76b5978a0554 with the context, destination, and selection value.

After that call returns, the function reads the context flags again. It does not reuse the earlier flag value. Depending on bit value 2 in this new read, it obtains either:

- The payload’s first unsigned byte, widened to 16 bits; or
- The payload’s first unsigned 16-bit value.

This is the unaugmented prefix value: no addition of one or two and no clearing of bit 16 are applied to this argument.

The function then calls F-dfe52f60212b with:

1. The context.
2. The destination.
3. The selection value.
4. The incoming payload address.
5. The newly read, unsigned 16-bit prefix value.
6. The 32-bit value read from the transfer-address slot.
7. The transfer parameter.

No result from this dependency is inspected. After it returns normally, the function writes one to the completion byte and returns zero.

The rereads after F-76b5978a0554 are observable. Changes to flags or payload contents made by dependencies may affect this final call, even though the earlier branch comparison used previous values.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless stated otherwise, assume valid memory, normally returning dependencies, and no dependency modification of the completion byte or relevant aliased state.

### Ineligible destination

Given a destination marker other than `0xFF`:

- The completion byte is written to zero.
- No dependency is called.
- The return value is zero.

### Eligibility dependency declines

Given marker `0xFF` and a zero result from F-8a92d5d60703:

- No comparison or update dependency is called.
- The function performs no final completion-byte write.
- The return value is zero.

### Equal values with byte prefix four

Given byte mode and a payload prefix of four:

- The augmented prefix value is five.
- F-3803ab006ceb receives five as its first argument.
- If the comparison values match, the direct-transfer displacement is adjusted to six.

If the context’s 16-bit table-position field is 20, the selection is two, and the signed table entry is negative four, then:

- The table entry is read at destination base plus 14.
- The transfer address is destination base plus two.
- F-70a021fc7c24 is called.
- After it returns, the completion byte is written to one.

### Boundary in 16-bit mode

Given 16-bit mode:

- Prefix 65,534 produces augmented value 65,536 and masked extent zero.
- Prefix 65,535 produces augmented value 65,537 and masked extent one.

On the equal-comparison path, their adjusted transfer displacements are zero and two, respectively. These outcomes follow from clearing bit 16, not saturation or rejection.

### Unequal values with insufficient wrapped sum

Suppose the first comparison value is 120, the second is 80, and F-8cb9e658d14d returns 39.

The sum is 119, which is less than 120. Neither F-76b5978a0554 nor F-dfe52f60212b is called.

### Unsigned overflow affects permission

Suppose the first comparison value is 100, the second is `0xFFFFFFF0`, and F-8cb9e658d14d returns 32.

The unsigned 32-bit sum wraps to 16. Since 16 is less than 100, the unequal-comparison path returns without performing its update sequence.

### A dependency changes the prefix mode

Suppose the initial flags select byte mode, but F-76b5978a0554 changes bit value 2 to set.

The earlier comparison input remains based on the original byte-mode read. The final call to F-dfe52f60212b receives a newly read 16-bit payload prefix. It does not receive the earlier byte value or augmented extent.
