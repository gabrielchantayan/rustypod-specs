# F-c5470e678f3c

## Purpose

F-c5470e678f3c conditionally submits a four-word record to F-6d16652f2d03 and returns a 64-bit value assembled from two 32-bit words.

A byte at offset 168 from the address represented by the first input selects the behavior:

- If the byte is zero, the function makes no dependency call and returns the original two inputs packed into a 64-bit result.
- If the byte is nonzero, the function replaces the working values with a fixed four-word record, passes that record and the original first input to F-6d16652f2d03, and then packs the record’s first two words into the result.

The record is writable temporary storage. The supplied evidence does not establish that F-6d16652f2d03 leaves it unchanged. Consequently, the nonzero-byte path does not unconditionally return the fixed values used to initialize the record.

The semantic purpose of the byte, the four constants, and the returned pair is unknown. Interpreting them as a mode flag, coordinates, dimensions, or another application-specific structure would be inferred intent rather than established behavior.

## Behavior

### Entry and flag inspection

The function first places the two inputs into private working storage. The first working word initially contains the first input’s 32-bit pattern; the second contains the second input.

It then reads the byte at offset 168 from the address represented by the original first input. That byte read occurs before any call to F-6d16652f2d03.

Only zero versus nonzero matters. The function does not distinguish among different nonzero byte values. Byte signedness therefore does not affect branch selection: a byte pattern such as `0x80` selects the same path as `0x01`.

There is one explicit inspection of this byte. The function does not explicitly reread it after the dependency returns.

### Zero-byte path

If the inspected byte is zero:

1. The initial first and second working words remain the return sources.
2. F-6d16652f2d03 is not called.
3. The function returns the original first input’s 32-bit pattern in the low half and the original second input in the high half.

The final two positions of the four-word temporary area are not initialized on this path. They are neither passed to a dependency nor used to form the return value, so their contents do not affect the established result.

There is no explicit write to caller-provided storage on this path.

### Nonzero-byte path

If the inspected byte is nonzero, the function replaces the working storage with the four-word record described above. The original first and second working values no longer supply the return value merely by virtue of being inputs.

The record is populated in increasing field-offset order: offsets 0, 4, 8, and 12. All four initial values are established before the dependency call.

The function then calls F-6d16652f2d03 exactly once, with:

- The original first input as its first argument.
- The address of the temporary record as its second argument.

The dependency’s return value, if it has one, is not used by this function.

If the dependency returns normally, F-c5470e678f3c forms its result from the record’s first two words as they exist at that point. Thus:

- Changes to offset 0 affect the low 32 bits.
- Changes to offset 4 affect the high 32 bits.
- Changes confined to offsets 8 and 12 do not directly affect the result.
- The caller’s original second input has no direct role in constructing the nonzero-path result after initialization of the fixed record.

The supplied evidence does not establish an evaluation order between the final reads of the first two words. Both are used after the dependency returns.
