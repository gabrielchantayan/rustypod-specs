# F-320e29a50dbb

## Purpose

F-320e29a50dbb conditionally prepares a record for a nonnegative-size operation and invokes an unresolved indirect target with the record’s current 32-bit value, a caller-supplied argument, and the requested size.

Two selector values are accepted. They determine a one-byte record field when a positive-size request successfully obtains a nonzero result from F-d33f6d597e5d. A zero-size request follows a distinct path: it skips that dependency and the associated record-field updates, but still invokes the indirect target.

Selected failures are reported through a caller-provided 32-bit error slot, without overwriting an existing nonzero error. Some paths return silently.

The apparent intent is resource or storage preparation followed by a transfer-like operation. That interpretation is inferred, not established: the meanings of the record value, selectors, indirect operation, and error values are not supplied.

## Interface

The recovered interface has five arguments and no explicit return value:

| Position | Contract name | Representation and use |
|---|---|---|
| 1 | Owner base | Pointer to storage. Its first 32-bit word is used as a sticky error slot. An address 2,760 bytes beyond this base is passed to F-a01d4dfb5f88. |
| 2 | Unused argument | A 32-bit argument with no direct use in the supplied body. |
| 3 | Requested size | Signed 32-bit integer. Negative, zero, and positive values have distinct behavior. |
| 4 | Operation argument | An opaque 32-bit value forwarded unchanged to the indirect target. |
| 5 | Selector | A 32-bit value accepted only when equal to `0x88E4` or `0x88E8`. |

Widths and offsets follow the recovered 32-bit representation: integer words occupy four bytes, and stepping the owner pointer by 690 words produces the 2,760-byte offset. The supplied body does not independently establish the original source-level types or complete object layouts.

The function uses the following external state:

- A context pointer returned by F-b44c6ce96792.
- The first 32-bit word addressed by that context pointer.
- Three external 32-bit error-value sources, called **default error**, **state error**, and **allocation error** in this contract. These names describe where the values are selected, not their numeric values or authoritative meanings.
- A record pointer returned by F-a01d4dfb5f88.
- An indirect call target obtained from external storage.

### Storage requirements

Requirements are path-dependent:

- If F-b44c6ce96792 returns null, no owner storage is directly accessed.
- An error-reporting path with a nonzero selected error requires a readable owner error slot. That slot must also be writable if its current value is zero.
- The lookup path requires an owner base for which the address at byte offset 2,760 is valid for the requirements of F-a01d4dfb5f88.
- The returned record must support a 32-bit access at offset 0 whenever the indirect target is reached.
- A successful positive-size preparation additionally requires writable 32-bit storage at offset 4 and writable one-byte storage at offset 8.
- The returned context must support a readable first 32-bit word on paths that examine it.
- The indirect target must be callable using the observed three-argument interface.

No explicit checks establish these storage requirements. Violation has no defined recovery behavior in the supplied body.

## Behavior

### Context acquisition and initial error selection

The first operation is a call to F-b44c6ce96792 with no explicit arguments.

If its result is null, the function returns immediately. In that case, the supplied body does not read the selector-dependent error sources, access the owner error slot, look up a record, or invoke the indirect target. Effects of the context-acquisition dependency itself remain possible.

For a nonnull context result, the function reads the default error value before validating the selector.

### Selector validation

The selector is interpreted as follows:

| Selector | Selected one-byte value |
|---|---:|
| `0x88E4` | 0 |
| `0x88E8` | 1 |
| Any other value | Rejected |

A rejected selector enters error reporting with the previously read default error value. It does not cause the context’s first word to be read by this body.

An accepted selector fixes the one-byte value for this invocation. The selector is not re-evaluated after later dependency calls.

### Size and context-state checks

For an accepted selector:

- A negative requested size enters error reporting using the default error value.
- A nonnegative requested size causes the state error value to be read, followed by a read of the context’s first 32-bit word.
- If that context word is zero, the function enters error reporting with the state error value.

Thus, a negative size does not cause this body to inspect the context’s first word. The state error source is read for a nonnegative size even if the subsequent context-word check fails.

When the requested size is nonnegative and the context word is nonzero, the function calls F-5028f4afa8de with no explicit arguments. Immediately after that call returns, it reads the state error value again.

If the dependency returns zero, the function enters error reporting using this newly read state error value. A nonzero result permits processing to continue.

The second read matters: F-5028f4afa8de is not established to preserve external error state, so a failure after this call need not use the same state error value read before the call.

### Record lookup and intervening dependency

After a nonzero result from F-5028f4afa8de, the function calls F-a01d4dfb5f88 with:

1. The address at byte offset 2,760 from the owner base.
2. The current first 32-bit word of the acquired context.

The context word is read again for this call. It is not guaranteed to equal the nonzero value used by the earlier check: the intervening dependency may have changed it. In particular, the supplied body does not reject a newly observed zero at this point.

The result of F-a01d4dfb5f88 is treated as the record pointer. There is no null-result check.

The function then calls F-66f29ea52eb3 with no explicit arguments. This occurs before either the positive-size preparation or the zero-size indirect call. Its purpose and effects are unknown. The record pointer must remain suitable for the accesses that follow; the supplied body neither verifies that condition nor reacquires the pointer.

### Positive-size preparation

For a requested size greater than zero, the function:

- Calls F-d33f6d597e5d with the requested size.
- Writes the dependency’s 32-bit result into the record at byte offset 0.
- Reads the allocation error value.
- Checks whether the dependency result was zero.

If the result was zero, the function enters error reporting with the allocation error value. Before doing so, it has already overwritten the record’s first word with zero. This failure path does not update the size field or selector byte and does not invoke the indirect target.

If the result was nonzero, the function writes:

| Record offset | Width | Written value |
|---|---:|---|
| 0 | 32 bits | Result of F-d33f6d597e5d, already stored before the zero check |
| 4 | 32 bits | Requested size |
| 8 | 8 bits | Selector-derived value, 0 or 1 |

The offset-4 write precedes the offset-8 write. The latter is a single-byte write; this body does not directly overwrite bytes 9 through 11.

The allocation error source is read even when the dependency succeeds. A nonzero value in that source does not, by itself, prevent the subsequent indirect call. The branch depends on the dependency result.

No local arithmetic scales or rounds the requested size. Every positive signed 32-bit value, including the largest representable value, is forwarded as supplied. Any size limits, arithmetic, or allocation policy inside F-d33f6d597e5d are unknown.

### Zero-size behavior

For a requested size of zero, the function skips all of the following:

- F-d33f6d597e5d.
- The direct write to record offset 0.
- The allocation error read.
- The direct write to record offset 4.
- The direct write to record offset 8.

It proceeds to the indirect invocation using the record’s then-current first word.

Consequently, accepting a selector for a zero-size request does not cause this body to update the selector byte. Any record modifications made by the lookup or other dependencies are separate from these skipped direct writes.

### Indirect invocation

Both a successful positive-size request and an eligible zero-size request invoke the unresolved indirect target with three arguments, in this order:

1. The current 32-bit word at record offset 0.
2. The original operation argument.
3. The requested size.

The first argument is read from the record for this invocation rather than supplied solely from the earlier dependency result.

The function returns after the indirect invocation. It does not inspect a return value, explicitly translate a downstream failure into the owner error slot, or perform a later cleanup operation.

The supplied representation does not establish the relative evaluation order of loading the indirect target and evaluating its arguments. It does establish that the invocation follows the applicable record preparation.

### Error reporting

All explicit local error exits share the same reporting rule:

- If the selected error value is zero, return without accessing the owner error slot.
- Otherwise, read the owner’s first 32-bit word.
- If that word is zero, write the selected error value there.
- If it is nonzero, leave it unchanged.

The selected error source is:

| Condition | Selected value |
|---|---|
| Rejected selector | Default error |
| Accepted selector with negative size | Default error |
| Nonnegative size with initially zero context word | State error read before that context check |
| Zero result from F-5028f4afa8de | State error read after that dependency returns |
| Zero result from F-d33f6d597e5d | Allocation error read after storing the zero result |

This body does not clear an existing error on success.

## Side effects

Directly observable writes are limited to:

- Record offset 0 after F-d33f6d597e5d returns, including when its result is zero.
- Record offset 4 after a nonzero result for a positive size.
- Record offset 8, as a single byte, after that size-field write.
- The owner’s first word on an error path, only when both the selected error is nonzero and the existing owner word is zero.

The function also calls dependencies whose effects are not supplied. Their names or positions do not establish that they allocate, free, synchronize, preserve globals, or retain pointers.

There is no explicit release of the previous record value before it is overwritten. F-66f29ea52eb3 may be relevant to that lifecycle, but this is not established. Similarly, the ownership of a nonzero value returned by F-d33f6d597e5d is unknown. Passing it through the record and indirect call does not by itself establish an ownership transfer.

No non-aliasing guarantee is shown. If owner, context, record, or external-state storage overlap, writes and dependency effects may affect later reads. Ordinary separate-object interpretations require corresponding caller or dependency guarantees.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless stated otherwise, storage is valid and dependencies return normally.

1. **No context:** F-b44c6ce96792 returns null. The function returns without directly reading or writing owner storage, regardless of selector or size.

2. **Rejected selector:** Context acquisition succeeds, the default error value is 7, and the owner error slot is zero. A selector other than the two accepted values causes the slot to become 7. Record lookup and the indirect invocation do not occur.

3. **Sticky existing error:** The selected error value is 7, but the owner error slot already contains 9. The function leaves 9 unchanged.

4. **Zero selected error:** A rejected selector selects a default error value of zero. The function returns without directly reading the owner error slot.

5. **Negative size:** With an accepted selector and size −1, the function uses the default error path. It does not directly read the context’s first word or call F-5028f4afa8de.

6. **State changes during eligibility check:** The state error value is initially 3. F-5028f4afa8de changes it to 5 and returns zero. The function reports 5, subject to the sticky-error rule.

7. **Context changes before lookup:** The initially checked context word is nonzero. F-5028f4afa8de returns nonzero but changes that word to zero. The lookup receives zero as its second argument; no second nonzero check occurs.

8. **Positive-size success:** With size 12 and selector `0x88E8`, F-d33f6d597e5d returns a nonzero value. The function stores that value at record offset 0, writes 12 at offset 4, writes byte 1 at offset 8, and invokes the indirect target with the current first record word, the supplied operation argument, and 12.

9. **Positive-size failure:** F-d33f6d597e5d returns zero. The record’s first word becomes zero before error reporting. This body leaves the size field and selector byte untouched and does not invoke the indirect target.

10. **Zero-size request:** Eligibility and lookup succeed. The function calls F-66f29ea52eb3, skips F-d33f6d597e5d and all three preparation writes, then invokes the indirect target with the current first record word and a size of zero.
