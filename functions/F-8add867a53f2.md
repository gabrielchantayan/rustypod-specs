# F-8add867a53f2

## Purpose

F-8add867a53f2 returns an unsigned 32-bit scalar derived from the exact product of two signed 32-bit integers. A third input controls which product bits contribute to the result.

**Established static behavior:** only the lowest eight bits of the control affect the displacement counts. The result combines two product-derived contributions by bitwise OR. One contribution involves signed 32-bit displacement, so a general, target-independent product-window interpretation is not established for every input.

**Inferred intent:** extract a 32-bit window from a wider product. This interpretation gives a definite numeric contract within the conservative arithmetic domain below. Extending it to negative products, overflowing signed displacements, or excessive displacement counts requires execution-model evidence that has not been supplied.

The function has no explicit input validation, rounding adjustment, saturation, or error-reporting operation. All conclusions in this document are static; no runtime tests have been performed.

\[

=
\left\lfloor
\frac{\text{exact product}}{2^{\text{control byte}}}
\right\rfloor.
\]

The product bound ensures that this quotient is between 0 and 2,147,483,647. No result truncation, wraparound, or saturation is needed within this domain.

Equivalently, number product bits from zero at the least significant position. The result contains the 32-bit window beginning at the position selected by the control byte, with that window’s lowest bit becoming result bit zero. The conservative bound ensures that the window’s highest bit is zero.

Bits below the selected window are discarded. There is no rounding toward the nearest value and no adjustment based on discarded bits.

The two contributions are combined by bitwise OR, not by addition. For valid counts and defined arithmetic, they occupy disjoint output positions. There is no carry propagation between them.

### Why valid counts are not sufficient

The lower product contribution has unsigned 32-bit interpretation. Its in-range rightward displacement is therefore zero-filling.

The upper contribution passes through signed 32-bit interpretation before leftward displacement. The supplied evidence does not establish unsigned, modulo-\(2^{32}\) displacement semantics for that contribution.

Under ordinary signed-shift rules requiring a nonnegative operand and a signed-representable result, a control byte between 1 and 31 also requires the upper product portion to be at most:

\[
2^{\text{control byte}-1}-1.
\]

For a nonnegative product, this is exactly the strict product bound stated in Interface. Equality at the product boundary is excluded from the conservative domain.

For a negative product, the upper half of its unsigned 64-bit representation is outside the positive signed 32-bit range. Its conversion to signed form is not independently characterized. Even assuming a conventional negative interpretation would not establish the validity of a subsequent signed leftward displacement.

These restrictions concern the semantics of the operations, not an explicit branch that rejects such inputs.
