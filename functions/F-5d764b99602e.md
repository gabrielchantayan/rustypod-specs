# F-5d764b99602e

## Purpose

F-5d764b99602e conditionally updates a selector in a caller-supplied state object, prepares an associated two-byte field, and invokes six dependencies in a fixed order.

The selector accepts either:

- An ordinary nonnegative index strictly below a dependency-provided unsigned bound.
- The distinguished 32-bit value `0xffffffff`, which bypasses bound acquisition and selects a separate initialization path.

**Established behavior:** rejection returns `0xffffffce`; completion of the update sequence returns zero.

**Inferred intent:** the operation appears to change a current selection and refresh related state. The meanings of the selection, associated two-byte field, and refresh operations are not established. They must not be treated as requirements beyond the observable behavior below.

| Requested selector | A 32-bit value interpreted through a sentinel check, a signed-negative test, and an unsigned bound comparison. |

The state base is not checked for nullness, alignment, allocation extent, or accessibility.

The requested selector is classified as follows:

### Return value

The observable result is a 32-bit value:

- `0x00000000` after all calls in the accepted sequence return normally.
- `0xffffffce` when the selector fails validation.

Interpreted as a signed 32-bit integer, `0xffffffce` is −50. No named error category is established.

There is no direct output pointer parameter. Outputs consist of the return value, direct state writes, and effects of dependencies.

### Preconditions for normal completion

The caller must supply storage and dependency-compatible state sufficient for the path taken. An accepted path requires the four-byte selector write and the relevant associated-field operation to be valid.

For an ordinary selector, the bound-acquisition dependency must be able to use the state-relative address at offset `0xe58`. The later dependencies must also be able to operate on the state base.

The function does not establish that these conditions hold. Invalid storage is not converted into the explicit rejection result.

## Behavior

### Validation

Validation precedes every direct state write.

1. **Sentinel:** If the requested selector is `0xffffffff`, validation succeeds without calling F-255ea5022a24.
2. **Other high-bit-set values:** If the requested selector lies between `0x80000000` and `0xfffffffe`, the function returns `0xffffffce`. No dependency is called.
3. **Ordinary values:** For values from zero through `0x7fffffff`, the function calls F-255ea5022a24 with the state-relative address at offset `0xe58`. Its result is treated as a 32-bit unsigned bound. The selector is accepted only if it is strictly less than that bound.

The bound comparison is unsigned. A bound with its high bit set is therefore larger than every ordinary selector accepted for comparison.

A zero bound rejects every ordinary selector, including zero. A selector equal to the bound is rejected. The sentinel remains accepted regardless of what bound the dependency might otherwise have produced, because the dependency is not called on that path.

If an ordinary selector fails the comparison, the function returns immediately. It performs no direct state write and invokes none of the update dependencies. However, F-255ea5022a24 has already run; its effects are not rolled back.

### Accepted-state update

After validation succeeds, the function first writes the complete requested selector as four bytes at state offset `0x0c`.

It then handles the associated field according to the selector class:

- **Sentinel:** It writes a two-byte zero at state offset `0x2c`. This is a two-byte store, not an established clearing of a larger field. F-21bf82981fa3 is not called.
- **Ordinary selector:** It calls F-21bf82981fa3 with the state base, the requested selector, and the address at state offset `0x2c`. The function itself does not directly initialize that two-byte field on this path.

For the ordinary path, the bound returned during validation is not passed to F-21bf82981fa3. No bound-derived value is directly stored in the associated field.

The selector write occurs before the associated-field operation. Consequently, F-21bf82981fa3 is invoked after the selector store, though the dependency's own interpretation of the object remains unknown.

### Ordered update sequence

After the associated-field operation completes, the function invokes these dependencies in order, passing the state base to each:

1. F-6f1c4979939e
2. F-9bd62b20df7c
3. F-41899b1592e0
4. F-3ea7a339f5ec
5. F-a96742fec78e
6. F-087700124fe9

The sequence is the same for sentinel and ordinary accepted selectors.

No return value from these calls, or from F-21bf82981fa3, is used to select another branch or determine the final return value. If all calls return normally, F-5d764b99602e returns zero.

This does not establish that dependency failures are impossible. A dependency that does not return normally can prevent completion; there is no visible recovery or rollback mechanism.

## Side effects

### Direct effects

On each accepted path, the function directly writes the requested selector at offset `0x0c`.

On the sentinel path, it additionally writes exactly two zero bytes at offset `0x2c`.

On a rejected path, it performs no direct writes.

There are no explicit direct state loads in the supplied body. State inspection may occur inside dependencies.

### Dependency-mediated effects

The dependencies may read or modify the state object, global state, or other reachable resources. Their implementations are not supplied, so preservation of any such state is not established.

In particular:

- F-255ea5022a24 may have effects even when the selector is subsequently rejected.
- F-21bf82981fa3 may modify more than the storage addressed by its third argument.
- Later update dependencies may overwrite either directly written field.
- A zero return does not guarantee that the final selector field still equals the requested selector.
- A zero return on the sentinel path does not guarantee that the associated field remains zero after all dependencies finish.

The contract guarantees the direct writes and call order, not preservation of their intermediate results through unknown callees.

### Ownership and lifetime

The absence of an explicit release here is not evidence that the complete operation cannot release memory.

## Acceptance examples

These examples are conditional contract cases, not reports of executed tests. Unless stated otherwise, all accessed storage is valid and all invoked dependencies return normally.

### Sentinel bypass

**Given:** the requested selector is `0xffffffff`.

**Required observations:**

- F-255ea5022a24 is not called.
- A four-byte `0xffffffff` is written at offset `0x0c`.
- A two-byte zero is then written at offset `0x2c`.
- F-21bf82981fa3 is not called.
- The six common update dependencies run in the specified order.
- The function returns zero.

Final field contents depend on the update dependencies.

### Negative non-sentinel rejection

**Given:** the requested selector is `0xfffffffe`, or any other value from `0x80000000` through `0xfffffffe`.

**Required observations:** return `0xffffffce`, with no dependency calls and no direct state writes.

### Empty bound

**Given:** the requested selector is zero, and F-255ea5022a24 returns zero.

**Required observations:** the bound dependency is called once; the function then returns `0xffffffce`. There are no direct writes and no subsequent dependency calls. Effects of the bound dependency remain possible.

### Exclusive upper boundary

**Given:** the requested selector is 3, and the bound dependency returns 3.

**Required observations:** return `0xffffffce` after bound acquisition, without direct writes or update calls.

### Unsigned bound boundary

**Given:** the requested selector is `0x7fffffff`.

- A bound of `0x80000000` accepts it.
- A bound of `0x7fffffff` rejects it.

A requested selector of `0x80000000` is rejected before bound acquisition, regardless of the bound that dependency could return.
