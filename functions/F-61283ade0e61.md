# F-61283ade0e61

## Purpose

The supplied static representation describes an ordered sequence of memory accesses, address calculations, and fixed-location state updates. It does not establish a conventional application-level purpose.

The represented interface has four explicit input slots and an additional stack-associated pointer dependency. No ordinary return or return value is represented. Both terminal paths end at invalid-instruction boundaries.

**Inferred intent:** modification of low-level execution state or executable memory is plausible because executable-symbol addresses are used as data and write destinations. This is not established functionality. Warnings about invalid instruction data and overlapping global objects limit confidence that the representation describes valid executable instructions.

This contract preserves the represented accesses without promising successful initialization, completion, or recovery.

## Behavior

### Width and arithmetic rules

Explicitly typed pointer accesses establish their represented access widths: byte, halfword, and word mean 8, 16, and 32 bits respectively.

**Assignments to named fixed-location objects do not establish destination access widths when their declarations are absent.** A 16-bit conversion, a 32-bit expression, or a small constant describes the assigned value, not necessarily the number of bytes written. Such global access widths remain **documented_only** throughout this contract. Similarly, a value subsequently used as 32 bits does not independently establish the width of the global read that supplied it.

Define:

- \(V\): the 32-bit value corresponding to \(A-0x24\). The subtraction is represented with a signed input; behavior outside the signed range is unresolved.
- \(W\): \(A-0xCC\), evaluated as unsigned 32-bit subtraction.
- \(U=W\mathbin{\&}0x7FFFFFFF\).
- \(N=U\mathbin{\gg}1\), using unsigned right shift.
- \(P=2W\), with unsigned 32-bit multiplication and discarded carry beyond 32 bits.

Consequently, \(0\le U\le0x7FFFFFFF\) and \(0\le N\le0x3FFFFFFF\).

The following calculations require unresolved signed-shift or signed-arithmetic semantics:

- \(Q\): the address obtained by shifting signed \(D\) left by two, then shifting the result right by 32.
- \(R\): the signed quantity obtained by interpreting \(E\) as signed 32-bit and shifting right by 32.
- \(T\): the low 16 bits of the signed interpretation of \(E\) shifted right by 31.

With arithmetic signed right shifts, \(T\) is zero for a nonnegative \(E\) and \(-1\) for a negative \(E\). Shifts by 32 on apparently 32-bit operands must not be silently interpreted as zero, sign extension, masked shift counts, or wider arithmetic.

Other signed additions, multiplications, and left shifts may also overflow. Their machine behavior is **documented_only** rather than an implicit promise of modular arithmetic.

### Executable-address-dependent branch

The function writes \(T\) at \(R+4\) using a 16-bit access, then tests whether the signed 32-bit interpretation of \(E\) is negative.

If negative, execution reaches the early invalid-instruction boundary. The preceding accesses, including the halfword write at \(R+4\), are part of that path.

Otherwise, the sequence continues:

1. Write \(T\) at \(R+0x12\), using a 16-bit access.
2. Write \(E\) at address \(E\), using a 32-bit access.
3. Read a signed 16-bit value at \(R+N\).
4. Repeat the 16-bit write of \(T\) at \(R+0x12\).
5. Repeat the 32-bit write of \(E\) at address \(E\).
6. Sign-extend the previously read halfword to 32 bits, shift it right by 16, and write the resulting 32-bit value at \(R+8\).

With arithmetic right shifts, the final value is zero for a nonnegative halfword and \(0xFFFFFFFF\) for a negative halfword.

The duplicate writes remain separate represented effects. Removing either can change fault ordering, alias-sensitive behavior, or device interactions.

## Side effects

No disjointness guarantees exist. Earlier writes can alter later values or destinations; narrow writes can partially overwrite wider values; later wide writes can replace earlier narrow updates. Unknown global widths also leave some overlap boundaries unresolved.

Any completed prefix may remain observable if a later operation faults or reaches a terminal boundary. No transaction, rollback, cleanup, or ownership change is represented.

Repeated reads and writes remain relevant where memory is device-backed or otherwise read-sensitive. The contract does not infer stable readback merely from an earlier assignment.

## Acceptance examples

These are conditional static deductions, not executed tests.

1. **Unsigned subtraction boundary.** For \(A=0xCC\), \(W=U=N=P=0\). The initial byte derived from \(N\) is zero. If execution progresses, the explicit halfword writes target addresses \(4\), \(6\), and \(2\), followed later by a halfword read at zero. Mapping and access success remain unknown.

2. **Wrapped subtraction.** For \(A=0xCB\), \(W=0xFFFFFFFF\), \(U=0x7FFFFFFF\), \(N=0x3FFFFFFF\), and \(P=0xFFFFFFFE\). The initial byte derived from \(N\) is \(0xFF\). No represented range check rejects these values; further address arithmetic remains subject to the stated execution-model limits.

3. **Indirect destination width.** If the halfword read at \(P\) observes \(0x9234\), the subsequent 32-bit write targets \(0x00009234\), not a sign-extended address, and stores \(V\mathbin{\&}0x897E8B80\).

4. **Early terminal path.** If signed \(E\) is negative and all preceding operations complete, the 16-bit write at \(R+4\) occurs before the early boundary. None of the continuing-path updates follows.

5. **Signed halfword propagation.** With arithmetic right shifts, a signed halfword observation of \(-2\) at \(R+N\) leads to \(0xFFFFFFFF\) at \(R+8\); \(+2\) leads to zero. Both self-address writes at \(E\) remain present.

6. **Stable address-holder readback.** If the assignment to \(0x0897EA80\) reads back as \(4S\) on every subsequent observation, step 2 writes \(4S\) at \(4S\), and step 3 writes \(N\) at \(4S+4\). This result requires the stated readback condition.

7. **Read-sensitive address holder.** If the destination-role read at \(0x0897EA80\) yields \(0x1000\), the value-role read yields \(0x2000\), and the later read yields \(0x3000\), the represented effects are a 32-bit write of \(0x2000\) at \(0x1000\), followed by a 32-bit write of \(N\) at \(0x3004\). This does not prescribe which role's read occurs first within the first assignment.

8. **Assignment width is not access width.** Assigning \(0xB8\) at \(0x0897E8C0\) establishes that assigned value, but does not establish that adjacent bytes remain untouched. Likewise, assigning a 16-bit converted value to a global does not by itself prove a halfword access.

9. **Later reset-state observation.** If intervening aliasing changes the reset-related operand to \(0x1234\), the final concatenated assigned value is \(0x1234EA70\), regardless of the original upper half of \(G\). Its destination access width remains unknown.
