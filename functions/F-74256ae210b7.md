# F-74256ae210b7

## Purpose

F-74256ae210b7 coordinates selection of an optional entry, acquisition and processing of an associated value, and two ordered checks against a caller-supplied object. It reports intermediate conditions through a context field and a callback that can either stop processing or permit continuation.

The normal return value is a four-byte Boolean-like result:

- **0:** a reporting callback returned zero, stopping the operation.
- **1:** processing reached the completion point, including cases where reporting callbacks permitted continuation after reported conditions.

A return of 1 therefore does **not** establish that all checks passed, that an associated value was acquired, or that the context’s report field is clear.

All normal return paths invoke F-55d57b266fd4 with the locally retained associated value, initially zero. Whether this invocation releases a resource is not established.

## Behavior

### 1. Capture the position and select an entry

The function first reads the signed position at context offset `0x58`. It initializes a locally retained associated value to zero.

It then reads context offset `0x54` and passes that value to F-10b760faca36. The dependency’s signed result participates in the comparison:

**captured position < result − 1**

The position is captured before this dependency executes. In contrast, context offset `0x54` is read again for the subsequent selection call. If F-10b760faca36 changes that field, selection can use a different value from the one used for the initial call.

There are two selection paths:

- **Comparison true:** F-6bbddce1b930 is invoked with the newly read value at context offset `0x54` and the captured position plus one.
- **Comparison false:** F-6bbddce1b930 is shown with only the newly read value at context offset `0x54`. Its result is then passed twice to the callback at context offset `0x30`, with the context address as the first argument.

The fallback callback is invoked even if the selected value is zero.

If that callback returns zero, the function writes `0x21` to context offset `0x5c` and invokes the reporting callback. A zero reporting result selects final result 0 and proceeds to the common final invocation. A nonzero result permits processing to continue with the selected value already held locally.

The selector’s inconsistent visible argument count is unresolved. No implicit index or default selection rule is established for the one-argument form.

### 2. Inspect a nonzero selected entry

A zero selected value skips entry inspection, associated-value acquisition, and F-3065da4b0377. Processing proceeds directly to the object checks.

For a nonzero selected value:

1. Read its flags at offset `0x24`.
2. If mask `0x2` is set there, read its flags at offset `0x28`.
3. If the first mask is set and the second is clear, write report value `0x23` and invoke the reporting callback.

A zero reporting result stops processing with final result 0. A nonzero result continues. The selected entry’s flags are not rechecked after this callback.

### 3. Acquire and process an associated value

For a nonzero selected entry that has not caused an early stop, invoke F-82d6fbbbf739 with the selected value. Retain its result locally for the final F-55d57b266fd4 invocation.

- If the result is zero, write report value **6** and invoke the reporting callback.
- If the result is nonzero, invoke F-3065da4b0377 with the original object-reference address and the retained result:
  - A strictly positive signed result proceeds directly to the object checks.
  - A zero or negative result writes report value **8** and invokes the reporting callback.

For reports 6 and 8, a zero reporting result stops processing with final result 0. Any nonzero reporting result continues to the object checks.

There is no retry, reacquisition, or rollback in this function. F-3065da4b0377 receives an address through which the caller-visible object reference could change; whether it changes that cell or the referenced object is unknown.

### 4. Capture the check argument

Immediately before the object checks, read context flags at offset `0x1c`.

- If mask `0x2` is set, use the address of context offset `0x18`.
- Otherwise, use zero.

This argument is captured once and reused for both F-1c432b999060 invocations. Later changes to the flag do not cause it to be recomputed. If it is an address, the contents at that address may nevertheless change between invocations.

### 5. Check the first object field

Interpret the signed result as follows:

| Result | Action |
|---|---|
| Negative | Continue without reporting. |
| Zero | Write report value `0x0f`, then invoke the reporting callback. |
| Positive | Write report value `0x0b`, then invoke the reporting callback. |

For either report, zero from the reporting callback stops processing with final result 0. Nonzero continues to the optional second check.

The first check is performed even when its object field is zero. Only the second check has a zero-field suppression rule.

- If the field is zero, skip the second dependency call.
- If the field is nonzero, reread the object reference and the field for the call argument, then invoke F-1c432b999060 with that value and the previously captured check argument.

| Negative | Write report value `0x0c`, then invoke the reporting callback. |

On every normal exit path, invoke F-55d57b266fd4 exactly once with the locally retained associated value, then return the selected result. The argument is zero if acquisition never occurred or returned zero. The final dependency’s return value does not affect the selected result.

## Acceptance examples

These examples are conditional static expectations, not executed tests. All reached accesses and calls are assumed valid and normally returning.

1. **No selected entry; checks pass.**  
   Selection returns zero without a stopping fallback report. The first check returns negative, and the second object field is zero. Acquisition and processing are skipped; the final dependency receives zero; the function returns 1.

2. **Fallback report stops processing.**  
   The fallback callback returns zero, followed by zero from the reporting callback. Report `0x21` is written before that reporting call. No entry flags or object checks are subsequently accessed. The final dependency receives zero, and the function returns 0.

3. **Entry-condition report is accepted.**  
   The entry has mask `0x2` set at offset `0x24` and clear at `0x28`. Report `0x23` is written. A nonzero reporting result allows acquisition to proceed without rechecking those flags.

4. **Acquisition fails but continuation is permitted.**  
   Acquisition returns zero. Report 6 is written, and the reporting callback returns nonzero. F-3065da4b0377 is skipped, but the object checks still occur. Reaching completion returns 1 and passes zero to the final dependency.

5. **Processing rejects a nonzero retained value.**  
   Acquisition returns nonzero and processing returns a negative value. Report 8 is written. If the reporting callback stops processing, the function still passes the acquired value to the final dependency before returning 0.

6. **Positive check results have different meanings.**  
   A positive first-check result produces report `0x0b`. If continuation is allowed and the second field is nonzero, a positive second-check result produces no report.

7. **Continuation does not clear prior reports.**  
   The first check returns zero and its report is accepted. The second field is zero. The function returns 1 without clearing report `0x0f`; the ultimate field value remains subject to callee mutations.

8. **Object replacement affects later reads.**  
   If an earlier call changes the cell at the object-reference address, later object accesses use the changed reference. They do not use an entry-time object snapshot.
