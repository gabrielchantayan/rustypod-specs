# F-722277db6904

## Purpose

F-722277db6904 repeatedly checks bit 2 of a selected unsigned 32-bit status word. A selector byte read through the input address chooses the status location on each attempt. After a check finds bit 2 clear, the function calls an external dependency with arguments 0 and 1 before trying again.

Before the first selector read, the function performs three ordered source-level evaluations of a global address source. These independently initialize three region addresses. The representation does not establish that the evaluations observe equal values or form a coherent snapshot. The initialized addresses are subsequently reused without visible reloads.

**Established static behavior:** a normal return follows a selected status read whose mask `0x00000004` is nonzero. Each unsuccessful check is followed by one dependency call; another attempt occurs if that call returns normally and execution remains valid.

**Inferred intent:** the function resembles a readiness wait across selectable regions. The meaning of readiness, the nature of the regions, and whether the dependency delays or yields execution are not established.

### Independently initialized region addresses

The following labels describe contract concepts, not additional inputs or source identifiers:

## Behavior

### Initialization order

Before entering the polling sequence, the function:

1. Evaluates the global address source to initialize Region 1 without an offset.
2. Evaluates the global address source again and adds `0x4000` bytes to initialize Region 2.
3. Evaluates the global address source again and adds `0x8000` bytes to initialize Region 3.

All three initializations precede the first selector read, even if the first selector chooses the fixed region and that status check immediately succeeds.

These are three ordered evaluations in the supplied representation. They do not prove three physical machine loads, nor do they prove that the observations are atomic, synchronized, or mutually consistent. A compiler’s access generation and the execution environment’s memory semantics are not supplied.

The representation contains no later reload of this global address source. Changes to it after initialization do not visibly replace the retained region addresses. Status contents are not captured during initialization.

### Per-attempt order

Each attempt has the following source-level observable sequence:

1. Read the selector byte at input address plus one.
2. Choose the corresponding fixed or retained region address.
3. Read the unsigned 32-bit status word at that region plus `0x10` bytes.
4. Test bit 2.
5. Return if the bit is set; otherwise call F-DEPENDENCY-01 with arguments 0 and 1.

If the dependency returns normally, the next attempt begins with a fresh selector read.

There is no dependency call before the first check or after a successful check. No unselected status word is directly read as part of the attempt.

This ordering does not establish processor barriers, volatile-access guarantees, cache behavior, inter-thread synchronization, or atomic access properties.

### Selector behavior

All 256 possible selector-byte patterns have a branch destination:

- Zero selects the fixed region.
- One selects Region 1.
- Two selects Region 2.
- Every other value selects Region 3.

There is no invalid-selector report. High-bit values such as `0x80` and `0xFF` select Region 3. Any signedness difference for the represented character type does not change those values’ inequality with zero, one, and two.

The selector is read once per source-level attempt. A later change does not visibly redirect the status read already selected for that attempt. A subsequent attempt can observe the changed selector.

### Completion and repetition

The completion condition is that the loaded word, masked with `0x00000004`, is nonzero.

| Selected status word | Decision |
|---|---|
| `0x00000004` | Return |
| `0xFFFFFFFF` | Return |
| `0x00000000` | Call the dependency |
| `0x00000008` | Call the dependency |
| `0xFFFFFFFB` | Call the dependency |

Other bits neither independently cause return nor prevent it when bit 2 is set. The function does not accumulate readiness across regions or require agreement among them.

There is no visible timeout, retry limit, cancellation input, or alternative normal completion condition. If every status check finds bit 2 clear and every dependency call returns normally, polling continues without a visible bound. If the dependency does not return, no later attempt is reached through the visible control flow.

For N unsuccessful checks followed by one successful check, the representation describes:

- Three initial global-source evaluations.
- N + 1 selector reads.
- N + 1 selected status-word reads.

These are source-level counts, not guaranteed physical bus or machine-instruction counts.

### Widths and address arithmetic

The selector access is one byte. The status access is unsigned 32-bit. The mask selects bit 2 of that 32-bit value.

The region offsets `0x4000`, `0x8000`, and `0x10` are byte offsets, not counts of 32-bit words. The input selector offset is also one byte.

The contract does not define address wraparound as a supported means of obtaining a valid location. Near an address-space boundary, the input increment, region initialization, or status offset may fall outside valid-address preconditions. Exact overflow and fault behavior are **documented_only**; no checked-arithmetic or recovery path appears.

## Acceptance examples

These are conditional static expectations, not executed tests. They assume valid accesses and normal execution except where stated otherwise.

### Fixed-region completion still performs initialization

Suppose the selector is `0x00` and the word at `0x3CC00010` is `0x00000004`.

The three ordered global-source evaluations and region initializations occur before the selector read. The function then reads the fixed status word and returns without calling F-DEPENDENCY-01. It does not read the status words of Regions 1, 2, or 3.

### Different initial observations remain distinct

Suppose the three ordered global-source evaluations yield, respectively:

- `0x10000000`
- `0x20000000`
- `0x30000000`

The retained region addresses are then `0x10000000`, `0x20004000`, and `0x30008000`.

Selector `0x02` checks `0x20004010`. Selector `0xFF` checks `0x30008010`. Neither address is derived from the first observed value. Return or retry depends on bit 2 of the selected word.

### Common-base layout requires stability

Suppose all three initial evaluations yield the same valid address B.

Under that condition, selectors one, two, and three check B + `0x10`, B + `0x4010`, and B + `0x8010`, respectively. This example does not establish equality of the three observations in other executions.

### Selector changes after a failed check

Suppose the first selector is `0x01` and the word at Region 1 plus `0x10` has bit 2 clear. F-DEPENDENCY-01 is called with 0 and 1.

If it returns after changing the selector to zero, the next attempt checks `0x3CC00010`. If that word has bit 2 set, the function returns after exactly one dependency call.

### Global-source changes do not reinitialize regions

Suppose Region 2 was initialized from the second global-source observation plus `0x4000`. After an unsuccessful check, the dependency changes the global source.

If the next selector is `0x02`, the next check still uses the retained Region 2 plus `0x10`, provided that address remains valid. It does not use the newly stored global value to rebuild Region 2.

### Other bits do not establish completion

Suppose the selected word is `0xFFFFFFFB`. Despite every other bit being set, bit 2 is clear. The function calls F-DEPENDENCY-01 rather than returning.

### Indefinite unsuccessful polling

If every selected status read has bit 2 clear and every dependency call returns normally with future accesses still valid, the function continues polling. There is no visible timeout result or finite completion bound.
