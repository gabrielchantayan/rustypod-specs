# F-ad249102164e

## Purpose

F-ad249102164e performs two ordered traversals of sentinel-terminated linked structures. Each traversal applies a payload operation and is followed by a separate dependency call receiving the then-current root of that structure.

The established sequence is:

1. Traverse the first structure, passing every visited payload to F-8349c252c168 with the fixed second argument `0x35`.
2. Call F-cf2724db5a22 with the current first root.
3. Traverse the second structure, invoking a payload-derived indirect target for each node whose payload passes a null check.
4. Call F-6d38d58e621c with the current second root.

This sequence is consistent with cleanup, but destruction, clearing, unlinking, and memory release are not established effects. The meanings of the payloads, the fixed argument, and the dependencies remain unknown.

The traversal is sensitive to mutation: forward links are read after payload operations, and the sentinel used for termination is reread on every comparison.

## Interface

### Entry and return

The function has no explicit parameters and returns no value. Its inputs are two global root slots and memory reached through those slots.

Normal completion requires both traversals to terminate and every invoked dependency to return normally. Dependency results, if any, are not used. The function produces no status, count, or error result.

The first and second root slots are distinct storage locations. Their contents are not checked for equality, and the function does not require the structures or their reachable objects to be disjoint.

### Widths and layouts

The supplied representation uses 32-bit words and 32-bit address-bearing values. Relevant accesses use the following byte offsets:

| Object | Offset | Value read |
|---|---:|---|
| Root | `0x10` / 16 | Sentinel address |
| Sentinel | `0x00` / 0 | Initial forward link |
| Node | `0x00` / 0 | Forward link to another node or a sentinel |
| Node | `0x08` / 8 | 32-bit payload |
| Second-phase payload object | `0x00` / 0 | Dispatch-table address |
| Dispatch table | `0x04` / 4 | Indirect call target |

The first-phase payload is passed as a 32-bit value without a null filter. Its signedness and semantic type are not established.

The second-phase payload is interpreted as an address for the null comparison and dispatch lookup. The fixed argument `0x35` is decimal 53 and fits within 32 bits without truncation.

The function does not establish a complete object layout. In particular, it does not use a backward link, element count, ownership flag, or capacity field.

### Execution preconditions

For normal completion:

- Each root used for an access must expose a readable sentinel field at offset 16.
- Each sentinel used to initialize a traversal must expose a readable forward link at offset zero.
- Every visited node must expose the payload and forward-link fields when those reads occur.
- A second-phase payload used for dispatch must expose a readable dispatch-table address, whose entry at offset four must designate a callable target.
- Each traversal must eventually encounter the sentinel value read by one of its condition checks.
- Every invoked operation must return normally.

These are requirements on the execution environment, not validations performed by this function. Null roots, invalid links, unsuitable object layouts, and invalid dispatch targets are not handled locally.

## Behavior

### First traversal initialization

The function reads the first root slot and retains that value as the root through which subsequent first-phase termination comparisons access the sentinel field.

It then accesses the first root slot again to initialize traversal. Through that root value, it reads the sentinel address at offset 16, then reads that sentinel’s forward link to obtain the initial current node.

The retained comparison root and the root used for initialization therefore come from separate accesses. The supplied representation does not establish that they must contain the same value if the global slot changes between those accesses.

The initial sentinel address is not retained as an immutable termination target.

### First traversal condition and payload operation

Before each possible body execution, the current node address is compared with the sentinel address read at offset 16 through the retained comparison root.

Equality ends the traversal without reading that node’s payload. Inequality causes the function to:

1. Read the current node’s 32-bit payload at offset eight.
2. Call F-8349c252c168 with that payload and the fixed value `0x35`.
3. After the call returns, read the current node’s forward link at offset zero to select the next current node.

A zero payload is passed to F-8349c252c168. There is no first-phase null-payload exclusion.

The forward link is not saved before the payload call. A dependency that changes that link can change the next node visited. A dependency that invalidates the current node can make the subsequent link read invalid; the function provides no protection against that outcome.

The next condition rereads the sentinel field through the retained root. Consequently, setting the current node’s forward link to a previously observed sentinel is not sufficient by itself to establish termination. Termination requires the resulting current node to equal the sentinel value actually read by a later comparison.

### First post-traversal call

When the first traversal terminates, the function reads the first root slot again and passes its current value to F-cf2724db5a22.

This argument need not equal the retained comparison root or the root used during initialization. Changing the global slot does not replace the retained comparison root, but it can change the argument supplied to this post-traversal call.

F-cf2724db5a22 is called even if the traversal visits no nodes.

The second phase begins only after this dependency returns. Its effects on the second root slot and reachable memory are not constrained by the visible caller. Such effects can therefore determine the second traversal’s starting state.

### Second traversal initialization

After F-cf2724db5a22 returns, the function reads the second root slot and retains that value as the comparison root for the second traversal.

It separately accesses the second root slot to obtain a sentinel address from offset 16, then reads that sentinel’s forward link to obtain the initial current node.

As in the first phase, initialization and comparisons use separately obtained root values, and each condition rereads the sentinel field through the retained comparison root.

### Second traversal payload operation

For every current node unequal to the sentinel read by the condition:

1. The function reads the payload at offset eight and compares it with null.
2. If that read yields null, no indirect call is made for the node.
3. If that read yields non-null, the dispatch expression reads the node’s payload field again.
4. Through the payload value used by dispatch, it reads the dispatch-table address at offset zero.
5. It reads and invokes the target at dispatch-table offset four.
6. After the optional call returns, it reads the current node’s forward link at offset zero.

The null check and dispatch are represented as separate payload-field accesses. The successful check does not establish that a later dispatch access will obtain the same value if the field changes between accesses. No second explicit null check is present.

The indirect invocation has no explicit arguments in the supplied representation. This does not establish an implicit receiver, an object-method calling convention, or a complete machine-level argument contract.

Null-payload nodes still participate in traversal: their forward links are read, and processing continues.

As in the first phase, a payload operation may affect the subsequent forward-link read and future sentinel reads. Neither the next node nor the termination sentinel is treated as an immutable value across the call.

### Final call and return

After the second traversal terminates, the function reads the second root slot again and calls F-6d38d58e621c with its current value.

This call occurs even if the second traversal visits no nodes or every visited payload is null. Its argument can differ from the retained second comparison root.

If this final dependency returns normally, F-ad249102164e returns without a value.

## Side effects

The visible body contains no explicit writes to global slots, roots, sentinels, nodes, payload objects, or dispatch tables. Its direct memory activity consists of reads and calls.

State changes may occur through:

- F-8349c252c168, for each visited first-phase node.
- F-cf2724db5a22, after first-phase termination.
- A runtime-selected indirect target, for each second-phase node whose null check succeeds.
- F-6d38d58e621c, after second-phase termination.

These operations must not be assumed to preserve either global root, any sentinel field, node links, payload fields, dispatch tables, or object lifetimes.

Passing a root or payload does not establish ownership transfer. No allocation, release, unlinking, clearing, or reference-count update is directly established. Whether a dependency performs any of these actions remains unknown.

There is no visible recovery, rollback, retry, exception handling, or error-result inspection. If an operation does not return, later traversal work and later calls are not reached. Invalid memory accesses and unusable indirect targets have no local handling shown.

## Acceptance examples

These are conditional consequences of the static representation, not runtime test results.

### Both structures remain empty

Assume valid roots, stable sentinel fields, and each sentinel’s forward link equal to that sentinel. Also assume F-cf2724db5a22 leaves the second structure empty and valid.

The expected call sequence is:

1. F-cf2724db5a22 with the current first root.
2. F-6d38d58e621c with the current second root.

No first-phase payload call or second-phase indirect call occurs. Normal return additionally requires both dependencies to return normally.

### First-phase zero payload is processed

Assume a valid, stable first-phase chain containing two nodes followed by the comparison sentinel. Their payloads are zero and a nonzero 32-bit value.

F-8349c252c168 receives zero first, then the nonzero value, each paired with `0x35`. F-cf2724db5a22 follows both calls. The zero payload is not skipped.

### Second-phase null payloads are skipped

Assume a valid, stable second-phase chain with payloads null, valid non-null, and null, in that order. The non-null payload provides a valid dispatch target.

Only the middle node produces an indirect call. All three nodes have their forward links read. F-6d38d58e621c follows traversal termination.

### A per-node call changes the next link and termination follows

Assume a payload operation changes the current node’s forward link to the sentinel address most recently used for comparison. Require all of the following:

- The current node remains readable until the subsequent forward-link read.
- That read obtains the assigned sentinel address.
- The retained comparison root remains readable.
- Its sentinel field remains unchanged through the next condition’s sentinel read.

The subsequent current-node value then equals the next comparison’s sentinel value, so the traversal terminates at that comparison. Nodes bypassed by the changed link are not visited.

The same reasoning applies in either phase. More generally, termination follows whenever the subsequent link read and the next condition’s sentinel read produce equal addresses.

### A changed sentinel defeats that termination conclusion

Assume a payload operation assigns the current node’s forward link to the previously observed sentinel address, but also changes the retained root’s sentinel field to a different address before the next comparison. Assume the current node and retained root remain readable, and the subsequent link read obtains the assigned old sentinel address.

The next comparison finds unequal addresses and does not terminate the traversal. Readability of the current node and old sentinel does not change that result.

The old sentinel address is now treated as the current node for body processing. Continuing validly requires the payload and forward-link accesses at that address to be supported. The sentinel layout alone does not establish that its payload offset is readable.

### A root slot changes during traversal

Assume a first-phase payload operation replaces the first global root while leaving the retained comparison root valid. Also assume the traversal subsequently terminates.

Termination comparisons continue through the retained root. F-cf2724db5a22 receives the replacement root from the global slot, not necessarily the retained root.

An analogous distinction applies between the second comparison root and the argument supplied to F-6d38d58e621c.

### The first post-traversal dependency changes the second structure

Assume F-cf2724db5a22 replaces the second root with a valid root before returning.

The second phase obtains its root values after that call and therefore starts from the replacement state, subject to any further changes between its separate root-slot accesses.

### A stable cycle excludes the sentinel

Assume a valid, stable reachable cycle whose nodes never equal the sentinel read by the condition. Assume payload operations return normally without changing this arrangement.

That traversal does not terminate. No visited-node tracking or iteration bound is visible. Later phases are not reached.
