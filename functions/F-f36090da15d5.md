# F-f36090da15d5

## Purpose

F-f36090da15d5 processes a collection of groups containing pairs of 32-bit words. It validates selected first words against dependency-produced values and directly assigns selected words in groups after the first.

For stable, nonoverlapping descriptors and positive entry counts:

- Every entry in the first group is checked.
- Each later group receives an initial first-word assignment.
- A later group containing one entry receives its aggregate quantity as that entry’s second word.
- A later group containing at least two entries has all but its final entry checked; the final entry is derived from its predecessor and the group’s aggregate quantity.

These descriptions depend on descriptor stability. In the general later-group branch, the actual post-loop target is the **terminating entry index**, not necessarily the current final entry. Descriptor changes can also cause the two post-loop writes to reach different arrays.

The function returns zero on completion, propagates a nonzero initialization result unchanged, or returns −7 for a checked first-word mismatch.

“Position,” “length,” and “aggregate” describe apparent arithmetic roles. Their external meaning is inferred, not established. The operation is not transactional: writes and dependency calls can occur before failure. No rollback is visible, but that does not establish that earlier written values persist until return.

## Behavior

### Initialization and early exit

Before directly reading the collection, the function calls **F-66310ffff1d9** with:

1. The first argument.
2. Selector 10.
3. The address of the local 32-bit copy of the fourth argument.

A nonzero result is returned unchanged. On that path, this function performs no subsequent collection traversal, entry writes, or dependency calls.

This is not a guarantee that initialization itself leaves collection storage, globals, or other external state unchanged.

### First-group validation

The entry index starts at zero. At each condition evaluation, the function reloads the group-array pointer and reads the first group’s signed entry count. It continues while the index is below that count.

Each iteration has the following call and access order:

1. Obtain the current entry’s second-word address using the group pointer obtained for the condition; pass that address and the first argument to **F-9b88190fe3bf**.
2. Reload the group-array and entry-array pointers; pass the current entry’s first-word address and the first argument to **F-9b88190fe3bf**.
3. Call **F-674655f0e759** with the first argument.
4. Reload the descriptor-reachable entry-array pointer and compare the indexed first word with the dependency’s 32-bit result.
5. If unequal, return −7.
6. If equal, reload descriptor-reachable storage to read the indexed second word; call **F-c019388e82bf** with the first argument and that word plus the dependency result.
7. Increment the entry index.

The second-word address is passed before the first-word address. Because pointers are reloaded between calls, those addresses need not belong to the same array if dependencies change descriptors.

The compared first word is read after all three preceding dependency calls. The second word used for advancement is read after the comparison. Neither is necessarily its pre-call value.

There are no direct entry assignments in this phase. Dependencies receive entry addresses and may modify storage.

A zero or negative signed count skips the loop. Count mutation can also alter when the loop terminates.

### Initial running position

After first-group validation terminates, the function calculates a 32-bit running position as:

- The first word at the first group’s entry-array base;
- Plus the first group’s aggregate quantity;
- Plus eight times its signed entry count.

The entry-array address is obtained through a fresh group-array load. The aggregate and count are read through the group pointer obtained by the terminating condition. These references must not be treated as one immutable descriptor snapshot. The source does not establish every operand-read order within this compound expression.

Even if validation ran zero times, this calculation still reads the first entry’s first word.

### Later-group selection and initial write

The later-group index starts at one. Before each group, the function reads the collection’s unsigned count. If the index is greater than or equal to that count, it returns zero.

Otherwise, it reloads the group-array and indexed entry-array pointers and writes the incoming running position to the first word at that entry-array base.

Only after this write does it reload the indexed group pointer and inspect the signed entry count to choose a branch. Consequently, overlapping storage can make the write affect the ensuing dispatch.

The write occurs before later validation failures. This function does not undo it, but subsequent dependencies or overlapping writes may replace it. Its value at return is not guaranteed.

### Later-group singleton branch

If the signed count read for dispatch equals one:

1. Read the aggregate quantity through the selected group pointer.
2. Obtain the entry-array pointer through that group pointer.
3. Write the captured aggregate quantity to the second word at that array base.

There are no dependency calls within this branch.

With stable, nonoverlapping storage, the sole entry becomes the incoming running position paired with the aggregate quantity. With aliasing, the initial first-word assignment may have affected the descriptor before these reads.

Processing then continues with running-position advancement.

### Later-group general branch

Every dispatch count other than one takes this branch, including zero and negative counts.

The function sets a local second-word accumulator to zero, then calls **F-c019388e82bf** with the first argument and the incoming running position minus eight.

It starts an entry index at zero. At every loop condition, it reloads the group-array pointer, selects the indexed group, and reads that group’s signed count. The loop continues while the entry index is less than that count minus one.

For each selected index:

1. Pass its second-word address to **F-9b88190fe3bf**, using the group pointer obtained by the condition.
2. Reload descriptor pointers and pass its first-word address to **F-9b88190fe3bf**.
3. Call **F-674655f0e759**.
4. Reload the group and entry-array pointers.
5. Read the indexed second word and add it to the accumulator.
6. Read the indexed first word through that same loaded entry-array pointer and compare it with the dependency result.
7. On inequality, return −7.
8. On equality, call **F-c019388e82bf** with the first argument and the dependency result plus the second word captured in step 5.
9. Increment the index.

The accumulator update precedes the mismatch test. It is local and is not exposed as a failure result.

Unlike first-group advancement, this branch uses the second word already captured before comparison; it does not perform another second-word read for the matching-entry advancement call.

### General-branch post-loop assignments

Let the **terminating index** mean the entry index when the general loop condition first fails.

The function then:

1. Reloads the group-array and indexed entry-array pointers.
2. Writes the first word at the terminating index as the sum of the two words immediately preceding that indexed entry, plus eight.
3. Reloads the group-array pointer and obtains the indexed group again.
4. Reads that group’s aggregate quantity and subtracts the accumulated second words.
5. Reads the entry-array pointer from that newly obtained group.
6. Writes the remainder to the second word at the same terminating index in this newly obtained array.

The first assignment occurs before the descriptor reads used for the second assignment. The two destination arrays are therefore not guaranteed to be identical. For example, the first assignment can overlap a descriptor field that affects the later lookup.

With mutable descriptors:

- The terminating index need not identify the current final entry.
- The target can lie outside the current logical count, even if allocated storage makes the access valid.
- A target can overlap storage previously checked.
- The predecessor words need not belong to the array used during validation.
- The accumulator can contain values read from different arrays or descriptor states.

For stable, nonoverlapping storage with a count of at least two, the terminating index is the final entry’s index. Only under those conditions is the final entry unvalidated and derived from its immediately preceding entry.

For a stable count of zero or less, no validation iteration occurs. The terminating index is zero. The function nevertheless reads the two 32-bit words immediately before the entry-array base, derives entry zero’s first word from them, and writes the aggregate quantity to entry zero’s second word.

### Running-position advancement

After either later-group branch, the function reloads the indexed group pointer. It advances the running position by the currently read aggregate quantity plus eight times the currently read signed entry count.

These need not be the values used for dispatch or post-loop assignment. The calculation does not sum the resulting entry contents.

The group index then increases, and collection-count selection repeats.

## Side effects

Direct caller-reachable writes are:

- The first word at each selected later group’s initially resolved entry-array base.
- The second word at a singleton branch’s resolved entry-array base.
- The first word at the general branch’s terminating index in one resolved array.
- The second word at that terminating index in a subsequently resolved array.

The function also initializes local storage for the fourth argument. No explicit allocation, deallocation, ownership transfer, or global assignment is visible.

Dependencies can have additional effects. **F-9b88190fe3bf** receives entry-word addresses, and **F-66310ffff1d9** receives a local address. Their access direction, pointer retention, ownership behavior, and global effects are unknown.

There is no visible rollback on failure. This establishes that earlier actions occurred—not that their results remain intact:

- Dependencies after a direct write may overwrite the same storage.
- Descriptor changes may redirect subsequent accesses.
- Completed groups may be modified again through dependencies or aliasing.
- A −7 return does not imply either restoration or persistence of earlier values.

Results from **F-9b88190fe3bf** and **F-c019388e82bf** are not checked. The result of **F-674655f0e759** is comparison data, not a separately recognized error status.
