### Terminal loop and carried arguments

Before loop entry, a call receives twice the initial narrow value. The following no-explicit-argument call supplies the **initial carried argument directly**, without an additional left shift.

Each iteration then has this order:

1. An opening indirect call receives the current carried argument and the current narrow-state word logically shifted right by eight.
2. Four calls follow.
3. A fresh byte is read at the retained, changed selector-read address, and zero is stored at that byte’s value plus 17.
4. Another call receives the latest primary result shifted left by two.
5. Four calls follow.
6. Their final primary result determines both arguments carried toward the next iteration.

The final result in step 5 is **shifted left by two before becoming the next iteration’s first explicit argument**. It is not carried directly.

Independently, that same unscaled final result is shifted left by twenty-six and assigned to the unsigned narrow-state word. The next opening call obtains its second argument by logically shifting this word right by eight.

Consequently:

- The first iteration’s first argument is the direct result of the pre-loop call.
- Every later iteration’s first argument is the preceding iteration’s final four-call result shifted left by two.
- The first iteration’s second argument is zero because its initial narrow value is at most 31.
- Under 32-bit modular shift semantics, later second arguments equal the preceding unscaled final result’s low six bits shifted left by eighteen.
