# F-ca2888499290

## Purpose

F-ca2888499290 transfers two byte-sized values from globally selected storage to two caller-supplied destinations. It rejects either destination being null by invoking F-a817d8d58c10, a dependency annotated as not returning.

The transfer is ordered, not atomic. The first destination is written before the second source byte is read. Aliasing between destinations and source storage can therefore affect the result.

A significant distinction is that the two source accesses do not use the same pointer-selection operation:

- The pointer used for the second byte is captured from a global pointer slot before destination validation.
- The pointer used for the first byte is obtained by reading that global pointer slot again after validation.

With stable global state and noninterfering destinations, the ordinary result is a copy of two consecutive source bytes into two separately supplied output locations. Stability and noninterference are conditions, not guarantees established by this function.

## Behavior

### Entry and validation

Before testing either destination for null, the function reads a pointer from a global pointer slot and retains that pointer for the later second-byte access.

It then tests whether either destination is null. If either is null, it invokes F-a817d8d58c10 without explicit arguments.

The dependency is annotated as not returning. Under that stated property, a null destination prevents both destination writes, and this function does not return normally. The earlier read of the global pointer slot has nevertheless already occurred.

The supplied material does not establish whether the dependency terminates a process, transfers control elsewhere, raises an exception, reports a diagnostic, or performs another nonreturning action.

### Successful transfer

When both destination pointers are non-null, the visible memory operations proceed in this order:

1. Read the global pointer slot again to select the source address for the first byte.
2. Read one byte at offset zero from that selected address.
3. Write that byte to the first destination.
4. Read one byte at offset one from the pointer captured before validation.
5. Write that byte to the second destination.
6. Return without a value.

These are the source-level access relationships established by the supplied body. They are not a claim about machine-instruction scheduling, atomicity, or volatile access semantics.

The first source read occurs before its corresponding destination write. The second source read occurs after the first destination write. The function does not read both source bytes into an isolated snapshot before writing outputs.

### Global pointer selection

The retained pointer for the second source byte and the later pointer selected for the first source byte can conceptually differ if the global slot changes between its two reads.

If the global slot remains unchanged, both accesses refer to the same source base, at offsets zero and one respectively.

If a defined execution environment permits the slot to change between those reads, the first output comes from the later selected base, while the second output still comes from offset one of the earlier captured base. The function contains no explicit synchronization that would make such a change safe or predictable.

Changes to the global slot after the second selection do not replace the retained pointer used for the second source access. Changes to the contents of the retained source storage can still affect that access.

### Aliasing

There is no explicit requirement that the destination pointers be distinct.

If both destinations identify the same writable byte and neither source read is affected by the writes, the byte receives the first value and is then overwritten by the second value. Its final value is the value obtained by the second source read.

Destination/source overlap is not excluded:

- If the first destination identifies the location that will subsequently supply the second source byte, the first write changes the value available to that later read.
- If a destination overlaps another source location, the result follows the actual read/write order rather than an assumed simultaneous two-byte copy.
- If the first destination overlaps the global pointer slot, the first write may alter that slot’s stored representation. The retained pointer for the second source access is still the pointer captured earlier, but broader validity and representation consequences are not established.

The function is therefore not specified as an overlap-independent copy operation.

### Partial completion and errors

The visible body provides no rollback.

If the first write succeeds but the later source read or second write cannot complete, the first destination may already have changed. No explicit status reports partial completion.

Non-null pointers are not necessarily valid pointers. An invalid non-null destination does not cause the explicit null-error dependency to be invoked merely because it is invalid. Likewise, a null or otherwise invalid global source pointer is not explicitly rejected before dereference.

The resulting fault, exception, trap, or language-level invalid behavior depends on execution details absent from the supplied material.

## Side effects

On a normal, noninterfering execution, the visible effects are:

- Two reads of the global pointer slot.
- One one-byte read from the later selected base at offset zero.
- One one-byte write to the first destination.
- One one-byte read from the earlier captured base at offset one.
- One one-byte write to the second destination.

The first write precedes the second source-byte read.

On a null-destination path, the visible body reads the global pointer slot and then calls F-a817d8d58c10. Under the dependency’s nonreturning annotation, it performs neither output write.

The function contains no explicit global assignment, allocation, release, logging, or synchronization. An aliased destination can nevertheless modify globally reachable storage. The dependency’s own side effects are unknown and must not be treated as absent.

## Acceptance examples

These examples are conditional static consequences, not results of executed tests.

### Stable source and distinct destinations

Given readable consecutive source bytes `0x24` and `0xB7`, a stable global pointer identifying the first byte, and two distinct writable destinations that do not interfere with the source or pointer slot:

- The first destination receives `0x24`.
- The second destination receives `0xB7`.
- The function returns without a value.

Changing only the unused 32-bit argument does not change the behavior visible in this body.

### Identical destinations

Given the same stable source and one writable byte supplied as both destinations, with no source overlap:

- That byte is first written with `0x24`.
- It is then written with `0xB7`.
- Its final value is `0xB7`.

### First destination overlaps the second source byte

Given stable source bytes `0x24` and `0xB7`, let the first destination identify the second source byte and the second destination identify separate writable storage.

The first write changes the second source byte to `0x24`. The subsequent second source read therefore obtains `0x24`, so the separate second destination also receives `0x24`.

This distinguishes the function from a transfer that snapshots both source bytes before either output write.

### Null destination

Given either destination is null and the global pointer slot itself is readable:

- The initial pointer-slot read occurs.
- F-a817d8d58c10 is invoked.
- If it does not return as annotated, neither output write occurs and there is no normal return.

No particular diagnostic or exit status is required by the available evidence.

### Different pointer selections

If the execution environment validly allows the global slot to change from one readable source base to another between its two reads, and both required source locations remain valid:

- The first destination receives offset zero from the later selected base.
- The second destination receives offset one from the earlier captured base.

This example does not assert that unsynchronized concurrent mutation is valid.
