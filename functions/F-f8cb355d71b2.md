## Purpose

A byte is read at twice the index state. It undergoes character-to-signed-integer conversion, a right shift by the index state’s low eight bits, and byte reduction. Character signedness and out-of-range shift behavior remain unresolved. The result is stored at initial-linked-record offset 0x08, followed by the entry link word at root offset 0x74 and the shifted byte at root offset 0x11.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

- **Input reduction:** For third input 0x123456ab, the first companion-0x11 store writes 0xab. This does not make execution safe: the third input also determines a word-store address.
- **Overwritten word:** A complete companion-0x54 write trace includes the third input followed by the fourth input, not merely the final value.
- **Full-width constant:** A word store of 0x74 replaces four bytes according to the execution environment’s byte order. A one-byte replacement is insufficient.
- **Nested payload capture:** If nested offset 0x60 overlaps primary offset 0x11, its word read occurs after byte 0x74 is written there and before the first primary payload’s low byte replaces it. The read must not be moved after both writes.
- **Forward-store precedence:** If forward offset 0x34 and primary offset 0x44 designate the same word, that word receives the earlier propagation payload before receiving the primary address.
- **Replacement precedence:** If late-record offset 0x34 and primary offset 0x14 designate the same word, the chain word is written first and the selected replacement address second.
- **Fresh links:** If an earlier store changes a later-read link, traversal uses the value actually read at that later point, not its entry value.
- **Repeated terminal access:** The halfword store at primary address plus terminal link word occurs twice, preserving the intervening store and byte read.
- **Fault:** If third input plus 0x54 is inaccessible, no graceful error result or reversal of earlier mutations is established.
