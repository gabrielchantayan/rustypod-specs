# F-558c7c583239

## Purpose

F-558c7c583239 performs an ordered series of memory mutations using two explicit inputs and three additional incoming machine-state values. It then transfers control to an unresolved indirect target with four arguments.

The supplied static representation establishes memory accesses and their ordering, but does not establish an application-level purpose. In particular, it does not justify describing this operation as object initialization, list maintenance, serialization, or memory management.

This contract describes the visible access trace rather than merely its final memory contents. Repeated stores, overlapping fields, low-address storage, and values loaded before subsequent mutations can affect observable behavior.

**Evidence status:** static-only. No runtime tests have been performed. Unresolved behavior is marked **documented_only** rather than supplied by assumption.

## Behavior

### Widths and arithmetic

Byte writes replace one byte. Word writes replace four bytes. One late write replaces a two-byte halfword.

Doubling A is represented as unsigned 32-bit arithmetic. Its result is therefore interpreted modulo 2³². Byte truncation retains only the least-significant eight bits.

Other address expressions involve signed-looking 32-bit values in the supplied representation. Their overflow behavior, pointer interpretation, and target address wrapping are **documented_only**. Examples involving these expressions assume representable addresses unless explicitly stated otherwise.

Byte order is not established. A four-byte write overlapping a byte field can change that field, but its resulting byte value cannot be specified independently of byte order.

### Opening mutation sequence

The opening operation is a word write of V at P + 0x54.

The function then establishes a recurring three-access relationship:

1. A byte containing the low byte of A is written at B + 0x19.
2. A byte containing the low byte of B is written at A + 0x11.
3. A word is written at B + 0x34.

For the first occurrence, the word written at B + 0x34 is P.

A finite, unrolled repetition follows. Each repeated group first writes V as a word at twice A + 0x54, then performs the same two byte writes, then writes twice A as a word at B + 0x34. The relative order within each group is significant.

These writes are visibly repeated rather than represented as a data-dependent traversal. The exact repetition count has not been independently established for this contract and is **documented_only**. It must not be inferred from a proposed optimization or replaced with an arbitrary iteration count.

For ordinary disjoint writable memory, repeated equal stores may leave the same final bytes as fewer stores. That observation does not authorize treating them as one access: aliasing, device memory, faults, or external observation can distinguish the trace.

### Snapshot acquisition and early byte updates

After the repeated sequence, the function obtains several four-byte values in this order:

- A word from fixed address 0xA9.
- A word from V + 0x74.
- After an intervening byte write described below, a word from C + 0x14.
- A word from A + 0x04.

Between the second and third reads, it writes a byte at fixed address 0x3A. That byte is the low eight bits of twice the low byte of A plus 0x30. Interpreting the intermediate byte as signed or unsigned does not change the final low-eight-bit result.

The function subsequently writes:

- The low byte of A at C + 0x0D.
- The byte 0x6C at A + 0x08.
- The low byte of B at A + 0x0D, then at A + 0x09.
- C as a word at C + 0x54.
- The low byte of the earlier word read from 0xA9 at fixed address 0x67.

These saved values are snapshots at their respective read times. Later writes to their original storage do not retroactively change them.

### Intermediate state and overlapping fields

Next, a word is read from C + 0x44. Call this snapshot S.

After that read, the byte at fixed address 0x67 is copied to fixed address 0x21. This is a read of the byte location, not an established use of a permanently cached global value.

The low byte of S is written at A + 0x10, and S is written as a word at B + 0x54. A byte derived by right-shifting S is then written at C + 0x01. The shift count is the low byte of A.

For nonnegative S and shift counts below 32, the byte is the low byte of the ordinary right-shifted value. Signed-negative behavior and counts of 32 or greater are **documented_only**.

The word at B + 0x54 is then overwritten with A. The earlier S write remains part of the observable trace.

The function reads a word from A + 0x40 and performs the following related updates:

- The saved word originally read from A + 0x04 is written at B + 0x74.
- The newly read word from A + 0x40 is written at A + 0x10.
- C is written as a word at B + 0x44.
- The current byte at fixed address 0x67 is written at A + 0x09.
- The low byte of A is written at C + 0x09.
- The saved word originally read from 0xA9 is written at A + 0x44.

The word write at A + 0x10 overlaps the earlier byte write there and covers offsets 0x10 through 0x13, including the earlier byte destination at offset 0x11. Those byte fields therefore do not have independently preserved final values.

### Address discovery and final mutations

A word is now read from A + 0x54. Treat its value as the discovered address H.

After this read, the current byte at fixed address 0x67 is again written at A + 0x09. The low byte of the saved word from V + 0x74 is written at H + 0x0D.

The saved word from C + 0x14 is written at C + 0x54, replacing the earlier self-address write there unless aliasing has already changed the situation.

A word is then read from A + 0x14. Its low byte is retained for a later write. Between this read and the next address-discovery read:

- The low byte of the saved word from V + 0x74 is written at C + 0x11.
- The low byte of H is written at A + 0x09.
- H is written as a word at A + 0x44.

The function reads a word from C + 0x04. Treat that value as discovered address J. It writes the halfword value 0x0065 at twice J, then reads a word from J + 0x64. Treat that word as K.

The halfword write precedes the read of K. If their storage overlaps, the write can affect K.

Next, the saved low byte from A + 0x14 is written at H + 0x11, and the word value 100, equivalently 0x00000064, is written at H + 0x54.

A word is then read from J + 0x74. This value becomes the final indirect-call argument. A separate word is read from C + 0x64; treat it as discovered address T.

The final visible memory mutations are:

- The low byte of J is written at C + 0x09.
- K is written as a word at T + 0x54.
- T is written as a word at twice K.

No validation of H, J, K, or T is visible before their use as address material.

## Side effects

The function visibly writes bytes, a halfword, and words to caller-related and indirectly discovered storage. It also reads a word at fixed address 0xA9 and writes bytes at fixed addresses 0x3A, 0x67, and 0x21.

The fixed word read spans addresses 0xA9 through 0xAC. The representation includes a warning that named global storage may overlap smaller symbols. Consequently, these locations must be treated as storage ranges, not automatically as independent language-level objects.

There is no visible allocation, release, reference-count operation, lock operation, or explicit ownership transfer before the indirect call. This does not establish that the indirect dependency has no such effects.

Aliasing can alter later reads even when each individual write uses a previously captured value. In particular:

- A write through B may change a later read through A or C.
- A byte written to fixed storage may affect another access if that storage aliases its range.
- Writing a saved word back to C + 0x54 does not imply that the saved word still equals the current contents of C + 0x14.
- A destination described by H, J, K, or T may overlap any earlier region.

No transactional or rollback behavior is visible. If execution stops at an invalid access, earlier mutations may already have occurred. Exact fault behavior and visibility of partial writes are **documented_only**.
