# F-ea3f284f11b2

## Purpose

F-ea3f284f11b2 initializes caller-provided destination storage using a mode, a selector, and, on one selector path, context-associated storage. Every visible normally returning path returns the original destination address.

The established choices are:

- A nonzero mode selects a shared source object, regardless of the selector.
- Zero mode with selector `0x6D2A` obtains a value through two dependencies.
- Zero mode with selector `0x6D2B` checks two markers in order. A selected marker determines a value-resolution path; rejection of both markers selects context-embedded source storage.
- Zero mode with any other selector selects default initialization.

Each path directly assigns a destination header from a global 32-bit word. These operands are **reads of mutable global storage at the corresponding assignment**, not fixed header constants captured at entry.

The interpretation as constructing text, translating messages, or copying a managed object is inferred intent. The visible evidence establishes branches, accesses, and dependency interactions, but not the complete object model or resource-management rules.

## Interface

### Arguments and result

| Argument | Established role |
|---|---|

The normal result is the original destination address, not a status code or a dependency’s return value.

The representation uses 32-bit words and address handling consistent with a 32-bit target. Signed ordering does not affect branch selection: the tests use equality and zero versus nonzero.

### Address arithmetic and storage

The context-derived address is context plus `0x4C`, meaning 76 bytes, not 76 words. The fallback source word is four bytes beyond that address, at context plus 80 bytes.

No explicit overflow check accompanies the context addition. The supplied representation does not establish defined behavior for signed overflow or address-space wraparound. Callers must provide a context value for which the derived address reaches the intended storage.

The directly accessed destination layout is:

| Byte offset | Width | Direct behavior |
|---|---:|---|
| 0 | 32 bits | Receives the value read from the path-selected header global. |
| 4 | 32 bits | Receives zero unless destination exactly equals the selected source on a source-transfer path. |

Paths writing both fields require at least eight writable bytes. Dependencies may require more storage, particular alignment, or an existing object invariant; those requirements are unknown.

### Shared inputs

The function directly reads the following categories of shared storage:

- A shared source pointer, read at entry before mode dispatch.
- A source-path header global.
- A default-path header global.
- A resolved-value header global.
- Three branch-associated 32-bit globals used as arguments during value resolution: one for selector `0x6D2A`, one for the first marker, and one for the second marker.

These names identify operand roles. Their contents, meanings, and equality or inequality are not established.

The shared source pointer is retained from its initial read. In contrast, a header global is read only when its corresponding destination-header assignment is reached. No entry-time snapshot of the header globals is established.

## Behavior

The ordering below describes visible accesses and calls. It does not establish atomicity, synchronization, or a cross-thread memory model.

### Initial shared-source read

Before inspecting mode, the function reads the shared source pointer and retains that address.

This read occurs even when subsequent selector processing does not use the retained address. It does not read or snapshot the pointed-to object’s second word. That word is accessed later only if a source-transfer path requires it.

### Nonzero mode: shared-source transfer

Any nonzero mode bypasses selector processing and context-derived marker checks.

The selected source is the address retained by the initial shared-pointer read. The visible sequence is:

1. Read the 32-bit source-path header global.
2. Write that value to destination offset 0.
3. Compare destination with the selected source address.

If the addresses are equal, the function returns the destination without directly clearing offset 4, reading the source’s second word, or invoking F-151ab4bfe553.

Exact self-source handling is therefore not a complete no-op: the header global is still read, and the destination’s first word is still overwritten.

If the addresses differ, the function continues by:

1. Writing zero to destination offset 4.
2. Reading the 32-bit word at selected source offset 4.
3. Invoking F-151ab4bfe553 with the destination and that word.
4. Returning the destination after the dependency returns normally.

The source payload read follows both destination writes. No copy-before-write behavior is established.

### Zero mode, selector `0x6D2A`: resolved value

The function invokes F-9d0ecc5f6adf without explicit arguments. After that call returns, it reads the selector-associated shared 32-bit value.

It invokes F-c0b020cd3882 with:

- The result of F-9d0ecc5f6adf as its first argument.
- The newly read selector-associated value as its second argument.

After F-c0b020cd3882 returns, the function performs resolved-value destination initialization:

1. Read the 32-bit resolved-value header global.
2. Write that value to destination offset 0.
3. Write zero to destination offset 4.
4. Invoke F-151ab4bfe553 with the destination and the result returned by F-c0b020cd3882.
5. Return the destination after normal dependency completion.

The branch-associated value is read after F-9d0ecc5f6adf returns. The resolved-value header is read after F-c0b020cd3882 returns. Thus changes those dependencies make to the respective globals affect the values subsequently consumed; neither operand is fixed at function entry.

There is no explicit context access on this path.

### Zero mode, selector `0x6D2B`: ordered marker checks

The function supplies the address at context plus 76 bytes and the marker `<<<note>>>` to F-3805a25164a0.

A zero result selects the first-marker resolution path. A nonzero result causes a second invocation of F-3805a25164a0, using the same context-derived address and the marker `<<<instructions_text>>>`.

A zero second result selects the second-marker resolution path. A nonzero second result selects the embedded-source fallback.

Only the zero/nonzero interpretation is established. The dependency’s implementation may be a comparison or another recognition operation; whole-string equality, prefix matching, case handling, encoding, and normalization are unknown.

The first check has precedence. When it returns zero, the second check is not performed.

#### First-marker resolution

Following a zero result from the first marker check:

- Invoke F-9d0ecc5f6adf.
- After it returns, read the first-marker-associated 32-bit global.
- Invoke F-c0b020cd3882 with the dependency result and that shared value.
- After F-c0b020cd3882 returns, perform resolved-value destination initialization.

That initialization includes reading the resolved-value header global immediately before its destination write. It does not reuse a header value read before the marker check or before either value-producing call.

#### Second-marker resolution

Following a nonzero first result and zero second result, the same sequence applies using the second-marker-associated global.

The selected shared value is read after F-9d0ecc5f6adf returns. The resolved-value header is read after F-c0b020cd3882 returns. Both marker calls precede these reads and the direct destination initialization.

The first-marker and second-marker globals occupy distinct roles; their actual contents need not be distinct.

#### Embedded-source fallback

Following nonzero results from both marker checks, the selected source becomes context plus 76 bytes. The initially retained shared source address is not used for the transfer.

Only after both marker calls return does the function:

1. Read the source-path header global.
2. Write that value to destination offset 0.
3. Compare destination with the context-derived source address.

Consequently, a change to the source-path header global made by either marker call is reflected in the subsequent header assignment, unless another intervening change supersedes it.

If destination equals the context-derived source address, the function returns without directly clearing the second word or invoking F-151ab4bfe553.

Otherwise, it clears destination offset 4, reads the 32-bit word at context plus 80 bytes, and passes that word with the destination to F-151ab4bfe553.

The marker dependencies have already received the context-derived storage. They are not assumed to leave its contents unchanged before this fallback read.

### Zero mode, any other selector: default initialization

For any selector other than `0x6D2A` and `0x6D2B`, the function:

1. Reads the 32-bit default-path header global.
2. Writes that value to destination offset 0.
3. Writes zero to destination offset 4.
4. Invokes F-438680ffebfe with the destination.
5. Returns the destination after normal dependency completion.

The default header is a global read at this assignment, not an unspecified immutable constant. Its read precedes its destination write.

No context-derived access, marker check, or value-resolution call occurs on this path. The initial shared source pointer read still occurs.

## Side effects

### Direct reads and writes

Every visible path reads one selected header global and writes its value to the destination’s first word. Each such global read precedes the corresponding destination write.

Every visible path directly clears the second destination word except exact source/destination equality on a source-transfer path.

The relevant read timing is:

| Operand | Read timing |
|---|---|
| Shared source pointer | Before mode dispatch. |
| Source-path header, nonzero mode | Before the first destination write and before exact-address comparison. |
| Source-path header, embedded fallback | After both marker calls return, before the first destination write and exact-address comparison. |
| Default-path header | On entering default initialization, before the first destination write. |
| Resolved-value header | After F-c0b020cd3882 returns, before the first destination write. |
| Branch-associated resolution value | After F-9d0ecc5f6adf returns, before F-c0b020cd3882 is invoked. |
| Source second word | After the destination header write and second-word clearing, only when source and destination differ. |

Dependencies may subsequently change destination contents. Normal return therefore does not establish that either directly written destination word retains its assigned value.

### Aliasing

Exact source/destination equality receives special handling only on source-transfer paths. It suppresses the second-word clear and transfer call, but not the header-global read or first-word write.

Distinct addresses are not checked for overlap. If destination writes overlap the selected source’s second word, the later source read observes the resulting value under ordinary memory behavior. General overlap safety is not established.

Likewise, no separate snapshot of a header global is established before its stated read event. Aliasing or dependency changes affecting that global before the read can affect the assigned header.

### Ownership and failure

No explicit release of a previous destination payload precedes the direct writes. Passing an already-populated object is not established as safe or leak-free.

No allocation, deallocation, retention, reference counting, or ownership transfer is directly established. Such effects may occur within dependencies, whose contracts are unavailable.

There are no visible null checks, bounds checks, explicit error results, rollback steps, or recovery branches. Invalid addresses may be accessed directly or passed to dependencies. Abnormal dependency completion and its effects remain documented_only.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Each assumes valid accesses and normal completion of the dependencies involved.

1. **Mode precedence.** With nonzero mode and destination distinct from the retained shared source, the function reads the source-path header, writes it, clears the second destination word, then reads the source’s second word for F-151ab4bfe553. The selector does not cause marker checks or value resolution.

2. **Exact shared-source alias.** With nonzero mode and destination equal to the retained source, the source-path header global is still read and assigned. No direct second-word clear, source-payload read, or F-151ab4bfe553 call follows.

3. **Resolution uses current shared operands.** With zero mode and selector `0x6D2A`, suppose F-9d0ecc5f6adf changes the selector-associated global before returning. F-c0b020cd3882 receives the value read after that change, not an entry-time snapshot.

4. **Resolved header reflects resolver changes.** On any resolved-value path, suppose F-c0b020cd3882 changes the resolved-value header global before returning. With no intervening change, the destination header assignment uses that changed value. The header read occurs after the resolver returns.

5. **First marker wins.** With zero mode, selector `0x6D2B`, and a zero first comparison result, the second marker is not checked. The first-marker-associated global supplies the resolution argument after F-9d0ecc5f6adf returns.

6. **Second marker selection.** With a nonzero first comparison result and zero second result, both comparisons precede value resolution. The second-marker-associated global supplies the resolution argument.

7. **Fallback header reflects marker-call changes.** Suppose both marker checks return nonzero and the second call changes the source-path header global. With no intervening change, the fallback reads and assigns that changed header value. It does not use a value captured before the calls.

8. **Fallback payload follows initialization.** With both marker checks nonzero and destination distinct from context plus 76, F-151ab4bfe553 receives the word at context plus 80 as read after the destination header write and second-word clear.

9. **Embedded self-source.** With both marker checks nonzero and destination equal to context plus 76, the function reads and writes the source-path header, then returns without directly clearing the second word or invoking F-151ab4bfe553.

10. **Default header is read before assignment.** With zero mode and selector `0x6D2C`, the current default-path header global is read and assigned before the second-word clear and F-438680ffebfe invocation. If that dependency leaves the first destination word unchanged, it retains the value obtained by this read.
