# F-e50b4dd1f091

## Purpose

- A 32-bit value read from fixed external storage is written at destination offset 0.
- The supplied 8-bit argument is written at destination byte offset 40.

The external value is read after F-ff4dff756de0 returns. The first supplied argument has no visible use.

This establishes two field-sized assignments, not a complete allocation, construction, registration, or ownership protocol. Interpreting the destination as an object, or its leading word as a type marker or other metadata, is inferred intent rather than established behavior.

Neither assignment explicitly reads its destination in order to preserve or merge previous contents. Nevertheless, previous destination contents can influence the values written: the external source may overlap destination storage, and the dependency may inspect existing storage and change the external source before returning.

## Behavior

### External source read and leading write

After the dependency returns, the function reads the 32-bit contents of a fixed external storage location. It writes the value obtained by that read to destination offset 0.

The transfer is 32 bits wide. The evidence does not establish whether the value represents a number, pointer, identifier, or other data. It also does not establish byte order.

The value is selected by the post-dependency read, not by a read performed before the call. If the dependency changes the source before returning, that change can affect the leading write.

Source and destination disjointness is not established. Consequently:

- If the source coincides with the leading destination word, existing destination contents can supply the entire value being written back.
- If the source partially overlaps destination storage, existing contents of the overlapping bytes can contribute to the value read.
- If the source includes destination byte 40, that byte’s value at the time of the source read can contribute to the leading word, before the later 8-bit assignment replaces byte 40.

These possibilities do not turn the assignment into an explicit preserve-or-merge operation. They describe influence through the source read.

### Trailing write

After the leading write, the function writes the second argument to destination byte offset 40.

The displacement is ten elements of four bytes each: 10 × 4 = 40 bytes. It is not a displacement of ten bytes. The access at that address is only one byte wide.

There is no explicit read of the old byte at offset 40 for preservation, comparison, or bit merging. The assignment replaces the byte with the supplied 8-bit pattern.

The evidence does not establish the width of destination addresses or the environment’s treatment of invalid address arithmetic. The stated layout requires valid addresses for the specified accesses; it does not promise wrapping-address behavior.
