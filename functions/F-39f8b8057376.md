# F-39f8b8057376

## Purpose

The visible operation is an ordered sequence of indirect calls interleaved with two 32-bit memory stores and four byte stores. Several call results feed later calls, address calculations, or byte values. Two additional incoming machine-state values supply data even though they are not formal parameters.

No application-level purpose is established. In particular, the evidence does not identify the addressed memory as ordinary RAM, device registers, a table, or an object layout.

The recovered control flow ends at an invalid-instruction boundary. The visible representation does not establish a normal return, a successful completion condition, or the behavior of any instructions beyond that boundary.

This contract distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.
- **Inferred interpretation:** a 32-bit machine-word model used to explain address and bit arithmetic.
- **Unknown behavior:** dependency effects, architecture-specific arithmetic details, and execution beyond the recovered boundary.

All behavior below is conditional on execution reaching the relevant operation without an earlier dependency failing, trapping, transferring control elsewhere, or failing to return.

### 2. First byte-store pair

**F-D12** is called with no explicit arguments. Its result is treated as an unsigned 32-bit value, called **first result** below.

A reusable address base is formed from:

\[
\text{payload} \times 0x80000.
\]

Under the 32-bit unsigned interpretation, this product is reduced modulo \(2^{32}\). The operation reads one unsigned byte at that base plus one. It then stores:

\[
(4 \times \text{first result}) \bmod 256
\]

at the address obtained by adding `0x11` to the byte just read.

The read and store are adjacent in the visible operation sequence: there is no represented dependency call between them.

After that store:

1. **F-D13** receives the full 32-bit value \(\text{first result} \ll 2\), with unsigned truncation to 32 bits.
2. **F-D14** runs with no explicit arguments and returns an opaque 32-bit value.
3. **F-D15** receives that opaque value.
4. **F-D16**, **F-D17**, and **F-D18** run in order with no explicit arguments.
5. **F-D19** runs with no explicit arguments and returns a signed 32-bit value.

The operation then reads a byte again from the previously calculated base plus one. This is a fresh memory read, not reuse of the earlier byte. The intervening dependencies may have changed that memory.

Using the newly read byte to choose the destination, the operation stores the low eight bits of:

\[
(\text{first result} \mathbin{\&} 0x3fffffff) \mathbin{\gg} 20.
\]

The resulting stored byte is precisely bits 20–27 of **first result**. Although the intermediate shifted quantity can contain ten bits, the byte store discards its upper two bits.

**F-D20** then receives the F-D19 result shifted left by two. The source represents this as a signed shift; negative inputs and signed overflow are unresolved as described under Uncertainties.

**F-D21**, **F-D22**, and **F-D23** follow in order with no explicit arguments.

### 3. Second byte-store pair

**F-D24** runs with no explicit arguments. Its result is treated as an unsigned 32-bit value, called **second result** below.

The operation reads a third byte from the same payload-derived base plus one. It stores:

\[
(4 \times \text{second result}) \bmod 256
\]

at the address selected by that byte plus `0x11`.

**F-D25** receives the byte that selected this destination, zero-extended to 32 bits. It does **not** receive the stored byte value or the second result. The supplied representation retains this selector across the store rather than showing another selector read for the call argument.

Next:

1. **F-D26** runs with no explicit arguments and returns an opaque 32-bit value.
2. **F-D27** receives that value.
3. **F-D28**, **F-D29**, and **F-D30** run in order with no explicit arguments.
4. **F-D31** runs with no explicit arguments and returns a signed 32-bit value.

The final explicit selector read uses a different address calculation:

\[
8 \times \text{second result} + 1.
\]

Under the unsigned 32-bit interpretation, multiplication and addition are reduced modulo \(2^{32}\).

At the address selected by this new byte plus `0x11`, the operation stores the low eight bits of:

\[
(\text{second result} \mathbin{\&} 0x3fffffff) \mathbin{\gg} 20.
\]

This stores bits 20–27 of **second result**.

**F-D32** receives the F-D31 result shifted left by two, again subject to the unresolved signed-shift interpretation.

Finally, **F-D33**, **F-D34**, **F-D35**, and **F-D36** are called in order with no explicit arguments. The recovered control flow then reaches the invalid-instruction boundary.

### 4. Arithmetic boundaries

The unsigned shifts and masks have explicit, useful boundaries:

- \(\text{payload} \gg 3\) ranges from zero through `0x1fffffff`.
- Each low-byte scaled-result store can produce only multiples of four from `0x00` through `0xfc`.
- Each upper-field byte store can produce any byte from `0x00` through `0xff`.
- Under 32-bit unsigned arithmetic, multiplying payload by `0x80000` discards every payload bit above bit 12.
- Multiplying the second result by eight discards its upper three bits before the final selector address is formed.

The signed multiplications used for the word addresses and the signed left shifts passed to F-D20 and F-D32 do not have an equally established overflow interpretation.
