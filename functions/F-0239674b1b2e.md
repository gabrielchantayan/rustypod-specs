# F-0239674b1b2e

## Purpose

The available static evidence describes a routine that invokes ten indirect call targets, performs one intervening byte read and byte write, and ends at an unresolved instruction boundary. It does not establish a higher-level purpose, a normal return path, or a recoverable error protocol.

The distinctive observable operation is a byte store whose destination is selected by an unsigned byte read from an incoming address-related value. The stored byte comes from bits 22 through 29 of a separate incoming 32-bit value. After this store, the routine passes a scaled result from an earlier dependency to another dependency.

This is a source-facing contract for the represented execution prefix, not a claim that the representation accurately captures valid executable instructions throughout. The supplied evidence explicitly reports invalid instruction data and truncated control flow.

## Behavior

### Scope and dependency notation

The ten call occurrences are assigned opaque local dependency IDs **U-01** through **U-10**. These IDs identify occurrences in this contract; they do not assert resolved external identities or independent implementations.

The following sequence is established by the supplied representation, conditional on each preceding operation completing normally. It describes represented operation order, not hardware memory-order guarantees.

### 1. Initial call

The routine first invokes U-01.

Its target is derived by adding `0xFEC` to the incoming control-base value. The second explicit input is supplied as an explicit argument.

The first input is not explicitly supplied by the represented call expression. This does not establish that its bits are absent from machine registers or inaccessible to the dependency.

The result of U-01, if any, is not explicitly used.

### 2. Four calls before the direct memory operation

The routine next invokes U-02, U-03, U-04, and U-05, in that order.

Each target is obtained from fixed address arithmetic in the represented body. No explicit arguments are shown for these four calls. This means only that no argument expressions are represented; it does not prove an empty machine-level argument state.

The results of U-02, U-03, and U-04 are not explicitly consumed. The result of U-05 is captured as a signed 32-bit intermediate for later use.

There is no visible conditional branch, retry, or result validation between these calls.

### 3. Read the destination selector

After U-05 returns, the routine reads one unsigned byte from the address obtained by adding one to the incoming data-base value.

Call the byte value the **selector**. Its numeric range is 0 through 255.

This read occurs after the first five calls. Consequently, it must not be interpreted as reading a snapshot taken at routine entry. If an earlier dependency changes the relevant memory and execution continues, the represented read observes the memory value available at this point.

The evidence does not establish signed-overflow behavior or address wraparound for forming the source address. The address addition must therefore be treated as subject to the actual execution model.

### 4. Compute and perform the byte write

The destination address is the selector’s unsigned numeric value plus hexadecimal `0x11`, which is decimal 17.

This is a direct numeric address calculation. It is not an index into a separately supplied output buffer, and no additional base pointer is added.

Thus, the represented destination address lies between:

- Decimal 17, hexadecimal `0x11`, when the selector is zero.
- Decimal 272, hexadecimal `0x110`, when the selector is 255.

The byte value is derived from the unsigned 32-bit bit-source value:

- Shift the bit-source value right by 22 positions.
- Retain the low eight bits for the byte store.

Equivalently, original bits 22 through 29 determine the stored byte. Original bits 0 through 21 and bits 30 through 31 do not affect it.

The unsigned right shift yields a value between 0 and 1023 before byte narrowing. Only its low eight bits are written.

The selector read precedes the write, including when the source and destination addresses overlap. The body shows one byte read and one byte write for this operation; it does not show a multi-byte load or store.

### 5. Call with a scaled dependency result

After the byte write, the routine invokes U-06. Its explicit argument is the result captured from U-05 shifted left by two positions.

The intermediate is represented as signed and 32-bit. This prevents an unconditional specification of the argument as a wrapping unsigned multiplication by four.

For nonnegative values no greater than `0x1FFFFFFF`, the shift is representable as a signed 32-bit value and produces four times the captured result. For negative inputs or larger positive inputs, the supplied representation does not establish a portable arithmetic result. Actual instruction semantics would be required to specify those cases.

The byte store precedes U-06. No rollback is shown if U-06 subsequently fails or does not return.

### 6. Remaining calls and unresolved endpoint

The routine invokes U-07, U-08, U-09, and U-10, in that order. No explicit arguments or consumed results are represented for these calls.

After U-10 returns, the representation ends at an invalid-instruction marker. There is no established ordinary return or further reachable continuation.

## Acceptance examples

These are conditional examples of the represented contract, not executed tests.

### Selector lower boundary

If the first five dependencies return and the selector read produces zero, the destination is address `0x11`.

If the bit-source value is `0x00400000`, the byte written there is `0x01`. U-06 is attempted only after that write completes.

### Selector upper boundary

If the selector is `0xFF`, the destination is address `0x110`, not `0x10`. The selector is widened for the address calculation; the addition is not reduced to eight bits.

If the bit-source value is `0x3FC00000`, the written byte is `0xFF`.

### High source bits discarded

If the bit-source value is `0xC0000000`, the written byte is zero. The unsigned right shift produces `0x300`, and the byte store retains only its low eight bits.

This distinguishes bits 30 and 31 from the eight bits that control the output byte.

### Representable scaled result

If U-05 returns signed value 7, the routine performs the selector read and byte write, then supplies explicit argument 28 to U-06.

If U-05 returns `0x1FFFFFFF`, the explicit argument is `0x7FFFFFFC`, within the representable nonnegative signed range.

A negative return or a value of `0x20000000` or greater does not have a fully established arithmetic contract here.

### Read/write overlap

If the selector source address is `0x20` and the byte read there is `0x0F`, the destination is also `0x20`.

The old byte selects the destination before the new byte replaces it. No second selector read is shown.

### Earlier dependency changes memory

If U-03 changes the selector byte and all calls through U-05 return, the later selector read uses the byte present at read time. The body does not preserve the entry-time byte.

### Interrupted execution

If U-04 does not return, U-05 and the direct byte operation are not reached along the represented sequence.

If U-06 does not return, the direct byte write has already occurred, while U-07 through U-10 are not reached along that sequence.
