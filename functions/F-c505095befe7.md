# F-c505095befe7

## Purpose

F-c505095befe7 selects and returns one byte using a record address and a byte displacement. Two address-bearing fields in the record influence the selection:

- A **probe-base field** at record offset 12 supplies an optional byte to inspect.
- A **fallback-base field** at record offset 8 supplies an optional alternate location from which to return a byte.

The probe byte is a routing condition, not the returned value. A nonzero probe byte selects a byte relative to the record itself. An absent probe base or a zero probe byte permits selection through the fallback-base field.

The apparent intent is a per-position choice between inline storage and alternate storage, with the probe providing a presence or selection indicator. That interpretation is inferred; the established behavior is only the address selection and byte reads described below.

## Interface

### Inputs

The function takes two integer-represented inputs:

| Input | Role |
|---|---|
| Record address | Base address for the two fields and for the inline return location. |
| Byte displacement | Offset added directly to a selected base address. |

There is no explicit length, capacity, validity flag, ownership token, or error-output parameter.

The displacement is not multiplied by an element size. Its unit is one byte. The supplied representation uses integer address arithmetic rather than a declared record or array type.

### Record layout

The function uses these record-relative locations:

| Offset | Width in the supplied model | Meaning |
|---|---:|---|
| 8 | 4 bytes | Integer-represented fallback base; zero means unavailable. |
| 12 | 4 bytes | Integer-represented probe base; zero means unavailable. |
| Byte displacement | 1 byte | Inline byte returned on paths that do not select fallback storage. |

The inline location is not established as a separate member or array. Depending on the displacement, it may overlap either address-bearing field or other record contents.

The supplied representation models the address-bearing fields and integer arithmetic as 32-bit. It does not independently establish the original declaration, target byte order, or precise machine behavior for address overflow.

### Output

The result is one 8-bit value read from either:

- the record address plus the displacement; or
- the fallback base plus the displacement.

The function does not directly return the probe byte. A result of zero is ordinary data, not a distinguished failure result. All byte patterns are possible results if present at the selected return location.

No pointer, reference, allocation, or ownership transfer is returned.

### Preconditions

For a defined successful access sequence:

- The record’s probe-base field must be readable.
- A nonzero probe base requires the probe location at that base plus the displacement to be readable.
- If the probe is absent or its byte is zero, the fallback-base field must be readable.
- The final selected return location must be readable.
- Address calculations must be meaningful under the actual execution environment.

These are path-dependent requirements. For example, a nonzero probe byte avoids reading the fallback-base field, but it does not avoid the final inline-byte read.

No validation enforces these preconditions.

## Behavior

### Initial probe-field read

The first memory operation established by the supplied representation is a read of the 32-bit probe-base field at record offset 12.

That value is retained for the probe decision. The representation does not show a second read of this field.

If the value is zero, the function does not read a probe byte. It proceeds as though the probe condition did not select inline storage.

If the value is nonzero, the function reads one byte at:

**probe base + byte displacement**

Only equality to zero matters for this byte. Although the temporary representation uses a character type, any signed-character interpretation does not affect the branch: every nonzero byte pattern takes the same route.

### Nonzero probe byte

When a probe base exists and the probe byte is nonzero:

- The fallback-base field is not read.
- The function reads and returns the byte at the record address plus the displacement.

The nonzero probe byte is not copied to the output. It only controls which return location is used.

Even if the inline byte is zero, the function returns that zero. There is no subsequent fallback decision based on the inline byte’s value.

### Absent or zero probe byte

When the probe base is zero, or when the probe byte is zero, the function reads the fallback-base field at record offset 8.

If this field is zero, the function reads and returns the inline byte at the record address plus the displacement.

If this field is nonzero, the supplied representation evaluates the fallback-base field again to form the return address, then reads and returns one byte at that base plus the displacement.

Thus, the successful fallback path contains two evaluations of the fallback-base field:

1. One to test whether fallback storage is available.
2. Another to obtain the base used for the return-byte address.

This distinction matters when assessing mutable or specially mapped memory. The supplied representation does not guarantee that the second value equals the first. It also does not establish whether a compiled implementation would preserve both reads as separate machine operations.

### Return-location decision table

For stable, ordinary memory, the selection is:

| Probe base | Probe byte | Fallback base | Return location |
|---|---|---|---|
| Nonzero | Nonzero | Not inspected | Record address + displacement |
| Nonzero | Zero | Nonzero | Fallback base + displacement |
| Nonzero | Zero | Zero | Record address + displacement |
| Zero | Not read | Nonzero | Fallback base + displacement |
| Zero | Not read | Zero | Record address + displacement |

There is no branch that returns zero solely because a base field is zero. A zero base changes routing; a final byte read still occurs.

## Acceptance examples

These examples are conditional static acceptance cases, not execution results. Unless stated otherwise, all referenced locations are valid, arithmetic is representable, and memory remains stable during the operation.

### Nonzero probe selects inline data

Suppose the displacement is 3, the probe base is nonzero, the probe byte at displacement 3 is `0x80`, and the inline byte at displacement 3 is `0x27`.

The result must be `0x27`. The fallback-base field must not be consulted by the represented control flow. The value `0x80` establishes a nonzero probe regardless of whether the environment treats character values as signed.

### Zero probe selects available fallback data

Suppose the probe byte is zero, the fallback base is nonzero, the fallback byte at the requested displacement is `0x91`, and the inline byte is `0x42`.

The result must be `0x91`. The inline byte does not influence selection and is not read on this path.

### Missing probe permits fallback without a probe-byte read

Suppose the probe-base field is zero, the fallback base is nonzero, and the fallback byte is `0x36`.

The result must be `0x36`. No access at zero plus the displacement is made for the probe.

### Missing fallback selects inline data

Suppose the probe is absent or its byte is zero, the fallback-base field is zero, and the inline byte is `0x5A`.

The result must be `0x5A`. A zero fallback base does not itself produce a zero result.

### Zero is valid returned data

Suppose a nonzero probe selects inline storage and the inline byte is zero.

The result must be zero, with no attempt to obtain a nonzero value from fallback storage.

Likewise, if fallback storage is selected and its byte is zero, that zero must be returned without retrying inline storage.

### Displacement zero has no special treatment

With displacement zero, each byte address is exactly its selected base. The function does not skip a header or adjust the displacement automatically.

### A selected invalid location has no guaranteed result

If the probe is nonzero but its byte location is unreadable, normal completion is not guaranteed—even when the inline return location would otherwise be readable. The probe read precedes the return-byte selection.
