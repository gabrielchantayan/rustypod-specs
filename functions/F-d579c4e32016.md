# F-d579c4e32016

## Purpose

F-d579c4e32016 conditionally replaces a structure’s recorded backing storage, detaches its pending node chain, and passes each reached node to a redistribution dependency.

The established sequence is a storage request, followed on a nonzero result by an old-storage call, publication of the replacement and requested count, callback resolution, chain detachment, and traversal. Each node’s destination is calculated from the saved replacement result, a callback result, and a mask derived from the requested count.

The inferred intent is to resize or rebuild a hash-oriented container. That interpretation does not establish allocation guarantees, ownership, bucket contents, or the valid range of requested counts.

This contract describes direct behavior separately from dependency effects. A dependency’s apparent allocation, release, or redistribution role is not proof of its complete contract.

## Interface

The function accepts two inputs and has no explicit return value:

- **Structure address:** An address identifying mutable storage with the fields below.
- **Requested count:** A signed 32-bit integer.

The supplied representation uses 32-bit address-bearing fields. All offsets below are byte offsets.

### Structure fields

| Offset | Width | Direct use |
|---|---:|---|
| 0 | 8 bits | Selector supplied to F-3da36e01ea24 after replacement publication. |
| 8 | 32 bits | Read as signed for two independent positivity tests; overwritten with the requested count on the nonzero-result path. |
| 12 | 32 bits | Node-chain address captured after callback resolution, then overwritten with zero. |
| 16 | 32 bits | Recorded storage value passed to F-94cb53877c15, then overwritten with the saved replacement result. |

No other structure fields are directly accessed. Dependencies may access additional state through supplied addresses or other means.

### Node fields

| Offset | Width | Direct use |
|---|---:|---|
| 0 | 32 bits | Successor address, read after the callback returns and before redistribution. |
| 12 | 32 bits | First callback argument. |
| 16 | 32 bits | Second callback argument. |

These accesses do not establish a complete node layout or the semantic meaning of the callback arguments.

### Preconditions and result interpretation

The structure must support the accesses performed on the selected execution path. For traversal to complete normally:

- Every reached nonzero node address must support the node-field reads.
- The resolved callback must be callable whenever a node is processed.
- Dependencies must accept the supplied arguments and return normally.
- The sequence of successor addresses actually observed must terminate.

The function performs no explicit validation of these conditions.

The requested count is not checked for positivity, nonzero value, or power-of-two form. The replacement result is tested only for equality to zero; a negative signed 32-bit result also enters the replacement path.

There is no returned success indicator. A zero storage-request result skips the function’s direct structure writes, but does not imply that preceding dependencies had no effects.

## Behavior

### Preliminary condition and storage request

The function first reads the signed 32-bit structure field at offset 8.

If that value is strictly positive, it calls F-7107f219f55e with zero. Otherwise, it skips that call. This condition concerns the existing structure field, not the requested count.

It then calls F-1c177d5ba9f6 with an expression formed by shifting the signed 32-bit requested count left by three bits.

For requested counts from 0 through 268,435,455 inclusive, the expression has the unambiguous value eight times the count within the signed 32-bit range. Negative counts and larger positive counts are not rejected, but their signed-shift behavior is not established portably by the supplied representation. This uncertainty concerns the request-size expression; it does not make the later unsigned destination arithmetic unspecified.

The signed 32-bit result of F-1c177d5ba9f6 is retained for the zero test, replacement publication, and destination calculations.

### Independent second condition

After the storage request returns, the function reads the signed field at structure offset 8 again.

If this newly observed value is strictly positive, it calls F-ffdded7ca165 with zero. Otherwise, it skips that call.

The two decisions are independent reads separated by dependency calls. A dependency that changes this field can cause either conditional call to occur without the other. Their placement does not establish locking, synchronization, or balanced resource acquisition and release.

The second conditional call occurs before the saved storage-request result is tested.

### Zero-result path

If the saved result from F-1c177d5ba9f6 is zero, the function returns without directly:

- Calling F-94cb53877c15.
- Replacing the storage field.
- Storing the requested count.
- Resolving a callback.
- Capturing or clearing the chain field.
- Traversing nodes or invoking redistribution.

Dependencies already invoked may have changed the structure, nodes, globals, or external state. No unchanged-state guarantee follows from this path alone.

### Nonzero-result publication

For any nonzero saved result, the function performs these operations in order:

1. Reads the current 32-bit value at structure offset 16.
2. Calls F-94cb53877c15 with that value.
3. Writes the saved replacement result to structure offset 16.
4. Writes the requested count to structure offset 8.

The old-storage argument is read at this point, not cached at entry. Earlier dependency effects can therefore change which value is supplied.

There is no null check on the old-storage value and no equality check between old and replacement values. F-94cb53877c15 is called even if the recorded old value is zero.

The old-storage call precedes both direct publication writes. Effects made by that dependency to offsets 16 and 8 are subsequently overwritten if it returns normally. No rollback is provided.

### Callback resolution and chain detachment

After publishing the replacement and count, the function:

1. Reads the selector byte at structure offset 0.
2. Passes it to F-3da36e01ea24.
3. Retains the returned callable address.
4. Reads the chain address at structure offset 12.
5. Writes zero to structure offset 12.

Callback resolution therefore occurs after publication but before chain capture. If F-3da36e01ea24 changes the chain field, traversal starts from the value read after that call.

The callback is resolved once. The selector is not re-read for individual nodes.

These steps also occur when the captured chain is empty. In that case, the returned callback is never invoked.

### Per-node processing

For each nonzero current node address, the function:

1. Reads the 32-bit fields at node offsets 12 and 16 and supplies them as the first and second callback arguments, respectively.
2. Receives a callback result consumed as an unsigned 32-bit value.
3. Reads the current node’s 32-bit successor field at offset 0.
4. Calculates a destination using the saved replacement result and original requested count.
5. Calls F-f32d03db7833 with the structure address, calculated destination value, and current node address, in that order.
6. Continues with the successor saved before the redistribution call.

The relative order of the two callback-argument reads is not established. Both occur before that callback invocation.

The successor is read **after** callback completion. Callback changes to the current node’s successor can therefore affect traversal.

The successor is saved **before** F-f32d03db7833 runs. Changes by that dependency to the current node’s successor do not change the immediately selected next node. Its changes to future nodes can still affect later reads.

The function does not directly clear node links, free nodes, or allocate replacement nodes. Relinking and ownership effects, if any, belong to dependencies.

### Exact destination arithmetic

Let:

- \(N\) be the original signed 32-bit requested count.
- \(R\) be the saved signed 32-bit replacement result.
- \(H\) be the callback result interpreted as unsigned 32-bit data.
- \(\operatorname{u32}(x)\) mean reduction to the unsigned 32-bit value congruent to \(x\) modulo \(2^{32}\).

The mask and selected index are:

\[
M=\operatorname{u32}\bigl(\operatorname{u32}(N)-1\bigr),
\qquad
I=H\mathbin{\&}M.
\]

The scaled byte offset and complete destination are:

\[
O=\operatorname{u32}(8I),
\]

\[
D=\operatorname{u32}\bigl(\operatorname{u32}(R)+O\bigr).
\]

Equivalently, the destination is the unsigned 32-bit reduction of the saved replacement result plus the unsigned 32-bit reduction of eight times the index.

**Both multiplication and addition wrap modulo \(2^{32}\).** Because the scaled index is unsigned 32-bit, the saved signed replacement result is converted to unsigned 32-bit before addition. A negative saved result contributes its corresponding unsigned bit-pattern value; addition is not signed arithmetic.

The nonzero test on \(R\) does not imply that \(D\) is nonzero. Addition can wrap a nonzero replacement base to destination zero. There is no check for this case, arithmetic wrap, alignment, or destination validity before F-f32d03db7833 is called.

This calculation uses the saved replacement result and original requested count, not later reads of structure offsets 16 and 8. Dependencies that change those fields do not change these arithmetic inputs.

Masking is not general remainder division:

- For a positive power-of-two count, the index ranges from zero through count minus one.
- For a positive non-power-of-two count, selected indices remain below the count, but some indices are unreachable. Count 6 gives mask 5 and permits only indices 0, 1, 4, and 5.
- Count zero gives an all-ones mask.
- Negative counts are not rejected; their unsigned conversion defines the mask if execution reaches this calculation, without establishing safe storage bounds.

## Side effects

The function’s direct structure writes occur only after a nonzero storage-request result, in this order:

1. Saved replacement result to offset 16.
2. Requested count to offset 8.
3. Zero to offset 12, after callback resolution and chain capture.

There are no direct node writes in the supplied representation. Callback and redistribution effects remain dependency-defined.

The replacement and count writes establish field values at those moments, not guaranteed final values. Later dependencies may modify them. Likewise, the direct chain clear does not guarantee that the chain field remains zero at return.

The operation is not shown to be atomic or transactional. The replacement is published before chain detachment, and detachment precedes redistribution. Interruption or a non-returning dependency can leave these steps partially completed.

There is no explicit rollback, error report, cycle detection, or iteration limit. A cycle in the observed successor sequence can prevent termination. No ownership transfer or memory release guarantee follows solely from the direct operations.

## Acceptance examples

These are conditional consequences of the static representation, not executed tests. Unless specified otherwise, dependencies return normally and preserve state needed by the example.

### Zero storage-request result

Assume structure offset 8 contains 4 throughout the preliminary calls, the requested count is 8, and F-1c177d5ba9f6 returns zero.

The observable call sequence is F-7107f219f55e with zero, F-1c177d5ba9f6 with 64, then F-ffdded7ca165 with zero. The function returns without its direct structure writes or subsequent calls.

### Independent positivity tests

Assume offset 8 initially contains zero and the storage-request dependency changes it to 3.

F-7107f219f55e is skipped, while F-ffdded7ca165 is called. Conversely, an initially positive value changed to zero before the second read yields the first conditional call without the second.

### Nonzero result with an empty chain

Assume the saved replacement result is nonzero and the chain field is zero when read after callback resolution.

The function calls F-94cb53877c15, writes the replacement and count, resolves the callback, and writes zero to the chain field. Neither the callback nor F-f32d03db7833 is invoked.

### Two nodes with count 8

Assume a terminating two-node chain, callback results 13 and 2, and replacement value 4096.

The mask is 7. The destination values are 4136 and 4112, respectively. Redistribution calls follow traversal order. This does not establish final ordering within either destination.

### Callback-controlled successor

Assume the callback changes the current node’s successor from one valid address to another.

The changed successor is read after callback return and selected for the next iteration. A subsequent redistribution change to that same successor field does not replace the saved selection.

### Addition wraps to destination zero

Assume requested count 8, saved replacement result \(-8\), and callback result 1 for a reached node.

The replacement result is nonzero, so it passes the success test. Its unsigned value is 4,294,967,288. The index is 1 and the scaled offset is 8. Unsigned addition produces destination zero modulo \(2^{32}\).

F-f32d03db7833 receives zero as its destination argument. Whether that dependency accepts zero or fails is unresolved; the enclosing function does not reject it.

### Multiplication wraps with count zero

Assume requested count zero, nonzero saved replacement result 4096, and callback result 536,870,912 for a reached node.

The request-size expression is zero and the mask is all ones. The selected index is 536,870,912. Scaling by eight wraps to zero, so the destination is 4096.

This establishes the arithmetic and supplied argument only. It does not establish valid backing storage for a zero-count request.
