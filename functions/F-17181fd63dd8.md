# F-17181fd63dd8

## Purpose

F-17181fd63dd8 conditionally obtains an object-associated temporary buffer, requests an operation using that buffer, and invokes two external operations after accepting a caller-specified range. It returns a 32-bit success or failure value.

Established behavior consists of dependency calls, unsigned range checks, conditional reads, and cleanup ordering. Interpreting the operations as allocating storage, populating it, copying a selected portion, and releasing storage is plausible but not established by the supplied dependency evidence.

Range acceptance uses a **32-bit wrapped offset-plus-length calculation**, not an overflow-safe mathematical bounds check. Some ranges with a mathematical end beyond the 32-bit address space therefore pass the checks.

## Behavior

- Failure is selected.
- No object dispatch occurs.
- No descriptor initialization or cleanup occurs.
- Execution proceeds to the common final call.

If acquisition returns a non-null pointer, the function reads the object’s dispatch-table address and invokes F-000000000003 through the entry at byte offset `0x2c`, passing the object pointer. The returned value is treated as an unsigned 32-bit size.

No independent check establishes that the non-null object, its dispatch table, or its dispatch entries are valid. Validity of these accesses is a precondition for normal execution.

### Range acceptance

The function accepts the range only if all three conditions hold:

1. Offset is strictly less than size.
2. Length is less than or equal to size.
3. Offset plus length, computed modulo \(2^{32}\), is less than or equal to size.

These conditions are evaluated in that order. The length condition is reached only if the offset condition passes. The wrapped-sum condition is reached only if the length condition passes.

Failure of any condition selects `0xffffffff` and proceeds to the common final call without initializing the descriptor.

Consequences:

- Size zero rejects every range.
- Offset equal to size is rejected, including when length is zero.
- Zero length is accepted when offset is strictly below size.
- A non-wrapping range ending exactly at size is accepted.
- A carry out of the 32-bit sum is not separately rejected.
- Some mathematically out-of-bounds ranges pass because their wrapped sum is small enough.

The size obtained from the first object operation is retained for later calls. The function does not query the size again.

### Descriptor initialization

1. The descriptor’s address.
2. The full size obtained from the object.

It then reads the descriptor’s first word.

If that word is zero, failure is selected and preparation is skipped. Otherwise, preparation is attempted.

The function does not initialize the descriptor before this call or independently check an initializer return value. A defined subsequent descriptor read therefore requires F-d9e0ae06e54d to establish appropriate contents.

### Preparation

1. The referenced global value.
2. The original request value.
3. The address of the 32-bit output slot.

## Acceptance examples

These examples are conditional deductions from static evidence, not executed tests. Unless otherwise stated, assume dependencies return normally, provide valid memory and required outputs, and return zero where zero is required.

### Missing object

If acquisition returns null, the result is `0xffffffff`. The entry call precedes acquisition, and the common final call follows it. No size query, descriptor initialization, preparation, or descriptor cleanup occurs.

### Range ending exactly at size

For size 16, offset 4, and length 12, all range checks pass.

On subsequent success, F-000000000001 receives the original destination, the then-current buffer address plus 4, and length 12. F-000000000002 follows, then descriptor cleanup, then the common final call. The result is zero.

### Zero-length range inside the object

For size 16, offset 15, and length zero, the range is accepted.

Zero length does not bypass descriptor initialization, preparation, the second object operation, or either successful-path external operation.

### Empty range at the end

For size 16, offset 16, and length zero, the strict offset comparison fails. Descriptor initialization does not occur, and the result is `0xffffffff` after the common final call.

Size zero likewise rejects offset zero and length zero.

### Ordinary overrun

For size 16, offset 12, and length 5, the wrapped sum is 17 without overflow. The range is rejected before descriptor initialization.

### Wrapped arithmetic

For size `0xfffffff0`, offset `0xffffffe0`, and length `0x30`:

- Offset is below size.
- Length does not exceed size.
- The 32-bit sum wraps to `0x10`, which does not exceed size.

The range passes. This establishes only the range decision, not memory safety or eventual success.

### Unavailable buffer

If descriptor initialization leaves its first word zero, preparation is skipped. Descriptor cleanup and the common final call still occur. The result is `0xffffffff`.

### Preparation failure

For an accepted range and nonzero first descriptor word, a nonzero preparation result prevents the second object operation and both successful-path external operations. Descriptor cleanup and the common final call occur, followed by `0xffffffff`.

### Second object-operation failure

If preparation succeeds but the second object operation returns nonzero, both successful-path external operations are skipped. Descriptor cleanup and the common final call still occur, and the result is `0xffffffff`.

### Global value changed before preparation

If an earlier dependency changes the referenced global, preparation receives the value read when preparation is reached, not a value captured at function entry. This example makes no assumption about the global’s storage type or read width.
