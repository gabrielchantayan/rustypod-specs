# F-0fd46b9a392f

## Purpose

F-0fd46b9a392f conditionally updates a state object obtained from F-7fba0909c452. Its action depends on a signed integer input, a shared comparison value, and whether the dependency returns a null pointer.

The established behavior has four possible outcomes:

- Return without accessing a state object when the dependency returns null.
- Set one selected bit in a byte at object offset 0x14C.
- Write the byte value 1 at an address derived from an object-resident displacement.
- Conditionally initialize the object’s first 32-bit word to 0x500.

Only one of these outcomes is selected per invocation. The flag-setting and displaced-byte paths do not also perform the first-word initialization.

The apparent intent is to record particular input categories and supply a default state for other inputs. That interpretation is inferred; the meanings of the categories, bits, displaced byte, and default value are not established.

## Interface

**Input.** One integer interpreted as a signed 32-bit value. Signed ordering matters when deciding which constant comparisons are reachable. The input is not treated as an unsigned 16-bit code, even though the explicitly compared positive constants fit within 16 bits.

**Return.** No return value is specified. Callers observe the invocation through memory effects and any effects of F-7fba0909c452.

**Dependency result.** F-7fba0909c452 is called without explicit arguments. Its result is interpreted as either null or a pointer to the state object.

**Shared comparison value.** A shared integer is read after the dependency returns successfully. Its recovered comparison semantics are signed 32-bit. This value is not an explicit argument, and its address and semantic name are not part of this contract.

**Relevant object layout.** Offsets are measured in bytes from the returned object pointer:

| Offset | Width | Use |
|---|---:|---|
| 0x000 | 32 bits | Read on the fallback path; replaced with 0x500 only when zero |
| 0x14C | 8 bits | Read and written on a flag-setting path |
| 0x250 | 32 bits | Read as a signed displacement on the displaced-byte path |
| Derived address | 8 bits | Written with 1; address is object base plus displacement plus 0x14D |

The recovered layout uses four-byte integer words. The access at 0x14C is a single-byte access, not a read or write of the entire surrounding 32-bit word.

**Memory preconditions.** A non-null result must permit the accesses selected by the actual branch:

- A flag path requires readable and writable storage at offset 0x14C.
- The fallback path requires a readable 32-bit word at offset zero and, if that word is zero, writable storage there.
- The displaced-byte path requires a readable 32-bit displacement at offset 0x250 and a writable byte at the computed address.

Null is checked explicitly. No other pointer validity, size, alignment, displacement-range, or access-permission check is visible. These requirements are path-specific; the function does not visibly validate a complete object layout before choosing a path.

## Behavior

### Dependency and null handling

The first established operation is one call to F-7fba0909c452.

If its result is null, F-0fd46b9a392f returns immediately. It does not then read the shared comparison value or perform any of the object accesses described below.

This is not a guarantee that the invocation has no side effects: the dependency has already executed, and its effects are unknown.

For a non-null result, the function selects a branch using the input and shared comparison value. It does not make another explicit function call.

### Comparison order

The first comparison tests whether the input equals the shared comparison value.

- If equal, the function selects flag mask 0x04.
- If unequal, it evaluates whether the shared comparison value is less than the input, using signed ordering.

The source represents the shared value separately in the equality and ordering expressions. It does not establish an explicit local snapshot reused for both comparisons. The comparison sequence must therefore not be strengthened into a guaranteed single-read or atomic-snapshot contract.

For a stable shared comparison value, the complete selection is:

| Relationship | Additional input condition | Selected action |
|---|---|---|
| Input equals shared value | None | Set flag mask 0x04 |
| Input greater than shared value | Input is 0x8078 | Write 1 at the displaced address |
| Input greater than shared value | Input is 0x8B9C | Set flag mask 0x08 |
| Input greater than shared value | Any other input | Fallback initialization |
| Input less than shared value | Input is 0x8074 | Set flag mask 0x01 |
| Input less than shared value | Input is 0x8075 | Set flag mask 0x02 |
| Input less than shared value | Any other input | Fallback initialization |

If the shared value changes between comparisons, the final group is more precisely the path where the equality comparison failed and the later “shared value less than input” comparison was false. It need not imply that the input was strictly less than one stable shared value.

The equality decision takes precedence over every constant-specific decision. For example, input 0x8078 selects flag mask 0x04 when it equals the shared value; it does not select the displaced-byte write in that case.

The constant checks also depend on the ordering branch. Input 0x8074 is not unconditionally associated with mask 0x01, and input 0x8B9C is not unconditionally associated with mask 0x08.

### Flag-setting paths

Every flag-setting path performs these object accesses in order:

1. Read the byte at offset 0x14C.
2. Set the selected bit while preserving all other bits in that byte.
3. Write the resulting byte back to offset 0x14C.
4. Return.

The possible masks are 0x01, 0x02, 0x04, and 0x08. The resulting byte equals the original byte with the selected mask ORed into it.

The masks used in the supplied evidence clear the selected bit before setting that same bit. This does not clear any other bit and does not make the operation a toggle. A selected bit that was already set remains set.

A byte store is still represented when the selected bit was already set. The operation is not conditional on whether the resulting byte differs from the original byte.

These paths do not visibly read or initialize the first object word and do not read the displacement at offset 0x250.

### Displaced-byte path

This path is reached only when the equality comparison fails, the subsequent ordering comparison places the shared value below the input, and the input is 0x8078.

Its object-access sequence is:

1. Read the signed 32-bit displacement at offset 0x250.
2. Form an address from the object base, that displacement, and the additional byte offset 0x14D.
3. Write the single-byte value 1 at that address.
4. Return.

The destination byte is not read first. Its previous value is replaced, not combined with a mask.

The additional offset is 333 bytes. The displacement is not shown as scaled by a word size; it contributes directly to the byte address. There is no visible condition requiring it to be nonnegative or keeping the resulting address within the returned object.

The recovered expression uses a 32-bit integer representation of the object address. A faithful interpretation must not silently replace this with unrestricted host-width address arithmetic. Exact overflow and address-wrap behavior are not independently established by the supplied evidence. Valid, representable address calculations are the supported precondition; overflowing calculations remain documented_only.

The computed address may alias other state. No non-aliasing guarantee is established. Consequently, this path cannot promise that the flag byte, first word, or displacement storage is unaffected if the supplied displacement directs the byte store into one of those locations.

### Fallback initialization

The fallback path is selected whenever neither equality nor the constant-specific action in the chosen ordering branch applies.

It performs:

1. A read of the 32-bit word at object offset zero.
2. A write of the 32-bit value 0x500 at that same location only if the read value is zero.
3. Return.

If the word is nonzero, it is left unchanged and no explicit object store occurs on this path. Negative nonzero values are preserved just as positive nonzero values are.

The replacement value is decimal 1280. This is a full 32-bit word write, not a byte update or bitwise combination.

## Side effects

The function contains at most one explicit object store on any path:

- One byte store to offset 0x14C.
- One byte store to the displacement-derived address.
- One 32-bit store to offset zero.
- Or no explicit object store.

It does not visibly write the shared comparison value. That statement applies only to its own explicit operations: F-7fba0909c452 may have effects on shared state before the comparisons occur.

No allocation, release, ownership transfer, reference-count update, or pointer retention is visible in F-0fd46b9a392f. The returned pointer is used for the selected accesses and is not explicitly released here. This does not establish whether the dependency returns borrowed, owned, cached, or newly allocated storage.

No explicit error result, diagnostic, retry, rollback, lock, or synchronization operation is present. A null result causes an ordinary return. Invalid non-null storage and invalid derived addresses have no defined recovery path in the supplied evidence.

The flag update is a byte read followed by a byte write; atomic read-modify-write behavior is not established. The fallback zero check and possible replacement are likewise separate operations. Concurrent modification can therefore not be assumed safe.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, assume a valid non-null dependency result, a stable shared comparison value during the comparisons, valid required memory, and no concurrent modification.

1. **Null result.**

3. **Lower-side first flag.**

5. **Already-set flag still selects the byte-store path.**  
   With input and shared value equal and flag byte 0xFF, the resulting byte remains 0xFF. The represented path nevertheless reads and writes that byte; it does not enter fallback initialization.

6. **Upper-side fourth flag.**  
   With input 0x8B9C, shared value 0x8076, and flag byte 0x03, the flag byte becomes 0x0B.

7. **Displaced destination.**  
   With input 0x8078, shared value 0x8076, and displacement 0x20, the byte at object offset 0x16D is replaced with 1. Its prior value is irrelevant. This example assumes the destination is valid.

8. **Valid negative displacement.**  
   Under the same branch conditions, a displacement of −1 directs the write to object offset 0x14C. The entire byte there becomes 1; this is not the flag-preserving operation. This example requires valid address arithmetic and storage.

9. **Special constant on the wrong side.**

10. **Fallback preserves nonzero state.**  
    With input zero, shared value one, and first word −1, fallback reads that word and leaves it unchanged.

11. **Signed ordering affects selection.**  
    With input 0x8074 and shared value −1, signed ordering places the input above the shared value. The result is fallback, not the mask-0x01 path.

12. **Changing shared value prevents a stable-threshold interpretation.**  
    If input 0x8074 is unequal to the value observed for equality, but a later ordering observation equals 0x8074, equality is not reconsidered. The ordering test is false, so the lower-side constant check can select mask 0x01. This illustrates the represented decision sequence; actual concurrent-read semantics are not established.
