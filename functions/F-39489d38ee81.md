# F-39489d38ee81

## Purpose

F-39489d38ee81 queries one bit in a word-addressed bit collection and returns that bit in its original position within the selected word.

The result is **not normalized to a Boolean integer**. An absent bit produces zero. A present bit produces a one-bit mask whose position is determined by the bit index modulo 32. Consequently, a present bit can produce any of 32 values, from 1 through 2,147,483,648 under the 32-bit interpretation.

The supplied static representation establishes a pointer-field read, a selected-word read, and a mask operation. Interpreting the surrounding object as a bitmap descriptor is inferred intent; the function does not inspect a length, capacity, type tag, or ownership field.

The backing array uses four-byte word spacing. Bit indices 0–31 select its first word, indices 32–63 select its second word, and so on.

### Output

- Zero, when the selected bit is clear.
- A single set bit in the selected bit’s position within its backing word, when that bit is set.

The function returns no separate status, bounds result, or error indicator. Zero therefore means “the observed selected bit was clear” only when the memory accesses themselves were valid.

## Behavior

### Selection and result

The word number is the bit index divided by 32, discarding the remainder. The bit position is the remainder after division by 32.

The selected word begins at the backing-array address plus four times the word number. Within that word, position 0 is its least significant bit and position 31 is its most significant bit under the 32-bit interpretation.

The returned value retains only that position from the selected word. All other positions are zero, regardless of the other bits in the word.

For example, bit indices 1 and 33 both use a mask of 2, but they read different backing words. The return value does not retain the absolute bit index or identify the selected word.

### Observable read order

The static representation establishes two logical memory reads:

1. Read the address-bearing field at descriptor byte offset 4.
2. Use the value obtained by that read to locate and read the selected backing word.

The second read depends on the first read’s result. The function does not visibly reread the descriptor field, read preceding array words, or inspect neighboring bits through separate memory accesses.

Index arithmetic is not itself an observable memory operation. No ordering beyond the dependency between the two reads is established. In particular, this is not a specification of volatile access semantics, processor bus transactions, atomicity, or memory barriers.

### Integer widths and limits

Under the 32-bit unsigned-index interpretation:

- The bit position ranges from 0 through 31.
- The word number ranges from 0 through 134,217,727.
- The relative byte offset ranges from 0 through 536,870,908.
- The relative byte offset is always a multiple of four.

The word-number multiplication by four fits within 32 bits and also within the positive range of a signed 32-bit integer. It therefore introduces no width overflow by itself for any 32-bit unsigned index.

Adding that offset to the loaded backing address is a separate issue. A valid relative offset does not establish a valid final address. Similarly, adding four to the descriptor address can encounter an address-space boundary. No guard against either case is visible.

For bit position 31, the intended 32-bit mask has only the high bit set. The supplied representation expresses the mask using a left shift of an integer literal. Its exact language-level signed-shift validity is not established independently of the recovered representation and target behavior. The expected 32-bit bit-selection result and this representation-level caveat must remain distinct.

### Boundary and invalid inputs

There is no special case for a zero descriptor address, a zero backing address, an empty collection, or an index beyond the actual allocation. Such inputs proceed toward the same address-dependent reads. Their outcome is not defined by an explicit error path in this function.

A high-bit-set descriptor value is not visibly rejected merely because the address input is represented with a signed integer type. Whether its bit pattern denotes a usable address depends on the target environment.
