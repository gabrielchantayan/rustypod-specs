## Behavior

### Arithmetic model

The behavioral reductions below use the following explicit model:

- Unsigned words and addresses are 32 bits.
- Unsigned addition, subtraction, and multiplication retain their low 32 bits.
- Halfwords are 16 bits.
- Adding one to a halfword-address value advances its numerical address by two bytes.
- Address equality is equality of the represented 32-bit values.
- Right shifts of unsigned values are logical.

The representation includes pointer/integer conversions and address arithmetic that should not be treated as a portable language-level specification. The reductions are conditional on the numerical model above, not a guarantee about every possible execution environment.

### Initial selector decision

The selector is multiplied by `0x40000000`, retaining 32 bits. The possible results are:

| Selector modulo four | Result |
|---:|---:|
| 0 | `0x00000000` |
| 1 | `0x40000000` |

If the result is nonzero, the represented conditional memory-processing regions are skipped. Execution reaches the final call sequence using the incoming continuation address as its initial call-base address.

If the result is zero, the initial halfword transfer occurs.

### Initial halfword transfer

For a selector divisible by four:

1. The destination address is formed by adding the offset word to the incoming source address, in bytes.
2. A 16-bit value is read from the incoming source address.
3. That value is written as a 16-bit value to the destination address.

The source read precedes the destination write. A zero offset therefore still produces a read followed by a write; it is not visibly optimized into no operation.

The representation also forms an adjusted source-address value:

- Incoming source address plus offset word, minus adjustment word.

This adjusted value participates in later conditions. It is not evidence that the caller receives an updated pointer through an output parameter.

There is no explicit allocation, buffer extent, terminator, or iteration count associated with this transfer. It is a single halfword transfer, not an established variable-length copy.

### Restricted continuation after the transfer

The next conditional chain can advance only when the incoming continuation address is zero.

Under that condition, each chained exclusive-or comparison is entered only after the preceding intermediate result was zero. Consequently, the apparent variable right-shift counts in this chain are zero whenever their operations are reached. Their behavior must not be generalized into an arbitrary-shift interface.

Under the stated arithmetic model, reaching the next memory-effect region requires all of the following:

- The selector is divisible by four.
- The incoming continuation address is zero.
- The stack-origin address is zero.
- The comparison word equals the offset word.
- The adjusted source-address value equals the adjustment word.
- The auxiliary word is zero.
- Twice the offset word is zero modulo \(2^{32}\).

The last condition permits exactly two offset-word values: `0x00000000` and `0x80000000`.

The stack-origin requirement follows from two gates. An earlier gate requires its logical right shift by one to be zero, admitting numerical values zero and one. A later zero-result condition adds twice the offset word; an odd stack-origin value cannot produce zero in that condition. Only zero remains.

These conditions are predicates over incoming values and derived arithmetic, not validation performed on behalf of a caller.

### Restricted second memory effect

- A special-register assignment is represented, with a value formed by multiplying the captured stack-origin address by 64.
- The continuation address is adjusted using that same captured stack-origin address.
- A halfword-derived store is performed.
- An internal halfword-address value is advanced by one element.

Under the reduced conditions, the stack-origin and continuation addresses are both zero. The special-register assignment therefore has numerical value zero, the adjusted continuation address remains zero, and the internal address increment produces numerical value two.

The halfword-derived store has this layout:

- Two source halfword evaluations are represented at address zero.
- One supplies a zero-extended 16-bit destination address.
- The other supplies a value increased by 15.
- The stored result is truncated to 16 bits.

The representation does not establish an order between those two source evaluations. Both are prerequisites to the resulting store. If the location can change between reads, the address-producing value and data-producing value must not be assumed equal.

For stable memory containing halfword value \(h\) at address zero, this operation writes:

- Stored halfword: \((h + 15) \bmod 2^{16}\).

A destination address of zero is not excluded.
