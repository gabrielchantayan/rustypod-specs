# F-be2248636b21

## Purpose

F-be2248636b21 searches 29 fixed-position integer fields in a caller-supplied memory region and returns the zero-based index of the **last matching field**. If no field matches the requested value, it returns the unsigned all-ones sentinel, `0xFFFFFFFF`.

The function examines all 29 fields, including fields after a match. It does not return the first match, count matches, or establish that a match is unique.

This contract describes behavior established by the supplied static source representation. No runtime tests have been performed. The surrounding data structure and its application-level meaning are unknown.

## Interface

The function has two inputs and one unsigned integer result:

| Item | Meaning |
|---|---|
| First input | Integer-encoded base address used to locate the fields. |
| Second input | Integer value compared for equality against each field. |
| Result | Last matching index, from 0 through 28 inclusive, or `0xFFFFFFFF` if no comparison matches. |

The supplied representation uses integer address arithmetic and integer loads. This contract describes the apparent 32-bit model: 32-bit address values, 32-bit comparison fields, and a 32-bit unsigned result. The representation does not independently establish the target ABI; confirmation of those widths remains a documented uncertainty.

Under that model, the memory layout is:

| Property | Value |
|---|---|
| Number of examined fields | 29 |
| First field’s offset from the base | 340 bytes, or `0x154` |

A conventional contiguous backing region would therefore need to extend through offset 567. The narrower actual requirement is that every examined four-byte field be readable and suitably aligned for the target. The function does not inspect the preceding bytes or the gaps to validate them.

The caller must supply memory that remains valid throughout the search. No null check, bounds check, length argument, alignment check, or address-overflow check is present.

## Behavior

### Traversal and matching

The function begins with a candidate result equal to the no-match sentinel. It then visits indices 0 through 28 in ascending order.

At each index, it reads the integer field at that index’s designated address and compares it with the second input. Equality replaces the candidate result with the current index. Inequality leaves the candidate result unchanged.

The function completes the traversal before returning. Consequently:

- With no matches, the result remains `0xFFFFFFFF`.
- With exactly one match, the result is that match’s index.
- With multiple matches, each later match supersedes the earlier candidate.
- A match at index 28 determines the result regardless of matches at earlier indices.

The result is an index, not an address, byte offset, Boolean, or match count. Index zero is a successful result. Consumers must not treat zero as the no-match indication.

### Read order and completion

The represented execution performs 29 field reads in increasing index order. Each examined field is read once by the visible operation. There is no early exit after finding a match.

This matters even when the eventual result appears determined by earlier fields: a valid match near the beginning does not remove the requirement that all later fields be readable. A later invalid address can prevent normal completion.

This ordering describes the supplied source-level representation. It does not establish a hardware memory-ordering guarantee, atomic access guarantee, or synchronization protocol.

### Equality and integer values

Matching uses integer equality. There is no ordering comparison, wildcard, masking, range check, or conversion to text.

Under the 32-bit model, any 32-bit field value can be a search target. Negative signed values are not excluded. In particular, a field containing the signed value −1 can match a search for −1. Such a match returns its index; it does not return the no-match sentinel merely because the field’s bits are all ones.

Successful indices are only 0 through 28, so they cannot collide with the 32-bit sentinel.

### Address arithmetic

The computed displacement ranges from 340 through 564 bytes. The multiplication and displacement addition therefore do not approach a 32-bit arithmetic limit.

Adding that displacement to the supplied base address can nevertheless overflow or produce an invalid address. The function provides no explicit handling for either condition. This contract does not promise wraparound-based access: the supplied representation alone does not resolve the target language, compiler, and address-space rules needed to define that case.

### Mutable memory

If another actor changes fields during execution, the observed sequence need not correspond to one consistent snapshot of the region. Whether such concurrent access is defined or supported depends on the target environment and is not established here.
