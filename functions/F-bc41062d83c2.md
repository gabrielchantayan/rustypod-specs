# F-bc41062d83c2

## Purpose

F-bc41062d83c2 maps an unsigned 32-bit position to a 32-bit primary result, using object-resident controls and, on selected paths, a table of 32-bit words. One path also explicitly stores an arithmetic displacement through a secondary-output argument.

Three behavioral cases are established:

- **Direct selection:** explicitly store the supplied position through the primary-output argument.
- **Indexed selection:** explicitly store either the table word indexed by the position or `0xffffffff` when a dependency-derived bound rejects that position.
- **Terminal selection:** explicitly store a displacement through the secondary-output argument, then obtain a table word selected using a later dependency result and explicitly store it through the primary-output argument.

These names describe the observed operations, not established application semantics. The dependency appears count-like, but its meaning and effects are unavailable. Its separate calls must remain distinct: they can return different values and can affect memory.

The absence of an explicit secondary-output store on direct or indexed selection does **not** guarantee preservation of the storage designated by that argument. A primary-output store can overlap it, and dependency effects are unknown.

## Interface

The function accepts four inputs and has no explicit return value or separate status result.

| Input | Established use |
|---|---|
| Object address | Identifies control fields and a table-reference location. |
| Position | Unsigned 32-bit value used in comparisons, displacement arithmetic, and indexed selection. |
| Primary-output address | Destination of one explicit 32-bit store on every normally completing path. |
| Secondary-output address | Destination of one explicit 32-bit store on terminal selection; no explicit store through this argument on ordinary selection. |

“Explicit store through an argument” identifies an operation performed by this function. It does not count writes by dependencies, overlapping writes through other arguments, or the number of physical memory transactions.

The supplied representation supports a 32-bit integer and address model for these accesses. Exact ABI, byte order, alignment requirements, and invalid-address behavior are not independently established. This layout is not a claim about a portable serialized format.

### Preconditions and output storage

For normal completion, each location actually accessed must support its corresponding read or write:

- The object’s initial control field must be readable.
- The byte control must be readable if ordinary selection is reached.
- The primary-output destination must support a four-byte write.
- The secondary-output destination must support a four-byte write if terminal selection is reached.

There are no explicit null checks, table-allocation checks, or independent capacity checks.

No non-aliasing restriction is established. Outputs may overlap one another, the object, or table storage, provided the accesses remain valid. Such overlap can change later observations.

A caller requiring a preserved secondary value during ordinary selection must ensure both that no overlapping write changes its storage and that dependency effects do not change it. Initializing that storage alone is insufficient.

## Behavior

### Initial path decision

The function first reads the 32-bit control field at offset `0x1c`.

If the field is zero, execution proceeds directly to ordinary selection without an initial dependency call.

If the field is nonzero, the function calls F-8059766980e7 with the address of the object location at offset `0x8c`. Let the returned 32-bit value be interpreted as unsigned for this comparison. The threshold is that value minus one, modulo \(2^{32}\).

- Position strictly below the threshold selects ordinary selection.
- Position equal to or above the threshold selects terminal selection.

A zero dependency result therefore produces threshold `0xffffffff`. It does not produce a zero threshold.

This function does not explicitly reread the control field at `0x1c`. The dependency may nevertheless read or modify it; its implementation is unavailable.

### Ordinary selection

The function reads the byte at offset `0x30`. When an initial dependency call occurred, this byte read follows that call. Any dependency-induced change to the byte can therefore affect the path.

#### Zero byte: direct selection

The function explicitly stores the supplied position through the primary-output argument and completes.

On this path, the function:

- Makes no additional dependency call.
- Does not explicitly read the table-reference contents or a table entry.
- Performs no explicit store through the secondary-output argument.

An initial dependency call may already have occurred. Its effects are not undone.

The storage designated by the secondary-output argument is not guaranteed unchanged. For example, if both output arguments designate the same word, the primary store changes that word to the position.

#### Nonzero byte: indexed selection

The function calls F-8059766980e7 with the address at offset `0x8c`. This is a fresh invocation, even if an initial call already occurred.

The returned value is compared with the position as an unsigned 32-bit quantity.

If the returned value is less than or equal to the position, the function explicitly stores `0xffffffff` through the primary-output argument and completes. This branch performs no explicit read of the table-reference contents or a table entry.

Otherwise, the function reads the table reference from offset `0x8c`, reads the 32-bit table word selected by the supplied position at a four-byte stride, and explicitly stores that word through the primary-output argument.

There is no index adjustment on this successful indexed path. The dependency result provides the only visible bound check; the function does not verify that the allocation contains that many entries.

Throughout indexed selection, the function performs no explicit store through the secondary-output argument. Its designated storage may still change through dependency effects or an overlapping primary store.

### Terminal selection

Terminal selection is reached only after a nonzero initial control field and an initial dependency result whose unsigned threshold is no greater than the position.

The byte at offset `0x30` is not explicitly read on this path.

After the initial decision, the following order is established:

1. A second invocation of F-8059766980e7 receives the address at offset `0x8c`.
2. The function explicitly stores the displacement through the secondary-output argument.
3. A third invocation of F-8059766980e7 receives that same object-relative address.
4. The function reads the table reference from offset `0x8c`.
5. The function reads the selected 32-bit table word.
6. The function explicitly stores that word through the primary-output argument.

The displacement bit pattern is:

\[
(\text{position} - \text{second dependency result} + 1)
\bmod 2^{32}.
\]

The destination is represented as a signed integer destination, but the expression producing the displacement uses unsigned 32-bit arithmetic. The contract therefore describes the stored 32-bit pattern rather than promising a portable signed numerical interpretation for every value. No clamping or rejection is visible.

The table selection uses the **third** dependency result, decremented by one, at a four-byte stride. It does not reuse either earlier result.

Thus the three calls have independent roles:

- The first determines the path.
- The second determines the displacement.
- The third determines the table selection.

No consistency check links their results.

The secondary store precedes both the third dependency call and the explicit table-reference read. If that store overlaps the table-reference location, object controls, table contents, or dependency-visible state, those later operations can observe the modified storage.

### Arithmetic and boundary limits

The initial threshold and displacement expressions use unsigned 32-bit arithmetic, including wraparound.

For ordinary indexed selection, multiplying the unsigned position by four uses unsigned 32-bit arithmetic in the supplied representation. The table-base addition participates in that unsigned expression. No overflow or address-wrap check is visible. A successful logical bound comparison does not independently establish a valid resulting address.

Terminal selection differs: its decremented dependency result, multiplication by four, and addition to the table-base representation are expressed using signed integer arithmetic. The source does not establish a portable result where those operations overflow their signed range. A behavioral contract must not silently replace all terminal address arithmetic with guaranteed unsigned wraparound.

A zero third result is not treated as an empty-table condition or converted into the sentinel. Where the signed arithmetic and address are valid, it selects one word before the table base. Whether such storage is readable is not established. Extreme returned values can also leave the safely defined signed-arithmetic range.

No pointer validation, bounds recovery, or explicit error handling follows these calculations.

## Side effects

On every normally completing path, this function performs exactly one explicit 32-bit store through the primary-output argument.

On terminal selection, it additionally performs exactly one explicit 32-bit store through the secondary-output argument. On ordinary selection, it performs zero explicit stores through that argument.

These counts do not imply that either designated storage region changes only that many times:

- A store through one output can overlap the other.
- An output can overlap object or table storage.
- Dependency calls may modify either output’s storage through unknown references.
- Dependency calls may modify globals or other state.

If the output addresses are identical:

- During direct selection, the shared word receives the position.
- During indexed selection, the shared word receives the selected table value or sentinel.
- During successful terminal selection, the shared word first receives the displacement and later receives the selected table value. The third dependency call occurs between those explicit stores.

For partially overlapping outputs, final byte contents depend on overlap and byte order. Byte order is not established here.

A selected table word is explicitly read before the primary store. A primary destination overlapping that word does not retroactively alter the value already read, although the store changes the table storage afterward.

There is no explicit allocation, release, ownership transfer, rollback, or synchronization operation in this function. No corresponding absence is guaranteed for F-8059766980e7. If an operation fails or does not return, normal completion and its final-output guarantees do not apply; a terminal displacement may already have been stored.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless an example states otherwise, assume valid storage, non-overlapping outputs, no relevant dependency mutations, and arithmetic within defined ranges.

1. **Direct selection without a dependency call.**  
   Both controls are zero and the position is 7. The function makes no dependency call, performs no explicit table read, and explicitly stores 7 through the primary-output argument. It performs no explicit secondary-output store. Under the stated isolation assumptions, the secondary storage retains its prior contents.

2. **Direct selection with identical outputs.**  
   Both controls are zero, the position is 7, and both output arguments designate the same valid word. The shared word becomes 7. There is still no explicit store through the secondary-output argument; its designated storage changes through the primary store.

3. **Indexed success.**  
   The initial control is zero, the ordinary-control byte is nonzero, the dependency returns 4, and the position is 2. The primary output receives the word eight bytes after the table base. There is one dependency call and no explicit secondary-output store.

4. **Indexed equality rejects the position.**  
   Under the same controls, a returned bound of 4 and position 4 produce primary value `0xffffffff`. The function does not explicitly read the table reference or a table entry. If both outputs designate the same word, that shared word also becomes `0xffffffff`.

5. **Ordinary selection after an initial call.**  
   The initial control is nonzero, the first result is 5, and the position is 3. Since 3 is below 4, ordinary selection follows. If the ordinary-control byte is zero when read, the primary result is 3 and there is no second call.

6. **Threshold equality enters terminal selection.**  
   The initial control is nonzero, the position is 4, and all three results are 5. The displacement is zero and the primary result is table entry 4. The ordinary-control byte is not explicitly read.

7. **Independent terminal results.**  
   With nonzero initial control, position 9, and successive results 5, 7, and 3, terminal selection occurs. The displacement is 3 and the primary result is table entry 2.

8. **Zero initial result.**  
   A nonzero initial control and first result zero produce threshold `0xffffffff`. Position zero enters ordinary selection; position `0xffffffff` enters terminal selection. Later operations still require valid arithmetic and storage.

9. **Displacement wraparound.**  
   With nonzero initial control, position zero, and successive results 1, 3, and 1, terminal selection stores displacement pattern `0xfffffffe` and obtains the primary result from table entry zero.

10. **Identical outputs during terminal selection.**  
    Both outputs designate the same valid word. The function stores the displacement before the third call and the selected table value afterward. On normal completion, the shared word contains the selected table value. Its intermediate contents are available to the third dependency call if that call can access the word.
