# F-a983d426a0e7

## Purpose

F-a983d426a0e7 updates request-related fields in a caller-supplied object, conditionally inserts the object’s embedded node into a singly linked chain, and conditionally invokes an indirect dispatch target.

The established contract concerns memory accesses, dependency-call order, branch conditions, and chain-link updates. It does not establish a complete scheduling API, an ownership protocol, or synchronization guarantees.

**Inferred intent:** the nonzero-interval path resembles scheduling an embedded timer node. A 32-bit interval-like value is multiplied by 1,000 and added to a value obtained from a dependency. Neither the units nor the meaning of that dependency’s result is established.

## Behavior

### 1. Entry updates and guard

1. The request value is stored as a 32-bit word at object offset `0x154`.
2. The byte value 6 is stored at object offset `0x158`.

It then calls F-936a8728139d twice. The first call explicitly receives the embedded-node address, object offset `0x128`. No explicit arguments are recoverable for the second call. The second call must not be specified as receiving the same argument merely because it invokes the same dependency.

After both calls return, the function reads the initialization-value source and copies that value to object offset `0x148`. It then reads the 32-bit guard at offset `0x144`.

If the guard is nonzero, the function returns immediately. No subsequent entry-resource, interval, insertion, exit-resource, or dispatch processing occurs.

A nonzero guard therefore does not make the function a no-op. The request write, byte write, both dependency calls, and initialization-value write have already occurred. The guard value used for this decision is the value read after those operations, not necessarily the value present at function entry.

### 2. Entry-resource call and interval selection

If the guard is zero, the function reads the entry-slot-address source and passes the resulting slot address to F-338d16f9ce72. No direct dereference of that slot is shown at this point.

The function next calls F-add44d4e9aaa with the embedded-node address. After this call returns, it reads the 32-bit interval-like field at object offset `0x12C`.

If the interval is zero, the function skips its deadline calculation, insertion-value write, chain traversal, and insertion writes. It proceeds to F-5bcae2eff9a7 and the final dispatch decision.

If the interval is nonzero, the function follows the insertion path. This test does not reject negative signed values.

The interval is captured before the value-producing dependency described below is called. No second read of the interval field is shown for the calculation. A dependency changing that field does not, by itself, replace the captured arithmetic operand.

### 3. Deadline-like calculation and chain setup

For a nonzero interval, the function invokes a dependency whose opaque ID is unavailable in the supplied mapping. The visible call has no explicit arguments and produces a 32-bit integer-like result.

1. Writes the calculated deadline-like value to object offset `0x130`.
2. Reads the insertion-value source and copies its 32-bit value to object offset `0x140`.

If either operation exceeds that range, portable signed-arithmetic behavior and an intentional wraparound policy are not established; those cases remain **documented_only**.

The head-slot address is obtained before the deadline and insertion-value writes. The head pointer itself is read afterward. Later changes to the chain-head-location source do not constitute a shown reload of the retained address.

### 4. Traversal and stopping condition

Traversal starts at the loaded head pointer, with no predecessor.

For each non-null current node, F-0d70d6f9010c receives:

1. An address eight bytes beyond the current node’s start.
2. The address of the new object’s field at offset `0x130`.
3. Auxiliary input A.
4. Auxiliary input B.
5. The additional value of unresolved origin.

A nonzero comparison result stops traversal at the current node.

A zero comparison result continues traversal. Only after that comparison returns does the function read the current node’s first 32-bit word as the next-node address. The current node becomes the predecessor for the next iteration.

Thus a comparison dependency that modifies the current node’s next link can affect the next node visited. No pre-call snapshot of that link is established.

Traversal ends either at a null pointer or at the first node whose comparison returns nonzero. No comparison is called for a null current pointer.

The function does not establish ascending order, descending order, equality handling, or stable insertion among equal keys. Those properties require the comparator’s contract and valid preexisting chain invariants.

### 5. Insertion and publication order

The new node is inserted immediately before the stopping node, or after the last visited node if traversal reaches null.

The direct writes occur in this order:

1. The embedded-node address is written either to the retained head slot, if there is no predecessor, or to the predecessor’s first 32-bit word.
2. Object offset `0x144` is written with 1.
3. The stopping-node address is written to the new node’s first word at offset `0x128`.

For an empty chain, the stopping-node address is null. For a comparison that stops traversal, it is the address of the node whose comparison returned nonzero.

Publication of the embedded node precedes writing its final next link. Setting the guard also precedes that next-link write. This order is not evidence of safe lock-free publication. Any protection against concurrent or reentrant observation must come from contracts not established here.

### 6. Exit-resource call and conditional dispatch

Both the zero-interval path and the completed-insertion path read the exit-resource source and call F-5bcae2eff9a7 with that value.

After this call returns, the final decision uses the following read order:

1. The entry-slot-address source is read again to obtain a slot address.
2. That slot address is **unconditionally dereferenced** to load a 32-bit candidate pointer.
3. If the candidate pointer is null, dispatch is skipped.
4. If the candidate pointer is non-null, its first 32-bit word is read.
5. If that word is zero, dispatch is skipped.
6. Otherwise, the target supplied by the separate dispatch-target source is invoked.

The slot address is not null-checked. A null or unreadable slot address does not safely suppress dispatch; it makes the unconditional slot read invalid.

Clearing the pointer stored in a valid slot does suppress dispatch. Changing the entry-slot-address source to another valid slot instead redirects which stored pointer is inspected.

The final slot address is freshly obtained after F-5bcae2eff9a7. It need not equal the slot address passed earlier to F-338d16f9ce72. Likewise, the pointer stored in the slot can change independently of the slot address.

The candidate’s first word is a condition, not the established dispatch target. The target comes from a separate visible source. No explicit dispatch arguments or usable dispatch return value are established.

- Byte value 6 at `0x158`.

These are access-level guarantees, not unconditional final-state guarantees. Dependencies may modify accessible storage, and unspecified aliasing may cause apparently distinct locations to overlap.

## Acceptance examples

These examples require valid reached storage, normally returning dependencies, and no unspecified interference beyond the effects stated.

1. **Nonzero guard after initialization.**  
   If the guard is nonzero when checked, the request and byte writes, both F-936a8728139d calls, and the initialization-value write have occurred. F-338d16f9ce72 and all later processing are skipped.

2. **Zero interval after F-add44d4e9aaa.**  
   With a zero guard and an interval read of zero, the entry-resource and node dependencies run, but the function performs none of its insertion-related writes. It still calls F-5bcae2eff9a7 and performs the final unconditional slot read before deciding whether to dispatch.

3. **Empty chain with representable arithmetic.**  
   If the interval is 2, the value-producing dependency returns 100, and the head slot contains null, offset `0x130` receives 2,100. No comparison occurs. The head slot receives the embedded-node address, the guard receives 1, and the new node’s link receives null, in that order.

4. **Traversal stops at the head.**  
   If the first comparison returns nonzero, the head slot is overwritten with the new node’s address. After the guard write, the new node’s link receives the stopping node’s address.

5. **A comparison changes the next link.**  
   If a comparison returns zero after changing the current node’s link to a different valid node, traversal follows the changed link. It does not use a link value sampled before the comparison.

6. **Clearing the pointed-to slot suppresses dispatch.**  
   If F-5bcae2eff9a7 leaves the entry-slot-address source identifying a valid slot but clears the pointer stored in that slot, the function reloads the slot address, reads the null pointer from it, and skips dispatch without reading a candidate object.

7. **Changing the slot address redirects the final check.**  
   If F-5bcae2eff9a7 changes the source from one valid slot address to another, the final check reads the second slot. If that slot contains a valid non-null pointer whose first word is nonzero, dispatch occurs. Changing the source to null instead produces an invalid unconditional dereference, not safe suppression.

8. **Negative interval.**  
   An interval of −1 is nonzero and takes the insertion path. With a returned arithmetic value of 5,000, the computed field receives 4,000; both arithmetic operations fit signed 32-bit range.
