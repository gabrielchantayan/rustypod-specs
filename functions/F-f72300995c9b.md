# F-f72300995c9b

## Purpose

F-f72300995c9b initializes two locations in caller-supplied storage using a selected descriptor, then invokes two dependencies in sequence. When its mode argument is nonzero, it selects a descriptor through a global reference and invokes a third dependency before returning an adjusted result.

The established behavior is a sequence of memory writes, dependency calls, and integer-address adjustments. Its broader role as an object initializer or constructor is inferred from the layout and call pattern, not established by the supplied evidence. In particular, the evidence does not establish the meaning of the descriptor’s first word, the ownership of any referenced storage, or the relationship between the returned value and the destination.

## Interface

The function accepts three arguments:

| Argument | Representation | Role |
|---|---|---|
| Destination | Address of storage accessed in four-byte integer units | Receives the initial descriptor word and a second descriptor-derived write; its address plus four bytes is passed to a dependency. |
| Mode | 32-bit integer | Zero selects the supplied descriptor and omits the final dependency. Every nonzero value selects the global descriptor and enables the final dependency. |
| Supplied descriptor | Address of a descriptor accessed in four-byte integer units | Used only when mode is zero. Its address is replaced by the global descriptor address otherwise. |

The return value is a 32-bit integer. It is obtained from dependency results, with different adjustment rules for zero and nonzero mode. Although those results participate in address-like arithmetic, the function does not establish that its return value is a valid pointer.

The visible layout uses four-byte words and byte-addressed offsets:

- Descriptor offset **0** contains a word copied to destination offset **0**.
- That same word is interpreted as an address for a metadata read at **12 bytes before** the address.
- The metadata word supplies a byte displacement relative to the destination.
- Descriptor offset **12** supplies the value written at that displaced destination address.
- Descriptor offset **4** is passed as an address to a dependency; this function does not directly read the word there.
- Destination offset **4** is passed as an address to another dependency.

This contract uses 32-bit integers and the 32-bit address interpretation exhibited by the supplied representation. It does not establish portability to a wider-pointer environment, byte order, or support for unaligned accesses.

## Behavior

### Descriptor selection

Mode is interpreted only as zero versus nonzero.

- With zero mode, the supplied descriptor is selected.
- With nonzero mode, the descriptor address is obtained from a global reference, replacing the supplied descriptor address.

There is no visible null check or fallback for the selected descriptor. In nonzero mode, this function does not dereference the supplied descriptor. That does not eliminate requirements on the globally selected descriptor.

The selected descriptor address is retained for subsequent work. The function does not visibly reread the global selector after the dependencies execute.

### Initial writes

The function first reads the four-byte word at selected-descriptor offset 0. It then writes that captured word to destination offset 0.

The captured word has a second role: it identifies the address whose location 12 bytes earlier contains a four-byte displacement. The function uses that displacement to identify a second destination location, measured in **bytes**, not four-byte elements.

The value for the second write comes from selected-descriptor offset 12. That value is written to the destination plus the metadata displacement.

The first write precedes the reads needed to complete the second write. Consequently, aliasing can affect the metadata or value observed during the second write:

- The first destination write may alter selected-descriptor offset 12 if those locations overlap.
- It may alter the metadata location if that location overlaps the first destination word.
- The captured first descriptor word remains the basis for locating metadata, even if the first write changes the descriptor’s stored first word.

The supplied evidence does not establish the relative evaluation order between the metadata read and the read at selected-descriptor offset 12. Both provide information required by the second write; neither should be assigned an unsupported priority over the other.

No requirement for a positive or nonzero displacement is visible. A zero displacement makes the second write target the first destination word. A negative displacement targets storage before the destination, provided the address calculation and access are valid.

### Dependency sequence

After the two writes, the function calls **F-d22dfb665fd5** with the destination address plus **4 bytes**.

Its integer result is reduced by **4**. The adjusted value becomes the first argument to **F-9dc96701a823**. That call receives three arguments, in order:

1. The result of F-d22dfb665fd5 minus 4.
2. Integer zero.
3. The selected descriptor address plus 4 bytes.

The second argument is zero regardless of the mode supplied to F-f72300995c9b.

If mode is zero, the integer returned by F-9dc96701a823 is returned unchanged.

If mode is nonzero, that integer is increased by **52 bytes** and passed as the sole argument to **F-1de9cff4fc92**. The integer returned by F-1de9cff4fc92 is then reduced by **52**, and that adjusted integer is returned.

The final adjustment is applied to the result of F-1de9cff4fc92, not automatically to its argument. Cancellation of the addition and subtraction is justified only if that dependency returns the value it received, which is not established here.

## Side effects

The function directly performs two four-byte writes before invoking any dependency:

1. The captured first descriptor word is written at the destination.
2. The word read from selected-descriptor offset 12 is written at the metadata-selected destination location.

These writes may overlap each other, the descriptor, metadata, or other accessible storage. No nonaliasing condition is stated in the supplied evidence. The validity of a particular overlap remains subject to memory-access and execution-model requirements.

In nonzero mode, the function also reads a global descriptor reference. No direct write to that global reference is visible.

The dependencies may perform additional reads, writes, allocation, release, or global-state changes. Their effects are unknown here. In particular:

- The initial destination contents are not guaranteed to survive the dependency calls.
- The selected descriptor’s contents are not guaranteed to remain unchanged.
- Dependencies are not assumed to preserve the global selector.

The visible function neither allocates nor releases storage directly. Its pointer-like arguments and results do not by themselves establish borrowing, ownership, lifetime extension, or a requirement to release the returned value.

## Acceptance examples

These examples are conditional static acceptance cases, not runtime observations. Unless stated otherwise, all addresses, alignments, accesses, and integer calculations are valid, and every dependency returns normally.

### Zero mode: supplied descriptor and two dependencies

Suppose:

- Destination address is 0x1000.
- Mode is zero.
- The supplied descriptor’s first word is 0x4000.
- The metadata word at 0x3FF4 contains displacement 32.
- The descriptor word at offset 12 contains 0x12345678.
- The relevant locations do not overlap.

1. Write 0x4000 at address 0x1000.
2. Write 0x12345678 at address 0x1020.

### Nonzero mode: global selection and adjusted return

Suppose mode is −1 and the global reference selects a valid descriptor. The negative mode value takes the same branch as any other nonzero mode value.

The supplied descriptor is not used for the direct reads or the descriptor-derived dependency argument. The initial writes use the globally selected descriptor, and F-9dc96701a823 receives that descriptor’s address plus 4 as its third argument.

If F-9dc96701a823 returns 0x5000, F-1de9cff4fc92 receives 0x5034. If that final dependency returns 0x6034, the function returns 0x6000, not 0x5000.

### Zero displacement: the second write replaces the first

Suppose the metadata displacement is zero and the descriptor and metadata do not overlap the destination.

The first write installs the captured first descriptor word at the destination. The second write then replaces that same four-byte location with the value read from descriptor offset 12.

Both writes occur before F-d22dfb665fd5 is invoked. The function does not preserve the first written value at that location.

### Aliasing affects the second value

Suppose selected-descriptor offset 12 is exactly the destination address, while the descriptor’s first-word location and metadata location remain distinct.

The first write changes selected-descriptor offset 12. The subsequent read from that descriptor offset therefore observes the newly written first descriptor word, absent an intervening external modification. The second write uses that value rather than the value that occupied descriptor offset 12 on entry.

This case demonstrates why the function must not be modeled as taking a complete descriptor snapshot before either write.

### No local null-result handling

If F-d22dfb665fd5 returns zero, the function still applies the subtraction by 4 and proceeds toward F-9dc96701a823 with the resulting value, provided execution remains defined.

There is no local branch converting that result into an early return or a reported failure.
