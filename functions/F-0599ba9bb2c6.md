# F-0599ba9bb2c6

## Purpose

The supplied static representation establishes the access and call sequence, but not an application-level purpose. In particular, it does not establish that the accessed addresses are ordinary objects, hardware registers, allocated storage, or encoded references. Terms such as “initialize,” “release,” and “validate” would imply semantics not supported by the evidence.

This contract describes the visible operations conditionally: execution reaches each operation only if all preceding calls return and all preceding accesses complete. No runtime tests have been performed.

## Behavior

### Call conventions used in this description

An **advance group** means four consecutive indirect calls with no explicit arguments in the supplied representation. When a result is named, it is the fourth call’s result. Earlier results in that group are not explicitly consumed by this body.

“No explicit arguments” does not establish that a callee has no machine-state inputs. Calls may read or modify globals, memory, or other state.

Dependency IDs below identify call roles only. Repeated roles do not establish identical callees, and separate roles do not establish distinct callees.

### 1. Entry exchange and first word transfers

Each iteration starts with this call sequence:

1. Invoke **F-U01** with the current first and second inputs.
2. Invoke **F-U02**, receiving a two-word result.
3. Invoke **F-U03** with that result’s low word followed by its high word.
4. Make one call without explicit arguments.
5. Obtain a 32-bit result **A** from another call.

Then read the byte at the entry address basis plus 1 and write the entry byte to the selected destination. The read precedes the write.

Next:

- Invoke **F-U04** with `A << 2`.
- Execute an advance group, obtaining **B**.
- Write `B << 2` to `fourth input × 4096 + 20`.
- Invoke **F-U05** with four arguments, in order: `fourth input × 1024`, the same value again, the additional entry-state value shifted left 12, and `B << 2`.
- Execute an advance group, obtaining **C**.
- Write the previously calculated `B << 2` to `C × 4 + 20`.
- Invoke **F-U04** with `C × 4`.

The two word writes have independently calculated destinations. No equality or non-aliasing between them is established.

### 2. Repeated value propagation and direct byte clearing

| Advance group gives **G** | `word[G × 4 + 20] ← F × 4` | `G × 4` |

After the call with `H << 2`:

- Obtain a one-word result through **F-U06**.
- Pass it to **F-U07**.

`((H & 0x3fffffff) >> 20) + 20`

Call the captured word **T**. The read follows the write based on **K**; aliasing can therefore affect **T**.

## Acceptance examples

These examples are conditional static consequences, not executed tests.

1. **Initial selector.** If the entry selector byte is 5 and the entry byte is `0xab`, the first explicit byte write targets address 22 with value `0xab`, after the opening five calls.

2. **Byte truncation.** If **N** is `0x43`, its shifted value is `0x10c`. The phase-3 byte write stores `0x0c`; the following explicit call receives `0x10c`.

3. **Changing selector.** If one read of `B(Q + 1)` yields 3 and a later read yields 9, their selected byte destinations are 20 and 26. Reusing the first selector would violate the visible read sequence.

4. **Retained selector.** If **S** is 9, the subsequent word destination is 29 even if intervening calls change `B(Q + 1)`.

5. **Table boundary.** For **H** equal to zero, the calculated word read is at address 20. For **H** equal to `0x3fffffff`, it is at address 1043. Whether those accesses succeed is an environmental prerequisite.

6. **Single-bit word value.** If **G** is even, `G << 31` is zero. If **G** is odd, it is `0x80000000`.

7. **Non-returning dependency.** If a call never returns, no later operation in the iteration is required to occur. Earlier completed writes remain part of the observable prefix.

8. **Iteration continuity.** If all calls and accesses complete, a second iteration begins with the derived inputs and a zero entry byte; no normal return is permitted by the visible control flow.
