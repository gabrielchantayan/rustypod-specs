# F-841460e30780

## Purpose

F-841460e30780 dispatches an input record through an ordered sequence of receiver-associated operations:

1. A conditional call to F-4fd087f2325e.
2. An optional preliminary indirect handler.
3. Exactly one of two primary indirect handlers, if execution reaches primary dispatch.
4. An optional final indirect handler, if primary dispatch returns zero.

A nonzero result from any indirect handler terminates the routine and is returned unchanged. The result of F-4fd087f2325e does not control continuation.

These are dispatch and return-value rules, not established application semantics. Nonzero may mean successful handling, failure, or another status; the supplied evidence does not distinguish them.

Later stages read their decision inputs again. An earlier call can therefore change the conditions, dispatch-table address, or target used by a later stage. The routine does not establish a single immutable snapshot of the receiver or input.

## Interface

### Arguments and layout

The routine receives:

- A **receiver address**, used to locate a dispatch-table address and receiver fields.
- An **input-record address**, used to locate a discriminator and a discriminator-dependent field.

The supplied representation supports the following apparent four-byte integer and address layout:

| Storage | Byte offset | Use |
|---|---:|---|
| Receiver | 0 | Dispatch-table address |
| Receiver | 0x50 | Integer compared during final dispatch |
| Receiver | 0x108 | Integer converted to plain character for F-4fd087f2325e |
| Input record | 4 | Main discriminator |
| Input record | 8 | Nested-record address or final comparison integer |
| Nested record | 4 | Secondary discriminator |

The receiver offsets 0x50 and 0x108 correspond to integer-element indices 0x14 and 0x42 under four-byte element spacing. They are not element indices to apply using an arbitrary host integer width.

The input field at offset 8 has distinct interpretations:

- When the currently read main discriminator is 0x16, it supplies a nested-record address.
- When the final-stage main discriminator is 0x0f, it supplies an integer comparison value.

No use of the input record’s first four bytes is established.

### Widths and conversion

The layout indicates an apparent 32-bit integer and address model. A wider host implementation must not silently change field sizes, receiver offsets, or dispatch-table byte offsets. Exact ABI details and byte order remain documented_only.

Before calling F-4fd087f2325e, the routine converts the integer read from receiver offset 0x108 to **plain character**. Conversion follows the target’s plain-character rules.

The evidence does not establish:

- The character width.
- Whether plain character is signed or unsigned.
- The target’s behavior for a value outside the destination type’s representable range.
- How the converted argument is represented or extended at the call boundary.

For a value representable in the target’s plain-character type, the conversion preserves that value. For an out-of-range value, behavior remains documented_only.

An eight-bit character width alone does **not** establish low-eight-bit retention when the destination is signed. Low-byte truncation is an acceptable description only conditional on a target whose conversion rules implement it. In particular, conversion of 0x180 must not unconditionally be specified as producing the byte pattern 0x80.

### Return value

The routine returns an integer:

- Any nonzero indirect-handler result is returned immediately and unchanged.
- If all invoked indirect handlers return zero, the routine returns zero.
- F-4fd087f2325e contributes no inspected result to this decision.

Negative indirect-handler results are nonzero and take the same immediate-return path as positive nonzero results. There is no demonstrated Boolean normalization or error-code translation.

### Preconditions

Every executed read requires accessible storage of the indicated width. Every invoked indirect target must be callable with the receiver and original input-record address and must supply an integer result if it returns normally.

There are no explicit checks for:

- Null or invalid receiver and input addresses.
- Missing or invalid nested records.
- Invalid dispatch-table addresses.
- Missing or invalid indirect targets.
- Storage invalidated by an earlier dependency.

Accessibility is path-dependent. A nested record is not accessed when the discriminator read for that stage differs from 0x16. When a later stage again reads 0x16, that stage requires the newly obtained nested address to be valid, regardless of any earlier address’s validity.

No recoverable error result is established for a violated precondition.

## Behavior

### Initial conditional call

The routine first reads the input discriminator at offset 4.

If that value differs from 0x16, this stage does not access the nested record or the receiver’s character-source field and does not call F-4fd087f2325e.

If the discriminator equals 0x16, the routine:

- Reads the nested-record address from input offset 8.
- Reads the secondary discriminator at nested offset 4.
- Adds negative 0x2500 to that secondary value.
- Tests whether the arithmetic result equals 2.

For arithmetic within the ordinary representable range, secondary value 0x2502 satisfies this condition. The supplied representation does not establish exceptional signed-arithmetic behavior for all possible input bit patterns; no wrapping or unbounded-integer rule is imposed here.

When the condition succeeds, the routine reads the integer at receiver offset 0x108, converts it to plain character under the target rules, and calls F-4fd087f2325e with:

1. The receiver address.
2. The converted character value.

If the call returns normally, dispatch continues without examining its result.

When the initial discriminator is not 0x16, the condition does not depend on any preexisting secondary-value temporary. No additional caller-supplied value is required for that skipped branch.

### Optional preliminary dispatch

After the initial stage, including after F-4fd087f2325e if called, the routine reads the input discriminator again.

If the fresh discriminator equals 0x16, it reads the nested-record address again and then reads that record’s secondary discriminator. The preliminary handler is eligible only if this fresh secondary discriminator equals zero.

When eligible, the routine reads the receiver’s dispatch-table address, obtains the target at dispatch-table byte offset 0x124, and calls it with the receiver and original input-record address.

- A nonzero result is returned immediately.
- A zero result permits primary dispatch.
- An ineligible preliminary handler is not called.

This stage does not reuse the first stage’s discriminator or secondary value. For example, F-4fd087f2325e may change a secondary value from 0x2502 to zero, making preliminary dispatch eligible.

### Primary dispatch

Unless preliminary dispatch has already returned a nonzero result, the routine reads the input discriminator again.

If that discriminator equals 0x16, it reads the nested-record address and then the nested secondary discriminator. Selection is:

| Fresh condition | Selected dispatch-table byte offset |
|---|---:|
| Main discriminator equals 0x16 and secondary discriminator equals 0x2a | 0x10c |
| Any other condition | 0x110 |

The routine obtains the receiver’s dispatch-table address for this dispatch, reads the selected target, and calls it with the receiver and original input-record address.

Exactly one primary target is invoked on normal execution reaching this stage. Returning zero does not cause the alternate primary target to be tried.

- A nonzero primary result is returned immediately and unchanged.
- A zero primary result permits the final stage.

A preliminary handler that returns zero can affect both primary selection and target resolution by changing the input record, nested record, receiver, or dispatch table.

### Final conditional dispatch

After a zero primary result, the routine reads the input discriminator again.

If it differs from 0x0f, the routine returns zero without reading either final comparison field for this stage.

If it equals 0x0f, the routine reads, in the represented order:

1. The integer at input offset 8.
2. The integer at receiver offset 0x50.

Unequal values produce a zero routine result without a final-handler call.

Equal values cause the routine to read the receiver’s dispatch-table address, obtain the target at byte offset 0xe0, and call it with the receiver and original input-record address.

- A nonzero final-handler result is returned unchanged.
- A zero final-handler result produces a zero routine result.

The primary handler can enable or disable this final call by changing the discriminator or comparison fields before returning zero.

## Side effects

### Direct reads and writes

The visible routine performs field reads, target reads, conversions, arithmetic, comparisons, and calls. It contains no explicit write to receiver, input-record, nested-record, dispatch-table, or global storage.

That absence of explicit stores does not establish purity. Invoked dependencies may change any state their implementations can reach.

The access ordering described above is the ordering expressed by the supplied representation. It does not establish volatile-access semantics, atomicity, synchronization, or machine-level memory-order guarantees under concurrent mutation.

### Ownership and lifetime

The routine itself shows no allocation, release, reference-count adjustment, ownership transfer, or record copy.

Every indirect handler receives the same receiver and original input-record addresses. F-4fd087f2325e receives the receiver and a converted scalar; it does not receive the input-record address as an explicit argument.

No dependency is assumed to:

- Preserve globals or receiver fields.
- Preserve the dispatch-table address or its entries.
- Preserve the input or nested record.
- Avoid retaining addresses.
- Avoid releasing storage.
- Return normally.

If a dependency returns and later execution accesses storage it invalidated, the routine has no validation or repair step. Continued validity of subsequently accessed storage is a precondition for that continued execution, not a guarantee supplied by the dependency contracts.

### Call ordering and bounds

The maximum visible call sequence in one normal invocation is:

1. F-4fd087f2325e.
2. The preliminary target at offset 0x124.
3. One primary target at offset 0x10c or 0x110.
4. The final target at offset 0xe0.

Each stage occurs at most once. There is no visible loop or retry.

All four calls require intervening state changes: unchanged secondary state cannot satisfy both the initial 0x2502 condition and the preliminary zero condition. Later changes must also make final dispatch eligible. Every indirect handler before the final call must return zero.

## Acceptance examples

These examples are conditional deductions, not observed executions. Unless explicitly stated otherwise, assume accessible storage, callable targets, normal returns, and preservation of relevant state.

1. **Default dispatch without nested access.**  
   A main discriminator other than 0x16 or 0x0f invokes only primary offset 0x110. A zero handler result produces a zero routine result. No nested record is accessed.

2. **Special primary selection and signed result.**  
   Main discriminator 0x16 and secondary discriminator 0x2a select primary offset 0x10c. A result of −7 is returned unchanged; final dispatch is not attempted.

3. **Preliminary early return.**  
   Main discriminator 0x16 and secondary discriminator zero invoke offset 0x124. A result of 9 ends the routine before primary dispatch.

4. **Preliminary fallthrough.**  
   With the same discriminators, a zero preliminary result without mutation leads to primary offset 0x110, not 0x10c.

5. **Initial call does not consume dispatch.**  
   Main discriminator 0x16 and secondary discriminator 0x2502 invoke F-4fd087f2325e. With unchanged state, preliminary dispatch is skipped and primary offset 0x110 is selected.

6. **Representable character conversion.**  
   If receiver offset 0x108 contains 65 and the target plain-character type represents 65, an eligible F-4fd087f2325e call receives converted value 65.

7. **Out-of-range character conversion remains conditional.**  
   If that receiver field contains 0x180, the supplied evidence alone does not determine the converted value. A byte pattern of 0x80 follows only on a target with eight-bit characters whose conversion rules perform low-byte truncation. Character width alone is insufficient.

8. **Earlier mutation changes later selection.**  
   A preliminary handler changes the secondary discriminator from zero to 0x2a and returns zero. Primary dispatch then selects offset 0x10c. If it also replaces the dispatch-table address, primary target lookup uses the newly read address.

9. **Final match and mismatch.**  
   For main discriminator 0x0f, primary offset 0x110 runs first. After a zero result, unchanged equal comparison fields cause offset 0xe0 to run; unequal fields instead produce zero without that call.

10. **Primary mutation enables final dispatch.**  
    A primary handler changes the main discriminator to 0x0f, establishes equal comparison fields, and returns zero. Final dispatch is then eligible regardless of the discriminator observed before primary dispatch.

11. **Full ordered sequence.**  
    Initial secondary value 0x2502 invokes F-4fd087f2325e, which changes it to zero. The preliminary handler returns zero. The selected primary handler changes the input to discriminator 0x0f with matching comparison values and returns zero. The final handler then runs. Its result determines the routine result.
