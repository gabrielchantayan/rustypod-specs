# F-13e8b3aa517a

## Purpose

F-13e8b3aa517a destructively reorganizes reachable record links into successor links while updating a caller-supplied head slot. For each nonzero current record, it recursively processes the record’s offset-12 branch, prepends the current record to the current head, and continues using the value read from offset 8 after recursion returns.

Under ordinary finite-tree conditions—distinct records, non-overlapping relevant storage, a separate head slot, valid accesses, and no external mutation—the resulting processed-record order is the offset-8 subtree, the current record, and then the offset-12 subtree, applying the same ordering recursively.

**The final record in the resulting processed-record chain has the original head value as its successor.** That record is the first record prepended, not the last. The last record prepended becomes the final head.

This connection preserves an existing chain as an unchanged suffix only if that chain’s relevant storage is separate from the modified storage and remains stable. An original head value naming a processed record can instead create a cycle.

Tree-to-chain conversion is inferred intent. The established behavior is the ordered sequence of field reads, recursive processing, and writes. No key ordering, search-tree property, or public ownership policy is established.

## Behavior

### Empty input

If the initial record value is zero, the function returns without reading or writing any specified field and without making a recursive call.

An invalid or otherwise unusable head-container address therefore does not cause a data access in this case.

### Processing and observable access order

For each nonzero current record, the following ordering is established:

1. The four-byte value at record offset 12 is read.
2. F-13e8b3aa517a is invoked recursively with the same head-container address and the value just read as its initial record.
3. After that invocation returns, the four-byte value at the current record’s offset 8 is read and retained as the continuation.
4. The four-byte current head value is read from head-container offset 4.
5. That head value is written to the current record’s offset-12 field.
6. The current record address is written to the head slot.
7. Processing continues with the retained continuation.

The recursive invocation occurs even when the offset-12 value is zero; that invocation returns without field accesses.

The current record is not prepended before its recursive work completes. Both its continuation and the head value used for its successor are obtained after that work. Recursive processing may therefore change what those later reads observe.

The continuation is retained before either prepend write. Processing does not reread offset 8 after those writes. If aliasing causes a prepend write to change that field, the retained value still determines the next iteration.

When the continuation is zero, the current invocation finishes. A suspended caller, if present, then resumes after its recursive call.

### Ordinary finite-tree result

Assume:

- The initial record denotes a finite binary tree, with zero denoting absent branches.
- Each tree record is distinct.
- Relevant record storage does not overlap.
- The head slot is separate from every processed record.
- There is no external mutation.
- All accesses and recursive calls complete normally.

Each record is then prepended exactly once.

The prepend order is the offset-12 subtree, followed by the current record, followed by the offset-8 subtree, recursively applying that rule. Because every prepend places a record before the existing head, the final processed-record chain has the reverse order:

- Offset-8 subtree.
- Current record.
- Offset-12 subtree.

If offsets 8 and 12 are interpreted as left and right branches, respectively, this final order is an in-order traversal. Those directional names and the tree interpretation are inferred, not established field semantics.

The last record prepended becomes the final head. The first record prepended becomes the final record among the processed records, and its successor contains the head value present before the invocation began.

This last statement concerns a stored value, not preservation of the storage named by that value. If the original head points into the processed tree, the resulting links can revisit processed records or form a cycle. A finite combined chain is not guaranteed merely because the input branches form a finite tree.

For an existing chain to remain an unchanged suffix, sufficient additional conditions are that its relevant storage is disjoint from the processed records and head slot, remains stable, and already has the claimed chain structure. The function does not traverse that chain merely because its address was initially in the head slot.

### Destructive updates and repeated invocation

For ordinary non-overlapping storage, each processed record’s offset-12 branch is overwritten by its successor. The original offset-12 topology is not retained by this function.

Offset-8 fields are read but not directly written. They remain unchanged under the non-overlap and stability assumptions.

A second invocation is not generally equivalent to the first. It can interpret successor values produced by the first invocation as recursive branches. No restoration or repeated-conversion guarantee is established.

No key comparison, numerical sorting operation, payload transformation, record count, or explicit inspection of the original head’s target appears.

### Aliasing, shared records, and cycles

There is no alias detection, visited-record set, or cycle check.

Recursive processing can modify storage that a suspended invocation later reads. In particular, a suspended record’s continuation is determined by the offset-8 value observed after recursion, not necessarily the value present when that invocation began.

If the head slot overlaps a record field, the established access order still applies, but ordinary conclusions about field preservation, final head identity, and tree ordering need not hold. A write can affect several logical roles through one physical location.

Shared records can be encountered more than once. A later encounter may read an offset-12 successor written during an earlier encounter rather than the original branch value.

Cycles can prevent normal completion. An offset-12 self-cycle causes recursive entry before any prepend at those invocations. Cycles involving continuation links can instead involve repeated processing and writes. No general outcome is established for arbitrary overlapping or cyclic graphs.

### Completion and failure

Normal completion requires all recursive work to return and each active invocation eventually to encounter a zero continuation.

The function supplies no explicit validation failure, error result, rollback, or recovery path. Invalid accesses, insufficient execution resources, and interruption behavior depend on the execution environment.

Writes completed before a failure are not undone by this function. A failure can leave the head slot and record links partially modified.

## Side effects

- The four-byte head slot at head-container offset 4.
- The four-byte offset-12 field of each record reaching its prepend phase.

These are physical access locations. Aliasing can make them coincide with storage used for other purposes.

## Acceptance examples

These are conditional consequences of static analysis, not executed tests. Unless stated otherwise, all accesses are valid, relevant storage is non-overlapping, the head slot is separate, there is no external mutation, and execution completes normally. Letter labels denote record addresses; “successor” denotes offset 12.

### Empty input

Given a zero initial record:

- No record field or head slot is read or written.
- No recursive call occurs.
- The head-container address need not identify usable storage.

### One record and an arbitrary original head

Given record A with both branch values zero and an initial head value H:

- The final head is A.
- A’s successor is H.
- A’s offset-8 field remains zero.
- No storage is accessed solely because H was initially in the head slot.

H need not identify a valid record or chain for these accesses to complete. A later consumer following H has separate validity requirements.

### Original head names the processed record

Given record A with both branch values zero and a separate head slot initially containing A:

- The final head is A.
- A’s successor becomes A.
- A’s offset-8 field remains zero.

The result contains a self-cycle. An ordinary finite input tree does not by itself guarantee a finite combined successor chain.

### Two branches distinguish prepend order from final order

Given root B with offset-8 branch A and offset-12 branch C, both branch values of A and C zero, and initial head H:

- Prepending occurs in the order C, B, A.
- The final head is A.
- A’s successor is B.
- B’s successor is C.
- C’s successor is H.
- All offset-8 values remain unchanged.

C, the first record prepended, receives H. A, the last record prepended, becomes the head. The final processed-record order is A, B, C.

If H identifies a separate stable chain, that chain remains the suffix. Otherwise, these link values do not establish that the combined structure is finite.

### Offset-8-only path

Given A’s offset-8 value B, B’s offset-8 value C, C’s offset-8 value zero, and all three offset-12 values initially zero:

- Prepending occurs A, B, C.
- The final head is C.
- C’s successor is B, B’s successor is A, and A’s successor is the original head value.
- Continuation among A, B, and C is iterative.

The final processed-record order reverses the offset-8 traversal order. A is first prepended and last in that final order.

### Offset-12-only path

Given A’s offset-12 value B, B’s offset-12 value C, C’s offset-12 value zero, and all offset-8 values zero:

- Recursive processing reaches C before any prepend.
- Prepending occurs C, B, A.
- The final head is A.
- A’s successor is B, B’s successor is C, and C’s successor is the original head value.

Again, the first record prepended receives the original head value.

### Direct recursive cycle

Given A’s offset-12 value A and stable storage:

- Each invocation enters another recursive invocation before reading A’s offset-8 field.
- Those invocations do not reach either prepend write while recursive entry continues.
- Normal completion is not established; resource exhaustion or another environment-level failure may intervene.

### Continuation retained across an overlapping write

If recursive processing returns and the current iteration reads continuation B, but a subsequent prepend write overlaps the field from which B was read, the next iteration still uses B.

The field’s post-write contents do not replace the retained continuation. This example establishes ordering, not termination or useful chain structure for the overlapping arrangement.
