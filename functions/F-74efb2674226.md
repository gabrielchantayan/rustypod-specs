# F-74efb2674226

## Purpose

F-74efb2674226 conditionally forms a rounded, scaled product from two 32-bit input words and presents a resulting 32-bit word to an unresolved indirect destination.

The arithmetic interprets the input sign bits as two’s-complement signs, multiplies unsigned magnitudes, scales by \(2^{-16}\), rounds the magnitude, and conditionally negates the narrowed result. Interpreting the second input as a signed fixed-point factor with 16 fractional bits is **inferred intent**, not an established interface type.

Two conditions bypass both the calculation and the indirect destination:

- The first input is zero.
- The second input is exactly `0x00010000`.

The visible interface has no explicit return value. This contract therefore does not describe an ordinary multiplication function that returns its product to the caller.

## Interface

### Inputs

The function accepts two 32-bit words:

- **First input:** the quantity whose zero value causes an immediate return.
- **Second input:** the factor whose exact positive-unity bit pattern, `0x00010000`, causes an immediate return.

The declared inputs are unsigned words. Their high bits nevertheless determine magnitude extraction and conditional negation as though the words represented signed two’s-complement integers.

There are no visible pointer parameters, output buffers, length arguments, or caller-provided storage locations. No aggregate or byte-oriented memory layout is exposed.

## Behavior

### 1. Bypass selection

The first decision tests whether the first input is zero.

- If it is zero, execution returns without reaching the indirect destination.
- Otherwise, the second input is compared with `0x00010000`.
- Equality causes a return without reaching the indirect destination.
- Arithmetic proceeds only if neither bypass condition holds.

The second comparison is an exact word comparison, not a comparison of magnitudes. Thus `0xffff0000`, the two’s-complement representation of \(-65536\), does not trigger the positive-unity bypass.

Zero is not treated symmetrically between the inputs. A zero second input proceeds to the indirect destination whenever the first input is nonzero.

### 2. Magnitude extraction

The first input’s unsigned magnitude is derived before the second input’s unsigned magnitude.

Let \(A\) and \(B\) denote those magnitudes. Each is the absolute value of its input’s signed two’s-complement interpretation, represented as an unsigned 32-bit word:

\[
0 \leq A,B \leq 2^{31}.
\]

On the arithmetic path, \(A\) is nonzero.

The most negative signed value is handled without a separate error or saturation case: its magnitude remains the unsigned value \(2^{31}\). Intermediate unsigned arithmetic supplies the required modular behavior.

### 3. Calculation-path selection

The compact calculation is selected exactly when:

\[
A \leq 2048
\quad\text{and}\quad
B \leq 1048576.
\]

Both boundaries are inclusive.

If \(A\) exceeds 2048, the split calculation is selected regardless of \(B\). If \(A\) is at most 2048, the second magnitude determines whether the compact calculation remains applicable.

These thresholds are calculation-selection boundaries, not input-validity limits. Exceeding either threshold does not suppress the indirect invocation or generate an error.

### 4. Rounded magnitude calculation

The compact calculation multiplies the two magnitudes, adds \(2^{15}\), and logically shifts right by 16.

Within its permitted ranges, the product is at most \(2^{31}\). Adding \(2^{15}\) therefore remains below \(2^{32}\), so neither the product nor its rounding addition wraps on this path.

The split calculation combines:

- The upper 16 bits of the second magnitude multiplied by the lower 16 bits of the first.
- The full second magnitude multiplied by the upper 16 bits of the first.
- The product of the two lower 16-bit portions, rounded by adding \(2^{15}\), then logically shifted right by 16.

The lower-portion product is at most \(65535^2\). Adding \(32768\) still fits in 32 bits. The other products and their combination are subject to modulo-\(2^{32}\) arithmetic.

Both calculation paths produce the same 32-bit magnitude word:

\[
M =
\left\lfloor
\frac{AB + 2^{15}}{2^{16}}
\right\rfloor
\bmod 2^{32}.
\]

This equivalence is derived from the static arithmetic decomposition, not from execution.

Before narrowing, adding \(2^{15}\) rounds the scaled magnitude to the nearest integer, with exact half cases rounded upward in magnitude. The subsequent narrowing retains only the low 32 bits. There is no saturation, overflow status, or visible error report.

### 5. Conditional negation

**The magnitude word is negated modulo \(2^{32}\) exactly when the input sign bits differ.**

Specifically:

- If the input sign bits match, the final word is \(M\).
- If the input sign bits differ, the final word is \((-M)\bmod 2^{32}\).

This rule does not guarantee the signed negativity of the final word.

If \(M\) is zero, conditional negation still produces zero. If the rounded magnitude exceeds the signed or unsigned result range, narrowing and modular negation can produce a word whose signed interpretation differs from the mathematical product’s sign.

For results representable in the signed 32-bit range, the calculation corresponds to nearest rounding with exact halves rounded away from zero. That statement does not extend to a signed interpretation of wrapped results.

In particular, the behavior is not equivalent to always adding a positive half-unit to a signed product and then performing an arithmetic right shift.

### 6. Indirect transfer

After conditional negation, the representation shows one indirect invocation with the final word as its sole explicit argument.

No subsequent arithmetic involving the original inputs is visible. No destination-produced result is visibly examined, and no local handling of a destination failure is shown.

The destination may return, fail, or not return. Its actual behavior is unresolved; the visible return after the invocation is conditional on control reaching it.
