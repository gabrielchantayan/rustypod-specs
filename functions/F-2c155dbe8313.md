# F-2c155dbe8313

## Purpose

This function performs a fixed, order-sensitive transformation of addressed storage, prepares activation-associated state, and attempts several external control transfers. The supplied evidence does not establish an application-level purpose.

The contract concerns the history of reads, writes, and calls, not merely final memory contents. Earlier writes may overlap later read locations. Repeated reads and repeated writes therefore remain distinct requirements even when their addresses or values appear identical.

All behavior is conditional on reaching the relevant operation. Valid addressing, defined arithmetic, successful calls, and normal completion are not established.

### Widths and execution requirements

All offsets below are byte offsets. A **word**, **halfword**, and **byte** occupy 32, 16, and 8 bits respectively. Displacements are read as signed halfwords and widened to signed 32-bit values.

Two byte-producing operations are distinguished:

- **Low-byte capture:** retention of the least significant eight bits.
- **Character conversion:** conversion to the represented character type. Signedness and out-of-range conversion behavior are unresolved.

A character used in address arithmetic contributes its interpreted numeric value. A stored pattern of 0xFF does not establish an address contribution of positive 255.

Address-bearing arithmetic is represented using signed 32-bit values. Multiplication and left shift are distinct operations. This contract does not impose modular wrapping or define signed overflow, invalid shifts, or narrowing beyond the supplied evidence.

Each reached memory operation requires access to its entire width. Alignment, byte order, address mapping, and access-failure behavior remain **documented_only**. No validation, recovery, or rollback is established.

## Behavior

### Behavioral model

The description partitions the fixed history into entry, eleven rounds, terminal processing, and external continuation. These are specification boundaries, not evidence of a variable-length loop or data-structure abstraction.

Within a round:

- **Incoming cursor** is the cursor retained from the preceding boundary.
- **Incoming carrier** is the retained word supplied by entry or the preceding round.
- **Selector** is the first observation of that round’s global-backed source.
- **Installation value** is a separate observation of the same source.
- **Field** is a word read at incoming cursor + 0x44.
- **Displacement** is a signed halfword read at incoming cursor + selector.
- **Token**, where required, is a character read at displacement + incoming carrier.
- **Anchor**, **markers**, and **route** are retained observations defined below.

**Context** and **payload** are mutable activation-associated 32-bit objects represented at coordinates 0x34 and 0x108. Coordinates identify represented storage relationships, not a verified physical stack layout. References to current context or payload require the value applicable at that use; applicable alias effects must not be erased by treating these objects as immutable captures.

### Entry contract

The first two writes publish argument 2 as a word at base + 0x14, then argument 4 as a byte at initial cursor + 0x11.

The entry observations then occur in this order:

1. A word at argument 1 + 0x64, whose low byte is retained.
2. A reference word at initial cursor + 0x44.
3. A signed displacement at initial cursor + base.

Before either of the following linkage observations, entry publishes initial cursor at argument 2 + 0x54, the retained byte at initial cursor + 0x11, and base at reference + 0x44, in that order.

An **entry probe** is then read at displacement + 0x44. An **entry link** is subsequently read at base + 0x14. The latter is a fresh observation, not necessarily argument 2.

Entry finishes with this ordering requirement: a second publication of the retained byte precedes a halfword write of the narrowed entry link at base + displacement; that write precedes the initial carrier read at base + 0x44; that read precedes publication of initial cursor at initial cursor + 0x54.

Consequently, overlap from the halfword write can affect the initial carrier, whereas the final cursor write cannot retroactively affect it.

### Context establishment and early routing

A fresh word at entry probe + 0x64 then supplies a character-converted byte at incoming cursor + 0x11. After this publication, a word at current context + 0x04 supplies the **context-derived word**, followed by a word at selector + 0x74 supplying the **early marker**. The context-derived word is published at incoming cursor + 0x54 before handoff.

The remaining rounds have these observation and cursor-selection relationships:

|---|---|---|
| 2 | Anchor refresh, field, displacement | Fresh word at selector + 0x14 |

Each anchor refresh reads a word at current context + 0x64. Because opening precedes refresh, round 7 opens using the earlier anchor; round 10 opens using round 9’s anchor.

Rounds 2 and 3 publish early marker at current context + 0x54 after displacement acquisition and before replacement-cursor acquisition. They then publish selector’s character conversion at replacement cursor + 0x0D.

Round 3 subsequently obtains route from incoming carrier + 0x14. Before its route-based handoff, it publishes current context at early marker + 0x54.

### Token-dependent and route-dependent effects

The token rounds impose additional ordering beyond their common boundaries:

- **Round 4:** token acquisition precedes publication of early marker’s character conversion at selector + 0x1D.
- **Round 5:** after token acquisition, a fresh word from current context + 0x64 is published at displacement + 0x54. This does not refresh anchor. Incoming carrier’s character conversion is then published at token + 0x0D. Only afterward is the **late marker** read at selector + 0x64.
- **Round 6:** after token acquisition, selector’s character conversion at current context + 0x01 precedes incoming carrier’s character conversion at selector + 0x0D. Late marker is then published as a word at selector + 0x44, followed by selector’s character conversion at token + 0x0D.

Token-relative addresses always use the token’s interpreted character value. Round 6’s outgoing carrier is not generally interchangeable with late marker: the token-relative byte and handoff halfword intervene before its carrier read.

In round 7, route is read at incoming carrier + 0x74 after displacement acquisition and before cursor replacement. Route’s character conversion is written at field + 0x0D before handoff.

In round 8, displacement acquisition precedes selector’s character conversion at incoming carrier + 0x15. This byte precedes publication of incoming carrier at selector + 0x44. Route is then read at field + 0x74 before handoff.
