# F-bb85056f54e1

## Purpose

F-bb85056f54e1 validates five date/time-like values, submits a partially preserved packed representation through two object operations, and conditionally writes shared state and sets a flag.

Year, month, day, hour, and minute are inferred semantic names. The established contract is the validation, representation, call sequence, and memory-access behavior described below. Validation is not calendar validation.

Normal returns are:

| Status | Established condition |
|---|---|
| 4 | Scalar validation rejects the inputs. |
| 2 | Validation succeeds, but object acquisition returns null. |
| 0 | Acquisition returns nonnull and the remaining operations complete normally. |

Status 0 does not establish that either object operation accepted or persisted the representation. Their results are ignored.

The shared-state processing does not establish a coherent single-record comparison or update. It captures one shared-state base for later use, but separately evaluates the shared-state global pointer for every reached comparison and for the first field store. Without a stability guarantee, these accesses can target different records.

## Behavior

### Validation

Validation precedes object acquisition, dependency calls, and explicit shared-state accesses.

The year condition subtracts 2000 using 32-bit unsigned arithmetic and requires the result to be below 100. This admits exactly the year bit patterns representing 2000 through 2099; negative signed years do not pass.

The subsequent initial conditions require a nonzero month below 13 and a nonzero day.

For a surviving day:

- An initial rejection condition records whether day exceeds 30.
- If day is below 32, that condition is replaced by whether hour exceeds 23.
- If rejection is not already selected, minute is tested against 59.

Thus day 31 passes when hour and minute are valid. Day 32 or greater fails regardless of hour and minute. The minute test is reached only when earlier conditions have passed.

Any rejected input returns 4 without calling a dependency.

### Temporary initialization and acquisition

After validation succeeds, the function initializes a separate 32-bit derived-value slot to zero and a three-word, 12-byte temporary block containing:

1. Original year.
2. Original month.
3. Original day.

It then calls **F-a4a34621f0a7** with no visible arguments.

A null result returns 2. Neither indirect operation, the derived-year dependency, nor the explicit shared-state processing follows.

A nonnull result is retained as the object pointer. The function contains no explicit allocation or release of that object.

### First object operation

The function reads the acquired object’s dispatch-table pointer and calls its entry at byte offset **0x24**.

The visible argument order is:

1. Pointer to the temporary block.
2. Acquired object pointer.

The block initially contains the three original scalar values. The operation’s result is ignored, but its modifications to the block can affect the next operation.

### Packed-field overlay

After the first operation returns, selected fields of the temporary block are replaced. Other portions retain their post-call contents.

In the following table, byte positions are numbered by numeric significance within each 32-bit word: byte 0 is least significant and byte 3 is most significant.

| Word | Byte 0 | Byte 1 | Byte 2 | Byte 3 |
|---|---|---|---|---|
| First | Preserved | Minute | Hour | Preserved |
| Second | Month | Preserved | Year bits 0–7 | Year bits 8–15 |
| Third | Day | Preserved | Preserved | Preserved |

The source-visible assignment order is:

1. Replace the second word’s upper 16 bits with the original year’s low 16 bits.
2. Replace bytes 1 and 2 of the first word with minute and hour.
3. Replace the second word’s low byte with month.
4. Replace the third word’s low byte with day.

“Preserved” refers to contents after the first object operation, not necessarily the original initialization. Every accepted value fits its selected field width.

This describes word bit fields. Their correspondence to increasing memory addresses depends on byte order, which is not independently established by the supplied evidence.

### Second object operation

The function reads the object’s dispatch-table pointer again and calls its entry at byte offset **0x20**.

The visible argument order is:

1. Acquired object pointer.
2. Pointer to the modified temporary block.

The argument order differs from the first operation. The second table lookup is separate; the first operation is not assumed to preserve the object’s table pointer.

The result is ignored. No later explicit shared-state comparison reads the temporary block, although this does not exclude other effects of the operation.

### Derived-year dependency

The function next calls **F-3a7a47316439** with:

1. Pointer to the separate 32-bit derived-value slot.
2. Original year.

The slot was initialized before acquisition and both object operations. It is not reset immediately before this call. The dependency’s return value is not inspected.

Subsequent processing uses only the slot’s low 16 bits. The conversion rule, write extent, and error behavior are unknown. The original year must not be substituted for this derived value.

### Shared-state capture and comparisons

After the derived-year dependency returns, the function first reads the shared-state global pointer and saves that value. This **saved base** is retained for later byte-field stores and flag-word addressing.

The function then separately evaluates the shared-state global pointer to read the year field. This read is not expressed through the saved base.

The source-visible access sequence is:

| Order | Access | Width | Required preceding result |
|---|---|---:|---|
| 1 | Capture shared-state global pointer as the saved base | 32-bit address value | Derived-year dependency returned |
| 2 | Separately evaluate that global pointer; read offset 0x2c | 16 bits | Always after capture |
| 3 | Separately evaluate that global pointer; read offset 0x2e | 8 bits | Year matched |
| 4 | Separately evaluate that global pointer; read offset 0x2f | 8 bits | Year and month matched |
| 5 | Separately evaluate that global pointer; read offset 0x30 | 8 bits | Year, month, and day matched |
| 6 | Separately evaluate that global pointer; read offset 0x31 | 8 bits | Year, month, day, and hour matched |

The comparisons are respectively against:

- Low 16 bits of the derived-value slot.
- Original month.
- Original day.
- Original hour.
- Original minute.

The byte reads are compared with the full unsigned input values after promotion. Accepted inputs fit in eight bits, so these comparisons do not introduce matches caused by input truncation.

A mismatch prevents later field reads. If every reached comparison ultimately matches through minute, the function returns 0 without explicit shared-field writes, auxiliary-pointer access, or dirty-word access.

Crucially, the saved base is not the specified basis for these comparison reads. Each reached read uses its own evaluation of the global pointer. Without an established stability guarantee:

- The saved base may differ from the base used for the year comparison.
- Different comparisons may read different records.
- An all-match outcome need not establish that any one record contains the complete requested field set.

These are source-level access distinctions, not a claim that concurrent mutation is supported or that particular machine instructions are guaranteed.

### Changed-state writes and flag update

If the comparison sequence detects a mismatch, all five fields are written. The source-visible order is:

1. Evaluate the shared-state global pointer again and store the derived value’s low 16 bits at offset 0x2c.
2. Store month as eight bits at offset 0x2e from the saved base.
3. Store day as eight bits at offset 0x2f from the saved base.
4. Read the auxiliary metadata global pointer.
5. Store hour as eight bits at offset 0x30 from the saved base.
6. Store minute as eight bits at offset 0x31 from the saved base.
7. Read a signed 32-bit index at offset 0x04 from the captured auxiliary metadata pointer.
8. Address a 32-bit flag word at the saved base plus four times that index plus 0x0c.
9. Read that word, combine it with mask 0x200 using bitwise OR, and write the result back.

The saved base in this sequence is the value captured **before all comparisons**. It is not recaptured after a mismatch.

The first store uses a new evaluation of the global pointer, rather than the saved base. Consequently, the year store, remaining field stores, and comparison reads cannot be specified as necessarily targeting one record.

The index has no visible bounds check. The address calculation uses the supplied 32-bit address model, with no visible widening or overflow check. Valid indexing and address arithmetic are required for normal completion; the evidence does not establish safe behavior for invalid results.

The flag update preserves other bits relative to the word it reads. It is not established as atomic. If the selected flag word overlaps field storage, its later write may affect the final field contents.

After this sequence completes, the function returns 0.

## Side effects

### Explicit effects

The accepted, nonnull-acquisition path always performs both indirect object calls and the derived-year call before inspecting shared fields. Matching shared state does not bypass those calls.

A detected mismatch causes:

- One 16-bit field store through a separately evaluated global pointer.
- Four eight-bit field stores through the previously saved base.
- An auxiliary metadata pointer read and signed index read.
- A 32-bit read-modify-write setting mask 0x200 at the index-selected location.

Rejected inputs perform none of these operations. A null acquisition stops before them.

### Ownership and lifetime

No explicit release of the acquired object is visible. Borrowing, ownership transfer, reference counting, and object lifetime remain unknown.

Pointers to temporary local storage are passed to dependencies. No explicit lifetime extension or retained-pointer management is visible. This does not establish that callees refrain from retaining those pointers, nor that retention would be safe.

### Ordering and partial effects

No rollback or synchronization is visible. Object operations precede shared-state processing, and a later failure does not undo their effects.

A fault during changed-state processing can leave only some stores completed. A changing global pointer can separate the year store from the saved-base stores. Unknown callees are not assumed to preserve globals, preserve the object, or avoid unrelated side effects.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Normal-return examples assume valid memory accesses and normally returning dependencies.

1. **Accepted boundaries.** Both 2000/1/1 at 00:00 and 2099/12/31 at 23:59 pass validation. Null acquisition returns 2; a normally completing nonnull path returns 0.

2. **Rejected boundaries.** Year 1999 or 2100, a negative signed year, month 0 or 13, day 0 or 32, hour 24, or minute 60 returns 4 when applicable. No dependency is called.

3. **Day 31.** Day 31 with hour 23 and minute 59 passes. Day 31 with hour 24 fails. The preliminary test against day 30 does not independently reject day 31.

4. **No calendar validation.** Year 2001, month 2, day 31, hour 12, minute 30 passes validation. This does not establish what either object operation does with that representation.

5. **Stable, matching record.** If the global pointer remains stable and all five fields match the derived year and requested byte values, the function performs no explicit shared-field or flag-word writes. Both object operations and the derived-year call still occur.

6. **Single mismatch.** With a stable pointer and only minute differing, all five fields are nevertheless stored, followed by the flag-word update.

7. **Derived year.** If the derived slot’s low 16 bits differ from the original year, those low bits govern the year comparison and any year store.

8. **Preserved packed byte.** If the first object operation changes the second word’s byte 1, that byte survives the overlay and reaches the second operation. The same word’s low byte and upper 16 bits are replaced.

9. **Capture differs from comparison base.** If the saved base identifies one valid record and the global pointer subsequently identifies another, the year comparison uses the separately evaluated pointer, not the saved base. The saved base remains the basis for later byte-field stores and flag addressing.

10. **Changing comparison bases.** If each reached global-pointer evaluation identifies valid storage and the respective field reads match, no explicit update occurs even if those fields came from different records. This does not establish a matching composite record.

11. **Split update.** If a mismatch occurs and the first store’s global-pointer evaluation differs from the saved base, the derived year is stored through that new pointer; month, day, hour, minute, and flag addressing still use the saved base.

12. **Short-circuit mismatch.** If the year comparison fails, no month, day, hour, or minute comparison read occurs before the update sequence.
