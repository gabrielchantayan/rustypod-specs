# F-d09d4e15f1d8

## Purpose

The visible behavior is an ordered sequence of indirect calls and calculated memory accesses, ending in an unconditional repeating call-and-store sequence.

No application-level purpose is established. Descriptions such as initialization, allocation, serialization, decoding, or device control would require evidence not supplied here.

The visible path has no normal return. If every dependency returns and every memory access succeeds, execution reaches a loop with no visible exit. Faults, nonreturning dependencies, and nonlocal control transfers remain possible.

This is a static behavioral contract. The supplied representation includes warnings about invalid instruction data and omitted regions, so its completeness as a description of executable behavior remains unresolved.

## Behavior

### Call-group terminology

A **four-call group** means four consecutive indirect calls with no displayed arguments. Unless otherwise stated, only the fourth call’s result is used by the subsequent visible operations.

A **forwarding stage** consists of:

- A call receiving a retained value.
- A no-displayed-argument call whose result is passed to another call.
- A second no-displayed-argument call whose result is passed to another call.
- A four-call group producing the stage’s final result.

These descriptions specify observable call order and result flow. They do not establish shared dependency identity, hidden arguments, or dependency semantics.

### Entry effects and initial scaling

The first direct effect is a 32-bit store of the first input at:

**4 × first input + 20**

This precedes every visible dependency call.

The first call receives the first input and **W(8H)**. Its target depends on the link-related entry state.

Next, a no-displayed-argument call produces a result consumed by a one-argument call. Another no-displayed-argument call produces a result consumed by a call whose second argument is **H >> 8**. A four-call group follows.

Before using that group’s final result, the operation writes the first input as 32 bits at **W(8H) + 20**. It then passes four times the group’s final result to another call.

A further four-call group supplies a result designated **A**. The next 32-bit store has:

- Destination: **16A + 20**.
- Value: **4A**.

No evidence establishes that **A** is an index, pointer, size, or allocation result.

### Entry-state and secondary-register processing

The next call receives four displayed arguments, in order:

1. **W(8H)**.
2. **W(8H)**.
3. **H >> 8**.
4. **third input >> 7**.

After a four-call group, the operation stores **W(8H)** at **W(8H) + 20**. This revisits the earlier destination that received the first input. Intervening dependencies may have modified that location.

The group’s final result, shifted left by two, is passed to another call. A further four-call group follows. The secondary-register value **E** exposed after the last call supplies the next store:

- Destination: **E × 2²⁶ + 20**.
- Value: **E × 2²⁴**.

The operation passes **E × 2²⁴** to another call. After a four-call group, its final result selects a destination at four times that result plus 20. The value stored there is again **E × 2²⁴**.

Four times that destination-selecting result is passed to another call. A further four-call group supplies a result designated **R**. The operation stores **4R** at **16R + 20**.

### Forwarded results and retained entry bits

The first forwarding stage begins with **4R** as its explicit retained argument. Its final result selects a destination at four times that result plus 20, where the operation stores the retained **4R**.

Four times the destination-selecting result is passed to another call. A four-call group then supplies **C**, giving the next store:

- Destination: **16C + 20**.
- Value: **4C**.

Define **K = W(4C)**.

A second forwarding stage begins with **K**. Its final result selects another destination at four times that result plus 20. This time the stored value is **H >> 16**, not **K**.

Four times that stage’s final result is passed to another call. A four-call group supplies **D**. The operation stores **4D** at **16D + 20**.

Define **S = W(16D)**. The next call receives:

1. **S**.
2. **S**.
3. **H >> 15**.

After a four-call group, the operation stores **S** at **S + 20**.

Under the same address-arithmetic interpretation, the last two stores address the same location. They have different values and are separated by dependency calls; they cannot be collapsed into one final-state assignment.

### Byte-selection state

Define:

**P = (K & 0x7fffffff) >> 7**

The mask occurs before the shift. Consequently, **P** lies between zero and `0x00ffffff`, inclusive. The repeated selector address in the next portion is **P + 1**.

A selector-based store means a fresh unsigned one-byte read, followed by a one-byte write at the read value plus 17. Its destination is therefore between 17 and 272, inclusive.

The selector read is not a pointer-sized load. Adjacent bytes do not contribute to the selected destination.

### Six byte stores before the loop

The final result of the preceding four-call group is shifted left by two and passed to another call. A further four-call group supplies an unsigned result **U**.

The first selector-based byte store reads from **P + 1** and writes **B(U << 2)** to the selected destination.

A call then receives **W(U << 2)** in all three displayed argument positions. A no-displayed-argument call produces a result consumed by another call, and a four-call group follows.

Before its new result is used as an argument, the operation rereads the selector at **P + 1** and writes:

**B((U & 0x3fffffff) >> 20)**

The two stores derived from **U** need not select the same destination. The second value still derives from **U**, not from the intervening group’s result.

That intervening result, shifted left by two, is passed to another call. A four-call group supplies an unsigned result **V**. Define:

**T = W(V << 2)**

Two byte stores follow without an intervening dependency call:

- A direct store of **B(T)** at **(H >> 23) + 28**.
- A zero store selected by a fresh read from **P + 1**.

The direct destination lies between 28 and 539, inclusive. Its store precedes the selector read. If the direct destination equals **P + 1**, it can change the selector used immediately afterward.

The next dependency calls receive **H >> 23**, then no displayed arguments, then **(V & 0x3fffffff) >> 6**, respectively. A four-call group follows. A further fresh selector read from **P + 1** selects another zero-byte store.

The latest group result, shifted left by two, is passed to another call. A four-call group supplies a result from which the operation derives:

**Q = (result & 0x3fffffff) >> 25**

Thus the initial **Q** is between zero and 31.

The sixth and final byte store before the loop is a zero store selected by a byte read from:

**W(T × 1024) + 1**

This selector address has a different derivation from **P + 1**. Equality is possible but is not required. The multiplication uses a signed intermediate in the supplied representation, so the low-32-bit address interpretation remains conditional.

A call receives **Q << 1**. A following no-displayed-argument call supplies the initial carried result for the loop. This initial carried result is not visibly scaled before its first use.

### Unconditional repeating behavior

The loop is entered at least once if execution reaches it.

Each iteration begins with a two-argument call receiving the carried result and **Q >> 8**. A four-call group follows. Its final result is retained while a fresh byte read from **W(T × 1024) + 1** selects a zero-byte store.

The retained result, shifted left by two, is then passed to another call. A second four-call group supplies a new result. Under the conditional 32-bit arithmetic model:

- Four times that result becomes the next carried result.
- That result shifted left by 26 becomes the next **Q**.

The selector address derived from **T** remains the same within the displayed data flow, but its byte contents are reread every iteration.

The first iteration’s second argument is necessarily zero because the initial **Q** is at most 31. Later iterations use the updated **Q**, not the initial bounded value. Under 32-bit wrapping, the later second argument is determined by the low six bits of the updating result, shifted left by 18.

The target calculation for the first two-argument loop call differs between initial entry and subsequent iterations. Equal argument shapes must not be taken as proof of an identical dependency target.

There is no visible exit test, success return, or failure return.

## Side effects

The visible prefix contains **twelve 32-bit stores**.

It then contains **six byte stores before entering the loop**, in this order:

| Store | Value | Destination derivation |
|---|---|---|
| 1 | **B(U << 2)** | Selector read from **P + 1**, plus 17. |
| 2 | **B((U & 0x3fffffff) >> 20)** | Fresh selector read from **P + 1**, plus 17. |
| 3 | **B(T)** | Direct address **(H >> 23) + 28**. |
| 4 | Zero | Fresh selector read from **P + 1**, plus 17. |
| 5 | Zero | Fresh selector read from **P + 1**, plus 17. |
| 6 | Zero | Selector read from **W(T × 1024) + 1**, plus 17. |

These six stores include five selector reads. The loop adds one selector read and one byte store per completed iteration. An iteration that stops after its store but before its end can already have produced that store.

These counts exclude dependency effects. Repeated zero stores remain separate accesses: selector contents can change, destinations can alias, and the memory’s external semantics are unknown.

## Acceptance examples

These are conditional static criteria, not runtime observations.

### Initial store precedes calls

With a first input of 3 and valid writable memory, the first direct effect is a 32-bit write of 3 at address 32. No dependency call precedes it.

### Revisited destination

With **H = 2**, the scaled entry-state destination is address 36. It first receives the first input and later receives 16.

Acceptance must allow unspecified dependency effects between those stores.

### Unsigned input shift

With a third input of `0xffffffff`, the early four-argument call’s fourth argument is `0x01ffffff`. Producing `0xffffffff` through an arithmetic right shift would not match the displayed unsigned operation.

### Byte value and selector width

If a selector read returns `0xff`, the selected destination is address 272.

If **U = 0x12345678**, the first byte value derived from **U** is `0xe0`; the second is `0x23`. These values do not require the two selector reads to return the same byte.

### Fresh selectors and aliasing

If successive reads from **P + 1** return 5 and 9, their stores target addresses 22 and 26. Reusing the first selector would violate the visible read sequence.

If the direct **B(T)** store addresses **P + 1**, and **B(T) = 9**, the immediately following selector read observes that written value in an ordinary coherent-memory scenario without an intervening modification. Its zero store then targets address 26.

### Prefix access count

If execution reaches the loop without interruption, the direct prefix includes twelve 32-bit stores and six byte stores—not seven byte stores. Five of those six byte stores have selector reads; the remaining store uses the direct destination derived from **H**.

### Loop entry and continuation

For every possible initial **Q**, the first loop call’s second displayed argument is zero.

If one loop iteration completes, it adds one selector-based zero store. If all calls continue returning and accesses continue succeeding, the visible behavior repeats rather than returning after that iteration.
