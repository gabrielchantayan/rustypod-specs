# F-c846f8d060b1

## Purpose

F-c846f8d060b1 conditionally updates one or two position-like fields in a caller-supplied state record and reports a relative position through a two-word output area.

The operation supports two independently requested regions, designated **A** and **B**. Each region has a start value, a current value, an end value, and an enable bit. The requested displacement is interpreted relative to a selected origin. A resulting relative position is accepted when it is nonnegative and no greater than the region’s end-minus-start extent.

When both regions are requested, A is processed before B. The operation is **not transactional**: A can be updated even if B subsequently fails and the reported result is failure.

The position and region terminology describes inferred intent. The supplied static representation establishes integer reads, comparisons, and writes; it does not establish the application-level meaning of the stored values.

## Behavior

### Shared calculation

A working relative origin begins at zero.

For a region that passes its preliminary eligibility checks, the ordinary origin interpretations are:

| Selector | Relative origin |
|---|---|
| 0 | Zero |
| 1 | Current minus start |
| 2 | End minus start |

The candidate relative position is the working origin plus the displacement.

Acceptance requires both:

- The candidate is nonnegative under the signed comparison used by the function.
- The candidate is no greater than end minus start, also using a signed comparison.

The upper endpoint is inclusive. Subject to arithmetic representability, a successful candidate equal to the extent writes the region’s current field to its end value.

On acceptance, the current field is set to start plus the candidate. The output result, if all requested processing succeeds, is the relative candidate rather than the newly stored absolute-like current value.

Unsupported selectors do not cause an explicit selector error. Their effective working origin remains zero on every reachable path shown here. A combined A-and-B request nevertheless rejects unsupported odd selectors during A eligibility checking.

### No regions requested

If neither `0x04` nor `0x08` is set in the request mask:

- No state field is read or written.
- The first output word receives the displacement.
- The second output word receives zero.

The nonnegative-position restriction does not apply on this path. A negative displacement is returned unchanged rather than converted to failure.

### Region A requested

A processing first reads the capability word and tests bit `0x04`.

If that capability bit is clear, the operation fails without reading A current.

If the capability bit is set, A current is read. A zero value causes failure.

For a nonzero A current:

- If B is not requested, there is no additional combined-request eligibility condition.
- If B is requested, the origin selector must be even, and a further read of the capability word must show bit `0x08` set.
- For a combined request with an odd selector, the function fails before that further B-capability read.

A failed A eligibility check prevents B processing entirely.

After eligibility:

- Selector 0 leaves the working origin at zero.
- Selector 1 uses A current minus A start.
- Selector 2 uses A end minus A start.
- Any other selector leaves the working origin at zero.

The candidate is then formed. If it is negative, A start and A end are not read for the bounds check.

For a nonnegative candidate, A start and A end are read to determine the signed extent. A candidate greater than that extent causes failure.

An accepted candidate causes a write to A current before any B-phase processing. If B is not requested, the operation then reports the accepted relative position. If B is requested, processing continues with B.

### Region B requested

B processing occurs either directly, when A was not requested, or after a successful A update.

The capability word is read and bit `0x08` is tested. This is a distinct access from any B-capability check performed during A eligibility.

If the capability bit is clear, the operation fails without reading B current.

If the capability bit is set, B current is read. A zero value causes failure, including after A has already been updated.

For a nonzero B current:

- Selector 0 sets the working origin to zero.
- Selector 1 uses B current minus B start.
- Selector 2 uses B end minus B start.
- Any other selector leaves the working origin unchanged. On reachable paths with such selectors, that value is zero.

The candidate is formed from this working origin and the displacement.

If the candidate is negative, the bounds-check reads of B start and B end do not occur. Otherwise, those fields are read and the candidate is compared against their signed difference.

Acceptance writes B current as B start plus the candidate. The accepted relative candidate is then written to the first output word.

### Combined requests

A request containing both relevant bits has these additional consequences:

1. A must be enabled and have a nonzero current value.
2. The selector must be even.
3. B must appear enabled during A’s combined-request eligibility check.
4. A’s candidate must pass A’s bounds check.
5. A current is written.
6. B is checked again, including a fresh capability read and its own nonzero-current requirement.
7. B’s candidate must independently pass B’s bounds check.
8. B current is written, followed by the output words.

Selector 1 therefore fails for combined requests, even if both regions individually support it.

Selector 2 computes a separate end-relative candidate for each region. The final successful output describes B’s candidate, not A’s.

An unsupported even selector can proceed with a zero relative origin. An unsupported odd selector fails before either current field is updated.

### Failure reporting and completion

Every shown failure path writes signed `-1` to the first output word. The second output word is then written as zero.

Failure does not undo an earlier A-current write.

On normal completion, the first output word is written before the second. There is no separate status flag indicating whether an earlier state update occurred.

## Side effects

### Ordered reads and writes

The externally relevant ordering is:

- A processing, if requested, precedes B processing.
- An accepted A-current write precedes all B-phase checks.
- An accepted B-current write precedes the first output write.
- The first output write precedes the second output write.
- No further state reads appear after the first output write.

Some fields can be read more than once. In particular:

- A combined request can read the capability word three times: for A, for B eligibility within A, and for B processing.
- A start can be read during origin calculation and again during bounds checking.
- B start can likewise be read during origin calculation and again during bounds checking.
- Selector 2 reads each applicable end during origin calculation and again during bounds checking.

The contract does not replace these accesses with a single coherent snapshot. No protection against concurrent mutation is shown.

### Ownership and aliasing

No allocation, release, ownership transfer, or external resource operation is visible. The function accesses caller-supplied memory directly.

The output area is not checked for overlap with the state record. If it overlaps:

- Output writes can overwrite state fields after the region processing has finished.
- The zero written to the second output word can replace an earlier region update.
- Logical field-update descriptions must be interpreted in the actual write order, rather than as a guarantee about final non-overlapping storage.

### Arithmetic and abnormal access

The function does not explicitly detect arithmetic overflow. Relevant arithmetic includes:

- Current minus start.
- End minus start.
- Working origin plus displacement.
- Start plus the accepted relative position.

Consequently, this contract’s numerical examples use representable intermediate values. Wraparound, trapping, or other overflow consequences remain documented_only rather than being assumed.

A negative extent causes every nonnegative candidate to fail, provided the subtraction producing that extent is representable.

No recovery from invalid or inaccessible memory is shown. The final zero output write is guaranteed only for normal completion, not after an access fault or other execution failure.
