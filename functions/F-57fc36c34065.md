# F-57fc36c34065

## Purpose

F-57fc36c34065 repeatedly performs a fixed sequence of indirect calls and memory accesses. Each completed iteration replaces its three working word inputs with one computed word, clears its working byte input, and begins another iteration.

The supplied representation establishes no higher-level purpose. Allocation, serialization, object construction, and device control are not established interpretations.

This contract describes operations that are reached only if preceding calls return and preceding memory accesses complete. It does not establish that the routine can complete an iteration in any particular environment.

## Interface

### Explicit inputs and output

| Input | Width | Established use |
|---|---:|---|
| First word input | 32 bits | Passed to the first dependency and written by the first explicit word store. |
| Second word input | 32 bits | Passed to the first dependency. |
| Third word input | 32 bits | Passed to the first dependency. |
| Byte input | 8 bits | Written four times early in each iteration. |

There is no visible normal return, returned result, termination condition, or error result. A dependency may prevent further progress by not returning; faults and nonlocal exits remain unspecified.

The routine also consumes ambient state:

- An incoming return-link value that participates in the first indirect target calculation.
- Other code-related values used to construct indirect targets.
- One global 32-bit word, read during each iteration.
- A 32-bit secondary machine-result value without a complete visible definition.
- Memory at calculated addresses.

The return-link value is not an additional ordinary argument. Near the end of an iteration, the working link state is replaced with a fixed code-related value. A subsequent iteration therefore does not use the original incoming link.

### Widths, arithmetic, and layouts

A **word** is a 32-bit bit pattern. A loaded selector byte is zero-extended from eight bits before address formation. A byte store retains only the low eight bits of its value.

All numerical examples and arithmetic simplifications below are conditional on **32-bit truncating machine arithmetic**: additions, multiplications, and left shifts retain their low 32 bits, including address calculations. Unsigned right shifts are logical.

The representation also contains signed-looking arithmetic and signed left shifts. Its expressions do not independently establish portable-language overflow or shift behavior. The truncating interpretation is therefore a stated condition, not an unconditional language-level guarantee.

Two access patterns recur:

- Word destinations formed from a scaled index plus 20 bytes.
- Byte-selected destinations formed by loading an unsigned byte and adding 17 bytes, without further scaling.

These patterns do not establish a structure type, allocated extent, or common owning object. Byte-selected byte destinations range from address 17 through 272. The cached-byte-selected word destination ranges from address 20 through 275.

Byte order, required alignment, address-space validity, memory ordering, and fault behavior are not established.

## Behavior

### Execution and dependency ordering

The body is an unconditional loop containing **146 indirect calls per iteration**, provided execution reaches every call.

**F-57fc36c34065-D001** through **F-57fc36c34065-D146** identify those call sites in execution order. Below, **D001**, for example, abbreviates **F-57fc36c34065-D001**. These are site identifiers, not assertions that all sites have distinct callees.

Every site in a stated interval executes in numerical order. Calls whose arguments or results are not described still occur. Their omitted argument lists do not establish zero-argument interfaces, and unused results do not establish absence of side effects.

Dependencies may change global or addressed memory. Consequently:

- A later selector load need not recover a previously stored byte.
- Repeated selector expressions denote separate reads unless explicitly described as cached.
- A retained word or cached selector is not replaced merely because a dependency changes its original memory source.

### 1. Initial records and byte writes: D001–D032

D001 receives the three working word inputs. Its target depends on the current return-link value plus 4094 bytes.

After D002–D005, D005 supplies a **first index**. The routine writes the first word input at four times that index plus 20. D006 then receives four times that index.

D010 supplies an **initial record index**. Define:

- **Initial scaled value:** four times the initial record index.
- **Initial byte base:** the initial record index multiplied by 2³⁰.

The routine writes the initial scaled value at 16 times the initial record index plus 20. D011 receives the initial scaled value in all three visible argument positions.

D015 supplies a **secondary index**. The routine writes the initial scaled value at four times the secondary index plus 20. D016 receives four times the secondary index.

D020 supplies an **initial selector word**. Before D021, the routine writes the working byte input:

1. At initial byte base plus 17.
2. At initial byte base plus 1.

D021 receives the initial selector word shifted left by two. D022 supplies a word passed to D023.

D027 supplies another word. Before forwarding that word shifted left by two to D028, the routine repeats the byte-input writes in the same order: initial byte base plus 17, then initial byte base plus 1. These are four distinct stores separated by dependency activity.

D032 supplies an **early record index**. The routine then performs, in order:

1. A word store of the secondary index shifted left by 31, at 16 times the early record index plus 20.
2. A word load at 20 plus the unsigned value of the initial selector word’s bits 20–29.

The computed word-load address ranges from 20 through 1043 and need not be word-aligned. The loaded word is retained for a following argument calculation.

### 2. First byte-selected updates and global capture: D033–D056

D033 receives four times the early record index. D034 supplies a **saved payload word**. D035 receives the previously loaded word shifted right by 22, then left by 28.

D039 supplies an index. The routine writes a zero word at four times that index plus 20; D040 then receives four times that index.

D044 supplies a **byte payload word**. The routine:

1. Loads the byte at initial byte base plus 1.
2. Writes the low byte of the byte payload word shifted left by two, at the loaded byte plus 17.

D045 receives the byte payload word shifted left by two. D046 supplies a word passed as D047’s first visible argument; D047’s second is the byte payload word shifted left by 30.

D051 supplies another index. Immediately afterward, the routine:

1. Reloads the byte at initial byte base plus 1.
2. Retains this value as the **cached byte index**.
3. Writes at cached byte index plus 17 the low byte of the byte payload word masked to 30 bits and shifted right by 20.

D052 receives four times D051’s index. After D053–D056, the routine writes the saved payload word shifted left by two at cached byte index plus 20.

This word destination uses the retained byte, not a fresh selector load. Changes to the original selector location during D052–D056 do not redirect that store.

Immediately after the cached-index word store, the routine reads the global word and retains that captured value. Later dependency changes to the global do not replace the captured value.

### 3. First paired result and propagation: D057–D083

D063 supplies a word. D064 receives that word and the first scaled pair value shifted left by 28.

D083 supplies a new destination index. The routine writes the same retained first propagated word at four times that index plus 20. The two propagation destinations may coincide.

### 5. Middle propagation and final-record selection: D108–D131

Define:

- **Middle scaled index:** middle index shifted left by two.
- **Middle propagated word:** middle index shifted left by 14.

After D109–D112, the routine writes the middle propagated word at middle scaled index multiplied by 4096, plus 20. Under truncating arithmetic, this destination is also middle propagated word plus 20.

D119 supplies an index. The routine writes the retained middle propagated word at four times that index plus 20. D120 receives four times that index.

D124 supplies the **final record index**. The routine reloads the byte at four times the second scaled pair value plus 1 and writes, at that byte plus 17, the low byte of the middle propagated word masked to 30 bits and shifted right by 20.

D125 receives the middle index shifted left by 26. D126 supplies a word. D127 receives that word and four times the final record index shifted left by 28.

D128 supplies another paired result. D129 receives its low half followed by its high half.

D131 supplies an index. The routine again reloads the byte at four times the second scaled pair value plus 1 and writes zero at that byte plus 17.

### 6. Final propagation and repetition: D132–D146

D132 receives D131’s index shifted left by two.

D136 supplies a word. Its left shift by two is the **final propagated word**. The routine writes that word at four times the final record index multiplied by 4096, plus 20.

D137 receives four visible arguments, in order:

1. Final record index multiplied by 4096.
2. Final record index multiplied by 4096 again.
3. Final record index shifted left by 14, equivalent to multiplication by 16384 under truncating arithmetic.
4. Final propagated word.

Only the first two arguments are necessarily equal. The third is not generally equal to them.

D141 supplies another destination index. The routine writes the retained final propagated word at four times that index plus 20. D142 receives four times that index.

Before D146, the routine establishes the fixed replacement link state. D146 supplies the **next-iteration index**.

The loop transition then occurs in this order:

1. The first working word becomes four times the next-iteration index.
2. The working byte becomes zero.
3. That computed word is stored at 16 times the next-iteration index plus 20.
4. The second and third working words become the same computed word.
5. Execution repeats without a termination check.

On every reached iteration after the first completed transition, D001 receives three equal working words, and the four early byte-input stores write zero.

## Side effects

A completed iteration contains:

- 146 indirect calls.
- 13 explicit 32-bit stores.
- 14 explicit byte stores.
- 10 explicit selector-byte loads.
- One computed-address word load.
- One global-word load.

Dependency effects are additional and unresolved.

Explicit stores are ordered as described, but the sequence is not transactional. No rollback, cleanup, retry, or recovery appears if execution stops partway through.

Address overlap is not excluded. Earlier writes can affect later reads, including through overlap between byte-selected destinations and selector storage. Intervening dependencies can introduce further changes. No dependency is assumed to preserve the global word, selector bytes, or destination memory.

There are no visible bounds checks, null checks, alignment checks, locks, or explicit error handling. Neither exclusive access nor atomicity is established.

No explicit allocation, release, reference-count change, or ownership transfer is established. A dependency receiving an address-like value is not thereby known to acquire ownership, retain storage, or release memory.

## Acceptance examples

These are conditional static examples, not executed tests. They assume the stated truncating arithmetic, accessible memory, returning dependencies, and execution reaching the relevant operation.

1. **Initial forwarding and store.** With first word input `0x12345678` and D005 returning index 3, the first explicit word store writes `0x12345678` at address 32. D001 has already received all three original word inputs.

2. **Initial byte-base truncation.** With initial record index 5, the initial byte base is `0x40000000`. With byte input `0xA5`, the first pair writes `0xA5` at base plus 17, then base plus 1. The pair repeats after D027.

3. **Computed word-read boundary.** If the initial selector word’s bits 20–29 are zero, the computed word read uses address 20. If all ten bits are one, it uses address 1043. The latter address does not establish permissible unaligned access.

4. **Unscaled byte destination.** A selector load returning 250 selects byte destination 267. It does not select a destination formed by multiplying 250 by a record size.

5. **Cached versus refreshed selector.** If the cached byte load after D051 returns 7, the subsequent cached-index word store uses address 27 even if D052–D056 change the original selector byte to 9. Later explicit reloads may observe 9.

6. **Byte truncation.** A byte payload word of `0x00000041` produces a shifted byte store of `0x04`, because the wider shifted value is truncated to eight bits.

7. **Distinct four-argument scales.** With final record index 1, D137’s first three arguments are 4096, 4096, and 16384. The preceding final-propagation store uses address 16404.

8. **Unresolved secondary argument.** Whatever the middle index, D115’s first argument is zero under truncating arithmetic. Its second argument remains unspecified; the zero first argument does not constrain it.

9. **Loop-carried state.** If D146 returns index 6, the loop-transition store writes 24 at address 116. The next D001 receives 24 in each of its three visible argument positions, and the next iteration’s four early byte-input writes carry zero.

10. **Interrupted iteration.** If a dependency fails to return after a store, later operations are not guaranteed. No explicit rollback or normal error result follows from the visible body.
