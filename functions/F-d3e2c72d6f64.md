# F-d3e2c72d6f64

## Purpose

F-d3e2c72d6f64 selects between a short return path, a delegated processing path, and a path represented as non-returning.

The selection begins with a 16-bit field read from an input record. A nonzero field leads to a normal return value of 4 after one mandatory dependency call. A zero field enables an indirect object query:

- A zero query result leads to construction of temporary storage, a delegated operation, and a normal return value of 0.
- A nonzero query result leads to additional indirect calls followed by a dependency designated as non-returning.

These numeric results are established behavior, not established semantic labels. The available evidence does not identify 0 as “success,” 4 as a particular error, or the non-returning path as a specific kind of termination.

Consequently, changes made by F-b7af80e829ec to the record’s selector do not change this invocation’s branch selection. Its side effects, failures, or failure to return remain observable even on the short return path.

### Nonzero-query path

When the indirect query returns nonzero, the function performs the following ordered calls:

1. Invokes the acquired object’s dispatch entry at byte offset 0xf8, passing that object.
2. Invokes its dispatch entry at byte offset 0xe8, again passing that object.
3. Uses the second call’s result as another object address.
4. Invokes the returned object’s dispatch entry at byte offset 0xa0, with no explicit arguments shown.
5. Calls F-feee9156a257 with the returned object address.

The results of the calls through offsets 0xf8 and 0xa0 are not otherwise consumed.

The original object’s dispatch table is read again for the call through offset 0xe8. A change to its dispatch-table pointer during the preceding call can therefore affect the next target. The function does not establish a single immutable dispatch-table snapshot.

The final dependency is represented as non-returning. Under that representation, this branch has no normal return value and does not continue into temporary initialization or F-dece790ddc92.

There is no explicit payload read on this branch.

## Side effects

### Direct effects

The function directly:

- Reads the selector from the caller-provided record.
- Conditionally reads the record’s first 32-bit word.
- Reads object and dispatch-table storage needed for indirect calls.
- Writes one zero byte into temporary local storage.

No explicit assignment modifies the input record, the acquired object, the returned object, or a named global.

This absence of direct stores is not a guarantee that those objects or global state remain unchanged. Every invoked dependency may have additional effects.

### Ordering and state visibility

Dependency calls are ordered as described in the behavior section. No guarantee is made that a dependency preserves globals, record contents, object contents, dispatch tables, or allocation state.

Important consequences include:

- Selector changes after the initial read do not alter branch selection.
- Payload changes before its later read can alter the delegated argument.
- Payload changes after that read do not alter the captured argument.
- Object changes during one indirect call may affect later dispatch.
- A dependency that does not return prevents all subsequent operations on that path.

### Ownership and lifetime

The function performs no explicit allocation, deallocation, reference-count adjustment, or release operation.

That does not establish ownership semantics for any dependency. In particular, the calls on the nonzero-query path cannot be labeled as cleanup, destruction, release, or ownership transfer from this evidence alone.

Temporary storage has invocation-local lifetime. The function provides its address to dependencies while executing, but no longer-lived allocation or lifetime extension is visible. Whether any dependency retains that address, and what restrictions govern such retention, remain unknown.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Each assumes valid storage and normally returning dependencies except where stated otherwise.

1. **Nonzero selector.**  
   With a captured selector of 1, F-b7af80e829ec is called once and the function returns 4. No explicit indirect call or payload read follows. A selector of −1 has the same branch behavior.

2. **Selector changed by acquisition.**  
   With an initial selector of 0, acquisition may change the stored selector to a nonzero value. The function nevertheless proceeds to the query because it uses the captured zero.

3. **Short path despite later zero.**  
   With an initial nonzero selector, acquisition may change the stored selector to zero. The function still returns 4 after acquisition returns.

4. **Zero query with ignored delegated result.**  
   With an initial zero selector and a zero query result, the function captures the payload, performs both initializer calls, writes the trailing zero byte, and calls F-dece790ddc92. Any ordinary return value from that dependency leaves the wrapper’s normal result at 0.

5. **Payload changes before capture.**  
   If acquisition or the query changes the payload before the zero-query processing path reads it, argument 2 to F-dece790ddc92 reflects the changed value.

6. **Payload changes after capture.**  
   If an initializer changes the payload after capture, argument 2 retains the captured value. The record passed as argument 1 may contain the newer value.

7. **Negative query result.**  
   A query result of −1 takes the same path as any other nonzero result: dispatch offsets 0xf8, 0xe8, and then 0xa0 on the returned object, followed by F-feee9156a257. No normal return is represented.

8. **Acquisition does not return.**  
   Even with a nonzero selector, the function does not return 4 if F-b7af80e829ec never returns.
