# F-ef52d6a65642

## Purpose

F-ef52d6a65642 transforms memory through a single ordered path involving incoming addresses, six global values, narrow signed reads, and arithmetic-derived addresses. It then passes a partially initialized stack region to an incoming callable, invokes F-cdec09f5d432, and, if both calls return, reaches an explicitly non-returning terminal operation.

No application-level purpose is established. The evidence does not justify describing the function as an allocator, constructor, serializer, or collection operation. References to “fields” below mean fixed-offset memory accesses, not a validated object layout.

This contract describes the supplied static representation. All later behavior is conditional on earlier operations completing and control continuing. No runtime tests have been performed.

## Behavior

### Observable ordering and value retention

The function has one represented execution path, not a set of independent updates. Reads observe memory at their particular positions. Stores may therefore affect later reads through overlapping addresses.

Two initial observations have different timing:

- The entry-base word at offset 100 is read before the initial halfword store. This **retained entry word** is used later even if its original location changes.
- The entry-base word at offset 68 is read after the initial halfword store. Its value may already reflect that store.

The initial halfword destination is the entry base plus the third argument; its payload is the low 16 bits of the entry payload.

The first argument’s offset-100 word is sampled four times during propagation. The low bytes of these four samples have distinct consumers. They are not interchangeable observations.

A narrow write affects only its stated width. “Low byte” and “low halfword” below describe payload narrowing, not a wider destination update.

### Propagation structure

The six globals participate in successive transitions, but the transitions are not identical operations.

Each transition includes a cursor self-address store at offset 84, an outgoing offset-68 replacement, and a 32-bit predecessor value written at offset 20 of the captured global value. Their common ordering is:

1. The cursor self-address store occurs before the global capture.
2. The outgoing offset-68 replacement follows that capture.
3. The captured-global offset-20 store follows the replacement.
4. The cursor offset-17 byte update follows that store.

The destinations and payloads vary as follows:

| Transition | Cursor | Outgoing offset-68 destination base | Predecessor stored at captured-global offset 20 | Cursor offset-17 payload |
|---|---|---|---|---|
| G1 | Initial cursor | Entry payload | Initial entry-base offset-68 word | Twice the cursor, narrowed |
| G2 | Initial cursor | Early byte-derived address | Reload from captured G1 offset 68 | First offset-100 sample |
| G3 | Cursor obtained during G2 | Base sampled during G2 | Word obtained through the G2 offset-116 result | Second sample |
| G4 | Same cursor as G3 | Base sampled during G3 | Word obtained through the G3 offset-116 result | Twice the cursor, narrowed |
| G5 | Cursor obtained during G4 | Base sampled during G4 | Reload from captured G4 offset 68 | Third sample initially |

The outgoing offset-68 payload is a separately referenced value of that transition’s global. Except for the initial G1 destination, the destination base comes from preceding memory observations, not from a proven link structure.

### G1: initial address-bearing byte

After the initial entry reads and the G1 transition, the function takes the first offset-100 sample. It then reads a signed halfword at the initial cursor plus captured G1, followed by a byte at that signed value plus the initial entry-base offset-68 word.

That byte is subsequently used as an address-bearing value. Its effective numeric value depends on unresolved plain-byte promotion.

Before G1 offset 68 is reloaded, five stores occur in this order:

- A byte at first-argument offset 1, from captured G1.
- A byte at captured G1 offset 13, from the initial offset-68 word.
- A full word at captured G1 offset 68, from the retained entry word.
- A byte at offset 13 of the byte-derived address, from captured G1.
- A halfword at the signed-halfword value plus captured G1, from the promoted byte.

The G1 offset-68 reload follows all five stores. It cannot generally be replaced by the retained entry word: intervening writes may overlap its location.

### G2 and G3: offset-116 traversal

After the G2 transition, the function takes the second offset-100 sample. Its next observations, in order, are the initial cursor’s offset-68 word, a signed halfword at that cursor plus captured G2, a word at offset 116 of the G1 reload, and the initial cursor’s offset-20 word. The last observation supplies the cursor used by G3 and G4.

The G2 offset-116 result has two roles. Its low byte is written at offset 13 of the sampled cursor-offset-68 base. It also combines with the signed halfword to address a halfword store whose payload is the sampled base’s low halfword. Only after those stores is its offset-68 word read as the G3 predecessor.

Following the G3 transition, the new cursor’s offset-68 word and a signed halfword at cursor plus captured G3 are read. A byte from captured G3 is written at predecessor offset 21, and the full predecessor is written at captured G3 offset 68.

The sampled cursor-offset-68 base is then followed through offset 116. That result, added to the signed halfword, addresses another halfword store narrowed from the sampled base. Reading the result’s offset-68 word supplies the G4 predecessor.

These traversals do not establish ownership, a list, or any particular data structure.

### G4 and G5: retained-word propagation

After the G4 transition, the third offset-100 sample is taken, followed by the current cursor’s offset-68 word and a signed halfword at cursor plus captured G4. A word read directly at signed-halfword value plus offset 20 supplies the next cursor.

The subsequent writes have this order:

- The sampled offset-68 base receives its own address at offset 84.
- Captured G4 plus the predecessor receives the full retained entry word.
- Captured G4 offset 20 is replaced with the sampled base.
- A fresh 32-bit read through retained-entry-word offset 68 supplies a byte for captured G4 offset 13.
- The new cursor’s offset-13 byte and the halfword at signed value plus captured G4 receive narrowed forms of the sampled base.

Captured G4 offset 68 is reloaded after these effects.

G5 begins with the transition described above, including the third sample’s byte at cursor offset 17. It then takes the fourth offset-100 sample, reads cursor offset 68, and reads a signed halfword at cursor plus captured G5.

Before obtaining another cursor through signed-value offset 20, G5 has three additional effects, in order:

- Offset 84 of the preceding G4 reload receives the current cursor. This is not necessarily a self-address store.
- Current cursor offset 17 is overwritten with the fourth sample’s low byte.
- The newly sampled base’s offset 68 receives captured G5.

The signed-value offset-20 read then supplies the cursor used by G6. G5 subsequently has the same retained-word write pattern described for G4, using G5’s sampled base, predecessor, and signed value. Its read through retained-entry-word offset 68 is fresh, not shared with G4. Captured G5 offset 68 is reloaded afterward.

### G6: multiplicative traversal

After the G6 transition, the function reads the current cursor’s offset-68 word and a signed halfword at cursor plus captured G6. This signed value remains the multiplier used in the following traversal.

Before the first product-based read, two consecutive identical write pairs occur. Each pair writes the signed value to its own offset 84, then writes the current cursor’s low byte at captured G6 offset 17. Both pairs are represented; matching payloads do not erase the second pair from the access sequence.

The first product combines the signed value with the sampled cursor-offset-68 word. Traversal from that address follows 32-bit fields at offsets 68, 116, and 20. The resulting container’s offset-20 word is read and retained before that same field is overwritten with twice the current cursor.

The retained field value—not the replacement—is followed through offset 20. That read is multiplied by the signed value to form the next product address. Before its offset-116 read, another signed-value self-address store occurs, followed by a G6 offset-17 byte write from the retained field value.

The product’s offset-116 word supplies the **derived value**. This observation also establishes the stack-offset-264 assignment at this point, before subsequent traversal writes and before final stack preparation.

### Final arithmetic-derived memory effects

The preceding product is multiplied once more by the signed value to obtain the **final product base**. A signed-value self-address store and a G6 offset-17 byte write from the derived value precede the final reads and writes.

The final product base’s offset-68 word is read before the first argument’s offset-116 word. Captured G6 offset 100 then receives the full derived value, and captured G6 offset 9 receives the low byte of that first product-base read.

The product-base offset-68 word is read again, after the G6 offset-9 write. This second observation supplies the byte written at final-product-base offset 17. Reusing the first observation is not equivalent under aliasing.

Another signed-value self-address store precedes a byte write at twice the final product base plus offset 17, with payload narrowed from the derived value.

A further offset-68 word is read through the product of the signed value and the final product base. The first argument’s offset-20 word is then read as a destination base. The concluding non-stack writes are, in order:

- Derived-value offset 1 receives a byte from the earlier first-argument offset-116 observation.

- Destination offset 9 receives the low byte of twice the final product base.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Initial overlap.** If the third argument is 68, the initial halfword store overlaps the subsequent entry-base offset-68 word read. That read must reflect the intervening write according to the environment’s byte order. The entry-base offset-100 observation has already occurred.

2. **Signed halfword.** If a halfword read produces −1, subsequent arithmetic uses the signed value, subject to the unresolved arithmetic model. Treating it as positive 65,535 changes the established input to that arithmetic.

3. **Fresh observations.** If an intervening write changes first-argument offset 100, later samples may differ. Likewise, G4 and G5 must use their respective fresh reads through retained-entry-word offset 68.

4. **G5 intermediate rewrite.** On reaching G5’s additional writes, cursor offset 17 receives the fourth sample after its earlier third-sample write. At the preceding offset-84 destination, the payload is the current cursor, not necessarily that destination’s base.

5. **Replacement versus retained traversal.** After a container’s offset-20 word is replaced with twice the cursor, the following traversal still uses the value read before replacement.

6. **Repeated product-base read.** If the G6 offset-9 write overlaps final-product-base offset 68, the later read used for the offset-17 byte can differ from the earlier read. Caching the earlier value would violate the ordering contract.

7. **Duplicate access pairs.** Where access repetition is observable, both consecutive signed-value offset-84/G6 offset-17 pairs must remain observable.

8. **Call boundary.** On entry to the indirect dependency, unspecified stack bytes are not guaranteed zero. If that dependency does not return, none of the post-call stack writes or the F-cdec09f5d432 invocation follows.

9. **Terminal reachability.** If F-cdec09f5d432 does not return, the terminal operation is not reached. If it returns, no supported ordinary return path follows.
