# F-91379f4bd2c8

## Purpose

F-91379f4bd2c8 constructs a 32-bit configuration word from an explicit input and several ambient values, writes that word to an ambient destination, invokes F-356357e9691d, and then writes two one-byte records through a global base reference.

The ordinary completion result is a 32-bit zero. The supplied representation contains no explicit validation, allocation, cleanup, failure return, or retry.

This contract distinguishes:

- **Established static evidence:** operations and ordering directly represented in the supplied material.
- **Inferred intent:** interpretations such as “configuration word” and “record,” used for readability rather than as established domain semantics.
- **documented_only unknowns:** information that cannot be established from the supplied material.

## Interface

### Explicit input and result

The explicit input is represented as a 32-bit signed integer. Its bit pattern contributes to a 32-bit left-shift operation and normally becomes the second argument to F-356357e9691d.

The result is a 32-bit value whose bit pattern is zero, provided execution reaches the return.

An odd-selector branch replaces the value passed as the second argument to F-356357e9691d. It does not replace the already computed shifted contribution.

## Behavior

### Initial word and mode-dependent contribution

The initial configuration contribution is the explicit input shifted left by 14 bit positions.

Under the 32-bit bit-vector interpretation of the supplied operations, the initial contribution is the low 32 bits of that shift. Consequently:

- Its low 14 bits are zero.
- Only the input’s low 18 bits contribute.
- A nonzero input can produce a zero contribution when those low 18 bits are all zero.

The conditional mode contribution depends on the shifted result, not on whether the original input is nonzero:

- If the shifted contribution is nonzero and Mode equals exactly 3, bits represented by mask `0x3000` are OR-ed into the word.
- Otherwise that OR operation is omitted.

Because the explicit input is represented as signed, the exact source-language meaning of left-shifting a negative value or a value beyond signed range is not established. The bit-vector account describes the represented word construction; it is not a portability guarantee for an independently compiled signed-language expression.

### Selector-dependent construction

Exactly one of the following cases applies. Selector comparisons use its full unsigned 32-bit value.

| Selector condition | Additional construction | Odd-branch dependency |
|---|---|---|
| Selector equals 1 | No selector-dependent contribution | Not called |
| Selector is less than 18 and is not 1 | OR the Low-range contribution into the word | Not called |
| Selector is at least 18 and even | OR the Even-range contribution and `0x10` into the word | Not called |
| Selector is at least 18 and odd | Obtain a two-word result and OR its derived nibble and `0x20` into the word | Called once |

Selector zero belongs to the low-range case. Selector 17 also belongs to that case despite being odd. Selector 18 is the first even-range case; selector 19 is the first odd-range case.

The Low-range and Even-range contributions are not masked. They can therefore set any configuration bit, including bits outside the apparent selector encoding. No branch clears bits already present.

### Odd-range dependency result

For Selector values at least 18 and odd, an additional dependency is invoked. This contract assigns it the local opaque identifier **F-000000000001** because no authoritative opaque mapping for that dependency was supplied.

No explicit arguments are shown for this call. That does not establish that it has no ambient inputs or hidden calling-convention requirements.

The result is represented as two 32-bit words:

- The low word supplies a four-bit contribution: subtract one and retain only the low four bits.
- The high word replaces the second argument later passed to F-356357e9691d.

The nibble transformation is modulo 16. A low word of zero yields 15; a low word of one yields zero; a low word of 17 also yields zero. This is not a range check, and values outside a presumed 1–16 range are not rejected.

The high word is represented as converted to a signed 32-bit value before the later call. Its role is established at the 32-bit word level; any stronger numerical interpretation depends on the target’s integer representation and conversion rules.

### Configuration write and main dependency call

After the word has been fully constructed, the function writes it as a 32-bit value at Configuration base plus 16 bytes.

It then calls F-356357e9691d with two explicit arguments:

1. The integer value 100.
2. The original explicit input, except in the odd-range case, where the high word returned by F-000000000001 is used instead.

The configuration write precedes this call. The final byte stores follow its normal return.

No result from F-356357e9691d is visibly inspected. This does not establish that the dependency cannot fail, transfer control elsewhere, modify memory, or alter global state.

### Final base reads and byte stores

After F-356357e9691d returns, the supplied representation shows this sequence:

1. Read the global record-base reference and retain that value for the later Selector-byte store.
2. Evaluate the global record-base reference again for the Mode-byte destination.
3. Store the low eight bits of Mode at that second base value plus Record displacement.
4. Store the low eight bits of Selector at the earlier captured base plus 17 bytes plus Record displacement.
5. Return the 32-bit value zero.

This distinction matters if the reference changes between its evaluations. A specification that unconditionally uses one captured base for both stores would erase a distinction present in the supplied representation.

The representation establishes two evaluations at this level. Whether the executable performs two distinct physical reads, and whether asynchronous changes are meaningful or permitted, are **documented_only**.

The stored bytes retain only the low eight bits of their source values. In particular, configuration branching uses the full Selector, not its eventual byte-sized record.

## Side effects

### Direct writes

On ordinary completion, the function directly performs one 32-bit write followed later by two 8-bit writes. It does not directly write the global record-base reference.

The direct-write order is:

1. Configuration word.
2. Mode byte.
3. Selector byte.

F-356357e9691d executes between the first and second writes. F-000000000001, when applicable, executes before all three.

### Aliasing

No non-aliasing guarantee is visible.

The configuration destination can overlap either record destination or other state. The two record stores can also target overlapping or identical locations if their evaluated bases differ appropriately. Where writes overlap ordinary memory, later writes determine the affected final bytes, subject to intervening dependency effects.

If a destination aliases the global record-base reference itself, earlier writes can influence subsequent address formation. Such arrangements are not validated or prohibited by the supplied body, but their validity on the actual platform is **documented_only**.

### Ownership and dependency effects

No direct allocation, release, ownership transfer, reference-count operation, or resource acquisition is visible.

No assumption is made that either dependency preserves globals or owns, retains, or releases memory. In particular, F-356357e9691d may affect the global record-base reference before this function reads it.

### Errors and interruption

There is no visible local error branch or rollback.

If F-000000000001 does not return, the configuration write and later operations are not reached. If F-356357e9691d does not return, the configuration write has already occurred but the final byte stores are not reached through the represented path.

A fault during a write may leave earlier writes intact. The supplied material does not establish an exception mechanism or an atomic transaction spanning these operations.
