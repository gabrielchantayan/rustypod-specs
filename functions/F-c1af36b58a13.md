# F-c1af36b58a13

These are structural descriptions. “Input,” “output,” “preparation,” and “reset” describe observed argument flow and direct operations, not an established resource type, encoding, or public API.

## Behavior

### Entry and admission

The first operations are three 32-bit stores of zero, respectively to `+0x14`, `+0x18`, and `+0x1c`.

The function then reads `+0x04`. If bit `0x08` is clear, it immediately returns `0xffffffff`, without calling a dependency.

Otherwise, it calls F-cf17a2203afd with the object address. Its represented result is 64 bits, but only the low 32 bits govern admission. Zero in those bits causes an immediate `0xffffffff` return.

The upper 32 bits do not affect subsequent control flow: where a later decision needs another value, it either takes an already-determined branch or obtains a fresh object-derived value. No object or global preservation guarantee is established for this prerequisite call.

### Input selection and pending-processing decision

After prerequisite success, the function reads bit `0x04` at `+0x10`.

When clear, it captures the input start from `+0x08`, then the endpoint from `+0x24`.

When set, it stores the supplied value in four-byte local storage. The selected start is the beginning of that storage, and the endpoint is one byte beyond its beginning. Only one byte is selected.

That byte is the first byte of the stored representation. Without established byte order, it cannot be equated with the numerical low eight bits. The terminal fallback has a separate, explicit numerical mask.

After the mode-dependent capture or local-value store, the function separately reads `+0x24` for the pending-processing decision:

- If this read is nonzero, processing is entered without another mode-bit read for this decision.
- If zero, the function freshly reads bit `0x04` at `+0x10` and enters processing only if that bit is set.
- If neither condition holds, it proceeds to reset.

The endpoint capture and pending-processing read are distinct reads, even though both may access `+0x24`. The mode reads likewise do not form one guaranteed stable snapshot.

### Conditional preliminary operation

On entering pending processing, the captured pending-processing operand is compared with a read of `+0x28`.

Equality proceeds directly to output preparation.

Inequality causes a call to F-d52d006afc42 with the object and the full supplied 32-bit value:

- A nonzero result proceeds to preparation.
- A zero result causes a fresh read of bit `0x04` at `+0x10`.
- If that bit is set, preparation proceeds.
- If clear, both output preparation and reset are bypassed, and execution reaches the terminal sequence.

Thus, zero from this preliminary call is not itself an explicit failure. The selected input addresses are retained across the call rather than recaptured afterward.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Numerical arithmetic examples assume valid, representable addresses and arithmetic.

1. **Eligibility rejection:** With eligibility clear, the three entry clears occur in order, no dependency is called, and the result is `0xffffffff`.

2. **Prerequisite rejection:** A prerequisite result with zero low 32 bits causes failure regardless of its upper bits.

4. **Preliminary bypass:** If the pending operand differs from `+0x28`, the preliminary call returns zero, and the subsequent mode read is clear, preparation and reset are skipped. The terminal sequence still occurs.

5. **Direct result need not equal length:** For a captured difference of `12`, a writer result of `1` is accepted. Bookkeeping adds `12`, not `1`.

6. **Two conversion lengths:** If conversion leaves output-end at scratch start plus `5`, the writer receives length `5`. If writer-side activity changes that exposed value to scratch start plus `9` and returns nonzero, accumulation adds `9`.

7. **Later conversion failure:** If one iteration’s writer succeeds and a later conversion returns `2`, the caller immediately returns `0xffffffff`. It issues no subsequent bookkeeping, reset, terminal sequence, or compensation. Persistence of previous dependency effects is unresolved.

8. **Equal nonnull bounds:** With conversion-mediated output selected and equal nonnull captured bounds, an initial conversion call still occurs because next-input initially equals null.

9. **Null endpoint:** With conversion-mediated output selected and a null endpoint, conversion and writer calls are skipped. Successful-output bookkeeping executes with zero accumulated length.

10. **Writer failure:** A zero conversion-path writer result prevents the post-call output-end reread and accumulation, as well as successful-output bookkeeping and the terminal sequence.

11. **Terminal masking:** For supplied value `0x123456ab`, the conditional fallback receives `0xab` when the terminal preliminary result is zero and the following mode read is clear. The final return still comes from F-9916da3e9ea8.
