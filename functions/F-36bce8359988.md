# F-36bce8359988

## Purpose

F-36bce8359988 dispatches three operations. On an accepted path that completes normally, it publishes one 32-bit word through a caller-supplied destination and returns one. An unsupported operation or selector mismatch returns zero without an explicit publication.

Two operations publish dependency-produced values. The third processes object-relative storage and publishes that storage’s address.

A guard-controlled sequence precedes operation validation. Consequently, even a rejected request can invoke dependencies and change externally visible state.

These are established static behaviors. “Initialization,” “resource,” “context,” and “processing” below describe apparent roles, not verified dependency semantics.

## Interface

### Arguments and return value

| Input | Width or representation | Contractual use |
|---|---|---|
| Object word | 32-bit word | Passed to dependencies; also used as the address base for operation `0x6610`. |
| Selector | Unsigned 32-bit word | Compared with an operation-specific global selector. Ignored by operation `0x6604`. |
| Operation | 32-bit integer | Recognizes exactly `0x6604`, `0x6610`, and `0x6614`. |
| Payload | Opaque 32-bit word | Copied locally, then supplied by value or through the address of that copy. |
| Result destination | Address of four writable bytes | Receives the published 32-bit word on an accepted, normally completing path. |

The 32-bit return value is:

- **Zero:** operation unsupported or required selector mismatched.
- **One:** the final result store completed.

One is not a dependency-success indicator. Zero-valued dependency results can be published with status one. No independent validation of allocations, resources, processing results, ownership, or lifetime is visible.

## Behavior

### Preliminary guard-controlled sequence

Before dispatch, the function captures the primary-root global. It then separately evaluates that global again and reads a 32-bit guard at the second value plus `0x24`. Incoming arguments are copied into local storage before the already-read guard’s bit zero is tested.

The captured root and the root used for this guard read are distinct observations. They need not agree.

If bit zero is set, the primary initialization calls are skipped. If clear, F-b255b26284e6 receives another freshly evaluated primary-root value plus `0x24`.

A zero acquisition result skips the remaining primary initialization calls. A nonzero result causes the following call chain:

- F-5b24edfb22c0 receives the **original captured root plus `0x38`**.
- F-804adc29bbfb receives that result and two global configuration words.
- F-d08d3ca17b81 receives the **original captured root plus `0x24`**.

The configuration words occupy fixed second and third argument positions. Their relative evaluation order within the call is not established.

Thus, the initial guard read, acquisition, and later initialization arguments can refer to different root observations. No global-root stability or synchronization guarantee is visible.

Dispatch proceeds whether acquisition returns zero or the completion-like call returns another value. Neither outcome directly rejects the request.

No store explicitly targets a guard by its guard address. This does **not** make guard contents dependency-only state: dependencies may modify them, and the final result publication can directly overwrite guard storage when the result destination aliases it.

### Operation `0x6604`: ungated publication

This operation accepts any selector.

F-f0da878d5c87 receives the original object word and copied payload value. Its result is supplied to F-7afe554bcf62 together with the address of the four-byte wrapper region.

F-46f0b3cb316e then receives the operation’s global destination value and the wrapper-producing call’s result. F-289ec4311c64 subsequently receives the wrapper-region address.

Only after that call returns is the destination global loaded again. F-44362605ab79 receives this new observation, and its 32-bit result is published.

The destination used for extraction need not equal the earlier destination supplied to F-46f0b3cb316e. Intervening dependencies are not assumed to preserve that global.

The wrapper sequence suggests preparation, use, and cleanup. It establishes neither allocation nor release semantics.

### Operation `0x6614`: selector-gated classification

The selector is compared with this operation’s dedicated global selector after preliminary initialization. A mismatch returns zero without calling F-d06cb787016b or explicitly publishing a result.

For a match, F-d06cb787016b receives the original object word and copied payload value. Its 32-bit result selects zero, one, or all other bit patterns.

**Classification zero or one.** F-9d0ecc5f6adf is called first. The corresponding zero-case or one-case resource global is loaded after that call returns. F-c0b020cd3882 receives the context-like result and selected resource. Its result is published directly.

The resource read is not an earlier snapshot: changes made by F-9d0ecc5f6adf can affect the argument.

**Any other classification.** Every other 32-bit pattern takes the shared-result path, including patterns interpreted as negative signed integers.

The function reads a 32-bit guard at the **original captured root plus `0x28`** and tests bit zero. This is not a fresh primary-root lookup.

If the bit is clear, F-b255b26284e6 receives a value loaded from a separate global guard-address slot. When that call returns nonzero:

- F-398e0e9a318a receives the shared-destination global and the address of a global data slot.
- F-804adc29bbfb receives its result and the same two configuration globals, in the same argument positions as primary initialization.
- F-d08d3ca17b81 receives a newly loaded value from the separate guard-address slot.

The tested guard location is not established to equal the acquisition address. The acquisition and completion arguments also need not agree, because they are separate global reads.

Shared-result production occurs whether the guard was already set, acquisition returned zero, or initialization completed. F-9d0ecc5f6adf runs, after which F-c0b020cd3882 receives its result and the shared-case resource global. F-1f62160dfd52 then receives the shared destination, the resource-producing result, and the original classification value.

After F-1f62160dfd52 returns, the shared-destination global is reloaded. F-44362605ab79 receives that observation, and its result is published. Neither the resource nor destination globals are assumed unchanged by preceding calls.

### Operation `0x6610`: selector-gated processing

The selector must equal this operation’s separate global selector. A mismatch returns zero without calling the operation’s processing dependencies or explicitly publishing a result.

For a match, F-50264aad3dd0 supplies a zero/nonzero discriminator.

1. The context-like result.
2. A second resource value loaded after the context call.
3. The fallback resource captured before that call.

F-4225f441f48b receives object plus `0x154`, the preceding result, and two 32-bit zero arguments. Its return value is not published. The function publishes object plus `0x154` and returns one.

**Nonzero discriminator: temporary-output processing.** F-ab2fcc048b68 receives the discriminator, the 36-byte temporary-region address, the copied payload value, the numeric argument eight, and the four-byte status-region address, in that order.

Afterward, only the first byte at the status-region address controls the branch. The remaining three bytes do not participate in this test.

If the first byte is nonzero, F-8c586dbad7fd receives the temporary region and object plus `0x154`. Fallback processing is skipped. The function publishes object plus `0x154`.

If the first byte is zero, F-280eb3d49abb receives object plus `0x218` and the address of the local payload copy. Only after it returns does this function read the four-byte comparison word at object plus `0x228`.

Equality between the dependency result and that post-call word causes F-98bc400129af to receive separate temporary output storage, object plus `0x218`, and the address of the same payload copy. F-280eb3d49abb may therefore influence both the comparison and the payload subsequently observed by F-98bc400129af.

Following the conditional call, the temporary output’s first 32-bit word is copied into two local words. Its immediately following byte replaces the low eight bits of another local word, retaining that word’s upper 24 bits. These copied values do not subsequently control a branch or the explicit publication.

Whether the comparison matched or not, the zero-status path proceeds through fallback processing and publishes object plus `0x154`.

No initialization of the status region or dependency-output regions is visible before their supplying calls. Defined downstream reads depend on suitable dependency-written contents. The unused copies do not establish that F-98bc400129af has no externally visible effects.

## Side effects

Established direct effects comprise global reads, guard reads, the conditional object comparison read, local-storage accesses, dependency calls, and the final four-byte publication on accepted paths.

The final store is not restricted to a separate output object. If its destination aliases a guard, it can change guard bits directly. If it aliases another global or object field, that storage receives the published word. Such a publication occurs after the dependency sequence for the selected path.

A rejected request performs no explicit result store. This does not guarantee an unchanged destination: preliminary dependencies may affect aliased or otherwise reachable storage.

Dependencies receive addresses of local storage, global storage, and object subregions. Their writes, synchronization, allocation, release, and address-retention behavior are not established. No dependency is assumed to preserve globals merely because its apparent role is unrelated to them.

The payload is passed into this function by value. Its addressable local copy can be modified on the lookup/construction path; no explicit writeback to caller payload storage is visible.

No explicit cleanup of the 36-byte temporary region is shown. Published values carry no established ownership transfer, permission to free, or indefinite lifetime guarantee. No rollback is visible if a dependency changes state and execution later fails to complete normally.

## Acceptance examples

These are conditional static cases, not executed tests. Unless specified otherwise, assume suitable memory, dependency-written outputs sufficient for subsequent reads, and normal dependency returns.

1. **Distinct root observations.** If the initial capture observes A, the initial guard evaluation observes B, and acquisition observes C, the first guard read is at B plus `0x24`. A clear bit permits acquisition at C plus `0x24`. Nonzero acquisition still leads to primary calls using A plus `0x38` and A plus `0x24`. A later shared-case guard read uses A plus `0x28`.

2. **Rejected request with effects.** An unsupported operation with a clear initial guard can invoke the primary initialization sequence, then return zero without explicit publication.

3. **Acquisition does not decide acceptance.** Zero from primary acquisition skips the remaining primary calls but does not prevent an otherwise accepted request from publishing and returning one.

4. **Ungated selector and destination reload.** Operation `0x6604` accepts an arbitrary selector. If F-289ec4311c64 changes the destination global, extraction receives its changed value.

5. **Publication aliases the primary guard.** Assume a stable primary root A, an initially set guard bit, and a result destination equal to A plus `0x24`. For accepted operation `0x6604`, if extraction returns zero and dependencies leave that guard unchanged, the final four-byte store clears the entire guard word. The function returns one. This direct guard modification is caused by publication, not by a dependency guard write.

6. **Selector mismatch.** A mismatching `0x6614` selector returns zero without classification. Preliminary initialization can already have occurred.

7. **Resource reload after context.** Classification one selects the one-case resource as observed after F-9d0ecc5f6adf returns, including any change made by that call.

8. **Nonbinary classification.** Classification `0xFFFFFFFF` selects shared processing and is forwarded unchanged to F-1f62160dfd52; it is not treated as an explicit error.

9. **Fallback discriminator.** A matching `0x6610` request with discriminator zero takes fallback processing and publishes object plus `0x154`, irrespective of the processing dependency’s return value.

10. **Byte-sized status decision.** A nonzero first status byte selects F-8c586dbad7fd even if the other three status bytes are zero. A zero first byte selects lookup/fallback even if those other bytes are nonzero.

11. **Post-call comparison and payload mutation.** If F-280eb3d49abb changes the comparison word, equality uses its changed contents. If it also changes the payload copy, conditional construction receives that modified copy. Equality invokes construction; inequality skips it. Both cases then execute fallback processing.
