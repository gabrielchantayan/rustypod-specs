# F-15a3a961bb13

## Purpose

It does not visibly validate its own input, the dispatch addresses derived from that input, or the readability of a non-null returned pointer.

## Behavior

The following order is established for an execution that reaches each operation normally:

1. Read the first 32-bit word from the input address.
2. Use that word as the dispatch-base address and locate the function-pointer slot 224 bytes beyond it.
3. Read the function pointer from that slot.
4. Invoke the selected function once.
5. Inspect the pointer returned by that invocation.
6. If the returned pointer is null, produce a 32-bit zero.
7. Otherwise, read one 32-bit word from the returned address and produce that word as the result.

There is no visible retry, alternate dispatch path, iteration, or second invocation. In particular, a null returned pointer does not cause another lookup or call.

The default result is established before dispatch, but the indirect call still occurs. Zero is not an early-return result for invalid input or invalid dispatch state.

### Result selection

The null test concerns the pointer returned by the callee, not the value stored at a non-null returned address. Consequently:

- A null returned pointer produces zero without a read through that pointer.
- A non-null returned pointer to a zero-valued word also produces zero, but requires the additional word read.
- A non-null returned pointer to a nonzero word produces that word.

The returned value alone therefore cannot distinguish “no pointer returned” from “a pointer to zero returned.”

There is no visible narrowing, sign extension, byte swapping, masking, saturation, or arithmetic on the selected result. The result is a 32-bit load in the target execution environment’s representation.
