## Behavior

### Conversion phase

The function invokes F-4e1ee8e86ebb three times, in a fixed order:

1. With the conversion context and the convertible header word.
2. With the conversion context and the requested transfer count.
3. With the conversion context and the prefix length.

Each invocation produces a 32-bit value retained for the header.

All three calls occur before this function’s first explicit record store. Consequently, dependency side effects occur before the header-writing phase. The function does not establish that these calls are pure, preserve globals, or leave the caller’s memory untouched.

The signed counts are supplied to the conversion dependency without any explicit range check. Negative values are not rejected here.

### Header-writing phase

After all three conversions return, the function performs four 32-bit stores in this order:

1. The converted prefix-length value at offset 12.
2. The direct header word at offset 0.
3. The converted convertible-header value at offset 4.
4. The converted requested-count value at offset 8.

This store order is distinct from the order of fields in the finished layout.

There is no explicit allocation, clearing, capacity check, or transaction boundary. Previously existing bytes outside the stores and later writes are not explicitly initialized.

### Prefix-copy phase

The function starts the payload cursor at offset 16.

If the signed prefix length is positive, it copies exactly that many bytes. The copy proceeds from the lowest offset upward. Each iteration reads one byte from the source address plus the current offset, then stores that byte at the current payload cursor and advances the cursor by one byte.

The source bytes are read after all four header stores. The operation is not a snapshot of the source before record construction.

Consequences include:

- A zero prefix length performs no prefix-source read and leaves the cursor at offset 16.
- A negative prefix length also performs no prefix-source read and leaves the cursor at offset 16.
- A positive prefix length advances the cursor to offset 16 plus that length.
- Overlapping source and destination ranges follow the observed forward byte-copy order, not a guaranteed overlap-safe bulk-copy contract.
- If the prefix source overlaps the header, the copy can read values already changed by the header stores.

There is no explicit terminator, padding, or alignment adjustment after the copied prefix.

### Transfer phase

After the prefix-copy phase, the function invokes F-5fa9dcb95913 with these four arguments, in order:

1. The current payload cursor.
2. The integer value 1.
3. The requested transfer count.
4. The transfer handle.

The destination is therefore immediately after the copied bytes, or at offset 16 if the prefix length is nonpositive.

The function makes this call even when the requested transfer count is zero or negative. It does not retry the call or explicitly compensate for a partial result.

The dependency’s returned signed 32-bit value is compared directly with the requested transfer count. Equality alone selects the success branch. There is no independent check that the returned count is nonnegative, that data was actually transferred, or that any reported count corresponds to initialized destination bytes.

### Completion phase

If the returned count equals the requested transfer count, the function stores the sum of the prefix length, the requested transfer count, and 16 through the reported-length destination, then returns 0.

This calculation uses the original signed prefix length, not the number of bytes actually copied. For a negative prefix length, the calculated value can therefore differ from the cursor position plus the requested transfer count.

If the returned count differs, the function returns 4 without an explicit reported-length store.

Failure does not undo the header stores, copied prefix bytes, or dependency effects. Even when the reported length is left untouched by this function, aliases or dependency effects can still have changed the memory designated by that pointer.
