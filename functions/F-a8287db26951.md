# F-a8287db26951

## Purpose

F-a8287db26951 dispatches a 32-bit operation word against mutable object state. Every visible normal-return path returns the 32-bit value zero or one.

Its established behavior includes an eligibility check, a one-shot override, indexed-position selection, ordered-entry processing, and a shared resolution-and-update path. These descriptions identify observable relationships, not established application semantics. In particular, returning one does not consistently mean that state changed, and returning zero does not imply that no processing occurred.

This contract describes static evidence only. It does not assume that dependencies preserve object fields, globals, associated pointers, or temporary contents.

## Behavior

### Initial eligibility and one-shot override

The first observable dependency call is F-b7abcf60c990 on the component at `0x060`.

If it returns zero, this function returns zero without directly reading or clearing the flag at `0x942`. The dependency itself may have changed that flag or other state; preservation is not guaranteed.

After a nonzero result, this function reads the flag. If the value then observed is nonzero, it writes zero to that byte and returns one without selector-specific processing.

Otherwise, the operation word masked with `0x7F` determines dispatch:

- Selector 0 returns zero.
- Selector 1 calls F-c314dc6fa2fa on the object. A nonzero result returns one; zero continues to the shared path.
- Selector 2 performs indexed-position selection.
- Selectors 3 and 4 enter the shared path directly.
- Selector 5 performs ordered-entry processing.
- All other selectors return zero.

Thus, the flag value observed after eligibility can override even an unsupported selector.

### Selector 2: indexed-position selection

The fourth argument is first copied into temporary storage. F-b7abcf60c990 is then called again on the component at `0x060`. A zero result returns zero. Otherwise, object dependency D01 is called; a nonzero result also returns zero.

Only after those checks does D19 enter the region at `0xA4C`. Every visible normal exit following this entry calls D20 on the same region.

The associated pointer is read. A null value causes exit and return zero. Otherwise, the receiver four bytes beyond this captured pointer is retained for this branch’s associated-receiver calls.

D02 obtains a count. If it is zero, the branch exits and returns zero. For a nonzero count:

1. D03 obtains a position from the object.
2. D04 maps that position to an index using the captured associated receiver.
3. If the index equals count minus one, selection is rejected.
4. Otherwise, D05 is called, followed by a read of a 32-bit global threshold. This read occurs even when D05 returns zero.
5. If D05 returned nonzero, D06 obtains the position at index plus one. This call occurs even if the index is not count minus two.
6. Only when that index is count minus two is D03 called again for an unsigned difference comparison. Selection is rejected if the position obtained in step 5 minus this new position, interpreted as a 32-bit unsigned result, is below the saved threshold.

If selection remains permitted, D06 obtains index plus one again. Its result becomes the candidate; an earlier result for the same index is not reused. The provisional successor is `0xFFFFFFFF` when index plus one equals count minus one; otherwise D06 obtains the successor at index plus two.

D05 is called again. If it returns nonzero, D03 supplies another position. When candidate minus this position, interpreted as unsigned 32-bit, is below the previously saved threshold, the candidate advances:

- D06 at index plus two supplies the new candidate.
- The successor becomes `0xFFFFFFFF` when index plus two equals count minus two.
- Otherwise, D06 at index plus three supplies the successor.

The second sentinel condition is distinct from the first. It is not a conventional test that the newly selected entry is last.

An accepted selection has this observable order:

1. D07 receives the selected position.
2. The selected position is written to `0x998`.
3. The successor is written to `0x994`.
4. The 32-bit notification global is read and saved.
5. That global is read again to obtain the argument for F-069a1d444a2d, which receives the object and this second value.
6. D08 is invoked on the embedded receiver at `0x014`, with the first, saved notification value and zero.
7. D20 runs, and the function returns one.

The two notification arguments originate from separate reads. No equality between them is guaranteed. Changes made by F-069a1d444a2d cannot replace the already saved argument subsequently supplied to D08.

The search compares entries in order, including the final entry.

If no comparison succeeds, or the successful comparison concerns the final entry, no subsequent-entry processing occurs.

Otherwise, processing begins with the entry immediately after the successful comparison:

- That entry is retrieved into an eight-byte temporary region.
- The unsigned traversal counter advances.
- F-1033f0501634 transfers the retrieved entry into the current-entry temporary.
- D09 receives that current entry, followed by zero, zero, three, three, zero.
- D10 is called.

Processing stops when D10 returns nonzero or the traversal counter reaches the count. If neither condition holds, the next entry is retrieved into a 16-byte temporary, and the same counter-advance, transfer, and processing sequence repeats.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Eligibility failure avoids direct flag access.** If the initial F-b7abcf60c990 returns zero, the result is zero without this function directly reading or clearing `0x942`. If the dependency changes that byte before returning, its change is not undone.

2. **Flag examination uses post-eligibility state.** If eligibility returns nonzero and the flag is then nonzero, the function clears it and returns one, even for selector `0x7F`. An initially set flag is insufficient if the dependency clears it first.

3. **High bits survive forwarding.** With operation word `0x00000203` and the shared path reached, F-b45341dc0ac0 receives `0x00000283`.

4. **The second eligibility check can reject selector 2.** If initial eligibility succeeds, the flag is observed clear, and the second eligibility call returns zero, selector 2 returns zero without D19 or direct position-field writes.

5. **The ordinary successor sentinel applies.** With count four, mapped index two, and both D05 results zero, D06 supplies index three as the selection, the successor is `0xFFFFFFFF`, and D07 precedes both field writes.

6. **The advancement sentinel is different.** With count five and index one, suppose selection reaches the second D05 and its distance condition succeeds. The advanced selection is index three and its successor is `0xFFFFFFFF`, because index plus two equals count minus two.

7. **Notification reads are distinct.** If the first notification-global read yields A and the second yields B, F-069a1d444a2d receives B and D08 receives A. If that call subsequently changes the global to C, D08 still receives A.

8. **Subtraction is unsigned, not absolute distance.** A 32-bit difference of `0xFFFFFFFF` compares as 4,294,967,295, not as distance one.

9. **Complete entry processing returns zero.** For three entries with entry zero matching, if D10 remains zero while entries one and two are processed, D09 runs twice, D11 does not run, and the result is zero. A nonzero D10 after entry one instead produces D11 and result one.

10. **Shared-path comparison controls distinct branches.** Equal before/after values with nonzero D17 skip both F-ef97548bea45 and the final-action sequence. Unequal values do not call D17 or F-ef97548bea45, but do execute the final-action sequence.
