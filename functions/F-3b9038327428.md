# F-3b9038327428

## Purpose

F-3b9038327428 coordinates a preparation operation, a primary operation, an optional follow-up operation, and a conditional transfer of a 16-bit field between objects obtained through different means.

The primary operation’s 32-bit result is the function’s return value. Subsequent calls and the conditional field transfer do not replace that result.

The field transfer is not an unconditional initialization of a stable destination object. It checks one object returned by a dependency, then obtains an object again before writing. The supplied evidence does not establish that those two objects are identical.

The function accepts two values represented as 32-bit integers:

| Input | Observable use |
|---|---|
| Object reference | Passed unchanged to two dependencies and used as the base address for a 16-bit field at byte offset `0xE6`. |
| Control value | Passed unchanged to the primary dependency. Its equality or inequality to zero controls subsequent work. |

The object reference acts as an address for direct memory access. Its precise source-language pointer type, object type, allocation size, lifetime, and ownership are not established.

The control value is not normalized before being passed to the primary dependency. For this function’s own branching, every nonzero value is treated alike. The primary dependency may distinguish different nonzero values.

Neither input is modified as a caller-visible argument slot. Dependencies may nevertheless modify memory reachable through the object reference or other shared state.

### Output

The signedness and semantic interpretation of this result are unknown. The supplied evidence does not establish whether it represents a status, count, handle, address, or other value. It is preserved across all later work on paths that reach the return.

## Behavior

### Unconditional dependency calls

On every ordinary execution path, the function first calls F-fdd8589eca2d with no arguments.

Its 32-bit result is passed as the first argument to F-3e5212464798. The second argument is the input object reference, and the third argument is exactly zero. The return value of F-3e5212464798 is not used.

The function then calls F-a3c410f12096 with:

- The original object reference.
- The original control value, without Boolean conversion.

The 32-bit result of this call is retained for the eventual return.

These calls occur before either direct field inspection or the optional follow-up call. There is no visible test of their results before execution continues.

### Optional follow-up operation

If the control value is nonzero, the function next calls F-5c5958cfd5fe with no arguments. Its return value is not used.

If the control value is zero, this call is omitted.

When the call occurs, it precedes the first direct read of the input object’s field. Any effects it has on that field, on objects later returned by F-fdd8589eca2d, or on other shared state can therefore affect the remaining behavior.

There is no visible branch that suppresses this optional call based on the result of F-a3c410f12096.

### Conditional field inspection

After the optional follow-up stage, the function reads the 16-bit field at offset `0xE6` from the input object reference.

This read occurs even when the control value is zero. The field test appears before the control-value test in the short-circuit condition. A zero control value therefore prevents the later accessor calls and transfer, but does not bypass this initial field read.

Further processing requires both:

- The field value just read is nonzero.
- The control value is nonzero.

If either requirement is not met, the function performs no direct destination-field access and returns the retained primary result.

If both requirements are met, the function calls F-fdd8589eca2d again. It treats this call’s result as a base address and reads the 16-bit field at offset `0x80`.

If that field is nonzero, no transfer occurs. The function returns the retained primary result.

### Conditional transfer

If the checked destination field is zero, the function calls F-fdd8589eca2d a third time.

The result of this third call supplies the base address for the eventual write. The function reads the input object’s 16-bit field at offset `0xE6` again and writes that value to offset `0x80` of the newly returned object.

The observable order relevant to this transfer is:

1. The second accessor call returns.
2. Its returned object’s destination field is read and found to be zero.
3. The third accessor call returns.
4. The input object’s source field is read again.
5. That newly read 16-bit value is stored in the third accessor result’s destination field.

The value copied is therefore not necessarily the value that satisfied the earlier nonzero condition.

There is no second check that the source remains nonzero after the third accessor call. If a dependency changes the source field to zero before the final source read, zero is copied.

There is also no check that the third accessor result identifies the object inspected after the second accessor call. The eventual destination can differ from the checked destination. Its existing field value is not read or tested before being overwritten.

### Completion

After the optional transfer, or after any condition prevents it, the function returns the retained 32-bit result from F-a3c410f12096.

No dependency return value is visibly interpreted as an error indication. There is no visible retry, rollback, alternate result, or cleanup path.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They are not results of runtime tests.

### Zero control still requires a source read

Given a zero control value, normal-returning dependencies, and a readable input field:

- The initial accessor, preparation dependency, and primary dependency run in that order.
- The optional follow-up dependency does not run.
- The input field is read.
- No additional accessor call or direct destination access occurs.
- The primary result is returned unchanged.

A zero control value is not sufficient to make an invalid input field address safe.

### Zero source prevents destination inspection

Given a nonzero control value and an input field that is zero when inspected:

- The optional follow-up runs before the input-field read.
- There is no second accessor call.
- No destination field is read or written.

### Nonzero checked destination prevents transfer

Given a nonzero control value, a nonzero source at the condition read, and a nonzero destination field from the second accessor result:

- The second accessor is called.
- Its destination field is read.
- The third accessor is not called.
- The source is not reread for copying.
- No direct store occurs.

### Stable objects permit a straightforward copy

Given a nonzero control value, a stable nonzero source, and second and third accessor results that identify the same valid object with a zero destination field:

- The source is read once for the condition and again for the copy.
- Its 16-bit value is written to the destination field.
- The primary result is returned unchanged.

### Source mutation changes the copied value

Given an initially qualifying source value and a zero checked destination, if the third accessor changes the source field before returning, the value copied is the changed value.

This includes copying zero. The earlier nonzero source test is not repeated after that accessor call.

### Different accessor results permit an unchecked overwrite

Given a zero field in the second accessor result and a different object returned by the third accessor:

- The store targets the third result.
- That object’s existing destination value need not be zero.
- The second result’s destination field is not directly written by this function.

### Primary result does not gate later work

Given any 32-bit primary result, the later branching remains governed by the control value and field reads. No bit pattern in the primary result visibly suppresses the follow-up call or transfer logic.
