# F-2ee25961a22a

## Purpose

F-2ee25961a22a assigns one logical Boolean value to destinations selected by a numeric address and a signed extent. A zero selector requests false; any nonzero selector requests true.

For an ordinary positive extent that stays within the numeric address range, the selected interval begins at the supplied address and contains as many destination starts as the extent specifies. Assignments proceed from the highest selected address to the lowest.

This is not an established capacity-checked buffer operation. The interface provides neither a storage size nor a completion result. Numeric boundary conditions matter: a zero extent is not universally empty, a negative extent is not universally rejected, and an excessive extent does not necessarily produce a wrapped interval.

**Established static evidence:** numeric destination selection, descending Boolean assignments, and no returned value.

**Inferred intent:** reverse-order Boolean filling. This interpretation does not establish that the extent is a validated object count or that consecutive numeric addresses identify separate Boolean objects.

**Verification status:** static analysis only. No runtime tests have been performed.

## Behavior

### Value selection

The assigned value depends only on whether the selector equals zero.

| Selector category | Logical value assigned |
|---|---|
| Zero | False |
| Positive | True |
| Negative | True |

The selector does not determine traversal direction, destination spacing, or interval length. Its magnitude is otherwise irrelevant.

Previous destination contents do not determine the assigned value or the selected addresses. No explicit read of those contents is present.

### Nonzero starting address

Under the conditional arithmetic profile, let **A** be a nonzero starting address. There are **M − A** numeric destination starts from **A** through the maximum address, inclusive.

The selection is:

| Converted extent | Required selection |
|---|---|
| **E = 0** | Empty |
| **1 ≤ E ≤ M − A** | Exactly E consecutive destination starts, beginning at A |
| **E > M − A** | Empty |

For a nonempty selection, the highest destination is **A + E − 1**. Assignments proceed in strictly descending numeric order, ending at **A**. Each selected start is assigned once.

Normal return follows the final assignment if all accesses and execution remain defined. No address below **A** is selected.

An interval that exactly reaches **M − 1** is included. An extent exceeding that capacity selects nothing; it does not select a shorter prefix or continue through zero. Consequently, increasing the extent can change a nonempty request into an empty request.

These are numeric-selection rules. They do not establish the availability of corresponding storage.

### Negative extent

There is no explicit rejection or separate handling of a negative extent.

Under the conditional arithmetic profile, a negative extent behaves according to its converted unsigned value:

- It produces a finite, potentially very large selection if that value fits between the nonzero starting address and the maximum address.
- It produces an empty selection if that value exceeds the available numeric interval.

Thus neither “negative means empty” nor “negative always means a large write” is a valid general contract.

### Zero starting address

Under the same profile, a zero starting address does not provide a terminating lower boundary.

The first selected destination is:

| Converted extent | First destination |
|---|---|
| Zero | **M − 1** |
| Nonzero | **E − 1** |

If execution continues validly, destinations descend through zero, continue at **M − 1**, and repeat. Each complete numeric cycle visits every address once.

The consequences are:

- Zero address with zero extent is not an empty request.
- A positive extent does not limit the total number of assignments.
- Assigning at address zero does not complete the function normally.
- No independent assignment counter provides termination.

This describes a conditional numeric traversal, not a guarantee that indefinite execution is possible. The evidence does not establish writable Boolean storage at every numeric address. Address zero, the maximum address, or any earlier destination may be unsupported in a particular environment.

## Acceptance examples

These are **conditional static acceptance criteria**, not observed executions.

Unless otherwise stated, assume a 32-bit unsigned address domain with corresponding 32-bit signed inputs and the arithmetic profile described above. Then **M = 4,294,967,296**, and the maximum numeric address is **0xFFFFFFFF**.

Every example involving assignments also requires valid storage for the complete Boolean access at each destination. Logical true and false do not prescribe a physical encoding.

### Ordinary finite interval

For starting address **0x1000**, selector **7**, and extent **3**:

- Assignment order is **0x1002 → 0x1001 → 0x1000**.
- All three destinations receive true.
- Neither **0x1003** nor **0x0FFF** is selected.
- Normal return follows the assignment at **0x1000**, provided execution remains defined.

An ascending traversal would not satisfy the ordering requirement, even if the final values matched.

| Selector | Assignment order | Required logical value |
|---|---|---|
| 0 | 0x1001 → 0x1000 | False |
| 1 | 0x1001 → 0x1000 | True |
| −9 | 0x1001 → 0x1000 | True |

### Empty selection

For starting address **0x1000** and extent **0**, no destination is accessed, and the function returns normally.

Writable storage at **0x1000** is unnecessary for this invocation. This criterion does not apply to a zero starting address.

### Inclusive maximum address

For starting address **0xFFFFFFFE**:

| Extent | Required behavior |
|---|---|
| 2 | Assign at 0xFFFFFFFF, then 0xFFFFFFFE, then return normally if both accesses are valid |
| 3 | Perform no destination access and return normally |

The first case requires the entire Boolean access starting at the maximum numeric address to be valid. Selection of that start does not establish sufficient storage beyond it.

The second case must not be treated as a three-destination interval wrapping through zero.

### Negative extent with different outcomes

For extent **−1**, the converted extent is **4,294,967,295**.

- Starting address **0x1000** produces an empty selection because the converted extent exceeds the available numeric interval.
- Starting address **1** selects destinations from **0xFFFFFFFF** down through **1**, excluding zero. If every access remains valid, normal return follows **4,294,967,295** assignments.

These outcomes follow from numeric boundaries, not from any validation of negative inputs.

### Zero address and zero extent

For starting address **0** and extent **0**, the first assignment targets **0xFFFFFFFF**.

If execution remains valid, traversal eventually reaches zero and then continues again at **0xFFFFFFFF**. Immediate normal return without an assignment would not satisfy the conditional selection behavior.

**1 → 0 → 0xFFFFFFFF → 0xFFFFFFFE**

The second assignment does not complete the operation normally. A requirement to stop after two assignments would impose a count-limited contract absent from the evidence.

### Unsupported access after a valid prefix
