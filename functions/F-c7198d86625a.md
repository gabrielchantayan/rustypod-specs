# F-c7198d86625a

## Purpose

F-c7198d86625a selects between two 64-bit result constructions according to a shared 32-bit condition value.

When the condition value is nonzero, the function returns the second input in the upper 32 bits and zero in the lower 32 bits. When the condition value is zero, it attempts three successive software interrupts using the same immediate selector, then returns a shared value in the upper 32 bits and the value seven in the lower 32 bits, provided execution continues through all three interrupts.

This is an established description of the supplied static representation. The reason for the interrupts, the meaning of the shared values, and whether the zero-condition path normally returns are not established. In particular, interpreting that path as an error, shutdown, diagnostic, or privilege-transition mechanism would add unsupported intent.

## Behavior

### Initial decision

Only equality with zero matters. Every nonzero 32-bit pattern selects the same path, including patterns that would be negative under a signed interpretation.

The condition is evaluated once in the visible body. There is no loop, retry, or second condition check after the decision. Consequently, a later change to the condition does not, by itself, cause the function to select the other branch.

The four-byte offset describes the location of the read; it does not establish the size or layout of an enclosing object. Address-width arithmetic, pointer provenance requirements, and behavior for an invalid base address are not recoverable from this body alone.

### Nonzero-condition path

If the condition read is nonzero:

1. The function constructs a 64-bit result whose upper 32 bits equal the second input.
2. The lower 32 bits are zero.
3. The function returns that result.

This construction zero-extends the unsigned second input to 64 bits before shifting it left by 32 positions. It does not perform a 32-bit shift by the width of the operand, and it does not sign-extend the input.

The largest possible second input therefore produces `0xFFFFFFFF00000000`, not an overflowed 32-bit intermediate or an all-ones 64-bit result.

No software interrupt or read of the return-prefix value is explicitly present on this path.

### Zero-condition path

If the condition read is zero, the function attempts software interrupts in this order:

1. A software interrupt with immediate selector `0x123456`.
2. A second software interrupt with the same selector, if execution reaches it.
3. A third software interrupt with the same selector, if execution reaches it.

If control continues after all three, the function reads the shared return-prefix value and constructs a 64-bit result with that value in the upper 32 bits and seven in the lower 32 bits.

The final shared-value read occurs after the three interrupt operations in the represented sequence. The body does not capture that value before issuing the interrupts. Thus, if an interrupt service changes the return-prefix value and then resumes execution normally, the final construction uses the value available at the later read, rather than a pre-interrupt snapshot.

The second input is not used to construct the result on this path. The first input is not referenced on either path.
