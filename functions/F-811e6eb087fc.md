# F-811e6eb087fc

## Purpose

F-811e6eb087fc performs a guarded traversal of entries associated with a caller-supplied object. It submits eligible entries to F-32201b880080 until that dependency returns a nonzero result or the traversal is exhausted. Entry 1 is excluded from ordinary submission and is considered separately after ordinary traversal completes without a nonzero result.

Whenever F-32201b880080 returns a nonzero result, F-811e6eb087fc invokes F-aacdb1821b51 for the same object and entry index, then returns the result produced by F-32201b880080.

The function also manages a byte-sized guard and conditionally clears bit 4 of an object field. It does not itself set that bit.

These are established control-flow effects. Interpreting the dependencies as “processing” and “finalization,” the entry flag as a disable marker, or the guard as a concurrency mechanism would require additional evidence.

## Interface

### Inputs

The function receives two arguments:

1. **Object reference.** An address identifying a readable and writable object with the layout described below. The supplied representation uses a 32-bit address-bearing value.
2. **Forwarded value.** An opaque 32-bit value passed unchanged to each invocation of F-32201b880080. This function does not inspect or dereference it.

No null checks, bounds checks, or validity checks are established.

### Return value

The return value is a signed 32-bit integer:

- Zero if the guard is already nonzero.
- Zero if no invocation of F-32201b880080 returns nonzero.
- Otherwise, the exact nonzero result from F-32201b880080.

Positive and negative results are treated identically for control flow. Neither is assigned a success or error meaning by the available evidence.

The return value of F-aacdb1821b51, if it has one, is not used.

### Object and entry layout

Offsets are byte offsets relative to the applicable base address.

| Location | Width | Established use |
|---|---:|---|
| Object + `0x04` | 32 bits, signed | Entry count or traversal bound, read repeatedly |
| Object + `0x08` | 32-bit address | Base of an entry table |
| Object + `0x0C` | 32 bits, unsigned | State field; initially snapshotted, potentially modified at completion |
| Object + `0x80` | 8 bits | Guard; zero permits entry, nonzero returns immediately |
| Entry table + `24 × index + 0x14` | 32-bit address | Reference to an entry-associated record |
| Referenced record + `0x5A` | 16 bits, unsigned | Flags; bit 0 controls eligibility |

The table uses a 24-byte stride. The evidence identifies the record-reference field within that stride, not the meanings of other entry bytes or the table’s full allocation.

For index 1, the record-reference location is table base + `0x2C`, because `24 + 0x14 = 0x2C`.

### Preconditions

For a normally completing invocation:

- The initial 32-bit state field and guard byte must be readable.
- If the guard is zero, the guard byte must also be writable.
- Every table reference, record reference, and flag field actually reached must be valid for its stated width.
- The object must remain valid across both dependencies and subsequent accesses.
- If the final state-field update is reached, that field must be readable and writable.
- Index-derived address calculations must identify valid storage. The evidence does not establish a portable overflow policy for invalid or excessively large layouts.

The function does not enforce these preconditions. There is no established recovery behavior for invalid addresses or dependency failures that do not return normally.

## Behavior

### 1. Capture state before checking the guard

The first established object access reads the entire unsigned 32-bit field at offset `0x0C` and retains its value as an initial snapshot.

The function then reads the guard byte at offset `0x80`.

If the guard is nonzero, it returns zero immediately. In this case:

- The initial state-field read has already occurred.
- No entry count, table, or record access is performed by this function.
- Neither dependency is called.
- No guard or state-field write is performed by this function.

Consequently, a nonzero guard does not make an unreadable initial state field safe.

### 2. Enter the guarded traversal

If the guard is zero, the function writes the value 1 to that byte. This occurs before the first entry-count read.

The traversal index starts at zero. The retained result starts at zero.

The count is read as a signed 32-bit value. It is not captured once for the entire invocation.

### 3. Traverse ordinary entries

At the beginning of each ordinary iteration, the function reads the current count.

If the current index is less than that signed count, it:

1. Reads the table reference from the object.
2. Reads the record reference for the current index.
3. Reads that record’s unsigned 16-bit flags.
4. Tests bit 0.
5. If bit 0 is clear, checks whether the current index differs from 1.

An invocation of F-32201b880080 occurs only if bit 0 is clear and the index is not 1. Its arguments are the object reference, current index, and unchanged forwarded value.

**Index 1 still has its record flags read during ordinary traversal.** Excluding it from submission does not exclude its table and record dereferences. In particular, an invalid index-1 record can fail during ordinary traversal even though its dependency invocation is deferred.

If bit 0 is set, or the index is 1, no dependency is called for that ordinary iteration.

If F-32201b880080 returns zero, traversal continues. If it returns nonzero:

- That exact result is retained.
- F-aacdb1821b51 is invoked with the object reference and the same index.
- Ordinary traversal terminates without another count or entry read.

The internal index advances after an ordinary iteration, including after the nonzero-result dependency pair. That advancement does not cause a further table access when the retained result is nonzero.

### 4. Consider entry 1 after ordinary exhaustion

When an iteration begins with the current index greater than or equal to the current signed count, ordinary traversal is exhausted.

The function then reads the count again. It does not reuse the value that caused exhaustion.

Only if this second count read is greater than 1 does it access entry 1:

1. Read the current table reference.
2. Read the record reference at table offset `0x2C`.
3. Read the unsigned 16-bit flags at record offset `0x5A`.
4. Test bit 0.

If bit 0 is clear, F-32201b880080 is invoked with index 1 and the forwarded value.

If that call returns nonzero, F-aacdb1821b51 is called for index 1. Whether the result is zero or nonzero, traversal ends after this deferred consideration.

The deferred path is not reached when an ordinary entry has already produced a nonzero result.

For stable input data, dependency submissions therefore occur in ascending index order with index 1 omitted, followed by index 1 last. This describes submission order, not flag-read order.

### 5. Clear the guard and conditionally update state

After normal traversal completion, the function unconditionally writes zero to the guard byte. It does not restore the guard’s previous value or preserve a value written there by a dependency.

It then considers the retained result and the initial state snapshot:

- If the retained result is nonzero, it performs no final state-field update.
- If the retained result is zero and initial bit 4 was set, it performs no final state-field update.
- If the retained result is zero and initial bit 4 was clear, it reads the **current** 32-bit state field, clears bit 4 with mask `0xFFFFFFEF`, and writes the result back.

The guard-clear write precedes this possible state-field read and write.

The initial snapshot determines whether the update is attempted; the current field supplies the value being updated. Other current bits are preserved by this function’s mask. If a dependency sets bit 4 after an initially clear snapshot, normal zero-result completion clears that newly set bit.

Even if current bit 4 is already clear, the eligible path still performs the read and write.

Finally, the retained result is returned.

## Side effects

### Direct memory effects

The established direct writes are limited to:

- Guard byte set to 1 after an initially zero guard.
- Guard byte set to 0 after normal traversal completion.
- A conditional 32-bit read-modify-write clearing state bit 4.

The function itself does not write entry counts, table references, record references, or record flags.

This limitation does not constrain dependency side effects.

### Dependency-visible effects and mutation

Dependencies execute after the guard has been set to 1. Re-entry while that byte remains nonzero returns zero after reading the initial state field.

The guard is not established as atomic, locked, or sufficient for thread safety. Dependencies may alter it; no preservation guarantee is available.

The function repeatedly reads mutable object data:

- Count is reconsidered at each iteration.
- Exhaustion causes a separate count read before deferred entry-1 processing.
- Table references and record flags are read when reached, rather than cached for the invocation.
- Entry 1’s flags may be read once during ordinary traversal and again during deferred consideration.

Changes made by dependencies can therefore affect later traversal. There is no established snapshot-consistency guarantee or unconditional termination guarantee under mutation.

### Ownership and lifetime

No direct allocation or deallocation is present. The function does not explicitly transfer ownership of the object, table, records, or forwarded value.

It is unknown whether either dependency allocates, releases, retains, or invalidates any referenced storage or changes global state. Continued validity of storage needed after a dependency returns is a precondition, not a proved dependency property.

Guard clearing and final state processing are established only for normal return paths. There is no demonstrated unwind or recovery mechanism for a dependency that faults, exits nonlocally, or never returns.

## Acceptance examples

These are conditional examples derived from static evidence, not executed tests. Unless stated otherwise, referenced storage is valid and dependencies leave relevant traversal data unchanged.

1. **Already guarded.**  
   With a nonzero guard, the function reads the initial state field and guard, returns zero, and performs no direct writes or dependency calls.

2. **Zero or negative count.**  
   With a zero guard and a stable signed count of zero or less, no table access occurs. The guard is set and cleared. The result is zero, with final state handling determined by initial bit 4.

3. **Single eligible entry.**  
   With count 1 and entry 0’s flag bit 0 clear, F-32201b880080 is called for index 0. A zero result leads to zero return without any index-1 access. A nonzero result triggers F-aacdb1821b51 for index 0 and is returned unchanged.

4. **Deferred index 1.**  
   With count 3, all flag bits clear, and results zero for indices 0 and 2, submission order is 0, 2, 1. Entry 1’s flags are read during ordinary traversal before index 2 is considered, then read again before deferred submission.

5. **Ordinary nonzero result prevents deferred submission.**  
   With count 4 and a nonzero result at index 2 after a zero result at index 0, the function calls F-aacdb1821b51 for index 2. It does not submit index 3 or deferred index 1.

6. **Negative result is terminal.**  
   If an eligible submission returns −7, the matching F-aacdb1821b51 call occurs and F-811e6eb087fc returns −7, not a normalized Boolean value.

7. **Set flag bit suppresses submission, not flag access.**  
   An ordinary entry whose bit 0 is set has its flag read but is not submitted. Other flag bits do not affect eligibility.

8. **Initially clear state bit, later set by dependency.**  
   If initial bit 4 is clear, a dependency sets it, and every submission returns zero, final processing clears that bit after clearing the guard. Other then-current state bits are preserved.

9. **Initially set state bit.**  
   If initial bit 4 is set, final state processing performs no state-field update, even if a dependency subsequently clears that bit.

10. **Count changed before exhaustion.**  
    If the index-0 submission returns zero and changes the count to 1, the next bound check at index 1 exhausts ordinary traversal. If the subsequent count read remains 1, no index-1 record access or deferred submission occurs.
