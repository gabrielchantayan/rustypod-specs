# F-6b7721c24036

## Purpose

F-6b7721c24036 conditionally invokes an indirect operation associated with a supplied object. If that operation returns the integer value −1, the function invokes F-8434be7161a5 with a freshly resolved object-relative address and the integer value 1. On every path that completes normally, it returns the original input pointer.

The supplied representation establishes address calculations, branch conditions, call order, and return identity. It does not establish the semantic meaning of the indirect operation, the referenced object, or the subsequent dependency call. Interpreting these as a stream operation, synchronization request, or error-state update would require additional evidence.

## Interface

**Input:** One pointer to an object whose layout supports the metadata-based accesses described below.

**Output:** The same pointer value received as input, provided execution completes normally. The result is not the address computed from the object’s metadata and is not the pointer used to select the indirect operation.

**Represented widths:** The supplied representation uses 32-bit integer quantities and an address model in which pointers participate in integer address calculations. This contract describes that represented 32-bit model. The actual binary ABI, pointer representation, and machine-level overflow behavior are not independently established.

The following layout roles are sufficient to describe the observed behavior:

| Role | Location or derivation | Interpretation |
|---|---|---|
| Input object address | Function argument | Original pointer, retained for the normal return |
| Metadata address | Pointer-sized value read at the input object address | Base for a metadata-relative displacement read |
| Object displacement | 32-bit integer read 12 bytes before the metadata address | Offset used to derive an adjusted object address |
| Adjusted object address | Input object address plus the object displacement | Base for the associated-pointer lookup and, conditionally, the first dependency argument |
| Associated pointer | Pointer-sized value read 52 bytes after the adjusted object address | Null means that no indirect operation is invoked |
| Dispatch-table address | Pointer-sized value read at the associated pointer | Base for locating the indirect target |

The two uses of the byte offset 52 are distinct: one locates an associated pointer within the adjusted object; the other locates a callable target within a dispatch table.

The input pointer is not checked for null. Its metadata address is also not checked for null. Only the associated pointer receives an explicit null check.

## Behavior

### Initial address resolution

Before deciding whether to call anything, the function resolves the associated pointer through the input object’s metadata:

1. It reads the metadata address from the beginning of the input object.
2. It reads a 32-bit displacement from the address 12 bytes before that metadata address.
3. It combines the input object address, that displacement, and a further byte offset of 52 to locate the associated-pointer field.
4. It reads the associated pointer from that field.

These are dependency-ordered accesses: locating the associated-pointer field requires the metadata address and displacement first.

The displacement is not restricted by an explicit range check. A negative displacement can direct the lookup before the input address; a positive displacement can direct it after the input address. Neither case is rejected solely because of its sign.

The representation does not establish defined behavior for address arithmetic outside the valid address range or outside the relevant storage. Such cases are not promised to wrap, trap, or produce a particular pointer.

### Null associated pointer

If the associated pointer is null:

- No dispatch-table lookup is performed through that pointer.
- No indirect operation is invoked.
- F-8434be7161a5 is not invoked.
- The function returns the original input pointer.

This is a no-call path, not a no-read path. The input object, metadata displacement, and associated-pointer field have already been read.

### Non-null associated pointer

If the associated pointer is non-null, the function:

1. Reads a dispatch-table address from the beginning of the associated object.
2. Reads the indirect target from the dispatch-table entry at byte offset 52.
3. Invokes that target.
4. Uses its represented integer result to select the next action.

There is no explicit null check for the dispatch-table address or the indirect target. A non-null associated pointer alone is therefore insufficient to make this path valid.

The supplied call expression shows no explicit arguments for the indirect operation. Its selection is established through the associated object’s dispatch table, but the calling convention is not. In particular, the evidence does not establish whether the associated object is supplied as an implicit receiver or whether any other implicit argument exists.

### Result other than −1

If the indirect operation returns any represented integer value other than −1, F-8434be7161a5 is not called. The function returns the original input pointer.

The branch is an exact sentinel comparison. It is not a general test for negative values, zero, or nonzero. For example, −2 does not select the same branch as −1.

The indirect result is not returned to the caller.

### Result equal to −1

If the indirect operation returns −1, the function resolves an adjusted address again from the original input pointer:

1. It rereads the metadata address at the original input object address.
2. It rereads the 32-bit displacement 12 bytes before that newly read metadata address.
3. It combines the original input object address with this newly read displacement.
4. It calls F-8434be7161a5 with that adjusted address as its first argument and the integer value 1 as its second argument.

The first argument does **not** include the additional 52-byte offset used for the initial associated-pointer lookup.

This second resolution occurs after the indirect operation returns. It must not be specified as reuse of the initial displacement or initial metadata address. If the indirect operation changes either location, the dependency argument follows the values observed by the later reads.

The associated-pointer field is not reread on this branch, and the indirect operation is not repeated.

The return value of F-8434be7161a5, if any, is not consumed by the shown function. If that call completes normally, F-6b7721c24036 returns the original input pointer.
