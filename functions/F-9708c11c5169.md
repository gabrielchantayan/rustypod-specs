# F-9708c11c5169

## Purpose

F-9708c11c5169 is represented as an unconditional, non-returning cycle of indirect dependency calls and memory accesses. It repeatedly derives addresses and stored values from dependency results, selected input words, an externally supplied register value, and a global word.

No application-level purpose is established. In particular, the supplied representation does not establish that the accesses implement an object model, device protocol, allocator, serializer, or initialization routine. Small effective addresses, byte-sized address selectors, and register-dependent entry state make such interpretations unsafe.

This contract describes the visible ordering and data dependencies of the supplied static representation. It does not establish that the representation is a faithful reconstruction of executable behavior.

## Interface

### Explicit inputs

The represented interface has four 32-bit arguments:

| Input | Visible use |
|---|---|
| First word | No explicit use in the displayed body. |
| Second word | No explicit use in the displayed body. |
| Third word | Supplies shifted values to a word store and a later dependency call; replaced near the end of each cycle by a dependency result. |
| Fourth word | Passed to a dependency near the beginning of each cycle; replaced near the end by four times another dependency result. |

“No explicit use” does not prove that the first two words are irrelevant to executable behavior. The indirect-call interfaces and their implicit register inputs are unresolved.

### Additional entry state

Two additional machine-state inputs are visible:

- An incoming register-derived base, called **entry base** below.
- An incoming link-related value used to form the first indirect-call target.

The entry base is not an ordinary argument in the displayed signature. A normal high-level invocation supplying only the four words is therefore insufficient to establish a valid execution environment.

The function also reads a global 32-bit word once per cycle. Its meaning, synchronization requirements, and relationship to overlapping global storage are unknown.

### Output and termination

There is no represented return value and no normal return path. The cycle has no exit test.

A dependency that does not return, an invalid instruction target, or a failing memory access can prevent further progress. There is no visible local error conversion, cleanup path, retry policy, or termination notification.

### Width and notation

The following descriptive names identify values, not source identifiers:

- **A**: the 32-bit result of the fourth opening call.
- **G**: the sampled global word.
- **L**, **M**: low 32-bit halves of two distinct 64-bit dependency results.
- **P**, **Q**, **T**: later 32-bit dependency results used in address and value calculations.
- **B**: the entry base for the current cycle.

For concise arithmetic descriptions:

- **scale4(x)** means the low 32 bits of four times a word.
- **field(x)** means bits 20–29 of a word, interpreted as an unsigned value from 0 through 1023.
- **upper10(x)** means an unsigned right shift by 22, producing a value from 0 through 1023.
- Left shifts and products below describe 32-bit machine-word bit patterns, with overflow discarded where the target uses ordinary 32-bit wrapping arithmetic.

That last interpretation is conditional. The representation contains signed-looking shifts and multiplications whose overflow is not portable high-level-language arithmetic. The actual machine semantics require independent confirmation.

A **selector write at base X** means: read one unsigned byte at X + 1, zero-extend it, add 17, and write one byte there. It does **not** mean dereference a pointer stored at X + 1.

## Behavior

### General ordering

The phases below occur in the stated order on every cycle. Calls between accesses are observable boundaries: dependencies may change memory, global state, or the external environment.

No memory access may be removed merely because a later access appears to overwrite it. Dependencies can observe intermediate values, and addresses can alias.

Dependencies are identified by opaque call-site IDs in the range F-D001 through F-D080. These labels identify positions in this contract, not verified distinct executable functions. Some IDs cover an ordered group of calls; group details appear under **Dependencies**.

### Opening state and initial writes

1. Three opening calls occur. A fourth call supplies A.
2. A selector write at B stores the low byte of A shifted left by two.
3. A dependency receives the full 32-bit value A shifted left by two.
4. Another dependency supplies a word, which is forwarded to the next dependency together with A shifted left by 30.
5. Four more calls occur; the last supplies a result.
6. The selector byte at B + 1 is read again. Its value is retained as an address base, **S**.
7. One byte containing the low eight bits of field(A) is written at S + 17.
8. A dependency receives four times the result from step 5.
9. Four further calls occur.
10. A 32-bit word equal to scale4(the current third input) is written at S + 20.

The selector reread in step 6 matters. The first and second selector-derived writes need not address the same byte. Conversely, the word store uses retained S, not a fresh selector read after the intervening calls.

The global word is then sampled into G, before the next dependency receives the current fourth input.

### First wide result and first paired word stores

Following the call that receives the fourth input, four calls occur. The last yields a represented 64-bit result.

Let L be its low word, and let **C = scale4(L)**.

The function then:

- Performs a selector write at B with the low byte of upper10(G).
- Passes the wide result’s high word to a dependency.
- Obtains another dependency word and forwards it, together with C shifted left by 28.
- Performs four calls, the last supplying a word.
- Performs a fresh selector write at B, storing zero.
- Passes four times the latest word to a dependency.
- Performs four calls, the last supplying another word.
- Passes four times that word twice to the next dependency.
- Performs four calls, the last supplying P.

The first paired stores are:

| Order | Address | Width | Value |
|---|---|---:|---|
| 1 | C × 4096 + 20 | 32 bits | scale4(P) |
| 2 | Four times a subsequent dependency result, plus 20 | 32 bits | The same scale4(P) |

Between these stores, a dependency receives C shifted left by 14, followed by four calls producing the second store’s address result.

After the second store, a dependency receives its address base without the +20 offset, followed by four calls yielding another 64-bit result.

### Second wide result and selector clearing

Let M be the low word of that second wide result, and **D = scale4(M)**.

Before forwarding its high word, the function reads a selector byte at C × 16384 + 1 and writes the low byte of field(scale4(P)) to the selected address plus 17.

It then:

1. Passes the wide result’s high word to a dependency.
2. Obtains and forwards another word.
3. Obtains a further 64-bit result and forwards its low and high words, in that order.
4. Performs two calls, the second supplying a word.
5. Performs a selector write at D × 268435456, storing zero.
6. Passes four times the latest word to a dependency.
7. Performs four calls, the last supplying Q.
8. Performs a selector write at D × 4, storing zero.

The function next calls a dependency with D shifted left by 10, obtains another word, and forwards that word together with the current third input shifted left by 28.

Four calls follow. The final result is multiplied by four and passed to a dependency, with another fresh zero selector write at D × 4 occurring immediately before that call.

### Second paired word stores

After four more calls, the function stores Q shifted left by 14 at:

- scale4(Q) × 4096 + 20.

It then passes scale4(Q) shifted left by 14 to a dependency. A subsequent call is followed by a two-argument call whose first argument is the stored value shifted left by 28 and whose second argument is an unresolved secondary register result.

Under 32-bit wrapping arithmetic, the first argument is zero: shifting Q left by 14 and subsequently left by 28 discards every original bit. The second argument must not be treated as zero, preserved input, or a conventional return value without additional evidence.

Four calls follow. The last supplies an address result, and the same Q-shifted-left-by-14 word is stored at four times that result plus 20.

A dependency then receives that address base, followed by four calls. Let the last result be T and **E = scale4(T)**.

### Two repeated scaling/store sequences

Four calls produce a word **J**. The function stores scale4(J) at J × 16 + 20, then passes scale4(J) three times to a dependency.

Four more calls produce an address result. The same scale4(J) is stored at four times that result plus 20, and that address base is passed to a dependency.

This pattern occurs again with a newly obtained word **K**:

- Store scale4(K) at K × 16 + 20.
- Set the next-cycle entry base to K × 1073741824.
- Pass scale4(K) three times to a dependency.
- Obtain another address result through four calls.
- Store scale4(K) at four times that result plus 20.
- Pass that address base to a dependency.

Under 32-bit arithmetic, the next-cycle entry base depends only on K’s bottom two bits. Its possible bit patterns are zero, 1073741824, 2147483648, and 3221225472.

### Final clearing, input replacement, and back edge

Four calls produce a word **U**. Using the newly assigned entry base, the function directly writes:

1. Zero at B + 17.
2. Zero at B + 1.

These are direct writes, not selector writes.

A dependency receives U shifted left by two. Another result is obtained and forwarded. Four calls produce another word, after which the same two direct zero writes occur again in the same order.

That result, multiplied by four, is passed to a dependency. Four calls then produce a word **N**.

The function:

- Replaces the fourth input with scale4(N).
- Stores an earlier retained address-result word shifted left by 31 at N × 16 + 20.
- Reads a 32-bit word at field(U) + 20.
- Calls a dependency with the replacement fourth input.
- Replaces the third input with the next dependency’s result.
- Passes upper10(the just-read word), shifted left by 28, to another dependency.
- Performs four calls, the last supplying a word **Z**.
- Stores a zero word at scale4(Z) + 20.
- Assigns a fixed internal continuation-related value for the next opening call.
- Calls a dependency with scale4(Z).
- Repeats the cycle unconditionally.

The terminal word store derived from the retained address result shifted by 31 is either zero or has only bit 31 set under 32-bit arithmetic.

## Side effects

### Memory

Visible writes include both single-byte and four-byte accesses. There is no demonstrated structure boundary or allocation boundary.

Selector-derived byte destinations range from address 17 through address 272. The final indexed word read starts between addresses 20 and 1043 inclusive. These accesses must not be silently reinterpreted as relative to a missing object base.

Some calculated word addresses are multiples of four plus 20, but the word store at S + 20 and the final indexed word read need not be aligned. Validity depends on the target’s memory map and unaligned-access behavior.

Endianness is not established. It affects the byte representation of word stores and interactions with overlapping byte accesses.

### State and ownership

The function updates its loop-carried third input, fourth input, entry base, and continuation-related state. The first cycle can therefore differ from later cycles even when dependency results repeat.

No allocation, release, ownership transfer, reference-count change, or resource acquisition is directly established. Dependencies may perform any of those actions; their absence from the visible body is not a preservation guarantee.

The global word is read, not directly written. Dependencies may modify it before a later cycle samples it.

### Failure behavior

- Selector range beyond its inherent byte width.
- Dependency failure results.
- Misalignment.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Byte truncation differs from call argument width.**  
   If A is 255, the opening byte write stores 252. The following explicit shifted argument is 1020, not 252.

2. **Selector reread observes intervening changes.**  
   If the first selector read yields 3 and an intervening dependency changes the selector to 9, the opening byte destination is address 20, while the later retained selector base is 9. Its byte destination is 26 and its word destination is 29, assuming those accesses are valid.

3. **Upper bits are discarded at byte stores.**  
   If field(A) is 1023, the corresponding byte store writes 255. A contract requiring a ten-bit memory write would be incorrect.

4. **Duplicate stores remain observable.**  
   If two calculated word destinations alias, both stores still occur, with the intervening dependency calls preserved. Equal values do not justify removing either access.

5. **No implicit selector dereference.**  
   If a selector byte is 128, its byte destination is address 145. It is not an address loaded from a four-byte pointer field.

6. **Loop-carried values replace entry arguments.**  
   After a completed cycle, the next cycle uses the newly obtained third input and scale4(N) as its fourth input, not the original invocation values.

7. **Zero selector does not suppress access.**  
   A zero selector directs a selector write to address 17. There is no visible null check.

8. **Failure halts ordered progress.**  
   If a word store faults, later calls and stores are not established to occur. No rollback is represented.
