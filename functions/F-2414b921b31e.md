# F-2414b921b31e

## Purpose

The contract is an **access-order contract**, not merely a specification of final memory contents. Addresses may overlap; consequently, an earlier write can change a later destination, selector, or sampled value. Repeated writes and fresh reads remain significant even when a particular memory arrangement makes them redundant.

No application-level purpose is established. Link-shaped values and recurring offsets suggest interconnected records, but do not establish a list, tree, allocator, ownership protocol, or valid object layout.

All behavior below is conditional on preceding accesses, arithmetic, and calls completing. The static evidence does not establish that any initial state permits the entire path.

## Behavior

### Observable ordering model

The following checkpoints are ordered. Within each checkpoint, the stated ordering and read-retention rules are part of the contract.

A **retained** value continues to mean the value already read, even if its former storage changes. A **fresh** read samples memory at its later position. Role names do not imply that the underlying addresses differ.

### Opening attachment

The first three writes occur in this order:

- Entry-root offset 0x44 receives the entry link as a word.
- Entry-link offset 0x14 receives argument 2 as a word.
- Entry-record offset 0x11 receives argument 4 as a byte.

An initial successor is then read from entry-record offset 0x44, followed by a signed halfword read at the sum of the entry-record and entry-link values. Both reads precede the byte write of the entry link to argument-2 offset 0x15 and the word write of argument 2 to entry-link offset 0x44. Those two writes occur in that order.

The initial successor’s offset 0x74 supplies an intermediate address. At that address plus the retained signed halfword, a halfword write stores the initial successor’s low 16 bits. Only afterward does intermediate-address offset 0x44 supply the initial continuation. Thus, overlap with the halfword write can affect the continuation.

The remaining opening attachment has these ordered effects:

- Entry-record offset 0x54 receives the entry record itself.
- G1 supplies a retained attachment base and the global-derived value written to initial-successor offset 0x44.
- The retained G1 base’s offset 0x14 receives the initial continuation.
- Entry-record offset 0x11 receives the low byte of the entry record shifted left by one bit.

The last write replaces the earlier argument-4 byte unless intervening aliasing has already affected that location. Each global attachment uses its global both as a base source and as a stored-value source. The evidence does not establish an atomic snapshot or exact physical load count for those references.

### First linking round

The first argument-1 offset-0x64 word sample occurs after the opening byte replacement. Its low byte is retained as the **first sample**.

A fresh entry-record offset-0x44 read supplies the first-round successor. A signed halfword at entry record plus retained G1 base supplies the selector. A word at selector plus 0x14 supplies the first destination record.

The round’s central update has a fixed effect order:

| Order | Required effect |
|---:|---|
| 1 | Successor offset 0x54 receives the successor as a word. |
| 2 | The address equal to attachment base plus continuation receives the external anchor as a word. |
| 3 | Attachment-base offset 0x14 receives the successor as a word. |
| 4 | A fresh word from external-anchor offset 0x44 supplies the byte written to attachment-base offset 0x0D. |
| 5 | Destination-record offset 0x0D receives the successor’s low byte. |
| 6 | Selector plus attachment base receives the successor’s low halfword. |

For this round, the attachment base is retained G1 and the continuation is the initial continuation. The external-anchor read occurs after the preceding three writes, so it is sensitive to their aliases.

After the central update, G1-base offset 0x44 supplies the first-round continuation. The first destination’s offset 0x54 then receives the first destination itself. G2 supplies the next retained base and the value written to first-round-successor offset 0x44. The G2 base’s offset 0x14 receives the first-round continuation. Finally, the first destination’s offset 0x11 receives the first sample.

### Second linking round

Argument-1 offset 0x64 is read again. This **second sample** is independent of the first and supplies both remaining destination-byte sample updates. There is no third read of that input field.

The first destination’s offset 0x44 supplies the second-round successor. A signed halfword at first destination plus retained G2 base supplies the new selector.

Before the second destination is read, three writes occur in order:

- First-round-continuation offset 0x54 receives the first destination.
- First-destination offset 0x11 receives the second sample’s low byte.
- Second-round-successor offset 0x44 receives the retained G2 base.

The first write is not necessarily a self-reference. All three precede the word read at selector plus 0x14 that identifies the second destination; any overlapping write can therefore affect that lookup.

The central six-effect update described above then applies with the second-round successor, G2 base, first-round continuation, and second destination. Its external-anchor word read is fresh rather than reused from the first round.

Afterward, G2-base offset 0x44 supplies the next continuation. Second-destination offset 0x54 receives the second destination itself. ### Factor-directed traversal

Second-destination offset 0x44 supplies a retained word. A signed halfword at second destination plus retained G3 base supplies the **factor**. The sign-extended factor is used both as a numerical multiplier and as an address base.

Before traversal, the following pair of writes occurs twice, in the same order each time: factor offset 0x54 receives the factor as a word, then G3-base offset 0x11 receives the second destination’s low byte. The second pair is not omitted from the represented behavior.

The factor multiplied by the retained second-destination word supplies the initial traversal address. Three dependent word reads, at offsets 0x44, 0x74, and 0x14 respectively, identify a selected record.

The selected record’s old offset-0x14 word is retained before that field is replaced with the second destination shifted left by one bit. A subsequent word read at retained-old-value offset 0x14 occurs after this replacement. If it overlaps the replaced field, it samples the replacement.

Multiplying that subsequent word by the factor produces the **first product address**. Before its offset 0x74 is read, factor offset 0x54 again receives the factor, followed by a byte write of the retained old value to G3-base offset 0x11.

The first-product offset-0x74 read supplies the **retained traversal value**. Multiplying the first product address by the factor produces the **second product address**. Another factor self-reference write follows, then G3-base offset 0x11 receives the retained traversal value’s low byte.

## Acceptance examples

These are conditional static consequences, not executed tests. Each assumes the preceding path completes, the relevant arithmetic is defined, and the accessed storage is valid.

1. **Opening-byte lifetime.** With no interfering alias, argument 4 first occupies entry-record offset 0x11. The later opening write replaces it with the low byte of twice the entry-record value. Preserving argument 4 there would not satisfy the contract.

2. **Signed selector.** A selector halfword containing 0xFFFF contributes −1, not 65535. Its destination lookup uses offset 0x14 relative to that sign-extended value, subject to the unresolved address model.

3. **Two independent samples.** If the two argument-1 offset-0x64 reads have low bytes 0x12 and 0x34, the first round ends by writing 0x12 to its destination’s offset 0x11. The second round uses 0x34 both for its early overwrite of that destination and for its final second-destination update.

4. **Non-self-reference and delayed lookup.** If the first-round continuation differs from the first destination, its offset 0x54 receives the first destination, not itself. If that write overlaps the second-destination lookup location, the lookup observes the post-write memory.

5. **Replacement-sensitive traversal.** If retained-old-value offset 0x14 coincides with selected-record offset 0x14, the read used in forming the first product address occurs after replacement. Reusing a pre-replacement value violates the ordering.

6. **Repeated accesses.** Where individual represented accesses are observable, the initial repeated factor-update pair comprises two word writes and two byte writes. Identical final contents do not justify deleting one pair. This does not establish physical bus-transaction counts.

7. **Fresh final read.** If the intervening G3-base writes alter second-product offset 0x44, the byte later written to second-product offset 0x11 comes from the changed word, not the earlier retained word.

8. **Post-call global mutation.** If F-unknown-01 changes the fourth global and returns, the second call receives the subsequently obtained value. Global preservation is not required.

9. **Partial progress.** If a later access fails, already completed opening writes have no represented rollback. If F-unknown-01 does not return, the argument-7 assignment, second call, and terminal region are not reached.
