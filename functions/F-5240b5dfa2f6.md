# F-5240b5dfa2f6

## Purpose

F-5240b5dfa2f6 coordinates parsing into a caller-supplied destination slot. A flag word selects either a single delegated parse or a sequence-building path that prepares input, creates or empties a collection, and repeatedly parses and appends items.

The routine returns a 32-bit status word:

- `1`: success, with the working input cursor copied back to the caller.
- `0`: ordinary failure or an absent destination-slot pointer.
- `0xffffffff`: a distinct failure propagated from certain dependency calls.

These outcomes are not transactional. In particular, collection contents may be removed before a later failure, and ordinary parsing failure can invoke destination cleanup and clear the destination slot. Conversely, some early failures return without invoking that cleanup.

“Cursor,” “collection,” and “item” are descriptive interpretations of the visible operations, not established external type definitions.

## Interface

The routine has six arguments:

| Argument | Visible representation | Role |
|---|---|---|
| Destination slot | Pointer to a 32-bit word | Holds a destination value or collection handle. A null pointer causes immediate return of `0`. |
| Cursor slot | Pointer to a 32-bit word | Supplies the initial working cursor. Receives the final working cursor only on success through the routine’s common success exit. |
| Input extent | Signed 32-bit integer | Passed to dependencies as an extent and used to initialize a mutable remaining-extent value. Its unit is not established. |
| Configuration | Pointer to 32-bit words | Supplies flags at byte offset `0`, an explicit selector at byte offset `4`, and a dependency-specific value at byte offset `16`. |
| Auxiliary argument A | Opaque 32-bit value | Forwarded to the initial parse or preparation dependency. |
| Auxiliary argument B | Opaque 32-bit value | Forwarded to the single parse and to each sequence-item parse. |

The destination and cursor slot contents may represent addresses, handles, or another 32-bit encoding. The supplied material does not establish their complete types.

### Configuration layout

The following fields and bits are visibly used:

- **Offset `0`, bits `0x02` and `0x04`:** if either is set, select the sequence-building path. Otherwise select the single-parse path.
- **Offset `0`, bit `0x08`:** selects whether the selector comes from the configuration’s second word.
- **Offset `0`, bits `0xc0`:** form a masked option value, retained only when bit `0x08` is set.
- **Offset `4`:** explicit 32-bit selector, read only when bit `0x08` is set.
- **Offset `16`:** opaque dependency argument, read where the relevant dependency call is made.

No use of the words at offsets `8` or `12` is visible in this routine. That does not establish that dependencies ignore them, because cleanup receives the configuration pointer itself.

### Preconditions

After a nonnull destination-slot pointer is accepted, the routine reads the configuration flags and then the cursor slot. Those locations must therefore be readable even if a later dependency fails immediately.

Additional requirements are path-dependent:

- The destination slot must support the reads and writes reached on the selected path.
- The configuration must expose offset `4` when explicit-selector mode is selected and offset `16` when a call using that field is reached.
- Dependencies must accept the supplied handles, cursor values, extents, and opaque arguments.
- Preparation must initialize the status byte before any successful path that subsequently reads it.

No pointer validation, bounds validation, or alias rejection is visible. Aliasing the destination slot, cursor slot, configuration, or dependency-accessible memory can change subsequent reads. The behavioral descriptions below assume those locations do not overlap unless explicitly stated otherwise.

## Behavior

### Entry and option selection

If the destination-slot pointer is null, return `0` immediately. The routine does not first read the cursor slot or configuration.

Otherwise:

1. Read the 32-bit configuration flags.
2. Copy the caller’s cursor value into a private working cursor.
3. Initialize a private remaining extent from the input extent.
4. Derive the masked options from flag bits `0xc0`.

The routine selects its path using the initially read flags. It does not visibly reload those flags to choose a different path after a dependency call.

Selector and option values are chosen as follows:

| Path | Bit `0x08` | Selector | Options |
|---|---:|---|---|
| Single parse | Clear | `0xffffffff` | `0` |
| Single parse | Set | Configuration word at offset `4` | Initial flags masked with `0xc0` |
| Sequence | Clear | `0x11` if bit `0x02` is set; otherwise `0x10` | `0` |
| Sequence | Set | Configuration word at offset `4` | Initial flags masked with `0xc0` |

Thus, when both `0x02` and `0x04` are set without `0x08`, the selector is `0x11`. Bit `0x04` alone selects `0x10`.

### Single-parse path

Call F-4ed56e8b59b4 with:

- The caller’s destination-slot pointer.
- The address of the private working cursor.
- The original input extent.
- The configuration word at offset `16`.
- The selected selector and options.
- Auxiliary arguments A and B.

Interpret its signed 32-bit result as follows:

- **Exactly `-1`:** return `0xffffffff` immediately. Do not copy the private cursor back, and do not invoke this routine’s common cleanup.
- **Any other nonzero value:** copy the private cursor to the caller’s cursor slot and return `1`. This includes negative values other than `-1`.
- **Zero:** take the common ordinary-failure path.

The dependency receives the actual destination-slot pointer, so it may change the caller’s destination before returning. This routine does not undo such changes on the special `-1` exit.

### Sequence preparation

Call F-38f7a73546d9 with ten visible arguments, in this order:

1. Address of the private remaining extent.
2. Zero.
3. Zero.
4. Address of a four-byte temporary status area.
5. Zero.
6. Address of the private working cursor.
7. Original input extent.
8. Selected selector.
9. Selected options.
10. Auxiliary argument A.

Only the first byte of the status area is subsequently inspected by this routine. Its semantic meaning is unknown.

Handle the preparation result as follows:

- **Zero:** call F-4fc89ec41a6d with the visible values `0x0d`, `0x84`, `0x3a`, `0`, and `0`, then return `0`. No destination cleanup or explicit destination clearing occurs on this exit.
- **Exactly `-1`:** return `0xffffffff` immediately, without copying back the cursor or invoking common cleanup.
- **Any other value:** proceed to collection initialization.

Preparation can change the private cursor and remaining extent. Those changes remain private unless execution later reaches the common success exit, subject to any indirect dependency effects.

### Collection initialization or clearing

Read the destination slot after successful preparation.

If it contains zero:

1. Call F-c141a8d8555e with no visible arguments.
2. Store its 32-bit result in the destination slot.

If it contains a nonzero value:

1. Capture that value as the collection handle for the clearing loop.
2. Call F-10b760faca36 with the captured handle.
3. While that result is strictly positive under signed comparison:
   - Call F-2eeed9557344 with the captured handle.
   - Store its result in a private item slot.
   - Call F-bd0a5082b3f8 with the address of that item slot and the configuration word at offset `16`.
   - Query F-10b760faca36 again with the same captured handle.

A zero or negative query result terminates clearing. A negative result is not separately treated as an error.

After creation or clearing, reread the destination slot. If it is zero, take the common ordinary-failure path using diagnostic value `0x84` rather than `0x83`.

The captured handle used for clearing is not refreshed on each iteration. Later appends, by contrast, read the destination slot again.

### Sequence processing

Each iteration records the current working cursor before any scanner or item-parser call.

If the remaining extent is less than `1` under signed comparison:

- First status byte equal to zero: succeed.
- First status byte nonzero: fail through common ordinary failure with diagnostic `0x83`.

For a positive remaining extent, call F-04d7b0f7c6e9 with the address of the private working cursor.

If that call returns nonzero:

- First status byte nonzero: succeed.
- First status byte equal to zero: fail through common ordinary failure with diagnostic `0x83`.

If the scanner returns zero:

1. Initialize a private item slot to zero.
2. Call F-4ed56e8b59b4 with:
   - The address of that private item slot.
   - The address of the private working cursor.
   - The current remaining extent.
   - The configuration word at offset `16`.
   - Selector `0xffffffff`.
   - Options `0`.
   - Zero in place of auxiliary argument A.
   - Auxiliary argument B.
3. If the result is zero, take common ordinary failure with diagnostic `0x83`.
4. Otherwise, reduce the remaining extent by the difference between the current working cursor and the cursor recorded at iteration entry.
5. Call F-754616bec4de with the current contents of the destination slot and the private item value.
6. If the append result is nonzero, begin another iteration. If zero, take common ordinary failure with diagnostic `0x83`.

Unlike the initial single parse, an item parse does **not** give `-1` special handling. Any nonzero result, including `-1`, proceeds to extent adjustment and append.

The extent adjustment includes cursor movement by both the scanner and the item parser. The item parser nevertheless receives the pre-adjustment remaining extent; the routine does not first subtract scanner movement.

No explicit progress requirement is enforced. Successful parsing and appending without cursor advancement can repeat indefinitely unless a dependency or another observable condition changes.

### Common success and failure

On common success, write the private working cursor into the caller’s cursor slot and return `1`.

On common ordinary failure:

1. Call F-4fc89ec41a6d with the visible values `0x0d` and the selected diagnostic value.
2. Call F-a8ecb9fc98cf with the destination-slot pointer and configuration pointer.
3. Write zero into the destination slot.
4. Return `0`.

The default diagnostic value is `0x83`; a zero destination after collection initialization or clearing selects `0x84`.

There is no direct cursor-slot write on this failure path. This does not guarantee that the cursor slot remains unchanged if arguments alias or dependencies mutate it indirectly.

## Side effects

### Directly established writes

The routine can directly write:

- A newly created collection value to the destination slot.
- Zero to the destination slot after common cleanup.
- The working cursor to the cursor slot on success.
- Private cursor, extent, item, and status storage used by dependencies.

Dependencies can cause additional externally observable effects. Their effects are not bounded by this routine’s visible writes.

### Mutation order and failure atomicity

In sequence mode, preparation precedes collection creation or clearing. Existing collection contents can therefore be removed before a subsequent item parse fails.

Common cleanup occurs before the routine explicitly clears the destination slot. Any effects of diagnostics or cleanup occur before that final write, assuming those calls return.

The routine does not restore removed contents, reverse successful appends, or roll back dependency changes.

### Ownership

The visible call pattern establishes that removed values are passed by address to F-bd0a5082b3f8, and parsed values are passed by value to F-754616bec4de. It does not establish whether either dependency consumes, retains, copies, or releases those values.

No separate item-disposal call is visible after an append failure. Whether cleanup handles that item, or whether the append dependency has already assumed responsibility, is unknown.

### Arithmetic

Cursor values, handles, configuration words, and return statuses are 32-bit quantities in the supplied representation. Remaining-extent comparisons are signed.

The remaining-extent update uses a cursor difference and subtraction represented as signed 32-bit arithmetic. No visible overflow check, monotonicity check, or range check exists. Behavior for differences outside the signed range, or overflowing extent arithmetic, requires machine-level clarification; mathematical unbounded subtraction must not be assumed.

The routine’s arithmetic does not establish whether cursor differences count bytes, characters, or another unit.

## Acceptance examples

These examples are conditional contracts, not executed tests. Unless stated otherwise, arguments do not alias, dependencies return normally, and no indirect mutation affects the stated slots.

1. **Null destination-slot pointer.**  
   Even with unusable cursor and configuration pointers, return `0` without reading them.

2. **Single-parse defaults.**  
   With bits `0x02`, `0x04`, and `0x08` clear, the parser receives selector `0xffffffff` and options zero, even if bits `0xc0` are set.

3. **Successful single parse.**  
   If the parser changes the private cursor and returns `2`, return `1` and copy that cursor to the caller. No common diagnostic or cleanup call occurs.

4. **Special single-parse failure.**  
   If the parser returns `-1`, return `0xffffffff`. Do not directly copy back the cursor or invoke common cleanup; parser destination mutations are not reversed.

5. **Preparation failure.**  
   If sequence preparation returns zero, issue the five-value diagnostic call and return `0`. Do not explicitly clear or clean up the destination.

6. **Empty prepared sequence.**  
   If preparation succeeds, collection setup leaves a nonzero destination, remaining extent is nonpositive, and the first status byte is zero, return `1` with the prepared cursor. A previously populated collection may already have been emptied.

7. **Opposite status polarity at scanner termination.**  
   With positive remaining extent and a nonzero scanner result, a nonzero status byte succeeds; a zero status byte fails. This is the inverse of the exhausted-extent condition.

8. **Item parser returns `-1`.**  
   In sequence mode, this proceeds to extent adjustment and append. It does not directly produce outer return `0xffffffff`.

9. **Append failure.**  
   After a nonzero item-parse result, an append result of zero causes diagnostic `0x83`, common cleanup, explicit destination clearing, and return `0`. The private cursor is not directly committed.

10. **Cursor advancement across two dependencies.**  
    If an iteration begins at cursor value `100`, the scanner advances it to `102`, and the item parser advances it to `107`, remaining extent decreases by `7`, provided arithmetic is representable. It does not decrease by only `5`.
