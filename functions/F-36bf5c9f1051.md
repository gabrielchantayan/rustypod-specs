# F-36bf5c9f1051

## Purpose

F-36bf5c9f1051 performs an initial operation on a supplied object, optionally refreshes one stored value, and then either returns early or continues through lookup, candidate processing, and final dispatch.

There are two normal-return outcomes:

- An early exit returns the 32-bit value `1` when either discriminator is nonzero after the specified conversion and reads.
- Successful continuation returns the saved 32-bit result of the initial dependency, independently of the final dispatch’s result.

Two lookup failures reach a dependency annotated as non-returning. No normal error return is established for those branches.

“Object,” “candidate,” “refresh,” and “completion” identify structural roles. Their application-level meanings are unknown.

## Interface

### Inputs and result

The function receives:

1. An object address used for word accesses, byte accesses, and indirect dispatch.
2. An unsigned 32-bit option.

The option is tested for zero but is not restricted to Boolean values. Any nonzero option enables refresh. On the completion path, the original option is passed unchanged to the final dependency, together with a second value obtained by a 32-bit exclusive OR with `1`.

The normal result is an opaque 32-bit quantity. The initial dependency’s result has no established success, failure, signedness, or Boolean interpretation.

### Object layout

Offsets are byte offsets from the input object. Widths describe the supplied static representation, not independently verified machine transactions.

| Offset | Represented width | Direct use |
|---|---:|---|
| `0x00` | 32 bits | Dispatch-table address used for final dispatch. |
| `0x20` | 32 bits | Word read whose value is converted to a character-sized value for the first discriminator. |
| `0x41` | 8 bits | Second discriminator, read only if the converted first value is zero. |
| `0xB8` | 32 bits | Optional refresh destination. |
| `0xE0` | 32 bits | Field passed to final dispatch. |
| `0xE8` | 8 bits | Flag written around the initial dependency call. |

The first discriminator is **not represented as a direct byte dereference at `0x20`**. The represented operation reads a 32-bit element there, converts its value to the character-sized type, and tests the converted value.

Consequently:

- Testing the entire word directly for nonzero is not equivalent.
- A nonzero word can produce a zero narrowed value.
- The evidence does not identify the narrowed value with the byte physically located at `0x20`.
- Neither endianness nor the width of an actual machine memory transaction is established.

The flag writes at `0xE8` are explicitly byte-sized. They do not establish writes to neighboring bytes.

### Preconditions

The function performs no visible validation of the input address, storage extent, alignment, lifetime, dispatch-table address, or indirect targets.

Storage and dispatch structures must remain valid for the operations actually reached. In particular, the first discriminator is represented using a word access, not merely access to one byte. Requirements imposed by dependencies remain unknown.

Validity is path-dependent: early exit avoids the function’s lookup and final dispatch, but does not avoid the initial dependency or an enabled refresh.

Non-null dependency results are not sufficient evidence of valid storage, valid dispatch tables, or continued lifetime.

## Behavior

The following ordering describes the function’s own operations. Each continuation assumes preceding calls return normally. Dependencies may introduce additional effects.

### Initial operation and flag writes

The function first writes byte value `1` at input-object offset `0xE8`. It then invokes F-UNRESOLVED-01 with the input object and saves that dependency’s 32-bit result. After a normal return, it writes byte value `0` at `0xE8`.

The original flag value is not preserved. This is an overwrite-and-clear sequence, not restoration of entry state.

The dependency may itself modify the flag. The surrounding writes therefore do not establish that the flag remains `1` throughout its execution.

No cleanup mechanism is visible for an abnormal departure from the dependency. If that call does not return normally, the later clear is not established.

### Optional refresh

If the original option is nonzero, the function calls F-76b1c50b12f7 and then F-22be49cfb47c. It stores the latter dependency’s 32-bit result at input-object offset `0xB8`.

Neither call has explicit arguments in the supplied representation. Their full argument contracts and internal effects are unknown.

If the option is zero, both calls and this direct store are skipped.

Refresh precedes discriminator evaluation. An invocation that eventually returns `1` may therefore already have completed both refresh calls and the store.

### Discriminator evaluation

After the initial call, flag clear, and any refresh:

1. The function reads the represented 32-bit element at input-object offset `0x20`.
2. It converts that word value to the represented character-sized type.
3. It tests the converted value against zero.

If the converted value is nonzero, the function returns the 32-bit value `1`. It does not perform the second discriminator read.

If the converted value is zero, the function reads the character-sized value directly at offset `0x41`. A nonzero value there also causes return of `1`.

Only when both tested values are zero does lookup begin.

These are reads after the preceding dependencies, not snapshots from function entry. Any dependency mutation before a read may affect that read’s result.

The distinction between the represented word read and the subsequent narrowing is part of the contract. Neither a full-word truth test nor an asserted physical-byte test captures that distinction. The exact conversion behavior for values outside the character type’s range is not independently established here.

### Lookup and candidate acquisition

The first F-d99467d4d2b3 call receives a visible zero argument. The value used for this argument is the second discriminator after it has been found equal to zero.

If this call returns zero, the function reaches F-a817d8d58c10.

Otherwise:

1. F-938c950e5046 supplies an address used as a dispatch receiver.
2. F-d99467d4d2b3 is called again.
3. F-UNRESOLVED-02 is selected through that receiver’s dispatch table at byte offset `0xE8`.
4. The indirect call receives the receiver and the second F-d99467d4d2b3 result.
5. Its result is treated as a candidate address.

The second F-d99467d4d2b3 call has no explicit arguments in the representation. It must not be assumed to receive zero, reuse the first call’s effective inputs, or return the same value.

The two calls are distinct observable operations. Replacing the second call with the first result would not preserve the established sequence.

The receiver from F-938c950e5046 is not visibly null-checked before dispatch. Its dispatch table is used after the second F-d99467d4d2b3 call; preservation across that intervening dependency is not guaranteed.

A null candidate reaches F-a817d8d58c10. A non-null candidate proceeds.

### Candidate processing

F-UNRESOLVED-03 is selected through the candidate’s dispatch table at byte offset `0x1C` and called with the candidate. Its 32-bit result is tested against zero.

If that result is zero, the remainder of candidate processing is skipped.

For a nonzero result, F-682adfd5a561 receives:

- The candidate-derived 32-bit value.
- The constant `0x6800`.

Its result is treated as an object address and checked for null.

**Non-null result:** F-UNRESOLVED-04 is selected through the returned object’s dispatch table at byte offset `0x58` and invoked. No explicit arguments are shown. The representation does not establish whether an implicit receiver or other arguments are supplied by the underlying calling convention.

**Null result:** the function calls F-8157a180d901 with `0x1C`, then calls F-2606ad6d534d. It subsequently invokes F-UNRESOLVED-05 through the candidate’s dispatch table at byte offset `0x2C`, passing the candidate and the F-2606ad6d534d result.

Both branches continue to completion if their calls return normally. In particular, a null result from F-682adfd5a561 is not itself a terminal failure or normal return.

No units or domain meanings are established for `0x6800` or `0x1C`. The dispatch offsets are byte displacements, distinct from constants passed as arguments.

### Completion and normal return

2. F-8f9bd59e3ec5 is called with that result and the original input object.
3. F-UNRESOLVED-06 is invoked through the input object’s dispatch table at byte offset `0x124`.

2. The 32-bit field at input-object offset `0xE0`.

4. Zero.

The field and dispatch target are obtained for this late call after F-8f9bd59e3ec5 returns. They are not entry-time snapshots. Earlier dependencies may change the object, the field, or its dispatch table.

The representation does not establish the relative ordering of the individual field and dispatch-table reads used to prepare that call. Argument-list order must not be interpreted as memory-read order.

## Side effects

The function’s direct writes are limited to:

- Byte value `1`, followed after the initial call by byte value `0`, at offset `0xE8`.
- The 32-bit refresh result at offset `0xB8` when the option is nonzero.

The first discriminator entails a represented word read at `0x20` followed by narrowing. The second discriminator entails a conditional character-sized read at `0x41`. This distinction does not establish physical memory transaction widths.

All other effects occur through dependencies. Those dependencies may mutate objects, globals, dispatch tables, resource state, or memory validity. No preservation contract is supplied.

No direct allocation, deallocation, reference-count operation, ownership transfer, or release is visible. Using a returned address as a receiver does not establish whether it is borrowed, owned, retained, or consumed. The absence of a visible release does not establish a leak or a dependency’s ownership behavior.

Completed writes and dependency effects are not rolled back on early return or terminal failure.

No synchronization, atomicity, concurrency, or reentrancy guarantee is established. The temporary flag must not be described as a lock solely from its surrounding writes.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Continuation assumes valid reached storage and normally returning dependencies, except for the terminal dependency.

### First converted discriminator is nonzero

Suppose the initial dependency returns `0x12345678`, the option is zero, and the word read at `0x20` converts to a nonzero character-sized value.

Required behavior:

- Write `1` at `0xE8`, call the initial dependency, then write `0`.
- Skip refresh.
- Evaluate the first discriminator through the represented word read and conversion.
- Return `1`, not the saved initial result.
- Skip the discriminator read at `0x41` and the lookup sequence.

This criterion makes no claim about which physical byte represents the converted value.

### A nonzero word narrows to zero

Suppose the word read at `0x20` is nonzero but converts to zero under the applicable character conversion, and the subsequently read value at `0x41` is zero.

The function begins lookup. Returning early merely because the original word was nonzero would violate the represented behavior.

Under an additionally established low-eight-bit narrowing model, `0x00000100` would illustrate such a word. That numeric illustration is conditional; the narrowing model and endianness are not independently established by this contract.

### Second discriminator controls the exit

Suppose the first word converts to zero, but the character-sized value subsequently read at `0x41` is nonzero.

The second read occurs, the function returns `1`, and lookup is skipped.

### Refresh precedes early return

Suppose the option is `2`, F-22be49cfb47c returns `0xFFFFFFFF`, and either discriminator subsequently tests nonzero.

Both refresh calls occur in order, the full 32-bit result is stored at `0xB8`, and the function then returns `1`.

### Lookup failures

With both discriminators zero:

- If the first F-d99467d4d2b3 result is zero, the terminal dependency is reached without F-938c950e5046, the second F-d99467d4d2b3 call, or lookup dispatch.
- If the first result is nonzero but lookup dispatch returns null, the terminal dependency is reached after those intervening calls.

Neither case reaches final dispatch.

### Candidate-derived value is zero

Suppose lookup produces a non-null candidate whose `0x1C` dispatch returns zero.

F-682adfd5a561 and both downstream processing branches are skipped. Completion proceeds through F-fdd8589eca2d, F-8f9bd59e3ec5, and final dispatch.

### Conversion-result branches

For a nonzero candidate-derived value:

- A non-null F-682adfd5a561 result causes dispatch through that result’s `0x58` slot.
- A null result causes F-8157a180d901 with `0x1C`, then F-2606ad6d534d, then candidate dispatch at `0x2C`.

Both branches continue to completion on normal returns.
