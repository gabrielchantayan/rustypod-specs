# F-e14a2dac0912

## Purpose

F-e14a2dac0912 performs an ordered, nontransactional mutation of memory selected through explicit arguments, additional incoming execution state, external words, and values obtained from earlier reads. After these mutations, it invokes an incoming indirect callback. If that callback returns, it modifies additional argument-associated and stack-associated storage, invokes F-cdec09f5d432, and, if that dependency returns, reaches a terminal sequence represented as nonreturning.

No application-level purpose is established. Address-bearing writes, repeated self-references, and recurring displacements do not establish a list, object model, serialization format, allocator, or device protocol.

This contract distinguishes:

- **Established static evidence:** behavior directly supported by the supplied representation.
- **Inferred intent:** a possible interpretation, not a required behavior.
- **documented_only:** an unresolved property for which no guarantee is supplied.

The seven explicit arguments are insufficient to determine the function’s effects.

## Behavior

### Widths and numeric interpretation

The represented memory access widths are 8, 16, and 32 bits. All displacements below are measured in bytes.

Byte stores retain the low eight bits of their source. Halfword stores retain the low sixteen bits. A stored address-bearing value therefore becomes a narrow bit pattern at a narrow destination; the source’s other uses do not enlarge that destination.

Halfword loads are represented as signed 16-bit quantities. When promoted for arithmetic, a halfword pattern of 0xffff contributes −1 rather than 65535. These signed values can determine addresses directly, including addresses formed by doubling or tripling them.

The signedness of plain byte loads is unresolved. Some loaded bytes subsequently supply address bases and halfword-store values. For high-bit-set bytes, the choice of sign extension or zero extension can therefore change both destinations and stored halfword patterns.

Address-bearing arithmetic is represented using 32-bit quantities. It includes addition, doubling, tripling, left shifts by one, four, and eight bits, and multiplication involving promoted signed halfwords. Later calculations multiply already-derived products again.

This evidence does not establish unlimited mathematical-integer arithmetic or a portable overflow rule. Signed overflow, negative left shifts, address wrapping, byte order, alignment requirements, and atomicity remain **documented_only**. No explicit detection or recovery for these conditions is represented.

### Observable ordering and aliasing

The body is a straight-line mutation sequence without a represented loop, conditional decision, checked error result, or early return. Its repeated patterns are not independent transactions.

The following ordering constraints are especially important:

- The first memory mutation is a halfword store at the sum of argument 3 and the lookup base, using the anchor’s low sixteen bits. The lookup-base word at displacement 0x44 is read afterward.
- The working base is stored to its own displacement 0x54 before the initial external linking state is acquired.
- Argument 4 supplies the initial byte written at the working base’s displacement 0x11. The word read through argument 1 at displacement 0x64 occurs afterward; its low byte supplies a later write.
- Later word and halfword reads occur among intervening narrow stores, self-reference stores, and externally supplied linking stores. They are not observations of a common initial snapshot.
- A late word at displacement 0x14 is saved before that location is replaced by twice the then-current working base. Subsequent indirection uses the saved value where represented, not a reread of the replacement.
- A product-derived word location at displacement 0x44 is read on separate occasions, with a byte store between those observations. The reads cannot generally be merged under arbitrary aliasing.

No nonaliasing relationship is established among arguments, incoming bases, external storage, or indirect destinations. Consequently, an earlier halfword or byte store may change a later word read. A write through a loaded address may also alter an external word or argument-associated storage.

Repeated writes remain part of the represented behavior even where their values appear redundant. Whether a platform exposes each access independently—for example, through special memory—is unresolved; the contract does not authorize treating all destinations as ordinary, disjoint record fields.

### Computed-address behavior

Several accesses cannot be described solely as selecting fields from incoming objects.

An early byte destination combines two dynamically obtained quantities. A signed halfword separately determines doubled and tripled addresses. Another halfword destination combines twice a working base with a dynamic quantity. Later word destinations use sums of loaded state.

The late portion introduces multiplication-dependent addressing. It combines a promoted signed halfword with a loaded word, traverses a word-read chain using displacements 0x44, 0x74, and 0x14, and obtains the value that must be saved before the displacement-0x14 replacement.

Further indirection from that saved value contributes to another product. A word at displacement 0x74 is retained before another multiplication changes the product used for subsequent destinations. Later accesses use the resulting product, twice that product, and an additional multiplication by the retained halfword-derived quantity.

Thus, “the product” is not one stable address throughout this portion. Distinct stages determine distinct reads and writes.

The retained displacement-0x74 word also supplies a later word store at displacement 0x64, a narrowed byte at a doubled-product-derived destination, and callback-preparation state. Another read through the earlier indirect base supplies a byte stored at displacement 0x01 from that retained word’s value.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless an example concerns a failure, required accesses are assumed to complete.

1. **Initial narrowing.** If the incoming anchor has bit pattern 0x12345678, the first halfword store has bit pattern 0x5678. This does not determine byte order.

2. **Overlap with an early read.** If the first halfword destination overlaps the lookup-base word at displacement 0x44, that word is read after the mutation. Using a prefetched original word would violate the established order.

3. **Argument byte versus loaded byte.** The early working-base byte at displacement 0x11 comes from argument 4. A later write uses the low byte of the word read through argument 1. These are distinct sources.

4. **Negative halfword.** A loaded halfword pattern of 0xffff contributes −1 to the represented promoted arithmetic. It is not interpreted as 65535. Whether any resulting address is usable remains unresolved.

5. **High-bit-set byte.** For a loaded byte pattern of 0x80 later used as an address base, this contract does not select signed or unsigned widening. Requiring exactly one derived address would exceed the evidence.

6. **Saved state.** When a displacement-0x14 word is saved before replacement by twice the current base, later calculations using the saved value must not substitute the replacement.

7. **Separate observations.** If an intervening byte store aliases the product-derived word at displacement 0x44, the later read must not be assumed equal to the earlier read.

8. **Unresolved-byte destinations.** A later initialized byte written through a changed base does not establish that an earlier unresolved-byte destination was overwritten.

9. **Callback reachability.** If all preceding accesses complete, F-unresolved-01 receives the argument-5-associated address and two zeros. The post-callback assignments have not yet occurred.

10. **Nonreturning callback.** If F-unresolved-01 does not return, neither the post-callback assignments nor F-cdec09f5d432 nor the terminal sequence is reached.

11. **Callback-modified external state.** If the callback changes the external word later supplied to F-cdec09f5d432, the contract does not require use of its pre-callback value.

12. **Terminal path.** If both callable dependencies return and intervening accesses complete, execution reaches the represented nonreturning terminal sequence; ordinary return is not promised.

13. **Partial effects.** A failure during late product-derived addressing does not establish reversal of earlier successful stores.
