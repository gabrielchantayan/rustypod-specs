## Behavior

### Initial state and indirect invocation

The fourth argument is copied into a local 32-bit working cell before the indirect call. This cell is initialized even if the dependency elects not to write it.

The function then resolves the callable through the first argument’s dispatch-bearing word and the table entry at byte offset 0x20. It invokes that callable with:

- The original first argument.
- The address of the initialized working cell.

The indirect dependency’s result is used only as a zero-versus-nonzero status. No particular nonzero value is required: negative and positive nonzero statuses take the same visible branch.

There is no direct write to the caller’s output storage before this invocation. This ordering does not imply that the dependency cannot modify that storage indirectly through aliases or other state available to it.

### Candidate selection

If the indirect dependency returns zero, the working cell does not affect the subsequent output decision. The function selects the direct-zero-output path regardless of the cell’s initial or final contents.

If the dependency returns nonzero, the candidate used for classification is the working cell’s low 16 bits after the call returns. Its upper 16 bits have no effect on classification or on a direct output store.

Thus, truncation occurs before comparison with 10 or 13. A successful working value with nonzero upper bits can still select either special case.

If a successful dependency leaves the working cell unchanged, the fourth argument supplies the effective candidate. The function does not require an observed write to that cell before using it.

### Zero-status and value-10 handling

Either of these conditions selects the same behavior:

- The indirect dependency returns zero.
- It returns nonzero and the candidate is 10.

The function writes a 16-bit zero to the second argument’s destination and returns 1.

In particular, a zero dependency status is not propagated as a zero function result. At this wrapper’s boundary, it is mapped to zero output with result 1.

The function performs no retry and no additional visible dependency invocation on this path.

### Value-13 delegation

On this path:

- There is no direct output store by F-cf333f114d7c before the delegated invocation.
- The fourth argument and working-cell address are not explicitly forwarded.
- The third argument is not forwarded.
- F-fce1d82bd517’s result becomes this function’s result.
- There is no visible output adjustment or result conversion after delegation.

The delegated function may have its own output, state, error, and ownership behavior. None of those details can be inferred merely from this call site.

### Other successful candidates

This includes candidate zero. A successful zero candidate therefore produces the same visible output and result as a zero dependency status, although the branches differ internally.
