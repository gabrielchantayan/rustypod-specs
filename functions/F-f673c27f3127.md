# F-f673c27f3127

## Purpose

F-f673c27f3127 exchanges the contents of two caller-supplied locations, each represented in the supplied source as holding one 32-bit value.

The established behavior is a raw value exchange. The function does not inspect the values, perform arithmetic on them, or interpret them as addresses, handles, signed numbers, or structured records. All 32 bits participate in the exchange.

The apparent intent is an in-place swap of two four-byte storage units. That intent does not establish support for invalid addresses, insufficiently sized storage, incompatible alignment, concurrent access, or partially overlapping locations.

This contract describes static source evidence only. No runtime tests have been performed.

## Interface

**Inputs**

The function accepts two address arguments:

- **First location:** an address from which one 32-bit value is read and to which one 32-bit value is subsequently written.
- **Second location:** an address from which one 32-bit value is read and to which one 32-bit value is subsequently written.

Both addresses must therefore designate readable and writable storage for successful ordinary execution. Neither argument is optional in the visible implementation. There is no null check or alternate behavior for an omitted location.

The source represents each stored unit as four bytes, or 32 bits. It provides no further type semantics for those bits. In particular, the contract does not assign signedness, a numeric range smaller than the full bit-pattern space, or ownership meaning to a stored value.

**Output**

The function returns without a result value. Its observable result is the mutation of the two addressed locations.

For distinct, nonoverlapping valid locations, successful execution leaves:

- The first location containing the value read from the second location.
- The second location containing the value originally read from the first location.

“Originally” refers to the first read performed by this function, not necessarily to a value observed earlier by the caller or another agent.

**Layout and calling requirements**

Each address is used directly as the address of one 32-bit unit. No offset, stride, length, or enclosing-object layout is supplied or calculated.

The source does not establish the machine-level calling convention, pointer width, required alignment, or byte order. Those properties belong to the execution environment and are documented_only here.

For the straightforward exchange guarantee, the caller must provide storage that remains accessible throughout the call and is not changed by another actor during the operation. This is a precondition for that guarantee, not a synchronization mechanism supplied by the function.

## Behavior

### Established access sequence

The visible operation has the following order:

1. Read one 32-bit value from the first location and retain that value temporarily.
2. Read one 32-bit value from the second location.
3. Write the value obtained by the second read into the first location.
4. Write the retained value from the first read into the second location.
5. Return without a result value.

Both source values are therefore read before the first visible destination write.

The retained first value is essential to the behavior: the final write uses what the first read obtained, rather than rereading the first location after it has been overwritten.

This ordering describes the source-level operations. The supplied material does not establish the exact number, width, or ordering of physical bus transactions, nor does it establish what another thread or device can observe under a particular compiler and hardware memory model.

### Distinct, nonoverlapping locations

When the locations are valid, distinct, nonoverlapping, and stable except for this function’s writes, the result is an exchange of their complete 32-bit contents.

The values themselves do not affect control flow. Equal values, zero values, values with the highest bit set, and all-ones values follow the same access sequence.

There is no addition, subtraction, multiplication, narrowing conversion, or value-based indexing. Integer overflow and numeric wraparound do not arise from the visible operation. The function exchanges bits rather than computing a new numeric value.

Applying the function twice to the same two stable, nonoverlapping locations restores their initial contents, provided both calls complete successfully and nothing else modifies the storage between or during those calls.

### Identical addresses

The source contains no distinct-address requirement or equality check.

If both arguments designate exactly the same valid 32-bit location, and that location is not independently changing, both reads obtain the same value. Both subsequent writes write that value back to the same location. Its final contents are unchanged.

This is not an early-return case. The visible source still contains the two reads and two writes. Unchanged final contents must not be interpreted as proof that no access occurred, particularly where an execution environment gives reads or writes additional effects.

### Partial overlap

The source does not check whether two different addresses designate partially overlapping four-byte ranges.

If an execution environment permits such accesses, the meaningful ordering remains: capture the first value, obtain the second value, write the second value to the first range, then write the captured first value to the second range.

Partial overlap is not equivalent to exchanging two independent objects. The last write can overwrite bytes written by the preceding write. Consequently, the simple postcondition that both ranges simultaneously contain the other range’s original four-byte contents is not generally guaranteed.

A byte-exact outcome additionally depends on the environment’s permitted access semantics and representation. Support for partially overlapping or unaligned operands is documented_only, not established by the source.

### Invalid access and interruption

There is no input validation, error return, retry, recovery branch, or rollback in the visible body.

If the initial read cannot complete, the source places no destination write before that read. If the second read cannot complete, the source likewise places no destination write before it.

If the first destination write completes but the final write does not, the operation is not transactionally complete. No restoration step is present.

These statements describe operation order, not a promise about how a particular platform reports faults or whether a failing machine access can have partial effects. The source does not establish those platform behaviors.
