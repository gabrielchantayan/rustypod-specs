# F-0e78d391116e

The established behavior is:

- Header bit 7 selects a payload starting one or two bytes after the input address.
- Header bits 0–1 select a zero result or a payload of one, two, or three bytes.
- Multi-byte payloads use little-endian significance.
- Header bits 2–6 do not contribute to the returned value or the payload selection.
- The function does not write memory, advance a caller-owned cursor, allocate storage, or invoke another function.

The apparent intent is decoding a small unsigned integer with an optional intervening byte. The meaning of that intervening byte and the surrounding format are not established.

## Behavior

For an input whose header remains stable during the call:

| Header property | Effect |
|---|---|
| Bit 7 clear | Payload begins at input offset 1 |
| Bit 7 set | Payload begins at input offset 2 |
| Bits 0–1 equal 0 | Return zero without reading payload |

1. The first obtains bit 7 to choose the payload location.
2. The second obtains bits 0–1 to choose the payload width.

The payload location is selected before the width is examined. A location one byte beyond the input is formed initially; when the first header observation has bit 7 set, the location two bytes beyond the input is selected instead.

For stable ordinary memory, both header observations describe the same byte. The source does not explicitly capture the entire header once and reuse that captured value.

| Selector | Payload reads, in order | Result |
|---|---|---|
| 0 | None | Zero |
| 1 | Offset 0 | That byte’s unsigned value |
| 2 | Offset 1, then offset 0 | Offset 0 plus 256 times offset 1 |
| 3 | Offset 2, then offset 1, then offset 0 | Offset 0 plus 256 times offset 1 plus 65,536 times offset 2 |
