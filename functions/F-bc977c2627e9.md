# F-bc977c2627e9

## Purpose

F-bc977c2627e9 recognizes an input item through callbacks, constructs bounded decimal digit sequences, invokes conversion dependencies, and conditionally stores a one-word or two-word result.

Established recognition includes an optional leading sign, a context-selected radix byte, decimal digits, and a decimal exponent. Particular prefixes trigger delegated recognition. Floating-point scanning is inferred intent; the numeric encoding, rounding rules, and delegated grammars are not established here.

Recognition success and conversion are separate. On the ordinary path, decimal conversion occurs before the function decides whether it has accepted the digits required for success. Suppressing assignment prevents destination access, not conversion.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Arguments and return value

The visible interface has four arguments, each represented by a 32-bit value or address:

| Argument | Established use |
|---|---|
| First | Retained locally; no further semantic use is visible |
| Second | Opaque input context passed to input callbacks and delegated recognizers |
| Third | Address of a writable 32-bit progress value |
| Fourth | Address of a mutable control record |

The 32-bit return value is:

- `-1` when the final read of the initial filtering phase returns `0xffffffff`.
- `-2` when ordinary finalization finds its current digit-accepted flag clear.
- The accumulated count on ordinary success, whether or not assignment is suppressed.
- A delegated recognizer’s result, propagated unchanged when that result is not `-3`.

A delegated result of `-3` requests local continuation. It is not itself an ordinary recognition-error result. Arithmetic extremes that could make a count coincide with a negative status are not resolved by the supplied evidence.

### Control record

| Byte offset | Established role |
|---|---|
| 0 | Mutable cursor into a sequence of 32-bit destination-pointer entries |
| 4 | Flags, copied near entry |
| 8 | Signed-looking 32-bit width, copied near entry |
| 24 | Input-read callback address |
| 28 | Repositioning callback address |

Each callback address is fetched from the record when needed and masked with `0xfffffffc`; its low two bits do not participate in the call address.

The read callback receives the input context and returns a 32-bit value. The repositioning callback receives that context, and its return value is ignored. The filtering callback receives no explicit argument; a nonzero result repeats the initial read/filter cycle.

Flags and width are local snapshots. Changes made by this function to those local values are not written back to their control-record fields.

## Behavior

### Initialization, radix lookup, and filtering

Flags and width are copied before F-187ab9ba4eb6 is called. Its returned context supplies the radix byte: a pointer is obtained from context offset 44, a 32-bit displacement is read through that pointer, and one byte is read at the pointer plus that displacement. That byte is zero-extended for comparisons.

These accesses precede the initial input loop, including when the eventual input result is end-of-input. The visible grammar compares one radix byte, not a multibyte separator.

The initial phase alternates an input-read call and a filtering call until the filter returns zero. The filter is called even when the corresponding input result is `0xffffffff`; only after filtering stops is that input result checked for end-of-input.

For \(r\) reads in this phase, the count is \(r-1\). Earlier reads contribute to the count without reducing width. The final read supplies the current lookahead. Calling this phase whitespace skipping is inferred intent, not an established filter contract.

A final lookahead of `0xffffffff` returns `-1` immediately, without ordinary repositioning, decimal conversion, or destination handling.

### Leading sign and delegated recognition

A leading `+` or `-` is consumed only when the copied width is positive. Consuming it increments the count, reads another input value, and then decrements width. Only `-` sets the negative-leading-sign flag.

The internal mantissa representation begins with a sign byte, `+` or `-`, even when no explicit sign was consumed.

With positive remaining width, lookahead `i`, `I`, `n`, or `N` invokes F-d86674b5a239. Its explicit arguments are:

- The 32-bit pattern `0xfffffffd`.
- The input context, progress address, and control-record address.
- The current count, local flags, and remaining width.

Any result other than `-3` returns immediately. On `-3`, local recognition continues with the existing local lookahead and recognition state. There is no visible rollback of dependency effects on input, progress, the control record, or other memory.

While width remains positive, leading `0` values are consumed without occupying retained mantissa-digit slots. Each increments the count, calls the read callback, decrements width, establishes digit acceptance, writes the count to progress, and increments the leading-zero tally.

If the subsequent lookahead is `x` or `X`, width remains positive, and exactly one leading zero was consumed, F-9da4d4bd3637 receives the same argument pattern. Its non-`-3` result returns immediately. Two or more leading zeros do not qualify for this delegation.

### Early radix and fractional zeros

Following leading-zero handling, the lookahead is compared with the radix byte without a positive-width prerequisite.

A match establishes radix acceptance and enters a special scan. Consuming the radix decrements width, increments the count, and reads another input value. Every consecutive `0` found by this scan decreases the decimal-scale adjustment by one, establishes digit acceptance, and writes progress through that zero. The scan then continues by consuming that zero and reading again.

There is no width-based termination condition within this scan. It continues through consecutive zeros even after width reaches zero or becomes negative. The first nonzero lookahead terminates it.

Consequently, width is not a global bound on reads or consumption.

### Main decimal recognition

The main loop runs only while remaining width is positive. It accepts:

- The radix byte if no radix has yet been accepted.
- A decimal digit, classified by whether its unsigned 32-bit difference from `0x30` is below ten.

An eligible radix match has priority over digit classification. If the configured radix equals a digit byte, the first eligible matching occurrence can be treated as radix rather than as a digit. Earlier leading-zero handling has its own ordering.

The mantissa retains at most 18 numeric digit bytes, each from 0 through 9:

- A retained digit after radix acceptance decreases the scale adjustment by one.
- A retained digit before radix acceptance leaves the adjustment unchanged.
- A digit beyond retention capacity is still accepted and consumed.
- An excess integral digit increases the adjustment by one.
- An excess fractional digit leaves the adjustment unchanged.

No visible rounding is performed when digits are discarded.

For each accepted main-loop character, width decreases. If digit acceptance is set after recognizing that character, progress is written as the count plus one. The count then increases, the next input read occurs, and the updated local recognition flags become current.

Thus a radix following accepted digits advances progress, although the radix is not a digit. A radix preceding all digits does not advance progress through this rule.

### Exponent recognition and overflow-word reads

An otherwise unaccepted `e` or `E` starts an exponent only when width is positive and mantissa digits have already been accepted.

Exponent entry clears both digit acceptance and exponent-negative state. Successful mantissa recognition therefore does not suffice for final success once exponent recognition begins.

The exponent marker is counted and followed by an input read even when it exhausts width. If width permits examining a following sign, `+` or `-` is consumed, counted, and followed by another read. An exponent sequence begins with its sign byte. Without an exponent, its ordinary conversion representation is an immediate terminator.

The exponent retains at most eight digit bytes. Leading zero digits are consumed, counted, and accepted but do not advance the retention cursor. Once a nonzero digit has advanced that cursor, subsequent zeros occupy capacity normally.

Each accepted exponent digit decreases remaining exponent width. Its retention or overflow processing occurs before the count increment and next input-read callback. After that callback returns, progress is written with the updated count, then digit acceptance is set.

For **every accepted digit after the eight retained slots are full**, overflow processing performs these ordered runtime accesses:

1. Read a first 32-bit global word and replace the decimal-scale adjustment with that value.
2. If the exponent is negative, read a second 32-bit global word and replace the adjustment again.

Both reads therefore occur for a negative exponent, in that order, before the next input-read callback. For a nonnegative exponent, only the first word is read. The first read on the negative path remains part of the access sequence even though the second assignment overwrites its contribution.

These are repeated reads of global storage, not established immutable constants or a selection between cached values. A later excess digit reads the applicable words again. An intervening callback can affect what the next read observes; preservation and mutability are not established.

Exponent processing ends on a nondigit or exhausted exponent width, then proceeds directly to finalization. Mantissa recognition does not resume.

### Ordinary finalization and assignment

Every ordinary finalization invokes the repositioning callback once. Its stream effect is unknown; interpreting it as restoring one lookahead value is inferred intent.

After that callback, the function terminates both internal sequences with `0xff`, zero-initializes two consecutive 32-bit result words, and calls F-e4f4e6c989bc with:

- The two-word result address.
- The exponent-sequence address.
- The mantissa-sequence address.
- The decimal-scale adjustment.

Only afterward does it check current digit acceptance. If clear, it returns `-2` without fetching a destination.

On success with `0x024` set, suppression returns the count immediately. Otherwise, the function reads the destination-list cursor, advances the cursor field by four bytes, reads the destination pointer from the saved entry, and writes the first result word followed by the second.

On success with `0x024` clear, F-c7bf4be19b88 is called first to obtain a one-word result from the two-word result. Suppression is checked only after this call. Unsuppressed assignment uses the same cursor-fetch, cursor-advance, and entry-read ordering, then writes one 32-bit word.

The two-word output consists of eight bytes of storage, but a particular floating-point encoding is not established.

## Side effects

Observable effects include input and filtering calls, repositioning, progress writes, conversion calls, reads of exponent-overflow global words, destination-cursor advancement, and result writes.

Progress is neither initialized nor cleared at entry. Its write timing differs by phase:

- Leading zeros: after the input-read callback.
- Early fractional zeros: after the read that discovers each zero.
- Main-loop acceptance: before the next input-read callback.
- Exponent digits: after the next input-read callback.

An error can coexist with prior progress updates. No rollback is visible for an incomplete exponent or delegated continuation.

The overflow global words are not visibly written by this function. Nevertheless, callbacks and dependencies are not established to preserve them. Repeated overflow reads can observe different values.

Callback addresses are fetched anew from the mutable control record. Earlier calls can therefore affect later callback selection. Local flags, width, and the radix byte remain local snapshots rather than being reloaded from their original sources.

Aliasing is not prevented. In particular, advancing the destination cursor precedes reading the destination pointer from the saved entry. Overlap among the control record, progress, destination entries, and output storage can change subsequent observed values.

## Acceptance examples

These are conditional static predictions, not runtime results. Unless stated otherwise, assume ASCII-valued input, radix `.`, immediately terminating initial filtering, adequate width, disjoint valid storage, and no dependency interference. Assume repositioning restores the final lookahead only where that interpretation matters.

- **`12Q`:** ordinary success returns 2. Progress advances through both digits. The mantissa supplied for conversion contains positive sign, numeric digits 1 and 2, and a terminator. Assignment follows the flags.

- **`-0.005Q`:** returns 6. The integral zero establishes acceptance without occupying mantissa retention space. Two fractional leading zeros contribute scale −2, and retained digit 5 contributes another −1. The mantissa contains negative sign and digit 5; scale is −3.

- **`.Q`:** the radix is consumed, but no digits establish acceptance. Repositioning and decimal conversion occur, followed by `-2`. No destination is fetched.

- **`1e+Q`:** exponent entry clears mantissa digit acceptance. No exponent digit restores it, so ordinary finalization returns `-2`. Earlier progress is not rolled back.

- **`1e0Q`:** returns 3. The exponent zero establishes acceptance despite not advancing the exponent retention cursor.

- **`0x…` versus `00x…`:** the first attempts F-9da4d4bd3637 if width remains positive at `x`; the second does not. A delegated result other than `-3` returns unchanged.

- **Width 1 with `.000Q`:** the special fractional-zero scan continues beyond width. Count reaches 4, and progress reaches 4. Ordinary finalization follows with digit acceptance set.

- **`1e1234567890Q`:** the first eight exponent digits fill retention capacity. Digit 9 reads the first overflow global word before the callback that reads digit 0. Digit 0 reads that word again before reading `Q`. If those reads yield \(A\) and \(B\), respectively, final scale is \(B\), absent other interference. The function does not reuse \(A\).

- **`1e-1234567890Q`:** for each of the last two exponent digits, the first global word is read and then the second. Both reads precede that digit’s following input-read callback. The final scale is the second word’s value at the last such read, not necessarily its value during the preceding overflow event.

- **Successful suppressed assignment:** no destination entry is fetched or advanced. Decimal conversion still occurs; one-word conversion also occurs when `0x024` is clear.
