# F-1d060f30d5b5

## Purpose

The established contract concerns observable memory accesses, dependency calls, and their ordering. Allocation release is an inferred purpose, not an established ownership contract. The supplied evidence does not establish whether notification releases a resource, whether either finalization dependency frees storage, or whether surrounding calls implement synchronization.

The function has no explicit return value. It can return without doing accounting, complete the accounting sequence, or invoke a dependency identified as non-returning when header validation fails.

2. The record’s 32-bit word at +0.
3. The literal zero.

**Alternative branch:** If the preferred-target test observes zero, context +8 is tested.

- Two decrements by one.

These are eight write operations, not necessarily eight distinct destinations. No non-aliasing requirement is established among context, record, metadata, and accounting storage. When valid addresses overlap, earlier writes can affect later reads.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Each case requires valid accesses and normal returns where later behavior is described. Stable memory or dependency preservation is required only where explicitly stated.

1. **Disabled context.** If the enable-byte read observes zero, the function returns without dependency calls or record access. The record need not be dereferenceable.

2. **Null record.** If the context enable byte is readable and nonzero, but the record is null, the function returns without dependency calls. This does not permit an unreadable context.

3. **No target.** If the preferred-target test observes zero and the alternative-target test observes zero, the function returns without clearing a record word or consulting its metadata.

4. **Preferred target wins.** With stable nonzero target fields, only F-080c1b708a86 is selected. It receives the first record word read for that call and zero as its third argument. After normal return, record +0 is cleared. Record +4 is not directly cleared by this function.

5. **Alternative notification with a zero value.** With a stable zero preferred target, a stable nonzero alternative target, and record +4 equal to zero when read, F-69819188e4c5 still receives a notification with zero as its second argument and one as its third. The subsequent clearing write still occurs.

6. **Validation failure based on observed reads.** After notification, clearing, F-2fd8826557a4, and state capture, a zero observed by the zero-check read invokes F-a817d8d58c10. Alternatively, a nonzero zero-check observation followed by bit 0 set at the separate bit-check read invokes the same dependency. Neither conclusion follows solely from the header’s entry value.

7. **An initially invalid header is repaired.** Suppose the entry header is zero, but an earlier dependency changes it to 0x10 and it remains 0x10 through both validation reads. Validation passes. The initial zero does not require failure.

8. **Non-atomic validation.** If the zero-check read observes 0x10 and the bit-check read subsequently observes zero, validation passes. This case does not establish what later amount reads observe.

9. **Masking.** If validation observes a stable header of 0xC0000012 and both amount reads also observe that value, validation passes and both accounting amounts are 0x10.

10. **Zero accounting amount.** If the header remains 0x40000000 through validation and both amount reads, validation passes and both amounts are zero. With normal dependency returns, both count decrements and both finalization calls still occur.

11. **Unsigned selector boundary.** A selector read of 65535 contributes a displacement of 262140 bytes before its counter-field offset is added. No selector-range failure is provided; the resulting address must be valid.

12. **Counter underflow.** For a valid amount-counter access containing 8 and an amount of 16, the stored result is 0xFFFFFFF8. A valid 32-bit count counter containing zero becomes 0xFFFFFFFF when decremented.

13. **Different final amount.** If the first amount read yields 16, F-09dcb55e8e0a changes the header so its masked value becomes 32, and that value remains through the final amount read, the first four amount updates subtract 16 while the update at state +8 subtracts 32.
