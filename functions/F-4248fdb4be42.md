# F-4248fdb4be42

## Purpose

F-4248fdb4be42 coordinates a staged operation against an object-associated resource. It obtains a context value through an indirect method, classifies that context, resolves additional data for selected classifications, and invokes a final operation using two caller-supplied values.

The established behavior is a gated sequence of dependency calls with cleanup. The function returns a 32-bit zero only when the initial method, resolution step, and final operation all report zero, and the classification is one of 2, 3, or 4. Every other normally returning path produces a 32-bit one.

The application-level meaning of the resource, classifications, selector values, resolved data, and final operation is unknown. Describing the operation as loading, decoding, copying, or transferring data would exceed the available evidence.

## Behavior

### 1. Obtain the context

The function first reads the dispatch-table address from the object, obtains the method at table offset 12, and calls it with:

1. The object address.
2. The address of a 4-byte context output slot.

The context slot has no explicit initialization before this call.

If the method returns anything other than zero, the function returns one immediately. It does not initialize either helper state, read either selector global, or invoke any of the named dependencies.

If the method returns zero, processing continues. The context slot is subsequently consumed without an additional validity check.

### 2. Initialize the primary helper and classify

The function calls F-a78f26e86530 with the address of a 4-byte primary-helper storage region. No explicit initialization of that region precedes the call, and no result from this dependency is tested.

It then calls F-cc79b872f81c with:

1. The primary-helper address.
2. The current 32-bit resource field read from object offset 4.
3. The current 32-bit context-slot value.

The returned classification controls the remaining work.

The object’s resource field is read after primary-helper initialization. It is not a snapshot captured before the initial method or before F-a78f26e86530.

### 3. Read and select the selector value

After classification, the function reads a first 32-bit global selector value. This read occurs for every classification that reaches this stage.

Selection then follows these rules:

| Classification | Additional global read | Resolution attempted |
|---|---|---|
| 2 | None | Yes, using the first selector value |
| 3 | Read the second selector value | Yes, using the second selector value |
| 4 | Read the second selector value | Yes, using the second selector value |
| Any other value | Read the second selector value | No |

Consequently, even an unsupported classification causes both selector globals to be read before the function proceeds to primary-helper cleanup.

For classifications 3 and 4, the first selector read still occurs, although its value is replaced by the second selector value for resolution.

The selector values are read after the classifier returns. No assumption is made that the initial method, initialization dependency, or classification dependency preserves those globals.

### 4. Resolve additional data for an accepted classification

For classification 2, 3, or 4, the function calls F-a2123d550bfc with:

1. The primary-helper address.
2. A fresh read of the object’s resource field.
3. The context-slot value as supplied at this call.
4. The selected 32-bit selector value.
5. The address of a 4-byte resolved-value output slot.
6. The address of a separate 4-byte auxiliary storage region.

Neither output region is explicitly initialized beforehand.

A nonzero resolution result skips secondary-helper initialization and the final operation. The function then cleans up the primary helper and returns one.

A zero resolution result permits the next stage. The resolved-value slot is later consumed without a separate check. The auxiliary region is not directly read again by this function.

The fresh resource-field read matters: classification and resolution are not guaranteed to receive the same field value if intervening dependencies modify the object or shared state.

### 5. Initialize the secondary helper and invoke the final operation

After successful resolution, the function calls F-41b37059d890 with:

1. The address of a 12-byte secondary-helper storage region.
2. The classification value, which is necessarily 2, 3, or 4 on this path.

No explicit initialization of that region precedes the call. No return status from this dependency is checked.

The function then calls F-e6be4b0a25d8 with these six arguments, in order:

1. The secondary-helper address.
2. A fresh read of the object’s resource field.
3. The 32-bit resolved-value slot.
4. A literal 32-bit zero.
5. The first caller-supplied forwarded value.
6. The second caller-supplied forwarded value.

The final operation can therefore receive a resource-field value different from those supplied during classification and resolution. This function does not enforce equality across those reads.

The resolved-value slot is read after secondary-helper initialization. Although its intended role appears to be the resolver’s output, preservation across intervening calls is not independently established.

### 6. Cleanup and return

Once the final operation returns, the secondary helper is cleaned up through F-33f41a428c53.

The primary helper is then cleaned up through F-28346ad464bf.

If the final operation returned zero, the function returns zero after both cleanup calls complete. Otherwise it returns one.

On unsupported-classification and failed-resolution paths, only primary-helper cleanup occurs. On initial-method failure, neither helper cleanup occurs.

Cleanup results are not checked. This establishes normal control flow only; it does not establish exception safety or recovery from a dependency that faults or fails to return.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Each assumes that invoked dependencies return normally and all accessed storage is valid.

1. **Initial method rejects the request.**  
   Given a nonzero initial-method result, the function returns one. None of the named dependencies is called, and neither selector global is read.

2. **Unsupported classification.**  
   Given a successful initial method and classification 5, both selector globals are read. Resolution, secondary initialization, and the final operation are skipped. Primary cleanup occurs, followed by return one.

3. **Classification 2 succeeds.**  
   Given classification 2, resolution receives the first selector value; the second selector global is not read by this function. If resolution and the final operation return zero, secondary cleanup precedes primary cleanup, and the result is zero.

4. **Classification 3 or 4 succeeds.**  
   Both selector globals are read in order. Resolution receives the second selector value. Secondary initialization receives the actual classification, not a common normalized classification. Successful resolution and final operation produce zero after cleanup.

5. **Resolution fails.**  
   Given an accepted classification and nonzero resolution result, no secondary helper is initialized. Primary cleanup occurs, and the result is one.

6. **Final operation fails.**  
   Given successful resolution and a nonzero final-operation result, both helpers are cleaned up in secondary-then-primary order. The result is one; the original error value is not returned.

7. **Resource changes between stages.**  
   If classification changes the object’s resource field, resolution receives the updated value. If resolution or secondary initialization changes it again, the final operation receives the value present at its own field read. Reusing an earlier cached resource value would not match this behavior.

8. **Forwarded values contain arbitrary 32-bit patterns.**  
   If execution reaches the final operation, both forwarded values retain their supplied bit patterns and argument order. Their validity for that dependency is a separate requirement.
