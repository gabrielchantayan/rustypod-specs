# F-6f3eae7c0190

## Purpose

F-6f3eae7c0190 selects a record associated with an input context and returns its address, or zero.

Selection depends on an unsigned 32-bit key obtained from a resolved object:

- A zero key delegates selection to F-90be72a33f67.
- A nonzero key requires an additional eligibility check, then searches either a cached pointer array or a linked chain.
- Missing initial state, a rejected prerequisite, or an unsuccessful search produces zero.

The function can construct and publish cached storage. A missing cache can lead to linked-chain fallback; a completed indexed search that finds no match cannot.

**Established static evidence:** the supplied representation establishes the accesses, calls, branches, explicit write, and search operations described below.

**Inferred intent:** the cached array appears intended as an ordered lookup index. Two dependencies surrounding cache access appear to form a synchronization pair. Neither interpretation establishes ordering, exclusion, ownership, or lifetime guarantees.

### Indexed lookup

The function reads the signed 32-bit count from the final search address. The initial inclusive bounds are zero and count minus one.

While the upper bound exceeds the lower bound by more than one, it examines the midpoint formed by signed addition of the bounds followed by division by two.

For each midpoint:

- The record address is read from the corresponding four-byte slot.
- The record’s unsigned 32-bit key at offset `0x0C` is compared for equality.
- Equality selects the midpoint slot’s record address and ends the search.
- Otherwise, the slot and key are read again for an unsigned ordering comparison.
- A requested key smaller than the observed record key moves the upper bound to the midpoint.
- Otherwise, the lower bound moves to the midpoint.

On midpoint equality, the slot is reread to obtain the returned address. Under mutation, the address selected for return need not equal the address whose key satisfied equality. On a mismatch, equality and ordering likewise need not observe the same record or key.

Once the interval is sufficiently small, the remaining entries are scanned in increasing index order, including both bounds. Each candidate address is loaded, its key is checked, and the first matching candidate is selected. An exhausted interval produces zero.
