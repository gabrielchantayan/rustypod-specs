# F-2b9d47918562

## Purpose

F-2b9d47918562 conditionally updates a primary unsigned 32-bit value and related fields in a caller-supplied object.

A selector byte chooses between two paths:

- **Zero:** obtain a candidate through an associated handle; accept it only when it exceeds the currently observed primary value.
- **Nonzero:** repeatedly apply an advancement mode while the primary value is at or below a fixed threshold. Return unsuccessfully if an entered iteration selects mode 0 or an unsupported mode.

The constants and packed representations suggest calendar recurrence processing. That is inferred intent, not an established definition of units, epoch, timezone, or calendar rules.

This contract describes static evidence only. Opaque dependencies are not assumed to preserve globals, preserve object fields, return normally, or follow an ownership convention.

## Interface

### Argument and result

The sole explicit argument is represented as a 32-bit object address. No null, alignment, accessibility, or object-validity checks are visible.

The return value is a 32-bit word:

| Result | Established meaning |
|---|---|
| 0 | The handle-derived candidate did not exceed the observed primary value, or an entered advancement iteration selected mode 0 or an unsupported mode. |
| 1 | The accepted handle update completed, or the advancement path observed a primary value greater than its fixed threshold. |

Returning 1 does not require a direct object write: the advancement path may find the primary value already above the threshold. Returning 0 does not establish absence of dependency effects or undo earlier completed iterations.

Normal return and termination are not guaranteed.

## Behavior

### Common preparation and cache observations

Common preparation precedes the selector read on every invocation.

The cache-pointer observations are distinct:

1. Read the cache-pointer global and retain that address as the **captured cache pointer**.
2. Evaluate the cache-pointer global again and dereference the address from this second observation for the zero test.
3. If the tested value is zero, call F-938c950e5046 and write its returned 32-bit value through the captured cache pointer.
4. Read the cache value through the captured cache pointer for the subsequent F-5710a8628cba call.

The zero test is therefore not necessarily a test of the storage later written or read. Their identity requires stability of the pointer global between its two observations. No call is explicitly placed between those observations, but the source still expresses separate reads.

If initialization returns zero, zero is written and subsequently passed onward; there is no retry or nonzero validation within this invocation. A later invocation can initialize again if its own zero test succeeds.

F-5710a8628cba receives the captured-pointer cache value and two global arguments. An unidentified dependency then receives a local 12-byte destination, the preceding result, and the value 10. Only afterward is the selector at `0x2c` read.

The unidentified dependency’s identity, output format, meaning of 10, and complete memory requirements are **documented_only**. Its call does not establish a particular formatting or conversion API.

### Advancement loop

At each loop entry, read the unsigned primary value at `0x08`.

If it exceeds the fixed threshold, return 1. Otherwise, retain that observed value for the iteration and call F-dee541b2a059 with it and the scratch destination.

Read the mode at `0x18` only after that call. Changes made by the dependency can therefore affect mode selection.

Every normally completed iteration writes its calculated word first to `0x0c`, then to `0x08`. The next comparison rereads `0x08`; it does not simply reuse the calculated word.

- **Mode 0:** return 0 without the current iteration’s final writes. Scratch production has already occurred.
- **Mode 1:** add 86,400 to the retained primary value.
- **Mode 4:** add 604,800 to the retained primary value.

#### Mode 2

| Classification | Adjustment |
|---:|---:|
| Below 5 | Add 86,400 |
| 5 | Add 259,200 |
| 6 | Add 172,800 |
| Above 6 | Leave the retained primary value unchanged |

The unchanged case still performs both final writes. Stable relevant state can therefore cause indefinite repetition.

#### Mode 3

For classification below 5, interpret P’s low 16 bits as a signed 16-bit value. Multiply that value by six minus the classification, then by 128, and add the adjustment to the retained primary value.

The factor ranges from 2 through 6. The adjustment lies between −25,165,824 and 25,165,056, so these products fit signed 32-bit arithmetic.

#### Unsupported modes and termination

Primary and threshold comparisons, classification comparisons, and the mode-5 limit comparison are unsigned. Fixed-interval additions wrap modulo \(2^{32}\). Adding a representable signed adjustment to the unsigned primary value likewise produces an unsigned 32-bit result.

There is no iteration bound or progress check. Wraparound, negative or zero adjustments, unchanged mode-2 results, and dependency mutations can prevent termination.

## Acceptance examples

These are conditional static consequences, not executed tests. Assume accessible memory, normally returning dependencies, and no relevant mutations except those stated. Signed multiplication examples require representable intermediates.

1. **Different cache-pointer observations.** Suppose the captured pointer addresses storage A, while the second pointer observation addresses storage B. If B contains zero, initialization writes its result into A, and the later cache-value argument is read from A. If B is nonzero, initialization is skipped even when A contains zero.

2. **Equal candidate rejected.** Selector zero, primary 500, and candidate 500 produce return 0 without direct object writes. Common preparation and candidate production still occur.

3. **Candidate accepted.** Primary 500, candidate 501, later conversion result 900, and extracted byte 31 produce `0x08 = 501`, then `0x0c = 900`, then `0x10 = 31`, followed by return 1.

4. **Opaque increment boundary.** An original second-word bit pattern of `0x7fffffff` does not alone establish signed overflow or a wrapping result. The signed destination temporary resolves neither question.

5. **Already above threshold.** Threshold 100 and primary 101 produce return 1 without scratch production or mode inspection. P and both Q observations still occur.

6. **Equality advances.** Threshold 100, primary 100, and mode 1 produce writes of 86,500 to `0x0c`, then `0x08`. The next comparison returns 1.

7. **Classification behavior.** Starting from 100, mode 2 produces 259,300 for classification 5 and 172,900 for classification 6. Stable classification 7 can repeat indefinitely without increasing the primary value.

8. **Signed narrowing.** P with low halfword `0xffff` and mode-3 classification 4 yields adjustment −256. Starting from 1,000 produces 744.

9. **Packed rollover.** In mode 5, byte `+4` equal to 12 and halfword `+6` equal to 65,535 produce halfword 0, then byte 1, before the helper call.

10. **Second helper result matters.** With limit 31, first helper result 28, and second result 29, scratch byte `+3` becomes 29. With limit 300 and both results 280, it becomes 24: comparison is full-width, selection is byte-width.

11. **Distinct Q observations.** Assume P is 1, Q-first is 365, and the second Q observation denotes 400 under arithmetic that yields retained Q-derived 399. From primary and threshold 100, mode 6 produces 51,172 for a zero predicate or 46,820 for a nonzero predicate.

12. **Unresolved subtraction boundary.** A second Q observation with bit pattern `0x80000000` does not establish signed subtraction overflow, unsigned wrapping, or the retained result without the missing source-type evidence.

13. **Unsupported mode.** At primary/threshold equality with mode 7, scratch production occurs, then return 0 follows without final iteration writes.
