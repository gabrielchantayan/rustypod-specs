# F-85ae53ac577b

## Purpose

F-85ae53ac577b updates a caller-supplied object, prepares temporary three-component records, and submits one or two groups of four records to dependencies.

Its established behavior includes:

- Initializing temporary transformation storage through global-value reads and dependency calls.
- Making three independently conditional transformation calls.
- Selecting and explicitly writing two object fields.
- Deriving two triples and combining them with a base triple through eight ordered dependency calls.
- Submitting the first group unconditionally on normal execution.
- Conditionally preparing and submitting a second, adjusted group.

**Inferred intent:** the records may represent transformed corners, and the conditional calculations may select an alternate representation. Geometry, units, arithmetic scaling, and resource semantics are not established.

Dependency behavior is not inferred from naming or apparent use.

## Interface

### Invocation and result

The routine takes one 32-bit argument used as the base address of a mutable object. It has no explicit return value.

There are no visible checks for a null object, invalid nested pointers, insufficient storage, or dependency failure. Normal completion requires all executed accesses and calls to be valid.

### Temporary layout and global inputs

Each submitted group has four consecutive record slots, each containing three 32-bit components: 12 bytes per record and 48 bytes per group.

The first group’s records are designated **A**, **B**, **C**, and **D** in increasing address order. Components are numbered 1–3. These are descriptive labels.

Four distinct global locations supply values:

- **Seed global:** supplies the initial transformation-storage word.
- **Transformation-initialization global:** supplies the second argument to the first F-c5a3e2a1a1d4 call.
- **Group-initialization global:** supplies the second argument to each group-initialization call.
- **Equality-reference global:** supplies the reference used in one adjustment branch.

These are global-value loads, not established static-data addresses. Their contents and stability are unknown. In particular, the group-initialization global is loaded separately for the two groups.

## Behavior

### 1. Initialize transformation storage

Before any nested object-field reads, the routine:

1. Reads the seed global and stores its 32-bit value at the transformation-storage base.
2. Reads the transformation-initialization global and passes that value as the second argument to F-c5a3e2a1a1d4. The first argument is the address four bytes beyond the transformation base; the remaining arguments are `4` and `16`.
3. Calls F-16920fdc01be with the transformation-storage base.

The second argument to F-c5a3e2a1a1d4 is not the address of the global itself. Whether its loaded value denotes an address, and what memory the dependency accesses, remain unknown.

### 2. Perform three ordered optional transformations

Each decision uses F-1d1b465375c3, whose nonzero 32-bit return enables the associated transformation. The routine does not directly test the nested value for nonzero at these decision points.

Two adjacent 32-bit temporary words are reused. Their physical relationship differs between the first comparison and the next two:

| Decision | Lower-address word | Immediately following word | Comparison arguments, in order |
|---|---|---|---|
| Nested value through `0x44` | Zero | Nested value | Value-word address, zero-word address |
| Nested value through `0x40` | Nested value | Zero | Value-word address, zero-word address |
| Nested value through `0x48` | Nested value | Zero | Value-word address, zero-word address |

For the first decision, the lower word is set to zero before the upper word receives the nested value. For each subsequent decision, the upper word is set to zero before the lower word receives the nested value.

The optional calls occur in this order:

1. F-28e770592bd9 for `0x44`.
2. F-9e2f629ba3ee for `0x40`.
3. F-30320663fc21 for `0x48`.

Each enabled call receives the transformation-storage base and a freshly reread nested value. Neither the nested address nor its word is preserved as a guaranteed snapshot across the comparison call.

The two comparison-pointer arrangements are not interchangeable. An unknown dependency may read wider than one word or mutate address-reachable storage.

### 3. Select and write two object fields

If the current word at `0xd4` is zero, directional calculation is skipped.

Otherwise:

- F-0f4b5d864dac receives a temporary-triple destination and three words read at transformation-base offsets `36`, `40`, and `44`.
- A separate temporary word is set to `0x00a00000`.
- F-0f4b5d864dac receives another temporary-triple destination and these component arguments:
  - The nested value through `0x34`.
  - Zero.
  - `0x00a00000` minus the nested value through `0x3c`.
- Another temporary word is set to zero.
- Three ordered F-a04224da5d98 calls receive, respectively, each first-triple component’s address and the corresponding second-triple component’s value.
- The three returned 32-bit values are added into a 32-bit result word.
- F-a09269e75221 receives the result-word address followed by the zero-word address.

The zero word immediately precedes the result word. The word previously set to `0x00a00000` immediately follows the result word. Intervening dependencies are not assumed to preserve these words.

A nonzero F-a09269e75221 result selects the alternate sources; otherwise, including when the directional calculation was skipped, the default sources apply.

| Selection | Source for `0x60` | Source for `0xa0` |
|---|---|---|
| Alternate | Reread `0xd4` | `0xd8` |
| Default | `0x54` | `0x94` |

The first source is read and written to `0x60` before the second source is read. The second source value is then written to `0xa0`.

The directional comparison’s meaning, including whether it tests sign or ordering, is not established.

### 4. Derive two triples

Three iterations execute in increasing index order: `0`, `1`, and `2`.

Within each iteration:

- A temporary word is set to `0x00460000`.
- F-a04224da5d98 receives the address at transformation-base offset `4 + 16 × index` and the value `0x00230000`. Its result becomes the corresponding component of the first derived triple.
- The same temporary word is set to `0x00460000` again.
- F-a04224da5d98 receives the address at transformation-base offset `8 + 16 × index` and the value `0x00230000`. Its result becomes the corresponding component of the second derived triple.

Thus, the address offsets are `4`, `20`, `36` for the first triple and `8`, `24`, `40` for the second.

The index is unsigned and 32-bit. Its update increments it and clears bit 16. That mask does not alter the reachable sequence `0, 1, 2, 3`; the loop terminates at `3`.

The temporary word repeatedly set to `0x00460000` immediately precedes the first group’s base. Its relationship to dependency semantics is unknown.

### 6. Gate and initialize the second group

Only after both preceding calls return does the routine reread `0x94`.

If that word is zero, the routine returns without constructing or submitting the second group. This gate is neither a saved earlier value nor the selected field at `0xa0`.

If nonzero, the routine:

1. Rereads the group-initialization global.
2. Calls F-c5a3e2a1a1d4 with the second group’s base, that newly loaded value, `12`, and `4`.
3. Assigns the second group’s first components from A1, B1, C1, and D1, in that order.
4. Reads the nested control value through `0x40`.
5. Sets the temporary word immediately preceding the first group’s base to zero.

The second initialization need not receive the same global value as the first.

**Control value zero**

- Call F-0ad82498f473 with A2’s address and that temporary-word address; store its result as the first second-group record’s component 2.

- Make a separate F-0ad82498f473 call with B2’s address; store its result as the second record’s component 2.

- Set the word eight bytes before the second group’s base to `0x00230000`.

**Nonzero control value equal to the equality reference**

It stores a loaded value into the address-exposed temporary word immediately before the second group’s base, then compares the saved control value against the equality-reference global’s value. The supplied representation references the global again for that comparison; global immutability or a single shared read must not be assumed.

The source uses signed right shift, not division by two.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Comparison layout:** The first F-1d1b465375c3 call receives the upper temporary address first and lower address second. The next two receive lower first and upper second. All use the same adjacent locations.

2. **Default selection:** If `0xd4` is zero at its gate read, directional calls are skipped. The routine writes the current `0x54` value to `0x60`, then reads `0x94` for the write to `0xa0`.

3. **Alternate selection:** If the directional branch executes and F-a09269e75221 returns nonzero, `0xd4` is reread for `0x60`; `0xd8` is read afterward for `0xa0`.

4. **Late gate:** If `0x94` becomes zero before its post-submission read, no second-group initialization, equality-reference load, or second submission occurs.

5. **Independent initialization loads:** If the group-initialization global differs between its two call sites, each F-c5a3e2a1a1d4 call receives the value loaded at its own site.

6. **Zero control:** With the late gate nonzero and control zero, the equality-reference global is not read. A2 and B2 undergo separate F-0ad82498f473 calls.

7. **Permutation:** If C3, D3, A3, and B3 remain respectively `30`, `40`, `10`, and `20` until their direct reads, the second group’s third components are assigned `30`, `40`, `10`, and `20`.

8. **Negative odd adjustment:** If the general branch returns adjustment `−3`, and signed right shift is arithmetic on the target, the half-adjustment is `−2`, not `−1`.
