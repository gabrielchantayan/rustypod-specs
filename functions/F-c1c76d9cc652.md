## Behavior

### Established sequence

The following ordering is visible:

1. The fallback selected value is established as the 32-bit value `0x00007FFF`, numerically 32767.
2. The function writes the numeric value 1 to the 16-bit field at offset `0x68` in the supplied record.
3. It reads the association field at offset `0x90` and compares it with zero.
4. If that read is zero, the selected value remains 32767.
5. If that read is nonzero, the visible expression reads the association field again and reads a 32-bit value at offset `0x30` relative to the address obtained by that second read. This value replaces the fallback.
6. The function invokes F-dep-01 with no explicit arguments and retains its 32-bit result.
7. It invokes F-dep-02 through the indirect target, passing the retained result, the original entry argument, and the selected value.
8. After normal completion of that invocation, the function returns without an explicit result.

The field write precedes the association lookup. The selected value is obtained before F-dep-01 is invoked. F-dep-01 completes before F-dep-02 is invoked.

### Association-field read behavior

The supplied representation contains one association-field read on the zero branch and two on the nonzero branch: one for the condition and another to obtain the address used for the associated-record read.

It does not establish an atomic snapshot spanning those accesses. If the field can change between reads, the address used for the associated-record access need not equal the nonzero value observed by the condition.

There is no second zero check before the associated-record access. A nonzero first read followed by a zero second read therefore does not select the fallback. It instead leaves the function attempting an access at offset `0x30` from the second address value, subject to the actual machine’s address semantics.

These are properties of the supplied representation, not proof of a particular volatile-access or concurrency contract.
