# F-404485218953

## Purpose

F-404485218953 derives a numeric mode from one dependency result, invokes six further dependencies in a fixed order, writes a fixed 32-bit value through a globally supplied base address, and returns 32-bit zero on normal completion.

The established contract is an ordered sequence of calls and a final memory update. The supplied static representation does not establish application-level meanings for the selected modes, the input values, or the stored constant. Initialization, compatibility selection, and resource management are possible interpretations, not established behavior.

## Behavior

### Initial query and mode selection

The first dependency call is F-a6e77b5dfc20, with no explicit arguments. Its returned value is used as an unsigned 32-bit quantity.

Mode selection uses two fields of that single captured result:

| Field | Bit positions | Numeric range |
|---|---|---|
| Upper field | 31 through 16 | 0–65,535 |
| Lower field | 15 through 0 | 0–65,535 |

The selected mode is **3** if, and only if:

- The upper field equals decimal 16, hexadecimal 0x0010; and
- The lower field is strictly greater than decimal 5.

Otherwise, the selected mode is **0**.

Thus, the complete set of query values selecting mode 3 is the inclusive unsigned interval **0x00100006–0x0010FFFF**. Every other 32-bit result selects mode 0.

The upper-field condition is exact equality, not “at least 16.” The lower-field comparison is unsigned; values with bit 15 set are not treated as negative.

Only one query is visible. Subsequent dependency activity does not trigger another query or a new mode calculation.

The initial result is inspected for this predicate. There is no separately established error check on that result. Because the query’s error contract is unknown, a value that its own contract might designate as a failure would still undergo the same documented predicate on the visible path.

### Final destination selection and write

After F-17d6434f9fa3 returns, the function reads the globally held base used to form the final destination.

The direct memory update has this layout:

| Property | Established value |
|---|---|
| Destination | Base plus 512 bytes |
| Displacement | 0x200 bytes |
| Write width | 32 bits, or four bytes |
| Stored value | Decimal 1,806; hexadecimal 0x0000070E |

The displacement is measured in bytes. It is not an index of 512 four-byte elements.

The base is read after all dependency calls, not captured at entry. Consequently, an earlier dependency’s change to that global base can affect the final destination. The contract does not assume that any dependency preserves the base.

No read of the previous destination value is visible. The write replaces the four-byte value rather than incrementing it or modifying selected bits.

The supplied representation establishes the 32-bit stored value, but not the target byte order, access atomicity, or address-overflow semantics. For a valid base whose displaced destination is writable, the observable destination is the base plus the stated byte offset. Behavior for an invalid or overflowing address calculation is **documented_only**.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Except where interruption is the subject of an example, assume that every dependency returns normally and that the final memory access succeeds.

### Lower-field threshold

For a query result of **0x00100005**, the upper field matches but the lower field does not exceed 5. F-a49a3de492d0, F-f5edfdcdd9e4, and F-c2147d93773d each receive mode 0.

For **0x00100006**, both conditions hold. Those three dependencies each receive mode 3.

Both cases retain the same remaining call sequence, final stored value of 0x0000070E, and zero return.

### Exact upper-field requirement

For **0x00110006**, mode 0 is selected despite the lower field exceeding 5. An upper field of 17 does not qualify.

For **0x000F0006**, mode 0 is also selected. The condition is neither a minimum nor a proximity test.

### Unsigned lower-field interpretation

For **0x0010FFFF**, mode 3 is selected. The lower field represents 65,535, not negative one.

For **0xFFFF0006**, mode 0 is selected because the upper field is not 0x0010.

### Input preservation at call boundaries

Given two 32-bit input patterns accepted by their receiving dependencies:

- F-a49a3de492d0 receives the first pattern unchanged as its second argument.
- The external dependency receives the second pattern unchanged as its sole explicit argument.

This does not imply that either dependency accepts every possible pattern or leaves referenced memory unchanged.

### Late base selection
