# F-1bcb8114d17f

## Purpose

F-1bcb8114d17f reads context fields selected by a one-byte flag, calls F-5ef10d079522 with context-derived values and an output address advanced by two bytes, then writes a derived 16-bit value at the original output address. It returns the dependency’s 32-bit result unchanged.

The clear-bit branch performs two separate lookups of a secondary-context pointer. Its two context-derived arguments therefore are not established to come from the same secondary object unless those lookups yield the same address.

The application-level meaning of the contexts, output region, and return value is unknown. Treating the first two output bytes as a header is a possible interpretation, not an established format contract.

## Interface

The represented interface has four arguments and a 32-bit return value. Addresses and context words use a 32-bit representation.

| Argument | Established role |

| Third | A 32-bit value with no visible use in the function body. |

The return value preserves the dependency’s 32-bit result. No success, failure, Boolean, or other semantic interpretation is established.

## Behavior

### Selector and represented context-read order

The wrapper first reads the byte at primary offset 29 and tests bit 0. Bits 1 through 7 do not participate in this branch decision.

The following ordering describes the logical reads represented by the supplied body. It is distinct from a guarantee about generated physical loads, volatility, atomicity, or synchronization.

#### Clear selector bit

When bit 0 is clear, the represented sequence is:

1. Read the 32-bit secondary-context pointer at primary offset 32.
2. Through that first pointer value, read the 32-bit word at secondary offset 40. Save this value for the dependency’s second argument.
3. Read the secondary-context pointer at primary offset 32 again.
4. Through that second pointer value, read the 32-bit word at secondary offset 0.
5. Add 192 to the word obtained by the final read to form the dependency’s first argument.

The first pointer lookup supplies the address for the offset-40 read. The second pointer lookup supplies the address for the offset-0 read. The representation does not cache a single secondary pointer for both accesses.

If the slot remains unchanged, both field reads use the same secondary-context address. If the two represented lookups yield different addresses, the dependency’s second argument comes from offset 40 of the first object, while its first argument comes from offset 0 of the second object plus 192.

This distinction does not assert that concurrent modification is valid, defined, synchronized, or guaranteed to be observed. It records the represented accesses without replacing them with a stronger single-context assumption.

#### Set selector bit

When bit 0 is set, the represented sequence is:

1. Read the 32-bit word at primary offset 40. Save this value for the dependency’s second argument.
2. Read the 32-bit word at primary offset 0.
3. Add 204 to the latter value to form the dependency’s first argument.

This branch does not visibly read primary offset 32 or dereference a secondary-context pointer.

In both branches, the value used for the dependency’s second argument is read before the value used to derive its first argument. Their eventual argument positions do not reverse that represented read order.

### Dependency invocation

After the branch-specific reads and arithmetic, the wrapper calls F-5ef10d079522 once. Its five arguments, in interface position order, are:

1. The branch-selected offset-0 word increased by 192 or 204.
2. The previously read offset-40 word.

Argument position order is not a claim about evaluation order for otherwise independent call-argument expressions. In particular, the evidence does not establish the global read’s exact ordering relative to every other access.

The second argument is the context word’s value, not the address of that word.

The third argument is an interior address relative to the caller’s output address. The wrapper does not visibly inspect any contents produced through it.

No explicit read of a result from that storage appears after the call. The address must not be treated as durable storage that remains valid after this invocation.

The fifth argument is global-derived. Its exact width, type, meaning, mutability, and ownership are not established. It is not specified as a constant.

### Final 16-bit write

After F-5ef10d079522 returns normally, the wrapper stores a 16-bit value at the original output address. No test of the dependency’s result intervenes.

At the represented 32-bit machine-bit level, the destination receives input bits 1 through 16 from the fourth argument:

- Input bit 0 is discarded.
- Input bit 1 becomes destination bit 0.
- Input bit 16 becomes destination bit 15.
- Input bits 17 through 31 are discarded.

For the unsigned interpretation \(U\) of the fourth argument’s 32-bit pattern, the resulting 16-bit pattern is:

\[
H = \left\lfloor U / 2 \right\rfloor \bmod 65536.
\]

This retains 16 bits, not 15. A fourth argument with only bit 16 set produces the stored pattern 0x8000.

The supplied expression performs a signed left shift by 15 before conversion to an unsigned 32-bit value and a right shift by 16. Consequently, the machine-bit description is not a promise of portable signed-arithmetic behavior for all inputs. Negative operands and values whose signed left shift is not representable remain subject to the execution model’s rules.

The final store establishes a 16-bit numeric pattern. Its byte ordering in memory is not established by the supplied material.
