# F-926b44f5ac05

## Purpose

F-926b44f5ac05 attempts to resize a table-like allocation, conditionally invokes an external operation over the portion beyond the current table extent, updates an extent field, and reports a success or failure classification through a reporting dependency.

The established behavior is a sequence of dependency calls and record mutations. The supplied evidence does **not** establish that the first dependency is a conventional reallocator, that the external operation clears memory, or that the reporting dependency is observational only. Those interpretations must not be treated as guarantees.

The function returns no value. Its caller-visible results are changes to the supplied record, effects performed by dependencies, and a final reporting call if execution reaches that point.

## Interface

### Inputs

The function accepts four arguments:

1. **Record address.** An address of a writable record containing at least six 32-bit slots.
2. **Auxiliary value A.** An opaque 32-bit value forwarded to the first dependency.
3. **Auxiliary value B.** An opaque 32-bit value forwarded twice to the first dependency.
4. **Auxiliary value C.** An opaque 32-bit value forwarded twice to the first dependency.

The supplied representation uses integer-valued addresses. It establishes four-byte arithmetic for table elements but does not establish a portable host-language pointer model.

### Record layout

Offsets are relative to the record address.

| Byte offset | Width | Established role |
|---|---:|---|
| 0 | 32 bits | Existing allocation value on entry; overwritten with the first dependency’s result |
| 4 | 32 bits | Current extent; used in size and address calculations; conditionally overwritten with the computed target extent |
| 8 | 32 bits | No direct access shown |
| 12 | 32 bits | No direct access shown |
| 16 | 32 bits | Multiplier used to compute the target extent |
| 20 | 32 bits | Value forwarded to the reporting dependency |

“Allocation value,” “extent,” and “multiplier” describe observed uses, not independently verified type declarations or invariants. In particular, the evidence does not prove that the extent is nonnegative or that the multiplier is greater than one.

### Output and completion

There is no explicit return value and no direct error code.

On ordinary completion, the function has invoked the reporting dependency once. Whether the record retains the state passed to that dependency is unknown because the dependency receives the record address and may modify it.

### Preconditions and limits

For defined, useful execution, the record must support the accesses described below. Any memory requirements imposed by the dependencies are additional preconditions whose details are unavailable.

The function performs no explicit validation of:

- A null or invalid record address.
- Negative, zero, or excessive extents.
- Negative, zero, or excessive multipliers.
- Arithmetic overflow.
- Whether the requested target is at least as large as the current extent.
- Whether an allocation result actually designates sufficient accessible storage.

Violations are not converted into a documented local error result.

## Behavior

### 1. Establish the target extent

Before calling any dependency, the function reads the extent at offset 4 and the multiplier at offset 16, and computes their product as the target extent.

This target is retained for later use. Subsequent changes to the record do not cause that target to be recomputed.

The evidence does not establish a required ordering between the two reads within the multiplication. It does establish that the target calculation precedes the first dependency call.

### 2. Request a replacement allocation value

The function calls F-dbea69bb52a6 with seven arguments, in this positional order:

| Position | Value |
|---|---|
| 1 | Allocation value read from record offset 0 |
| 2 | Target extent multiplied by four |
| 3 | Auxiliary value B |
| 4 | Auxiliary value C |
| 5 | Auxiliary value A |
| 6 | Auxiliary value B again |
| 7 | Auxiliary value C again |

The second argument represents a byte-sized quantity in the observed arithmetic. Each element contributes four bytes.

No ordering among argument evaluations beyond their preparation before the call is established by the supplied representation. Their positional mapping is established.

After F-dbea69bb52a6 returns normally, its 32-bit result is written to record offset 0 **unconditionally**. This write happens before the result is tested.

Consequently, a zero result replaces the prior allocation value with zero. The function does not preserve the old value in the record for recovery.

### 3. Handle a zero allocation result

If the returned result is zero:

- The external range operation is skipped.
- This function does not write the computed target into the extent field.
- The classification selected for reporting is failure.
- Execution proceeds to the reporting call.

This path does not prove that the extent remains equal to its entry value: F-dbea69bb52a6 may have changed it indirectly. The narrower established fact is that this function does not perform its conditional extent assignment on this path.

The first dependency’s behavior toward the previous allocation is unknown. A zero result therefore establishes neither preservation nor release of that allocation.

### 4. Handle a nonzero allocation result

If the returned result is nonzero, the function invokes an external dependency with two arguments:

- **Range start:** the returned allocation value plus four times the extent read from record offset 4.
- **Range quantity:** four times the difference between the previously computed target extent and an extent read from record offset 4.

These calculations use the allocation result returned by F-dbea69bb52a6, not a fresh read of record offset 0.

The extent operands are read after F-dbea69bb52a6 returns. They are not guaranteed to equal the extent used to establish the target. The supplied expressions also do not establish that the extent is read only once, or that the two argument calculations observe one common snapshot.

The external dependency’s behavior is unresolved. The two arguments resemble a start address and a byte count, but neither the write pattern nor even a memory-writing contract is supplied. In particular, zero-initialization is not established.

No result from this dependency is examined.

After the external dependency returns normally, the function writes the retained target extent to record offset 4. This assignment occurs regardless of any unexamined result from the external operation.

The function then reads record offset 0 again:

- A nonzero value selects success.
- A zero value selects failure.

This second check is distinct from the initial check of the allocation result. A nonzero allocation result can therefore lead to failure classification if the allocation field has become zero before the second check.

### 5. Report the outcome

On either normally completing branch, the function calls F-bdd116c3204b with seven arguments:

1. The record address.
2. The integer value 2.
3. A fixed relocation-oriented format string.
4. The value read from record offset 20.
5. The allocation value read from record offset 0.
6. The extent read from record offset 4.
7. The selected success or failure text.

The format describes a table relocation, including a table label, a hexadecimal allocation value, a decimal extent, and the selected classification. The exact output destination and formatting behavior belong to F-bdd116c3204b.

The classification is selected before the reporting call. It is not independently recomputed from the allocation argument passed to that call. Argument-read ordering is not sufficiently specified to promise a single atomic snapshot of the record.

The function returns after the reporting dependency returns normally.

## Side effects

### Direct record writes

This function directly performs at most two record writes:

1. It always writes the result of F-dbea69bb52a6 to offset 0 after that dependency returns.
2. It writes the target extent to offset 4 only on the nonzero-result path, after the external dependency returns.

There is no rollback. In particular:

- A zero result is committed to offset 0 before failure reporting.
- The target extent is committed before the final allocation-field check.
- Failure classification after that assignment does not restore the prior extent.

No direct write to offsets 8, 12, 16, or 20 is shown.

### Memory and ownership

The allocation value is passed to F-dbea69bb52a6, but the evidence does not define ownership transfer, allocation lifetime, preservation of existing contents, or failure semantics.

The function does not explicitly release the old allocation itself. That does not imply the old allocation survives: F-dbea69bb52a6 may release, replace, retain, or otherwise affect it.

The external dependency receives a calculated location within or relative to the returned allocation. Its accessible-region requirements and effects are unknown.

Because dependencies may modify shared state or aliased memory, the direct writes listed above are not a complete inventory of possible externally observable changes.

### Errors and interruption

There is no explicit handling for dependency errors other than the zero-result branch following F-dbea69bb52a6.

If a dependency does not return normally, later writes and reporting are not guaranteed to occur. Invalid accesses and invalid arithmetic have no local recovery path in the supplied evidence.

## Acceptance examples

These are conditional behavioral examples derived from static evidence. They are not executed tests. Unless stated otherwise, arithmetic is representable and dependencies return normally without modifying the record indirectly.

- D-1 is not called.
