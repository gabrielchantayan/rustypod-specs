# F-9a0ed9935fa9

## Purpose

F-9a0ed9935fa9 conditionally forwards a request after a preliminary dependency call and inspection of a caller-supplied record.

The established decision structure is:

1. Capture a 32-bit companion value.
2. Invoke F-eef02e922a52 in a preliminary form.
3. If its 32-bit result is zero, inspect a 16-bit discriminator through a stack-resident record-address slot.
4. For a recognized discriminator, obtain a 32-bit value.
5. If that value is nonzero, invoke F-eef02e922a52 with seven explicit arguments.
6. Return a 64-bit concatenation of a selected companion value and the selected dependency result.

Only the companion value is visibly captured before the preliminary call. The record address is referenced afterward through its stack slot. On one branch, an intervening dependency call separates the computation of its input address from the subsequent computation of the forwarding payload address. Consequently, these addresses are not unconditionally relative to one unchanged record.

“Forwarding,” “record,” and “payload” describe structural roles. Their application-level meanings are not established.

## Behavior

### Initial snapshot and preliminary call

Before invoking any dependency, the function captures the 32-bit companion value for possible use as the upper return word.

It then calls F-eef02e922a52 with no explicit arguments shown in this call form. The result is treated as a 32-bit integer.

If that result is nonzero, processing stops:

- No direct record read occurs.
- F-4055be9c3f18 is not invoked.
- No forwarding invocation occurs.
- The lower return word is the preliminary result.
- The upper return word is the companion value captured before the call.

This remains the upper-word rule even if the preliminary dependency changes the companion slot. No explicit arguments shown does not prove that the dependency receives no implicit state or cannot access caller storage.

### Discriminator access after the preliminary call

If the preliminary result is zero, the function reads the record-address slot and accesses the 16-bit discriminator through the address then supplied.

There is no demonstrated use of an entry-time saved record pointer. If the preliminary dependency changes the record-address slot and returns zero, the discriminator access uses the post-call slot value.

An unsupported discriminator ends processing without further local record access or forwarding. The lower result word remains zero, and the upper word remains the initial companion snapshot.

The function does not re-read the discriminator after a subsequent dependency call.

### Inline acquisition

For discriminator 3 or 4, the function:

- Obtains a 32-bit value from offset 4 relative to the record-address slot at that read.
- Then selects an address at offset 8 relative to the record-address slot at payload selection.

No dependency call separates these two operations. Both occur after the preliminary call; neither is established as using an entry-time record-address snapshot.

The function does not invoke F-4055be9c3f18 on this branch. Selecting the payload address does not itself read the payload bytes.

### Dependency-based acquisition

For discriminator 768 or 1024, the function computes an address 10 bytes beyond the record-address slot value available before invoking F-4055be9c3f18. That computed address is the dependency’s explicit argument.

After the dependency returns:

- Its 32-bit return becomes the obtained value.
- The function computes the payload address from the record-address slot available after the call, using a displacement of 14 bytes.

The input address already supplied to F-4055be9c3f18 and the later payload address can therefore have different base pointers. Preservation of the record-address slot across this call is not established.

The discriminator that selected this branch is not validated again. Changing the slot or record contents during F-4055be9c3f18 does not cause a new classification. There is also no local inline read at offset 4 on this branch.

Payload-address selection precedes the test of the obtained value. If the obtained value is zero, the selected address is not forwarded. This does not establish safety for invalid or overflowing address calculations; the applicable machine behavior is unknown.

A zero obtained value suppresses forwarding. The lower result word stays zero from the preliminary call, and the upper word stays the initial companion snapshot.

Any nonzero 32-bit pattern permits forwarding, including patterns that represent negative signed integers. No positivity check, upper bound, length check, or normalization is visible.
