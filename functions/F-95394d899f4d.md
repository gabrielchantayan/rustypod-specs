# F-95394d899f4d

## Purpose

F-95394d899f4d searches an indexed sequence by repeatedly selecting a midpoint and invoking a caller-supplied comparison callback. It returns the computed address of the first examined position whose comparison result is zero. If the search interval becomes empty without such a result, it returns zero.

The search does not inspect element contents directly. It computes candidate addresses from a base value, an index, and a stride, then delegates comparison to the callback.

**Established static behavior:** negative callback results select the lower-index portion of the current interval; positive results select the higher-index portion; zero causes an immediate return.

**Inferred intent:** this is a binary-search-style operation over fixed-stride elements. Correct lookup behavior requires a comparison ordering consistent with the sequence. Sorting, element validity, and callback consistency are not checked.

## Interface

### Inputs

Five inputs are represented:

|---|---|---|
| Search token | One 32-bit opaque word | Passed as the callback’s first argument without explicit interpretation by this function. |
| Base value | 32-bit integer/address value | Starting value for candidate-address calculation. |
| Element count | Signed 32-bit integer | Initial exclusive upper bound on candidate indices. |
| Stride | Signed 32-bit integer | Multiplier used to turn an index into an offset from the base. |
| Comparison callback | Callable address; pointer width not independently established | Invoked with the search token and a computed candidate address; its result is interpreted as a signed 32-bit integer. |

These widths describe the supplied recovered interface. The underlying calling convention, actual declared types, register assignment, and pointer representation are not independently established.

The base is used arithmetically. This function does not establish that it identifies an allocation, an array, or readable storage. The stride is not validated as positive, nonzero, aligned, or equal to an element’s actual size.

### Output

The represented return type is a 32-bit integer used as an address-like result:

- On a zero comparison result, return the address value computed for that callback invocation.
- If no comparison succeeds before the interval becomes empty, return zero.

There is no separate success flag. If a successful candidate address is zero, its return value is indistinguishable from the no-match return value.

### Preconditions and supported interpretation

For an ordinary, memory-safe array search, the caller must provide:

- A callable callback whenever the count is positive.
- A base, stride, count, and backing storage for which every candidate examined by the callback is valid for that callback’s accesses.
- Arithmetic that does not exceed the established range of the intended execution model.
- A comparison relation whose signs consistently identify which side of a candidate can contain a match.

The function itself does not enforce these conditions.

A callback need not return exactly minus one or plus one. Every signed negative value takes the lower-index branch, and every signed positive value takes the higher-index branch.

## Behavior

### Initial interval

A zero count causes an immediate zero return without invoking the callback.

A negative count also causes a zero return without invoking the callback. Although a nonzero count enters the outer search path, the initial lower bound is zero, and zero is not less than a negative upper bound.

For a positive count, the initial candidate interval contains indices from zero through one less than the count. The upper bound is exclusive.

### Candidate selection

For each nonempty interval:

1. The current upper bound is retained for that iteration.
2. A midpoint is obtained by adding the lower bound and the retained upper bound, then dividing the sum by two.
3. A candidate address is calculated as the base plus the product of the stride and midpoint.
4. The callback is invoked with the search token first and the candidate address second.
5. The signed callback result determines the next action.

This is a description of the observable search contract, not a guarantee that all arithmetic is safe for every represented input.

When the midpoint sum is representable and the bounds are nonnegative, the selected midpoint is the lower integer midpoint of the half-open interval. For example, an interval beginning at zero and ending exclusively at five selects index two.

The candidate-address calculation happens before the callback invocation. The computed address is retained for a possible successful return; the source does not show a post-callback recalculation.

### Comparison outcomes

**Negative result**

The midpoint becomes the exclusive upper bound. The lower bound is unchanged. The midpoint itself is excluded from subsequent consideration.

**Zero result**

The function immediately returns the candidate address passed to that callback. No subsequent comparison is made.

**Positive result**

The lower bound becomes one greater than the midpoint. The previous upper bound is restored as the interval’s exclusive upper bound. The midpoint itself is excluded from subsequent consideration.

If the resulting interval is empty, the function returns zero.

### Ordering required for successful search

Under the inferred sorted-sequence use:

- A negative result must indicate that a matching position, if any, lies at a smaller index.
- A positive result must indicate that a matching position, if any, lies at a larger index.
- A zero result identifies an acceptable match at the current position.

The function does not verify that an excluded region contains no match. An inconsistent callback or incompatible sequence ordering can therefore cause a zero return even when some unexamined position would compare equal.

Duplicate matches have no first-match or last-match guarantee. The returned match is whichever matching midpoint is encountered first.

### Arithmetic boundaries

The interval arithmetic is represented using signed 32-bit values. For positive counts with representable midpoint sums, each unsuccessful comparison strictly reduces the interval.

The midpoint calculation adds the two bounds before dividing. It is not an overflow-avoiding midpoint formulation. Even when both bounds are valid nonnegative indices, their sum can exceed the signed 32-bit maximum. Search correctness and termination must not be extrapolated across that boundary without establishing the target’s arithmetic behavior.

The stride multiplication and base addition can also exceed the represented integer range. The supplied evidence does not establish whether overflowing calculations trap, wrap at machine width, or have some other applicable language-level consequence. No modular-address contract is asserted.

Neither zero nor negative strides are rejected:

- With zero stride, every callback receives the same candidate address even though the index interval changes.
- With negative stride, increasing indices produce decreasing address values, provided the calculations remain representable.
- A negative stride does not reverse the sign interpretation. Branches remain defined by index order, not ascending numeric address order.

### Termination

For a positive count, representable arithmetic, and callbacks that return normally, each nonmatching iteration removes the selected midpoint and at least one candidate from the interval. The search therefore terminates after a logarithmic number of comparisons.

No termination guarantee applies if the callback does not return. Behavior after arithmetic outside the established representable domain is documented_only.

## Side effects

### Direct effects

The supplied body contains no explicit writes through the base, candidate addresses, search token, or callback address. It does not explicitly read element bytes, allocate memory, release memory, or access a named global object.

Its direct operations are bound updates, integer/address calculations, callback invocations, and a return.

The visible call ordering is:

1. Compute one candidate address.
2. Invoke the callback for that candidate.
3. Receive and classify the callback result.
4. Return or update the interval.
5. Only then, if needed, compute and invoke the next candidate.

Callbacks are not batched. A later comparison is not initiated before the preceding comparison returns.

### Callback-mediated effects

All element-content inspection is delegated to the callback. The callback may read or modify memory, alter global state, perform I/O, or fail to return. The supplied evidence does not constrain those effects.

The absence of direct writes in this function does not establish that the overall search is read-only.

No ownership transfer, borrowing lifetime, allocation ownership, or release obligation is established for any input or returned value. In particular, this function does not itself release storage, but that does not establish what the callback may release.

If a callback invalidates storage associated with its candidate and then returns zero, this function still returns the previously computed numeric address. It performs no visible lifetime validation.

- A zero result returns 4096 immediately.
- A negative result returns zero after that single comparison.
- A positive result also returns zero after that single comparison.

### Lower-index progression

With base 4096, stride four, and count five:

- The first candidate is index two, address 4104.
- If the first result is negative, the next candidate is index one, address 4100.
- If that result is also negative, the next candidate is index zero, address 4096.
- A further negative result empties the interval and produces zero.

No candidate at index three or four is examined along this path.

### Higher-index progression

With the same base, stride, and count:

- The first candidate is index two, address 4104.
- A positive result selects index four next, address 4112.
- A negative result there selects index three next, address 4108.
- A zero result at that third comparison returns 4108.

This example distinguishes the exclusive upper bound and midpoint rounding from alternative binary-search conventions.

### Non-unit comparison magnitudes

At any candidate, a callback result of negative seventeen selects the same branch as negative one. A result of positive twenty-three selects the same branch as positive one.

### Duplicate matches

If several indices would compare equal and the first midpoint compares equal, the function returns that midpoint’s address. It does not continue searching for an earlier or later equal element.

### Zero stride

With base 4096, stride zero, and count five, every candidate address is 4096.

If the callback always returns positive one, the examined indices are two and four, followed by a zero return. Both callback invocations receive address 4096.

### Successful zero address

With base zero, count one, and any representable stride, the callback receives candidate address zero.

If it returns zero, the function successfully returns zero. That return alone cannot distinguish this success from a no-match result.

### Negative stride

With base 4096, stride negative four, and count five, the first candidate is index two at address 4088.

A positive comparison selects a higher index, despite that index having a lower numeric address. This behavior is valid only under a callback ordering consistent with index order.
