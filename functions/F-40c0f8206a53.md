# F-40c0f8206a53

## Purpose

The established behavior is an ordered sequence of indirect dependency calls, two 32-bit memory stores, two selector-byte reads, and two selector-directed byte stores. No application-level purpose is established.

One explicit input supplies both word-store payloads and the index for the first word-store destination. Dependency results supply the second word-store index, both byte-store payloads, and several later call arguments. A hidden entry value determines the selector-read address. Each byte-store destination is selected by a separate read from that address.

The visible sequence ends at a boundary marked as invalid instruction data. This establishes neither a successful return nor a particular runtime fault.

This contract distinguishes:

- **Established static evidence:** visible access widths, value dependencies, call ordering, and the absence of a visible normal return.
- **Inferred interpretation:** 32-bit wrapping address arithmetic where signed expressions otherwise leave overflow behavior unresolved.
- **documented_only unknowns:** calling conventions, dependency effects, memory validity, and execution beyond the supplied boundary.

## Behavior

Some scaled indices, target calculations, and later left shifts are represented using signed values. Their overflow behavior and signed-shift validity are not resolved by the supplied evidence.

Where numerical examples require wrapping signed address arithmetic, they are explicitly conditional on a 32-bit machine interpretation: scaling and addition retain their low 32 bits. This interpretation must not be mistaken for a portable signed-arithmetic guarantee.

### Initial word store and entry-dependent call

This store occurs before every dependency call. If it cannot complete, no dependency call has yet been reached.

D-01 follows. Its target is derived from the hidden entry control value plus `0xFFE`. Its three explicit arguments, in order, are:

1. The hidden entry word’s low six bits, shifted left fourteen positions.
2. The unchanged explicit argument.

### First selector-directed byte store

After D-10 returns, the routine reads one byte from the selector-read address derived from the hidden entry word.

The selector is zero-extended and increased by `0x11` to obtain the byte-store destination. The stored payload is the low byte of the D-10 result shifted left two positions. Equivalently, it is four times the low six bits of the D-10 result.

Consequently, this payload is a multiple of four in the inclusive range zero through `0xFC`.

The selector read precedes the associated write, with no visible dependency call between them. Their addresses cannot coincide under the stated 32-bit address interpretation.

### Intermediate calls

- The same shifted value again.
- The D-10 result shifted left four positions.

These are full-width arguments, not the truncated byte written earlier.

D-12 follows and supplies a 32-bit result that is passed directly as the sole explicit argument to D-13. No arithmetic transformation or direct dereference of this result is visible between those calls. Its meaning as an address, scalar, handle, or another representation remains unknown.

D-14, D-15, D-16, and D-17 then execute in order. D-17 supplies another 32-bit result, retained for D-18.

### Second selector-directed byte store

After D-17 returns, the routine performs a second byte read from the selector-read address. It does not reuse the first selector.

The two read addresses are derived from the same hidden entry value and the same expression. Their observed contents need not match: intervening dependencies may modify the addressed memory. External mutation is also not excluded by the evidence.

Neither direct byte store can modify selector memory by address aliasing. The selector-read address set and byte-store destination interval are disjoint. Possible overlap with a direct word store is a separate issue.

The second selector is saved as a zero-extended value. The second byte-store destination is that saved value plus `0x11`.

Its payload comes from the original D-10 result. The visible derivation masks that result to its low thirty bits, shifts right twenty positions, and truncates to a byte. The stored byte is therefore exactly bits 20 through 27 of the D-10 result.

Bits 28 and 29 can survive the intermediate right shift but are discarded by byte truncation. Bits 30 and 31 are removed by the preceding mask.

### Final calls and visible endpoint

D-18 follows the second byte store and receives the D-17 result shifted left two positions. This shift involves a signed-represented result; behavior outside a valid signed-shift range is unresolved unless wrapping machine semantics are assumed.

D-19, D-20, D-21, and D-22 follow in order. D-22 supplies a 32-bit result.

D-23 receives two explicit arguments:

1. The D-22 result shifted left two positions.
2. The saved, zero-extended second selector.

The same signed-shift limitation applies to the first argument. The second argument is not obtained from a fresh memory read. Later changes to selector memory therefore do not substitute a new value for that argument in the visible data flow.

D-24 follows. The next established boundary is invalid instruction data. No normal return, subsequent continuation, cleanup path, or specific hardware trap is established.

### Aliasing constraints

The two word writes may address the same location. The two byte writes may also address the same location if their selectors are equal.

A byte-store destination may overlap a byte within a word-store region. A word-store region may also overlap selector memory where the calculated addresses permit it. These possibilities do not imply a particular byte value at the overlap, because endianness is unresolved.

In contrast, a direct byte-store destination cannot overlap a selector-read location under the stated arithmetic interpretation:

- Byte-store destinations range from `0x11` through `0x110`.
- Selector-read locations are `0x01`, `0x04000001`, and subsequent values separated by `0x04000000`.

Thus, the first byte write cannot itself change the second selector by aliasing selector memory. Dependencies between the reads can still change selector memory.

## Acceptance examples

These are conditional static deductions, not executed tests. They assume valid memory mappings, returning dependencies, and any stated wrapping arithmetic interpretation.

### Word stores and ordering

With explicit argument `3`, the initial word store targets `0x20` and stores `3`.

If D-05 returns `7`, the second word store targets `0x30`, also storing `3`. D-06 receives `0x1C`, not `0x30`.

A trace that reaches D-01 before performing the initial word store contradicts the established ordering.

### Entry-word extraction

With hidden entry word `0x1234567F`, D-01’s first and third arguments are respectively `0x000FC000` and `0xF0000000`; its second argument remains the explicit argument.

The selector-read address is `0xFC000001` under unsigned 32-bit arithmetic.

### Distinct selectors and retained payload source

Suppose D-10 returns `0x0AB12345`.

If the first selector is `0x20`, the first byte store targets `0x31` and writes `0x14`.

If the second selector is later `0x80`, the second byte store targets `0x91` and writes `0xAB`. D-23’s second explicit argument is `0x00000080`, even if a dependency after that second read changes selector memory.

Using the first selector for the second store, or deriving the second payload from D-17, would contradict the visible data dependencies.

### Selector and byte-store disjointness

With hidden entry word zero, both selector reads address `0x01`. A selector of zero directs a byte write to `0x11`; a selector of `0xFF` directs it to `0x110`. Neither write reaches `0x01`.

With hidden entry word one, both selector reads address `0x04000001`, beyond every possible direct byte-store destination.

With hidden entry word `0x40`, the selector-read address returns to `0x01` because the multiplication retains only 32 bits. These cases illustrate low-six-bit address dependence, not valid target memory mappings.

A scenario that attributes a changed second selector solely to the first direct byte write aliasing selector memory is incompatible with these address ranges. A change caused by an intervening dependency remains compatible.

### Partial execution

If the initial word store faults, no dependency call has been reached.

If D-17 does not return, the first byte store has occurred, but the second selector read has not been reached.

If every visible memory access and dependency completes normally, the established endpoint is the invalid-instruction boundary, not successful return.
