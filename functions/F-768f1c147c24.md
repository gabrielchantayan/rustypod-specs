# F-768f1c147c24

## Purpose

F-768f1c147c24 searches a contiguous array of 32-bit slots using a byte-derived hash and backward probing. It returns the address of either:

- A slot whose referenced entry passes the function’s key-comparison conditions; or
- The first zero-valued slot encountered along that probe sequence.

The function does not explicitly insert an entry, allocate storage, or report whether the returned slot represents a match or an empty position.

**Inferred intent:** this is a lookup-position operation for an open-addressed table with string-like keys. That interpretation is consistent with the visible structure, but the supplied evidence does not establish the surrounding table implementation or the behavior of its dependencies.

## Interface

### Inputs

The function accepts two machine-level arguments:

1. **Query address.** A pointer to bytes. Initially, bytes are read sequentially until a zero byte is encountered.
2. **Context address.** An address used to access these fields:

| Byte offset | Width | Observed use |
|---|---:|---|
| +4 | 32 bits | Passed to F-d7be9cfb4000; also read during probe wrapping |
| +12 | 32-bit pointer representation | Base address of the slot array |

No other context fields are visibly accessed.

The supplied representation uses 32-bit integers and 32-bit slot elements. Pointer-bearing words are treated as addresses in that representation. This describes the visible layout; it does not independently establish the original language’s complete type declarations or the execution platform’s ABI.

### Slot and entry layout

The slot array contains consecutive 4-byte elements.

- A zero slot value denotes an available stopping position.
- A nonzero slot value is treated as an entry address.
- The first 32-bit word at that entry address is treated as a pointer to key bytes.
- The first byte at that key address is read before any comparison dependency is called.

No other entry fields are accessed directly.

### Output

The result is the **address of a slot**, not the entry address stored in that slot and not a Boolean result.

For a normal, memory-safe completion, the returned address identifies the slot at which probing stopped. Its value was either observed as zero, or its referenced key passed the first-byte check and the comparison dependency returned zero.

Those observations are not a guarantee about the slot’s contents at return if a dependency or another actor can mutate the table.

### Preconditions for ordinary completion

The visible function performs no validation. Safe execution therefore depends on the relevant accesses being valid:

- The query must remain readable through the zero byte reached by the initial scan.
- The two accessed context fields must be readable.
- The captured slot-array base and the index supplied through F-d7be9cfb4000 must produce a valid initial slot address.
- Every visited nonzero slot must identify a readable entry whose first word identifies readable key bytes.
- Any additional memory requirements of the comparison dependency must hold.
- Pointer calculations and ordering comparisons must be meaningful in the target execution model.

Termination additionally requires that probing eventually encounters a zero slot or a qualifying comparison result. The function does not enforce that requirement.

## Behavior

### Initial state capture

The slot-array base is read from context offset +12 **before** the query is scanned.

That captured base is retained for initial slot selection, backward-boundary detection, and wrap-address construction. The function does not visibly reload the context’s base field afterward.

Consequently, changing the context’s base field during a dependency call does not redirect this invocation to a different base.

### Query hashing

The function starts a 32-bit accumulator at zero and reads query bytes in increasing address order until it observes a zero byte.

Each nonzero byte is interpreted as an unsigned value from 1 through 255. For each such byte, the accumulator is multiplied by 31 and the byte value is added. The terminating zero byte does not contribute to the accumulator.

The visible arithmetic has 32-bit operands and storage. Under a 32-bit wrapping machine interpretation, the accumulated bit pattern is the polynomial hash reduced modulo \(2^{32}\). The evidence does not justify treating that result as an unbounded mathematical integer. Nor does it establish portable source-language behavior for overflowing signed arithmetic.

An empty query produces the accumulator bit pattern zero.

The function does not retain a copy of the scanned query. It later reads the query’s first byte again and passes the original query address to the comparison dependency.

### Initial probe position

After hashing, the function reads the 32-bit field at context offset +4 and calls F-d7be9cfb4000 with:

1. The accumulated 32-bit hash bit pattern.
2. The just-read context field.

The initial slot displacement is obtained from the machine’s secondary result register, identified in the supplied representation as `r1`, after that call. The function adds that displacement in **4-byte slot units** to the previously captured base.

The supplied evidence does not establish F-d7be9cfb4000’s semantics. In particular, it does not establish that the displacement is:

- A remainder;
- Nonnegative;
- Smaller than the supplied context field; or
- Valid for the captured array.

The caller performs no visible normalization or bounds check on that initial displacement. The ordinary primary return value of the dependency is not visibly used.

### Candidate evaluation

At each candidate slot, the function first reads the slot’s 32-bit value.

If that value is zero, probing stops immediately and the slot address is returned. No entry or stored-key dereference is required on that path.

For a nonzero slot:

1. The slot value is treated as an entry address.
2. The first word at that address is read as the stored-key address.
3. The first stored-key byte and the first query byte are compared.
4. If those bytes differ, the slot is rejected without calling the comparison dependency.
5. If those bytes are equal, F-unmapped-01 is called with the stored-key address first and the query address second.
6. A zero result accepts the current slot. A nonzero result rejects it.

The supplied expression does not establish the evaluation order between the two first-byte reads. It does establish that both participate in the gate before the comparison call.

The direct comparison establishes equality only of the first bytes. Whole-key equality depends on F-unmapped-01’s undocumented behavior. The contract must not equate a zero result with string equality unless that dependency’s contract is supplied separately.

### Backward probing and wrap

A rejected nonzero candidate causes the candidate address to move backward by one 4-byte slot.

After that decrement:

- If the resulting address is not below the captured base, probing continues there.
- If it is below the captured base, the function rereads the 32-bit field at context offset +4 and selects the address corresponding to “captured base plus that many slots, minus one slot.”

Thus, under the conventional interpretation of the field as a positive slot count, rejecting slot zero wraps to the final slot.

The count-like field is not cached for the entire search. Its value used during a later wrap may differ from the value passed to F-d7be9cfb4000. In contrast, the base remains the originally captured base.

There is no visible visited-slot counter, cycle detector, or full-table failure path.

### Completion and failure behavior

There is one visible kind of normal return: a candidate slot address.

There is no explicit error return for:

- A null query or context;
- An invalid entry or key pointer;
- A zero or negative count-like field;
- An invalid dependency-produced displacement;
- A full table with no qualifying match;
- A probe cycle.

Invalid accesses may fault or otherwise fail according to the execution environment. A probe sequence containing only rejected nonzero slots may continue indefinitely. Neither outcome is converted into an explicit error result by the visible function.

It contains no explicit allocation, deallocation, ownership transfer, or reference-count update.

The returned slot address aliases the existing table storage. Nothing in the function establishes that this address is newly owned, independently allocated, or safe to retain after the table changes.

## Acceptance examples

These examples are conditional behavioral checks, not executed tests. Unless stated otherwise, they assume stable readable storage, valid pointer arithmetic, and dependencies that do not mutate relevant state.

### Empty initial slot

Given an initial displacement selecting a zero-valued slot, the function returns that slot’s address.

No entry-key access or comparison call occurs. The initial query scan and F-d7be9cfb4000 call still occur.

### First-byte mismatch

Given a nonzero initial slot whose stored key begins with `b`, and a query beginning with `a`, the comparison dependency is not called for that slot.

The next candidate is the preceding slot, subject to wrapping at the captured base.

### Equal first byte, accepted comparison

Given a nonzero candidate whose stored key and query both begin with `a`, and F-unmapped-01 returning zero, the current slot address is returned.

The function does not require any additional visible equality check.

### Equal first byte, rejected comparison

Given matching first bytes but a nonzero comparison result, the candidate is rejected. Probing proceeds backward exactly as for a first-byte mismatch.

### Wrap from the first slot

Given a stable count-like value of four, rejecting slot zero causes the next candidate to be slot three.

If that field instead contains three when the wrap read occurs, the next candidate is slot two, regardless of the value previously passed to F-d7be9cfb4000.

### Empty query

A query beginning with zero produces a zero hash accumulator.

For an occupied candidate whose stored first byte is also zero, F-unmapped-01 is called. The empty query is not automatically accepted or rejected by a separate rule.

### High-valued query byte

A one-byte query containing byte value 255 followed by zero produces accumulator value 255 before the dependency call. The byte is not interpreted as negative one.

### Mutation during an accepted comparison

If F-unmapped-01 clears the current slot and returns zero, the function returns the address of that now-cleared slot. It does not visibly restart the slot test.

### No stopping candidate

Given a valid finite probe cycle in which every slot is nonzero and every candidate is rejected, the function has no normal full-table rejection outcome. It continues probing while those conditions persist.
