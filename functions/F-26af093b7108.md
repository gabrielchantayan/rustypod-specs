# F-26af093b7108

## Purpose

F-26af093b7108 writes a shared nine-word result area and returns its address. A signed 32-bit input value of −1 selects a distinguished initialization path. All other values select a calculation involving repeated dependency calls, global values, and byte-table reduction.

The field arrangement and constants suggest a broken-down calendar-time calculation. That is **inferred intent**, not an established interface: the dependency semantics, epoch, units, table contents, and calendar conventions are unavailable.

This contract distinguishes facts established by the supplied static representation from conditional interpretations and unresolved behavior. No runtime tests have been performed.

## Interface

### Input

The sole explicit argument is a pointer to a signed 32-bit integer.

The supplied representation contains:

- One input read to select the branch.
- A second input read on the ordinary path, supplying the first calculation call.

These reads must not be collapsed into a contractual promise of a single captured input value. If the storage changes between them, the first observed value selects the branch and the second supplies the calculation.

There is no explicit null-pointer, alignment, accessibility, or input-range validation. The function does not directly write through the input pointer. Aliasing with result storage, or effects of dependencies, can nevertheless change that storage.

### Result storage and return value

At entry, before reading the input, the function reads a global result-pointer slot and captures its value. Explicit result writes and the eventual return use this captured pointer.

The result area contains nine consecutive 32-bit words:

| Byte offset | Field | Ordinary-path value |
|---:|---|---|
| 0 | A | Upper 32 bits of the first calculation result |
| 4 | B | Upper 32 bits of the second calculation result |
| 8 | C | Upper 32 bits of the third calculation result |
| 12 | D | Final table-reduction residual plus one |
| 16 | E | Number of table entries consumed |
| 20 | F | Combined value derived from later calculation results |
| 24 | G | Secondary result associated with the call using 7 |
| 28 | H | Residual before adjustment and table reduction |
| 32 | I | All-one bit pattern, 0xffffffff |

The labels describe storage positions, not calendar meanings or signed field types.

The distinguished path reads the global result-pointer slot **again** for its external call. That second pointer need not equal the captured pointer. The external call’s target, the later explicit write target, and the returned address therefore require separate treatment.

### Ownership and validity

No allocation or release is explicit in this function. Returning the captured pointer does not establish ownership transfer, caller deallocation rights, exclusive access, or any lifetime beyond that supported by the surrounding system.

Successful execution requires valid storage for each actual access. An ordinary completed execution writes all 36 result bytes. The distinguished path explicitly writes only the word at offset 12; the external dependency’s memory-access requirements are unknown.

Dependencies must not be assumed to preserve globals, preserve result contents, or retain allocated storage. If a dependency invalidates the captured result area, later accesses are not established as safe.

## Behavior

### Entry and branch selection

The function first captures the global result pointer and initializes a signed 32-bit table-position counter to zero. It then reads the input.

An observed input of −1 selects the distinguished path. Every other 32-bit input pattern selects the ordinary path. Both paths, if completed, return the originally captured pointer rather than rereading the global slot at return.

### Distinguished path

After selecting this path, the function rereads the global result-pointer slot. It passes that newly read pointer and the value 36 to an unidentified external dependency.

After the dependency returns, the function writes the 32-bit value 1 to field D of the **captured** result area, then returns the captured pointer.

The established behavior is the call with those arguments followed by the explicit write. It is not established that the call clears memory, initializes nine fields, or operates on the same area subsequently returned.

If the global slot changes between its two reads:

- The external dependency receives the second pointer.
- The field-D write still targets the first pointer.
- The return value is still the first pointer.

Even if the external dependency is independently known to clear 36 bytes, a guarantee that the returned area is cleared additionally requires that its argument identifies the captured area.

### Ordinary-path decomposition

The ordinary path rereads the signed 32-bit input and calls F-d7be9cfb4000 with that value and 60.

For the first three calls, the returned quantity is represented as 64 bits, with independently used lower and upper 32-bit components:

1. The first upper component is written to A. Its lower component, interpreted as signed 32-bit, becomes the first argument of a second call with 60.
2. The second upper component is written to B. Its lower component, interpreted as signed 32-bit, becomes the first argument of a third call with 24.
3. The third lower component, interpreted as signed 32-bit, is increased by 25,568 to form an intermediate value. The third upper component is then written to C.

The offset addition precedes the write to C. Its signed-overflow qualification is described below.

The repeated splitting resembles quotient/remainder decomposition, but neither that interpretation nor any particular rounding rule is established without the dependency’s contract.

### Secondary result and combined value

The function calls F-d7be9cfb4000 with the intermediate value and 7, then writes an associated secondary 32-bit result to G.

The supplied representation does not express this value as an extracted upper half of a retained 64-bit return. Its relationship to the earlier upper components remains unresolved.

Next, the function reads a first global calculation value and calls F-d7be9cfb4000 with the intermediate value and that observed value.

From this result:

- The upper 32 bits become an unsigned residual.
- The lower 32 bits are interpreted as signed 32-bit and multiplied by four.
- The multiplication result is assigned to an unsigned 32-bit combined value.

The unsigned destination does **not** make the preceding multiplication unsigned. Signed multiplication overflow remains outside the established behavior.

An additional call occurs exactly when the unsigned residual exceeds 365. The two comparisons in the supplied representation jointly select residual values from 366 through 0xffffffff.

On that path, the function reads a second global calculation value and calls F-d7be9cfb4000 with the unsigned expression “residual minus one” and the newly read global value. The upper result replaces the residual. The lower result, interpreted as signed 32-bit and then participating in unsigned addition, is added to the combined value modulo \(2^{32}\).

The two global calculation values are distinct reads from distinct locations. Neither equality nor immutability is established. The second location is not read on the path that skips this additional call.

### Residual adjustment and table reduction

After the optional call, the function reads a signed 32-bit global table-address component. It then writes:

1. The combined value to F.
2. The current residual to H.

H therefore preserves the residual before either the following adjustment or table reduction.

If the combined value has either of its low two bits set, the working residual is increased by one when it exceeds 58. Otherwise it is unchanged. This is unsigned 32-bit arithmetic: incrementing 0xffffffff produces zero.

The table-position counter begins at zero. Each table address is formed by signed additions of:

- The captured global table-address component.
- The fixed base 0x08033644.
- The current signed table-position counter.

The resulting integer is converted to a byte pointer. The signed arithmetic and pointer-conversion restrictions below apply before accessibility of the resulting byte can be considered.

At each position, the representation reads an unsigned byte and compares it with the unsigned working residual:

- A byte greater than the residual stops reduction.
- A byte less than or equal to the residual causes consumption of that position.

For a consumed position, the representation reads the byte **again**, subtracts that second observed byte from the residual using unsigned 32-bit arithmetic, and increments the signed position counter.

For stable table contents, the tested and subtracted bytes agree. Without stability, that equality is not guaranteed. A second byte larger than the residual can therefore cause unsigned subtraction to wrap even though the first comparison permitted consumption.

After reduction stops, the function writes, in order:

1. Working residual plus one to D.
2. 0xffffffff to I.
3. The position counter to E.

It then returns the captured result pointer.

### Arithmetic and termination limits

The following operations require separate treatment:

- **Signed offset addition:** The third lower result is interpreted as signed 32-bit before adding 25,568. The mathematical sum is representable only when that operand is at most 2,147,458,079. Signed-overflow behavior is not established.
- **Signed multiplication:** The later lower result is interpreted as signed 32-bit before multiplication by four. The representable operand range is −536,870,912 through 536,870,911 inclusive. Assignment to unsigned storage does not justify modular multiplication outside that range.
- **Unsigned accumulation:** Adding the optional call’s lower component to the unsigned combined value uses unsigned 32-bit arithmetic and discards carry beyond bit 31.
- **Unsigned residual arithmetic:** Conditional increment, table subtraction, and the final addition of one use unsigned 32-bit arithmetic.
- **Signed address additions:** The addition of the global table component to 0x08033644, and the subsequent addition of the position counter, must each remain within signed 32-bit range for the represented arithmetic to stay within its established domain.
- **Signed counter increment:** Advancing beyond 2,147,483,647 is outside the established signed range.

An accessible intended table and an in-range counter are insufficient by themselves: intermediate signed address addition can overflow before pointer conversion. Conversely, representable integer additions do not establish that the resulting pointer conversion or memory access is valid on the execution platform.

No table length or explicit loop bound is supplied. A stable zero byte is consumed without reducing the residual and does not terminate the loop. Completion requires eventually observing a comparison byte greater than the then-current residual while every preceding address calculation, read, and counter increment remains valid.

## Side effects

The ordinary path explicitly writes result fields in this order:

A, B, C, G, F, H, D, I, E.

Dependency calls intervene between some writes. The update is not atomic; observers or dependencies can encounter a partially updated result.

The global table component is read before the writes to F and H. If those writes alias its storage, the already captured component is still used. Table bytes themselves are read afterward, so aliasing with result storage can affect the reduction.

On the distinguished path, the second global pointer read and external call precede the explicit D write. No other result field has an independently established final value.

The function also reads global calculation values and table memory. Dependencies may modify those locations or other state. Values used after calls are the values read at their specified points, not an assumed entry-time snapshot.

No explicit locking, rollback, error status, exception handling, or recovery is visible. A failure or invalid access can leave earlier writes intact. The body provides no separate failure return.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Distinguished path with a stable pointer slot.** If the input is −1 and both slot reads yield the same valid area, the external call receives that area and 36. If it returns with the area writable, D becomes 1 and the function returns that area. Other field values depend on the external dependency.

2. **Different pointer-slot observations.** If the entry read captures area P and the distinguished-path reread yields distinct area Q, the external call receives Q and 36. After a successful return preserving writable P, the explicit D write targets P and the function returns P. No clearing of P follows merely from clearing Q.

3. **Conditional clearing guarantee.** If the external dependency clears exactly 36 bytes, its argument identifies the captured area, and that area remains writable, all nine fields end as zero except D, which becomes 1.

4. **Additional-call boundary.** A first residual of 365 skips the optional call. A residual of 366 takes it with first-argument bits representing 365.

5. **Adjustment and stored residual.** With nonzero low two bits in the combined value, residual 58 stays 58, while 59 becomes 60. In the latter case, H remains 59 and table reduction begins from 60. With both low bits zero, neither value is adjusted.

6. **Exact table consumption.** With valid address arithmetic, stable bytes beginning 31, 28, 31, and starting residual 31, the first byte is consumed. Residual zero then stops at 28, producing D = 1 and E = 1.

7. **Immediate stop.** With the same validity conditions, starting residual 30 and first byte 31 produce D = 31 and E = 0.

8. **Multiplication boundary.** A signed lower component of 536,870,911 has a representable product of 2,147,483,644. A component of 536,870,912 does not; unconditional wraparound is not an acceptance requirement.

9. **Address-arithmetic boundary.** If the global component plus the fixed base exceeds signed 32-bit range, a readable intended table does not establish defined execution. Likewise, a representable first sum does not suffice if adding the current position overflows.

10. **Later global pointer mutation.** If an ordinary-path dependency changes only the global result-pointer slot while preserving the captured area, subsequent explicit result writes and the return still use the captured area.
