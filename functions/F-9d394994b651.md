# F-9d394994b651

## Purpose

F-9d394994b651 coordinates a sequence of dependency calls around three indirect control values and six additional caller-supplied values. It initializes two working words from a common seed, processes the control arguments, selects later operations using exact control-value comparisons, and returns a 32-bit zero if execution reaches the end.

The established behavior is an ordered dispatch procedure, not a demonstrated implementation of any particular encoding, parsing, or serialization format. The repeated use of two working-word addresses suggests shared processing state, but the meanings of that state and the dependency operations are unknown.

This contract distinguishes behavior directly visible in the supplied static material from inferred intent and unresolved dependency behavior. No runtime tests have been performed.

## Behavior

### 1. Initialize and process the first two control slots

Both working words are initialized from State seed before any dependency is called.

F-f884c002a630 is then invoked twice, in this order:

1. With the two working-word addresses, First control slot, and the constant 1.
2. With the two working-word addresses, Second control slot, and the constant 1.

The function does not restore either working word between these calls. Any dependency changes to those words are therefore available to subsequent calls.

Neither first nor second control word is tested before these two calls complete.

### 2. Establish the third control slot

1. F-d33f6d597e5d is called with the numeric argument 4.

3. A 32-bit zero is written at that returned address.

The slot replacement precedes the zero store. No release of any previous address in Third control slot is visible. There is no visible allocation-failure check or branch.

**For values 6 through the maximum unsigned 32-bit value:**

F-f884c002a630 is called with the two working-word addresses, Third control slot, and the constant 1.

This branch contains no direct allocation-result store or direct zero initialization by F-9d394994b651. The dependency’s effects on the slot and its referenced storage are unknown.

### 3. Select the first optional operation

After third-slot processing completes, the function reads First control slot and then reads the 32-bit word at the resulting address.

If, and only if, that word equals exactly 1, F-70b9ea10a620 is called with:

- The two working-word addresses.
- First conditional operand.
- The constants 8, 2, and 256, in that order.

Zero, 2, and every other bit pattern skip this call. The condition is exact equality, not a general nonzero test.

The tested value is the value present at this point in execution. It is not a saved value from before the preceding dependency calls.

### 4. Perform the primary operation

- The two working-word addresses.
- Primary operand.
- Count, unchanged.
- The constants 16 and 256, in that order.

This call is unconditional once execution reaches this stage. It occurs even when Count is zero or negative. No visible normalization, clamping, or unsigned conversion of Count is performed before forwarding it.

### 5. Select an operation using Count and the third control word

Count is compared with 1 using a signed comparison.

If Count is less than or equal to 1, both operations in this stage are skipped. In particular, there is no direct read of Third control slot or its referenced control word for this stage.

If Count is greater than 1, the function reads Third control slot and then the 32-bit word at the resulting address:

- **If the word is zero:** F-f884c002a630 is called with the two working-word addresses and Zero-third-control operand.
- **If the word is nonzero:** F-0d6ca63768f0 is called with the two working-word addresses, Nonzero-third-control operand, and the constants 4 and 256.

The zero-control invocation of F-f884c002a630 visibly supplies three arguments. Its earlier invocations visibly supply four. This contract preserves that difference. It does not invent a fourth argument or assume an omitted argument has value 1.

The below-6 revision branch initially writes zero to the allocated word, but that does not establish which operation will later be selected. Intervening dependencies may change the slot or reachable storage.

### 6. Select the final pair of operations

After the Count-dependent stage, the function reads Second control slot and then the 32-bit word at the resulting address.

If that word equals exactly 1, it performs these calls in order:

1. F-70b9ea10a620 with the two working-word addresses, Second-control leading operand, and constants 8, 2, and 256.
2. F-0e17a706db33 with the two working-word addresses, Second-control trailing operand, and constants 8 and 256.

If the word is anything other than 1, neither call occurs.

The condition is evaluated once before this pair. There is no visible second-control recheck between the calls. If the first returns normally, the second follows even if the first changed the second control word.

### 7. Return

After all selected calls return normally, the function returns a 32-bit zero.

No dependency return value is visibly interpreted as a success or failure status. The allocation dependency’s result is used as an address, not checked as a status. A zero return from F-9d394994b651 therefore does not independently establish success of the dependency operations.

## Side effects

### Directly established effects

Outside its private working words, the function’s explicit writes occur only in the below-6 revision branch:

- Replacement of Third control slot with the allocation result.
- A subsequent 32-bit zero store at that address.

No explicit write is made directly to First control slot or Second control slot. Their addresses are passed to dependencies that may modify them.

The function directly performs the conditional control reads in this order:

1. First control word, after third-slot processing.
2. Third control word, only when Count is greater than 1 and after the primary operation.
3. Second control word, after the Count-dependent stage.

Dependencies may perform additional reads and writes not described by the available evidence.

### Aliasing and state visibility

No non-aliasing condition is established for the three control slots or their referenced storage. If slots alias, a write through Third control slot may change the address later obtained through First control slot or Second control slot.

Likewise, changes made by earlier dependencies can affect later branch decisions. The procedure does not snapshot all controls at entry.

Both working words retain their current contents across dependency calls. No reset to State seed occurs after initialization, and no final working-word value is explicitly returned or copied into a caller-supplied destination by this function.

### Ownership and lifetime

The below-6 branch requests storage with the numeric argument 4 and exposes the returned address through Third control slot. No release is visible within F-9d394994b651.

This does not establish who owns that storage, whether a dependency later releases it, or whether an overwritten prior address required release. Those questions are documented_only.

Dependencies receive addresses of invocation-local working words. Whether they retain those addresses is unknown; safe retention beyond the invocation is not established.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Each assumes valid accesses and normally returning dependencies.

1. **Lower revision boundary.** With Revision selector 5, the third-slot stage must call F-d33f6d597e5d with 4, store its result into Third control slot, and then store a 32-bit zero at that result. It must not use the four-argument third-slot processing call instead.

2. **Upper revision boundary.** With Revision selector 6, the third-slot stage must call F-f884c002a630 with Third control slot and trailing constant 1. No direct allocation or zero store belongs to that branch.

3. **Signed Count boundary.** With Count equal to 1, 0, or a negative signed 32-bit value, the primary operation must still receive that Count. Neither third-control-selected operation occurs, and the function makes no third-control read for that selection stage.

4. **Zero third control.** With Count 2 and a third control word of zero at the actual decision point, the selected call must be the three-argument invocation of F-f884c002a630 using Zero-third-control operand. F-0d6ca63768f0 must not be selected.

5. **Nonzero third control.** With Count 2 and any nonzero third control word at that decision point, F-0d6ca63768f0 must receive Nonzero-third-control operand, 4, and 256. This includes nonzero values other than 1.

6. **Exact first-control comparison.** A first control word of 2 must skip the first optional operation. A value of 1 must select it. The relevant value is the one observed after third-slot processing.

7. **Late second-control observation.** If an earlier dependency changes the second control word from 0 to 1 before its final read, the final pair must be selected. An entry-time value of 0 must not suppress that later decision.

8. **No recheck within the final pair.** If the second control word is 1 when tested and the leading operation changes it to 0, the trailing operation must still follow, provided the leading operation returns normally.

9. **Allocation failure is not a handled outcome.** If the allocation dependency returns an address that cannot accept the zero store, the evidence establishes no normal error return or recovery path. The contract must not describe such a result as safely returning zero.
