Different sequences must not be treated as calls to the same function. Nor does “no explicit arguments” establish that the machine-level call receives no register state.

A **bridge** consists of four calls: a leading call with the listed arguments, a no-explicit-argument call producing a 32-bit result, a call receiving that result, and another no-explicit-argument call producing a further result. That final result becomes an argument to the following five-call sequence.

## Acceptance examples

These are conditional static acceptance examples, not observed executions.

1. **Third-argument grouping.** If the initial word is `0x11223344`, dependencies return, and the relevant destination is writable, third arguments zero through 127 select address twenty for both initial word writes. An argument of 128 selects address twenty-four. Both writes use the saved initial word.

2. **Fresh selector reads.** If the incoming base’s selector byte is three before the first write and nine after F-D01, the first write targets address twenty and the second targets address twenty-six. Caching the first selector would violate the represented read order.

3. **Snapshot preservation.** If the primary word is read as `0xA1B2C3D4`, its later derived values include `0xA1B2` for the sixteen-bit shift, `0xA1` for the twenty-four-bit shift, and one for the thirty-one-bit shift. Dependency changes to the original word location do not themselves refresh this saved value.

4. **Byte truncation.** If the first byte-stage result is `0x00000041`, its first byte payload is `0x04`, not `0x104`. If its thirty-bit-masked value shifted right by twenty exceeds 255, the later byte write still retains only eight bits.

5. **Ordered final writes.** If the primary word’s top bit is clear, the second byte-stage payload targets address twenty-eight. The subsequent selector-based zero write occurs afterward and may overwrite that byte if its selector chooses the same address.

6. **Loop argument transition.** The first loop call’s second argument is zero. Under 32-bit bit-vector arithmetic, if the final result of the second loop sequence is one, the next first argument is four and the next loop quantity is `0x04000000`; the next iteration’s second argument is therefore `0x00040000`.

7. **No completion promise.** Even if every dependency returns and every access succeeds, reaching the loop does not produce a normal return. Conversely, a dependency that does not return prevents subsequent visible operations.
