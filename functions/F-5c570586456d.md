# F-5c570586456d

## Purpose

F-5c570586456d compares two supplied 32-bit endpoint values. Equal endpoints produce an immediate two-word result without dependency calls. Unequal endpoints cause an ordered sequence of dependency calls and context-relative reads before a different two-word result is returned.

The established behavior is argument selection, result forwarding, memory-access ordering, and result packing. The supplied caller does not establish the application meaning of the endpoints or dependency results.

Allocation, object construction, registration, and association are possible interpretations of the unequal-endpoint sequence, not established dependency contracts. In particular, the three calls to F-8157a180d901 pass the integers 24, 24, and 36. Their units, meaning, and relationship to storage are unknown.

## Interface

| Position | Descriptive role | Established use |

| 2 | Caller-supplied word | Forwarded unchanged to F-2698159acdb1 on the unequal path; becomes the upper result word on the equal path. |
| 3 | First endpoint | Compared with the fourth argument; shifted left by 16 for one dependency argument. |

Calling the first argument “owner-designating” does not establish that it points to an object, identifies owned storage, or transfers ownership. Its arithmetic use is established; its domain meaning is not.

### Output

The return value contains two 32-bit words in a 64-bit layout:

| Completed path | Upper word, bits 63–32 | Lower word, bits 31–0 |
|---|---:|---:|
| Equal endpoints | Argument 2, unchanged | 0 |
| Unequal endpoints, mode zero | 0 | 1 |
| Unequal endpoints, mode nonzero | 135, or 0x00000087 | 1 |

The upper word occupies the more significant half of the result. This specifies numeric bit layout, not memory byte order or an ABI register assignment.

The lower word distinguishes the completed branches. It is not a validated success code from the dependencies: the function does not inspect dependency results for failure before returning one.

### Conditions for normal completion

On the unequal path:

- Every dependency must return normally for the function to reach its return.
- The result of F-2698159acdb1 must permit the explicit 32-bit reads at byte offsets 0x30 and 0x04 when those reads occur.
- The endpoint shifts and owner-derived addition must have defined execution semantics.
- All forwarded values and the final local-slot address must satisfy the dependencies’ requirements.

These conditions are not checked by this function. No stronger precondition concerning F-8157a180d901 returning allocated storage or addresses is established.

The equal path does not perform these context reads, endpoint shifts, or owner-derived addition.

## Behavior

### Equal endpoints

The third and fourth arguments are compared before any dependency call or configuration read.

When their complete 32-bit values are equal:

- No dependency is called.
- The global configuration word used by the other path is not read.
- The mode selector has no effect on the result.
- The function returns argument 2 in the upper word and zero in the lower word.

No explicit caller-visible memory read or write is shown on this path beyond handling the invocation’s own execution state. The first argument need not support the address-related operations of the unequal path because those operations are not performed.

### Unequal endpoints: mode selection

For unequal endpoints, the sixth argument selects two words:

| Mode selector | Configuration word | Selected mode word |
|---|---|---:|
| Zero | A 32-bit word read from global storage | 0 |
| Nonzero | 200 | 135 |

Any nonzero 32-bit value, including a negative value, selects the second row.

The global read occurs only in zero mode and precedes the first dependency call. The read value is selected for the forthcoming call; later changes to that global do not retroactively change the argument already supplied.

After selection, the second endpoint is written to a 32-bit local slot. That initial value is replaced later, before the slot’s address is passed to a dependency.

### Endpoint transformation

Each endpoint is supplied to F-545766d274bf after a left shift by 16 positions. The operand representation is signed 32-bit, so this must not be described as unrestricted mathematical multiplication.

Under a defined 32-bit bit-vector interpretation:

- The endpoint’s low 16 bits become result bits 31–16.
- Result bits 15–0 are zero.
- The endpoint’s original high 16 bits are discarded.

The supplied representation does not resolve execution semantics for negative signed operands or nonnegative operands whose shifted mathematical value exceeds the signed 32-bit range. Any acceptance criterion using such operands must state its shift interpretation explicitly.

Equality is tested before transformation. Unequal endpoints can therefore yield identical transformed words without taking the equal-endpoint path.

### Read timing and local-slot behavior

The context fields are observed at different stages:

- Offset 0x30 is read after the third F-8157a180d901 call and before F-2b6fe108bb2f.
- Offset 0x04 is read after both F-cc387e609895 calls and F-2278c411a14d, but before the final three dependency calls.

The caller provides no basis for assuming that intervening dependencies preserve context memory or globals. Each read observes the field at its specified stage, not a value implicitly captured when the context was obtained.

The local slot initially contains the second endpoint and is later overwritten by the offset-0x04 value. Its address is supplied only to the final dependency. Whether that dependency reads, modifies, copies, or retains the referenced word is unknown. The address designates invocation-local storage and is not established as valid after the invocation returns.
