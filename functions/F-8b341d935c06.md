# F-8b341d935c06

## Purpose

F-8b341d935c06 conditionally updates one 32-bit word in a fixed-address region. A selector determines the word’s address. A separate control argument determines which bit transformation is applied.

On every active invocation, the function first calls dependency F-ddf4a1f94e38, then reads the selected word, transforms it, and writes the result back to the same address. One class of invocations returns without calling the dependency or accessing that region.

The fixed-address access and bit manipulation are consistent with hardware-register configuration, but that purpose is inferred rather than established. No peripheral identity, register-field meaning, or external hardware effect is established by the supplied evidence.

## Interface

## Behavior

### 1. Determine whether the invocation is active

The function examines the selector’s low seven bits and whether control is zero.

If the low-seven-bit index is zero **and** control is zero, the function returns immediately. On this path:

- F-ddf4a1f94e38 is not called.
- No selected-word read occurs.
- No selected-word write occurs.

Selector bit 7 and selector bits 8–31 cannot make this otherwise inactive case active.

Every other input combination takes the active path. In particular, index zero is accepted whenever control is nonzero.

### 2. Call the dependency

An active invocation calls F-ddf4a1f94e38 with:

1. The original 32-bit context token.
2. The complete original 32-bit selector.

Control is not passed.

This call precedes the selected-word read. Consequently, the update uses the word’s value **after** the dependency returns, not a value captured before the call.

No preservation guarantee is established for the dependency. It may affect memory, global state, or the selected location. Such effects must not be excluded when interpreting the subsequent read.

If the dependency does not return normally, the evidence does not establish that the selected-word read or write occurs.

### 3. Select the 32-bit word

Let the index be the unsigned value represented by selector bits 0–6. Its range is 0 through 127 inclusive.

The bank offset is:

| Selector bit 7 | Bank offset |
|---|---:|
| Clear | `0x00000B00` |
| Set | `0x00000900` |

The selected address is the fixed base `0x38400000`, plus the bank offset, plus the index multiplied by `0x20`.

Thus, the logical layout has:

- A 32-byte stride between adjacent indices.
- A 32-bit word accessed at each selected address.
- A maximum index contribution of `0x00000FE0`.
- Four-byte-aligned selected addresses throughout the possible range.

The bank whose offset is `0xB00` selects addresses from `0x38400B00` through `0x38401AE0`. The bank whose offset is `0x900` selects addresses from `0x38400900` through `0x384018E0`. These ranges describe the possible index addresses, spaced 32 bytes apart; the function does not traverse or access every byte between the endpoints.

The bank offset, index multiplication, and final address all fit within unsigned 32-bit arithmetic. No wraparound is needed to obtain any selected address.

#### Address aliasing between banks

The banks are not disjoint. Their offsets differ by `0x200`, equal to sixteen index strides.

For each index from 0 through 111, selecting that index with bit 7 clear addresses the same word as selecting index sixteen greater with bit 7 set.

For example, index 1 with bit 7 clear and index 17 with bit 7 set both select `0x38400B20`.

This address alias does not make the invocations fully equivalent. The dependency receives different complete selector values and may behave differently. The activity gate can also differ between selectors that address the same location.

### 4. Read, transform, and write

After the dependency returns, the function reads one 32-bit word from the selected address. It transforms that value according to whether control is zero, then writes one 32-bit result to the same address.

Bit numbering below starts at bit 0 for the least significant bit.

#### Control equal to zero

This branch can be reached only when the index is nonzero, because index zero with zero control returns earlier.

The read value is ANDed with `0x03DDFFFF`, then ORed with `0x10000000`.

The resulting bit contract is:

| Bits | Result |
|---|---|
| 0–16 | Preserved from the read value |
| 17 | Cleared |
| 18–20 | Preserved |
| 21 | Cleared |
| 22–25 | Preserved |
| 26–27 | Cleared |
| 28 | Set |
| 29–31 | Cleared |

Bit 28 is forced to one regardless of its prior value.

#### Control nonzero

This branch permits every index, including zero.

The read value is ANDed with `0x03FDFFFF`, then ORed with `0x00200000`.

The resulting bit contract is:

| Bits | Result |
|---|---|
| 0–16 | Preserved from the read value |
| 17 | Cleared |
| 18–20 | Preserved |
| 21 | Set |
| 22–25 | Preserved |
| 26–31 | Cleared |

Bit 21 is forced to one regardless of its prior value. Bit 28 is cleared in this branch.

### 5. Return

After the write, the function returns without checking the written location or exposing a status value.

There is no evidenced retry, polling loop, readback verification, or alternate path after the write. A write is still performed when the transformed value equals the value read.

## Acceptance examples

These are conditional acceptance cases derived from static evidence. They are not reports of executed tests.

For active-path examples, assume that the dependency returns normally and that the selected address permits the required accesses. Any stated initial word value means the value observed by the read **after** the dependency returns.

### Inactive index zero

Given selector `0x00000000` and control zero, the function returns without a dependency call or selected-word access.

The same behavior applies to selector `0x00000080` and control zero. Setting the bank bit alone does not activate the function.

Selector `0xFFFFFF80` with control zero is also inactive: its low seven bits remain zero despite its other set bits.

### Zero-control transformation

Given selector `0x00000001` and control zero:

- The dependency receives the original context token and selector `0x00000001`.
- The selected address is `0x38400B20`.
- If the read value is `0xFFFFFFFF`, the written value is `0x13DDFFFF`.
- If the read value is `0x00000000`, the written value is `0x10000000`.

These cases distinguish the forced bit from the preserved and cleared bits.

### Nonzero control permits index zero

Given selector `0x00000080` and control 1:

- The dependency is called.
- Index zero is used in the bank selected by bit 7.
- The selected address is `0x38400900`.
- If the read value is `0xFFFFFFFF`, the written value is `0x03FDFFFF`.

This must not be treated as an inactive invocation.

### Negative control

Given selector `0x00000001` and control −1, the nonzero transformation applies at `0x38400B20`.

If the read value is zero, the written value is `0x00200000`. With the same observed read value, control 1 produces the same direct write.

### Upper selector bits

Selectors `0x00000001` and `0xA5000001` both select `0x38400B20` and have the same local activity decision.

They are nevertheless forwarded as distinct values to F-ddf4a1f94e38. Identical overall effects cannot be required without a separate dependency contract.

### Aliased addresses

Selectors `0x00000001` and `0x00000091` both select `0x38400B20`.

If control, the post-dependency read value, and successful access conditions are the same, the direct written value is the same. Dependency effects need not be identical.
