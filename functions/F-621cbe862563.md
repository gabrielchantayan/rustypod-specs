## Behavior

### Ordered memory operations

The established sequence is:

1. Write the first supplied four-byte value at offset `0xAC`.
2. Read the four-byte value at offset `0x90`.
3. Write that read value at offset `0xA4`.
4. Write the second supplied four-byte value at offset `0xA8`.
5. Return without an explicit result.

This order matters. The first supplied value is written before the source field is read. The second supplied value is written only after the copied value has been written.

The contract does not substitute offset order for execution order: although `0xA4` precedes `0xAC` in the layout, its write occurs later.

### Successful final state

If all accesses complete, the addresses denote ordinary distinct storage, and no external actor interferes:

- Offset `0xAC` contains the first supplied value.
- Offset `0xA4` contains the value obtained by the read at offset `0x90`.
- Offset `0xA8` contains the second supplied value.
- The routine does not directly modify the source field at offset `0x90`.
- No other memory write is shown.

The source field is sampled during execution, after the first destination write. Its value is not established as a snapshot taken at function entry.

The old contents of the three destination fields are not read by the shown operation. They do not control whether a write occurs. All three writes are unconditional along the normal path.
