# F-b6c3621512e1

## Purpose

F-b6c3621512e1 conditionally acquires storage, invokes an initial processing dependency, searches from a payload address, writes two words after the selected search position, and invokes a submission dependency.

The operation applies only when a 16-bit input field equals 8. Other values return 1 without calling dependencies.

Under consistent marker observations within each search iteration, the search selects the first matching candidate or stops at payload displacement 512 bytes. A missing marker does not itself cause failure: a nonmatching post-search comparison selects two zero replacement words, after which submission is still attempted.

The consistency qualification is essential. The supplied representation references the global marker three times within each iteration, for different parts of the termination decision. Those references cannot unconditionally be collapsed into one comparison. Behavior under inconsistent marker observations has no established bounded-search guarantee.

“Acquisition,” “payload,” “marker,” and “submission” describe the visible data flow. Their application-level meanings are inferred.

### Search: established marker-reference structure

The search starts at payload displacement zero. Each continuing iteration advances the candidate address by four bytes and the 32-bit displacement by four.

Within an iteration, the supplied representation first reads the current 32-bit candidate. It then contains three separate global-marker references, in this order:

1. A marker reference used to determine signed subtraction overflow for candidate minus marker.
2. A marker reference used to obtain the 32-bit candidate-minus-marker subtraction result.
3. A marker reference used for the candidate inequality check.

These are ordered references in the supplied representation. They do **not** establish three separate physical machine loads, nor do they establish that different values can actually be observed in the target environment.

The inequality check determines which arithmetic information governs termination:

- If the candidate differs from the third marker observation, the earlier candidate-related arithmetic information is replaced by the overflow and result information for displacement minus 512.
- If the candidate equals the third marker observation, the earlier candidate-related overflow information and subtraction result remain in use.

Termination occurs when the selected subtraction result’s negative-status boolean equals the selected signed-overflow boolean. With a coherent subtraction, that relation implements signed greater-than-or-equal comparison.

If the three marker observations differ, the retained candidate subtraction result and overflow information need not describe subtraction against the same marker value. Consequently, equality with the marker used by the inequality check does **not**, by itself, establish termination.

- A candidate equal to that iteration’s marker value terminates the search.
- Otherwise, displacement 512 terminates the search.
- Otherwise, the search advances by one 32-bit word.

## Side effects

### Direct memory effects

Every execution that reaches replacement performs two ordered 32-bit stores before submission. Search termination, not merely successful initial processing, is required to reach those stores.

There is no explicit rollback when submission returns zero. Whether the stores remain externally observable depends on storage lifetime and dependency behavior.

The function makes no explicit store through its input-object address, but input storage, acquired storage, and marker storage are not established to be disjoint.

Aliasing matters:

- The first destination store can affect the later read of the second replacement source.
- Either store can affect selectors subsequently reread for submission.
- A store may affect other overlapping state, including marker storage if such aliasing is permitted.

An equivalent contract must therefore preserve the source-read/store ordering rather than treating both replacement sources as an advance snapshot.

If execution fails to leave the search, the source does not provide an alternative finalization path.

The call discipline does not establish ownership. Acquisition might allocate, borrow, lock, or select existing storage. Finalization might release resources or perform another operation; no such interpretation is guaranteed.

F-3ba698310ee1 is called once on each reached applicable-input failure-return path, always with 0. It is not called on either success-return path.

No acquired address is explicitly returned to the caller.

## Acceptance examples

These are conditional static predictions, not executed tests. They assume valid reached accesses and normally returning dependencies. Search examples additionally state their marker-consistency conditions.

1. **Non-applicable input.** With discriminator other than 8, the result is 1. No dependency calls or direct payload stores occur.

2. **Acquisition failure.** With discriminator 8 and zero acquisition result, F-3ba698310ee1 receives 0 and the result is 0. Initial processing, submission, and finalization are not called.

3. **Initial-processing failure.** With nonzero acquisition and zero initial-processing result, no search or direct replacement occurs. Finalization precedes failure notification, and the result is 0.

4. **Stable first-word match.** If the marker and candidate remain stable through the first iteration and post-search comparison, and the first candidate equals the marker, replacement uses the input words. For nonaliasing storage, offset `0x1F4` supplies payload offset 4, then offset `0x1F0` supplies payload offset 8.

5. **Multiple stable matches.** With a stable marker and stable candidate storage throughout the search, the earliest matching candidate is selected. Later matches are not examined.

6. **Stable boundary match.** With no earlier match and a stable match at displacement 512, replacement destinations are offsets 516 and 520. The boundary match is accepted.

7. **Stable absence.** With a stable marker, no matching candidate through displacement 512, and a nonmatching post-search comparison, zeros are written at offsets 516 and 520. Submission still occurs; a nonzero submission result produces return value 1.

8. **Post-search mismatch.** Even after a search comparison selects a matching position, a later nonmatching post-search comparison selects zero replacements. Search-time equality alone does not determine replacement values.

9. **Submission failure.** After replacement, a zero submission result leads to finalization, failure notification, and return value 0. No explicit restoration occurs.

10. **Selector mutation.** If initial processing changes a selector and the change remains visible, submission receives the reread value, not the initial argument value.

11. **Inconsistent marker references.** If the third marker observation equals the candidate but the earlier observations produce retained arithmetic information satisfying the continuation condition, equality does not stop that iteration. This scenario must not be accepted as an unconditional first-match search or assigned the 129-candidate bound.
