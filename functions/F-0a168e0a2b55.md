# F-0a168e0a2b55

## Purpose

F-0a168e0a2b55 searches a three-slot pointer table for an entry whose comparison field matches a value derived from the call’s inputs. On a match, it increments a 32-bit field in the entry currently occupying that slot and returns the slot index. If no match is found, it requests construction of a new entry and attempts to place it in the first empty slot.

Successful normal returns are the unsigned 32-bit indices 0, 1, or 2. An unsuccessful insertion path returns the unsigned 32-bit sentinel 4,294,967,295. Some paths instead transfer control to a dependency identified as nonreturning.

The interpretation of the table as a small registry, the incremented field as a reference count, and the comparison field as an identity or name are inferred intent, not established semantics.

## Behavior

### Search order and temporary state

The function captures the global table base before searching. Both the comparison search and the later empty-slot search use that captured base; the global location supplying the base is not visibly reread.

Slots are examined in increasing index order: 0, then 1, then 2. For each slot, the function first reads its four-byte value.

An empty slot causes no comparison-helper calls. Search continues to the next slot. An empty slot does **not** cause immediate allocation or insertion: later occupied slots are still checked for a match.

For an occupied slot, observable operations occur in this order:

1. F-398e0e9a318a receives the local two-word region’s address and the first input argument.
2. F-44362605ab79 receives the same local-region address and returns a 32-bit value.
3. The field at offset 4 of the entry originally read from the slot is read.
4. F-4a6c0bf0740c receives that field value as its first argument and the preceding dependency’s result as its second.
5. F-289ec4311c64 is called without explicit arguments after the comparison returns, whether its result indicates equality or inequality.

A zero result from F-4a6c0bf0740c means a match. Every nonzero result means no match; its sign or magnitude has no further visible significance.

The visible body calls F-289ec4311c64 once for each occupied-slot comparison that reaches this point. It does not call that dependency for empty slots. This is not evidence of cleanup on abnormal exits from earlier dependencies.

### Matching an existing slot

After a zero comparison result and the subsequent call to F-289ec4311c64, the function rereads the matching table slot.

It then reads the 32-bit field at offset 12 of this reread entry address, adds one, writes the result back to the same field, and returns the slot index.

The slot reread is significant. The entry receiving the increment need not be the same entry whose offset-4 field was compared if a dependency or another actor changed the slot in the meantime. There is no visible check that the reread value is nonzero or unchanged.

The increment is a four-byte read followed by a four-byte write, not an established atomic operation. No bounds or overflow check is visible. For values whose addition is representable as a signed 32-bit integer, the update is unambiguous. Behavior at the signed upper boundary is documented_only: the supplied representation shows signed addition but does not establish the underlying overflow semantics sufficiently to promise wraparound.

The first matching slot ends the search. Later slots are not inspected by this invocation after that match.

### Constructing a new entry

Only after all three slots have failed to match does the function request a new entry:

- F-8157a180d901 is called with the size value 16.
- Its 32-bit result is passed as the first argument to F-1f63acf1354e.
- The original first input argument is passed as the second argument to F-1f63acf1354e.

There is no visible validation of the allocation result before construction.

The function next reads the 32-bit field at offset 12 of the address returned by F-1f63acf1354e. This read occurs **before** the visible test for whether that returned address is zero.

If the field is nonzero, the function searches the captured table again from slot 0 through slot 2. The first slot whose current value is zero receives the returned entry address, and that slot’s index is returned.

This is a fresh scan, not reuse of an empty-slot observation from the comparison phase. Consequently, insertion depends on the table contents at the time of this second scan.

The function does not visibly increment the new entry’s offset-12 field before publishing it. It requires that field to be nonzero and otherwise leaves its value unchanged.

If all three slots are occupied during this insertion scan, the function returns 4,294,967,295. No release of the newly constructed entry is visible on that path.

### Zero construction field

If the new entry’s offset-12 field is zero and its returned address is nonzero, the function calls F-6b7be1ef0488 with that address and then calls F-feee9156a257. The latter is identified in the supplied evidence as nonreturning. No ordinary result is established for this path.

If the returned address is zero, the offset-12 read has nevertheless already occurred. A null return therefore cannot be treated as a safely handled construction failure. Only if that read completes and produces zero does the visible branch structure proceed to the failure sentinel without calling these two dependencies. Whether such an access can complete in the target environment is unknown.

## Side effects

Direct writes by this function are limited to:

- Initializing the two local argument-copy words.
- Incrementing the offset-12 field of an entry reread from a matching slot.
- Storing a constructed entry address into the first currently empty table slot.

Dependencies may perform additional writes, allocate or release resources, change global state, or alter the table. Their absence of explicit table arguments does not establish that they cannot do so.

The function visibly requests allocation only after no slot matches. It does not visibly allocate on a successful match path.

Ownership is only partially observable:

- Existing entries are not explicitly released by this function.
- A newly constructed entry is published by storing its address in the table.
- The nonzero-address, zero-field construction path passes the entry to F-6b7be1ef0488 before the nonreturning call.
- A constructed entry rejected because the table is full has no visible release operation.

These facts do not prove ownership transfer, deallocation, or a leak. Such conclusions require dependency contracts and the surrounding ownership model.

No direct output, logging, or I/O operation is visible. Dependencies may have such effects.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, assume valid memory, normally returning dependencies, and no relevant mutation by dependencies or concurrent actors.

1. **First slot matches.** Slot 0 is occupied, its comparison returns zero, and its offset-12 field initially contains 7. F-289ec4311c64 runs before the field update. The field becomes 8 and the result is 0. Slots 1 and 2 are not searched.

2. **An early hole does not prevent reuse.** Slot 0 is empty and slot 1 matches. No comparison dependencies run for slot 0. Slot 1 receives the increment and the result is 1. No allocation is requested.

3. **All slots empty.** No comparison dependencies run. Construction is requested after all three slots have been inspected. If construction returns a valid entry with a nonzero offset-12 field, that address is stored in slot 0 and the result is 0. The function does not add one to the new entry’s field.

4. **Nonmatching occupied slots followed by insertion.** Slots 0 and 2 are occupied and compare nonzero; slot 1 is empty. Each occupied slot causes one complete comparison sequence, including F-289ec4311c64. If construction succeeds under the stated field condition, insertion uses slot 1 and returns 1.

5. **Full table with no match.** All three slots compare nonzero. Construction is still requested. If the new entry’s offset-12 field is nonzero and the table remains full, the result is 4,294,967,295. No explicit release of that entry occurs in the visible body.

6. **Table entry changes during comparison.** Slot 2 originally points to one entry, but a dependency replaces it with another valid entry before the post-match reread. If the comparison returns zero, the replacement entry’s offset-12 field is incremented and the result is 2.

7. **Invalid construction state at a nonzero address.** Construction returns a valid nonzero address whose offset-12 field is zero. F-6b7be1ef0488 receives that address, followed by F-feee9156a257. No ordinary return is expected.

8. **Null construction result.** A zero result from construction is not sufficient to predict a failure-sentinel return: the function first attempts the offset-12 memory read. The outcome depends on that access.
