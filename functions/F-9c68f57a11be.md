# F-9c68f57a11be

## Purpose

F-9c68f57a11be searches up to 201 indexed key positions in ascending index order. On the first observed key equal to the requested key, it obtains a four-byte payload, writes that payload to caller-supplied storage, and returns 1. If all 201 comparisons fail, it returns 0 without writing through the output argument.

The table base is held in an external reference. The function evaluates that reference separately for each key access and evaluates it again for the payload access after a match. It does not visibly capture or stabilize the base for the invocation.

With an unchanged table base and stable table contents, this is a first-match lookup over 201 eight-byte records. Duplicate keys do not cause an error; the earliest matching record supplies the payload. If the table reference changes during execution, the compared key and the selected payload need not come from the same table.

An identifier-to-value translation is **inferred intent**. The meanings of the keys and payloads are not established.

|---|---|
| 1 | A key comparison succeeded; the selected four-byte payload was written to the output destination before return |

No other normal error result is visible. A memory-access failure is not translated into return value 0 by the supplied body.

## Behavior

### Ordered search

The first comparison uses index 0. For each eligible index, the function obtains the table base from the external table reference, reads the key at that index’s eight-byte offset, and compares it with the input key.

A failed comparison advances the index by one. The function does not use key ordering to stop early, and it does not require a sorted table.

A successful comparison ends the search. At the matching index, the function independently evaluates the table reference again, reads the four-byte payload at that base plus the indexed record offset plus four bytes, writes the payload to the output destination, and returns 1.

After a failed comparison at index 200, the function returns 0. It does not perform a key access at index 201.

“First match” therefore means the first successful comparison in this ascending-index sequence. Under a stable base and stable contents, that is the earliest matching record in one table. Without those conditions, it is the earliest matching key observation across the accesses actually performed.

### Logical memory-access order

For each unsuccessful comparison, the represented access sequence is:

1. Read the external table reference to obtain a base.
2. Read the four-byte key at the current indexed offset.
3. Compare that key with the input and continue if unequal.

No payload read is expressed for a nonmatching index.

For a successful comparison, the sequence is:

1. Read the table reference for the key access.
2. Read and compare the indexed key.
3. Read the table reference again for the payload access.
4. Read the four-byte payload using this second base and the same index.
5. Write the payload to the output destination.
6. Return status 1.

The payload belongs to the same table record as the compared key only when the two base evaluations identify the same table storage. Even then, the key and payload are separate reads; no atomic record snapshot is established.

For success at index \(j\), where \(0 \leq j \leq 200\), the supplied representation expresses:

- \(j+1\) table-reference reads for key accesses.
- \(j+1\) key reads.
- One additional table-reference read for the payload access.
- One payload read.
- One four-byte output write.

Thus, success expresses \(j+2\) table-reference reads. An unsuccessful lookup expresses 201 table-reference reads, 201 key reads, no payload read, and no output write.

These are logical accesses in the supplied representation. They do not establish machine-instruction counts, hardware transaction widths, speculative behavior, atomicity, or whether a compiler may combine ordinary nonvolatile reads.

### Widths and arithmetic

The lookup key, key fields, and counter are represented as 32-bit integers. Payload reads, destination writes, and the return result are four bytes.

Equality determines matching. There is no visible normalization, masking, negative-key rejection, or special handling of zero. Signed ordering of keys is irrelevant to this comparison.

The counter starts at zero and increases only after a failed comparison. It reaches 201 as a termination value, not as an accessed record index.

The largest accessed record-start offset is \(200 \times 8 = 1600\) bytes. The last eligible payload begins at offset 1604 and occupies bytes through offset 1607. These counter and offset calculations do not approach signed 32-bit overflow.

The bounded offsets do not prove address validity. The base width, address arithmetic rules, and validity of each resulting address remain environmental matters.

### Failure and exceptional conditions

A missing key is an ordinary unsuccessful lookup: return 0, with no output write.

An unreadable table reference, inaccessible key or payload, or unwritable destination has no visible recovery path. The resulting fault, termination, or other platform behavior is **documented_only**, not a specified lookup result.

An unusable output destination is not accessed through the output argument on the no-match path. That conditional absence of access does not guarantee safety if the same storage is also involved in the table reference or searched data.

## Acceptance examples

These are conditional behavioral cases, not observed executions. Unless a case states otherwise, assume valid memory, an unchanged table base, and stable table contents.

### First eligible record matches

If index 0 contains the requested key, the function reads the table reference for that key access, reads it again for the payload access, writes index 0’s payload, and returns 1. It does not examine index 1.

### Last eligible record matches

If indices 0 through 199 do not match and index 200 does, the function performs 201 key comparisons. It then separately obtains the payload base, reads the payload at offset 1604, writes it, and returns 1.

### No eligible record matches

If all 201 eligible keys differ from the input, the function returns 0 without writing through the output argument. A matching key at index 201 does not change the result because that index is not examined.

### Duplicate keys

If indices 12 and 37 both match and no earlier index matches, index 12 supplies the payload and the function returns 1. Index 37 is not examined.

### Zero payload or negative key

A selected payload containing zero is written as zero and produces return value 1.

A negative input key can match an equal eligible key normally. No negative-key rejection appears.

### Base changes before the payload access

Suppose the key access at index 5 uses one base and observes a match. If the subsequent table-reference evaluation supplies a different base, and such a change has defined behavior in the execution environment, the payload is read from offset 44 of the second base.

The function does not recheck that second table’s key at index 5. It writes the payload obtained there and returns 1. This case does not establish a portable concurrent-update mechanism.

### Destination overlaps a searched key

If the destination designates a key field, that field’s existing bytes can participate in the search before any output write occurs. If a match is subsequently found and the overlap is valid, the selected payload overwrites the destination field. The status returned is 1.

This case demonstrates why “no explicit destination read” does not imply independence from destination contents under aliasing.

### Destination overlaps the table reference

If a valid four-byte output write overlaps the table-reference object, success can alter that object after the payload has been read. The function then returns 1 without rereading the reference. Consequences for later lookups depend on the resulting stored base representation.

### Unwritable destination

With no matching key, no access through the output argument occurs.

With a matching key and a readable payload, the function attempts the four-byte destination write. Normal completion and a specific fault outcome are not established.
