# F-9c4005934302

## Purpose

F-9c4005934302 publishes an opaque input word into indexed memory, performs an ordered sequence of dependency calls and width-specific memory accesses, updates global storage, and finally attempts a call to address zero.

The supplied static evidence does not establish an application-level purpose. Descriptions such as initialization, allocation, serialization, dispatch, or cleanup would add unsupported meaning. Repeated access layouts establish address calculations and data dependencies, not object types or ownership protocols.

This contract distinguishes:

- **Established static evidence:** represented accesses, call arguments, widths, ordering, and retained data dependencies.
- **Derived consequences:** numeric properties that follow from established unsigned widths and operations.
- **Inferred intent:** possible application meaning, which is not an acceptance requirement.
- **documented_only:** unresolved behavior requiring dependency contracts, platform information, or execution evidence.

No successful-result value is established. Completion is conditional on every preceding access and call completing, including the terminal call.

## Behavior

### Ordering and observability

The visible body contains no explicit branches or loops. It represents one ordered path, conditional on accesses succeeding and calls returning.

Calls are observable boundaries. Their effects on memory, globals, secondary outputs, allocation state, or control flow are unknown. A later represented read must not be replaced by a previously observed value merely because its address expression is unchanged.

Retained values and fresh reads are different contract elements. A value explicitly retained across calls continues to supply later calculations; memory explicitly read again supplies a new snapshot.

Repeated writes are separate events. No batching, rollback, atomic publication, or transactional behavior is established.

### Initial word publication

The first visible operation is a 32-bit store of the input word at four times the input selector plus 0x14.

After that store, a 32-bit word is read at offset 0x14 from an incoming base and logically shifted right by 19. The first dependency receives the input word, that shifted value, zero, and the input word again.

The store precedes the read. If their locations overlap, the read observes memory after the store, subject to platform memory behavior.

After several dependency calls, a returned selector determines another destination using the same four-times-selector-plus-0x14 layout. The input word is stored there unchanged. The following dependency receives four times that selector, without the additional 0x14.

### Byte-selected low-address writes

A recurring access pattern reads one unsigned byte from a calculated source and then writes one byte at 0x11 plus the byte value. Every such destination lies between 0x11 and 0x110 inclusive.

The intermediate value is a byte, not a full-width pointer.

The first two selecting reads use offset 1 from the second incoming base. Their respective stored values are:

- The low byte of a call-produced word shifted left by two.
- The low byte of that word masked to 30 bits and shifted right by 20.

Dependencies intervene, and the selecting byte is reread. The destinations need not match.

Later selected writes mostly store zero. Their selecting sources include returned bases, secondary outputs, masked and shifted words, scaled values, and address 1. Other selected writes store truncated call results or shifted retained words.

No flag, counter, tag, or ownership meaning is established.

### Early extraction and memory forwarding

An early call-produced word is masked to 30 bits and shifted right by 17 and by 7 to form separate derivatives. These feed later dependencies and selecting-address calculations.

A subsequent 64-bit result is split into low and high 32-bit halves. The high half is forwarded; the low half supplies later shifts and addresses.

Interleaved calls and selected byte clears surround these distinct accesses:

- An unsigned byte read at twice a retained word, forwarded in four argument positions.
- A 32-bit read at a retained word plus a high-bit-only contribution.
- A byte read at offset 0x0e from a secondary-output base, forwarded four times.
- An unsigned byte read at a retained returned base plus a secondary-output displacement, forwarded four times.
- A 16-bit read at a right-shifted word plus a previously read unsigned byte, forwarded four times.

The high-bit contribution is an unsigned 32-bit value shifted left by 31. It is either zero or 0x80000000, not an unrestricted displacement.

The halfword access remains 16 bits. Its byte order and argument-extension convention are unresolved.

One dependency receives the same stack-storage address in four argument positions. This establishes address exposure during that call, not initialization, storage size, ownership transfer, or permission to retain it.

### Indexed publication and offset-0x0d updates

Following the halfword sequence, a retained word shifted right by 19 is published into two 32-bit slots using four-times-selector-plus-0x14 destinations. The first selector is the high half of a 64-bit result; the second comes from a later dependency.

The low half of that result supplies the base for two byte stores at offset 0x0d. The first stores the low byte of the base shifted left by one. The second stores 4. Calls separate them.

Two word reads involving offset 0x44 have different layouts:

- Four times a returned word plus 0x44.
- That word masked to 30 bits, shifted right by 20, then increased by 0x44.

The second read does not include four-byte element scaling.

### Repeated indexed-word layouts

The middle and later portions use several distinct destination families:

| Destination layout | Represented stored values |
|---|---|
| Four times a selector plus 0x14 | Input words, scaled selectors, masked or shifted derivatives, retained words, widened bytes, and zero |
| Sixteen times a selector plus 0x14 | Usually four times that selector; later, a retained word |
| 256 times a selector plus 0x14 | Another retained word multiplied by four |

A common offset does not establish common allocation, element type, or stride.

Many sequences obtain a selector, publish a word using it, and then pass four times the selector to a dependency. Other sequences forward an unscaled secondary-output selector. These argument forms are not interchangeable.

Further publications include a 26-bit-masked value shifted right by 13, a scaled selector masked to 30 bits and shifted right by 19, and retained secondary-output values subjected to successive left shifts. Signed-looking overflow cases remain unresolved.

### Offset-0x24 state and offset-0x74 traversal

A later stage clears a word at offset 0x24 from a base formed by multiplying a selector by sixteen. It then reads the word at offset 0x74 from that scaled base and retains the result as a subsequent base.

A dependency-produced unsigned word is shifted right by 20. After intervening calls, that derivative is stored as a word at offset 0x24 of the subsequent base. The word at offset 0x74 of that base is then freshly read and forwarded.

The right-by-20 derivative is at most 0x0fff. Shifting that retained derivative right by 21 therefore yields zero. This consequence does not remove adjacent reads, writes, or calls.

Two byte-selected writes through offset 1 of the subsequent base occur around more dependencies: first a truncated masked-and-shifted value, then zero. Their selecting reads remain distinct.

Three later unsigned byte reads use offset 0x15 from separately supplied secondary-output bases. Calls intervene. The third byte is widened to 32 bits and published into an indexed word slot.

Another secondary output is masked to 29 bits and shifted right by 18. The resulting value is later shifted left by 13 and published as a word.

### Explicit zeros and low-address accesses

Several values are explicitly set to zero and later shifted or scaled without reassignment. Those particular derivatives remain zero.

Consequently, some selecting reads resolve to address 1, and some forwarded arguments are zero. A later ordinary byte read also resolves to address 1.

The byte at address 1 is not established as constant. It is repeatedly read, and dependencies or aliased writes may affect it.

Some byte-derived values are masked and shifted beyond their possible nonzero range. For example, a value already known to be an unsigned byte becomes zero when masked to 22 bits and shifted right by 12. Such deductions concern the retained value, not the stability of its original memory source.

### S-01 clearing and first snapshot

S-01 is explicitly cleared before a long sequence of dependencies, indexed stores, and traversals.

Its first later 32-bit snapshot is taken immediately after an indexed word publication in the late traversal, before the following dependency. Calls then intervene before the retained snapshot is shifted right by 23.

That shifted snapshot is supplied to a dependency alongside a separately derived traversal value. It is subsequently shifted right by 23 again. The twice-shifted result is zero for every possible unsigned 32-bit snapshot.

This establishes the derivative’s value, not the snapshot’s value. The earlier clear does not prove that this read returns zero: calls and possibly aliased writes intervene.

The zero derivative is later overwritten by another retained word. Its zero property must not be propagated into calculations using that replacement.

### Late traversal and repeated truncating transfers

One late byte clear uses a previously scaled selector, multiplied again by 0x2000, plus offset 9. A later base has its own offset-9 byte overwritten with the low byte of that base.

A word at offset 0x34 from that base is read and passed alongside the high half and a shifted low half of a 64-bit result.

Further word reads use offset 0x14 with retained bases, unsigned shifts, and masked secondary outputs. Indexed stores can precede these reads without intervening calls, so aliasing remains significant.

Later, a byte read from address 1 is retained and widened to form a base for selected low-address clearing and an offset-0x74 word read.

A call-produced 32-bit word is assigned to S-02 before the next dependency executes. After additional calls, the offset-0x74 word is read and its low byte stored at offset 1 of the corresponding base.

Similar word-to-byte transfers occur through other bases. One repeats the same source and destination expressions after intervening calls, requiring a fresh source read. Another retains the entire source word for subsequent 32-bit publications, including a sixteen-times-selector-plus-0x14 destination.

### S-01 second snapshot and dependent read

The second 32-bit snapshot of S-01 occurs later than the call-produced word publication to S-02.

More precisely, a dependency produces a 64-bit result; its high half selects an indexed word destination, and its low half shifted left by two is stored there. S-01 is then freshly read, before the following dependency.

This second snapshot is retained unchanged across several calls. After another indexed word publication, it becomes the base for a 32-bit read at offset 0x14. That read precedes the next dependency and supplies later truncated byte publications.

The address is the second snapshot plus 0x14, not the first snapshot, the earlier cleared value, or a fresh S-01 read at the time of use.

Neither snapshot’s value is established. S-01 and S-02 are distinct labels, not a guarantee of non-overlap or dependency preservation.

### Terminal composite and completion attempt

After the final dependency produces an 8-bit result, the procedure writes zero through a secondary-output pointer. This is a one-byte store.

Only after that store does construction of the composite read the three-byte component from S-03. There is no intervening represented dependency call. The pointer may alias S-03, so the read must reflect memory after the byte clear.

The freshly read 24-bit component supplies the upper 24 bits; the returned dependency byte supplies the low eight bits. The resulting **32-bit composite is assigned to S-02**, the same destination that earlier received the call-produced word.

This is a full 32-bit destination assignment. Component widths do not imply a partial-width store or preservation of S-02’s previous upper bytes.

A zero halfword is then stored at an address formed by masking a retained low result half to 30 bits and shifting right by 7. The procedure finally attempts the address-zero call with three zero arguments.

No rollback of preceding effects is represented.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Initial publication.** With input 0x89abcdef and selector 3, if accessible, the first store writes that word at address 0x20 before the initial dependency.

2. **Zero selector.** Selector zero selects address 0x14; no represented branch disables the write.

3. **Unsigned byte selection.** A selecting byte of 0xff produces destination 0x110, not a negative displacement.

4. **Fresh selector read.** If an intervening dependency changes a selecting source byte, the later selected store uses the newly read byte.

5. **Byte truncation.** A retained word of 0x3fffffff, masked to 30 bits and shifted right by 20, yields 0x3ff; a byte store writes 0xff.

6. **First S-01 snapshot need not be zero.** If its first snapshot is 0xff800000, the right-by-23 derivative is 0x1ff. Shifting that derivative right by 23 yields zero, regardless of S-01’s earlier clear.

7. **Second snapshot is retained.** If the second S-01 snapshot is 0x1000, its dependent word read uses address 0x1014. A later dependency changing S-01 to 0x2000 does not change that retained base.

8. **Fresh terminal component.** If the terminal pointer clear changes aliased S-03 so its subsequent three-byte read yields 0x112233, and the dependency byte is 0xaa, S-02 receives the full word 0x112233aa. Using the component’s pre-clear value is incorrect.

9. **No destination-byte preservation.** If S-02 previously held 0xdeadbeef, the composite in example 8 replaces it with 0x112233aa; its previous upper bytes are not preserved by this assignment.

10. **Truncating transfer.** An offset-0x74 word read of 0x123456ab supplies 0xab to its associated offset-1 byte store.

11. **Terminal failure.** If the address-zero call faults, preceding accesses and stores have already been attempted in order. No transactional undo is established.
