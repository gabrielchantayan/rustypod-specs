# F-459c146587b1

## Purpose

F-459c146587b1 forwards a 32-bit input to an indirect dependency, performs an ordered sequence of calls and address-derived memory accesses, initializes a six-word record, and invokes further dependencies. The supplied static representation ends at an instruction-decoding boundary; it does not establish a normal return.

No application-level purpose is established. Initialization, device configuration, and registration are possible interpretations, but none is supported strongly enough to define required behavior.

This contract distinguishes:

- **Established static evidence:** operations, widths, dependencies between values, and ordering visible in the supplied representation.
- **Inferred intent:** possible interpretations, not requirements.
- **documented_only:** unresolved behavior that cannot be determined from the supplied material.

Every later operation is conditional on earlier accesses completing and called dependencies returning. The representation does not establish that execution can reach the entire sequence.

## Behavior

### 1. Initial call sequence

The first indirect-call destination is derived by adding 4,094 bytes to the entry link value. That call receives the explicit input unchanged.

Five producer/consumer pairs follow, in order. Each pair consists of:

1. An indirect call with no explicit argument, producing a 32-bit value.
2. A separate indirect call receiving that value without an explicit transformation.

A consumer’s result is not explicitly consumed. Each consumer precedes the next producer.

After the fifth pair, one additional no-explicit-argument indirect call occurs. The auxiliary byte-sized register value exposed after that call supplies the first address calculation.

These are distinct call events. Similar destination calculations do not establish identical targets or interchangeable behavior. “No explicit argument” does not exclude implicit register, memory, or machine-state inputs.

### 2. First address-derived memory sequence

The following accesses occur in the represented order:

1. Widen the auxiliary byte, shift it left by two bits, and load one byte from the resulting address.
2. Widen that loaded byte.
3. Store the widened value as a 32-bit word at an address equal to that value plus 112.
4. Load a 32-bit word from an address equal to the same widened value plus 32.
5. Multiply the newly loaded word by \(2^{24}\), then store the 32-bit product at an address equal to that product plus 64.
6. Shift the loaded word from step 4 left by 25 bits. From that address, load a signed 16-bit quantity and sign-extend it.
7. Store the sign-extended value as a 32-bit word at an address equal to that value plus 312.
8. Multiply the sign-extended value by \(2^{16}\).
9. Store the 32-bit product at an address equal to that product plus 16.
10. Store a 16-bit zero at an address equal to that product plus 312.

Neither byte is explicitly unsigned. Values with bit 7 set therefore require a character-signedness interpretation before their widened values and derived addresses can be determined.

No null, range, alignment, overflow, or permission check is shown.

### 3. Repeated fixed-location reads and overlapping writes

First, a fixed-location 32-bit word is read and captured.

The next 32-bit store uses **two additional reads of that same fixed location**:

- One read supplies the destination calculation: its value plus 64.
- Another read supplies the stored word.

The relative evaluation order of those two reads is unresolved. Neither is established to equal the earlier captured value, and the two additional reads are not established to equal each other. The store must not be specified as using the initial capture for either purpose.

Subsequent operations instead use the original captured word:

1. Store its low 16 bits at an address equal to the captured word minus 304.
2. Extract its upper byte by an unsigned right shift of 24 bits.
3. Shift that extracted byte left by 17 bits to form another address.
4. Store a 32-bit word equal to the extracted byte multiplied by \(2^{16}\) at that address.
5. Store a 16-bit zero at the same address.
6. Read that address separately for a nested store’s destination and source. One read supplies the destination address; the other supplies the 32-bit value written there.

The final two reads have unresolved relative evaluation order. Without stable memory, they need not return the same value. A single-read interpretation would require an additional stability guarantee.

The 16-bit zero store overlaps the preceding 32-bit store. Under ordinary little-endian memory, it clears a halfword that was already zero. Under ordinary big-endian memory, it clears the halfword containing the potentially nonzero extracted byte. Device-memory behavior could differ from either ordinary-memory case.

### 4. Symbol-derived value and unresolved shift

The reset-associated symbol is converted to a 32-bit integer-like value. Using that value:

1. Store it as a 32-bit word at an address equal to itself plus 16.
2. Store an 8-bit zero at an address formed by multiplying it by 1,024 and subtracting 304.

No explicit memory load through the symbol precedes these operations.

Next:

1. Read another fixed-location 32-bit value.
2. Multiply it by \(2^{28}\), subtract 304, and load a signed 32-bit word from the resulting address.
3. Apply a represented signed right shift by 32 bits.
4. Store the resulting quantity as a 32-bit word at an address equal to itself minus 304.
5. Capture a first further fixed-location 32-bit value.
6. Capture a second further fixed-location 32-bit value.

The right shift by 32 is unresolved for the represented 32-bit operand. This contract does not replace it with a zero-bit shift, a sign-fill result, zero, or any particular instruction behavior.

The two later fixed-location captures are ordered: the first precedes the second. They remain distinct inputs to record initialization.

### 5. Derived quantities and preparation calls

Starting from the unresolved shift result, the representation derives a base through these arithmetic stages:

- Add four using an unsigned 32-bit operation.
- Retain only the upper four bits.
- Interpret that masked value as signed and shift it right by 24 bits.
- Multiply by 256.
- Subtract 304 and retain the low 16 bits.
- Shift the resulting nonnegative value right by four.
- Multiply by \(2^{16}\).

The signed right shift remains dependent on the target’s treatment of negative operands. The initial unsigned addition and masking do not resolve every later signed-arithmetic question.

A 32-bit word is loaded from the derived base plus 16. Two quantities are then formed from that loaded word:

- A **scaled quantity**, obtained by multiplication by \(2^{16}\).
- A **secondary base**, obtained by a left shift of 12 bits.

The following calls occur in order:

1. An indirect call receiving the derived base plus the scaled quantity.
2. An indirect call receiving the scaled quantity shifted left by five bits.
3. A first no-explicit-argument indirect call.
4. A second no-explicit-argument indirect call.
5. A third no-explicit-argument indirect call.
6. A fourth no-explicit-argument indirect call.

All four no-explicit-argument calls precede the record-address load. Their possible memory effects therefore affect what that subsequent load may observe.

### Independent fixed-location reads

Suppose the initial fixed-location capture is `0x00001000`. Suppose the later destination-calculation read returns `0x00002000`, and the source-value read returns `0x00003000`.

If those reads and the store complete, the 32-bit store targets `0x00002040` and writes `0x00003000`. It does not target `0x00001040` merely because the earlier capture was `0x00001000`.
