# F-04c06cd369a6

## Purpose

F-04c06cd369a6 conditionally configures a selected entry in a memory-mapped register bank, updates shared state, and returns a 32-bit result determined by the mode and size arguments.

**Established static behavior:** the function selects an entry using seven selector bits, selects a bank using an eighth bit, invokes F-ad34778f6370, updates a bitmap, writes an entry-control word, and performs mode-specific processing.

**Inferred intent:** the bank arrangement, entry stride, and size encoding suggest hardware-channel or endpoint configuration. No specific device protocol or hardware-field meaning is established.

Two paths terminate before configuration:

- A zero entry index returns 64 after capturing the shared-state base.
- A mode-1 ownership conflict returns `0xffffffff` after ownership checks but before either dependency or any direct write.

All behavior below describes the supplied static representation. No runtime tests have been performed.

## Interface

The function accepts five arguments and returns one unsigned 32-bit value.

| Argument | Width and interpretation | Role |
|---|---|---|
| First | Unsigned 32-bit address value | Configuration-object address; forwarded to F-ad34778f6370 and conditionally accessed at byte offsets `0x28`, `0x29`, and `0x2b`. |
| Second | Unsigned 32-bit value | Selector: bits 0–6 select the entry; bit 7 selects the bank. The complete value participates in ownership comparison. |
| Third | Signed 32-bit integer | Mode; forwarded to F-ad34778f6370 and shifted into the control word. Modes 0–3 have explicit result calculations. |
| Fourth | Unsigned 32-bit value | Original size or encoded size; forwarded unchanged twice before local decoding. |
| Fifth | Signed 32-bit integer | Mode-1 flag request. Exactly 1 sets the flag; every other value clears it. |

There is no explicit output buffer.

## Behavior

### 1. Capture the base and recognize a zero index

The function first reads the shared-state-base global and retains that base for the possible later flag write.

It then tests the selector’s low seven bits. If they are zero, it returns 64.

On this path:

- No dependency is called.
- The configuration object is not accessed.
- No ownership byte, flag byte, bitmap, or control word is accessed.
- The other arguments do not affect the result.

The entry-time global read still occurs, even though the captured base is not subsequently dereferenced.

### 2. Perform mode-1 ownership processing

For a nonzero index and mode exactly 1, the function performs this ordered sequence:

1. Reload the shared-state-base global.
2. Read the ownership byte at offset 9 through that freshly loaded base.
3. If that byte is nonzero, reload the global again and read offset 9 through this second freshly loaded base.
4. Compare the second byte, zero-extended, with the complete 32-bit selector.
5. If unequal, return `0xffffffff`.
6. Otherwise, or if the first ownership byte was zero, reload the global again and write the selector’s low eight bits to offset 9 through this newly loaded base.

The first ownership-byte read determines only whether the second read and comparison occur. The second read determines equality. If the first read is nonzero but the second read is zero, the request conflicts because a selector with a nonzero index cannot equal zero.

These accesses need not use the entry-captured base or the same base as each other. Neither stable global contents nor synchronization is established.

The comparison is full-width. A selector greater than 255 cannot equal any ownership-byte value. Such a selector nevertheless proceeds if the first ownership read is zero; its low eight bits are then stored.

The ownership write occurs before F-ad34778f6370 and does not depend on that dependency reporting success. Other modes perform no ownership-byte processing.

### 3. Call the configuration dependency

F-ad34778f6370 receives, in order:

1. The original first argument.
2. The original second argument.
3. The original third argument.
4. The original fourth argument.
5. The original fourth argument again.

The caller’s fifth argument is not forwarded.

The dependency’s signed 32-bit primary result contributes to the control word. No explicit success/failure branch follows the call.

The call precedes configuration-object reads, the bitmap update, local size decoding, and the control-word write. Its effects on memory or globals must not be assumed absent.

### 4. Select the bank and retained contribution

Bank selection and bitmap positioning use only the selector’s low eight bits:

| Selector bit 7 | Bank base | Bitmap shift count |
|---|---|---|
| Clear | `0x38400b00` | Index plus 16 |
| Set | `0x38400900` | Index |

For the bit-7-clear bank, the retained contribution is zero and no old control-word read occurs.

For the bit-7-set bank, after F-ad34778f6370 returns:

- Read the configuration-object byte at offset `0x2b`.
- If it is zero, read the selected 32-bit control word and retain only bits under mask `0x7800`.
- If it is nonzero, do not read the old control word; the retained contribution remains zero.

The optional control-word read precedes the bitmap update. Higher selector bits affect neither bank nor index, but remain visible to the dependency and mode-1 ownership comparison.

### 5. Update the bitmap

The function reads the 32-bit bitmap, ORs in a shifted contribution, and writes the result back to `0x3840081c`.

The shift count is the selected position reduced to its low eight bits. With nonzero indices, possible counts are:

- 1–127 for the bit-7-set bank.
- 17–143 for the bit-7-clear bank.

The reduction therefore does not make all counts valid for a 32-bit shift.

The shifted left operand is a **signed 32-bit literal 1**:

- Counts 0–30 have a defined portable signed-shift interpretation. Count 0 is not reached on this path.
- Count 31 shifts into the sign bit and requires target-level clarification.
- Counts 32 or greater are outside the operand width and also require target-level clarification.

No modulo-32 shift rule or particular hardware result is established for the latter cases.

This is a read-modify-write operation, not an established atomic update. Concurrent changes may be lost; no locking or synchronization is shown.

### 6. Decode the size

The original fourth argument produces a payload contribution and an effective size.

For values 0 through 1024 inclusive:

- Payload contribution equals the original value.
- Effective size equals the original value.

For values greater than 1024:

- Payload contribution is the low 11 bits.
- Bits 11–12 form a value from 0 through 3.
- The multiplier is that value plus 1.
- Effective size is payload contribution multiplied by the multiplier.

Consequently:

- Payload contribution is at most 2047.
- Multiplier is at most 4.
- Effective size is at most 8188.
- Bits above bit 12 do not contribute to the decoded quantities once this branch is taken.

These products fit within 32 bits. F-ad34778f6370 has already received the original size, not the decoded effective size.

### 7. Write the control word

The function writes one 32-bit word at the selected bank base plus `0x20 × index`.

The written word OR-combines:

- Mode shifted left by 18.
- F-ad34778f6370’s signed primary result shifted left by 22.
- The retained contribution.
- The payload contribution.

No explicit mask is applied to the mode or dependency result before shifting. No field-overlap validation occurs.

Both shifted inputs are represented as signed 32-bit integers. Portable signed-shift semantics require nonnegative operands and representable shifted results. In particular, modes 0–8191 and dependency results 0–511 satisfy those respective arithmetic bounds. Negative values and larger positive values require target-level clarification; the later unsigned OR operations do not establish defined semantics for an already-invalid signed shift.

The control write follows the bitmap update and precedes mode-specific processing.

### 8. Perform mode-specific processing

#### Mode 0

Return 64.

Unlike the zero-index path, this path has already called F-ad34778f6370, updated the bitmap, and written the control word.

#### Mode 1

Write the flag byte at offset 7 through the **entry-captured base**:

- Write 1 if the fifth argument equals 1.
- Write 0 otherwise.

Return ten times the effective size. The maximum established result is 81880, so this multiplication does not overflow 32 bits.

A change to the shared-state-base global does not redirect this flag write. It may, however, have redirected earlier ownership accesses. The captured object must remain valid through this later write.

#### Mode 2

After the control-word write:

1. Read the signed byte at configuration-object offset `0x28`.
2. Read the signed byte at offset `0x29`.
3. Construct a signed 32-bit mask equal to two raised to the second byte’s value, minus one.
4. Call F-d7be9cfb4000 with that mask and the unsigned effective size.
5. Form an unsigned candidate from the effective size multiplied by two raised to the previously captured first byte’s value, minus one.
6. Subtract the dependency’s signed 32-bit secondary result from the signed mask.
7. Convert that subtraction result to an unsigned 32-bit bound.
8. Return the smaller of the candidate and bound using unsigned comparison.

The first signed byte is captured before the dependency call and is not reread afterward.

For both power constructions, counts 0–30 yield defined portable signed arithmetic. Negative counts, count 31, and larger counts require target-level clarification. Zero effective size does not make an invalid shift valid.

The candidate multiplication has unsigned 32-bit arithmetic because the effective size is unsigned. If its mathematical product exceeds `0xffffffff`, it is reduced modulo \(2^{32}\).

The subtraction has different rules: **both operands are signed 32-bit integers, so subtraction occurs before conversion to unsigned**.

- A representable nonnegative difference converts without changing value.
- A representable negative difference converts modulo \(2^{32}\).
- A difference outside the signed 32-bit range is signed overflow. Unconditional wrapping subtraction is not established.

The dependency’s secondary-result interface remains unresolved.

#### Mode 3

Return the effective size shifted left by three, equivalent to eight times that size. The maximum result is 65504.

#### Other modes

If execution reaches the final mode selection, the returned value comes from an incoming machine value not represented among the five formal arguments.

No stable result or rejection code is established. These modes may also encounter unresolved signed-shift behavior earlier while constructing the control word.

## Side effects

The established direct access and call order is:

1. Read and capture the shared-state-base global.
2. For mode 1 with nonzero index, reload the global and read ownership.
3. If the first ownership byte is nonzero, reload the global again and read ownership again.
4. If ownership processing permits continuation, reload the global and write ownership.
5. Call F-ad34778f6370.
6. For the bit-7-set bank, read configuration offset `0x2b`.
7. Conditionally read the old control word.
8. Read and write the bitmap.
9. Write the selected control word.
10. For mode 1, write the flag through the entry-captured base; for mode 2, read offsets `0x28` and `0x29`, then call F-d7be9cfb4000.

Early returns truncate this sequence as described above.

There is no explicit rollback. In particular, the ownership claim precedes the first dependency.

The visible body contains no explicit allocation, release, or ownership transfer. Neither dependency is thereby guaranteed to preserve allocation lifetimes, globals, or memory contents.

Aliasing is not excluded. Earlier writes or dependency effects may change later reads, including through overlapping storage. Hardware-specific read or write effects are unknown.

## Acceptance examples

These are conditional static consequences, not executed tests. Unless an example concerns unresolved arithmetic, assume accessible storage, defined shifts, normal dependency returns, and no unstated mutations.

1. **Zero index:** selector `0x80` returns 64 for any mode and size. The entry-time global read occurs, but no object byte or register is accessed and no dependency is called.

2. **Ownership conflict:** mode 1, selector 5, first ownership read 6, and second ownership read 6 return `0xffffffff`. No ownership write or dependency call occurs.

3. **Distinct ownership bases:** suppose the entry capture and three ownership-related reloads identify four distinct valid objects. For selector 5, a nonzero first ownership byte and a second ownership byte equal to 5 permit continuation. The claim is written to the fourth object. The later flag write targets the entry-captured object, not any of the ownership objects.

4. **Full-width comparison:** selector `0x105`, mode 1, and ownership reads of 5 cause rejection. If the first ownership read is zero instead, the request writes ownership byte 5 and proceeds using index 5.

5. **Threshold decoding:** size 1024 produces payload and effective size 1024. Size 1025 takes the encoded branch but still produces payload and effective size 1025.

6. **Encoded multiplier:** size `0x1805` produces payload 5, multiplier 4, and effective size 20. Mode 1 returns 200; mode 3 returns 160.

7. **Encoded zero:** size `0x800` produces payload and effective size zero despite a nonzero original argument.

8. **Preservation:** selector `0x83`, configuration offset `0x2b` equal to zero, and old control word `0x12347800` yield retained contribution `0x7800`. No other old-word bits are retained.

9. **Exact flag predicate:** mode 1 with fifth argument 2 writes flag value 0. Only fifth argument 1 writes 1.

10. **Mode-2 positive bound:** offsets `0x28` and `0x29` equal to 2 and 3, effective size 2, and secondary result 2 produce candidate 6, mask 7, bound 5, and return 5.

11. **Mode-2 negative difference:** with the same bytes and size, secondary result 9 produces signed difference −2, unsigned bound `0xfffffffe`, and return 6.

12. **Mode-2 signed overflow:** mask 7 and secondary result −2147483648 require signed subtraction outside the signed 32-bit range. No wrapping bound or final return is established.

13. **Bitmap boundaries:** selector `0x9e` reaches count 30, whose shifted contribution is `0x40000000`. Selector `0x9f` reaches count 31; selector `0xa0` reaches count 32. Neither latter case has a specified portable bitmap result.
