# F-9bdd54e79178

## Purpose

F-9bdd54e79178 performs mode-dependent preparation, conditionally notifies an associated object, and conditionally executes a state-changing operation followed by virtual dispatches.

The established behavior has three phases:

1. When the mode is zero, invoke two dependencies and, depending on the second dependency’s result, invoke an object callback and another dependency.
2. If a captured associated object points back to the input object, notify that associated object with a value derived from the mode.
3. If a flag condition is satisfied on the input object or a captured related object, set a flag on the input object, invoke an operation, conditionally dispatch through the current related object, and set a flag on an object returned by a final callback.

These are structural descriptions. The supplied material does not establish application-level meanings such as destruction, activation, rendering, ownership transfer, or event delivery.

## Behavior

### 1. Zero-mode preparation

When mode is zero:

1. Invoke F-2318d06eb0b2 with the address 0xA4 bytes into the input object.
2. After that invocation returns, invoke F-a1a48bd3fbde with the input object.
3. If the second invocation returns a nonzero 32-bit integer:
   - Read the input object’s dispatch-table pointer and invoke its entry at offset 0x1C, explicitly supplying the input object.
   - After that callback returns, invoke F-20460d1f31d3 without explicit arguments.

A zero result from F-a1a48bd3fbde skips both the offset-0x1C callback and F-20460d1f31d3. It does not terminate this function.

A nonzero mode skips this entire preparation phase.

Later object-field accesses occur after these calls. Consequently, they observe whatever state is present when preparation finishes; the supplied evidence does not establish that preparation preserves any fields or object lifetimes.

### 2. Capture relationship pointers and conditionally notify

After preparation, or immediately when preparation is skipped:

1. Read the associated-object pointer at input offset 0x3C.
2. Read the related-object pointer at input offset 0x34.

These are distinct captured values. The related-object value captured here is the one used by the later flag gate.

If the captured associated-object pointer is nonnull, read its pointer field at offset 0x78. Invoke F-df6da5bd408b only if that field equals the input object pointer.

The invocation receives the captured associated object and a derived integer:

| Mode | Derived integer |
|---:|---:|
| 0 | 1 |
| 1 | 0 |
| 2 through 0xFFFFFFFF | 0 |

Thus, every nonzero mode produces the same notification value, but only mode zero executes the earlier preparation phase.

The source representation includes a subtraction from one and an unsigned comparison. The observable argument mapping above does not require interpreting values above one as negative modes. In particular, 0xFFFFFFFF is a nonzero unsigned mode and yields notification value zero.

There is no visible reload or revalidation of the captured relationship pointers before this notification. Its effects are otherwise unknown.

### 3. Evaluate the flag gate

After the possible associated-object notification, read the input object’s flags word at offset 0x48 and test mask 0x10.

- If mask 0x10 is set on the input object, proceed to the state-changing phase. The captured related object’s flags are not read for this gate.
- If mask 0x10 is clear and the captured related-object pointer is null, return.
- If mask 0x10 is clear and the captured related-object pointer is nonnull, read that object’s flags word at offset 0x48. Proceed only if mask 0x10 is set there; otherwise return.

The input flags are read after the possible notification, whereas the related-object pointer used by this gate was captured before it. If F-df6da5bd408b changes the input object’s related-object field, that replacement does not replace the captured pointer used for this gate.

An early return here does not undo earlier calls. Zero-mode preparation and associated-object notification may already have occurred.

2. Write that word with mask 0x20 set, preserving the other bits present in the value used for this update.

### 5. Conditionally dispatch through the current related object

After F-6d16652f2d03 returns:

1. Read the input object’s related-object field at offset 0x34 again.
2. If it is null, skip this phase’s callback.
3. If it is nonnull, read the word at input offset 0xA0 and test its least-significant eight bits.
4. If those eight bits are zero, dispatch through the current related object’s table entry at offset 0x128.

The related-object field is accessed again to obtain the dispatch target. It is not the earlier captured pointer used by the flag gate. No synchronization or stability guarantee is established for the repeated accesses.
