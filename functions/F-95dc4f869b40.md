## Behavior

### Arithmetic and conversion boundaries

The current seed and dispatch bias are signed 32-bit values. Their addition produces the selector only where the signed arithmetic has defined behavior. Likewise, entry-time additions and the initialization subtraction must not be treated as automatically wrapping modulo \(2^{32}\).

Selectors two and five have an additional boundary:

- Their routing expressions produce **unsigned 32-bit results**.
- These results are assigned to the **signed 32-bit current seed**.
- Results from zero through 2,147,483,647 are representable and retain their numeric value.
- Larger results require an unsigned-to-signed conversion whose behavior is not specified by the supplied evidence.

In particular, choosing an algebraically negative seed does not, by itself, establish that the next signed current seed is that negative value. Its unsigned routing result is outside the signed destination’s range.

Where a routing claim below relies on preserving a negative seed, it is conditional on a **target conversion model** that maps the unsigned result to the signed value with the same low 32-bit representation. Without that assumption, the out-of-range conversion remains implementation-defined and must not be replaced by a guaranteed seed value or next selector.

This issue is distinct from signed overflow, character narrowing, and signed right shift.

### Dispatch preparation

Every iteration performs the following preparation in the represented order:

1. Read the snapshot source and retain that iteration’s value.
2. Read the payload-address source.
3. Add the current seed to the captured bias to form the selector.
4. Read the default-seed source and install it as the provisional next current seed.
5. Execute the selected branch.

Even an iteration that returns has already performed the shared-source reads in this preparation.

A branch may replace the provisional next seed. The next iteration adds that seed to the captured bias; a seed is not itself a selector.

### Selector two: flag-based routing

The branch reads the unsigned 32-bit word at offset 12 and tests bit zero.

Its unsigned routing result is:

- When bit zero is set: the cached plus-three seed converted to unsigned 32-bit form.
- When bit zero is clear: the clear-flag seed converted to unsigned 32-bit form.

The expression uses arithmetic weighting rather than a short-circuit selection. The clear-flag seed remains an operand even when its contribution is zero; the representation does not support a conditional-read guarantee for that source.

The unsigned result is then converted to the signed current seed:

- A selected nonnegative signed seed is preserved numerically.
- A selected negative signed seed produces an unsigned result above 2,147,483,647. Preservation of that negative value requires the target conversion model described above.
- Without that model, the resulting signed seed is implementation-defined.

For example, an algebraically selected seed of −1 produces unsigned routing result 4,294,967,295. The source alone does not guarantee that assignment makes the current seed −1.

This branch does not write the flag word.

### Selector four: default routing

### Selector five: status-based routing

This branch contains two reads of the character at record offset 0. One participates in multiplication by 43 and the other in multiplication by −43. The products are combined using bitwise OR. The result is narrowed to a character, converted to a signed integer, shifted right by 31, and negated to form an unsigned 32-bit routing weight.

No single atomic status snapshot or relative evaluation order between the two status reads is established.

Under all of these assumptions:

- Characters are signed and eight bits wide.
- Character narrowing retains the low eight bits with two’s-complement interpretation.
- Negative signed right shifts extend the sign.
- Both reads observe the same status value.

the routing weight is zero for status zero and one for every nonzero status-byte pattern. Multiplication by 43 cannot turn a nonzero byte into zero modulo 256 because 43 is odd.

Under those assumptions, the unsigned routing result is:

- For zero status: the zero-status seed converted to unsigned 32-bit form.
- For nonzero status: the cached plus-two seed converted to unsigned 32-bit form.

That result is then assigned to the signed current seed. Nonnegative selected seeds are preserved. Negative selected seeds are preserved only under the stated target conversion model; otherwise the resulting signed seed remains implementation-defined.

The zero-status seed participates in the arithmetic expression even when its routing contribution is zero. No conditional-read guarantee is established.

If the character, narrowing, shift, or equal-read assumptions do not hold, the zero/nonzero simplification is not a required behavior. The represented arithmetic remains the evidence; no alternative routing rule is supplied.
