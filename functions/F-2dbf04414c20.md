# F-2dbf04414c20

## Purpose

The supplied static representation describes an indefinitely repeating sequence of indirect calls and memory updates. It does not establish a higher-level service, data structure, or device protocol.

The observable work consists primarily of:

- Obtaining 32-bit and paired 32-bit results from indirect dependencies.
- Scaling and truncating those results into addresses, stored words, stored bytes, and later dependency arguments.
- Updating locations at offsets `1`, `17`, and `20` from several different computed bases.
- Reading one externally named 32-bit storage location.
- Carrying selected results into the next iteration.

There is no represented normal return, loop termination condition, input validation, or explicit error result. The semantic meaning of the addresses and stored values is **documented_only**.

### Width and address notation

This contract uses mathematical labels to describe values, not implementation identifiers:

- **word**: 32 bits.
- **byte**: 8 bits.
- **low** and **high**: respectively the low and high 32-bit halves of a represented 64-bit result.
- **W(address)**: a 32-bit memory access.
- **B(address)**: an unsigned 8-bit memory access.
- **S(base)**: read `B(base + 1)`, zero-extend it, then use that value plus `17` as a byte-store address.

Thus, an operation through **S(base)** is a byte read followed by a byte write. It is not a pointer-sized load followed by a field access.

All products, left shifts, and address sums below describe their low 32 bits under a 32-bit machine-word interpretation. Stored bytes retain only the low eight bits. Logical right shifts apply to unsigned quantities.

The representation contains signed-looking shifts and products for which portable language-level overflow behavior is not established. The modular interpretation describes the apparent machine-width dataflow; exact instruction semantics remain **documented_only**.

For compactness:

- A **five-call group** contains five consecutive indirect invocations. Unless stated otherwise, only the first has explicitly shown arguments, and only the fifth supplies the result described.
- A **six-call group** similarly contains six consecutive invocations.

The routine then:

1. Forms the first carried word from four times that result’s low word.
2. Retains the high word as a second carried word.
3. Reads the byte at the inherited base plus `1`.
4. Writes the inherited byte to the selected address plus `17`.

Only after this store does the repeating body begin.

## Side effects

The local effects are ordered reads and writes of one or four bytes, interleaved with indirect calls. The body contains no represented allocation, release, lock operation, explicit barrier, exception handling, or rollback.

Important consequences:

- Selector reads are unsigned byte reads, limiting the selected byte-store destination to addresses `17` through `272`.
- The retained-selector word store can begin at any address from `20` through `275`; alignment is not guaranteed.
- Several computed bases can wrap or collapse to zero. No minimum-address guard is present.
- Repeated writes remain observable operations. They cannot be treated as redundant merely because an earlier store used the same value.
- Unknown dependencies may modify selectors, globals, or overlapping storage between local operations.
- The global snapshot is taken before F-000000000027, not after it.
- No failure recovery is represented. A fault or nonreturning dependency can prevent all later effects.

The specification does not grant the routine ownership of any touched memory.

## Acceptance examples

These examples are conditional static consequences, not runtime test results. Each assumes required calls return and all mentioned memory accesses succeed.

1. **Entry selector**
   
   If the initial selector read yields `7` and the inherited byte is `0xab`, the entry prefix writes one byte, `0xab`, at address `24`. It does not read a word-sized pointer from the selector location.

2. **First scaled word**
   
   If **P** is `3` and F-000000000002 yields `5`, **A** is `20`, and the first body word store begins at address `12308`.

3. **Byte truncation after masking**
   
   If **A** is `0x3ff00000`, the masked right shift yields `0x3ff`; the stored byte is `0xff`, not a ten-bit value.

4. **Repeated selector reads**
   
   If a dependency changes `B(K + 1)` between two selector-based zero stores, those stores can target different addresses. The routine does not cache that selector across the calls.

5. **Retained selector**
   
   If the selector retained after F-000000000025 is `9`, the later word store uses address `29`, even if F-000000000026 changes `B(Z + 1)`.

6. **Shift collapse**
   
   With 32-bit modular arithmetic, `C << 28` is zero for every **R**, because **C** is already `R << 14`. The corresponding dependency call still occurs.

7. **Direct-clear base**
   
   If **N** is `4`, **Z** is zero under the same arithmetic interpretation. The direct byte clears therefore address `17` and `1`, in that order.

8. **No normal completion**
   
   If every dependency returns and every memory access succeeds indefinitely, execution continues indefinitely. No represented input selects a normal return path.
