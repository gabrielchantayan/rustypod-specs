# F-ea36303687cb

## Purpose

F-ea36303687cb conditionally processes a pending state in a caller-supplied mutable record. A nonzero byte enables processing. When enabled, the function invokes an initial dependency, propagates any nonzero result, updates several record fields and an indirectly addressed byte, and may invoke a second dependency if the initial dependency produced a negative signed value.

Successful completion clears the enabling byte and a separate 32-bit field. An inactive record returns zero without calling either dependency.

The apparent intent is to complete a pending transition while synchronizing two working fields with two other fields. That interpretation is inferred. The established contract is the conditional calls, memory accesses, partial updates, and return behavior described below. The source does not establish the application-level meanings of the fields.

### Updates following initial success

If the initial dependency returns zero, the wrapper performs the following operations in this order:

1. It reads the address-bearing value at offset 72 and writes a single zero byte through that address.
2. It reads the 32-bit value at offset 40 and writes that value to offset 8.
3. It reads the 32-bit value at offset 44 and writes that value to offset 12.
4. It writes a Boolean value at offset 25: true if the local signed output equals zero, false otherwise.

The copies use values read after the initial dependency has returned. They are not guaranteed to match the values previously supplied to that dependency.

The indirect byte clear also precedes both copies. If its target aliases either source field, it can affect the value subsequently copied. Similarly, dependencies may have changed the record through aliases or other access. The contract therefore concerns the values present at the individual read points, not necessarily the entry values.

The Boolean write records the zero comparison performed before any optional second dependency call. No later refresh of this byte is shown.

### Negative-output branch

After those writes, the function tests whether the local signed 32-bit output is negative.

If the value is zero or positive, no second dependency is called.

If the value is negative, the function calls F-2f6a05274b3a with:

| Position | Supplied value |
|---|---|
| 1 | A fresh read of the 32-bit value at record offset 0. |
| 2 | Address of the same local signed output slot used for the initial call. |

If F-2f6a05274b3a returns nonzero, the function immediately returns that exact result. The indirect clear, the two copies, and the Boolean write have already occurred. There is no rollback.

If the second dependency returns zero, execution continues. The wrapper does not inspect the local output again, even if the second dependency modified it.

### Successful completion

When no second call is needed, or when the second call returns zero, the wrapper:

1. Writes zero to the one-byte enabling field at offset 32.
2. Writes zero to the 32-bit field at offset 104.
3. Returns zero.

These two clears are completion-only operations. They are skipped on either nonzero dependency return.

The enabling byte is not reread to decide whether processing should continue after the initial dependency. A dependency changing that byte does not itself cause a new wrapper-level gate check.

## Side effects

### Explicit writes

On the full enabled success path, the wrapper performs:

- One indirect one-byte zero write through the address read at offset 72.
- Two four-byte copies into offsets 8 and 12.
- One Boolean write at offset 25.
- One one-byte zero write at offset 32.

If the second dependency reports nonzero, only the first four operations have occurred. If the first dependency reports nonzero, none of these wrapper writes have occurred.

The established operation order must be retained when reasoning about such cases; treating all updates as simultaneous would be incorrect.
