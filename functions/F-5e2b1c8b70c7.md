# F-5e2b1c8b70c7

## Purpose

F-5e2b1c8b70c7 coordinates an invocation-local context, geometry records, conditional dependency calls, and a dynamically selected callback. One conditional path explicitly publishes four geometry components into the input object.

A dependency result gates the conditional processing. It does not establish whether rendering occurs: the implementations of the setup, processing, callback, and finalization dependencies are unavailable.

A track-and-thumb interpretation is **inferred intent**, not an established interface or rendering guarantee. The contract below describes accesses, calculations, and calls without assigning domain semantics to opaque dependencies.

Every normally completing path reaches two finalization calls. There is no explicit return value.

## Interface

### Input, result, and preconditions

The sole explicit input is an object address. The supplied representation uses four-byte integer slots, 32-bit geometry components, and 32-bit address-bearing fields.

There are no explicit null checks, bounds checks, access-validity checks, or error results. The caller must provide valid storage for every access reached. In particular, the first two selector evaluations require a full 32-bit object field, not merely an accessible byte. The callback path requires a usable dispatch table and callback entry.

Observable results comprise dependency invocations, reads, conditional object writes, and any effects performed by dependencies. No geometry is returned directly.

### Records and selector representation

A geometry record consists of four consecutive components, denoted `(a₀, a₁, b₀, b₁)`. Its first-axis extent is `b₀ − a₀`; its second-axis extent is `b₁ − a₁`. Units, endpoint conventions, and normalization are unknown.

Invocation-local storage includes a 68-byte context and separate geometry records for the initial result, first processing sequence, dependency-produced associated geometry, directly loaded associated geometry, and second processing sequence.

The three selector evaluations are not interchangeable:

- The first two read the **32-bit word** at `0x26C`, convert its value to plain character type, and compare the converted result with `1`.
- The third explicitly reads the **unsigned byte** at `0x26C`, promotes that value, and compares it with `1`.

These are source-level access distinctions, not claims about particular machine load instructions.

Equating the first two results with the addressed byte requires additional target assumptions: an eight-bit character representation, the least-significant byte stored at the lowest address, and a word-to-character conversion rule preserving the low eight bits. Plain-character signedness and out-of-range conversion behavior are not established. The supplied representation alone does not prove that all three evaluations select the same axis even if storage is unchanged.

### Global storage

Three distinct global locations supply opaque 32-bit values:

- **Default source**, read during each context selection.
- **First alternate source**, conditionally read during the first selection.
- **Second alternate source**, conditionally read during the second selection.

Distinct locations may contain equal values. Repeated reads need not return equal values.

## Behavior

### Setup and eligibility

The following calls occur in order:

1. F-a4c26c2b4842 receives the temporary context.
2. F-7fa874cbac7a receives the object and context.
3. F-960363c07b32 receives the object and initial-geometry destination.
4. F-2adbf0d1a289 receives the object and supplies an eligibility result.

A zero result proceeds directly to finalization. Initial geometry has already been requested, but the conditional geometry sequences, callback, and explicit publication are omitted. Effects of the executed dependencies remain unknown.

For a nonzero result, the function reads the flags and caches whether bit `0x02000000` is set. Later flag changes do not revise that decision. The set-bit case is called **proportional mode** here solely to describe the visible arithmetic.

### First geometry-processing sequence

The initial geometry is copied into the first processing record in component order. F-e84807520bd9 receives that record and two scalar arguments, both `1`.

The first selector evaluation then reads the 32-bit word at `0x26C` and converts it to plain character type:

- Converted value exactly `1`: replace the second-axis start from `0x0D4`, then the second-axis end from `0x1A0`.
- Any other converted value: replace the first-axis start from `0x0D0`, then the first-axis end from `0x19C`.

Unselected components retain their post-dependency values.

The first context selection reads, in order:

1. The default global source.
2. The full 32-bit state at `0x0C0`.
3. The first alternate source, but only if that state is nonzero.

The default read occurs even when its value is discarded. Any nonzero state bit suffices; the low byte need not be nonzero.

The function then invokes:

1. F-d06d54bfd78a with the context and selected value.
2. F-a7cb9e140c0e with the context and first processing record.
3. F-ca73cb512206 with the address of the publication area at `0x274`.

Only afterward is the associated-object field tested. Zero proceeds to finalization without the second selection or callback. Absence of later explicit publication does not imply an unchanged publication area: F-ca73cb512206 has already received its address.

### Second selection and associated geometry

A nonzero associated-object presence test enables another selection:

1. Read the default source again.
2. Read the full state again.
3. If nonzero, read and select the second alternate source.

Neither the first selection nor its state is reused. Intervening dependencies may change both.

F-d06d54bfd78a receives the newly selected value and context. The associated-object field is then read again and passed to F-756b664b4a2c with an associated-geometry destination.

After that call, the associated-object field is read once more. This newly obtained address supplies direct component reads at `0x80`, `0x84`, `0x88`, and `0x8C`, in that order.

Thus presence, dependency argument, and direct-load base involve three separate field reads. Their values may differ. There is no repeated null check protecting the latter uses.

The second selector evaluation reads the full 32-bit word at `0x26C`, converts it to plain character type, and compares the converted value with `1`. Exactly `1` selects second-axis components from both associated records; otherwise first-axis components are selected.

Define:

- **R**: selected extent of the dependency-produced associated geometry.
- **C**: selected extent of the directly loaded associated geometry.

Both are calculated by 32-bit subtraction. The second processing branch executes if signed **C < R**, or if cached proportional mode is set.

Otherwise, size calculation, second processing, and explicit publication are skipped. The callback still follows.

### Size calculation

On entering the second branch, the initial geometry is copied into a separate processing record.

The third selector evaluation explicitly reads an unsigned byte at `0x26C`. This byte value is retained for subsequent endpoint construction:

- Exactly `1`: read start **S** from `0x0D4`, then end **E** from `0x1A0`.
- Otherwise: read **S** from `0x0D0`, then **E** from `0x19C`.

This decision can differ from the preceding word-to-character decision because storage changed or because their representation semantics differ. **R** and **C** are not recomputed.

With proportional mode clear, size comes directly from a read of `0x2AC`. There is no comparison with the available span.

With proportional mode set, define **T** as the represented 32-bit difference **E − S**:

- If signed **R ≤ 0**, the candidate is zero; F-870c4fcf7295 is omitted.
- If signed **R > 0**, F-870c4fcf7295 receives the 32-bit product of **C** and the unsigned representation of **T**, together with **R**. Its result supplies the candidate.

The candidate, interpreted as signed, is compared with a read of `0x2AC`.

- If smaller, size comes from a **fresh read** of `0x2AC`. The upper comparison is bypassed.
- Otherwise, signed **T** is compared with the signed candidate. If **T** is smaller, size becomes **T**; otherwise the candidate is retained.

This is not an unconditional interval clamp. A selected threshold may exceed the span. Negative sizes and spans are not rejected. The threshold comparison and replacement are distinct source-level reads, although no dependency call separates them.

F-870c4fcf7295’s arithmetic is unknown. Division, rounding, saturation, and exceptional behavior must not be assumed.

### Position, processing, and publication

If **R** and **C** have equal represented values, the offset is zero and F-d7be9cfb4000 is omitted. Otherwise that dependency is invoked without explicit arguments, and its result supplies the offset.

Using the retained unsigned-byte selector:

- Selected-axis start becomes **S + offset**.
- Selected-axis end becomes **S + size + offset**.

The unselected components remain from the initial-geometry copy, subject to any dependency-mediated modification of accessible storage.

The state at `0x0C0` is read afresh and masked to its low eight bits. F-cf7ecaff2699 receives the context, second processing record, and masked state.

After it returns, the record’s **post-call** components are explicitly written in order:

1. `a₀` to `0x274`.
2. `a₁` to `0x278`.
3. `b₀` to `0x27C`.
4. `b₁` to `0x280`.

Changes made by that dependency through the record address are therefore included.

### Callback and finalization

2. F-282eebd7c413 with the context.

“Finalization” describes call position only. It does not establish cleanup, release, or rendering semantics.

## Side effects

Direct effects include the ordered accesses and calls above, temporary-record manipulation, and conditional four-word publication. The function reads, but does not directly write, the three identified globals.

Dependencies and the callback may modify globals, object fields, or address-passed storage. No preservation guarantee is available. Repeated object and global accesses must not be replaced in this contract by assumed stable values.

No explicit heap allocation, deallocation, or ownership transfer appears. Temporary storage is invocation-local. Passing its address establishes neither permission to retain it nor an obligation to release it; callee ownership and retention behavior remain **documented_only**.

Arithmetic is represented at 32 bits, without an explicitly widened multiplication or overflow checks. Extent ordering, threshold comparisons, and span comparisons use signed interpretations. The proportional product uses an unsigned span operand, so its unsigned 32-bit arithmetic must not be replaced by unbounded multiplication. Signed subtractions and additions may encounter overflow; conversions between signed and unsigned representations also matter. The source alone does not establish a universal wraparound rule for every expression.

There is no visible synchronization, rollback, or transactional publication. The four writes are not established as collectively atomic.

Invalid accesses and dependency failures have no specified recovery here. If a dependency or callback does not return normally, subsequent calls, including finalization, are not guaranteed.

## Acceptance examples

These are conditional static cases, not executed tests. Unless stated otherwise, dependencies return normally, produce the stipulated values, and leave relevant storage unchanged except for described effects. Arithmetic examples avoid overflow.

1. **Zero eligibility.** The four setup calls execute, followed by both finalization calls. Neither selection sequence, conditional processing, callback, nor explicit publication occurs. Effects of the executed dependencies remain unknown.

2. **Associated-object field zero at its test.** The first processing sequence and F-ca73cb512206 occur before the test. Finalization follows without the second selection or callback. F-ca73cb512206 may already have changed the publication area.

3. **Nonzero state in both selections.** Reads occur as default, state, first alternate, then later default, state, second alternate. Both default reads occur even if discarded.

4. **Changed default with zero state.** If the first default read yields `12` and an intervening dependency changes that storage to `34`, the two selection calls receive `12` and `34`. Neither alternate is read.

5. **Full-width versus masked state.** State `256` selects an alternate. If unchanged at second processing, its masked argument is zero.

6. **Direct size exceeds span.** With proportional mode clear, **C = 20**, **R = 100**, **S = 10**, **E = 30**, size `50`, and offset `3`, the branch executes and constructs endpoints `13` and `63`. No upper comparison reduces the size.

7. **Threshold bypasses upper comparison.** With proportional mode set, **T = 20**, candidate `4`, and both threshold reads yielding `30`, size becomes `30`, not `20`.

8. **Candidate exceeds span.** With proportional mode set, **T = 40**, candidate `80`, and threshold `10`, size becomes `40`.

9. **Equal extents.** With proportional mode set and **R = C**, second processing executes with zero offset and no F-d7be9cfb4000. With proportional mode clear, equality skips second processing. Both paths still invoke the callback after a successful presence test.

10. **Nonpositive proportional extent.** Signed **R ≤ 0** omits F-870c4fcf7295. Candidate zero still undergoes the threshold comparison and, unless bypassed, the span comparison.

11. **Changed associated-object address.** If F-756b664b4a2c changes that field, direct component reads use the newly read address without another null check.

12. **Post-call publication.** If F-cf7ecaff2699 replaces all four components, those replacements are published in order before the callback.

13. **Distinct selector evaluations.** At the first two evaluations, second-axis selection requires the **word-to-character result** to equal `1`. At the third, it requires the **addressed unsigned byte** to equal `1`; byte values `0`, `2`, and `255` select the first axis there. Applying this byte rule to the first two evaluations requires the representation and conversion assumptions stated above.

14. **Stable storage need not imply equal selector decisions.** Conditionally, on an eight-bit, most-significant-byte-first target whose word-to-character conversion retains the low eight bits, a stored word value `1` produces converted value `1` for the first two evaluations but addressed byte `0` for the third. The earlier extent choice is not recomputed when the third evaluation selects the other axis.
