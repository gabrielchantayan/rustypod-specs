# F-35926b73b212

## Purpose

F-35926b73b212 performs a staged, in-place update of destination storage using a source record, an explicitly supplied selector byte, and two inherited 32-bit values.

The update is not atomic. Destination writes precede validation, and explicit rejection leaves earlier writes intact. A normally completed successful path processes an auxiliary block, updates derived fields, increments an externally located counter, calls a final dependency, and returns zero.

“Configuration,” “auxiliary block,” and “completion notification” are inferred roles, not established application-level meanings.

Here, **a** denotes the low eight bits of A, and **b** denotes the low eight bits of B. Neither value is established to be zero, one, Boolean, or an address.

The selector is read after the first four stores, not at function entry. The captured selector controls the first dispatch even if destination `0x58` subsequently changes.

Each source field is read when its copy is reached. There is no whole-record snapshot. Overlapping storage can therefore make an earlier destination write affect a later source read.

### Selector-dependent fields

The captured explicit selector controls these changes:

| Selector | Destination changes, in order |
|---|---|
| `0` or `7` | Write a to `0x42`, then `0x43`; copy source bytes `0x30`–`0x33` individually to destination `0x5d`–`0x60`, in ascending order |
| `1`, `2`, or `5` | Write a to `0x42`, then `0x43` |
| `3` | Write a to `0x42`, then `0x43`; copy source bytes `0x2c`–`0x2f` individually to destination `0x59`–`0x5c`, in ascending order |
| `4` | Copy source byte `0x10` to destination `0x42`, then source byte `0x11` to destination `0x43` |
| `6` or any other byte | No writes in this stage |

No selector value causes rejection here. Unselected fields retain their contents unless affected through overlapping storage.

### Range gate and mode processing

The function reads source word `0x08` as unsigned, then writes a to destination byte `0x40`.

- If the captured range value is at most 8, destination word `0x3c` is not written by the range stage.
- If it is greater than 8, source word `0x08` is read again as unsigned.
  - A second value greater than 16 causes immediate rejection.
  - Otherwise, destination word `0x3c` receives B.

With stable source storage, 0–8 preserve `0x3c`, 9–16 assign B, and 17–`0xffffffff` reject. With changing storage, the second read is tested only against 16; it need not remain greater than 8.

Next, source word `0x0c` is read and compared with 1:

- Equality writes b to destination byte `0x41`.
- Otherwise, a is written to `0x41`, and source word `0x0c` is read again.
  - A second value other than 2 causes rejection.
  - A second value of 2 causes a signed 32-bit read, increment, and write of destination word `0x3c`.

Thus, mode 2 can increment pre-existing destination state when the range stage left `0x3c` unchanged. Signed-overflow boundary behavior is unresolved.

After mode processing succeeds, source word `0x0c` is read once more and copied to destination word `0x14`. This copied value need not equal either earlier observation if storage changes.

A byte is now read from source offset `0x00`. This discriminator is independent of the explicit selector.

| Source kind | Action |
|---|---|

| `7` | Read another external 32-bit constant and write it to `0x78`; continue |
| `2`, `4`, `6`, or any other byte | Reject with `0xffffffff` |

The constants’ numerical values and relationship are unknown. Rejection at this stage follows all earlier common writes but precedes both dependency calls.

### Auxiliary decision

For an accepted source kind, F-6d8c85350b66 is called with source base plus `0x40`. Its result is tested only for zero versus nonzero.

No assumption is made that the dependency preserves source storage, destination storage, or external data.

#### Zero result

The following writes occur in order:

1. Destination byte `0x28` receives a.
2. Destination words `0x2c`, `0x30`, `0x34`, `0x38`, `0x7c`, and `0x80` each receive A, in that order.

These are not necessarily zeroing operations.

#### Nonzero result: imports and optional scaling

Destination byte `0x28` first receives b. The function then performs these imports in order:

| Source offset | Destination offset | Width |
|---:|---:|---|
| `0x40` | `0x2c` | Word |
| `0x44` | `0x30` | Word |
| `0x48` | `0x34` | Word |
| `0x50` | `0x38` | Word |

The values imported from `0x44`, `0x48`, and `0x50` are also retained for possible scaling.

After the imports, destination byte `0x58` is reread. If it equals 7, the three retained values are shifted left by one and written to destination words `0x30`, `0x34`, and `0x38`, respectively, in that order.

The scaling decision uses the post-dependency destination byte, not necessarily the original selector. Scaling uses the retained imports, not fresh destination reads. The represented shifts have signed 32-bit operands; negative operands and results outside the signed representable range remain unresolved.

#### Nonzero result: derived arithmetic

After any scaling:

1. Destination word `0x78` is read once as unsigned 32-bit and retained as the arithmetic baseline.
2. Destination word `0x30` is read as signed 32-bit.
3. Their sum is written to destination word `0x7c`.
4. Destination word `0x34` is read as unsigned 32-bit for comparison with the retained baseline.
5. If that comparison value is strictly greater than the baseline, destination word `0x34` is read **again**, as unsigned 32-bit, and the baseline is subtracted from this second value.
6. Otherwise, the selected difference is zero and there is no subtraction read of `0x34`.
7. The selected difference is written to destination word `0x80`.

The addition is **unsigned 32-bit addition modulo \(2^{32}\)**. Although the `0x30` operand is read as signed, the other operand is unsigned 32-bit; the arithmetic conversions make the addition unsigned. A negative signed operand is converted to its unsigned value before addition. This wraparound is established and is not part of the unresolved signed-overflow behavior.

The subtraction also uses unsigned 32-bit operands and is calculated modulo \(2^{32}\). Its signed-typed intermediate does not make the subtraction signed arithmetic.

When both reads of `0x34` agree, the result at `0x80` is the unsigned difference floored at zero. That characterization is conditional:

- The first read determines whether subtraction occurs.
- Only the second read supplies its minuend.
- If the first value exceeds the baseline but the second is smaller, the subtraction wraps modulo \(2^{32}\), rather than yielding zero.

The `0x7c` write precedes both `0x34` reads. The retained baseline is not reread for subtraction and must not be assumed to equal its pre-dependency assignment.

### Successful completion

Both auxiliary branches converge on this sequence:

1. Obtain the externally supplied counter location.
2. Write a to destination byte `0x8c`.
3. Read the counter as signed 32-bit, increment it, and write it back.
4. Call F-266a29fc8dc5 with an externally supplied first argument and literal zero as its second argument.
5. Return `0x00000000` if that call returns normally.

The counter location is obtained before the `0x8c` write, but the counter value is read afterward. Aliasing can therefore affect the value incremented. The final dependency’s external first argument is obtained after the counter update.

There is one visible counter increment and one final dependency call per normally completed successful invocation. No atomic update or synchronization is shown.

## Side effects

### Partial updates and errors

There is no rollback:

- Range rejection follows the initial writes, selector-dependent writes, and destination-byte `0x40` write.
- Mode rejection additionally follows the write of a to `0x41` and may follow assignment of B to `0x3c`.
- Source-kind rejection follows the common state writes.

None of these explicit rejections reaches the auxiliary dependency, counter update, or final dependency.

The body provides no separate error result for dependency failures. A zero auxiliary result selects a normal branch, not an explicit failure return.

### Ownership and lifetime

There is no explicit allocation, release, or ownership transfer in this body. Copied words are uninterpreted 32-bit values; they are not established to be pointers.

The dependency contracts are unavailable. Either dependency’s retention of addresses, allocation, release, or mutation of shared storage remains unknown. A valid invocation requires accessed storage to remain usable for every operation actually reached; this body supplies no lifetime protection.

### Aliasing and changing storage

No non-overlap condition is checked. Source, destination, selector, external data, and counter storage may interact through overlapping addresses.

The ordered reads and writes are therefore significant, including:

- Selector capture after four destination stores.
- Repeated range and mode reads.
- Post-dependency imports and destination reads.
- The sum store before the comparison read.
- The separate comparison and subtraction reads of `0x34`.
- Counter-location capture before the completion-byte store.

These describe the supplied static access structure. They do not establish safe concurrent mutation, language-level race semantics, or hardware visibility guarantees.

## Acceptance examples

These are conditional static examples, not executed tests. Unless stated otherwise, accessed storage is valid and non-overlapping, values remain stable, dependencies return normally, and dependencies preserve the fields discussed.

1. **Range rejection.** With source word `0x08` equal to 17, the function returns `0xffffffff` after writing a to destination `0x40`. Mode processing and both dependencies are not reached.

2. **Upper accepted range.** With range 16 and mode 1, destination `0x3c` receives B and byte `0x41` receives b. Successful completion still requires an accepted source kind.

3. **Pre-existing state in mode 2.** With range 8, mode 2, and initial destination `0x3c` equal to 41, that word becomes 42. It is not first replaced with B.

4. **Mode rejection after mutation.** With range 9 and mode 3, destination `0x3c` receives B and byte `0x41` receives a before rejection. No counter update occurs.

5. **Independent discriminators.** Explicit selector 4 copies source bytes `0x10` and `0x11`. Source kind 0 separately accepts the record and assigns A to `0x78`.

6. **Late rejection.** If earlier gates pass but source kind is 2, the common state writes remain, the result is `0xffffffff`, and neither dependency is called.

7. **Zero auxiliary result with nonzero A.** If A is `0x12345678`, the zero-result branch assigns that word to `0x2c`, `0x30`, `0x34`, `0x38`, `0x7c`, and `0x80`; byte `0x28` receives `0x78`.

8. **Representable selector-7 scaling.** On the nonzero branch, if destination `0x58` remains 7 and the three retained imports are 3, 4, and 5, destination `0x30`, `0x34`, and `0x38` become 6, 8, and 10.

9. **Defined addition wraparound.** Without scaling, suppose destination `0x30` is read as signed −2 and the retained baseline is 5. The unsigned addition writes 3 to `0x7c`.

10. **Stable difference.** With baseline 10 and a stable `0x34` value of 7 or 10, destination `0x80` receives zero and no subtraction read occurs. With a stable value of 13, the second read occurs and the result is 3.

11. **Changing difference operand.** Conditional on an execution model allowing the two reads to observe different values, let the baseline be 10, the comparison read be 13, and the subtraction read be 7. Subtraction occurs and calculates `0xfffffffd` modulo \(2^{32}\), not zero. This example does not establish that unsynchronized concurrent modification is supported.
