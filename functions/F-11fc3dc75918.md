# F-11fc3dc75918

## Purpose

F-11fc3dc75918 resolves a metadata description for a node within a linked resolution context. Its primary result is a pointer-sized value used as a textual description. It can also return three associated metadata values through caller-provided output locations.

Established behavior includes:

- Dispatch on the node’s first byte.
- Lookup of a 32-bit key through a chain of contexts.
- Resolution against either a table-like descriptor or a projected expression.
- Recursive resolution through a constructed context.
- Optional publication of three secondary results.

The interpretation as type and column-origin metadata is inferred from the descriptor access patterns and the literal results `INTEGER` and `rowid`. The complete meaning of the structures and metadata fields is not established.

## Interface

### Inputs

The function has five arguments:

1. **Resolution context** — a pointer to a structure with at least these fields:
   - Offset 0: a pointer used to obtain connection-related state.
   - Offset 4: a pointer to the current lookup environment.
   - Offset 32: a pointer to a parent context.

2. **Node** — a pointer to a byte-addressed structure. Its first byte selects the behavior. Depending on that byte, additional fields are read at offsets 36, 40, or 56.

3. **First secondary-output location** — an optional pointer to a 32-bit result slot. This pointer also gates all three secondary-output writes.

4. **Second secondary-output location** — a pointer to another 32-bit result slot.

5. **Third secondary-output location** — a pointer to a slot receiving a pointer-sized value.

The source uses 32-bit words and converts pointers to signed integers for some comparisons and indexing. The contract therefore describes the apparent 32-bit representation. Portability to a different pointer width is not established.

### Results

The primary result is either:

- A null pointer;
- A pointer read from metadata;
- The literal `INTEGER`;
- A fixed, non-null static value whose contents are not supplied; or
- A result returned by a recursive invocation.

Although the declared return type is an integer pointer, the implementation uses the result as a character pointer. Textual interpretation is therefore supported by usage, not by the declared return type alone.

The secondary results begin as:

- First: zero.
- Second: zero.
- Third: null.

They may subsequently receive metadata or recursive results.

### Preconditions

A null node is explicitly supported.

For a non-null node, the context must be readable at offset 4. A null context with a non-null node is not handled safely.

Other required pointers depend on the selected path. There is no general validation of descriptor pointers, array bounds, output capacity, linked-context cycles, or recursion depth.

If the first secondary-output pointer is non-null, both other output pointers must also designate writable storage. They are written without independent null checks.

If the first secondary-output pointer is null, the other two output pointers are ignored for final publication. This does not suppress internal metadata resolution, dependency calls, or recursion.

## Behavior

### 1. Initial eligibility check

The function initializes its internal secondary results to zero, zero, and null.

It then evaluates the node and context:

- If the node is null, it returns null without reading the context.
- Otherwise, it reads the environment pointer at context offset 4.
- If that environment pointer is null, it returns null.

Both early returns bypass secondary-output publication. Existing caller output values remain unchanged.

Once this check passes, the function reads the node’s first byte.

### 2. Node kind `0x6e`: recursive resolution with a parent context

For node kind `0x6e`, the function obtains a descriptor pointer from node offset 56.

It reads:

1. A 32-bit environment value at descriptor offset 12.
2. A pointer from descriptor offset 0.
3. A pointer from offset 12 of that pointed-to object.
4. A 32-bit value from the start of the latter object, used as the recursive node pointer.

The function then constructs a temporary resolution context whose relevant fields are:

- Offset 0: the current context’s offset-0 value.
- Offset 4: the environment value obtained above.
- Offset 32: the current context pointer.

It invokes F-11fc3dc75918 recursively with that temporary context and the extracted node. The recursive invocation receives addresses of the current invocation’s internal secondary-result slots.

The recursive primary result becomes the current primary result.

The temporary context is local to the invocation. Its layout is established only to the extent of the fields consumed by this function; other fields are not established as initialized.

### 3. Node kinds `0x95` and `0x97`: context lookup

Both node kinds use the same path.

The function first reads the 32-bit value at node offset 40. Despite its pointer-shaped source representation, this value is subsequently treated as a signed 32-bit column index.

The lookup key is the 32-bit field at node offset 36.

Each searched context supplies an environment pointer at offset 4. Within that environment:

- Offset 0 contains a signed 16-bit entry count.
- Entries are addressed with a 48-byte stride.
- For entry index \(i\):
  - The matching key is at environment offset \(32 + 48i\).
  - A table-like descriptor pointer is at offset \(20 + 48i\).
  - A projection descriptor pointer is at offset \(24 + 48i\).

Entries are examined in increasing index order. For each candidate, the key comparison reads the node’s offset-36 field again rather than relying on an established immutable copy.

If no entry matches, the search continues at the context’s offset-32 parent pointer. The environment count and entries are then read from that parent’s environment.

The initial environment check applies only to the starting context. A subsequently reached parent with a null environment is not rejected before the environment is dereferenced.

The first matching entry controls resolution. Its two descriptor pointers are loaded, and the search does not proceed to a later matching entry or parent merely because the first match is unusable.

A notable exceptional case is a matching entry whose table-like descriptor pointer is null: the loop remains on the same context and searches it again. With stable memory, this produces nontermination rather than a missing-result return.

If the context chain ends without a usable match, the primary result is the fixed non-null static value whose contents are unavailable. The secondary results remain at their defaults.

### 4. Matched entry without a projection descriptor

If the projection descriptor is null, resolution uses the table-like descriptor.

The descriptor’s 32-bit field at offset 76 acts as an enablement gate:

- If it is zero, no further metadata is populated.
- If it is nonzero, column metadata is resolved.

When enabled, the signed column index is handled as follows:

- A nonnegative index is used directly.
- A negative index is replaced by the descriptor’s signed 32-bit field at offset 12.
- If the replacement is also negative, the primary result becomes `INTEGER` and the third secondary result becomes `rowid`.

For a nonnegative effective index, the function reads the column-array base pointer at descriptor offset 8. Column records have a 20-byte stride:

- Record offset 0 supplies the third secondary result.
- Record offset 8 supplies the primary result.

There is no visible upper-bound check on this index. Valid array extent is a caller or structure invariant, not a property enforced by this function.

After determining the primary and third results, the function copies the 32-bit field at descriptor offset 0 into the second secondary result.

It next reads the matched context’s offset-0 pointer:

- If null, the first secondary result remains zero.
- Otherwise, it invokes F-49f750c2c596 and uses its result to select an additional 32-bit metadata value.

The dependency receives:

1. The first 32-bit word of the object referenced by context offset 0.
2. The table-like descriptor’s offset-76 value, read for this call.

After the call, the function re-reads the context-derived pointer chain. It obtains an array base from offset 8 of the object reached through the first word of the context’s offset-0 object, then reads the first word of the array record selected by the dependency result. These records have a 24-byte stride.

That word becomes the first secondary result.

The dependency result is not visibly range-checked.

### 5. Matched entry with a projection descriptor

A non-null projection descriptor selects expression-based resolution instead of the table-metadata path.

Negative column indices produce a null primary result and default secondary results.

For a nonnegative index, the function reads a header pointer from projection-descriptor offset 0. The first 32-bit header value acts as the expression count.

The index is accepted only when it is strictly less than that count under the signed comparisons shown. In particular:

- Equality is rejected.
- An index greater than the count is rejected.
- Index zero is accepted when the count is positive.
- Zero is rejected when the count is zero or negative.

For an accepted index:

- Header offset 12 supplies an expression-array base pointer.
- Expression records have a 12-byte stride.
- The first 32-bit word of the selected record supplies the recursive node pointer.
- Projection-descriptor offset 12 supplies the recursive environment.

The temporary recursive context contains:

- Offset 0: the matched context’s offset-0 value.
- Offset 4: the projection environment.
- Offset 32: null.

The recursive call therefore does not inherit the matched context as a parent through this field. Lookup within any parent chain already embedded in other reachable structures is a separate matter.

The recursive primary and secondary results become the current results.

### 6. Other node kinds

Any first-byte value other than `0x6e`, `0x95`, or `0x97` skips resolution.

After the initial eligibility check succeeds, such a node produces a null primary result and default secondary results.

### 7. Secondary-output publication

All paths reaching the common completion point use the same publication rule.

If the first output pointer is non-null, writes occur in this order:

1. First secondary result.
2. Second secondary result.
3. Third secondary result.

If it is null, none of the three caller output locations is written.

This ordering matters for overlapping output locations. No non-aliasing validation is present. The two initial early returns are different: they perform none of these writes even when the output pointers are valid.

## Side effects

Directly visible writes are limited to local state and the three caller output locations. The function does not explicitly allocate or free memory.

The returned primary pointer and pointer-valued metadata are obtained from existing descriptors, static data, or recursive results. No copying is performed. The function provides no explicit ownership transfer or lifetime guarantee; callers must not infer permission to release these pointers.

F-49f750c2c596 may have side effects not described by the supplied evidence. In particular, it must not be assumed to preserve global state, descriptor contents, connection-related pointers, or memory ownership. Pointer chains used after that call are re-read.

The function provides no explicit error code, exception translation, or recovery path. Null results are ambiguous: they can indicate initial ineligibility, an unsupported node kind, disabled metadata, a rejected projection index, or a recursive null result.

Malformed structures can cause invalid reads, invalid writes, unbounded lookup, or unbounded recursion.

## Dependencies

### F-49f750c2c596

Used only on the non-projection table-metadata path when:

- The descriptor’s offset-76 value is nonzero; and
- The matched context’s offset-0 pointer is non-null.

Its return value selects a 24-byte metadata record.

Its semantic purpose, valid argument domains, return range, failure behavior, allocation behavior, and side effects are unknown.

### F-11fc3dc75918

Used recursively by node kind `0x6e` and by accepted projection references.

The two recursive paths differ materially in parent linkage:

- `0x6e` links the temporary context to the current context.
- Projection resolution sets the temporary parent field to null.

No cycle detection or recursion limit is visible.

## Acceptance examples

These examples are conditional on valid, stable structures except where a hazard is explicitly illustrated. They are static contract examples, not executed tests.

1. **Null node preserves caller outputs.**  
   Given a null node and prefilled output slots, the result is null and all output slots retain their previous values. The context need not be dereferenced.

2. **Null initial environment preserves caller outputs.**  
   Given a non-null node and a readable context whose offset-4 field is null, the result is null and outputs remain unchanged.

3. **Unsupported kind publishes defaults.**  
   Given an eligible context and a node with first byte `0x01`, valid enabled output slots receive zero, zero, and null, in that order. The primary result is null.

4. **Output suppression does not suppress work.**  
   Given a table-metadata path that requires F-49f750c2c596, setting only the first output pointer to null suppresses final output writes but does not prevent the dependency call.

5. **Parent lookup after a local miss.**  
   Given no matching local entry and a matching parent entry, metadata is resolved using that parent entry and its context-associated state.

6. **Null descriptor on a matching entry is not a normal miss.**  
   Given stable memory and a first matching entry with a null table-like descriptor, the function repeatedly searches the same context. It does not advance to the parent.

7. **Negative index with negative replacement.**  
   Given enabled table metadata, no projection descriptor, a negative node index, and a negative replacement index, the primary result is `INTEGER` and the third result is `rowid`. The second result still comes from descriptor offset 0; the first remains conditional on connection-related state.

8. **Projection bounds.**  
   Given a projection count of three, indices zero and two select expressions; index three does not. A negative index does not select an expression.

9. **Missing key has a distinct primary result.**  
   Given an acyclic chain with readable environments and no matching entry, the primary result is the fixed non-null static value, while the secondary results are defaults. Its textual contents are not established.

10. **Aliased output slots follow write order.**  
    If all three output locations refer to the same suitably sized storage, the third write determines its final contents. Such aliasing is not rejected.

## Uncertainties

### Inferred intent

The function appears to derive a textual type plus origin-related metadata for expression-like nodes. The table path, column-record fields, and `rowid` special case support this interpretation, but do not establish external structure names or a public API.

### Documented only

The following remain unresolved:

- The contents and semantic meaning of the missing-key static result.
- The full meaning of each secondary result.
- Complete structure layouts beyond accessed fields.
- String encoding, termination, and pointer lifetimes.
- Whether legal inputs exclude context cycles, recursive expression cycles, or null matching descriptors.
- Whether descriptor invariants guarantee valid column indices.
- Whether dependency results are always valid record indices.
- Whether arithmetic overflow is excluded by input invariants.

The arithmetic uses strides of 48, 20, 12, and 24 bytes. No explicit overflow checks are present. Exact behavior outside valid addressable ranges cannot be established from this representation alone.
