# F-c77f56a4934d

## Purpose

F-c77f56a4934d conditionally searches a count-prefixed sequence for a value captured from a context object. When sequence processing is permitted, an existing equal entry prevents local insertion; otherwise, the function stores the captured value in the next counted slot and increments the count.

Two preliminary gates can cause a direct return without sequence access. A third gate can lead to an unresolved indirect transfer instead of sequence processing. Successful search and insertion paths also end at unresolved indirect transfers.

**Established static behavior:** the visible body implements gated equality search and conditional insertion, with no local capacity check.

**Inferred intent:** the sequence resembles a collection of distinct identifiers or references. Neither that interpretation nor the business meaning of the context fields is established.

The contract describes local effects up to each unresolved transfer. It does not promise that a transfer destination preserves those effects, returns, or retains ownership of either input.

## Interface

### Inputs and representation

There are two recovered inputs:

| Input | Recovered representation | Required storage |
|---|---|---|
| Context | Address carried in a 32-bit integer-like input | Context fields reached on the selected path |
| Sequence | Address of unsigned 32-bit words | Count, inspected entries, and any insertion destination |

The context contains these relevant fields:

| Byte offset | Access width | Local role |
|---|---:|---|
| `0xB0` | 32 bits | Unsigned candidate, captured at entry |
| `0xB4` | 32 bits | Zero/nonzero gate |
| `0x80` | 16 bits | Unsigned discriminator controlling an indirect-transfer gate |

The sequence uses a count-prefixed layout:

| Word index | Byte offset | Meaning |
|---|---:|---|
| 0 | 0 | Unsigned 32-bit count |
| 1 | 4 | First counted entry |
| 2 | 8 | Second counted entry |
| \(n\) | \(4n\) | Last counted entry when the count is \(n>0\) |
| \(n+1\) | \(4(n+1)\) | Ordinary insertion destination for count \(n\) |

The insertion-offset formula assumes that index arithmetic has not wrapped and that address calculation remains valid. It is not a capacity guarantee.

The displayed types support a model with 32-bit unsigned count, candidate, and search-position operations, and a 16-bit unsigned discriminator. The complete target ABI, pointer representation, byte order, and alignment requirements are not independently established.

### Output

## Behavior

### Eligibility and access ordering

The candidate is the first visible context value read. Its unsigned 32-bit value is retained for subsequent comparisons and insertion.

A candidate below 2 causes direct return. Neither the other context fields nor the sequence are visibly accessed on that path.

For a candidate of at least 2, the next visible access is the 32-bit field at `0xB4`. A nonzero value causes direct return without discriminator or sequence access. The signed interpretation of this field does not affect its zero/nonzero test.

Only a candidate of at least 2 together with a zero field at `0xB4` reaches the discriminator gate.

The candidate is not refreshed during local sequence processing. Later changes to the original context field do not change the captured comparison or insertion value.

### Discriminator gate

The discriminator expression requires attention to integer promotion. Under the displayed types and ordinary 32-bit signed-integer promotion, the unsigned 16-bit value is promoted before subtracting `0x191`, which is 401 decimal.

The resulting subtraction ranges from −401 through 65,134. It does not overflow a signed 32-bit integer. Its result exceeds 4 exactly when the first discriminator value exceeds `0x195`, or 405 decimal.

Consequently, values below `0x191` do **not** take the transfer merely because they are below the subtraction constant. The promoted subtraction is signed rather than a wrapping unsigned subtraction.

The gate contains a short-circuited second read:

- When the first discriminator value is at most `0x195`, sequence processing follows without the second discriminator read.
- When the first value exceeds `0x195`, a second discriminator read determines whether the value is nonzero.
- A nonzero second value leads to an unresolved indirect transfer, with no preceding local sequence access.
- A zero second value permits sequence processing.

For stable fields, discriminator values from zero through `0x195`, inclusive, permit sequence processing. Values from `0x196` through `0xFFFF`, inclusive, select the discriminator-gated transfer.

These are access and evaluation properties of the supplied representation. They do not establish that an optimized executable issues two physical memory reads, or that unsynchronized changes between reads are supported.

### Counted search

Sequence processing searches counted entries in ascending order, beginning with word index 1.

Each search-bound decision reads the count and compares it with an unsigned 32-bit search position. If the position is below that observed count, the corresponding entry is read and compared with the captured candidate.

An equal entry ends the search and leads to an unresolved indirect transfer. Before that transfer:

- The equal entry is not rewritten.
- The count is not incremented.
- Later entries are not inspected.
- Existing duplicates are not removed.

An unequal entry advances the search position and permits another count check.

The count is not captured once for the whole operation. Each bound check uses a count read from sequence storage. This is an access property, not a synchronization protocol.

For stable storage, the search inspects at most the counted entries and stops at the first match. Storage beyond the counted region does not participate in duplicate detection.

### Insertion

Insertion occurs when the search position is greater than or equal to the count observed by the current bound check. With a stable count, this is the ordinary end-of-sequence condition.

The insertion destination uses a further count read. The function writes the captured candidate there before updating the count. The count update itself reads the count and then stores its incremented value.

For a stable count \(n\), adequate capacity, valid arithmetic, and a destination distinct from the count word, the state immediately before the ensuing transfer is:

- Entries 1 through \(n\) are unchanged.
- Entry \(n+1\) contains the captured candidate.
- The count is \(n+1\).

An initial count of zero reaches insertion without reading any entry. The candidate is stored at word index 1 before the count becomes 1.

The source does not establish one immutable count shared by search termination, destination selection, and count increment. If those reads observe different values, the ordinary append postcondition does not apply.

### Arithmetic boundaries and overlapping storage

Count, search-position, and sequence-index arithmetic use the recovered unsigned 32-bit model. Addition therefore wraps modulo \(2^{32}\).

An increment produces zero if its operand is `0xFFFFFFFF`. Likewise, a count of `0xFFFFFFFF` used to select the insertion destination makes the count-plus-one index wrap to zero.

That wrapped destination is the count word itself. If this case is reached with valid accesses and no intervening change:

- The candidate write overwrites the count word.
- The following count update reads that overwritten value.
- The resulting count is the captured candidate plus one, modulo \(2^{32}\).

It would therefore be incorrect to promise a final zero count solely because the count used for destination selection was `0xFFFFFFFF`.

This conditional consequence does not establish that such a sequence can be backed by valid storage or reached safely. Pointer arithmetic, object limits, and the required preceding entry accesses remain separate constraints.

Overlap between context and sequence is not prohibited by the supplied interface. Sequence writes can therefore alter context storage if the addresses overlap. The candidate remains the value captured before those writes; it is not reread.
