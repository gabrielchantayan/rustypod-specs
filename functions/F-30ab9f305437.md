# F-30ab9f305437

## Purpose

F-30ab9f305437 builds an object from parsed inputs, forwards selected entries into it, submits it to another object, and returns a status determined by the stages reached and two exact-success checks.

The established sequence is initialization, primary parsing, optional secondary parsing, two additional-source stages, final operations, and cleanup. “Configuration,” “source,” and “execution object” below describe data-flow roles. Their domain meanings are inferred, not established dependency semantics.

This contract describes normal returns and explicit operations in the supplied static representation. It does not guarantee dependency success, memory safety for invalid objects, or rollback of effects already performed.

## Interface

The first four saved words occupy consecutive 32-bit temporary-storage positions in argument order. In particular, the saved secondary auxiliary word immediately follows the saved secondary-input word.

The parser receives storage addresses, not merely input values. Mutation through these addresses is unresolved, including whether a dependency accesses adjacent words. The contract therefore does not equate saved words at later checks with their original argument values.

The adjacency is evidence about layout, not proof that a parser is permitted to access an arbitrarily large region. Required access extent is **documented_only**.

### Return value

The result is a 32-bit status:

- **1:** The saved primary-input word is zero at the post-initialization check.
- **0:** Every required stage succeeds, an execution object is nonzero, and both final operations return exactly 1.
- **3:** Every other visible normal-return failure.

The two final operations require equality to 1, not merely a nonzero result.

## Behavior

### Initialization and primary parsing

The function initializes status to 3, clears its tracked resource slots and distinguished-entry word, and copies arguments 1–4 into temporary storage.

It then calls F-5fc3a5236553 without explicit arguments. Only afterward does it inspect the saved primary-input word. A zero value returns 1 immediately, without configuration creation or parsing.

Otherwise, F-afd7fb396b2f obtains the configuration. A zero result returns 3 immediately. For a nonzero result, the function reads an opaque global word and writes it to configuration offset +0x1c.

The primary parser call to F-e2f82ac49d6f receives:

- A leading zero.
- The saved primary-input word’s address.
- The original argument-2 value.

A nonzero parser result is validated in this order:

1. Read its +0x10 word and inspect it through F-2eb743f270d1.
2. Continue only if the inspection result equals 0x16.
3. Read its +0x14 payload pointer and require nonzero.
4. Follow the payload’s +0x14 descriptor pointer, read descriptor offset +0x10, and inspect that word.
5. Continue only if the second inspection result equals 0x15.

Failure stops progression and leads to applicable cleanup. A nonzero parser result remains tracked even if validation fails.

### Primary traversal

The primary payload’s +0x08 collection is traversed from index zero.

Before each retrieval, F-10b760faca36 obtains the bound using the currently loaded collection pointer. If the signed bound exceeds the index, the collection pointer is loaded again and F-6bbddce1b930 retrieves that index.

At index zero, the returned word becomes the distinguished primary entry. At every later index, the returned word is passed to F-af72924a9125 with the configuration.

An empty collection leaves the distinguished entry zero and does not itself cause failure. No individual primary-entry cleanup is visible.

### Secondary processing

After primary traversal, the function tests the **current saved secondary-input word**.

If nonzero, it performs the first secondary parse. F-e2f82ac49d6f receives zero, the address of that saved word, and the **current saved secondary auxiliary word**. The result must pass the same validation as the primary result.

Its payload’s +0x0c collection is traversed from index zero. Every retrieved entry is passed once to F-1c9cf5ebca5d with the configuration, in that traversal’s index order.

After this traversal—or immediately if the first parse was skipped—the function tests argument 7. If nonzero, it performs the second secondary parse using the same saved-input address and the auxiliary word’s value at this later call. This parse is attempted even if the saved input is then zero. Its validation and traversal rules are identical.

Consequently:

- A zero saved secondary word at the first check skips the first parse.
- A nonzero saved word at that check requests the first parse.
- Argument 7 independently requests the second parse after successful preceding stages.
- Failure of the first requested parse prevents the second.
- A later parse may observe input or auxiliary values different from those used earlier.
- Each successful traversal forwards its own retrieved entries once. The two objects, collections, entry values, and bounds need not match.
- Duplicate forwarding is possible, but is not established merely by requesting two parses.

The two secondary parser results occupy distinct tracking slots. No deduplication or rollback is visible.

### Bounds and arithmetic

Indices and comparisons use signed 32-bit values.

For primary and secondary traversals, F-10b760faca36 is represented as returning 64 bits, but only its low 32 bits determine the signed bound. The upper half does not enlarge the collection range. Additional-source traversals likewise use a signed 32-bit bound.

A bound less than or equal to the current index ends that traversal. At index zero, a zero or negative bound retrieves nothing.

Bounds and collection pointers are reloaded; they are not stable snapshots. Dependency-driven changes can affect later iterations.

Under the visible progression, an increment occurs only while the index is below a signed bound no greater than 0x7fffffff. Therefore, the index cannot overflow: it can reach 0x7fffffff, but cannot increment beyond it. Assuming dependency calls return and do not corrupt traversal state, each traversal performs at most 2,147,483,647 retrievals. Continuously increasing bounds alone cannot make this signed-index loop infinite.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Primary rejection:** If the saved primary word is zero after initialization, initialization has occurred, the result is 1, and configuration creation is not attempted.

2. **Primary entry selection:** With a stable three-entry primary collection, the first retrieved entry becomes the distinguished final-operation argument. The other two are forwarded in order.

3. **Empty primary collection:** A zero signed bound leaves the distinguished entry zero. This alone does not prevent final success.

4. **Changed secondary selector:** If argument 3 was initially nonzero but the saved secondary word is zero at the post-primary check, the first secondary parse is skipped. With argument 7 zero, neither secondary parse occurs.

5. **Changed auxiliary storage:** If a first secondary parse or an intervening dependency changes the saved auxiliary word, a requested second parse receives the value present at its own call, not necessarily argument 4 or the first parse’s auxiliary value.

6. **Distinct secondary collections:** If the first traversal retrieves entries A and B and the second retrieves C, forwarding is A, B, then C. No repeated A or B is required.

7. **Zero input with forced second parse:** If the saved secondary word is zero at the first check and argument 7 is nonzero, only the second secondary parse is requested, using the storage contents at that call.

8. **Constructor changes globals:** If a source-global capture yields S, construction changes that global and changes the initialization global to T, initialization receives T second and the retained S third. It does not substitute the changed source-global value for S.

9. **Nondefault global read:** With argument 5 nonzero, the relevant source-global capture still occurs, although constructor and initializer calls do not.

10. **Cleanup affects second-source capture:** If immediate cleanup of the first parsed additional source changes the second source global, the second capture observes the value after that cleanup returns.

11. **Signed bound:** A primary count with low word 0x80000000 causes no retrieval at index zero, regardless of its upper 32 bits.

12. **Exact final gate:** A return of 2 from F-cd3cf16c4fbf suppresses F-eace0518d18e and leaves status 3. Exactly 1 from both final operations produces status 0, followed by cleanup.
