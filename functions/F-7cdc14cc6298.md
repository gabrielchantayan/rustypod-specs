# F-7cdc14cc6298

## Purpose

F-7cdc14cc6298 conditionally performs a transfer through an opaque dependency, limits the requested amount against a stored two-word boundary, and advances a two-word position by the resulting amount.

The established behavior is a gated, boundary-aware operation with an in/out amount and a four-value status result. Interpreting the opaque payload as a buffer, the position as a stream offset, or the boundary as an object length is **inferred intent**, not an established interface guarantee.

The function does not independently validate the context, the amount pointer, or the payload. Its result is determined by the entry gate, whether the initial request exceeds the boundary, and whether the transfer dependency changes the amount. A dependency’s return value alone does not determine the result.

### Preconditions

The context must permit the reads and writes reached by the selected execution path. The amount pointer must permit 32-bit reads and writes if the entry gate succeeds. The inactive path does not directly dereference the amount pointer.

No null checks, extent checks, alignment checks, or access-failure recovery are established. Requirements imposed by the dependencies remain additional, undocumented preconditions.

The extract does not establish that the amount word is disjoint from the context. The straightforward numeric interpretation below assumes disjoint storage and no intervening mutation. If storage aliases, the stated read/write sequence governs instead; writes through the amount pointer can alter later context reads.

## Behavior

### Entry gate

The function first reads the word at context offset +4 and tests it for zero.

- If that word is zero, it does not read the gate byte at +24.
- Otherwise, it reads that byte and tests it for zero.
- Unless both tests are nonzero, it returns 3 without directly reading or writing the amount word, advancing the position, or calling any of the three dependencies.

Any nonzero gate byte qualifies. Its signed interpretation is immaterial to this test.

### Initial endpoint calculation

On the active path, the function initially retains status 0.

It forms an endpoint using:

- The low position word at +16.
- The contribution at +8.
- The caller’s requested amount.
- The high position word at +20.
- Carries from two successive low-word additions.

Specifically, the low endpoint is the low 32 bits of the sum of the low position, the contribution, and the requested amount. The high endpoint is the high position plus the carry from adding the low position to the contribution, plus the carry from adding the requested amount to that intermediate low word.

Every word-sized result wraps modulo \(2^{32}\). The endpoint pair therefore represents the corresponding arithmetic modulo \(2^{64}\). There is no separate high-word contribution associated with the field at +8.

The function reads the boundary pair at +40 and +44 and compares the endpoint against it using unsigned high-word comparison followed, when necessary, by unsigned low-word comparison.

An endpoint exactly equal to the boundary is allowed without recording a boundary reduction. Only a strictly greater endpoint triggers that reduction. Because comparison follows wrapped arithmetic, overflow of the high endpoint is not separately detected.

### Boundary reduction

If the computed endpoint is strictly greater than the boundary:

1. The retained status becomes 2.
2. The function reloads both boundary words.
3. It writes a replacement amount through the caller’s amount pointer.

The replacement is the reloaded low boundary word minus the sum of the then-read low position and contribution, with the result reduced modulo \(2^{32}\).

This is a low-word subtraction. The function does not check whether the current effective position already exceeds the boundary, reject an underflow, or verify that the replacement endpoint now lies within the boundary.

For ordinary nonwrapping positions already at or below the boundary, this calculation can represent the remaining allowable amount. That interpretation requires those preconditions; it is not a general saturation guarantee.

### Preparatory dependency and loop

After any boundary reduction, the function reads:

- The mode at +32.
- The current amount through the caller’s pointer.

It captures the amount for later use and invokes F-d7be9cfb4000 with four 32-bit arguments, in this order:

1. The captured amount.
2. The captured mode.
3. The retained low boundary word.
4. The retained high boundary word.

The boundary arguments are the initially read pair when no reduction occurred, or the reloaded pair when reduction occurred.

The function also initializes a private temporary word to the finalization selector before this call. That value is overwritten with the captured amount before the temporary’s address is passed to the transfer dependency. Consequently, the selector is not the transfer dependency’s initial amount.

If the captured mode equals exactly 2, the function runs an empty loop whose unsigned 32-bit counter advances from zero while less than F-d7be9cfb4000’s returned unsigned 32-bit value. Other modes skip the loop.

The loop body contains no explicit memory access or dependency invocation. A delay-like purpose is inferred, not established. No duration or externally measurable timing guarantee follows from this extract.

### Transfer dependency and amount reconciliation

After the preparatory call and any loop, the function sets its private temporary amount to the previously captured amount. It then invokes F-16354eccf516 with:

1. A fresh read of the word at context offset +4.
2. The unchanged opaque payload.
3. The address of the private 32-bit amount temporary.

The dependency receives a pointer to this temporary, not the caller’s amount pointer directly.

On return, the function compares the temporary’s value with a fresh read through the caller’s amount pointer.

- If they are equal, the retained status remains unchanged. The dependency’s return value does not otherwise affect the status.
- If they differ, the retained status becomes 1 when the dependency returned exactly 1, or 3 for every other return value. The function then writes the temporary’s value through the caller’s amount pointer.

Thus an amount mismatch overrides an earlier status of 2. There is no second boundary check after the dependency changes the amount.

The comparison is not necessarily against the amount originally passed to the dependency: the caller-visible amount word is reread after the call and could have changed through aliasing or dependency side effects.

### Position advancement and optional finalization

The function next reads the current caller-visible amount and the current low position word at +16. It writes their modulo-\(2^{32}\) sum to +16.

It then reads the high position word at +20 and writes that value plus the carry from the low-word addition, again modulo \(2^{32}\), back to +20.

This advancement occurs on every active path that returns normally from the dependencies, including paths whose retained status is 1, 2, or 3. There is no error-based rollback.

If the original finalization selector is nonzero, the function then calls F-edc12d2b6d4e with the context address. It does not inspect a return value from that call. It finally returns the retained status.

The position used for advancement is read after the transfer call. It is not necessarily the position used for the initial endpoint calculation.

## Side effects

### Direct reads and writes

On a normal active execution, the significant ordering is:

1. Read and evaluate the entry gates.
2. Read fields and the requested amount needed for endpoint calculation and boundary comparison.
3. If required, reload the boundary and write a reduced amount.
4. Read and capture the mode and amount.
5. Call F-d7be9cfb4000 and, conditionally, perform the empty loop.
6. Read the current word at +4 and call F-16354eccf516 using the private amount temporary.
7. Reread the caller-visible amount; conditionally overwrite it and replace the retained status.
8. Read the current amount and low position; write the low position.
9. Read and write the high position using the low-addition carry.
10. Conditionally call F-edc12d2b6d4e.
11. Return the retained status.

The extract establishes these phase relationships, but not a portable ordering among every operand read within an individual arithmetic expression.

A boundary-adjustment write is visible before either dependency is called. A subsequent dependency-adjustment write is visible before the position update. The low position write precedes the high position read and write; the pair is not updated atomically.

### Ownership and dependency effects

The function performs no explicit allocation, deallocation, payload copy, or ownership transfer.

That does not establish what the dependencies do. In particular:

- F-d7be9cfb4000 is not known to preserve global or shared state.
- F-16354eccf516 may modify its private amount argument; other effects are unknown.
- F-edc12d2b6d4e is not established to preserve the context, retain it, release it, or avoid further position changes.

No thread-safety, reentrancy, lifetime, or pointer-retention guarantee is established. The function also provides no local recovery if a dependency fails to return normally or invalidates storage needed later.

## Acceptance examples

These examples are conditional static consequences, not executed tests. Unless stated otherwise, assume valid disjoint storage, no unmentioned dependency side effects, normal dependency returns, and an active entry gate.

### Inactive context

If the word at +4 is zero, the result is 3. The gate byte, amount word, boundary, and position are not directly accessed afterward, and no dependency is called.

If the word at +4 is nonzero but the gate byte is zero, the same result and absence of subsequent direct effects apply.

### Request within the boundary

With position 100, contribution 20, request 30, and boundary 200, the endpoint is 150. No reduction occurs.

If F-16354eccf516 leaves its amount at 30, the function returns 0 and advances the stored position from 100 to 130. The contribution participates in the boundary calculation but is not added to the stored position during advancement.

This return remains 0 even if the dependency returns a value other than 1, provided the observed amounts are equal.

### Exact boundary

With position 100, contribution 20, request 80, and boundary 200, the endpoint equals the boundary. The function does not record status 2.

If the dependency leaves the amount unchanged, the result is 0 and the stored position becomes 180.

### Boundary reduction

With position 100, contribution 20, request 90, and boundary 200, the endpoint is 210. Before either dependency call, the caller-visible amount becomes 80.

If the transfer temporary remains 80 and no other amount mutation occurs, the result is 2 and the stored position becomes 180, irrespective of the transfer dependency’s return value.

### Dependency changes the amount

Continue the preceding example, but let F-16354eccf516 change its temporary from 80 to 50.

- If it returns 1, the function returns 1.
- Otherwise, the function returns 3.

In either case, the caller-visible amount becomes 50 and the stored position becomes 150. The earlier boundary status is replaced.

### Dependency increases the amount

With position 100, contribution zero, request 10, and boundary 120, suppose the transfer dependency changes the amount to 50 and returns 1.

The function returns 1, reports amount 50, and advances the position to 150. It does not reapply the boundary limit.

### Low-word carry

With position high word 7 and low word 4,294,967,294, an eventual amount of 3 produces low word 1 and high word 8, assuming no intervening mutation.

### Underflowing reduction

With position 300, contribution zero, request 1, and boundary 200, the initial endpoint exceeds the boundary. The replacement amount is 4,294,967,196, not zero.

If the dependency preserves that amount, the function returns 2 and advances the position by that large amount. This demonstrates why the boundary reduction must not be specified as unconditional saturation to a nonnegative remainder.

### Finalization selection

A zero selector suppresses F-edc12d2b6d4e. Any nonzero selector requests it after position advancement, regardless of the retained status. The inactive path never reaches it.
