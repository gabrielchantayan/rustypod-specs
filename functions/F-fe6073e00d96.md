# F-fe6073e00d96

## Purpose

F-fe6073e00d96 performs an ordered series of memory reads and writes using three ambient address-bearing values, several fixed-address globals, and addresses obtained from memory. It then invokes an unresolved indirect target with four arguments.

The established behavior is memory mutation followed by indirect dispatch. The supplied static representation does not establish a higher-level purpose, such as initialization, list manipulation, device control, or message processing. Field names and object types therefore remain unspecified.

The order of access is material. Several locations are written repeatedly, and writes may affect subsequent reads through aliasing. A contract expressed only as final field values would omit observable behavior.

## Interface

### Explicit arguments

The represented interface has four explicit arguments:

| Position | Width | Established use |
|---|---:|---|
| First | 32 bits | Not referenced by the represented body. |
| Second | 8 bits | Written to a fixed-address byte location near the beginning of execution. |
| Third | 32 bits | Not referenced by the represented body. |
| Fourth | 8 bits | Written to two address-relative byte locations. |

No return value is represented. Normal completion occurs only if the indirect target returns and execution reaches the final return.

The absence of a represented use of the first and third arguments does not establish that they are irrelevant to an unrecovered calling convention or to the indirect target’s ambient state.

### Ambient inputs

Three incoming values are used without being established by the explicit arguments:

- **A:** a 32-bit unsigned value used as an address base, a full-width stored value, a byte-valued source, and a shift-count source.
- **B:** an integer/address-bearing value used as an address base and a byte-valued source.
- **C:** an integer/address-bearing value used as an address base and a full-width stored value.

The represented operations treat B and C as 32-bit integer/address-bearing quantities. Their actual calling-convention roles are not established.

A callable interface consisting only of the four explicit arguments is therefore incomplete. A caller must also arrange the required ambient state.

This contract uses:

- **Halfword:** 16-bit access.
- **Word:** 32-bit access.
- **Low byte:** the least significant eight bits of a value.
- **Base + offset:** an effective address, not a declared structure member.

The offsets describe accessed storage, not proven object boundaries or allocated object sizes.

Four fixed-address locations are relevant:

## Behavior

### Ordered access contract

The following sequence describes the represented accesses. Names for captured values identify snapshots: once captured, a value is retained even if its original memory location is subsequently overwritten.

An access that faults or otherwise fails can prevent all later steps. There is no represented rollback.

#### 1. Capture initial values

In order:

1. Read a word from G-source. Call this snapshot **S**.
2. Read a word from C + 0x14. Call this snapshot **T**.
3. Read a word from A + 0x04. Call this snapshot **U**.

These reads precede all represented writes.

#### 2. Perform initial byte writes and record C

In order:

1. Write the second explicit argument to G-input.
2. Write the low byte of A to C + 0x0D.
3. Write byte value 0x6C to A + 0x08.
4. Write the low byte of B to A + 0x0D.
5. Write the low byte of B to A + 0x09.
6. Write the full-width value C to C + 0x54.
7. Write the low byte of S to G-byte.

These writes are not interchangeable. For example, if A and C are equal, the writes at offset 0x0D target the same byte, with the B-derived byte written second.

#### 3. Read C-relative state and perform intermediate writes

In order:

1. Read a word from C + 0x44. Call this snapshot **L**.
2. Read G-byte and write the resulting byte to G-copy.
3. Write the low byte of L to A + 0x10.
4. Write L as a word to B + 0x54.
5. Shift L right using the low byte of A as the shift count, then write the low byte of the represented result to C + 0x01.
6. Write A as a word to B + 0x54, replacing the earlier word at that address when ordinary memory semantics apply.
7. Read a word from A + 0x40. Call this snapshot **M**.

The shift operates on a value represented as a signed integer. The result for negative L, and for counts outside the ordinary 32-bit operand range, cannot be specified portably from the supplied evidence. No explicit shift-count validation or normalization is represented.

The first write to B + 0x54 is still part of the contract even though the same address is written again. It may be observable through memory-mapped storage, instrumentation, or aliasing with C + 0x01.

#### 4. Copy saved and newly read words

In order:

1. Write U as a word to B + 0x74.
2. Write M as a word to A + 0x10.
3. Write C as a word to B + 0x44.
4. Read G-byte and write that byte to A + 0x09.
5. Write the low byte of A to C + 0x09.
6. Write S as a word to A + 0x44.
7. Read a word from A + 0x54. Interpret it as an address-bearing value **P**.

The word write to A + 0x10 covers offsets 0x10 through 0x13. Under ordinary memory semantics, it replaces the earlier byte write at A + 0x10. That earlier byte write remains an actual access.

P is read after all preceding writes. If any preceding destination aliases A + 0x54, P reflects the resulting memory state rather than necessarily the entry-state value.

#### 5. Write through P and restore a captured C-relative value

In order:

1. Read G-byte again and write that byte to A + 0x09.
2. Write the fourth explicit argument to P + 0x0D.
3. Write T as a word to C + 0x54.
4. Read a word from A + 0x14. Call this snapshot **N**.
5. Write the fourth explicit argument to C + 0x11.
6. Write the low byte of P to A + 0x09.
7. Write P as a word to A + 0x44.

The two G-byte reads used for A + 0x09 are distinct reads. They are not guaranteed to produce the same byte if intervening writes alias G-byte or if external memory behavior permits changes.

The write to C + 0x54 uses the early snapshot T. It does not reread C + 0x14 at this point.

#### 6. Access memory through a C-derived address

In order:

1. Read a word from C + 0x04. Interpret it as an address-bearing value **D**.
2. Write halfword value 0x0065 to the absolute effective address calculated as twice D.
3. Read a word from D + 0x64. Call this address-bearing value **E**.
4. Write the low byte of N to P + 0x11.
5. Write word value 100, equivalently 0x00000064, to P + 0x54.
6. Read a word from D + 0x74. Call this snapshot **V**.

The doubled address is twice D itself. It is not C + twice D, nor a location relative to another established object.

The halfword store writes two bytes. Their byte order is not established by the supplied representation.

#### 7. Perform final local writes

In order:

1. Read a word from C + 0x64. Interpret it as an address-bearing value **Q**.
2. Write the low byte of D to C + 0x09.
3. Write E as a word to Q + 0x54.
4. Write Q as a word to the absolute effective address calculated as twice E.

The final doubled-address store is a word store, unlike the earlier halfword store at twice D.

E and Q are read at their stated positions. In particular, the earlier halfword write at twice D can affect E if the accessed regions overlap. Likewise, the write of 100 to P + 0x54 can affect the later read of Q if those regions overlap.

#### 8. Invoke the indirect dependency

Invoke the unresolved indirect target, labeled **F-unknown-01**, with these four argument values in order:

1. 0x00000072.
2. E.
3. T, the early snapshot from C + 0x14.
4. V, the later snapshot from D + 0x74.

If the target returns normally, the represented body returns without further explicit memory accesses.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless a case explicitly discusses overlap, assume ordinary readable/writable memory, no relevant aliasing, no concurrent changes, valid arithmetic, and a callable indirect target.

### Captured values survive source-memory changes

Suppose C + 0x14 initially contains 0x12345678.

The function must capture that word before any writes. It must later write 0x12345678 to C + 0x54 and supply 0x12345678 as the third indirect-call argument, even if the original C + 0x14 storage changes in between.

This criterion concerns the function’s captured value. It does not constrain subsequent changes made by F-unknown-01.

### Byte arguments remain distinct

With the second argument equal to 0xA5 and the fourth equal to 0x3C:

- The early write to G-input must contain 0xA5.
- The designated writes to P + 0x0D and C + 0x11 must contain 0x3C.

If those addresses alias other destinations, later writes can replace these values.

### Repeated writes are preserved as accesses

If L is 0x11223344 and A is 0x00002000, an observer of B + 0x54 must see a word write of 0x11223344 followed later by a word write of 0x00002000.

An implementation that omits the first write would not preserve the represented access behavior.

### Defined-range shift example

If L is 0x00001234 and the low byte of A is 4, the write to C + 0x01 must contain 0x23: the low byte of the right-shifted value 0x00000123.

This does not establish expected results for negative L or large shift counts.

### Doubled addresses use different widths

If D is 0x00001000 and E is 0x00001800, with valid effective addresses:

- The earlier doubled-address access writes halfword 0x0065 at 0x00002000.
- The later doubled-address access writes Q as a word at 0x00003000.

Neither destination receives an additional base-address offset.

### Aliasing changes which value is read

If P + 0x54 is exactly C + 0x64, and no intervening overlapping write changes that storage, the write of word value 100 through P occurs before Q is read.

Q must consequently be read as 100. Subsequent destinations derived from Q use that value, provided they are valid.

### Indirect-call arguments preserve sampling order

If E is 0x00001800, T is 0x12345678, and V is 0xABCDEF01, the indirect invocation must receive, in order:

0x00000072, 0x00001800, 0x12345678, and 0xABCDEF01.

The third argument comes from the initial C-relative snapshot, whereas the fourth comes from a substantially later D-relative read.
