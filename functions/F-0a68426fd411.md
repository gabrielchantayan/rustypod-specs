# F-0a68426fd411

## Purpose

F-0a68426fd411 traverses a byte-addressed sequence through two cursor-manipulation dependencies, compares values obtained during backward traversal with a supplied target, and invokes an external transfer operation for each match. It returns the number of matches processed.

The apparent intent is to remove occurrences of a target value from an encoded string and then adjust the owning object’s storage. That interpretation is **inferred**, not an established contract of the unknown dependencies. The supplied evidence establishes neither the encoding nor the external transfer operation’s semantics.

The behavior below preserves the distinction between the computed arguments and their likely meaning. In particular:

- The transfer extent is not reduced by the target’s reported width before the transfer call.
- The final method’s nonzero result participates in an address calculation; it is not merely tested as a success flag.
- A zero reported width can produce a positive match count without invoking the final method.

No runtime tests have been performed.

## Interface

### Inputs

The function receives:

1. **Object address.** An address used to access an array-like object containing at least two machine words:
   - Word 0 supplies an address used for indirect method lookup.
   - Word 1 supplies the initial sequence address.

2. **Target.** An integer passed unchanged to F-ff169115f82a and compared for exact equality with each result from F-13bcc08bc7a3.

The supplied representation uses integer-sized address storage, integer results, and four-byte-style word indexing. The contract therefore describes a **32-bit address and integer interpretation**. The underlying ABI and original source types are not independently established. Behavior on a wider-address architecture cannot be inferred by mechanically widening selected fields.

The sequence is inspected one byte at a time for a zero terminator during forward traversal. Its semantic units need not be bytes: cursor movement and backward decoding belong to dependencies.

### Output

The integer result is the number of backward traversal results equal to the target, provided execution completes without arithmetic or memory-access failure.

This count does not establish that:

- A valid encoded unit was removed.
- The external transfer succeeded.
- The final method succeeded.
- The sequence remains valid.
- The object’s length or allocation metadata was updated.

The return value of the external transfer operation is ignored. A zero result from the final method does not reduce the returned match count or produce a distinct error result.

### Ownership and storage

The function does not explicitly allocate or release memory. It passes addresses into external operations and invokes an indirect method on the object.

Ownership effects of those dependencies are unknown. In particular, this contract does not assume that a dependency preserves the object, retains the original sequence allocation, or refrains from allocation, release, or reallocation.

The object must remain accessible whenever its fields are subsequently read. Any addresses used by the function or its dependencies must remain valid for the accesses actually performed.

## Behavior

### 1. Initial sequence selection

The function reads object word 1 and places that address in a local cursor. The match count starts at zero.

If the initial sequence address is zero, the function returns zero immediately. It performs no sequence-byte read, traversal call, width query, transfer call, or indirect finalization call.

This is not a null-object check. Reading word 1 already requires a valid object address.

### 2. Forward traversal and iteration counting

For a nonzero initial cursor, the function repeatedly inspects the byte at the cursor.

- A zero byte ends the forward traversal.
- A nonzero byte causes a call to F-d3922c7fe0ec with the address of the local cursor storage.
- After that call returns, a signed integer traversal count is incremented.
- The next loop test reads the byte at the cursor’s current value.

The dependency can therefore replace the cursor through the address it receives. No return value from this dependency controls the loop.

The traversal count measures **completed forward dependency calls**, not bytes, characters, or validated encoded units. Its relationship to any of those quantities depends on F-d3922c7fe0ec.

Termination requires that the dependency eventually leave the cursor at an accessible zero byte. The function itself does not ensure progress, detect cycles, or enforce a sequence bound.

### 3. Initial span and target width

After the forward scan stops, the function rereads object word 1. It constructs an address-sized value from:

- The terminal cursor address;
- One added byte;
- The sequence-base value obtained from this new object-field read.

Call this numeric value the **initial span**. In mathematical terms, where the relevant arithmetic is representable:

\[
S_0 = E + 1 - B_{\text{scan}}
\]

Here, \(E\) is the cursor at the end of the scan, and \(B_{\text{scan}}\) is the base reread after scanning.

Although represented through a pointer-typed temporary in the supplied evidence, this value is subsequently used as an extent-like number and method argument. It is not dereferenced at this stage.

If the base has remained stable and the terminal cursor addresses the first zero byte after \(N\) content bytes, the initial span is \(N+1\). This interpretation is conditional on dependency behavior; the base is not guaranteed to remain stable during traversal.

The function then calls F-ff169115f82a with the target. Its integer result is retained as the **width** for every matching iteration. The function does not verify that the result is positive or agrees with cursor movement.

A working span begins equal to the initial span.

These operations occur even when the initial nonzero sequence address already points to a zero byte.

### 4. Backward traversal

The function performs backward iterations while the forward traversal count is positive. Each iteration:

1. Calls F-13bcc08bc7a3 with the address of the same local cursor storage.
2. Compares that dependency’s integer result with the target.
3. Processes a match, if any.
4. Decrements the traversal count.

The number of backward dependency calls is controlled by the saved forward-call count. There is no separate backward termination-byte test and no direct check that the cursor has reached the beginning of the sequence.

No restoration of the cursor occurs between the forward and backward phases. Backward processing begins with whatever cursor value remains after the forward scan and any intervening dependency effects.

### 5. Match processing

On an exact integer match, the function rereads object word 1 and invokes an external transfer dependency with three ordered arguments:

1. The current cursor address;
2. The current cursor address plus the retained width;
3. The working span minus the difference between the current cursor address and the newly read sequence base.

Writing \(C\) for the current cursor, \(B_{\text{match}}\) for that base read, \(S\) for the current working span, and \(W\) for the width, the arguments are:

\[
C,\qquad C+W,\qquad S-(C-B_{\text{match}})
\]

The function does not subtract \(W\) from the third argument before making the call.

After the transfer returns, the function:

- Decreases the working span by the width;
- Increments the match count.

The transfer result is not inspected. Consequently, the count records that the matching path completed, not an independently confirmed transfer outcome.

The base used to calculate a transfer extent is read afresh for each match. It need not equal the base used to calculate the initial span if a dependency has changed object state.

### 6. Conditional final method and terminator write

After all backward iterations, the function compares the final working span with the initial span.

If they are equal, it skips the final method entirely. The decision is based on span equality, not on whether the match count is nonzero.

If they differ, the function:

- Reads object word 0.
- Uses that value as the base for an indirect method lookup at byte offset 8.
- Calls the resulting method with the object address, final working span, and integer constant 1.

Let the integer result of that method be \(R\), and the final working span be \(S_f\).

If \(R=0\), no explicit final byte write occurs.

If \(R\ne0\), the function writes a zero byte at the address numerically formed as:

\[
R + S_f - 1
\]

Thus \(R\) affects the write address. Treating every nonzero result as an interchangeable Boolean success value would misstate the behavior.

A plausible interpretation is that \(R\) represents a returned storage base and \(S_f-1\) selects its final byte. This interpretation is **inferred**. The method’s true return type and allocation contract are unknown.

The function then returns the match count.

## Side effects

### Established direct effects

The function directly:

- Reads object word 1 initially, after forward traversal, and once per match.
- Reads sequence bytes while testing forward traversal termination.
- Supplies writable local cursor storage to both traversal dependencies.
- Reads object word 0 and the method entry at offset 8 only when the span changes.
- Writes one zero byte after a nonzero final-method result.

It does not directly store a replacement sequence address into object word 1 or directly update an object length field.

### Dependency-mediated effects

Each dependency may have additional effects not specified by the supplied evidence. Nothing establishes that these calls preserve global state, object fields, allocation ownership, or sequence contents.

This matters because later reads are observable:

- Forward traversal effects can influence the base reread used for the initial span.
- The width dependency runs before backward traversal.
- Each backward dependency call occurs before the current match’s base reread.
- A transfer call completes before the next backward dependency call.
- Final method lookup happens after all transfer calls.

The contract does not impose an unsupported ordering among separate operand reads within a single argument expression. It does preserve the call and phase order established above.

### Bounds and arithmetic risks

The function supplies no explicit capacity, encoding-validity, or arithmetic checks.

Correct execution requires representable traversal counts, match counts, span calculations, cursor arithmetic, and final write addresses. The supplied representation is insufficient to promise a particular wraparound behavior for signed overflow or invalid pointer arithmetic.

If the external dependency performs a conventional byte transfer using its third argument as a length, a further boundary risk follows from the exact extent calculation. For positive width, its source range extends beyond the current span’s nominal end by that width. A contract for a conventional transfer implementation would therefore require additional readable source storage; the zero terminator alone does not prove adequate bounds.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes valid storage and representable arithmetic unless stated otherwise.

### Null initial sequence address

Given a valid object whose word 1 is zero:

- Result: zero.
- No dependency is called.
- No sequence byte is read.
- No final method lookup or terminator write occurs.

### Initially empty sequence

Given a nonzero sequence address whose first byte is zero, with a stable object base:

- No forward or backward traversal dependency is called.
- The initial span is 1.
- F-ff169115f82a is called once.
- No transfer or final method is called.
- Result: zero.

This case distinguishes an empty sequence from a null sequence address.

### Traversal with no matches

Suppose forward traversal makes three calls before reaching a zero byte, and all three backward results differ from the target:

- There are three backward dependency calls.
- There are no transfer calls.
- The working span remains unchanged.
- The final method is skipped.
- Result: zero.

### One matching backward result

Suppose the stable base is \(B\), the initial span is 6, the width is 1, and the matching backward call leaves the cursor at \(B+3\):

- Transfer arguments are \(B+3\), \(B+4\), and 3.
- The working span becomes 5.
- The match count becomes 1.
- If no other match occurs, the final method receives the object, 5, and 1.
- If that method returns a nonzero value \(R\), the final zero byte is written at \(R+4\).

If the transfer is a conventional three-byte copy, its source bytes include \(B+6\), beyond a terminator at \(B+5\). This boundary requirement must not be silently shortened to make the operation resemble conventional removal.

### Matches with zero width

Suppose two backward results match and the width dependency returns zero:

- Two transfer calls occur.
- Each transfer has identical first and second address arguments.
- The working span remains equal to its initial value.
- The final method is skipped.
- Result: two.

A positive result therefore does not imply finalization.

### Final method returns zero

Suppose matches change the span, and the final method returns zero:

- The final method has still been called.
- No explicit final zero-byte write occurs.
- The accumulated match count is returned unchanged.

No rollback or failure result is established.

## Uncertainties

The following remain **documented_only**:

- The original ABI, exact source types, and language-level overflow rules.
- The object’s complete layout and method-table convention.
- The sequence encoding and validity requirements.
- Whether the traversal dependencies advance and retreat by corresponding units.
- Whether the width dependency agrees with those units.
- Whether the external dependency is a byte-copy operation and supports overlap.
- Whether sufficient readable padding exists beyond the terminator.
- Whether dependencies mutate object fields, global state, or allocation ownership.
- Whether the final method returns an address, an integer with another meaning, or an error representation.
- Behavior after dependency failure, invalid memory access, nontermination, or arithmetic outside the representable domain.

Negative or zero widths are not rejected in the visible behavior. They must not be declared impossible without a dependency contract.
