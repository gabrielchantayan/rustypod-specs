# F-75c7683ed1da

## Purpose

F-75c7683ed1da reorders a contiguous sequence of fixed-size records in place, using an ascending comparison value derived from the first two words of each record. All four words move together; the remaining two words do not participate in comparisons.

The established mechanism combines partitioning for ranges containing more than nine records with adjacent-exchange insertion sorting for smaller ranges. Deferred ranges are maintained in a fixed-size local workspace rather than through recursive calls.

The apparent intent is an ascending sort. That interpretation depends on the arithmetic used to construct comparison values behaving consistently throughout execution. In particular, the supplied representation does not establish a portable meaning for signed arithmetic overflow.

This is not a stable sort: records with equal comparison values can change relative order.

## Interface

**Inputs**

- A base address identifying the first record of a writable, contiguous record sequence.
- A signed integer count giving the number of records in that sequence.

**Output**

There is no explicit return value. Successful completion is observed through the modified record sequence.

**Record layout**

The visible address arithmetic establishes a record stride of 16 bytes, represented as four consecutive 32-bit words:

| Byte offset | Width | Role |
|---|---:|---|
| 0 | 32 bits | First comparison component |
| 4 | 32 bits | Second comparison component |
| 8 | 32 bits | Uninterpreted payload |
| 12 | 32 bits | Uninterpreted payload |

Comparison expressions treat the first two components as signed integers. For a record whose first two words are \(a\) and \(b\), the expressed comparison value is:

\[
K = a + 65536b
\]

Neither component is masked to 16 bits, and neither is explicitly narrowed to a 16-bit quantity. Consequently, this expression must not be specified as an unsigned concatenation of two 16-bit fields.

Different component pairs can have the same comparison value. For example, where the arithmetic is representable, \((65536,0)\) and \((0,1)\) both produce 65536.

**Valid-use preconditions**

The caller must provide:

- A nonnegative count.
- A record region large enough for the count, with readable and writable storage for every included word.
- Addresses and range sizes representable by the visible pointer-to-integer conversions and signed range calculations.
- Suitable alignment for the word accesses.
- Exclusive or otherwise externally coordinated access while records are being moved.
- Comparison components whose arithmetic has a defined, consistent interpretation on the actual target.
- An execution whose number of simultaneously deferred ranges fits the local workspace.

The visible implementation performs no validation of these conditions.

A zero count does not establish that a null or otherwise invalid base address is supported: address arithmetic still occurs even when record contents are not accessed.

## Behavior

### Comparison semantics

Every ordering decision uses the derived value \(K\), rather than comparing the two components lexicographically or comparing payload words.

All visible ordering tests are signed comparisons. Under ordinary, non-overflowing arithmetic:

- A smaller \(K\) belongs earlier.
- Equal values are equivalent for sorting purposes, regardless of differences in either comparison component or either payload word.
- Payload data has no effect on placement except that it follows its containing record.

The visible representation uses 32-bit words and signed integer expressions. Multiplication by 65536 and subsequent addition can exceed the signed 32-bit range. No widening, overflow check, saturation, or explicit wrapping conversion is present. A contract for overflowing values therefore requires additional target evidence; it cannot be inferred merely from the record layout.

### Range organization

The active range is represented by a beginning address and an exclusive ending address. Initially, the ending address is calculated from the supplied count using a 16-byte record stride.

The number of records in an active range is derived from the signed integer difference between its endpoint addresses, shifted right by four bits. This makes representability of both the addresses and their difference relevant. A valid mathematical record count alone is not sufficient if the address calculations overflow or are truncated.

Ranges containing more than nine records are partitioned. Ranges containing at most nine records proceed directly to adjacent-exchange sorting.

### Sampling and pivot placement

For a partitioned range containing \(m\) records:

1. The first record is exchanged with the record at index \(\lfloor m/2\rfloor\), measured from the range beginning.
2. The record at index 1 and the last record are compared. They are exchanged if the last record has the smaller comparison value.
3. The first record and the record at index 1 are compared. They are exchanged if the first record has the smaller comparison value.
4. The first record and the last record are compared. They are exchanged if the first record has the larger comparison value.

These are complete four-word exchanges, not exchanges of keys alone.

After these operations, under consistent comparison arithmetic, the record at index 1 has a value no greater than the first record, and the last record has a value no less than the first record. The first record then supplies the pivot value.

The initial first/middle exchange is unconditional. Even already sorted input may therefore be written and rearranged temporarily.

### Partition scanning

Two scanning positions are initialized near the ends of the active range:

- The low-side position begins at index 1 and advances before its first comparison, so its first examined candidate is index 2.
- The high-side position begins at the last record and retreats before its first comparison, so its first examined candidate is the penultimate record.

The low-side scan advances over values strictly less than the pivot. The pivot value is re-read from the first record during this scan.

The high-side scan retreats over values strictly greater than the pivot, using the pivot value obtained by the preceding low-side scan.

If the high-side position lies before the low-side position, scanning stops. Otherwise, the records at those positions are exchanged, and scanning continues with another advance and retreat.

Equal values stop both scans. They can consequently be exchanged even though their comparison values are identical. If both positions identify the same record, the visible control flow still performs the exchange rather than treating equality of addresses as a stopping condition.

The sampled boundary records provide stopping values for the scans when arithmetic and memory assumptions hold. There are no separate scan-limit checks against the beginning or ending address on every comparison.

When the scan positions cross, the first record is exchanged with the record at the final high-side position. This places the pivot at that position.

### Remaining ranges and processing order

After pivot placement, the two candidate ranges are:

- The range from the original beginning up to, but excluding, the pivot position.
- The range from the final low-side scan position up to the original exclusive ending.

The pivot itself is excluded. If scanning previously met on an equal-valued record, there can also be an intervening record excluded from both ranges; that record is pivot-equivalent under consistent comparisons.

The function compares the sizes of the two candidate ranges:

- If the right candidate is strictly smaller, it defers the left candidate and processes the right candidate immediately.
- Otherwise, including equal sizes, it defers the right candidate and processes the left candidate immediately.

Deferred ranges are stored as pairs of addresses in a last-in, first-out local workspace. This chooses smaller-first processing while retaining the larger range for later.

The workspace contains 40 32-bit slots, allowing 20 endpoint pairs. Each partition stores a pair without an explicit capacity check. The supplied material does not independently establish a worst-case workspace bound for every admissible target address space and input.

### Small-range sorting

An active range of at most nine records is handled by adjacent exchanges.

The function visits record positions in increasing address order, beginning with the second record. At each position, it compares the current record with its predecessor. While the current record has a strictly smaller comparison value, the two complete records are exchanged and the comparison moves one record toward the beginning.

Backward movement stops when either:

- The preceding value is no greater than the moving record’s value; or
- An exchange has reached the beginning of the active range.

Equal-valued records are not exchanged by this small-range phase. Thus a sequence processed entirely by this phase preserves the relative order of equal-valued records. That local property does not make the full function stable.

After finishing an active range, the function retrieves the most recently deferred range, if any, and continues. It returns only when no deferred range remains.

### Empty and singleton ranges

For a valid zero-length range, no record comparison or record-word write occurs. The function nevertheless computes range and next-record addresses.

For a valid singleton range, no record-word comparison or write occurs.

Negative counts are not treated as an error category. There is no explicit rejection, and no meaningful sorting guarantee is established for them.

## Side effects

**Caller-owned storage**

The function directly modifies the supplied record region. It neither creates a replacement sequence nor returns a new base address.

All four words participate in every record exchange. For valid execution, payload words remain attached to their original comparison components. Records are permuted rather than merged, reconstructed from keys, or discarded.

**Read/write ordering**

Record exchanges are sequences of scalar operations, not atomic 16-byte transactions. The visible exchanges retain the necessary source values, write one destination in increasing word-offset order, and then write the other destination in increasing word-offset order.

Consequences include:

- A concurrent observer can see a partially written record.
- During an exchange, the memory region need not temporarily represent a permutation of complete original records.
- Even an exchange whose two addresses coincide can execute word writes.
- Equal comparison values do not imply that no write occurs.

The explicit statement ordering supports these exchange-level observations. It does not establish a portable order between separate operand reads within a single arithmetic or comparison expression.

**Local state**

The function uses a fixed local workspace for deferred range endpoints and temporary scalar storage for exchanges. No dynamic allocation, deallocation, reference-count update, or ownership transfer is visible.

**External state**

No external function calls, explicit global-variable accesses, file operations, logging, or callback invocations are visible.

This does not make the supplied memory ordinary private storage by assumption. Memory-mapped storage, shared storage, invalid storage, or externally changing storage can expose additional effects outside the supported sorting contract.

**Errors**

There is no error return, diagnostic, rollback, or validation path. Invalid addresses, arithmetic problems, or workspace exhaustion are not converted into a reported failure. If execution fails after writes begin, the original ordering is not preserved transactionally.

## Acceptance examples

These examples are conditional acceptance criteria derived from static evidence, not executed tests.

### Small ascending result with payload association

Given three records whose comparison components are respectively \((3,0)\), \((1,0)\), and \((2,0)\), with distinct payload pairs:

- The resulting comparison values must be 1, 2, and 3.
- Each original payload pair must remain attached to its original comparison components.
- No word outside the supplied three-record region may be written during a valid execution.

This exercises the adjacent-exchange path.

### The second component contributes a factor of 65536

Given records with components \((0,1)\) and \((65535,0)\):

- Their comparison values are 65536 and 65535.
- The record with components \((65535,0)\) must appear first.

Treating the first component alone as the key would not satisfy this criterion.

### Negative comparison values

Given components \((-1,0)\), \((0,0)\), and \((1,0)\), all arithmetic is representable.

The resulting order must be \((-1,0)\), then \((0,0)\), then \((1,0)\). An unsigned comparison of the first word would be incompatible.

### Equal derived values from different components

Given two records with components \((65536,0)\) and \((0,1)\):

- Both have comparison value 65536.
- If these are the entire two-record input, their original order must remain unchanged because the small-range phase exchanges only on strict inequality.
- In a larger partitioned input, preservation of their relative order is not guaranteed.

### Threshold behavior

For nine valid records, the function must use the small-range sorting path without performing the midpoint sampling exchange.

For ten valid records, it must enter the partitioning path before completing the resulting smaller ranges.

In both cases, representable keys must finish in nondecreasing order with complete records preserved.

### Already sorted and equal-valued inputs

An already sorted range larger than nine records is not a no-write case: the initial midpoint exchange still occurs.

An all-equal range larger than nine records must not be assumed stable or untouched. Equal values stop both partition scans, permitting whole-record exchanges.

### Empty and singleton inputs

With valid address arithmetic:

- A zero count must cause no record-word reads or writes.
- A count of one must leave the record unchanged.

Neither example establishes support for an invalid base address.

### Overflow boundary

A second component of 32768 makes its multiplication by 65536 equal to 2147483648 mathematically, outside signed 32-bit range.

No particular ordering for that record is an acceptance requirement without additional arithmetic evidence. Requiring wraparound, saturation, or widened arithmetic would add behavior not established here.

## Uncertainties

**documented_only — Overflow semantics.** The supplied representation does not resolve machine-level wrapping versus language-level signed-overflow behavior. The guaranteed ordering domain is restricted to arithmetic whose meaning is established.

**documented_only — Exact platform ABI.** Four-byte words, 16-byte records, and integer-encoded addresses are visible. The original declared data types, calling convention, and broader address-space guarantees are not independently available.

**documented_only — Workspace sufficiency.** Smaller-first processing supports the inference that deferred-depth growth is controlled. A complete bound proving the 20-pair capacity sufficient is not supplied.

**documented_only — Invalid inputs.** Negative counts, misalignment, invalid storage, nonrepresentable endpoints, and concurrent mutation have no defined recovery behavior in the visible body.

**Inferred intent.** The function is an in-place hybrid quicksort/insertion sort. The algorithmic classification explains the structure but adds no guarantees about stability, worst-case running time, or invalid-input handling.

## Evidence

The established behavior comes exclusively from static inspection of the supplied function body:

- Four-word record exchanges and 16-byte range arithmetic establish the record layout.
- Repeated first-word-plus-65536-times-second-word expressions establish the comparison rule.
- The greater-than-nine range test establishes the partition threshold.
- Midpoint sampling, inward scans, pivot placement, and deferred endpoint pairs establish the large-range behavior.
- Strict adjacent comparisons establish the small-range behavior.
- The fixed 40-word workspace establishes storage for 20 deferred endpoint pairs.
- The absence of visible calls, allocation, diagnostics, and a return value limits the dependency and error contracts.

No runtime tests have been performed. Ordering claims are conditional on the stated arithmetic, memory, address-representation, and workspace preconditions.
