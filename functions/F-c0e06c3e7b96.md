# F-c0e06c3e7b96

## Purpose

F-c0e06c3e7b96 builds a zero-terminated byte sequence from mutable input under control of a caller-supplied classification table. Its directly established transformations are ordinary byte copying, two delimiter-removal forms, escape handling, and dollar-prefixed lookup substitution.

Successful completion publishes an output-storage pointer through a caller-provided slot and returns the 32-bit value 1. Represented failure paths return 0 if their dependency calls return normally.

The syntax suggests configurable quoting and expansion, but no conventional shell-language semantics are established. In particular, substitution lookup receives a context and a selector, not a separate argument for the scanned suffix name.

## Interface

### Arguments and result

The function accepts four arguments:

1. **Classification context:** a 32-bit pointer identifying storage containing a classification-table pointer at byte offset 4.
2. **Default lookup selector:** a byte pointer passed to lookup when no double-colon prefix is recognized. This function does not directly inspect the selector’s contents.
3. **Output slot:** a pointer to a readable and writable 32-bit slot. The function directly reads and replaces this slot only during successful completion.
4. **Mutable input:** a byte pointer. Substitution parsing writes temporary zero bytes into this storage.

The result is 32 bits:

- **1:** the successful output-publication sequence completed, including its final dependency call.
- **0:** construction returned zero, preparation returned zero, or a substitution error completed reporting and cleanup.

These return descriptions do not establish the absence of dependency side effects. A dependency that does not return prevents the later steps described here.

### Preconditions and dependency boundaries

Defined execution requires valid storage for every actual read and write, including:

- Context and classification entries.
- Input bytes examined by scanning and one- or two-byte lookahead.
- Writable input locations used as substitution split points.
- The output slot.
- Output storage sufficient for every write.
- Replacement storage readable through its terminating zero.

A zero input byte is not inherently a parser terminator. Top-level termination depends on classification bit `0x0008`, subject to higher-priority dispatch. Name scanning instead uses mask `0x0107`; it does not independently stop at zero or at the termination bit.

These requirements do not establish dependency contracts. No dependency is known here to preserve input, classification data, output storage, accessible globals, or other reachable state.

### Dispatch precedence

At each top-level iteration, the function reads the current input byte, loads the classification-table pointer from the context, and reads that byte’s 16-bit classification.

The first applicable rule wins:

| Priority | Condition | Action |
|---|---|---|
| 1 | Bit `0x0040` | First delimiter form |
| 2 | Bit `0x0400` | Second delimiter form |
| 3 | Bit `0x0020` | Top-level escape |
| 4 | Bit `0x0008` | Successful completion |
| 5 | Byte equals dollar, `0x24` | Substitution |
| 6 | Otherwise | Copy the byte unchanged |

Thus a delimiter or escape classification overrides termination. Any of the four classification branches overrides dollar substitution.

Ordinary copying writes one byte at the current output position, increments that position by one, and advances input by one byte.

### First delimiter form

The opening byte, classified with `0x0040`, is remembered as the delimiter and omitted from output.

The function examines successive following bytes:

- A byte carrying `0x0008` stops the scan before copying.
- Otherwise, a byte equal to the opening delimiter stops the scan.
- Otherwise, a byte carrying `0x0020` is omitted, and the following byte is examined using the same table pointer loaded for this scan step.
  - If that following byte carries `0x0008`, the scan stops without copying it.
  - Otherwise, that following byte is copied literally.
- Any other byte is copied literally.

The table pointer is reloaded from the context on each scan step. Escape removal here performs no translation of `r`, `n`, `b`, or `t`.

On exit, input is positioned at the stopping byte. If that byte equals the opening delimiter, it is consumed; otherwise it remains current. Top-level dispatch then resumes.

An escaped delimiter is copied when its termination bit is clear. A missing closing delimiter does not itself produce an error. A termination-classified stopping byte is reconsidered by top-level dispatch unless it also equals the opening delimiter and is consumed by the exit rule.

### Second delimiter form

The opening byte, classified with `0x0400`, is omitted and remembered as the delimiter.

For each subsequent scan step:

- A byte carrying `0x0008` stops the scan.
- A different byte is copied unchanged.
- A matching delimiter stops the scan unless the immediately following byte is the same delimiter.
- Two consecutive matching delimiters produce one delimiter byte and scanning continues after both.

The second member of a doubled pair is compared by value; its classification is not separately checked. The table pointer is reloaded for each scan step.

At scan exit, a stopping byte equal to the opening delimiter is consumed. Otherwise it remains current. Parsing resumes at top level.

This form does not interpret escapes or substitutions within its contents.

### Top-level escape

The function reads the byte immediately following an escape-classified byte and classifies it using the table pointer already loaded for the current top-level iteration.

If the following byte carries `0x0008`, the function proceeds directly to successful completion. Neither byte is emitted, and the following byte is not independently dispatched.

Otherwise, one byte is emitted:

| Following byte | Output byte |
|---|---|
| `r`, `0x72` | Carriage return, `0x0D` |
| `n`, `0x6E` | Line feed, `0x0A` |
| `b`, `0x62` | Backspace, `0x08` |
| `t`, `0x74` | Horizontal tab, `0x09` |
| Any other byte | Unchanged |

Input advances by two bytes and output position increases by one.

### Substitution syntax and scanning

A dollar byte reaching the substitution branch selects its form from the next byte:

- `{` selects required closer `}`.
- `(` selects required closer `)`.
- Anything else selects an unbracketed form without a required closer.

Bracketed scanning starts after the opening bracket. Unbracketed scanning starts immediately after the dollar.

The first scan advances while the current byte’s classification has at least one bit in `0x0107`. It uses the table pointer already loaded for the top-level dollar iteration. Empty scanned text is allowed.

There is no separate syntax-character override within this scan. A bracket, colon, or zero carrying a name-mask bit can be scanned past.

### Double-colon selector

After the first scan, the function checks whether its endpoint is a colon immediately followed by another colon.

If so:

1. It writes zero over the first colon.
2. It selects the beginning of the first scanned segment as the lookup selector.
3. It starts a second scan after both colons.
4. That scan accepts the same `0x0107` mask, reloading the context’s table pointer for each classification.

Otherwise, the selector remains the second function argument.

Only one double-colon split is recognized. Neither the prefix nor the suffix is required to be nonempty.

### Endpoint write and closer validation

The function saves the final scan-endpoint byte and writes zero over that location.

For a bracketed form, the saved byte must equal the required closer. A mismatch causes the function to call F-4fc89ec41a6d with:

`0x0E`, `0x65`, `0x66`, `0`, `0`.

Before this reporting call, the endpoint has been zeroed, and the first colon has also been zeroed if a double-colon split occurred. This function does not restore either location on that error path.

That establishes local writes and absence of local restoration—not persistent contents after dependency execution. F-4fc89ec41a6d and subsequent F-28097aea1ffc may modify accessible storage. Post-dependency contents are unknown.

If reporting returns normally, failure cleanup receives the temporary object, followed by return 0.

A valid bracketed substitution resumes after the closer. An unbracketed substitution resumes at its endpoint.

### Lookup and restoration

After validation, F-9f492d6c62e6 receives exactly:

1. The classification context.
2. The selected selector.

No separate suffix-name argument is supplied. The input split locations are still zeroed when lookup is called.

After lookup returns normally, this function performs restoration in this order:

1. Writes a colon back to the first split location, if present.
2. Writes the saved endpoint byte back to the final endpoint.

These are writes of remembered values, not a guarantee that the rest of the input was preserved during lookup.

## Side effects

### Direct writes and ownership

Direct writes comprise output bytes, a final output zero, substitution split-point writes and restoration writes, and successful replacement of the output slot.

The function does not directly replace the output slot on represented failure paths. This does not promise that dependencies leave it unchanged.

Publication suggests an intended transfer of a constructed buffer, but ownership is unresolved. F-5990a26eaaa3 must not be assumed to free an old output, detach storage, or destroy only an object wrapper. F-28097aea1ffc’s cleanup effects are likewise unknown.

There is no explicit release of a nonzero lookup result. Whether it is borrowed, owned, retained, or invalidated by another dependency is unknown.

### Aliasing and state changes

No overlap checks or isolation mechanisms are present. Input, replacements, output storage, context storage, and the output slot may affect one another if they overlap.

Output storage is obtained through the temporary object’s field for output writes. The classification table is reloaded at the points described above, rather than held uniformly throughout parsing.

No dependency-preservation guarantee follows from normal return. In particular, a normally returning reporter or cleanup dependency may change locations previously zeroed by this function.

### Arithmetic limits

The source does not establish portable behavior for signed overflow or a safe interpretation of an out-of-range size request. Wraparound safety, saturation, and allocation success must not be inferred.
