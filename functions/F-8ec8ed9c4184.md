# F-8ec8ed9c4184

## Purpose

F-8ec8ed9c4184 describes a stateful control-flow fragment that writes memory, invokes indirect dependencies, consumes pointer-like call results, and enters a recurring processing phase. No application-level purpose or normal return is established.

The contract records the supplied static representation, not verified execution. Initialization-like operations precede a recurring sequence whose behavior depends on incoming machine state, external calls, writable addresses, and unresolved arithmetic.

**Status: documented_only.** The representation does not establish a safe standalone entry point. Invalid accesses, nonreturning dependencies, arithmetic outside established semantics, or breakpoint handling can prevent subsequent effects.

### Outputs and preconditions

There is no established return value or normal-return path. Observable effects include byte, halfword, word, and doubleword writes; indirect calls; reads through computed addresses; and software breakpoint 4.

Continuation requires each reached access to be permitted, each required dependency to return, and any breakpoint to permit resumption. These are environmental preconditions, not checks performed by this fragment.

No allocation, release, ownership transfer, or pointer-lifetime guarantee is established.

### Arithmetic and layout

Addresses and ordinary words are represented as 32 bits. A represented 64-bit call result is split into a lower 32-bit word and an upper 32-bit word. This logical split does not establish memory endianness.

Unsigned 32-bit calculations have modular behavior where the expression is actually unsigned. Signed operations must be considered separately. In particular:

- The recurring result scaling performs **signed 32-bit multiplication by 32 before conversion to unsigned**.
- Seed scaling, accumulator arithmetic, some pointer-derived products, and signed left shifts have their own overflow or conversion uncertainties.
- A right shift by 32 of a represented 32-bit operand has no established portable result.
- Signed right shifts express arithmetic-shift intent, but their concrete execution semantics are not independently verified.

Byte and halfword stores retain the relevant low-width value. Alignment, byte order, memory permissions, device behavior, and physical overlap between global views remain unknown.

## Behavior

### 1. Entry sequence

The represented order is:

1. Write the incoming halfword at the initial destination plus 2.
2. Capture the signed 32-bit seed from fixed storage.
3. Call F-02 with the signed interpretation of the two bit operands’ exclusive-OR, shifted right by 8.
4. After return, assign zero to one represented stack slot.
5. Read one byte from the address formed by the captured seed multiplied by 32; zero-extend it into the other represented stack slot.
6. Write the seed multiplied by 16 as a word at the seed-times-32 address.
7. Write byte zero at `0x00000009`.
8. Write a represented halfword zero at `0x00000030`.
9. Write the seed’s low halfword at `0x0000000e`.

The seed is captured before F-02. Changes to its backing storage during F-02 do not cause a represented reread. The scaled-address byte load occurs after F-02 and can observe that call’s memory effects.

The signed seed products are not unconditionally specified as wrapping products.

### 2. Setup and inner transition

Both setup indices initially equal zero. Using the active cursor, setup:

- Writes the initial stored word at cursor minus 4.
- Writes a word equal to eight times the first index at that same numeric address. Initially this writes zero at address zero.
- Writes a zero word through an address involving a signed right shift by 32, followed by addition of `0x10`. The destination is unresolved.
- Writes halfword `0xc470` at the initial stored word shifted logically right by 4, minus sixteen times the second index, minus one if bit 3 of that word is clear, plus `0x26`.
- Writes `0x8000` to fixed storage associated with `0xfe238028`.
- Sets a setup value to `0x0897f228`.
- Writes the 32-bit self-address value `0x225fc470` at that address.
- Writes `0x225f` to fixed storage associated with `0x0000229f`.
- Reads the word-like fixed view associated with `0x00000022`, extracts its upper 16 bits, and writes that zero-extended value as a word at cursor plus 84.

The declarations of some fixed global views are absent; their exact storage widths are not all independently established by their assigned constants.

If the comparison address differs from cursor plus 20, F-03 is called without explicit arguments. This condition does not guard the preceding writes.

The inner state then contains:

- A 64-bit pair with lower word zero and upper word `0x0897f1f8`.
- A signed accumulator initially zero.
- A stored offset initially `0x0897f22d`.
- An address-like working value initially `0x0897f1f8`.

Each represented inner iteration:

1. Writes the stored offset as a word at the pair’s lower word plus 12.
2. Interprets the lower word as signed and right-shifts it by its low-byte value.
3. Records whether subtracting one from that shifted value would overflow signed 32-bit arithmetic.
4. Reads a word at twice the shifted value.
5. Writes the fetched word’s low halfword to storage associated with F-422afe36d401.
6. Writes word `0x0897f1f8` at the fetched word plus 4.
7. Replaces the active cursor with the preceding cursor position.

An overflow result returns control to setup. The stored-word input has by then been replaced with `0x0897f1ec`; the cursor and setup-related state are not restored to entry values.

On the non-overflow path:

1. Write byte `0xd8` at the pair’s upper-word address.
2. Initialize a separate carried word to 8.
3. Call F-04 with zero and capture its 64-bit result.
4. Add the incoming increment to the signed accumulator.
5. Replace the active cursor with a zero-extended 16-bit value read from fixed storage.
6. Read a byte at F-04’s lower result word plus `0x0897f1f8`. This becomes the first recurring byte source.
7. When the saved overflow indicator equals zero, read a 16-bit destination address at F-04’s lower word plus the stored offset, then write the accumulator as a word to that zero-extended address.
8. Set the recurring call argument to zero and enter the recurring phase.

Initially the shift operand and count are both zero. Subtracting one from zero does not overflow, so the first inner iteration takes the non-overflow path if preceding operations complete. Its 16-bit destination load restricts the subsequent word-store start address to `0x00000000`–`0x0000ffff`.

### 3. Recurring state and initial call

The recurring phase carries distinct state:

| State role | Initial value |
|---|---|
| Address-like working value | `0x0897f1f8` |
| Carried word | 8 |
| Byte source | Byte loaded after F-04 |
| Active cursor | Zero-extended fixed halfword |
| Accumulator | Incoming increment added to zero, subject to signed arithmetic |
| Recurring argument | Zero |

These roles are separate. In particular, the retained byte is not initially taken from the address-like working value.

At each pass:

1. Retain the low byte of the current byte source.
2. Call F-05 with the recurring argument.
3. Interpret its upper result word as a destination pointer.
4. Interpret its lower result word as signed 32 bits, multiply by 32, and assign the result to an unsigned 32-bit scaled value.
5. Write that scaled value as a word at its own numeric address.
6. Compare the scaled value, unsigned, with `0x14`.

If the scaled value is below `0x14`, the common call receives zero and the extended path is skipped.

For a signed lower-word value from `-0x04000000` through `0x03ffffff`, the product fits signed 32 bits. Within that established multiplication domain, the unsigned scaled value is a multiple of 32, and the below-`0x14` branch occurs only for a zero product.

Outside that domain, signed multiplication overflows. The representation does **not** establish an unconditional modulo-\(2^{32}\) result or branch outcome.

### 4. Extended update path

For a scaled value at least `0x14`, the following order is represented:

1. Write the current address-like working value at scaled address plus `0x58`.
2. Write the active cursor’s low halfword at the old working value plus `0x0e`.
3. Replace the carried word with the old working value shifted left by 2 as an unsigned word.
4. Read the currently stored reset-associated byte.
5. Combine that read byte as the upper byte with the retained byte as the lower byte, then write the resulting reset-associated halfword.
6. Call F-06 with the active cursor shifted logically right by 2.
7. Call F-07 and capture its 64-bit result.

The reset byte read and halfword write are distinct accesses. No relationship proving that the read byte is the destination halfword’s existing upper byte is established.

Let the lower and upper words returned by F-07 denote its two pointer-like values. The next effects are:

1. Write the retained byte at twice the lower pointer.
2. Write the upper pointer’s low byte at lower pointer plus 8.
3. Write F-05’s destination pointer as a word at twice the current accumulator.
4. Write the complete 64-bit F-07 result at the lower pointer.
5. Replace the accumulator with four times F-05’s destination pointer, using the represented signed calculation.
6. Replace the address-like working value with the active cursor shifted left by 8.
7. Write three consecutive words at F-05’s destination:
   - The carried word, which holds the old working value shifted left by 2.
   - The **updated** working value.
   - The active cursor.

The working-value replacement precedes all three destination writes. That replacement also determines later common-continuation addresses unless the breakpoint path replaces it again. The cursor shift is expressed through a signed 32-bit value; arbitrary overflowing inputs do not have an established portable result.

A branch selector is then derived from the cursor using a signed left shift by 31, a signed right shift by 32, conversion to unsigned, and a logical right shift by 20. Its concrete result is unresolved.

If the selector is zero:

- Write the low halfword of the carried word multiplied by 256 to reset-associated storage.
- Add the carried word to the accumulator’s four-times-destination value.
- Write that sum through F-07’s upper pointer.
- Select zero as the common call argument.

Otherwise:

- Write the selector as a word at the carried-word-times-256 value plus `0x20`.
- Derive the common argument by signed right shift by 29 of the represented signed form of that times-256 value.
- Execute software breakpoint 4.
- If execution resumes, replace the working value with F-07’s upper pointer interpreted as signed and shifted right by 18.

The nonzero branch leaves the accumulator at its four-times-destination value. The zero branch additionally includes the carried word. These accumulator updates affect later passes.

### 5. Common continuation and loop-carried updates

F-08’s effective target depends on whether execution used the short path, extended zero-selector path, or breakpoint path. Its explicit argument is zero except on the breakpoint path.

After F-08 returns:

1. Write its lower result word’s low halfword at the address given by that lower word.
2. Write a self-addressing word at 64 times the current working value, using unsigned 32-bit multiplication.
3. Read and capture a word through the current active cursor.
4. Write the low halfword of the old cursor plus 4 at the current working value plus 4.
5. Read a replacement cursor pointer from F-08’s upper result word plus `0x50`.
6. Call F-09 without explicit arguments.
7. Call F-10 without explicit arguments.
8. Replace the byte source with the current carried word.
9. Call F-11 with the captured cursor word.
10. Set the next recurring argument to the captured word shifted logically right by 3.
11. Replace the carried word with the captured cursor word.
12. Repeat.

The byte-source assignment occurs **before F-11**; the carried-word replacement occurs **after F-11**. Consequently, the next pass retains a byte from the carried value preceding that replacement.

On an extended pass, that next byte comes from the old working value shifted left by 2. On a short pass, it comes from the carried word already present on entry to the pass. The newly captured cursor word becomes carried state for subsequent processing, not immediately the next byte source.

The captured cursor word survives as the represented argument and next-state source despite later memory changes by F-09 or F-10. The replacement cursor affects subsequent passes.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Entry capture.** If F-02 changes the seed storage and returns, subsequent seed-derived operations still use the captured seed. The scaled byte read can nevertheless observe memory changed by F-02.

2. **Setup comparison.** If the comparison address equals cursor plus 20, F-03 is skipped. Earlier setup writes remain required if reached successfully.

3. **Initial inner transition.** With successful accesses and a returning F-04, the initial zero shift produces no subtraction overflow. The zero-extended 16-bit destination receives the accumulator before recurring processing begins.

4. **Nonoverflowing scaling.** If F-05’s lower word is zero, a zero word is written at address zero before the short branch. If it is one, `0x20` is written at `0x20` before the extended path.

5. **Overflowing scaling.** A lower word of `0x08000000` makes the signed product exceed the signed 32-bit range. No scaled address or branch is guaranteed. Under an explicitly hypothetical wrapping interpretation, it would become zero; that is not established acceptance behavior.

6. **Working-value transition.** If the active cursor is `0x100` and the extended path reaches its destination writes, the updated working value is `0x10000`. Without a later breakpoint replacement, the common self-address store is at `0x00400000`, and the cursor-derived halfword store is at `0x00010004`.

7. **Retained-byte transition.** On the first extended pass, the initial working value shifted left by 2 is `0x225fc7e0`. If that pass completes, the following pass retains byte `0xe0`, even if F-11 received a cursor word with a different low byte.

8. **Reset read.** If the separately addressed reset byte reads as `0x7a` and the retained byte is `0xe0`, the first reset-associated halfword write has value `0x7ae0`. This does not establish preservation of any preexisting destination byte.

9. **Breakpoint boundary.** If execution stops at breakpoint 4, neither the subsequent working-value replacement nor the common continuation is required.
