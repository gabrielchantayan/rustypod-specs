# F-7389f1b2ad11

## Purpose

F-7389f1b2ad11 performs a state-dependent sequence of operations on caller-provided storage:

1. Either a direct byte transfer or an initial dependency call.
2. Zero or more processing calls.
3. One finalization call, provided execution reaches that phase.
4. An optional dependency call followed by zero or more in-place byte substitutions.

The function returns the 32-bit value zero whenever it reaches its explicit return. That value does not report dependency success, transfer length, processing progress, or output validity.

“Transfer,” “processing,” “finalization,” and “substitution” describe observable roles, not an identified algorithm. The evidence does not establish a file format, cryptographic operation, block size, or application-level purpose.

This contract specifies phase ordering, data dependencies, capture lifetimes, access widths, call arguments, and conditional effects. Exact numerical selection rules for the branches, loop boundaries, and lookup address remain **documented_only** here rather than being reproduced as renamed implementation expressions. Consequently, the acceptance examples are conditional, not a complete numerical oracle.

### Arithmetic model

The observable arithmetic is described using 32-bit words:

- Addition, subtraction, negation, and multiplication retain their low 32 bits.
- Bit operations act on those 32 bits.
- A signed-negative decision tests whether the resulting word has its top bit set.
- Address arithmetic is likewise 32-bit; wrapping does not make the resulting address valid.
- Direct data transfers and lookups access one byte at a time.
- A loaded byte is treated as an unsigned value from 0 through 255.

This describes the represented word-level behavior. It does not assert that unrestricted signed arithmetic in an independently written high-level implementation would have the same language semantics.

## Behavior

### Entry captures and initial choice

Before either initial path executes, the function captures four values in this order:

1. An entry seed from \(S_0\).
2. A processing-boundary value formed by adding argument 3 to another observation of \(S_0\).
3. A byte displacement derived from observations of \(S_0\), using exclusive-or and a signed right shift by 29 positions.
4. An initial transfer cursor from a subsequent observation of \(S_0\).

The seed, processing boundary, and displacement are retained values. Later external-state changes do not refresh them. The captures need not agree with one another if \(S_0\) changes between observations.

The initial decision consults the word addressed by argument 4, current observations of \(S_0\), and the captured displacement. Its 32-bit signed result selects one of two exclusive paths:

- A negative result selects the direct-transfer loop.
- A nonnegative result selects a call to F-d2332752ccd0.

The pointed-to word occurs more than once in the represented decision. A single read cached at function entry is not established.

The exact numerical classification of this decision remains documented_only. It must not be replaced by an assumed length, equality, or ordinary range comparison.

### Initial operation

On the dependency path, the function calls F-d2332752ccd0 with arguments 1, 7, and 2, in that order. Its return value is ignored. The direct-transfer loop is not also performed.

On the direct path, a boundary decision occurs before every byte transfer, including the first. That decision depends on the current transfer cursor and current observations of \(S_1\), \(S_2\), and \(S_3\). A negative result exits the loop; a nonnegative result permits one iteration.

Each permitted iteration:

- Reads one byte from argument 1 plus the current cursor plus the captured displacement.
- Writes that byte to argument 2 at the same effective offset.
- Advances the cursor by one plus the captured displacement plus the captured entry seed, with 32-bit wrapping.

The source read precedes its corresponding destination write. The function does not capture the whole source region before writing. Overlapping storage can therefore cause an earlier destination write to affect a later source read.

The advancement may wrap or equal zero. Neither the interface nor the supplied state definitions establish termination or a conventional contiguous transfer length.

The exact numerical boundary rule remains documented_only.

### Processing phase

After the initial operation finishes, the function captures a processing boundary offset equal to a read of \(S_4\) minus two. It then initializes the processing cursor from another read of \(S_4\). These are separate observations, not necessarily a single shared value.

Before each processing call, a boundary decision uses:

- The current processing cursor.
- The entry-captured processing boundary.
- The captured boundary offset.
- Current observations of \(S_5\).

A negative result ends processing. A nonnegative result causes F-d0d1ab73f88c to receive:

| Dependency position | Value |
|---|---|
| 1 | Argument 2 |
| 2 | Argument 9 |
| 3 | Argument 10 |
| 4 | Current 32-bit processing cursor |
| 5 | Argument 6 |
| 6 | Argument 8 |

The dependency return value is ignored.

After the call returns, the cursor advances by one plus a then-current read of \(S_7\) plus the captured entry seed. Thus, changes to \(S_7\) made by the dependency can affect the very next cursor value.

Neither the entry-captured processing boundary nor the captured boundary offset is refreshed after processing calls. The exact numerical boundary rule remains documented_only, and no finite call count is established.

### Finalization phase

Once processing terminates, F-eda87ef38dc8 is called with two arguments:

1. Argument 2.
2. Argument 8 plus 4096 times the quantity obtained by adding argument 3 to the captured boundary offset and subtracting 895.

The second argument is evaluated as a 32-bit word. Intermediate overflow does not produce an explicit error report.

This call occurs even if processing made no calls. Its return value is ignored. It is not reached if an earlier operation fails to return, faults, or loops indefinitely.

### Optional transformation

After finalization returns, the function captures a value from \(S_6\). This capture is retained for later lookup addressing.

The optional-path decision then consults:

- The word addressed by argument 5.
- The captured entry seed.
- Current observations of \(S_6\).

The decision contains a right shift by 30 positions whose signedness cannot be established from the supplied declaration information. The pointed-to word is referenced more than once; no single shared observation is guaranteed.

A negative decision skips the entire optional phase. A nonnegative decision first calls F-d2332752ccd0 with arguments 2, 11, and 2. Its return value is ignored.

The exact numerical decision rule, including the unresolved shift interpretation, remains documented_only.

After that dependency returns, the rewrite cursor starts at the captured entry seed. The earlier \(S_6\) capture remains in use even if the dependency changed \(S_6\).

Before each rewrite iteration, a boundary decision uses the current cursor, captured boundary offset, and current observations of \(S_8\), \(S_9\), and \(S_3\). A negative result exits without accessing a destination byte or lookup byte for that iteration.

Each permitted iteration has the following observable access sequence:

1. Form a destination address from argument 2, the current cursor, and a read of \(S_7\).
2. Read the byte at that address and retain the address for the later write.
3. Advance the rewrite cursor using one plus a fresh read of \(S_7\) plus the captured entry seed.
4. Read one lookup byte through argument 12 at a computed 32-bit offset.
5. Write that lookup byte to the retained destination address.

Cursor advancement precedes the lookup-byte read and final write. It does not change the retained destination address.

For lookup addressing, the original destination byte is first increased by 155 and reduced modulo 256. For example, an original value of 101 produces a transformed byte value of zero.

The lookup offset depends on that transformed byte, the pre-advancement cursor and its captured-boundary relationship, the captured boundary offset, the entry seed, the earlier \(S_6\) capture, and another observation of \(S_7\). The observations of \(S_7\) used for destination addressing, cursor advancement, and lookup addressing need not match.

The exact lookup-offset rule and rewrite-boundary rule remain documented_only. In particular, the lookup cannot be specified as a simple 256-entry substitution indexed only by the original byte.

## Side effects

Directly visible effects include:

- External-state reads.
- Word reads through arguments 4 and 5 at their respective phases.
- Conditional byte reads and writes through arguments 1, 2, and 12.
- Calls to three dependencies in the order described above.

There is no explicit assignment to a named external word. Nevertheless, byte destinations may alias external storage, and dependencies may mutate external words. External state must not be assumed unchanged.

No allocation or release is directly visible. This establishes neither ownership transfer nor its absence inside dependencies. In particular, passing argument 2 in both the first and third positions of the optional F-d2332752ccd0 call does not prove alias safety or continued storage validity.

Argument 12 may alias destination storage. Its byte is read before the corresponding destination write, but earlier iterations or dependency calls may already have changed that storage.

There is no rollback or error translation. Effects completed before a fault, nonreturning call, or nonterminating loop remain observable.

## Acceptance examples

These are conditional requirements, not executed tests.

1. **Alternative initial path.** Given a nonnegative initial decision, F-d2332752ccd0 receives arguments 1, 7, and 2. No direct-transfer iteration occurs.

2. **Empty direct transfer.** Given a negative initial decision followed by a negative first transfer boundary, neither a source byte nor destination byte is accessed by the transfer loop. The alternative initial call does not occur.

3. **Overlapping transfer.** If a completed destination write changes a location read by a later transfer iteration, that later read is not required to recover the location’s entry-time contents.

4. **Empty processing phase.** Given a negative first processing boundary, F-d0d1ab73f88c is not called. Finalization still occurs if execution proceeds normally.

5. **State changed by processing.** If a processing call changes \(S_7\), the post-call advancement uses the subsequently observed value, not an entry-time snapshot.

6. **Finalization argument wrap.** If computing the finalization argument exceeds the 32-bit word range, the dependency receives the low 32 bits. No overflow status is returned.

7. **Skipped optional phase.** Given a negative optional decision, there is no later F-d2332752ccd0 call and no rewrite lookup.

8. **Enabled but empty rewrite.** Given a nonnegative optional decision and a negative first rewrite boundary, the later F-d2332752ccd0 call occurs, but no rewrite destination or lookup byte is accessed by the loop.

9. **Byte reduction.** If a rewrite reads destination byte 101, its lookup-address contribution uses transformed byte zero. This does not establish lookup offset zero.

10. **Retained destination.** If \(S_7\) changes after destination addressing, the iteration still writes to the retained address. Later uses of \(S_7\) may affect advancement or lookup addressing instead.

11. **Captured lookup state.** If the optional dependency changes \(S_6\), lookup addressing still uses the value captured before that call.

12. **Normal return.** If all reached accesses complete, all dependencies return, and all reached loops terminate, the result is zero regardless of dependency return values.
