# F-1316e89b887b

## Purpose

F-1316e89b887b performs an ordered sequence of indirect dependency invocations, transforms their results and incoming execution-state values, and then mutates memory through computed and fixed addresses. It ends with an unresolved indirect transfer carrying four explicit arguments.

**Established static evidence:** no explicit parameters or return value are represented. Observable operations include dependency calls, 8-, 16-, and 32-bit memory accesses, repeated writes, a consequential 32-bit global read, and the terminal transfer.

**Inferred intent:** masks and shifts suggest packed-value manipulation; recurring offsets suggest structured storage. Neither observation establishes a protocol, object model, device interface, or application purpose.

This contract describes supported access-order and value-origin constraints. It does not establish that the represented execution is safe, that its control flow is complete, or that repeated accesses can be removed.

## Behavior

### Dependency-call phase

The visible direct-memory phase follows a long ordered call phase. The first indirect destination is the incoming control-link value plus 4094. Later destinations predominantly use embedded control-location values plus the same displacement; no function-pointer-table load is demonstrated.

The early call sequence establishes these constraints:

- Two calls with no explicit arguments precede the third call, whose primary result is retained.
- That result, shifted left by eight bits, becomes the next call’s argument.
- After two intervening calls, that retained shifted result is shifted left by another seven bits and supplied twice in one argument list.
- Independently, the incoming register-carried value is shifted left by twelve bits for later arguments.
- Later argument lists combine newly returned values, retained values, secondary result components, and explicit zeros.

Calls have zero through four explicit arguments. Many paired-result consumers use a shifted low word together with the unchanged or separately shifted high word. Other calls expose secondary register-carried values without a fully established result convention.

Similar arguments do not establish identical dependencies. Calls with unused results still occur and may have side effects. No visible success-status branch, retry, cancellation, or rollback is represented.

### Arithmetic and truncation

Unsigned 32-bit arithmetic must retain its finite width. Discarded high bits are not restored by a later right shift. In particular, left-shifting a 32-bit value by eight and then logically right-shifting by eight retains only the original low 24 bits.

For a 64-bit unsigned paired result, right shifts by 34, 36, and 44 bits yield its high 32-bit portion logically shifted right by 2, 4, and 12 bits, respectively.

Other established numerical constraints include:

- A 24-bit mask retains bits 0–23.
- A 22-bit mask retains bits 0–21.
- A 20-bit mask, followed by a logical right shift of ten and a left shift of six, produces a multiple of 64 from 0 through 65,472.
- A 19-bit mask followed by a left shift of two produces at most 2,097,148.
- Two successive 28-bit left shifts produce zero under 32-bit bit-vector semantics.

Some arithmetic is represented as signed 32-bit arithmetic. Signed overflow, signed left shifts, and target address-wrap behavior are not resolved by this material. Examples involving potentially overflowing arithmetic are conditional on an explicitly stated bit-vector interpretation.

### Entry into direct memory mutation

The first direct accesses use several distinct retained bases. In particular, the base obtained from multiplying the latest low result by 256 is not interchangeable with the separately retained base obtained by multiplying an earlier primary result by 33,554,432.

The initial access ordering is significant:

- A retained 32-bit value is written at offset 20 from the latest paired result’s high-word base.
- The low byte of that high word is written at offset 9 from another retained base.
- The earlier primary result multiplied by 33,554,432 is written at offset 84 from the latest low result multiplied by 256.
- The offset-9 byte destination is overwritten with the low byte of another retained value.

The function then clears the offset-20 word of the separately retained, 33,554,432-scaled base; reads its offset-5 byte; clears another computed offset-20 word; and writes the unsigned byte value as a word at offset 52 of the 33,554,432-scaled base. It subsequently reloads that base’s offset-20 word.

These reads and writes cannot be collapsed into a final-memory description. Aliasing or access-sensitive storage may distinguish them.

### Earlier fixed-address read and following mutations

After another clear and two consecutive byte writes at a computed offset-21 destination, the function reads the byte at fixed address 5. The next represented memory access writes a byte at fixed address 1, using the low byte of a retained doubled address component.

The address-5 read therefore precedes the address-1 write and the following computed-address mutations. Its zero-extended value supplies a base for an offset-21 byte store and later an offset-84 word load and overwrite.

Between that fixed read and the offset-84 load, the function also writes and clears a computed offset-17 byte and performs an offset-84 word store elsewhere. These mutations can alias storage used by subsequent reads. The retained address-5 value must not be replaced with a later read of address 5.

The ensuing region interleaves word loads at offsets 4, 100, and 116 with mixed-width stores. It includes repeated self-referential word writes at offset 36, byte writes at offsets 9 and 21, and successive assignments to the same offset-20 and offset-84 words. A word at fixed address 84 receives twice a retained word value; a later byte write targets fixed address 21.

No list, allocator, ownership, or object-initialization protocol is established by these patterns.

### Literal writes and the consequential global read

A later region writes numerical 58 as:

- A byte at a computed address.
- A halfword at another scaled address.
- A word at offset 32 from the first computed address.

A subsequent computed word destination receives 32, then 47, then the zero-extended byte freshly read at offset 4 of its base, then 32 again. The byte read occurs between the second and third word writes.

Only after that fourth word write does the function read the 32-bit global at 0x087FBBBC. The next represented memory access writes the word value 32 at fixed address 96.

The loaded global value becomes the retained **global-derived base**. This is a read at the stated point, not an entry-time snapshot and not a constant. Earlier dependency effects or aliasing stores may affect its observed value.

### Repeated-write region

For describing value origins, the **retained seed** is an earlier loaded 32-bit word. The **adjusted quantity** is four times that seed minus 150. Four times the adjusted quantity supplies a **reciprocal base**.

After the global read and address-96 write, the first four-write group has this observable structure:

|---|---|---|
| Word write | Eight times the retained seed, plus 84 | A retained scaled word |
| Byte write | Global-derived base, plus 25 | Low byte of the reciprocal base |

The following repeated groups use eight times the adjusted quantity for both the first write’s scaled base and the fourth write’s word value. Their two intervening byte writes retain the same origins described above.

The first offset-52 value and subsequent offset-52 values have **different derivations**, not necessarily different numerical values. If the retained seed is 50, its quadruple minus 150 is also 50; both derivations then supply 400.

The global-derived base is retained from the single global read. No fresh global read is represented within the repeated groups. A write aliasing the global’s storage does not, by itself, change that retained base.

### Final fixed-storage ordering and fresh reads

The final region begins with a word read at fixed address 169. Its full value and low byte are retained for different later uses.

A computed offset-116 word load follows that fixed read, before the byte write at fixed address 58. The address-58 byte is derived from eight times the adjusted quantity plus 48, truncated to eight bits.

After the address-58 write, the function loads an offset-20 word from another retained base and an offset-4 word from the reciprocal base. It then performs several computed byte and word mutations, including a byte write of 108, before writing the retained low byte from the address-169 word to fixed address 103.

The first address-103 byte read occurs **after** a computed offset-68 word load. Its result is copied to fixed address 33. This copy is therefore not an unconditional reuse of the originally retained address-169 low byte.

Two further address-103 byte reads supply two later byte stores at offset 9 of the reciprocal base:

- The second read follows intervening computed stores, an offset-64 word load, and further word stores.
- The third read follows another byte store, a word store carrying the retained full address-169 value, and an offset-84 word load.

These are three distinct reads of address 103, separated by memory operations. Without a non-aliasing and stability guarantee, none may be replaced by the originally retained byte or by another read’s result.

One intervening byte store uses a signed right shift of a loaded 32-bit word. Its shift count comes from the low eight bits of the reciprocal base and can exceed 31. The result for such counts is **documented_only**.

### Terminal mutations and transfer

The function continues copying retained words and low bytes among offsets 9, 13, 16, 17, 68, 84, and 116. A freshly loaded offset-84 word supplies another destination base.

Near completion:

- A word loaded at offset 4 of a retained base is doubled to form the destination of a 16-bit store of 101.
- That loaded word also supplies a base for word reads at offsets 100 and 116.
- A computed offset-84 word receives 100.
- A further offset-100 word load supplies a destination base for storing the retained offset-100 value at offset 84.
- Twice the retained offset-100 value supplies another word-store destination.

The terminal dependency receives, in order:

1. Numerical 114.
2. The retained word read at offset 100 from the base obtained by the near-terminal offset-4 load.
3. The earlier offset-20 word read after the fixed address-58 write.
4. The retained word read at offset 116 from the same base used for argument 2.

These are retained load results, not permission to reload memory at the transfer boundary. Actual transfer mechanism, destination, and return behavior remain unresolved.

## Acceptance examples

These are conditional static acceptance criteria. **No runtime tests have been performed.**

### Finite-width shift

If F-U002 supplies 0x00123456, its immediate shifted consumer receives 0x12345600 under 32-bit bit-vector semantics. A supplied value of 0xFF123456 produces the same shifted argument under that interpretation.

### Byte propagation

A byte store supplied with 0x123456AB writes 0xAB, not four bytes. If the early computed offset-5 unsigned byte read returns 0xE7, the subsequent word propagation supplies numerical 231.

### Equal results from different origins

If the retained seed is 50 and the relevant arithmetic is defined, the adjusted quantity is also 50. The first and later repeated-region offset-52 writes may all supply 400. Requiring unequal values would reject behavior supported by the evidence.

### Global-read timing

If an earlier aliasing write changes the word at 0x087FBBBC, the repeated region uses the value observed after the four-word literal sequence, not an entry-time value. The word write of 32 at address 96 follows that global read.

### Earlier fixed-byte timing

An access observer must see the address-5 byte read before the address-1 byte write and before the subsequent computed mutations. Reading address 5 only after those mutations does not preserve the established ordering.

### Final fixed-storage trace

An observer must see the address-169 word read before the address-58 byte write. The later address-103 byte write uses the retained word’s low byte.

The copy to address 33 uses a fresh address-103 read after the intervening computed word load. If permitted aliasing mutations change address 103 before either later read, each later computed byte store uses its own newly read value.

### Read after clear

An earlier cleared word reloads as zero only if it is ordinary stable memory and no intervening operation aliases or otherwise changes it. The clear alone does not establish the later value.
