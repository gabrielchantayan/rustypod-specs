# F-f106740c25de

## Purpose

F-f106740c25de performs an ordered update of an address-designated object. It invokes an operation on an embedded location, queries the object, conditionally decreases two 32-bit fields, and may invoke another object-level operation. It then decreases a third 32-bit field and conditionally dispatches through a function-pointer slot at global address `0x08037E14`.

The final dispatch requires both a non-null pointer at object offset `0x2C` and a nonzero 32-bit integer at the address designated by that pointer. The global target slot is read only after those conditions succeed.

These operations establish an access and control-flow contract, not the semantic purpose of the object. Container removal, cursor movement, reference counting, and resource release are possible interpretations but are not established behavior.

## Behavior

### Initial embedded-location operation

The first operation is a call to F-4a19e3742733 with the address of object offset `0x2C`.

This supplies the location’s address, not the pointer value stored there. The function does not first read the location’s contents or check whether they are null.

The dependency’s effects are unknown. It may change the embedded location, other object storage, referenced storage, or global state, including the target slot at `0x08037E14`. No preservation or ownership guarantee may be assumed.

### First object query

After the initial dependency returns, F-be518f1dc9cf is called with the object base.

Only whether its result is zero matters. Nonzero results are treated alike regardless of sign or magnitude.

If the first result is nonzero, this function skips:

- Both direct updates at `0x10` and `0x20`.
- The second query.
- The comparison involving `0x10` and `0x14`.
- The call to F-8af476964e3d.

Execution then proceeds to the update at `0x34`. These skipped actions describe this function’s behavior, not restrictions on actions performed inside dependencies.

### Conditional updates

If the first query returns zero, two ordered read-modify-write operations occur:

1. The 32-bit integer at `0x10` is read, decreased by four, and written back.
2. The 32-bit integer at `0x20` is read, decreased by one, and written back.

The write to `0x10` precedes the update at `0x20`. Both updates complete before the second query is invoked.

The represented operation at `0x10` is integer arithmetic, not typed pointer arithmetic. Its decrement of four does not establish an element size, pointer type, or movement through an array.

No local boundary check is present. For values whose mathematical result is representable as a signed 32-bit integer, the subtraction determines the resulting value. ### Second query and optional object operation

After both conditional updates, F-be518f1dc9cf is called again with the object base.

The invocation condition for F-8af476964e3d is short-circuited:

- A nonzero second query result causes the call without requiring reads of the comparison fields.
- A zero second query result causes the 32-bit fields at `0x10` and `0x14` to be compared. Equality causes the call; inequality skips it.

The equality comparison uses values read after the second query returns. The function must not substitute a value retained from before that call. For example, the second query may change `0x10` after the local decrease.

The relative order of the two comparison operand reads is not established. The comparison itself does not write either field.

F-8af476964e3d receives the object base and is invoked at most once by this function. Its effects, preservation guarantees, and return behavior are unknown.

### Final direct update

After the preceding path completes, the function reads the 32-bit integer at `0x34`, decreases it by one, and writes it back.

This update occurs whether the first query was zero or nonzero and whether F-8af476964e3d was called. It occurs only if execution reaches this stage: a non-returning dependency or failed earlier operation prevents later actions.

The value decreased is the value present at this point. An earlier dependency may have changed it. Arithmetic-boundary uncertainty is the same as for the conditional decreases.

### Pointer gate, integer gate, and global dispatch

After the write to `0x34`, the function reads the current pointer-bearing value at `0x2C`.

If the pointer is null:

- No pointed-to integer is read.
- The global function-pointer slot at `0x08037E14` is not read by this function.
- No final indirect dispatch occurs.

If the pointer is non-null, one 32-bit integer is read from the address it designates.

If that integer is zero:

- The global target slot is not read by this function.
- No final indirect dispatch occurs.

If that integer is nonzero:

1. The function reads the function-pointer slot at global address `0x08037E14`.
2. It dispatches through the target obtained from that slot.

Thus, the dispatch address comes from the known global slot, not from the object pointer or the integer read through that pointer. The integer is only a zero/nonzero gate.

The global read follows the successful pointer and integer checks. Earlier dependencies may modify that global slot, so using a target cached before those calls is not justified. The applicable target is the slot’s contents when the final read occurs.

There is no explicit validity or null check on the target obtained from the global slot. No explicit argument is shown at the invocation site. Callee identity, complete argument state, calling convention, and whether the transfer returns normally remain documented_only.
