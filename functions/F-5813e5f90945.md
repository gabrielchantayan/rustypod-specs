# F-5813e5f90945

## Purpose

F-5813e5f90945 conditionally invokes F-d3922c7fe0ec repeatedly and returns the number of those invocations that return a nonzero integer.

The condition for entering this process is an integer read from an address four bytes beyond the supplied base value. If that initial integer is zero, the function returns zero without invoking the dependency. Otherwise, the function passes the address of a mutable local integer to the dependency until an invocation returns zero.

The supplied evidence establishes a counting loop, not the meaning of the values being processed. Interpreting the initial integer as a cursor, handle, link, or collection position is **inferred intent**, not an established contract. Likewise, the returned count is not necessarily a collection size: that interpretation would require additional evidence about F-d3922c7fe0ec.

## Behavior

### Initial access and local state

The function first reads the integer at the derived address and copies it into a local integer slot. It then initializes a separate local counter to zero.

The initial read is unconditional. A base value that appears empty or invalid does not cause an early return before that read. The zero check applies to the loaded field, not to the supplied base.

The visible function reads the input field once. Its subsequent decisions use the local copy and dependency return values. It does not visibly reload the field or write the local copy back to the original field.

### Zero initial value

If the loaded integer is zero, the function returns the zero counter immediately.

In this case:

- F-d3922c7fe0ec is not invoked.
- The local slot’s address is not passed to the dependency.
- No direct write to caller-provided storage is shown.

The initial memory read still occurs.

### Nonzero initial value

If the loaded integer is nonzero, the function invokes F-d3922c7fe0ec with the address of the local integer slot. That slot initially contains the loaded value.

The dependency’s integer result controls the loop:

- A nonzero result causes the counter to increase by one, followed by another dependency invocation.
- A zero result ends the loop and causes the current counter to be returned.

Every invocation receives the address of the same local slot within that execution of F-5813e5f90945. If the dependency changes the slot, the changed value remains in that slot for the next invocation unless the dependency changes it again.

The initial field’s nonzero condition is checked only before entering the loop. The function does not independently recheck the slot after each dependency call. Consequently:

- A dependency may set the slot to zero and return nonzero; the function still counts that call and invokes the dependency again.
- A dependency may leave the slot nonzero and return zero; the function still stops.
- A dependency need not visibly advance or modify the slot for a nonzero return to be counted.

Dependency results are interpreted only as zero versus nonzero. Negative results are counted in the same way as positive results. A negative dependency result is not visibly treated as an error.

### Ordering and call counts

The established logical order is:

1. Read the initial integer from the derived address.
2. Initialize the counter.
3. Check whether the loaded value is zero.
4. If nonzero, invoke the dependency.
5. After each nonzero return, increment the counter before the next invocation.
6. After a zero return, return the counter without incrementing it.

For a nonzero initial field, normal completion with a returned count of *n* requires *n* nonzero dependency returns followed by one zero return. Thus, the total number of dependency invocations is one greater than the returned count, assuming representable counting arithmetic and ordinary completion.

Once the required count exceeds the signed type’s range, a portable result is not specified. A contract must not promise a negative wrapped result or continued correct counting beyond that boundary.
