# F-6b976a6e2be2

## Purpose

F-6b976a6e2be2 conditionally produces one 16-bit output unit using values supplied by an object’s indirect operations. Its masks and shifts resemble one-, two-, and three-byte UTF-8 decoding, but the established behavior neither requires byte-sized inputs nor validates UTF-8.

The function obtains between one and three values on normally returning paths. It either combines selected bits, emits the low 16 bits of its first-value storage, or reports acquisition failure. On an unrecognized-prefix path, it makes two additional indirect calls before reading first-value storage for output.

The distinction between **storage** and **acquisition-time values** is essential. Dependencies receive addresses of temporary storage. Later dependencies can potentially modify previously exposed storage through retained addresses while that storage remains live. Branches, arguments, output, and the return’s high half use contents at their respective read points—not necessarily the values originally acquired.

Character decoding and input restoration are inferred intent. The call sequence, masks, explicit writes, and return construction are established static behavior.

## Interface

### Arguments and representation

The supplied representation exposes four arguments:

| Argument | Role | Represented width |
|---|---|---|
| Object address | Supplies indirect dispatch and receives a conditional state write | 32-bit address |
| Output address | Destination for the successful result | 32-bit address |
| Second-value seed | Initial contents of second-value storage | 32 bits |
| First-value seed | Initial contents of first-value storage | 32 bits |

“First” and “second” describe acquisition order, not argument order.

Three temporary storage locations are relevant:

- **First-value storage:** initialized from the fourth argument.
- **Second-value storage:** initialized from the third argument.
- **Third-value storage:** initialized with the 32-bit representation of the output address.

The original output address remains the output destination even after third-value storage has been changed.

The object’s first 32-bit word supplies a dispatch-table address. Relevant table entries are selected at byte offsets `0x24` and `0x08`. A conditional error write targets one byte at object offset `0x04`.

These widths describe the supplied 32-bit representation, not a portable object layout or a 64-bit pointer ABI.

### Result

The function returns a 64-bit quantity constructed from two 32-bit halves:

| Outcome | Low half | High half |
|---|---:|---|
| Success | `1` | Then-current contents of third-value storage |
| Failure | `0` | Then-current contents of third-value storage |

The high half is not established as an independent status. If third-value storage has not been modified, it contains the output address representation. After its address has been supplied to a dependency, its contents may differ on either success or failure.

The return construction occurs after the successful output store, or after any applicable failure-state write. A failed invocation can therefore return a nonzero 64-bit quantity. Only the low 32 bits provide the established success indication.

Success includes one direct 16-bit store through the original output address. Failure includes no direct output store.

### Preconditions

Ordinary defined execution requires:

- Readable object and dispatch-table storage for every reached dispatch lookup.
- Callable entries compatible with the supplied object, temporary-address, or integer arguments.
- A writable output destination for a reached 16-bit store.
- A writable object byte at offset `0x04` when a second or third acquisition fails.
- Dependency accesses to temporary storage that remain within valid storage and lifetime.

No explicit null, bounds, alignment, or dispatch-validity checks are present. Fault handling and abnormal dependency termination are not established.

## Behavior

### Initialization and first acquisition

The three temporary locations are initialized as described above. The function then invokes F-dep-A with the object address and the address of first-value storage.

A zero dependency result causes immediate failure:

- No direct output store occurs.
- No direct write to the state byte occurs.
- The return’s high half comes from third-value storage.

Any nonzero dependency result permits processing to continue. Negative and positive nonzero results are not distinguished.

After the first call returns successfully, the function reads first-value storage and tests bit 7.

If bit 7 is clear, no further dependency is called. The function stores the then-current low 16 bits of first-value storage through the output address and returns success.

This is not a whole-value range check. For example, `0x00000141` has bit 7 clear and yields `0x0141` under ordinary preservation assumptions.

### Second acquisition and two-value combination

If the bit-7 test found that bit set, F-dep-A is invoked with the address of second-value storage.

This call occurs **before** testing the two-value prefix. During it, first-value storage is still live, and its address has already escaped to a dependency.

If the second call returns zero:

1. The function writes byte value `1` at object offset `0x04`.
2. It performs no direct output store.
3. It returns failure.

There is no direct restoration call on this path.

If the second call returns nonzero, the function reads the **post-second-call** first-value storage and tests:

\[
(\text{first} \mathbin{\&} \texttt{0xE0}) = \texttt{0xC0}.
\]

The value tested need not equal the value used for the earlier bit-7 decision. The function does not repeat the bit-7 test.

If this prefix condition holds, the function forms:

\[
((\text{first} \mathbin{\&} \texttt{0x1F}) \ll 6)
\mathbin{|}
(\text{second} \mathbin{\&} \texttt{0x3F}).
\]

Both operands come from storage after the second acquisition has returned. The result fits within 11 bits. It replaces the low 16 bits of first-value storage; this direct update does not replace that storage’s upper 16 bits.

The function then stores the low 16 bits of first-value storage through the output address and returns success. No third acquisition occurs.

The second value is not checked for a continuation prefix. Overlong sequences are not rejected.

### Third acquisition and three-value combination

If the post-second-call two-value prefix test fails, F-dep-A is invoked with the address of third-value storage.

If this call returns zero, the function writes byte value `1` at object offset `0x04`, performs no direct output store, and returns failure. Any contents left in third-value storage—including contents written by the failing call—supply the return’s high half.

If the third call returns nonzero, the function reads the **post-third-call** first-value storage and tests:

\[
(\text{first} \mathbin{\&} \texttt{0xF0}) = \texttt{0xE0}.
\]

Earlier first- and second-value addresses have escaped. The third call may therefore affect the values used by this test and the following combination. Neither earlier prefix test is repeated.

When the three-value prefix condition holds, the resulting 16-bit unit is:

\[
((\text{first} \mathbin{\&} \texttt{0x0F}) \ll 12)
\mathbin{|}
((\text{second} \mathbin{\&} \texttt{0x3F}) \ll 6)
\mathbin{|}
(\text{third} \mathbin{\&} \texttt{0x3F}).
\]

The low-nibble restriction on the first operand expresses truncation to the 16-bit destination: higher shifted bits do not survive. Operands are read after the third call; no acquisition-time snapshot is established.

The result replaces the low 16 bits of first-value storage. Its upper 16 bits are not directly replaced. The function then performs the 16-bit output store and returns success.

There is no continuation-prefix validation, overlong-sequence rejection, or surrogate exclusion.

### Unrecognized-prefix path

If the post-third-call three-value prefix test fails, the function makes two calls through F-dep-B:

1. It reads third-value storage, takes its low 16 bits, zero-extends them to a 32-bit argument, and makes the first call.
2. **After that call returns**, it reads second-value storage, takes its low 16 bits, zero-extends them to a 32-bit argument, and makes the second call.
3. **After both calls return**, it reads first-value storage and writes its then-current low 16 bits through the original output address.
4. It returns success, using the then-current third-value storage for the high half.

Both dependency results are ignored.

The arguments are not both captured before the first call. That call may change second-value storage through a retained address, affecting the next argument. Either call may change first-value storage, affecting output, or third-value storage, affecting the returned high half. A change made during the first call cannot retroactively change the argument already passed to that call.

Only with an explicit preservation assumption does this path emit the first acquired value and offer the third and second acquired values in reverse order.

The sequence is consistent with lookahead restoration through a stack-like interface, but restoration is not established. Byte-range inputs resembling continuation bytes or four-byte UTF-8 leaders can enter this path. There is no fourth acquisition.

## Side effects

### Direct memory changes

The function directly performs:

- Initialization of three temporary locations.
- A low-16-bit update to first-value storage on either recognized combination path.
- One 16-bit output store on success.
- One byte store of `1` at object offset `0x04` after a failed second or third acquisition.

The function does not explicitly clear the state byte on entry or success. A previously set byte can remain set.

“No direct output store on failure” does not guarantee unchanged output memory. Dependencies may modify it, and the output destination may alias other affected storage. For example, if it overlaps the state byte, the failure-state write can alter output memory despite the absence of an output store.

### Observable ordering and escaped storage

The dependency-sensitive sequence is:

| Read or action | Position |
|---|---|
| First bit-7 test | After first acquisition, before second acquisition |
| Two-value prefix test and combination | After second acquisition |
| Three-value prefix test and combination | After third acquisition |
| First fallback argument | Before first F-dep-B call |
| Second fallback argument | After first F-dep-B call, before second |
| Fallback output-value read | After both F-dep-B calls |
| Return high-half read | At return construction |

The representation establishes these call boundaries, not a separate operand-by-operand ordering within each arithmetic expression.

Temporary addresses supplied to dependencies remain live during subsequent calls in this invocation. Preservation of those temporaries is not guaranteed merely because they belong to this function. Conversely, retaining an address does not establish permission to use it after its lifetime ends.

Each indirect call uses the object’s dispatch information at that call site. The function does not cache one target for the entire invocation. Dependency changes to the object or table can affect later dispatch.

### Ownership

The function body contains no explicit allocation, release, destruction, or ownership transfer. It does not establish that dependencies preserve globals, preserve unrelated object fields, or refrain from allocating or releasing memory.

No transactional rollback of dependency effects is present.

## Dependencies

The following opaque IDs identify dispatch roles, not recovered implementations:

| ID | Selection | Observed contract |
|---|---|---|
| F-dep-A | Dispatch-table byte offset `0x24` | Receives the object and a temporary-storage address. Its represented 32-bit result is tested for zero versus nonzero. |
| F-dep-B | Dispatch-table byte offset `0x08` | Receives the object and a zero-extended 16-bit value in a 32-bit argument. Its result is ignored. |

On normally returning executions, F-dep-A is invoked one to three times. F-dep-B is invoked exactly twice on the unrecognized-prefix success path and otherwise not invoked.

Unknown dependency properties include write width, failure-write behavior, consumption, restoration, retained-address use, global changes, ownership effects, and abnormal termination. The same dispatch role need not resolve to the same implementation on later calls.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless an example states otherwise, assume acquisitions write the complete indicated 32-bit value, all dependencies return normally, dispatch remains valid, and dependencies preserve all other storage. Also assume the output destination does not alias the object or temporary storage. Let \(D\) denote the 32-bit output address representation.

1. **First acquisition fails.**  
   F-dep-A returns zero. There is no direct output or state-byte store. Return halves are high \(D\), low `0`.

2. **Bit-7-clear value with upper bits set.**  
   The first acquisition supplies `0x00000141` and succeeds. Output is `0x0141`, only one acquisition occurs, and return halves are high \(D\), low `1`.

3. **Two-value combination without continuation validation.**  
   Successful acquisitions supply `0xC2` and `0x41`. Output is `0x0081`; there is no third acquisition.

4. **Three-value combination.**  
   Successful acquisitions supply `0xE2`, `0x82`, and `0xAC`. Output is `0x20AC`; return halves are high `0x000000AC`, low `1`.

5. **Surrogate accepted.**  
   Successful acquisitions supply `0xED`, `0xA0`, and `0x80`. Output is `0xD800`, and success is reported.

6. **Fallback with preservation.**  
   Successful acquisitions supply `0xF0`, `0x90`, and `0x80`. F-dep-B receives `0x80`, then `0x90`. Output is `0x00F0`, and the return high half is `0x00000080`. No fourth acquisition occurs.

7. **Second acquisition changes first-value storage.**  
   The first acquisition supplies `0xF0`. During the second acquisition, the dependency writes `0xC2` through the retained first-storage address and supplies second value `0xA2`. The post-call two-value test succeeds. Output is `0x00A2`; no third acquisition occurs.

8. **Third acquisition changes the prefix decision.**  
   The first two acquisitions supply `0xF0` and `0x82`. The third supplies `0xAC` and changes first-value storage to `0xE2`. The post-third-call three-value test succeeds, producing `0x20AC`. No F-dep-B call occurs.

9. **Fallback calls modify later reads.**  
   Acquisitions initially supply `0xF0`, `0x90`, and `0x80`. The first F-dep-B call receives `0x80`, then changes second-value storage to `0x12345678` and third-value storage to `0xABCDEF01`. The second F-dep-B call consequently receives `0x5678`; during that call it changes first-value storage to `0x00001234`. Output is `0x1234`, and return halves are high `0xABCDEF01`, low `1`.

10. **Second acquisition fails.**  
    The first acquisition supplies `0xC2` and succeeds; the second returns zero. The state byte becomes `1`; no direct output store or F-dep-B call occurs. The low return half is `0`.

11. **Third acquisition writes and fails.**  
    A third acquisition is reached, writes `0x12345678` to third-value storage, and returns zero. The state byte becomes `1`; no direct output store occurs. Return halves are high `0x12345678`, low `0`.
