## Behavior

2. Its result is used as the destination address.
3. A four-byte value is read from the global source location.
4. That value is written to destination offsets 0–3.
5. The second input is written to destination offsets 8–11.
6. The function returns without an explicit result value.

This sequence matters in several ways.

**The global source is read after the dependency returns.** The wrapper does not visibly capture that value before calling the dependency. If the dependency changes the global source and then returns normally, the first destination write uses the value available at the subsequent read, subject to the execution environment’s memory semantics.

**The two destination writes are ordered.** The offset-0 write precedes the offset-8 write in the supplied representation. The function does not present the two fields as a transactional update. There is no visible rollback if execution cannot complete the second write.

**The second input is used without a visible value transformation.** Its 32-bit value is assigned to the offset-8 field. No truncation to a smaller field, sign extension to a larger field, masking, range check, or arithmetic adjustment is shown.

**The original destination fields are not inspected.** The wrapper does not visibly branch on prior contents or read either destination field before replacing it. It also does not visibly initialize the four-byte gap between them.

**There is no input-dependent branch in the wrapper.** Zero, high-bit-set, or otherwise unusual input values do not select a different wrapper path. Whether such values are acceptable to the dependency remains unknown.

The established order is the order represented by the supplied static evidence. It does not establish machine-level atomicity, synchronization, or a cross-thread visibility guarantee.
