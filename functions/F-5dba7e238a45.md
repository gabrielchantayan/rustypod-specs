## Behavior

### 1. Capture the four source values

The function reads the four source-designated 32-bit values and places them into four consecutive 32-bit words in temporary storage.

The reads occur in the order corresponding to the first, second, third, and fourth words. Each word receives its own source value before the transformation begins.

These are value copies. Subsequent changes to the original source storage do not, by themselves, replace the captured temporary values. This does not imply that the dependencies cannot access or modify the source storage independently.

The supplied evidence does not reveal the numeric contents of the four source values. It also does not establish that those values remain constant across invocations.

### 2. Transform the captured words

Each captured word is independently shifted right by one bit using unsigned 32-bit semantics.

For a captured value \(x\), the resulting word is:

\[
\left\lfloor \frac{x}{2} \right\rfloor
\]

The high bit is filled with zero, and the original least-significant bit is discarded. There is no carry or bit transfer between adjacent words.

The temporary words are processed in reverse address order:

1. Fourth word.
2. Third word.
3. Second word.
4. First word.

All four transformations complete before any dependency is called. Although this reverse order does not change the final values of independent words, it is the store order established by the supplied representation.

This operation is not a right shift of a single combined 128-bit quantity. It is also not an arithmetic right shift of signed values.

### 3. Write the following zero byte

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

### Independent unsigned transformation

If the captured words, in increasing address order, are:

| Position | Captured value | Value after transformation |
|---|---:|---:|
| First | `0x00000000` | `0x00000000` |
| Second | `0x00000001` | `0x00000000` |
| Third | `0x80000000` | `0x40000000` |
| Fourth | `0xFFFFFFFF` | `0x7FFFFFFF` |

then the transformed-data region must contain those four resulting word values before the dependency calls, subject to the target’s native byte representation.

A fourth-word result of `0xFFFFFFFF` would incorrectly apply signed shift behavior. Movement of discarded bits into neighboring words would incorrectly treat the region as one multiword integer.

### Reverse transformation order

If an observation mechanism can distinguish temporary-word writes, the shift-and-store operations occur in fourth-to-first order. The zero byte at offset 16 is written after all four transformations.

### Embedded zero bytes

If one transformed word is zero, the region contains zero bytes within its first 16 bytes, not merely at offset 16.

If F-42999360227b interprets the region as zero-terminated bytes, it may stop before offset 16. If it uses another interpretation, its consumption may differ. Neither behavior is selected by this function’s evidence alone.

### Destination changed by a dependency

If the third call supplies byte `0xA5`, the final direct write is `0xA5` at region B’s offset 40. Using the initially selected region A would contradict the established post-call destination selection.

### Result byte stored without interpretation

### Dependency does not return
