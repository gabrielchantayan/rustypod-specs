# F-a04c50db480a

## Purpose

F-a04c50db480a partitions an unsigned 16-bit quantity using an externally selected byte table and writes two encoded components into a caller-provided record. The outputs ordinarily represent a one-based table position and a one-based remainder.

F-7264181a6e68 classifies a second 16-bit input. A zero result enables special handling at zero-based table position 1: traversal subtracts 28 rather than the table byte, and a separate post-traversal adjustment handles a remainder of exactly 28.

The established behavior is table-driven arithmetic, not a validated conversion between known units. A calendar-like interpretation is plausible but remains inferred intent. Neither actual table contents nor the semantic meaning of the inputs and outputs is established.

The table base is obtained from global state separately for every table access. It is not captured before the dependency call or retained across traversal accesses. Changes to that global can therefore change which table supplies a comparison or subtraction.

## Behavior

### Input acquisition

The function first reads the unsigned quantity from offsets 4–5 and retains that value in its working state.

It initializes the table position to zero, reads the 16-bit field at offsets 0–1, and calls F-7264181a6e68 once with that field’s value.

The quantity is not reread after the call. A dependency-induced change to offsets 4–5 therefore does not replace the captured quantity. Likewise, the dependency argument has already been obtained when the call executes.

No table-base value is captured before the dependency call. The dependency may change the global table base, table contents, record, or other accessible state. The first traversal access uses the base evaluated after the call returns.

### Traversal and table-base evaluation

Each loop-condition evaluation performs a new evaluation of the global table-base value and reads the unsigned byte selected by that base plus the current position. That byte is compared with the signed interpretation of the working remainder.

Traversal consumes an entry when the byte is less than or equal to that signed remainder. Equality consumes; it does not stop traversal.

A failed comparison ends traversal. Its table-base evaluation and byte read still occur. In particular, a negative signed interpretation of the remainder does not eliminate the next table access: the byte is read before the comparison rejects it.

A successful comparison selects one of two paths:

- **Position 1 and zero dependency result:** The position becomes 2, and the working remainder is reduced by 28. This path performs no second table access for the subtraction.
- **All other cases:** The global table base is evaluated again. A byte at the current position relative to this newly evaluated base is read and subtracted from the working remainder. The position then advances by one.

Consequently, an ordinary consuming iteration contains two distinct global-base evaluations and two distinct byte reads: one pair for the condition, another pair for subtraction.

These accesses need not select the same address. A change to the global base between them can make the condition use one table and the subtraction use another. Even if the base remains unchanged, a change to the addressed byte can make the two values differ.

There is no explicit dependency call inside traversal. The representation nevertheless does not establish immutability, synchronization, or freedom from externally changing state.

### Subtraction and signed comparison

Subtraction operates on the 32-bit unsigned remainder. An amount greater than the remainder produces modular wrap, not an error or saturation.

On the following loop-condition evaluation, the remainder is interpreted as signed. Under the represented 32-bit interpretation, a value with its high bit set is negative. Every unsigned table byte is nonnegative, so the comparison then fails—provided the required global-base and byte accesses succeed.

The special subtraction can wrap even when the base and table bytes remain stable. Its entry condition uses the table byte at position 1, but its subtraction amount is always 28. A threshold below 28 can therefore admit a remainder smaller than 28.

For an ordinary iteration, absence of underflow follows only when the condition and subtraction accesses return the same byte value. Stability of the base alone is insufficient if the byte changes. Stability of bytes within separate tables is also insufficient if the base changes to a table containing a different value. Stable base and stable addressed bytes together are a sufficient qualification.

### Post-traversal adjustment

After traversal stops, the function saves whether the stopping position is 1.

If that saved condition is true, the dependency result is zero, and the remainder is exactly 28, the function changes the position to 2 and clears the remainder to zero.

The position change and remainder clearing have separate guards, but both use the saved stopping-position condition. Updating the position does not prevent the remainder from being cleared.

For a stable base and stable addressed bytes, stopping at position 1 with remainder 28 requires the condition byte there to exceed 28. A byte of 28 or less would cause another iteration instead.

More generally, regardless of earlier base changes, the particular condition read that stops traversal at position 1 with remainder 28 must return a byte greater than 28.

### Output encoding

The function writes the outputs in this order:

1. Offset 2 receives the encoded final position.
2. Offset 3 receives the encoded final remainder.

Each encoding narrows its value to a character-sized value, adds one, and stores a byte. Under the represented low-byte conversion behavior, the resulting bytes are:

- Position output: \((\text{final position}+1)\bmod 256\).
- Remainder output: \((\text{final remainder}+1)\bmod 256\).

For values within the ordinary component range, these are one-based components. The function does not validate that either encoded byte is nonzero or that the position fits in a byte.

The modular description is conditional on the represented conversion behavior. The supplied representation does not independently settle all language-level portability questions concerning character narrowing.

The stores are separate, not a single atomic record update. If execution faults or stops after the first store, offset 2 may contain the new result while offset 3 retains its prior contents.

## Side effects

The directly represented access order is:

2. Read the 16-bit dependency argument at offsets 0–1.
3. Call F-7264181a6e68.
4. Evaluate the global table base and read the selected byte for the first loop condition.
5. For each successful ordinary iteration, evaluate the global table base again and read the selected subtraction byte.
6. Evaluate the global table base and read the selected condition byte for each subsequent condition, including the terminating condition.
7. Apply the local post-traversal adjustment, if applicable.
8. Write offset 2.
9. Write offset 3.

A successful special iteration has only its condition’s base evaluation and byte read; the subtraction uses the constant 28.

The function does not directly assign to the global table base or table bytes. It performs no explicit allocation, release, record copy, logging, or error reporting.

Such an effect occurs after this function’s table traversal, because both output writes follow all its table accesses.

## Acceptance examples

These are conditional arithmetic examples, not observed executions.

Except for the changing-base example, assume a valid record, a returning dependency, an unchanged global table base throughout traversal, unchanged addressed bytes, sufficient accessible table storage, and the represented arithmetic and byte-conversion behavior. Output pairs list offsets 2 and 3.

### Below the first threshold

With first table byte 31:

- Quantity 0 produces **(1, 1)**.
- Quantity 30 produces **(1, 31)**.

Neither case enters traversal. The dependency result does not affect either output.

### Equality consumes

With initial table bytes 31 and 29 and quantity 31, the first condition succeeds on equality.

The first subtraction leaves remainder zero at position 1. The next threshold, 29, stops traversal. Either dependency-result class produces **(2, 1)**.

### Boundary adjustment

With table prefix 31, 29, 31 and quantity 59, the first subtraction leaves remainder 28 at position 1. The next threshold, 29, stops traversal.

- Zero dependency result produces **(3, 1)**.
- Nonzero dependency result produces **(2, 29)**.

The zero-result case advances the stopped position and clears the remainder.

### Special subtraction differs from its threshold

With the same table prefix and quantity 60, the first subtraction leaves remainder 29 at position 1. Its threshold permits another iteration.

- Zero result subtracts 28, leaving remainder 1 at position 2; output **(3, 2)**.
- Nonzero result subtracts the table byte 29, leaving remainder zero at position 2; output **(3, 1)**.

### Zero is not a terminator

With initial table bytes 0 and 29 and quantity zero, the first comparison succeeds. The ordinary path subtracts zero and advances.

Traversal stops at position 1 with remainder zero, producing **(2, 1)** for either dependency-result class.

### Special subtraction wraps

With table prefix 31, 1, 31, quantity 32, and a zero dependency result:

- The first subtraction leaves remainder 1 at position 1.
- Threshold 1 admits the special subtraction of 28.
- The unsigned remainder becomes \(2^{32}-27\).
- The condition at position 2 reads its byte and compares against signed remainder −27, stopping traversal.

The output is **(3, 230)**.

### A changed base changes the subtraction

Assume quantity 5 and a nonzero dependency result. The first condition evaluates a base selecting a table whose byte at position 0 is 5. Before the ordinary subtraction evaluates the global base again, that global changes to select another table whose bytes at positions 0 and 1 are 7 and 9. It then remains unchanged.

The condition succeeds using 5, but subtraction uses 7. The remainder becomes \(2^{32}-2\), and the position becomes 1.

The next condition reads 9 and compares against signed remainder −2, stopping traversal. The output is **(2, 255)**.

This example requires a base change to occur; the function does not itself perform that change.
