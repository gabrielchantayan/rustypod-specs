# F-736f75d0ae34

## Purpose

The supplied static representation describes a sequence of indirect calls, computed-address memory reads, and byte- and word-sized writes. It does not establish a reliable application-level purpose.

The visible effects include:

- Publishing the second and third explicit inputs to computed word locations.
- Repeatedly clearing words and bytes.
- Constructing values from dependency results through shifts, masks, and scaling.
- Using an unsigned byte read from memory as an address component for a later write.
- Repeatedly clearing the 32-bit location at absolute address `0x24`.
- Ending at an explicitly marked invalid-instruction boundary, rather than a visible normal return.

**Inferred intent:** some operations resemble state initialization, field updates, or descriptor construction. These interpretations are not established requirements. The low absolute addresses, unresolved calls, and damaged-control-flow warning make a conventional object model particularly unsafe to assume.

This contract describes the visible sequence conditionally: each later operation is reached only if preceding calls and memory accesses complete and execution follows the represented path.

## Behavior

### Dependency notation

Unresolved call targets are given opaque documentation IDs in the Dependencies section. Repeated use of an ID denotes a class of visible call behavior, not proven identity of the underlying target.

A recurring **five-call group** consists of:

1. One indirect call with the explicitly described arguments.
2. Four subsequent indirect calls with no explicit arguments shown.

When a result is attributed to such a group, it is the result of its fifth call. “No explicit arguments shown” does not establish that machine argument registers are cleared or that the actual callee takes no arguments.

All calls remain observable boundaries. They must not be omitted or merged merely because their results are unused.

### 1. Initial publication and seed acquisition

The function first reads a 32-bit word from the incoming address-like value plus `0x14`. It logically shifts that word right by three bits.

It then performs a five-call group. The first call receives:

- The shifted word.
- The second explicit input.
- The third explicit input.
- The incoming shift-source value shifted left by four bits.

The final call supplies an index. The function writes the second explicit input as a 32-bit word at four times that index plus `0x14`.

A second five-call group follows. Its first call receives four times the same index. Its final result supplies the **initial seed**, a 32-bit unsigned value used throughout much of the remaining sequence.

The function next writes the third explicit input as a 32-bit word at the incoming scale-source value times `0x80000`, plus `0x24`.

### 2. Seed-derived addresses and first byte update

Three quantities are derived from the initial seed:

- The **sixteenfold base**: initial seed times `16`.
- The **reduced seed**: the initial seed masked with `0x3fffffff`, then logically shifted right by one.
- Later, the **compact seed**: reduced seed masked with `0x3fffff`.

A five-call group receives the sixteenfold base and the initial seed shifted left by two bits.

After that group completes, the third explicit input is written as a 32-bit word at the sixteenfold base plus `0x24`.

The function reads a 32-bit word at the sixteenfold base plus `0x74`. That word is passed to another five-call group. Its final result is retained as the **shift source**.

Next, a byte is read at the sixteenfold base plus one. Its unsigned value, plus `0x11`, selects an absolute byte address. The function writes there the low byte of the initial seed masked with `0x3fffffff` and logically shifted right by 20 bits.

This is byte-derived absolute addressing, not a demonstrated pointer dereference through a full-width pointer field.

### 3. Clearing the first byte-derived locations

A separate indirect call receives the shift source shifted left by two bits. A subsequent call produces a 32-bit token, which is passed to a five-call group. That group’s final result supplies another index.

The function reads the byte at the sixteenfold base plus one again, then writes zero to the unsigned byte value plus `0x11`.

This second byte read is independent of the earlier read. Intervening calls may have changed its value.

A five-call group receives the new index shifted left by two bits.

The function then performs two byte clears in order:

1. Zero is written at reduced seed plus `0x0f`.
2. A byte is read at reduced seed times `0x400`, plus one; zero is written at that unsigned byte value plus `0x11`.

The scaled address used by the second clear is retained for later operations.

### 4. Clearing state associated with the retained scaled address

A separate call receives four arguments:

- Shift source shifted left by 23 bits, repeated three times.
- Shift source shifted left by 25 bits.

Another call supplies a token, which is passed into a five-call group. The final result supplies an index.

The function reads a byte from the retained scaled address plus one. It caches that unsigned byte value and writes zero at that value plus `0x11`.

A five-call group receives the latest index shifted left by two bits.

After those calls, the cached byte—not a fresh memory read—is used to write a 32-bit zero at the byte value plus `0x44`. Immediately afterward, the function writes a 32-bit zero at absolute address `0x24`.

Thus, changes to the original selector byte during the intervening calls do not change this particular word-write address.

### 5. Repeated word clearing

A separate call receives four explicit arguments: zero, `0x98`, the retained scaled address, and `0x98`.

It is followed by a token-producing call, a call consuming that token, a further token-producing call, and a five-call group consuming the latter token.

The group’s result supplies an index. The function writes a 32-bit zero at four times that index plus `0x44`, then writes a 32-bit zero at absolute address `0x24`.

A five-call group receives four times that index. Its final result is represented as 64 bits.

A separate call receives the lower 32-bit half shifted left by two bits. After that call, the function uses the upper 32-bit half of the previously captured result to write a 32-bit zero at twice that half plus `0x44`. It then clears the 32-bit location at `0x24` again.

The next separate call receives zero, an additional machine result from the immediately preceding dependency call, and that additional result shifted left by two bits. The provenance and validity of this additional result are unresolved.

After one further call with no explicit arguments shown, a five-call group receives compact seed shifted left by seven bits.

The group’s final index selects another word at four times the index plus `0x44`. That word is cleared, followed by another 32-bit clear at `0x24`.

These four writes to `0x24` are separate events, with intervening calls and writes. They are not one logically coalescible clear.

### 6. Zeroing and populating offset-`0x14` words

A five-call group receives four times the most recent index. Its final result supplies another index.

A separate call receives that index shifted left by two bits and returns a replacement index. The function writes a 32-bit zero at four times the replacement index plus `0x14`.

A five-call group then receives the replacement index three times, followed by compact seed shifted left by seven bits. Its final result selects another word at four times that result plus `0x14`, which is also cleared.

A five-call group receives four times this latest result. Its final result is the **construction index**. The function stores four times the construction index as a 32-bit value at sixteen times the construction index plus `0x14`.

A subsequent five-call group receives four times the construction index. Its final result selects a word at four times that result plus `0x14`. The value written there is still four times the earlier construction index.

Another five-call group receives four times the latest result. Its final result supplies a new index. The function writes four times that new index at sixteen times that index plus `0x14`.

### 7. Compact-seed publication

A separate call receives four times the latest index and sixteen times that index.

A token-producing call follows. Its token is passed to a five-call group together with compact seed shifted left by four bits.

At four times that group’s final result plus `0x14`, the function writes a 32-bit value equal to compact seed times `0x80`.

This value is numerically the same as compact seed shifted left by seven bits under the stated 32-bit interpretation. Since compact seed is at most `0x3fffff`, this particular multiplication does not overflow 32 bits.

### 8. Final byte updates

A five-call group receives four times the latest index and returns a **first terminal seed**.

The function computes a **terminal selector base** as reduced seed times `0x4000000`. It reads a byte at that base plus one and writes the low byte of the first terminal seed shifted left by two bits at the byte-selected address plus `0x11`.

A separate call receives the first terminal seed shifted left by two bits. A token-producing call follows, then a five-call group consuming that token.

After that group, the function freshly reads the selector byte at terminal selector base plus one. It writes the low byte of the first terminal seed masked with `0x3fffffff` and logically shifted right by 20 bits at the newly selected address plus `0x11`.

A five-call group receives the latest group result shifted left by two bits. Its final result supplies the **second terminal seed**.

The selector byte at terminal selector base plus one is read again and cached. At that cached byte value plus `0x11`, the function writes the low eight bits of four times the second terminal seed.

A separate call receives the cached selector byte zero-extended to 32 bits. A token-producing call follows, then a five-call group consuming the token.

The function then reads a byte at eight times the second terminal seed plus one. At that unsigned byte value plus `0x11`, it writes the low byte of the second terminal seed masked with `0x3fffffff` and logically shifted right by 20 bits.

A final five-call group receives the latest group result shifted left by two bits. The visible path then reaches the invalid-instruction boundary.

## Side effects

All described writes are externally relevant, including repeated writes of zero. The representation does not establish ordinary RAM semantics; locations could alias, overlap, fault, or have device effects.

Important consequences include:

- A byte-selected write address lies between `0x11` and `0x110`, inclusive.
- A cached-byte-selected word address lies between `0x44` and `0x143`, inclusive.
- Such word addresses need not be naturally aligned.
- Computed locations may overlap each other or the absolute word at `0x24`.
- Intervening dependencies may modify memory used by later selector reads.
- No synchronization, rollback, transaction boundary, or cleanup path is visible.

There is no established allocation or deallocation operation. No pointer ownership transfer, lifetime extension, reference-count change, or release obligation can be assigned to an unresolved dependency.

No explicit validation, error code, bounds check, null check, or retry is visible. If a call fails to return or an access faults, completion of later effects is not established.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Early input publication.** If the initial group returns index `3`, the next visible word write places the second explicit input at address `0x20`. The following group’s first explicit argument is `12`.

2. **Logical right shift.** If the initial 32-bit read yields `0x80000000`, the first call receives `0x10000000` as its first argument, not a sign-extended result.

3. **Selector re-read.** If the selector at the sixteenfold base plus one initially contains `7` but an intervening dependency changes it to `9`, the first selected byte write targets `0x18`; the subsequent clear targets `0x1a`.

4. **Cached selector.** If the retained scaled-address selector yields `5`, its immediate byte clear targets `0x16`. Even if a subsequent dependency changes the selector to `8`, the later cached-selector word clear still targets `0x49`.

5. **Byte truncation.** If the first terminal seed is `0x41`, its initial terminal byte value is `0x04`, because four times `0x41` is `0x104` and only eight bits are stored.

6. **Masked extraction.** If the initial seed is `0x3ff00000`, its first selected-byte value is `0xff`: the masked right shift produces `0x3ff`, whose low byte is retained.

7. **64-bit split.** If the paired result has lower half `3` and upper half `5`, the following call receives `12`. The subsequent word clear targets `0x4e`, provided that call returns and the access is supported.

8. **Termination boundary.** Completing the final call group does not establish a normal return. Acceptance must account for the unresolved invalid-instruction endpoint rather than inventing a success value.
