# F-f61cff11771d

## Purpose

F-f61cff11771d performs an ordered dispatch of a resolved object:

1. Offer the object to entries in an optional preliminary collection.
2. If none returns a nonzero result, invoke either an explicitly supplied recipient or a default recipient chain.
3. Invoke a final virtual operation on the resolved object, when nonnull.
4. Return the dispatch result as a 32-bit value.

**Established behavior:** A nonzero result stops dispatch. A zero result permits further processing only where the selected dispatch path provides another recipient. In particular, an explicit recipient replaces the default chain; its zero result does not activate that chain.

**Inferred intent:** The preliminary collection may represent interceptors, and the default chain may represent propagation through related recipients. These interpretations are not necessary to the contract. Likewise, the final object operation resembles a release, but its ownership semantics are not established.

## Interface

### Inputs

The function accepts two arguments:

| Argument | Representation | Observed use |
|---|---|---|
| Resolution input | One 32-bit value | Passed unchanged to F-17c2f3b940d8 after obtaining a lookup-related value from F-483a717208e6. |
| Explicit recipient | Nullable pointer in the supplied 32-bit object representation | If reached and nonnull, receives a virtual call at table byte offset `0x30`, with the resolved object as its second argument. |

No explicit validation of either argument is visible.

### Output

The function returns a 32-bit integer dispatch result:

- Initially zero.
- Replaced by each recipient’s result when that recipient is invoked.
- Returned without Boolean normalization.
- Left zero when no recipient produces a nonzero result.

A negative result is nonzero and therefore terminates dispatch just as a positive result does. No distinct success, rejection, or error classification is established.

### Object and state layouts

All offsets below are byte offsets. The supplied representation uses four-byte pointer and integer fields.

The resolved object, if nonnull, is accessed through a virtual table pointer at object offset `0x00`:

| Virtual table offset | Use |
|---|---|
| `0x04` | Final object operation before ordinary return |
| `0x14` | Query producing a 64-bit result for default-chain eligibility |

Recipients also have a virtual table pointer at object offset `0x00`:

| Virtual table offset | Use |
|---|---|
| `0x1c` | Obtain the next default-chain recipient; the result is represented as 64 bits |
| `0x30` | Dispatch to an explicit or default-chain recipient |
| `0x34` | Dispatch to an entry supplied by the preliminary collection |

A default-chain recipient additionally has a four-byte link or metadata pointer at object offset `0x0c`. When eligibility filtering is enabled, a 32-bit field at offset `0x0c` within that pointed-to structure is read.

The context returned by F-3fdd14ecd250 is accessed at:

- `0x28`: initial default-chain recipient pointer.
- `0x2c`: preliminary collection reference.

There is no visible null check on the returned context before these accesses.

## Behavior

### 1. Resolve the dispatch object

The function first calls F-483a717208e6 with the 32-bit value `8`.

It then calls F-17c2f3b940d8 with:

1. The preceding call’s return value.
2. The original resolution input.

The returned pointer becomes the resolved object for the entire invocation. It may be null. A null result does not itself cause an early return and is still passed to recipient callbacks.

The dispatch result is initialized to zero before examining the context.

### 2. Process the preliminary collection

The function calls F-3fdd14ecd250 and reads the context field at `0x2c`.

If that field is zero, preliminary collection processing is skipped.

If it is nonzero:

1. A 20-byte local iterator storage region is supplied to F-538044b67754.
2. The collection field at context offset `0x2c` is read again and supplied to that call.
3. The third argument is the 32-bit bit pattern `0xfffffffe`, equivalent to `-2` under signed 32-bit interpretation.
4. F-6e4651b532dc is repeatedly invoked with the iterator storage and a two-pointer output area.

For each iterator advance:

- A zero advance result ends preliminary processing.
- Any nonzero advance result causes the first output pointer to be used as a recipient.
- That recipient’s virtual operation at `0x34` is invoked with the recipient and the resolved object.
- Its 32-bit result becomes the current dispatch result.
- Zero continues iteration.
- Nonzero stops iteration immediately.

The second pointer in the iterator output area is not consumed by this function.

F-944b595e25e9 is called on the iterator storage after either normal exhaustion or a nonzero preliminary dispatch result. On ordinary control flow, exactly one such finalization occurs for an initialized preliminary iteration.

If a preliminary recipient returns nonzero, no explicit recipient or default-chain recipient is invoked. Processing proceeds to the final object operation.

If iteration exhausts, processing continues to recipient selection. The iterator’s advance result is not returned as the dispatch result.

There is no visible validation of an entry pointer before its virtual call.

### 3. Prefer the explicit recipient

After the preliminary collection is absent or exhausted, the explicit-recipient argument is examined.

If nonnull, its virtual operation at `0x30` is invoked with:

1. The explicit recipient.
2. The resolved object, including null if resolution returned null.

Its result becomes the final dispatch result. Default-chain processing is skipped regardless of whether that result is zero.

If the explicit recipient is null, the default-chain path is selected.

### 4. Capture the default-chain head and query eligibility

The default-chain path calls F-3fdd14ecd250 again. It does not reuse the earlier returned context pointer.

It reads the field at `0x28` and captures that value as the initial chain recipient. This read occurs before the resolved object’s eligibility query. Consequently, a later callback changing the context’s head field does not replace the captured initial recipient.

If the resolved object is null:

- The eligibility-query virtual operation is not called.
- Eligibility filtering is disabled.

If the resolved object is nonnull, its virtual operation at `0x14` is called and returns a 64-bit value:

- A zero low 32-bit word disables eligibility filtering.
- A nonzero low 32-bit word enables eligibility filtering.
- The high 32-bit word does not determine whether filtering is enabled.
- This query result is not the function’s dispatch result.

The query occurs even if the captured chain head is null.

The supplied representation carries an initial high-word value of `0x00000a00` when no query occurs, or the query’s high word when it does. This high word does not affect a visible dispatch decision: when filtering is disabled, the associated eligibility condition succeeds without using it; when filtering is enabled, the metadata read replaces it before the condition is evaluated.

### 5. Traverse the default chain

Traversal continues only while both conditions hold:

- The current recipient pointer is nonnull.
- The current dispatch result is zero.

When eligibility filtering is disabled, the current recipient is dispatched to directly through virtual offset `0x30`.

When eligibility filtering is enabled:

1. Read the current recipient’s pointer field at `0x0c`.
2. Read the 32-bit field at offset `0x0c` through that pointer.
3. If that nested field is zero, invoke the recipient directly.
4. If that nested field is nonzero, call F-35b8bd5fa9e0 with the resolved object.
5. Invoke the recipient only if that dependency returns nonzero.

A zero result from F-35b8bd5fa9e0 skips the current recipient’s dispatch operation but does not itself terminate traversal. The dispatch result remains zero.

The nested metadata dereference occurs before any null check of the recipient’s field at `0x0c` on this filtering path. Thus, a nonnull current recipient is insufficient for safe traversal: the nested field must also be readable whenever filtering is enabled.

After a recipient is invoked:

- Its result becomes the dispatch result.
- A nonzero result immediately ends traversal.
- A zero result proceeds to the link check.

After either a skipped recipient or a recipient returning zero:

1. The current recipient’s field at `0x0c` is read.
2. If it is zero, traversal stops with a zero result.
3. Otherwise, the recipient’s virtual operation at `0x1c` is called.
4. The low 32-bit word of that operation’s 64-bit return becomes the next recipient pointer.

The high word of the next-recipient result does not determine the returned dispatch status or bypass the next iteration’s metadata rules.

The post-processing link read is distinct from the earlier eligibility metadata read. A callback may have changed the field between them. The function follows the value observed by the later read; it does not visibly preserve the earlier value for this decision.

There is no visible cycle detection, traversal bound, or deduplication. Termination requires a nonzero dispatch result, a null current recipient, a zero link field, or termination inside a dependency.

### 6. Perform the final object operation and return

After ordinary dispatch processing, if the resolved object is nonnull, its virtual operation at `0x04` is invoked with that object.

This operation occurs after preliminary iterator finalization and after any selected recipient traversal. Its return value is ignored. The function then returns the saved dispatch result.

When the resolved object is null, this final operation is skipped.

The function does not re-resolve the object or verify that callbacks have preserved its validity.

## Side effects

### Established direct effects

The function:

- Creates local iterator and iterator-output storage.
- Updates its local dispatch result.
- Reads context, recipient, virtual-table, and metadata fields.
- Calls dependencies and virtual operations in the order described above.

No direct write to caller-owned object fields or context fields is visible.

### Effects mediated by dependencies

Callbacks may mutate state, perform external work, or affect object lifetimes. Their bodies are unavailable here. In particular, the contract does not assume that:

- Repeated context-access calls return the same pointer.
- Context fields remain unchanged between reads.
- Iterator operations preserve global state.
- Recipient callbacks preserve metadata or chain links.
- The eligibility dependency is pure.
- The final object operation is specifically a decrement, destruction, or deallocation.

The two reads of the preliminary collection field must not be treated as one immutable observation. Similarly, a recipient’s metadata/link field may be observed more than once during a single visit.

### Ownership and lifetime

The resolved pointer is retained locally and passed unchanged to callbacks. A nonnull resolved pointer receives the final operation at `0x04` on each ordinary return path.

That pairing does not establish an ownership model. Whether resolution acquires a reference, whether the final operation releases one, and whether recipients borrow or retain the object remain unknown.

The function does not visibly apply a finalization operation to recipients or to context objects.

No exceptional-control-flow cleanup is established. A dependency that faults, throws, or does not return may prevent subsequent iterator finalization or the final object operation.

## Acceptance examples

These examples are conditional behavioral requirements, not reports of executed tests. Unless stated otherwise, dependencies return normally and all accessed memory is valid.

### Preliminary handling takes precedence

Given two preliminary entries, the first returning zero and the second returning `7`:

- Both entries receive the same resolved pointer, in iteration order.
- No further iterator advance occurs after the second dispatch.
- The iterator is finalized.
- Neither the explicit recipient nor the default chain is used.
- A nonnull resolved object receives its final operation.
- The function returns `7`.

### Explicit zero does not fall through

Given an absent or exhausted preliminary collection and a nonnull explicit recipient returning zero:

- The explicit recipient is invoked once at `0x30`.
- The default-chain context lookup does not occur.
- The function returns zero after the applicable final object operation.

### Null resolution still permits dispatch

Given a null resolved object, no preliminary handling, and a null explicit recipient:

- The default-chain head is obtained.
- No object eligibility query occurs.
- Filtering is disabled.
- Default recipients may receive null as their object argument.
- No final object operation is invoked.

### Low word controls filtering

Given an eligibility query result with a nonzero high word but a zero low word:

- Filtering is disabled.
- No nested eligibility metadata read is required before dispatch.
- The high word alone cannot enable filtering.

Conversely, any nonzero low word enables filtering, regardless of the high word.

### A gated recipient can be skipped

Given filtering enabled, a nonzero nested metadata field, and F-35b8bd5fa9e0 returning zero:

- The current recipient’s `0x30` operation is not called.
- Its link field is then read.
- A nonzero link permits a `0x1c` next-recipient call.
- Skipping does not produce a nonzero result.

### Metadata zero bypasses the gate

Given filtering enabled and a readable nested metadata field containing zero:

- F-35b8bd5fa9e0 is not called for that visit.
- The current recipient is dispatched to directly.

### Negative dispatch results terminate

Given any invoked recipient returning `-1` in the 32-bit result representation:

- Further recipient processing stops.
- Applicable ordinary finalization still occurs.
- The returned result remains `-1`, not `1`.

### Empty default chain still permits the object query

Given a nonnull resolved object and a captured null default-chain head:

- The object query at `0x14` is still invoked.
- No default recipient is invoked.
- The result remains zero.
