# F-5fba96760515

## Purpose

F-5fba96760515 conditionally obtains a nonzero integer-valued destination, invokes an external operation with that destination and two caller-supplied values, and writes a zero byte at a destination-relative address.

The visible structure is consistent with creating a zero-terminated copy of a caller-specified byte range. That interpretation is **inferred intent**, not an established guarantee: neither dependency’s implementation or contract is available. In particular, the external operation is not established to copy bytes, and the destination-producing dependency is not established to allocate memory.

The established contract is therefore an ordered sequence of calls, a conditional one-byte write, and a returned integer value.

## Interface

The function accepts two integer-valued inputs and returns an integer-valued result:

| Item | Role established by the visible body |
|---|---|
| First input | Tested against zero. If nonzero and destination acquisition succeeds, passed as the second argument to the external dependency. |
| Second input | Used to calculate the argument to the destination-producing dependency, passed unchanged as the third argument to the external dependency, and used as the offset for the final byte write. |
| Return value | Zero on either visible zero-result path; otherwise the nonzero value returned by the destination-producing dependency. |

For readability, this contract calls the first input the **source value**, the second input the **extent**, and the first dependency’s result the **destination value**. These names describe apparent roles, not independently verified pointer, length, or ownership types.

### Widths and representation

The displayed interface uses signed integer types for both inputs, the return value, and the destination value. The supplied material does not independently establish their target bit width. A 32-bit signed interpretation may be plausible, but is not promoted here to a verified interface fact.

The terminal store writes one byte containing zero. It does not write an integer-sized zero.

There are two relevant additions:

- Extent plus one, used as the first dependency’s argument.
- Destination value plus extent, used as the address of the terminal byte.

Their overflow behavior, signedness at the machine level, and address-conversion rules are not established by the supplied material. This contract does not assume wrapping arithmetic. If the displayed signed arithmetic accurately represents execution, signed overflow lies outside defined behavior for that interpretation.

## Behavior

### Zero source value

The source value is tested before either dependency is called.

If it equals zero, the function returns zero immediately. This path performs:

- No call to either dependency.
- No extent-plus-one calculation.
- No terminal byte write.

This is a value check, not a check of the memory potentially designated by a nonzero source value. A nonzero source whose first byte is zero does not take this path merely because it might represent an empty string.

### Destination acquisition

For a nonzero source value, the function calculates extent plus one and invokes F-391e3d30e634 with that result as its sole visible argument.

The resulting destination value is tested against zero.

If it equals zero, the function returns zero. On that path, it does not invoke the external dependency and does not perform the terminal store. Effects already performed by F-391e3d30e634 are neither reversed nor inspected.

There is no retry, alternate destination, or explicit error translation.

### Nonzero destination

If F-391e3d30e634 returns a nonzero destination value, the function invokes F-UNMAPPED-01 with three arguments, in this positional order:

1. The destination value.
2. The original source value.
3. The original extent.

The visible body does not inspect or use a return value from this call.

If the call returns normally, the function next stores a zero byte at the address obtained by adding the extent to the destination value. The terminal store occurs **after** the external operation. Thus, if the external operation also writes that byte, the wrapper’s zero store is later in the visible sequence.

After that store, the function returns the destination value produced by F-391e3d30e634. It does not substitute any value produced by F-UNMAPPED-01.

### Boundaries and exceptional execution

An extent of zero is not an early-return condition. With a nonzero source and a nonzero destination result:

- F-391e3d30e634 receives one.
- F-UNMAPPED-01 is still called, with a third argument of zero.
- The zero byte is written at the destination address itself.

Negative extents are not rejected. They affect both the first dependency’s argument and the terminal address calculation. Their validity is unknown and must not be inferred from the absence of a check.

If either dependency fails to return normally, or if the terminal store faults, the remaining visible sequence is not established to occur. There is no visible exception handler, fault recovery, or cleanup path.

## Side effects

The only memory write directly established in the wrapper is the single zero-byte store on the nonzero-destination path.

The wrapper contains no explicit source-memory read. Any reading of the memory apparently designated by the source value is behavior of F-UNMAPPED-01, not established behavior of the wrapper itself.

Observable side effects have the following partial order:

1. F-391e3d30e634 executes.
2. If its result is nonzero, F-UNMAPPED-01 executes.
3. If that call returns normally, the terminal zero-byte store occurs.
4. The destination value is returned.

Both dependencies may have additional effects. Their effects on global state, memory, ownership, error indicators, or external resources are unknown. No preservation guarantee is assumed.

There is no explicit deallocation or ownership-transfer operation in the wrapper. Returning the destination value does not establish that the caller owns it, may release it, or must release it. Likewise, passing it to F-UNMAPPED-01 does not establish that the dependency preserves its allocation or lifetime.

No explicit synchronization is visible. The final byte write alone does not establish atomic publication, thread safety, or ordering relative to accesses by other threads.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

1. **Zero source short-circuits all work.**  
   Given a source value of zero, the result must be zero without either dependency being invoked or the terminal store occurring. This applies regardless of the extent, because the arithmetic involving it is not reached.

2. **Zero destination stops the sequence.**  
   Given a nonzero source and a representable extent of six, F-391e3d30e634 must receive seven. If it returns zero, the wrapper must return zero without calling F-UNMAPPED-01 or writing a terminal byte.

3. **Nonzero destination determines the return value.**  
   Given a nonzero source, extent six, and a nonzero destination result, F-UNMAPPED-01 must receive that destination, the original source, and six. If it returns normally and the address is valid, the wrapper must then write zero at destination plus six and return the original destination value.

4. **The terminal write follows the external operation.**  
   If F-UNMAPPED-01 writes a nonzero byte at destination plus extent and leaves that address writable, the wrapper must overwrite it with zero before returning normally.

5. **Zero extent still invokes both dependencies.**  
   Given a nonzero source and a nonzero result from F-391e3d30e634, an extent of zero must still cause the second call. The subsequent zero-byte store must target the destination itself.

6. **Copied content requires an additional dependency contract.**  
   If F-UNMAPPED-01 is separately established to copy exactly the requested bytes, and all accesses are valid, the resulting destination contains those bytes followed by the wrapper’s zero byte. Without that dependency contract, the payload contents are not specified here.
