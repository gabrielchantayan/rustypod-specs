# F-d2583dc80b91

## Purpose

F-d2583dc80b91 dispatches a property query for one of eight indexed record positions associated with a caller-supplied context. Depending on the selector, it either transfers one 32-bit word directly to caller storage or passes record-derived data through opaque dependencies.

Its normal return value is:

- **1** after completing a supported selector branch.
- **0** after calling F-375c8199e7c2 with error value **0x500** for an invalid index or unsupported selector.

A return of 1 establishes completion of the selected branch, not independently verified output correctness. Dependency return values do not affect this function’s normal status.

“Property,” “record,” and “query” describe inferred organizational intent. The static evidence establishes addressing, dispatch, memory accesses, and dependency calls, but not the application-level meaning of the selected data.

## Interface

### Arguments and result

| Argument | Represented width | Established use |
|---|---:|---|
| Context | 32 bits | Contributes to record-address calculation; passed unchanged to the error dependency. |
| Record index | 32 bits | Accepted exactly for **0x4000–0x4007**, inclusive. |
| Property selector | 32 bits | Selects one of **0x1200–0x1209** after index validation and the global-bias read. |
| Output address | 32-bit pointer representation | Destination of a direct word store or argument to an output dependency. |
| Return value | 32 bits | Normally 0 or 1, as described above. |

These widths describe the supplied 32-bit representation. They do not establish a portable interface on architectures with different pointer or integer widths.

### Addressing inputs

For an accepted index, the function reads an addressing bias from a global value and forms the selected record address from:

- the context;
- the **full index multiplied by 0xA8**;
- the global bias value read during this invocation.

The index is not normalized by subtracting 0x4000 before multiplication. Its contribution ranges from **0x2A0000** for index 0x4000 to **0x2A0498** for index 0x4007. Adjacent accepted indices therefore contribute addresses separated by **0xA8 bytes**, assuming the same context and bias value.

The global bias read occurs **after successful index validation and before selector dispatch**. Consequently:

- An invalid index bypasses this represented global read.
- A valid index causes this read even when the selector is unsupported.
- The resulting address is used without a represented reload of the bias after dependency calls.

The bias is established as a global value, not merely an unspecified constant or relocation convention. Its value, mutability, initialization, and application meaning remain unknown.

### Memory preconditions

The function performs no explicit null, alignment, accessibility, destination-size, or overlap checks.

For normal completion:

- Every accepted-index path requires the represented global-bias read to be valid, including paths with unsupported selectors.
- Supported selectors require any direct record accesses and dependency accesses to be valid.
- Direct-transfer selectors require a destination suitable for one 32-bit store.
- Dependency-driven selectors require storage satisfying the relevant dependency contracts, whose complete requirements are unavailable.

A 16-byte or 12-byte local temporary does not establish the required size of caller output storage or the source extent read by a dependency.

The accepted index multiplication fits within a signed 32-bit integer. The complete address calculation additionally involves the context and global bias. Valid address ranges, overflow handling, and fault behavior are not independently established by the supplied representation.

## Behavior

### Validation, global read, and dispatch order

The index gate evaluates the 32-bit unsigned difference between the index and **0x4000**, accepting the index only when that difference is at most **7**.

This accepts exactly **0x4000–0x4007**. Values below the range are rejected through unsigned subtraction semantics; values above the range are also rejected.

For an invalid index, the function:

1. Calls F-375c8199e7c2 with the context followed by **0x500**.
2. Returns **0** if that call returns normally.

This path contains no represented global-bias read, property-specific record read, or direct output store. The error dependency’s own accesses and side effects remain unknown.

For a valid index, the function:

1. Reads the global addressing bias.
2. Forms the record address using the context, full-index contribution, and captured bias value.
3. Dispatches on the property selector.

An unsupported selector then invokes F-375c8199e7c2 with the context and **0x500**, followed by return **0** if the dependency returns normally. Thus, an unsupported selector with a valid index differs observably from an invalid index: the former reaches the global-bias read first.

Address formation alone does not establish a read of record contents. In particular, the unsupported-selector path has no represented record-field read.

### Selectors 0x1200, 0x1201, and 0x1202

These selectors use the same two-call sequence with different source addresses:

| Selector | Source address relative to the computed record address |
|---|---:|
| 0x1200 | +0x00 |
| 0x1201 | +0x10 |
| 0x1202 | +0x20 |

The function provides a **16-byte local temporary area** to F-a325b0adc5e9 as its first argument and the selected source address as its second argument.

After that call returns, it calls F-01be51f7fed7 with:

1. The same temporary area.
2. The caller’s output address.

It then returns **1** if both calls return normally.

There is no explicit initialization of the temporary before the first call. The function relies on the dependency interaction for whatever temporary contents the second call consumes.

The temporary’s size does not establish that F-a325b0adc5e9 reads exactly 16 source bytes, initializes every temporary byte, or performs a plain copy. The output extent and interpretation of F-01be51f7fed7 are also unknown.

The selected source address derives from the bias already read before dispatch. No bias reload or source-address recomputation is represented after the first dependency call. A dependency changing the global bias does not cause this invocation to select a new source through any explicit operation shown here.

### Selector 0x1203

This branch explicitly captures four 32-bit words into a four-word local temporary before calling its dependency.

| Represented read order | Record offset | Temporary offset | Width |

| 1 | +0x30 | +0x00 | 32 bits |
| 2 | +0x34 | +0x04 | 32 bits |
| 3 | +0x38 | +0x08 | 32 bits |

Each source word is assigned to its corresponding temporary position before the next listed source assignment. After all four assignments, F-e1bd00d0c4e2 receives the temporary’s address followed by the caller’s output address.

The function returns **1** if that call returns normally.

The dependency receives the captured words through local storage, not the original record address. A later change to the original record does not, by itself, change those captured values.

The representation does not establish an atomic four-word snapshot, synchronization with concurrent writers, or machine-level ordering beyond the expressed access sequence. The dependency’s interpretation of these words and its output layout remain unknown.

### Selector 0x1204

First, F-eaf776d4a45e receives:

1. The temporary area.
2. The computed record address plus **0x4C**.

After that call returns, F-230deefc2f3b receives:

1. The same temporary area.

The function then returns **1** if both calls return normally.

The temporary is not explicitly initialized before the first call. Neither the first dependency’s source-read extent nor the second dependency’s output-write extent is established.

A 12-byte temporary does not establish a three-component mathematical type, floating-point representation, or plain-copy operation.

### Selectors 0x1205 through 0x1209

Each branch reads the selected word, stores that captured word at the output address, and returns **1**.

No sign conversion, floating-point conversion, range adjustment, or byte-order transformation is expressed. The transfer preserves the represented word’s bits; its application-level type is unknown.

If the output address equals the selected source address, the represented sequence still reads the word before storing the captured value back. Other overlap arrangements remain subject to memory validity and the underlying execution model; no special overlap handling is present.

## Side effects

### Directly represented effects

The function directly:

- Reads the global addressing bias once on every accepted-index path, before selector dispatch.
- Reads selected record words for selectors **0x1203** and **0x1205–0x1209**.
- Writes the four-word local temporary for selector **0x1203**.
- Writes one 32-bit word to caller output for selectors **0x1205–0x1209**.
- Invokes dependencies according to the selected branch or error path.

It expresses no direct write to the global bias. It expresses no direct write to record storage except when the caller’s output aliases that storage.

No heap allocation, explicit release, or persistent pointer retention is directly represented.

### Dependency effects and global changes

Dependency behavior must not be inferred from its placement in a query path.

The dependencies may affect globals, context-associated state, source storage, or output storage. Their contracts are not supplied. In particular, no dependency is established to preserve the global bias.

The function nevertheless contains no represented reload of that bias after dependency calls. Its own record-derived addressing uses the value captured before selector dispatch; this is not a guarantee that the global remains unchanged.

An error path contains no direct output store, but output preservation is not guaranteed. The error dependency may reach the same storage indirectly. Similarly, an invalid-index path bypasses this function’s global-bias read, but the error dependency’s own global accesses are unknown.

### Ownership and lifetime

The temporary areas belong to the current invocation and are available during the dependency calls. They are not persistent allocations.

No ownership transfer of the context, record storage, or caller output is visibly expressed. However, pointer retention, allocation, release, or other ownership behavior inside dependencies remains **documented_only**.

Safe integration requires dependency behavior compatible with the temporary lifetimes. The supplied representation does not prove that dependencies refrain from retaining or releasing the pointers they receive.
