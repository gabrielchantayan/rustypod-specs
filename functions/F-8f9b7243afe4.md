# F-8f9b7243afe4

## Purpose

F-8f9b7243afe4 decodes one variable-length, UTF-8-shaped unsigned integer from the start of an input buffer. Successful decoding produces a 32-bit value and returns the number of input bytes consumed. Failure produces a distinguished return pattern without writing the output.

The accepted forms occupy one through six bytes and collectively represent values from zero through `0x7FFFFFFF`. Multibyte forms require valid continuation-byte patterns and reject values that could have been represented in fewer bytes.

This is not a modern Unicode UTF-8 validity check. The visible checks permit surrogate values, values above `0x10FFFF`, and five- and six-byte forms. Historical UTF-8-style decoding is an inferred intent; the byte patterns, arithmetic, and error precedence below are established by static evidence.

Only the first encoded value is processed. Remaining input is neither decoded nor validated.

## Behavior

### Length gate and lead classification

A signed available length below one produces zero immediately, before any input read.

For a positive length, the first byte determines the selected form under stable-input conditions:

| First byte | Total width | Lead payload bits | Minimum accepted value | Maximum value |
|---|---:|---:|---:|---:|
| `00`–`7F` | 1 byte | 7 | `0x00000000` | `0x0000007F` |
| `C0`–`DF` | 2 bytes | 5 | `0x00000080` | `0x000007FF` |
| `E0`–`EF` | 3 bytes | 4 | `0x00000800` | `0x0000FFFF` |
| `F0`–`F7` | 4 bytes | 3 | `0x00010000` | `0x001FFFFF` |
| `F8`–`FB` | 5 bytes | 2 | `0x00200000` | `0x03FFFFFF` |
| `FC`–`FD` | 6 bytes | 1 | `0x04000000` | `0x7FFFFFFF` |

First bytes in `80`–`BF` or `FE`–`FF` are invalid leads and produce `0xFFFFFFFE`. No continuation byte is read on that path.

For a one-byte form, the low seven bits are stored as the result and the function returns one. A zero byte is a successful representation of zero, not a terminator or an empty-input indication.

The minimum-value column is an acceptance requirement applied after multibyte assembly. Thus `C0` and `C1` select the two-byte form but cannot produce a successful stable-input decoding.

### Declared-length precedence

For each multibyte form, the function checks the entire required width before reading any continuation byte.

If the available length is smaller than that width, the result is `0xFFFFFFFF`. Any malformed continuation bytes in the available prefix are irrelevant because they have not been inspected.

For example, a three-byte lead with declared length two produces the insufficient-length result even if the second byte would be invalid as a continuation.

A length greater than the selected width does not change decoding and does not cause a scan of the remaining bytes.

### Continuation validation

Each continuation must lie in `80`–`BF`: its two highest bits must be binary `10`.

Validation proceeds from the second byte toward the end of the selected form. At the first invalid continuation, the function returns `0xFFFFFFFD`. Later input bytes are not read on that failing path.

There is no additional lead-specific restriction on the first continuation. In particular, the function does not directly exclude surrogate encodings or enforce the modern Unicode maximum.

Continuation validity takes precedence over the overlong check. The function must finish structural validation before it can reject the assembled value as too small.

### Payload layout and arithmetic

The decoded value is the concatenation of the lead payload and the continuation payloads, in input order, with the lead payload most significant. Every continuation supplies its low six bits.

For widths two through six, the lead payload begins at bit positions 6, 12, 18, 24, and 30 respectively. The final continuation always supplies bits 0–5. Each intervening continuation supplies the next six-bit group toward the high end.

For example, a four-byte form contains three lead payload bits followed by three six-bit continuation payloads, for 21 payload bits in total.

The six-byte form contains one lead payload bit and five six-bit continuation payloads: 31 bits overall. Its largest value is `0x7FFFFFFF`; its largest shift count is 30. With the indicated unsigned 32-bit operations, payload assembly neither overflows nor requires a wider result.

This numeric layout is independent of machine byte order. The physical byte order of the subsequent output store remains a target property.

### Overlong rejection

Once all required continuations pass, the assembled value must meet the minimum for the selected width:

| Selected width | Required lower bound |
|---|---:|
| 2 bytes | `0x80` |
| 3 bytes | `0x800` |
| 4 bytes | `0x10000` |
| 5 bytes | `0x200000` |
| 6 bytes | `0x4000000` |

A value below the applicable bound produces `0xFFFFFFFC` without an output store.

There is no further value-validity check. Consequently, structurally valid, non-overlong encodings can successfully produce:

- Surrogate values `0xD800`–`0xDFFF`.
- Values above `0x10FFFF`.
- Unicode noncharacters.
- Values requiring five or six bytes in this format.

## Side effects

### Input access order

The supplied static representation establishes these source-level access relationships:

1. A positive-length path reads the first byte to obtain its numeric value.
2. It reads the first byte again to decide whether its high bit is clear.
3. A selected multibyte form checks its full declared-length requirement before any continuation read.
4. Continuations are checked in increasing address order, stopping at the first invalid byte.
5. After all continuations pass, the second byte is read again for payload assembly.
6. Successful output storage occurs after assembly and the minimum-value check.

For a two-byte form, the second byte is read once for continuation validation and again for its payload. For three- through six-byte forms, the second byte is likewise reread; the later continuation payloads use values obtained during validation.

The repeated second-byte read occurs even when the subsequent minimum-value check rejects the representation. It does not occur after an earlier continuation-validation failure.
