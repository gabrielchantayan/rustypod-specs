# F-51915aa6d21d

## Purpose

F-51915aa6d21d scans a sequence of two-word records, selects records whose first word equals a requested key and whose second word is the all-ones sentinel, invokes one of two dependencies for each selected record, and then replaces both words.

The normal return value indicates whether at least one replacement completed. The operation does not stop after its first match.

The scan starts at an address computed from an object, a selector, and a shared table. Its stopping address is obtained indirectly from the object and is reevaluated throughout the scan. Consequently, dependency side effects can affect how much of the sequence is visited.

The established behavior is a conditional record update with a preceding dependency call. Any interpretation as registration, removal, notification, or ownership transfer is inferred intent, not established behavior.

## Interface

### Inputs

The function accepts five inputs, represented in the supplied evidence as 32-bit integer-sized values:

| Input | Meaning established by use |
|---|---|
| Object address | Address of an object containing pointers, a scan-base address, and a dependency argument. |
| Search key | Word compared with the first word of each visited record. |
| Replacement first word | Value written to a selected record’s first word. |
| Replacement second word | Value written to a selected record’s second word. |
| Mode | Selects the dependency: zero chooses F-aaebd6c6403f; every nonzero value chooses F-73a1423ea490. |

The object address is used as an address despite its integer-shaped declaration. No null check, alignment check, range validation, or object-type validation is shown.

The three record-related inputs are not dereferenced. Equality is word equality; their higher-level interpretation is unknown. In particular, no restriction to positive keys or nonnegative replacement values is established.

### Return value

The function returns a 32-bit value:

- **0:** No qualifying record replacement completed.
- **1:** At least one qualifying record replacement completed.

This is a Boolean result, not a replacement count. Multiple replacements still produce 1.

These descriptions apply to normal return. Invalid accesses, a dependency that does not return, or other abnormal execution need not produce either result.

### Referenced layout

Offsets below are byte offsets. The supplied representation uses four-byte words and pointers.

| Location | Use |
|---|---|
| Object + 0x50 | Pointer to a selector-bearing structure. |
| Selector-bearing structure + 0x10 | Selector used to locate an entry in a shared table. |
| Object + 0x54 | Base address used to construct the initial scan address. |
| Object + 0x64 | Pointer to a structure containing the stopping address. |
| Stopping-address structure + 0x2c | Current exclusive upper address for the scan. |
| Object + 0x68 | Four-byte value supplied as the first dependency argument. |
| Shared-table base + selector × 12 + 4 | Four-byte displacement used in constructing the scan start. |

The initial scan address is the base from object offset 0x54 plus **12 times the displacement read from the shared table**.

The shared-table entry stride and the scan stride are different:

- Shared-table entries are addressed with a **12-byte stride**.
- Successive scan positions are **8 bytes apart**.
- Each visited scan position exposes a first word at offset 0 and a second word at offset 4.

The evidence does not establish the complete layout of either enclosing structure, the shared table, or the scan storage.

### Preconditions for defined use

A caller must provide storage and address values that make every access actually reached valid. This includes indirect accesses used for initialization, repeated stopping-address reads, record accesses, and accesses following any dependency-induced state changes.

The record storage must be writable for selected records. Dependency-specific preconditions are unknown.

No recovery behavior is established for violated preconditions.

## Behavior

### Initialization

The function initializes its eventual return value to 0.

It obtains the selector through the pointer at object offset 0x50, reads the corresponding displacement from the shared table, and combines that displacement with the base at object offset 0x54 to establish the initial scan address.

This initialization occurs even when the resulting scan is empty. An invalid selector pointer or shared-table access therefore cannot be assumed harmless merely because the stopping address would exclude all records.

The evidence establishes the inputs to the initial-address calculation, but not a reliable relative machine-level ordering among all independent reads within that calculation. In particular, it should not be treated as an atomic snapshot of the object and shared table.

Once constructed, the scan address advances from its current value; the starting base and table lookup are not recomputed on each iteration.

### Scan admission and termination

Before each candidate record is processed, the function obtains the current stopping address by:

- Reading the pointer at object offset 0x64.
- Reading the address stored at offset 0x2c in that referenced structure.

A record is processed only while the current scan address compares strictly below that stopping address. Equality terminates the scan without accessing that candidate record.

The stopping address is therefore **live**, not captured once at entry. The pointer to its containing structure is also read again for subsequent loop conditions.

The condition tests the record’s starting address only. It does not separately verify that the entire eight-byte record lies below the stopping address. If a candidate start is admitted, any first-word read and any conditional second-word access must still be valid independently of that comparison.

The supplied representation uses an address comparison. Its precise target-level ordering for pathological, unrelated, or wrapped addresses is not independently established.

### Selection of a record

For each admitted scan position:

1. The first four-byte word is read and compared with the search key.
2. Only if that comparison succeeds is the second four-byte word read.
3. The record qualifies only if its second word equals −1, represented as the 32-bit all-ones value.

A first-word mismatch does not cause a direct second-word read by this function.

A matching first word with any second-word value other than the sentinel is skipped without a dependency call or direct record write.

### Dependency selection and call

Each qualifying record causes exactly one dependency invocation before the direct replacement writes:

| Mode | Dependency | Arguments, in order |
|---|---|---|
| Zero | F-aaebd6c6403f | Current value read from object + 0x68; current record address. |
| Nonzero | F-73a1423ea490 | Current value read from object + 0x68; current record address; literal value 1. |

The value at object offset 0x68 is read for the particular invocation; it is not established as an entry-time snapshot.

The second dependency receives 1 as its third argument regardless of the magnitude or sign of the nonzero mode input. The mode itself is not forwarded.

No dependency return value is used to authorize, reject, count, or otherwise alter the subsequent replacement. The dependencies’ actual return contracts are unknown.

### Replacement and continuation

If the selected dependency returns normally:

- The current record’s first word is assigned the replacement first word.
- The current record’s second word is then assigned the replacement second word.
- The function’s eventual return value becomes 1.

The selection condition is not checked again after the dependency returns. A dependency’s changes to either record word do not prevent these direct assignments.

The direct first-word assignment precedes the direct second-word assignment. The pair is not established as an atomic update. These are the accesses expressed by the supplied evidence; exact externally observable machine behavior under concurrent access is not established.

After processing or skipping a candidate, the scan address advances by eight bytes. The next loop condition rereads the stopping-address chain.

Setting the eventual return value to 1 does not terminate the loop. Every subsequently admitted qualifying record is processed in the same manner.

### Arithmetic boundaries

The supplied representation is consistent with a 32-bit address-and-word model. The selector and table displacement are represented as integer quantities, and the computation includes two separate multiplications by 12: one for locating the table field, another for converting its value into a scan-start displacement.

No overflow check, selector bounds check, or scan-address wrap check is shown. The evidence does not justify assigning a safe fallback to negative selectors, negative displacements, overflowing multiplication, or wrapped address addition.

A normal valid-use contract therefore requires these computations to designate the intended valid storage without relying on unspecified arithmetic or address-ordering behavior.

## Side effects

### Direct effects

For every selected record whose dependency returns normally, the function writes exactly the two record words described above.

There are no explicit direct writes to the object fields, shared table, or stopping-address structure. This does not imply those locations remain unchanged: aliasing and dependency side effects can change them.

A write of a value already present still follows the same dependency-and-assignment path. The return value reports a completed qualifying replacement, not proof that stored bits changed.

### Indirect effects

Dependency effects are unrestricted by the available evidence. Neither dependency may be assumed to:

- Preserve the object, shared table, stopping address, or future records.
- Preserve the selected record.
- Retain, release, or transfer ownership of any argument.
- Leave the record storage allocated and writable.
- Return normally.

For normal continuation, the selected record must remain valid for the two writes after the call.

A dependency can affect later scan behavior by changing the stopping-address chain or future record contents. Changing the original base or shared-table lookup does not by itself redirect the already-established scan address.

Aliasing also matters. If record writes overlap control data, those writes can influence later reads. No non-aliasing guarantee is supplied.

### Ownership and failure

The function contains no explicit allocation, deallocation, rollback, or error-reporting mechanism. This establishes only the absence of those direct operations, not their absence inside dependencies.

There is no transaction boundary. Earlier replacements are not explicitly undone if later execution faults or a later dependency fails to return. A failure between the two replacement writes can leave a partially updated record; no recovery path is shown.

## Acceptance examples

These are conditional acceptance cases derived from static evidence. They are not reports of executed tests.

1. **Empty scan.** If initialization is valid and the initial scan address equals the stopping address on the first condition check, no record is read or written, neither dependency is called, and the return value is 0.

2. **Key mismatch.** If one record is admitted and its first word differs from the search key, the function does not directly read its second word, does not invoke a dependency for it, and does not write it. If the next condition terminates the scan, the result is 0.

3. **Matching key without the sentinel.** If an admitted record’s first word matches but its second word is 0 rather than the all-ones sentinel, that record is skipped. No replacement is performed for it.

4. **Zero-mode replacement.** If one admitted record matches both conditions and mode is zero, F-aaebd6c6403f receives the current offset-0x68 value and that record’s address. Upon its normal return, the first word is replaced, then the second word is replaced. With no other admitted records, the function returns 1.

5. **Nonzero mode normalization.** With the same qualifying record and a mode of −7, F-73a1423ea490 is selected. Its third argument is 1, not −7.

6. **Multiple matches.** If two admitted records qualify and both dependency invocations return normally with valid writable record storage remaining, both records are replaced. The result is 1, not 2.

7. **Dependency changes the current record.** If a dependency changes the selected record’s second word away from the sentinel and returns normally, the function does not revalidate that word. It performs both requested assignments.

8. **Dependency shortens the scan.** If a dependency changes the live stopping address so that the next eight-byte scan position is no longer below it, the current replacement still completes. The next condition terminates traversal.

9. **Replacement leaves a qualifying-looking record.** If the replacement first word equals the search key and the replacement second word is the sentinel, the current record is nevertheless processed only once during this ordinary forward visit. The scan advances eight bytes rather than retrying it.

10. **Initial displacement and scan stride differ.** Under valid, nonoverflowing address arithmetic, a shared-table displacement of 2 places the initial scan address 24 bytes beyond the object’s base value. The next candidate is eight bytes beyond that initial address, not twelve.

These unknowns do not justify assuming a stable scan bound, preserved globals, valid post-call memory, or transactional behavior.
