# F-66b9c666fc2b

## Purpose

F-66b9c666fc2b conditionally performs up to four calls to F-9ad23bf5b97e, derives an address through two sequential calls to F-d7e553017aba, writes one 32-bit word at the derived address, invokes F-03b9616af95f, and returns that address if execution completes normally.

The established behavior is an ordered sequence of reads, calls, address calculations, and one explicit write. It does not establish that this function allocates, initializes, destroys, or releases an object. Such interpretations depend on the meanings of the fields, global data, and dependencies, which are unavailable.

## Interface

The supplied representation exposes four formal inputs, each occupying a 32-bit machine word:

| Input | Established use |
|---|---|
| First input | Treated as a base address. Four 32-bit fields are read relative to it, and a fifth relative address is passed to F-d7e553017aba. |
| Second input | Not explicitly used by the visible body. |
| Third input | Forwarded unchanged as the third visible input to F-03b9616af95f. |
| Fourth input | Forwarded unchanged as the fourth visible input to F-03b9616af95f. |

The first input must support the accesses actually reached during execution. The representation uses a 32-bit integer for this input while also using it for addressing. It does not establish a higher-level type, allocation size, or ownership relationship.

Two additional machine-context values appear as the fifth and sixth inputs to F-03b9616af95f:

- A 32-bit value associated with an incoming preserved-register location.
- A 32-bit value associated with the incoming return-link location.

These are not exposed as formal inputs to F-66b9c666fc2b. Their interpretation as intentional dependency arguments, rather than calling-convention or analysis artifacts, is unresolved.

### Output

On normal completion, the function returns a 32-bit pointer-shaped value. It is the address obtained by subtracting `0x80` bytes from the result of the second F-d7e553017aba call.

The returned address is also:

1. The destination of the function’s explicit 32-bit store.
2. The second visible input to F-03b9616af95f.

The function does not return the result of F-03b9616af95f.

### Global data roles

For this contract, the visible global data has three roles:

- **Conditional-call pointer:** a global pointer value captured before the first condition is read. Its pointee supplies 32-bit arguments to F-9ad23bf5b97e.
- **Header value:** a global 32-bit value written at the derived result address.
- **Final-call pointer:** a global pointer whose pointee supplies the first 32-bit input to F-03b9616af95f.

These names describe access roles only. They do not establish object types or ownership.

## Behavior

### 1. Capture the conditional-call pointer

Before inspecting any of the four input-relative conditions, the function reads the conditional-call pointer and retains that address for later use.

This capture matters if a dependency subsequently changes the global pointer. The second, third, and fourth conditional call sites use the captured address rather than re-reading that global pointer.

The captured address is not the same as a captured argument value. The pointee is read afresh at each applicable later call site.

### 2. Process four conditions in fixed order

The function reads and tests the fields in this order:

1. `0x54`
2. `0x94`
3. `0xD4`
4. `0xD8`

For each field:

- If its current 32-bit value is zero, that condition causes no F-9ad23bf5b97e call.
- If its current value is nonzero, one such call is made.
- The next condition is not read until the preceding call, if any, has returned.

Each field is therefore observed at its own point in the sequence. The behavior is not equivalent to snapshotting all four conditions at entry. A dependency may alter a later field before that field is examined.

For the first condition, the visible call argument is obtained by reading the pointee of the conditional-call pointer through the global pointer reference at that call site. For the remaining conditions, the argument is obtained by reading the pointee at the address captured before the first condition.

Without intervening asynchronous mutation, the initial capture and the first call-site pointer read identify the same address: no dependency call occurs between them. The representation nevertheless distinguishes these accesses. It supplies no synchronization or atomicity guarantee.

The condition-field value itself is not passed to F-9ad23bf5b97e. It only controls whether a call occurs. The argument comes from the global-backed pointee.

The visible result of each F-9ad23bf5b97e call is ignored. The function does not clear the tested field or otherwise explicitly record that the call occurred.

### 3. Perform two dependent address transformations

After all four conditions have been processed, the function calls F-d7e553017aba with an address `0xC0` bytes beyond the first input.

Once that call returns, the function subtracts `0x40` bytes from its result and passes that adjusted value to a second F-d7e553017aba call.

The second call depends on the first call’s actual result. There is no visible validation, null check, or alternative path between them.

The function then subtracts `0x80` bytes from the second result. That adjusted address becomes the eventual return value.

### 4. Store a 32-bit header value

At the derived return address, the function stores the global header value as one 32-bit word.

This store occurs:

- After both F-d7e553017aba calls have returned.
- Before the explicit pointee read supplying the first input to F-03b9616af95f.
- Before F-03b9616af95f is invoked.

Only this one word-sized store is explicit in the visible body. There is no explicit initialization of adjacent bytes.

### 5. Invoke F-03b9616af95f

The final dependency receives these visible inputs, in positional order:

1. The 32-bit value read through the final-call pointer.
2. The derived return address.
3. The unchanged third formal input.
4. The unchanged fourth formal input.
5. The incoming preserved-register-context value.
6. The incoming return-link-context value.

The explicit header store has already occurred when this call is made. Consequently, if the final-call pointee aliases the stored word, its argument read observes the post-store contents, subject to the execution environment’s memory semantics.

The final dependency’s result is not used to determine the function’s return value.

### 6. Return

If F-03b9616af95f returns normally and execution reaches the return, the function returns the derived address.

This is an address-return guarantee, not a guarantee about the contents or lifetime of memory at that address after the final dependency runs.

## Side effects

- A capture of the conditional-call pointer.
- Four ordered 32-bit condition-field reads on a fully completing path.
- Zero to four conditional pointee reads and F-9ad23bf5b97e calls.
- Two sequential F-d7e553017aba calls.
- One explicit 32-bit store at the derived address.
- A pointee read through the final-call pointer.

Dependency effects are additional and unspecified. In particular, this contract does not assume dependencies preserve:

- The condition fields.

There is no visible allocation, deallocation, ownership transfer, or reference-count operation that can be established independently of the dependencies. Returning an address and passing it to a dependency do not prove any of these actions.

The function has no explicit error status, rollback, or recovery branch. Invalid memory access or failure to return from a dependency can prevent later operations and normal return. No particular fault, exception, or termination mechanism is established.

## Acceptance examples

These examples are conditional static acceptance criteria, not reports of executed tests. Unless an example states otherwise, all reached memory accesses are valid, dependencies return normally, arithmetic produces usable addresses, and no unspecified mutation or concurrency changes the described observations.

### All conditions are zero

If all four condition fields are zero when individually read:

- F-9ad23bf5b97e is not called.
- Both F-d7e553017aba calls still occur.
- The header store and F-03b9616af95f call still occur.
- The derived address is returned.

Zero conditions do not produce an early return.

### Nonzero does not mean exactly one

If the four observed field patterns are `0x00000001`, zero, `0x80000000`, and `0xFFFFFFFF`, F-9ad23bf5b97e is called three times, at the first, third, and fourth condition positions.

The high bit and signed interpretation do not affect the zero/nonzero decisions.

### A dependency changes a later condition

Suppose the first condition is nonzero and its dependency call changes the field at `0x94` from zero to a nonzero value before returning.

The second condition then causes another call. An implementation that used an entry-time snapshot of that field would not match the established ordering.

### A dependency changes the global pointer

Suppose the captured conditional-call pointer initially identifies location A. The first conditional dependency changes the global pointer to identify location B.

If a later condition is nonzero, its argument is read from A, not B. If the contents of A have also changed, the later call receives A’s current contents rather than an earlier snapshot.

### Address derivation and aliasing

Suppose the first F-d7e553017aba call returns `0x2000`, and the second returns `0x3000`.

Then:

- The second call receives `0x1FC0`.
- The explicit store targets `0x2F80`.
- F-03b9616af95f receives `0x2F80` as its second visible input.
- Normal return yields `0x2F80`.

If the final-call pointer also identifies `0x2F80`, its pointee read occurs after the header store and supplies that stored value, absent another intervening mutation.

### The final dependency overwrites the header

If F-03b9616af95f overwrites the stored word and returns normally, the returned address remains the derived address. The contract does not require the header value to remain there afterward.
