# F-28377ed279d9

## Purpose

F-28377ed279d9 constructs an unsigned result from three byte loads, assigning the first loaded position to bits 16–23, the second to bits 8–15, and the third to bits 0–7 under the apparent eight-bit-byte interpretation.

For a stable base address and valid address arithmetic, this is a three-byte, most-significant-byte-first decode at a signed offset from an indirectly supplied base address. It does not advance that base address or write to the byte region.

That summary has an important qualification: the supplied source evaluates the stored base address twice. One evaluation establishes the address used for the second and third byte positions; another supplies the address used for the first position. A coherent three-byte decode therefore requires those evaluations to produce the same base value.

## Interface

### Inputs

The function receives two arguments:

- **Base-address storage:** a pointer to a signed integer object. The integer value stored there is used as a numeric memory address, not as the first decoded byte.
- **Offset:** a signed integer added to the stored base address before accessing bytes.

The pointer itself, the integer object it designates, and the memory designated by the resulting numeric addresses are distinct parts of the interface. Passing readable byte data directly as the first argument does not satisfy the interface unless that data also represents the intended stored integer address.

### Output

The return type is unsigned integer.

Under the apparent eight-bit-byte model, and provided the unsigned result type is at least 24 bits wide, the returned value is:

- the first byte multiplied by 65,536;
- combined with the second byte multiplied by 256;
- combined with the third byte.

The combination uses bitwise OR. Because these three contributions occupy disjoint bit ranges under that model, the result is between 0 and 16,777,215 inclusive. If the return type is 32 bits wide, bits 24–31 are zero.

The source does not provide the type definitions or target ABI needed to independently establish the exact storage widths of the signed integer, unsigned integer, address space, or byte alias. A 32-bit integer/address and eight-bit-byte interpretation is plausible, but those exact platform widths remain a prerequisite rather than a proven fact.

### Preconditions

For an ordinary successful return:

- The first argument must designate a live, suitably aligned, readable signed integer object.
- Both evaluations of that object must be valid reads.
- Every evaluated signed address addition must be valid under the applicable arithmetic model.
- Conversion of the resulting integer addresses to byte pointers must yield usable addresses.

For a coherent decode from three consecutive locations, the stored base address must remain stable across its two evaluations.

## Behavior

### Address preparation

The function first reads the integer designated by the first argument and adds the offset. It retains that sum for later byte accesses.

This preparation precedes evaluation of the return expression in the supplied source. Consequently, the initial base-address read occurs before the byte loads described below.

### Byte selection

The return expression contains three byte loads:

1. A load at the address obtained by reading the base-address storage again and adding the offset.
2. A load at one byte beyond the retained sum.
3. A load at two bytes beyond the retained sum.

With a stable stored base address, these select three consecutive byte positions beginning at the base plus offset.

The first position is not selected solely from the retained sum. If the two base evaluations differ in an execution model that permits such an observation, the first byte can come from a different region than the other two. This is a consequence of the supplied expression structure, not a supported synchronization mechanism.

### Value construction

Each byte value is converted to the unsigned result type before its shift or combination:

- The first position contributes at shift distance 16.
- The second position contributes at shift distance 8.
- The third position contributes without a shift.

Under the eight-bit unsigned-byte interpretation, values from 128 through 255 remain positive contributions; they are not sign-extended.

The construction is independent of the machine’s native multibyte endianness because it uses separate byte loads and explicit shifts. This does not establish that any particular compiler emits three separate machine load instructions.

The source establishes that the initial base-address read and retained-sum computation precede evaluation of the return expression.

It does **not** establish a left-to-right order among the three byte loads. The bitwise-OR expression supplies no sequencing guarantee between its operands. Within the first byte’s address calculation, the second base-address read necessarily supplies the address before that byte is loaded, but its order relative to the other two byte loads is unspecified by the supplied expression.

Accordingly, this function does not promise:

- first-byte, then second-byte, then third-byte observation;
