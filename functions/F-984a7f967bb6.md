# F-984a7f967bb6

## Purpose

F-984a7f967bb6 obtains a collection-like value from a caller-supplied context, performs a no-argument initialization operation, and repeatedly obtains candidate values. Each candidate is passed to a context-dependent predicate. Candidates whose predicate result is exactly zero are written consecutively to caller-provided storage.

The returned value is the number of candidates written, subject to the signed-counter representability limits described below.

This is a source-facing behavioral contract. It describes the supplied static evidence, not verified runtime behavior. The collection interpretation, initialization purpose, and predicate meaning are inferred intent; the observable calls, comparisons, and writes are established by the supplied representation.

- The bound is queried again after every completed iteration.
- The terminating condition involves a bound-query call, not merely a comparison against a cached value.
- The number of iterations is not necessarily determined by the first bound.

### Candidate processing

For each permitted iteration:

1. F-af55eff9cfe2 is called with the retained collection-like value.
2. Its four-byte result is passed, together with the original context address, to F-ae874c5d2fdd.
3. The predicate result determines whether the candidate is written.

No iteration index is passed to F-af55eff9cfe2. The supplied evidence does not establish how successive candidates are chosen. Advancement could depend on internal state, shared state, or another mechanism.

A predicate result of exactly zero selects the candidate. Any nonzero result rejects it, including negative results.

For a selected candidate, the function writes the candidate’s four-byte value at:

**output base + 4 × number of previously selected candidates**

It then advances the selected-entry count by one.

For a rejected candidate, no output write occurs and the selected-entry count is unchanged.

The iteration count advances once for every processed candidate, regardless of selection. Thus rejection does not cause the same iteration number to be retried.

### Ordering and termination

At the external-call and memory-access level, the normal ordering is:

- Read the context field.
- Call F-3bcd8079c38b.
- Call F-48bbe7bd336f.
- Query the current bound.
- For each admitted candidate, obtain it, evaluate it, optionally write it, and then query the next bound.

A selected candidate is therefore written after its own predicate call and before the next bound query.

The unsigned iteration count increases monotonically from zero. An iteration can start only while that count is below an unsigned 32-bit result. Consequently, the loop admits at most 4,294,967,295 iterations; it does not wrap its iteration count back to zero. This bound assumes calls return and execution is not interrupted by another failure.

This does not guarantee overall completion: a dependency may fail to return, memory access may fail, or selected-count/address arithmetic may leave its supported range.
