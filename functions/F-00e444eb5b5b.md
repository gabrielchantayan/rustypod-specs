# F-00e444eb5b5b

## Purpose

F-00e444eb5b5b returns a signed 32-bit comparison result for two indirectly referenced objects. Its comparison priorities are:

1. Header fields.
2. Collection counts.
3. Entry tags, selected content, and secondary values, visiting entries in descending index order.
4. Entry keys, in a separate descending-index pass.

Results are not normalized to −1, 0, or 1. A terminating result may be an unchanged dependency result or an arithmetic difference.

Comparison of structured objects is inferred intent. The supplied representation does not establish a total order, antisymmetry, transitivity, or repeatability. Dependencies may modify storage used later, collection counts are queried repeatedly, and one content dependency receives only the left payload.

## Behavior

### Header comparison and collection-slot selection

The function first reads the left object address, then the right object address, from the argument slots. These object addresses are retained; the argument slots are not reread.

It supplies the objects’ offset-4 fields to F-9a2842991e6f in left/right argument order. The relative evaluation order of the two header-field reads is not established.

A nonzero dependency result is returned immediately, without collection access.

After a zero result, the function reads the right object’s offset-12 field, then the left object’s offset-12 field. These values identify collection-handle slots whose addresses are retained.

Each later collection operation rereads the handle from its retained slot. Consequently:

- Changing a retained slot’s contents can change subsequent collection arguments.
- Changing only an object’s offset-12 field does not redirect subsequent operations to another slot.
- Header-dependency mutations can affect the initially selected slots because slot selection occurs after that call.
- Changing an argument slot during the header call does not replace the already-retained object address.

### Count comparison

F-10b760faca36 is called with the current left handle, then with the current right handle.

If these results differ, the function queries the current left handle again, then the current right handle again. It immediately returns the second left count minus the second right count.

The first pair only selects this return path. It does not supply the subtraction operands. Equal recomputed counts therefore produce an immediate zero despite the initial mismatch.

If the first pair agrees, a further left-handle count query supplies the first pass’s starting count. This new result need not equal either earlier result. There is no corresponding fresh right-count check.

### First descending pass

For an ordinary nonnegative starting count, entries are visited from count minus one through zero. The traversal decrements before testing whether the index is negative.

At each visited index:

1. F-6bbddce1b930 retrieves the left entry using the current left handle.
2. F-6bbddce1b930 retrieves the right entry using the current right handle.
3. The left entry’s payload address and payload tag are read.
4. The right entry’s payload address and payload tag are read.
5. The right tag is subtracted from the left tag.

A nonzero tag difference is returned immediately.

A zero tag difference selects a content branch using the already-read left tag. Tags are not revalidated after subsequent dependency calls.

A nonzero content result terminates the function. Otherwise, the function subtracts the right entry’s offset-8 secondary value from the left entry’s offset-8 secondary value. These fields are read after the content operation, allowing its dependencies to affect them. Their relative read order is not established.

A nonzero secondary difference terminates the function. Zero permits the next lower index.

All first-pass comparisons precede every key comparison. A content difference at a lower index can therefore terminate execution before a key difference at a higher index is considered.

### Byte branch: payload selection and initial lengths

The function reads and retains the left payload address, then the right payload address. Subsequent byte-branch payload accesses use these retained addresses, not fresh reads of the entries’ payload-address fields.

The right payload’s signed offset-0 length is read first and saved. The left length is then read and compared with that saved right length.

If the lengths differ, the function rereads the left length and subtracts the saved right length. This difference is the content result. No byte transformation occurs, and the right length is not reread.

If storage changes between the left-length reads, the resulting difference can be zero despite the earlier inequality. Zero then permits the secondary comparison; it is not an immediate return from the whole function.

### Byte branch: dynamic traversal

If the initial lengths compare equal, byte traversal starts at index zero.

Every loop-condition evaluation rereads the retained left payload’s signed length. This includes the first condition and the condition after each equal transformed pair. The initial length is not a fixed bound.

For each entered iteration, the sequence is:

1. Read the retained left payload’s offset-8 buffer address.
2. Load one byte at the current index and pass it to F-1aef7372e8d8.
3. Read the retained right payload’s offset-8 buffer address.
4. Load one byte at the same index and pass it to F-1aef7372e8d8.
5. Compare the two transformation results.

Unequal transformation results immediately end the content comparison with left result minus right result. No later byte index is examined.

Equal results advance the index by one. A fresh left-length read then determines whether another iteration begins. If the condition fails, the content result is zero.

The controlling observation is the length read at that next condition, not a length value written by either transformation call:

- A left-call increase does not guarantee another iteration; the right call can reduce the length again.
- A left-call decrease does not guarantee termination; the right call can restore or increase the length.
- After an equal pair at index zero, index one is entered only if the next condition observes a left length greater than one.
- A change to the length during an iteration does not cancel its remaining right-byte access and transformation.
- The right length is not reread and does not independently constrain traversal.

Buffer fields are also reread for each byte access. The left transformation can redirect the right buffer access for the same index. Either transformation can change buffer fields used later.

Zero-valued bytes have no special terminating meaning; they are transformed like other bytes.

#### Stable-data interpretation

With stable equal positive lengths and stable buffer fields, the branch examines up to that many byte pairs in ascending index order. The first unequal transformed pair ends comparison immediately.

The complete range from zero through length minus one is examined only if every pair before the last index compares equal. A mismatch at the final index examines the full range but still yields a nonzero result. Completion with zero requires equal transformation results throughout and exhaustion of the bound.

Stable equal zero or negative lengths cause no transformations.

Without stability, the condition may admit indices beyond the initial length or stop before that initial range is exhausted. Termination is not established when dependencies keep changing the bound.

## Acceptance examples

These are conditional acceptance scenarios, not executed tests. All require valid accessed storage, returning dependencies, and defined arithmetic. Stability is assumed only where stated.

1. **Header short circuit.** If F-9a2842991e6f returns −7, the function returns −7 without collection calls.

2. **Recomputed counts.** Initial counts of 2 and 5 followed by counts of 4 and 6 produce −2. Recomputed counts of 4 and 4 instead produce an immediate zero.

3. **Stable empty collections.** With a zero header result and every count query returning zero, neither pass retrieves entries, and the result is zero.

4. **Descending priority.** A first-pass count of three starts at index 2. A terminating difference there prevents retrieval at indices 1 and 0.

5. **Tag difference.** Left tag 0x16 and right tag 0x13 produce 3, without content or secondary comparison for that entry.

6. **One-sided content result.** Matching tag 0x13 and an F-4d3d7560af30 result of 5 produce an immediate result of 5.

7. **Unequal byte lengths.** A saved right length of 3 and both relevant left-length reads returning 2 produce −1 without transformations.

8. **Early byte mismatch.** With stable equal lengths of four, transformation results 12 and 20 at index zero produce −8. Later indices and the entry-secondary comparison are skipped.

9. **Final-index mismatch.** With stable equal lengths of two, equal results at index zero followed by results 12 and 20 at index one produce −8. Both indices are examined.

10. **Complete byte equality.** With stable equal length three and equal transformation results at every index, exactly three byte pairs are examined. The zero content result permits secondary comparison.

11. **Growth observed by the next condition.** Initially equal lengths of one allow index zero. If its transformed pair is equal and the next condition reads a retained left length greater than one, index one is entered. A left transformation’s increase to two alone is insufficient: the subsequent right transformation may change the length again.

12. **Shrinkage observed by the next condition.** Suppose index zero is entered with initially equal lengths of three, and its left transformation sets the retained left length to zero. The right-byte access and transformation still occur. If the pair compares equal and the next condition observes a nonpositive left length, traversal ends with zero content result. If the right transformation instead restores a length greater than one and that value is observed, index one is entered.

13. **Right-buffer redirection.** If the left transformation changes the retained right payload’s buffer field, the current right byte is loaded through the changed field.

14. **Right length is not the ongoing bound.** Changing only the right length to zero after initially equal lengths of two does not stop traversal. If the first pair agrees and the next condition reads left length two, index one is examined.

15. **Stable nonpositive lengths.** Stable equal lengths of zero or −1 cause no transformations and permit secondary comparison.

16. **Content before keys.** A first-pass content difference at index 1 wins even if keys differ at index 2. F-9878699bd825 is not reached.

17. **Fresh key-pass count.** If the first pass completes with count two but the key-pass count is one, only index zero is visited for keys. Its nonzero comparison result is returned unchanged.
