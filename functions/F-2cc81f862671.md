# F-2cc81f862671

## Purpose

F-2cc81f862671 accepts two 32-bit operand words. It either:

- Returns the first operand unchanged.
- Returns a packed status word derived from raw-word comparisons and an ambient status byte.
- Dispatches to an unresolved indirect dependency and forwards its normally returned result.

The operand boundaries match IEEE 754 binary32 finite, infinity, and NaN encodings. That interpretation is inferred intent. The established behavior is integer manipulation of bit patterns, not floating-point arithmetic or a conventional floating-point comparison interface.

The dispatch behavior depends on shared configuration, separately addressed data words, and an ambient target-bearing word. The supplied representation does not establish the actual indirect target, its calling convention, or its effects.

The operands are passed by value. The directly represented logic does not dereference them.

Arithmetic and bitwise transformations described here use 32-bit words. Addition, subtraction, doubling, and left shifts discard bits beyond bit 31. Complements invert exactly 32 bits. Signed interpretations use two’s-complement 32-bit values. Comparisons are unsigned unless stated otherwise.

Bit numbering starts at zero for the least significant bit.

## Behavior

### Operand classification

For classification, an operand’s **magnitude field** is its lower 31 bits.

The initial gate is equivalent to the following condition:

> If both magnitude fields are strictly less than `0x7f800000`, return the original first operand unchanged.

This equivalence follows from the represented signed tests, overflow tests, and individual-operand checks. It does not require floating-point interpretation.

Consequences include:

- Positive and negative zero are returned without normalization when paired with another finite-like operand.
- Subnormal and ordinary finite-like operands take the identity path when both operands are below the magnitude boundary.
- Combining bits from two individually finite-like operands does not by itself force dispatch or status construction.
- No shared configuration or dispatch data word is read on this path.

If the identity condition does not hold, the function distinguishes the exact boundary from values above it.

It doubles the first operand modulo \(2^{32}\). Only if that value is below `0xff000001` does it use the doubled second operand for the remaining threshold decision. A selected doubled value below `0xff000001` leads to packed-status construction; otherwise, execution enters configuration-dependent dispatch.

Equivalently:

| Operand magnitudes | Outcome |
|---|---|
| Both below `0x7f800000` | Identity return |
| At least one equals `0x7f800000`, neither exceeds it | Packed-status construction |
| At least one exceeds `0x7f800000` | Configuration-dependent dispatch |

Thus, under the inferred binary32 interpretation, finite pairs return the first operand, an infinity without any NaN reaches status construction, and any NaN-like operand reaches dispatch. No distinction between signaling and quiet NaN encodings is established.

### Packed-status construction

The comparisons use the original raw operand words. They are not substituted with floating-point numerical ordering.

Every packed-status result has bits 0–26 clear. The treatment of bits 27–31 depends on whether either operand has bit 31 set.

#### At least one operand has bit 31 set

The function combines the ambient status byte with equality at field bit 3 and unsigned first-less-than-or-equal-to-second at field bit 2. It retains only field bits selected by `0x0d`, then shifts that field left by 27 bits. It additionally sets result bit 31 when the first operand is unsigned-greater-than the second.

The complete returned layout is:

| Result bit | Set when |
|---|---|
| 31 | First operand is unsigned-greater-than the second |
| 30 | Operands are equal, or ambient status bit 3 is set |
| 29 | First operand is unsigned-less-than-or-equal to the second, or ambient status bit 2 is set |
| 28 | Never |
| 27 | Ambient status bit 0 is set |
| 0–26 | Never |

Ambient status bits 1 and 4–7 do not survive this branch.

A negative-infinity-like raw word is unsigned-greater-than any nonnegative raw word. That raw ordering is part of the behavior, regardless of inferred floating-point intent.

#### Neither operand has bit 31 set

The function combines:

- Field bit 4 for first operand less than second.
- Field bit 3 for equality.
- Field bit 2 for second operand less than or equal to first.
- The ambient status byte.

The combined value is narrowed to eight bits and shifted left by 27 bits as a 32-bit word. Only the lowest five field bits survive that shift.

| Result bit | Set when |
|---|---|
| 31 | First operand is less than second, or ambient status bit 4 is set |
| 30 | Operands are equal, or ambient status bit 3 is set |
| 29 | Second operand is less than or equal to first, or ambient status bit 2 is set |
| 28 | Ambient status bit 1 is set |
| 27 | Ambient status bit 0 is set |
| 0–26 | Never |

The supplied representation contains an alternative guarded by signed subtraction overflow. It cannot be selected here: both operands are between zero and `0x7fffffff`, so their mathematical difference is within the signed 32-bit range. The table therefore describes all reachable results in this branch.

### Configuration-dependent dispatch

Dispatch occurs when at least one operand’s magnitude exceeds `0x7f800000`.

The following shared configuration accesses are separate represented reads. No single-snapshot guarantee is supplied. Decisions based on a previously retained mode continue to use that mode even if a later configuration read differs.

Every invocation below targets F-INDIRECT-01. If it returns normally, its 32-bit result becomes this function’s result without further represented processing.

#### Initial configuration gate

First, read the configuration word and test mask `0x000d0000`.

- If any masked bit is set, proceed directly to the later configuration tests.
- If all masked bits are clear, read the configuration word again and retain its low four bits as the mode.

The initial mask selects bits 16, 18, and 19. It does **not** select bit 17, whose mask is `0x00020000`.

#### Mode 10

For retained mode 10:

1. Read the default dispatch word.
2. Read the configuration word and test `0x40`.
3. Dispatch with one represented argument: `0x80000000` if that bit is set, otherwise the previously read default dispatch word.

The default dispatch word is read even when its value is subsequently discarded.

#### Mode 8

For retained mode 8, read the configuration word and test `0x40`.

If set, dispatch with two represented arguments, both zero. Neither dispatch seed is read on that branch.

If clear:

1. Read the first dispatch seed.
2. Read the configuration word and test `0x10`.
3. If clear, dispatch with the first seed followed by the original second operand.
4. If set, read the second dispatch seed and dispatch with zero followed by that seed.

The first seed is read before the `0x10` test and remains a represented access even when that test causes its value to be discarded.

#### Other modes except 9

For retained modes other than 8, 9, or 10, dispatch with no explicitly represented arguments.

This does not establish that machine argument locations are cleared, absent, or irrelevant to the actual target.

#### Mode 9

For retained mode 9, replace the first operand’s working value with the 32-bit integer 8, then continue to the later configuration tests.

This replacement affects a possible subsequent dispatch argument. It does not write to caller-owned operand storage or alter the original second operand.

### Later configuration tests

These tests are reached either through the initial masked gate or after retaining mode 9.

First, read the configuration word and test `0x00100000`.

- If clear, dispatch with one represented argument, zero.
- If set, read the configuration word again and test `0x00070000`.

When that later mask is zero, dispatch with three represented arguments, in order:

1. `0x30000000`.
2. The original second operand.
3. `0x30000000`, additionally containing `0x08000000` when ambient status bit 0 is set.

The third argument is therefore either `0x30000000` or `0x38000000`.

When that later mask is nonzero, read the configuration word once more and dispatch with two represented arguments:

1. The first operand’s working value: 8 after mode 9, otherwise the original first operand.
2. The result of shifting this final configuration observation left by 15 bits, complementing the resulting 32-bit word, and shifting that complement left by one bit.

All truncations are 32-bit. The second argument always has bit 0 clear and bits 1–15 set. Its upper 16 bits are the bitwise complement of the low 16 bits of the configuration observation used for argument construction.

The `0x00070000` test selects bits 16, 17, and 18. Unlike the initial mask, it includes bit 17. Stable configuration can therefore both select mode 9 and reach this final two-argument dispatch.

## Acceptance examples

These are conditional consequences of static analysis, not executed tests. Ambient status is zero unless stated otherwise. A stable configuration means every configuration read during the example observes the stated value.

### Identity and boundary cases

- First operand `0x3f800000`, second operand `0x40000000`: return `0x3f800000`, with no configuration-dependent dispatch.
- First operand `0x80000000`, second operand `0x00000000`: return `0x80000000`. Negative zero is not normalized.
- First operand `0x7f7fffff`, second operand `0x00000000`: return `0x7f7fffff`; the largest positive finite-like encoding remains below the boundary.
- Both operands `0x7f800000`: return `0x60000000`, representing equality and second-less-than-or-equal-to-first.
- First operand `0x3f800000`, second operand `0x7f800000`: return `0x80000000`.
- First operand `0xff800000`, second operand `0x3f800000`: also return `0x80000000`, because the first raw word is unsigned-greater-than the second in the sign-set branch.

### Ambient status retention

With both operands `0x7f800000` and ambient status `0x02`, return `0x70000000`. Ambient bit 1 survives as result bit 28.

With both operands `0xff800000` and the same ambient status, return `0x60000000`. The sign-set branch masks that ambient bit away.

### Mode 10 reads before overriding

With first operand `0x7fc00000` and stable configuration `0x0000004a`:

- The initial mask is zero and retained mode is 10.
- The default dispatch word is read.
- Configuration bit `0x40` selects the replacement.
- F-INDIRECT-01 receives the single argument `0x80000000`.

Any normally returned word is forwarded unchanged.

### Mode 8 argument selection

With a NaN-like operand and stable configuration `0x00000008`, the first dispatch seed is read, and F-INDIRECT-01 receives that seed followed by the original second operand.

With stable configuration `0x00000018`, the first seed is still read, but the later `0x10` test selects replacement arguments. The second seed is then read, and the dependency receives zero followed by the second seed.

With stable configuration `0x00000048`, the dependency receives zero and zero without either seed being read.

### Stable mode 9 reaches the final two-argument dispatch

With a NaN-like operand and stable configuration `0x00120009`:

- Its intersection with `0x000d0000` is zero, so mode decoding occurs.
- Retained mode 9 replaces the first working operand with 8.
- Bit `0x00100000` is set.
- The later `0x00070000` test finds bit `0x00020000` set.
- F-INDIRECT-01 receives `0x00000008` followed by `0xfff6fffe`.

This path requires no change in configuration observations.

### Other later-dispatch shapes

With a NaN-like operand and stable configuration `0x00000009`, mode 9 is retained, but bit `0x00100000` is clear. The dependency receives the single argument zero.

With stable configuration `0x00100009`, the three-argument branch is selected. If the original second operand is `0x12345678` and ambient status bit 0 is set, the arguments are `0x30000000`, `0x12345678`, and `0x38000000`.

With stable configuration `0x00140000`, the initial mask bypasses mode decoding. The final two-argument branch receives the original first operand, not 8, followed by `0xfffffffe`.
