- Copy a 32-bit field at state offset +12 into the field at offset +8.

### Eligibility

If the index is negative, dispatch is skipped and the function returns zero normally. The object bound and function table are not read on this path.

If the index is nonnegative, the function reads the signed 32-bit bound at object offset +4. The incoming third scalar does not supply this bound.

The combined signed comparison accepts exactly those indices that are:

- At least zero; and
- Strictly less than the object bound.

The supplied representation separately excludes equality and requires a less-than-or-equal relation. Together, these establish strict inequality rather than an inclusive upper bound.

Consequences:

- Index zero is eligible for any positive bound.
- Equality with the bound is rejected.
- An index above the bound is rejected.
- A zero or negative bound admits no index.
- The maximum signed 32-bit index, 2,147,483,647, is never eligible.
- With the maximum signed bound, 2,147,483,646 is eligible, while 2,147,483,647 is not.

No addition, subtraction, increment, or scaling of the index or bound is shown. The eligibility decision therefore does not depend on overflow from such arithmetic. Signed interpretation is material: a 32-bit all-ones index is negative, not a large accepted unsigned index.
