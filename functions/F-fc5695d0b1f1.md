# F-fc5695d0b1f1

## Purpose

F-fc5695d0b1f1 performs an extended sequence of indirect dependency invocations, modifies an address-based state space through mixed-width operations, and transfers four arguments to an unresolved final target.

The established behavior concerns invocation order, fixed-width expression results, address derivation, explicitly typed memory accesses, retained captures, and later reevaluations of global symbols. No business-level purpose, object model, ownership protocol, or successful-result invariant is established.

This contract distinguishes:

- **Established static evidence:** operations and relationships visible in the supplied representation.
- **[INFERENCE]:** interpretations that are not acceptance requirements.
- **documented_only:** unresolved details for which this contract supplies no executable guarantee.

All acceptance examples are conditional static criteria. No runtime tests have been performed.

## Behavior

### Widths, arithmetic, and ordering

For explicitly typed indirect accesses, **byte**, **halfword**, and **word** mean 8, 16, and 32 bits. Explicit unsigned-byte reads used numerically are zero-extended. Explicit byte stores retain the low eight bits.

These rules do **not** establish access widths for undeclared global symbols. Converting a global expression to 32 bits establishes the converted result, not the global’s storage width, signedness, extension behavior, or physical access size. Likewise, an eight-bit right-hand value does not establish an eight-bit global store.

The body has no visible conditional branch or loop. Dependencies may nevertheless branch, fail, or not return. Ordering below describes represented operation boundaries, not an instruction-level bus trace or a guarantee that every source-level evaluation causes a separate physical transaction.

A retained capture is not replaced by a later reread. Addresses are not assumed disjoint.

Under a **conditional 32-bit bit-vector interpretation**, arithmetic and left shifts retain their low 32 bits, and unsigned right shifts are logical. Signed overflow and signed-shift semantics are not established as portable behavior. Address wrapping is also unresolved.

Represented 64-bit result containers contribute fields extracted above bit positions 32, 34, 36, and 44. Those extractions contain at most 32, 30, 28, and 20 bits respectively.

### Dependency-driven preparation

The first invocation receives the first explicit input unchanged. Further preparation invocations have zero to four represented arguments.

Their argument relationships include shifted primary results, extracted upper portions of 64-bit results, secondary result channels, duplicated values, retained values spanning intervening calls, and explicitly zero-valued arguments. Incoming machine state contributes shifts by 3, 9, and 10; the fourth explicit input contributes a shift by 25.

Masks and shifts select or reposition fields of several widths. Truncating a shift before applying a mask is not generally interchangeable with masking first. Some zero-initialized intermediates remain zero through subsequent transformations, but invocations receiving those zeros remain dependency boundaries.

Similar argument shapes do not establish identical targets. The preparation sequence cannot be replaced by an assumed allocation, formatting, encoding, or arithmetic service.

## Acceptance examples

These examples assume execution reaches the relevant region and all required operations are supported.

1. **Forwarding:** First input `0x12345678` reaches F-000000000001 unchanged.

2. **Shift truncation:** Under compatible 32-bit bit-vector shifts, fourth inputs 1 and 129 both contribute `0x02000000` after shifting left by 25. Entire executions need not be equivalent.

3. **Index boundary:** A contributing result with lowest seven bits `0x7f` yields small index 508 and index base 1016.

4. **Global-selected address:** If evaluation and unsigned 32-bit conversion of the `0x05` global produce `0x1234`, the subsequent explicit byte destination is `0x1249`. The contract does not truncate that base to `0x34` or require a byte load at `0x05`.

5. **Narrow value, unknown store:** For index base `0x3f8`, the value offered to the `0x01` global assignment is the eight-bit value `0xf8`. Its physical store width and neighboring-byte effects are unresolved.

6. **Scaling boundary:** For captured link 3 under compatible arithmetic, the expression offered to the `0x54` global assignment is 6. The assignment remains between the specified derived word publications; its storage width is unknown.

7. **Fresh global evaluation:** If a later evaluation of the `0x67` global produces a value whose conversion to an explicit byte is `0xbb`, the corresponding derived byte publication receives `0xbb`, not a cached earlier `0xaa`. No particular global read width follows.

8. **Character arithmetic:** With adjusted scale 16, the expression assigned to the `0x3a` global is 176. This does not establish an eight-bit destination.

9. **Capture preservation:** A retained state word captured as `0x11223344` remains final argument three despite a later overwrite of its source location.

10. **Distinct late arguments:** Dispatch word 7 and late transfer word 9 produce final arguments two and four of 7 and 9.

11. **Explicit widths:** The three derived `0x3a` constant publications use byte, halfword, and word widths respectively.

12. **Interrupted preparation:** If a preparation dependency does not return, subsequent mutations and final dispatch are not required to occur.
