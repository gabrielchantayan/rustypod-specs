# F-09cad11f7a05

### Selector encoding for dispatch values 1 through 4

These paths read A+0x28, then reread the byte at A+0x2C. Let \(s\) be this second byte value, interpreted as unsigned.

The middle output word has the 32-bit pattern

\[
\text{0x80000010} + 256s.
\]

The byte value is zero-extended before multiplication. Since \(0 \leq s \leq 255\), the product ranges from 0 through 0xFF00. Adding it to 0x80000010 does not overflow an unsigned 32-bit word. The resulting patterns range from 0x80000010 through 0x8000FF10.

Interpreted as signed 32-bit values, those patterns equal

\[
-2147483632 + 256s,
\]

which also remains within the signed 32-bit range. No saturation or overflow-dependent behavior is needed to obtain the stated result.

If both selector reads agree, dispatch values 1, 2, 3, and 4 produce middle words 0x80000110, 0x80000210, 0x80000310, and 0x80000410.

The second byte read is not range-checked. A different second value changes the encoding without changing the already selected branch. Whether intervening mutation is possible under the actual execution environment is unresolved.
