# F-7282d0de00cb

## Purpose

F-7282d0de00cb exposes a long sequence of external calls, computed-address memory writes, byte extraction, and a terminal loop with no visible exit.

The available static representation does **not** establish a higher-level purpose. In particular, it does not justify describing this operation as initialization, serialization, allocation, device control, or data conversion. The most defensible contract is an ordered account of the visible effects, conditional on the recovered control flow being accurate.

The representation reports invalid instruction data and removed unreachable regions. Consequently, the sequence below is established as **visible static evidence**, not as verified executable behavior.

The terminal region is an unconditional loop. If execution reaches it and every memory operation and dependency call completes normally, the visible representation never returns. Earlier faults, nonreturning dependencies, exceptions, or transfers outside the recovered flow remain possible; their handling is unknown.

## Behavior

### Interpretation and notation

The following notation describes data relationships, not an implementation:

- **W(address, value)** is one visible four-byte write.
- **B(address, value)** is one visible one-byte write, retaining only the low eight bits of the value.
- **L** is the unsigned 32-bit word read from entry base plus 20.
- **H** is the entry word.
- **R1, R2, …** name successive selected dependency results in the ordering below. These are editorial names, not source identifiers.
- **Q** is the auxiliary call-boundary result noted in the interface.
- **K** and **T** are derived unsigned quantities defined where used.

All offsets are byte offsets. A four-byte value does not establish the existence of a larger object or structure. In particular, repeated offset 20 accesses do not prove that their addresses share an object layout.

Unsigned right shifts are logical shifts. Signed-looking multiplication and left-shift expressions occur in the representation. Their overflow semantics are not established by that representation alone. Where examples use wraparound, that interpretation is explicitly conditional.

### Dependency sequence notation

The dependency identifiers below are opaque, document-local labels. They do not assert externally established identities.

- **F-U01**: the initial two-input call.
- **F-U02**: an ordered pair of no-explicit-input producer calls, each immediately followed by a consumer receiving that producer’s 32-bit result.
- **F-U03**: an ordered group of four calls with no explicit arguments; the fourth supplies the selected result.
- **F-U04**: a call receiving the arguments stated at its occurrence.
- **F-U05**: an ordered pair of producer/consumer pairs. Each producer has no explicit arguments. The first consumer receives its producer’s result; the second receives its producer’s result and any additional argument specified below.
- **F-U06**: a single no-explicit-input producer followed by a consumer receiving its result.
- **F-U07**: the first terminal-loop entry call.
- **F-U08**: the terminal-loop entry call used on subsequent iterations.

Repeated labels describe a call-sequence shape, **not a claim that the underlying target addresses are equal**. Individual occurrences can invoke different targets. No preservation, ownership, or failure behavior is attributed to these dependencies.

### Initial access and first results

The visible order begins as follows:

1. W(four times the second input plus 20, entry payload).
2. Read L from entry base plus 20.
3. Invoke F-U01 with the first and second inputs.
4. Execute F-U02.
5. Execute F-U03, obtaining R1.
6. W(second input plus 20, L shifted right by eight).
7. Invoke F-U04 with four times R1.
8. Execute F-U03, obtaining R2.

The first write therefore precedes the load of L. If their byte ranges overlap, the load can observe the first write. The later write using L uses the captured value, not a fresh read from entry base.

The two destinations derived from the second input are different formulas: four times that input plus 20, and that input plus 20. Neither may be substituted for the other.

Before step 5, the third input is logically shifted right by seven. Step 7 passes that intermediate value shifted right by seven again. It does not pass merely the original value shifted right by seven.

Before step 15’s calls, K is derived as:

**K = ((4 × R13) AND 0x7fffffff) shifted right by 7.**

The multiplication’s width and overflow interpretation must be resolved before this formula can be assigned unconditional machine semantics.

Calls separate several writes to the same computed destination. Such writes are distinct observable events. Unknown dependencies may change the intervening contents.

### Byte-addressed phase

A recurring operation in this phase reads one unsigned byte from K plus 1, adds 17 to that byte’s numeric value, and uses the result as a byte-write address.

The resulting destination is in the numeric range **17 through 272**, inclusive. It is not established as a pointer-sized value loaded from memory.

The sequence is:

1. Read the byte at K + 1; write the low byte of 4 × R17 to the resulting byte value plus 17.
2. Invoke F-U04 with three identical arguments, each 4 × R17.
3. Execute F-U06.
4. Execute F-U03 → R18.
5. **Read the byte at K + 1 again**; write the low byte of `(R17 AND 0x3fffffff) shifted right by 20` to the newly derived destination.
6. Invoke F-U04 with 4 × R18; execute F-U03 → R19.
7. B((H shifted right by 23) + 28, 4 × R19).
8. Read the byte at K + 1 again; write zero to that byte value plus 17.
9. Invoke F-U04 with H shifted right by 23.
10. Make one no-explicit-input call whose ordinary result is ignored.
11. Invoke F-U04 with `(R19 AND 0x3fffffff) shifted right by 6`.
12. Execute F-U03 → R20.
13. Read the byte at K + 1 again; write zero to that byte value plus 17.
14. Invoke F-U04 with 4 × R20; execute F-U03 → R21.

The repeated byte-source reads are not interchangeable with a cached value. Dependencies, aliasing writes, or externally changing memory can alter the source between occurrences.

The shift used in step 5 leaves at most ten meaningful bits before byte truncation. The stored byte therefore contains bits 20 through 27 of R17; bits 28 and 29 do not survive the byte write.

### Transition into the terminal loop

Set T to `(R21 AND 0x3fffffff) shifted right by 25`. Thus the initial T is between 0 and 31.

Next:

1. Read one unsigned byte at `(4 × R19) × 1024 + 1`.
2. Write zero to that byte value plus 17.
3. Invoke F-U04 with twice T.
4. Make one no-explicit-input call, obtaining R22.

The byte source here is different from K + 1. Its address retains the earlier R19-derived quantity.

### Terminal loop

The first iteration invokes F-U07 with R22 and T shifted right by eight. Since initial T is at most 31, this second argument is zero.

Each iteration then:

1. Makes four no-explicit-input calls, selecting the fourth result.
2. Reads the byte at `(4 × R19) × 1024 + 1` again and writes zero to that byte value plus 17.
3. Invokes an argument-taking dependency with four times the selected result.
4. Makes four further no-explicit-input calls, selecting a new result.
5. Forms the next first argument as four times that new result.
6. Forms the next T by shifting that result left by 26.

Subsequent iterations use F-U08 rather than the first iteration’s F-U07. Their second argument is the updated T logically shifted right by eight.

There is no visible exit condition, explicit delay, error branch, or return.

## Side effects

The visible effects include:

- One early four-byte read.
- Numerous four-byte writes through arithmetic-derived addresses.
- Repeated unsigned-byte reads used to derive low numeric write addresses.
- Byte writes containing truncated arithmetic results or zero.
- An unbounded sequence of dependency calls and byte writes if the terminal loop continues.

No allocation, deallocation, ownership transfer, reference-count change, or resource release is established. Passing a value to a dependency does not establish whether that value denotes owned memory.

No rollback is visible. A fault or nonreturning dependency can leave any already completed writes in place.

The sequence does not establish atomicity, synchronization, volatile semantics, or inter-thread ordering. Endianness is unspecified for four-byte accesses.

## Dependencies

F-U01 through F-U08 identify only the opaque call relationships described above.

The first target depends on incoming control state. Other visible targets are formed from embedded control-address values, including one target formed through a code-associated byte pointer. Their names, signatures beyond displayed arguments, and implementations are unavailable.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Early aliasing.** If the initial four-byte destination equals the subsequent four-byte source, and ordinary memory semantics apply, L reflects the entry payload just written. Reading the original contents instead would contradict the visible order.

2. **Two-stage third-input shift.** With third input 0x00004000, the fourth argument at word-write step 7 is 1. With third input 0xffffffff, it is 0x0003ffff.

3. **Distinct word destinations.** With R2 equal to 3 and no arithmetic overflow, the first two table writes target addresses 68 and 32 respectively. Both store 12.

4. **Repeated destination read.** If the byte at K + 1 is 5 for the first byte write and 9 for the next, the destinations are 22 and 26. Reusing address 22 for the second write is not supported.

5. **Byte truncation.** If R17 is 0x12345678 under 32-bit wraparound arithmetic, the first byte write stores 0xe0. The later R17-derived byte write stores 0x23.

6. **Initial loop argument.** Every possible initial T produces zero for the first loop call’s second argument. This does not imply that subsequent iterations also pass zero.

7. **Loop-state update under wraparound.** If a loop’s final selected result is 1, the next first argument is 4 and its second argument is 0x00040000, assuming 32-bit left shifts retain the low 32 bits.

8. **Interrupted progress.** If a dependency fails to return after a write, later writes are not required to occur. The visible sequence supplies no rollback guarantee.
