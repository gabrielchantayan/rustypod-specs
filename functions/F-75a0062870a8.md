# F-75a0062870a8

## Purpose

F-75a0062870a8 selects an object and coordinates one of two state-transition sequences. Its observable behavior includes conditional cache initialization, service queries, subordinate-object calls, one-byte marker writes, notifications, and a final notification sequence on a separately obtained receiver.

**Established static behavior:** a dependency supplies a 32-bit discriminator and a 32-bit object pointer. A zero discriminator selects a path with preliminary service work and a marker-dependent early return. Any nonzero discriminator selects a path without that gate. Both paths condition some transition work on a subordinate query.

**Inferred intent:** the two paths appear complementary, possibly disabling and enabling a mode. That interpretation is not required by this contract. They are called the **zero path** and **nonzero path** below.

Notification categories, payloads, and branch-specific opaque data have no established application-level meanings.

## Behavior

The following ordering describes the supplied static representation. It assumes dependencies return normally and all subsequently accessed storage remains valid. It does not establish atomicity, synchronization, or preservation of shared state.

### Selection

Call F-f2db0ea1d7cc with the input twice. Extract the selected-object address and discriminator from the result. Retain the selected-object address for the chosen branch.

### Zero path: cache and service work

Read the 32-bit cache at offset 0x94.

If the cache is zero:

1. Call F-938c950e5046 to obtain a receiver.
2. Dispatch through that receiver’s slot 0xF8, passing the receiver and an opaque initialization value read from global storage.
3. Store the 32-bit result at selected-object offset 0x94.

A zero result is stored as zero. There is no retry within this invocation and no separate initialized flag in the visible behavior.

Next, call F-87be4aa684d1 and retain its returned receiver for the preliminary service sequence:

1. Invoke slot 0x190.
2. Only if that result is zero, invoke slot 0x194.
3. If either evaluated result is nonzero, invoke slot 0xEC once.

Thus, a nonzero first result suppresses the second query but not the action. Two zero results suppress the action.

These operations occur before the marker test. They can therefore have effects even when the function subsequently returns early.

### Zero path: marker gate and subordinate query

Read the 32-bit quantity at offset 0x2C and test its character-narrowed value.

If the narrowed value is zero, return immediately. This route performs no subordinate query, selected-object notification, or common completion.

Otherwise:

1. Write a zero byte at offset 0x2C.
2. Resolve and invoke subordinate slot 0x20.
3. Read the zero-path primary category from global storage and retain that 32-bit value.

The marker clear precedes the query. The primary-category read follows the query, irrespective of its result.

### Zero path: conditional transition

If the subordinate query returned nonzero, perform the following sequence:

1. Invoke subordinate slot 0x24 with the subordinate receiver and integer 1.
2. Invoke subordinate slot 0x30 with the subordinate receiver and the byte read from selected-object offset 0x2D.
3. Call F-9c5c2db853f7 with the selected object, the 32-bit value read at offset 0x20, and integer 1.
4. Call F-438680ffebfe with the selected-object address plus 0x8C and the address of zero-path opaque global data.
5. Notify the selected object through slot 0x58 using the retained primary category and the first conditional payload.
6. Read the zero-path secondary category from global storage and retain a snapshot.
7. Issue the first secondary notification. Its category argument comes from a **separate read of that same category global**, not from the snapshot. Its payload comes from the first secondary-payload location.
8. Issue the second secondary notification using the retained secondary-category snapshot and the payload from the second secondary-payload location.
9. Call F-6ac70711bbb5.
10. Call F-7027ea1c0db7.

The snapshot read precedes the separate category read used by the first secondary notification. No ordering is established among the individual receiver, dispatch-target, category, and payload evaluations within that notification call.

If the query returned zero, skip this entire conditional sequence.

Then, for either query result, issue two selected-object notifications in order. Both use the retained primary category; their payloads are read from two separate zero-path completion-payload locations.

Call F-ac356e5603c7 and proceed to common completion.

### Nonzero path

This path has no explicit cache initialization, preliminary service sequence, or marker gate.

1. Resolve and invoke subordinate slot 0x20.
2. Read and retain the nonzero-path primary category from global storage.

If the query returned nonzero:

1. Call F-29eca01f3b88 with the selected object.
2. Invoke subordinate slot 0x24 with the subordinate receiver and integer 0.
3. Call F-438680ffebfe with the selected-object address plus 0x8C and the address of nonzero-path opaque global data.

5. Read and retain a snapshot of the nonzero-path secondary category.
6. Issue the first secondary notification using a **separate read of that same category global** as its category argument and the first secondary payload.
7. Issue the second secondary notification using the retained secondary-category snapshot and the second secondary payload.

If the query returned zero, skip the conditional sequence.

After the conditional sequence, or immediately after skipping it:

2. Issue two selected-object notifications in order, using the retained primary category and payloads from two separate nonzero-path completion locations.
3. Call F-ac356e5603c7.
4. Proceed to common completion.

The marker write occurs after conditional transition work, unlike the zero-path marker clear.

2. Invoke receiver slot 0x58 using a **separate read of the common category global** and the payload from the first common-payload location.

## Side effects

### Direct writes

The visible direct data writes are:

- A 32-bit cache write at offset 0x94 when the zero path initially observes a zero cache.
- A zero-byte write at offset 0x2C after a nonzero zero-path marker test.
- A one-byte write at offset 0x2C on the nonzero path after any conditional transition work.

The marker writes do not directly overwrite offset 0x2D or the other bytes covered by the 32-bit marker read. Dependencies may independently modify any of these locations.

### Read timing and mutation

The selected-object address is retained, but subordinate references and dispatch targets are resolved at their respective operations. A callback that replaces the pointer at offset 0x88 can affect later subordinate calls. The contract does not freeze the initially queried subordinate object.

The service receiver obtained from F-87be4aa684d1 is retained for its query/action sequence; its dispatch table is not guaranteed to remain unchanged.

Other relevant ordering:

- The zero-path byte at offset 0x2D is read after subordinate slot 0x24 returns.
- The value at offset 0x20 is read after subordinate slot 0x30 returns.
- Each primary category is captured after the subordinate query.
- Each secondary-category snapshot is taken after the first conditional notification.
- The common-category snapshot is taken after F-ac356e5603c7 returns.

A retained category remains the argument source for later calls that use that snapshot, even if callbacks change its original global storage.

By contrast, each first secondary notification and the first common notification reads its category global separately after the corresponding snapshot. The representation does not guarantee equality or inequality between those two reads. It supplies no synchronization model explaining whether an intervening change is possible.

Payloads are read at their respective call sites, not collectively captured at the start of a sequence.

### Ownership, preconditions, and errors

No explicit allocation, release, reference-count operation, rollback, or error-reporting operation is visible. This does not establish that dependencies perform none.

Normal execution requires valid storage for each reached access, readable dispatch tables, valid callable targets, and valid opaque-data addresses. There are no explicit null checks or object-boundary checks.

A nonzero query result selects work; it is not established as an error code. No local recovery is shown for faults, nonreturning calls, or dependency failures. Effects already performed are not visibly rolled back.

Pointer ownership, lifetime extension, and release behavior are unknown. A dependency that invalidates storage still needed by the caller violates the conditions under which the subsequent described accesses can complete normally.

## Acceptance examples

These are conditional expectations, not executed tests. Unless stated otherwise, assume valid memory, normally returning dependencies, and no intervening mutations.

1. **Zero discriminator and zero marker.** With a nonzero cache, initialization is skipped. Preliminary service queries still occur. The marker gate then returns without subordinate or notification calls.

2. **Initialization produces zero.** A zero cache causes initialization and a 32-bit zero writeback. A later invocation that again observes zero attempts initialization again.

3. **Service short-circuit.** A nonzero slot-0x190 result suppresses slot 0x194 and causes one slot-0xEC call. If both queried results are zero, slot 0xEC is skipped.

4. **Zero-path query returns zero.** With a nonzero marker test, the marker byte is cleared before the query. Conditional transition work is skipped, but two selected-object completion notifications and represented common completion remain.

5. **Zero-path query returns nonzero.** Subordinate state setting uses integer 1. The byte-setting call precedes F-9c5c2db853f7. Three conditional notifications precede the two completion notifications, with F-6ac70711bbb5 and F-7027ea1c0db7 between those groups.

6. **Nonzero-path query returns zero.** The initial marker does not gate execution. The function writes marker byte 1, emits two selected-object notifications, and obtains the common receiver.

7. **Nonzero-path query returns nonzero.** F-29eca01f3b88 precedes subordinate slot 0x24 with integer 0. The explicit marker write to 1 occurs only after F-93bd7d506529 returns.

8. **Subordinate replacement.** If a callback replaces the pointer at offset 0x88, a later subordinate operation resolves through the replacement field value rather than a guaranteed original receiver.

9. **Secondary-category read distinction.** On either conditional route, suppose the snapshot read yields one value and the separate first-notification category read yields another. The first secondary notification receives the latter; the second receives the snapshot. If no change occurs, both may receive equal values. This example does not establish that intervening modification is supported or occurs.

10. **Common-category retention.** If the first common notification changes the common-category global, the second and third still use the earlier snapshot. The first notification’s category came from its own separate read.

11. **Equal common payload contents.** If all three common-payload locations contain the same value, the represented sequence still has three ordered dispatches with equal payload arguments. Separate locations do not require distinct values.
