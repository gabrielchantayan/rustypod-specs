# F-5602e6ff7e58

## Purpose

F-5602e6ff7e58 coordinates dependency calls for a caller-supplied object and an indexed table entry. An eight-bit selector determines which of two paths runs:

- A zero selector causes an object-processing call and a two-argument operation. An exact −1 result from that operation triggers an indirect call with one argument.
- A nonzero selector causes repeated processing until a dependency returns zero. A subsequent object-state check determines whether a different indirect call occurs.

The function reads the table-base global **twice**, in order, after obtaining the index. The first value is retained for loop-byte access. The second value is used to calculate the record address for the selector and zero-selector path. The supplied evidence does not establish that these two values are equal.

“Processing,” “selector,” and “dispatch” describe observable roles, not established application semantics.

## Interface

1. **Object address.** An address to storage accessed as 32-bit words. The function passes this address to dependencies and directly accesses:
   - The 32-bit word at byte offset 52 during preparation.
   - The first 32-bit word after the repeated-processing path terminates, interpreting it as a pointer.

2. **Auxiliary value.** An opaque 32-bit value passed unchanged to two dependencies.

No explicit object size, table length, ownership annotation, or error-output location is supplied.

### Output

The function has no explicit return value. Its observable behavior consists of memory reads, ordered dependency calls, conditional indirect calls, and any effects of those callees.

Normal return is not guaranteed: dependency calls may not return, and the repeated-processing path has no visible iteration limit.

## Behavior

### Preparation

The function first invokes F-338d16f9ce72 with no explicit arguments. Any result is unused.

After that call returns, the function reads the object’s 32-bit word at byte offset 52. It passes that word and the auxiliary value to F-ddf4a1f94e38. Any result is unused.

It then invokes F-36a285714182 with the object address and auxiliary value. The returned 32-bit integer supplies the table index.

These calls may mutate the object, globals, or other memory. The offset-52 access therefore occurs against the state left by F-338d16f9ce72, and subsequent table-base reads occur after F-36a285714182 returns. No preservation or ownership guarantee is established for these dependencies.

### Two table-base reads and branch selection

After index acquisition, the function performs two distinct reads of the same table-base global:

1. It reads and retains the base used for loop-byte access.
2. It reads the global again and calculates the selector-record address using this second base plus the index multiplied by 24 bytes.

It then reads the eight-bit selector at offset 17 of the record calculated from the second base.

There is no intervening dependency call between these two global reads. Nevertheless, equality is not an established property of the supplied body. Whether external mutation or the storage’s actual access semantics can make the reads differ remains documented_only. A contract must preserve both reads rather than replace them with one.

The index and stride calculation use the recovered 32-bit integer representation. Negative indices are not rejected, and no range or overflow checks are visible. The evidence does not establish defined wraparound behavior for overflowing arithmetic or valid storage for an out-of-range result.

Neither table-base value is visibly refreshed after later dependency calls:

- Loop-byte access continues to use the first retained base and original index.
- Zero-path pointer access continues to use the record address calculated from the second base.

### Zero-selector path

If the selector is zero, the function invokes F-1333331b2da1 with the object address.

Only after that call returns does it read the pointer at offset 4 of the record calculated from the second table-base read. It then reads the first 32-bit word at the pointed-to address.

That loaded word is retained and passed as the second argument to F-9813035c7ce7; the first argument is the integer 1.

The timing of these reads matters:

- F-1333331b2da1 may change the offset-4 pointer or its target before either is read.
- Changing only the table-base global does not redirect this access to a newly calculated record.
- If F-1333331b2da1 invalidates the retained record or the subsequently followed storage, no recovery is visible.

If F-9813035c7ce7 returns any value other than −1, F-5602e6ff7e58 returns without either indirect dispatch.

If its result is exactly −1, the retained 32-bit word is interpreted as an address. The function reads a 32-bit word four bytes beyond that address and uses it as the sole explicit argument to an indirect target obtained through the failure-dispatch global slot. If the indirect target returns, this function returns.

The failure-argument read occurs after F-9813035c7ce7 returns. It uses the retained address-like word, not a refreshed pointer-chain lookup. Consequently:

- Changes to the earlier pointer-chain storage do not replace the retained address.
- Changes to memory at the retained address plus four can affect the dispatch argument.
- Releasing or invalidating that memory can invalidate the access.

No null check protects this chain. This path does not enter the processing loop or perform the final object-state gate.

### Nonzero-selector path

If the selector is nonzero, the function enters a loop that executes at least once.

Before each call, it reads one byte at the first retained table base plus the original index multiplied by 24 bytes. It passes the object address, this byte, and the integer 1 to F-0ea4820fe774.

A nonzero result causes another iteration. A zero result ends the loop.

The byte is read again on every iteration. Changes to memory at this retained loop-byte address may therefore affect later arguments. Updating the table-base global alone does not redirect the reads.

The selector is not rechecked. Changing the selector at the record derived from the second base does not switch paths after the loop has begun.

The source establishes the eight-bit value supplied from memory, but not its complete machine-level extension or promotion at the call boundary. The zero-versus-nonzero loop condition applies to the dependency’s integer result; −1 continues the loop.

### Post-loop object-state gate

After the first zero result from F-0ea4820fe774, the function reads the object’s first 32-bit word as a pointer.

- If the pointer is null, the function returns without dereferencing it.
- If it is nonnull, the function reads the first 32-bit integer at that address.
- If that integer is zero, the function returns.
- If it is nonzero, the function invokes the separate post-loop indirect target with no explicit arguments.

If that target returns, this function returns.

Both object-state reads occur after the terminating processing call. They can therefore observe changes made during any loop iteration, including the last one.

This is a valid conditional case, not an unconditional layout guarantee.

### Zero selector and ordinary result

- The chain’s loaded 32-bit word becomes the second argument to F-9813035c7ce7.
- Results such as 0, 7, or −2 cause return without indirect dispatch.
