## Behavior

### 1. Capture the initial values

The function reads the eight external source values and places them into successive four-byte regions of the temporary block.

The represented initialization order is source value 0 through source value 7. All eight initializations precede normalization and the dependency call.

These are separate reads, not an established atomic snapshot. If another actor can change the source storage during this sequence, the function itself provides no visible synchronization or consistency check. The behavior of such concurrent changes depends on the surrounding execution environment and memory model.

The supplied material does not reveal the actual values in those external locations. A conforming description therefore cannot replace them with a literal payload, string, or table.

### 2. Normalize every word by an unsigned right shift

The function processes the eight words in descending address order:

- First, the word at offset 28.
- Then offsets 24, 20, 16, 12, 8, and 4.
- Finally, the word at offset 0.

For each word, it reads the current 32-bit unsigned value and writes back that value shifted right by one bit. The shift is logical: the incoming high bit is zero, and the original low bit is discarded.

For each captured unsigned value \(x_i\), the value after this stage is:

\[
y_i = \left\lfloor \frac{x_i}{2} \right\rfloor,
\qquad 0 \leq x_i \leq 2^{32}-1.
\]

Consequently, every shifted word is between zero and \(2^{31}-1\), inclusive.

Exactly eight words are transformed. The represented traversal begins immediately beyond the 32-byte block and moves backward before each access. It does not shift a ninth word beyond the block, and it does not read or write a word before the block as part of the transformation.

That traversal description specifies the accesses shown by the supplied representation; it does not establish that the reconstructed pointer comparisons constitute portable language-level source.

### 3. Narrow the final region’s three-byte portion

After all eight shifts, the function performs an additional operation on the three-byte portion of the final four-byte region.

It retains only that portion’s least significant 16 bits and assigns the result back into the 24-bit portion. This makes the upper eight bits of that 24-bit portion zero. The separately represented adjacent one-byte portion is outside this assignment and is preserved by this operation.

This narrowing is not a second right shift. It also is not a 16-bit replacement of the entire last 32-bit word: the separate adjacent byte is retained.

Under a little-endian interpretation in which the three-byte portion occupies the low 24 bits of the final word, the final word supplied to the dependency is:

\[
z_7 = y_7 \mathbin{\&} \texttt{0xFF00FFFF}.
\]

Under that interpretation, the third byte of the last word—block offset 30—is cleared, while the byte at offset 31 is preserved.

The logical 24-bit-to-16-bit narrowing is directly represented. The little-endian whole-word mask is a conditional interpretation; target byte order is not independently supplied.

### 4. Invoke the dependency

There is no shown validation of the prepared values and no branch selecting whether to call the dependency. The call is not repeated.

The temporary block is addressable when the dependency is invoked. The caller does not explicitly supply a bound or transfer ownership through a separate operation. It also does not visibly allocate or release heap storage.

Because the block is temporary call-local storage, its address must not be treated as durable storage after this invocation ends. Whether the dependency respects that lifetime is unknown.

### 5. Store the returned byte

If F-f20739aca2fe returns normally, the caller captures its eight-bit result.

The represented sequence then reads the external destination base, adds 23 to that address value, and writes the returned byte at the resulting address. The destination base is therefore obtained after the dependency call, not captured during initial block preparation.

This timing is significant: if the dependency changes the external destination base and then returns, the final write uses the subsequently read base value.

There is no shown Boolean conversion, comparison, masking, or success/failure interpretation of the returned byte. All eight result bits are forwarded to the destination.

The function then returns without an explicit result.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

### Zero-valued preparation

If all eight captured source values are zero, the dependency must receive a block whose eight words are zero. The additional narrowing of the last region leaves that block unchanged.

If the dependency returns the byte `0xA5` and the post-call destination base selects valid writable storage, the caller must write `0xA5` exactly 23 bytes beyond that base.

### Unsigned shift behavior

If source value 0 is `0x80000001`, its word at dependency entry must be `0x40000000`.

A value of `0xC0000000` would not satisfy this contract: it would reflect signed high-bit propagation rather than the represented unsigned shift.

### Discarded low bit

If source value 3 is 1, the word at block offset 12 must be zero after normalization. If it is 3, that word must be 1.

There is no rounding upward for odd values.

### Additional final-region narrowing

Assuming the stated little-endian interpretation, if source value 7 is `0xFFFFFFFF`, the ordinary shift first produces `0x7FFFFFFF`. The additional narrowing then produces `0x7F00FFFF`.

The final four bytes presented to the dependency are consequently `FF FF 00 7F` in increasing address order. Clearing the entire upper halfword instead would incorrectly discard the preserved final byte.

Under the same interpretation, a final source value of `0x00020000` shifts to `0x00010000` and then becomes zero because the additional narrowing clears its remaining set bit.

### Destination selected after the call

Suppose the destination-base source contains address A before the dependency call. If the dependency changes that source to address B and returns `0x37`, the caller’s final write must target B plus 23, assuming valid accesses and no intervening change.

A write to A plus 23 based on an earlier cached value would not match the represented sequence.

### No result classification

If the dependency returns `0x00`, the caller writes `0x00`. If it returns `0xFF`, the caller writes `0xFF`. Neither value causes a shown alternative path.

### Dependency does not return

If the dependency does not return normally, this caller does not reach its subsequent destination-base read or result-byte write. No rollback or alternate completion path is established.
