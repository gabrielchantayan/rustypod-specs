# F-d78399cbb975

## Purpose

F-d78399cbb975 performs a state-dependent update on a caller-supplied object. It either records a 32-bit requested value immediately or follows a longer sequence involving resolution, dependent updates, temporary-state construction, optional submission, late recording, and cleanup.

On the longer path, the function may obtain a 16-bit submission argument from an address computed using the object base and a displacement read from global storage. This is a conditional, runtime-selected address—not a fixed object-relative offset whose numeric value is merely unavailable.

These descriptions identify observable structure, not application semantics. The object’s domain, the requested value’s meaning, and the effects of the dependencies are not established.

## Behavior

If the byte is nonzero, the function writes the requested 32-bit value at offset `0x118` and returns. Every nonzero flag value selects this path.

On this path:

- Neither control input affects behavior.
- The supplied byte is not written.
- No dependency is called.
- The global displacement is not read.
- No displacement-dependent two-byte load occurs.
- No temporary state is constructed or cleaned up.

The flag is not explicitly reread later.

### Longer-path entry and resolution

If the flag byte is zero, the function first writes the supplied byte at object offset `0x11C`.

It then calls F-1f46730b1ced with the address of the embedded region at `0xE8` and the requested 32-bit value. The returned 32-bit result is compared with zero.

The byte write has already occurred before this failure transfer. The function has not yet explicitly written the requested value at `0x118`, constructed temporary state, or called cleanup. No rollback is visible.

If resolution returns a nonzero result, the function performs these calls in order:

1. F-d2f99870cc43 receives the resolution result and produces a 32-bit value.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. Unless stated otherwise, memory is valid and reached dependencies return normally.

1. **Immediate path.** With a nonzero flag byte, the requested value is written at `0x118`. No dependency, byte update at `0x11C`, global displacement read, or temporary-state operation occurs.

2. **Zero resolution result.** With a zero flag and zero resolution result, the supplied byte is written before F-a817d8d58c10 is called. Under the represented nonreturning behavior, the late value write and cleanup are not reached.

3. **Mode exactly eight.** Successful resolution and mode `8` still require both initial lookups and construction. They do not require the third lookup, submission, or either displacement-dependent read. Recording precedes cleanup.

4. **Zero primary control.** With mode other than `8` and primary control zero, submission still occurs. Its fourth and fifth arguments are zero. Global displacement storage need not be readable for this function’s direct accesses on that path.

5. **Nonzero secondary control.** With mode other than `8` and nonzero secondary control, the third lookup occurs and submission receives a zero final argument. The primary control is forwarded unchanged; the displacement is not read.

6. **Displacement changed by the third lookup.** Suppose secondary control is zero and primary control is nonzero. If the global displacement initially denotes `0x140`, but the third lookup changes it to `0x160`, the subsequent two-byte read uses object base plus `0x160`, assuming those values are representable and that address is valid. The earlier displacement must not be substituted.

7. **Selected contents changed.** On the same branch, a dependency’s change to the two bytes at the subsequently selected address affects the value supplied to submission. The function does not take an earlier snapshot.

8. **Distinct lookup results.** If the first two lookups return different valid addresses, construction uses the byte from the first and the four-byte value from the second.

9. **Submission does not return.** The late write at `0x118` and cleanup are not reached. Earlier writes and dependency effects are not rolled back.
