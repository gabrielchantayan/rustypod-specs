# F-f993e2a4d44b

## Purpose

F-f993e2a4d44b selects between two arrangements of shared values, writes a corresponding integer into a caller-supplied object, invokes F-56b9f3361bf9, and then clears two byte fields in each of four records.

Selection depends on an unsigned 32-bit input and a separately accessed flag byte:

- With a zero flag, a zero selector chooses the zero arrangement; any nonzero selector chooses the nonzero arrangement.
- With a nonzero flag, only a zero selector chooses the nonzero arrangement. Every other selector chooses the zero arrangement.

The shared-state global pointer is read repeatedly. The representation does **not** establish that all source values and destination fields belong to one stable block. Some destinations use the initially obtained base, another destination uses a separately obtained base, and every source access obtains its own base.

The application meaning of these arrangements and cleared record fields is unknown.

The representation uses integer-based address arithmetic. This contract describes the shown offsets and access widths, not a portable interface across arbitrary address widths.

### Global inputs and retained addresses

The function accesses:

2. A global pointer through which one flag byte is read.
3. A global record-base address, read after the dependency returns.

| Read | Timing | Use of the obtained pointer |

Each source value is retained after its read. The initial destination base and the separately formed destination address are also retained. Later changes to the global pointer do not redirect those retained destinations.

## Behavior

### Selection

The initial shared-state base is obtained before the flag is examined.

If the flag byte is zero, the selector is unchanged. Otherwise, the function computes unsigned 32-bit `1 − selector`, while retaining whether the original selector exceeded one. If it did exceed one, the computed result is replaced with zero.

| Flag | Original selector | Effective selector | Arrangement |
|---|---:|---:|---|
| Zero | `0` | `0` | Zero |
| Zero | Any nonzero value | Original value | Nonzero |
| Nonzero | `0` | `1` | Nonzero |
| Nonzero | `1` | `0` | Zero |
| Nonzero | Greater than `1` | `0` | Zero |

Unsigned subtraction is modulo \(2^{32}\). For original selectors greater than one, any wrapped subtraction result is overridden and does not select the nonzero arrangement. With a zero flag, the subtraction and greater-than-one handling are not performed.

Only the distinction between zero and nonzero matters for the flag byte.

### Destination preparation and source capture

After selection processing, the global shared-state pointer is read again. Its value plus `0x1A` becomes a retained destination address.

The following source accesses then occur in order, with a fresh read of the shared-state global pointer for each access:

1. Read one byte at offset `0x03`.
2. Read four bytes at offset `0x16`.
3. Read four bytes at offset `0x12`.
4. Read one byte at offset `0x02`.

All four source values are captured before the object or arrangement destinations are written. They are ordered snapshots, not an established atomic snapshot of one block.

The four-byte values undergo no visible arithmetic or interpretation. They are transferred through equal-width reads and writes. Endianness is not independently established.

### Zero arrangement

When the effective selector is zero, the direct writes occur in this order:

| Order | Destination | Width | Value |
|---:|---|---:|---|
| 1 | Object address plus `0x5C` | 4 bytes | Integer `2` |
| 2 | Initial shared-state base plus `0x1E` | 4 bytes | Captured source from offset `0x16` |
| 3 | Separately retained offset-`0x1A` destination | 4 bytes | Captured source from offset `0x12` |
| 4 | Initial shared-state base plus `0x00` | 1 byte | Captured source from offset `0x02` |
| 5 | Initial shared-state base plus `0x01` | 1 byte | Captured source from offset `0x03` |

### Nonzero arrangement

When the effective selector is nonzero, the direct writes occur in this order:

| Order | Destination | Width | Value |
|---:|---|---:|---|
| 1 | Object address plus `0x5C` | 4 bytes | Integer `1` |
| 2 | Separately retained offset-`0x1A` destination | 4 bytes | Captured source from offset `0x16` |
| 3 | Initial shared-state base plus `0x1E` | 4 bytes | Captured source from offset `0x12` |
| 4 | Initial shared-state base plus `0x00` | 1 byte | Captured source from offset `0x03` |
| 5 | Initial shared-state base plus `0x01` | 1 byte | Captured source from offset `0x02` |

The destination write order differs between branches. This matters if destinations overlap.

Because source capture is complete first, an arrangement write that overlaps source storage does not change the already captured values. Likewise, overwriting the shared-state global pointer during these writes does not redirect the retained destinations. Overlapping destination writes can overwrite one another according to the listed order.

### Dependency call

After all five arrangement writes, F-56b9f3361bf9 is invoked exactly once, with no explicit arguments in the visible call. No return value is consumed.

The call occurs after the arrangement writes, but this does not guarantee that each written value survives until or beyond the call: aliasing may already have overwritten earlier destinations, and the dependency’s effects are unknown.

If the dependency does not return normally, the subsequent clearing phase is not reached through the visible control flow.

### Record clearing

After the dependency returns, the global record-base address is read and retained. A value saved before the call is not used.

Four records are processed in ascending index order. In each record, the byte at offset `0x11` is written with zero before the byte at offset `0x12`.

The complete sequence of byte-write offsets from the retained record base is:

`0x11`, `0x12`, `0x29`, `0x2A`, `0x41`, `0x42`, `0x59`, `0x5A`.

The record base is not refreshed between records. Previous field contents are not read.

The largest stride displacement is `3 × 0x18 = 0x48`; the final byte offset is `0x48 + 0x12 = 0x5A`. These fixed calculations fit within 32-bit integer ranges. Validity of adding them to an actual address remains a separate requirement.

- Two four-byte and two one-byte arrangement writes, potentially distributed across different shared-state destination bases.
- One invocation of F-56b9f3361bf9.
- Eight one-byte clearing writes if execution reaches that phase.

No direct allocation, release, ownership transfer, logging, or synchronization is visible. There is no evidence that passing the object address transfers ownership.

The dependency may have additional effects, including changing pointers or storage lifetimes; those effects are not established here. In particular, its return does not by itself prove that any previously referenced storage remains live.

No rollback or explicit error handling is present. Invalid accesses or abnormal control flow may leave earlier writes in place; the resulting platform behavior is not specified by the supplied evidence.

The final clearing writes can overwrite arrangement fields or the object field if regions alias. The dependency can also supersede earlier writes. Final arrangement values therefore require explicit preservation and nonoverlap assumptions.
