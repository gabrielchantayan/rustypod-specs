# F-032735daf1f7

Under the 32-bit address-arithmetic model specified below, the reachable prefix has only two possible memory-writing operations:

- An initial 16-bit transfer selected by the second argument.
- A further 16-bit store selected by restrictive relationships among incoming machine state and the address of the fifth argument.

The later pointer load, paired 32-bit stores, and final stores are unreachable under that model. Their presence in the representation does not establish executable behavior.

No ordinary return value, error return, allocation protocol, or ownership-transfer protocol is visible.

## Behavior

### Initial selection and halfword transfer

Define **A** as Q multiplied by 4096, reduced to 32 bits.

The initial transfer is selected exactly when A is zero. Equivalently, Q’s low 20 bits must be zero. Q itself need not be zero.

When A is nonzero, no prefix memory access is selected. Execution proceeds to dispatch with incoming L as the base.

When A is zero, the prefix constructs address-like quantities and performs the following observable memory operations, in order:

1. Read an unsigned 16-bit value at incoming P.
2. Store that value at P + Y.

The destination is a byte displacement, not a displacement measured in halfwords. Between the displayed source read and destination store, the carried source address is updated to P + Y − Z. This update is not a demonstrated write to a caller-owned pointer slot.

If source and destination coincide, the read precedes the write-back. No stronger overlap, atomicity, or concurrency guarantee is established.

The prefix also constructs:

- **H**, equal to incoming L plus the Boolean contribution of Q’s 0x40000 bit plus S shifted right by one.
- Another scaled address equal to Q multiplied by 8192, reduced to 32 bits.

If incoming L is nonzero, the deeper conditional chain is not selected. The initial transfer is followed by dispatch.

### Conditions for the first state-changing block

Deeper processing requires both A = 0 and incoming L = 0.

A = 0 clears Q’s low 20 bits, including its 0x40000 bit. Therefore, on this path, H equals S shifted right by one.

The subsequent XOR-and-shift stages are entered only after a preceding result is zero. Their executed shift counts are consequently zero. They act as equality or zero gates here, not arbitrary variable shifts.

Advancing to the accumulation gates requires all of the following:

- H = 0.
- X = Y.
- The updated source address P + Y − Z equals Z.

The Q-derived scaled addresses are already zero because A = 0.

H = 0 restricts S to either 0 or 1 under the stated 32-bit model. Ordinary argument storage whose address shifted right by one is nonzero cannot pass this gate.

The next accumulation combines T, Q’s low 20 bits scaled by 2048, and a carried condition bit. The latter two contributions are zero on this path. Passing its zero-result gate therefore requires T = 0, with no carry from this addition.

The final gate before the state-changing block requires the low 32 bits of S + 2 × Y to be zero. The displayed carry calculations operate on 32-bit operands; they do not preserve an extra high bit discarded by the multiplication of Y by two.

These constraints yield a stronger conclusion:

- S is either 0 or 1 from the earlier gate.
- A wrapped sum of S and an even value cannot be zero when S = 1.
- Therefore, entry into the block requires S = 0.
- With S = 0, Y must be either 0 or 0x80000000.

Subject to the selected memory accesses completing, the arithmetic conditions for entering this block are thus:

| Quantity | Required relationship |
|---|---|
| Q | Low 20 bits zero |
| Incoming L | Zero |
| S | Zero |
| X | Equal to Y |
| Y | Either 0 or 0x80000000 |
| P and Z | P + Y − Z equals Z, modulo 2³² |
| T | Zero |

These are arithmetic reachability conditions, not evidence that a real calling environment permits argument storage at address zero.

### Effects of the first state-changing block

When selected, this block:

- Assigns the scaled-storage intermediate from 64 × S.
- Forms a working L-related address equal to incoming L + 64 × S.
- Uses unsigned halfword reads at incoming L to determine a destination address and a payload.
- Stores a 16-bit result at that derived destination.
- Advances the A-related address by one halfword, or two bytes.
- Clears the carried condition bit.
- Retains the newly formed L-related address as the working dispatch-related address.

Under stable ordinary memory, if the halfword at incoming L is **V**, the store destination is V zero-extended to a 32-bit address, and the stored value is V + 15 reduced to 16 bits.

The representation references the halfword at incoming L separately for destination construction and payload construction. It does not establish a single sampled value for volatile or concurrently changing memory, nor a guaranteed ordering between those source evaluations. Both destination and payload must be obtained before the dependent store can complete.

On every arithmetically reachable entry to this block, incoming L = 0 and S = 0. Consequently:

- The source halfword address is zero.
- The scaled-storage intermediate is zero.
- The updated L-related address remains zero.
- The advanced A-related address is 2.

A valid mapping at address zero is not established. If the required access fails, subsequent dispatch is not guaranteed.

### Proof that the later conditional operations are unreachable

The next chain can be entered only through the preceding state-changing block.

Even without the stronger parity deduction above, reaching that block gives S ∈ {0, 1}, updated L = 64 × S, and advanced A-related address = 2. Continuing beyond its first post-block gate requires updated L = 0, forcing S = 0.

At that point:

- H = 0.
- Updated L = 0.
- The first post-block XOR result is zero.
- The following XOR result is 2 XOR 0, which is 2.

That result fails the required zero test. The remaining conditional stages are disabled and do not become enabled later.

Therefore, under the same 32-bit model:

- The later shift/subtraction gates do not execute.
- The character-derived pointer load does not execute.
- The paired 32-bit stores do not execute.
- The final signed-halfword load and final stores do not execute.

Oversized-shift semantics cannot affect this reachability result: the relevant shift is downstream of the failed gate.

## Acceptance examples

These are conditional static acceptance criteria. No runtime tests have been performed.

1. **Nonzero scaled selector.** With Q = 1, A = 0x1000. No prefix memory operation is selected. The first computed call target is incoming L + 0x0eb6.

2. **Nonzero Q with zero A.** With Q = 0x00100000, multiplication by 4096 wraps to zero. The initial transfer is selected. Testing Q itself for zero would not match the established selector.

3. **Byte-based destination.** With A = 0, P = 0x1000, and Y = 6, the initial read is at 0x1000 and its store is at 0x1006, not 0x100c.

4. **Nonzero incoming L.** With A = 0 and L nonzero, the transfer occurs, but no deeper prefix memory operation is selected. Dispatch uses incoming L.

5. **Ordinary nonzero storage address.** With A = 0, L = 0, and S shifted right by one nonzero, the deeper chain stops before the state-changing block.

6. **S = 1 does not reach the extra store.** Although S shifted right by one is zero, S + 2 × Y cannot be zero modulo 2³² for any Y. No extra halfword store is selected.

7. **Conditional extra halfword store.** Suppose Q = 0, L = 0, S = 0, X = Y = T = 0, P = 0x2000, and Z = 0x1000. If all selected mappings are valid and the stable halfword at zero is 0x1234, the initial transfer reads and writes 0x2000. The extra store writes 0x1243 at address 0x1234. The subsequent zero chain fails at result 2; no later prefix operations execute.

8. **No paired-store execution.** No incoming values satisfying this contract’s arithmetic model select the later signed-halfword paired-store path. Such a store cannot be accepted as prefix behavior merely because the expression appears in the representation.

9. **Repeated dispatch.** If both calls and the interrupt return normally, the interrupt precedes the base reset. The next first-call target is 0x083d5b78 in the represented state flow.

10. **Access failure.** If the initial source is unreadable, no error return or subsequent dispatch is guaranteed. If the later access at zero fails, the initial transfer may already be observable.
