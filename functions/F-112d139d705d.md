# F-112d139d705d

## Purpose

F-112d139d705d conditionally performs a sequence of indirect calls and memory updates before dispatching through an unresolved indirect target.

The supplied static evidence establishes two principal paths:

- A direct-dispatch path that passes the first two arguments, a local-storage address, and a shifted form of the second argument to the final target.
- A preparation path that invokes additional dependencies, executes a breakpoint operation, updates memory through an address returned by a dependency, and selects further behavior using an implicit context value.

A subsidiary preparation path ends at an invalid-instruction boundary rather than reaching the final dispatch.

The application-level purpose is **documented_only**. The available evidence does not establish whether this routine constructs a message, accesses a device, performs a transfer, or implements another operation. Such interpretations must not become acceptance requirements.

This contract distinguishes the recovered operations from uncertainty about whether the recovered instruction stream accurately represents executable behavior.

## Behavior

### 1. Establish local state and choose a path

The recovered sequence:

1. Computes the fourth argument shifted left by one bit.
2. Establishes an address within local stack storage.
3. Writes a fixed data address into another local slot.
4. Saves the fourth argument into a 32-bit local slot.

Relative to the established local-storage address, the fixed data-address slot is at offset 116 bytes and the saved fourth-argument slot is at offset 48 bytes.

No read of either saved slot is visible in the remaining recovered sequence. Their presence must not be interpreted as proof of an externally consumable record layout.

The preparation path is selected when either:

- The doubled 32-bit value is zero; or
- The sign of that doubled value differs from the incoming overflow-condition value.

Otherwise, execution proceeds directly to final dispatch.

This condition must not be simplified to “the fourth argument is nonpositive.” Its result depends on both the doubled bit pattern and the separately represented condition state. The supplied evidence does not establish the provenance or freshness of that condition state.

### 2. Direct-dispatch path

When preparation is not selected, the final dependency receives:

1. The original first argument.
2. The original second argument.
3. The established local-storage address.
4. The original second argument shifted left by 30 bits at 32-bit width.

The third explicit input is not forwarded.

No initialization of the storage beginning exactly at the supplied third-argument address is shown on this path. A consumer must not assume that this address identifies a fully initialized buffer, a particular record, or storage valid after the routine returns.

### 3. Common preparation sequence

When preparation is selected, the recovered order is:

1. Invoke F-DEP-01.
2. Capture the low byte of the fourth argument.
3. Execute a software breakpoint with selector 119.
4. If execution resumes, invoke F-DEP-02.
5. Treat the low 32 bits of F-DEP-02’s result as an address.
6. Store that address as a 32-bit word at local-storage offset 96.
7. Store the low 16 bits of the doubled fourth argument at offset 20 from the returned address.
8. Select subsequent behavior according to whether the implicit context value is zero.

F-DEP-02 supplies a result represented as 64 bits. Its upper and lower words have distinct subsequent uses; they must not be collapsed into a single pointer-sized value.

No validity check precedes the store through the returned address. Nullness, allocation extent, alignment, writability, and ownership are not established.

The breakpoint is not an ordinary dependency call. Whether it traps, resumes, changes state, or prevents later operations depends on the execution environment.

### 4. Preparation with zero context

If the context value is zero:

1. Interpret the upper 32 bits of F-DEP-02’s result as a signed 32-bit displacement.
2. Write the low byte of that same result at the established local-storage address plus that displacement.
3. Invoke F-DEP-03 with the low-word address from F-DEP-02.
4. Store F-DEP-03’s 32-bit result at local-storage offset 96, replacing the earlier value.
5. Invoke F-DEP-04.
6. Reach the recovered invalid-instruction boundary.

The indexed byte write is not shown to be within the local frame. A negative or large displacement may address unrelated memory or fault.

The static representation ends this path at invalid instruction data. It does not establish a normal return, a final-dispatch call, or a defined recovery action. F-DEP-03 and F-DEP-04 must not be labeled as release or cleanup operations without additional evidence.

### 5. Preparation with nonzero context

If the context value is nonzero, the recovered sequence instead:

1. Writes the captured low byte of the fourth argument at offset 22 from the address returned by F-DEP-02.
2. Writes the low byte of F-DEP-02’s result at local-storage offset 20.
3. Logically shifts the numerical local-storage address right by seven bits and treats the result as another address.
4. Reads a 32-bit word from the address obtained by multiplying the context by 1,024 and adding 24.
5. Writes that word at offset 0 of the shifted-address destination.
6. Writes the doubled fourth argument as a 32-bit word at destination offset 4.
7. Writes the context shifted left by nine bits as a 32-bit word at destination offset 8.
8. Invokes F-DEP-05 with destination offset 12 as its explicit argument.
9. Invokes F-DEP-06 with F-DEP-05’s 32-bit result.
10. Uses F-DEP-06’s 32-bit result as the replacement first argument.
11. Reads one byte from the address obtained by multiplying the context by 4,096 and adding 1.
12. Zero-extends that byte to become the replacement second argument.
13. Replaces the final third argument with the 32-bit address bit pattern representing −70.
14. Proceeds to final dispatch.

The shifted-address destination is derived from the numerical stack address, not merely from an offset within the stack frame. It must not be described as ordinary stack allocation.

The replacement third argument is a fixed address bit pattern, not the address returned by F-DEP-02 and not the address passed to F-DEP-05. Its validity is unknown.

The context-derived byte read occurs after both F-DEP-05 and F-DEP-06. Consequently, the read can observe memory effects of those dependencies. No assumption that dependencies preserve globals or referenced memory is permitted.

### 6. Final dispatch

F-DEP-07 is invoked with four arguments:

- The current unsigned second-argument value.
- The current third-argument address.
- The current second-argument value shifted left by 30 bits, truncated to 32 bits.

The final argument therefore depends only on the lowest two bits of the current second argument.

F-DEP-07’s identity, signature beyond the visible arguments, return behavior, and interpretation of these values are unresolved. The recovered representation treats the indirect transfer as a call followed by return; that classification is not independently verified.

## Acceptance examples

These examples are conditional static expectations, not executed tests.

1. **Direct dispatch with a nonzero doubled value.**  
   If the fourth argument is 1 and the incoming overflow condition is clear, the doubled value is 2 and preparation is not selected. With second argument 3, F-DEP-07 receives fourth argument `0xC0000000`, while its first two arguments remain the original first argument and 3.

2. **Zero after width truncation.**  
   If the fourth argument has bit pattern `0x80000000`, its doubled 32-bit value is zero. Preparation is selected regardless of the incoming overflow condition. This example prevents replacing the branch with an unbounded mathematical comparison.

3. **Condition-state sensitivity.**  
   With fourth argument 1, setting the incoming overflow condition selects preparation even though the doubled value is positive and nonzero.

4. **Zero-context narrow write and displacement.**  
   Assume preparation is selected, breakpoint handling resumes, and F-DEP-02 returns a valid low-word address with upper word `0xFFFFFFFF`. The indexed byte write targets one byte before the established local-storage address. It does not use an unsigned forward offset of 4,294,967,295 bytes as a bounds-checked buffer index.

5. **Nonzero-context dispatch values.**  
   Assume all accesses succeed, dependencies return, and the late context-derived byte read yields `0xFE`. F-DEP-07 receives second argument 254, fourth argument `0x80000000`, third argument `0xFFFFFFBA`, and first argument equal to F-DEP-06’s result.

6. **Breakpoint does not resume.**  
   If breakpoint handling terminates or suspends execution without resuming, no subsequent dependency call or returned-address write is required to occur.

7. **Returned-address access fails.**  
   If the 16-bit store at returned-address offset 20 faults, later preparation operations are not established. The routine has no visible error return or rollback for this case.
