## Behavior

### Search order and stopping conditions

The initial candidate is obtained from the descriptor’s offset-4 field. That field is not reread during the search.

Before a candidate is submitted to the dependency, the function reads the descriptor’s offset-8 field and compares it with the current candidate. Equality causes immediate exhaustion. Consequently, a candidate equal to the observed end value is not submitted for acceptance.

For each candidate that does not equal the observed end:

- F-768eb5ddd234 receives the current candidate and the auxiliary input.
- A zero dependency result means that the candidate is rejected.
- Any nonzero dependency result means that the candidate is accepted.

Rejected candidates are followed by a candidate eight units higher in the recovered integer representation. Accepted candidates stop the search immediately. The function stores the accepted candidate through the result reference and returns 1.

The dependency result is interpreted only as zero versus nonzero. Its sign and magnitude do not otherwise affect the result. A negative result, where the recovered return type supports that interpretation, is accepted just as a positive nonzero result is.

### Observable access order

The direct access order matters when the descriptor or result storage aliases memory accessible to the dependency:

1. The initial-candidate field is read before the first end-field read.
2. The end field is read before every dependency invocation.
3. A rejected candidate is advanced before the next end-field read.
4. An accepted candidate is written to the result destination after the accepting invocation returns.
5. There is no further end-field read after acceptance and before the successful return.

There is no preliminary read of the result destination and no result initialization on entry.

The current candidate is retained as the function’s search state. If the dependency changes the descriptor’s initial-candidate field, that change does not restart or redirect the current search. If it changes the end field, a later boundary comparison uses the changed value.

An end-field change during an accepting dependency invocation does not cause an additional end check. Once that invocation returns nonzero, the function stores the candidate and reports success.
