# F-2b18ba4e9228

## Purpose

F-2b18ba4e9228 performs an ordered, data-dependent sequence of memory reads and writes, followed by an unresolved indirect invocation.

The supplied static representation does not establish an application-level purpose. It does not support identifying this routine as a parser, allocator, initializer, text processor, or conventional container operation. Printable values among the stored constants do not establish text semantics.

Its established behavior is a low-level memory transformation whose execution depends on explicit arguments, incoming machine state, external storage, and the evolving contents of linked memory. Capture timing is significant: an external word read before an intervening store remains a captured value even if that store subsequently changes its source.

Successful completion and return are conditional on all executed accesses succeeding and the indirect dependency returning. No validation, recoverable error result, or rollback is represented.

## Behavior

### Entry ordering and external-root capture

The first effect is a byte store to absolute address `0x6e`, containing the low byte of one incoming address-like value.

The routine next reads a word at the third argument plus `0x04`. At the resulting address plus `0x54`, it stores the other incoming address-like value. Only afterward does it read the unsigned byte at the third argument plus `0x05`. The intervening word store can therefore change that byte through aliasing.

The subsequent early accesses have this order:

1. Store word `0x65` at the first incoming base plus `0x54`.
2. Store word `0x65` at the captured unsigned byte plus `0x65`.
3. Read a word from the first incoming base plus `0x74`.
4. Store that captured word at the other incoming base plus `0x54`.
5. Store the fourth argument’s low byte at the captured unsigned byte plus `0x11`.
6. Capture the external root word from storage at `0x087fc514`.
7. Store the complete second argument at the other incoming base plus `0x34`.
8. Store the complete fourth argument at the first incoming base plus `0x54`.

The external root is thus captured **before** the final two stores, not after them. Either store may alias the root’s source storage. Subsequent root-based traversal nevertheless uses the root already captured.

Capturing the root does not capture its pointee contents. The first unsigned-byte read at captured-root offset `0x05`, the word copy from offset `0x50` to offset `0x20`, and subsequent link reads occur after those two argument stores. They can observe their effects if their destinations alias the captured root’s reachable storage.

### Initial linked traversal

From the captured root, the routine follows word-sized links, including root offsets `0x00` and `0x74`, and a further offset `0x64`. It copies words, writes low address bytes, and reads unsigned bytes that become small numeric address bases.

The root byte at offset `0x05` is read once for a retained arithmetic value and read again for a later byte copy to offset `0x11`. These are separate accesses. They must not be merged merely because their nominal source address is identical.

The word captured early from the incoming base at offset `0x74`, reduced by `0x70`, becomes another address-like value. It is stored into linked storage and used in subsequent address construction. This is not evidence that the resulting address denotes callable code.

An external-root-derived byte also controls a halfword store at byte-plus-`0x45`. Later, the fourth argument’s low byte is stored at that same starting address. The later byte replaces only the addressed byte; the other byte of the earlier halfword remains unless another aliasing write changes it.

A linked word captured at offset `0x60` supplies byte and halfword data across subsequent operations. Its captured value is not refreshed merely because related storage changes.

### Arithmetic and partial overwrites

Address calculations combine retained words, incoming state, comparison results, and explicit carry predicates. Boolean comparison contributions are numerically zero or one.

The carry stage doubles the retained `0x087fc710` value and adds the unsigned comparison of the incoming arithmetic operand against an earlier derived word. Its carry combines:

- Carry from doubling the retained word.
- Carry from adding the comparison contribution to the doubled result.

A later calculation incorporates carry from adding `0x59` and that carry contribution to the external operand from `0x087fc6e4`. These are unsigned 32-bit carry conditions, not signed-overflow tests.

One captured word is interpreted as signed and shifted right by its own low byte. Later, a character read from a doubled address is shifted right using an address value’s low byte as the count. Counts can exceed thirty-one. No portable count masking, saturation, or oversized-shift result is established.

Partial-write ordering is consequential. A computed location is read as a word and later receives narrower stores; the earlier word remains captured. Elsewhere, a halfword is stored before a later word read from the same computed location supplies another destination. That later word read includes the effects of preceding writes, subject to byte order and aliasing.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

- **Entry fault ordering:** If the first byte store at `0x6e` faults, the subsequent read through the third argument is not required to occur.
- **Early aliasing:** If the first pointer-derived word store changes the byte at third-argument offset `0x05`, the later unsigned-byte read uses the changed contents.
- **Root capture:** If either early argument word store changes storage at `0x087fc514`, later traversal still starts from the previously captured root. Its pointee reads may nevertheless observe those stores.
- **Delayed external reads:** If the halfword store associated with `0x087fc710` overlaps `0x087fc6f8`, the later captured word includes that modification. The same condition applies independently to `0x087fc6e8`.
- **Retained low-address word:** If a linked mutation changes absolute `0xdb` after its capture, the later full-word and low-byte consumers still use the captured value.
- **Truncation:** A fourth argument with low byte `0xab` supplies `0xab` to its byte stores while its word store retains all thirty-two bits.
- **Overlap width:** A byte store following a halfword store at the same starting address replaces one byte, not both. The resulting halfword’s numeric value depends on endianness.
- **Final character conversion:** A final character value of positive one produces first call argument `0x45`. For stored pattern `0x80`, zero-extension would produce `0x000000c4`, while signed-eight-bit interpretation followed by unsigned conversion would produce `0xffffffc4`; the evidence does not select between them.
- **Final capture:** A final store that aliases the linked offset-`0x44` source does not replace the already captured third call argument.
- **Nonreturning target:** If D-indirect does not return, no return from this routine is required.
