# F-14a43eb4f6d0

## Purpose

F-14a43eb4f6d0 conditionally performs a table-initialized, fixed-width numerical calculation comprising 32 iterative updates, then supplies two derived words to an opaque dependency. It returns no explicit value.

Established behavior includes a signed input gate, a descending search of nine records, optional initialization using signed 64-bit products and three dependency calls, sign-directed iteration, and a final four-call sequence.

The input-field extraction resembles interpretation of a positive IEEE 754 binary32 encoding. The numerical updates resemble a fixed-point approximation algorithm. These are inferred intentions, not mathematical guarantees. The supplied representation does not establish a named mathematical function, accuracy bound, rounding policy, or externally observable result destination.

**Explicit input:** One 32-bit word, interpreted both as:

- A signed 32-bit integer for the entry gate.
- An unsigned bit pattern for field extraction.

There is no explicit pointer, length, context, or output-buffer argument.

**Return:** No explicit value. The final dependency’s return value is ignored.

The address-base globals are distinct inputs from the contents of the tables they locate. Their reads occur at the points described below; neither table address is established as a function-wide snapshot.

**Execution preconditions:**

## Behavior

### Entry gate and initial state

The calculation proceeds only if the input, interpreted as signed 32-bit, is strictly greater than `0x39800000`.

Otherwise, the function returns without reading either address-base global, reading either numerical table, or calling a dependency.

Thus:

- `0x39800000` is rejected.
- Every word with its most significant bit set is rejected.
- Words from `0x39800001` through `0x7fffffff` are admitted.
- Infinity and NaN encodings receive no separate classification.

For an admitted word, define the extracted exponent \(E\) as bits 23–30 minus 127. Its admitted-path range is −12 through 128.

The initial vertical component is formed by taking the low 23 bits, forcing bit 23 to one, and shifting left by six. It lies between `0x20000000` and `0x3fffffc0`, inclusive.

The remaining initial state is:

| Quantity | Initial value |
|---|---:|
| Horizontal component | `0x20000000` |
| Accumulated quantity | 0 |
| Working exponent adjustment | 0 |
| Scale selector | 0 |
| Starting coefficient index | 0 |

These defaults survive if no record qualifies.

Under a binary32 interpretation, the gate threshold represents \(2^{-12}\). This interpretation does not replace the signed-word comparison.

### Descending record search

Candidate indices are examined in order 8, 7, …, 0. The first qualifying candidate is selected.

For each candidate, the function reads the record-address-base global and computes that candidate’s address using a fixed displacement and a 32-byte index stride. The base is therefore read anew for each candidate address calculation, rather than captured once before the search.

Each record has this layout:

| Byte offset | Width | Use |
|---|---:|---|
| 0 | 32 bits | Signed threshold |
| 4 | 32 bits | Signed comparison exponent |
| 8 | 32 bits | Signed first multiplication coefficient |
| 12 | 32 bits | Signed second multiplication coefficient |
| 16 | 32 bits | Signed exponent adjustment |
| 20 | 32 bits | Initial accumulated quantity |
| 24 | 32 bits | Scale word |
| 28 | 32 bits | Signed starting coefficient index |

The comparison exponent is read first. A comparison exponent below \(E\) rejects the candidate without reading its threshold.

Otherwise, the threshold is read. The function subtracts an arithmetic-right-shifted version of the initial vertical component from that threshold. The shift request is the low eight bits of the comparison-exponent difference.

The candidate qualifies only when this subtraction produces a strictly positive signed 32-bit result. A zero result rejects it. The threshold test must not be replaced by an unbounded-integer comparison when overflow can affect the represented subtraction.

Rejected records do not modify numerical state and do not cause dependency calls. The search stops immediately after a selection; lower-numbered candidates are not examined.

### Selected-record initialization

The selected candidate’s computed address is retained as a record pointer. Subsequent initialization calls do not cause that pointer to be recomputed from the record-address-base global.

The function reads the first coefficient, prepares signed 64-bit products, and reads the record’s exponent adjustment before the first initialization call. The second coefficient is read once for its product with \(2^{29}\) and again for its product with the vertical component. These are separate accesses; the record is not copied into an atomic snapshot.

For the formulas below, let:

- \(A\) denote the retained first coefficient.
- \(B\) denote the second coefficient, assuming its two reads agree.
- \(V\) denote the initial vertical component.
- \(H_0\) denote the record’s exponent adjustment.
- \(H\) denote the working exponent adjustment after its update.

The normal-return sequence is:

1. Prepare the signed 64-bit products \(B \times 2^{29}\), \(V \times A\), and \(V \times B\).
2. Call F-703fd5651586 with the low and high 32-bit words of \(V \times B\), followed by \(H_0-E\).
3. Add \(A \times 2^{29}\) to that returned 64-bit result, retaining the sum for the horizontal component.
4. Set \(H\) to the signed minimum of \(H_0\) and \(-E\).
5. Call F-703fd5651586 with the low and high words of the previously prepared \(V \times A\), followed by **\(-(E+H)\)**.
6. Call F-703fd5651586 with the low and high words of the previously prepared \(B \times 2^{29}\). No explicit third argument is present for this invocation in the supplied representation.
7. Add the second and third returned 64-bit results, retaining the sum for the vertical component.
8. Convert the retained horizontal and vertical sums into their respective 32-bit component words.
9. Read the accumulated quantity, scale word, and starting index from offsets 20, 24, and 28 of the retained selected-record pointer, in that order.

The third argument in step 5 negates the entire sum: \(-(E+H)\), not \((-E)+H\).

Each component conversion combines the low word shifted logically right by 29 with the high word multiplied by eight. Where the represented fixed-width operations are defined, this retains bits 29–60 of the 64-bit value. There is no explicit rounding increment or saturation.

The scale selector becomes the scale word minus one, retaining the 32-bit unsigned result.

The last three record reads occur after all three initialization dependency calls. A dependency that modifies the selected record’s storage can therefore affect them. A dependency that changes only the record-address-base global does **not** redirect these reads: they use the retained selected-record pointer. Earlier coefficient values, prepared products, and the exponent adjustment are not reread from that global.

### Shift-schedule initialization

Let \(K\) be the starting coefficient index, \(H\) the working exponent adjustment, and \(S\) the scale selector. Define:

\[
J=K-[K>3]-[K>13],
\]

where the bracketed comparisons use signed \(K\).

Three 32-bit shift counters are initialized:

| Operand shifted | Initial counter |
|---|---|
| Vertical component | \(J+H+1\) |
| Horizontal component | \(J-H+1\) |
| Table coefficient | \(J-S+1\) |

Actual shift requests use only the low eight bits of their respective counters. This is not evidence for reducing requests modulo 32.

If no record was selected, \(K\), \(H\), and \(S\) remain zero, so all three counters begin at one.

### Thirty-two numerical rounds

The function executes exactly 32 rounds if all accesses, arithmetic, and dependency calls complete normally.

For each round:

1. Obtain arithmetic-right-shifted versions of the old vertical and horizontal components using their respective counters.
2. Read the coefficient-address-base global again.
3. Compute the current coefficient address using a fixed displacement and four-byte index stride.
4. Read one signed 32-bit coefficient and arithmetic-right-shift it using the coefficient counter.
5. Update the components and accumulated quantity according to the sign of the old vertical component.

The coefficient-address base is not retained for all 32 rounds. A changed base can affect a later round’s coefficient address.

When the old vertical component is nonnegative:

- Subtract the shifted old vertical component from the horizontal component.
- Subtract the shifted old horizontal component from the vertical component.
- Add the shifted coefficient to the accumulated quantity.

When the old vertical component is negative:

- Add the shifted old vertical component to the horizontal component.
- Add the shifted old horizontal component to the vertical component.
- Subtract the shifted coefficient from the accumulated quantity.

Both component updates use the old state. The vertical update does not use the newly computed horizontal component.

After the numerical update:

- Each shift counter increases by one unless the current coefficient index is exactly 3 or 13.
- The coefficient index increases by one.
- The completed-round count increases by one.

Indices 3 and 13 suppress only the counter increments. They do not suppress the coefficient read or numerical update.

There is no convergence test, saturation, reported overflow, or data-dependent early exit. Component words retain 32-bit results, subject to the unresolved arithmetic semantics described below.

### Final dependency sequence

After round 32, the function:

1. Calls F-1c7710595b35 with the represented 32-bit result of shifting one left by the low eight bits of \(S\).
2. Calls F-f2b8ff34d9f0 with that returned word and the integer 30.
3. Calls F-1c7710595b35 with the final accumulated quantity.
4. Calls F-450415463608 with the result of step 3 as its first argument and the saved result of step 2 as its second argument.
5. Returns without exposing the final call’s return value.

The first conversion result feeds step 2. It is **the result of step 2**, not the first conversion result, that is retained across step 3 and supplied as the final call’s second argument.

This retention establishes argument flow only; it does not establish preservation of unrelated globals by any dependency.

## Acceptance examples

These are conditional static criteria, not reported executions.

1. **Gate equality:** Input `0x39800000` returns without either address-base read, any numerical-table read, or any dependency call.

2. **Signed rejection:** Inputs `0x80000000` and `0xffffffff` are rejected regardless of any floating-point interpretation.

3. **Smallest admitted input:** Input `0x39800001` begins with exponent −12 and vertical component `0x20000040`.

4. **Infinity encoding:** Input `0x7f800000` is admitted, producing exponent 128 and initial vertical component `0x20000000`. There is no infinity-specific exit.

5. **Search priority:** With unchanged table state, if records 8 and 5 qualify, record 8 is selected and record 5 is not examined.

6. **Threshold equality:** A candidate whose threshold equals the shifted vertical component is rejected.

7. **Adjustment parentheses:** If selected-record processing yields \(E=5\) and \(H=-7\), the second initialization call’s third argument is \(-(5+(-7))=2\), not \((-5)+(-7)=-12\).

8. **Retained record pointer:** If an initialization dependency changes only the record-address-base global, subsequent accumulated-quantity, scale, and starting-index reads still use the previously selected record’s address. If that dependency instead changes those fields at the retained address, the later reads can observe the changes.

9. **Per-round coefficient base:** If an externally visible base change occurs between rounds, a later round computes its coefficient address from the newly read coefficient-address base, subject to the environment’s memory semantics.

10. **No selected record:** If all candidates fail, initialization calls are omitted, but 32 numerical rounds still begin at coefficient index zero with all three shift counters equal to one. The final four-call sequence follows.

11. **Old-state update:** A nonnegative-vertical round uses the shifted old horizontal component for the vertical subtraction, not the horizontal result of that round.

12. **Exceptional schedule indices:** At index 3 or 13, the numerical update occurs. The next round uses the next coefficient index but unchanged shift counters.

13. **Final argument retention:** If the first conversion, the following two-argument dependency, and the second conversion return distinct words, the final call receives the second conversion’s word first and the two-argument dependency’s word second. Its return value is discarded.
