# F-2f9997151410

## Purpose

F-2f9997151410 replaces a 32-bit field in a caller-supplied memory region and returns that field’s previous value. If the replacement differs from the previous value, it first clears a separate 32-bit field in the same region.

The established behavior is a conditional clearing operation followed by an unconditional replacement. A possible intent is to invalidate auxiliary state when a selected value changes. That interpretation is inferred; the supplied evidence does not establish the meanings of either field.

## Behavior

### Established access sequence

The operation has the following source-level order:

1. Read the 32-bit value field at byte offset 16.
2. Compare that captured value with the replacement value.
3. If they differ, write a four-byte zero value to the auxiliary field at byte offset 8.
4. Write the replacement value to the value field at byte offset 16, regardless of whether it differs from the captured value.
5. Return the captured value.

The comparison is equality-based. There is no ordering comparison, range check, increment, truncation step, or arithmetic transformation of the replacement value.

### Unequal-value case

When the captured value and replacement differ, the auxiliary-field clearing precedes the value-field replacement in the supplied operation order.

On normal completion, absent external modification:

- The auxiliary field contains zero.
- The value field contains the replacement.
- The return value is the original value field content.

The auxiliary field is not read before being cleared. Its previous contents do not affect the decision or the returned value.

### Equal-value case

When the captured value equals the replacement:

- The auxiliary field is not accessed.
- The value field is still written.
- The captured value is returned.

Thus, equality suppresses only the auxiliary-field write. It does not make the function read-only and does not eliminate the value-field assignment.
