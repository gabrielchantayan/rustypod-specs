# F-5f79b0b8cb08

## Purpose

F-5f79b0b8cb08 selects a 32-bit result using two ordered comparisons and, if neither comparison reports zero, an object-associated fallback value.

The selection has three levels of precedence:

1. A comparison involving a value obtained without using the input.
2. A comparison involving a value obtained from the input address plus 40 bytes.
3. A value read at the input address plus 44 bytes, with a shared replacement value selected when a separate read of that location is zero.

The established behavior is selection by comparison results, not any particular business meaning. Interpreting the comparisons as string comparisons, the results as names, or the input as a particular object type would require additional evidence.

This contract describes static evidence only. No runtime tests have been performed.

## Behavior

### First-priority selection

F-5f79b0b8cb08 first calls F-3ad65987df9a without arguments and retains its 32-bit result.

It then calls a comparison dependency with:

- That returned value as the first argument.
- The first comparison reference as the second argument.

A comparison result of exactly zero selects the first-priority result. The function obtains that result from its shared-data location and returns it immediately.

On this path:

- F-44362605ab79 is not called.
- The second comparison is not performed.
- The field at offset 44 is not directly read by this function.

The first-priority result is obtained after the comparison returns. The evidence does not establish that either dependency preserves shared state, so the returned word must not be described as necessarily equal to its value at function entry.

A negative or positive nonzero comparison result advances to the second selection stage. No distinction between different nonzero values is shown.

### Second-priority selection

If the first comparison is nonzero, the function forms an address 40 bytes beyond the supplied base and passes it as the sole argument to F-44362605ab79.

The 32-bit value returned by that dependency becomes the first argument of a second call to the comparison dependency. The second comparison reference supplies the second argument.

If this comparison returns exactly zero, the function obtains the second-priority result from shared storage and returns it immediately.

On this path, the field at offset 44 is not directly read by this function. F-44362605ab79 and the comparison dependency may nevertheless access or modify that field; their implementations are unavailable.

As with the first-priority result, the second-priority result is obtained after the corresponding comparison. Its entry-time value is not guaranteed to be preserved.

### Field and fallback selection

If both comparisons return nonzero, the supplied representation shows two reads of the 32-bit field at offset 44:

1. An initial read supplies a candidate return value.
2. A second read determines whether the field is zero.

If the second read is zero, the function replaces the candidate with the shared fallback word and returns that fallback.

If the second read is nonzero, the function returns the value from the initial read.

For stable ordinary memory, this reduces to returning the field value when nonzero and otherwise returning the shared fallback. That simplification does not capture the supplied representation when the two reads observe different values.

The distinction matters conditionally:

- An initial value of zero followed by a nonzero zero-testing read selects the initial zero.
- An initial nonzero value followed by a zero zero-testing read selects the shared fallback.

These are consequences of the displayed two-read representation, not evidence that concurrent mutation is supported or that the executable necessarily performs two physical loads. Machine-level access behavior and memory-model guarantees remain unknown.
