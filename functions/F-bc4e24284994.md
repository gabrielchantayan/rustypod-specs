# F-bc4e24284994

## Purpose

F-bc4e24284994 transforms the first 32-bit word at successive eight-byte record positions. At each visited position, it supplies that word and two unchanged 32-bit inputs to F-280a6058ff6e, then stores the dependency’s 32-bit result back at the same position.

The traversal begins at an address read from a caller-supplied descriptor. Before each iteration, the function reads the descriptor’s stopping address and compares it with the current position. Termination is based on equality, not on ordering or a record count.

The second 32-bit word of each record is not directly accessed by this function. Its preservation is conditional on dependency effects and storage aliasing.

This contract describes established static behavior, conditional consequences, and unresolved behavior separately. No runtime tests have been performed.

## Behavior

### Initialization and comparison

The function reads the descriptor’s initial-address field once and establishes its current record position from that value.

Before reading a record, it reads the stopping-address field and compares the interpreted address with the current position:

- Equality ends the function without processing that position.
- Inequality admits another iteration.

There is no less-than or greater-than test. Advancing past an endpoint does not itself cause termination.

The stopping-address field is read again for each comparison, including the comparison that ends an ordinary traversal. The initial-address field is not reread to reset or redirect the current position.

These are source-level access relationships. They do not establish volatile access, hardware transaction widths, or a concurrent-memory protocol.

### Processing an admitted record

For each position admitted by the comparison, the established order is:

1. Read the 32-bit first word at the current position.
2. Invoke F-280a6058ff6e with the first forwarded value, the second forwarded value, and the just-read word, in that argument order.
3. After normal dependency return, store the dependency’s 32-bit result at the current position.
4. Advance the current position by eight bytes.
5. Perform the next stopping-address comparison.

The result store is not deferred until the end of the traversal. The function does not snapshot later records before processing begins.

The two forwarded inputs are reused without a caller-side transformation. No external storage is reread to obtain replacements for those inputs.

### Fixed-range consequence

If the endpoint remains fixed and equals the initial address plus eight times a nonnegative record count, the function processes exactly that many positions, provided all accesses and advances are valid and every dependency call returns normally.

The endpoint is exclusive: the position equal to it is compared but not processed.

“Endpoint remains fixed” includes both dependency effects and this function’s own result stores. A dependency that leaves the descriptor untouched is not sufficient if a result store aliases the stopping-address field.

The function issues its stores in traversal order. This does not imply that earlier results survive later dependency calls or remain observable after storage is invalidated.

### Mutable endpoint and overlapping storage

The stopping-address field is live traversal state. A change made before the next comparison can change whether another record is processed.

The source establishes no separation between descriptor storage and record storage. A result store can therefore modify a descriptor field if their addresses overlap:

- A store to the initial-address field does not reset the already-established current position.
- A store to the stopping-address field determines the endpoint value available to the next comparison, subject to any further effects.

The post-call result store occurs after any endpoint change made during that dependency invocation. If the current record’s first word is also the stopping-address field, the returned result replaces the dependency’s endpoint update.

Consequently, termination at the next comparison depends on the endpoint value **after the result store**, not merely on the value present when the dependency returns. With no further intervening change, that post-store endpoint must equal the next record position.

The same ordering applies to changes to record contents. If the dependency writes the current first word during its call, the caller’s subsequent result store replaces that intermediate value, provided the storage remains valid and writable. If the dependency changes a future record, that record is later read in its then-current state.

### Widths and arithmetic

The forwarded inputs, descriptor fields, record values, and dependency result are represented as 32-bit quantities.

The cursor advances by two 32-bit words, giving an eight-byte stride. No explicit integer record counter, length multiplication, or overflow check is present.

The descriptor fields are interpreted as addresses, but the supplied representation does not independently establish the complete pointer ABI. It does not justify arbitrary 64-bit addresses, a particular pointer-truncation rule, or wraparound traversal.

For a fixed endpoint, an address difference that is not a nonnegative multiple of eight does not describe an ordinary bounded traversal. The function has no overshoot check or fallback error return. Behavior after invalid pointer arithmetic or an invalid memory access remains unspecified by the supplied evidence.
