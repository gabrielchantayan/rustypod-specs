# F-4a2648cc89e4

## Purpose

F-4a2648cc89e4 performs an ordered sequence of indirect calls, 32-bit memory writes, and byte reads and writes, followed by an unconditional repeating call-and-write sequence.

A higher-level purpose is not established. The supplied representation does not justify identifying this operation as initialization, serialization, device control, allocation, or any particular application protocol.

The visible control flow has no normal return. If all calls return and all memory accesses succeed, execution reaches a loop with no exit condition. This is a statement about the supplied representation, not proof that the recovered control flow matches the original executable.

This contract uses \(W(x)\) to mean the low 32 bits of \(x\) when describing a **conditional 32-bit machine-arithmetic interpretation**. That interpretation is useful for specifying bit patterns, but is not an assertion that overflowing signed expressions have a valid language-level meaning.

Byte order, access alignment requirements, memory mapping, and fault handling are unknown.

## Behavior

### Dependency notation

The dependency labels below are opaque, document-local identifiers for **call sites**, not verified identities of distinct functions.

For compactness, each numbered family identifies five consecutive call sites:

- Family 01 means F-U0101 through F-U0105.
- Family 02 means F-U0201 through F-U0205.
- The same convention applies through Family 14.

Unless otherwise stated, a five-call family supplies the stated arguments to its first call, shows no explicit arguments for the next four calls, and obtains the described result from its fifth call. Calls with no displayed arguments must not be interpreted as receiving cleared argument registers or having a verified zero-argument ABI.

All ordering below is conditional on preceding calls returning normally and preceding accesses completing.

### 1. Entry write and initial result construction

Before any displayed call, the function writes the incoming 32-bit payload at the incoming base address plus 20 bytes.

Family 01 then executes. Its first call receives the first explicit argument. After its fifth call, an auxiliary machine-register result is used to form:

- A stored value equal to that result multiplied by \(2^{24}\).
- A destination address equal to that result multiplied by \(2^{26}\), plus 20 bytes.

A 32-bit store writes the former to the latter.

Call this stored value \(S\). Overflow and address interpretation remain subject to the arithmetic qualification above.

### 2. Initial indexed stores

Family 02 receives \(S\) and produces a result \(A\). The function writes \(S\) as a 32-bit value at address \(4A+20\).

Family 03 receives \(4A\) and produces \(B\). It forms \(T=4B\), then writes \(T\) as a 32-bit value at address \(16B+20\).

A four-call bridge follows, in this order:

1. F-U1501 receives \(T\).
2. F-U1502 produces a 32-bit result.
3. F-U1503 receives that result.
4. F-U1504 produces another 32-bit result.

Family 04 receives the final bridge result and produces \(C\). The function writes \(T\) at address \(4C+20\).

Family 05 receives \(4C\) and produces \(D\). It forms the unsigned 32-bit value \(U=4D\), then writes \(U\) at address \(16D+20\).

A second four-call bridge follows:

1. F-U1601 receives \(U\).
2. F-U1602 produces a result.
3. F-U1603 receives that result.
4. F-U1604 produces another result.

No equivalence between these bridge call sites and the earlier bridge is established.

### 3. Third-argument-derived store and replacement store

Family 06 receives the second bridge’s final result and produces \(E\).

The function writes the unsigned value obtained by shifting the third argument right by eight bits at address \(4E+20\). This is a 32-bit store, not a byte store.

Family 07 receives \(4E\) and produces \(F\). At address \(16F+20\), the function writes \(4F\).

It also derives:

\[
Q = (U \mathbin{\&} \text{0x7FFFFFFF}) \gg 7
\]

Family 08 receives three explicit values: \(16F\), \(16F\), and the third argument shifted right by seven bits. It produces \(G\).

After those five calls, the function writes \(16F\) at address \(16F+20\). Thus, the same displayed address previously receiving \(4F\) now receives \(16F\), with five intervening calls that may themselves affect memory.

### 4. First byte-addressed updates

Family 09 receives \(4G\) and produces an unsigned result \(H\).

The following access sequence then occurs:

1. Read one unsigned byte from address \(Q+1\).
2. Add 17 to that byte’s numeric value.
3. Write the low byte of \(4H\) at the resulting address.

The destination is therefore between address 17 and address 272 inclusive. It is not a pointer loaded from a pointer-sized field: only one byte is read to obtain the destination’s base value.

F-U1701 receives three copies of \(4H\). F-U1702 then produces a result.

Family 10 receives that result and produces \(I\). One of this family’s call targets is expressed through an embedded code-address reference rather than solely through a numeric address expression; its functional identity remains unresolved.

The function again reads the byte at \(Q+1\), independently of its earlier read. It writes the low byte of

\[
(H \mathbin{\&} \text{0x3FFFFFFF}) \gg 20
\]

at the newly selected byte destination.

The two destination selections need not agree. Intervening calls may change the selector byte, and the earlier destination write may itself overlap the selector address.

### 5. Third-argument-derived byte write and repeated clearing

Family 11 receives \(4I\) and produces unsigned result \(J\). Define \(V=4J\), subject to 32-bit arithmetic interpretation.

The function performs these operations in order:

1. Write the low byte of \(V\) at the address formed by shifting the third argument right by 15 bits and adding 28.
2. Read the selector byte at \(Q+1\).
3. Write zero at that selector’s value plus 17.

F-U1801 receives the third argument shifted right by 15 bits. F-U1802 is then called with no displayed arguments.

Family 12 receives

\[
(J \mathbin{\&} \text{0x3FFFFFFF}) \gg 6
\]

and produces \(K\).

The function rereads the selector at \(Q+1\) and writes zero at the selected address plus 17.

These zero writes are separate observable operations. They are not a single initialization that may safely be coalesced across the intervening calls.

### 6. Transition to the repeating phase

Family 13 receives \(4K\) and produces unsigned result \(L\). The function derives:

\[
N = (L \mathbin{\&} \text{0x3FFFFFFF}) \gg 25
\]

At this point, \(N\) is between 0 and 31 inclusive.

The function then:

1. Reads an unsigned byte at address \(1024V+1\).
2. Writes zero at that byte’s value plus 17.
3. Calls F-U1901 with \(2N\).
4. Calls F-U1902, obtaining the initial repeating-phase state value.

The selector address \(1024V+1\) is derived from \(J\), not from \(L\) or \(N\). Its arithmetic may wrap under a 32-bit machine interpretation.

### 7. Unconditional repeating phase

Every iteration performs this sequence:

1. Execute Family 14. Its first call receives the current state value and \(N\) shifted right by eight bits. Its fifth call produces \(M\).
2. Read the unsigned selector byte at address \(1024V+1\).
3. Write zero at that selector’s value plus 17.
4. Execute the five call sites F-U2001 through F-U2005. The first receives \(4M\); the remaining four have no displayed arguments. The fifth produces \(R\).
5. Replace the state value with \(4R\).
6. Replace \(N\) with \(R\) shifted left by 26 bits.
7. Repeat without a displayed termination test.

For the first iteration, the second argument to Family 14 is necessarily zero because the initial \(N\) lies between 0 and 31.

Under a 32-bit bit-pattern interpretation, subsequent \(N\) values retain only the low six bits of \(R\), positioned in bits 26 through 31. The next iteration’s second argument therefore has its low 18 bits clear.

The byte-selector address remains derived from the earlier \(V\); the selector byte is nevertheless reread on every iteration.

- Ordered 32-bit stores to computed addresses.

## Acceptance examples

These are conditional contract examples, not executed tests.

1. **Initial write precedes calls.** Given valid entry-state memory and returning dependencies, the incoming payload is stored at the incoming base plus 20 before F-U0101 executes.

2. **Third-argument shifts remain distinct.** With third argument `0x12345678`, the 32-bit write after Family 06 carries `0x00123456`. Family 08 receives `0x002468AC` as its third explicit value. The later byte-write address derived from this argument is `0x2484`.

3. **Byte destinations use a byte-sized selector.** If the selector read returns `0xAB`, that operation writes at address `0xBC`, regardless of adjacent bytes. It does not load a multi-byte destination pointer.

4. **Selector reads are not cached.** If the first selector read returns 3 and an intervening dependency changes it to 9, the corresponding destinations are 20 and 26. This assumes no earlier fault or nonreturning call.

5. **Byte payloads truncate.** If \(H=\text{0x00100043}\), the first byte payload is `0x0C`; the later payload derived from the masked right shift is `0x01`.

6. **Replacement store remains ordered.** If \(F=2\), the two displayed stores at address 52 carry 8 and then 32, separated by Family 08. These values alone do not describe intervening dependency writes.

7. **First repeating argument is constrained.** Whatever Family 13 returns, the initial second argument to Family 14 is zero. Under 32-bit shift semantics, if a later \(R\) is 1, the following state value is 4 and the following second argument is `0x00040000`.

8. **Returning dependencies do not imply completion.** With valid memory and dependencies that always return, execution continues repeating. A normal successful return is not supported by the visible flow.
