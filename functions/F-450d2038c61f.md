# F-450d2038c61f

## Purpose

F-450d2038c61f copies four integer components from a source object into a caller-supplied output region, passes that output region to F-ddca41e891a8, and conditionally adjusts the components after the dependency returns.

The dependency’s return value gates all adjustments:

- A zero result enables four independently controlled adjustments.
- Any nonzero result skips all four adjustments.

When enabled by their respective flags, the adjustments subtract from the first and second output components and add to the third and fourth.

The arrangement suggests adjustment of four ordered boundaries, but their geometric meaning is not established. This contract therefore describes four components without assigning coordinate names, units, or validity rules.

## Behavior

### Initial transfer

Before calling F-ddca41e891a8, the function performs this ordered transfer:

1. Reads the source component at `0x84`.
2. Reads the source component at `0x88`.
3. Reads the source component at `0x8c`.
4. Reads the source component at `0x80` and writes it to output component 1.
5. Writes the previously captured value from `0x84` to output component 2.
6. Writes the previously captured value from `0x88` to output component 3.
7. Writes the previously captured value from `0x8c` to output component 4.

Consequently, all four initial source components are read before the first output write. The captured values for components 2–4 are not reread during their output writes.

This ordering matters when source and output storage overlap: the initial output writes cannot change the values already captured for this transfer. They can, however, change other source fields that will be read later.

These are the access relationships expressed by the supplied representation. They do not establish atomicity, synchronization, or a hardware-level trace for concurrent or device-memory observers.

### Dependency call

After all four output slots have been initialized, the function calls F-ddca41e891a8 exactly once, passing the output address.

The return value is tested only for equality to zero. The function does not distinguish among different nonzero results or expose the result to its caller.

The dependency receives access to the output region. Its implementation is absent, so it must not be assumed to preserve those components. Likewise, it must not be assumed to preserve source fields, globals, or other reachable state.

### Nonzero result

If F-ddca41e891a8 returns nonzero, F-450d2038c61f returns without performing any adjustment-stage flag reads or output writes.

The initial copy is not rolled back. Any output changes made by the dependency also remain unless the dependency itself reverses them.

This path does not establish that nonzero means failure. It establishes only that nonzero suppresses the subsequent adjustments.

### Zero result

If F-ddca41e891a8 returns zero, the function considers the four adjustments in component order.

Each flag test requires both bits selected by `0x80000002` to be set:

- Bit 31 must be set.
- Bit 1 must be set.
- Other bits do not affect eligibility.

A negative flag value alone is insufficient, because bit 1 must also be set. Bit 1 alone is likewise insufficient.

The stages are:

| Stage | Flag read | Enabled operation |
|---|---|---|
| 1 | Source `0x54` | Subtract the current amount at `0x58` from current output component 1 |
| 2 | Source `0x60` | Subtract the current amount at `0x64` from current output component 2 |
| 3 | Source `0x6c` | Add the current amount at `0x70` to current output component 3 |
| 4 | Source `0x78` | Add the current amount at `0x7c` to current output component 4 |

For each stage:

- The flag is read when that stage is reached, not before the dependency call.
- If the flag test fails, that stage does not read its adjustment amount or directly access its output component.
- If the flag test passes, the current output value and current adjustment amount are used, and the result is written to that output slot.
- The selected write completes before the next stage’s flag test.

The relative evaluation order of the output-value read and adjustment-amount read within a selected arithmetic operation is not established. Both contribute to the result before its write.

No pre-call snapshot of flags or adjustment amounts is taken. No original component value is restored after the dependency call. Dependency mutations and earlier overlapping writes can therefore affect later stages.

### Arithmetic and edge conditions

Adjustment amounts are integer values, not validated nonnegative magnitudes. Within the supported arithmetic range:

- Subtracting a negative amount increases the component.
- Adding a negative amount decreases the component.
- A zero amount still selects an arithmetic update and write when its flag test passes.

There is no explicit saturation, clamping, overflow check, ordering check, or relationship check among the four components.

The available evidence does not settle signed-overflow semantics. A contract must not promise either wrapping or saturation when a mathematical result exceeds the signed 32-bit range.

## Acceptance examples

These are conditional acceptance examples derived from static evidence, not runtime observations. Except where stated otherwise, they assume disjoint source and output storage, valid accesses, representable arithmetic, and a dependency that preserves the relevant storage.

### Nonzero dependency result bypasses adjustment

- The output is initialized to `(10, 20, 30, 40)` before the call.
- No adjustment flags or amounts are read afterward.

### Both selected bits are required

- `0x80000000`
- `0x00000002`
- `0x80000002`

Only components 3 and 4 are adjusted. The first two flags each lack one required bit; the fourth qualifies despite its additional set bits.

### Post-call output is the arithmetic base
