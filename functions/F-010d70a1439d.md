# F-010d70a1439d

## Purpose

F-010d70a1439d obtains a value through an object-dispatched callback, then either delegates processing or obtains a second value and converts two table mappings into a 16-bit output.

The established local conversion is sixteen times the first mapping plus the second mapping. A combined value of decimal 10 is replaced with decimal 29; decimal 13 is replaced with decimal 28. A mapping byte of 255 causes local failure. Other mapping bytes, including values above 15, are accepted.

**Inferred intent:** the weighting suggests a two-digit hexadecimal-style conversion with special treatment of two control values. Neither the input encoding nor the mapping-table contents is established, so this interpretation does not constrain accepted inputs.

The mutable input state is significant across dependency calls. Classification receives one low-16-bit observation of that state; delegation or the first lookup uses a later observation. Equality between those observations is not guaranteed.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Arguments and representation

The supplied representation establishes a 32-bit interface with four arguments:

| Argument | Established role |
|---|---|
| Object reference | Provides access to a dispatch-table reference and a one-byte failure-status location. Passed to every dependency invoked by this function. |
| Output reference | Destination for a 16-bit local-conversion result. Also passed to F-00a8b940085b when delegation occurs. |
| Opaque third argument | Present in the interface but not read or forwarded by this function. |
| Initial input state | A 32-bit value copied into a mutable local state cell. The callback receives that cell’s address. |

The object layout established by this function is limited to:

- At byte offset 0: a 32-bit dispatch-table reference.
- At byte offset 4: a one-byte location written with 1 on local failure.

For each callback invocation, the callable entry is obtained from byte offset 36 in the current dispatch table. No other object fields or dispatch entries have an established meaning here.

The local state cell is 32 bits wide. Classification, delegation, and table indexing each use its low 16 bits at their respective read points, producing a nonnegative value from 0 through 65535. The high 16 bits remain part of the cell passed to the callback, even though this function does not use them for those operations.

### Return value

The return value is 32 bits:

- Local conversion success returns 1.
- Local failure returns 0.
- Delegation returns F-00a8b940085b’s complete 32-bit result unchanged.

The function’s overall return domain is therefore not established to be Boolean. In particular, a delegated zero does not itself trigger this function’s local failure handling.

Defined execution requires valid storage and compatible callees for the accesses actually reached:

- The object and dispatch table must support the required reads.
- The dispatch entry must identify a callable operation compatible with the observed arguments.
- Local failure requires a writable byte at object offset 4.

There are no explicit null, bounds, alignment, or callable-entry checks. The source does not establish consequences for invalid memory, incompatible callees, or a dependency that fails to return normally.

## Behavior

### Initialization and table capture

Before invoking a dependency, the function reads a global mapping-table address and retains it for this invocation. It also initializes a 16-bit accumulator to zero, records that no mappings have been accepted, and copies the initial 32-bit state into the local mutable cell.

The captured table address is not reread from the global location. A dependency changing that global location does not redirect this invocation’s subsequent table lookups.

This capture does not freeze the table’s contents or establish its lifetime. Each lookup reads the byte present at the selected address when the lookup occurs. Dependencies are not established to preserve that storage.

### Obtaining input

The function resolves the callback from the object’s current dispatch-table reference and entry at byte offset 36, then invokes F-dynamic-01 with:

1. The object reference.
2. The address of the local 32-bit state cell.

A zero callback result immediately causes local failure. Every nonzero result permits processing; the test does not distinguish positive from negative nonzero results.

The callback is not required by the observed caller to replace the state. If it reports success without modifying the cell, subsequent reads observe the existing state unless another intervening operation changes it.

There is one local state cell for the entire invocation. It is not reset before a second callback. The second callback receives that same address and the cell’s contents at the time of the second call—not necessarily the contents left by the first callback. In particular, F-bc4079d4964b executes between the callbacks on the local-conversion path and is not established to preserve the cell. The first callback could have retained an alias through which that dependency can modify it while the cell remains alive.

At most two callback invocations occur. Failure of either callback ends processing immediately.

### Classification and delegation

After the first successful callback, before any mapping-byte lookup, the function reads the state cell and passes its low 16 bits to F-bc4079d4964b, along with the object reference.

That argument is the value observed when preparing the classification call. The function does not preserve it as the authoritative input for the next operation.

After F-bc4079d4964b returns:

- If its result is nonzero, the function reads the mutable state cell again, extracts the low 16 bits, and passes this newly observed value to F-00a8b940085b with the object and output references.
- If its result is zero, the function reads the mutable state cell again to obtain the first table index.

Consequently, neither delegation nor the first lookup is guaranteed to use the value supplied to classification. An intervening mutation through a retained alias can change the state, including its low 16 bits.

On delegation, F-010d70a1439d immediately returns the complete result from F-00a8b940085b. It performs no local mapping lookup, output store, or failure-status store on that path. This does not restrict effects performed by the dependencies themselves.

F-bc4079d4964b is called only after the first successful callback. It is not called after the second callback. A failed first callback bypasses both named dependencies.

### Local mapping and accumulation

If classification returns zero, the first table lookup uses the low 16 bits read from the state cell after classification returns.

After a successful second callback, the second lookup uses the low 16 bits read from the state cell following that callback. There is no intervening classification call for the second value.

Each lookup reads one unsigned byte at the captured table address plus the selected index:

- A byte of 255 causes local failure.
- Every byte from 0 through 254 is accepted.

After the first accepted mapping, the accumulator equals that mapping. The function then resolves and invokes the callback again.

After the second accepted mapping, the accumulator equals sixteen times the first mapping plus the second mapping. Processing then proceeds directly to result transformation and output; no third callback occurs.

The first accepted mapping remains part of the accumulator even if a dependency subsequently changes the table byte from which it was read. The second mapping is a separate later read.

### Result transformation and output

After two mappings have been accepted:

- A combined result of decimal 10 becomes decimal 29.
- A combined result of decimal 13 becomes decimal 28.
- Every other combined result is unchanged.

The function performs one explicit 16-bit store to the output destination and returns 1.

The evidence establishes the store width, not the destination byte order. No explicit status-byte clear occurs on success.

### Local failure

Local failure occurs when:

- Either callback returns zero; or
- Either selected mapping byte is 255.

The function writes the byte value 1 at object offset 4, then returns 0.

There is no explicit output-destination store on this path. If the first mapping was accepted before failure, the partial accumulator is not published through the output reference.

This is not an unconditional guarantee that output storage remains unchanged. A dependency may modify it indirectly, and an overlapping output destination may be affected by the failure-status write.

### Widths and arithmetic

The index range is 0 through 65535 because each indexing observation is masked to 16 bits.

Each accepted mapping is an unsigned byte from 0 through 254. Therefore:

- The first accumulated value is at most 254.
- The largest combined result is 254 × 16 + 254 = 4318.
- Every reachable local-conversion result fits in a signed 16-bit value.
- Neither multiplication, addition, nor assignment to the 16-bit accumulator requires wrapping to explain any reachable result.

The two replacements, 29 and 28, also fit within 16 bits. No range restriction to 0 through 15 is enforced on accepted mappings.

## Side effects

### Explicit accesses and ordering

The function’s relevant externally directed operations occur in this order:

1. Read and capture the global table address.
2. Read the object’s dispatch reference and callback entry; invoke the first callback.
3. If that callback succeeds, read the state cell for the classification argument and invoke F-bc4079d4964b.
4. After classification returns, reread the state cell for either delegation or the first mapping index.
5. If delegating, invoke F-00a8b940085b and return its result.
6. Otherwise, read the first mapping byte.
7. If accepted, reread the object’s dispatch reference and callback entry; invoke the second callback using the existing state cell.
8. If that callback succeeds, read the state cell for the second index and read the second mapping byte.
9. On local success, write the 16-bit output and return 1.
10. On any local failure, write the one-byte failure status and return 0 instead.

The second dispatch resolution uses the object and dispatch-table contents then present. An earlier dependency may have changed either.

The function explicitly reads zero, one, or two mapping bytes. It does not explicitly read the failure-status byte or clear it on entry, success, or delegation.

### Dependency effects and aliasing

No supplied dependency contract establishes preservation of globals, object fields, table contents, output storage, or the mutable state cell.

The distinction between a retained value and a later memory read matters:

- The table address is retained across calls.
- Each table byte is read when its lookup is reached.
- The classification argument is obtained before classification executes.
- The state is reread after classification for delegation or local mapping.
- The same state cell is reused for the second callback without restoration.

These rules permit intervening dependency mutations to affect later behavior. They do not establish that any particular dependency actually performs such mutations.

### Ownership and lifetime

This function performs no explicit allocation, release, or ownership transfer.

The callback receives access to a local state cell whose lifetime ends when this invocation returns. Retaining an alias can affect later operations while the cell is alive; it does not extend the cell’s lifetime or authorize access after return.

Allocation, release, reference retention, and ownership behavior inside the dependencies are **documented_only**. In particular, preserving the captured table address does not guarantee that dependencies leave its backing storage valid.

There is no explicit rollback of input consumption or dependency side effects when later processing fails.

## Acceptance examples

These are conditional static examples, not executed tests. Unless stated otherwise, assume valid non-overlapping storage, successful callbacks, zero from classification, and no dependency effects beyond the stated changes.

1. **Ordinary conversion.** Mapping bytes 1 and 2 produce a 16-bit output of 18 and return 1.

2. **Special replacements.** Mappings 0 and 10 produce 29. Mappings 0 and 13 produce 28.

3. **Mappings above 15.** Mapping bytes 254 and 254 produce 4318 and return 1. Rejecting them solely for exceeding 15 would contradict the local behavior.

4. **First callback failure.** A zero first callback result causes a status-byte write of 1 and return 0. Neither named dependency is called, and no mapping byte is read.

5. **Second callback failure.** After an accepted first mapping, a zero second callback result causes local failure without an explicit output store.

6. **Mapping sentinel.** A first mapping of 255 causes failure without a second callback. A second mapping of 255 causes failure after two callbacks. Neither path explicitly stores a converted output.

7. **Classification bypasses mapping.** If classification returns nonzero, no mapping byte is read, even if the eventual delegation value would index a byte containing 255.

8. **Delegated zero.** If delegation returns zero, this function returns zero without explicitly writing its failure-status byte.

9. **Classification changes the delegation value.** The first callback leaves low bits equal to 65. Classification receives 65, changes the state through an available alias so its low bits become 66, and returns nonzero. Delegation receives 66, not 65.

10. **Classification changes the first index.** With the same mutation from 65 to 66, but a zero classification result, the first lookup uses index 66.

11. **Second callback sees intervening changes.** Classification changes the full state cell through an alias and returns zero. If the first mapping is accepted and nothing else changes the cell, the second callback receives that changed state, not a restored copy of the first callback’s result.

12. **Callback leaves the state untouched.** If the first callback reports success without modifying the cell, classification receives the initial argument’s low 16 bits. A subsequent lookup uses those same bits only if the cell remains unchanged through classification.

13. **High bits and lookup equivalence.** Two lookup-time states with identical low 16 bits select the same index, regardless of their high bits. This does not imply that dependencies receiving the full cell behave identically.

14. **Captured address versus current contents.** Changing the global table address during classification does not redirect the first lookup. Changing the selected byte at the captured table address can change that lookup’s result.
