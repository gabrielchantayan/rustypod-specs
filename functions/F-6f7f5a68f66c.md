# F-6f7f5a68f66c

## Purpose

F-6f7f5a68f66c searches a counted sequence of 16-bit units for a counted pattern. Under ordinary, nonnegative-length conditions, it returns the **one-based position of the first matching candidate**, or zero if no candidate matches.

Comparison has two modes, selected solely by the least significant bit of a 32-bit options value:

- **Direct mode:** compare zero-extended 16-bit units directly.
- **Dependency-assisted mode:** use 32-bit results from F-3aa514044abb in comparisons.

The broad search behavior is established by the supplied static evidence. A stronger interpretation—such as case-insensitive Unicode searching—is not established. In particular, one dependency call used for later pattern units has no recoverable explicit argument in the supplied representation. Consequently, dependency-assisted matching cannot be fully specified as applying a known transformation uniformly to both sequences.

An empty pattern returns zero. This return value is therefore ambiguous between an empty pattern and an unsuccessful nonempty search.

## Interface

### Inputs

The function has five positional inputs:

| Input | Representation | Meaning |
|---|---|---|
| Search base | Pointer to 16-bit units | Start of the sequence to search. |
| Search count | Signed 32-bit integer | Number of searchable units under the ordinary nonnegative-count contract. |
| Pattern base | Pointer to 16-bit units | Start of the pattern. |
| Pattern count | Signed 32-bit integer | Number of pattern units under the ordinary nonnegative-count contract. |
| Options | Unsigned 32-bit integer | Only bit 0 affects local control flow. |

The counts are in **16-bit units, not bytes**. Successive units occupy two bytes. There is no terminator-based stopping rule: a zero-valued unit is ordinary input data.

Each observed unit read produces a 16-bit unsigned value, which is zero-extended before direct comparison or use as an explicitly supplied dependency argument. Dependency-assisted comparisons use the resulting 32-bit values without a visible reduction back to 16 bits.

The supplied representation does not establish byte order, alignment tolerance, address-space rules, or whether the units have any particular character encoding.

### Output

The result is a signed 32-bit integer:

- Zero for a zero pattern count.
- Zero when scanning exhausts the search count without finding a complete match.
- For an ordinary successful search, the candidate’s one-based unit position relative to the search base.

The success position identifies the **start of the candidate**, not the position after its matched pattern.

There is no separate error result, output buffer, consumed-length result, or returned pointer.

### Preconditions for ordinary search semantics

The ordinary search interpretation requires:

- Nonnegative search and pattern counts.
- Readable storage for all units that the execution actually accesses.
- Valid pointer advancement and representable address arithmetic.
- If dependency-assisted mode is enabled, dependency behavior compatible with completing the calls and subsequent reads.

A zero pattern count requires no input-buffer reads. A zero search count with a nonzero pattern count still requires a readable first pattern unit.

No visible validation enforces these preconditions. Negative counts are not treated as empty sequences.

## Behavior

### 1. Select comparison mode and handle an empty pattern

Only options bit 0 is retained for local decisions. Other option bits do not independently affect scanning, comparison, or the return value.

If the pattern count is zero, the function immediately returns zero:

- Neither sequence is read.
- F-3aa514044abb is not called.
- The search count is irrelevant to this branch.

This is the only branch that bypasses the initial pattern read.

### 2. Cache the first pattern comparison value

For every nonzero pattern count, the function first reads the initial 16-bit pattern unit.

In direct mode, that zero-extended value becomes the cached first-pattern comparison value.

In dependency-assisted mode, F-3aa514044abb is called with that zero-extended value, and its 32-bit result becomes the cached value.

This read, and any associated call, occurs **before checking whether the search count is zero**. Thus an empty search does not prevent access to a nonempty pattern’s first unit.

The cached value is retained for all candidate-start comparisons. There is no visible reread of the first pattern unit when the search moves to another candidate. This matters if a dependency changes memory: subsequent candidate starts still use the earlier cached result.

### 3. Scan candidate starts in ascending order

Candidate starts are visited one unit at a time, beginning at the search base.

Before reading a candidate’s first unit, the function checks whether the remaining outer search count is zero. If so, it returns zero.

Otherwise it:

1. Reads the candidate’s first 16-bit unit.
2. In dependency-assisted mode, calls F-3aa514044abb with its zero-extended value.
3. Decrements the outer remaining search count by one.
4. Retains the next unit as the next candidate start.
5. Compares the candidate’s first comparison value with the cached first-pattern value.

If those values differ, scanning proceeds to the next candidate without inspecting that candidate’s later units.

If they agree, the function attempts to extend the candidate into a complete pattern match.

There is no visible preliminary check that the whole pattern fits within the remaining search sequence. A candidate whose first unit agrees can enter extension even when too few search units remain.

### 4. Extend a candidate

Each extension attempt starts with:

- The candidate’s first comparison already equal.
- A private remaining-search count equal to the outer count after consuming the candidate’s first unit.
- A private remaining-pattern count equal to the original pattern count.
- The pattern cursor initially at the first pattern unit.

At each extension-loop boundary, the pattern cursor advances one unit and the private remaining-pattern count decreases by one. The function then stops extending if any of these conditions holds:

- The most recently compared values differ.
- The private remaining-search count is zero.
- The private remaining-pattern count is zero.

This ordering is significant. The pattern cursor advances and the pattern count decreases even at the boundary that recognizes a mismatch or search exhaustion. Pointer advancement alone is not a read of the newly selected pattern unit.

If extension continues, the next comparison is obtained in this observable order:

1. Read the next search unit.
2. In dependency-assisted mode, call F-3aa514044abb with that search unit’s zero-extended value.
3. Read the next pattern unit.
4. Decrement the private remaining-search count and advance the search-extension cursor.
5. In dependency-assisted mode, call F-3aa514044abb again and use its return value as the pattern-side comparison value.

For the last call in this sequence, the supplied static representation does **not** recover an explicit argument. It is therefore not established that the newly read pattern unit is passed to that call. The pattern read itself remains visible in the supplied evidence.

In direct mode, later comparisons are simply between the zero-extended units read from the two sequences.

### 5. Accept or reject a candidate

An extension attempt succeeds only when both conditions hold:

- The latest comparison values agree.
- The private remaining-pattern count is zero.

Consequences for positive counts include:

- A one-unit pattern succeeds immediately when a candidate’s first comparison agrees.
- A candidate ending exactly at the search boundary succeeds if its final pattern unit agrees.
- A matching prefix that exhausts the search before exhausting the pattern fails.
- A mismatch on the final pattern unit fails, even though the remaining-pattern count has reached zero.

When extension fails, the next candidate is the unit immediately after the failed candidate’s start. The extension’s lookahead does not consume or skip those later starts in the outer scan.

Accordingly, overlapping candidates are examined. Search units inspected during one extension may be read and dependency-processed again during later attempts.

### 6. Compute the successful result

On success, the function uses the address of the unit immediately after the candidate’s first unit, subtracts the search-base address, and shifts the resulting signed integer right by one.

For ordinary valid addresses and representable differences, the byte difference is twice the candidate’s one-based unit position. The result is therefore that one-based position.

The supplied representation expresses address conversion and subtraction through signed integer values. Behavior for address differences outside the representable range, or for arithmetic crossing implementation limits, is not established as a portable contract.

## Side effects

### Directly visible effects

The function visibly:

- Returns a signed 32-bit result.

The input sequences are used as borrowed readable storage for the duration of execution. This does not establish any ownership or retention policy of the dependency.

### Dependency-mediated effects

The effects of F-3aa514044abb are unknown. It must not be assumed to be pure, deterministic, memory-preserving, global-state-preserving, non-retaining, or allocation-free.

The ordering of calls and reads can therefore affect behavior:

- Initial pattern processing occurs before the empty-search check.
- Search-side dependency processing occurs before the corresponding later pattern read.
- Later pattern-side dependency processing occurs after that read.
- A dependency may affect subsequent reads or calls; no snapshot of either sequence is established.
- The cached first-pattern comparison value is not recomputed between candidates.

No visible exception handling or dependency-failure translation exists. Invalid memory access and dependency failure have no specified recoverable result.

### Repeated work

Failed extension does not preserve comparison results for later candidates. The same search or pattern unit can be read and processed repeatedly.

For ordinary positive counts, a direct-mode search can therefore perform work proportional to the product of the search and pattern lengths in unfavorable cases. No skip table, memoization, or normalization buffer is visible.

## Acceptance examples

These examples are conditional static expectations, not runtime observations. Unless stated otherwise, they assume valid readable storage, nonnegative counts, representable address arithmetic, stable input memory, and direct comparison mode.

### Empty pattern

Given any search count and pattern count zero:

- The result is zero.
- Neither sequence is read.
- No dependency call occurs.

Input pointers need not be dereferenceable for this branch.

### Empty search with a nonempty pattern

Given search count zero and pattern count one:

- The first pattern unit is read.
- No search unit is read.
- The result is zero.

If dependency-assisted mode is enabled, the initial pattern dependency call occurs before the zero result.

Given search units `[12, 34, 56]` and pattern `[12]`, the result is `1`.

These distinguish a one-based position from a zero-based index.

### Multi-unit match

The later occurrence is not selected because the earlier candidate completes successfully.

- The first candidate agrees on its first unit and fails on its second.
- The second candidate is still examined.
- The result is `2`.

Lookahead from the failed first candidate does not skip the second candidate.

The third pattern unit is not read during the first candidate’s extension because no search unit remains. Later candidate processing still follows the ordinary outer scan.

### Final-unit mismatch

Reaching the pattern-count boundary is insufficient when the latest comparison differs.

### Embedded zero units

Given search `[5, 0, 6]` and pattern `[0, 6]`, the result is `2`.

### Option-bit equivalence

For identical inputs and otherwise identical dependency behavior:

- Options `0` and `2` select the same direct-mode behavior.
- Options `1` and `3` select the same dependency-assisted control path.

Higher bits do not create additional modes.

### Conditional dependency-assisted match

For a one-unit pattern, if the initial pattern call and the first candidate’s call return equal 32-bit values, the result is `1`, even if the raw 16-bit units differ.

For a longer pattern, acceptance additionally requires equality of the later comparison results, including the results of pattern-side calls whose arguments are unresolved.
