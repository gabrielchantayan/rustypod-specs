# F-6d8420276e17

## Purpose

F-6d8420276e17 attempts to replace a table’s backing storage, conditionally invokes an external operation on the region following the table’s previously recorded extent, updates the recorded extent, and reports the resulting state through a diagnostic dependency.

The apparent intent is multiplicative table growth followed by initialization of the added region. That intent is inferred from the arithmetic and call structure. The available evidence does **not** establish that the storage dependency reallocates memory, that the external region operation clears memory, or that either operation preserves the table descriptor.

This contract distinguishes:

- **Established behavior:** operations and control flow directly visible in the supplied representation.
- **Inferred intent:** interpretations suggested by argument shapes and referenced text.
- **Documented-only unknowns:** behavior requiring dependency implementations, target arithmetic details, or runtime evidence.

No runtime tests have been performed.

## Behavior

### Target calculation

Before invoking any dependency, the function reads the descriptor’s growth factor and recorded extent and calculates their product. This product is the **saved target extent**.

The representation does not establish the relative order of the two reads within that multiplication. Both precede the storage-dependency call.

The saved target extent is a local calculation. Later changes to descriptor slots do not cause it to be recomputed.

### Storage request and unconditional replacement

The function invokes F-dbea69bb52a6 with seven positional arguments:

| Position | Supplied value |
|---|---|
| 1 | Descriptor’s storage value, read for this call |
| 2 | Saved target extent multiplied by four |
| 3 | Auxiliary value B |
| 4 | Auxiliary value C |
| 5 | Auxiliary value A |
| 6 | Auxiliary value B again |
| 7 | Auxiliary value C again |

The exact evaluation order of arguments within this call is not established.

After the dependency returns, the function **unconditionally writes its returned value into descriptor slot 0**. This write occurs even when the result is zero.

Consequences:

- A zero result replaces the descriptor’s previous storage value with zero.
- The function does not visibly restore the old storage value.
- The function does not visibly retain a separate recovery copy of the old storage value.
- Any descriptor mutation performed by the dependency may be followed by this overwrite of slot 0.

The next branch tests the returned value itself, rather than performing a fresh descriptor read.

### Zero-result path

If F-dbea69bb52a6 returns zero:

- The external region operation is not called.
- This function does not write slot 1.
- The failure-designated status is selected.
- Reporting proceeds.

“This function does not write slot 1” does not mean that slot 1 necessarily retains its entry value. F-dbea69bb52a6 may have changed it through mechanisms not visible here.

### Nonzero-result path

If F-dbea69bb52a6 returns a nonzero value, the function calls an external region dependency with two arguments:

1. The returned storage value plus four times a newly read recorded extent.
2. Four times the difference between the saved target extent and a newly read recorded extent.

Under a stable descriptor, this describes the region immediately after the previously recorded elements, extending to the saved target extent.

Two distinctions are material:

- The region base uses the **storage dependency’s returned value**, not a fresh read of descriptor slot 0.
- The extent used for region calculations is read **after** F-dbea69bb52a6 returns. It is not necessarily the extent used in the initial multiplication.

The recorded extent occurs separately in the two region arguments. The supplied representation does not establish their relative evaluation order or make them one atomic snapshot.

The external operation’s purpose is unknown. Its argument shape is consistent with a region-initialization operation, but no content-writing behavior, including zero filling, is established.

After the external dependency returns, the function writes the saved target extent into descriptor slot 1.

It then freshly reads descriptor slot 0:

- Nonzero selects the success-designated status.
- Zero selects the failure-designated status.

Thus, a nonzero storage-dependency result does **not** guarantee selection of the success-designated status. The external dependency may affect state subsequently observed through the descriptor.
