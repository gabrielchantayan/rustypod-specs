# F-b98ce5d77965

## Purpose

F-b98ce5d77965 attempts an operation against a supplied object using a requested value and an associated 32-bit candidate value. It first consults a preparation dependency. When preparation permits execution, it tries the object's callback with a candidate held in temporary storage. If that callback rejects the candidate, it searches a collection associated with the object and tries eligible entries.

The result is a 64-bit composite containing a 32-bit status in its low half and a pointer-valued field in its high half. A successful attempt also writes a selected candidate to caller-provided storage.

The established behavior is the sequence of calls, memory accesses, branches, and result construction described below. Terms such as “preparation,” “candidate,” “collection,” and “cleanup” are descriptive roles, not established domain meanings or guarantees about ownership.

## Interface

The function receives four arguments:

| Argument | Observed representation | Role |
|---|---|---|
| Output destination | Pointer to a 32-bit integer location | Receives the accepted candidate on a success path. |
| Object | Pointer to a structure accessed through 32-bit words | Supplies a callback and access to a collection. Also appears in most returned results. |
| Request | Opaque 32-bit value | Used to derive a search key and passed unchanged to each callback invocation. |
| Initial candidate | 32-bit integer | Initializes the candidate portion of a temporary two-word region. |

The output destination is not initialized on entry. The function's explicit assignment to it occurs only on success. Dependencies or aliasing may produce other effects; therefore, an unsuccessful result does not establish that the underlying storage was untouched.

### Observed object and entry layouts

The following fields are accessed directly:

| Structure | Byte offset | Observed use |
|---|---:|---|
| Object | 0 | A 32-bit pointer to an associated structure. |
| Object | 48 | A callable address. |
| Associated structure | 4 | A 32-bit collection handle or pointer. |
| Collection entry | 0 | A 32-bit discriminator, required to equal 1 for continued scanning. |
| Collection entry | 4 | A 32-bit candidate supplied to transformation and callback operations. |

The callback receives three arguments: the object pointer, the original request, and a candidate value. Its result is interpreted as a 32-bit integer: zero rejects the attempt; any nonzero value accepts it.

These offsets describe only accessed fields. They do not establish complete structure sizes, packing rules beyond the observed word accesses, or the meanings of other fields.

### Temporary region

The function creates a contiguous two-word temporary region:

- Offset 0: the original 32-bit request.
- Offset 4: the initial 32-bit candidate.

The preparation dependency receives the address of the first word. The second word is subsequently read as the candidate for the first callback attempt. The supplied evidence does not restrict preparation's writes to the first word, nor establish the complete temporary-region contract.

### Return encoding

The return is composed of two 32-bit halves:

| Outcome | High 32 bits | Low 32 bits |
|---|---|---|
| Success | Supplied object pointer | 1 |
| No accepted candidate | Supplied object pointer | 0 |
| Preparation error other than the distinguished error | Supplied object pointer | All bits set |
| Distinguished preparation error, if the diagnostic call returns | Zero | All bits set |

“All bits set” is `0xFFFFFFFF`, interpreted as −1 when viewed as a signed 32-bit status. It is not a statement that the entire 64-bit result equals −1.

No null-pointer validation, structure validation, or output-capacity check is visible. Each executed access requires valid storage or a valid callable target at the time of that access.

## Behavior

### Preparation

Before calling any dependency, the function initializes the two-word temporary region from the request and initial candidate.

It then calls F-cf23980ec4fa with the original request and retains the returned 32-bit value as the search key. This key is computed once. Subsequent changes to temporary storage do not trigger recomputation.

Next, it calls F-89508a506e1c with:

1. The supplied object.
2. The constant 1.
3. The retained search key.
4. The address of the temporary region.

The preparation result controls the next action:

- **Result 0:** Return the object with status 0. There is no explicit output assignment, callback invocation, collection search, or temporary cleanup on this branch.
- **Result −1:** Call F-c088595ce204 with the temporary-region address, then call F-4fc89ec41a6d with the constants 11, 127, and 106. If that diagnostic call returns normally, return a zero high half and status −1.
- **Any result other than 0, 1, or −1:** Call F-c088595ce204 with the temporary-region address, then return the object with status −1.
- **Result 1:** Proceed to the first callback attempt without first calling F-c088595ce204.

No evidence establishes that F-4fc89ec41a6d must return. The encoded distinguished-error result describes only the continuation if it does.

### First callback attempt

After preparation returns 1, the function reads the object's callback field and invokes it with:

- The supplied object.
- The original request, not a re-read of the temporary region's first word.
- The current second word of the temporary region.

Consequently, a preparation dependency that changes the temporary candidate can change this attempt's candidate.

If the callback returns nonzero, the function writes the temporary candidate to the output destination and returns the object with status 1. The function performs no explicit temporary cleanup on this success path.

The output value is read from temporary storage after the callback returns. It is not explicitly saved before invocation. Although the callback is not directly passed the temporary-region address, the supplied evidence does not prove that indirect mutation is impossible.

If the callback returns zero, the function calls F-c088595ce204 with the temporary-region address before beginning the collection search.

### Collection search initialization

After that cleanup call, the function reads the object's associated-structure pointer, reads the collection field at offset 4 within that structure, and calls F-198ffacb6983 with:

- The collection value.
- The constant 1.
- The retained search key.

The returned 32-bit integer becomes the starting index.

A starting index of −1 terminates the search immediately and produces status 0. There is no explicit rejection of any other negative starting index.

### Collection traversal

For every iteration, the function first re-reads the collection through the object and its associated structure, then obtains a count from F-10b760faca36.

The index and count are compared as signed 32-bit integers. If the index is not less than the count, traversal ends with status 0.

When the index is less than the count, the function independently re-reads the collection and calls F-6bbddce1b930 with that collection and the current index. The returned pointer identifies the current entry.

The function then reads the entry's first word:

- If it is not 1, traversal ends with status 0.
- If it is 1, the entry's candidate at offset 4 is passed to F-6261bc5c6581.

The result of that transformation is passed to F-cde148df0583 together with the retained search key. A nonzero comparison result ends the search immediately with status 0. A zero result permits a callback attempt for this entry.

Thus, traversal does not skip entries of another discriminator or entries whose transformed candidate does not compare equal. It examines only the consecutive eligible region encountered from the starting index.

### Entry callback attempts

For an eligible, matching entry, the function reads the object's callback field again and invokes it with:

- The supplied object.
- The original request.
- The entry's current candidate at offset 4.

This candidate is read after the transformation and comparison dependencies have returned. It need not equal the value previously supplied to F-6261bc5c6581 if an intervening dependency changed the entry.

If the callback returns zero, the index increases by one and traversal repeats. There is no explicit entry-removal call for a rejected entry.

If the callback returns nonzero:

1. The candidate is read again from the same entry pointer.
2. That value is written to the output destination.
3. F-6b26b6644c65 is called with the entry pointer.
4. The function returns the supplied object with status 1, provided the dependency returns normally.

The value written to the output can therefore differ from the value passed to the callback if the callback changes the entry's candidate.

The output write precedes F-6b26b6644c65. That ordering matters when output storage aliases memory reachable through the entry or when the dependency observes the output destination indirectly.

### Search termination and arithmetic

Every search exit without an accepting callback returns the object with status 0. Such exits include:

- Starting index −1.
- Index not less than the current count.
- Entry discriminator other than 1.
- Nonzero comparison result.
- Repeated callback rejection followed by one of those conditions.

The index increments only after satisfying a signed less-than comparison against a signed 32-bit count. Under that representation, the current index cannot be the maximum signed 32-bit integer when incremented, so the visible increment does not require signed overflow.

Negative indices other than −1 can reach F-6bbddce1b930 when they compare less than the count. Whether such indices are meaningful or valid is not established.

## Side effects

The function's explicit effects are:

- Initializing and potentially exposing a two-word temporary region to dependencies.
- Writing one 32-bit candidate to the caller's output destination on a success path.
- Invoking the object's callback one or more times.
- Calling the temporary-region cleanup dependency on specified failure or fallback paths.
- Calling F-6b26b6644c65 after a successful collection-entry attempt.
- Calling the diagnostic dependency for the distinguished preparation error.

No direct heap allocation or direct deallocation is visible. This does not establish that dependencies allocate nothing or release nothing.

Ownership cannot be inferred from the cleanup-like calls:

- Passing temporary storage to F-c088595ce204 does not prove which referenced resources, if any, it releases.
- Passing an entry to F-6b26b6644c65 does not establish whether it removes an entry, destroys a value, releases memory, or performs another operation.
- Absence of explicit cleanup on initial success or preparation result 0 does not prove a leak or a transfer of ownership.

Dependencies and callbacks may mutate shared state. In particular:

- The collection used for the count call can differ from the collection used for retrieval in the same iteration, because the collection is re-read between calls.
- The callback address can differ between attempts.
- An entry candidate can change between transformation, callback invocation, and output assignment.
- No visible locking or snapshot mechanism stabilizes these observations.

For defined execution, object fields and entry storage must remain valid until their last executed use. After a successful entry callback, the entry must remain readable through the output assignment and usable as an argument to F-6b26b6644c65.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes valid accessed memory and normal return from the dependencies involved.

1. **Preparation declines without cleanup.**  
   If preparation returns 0, the result has the object in its high half and zero in its low half. The function does not explicitly write the output, call the callback, or call the temporary cleanup dependency.

2. **Distinguished preparation failure.**  
   If preparation returns −1, temporary cleanup occurs before the diagnostic call. If the diagnostic returns, the high result half is zero and the low half is `0xFFFFFFFF`.

3. **Other preparation failure.**  
   If preparation returns 2, temporary cleanup occurs and the result contains the object with low half `0xFFFFFFFF`. No diagnostic call occurs.

4. **Preparation changes the candidate.**  
   If preparation returns 1 after changing the temporary candidate from 8 to 19, the first callback receives 19. If it accepts and that temporary word remains 19, the output receives 19 and the result status is 1. No explicit temporary cleanup follows.

5. **First rejection, no starting entry.**  
   If the initial callback rejects, temporary cleanup occurs before starting-index lookup. If lookup returns −1, the result status is 0 and no collection count or entry-retrieval call follows.

6. **Mismatching entry stops the scan.**  
   If a retrieved entry has discriminator 1 but comparison returns nonzero, its callback is not invoked and later indices are not examined.

7. **Rejected match followed by accepted match.**  
   If two consecutive retrieved entries both have discriminator 1 and compare equal, the first callback rejects, and the second accepts, the second entry supplies the output. Only the accepted entry is passed to F-6b26b6644c65.

8. **Callback changes the accepted entry.**  
   If an entry callback receives candidate 23, changes that entry's candidate to 29, and returns nonzero, the function writes 29 to the output before calling F-6b26b6644c65.

9. **Unexpected negative starting index.**  
   If lookup returns −2 and the count is 3, the visible signed comparison permits retrieval with index −2. Whether that retrieval succeeds is documented_only; this function supplies no additional validation.
