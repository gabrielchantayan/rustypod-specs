# F-84f25e86d55f

## Purpose

F-84f25e86d55f produces a three-valued result from two scalar inputs and externally stored state:

- **1:** the second input is within an externally stored admission limit, and its scaled value is no greater than an unsigned interpretation of a difference.
- **0:** the second input is within that admission limit, but the scaled comparison fails.
- **0xFFFFFFFF:** the second input exceeds the admission limit.

The comparison uses a scale factor of **1000**. The difference is formed from a signed word in an externally addressed object minus the first input.

A possible intent is to determine whether an interval has elapsed or whether sufficient distance remains relative to a reference value. That interpretation is not established: the supplied evidence does not identify units, time sources, object semantics, or caller expectations.

The distinction between **0** and **0xFFFFFFFF** is part of the observable contract. Treating the return value solely as a Boolean would merge the out-of-limit result with the successful comparison result.

## Behavior

### Admission decision

The function first compares the second input with the externally stored admission limit.

Equality is admitted. Only a strictly greater second input takes the rejection path.

On rejection, the function returns the unsigned all-ones sentinel. The supplied representation does not evaluate the object-base lookup or the comparison-word dereference on this path. Consequently, the pointed-to object is not needed to determine this result.

This early exit does not make the function independent of all memory validity: obtaining the admission limit must still succeed.

### Admitted comparison

For an admitted second input, the result depends on two quantities:

- The second input multiplied by 1000 using unsigned arithmetic.
- The signed comparison word minus the first input, followed by conversion of that difference to unsigned.

The return value is 1 when the first quantity is less than or equal to the second quantity; otherwise it is 0. Equality therefore succeeds in both the admission comparison and the final comparison.

The unsigned conversion occurs **after** the represented signed subtraction. It must not be interpreted as evidence that each subtraction operand is first converted to unsigned.

### Multiplication width and wraparound

Under the 32-bit model, the multiplication by 1000 is an unsigned 32-bit multiplication. Its result is reduced modulo 4,294,967,296.

There is no explicit overflow check, saturation, widening to a 64-bit result, or rejection of large admitted values.

For example:

- A second input of 4,294,967 produces 4,294,967,000.
- A second input of 4,294,968 produces **704** after unsigned wraparound.

Thus, increasing the second input does not necessarily increase the scaled value used by the final comparison. An admission limit that permits multiplication overflow can expose this nonmonotonic behavior.

### Signed subtraction and unsigned conversion

When the mathematical difference between the signed comparison word and the first input is representable as a signed 32-bit integer, the subsequent conversion to unsigned is well characterized:

- A nonnegative difference retains its numerical value.
- A negative difference becomes its value modulo 4,294,967,296.

For example, a representable difference of −1 becomes 4,294,967,295. Every possible unsigned 32-bit scaled value is less than or equal to that result.

This means a negative signed difference does not necessarily cause a false result. The function does not perform a signed comparison against the scaled input.

If the signed subtraction itself exceeds the signed range, the supplied representation does not establish a portable result. A machine implementation might perform a wrapping subtraction, but that behavior cannot be promoted into a requirement without instruction-level or equivalent evidence. Such cases are **documented_only**.

### Zero and boundary inputs

A zero second input has a scaled value of zero. If it is admitted and the subtraction has defined semantics, the final unsigned comparison succeeds because every unsigned value is at least zero.

A second input exactly equal to the admission limit proceeds to the final comparison; it does not return the sentinel merely because it reaches the limit.

A scaled value exactly equal to the converted difference returns 1.

### Observable ordering

The established control dependence is:

1. Obtain the admission-limit value for the initial comparison.
2. Decide whether the second input is admitted.
3. Only if admitted, obtain the object base and read the signed comparison word.
4. Produce the corresponding return value.

The object-base value must be available to form the address of the comparison word.

The supplied expression does not establish a finer evaluation order between calculating the unsigned product and evaluating the subtraction operand. It also does not establish hardware transaction counts, compiler reload behavior, or memory barriers.
