# F-44c315c6ba20

## Purpose

F-44c315c6ba20 copies a count-derived sequence of four-byte words from a source region into the payload of a destination region. The destination’s first word supplies the count used to determine the copy length; that first word is not itself copied. The source sequence likewise begins four bytes beyond the supplied source address.

The operation is a forward, word-at-a-time transfer, not an overlap-safe bulk move. If the regions overlap, earlier writes can change the values read by later iterations.

An apparent intended use is copying packed storage whose logical length is measured in bits, with one payload word per 32 logical elements. That interpretation is inferred from the length calculation, not established by any type declaration or validation. The established behavior is the arithmetic and memory-access sequence described below.

## Interface

**Inputs**

- **Destination region:** A pointer to an integer-word region. Its first word is read as the length-control value. Subsequent words are writable payload storage.
- **Source address:** An integer-valued address identifying a source region. Payload reads start at this address plus four bytes. The source’s first four bytes are not explicitly read by this function.

**Output**

The function returns no value. Its result consists of writes to destination payload words.

**Widths and layout**

The supplied representation uses integer words, four-byte source strides, and a five-bit right shift for the length calculation. The behavioral description below uses the corresponding 32-bit integer model:

| Byte offset | Destination interpretation | Source interpretation |
|---|---|---|
| 0–3 | Length-control word, read once | Skipped leading word |
| 4–7 | First destination payload word | First source payload word |
| 8–11 | Second destination payload word | Second source payload word |
| Subsequent four-byte offsets | Remaining payload words | Remaining payload words |

The source representation explicitly establishes four-byte spacing for source accesses. The destination uses consecutive integer elements. Treating both as matching four-byte words relies on the target’s integer and pointer model; exact ABI details are not independently supplied.

No byte-order transformation, bit masking, or partial-word copy is expressed. Subject to valid word accesses, each source word is transferred as a complete word.

**Preconditions for a defined, successful invocation**

- The destination’s first word must be readable even when the resulting payload length is zero.
- For a nonzero payload length, every selected source word must be readable and every selected destination word must be writable.
- Both regions must satisfy the target’s alignment and address-representation requirements.
- Address calculations and accesses must remain meaningful for the target execution environment.
- If a snapshot copy is required, the caller must avoid overlap that allows earlier destination writes to overwrite source words not yet read.

## Behavior

### Length selection

The destination’s first word is read once, before any payload transfer. The saved value determines the entire transfer length; the function does not reread the destination header between words.

Under the 32-bit model, the payload word count is calculated by:

1. Interpreting the saved header’s bit pattern as an unsigned 32-bit value.
2. Adding 31 with unsigned 32-bit wraparound.
3. Shifting the resulting unsigned value right by five bits.

For nonnegative signed 32-bit header values, this is the ceiling of the header divided by 32. A header of zero selects zero words.

Negative signed header values must not be treated as ordinary negative loop limits. The unsigned arithmetic can instead select either a very large copy or no copy at all. In particular:

- Headers from −31 through −1 select zero words because the addition wraps to a value below 32.
- A header of −32 selects 134,217,727 words.
- The most negative signed 32-bit header selects 67,108,864 words.

Thus, “negative length means no work” is not a valid contract.

The maximum selected length under this arithmetic is 134,217,727 words, or 536,870,908 payload bytes. This is an arithmetic limit, not evidence that any invocation has that much valid storage.

### Transfer sequence

For each selected word, starting with the first payload word:

- The function reads the corresponding source word.
- It writes that value to the corresponding destination payload word.
- It advances to the next word.

Transfers proceed in increasing word-index order. No reverse-copy path, temporary snapshot, or overlap detection is present.

The function does not explicitly read the source’s leading word. It does not assign to the destination’s leading word. It also does not transfer any words beyond the selected payload count.

### Zero-length operation

If the selected word count is zero, the function returns after reading the destination header. It performs no source payload reads and no destination payload writes.

Consequently, source payload readability is not exercised on this path. This does not establish a general guarantee about all invalid integer-address values on every target; it establishes that the source-access loop is not entered.

### Overlap

Overlap is handled only by the ordinary forward sequence of reads and writes.

Identical source and destination regions cause each payload word to be read and written back to the same location. The memory accesses still occur.

When the destination payload starts later in memory than the source payload, a write may overwrite a source word needed by the next iteration. Later iterations then read the overwritten value, not necessarily the value present at entry.

When the destination payload starts earlier, the sequence may preserve the original source words needed for subsequent iterations. The function nevertheless makes no independent overlap-safety check.

### Completion and errors

After the selected transfers, the function returns without a status value.

There is no explicit error path for a null destination, insufficient capacity, invalid source address, misalignment, negative header, or overlapping regions. A failure during an access has no function-defined recovery or rollback. Earlier completed writes are not undone by any logic shown.

## Side effects

The established memory effects are:

- One initial read of the destination header.
- One source payload-word read for each selected word.
- One destination payload-word write for each selected word.

For ordinary valid, nonoverlapping regions, all other bytes remain untouched by this function. In particular:

- The destination header remains unchanged.
- The source’s leading word is not copied.
- Destination storage after the selected payload range remains unchanged.
- No unused bits in the last copied word are cleared.

The last point matters if the header represents a logical bit count. A count of 33 selects two complete words; it does not limit the second write to one bit.

No allocation, release, ownership transfer, callback, or external function call is present in the supplied body. The function neither returns storage nor records either address for later use.

These observations do not establish broader synchronization guarantees. No locking, atomic-access contract, or concurrent-modification policy is expressed. Behavior under concurrent mutation or device-backed memory is not specified beyond the visible access structure.

## Acceptance examples

The following are conditional acceptance criteria derived from static evidence. They are not runtime test results. Unless stated otherwise, they assume the 32-bit model, valid aligned storage, and nonoverlapping regions.

1. **Zero header**

   Given a destination header of zero, the function reads that header and performs no payload transfer. Existing destination payload values remain unchanged.

2. **One selected word**

   Given a header of 1 and a first source payload word of `0xA5A5A5A5`, the first destination payload word becomes `0xA5A5A5A5`. The destination header remains 1. No second payload word is accessed.

   A header of 32 selects the same one-word transfer length.

3. **Partial logical final word**

   Given a header of 33 and source payload words `0x12345678` and `0xFFFFFFFF`, both complete words are copied. The second destination word becomes `0xFFFFFFFF`; it is not masked to a single valid bit.

4. **Source header is not transferred**

   Given a destination header of 32 and a different value in the source’s leading word, the destination header remains 32. Only the source word at byte offset four supplies the copied payload.

5. **Forward-overlap propagation**

   Let a valid region contain, in increasing word order: 65, A, B, C, and D. Let the destination begin at the word containing 65, and let the source address be one word earlier.

   Three payload words are selected. The first transfer reads the destination header and writes 65 over A. The second reads that newly written 65 and writes it over B. The third reads the newly written 65 and writes it over C. D remains unchanged.

   This outcome distinguishes the function from a snapshot copy.

6. **Negative header selecting no transfer**

   A header of −1 selects zero payload words under unsigned 32-bit arithmetic. The function still reads the destination header but does not read source payload storage.

7. **Negative header selecting a large transfer**

   A header of −32 selects 134,217,727 payload words. Successful completion requires valid storage for that selected range. An implementation that rejects the value or silently performs no transfer would differ from the established arithmetic.
