# F-352a6facb968

## Purpose

F-352a6facb968 conditionally initializes a newly obtained object or substitutes a caller-supplied object, then publishes a 32-bit object address through an output pointer.

The operation selects among three modes using a flags word. The modes have strict precedence: bit 0 selects two-argument initialization; otherwise bit 2 selects one-argument initialization; otherwise bit 1 permits substitution of an existing object. An unsupported selection or a zero substitution address takes the failure path.

The established behavior includes acquiring a 40-byte object before evaluating the mode, writing a saved context value into that object, and releasing the acquired object when substitution is selected. This acquisition still occurs when the caller intends to supply an existing object.

Terms such as “object,” “context,” “acquire,” and “release” describe the apparent roles of values and dependencies. Their allocation, ownership, and lifetime semantics are not independently established.

## Interface

The function has four inputs and returns a 32-bit signed status value.

| Input | Representation | Established use |
|---|---|---|
| Context reference | Pointer to a readable 32-bit word | Its first word is saved and passed to dependencies. |
| Configuration | Pointer to 32-bit unsigned words | Supplies flags, initialization arguments, or an existing object address. |
| Output reference | Pointer to a writable 32-bit word | Receives zero initially and, on paths reaching final publication, the selected object address or zero. |
| Initial status value | 32-bit signed integer | Initializes a local status cell whose address is passed to F-3ce007b692cc. |

The visible representation uses 32-bit object addresses and 32-bit words. This is not a contract for native-width pointers on an arbitrary host architecture.

### Configuration layout

Offsets are measured in bytes from the configuration address.

| Offset | Width | Meaning when selected |
|---|---:|---|
| 0 | 32 bits | Flags |
| 4 | 32 bits | First argument for the bit-0 initializer |
| 8 | 32 bits | Second argument for the bit-0 initializer |

Only the selected branch reads its branch-specific fields. The flags word is read once after successful acquisition and the initial object-context write. Bits outside masks 1, 2, and 4 do not participate in selection.

### Object layout used directly

The function directly writes these fields:

| Object-relative offset | Width | Value |
|---|---:|---|

The acquisition request is 40 bytes. That request does not establish the meanings or initialization state of any other bytes.

### Preconditions

Apart from two explicit null checks, memory validity is a caller/dependency precondition:

There are no visible bounds, alignment, object-type, or address-overflow checks.

## Behavior

### Early validation and initial output write

Validation occurs in this order:

1. A null context reference returns status 33 immediately.
2. Otherwise, a null configuration returns status 6 immediately.
3. Otherwise, the output word is set to zero.

Neither early return writes the output or invokes a dependency. In particular, a null context reference takes precedence over a null configuration.

The initial output write occurs before reading the context word. Consequently, permitted aliasing can affect later behavior: if the output aliases the context word, the saved context will be zero. If it aliases a configuration field, that field is changed before configuration selection.

### Acquisition

After zeroing the output, the function:

- Reads and saves the first 32-bit context word.
- Initializes a local 32-bit status cell from the fourth input.
- Calls F-3ce007b692cc with the saved context, the value 40, and the address of that status cell.
- Treats the dependency’s 32-bit return value as the acquired object address.
- Reads the status cell.

If that status is nonzero, the function returns it immediately. It does not publish the acquired address, write the object’s context field, or invoke F-bf7242c98d06 on this path. The output has already been zeroed, but dependency side effects or aliases may have changed it.

If the status is zero, the function writes the saved context into the acquired object at offset 28. It does not first test whether the acquired address is zero.

Only after this object write does the function read the flags word and select a mode.

### Mode precedence

Selection is determined by the flags value already read:

| Condition | Selected behavior |
|---|---|
| Bit 0 set | Two-argument initialization |
| Bit 0 clear, bit 2 set | One-argument initialization |
| Bits 0 and 2 clear, bit 1 set | Existing-object substitution, subject to a nonzero candidate |
| Bits 0, 1, and 2 clear | Failure with status set to 6 |

Setting additional lower-priority mode bits does not combine modes. For example, flags 7 select only the bit-0 initializer.

### Bit-0 initialization

The function calls F-8f073f7099e1 with:

- The acquired object address.
- The configuration word at offset 4.
- The configuration word at offset 8.

Both configuration arguments are obtained for this call; their relative read order is not established by the supplied representation.

The dependency’s return value is not assigned to the local status. This path does not explicitly replace the zero status established after acquisition. Nevertheless, dependency side effects are not proven absent.

After the call, execution proceeds to the common status decision.

### Bit-2 initialization

The function reads the configuration word at offset 12 and passes it, with the acquired address, to F-9609821066af.

The dependency’s return value replaces the local status.

After the call returns, the function reads the configuration word at offset 12 again and writes that value into the acquired object at offset 16. This write occurs regardless of whether the returned status is zero.

The two configuration reads need not produce the same value if the dependency changes accessible configuration memory. The copied field therefore reflects the post-call read, not necessarily the argument passed to the initializer.

Execution then proceeds to the common status decision.

### Bit-1 substitution

This branch is available only when bits 0 and 2 are clear and bit 1 is set.

The function first reads the existing address at configuration offset 16.

- If that read yields zero, it sets the local status to 6 and takes the common failure cleanup path.
- If it is nonzero, it calls F-bf7242c98d06 with the saved context and the acquired address.

After that dependency returns, the function reads configuration offset 16 again and makes this second value the selected object address. It does not reuse the first value and does not repeat the nonzero check.

Thus, if the release dependency changes that configuration word, the selected address can differ from the address that passed the check. A second-read value of zero is not rejected before the subsequent object-field write on a zero-status path.

The function does not explicitly assign a new local status in the successful substitution branch. Execution proceeds to the common status decision.

### Unsupported or rejected selection

When no recognized selection bit is set, or when the first substitution-address read is zero, the function sets the local status to 6.

It then invokes F-bf7242c98d06 on the acquired address and proceeds to final publication with a zero selected address.

### Common status decision and publication

For initialization and accepted-substitution paths:

- If the current local status is zero, the saved context is written at offset 28 of the selected object.
- Otherwise, F-bf7242c98d06 is called with the saved context and selected address, after which the selected address is set to zero.

The selected address is then written to the output word, and the current local status is returned.

For successful initialization, the offset-28 context write therefore occurs twice: once before mode selection and once after the initializer. The second write restores that field if the initializer changed it.

For successful substitution, the initial context write targets the acquired temporary object; the final context write targets the address obtained by the second configuration read.

The final output write follows the final object-context write. If the output aliases that field, publication overwrites it with the selected address.

## Side effects

### Direct memory effects

The function can directly:

- Zero the output word.
- Write the saved context at offset 28 of the acquired object.
- Write the post-call configuration value at offset 16 on the bit-2 path.
- Write the saved context at offset 28 of the final selected object.
- Publish the selected address or zero through the output reference.

It also exposes the address of its local status cell to F-3ce007b692cc.

No direct global access is shown. Dependencies may have additional effects; preservation of globals or caller-accessible memory is not established.

### Resource and ownership effects

The visible call discipline is:

- No acquisition occurs on either early null-input return.
- Acquisition occurs before mode selection on every other path.
- A nonzero acquisition status returns without release by this function.
- Ordinary successful initialization retains the acquired address and publishes it.
- Accepted substitution releases the acquired address before selecting the replacement.
- Rejected selection releases the acquired address.
- A nonzero status at the common decision releases the currently selected address.

These calls do not prove that F-bf7242c98d06 actually frees memory or that F-3ce007b692cc allocates it. Nor do they establish who must eventually dispose of a published object.

Dependency exceptions, nonlocal exits, faults, or other failure mechanisms are not handled in the visible function.

## Acceptance examples

These are conditional static examples, not results of executed tests. Unless stated otherwise, memory is valid, relevant regions do not overlap, dependencies return normally, and they do not mutate unmentioned state.

1. **Null context takes precedence.**  
   With null context and null configuration, the result is 33. The output remains untouched, and no dependency is called.

2. **Null configuration is rejected before output access.**  
   With a nonnull context and null configuration, the result is 6. The context word is not read, and the output remains untouched.

3. **Acquisition reports failure.**  
   If F-3ce007b692cc leaves status 12, the function returns 12 after the initial output-zero write. It neither writes the candidate object nor invokes cleanup, regardless of the returned candidate address.

4. **Flags 7 select only bit 0.**  
   With acquisition status zero, F-8f073f7099e1 receives the acquired address and the words at offsets 4 and 8. Neither other mode is selected. If status remains zero, the context field is rewritten and the acquired address is published.

5. **Bit-2 success uses a post-call configuration read.**  
   Suppose flags are 4 and the offset-12 word initially contains 100. If F-9609821066af receives 100, changes that word to 200, and returns zero, the object’s offset-16 field receives 200. The acquired address is published.

6. **Bit-2 failure still writes the field.**  
   If that initializer returns 9, the post-call offset-12 value is still copied to object offset 16 before cleanup. With no later status mutation, the final output is zero and the return is 9.

7. **Substitution releases the temporary first.**  
   With flags 2 and a stable nonzero existing address, the acquired object first receives the context field, then is passed to F-bf7242c98d06. The existing address is reread, receives the context field, and is published if status remains zero.

8. **Zero substitution address is rejected.**  
   With flags 2 and a first offset-16 read of zero, the acquired object is cleaned up. With no cleanup-induced status mutation, the function publishes zero and returns 6.

9. **Unrecognized bits alone do not select a mode.**  
   Flags 8 follow the same status-6 cleanup outcome as flags zero.

10. **Output-context aliasing changes the saved context.**  
    If the output word is the context word, initial output zeroing makes the subsequently saved context zero. Dependency calls and object-context writes use zero, not the context word’s entry value.

## Uncertainties

**documented_only — Stable status assumptions.** The bit-0 and substitution paths do not explicitly assign status after successful acquisition. A claim that they necessarily return zero requires assumptions about dependency effects on the escaped status-cell address.

**documented_only — Concurrent mutation.** Sequentially repeated reads are explicit, but no synchronization or atomicity guarantees are shown. Concurrent-access semantics are not established.

**documented_only — Status vocabulary.** Values 33 and 6 are explicit outcomes; their human-readable error meanings are unknown. Other status values come from the acquisition status cell or the bit-2 initializer.
