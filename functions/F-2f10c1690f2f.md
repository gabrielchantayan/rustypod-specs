# F-2f10c1690f2f

## Purpose

F-2f10c1690f2f is a six-argument operation with no explicit return value. Global configuration controls a dispatcher that transforms 32-bit numeric state, conditionally reads a caller-supplied word, and invokes three dependencies. Two dependencies receive the address of a six-word invocation-local record.

The supplied representation establishes neither a normal execution path nor guaranteed termination. Configuration can select an immediate return, dependency calls, repeated activation, uninitialized-record exposure, or cycles.

**Inferred intent:** numeric operations and record submission appear coordinated by configuration. No business domain, success convention, or intended configuration is established.

## Behavior

### Configuration and arithmetic

The following descriptive names identify roles, not concrete configuration values:

- **M** and **N:** 32-bit factors captured at entry.
- **Entry selector:** the initial dispatcher state, captured at entry.
- **Base:** a global word read for each dispatch.
- **H:** a global factor read when constructing a dependency-result mask.
- Other globals provide numeric seeds, multipliers, call options, and transition destinations.

The entry-time global-read order is **N, then M, then Entry selector**. M and N remain captured for the invocation. Base is not captured at entry: each dispatch evaluates the current state minus a fresh Base read.

The resulting difference selects explicit actions 0 through 10. Action 8 and unmatched differences use the same fallback action.

Arithmetic descriptions below use the conventional 32-bit machine-word interpretation: products, additions, subtractions, and complements retain 32-bit results. A sign test examines bit 31. The supplied representation includes signed arithmetic; exact language-level behavior on signed overflow is **documented_only**, not an independently established portability guarantee.

\[
S(r)=\operatorname{NOT}\left(P(r)\operatorname{OR}(HMr)\right).

Each operation is at 32-bit width under that interpretation. H is read at the action-specific point described below. \(S(r)\) is a control mask, not an established success or error code.

The branch descriptions assume the represented signed right shift propagates the sign bit, yielding selection by bit 31. They do not establish a portable language-level rule for every arithmetic implementation.

2. Compute \(M P(r)\) into the intermediate word.
3. Read the record-operation destination global once and form its plus-six candidate.

## Acceptance examples

These are conditional static consequences, not executed tests. Arithmetic examples use the 32-bit interpretation described above.

1. **Immediate return.** If the entry state minus the dispatch-time Base selects action 7, the operation returns without activation, target-word reads, record construction, or dependency calls. A null supplied pointer is not rejected on this path.

2. **Activation without dereference.** Reaching action 5 installs the supplied pointer but does not read its target. It replaces the initially zero active payload with the supplied payload.

3. **First numeric call following activation.** If action 1 follows activation with no intervening working-value changes, its second dependency argument is \(NM\) times the primary input. Its third and fourth arguments are zero. The first argument is read when the call is prepared, not at entry.

4. **Zero numeric result.** If either numeric form returns zero, both terms inside the mask OR are zero, so the mask is `0xffffffff`. Action 1 selects its separately read unadjusted destination. Action 4 selects the unadjusted Base occurrence; the next dispatch still uses another Base read.

5. **Zero retained fields only without prior changes.** If both retained numeric fields have remained unchanged since their entry initialization, and action 6 follows activation, offsets 0 and 4 receive zero. The other fields receive the activated payload, scaled auxiliary input, fresh target word, and M times the primary input.

6. **Reactivation preserves retained results.** If action 1 leaves nonzero retained fields, a later action 5 does not clear them. An immediately following action 6 writes those retained values at offsets 0 and 4. If action 4 changed the second field before reactivation, that updated value likewise survives.

7. **Separate action 6 destination reads.** Suppose its plus-six read yields 100 and its subsequent unadjusted read yields 200. The selected state is 106 for a clear mask sign bit or 200 for a set sign bit. H is read only after both destination reads. The next dispatch subtracts its own fresh Base value.

8. **Repeated record construction.** Every completed action 6 rewrites all six fields. A changed target word can change offset 16. Earlier dependency modifications within these fields are overwritten; modifications elsewhere are not addressed by this construction.

9. **Uninitialized-record exposure.** If action 3 precedes every action 6, it still passes the record address. No zero-filled or deterministic contents may be assumed.

10. **Pre-activation target read.** If action 1, 4, or 6 reaches its target-word read before activation, the working pointer is null. No protective branch or defined recovery is established.

11. **Low-word arithmetic.** Multiplying `0xffffffff` by two produces `0xfffffffe` under the stated word model. Mathematical unbounded-integer multiplication is not the model used for the mask.
