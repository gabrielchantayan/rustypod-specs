# F-78effd4e3255

## Purpose

F-78effd4e3255 writes a fixed five-byte record into caller-supplied storage and returns an unsigned 32-bit value capped at five.

The record contains one byte read from an input structure or memory region, one caller-supplied byte, and three fixed bytes. The fourth argument affects only the returned value. It does not limit the number of bytes written.

**Established behavior:** every normally completed invocation writes five destination bytes, including invocations whose fourth argument is zero.

**Inferred intent:** the record may represent a small protocol or control structure. No field meanings, protocol identity, or relationship between the returned value and downstream consumption are established.

## Interface

The function has four inputs and one scalar output:

| Input | Established representation | Role |
|---|---|---|
| Source base | Presented as a 32-bit signed integer used to form an address | Identifies the memory region from which one byte is read at offset 24 |
| Supplied byte | One byte, eight bits | Becomes destination byte 1 |
| Destination | Pointer to byte-addressable storage | Receives five consecutive byte writes |
| Requested amount | Unsigned 32-bit integer | Determines the capped return value, but not the write extent |

The return value is an unsigned 32-bit integer equal to the smaller of the requested amount and five. Its possible values are therefore zero through five inclusive.

The supplied byte is treated as an opaque byte value. No sign interpretation, character encoding, boolean conversion, or numerical scaling is established.

### Required memory access

For normal completion:

- The address formed from the source base plus 24 bytes must permit a one-byte read.
- The destination must permit one-byte writes at offsets 0 through 4.
- Address formation must behave validly for the execution environment.

There is no established requirement that the source region be readable before or after the selected byte. Likewise, no destination bytes beyond offset 4 are explicitly accessed.

The requested amount is not a destination-capacity guarantee. A caller passing a value below five must still supply space for all five writes. This function performs no capacity check.

The supplied source representation does not establish portable behavior when adding 24 exceeds a signed 32-bit range or produces an invalid address. Neither signed-overflow semantics nor address wrapping should be assumed from the available evidence.

## Behavior

All fields are individual bytes. No multi-byte field, byte-order conversion, padding, terminator interpretation, or checksum operation is established.

### Observable access order

The established logical memory-access order is:

1. Read the byte at source-base offset 24.
2. Write that byte to destination offset 0.
3. Write the supplied byte to destination offset 1.
4. Write zero to destination offset 2.
5. Write one to destination offset 3.
6. Write zero to destination offset 4.

After the writes, the function returns the requested amount when it is at most five, or five otherwise. There is no early-return path for a small requested amount.

This is the access order expressed by the supplied function body. It does not establish hardware transactions, compiler-level access guarantees for special memory, memory barriers, or inter-thread visibility ordering.

### Return-value boundaries

The comparison uses the unsigned 32-bit requested amount:

- Zero returns zero.
- Values one through four return unchanged.
- Five returns five.
- Every value greater than five returns five.
- The maximum unsigned 32-bit value, 4,294,967,295, returns five.

The function performs no signed-negative case analysis on this input. A high-bit-set unsigned value remains a large positive value for the cap comparison. How an external caller converts a differently typed argument before invocation is outside this contract.

The return value must not be interpreted as the number of bytes modified: all five bytes are written regardless of whether the return value is zero, one, two, three, four, or five.

## Acceptance examples

These are conditional expectations derived from static evidence. They are not reports of executed tests. Unless stated otherwise, they assume valid ordinary memory and normal completion.

### Requested amount below the write extent

Given a selected source byte of hexadecimal A6, a supplied byte of hexadecimal 3C, and a requested amount of two:

- Destination offsets 0 through 4 become A6, 3C, 00, 01, 00.
- The returned unsigned value is two.
- Five bytes are written, not two.

### Zero requested amount

With the same source and supplied bytes, a requested amount of zero still produces A6, 3C, 00, 01, 00.

The returned value is zero. The invocation does not skip memory access, and zero does not make an otherwise invalid source or destination acceptable.

### Exact cap and values above it

A requested amount of five returns five. Requested amounts of six and 4,294,967,295 also return five.

In all three cases, the destination receives the same five-byte record when the other inputs are unchanged.

### Byte values without interpretation

If both the selected source byte and supplied byte are hexadecimal FF, the destination becomes FF, FF, 00, 01, 00.

The two FF bytes are preserved as eight-bit values. No established behavior treats them as negative values or errors.

### Overlapping selected source and destination

Suppose the selected source address is destination offset 3, initially containing hexadecimal 7B, and the supplied byte is hexadecimal 42.

The final destination bytes are 7B, 42, 00, 01, 00. The initial 7B is read before destination offset 3 is overwritten with 01.

### Insufficient destination storage

If only two destination bytes are writable, passing a requested amount of two does not make the call valid. The function still attempts writes through offset 4. No defined successful result or recovery behavior is established.
