# F-047d22db5c73

## Purpose

F-047d22db5c73 transfers selected raw storage from a source base address to a destination base address. It transfers three consecutive 32-bit quantities and one following 8-bit quantity, beginning four bytes after each base.

The established behavior is a sequence of four read-and-write pairs, not a snapshot of the entire source region. This distinction matters when the source and destination overlap: an earlier destination write can change the value obtained by a later source read.

The apparent intent is to copy a 13-byte portion of a larger record while leaving its initial four bytes unchanged. That interpretation is inferred intent only. The evidence does not establish a record type, field meanings, or the reason for excluding the initial four bytes.

## Behavior

### Transfer sequence

The established logical access order is:

1. Read 32 bits at source offset 4, then write that value at destination offset 4.
2. Read 32 bits at source offset 8, then write that value at destination offset 8.
3. Read 32 bits at source offset 12, then write that value at destination offset 12.
4. Read 8 bits at source offset 16, then write that value at destination offset 16.
5. Return without an explicit result.

Each source value is obtained for its own transfer. The evidence does not show all source quantities being captured before the first destination write.

The transferred quantities are uninterpreted bits. There is no visible arithmetic on their contents, sign conversion, comparison, normalization, byte-order conversion, or conditional transformation. The first three transfers each use a four-byte access; the last uses a one-byte access.

The sequence above describes the supplied representation. It does not establish processor-level atomicity, bus transactions, memory barriers, or guarantees for concurrently accessed or device-backed memory.

### Disjoint source and destination

For valid, nonoverlapping ordinary storage with no intervening changes, normal completion gives the destination the source’s corresponding initial contents at offsets 4 through 16.

The function does not directly access offsets 0 through 3 at either base, or offsets beyond 16. In a disjoint ordinary-memory case, those destination bytes remain unchanged.

This boundary is exact: the final transfer writes only offset 16, not a four-byte quantity beginning there.

### Identical bases

Identical source and destination bases are not rejected. For ordinary memory without external changes, each transfer reads storage and writes the same value back to that storage. The final byte contents therefore remain unchanged.

The call must not be treated as an access-free operation merely because the bases are equal. The supplied behavior still includes four reads and four writes. Whether those accesses have additional significance in a particular memory environment is not established.

### Partially overlapping regions

Partial overlap is not checked or specially handled. Later reads observe the storage available at their turn, including changes caused by earlier writes.

Consequently, the function does not provide a general “copy from the source’s entry-time contents” guarantee for overlapping regions. The relationship between the two bases determines which later reads, if any, are affected.

Descriptions of bytes left untouched are relative to the actual written addresses. A write through the destination base can alter a byte that also belongs to the source region, even though the function has no separately expressed source write.

If execution cannot complete an access, the supplied evidence does not define a portable failure result. It also provides no rollback or all-or-nothing guarantee. Earlier writes may already have occurred before a later access fails, subject to the execution environment’s fault behavior.
