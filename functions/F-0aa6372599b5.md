# F-0aa6372599b5

## Purpose

F-0aa6372599b5 performs a long, externally mediated sequence of memory updates, value transformations, and indirect calls. Its visible effects include publishing the first input into indexed storage, propagating dependency-produced values through several address layouts, modifying byte-sized metadata, updating two global storage locations, and finally attempting a call to address zero.

No application-level purpose is established. In particular, the supplied representation does not establish that this is an allocator, initializer, serializer, dispatcher, or supervisor-service implementation. Those interpretations would require dependency and execution-context evidence.

This contract distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.
- **Inferred intent:** possible interpretations that are not acceptance requirements.

All normal-progress descriptions are conditional on preceding accesses and calls completing and returning control. No runtime tests have been performed.

## Behavior

### Observable ordering model

The visible body is a single represented sequence: no explicit conditional branches or loops appear. Dependencies may nevertheless branch, fail, mutate memory, or not return.

The order of direct accesses relative to intervening calls is significant. An implementation must not assume that repeated reads separated by calls return the same value. It must not collapse repeated stores merely because they appear to write the same byte.

Two address conventions recur:

- **Indexed word storage:** a 32-bit value is written at four times an index plus `0x14`.
- **Byte-selected metadata:** an unsigned byte is read at a computed address; that byte, plus `0x11`, becomes the address of an 8-bit write.

The second convention is not an ordinary pointer dereference through a full-width pointer. The selected write address lies from `0x11` through `0x110`, inclusive. The byte supplying that selection must be read at each represented occurrence.

The following phases describe the established dataflow and ordering anchors. Intervening calls remain observable operations even when no explicit arguments are represented.

### 1. Publish the explicit input

The first observable operation is a 32-bit store of the first input at four times the second input plus `0x14`.

Only afterward does the routine read a 32-bit word at the first input plus `0x14`. The initial dependency receives:

1. The first input.
2. That word logically shifted right by 19.
3. Zero.
4. The first input again.

Consequently, if the initial store aliases the subsequent read, the dependency observes the stored value, subject to actual memory semantics.

A sequence of calls follows. A dependency-produced index then selects another indexed word destination, which also receives the first input. The scaled index is passed onward.

### 2. Derive packed fields and modify selected bytes

A later 32-bit dependency result supplies several distinct derived values:

- The result shifted left by two.
- The result masked with `0x3FFFFFFF`, then shifted right by 17.
- The same masked value shifted right by 20.
- The same masked value shifted right by seven.

The low byte of the left-shifted result is written through an incoming-state byte selector. Later, after intervening calls, that selector is read again and the low byte of the masked, right-shifted-by-20 value is written.

These are separate reads and writes. The destination need not remain unchanged between them.

The left-shifted value is forwarded twice in one call together with the first input. Later calls forward scaled dependency results, including duplicate arguments. Another call receives four copies of one result, both masked field extractions, and a control-derived value whose application meaning is unknown.

A paired result is subsequently split. Its high half is forwarded twice with an earlier result; its low half is retained for subsequent addressing. Before that forwarding, a byte-selected metadata destination derived from the earlier seven-bit field extraction is cleared. That selector is read and cleared again later.

### 3. Read through packed and secondary-register-derived addresses

The next region repeatedly clears byte-selected metadata, obtains dependency results, scales those results, and performs narrow or word reads.

Established accesses include:

- Clearing metadata selected by a byte at a retained word shifted right by nine, plus one.
- Reading an unsigned byte at twice a retained word and forwarding that byte in four argument positions.
- Clearing metadata selected by the byte at absolute address one.
- Calling a dependency with a secondary unsigned result shifted right by 18, then forwarding its result four times.
- Reading a 32-bit word at a retained word plus a high-bit contribution derived from that word’s bit 19; the loaded word is forwarded four times.
- Reading one byte at a secondary-result address plus `0x0E`; the loaded byte is forwarded four times.

Some represented arguments are algebraically zero under 32-bit bitvector arithmetic. For example, a value already shifted left by two, then shifted left by 31, contributes no surviving bits. This does not justify removing intervening calls or memory effects.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Initial publication:** Given first input `0x1000` and second input three, the first direct write places the 32-bit value `0x1000` at address `0x20`, before any dependency call.

2. **Aliasing at entry:** If the second input is four and the first input is `0x10`, the initial write and subsequent word read both address `0x24`. With ordinary writable memory, the initial dependency’s shifted argument is zero.

3. **Unsigned selection:** If a metadata-selector byte is `0xFF`, its corresponding byte write targets `0x110`, not a sign-extended negative address.

4. **Byte truncation:** If a contributing word is `0x00000043`, writing its left-shift-by-two result as a byte writes `0x0C`.

5. **Repeated metadata lookup:** If an intervening dependency changes a selector byte from two to nine, the corresponding successive writes target `0x13` and `0x1A`. Reusing the earlier selector would not preserve the represented behavior.

6. **Global mutation:** If a dependency changes G1 after its explicit zero assignment, a later read uses the changed value. Treating every later G1 read as zero is not acceptable.

7. **Word-to-byte copy:** For a reached word value of `0x123456AB` at a base plus `0x74`, the associated byte write at base plus one stores `0xAB`.

8. **Terminal failure:** If address zero is not callable, successful normal return is not an acceptance requirement. The final call attempt remains ordered after the preceding byte, global, and halfword writes.
