# F-34ea75d5d6e0

## Purpose

F-34ea75d5d6e0 invokes a dependency with two fixed arguments, then transfers 68 consecutive 16-bit units from a source region to a destination region. The transfer covers 136 bytes and proceeds in increasing address order.

The defining behavior is an ordered sequence of individual reads and writes, not an atomic block replacement or an overlap-safe move. Each source unit is read immediately before its corresponding destination unit is written. A preceding destination write can therefore affect a later source read if the regions overlap.

The dependency executes before either transfer base is obtained. Consequently, changes that the dependency makes to the base-address state or transfer memory can affect the subsequent transfer.

This contract describes the supplied static evidence. It does not establish the purpose of the dependency, the identity of either memory region, or a hardware-specific interpretation of the transferred units.

### 2. Obtain the transfer bases

After the dependency returns, the function obtains the source base from its global cell. It then obtains the destination base from its separate global cell.

This ordering matters:

- Neither base is captured before the dependency call.
- The source-base read precedes the destination-base read.
- The captured values, rather than repeated reads of the global cells, are used throughout the transfer.

If F-86393e9907da changes either base cell before returning, the transfer uses the resulting value read afterward. The dependency must not be assumed to preserve either cell.

Once both bases have been captured, later changes to the global cells do not redirect the remaining accesses in the shown transfer. This remains true if a destination write happens to overwrite a base cell: the current invocation continues using its already captured bases. Such an overlap can still change global state visible after the function returns.

### 3. Transfer the units

The function processes ordinal positions zero through 67, inclusive.

At each position, it reads one 16-bit unit from the source base plus twice the position, then writes that value to the destination base plus the same offset. The write for one position completes in the shown sequence before the read for the next position.

Thus, the access order begins with a source read at offset zero and a destination write at offset zero. It continues with a source read and destination write at offset two, and ends with a source read and destination write at offset 134.

The function does not first capture all source contents. It does not inspect the transferred values to determine whether to continue. There is no early exit based on a value being zero, equal to the destination, or otherwise special.

The loop executes 68 times on its normal path. Its bounded index and offset calculations reach at most 68 for the loop count and 134 for a transfer offset. These small values do not require arithmetic near an integer-width limit. The supplied material does not independently establish the machine width of the index or address values; the principal arithmetic uncertainty concerns adding offsets to the captured bases.

### 4. Return

After the write at offset 134, the function returns without a result value. No further direct operation is shown.

There is no explicit completion flag, checksum, result count, memory release, or restoration of prior destination contents.

### Overlap behavior

No overlap check or direction selection is present. The transfer always proceeds forward.

For disjoint ordinary-memory regions, with no other actor modifying the relevant memory, the destination receives the source units as they exist during the corresponding reads. Because destination writes cannot then affect the source, this is also the source sequence present at transfer start.

For identical source and destination bases, every unit is still read and written. Ordinary memory contents remain unchanged by the transfer itself, but the accesses are not omitted. That distinction can matter for memory-mapped locations.

For overlapping regions, the destination cannot generally be described as a copy of the source’s initial contents. Earlier writes can replace values that later reads consume. No temporary buffer or snapshot protects those later reads.

## Acceptance examples

### Disjoint ordinary-memory regions

Assume the dependency returns normally, both captured regions are valid and disjoint, and no other actor changes them during the transfer.

The destination must receive 68 consecutive 16-bit source units in order. For example, if the source units have values zero through 67 in ascending order, the corresponding destination units must have those values after normal completion.

The same principle applies independently to a dependency-induced change of the destination base.

### Identical bases

Assume both captured bases identify the same valid ordinary-memory region and no external actor modifies it.

The final contents remain the same, but 68 read-then-write pairs still occur. Skipping the accesses solely because the bases are equal would not preserve the evidenced access behavior.

### Destination begins one unit after the source

Assume ordinary memory, a destination base exactly two bytes above the source base, and initially distinct source units.

The first source unit is written over the second source unit. The next source read therefore obtains the value just written. This propagation continues through the transfer, so all 68 destination units become equal to the first source unit’s original value.

This outcome distinguishes the function from a snapshot-based or overlap-safe move.

### Destination begins one unit before the source

Assume ordinary memory, a destination base exactly two bytes below the source base, valid overlapping regions, and no external modification.

Each destination write is below the source location just read and does not overwrite a source unit that remains to be read. The destination therefore receives the original source sequence in this case.
