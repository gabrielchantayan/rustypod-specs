# F-776e6a3d3e9b

## Purpose

F-776e6a3d3e9b conditionally converts an event discriminator into one of four animation-completion labels, invokes a dependency with that label and two writable argument copies, forwards the dependency’s 32-bit result to an indirect object operation, and then invokes a final dependency on one of the copies.

Four discriminator values take this processing path. All other discriminator values bypass the dependency calls and object dispatch.

Every path that returns normally returns the 32-bit value 1. The function does not expose a separate success, failure, or “event recognized” result.

The animation-completion interpretation is inferred from the selected labels. The pointer traversal, discriminator selection, argument-copy behavior, call ordering, and constant normal return are established by the supplied static evidence.

## Interface

The function has four inputs and one 32-bit output:

| Input | Required representation | Use |
|---|---|---|
| Object reference | Address of an object whose first field supplies an indirect-dispatch-table address | Used only for recognized discriminator values, after F-9b9c1c7483f4 returns |
| Event reference | Address of a structure with a pointer-bearing field at byte offset 8 | Traversed to obtain the discriminator |
| First payload word | Opaque 32-bit value | Copied into a local writable 32-bit cell for the recognized path |
| Second payload word | Opaque 32-bit value | Copied into a different local writable 32-bit cell for the recognized path |

**Output:** the 32-bit integer value 1 on every normal return.

The supplied representation uses 32-bit words and pointer-bearing fields. Offsets in this contract are byte offsets. The payload words are not established as integers, pointers, ownership tokens, or handles; their semantic types are unknown.

### Event layout

The discriminator is reached through this structure:

| Location | Content used |
|---|---|
| Event reference + 8 | Pointer to an intermediate record |
| Intermediate record + 12 | Pointer to a discriminator word |
| Discriminator-word address | A full 32-bit word |

The effective discriminator is the least significant eight bits of that 32-bit word. It is not established as a one-byte memory read. The upper 24 bits are read as part of the word but do not affect the selection.

### Object layout

On the recognized path, the first pointer-sized field of the object supplies a dispatch-table address. The callable entry is read at byte offset 284, hexadecimal 0x11C, within that table.

The indirect operation receives:

1. The original object reference.
2. The 32-bit result returned by F-9b9c1c7483f4.

The operation’s return value, if any, is not used.

### Preconditions

For defined execution of the event lookup, the event reference, intermediate-record pointer, and discriminator-word pointer must support their respective reads. No explicit null, bounds, alignment, or accessibility checks are present.

For a recognized discriminator, the additional preconditions include:

- Both dependency calls must support the argument forms described below.

- The selected dispatch entry must designate an operation callable with the two observed arguments.

The object need not be dereferenceable for an unrecognized discriminator: that path does not access it.

## Behavior

### Discriminator acquisition

Before selecting a label or invoking either dependency, the function performs the event traversal in this order:

1. Reads the pointer-bearing field at offset 8 from the event reference.
2. Reads the pointer-bearing field at offset 12 from the resulting intermediate record.
3. Reads a 32-bit word through the resulting pointer.
4. Retains that word’s least significant eight bits for selection.

The selection is therefore based on a value from 0 through 255. Upper-bit differences alone cannot change the selected path.

There is no range expansion, signed-byte interpretation, or arithmetic on the payload words. The relevant arithmetic consists of fixed address offsets and the low-eight-bit mask.

### Label selection

The mapping is exact and case-sensitive:

| Effective discriminator | Selected label |
|---|---|
| 2 | `LeaveFlowAnimationEnded` |
| 4 | `FlipToAlbumBacksideEnded` |
| 6 | `AlbumSelectedAnimationEnded` |
| 7 | `SongSelectedAnimationEnded` |

For every other effective discriminator, the function returns 1 immediately after selection. It does not invoke F-9b9c1c7483f4, the object operation, or F-8a5aadac202f.

The labels are passed by reference to F-9b9c1c7483f4. The supplied evidence establishes their selection and spelling, but not whether that dependency copies, retains, compares, or otherwise interprets them.

### Payload-copy preparation

For a recognized discriminator, the function creates two separate writable 32-bit local cells:

- The first receives the first payload word.
- The second receives the second payload word.

The first copy is established before the second copy in the supplied static sequence. These are local copies, not references to caller-owned payload storage.

Their contents have no established interpretation at this point. In particular, the second cell is initialized from the fourth input; it is not shown as zero-initialized or uninitialized.

### First dependency call

The function invokes F-9b9c1c7483f4 with three arguments, in this order:

1. Address of the second local cell.
2. Reference to the selected label.
3. Address of the first local cell.

The dependency returns a 32-bit value.

Both cell addresses designate writable local storage. The dependency may modify either cell if its own contract permits that behavior. This function does not validate either cell afterward and does not inspect their post-call contents before dispatch.

The first dependency’s result is forwarded unchanged to the object operation. No result-code comparison, null check, conversion, or conditional bypass is visible.

### Indirect object operation

After F-9b9c1c7483f4 returns, the function reads the object’s dispatch-table address and the entry at offset 284. It then calls that entry with the original object reference and the first dependency’s result.

The placement of this lookup matters: the dispatch metadata is read after the dependency call, not cached beforehand. Consequently, if the dependency legitimately changes relevant object or global state, the later lookup uses the state present at that time.

The function performs no explicit object-field writes of its own. Any object mutation caused by this operation belongs to the operation’s behavior, which is not supplied.

### Final dependency call and return

If the object operation returns normally, the function invokes F-8a5aadac202f with the address of the second local cell.

This is the same cell whose address was passed as the first argument to F-9b9c1c7483f4. Its contents may have changed since initialization. The original second payload word is not recopied into it before the final dependency call.

The first local cell is not passed to a corresponding final dependency in the visible behavior.

After F-8a5aadac202f returns normally, the function returns 1. No dependency return value changes that result.

## Side effects

### Directly established effects

The function directly:

- Reads the event pointer chain and the 32-bit discriminator word.
- Writes the two local payload copies on recognized paths.
- Reads object dispatch metadata on recognized paths, after the first dependency returns.
- Calls two dependencies and one indirect object operation, in that order.

No direct writes to event storage, object fields, or global variables are visible.

For unrecognized discriminators, the visible behavior is limited to the event lookup and return. Local payload preparation and all three calls are bypassed.

### Dependency-mediated effects

The callees’ side effects are not established. They may affect memory or global state according to contracts not included here. This function must not be described as globally side-effect-free merely because it contains no explicit global write.

Similarly, the final dependency’s position suggests a finalization role, but does not establish deallocation, reference-count decrement, or any particular ownership transfer.

### Lifetime and ownership

Passing a payload word by value does not itself establish ownership transfer of any resource that the word might represent. Passing a local cell to either dependency likewise does not establish that the dependency owns or releases its contents.

The forwarded 32-bit result has unknown ownership and lifetime requirements. No separate disposal of that result is visible.

### Abnormal completion

The final dependency call is reached only after the first dependency and the indirect operation both return normally. If either does not return normally, the supplied evidence does not establish that F-8a5aadac202f runs.

## Acceptance examples

These examples are conditional static acceptance criteria, not reports of runtime tests.

1. **Recognized value 2.** Given a valid event traversal ending in the 32-bit word 2, the selected label is `LeaveFlowAnimationEnded`. If both dependencies and the indirect operation return normally, the call order is F-9b9c1c7483f4, the indirect operation, then F-8a5aadac202f, followed by return value 1.

3. **Upper bits ignored for selection.** A discriminator word of hexadecimal 0x12345602 selects the same label as the word 2. The entire 32-bit word must still be readable.

4. **Unrecognized value.** Given a valid event traversal ending in 3, the function returns 1 without invoking either dependency or the object operation. No object dispatch-table read is required.

5. **Payload positioning.** Given distinct payload words A and B, the first dependency receives an address to a cell initially containing B as its first argument and an address to a separate cell initially containing A as its third argument.

6. **Modified second cell.** If the first dependency changes the second cell from B to C, and no intervening operation changes it again, the final dependency receives the address of the cell containing C. The wrapper does not restore B.

7. **Unfiltered forwarded result.** If the first dependency returns the 32-bit value zero and the remaining execution is valid, the indirect operation is still invoked with zero. The wrapper does not treat zero as a failure indicator.

8. **Post-dependency dispatch lookup.** If the first dependency changes the object’s dispatch metadata through a valid mechanism, the subsequent indirect call uses the metadata read after that dependency returns.

9. **Different recognition, same normal result.** A recognized event and an unrecognized event both return 1 when they complete normally. The return value alone cannot distinguish those cases.
