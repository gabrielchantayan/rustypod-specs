# F-9606f89bc518

## Purpose

F-9606f89bc518 coordinates a preparation step, a type-dependent eligibility check, two ordered operations with different selectors and output buffers, optional finalization, and conditional cleanup.

Its defining behavior is error precedence rather than early termination: once the two-operation path is entered, both operations are attempted, optional finalization and conditional cleanup follow, and only then are the operation results examined for return.

The supplied static evidence establishes this orchestration. It does not establish the application-level meaning of the inputs, selectors, buffers, or dependency results.

## Behavior

### 1. Initial state and control-area initialization

The shared finalization request is set to zero. The mutable state is initialized from the fourth input.

An initialization dependency is then called with the control-area address and the numeric argument 44. Its result is not used. The evidence does not establish whether 44 is a byte count or another parameter, nor whether the dependency clears, fills, registers, or otherwise processes the area.

After that call returns, the function explicitly writes 16, or hexadecimal 0x0010, into the first 16-bit control field. This assignment replaces the entire field rather than preserving any bits previously written there. Its least significant bit is therefore clear immediately after this write.

### 2. Preparation

F-27385576fa62 is called with seven arguments, in this order:

1. First input.
2. Second input.
3. Third input.
4. Zero.
5. Current mutable state, initially the fourth input.
6. Address of the preparation output area.
7. Address of the mutable state.

The dependency may update the address-exposed storage according to its own contract, which is unavailable here.

If preparation returns nonzero:

- The fallback status is not read.
- The preparation discriminator is not tested.
- Eligibility checking and both operations are skipped.
- Optional finalization is skipped.
- Conditional cleanup is considered.
- The preparation result is returned.

### 3. Fallback status and discriminator

If preparation returns zero, the function reads a separate global status value and adopts it as its current return candidate. It then reads the first signed 16-bit element of the preparation output and compares it with 2.

This ordering matters: the global status is read even when the discriminator equals 2 and the eligibility call will subsequently replace that return candidate.

If the discriminator is not 2:

- Eligibility checking and both operations are skipped.
- Optional finalization is skipped.
- Conditional cleanup is considered.
- The previously read global status is returned.

No sign-sensitive discriminator logic is present beyond equality with 2. All other representable 16-bit values take this same path.

The global status may itself be zero or nonzero. Consequently, skipping the two operations because of a discriminator mismatch does not necessarily produce a nonzero result.

### 4. Eligibility check

If preparation returned zero and the discriminator equals 2, F-211960b717b8 is called with:

1. First input.
2. Second input.
3. Third input.
4. Current mutable state.

The fourth argument reflects any preparation-time update to that local state.

The eligibility result replaces the previously read global fallback status. If it is nonzero, the two operations and optional finalization are skipped. Conditional cleanup is considered, and the eligibility result is returned.

### 5. Two ordered operations

If the eligibility result is zero, F-6484a4b0a8c5 is called twice.

The first call receives:

- First input.
- The 32-bit operation operand.
- Selector 0.
- Address of the 80-byte buffer.
- Address of the shared 32-bit finalization request.

The second call receives:

- First input.
- The same operation-operand storage, read again for this call.
- Selector 255, hexadecimal 0xFF.
- Address of the 336-byte buffer.
- Address of the same finalization request.

Selector 255 is supplied as a positive integer value; the caller does not supply −1.

The second call occurs regardless of the first call’s returned status, provided the first call returns normally. The caller does not inspect the first result before making the second call.

The shared request is not reset between calls. Its value after the second call governs the subsequent decision. Thus, a request made by the first call can be preserved, altered, or cleared by the second call.

The caller does not inspect either output buffer after the calls.

### 6. Optional finalization

After both operations return, the function examines the low eight bits of the shared 32-bit request.

- If those bits are zero, F-22d5d80d8e4d is not called.
- If those bits are nonzero, F-22d5d80d8e4d is called with the first input.

Upper request bits do not independently trigger finalization. For example, a request value of 256 has a zero low byte and does not trigger this call.

When called, the finalization dependency’s result replaces the current return candidate. Otherwise, that candidate remains the zero result from eligibility checking.

Finalization is considered without regard to either operation’s returned status.

### 7. Conditional cleanup and return selection

The function tests the least significant bit of the 16-bit control field.

If that bit is set, it calls F-f09338a20fc0 with the 32-bit cleanup operand. The cleanup result is ignored.

On the two-operation path, this cleanup decision occurs after optional finalization but before either saved operation result is selected for return.

Return precedence on that path is:

1. First operation result, if nonzero.
2. Otherwise, second operation result, if nonzero.
3. Otherwise, finalization result, if finalization was called.
4. Otherwise, zero.

On paths that do not reach the operations, cleanup does not replace the selected preparation, global-fallback, or eligibility result.

## Side effects

2. Call the unmapped initialization dependency.
3. Write 0x0010 to the 16-bit control field.
4. Call preparation.
5. If preparation succeeded, read the global fallback status.
6. Then inspect the preparation discriminator.
