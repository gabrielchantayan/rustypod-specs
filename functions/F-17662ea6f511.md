# F-17662ea6f511

## Purpose

F-17662ea6f511 performs an ordered sequence of mixed-width memory updates, derives further addresses from memory, modifies fixed-address storage, and invokes an unresolved indirect dependency with four visible argument values.

The supplied representation establishes no application-level purpose. Printable constants and recurring offsets do not establish a text format, object type, collection, or serialization protocol. The observable contract is therefore expressed in terms of access widths, address relationships, snapshots, and access order.

This is a static, source-facing contract. It does not establish that the supplied representation accurately recovers the executable function boundary, calling convention, or individual machine transactions.

## Behavior

The following order describes the supplied memory accesses. Arithmetic-only derivations are explanatory relationships, not additional memory accesses. Aliasing is unrestricted; earlier writes can affect later reads.

### Entry effects and first selection

The entry effects occur in this order: the primary base is stored at first-input offset `0x54`; the seed is stored at second-input offset `0x14`; the second input’s low byte is stored at first-input offset `0x01`; and the seed store at second-input offset `0x14` is repeated.

Secondary-anchor offset `0x15` then receives the primary anchor’s low byte twice. First-input offset `0x15` receives the secondary anchor’s low byte. Both duplicate-store pairs belong to the visible trace.

Primary-anchor offset `0x54` next receives the fourth input. Secondary-anchor offset `0x34` receives the seed anchor. A word read from secondary-anchor offset `0x74`, doubled, establishes the **first discovered anchor**.

Seed-anchor offset `0x54` receives the seed anchor. Primary-anchor offset `0x15` receives the wide seed’s low byte. Seed offset `0x44`—relative to the original seed, not the seed anchor—receives the first discovered anchor.

A byte read at seed-anchor offset `0x05` supplies the **initial selector**. A word read at absolute address `initial selector + 0x74` establishes the **first selected address**. First-selected-address offset `0x44` receives the first discovered anchor.

### Interlinked updates and carrier selectors

Immediately afterward, primary-anchor offset `0x15` receives the seed anchor’s low byte. Seed-anchor offset `0x0D` receives the first selected address’s low byte, and seed-anchor offset `0x14` receives the seed anchor itself.

Primary-anchor offset `0x54` is then overwritten with the seed anchor. Only after that store is a word read at seed-anchor offset `0x64` to obtain another destination. That destination receives the first selected address’s low byte at offset `0x0D`, followed by its own complete address value at offset `0x14`.

A word read at primary-anchor offset `0x04` establishes the **selector carrier**. This read precedes the write of the first selected address’s low byte to first-discovered-anchor offset `0x09`. First-discovered-anchor offset `0x44` then receives the wide seed.

The **first carrier selector** is read as a byte at selector-carrier offset `0x05`. After this read, the following updates occur in order:

- Seed-anchor offset `0x09` receives the first discovered anchor’s low byte.
- First-selected-address offset `0x44` receives the first carrier selector as a zero-extended word.
- Primary-anchor offset `0x14` receives the wide seed.
- First-discovered-anchor offset `0x15` receives the selector carrier’s low byte.
- First-discovered-anchor offset `0x44` receives the primary anchor.

The first carrier selector does **not** initiate a low-address word lookup.

The byte at selector-carrier offset `0x05` is then read again, establishing the **second carrier selector**. Primary-anchor offset `0x15` receives the wide seed’s low byte **after this byte read but before** the ensuing word lookup. The word read at absolute address `second carrier selector + 0x74` establishes the **second selected value**. Twice that value is the **doubled selection**.

After the lookup, primary-anchor offset `0x15` receives the selector carrier’s low byte, and primary-anchor offset `0x54` receives the seed anchor. Seed-anchor offset `0x09` then receives the doubled selection’s low byte, before primary-anchor offset `0x14` receives the wide seed.

There are three distinct selector-byte reads: the initial selector selects the first selected address; the first carrier selector is stored as a word; the second carrier selector selects the second selected value. None may be substituted for another.

### Constants and repeated stores

The second selected value determines these ordered stores:

| Destination | Width | Value |
|---|---:|---:|
| Four times the second selected value | 8 bits | `0x3A` |
| Eight times the second selected value | 16 bits | `0x003A` |
| Four times the second selected value, plus `0x20` | 32 bits | `0x0000003A` |

Transfer-anchor offset `0x20` receives `0x20`, then `0x2F`. A byte is then read from transfer-anchor offset `0x04` and stored, zero-extended, as a word at transfer-anchor offset `0x20`. That destination subsequently receives `0x20` again.

The global address word is read to capture the global destination. A word store of `0x20` to absolute address `0x60` follows.

A finite repeated-store region then uses captured values without further visible memory-dependent reads. Its initial group performs these four accesses in order:

- Wide-seed offset `0x54` receives four times the second selected value.
- Global-destination offset `0x19` receives the transfer anchor’s low byte.
- Transfer-anchor offset `0x11` receives the global destination’s low byte.
- Global-destination offset `0x34` receives the wide seed.

Subsequent groups preserve that four-access ordering but replace the wide-seed destination and source with eight times the adjusted primary. The other destinations and values remain unchanged.

This region establishes repeated accesses, not collection traversal or a data-dependent loop. Its exact numeric repetition cardinality is **documented_only**, not a quantified acceptance requirement here. It must not be collapsed to final-state stores where repeated accesses are observable.

### Late snapshots and byte updates

After the repeated region, the operation captures a word from absolute address `0xA9`, then a word from offset `0x74` of four times the second selected value. These are the **fixed snapshot** and **selection snapshot**, respectively.

Absolute address `0x3A` then receives a byte derived from eight times the adjusted primary plus `0x30`. Its low-byte relationship does not establish digit encoding.

Next, a word from doubled-selection offset `0x14` becomes the **saved selection word**, followed by a word from transfer-anchor offset `0x04`, the **saved transfer word**.

Immediately after that latter read, these stores occur in order:

1. Doubled-selection offset `0x0D` receives the transfer anchor’s low byte.
2. Transfer-anchor offset `0x08` receives `0x6C`.
3. Transfer-anchor offset `0x0D` receives the global destination’s low byte.
4. Transfer-anchor offset `0x09` receives that same low byte.
5. Doubled-selection offset `0x54` receives the doubled selection itself.
6. Absolute address `0x67` receives the fixed snapshot’s low byte.

A word is then read from doubled-selection offset `0x44`; call it the **shift source**. Only afterward is address `0x67` read as a byte and its value stored at absolute address `0x21`. That fresh byte read cannot generally be replaced by the fixed snapshot’s low byte.

Transfer-anchor offset `0x10` receives the shift source’s low byte. Global-destination offset `0x54` receives the complete shift source. Doubled-selection offset `0x01` receives the low byte of a signed right-shift result, using the shift source as operand and the transfer anchor’s low eight bits as count. Counts of 32 or greater have no established portable result; right-shifting a negative signed operand also requires target-specific semantics.

Global-destination offset `0x54` is overwritten with the transfer anchor.

A word is read from transfer-anchor offset `0x40`. **Before that newly read word is stored**, global-destination offset `0x74` receives the saved transfer word. Transfer-anchor offset `0x10` then receives the word just read from offset `0x40`. This latter store overlaps the earlier bytes at offsets `0x10` and `0x11`.

Global-destination offset `0x44` receives the doubled selection. A fresh byte read from absolute address `0x67` supplies transfer-anchor offset `0x09`. Doubled-selection offset `0x09` receives the transfer anchor’s low byte. Transfer-anchor offset `0x44` receives the fixed snapshot.

### Final address chain and invocation

A word read at transfer-anchor offset `0x54` establishes the **late destination**. Another fresh read of absolute address `0x67` supplies a byte store at transfer-anchor offset `0x09`.

Late-destination offset `0x0D` receives the selection snapshot’s low byte. Doubled-selection offset `0x54` is restored from the saved selection word.

A word read at transfer-anchor offset `0x14` establishes the **late transfer snapshot**. Immediately afterward, doubled-selection offset `0x11` receives the selection snapshot’s low byte—not the late transfer snapshot’s byte.

Transfer-anchor offset `0x09` next receives the late destination’s low byte, and offset `0x44` receives the complete late destination.

A word read at doubled-selection offset `0x04` establishes the **chain base**. A halfword store of `0x0065` occurs at twice the chain base. A word read at chain-base offset `0x64` then establishes the **chain link**.

Only after that word read does late-destination offset `0x11` receive the late transfer snapshot’s low byte. Late-destination offset `0x54` immediately receives the word value 100.

A word read at chain-base offset `0x74` supplies the fourth invocation argument. Another word read, at doubled-selection offset `0x64`, establishes the **final destination**.

The chain base’s low byte is written to doubled-selection offset `0x09`. Final-destination offset `0x54` receives the chain link. A word store at twice the chain link receives the final destination.

The unresolved indirect dependency is then invoked with these visible argument values:

| Second | Chain link |
| Third | Saved selection word |
| Fourth | Word captured from chain-base offset `0x74` |

## Acceptance examples

These are conditional requirements, not executed tests. Arithmetic examples assume defined, representable intermediates and valid reached storage.

1. **Unsigned selection.** An initial or second carrier selector of `0xFE` causes its associated word lookup at absolute address `0x172`. Sign-extension to −2 is not equivalent.

2. **Different selector consumers.** If the first carrier selector is `0x12` and the second is `0x34`, first-selected-address offset `0x44` receives word value `0x12`; the later lookup occurs at `0xA8`. No lookup at `0x86` is attributable to the first carrier selector.

3. **Carrier-load ordering.** If the write to first-discovered-anchor offset `0x09` aliases bytes of primary-anchor offset `0x04`, the selector carrier still comes from the preceding word read. Moving that read after the byte write can change behavior.

4. **Lookup ordering.** If primary-anchor offset `0x15` overlaps the word selected by the second carrier selector, its intervening wide-seed byte store precedes that word read and can affect the selected value.

5. **Repeated visibility.** Observable storage at second-input offset `0x14` receives two seed writes. Observable storage at primary-anchor offset `0x54` receives the fourth input before the later seed-anchor writes.

6. **Late byte sequence.** Following the saved transfer-word read, the four byte stores target doubled-selection offset `0x0D`, then transfer-anchor offsets `0x08`, `0x0D`, and `0x09`. The self-address word store and fixed-address `0x67` store follow them.

7. **Overlapping snapshot stores.** If global-destination offset `0x74` overlaps transfer-anchor offset `0x10`, the saved transfer-word store occurs first. The subsequent store of the offset-`0x40` snapshot determines the overlapping bytes, subject to target byte encoding.

8. **Delayed late byte.** If late-destination offset `0x11` overlaps chain-base offset `0x64`, the chain-link read occurs before the late transfer snapshot’s byte is written there.

9. **Preserved invocation value.** Changes to doubled-selection offset `0x14` after the saved selection-word read do not change the third invocation argument.

10. **Fresh fixed-address reads.** If aliasing changes address `0x67` between accesses, later byte transfers use their own reads, not an assumed copy of the original fixed snapshot.

11. **Invalid access.** An inaccessible derived destination does not require successful completion, a particular error code, or restoration of earlier memory.
