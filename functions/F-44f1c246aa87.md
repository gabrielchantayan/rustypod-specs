# F-44f1c246aa87

## Purpose

F-44f1c246aa87 searches a pointer-linked structure, conditionally selects an existing node, and otherwise delegates creation or insertion to a dependency. It writes a node-sized result and a one-byte branch indicator to caller-provided storage.

The structure and traversal resemble an ordered tree with a header node. That interpretation is inferred intent, not a prerequisite for describing the observed operations. The established behavior is defined by field offsets, dependency results, and pointer comparisons.

The indicator distinguishes two paths:

- **0:** an existing candidate was returned without invoking the insertion dependency.
- **1:** the insertion dependency was invoked and its output word was returned.

An indicator of 1 does not independently establish that allocation or insertion succeeded. No success result from that dependency is checked.

## Interface

### Inputs

The function receives three arguments:

1. **Output address.** Writable storage for a four-byte result at offset `0x00` and a one-byte indicator at offset `0x04`.
2. **Container address.** A 32-bit address used as the base of the container layout described below.
3. **Request word.** An opaque four-byte value forwarded to dependencies. Its interpretation as a pointer, key, value, or descriptor is not established.

The supplied representation uses four-byte pointer fields and four-byte integer-sized values. The contract is therefore specific to that represented 32-bit layout; it does not establish a corresponding 64-bit layout.

There is no meaningful direct return value in the supplied evidence.

### Output layout

| Offset from output address | Width | Meaning |
|---|---:|---|
| `0x00` | 4 bytes | Existing candidate address, or the word supplied by the insertion dependency |
| `0x04` | 1 byte | 0 for existing-candidate return; 1 for insertion-dependency return |

The function does not explicitly write output bytes at offsets `0x05` through `0x07`. Callers must not assume those bytes are initialized or cleared.

On normal completion, the four-byte result is written before the indicator byte. The writes are separate, not an atomic result publication.

### Container fields

| Offset | Width or interpretation |
|---|---|
| `0x10` | Four-byte header pointer |
| `0x18` | One-byte mode field, tested for zero versus nonzero |
| `0x19` | Address passed as the first argument to the comparison dependency |

The size and contents of the comparison context beginning at `0x19` are unknown.

### Referenced-node fields

| Offset | Width or interpretation |
|---|---|
| `0x00` | One byte examined during predecessor-like adjustment |
| `0x04` | Four-byte link |
| `0x08` | Four-byte link |
| `0x0c` | Four-byte link |
| `0x10` | Address passed to the comparison dependency during search |

The header is also accessed at offsets `0x04` and `0x08`.

A conventional tree interpretation identifies the link at `0x04` as a parent or header-root link, `0x08` as a left link, and `0x0c` as a right link. The operational rules below do not depend on assigning those names.

### Preconditions

The output region must be writable. Every address dereferenced on the selected path must refer to readable storage of the required width.

The function performs no explicit validation of:

- The container address.
- The header pointer.
- Referenced links or payload addresses.
- Output capacity or alignment.
- Link consistency or absence of cycles.
- The request word.
- Dependency success.

The output region need not be dereferenced until late in execution, but invalid output storage can still fail after dependencies have already produced side effects.

## Behavior

### 1. Initial search

The function initializes its remembered comparison result to the nonzero value 1.

It obtains the initial search node through two pointer reads: the container’s header pointer at `0x10`, followed by the link at header offset `0x04`. It then separately reads the container’s header pointer again to initialize the remembered terminal node.

These are distinct header-pointer reads. The evidence does not establish synchronization or guarantee that they observe the same value under concurrent modification.

For each non-null search node:

1. Two four-byte scratch slots are cleared.
2. F-4a197a0807f0 is called with:
   - The container address plus `0x19`.
   - The request word.
   - The current node address plus `0x10`.
3. The current node becomes the remembered terminal node.
4. The comparison result selects the next link:
   - Zero selects the four-byte link at node offset `0x0c`.
   - Any nonzero result selects the four-byte link at node offset `0x08`.

Only zero versus nonzero matters. Negative and positive nonzero results have identical control-flow effects.

The next link is read after the comparison call. The function does not cache that link before invoking the dependency, so dependency changes to the node can affect traversal.

When a null link is reached, the remembered terminal node is the last visited node. If the initial link was null, it remains the separately read header pointer, and the remembered comparison result remains 1.

No bound or cycle detection limits this search.

### 2. Mode selection

After the search ends, the function reads the one-byte field at container offset `0x18`.

- A nonzero value skips existing-candidate checking and proceeds directly to the final insertion-dependency call.
- A zero value enables the candidate-selection path.

The mode is read after all search comparisons. It is not snapshotted before the search.

### 3. Candidate initialization and boundary decision

In zero mode, a mutable candidate cursor is initialized to the remembered terminal node.

If the remembered comparison result is zero, the function proceeds directly to candidate extraction and comparison.

If the remembered comparison result is nonzero, it first:

1. Reads the container’s header pointer again.
2. Reads the four-byte field at that header’s offset `0x08` into boundary scratch storage.
3. Calls F-ca7a1f20809e with the address of the candidate cursor and the address of that boundary storage.

Both arguments expose mutable local storage. The supplied function does not establish that the dependency leaves either value unchanged.

If F-ca7a1f20809e returns nonzero, the function immediately takes an insertion path:

- It calls F-c0987eb09f73 with an output-slot address, the container address, a four-byte zero argument, the remembered terminal node, and the request word.
- It copies the dependency’s four-byte output slot to the caller’s output at `0x00`.
- It writes indicator 1 at output offset `0x04`.
- It returns without extracting or comparing a candidate value.

The remembered terminal node passed to insertion is distinct from the mutable candidate cursor. A change to the cursor by F-ca7a1f20809e does not directly replace that insertion argument.

### 4. Candidate adjustment

If F-ca7a1f20809e returns zero, the function performs a predecessor-like adjustment on the candidate cursor as it exists after that call.

It first reads the candidate’s byte at offset `0x00`.

If that byte is zero, it additionally follows the candidate’s link at `0x04` and reads offset `0x04` from the resulting object. If that second link equals the candidate itself, the candidate becomes its own link at offset `0x0c`.

Otherwise, adjustment uses the candidate’s link at `0x08`:

- **Non-null link at `0x08`:** move to that node, then repeatedly follow links at `0x0c` until the currently selected node has a null link there.
- **Null link at `0x08`:** begin with the candidate’s link at `0x04`. Move the candidate upward through those `0x04` links while the upper node’s link at `0x08` equals the prior candidate. The first upper node for which that equality is false becomes the candidate.

No null check protects all parent-like dereferences in this adjustment. Correct sentinel and link relationships are therefore an input-structure requirement, not something enforced here.

The adjustment contains no callbacks. It also has no cycle detection.

### 5. Candidate extraction and duplicate-like decision

After candidate initialization or adjustment, the function clears another four-byte scratch field and calls F-386f5972e7a8 with the selected candidate address.

The dependency’s four-byte return value is then passed to F-4a197a0807f0 as follows:

1. Container address plus `0x19`.
2. The value returned by F-386f5972e7a8.
3. The original request word.

This argument order differs from the initial search comparisons. The search compares the request word against a node-relative address; the final check compares an extracted value against the request word.

If this final comparison returns zero:

- The candidate cursor’s value is written as the four-byte output result.
- Indicator 0 is written afterward.
- F-c0987eb09f73 is not called on this path.

The evidence establishes only this comparison outcome and path selection. Equivalence, duplicate detection, and ordering semantics depend on the comparison dependency and structural invariants.

### 6. Final insertion path

The function calls F-c0987eb09f73 when either:

- The mode byte is nonzero; or
- Zero mode reaches the final candidate comparison and that comparison returns nonzero.

Its arguments are:

1. Address of a four-byte output slot.
2. Container address.
3. Four-byte zero.
4. Remembered terminal node from the initial search.
5. Original request word.

After the call, the function copies the output slot’s four-byte contents to the caller’s result and writes indicator 1.

There is no retry, fallback, rollback, or explicit error conversion.

## Side effects

### Established local behavior

The function explicitly writes caller-visible storage only at the output result word and indicator byte. It does not directly assign container fields or node links.

Its direct structure accesses are reads. Dependency calls may have additional effects.

The output result write occurs only after the selected dependency work has completed. In an insertion path, dependency side effects therefore precede publication of the returned word.

### Dependency effects and ownership

The function delegates all creation or insertion work to F-c0987eb09f73. There is no direct allocation, release, destruction, or reference-count operation in the supplied body.

The evidence does not establish:

- Whether insertion allocates.
- Whether the request word transfers ownership.
- Whether an existing candidate is borrowed or retained.
- Whether any dependency releases memory.
- Whether dependencies preserve container fields, globals, or unrelated memory.
- Whether insertion failure is represented by a null output, another sentinel, an exception, or a non-returning failure.

No ownership guarantee should be inferred from indicator 0 or 1 alone.

### Scratch-slot initialization

The scratch slots supplied as insertion outputs are not uniformly initialized on every path.

Two slots are cleared during every initial-search iteration. An empty search performs none of those clears. The boundary-check path also loads one slot from header offset `0x08` and exposes it to F-ca7a1f20809e.

Consequently, the insertion dependency’s incoming output-slot contents depend on the path. This function does not guarantee a universal zero-initialized output parameter. If the dependency returns without defining the output word, the caller-visible result may contain residual scratch contents rather than a valid node.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, assume valid memory, terminating links, and dependencies that return normally without unrelated mutations.

1. **Search chooses offset `0x0c` on zero.**  
   Given a non-null current node, if the search comparison returns zero, the next search address is read from that node’s `0x0c` field. Its `0x08` field is not the selected next link.

2. **Any nonzero search result chooses offset `0x08`.**  
   Results such as 1 and a negative nonzero value select the same branch. Their signs do not alter traversal.

3. **Nonzero mode bypasses candidate processing.**  
   After search termination, a nonzero mode byte causes one insertion-dependency call. Neither boundary checking nor candidate extraction occurs afterward. The published indicator is 1.

4. **Boundary dependency requests immediate insertion.**  
   In zero mode with a nonzero remembered search result, a nonzero return from F-ca7a1f20809e causes insertion without candidate extraction. The insertion argument is the remembered terminal node, even if the boundary dependency changed the candidate cursor.

5. **Existing-candidate return.**  
   If candidate extraction completes and the final comparison returns zero, the candidate cursor is published with indicator 0. The insertion dependency is not invoked.

6. **Final comparison requests insertion.**  
   If the final comparison returns nonzero, insertion receives the original remembered terminal node, not necessarily the adjusted candidate. Its output word is published with indicator 1.

7. **Empty initial search.**  
   A null initial link leaves the remembered comparison nonzero and the remembered terminal node equal to the separately read header. With nonzero mode, insertion is called directly. With zero mode, boundary checking occurs first; successful handling of the header by later operations depends on undocumented dependency and sentinel contracts.

8. **Output width is preserved.**  
   On normal completion, the function writes four bytes at output offset `0x00` and one byte at `0x04`. Bytes beyond that indicator are not explicitly initialized by this function.
