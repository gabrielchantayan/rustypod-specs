# F-89863358a818

## Purpose

F-89863358a818 scans a byte-addressed region for zero-valued bytes, conditionally updates two fields in a caller-supplied record, and then invokes an unresolved indirect dependency using an address-like argument and an extent-like argument.

Under ordinary, non-overlapping memory conditions and a positive scan count:

- The first zero byte determines a stored starting offset, scaled by 512.
- The last zero byte determines a stored endpoint, also scaled by 512, with an additional value read from global storage.
- The indirect dependency receives the record’s base value plus the stored starting offset, followed by the stored endpoint minus the stored starting offset plus one.

The function does **not** establish that the resulting interval is valid. If no zero is found, the two offset fields retain their prior values and still participate in the indirect invocation.

Interpreting the operation as selecting an inclusive range is **inferred intent**. The established behavior is arithmetic on record fields followed by an indirect invocation; the meaning of the resulting arguments is unknown.

### Widths and representation

## Behavior

### Entry-state capture

The function first reads slot 3 and retains that value as its scan count.

The count is not explicitly refreshed from the record during either scan. A later change to slot 3 therefore does not change the locally captured count in the supplied representation.

### Forward scan and starting-offset update

The forward scan considers byte indices beginning at zero and increasing toward, but not including, the captured count.

For each reached index:

- The byte-region address comes from slot 4.
- The byte at that address plus the index is tested for zero.
- A nonzero byte advances the scan.
- The first zero byte ends the forward scan after slot 5 is assigned the index scaled by 512.

Only the first zero encountered by this scan triggers a starting-offset write. A zero at index zero assigns zero to slot 5.

If the captured count is zero or negative, the forward scan reads no bytes and does not write slot 5.

If the count is positive but every inspected byte is nonzero, slot 5 remains unchanged. There is no explicit “not found” value and no clearing of a previously stored offset.

### Reverse scan and endpoint update

After the forward scan, the function begins a reverse scan using the captured count, not the forward scan’s stopping index.

The reverse position is decremented before either the negative-position check or a byte read. Consequently, for a positive count, the first candidate is the byte at index count minus one.

For each candidate:

- If the decremented position is negative, reverse scanning ends without writing slot 6.
- Otherwise, the byte-region address is obtained from slot 4 and the candidate byte is tested.
- A nonzero byte causes another decrement and test.
- The first zero encountered in reverse order ends the scan and causes slot 6 to be assigned the endpoint baseline plus the index multiplied by 512.

For stable, non-overlapping byte storage, this selects the last zero within the scanned region. The reverse scan does not search beyond that region and does not require the zeros between the first and last matches to be contiguous.

If no zero is found, slot 6 retains its prior value.

For a count of zero, the reverse position becomes −1 and no byte is read. For an ordinary negative count, it becomes more negative and likewise reaches the final invocation without a byte read. The minimum representable signed count is exceptional because its decrement can overflow; its result is not established here.

### Final indirect invocation

Both scan outcomes converge on the same indirect invocation. There is no separate success or failure return path for a missing zero.

The invocation uses these argument expressions:

| Argument | Construction |
|---|---|
| First | Current slot 0 plus current slot 5 |
| Second | Current slot 6 minus current slot 5, plus one |

These expressions use the fields as they stand at invocation time:

- A field updated by a scan contributes its new value.
- A field not updated contributes its pre-existing value, unless some other permitted memory effect changed it.
- The body does not verify that the second expression is positive.
- The body does not verify that the first expression denotes a valid address.

The exact ordering of the final argument-field reads and dispatch-target read is not established by the supplied source representation. The contract therefore does not impose a left-to-right load order.

### Ordering and aliasing

The established phase order is:

1. Capture the scan count.
2. Perform the forward scan.
3. If a forward match exists, write slot 5.
4. Perform the reverse scan.
5. If a reverse match exists, write slot 6.
6. Invoke the indirect dependency.

This order matters if the byte region overlaps mutable record storage. In particular, the slot-5 write occurs before reverse scanning and can change bytes that the reverse scan later inspects.

Accordingly, “first zero” and “last zero” describe the same original byte sequence only when the relevant storage remains unchanged between observations. The supplied body does not create a snapshot or prohibit overlap.

These are logical access dependencies of the supplied representation, not a claim about the exact number or ordering of generated machine loads.

## Side effects

### Direct effects

The body can directly modify:

- Slot 5, once, if the forward scan finds a zero.
- Slot 6, once, if the reverse scan finds a zero.

It does not explicitly write either field when its corresponding scan finds no zero. It does not explicitly modify the count, base-value slot, or byte-region address slot.

The byte region is accessed through reads, but those bytes can nevertheless change through overlapping record writes.

### Indirect effects

The unresolved dependency is invoked once on every path that reaches the end of the body without an arithmetic, memory, or dispatch failure.

Its effects are unknown. In particular, the evidence does not establish that it:

- Preserves the record or global storage.
- Leaves the inspected bytes unchanged.
- Returns normally.
- Allocates or releases memory.
- Interprets either argument as a pointer, size, inclusive extent, or another quantity.

No allocation or deallocation is explicit in this function. Ownership transfer cannot be inferred from the indirect invocation.

### Errors and interruption

The body supplies no explicit error code, exception translation, diagnostic output, or recovery logic.

Invalid memory, invalid dispatch state, or invalid arithmetic can prevent completion. The supplied evidence does not establish the platform-specific manifestation of such failures.

Updates are not transactional. For example, a successful slot-5 write is not rolled back if a later reverse-scan read fails.

## Acceptance examples

The following are conditional acceptance cases derived from static inspection, not executed tests.

Unless a case states otherwise, assume stable non-overlapping storage, valid addresses and dispatch, representable arithmetic, and a dependency compatible with the recovered invocation.

### 1. Multiple separated zeros

Given:

- Scan count: 5.
- Bytes: nonzero, zero, nonzero, zero, nonzero.
- Base value: 1,000.
- Endpoint baseline: 7.

The expected direct updates are:

- Slot 5 becomes 512.
- Slot 6 becomes 1,543.

The indirect invocation receives 1,512 and 1,032.

Nonzero bytes between the two zeros do not prevent these updates.

### 2. A zero at the beginning and end

Given a count of 4 and zero bytes at indices 0 and 3:

- Slot 5 becomes zero.
- Slot 6 becomes the endpoint baseline plus 1,536.
- The first argument equals the base value.
- The second argument equals the endpoint baseline plus 1,537.

This case assumes all additions are representable.

### 3. Exactly one zero

Given a count of 3 and a sole zero at index 1:

- Both scans select index 1.
- Slot 5 becomes 512.
- Slot 6 becomes the endpoint baseline plus 512.
- The second argument is the endpoint baseline plus one.

A single selected byte therefore does not, by itself, establish a second argument of one. That result additionally requires a zero endpoint baseline.

### 4. No zero in a positive-length region

Given:

- Count: 3.
- All three bytes nonzero.
- Initial slot 5: 20.
- Initial slot 6: 30.
- Base value: 100.

Neither offset field is directly changed. The indirect invocation receives 120 and 11.

The implementation does not suppress the invocation merely because both searches failed.

### 5. Zero-length region

Given a count of zero, no byte-region access occurs in either scan.

If the initial offset fields are 20 and 30 and the base value is 100, the invocation again receives 120 and 11. The byte-region address need not be dereferenced by this body on this path.

### 6. Negative count without decrement overflow

Given a count of −1:

- The forward scan performs no byte reads.
- The reverse position becomes −2 and immediately exits.
- Both stored offset fields remain unchanged by the scans.
- The indirect invocation still occurs.

This example does not extend to the minimum representable signed count.

### 7. Pre-existing reversed endpoints

Given a no-match path with slot 5 equal to 100 and slot 6 equal to 50, the second argument expression produces −49 under signed arithmetic.

There is no explicit rejection or correction. Whether the destination accepts that value, or receives a converted representation, is unknown.
