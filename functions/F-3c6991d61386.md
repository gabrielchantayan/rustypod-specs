# F-3c6991d61386

## Purpose

The initialization includes **two ordered reads of the same global storage location**. The first value is retained for an addition used at object byte offset 28. The second value is written at object byte offset 0. The two values are not guaranteed to be equal.

The established contract concerns memory accesses, call ordering, branch conditions, and returned pointer identity. An object-construction or initialization role is inferred intent, not an established allocation, ownership, or lifetime guarantee.

### Two global reads and four ordered writes

The initialization sequence is:

1. Read the initialization global and retain that first four-byte integer value.
2. Read the same global again.
3. Write the second read’s value to object offset 0.
4. Add 220 to the retained first value and write the result to object offset 28.
5. Write the fourth argument to object offset 32.
6. Write zero to object offset 36.

The first read precedes the second, and both precede the offset-0 write. The four object writes occur in the order 0, 28, 32, then 36.

There is no intervening explicit dependency call between the two global reads. That fact does not justify replacing them with one observation or guaranteeing equal results. The representation contains two reads, and the destinations depend on them separately.

In particular:

- The offset-0 write does not use the retained first value.
- The offset-28 calculation does not use the second read’s value.
- The offset-28 calculation does not reread the initialization global.
- The offset-28 calculation does not read back the object’s offset-0 field.
