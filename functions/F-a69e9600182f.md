# F-a69e9600182f

## Purpose

F-a69e9600182f performs a bounded, binary-search-style lookup over an externally located record table. It compares a 32-bit field from the caller-supplied object with a 32-bit field from a selected table record, using dependency F-4a6c0bf0740c.

On an equality result, it returns the selected record’s first byte. If the search interval becomes empty, it returns the byte value zero.

The established behavior is a search driven by the sign of the dependency’s result. Interpreting that search as a correct lookup over sorted keys requires additional assumptions about table ordering and the dependency’s comparison semantics. Those assumptions are not established by this function alone.

A zero return is ambiguous: it can indicate an exhausted search or a matching record whose first byte is zero.

## Behavior

### Initialization

The function establishes an inclusive upper search address by obtaining the external table base and adding 152 bytes. It then establishes the lower search address from the external table base.

The supplied representation contains separate base references for these two initializations. It does not establish an atomic snapshot of the external base. Under the ordinary stable-base assumption, the resulting interval contains exactly the 20 records described above.

The function does not validate the relationship between the two initialized addresses, the allocation containing them, or the accessibility of the resulting interval.

### Empty-interval check

Before selecting a record on each iteration, the function compares the upper and lower search addresses.

If the upper address precedes the lower address, it returns zero immediately. For that iteration, it performs no input-field read, table-key read, or dependency call.

Address ordering follows the comparison represented in the supplied evidence. Behavior involving unrelated allocations, invalid addresses, or wrapped address calculations is not established as a portable contract.

### Candidate selection and arithmetic

For a nonempty interval, the function selects a candidate at an eight-byte record boundary, using the midpoint of the remaining inclusive interval and choosing the lower midpoint when there are two central records.

The represented calculation uses a signed integer address difference, a right shift by three bits, division by two, and multiplication by eight before adding the resulting byte offset to the lower search address.

Under the intended invariants—ordered bounds within the same table, an eight-byte stride, and representable address arithmetic—the distance is nonnegative and divisible by eight. The calculation therefore selects the record at the lower bound plus half the record-index distance, rounded down.

For the initial stable 20-record interval, the first candidate is record 9, at byte offset 72. It is not record 10.

These midpoint properties depend on representable arithmetic. The evidence does not justify treating signed overflow, address wraparound, or invalid pointer arithmetic as supported behavior.

### Comparison

For each selected candidate, the function obtains:

1. The four-byte field at input-object offset 4.
2. The four-byte field at candidate-record offset 4.

It passes those values to F-4a6c0bf0740c, with the input field as the first argument and the candidate field as the second.

Both values are obtained before that dependency invocation. Their relative read order is not established by the supplied call expression.

The input field is loaded for every comparison. It is not captured once for the entire lookup. Likewise, the candidate field is read when that candidate is examined; the function does not copy or snapshot the table.

The dependency’s result controls the next action:

- **Zero:** accept the current candidate.
- **Negative:** continue only below the current candidate, setting the inclusive upper address to eight bytes before it.
- **Positive:** continue only above the current candidate, setting the inclusive lower address to eight bytes after it.

Only the sign and zero/nonzero classification matter. No particular negative or positive magnitude is required.

### Match completion

After a zero comparison result, the function reads the byte at candidate offset 0 and returns it.

This byte read occurs after F-4a6c0bf0740c returns. The byte is not loaded in advance. Consequently, if the dependency changes that byte while leaving it readable, the returned value reflects the later read.

The function does not rescan the candidate’s key or reload the input field to validate the equality result.

### Search completion

After a nonzero comparison, the process repeats with the narrowed interval. If subsequent narrowing empties the interval, the function returns zero.

With a stable initial 20-record interval and ordinary representable address arithmetic, at most five comparisons occur. This bound follows from the interval reductions and does not require consistent comparison results, provided every invoked dependency call returns normally and execution continues with valid accesses.

The function stops at the first examined candidate for which the dependency returns zero. It does not seek the earliest or latest equal record, count duplicates, or check other records after a match.
