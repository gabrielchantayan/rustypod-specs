# F-539bdcd77108

## Purpose

F-539bdcd77108 conditionally delegates a record to an object-associated handler, then applies two fallback recognition rules if delegation does not produce a nonzero result.

Established behavior:

- Two record categories can qualify for initial delegation.
- A nonzero result from the delegated handler is returned unchanged.
- Fallback handling recognizes only category 0x13.
- Each successful fallback invokes an object-associated operation and returns 1.
- All remaining paths return 0.

Interpreting the record as an event, the object as a receiver, and the fallback operations as application actions is inferred intent. The category meanings and the semantic meanings of the object fields are not established.

## Behavior

### 1. Initial delegation qualification

The function first reads the category at record offset +0x04.

For category **0x0f**:

1. Read the record word at +0x08.
2. Read the object word at +0x1ac.
3. Qualify for delegation only if those words are equal.

A category 0x0f record that fails this comparison proceeds to fallback processing. It does not use the category 0x13 qualification rule.

For category **0x13**:

1. Read the record word at +0x0c.
2. Read the object word at +0x144.
3. Qualify for delegation only if those words are equal.

Every other category proceeds directly to fallback processing.

The two qualification rules are alternatives selected by category. Matching an object’s primary or secondary fallback target does not itself qualify a record for initial delegation.

### 2. Initial delegated call

If qualification succeeds, the function resolves the indirect target at table byte offset +0x15c from the object’s dispatch table and calls it with:

- the object reference;
- the record reference.

This dependency is labeled **F-D1** in this contract.

If F-D1 returns a nonzero 32-bit result, the function immediately returns that same result. No fallback category read or fallback action follows.

If F-D1 returns zero, execution continues into fallback processing.

No preservation guarantees for F-D1 are available. In particular, it must not be assumed to preserve the record, object fields, dispatch table, or external words. Fallback behavior therefore depends on the state subsequently read, not necessarily on the state that qualified the initial call.

### 3. Fallback category gate

At entry to fallback processing, the function reads the record category at +0x04 again.

If this newly read category is not 0x13, the function returns 0.

This is a fresh read, not reuse of the category captured before delegation. Consequently, a zero-returning F-D1 can affect fallback eligibility by changing the record category.

If the newly read category is 0x13, the function reads the record word at +0x0c. That captured word is used as the target value for both fallback rules. The function does not reread +0x0c between those rules.

### 4. Primary fallback rule

The captured target is compared with the object word at +0x44.

If the target differs, the primary rule fails without reading the record word at +0x08 for this rule and without reading G-A.

If the target matches:

1. Read the record word at +0x08.
2. Read the object word at +0x40.
3. Compare those two captured words.
4. If they differ, read G-A and compare the captured record value with G-A.

The primary rule succeeds if either:

- the record value equals the object value at +0x40; or
- the record value differs from that object value but equals G-A.

G-A is not read when the first comparison succeeds.

On success, the function resolves the indirect target at dispatch-table byte offset +0xd4 and calls it with the object reference. This dependency is labeled **F-D2**.

After F-D2 returns normally, the function returns 1. No result from F-D2 is inspected, and the secondary rule is not attempted.

### 5. Secondary fallback rule

This rule is evaluated only if the primary rule did not succeed.

First, read the object flag at +0x9c. If it is zero, return 0.

If the flag is nonzero, compare the captured target from record offset +0x0c with the object word at +0x98.

If those words differ, return 0. On that mismatch path, neither the record value at +0x08 nor G-B is read by the secondary rule.

If the targets match:

1. Read the record word at +0x08.
2. Read G-B.
3. Compare the two captured words.

If they differ, return 0.

If they match:

1. Call F-5710a8628cba with no explicit arguments.
2. Capture an 8-bit result from that call.
3. Resolve the indirect target at dispatch-table byte offset +0xa0.
4. Call that target with the object reference and the captured byte.

The latter indirect dependency is labeled **F-D3**.

After F-D3 returns normally, the function returns 1. F-D3’s result, if any, is not inspected.

The table used to resolve F-D3 is read after F-5710a8628cba returns. No assumption that the earlier call preserves that table is warranted.

## Acceptance examples

These examples are conditional static acceptance cases, not executed tests. Unless stated otherwise, dependencies return normally and do not mutate relevant state.

1. **Unrecognized category.**  
   The record category is neither 0x0f nor 0x13 and remains unchanged. No dependency is invoked. The result is 0.

2. **Category 0x0f delegation succeeds.**  
   The record word at +0x08 equals the object word at +0x1ac. F-D1 returns 7. The result is exactly 7, not normalized to 1. No fallback action occurs.

3. **Category 0x0f delegation declines.**  
   The same qualification holds, but F-D1 returns 0 and leaves the category as 0x0f. The fallback category read rejects it, and the result is 0.

4. **Category 0x13 delegation and fallback use different targets.**  
   The record target does not equal the object word at +0x144, but does equal the word at +0x44. The record value equals the object word at +0x40. F-D1 is not called; F-D2 is called; the result is 1.

5. **Primary alternate match.**  
   The fallback target matches +0x44. The record value differs from +0x40 but equals G-A. F-D2 is called, and the result is 1.

6. **Primary direct match avoids G-A.**  
   The fallback target matches +0x44 and the record value matches +0x40. G-A is not read. The primary action succeeds regardless of G-A’s stored value.

7. **Secondary success.**  
   The primary rule fails. The flag at +0x9c is nonzero, the target matches +0x98, and the record value equals G-B. F-5710a8628cba returns byte 0xa5. F-D3 receives that byte, and the function returns 1.

8. **Secondary disabled.**  
   The primary rule fails and the flag at +0x9c is zero. The secondary target comparison, G-B read, and both secondary dependencies are skipped. The result is 0.

9. **Primary precedence.**  
   Both fallback rules would otherwise match. Only F-D2 is invoked because primary success returns immediately.

10. **Delegation changes fallback eligibility.**  
    A category 0x0f record qualifies for F-D1. F-D1 changes the category to 0x13, supplies matching fallback fields, and returns 0. The subsequent fresh category read permits fallback handling.

11. **Delegation removes fallback eligibility.**  
    A category 0x13 record qualifies for F-D1. F-D1 changes the category to a value other than 0x13 and returns 0. The function returns 0 without invoking either fallback action.

12. **Auxiliary input independence.**  
    With identical accessible state and dependency behavior, changing only the auxiliary input does not change the selected calls or return value.
