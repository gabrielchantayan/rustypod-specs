# F-4cf587a7e13d

## Purpose

F-4cf587a7e13d conditionally invokes two dependencies and then clears one byte at an address derived from shared state and its two inputs. It returns a 32-bit zero on every path that reaches its return.

The established behavior is deliberately narrow:

- A zero first input suppresses both calls and the byte write.
- A second input equal to negative one also suppresses both calls and the byte write.
- Every other input pair proceeds through the same two calls, in a fixed order, followed by the byte write.

The address calculation has an eight-byte stride associated with the first input. This is consistent with an indexed storage arrangement, but the supplied evidence does not establish a table, record type, valid index range, or meaning for the cleared byte. Describing the operation as deletion, release, unregistering, or resetting an object would go beyond that evidence.

## Behavior

### Suppressed path

The active path is selected only when both conditions hold:

1. The first input is not zero.
2. The second input is not negative one.

If either condition fails, the function proceeds directly to its zero return. On this path, its body does not invoke either listed dependency, obtain the shared base for the destination, or perform the final byte store.

These are exact sentinel comparisons, not general validity checks. In particular:

- Negative first inputs other than zero are not rejected by the visible gate.
- Negative second inputs other than negative one are not rejected.
- A zero second input is accepted when the first input is nonzero.
- No visible upper bound is enforced for either input.

Those facts describe branch selection only. They do not establish that all branch-selected inputs are safe.

### Active path and ordering

For an input pair that passes the gate, the function performs the following externally relevant sequence:

1. Invoke F-91ecc91bc8aa with the original first and second inputs.
2. After that invocation returns normally, invoke F-adb9b73e2498 with the same original input values.
3. After the second invocation returns normally, obtain the shared base used for addressing and store a zero byte at the calculated destination.
4. Return a four-byte zero.

The second dependency is not called before the first one returns. The final byte write is not performed before the second one returns.

Neither dependency’s return value is used to select a branch, calculate the destination, or choose the explicit result. There is no visible success check between the calls or between the second call and the store.

This does not imply that dependency execution is irrelevant to the outcome. Either dependency can have effects not described by the supplied body. In particular, the contract must not assume that either preserves the shared base, preserves the destination allocation, or leaves the target byte unchanged.

The supplied representation places the shared-base use in the final store expression, after both calls. It does not show a base snapshot taken before the calls. Consequently, the destination must not be specified as necessarily relative to the base that existed at function entry.

For inputs and addresses whose arithmetic is well-defined, the function clears the byte at:

**shared base + 8 × first input + second input − 8.**

## Side effects

On the suppressed path, the body has no explicit data-memory write and no dependency call.

On the active path, effects comprise:

- All effects of F-91ecc91bc8aa.
- All effects of F-adb9b73e2498, invoked afterward.
- A final explicit one-byte zero store, if execution reaches a valid writable destination.

No ownership guarantee can be derived for the destination memory. A safe invocation requires the final destination to remain valid and writable when the store occurs, including after both dependencies have run. Having valid storage only at entry is insufficient if a dependency can invalidate it.

No synchronization or atomicity guarantee is established. The source-level one-byte store does not prove that the entire call sequence is atomic, that concurrent changes to shared state are excluded, or that concurrent readers observe the calls and write as a single operation.
