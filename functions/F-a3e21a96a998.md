# F-a3e21a96a998

## Purpose

F-a3e21a96a998 performs a mode-dependent sequence of operations on a mutable object, conditionally notifies a related object, and conditionally propagates flag changes through further calls.

The established behavior is the ordering of calls, field accesses, branch decisions, and bit updates described below. Names such as “object,” “related object,” and “embedded region” describe structural roles only. Lifecycle intent—such as activation, deactivation, detachment, or destruction—is not established.

The mode distinguishes zero from every nonzero 32-bit value. Values greater than one do not select a third overall path.

## Interface

### Inputs

- **Object address:** an address interpreted as the base of a mutable object with 32-bit fields and 32-bit address-bearing entries.
- **Mode:** an unsigned 32-bit integer.

The supplied representation uses four-byte integer elements and address-bearing values stored in those elements. This contract describes that 32-bit layout; it does not establish compatibility with a native 64-bit object layout.

### Output

The function has no explicit return value. Normal completion is either:

- an early return after the related-object notification stage; or
- a return after the final flag update.

There is no explicit status code, error object, or failure return.

### Relevant object layout

Offsets are byte offsets from the input object unless another base is specified.

| Offset | Width or interpretation | Observed use |
|---|---|---|
| `0x00` | 32-bit table address | Locates indirect call targets. |
| `0x34` | 32-bit address-bearing field | Related-object reference; read once for a cached decision and again later for a separate decision. |
| `0x3C` | 32-bit address-bearing field | Reference to an object whose field at `+0x78` is compared with the input object address. |
| `0x48` | 32-bit flag word | Tests bit `0x10`; may set bit `0x20`. |
| `0x80` | Embedded-region address | Passed as an argument, without establishing that region’s extent. |
| `0xA0` | Low byte of a 32-bit field | Later compared with zero. Upper bytes do not affect that comparison. |
| `0xF0` | 32-bit word | On the nonzero-mode path, bit `0x40` selects one of two embedded-region call sequences. |
| `0xF8` | 32-bit value | Supplied to an indirect call on the nonzero-mode path. |
| `0x1F4` | Embedded-region address | Passed to one of two call sequences. |
| `0x468` | Embedded-region address | Passed to a call on the zero-mode path. |

Other referenced layouts are:

- The object referenced by `+0x3C` has an address-bearing field at `+0x78`.
- The object referenced by `+0x34` may have a 32-bit flag word at `+0x48` and a dispatch-table address at its base.
- The address returned by the final indirect call must support a 32-bit flag read and write at `+0x48`.

These are accessed regions, not complete object-size declarations.

### Preconditions

There is no explicit null-pointer validation for the input object. All field accesses, embedded-region addresses, and selected indirect call targets must be valid when reached.

Conditional requirements include:

- A nonzero reference at input offset `0x3C` must support reading its field at `+0x78`.
- A nonzero cached reference from input offset `0x34` must support a flag read at `+0x48` if that read is needed.
- The final indirect call must return an address valid for a 32-bit read-modify-write at `+0x48`.

The function does not validate table contents, object lifetimes, alignment, or the result of the final indirect call. Called functions may impose additional unknown preconditions.

## Behavior

The following sequence applies when each reached dependency returns normally.

### 1. Select the initial sequence by mode

For **mode zero**:

1. Call F-936a8728139d with the address of the input object’s embedded region at `0x468`.

For **any nonzero mode**:

1. Call F-7a1c296974df with the input object address.
2. Invoke the input object’s indirect dependency at table byte offset `0x130`, passing the input object address and the 32-bit value obtained from input offset `0xF8`.
3. Invoke the input object’s indirect dependency at table byte offset `0x12C`, passing the input object address.
4. Call F-42382d1a1b3b with the input object address and the integer value `1`.

The dispatch-table references used by the two indirect calls are obtained at their respective call sites. The function does not establish that an earlier call preserves the input object’s table address or other fields.

The second argument to the `0x130` call is read after F-7a1c296974df returns. It is not an entry-time snapshot. The supplied representation does not independently establish the relative evaluation order of that argument read and the table lookup within the same call expression.

### 2. Process the embedded region at `0x1F4`

For mode zero, call F-936a8728139d with the embedded-region address at `0x1F4`. The field at `0xF0` is not needed for this branch decision.

For nonzero mode, read the 32-bit field at `0xF0` after the initial sequence completes:

- If bit `0x40` is clear, call F-936a8728139d with the embedded-region address at `0x1F4`.
- If bit `0x40` is set:
  1. Call F-6904f7699031 with the embedded-region address at `0x1F4` and a global datum.
  2. Call F-ec4cfa552cce with that same embedded-region address.

Other bits in the field at `0xF0` do not affect this selection. Although the supplied representation temporarily treats this field as address-shaped, this decision uses its numeric bit pattern and does not dereference it.

The global datum’s meaning and storage width are not established.

### 3. Perform an additional zero-mode check

Only for mode zero:

1. Call F-a1a48bd3fbde with the input object address.
2. If its integer result is nonzero:
   - invoke the input object’s indirect dependency at table byte offset `0x1C`, passing the input object address;
   - then call F-20460d1f31d3 with no explicit arguments.

A zero result skips both calls. Nonzero results are not otherwise distinguished.

Nonzero mode skips this entire stage, including the call to F-a1a48bd3fbde.

### 4. Capture related references and conditionally notify

After the preceding stages:

1. Read the address-bearing field at input offset `0x3C`.
2. Read and retain the address-bearing field at input offset `0x34`.
3. If the first reference is nonzero, read its field at `+0x78`.
4. If that field equals the input object address, call F-df6da5bd408b with:
   - the reference obtained from input offset `0x3C`; and
   - `1` for mode zero, otherwise `0`.

The second argument is exactly the indicator for mode being zero. It is not an unbounded subtraction result: all nonzero modes, including values above one, produce zero.

If the reference from `0x3C` is zero, its `+0x78` field is not read. If that field does not equal the input object address, F-df6da5bd408b is not called.

The reference captured from `0x34` is retained across this possible call. Later decisions therefore distinguish between this cached reference and a fresh read of the same input field.

### 5. Decide whether to return early

After the optional F-df6da5bd408b call, inspect the input object’s 32-bit flags at `0x48`.

- If bit `0x10` is set, continue to the propagation stage without reading the cached related object’s flag word.
- If bit `0x10` is clear:
  - return immediately if the cached reference from `0x34` is zero;
  - otherwise read that cached object’s 32-bit flags at `+0x48`;
  - return immediately if its bit `0x10` is clear;
  - continue if that bit is set.

Thus continuation requires bit `0x10` on either the input object or the object identified by the cached reference.

The cached reference predates the optional notification call, but its flag contents are read afterward. If that call changes input offset `0x34`, the early-return decision still uses the old reference. If it changes the old referenced object’s flags, the later flag read can observe that change.

### 6. Mark and propagate

If the early return is not taken:

1. Read the input object’s flags at `0x48`, OR them with `0x20`, and write the resulting 32-bit word back.
2. Call F-6d16652f2d03 with:
   - the input object address; and
   - the embedded-region address at input offset `0x80`.

This direct flag write preserves all other bits from the value used by the read-modify-write. It does not establish that a later dependency preserves those bits or leaves `0x20` set.

### 7. Conditionally invoke the current related object

After F-6d16652f2d03 returns:

1. Read input offset `0x34` again.
2. If it is zero, skip this indirect call and do not evaluate the low-byte condition.
3. If it is nonzero, examine the low byte of the 32-bit field at input offset `0xA0`.
4. If that byte is zero, invoke the dependency located through the current related object’s table at byte offset `0x128`.

This call has **no explicit arguments in the supplied representation**. The contract does not infer a receiver argument merely because the target is selected through a related object.

Only the low byte controls this condition. For example, a word value of `0x00000100` satisfies the zero-byte condition, whereas `0x00000101` does not.

The related object used here need not be the object captured earlier from `0x34`. F-6d16652f2d03 or another preceding dependency may have changed that field.

### 8. Mark the final returned object

Finally:

1. Invoke the input object’s indirect dependency at table byte offset `0x5C`, passing the input object address.
2. Treat its return value as an object address.
3. Read the 32-bit flags at that address plus `0x48`.
4. OR those flags with `0x40` and write the result back.

There is no explicit null check before this final read-modify-write. No subsequent call appears before normal return.

## Side effects

The directly established writes are conditional:

- Input flags at `0x48` receive bit `0x20` when the propagation stage is reached.
- Flags at `+0x48` of the final returned object receive bit `0x40` when the final stage completes.

All other mutation, allocation, release, registration, notification, or external effects are dependency-defined and unknown.

The function passes object and embedded-region addresses to dependencies. It contains no explicit allocation or release operation of its own. This does **not** establish that dependencies retain no addresses, release no storage, or preserve object lifetimes.

There is no rollback path. Earlier calls and writes occur before later calls. If a dependency does not return normally, the supplied representation establishes no recovery behavior.

The flag updates are ordinary read-modify-write operations in the supplied representation. Atomicity, synchronization, and concurrent-use safety are not established.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. They require valid storage and normally returning dependencies.

1. **Zero mode with no propagation qualification.**  
   F-936a8728139d is called first for `0x468`, then for `0x1F4`. F-a1a48bd3fbde is called. If it returns zero, the two additional zero-mode calls are skipped. If the later propagation gate fails, neither direct flag write occurs.

2. **Nonzero mode with bit `0x40` clear at `0xF0`.**  
   The initial four-call sequence occurs in the specified order. F-936a8728139d then receives the region at `0x1F4`. F-a1a48bd3fbde is not called.

3. **Nonzero mode with bit `0x40` set at `0xF0`.**  
   After the initial sequence, F-6904f7699031 and F-ec4cfa552cce occur in that order. This stage does not call F-936a8728139d.

4. **Modes `1`, `2`, and `0xFFFFFFFF` with a qualifying back-reference.**  
   Each passes zero as the second argument to F-df6da5bd408b. Mode zero instead passes one.

5. **Input flags already contain `0x10`.**  
   The propagation gate succeeds even if the cached reference from `0x34` is zero. That gate does not read a related object’s flags.

6. **Only cached related flags contain `0x10`.**  
   If input bit `0x10` is clear, the cached reference is nonzero, and its flags contain `0x10`, propagation proceeds. An input flag value of `0x04` becomes `0x24` at the direct write, before subsequent dependency effects.

7. **The related reference changes during propagation.**  
   If F-6d16652f2d03 replaces input offset `0x34`, the optional `0x128` dispatch uses the current reference, not the earlier cached one.

8. **Final returned flags contain `0x81`.**  
   The final direct write produces `0xC1`. The returned object may alias the input object or another referenced object; the function does not prohibit either case.
