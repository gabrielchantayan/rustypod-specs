# F-ed9f0758543c

## Purpose

F-ed9f0758543c mutates selected 32-bit fields, invokes F-d2e511bc1037 with its final two inputs exchanged and negated, conditionally performs another field assignment, and finally negates one field in the object selected at entry.

The established behavior is an ordered sequence of accesses and a dependency invocation. Domain meanings for the objects, fields, mode byte, and numeric inputs are not established. A sign-convention or coordinate-system adaptation is plausible intent, not a behavioral guarantee.

The operation is not generally reversible. Three or four fields are negated before the dependency, but only one receives an unconditional post-call negation. That final negation uses the field’s then-current value; it need not restore its entry value.

The conditional assignment has an important distinction: its destination address and source-field address involve separate evaluations of the primary object’s pointer field. The source does not establish one cached conditional-object pointer.

## Behavior

### Selection and pre-call changes

The wrapper first reads primary offset `0x38` and retains that address for all selected-object operations in this invocation.

It then performs the following selected-object field changes in order:

1. Negates the 32-bit value at offset `0x04` and writes the result there.
2. Negates the 32-bit value at offset `0x0C` and writes the result there.
3. Negates the 32-bit value at offset `0x14` and writes the result there.
4. If the second input is greater than two under signed comparison, negates the 32-bit value at offset `0x1C` and writes the result there.

Each field’s value is read before its replacement is written. No atomic read-modify-write guarantee is established.

The threshold is strict. Negative second inputs, zero, one, and two do not activate the fourth mutation. No local check establishes that this input represents a dimension, count, or enumeration.

After all applicable pre-call field changes, the wrapper reads and retains the mode byte at primary offset `0x5A`. This is not necessarily the byte’s entry value: earlier writes could affect it through aliasing.

### Post-call condition

If the dependency returns normally, the saved mode byte controls the next accesses:

- If the saved byte was zero, the wrapper skips the conditional assignment without reading the current mode byte.
- If the saved byte was nonzero, the wrapper reads primary offset `0x5A` again.
- If that current byte is nonzero, it skips the conditional assignment.
- If the saved byte was nonzero and the current byte is zero, it performs the conditional assignment described below.

This is a nonzero-to-zero observation across the call, not a test for any mode-byte change. Different nonzero values do not qualify. A zero-to-nonzero change does not qualify and does not cause the post-call mode-byte read.

### Conditional assignment and address evaluation

When the condition succeeds, the wrapper assigns a negated 32-bit source value to a 32-bit destination field. Both fields are located at offset `0x14`, but their bases arise from separate source-level evaluations of primary offset `0x5C`:

- One evaluation supplies the base used to locate the destination.
- Another evaluation supplies the base used to locate the source field whose value is negated.

Neither base is saved before the dependency call. These evaluations belong to the post-call conditional assignment.

The relative evaluation order of the destination-address calculation and the source-side calculation is unspecified by the supplied expression. Consequently, the contract does not require the destination-related pointer evaluation to occur first, or the source-related evaluation to occur first. The source value must be obtained, and the destination must be determined, before the assignment’s store.

This establishes two source-level pointer-field evaluations, **not exactly two executable memory loads**. The supplied evidence does not settle compiler load reuse, generated instruction counts, or the observation semantics of externally changing storage.

If primary offset `0x5C` remains stable throughout the assignment, both roles designate the same object, and the operation negates that object’s offset-`0x14` field in place. Without a suitable stability guarantee, the source does not justify describing the assignment as a single-object read-modify-write.

If a valid execution model permits the two evaluations to produce different addresses, the stored value is the negation of the conditional source field, written to the conditional destination field. It is not necessarily the negation of the destination field’s previous value. This observation does not establish that unsynchronized concurrent changes are valid.

### Final selected-object change

After conditional processing, the wrapper negates and writes back the 32-bit field at offset `0x04` of the originally selected object.

It does not reload primary offset `0x38`. A dependency change to that pointer field does not redirect the final operation.

The final negation uses the field value present at that time. Dependency writes or intervening alias effects may have changed it. Restoration of the entry value therefore requires additional preservation assumptions.

The wrapper then returns without a result value.
