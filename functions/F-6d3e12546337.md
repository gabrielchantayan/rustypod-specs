## Behavior

### Capture and aliasing rules

A captured value remains the value read at its specified capture point. A later read of the same field is a new observation, not permission to reuse the earlier value.

The principal roles are:

- **Primary:** read from second input `+0x74`.
- **Target:** read from third input plus the ambient address-like input.
- **Companion:** read from third input `+0x14`.
- **Child:** a later read from primary `+0x14`.
- **Central:** a subsequent, independent read from primary `+0x14`.
- **Child-linked record:** read from child `+0x74`.
- **Hub:** read later from child-linked record `+0x14`.

### Terminal effects and transfer

Three late fixed-storage words are read at separate capture points. The **first late value** is read from `0x087FC9C0` before central `+0x74` is read.

That central-field read establishes the **terminal link** and its retained low halfword. The terminal effects then occur in this order:

1. Write the retained halfword at terminal link plus central.
2. Write first late value’s low halfword at twice final nested.
3. Read a signed byte at surrounding link plus central; sign-extend it and convert it to unsigned 32-bit form.
4. Write terminal link’s retained halfword at first late value plus terminal link.
5. Repeat the halfword write at terminal link plus central.
6. Write word `0x45` at the unsigned byte-derived value plus `0x45`.
7. Read the **second late value** from `0x087FC9DC`, then the **late payload** from `0x087FC9C8`, then central `+0x44`.
8. Write byte `0x44` at the unsigned byte-derived value plus `0x44`.
9. Write late payload at twice second late value.
10. Write second late value’s low halfword at retained link plus second late value.

F-UNRESOLVED-01 then receives, in argument order: the unsigned byte-derived value bitwise-ORed with `0x44`; second late value; and the captured central-`+0x44` word. The first argument uses OR, not addition.

## Acceptance examples

These are conditional static expectations, not executed tests.

- **Initial overlap:** absent other aliasing writes, second input `+0x45` receives the fourth input byte after the halfword store. The adjacent byte’s value depends on byte order and the original halfword.
- **Child installation:** primary `+0x74` is captured before primary `+0x09` is written. If that byte destination overlaps child `+0x54`, the subsequent word write still uses the captured child-install value.
- **Linked-read ordering:** before the primary `+0x11` write following child byte `0x79`, the relevant reads are child `+0x74` and then child-linked record `+0x54`. Child-linked record `+0x74` is read substantially later.
- **Hub-byte provenance:** hub `+0x11` receives the child-install value’s low byte before the fresh hub `+0x14` read used for the linked `+0x15` byte. If the hub byte write changes that field through aliasing, the fresh read observes the changed memory.
- **Nested capture:** if nested `+0x54` overlaps nested `+0x74`, the early nested link is captured before the self-link write changes that memory.
- **Traversal captures:** if destination `+0x20` overlaps central `+0x64`, the first traversal capture precedes the `0x73` word store; the second follows it and may differ.
- **Central capture:** if installed link `+0x09` overlaps central `+0x54`, the saved central word is read before that byte write, but after central `+0x14` receives installed link.
- **Late fixed-storage alias:** the first terminal halfword write cannot retroactively change the already captured first late value, even if its destination overlaps that fixed-storage word.
- **Negative terminal byte:** signed byte `−1` becomes unsigned `0xFFFFFFFF`; OR with `0x44` remains `0xFFFFFFFF`. Its unsigned `+0x45` and `+0x44` expressions reduce to `0x44` and `0x43`, respectively, before address conversion.
- **Address-like payload:** displaced link minus `0x20` must support a word write. The payload displaced link minus `0x74` is not dereferenced by that operation.
