# F-5da1ad7278c2

## Purpose

F-5da1ad7278c2 conditionally prepares an input, waits for a nonzero readiness byte, and delivers an eight-bit value to another dependency.

The established behavior has three gates:

1. A zero first argument prevents all dependency calls and readiness-state access.
2. A zero result from the preparation dependency prevents polling and delivery.
3. Following a nonzero preparation result, delivery occurs only after the readiness byte is observed to be nonzero.

The delivered value is the low eight bits of a writable 32-bit value initialized from the fourth argument. The preparation dependency can change that value before it is narrowed.

Interpreting the readiness byte as a device-ready indicator, the polling dependency as a delay or scheduler operation, or the delivery dependency as an output operation is **inferred intent**, not established behavior. No such interpretation is required by this contract.

## Behavior

### 1. Zero-input exit

The first observable decision is whether the first argument equals zero.

If it is zero, the function returns without:

- Calling F-f864d4b0c549.
- Reading the readiness-base slot.
- Reading the readiness byte.
- Calling the polling dependency.
- Calling F-b4c8a64376c1.

The second, third, and fourth arguments do not alter this exit.

### 2. Preparation and base capture

For a nonzero first argument, the function initializes a writable 32-bit temporary with the fourth argument.

It then calls F-f864d4b0c549 with:

1. The first argument, unchanged.
2. The address of that temporary.

The address permits the dependency to modify the temporary during the call. This function does not establish whether the dependency actually writes it, how many writes occur, or what other state the dependency affects.

After the dependency returns, the function reads the readiness-base slot and captures its value. This read occurs before the preparation result is used to decide whether polling should proceed.

Consequently, even a zero preparation result does **not** avoid the readiness-base-slot read. It does avoid the later byte reads and delivery call.

The captured base is the value present after the preparation dependency returns. A base-slot change performed by that dependency can therefore affect which byte is subsequently polled.

### 3. Preparation-result gate

The dependency result is tested only for equality with zero.

- A zero result causes normal return after the base-slot read.
- Any nonzero result permits the readiness wait and eventual delivery.

No ordering, sign, magnitude, or named status-code interpretation is applied to this result. A negative nonzero result, if representable by the dependency interface, is accepted by this gate just as a positive nonzero result is.

### 4. Eight-bit value selection

On the nonzero-result path, the function takes the temporary’s low eight bits by applying a mask of 255.

The resulting value is in the inclusive range 0 through 255. This is bit selection, not saturation, range validation, signed conversion, or rejection of out-of-range inputs.

The temporary is sampled for this calculation after F-f864d4b0c549 returns and before the first readiness-byte test. Thus:

- A modification made by that dependency affects the selected value.
- If the dependency leaves the temporary unchanged, the fourth argument supplies the selected bits.
- The selected value is not recalculated during the polling loop.

For example, a temporary value of 0x123456AB selects 171. A temporary value of 0xFFFFFFFF selects 255.

The mask itself cannot overflow a 32-bit unsigned value. No arithmetic using the second or third argument occurs.

### 5. Readiness wait

The function tests the byte at offset two from the captured base.

If the byte is nonzero on the first test, it proceeds directly to delivery without calling the polling dependency.

If the byte is zero, the function calls the polling dependency with the numeric arguments zero and one. If that call returns, the readiness byte is tested again at the same captured base and offset.

This cycle continues for as long as successive readiness observations are zero.

Established properties of this wait are:

- Each zero observation is followed by one polling-dependency call before the next test.
- Readiness is determined solely by zero versus nonzero.
- No particular nonzero bit pattern is required.
- There is no explicit retry count or time limit.
- The readiness-base slot is not explicitly reloaded inside the loop.
- The selected delivery value is not explicitly recomputed inside the loop.

Changing the readiness-base slot during polling does not redirect this invocation’s explicit byte accesses. Changing the byte at the captured address can affect the next readiness test.

The supplied byte type’s signedness does not change the zero/nonzero decision: every nonzero eight-bit representation passes this gate.

### 6. Delivery and return

After observing a nonzero readiness byte, the function calls F-b4c8a64376c1 with:

1. The previously selected value, numerically between 0 and 255.
2. Zero.

There is one explicit delivery call on this path. No further readiness check, retry, or result-dependent branch follows it.

If the delivery dependency returns normally, this function returns normally. Any result produced by that dependency is not used by the visible function.

## Acceptance examples

These examples are conditional specifications, not executed tests. Dependency behavior and memory validity are assumed only where explicitly stated.

### Zero first argument

Given a zero first argument and arbitrary remaining arguments, the function returns without dependency calls or readiness-state reads.

An implementation that reads the readiness-base slot before this exit would not match the represented ordering.

### Preparation returns zero

Given a nonzero first argument, if F-f864d4b0c549 returns zero normally, the function reads the readiness-base slot and then returns.

It must not test the byte at offset two, call the polling dependency, or invoke F-b4c8a64376c1 on this path.

### Ready immediately after preparation

Suppose preparation returns nonzero and leaves the temporary equal to 0x123456AB. Suppose the captured readiness byte is valid and initially nonzero.

The function performs no polling-dependency call and invokes F-b4c8a64376c1 with 171 and zero.

### Preparation changes both relevant inputs

Suppose preparation changes the temporary from the fourth argument’s value to 0x00000102 and updates the readiness-base slot before returning nonzero.

The function captures the updated base and selects the value 2. If that base’s offset-two byte is nonzero when tested, delivery receives 2 and zero.

### Two unsuccessful readiness observations

Suppose preparation returns nonzero and readiness tests observe zero, zero, then a nonzero byte. Suppose both intervening polling calls return normally.

The visible order is the first zero observation, one polling call, the second zero observation, one polling call, the nonzero observation, and then one delivery call.

### Base slot changes during waiting

Suppose the polling dependency changes the readiness-base slot but the byte at the originally captured address remains zero.

The slot change alone does not redirect the wait. If every subsequent read at the captured address remains zero and polling calls continue to return, the function continues waiting and does not deliver.

### Nonzero result without positive-result semantics

Suppose preparation returns a negative nonzero result. Provided the remaining state is valid, the function follows the same readiness and delivery path as for any other nonzero result.

Treating that result as failure solely because it is negative would add behavior not present in the evidence.
