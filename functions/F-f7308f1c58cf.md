# F-f7308f1c58cf

## Purpose

F-f7308f1c58cf dispatches a 32-bit selector and mode against a wrapper, optionally publishes a 32-bit result, and returns a 32-bit completion indicator.

Established behavior includes initialization, availability gating, scalar retrieval, conversion, text-related composition, reference-like publication, and count processing. Initialization and availability processing occur even when subsequent dispatch rejects the request.

“Value,” “Metadata,” “Reference,” and “text” are descriptive roles inferred from use, not established external API meanings. Dependency behavior is unknown beyond the visible calls, arguments, and use of results.

## Behavior

### Initialization and availability

First save the shared-base global as the **entry base**. Independently read that global again to inspect bit zero of the 32-bit word at base `+4`.

If the bit is clear, read the shared-base global again and call F-b255b26284e6 with that base `+4`. A nonzero result triggers, in order:

1. F-5b24edfb22c0 with entry base `+0x2c`.
2. F-804adc29bbfb with the preceding return word and two global words obtained after that call returns.
3. F-d08d3ca17b81 with entry base `+4`.

The relative evaluation order of the two global arguments is not established. A set initialization bit or zero acquisition result skips the remaining initialization calls. Changes to the shared-base global do not replace the saved entry base.

Next call F-342742914355 with wrapper `+0x18`. After its return, save the current Value-mode word, then the current reference-output word. Both reads precede availability rejection. Later dispatch comparisons read mode globals afresh; common completion uses the saved Value word.

Nonzero availability admits dispatch. Zero availability performs two separate comparisons against Metadata:

- If the first comparison fails, establish a 32-bit intermediate equal to selector minus `0x7800`.
- The second comparison rejects only when it fails and the intermediate is not `1`.

With stable Metadata, this admits Metadata mode or selector `0x7801`, and otherwise returns zero without a direct output write.

If the first comparison succeeds but the second fails, the intermediate was not assigned by this gate. The supplied representation instead exposes an incoming machine word: `1` permits dispatch; another value rejects. Its origin and validity remain **documented_only**, not an ordinary selector exception.

### Common completion

Successful branches converge after their branch-specific writes and cleanup:

1. Read wrapper byte `+0x25`.
2. If nonzero, compare the supplied mode with the saved post-availability Value word.
3. If equal, read the current output word and write that word plus one modulo \(2^{32}\).
4. Return `1`.

The increment uses current output contents, including dependency mutations after the branch’s initial write. Reference-like and text-related words are not exempt. A Zero branch can also be incremented if Zero and the saved Value word coincide.

### Count and special paths

## Acceptance examples

These are conditional static expectations, not executed tests. Numeric selectors must reach their named cases. Unless varied, relevant globals remain stable, modes are distinct, and dependencies do not mutate output or flags.

1. **Availability rejection:** Zero availability, non-Metadata mode, and selector other than `0x7801` return zero without a direct output write, after initialization and snapshot processing.

2. **Saved initialization base:** Entry base is A; acquisition changes the shared-base global to B. Construction still receives A `+0x2c`; initialization completion receives A `+4`.

3. **Metadata read before Reference:** Upper B, `0x782d`, or `0x7837` reaches Reference. After Zero and Value fail, read the metadata-result global before comparing Metadata, resolving, or invoking the Reference method.

4. **Metadata read before rejection:** The same three paths receive an unsupported mode. Each still reads its metadata-result word after Zero and Value fail, then rejects.

5. **Count read boundary and collision:** For `0x781c`, mode matches Value and Metadata but not Zero. Read metadata before comparing Value, then retrieve the count rather than publish metadata. An unsupported non-Zero mode also causes that read before rejection.

6. **Special-path collision:** For `0x7819` or `0x781a`, mode matches Value and Reference but not Zero. Execute both Value calls and publish the second result; do not take Reference’s zero-result alternative.

7. **Reference ordering:** `0x7812` Reference stores method `0x208`’s result at entry base `+8`, then writes the saved reference-output word, despite intervening global changes.

8. **Repeated query:** Boundary A’s first F-1862b8feb88c result is nonzero, but its second result is zero. Publish zero, then clean the temporary; do not reuse the first result.

9. **Text reload:** Assignment uses shared-text address A and changes its global to B. Without another change, final representation uses B.

10. **Count adjustments and wrap:** `0x781c` retrieves `4`, both wrapper flags are nonzero, and completion mode matches: write `5`, then `6`. With retrieved count `0xffffffff`, write zero after the first adjustment, then `1` at completion.

11. **Enumeration:** `0x7822` retrieves `3`: process indices `0`, `1`, `2`, then write the saved count `3`. A zero count performs no element calls.

12. **Completion snapshot:** Saved Value is X; dispatch later reads Y. A mode matching Y selects Value behavior but does not trigger completion increment when X differs.

13. **Mode-independent representation:** An admitted `0x7801` request accepts an otherwise unsupported mode, writes its representation result, and completes.
