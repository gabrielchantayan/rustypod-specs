# F-27e49f66c358

## Purpose

F-27e49f66c358 updates a destination record using a 32-bit input value. It always stores the input’s lower 16 bits at one destination location. It stores the input’s upper 16 bits at another destination location only when a 16-bit field in a separate, potentially overlapping record equals 8.

The ordering is significant: the unconditional destination write occurs before the condition field is read. If the two records overlap, that first write can change the condition used to decide whether the second write occurs.

This contract describes the supplied static evidence. It does not establish the broader meaning of either record, the reason for the condition value, or whether the two destination fields represent one logical value.

## Interface

The function accepts three inputs:

| Input | Interpretation | Required use |
|---|---|---|
| First input | Address-bearing value identifying the record containing the condition field | A 16-bit field is read at byte offset `0x6C` |
| Second input | Address-bearing value identifying the destination record | A 16-bit field is written at byte offset `0x1A`; another may be written at byte offset `0x14` |
| Third input | A 32-bit value whose bit pattern supplies the destination data | Its lower and upper 16-bit portions are used independently |

The function has no return value. Its observable result is the memory modification described below.

## Behavior

### Unconditional destination update

The first record access shown is a 16-bit write at destination offset `0x1A`.

The stored bit pattern is the lower 16 bits of the third input. The input’s upper 16 bits have no effect on this write. The previous contents of this destination field are replaced without being read.

For example, an input bit pattern of `0x1234ABCD` produces the 16-bit destination pattern `0xABCD` at this location.

The operation is a field write, not a demonstrated read-modify-write of a larger record word.

### Condition evaluation

After the unconditional write, the function reads the 16-bit field at offset `0x6C` from the first input address.

The conditional update is selected only when the value read is exactly 8. Values such as 0, 7, 9, or a value merely containing the bit associated with 8 do not satisfy the condition.

The supplied type identifies this field as a signed 16-bit quantity. Because the comparison is against the positive value 8, the accepted ordinary 16-bit representation is `0x0008`; signedness does not expand the set of accepted values.

The function does not take a snapshot of the condition before writing the lower portion. Consequently, the relevant condition is the value available at the time of this read.

### Conditional destination update

If the condition equals 8, the function writes the input’s upper 16-bit pattern to destination offset `0x14`.

Extraction is unsigned: an input with its highest bit set still supplies its upper half without arithmetic sign extension. For an input bit pattern of `0xFEDC1234`, this write stores `0xFEDC`.

If the condition does not equal 8, no write to destination offset `0x14` is shown. Its previous contents are retained by this function, unless they were affected through some overlapping address relationship.

In either case, the function then returns without a result value.

### Access order and overlap

For valid execution, the function-level access order is:

1. Write the lower input portion to destination offset `0x1A`.
2. Read the condition at first-record offset `0x6C`.
3. Only if that read yields 8, write the upper input portion to destination offset `0x14`.

No non-overlap requirement is expressed in the supplied body.

If the condition field is the same two-byte location as the unconditional destination field, the condition observes the newly stored lower portion. Under that address relationship, the conditional write occurs precisely when that lower portion represents 8.

If the condition field instead coincides with the conditional destination field, its old value determines whether it is replaced by the upper portion. The function does not reread it after replacement.

Partial overlap can also make the first write affect the condition. The resulting numeric condition then depends on the exact overlapping bytes and the target’s byte order. No target-independent numeric result is specified for such a case.

Additional ordering and boundary cases:

- **Exact equality:** With a condition of 9, only the lower field is updated. Sharing a set bit with 8 does not satisfy the condition.
- **Unconditional replacement:** Even when the condition is not 8, the lower field receives the input’s lower portion.
- **Condition overlaps the lower field:** If both identify the same two-byte location and the input is `0x24680008`, the first write stores 8 there. The subsequent condition succeeds, and the upper field receives `0x2468`, regardless of the condition location’s earlier contents.
- **Overlapping condition becomes false:** With the same overlap and input `0x24680009`, the condition reads 9. The upper field is not written.
- **Condition overlaps the upper field:** If that shared field initially contains 8 and the input is `0x13572468`, it is replaced by `0x1357`. The function does not reevaluate the condition afterward.
- **Conditional address validity:** When the condition is not 8, the supplied body does not access the upper field. When it is 8, a valid write to that field is required.
