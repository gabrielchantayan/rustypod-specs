# F-87ea3af356b2

## Purpose

F-87ea3af356b2 destructively relinks reachable records into a chain whose head is stored in a separate control record. Each processed record’s four-byte field at offset 12 becomes its chain link.

The operation processes a record’s offset-12 link recursively, inserts that record at the current head, and then continues through the record’s offset-8 link. Both the continuation link and the head are read after the recursive call returns.

For a finite, nonoverlapping binary tree, interpreting offset 8 as the left-child link and offset 12 as the right-child link, the transformation places the tree records in left–root–right order along their offset-12 links. The last record in that order receives the **original head value** in its offset-12 field, provided the control head storage does not overlap the tree records and no external modification occurs.

That final stored value does not establish preservation of an original destination chain. If the original head identifies a processed record, that record’s link may have been overwritten. Preservation of an existing chain requires the additional condition that its link storage remains unaffected by every write.

The binary-tree interpretation is inferred intent. The established operation is the ordered mutation described below; the function does not validate a tree or a destination chain.

## Behavior

### Empty input

An initial record address of zero causes an immediate return without a recursive call or memory access through either input address.

The control head is neither read nor changed.

### Ordered processing of a nonzero record

Each nonzero current record undergoes the following observable sequence:

1. Its four-byte offset-12 value is read and supplied to a recursive invocation of F-87ea3af356b2, using the same control address.
2. The recursive invocation completes before the caller performs its remaining field accesses.
3. The caller reads the current record’s four-byte offset-8 value and retains it as its continuation.
4. The caller reads the four-byte head at control offset 4.
5. That head value is written into the current record’s offset-12 field.
6. The current record’s address is written into the control head field.
7. Processing continues with the retained continuation. A zero continuation ends this invocation.

The order has several consequences:

- Neither the continuation nor the head is saved before recursion.
- Recursive mutations can affect both values subsequently read by the caller.
- The continuation is retained before either insertion write.
- The record link is replaced before the control head is replaced.
- Changing the storage from which the continuation was read does not retroactively change the already-retained continuation.

The recursive call is made even when the offset-12 value is zero. Such a call returns without accessing fields.

### Result for a finite, disjoint tree

Assume:

- Reachable records form a finite binary tree without shared records.
- Offset 8 denotes the left child and offset 12 the right child.
- Record storage does not overlap other record storage or the control head field.
- No external agent changes relevant memory.
- All accesses and recursive calls complete normally.

Under these conditions, records are inserted in right-subtree, root, left-subtree order. Because each insertion prepends, the final offset-12 links place the processed records in left-subtree, root, right-subtree order.

For a nonempty tree:

- The control head becomes the first record in left–root–right order.
- Every processed record except the last points to its successor in that order.
- The last record’s offset-12 field contains the original control head value.
- Offset-8 fields remain unchanged.
- Original offset-12 child links are replaced, so the original tree representation is not preserved.

These statements describe the processed-record sequence and its final stored link value. They do **not** guarantee that following links beyond that sequence reaches an unchanged preexisting chain or terminates.

### Existing-head value versus existing-chain preservation

The initial head is not traversed merely because it is the head. During insertion it is used as a stored value. It may be zero, identify valid storage, identify a processed record, or identify inaccessible storage.

If the initial head identifies a processed record, the final link can return to the processed sequence and create a cycle. This is consistent with storing the original head value.

Preservation of a preexisting offset-12 chain requires additional assumptions:

- Its links initially describe the chain being claimed.
- All of its offset-12 link storage remains unaffected by writes to processed records and the control head.
- No external agent modifies those links during the operation.

Complete separation of that chain from the processed records and control storage is a sufficient condition. Under those conditions, the newly arranged records lead to the unchanged old chain. Without them, only the stored original-head value is guaranteed by the tree result.

### Aliasing and repeated reachability

Outside the disjoint-tree conditions, behavior follows the ordered accesses rather than a fixed traversal of the original graph.

Overlapping storage can cause a write to one logical field to alter another logical field. In particular:

- Recursive processing can change the caller’s continuation before it is read.
- An insertion write can change fields that future iterations or recursive calls will read.
- Control-head writes can also change record fields when their storage overlaps.

There is no visited-record set or duplicate suppression. A record reached more than once is processed using its contents at the time of each access. Its offset-12 field may already contain an inserted chain link rather than its original recursive link.

Consequently, shared records and cycles may cause repeated insertion, altered traversal, nontermination, or access failure. The function provides no once-only guarantee for a general graph.

### Termination

An invocation finishes when its current record becomes zero, after all recursive calls it has made have returned.

There is no explicit recursion limit, iteration limit, or cycle detection. A cyclic recursive path may prevent any insertion on that path and exhaust stack resources. A cyclic continuation path may prevent iterative completion. For mixed or aliased structures, termination depends on the actual mutations and subsequent reads, not just the initial links.

## Side effects

### Direct memory writes

Each completed insertion performs two four-byte writes, in this order:

1. The current head value into the current record’s offset-12 field.
2. The current record’s address into the control head field.

Recursive invocations perform the same operations. No other direct write destinations are visible. Aliasing can make these writes affect additional logical fields.

### Ownership and lifetime

No allocation, release, reference counting, or ownership-transfer protocol is visible. The operation reuses existing storage and address values.

The source does not establish:

- Who owns the records or control storage.
- Who may release them afterward.
- Whether replacing a link discards an externally defined ownership obligation.
- Whether the resulting structure is expected to be acyclic.

Required storage must remain valid for every access reached. The absence of a release operation does not establish any broader ownership contract.

### Partial progress and errors

The transformation is not transactional.

A recursive portion can be fully modified before the caller reads its own continuation. An insertion also has an intermediate state in which the record’s offset-12 field has changed but the control head has not yet been updated.

No rollback or explicit error handling is present. If execution fails or does not terminate, earlier mutations may remain. The exact outcome of invalid access or stack exhaustion is execution-environment dependent.

### Concurrency

No locking, atomic operations, barriers, or synchronization protocol is shown. The source-level operation order does not establish atomic publication or a cross-thread consistency guarantee.

Concurrent observation or modification requires an external contract. In its absence, the single-execution access order is the only behavior established here.

### Resource use

Offset-12 processing introduces recursive invocations. Offset-8 continuation occurs iteratively within the current invocation.

An offset-8-only path does not accumulate one active recursive invocation for each continuation edge. A nonzero offset-12 path can accumulate nested invocations. Exact stack consumption and exhaustion behavior are unknown.

## Acceptance examples

These are conditional expectations derived statically, not executed tests. Unless an example states otherwise, storage is accessible and disjoint, relevant memory is not concurrently modified, and execution completes normally. Letters identify distinct nonzero record addresses.

### 1. Empty input

Given an initial record address of zero:

- No memory is read or written through either input.
- No recursive call occurs.
- The control address need not identify accessible storage for this invocation.

### 2. Single record with an arbitrary head value

Given record **A** with both links zero and initial head value **H**:

- The final head is **A**.
- **A**’s offset-12 field contains **H**.
- **A**’s offset-8 field remains zero.
- **H** is not dereferenced.

The result establishes the link value **A → H**. It does not, by itself, establish that **H** begins a valid or unchanged chain.

### 3. Root with two children

Given root **B**, left child **A**, right child **C**, and zero links in both children:

- Insertion order is **C**, **B**, **A**.
- The final head is **A**.
- Offset-12 links become **A → B → C → H**, where **H** is the original head value.
- Offset-8 fields remain unchanged.

If **H** identifies a separate chain whose link storage is unaffected by all writes, that chain remains intact after **C**. Otherwise, the final stored value **H** makes no preservation claim about its target.

### 4. Offset-8-only path

Given offset-8 links **C → B → A → zero**, with all offset-12 links zero:

- Insertion order is **C**, **B**, **A**.
- The resulting offset-12 links are **A → B → C → H**.
- Each zero recursive input returns before the next continuation is processed.
- The continuation edges do not accumulate recursive nesting.

### 5. Offset-12-only path

Given offset-12 links **A → B → C → zero**, with all offset-8 links zero:

- Recursive descent reaches **C** before any insertion.
- Insertion order is **C**, **B**, **A**.
- The resulting offset-12 links are **A → B → C → H**.
- The nonzero recursive path requires nested invocations.

### 6. Head storage aliases the continuation field

Given record **A** whose offset-8 field occupies the same storage as the control head, with that shared field initially zero and **A**’s offset-12 field zero:

- The continuation is retained as zero.
- The head read for insertion is zero.
- **A**’s offset-12 field becomes zero.
- The shared head/offset-8 field becomes **A**.
- The invocation terminates using the retained zero continuation.

Thus, offset-8 preservation requires absence of overlapping write destinations.

### 7. Original head identifies the single processed record

Given **A** with both links zero and initial head **A**, with control storage separate from **A**:

- The final head is **A**.
- **A**’s offset-12 field becomes **A**.
- The invocation completes.
- Following the resulting link repeats **A** indefinitely.

Before the call, the destination beginning at **A** had link **A → zero**. That chain is not preserved, despite the input being a finite, single-record tree. The established terminal write stores the original head value **A**.

### 8. Original head identifies a processed interior record

Use the three-record tree from example 3, but set the original head to **B**:

- The final head is **A**.
- Links become **A → B → C → B**.
- Subsequent traversal alternates between **B** and **C** after reaching them.

The tree transformation completes, but it does not produce a null-terminated chain. No overlap between distinct tree records is needed for this result; overlap between the destination chain and processed records is sufficient.
