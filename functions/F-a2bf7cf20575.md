# F-a2bf7cf20575

## Purpose

F-a2bf7cf20575 classifies a descriptor against shared state, then handles its effective 16-bit selector.

Established behavior includes:

- Rejecting ineligible or mismatched descriptors with response status 7.
- Recognizing an optional two-byte control payload for selector 0.
- Accumulating numeric contributions and handling acceptance or retries for selector 3.
- Decoding and storing a 32-bit result for selector 5.
- Responding with status 5 for other eligible selectors.
- Either returning 32-bit zero or reaching a cleanup dependency marked non-returning.

The numeric constants suggest capability negotiation. That interpretation is inferred intent, not a required application-domain meaning.

This contract distinguishes individual shared-state pointer reads. It does not assume that repeated reads select the same object, or that dependencies preserve globals, fields, payloads, or ownership.

## Interface

### Inputs and representation

The function receives a context address and a descriptor address in a 32-bit address model.

Descriptor fields are read as 32-bit words:

| Byte offset | Meaning established here |
|---|---|
| +0 | Associated-object address |
| +8 | Payload address |
| +12 | Payload length; only its low 16 bits are retained |
| +16 | Selector; only its low 16 bits are retained |

The word at +4 is not explicitly accessed by this function. Dependencies receiving the descriptor may access additional fields.

The associated object supplies a 32-bit identity at +8.

The context supplies opaque 32-bit handles at +0x2D0 and +0x2D4. Each explicitly described handle read occurs separately; entry and exit operations need not receive identical values if intervening effects change the context.

A global shared-state pointer provides access to:

| Byte offset | Observed field |
|---|---|
| +1 | Eight-bit retry counter |
| +4 | Expected 32-bit identity |
| +8 | Expected associated-object address |
| +0x10 | Stored 32-bit accumulator |
| +0x2C | Opaque coordination target |
| +0x30 | Opaque coordination target |
| +0x34 | Stored 32-bit decoded value |

A separate global comparison pivot is used in signed 32-bit comparisons during selector-3 processing. Its value and stability are not supplied.

### Results and preconditions

Every explicit ordinary return is 32-bit zero. Response statuses are dependency arguments, not return values.

Cleanup calls F-09ba55c206ac with the descriptor, then F-feee9156a257. The latter is marked non-returning. The evidence does not establish whether it exits a process, terminates a thread, throws, or uses another mechanism.

The descriptor must permit the specified word reads, and its associated object must permit the identity read at +8. These accesses precede any descriptor-null comparison. Null descriptor input is therefore not protected by the later cleanup check.

Context and state addresses must support the accesses selected by control flow. Payload requirements differ:

- Selector 0 explicitly reads up to two bytes, under the guards described below.
- Selector 5 calls the decoder only for a non-null payload with effective length 4.
- Selector 3 has no explicit payload-null check.

The decoder’s access width, alignment requirements, and treatment of invalid addresses are unknown. Four-byte entry spacing and a 32-bit result do not establish four-byte memory reads.

## Behavior

### Entry, eligibility, and state snapshots

The observable entry sequence is:

1. Read the associated-object address from the descriptor.
2. Read and narrow the selector to 16 bits.
3. Read the associated object’s identity at +8.
4. Obtain an environment address through F-unmapped-01.
5. Call F-62d1a359629f with that address advanced by four bytes and the identity.
6. Read the shared-state global pointer and retain an **entry snapshot**.
7. Read the descriptor’s payload address and effective 16-bit length.

The entry snapshot is retained for selector 0 and selector 5. It is not the pointer used implicitly for all subsequent eligibility reads.

Eligibility is evaluated in this order:

- Test result bit 0x400 from F-62d1a359629f.
- If set, read the shared-state global pointer afresh and read its +8 field. Compare that address with the previously read associated-object address.
- Only if those addresses match, read the shared-state global pointer afresh again and read its +4 field. Compare it with the previously read identity.

The two comparison fields can therefore belong to different objects, and neither is necessarily in the object selected by the entry snapshot.

If any check fails, call F-09b5d9827724 with the descriptor, original associated-object address, zero, 10, 1, and status 7. Then call F-256e8a77aa59 with the descriptor and zero, and return zero.

### Selector 0: conditional action followed by cleanup

The control action requires a non-null payload, effective length exactly 2, first byte zero, and second byte 4.

The first byte is read only after the non-null and length checks succeed. The second byte is read only after the first byte matches.

For a match:

1. Read context +0x2D4 and call coordination-entry dependency F-unmapped-02.
2. Obtain an execution token through F-unmapped-03.
3. Read +0x30 through the entry snapshot and pass that target, together with the token, to F-23aadb16b673.
4. Read context +0x2D4 again and call coordination-exit dependency F-unmapped-04.

The target read occurs after token acquisition. It does not reload the shared-state global pointer.

Matching, nonmatching, null, and wrong-length payloads all proceed to common cleanup. Selector 0 sends no explicit response through F-09b5d9827724.

### Selector 3: initial coordination

Before evaluating the parsing loop:

1. Read context +0x2D0 and invoke F-unmapped-02.
2. Obtain a token through F-unmapped-03.
3. Read the shared-state global pointer afresh, then its +0x2C target, and call F-23aadb16b673 with the token and target.
4. Read context +0x2D0 again and invoke F-unmapped-04.

The accumulator starts at unsigned 32-bit zero.

### Selector 3: iteration and pointer capture

The entry offset starts at zero. At **every loop-condition evaluation**, the function reads and captures the shared-state global pointer before comparing the offset with the effective length.

This includes:

- The initial evaluation, even for zero length.
- Evaluations between recognized entries.
- The terminating evaluation of a normally completed parse.

For each iteration, F-c25a2fcc75b5 receives the payload address advanced by the current offset. Its low 32-bit result is interpreted as a signed 32-bit integer for recognition.

After a recognized entry, the offset increases by four, then bit 16 is cleared. Starting from zero, this produces offsets 0, 4, …, 65532, then zero again.

Consequences:

- Length zero makes no decoder call.
- Lengths 1–3 make one decoder call.
- A length not divisible by four permits a decoder call with fewer than four declared bytes remaining.
- Lengths through 65532 terminate after finitely many recognized entries.
- Lengths 65533–65535 wrap the offset to zero rather than terminating. If recognition continues and dependencies return, parsing repeats.

The declared length does not bound the decoder’s actual memory accesses. Whether any call reads beyond the declared payload is documented_only.

### Selector 3: recognition and arithmetic

Each decoded entry uses separately observable pivot reads:

1. Read the pivot and compare it for equality with the decoded signed value.
2. If equal, add 0x10. No ordering comparison is required.
3. If unequal, read the pivot again and test whether this second value is less than the decoded signed value.

When the second pivot is less than the decoded value, recognize only:

| Decoded value | Contribution |
|---|---|
| 24000 | 0x20 |
| 32000 | 0x40 |
| 44100 | 0x80 |
| 48000 | 0x100 |

Otherwise, recognize only:

| Decoded value | Contribution |
|---|---|
| 8000 | 1 |
| 11025 | 2 |
| 12000 | 4 |
| 16000 | 8 |

An unmatched value immediately enters failure handling.

The final branch is “second pivot is not less than the decoded value,” not unconditionally “decoded value is less than the pivot.” The second pivot can equal the decoded value even though equality with the first pivot failed.

Decoder calls may change the pivot between entries. No supplied stability guarantee makes the two reads within one entry equal either. A fixed recognized-value set cannot be asserted without additional assumptions.

Contributions are added using unsigned 32-bit arithmetic, modulo \(2^{32}\). They are not combined by bitwise union. Duplicate entries can carry into other bits.

### Selector 3: acceptance

After normal loop termination, acceptance requires all bits in 0x1C0 to be set in the accumulated numeric result.

On acceptance, in order:

1. Read the shared-state global pointer afresh and store the full accumulator at +0x10 through that pointer.
2. Clear the retry byte at +1 through the pointer captured by the terminating loop-condition evaluation.
3. Prepare a temporary 12-byte record.
4. Call F-c6c589453fa8 with 10, zero, the record address, and length 12.
5. Enter common cleanup.

The accumulator store and retry clear are not guaranteed to address the same object.

The record layout is:

| Byte range | Established contents |
|---|---|
| +0 | Byte value 1 |
| +1 through +3 | Not established as initialized |
| +4 through +7 | 32-bit zero |
| +8 through +11 | 32-bit zero |

The record must not be represented as fully initialized or fully zeroed.

### Selector 3: failure and retry handling

An unrecognized entry or a completed parse lacking the required mask enters the same failure path.

The state-access sequence is:

1. Read the shared-state global pointer and retain a **failure snapshot**.
2. Read the global pointer again and read the retry byte at +1 through that fresh pointer.
3. Increment the byte value and narrow the result to eight bits.
4. Read the global pointer again and write the incremented byte at +1 through that fresh pointer.

Thus the read, initial write, and captured failure target are not necessarily the same object.

If the incremented byte is below 4:

1. Call F-09b5d9827724 with the descriptor, original associated-object address, zero, 10, 1, and status 4.
2. Read context +0x2D0 and invoke F-unmapped-02.
3. Call F-256e8a77aa59 with the descriptor and zero.
4. Obtain a token, then read +0x2C through the failure snapshot and call F-23aadb16b673.
5. Obtain another token, then read +0x2C through the same failure snapshot again and call F-8becc2a0337c.
6. Read context +0x2D0 again and invoke F-unmapped-04.
7. Return zero.

The two target-field reads can yield different values despite using the same captured pointer.

If the incremented byte is at least 4, write zero at +1 through the failure snapshot, then enter common cleanup. No status-4 retry response is explicitly sent.

The increment is eight-bit wrapping arithmetic: 255 becomes zero and takes the below-4 response path. On the terminal branch, the value written through the failure snapshot is established as zero; it is not an independently observable decoder-status byte.

### Selector 5 and other selectors

For selector 5, a non-null payload and effective length exactly 4 cause one call to F-c25a2fcc75b5. Store its low 32-bit result at +0x34 through the entry snapshot, then select response status 0.

The store uses the entry snapshot even if the decoder changes the shared-state global pointer. It occurs after the decoder returns.

A null payload or any other effective length selects status 4 without decoding or performing that store.

Every other eligible selector selects status 5.

These paths call F-09b5d9827724 with the descriptor, original associated-object address, zero, 10, 1, and the selected status; then call F-256e8a77aa59 with the descriptor and zero and return zero.

The response paths also assign a separate local three-word area containing the effective selector, zero, and 0xFF. Its address is not explicitly passed to either dependency. Those assignments do not establish an external response layout.

### Common cleanup

Cleanup checks whether the descriptor address is null. If so, it returns zero. This does not make null entry input valid because earlier descriptor reads are unconditional.

For a non-null descriptor, cleanup calls F-09ba55c206ac, followed by F-feee9156a257. Under the supplied non-return annotation, this path has no ordinary return.

## Side effects

Explicit persistent writes are limited to shared-state fields:

- +0x10: accepted selector-3 accumulator, using a fresh global-pointer read.
- +1: selector-3 retry updates, using the distinct pointers specified above.
- +0x34: selector-5 decoded result, using the entry snapshot.

No stable-object, atomicity, locking, or memory-ordering guarantee follows from these accesses. The paired coordination calls suggest synchronization intent but do not establish a synchronization contract.

Dependency effects are unknown unless stated. In particular:

- Descriptor or payload release, retention, transfer, or continued validity is not established.
- Passing the descriptor to F-256e8a77aa59 does not prove that subsequent coordination is safe under an ownership model supplied elsewhere.
- Passing temporary storage to F-c6c589453fa8 does not establish whether it copies or retains that storage.
- Capturing a pointer preserves the address used by later explicit accesses; it does not freeze the pointed-to fields or guarantee object lifetime.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Eligibility denied:** With result bit 0x400 clear, the entry snapshot and payload fields are still read. The +8 and +4 eligibility fields are not read. Status 7 precedes F-256e8a77aa59 and a zero return.

2. **Narrowing:** Selector word 0x00010005 selects operation 5. Length word 0x00010004 supplies effective length 4.

3. **Control payload:** Eligible selector 0 with bytes zero and 4 and effective length 2 performs the +0x2D4 coordination sequence before cleanup. A mismatch skips that sequence but still reaches cleanup.

4. **Decoder changes the global pointer:** For valid selector 5, if the decoder returns low bits 0x12345678 while changing the shared-state global pointer, the store still targets entry-snapshot +0x34. Status 0 follows the store.

5. **Empty capability payload:** Selector 3 with effective length zero performs initial coordination and one loop-condition pointer capture, but no decoding. The zero accumulator fails acceptance. If the failure-path retry read yields zero, the incremented value is 1 and the retry-response path is taken.

6. **Conditional capability acceptance:** If 32000, 44100, and 48000 each fail equality against their respective first pivot reads and exceed their respective second pivot reads, they contribute 0x40, 0x80, and 0x100. With length 12, their sum 0x1C0 passes acceptance. No common pivot value is required.

7. **Duplicate contributions:** Seven decoded values of 32000 contribute 0x1C0 if each independently reaches its 0x40 match. With length 28, acceptance does not require distinct input values.

8. **Changing pivot within one entry:** For decoded value 8000, a first pivot read of 9000 fails equality. A second read of 8000 makes the ordering test false, so the lower table recognizes 8000 and contributes 1.

9. **Split acceptance writes:** If the terminating condition captures one state object and the acceptance-store global read selects another, +0x10 is written in the latter and +1 is cleared in the former.

10. **Retry boundaries:** A failure-path retry read of 3 produces an initial write of 4, followed by a zero write through the failure snapshot and cleanup. A read of 255 produces zero and takes the retry-response path.

11. **Short declared payload:** Selector 3 with effective length 1 calls the decoder once at the payload base. This establishes neither the number of bytes accessed nor an actual overread.
