# F-2829a6e7231a

## Purpose

F-2829a6e7231a searches a byte-addressed sequence for a position accepted by an external comparison dependency. Search begins at the requested displacement when that displacement is positive, and at displacement zero otherwise. Success returns the accepted position’s byte displacement from the initially captured sequence address. Ordinary search failure returns −1.

The established behavior is dependency-driven, not an independently specified substring comparison. A candidate must have a nonzero current byte and satisfy a numerical eligibility condition before the comparison dependency is consulted. A zero comparison result accepts that candidate.

**Inferred intent:** searching for a substring in a zero-terminated byte string. The available material does not establish that either dependency implements conventional string operations. This contract therefore does not promise ordinary substring-search semantics, including unconditional success for an empty search operand.

### Conditions for a defined execution

The address slot must be readable for the initial 32-bit load. A null slot address is not handled as a search failure. By contrast, a readable slot containing a null sequence address is explicitly supported and produces −1.

A finite zero-terminated region is a sufficient traversal boundary under stable-memory assumptions, but it is not established as an enforced input format. Absence of a reachable zero byte can expose further memory reads or arithmetic limits.

## Behavior

### Captured-address semantics

The sequence address is captured through one initial 32-bit slot read. The function does not visibly read the slot again.

A null captured address produces −1 without either dependency being called and without a sequence-byte read. The requested starting position does not change this outcome.

For a nonnull address, subsequent traversal remains based on that captured value. A dependency-side replacement of the slot contents does not redirect the search. Modification or invalidation of the storage reached through the captured address can nevertheless affect subsequent execution.

### Dependency measurements

Before this function performs its own sequence-byte traversal, it obtains two results from F-cd6a6ecb5056:

| Invocation order | Argument | Use of returned value |
|---|---|---|
| First | Search operand | Retained as an unsigned comparison extent |
| Second | Captured original sequence address | Retained as a signed sequence measure |

Both invocations occur on a normally progressing nonnull-address path, even when the requested starting position will later prove unreachable. If an invocation faults or does not return, later activity is not guaranteed.

Neither result is checked for an error indication or verified against accessible memory. The term “measure” describes subsequent numerical use; it does not establish a length contract.

These calls are ordered observations, not a snapshot operation. Effects of the first invocation may be visible to the second. Effects of either invocation may be visible during later byte traversal. The returned values are retained; comparison calls do not cause them to be recomputed.

### Starting-position rules

A positive requested position excludes all earlier positions from comparison. To reach it, the function reads each byte that must be passed and requires that byte to be nonzero.

Encountering zero before reaching the requested position produces −1, with no comparison at that byte. The initial traversal does not use either measurement result as a bound.

Zero and negative requested positions require no initial traversal. Both begin candidate consideration at displacement zero. Negative requests are neither rejected nor interpreted as backward indexing.

Landing at a position does not itself establish that the position is eligible. Its byte is examined as a candidate. Consequently, requesting exactly the terminator’s position fails without a comparison call.

### Candidate eligibility and acceptance

Candidate positions are considered in increasing byte displacement. A position is eligible only if:

- Its byte is nonzero when this function reads it.
- The retained unsigned comparison extent is no greater than the unsigned conversion of the signed difference between the sequence measure and that position’s displacement.

The byte observation precedes the numerical condition. A zero byte prevents evaluation of that numerical condition and prevents a comparison call.

For an eligible candidate, F-7f14f1ab6851 receives the candidate address, the original search operand value, and the retained unsigned comparison extent, in that order.

A zero return accepts the position. The function returns its displacement immediately, without validating the candidate again. A nonzero return rejects the position; its sign and magnitude have no further significance.

After rejection, the next considered position is one byte later. There is no repeated check of the rejected position before advancing. Dependency mutations can therefore affect later observations, but a newly introduced zero at an already rejected position is not necessarily observed by this function.

Either a zero candidate byte or a failed numerical condition ends the entire search with −1. Neither event merely skips the current candidate. No later position is examined after that failure.

Thus, the returned position is the first candidate accepted among those actually reached and deemed eligible. It is not necessarily the first matching byte pattern under an external definition of equality.

### Numerical boundary

The eligibility calculation uses a **signed subtraction followed by an unsigned conversion**. It is not a signed comparison of a remaining length, nor an independently checked proof that the candidate region is accessible.

Under the signed 32-bit interpretation:

- A representable difference of two becomes unsigned two.
- A representable difference of −1 becomes unsigned 4,294,967,295.
- An extent of zero satisfies the numerical comparison whenever the subtraction and conversion are valid.

An unexpectedly small sequence measure can therefore permit comparison rather than prevent it. For example, a measure of two at displacement three produces the representable difference −1, whose unsigned conversion admits any 32-bit unsigned extent.

This conversion does not establish wrapping semantics for an overflowing signed subtraction. If the mathematical difference is outside the signed range, the available material does not establish a portable result. The same limitation applies to a displacement increment beyond its signed range. Pointer advancement outside valid storage has no defined search result established here.

Even a successful numerical check says nothing conclusive about how many bytes the comparison dependency can safely access.

### Result and error boundaries

On an ordinary execution with valid pointer movement and nonoverflowing arithmetic, success is a nonnegative byte displacement from the original address. It is not relative to the requested start, not an address, and not the comparison dependency’s return value.

The visible −1 outcomes are:

- A null address loaded from a valid slot.
- Zero encountered while passing bytes to reach a positive requested position.
- Zero at a candidate position.
- Failure of the candidate’s numerical eligibility condition.

There is no visible mechanism converting dependency faults, inaccessible memory, invalid pointer movement, arithmetic overflow, or nontermination into −1. Those conditions must not be treated as ordinary unsuccessful searches.

## Side effects

The function performs no explicit stores to caller-provided memory. It does not visibly overwrite the address slot, edit sequence bytes, allocate storage, or release storage.

That observation does not establish purity, storage preservation, or freedom from ownership effects. Both dependencies have unavailable bodies and contracts.

The externally relevant ordering is:

1. The initial address-slot load.
2. For a nonnull captured address, the measurement call on the search operand.
3. The measurement call on the captured sequence address.
4. Reads needed to pass positions before a positive requested start.
5. At each reached candidate, its byte read, then the numerical check if the byte is nonzero, then any eligible comparison call.

A comparison rejection is followed by advancement to the next position. A comparison acceptance is followed by return, without another direct sequence read.

A dependency may alter memory observed by later operations. For example, a comparison that rejects one candidate may change the byte checked at the next candidate. The function uses its retained measurements despite such changes.

No ownership transfer is explicitly expressed. Whether a dependency retains an address, modifies storage, releases storage, or changes globals is **documented_only**. No preservation guarantee for those resources is inferred from this function’s lack of explicit writes.
