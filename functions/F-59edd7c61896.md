# F-59edd7c61896

## Purpose

F-59edd7c61896 coordinates a drawing-like operation using a temporary 68-byte workspace, a primary resource, up to two conditional secondary resources, and optional formatted content.

**Established static evidence:** the function initializes the workspace, derives a value from its second input, associates the workspace with its first input, and conditionally issues resource, geometry, formatting, and workspace operations. It finalizes the workspace on every visible normal-return path.

**Inferred intent:** the primary resource is a base image; the secondary resources are overlays positioned relative to its bounds; the final optional operation draws formatted text. These interpretations are consistent with the call structure but are not established dependency contracts.

The function has no explicit result value and exposes no local error-reporting mechanism.

## Behavior

### 1. Establish the temporary operation

The initial calls occur in this order:

1. F-a4c26c2b4842 receives the address of the 68-byte workspace.
2. F-682adfd5a561 receives the lookup input and 6. Its 32-bit result is retained as the **derived value**.
3. F-7fa874cbac7a receives the context address and workspace address.
4. The primary-resource field at `0x1B4` is tested against zero.

The lookup call occurs even when the lookup input is zero. It also occurs before testing whether a primary resource exists.

Because F-7fa874cbac7a runs before the primary-resource test, that test observes the context after this call. It must not be described as necessarily using the context’s entry-time contents.

If the primary-resource field is zero at the test, the function skips all remaining resource, conditional-check, geometry, and formatted-content work and proceeds to workspace finalization.

### 2. Process the primary resource

For a nonzero primary-resource field:

1. F-59fa3fd3efc5 receives a value read from `0x1B4` and the address of a 16-byte primary record.
2. All four words of that record are copied into a separate 16-byte primary destination record.
3. F-b774eb6cb163 receives:
   - The workspace address.
   - A value read again from `0x1B4`.
   - The primary record address.
   - The primary destination-record address.
   - The 32-bit constants 255 and 0.

The two primary-resource reads are not an explicit snapshot. If the first dependency changes the context, the subsequent call can receive a different resource value.

Likewise, the primary destination record is passed by address to F-b774eb6cb163. Later placement calculations read its third and fourth words after that call. Their continued equality to the original copied values is not established.

After the primary operation, a 32-bit value is captured from one global data location. This captured value is retained for the second conditional check. The first conditional check instead reads that global location as part of its own argument construction.

### 3. Conditionally process the first secondary resource

The first secondary path requires all of the following, in short-circuit order:

1. The field at `0x274` is nonzero.
2. The original lookup input is nonzero.
3. F-9dfe5f6048f1 returns nonzero.

The conditional-check call receives:

- The derived value.
- The current value of the shared global data location.
- A value from a first branch-specific global data location.
- A value read from context offset `0xF0`.

A zero derived value does **not** itself suppress this first call. If the original lookup input is nonzero, the resource is present, and the conditional check accepts a zero derived value, this path can execute.

When accepted:

1. F-59fa3fd3efc5 receives the first secondary-resource value and a secondary 16-byte record.
2. Its four words are copied into a separate secondary destination record.
3. F-d156b0b83eb3 receives the secondary destination-record address and two calculated arguments.
4. F-b774eb6cb163 receives the workspace, a newly read first secondary-resource value, both secondary record addresses, 255, and 0.

The first calculated argument is:

**fourth primary-destination word − (fourth secondary-record word − second secondary-record word) − 2**

The second argument is the constant **3**.

**Inferred intent:** the expression places one edge two units inside the base boundary, with a fixed three-unit offset on the other axis. Whether F-d156b0b83eb3 translates, resets, or otherwise modifies the record is unknown.

The return from the first conditional check is used only as a zero/nonzero gate. It does not replace the derived value retained for the second path.

### 4. Conditionally process the second secondary resource

2. The derived value is nonzero.

## Acceptance examples

These are conditional static acceptance scenarios, not executed tests. Unless stated otherwise, dependencies return normally and do not change context fields or relevant records unexpectedly.

1. **Absent primary resource:** If `0x1B4` is zero when tested, initialization, lookup, association, and finalization still occur. No record acquisition, secondary conditional check, or formatted-content operation occurs, even if other resource fields are nonzero.

2. **Zero original input, nonzero derived value:** With a primary resource and both secondary resources present, the first conditional check is skipped. The second conditional check can run and enable its resource.

3. **Nonzero original input, zero derived value:** The first conditional check can run with zero as its first argument. If it returns nonzero, the first secondary resource is processed. The second conditional check is skipped.

4. **First check rejects:** A zero first-check result skips only the first secondary operation. A nonzero derived value still permits evaluation of the second conditional path.

5. **Placement calculation:** Suppose the primary destination’s third and fourth words are 100 and 80, and a secondary record is `(0, 0, 20, 10)`. The first path supplies adjustment arguments `(68, 3)`; the second supplies `(68, 78)`. This verifies argument calculation, not the adjustment dependency’s resulting geometry.

6. **Changing shared global:** If the shared global changes during the first conditional path, the second conditional check still receives the value captured after the primary operation. It does not reload that argument.

7. **Optional content only:** With a primary resource, absent secondary resources, and nonzero `0xF4`, primary processing is followed by the optional content call sequence and then finalization.

8. **Field mutation during optional work:** If a dependency changes `0xF4` after its enabling test, F-ccb5d9751852 receives the later value, including zero if that is what the later read observes.
