# F-a8e5fa926d00

## Purpose

F-a8e5fa926d00 conditionally records a coordinate pair and a one-byte classification at a signed, 16-bit index, then advances the index.

A byte in the supplied object controls whether recording occurs. When that byte is nonzero, the function:

- Converts two signed, 32-bit coordinate arguments by shifting each right by 16 bits.
- Writes the resulting pair into an indexed, eight-byte record.
- Writes a classification byte into a separate indexed byte array.
- Copies the recorded coordinates into two fields of the supplied object.

The index update occurs whether or not recording is enabled. Consequently, disabling recording does not pause index advancement.

These are statically established operations. Interpreting the index as a record count, the coordinates as fixed-point values, or the classification as a particular application-level status is inferred intent, not an established contract.

- The first four bytes hold the first signed coordinate result.

Each classification entry occupies one byte.

## Behavior

### Initial reads and branch selection

The function first reads the associated-state address from object offset `0x14`. It then reads the enable byte at object offset `0x51`.

The state address is retained for subsequent state accesses. Changes to the object’s state-address field after this initial read do not cause the function to select a different state during the same invocation.

Only the enable byte’s zero/nonzero distinction matters:

- Zero skips all coordinate recording and classification work.
- Any nonzero byte enables that work.

The enable byte is not reread later.

### Enabled recording

When recording is enabled, the function performs the following memory operations in the order expressed by the supplied body:

1. Reads the state index as a signed, 16-bit value.
2. Reads the classification-array base from state offset `0x08`.
3. Reads the coordinate-array base from state offset `0x04`.
4. Writes the shifted first coordinate to the first four-byte field of the selected coordinate record.
5. Writes the shifted second coordinate to the second four-byte field of that record.
6. Writes the selected classification byte.
7. Reads the record’s second coordinate back from memory.
8. Reads the record’s first coordinate back from memory.
9. Writes the reread first coordinate to object offset `0x18`.
10. Writes the previously reread second coordinate to object offset `0x1c`.

The coordinate record is selected using the captured signed index multiplied by eight. The classification byte is selected using that same captured signed index without scaling.

The two array bases and the enabled-path index are captured before the coordinate stores. The function does not reload those bases before writing the classification byte.

### Coordinate conversion

Each coordinate is a signed, 32-bit value shifted right by exactly 16 bits. The result is stored in a four-byte field.

For nonnegative inputs, the result is division by 65,536 with the fractional part discarded. For example:

- 65,535 becomes 0.
- 65,536 becomes 1.
- 196,607 becomes 2.

Negative signed right-shift behavior is not independently established by the supplied representation. With arithmetic, sign-extending right shift, negative values round downward rather than toward zero: −1 becomes −1, and −65,537 becomes −2. Those negative results are conditional on that shift behavior.

The operation is not saturation, rounding to nearest, or a 16-bit destination write. Although the input is shifted by 16 bits, the resulting record fields and object cache fields are four bytes wide.

### Classification selection

The classification selector is compared with zero at its full argument width:

- A zero selector produces classification byte 2.
- Any nonzero selector produces classification byte 1.

Negative nonzero selectors therefore select 1. A nonzero selector whose lowest byte is zero also selects 1; the decision is not based on a narrowed byte.

### Coordinate cache semantics

The object cache is populated by rereading the selected record, not directly from the shifted arguments.

For disjoint, stable memory, the cache therefore receives the two values just written. If the classification store overlaps either coordinate field, however, the rereads can observe that modification.

The second coordinate is captured before the first coordinate is reread and before either object cache store. Thus, an object-cache store that overlaps the record’s second coordinate does not change the second value already captured for the subsequent cache write.

### Unconditional index advancement

After the optional recording work, the function reads the signed, 16-bit index again from the retained state address, adds one, and stores the result back into the same two-byte field.

This final read occurs even if recording was disabled.

The final update does not necessarily increment the index captured at the start of enabled recording. An overlapping earlier write can change the index field before the final read. With ordinary disjoint memory and no external mutation, both reads observe the same index.

For an index from −32,768 through 32,766, adding one produces a value representable in the signed, 16-bit destination. For an index of 32,767, the addition produces 32,768 before assignment to that destination. The signed narrowing behavior is not established independently. A low-16-bit storage interpretation would produce the bit pattern corresponding to −32,768, but unconditional wraparound is not claimed here.

The signed index multiplied by eight ranges from −262,144 through 262,136. That multiplication fits in a signed, 32-bit integer. Adding the resulting displacement to an array address may still raise separate address-range or signed-arithmetic issues.

### Disabled recording

When the enable byte is zero:

- Neither array-base field is read.
- No coordinate record is accessed.
- No classification byte is written.
- Neither object coordinate cache field is written.
- The state index is still read, incremented, and stored.

The state address is nevertheless read before the enable test.

## Acceptance examples

These examples describe expected behavior under stated conditions. They are not runtime-test results. Except where noted, storage is valid, disjoint, and unchanged by other execution.

### Enabled recording with positive coordinates

Given:

- A nonzero enable byte.
- An index of 3.
- First coordinate 98,304.
- Second coordinate 196,607.
- A zero classification selector.

Expected:

- The coordinate record at byte displacement 24 receives first coordinate 1 and second coordinate 2.
- Classification entry 3 receives byte 2.
- The object coordinate cache receives 1 and 2.
- The state index becomes 4.

Adjacent records and classification entries are not directly targeted.

### Nonzero selector is not narrowed

Given enabled recording and a selector of 256, the classification byte is 1, despite the selector’s lowest byte being zero.

A selector of −1 also produces byte 1.

### Disabled recording still advances

Given a zero enable byte, an index of 7, and existing cache values of 40 and 50:

- The index becomes 8.
- The cache remains 40 and 50.
- Neither array is accessed through its base field.

This case does not require usable array-base values, provided all mandatory object and index accesses remain valid and nonoverlapping.

### Negative coordinate conversion

Given enabled recording, first coordinate −1, and second coordinate −65,537:

- Under arithmetic right shift, the selected record receives −1 and −2.
- Under disjoint storage, the cache receives those same values.
- Without an established signed-shift rule, those exact negative results remain conditional.

### Negative index

Given an index of −1, enabled recording targets:

- The eight-byte coordinate record immediately before the coordinate base.
- The classification byte immediately before the classification base.

If those locations are valid writable storage, the function proceeds and the final index becomes 0. If they are not valid, the function provides no bounds rejection.

### Reread observes overlapping classification storage

Suppose the classification byte aliases the lowest-addressed byte of the selected record’s first coordinate. Give the first coordinate an argument value of zero and choose a zero selector.

The first coordinate store initially writes zero. The later classification store changes the overlapping byte to 2. The first-coordinate reread therefore observes the modified representation, and the object cache receives that modified value rather than necessarily zero. Its exact numeric value depends on byte order.

### Maximum signed index

Given disabled recording and an index of 32,767, the function attempts the final signed, 16-bit assignment of the incremented value.

If the environment stores the low 16 bits on this conversion, the stored representation becomes `0x8000`. That result is conditional; the supplied evidence does not establish a portable overflow policy.
