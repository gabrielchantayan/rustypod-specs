# F-22959c398a0b

## Purpose

F-22959c398a0b extracts a low-order bit field from one byte selected through an indirectly supplied address. It reads an integer-valued base address, adds a signed byte displacement, reads the selected byte, shifts that byte right, and applies a mask derived from a requested field width.

The result is returned as an unsigned integer. No explicit memory write, allocation, release, validation, or error-reporting operation is present.

The field-width argument does not cause the function to read additional bytes. All extracted information comes from the single selected byte. Consequently, for defined executions with an unsigned eight-bit byte, the result cannot exceed 255, regardless of the requested mask width.

This is a static behavioral contract. No runtime tests have been performed.

| Input | Represented type | Meaning |

| Address-cell pointer | Pointer to signed integer | Identifies the integer object containing the base address. |
| Byte displacement | Signed integer | Added to the loaded base address before the byte read. Negative values are not explicitly rejected. |
| Shift argument | Unsigned integer | Its low eight bits determine the right-shift count. |
| Field-width argument | Unsigned integer | Its low eight bits determine the shift used to construct the mask. |

The address-cell pointer is not itself the base address of the byte data. There are two levels of access: first an integer is read through that pointer; then a byte is read at an address calculated from the integer.

The supplied representation uses an unsigned byte type for the second read. This contract treats that read as yielding an eight-bit value from 0 through 255. The definitions of the integer type aliases and the target ABI are not supplied. In particular, a 32-bit signed integer and a 32-bit unsigned return type are a target-model assumption, not an independently established platform fact.

## Behavior

### Address selection and reads

The function first obtains the integer stored at the address-cell pointer. It then adds the signed displacement to that integer and treats the result as the address of the selected byte.

The displacement is a byte displacement: there is no multiplication by the size of an integer or another element type. The address calculation is integer arithmetic followed by conversion to a byte pointer, rather than arithmetic on the incoming integer pointer.

The selected byte read depends on the result of the address-cell read. The address-cell read therefore precedes the dependent byte read in the represented computation. No further data byte is read.

Successful, defined execution requires all of the following:

- The address-cell pointer permits a valid read of the represented signed integer object, including applicable alignment requirements.
- The base-plus-displacement calculation is valid under the applicable signed-integer rules.
- Conversion of the calculated integer to a pointer produces an address usable for the byte access.
- The selected address permits a valid byte read.
- Both shift operations have defined counts and operands under the applicable integer rules.

There is no explicit check for any of these conditions.

### Argument reduction

The shift argument and field-width argument are each reduced independently to their low eight bits. Their effective values therefore range from 0 through 255.

This reduction is not a reduction to the machine word’s shift-count range. For example, on a 32-bit integer model, an effective count of 32 remains 32; the represented operation does not explicitly reduce it to zero.

Changing only bits above the low eight bits of either unsigned argument leaves that argument’s effective count unchanged, provided the complete execution remains defined.

### Extraction

For executions where the arithmetic and shifts are defined, the returned value is described by:

\[
R=\operatorname{unsigned}(X \mathbin{\mathrm{rightshift}} S)
\;\mathbin{\mathrm{AND}}\;
\left(2^W-1\right).
\]

The mask in this equation is a mathematical description of the defined cases, not a claim that every \(W\) from 0 through 255 is supported.

The byte is promoted before the right shift. With the unsigned eight-bit interpretation above, its promoted value is nonnegative. A valid right shift therefore discards low-order bits and introduces zeros at the high end.

The mask is constructed by shifting a signed integer constant with value one, then subtracting an unsigned constant with value one. That distinction limits the defined range. The unsigned subtraction does not retroactively make the preceding signed left shift safe.

Under an ordinary 32-bit C integer model:

- Effective right-shift counts from 0 through 31 are valid.
- Effective right-shift counts from 32 through 255 are outside the defined shift-count range.
- Effective mask widths from 0 through 30 produce the expected low-bit masks.
- Effective mask width 31 attempts a signed left shift whose mathematical result is not representable as a positive signed integer.
- Effective mask widths from 32 through 255 additionally exceed the shift-count range.

Thus the ordinary, defined 32-bit domain is \(0\leq S\leq31\) and \(0\leq W\leq30\), together with valid address operations. Different language or target rules require separate qualification.

### Boundary behavior

A zero field width produces a zero mask and therefore a zero result when the rest of the execution is defined. It does not waive either memory-read precondition. The selected byte remains an operand of the represented computation.

A zero shift count leaves the selected byte unchanged before masking.

For an eight-bit byte, valid shift counts of eight or more produce zero. Counts at or beyond the promoted operand’s width are not covered by that rule: they are invalid shifts rather than a defined way to obtain zero.

A field width larger than the number of remaining byte bits does not fetch adjacent data. In defined cases, it merely retains all remaining bits from the selected byte.
