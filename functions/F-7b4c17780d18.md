# F-7b4c17780d18

## Purpose

F-7b4c17780d18 performs a lookup using a supplied 32-bit value, examines one byte in a successful lookup result, and conditionally updates a caller-supplied context.

There are three observable paths:

- **Lookup failure:** return a designated 32-bit result without directly accessing the context.
- **Successful lookup with a nonzero discriminator byte:** store the supplied value in the context and return a previously captured 32-bit result.
- **Successful lookup with a zero discriminator byte:** invoke a context-dependent operation, conditionally transform a context word, store the supplied value, invoke three further operations in a fixed order, and return another designated 32-bit result.

The broader meanings of the lookup, discriminator, context fields, and result values are not established. In particular, the visible behavior does not establish that the function implements selection, activation, cancellation, or a timer, even though such interpretations might fit parts of the sequence.

|---|---|---|

| Supplied value | Opaque 32-bit quantity | Passed to the lookup dependency and, on lookup success, stored unchanged in the context |

The supplied value is not visibly interpreted as a number, pointer, handle, or ownership-bearing reference. Its complete 32-bit representation is forwarded and stored.

The context has no visible size argument. Its required accessible extent depends on the path taken and on requirements imposed by dependencies.

### Output

The function returns one opaque 32-bit quantity. Three externally supplied result words participate:

- **Missing-result word:** read and returned when lookup yields zero.
- **Captured-result word:** read immediately after lookup returns; returned when lookup succeeds and the discriminator is nonzero.
- **Completion-result word:** read and returned after the longer zero-discriminator path finishes.

These names describe their roles, not their numeric values or meanings. The evidence does not establish that the three words differ.

The function has no visible null check for the context. However, it does not directly dereference the context on lookup failure. A nonzero lookup result is not otherwise validated before its discriminator is read.

## Behavior

### 1. Perform the lookup and capture a result word

The function calls F-682adfd5a561 with:

1. The supplied 32-bit value.
2. A value obtained from an external lookup-parameter location.

After that call returns, the function reads the captured-result word. This read occurs before testing whether the lookup result is zero.

Consequently, even the lookup-failure path performs the captured-result-word read, although it does not return that captured value.

The lookup dependency may have side effects. The contract does not assume that it leaves the external lookup parameter, result-word locations, context, or any other memory unchanged.

### 2. Handle a zero lookup result

If F-682adfd5a561 returns zero, the function reads and returns the missing-result word.

On this path, the visible function body:

- Does not read a discriminator.
- Does not directly access any context field.
- Does not invoke the remaining four dependencies.

These are limits on the function’s direct behavior, not guarantees about effects performed inside the lookup dependency.

### 3. Read the discriminator after a successful lookup

If the lookup result is nonzero, the function reads one byte at offset `0x71` from that returned address.

The function performs no visible bounds check, ownership check, or additional validity check before this read.

### 4. Handle a nonzero discriminator

If the discriminator byte is nonzero, the function:

1. Writes the supplied value as a 32-bit word at context offset `0xDC`.
2. Returns the captured-result word obtained immediately after lookup.

No other dependency is called on this path.

The returned value is the earlier captured value, not a fresh read at return time. This distinction can matter if writing the context field aliases or otherwise affects the location from which the result word was captured.

### 5. Handle a zero discriminator

If the discriminator byte is zero, the function first calls F-9e15e25fb55e with the context address.

Its result controls only the direct update of context offset `0x4E8`:

- A zero result enables the update described below.
- Any nonzero result skips that direct update.

Neither outcome skips the later supplied-value write or the three subsequent calls.

#### Conditional word transformation

When F-9e15e25fb55e returns zero, the visible listing contains two reads of the unsigned 32-bit word at context offset `0x4E8`.

The first read supplies the operand for subtraction from one. The second supplies the operand for an unsigned comparison against one. The function then writes a 32-bit result to that same field:

- If the second read is greater than one, the stored result is zero.
- Otherwise, the stored result is the 32-bit result of subtracting the first-read value from one.

With stable memory between those reads, the transformation is:

| Original unsigned word | Stored word |
|---:|---:|
| `0` | `1` |
| `1` | `0` |
| Any value from `2` through `4,294,967,295` | `0` |

The stable-memory case therefore toggles the two values zero and one and collapses every other unsigned value to zero. It is not a general arithmetic decrement.

The subtraction uses a 32-bit unsigned operand. Its 32-bit result is interpreted modulo \(2^{32}\); it is not a checked subtraction or a saturating subtraction. Under stable memory, an underflowed intermediate for an input above one is superseded by the zero selected by the comparison.

If the two reads observe different values, the stable-memory table is not sufficient. The first read determines the subtraction result, while the second determines whether that result is replaced by zero. The source does not establish synchronization or define supported concurrent mutation.

#### Common remainder of the zero-discriminator path

After the conditional transformation, or immediately after F-9e15e25fb55e returns nonzero, the function proceeds in this order:

1. Write the supplied value as a 32-bit word at context offset `0xDC`.
2. Call F-6904f7699031 with the interior address at context offset `0x548` and the numeric argument `500`.
3. Call F-ec4cfa552cce with that same interior address.
4. Call F-bf8276908a13 with the context address.
5. Read and return the completion-result word.

The visible function does not inspect the return values of these final three dependencies.

The value `500` is established. Its units, semantic role, and the callee’s parameter type are not.

The completion-result word is read after all three calls, not captured before them. Any permitted mutation of its storage by those dependencies can therefore affect the value returned.

- Offset `0xDC`: written exactly once on either successful-lookup path, with the supplied value.
- Offset `0x4E8`: written exactly once only when the discriminator is zero and F-9e15e25fb55e returns zero.

There is no visible direct allocation, deallocation, copying of an entire object, or clearing of other fields.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They are not executed tests. Unless a case states otherwise, assume valid memory, normal dependency returns, stable observed fields, and no unmentioned dependency mutations.

### Lookup failure

Given that F-682adfd5a561 returns zero:

- The captured-result word is still read after the lookup.

- No remaining dependency is invoked.

- The function returns the captured-result word.

### Zero discriminator with transformation enabled

- A stable word of one becomes zero.
- A stable word of `0xFFFFFFFF` becomes zero; it is compared as unsigned, not treated as negative.
- The supplied-value write follows that transformation.
- The final three dependencies execute in their specified order.
- The completion-result word is read after the final dependency returns.

- It still writes offset `0xDC`.
- It still invokes all three subsequent dependencies.

### Result storage changed by dependencies
