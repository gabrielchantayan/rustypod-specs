# F-e6020fb0c578

## Purpose

F-e6020fb0c578 performs two ordered sequences of 16-bit stores, using a caller-supplied transformation function and three countdown-controlled adjustments to a 32-bit working value.

The input word is partitioned into fields occupying bits 11–15, 5–10, and 0–4. These positions suggest a packed three-component value, possibly a color. That interpretation is **inferred intent**, not an established interface requirement. The observable contract is defined by integer operations, dependency calls, and memory accesses.

The two sequences are not independent. All three countdowns carry their remaining values from the first sequence into the second. Each sequence obtains its initial working value from the callback’s return value; subsequent callback results are stored but do not replace that working value.

No runtime tests have been performed. The behavior below is a static reading of the supplied representation, subject to the uncertainties stated later.

## Interface

### Inputs

The function has two explicit inputs:

- A pointer to a readable, unsigned 16-bit word.
- A callable dependency, referred to here as the **callback**.

The callback is invoked with one 32-bit value. Its result is consumed as a 32-bit value for the first call of each sequence, and only its low 16 bits are retained for the other calls. The actual callback ABI, declared return type, and compatibility requirements are not established beyond those uses.

The function also depends on three externally stored values:

- **Mask:** a 32-bit value used to form two dependency arguments and the first callback argument.
- **Primary destination:** a pointer used for indexed 16-bit stores.
- **Secondary destination:** an address used for one 16-bit store at a byte offset of 254.

These names describe their uses, not ownership or application meaning.

### Result

There is no explicit return value or success indicator.

On normal completion, the function makes:

- Three calls to F-d7be9cfb4000.
- 256 callback invocations.
- 256 explicit 16-bit stores.

Those are operation counts, not counts of distinct memory locations. Destination aliasing and dependency-induced pointer changes can cause stores to overlap or target different allocations.

### Preconditions

Normal execution requires:

- The input word to be readable at both of its read points.
- A valid callback compatible with the actual calling convention.
- Valid writable storage for every destination selected at each store.
- Successful return from every dependency invocation.
- Arithmetic behavior compatible with the underlying implementation.

The function performs no visible null checks, destination-capacity checks, callback validation, or error reporting.

The caller must not assume that the input, destinations, mask, or callback environment remain unchanged across dependency calls. Such stability requires an external guarantee.

## Behavior

### 1. Capture the initial input and derive three countdown intervals

The function first captures the mask for later use as the initial callback argument. It then reads the unsigned 16-bit input word.

Three quantities are derived from that input:

| Interval | Derived second argument to F-d7be9cfb4000 |
|---|---|
| High-field interval | `(32 − high field) AND mask`, where the high field is bits 11–15 |
| Low-field interval | `32 − low field`, where the low field is bits 0–4 |
| Middle-field interval | `(64 − middle field) AND mask`, where the middle field is bits 5–10 |

Before masking:

- The high-field quantity ranges from 1 through 32.
- The low-field quantity ranges from 1 through 32.
- The middle-field quantity ranges from 1 through 64.

Masking can make either masked quantity zero. The supplied representation establishes no constraint preventing that.

The middle-field masked quantity is computed before the first dependency call. The high-field masked quantity is also evaluated before that call. They use reads of the external mask; they are not expressly computed from the previously captured mask value.

F-d7be9cfb4000 is then called three times, in this order:

1. First argument 256; second argument the high-field masked quantity.
2. First argument 256; second argument the low-field quantity.
3. First argument 256; second argument the middle-field masked quantity.

Each result becomes a 32-bit interval and the initial value of its corresponding countdown. No division, rounding rule, positivity guarantee, or error convention for this dependency is established.

All three call arguments are based on the initial input-word read. A later change to the input word does not recompute these intervals.

### 2. Seed the first sequence

After the three interval calls, the callback is invoked with the mask value captured at entry.

Its full 32-bit result becomes the working value. The low 16 bits of that result are stored at primary destination index 0.

The destination pointer is obtained for the store after the callback returns. A callback that changes the externally stored primary destination can therefore affect this store.

The three countdowns are initialized from their intervals before the repeated portion begins.

### 3. Emit primary indices 1 through 127

The function performs 127 iterations, writing primary indices 1 through 127 in ascending order.

Each iteration has the following observable order:

1. Inspect the high-field countdown. If it is exactly zero:
   - Subtract 2,048 from the working value.
   - Retain only the low 16 bits.
   - Reload that countdown from its interval.
2. Inspect the low-field countdown. If it is exactly zero:
   - Subtract 1 from the working value.
   - Retain only the low 16 bits.
   - Reload that countdown from its interval.
3. Inspect the middle-field countdown. If it is exactly zero:
   - Subtract 32 from the working value.
   - Retain only the low 16 bits.
   - Reload that countdown from its interval.
4. Invoke the callback with the current working value.
5. Decrement all three countdowns by one.
6. Obtain the primary destination pointer and store the low 16 bits of the callback result at the current index.

The adjustments are sequential and apply to the entire working value, not to independently clamped fields. Borrow between apparent component fields is possible.

The working value is truncated to 16 bits only when an adjustment occurs. If no adjustment has yet occurred, high bits from the initial callback result can remain present in subsequent callback arguments even though the stored results are 16-bit values.

A countdown that becomes zero through the post-callback decrement triggers its adjustment at the beginning of the **next** iteration.

The callback results from these 127 iterations do not replace the working value. They affect output stores, but later callback arguments continue from the internally maintained working value.

### 4. Seed the second sequence

After primary index 127 has been stored, the function reads the input word again and invokes the callback with that unsigned 16-bit value, extended to the callback argument width.

This is a fresh read. It need not match the input used to derive the intervals if the input was changed by an earlier dependency call or an aliased destination store.

The callback’s full 32-bit result replaces the working value. Its low 16 bits are stored at:

- Secondary destination plus **254 bytes**.

This address is not established to be any particular primary destination index. In particular, the contract does not assume that the secondary destination equals the primary destination.

The three countdowns are **not reset** at this boundary. Their states after the preceding 127 iterations are retained.

### 5. Emit primary indices 254 through 128

The function performs another 127 iterations, writing primary indices 254 down through 128 in descending order.

Each iteration:

1. Checks the high-field countdown for exact zero. On zero, adds 2,048 to the working value, applies mask `0xFFFEFFFF`, and reloads the countdown.
2. Checks the low-field countdown for exact zero. On zero, adds 1, applies the same mask, and reloads the countdown.
3. Checks the middle-field countdown for exact zero. On zero, adds 32, applies the same mask, and reloads the countdown.
4. Calls the callback with the working value.
5. Decrements all three countdowns.
6. Obtains the primary destination pointer and stores the callback result’s low 16 bits at the current index.

The mask `0xFFFEFFFF` clears **bit 16 only**. It does not truncate the working value to 16 bits and does not clear bits 17–31.

Consequently, a full-width seed result can retain upper bits throughout this sequence. If no adjustment occurs in an iteration, no mask is applied in that iteration.

As in the first sequence, ordinary callback results are output values only; they do not feed back into the working value.

### 6. Complete

The function returns after the store at primary index 128.

There is no explicit store at primary index 255. Across both loops and the first seed store, the explicitly primary-indexed stores cover indices 0 through 254 exactly once each, provided the primary pointer remains fixed. The separate secondary store may overlap that range or lie elsewhere.

## Side effects

### Memory access order

The explicit input reads occur:

1. Before the three interval calls.
2. After the entire first sequence and immediately before the second seed callback.

The explicit output-store order is:

1. Primary index 0.
2. Primary indices 1 through 127, ascending.
3. Secondary address plus 254 bytes.
4. Primary indices 254 through 128, descending.

Each store follows the callback whose result it records. The supplied representation obtains the applicable destination pointer after that callback.

If the two destinations have the same stable base, the secondary store addresses primary index 127 and overwrites the preceding value at that index. Under that condition, there are 256 stores but only 255 distinct halfword locations written. Equality of the destination bases is not established.

## Acceptance examples

These examples are conditional static consequences, not results of executed tests.

### Argument derivation at input extremes

If the first input read is zero and the relevant mask reads preserve all derived bits, the interval dependency receives second arguments 32, 32, and 64, in high/low/middle call order.

If the first input read is 65,535 under the same mask condition, all three second arguments are 1.

These examples constrain arguments only; they do not predict dependency results.

### Countdown timing and carryover

Suppose all three interval results are 1 and all required arithmetic is valid.

- The first repeated iteration performs no adjustment because each countdown starts at 1.
- Its decrements leave all three countdowns at zero.
- The next repeated iteration performs all three downward adjustments, in high/low/middle order.
- The first iteration of the second sequence performs all three upward adjustments because the carried countdowns are zero.

Resetting countdowns at the sequence boundary would violate this behavior.

### Zero intervals

Suppose an interval result is zero.

Its adjustment occurs on the first repeated iteration. Reloading zero and then decrementing produces −1. The next iteration does not adjust that countdown, because the check is for equality to zero, not for a nonpositive value.

Any later effect involving signed overflow requires target-specific arithmetic information.

### Downward truncation

Suppose the first seed result is `0x12340000` and no countdown is zero on the first repeated iteration.

That iteration passes `0x12340000` to the callback, although the initial store retained only `0x0000`.

If a later low-field adjustment occurs alone, the subtraction followed by the 16-bit mask changes the working value to the low 16 bits of the decremented value.

### Upward masking

Suppose an upward low-field adjustment occurs alone.

- A working value of `0x0000FFFF` becomes zero after addition and masking.
- A working value of `0x00020000` becomes `0x00020001`; bit 17 is retained.

Replacing the upward mask with a 16-bit truncation would violate the second case.

### Callback changes between stores

If the callback changes the primary destination pointer before returning, the associated primary store uses the destination pointer read after that return.

If an early callback changes the input word, the second seed callback receives the later input value, while the intervals remain based on the first input read.
