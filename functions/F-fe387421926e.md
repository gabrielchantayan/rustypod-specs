### Field extraction and truncation

### Global acquisition timing

Suppose the word at `0x087FBBBC` contains `0x1000` when the specified global read occurs. The repeated global-relative byte and word destinations use `0x1019` and `0x1034`.

If later stores change the backing global word, the represented retained base remains `0x1000`. Conversely, a change before acquisition can affect that base. Moving the read to function entry is not equivalent without additional preservation and aliasing assumptions.

### Fixed input ordering

The fixed byte read at `0x05` must precede the fixed byte write at `0x01`. The fixed word read at `0xA9` must precede the computed payload-base offset-`0x74` read, which must precede the fixed byte write at `0x3A`.

An implementation preserving only final byte values does not satisfy these event-order criteria.

### Separate observations of `0x67`

Assume valid accesses. If the initial `0x67` write carries `0xAB`, but the following computed offset-`0x44` read has an environment-visible effect changing `0x67` to `0xCD`, the read supplying `0x21` observes `0xCD`.

Likewise, if an intervening computed write aliases `0x67`, either later working-base offset-nine copy can observe the changed byte. Reusing cached `0xAB` for all copies is not generally equivalent. This example is conditional on such aliasing or memory behavior; it does not assert that ordinary non-aliasing memory changes spontaneously.
