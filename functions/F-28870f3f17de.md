# F-28870f3f17de

## Purpose

F-28870f3f17de conditionally searches an indexed sequence for the first nonzero integer. Each indexed operation returns an address; the function reads the candidate integer from that address. Selection depends on the integer read, not on whether the returned address is zero or nonzero.

For the first nonzero candidate, the function invokes F-4929c2fbf85b and then, if that invocation returns normally, F-feee9156a257. Both receive the same captured integer.

The function returns normally without invoking either named dependency when the entry gate is disabled, the captured count is nonpositive, or all examined candidates are zero.

This describes the established control flow, not the application-level meaning of the operation. The evidence does not establish whether candidate integers represent ordinary data, identifiers, encoded addresses, resources, or errors.

The function accepts one pointer to a structure-like storage region. No explicit result value is exposed.

### Widths and representations

The count, index, and candidate use the same signed-integer representation. The index begins at zero.

Under a concrete 32-bit interpretation:

- The count, index, and candidate are signed 32-bit integers.
- Each input slot occupies four bytes.
- The dispatch reference is represented in the first four-byte slot.

The gate is tested after conversion to a character-sized representation. It is not tested directly as a full-width integer. Under an eight-bit truncating interpretation, the low eight bits determine whether the gate is zero. Exact character width and conversion behavior are not independently established.

## Behavior

### Entry decision and count capture

The function first reads the gate field and compares its character-sized conversion with zero.

If the converted value is zero, the function returns immediately. It does not read the count, inspect the dispatch reference, or invoke a dependency.

Otherwise, it reads and captures the count once. The gate is not checked again, and subsequent changes to the stored count do not change the captured search bound.

This is a local control-flow guarantee. It does not imply that dependencies ignore the current gate or count when performing their own work.

### Indexed search and observable order

The search starts at index zero. Before each lookup, the current index is compared with the captured count using signed ordering. If the index is greater than or equal to the captured count, the function returns.

For each index below the captured count, the observable sequence is:

1. Read the dispatch-table reference from the input’s first slot.
2. Resolve the indirect operation at displacement 64 from that reference.
3. Invoke that operation with the original input pointer and current index.
4. After it returns normally, read one integer from the returned address.
5. If that integer is zero, advance the index and consider the next iteration.
6. If that integer is nonzero, select it and end the search.

The indexed operation returns an address, not the candidate integer. A zero returned address is still used for the integer read; it is not interpreted as an end marker, a zero candidate, or permission to advance.

The dispatch reference and dispatch entry are resolved again for each attempted lookup. They are not captured with the count. If an indexed operation changes the reference and returns an address whose subsequently read integer is zero, a later iteration uses the reference then present in the input.

Similarly, if a dependency changes an entry within an existing dispatch table, a later lookup reads that entry again. Continued execution still requires valid storage and a compatible target.

These ordering statements describe the supplied access and call sequence. They do not establish atomicity, synchronization, or a machine-instruction trace.

### Candidate selection and subsequent calls

Every nonzero candidate qualifies, including a negative integer. No positivity check or other candidate validation is visible.

Once a candidate is selected:

- No later index is examined.
- F-4929c2fbf85b is invoked with the captured candidate.
- Any ordinary result from that invocation is unused.
- If it returns normally, F-feee9156a257 is invoked with the same captured candidate.

The candidate storage is not reread between the two named calls. A change to that storage by F-4929c2fbf85b does not replace the argument passed to F-feee9156a257.

If F-4929c2fbf85b faults, fails to terminate, or exits nonlocally, the second invocation is not reached through the visible sequential path.

F-feee9156a257 is marked nonreturning in the supplied static evidence. The selected-candidate path is therefore represented as having no normal return after that call. Its actual nonreturning mechanism and behavior if it unexpectedly returns remain unresolved.

### Search bounds and arithmetic

For a positive captured count of \(N\), if every indexed operation returns normally and every candidate read is zero, the function performs exactly \(N\) indexed calls, in order from index zero through \(N-1\), and then returns.

If the first nonzero candidate is at index \(k\), it performs exactly \(k+1\) indexed calls before invoking F-4929c2fbf85b, assuming all preceding operations complete normally.

The index advances only after a zero candidate is read at an index strictly below the captured count. With the same signed-integer range for count and index, this increment does not overflow. Even for the maximum positive count, the final increment reaches that count; the next comparison returns before any further increment.

The visible search performs no arithmetic on candidate values and no index-based address calculation of its own. How the indirect operation interprets an index is unknown.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless otherwise stated, assume accessible storage, compatible dispatch targets, and normal returns from indexed operations.

### Disabled gate

If the gate’s character-sized conversion is zero, the function returns without reading the count or resolving a dispatch entry.

Under an eight-bit truncating interpretation, a full gate slot containing 256 converts to zero and disables the search.

### Enabled gate with a nonpositive count

If the gate permits entry and the captured count is zero or negative, the function returns before dispatch resolution. No candidate address is requested.

### All candidates are zero

For a captured count of three, suppose the operations for indices zero, one, and two each return an address from which the subsequent integer read yields zero.

The function requests those indices in order, reads one integer from each returned address, invokes neither named dependency, and returns after exhausting the bound.

### First nonzero candidate

For a captured count of four, suppose index zero returns an address containing zero and index one returns an address containing 17.

Only indices zero and one are requested. F-4929c2fbf85b receives 17. If it returns normally, F-feee9156a257 receives 17. Indices two and three are not requested.

### Negative candidate

If the first returned address contains −1, that candidate is selected immediately. F-4929c2fbf85b receives −1, followed by F-feee9156a257 with −1 if the first call returns normally.

### Count and gate mutation

Suppose the captured count is three. During the index-zero call, the indirect operation changes the stored count to zero and disables the gate, then returns an address whose integer value is zero.

If all storage and targets required for continuation remain valid, the search proceeds to index one using the captured bound of three. Neither the gate nor the count is reread by this function.

### Dispatch mutation

Suppose the index-zero operation changes the input’s dispatch reference and returns an address whose subsequent integer read yields zero.

The index-one lookup uses the updated dispatch reference. Merely returning a zero address would not establish this continuation; the candidate read must complete and yield zero.

### Candidate mutation after selection

Suppose the selected integer is 9. F-4929c2fbf85b changes the original candidate storage to 12 and returns normally.

F-feee9156a257 receives 9, not 12, because its argument is the captured candidate.

### Zero returned address

Suppose an indexed operation returns address zero.

The function attempts an integer read through address zero. It does not skip the candidate or increment the index based on the address alone. If the read is valid and yields zero in the execution environment, the search advances; if it yields a nonzero integer, that integer is selected. If the read is invalid, the resulting abnormal behavior is not specified by the supplied evidence.
