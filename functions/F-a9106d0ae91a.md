# F-a9106d0ae91a

## Purpose

F-a9106d0ae91a searches up to 32 record positions for an unsigned key equal to its input. On the first successful comparison, it returns a signed 16-bit result widened to the return type. If every comparison fails, it returns 2,147,483,647.

**Established static behavior:** record positions are examined in ascending order, starting at zero. Each position has a four-byte stride, an unsigned 16-bit key at offset two, and a signed 16-bit result at offset zero. The input is not narrowed to 16 bits before comparison.

The external table-address reference is evaluated separately for every visited key access. After a successful comparison, it is evaluated again for the result access. The function does not explicitly capture one invariant table base for the entire invocation.

With a stable address reference and stable backing storage, this is a first-match lookup in one 32-record table. Without those assumptions, the source-level accesses need not refer to one consistent table or even to the same backing storage for a successful key comparison and its subsequent result read.

**Inferred intent:** a small key-to-signed-value mapping. The domain meanings of keys, results, and the no-match value are not supplied.

## Interface

### Input and return value

The function accepts one unsigned integer. The recovered interface is treated as having a 32-bit input, giving a range of 0 through 4,294,967,295. Independent ABI confirmation is unavailable.

The full input participates in comparison with each unsigned 16-bit key:

- Inputs from 0 through 65,535 can match.
- Inputs greater than 65,535 cannot match any value obtained from a key field.
- There is no visible input masking, truncation, normalization, or range-rejection branch.

The recovered return type is treated as a signed 32-bit integer.

| Outcome | Return value |
|---|---|
| A key comparison succeeds | The subsequently read signed 16-bit result, widened with its sign preserved |
| All 32 key comparisons fail | 2,147,483,647 |

A retrieved result is therefore between −32,768 and 32,767 inclusive. The no-match sentinel lies outside that range.

There is no caller-supplied table address, length, output buffer, status flag, or starting position.

The function obtains access addresses through an external table-address reference. For any particular evaluation of that reference, record position \(i\) has the following layout:

| Field | Displacement from the evaluated base | Width | Interpretation |
|---|---:|---:|---|
| Result | \(4i\) bytes | 16 bits | Signed |
| Key | \(4i+2\) bytes | 16 bits | Unsigned |

Visited positions range from 0 through 31. Relative to a stable base, the complete logical layout occupies 128 bytes. The last result starts at displacement 124 and the last key at displacement 126.

The result displacement uses the same record index that produced the successful key comparison. It does **not** follow that the result comes from the same record object or backing allocation: its address uses a fresh evaluation of the external reference. That stronger same-record interpretation requires a stable reference.

## Behavior

### Ordered search

The function begins with record position zero and visits successive positions through, at most, position 31.

At each visited position, it evaluates the external address reference, obtains the unsigned 16-bit key at that position’s key displacement, and compares the key’s numeric value with the full unsigned input.

A mismatch leads to the next position. A match leads to a separate evaluation of the external reference and a signed 16-bit read at the current position’s result displacement. The function returns that result immediately.

After 32 unsuccessful comparisons, it returns the no-match sentinel.

There is no empty-table condition, stored length, terminator record, or visible early rejection for inputs outside the key range.

### Source-level reference and field-access order

The supplied representation establishes this order:

1. For each visited position, the external table-address reference is evaluated for that position’s key access.
2. The key is read and compared with the input.
3. Only after a successful comparison is the external reference evaluated again for the result access.
4. The result is read and returned; later positions are not visited.

Thus, if the first successful comparison occurs at position \(i\):

- Exactly \(i+1\) source-level reference evaluations supply key addresses.
- Exactly \(i+1\) key fields are read.
- One additional source-level reference evaluation supplies the result address.
- Exactly one result field is read.

A completed no-match search has 32 source-level reference evaluations for keys, 32 key-field reads, and no result-reference evaluation or result-field read.

These are counts and ordering in the supplied source-level representation. They do not establish physical loads of the reference storage, instruction counts, bus transactions, compiler caching, or hardware memory ordering. In particular, separate source-level evaluations must not be replaced in this contract by a claim that the function captures one base, nor interpreted as proof of separate hardware reloads.

### Stable and changing references

With a stable external reference, the successful key and result accesses use the same base and record index. With stable contents as well, the returned result is the value paired with the first matching key in that table.

If the reference yields different addresses on different evaluations, each access is described relative to the address selected for that access. A successful key comparison at one base is not followed by validation that the fresh result base is identical.

The function contains no explicit retry, reference-consistency check, second key comparison, or snapshot construction. Whether changes can occur and be observed during an invocation is not established. No supported concurrent-update semantics should be inferred from the separate evaluations.

### Comparison and result widths

The key is unsigned and 16 bits wide. Its numeric value is compared with the full input rather than with the input’s low 16 bits.

Consequently:

- Key 65,535 can match input 65,535.
- Key zero cannot match input 65,536.
- Key one cannot match input 65,537.

For an input greater than 65,535, every successfully read key necessarily fails the comparison. With all required accesses valid, the function still visits all 32 positions and returns the sentinel.

The result is interpreted as signed 16-bit before widening. A result field representing −1 returns −1, not 65,535. A result field representing −32,768 returns −32,768, not 32,768. Zero is an ordinary successful result.

### Duplicates and arithmetic bounds

With stable reference and contents, the lowest-index matching record wins. Later duplicate keys are not examined. Reordering duplicate-key records can therefore change the result.

More generally, without assuming stability, the function returns after the first successful comparison among the keys actually read in visit order.

Record accesses use only indices 0 through 31. The largest record displacement is 124 bytes, and the largest key displacement is 126 bytes. The index advances to 32 to terminate the search, but no record is accessed at that index.

These index and displacement values fit in the recovered 32-bit unsigned arithmetic. That does not establish the width or safety of base-address arithmetic. Validity of the resulting addresses remains an external precondition.
