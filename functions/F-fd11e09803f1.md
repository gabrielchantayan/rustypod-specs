# F-fd11e09803f1

## Purpose

F-fd11e09803f1 performs a small, read-only classification of a context and a candidate record. It returns one of three 32-bit status values: **1**, **2**, or **3**.

The established decision priority is:

1. A distinguished context value of **−2** produces status **2**, without consulting the candidate.
2. Otherwise, a candidate whose address equals the context’s stored candidate address produces status **1**, without inspecting the candidate’s contents.
3. For a different candidate address, a candidate marker other than **−1** produces status **2**.
4. If that marker is **−1**, equality between the candidate’s first integer and the context’s comparison value determines status **1** or **3**.

The apparent intent is to recognize either an already-associated candidate or a different candidate satisfying two field conditions. That interpretation is inferred, not established terminology. The status values have no supplied external names; this contract does not label them as success, failure, ownership, or validity states.

## Interface

### Inputs

The function receives two arguments:

- **Context address:** an address-like value used to locate fields at fixed byte offsets.
- **Candidate address:** a pointer to integer storage, accessed only on the different-address path described below.

The recovered interface represents the context address using an integer type and the candidate address using an integer-pointer type. This is evidence of how addresses are represented in the supplied material, not a portable calling convention. The target ABI, pointer width, address-space rules, and alignment requirements are not independently supplied.

### Relevant layouts

Offsets below are byte offsets from the respective input address.

| Object | Offset | Interpretation | Access condition |
|---|---:|---|---|
| Context | +0x14, decimal 20 | Signed integer comparison value | Always read initially; read again on the final comparison path |
| Context | +0x1c, decimal 28 | Stored candidate pointer | Read only when the initial context value is not −2 |
| Candidate | +0 | First signed integer | Read only after pointer inequality and a marker equal to −1 |
| Candidate | +4 | Second signed integer, used as a marker | Read only after pointer inequality |

The recovered integer accesses are treated as **32-bit accesses** in this contract. Accordingly, the candidate’s relevant fields occupy bytes 0–3 and 4–7. The context comparison field occupies bytes 20–23.

The context’s stored pointer is compared with the candidate address as a pointer value. Its storage width is not independently established by the supplied material; a particular pointer width must not be inferred solely from the four-byte spacing between integer fields elsewhere.

No candidate length, context length, tag, or allocation metadata is passed separately.

### Output

The return value is four bytes wide and is always one of:

| Value | Established condition |
|---:|---|
| 1 | Matching stored candidate address, or a different candidate with marker −1 and matching comparison value |
| 2 | Initial context value −2, or a different candidate whose marker is not −1 |
| 3 | Different candidate address, marker −1, and unequal comparison values |

These are ordinary return values. No supplied evidence establishes an exception object, error-number update, or diagnostic accompanying them.

### Preconditions

Each memory access reached during execution requires a readable, appropriately represented location. The function does not establish those conditions before accessing memory.

In particular:

- The context comparison field must be readable on every invocation.
- The stored pointer field must be readable if the initial comparison value is not −2.
- The candidate marker must be readable if the addresses differ.
- The candidate’s first integer must be readable if the addresses differ and the marker is −1.

These are path-specific requirements. Requiring a fully readable candidate on every path would be stronger than the observed behavior.

## Behavior

### Initial context gate

The first observable data access is a read of the context’s integer at offset +0x14.

If that value equals **−2**, the function returns **2** immediately. The stored pointer and both candidate integers are not read on this path.

This gate has priority over all later conditions. A matching candidate address cannot override it.

### Stored-address comparison

When the initial context value is not −2, the function reads the pointer stored at context offset +0x1c and compares it with the supplied candidate address.

If the pointer values are equal, the function returns **1**. It does not inspect either candidate integer. Candidate contents therefore cannot affect this path.

This is an address comparison, not a record-content comparison. Two distinct addresses containing identical integers do not qualify for this shortcut.

### Different-address marker gate

When the pointer values differ, the function reads the candidate’s second integer, at offset +4.

If this marker is anything other than **−1**, the function returns **2**. Neither the candidate’s first integer nor a second read of the context comparison field is required on this path.

The marker check is exact equality with −1. Other negative values, zero, and positive values all take the same status-2 branch.

### Final value comparison

When the addresses differ and the candidate marker equals −1, the function compares:

- The candidate’s first integer at offset +0.
- The context’s integer at offset +0x14, read again for this comparison.

If they differ, the function returns **3**. If they are equal, it returns **1**.

The final comparison does not reuse an explicitly saved copy of the initial context value. The supplied expression references the context field again. The relative evaluation order of the two operands of this final comparison is not established, so this contract does not require the candidate value to be read before the repeated context value, or vice versa.

The initial −2 gate is not repeated after this second context read.

### Arithmetic and boundaries

The behavior consists of fixed-offset addressing, pointer equality, and integer equality or inequality. There is no value addition, multiplication, narrowing conversion, range check, or signed ordering comparison in the classification itself.

For a conventional 32-bit two’s-complement representation, −1 corresponds to all 32 bits set, and −2 corresponds to all bits set except the least significant bit. Those bit patterns depend on the representation assumption; the established comparisons are to the signed values −1 and −2.

No address-wraparound behavior is established. Inputs must permit the required field accesses under the target memory model.

## Side effects

The supplied body contains **no explicit memory writes** and **no calls**.

Consequently, it does not explicitly:

- Modify the context or candidate.
- Replace the stored pointer.
- Allocate, retain, release, or transfer ownership of either object.
- Update a global status field.
- Emit diagnostics.
- Invoke a callback.

The function only reads the fields reached by its decision path and returns a status.

This read-only characterization does not make invalid addresses safe. An invalid or inaccessible reached location can cause platform-dependent failure. No recovery or status mapping for such failures is shown.

There are no synchronization operations or snapshot guarantees. Concurrent modification, memory-mapped device behavior, and language-level data-race semantics are outside the established contract. In particular, the two references to the context comparison field must not be described as an atomic snapshot.
