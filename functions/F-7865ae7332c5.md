# F-7865ae7332c5

## Purpose

F-7865ae7332c5 conditionally submits a translated, zero-terminated byte sequence to an indirectly selected callback. If that callback returns a nonzero result and a subsequent allocation-like dependency returns a nonzero address, the function initializes a replacement record through two copy-like calls and several direct field writes. Otherwise, the low 32 bits of its result identify the original record.

This is not a simple success/failure return. The 64-bit result also contains a 32-bit upper component whose value changes once execution reaches the callback stage. That upper component can identify temporary storage belonging to this invocation; it is not established as a usable output pointer.

The apparent intent is to create an updated record after callback acceptance. The supplied evidence establishes the control flow, addresses, argument values, and direct accesses. It does not establish the semantics of the external dependencies, ownership transfers, or the meaning of the record fields.

### Result

The low 32 bits are:

- The original record address on every ordinary return except the replacement-producing path.
- The nonzero address returned by F-f053f140662a on the replacement-producing path.

The upper 32 bits are:

- Initially, the original record address.
- After successful preparation and translation of a non-null sequence, the address of a local 32-bit slot holding the saved auxiliary value.

That second upper-component value remains selected even if the callback rejects the operation or the later allocation-like call returns zero. It therefore does not independently indicate success.

The local slot ceases to have an established lifetime when this invocation returns. Nothing in the supplied evidence authorizes dereferencing its returned address afterward.

## Behavior

### 1. Eligibility checks

The function initially selects the original record address for both result components.

It proceeds only when the descriptor is non-null and its first byte compares equal to −107. Otherwise, it returns without invoking any of the listed dependencies.

For a matching descriptor, accesses occur in this order:

1. Read the linked-object address at descriptor offset 60.
2. If that address is nonzero, read the byte at linked-object offset 57.
3. If that byte is nonzero, read the interface address at linked-object offset 64.
4. Dereference the interface address to obtain the dispatch-base address.
5. Read the callback address at dispatch-base offset 72.
6. Continue only if that callback address is nonzero.

A zero linked-object address, zero eligibility byte, or zero callback address produces the ordinary fallback return.

There are no explicit null checks for the interface address or dispatch-base address before dereferencing them. Invalid addresses at either stage are not converted into a fallback result. The same limitation applies to unreadable descriptor and linked-object fields.

### 2. Sequence preparation

After eligibility succeeds, the function:

1. Saves the auxiliary value in a local 32-bit slot.
2. Initializes a separate local pointer slot with the descriptor address.
3. Calls F-8ad0042eaec1 with the context and original-record address plus 28.
4. Reads a global translation-table address after that call returns.
5. Tests the returned sequence address for zero.

The translation-table address read occurs even when the returned sequence address is zero. A zero sequence address causes fallback without callback invocation and without invoking F-94cb53877c15.

The meaning of F-8ad0042eaec1 is not supplied. Its return is subsequently treated as writable, zero-terminated byte storage. The evidence does not establish that it allocated that storage, copied the original sequence, or returned non-aliased memory.

### 3. In-place translation

For a nonzero sequence address, the function processes bytes in increasing address order:

- Read the current byte.
- If it is zero, end translation.
- Otherwise, read the translation-table byte indexed by that original byte value.
- Write the translated byte back to the current sequence position.
- Advance one byte.

Indices are unsigned byte values. Because zero terminates traversal before lookup, only indices 1 through 255 are used.

A translated byte of zero does **not** stop this traversal. The next iteration examines the next address. Consequently, the callback may receive a sequence containing a newly introduced early zero even though translation continued through later bytes up to the original terminator.

The original terminator is read but not rewritten by this loop. No length bound is present. A non-terminated sequence can cause reads and writes beyond valid storage.

The translation-table address is captured once for the loop. Its contents are not copied or protected against other mutation.

### 4. Callback invocation and post-call dependency

After translation finishes, the function changes the selected upper result component to the address of its local auxiliary-value slot.

It then invokes the callback using:

1. The saved interface address.
2. The auxiliary input by value.
3. The translated sequence address.
4. The address of the local pointer slot initially containing the descriptor address.

The fourth argument permits the callback to replace that local pointer value. A subsequently created replacement record receives the value left in this slot.

The callback address is read again from offset 72 of the saved dispatch base at invocation time. The earlier nonzero check does not freeze that address. In particular, F-8ad0042eaec1 runs between the check and invocation, and its effects are unknown. The function does not repeat the nonzero check after reloading the callback address.

After a normal callback return, F-94cb53877c15 is called with the translated sequence address. This happens before testing whether the callback returned zero.

The post-callback dependency is therefore invoked for both callback acceptance and rejection. Its name and implementation are unavailable; calling it a release operation is inferred intent, not an established ownership fact.

A zero callback result leads to fallback after that call. A nonzero callback result permits replacement construction. If either call does not return normally, no later behavior is guaranteed by this function.

### 5. Replacement construction

Following a nonzero callback result, the function:

1. Calls F-1cb585febd84 with the original-record address plus 28.
2. Adds 32 to the returned 32-bit value.
3. Calls F-f053f140662a with the context and that adjusted value.
4. Tests its returned address for zero.

A zero address produces fallback. A nonzero address triggers the following operations in order:

1. Invoke the unmapped copy dependency with the new address, original-record address, and count 32.
2. Call F-1cb585febd84 again with the original-record address plus 28.
3. Invoke the same copy dependency with destination equal to new address plus 28, source equal to original-record address plus 28, and count equal to this second result plus one.
4. Write the current local descriptor-slot value at replacement offset 16.
5. Write the saved auxiliary value at replacement offset 8.
6. Read the byte at replacement offset 4 and write it back with bit `0x04` set.
7. Return the new address in the low result component.

The apparent layout is a 32-byte header with sequence storage beginning at offset 28. Thus, the second copy-like operation starts four bytes before the end of the first operation’s nominal destination range. This overlap in destination regions is part of the observed call sequence, not a reason to move the sequence start to offset 32.

The two F-1cb585febd84 calls are separate. The second occurs after the first copy-like call. There is no check that their results agree.

The requested amount is the first result plus 32, while the later sequence-copy count is the second result plus one. If the dependency measures byte length and both results equal a nonnegative value \(L\), the nominal copied sequence ends at replacement offset \(28 + L\), inclusive. The requested \(L + 32\) bytes cover that range. This conclusion depends on ordinary allocation and copying semantics, stable lengths, and non-overflowing arithmetic; none is enforced here.

## Side effects

Established direct effects include:

- Ordered reads through the descriptor, linked object, interface, and dispatch base.
- A global translation-table address read.
- In-place writes to every nonzero byte encountered before the input sequence terminator.
- A callback invocation that receives a writable local pointer slot.
- Direct replacement-field writes at offsets 16, 8, and 4 when construction reaches that stage.

Additional effects are dependency-controlled and unknown.

The function does not itself establish ownership of either the translated sequence or the replacement. It calls F-94cb53877c15 once after a normally returning callback, but that call does not prove deallocation. Likewise, a nonzero result from F-f053f140662a does not, by itself, prove a particular allocator, allocation extent, or caller release obligation.

No explicit cleanup call is made for a successful replacement before returning it.

Aliasing can affect outcomes. For example, the preparation dependency might return storage overlapping the original record, allowing translation to change data used later. Unknown callees may also mutate globals or reachable objects. The contract does not assume such preservation.

## Acceptance examples

These examples are conditional observations, not executed tests. They assume readable and writable memory for every reached access and normally returning dependencies unless stated otherwise.

1. **Absent descriptor.** With a zero descriptor address, neither descriptor memory nor any listed dependency is accessed. Both result components contain the original-record address.

2. **Wrong identifying byte.** With a readable descriptor whose first byte does not compare equal to −107, the linked-object field is not read. Both result components retain the original-record address.

3. **Disabled linked object.** A matching descriptor and nonzero linked-object address with eligibility byte zero cause fallback without reading the interface field.

4. **Missing prepared sequence.** If eligibility succeeds but F-8ad0042eaec1 returns zero, the translation-table address is still read. No translation, callback, or F-94cb53877c15 call occurs. Both result components retain the original-record address.

5. **Translation introduces a terminator.** Suppose the sequence contains bytes `0x41`, `0x42`, then zero, and the table maps `0x41` to zero. Both nonzero input positions are still translated. The callback receives an address whose first byte is now zero.

6. **Callback rejection.** After successful translation, a zero callback result is followed by F-94cb53877c15 and then fallback. The low component is the original-record address; the upper component is the selected local-slot address, not the original-record address.

7. **Replacement request fails.** With a nonzero callback result and a zero F-f053f140662a result, neither copy-like call nor any direct replacement-field write occurs. The result components follow the same pattern as callback rejection.

8. **Successful replacement with descriptor substitution.** If the callback changes its supplied pointer slot and replacement construction completes, replacement offset 16 receives that changed value. Offset 8 receives the saved auxiliary value, and bit `0x04` is set at offset 4 without directly clearing other bits.

9. **Unstable length-like results.** If the two F-1cb585febd84 results differ, the requested amount uses the first and the second copy count uses the second. There is no consistency check or compensating request.
