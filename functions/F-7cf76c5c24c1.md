# F-7cf76c5c24c1

## Purpose

The visible operation interleaves unresolved indirect calls with 8-bit and 32-bit memory accesses. It propagates scaled call results, writes selected fragments of packed values, uses bytes as absolute-address selectors, and clears several computed locations.

No domain-specific purpose is established. The accesses do not establish object initialization, serialization, device control, allocation, or any particular data structure.

This contract describes the visible path conditionally. Each later event requires all preceding calls to return and all preceding accesses to complete. The path ends at a bad-instruction boundary; neither successful execution of the entire sequence nor a normal return is established.

## Interface

### Explicit inputs

The displayed interface accepts four 32-bit arguments:

| Input | Established use |
|---|---|
| First argument | No explicit use appears. |
| Second argument | Passed to the first indirect invocation. |
| Third argument | No explicit use appears. |
| Fourth argument | Interpreted as unsigned, shifted right by three, and written in the first 32-bit store. |

Absence of explicit use does not establish that an argument is inaccessible through machine state or irrelevant to the actual executable.

### Implicit inputs

The operation also depends on:

- An additional machine result exposed by one later invocation.

The ordinary calling convention, preservation requirements, and means of supplying these implicit inputs are **documented_only**.

### Outputs and termination

No ordinary return value or normal return is established. The visible path terminates at a bad-instruction marker.

There is no displayed success status, recoverable failure result, validation branch, or rollback mechanism. Failure to complete an invocation or memory access prevents any guarantee about subsequent events.

### Widths and notation

The following descriptive terms apply throughout:

- **Word access:** a 32-bit read or write.
- **Byte access:** an 8-bit read or write.
- **Fourfold value:** four times a retained value.
- **Fragment:** the low eight bits of the unsigned value obtained by masking a 32-bit quantity with `0x3FFFFFFF` and shifting right by 20.
- **Reduced value:** the unsigned value obtained by masking a 32-bit quantity with `0x3FFFFFFF` and shifting right by one.

A fragment’s intermediate extraction can occupy ten bits; the destination retains eight. A reduced value lies between zero and `0x1FFFFFFF`, inclusive.

Byte reads produce values from zero through 255. Byte stores retain the destination’s eight-bit pattern.

Unsigned 32-bit multiplication and shifts retain a 32-bit result. Some other displayed address calculations and shifts use signed quantities; authoritative overflow and signed-shift semantics for the actual target are not established. Address expressions involving those operations are conditional on the target’s interpretation. Endianness, alignment requirements, and fault behavior remain unresolved.

## Behavior

### Invocation convention

A **five-call interval** consists of one indirect invocation with the stated explicit arguments, followed by four invocations with no explicit arguments shown. Unless otherwise stated, the interval result is the fifth invocation’s displayed result.

Each invocation is identified by the opaque occurrence ID `F-UNRESOLVED[n]`, with `n` increasing in execution order. This identifies an occurrence, not a known implementation. Different occurrences may or may not reach the same dependency.

“No explicit arguments shown” does not establish zero arguments, absence of implicit inputs, or preservation of memory and machine state.

The following phases specify ordering and retained data relationships. They do not permit combining calls, repeated reads, or stores.

### Initial input store and selector acquisition

The first five-call interval begins with the second argument. Its result selects the first word destination: four times that result plus `0x14`. The stored value is the unsigned fourth argument shifted right by three.

A second five-call interval begins with four times the first interval’s result. Its result becomes the **initial packed value**; its fourfold value becomes the **initial payload**.

Next, a byte is read at the implicit entry base plus one. The low eight bits of the initial payload are written to the absolute address equal to that byte plus `0x11`.

The following five-call interval begins with three arguments, in order:

- The byte just read, shifted right by three.
- The initial payload.
- The implicit entry base shifted left by two.

Its result becomes the **secondary index**.

The byte at the implicit entry base plus one is then read again. This second value becomes the retained **selector**. The fragment of the initial packed value is written to the selector plus `0x11`.

A five-call interval beginning with four times the secondary index follows. Its result is not used by the next visible store. That store writes the initial payload at four times the retained selector plus `0x14`.

The two entry-base byte reads are separate. Intervening calls may change the location, so the initial byte write and the fragment write need not select the same address. Later uses of the retained selector do not refresh it from memory.

### Scaled word propagation

A five-call interval begins with four arguments: the selector three times, followed by the selector shifted right by one. Its result selects a word destination at four times the result plus `0x14`; the initial payload is written there.

A five-call interval beginning with four times that destination index produces the **first self-index**. Its fourfold value becomes the **first self-payload**, which is written at sixteen times the first self-index plus `0x14`.

A five-call interval beginning with the first self-payload selects another word destination at four times its result plus `0x14`. The first self-payload is written there.

A five-call interval beginning with four times this new destination index produces the **second self-index**. Its fourfold value becomes the **second self-payload**, written at sixteen times the second self-index plus `0x14`.

Next come an invocation with the second self-payload, an invocation with no explicit arguments, and a five-call interval beginning with the second invocation’s result. At four times the interval result plus `0x14`, a word store writes the reduced value of the second self-payload.

A five-call interval beginning with four times that destination index produces the **third self-index**. Its fourfold value becomes the **third self-payload**, written at sixteen times the third self-index plus `0x14`.

The next access reads a word at the third self-payload plus `0x14`. Its unsigned value, shifted right by three, begins another five-call interval. The third self-payload is then written at four times that interval’s result plus `0x14`.

This read is not generally a read-back of the preceding self-store: the store uses sixteen times the self-index, while the read uses four times the self-index.

A five-call interval beginning with four times the latest destination index produces the **central value**.

### Selector propagation and byte clearing

Before another invocation, a word store writes the retained selector at:

`(selector shifted right by three) × 0x80000 + 0x24`.

Two retained quantities are derived from the central value:

- **Central base:** sixteen times the central value.
- **Reduced central value:** the reduced value of the central value, bounded by `0x1FFFFFFF`.

A five-call interval begins with the central base and four times the central value. Its result is not consumed by the next store, which writes the retained selector at central base plus `0x24`.

A word is then read at central base plus `0x74`. A five-call interval begins with that word and produces the **control value**.

A byte read at central base plus one selects an absolute destination at the read byte plus `0x11`. The fragment of the central value is written there.

An invocation with four times the control value follows, then an invocation with no explicit arguments, then a five-call interval beginning with the second invocation’s result. Its result is retained. The byte at central base plus one is read again, and zero is written to the newly selected address plus `0x11`.

A five-call interval begins with four times the retained interval result. Its result is not used by the next accesses:

- Zero is written as a byte at reduced central value plus `0x0F`.
- The **clearing base** is derived as reduced central value multiplied by `0x400`.
- A byte at clearing base plus one is read, selecting a zero-byte destination at that byte plus `0x11`.

The following invocation receives four arguments: the control value shifted left by 23 three times, followed by the control value shifted left by 25. An invocation with no explicit arguments follows, then a five-call interval beginning with that invocation’s result.

The byte at clearing base plus one is read again. This value becomes the retained **clearing selector**, and zero is written at clearing selector plus `0x11`.

A five-call interval beginning with four times the preceding interval result follows. Two word stores then occur, in order:

1. Zero at clearing selector plus `0x44`.
2. Zero at absolute address `0x24`.

The clearing selector remains the earlier byte value despite the intervening calls.

### Repeated word clearing

The next invocation receives `(0, 0x98, clearing base, 0x98)`. It is followed by:

- An invocation with no explicit arguments.
- An invocation with that result.
- An invocation with no explicit arguments.
- A five-call interval beginning with the latest result.

Two word stores follow: zero at four times the interval result plus `0x44`, then zero at absolute address `0x24`.

A five-call interval beginning with four times that destination index produces a displayed 64-bit result. Its low and high 32-bit halves have different uses.

An invocation receives four times the low half. After it, zero is written as a word at twice the retained high half plus `0x44`, followed by another zero-word store at absolute address `0x24`. The high half comes from the preceding 64-bit result, not from this intervening invocation.

That intervening invocation also exposes an additional machine result. The next invocation receives zero, that additional result, and its fourfold value. An invocation with no explicit arguments follows.

The **masked reduced value** is the reduced central value masked with `0x3FFFFF`. Its range is zero through `0x3FFFFF`.

A five-call interval begins with the masked reduced value shifted left by seven. Zero is written at four times its result plus `0x44`, followed by zero at absolute address `0x24`.

A five-call interval beginning with four times that destination index follows. Another invocation receives four times the interval result. This invocation’s result becomes the **clear index**. Zero is written at four times the clear index plus `0x14`.

A five-call interval then begins with the clear index three times and the masked reduced value shifted left by seven. Zero is written at four times its result plus `0x14`.

There are four explicit zero-word stores to absolute address `0x24` in the visible path. Computed destinations may also alias that address; such aliasing does not merge the events.

### Final word propagation

A five-call interval begins with four times the preceding destination index. Four times its result is written at sixteen times that result plus `0x14`.

A five-call interval beginning with that retained payload selects a destination at four times its result plus `0x14`. The same payload is written there.

A five-call interval beginning with four times the new destination index produces another result. Its fourfold value is written at sixteen times that result plus `0x14`.

The next invocation receives four times and sixteen times this most recent result. An invocation with no explicit arguments follows. A five-call interval then begins with that invocation’s result and the masked reduced value shifted left by four.

At four times the interval result plus `0x14`, a word store writes the masked reduced value multiplied by `0x80`. This product is at most `0x1FFFFF80` and requires no 32-bit overflow.

### Final byte propagation and terminal boundary

A five-call interval beginning with four times the latest word-destination index produces the **late packed value**. The **late base** is the reduced central value multiplied by `0x4000000`, retaining the unsigned 32-bit product.

A byte read at late base plus one selects a destination at the read byte plus `0x11`. The low eight bits of four times the late packed value are written there.

An invocation with four times the late packed value follows, then an invocation with no explicit arguments, then a five-call interval beginning with the latter result.

The byte at late base plus one is read again. The fragment of the late packed value is written at this new selector plus `0x11`.

A five-call interval beginning with four times the preceding interval result produces the **last packed value**. Another byte read at late base plus one selects the destination for the low eight bits of four times the last packed value.

The next invocation receives the byte just read, widened to 32 bits. An invocation with no explicit arguments follows, then a five-call interval beginning with that invocation’s result.

The final selector read uses a different address: eight times the last packed value plus one. The fragment of the last packed value is written at this selector plus `0x11`.

A final five-call interval begins with four times the preceding interval result. The supplied path then reaches the bad-instruction boundary. No subsequent behavior is established.

## Side effects

### Memory and ordering

The reads, writes, and invocations occur in the stated order, conditional on continued execution.

A byte-selected destination formed by adding `0x11` is an absolute address between `0x11` and `0x110`, inclusive. No separate object base is shown.

The word store selected by clearing selector plus `0x44` begins between `0x44` and `0x143`, inclusive, and may be unaligned.

Unknown dependencies may modify memory between accesses. Therefore:

- Repeated selector reads must remain distinct.
- Retained selectors must not be replaced with later reads.
- Repeated stores must not be discarded as redundant.
- Computed addresses may alias other destinations or future read locations.
- A visible store does not establish the location’s value at termination, because later dependencies may change it.

The representation does not establish atomicity, synchronization, volatile semantics, or a device-memory interpretation.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Unsigned input reduction.** With fourth argument `0xFFFFFFFF`, the first word store carries `0x1FFFFFFF`, if execution reaches it.

2. **Byte truncation versus word payload.** An initial packed value of `0x43` produces initial payload `0x10C`. Its first byte store carries `0x0C`; subsequent word propagation uses `0x0000010C`.

3. **Separate initial selectors.** If the first entry-base byte read yields `0x20` and the second yields `0x30`, the corresponding byte destinations are `0x31` and `0x41`. The retained selector is `0x30`.

4. **Fragment width.** For packed value `0x3FF00000`, masking and shifting produce intermediate value `0x3FF`; the byte written is `0xFF`. Packed value `0xC0000000` produces a zero fragment.

5. **Different self-store and read addresses.** A third self-index of two produces payload eight, stored at `0x34`. The following word read is at `0x1C`, not `0x34`.

6. **Fresh versus retained selectors.** If a dependency changes the byte at central base plus one, the later zero-byte store uses the fresh read. Conversely, changing clearing base plus one after acquisition of the clearing selector does not change the subsequent word destination at retained clearing selector plus `0x44`.

7. **Partial progress.** If execution stops after the first explicit zero store at `0x24`, the remaining three explicit zero stores and the terminal boundary are not guaranteed. No rollback is established.

8. **Reachable reduced-value boundary.** Central value `0x3FFFFFFE` produces reduced central value `0x1FFFFFFF`, its maximum. Masking that value with `0x3FFFFF` produces `0x3FFFFF`; multiplication by `0x80` produces `0x1FFFFF80`.

9. **Final selector-base change.** The first three late selector reads use late base plus one. The fourth uses eight times the last packed value plus one. Equality of those addresses is not guaranteed.
