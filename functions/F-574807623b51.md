# F-574807623b51

## Purpose

F-574807623b51 copies a prefix of a character sequence into caller-supplied storage. Copying stops at the first zero-valued source character or the first character equal to any of three externally configured delimiter characters.

The destination receives a terminating zero character. A matched delimiter is consumed from the source but is not copied. A source terminator is not consumed. The return value identifies the resulting source position.

On every normal completion with a non-null source, the function also adds its integer argument to an externally referenced accumulator. That argument is **not a destination capacity, copy limit, or automatically calculated character count**.

These behaviors are established by the supplied static representation. A possible token-extraction purpose is inferred intent, not an additional contract.

## Interface

### Arguments

1. **Destination address**
   - Identifies the first character-sized destination location.
   - For a non-null source, storage must support all ordinary-character writes plus one terminating-zero write.
   - There is no capacity argument and no destination-bounds check.
   - For a null source, the destination is not dereferenced and need not designate writable storage.

2. **Accumulator adjustment**
   - Presented as a signed integer argument.
   - Used only in the accumulator update at normal completion.
   - Does not control copying, delimiter recognition, or source advancement.
   - Positive, zero, and negative values are not distinguished by explicit validation or branching.

3. **Source address**
   - Either null or the address of the first character to examine.
   - For a non-null source, readable storage must extend through every character examined before stopping.
   - A zero character or a matching delimiter must eventually be encountered for normal termination.

### External state

The function uses four externally stored pointer bindings:

- A **first delimiter binding**, identifying one character-sized delimiter location.
- A **second delimiter binding**, identifying another such location.
- A **third delimiter binding**, identifying another such location.
- An **accumulator binding**, identifying the storage updated at completion.

The three delimiter pointer values are captured at entry. Their pointed-to characters are not captured together at entry; they are read during scanning, subject to short-circuit conditions.

The accumulator binding is used during completion rather than captured alongside the delimiter bindings.

### Result

- With a null source: returns a null pointer.
- After encountering a zero source character: returns the address of that character.
- After encountering a delimiter: returns the address immediately following that delimiter.

The result is a source-position pointer, not the destination address or a newly allocated string.

### Widths and layout

Source and destination accesses operate on single character-sized elements. Source and destination advancement is by one such element. The destination layout is the copied sequence followed immediately by one zero-valued character; no length field, padding, or other metadata is produced.

The representation uses a character type and a signed integer type, but does not independently establish their bit widths. An eight-bit character and a 32-bit integer are plausible target assumptions, not proven requirements. No multibyte encoding, Unicode interpretation, or locale-dependent comparison is established.

The accumulator’s storage type and width are absent from the supplied declarations. Consequently, its conversion rules, overflow behavior, alignment requirements, and write width cannot be specified exactly from this evidence.

## Behavior

### Entry and null-source handling

The visible entry sequence obtains the third delimiter pointer, then the second delimiter pointer, then the first delimiter pointer. These pointer-value accesses precede the null-source check.

If the source is null, the function returns null immediately after that check:

- No source character is read.
- No destination character is written.
- No delimiter character is dereferenced.
- The accumulator is not updated.

This is not an entirely external-state-free path: the three delimiter pointer bindings are accessed first. Null values stored in those bindings do not themselves require dereferencing on this path, although the bindings must be accessible.

The ordering above is established at the level of the supplied representation. Exact machine-load behavior for non-volatile storage is not independently established.

### Source examination and delimiter precedence

For a non-null source, each iteration first reads the current source character.

If that character is zero, scanning stops without consulting any delimiter character.

For a nonzero source character, comparisons occur in this priority order:

1. Read the character through the captured first delimiter pointer and compare it with the source character.
2. Only if the first comparison does not match, read through the captured second delimiter pointer and compare.
3. Only if neither earlier comparison matches, read through the captured third delimiter pointer and compare.

A match against any delimiter stops scanning. The return value does not identify which delimiter matched.

This short-circuit behavior affects required readable storage. An invalid second delimiter pointer is not dereferenced when the first delimiter matches. Neither the second nor third delimiter location is read when the source character is zero.

Duplicate delimiter values are permitted by the visible logic. A delimiter value of zero adds no distinct stopping behavior: a zero source character takes the source-terminator path before delimiter comparisons.

### Ordinary-character copying

When a nonzero source character matches none of the three delimiter characters:

- The source position advances by one character.
- The previously read source character is written to the current destination position.
- The destination position advances by one character.
- Scanning continues.

The character written is the character already read for that iteration. A write that changes the original source location does not change that saved character, although it can affect later reads.

There is no pre-scan, capacity check, or bulk-copy operation in the visible behavior. Ordinary characters are copied incrementally.

### Stopping on a delimiter

When a source character matches a delimiter:

- That character is not copied.
- The source position advances by exactly one character.
- A zero character is written at the current destination position.
- The accumulator update is performed.
- The advanced source position is returned.

Exactly one delimiter is consumed per invocation. Consecutive delimiters are not skipped as a group.

A delimiter at the initial source position therefore produces an empty destination sequence and returns the next source position.

### Stopping on a source terminator

When the current source character is zero:

- The source position remains at that character.
- A zero character is written at the current destination position.
- The accumulator update is performed.
- The unchanged source position is returned.

An initially empty source still causes a destination terminator write and an accumulator update.

### Accumulator update

The destination terminator is written before the accumulator update.

The visible update adds the supplied integer adjustment to the value reached through the accumulator binding and stores the result back through that binding. It occurs once on each normal non-null-source completion, irrespective of:

- How many characters were copied.
- Whether any characters were copied.
- Whether stopping resulted from a delimiter or a source terminator.
- Whether the adjustment is positive, zero, or negative.

A zero adjustment does not bypass the update expression.

The evidence does not establish wrapping, checked arithmetic, saturation, or a defined result for overflow. Those properties depend on the unavailable accumulator type and target arithmetic rules.

## Side effects

### Destination writes

For an execution that copies \(n\) ordinary characters and completes normally, the function makes \(n\) ordinary-character writes followed by one terminating-zero write.

It does not intentionally clear the remaining destination storage. It does not enforce a destination size or reserve capacity based on the integer argument.

### External-state reads and writes

Delimiter pointer bindings are captured once at entry. Their pointed-to character values are consulted repeatedly as scanning proceeds, only when required by comparison precedence.

Consequences include:

- Changing a delimiter binding after capture does not redirect the captured pointer.
- Changing a character at a captured delimiter location can change later comparisons.
- Destination writes can change later delimiter recognition if destination storage aliases a delimiter location.

The accumulator update occurs after the destination terminator write. If that write aliases the accumulator binding or accumulator storage, the update can observe the resulting modification. The evidence is insufficient to promise preservation of overlapping external state.

### Aliasing

No overlap detection or overlap-safe copy guarantee is present.

With identical source and destination addresses, ordinary-character writes place each saved character back at its original position. At a delimiter, however, the terminating-zero write replaces that delimiter while the returned pointer still points immediately after it.

Other overlaps may change source characters before they are examined. In particular, a destination located ahead of the source can overwrite unread source data. No snapshot-of-input semantics or termination guarantee should be assumed for such arrangements.

The return value records an address, not a promise about the final contents at that address. Aliased destination or accumulator writes may change source storage before return.

### Ownership and failure behavior

No allocation, deallocation, or ownership transfer is visible. The caller retains ownership of supplied storage and must maintain the lifetime of any storage accessed through external bindings.

There is no explicit error result for insufficient capacity, inaccessible memory, missing terminators, invalid delimiter pointers, invalid accumulator storage, or arithmetic failure. Null source is the only explicit early-return condition.

If an access fails after copying has begun, earlier destination writes may already have occurred. No rollback or transactional guarantee is established.

## Acceptance examples

These examples are conditional predictions from static evidence, not runtime observations. Unless stated otherwise, assume valid non-overlapping storage, stable delimiter characters, sufficient destination capacity, and an accumulator addition that is representable under the actual arithmetic rules.

Use comma, semicolon, and vertical bar as the first, second, and third delimiter values.

### Ordinary prefix followed by a delimiter

For a source containing `alpha,beta` followed by a zero character:

- The destination becomes `alpha` followed by zero.
- The comma is consumed but not copied.
- The return value points to the `b` in `beta`.
- An adjustment of 7 adds 7 to the accumulator, not 5 and not 6.

### Source terminator before any delimiter

For `alpha` followed by zero:

- The destination receives the five ordinary characters and a zero.
- The return value points to the original source terminator.
- The accumulator update still occurs.

### Leading delimiter

For `;beta` followed by zero:

- The destination receives only a zero.
- The return value points to the `b`.
- The accumulator is adjusted despite zero ordinary characters being copied.

For `,,beta` followed by zero, one invocation returns the position of the second comma. It does not skip both commas.

### Empty source

For an initial zero source character:

- The destination receives a zero.
- The return value equals the supplied source address.
- No delimiter character is read.
- The accumulator is adjusted.

### Null source

With a null source:

- The result is null.
- Destination storage remains untouched by this function.
- The accumulator remains untouched by this function.
- Delimiter pointer bindings are accessed, but their target characters are not.

### Integer argument is not a capacity

For `abc` followed by zero and an adjustment of zero:

- All three ordinary characters and the terminating zero are written.
- The accumulator update expression still executes.
- No truncation occurs.

An adjustment of 1 likewise does not restrict the destination to one character.

### Short-circuited delimiter access

If the source begins with comma and the first delimiter is comma:

- The second and third delimiter characters are not read.
- The destination becomes empty.
- The return value advances one character.

This example does not establish that invalid later delimiter pointers are safe for other source contents.

### Identical source and destination

For writable shared source/destination storage containing `ab,cd` followed by zero:

- The `a` and `b` remain in place.
- The comma is overwritten with zero.
- The return value points to `c`.
- The accumulator update follows the zero write.
