# F-9265dc5f2247

## Purpose

F-9265dc5f2247 conditionally selects an indexed record through a descriptor, submits a candidate address to a checking dependency, and, on acceptance, publishes a recomputed address in caller-supplied output storage.

The established behavior includes:

- Rejecting an initially zero object reference or zero gate byte.
- Comparing the original unsigned index with a first dependency-provided inclusive bound.
- Conditionally transforming the index based on a **32-bit descriptor-word evaluation narrowed to a character value**.
- Comparing the effective index with a second dependency-provided inclusive bound.
- Constructing a candidate address using a 40-byte stride.
- Accepting only a checking result equal to 1.
- Writing an output marker before rereading the descriptor and publishing the resulting address.

The initial byte access and later word evaluation are distinct operations with different source-level access requirements. They must not be collapsed into two reads of the same byte.

**Inferred intent:** The function appears to select and validate a record, optionally mapping a logical index to an odd-numbered physical entry. Record semantics, ownership, and lifetime are not established by that interpretation.

## Interface

### Arguments

The function receives three arguments.

| Argument | Representation and use |
|---|---|
| Descriptor address | Address used for a 32-bit object-reference read at offset 0, an initial 8-bit gate read at offset 4, and, on a later path, a 32-bit word evaluation at offset 4. The object reference is read repeatedly. |
| Requested index | Unsigned 32-bit value. Used unchanged for the first bound comparison, then potentially transformed for subsequent operations. |
| Output address | Address receiving a 32-bit record address at offset 0 and an 8-bit marker at offset 4 on success. |

The descriptor accesses at offset 4 overlap but differ in width:

- The initial gate explicitly accesses **one byte** at offset 4.
- After the first bound comparison passes, the selection condition evaluates a **32-bit word** beginning at offset 4, narrows its value to a character, and compares that character with 2.

Thus, the later source-level expression requires a readable four-byte word at offsets 4–7, not merely the single byte required by the initial gate. This describes the supplied representation’s access requirements. It does **not** establish whether an executable performs a four-byte hardware load, a narrower optimized load, or another equivalent instruction sequence.

The descriptor contents are not captured as one immutable snapshot.

### Referenced storage

A current object reference is used to read a 32-bit table-base field at object offset 20.

The record-address calculation is:

**table base + effective index × 40**

The 40-byte stride is established. Record contents, alignment, allocation extent, and whether adjacent entries are independently allocated are not established.

The output layout is only partially defined:

| Output offset | Width | Successful write |
|---|---:|---|
| 0 | 32 bits | Recomputed record address |

The function does not initialize output bytes beyond those fields. No larger output-structure size is established.

### Return value

The return value is a 32-bit status.

| Status | Condition |
|---:|---|
| 0 | The checking dependency returned exactly 1 and the success-path writes completed. |
| 8 | Either unsigned bound comparison failed. |
| 17 | The initial object reference was zero, or the initial gate byte was zero. |
| 20 | The checking dependency returned a value other than 1. |

These are numeric results, not established names from an external error-code system.

### Access preconditions

The descriptor must support every access reached on the selected path. A null descriptor address is not handled as an empty descriptor: the function first reads through that address.

Path-specific requirements differ:

- An initially zero object reference returns before accessing descriptor offset 4.
- A nonzero initial object reference requires the byte access at offset 4.
- Passing the first bound comparison reaches the four-byte word evaluation at offset 4, even though only a narrowed character value determines the branch.

Paths reaching address construction require the current object reference to support the table-base read at offset 20. The computed candidate must satisfy whatever access requirements F-2fb175a232ca imposes.

The output address is directly accessed only on success. It must then support the marker write followed by the address-word write.

No explicit checks establish alignment, allocation size, synchronization, address validity, or storage lifetime. Invalid accesses and abnormal dependency termination are not assigned normal status returns by the supplied evidence.

## Behavior

### Initial gate

The function first reads the descriptor’s 32-bit object reference.

If that value is zero, it returns 17 without reading the gate byte, calling either dependency, or directly accessing the output.

Otherwise, it reads one byte at descriptor offset 4. A zero byte causes return 17. Every nonzero byte passes this gate; no narrower enumeration of permitted values is enforced.

The requested index does not affect this gate. Index zero is permitted.

### First bound comparison

After the gate passes, the function calls F-e84094e554a6 with the object reference obtained by the initial descriptor read.

The returned value is interpreted as an unsigned 32-bit bound. The original requested index must be less than or equal to that bound.

If the index is greater, the function returns 8. This path does not reach the later descriptor-word evaluation, second bound call, candidate check, or direct output writes.

Equality passes. Consequently, the bound cannot be described unconditionally as a conventional element count with an exclusive upper limit.

### Word-based selection and index transformation

After the first comparison passes, the function evaluates the 32-bit descriptor word beginning at offset 4. It narrows that word’s value to a character and compares the result with 2.

If the narrowed character equals 2, the effective index becomes:

**(2 × requested index + 1) modulo 2³²**

Otherwise, the effective index remains the original requested index.

The character comparison does not compare the entire word with 2. Under the represented 8-bit narrowing model, a word whose low-order eight bits are 2 selects the transformation even when its higher bits are nonzero. Whether the character is treated as signed or unsigned does not change equality with the representable positive value 2.

The later evaluation is not another explicit one-byte access. It also must not be identified unconditionally with the byte at the lowest addressed position of the word: that relationship depends on byte order.

There is no repeated nonzero gate. A later narrowed value of zero selects the untransformed index rather than producing status 17.

Because the first dependency executes before this evaluation, changes it makes to descriptor offsets 4–7 can affect the selection condition. The original gate byte does not permanently determine whether transformation occurs.

### Second bound comparison

The function rereads the descriptor’s 32-bit object reference and calls F-e84094e554a6 with that current value.

The effective index must be less than or equal to the second unsigned 32-bit bound. A greater value causes return 8.

This call occurs whenever the first comparison passes, regardless of whether the index was transformed. It is not behaviorally redundant:

- The effective index may differ from the original index.
- The descriptor may now reference a different object.
- The dependency may return a different bound.
- The dependency may have side effects.

There is no new zero-reference gate before this call. If the descriptor reference has become zero, zero is passed to the dependency.

### Candidate construction and checking

After the second comparison passes, the function again reads the descriptor’s object reference. Through that reference, it reads the 32-bit table-base field at offset 20.

The byte displacement is:

**(effective index × 40) modulo 2³²**

The candidate address combines that displacement with the table base in the represented 32-bit address model. Overflow is not rejected. In that model, the resulting address is the low 32 bits of the sum.

These arithmetic rules do not establish that a wrapped address designates valid storage. The function performs no separate overflow, extent, or alignment check.

The candidate address and a fixed static-data argument are passed to F-2fb175a232ca.

Only a result equal to 1 is accepted. Any other result causes return 20, including zero and other nonzero results.

The static-data argument’s contents and meaning are unavailable. It must not be described as a particular string, type name, signature, or validation rule.

### Success publication

When F-2fb175a232ca returns exactly 1, the function performs the following operations in order:

1. Writes the byte value 1 at output offset 4.
2. Rereads the descriptor’s 32-bit object reference.
3. Reads the current referenced object’s 32-bit table-base field at offset 20.
4. Recomputes the address using the retained effective index and 40-byte stride.
5. Writes the resulting 32-bit address at output offset 0.
6. Returns 0.

The effective index is retained; the selection word is not evaluated again.

The published address is recomputed rather than copied from the checked candidate. If the checking dependency changes the descriptor or table-base field, the published address can differ from the checked address.

The marker write itself can also affect subsequent reads when storage aliases. No atomic publication or all-or-nothing update is established. If an abnormal access occurs after the marker write, the marker may already have changed without a completed address write or normal return.

## Side effects
