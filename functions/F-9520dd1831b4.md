# F-9520dd1831b4

## Purpose

F-9520dd1831b4 selects a 64-bit result from a caller-supplied record. A 32-bit control word selects one of four behaviors, in descending priority:

1. Return a stored 64-bit bit pattern.
2. Construct a result from a stored signed 64-bit integer.
3. Attempt a dependency-mediated operation using an initialized local result area.
4. Return a pair of external fallback words.

Static evidence supports interpreting the integer branch as signed-integer-to-IEEE-754-binary64 conversion with round-to-nearest, ties-to-even. However, some normalization shifts have counts at least 32, and their target semantics are not supplied. Unconditional equivalence to that floating-point conversion therefore remains unresolved.

The function returns only a 64-bit bit pattern. It provides no separate status indicating whether that pattern came from stored data, integer conversion, a dependency, or fallback storage.

## Behavior

### Selection and precedence

The function first reads the complete 32-bit control word at offset 28. That captured value determines the branch:

| Initial control condition | Behavior |
|---|---|
| Bit 3 set | Return the stored result. |
| Bit 3 clear and bit 2 set | Execute the integer branch. |
| Bits 3 and 2 clear, and either bit 1 or bit 4 set | Execute the dependency-mediated branch. |
| Bits 1, 2, 3, and 4 all clear | Return the external fallback pair. |

Other bits do not affect visible selection.

Selection is not repeated after dependency execution. A dependency changing the control field cannot cause this invocation to switch to the stored-result or integer branch.

### Stored-result branch

The function reads the low result word at offset 8, then the high result word at offset 12, and returns their concatenation.

This branch makes no visible record write, fallback-word access, or dependency call. It does not inspect the integer fields.

The two field reads are separate. No atomic 64-bit access or coherent-snapshot guarantee is established.

### Integer branch

The function reads the low integer word at offset 0, followed by the high integer word at offset 4. The original high word’s bit 31 supplies the result sign.

The input interpretation is a signed 64-bit two’s-complement integer. Word arithmetic is 32-bit modular arithmetic unless a carry or wider concatenation is explicitly described.

#### Negative-input magnitude

For a nonnegative input, the two words already supply the magnitude.

For a negative input:

- The magnitude’s low word is the original low word negated modulo \(2^{32}\).
- The magnitude’s high word is the **negation of the sum** of the original high word and an indicator, modulo \(2^{32}\).
- The indicator equals 1 when the **original** low word is nonzero, and 0 otherwise.

Equivalently, if the original words are \(H\) and \(L\), the magnitude high word is
\[
-\bigl(H+\mathbf{1}_{L\ne0}\bigr)\pmod{2^{32}}.
\]

The indicator is inside the negation; it is not added after negating the high word.

This construction supports the magnitude \(2^{63}\) for the most-negative signed input without requiring a positive signed 64-bit intermediate. The original sign remains available separately.

#### Zero and normalization

If both magnitude words are zero, the returned pattern is all zero. This path does not construct negative zero.

For a nonzero magnitude, normalization uses the high magnitude word when it is nonzero; otherwise it uses the low magnitude word. Leading-zero counting is applied only to that selected nonzero word.

The normalization adjustment is:

- 32 minus the selected word’s leading-zero count when the high magnitude word is selected.
- Zero minus that count when only the low magnitude word is nonzero.

The adjustment participates in 32-bit modular arithmetic. Normalization combines the selected word and low magnitude word into upper and lower working words, and the adjustment contributes to the constructed exponent.

The visible shift-count expressions retain only their low eight bits. This is not evidence that counts are reduced modulo 32. Counts at least 32 occur, so the target’s actual shift behavior is necessary to establish every integer result.

#### Precision and rounding

The lower normalized word supplies the rounding information:

| Bit positions | Role |
|---|---|
| 0–9 | Information below the halfway bit. |
| 10 | Halfway bit. |
| 11 | Least significant retained bit before rounding. |

The rounding increment is one precisely when bit 10 is set and either:

- At least one of bits 0–9 is set; or
- Bits 0–9 are all clear and bit 11 is set.

Otherwise the increment is zero. This is the round-to-nearest, ties-to-even decision pattern.

Result construction combines retained portions of the normalized words. It detects carry from assembling the low result word and carry from adding the rounding increment, incorporating a carry into the high result word. Rounding carry is therefore not simply discarded.

Under the intended binary64 normalization semantics, the branch retains 53 significant bits, represents exactly representable integers exactly, rounds other integers to nearest with even halfway selection, and permits rounding to advance the exponent.

No floating-point rounding-mode query or floating-point arithmetic operation is visible. This branch performs no visible record write and invokes no dependency.

### Dependency-mediated branch

This branch first reads the external low fallback word, then the external high fallback word, into a local two-word result area. Those saved values initialize the result used if the final dependency is reached.

It then rereads the complete control word at offset 28. From that later read, it takes the numeric low 16 bits, sets bit 1, and performs a 16-bit write at offset 28.

That write must occur before F-98085658bfd4 is called. The function then calls F-98085658bfd4 with:

- The record pointer.
- The 32-bit value 1.
- The original third argument.
- The original fourth argument.

If F-98085658bfd4 returns nonzero, no further dependency is called. The function returns newly read external fallback words.

If F-98085658bfd4 returns zero, the function calls F-94f17d1d24a0 with the record pointer. A nonzero result likewise skips the final dependency and returns newly read external fallback words.

Only if both checks return zero does the function read the 32-bit field at offset 20 and pass it, together with the address of the initialized local result area, to F-d920a917d399. The offset-20 read therefore occurs after both checking calls. It can observe changes those calls made to that field.

After F-d920a917d399 returns, the function returns the local result words. It does not visibly inspect that dependency’s return value or reread the external fallback words.

If the final dependency leaves a result word unchanged, that word retains its initialized value, provided no other indirect action has altered the local storage. The visible body does not establish what the dependency actually writes.

### Fallback return

The function returns the external fallback pair when no branch-selection bit applies, or when either checking dependency returns nonzero.

On a dependency rejection path, the returned words are read after the relevant calls. They are not necessarily the values saved before those calls. Dependency changes to external fallback storage can therefore affect the rejection result.

The relative read order of the two words in the final fallback-return expression is not established by the supplied representation. No atomic-pair guarantee is visible.

## Side effects

### Control-field write

The only explicit write to caller-provided storage is the 16-bit write at offset 28 on the dependency-mediated branch.

At the moment of that write:

- The written value derives from the numeric low half of a fresh 32-bit control read.
- Bit 1 of the written value is set.
- Its other 15 bits match that numeric low half.
- The other two bytes of the four-byte field are not explicitly written.

On a little-endian target, this implements setting control bit 1 while preserving the other control bits, absent intervening mutation. On another byte order, the relationship between the numeric low half and the addressed halfword differs. Target byte order is not independently established.

**The function performs no explicit rollback of this write. That does not guarantee persistence of the written value.** Either checking dependency receives the record pointer and may overwrite the control field before returning, whether its result is zero or nonzero. No post-call control value is guaranteed by this body alone.

### Dependencies, storage, and ownership

The record pointer is passed to two dependencies. Their record mutations, global accesses, allocations, releases, and reentrant behavior are unknown.

F-d920a917d399 receives a pointer to local result storage, represented as a low 32-bit word followed by a high 32-bit word. That storage is not visibly heap-allocated. The enclosing function performs no visible allocation or release.

The supplied evidence does not establish that any dependency:

- Preserves the control field, other record fields, or globals.
- Owns, borrows, or releases an object represented by the offset-20 value.
- Writes both result words.
- Avoids retaining the result pointer.
- Returns normally.

The local result area does not provide a caller-owned persistent buffer. Any use of its address after this invocation requires a lifetime guarantee unavailable here.

## Acceptance examples

These are static acceptance conditions, not runtime observations.

### Stored-result precedence

With bits 3 and 2 both set initially, low stored word `0x89ABCDEF`, and high stored word `0x01234567`, the result must be `0x0123456789ABCDEF`.

No integer conversion or dependency call is selected, regardless of the other fields.

### Integer zero

With bit 2 set, bit 3 clear, and both integer words zero, the result must be `0x0000000000000000`.

Setting bits 1 or 4 as well does not select dependencies.

### Negative magnitude boundaries

For an integer input of −1, the original words are both `0xFFFFFFFF`. The magnitude must be low word `0x00000001`, high word `0x00000000`. The high-word calculation negates the modular sum of `0xFFFFFFFF` and 1.

For an input of \(-2^{32}\), the original low word is zero and high word is `0xFFFFFFFF`. The indicator is zero, producing magnitude low word zero and high word 1.

For \(-2^{63}\), the magnitude must be low word zero and high word `0x80000000`.

These magnitude conditions do not depend on resolving the subsequent large-shift semantics.

### Conditional binary64 results

Subject to the intended target normalization semantics:

| Signed input | Expected result pattern |
|---|---|
| 1 | `0x3FF0000000000000` |
| −1 | `0xBFF0000000000000` |
| \(2^{53}\) | `0x4340000000000000` |
| \(2^{53}+1\) | `0x4340000000000000` |
| \(2^{53}+3\) | `0x4340000000000002` |
| \(-2^{63}\) | `0xC3E0000000000000` |
| \(2^{63}-1\) | `0x43E0000000000000` |

The two halfway cases select the even representable integer. The final example rounds across an exponent boundary.

### First dependency returns nonzero

With only bit 4 set initially, the function must initialize the local result pair, perform the control halfword write, and then call F-98085658bfd4.

If that call returns nonzero:

- Neither remaining dependency is called.
- The function performs no explicit rollback.
- No persistence of the written control value is required: the dependency may have overwritten it.
- The result comes from fallback-word reads after the call.

### Second dependency returns nonzero

If the first check returns zero and the second returns nonzero, F-d920a917d399 must not be called. The returned fallback words are read after both checks.

Either check may have changed the control field; the function does not restore it.

### Local-result return

If both checks return zero and F-d920a917d399 writes low word `0x76543210` and high word `0xFEDCBA98`, the result must be `0xFEDCBA9876543210`.

If it changes only the low word, and nothing else alters the local high word, the returned high word is the fallback high word saved before the checking calls—not a later external value.

### No selected conversion

With bits 1, 2, 3, and 4 all clear, the function returns the external fallback pair without a visible record write or dependency call.
