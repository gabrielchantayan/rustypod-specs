# F-88567bb82e2a

## Purpose

F-88567bb82e2a repeatedly examines an object-associated condition, performs synchronization-related dependency calls, and dispatches commands selected through a global descriptor reference. A separate termination path conditionally writes three object fields, drains a resource through dependency calls, and returns.

Two exit forms are visible:

- Normal return after the termination-path drain yields zero.
- Transfer to F-feee9156a257 after an ordinary-path resource query yields nonzero. The supplied representation identifies this dependency as nonreturning.

“Termination,” “drain,” “context,” and “command” describe apparent roles, not established domain semantics. The available evidence does not define the underlying resource types, synchronization primitives, or command purposes.

## Behavior

### Main-loop selection

Every iteration begins with F-7f659ff345b7 receiving object +0x120.

- A nonzero result selects the termination-and-drain path.
- A zero result selects the ordinary path.

No iteration bound, timeout, or backoff is visible.

### Termination-and-drain path

The established sequence is:

1. Call F-338d16f9ce72 with object +0x10C.
2. Recheck through F-7f659ff345b7 with object +0x120.
3. If the recheck is nonzero, write the 32-bit pattern 0xFFFFFFFF to object +0x140, then +0x144, then +0x148.
4. Call F-1333331b2da1 with object +0x10C.
5. Repeatedly call F-08e7aeef99f4 with object +0x118.
6. For every nonzero result, treat it as an element address, read its word at +4, and call D-01 with that word.
7. When the resource query returns zero, return normally.

A zero recheck suppresses only the three stores. It does not return to ordinary processing or cancel the drain.

The stores are three distinct operations in increasing offset order, not an established atomic aggregate update. Calling their value a signed sentinel would be an interpretation rather than an additional established behavior.

Each element-field read follows its corresponding resource query. The next query follows the D-01 call, assuming that call returns. D-01 receives the element’s +4 field, not the element address itself. Neither disposal nor ownership transfer is established.

### Ordinary path

The established sequence is:

1. Call F-338d16f9ce72 with object +0x12C.
2. Query F-556b91bc9773 with object +0x120.
3. For each nonzero result, call F-162a41bac6a7 with object +0x134, then query F-556b91bc9773 again.
4. After a zero result, call F-08e7aeef99f4 with object +0x124.
5. If this result is nonzero, transfer to F-feee9156a257.
6. Otherwise, call F-1333331b2da1 with object +0x12C and proceed to descriptor observation and dispatch.

The nonzero branch at step 5 does not first call F-1333331b2da1 for object +0x12C. It does not pass the result to D-01 or process it as a command payload.

After a command handler returns, execution repeats the main loop. An unrecognized selector invokes no command-specific dependency and also repeats the loop.

### Descriptor observation sequence

After the ordinary-path F-1333331b2da1 call returns, the supplied representation exposes these distinct observations:

1. Read the global descriptor reference and retain that descriptor address for possible use by selectors 0x66000024 and 0x66000025.
2. Separately read the global descriptor reference and read the selector word at +4 of the descriptor obtained by this second observation.
3. For a selected payload-consuming command other than 0x66000024 or 0x66000025, read the global descriptor reference again to obtain the descriptor whose +0x0C field supplies the payload address.

The third observation applies to selectors 0x6600000D–0x6600000F, 0x66000011–0x66000015, 0x66000018, 0x66000019, 0x6600001B, 0x6600001F, 0x66000020, and 0x66000023.

Selectors without payload consumption have no corresponding payload lookup. The initial descriptor-reference retention still precedes selector selection even when the selected command does not use that retained address.

Selectors 0x66000024 and 0x66000025 instead use the address retained by the first observation. After object acquisition returns, they obtain the payload address from +0x0C of that retained descriptor.

Consequently, the retained indirect-command descriptor, selector-bearing descriptor, and ordinary payload-bearing descriptor are not required by the visible expressions to be the same observation or snapshot. This is a source-visible distinction, not proof of separate physical loads or a supported concurrent-mutation protocol.

### Payload timing across dependency calls

For single-byte and single-word context commands, the descriptor payload address and the payload value are obtained before context acquisition. The retained value is passed to the handler afterward.

Merely changing the global descriptor reference or the descriptor’s payload-address field during acquisition does not redirect these already-addressed reads.

For 0x66000023, the current root and ordinary payload word are obtained for the call without context acquisition. Their relative read order is not established.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests.

1. **Confirmed termination.** If both termination queries return nonzero and the drain immediately returns zero, the fields at +0x140, +0x144, and +0x148 receive 0xFFFFFFFF in that order. F-1333331b2da1 precedes the drain query and normal return.

2. **Cleared recheck.** If the first termination query is nonzero and the recheck is zero, no direct field stores occur. The function still performs the later synchronization-related call, drains, and returns.

3. **Two drain elements.** If the drain returns element addresses A, B, then zero, D-01 receives the word at A+4 and then the word at B+4. This does not establish release of A, B, or their field values.

4. **Ordinary wait and terminal transfer.** If the ordinary condition yields nonzero, nonzero, then zero, F-162a41bac6a7 is called twice before the resource query. If that resource query returns nonzero, F-feee9156a257 is reached without the ordinary-path F-1333331b2da1 call or command dispatch.

5. **Distinct descriptor observations.** If the source-visible retention, selector lookup, and ordinary payload lookup observe descriptors A, B, and C respectively, and B selects 0x66000012, the scalar comes from the payload identified by C, not necessarily A or B. This condition does not assert that concurrent mutation is supported.

6. **Retained indirect descriptor differs from selector descriptor.** If retention observes A and the separate selector observation sees B selecting 0x66000024, the post-acquisition payload lookup uses A’s +0x0C field. B supplies the selector, not that payload field.

7. **Low-byte reduction.** For 0x6600000D, words 0x123456AB and 0xFFFFFF02 yield arguments 0xAB and 0x02 after the context argument.

8. **Scalar captured before acquisition.** For 0x66000012, if the payload word is 7 when read and context acquisition changes it to 9, F-abbfbee5bb55 receives 7.

9. **Tuple read after acquisition.** For 0x66000020, changes during context acquisition to the two words at the retained payload address affect the subsequent arguments. Redirecting only a descriptor reference or payload-address field does not redirect those reads.

10. **Indirect lookup after acquisition.** For 0x66000025, changing the retained descriptor’s payload-address field during object acquisition affects the later lookup. Changing only the global descriptor reference does not.

11. **Mixed width and unknown selector.** For 0x66000019, the middle payload argument is the byte at +4, not a word including +5 through +7. For an unrecognized selector, no command handler is called; assuming returning dependencies, processing resumes with the next termination query.
