# F-64f588d0d937

## Purpose

F-64f588d0d937 selects one of two request bits in a shared control location, then polls a mode-dependent combination of status and control bits. Polling ends when either the observed bit condition ceases to require waiting or an external continuation check returns a nonzero result.

Every normally completing invocation returns the 32-bit value `1`. The return value does not distinguish an immediately satisfied condition from termination caused by the external check.

The interpretation as a device request followed by readiness polling is **inferred intent**. The established behavior is a read-modify-write, a dependency call, and an ordered polling loop. The supplied evidence does not establish the meanings of the bits, the time unit of the external check, or whether either termination path represents success.

## Interface

|---|---|---|
| First argument | Opaque 32-bit value | Not referenced by the visible function body. |
| Second argument | Signed 32-bit integer | Compared with zero. Zero selects one branch; every nonzero value selects the other. |

The second argument is not restricted to `0` and `1`. Negative values and positive values greater than one select the same nonzero branch.

No pointer interpretation, dereference, ownership transfer, or validation of the first argument is visible. Passing a particular bit pattern as that argument does not, by itself, cause the function to access an object at that address.

### Output

The result is a 32-bit value equal to `1`, provided execution reaches the return.

There is no visible alternative result for:

- A polling condition that is already satisfied on the first observation.
- A nonzero result from the external continuation check.
- Any number of repeated polling passes.

Normal completion is not guaranteed: the loop may continue indefinitely, and either external dependency may fail to return.

## Behavior

### Initial request update

The function first updates the control location. This occurs before calling either external dependency and before reading the status location.

When the second argument is zero, the function reads the control location, forms its bitwise OR with `0x400`, and writes that result back to the control location.

When the second argument is nonzero, it performs the corresponding operation with `0x200`.

At the logical value level, this sets the selected bit without deliberately clearing any bit present in the value read. It does not clear the other branch’s request bit. Consequently:

- A zero-mode invocation may leave both `0x400` and `0x200` set.
- A nonzero-mode invocation may also leave both set.
- If the selected bit was already set, the write is still represented in the visible behavior.

This is a read-modify-write, not an established atomic bit-set operation. A concurrent modification between the read and write may be overwritten. Device-specific write semantics could also differ from ordinary memory semantics; those semantics are not supplied.

After this update, the function calls dependency **F-000000000001** with no explicit arguments. It retains that dependency’s opaque 32-bit result for possible use in polling checks.

The function then enters the polling body at least once. It does not call the continuation-check dependency before the first polling pass.

### Common observation order

Each polling pass contains two ordered reads of the status location:

1. The first read determines whether status bit `0x80` has the branch-specific value that permits further waiting.
2. A second status read occurs regardless of the first read’s result.
3. If the first read permits further waiting, the function then reads the control location.
4. Only when both the status gate and the control-bit condition require continued waiting does it call **F-000000000002**.

The second status read does not determine the gate. When the gate permits waiting, its value is superseded by the subsequent control read. When the gate does not permit waiting, the control read and external continuation check are skipped, and the loop ends.

Thus, the second status read remains an observable access even though its value does not affect the visible continuation decision. This distinction matters if reads have side effects or another observer can distinguish access counts and ordering.

The first status observation and the later control observation are separate observations. They need not describe the same instant. The function does not visibly acquire a lock or obtain a coherent snapshot spanning both locations.

### Zero-mode polling

For a zero second argument, waiting is eligible to continue only when:

- The **first** status read in that pass has bit `0x80` set; and
- The subsequent control read has bit `0x08` set.

If either requirement is false, the loop ends without calling F-000000000002 on that pass.

If both requirements are true, the function calls F-000000000002 with:

- The opaque value previously returned by F-000000000001.
- The integer value `100`.

A zero result from this check causes another polling pass. Any nonzero result ends the loop.

### Nonzero-mode polling

For a nonzero second argument, waiting is eligible to continue only when:

- The **first** status read in that pass has bit `0x80` clear; and
- The subsequent control read has bit `0x08` clear.

If either requirement is false, the loop ends without calling F-000000000002 on that pass.

If both requirements are true, F-000000000002 receives the same retained opaque value and the integer value `100`. A zero result causes another pass; any nonzero result ends the loop.

The two branches therefore invert both tested bit conditions. They do not merely select different request bits while sharing one polling predicate.

### Completion and repeated checks

The result of F-000000000001 is obtained once per invocation that reaches that call. It is reused for every continuation check. The visible body does not refresh it between passes.

The value `100` is also unchanged between calls. No visible counter is incremented or decremented. There is no local arithmetic that independently enforces a maximum number of passes.

After a zero result from F-000000000002, the next pass rereads shared state. Changes made by that dependency, hardware, or another execution context can therefore affect the next decision. The function does not restore the initial control value or reassert the selected request bit on each pass.

Once the loop ends, the function returns `1` without a visible cleanup operation or final register write.

## Side effects

The direct shared-state effects visible in the function are:

- One initial control read and write that set the branch-selected request bit.
- Two status reads per polling pass.
- One additional control read on each pass whose first status observation permits waiting.

There is no visible write to the status location and no visible clearing of either request bit at completion.

External dependencies may have additional effects. In particular, the evidence does not establish that they preserve either shared location, other global state, device state, or execution-context state.

No allocation, explicit release, caller-buffer write, or ownership transfer appears directly in the function. That observation does not establish the memory behavior of its dependencies. The opaque value from F-000000000001 must not be characterized as an owned allocation, borrowed pointer, timestamp, or resource handle without additional evidence.

The function provides no visible synchronization, cancellation interface, diagnostic output, or separate error reporting. Whether interrupts, concurrency restrictions, or device access permissions are required is unknown.

## Acceptance examples

These are conditional acceptance scenarios derived from static evidence. They are not reports of executed tests. Values below describe logical observations; they do not assume ordinary-memory behavior for an unspecified device.

### Zero mode with immediate status termination

Assume the second argument is `0` and the initial control read yields `0x20`.

The initial control write must carry `0x420`. F-000000000001 is then called. If the first polling status read has `0x80` clear, another status read still occurs. There is no polling control read and no call to F-000000000002 on that pass. The function returns `1`.

### Zero mode with one continuation check

Assume the first status read has `0x80` set and the subsequent control read has `0x08` set.

F-000000000002 must be called after the two status reads and the control read, using the retained opaque value and `100`. If it returns `-1`, polling terminates and the function returns `1`; the negative result is not propagated.

### Zero mode with control-driven termination

Assume the first status read has `0x80` set but the subsequent control read has `0x08` clear.

The second status read and the control read occur. F-000000000002 is not called on that pass, and the function returns `1`.

### Nonzero mode with immediate status termination

Assume the second argument is `-7` and the initial control read yields `0x400`.

The initial write must carry `0x600`; the existing `0x400` bit is not cleared. If the first polling status read has `0x80` set, the second status read still occurs, but the polling control read and continuation check do not. The function returns `1`.

### Nonzero mode with repeated polling

Assume each pass first observes `0x80` clear and later observes control bit `0x08` clear.

Each pass reaches F-000000000002. If its first two results are zero, two further passes begin. If its third result is any nonzero value, the third pass terminates polling. All three calls use the same retained opaque value and `100`.

If those shared-state conditions remain true and every check returns zero, the visible logic permits indefinite polling.

### Status changes between the two reads

In zero mode, suppose the first status read has `0x80` set but the second has it clear.

The first read still permits the subsequent control read. If that control read has `0x08` set, F-000000000002 is called. The second status value does not revoke the gate.

Conversely, if the first status read has `0x80` clear and the second has it set, polling terminates without a polling control read. The later value does not reopen the gate.
