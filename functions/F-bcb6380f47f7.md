# F-bcb6380f47f7

## Purpose

F-bcb6380f47f7 updates selected bits in a memory word identified by a caller-provided descriptor. A zero selector requests clearing; a nonzero selector requests setting. In either case, bits outside the descriptor’s mask retain their values from the target word read during the call.

The effect is a read–modify–write operation, not a replacement of the entire word with the mask. The selector’s magnitude does not specify a bit position or a replacement value.

This contract describes static evidence. It does not establish atomicity, synchronization, device-register compatibility, or the application meaning of the selected bits. Interpreting the target as a flag word is reasonable inferred intent, not an established requirement.

## Interface

### Arguments and descriptor layout

The function accepts a descriptor address and an integer selector. It returns no value.

The descriptor contains two adjacent four-byte entries:

| Byte offset | Entry width | Role |
|---|---:|---|
| 0 | 32 bits | Address-bearing value used to locate the target |
| 4 | 32 bits | Mask identifying the bits affected by the operation |

The first entry contains an address representation, not the target’s current contents. The second entry is a bit mask, not an index or count. No additional descriptor fields are used by the supplied body.

The target is accessed through an unsigned integer type. The descriptor’s four-byte entry size is explicit in the supplied representation, but the underlying definition of the target’s unsigned type is absent. Accordingly:

The address-bearing entry is interpreted as a pointer for target access. The evidence does not establish whether that interpretation is valid for every possible 32-bit entry value or how it behaves on a platform with wider pointers.

## Behavior

### Bit-level effect

For each bit position within the target word, the mask determines whether the operation changes that position:

| Mask bit | Selector | Resulting target bit |
|---|---|---|
| 0 | Zero or nonzero | Preserved from the target value read during the call |
| 1 | Zero | Cleared |
| 1 | Nonzero | Set |

All selected positions participate independently. Multiple set bits in the mask request multiple bit changes; they do not encode a single numeric position.

Under the 32-bit interpretation, this applies across exactly 32 target positions. Clearing does not imply an unbounded complement or changes beyond the target word. No addition, subtraction, multiplication, or shift contributes to the result.

The preservation rule refers to the earlier target read. It is not a promise to preserve changes made by another execution agent after that read.

### Access relationships

The target’s original value is obtained using the descriptor’s address-bearing entry before the mask is consumed for the update. Both selector outcomes depend on that original target value.

The final assignment also identifies its destination through the descriptor’s address-bearing entry. With stable descriptor contents, the read and assignment refer to the same target word. The representation does not establish a separately retained destination address whose reuse would remain guaranteed if the descriptor changed during the call.

These are source-level dependencies and access relationships, not a physical transaction trace. No volatile access or synchronization primitive is expressed. The evidence therefore does not guarantee:

- A particular number of machine loads.
- A physical reload of the address-bearing entry.
- A device-visible read/write sequence.
- An indivisible operation.

Changes to the descriptor during execution are outside the established stable-memory contract. They must not be assigned deterministic semantics merely because the final destination is expressed through the descriptor again.

### Unchanged results

A zero mask preserves the entire value obtained from the target read in either selector mode. The body nevertheless contains an unconditional final assignment; it has no explicit branch that omits the assignment when the mask is zero.

The same distinction applies when setting already-set bits or clearing already-clear bits: the resulting value may be unchanged, but the body does not explicitly suppress the assignment.

This does not guarantee a physical store for an unchanged ordinary-memory value. Compiler transformations and the access model remain relevant.

An all-one mask clears the entire target in zero-selector mode and sets the entire target in nonzero-selector mode, under the 32-bit interpretation.

### Descriptor overlap

A target that validly overlaps descriptor storage can change the descriptor itself.

If the target coincides exactly with the mask entry, and the target and entry are compatible 32-bit objects with stable contents, the original target and mask have the same value. Clearing consequently replaces that entry with zero; setting leaves its value unchanged.

If the target coincides exactly with the address-bearing entry under compatible width and access rules, the assignment can replace the descriptor’s stored address representation. The assignment’s destination must be determined before that assignment takes effect. A later invocation may therefore interpret a different address, which need not be valid.

These are conditional overlap cases, not permission to construct arbitrary overlapping objects. Partial overlaps, incompatible types, and different target widths require information not supplied here.

## Side effects

The body contains one explicit target-word assignment. For valid, disjoint ordinary storage, descriptor contents are read but not changed by this function. If the target overlaps the descriptor, the assignment may change descriptor contents.

There are no explicit calls, allocations, releases, callbacks, or independent I/O operations. Target access could itself have external effects if the execution environment maps the address to special storage, but ordinary-memory reasoning does not establish the behavior of such storage.

No ownership transfer is expressed. The caller retains responsibility for the descriptor and target lifetimes. The function contains no operation that frees or otherwise releases either object.

The update is not expressed atomically. Where concurrent access is otherwise permitted, a change occurring after the original read can be lost when the derived result is assigned. In an execution model that forbids unsynchronized conflicting accesses, such a situation may instead invalidate the execution. The supplied evidence does not choose between those environments or provide synchronization for either.

Invalid or inaccessible storage has no specified successful outcome. A fault, language-level invalid behavior, or another environment-specific failure may occur. There is no explicit recovery, rollback, or error report. A mask that would leave the value unchanged does not create a validation bypass or remove the target-read requirement expressed by the body.
