### Conversion distinctions

A 16-bit store through a signed-short destination does not, by itself, establish truncation to the source’s low 16 bits.

- A source value representable in signed 16-bit form retains its numeric value upon conversion.
- An out-of-range conversion requires target conversion semantics. Depending on the applicable rules, its result may be implementation-defined or a signal may occur.
- A physical low-bit representation must not be inferred without the necessary conversion and representation guarantees.

Plain-character conversions require a similar distinction:

- If plain character has unsigned 8-bit semantics and the source has an established integer interpretation, conversion is modulo \(2^8\).
- If plain character has signed 8-bit semantics, representable values are preserved numerically; out-of-range behavior is not established.
- Conversion from an opaque retained value additionally requires an interpretation of that value.

These uncertainties do not apply in the same way to copying auxiliary C into an opaque 16-bit destination or storing the representable opaque-halfword constant 89.
