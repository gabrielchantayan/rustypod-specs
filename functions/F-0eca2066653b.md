# F-0eca2066653b

## Purpose

F-0eca2066653b performs a conditionally enabled 16-bit memory transfer, may perform a second 16-bit memory update under highly restrictive entry-state conditions, and then enters an unconditional dispatch-and-interrupt loop.

No higher-level purpose is established. In particular, the supplied material does not establish a buffer-processing API, an object format, an allocation protocol, or a successful completion condition.

The contract below distinguishes:

- **Established static evidence:** operations and control flow directly represented in the supplied material.
- **Derived static consequences:** reachability and arithmetic conclusions under the stated 32-bit interpretation.
- **documented_only:** behavior requiring an architecture, calling convention, memory map, or external implementation not supplied.

No runtime tests have been performed.

## Behavior

### 1. Initial transfer eligibility

The function first forms the low 32 bits of the selector multiplied by \(2^{19}\).

The initial memory-transfer branch is taken exactly when this result is zero. Under 32-bit arithmetic, this is equivalent to:

\[
\text{selector} \mathbin{\&} \texttt{0x1fff} = 0.
\]

Thus, eligibility depends on the selector’s low 13 bits, not on whether the entire selector is zero.

When that condition is false, the conditional prefix performs no represented data-memory reads or writes. Execution proceeds to the dispatch loop with the incoming link value as its initial base.

### 2. Initial 16-bit transfer

When eligible, the function:

1. Forms a destination address by adding the incoming source address and offset, modulo \(2^{32}\).
2. Reads an unsigned 16-bit value from the incoming source address.
3. Changes its working source-address state to the destination minus the adjustment, modulo \(2^{32}\).
4. Writes the previously read 16-bit value to the destination.

The source read precedes the destination write. Consequently, when source and destination coincide, this remains a read followed by a write of the captured value; it is not a checked or omitted self-copy.

No range, alignment, overlap, or ownership validation occurs.

The changed working source address is not written back through an explicit output parameter. It does, however, participate in subsequent internal conditions.

### 3. Conditions for the additional memory update

After the initial transfer, a sequence of zero-result gates controls a possible additional update.

Under the 32-bit interpretation above, reaching that update requires all of the following:

- The incoming link value is zero.
- The entry stack address is zero.
- The offset equals the companion value.
- The offset is either zero or `0x80000000`.
- The adjustment equals the updated working source address.
- The accumulator is zero.

The updated working source address in this list is the initial destination minus the adjustment. Equivalently, the adjustment must equal that subtraction result modulo \(2^{32}\); it is not merely compared with the incoming source address.

These conditions are static consequences of the represented gates, not evidence that such an entry state is valid on the actual platform.

In particular, the stack-address requirement makes this path unusual on conventional systems. It must not be replaced with an assumption that the path is impossible: the actual execution environment is not supplied.

### 4. Additional 16-bit update

If the additional-update path is reached, the represented operations include:

- An assignment to an architecture-specific register-like state location.
- A 16-bit update using the memory at the link address.
- An internal two-byte advancement of a working address used by later gates.

The register-like assignment computes the low 32 bits of the stack address multiplied by 64. Under the derived reachability conditions, its assigned value is zero. The architectural meaning and external observability of this state location are **documented_only**.

The memory update uses:

- A 16-bit value read from the link address as an absolute destination address, zero-extended to 32 bits.
- A 16-bit value read from that same link address as the value to which 15 is added.
- A 16-bit store of the resulting sum at the selected destination.

Under the derived entry conditions, the link address is zero. This path therefore reads at address zero; it does not interpret zero as an absent pointer.

The source representation contains separate uses of the 16-bit value at the link address. It does not establish the evaluation order or physical read count of those uses. For stable ordinary memory, if both uses observe the same value \(v\), the effect is a write of:

\[
(v + 15) \bmod 2^{16}
\]

to absolute address \(v\).

That stable-memory formulation must not be applied unconditionally to read-sensitive device memory.

### 5. Later conditional regions

The supplied representation contains further guarded calculations and memory operations after the additional-update region. Under the stated 32-bit interpretation, those later memory operations are unreachable from the represented entry.

The relevant static consequences are:

- If the additional-update region is not entered, its successor gate remains false.
- Entering that region requires the stack address to be zero.
- With that stack address, the next zero-result gate succeeds, but the following gate produces the nonzero value two because of the two-byte working-address advancement.
- The subsequent chain therefore stops before the later memory operations.

Accordingly, this contract does not require those unreachable stores, signed reads, or pointer-like record writes as observable behavior. They do not establish a usable data structure or a supported secondary interface.

This reachability conclusion is conditional on the supplied entry boundary and arithmetic interpretation being accurate.

### 6. Dispatch-and-interrupt loop

After the conditional prefix, the function repeatedly performs the following externally significant sequence:

1. Makes an indirect call using the current dispatch base plus `0xEB6` bytes.
2. Makes a second indirect call to numeric target `0x0857A94B`.
3. Requests software interrupt `0x5B`.
4. Sets the dispatch base to `0x083D4CC2`.
5. Repeats.

The first call is represented with three argument values:

- Zero.
- Zero.
- The 32-bit bit pattern `0xFFFFFFA5`.

The third value is unsigned 4294967205, or −91 if interpreted as a signed 32-bit integer. Its semantic meaning is unknown.

The second call has no arguments explicitly represented at its call site. This does not establish that the callee accepts no machine-state inputs.

For the first iteration, the dispatch base is the incoming link value. Even on the exceptional additional-update path, its computed replacement remains zero, equal to the required incoming link value.

For subsequent iterations, the first target is:

\[
\texttt{0x083D4CC2} + \texttt{0xEB6}
= \texttt{0x083D5B78}.
\]

These are numeric targets represented by the supplied material, not verified runtime entry points.

The sequence advances only if each preceding call or interrupt returns normally. No normal function return or ordinary loop-exit condition is represented.

### Nonzero selector enables the transfer

Given selector `0x2000`, source address `0x1000`, offset `0x20`, and a nonzero link value:

- The selector’s low 13 bits are zero.
- The function reads 16 bits at `0x1000`.
- It writes that captured value at `0x1020`.
- The additional-update path is not entered because the link value is nonzero.

This distinguishes the actual condition from a selector-equals-zero check.

### Transfer aliases its source

Given an eligible selector and offset zero:

- The initial source and destination addresses coincide.
- The source value is read before being written back.
- No overlap error is produced.

For device memory, the read and write remain potentially observable operations.

### Exceptional update with stable memory

Assume all required addresses are mapped, selector zero, source address `0x2000`, offset zero, adjustment `0x1000`, companion value zero, accumulator zero, link value zero, and stack address zero.

The updated working source address is `0x1000`, matching the adjustment.

If the stable 16-bit value at address zero is `0x0100`, the exceptional update writes `0x010F` at absolute address `0x0100`, after the initial transfer.

### Exceptional update wraps at 16 bits

Under the same exceptional-path conditions, if both reads at address zero observe `0xFFF8`, the stored value is `0x0007` at absolute address `0xFFF8`.

There is no saturation or overflow error.

### A dependency does not return

If the first indirect call does not return, the second call and interrupt are not reached for that iteration.

Likewise, if the interrupt does not return, the next iteration is not reached.
