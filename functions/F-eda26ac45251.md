## Behavior

### Entry reads and snapshots

The entry sequence distinguishes captured values from later global reads.

The observable global-read order established at entry is:

1. Read one global word and retain it as the **entry unsigned arithmetic operand**.
2. Read a different global word and retain it as the **entry signed arithmetic operand**.
3. Read the **initial-state global** and derive a saved return-routing state by subtracting five.
4. Read that same initial-state global again and use this second value as the initial dispatch state.
5. At the first dispatch, read the **dispatch-offset global** for selection.

Local initialization occurs between some of these reads, but does not merge the two reads of the initial-state global. The saved return-routing state is derived from the first read; initial dispatch uses the second read. Neither value may be substituted for the other without an additional global-stability assumption.

The saved return-routing state is retained locally. Later result-routing actions reuse that saved state rather than rereading the initial-state global. Likewise, the two entry arithmetic operands remain captured values even if dependencies subsequently modify their backing globals.

The two input pointers are retained locally. Initially, the active descriptor, active source, and saved source pointers are null. The result accumulator, byte selector, workspace displacement, and progression-related fields are initialized to zero. The workspace contents are not.

### Dispatch and state transitions

Every dispatch selects an action by combining the current 32-bit state with a read of the dispatch-offset global. **The dispatch-offset global is reread at every dispatch**, including dispatches following direct transitions, conditional transitions, reset actions, and dependency calls.

It is not an entry snapshot. Consequently, the same current state can select different actions if successive dispatch-offset reads differ.

The visible selector set comprises actions numbered 0 through 22. Selector 4 and every unmatched selector execute the same default action: a descriptor-driven F-a1e5ead1c5b9 call. An unmatched selector is therefore not an established rejection, no-op, or termination condition.

Actions either return, set a subsequent state directly, or calculate a selector used to combine two candidate states. Most conditional selectors are obtained by unsigned right shift by 31 and therefore have values zero or one. A progression action instead uses a signed right shift followed by addition of one; its interpretation depends on target signed-shift semantics.

The return-routing state’s name describes its visible use, not a guarantee that it selects the return action. Its eventual action also depends on the dispatch-offset read at that dispatch.

Missing global values prevent an established ordering among setup, dependency calls, byte processing, result routing, and return.
