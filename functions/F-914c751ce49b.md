# F-914c751ce49b

## Purpose

F-914c751ce49b selects a traversal occurrence using a dependency-supplied selector and a dependency-supplied classification result. Only classification-positive occurrences count toward selection. The comparison precedes the counter increment, making the selector a zero-based ordinal for nonnegative values within the established arithmetic range.

The function returns a packed 64-bit value:

- The low 32 bits contain the selected output value, captured after classification, or zero when advancement stops without selection.
- The high 32 bits contain the value of an address-passed scalar after finalization returns.

The function does not itself establish what is traversed, what classification means, or whether either return word represents a resource or status.

This contract describes static evidence from the supplied representation. No runtime tests have been performed.

## Behavior

### Initial reads and setup

The function first reads a 32-bit address-bearing value from byte offset `0x1E0` relative to the first argument.

It then calls F-b3f4a7a52609 without visible arguments. That call returns the 32-bit selector.

The function establishes:

- A separate qualifying-occurrence counter initialized to zero.
- The first scalar initialized from the selector.
- The second scalar initialized from the third argument.
- The output array’s first element initialized from the fourth argument.

The output array’s second element is not visibly initialized.

The selector is retained separately from the address-passed first scalar. Subsequent changes to that scalar do not, by themselves, change the selector used in comparisons.

### Initialization

F-8ca21d3a8cca is called once with:

1. The address of the first scalar.
2. A 32-bit value read at byte offset `4` from the previously obtained address-bearing value.

The initial address-bearing field is read before F-b3f4a7a52609. The read at the saved address plus `4` occurs after that dependency returns.

Consequences of this ordering include:

- If F-b3f4a7a52609 changes the memory used by the later read, initialization can receive the changed value.
- If it changes the original address-bearing field, the function nevertheless uses the address-bearing value already obtained. That field is not visibly read again.
- If it invalidates the saved address, validity of the later access is not guaranteed.

The initialization result is not inspected.

Initialization receives no explicit pointer to the second scalar or output array. Whether its actual interface accesses additional storage, or whether other aliases exist, is not established by this function.

### Advancement

Each traversal attempt calls F-b38a3aba0e18 with two separately supplied addresses:

1. The address of the first scalar.
2. The address of the output array.

These arguments are not evidence of an overlapping state/output layout.

After advancement returns, the prospective low return word is reset to zero. The function then uses only the zero/nonzero distinction of the advancement result.

If the result is zero:

- No classification call occurs for that attempt.
- Traversal ends.
- The low return word remains zero, including when advancement wrote data into the output array.

If the result is nonzero:

- The first output element is read.
- Its 32-bit value is passed by value to F-56e5aaaec5ab.

There is no visible requirement that advancement replace the first output element on every successful attempt. Classification receives whatever value that element contains at the subsequent read.

### Classification and selection

The classification result is also tested only for zero versus nonzero.

A zero result causes another advancement attempt without incrementing the qualifying-occurrence counter.

A nonzero result causes the function to:

- Read the first output element again and capture that value as the prospective low return word.
- Compare the retained selector with the current qualifying-occurrence counter.
- End traversal if they are equal.
- Otherwise increment the counter and attempt advancement again.

The post-classification read matters. The selected value is not necessarily the value passed to classification. For example, advancement could make the output array reachable through another alias, and classification could modify its first element through that alias.

A value captured on a classification-positive nonmatch is not a fallback result. The next advancement attempt resets the prospective low word to zero. If that attempt stops traversal, zero is returned in the low word.

### Counting and arithmetic

The selector and qualifying-occurrence counter are represented as signed 32-bit integers. The counter starts at zero and increments by one only after a classification-positive nonmatch.

Within the nonnegative range:

- Selector zero selects the first classification-positive occurrence.
- Selector one selects the second.
- Selector two selects the third.

Classification-negative occurrences do not consume an ordinal. Repeated output values are counted as separate occurrences; no uniqueness check is visible.

A nonnegative selector does not guarantee termination. Advancement could continue indefinitely while classification always returns zero.

For a negative selector, equality cannot occur while the counter remains nonnegative. The representation does not establish a defined result for incrementing the counter beyond `2,147,483,647`. Wraparound and eventual selection of a negative selector must not be assumed.

### Finalization and packing

After either normal traversal exit, F-d0d3f100effc is called once with the address of the first scalar.

The function then reads that scalar for the high return word. Finalization can therefore affect the high word.

The low word was already captured separately. There is no explicit post-finalization reload from the output array. A finalization-time change to that array alone does not replace the captured low word.

No alternate error return or exception-cleanup path is visible. If initialization, advancement, classification, or another operation fails to return normally, this representation does not establish that finalization occurs.

### Error handling

The high return word might encode status, but no such interpretation is established.

## Acceptance examples

These are conditional specifications, not executed tests. Named item values are arbitrary 32-bit patterns. Unless stated otherwise, dependencies return normally, storage accesses are valid, and classification does not modify the output element.

### First qualifying occurrence

Given selector zero, advancement returns nonzero with item A, and classification returns nonzero.

A is selected. No second advancement occurs. Finalization runs, and the return contains A in the low word and the post-finalization first scalar in the high word.

### Skipping classification-negative occurrences

|---|---|---|

| Second | B | Nonzero |
| Third | C | Zero |

### Exhaustion without enough qualifying occurrences

Given selector two, exactly two classification-positive occurrences occur, followed by advancement returning zero.

The low return word is zero, not the second qualifying value. Finalization still runs.

### Output written by a stopping advancement

Given advancement writes A into the first output element but returns zero, A is not classified. The low return word is zero.

### Classification-time mutation

Given selector zero, advancement leaves A in the first output element and returns nonzero. Classification receives A, changes the element to B through an available alias, and returns nonzero.

The low return word is B because capture follows classification.

### First-scalar mutation does not change the selector

Given selector one, initialization changes the first scalar to zero. Advancement and classification then produce two classification-positive occurrences.

The first occurrence is not selected merely because the scalar now contains zero. The retained selector still selects the second positive occurrence. The high return word depends on the scalar’s later value after finalization.

### Finalization-time mutation

Given an item has been selected, finalization sets the first scalar to `0x12345678`.

The high return word is `0x12345678`. A change to the output array alone does not replace the captured low word.

### Zero-valued selection

Given selector zero and a successful, classification-positive occurrence whose post-classification output value is zero, selection occurs but the low return word is zero.

### Negative selector with early exhaustion

Given selector `−1`, two classification-positive occurrences occur and the next advancement returns zero.

Neither occurrence matches the counter. Finalization runs and the low return word is zero. This example requires no overflow assumption.
