# F-65623a14cfaa

## Purpose

F-65623a14cfaa rewrites a descriptor’s 32-bit encoding field and submits either that descriptor or a sequence of temporary descriptors to F-a92212b36fcf.

The sequence is controlled by a mode byte, an original position-like value, and a length-like value. Two modes use boundary sizes of 8,192 and 16,384 units respectively. When the calculated start and end boundary indices differ, the function constructs temporary descriptors and advances a separate address-like field between dependency calls.

The names “position,” “length,” and “address” describe inferred roles, not established units or resource types. In particular, intermediate submitted lengths are calculated relative to the original position, not relative to the preceding boundary. That distinction is part of the observable behavior.

## Interface

The function takes six arguments and has no explicit return value:

| Argument | Established use |
|---|---|
| First opaque value | A 32-bit value forwarded as the first argument to every dependency call. |
| Second opaque value | A 32-bit value forwarded as the second argument to every dependency call. |
| Descriptor | A writable memory address containing the fields listed below. |
| Encoding input | An unsigned 32-bit value used to construct the replacement encoding. |
| Third opaque value | A 32-bit value forwarded as the fourth argument to every dependency call. |
| Context | An address whose byte at offset 5 selects the mode; forwarded as the fifth dependency argument. |

Each dependency invocation receives, in order: the first opaque value, the second opaque value, a descriptor address, the third opaque value, and the context.

### Descriptor layout

Offsets are in bytes from the descriptor address.

| Offset | Width | Observed role |
|---|---:|---|
| 0 | 1 byte | Copied into temporary descriptors when splitting occurs. |
| 4 | 32 bits | Address-like or index-like field; copied and subsequently advanced. |
| 8 | 32 bits | A derived count in temporary descriptors. The original field is not read or rewritten by this function. |
| 12 | 32 bits | Initially supplies the original position; overwritten with an encoding before any dependency call. |
| 16 | 32 bits | Length-like field; used to determine the end index and final remainder. |
| 20 | 1 byte | Copied into temporary descriptors when splitting occurs. |

Bytes not listed are not initialized by the visible temporary-descriptor construction. No contract for their values is established.

### Preconditions

The descriptor must support the required reads and the write at offset 12. The context must support a one-byte read at offset 5. Alignment and accessibility must satisfy the target platform’s requirements for the observed 32-bit accesses.

When temporary descriptors are used, F-a92212b36fcf must tolerate their partially initialized representation. A dependency that reads other bytes may observe indeterminate data.

The dependency must not retain a temporary descriptor address for use after this invocation returns. The visible function provides no persistent storage for those descriptors.

No validation, allocation, ownership transfer, or error result is visible.

## Behavior

### Arithmetic model

The established computations use 32-bit unsigned quantities for the original position, encoding input, boundary indices, calculated lengths, and counts. Unsigned additions, subtractions, multiplications, and left shifts retain only the low 32 bits. Right shifts of these unsigned quantities are logical.

For the expressions below:

- \(S\) is the original 32-bit field at descriptor offset 12.
- \(P\) is the unsigned encoding input.
- \(W(x)\) means the low 32 bits of \(x\).
- “OR” and “AND” are bitwise operations.
- \(L_0\) is the offset-16 value read when calculating the end index.

The field at offset 4 is presented as signed storage, but its update combines it with an unsigned 32-bit count. Its resulting bit pattern follows 32-bit modular addition. Whether consumers interpret that pattern as an address, signed number, or unsigned number is unknown.

### Initial reads and mode selection

The function first reads \(S\) from descriptor offset 12. It then reads the context byte at offset 5.

Only the exact byte value 1 selects the first mode. Every other byte value selects the second mode.

#### Mode selected by byte value 1

The boundary size is \(B=8{,}192\), with shift count 13. The initial boundary index is:

\[
J=S\mathbin{\gg}13
\]

The function constructs and writes the following encoding to descriptor offset 12:

\[
R =
W\left(
((S\mathbin{\mathrm{AND}}8191)\ll1)
\mathbin{\mathrm{OR}}
((S\gg13)\ll15)
\mathbin{\mathrm{OR}}
((P\mathbin{\mathrm{AND}}1)\ll14)
\mathbin{\mathrm{OR}}
((P\gg1)\ll3)
\right)
\]

The separate encoding progression state begins as:

\[
Q=(R\mathbin{\mathrm{AND}}\texttt{0xFFFFC000})
\mathbin{\mathrm{OR}}W((P\gg1)\ll3)
\]

The progression increment is 32,768.

These bit ranges can overlap. The construction uses bitwise OR, not addition or independently validated fields. No range check restricts \(P\).

#### Mode selected by every other byte value

The boundary size is \(B=16{,}384\), with shift count 14. The initial boundary index is:

\[
J=S\mathbin{\gg}14
\]

The progression state begins as:

\[
Q=W\left(((S\gg14)\ll16)\mathbin{\mathrm{OR}}(P\ll14)\right)
\]

The function writes this encoding to descriptor offset 12:

\[
R=Q\mathbin{\mathrm{OR}}(S\mathbin{\mathrm{AND}}16383)
\]

The progression increment is 65,536.

Again, bit ranges may overlap, and high bits shifted beyond 32 bits are discarded.

### End-index calculation

After rewriting descriptor offset 12, the function reads descriptor offset 16 and calculates:

\[
E=W(L_0+S-1)\gg n
\]

Here \(n\) is 13 or 14 according to the selected mode.

The subtraction by one is unconditional. A zero length is not a special case and does not cause an immediate return.

The original \(S\), rather than the newly written encoding, is used throughout the boundary and length calculations.

### Direct submission

If \(J=E\), the function calls F-a92212b36fcf exactly once with the original descriptor address, then returns.

In this case:

- Offset 12 has already been rewritten.
- No temporary descriptor is constructed.
- This function does not adjust offsets 4, 8, or 16.
- Any dependency changes to the original descriptor remain observable.

### Temporary-descriptor submission

If \(J\ne E\), the function prepares one reusable temporary descriptor. Its initial copies occur in this order:

1. Byte at original offset 0.
2. Word at original offset 4.
3. Byte at original offset 20.
4. Rewritten word at original offset 12.

Other temporary fields are supplied before each call as described below. Unlisted bytes are not initialized.

The original descriptor remains rewritten at offset 12, but is not itself passed to the dependency on this path.

For each current boundary index \(j\), starting at \(J\) and continuing until the index equals \(E\), the function performs the following observable work:

- Sets temporary offset 16 to:
  \[
  D_j=W(B(j+1)-S)
  \]
- Sets temporary offset 8 to:
  \[
  C_j=D_j\gg2
  \]
- Calls F-a92212b36fcf with the temporary descriptor.
- Advances the private encoding progression state:
  \[
  Q=(Q+\text{increment})\mathbin{\mathrm{AND}}\texttt{0x1FFFF}
  \]
- Advances temporary offset 4 by the value currently present at temporary offset 8, using 32-bit modular addition.
- Writes the new \(Q\) to temporary offset 12.
- Increments the boundary index using 32-bit unsigned arithmetic.

The order after the dependency call matters. The offset-4 update uses the dependency-visible temporary fields after that call, not immutable copies of their pre-call values. For example, if the dependency changes temporary offset 8, the changed count controls the address-like advance. If it changes temporary offset 4, the addition starts from that changed value.

Conversely, temporary offset 12 is overwritten after each loop call. A dependency mutation of that field does not replace the private progression state.

Temporary offsets 0 and 20 are copied only once. Dependency mutations to them can therefore persist into later submissions. Temporary offsets 8 and 16 are recalculated before the next submission.

### Final temporary submission

After the boundary index reaches \(E\), the function rereads offset 16 from the original descriptor. Let that newly observed value be \(L_f\). It sets:

\[
D_{\mathrm{final}}=
W\left(L_f-W(BE-S)\right)
\]

Temporary offset 16 receives this result, and temporary offset 8 receives:

\[
D_{\mathrm{final}}\gg2
\]

The function then calls F-a92212b36fcf once more with the same temporary descriptor and returns. There is no further address or encoding advance after this final call.

The initial end index remains based on \(L_0\). Changes to the original length during dependency execution can affect the final remainder without changing the number of loop iterations.

### Boundary-count and length consequences

The loop tests inequality, not whether the current index is less than the end index. If \(E<J\), it continues through unsigned index wraparound rather than skipping the loop.

Assuming normal returns and no invalid memory accesses, the number of loop calls is:

\[
K=(E-J)\bmod2^{32}
\]

There is one additional final call. Equal indices instead take the direct path with one call.

Intermediate lengths are cumulative distances from \(S\) to successive boundaries. They are not necessarily bounded by \(B\). The address-like field nevertheless advances by each submitted count. Replacing these lengths with individual boundary-sized pieces would change the established behavior.

The count is a floor division by four. Nonmultiples of four retain their full length at offset 16 but discard the low two bits when producing offset 8.

## Side effects

The function always writes original descriptor offset 12 before its first dependency call, assuming the required preceding reads succeed.

On the temporary-descriptor path, the function’s only explicit write to the original descriptor is that encoding write. Its address-like and length-like updates target temporary storage. Dependency effects may modify additional memory.

F-a92212b36fcf is called synchronously and sequentially. The same temporary descriptor storage is reused across calls on the split path. No allocation or release is visible.

There is no visible check of a dependency return value, no rollback of the original encoding, and no explicit error reporting. Behavior after a dependency failure to return normally is not established.

The dependency’s effects on globals, external resources, ownership, or aliased memory are unknown. Preservation of such state must not be assumed.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Examples involving several calls assume that the dependency returns normally and leaves descriptor fields and the original length unchanged unless stated otherwise.

### One direct submission

Given mode byte 0, \(S=5\), \(L_0=4\), and \(P=0\):

- Both boundary indices are zero.
- Original offset 12 becomes 5.
- Exactly one call receives the original descriptor.
- This function does not normalize its existing offset-8 value.

### One boundary crossing

Given mode byte 0, \(S=0\), \(L_0=16{,}388\), \(P=0\), and initial offset-4 value \(A\):

- Original offset 12 becomes 0.
- The first temporary call has offset 4 equal to \(A\), offset 8 equal to 4,096, offset 12 equal to 0, and offset 16 equal to 16,384.
- The final temporary call has offset 4 equal to \(W(A+4096)\), offset 8 equal to 1, offset 12 equal to 65,536, and offset 16 equal to 4.
- Both calls receive the same temporary descriptor address, not the original descriptor.

### Multiple boundaries preserve cumulative lengths

Given mode byte 0, \(S=0\), \(L_0=32{,}772\), \(P=0\), and initial address-like value \(A\):

| Call | Offset 4 | Offset 8 | Offset 12 | Offset 16 |
|---|---|---:|---:|---:|
| First | \(A\) | 4,096 | 0 | 16,384 |
| Second | \(W(A+4096)\) | 8,192 | 65,536 | 32,768 |
| Final | \(W(A+12288)\) | 1 | 0 | 4 |

The second submitted length is 32,768, not 16,384.

### Exact mode selection and first-mode encoding

Given mode byte 1, \(S=3\), \(L_0=1\), and \(P=2\), the rewritten encoding is 14 and the original descriptor is submitted directly.

A mode byte of 2 instead selects the 16,384-unit mode. It is not treated as equivalent to 1.

### Dependency mutation affects advancement

Under the one-boundary-crossing example, if the dependency changes temporary offset 8 to 7 during the first call and leaves offset 4 unchanged, the final call receives offset 4 equal to \(W(A+7)\).

The final count is still recomputed from the final remainder; it does not remain 7.

### Zero length is not an empty-operation guarantee

Given mode byte 0, \(S=1\), \(L_0=0\), and \(P=0\), both indices are zero and one direct call occurs.

Given instead \(S=0\) and \(L_0=0\), the end-index calculation wraps to 262,143. Subject to normal completion, this produces 262,143 loop calls followed by one final call.
