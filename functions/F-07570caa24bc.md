# F-07570caa24bc

## Purpose

The evidence does not justify describing it as object construction, serialization, device control, or a particular numerical algorithm.

This contract covers the **visible execution prefix**, not a verified complete function. The supplied static representation reports invalid instruction data and terminates at a damaged control-flow boundary. Every later operation is conditional on execution reaching it, earlier accesses succeeding, and dependencies returning to the represented continuation.

Established behavior is distinguished below from conditional 32-bit arithmetic interpretations and unresolved machine-interface details.

### Width and address conventions

A byte is 8 bits; a word is 32 bits. Byte stores retain the low eight bits. Unsigned right shifts are logical.

For numerical examples, multiplication, left shifts, and address arithmetic use a **conditional 32-bit bit-vector interpretation**: retain the low 32 bits. This is not a claim that every signed expression has defined portable-language behavior, nor independent confirmation of the machine’s address arithmetic.

Two recurring address relationships are:

- **Word slot:** four times a selector, plus 20.
- **Byte-selected destination:** the unsigned selector byte’s value, plus 17.

A byte-selected destination is therefore a numeric address from 17 through 272 inclusive. The selector’s read address is not a base added to this destination.

Word byte order, alignment requirements, memory mappings, and exceptional-access behavior are unknown.

## Behavior

### Entry and incoming-byte write

The first indirect dependency receives the first explicit input. Its target is derived from incoming control-link state. Subsequent targets generally use embedded control-position values with an offset of `0xffe`.

Further calls produce an initial 32-bit result. Before that result is forwarded, the prefix:

1. Reads an unsigned byte at the incoming address-bearing value plus one.
2. Writes the incoming byte to the byte-selected destination.
3. Invokes a dependency with four times the initial result.

Additional calls produce another result. An argument-bearing dependency then receives, in order:

- The third explicit input shifted left by 26.
- The new result shifted left by two.

Under the conditional 32-bit interpretation, only the third input’s low six bits contribute to the first argument.

### Retained value and first auxiliary result

A subsequent indirect return supplies a retained word. F-674e75a953e8 receives that retained word in both visible argument positions. Its return is not explicitly consumed.

After another indirect call, the retained word is stored in the word slot selected by the first auxiliary register result.

The next argument-bearing call receives:

- The first auxiliary result.
- That result masked with `0x3fffffff`, then logically shifted right by 10.

After intervening calls, another returned selector chooses a word slot. The first auxiliary result is stored there. A following dependency receives four times that selector, **without** the slot’s additional 20-byte offset.

These are the two explicit word writes preceding the split-result phase. No producer, preservation rule, or ownership meaning is established for the auxiliary result.

### First pair of byte transformations

1. Reads a selector byte at eight times the retained word, plus one.
2. Stores the low byte of four times the transformation source at the byte-selected destination.
3. Calls a dependency with four times the transformation source.
4. Executes intervening calls and obtains another result.
5. Reads a selector byte at 64 times the transformation source, plus one.
6. Stores the low byte of the transformation source masked with `0x3fffffff` and shifted right by 20 at this newly selected destination.
7. Calls a dependency with four times the result obtained in step 4.
8. Executes further calls.
9. Calls a dependency with four times another returned result, followed by the selector byte from step 5.

The second stored payload contains source bits 20 through 27. The first selector address depends on the retained word; the second depends on the transformation source. They are not interchangeable.

Both selector reads occur at their respective points in the sequence. The earlier store and intervening dependencies may affect later memory through aliasing or other side effects.

## Acceptance examples

These are **conditional static expectations**, not runtime tests.

1. **Numeric byte destination.** If a selector read returns `0xff`, its corresponding byte store targets address `0x110`. The selector-read address is not added to that destination.

2. **Truncation and extraction.** For a first transformation source of `0x12345678`, the four-times byte payload is `0xe0`; the masked-right-shift byte payload is `0x23`. Both expectations require reaching the corresponding stores.

3. **Third-input width.** Under 32-bit interpretation, third-input bit patterns `1` and `0x41` both produce `0x04000000` after shifting left by 26. This does not imply otherwise equivalent executions.

4. **Zero update.** If the selector read at address one returns seven, the associated operation writes one zero byte at address 24.

5. **Different scaled addresses.** For a primary selector of three, the scaled value is 12. The initial word store targets address 68; an associated word read targets address 32. The read need not observe the stored value.

6. **Split-result upper word.** If the represented upper word is two, the first split-phase store writes zero at address 28, independently of the lower word.

7. **Fresh final selection.** If the two final selector reads return two and nine, their byte stores target addresses 19 and 26 respectively.

8. **Secondary-selector retention.** If the fourth secondary selector is three, the final selector-read address is `0x30000001` under 32-bit interpretation. Substituting the fourth primary selector would violate the visible data dependency.

9. **Prefix store counts.** If all represented stores are reached, the explicit total is seven byte writes and sixteen word writes. Dependency writes are outside these totals.

10. **Interrupted continuation.** If a dependency never returns, subsequent operations are not required to occur. Previously completed stores have no established rollback.
