# F-373ca1af5d62

## Purpose

F-373ca1af5d62 searches a pointer-linked structure, then either publishes an existing candidate or invokes F-7a76570dbcfc and publishes the word supplied through that dependency’s temporary result slot.

The output has two fields:

- A 32-bit word representing the selected candidate or the dependency-produced result.
- A one-byte disposition flag: **0** for the candidate-selection path, **1** for the F-7a76570dbcfc path.

The flag identifies the path taken. It is not an independently checked success indication.

The structure and navigation are consistent with a header-based ordered binary tree and predecessor-based candidate checking. Insertion, uniqueness enforcement, allocation, and balancing are inferred possibilities, not established behavior of this function.

## Interface

The function accepts three arguments and has no explicit return value.

| Argument | Established use |
|---|---|
| Result-storage address | Receives a 32-bit word at offset 0 and one byte at offset 4. |
| Structure address | Supplies the header-pointer field, mode byte, and comparison-context address. |
| Query token | Opaque 32-bit value passed unchanged to dependencies. |

The function does not directly dereference the query token. Its interpretation as an address, key, handle, or other representation is **documented_only**.

### Widths and result layout

The 32-bit result word is written before the disposition byte. These are separate writes, not an atomic publication of the complete result. No direct write initializes bytes beyond offset 4.

These offsets describe the supplied 32-bit representation, not a portable layout using native pointers of arbitrary width. Field-address calculations use fixed byte offsets; there is no bounds or address-overflow validation.

### Preconditions and null handling

Normal completion requires:

- Writable result storage for the two output fields.
- Readable structure fields and a valid initial header.
- Valid memory for every node and parent-like link dereferenced on the selected path.
- Terminating search and navigation.
- Dependencies that accept the supplied values and addresses and return normally.

There are **no explicit null checks validating the result address, structure address, or initial header pointer**. In particular, a null header is not accepted as an empty structure: the function dereferences the header to obtain the root link.

There **are explicit null-link checks controlling traversal and navigation**:

- The search-node pointer is checked before each search iteration.
- A candidate’s offset-8 child link is checked to choose between descent and ascent.
- Offset-0x0c child links are checked to terminate subtree descent.

These checks support null-linked traversal; they do not validate the surrounding objects or parent chain. The discriminator-byte zero test is also not a candidate-pointer validity check: it occurs only after the candidate has been dereferenced.

There are no explicit structural-integrity, bounds, cycle, or parent-validity checks. Aliasing between result storage, the structure, nodes, and dependency-accessible memory is not specified. Separate result storage avoids output writes modifying the searched representation.

## Behavior

### Initial search state

The function reads the header address from structure offset 0x10, then reads the link at that header’s offset 4 as the initial search node.

It separately reads structure offset 0x10 again to initialize the remembered search position. The initial search node and remembered position therefore originate from distinct header-field reads.

The remembered comparison outcome starts as nonzero. An empty search retains that outcome and the separately loaded header as its remembered position.

### Search traversal

While the current search node is non-null, the function:

1. Clears two local 32-bit temporary words.
2. Calls F-4b52c8e01045 with the comparison-context address at structure offset 0x19, the original query token, and the current node’s offset-0x10 address.
3. Remembers the current node as the last visited position.
4. Reads the next link from that node: offset 0x0c for a zero comparison result, offset 8 for a nonzero result.

The comparison result is tested only for zero versus nonzero. Negative and positive nonzero results select the same link. A conventional signed three-way ordering interpretation is not justified without an additional dependency contract.

The selected child is read after the comparison call. Dependency changes to reachable node storage may therefore affect subsequent traversal. No dependency-preservation guarantee is established.

Search ends when the current search pointer is null. This is an explicit traversal-termination check, not an error path.

### Mode selection

After search terminates, the function reads the byte at structure offset 0x18.

- **Nonzero:** bypass candidate checking and take the common F-7a76570dbcfc path.
- **Zero:** initialize a local candidate slot from the remembered search position and continue with candidate handling.

The mode is not snapshotted before search. A change made by a search dependency can affect the later mode decision.

### Boundary handling

If mode is zero and the final search comparison was zero, the function skips boundary handling and candidate adjustment.

Otherwise, including an empty search with its initial nonzero outcome, it:

1. Reloads the header address from structure offset 0x10.
2. Loads the 32-bit word at that header’s offset 8 into a boundary slot.
3. Calls F-be1b50af3623 with the addresses of the candidate slot and boundary slot.

Both slots are addressable dependency arguments. Their contents after the call must not be assumed equal to their initial contents.

A nonzero return selects the early F-7a76570dbcfc path immediately. A zero return proceeds to candidate adjustment using the candidate slot’s then-current value.

The boundary dependency’s return is tested only for zero versus nonzero. No interpretation as equality, validity, or ordering is established.

### Candidate adjustment

Adjustment occurs only after zero mode, a nonzero final search outcome, and a zero boundary-dependency return.

First, the function reads the candidate’s discriminator byte at offset 0.

If that byte is zero, it reads the candidate’s offset-4 link and then the target’s offset-4 link. If the resulting address equals the candidate, the candidate becomes its offset-0x0c link. This branch performs no further navigation or null check before candidate extraction.

Otherwise, adjustment follows one of two paths.

**Non-null offset-8 child**

The function enters the offset-8 subtree, then follows offset-0x0c links until reaching a node whose offset-0x0c link is null. That terminal node becomes the candidate.

**Null offset-8 child**

The function reads the offset-4 parent-like link. At each ascent step, it compares the parent’s offset-8 link with the current candidate and replaces the candidate with that parent. It continues upward while the comparison was equal, stopping at the first unequal relationship.

The candidate is replaced with the parent even on the final, unequal step. There is no explicit null-parent termination check.

The source contains repeated child-field reads: the initial offset-8 link is loaded before being read again for its null test, and each subtree-descent iteration loads an offset-0x0c link before reading that field again for its termination test. Stable links give the navigation described above. Behavior under concurrent or otherwise unstable field values is not established.

This adjustment is consistent with predecessor navigation. The concrete links and branch conditions, rather than that interpretation, define the established behavior.

### Candidate checking

After candidate handling, unless the early dependency path was selected, the function clears another local 32-bit word and calls F-5037e08d05fd with the candidate.

It then calls F-4b52c8e01045 with:

1. The comparison-context address at structure offset 0x19.
2. The 32-bit value returned by F-5037e08d05fd.
3. The original query token.

The operand order differs from search: search passes the query before the node-associated address; candidate checking passes the extracted value before the query.

If this comparison returns zero, the function writes the candidate representation to result offset 0, then writes disposition 0 at result offset 4 and returns.

If it returns nonzero, the function takes the common F-7a76570dbcfc path.

Zero here means only that this function selects the existing candidate. Mathematical equality requires a dependency contract not supplied.

### Dependency-produced result

There are two F-7a76570dbcfc call sites:

- An early site selected by a nonzero F-be1b50af3623 return.
- A common site selected by nonzero mode or a nonzero candidate-check comparison.

Both pass:

1. The address of a local 32-bit result slot.
2. The structure address.
3. The integer zero.
4. The remembered search position.
5. The original query token.

The fourth argument is the remembered search position, not the adjusted candidate. Candidate-slot changes made by boundary handling or navigation do not substitute that candidate for this argument.

After the dependency returns, the function reads its temporary slot, writes that 32-bit word to result offset 0, then writes disposition 1 at result offset 4.

There is no explicit validation of the supplied word and no checked success result from this dependency.

## Side effects

### Direct writes and publication

On a normally completed path, the only direct writes to caller-provided storage are the result word and disposition byte, in that order. The function makes no direct writes to structure or node fields.

Local writes initialize search temporaries, establish and adjust the candidate slot, load the boundary slot, clear an additional word before extraction, and prepare the disposition byte.

If output storage overlaps other reachable storage, the final writes modify that overlapping memory. The function provides no alias detection or rollback.

### Temporary result-slot state

The early F-7a76570dbcfc site receives one of the words cleared before each search comparison. After a nonempty search, that word has been initialized to zero; with no search iterations, this function has not initialized it before the early call.

The common site receives the other search-cleared word. Depending on the path, it may contain zero, the header boundary word, or a value left by F-be1b50af3623. An empty search followed by nonzero mode reaches this site without an established prior initialization.

Thus, F-7a76570dbcfc cannot require every supplied result slot to arrive zero-initialized based on this function alone. A meaningful published result requires that the slot contain a defined 32-bit word when the dependency returns. Dependency effects on previously exposed memory remain unspecified.

### Dependency effects and ownership

Dependencies receive structure-associated addresses, node-associated addresses, local-slot addresses, or the structure itself. Their effects on reachable memory and globals are unknown.

This function performs no explicit allocation, release, retain, or ownership transfer. Neither returning an existing candidate nor copying a dependency-produced word establishes ownership semantics.

### Errors and interruption

There is no explicit error output, recovery, rollback, or exception handling. A dependency that does not return prevents later publication. Invalid reached addresses and malformed or cyclic links have no defined recovery path in this body.

The normal null-child checks terminate or redirect navigation; they do not constitute general invalid-input handling.

## Acceptance examples

These are conditional behavioral expectations, not executed tests. All reached memory must be valid, links must be stable where navigation relies on repeated reads, and dependencies must behave as stated.

### Null root versus null header

Given a valid header whose offset-4 root link is null, search performs no comparison and proceeds to the mode read.

A null header is different: the function attempts to read its offset-4 field without first validating the header. No graceful empty-structure result is established for that input.

### Search directions

For a valid search node:

- A zero comparison selects its offset-0x0c link.
- Either −1 or +1 selects its offset-8 link.
- If the selected link is null, the next search-condition check ends traversal without dereferencing that null child.

### Nonzero mode

Given terminating search and nonzero mode when read, candidate checking is bypassed. F-be1b50af3623 and F-5037e08d05fd are not called. If F-7a76570dbcfc leaves word W in its slot, output becomes W followed by disposition 1.

### Direct candidate selection

Given zero mode and a final search comparison of zero, boundary handling and adjustment are skipped. F-5037e08d05fd receives the remembered candidate. If candidate comparison returns zero, that candidate is published with disposition 0, without calling F-7a76570dbcfc.

### Early dependency path

Given zero mode, a nonzero final search outcome, and a nonzero boundary-dependency return, extraction and candidate comparison do not occur. F-7a76570dbcfc receives the remembered search position even if the boundary dependency changed the candidate slot.

### Subtree and ascent boundaries

Given adjustment with no matching special-header condition:

- A non-null offset-8 child selects descent, ending at the node with a null offset-0x0c link.
- A null offset-8 child selects ascent instead; it does not itself signal an error.
- Ascent requires valid parent-like links because there is no null-parent guard.

### Rejected adjusted candidate

If adjustment changes the candidate and candidate comparison then returns nonzero, F-7a76570dbcfc still receives the remembered search position. Its supplied word is published with disposition 1.

### Empty search with zero mode

A valid header with a null root produces no search comparison and retains the initialized nonzero outcome. Zero mode therefore invokes boundary handling. Whether subsequent adjustment safely handles the header depends on the boundary dependency and structural invariants.
