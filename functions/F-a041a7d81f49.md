# F-a041a7d81f49

## Purpose

F-a041a7d81f49 performs an ordered sequence of memory reads and writes, derives a signed-offset address from data associated with a supplied address, and transfers control indirectly with three arguments.

The supplied static representation establishes those operations but does not establish a higher-level purpose. In particular, it does not justify describing the addressed memory as an object, dispatch table, packet, device register bank, or owned allocation.

This contract distinguishes:

- **Established static behavior:** accesses, arithmetic, ordering, and argument construction visible in the supplied representation.
- **Inferred interpretation:** conventional meanings of widths, addresses, and signed arithmetic needed to describe that representation.
- **documented_only unknowns:** calling convention, memory validity, target behavior, and other properties not established by the evidence.

No runtime tests have been performed.

## Behavior

### Arithmetic conventions

The behavior below uses byte offsets, matching the apparent address arithmetic in the supplied representation. The representation uses a code-address-like type for T; its exact element scaling is not independently verified.

For calculations involving B, define:

- **Q:** B shifted right by 18 bits using an unsigned shift.
- **D:** Q minus 87.

With a 32-bit B:

- Q ranges from 0 through 16,383.
- D ranges from −87 through 16,296.
- Q minus 84 ranges from −84 through 16,299.

These mathematical ranges fit within a signed 32-bit integer. However, subtraction from the unsigned shifted value is first subject to unsigned arithmetic in the supplied representation. Negative mathematical results therefore correspond to wrapped unsigned bit patterns before any interpretation as signed values or addresses.

A “low byte” below means the least significant eight bits. Arithmetic narrowed to a byte is described modulo 256; its ultimate signed character interpretation does not change those stored bits.

### Ordered observable operations

The sequence below applies only while all preceding operations complete. It specifies logical order in the supplied representation, not verified hardware instruction order or concurrency guarantees.

1. **Write the additional four-byte input.**  
   Store W as four bytes at B plus 88.

2. **Write the explicit byte input.**  
   Store V as one byte at A plus 25.

3. **Follow six byte-valued address selections.**  
   First read one unsigned byte at S plus 31. For each of five subsequent reads, use the preceding byte value as an address-sized unsigned number, add 31, and read one byte there.

   The sixth byte is retained for a later write destination. These are six dependent reads, not a single read through a conventional pointer chain.

   After the first read, every read address is in the inclusive range 31 through 286. Each earlier byte value selects the next address.

4. **Read an entry associated with T.**  
   Read the element represented at T plus 26. Its low byte is used later.

   The supplied representation treats this as a code-valued element. Its precise physical read width is not securely established; only its subsequent reduction to eight bits is visible.

5. **Derive the shifted values from B.**  
   Compute Q and D as defined above. This step introduces no additional visible memory access.

6. **Write a byte to the address derived from Q.**  
   Store the low byte of T at the address represented by Q minus 84.

   For Q below 84, the corresponding 32-bit unsigned address expression wraps. The evidence does not justify interpreting such an address as a valid ordinary negative offset.

7. **Read a selector byte.**  
   Take the low byte of the element read in step 4, add 16, and read one unsigned byte at that address. Call the resulting byte the **selector**.

   This read address lies between 16 and 271 inclusive.

8. **Perform the byte-selected write through R.**  
   At R plus the sixth byte obtained in step 3, store the low byte of R.

9. **Read a signed displacement.**  
   Read a signed 16-bit value at T plus the selector. Call this value the **displacement**.

   The selector is an unsigned byte offset ranging from 0 through 255. No multiplication or alignment adjustment is visible before this read.

10. **Store the widened selector.**  
    At R plus 44, store the selector as a four-byte unsigned value. Its numeric value remains between 0 and 255.

11. **Store D through an offset also equal to D.**  
    At R plus D, store D as a four-byte integer.

    Both the destination offset and the stored integer derive from the same shifted value of B. D can be negative; the operation is not restricted to locations after R.

12. **Write another byte through R.**  
    At R plus 200, store the low byte of R minus 70, reduced modulo 256.

13. **Write the absolute-address byte.**  
    At absolute address 277, store the low byte of T minus 4, reduced modulo 256.

14. **Clear four bytes associated with T.**  
    Store the four-byte zero value at T plus 104.

15. **Construct the final arguments and transfer control.**  
    Form a derived address by adding eight times the signed displacement to T.

    Read the element represented at that derived address plus 22. Transfer control to T with three arguments, in this order:

    - The integer constant 252.
    - The derived address.
    - The element read at the derived address plus 22.

The signed displacement ranges from −32,768 through 32,767. Multiplication by eight therefore ranges from −262,144 through 262,136, without overflowing a signed 32-bit integer. Adding that offset to T may still wrap or produce an invalid address, depending on the actual address model.

The precise width and ABI representation of the third argument are not established.

### Aliasing and timing of reads

The accesses are not independent. Inputs may designate overlapping storage, and later reads observe memory after earlier writes.

Consequences include:

- The first two writes can change bytes subsequently used by the six-read chain.
- The write at Q minus 84 can change the selector’s source location before that selector is read.
- The byte-selected write through R can change the signed displacement before its read.
- Later writes can modify the derived-address element before the third argument is fetched.
- Writes through R or to absolute address 277 can overlap T or memory subsequently used for control transfer.

The contract does not permit treating every read as a snapshot of entry-state memory. Values already read are retained for their later uses, but future reads remain sensitive to intervening writes.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless stated otherwise, they assume valid accesses, no external concurrent modification, and no aliasing that changes the described values.

### Byte truncation and widening

If the low byte of R is 32, the write at R plus 200 stores byte value 218, because 32 minus 70 reduces to 218 modulo 256.

If the selector is 255, the four-byte write at R plus 44 represents unsigned integer 255, not signed integer −1. Its byte order remains platform-dependent.

### Repeated dependent reads

If the first read at S plus 31 returns 5, the second read is at address 36.

If that second read returns 200, the third read is at address 231. The remaining three reads continue the same rule. A conforming account must preserve all six reads and their dependency order.

### Zero shifted difference

If B is 87 multiplied by 262,144, Q is 87 and D is zero.

Subject to valid addresses:

- The Q-derived byte write targets address 3.
- The four-byte D write targets R itself and stores zero.

This example also demonstrates that the Q-derived destination need not be near B.

### Lower arithmetic boundary

If B is zero:

- Q is zero.
- D has the mathematical signed value −87.
- The four-byte D write targets R minus 87.
- The Q-derived byte destination corresponds to the wrapped 32-bit representation of −84.

Successful completion is not promised for that wrapped address.

### Negative final displacement

If the signed 16-bit displacement is −1, the second argument to F-indirect-01 is T minus 8. The third argument is read from the represented element at T plus 14, because the additional offset is 22.

Interpreting the displacement as unsigned would produce a different destination and would violate the visible signed-read behavior.

### Aliasing before a read

If the destination of the byte-selected write through R overlaps either byte of the forthcoming signed displacement read, that read must use the modified memory.

An implementation that captures the displacement before performing that write would not preserve the represented behavior.
