# F-945c6c006d3d

## Purpose

F-945c6c006d3d coordinates an optional call through an associated object, an optional callback stored in a primary object, and a conditional three-call sequence involving a temporary two-word record.

The established behavior is the ordering of these operations and the values supplied to them. The supplied evidence does not establish a higher-level operation such as destruction, notification, reference release, or task completion. Those are possible interpretations, not contractual semantics.

The function has no explicit return value. Its externally visible effects arise from its memory reads and the calls it makes. No runtime tests have been performed.

## Interface

|---|---|---|
| Primary object address | 32-bit address-bearing value | Base address for fixed-offset field reads. |
| Requested operation flag | Unsigned 32-bit integer | Initially supplied by the caller; conditionally replaced by an object byte. |
| Incoming callable value | Function-pointer-shaped value in the apparent 32-bit layout | Used to initialize the first word of a temporary record unless replaced by the associated-object dispatch target. |
| Auxiliary value | Uninterpreted 32-bit word | Initializes the second word of the temporary record. |

| Byte offset | Accessed representation | Observed use |
|---|---|---|
| `+0x04` | 32-bit word | Argument to the primary object's optional callback. |

| `+0x0C` | 32-bit address-bearing or handle-like word | Tested against zero; subsequently read again as an argument to F-f111da7737c5. |

| `+0x52` | Unsigned byte | Replaces the requested operation flag when the associated-object pointer is non-null. |

The associated object is accessed through an additional level of indirection:

- Its first word supplies a dispatch-table base address.
- A function pointer is read at byte offset `+0xA0` from that table base.
- That function is called with the associated-object address and a zero argument.

The temporary record consists of two adjacent 32-bit words:

| Record offset | Initial contents |
|---|---|
| `+0x00` | Incoming callable value, or the selected associated-object dispatch target if that dispatch occurred. |
| `+0x04` | Auxiliary value. |

The supplied representation supports a 32-bit layout interpretation. It does not independently establish a complete ABI, alignment rules, byte order, or all indirect-call signatures.

## Behavior

### 1. Select the effective operation flag

The function first reads the associated-object pointer from primary-object offset `+0x10`.

If that pointer is null:

- The incoming requested operation flag remains the effective flag.
- The byte at `+0x52` is not read.
- The associated-object dispatch is skipped, regardless of the incoming flag.

If the pointer is non-null:

- The function reads the byte at primary-object offset `+0x52`.
- That byte replaces the incoming requested operation flag.
- The byte is interpreted as unsigned, producing a value from 0 through 255.

The incoming flag is therefore not combined with the object byte. With a non-null associated object, the byte alone controls whether dispatch occurs. A zero incoming flag does not suppress dispatch when the byte is nonzero, and a nonzero incoming flag does not force dispatch when the byte is zero.

The associated-object pointer used for this decision and the ensuing dispatch is the value obtained by the initial read. The supplied body does not re-read the primary object's `+0x10` field for this stage.

### 2. Optionally invoke the associated-object dispatch target

Dispatch occurs only when both conditions hold:

1. The initially read associated-object pointer is non-null.
2. The effective flag is nonzero.

When dispatch occurs, the function reads the associated object's first word as a dispatch-table base, then reads the callable at table offset `+0xA0`.

That callable replaces the incoming callable value in the function's retained state. It is then invoked with:

- The initially read associated-object pointer.
- Zero as the second argument.

There is no separate null check for the dispatch-table base or selected callable.

The identity of the selected callable matters beyond this invocation: it becomes the initial first word of the later temporary record. The function does not substitute a return value from this call.

When dispatch is skipped, the incoming callable value remains selected. It is not invoked merely because it was supplied as an argument.

### 3. Initialize the temporary record

After the optional associated-object call returns, the function initializes a local two-word record:

- First word: the selected callable value.
- Second word: the original auxiliary value.

This initialization occurs before the primary-object callback check.

The function itself does not inspect the auxiliary value or dereference the selected callable value as part of this record initialization. A null incoming callable can therefore be stored in the record when dispatch is skipped. Whether later dependencies accept that record content is unknown.

The temporary record is local to this invocation. Its address is later passed to dependencies only if the final conditional branch is entered.

### 4. Optionally invoke the primary-object callback

The function reads the callback field at primary-object offset `+0x08` and tests it against null.

If the tested value is null, the callback invocation is skipped.

If it is non-null, the supplied body reads the callback field again for invocation and reads the word at primary-object offset `+0x04` as its sole explicit argument. It then invokes that callback.

The displayed expression does not establish the relative evaluation order between obtaining the invocation target and obtaining its argument. A contract requiring one of those reads to precede the other would exceed the evidence.

The callback stage occurs after the optional associated-object dispatch. Consequently, changes made by that earlier call to the primary object's callback or argument fields can affect this stage.

The callback's return value, if any, is not used by this function.

### 5. Conditionally execute the record-processing sequence

After the callback stage, the function reads primary-object offset `+0x0C` and tests the resulting word against zero.

If it is zero:

- F-17c2f3b940d8 is not called.
- F-f111da7737c5 is not called.
- F-U01 is not called.
- The function reaches its ordinary return.

If it is nonzero, the function performs the following ordered sequence, provided each call returns normally:

1. Calls F-17c2f3b940d8 with the temporary record's address and zero.
2. Reads primary-object offset `+0x0C` again and calls F-f111da7737c5 with that newly read value and the temporary record's address.
3. Calls F-U01 with the temporary record's address.

The initial nonzero test does not capture the value ultimately passed to F-f111da7737c5. F-17c2f3b940d8 runs between the test and the second read. If that dependency changes the field through an alias or other reachable state, the second read observes the then-current value.

In particular, if the field becomes zero after the branch is entered, the body still proceeds to F-f111da7737c5 and supplies the re-read zero. There is no second zero check.

The same temporary record address is supplied to all three dependencies. Because they receive access to that record, its initial contents cannot be assumed to remain unchanged between calls.

### 6. Return and failure behavior

After the selected operations complete normally, the function returns without an explicit result.

No error status is examined. No retry, recovery branch, exception handler, or explicit diagnostic appears in the supplied body.

If an indirect call or dependency does not return normally, the body provides no evidence that subsequent calls will execute. In particular, F-U01 is a sequential final call, not an established guaranteed-unwind action.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, all memory is valid, calls return normally, and dependencies do not change relevant fields.

1. **No associated object, callback, or final sequence.**  
   Given a null `+0x10` pointer, a null `+0x08` callback, and a zero `+0x0C` word, no call occurs. The incoming requested flag does not change that outcome. The `+0x52` byte is not read.

2. **Object byte suppresses dispatch.**  
   Given a non-null associated object, a zero byte at `+0x52`, and a nonzero incoming requested flag, F-U02 is not invoked. The record's first word is initialized from the incoming callable value.

3. **Object byte enables dispatch.**  
   Given a non-null associated object, a nonzero byte at `+0x52`, and a zero incoming requested flag, F-U02 is invoked with the associated-object address and zero. Its target address, rather than the incoming callable value, initializes the record's first word.

4. **Unsigned byte boundary.**  
   A byte value of 255 enables dispatch just as a byte value of 1 does. No signed-byte interpretation or flag-bit filtering is evidenced.

5. **Full normal call order.**  
   When all optional stages are enabled, the call order is F-U02, F-U03, F-17c2f3b940d8, F-f111da7737c5, then F-U01.

6. **Callback affects branch selection.**  
   If F-U03 changes `+0x0C` from nonzero to zero before returning, the final three-call sequence is skipped. Conversely, changing it from zero to nonzero enables that sequence.

7. **Branch value differs from forwarded value.**  
   If `+0x0C` is nonzero at the branch test but F-17c2f3b940d8 changes it to zero, F-f111da7737c5 is still invoked and receives zero as its first argument.

8. **Mutable record propagation.**  
   If F-17c2f3b940d8 modifies a record word, F-f111da7737c5 receives the same record storage containing that modification, absent intervening changes. F-U01 likewise receives that storage after F-f111da7737c5 returns.

9. **Non-returning dependency.**  
   If F-f111da7737c5 does not return normally, execution of F-U01 is not guaranteed by this function.
