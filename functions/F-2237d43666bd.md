Halfword reads are signed. For example, the halfword pattern 0xFFFF contributes −1, not 65,535, to subsequent arithmetic and addressing.

Character reads have unresolved signedness. A high-bit byte can therefore produce different widened values, affecting addresses and later halfword stores. This contract does not choose an interpretation.

Narrow stores use the destination-width representation supported by the actual execution model. Low-byte examples below describe bit patterns without resolving every out-of-range signed conversion.

Addition, multiplication, doubling, and signed left shifts occur. Universal modulo-32-bit arithmetic is not established. Overflow, negative signed shifts, integer-to-address conversion, and invalid address formation remain unresolved outside supported ranges.

The recurring offsets do not prove a record layout. In particular:

- Byte fields include offsets 0x01, 0x09, 0x0D, 0x11, 0x15, and 0x1D.

Different bases can identify overlapping storage. A byte at offset 0x15 can overlap a word at offset 0x14. Endianness is unknown.

An earlier captured value remains distinct from a later read of its source. The ordering described below establishes access dependencies, not atomicity, synchronization, or a total order between reads within one expression.

The terminal signed value is stored as a word at its own offset 0x54. The active base supplies a byte at the terminal external base’s offset 0x11. This pair occurs twice consecutively, using the same captured values.

The product of the terminal signed value and the initial operand starts a dependent word-read chain through offsets 0x44, 0x74, and 0x14. The result is the **chain base**. Its offset-0x14 word is captured as the **saved link** before that location receives twice the active base. Subsequent addressing uses the saved link, not a reread of the overwritten location.

A word at the saved link’s offset 0x14 is multiplied by the terminal signed value, producing the **product base**. The product base’s offset 0x74 supplies the **late word**. Multiplying the product base by the terminal signed value produces the **latest product**.

These names describe data provenance, not separately allocated objects.

Observable constraints on the terminal writes are:

After a further signed-value self-store, the late word supplies a byte at twice the latest product plus offset 0x11. Thus the terminal region contains five signed-value self-stores in total, conditional on reaching all of them.

## Acceptance examples

These are conditional static obligations, not executed tests.

1. **Intermediate state matters.** If both entry offset-0x54 word stores complete, the fourth argument is written before the entry base. Matching only the final contents is insufficient.

2. **Store widths differ.** For fourth-argument pattern 0x123456AB, the early word store carries the full pattern; its byte store carries 0xAB under the represented narrowing.

3. **Signed halfword addressing.** A halfword pattern of 0xFFFF contributes −1. Substituting 65,535 is not equivalent.

4. **Character interpretation remains conditional.** A read byte of 0xFF can contribute −1 or 255 according to unresolved character signedness. Its destination cannot be fixed from the byte pattern alone.

5. **External observations can differ.** If a source changes between its base capture and associated value observation, the destination base and stored external word need not be equal.

6. **Fresh reads remain fresh.** If an earlier write changes the first argument’s offset 0x64, a later one of its six observations uses the then-current contents.

7. **Overwrite does not refresh a capture.** Updating the chain base’s offset 0x14 with twice the active base does not replace the saved link already captured there.

8. **Terminal reads are distinct.** If intervening writes change the latest product’s offset 0x44, its two observations may supply different bytes.

9. **Final byte provenance differs.** If twice the latest product has low byte 0x28 and the late word has low byte 0x7B, the final selected destination’s offset 0x09 receives 0x28. The separate doubled-product-address destination receives 0x7B, subject to valid arithmetic and accesses.

10. **Control transfers gate later effects.** Non-returning F-U1 prevents subsequent slot assignments and F-cdec09f5d432. Non-returning F-cdec09f5d432 prevents F-U2. If both return and preceding operations complete, the represented terminal continuation path is reached.
