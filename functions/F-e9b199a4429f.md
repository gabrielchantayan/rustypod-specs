# F-e9b199a4429f

## Purpose

F-e9b199a4429f conditionally constructs and submits one 32-bit word, then marks a designated object with flag `0x200`.

The supplied static evidence establishes two construction paths:

- A displacement-like path that calls F-5c41f627540d three times and combines selected results with an object byte and fixed encoding bits.
- A transfer-like path that calls F-cbaaedb97720, then combines bytes from two objects with a different fixed encoding.

If the designated object already has flag `0x200`, the function does nothing further.

**Inferred intent:** the constants and field placement resemble 32-bit instruction encodings, and the flag appears to record that an object has been materialized or otherwise handled. These interpretations are not prerequisites for the behavioral contract. The established behavior is word construction, submission, and a flag update; instruction execution and successful materialization are not established.

## Behavior

### 1. Initial gate

The first observable access is a 32-bit read of the designated object’s flag word at offset `0x18`.

If bit `0x200` is set:

- No context-selected object is read.
- No dependency is called.
- No word is submitted.
- No memory is written by this function.
- The function returns.

Other flag bits do not affect this initial decision.

If bit `0x200` is clear, execution proceeds.

### 2. Path selection

The function reads the object address at context offset `0x08`.

If that address equals the designated object’s address, the displacement-like path is selected. There is no second flag read for the purpose of selecting the path.

If the addresses differ, the function reads the selected object’s 32-bit flag word at offset `0x18`:

- Bit `0x200` clear: select the displacement-like path.
- Bit `0x200` set: select the transfer-like path.

Address equality, not structural equality or matching field contents, controls the equal-object case.

This decision is not revisited after subsequent dependency calls.

### 3. Displacement-like construction

This path calls F-5c41f627540d exactly three times, in sequence. Every call receives the environment and context arguments.

The three results have distinct roles:

1. The first result is interpreted as a signed 32-bit value and is used only to choose whether the second result is negated.
2. The second result supplies the initial 32-bit contribution to the constructed word.
3. The third result is interpreted as signed and controls whether bit `0x00800000` is contributed.

The calls must not be treated as one computation whose result can be reused. Their return values may differ, and their side effects may be observable.

If the first result is negative, the initial contribution is the negation of the second result, represented in the 32-bit word domain. Otherwise, the second result is used directly as a 32-bit contribution.

This is not necessarily the absolute value of any one result. For example, a negative first result followed by a positive second result causes the positive second result to be negated.

The function then reads the designated object’s unsigned byte at offset `0x0C`, shifts its value left by 12 positions, and combines that contribution with the initial contribution using bitwise OR.

This byte read occurs after the second dependency call and before the third. Consequently:

- Side effects from either of the first two calls can affect the byte read.
- Changes to that byte during the third call do not change the already captured contribution.

After the third result is obtained, the function combines the current word with:

- Fixed bits `0xE51B0000`.
- An additional `0x00800000` when the third result is nonnegative.
- No additional bits from that sign selection when the third result is negative.

Thus, for the ordinary sign interpretation shown by the supplied representation, the fixed encoding contribution is:

| Third result | Fixed encoding contribution |
|---|---:|
| Negative | `0xE51B0000` |
| Zero or positive | `0xE59B0000` |

The sign test on the first result and the sign-dependent encoding from the third result are independent.

No mask confines the second result’s contribution to a displacement-sized field. All of its resulting 32 bits participate in the OR operation. Likewise, the full unsigned object byte participates after shifting; it is not restricted to four bits. Contributions outside a presumed field can therefore set bits otherwise associated with the fixed encoding or neighboring fields.

The exact result of negating the minimum signed 32-bit value is not established by the supplied representation; see **Uncertainties**.

### 4. Transfer-like construction

This path is selected only when the initially selected object differs from the designated object and has flag `0x200`.

The function reads the 32-bit value at offset `0x08` of that initially selected object and passes it to F-cbaaedb97720. The dependency’s result, if any, is not used.

After that call, the function reads the object address from context offset `0x08` again. It then reads the unsigned byte at offset `0x0C` of this newly selected object.

The object used for this byte need not be the object whose flag selected the path or whose field was passed to the dependency. F-cbaaedb97720 may have changed the context’s selected object.

The function also reads the designated object’s unsigned byte at offset `0x0C`. Both byte reads occur after F-cbaaedb97720 returns. The supplied expression does not establish a relative evaluation order between the designated-object byte read and the context reload/source-byte read.

The submitted word is the bitwise OR of:

- Fixed bits `0xE1A00000`.
- The newly selected object’s unsigned byte, unshifted.
- The designated object’s unsigned byte shifted left by 12.

Neither byte is masked to a narrower logical field. In particular, the unshifted source contribution can occupy bits 0 through 7, not merely bits 0 through 3.

No post-call flag check is performed on the newly selected object. A changed context pointer does not cause path selection to restart.

### 5. Submission and marking

Both construction paths converge on one call to F-80812c986798.

Its arguments are:

1. The 32-bit value read from environment offset `0x10`.
2. The constructed 32-bit word.

The environment field is read after word construction and after all earlier dependency calls on the chosen path. A dependency’s modification to that field can therefore affect the submission destination or handle.

After F-80812c986798 returns, the function:

1. Rereads the designated object’s 32-bit flag word at offset `0x18`.
2. Sets bit `0x200` by bitwise OR.
3. Writes the resulting 32-bit flag word back to the same field.

This uses the flag word present after submission, not the value captured at entry. Other flag bits present in that final read are preserved.

The mark is applied without testing a submission result. If F-80812c986798 returns normally, the flag update follows even if that dependency internally recorded a failure. If a dependency does not return normally, subsequent operations are not established to occur.

## Acceptance examples

These are conditional static acceptance examples, not reports of executed tests. Unless stated otherwise, dependencies return normally, required storage remains valid, and no unmentioned mutation occurs.

### Already marked

Given an initial designated-object flag word of `0x00000240`, the function returns after its initial flag read. It performs no dependency calls and leaves that word unchanged.

The environment and context need not be dereferenced on this path.

### Equal objects bypass the second-object flag test

Given an initially clear designated-object flag and a context-selected address equal to the designated object’s address, the function selects the displacement-like path.

It calls F-5c41f627540d three times, does not call F-cbaaedb97720, submits once, then marks the designated object.

### Distinct results remain distinct

Given:

- A displacement-like path.
- Designated-object byte `2`.
- Successive F-5c41f627540d results of `5`, `12`, and `-1`.

The submitted word is `0xE51B200C`.

Changing only the third result to zero changes the submitted word to `0xE59B200C`. The first result does not substitute for the second or third.

### Negative first result controls negation

Given successive results of `-7`, `-20`, and `0`, and designated-object byte `2`, the second result is negated to contribute `20`. The submitted word is `0xE59B2014`.

This example depends on the second result, not on the magnitude of the first.

### Transfer after preparation

Given a distinct, initially marked context-selected object, with source byte `3` and designated-object byte `2`, the transfer-like path calls F-cbaaedb97720 before reading the encoding bytes.

If the dependency leaves the relevant state unchanged, the submitted word is `0xE1A02003`.

If it instead changes the context-selected address to another valid object whose byte is `7`, the submitted word is `0xE1A02007`. The replacement object’s flag is not checked.

### Final flags reflect submission-time mutation

Suppose F-80812c986798 changes the designated object’s flag word to `0x40` and returns normally. The subsequent final read and write produce `0x240`.

The entry-time flag word is not restored.
