# F-476e44dfd77f

## Purpose

F-476e44dfd77f transfers five consecutive 32-bit values from a caller-supplied address into five consecutive fields of globally selected storage, then returns a 32-bit zero.

The established behavior is an ordered sequence of five read-and-write operations, not an atomic update and not necessarily a snapshot copy. Each input value is obtained for its corresponding assignment after the preceding assignment has completed. Overlap between input and destination storage can therefore affect the values transferred.

The apparent intent is to update a five-field record within a larger object. That interpretation is inferred from the contiguous destination layout; the meanings of the fields and the larger object are unknown.

## Interface

### Input

The function accepts one address identifying storage for five consecutive 32-bit values.

| Input element | Byte offset from input address | Width |
|---|---:|---:|
| First | 0 | 32 bits |
| Second | 4 | 32 bits |
| Third | 8 | 32 bits |
| Fourth | 12 | 32 bits |
| Fifth | 16 | 32 bits |

The input span is 20 bytes. There is no length argument, presence flag, or format tag. All five elements are accessed on a normal execution.

The values are treated as opaque 32-bit quantities. The supplied representation establishes no signed interpretation, numerical conversion, field validation, byte swapping, or pointer dereference through any transferred value.

### Implicit input

A global location supplies a destination base address. This base identifies storage containing the destination fields; it is not supplied by the caller as an explicit argument.

The supplied representation distinguishes:

- A base value captured at entry.
- A further use of the global base expression for the first destination.
- Use of the captured base for the remaining four destinations.

With a stable global base, all five destinations belong to the same contiguous 20-byte region. The distinction matters if that global can change between its uses.

### Output

Normal completion returns a 32-bit value whose bits are all zero.

The return value does not encode any transferred field, count, previous value, or validation result. There is no established nonzero return path.

### Preconditions for normal completion

The caller and surrounding environment must provide:

- Readable storage for each input access when that access occurs.
- A usable global destination-base value.
- Writable storage at every destination address actually selected.
- Address calculations and access alignment supported by the target execution environment.

These are access requirements, not checks performed by this function. Null addresses, inaccessible storage, invalid bases, and unsupported alignment have no documented recovery behavior.

Input and destination storage are not required by the visible body to be disjoint. However, overlapping storage must be interpreted according to the ordered behavior below.

## Behavior

### Destination layout

For a stable destination base, the function writes the following fields:

| Transfer order | Input byte offset | Destination byte offset | Width |
|---|---:|---:|---:|
| First | 0 | 492 | 32 bits |
| Second | 4 | 496 | 32 bits |

The destination fields occupy byte offsets 492 through 511 inclusive, relative to that base. The total explicitly written span is 20 bytes.

The offset of the third field is 500 bytes, not 500 elements. All five destination offsets advance in four-byte increments.

### Ordered transfer

The established sequence is:

1. Capture the global destination base.
2. Obtain the first input value and write it at offset 492 from the base selected by the first assignment’s global-base expression.
3. Obtain the second input value and write it at offset 496 from the captured base.
4. Obtain the third input value and write it at offset 500 from the captured base.
5. Obtain the fourth input value and write it at offset 504 from the captured base.
6. Obtain the fifth input value and write it at offset 508 from the captured base.
7. Return 32-bit zero.

This describes the ordering of completed assignments established by the supplied representation. It does not establish a machine-instruction trace, atomic memory operations, or an exact evaluation order between an assignment’s destination-address expression and its input-value expression.

There is no preliminary read of all five input values. In particular, an earlier destination write may change storage used by a later input read.

### Stable-base behavior

When the global base remains stable, input and destination storage do not interfere, and every access succeeds, the result is a bit-preserving transfer:

- Destination offset 492 receives the first input value.
- Destination offset 496 receives the second.
- Destination offset 500 receives the third.
- Destination offset 504 receives the fourth.
- Destination offset 508 receives the fifth.

Existing destination values are overwritten. They are neither returned nor explicitly read before replacement.

### Changing-base behavior

The first destination expression uses the global base separately from the entry capture. The other four destination addresses use the captured base.

Consequently, the representation does not justify a contract that all five writes must follow every later change to the global base. Nor does it justify ignoring the separate global use for the first destination.

For ordinary storage with a stable global, this distinction has no effect. Whether two physical global loads occur, or whether changes from another execution context can be observed, requires information beyond the supplied representation.

### Overlap behavior

Each later input access sees the storage available at that point in the sequence. The function does not preserve original input contents against its own preceding writes.

If a destination field overlaps a later input element, the later read can obtain the value written by an earlier transfer. This is a consequence of the assignment order, not an additional propagation feature.

If each destination field coincides exactly with its corresponding input element, the transfers write back the same values they read, provided the storage is ordinary readable and writable memory and there is no intervening mutation.

Partial-byte overlap is not given a portable byte-level contract here. Its outcome depends on address validity, alignment, representation, and memory-access semantics not established by the supplied material.

### Arithmetic and representation

The explicit payload width is 32 bits per field. The function performs no arithmetic on those payload values.

Destination offsets are byte displacements. The contract requires the resulting addresses to be valid; it does not prescribe wrapping at an address-space boundary.

The exact address width, pointer representation, integer-to-address behavior, and overflow rules are not established sufficiently to define boundary-address behavior. A 32-bit payload width alone does not prove a 32-bit address space.
