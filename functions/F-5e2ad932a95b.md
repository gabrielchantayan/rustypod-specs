# F-5e2ad932a95b

## Purpose

F-5e2ad932a95b modifies eight 32-bit fields in a caller-supplied memory region. It clears six low bits in selected fields, rounds other fields to a 64-unit grid, and recomputes two fields using the original values of a mode-selected pair.

The selector has two behaviors: zero and nonzero. All nonzero selector values take the same path.

**Established behavior:** the routine performs fixed-width arithmetic and in-place writes. It returns no value and invokes no dependencies.

**Inferred intent:** the fields may describe coordinates, extents, and associated positions on a grid with 64 units per step. The two recomputed fields resemble adjusted extents. These interpretations are not established field types or application-level guarantees.

## Behavior

### Arithmetic model

All field arithmetic below is interpreted on 32-bit words. Addition and subtraction wrap modulo \(2^{32}\). This is important near the limits of the word range; these operations are not saturating and do not use an unbounded intermediate result.

Define three transformations:

- \(D(x)\): clear the lowest six bits of \(x\), equivalently retain only bits selected by `0xFFFFFFC0`.
- \(U(x)\): add 63 with 32-bit wraparound, then apply \(D\).
- \(H(x)\): add 32 with 32-bit wraparound, then apply \(D\).

For ordinary nonnegative values away from overflow:

- \(D\) rounds down to a multiple of 64.
- \(U\) rounds up to a multiple of 64.
- \(H\) rounds to a multiple of 64, with an exact half-step rounded toward the higher multiple.

The bit operations, rather than these geometric descriptions, govern all 32-bit inputs.

In the formulas below, “original” means the field value at entry under the stable-memory precondition.

### Final values shared by both selector paths

Both paths produce these anchor and position results:

### Alignment and boundary properties

On normal completion, all eight output fields have their lowest six bits clear. This includes the extents, because each is the difference of two multiples of 64 in 32-bit arithmetic.

Other important boundaries:

- Already aligned anchors remain unchanged by their respective rounding operations.
- A zero extent need not remain zero. An unaligned associated anchor can cause it to become 64.
- Negative-looking bit patterns are not rejected.
- Extents are not checked for positivity, consistency, or physical plausibility.
- Overflow can produce zero or a high unsigned value; it is not reported.
- \(H\) uses an exact 32-unit bias. It is not round-to-even.
- Under stable-memory assumptions, applying the routine again with the same selector leaves the result unchanged. After one call, all relevant fields are multiples of 64, so the rounding and extent formulas preserve them. This is a derived arithmetic property, not a separately checked condition.

- Anchor A becomes 64.
- Anchor B becomes 128.
- Both extents become 64.

The routine does not preserve empty extents merely because their input value is zero.

### Wraparound

Using hexadecimal 32-bit words:

- Anchor B initially `0xFFFFFFFF` becomes `0x00000000`, because adding 63 wraps before masking.
- Any downward-rounded anchor initially `0xFFFFFFFF` becomes `0xFFFFFFC0`.
- Either position initially `0xFFFFFFE0` becomes `0x00000000`, because adding 32 wraps exactly to zero.

These results must not be replaced by saturating arithmetic.
