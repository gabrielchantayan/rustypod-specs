# F-4e12fc80816d

## Purpose

F-4e12fc80816d selects a configuration operation using a signed numeric selector, performs that operation, and then records the low eight bits of two arguments in selector-indexed storage. Every normally completing path returns zero.

**Established static behavior:** selector-dependent word accesses, masked updates, dependency calls, two polling loops, and two final byte stores.

**Inferred intent:** configuration of related peripheral channels or fields. The supplied representation does not establish peripheral identity, register meanings, supported configuration values, or whether the storage is hardware-backed.

This contract describes the supplied static representation. It does not assign semantics to unknown dependencies or assume they preserve globals, preserve memory, or return normally.

| Return value | A 32-bit zero on normal completion. No nonzero error return is visible. |

### Storage model

The following are descriptive names, not source identifiers:

- **Register binding:** a global binding to word-addressed storage. Words 0–5 are 32 bits wide, at byte offsets 0, 4, 8, 12, 16, and 20.
- **Entry register base:** the register binding captured at function entry.
- **Auxiliary binding:** a global binding used to obtain one 32-bit input for selector 5.
- **Standalone binding:** a global binding used for selector 8’s 32-bit store.
- **Bookkeeping binding:** a global address binding used after dispatch.

Accesses through the entry register base and accesses through the global register binding are distinguished below. A dependency changing the global binding does not redirect an access explicitly using the entry capture.

Bookkeeping uses a different sequence:

1. Capture the bookkeeping binding after dispatch.
2. Separately consult that global binding to address the mode-byte store.
3. Use the earlier capture to address the value-byte store.

The mode-byte destination is the separately consulted binding plus selector. The value-byte destination is the captured binding plus 17 plus selector. These use the same base only under an appropriate binding-stability assumption.

This distinction describes the supplied representation’s evaluations and address sources. It does not independently establish distinct physical loads, bus transactions, or memory-ordering guarantees.

With a stable bookkeeping binding, two adjacent 17-byte tables are consistent with selectors 0–16. Allocation size and supported selectors are not established.

### Arithmetic conventions

Value-derived arithmetic is unsigned and 32-bit. Subtraction wraps modulo \(2^{32}\); right shifts are logical.

The following names abbreviate encodings:

| Encoding | Definition |
|---|---|
| Short | \((\text{value}-1)\mathbin{\&}15\) |
| Half | \(((\text{value}\gg1)-1)\mathbin{\&}15\) |
| Wide-half | \(((\text{value}\gg1)-1)\mathbin{\&}31\) |

Mode contributes these masks:

| Mode | Low mode bits | High mode bits |
|---|---:|---:|

Contributions are combined by bitwise OR. Existing bits are removed only where a stated preservation mask clears them.

Valid storage for every executed access is a prerequisite for ordinary completion. The function performs no visible bounds, alignment, pointer, selector, mode, or value validation.

## Behavior

### Common sequencing

The function captures the entry register base and calculates the three value encodings before dispatch.

After the selected operation completes normally, it:

1. Captures the then-current bookkeeping binding.
2. Separately consults that binding and stores the low eight bits of mode at selector offset.
3. Stores the low eight bits of value at offset 17 plus selector from the earlier capture.
4. Returns zero.

There is no dependency call between these bookkeeping operations. Nevertheless, the representation does not justify replacing the separate binding consultation with the earlier capture without a stability assumption.

A dependency that does not return, a storage fault, or an endless polling loop can prevent bookkeeping and return. No rollback is visible.

### Selector 0: update words 0 and 1, then poll

The function prepares word 0 by reading it through the global register binding, preserving only bits 16–31, and ORing in the low mode bits.

It next reads word 1 through the global register binding and prepares:

- For value 1: the original low 24 bits only.
- For every other value: the original low 24 bits, ORed with wide-half shifted left 24 bits and `0x40000000`.

It writes the prepared word 0 through the global register binding, then writes the prepared word 1 through the entry register base.

It then repeatedly reads word 0 through the entry register base until its low 16 bits equal the prepared word 0’s low 16 bits. Upper-half differences do not prevent completion. At least one polling read is represented; there is no timeout or retry limit.

### Selectors 1, 3, 7, 9, 10, and 13

These selectors have no dispatch-specific calls or register writes. Common bookkeeping still occurs.

### Selector 2: delegated configuration

The function calls F-47de6633aece with mode followed by value. Its result is unused. Normal return from the dependency is followed by bookkeeping.

### Selector 4: transformed word-1 update and polling

The function reads word 1 through the global register binding and preserves all bits except bits 8–15, using `0xFFFF00FF`.

For value other than 1, it additionally ORs in wide-half shifted left 8 bits and `0x00004000`. Value 1 adds neither.

It passes the complete candidate word to F-5c24bc78359c. The dependency’s 32-bit result is written to word 1 through the entry register base.

Polling repeatedly reads word 1 through that same entry base until bits 8–15 match those of the dependency result. Other bits are irrelevant to completion. No timeout is visible.

Mode does not affect this branch’s candidate, but its low byte is recorded during bookkeeping.

### Selector 5: dependency-assisted upper-half update of word 4

The operation has this order:

1. Read the auxiliary word and call F-000000000001 with that word followed by value. Its result is unused.
2. After the call returns, read word 4 through the entry register base.
3. Preserve only bits 0–15 and OR in the high mode bits.
4. Add the value-dependent encoding below.
5. Call F-73ad38c1c987 without arguments.
6. After that call returns, write the prepared word to word 4 through the entry register base.

| Value condition | Additional bits |
|---|---|
| Value 1 | None |
| Value below 17, excluding 1 | Short shifted left 16 bits |
| Value at least 17 | Half shifted left 16 bits, plus `0x00100000` |

Zero belongs to the below-17 case.

The first dependency may change word 4 before its read; those changes can affect the preserved low half. Initial contents before the dependency do not establish the later read value.

The second dependency runs after preparation. Its changes to the destination word may be overwritten by the prepared write. Neither dependency is assumed to preserve any global binding.

### Selectors 6 and 12: lower-field update followed by a call

Selector 6 targets word 3; selector 12 targets word 4.

The function reads the target through the global register binding, preserves bits 15–31 with `0xFFFF8000`, and ORs in the low mode bits. Bits 0–14 of the original word are cleared.

It then adds:

| Value condition | Additional bits |
|---|---|
| Value 1 | None |
| Value below 18, excluding 1 | Short in bits 0–3 |
| Value at least 18 and even | Half in bits 0–3, plus `0x00000010` |
| Value at least 18 and odd | Dependency-derived nibble in bits 0–3, plus `0x00000020` |

For the odd, at-least-18 case, F-000000000001 receives value followed by 3. The derived nibble is its returned 32-bit result minus one, with unsigned wrapping, masked to four bits.

The target read precedes this dependency call. The later write uses the already prepared contents and the entry register base, not a newly obtained global base.

After the write, F-356357e9691d is called with 100. Bookkeeping follows its normal return. The argument’s units and any timing effect are unknown.

### Selector 8: standalone store

### Selector 11: mixed-position update of word 3

The function reads word 3 through the global register binding and preserves bits 15–31 with `0xFFFF8000`. It ORs in the high mode bits.

Value-dependent contributions are:

| Value condition | Additional bits |
|---|---|
| Value 1 | None |
| Value below 18, excluding 1 | Short in bits 0–3 |

## Side effects

### Accesses, concurrency, and aliasing

The represented register accesses are 32-bit reads or writes. Each final bookkeeping store is one byte.

Read-modify-write updates are not demonstrated atomic operations. Changes made after a read and before its write may be lost, including changes made by dependencies between those operations.

No explicit lock, barrier, or synchronization primitive is visible. Volatile qualification, hardware read/write side effects, actual bus transactions, and compiler access-combining behavior are not established.

Polling completion establishes only equality of the compared field at an observed read. It does not establish equality of the full word or broader device completion.

If addressed regions overlap, earlier writes may affect later reads or destinations. Bookkeeping may overwrite bytes of register storage. Such aliasing must be evaluated using the stated order.

### Global-binding changes

Dependencies are not assumed to preserve bindings or pointed-to memory.

- Entry-base accesses continue to use the captured register base after a dependency changes the global register binding.
- Selector 5 reads word 4 through the entry base only after its first dependency returns. That word’s contents may already have changed.
- Bookkeeping begins after all normally returning dispatch dependencies.
- Bookkeeping first captures its binding, then separately consults the global binding for the mode-byte destination.
- Only the value-byte store explicitly uses the earlier bookkeeping capture.

A dependency’s change to the bookkeeping binding before dispatch completes affects the binding subsequently captured. A change between that capture and the separate consultation can make the stores use different bases. Whether such an intervening change can occur in the execution environment is **documented_only**.

### Ownership and failure

No allocation, release, ownership transfer, or explicit resource acquisition is visible in this function. Dependency ownership behavior is unknown.

No recovery is visible for access faults, dependency failures, nonreturn, or stalled polling. Partial side effects may remain. Zero is a normal-completion return, not a demonstrated validation or hardware-success status.

## Acceptance examples

These are conditional static examples, **not executed tests**. They assume valid nonaliasing storage, stable bindings, ordinary word-storage behavior, and normal dependency return unless stated otherwise. Dependency memory preservation is not implied.

1. **Selector 0, mode 2, value 1.**  
   Given reads of word 0 as `0xABCD5678` and word 1 as `0xFFFFFFFF`, the writes are `0xABCD2000` and then `0x00FFFFFF`. Completion requires a subsequent word-0 read whose low half is `0x2000`.

2. **Selector 4 uses the returned word.**  
   A word-1 read of `0x12345678` with value 2 produces candidate `0x12344078`. If F-5c24bc78359c returns `0xAABBCCDD`, that returned word is written. Polling requires `0xCC` in bits 8–15, not the candidate’s field.

3. **Selector 5’s boundary uses post-call state.**  
   With mode zero and the low 16 bits of word 4 equal to zero **when read after F-000000000001 returns**, value 16 prepares `0x000F0000`; value 17 prepares `0x00170000`. F-73ad38c1c987 must return before either write. An initially zero word before the first dependency is insufficient unless that dependency preserves the relevant low bits.

4. **Selector 5 incorporates a first-dependency mutation.**  
   If the first dependency leaves word 4 with low half `0x1234` at the post-call read, mode zero and value 16 prepare `0x000F1234`, irrespective of the word’s earlier contents.

5. **Selector 6 crosses its boundary at 18.**  
   With a target read of zero and mode zero, value 17 prepares zero; value 18 prepares `0x00000018`. Each write precedes the call to F-356357e9691d with 100.

6. **Odd large values depend on the unknown result.**  
   For selector 12, mode zero, value 19, and a target read of zero, a result of zero from F-000000000001 produces `0x0000002F`. Subtracting one wraps, yielding nibble 15.

7. **Selector 11 retains high bits.**  
   A word-3 read of `0x10000000`, mode 2, and value 1 produces `0x30000000`, not `0x20000000`.

8. **Selector 11 places small encodings low.**  
   A word-3 read of zero, mode zero, and value 3 produces `0x00000002`, not `0x00020000`.

9. **Zero is accepted by the visible arithmetic.**  
   Selector 8 with value zero writes `0xFFFFFFFF`. Selector 15 with mode zero, value zero, and a target read of `0x1234ABCD` writes `0x1234000F`.

10. **Bookkeeping truncates arguments.**  
    Selector 1, mode −1, and value `0x12345678`, with stable bookkeeping binding, store `0xFF` at offset 1 and then `0x78` at offset 18, returning zero.

11. **Bookkeeping bases need not coincide.**  
    If the bookkeeping capture yields one base but the separate consultation yields another, selector 1 stores the mode byte at offset 1 from the second base and the value byte at offset 18 from the first. This is conditional on such a binding change being possible; it asserts no independently verified physical transaction sequence.

12. **Unsupported selectors still index storage.**  
    Selector 17 has no dispatch-specific operation. With stable bookkeeping binding it stores at offsets 17 and 34. Safety depends on available storage, not a function-side check.
