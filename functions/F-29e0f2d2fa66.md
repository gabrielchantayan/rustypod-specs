# F-29e0f2d2fa66

## Purpose

F-29e0f2d2fa66 scans an indexed collection of signed 32-bit values against a parallel collection of signed 32-bit requirements. A zero requirement makes an entry inactive. An active entry must have a nonzero value with the same sign as its requirement.

For each acceptable active entry, the function obtains a factor and passes it, together with a running 32-bit result, to F-8f41f510c86c. The initial running result is 65,536. The factor is either:

- The magnitude of the entry value, when flag bit `0x4000` is clear.
- A dependency-produced result based on the entry’s distance from one of two strict bounds, when that bit is set.

An entry failing a checked condition causes an immediate return of zero. Otherwise, the final running result is returned.

**Inferred intent:** the constant 65,536 suggests a fixed-point scale. Neither the mathematical operation performed by F-8f41f510c86c nor the units of the input values are established. This contract does not assign multiplication, division, normalization, or probability semantics to the result.

## Interface

### Inputs

The function has five inputs:

1. **Collection descriptor address.** Addresses a structure whose two observed fields are:
   - At byte offset 0: an unsigned 32-bit entry count.
   - At byte offset 4: a 32-bit address of the entry-value array.

   No additional fields are accessed directly by this function.

2. **Flags.** An unsigned 32-bit value. Only bit `0x4000` is inspected by the visible body.

3. **Requirements address.** Addresses an array of signed 32-bit requirements. Entries are selected at four-byte intervals.

4. **Lower-bounds address.** Addresses an array of signed 32-bit lower bounds. It is accessed only in bounded mode, and only after an active entry passes the nonzero and sign checks.

5. **Upper-bounds address.** Addresses an array of signed 32-bit upper bounds. It is accessed only in bounded mode, and only after the corresponding lower-bound check passes.

The entry-value array likewise contains signed 32-bit elements at four-byte intervals.

The visible representation uses 32-bit address-bearing fields and four-byte element strides. Broader ABI details, alignment requirements, and valid address ranges are not supplied.

### Output

The output is a 32-bit word:

- Zero for any explicit entry rejection.
- 65,536 if the scan completes without processing an active entry.
- Otherwise, the most recent result returned by the three-argument use of F-8f41f510c86c.

Zero is not an unambiguous failure discriminator: the dependency may itself return zero, and the function does not distinguish that result from an explicit rejection.

## Behavior

### Scan and termination

The function initializes a running result to 65,536 and an unsigned 32-bit entry index to zero.

At the start of each iteration, it reads the current entry count from the descriptor. If the index is greater than or equal to that count under an unsigned comparison, it returns the running result immediately.

The count is therefore not a fixed snapshot. A dependency’s effects on the descriptor, if any, can affect later termination checks.

For an index still within the currently observed count, the function reads that index’s signed requirement.

- If the requirement is zero, it does not read the entry value or either bound for that entry.
- If the requirement is nonzero, the entry undergoes the checks and factor processing below.

After an entry is skipped or successfully processed, the index advances by one and the function repeats the count check.

### Active-entry validation

For a nonzero requirement, the function reads the entry-value array address from the descriptor, then reads the indexed signed entry value.

The following cases reject the entire operation immediately with zero:

- The entry value is zero.
- The entry value is negative and the requirement is positive.
- The entry value is positive and the requirement is negative.

Because this path is entered only for nonzero requirements, successful validation means that both values are strictly positive or both are strictly negative.

These checks precede all bound reads and dependency calls for the entry.

The requirement’s magnitude does not impose a general threshold on the entry value. In unbounded mode, it has no further effect after sign validation. In bounded mode, its signed ordering relative to the entry value selects which distance is used.

### Unbounded mode

When flag bit `0x4000` is clear:

- A positive entry value is used directly as the factor.
- A negative entry value is negated to obtain the factor.
- Neither bounds array is read by the visible body.
- There is no separate two-argument dependency call to construct the factor.

The function then invokes F-8f41f510c86c with three visible arguments, in this order:

1. The running result.
2. The factor.
3. The constant 65,536.

The returned 32-bit word replaces the running result.

For an entry value of −2,147,483,648, mathematical negation cannot be represented as a positive signed 32-bit integer. The exact overflow behavior is not established by the supplied representation; this edge case is documented_only rather than assigned an assumed magnitude.

### Bounded mode

When flag bit `0x4000` is set, the function performs ordered strict-bound checks:

1. Read the indexed lower bound.
2. Reject with zero unless the entry value is strictly greater than that lower bound.
3. Read the indexed upper bound.
4. Reject with zero unless the entry value is strictly less than that upper bound.

Both comparisons are signed. Equality with either bound is rejected.

Only after both checks pass does the function choose a distance:

- If the entry value is strictly less than the requirement, use the entry value minus the lower bound.
- Otherwise, use the upper bound minus the entry value.

Equality between the entry value and requirement takes the second branch: distance to the upper bound.

This is not necessarily a selection of the nearer bound. It is controlled by the signed comparison with the requirement. The requirement is not required to lie between the bounds.

The function invokes F-8f41f510c86c with two visible arguments:

1. The selected distance.
2. The constant 65,536.

It uses the returned 32-bit value as the factor for the subsequent three-argument call:

1. The current running result.
2. That factor.
3. The constant 65,536.

The latter return value replaces the running result.

With ordinary nonoverflowing arithmetic, the selected distance is positive because the entry has already passed both strict bounds. However, a positive mathematical difference can exceed the signed 32-bit range. The visible body does not detect that case.

### Early exits and dependency results

An explicit rejection returns zero immediately, regardless of any running result accumulated from earlier entries.

A dependency result of zero does not trigger an early exit. The function continues to subsequent entries unless an explicit rejection occurs, the count check terminates the scan, or a dependency fails to return normally.

There is likewise no visible shortcut for any other dependency result.

## Side effects

### Direct memory access

The function has no visible direct writes to caller-provided memory. Its own state changes consist of the running result, current index, and temporary values.

For each iteration, the direct-read order is:

1. Descriptor count.
2. Requirement, if the index is below that count.
3. Descriptor’s entry-array address, if the requirement is nonzero.
4. Entry value.
5. Lower bound, only after sign validation and only in bounded mode.
6. Upper bound, only after the lower-bound check passes.

The dependency calls occur after the reads needed for that entry. In bounded mode, the factor-producing call precedes the running-result update call.

A failing check prevents later reads and calls for that entry. Termination at the count check prevents all array reads for that iteration.

## Acceptance examples

These examples are conditional on readable memory, defined arithmetic, normal dependency returns, and no dependency-driven changes that alter later scan inputs. They describe required observable behavior, not results of executed tests.

### Empty collection

If the first observed count is zero:

- Return 65,536.
- Do not read any requirement, entry value, or bound.
- Do not call F-8f41f510c86c.

### Inactive entries

If the count is three and all three requirements are zero:

- Read the requirements in index order.
- Do not read the entry-array address or entry values.
- Do not read bounds.
- Make no dependency calls.
- Return 65,536 once the index reaches the count.

This remains true with flag bit `0x4000` set.

### Zero active value

With a nonzero requirement and an entry value of zero:

- Return zero.
- Do not read either bound for that entry.
- Make no dependency call for that entry.

Earlier dependency effects, if any, remain outside any visible rollback mechanism.

### Sign mismatch

A requirement of −4 and entry value of 7 reject with zero. A requirement of 4 and entry value of −7 also reject with zero.

The flag setting and bound contents do not change these outcomes because the sign rejection occurs first.

### Unbounded negative entry

For one active entry with requirement −2, entry value −7, and bit `0x4000` clear:

- The factor is 7.
- Make one visible dependency call with arguments 65,536, 7, and 65,536.
- Return that call’s result when the next count check ends the scan.

Neither bounds array is read.

### Lower-distance selection

For one bounded entry with requirement 8, entry value 5, lower bound 2, and upper bound 12:

- Both strict-bound checks pass.
- Since 5 is less than 8, the selected distance is 3.
- First call the dependency with 3 and 65,536.
- Then call it with 65,536, the first call’s result, and 65,536.
- Return the second call’s result when the scan ends.

### Equality selects the upper distance

For requirement 5, entry value 5, lower bound 2, and upper bound 12 in bounded mode:

- Equality with the requirement is acceptable.
- The selected distance is 7, not 3.
- The same two-call sequence applies using that distance.

### Strict bounds and read ordering

For a bounded entry value of 5:

- Lower bound 5 causes immediate rejection without reading the upper bound.
- Lower bound 2 followed by upper bound 5 causes rejection after reading both bounds.
- Neither case makes a dependency call for that entry.

### Zero dependency result

If a running-result update returns zero and further entries remain:

- The function continues scanning.
- A later active entry can produce another dependency call whose first argument is zero.
- No guarantee that the final result remains zero follows from the available dependency evidence.
