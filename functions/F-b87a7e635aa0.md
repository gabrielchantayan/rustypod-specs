# F-b87a7e635aa0

## Purpose

F-b87a7e635aa0 conditionally returns a four-byte payload from an address calculated using a stored integer base and an unsigned index.

It first calls F-32a0cd51a77a to obtain an unsigned 32-bit comparison value. If that value is less than or equal to the index, it calls F-a817d8d58c10, which is annotated as non-returning. Otherwise, it reads the integer base through the first argument, calculates an unsigned 32-bit integer address value, converts that value to a pointer, and reads the payload.

The apparent intent is a bounds-checked lookup into storage with 12-byte spacing and a four-byte field displacement. That interpretation is inferred, not an established data-model guarantee. The supplied material does not establish that the comparison value is an element count, that the base identifies an array, or that the payload has a particular semantic type.

The complete integer address calculation is modulo \(2^{32}\). Multiplication and both additions wrap at 32 bits before pointer conversion. Unknown pointer-conversion behavior does not make the preceding integer calculation wider.

### Output

On normal completion, the function returns the four-byte payload read from the calculated address. The supplied return type establishes a four-byte result but does not identify it as a signed integer, unsigned integer, pointer, floating-point value, or structured field.

The contract therefore treats the result as a 32-bit payload without assigning a higher-level interpretation. No separate success flag or error value is established. A payload containing four zero bytes remains a successful data result when the read completes normally.

No particular result-register convention, byte order, or interpretation by callers is established.

### Descriptor read and integer address calculation

On the accepted path, the function first reads the signed 32-bit integer base through the descriptor address.

For address formation, that integer is converted to unsigned 32-bit form. A negative stored base is therefore represented by its value modulo \(2^{32}\), rather than being carried forward as a negative or sign-extended address contribution.

Let:

- \(i\) denote the unsigned 32-bit index;
- \(b\) denote the loaded base after conversion to unsigned 32-bit form;
- \(a\) denote the final unsigned integer address value.

The established calculation is:

\[
a =
\left(
\left(
b + ((12i) \bmod 2^{32})
\right) \bmod 2^{32}
+ 4
\right) \bmod 2^{32}.
\]

Thus:

1. Index scaling by 12 is unsigned 32-bit multiplication.
2. Adding the converted base is unsigned 32-bit addition.
3. Adding the displacement of 4 is also unsigned 32-bit addition.
4. Only the resulting 32-bit integer value is converted to a pointer.

All three arithmetic operations wrap modulo \(2^{32}\). No overflow check is present.

The formula describes arithmetic grouping, not an additional memory-access sequence. The observable local memory reads remain the descriptor-base read followed by the payload read.

A wider pointer representation would not widen these preceding integer operations. Whether and how the final integer value maps to a usable pointer is a separate target-dependent question.

### Arithmetic boundaries

A successful comparison does not prevent multiplication wraparound, either addition from wrapping, or multiple indices from producing the same integer address value.

For example, index `0x40000000` multiplied by 12 produces zero modulo \(2^{32}\). If that index passes the comparison, its address calculation has the same integer result as index zero for the same loaded base.

Addition wraparound is equally established. A base bit pattern of `0xfffffff8` and index 1 produce:

- Scaled index: `0x0000000c`.
- Base plus scaled index: `0x00000004`.
- Final integer address value after adding four: `0x00000008`.

The pre-conversion result is `0x00000008`, not the wider mathematical sum `0x100000008`.

Similarly, a converted base of `0xfffffffc` with index zero produces final integer address value zero. Whether converting zero produces a null pointer, and what happens on the ensuing read, are not established by the supplied material.
