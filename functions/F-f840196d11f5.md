# F-f840196d11f5

## Purpose

F-f840196d11f5 traverses a linked, tree-shaped structure using an opaque comparison operation. It then either publishes a selected position or calls a position-producing dependency and publishes the word present in that dependency’s result destination afterward.

The output contains a 32-bit position word and a one-byte disposition:

- **0:** the routine selected the working position without calling F-222f1190a568.
- **1:** the routine called F-222f1190a568 and published the resulting contents of its destination word.

Disposition 1 does not establish insertion success, a valid position, or even that the dependency wrote its destination. No such check follows the call.

The structure resembles an ordered container with mode-dependent duplicate handling. That is inferred intent, not an established semantic guarantee.

## Interface

The routine accepts three arguments. No returned data value is established; its result is delivered through output storage.

| Argument | Established role |
|---|---|
| Output address | Writable storage receiving a four-byte position word followed by a one-byte disposition. |
| Container address | Address of an object supplying a header pointer, mode byte, and comparison-state address. |
| Supplied value | Opaque 32-bit value passed to comparison and position-producing dependencies. |

The representation uses 32-bit pointers and four-byte words. Offsets below are byte displacements.

### Output layout

| Offset | Width | Meaning |
|---|---:|---|
| +0 | 4 bytes | Selected position or post-call result-destination contents. |
| +4 | 1 byte | Disposition, exactly 0 or 1 on normal completion. |

The four-byte write precedes the one-byte write. There is no direct initialization or clearing of bytes beyond +4 and no established larger output layout.

### Container and linked-structure fields

| Structure | Offset | Width | Use |
|---|---|---:|---|
| Container | +0x10 | 4 bytes | Header pointer, read at multiple points. |
| Container | +0x18 | 1 byte | Zero versus nonzero mode selector. |
| Container | +0x19 | Address only | Embedded comparison-state address supplied to F-bcefa5957e76. |
| Header | +4 | 4 bytes | Initial traversal position. |
| Header | +8 | 4 bytes | Boundary-path word. |

The header retained as the initial candidate can also participate in later positional operations. An empty traversal does not eliminate the need for valid header fields on paths that use them.

### Preconditions and ownership

Every address actually dereferenced must support the indicated access width. Selected chains must terminate for normal completion.

There are no protective null checks for the output address, container, header, or parent pointers used during movement. A null traversal position is explicitly recognized; this does not imply general null tolerance.

The routine establishes no ownership transfer, lifetime extension, allocation policy, or release obligation for supplied values or positions. Dependencies must accept the arguments and storage exposed on the selected path.

No general aliasing, concurrency, reentrancy, or dependency-purity guarantee is established.

## Behavior

### Initial reads and candidate selection

The routine initially remembers a nonzero comparison outcome.

It reads the container’s header pointer and then that header’s +4 pointer to obtain the traversal start. It separately reads the container’s header pointer again and retains this second result as the initial candidate.

These are distinct header-pointer reads. Their equality is not checked. With an empty traversal, the second header value remains the candidate and the remembered comparison outcome remains nonzero.

### Traversal and result-storage initialization

Two separate four-byte local words later serve as destinations for F-222f1190a568:

- The **early-result word**, used when the boundary helper returns nonzero.
- The **ordinary-result word**, used by the ordinary production path.

At the beginning of **every nonempty traversal iteration**, the routine writes zero to the early-result word and then zero to the ordinary-result word. Both writes precede that iteration’s call to F-bcefa5957e76.

These clears do not occur when the traversal is empty. They are not unconditional initialization at function entry, nor are they repeated immediately before every position-producing call.

For each non-null traversal position, F-bcefa5957e76 receives, in order:

1. The container’s comparison-state address at +0x19.
2. The supplied 32-bit value.
3. The current position’s address plus 0x10.

After the call, the current position becomes the candidate. The returned integer determines which child field is read:

- Zero selects +0x0c.
- Any nonzero value selects +8.

The selected child pointer is read after the dependency returns. A negative comparison result and a positive nonzero result take the same branch.

Traversal stops when the selected pointer is null. The candidate is the last visited position, or the initially retained header when no position was visited. The remembered outcome is the last comparison result, or the initial nonzero value for an empty traversal.

There is no cycle detection or traversal limit.

### Mode selection

After traversal, the routine reads the container byte at +0x18.

Any nonzero byte selects ordinary position production immediately. This bypasses the boundary helper, predecessor-like movement, extraction dependency, and final comparison.

Zero enables the additional processing below. Because this read follows traversal dependency calls, it is not an entry-time snapshot of the mode.

### Boundary processing and reuse of ordinary-result storage

In zero mode, the working-position word is initialized from the retained candidate.

If the remembered comparison outcome is zero, the routine skips boundary processing and movement.

Otherwise, it:

1. Rereads the container’s header pointer.
2. Reads the four-byte word at that header’s +8.
3. Stores that word into the **ordinary-result word**, replacing its previous contents.
4. Calls F-626327d2116a with the address of the working-position word and the address of the ordinary-result word.

Thus, the boundary dependency receives mutable local storage. Its second argument is the same word subsequently used as the ordinary position-producing destination. Neither preservation of these words nor equality-test semantics is established.

If F-626327d2116a returns nonzero, the routine calls F-222f1190a568 with:

- The address of the early-result word.
- The container address.
- A literal zero.
- The original traversal candidate.
- The supplied value.

It then publishes the early-result word’s post-call contents and disposition 1. There is no extraction or final comparison on this path.

If the boundary helper returns zero, movement begins from the working-position word as it exists after that call.

### Predecessor-like movement and distinct reads

The marker test has precedence over subtree descent.

First, the routine reads the working position’s one-byte marker. If that byte is zero, it reads the working position’s +4 pointer and then the pointed-to structure’s +4 pointer. If that second pointer equals the working position, the routine replaces the working position with its +0x0c pointer. This is the **special marker transition**; it bypasses both the +8 descent decision and parent ascent.

If the marker is nonzero, or the zero-marker pointer comparison fails, movement proceeds as follows.

**Descent-versus-ascent selection uses two separate +8 reads:**

- The first read obtains a potential descent position.
- The second read decides whether to descend or ascend.

If the second read is nonzero, descent begins using the pointer obtained by the first read. If it is zero, the first result is discarded and parent ascent begins. The two reads are not checked for agreement.

**During descent**, each iteration makes the potential descent position the working position, then reads that position’s +0x0c field twice:

- The first read obtains the potential next position.
- The second read determines whether another iteration occurs.

A zero second read ends descent with the current working position. A nonzero second read continues using the pointer obtained by the first read.

For stable fields, this selects the last position reached by entering the +8 child and repeatedly following +0x0c links. With changing fields, that simplified description is insufficient: the continuation decision can disagree with the retained next pointer, potentially leading to an invalid dereference. There is no consistency check or retry.

**During parent ascent**, the routine reads the working position’s +4 pointer as a prospective parent. It compares that parent’s +8 field with the previous working position, then replaces the working position with the prospective parent regardless of the comparison result.

If equal, ascent continues by reading the new working position’s +4 pointer. If unequal, ascent stops. No null-parent guard or cycle check protects this process.

Movement changes the working-position word, not the separately retained traversal candidate.

### Extraction and final comparison

After any required movement, the routine clears another four-byte local word before calling F-e963ec30d8b9. No explicit argument exposes that additional word, and no later direct read of it is established.

F-e963ec30d8b9 receives the current working position and returns an opaque 32-bit operand.

F-bcefa5957e76 is then called with:

1. The container’s comparison-state address at +0x19.
2. The extracted operand.
3. The supplied value.

This differs from traversal: the supplied value is now the third argument rather than the second, and the second argument comes from extraction rather than a node-address calculation.

If the comparison returns zero, the routine rereads the working-position word, publishes it, and writes disposition 0. It does not call F-222f1190a568.

If the comparison returns nonzero, ordinary position production follows.

### Ordinary position production

F-222f1190a568 receives:

1. The address of the ordinary-result word.
2. The container address.
3. A literal zero.
4. The original traversal candidate.
5. The supplied value.

The routine publishes whatever four-byte word is present in the ordinary-result destination after the call, then writes disposition 1.

It does not verify that the dependency wrote that destination. In particular, the destination is not uniformly fresh or uninitialized:

| Selected path | Established prior direct contents |
|---|---|
| Nonempty traversal, boundary processing skipped | Zero from the last traversal iteration. |
| Boundary processing performed | Current header’s +8 word, subsequently exposed to F-626327d2116a for possible mutation. |
| Empty traversal with nonzero mode | No direct initialization of the ordinary-result word. |

For the early-result destination, a nonempty traversal establishes a preceding clear; an empty traversal does not. Dependencies may further affect accessible storage, so preceding direct contents are not unconditional preservation guarantees.

Neither production path validates a position, rejects zero, or reports a separate error status.

## Side effects

The only direct writes to caller-supplied objects identified in the routine are the output position and disposition. No container or linked-position field is directly updated.

Local writes include traversal clears, candidate-to-working-position initialization, the boundary overwrite of the ordinary-result word, movement updates, the additional pre-extraction clear, and disposition bookkeeping.

On the early-production path, the early-result word is copied to output before its low byte is reused to hold disposition 1. Consequently, that bookkeeping does not itself replace the position word already published. All normal completion paths write the output position before the disposition byte.

Output storage is not preinitialized. Abnormal termination before publication provides no completed result; interruption between output writes can leave a partially updated result. There is no rollback or atomic-publication guarantee.

Dependencies may mutate accessible state, allocate, release memory, retain addresses, or fail to return normally; their contracts are unavailable. The routine provides no ownership or lifetime guarantee based merely on passing an address.

All position words, supplied values, extracted values, and relevant integer results use the represented 32-bit width. Marker, mode, and disposition accesses are one byte. Integer results are tested only for zero versus nonzero.

Address calculations use fixed byte offsets. No visible count arithmetic, size multiplication, address-wrap validation, or overflow recovery is present.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless stated otherwise, assume valid stable structure fields, normal dependency completion, and preservation of relevant storage except for specified writes.

1. **Empty traversal, nonzero mode.**  
   No traversal comparison or result-word clear occurs. F-222f1190a568 receives the retained header as candidate and the ordinary-result destination. If it writes a known position, that position is published with disposition 1. Without a destination write, no initialized position value is established.

2. **Traversal direction and initialization.**  
   Each visited position causes both result words to be cleared before comparison. A zero comparison selects +0x0c; any nonzero comparison selects +8.

3. **All nonzero modes bypass extra processing.**  
   Mode 0x80 follows the same mode branch as mode 1. No boundary, extraction, or final-comparison call occurs.

4. **Boundary-selected early production.**  
   With zero mode, a nonzero remembered outcome, and a nonzero boundary-helper return, production uses the early-result destination and original candidate. Neither extraction nor final comparison occurs.

5. **Boundary word survives into ordinary production.**  
   Suppose the boundary path stores value A into the ordinary-result word, F-626327d2116a changes it to B and returns zero, and the final comparison is nonzero. If F-222f1190a568 leaves its destination unchanged, B is published with disposition 1.

6. **Reuse without movement.**  
   With zero mode and a zero remembered traversal outcome, boundary processing is skipped. If the final comparison is zero, the working position is published with disposition 0.

7. **Subtree descent requires marker-transition exclusion.**  
   Suppose the special marker transition does not apply and both +8 reads yield the same non-null child. With stable +0x0c fields, movement selects the last position along that child’s +0x0c chain. A zero final comparison publishes that position with disposition 0.

8. **Production retains the original candidate.**  
   Under example 7’s conditions, a nonzero final comparison calls F-222f1190a568 with the original traversal candidate, not the descended working position.

9. **Marker transition overrides a non-null child.**  
   If the marker is zero and the parent-like structure’s +4 pointer equals the working position, movement selects the working position’s +0x0c pointer even when its +8 child is non-null. The +8 descent-selection reads are bypassed.

10. **Zero position and output footprint.**  
    If the production destination contains zero after the call, output receives zero and disposition 1. Normal completion directly writes four bytes at output +0 and one byte at +4, without clearing bytes +5 onward.

## Uncertainties

The following remain **documented_only**:

- The semantic types of supplied, extracted, header, and position values.
- The comparison relation and whether modes implement duplicate policies.
- Whether header fields conventionally represent root or minimum positions.
- Whether the marker identifies a sentinel.
- Dependency mutation, ownership, allocation, release, address-retention, and failure behavior.
- Required extents of local regions exposed through dependency arguments; initializing one word does not establish initialization of a larger region.
- Whether either production call writes its destination on every normal return.
- Safe behavior under aliasing, concurrent mutation, or reentrancy.
- The intended meaning of a zero published position.

These unknowns do not erase established local initialization, boundary-storage reuse, or repeated field reads. Invalid or unstable structures can produce invalid accesses or nontermination instead of a reported error.
