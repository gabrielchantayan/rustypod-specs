## Behavior

### Eligibility evaluation

The function first reads the 32-bit field at input offset 16 and invokes F-2eb743f270d1 with that value.

If the dependency returns 22, eligibility succeeds immediately. No second invocation occurs, and the argument field is not read again by this function.

If the first result is anything other than 22, the function reads the same object field again and makes a second invocation of F-2eb743f270d1. This second invocation uses the newly read value, not a retained copy of the first argument.

If the second result is 24, eligibility succeeds. If it is anything else, the function returns zero.

The comparisons use exact integer values: 22 (`0x00000016`) for the first result and 24 (`0x00000018`) for the second. They are not masks, ranges, or nonzero tests. Other results, including negative values where representable by the dependency’s interface, do not match those constants.

A first result of 24 does not itself permit retrieval. It causes a second invocation, and that second invocation must return 24. Conversely, a second result of 22 does not permit retrieval.

### Successful retrieval

Both retrieval reads occur after the dependency invocation that establishes eligibility. The function does not capture the address-bearing field before invoking the dependency.

Consequently, if the dependency changes that field or the indirectly reached value, successful retrieval uses the contents encountered after those changes. No preservation guarantee for dependency-visible memory is established.
