## Behavior

### Input-dependent evaluation

1. With the first input. A 32-bit result is retained for the next call.
2. With the second input and the retained 32-bit result. A 32-bit result is retained for validation and possible storage.
3. With the third input. A 64-bit result is retained and divided numerically into upper and lower 32-bit halves.

This is the call and result-use pattern represented in the supplied evidence. It does **not** resolve the actual signature of F-66388a70e189: the varying apparent argument counts and return widths are an explicit uncertainty.

All three calls occur before the local failure decision. There is no local early exit after either of the first two evaluations.

### Failure decision

The following three 32-bit quantities are checked independently:

- The upper half of the third call’s 64-bit result.
- The second call’s retained result.
- The lower half of the third call’s 64-bit result.

Failure occurs if any checked quantity has bit pattern 0xFFFFFFFF, interpreted as signed −1.

The first call’s retained result is not independently checked for this sentinel. Its established use is as an argument to the second call.

On failure:

- The 32-bit word at state offset 0 is read.
- If that word is zero, it is replaced with 0x00000500.
- If that word is nonzero, it is left unchanged.
- None of the three target bytes is directly written by this function.

Thus an existing nonzero condition value takes precedence over the new value 0x500. Any effects already performed by the dependency calls are not undone.

### Successful update

If none of the three checked quantities equals 0xFFFFFFFF, the function performs these byte writes, in order:

| Target byte offset | Stored value |
|---|---|
| 0x9E8 | Low eight bits of the upper 32-bit half of the third result |
| 0x9E9 | Low eight bits of the second result |
| 0x9EA | Low eight bits of the lower 32-bit half of the third result |

There is no local range check, clamping, or normalization. Bits above the low eight bits are discarded for storage.

The sentinel check occurs before truncation. Consequently, a checked quantity of 0x000000FF is accepted and stores byte 0xFF, whereas 0xFFFFFFFF causes failure.

On success, this function does not directly read, clear, or update the condition word at offset 0. A previously nonzero condition word does not locally prevent the byte update.
