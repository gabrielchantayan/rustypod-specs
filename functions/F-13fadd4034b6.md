# F-13fadd4034b6

## Purpose

The supplied static representation describes a routine that interleaves indirect calls with address calculations, five 32-bit stores, one 32-bit load, and two byte-copy transformations. Its application-level purpose is not established.

The observable contract is principally an ordered interaction contract:

- Forward the explicit input to an entry-context-dependent call target.
- Obtain several values from subsequent indirect calls.
- Use those values to construct addresses and write 32-bit quantities.
- Read a 32-bit quantity and later store its logical right shift by 12.
- Read a byte-sized address selector twice, with intervening calls, and perform a byte store after each read.
- Finish the visible call sequence at an invalid-instruction boundary rather than an established normal return.

The representation explicitly warns of invalid instruction data and truncated control flow. Consequently, this document specifies the visible static behavior conditionally: execution must reach the described operations, indirect calls must return where required, and the represented memory operations must be valid. It does not establish that the routine is a valid, independently callable implementation.

### Memory layout and aliasing

The direct accesses are absolute computed addresses in the representation. There is no established object base, allocation header, array length, or enclosing structure.

The recurring offset `0x14` is 20 bytes. Its repetition does not establish that the addresses refer to the same structure type. In particular:

- A destination formed as `16 × B + 0x14` is not generally the same address as `4 × B + 0x14`.
- The word written immediately before W is loaded therefore does not generally determine W.
- Repeated formulas may alias earlier writes, dependency-managed state, or other memory.
- No disjointness guarantee is visible.

Under the 32-bit bit-pattern interpretation, the two B-based addresses coincide when `12 × B` is zero modulo 2³². This includes B equal to zero and the other multiples of 2³⁰.

Each byte destination lies between `0x11` and `0x110`, inclusive, because its selector is an unsigned byte. These low addresses are a material uncertainty, not evidence that the routine has an implicit buffer base. An implementation must not invent such a base to make the accesses appear conventional.

### Bit transformations

Under the 32-bit bit-pattern interpretation:

- The first argument to F-D21 depends only on the low four bits of C and ranges from zero through `0xF0000` in increments of `0x10000`.
- The third argument to F-D21 depends only on the low two bits of C.
- The byte-selector source address depends only on the low four bits of C, followed by an offset of one.
- The first byte-store payload contains bits 0–5 of U shifted into byte positions 2–7. Its low two bits are zero.
- The second byte-store payload contains bits 20–27 of U. The mask and shift initially produce up to ten bits, but the byte store retains only eight.

These reductions do not add validation or imply a higher-level encoding format.

### Repeated selector observation

The selector source is read twice. The first observation is not reused for the second store.

Calls F-D31 through F-D37 occur between those reads and may change the source byte. Therefore:

- The two byte stores may target different addresses.
- If their selectors match, the later store overwrites the earlier byte, subject to any intervening effects.
- F-D43 receives Selector 2, not Selector 1.
- Calls after the second read may change the source again, but the argument to F-D43 remains the captured Selector 2.

## Acceptance examples

These are conditional acceptance examples, not executed tests. They assume the visible sequence is reachable, the necessary calls return, memory is accessible, and arithmetic follows the 32-bit bit-pattern interpretation.

### Explicit input forwarding

Given Input equal to `0x89ABCDEF`, F-D01 receives that same 32-bit bit pattern. No signedness conversion, masking, or address dereference of Input is visible before that call.

### Distinct B-based locations

Given B equal to 1:

- The direct word store writes 4 at address `0x24`.
- The subsequent word load reads address `0x18`.

If the word observed at `0x18` is `0xABCDEF01`, W has that value. Given C equal to 2, the later shifted-word store writes `0x000ABCDE` at address `0x1C`.

A contract that substitutes the preceding stored value for W would be incorrect.

### Aliasing B-based locations

Given B equal to zero, both B-based accesses use address `0x14`. The direct store writes zero before the direct load.

For ordinary readable and writable memory, with no external modification or special access behavior between those operations, W is therefore zero. This conclusion must not be generalized to every B.

### F-D21 argument formation

Given C equal to 3 and D equal to 5, F-D21 receives:

1. `0x00030000`.
2. `0x00000014`.
3. `0xC0000000`.

This example is conditional on 32-bit left-shift interpretation; it is not a claim about portable signed-language arithmetic.

### Different byte destinations

Given U equal to `0x0AB00013`:

- The first byte payload is `0x4C`.
- The second byte payload is `0xAB`.

If Selector 1 is `0x20` and Selector 2 is `0x30`, the first payload is stored at `0x31`, and the second at `0x41`. F-D43 receives `0x30` as its second argument, regardless of the first selector.

### Repeated destination and overwrite

Given the same U and both selectors equal to `0x20`, the visible direct stores write `0x4C` and later `0xAB` to address `0x31`.

Immediately after the second direct store, ordinary memory there contains `0xAB`. No claim is made about its value after subsequent dependencies execute.

### Interrupted sequence

If F-D15 does not return, the shifted-word store based on C and all later visible operations are not reached. Earlier calls and stores are not undone by any visible mechanism.
