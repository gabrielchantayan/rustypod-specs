# F-d8b79fc4b172

## Purpose

F-d8b79fc4b172 reads a sequence of bytes through a caller-supplied cursor, constructs an unsigned 32-bit value in byte-arrival order, and writes the advanced cursor back to the supplied cursor slot.

For one through four consumed bytes, the first byte becomes the most significant byte of the consumed sequence’s numeric value. When more than four bytes are consumed, only the final four contribute to the returned value. Earlier bytes are still read, and the cursor advances past every consumed byte.

The count has a significant width-dependent boundary rule: exactly zero consumes nothing, whereas a nonzero count with a zero low byte consumes 256 bytes. Other nonzero counts consume the number of bytes specified by their low byte.

These are established consequences of the supplied static representation. Interpreting the operation as a parsing utility is inferred intent, not an additional interface requirement.

## Behavior

### Cursor acquisition and publication

The function obtains the initial cursor from the supplied slot once, before consuming input bytes. Byte accesses use that acquired cursor; the function does not reread the slot between bytes.

For a positive effective count, it consumes bytes in increasing address order, advancing the acquired cursor by one byte after incorporating each byte into the result.

The function does not publish intermediate cursor positions. After all required byte reads, it writes the final cursor into the supplied slot. On normal completion, that cursor identifies the position immediately after the consumed sequence.

For count zero, the function skips byte consumption and writes the originally acquired cursor back unchanged. The final slot write is still represented even though its value is unchanged.

### Result construction

The accumulator begins at zero. Each consumed byte is interpreted as an unsigned value from 0 through 255.

For each byte, the previous accumulated value is shifted left by eight bits within the 32-bit result width, and the new byte is incorporated into the low eight bits. Bits shifted beyond the result width are discarded.

The resulting layouts are:

- **One byte:** The byte occupies bits 0–7; bits 8–31 are zero.
- **Two bytes:** The first byte occupies bits 8–15 and the second occupies bits 0–7; bits 16–31 are zero.
- **Three bytes:** The bytes occupy bits 16–23, 8–15, and 0–7, respectively; bits 24–31 are zero.
- **Four bytes:** The bytes occupy bits 24–31, 16–23, 8–15, and 0–7, respectively.
- **More than four bytes:** Each additional byte removes the oldest retained byte from the result and places the new byte at the least significant end.

Equivalently, the result is the big-endian numeric interpretation of the last, at most four, consumed bytes. Fewer than four bytes are zero-extended to 32 bits. With no consumed bytes, the result is zero.

This describes numeric significance, not the result’s in-memory byte order. Because the input is read one byte at a time, the value construction does not require a particular host byte order for multibyte integers. Cursor-slot representation remains environment-dependent.

### Count progression and arithmetic width

The first consumption decision examines the complete 32-bit count. After each consumed byte, the count is decremented and restricted to its low eight bits before the next decision.

That ordering matters. Narrowing the count to eight bits before the first decision would incorrectly make nonzero multiples of 256 consume nothing.

For a nonzero count whose low byte is zero, the first byte is consumed before the updated count becomes 255. Another 255 bytes are then consumed, producing a total of 256.

For a nonzero count whose low byte is between 1 and 255, consumption ends after exactly that many bytes. High count bits do not cause additional cycles.

Consequently:

- Count 0 consumes 0 bytes.
- Count 255 consumes 255 bytes.
- Count 256 consumes 256 bytes.
- Count 257 consumes 1 byte.
- Count 512 consumes 256 bytes.
- Count 4,294,967,295 consumes 255 bytes.

All accumulator operations remain within the represented unsigned 32-bit width. Byte values are not sign-extended.
