# F-e16ed3a93815

## Purpose

F-e16ed3a93815 performs a stateful operation on source and destination records. Its behavior depends on two explicit arguments, inherited addresses and values, entry condition flags, and external data.

Two routes are represented:

- **Computed dispatch:** perform initial destination writes, transfer control to a computed code-entry address, and return the selected entry’s result.
- **Configuration:** perform the same initial writes, validate selected source fields, initialize destination state, conditionally incorporate auxiliary quantities, update a shared counter, and invoke a final dependency.

“Configuration” is an inferred purpose, not an established subsystem meaning. The observable contract consists of the accesses, ordering, conditions, calls, and results described below.

The operation is not transactional. Rejection can follow destination writes; no rollback is represented.

## Behavior

### Initial writes and route selection

Every represented route begins with three 32-bit copies, in this order:

| Source offset | Destination offset |
|---|---|
| `0x18` | `0x64` |
| `0x14` | `0x54` |
| `0x28` | `0x74` |

Each source read supplies its corresponding destination write before the next copy. Destination `0x88` then receives the full baseline value, followed by destination `0x84` receiving that value. Destination byte `0x8d` then receives the alternate value’s low byte.

These writes precede dispatch and every visible rejection. There is no whole-record snapshot. Overlap can therefore let an earlier destination write affect a later source read. Disjoint storage is required for an interpretation based on an unchanged source record, but overlap is not explicitly rejected.

Carry clear **or** zero set selects computed dispatch. Configuration is represented only for carry set and zero clear.

### Computed code-entry selection

The dispatch route computes a code-entry address from the fixed base `0x0800665c` plus four times the signed second argument.

The represented operation invokes code **at that computed address**. It does not show reading a function pointer from memory at that address. The four-byte stride therefore describes code-entry spacing, not established pointer-table element spacing.

The selected entry’s represented result is returned. No configuration-route work is performed by the visible body after selecting this route.

The evidence does not establish valid indices, entry identities, entry boundaries, argument conventions, or behavior for negative or out-of-range indices. It also does not establish that the represented call-and-return structure faithfully describes the underlying indirect control transfer. ### Range acceptance

On the configuration route, the function first reads source `0x08` as an unsigned 32-bit value. It then writes the baseline low byte to destination `0x40`.

A first range read at most eight allows processing to continue without changing destination `0x3c` at this stage.

A first range read greater than eight causes another read of source `0x08`. A second value greater than sixteen rejects with `0xffffffff`. Otherwise destination `0x3c` receives the full alternate value.

For stable storage:

- Zero through eight leave `0x3c` unchanged at this stage.
- Nine through sixteen replace `0x3c` with the alternate value.
- Seventeen through `0xffffffff` reject.

The second comparison uses a fresh read. If the field changes, the stable-storage categories do not apply. In particular, a first value greater than eight followed by a second value at most eight still causes the alternate-value write.

### Mode acceptance

The first source `0x0c` read determines whether mode one applies.

If that read equals one, destination byte `0x41` receives the alternate low byte.

Otherwise, destination `0x41` first receives the baseline low byte. A fresh source `0x0c` read must equal two; any other value rejects with `0xffffffff`. Acceptance through this branch increments destination `0x3c` using a 32-bit signed operation.

There is no unconditional initialization of `0x3c`. With stable range at most eight and stable mode two, the increment uses its existing destination value. With stable range nine through sixteen, it increments the alternate value written during range handling. Arithmetic boundary qualifications appear under **Uncertainties**.

After mode acceptance, another source `0x0c` read is copied to destination `0x14`. That copied value need not match an earlier mode read if the source changes.

The retained `0x78` value is read **after** F-6d8c85350b66 returns. It need not equal the earlier kind-selected value if the dependency or another actor changes it.
