# F-793a94891814

## Purpose

The established behavior is initialization-shaped, but the supplied evidence does not establish a constructor, an object type, an allocation operation, or an ownership transfer. In particular, it does not establish that the returned address equals the original storage address.

This contract distinguishes direct effects of this function from effects of its dependencies. A field written before a dependency call is not guaranteed to retain that value afterward.

## Behavior

### Initial storage updates

The following is the observable sequence expressed by the supplied static representation. It is not a claim about instruction scheduling, atomicity, or behavior under concurrent unsynchronized access.

1. **Write a shared four-byte value at input offset `0x00`.**  
   A four-byte value is read from one shared storage location and written to the beginning of the input storage. This contract calls that source **shared word A**. Its value and semantic role are not supplied.

2. **Read and replace the byte at input offset `0x04`.**  
   The existing byte is combined with the sixth input:
   - Output bit 0 equals bit 0 of the sixth input.
   - Output bit 1 is always zero.
   - Each output bit from 2 through 7 is the logical OR of the corresponding existing bit and input bit.

   Consequently, the sixth input can set bits 2 through 7 but cannot clear an already-set bit in that range. Bit 0 is replaced rather than merely set. Bit 1 is cleared regardless of either input.

   This operation uses only the byte at offset `0x04`. No direct access to offsets `0x05` through `0x07` is shown.

3. **Write the fifth input at input offset `0x08`.**  
   Exactly four bytes are assigned.

4. **Write the second input at input offset `0xB4`.**  
   Exactly one byte is assigned.

5. **Write the third input at input offset `0xB8`.**  
   Exactly four bytes are assigned.

6. **Write the fourth input at input offset `0xBC`.**  
   Exactly one byte is assigned.

These writes occur before either dependency is called. They are not delayed until dependency success, and no rollback is shown.

### First dependency call

F-a891c2749310 is called with the address at byte offset `0xC0` from the input storage base.

Its returned integer becomes the reference for every remaining direct memory access and for the final return calculation. The function does not visibly compare that result with the passed interior address, the input base, zero, or any validity indicator.

The dependency’s result must not be assumed to equal the address it received. The dependency must also not be assumed to preserve previously written storage or shared values.

### Updates relative to the dependency result

After F-a891c2749310 returns:

1. Four-byte zero is written at offset `+0xB8` from its result.
2. Four-byte zero is written at offset `+0xBC` from its result.
3. F-UNRESOLVED-01 is called with:
   - First argument: the address at offset `−0xB4` from that result.
   - Second argument: numeric value `0xA8`, or 168 decimal.
4. After F-UNRESOLVED-01 returns, shared word B is read and written as four bytes at offset `−0xB4` from the first dependency’s result.
5. One byte with value `8` is written at offset `−0xB0`.
6. Shared word C is read and written as four bytes at offset `−0xAC`.

Shared words A, B, and C identify three distinct source locations in the supplied evidence. Their contents need not be distinct, constant, or immutable.

The return value of F-UNRESOLVED-01, if any, is not used. Its arguments do not establish its behavior. In particular, the value 168 is not proof of a byte count, clearing range, or allocation size.

### Final result calculation

After the last four-byte write, the function returns the first dependency’s result minus `0xC0`.

The returned address-like value is therefore:

- `0x0C` bytes before the address passed to F-UNRESOLVED-01;
- `0xC0` bytes before the first dependency’s result.

Those relationships assume the address arithmetic is valid and does not wrap.

Equality with the original input base is conditional: it holds if F-a891c2749310 returns exactly the interior address it was passed and the subtraction behaves as ordinary address arithmetic.

Thus:

- F-a891c2749310 is entered after the initial field updates.
- F-UNRESOLVED-01 is entered after both zero writes.
- The zero-valued fields are not necessarily zero at function return, because F-UNRESOLVED-01 executes afterward.
- Shared words B and C are read after both dependency calls. Their values must not be treated as snapshots taken at entry.
- The final shared-word-C read occurs after the shared-word-B write and the byte write of 8. Aliasing could make that order significant.

The evidence does not establish disjointness among input storage, dependency-result-relative storage, and shared storage. If regions overlap, the stated operation order governs their interaction.
