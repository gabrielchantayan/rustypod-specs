# F-978558fbe47c

## Purpose

F-978558fbe47c conditionally transfers selected fields between a caller-provided object and an external context. A mode argument selects one of two behaviors:

- **Nonzero mode:** emit a fixed sequence of field operations to the context.
- **Zero mode:** consume tagged items from the context, update recognized object fields, and delegate unrecognized items.

A byte in the object gates both behaviors. If that byte is zero, the function returns zero without accessing the context through any dependency.

These descriptions of emission and consumption are inferred intent. The established behavior is the dependency-call sequence, field accesses, tag handling, and status propagation specified below. The context’s external representation and the semantic meanings of the fields are not established.

## Interface

### Arguments and result

The function accepts three arguments:

| Argument | Established representation | Role |
|---|---|---|
| Object address | A 32-bit address-bearing value | Base address for the fields described below |
| Context | An opaque 32-bit value | Passed unchanged to transfer dependencies |
| Mode | A 32-bit integer | Zero selects consumption; every nonzero value selects emission |

The function returns a 32-bit integer status:

- Zero when the initial gate is disabled.
- Zero when consumption encounters the recognized terminating tag.
- Otherwise, the status returned by a checked dependency at the point the function stops.
- In emission mode, the final result is the status of the closing operation if all preceding checked operations succeeded.

For checked dependencies, **zero means continue** and **any nonzero value means return that value immediately**. No particular error-code vocabulary, sign convention, or distinction between positive and negative nonzero statuses is established.

### Preconditions

The caller must provide storage valid for every access reached on the selected path. Even the disabled path requires the byte at `+0x2C` to be readable.

Enabled operation additionally requires:

- A context acceptable to the invoked dependencies.
- Suitable object storage for dependency-mediated accesses at the listed offsets.
- Writable storage for direct updates in consumption mode.
- Any alignment and lifetime conditions required by the target platform and dependencies.

The function performs no visible null-address, object-size, context-validity, or alignment checks. No behavior is established for invalid storage, faults, or dependency contract violations.

## Behavior

### Initial gate and mode selection

The function first reads the byte at object offset `+0x2C`.

If the byte is zero, it returns zero immediately. It does not inspect a tag, issue an opening operation, or directly modify the object.

If the byte is nonzero, the function selects emission for nonzero mode and consumption for zero mode. The gate is not explicitly reread during the operation. In particular, a dependency changing the gate does not cause an explicit gate recheck.

### Emission mode

The function performs the following operations in order. Each checked operation must return zero before the next step is reached.

1. Invoke F-56ffc99ff66d with the context and identifier **5**.
2. Invoke F-7de8e89baf04 with the context, identifier **6**, and the address at object offset `+0x08`.
3. Invoke F-7de8e89baf04 with the context, identifier **7**, and the address at object offset `+0x14`.
4. Invoke F-7de8e89baf04 with the context, identifier **59**, and the address at object offset `+0x18`.
5. Invoke F-7de8e89baf04 with the context, identifier **31**, and the address at object offset `+0x04`.
6. Read the 32-bit word at object offset `+0x1C` into temporary storage. Invoke F-7de8e89baf04 with the context, identifier **8**, and the address of that temporary.
7. Read the 32-bit word at object offset `+0x24` and pass that value to F-8810f53aaa0b.
8. Invoke F-44362605ab79 with the address at object offset `+0x20`.
9. Invoke F-50a6dfa3b527 with the context, identifier **60**, the result of F-44362605ab79, and the result of F-8810f53aaa0b, in that argument order.
10. Invoke F-77aa48fed92a with the context and identifier **5**. Return its result.

The results of the two preparation calls in steps 7 and 8 are treated as opaque 32-bit values. They are not individually checked for failure.

Important ordering constraints:

- The fields are emitted in the order **6, 7, 59, 31, 8, 60**, not numerical order.
- The read at `+0x1C` occurs only after identifier 31 has completed successfully.
- The read at `+0x24` occurs only after identifier 8 has completed successfully.
- F-8810f53aaa0b completes before F-44362605ab79 is invoked.
- The closing operation occurs only if the identifier-60 operation returns zero.

The identifier-8 operation receives a copy, not the object field’s address. A dependency-mediated change to that temporary is not explicitly copied back to `+0x1C`.

The function makes no explicit object writes in emission mode. That does not establish read-only behavior: dependencies receive object addresses or other values through which they may have side effects.

There is no visible rollback or compensating close after an earlier failure.

### Consumption mode

Consumption repeatedly invokes F-4b3a084696b2 with the context and the address of a temporary 32-bit tag word.

A nonzero result is returned immediately. On zero, the tag word is interpreted as:

- **Identifier:** low 24 bits.
- **Upper tag bits:** high 8 bits.

The identifier is therefore in the range 0 through 16,777,215. The masking operations do not introduce signed comparisons or arithmetic overflow.

The following cases apply.

#### Identifier 5: conditional termination

If the high byte equals hexadecimal `C0`, the function returns zero immediately. The complete terminating word is therefore `0xC0000005`.

For identifier 5 with any other high byte, the function takes no explicit payload-consumption or skip action. It proceeds directly to obtain another tag.

Identifier 5 is thus not universally a terminator, and its nonterminating forms are not sent to the unrecognized-item dependency.

#### Identifier 6: consume and mirror

Invoke F-7d397109ac66 with the context and the address at object offset `+0x08`.

- On nonzero result, return that result immediately.
- On zero, read the 32-bit word at `+0x08` and write that word to `+0x0C`.
- Continue with the next tag.

The mirror uses the value present after the dependency returns. If the dependency reports failure after modifying `+0x08`, this function does not perform the mirror write.

#### Identifiers 7, 31, and 59: direct destination consumption

Invoke F-7d397109ac66 with the context and the destination selected below:

| Identifier | Destination |
|---:|---|
| 7 | Object offset `+0x14` |
| 31 | Object offset `+0x04` |
| 59 | Object offset `+0x18` |

Return any nonzero result immediately. Otherwise, continue with the next tag.

The supplied function does not establish how much destination storage the dependency accesses or whether a failing call leaves a partial update.

#### Identifier 8: consume into a temporary, then commit

Invoke F-7d397109ac66 with the context and the address of a temporary word.

- On nonzero result, return it without an explicit write to object offset `+0x1C`.
- On zero, copy the temporary’s 32 bits to object offset `+0x1C`.
- Continue with the next tag.

No successful-output validation is visible between the dependency’s return and the object write.

#### Identifier 60: consume into scratch storage, then apply

Invoke F-478dbb7dfe10 with:

- The context.
- The numeric argument **256**.
- The address of local byte-oriented scratch storage.

On nonzero result, return it immediately without invoking the subsequent application dependency.

On zero, invoke F-151ab4bfe553 with the address at object offset `+0x20` and the scratch-storage address. Its result is not checked. Continue with the next tag.

The meaning of 256 is not established. In particular, the supplied evidence does not prove whether it denotes capacity, a maximum payload, a format parameter, or something else.

#### All other identifiers

Invoke F-fa92e3e1239e with the context and the **complete original 32-bit tag word**, including its high byte.

Return a nonzero result immediately. Otherwise, continue with the next tag.

For recognized identifiers other than 5, the function does not validate the high byte before dispatch. Their behavior is selected solely by the low 24 bits.

### Repetition and termination

Recognized items may occur in any order and may repeat. Each occurrence is processed as encountered; there is no duplicate rejection or required-field tracking.

The function does not initialize absent fields. It also does not require an opening identifier-5 item before processing data items.

There is no explicit iteration bound. Normal successful termination requires the exact terminating tag. End-of-input behavior depends on F-4b3a084696b2 and is not independently established.

## Side effects

Direct object writes are limited to these consumption actions:

- The word copy from `+0x08` to `+0x0C` after successful identifier-6 consumption.
- The word write to `+0x1C` after successful identifier-8 consumption.

Additional object and context changes may occur through dependencies. Their global-state effects, aliasing behavior, and mutation guarantees are unknown.

Updates are incremental, not transactional. A later failure does not undo earlier direct writes or successful dependency calls. A failed direct-destination consumption call may itself have modified its destination; this function performs no restoration.

The function visibly performs no allocation, release, ownership transfer, or explicit cleanup. This does not establish that dependencies do none of those things.

Temporary addresses are supplied to dependencies. Whether any dependency retains such addresses, copies their contents, or requires a particular lifetime is unknown. The lifetime and ownership of values returned by F-8810f53aaa0b and F-44362605ab79 are likewise not established.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

1. **Disabled object:** Given a readable zero gate byte, either mode returns zero with no dependency invocation.

2. **Successful emission:** Given a nonzero gate and nonzero mode, if every checked call returns zero, the checked operations occur in the exact sequence 5-opening, 6, 7, 59, 31, 8, 60, 5-closing. The two preparation calls occur between the identifier-8 and identifier-60 operations, in the specified order.

3. **Emission failure:** If identifier 59 returns a nonzero status, that status is returned. Identifier 31 and all subsequent operations are not invoked.

4. **Exact terminating tag:** In consumption mode, a successfully obtained `0xC0000005` causes an immediate zero return, without another tag read or an unrecognized-item call.

5. **Nonterminating identifier 5:** A successfully obtained `0x00000005` causes another tag request without calling the unrecognized-item dependency for that item.

6. **Ignored high byte on recognized data:** A tag of `0xA5000006` selects identifier-6 consumption. If that call succeeds and leaves the word `0x12345678` at `+0x08`, the function writes `0x12345678` to `+0x0C`.

7. **Failed identifier 6:** If its consumption dependency returns nonzero, the function returns that status without performing the mirror write. Any mutation already made by the dependency is outside that guarantee.

8. **Identifier-8 commit boundary:** If the dependency successfully supplies `0xFFFFFFFF`, all 32 bits are copied to `+0x1C`. If it instead returns nonzero, no explicit commit to that field occurs.

9. **Unknown tag preservation:** For a tag such as `0xAB000009`, F-fa92e3e1239e receives `0xAB000009`, not merely identifier 9.

10. **Repeated fields:** Two successful identifier-8 items cause two successive writes to `+0x1C`. Subject to no intervening dependency mutation, the second value remains after termination.

11. **Identifier-60 failure boundary:** If F-478dbb7dfe10 fails, F-151ab4bfe553 is not called. If it succeeds, the application call occurs and the loop continues without a status check on that call.
