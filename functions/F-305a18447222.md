# F-305a18447222

## Behavior

### Initial carry-dependent writes

The incoming carry flag selects the following first two writes:

| Carry | First write | Second write |
|---|---|---|
| Set | 16-bit zero at `0x0000001C` | Complete 32-bit second argument at `0x00000000` |
| Clear | 16-bit `0xFFFE` at `0x0000001A` | Complete 32-bit second argument at `0xFFFFFFFC` |

Execution then proceeds in this order:

1. Assign the incoming 16-bit register value to a global location whose address and declared storage width are not supplied.
2. Write the low 16 bits of the second argument at `0x00000000` if carry is set, or at `0x00001FFF` if carry is clear.
3. Assign `0x22` to the global location at `0x00000062`.

The declaration of the last global is unavailable, so its storage width is not independently established.

The carry-clear halfword destination is odd. Alignment support is therefore a required environmental condition for that access to succeed. In the carry-set case, the halfword write overlaps the preceding word write at zero.

### Initial reads and working-address writes

The incoming 32-bit addressing register is doubled. Two 32-bit words are read in order:

1. The word at that doubled address.
2. The word four bytes later.

The working address is twice the second word, retaining 32 bits.

Next, the scalar at `0x00000E2E` is read and converted to an unsigned 32-bit value. Its original storage width and signedness are unavailable; the conversion must not be treated as proof of a 32-bit unsigned memory read.

Two writes follow:

1. Write the 32-bit value `0x71` at the working address plus eight.
2. Write the first word from the initial pair at the address obtained by multiplying the converted scalar by `0x800` and subtracting `0x71`.

These writes occur before the pointer-global reads described below. Aliasing can therefore affect the values those reads observe.

### Selection and pointer publication

Interpret the wrapped working address plus four as signed 32-bit data and shift it right arithmetically by 31 positions. The resulting mask is:

- Zero if that signed value is nonnegative.
- `0xFFFFFFFF` if it is negative.

The selection offset is obtained by shifting the second argument left once, applying that mask, and doubling the result. The halfword address is the selection offset plus two.

Consequently:

- With a zero mask, the halfword address is `0x00000002`.
- With an all-ones mask, it is four times the second argument plus two, modulo \(2^{32}\).

A 32-bit zero is written at the working address plus the mask. An all-ones mask therefore selects the working address minus one.

Pointer publication then contains **two distinct evaluations** of the global pointer at `0x0897F5B8`:

1. Read that global and retain its value as the first publication pointer.
2. Evaluate the same global again to obtain the publication destination pointer.
3. Through the publication destination pointer, store the halfword address as a 32-bit pointer value.

The second evaluation must not be replaced in this contract by the first value. The representation does not provide enough information about global declarations or memory-mapped behavior to establish that both evaluations return the same pointer.

Subsequent address calculations use the **first publication pointer**, not the publication destination pointer. Form a derived record address by adding four to the first publication pointer and multiplying by `0x100`, retaining 32 bits. At that derived address, perform these writes in order:

1. Store the derived record address itself as a 32-bit pointer at offset zero.
2. Store the halfword address as a 32-bit pointer at offset four.
3. Store one zero byte at offset zero.

The final byte store overlaps the self-pointer store. Whether it changes the numeric pointer value depends on byte order and the pointer’s bytes.

A separate pointer-valued global is then assigned an address formed from bits 16–23 of the first publication pointer plus four. The assigned numeric value is between `0x00` and `0xFF`.

That assignment is followed by a **new evaluation of the separate pointer global**. Through the pointer returned by this evaluation, write the low 16 bits of the working address.

The assigned pointer value and the subsequently read pointer value must remain distinct in the contract. Ordinary stable memory could make them equal, but the available declarations and environmental information do not establish that equality. The halfword store is addressed by the reread value, not unconditionally by the computed low address.

2. A 32-bit loaded record pointer from the original record base plus eight.

These reads observe the memory state after the call and the intervening global assignment.

2. Write the halfword address as a 32-bit pointer at the loaded record pointer.
3. Interpret the product as signed 32-bit data and shift it right by the low eight bits of the loaded halfword pointer.
4. Write the low 16 bits of the shifted result at the halfword address.
5. Read one unsigned byte at the halfword address multiplied by `0x400`, plus `0x0F`, retaining 32 bits.

## Acceptance examples

These examples are conditional consequences of static evidence, not executed tests.

1. **Carry set.** If the initial accesses succeed, the routine writes a zero halfword at `0x1C`, the second argument as a word at zero, and later its low halfword at zero. The incoming-register global assignment remains between the two writes at zero.

2. **Carry clear.** The first three explicitly sized writes target `0x1A`, `0xFFFFFFFC`, and `0x1FFF`, with widths 16, 32, and 16 bits. Substituting `0x1FFE` for the third destination does not match the calculation.

3. **Nonnegative wrapped sum.** If the signed working address plus four is nonnegative, the halfword address is two and the original record base is `0x40`. The pre-call self-pointer store targets `0x60`.

4. **Negative wrapped sum.** If that signed sum is negative and the second argument is three, the selection offset is twelve and the halfword address is fourteen. The earlier zero word store targets the working address minus one.

5. **Different publication reads.** Suppose the first pointer-global evaluation yields `0x00001000` and the second yields `0x00002000`. If execution continues, the halfword address is published at `0x00002000`, while the derived record address is `0x00100400`. Using the second pointer for the derived record, or using the first pointer as the publication destination, would not match the represented evaluations.

6. **Separate low-pointer reread.** With a first publication pointer of `0x00001000`, the computed value assigned to the separate pointer global is zero. If its subsequent evaluation yields `0x00003000`, the working-address halfword is stored at `0x00003000`, not at zero. Whether such a differing read can occur on the actual target remains unresolved.

7. **Dependency changes a field.** If F-000000000001 changes the pointer at original record base plus eight and returns, the later loaded record pointer comes from the post-call field, subject also to any aliasing from the intervening global assignment.

8. **Two distinct halfword stores.** If the loaded halfword pointer is `0x00001004` and execution reaches both stores, zero is written through it before `0x1004` is written through it. Replacing both with one final store loses the ordered effects.

9. **Overlapping record byte.** The zero-byte store follows the derived record’s self-pointer store. An intact final self-pointer is acceptable only where the target byte order and original bytes make that byte overwrite numerically harmless.
