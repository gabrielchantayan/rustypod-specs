# F-5855f81e15f0

## Purpose

The established behavior consists of:

- Calling F-744bf0af5c75 twice with the address at input offset 56.
- Storing the first call’s 32-bit result at input offset 1328.
- Passing the second call’s result and the numeric argument 20 to F-870c4fcf7295.
- Writing the transformed result, zero, and five into three consecutive 32-bit words.
- Returning a pointer captured from the global destination selection after the dependency calls.

The meaning of the embedded region, the stored field, the transformation, and the two constant result words is not established. In particular, the evidence does not establish that the two calls read identical values, that 20 denotes a byte count, or that the returned storage is newly allocated.

## Behavior

The following ordering is established for normal completion.

1. **First dependency invocation.** The function forms the address 56 bytes beyond the input base and supplies it as the sole argument to F-744bf0af5c75.

2. **Publication into the input object.** After that invocation returns, the function writes its 32-bit result to the address 1328 bytes beyond the input base. This store occurs before the second dependency invocation.

3. **Second dependency invocation.** The function again supplies the address at input offset 56 to F-744bf0af5c75. This is a distinct call. The function does not substitute the previously obtained result, and it does not visibly load the field at offset 1328 to obtain this second result.

4. **Transformation of the second result.** The function calls F-870c4fcf7295 with two arguments: the second result from F-744bf0af5c75 and the numeric value 20. The resulting value is used as a 32-bit word.

5. **Destination capture.** Only after the transformation call returns does the function obtain the globally selected output pointer for its return value and subsequent indexed stores. Consequently, dependency-induced changes to that global selection before this point can affect the destination.

6. **Result publication.** The transformed value is written through the global destination selection. Zero is then written at byte offset 4 through the captured pointer, followed by five at byte offset 8 through that pointer.

7. **Return.** The function returns the captured pointer after the three stores.

The supplied representation uses the global selection directly for the first result-word store and the captured pointer for the next two stores. If the selection remains stable during these operations, all three writes address one contiguous 12-byte region. This stability must not be silently assumed for environments permitting asynchronous changes to that global location. The evidence provides neither synchronization nor an atomic snapshot guarantee for the complete publication.
