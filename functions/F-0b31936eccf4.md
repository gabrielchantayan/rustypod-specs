# F-0b31936eccf4

## Purpose

F-0b31936eccf4 selects one 32-bit unsigned value from a fixed-size, externally supplied table and combines that value with a caller-supplied 32-bit payload into a 64-bit result.

For a table sorted in nondecreasing unsigned order, selection has the following meaning:

- Select the first table entry whose value is greater than or equal to the requested value.
- If every entry is smaller than the request, select the final entry instead.

Thus, on a suitably ordered table, the operation behaves as a lower-bound lookup with saturation at the final entry. This interpretation is conditional on table ordering; the function does not establish or check that ordering.

The supplied evidence establishes a search over exactly 40 entries. It does not establish what those entries represent, how the table is initialized, or how callers interpret the two halves of the result.

## Behavior

### Search domain and comparison rule

The initial candidate range consists of all 40 entries preceding the anchor.

The function repeatedly examines the middle entry of the remaining candidate range. For an even-sized range, this is the entry at the range-relative index equal to half its length, making it the upper of the two central positions.

Each examined table value is compared to the request using a strict unsigned less-than comparison:

- A value smaller than the request excludes that entry and all earlier entries in the current range.
- A value equal to or greater than the request retains the earlier portion of the range and excludes the examined entry from further comparisons.

The process ends when no candidates remain. Equality therefore moves the search toward earlier entries, rather than accepting an arbitrary equal entry immediately.

For a stable, nondecreasing table, the resulting position is precisely the first entry whose value is at least the request, or the anchor if no such entry exists.

### End-of-table handling

If the resulting position is the anchor, it is moved back by one entry before the result value is read. Under the stable-table precondition, this selects entry 39.

This adjustment is the sole evidenced boundary fallback. It is not an error report and does not change the payload.

The function does not construct an empty-table result. Its search length is always 40, irrespective of external allocation size or initialization state.

### Final value read

After selection and any end-of-table adjustment, the function reads the selected entry to construct the result.

This final read is logically separate from the reads used for comparisons. A selected entry may therefore be read once during the search and again when constructing the result. Under a stable-table precondition, both reads observe the same value. Without that precondition, the evidence does not establish snapshot consistency.

### Read ordering and amount

At the level of the supplied function representation, the observable access sequence is:

1. Obtain the external anchor to identify the start of the 40-entry range.
2. Read one table entry for each comparison, in search order.
3. Consult the external anchor for the end-position comparison.
4. Read the final selected entry.
5. Return the assembled 64-bit result.

The comparison phase takes either five or six iterations for a valid 40-entry range. Consequently, the representation shows five or six comparison reads followed by one final selected-value read.

The first comparison reads entry 20. Subsequent comparison addresses depend on earlier comparison outcomes. The function does not scan the table in order, and it need not read either endpoint during the comparison phase.

These statements describe the supplied representation. They do not establish the exact number of physical loads after optimization, whether accesses have volatile semantics, or a memory-ordering protocol.
