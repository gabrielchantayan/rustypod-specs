# F-5c4930be3ae6

## Purpose

F-5c4930be3ae6 conditionally transfers one 16-bit memory value, then enters an unbounded sequence of two indirect calls followed by software interrupt `0x5b`.

The supplied representation establishes no ordinary return path. It does not establish a higher-level purpose, such as initialization, decoding, dispatch, or error handling. Those interpretations must not be adopted as contractual behavior.

Although the representation contains many conditional arithmetic and memory operations, most cannot execute under its own 32-bit arithmetic and branch conditions. The contract below distinguishes reachable effects from those merely present in the representation.

No runtime tests have been performed.

| Position | Represented width | Established use |

### Width and address model

The behavior below uses the 32-bit bitvector and address model expressed by the supplied representation:

- Word-sized unsigned arithmetic wraps modulo \(2^{32}\).
- Halfword values have 16 bits.
- A two-byte pointer increment advances the address by two bytes.
- Explicit integer address additions use byte offsets.
- Conversion of a halfword value to an address zero-extends it unless a signed conversion is expressly involved.

Target byte order, alignment rules, executable-address interpretation, and the actual calling convention are not established. Ordinary mathematical integers or a native 64-bit pointer model are not interchangeable with this model.

### Result

There is no normal result. If execution continues through the indirect calls and interrupt, the function repeats indefinitely.

A callee that does not return, an interrupt that does not resume, a memory fault, or an invalid indirect target can prevent further execution. No recovery behavior for those cases is established.

## Behavior

### Initial selection

Only the bottom two bits of the second explicit input affect the initial branch.

- If either bit is set, the initial memory transfer is skipped.
- If both bits are clear, the initial memory transfer occurs.

This follows from the represented multiplication by `0x40000000`: its low 32-bit result is zero exactly when the unsigned input is divisible by four. Higher input bits do not change that decision.

### Initial memory transfer

When the second input is divisible by four, the function:

1. Reads one unsigned 16-bit value at the transfer source address.
2. Writes that captured value at the address obtained by adding the transfer displacement to the transfer source address, modulo \(2^{32}\).

The displacement is measured in bytes, not halfwords.

The source read precedes the destination write. Consequently, if the addresses are equal, the represented operation reads the value before writing it back. Overlap does not introduce a second source read in this transfer.

An adjusted address is also computed from the destination address minus the transfer adjustment. That adjusted address is used only in subsequent exceptional-path comparisons. There is no established second transfer using it.

No bounds, accessibility, alignment, or overlap checks are performed.

### Exceptional pre-loop path

A further memory-writing path is present, but its guards are exceptionally restrictive. Under the represented 32-bit model, reaching it requires all of the following:

- The second input is divisible by four.
- The entry continuation address is zero.
- The fifth-input storage address is zero.
- The comparison word equals the transfer displacement.
- The adjusted address described above equals the transfer adjustment.
- The additional arithmetic word is zero.
- Twice the transfer displacement is zero modulo \(2^{32}\).

The final condition restricts the displacement to `0x00000000` or `0x80000000`.

These conditions are necessary and sufficient for entry to this represented block, provided execution has survived the initial memory transfer and the relevant operations retain their represented meanings.

The zero storage-address requirement is not an ordinary valid-stack precondition. In conventional environments where a parameter cannot reside at address zero, this path is unreachable. The supplied material does not establish such an environment, so the path is documented rather than discarded.

On this exceptional path:

- The continuation value used for the first indirect call becomes zero.
- A halfword at address zero supplies both a destination address and a value to increment.
- The destination address is the zero-extended 16-bit value obtained from address zero.
- The value written is the halfword value plus fifteen, narrowed to 16 bits.

The expression contains separate uses of the halfword at address zero. Their evaluation order and the number of physical memory transactions are not established. For stable ordinary memory, both uses have the same value; that assumption must not be extended to volatile, device-backed, or concurrently modified memory.

The representation also assigns a value derived from the fifth-input storage address to an apparent stack-related state location. On this path that derived value is zero. The actual architectural meaning and validity of this assignment are **documented_only**.

### Later conditional operations

The remaining pre-loop memory-writing blocks are unreachable under the represented control flow and width model.

The decisive constraint is the exceptional block above:

- Without entry to that block, the condition enabling the next chain is false.
- With entry, the continuation value is zero, the relevant computed address is zero, and a separate two-byte-adjusted value is two.
- The next equality chain therefore encounters a nonzero result of two and cannot enable the later blocks.

Accordingly, the later pointer loads, record-like writes, signed-halfword-derived writes, and associated address updates are not additional reachable behavior of this contract. Their textual presence does not justify describing an object layout or an alternate processing mode.

This reachability conclusion depends on the supplied representation and its 32-bit arithmetic. It is not independent evidence about machine instructions outside that representation.

### Repeating call-and-interrupt sequence

After the pre-loop work, execution enters a loop with the following order:

1. Invoke the first indirect dependency with three represented 32-bit arguments:
   - `0x00000000`
   - `0x00000000`
   - `0xffffffa5`
2. If that invocation returns, invoke the second indirect dependency without explicit arguments in the supplied representation.
3. If that invocation returns, issue software interrupt `0x5b`.
4. If execution resumes, replace the first-call base with `0x083d4cc2` and repeat.

On the first iteration, the first indirect target is the current continuation value plus `0x0eb6`, modulo \(2^{32}\). Ordinarily, that value is the entry continuation address. On the exceptional path it is zero.

On subsequent iterations, the represented first-call target is `0x083d5b78`.

The second indirect target is `0x0857a94b` on every iteration. This is the arithmetic address expressed by the supplied representation; any architecture-specific interpretation of its low bits remains unknown.

The first call’s third argument has the exact bit pattern `0xffffffa5`. It is −91 when interpreted as a signed 32-bit integer, but the dependency’s expected signedness is not established.

Neither call’s return value is consumed by the represented control flow. The loop has no explicit exit condition, iteration bound, or return statement.

## Side effects

### Memory

Established reachable memory effects are:

- A conditional 16-bit source read and destination write.
- On the exceptional path, access to address zero and a 16-bit write through an address obtained from a halfword value.

There is no identified allocation, release, ownership transfer, or lifetime extension. The function does not establish ownership of any accessed memory.

A caller seeking execution beyond these accesses must provide readable and writable locations as applicable. No explicit error result is produced for invalid addresses.

The halfword accesses do not establish byte order. They also do not establish whether unaligned accesses succeed, fault, or have target-specific behavior.

### External execution

Each completed loop iteration invokes both indirect dependencies and issues the interrupt, in that order. Those operations may have additional effects that cannot be bounded from this material.

No preservation of globals, memory, device state, or ownership may be assumed for an unknown dependency. Nor does the absence of explicit arguments to the second dependency establish that it consumes no machine state.

### Failure and partial progress

There is no transactional rollback.

If the initial destination write fails, the preceding source read may already have occurred. If the second dependency is never reached, the first may already have produced effects. If the interrupt does not resume execution, both calls for that iteration have already occurred.

No exception handler, retry policy, diagnostic output, or cleanup path is established.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

### Non-divisible second input

Given a second input of `1`, `2`, or `3`, no pre-loop memory access is required by the represented reachable path.

The first indirect invocation must target the entry continuation address plus `0x0eb6`, modulo \(2^{32}\), and receive the three specified bit patterns. A test need not provide valid transfer-memory addresses merely for this skipped transfer, although the calls and interrupt still require a suitable execution environment.

### Divisible second input

Given a second input of `4`, a transfer source address of `0x00001000`, a displacement of six, and readable source contents `0x1234`, the initial transfer must read a halfword at `0x00001000` and write `0x1234` at `0x00001006`.

This assumes valid accesses and excludes later dependency effects. It does not prescribe the bytes’ order in memory.

### Same-address transfer

Given a divisible second input and zero displacement, the initial read and write address are identical. The value written must be the value captured by the initial read, not a newly fetched value.

### Ordinary exclusion of the exceptional path

Given any nonzero entry continuation address, the exceptional pre-loop write cannot occur. If the initial transfer is selected, that transfer still occurs before the function enters its repeating sequence.

A nonzero fifth-input storage address also excludes the exceptional path under the represented model.

### Exceptional halfword wraparound

If all exceptional-path guards hold, address-zero accesses are permitted, and the halfword at address zero remains `0xfff8` throughout the expression, the exceptional write is directed to `0x0000fff8` and stores `0x0007`.

This example is conditional on a nonstandard address-space arrangement; it does not assert that such an arrangement is supported by the actual platform.

### Repeated execution

If both dependencies return and the interrupt resumes execution, the next iteration must call F-indirect-01 at `0x083d5b78`, then F-indirect-02, then issue interrupt `0x5b` again.

No acceptance criterion may expect a normal return after a finite number of these iterations.
