# F-1300bfd70e15

## Purpose

F-1300bfd70e15 queries a byte of context state and conditionally translates it into a 32-bit unsigned output. It first obtains the context through F-7fba0909c452.

After that dependency returns, the function’s explicit actions have three possible forms:

- Write one translated value to the output location.
- For an unsupported request, read the context status word and replace zero with `0x500`, without accessing the output.
- Return without either write.

These describe the post-dependency body, not all observable effects of the invocation. The dependency’s effects are unknown and may include changes to globally reachable output, context, or translation data.

A recognized translation path with an unaccepted state byte returns without initializing status. Invalid state encodings and unsupported requests are therefore distinct.

The supplied representation establishes translation rules and a schedule of global-value evaluations. It does not supply the declarations or contents of thirteen referenced data locations. Concrete selector reachability, expression types, and some arithmetic behavior remain **documented_only**.

## Behavior

### Dependency boundary and direct request

F-7fba0909c452 is called exactly once, before any explicit context, output, or translation-data access.

If it returns null, the remaining body performs no memory access or write. This does not imply that memory retained its invocation-entry contents: the dependency may already have changed it.

For a non-null context:

- Category `0x2300` selects the principal dispatcher.
- Category `0x8861` with selector `0x8862` selects the direct-byte path.
- Other category/selector combinations outside category `0x2300` select the unsupported-request path, subject to the arithmetic qualifications below.

The direct-byte path reads the index, reads the byte at `0x986 + 36 × index`, zero-extends it, and writes the resulting 32-bit value. Every byte value from zero through 255 is accepted. It reads no K location and does not consult status.

### Principal dispatch and preliminary global reads

Category `0x2300` begins with these separate K1 evaluations, in this order:

| Order | Captured value or decision |
|---|---|
| 1 | K1 minus one, converted to an unsigned 32-bit capture named **A-minus-one**. |
| 2 | K1 minus two, converted to an unsigned 32-bit capture named **A-minus-two**. |
| 3 | Selector equality against a newly evaluated K1 plus `0x11`. |
| 4, only if equality fails | Ordered comparison against another newly evaluated K1 plus `0x11`, explicitly converted to signed 32-bit form. |

A successful pivot equality immediately selects family B. Otherwise, the signed comparison determines the upper or lower dispatch region. Because its K1 read is separate, that comparison need not use the pivot value used for equality.

The initial captures occur even when dispatch later rejects the request.

#### Upper dispatch region

On entering this region, the function reads K6, evaluates K6 minus one, and converts the result to an unsigned 32-bit capture named **upper-minus-one**. This precedes all K7 tests and occurs even if the request is ultimately unsupported.

Dispatch then observes:

| Decision | Result |
|---|---|
| Selector equals a fresh K7 read | Family C. |
| Equality failed, and selector is below a second K7 read | `0x858A` selects B; `0x8590` or `0x8591` selects C; otherwise unsupported. |
| Equality failed, and the second comparison does not select the below region | `0x8598`, `0x8599`, or `0x859A` selects D; otherwise unsupported. |

The K7 equality and ordering tests are separate observations. Their ordered-comparison signedness cannot be determined without the missing declaration.

#### Lower dispatch region

The selector is first compared for equality against a fresh K3 read. Equality selects family A.

If equality fails, a second K3 read supplies the ordered comparison:

- Below that second value: enter the dedicated-selector region.
- Otherwise: `0x8581` or `0x8582` selects A; `0x8588` selects B; other selectors are unsupported.

The ordered comparison’s signedness is unresolved. Changes between K3 reads can affect routing.

#### Dedicated-selector region

Before checking selector `0x2200`, the function reads K4 and converts it to an unsigned 32-bit capture named **shared-value**.

If the selector is not `0x2200`, three further evaluations occur in this order, before either remaining dedicated selector is checked:

| Order | Capture |
|---|---|
| 1 | K5 plus `0x8E`, converted to unsigned 32-bit **plus-8E**. |
| 2 | A separate K5 read plus `0x8D`, converted to unsigned 32-bit **plus-8D**. |
| 3 | Another K5 read, converted to unsigned 32-bit **base-value**. |

Selector `0x8571` then selects its table; otherwise `0x8572` selects its table. Other selectors are unsupported.

Consequently, a rejected selector in this region still causes the K4 read and all three K5 reads. A request reaching the `0x2200` table does not cause those K5 reads.

These dispatch rules are ordered and conditional. Missing data values prevent treating every literal selector listed here as unconditionally reachable.

#### Families A and B

After reading the state byte, both families read K2 and convert it to an unsigned 32-bit value, regardless of whether that state will be accepted.

| State byte | Output |
|---|---|
| `0` | The post-byte K2 value. |
| `1` | Previously captured A-minus-two. |
| `2` | Previously captured A-minus-one. |
| `3` | A later K1 read, converted to unsigned 32-bit. |
| Anything else | No output write. |

The later K1 read occurs whenever the state is neither zero, one, nor two. It therefore also occurs for every invalid state, even though its value is discarded.

Neither the post-byte K2 read nor the later K1 read refreshes the initial decrement captures. Family B reached through the upper region also has the earlier K6-minus-one read, although that capture is unused by B.

#### Family C

| State byte | Output |
|---|---|
| `0` | `0x300`. |
| `1` | Post-byte K13 value converted to unsigned 32-bit. |
| `2` | Previously captured upper-minus-one. |
| `3` | A later K6 value converted to unsigned 32-bit. |
| Anything else | No output write. |

K13 is read after the byte for **every nonzero state**, including states two, three, and invalid states. State zero causes neither this read nor a later K6 read.

For nonzero states other than one and two, a fresh K6 read follows the K13 read. That includes invalid encodings. State two uses upper-minus-one, not a decrement of this later K6 value.

#### Family D

| State byte | Output |
|---|---|
| `2` | Previously captured upper-minus-one. |
| `3` | A post-byte K6 value converted to unsigned 32-bit. |
| Anything else | No output write. |

Family D reads K6 after the byte whenever the state is not two, including zero, one, and all invalid encodings. It never reads K13.

For all four families, invalid encodings return without consulting status. Whether the character-sized state representation is signed does not change the accepted bit patterns.

Unaccepted states do not take the unsupported-request path.

### Unsupported requests

The unsupported-request path reads the 32-bit status word at context offset zero:

- Zero is replaced with `0x500`.
- Nonzero is left unchanged.
- The output location, index, and state byte are not accessed by this path.

Principal dispatch may already have read K locations before reaching this path. Status preservation refers to the value observed after the dependency returns, not necessarily its invocation-entry value.

### Arithmetic and validity

Unsigned 32-bit destinations do **not** establish unsigned evaluation of the preceding expressions.

For example, the declarations needed to determine the evaluation types of K1 minus two, K5 plus `0x8E`, and K1 plus `0x11` are missing. These expressions might use unsigned arithmetic, or signed arithmetic with overflow restrictions. Assignment afterward cannot remove earlier signed overflow.

When an integer expression is defined, conversion to an unsigned 32-bit capture or output gives its value modulo \(2^{32}\). That conversion rule must be distinguished from the unresolved arithmetic producing the value. The pivot’s explicit signed conversion also requires applicable implementation rules for values outside the signed range.

The representation additionally uses signed arithmetic in request normalization, selector normalization, and address construction. Extreme input values or indices may exceed its defined arithmetic range. The nominal dispatch rules do not establish portable behavior for such cases.

Negative indices are not rejected. The caller must provide readable addressed storage, valid arithmetic, sufficient lifetime, and a writable 32-bit output location on producing paths. Invalid-address, alignment, and fault behavior are not established. A null output is not explicitly rejected; nonproducing paths do not dereference it.

## Side effects

After the dependency returns, the body explicitly performs at most one write:

- One unsigned 32-bit output write; or
- One 32-bit status write on an unsupported request observing zero status.

It does not explicitly read the output, initialize output on failure, allocate, release, retain a pointer, or change a reference count.

Translation reads the index before the state byte and writes output only after the relevant global reads. Preliminary dispatch reads precede index access. Unused global reads remain part of the represented schedule, including reads on requests that ultimately fail.

No non-aliasing requirement is shown. Output may overlap context storage or referenced data if the surrounding memory rules permit it. The output write follows the selected reads, but can affect later invocations. Output aliasing the status word can overwrite a nonzero status on a successful query; sticky-status behavior applies only to the unsupported-request path.

No ownership transfer can be established. Absence of an explicit release does not prove that the context is borrowed or that the dependency does not manage memory.

## Acceptance examples

These are conditional static criteria, not executed tests. Memory values and validity assumptions below apply **at the dependency-return boundary**, unless a later observation is explicitly specified. Assume defined arithmetic, valid accesses, and no mutation except the stated changing-read examples.

1. **Null context.** If the dependency returns null, the subsequent body performs no read or write. A sentinel already present in output at that boundary is not changed by the body; its invocation-entry value is not guaranteed.

2. **Full-range direct byte.** With category `0x8861`, selector `0x8862`, index zero, and byte `0xFF` at offset `0x986`, output becomes `0x000000FF`.

3. **Unsupported category.** With category zero and status zero at the boundary, status becomes `0x500`. Output retains its boundary value. If status instead equals `0x123`, that value is preserved.

4. **Independent initial captures.** Suppose the first K1 read yields ten, the second yields twenty, and subsequent dispatch selects A. State two produces nine; state one produces eighteen. The captures do not share one assumed K1 value.

5. **Changing pivot observations.** If pivot equality succeeds, B is selected without the signed pivot comparison or any K7 test. If equality fails, the following comparison uses its own K1 observation, even if different.

6. **Rejected A/B encoding.** With B selected and state four, K2 is read and then K1 is read. Neither output nor status is written.

7. **Unused upper-family reads.** With C selected and state two, K13 is read but discarded; output uses the earlier upper-minus-one capture. With C state four, K13 and then K6 are read, but no output or status write occurs.

8. **Family-D distinction.** With D selected and state zero, K6 is read after the state byte and no output is written. With C selected and state zero, output becomes `0x300`, with no post-byte K13 or K6 read.

9. **Rejected dedicated-region selector.** If dispatch enters the dedicated-selector region but matches none of its selectors, K4 and the three ordered K5 evaluations occur before status is inspected.

10. **Dedicated accepted ranges.** If the `0x8571` table receives state six, it reads K11 and writes its converted value. The `0x8572` table receiving six writes neither output nor status.

11. **Output aliasing.** If direct-byte output addresses the context status word, that word becomes the zero-extended byte, regardless of its previous nonzero value.
