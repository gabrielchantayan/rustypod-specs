# F-e8b751a5720a

## Purpose

F-e8b751a5720a prepares a scoped dependency state and then either activates a supplied node or records it for deferred handling.

The branch is selected by a one-byte field in a controller object, read **after** the preparation dependency returns:

- A zero byte selects immediate activation.
- Any nonzero byte selects deferred recording.

Immediate activation may first invoke operations on the controller’s current node, then notify a separately obtained object, link the supplied node into the controller, invoke the supplied node’s activation operation, and optionally invoke a controller callback.

The description “activation” is inferred intent. The established behavior is the ordered calls, reads, and writes specified below. No runtime tests have been performed.

## Behavior

### 1. Preparation precedes branch selection

Two local 32-bit storage cells are initialized from the first and second values. The recovered local layout places the second cell four bytes after the first.

F-17c2f3b940d8 is then called with five explicit arguments, in this order:

1. Address of the first local cell.
2. Zero.
3. The original first value.
4. The original second value.
5. The supplied-node pointer.

Only the first local cell’s address is explicitly passed. The preparation dependency’s permitted access extent and interpretation of that storage are unknown.

No controller selector read occurs before this call. Consequently, if preparation changes the controller’s selector or current-node state through accessible state, subsequent behavior uses the resulting state.

The later low-byte stores use the original first input value, not a reread of the local cell exposed to preparation.

### 2. Branch selection

After preparation returns, the function reads the byte at controller offset `0x0c`.

This is the only selector test shown. The function does not recheck it after later dependency calls.

### 3. Immediate path: process current nodes

This path is selected when the selector byte is zero.

The function first reads the controller’s current-node pointer. If it is null, current-node processing is skipped.

If it is nonnull, the function resolves D-01 through the then-current node and invokes it. No explicit call arguments are shown for D-01. Its 32-bit result is tested against zero:

- Zero skips the processing loop.
- Any nonzero value enters the loop.

After this initial successful query returns, the function rereads the controller’s current-node pointer and saves it as the comparison pointer. This is not necessarily the pointer that was used for the query: D-01 may have changed controller state.

Each loop iteration has the following externally relevant order:

1. Resolve D-02 through the controller’s then-current node and invoke it. No explicit arguments are shown.
2. Reread the controller’s current-node pointer into a snapshot.
3. Stop if that snapshot is null.
4. Otherwise stop if it equals the saved comparison pointer.
5. Otherwise invoke D-01 on the snapshot node.
6. Stop if that query returns zero.
7. Otherwise reread the controller’s current-node pointer, replace the saved comparison pointer with that value, and continue.

Important consequences:

- D-02 is invoked before the loop’s null and pointer-equality stopping checks.
- Equality is pointer equality, not a comparison of node contents.
- An unchanged current-node pointer terminates the loop after that iteration’s D-02 call.
- A newly observed nonnull pointer is queried only when it differs from the saved comparison pointer.
- If the loop’s D-01 call changes the controller’s current pointer, the next comparison pointer comes from a fresh controller read, not from the snapshot passed to that query.
- There is no explicit iteration bound or general cycle detection.

The function does not itself remove nodes or update the current-node pointer during this phase. Progress, if any, depends on effects of the invoked dependencies or other accessible state changes.

### 4. Immediate path: acquire and notify another object

After current-node processing finishes or is skipped, the function calls F-17fe47085641 with no explicit arguments.

It treats the returned 32-bit value as an object pointer, reads that object’s dispatch table, and invokes D-04 at table offset `0x1ec`. No explicit arguments are shown for D-04.

The result is not checked for null or validity. This step occurs before any of the function’s direct supplied-node activation writes.

### 5. Immediate path: write and publish the supplied node

After D-04 returns, the function performs these writes in order:

1. Write the low eight bits of the original first value to supplied-node offset `0x18`.
2. Read the controller’s current-node pointer and write that 32-bit value to supplied-node offset `0x14`.
3. Write the supplied-node pointer to controller offset `0x04`.

The link therefore captures the controller’s current pointer **after** F-17fe47085641 and D-04 have returned. It is not a saved pointer from the earlier processing loop.

The byte store modifies only offset `0x18`; it is not a 32-bit store to the containing word.

The function then resolves D-03 from the supplied node’s dispatch table and calls it with the supplied-node pointer as its one explicit argument. At entry to this call, the preceding direct writes have already published the supplied node as current. D-03 may subsequently change that state; this function does not restore it.

### 6. Immediate path: optional callback

After D-03 returns, the function reads the callback field at controller offset `0x28`.

- If zero, it skips the callback.
- If nonzero, it invokes D-05 with the 32-bit value from controller offset `0x2c` as its one explicit argument.

The callback address is resolved from the controller field rather than retained from an earlier activation phase. The recovered expression reads the field for the null test and again for invocation. No atomicity or protection against intervening mutation is established.

Neither the original first value nor the supplied-node pointer is explicitly passed to D-05, except insofar as the callback-argument field might independently contain such a value.

### 7. Deferred path

When the selector byte is nonzero, the function performs these direct writes in order:

1. Write the supplied-node pointer to controller offset `0x20`.
2. Write the low eight bits of the original first value to controller offset `0x24`.

This path does not directly:

- Read or replace the controller’s current-node field.
- Write the supplied node’s link or byte field.
- Call D-01, D-02, F-17fe47085641, D-04, D-03, or D-05.

Preparation and finalization still occur. Their effects are not restricted by this list.

Any previously stored deferred pointer is overwritten without an explicit release or notification operation in this function.

### 8. Finalization

This call uses the local storage as it exists at finalization time. The visible function does not restore its initial contents first.

There is no visible recovery path around failed accesses, abnormal dependency exits, or nontermination. Finalization is established for ordinary control flow reaching the end, not for every possible failure mechanism.

## Acceptance examples

### Deferred recording truncates to one byte

Given a nonzero selector after preparation, a first value of `0x123456ab`, and supplied node N:

- Controller offset `0x24` becomes `0xab`.
- The function makes no direct supplied-node writes.
- Preparation precedes these writes; finalization follows them.
- No immediate-path dependency is invoked.

### Immediate activation with no current node

Given a zero selector and a null current pointer:

- D-01 and D-02 are skipped.
- F-17fe47085641 and D-04 run.
- If the current pointer remains null, N’s link becomes null.
- N becomes the controller’s current node.
- D-03 runs with N explicitly passed.
- D-05 runs only if the callback field is nonzero after D-03.
- Finalization follows.

### Initial query declines processing

Given current node A and an initial D-01 result of zero:

- D-02 is not invoked.
- Acquisition, D-04, node writes, and D-03 still occur.
- If the current pointer remains A until the link write, N’s link becomes A.

### An unchanged pointer stops processing

Given A’s initial query returns nonzero and D-02 leaves the current pointer equal to saved pointer A:

- D-02 is invoked once.
- Pointer equality stops the loop.
- No second D-01 call occurs in that loop.
- Immediate activation continues.

### A changed pointer is queried

Given the saved comparison pointer is A and D-02 changes the current pointer to B:

- If B is null, processing stops without a query.
- If B is nonnull and differs from A, D-01 is invoked on B.
- A zero result stops processing.
- A nonzero result continues after saving a fresh read of the controller’s current pointer.

### Notification changes the link source

Given current pointer A when processing ends, but D-04 changes it to B:

- N’s link receives B, not A.
- The controller’s current pointer is then set to N.

### Existing-current supplied node

Given N is still current when the link write occurs:

- N’s link is written as N.
- No duplicate-node or self-link rejection occurs.
