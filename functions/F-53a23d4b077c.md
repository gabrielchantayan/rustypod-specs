# F-53a23d4b077c

## Purpose

F-53a23d4b077c conditionally returns an object associated with a requested target. It applies two gates, optionally accepts an object supplied through a dispatch operation, and otherwise obtains an object through a separate dependency. The latter path initializes selected fields, performs context-dependent operations, and invokes a final integration dependency.

The result is either a null pointer or an object pointer. Null does not distinguish gate rejection, target restriction, acquisition failure, or conditional preparation failure.

“Object,” “target,” “dispatch,” “acquisition,” “preparation,” and “integration” describe apparent roles. They do not establish application-level types, allocation behavior, ownership, or hidden dependency semantics.

## Behavior

### Entry gates and temporary argument block

Before the first dependency call, a contiguous 16-byte temporary block contains four words in this order: the original context pointer, original requested-target pointer, auxiliary A, and auxiliary B.

F-724e1e872fe7 is called without explicit arguments. A zero result returns null immediately and suppresses all subsequent calls.

Otherwise, F-06f4ceb6a4f2 receives the original requested target. Its zero result also returns null. Neither rejection path performs a direct context-field or target-field read in this function. This does not constrain memory accesses performed inside either gate.

### Initial-object comparison

After both gates succeed, the initial comparison pointer is the word at context offset 0x00 when context is non-null, and null otherwise.

If the requested target equals that pointer, both the restriction test and dispatch attempt are bypassed. Processing proceeds to acquisition.

If the pointers differ, the byte at initial-object offset 0x21 is read. Mask 0x01 being set causes an immediate null return. If clear, the target’s dispatch eligibility is considered.

There is no null guard on the initial object before the restriction-byte access. A null context with a non-null target, or a context whose first word is null with a non-null target, therefore reaches an attempted read at address 0x21 if the gates succeed. Conversely, equality of two null pointers bypasses that read but does not make the later target access safe.

### Dispatch and candidate acceptance

For differing pointers that pass the restriction, mask 0x02 in the target byte at offset 0x20 controls dispatch. A set bit bypasses dispatch and proceeds to acquisition.

When that bit is clear, F-c67cb20988a1 receives the temporary block address and 0x10. After it returns, only the block’s first word is restored to the original context pointer.

The dispatch global operand is then read when constructing the call to F-3182ac1ca82f. This read occurs **after F-c67cb20988a1 has returned and after restoration of the block’s first word**. F-3182ac1ca82f receives the original requested target, that global operand’s value at this read, and the block address.

The global is not established to be a fixed constant. Earlier dependencies, including F-c67cb20988a1, may affect its value. No entry-time snapshot or preservation guarantee is visible.

After dispatch returns, the block’s second word is read as a candidate pointer. Acceptance requires both a zero dispatch result and a non-null candidate. A nonzero dispatch result rejects the candidate regardless of its value; a zero result with a null candidate also falls through to acquisition.

For an accepted candidate, F-2d353fe6cfb2 receives the original context and that candidate. The function then returns the same candidate pointer value without acquisition-path initialization.

The block’s last three words are not restored before dispatch. Thus:

- The candidate need not be the original target.
- The auxiliary words need not retain their original values.
- Changes to block entries do not replace the original argument values used elsewhere by this function.
- No visible cleanup is performed for a candidate rejected because dispatch returned nonzero.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. They assume reached accesses are valid and relevant dependencies return normally.

1. **First gate rejects.** A zero result from F-724e1e872fe7 produces null. No other dependency is called.

2. **Second gate rejects.** After a successful first gate, a zero result from F-06f4ceb6a4f2 produces null before the direct context-field read.

3. **Restriction rejects a differing target.** If the target differs from the initial object and its restriction byte has mask 0x01 set, the function returns null without reading target offset 0x20.

4. **Matching pointers bypass dispatch.** Equality of target and initial object bypasses both the restriction-byte access and dispatch. Acquisition uses the target word at offset 0x44.

5. **Dispatch observes a changed global.** Suppose the dispatch global has one value before F-c67cb20988a1, that dependency changes it to another value, and nothing changes it before the later read. F-3182ac1ca82f receives the later value. The contract does not substitute an entry-time value.

6. **Dispatch accepts an alternate candidate.** If dispatch returns zero and leaves a non-null alternate pointer in the block’s second word, F-2d353fe6cfb2 receives that pointer. The function returns it without acquisition.

7. **Dispatch status overrides a candidate.** A nonzero dispatch result rejects even a non-null block candidate. Acquisition follows, with no explicit candidate-release call.

8. **Acquisition fails.** A null result from F-4ea4af41aab6 produces null without F-ad023a375886 or later initialization.

9. **Bit clearing preserves unrelated bits.** A result byte of 0xb7 immediately before the offset-0x14 modification becomes 0xa7. A word of 0xffffffff immediately before the offset-0x1c modification becomes 0xffffffc7.

10. **Post-call pointer rereads matter.** If F-c4407f9efc54 changes result offset 0x10, the subsequent external call uses the changed pointer, assuming it remains available at the later read.

11. **Preparation failure stops integration.** If the arithmetic condition holds, context byte 0x16 is not 0x01, and preparation returns nonzero, F-2eb76f8c5126 is called and the result is null. No 0x30 external operation or final integration follows.

12. **Preparation bypass still performs branch work.** If the arithmetic condition holds and context byte 0x16 equals 0x01, preparation is skipped, but the 0x30 external operation and F-6a9ebe09334a still occur before final integration.
