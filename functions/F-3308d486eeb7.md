# F-3308d486eeb7

## Purpose

F-3308d486eeb7 prepares shared operation state, repeatedly calls an external dependency until it returns nonzero, programs a register-like block, and supervises an operation until a status or dependency result permits exit. It then replaces a shared coordination value and returns a result determined by a final status-byte read.

The established return rule is:

- **0** when the final status-byte observation equals **24**.
- **96** otherwise.

The operation-record address is read twice at entry. The first address is retained for subsequent record accesses; the second addresses the initial status write. These addresses are not established to be equal.

Hardware initiation and asynchronous completion are inferred intent, not established device semantics. The evidence does not identify a device, protocol, operating system, or broader meaning for the numeric statuses.

## Interface

### Arguments and result

| Argument | Representation | Established use |
|---|---|---|
| First | Signed integer represented as 32 bits | Shifted left one bit, combined with a low-order 1 bit, and written as a 32-bit register-like value |
| Second | Opaque 32-bit value | Stored at byte offset 8 of the retained operation record |
| Third | Opaque 32-bit value | Stored at byte offset 12 of the retained operation record |

The second and third arguments undergo no visible validation or interpretation. Their possible meanings, including whether they represent addresses, are unknown.

For first-argument values from **0 through 1,073,741,823**, the signed 32-bit left shift has an unambiguous representable result, and the programmed value is twice the argument plus one. Behavior for negative inputs or inputs whose left shift exceeds the signed range is **documented_only**. A wrapping interpretation is not established.

The returned quantity is 32 bits. Neither an acquisition result nor a supervision-dependency result is returned directly.

### Shared locations and accessed layouts

The function reads shared locations supplying:

- An operation-record address, read twice at entry.
- A register-block address, captured once.
- A coordination-slot address, captured once.
- An opaque 32-bit value, captured after register programming.

Two operation-record addresses must be distinguished:

- **Retained record:** identified by the first operation-record address read. Subsequent field writes, supervision reads, conditional status writes, and the final status read use this address.
- **Initial-status target:** identified by the second read of the same shared address location. Only the initial status-20 write is directly addressed through this second value.

They may identify the same record, but address stability is not checked.

The operation-record accesses are:

| Target | Byte offset | Width | Access |
|---|---:|---:|---|
| Initial-status target | 1 | 8 bits | Written with 20 |
| Retained record | 1 | 8 bits | Read during supervision, conditionally written with 23, and read for return selection |
| Retained record | 4 | 32 bits | Written with zero |
| Retained record | 8 | 32 bits | Written with the second argument |
| Retained record | 12 | 32 bits | Written with the third argument |

When both addresses are equal, these accesses describe one record. Otherwise, the initial status write and subsequent record operations target different bases. There is no explicit status-20 initialization of the retained record in that case.

The register-like block has these accesses:

| Byte offset | Width | Access |
|---|---:|---|
| 0 | 32 bits | Read, combined with mask 128, then written |
| 4 | 32 bits | Written with 176 |
| 12 | 32 bits | Written with the transformed first argument |
| 16 | 32 bits | Repeatedly read until the entire value equals zero |

The coordination slot is read and written as a 32-bit quantity. These layouts describe accessed fields only, not complete objects.

### Preconditions

No visible null, alignment, bounds, or accessibility checks protect these accesses. Both operation-record addresses must support their respective accesses, and the captured register and coordination addresses must remain usable throughout the function.

No non-overlap check exists. Object overlap is unresolved and can affect later observations, including the status byte. Address-containing shared locations are not established to be disjoint from writable objects.

Termination requires external progress: acquisition must eventually return nonzero, each reached register wait must eventually observe zero, and supervision must eventually reach an exit condition. Dependencies must also return normally for execution to proceed beyond their calls.

## Behavior

### 1. Read the record address twice and publish initial fields

The entry sequence is ordered as follows:

1. Read the shared operation-record address and retain that value.
2. Read the same shared address location again.
3. Write **20** to the byte at offset 1 through the second address.
4. Read and retain the register-block address.
5. Read and retain the coordination-slot address.
6. Write zero to the retained record’s 32-bit field at offset 4.
7. Write the second argument to its 32-bit field at offset 8.
8. Write the third argument to its 32-bit field at offset 12.

The second record-address read is distinct from the first. If the shared address changes between them, the status-20 write can affect a different record from the one subsequently supervised.

The initial status write precedes capture of the register and coordination addresses. If storage overlaps, that write could affect values subsequently captured; the evidence does not exclude this.

All four initial data stores occur before the first acquisition call. The function therefore modifies shared state before obtaining the nonzero acquisition result. Any protection required for those writes must come from an external arrangement.

After these captures, changes to the shared address locations do not by themselves redirect the retained record, register-block, or coordination-slot accesses. Changes to the contents at those captured addresses can still affect execution.

### 2. Retry acquisition

Each acquisition attempt calls **F-000000000001** with:

- A newly read 32-bit value from the captured coordination slot.
- The integer **100**.

A nonzero result ends acquisition. Every nonzero result is accepted; no finer classification is visible.

A zero result causes a call to **F-000000000002**:

- If its result is nonzero, call **F-000000000003** with **0** and **1**, then retry acquisition.
- If its result is zero, retry acquisition without that additional call.

The coordination value is reread for every attempt. Dependencies or other actors may change it between attempts.

Zero acquisition results do not produce a returned error. The retry sequence has no visible attempt limit. The meaning and units of 100 are unknown.

### 3. Program the register-like block

After acquisition succeeds, three separate waits precede three ordered writes:

1. Repeatedly read the 32-bit field at offset 16 until it equals zero. Then read the 32-bit field at offset 0, force bit 7 to one, and write the resulting value back to offset 0.
2. Again wait for offset 16 to equal zero. Then write the transformed first argument to offset 12.
3. Again wait for offset 16 to equal zero. Then write **176** to offset 4.

Each wait performs at least one read. It tests the entire 32-bit value for zero, rather than testing a selected bit.

The offset-0 operation preserves the bits present in the value actually read, except that bit 7 is forced to one. Atomicity is not established. A concurrent modification between the read and write may be overwritten.

There is no visible timeout, delay dependency, cancellation check, or recovery action within these waits. If a reached wait never observes zero, later programming, supervision, and finalization are not reached.

After the offset-4 write, the function reads and retains the opaque shared 32-bit value used in one supervision path. Later changes to that shared source location do not change the retained argument.

### 4. Supervise the retained record

Each supervision iteration starts by reading the retained record’s status byte as an **unsigned 8-bit value**.

- An observed value greater than **22** ends supervision without a status write on that branch.
- An observed value from **0 through 22** causes a call to **F-000000000002**.

Values from 128 through 255 therefore satisfy the exit comparison. This is not a signed-byte threshold test.

There is no further status read between the threshold check and selection of the dependency path. A status change during a dependency call does not prevent the already-selected work.

#### Nonzero result from F-000000000002

The function calls **F-000000000004** with **61** and **100**.

- Result **5** causes an explicit write of **23** to the retained record’s status byte, followed by exit from supervision.
- Every other result returns to the beginning of supervision for a fresh status read.

No status check intervenes between result 5 and the write of 23. A status established during the call can be overwritten.

#### Zero result from F-000000000002

The function:

1. Calls **F-000000000005** with the previously retained opaque value.
2. Retains that call’s result.
3. Calls **F-ca2ffda9d056** with **0**.
4. Compares the retained result with **31**.

Result 31 causes an explicit write of **23** to the retained record’s status byte and ends supervision. Any other result begins another iteration.

F-ca2ffda9d056 is called even when the retained result is 31. Its status changes, if any, can consequently be overwritten by the subsequent write of 23.

The function’s explicit assignments to designated status-byte fields use only **20** and **23**. This does **not** establish that its other direct stores cannot produce status 24: overlapping storage could allow a different store to affect the byte. Only under a non-overlap assumption does observing 24 require a dependency, another actor, or previously existing state to have established it.

### 5. Replace the coordination value and choose the return

All visible supervision exits converge on this sequence:

1. Call **F-000000000006** without arguments.
2. Write its 32-bit result to the captured coordination slot.
3. Read the retained record’s status byte.
4. Return **0** if the byte equals **24**, otherwise **96**.

The final status read occurs after both the dependency call and the coordination-slot store. The earlier status observation or explicit write that ended supervision does not determine the return by itself.

The coordination store can itself affect the final status if the slot overlaps that byte. Its effect then depends on the overlap position and stored byte representation, neither of which is established.

## Side effects

Established direct effects include:

- Two ordered reads of the shared operation-record address.
- An initial status-20 write through the second address.
- Three 32-bit field writes through the first, retained address.
- Repeated coordination-slot reads during acquisition.
- Register polling, one register read-modify-write, and two further register writes.
- Conditional status-23 writes through the retained record address.
- A final 32-bit coordination-slot replacement.
- The dependency calls described below.

No allocation, pointed-to payload copy, or explicit memory release is visible in this function. Storing an argument does not establish ownership transfer. Replacing the coordination value does not establish release or destruction of anything represented by its old contents.

Dependencies may modify shared state, block, or have other effects. Their preservation of globals and their ownership or release behavior are unknown.

The represented access order does not establish atomicity, hardware barriers, volatile semantics, or cross-thread visibility guarantees.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests.

1. **Stable record address.**  
   If both entry reads return the same address and the relevant objects do not overlap, that record receives status 20, then the zero field and both argument fields, before the first acquisition call.

2. **Changed record address.**  
   If the first entry read identifies record A and the second identifies distinct, non-overlapping record B, the initial status-20 write targets B. The field writes at offsets 4, 8, and 12, subsequent supervision, and final status selection use A. This function does not explicitly initialize A’s status to 20.

3. **Fresh acquisition input.**  
   If an acquisition call returns zero and the coordination slot changes before the next attempt, that next call receives the value read for that attempt rather than a cached first-attempt value.

4. **Retry branch selection.**  
   Following a zero acquisition result, a zero F-000000000002 result omits F-000000000003. A nonzero result calls it with 0 and 1 before retrying.

5. **Register ordering.**  
   With first argument 3 and all waits completing, the register writes occur in this order: force bit 7 at offset 0, write 7 at offset 12, write 176 at offset 4. Each follows its own zero observation at offset 16.

6. **Blocked second wait.**  
   If the second register wait never observes zero, the offset-12 write and all subsequent phases are not reached.

7. **Unsigned status threshold.**  
   Status 22 enters dependency-driven supervision. Status 23, 24, or 255 ends supervision immediately at that iteration’s threshold check.

8. **Helper precedes forced status.**  
   If F-000000000005 returns 31, F-ca2ffda9d056 is still called. If it writes status 24, the following explicit write replaces that byte with 23 before finalization.

9. **Final read controls the result.**  
   If supervision observes 24 but the final status is 25, return 96. If supervision ends by writing 23 but the final status is 24, return 0.

10. **Overlapping final store.**  
    If the coordination slot overlaps the retained status byte and its final store places byte value 24 at that location, the final comparison selects zero, provided no intervening modification changes it. This need not involve an explicit status-24 assignment or another actor.

11. **No local termination guarantee.**  
    Perpetually unsuccessful acquisition, a perpetually nonzero polled register, or supervision without an exit condition can prevent return.
