# F-9c01f3513f11

## Purpose

F-9c01f3513f11 conditionally transforms an object containing a signed-count-like header and an array of 32-bit words. The signed interpretation of an unsigned 32-bit operation argument selects movement toward higher or lower word positions.

**Inferred intent:** the object resembles a signed, multiple-precision integer whose magnitude words are stored least-significant word first. The transformations resemble left and right shifts.

**Established qualification:** a displacement remainder of one bit receives the same treatment as a remainder of zero bits. The function therefore cannot be specified as an ordinary arithmetic shift for every argument.

Global factors participate in interpreting headers, reading words, and storing results. Distinct reads of a factor are not interchangeable without an established stability guarantee.

The Boolean result is not a general success indicator. Normal completion of every admitted path returns false, including a lower-direction path that skips local transformation because a dependency returns nonzero.

## Interface

### Explicit inputs and layout

The first input references a writable record with these fields:

| Byte offset | Width | Meaning |
|---|---:|---|
| 0 | 32 bits | Header interpreted through direction-specific factors |
| 4 | 32 bits | Backing-storage address |

Backing storage consists of four-byte words. Index zero begins at the stored address; successive indices are four bytes apart. The representation uses a 32-bit address field, not a native-width pointer abstraction.

The second input is an **unsigned 32-bit operation argument**, interpreted by its signed 32-bit bit pattern when selecting direction:

- Zero selects immediate false return after the entry global reads.
- `0x00000001` through `0x7fffffff` select the higher-position branch.
- `0x80000001` through `0xffffffff` select the lower-position branch, with unsigned negation producing the displacement magnitude.
- `0x80000000` also selects the lower branch. Its unsigned negation remains `0x80000000`; its signed interpretation then fails admission.

### Result

For arithmetic within the defined domain described below:

- Zero argument: false.
- Admitted operation returning normally: false.
- Rejected nonzero operation: true.

There is no separate capacity, allocation, pointer-validity, or dependency-error result.

### Global-factor terminology

The following names describe roles, not external symbols:

- **Higher count factor** and **lower count factor:** each is read at entry. The selected factor is read again for admission.
- **Lower word-read factor**, **lower word-store factor**, and **lower header factor:** captured after F-18cbf7a56e3c returns. The lower header factor is read yet again on the raw-copy path.
- **Higher word-store factor** and **higher word-read factor:** captured after F-d72f047fba8b returns.
- **Higher header-store factor:** read for the final higher-direction header update.

“Entry factor,” “admission factor,” “post-dependency captured factor,” and “update-time factor” distinguish reads even when they address the same global storage.

### Preconditions and arithmetic domain

Every field and word actually accessed must support the required access. Backing storage must accommodate all writes, including an extra high candidate word on the higher multi-bit path. No local capacity check is visible.

Dependencies must return normally for subsequent local behavior to occur. If a dependency changes the backing address, subsequent accesses use the changed record.

Word results are described as 32-bit patterns, with logical right shifts and low-32-bit products where those operations are established. Signed header products, absolute-value formation, and other signed expressions require additional care: signed overflow and minimum-signed-value absolute formation are not assigned portable behavior here. Signed intermediate word expressions and left shifts likewise require the arithmetic assumptions stated under **Uncertainties**.

No ownership transfer, allocation guarantee, or release obligation is established.

## Behavior

### Entry reads and admission

The initial observable global-read sequence is:

1. Read and retain the higher count factor.
2. Read and retain the lower count factor.
3. Test the operation argument for zero.

A zero argument returns false without locally dereferencing the object.

For a nonzero argument, the selected direction’s count factor is **read again** and multiplied by the object header. Admission uses this fresh value, not the retained entry value. Let \(n\) be the nonnegative absolute value of that product, assuming its formation is defined.

The retained entry factor remains available separately for later header calculations. There is no established guarantee that it equals the admission-time factor.

For the lower branch, the displacement magnitude is the unsigned 32-bit negation of the original argument. For the higher branch, it is the original argument. Let:

- \(q\) be the unsigned magnitude divided by 32.
- \(r\) be the magnitude modulo 32, from zero through 31.

Admission requires both:

- \(n \leq 28\); and
- The magnitude’s signed 32-bit interpretation is strictly positive.

Rejection returns true without a dependency call or local object write. The header read and its arithmetic precede rejection.

In particular, `0x80000000` does not cause unsigned-negation overflow. Negation preserves its bit pattern, whose signed interpretation is negative. It therefore returns true, provided the preceding header-product and absolute-value operations are defined.

The threshold limits the interpreted **input count**, not the output count or required capacity. A small admitted input may request a very large whole-word displacement.

### Lower-position branch

After admission, F-18cbf7a56e3c is called with the object reference. After its return, the function captures, in order:

1. Lower word-read factor.
2. Lower word-store factor.
3. Lower header factor.

These reads occur even when the dependency returns nonzero.

The admission count \(n\), displacement components, and retained entry lower count factor remain pre-call quantities. Subsequent object accesses use the then-current record and storage.

If the dependency returns nonzero, the function performs no subsequent local header or word write and returns false. Dependency effects are not undone.

#### Entire interpreted value discarded

If the dependency returns zero and \(q \geq n\), the function writes zero to the header and returns false.

No backing words are locally cleared. This case includes an admitted zero-count object.

#### Remainder zero or one: raw movement

If \(q<n\) and \(r\) is zero or one, the function:

- Reads the then-current header and multiplies it by the **retained entry** lower count factor.
- Moves that interpreted header toward zero by \(q\): subtracting \(q\) when nonnegative, adding \(q\) when negative.
- **Reads the lower header factor again** for this update and multiplies by that fresh value.
- Writes the header before copying words.
- Copies \(n-q\) raw words from indices beginning at \(q\) to indices beginning at zero, in increasing destination order.

The post-dependency captured lower header factor is not the factor used for this raw-path header store.

The copied words are not scaled by either word factor. Remainder one does not shift bits. With \(q=0\), each word is read and written at its existing index.

Discarded high storage positions are not cleared. The function returns false.

#### Remainder two through thirty-one: combined words

If \(q<n\) and \(2 \leq r \leq 31\), let \(m=n-q\).

Each destination below the final destination combines:

- The source at its index plus \(q\), scaled by the captured lower word-read factor and logically shifted right by \(r\).
- The next source, similarly scaled and shifted left by \(32-r\).

The contributions are combined by bitwise OR and multiplied by the captured lower word-store factor. Writes proceed in increasing destination order.

The final destination, index \(m-1\), receives only the right-shift contribution from source index \(n-1\), multiplied by the store factor.

The function then tests the captured word-read factor multiplied by the **computed final stored value**. This is not an additional memory read of the final destination. A zero product reduces the result count from \(m\) to \(m-1\); a nonzero product retains \(m\). No further high-word normalization occurs.

After word writes, the function reads the current header and multiplies it by the retained entry lower count factor:

- Strictly positive selects the positive result count.
- Zero or negative selects the negative result count.

The selected signed count is multiplied by the **post-dependency captured** lower header factor and written to the header. Unlike the raw path, this path does not reread that factor for the update. The function returns false.

### Higher-position branch

After admission, F-d72f047fba8b is called with the object reference. The function then captures:

1. Higher word-store factor.
2. Higher word-read factor.

The admission count remains the iteration count even if the dependency changes the header.

If \(n=0\), the function returns false without subsequent local word or header writes. The dependency call and post-call factor reads have nevertheless occurred.

#### Remainder zero or one: raw movement

For nonzero \(n\) and \(r\) equal to zero or one:

- Copy \(n\) raw words upward by \(q\) positions, processing source indices from highest to lowest.
- Write zero into the lowest \(q\) positions, from index \(q-1\) downward to zero.
- Read the header and multiply it by the retained entry higher count factor to determine whether \(q\) is added or subtracted.
- Read the header again for the base product in the header calculation.
- Add \(q\) for a nonnegative sign-test product, or subtract \(q\) for a negative sign-test product.
- Multiply by the higher header-store factor read for the final update, and write the header.

The two header reads are distinct; equality of their values requires stability. The dependency’s return value does not participate in this path’s header calculation.

The word factors are not applied to raw copied data. Remainder one produces no one-bit shift. The function returns false.

#### Remainder two through thirty-one: combined words

For nonzero \(n\) and \(2 \leq r \leq 31\), the function reads the original \(n\) source positions in descending order.

Each source is scaled by the captured higher word-read factor and treated as a 32-bit pattern. Its upper bits are combined with the left-shifted contribution retained from the previously processed, higher source.

The first destination written is index \(n+q\). Writes then descend. After all source words have been read:

- The remaining left-shifted contribution is stored at index \(q\).
- Lower indices are written as zero, descending to index zero.

The combined-word stores, residual store, and low-zero stores use the captured higher word-store factor.

After these writes, the function reads back destination index \(n+q\), multiplies it by the captured higher word-read factor, and tests the product:

- Zero selects count \(n+q\).
- Nonzero selects count \(n+q+1\).

This count is multiplied by the return value of F-d72f047fba8b, then by the higher header-store factor read for the final header update. The product is stored in the header.

Only the single highest candidate word is inspected. The function returns false.

## Side effects

### Observable ordering and aliasing

Established sequencing includes:

- Higher then lower entry count-factor reads, even for a zero argument.
- A separate selected count-factor read for nonzero admission.
- Admission before any dependency call.
- Direction-specific captured-factor reads after the dependency returns.
- Lower raw-path update-time header-factor read and header write before word copying.
- Lower multi-bit word writes before the final header read and header write.
- Higher word writes before final header processing.
- Increasing lower-direction destination traversal and decreasing higher-direction traversal.
- An actual high-word readback on the higher multi-bit path, but a computed-value test on the lower multi-bit path.

This does not establish an evaluation order between every operand read within a single expression.

The backing address is obtained from the record during processing; the behavior must not be modeled as necessarily using one immutable address captured before the dependency or loop.

Ordinary word-array examples assume the record, backing storage, and globals do not overlap. With aliasing, header writes, word writes, or global overlap can affect later reads. The function provides no isolation or rollback guarantee.

### Ownership and errors

No direct allocation or release is visible. Either dependency may affect storage ownership, the record, words, or globals; none of those effects is established here.

A reduced count does not erase discarded storage. The higher multi-bit path writes its extra high candidate word even when that word is subsequently excluded from the result count.

There is no local null, address, capacity, or lifetime validation. A fault or abnormal dependency exit prevents the normal Boolean-return contract from applying. Partial writes may remain.
