### Entry into direct memory mutation

The final represented 64-bit result of F-U001 supplies low and high 32-bit halves.

The following descriptive terms identify retained quantities, not object types:

- **Packed word:** a retained 32-bit transformed result also used directly as an address base.
- **Large base:** an earlier result multiplied by `0x02000000`.
- **Small value:** the constrained masked quantity described above.

The first direct stores occur in this order:

| Order | Width | Destination and payload |
|---|---|---|
| 1 | 32 bits | High result half plus `0x14`; stores the packed word. |
| 2 | 8 bits | Packed word plus 9; stores the high result half’s low byte. |
| 3 | 32 bits | Low result half multiplied by 256, plus `0x54`; stores the large base. |
| 4 | 8 bits | Packed word plus 9 again; stores the packed word’s low byte. |

The word store between the byte stores prevents treating those byte stores as adjacent replacement operations. Their addresses may overlap other computed accesses.

The next region has this established order:

1. Clear a 32-bit word at the large base plus `0x14`.
2. Read an unsigned byte at the large base plus 5.
3. Clear a 32-bit word at twice the small value plus `0x14`.
4. Store the widened byte as a 32-bit word at the large base plus `0x34`.
5. Reload the word at the large base plus `0x14`.
6. Repeat the clear at twice the small value plus `0x14`.

**Under ordinary memory semantics without external mutation, the reload returns zero.** Only two writes intervene between the initial clear and that reload:

- The other zero-word store cannot make any overlapping cleared bytes nonzero.
- The widened-byte word store starts `0x20` bytes beyond the cleared word. The two four-byte regions do not overlap under ordinary 32-bit address arithmetic, including modular wraparound.

Aliasing among these computed references therefore does not justify an unknown reload value.

The reload nevertheless remains a distinct represented read. Establishing its ordinary-memory value does not establish that eliminating an observable access is permissible. Any departure from zero requires separately unresolved memory behavior, such as concurrent mutation, device effects, or mappings that do not behave as ordinary independent byte-addressed storage.

The retained reload value supplies two subsequent byte stores at twice the small value plus `0x15`. Under the same ordinary-memory assumptions, both payloads are zero. It also later supplies an offset-`0x54` destination base; under those assumptions, that destination is address `0x54`.

## Acceptance examples

These are conditional static examples, not executed tests.

### Initial arguments

Given ambient unsigned words `0x80000000` and `0x00008000`, their respective logical right shifts by 15 produce `0x00010000` and 1. The first invocation preserves the first and third explicit inputs in argument positions one and three.

### Masked extraction

Masking `0x12abcdef` to 24 bits and logically shifting right by 8 produces `0xabcd`.

### Clear, reload, and overlapping zero store

Assume valid ordinary memory, ordinary 32-bit address arithmetic, completed accesses, and no external mutation.

After clearing the word at the large base plus `0x14`, the reload of that word returns zero. This remains true if the intervening zero-word destination partially or completely overlaps it: writing additional zero bytes cannot introduce nonzero cleared bytes.

The widened-byte word store at the large base plus `0x34` is `0x20` bytes away and does not overlap the cleared word, regardless of the byte’s value.

The reload remains a distinct represented read. A nonzero observation requires behavior outside these assumptions; overlap among the specified intervening writes is not a sufficient explanation.

Under these assumptions, the two following byte stores derived from the reload both supply zero, and the later offset-`0x54` store using that retained value as its base addresses `0x54`.

### Fixed-address conversion and order

The read associated with `0x05` precedes the assignment associated with `0x01`; this does not require an unsigned-byte read at `0x05`.

If conversion of that object’s value produces `0x12345678`, subsequent base calculations use that unsigned 32-bit value, not `0x78`. Whether the object can supply it depends on its missing declaration and contents.

The assignment at `0x54` precedes the assignment at `0x15`. The read at `0x087fbbbc` precedes the assignment at `0x60`.

### Retained values versus repeated reads

If the word retained from `0xa9` is `0x12345678`, the later assignment at `0x67` supplies `0x78`.

If intervening mutation changes what a subsequent read of `0x67` observes, a later explicit byte store uses the newly observed value’s low eight bits. The independently retained word remains `0x12345678`.

### Widths and final arguments

A 32-bit store of `0x2f` is not equivalent to a one-byte slash store. Eliminating the first initial offset-9 byte store loses a represented access separated from the second by a word store.

If later mutation changes the location used for the earlier offset-`0x14` read, F-U002 still receives the retained word as its third argument. Reaching F-U002 proves neither successful return nor an ownership outcome.
