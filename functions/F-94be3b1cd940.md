# F-94be3b1cd940

## Purpose

F-94be3b1cd940 describes a fixed-order sequence of indirect calls, interspersed with four explicit one-byte memory writes. Selected call results are transformed into later call arguments or write addresses. The supplied representation ends at an invalid-instruction boundary rather than an ordinary return.

The application-level purpose is unknown. Repetition and scaling do not establish that this function processes an array, initializes objects, renders data, or implements a protocol.

This contract distinguishes:

- **Established static evidence:** operations and ordering visible in the supplied representation.
- **Inferred intent:** possible interpretations, not requirements.
- **documented_only:** unresolved behavior requiring instruction-level, dependency, or execution evidence.

The representation carries an explicit warning about invalid instruction data. Accordingly, the contract describes the represented path; it does not establish that this path is executable or correctly recovered throughout.

## Behavior

### Ordering model

The represented path is sequential. Calls and explicit writes retain their displayed order; the contract does not authorize batching, parallel execution, deduplication, or moving a store across a call.

A call with no explicitly represented arguments is not proven to consume no machine-state inputs. Likewise, an unused return value does not imply that the call has no effects.

For the schedule below, a **scaling segment** means:

- A sequence of calls without explicitly represented arguments.
- The final call in that sequence produces a 32-bit result.
- The immediately following call receives that result shifted left by two as its one explicitly represented argument.

This is a description of observable dataflow, not a claim that all segments share a dependency or application purpose.

### Stage 1: initial scaling and first write

The function begins with five scaling segments.

The first segment has three calls before its argument-bearing call: two whose results are unused, followed by the result-producing call. Its first destination depends on the incoming control-link value plus 4,094.

Each of the next four segments has four calls before its argument-bearing call: three whose results are unused, followed by the result-producing call.

After those five segments, four more calls occur without explicitly represented arguments. The fourth produces an unsigned 32-bit selection word.

The selection word determines an intermediate address operand:

- If bit 30 is set, the operand is the selection word shifted left by two.
- If bit 30 is clear, the operand is the incoming fallback word shifted left by ten.

Bit 30 is tested on the selection word before choosing between these operands. The condition does not test bit 31, the shifted result’s sign, or whether the resulting address is valid.

The first explicit write then stores the low eight bits of the incoming payload word at an address obtained by multiplying the selected operand by two.

Immediately afterward, a dependency receives two explicitly represented arguments, both equal to the selected operand. These arguments are not the doubled write address.

### Stage 2: forwarding, scaling, and second write

After the first write and its following two-argument call:

1. Four calls occur without explicitly represented arguments.
2. The fourth returns an unclassified 32-bit value.
3. The next call receives that value unchanged as one explicitly represented argument.

Nine scaling segments follow. Each has three calls with unused results, then a result-producing call, then the call receiving the result shifted left by two.

Four additional calls then occur without explicitly represented arguments. The fourth produces a signed 32-bit address-producing result.

The second explicit write stores one byte at the address formed by shifting that result left by three. The byte is taken from bits 22 through 29 of the incoming unsigned payload word: the word is shifted right by 22, then narrowed to eight bits.

The immediately following dependency receives two different transformations of the same address-producing result:

- First argument: the result multiplied by four.
- Second argument: the result shifted left by ten.

Neither argument is the second write address.

### Stage 3: extended prelude, scaling, and third write

Nine calls occur without explicitly represented arguments. The first eight results are unused; the ninth supplies the value for a following call receiving that value shifted left by two.

Eight ordinary scaling segments follow. Each contains three unused-result calls, a result-producing call, and a call receiving the shifted result.

Thus this stage contains nine shift-by-two consumers before its final write-producing prelude, but its first prelude is longer than the others. A behavioral implementation must not normalize that difference away.

Four more calls occur without explicitly represented arguments. The fourth produces a signed 32-bit address-producing result.

The third explicit write stores a zero byte at the address formed by shifting this result left by three.

Immediately afterward, a dependency receives two equal arguments, each formed by shifting the same result left by fourteen.

### Stage 4: forwarding, scaling, and fourth write

Four calls occur without explicitly represented arguments. The fourth produces an unclassified 32-bit value, which the next call receives unchanged as one explicitly represented argument.

Nine ordinary scaling segments follow, each with three unused-result calls, one result-producing call, and a shift-by-two consumer.

Four further calls occur without explicitly represented arguments. The fourth produces another signed 32-bit address-producing result.

The fourth explicit write stores a zero byte at the address formed by shifting this result left by three.

The following dependency receives two equal arguments, each formed by shifting that result left by fourteen.

### Stage 5: duplicated forwarding and terminal sequence

Four calls occur without explicitly represented arguments. The fourth produces an unclassified 32-bit value.

The next call receives that value unchanged in **both** explicitly represented argument positions. This differs from the single-argument forwarding operations in Stages 2 and 4.

Nine ordinary scaling segments follow.

Finally, four calls occur without explicitly represented arguments, with no represented use of their results. The representation then terminates at an invalid-instruction boundary. An ordinary function return is not shown.

### Arithmetic boundaries

The contract preserves the distinction between signed and unsigned operations in the evidence:

- The first selection word is unsigned, so its left shift is represented as an unsigned operation.
- Most later shifted results are signed 32-bit quantities.
- Address multiplication and several left shifts involve signed quantities.
- Extraction of the second payload byte uses an unsigned right shift.

It is not safe to replace every operation with unbounded mathematical multiplication. Nor does the supplied representation justify assigning modulo-\(2^{32}\) behavior to every signed expression.

For nonnegative values whose transformed results remain within the signed 32-bit range, left shifts have the ordinary scaling interpretation. Negative operands, signed overflow, out-of-range address conversions, and high-bit unsigned-to-signed conversions require additional evidence. Their executable outcomes are **documented_only**.
