# F-0f9e751358c3

## Purpose

F-0f9e751358c3 replaces an unsigned word at byte offset `0x48` from a supplied base address. Under the 32-bit interpretation of the supplied representation, it clears bits 9 and 10 of the existing word, then combines the remaining bits with the entire update argument using bitwise OR.

The update argument is **not masked to bits 9 and 10**. It can therefore set any bit in the resulting word. The operation acts as an isolated two-bit replacement only when the supplied update has no set bits outside those two positions.

The static evidence establishes this memory transformation. It does not establish the meaning of the word, the affected bits, or the containing storage.

## Behavior

### Word transformation

Let:

- \(W\) be the 32-bit unsigned value obtained from the target word.
- \(V\) be the 32-bit unsigned update argument.
- \(R\) be the replacement value.

The required transformation under this width interpretation is:

\[
R = (W \mathbin{\&} \texttt{0xFFFFF9FF}) \mathbin{|} V
\]

The replacement is written to the same word from which \(W\) was obtained. The function then returns without a value.

The data transformation uses only bitwise AND and OR. It performs no data-word addition, subtraction, shifting, saturation, or carry propagation. The separate calculation locating the word does include addition of the address displacement.

### Bit-level requirements

Bits are numbered from zero at the least significant position.

The mask has zeroes at bits 9 and 10 and ones at every other position within the 32-bit word. Consequently:

- Result bit 9 equals update bit 9, independently of old-word bit 9.
- Result bit 10 equals update bit 10, independently of old-word bit 10.
- Every other result bit equals the OR of the corresponding old-word and update bits.

For a bit outside positions 9 and 10, an existing one remains one. A supplied one can set an existing zero. A supplied zero cannot clear an existing one.

For positions 9 and 10, either bit can be cleared or set according to the update argument. The previous values of those two bits have no effect on the replacement.

### Update-value restrictions

No restriction to the selected two bits is enforced.

For an isolated replacement of bits 9 and 10, the update must have no set bits outside mask `0x00000600`. Under that condition, the possible update values are `0x00000000`, `0x00000200`, `0x00000400`, and `0x00000600`.

This is a condition for that particular use, not an established general precondition. Other 32-bit unsigned updates have defined results under the transformation above: their additional set bits are ORed into the target word.

A numerical upper bound alone would not describe the isolated-field condition. For example, update `0x00000001` is numerically below `0x00000600` but sets bit 0.
