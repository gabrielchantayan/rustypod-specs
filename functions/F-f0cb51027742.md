# F-f0cb51027742

## Purpose

F-f0cb51027742 performs a forward, fixed-stride transfer of two-word items from a source range to a destination position. Each word is 32 bits; each item therefore occupies 8 bytes.

For each visited source item, a non-null destination causes two words to be transferred in a specific order. The destination position advances by one item whether or not that iteration performs a transfer. The function returns the resulting destination position.

This is not an overlap-safe bulk-copy contract. Source values are obtained incrementally, and earlier destination writes can change values read by later iterations. A null destination is not established as a supported way to discard an entire nonempty range.

## Interface

The function has three pointer-valued inputs and one pointer-valued output:

| Input | Meaning |
|---|---|
| Source cursor | Address of the first two-word source item to visit. |
| Source endpoint | Address at which source traversal stops. This is an exclusive endpoint tested by equality. |
| Destination cursor | Address at which the next two-word destination item would be written, subject to the per-iteration null check. |

The returned value is the destination cursor after all completed iterations.

### Widths and layout

A word is an uninterpreted 32-bit quantity. No signed arithmetic, numerical conversion, byte swapping, or interpretation of the word contents is visible.

For an item beginning at address \(p\):

- Its first word occupies the 4 bytes beginning at \(p\).
- Its second word occupies the 4 bytes beginning at \(p+4\).
- The next item begins at \(p+8\).

Pointer width, byte order, and required alignment are not established by the supplied evidence. An 8-byte item width does not imply a 64-bit pointer representation.

### Preconditions for a fully defined transfer

For an ordinary nonempty transfer:

- The endpoint must be reachable from the initial source cursor by a finite number of forward, 8-byte advances.
- Every source word actually read must be accessible with the required alignment and access permissions.
- Every destination word actually written must be writable with the required alignment.
- The cursor advances, including the final advances, must be valid in the execution environment.
- The underlying objects must remain valid for the duration of the operation.

A source endpoint that is merely numerically greater than the initial source address is insufficient. The difference must correspond to a whole number of items, and the traversal must be valid within the applicable object and pointer model.

Overlap is not explicitly rejected. Its observable consequences are part of the behavior below, provided the particular accesses and pointer operations are otherwise valid.

## Behavior

### Termination and empty ranges

Before each iteration, the current source cursor is compared with the supplied source endpoint.

If they are equal on entry, the function:

- Reads no source item.
- Writes no destination item.
- Does not advance either cursor.
- Returns the destination input unchanged.

The destination is not inspected for nullness on this empty-range path.

There is no less-than comparison, byte-count parameter, length check, or endpoint correction. Traversal ends only when equality is reached. An endpoint behind the source cursor, or an endpoint offset by a nonmultiple of 8 bytes, does not describe a supported finite range merely because the corresponding addresses exist.

### One iteration

When the current source cursor differs from the endpoint, the current destination cursor is checked against null.

If the destination is non-null, the source-level access order is:

1. Read the second source word.
2. Retain that 32-bit value for the later second-word write.
3. Read the first source word.
4. Write that first-word value to the first destination word.
5. Write the retained second-word value to the second destination word.

The destination cursor then advances by 8 bytes. The source cursor subsequently advances by 8 bytes, after which the endpoint comparison is repeated.

If the destination is null, neither source word is read and neither destination word is written during that iteration. The same destination and source cursor advances are nevertheless reached.

The second source word is therefore captured before the first destination write. The first source word is also read before that write. The evidence does not establish an atomic 8-byte read or an atomic 8-byte write.

### Multiple iterations and returned position

For a valid range containing \(N\) items, the body is visited \(N\) times. Both cursors advance by one 8-byte item per iteration.

Where the pointer arithmetic is valid, the returned destination position is the initial destination position advanced by \(N\) items, or \(8N\) bytes.

There is no explicit integer item counter, byte-count calculation, multiplication, or arithmetic-overflow check. The expression \(8N\) describes the displacement; it is not a separately computed intermediate visible in the supplied behavior. No wrapping-address behavior should be inferred from it.

The return value is not a status code, an allocation result, or the original destination address. For a nonempty ordinary transfer, it identifies the position immediately after the destination items traversed.

### Overlap

Each iteration obtains its values from the source memory as it exists when that iteration runs. There is no whole-range snapshot and no choice of traversal direction based on overlap.

Consequently:

- Earlier destination writes can overwrite a later source item.
- Later iterations then read the modified contents.
- The retained second word protects that particular value from changes caused by the first destination write in the same iteration.
- That retention does not protect future source items.

When source and destination begin at the same valid address, each iteration still performs its reads and writes. The ordinary final word values are unchanged, but this is not a no-access shortcut.

### Null destination

The null check applies to the current destination cursor, not just the original argument.

On an iteration whose destination cursor is null, item accesses are skipped, but an 8-byte destination advance is still attempted. The function does not preserve null deliberately, return early, or remember that the original destination was null.

The evidence does not establish that advancing a null pointer is valid, what resulting pointer value the execution environment would produce, or whether subsequent accesses could be valid. Thus:

- An empty range with a null destination returns null without item access.
- A nonempty range with a null destination has no established successful-completion guarantee.
- Null must not be advertised as a general discard-output mode.

## Side effects

The visible data effects are 32-bit source reads and 32-bit destination writes on iterations with a non-null destination.

On a valid, non-overlapping, all-non-null transfer of \(N\) items, the described operation performs two word reads and two word writes per item. Source memory is not explicitly written; it can nevertheless change when destination storage overlaps it.

The function contains no explicit:

- Allocation or deallocation.
- Resource acquisition or release.
- Ownership transfer.
- Global-state access.
- Callback invocation.
- Logging, error reporting, or synchronization.

Cursor advancement changes the function’s traversal positions; no caller-held pointer object is explicitly updated through a pointer-to-pointer output.

There is no validation pass before writes begin, no rollback, and no error result. If an access fails after earlier items have been written, the supplied behavior provides no restoration mechanism. The precise failure mechanism is environment-dependent.

The access order above describes the supplied operation. It is not evidence of hardware atomicity, memory barriers, a device-I/O protocol, or a concurrency guarantee. Concurrent mutation and externally observable access behavior require execution-model information not supplied here.

## Acceptance examples

These examples are conditional on valid storage, permitted overlap, suitable alignment, and valid pointer arithmetic. Letters denote arbitrary 32-bit word values. They are specification examples, not executed tests.

### Empty range

Given equal source and endpoint pointers and any destination pointer \(D\):

- No item is read or written.
- The return value is exactly \(D\).

This includes a null destination.

### One ordinary item

Given source words \([A, B]\), an endpoint 8 bytes after the source, and a separate writable destination:

- The destination receives \([A, B]\).
- The second source word is read before the first source word.
- The first destination word is written before the second destination word.
- The return value is 8 bytes after the initial destination.

### Two non-overlapping items

Given source words \([A, B, C, D]\), an endpoint 16 bytes after the source, and a separate destination:

- The destination receives \([A, B, C, D]\).
- The first item is transferred before the second.
- The return value is 16 bytes after the initial destination.

### Identical source and destination

Given two valid items with both cursors initially at the same address:

- The final ordinary word values equal their initial values.
- The specified reads and writes still occur.
- The return value is two items after the initial destination.

An implementation that skips all accesses solely because the cursors are equal would not preserve the specified access behavior.

### Destination begins one word into the source

Given initial words \([A, B, C]\), a one-item source range beginning at the first word, and a destination beginning at the second word:

- \(B\) is retained before the destination writes.
- The first destination write replaces the original \(B\) with \(A\).
- The second destination write replaces \(C\) with the retained \(B\).
- The final words are \([A, A, B]\).

This distinguishes the operation from one that rereads the second source word after the first destination write.

### Destination begins one item into the source

Given initial words \([A, B, C, D, E, F]\), a two-item source range covering the first four words, and a destination beginning at the third word:

- The first iteration replaces \([C, D]\) with \([A, B]\).
- The second iteration reads that modified item.
- The final words are \([A, B, A, B, A, B]\).

A whole-range snapshot yielding \([A, B, A, B, C, D]\) would not match this behavior.
