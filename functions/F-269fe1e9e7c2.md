# F-269fe1e9e7c2

## Purpose

F-269fe1e9e7c2 selects one of two records embedded in a context object, acquires an associated resource, and checks two prerequisite words. A subsequently read mode byte selects either normal processing or an alternate sequence involving provider operations, optional output construction, and record-field resets.

The function returns 0 on its explicit success paths. Selection, acquisition, prerequisite, and most alternate-operation failures produce 3. Alternate status 2 produces 5. Nonzero results from the normal-processing dependencies can instead be returned unchanged.

“Acquisition,” “release,” “setup,” and “restoration” describe inferred roles. The available static evidence establishes calls and control flow, not the dependencies’ synchronization or ownership semantics.

## Interface

### Inputs and validity requirements

The function receives two values represented as 32-bit addresses:

- **Context address:** identifies storage containing embedded records, a provider reference, a resource-manager word, and a mode byte.
- **Request address:** identifies an object whose dispatch interface supplies a selector and which is later passed to an output-storage dependency.

Neither address is explicitly checked for nullness, alignment, accessibility, or sufficient extent. Any reached indirect call requires valid object and dispatch-table storage. Output construction requires the resulting output address to support four consecutive 32-bit stores. Invalid storage and indirect-call targets have no defined recovery behavior in this function.

### Context layout

Offsets below are byte offsets from the context address.

| Offset | Width or form | Established use |
|---|---|---|
| 0x61c | 32-bit address | Provider reference used for indirect calls |
| 0x624 | 32-bit word | First argument to acquisition and release dependencies |
| 0x628 | Embedded record | Selected by selector byte 1 |
| 0x648 | Embedded record | Selected by selector byte 0, subject to an initial mode check |
| 0x6a9 | 8-bit value | Selection restriction and subsequent processing-mode choice |
| 0x6ac | Embedded storage address | Second argument for secondary acquisition and release |

Each selected record has these relevant fields:

| Record-relative offset | Width or form | Established use |
|---|---|---|
| +0x04 | Embedded storage address | Second argument for initial acquisition and failure-path release |
| +0x0c | 32-bit word | Signed comparison operand, normal-processing argument, alternate-path reset target |
| +0x10 | 32-bit word | Signed comparison operand and alternate-path reset target |
| +0x14 | 32-bit word | Nonzero prerequisite, provider input, output-record source |
| +0x18 | 32-bit word | Nonzero prerequisite and provider input |

No direct use of the selected record’s first word is established.

### Request and provider interfaces

The request’s first 32-bit word identifies a dispatch table. Its entry at byte offset +0x08 receives the request address and the address of a four-byte selector buffer. The function does not explicitly initialize that buffer or inspect a callback return value. Only its first byte is subsequently read.

The provider reference identifies an object whose first word supplies a dispatch table. Three byte offsets are used:

| Dispatch offset | Arguments after the provider address | Result use |
|---|---|---|
| +0x30 | Address of one local 32-bit output slot | Unsigned 32-bit status |
| +0x28 | Two record words and addresses of two local 32-bit output slots | Unsigned 32-bit status |
| +0x34 | One mode-derived 32-bit argument | Unsigned 32-bit status |

The output slot passed to +0x30 is reused as the second output slot passed to +0x28. Its initialization and contents depend on those calls; the caller does not explicitly clear it between them.

### Return representation

The return is a 32-bit value. The fixed results 0, 3, and 5 have the meanings described below. Propagated normal-path results retain their 32-bit values; their complete status domain and signed semantic interpretation are unknown.

Address offsets are byte displacements. No overflow, range, or alignment checks are visible. The contract does not assign meaningful behavior to address calculations that fail to identify valid storage.

## Behavior

### Selector acquisition and record selection

The request selector callback occurs before any explicit context-mode read or resource acquisition.

- First selector byte **0**: read context +0x6a9. If nonzero, return 3. Otherwise select context +0x648.
- First selector byte **1**: select context +0x628 without that initial mode check.
- Any other first byte: return 3.

The remaining selector-buffer bytes have no observed effect. The selected record address is fixed for the remainder of the invocation; later mode changes do not select a different record.

### Initial acquisition and prerequisite checks

Call F-f0216cff9365 with the current word at context +0x624 and the address selected-record +0x04.

A nonzero result causes an immediate return of 3, without a corresponding release call.

After a zero result, test selected-record +0x14 for nonzero. Read and test +0x18 only if +0x14 passed. Both must be nonzero to proceed. These are zero/nonzero checks: a word with its high bit set is not rejected merely because its signed interpretation is negative.

If either prerequisite fails, call F-2bb3dbfa7286 with the then-current context +0x624 word and selected-record +0x04, then return 3.

### Processing-mode read

After both prerequisites pass, read context +0x6a9:

- Zero selects normal processing.
- Any nonzero byte selects alternate processing.

For selector 0, this is a separate read from the selection-time check. Dependencies or concurrent actors may have changed the mode between the reads. There is no established synchronization guarantee requiring them to agree.

### Normal processing

Compare selected-record +0x10 with selected-record +0x0c using a **signed 32-bit less-than-or-equal comparison**.

If the comparison is false, omit preliminary processing.

If true, attempt secondary acquisition through F-f0216cff9365, using the current context +0x624 word and context +0x6ac:

- Nonzero acquisition result: omit preliminary processing and continue to the main normal-processing call.
- Zero acquisition result: call F-336170d53b85 with the context and selected record, then call F-2bb3dbfa7286 with the then-current context +0x624 word and context +0x6ac.

If F-336170d53b85 returned nonzero, release the selected-record resource through F-2bb3dbfa7286 and return that result unchanged. The secondary release precedes the selected-record release. Do not call the main normal-processing dependency on this path.

Otherwise, call F-08aceac14924 with:

1. Context address.
2. Selected-record address.
3. The then-current word at selected-record +0x0c.
4. Request address.

The third argument is read after any preliminary-processing sequence; it need not match the earlier comparison operand.

If F-08aceac14924 returns zero, return 0 without an explicit selected-record release. For a nonzero result, release the selected-record resource using the then-current context +0x624 word, then return that result unchanged.

### Alternate processing: mode and acquisition

Derive a 32-bit argument from the processing-mode byte already read:

| Mode byte | Derived argument |
|---|---:|
| 1 | 0 |
| 2 | 1 |
| Any other nonzero byte | 2 |

Later mode changes do not recompute this argument.

Attempt secondary acquisition through F-f0216cff9365 using the current context +0x624 word and context +0x6ac.

If acquisition fails, set the alternate status to 3 and proceed to the record resets. There are no provider, setup, restoration, or secondary-release calls on this failure path.

### Alternate processing: setup and separate global reads

After successful secondary acquisition, the established order is:

1. Call F-fe0b01a098f9.
2. Read a 32-bit global word and save that value for restoration.
3. Independently read the same global word again for the setup call’s second argument.
4. Call F-1a5cca324bde with the first dependency’s result, the value from the **second global read**, 0, and 0.
5. Invoke provider dispatch +0x30.

The saved restoration value and the setup argument are not established to be equal. If the global changes between the two reads, setup receives the later value while restoration receives the earlier saved value. Restoration does not reread this global.

The setup call’s result does not select a branch or determine the alternate status.

### Alternate processing: provider sequence and output

Load the provider through context +0x61c and invoke dispatch +0x30, passing the address of a local 32-bit output slot.

Interpret its result as unsigned 32-bit status. Only status 0 permits dispatch +0x28. Any other result skips output construction and the final provider operation.

For status 0:

1. Initialize a local output-storage handle to the 32-bit address value 2.
2. Obtain the provider reference again from context +0x61c.
3. Invoke dispatch +0x28 with the current selected-record words at +0x14 and +0x18 and addresses of two local 32-bit outputs.

The second output slot is the slot previously passed to +0x30. The first output slot has no explicit initialization before +0x28.

Interpret the +0x28 result as unsigned:

- **4:** replace the status with 3; omit output construction and dispatch +0x34.
- **0 or 1:** construct output as described next.
- **Any other value:** retain that status; omit output construction and dispatch +0x34.

For status 0 or 1, call F-e2669f32f0eb with the request address and the address of the output-storage handle. Its return value is not checked. Through the resulting handle, perform these four 32-bit stores in order:

| Output byte offset | Stored value |
|---|---|
| +0x00 | Then-current selected-record +0x14 |
| +0x04 | First local output slot passed to +0x28 |
| +0x08 | Second local output slot passed to +0x28 |
| +0x0c | 1 |

The output occupies 16 bytes. No address, capacity, or alignment check intervenes before these stores.

The first output word is read after F-e2669f32f0eb returns. It therefore need not equal the earlier +0x14 value supplied to provider dispatch +0x28.

If +0x28 returned 0, obtain the provider reference again and invoke dispatch +0x34 with the derived mode argument. Its return becomes the alternate status.

If +0x28 returned 1, omit +0x34 and retain status 1, despite having written the output record.

### Alternate processing: restoration, resets, and return

After every provider sequence reached through successful secondary acquisition, including sequences stopped by a nonzero provider status:

1. Call F-fe0b01a098f9 again.
2. Call F-ec845e376fce with that second call’s result, the value saved from the **first global read**, and the 32-bit argument 250.
3. Call F-2bb3dbfa7286 with the then-current context +0x624 word and context +0x6ac.

These calls do not replace the selected alternate status.

After either secondary-acquisition outcome, perform these explicit stores in order:

1. Store 0xffffffff at selected-record +0x10.
2. Store 0 at selected-record +0x0c.

Then map the alternate status:

| Alternate status | Selected-record release | Return |
|---|---|---:|
| 0 | No explicit release | 0 |
| 2 | F-2bb3dbfa7286 | 5 |
| Any other value | F-2bb3dbfa7286 | 3 |

The selected-record release uses the then-current context +0x624 word and selected-record +0x04. Its result is ignored.

The reset stores precede this release on nonzero-status paths. Because the release dependency’s effects are unknown, those stores do **not** guarantee the record’s final contents after return.

## Side effects

### Explicit writes and their limits

The function explicitly initializes the output-storage handle, conditionally writes the four-word output record, and writes the two alternate-path reset fields. Dependencies also receive writable local-storage addresses.

There is no explicit normal-path store to the reset fields. Dependencies may nevertheless modify them.

There is no explicit rollback of output construction or of the reset stores. This is not a guarantee of persistence:

- Provider dispatch +0x34, restoration calls, and release calls may run after output construction.
- Output storage may alias context or record storage; alias restrictions are unknown.
- Alternate reset stores may themselves overwrite aliased output.
- A selected-record release after the reset stores may modify the record or aliased output.

Final output or field contents are therefore conditional on subsequent operations not overwriting them. For alternate status 0, no further dependency call is shown after the two reset stores, but output aliasing still matters.

### Re-reads and ordering

Context +0x624 is read for each acquisition and release call rather than retained for the invocation.

Provider references are obtained again for successive provider operations. Intervening dependencies may change the context, so successive operations are not guaranteed to use the same provider.

The two setup-stage global reads are separate and ordered: first save the restoration value, then read the setup argument. Their values may differ. Restoration uses the saved value, not a later global read.

The two F-fe0b01a098f9 calls are distinct; their results need not match. Within a call’s argument preparation, no additional total ordering of independent reads is established.

### Ownership

After successful initial acquisition, shown nonzero-return paths explicitly release the selected-record resource. Both success paths return without that explicit release.

This establishes neither a leak nor an ownership transfer. Dependencies may release, retain, or transfer resources, but their behavior is unavailable.

F-e2669f32f0eb receives an in/out address handle. Allocation, capacity, ownership, retention, and disposal of the resulting storage are unknown. This function performs no explicit deallocation.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Assume valid storage and normally returning dependencies. State-content expectations additionally require that later calls and aliased stores do not overwrite the relevant storage.

1. **Unsupported selector:** First selector byte 2 produces return 3 without an acquisition call.

2. **Selector 0 rejected:** Selector 0 and a nonzero initial mode produce return 3 before acquisition.

3. **Mode changes after selection:** Selector 0 initially observes mode 0 and selects context +0x648. If the later processing-mode read observes 2, alternate processing uses that same record and derives provider argument 1.

4. **Initial acquisition failure:** Nonzero initial acquisition produces return 3 without a matching release.

5. **First prerequisite missing:** With +0x14 equal to zero, do not read +0x18 for the prerequisite check. Release the selected-record resource and return 3.

6. **Signed comparison:** In normal mode, +0x10 equal to 0xffffffff and +0x0c equal to zero satisfies the comparison and triggers secondary acquisition.

7. **Normal secondary acquisition fails:** Omit F-336170d53b85 but still call F-08aceac14924. Its result determines the normal return path.

8. **Preliminary error:** If F-336170d53b85 returns 7, release secondary storage, release selected-record storage, and return 7 without main normal processing.

9. **Normal success:** A zero result from F-08aceac14924 returns 0 without an explicit selected-record release.

10. **Different global observations:** If the first setup-stage global read observes 10 and the second observes 20, F-1a5cca324bde receives 20 as its second argument; F-ec845e376fce later receives the saved 10. No equality is required.

11. **Alternate secondary acquisition fails:** Skip setup and provider calls. Store 0xffffffff at +0x10, then zero at +0x0c; release selected-record storage and return 3. Final field contents depend on that release’s effects.

12. **Initial provider status 2:** Omit +0x28 and output construction. Perform restoration, secondary release, resets, and selected-record release; return 5.

13. **Provider +0x28 status 1:** Write the output record, omit +0x34, perform restoration and releases with the intervening reset stores, and return 3. Output persistence is conditional.

14. **Output followed by status 2:** If +0x28 returns 0 and +0x34 returns 2, output construction precedes the failure return 5. There is no explicit rollback, but subsequent calls or aliasing may overwrite the output.

15. **Alternate success:** With mode 2 and all three provider statuses zero, +0x34 receives 1. After restoration, secondary release, and reset stores, return 0 without an explicit selected-record release.

16. **Release modifies reset fields:** On an alternate failure path, a selected-record release that changes +0x0c after the reset is consistent with the available evidence. The contract requires the preceding zero store, not a final zero value.
