# F-252d022adf90

## Purpose

F-252d022adf90 performs a fixed sequence of six memory writes, using address calculations derived from two incoming machine-state values and several indirect memory reads. It then enters a nonterminating loop that repeatedly requests a coprocessor transfer.

The supplied representation establishes these operations but not their application-level purpose. It does not establish that the writes initialize an object, acknowledge an interrupt, release a resource, or implement a particular device protocol.

The apparent interface has no explicit arguments and no returned value. Its actual inputs include incoming register state, memory contents, and two coprocessor-related values.

The source data includes warnings about invalid instruction data, removed unreachable regions, and overlapping global symbols. Accordingly, this contract distinguishes the behavior represented by the supplied body from claims about the original executable. No runtime tests have been performed.

## Behavior

### 1. Copy a low byte within seed-relative memory

The function first reads a 32-bit value from the address seed plus 100 bytes.

It then writes the low eight bits of that loaded value to the address seed plus 3 bytes.

The operation is a 32-bit read followed by an 8-bit write. It is not established as a byte read from a fixed position within the four-byte source: that physical position depends on byte order.

### 2. Clear a byte through an index-derived pointer

The function retains the low 22 bits of the index seed, multiplies that unsigned value by 16, and adds 60 bytes. It reads a 32-bit pointer value from the resulting address.

It then writes a zero byte at that loaded pointer plus 2 bytes.

The pointer-location calculation ranges from hexadecimal `0x0000003C` through `0x0400002C`. That calculation does not overflow 32 bits. Adding 2 to the loaded pointer can wrap in the represented 32-bit address model.

No pointee type, allocation size, ownership relationship, or validity check is established.

### 3. Clear a word through a fixed-address pointer

The function next reads a 32-bit pointer value from absolute address hexadecimal `0x00000060`.

It writes a 32-bit zero value at that pointer plus 44 bytes.

This pointer is read at this point in the sequence. It is not a cached value established before the earlier writes. If an earlier write overlaps its storage, the new contents affect this step.

The overlapping-global warning prevents stronger conclusions about the identity or layout of the data at the fixed address.

### 4. Store a seed-derived byte at a scaled address

The function multiplies the address seed by 1024, retaining the resulting 32-bit address.

At that address, it writes the low eight bits of the original address seed.

This is a one-byte store. It does not write the full seed, clear the surrounding memory, or establish the size of any object at the destination.

### 5. Perform two indirect reads and write a derived byte

The function forms an intermediate address by adding 158 bytes to the scaled address from the preceding step.

It then obtains another destination through two 32-bit reads:

1. Retain the low 22 bits of the address seed, shift that unsigned value right by two bits, and add 104 bytes.
2. Read a 32-bit pointer at that location.
3. Add 96 bytes to the loaded pointer.
4. Read a 32-bit unsigned value at that second location.
5. Shift the second loaded value right by two bits and add 4 bytes.

At the final address, the function writes the low eight bits of the intermediate address.

The first pointer-read address ranges from hexadecimal `0x00000068` through `0x00100067`. There is no visible alignment adjustment. Some seed values therefore produce an address unsuitable for a 32-bit load on an environment requiring aligned access.

The final destination ranges from hexadecimal `0x00000004` through `0x40000003`, because its input is an unsigned 32-bit value shifted right by two before adding four.

The stored byte is always hexadecimal `0x9E` under the represented arithmetic. Multiplication by 1024 clears the low ten bits; adding 158 fixes the low byte to 158. This is an arithmetic consequence, not evidence that the byte is a protocol constant.

### 6. Clear a byte at a second scaled address

The function multiplies the intermediate address by 1024 using the represented 32-bit address arithmetic.

It writes a zero byte at that result minus 94 bytes.

The destination is calculated directly. No pointer is loaded from the intermediate address.

For subsequent loop behavior, the function also forms the same second scaled result minus 104 bytes. That value is not a memory read.

### 7. Repeat a coprocessor transfer indefinitely

On the first loop iteration, the function logically shifts the value formed by subtracting 104 right by 11 bits. That shifted result becomes the varying operand of a coprocessor-transfer operation.

Before issuing that operation, the loop replaces its working value with zero.

The represented transfer uses:

- Fixed selector values 8, 5, and 4.
- The shifted operand just described.
- The two incoming coprocessor-related values.

On every subsequent iteration, the shifted operand is zero.

There is no visible loop exit or normal return. Continued repetition is conditional on the transfer operation completing and execution continuing. The supplied representation does not establish whether the operation can trap, block, stop the processor, or otherwise prevent a later iteration.

## Side effects

### Observable access order

For valid, ordinarily behaving memory, the visible sequence is:

1. Read one 32-bit seed-relative value.
2. Write one seed-relative byte.
3. Read one index-derived 32-bit pointer.
4. Write one zero byte through that pointer.
5. Read one 32-bit pointer from absolute address `0x00000060`.
6. Write one zero 32-bit word through that pointer.
7. Write one byte at the first scaled address.
8. Read the first pointer in the second indirection chain.
9. Read the second 32-bit value in that chain.
10. Write byte `0x9E` to the derived destination.
11. Write one zero byte at the second scaled destination.
12. Repeatedly request the coprocessor transfer.

This comprises five visible 32-bit memory reads and six visible memory writes before the loop.

Address calculations alone do not introduce additional memory reads.

### Aliasing

The contract does not require the accessed locations to be disjoint.

Earlier writes may alter later pointer values or later loaded data if their storage overlaps. For example, the first byte write can modify part of a pointer read later in the sequence. The later read then uses the modified contents.

The sequence must therefore not be interpreted as first collecting all pointer values and then performing all writes.

A failed access can occur after earlier writes have completed. No rollback or transactional behavior is visible.

### Ownership and lifetime

There is no visible allocation, deallocation, reference-count update, or ownership transfer. Writing through a pointer does not establish ownership of the referenced storage.

The coprocessor primitive’s effects on memory, global state, or resource lifetime are unknown. No preservation or ownership guarantee is supplied for it.

## Acceptance examples

These examples are conditional consequences of the represented behavior, not executed tests.

### Low-byte copy

If the first 32-bit read returns hexadecimal `0x123456AB`, and the destination is writable, the first byte write stores hexadecimal `0xAB`.

This does not determine which physical source byte held `0xAB` without a byte-order definition.

### Index masking

If two index seeds differ only in their upper ten bits, they select the same pointer-read address in step 2.

If the selected memory contents and prior effects are otherwise identical, the step-2 destination is identical.

### Pointer values affected by earlier writes

If the first byte-write destination overlaps a byte of the pointer read in step 2, step 2 uses the pointer value after that byte modification.

A model that always uses the pointer’s entry-time value would not match the represented order.

### Fixed byte in the second indirection chain

If both indirect reads in step 5 succeed and the destination is writable, the written byte is `0x9E`, regardless of the address seed.

The destination can still vary with the address seed and loaded memory values.

### Zero address seed

With a zero address seed, and assuming all accesses complete:

- The first source read is at address 100.
- The first byte destination is address 3.
- The first scaled-address byte store targets address 0 and writes zero.
- The first pointer read in step 5 is at address 104.
- The final zero-byte destination is hexadecimal `0x000277A2`.
- The first shifted coprocessor operand is hexadecimal `0x4E`.
- Later shifted operands are zero.

These addresses are arithmetic results, not assertions that low memory is accessible.

### Access failure

If the 32-bit pointer read at absolute address `0x00000060` faults, the earlier writes may already have occurred. No visible local recovery, rollback, or error return is specified.

### Continued loop execution

If all memory accesses and every coprocessor transfer complete normally, execution does not return. Only the first transfer can receive a nonzero shifted operand; all later transfers receive zero for that operand.
