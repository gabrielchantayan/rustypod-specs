# F-10b0ba679df5

## Purpose

The supplied static representation describes an ordered sequence of memory accesses with a sign-dependent termination point and a final abnormal-termination marker. It does not establish an application-level purpose, a valid object model, or a normal successful return.

The contract is therefore conditional: it describes the represented accesses and their dependencies if execution reaches them and the target permits them. Invalid-instruction warnings, overlapping global storage, missing implicit-input initialization, and two shifts by the represented operand width prevent an unconditional executable interpretation.

Two function identities, **F-e47d7b2e9c88** and **F-8afdaab91693**, are used numerically. Neither has a visible invocation.

**Evidence status:** static analysis only. No runtime tests have been performed.

## Behavior

The following order is the order displayed by the static representation. It does not prove executable reachability.

### 1. Capture initial globals and derive the selector

The routine first reads the early context address from global storage, then reads the table base from another global location.

The **selector** is the first input shifted right by 23 as a signed 32-bit value, then retained as an unsigned 32-bit value. If signed right shift is arithmetic, the signed result lies between −256 and 255. A negative result becomes a large unsigned value; this is not an unsigned nine-bit extraction.

Before the table lookup, the routine writes the low 16 bits of the second input to the address obtained by adding the full second input to the implicit register-held base. This write can affect subsequent reads through aliasing.

### 2. Perform the initial linked accesses

The **lookup displacement** is the selector combined with `0x88` by bitwise OR, not addition.

The represented access order is:

1. Read a word from the captured table base plus the lookup displacement.
2. Read an unsigned byte from the implicit register-held base plus that displacement.
3. Write the table word at offset 8 from the fourth input.
4. Write the fourth input as a word at selector plus `0x40`.
5. Write the table word at offset `0x74` from the captured early context address.
6. Read a word at offset `0x28` from the fourth input.
7. Read four opaque bytes at offset `0x5C` from the early context address.
8. Write the low byte of the early context address at offset 3 from the table word interpreted as an address.
9. Write the previously read byte at early-context offset `0x10`.
10. Write the low byte of the opaque four-byte value to the address equal to the previously read unsigned byte plus `0x1C`.

The final destination is numerically between `0x1C` and `0x11B`. It is not obtained by dereferencing that byte as a pointer.

The two initial global values are captured before these writes. Later references to those captured values are not fresh reads of their original globals.

### 3. Initialize derived storage

Several quantities are derived:

- A **difference**, equal to selector minus `0x38`.
- A **masked difference**, equal to selector minus `0xE0`, with bit 31 cleared.
- A **halved quantity**, equal to the masked difference shifted right by one. Its range is zero through `0x3FFFFFFF`.
- A **halfword-region address**, equal to twice the result of selector minus `0xE0`, at the represented unsigned width.

Another address is formed from the word read at fourth-input offset `0x28`: that signed word is shifted left by two and then right by 32. This address is **unresolved**. Both the signed left shift and the width-sized right shift require target semantics.

The following accesses then appear:

1. Write the low byte of the halved quantity at the captured fourth-input word plus `0x0897E8B8`.
2. Assign `0xB8` to a global cell of unestablished width.
3. Write the low byte of the difference at selector minus `0x32`.
4. Write the full difference as a word through the unresolved address.
5. Write halfword `0xFFFF` at halfword-region offsets 4 and 6, in that order.
6. Write byte `0xB8` at offset 4 from the unresolved address.
7. Write halfword `0xFFFF` at halfword-region offset 2.
8. Assign the low 16 bits of the halfword-region address to another global cell.
9. Read the unsigned halfword at the start of the halfword region.
10. Use its zero-extended value as the destination address for a word containing the difference AND `0x897E8B80`.

The first halfword of the region is not directly initialized by the listed halfword writes. Earlier writes can nevertheless alter it through aliasing.

### 4. Use F-e47d7b2e9c88 numerically and branch

The numeric value associated with **F-e47d7b2e9c88** supplies:

- A signed sign test.
- A derived address obtained by signed right shift by 32.
- A halfword obtained by signed right shift by 31 and truncation.

The derived address remains unresolved. With arithmetic signed right shift, the halfword is zero for a nonnegative function value and `0xFFFF` for a negative value.

The routine writes this halfword at derived-address offset 4 **before** testing the sign.

If the function value is negative as signed 32 bits, the displayed path ends at a bad-instruction termination marker. No later accesses are represented on that path.

For a nonnegative value, the continuation performs:

1. A halfword write at derived-address offset `0x12`.
2. A word write storing the function value at the address numerically equal to that value.
3. A signed-halfword read at the derived address plus the halved quantity.
4. Another halfword write at offset `0x12`.
5. Another self-addressed word write of the function value.
6. A word write at derived-address offset 8 containing the signed halfword promoted to signed 32 bits and shifted right by 16.

With arithmetic right shift, the final word is zero or `0xFFFFFFFF`, according to the sign of the read halfword.

Both repeated writes belong to the represented trace. Their repetition is not removable without additional memory and observability guarantees.

### 5. Update global, low-address, and stack-derived storage

The continuation clears a global cell, then derives a **small value** by taking bit 2 of the function value and adding `0x58`. The result is `0x58` or `0x5C`.

The routine then:

- Writes the unresolved derived address as a word at `0x5C` or `0x60`, respectively.
- Assigns the masked difference shifted right by 17 and converted to 16 bits to a global slot.
- Assigns the low byte of the halved quantity, zero-extended to 16 bits, to another global slot.
- Writes the full halved quantity at `0x170` or `0x180`, respectively.
- Assigns the halved quantity to another global cell.

The incoming stack-derived pointer receives these writes in order:

1. A halfword containing the small value.
2. A word containing the unresolved derived address shifted left by eight.
3. The same word at pointer offset 20.
4. A word containing the pointer’s own numeric address.

A word is then read from twice the incoming pointer’s numeric address. Its low halfword is written through the incoming pointer, followed by a full-word write of the read value to the address numerically equal to that value.

Next, a word is written to an address formed from **the address of the incoming stack slot**, multiplied by 32 and increased by `0x18`. The stored value is the incoming pointer interpreted as signed 32 bits and shifted right by 31. The slot address and the pointer held there must not be conflated.

A subsequent global assignment concatenates the 16-bit value 5 above a freshly referenced byte of overlapping global storage. The concatenation expression contains 24 bits; the destination’s exact width and treatment of neighboring bytes are not established.

Finally, the incoming pointer is written as a 32-bit pointer value at four times its numeric address plus `0x18`.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Selector boundary.** With arithmetic signed right shift, first input `0x007FFFFF` produces selector zero; `0x00800000` produces selector one. Their lookup displacements are `0x88` and `0x89`.

2. **Negative selector.** Under the same rule, first input −1 produces unsigned selector `0xFFFFFFFF`, not `0x1FF`.

3. **Full displacement, truncated value.** Second input `0x00012345` supplies the full displacement for the initial address calculation but stores halfword `0x2345`.

4. **Early aliasing.** If the initial halfword write overlaps the following table read, the table read occurs after that write. Its value depends on byte order and the resulting bytes, not on an entry snapshot.

5. **Negative function value.** If F-e47d7b2e9c88 is negative as signed 32 bits and the branch is reached, the derived-address offset-4 halfword write precedes termination. The nonnegative continuation is absent.

6. **Repeated writes.** On the nonnegative path, both offset-`0x12` halfword writes and both self-addressed function-value word writes remain observable operations where the memory model exposes them.

7. **Stack-pointer ordering.** The incoming pointer’s initial halfword write precedes its first word overwrite. The read from twice its numeric address follows the self-pointer word write.

8. **Scaled-pointer global unchanged.** If no intervening effect changes the scaled-pointer global, the offset-4 destination is the originally assigned scaled pointer plus four.

9. **Scaled-pointer global changed.** If the self-addressed word write changes that global from its initially assigned value to another address-like value, the subsequent offset-4 write uses the new value plus four. A model that always uses the original scaled pointer is incompatible with the represented reads.

10. **Late upper-halfword read.** If the upper-halfword global initially receives `0x1234` but an intervening write changes it to `0xABCD`, the final concatenation is `0xABCDEA70`, assuming execution reaches that assignment and the change persists until its read.

11. **Unresolved shifts.** A model must not assign zero, sign fill, or an unchanged operand to either shift-by-32 result without additional target evidence.
