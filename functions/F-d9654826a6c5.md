# F-d9654826a6c5

## Purpose

F-d9654826a6c5 coordinates up to three synchronous dependency calls using a context object and a request object:

1. A conditional preliminary call when the request identifies a particular address inside the context.
2. A mandatory dispatch call, unless the preliminary call returned nonzero.
3. A conditional final call when the request identifies an address stored in the context.

The first nonzero dependency result is returned unchanged. If every dependency actually invoked returns zero, the function returns zero.

The established behavior is dispatch and result propagation. The meanings of the request discriminators, the nested discriminator, the context fields, and the dependency results are not established. In particular, zero and nonzero must not be assigned application-level meanings such as “success,” “failure,” or “handled” without additional evidence.

## Interface

### Inputs

The function receives two addresses:

- **Context address:** the base of a context object containing a dispatch-table address, an address-valued field, and an interior location used for identity comparison.
- **Request address:** the base of a request object containing a discriminator and, for particular discriminator values, an address-valued payload.

Both arguments are forwarded unchanged to every dependency invoked by this function. Neither argument is replaced with the payload address or the interior context address.

### Widths and relevant layout

The supplied representation uses four-byte integer words. Address values are carried through those words, supporting a 32-bit address model for this contract. These observations do not establish a portable 64-bit interface.

Only the following locations are relevant to this function:

| Object | Byte offset | Role |
|---|---:|---|
| Context | 0 | Address of a dispatch table |
| Context | 80, or 0x50 | Address value used in the final identity comparison |
| Context | 176, or 0xB0 | Interior address used in the preliminary identity comparison |
| Request | 4 | Four-byte discriminator |
| Request | 8 | Address-valued payload, read on particular paths |
| Nested object addressed by the request payload | 4 | Four-byte nested discriminator |
| Dispatch table | 224, or 0xE0 | Final-call function-address slot |
| Dispatch table | 268, or 0x10C | Special-dispatch function-address slot |
| Dispatch table | 272, or 0x110 | Default-dispatch function-address slot |

The preliminary comparison uses the **address at context base plus 176 bytes**. It does not read the contents at that location.

The final comparison instead reads the **address value stored at context base plus 80 bytes**. These are distinct operations and distinct locations.

The function does not directly inspect the request’s first word at byte offset zero.

### Output

The output is a four-byte integer:

- An invoked dependency’s nonzero result, propagated without translation; or
- Zero when all invoked dependencies return zero.

Negative and positive nonzero results are treated alike for control flow. No result range is reserved or interpreted by this function.

### Preconditions

All storage, address values, and function targets actually used along the selected path must be valid for their corresponding operations. The function performs no explicit null, bounds, alignment, lifetime, or callable-target checks.

Requirements are path-dependent. For example:

- Reading the nested discriminator is required only when the current request discriminator equals 22.
- Reading the context field at byte offset 80 is required only when the post-dispatch request discriminator equals 15.
- Reading the final-call table slot is required only after the final identity comparison succeeds.
- An early nonzero preliminary result bypasses every later access.

Dependencies may impose additional preconditions that are not available here.

## Behavior

### 1. Preliminary identity check

The function first reads the request discriminator at byte offset 4.

If that value is not 15, it does not read the request payload for this check and does not invoke the preliminary dependency.

If the value is 15, it reads the request payload at byte offset 8 and compares that address value with the context’s interior address at byte offset 176.

This is address equality, not a comparison of the contents of two objects. The payload is not dereferenced during this check.

When both conditions hold, the function invokes F-3718c422eac3 with the original context and request arguments.

- A nonzero result is returned immediately.
- A zero result permits processing to continue.

A zero result does not imply that either object, the dispatch table, or any other state remains unchanged. The next stage reads the request discriminator again.

### 2. Main dispatch selection

The function reads the request discriminator at byte offset 4 after the preliminary stage has completed.

If the current value is 22:

1. It reads the payload address at request byte offset 8.
2. It reads the nested discriminator four bytes beyond that payload address.
3. It selects the special dispatch slot if the nested discriminator equals 42; otherwise it selects the default dispatch slot.

If the current request discriminator is anything other than 22, the function selects the default dispatch slot without reading the nested object.

The selected slot is:

- Dispatch-table byte offset 268 when the current request discriminator is 22 and the nested discriminator is 42.
- Dispatch-table byte offset 272 in every other case.

After making that selection, the function reads the dispatch-table address from context byte offset zero and obtains the selected function address from that table.

It invokes the selected dependency with the original context and request arguments.

This call occurs on every path that did not already return a nonzero preliminary result.

- A nonzero result is returned immediately.
- A zero result permits the final stage to run.

The function does not attempt the other main-dispatch slot after the selected dependency returns zero. Zero advances to the final identity check; it is not a request to retry main dispatch.

### 3. Final identity check

After a zero main-dispatch result, the function reads the request discriminator again.

If its current value is not 15, the function returns zero without reading the request payload for this check or the context field at byte offset 80.

If its current value is 15, the function:

1. Reads the payload address at request byte offset 8.
2. Reads the address value stored at context byte offset 80.
3. Compares those two address values.

The comparison does not dereference either compared address.

If the addresses differ, the function returns zero.

If they are equal, the function reads the dispatch-table address from context byte offset zero, obtains the function address at table byte offset 224, and invokes that dependency with the original arguments.

- A nonzero result is returned unchanged.
- A zero result leads to a zero return.

There is no further dispatch or identity check after this call.

### Mutation-sensitive sequencing

The three stages do not operate on a single immutable snapshot.

In particular:

- A zero-returning preliminary dependency may change which main-dispatch slot is selected.
- The main dependency may change whether the final dependency is invoked.
- The main dependency may replace the context’s dispatch-table address, affecting the final call.
- Changes to the request payload or the context field at byte offset 80 may affect the final identity comparison.

The supplied body explicitly performs later reads rather than retaining the initial discriminator or the initial table address across all stages.

These statements describe synchronous dependency effects. They do not establish thread safety, atomicity, volatile-access semantics, or defined behavior under unsynchronized concurrent mutation.

No explicit overflow handling is present. Valid address formation and valid dereferences are caller and dependency obligations on the paths where they occur; this contract does not define wrapping-address behavior.

## Acceptance examples

These are conditional acceptance criteria derived from the supplied representation. They are not reports of executed tests. Each example assumes valid storage and callable targets for every reached operation.

### Preliminary result terminates processing

Given an initial discriminator of 15 and a payload equal to context base plus 176 bytes, F-3718c422eac3 is invoked.

If it returns −7, the function returns −7. Neither main-dispatch dependency nor the final dependency is invoked.

### Special main dispatch

Given a main-dispatch discriminator of 22 and a payload addressing a nested object whose discriminator at byte offset 4 is 42, F-dynamic-A is selected.

If it returns 9, the function returns 9 without performing the final identity check.

The nested object’s word at byte offset zero does not affect this selection.

### Nested mismatch uses default dispatch

Given a main-dispatch discriminator of 22 and a nested discriminator other than 42, F-dynamic-B is selected.

The nested discriminator is read even though its value ultimately selects the default slot.

### Other discriminators do not require nested storage

Given a main-dispatch discriminator other than 22, F-dynamic-B is selected without dereferencing the payload as a nested object.

This does not make the entire invocation valid automatically: dependencies may still use the payload, and a later discriminator of 15 causes a payload read during the final check.

### Preliminary mutation changes dispatch

Given that the preliminary identity condition holds, suppose F-3718c422eac3 changes the request discriminator to 22, installs a payload whose nested discriminator is 42, and returns zero.

The next stage selects F-dynamic-A from the current request state. It does not dispatch using the initial discriminator of 15.

### Main mutation enables the final call

Suppose the selected main dependency changes the request discriminator to 15, sets the payload equal to the address then stored at context byte offset 80, and returns zero.

F-dynamic-C is invoked. If it returns 6, the overall result is 6.

### Main mutation replaces the final table

Suppose the selected main dependency returns zero after replacing the context’s dispatch-table address and arranging a successful final identity comparison.

The final function address is read from byte offset 224 of the replacement table, not from a table address retained before the main call.

### All three calls can occur

Given a successful preliminary identity comparison, a zero preliminary result, a zero main result, and a successful final identity comparison, all three stages invoke dependencies.

If the final dependency also returns zero, the function returns zero. The two identity comparisons are not mutually exclusive.

### Equal null address values can satisfy the final comparison

If the post-dispatch discriminator is 15 and both the request payload and the address stored at context byte offset 80 are zero, their equality satisfies the final comparison.

The compared addresses are not dereferenced by that comparison. Whether F-dynamic-C accepts such state is unknown.
