# F-313c9c2b5f6d

## Purpose

F-313c9c2b5f6d performs two memory reads, selects a sequence of memory writes according to whether its second argument is zero, and returns its fifth argument unchanged on normal completion.

Two ambient inputs, not included among the five explicit arguments, affect its behavior: a base selector used to construct addresses and a payload word written to global storage on the zero-second-argument path.

The zero comparison occurs **after both reads**. A zero second argument therefore does not bypass address-dependent access: it causes the first read to target address 0x00000004.

The second read supplies a value written on **both** paths. On the nonzero path, its unsigned 16-bit result is widened and written at the derived base plus 0x30. On the zero path, the same widened result is first written at the derived base plus 0x3B; the value for the subsequent, final store is then replaced with 0x0000008D, and that final store targets absolute address 0x00000030.

The application-level purpose of these accesses is not established. Labels associated with the global storage do not prove hardware configuration, exception handling, or any other subsystem role.

## Behavior

### Common sequence

If execution reaches each operation, the represented order is:

1. Form the derived base from the ambient base selector.
2. Read an unsigned 16-bit value from the second argument plus four.
3. Read an unsigned 16-bit value from the derived base plus 0x28, widening it to an unsigned 32-bit value.
4. Compare the second argument with zero.
5. Perform the selected write sequence.
6. Return the fifth argument.

Both reads precede the comparison and all represented writes.

The first read is performed on both paths, although its value is used only on the zero path. The second read is also performed on both paths, and its value supplies an explicit 32-bit store on each path.

A read whose value is unused on a particular path is still part of the represented access sequence. Its accessibility, fault behavior, or interaction with special memory can affect whether later operations occur.

Both read results are unsigned halfwords, with numeric values from 0 through 65,535. Widening either result to 32 bits fills the upper 16 bits with zero; it does not sign-extend bit 15.

### Nonzero second argument

When the second argument is nonzero:

- None of the five conditional global assignments occurs.
- The widened result of the second read is stored as a 32-bit value at the derived base plus 0x30.
- Normal completion returns the fifth argument unchanged.

The first read’s value does not contribute to this store or the return value. The function does not combine the two sampled values.

For example, a second-read result of 0x8001 produces the 32-bit store value 0x00008001, not 0xFFFF8001.

### Zero second argument

When the second argument is zero, the first read has already targeted address 0x00000004. The second read has also completed before the conditional writes begin.

The zero-path operations occur in this represented order:

| Order | Destination | Assigned value |
|---:|---|---|
| 1 | First global destination | Derived base minus five |
| 2 | Derived base plus 0x3B | Second read’s zero-extended value, stored as 32 bits |
| 3 | Second global destination | 0xFFFFFB00 |
| 4 | Third global destination | First read’s zero-extended value |
| 5 | Fourth global destination | Derived base |
| 6 | Fifth global destination | Ambient payload word |
| 7 | Absolute address 0x00000030 | 0x0000008D, stored as 32 bits |

After the second global assignment, the internal value selected for the final store becomes 0x0000008D, and the final address base becomes zero. These internal changes do not alter the value already used by the intermediate store at the derived base plus 0x3B.

Thus, the second read is **not discarded on the zero path**. It supplies the intermediate store. Only the later final store uses the replacement constant.

The final store’s address is independent of the derived base. It is not the derived base plus 0x30, except when the derived base itself is zero.

Under the conditional wrapping model, the derived base is divisible by four, so the 32-bit access at the derived base plus 0x3B starts three bytes past a four-byte boundary. The representation does not establish whether the target permits this alignment or how it executes the access.
