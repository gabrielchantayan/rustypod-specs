# F-4128d4e641bf

## Purpose

F-4128d4e641bf conditionally records an input value in a shared byte-sized field and invokes F-3a6f7fda3c0d with that input and four fixed arguments.

The decision uses two fields in a shared byte-addressed object:

- A byte at offset 3, compared against the full unsigned input.
- A byte at offset 0, consulted only when that comparison is equal.

The operation is suppressed only when the offset-3 byte equals the full input and the subsequently read offset-0 byte is zero. In every other case, the function writes the low eight bits of the input to offset 3 before invoking the dependency.

**Inferred intent:** the offset-3 byte may represent a remembered selection, while the offset-0 byte may force an otherwise redundant operation. Those roles are not established. This contract therefore describes the fields by offset rather than assigning application-specific meanings.

## Behavior

### Decision and access order

The function first reads the byte at offset 3 and converts that byte to the unsigned integer comparison type. The resulting value lies between 0 and 255 inclusive.

It compares that value against the full input. This is not a comparison between two truncated bytes.

If the values differ:

- The function does not directly read offset 0.
- It proceeds to the write-and-call path.

If the values are equal:

- The function next reads the byte at offset 0 and converts it to the unsigned comparison type.
- A zero byte suppresses both the write and the dependency call.
- Any nonzero byte selects the write-and-call path.

Thus the suppressing condition requires both full-value equality with offset 3 and a zero value at offset 0. A matching offset-3 byte alone is insufficient.

### Write-and-call path

When selected, this path performs these externally relevant actions in order:

1. Write the input reduced modulo 256 to offset 3.
2. Invoke F-3a6f7fda3c0d with five arguments, in this positional order:

| Position | Argument value |
|---|---|
| 1 | 28, equivalent to hexadecimal 1C |
| 2 | 29, equivalent to hexadecimal 1D |
| 3 | The original full unsigned input |
| 4 | 11, equivalent to hexadecimal 0B |
| 5 | 0 |

The third argument is not replaced by the stored byte. For example, an input of 256 produces a byte write of zero but a dependency argument of 256.

The write occurs even if the byte being stored is identical to the byte previously read. There is no separate same-byte optimization on this path.

The function performs no explicit follow-up state access or result check after the dependency invocation. Any dependency result is not used to choose further behavior.

### Suppressed path

When the comparison is equal and offset 0 is zero:

- Offset 3 is not written.
- F-3a6f7fda3c0d is not called.
- No additional direct shared-state access is shown.
- The function returns without a status value.

“Suppressed” therefore means absence of the write and call, not absence of all activity: the offset-3 and offset-0 reads have already occurred.

### Width-sensitive cases

Under the 32-bit input interpretation:

- Inputs from 0 through 255 can equal the widened offset-3 byte.
- Inputs from 256 through 4,294,967,295 cannot equal that byte.
- Every input above 255 selects the write-and-call path without a direct read of offset 0.
- The stored byte is always between 0 and 255.
- The full input remains available as the dependency’s third argument.

No addition, subtraction, or multiplication is involved. The relevant numeric distinction is full-width comparison versus byte-sized storage.
