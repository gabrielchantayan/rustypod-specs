# F-bc483e8386da

## Purpose

F-bc483e8386da dispatches an event-like input against a receiver. It selects behavior from a 32-bit discriminator, delegates several event classes to receiver callbacks, and handles one class through conditional receiver-state updates.

A secondary path runs when an ordinary dispatch returns zero and the input’s subsequently observed discriminator is `0x22`. That path obtains a resource, obtains an input-derived value, asks a dependency to produce an object, passes that object to an associated receiver, and conditionally invokes an object callback.

These are behavioral descriptions of the supplied static representation. Interpretations such as “event,” “resource,” “associated receiver,” and “release callback” are descriptive, not established domain semantics.

## Interface

### Inputs

The function accepts two address-bearing arguments:

- **Receiver:** a pointer to writable receiver storage. Its first 32-bit word identifies a callback table.
- **Input:** an address identifying an event-like record. A 32-bit discriminator is read at byte offset `0x04`.

The supplied representation uses 32-bit words and address-bearing values. This contract describes that apparent 32-bit execution model; it does not establish portability to a wider-pointer environment.

## Behavior

### Initial selection

The function first reads the input discriminator at offset `0x04`. The initial value selects one of four explicit branches or a fallback dependency.

Selectors such as `0x0A00` and `0x3900` are literal arguments to F-682adfd5a561. Their internal interpretation is not established.

### Discriminators `7` and `0x0D`

For either discriminator:

1. Invoke F-682adfd5a561 with the input and selector `0x0A00`.
2. After that dependency returns, read the receiver’s callback-table address and select the entry at offset `0x178`.
3. Invoke that callback with the receiver and the lookup result.
4. Use its 32-bit result as the ordinary dispatch result.

The lookup result is forwarded without a visible null check or local dereference.

The receiver callback is resolved after the lookup. If the lookup changes receiver state through an otherwise available reference, this ordering allows the subsequent table read to observe that change. No preservation guarantee is assumed.

### Discriminator `0x15`

This branch follows the same pattern, with two differences:

- The lookup selector is `0x3500`.
- The receiver callback-table entry is at offset `0x17C`.

Its callback result becomes the ordinary dispatch result.

### Discriminator `0x13`

This branch has its own completion behavior and does not enter secondary processing.

First, invoke F-682adfd5a561 with the input and selector `0x0C00`. Read the 32-bit value at offset `0x0C` from the returned address. Compare that value with the receiver’s 32-bit field at offset `0x44`.

The comparison has three outcomes:

- **Equal:** perform no branch-specific state update, then invoke the final receiver callback.
- **Unequal, extracted value `0x80AB`:**
  1. Invoke F-938c950e5046 without visible arguments.
  2. Invoke F-15a3bb70a7c7 without visible arguments.
  3. Store the latter dependency’s 32-bit result in the receiver field at offset `0xE8`.
  4. Invoke the final receiver callback.
- **Unequal, extracted value `0x60AE`:**
  1. Invoke F-23e8d37d5f69 without visible arguments.
  2. If its result is nonzero, invoke F-97c1f322872e and store its 32-bit result in the receiver field at offset `0x100`.
  3. If its result is zero, do not perform that acquisition or direct field write.
  4. Invoke the final receiver callback.

For any other unequal extracted value, return `1` immediately. The final receiver callback is not invoked.

The final receiver callback is obtained from the receiver’s then-current callback table at offset `0x0D4`. It receives only the receiver. Its return value is ignored, and F-bc483e8386da returns `1`.

Equality takes precedence over the special constants. If both compared values are `0x80AB`, for example, neither F-938c950e5046 nor F-15a3bb70a7c7 is invoked by this branch.

No direct write to the receiver’s comparison field at offset `0x44` is visible.

### Other discriminators

For every other initial discriminator, invoke F-unknown-01 with the receiver and input. Its 32-bit result becomes the ordinary dispatch result.

F-unknown-01 is an opaque identifier assigned in this document to the fallback dependency for which no published mapping was supplied.

### Ordinary completion and secondary-processing gate

After an ordinary dispatch:

- If its result is nonzero, return that result immediately. The input discriminator is not read again by this function.
- If its result is zero, read the input discriminator again at offset `0x04`.
- If this later value is not `0x22`, return zero.
- If this later value is `0x22`, perform secondary processing.

The gate uses the later read, not the initial discriminator. Consequently:

- An initially different discriminator can reach secondary processing if a dependency changes it to `0x22` and returns zero.
- An initial discriminator of `0x22` does not guarantee secondary processing if fallback dispatch changes it before returning zero.
- The explicit `0x13` branch never reaches this gate, even if a dependency changes the input discriminator.

### Secondary processing

Secondary processing occurs in this observable call order:

1. Invoke F-f2ddcdbfb0c6 without visible arguments.
2. Invoke F-c5a232e4455b with that result and the literal `0x10`.
3. Invoke F-682adfd5a561 with the input and selector `0x3900`.
4. Invoke F-98b04955532b with:
   - The result of F-c5a232e4455b.
   - The result of the `0x3900` lookup.
   - The receiver.
5. Read the associated receiver address from receiver offset `0x38`. Resolve its callback-table entry at offset `0x30` and invoke it with the associated receiver and the object returned by F-98b04955532b.
6. Preserve that callback’s 32-bit result as the function’s return value.
7. If the produced object is nonnull, read its callback-table address and invoke the entry at offset `0x04`, passing the object itself.
8. Return the preserved associated receiver callback result.

The associated receiver callback is invoked even when the produced object is null. The null check controls only the subsequent object callback.

For a nonnull object, its callback table is read after the associated receiver callback returns. The object must therefore remain valid for that later dereference, regardless of what the associated receiver callback does.

The final object callback’s result is ignored.

## Side effects

Each stores a 32-bit dependency result without visible filtering or validation.

### Observable read and call ordering

The following ordering constraints are significant:

- The initial discriminator read precedes dispatch.
- Explicit lookup calls precede resolution of the corresponding receiver callbacks.
- In the `0x13` branch, the extracted comparison field and receiver comparison field are read after the lookup returns.
- Conditional `0x13` field writes precede resolution and invocation of the final receiver callback.
- The second discriminator read occurs only after an ordinary dispatch returns zero.
- Secondary resource production precedes the `0x3900` lookup, which precedes object production.
- Associated receiver lookup occurs after object production.
- Object callback resolution occurs after the associated receiver callback.

No ordering guarantee beyond the supplied control flow is established for hidden accesses inside dependencies.

### Ownership and lifetime

The function does not visibly copy or independently free lookup results.

Secondary processing forwards a resource-like value and a lookup result to F-98b04955532b. It then forwards the produced object to another callback and, when nonnull, invokes an additional object callback.

The last callback may plausibly release a local ownership interest, but that is inferred intent only. The evidence does not establish:

- Whether either production dependency allocates memory.
- Whether an argument is borrowed or transferred.
- Whether the associated receiver retains, consumes, or destroys the object.
- Whether the final object callback releases memory.
- Whether a null object represents failure or an ordinary condition.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. They assume normal dependency returns and valid memory for every performed dereference.

1. **Nonzero ordinary callback result.**  
   Given initial discriminator `7`, the `0x0A00` lookup precedes the receiver callback at offset `0x178`. If that callback returns `9`, the function returns `9` without a second discriminator read or secondary processing.

2. **Zero result without secondary discriminator.**  
   Given initial discriminator `0x15`, if the callback at offset `0x17C` returns zero and the later discriminator is `0x15`, the function returns zero without secondary processing.

3. **Mutation enables secondary processing.**  
   Given initial discriminator `7`, if its callback changes the input discriminator to `0x22` and returns zero, secondary processing runs.

4. **Mutation prevents secondary processing.**  
   Given initial discriminator `0x22`, if fallback dispatch changes it to `8` and returns zero, the function returns zero without secondary processing.

5. **Equal comparison suppresses special update.**  
   Given discriminator `0x13`, if the extracted comparison value and receiver field both equal `0x80AB`, the two special dependencies are skipped. The callback at offset `0x0D4` runs, and the function returns `1`.

6. **Unequal `0x80AB` update.**  
   If the extracted value is `0x80AB` and differs from the receiver comparison field, F-938c950e5046 precedes F-15a3bb70a7c7. The latter’s result is stored at offset `0xE8` before the final receiver callback.

7. **Unequal `0x60AE` with zero gate.**  
   If F-23e8d37d5f69 returns zero, this function neither invokes F-97c1f322872e nor directly writes offset `0x100`. The final receiver callback still runs, and the function returns `1`.

8. **Unsupported unequal comparison.**  
   If the extracted value differs from the receiver comparison field and is neither special constant, the function returns `1` without the final receiver callback.

9. **Null produced object.**  
   During secondary processing, a null object is still passed to the associated receiver callback. If that callback returns `-3`, the function returns `-3` and performs no object-table dereference.

10. **Nonnull produced object.**  
    If the associated receiver callback returns `6`, the object callback at offset `0x04` runs afterward. Its return value does not replace `6`.
