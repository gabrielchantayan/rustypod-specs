# F-350c3f9b3126

## Purpose

F-350c3f9b3126 advances a caller-held reference through a linked structure, modifying the reference storage in place. Its result includes both the final reference and any intermediate reference updates.

The access pattern is consistent with finding an in-order successor in a binary tree: either descend into one subtree and follow its opposite edge, or ascend through ancestors. That interpretation is **inferred intent**, not an established requirement on the input topology. The function does not independently recognize a root, an end position, or a sentinel.

A distinguishing behavior occurs after upward traversal: the first candidate that stops the ascent is not necessarily installed as the result. A separate relationship check can retain the last reference already published to the caller.

## Behavior

### Route selection

The initial branch-link value determines the route for the entire invocation:

- A nonzero branch link selects downward traversal.
- A zero branch link selects upward traversal.

Subsequent field values do not cause a switch between routes.

### Downward result and publication

For stable, non-overlapping storage, the downward destination is the end of this path: the initial node’s branch link, followed by descent links until a zero descent link is reached.

Every nonzero node reference on that path is published to the caller’s slot, in path order. Publication is not deferred until the destination is known. Each visited node is published **before** its descent link is inspected.

Thus, when the initial branch target already has a zero descent link, it is the sole published reference. With several descent steps, each intermediate node becomes the caller-held reference before traversal continues.

This route does not inspect upward links. After route selection, it does not inspect any further branch links. An implementation that computes the same final destination but performs only the final slot write would not preserve the represented update behavior.

A cycle of nonzero descent links has no explicit escape mechanism. If a later access cannot complete, earlier slot updates have already occurred at the level of the represented operation sequence; no rollback is provided.

### Upward result and publication

The upward route uses the initial node’s upward link as its first candidate.

The continuation relationship is that a candidate’s branch link identifies the reference currently held in the caller’s slot. Candidates satisfying that relationship are published to the slot, and ascent continues through their upward links. Consequently, each continuing ascent step makes the candidate the caller-held current node before its upward link is used for further traversal.

The first candidate not satisfying that relationship stops ascent. That candidate is then subject to a different acceptance rule: it is installed only if the branch link of the **currently held node** differs from the candidate.

These two comparisons examine opposite relationships:

- Continuation asks whether the candidate’s branch link identifies the current node.
- Final acceptance asks whether the current node’s branch link identifies the candidate.

If the final relationship is equality, the current reference is retained. The function must not be specified as an unconditional replacement with the first candidate that stops ascent.

### Access ordering

The represented behavior establishes the following ordering constraints:

- The initial branch-link read selects the route before any reference-slot update.
- On the downward route, publication of a candidate precedes inspection of that candidate’s descent link.
- On the upward route, the continuation comparison precedes publication of a matching candidate.
- An upward candidate is published before its upward link is read to obtain the next candidate.
- After ascent stops, the current node’s branch link is read before the optional final publication.

The last branch-link read is a distinct represented access, even when the same field was inspected earlier. Under overlapping storage, an intervening slot write can affect its value.

These constraints do not establish every machine-level memory access or evaluation order. In particular, the relative evaluation order of the two operands in an equality comparison is not specified by the supplied text. Atomicity, compiler treatment of repeated reads, memory barriers, and inter-thread visibility are not established.

### Boundary behavior

Zero terminates the downward route only when encountered as a descent link. An initial zero branch link selects ascent rather than producing an immediate return.

A zero upward candidate is not a recognized stopping condition. The continuation comparison still requires a branch-link access using that candidate. A successful “no parent” or “end reached” result cannot be inferred from a zero upward link.

Upward termination depends on encountering a candidate whose branch link differs from the current reference. A cycle that perpetually satisfies the continuation relationship can run indefinitely. A cycle alone does not prove nontermination; the encountered relationships determine whether ascent continues.

No special handling establishes behavior for an empty structure, a root without an accessible parent representation, or the largest element of a tree. Those cases require topology conventions outside the supplied evidence.
