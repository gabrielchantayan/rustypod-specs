# F-b04928163bc1

## Purpose

F-b04928163bc1 performs an ordered state transition on an object recovered indirectly from its input. It changes two input fields, requires six further fields to be zero, recovers an object address through dependencies, replaces that object's leading word at three stages, processes optional associated state, and returns the recovered address.

**Established static evidence:** the supplied representation establishes the accesses, widths, branch predicates, explicit arguments, and call sequence described below. Global contents are read at particular points; they are not established constants.

**Inferred intent:** the leading-word transitions and dependent operations resemble layered teardown. This does not establish concrete types, destruction semantics, ownership transfer, or deallocation.

**Unknown:** dependencies may change globals, context, or object storage. A normal return does not establish that the returned address still denotes a live object.

No runtime tests have been performed.

## Behavior

### Initial global reads, writes, and validation

The initial sequence contains **two source-level reads of the same global location**, not one shared read:

1. The first read is captured for the later addition.
2. The global location is evaluated again, and that second observed value is written to input offset `0x00`.
3. The first captured value plus `0x124` is written to input offset `0xA4`.

Thus, the two writes need not derive from the same observed global value. The second read is not substituted for the captured first value in the addition.

The function then checks input offsets `0xA8`, `0xAC`, `0xB0`, `0xB4`, `0xB8`, and `0xBC`, in that order. Each later field is examined only after the earlier fields have passed.

At the first nonzero field, F-163ea045cd81 is called without visible explicit arguments. If it returns, F-feee9156a257 is called, also without visible explicit arguments and represented as nonreturning.

Both input writes precede every such failure. Later checks and address recovery are not reached after a failure, and no rollback is visible.

### Address recovery

After all six checks pass:

- F-917e96f61d51 receives input plus `0x118`.
- F-22f5c8cfa30b receives the preceding result minus `0x24`.

### Associated-state entry

If zero, all associated-state processing is skipped.

Otherwise, the function retains that associated-state address and captures its 32-bit field at `0x04`. These retained values remain the arguments used in the later calls specified below, even if dependencies change the object's `0x0C` field.

The function then tests object offset `0x04`.

If zero, it returns the recovered object without examining object offset `0x08`.

If nonzero:

2. Object offset `0x04` is tested again.

## Acceptance examples

These are conditional expectations, not executed tests. They assume usable storage, valid indirect targets, and normal dependency returns except at the represented nonreturning endpoint.

1. **Different initial observations.** If the first global read observes `0x1000` and the second observes `0x2000`, input `0x00` receives `0x2000`, while input `0xA4` receives `0x1124`.

2. **32-bit addition boundary.** If the first captured value is `0xFFFFFF00`, the low-32-bit addition result is `0x00000024`. The second read independently supplies input `0x00`; language-level overflow interpretation remains documented_only.

3. **Earliest validation failure.** A nonzero input `0xA8` causes both initial writes, then F-163ea045cd81 and F-feee9156a257. Later validation fields and recovery dependencies are not reached.

4. **Changed global before use.** If F-a6fdc7050c77 changes the global supplying the second leading-word replacement, that replacement uses the value read after the call, not an entry-time snapshot. The notification argument and final replacement likewise use their own later reads.

5. **Optional interface mismatch.** If F-d277584d672d returns nonzero but slot `0x80` returns another address, slot `0x7C` is skipped. F-a6fdc7050c77 remains next in the outer sequence.

6. **No associated state.** A zero object `0x0C` skips all associated-state calls and traversal. The final global read and leading-word write still occur.

7. **Two captured-value calls.** A nonzero active-state result and a later matching context `0x28` cause two F-a82ec4b43e2f calls with the original captured value, even if associated state has since changed.

8. **Zero traversal output.** A nonzero traversal result with zero output causes no item invocation and proceeds to another traversal call.

9. **Changed context.** If the `0x24` comparison matches but the next accessor returns another context, the zero write targets that latter context.

10. **Final branch distinctions.** An initially zero object `0x04` bypasses the `0x08` check. An initially nonzero `0x04` cleared by F-c719314a16bb suppresses the indirect call but still reaches that check.
