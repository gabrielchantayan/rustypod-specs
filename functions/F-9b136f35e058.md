# F-9b136f35e058

## Purpose

F-9b136f35e058 requests a result from a primary object using a 32-bit selector. If that request returns a non-null pointer, the function returns it without entering the fallback path.

If the primary request returns null, the function obtains a fallback record sequence and scans it for the selector. The first matching record causes a sequence of dependency calls, a submission through a context-associated dispatch site, a second call using a previously captured value, and a final dispatch through the fallback result. The fallback result is then returned.

“Lookup,” “construction,” “registration,” “activation,” and “temporary state selection” are possible interpretations, not established semantics. In particular, the call to F-8157a180d901 with argument 8 does not establish an allocation, an eight-byte size, or any ownership relationship.

## Behavior

### Initial request

The function dispatches through the primary object’s table entry at +0xE4. The five visible arguments, in logical argument order, are:

1. The primary object address.
2. The selector.
3. A callable address retrieved through the primary object’s table entry at +0xE4.
4. The auxiliary value.
5. The same auxiliary value.

The call target and the third argument arise from distinct retrieval expressions. The supplied evidence does not establish the evaluation order of those retrievals, whether an implementation combines reads, or whether the retrieved callable addresses remain equal under mutation.

If the call returns non-null, that exact pointer is returned. On this path the function performs no fallback acquisition, fallback-record access, context-field access, matching-path dependency call, or final fallback-result dispatch. The initial callable’s own effects remain unknown.

### Fallback acquisition

If the primary request returns null, the function reads the two global-storage inputs for F-8967e4fb3bba:

- The value from 0x0818728C supplies the first argument.
- The value from 0x08187288 supplies the second argument.

Their argument positions are established; their read order within the call expression is not.

The returned address is immediately used to read the signed 32-bit bound at +0x00. No null check occurs first. The bound is captured once and is not replaced by values from later records.

### Scan and index arithmetic

The scan starts at index zero and continues while the signed index is less than the captured signed 32-bit bound.

For each iteration:

- The current record’s selector at +0x18 is read and compared with the input selector.
- On equality, the matching sequence runs and the function returns from that path.
- On inequality, the relative displacement at +0x04 is read and applied to the cursor.
- The index advances with signed 16-bit narrowing.

The effective index update retains the low 16 bits of the incremented value and interprets them as signed. Thus 32767 advances to −32768, not 32768.

Consequences:

- A zero or negative bound causes no selector or link reads. The initial bound read still occurs.
- For bounds 1 through 32767, a completely mismatching scan examines exactly the bound’s number of records, assuming accessible storage and normal execution.
- After the last mismatch in such a scan, the function still reads and applies that record’s link before the next loop comparison ends the scan.
- For a bound greater than 32767, the narrowed index cannot reach the bound. The visible count condition therefore cannot terminate the scan. A match, invalid access, or other interruption may still stop execution.

The scan has no visible cycle detection, link validation, or independent traversal limit. Address-overflow behavior is not established by the supplied representation.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Primary success bypasses fallback.**  
   If the initial request returns a non-null pointer, that exact pointer is returned. An otherwise inaccessible context does not affect this path because this function does not dereference it.

2. **Global argument identity.**  
   If the fallback-acquisition reads yield different values, the value read from 0x0818728C is the first argument to F-8967e4fb3bba and the value read from 0x08187288 is the second. This does not constrain which read occurs first.

3. **Empty or negative bound.**  
   After an initial null result, a valid cursor containing bound zero or −1 causes a null return without reading a record selector or link.

4. **One mismatch.**  
   With bound 1 and a mismatching selector, the function reads and applies the record’s link, then returns null. The link must be readable even though the computed next record is not examined.

5. **Relative link.**  
   For a record at 0x1000 with displacement 0x20, the next cursor is 0x1024, assuming valid address arithmetic.

6. **First match wins.**  
   A matching first record enters the full matching sequence without reading its next link. No later record is examined.

7. **Later global value is used.**  
   If F-7b103854e61a or the first F-d0b41dd4354d call changes storage at 0x08187290, the fourth argument to F-f3fa9f888021 comes from the subsequent read of that storage. The function does not preserve an earlier copy.

8. **Submission reads may disagree.**  
   If the dispatch-selection read of context +0x40 yields one object and the argument-supplying read yields another, the callable is selected through the former while receiving the latter as its first argument. No ordering between those reads is required by this contract.

9. **Opaque return processing.**  
   If F-8157a180d901 returns one value and F-69358e3b5d65 returns a different value, submission receives the latter. Neither value is required to designate an allocation.

10. **Signed-index boundary.**  
    With bound 32768 and no match during the first 32768 iterations, the index narrows to −32768. Reaching that iteration count does not terminate the scan.

11. **Null fallback result.**  
    If F-f3fa9f888021 returns null, null is still passed to F-69358e3b5d65. If execution reaches the final dispatch, it attempts a dispatch-table access through null. A graceful null return is not established.
