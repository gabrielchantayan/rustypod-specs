# F-f117592ec0a0

## Purpose

F-f117592ec0a0 processes indexed items using mutable cursor, timing, lookup-cache, interval, and checkpoint state. It stages sizes and source locations, writes reverse-growing output descriptors, and normally delegates payload processing to F-aeee487fad33 before writing a footer.

**Established behavior:** state advancement, staging, descriptor emission, transfer-count updates, and dependency calls are interleaved. Errors do not roll back earlier changes. The count passed to the transfer dependency is not necessarily the number of populated staging entries.

**Inferred intent:** the structures resemble a timed item reader supporting interval selection and checkpoint replay. No domain interpretation is required by this contract.

## Interface

### Arguments and representation

The function receives four arguments:

| Argument | Contract |
|---|---|
| Context address | Writable context containing configuration, references, cursors, timing, and checkpoint state. |
| Output address | Caller-provided output region. Zero receives explicit handling. |
| Capacity | Signed 32-bit byte count used for admission, budget comparisons, and output placement. |
| Cancellation address | Address of a readable byte at reached cancellation checkpoints. |

Addresses, table references, indices, sizes, and individual context words are 32 bits in the supplied representation. Paired timing values use low and high 32-bit words. Replay flags and cancellation are byte-sized.

Cancellation requires byte value **exactly 1**. Other nonzero values do not satisfy the visible cancellation checks.

### Return value

The result is a 32-bit status:

| Value | Visible cause |
|---|---|
| 0 | Ordinary stopping condition, including capacity handling; exact-capacity handling explicitly resets an earlier status to zero. |
| 1 | Lookup-refresh failure, item-index exhaustion, or interval exhaustion, unless subsequently replaced or reset. |
| 2 | Cancellation observed locally. |
| 3 | Zero output address, or zero context word at 0x10. |
| 4 | Capacity is smaller than the first staged size plus 32. |
| Other nonzero | May be returned by F-aeee487fad33 and propagated. |

These are not disjoint dependency-status namespaces. Any nonzero transfer result replaces the status selected before transfer. A zero transfer result preserves that status, including an exact-capacity reset to zero.

### Preconditions

Beyond the two result-3 checks, the function trusts references, bounds, arithmetic, and storage.

Reached context fields, tables, checkpoint arrays, and output locations must be valid. The cancellation address must be readable when checked. No general validation establishes nonnegative capacity, sufficient footer space, alignment, table-index validity, or freedom from overflow.

The visible body does not guarantee safe dependency behavior when the transfer count exceeds the number of populated entries or the staging-array extent.

## Behavior

### 1. Entry, initialization, and batch admission

A zero output address returns 3 without reading context offset 0x10. Otherwise, that context word is read; zero returns 3. Neither path performs finalization.

After validation, the function initializes:

- Descriptor count and transfer-count accumulator to zero.
- Logical output budget to 16 bytes.
- Accounted payload bytes to zero.
- Current item index from context offset 0x88.
- First descriptor address to output plus four times the signed, truncation-toward-zero quotient of capacity minus 32 divided by four.

It converts the time at 0xa8/0xac through F-1e0edc6e0bc9, saves the returned low word, and then calls F-94bd82ad6ce8 with the context and starting index. Thus the initial conversion precedes any changes made by that preparation call.

At the outer admission point, another attempt requires both:

- Logical budget strictly below capacity.
- Transfer-count accumulator strictly below 1,536.

The accumulator also indexes the staging arrays. It is not a reliable completed-item count: terminal processing can omit an increment or increment it twice. Replay restarts checkpoint recognition without returning through this admission check.

### 2. Checkpoint recognition

Context offset **0x40** references the checkpoint-list structure:

| Structure offset | Meaning |
|---|---|
| 0 | Signed 32-bit count used by the recognition guard. |
| 4 | Pointer to 32-bit item indices. |

The function reads the position at context offset 0xa4 and compares it with the count reached through 0x40. Only when the position is below that count does it read the indexed item value through the structure’s offset-4 pointer.

If that value equals the current item index, it increments 0xa4, stores the current index at 0x240, and copies these words in the listed order:

| Active context offsets | Saved context offsets |
|---|---|
| 0x8c, 0x90, 0x94, 0x98, 0xa0 | 0x244, 0x248, 0x24c, 0x250, 0x254 |
| 0xa8, 0xac, 0xb0, 0xb4 | 0x260, 0x264, 0x268, 0x26c |
| 0xc0, 0xc4 | 0x258, 0x25c |
| 0xc8, 0xcc, 0xd0, 0xd4 | 0x278, 0x27c, 0x280, 0x284 |
| 0xd8, 0xdc | 0x270, 0x274 |

These are individual ordered copies, not an atomic snapshot. The attempt is marked as a checkpoint. At most one list entry is recognized per attempt; repeated equal entries are not consumed by an inner recognition loop.

### 3. Size resolution and immediate capacity rejection

The structure referenced at context offset 0x18 contains:

| Offset | Meaning |
|---|---|
| 0 | Fixed size; zero selects variable sizes. |
| 4 | Highest accepted item index. |
| 8 | Variable-size cache base. |
| 12 | Pointer to 32-bit variable sizes. |

A nonzero fixed size is staged and supplies the initially selected payload size.

For variable sizes, cancellation is checked first. If the item index exceeds the highest accepted index, the staged size becomes −1 while selected payload size remains zero. Otherwise, the entry index is current item index minus cache base minus one.

F-3563447b05c9 refreshes the cache when the current index exceeds base plus 32,768 or its predecessor is below base. It receives the context and predecessor index. A nonzero result selects status 1 and goes directly to finalization.

After size staging, capacity is compared against **staging entry zero plus 32**, including on later attempts. Insufficient capacity returns 4 immediately. This path does not transfer, write the footer, store the continuation index, or call F-5cbc85e92503. Earlier checkpoint and dependency effects remain.

### 4. Interval selection and replay

A zero reference at context offset 0x38 bypasses interval selection and initially selects the item.

Otherwise, while the start boundary at 0xc8/0xcc is all ones, the function:

- Adds the pair at 0xd8/0xdc to 0xa8/0xac, propagating carry.
- Increments the interval cursor at 0xc4.
- Calls F-b1214ca19495.

There is no visible count guard or local iteration bound on this sentinel-consumption loop.

Selection compares the **signed extension of the low word at 0xb0**, not the full pair at 0xb0/0xb4, against signed 64-bit boundaries at 0xc8/0xcc and 0xd0/0xd4. The start is inclusive; the end is exclusive.

Outside the interval, the item is unselected. A checkpoint with replay-active byte 0x23c equal to zero sets pending-replay byte 0x23d to 1. Unless replay-active is exactly 1, selected payload size and its proposed budget contribution are forced to zero.

Inside the interval:

- Pending replay zero, or an attempt that is itself a checkpoint, clears both replay bytes.
- Otherwise, replay-active becomes 1, the saved item index and snapshot words are restored, pending replay is cleared, and F-94bd82ad6ce8 is called with the restored index.
- Processing restarts at checkpoint recognition using the same staging index, without ordinary item advancement for the interrupted attempt.

Checkpoint-list position 0xa4 is not restored. Replay-active is value-sensitive: suppression tests for exactly 1, whereas later accounting tests for any nonzero value.

### 5. Precommit lookup and budget checks

Three cached structures have a cache base at structure offset 4 and an entry pointer at offset 8:

| Context reference | Entry width | Refresh condition | Dependency |
|---|---:|---|---|
| 0x30 | 8 bytes | Cursor 0xc0 below base or at least base + 32,768 | F-58e3c92f2660 |
| 0x28 | 12 bytes | Cursor 0x8c below base or at least base + 32,767 | F-bc4667302afc |
| 0x20 | 4 bytes | Cursor 0x90 above base + 16,384, or its predecessor below base | F-40fcaf87b7ef |

The 12-byte structure’s first word is also its entry count.

The first two checks occur before the proposed-budget comparison. Their nonzero refresh results select 1 and skip transfer.

For normally selected items, the proposed budget is current budget plus selected payload size plus 16. Ordinarily suppressed items contribute zero. A proposal exceeding capacity stops with status 0 before ordinary cursor advancement; the resolved size may already occupy a staging entry.

The 4-byte-table refresh follows the capacity decision. Its lookup supplies a source base using cursor minus cache base minus one. Refresh failure selects 1 and skips transfer.

A second cancellation check follows that lookup. It applies in both fixed-size and variable-size modes. Cancellation selects 2 and skips transfer.

The highest accepted item index is then checked again. Exceeding it selects 1 and proceeds to transfer without ordinary advancement of that item.

### 6. Cursor advancement and source staging

For an accepted item, advancement occurs in this order:

1. Compare repetition counter 0xa0 with the first word of the current 8-byte entry. Increment it when below that word; otherwise reset it to 1, increment cursor 0xc0, and refresh if required.
2. Increment counter 0x94.
3. If that counter exceeds the second word of the current 12-byte entry, increment cursor 0x90, refresh its table if required, reload the source base, reset source offset 0x98 to zero, and reset counter 0x94 to 1.
4. Consider advancing cursor 0x8c. This requires **both** that it is less than the 12-byte structure’s first word minus one and that the next entry’s first word is at most cursor 0x90. The count guard is evaluated before the next-entry threshold read. If both hold, advance by exactly one and refresh if required.
5. Add the current 8-byte entry’s signed second word to 0xb0/0xb4.
6. Stage source offset 0x98 plus the loaded source base.
7. Increase source offset 0x98 by the staged size.
8. Convert time 0xa8/0xac through F-1e0edc6e0bc9.

In particular, the final-entry count guard prevents the next-entry threshold read when cursor 0x8c is not below count minus one. The timing increment is read after possible cursor advancement, not necessarily from the entry used for the initial repetition comparison.

Any reached refresh failure selects 1 and skips transfer, retaining earlier mutations.

### 7. Checkpoint result arrays and accounting

A checkpoint attempt can write converted time, staged size, and staged source location through context references 0x22c, 0x228, and 0x230, respectively.

When context word 0x218 equals 1, the index for all three is checkpoint-list position minus one. Writes occur in time, size, location order.

Otherwise, F-870c4fcf7295 is called first with position minus one. A zero high return word permits all three writes; its low word indexes the time array. Separate later calls, visibly also supplied word 0x218, provide the size and location indices. These indices are not established to be equal. The time write precedes the next call, and the size write precedes the final call.

Accounting then depends on replay-active:

- Zero and selected: reread the current signed timing increment, add it to 0xa8/0xac, and add staged size to accounted payload bytes.
- Zero and unselected: replace staged size with −1.
- Nonzero: add staged size to accounted payload bytes without that time increment.

With interval processing enabled, the updated signed-low-word position is compared with the end boundary. Reaching or exceeding it increments interval cursor 0xc4. If the new cursor is at least the interval structure’s count, status becomes 1. F-b1214ca19495 is called after this advancement even when exhaustion selected status 1.

### 8. Descriptors, count transitions, and transfer

Only a strictly positive selected payload size emits a descriptor. Its four 32-bit words, written in order, are:

| Word | Value |
|---|---|
| 0 | Output address + accounted payload bytes − selected payload size |
| 1 | Selected payload size |
| 2 | Converted item time |
| 3 | Checkpoint marker, 0 or 1 |

Emission increments descriptor count, commits the proposed logical budget, and moves the next descriptor address backward by 16 bytes. If status is already 1, emission also increments the transfer-count accumulator.

The subsequent count and status behavior is:

| Condition after possible emission | Additional count change | Result before transfer |
|---|---:|---|
| Budget differs from capacity; status is 1 | None | Transfer immediately with status 1 |
| Budget differs from capacity; status is not 1 | +1 | Return to outer admission |
| Budget equals capacity | +1 | Unconditionally reset status to 0 and transfer |

Consequences:

- An interval-exhausting attempt with nonpositive selected size can update state and both staging arrays yet remain excluded from the transfer count.
- A positive-size, interval-exhausting attempt normally contributes one increment inside emission.
- If that emission also reaches capacity exactly, the attempt contributes **two** increments, and interval-exhaustion status 1 is reset to 0.
- Zero-sized attempts can advance state without a descriptor or budget increase.

The two temporary arrays each contain 1,536 32-bit entries. The admission guard bounds their visible population indices, but does **not** guarantee a transfer count at most 1,536. An admitted attempt at index 1,535 can produce count 1,537 through interval exhaustion plus exact-capacity emission. The additional entry implied by the double increment is not populated by the visible body.

Ordinary stopping paths call F-aeee487fad33 with context, output, count accumulator, size array, location array, and cancellation address. Nonzero transfer status replaces the selected status. Local cancellation and refresh failures bypass transfer; result-3 and result-4 returns bypass finalization as well.

### 9. Finalization

The footer endpoint is output plus four times the signed, truncation-toward-zero quotient of capacity divided by four.

Finalization performs these actions in order:

1. Write 1 at endpoint minus 4.
2. Write descriptor count at endpoint minus 8.
3. Write initial converted time at endpoint minus 12.
4. Reconvert current time 0xa8/0xac.
5. Write current converted time minus initial converted time at endpoint minus 16.
6. Store the selected continuation index at context offset 0x88.
7. Call F-5cbc85e92503 with context and initial converted time.
8. Return selected status.

Continuation is the current item for cancellation, precommit capacity rejection, input-index exhaustion, variable-size refresh failure, and precommit 4-byte-table refresh failure. Precommit 8-byte or 12-byte refresh failures, advancement-time refresh failures, and completed attempts use the next item index. An outer admission stop retains the index awaiting processing.

No rollback occurs.

## Side effects

Visible writes affect context, checkpoint storage, checkpoint result arrays, descriptors, and footer. Dependencies can have additional effects; their apparent roles do not establish preservation of globals, context fields, or output.

No explicit allocation, release, or ownership transfer appears in this body. Dependency allocation, release, retention, and asynchronous use remain unknown. In particular, passing temporary staging-array addresses does not establish that retention is permitted.

Output writes are native 32-bit word writes. Byte order and alignment requirements are not established. For nonnegative capacities, the footer endpoint is capacity rounded down to a multiple of four, leaving up to three trailing bytes untouched by the footer itself.

## Acceptance examples

These are conditional static cases, not executed tests. Unless stated otherwise, references and arithmetic are valid, dependencies return zero and do not alter the scenario’s controlling state.

1. **Early rejection:** Zero output returns 3 without reading the enable word. Nonzero output with enable word zero also returns 3, without initialization calls.

2. **Initial capacity check:** First staged size 100 and capacity 131 return 4. Capacity 132 passes that check.

3. **Exact capacity with interval exhaustion:** First size 100, capacity 132, positive descriptor emission, and interval exhaustion during that item produce budget 132. Emission increments the transfer count to 1; exact-capacity handling increments it to 2 and resets status to 0. Only staging entry zero was populated. A zero transfer result leaves final status 0; a transfer result of 7 yields 7.

4. **Positive exhaustion below capacity:** First size 100, capacity 200, and interval exhaustion produce one descriptor, transfer count 1, and pretransfer status 1.

5. **Nonpositive exhaustion:** A first zero-sized item that advances state and exhausts the interval, with capacity 64, emits no descriptor and reaches transfer with count 0 and status 1, despite populated staging entry zero.

6. **Upper count boundary:** If admission occurs with count 1,535 and the attempt both exhausts the interval and emits to exact capacity, transfer receives 1,537. Only indices through 1,535 can have been populated by normal admitted attempts; dependency handling of this mismatch is unknown.

7. **Final 12-byte entry:** With count 5 and cursor 4, the cursor is not below count minus one. The next-entry threshold is not read, and this advancement branch does not increment the cursor.

8. **Checkpoint access:** A position equal to the count reached through 0x40 prevents the indexed checkpoint-item read. A lower matching position increments 0xa4 and captures the snapshot.

9. **Cancellation:** Byte 1 cancels at a reached check; byte 2 alone does not. Fixed-size operation omits the early variable-size cancellation check, so lookup and capacity handling can precede cancellation.

10. **Placement:** Capacity 100 places the footer at offsets 84–99 and the first descriptor at 68–83. This does not establish where the transfer dependency writes payload.

11. **Selection and failure:** Start equality selects an item; end equality does not. Ordinary suppression can stage −1 without a descriptor. A subsequent refresh failure skips transfer without undoing prior descriptors or state changes.
