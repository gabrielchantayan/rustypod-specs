# F-03c1eb785d59

Three distinct 32-bit globals supply successive values written to the object’s first field. These are **reads of global storage, not assignments of established constants**. Their contents and stability are unknown. Each read occurs at its specified stage; an earlier read cannot substitute for a later one.

The sequence is consistent with staged teardown or dispatch-state transitions. That interpretation is **inferred intent**, not an established lifecycle or ownership contract. The supplied representation does not establish that any dependency destroys an object, releases storage, preserves globals, or leaves unrelated fields unchanged.

## Behavior

### Initial global read, field write, and dependency call

The function first reads the current 32-bit contents of G-01 and writes that value to object offset 0. It then calls F-dcc4d97501c0 with the object address.

The global read precedes the object write, which precedes the call. The dependency may therefore observe the field value installed by this stage. No guarantee establishes that the dependency preserves that field, any global, or any other memory.

After the dependency returns, the function reads the current 32-bit contents of G-02 and writes that value to object offset 0. This is a new read after the dependency, not an entry-time snapshot. If the dependency changes G-02, the later read uses the changed contents.

The second field write replaces whatever value is then present at offset 0, including any value written by the dependency.

Aliasing also matters: without a non-aliasing precondition, an earlier object write may affect a later global read. The contract therefore preserves the read/write order rather than treating these stages as installations of three predetermined constants.

Expected behavior: the clear of offset 36 occurs before the G-03 read. Without an intervening change, that read obtains zero, and the subsequent offset-0 write stores zero. Treating G-03 as an immutable constant would produce an unsupported result.
