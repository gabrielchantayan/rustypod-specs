# F-c6c1a97a371b

## Purpose

F-c6c1a97a371b performs initialization followed by an indefinitely repeated state-processing cycle. Each cycle adjusts working state, invokes two services, conditionally performs a reporting sequence, consumes accumulated quantities from records, and increments selected counters.

Periodic telemetry or status reporting is an inferred purpose, not an established interface guarantee. The meanings of the quantities, output destination, and timing mechanism are unknown.

Established behavior includes replacing consumed record quantities and selected counters with an incoming 32-bit **seed**. The seed is not established to be zero; these replacements are not unconditional zero resets.

No normal return, termination condition, or explicit error result is visible.

## Interface

### Explicit and implicit inputs

The visible interface contains three 32-bit arguments:

| Input | Established use |
|---|---|
| Argument 1 | Supplied twice to the first initialization dependency |
| Argument 2 | No explicit use |
| Argument 3 | Stored at an initialization-derived address |

Additional incoming state is required:

- A structure address whose word at byte offset 20 supplies the primary-counter pointer.
- A control-structure address used for a flag byte at offset 0, a byte at offset 16, and a word at offset 84.
- A signed 32-bit selector used in initialization address calculations.

This evidence does not establish a self-contained, conventional three-argument calling interface. There is no visible returned value.

### Memory layouts

Unless otherwise stated, words are 32 bits and offsets are in bytes.

**Primary counters:** A word array obtained through the incoming structure at offset 20. Reporting accesses elements 0–3. Every iteration increments the element selected by the current-category index, without checking that index.

**Secondary counters:** A word array whose address is obtained through three 16-bit reads during initialization. Reporting accesses elements 0–3. Enabled iterations increment one element from pair 0/1 and one from pair 2/3.

**Working state:**

| Offset | Established use |
|---|---|
| 0 | Flag word tested with masks 2 and 70 |
| 4 | First aggregation bucket |
| 8 | Second aggregation bucket |
| 12 | Threshold-adjusted word |
| 20 | Category-derived word |

The initial working-state pointer is address **0x08002d7b**: three bytes beyond the data object at **0x08002d78**. A word from that same object is later read for report admission. Thus the initial working state and the admission-data object have a known address relationship and potentially overlapping accesses; they must not be modeled as unrelated allocations.

During aggregation, the working-state pointer is replaced using a global pointer slot. That pointer is not established to equal the initial pointer.

**Records:** A record array has a 52-byte stride. Each visited record supplies a signed classification at offset 36 and a 32-bit accumulated quantity at offset 48. A separately obtained signed word supplies the inclusive record-index bound.

**Frame regions:** Reporting uses regions beginning at offsets 16, 104, 120, and 248; words at offsets 44, 256, 260, and 264; bytes at offsets 112 and 113; and a category-indexed word at offset \(484 + 16k\). These accesses do not establish complete object sizes or ownership.

## Behavior

### Initialization

The established sequence is:

1. Invoke F-000000000001 with argument 1 twice. Its target is obtained by clearing the incoming link-like address’s bottom two bits and adding 1,536. This is the only initialization target dependent on that incoming address.

2. Invoke F-000000000002 without visible explicit arguments. Its statically determined target is **0x08002da4**.

3. Invoke F-000000000003 without visible explicit arguments, retaining its 32-bit result as the initialization value. Its statically determined target is **0x08002da8**.

4. Perform two word stores, in order:
   - At selector × 512 + 84, store selector × 262,144.
   - At selector × 512 + initialization value, store argument 3.

5. Load the primary-counter pointer from the incoming structure at offset 20.

6. Perform these stores, in order:
   - Store the incoming structure address at control-structure offset 84.
   - Store the primary-counter pointer’s low eight bits at control-structure offset 16.
   - Store the initialization value’s low eight bits at selector × 262,144 + 17.

7. Select the initial working-state pointer, 0x08002d7b.

8. Invoke F-000000000004 with the initialization value shifted left by 12, the initialization value itself, and zero. Its statically determined target is **0x08002c6c**. Retain its 64-bit result as the loop-control value.

9. Construct the secondary-counter pointer through this dependent read sequence:
   - Read 16 bits at the retained result’s high 32-bit half plus 10.
   - Zero-extend that value, use it as an address base, and read 16 bits at base plus 12.
   - Shift the second value right by two.
   - Read 16 bits at the resulting address plus 18.
   - Zero-extend the final value to form the secondary-counter address.

The pointer chain establishes neither allocation nor an ownership transfer.

### Loop-head adjustments

Compare the retained loop-control value as an unsigned 64-bit quantity against \(5 \times 2^{32}\).

- Below that threshold, leave working-state offset 20 unchanged.
- Otherwise, convert the low word to signed 32-bit form:
  - If it equals 3, write 3 at offset 20.
  - Otherwise, add one using the displayed signed 32-bit expression and store the resulting word.

The conversion’s behavior for values outside the signed range and signed addition overflow are not independently established. A converted value of \(2^{31}-1\), for example, does not justify a promised wrapped result.

Next, read working-state offset 12 as unsigned:

- If below 51, replace it with the seed.
- Otherwise, read it again, subtract 50, and store the unsigned result.

The comparison and subtraction paths therefore do not necessarily use the same observed value under external mutation.

### Services and report admission

Invoke F-12f1e1cd8133, then F-6750d7407908 with 0 and 100.

After both calls, read the control flag byte:

- If zero, skip reporting.
- If nonzero, invoke F-84f25e86d55f with the stored reporting token and a word read from the fixed slot at 0x08002d78. Enter reporting only if its 32-bit result is nonzero.

The admission word is mutable slot content, not an established constant. It is read after the service calls. Its slot is the same data object located three bytes before the initial working-state pointer.

1. Invoke F-000000000005 with the frame region beginning at offset 104.

2. Invoke F-000000000006 with the **address** of the frame word at offset 264.

3. After that pointer-taking call, read the word at offset 264 and pass its value to F-000000000007. Store the result at offset 260.

4. Invoke F-000000000008 with two primary-counter expressions, storing its result at offset 256:
   - Weighted expression: \(192c_0 + 96c_1 + 32c_2 + 16c_3\).
   - Sum expression: \(c_0 + c_1 + c_2 + c_3\).

   Here \(c_i\) denotes an access to element \(i\), not a captured snapshot. Each primary element is read separately for each expression. The representation does not establish an operand-evaluation order across those accesses.

5. Invoke F-000000000008 with \(100s_2\) and \(s_2+s_3\), retaining the result. Element 2 is read separately for numerator and denominator expressions; no snapshot or operand-evaluation order is established.

6. Invoke F-000000000008 with \(100s_0\) and \(s_0+s_1\). Element 0 is likewise read separately for the two expressions. No explicit assignment of this call’s result is visible.

7. Read the current-category index and the corresponding frame word at offset \(484 + 16k\). Invoke F-000000000008 with 192 and that word, retaining its result.

8. Invoke F-000000000009 with a word read from the fixed global slot at **0x08002d7c**, the preceding result, the stored primary calculation, and the word at frame offset 260. The global word is read for this call, after earlier dependencies; its value is not fixed by the slot address.

10. Store the retained secondary calculation from step 5 at frame offset 16.

11. Invoke F-00000000000a with the frame region at offset 120, a word read from the fixed global slot at **0x08002d80**, and bytes from frame offsets 112 and 113. This global value is read at this call site and may differ from any earlier state.

12. Invoke F-00000000000b with 52.

13. Invoke F-56b21d9963d1 with frame-region addresses at offsets 16 and 248.

    - F-00000000000c with the region at offset 16, an unspecified outgoing-register value, zero, and zero.
    - F-53f124131191 with the region at offset 120.
    - F-00000000000d with the region at offset 16 and the preceding result.

    A nonzero inspected word skips all three calls.

15. Invoke F-00000000000e with the region at offset 16.

16. Invoke F-00000000000f with 52 and 100.

17. Replace primary-counter elements 3, 2, 1, and 0 with the seed, in that order.

18. Replace secondary-counter elements 3, 2, 1, and 0 with the seed, in that order.

### Record aggregation

Whether reporting was skipped or completed:

1. Load the global pointer to the record-bound word.
2. Load the replacement working-state pointer from its global slot.
3. Store the seed into the first bucket through the global working-state reference, then into offset 8 through the retained working-state pointer.
4. Read the record-array base.
5. Read the signed inclusive bound once.

With a stable global working-state pointer, step 3 writes offsets 4 and 8 of the selected block, in that order. The first store is expressed through the global reference; the evidence does not establish atomic capture of that reference against concurrent changes.

Starting at index zero, visit records through the bound inclusively, subject to valid address and signed-index arithmetic. A negative bound causes no visits.

For each record:

- Read its signed classification at offset 36.
- Read bucket 1 if classification is below 127; otherwise read bucket 2.
- Read the quantity at offset 48 and form the unsigned 32-bit sum.
- Read classification again and select the destination bucket using the same threshold.
- Store the sum to that bucket.
- Replace the record quantity with the seed.

The two classification reads can select different buckets if memory changes between them. The routine provides no visible synchronization.

### Counter updates and continuation

Read the current-category index once and increment the corresponding primary counter.

Read the control flag byte again. If nonzero, read the working-state flag word once and:

- Increment secondary element 1 if bit 1 is clear; otherwise element 0.
- Then increment secondary element 3 if mask 70 selects no set bits; otherwise element 2.

Mask 70 is 0x46, selecting bits 1, 2, and 6. Both choices use the same captured flag word.

The tail then performs **two distinct reads** of working-state offset 8:

1. The first supplies the high word of the retained 64-bit loop-control value. Its low word is the previously captured category’s 32-bit representation.
2. A subsequent read decides whether the second bucket is unsigned-greater than one.

If the second read exceeds one, return to the outer loop-head comparison using the already captured 64-bit value. External mutation can therefore make the branch decision disagree with its captured high word.

Otherwise, immediately write offset 20:

- Category zero writes zero.
- Any other category supplies the signed expression category minus one, subject to the arithmetic qualifications above.

Resume at the offset-12 adjustment, bypassing the outer 64-bit comparison. There is no visible termination.

## Acceptance examples

These are conditional static examples, not executed tests. They assume valid memory, representable signed arithmetic, stable relevant values, and no aliasing or dependency interference except where explicitly illustrated.

1. **Threshold adjustment:** Offset-12 values 50, 51, and 100 become the seed, 1, and 50 respectively.

2. **Reporting disabled:** A zero flag after the service calls prevents F-84f25e86d55f from being called. Aggregation and the selected primary increment still occur.

3. **Reporting rejected:** A nonzero flag followed by a zero admission result skips report construction, report-related counter replacement, and token refresh.

4. **Pointer-taking preparation:** If F-000000000006 writes value 17 through its supplied address, and nothing changes that word afterward, F-000000000007 receives 17—not the address or a pre-call value.

5. **Inclusive records:** Bound zero visits record zero. Bound negative one visits no records.

6. **Classification boundary:** With seed zero and two records containing quantities 5 and 7 classified as 126 and 127, the buckets become 5 and 7; both quantities become zero.

7. **Nonzero seed:** With seed 9 and no records visited, both initialized buckets remain 9. Admitted reporting writes 9 to counter elements before later increments.

8. **Flag selection:** Flag words 0, 2, and 4 select secondary pairs (1, 3), (0, 2), and (1, 2), respectively.

9. **Unsigned wrap:** Incrementing a selected counter containing \(2^{32}-1\) stores zero.

10. **Stable tail values:** If both tail reads are 2, execution reaches the outer comparison but does not meet its five-high-word threshold. If both are 5 and category is 3, the outer rule writes 3. If both are at most 1 and category is 3, the immediate rule writes 2.

11. **Different tail observations:** If the first bucket read is 5 and the second is 2, the branch reaches the outer comparison with captured high word 5. Category 3 therefore produces 3 at offset 20.

12. **Signed boundary:** A high-threshold low word converting to \(2^{31}-1\) reaches signed addition overflow. This contract supplies no wrapped-result acceptance criterion for that case.

13. **Mutable reporting slots:** If an earlier reporting dependency changes the slot at 0x08002d80, its value when read for F-00000000000a is used; an entry-time constant is not substituted.
