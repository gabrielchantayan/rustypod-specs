# F-3e0d7ef9b610

## Purpose

F-3e0d7ef9b610 conditionally derives an inclusive position interval from an indexed object, checks whether a separately obtained position lies within that interval, and submits the interval length and relative position through F-dece790ddc92.

The function first filters on a 16-bit field in an input record. For matching records, it obtains a primary object and consults that object’s state. A zero state result enters an inspection path that ends in a dependency marked as non-returning, whether or not submission occurs.

**Established behavior:** the ordinary return paths produce the 32-bit values 4 or 2. The inspection path has no established normal return.

**Inferred intent:** the indexed values appear to describe boundaries, with the following boundary—or a terminal position—closing the selected interval. Neither the domain meaning of those positions nor the meaning of the submitted operation is established.

## Interface

### Inputs

The supplied representation exposes two arguments:

| Input | Established use |
|---|---|
| First argument | A 32-bit value that is not directly read or forwarded by this function. |
| Second argument | A pointer to a record accessed using 32-bit word spacing. |

The input record has the following observed fields:

| Byte offset | Access | Meaning established by this function |
|---|---|---|
| 0 | 32-bit read | Tested against zero before submission; subsequently read again as an argument to F-dece790ddc92. |
| 8 | 32-bit read | Passed to F-c25a2fcc75b5 to obtain an unsigned index. |
| 12 | 32-bit word access followed by 16-bit narrowing | Its low 16 bits determine whether the record qualifies for further processing. |

The field at offset 4 is not directly accessed.

The qualification test is equivalent to requiring the low 16 bits of the word at offset 12 to equal 4. The upper 16 bits do not affect that test. Although the narrowed value is represented as signed, signedness does not alter equality with positive 4.

### Outputs

The normal return value is a 32-bit quantity:

- **4:** the qualification field does not equal 4.
- **2:** the field equals 4, a non-null primary object is obtained, and its state operation returns a nonzero value.

For a qualifying record whose primary-object state operation returns zero, execution reaches F-feee9156a257 unless an earlier dependency fails to return or the fatal path is taken. F-feee9156a257 is marked non-returning in the supplied evidence.

### Preconditions

The function performs no explicit null check on the input record before reading its qualification field. The caller must provide storage readable at the offsets actually reached.

Any object pointer used for indirect dispatch must support the observed object layout: a dispatch-table pointer at the beginning of the object, with callable entries at the byte offsets described below. Object and dispatch-table validity are not checked beyond the explicit null tests.

No ownership transfer of the input record is established.

## Behavior

### 1. Qualification

The first substantive operation reads the qualification field at record offset 12.

If its low 16 bits are not 4, the function returns 4. No dependency call or other record-field read is established on this path.

If the field qualifies, the function calls F-b7af80e829ec without explicit arguments to obtain a primary-object pointer.

A null result invokes F-a817d8d58c10, which is marked non-returning. This path does not establish a normal return or subsequent inspection.

### 2. Primary-object state gate

For a non-null primary object, the function invokes its dispatch-table entry at byte offset 288, explicitly supplying the primary-object pointer.

A nonzero result causes the function to return 2. The index conversion, secondary-object acquisition, interval reads, and submission do not occur on this path.

A zero result enters the inspection path.

### 3. Index conversion and secondary-object acquisition

The function reads the 32-bit record field at offset 8 and passes it to F-c25a2fcc75b5. Its result is used as an unsigned 32-bit index.

The function then invokes the primary object’s dispatch-table entry at byte offset 232, explicitly supplying the primary-object pointer. The returned pointer is retained as the secondary object.

If that pointer is null, the interval checks are skipped. Execution still proceeds to F-feee9156a257 with the null pointer.

For a non-null secondary object, the function invokes its dispatch-table entry at byte offset 8. No explicit arguments are shown for this invocation. If its result is zero, the remaining interval checks are skipped, and the secondary-object pointer is passed to F-feee9156a257.

A nonzero result permits the next step.

### 4. Index range check

The function invokes the secondary object’s dispatch-table entry at byte offset 312. No explicit arguments are shown. The result is treated as an unsigned 32-bit count.

The converted index must be strictly less than this count. If it is equal to or greater than the count, no boundary or current-position operations are performed, and no submission occurs. Execution proceeds to F-feee9156a257.

This makes a zero count an unconditional rejection of every possible unsigned index.

### 5. Boundary acquisition

For an in-range index, the function obtains a start boundary by invoking the secondary object’s dispatch-table entry at byte offset 316 with two explicit arguments: the secondary-object pointer and the index.

It then selects the end-boundary source:

- If the index plus one is strictly less than the previously obtained count, the same entry at byte offset 316 is invoked with the secondary-object pointer and the next index.
- Otherwise, the entry at byte offset 160 is invoked with no explicit arguments shown, and its result supplies the end boundary.

Both boundaries are treated as unsigned 32-bit quantities.

The count and index used for this decision are retained values. They are not refreshed after the start-boundary call. Consequently, a dependency that changes the underlying object does not cause the function to restart or revalidate the selection.

The addition of one cannot wrap on this established path: the earlier strict comparison guarantees that the index is at most one less than an unsigned 32-bit count, so the index cannot be the maximum unsigned 32-bit value.

### 6. Boundary ordering and current position

The start boundary must be less than or equal to the end boundary under unsigned comparison.

If the boundaries are reversed, the current-position operation is not invoked, submission is skipped, and execution proceeds to F-feee9156a257.

For ordered boundaries, the function invokes the primary object’s dispatch-table entry at byte offset 248, explicitly supplying the primary-object pointer. Its result is treated as an unsigned 32-bit current position.

Submission is eligible only if:

- the start boundary is less than or equal to the current position; and
- the current position is less than or equal to the end boundary.

Both endpoints are included. There is no strict-positive-length requirement.

### 7. Payload preparation and submission

For an eligible interval, the function makes two calls to F-b9d9c0b9bfab, in this order:

1. A call with the address of the first four-byte temporary region and the unsigned difference between end and start.
2. A call with the address of the next four-byte temporary region and the unsigned difference between current position and start.

The comparisons preceding these calls ensure that both differences are nonnegative in unsigned ordering and require no subtraction wraparound.

The two temporary regions occupy consecutive four-byte locations in the supplied stack layout. The function subsequently passes the address of the first region together with a length of 8. The intended representation appears to be an eight-byte payload with two components, but the bytes actually written by F-b9d9c0b9bfab are not established.

Only after both helper calls does the function inspect the record’s first 32-bit word.

- If that word is zero, it invokes F-a817d8d58c10.
- If nonzero, it calls F-dece790ddc92 with seven arguments, in order:

| Position | Argument |
|---|---|
| 1 | Input-record pointer |
| 2 | A fresh read of the record’s first 32-bit word |
| 3 | Constant 0 |
| 4 | Constant 4 |
| 5 | Constant 6 |
| 6 | Address of the first temporary region |
| 7 | Constant 8 |

The zero check and the argument read are distinct accesses. Their equality is not guaranteed under external mutation.

The return value of F-dece790ddc92, if any, is ignored.

### 8. Terminal dependency

After the inspection path, F-feee9156a257 is called with the retained secondary-object pointer. This occurs after a normal return from submission and also when submission was skipped because of:

- a null secondary object;
- a zero secondary-object eligibility result;
- an out-of-range index;
- reversed boundaries; or
- a current position outside the inclusive interval.

The supplied evidence marks this dependency as non-returning. No normal continuation from it is established.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes valid storage and dependencies that return the stated values without invalidating later accesses.

1. **Nonqualifying record.** The low 16 bits at offset 12 are 3. The function returns 4 without invoking any dependency. The first word and index-source field need not be inspected.

2. **Ignored upper qualification bits.** The qualification word is `0xABCD0004`. It qualifies because its low 16 bits are 4. A word of `0x00010003` does not qualify.

3. **Nonzero primary state.** The record qualifies, acquisition returns a valid primary object, and its state result is nonzero. The function returns 2. Neither index conversion nor secondary-object acquisition occurs.

4. **Missing primary object.** The record qualifies and F-b7af80e829ec returns null. F-a817d8d58c10 is invoked; no ordinary return is established.

5. **Missing secondary object.** The primary state result is zero and secondary-object acquisition returns null. No secondary dispatch occurs. F-feee9156a257 receives null.

6. **Index at the count boundary.** The converted index and count are both 5. The strict range check fails. No boundary or current-position operation occurs, and F-feee9156a257 receives the secondary object.

7. **Accepted interior position.** The index is 1, count is 3, start is 10, next boundary is 20, and current position is 14. The helper calls receive differences 10 and 4, respectively. If the record-first-word check succeeds, submission occurs with the stated fixed arguments and buffer length 8. If submission returns, F-feee9156a257 follows.

8. **Accepted endpoints.** For boundaries 10 and 20, current positions 10 and 20 both qualify. The relative-position difference is respectively 0 or 10.

9. **Zero-length interval.** Start, end, and current position are all 10. Submission remains eligible. Both helper values are zero.

10. **Last indexed interval.** The index is 2 and count is 3. The end boundary comes from the terminal-boundary operation, not an indexed request for 3.

11. **Reversed interval.** Start is 20 and end is 10. The current-position operation, payload preparation, and submission are skipped.

12. **Late zero first word.** The interval and current position qualify, but the record-first-word check returns zero. Both payload helper calls have already occurred before F-a817d8d58c10 is invoked.
