# F-70b6f3399924

## Purpose

F-70b6f3399924 is an externally directed state machine that can obtain an octet from F-a6985b136b4f and write it to a calculated address. External control words determine whether execution adopts the supplied arguments, recalculates arithmetic state, writes an octet, resets a counter, redirects dispatch, or returns.

The established behavior is not a conventional buffer-fill contract. The arguments are initially inactive; the initial destination base and offset are both zero. Writing an octet does not advance either component of the destination address. No capacity check, requested-write count, or termination bound is established.

Memory population is an inferred purpose. Interpreting the second argument as a length, or the result as a status or byte count, is unsupported.

This contract describes static evidence and qualified mathematical consequences. No runtime tests have been performed.

## Interface

### Arguments

The function accepts two signed 32-bit values.

| Argument | Established use |
|---|---|
| Address argument | Supplies the active destination base after an argument-adoption transition. |
| Arithmetic argument | Supplies the active operand used by subsequent calculation transitions. |

Both original argument values remain available for repeated adoption. Adoption replaces the two active values with those original arguments, not with previously transformed values.

Neither argument is validated. Zero and negative values receive no explicit rejection. There is no established relationship between the arithmetic argument and the amount of accessible destination storage.

### Result

The represented result is 64 bits. Its construction places a stack-sourced 32-bit quantity in the upper half and zeros in the lower half. No initialization of that source quantity is established.

Consequently, there is no deterministic upper-half value or established interpretation of the result. The zero lower half describes the represented construction; it does not guarantee a defined result in an execution model where reading the uninitialized quantity invalidates execution.

A return is possible only when dispatch selects the return operation. It is not guaranteed to occur.

## Behavior

### Persistent execution state

The function carries six conceptual state components:

- Active destination base.
- Active arithmetic operand.
- Pending destination offset.
- Encoded counter.
- Retained scratch value.
- Current selector.

All except the selector initially equal zero. The selector initially comes from the entry-selector word. The encoded counter remains within 0 through 65,535 after every normally completed visible assignment.

Dispatch interprets the current selector relative to the selector-origin value observed for that dispatch. The default successor is observed before the selected operation takes effect, including when the selected operation returns.

### Operation contract

| Operation number | Effect |
|---|---|
| 0 | Calls the octet dependency, writes one octet, replaces the counter, and selects the production/reset successor. |
| 1 | Attempts the return construction. |
| 2 | Clears the counter and selects the production/reset successor. |
| 3 | Adopts both original arguments and selects the default successor. |
| 4 | Selects the routing successor without changing carried arithmetic state or active arguments. |
| 5 | Replaces the destination offset and scratch value, and calculates a successor. |
| Any other value | Adopts both original arguments and selects the default successor. |

Production, reset, routing-only, and calculation preserve the active arguments. Adoption preserves the counter, offset, and scratch.

An unrecognized operation is therefore not an explicit error. It can form part of an indefinite dispatch cycle.

### Production

Each reached production operation calls F-a6985b136b4f without explicit arguments and consumes its result as one octet.

The call must return before the destination write occurs. After that return, the function observes the encoding coefficient and forms a 32-bit product with the retained scratch. The octet is then written at the active destination base plus the pending offset.

Only after the write does the function observe the counter coefficient. The replacement counter is the low 16 bits of the product of that coefficient and the previously formed scratch product, subject to the arithmetic qualifications below. The production/reset successor is observed afterward.

This establishes several observable boundaries:

- Dependency-side changes can affect the encoding coefficient used by the operation.
- A destination write that overlaps control storage can affect the subsequently observed counter coefficient or successor.
- Changes to the encoding coefficient after the scratch product has been formed do not change that retained product.
- No dependency-status check separates the dependency return from the attempted destination write.

Production preserves the active arguments, offset, and scratch. It neither advances the destination nor directly increments the counter. Consecutive production operations can overwrite the same octet.

### Reset, adoption, and routing-only behavior

Reset clears only the encoded counter. It does not discard a previously calculated offset or scratch value.

Adoption changes only the active arguments. In particular, an offset calculated before adoption remains available for a later write using the newly adopted address.

Routing-only dispatch changes the selector without an explicit dependency call or destination write. It preserves the active arguments and all carried arithmetic state.

### Calculation: arithmetic domain

The calculation contract below uses 32-bit words and modular arithmetic, except for explicitly stated 16-bit reductions. It describes the represented bit-level relationships when the reached expressions execute normally.

This qualification matters. Several represented products and sums use signed 32-bit operands. Overflow in those expressions is not made valid merely by a later mask or conversion. Other expressions involve unsigned operands and therefore have modular behavior. Conversion of an out-of-range unsigned result to a signed working value, signed right shift, and integer-derived addressing require the execution environment’s interpretation.

The formulas do not authorize substituting unlimited-precision arithmetic for intermediate operations.

### Calculation: transformed inputs and destination offset

A calculation uses two inputs:

1. The current encoded counter.
2. The low 16 bits of the active arithmetic operand multiplied by the argument coefficient.

Each input has its own encoding-coefficient observation and its own transformation-coefficient observations.

For an input \(z\), let \(H\) be its 32-bit encoding product with the low 16 bits cleared. Its transformed value is characterized by

\[
T(z)=Lz+(D-C_2)H+C_1-C_2 \pmod{2^{32}}.
\]

Here:

- \(L\) denotes the linear-coefficient observation.
- \(D\) denotes the upper-part-coefficient observation.
- \(C_1\) and \(C_2\) denote the two repeated-coefficient observations.

The subscripts distinguish expression roles, not a guaranteed order of observation.

Let \(X\) be the transformed counter and \(Y\) the transformed reduced arithmetic input. Their coefficient observations are separate. Equal values across the two transformations must not be assumed.

The new pending destination offset is \(X\) multiplied by the second-scale value observed specifically for offset formation. It does not come directly from \(Y\).

The transformation is not necessarily zero-preserving: for a zero input, its result is \(C_1-C_2\). It becomes zero under that condition only when the two repeated-coefficient observations agree.

### Calculation: routing

Routing uses three scaled words:

- \(a\): \(X\) multiplied by one first-scale observation.
- \(b\): \(Y\) multiplied by one second-scale observation.
- \(g\): \(Y\) multiplied by a separate first-scale observation, then reduced by one.

The scale observations are independent of one another and of the second-scale observation used for the offset.

The routing result can be specified without assigning it an unsupported comparison or length-check meaning. Define the following 32-bit words:

\[
P=a-1,\qquad S=a+b-1,\qquad U=P\lor S.
\]

Let \(K_1,K_2,K_3\) denote the three routing-mask occurrences. Define \(M\) by selecting, independently at each bit position:

- The corresponding bit of \(K_1\) where \(U\) is one.
- The complement of the corresponding bit of \(K_2\) where \(U\) is zero.

Then define

\[
N=
\left(M\oplus K_3\oplus(\neg S\land g)\right)
+
(\neg P\land g)
\pmod{2^{32}}.
\]

Under arithmetic right shift for the represented signed shift, the routing choice is the high bit of \(N\):

- A clear high bit selects the selector-origin occurrence associated with adding four.
- A set high bit selects the other selector-origin occurrence, without adding four.

Both selector-origin occurrences remain represented, including the one whose multiplier contributes zero. Their relative evaluation order is not established.

If the selected origin value equals the origin observed at the next dispatch, the clear-high-bit route selects operation 4 and the set-high-bit route selects operation 0. A changing origin can invalidate that correspondence.

When all three routing-mask observations agree, their common value cancels from this relation. That simplification is invalid when the observations differ.

### Calculation: scratch replacement

Calculation replaces the retained scratch with the encoded counter plus hexadecimal C5AB, with bit 16 cleared.

Clearing that bit is not generally a low-16-bit reduction. For this function’s reachable counter range, however, the sum cannot set bits 17 through 31. The replacement therefore equals addition of C5AB modulo 65,536.

Calculation preserves the encoded counter and active arguments. It performs no explicit destination write.

## Side effects

### Access ordering

The entry-selector observation precedes dispatch. Within each dispatch, the selector-origin observation precedes the default-successor observation.

For calculation, the established ordering between observation groups is:

1. Counter encoding.
2. Arithmetic-argument scaling and reduction, then encoding of that reduced value.
3. Counter transformation, then its first-scale observation.
4. Arithmetic-input transformation, then its second-scale observation.
5. The separate first-scale observation used for routing.
6. The separate second-scale observation used for the offset.
7. Routing-mask observations.
8. Successor-origin observations.

Scratch replacement occurs before successor construction.

This is not a complete ordering of every occurrence inside a compound expression. In particular, the repeated-coefficient occurrences, routing-mask occurrences, and successor-origin occurrences must not be assigned an invented left-to-right order.

Production has a distinct ordering guarantee: dependency return, encoding-coefficient observation and scratch-product formation, destination write, counter-coefficient observation and counter replacement, then successor observation.

## Acceptance examples

These examples are conditional static consequences, not executed tests. They assume all reached accesses and operations are valid under the stated execution model.

1. **Immediate return.** If the first selector and observed origin select operation 1, the default successor is nevertheless observed. No explicit dependency call or destination write precedes the attempted return. A deterministic upper result half is not required.

2. **Production before adoption.** If production is selected first, the active base and offset are zero. The dependency is called before the attempted write to the address represented by zero. The supplied address argument has not yet become active.

3. **Adoption preserves an existing offset.** If calculation establishes an offset, adoption follows, and production follows adoption, the destination combines the original address argument with that retained offset.

4. **Reset preserves pending destination state.** Reset clears a nonzero counter but preserves a nonzero offset and scratch. Later production uses both retained values for its destination and counter-replacement behavior.

5. **Repeated production overwrites.** Two production operations with no intervening base or offset change target the same destination. Counter replacement alone does not advance it.

6. **Unequal repeated-coefficient observations.** For a zero transformation input, observations of seven and three produce a transformed word of four. Equal observations produce zero.

7. **Zero-coefficient routing boundary.** If the arithmetic coefficients and scales remain zero throughout calculation, and the three routing-mask observations agree, both transformed values and the offset are zero. The routing quantity \(N\) is zero. With a matching origin at the following dispatch, execution selects operation 4, not production.

8. **Maximum reachable counter.** A counter of 65,535 yields scratch hexadecimal C5AA. This follows from the reachable range; it does not establish that clearing bit 16 is generally equivalent to retaining only 16 bits.

9. **Write-sensitive successor.** If the destination validly overlaps production/reset-successor storage, the octet write precedes observation of that successor. Its pre-write value alone does not determine the next selector.

10. **Dependency mutation affects production.** If the dependency changes the encoding coefficient before returning, the subsequently observed coefficient participates in the scratch product. Preservation of its earlier value is not required.

11. **Unrecognized-operation cycle.** Stable controls can repeatedly select an unrecognized operation. Such a cycle repeatedly adopts the original arguments without an explicit dependency call or return.
