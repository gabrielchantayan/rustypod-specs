# F-070d09a2a133

## Purpose

F-070d09a2a133 performs preparation through opaque dependencies, resolves a destination slot, and selects an update operation based on metadata preceding the payload referenced by a source slot. On normal completion, it returns the resolved destination slot address.

The established behavior distinguishes two cases using a 32-bit word located 12 bytes before the captured source payload address:

- **All ones:** if the source and destination slot addresses differ, invoke an opaque operation involving both payloads and their metadata. If the slot addresses are identical, skip that operation.
- **Any other value:** invoke two dependencies in order, then copy the source slot’s freshly read 32-bit value into the destination slot.

A managed payload representation is **inferred intent**, not an established ownership model. The visible behavior does not establish reference counting, allocation, destruction, sharing, or deep-copy semantics.

## Interface

### Explicit inputs

| Input | Representation and established use |
|---|---|
| Context address | A 32-bit integer-form value used as an address for a 32-bit read at byte offset 84, as the base of a stride calculation, and as an argument to F-e8bbeba61a78. |
| Selection value | An opaque 32-bit value passed as the second visible argument of the second call to F-b4a9589b2ea9. |
| Source slot address | An address of a 32-bit slot whose contents are treated as a payload address. Passed to F-4fcc06b56813 before the function explicitly reads the slot. |

The selection value is not established to be an index, key, length, or address.

The source slot’s entry-time contents are not necessarily the contents used for branch selection. Preparation dependencies execute before the explicit source-slot read and are not known to preserve it.

### Additional incoming machine state

In the all-ones, distinct-slot case, three additional 32-bit incoming machine-state values appear as arguments to F-5aa61f6c87d1. Two are incoming register-state values; the third is return-link-related state.

These values are not declared as explicit inputs in the visible three-input interface. Their semantic roles and required values are **documented_only**. They must not be treated as established flags, sizes, or ownership tokens.

### Output

On normal completion, the function returns the destination slot address obtained from the second call to F-b4a9589b2ea9.

The result identifies the slot, not necessarily the payload address held in that slot. The retained address is not visibly replaced by a branch dependency’s result. Whether its storage remains valid after dependency execution is unknown.

### Preconditions

The function contains no visible null, alignment, bounds, or address-validity checks. Each address must support the access actually reached, at the time of that access.

In particular:

- The context field must be readable before preparation begins.
- After preparation, the source slot and the discriminator preceding its captured payload must be readable.
- The all-ones, distinct-slot case additionally requires readable destination-slot contents and readable metadata four bytes before both relevant payload addresses.
- The non-sentinel case requires a readable source slot and writable destination slot after both branch dependencies return.

Dependencies may impose further preconditions. Their contracts are unavailable.

## Behavior

### Preparation and destination resolution

The first explicit memory operation is a 32-bit read at context offset 84. The function multiplies that field by 28 and adds the result to the context address. There is no separate fixed header offset in this calculation.

The visible dependency sequence is:

1. F-b4a9589b2ea9 receives the stride-derived value.
2. F-4fcc06b56813 receives that call’s result and the source slot address.
3. F-e8bbeba61a78 receives the context address.
4. F-b4a9589b2ea9 receives the preceding result and the selection value.

The result of the fourth call becomes the retained destination slot address.

The first and second appearances of F-b4a9589b2ea9 have different visible argument counts: one and two, respectively. The actual callable signature and the reason for this difference are unresolved. The contract preserves the visible uses without inventing a signature.

All four preparation calls precede the explicit source-slot read that controls branch selection. Their effects on the source slot, context, globals, or related storage are unknown.

### Capturing and classifying the source

After destination resolution, the function reads the source slot’s 32-bit contents and captures that value as the source payload address. It then reads the 32-bit word 12 bytes before that address.

An exact all-ones value selects the sentinel case. In the supplied signed 32-bit interpretation, this is negative one.

Every other bit pattern selects the non-sentinel case. Zero and negative values other than negative one do not select the sentinel case.

The captured payload address remains the basis for the branch’s source-metadata operations. A later change to the source slot does not cause the discriminator to be rechecked.

### All-ones discriminator: slot-identity check

The function compares the destination slot address with the source slot address. It does not compare their stored payload addresses.

If the slot addresses are equal:

- F-5aa61f6c87d1 is not invoked.
- Neither non-sentinel dependency is invoked.
- No direct branch-local slot assignment occurs.
- Execution proceeds to return the retained destination address.

This is not an invocation-wide no-op: preparation and source classification have already occurred.

### All-ones discriminator: distinct slots

If the slot addresses differ, F-5aa61f6c87d1 is invoked with these visible arguments, in argument-position order:

1. Destination slot address.
2. Zero.
3. The 32-bit word four bytes before the payload address read from the destination slot.
4. Captured source payload address.
5. The 32-bit word four bytes before that captured source payload address.
6. First additional incoming machine-state value.
7. Second additional incoming machine-state value.
8. Incoming return-link-related machine-state value.

Constructing these arguments requires reading the destination slot and then reading metadata relative to its contents. It also requires reading metadata relative to the captured source payload.

The supplied evidence does not establish the relative evaluation order between the source-metadata read and the destination-related reads. It does establish that the destination slot supplies the address needed for its associated metadata read, and that these argument reads occur after sentinel classification and the slot-identity decision.

No direct slot assignment is visible after F-5aa61f6c87d1 returns. Any payload copying, mutation, replacement, allocation, or disposal is dependency behavior and remains unknown.

### Non-sentinel discriminator

For every discriminator other than all ones, the function:

1. Invokes F-54e9fd6505cf with the captured source payload address minus 12.
2. After that call returns, invokes F-8a5aadac202f with the destination slot address.
3. After that call returns, rereads the source slot.
4. Writes the newly read 32-bit value into the destination slot.

The address supplied to F-54e9fd6505cf refers to the discriminator location associated with the earlier captured payload. The final assignment, by contrast, uses the source slot’s value after both dependencies have executed.

There is no slot-identity exemption in this case. Identical source and destination slot addresses still cause both dependency calls and the final read and write. Such an invocation is not established to be harmless self-assignment: the dependencies can affect the slot or its storage before the assignment.

### Return and abnormal completion

Following either normally completed branch, the retained destination slot address is returned.

There is no visible status result, explicit error branch, rollback, or local recovery path. If a dependency does not return normally, later operations are not established to occur. Earlier effects may already have happened.

## Side effects

### Direct effects

The function visibly performs:

- A 32-bit context-field read.
- A source-slot read and discriminator read after preparation.
- Conditional destination-slot and payload-metadata reads for the sentinel, distinct-slot call.
- A second source-slot read followed by one 32-bit destination-slot write in the non-sentinel case.
- The dependency calls described above.

The non-sentinel destination assignment is the only explicit memory write in the supplied body. This does not limit writes performed by dependencies.

### Dependency-mediated effects

All six distinct dependency identities may have effects not established by this body. There are seven static call sites because F-b4a9589b2ea9 appears twice. The reviewed function is not an additional called dependency.

No dependency is assumed to:

- Preserve globals or unrelated memory.
- Preserve either slot or either payload.
- Allocate or avoid allocating.
- Retain, release, destroy, or preserve storage.
- Preserve storage validity.
- Return normally.

The order of calls and subsequent reads therefore matters. In particular, a change to the source slot during preparation can change branch selection; a change during either non-sentinel dependency can change the value finally assigned.

### Ownership and aliasing

No definitive ownership transfer is established.

The non-sentinel sequence is compatible with source retention, destination release, and payload sharing, but those meanings are **inferred intent only**. The sentinel operation is likewise compatible with content transfer without establishing how it manages storage.

Only exact slot-address equality receives explicit handling, and only in the sentinel case. Distinct slots holding the same payload address do not satisfy that check. Support for other overlap, including overlap with context or metadata, remains **documented_only**; it must not be inferred from the absence of checks.

## Acceptance examples

These examples are conditional obligations derived from static evidence, not executed tests. Unless otherwise stated, assume valid accesses and normal dependency completion.

### Sentinel metadata with distinct slots

If the post-preparation source discriminator is all ones and the resolved destination slot differs from the source slot:

- Preparation completes before classification.
- F-5aa61f6c87d1 is called once.
- Its source payload argument is the address captured during classification.
- F-54e9fd6505cf and F-8a5aadac202f are not called.
- The retained destination slot address is returned.

The destination’s resulting contents cannot be specified without the called dependency’s contract.

### Sentinel metadata with identical slots

If the discriminator is all ones and both slot addresses are identical, the function skips F-5aa61f6c87d1 and performs no direct branch-local assignment.

Preparation and classification still occur. The invocation is not guaranteed to leave memory unchanged.

### Distinct slots referencing one payload

If two distinct slots hold the same payload address and its discriminator is all ones, F-5aa61f6c87d1 is still called. Payload-value equality does not bypass the operation.

### Non-sentinel boundary values

Discriminators of zero, one, and the 32-bit pattern representing negative two all select the non-sentinel sequence.

For each, F-54e9fd6505cf precedes F-8a5aadac202f, and the final destination assignment uses a source-slot read performed after both calls.

### Source replacement during preparation

If preparation changes the source slot from payload A to valid payload B, classification uses B and the word 12 bytes before B. Metadata associated with A does not determine the branch.

### Source replacement after non-sentinel classification

If classification captures payload A with a non-sentinel discriminator, and either branch dependency changes the source slot to B, the final assignment writes B, provided B is the slot’s value at the final read.

F-54e9fd6505cf still receives the address 12 bytes before A. Classification is not repeated.

### Non-sentinel identical slots

If source and destination are the same slot with a non-sentinel discriminator, both branch dependencies execute. The final read and write occur afterward. No safe no-op or payload-preservation guarantee follows.

### Abnormal dependency completion

If F-54e9fd6505cf does not return normally, the visible sequence does not establish execution of F-8a5aadac202f, the final slot read, the assignment, or the normal return. Prior preparation effects are not rolled back by any visible mechanism.

- Actual signature of F-b4a9589b2ea9.

- Supported overlap beyond the explicit sentinel slot-identity check.
- Concurrency, reentrancy, and synchronization requirements.
- Dependency validation, failures, and abnormal-exit behavior.

The stride calculation uses a 32-bit context representation and a 32-bit field interpreted as an integer, multiplied by 28. No widening or overflow guard is established. The evidence does not settle signed-overflow semantics, address wrapping, or supported negative field values. Subtractions used to reach payload metadata likewise have no visible validity checks.

The conservative precondition is that arithmetic and subsequent address use remain valid for the implementation and relevant dependencies. Wraparound, overflow recovery, and arbitrary negative offsets must not be promised as supported behavior.
