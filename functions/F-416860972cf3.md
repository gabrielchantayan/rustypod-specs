# F-416860972cf3

## Purpose

F-416860972cf3 conditionally copies a 16-bit memory value, may perform a second, value-addressed 16-bit write, and then enters an indefinite loop containing two indirect calls and a software interrupt.

No application-level purpose is established. The available evidence does not identify a protocol, data structure, ownership operation, or ordinary returning service.

Behavior depends on more than the five explicit arguments. Incoming machine state and the address of the fifth argument’s storage also participate in the conditions and address calculations.

This contract distinguishes:

- **Established static evidence:** operations and control relationships represented in the supplied material.
- **Conditional deductions:** consequences of interpreting word arithmetic and addresses as 32-bit quantities with the wrapping behavior described below.
- **Documented-only unknowns:** execution-environment details and external behavior not established by the representation.

No runtime tests have been performed.

## Behavior

### Initial transfer selector

Let \(x\) denote the second argument. The initial selector is the low 32 bits of:

\[
x \times 2^{19}.
\]

The initial transfer is selected exactly when that result is zero. Under the width model, the equivalent condition is:

\[
(x \mathbin{\&} \texttt{0x1fff}) = 0.
\]

Thus zero is not the only selecting argument. Every 32-bit value whose low 13 bits are clear selects the transfer, including `0x00002000`.

When this condition is false, the represented conditional prefix performs no explicit data-memory access. Its later conditional-write blocks are also skipped.

### Initial 16-bit transfer

When the selector is zero, the represented sequence is:

1. Calculate the destination as the source address plus the displacement, modulo \(2^{32}\).
2. Read an unsigned 16-bit value from the source address.
3. Update an internal address to the destination minus the adjustment word, modulo \(2^{32}\).
4. Write the previously read 16-bit value to the destination.

The displacement is measured in **bytes**. It is not multiplied by two for this transfer.

The source read precedes the destination write. Later gates do not suppress or undo this transfer. If displacement is zero, the represented behavior remains a read followed by a write to the same address; it is not an omitted operation.

No source-value reread is represented between this transfer’s load and store. Overlap, device-memory behavior, and access faults must therefore be considered with that ordering.

### Conditions for the additional write

The intervening arithmetic consists of zero-gated chains: each subsequent operation requires the preceding result to be zero. Consequently, the shift counts derived from those preceding results are zero on the paths that continue through these chains. Arbitrary nonzero shift behavior is not needed to characterize the reachable writes.

Under the 32-bit model, the additional-write block is reached only when all of the following hold:

- The initial selector is zero.
- The entry continuation is zero.
- The argument-storage address, logically shifted right by one, is zero.
- The comparison word equals the displacement.
- The updated internal address from the initial transfer equals the adjustment word.
- The accumulator word is zero.
- The argument-storage address plus twice the displacement is zero modulo \(2^{32}\).

The initial-selector condition also clears the separately tested bit of the second argument and its masked contribution to the accumulator addition. The carry into the final address gate is therefore zero on a continuing path.

These requirements simplify to the following complete conjunction:

| Requirement | Value or relation |
|---|---|
| Second argument | \((x \mathbin{\&} \texttt{0x1fff}) = 0\) |
| Argument-storage address | Zero |
| Entry continuation | Zero |
| Displacement | Either `0x00000000` or `0x80000000` |
| Comparison word | Equal to displacement |
| Accumulator word | Zero |
| Source and adjustment relation | Source address + displacement = twice the adjustment word, modulo \(2^{32}\) |

The storage-address restriction follows because shifting it right by one permits only zero or one. Adding twice a word cannot make the odd value one wrap to zero. With storage address zero, twice the displacement must wrap to zero, giving the two listed displacement values.

For displacement `0x80000000`, doubling produces the 32-bit value zero. A discarded high bit from that multiplication must not be treated as an additional carry input.

These are arithmetic reachability conditions, not a claim that an ordinary calling environment can place argument storage at address zero. Required memory accesses must also complete for execution to reach and finish the block.

### Additional value-addressed write

Within this block, the representation:

- Assigns an auxiliary machine-state quantity the argument-storage address multiplied by 64.
- Calculates a replacement continuation by adding 64 times the argument-storage address to the old continuation.
- Uses an unsigned halfword read through the old continuation as a numeric destination address.
- Writes a halfword formed by adding 15 to a halfword read through the old continuation.

On every path satisfying the derived conditions, the argument-storage address and old continuation are both zero. Thus:

- The auxiliary assigned quantity is zero.
- The continuation remains zero.
- The source halfword expression addresses zero.

The halfword expression appears separately in the destination calculation and the stored-value calculation. The representation does not establish the physical read count or the relative evaluation order of those uses. For mutable or device memory, the address-selecting value and arithmetic value must not be assumed identical.

For stable ordinary memory containing halfword \(h\), the resulting write is:

\[
\text{destination address}=\operatorname{zeroextend}_{32}(h),
\]

\[
\text{stored halfword}=(h+15)\bmod 2^{16}.
\]

The destination is the **loaded value interpreted as an address**, not necessarily the continuation address.

The initial transfer occurs before this block. If its destination aliases address zero, its write can affect the halfword used here.

### Later conditional memory blocks

Additional memory-manipulating blocks occur later in the representation, but they are unreachable under the stated model.

Their entry gates require the additional-write block to execute first. That block changes a gate operand from the zero selector to numeric address two, because it advances a halfword pointer by one. The subsequent chain requires another operand to be zero and then requires it to equal that address two. Both conditions cannot hold.

Accordingly, the reachable contract does not include the later apparent record writes, signed-halfword-derived writes, or additional pointer-based reads. This exclusion is a control-flow deduction, not a statement that those textual operations are harmless if reached under a different interpretation.

### Indefinite call-and-interrupt loop

After the prefix, the represented body repeats these operations in order:

1. Invoke **U-01** through the current continuation plus `0x0eb6` bytes, modulo \(2^{32}\).
2. Invoke **U-02** through numeric target `0x0857a94b`.
3. Issue **U-03**, a software interrupt with immediate `0x5b`.
4. Replace the internal continuation with `0x083d4cc2`.

The first call’s offset is 1883 halfword units, or 3766 bytes. It is not an offset of 1883 bytes.

U-01 receives three explicit 32-bit argument patterns:

| Argument | Bit pattern |
|---|---|
| First | `0x00000000` |
| Second | `0x00000000` |
| Third | `0xffffffa5` |

The third pattern represents −91 under signed 32-bit interpretation. Its meaning to the callee is unknown.

U-02 has no explicit arguments in the representation. That does not establish an absence of machine-state inputs.

The first iteration uses the entry continuation: the only reachable prefix block that replaces it requires both its old value and its increment to be zero.

After an iteration reaches and completes the interrupt and continuation assignment, the next U-01 target is `0x083d5b78`. No architecture-specific interpretation or normalization of the odd-valued U-02 target is assumed.

## Acceptance examples

These are conditional acceptance criteria, not executed tests. Successful memory operations and returning dependencies are assumptions only where explicitly stated.

### Selector excludes all conditional writes

For second argument `0x00000001`, the selector is nonzero. The prefix performs neither the initial transfer nor the additional value-addressed write.

This remains true even if the entry continuation, argument-storage address, displacement, comparison word, and accumulator word are all zero. Those values cannot substitute for the missing selector prerequisite.

Subject to reaching the loop, the first U-01 target is the entry continuation plus `0x0eb6`.

### Nonzero argument selects the transfer

For second argument `0x00002000`, a source halfword of `0xbeef`, and displacement six, the function reads `0xbeef` from the source and writes it six bytes after that source, assuming both accesses complete.

A nonzero entry continuation prevents the additional write but does not prevent this transfer.

### Zero displacement retains both accesses

For a second argument satisfying \((x \mathbin{\&} \texttt{0x1fff})=0\) and displacement zero, the initial transfer reads and then writes the same address. The represented write is retained even when stable ordinary memory would end with unchanged contents.

### Selected transfer can fail before any call

If the selector is zero but the source is unreadable, the initial read may fault before the destination write or either indirect call. No recovery or successful completion is promised.

### Restrictive additional write

Assume all of the following:

- The second argument satisfies \((x \mathbin{\&} \texttt{0x1fff})=0\), for example \(x=0\).
- Argument-storage address and entry continuation are zero.
- Displacement, comparison word, and accumulator word are zero.
- Source address is `0x00001000`.
- Adjustment word is `0x00000800`.
- Required accesses are permitted.
- Address zero stably contains halfword `0x0020` during the additional block’s reads.

The initial transfer reads and writes address `0x00001000`. The source/adjustment equality holds because twice `0x00000800` is `0x00001000`. The additional block then writes halfword `0x002f` at address `0x00000020`.

The zero-address storage and accesses require an environment that permits them.

### Halfword wraparound

Assume the same restrictive conditions, **including a second argument satisfying \((x \mathbin{\&} \texttt{0x1fff})=0\)**. If address zero instead stably contains `0xfffa` during the additional reads, the block writes `0x0009` at address `0x0000fffa`.

The stored result wraps at 16 bits. The destination remains the zero-extended original halfword.

### Loop progression

If U-01, U-02, and U-03 return so that an iteration completes, the next iteration invokes U-01 at `0x083d5b78`. Within each completed iteration, U-01 precedes U-02 and U-02 precedes U-03.
