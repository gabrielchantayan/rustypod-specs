# F-cd8542855c0d

## Purpose

F-cd8542855c0d interleaves indirect dependency calls with selected byte writes and computed 32-bit memory accesses. The displayed path retains values across calls, reuses earlier addresses and values, and eventually enters an unconditional call-and-write cycle.

No application-level purpose is established. Descriptions such as initialization, serialization, decoding, allocation, or device control would require evidence not supplied here.

This contract distinguishes:

- **Established static evidence:** explicit accesses, calls, value dependencies, and control-flow relationships in the supplied representation.
- **Conditional arithmetic interpretation:** calculated addresses and transformed values under 32-bit machine-word arithmetic.
- **documented_only unknowns:** dependency behavior, memory validity, execution-environment properties, and uncertainties in the recovered representation.

The supplied material warns about invalid instruction data, removed unreachable regions, and overlapping global symbols. This contract describes the displayed path; it does not establish that the original executable follows that path.

## Behavior

### Ordering and notation

The order below is the order of explicit accesses and dependency calls. Dependencies may introduce additional effects between those operations.

A **five-call sequence** consists of a call with the stated arguments followed by four calls with no displayed explicit arguments. When the sequence supplies a result, that result is the fifth call’s ordinary return.

A **four-call bridge** consists of:

- A call with the stated arguments.
- A call with no displayed explicit arguments.
- A call receiving the preceding call’s ordinary result.
- A call with no displayed explicit arguments.

Its output is the fourth call’s ordinary result.

These terms describe occurrence order, not shared callee identity. “No displayed explicit arguments” does not establish a complete ABI-level argument list.

**W**, **V**, **Q**, and the other named quantities below are contract labels for retained values, not additional memory objects or interface parameters. Their described reuse follows the displayed data flow; it does not establish a general rule that unknown callees preserve registers or globals.

Every continuation after a dependency call is conditional on that call returning normally to the displayed continuation.

### Initial selected byte writes

The routine first reads an unsigned selector byte at the incoming register-held address plus one. It writes the first input’s low byte to address **selector + `0x11`**.

A five-call sequence begins with the full first input. Its result is retained. The selector is then reread from the same selector location, and the newly selected destination receives the low byte of the first input shifted right by 22.

A second five-call sequence begins with four times the retained result. Its final ordinary return is not explicitly used.

Each selected destination lies between `0x11` and `0x110`, inclusive. The selector contributes directly to the destination address; it is not a pointer loaded from memory. The two destinations need not match because the selector is read separately around intervening calls.

### Captured global and third-input destination

After those calls, the routine captures the global associated with `0x3C`. The destination for its two explicit word writes is:

**4 × (third input shifted right by 7) + `0x14`**

The captured value is written there, followed by a five-call sequence beginning with that value. The same captured value is then written to the same destination again. There is no intervening explicit reread of the global.

Another five-call sequence begins with four times the preceding sequence’s result. Its result supplies the next stage.

For a 32-bit third input, this destination is four-byte aligned and ranges from `0x14` through `0x08000010`.

### First captured word

Let **A** denote the latest result. The routine writes **4A** at **16A + `0x14`**, then reads a word at **4A + `0x14`**. The captured word is **W**.

It also retains **H = A shifted left by 26**. Under the conditional 32-bit interpretation, only A’s low six bits contribute to H.

A four-call bridge receives **16A, 4A, H, 4A**, in that order. A five-call sequence begins with the bridge output.

The earlier write of 4A at 16A + `0x14` is then repeated using its retained address and value. Another five-call sequence begins with four times the latest sequence result.

The read capturing W follows the first write without an intervening dependency call. These addresses can alias; they are not guaranteed to identify separate objects.

### Second captured word

A four-call bridge receives **4B, 4B**. A five-call sequence begins with its output. The routine then writes **V shifted right by eight** to the address from which V was captured.

This is a transformation of the captured value, not a fresh read after the calls. A further five-call sequence begins with four times the latest result.

**8 × (W shifted right by 8)**

A four-call bridge receives the current four-times value and the W-derived offset. A five-call sequence begins with the bridge output and W shifted right by 16. The routine then writes that retained four-times value at **W-derived offset + `0x14`**.

- The W-derived offset again.

### Terminal cycle

If reached, each iteration performs the following ordered activity:

1. A five-call sequence begins with the current result and the accumulator shifted right by eight.
2. A fresh read at the retained terminal selector location selects a destination for a zero-byte write.
3. A five-call sequence begins with four times the preceding sequence result.
4. Four times the latest result becomes the next current result; that latest result shifted left by 26 becomes the next accumulator.

The first iteration’s second argument is zero because the initial accumulator is at most 31.

For later iterations, that argument equals the previous iteration’s final result’s low six bits shifted left by 18, under the conditional 32-bit interpretation.

These are conditional static examples, not executed tests. Arithmetic examples use the 32-bit interpretation, and later effects require successful earlier accesses and normally returning calls.

1. **Initial truncation.** With first input `0xFFFFFFFF`, both initial selected writes carry byte `0xFF`. Their destinations may differ because their selectors are read separately.

2. **Third-input grouping.** Third inputs 0 and 127 select `0x14`; input 128 selects `0x18`. This establishes destination grouping, not whole-routine equivalence.

3. **Captured global reuse.** If a dependency changes the global after capture, the second explicit write still uses the captured value. Its occurrence requires the intervening calls to return normally.

4. **Aliased capture.** If A is zero, the first word store writes zero at `0x14`, and the following W read also addresses `0x14`. For ordinary stable memory without external interference or read-side effects, W is zero.

7. **Non-returning dependency.** If the first dependency does not return normally, the initial selected byte write has already occurred, but the displayed continuation does not reach the second selector read. No rollback or alternate outcome is established.

8. **Terminal behavior.** If terminal setup completes, the first iteration’s second argument is zero. If all subsequent calls return normally and accesses succeed, the cycle continues rather than producing a completion status.
