# F-61178237911c

## Purpose

F-61178237911c conditionally invokes a lookup dependency and follows a bounded chain of indirect results. A terminal result supplies the function’s 32-bit return value. Rejected input, unsuccessful preparation, an absent lookup result, and excessive indirection all return zero.

Two distinct accesses to a global pointer-bearing location govern context handling:

- The pointer obtained at entry is retained for all lookup calls.
- When the first input is nonzero, the global location is read again. The pointer obtained by this second read is dereferenced to decide whether preparation is required.

These pointers can identify different cells if the global location changes between the reads. No dependency call occurs between those reads. The function does not establish synchronization or explain how such a change might occur.

“Preparation,” “lookup,” “key,” and “indirection” describe inferred roles. The established contract consists of the visible reads, writes, calls, branches, and return values; application-level meanings remain unspecified.

## Behavior

### Entry and zero-input path

The function first reads the global pointer-bearing location and retains the resulting pointer for lookup use. It then initializes request offset 4 to 1 and initializes the indirect-result counter to zero.

Only after those operations does it test the first input.

If the first input is zero, the function returns zero. On this path it does not:

- Read the global pointer-bearing location a second time.
- Dereference the retained pointer.
- Write the fourth input into the adjacent stack word.
- Call either dependency.

Thus, obtaining a pointer from global storage is unconditional, but dereferencing a context pointer is not.

### Nonzero-input path and preparation gate

For a nonzero first input, the function first writes the fourth input into the adjacent stack word.

It then reads the global pointer-bearing location again and dereferences the pointer obtained by this second read. This 32-bit cell value controls whether preparation is attempted.

The order is significant: the second global read follows the fourth-input write. The preparation gate does not use the pointer retained at entry. No dependency call occurs between the entry global read and this second global read.

If the preparation-gate cell contains a nonzero value, preparation is skipped and execution proceeds to lookup setup.

If the preparation-gate cell contains zero, the function writes the first input to request offset 0 and the third input to request offset 8, then calls F-ea867029bc2c. No explicit arguments are shown for this dependency.

A zero preparation return causes the function to return zero without a lookup. Any nonzero preparation return permits lookup setup.

The scratch writes precede preparation, but the visible call representation does not establish that the dependency receives or reads that storage.

### Lookup setup

Once the gate permits lookup, the function writes 1 to request offset 0 and the first input to request offset 8. These writes replace the preparation-stage values at those offsets, if preparation occurred.

Request offset 4 is not visibly rewritten at this point. Its caller-initialized value is 1; preservation across any intervening dependency is not established.

There is no subsequent test requiring either context cell to contain a nonzero value. In particular:

- A nonzero preparation-gate value can permit lookup even when the retained lookup cell contains zero.
- A nonzero preparation return can permit lookup even when the retained lookup cell contains zero.

### Lookup invocation and context selection

Each invocation of F-932a35189ea0 receives:

1. The current 32-bit contents of the retained lookup cell.
2. A pointer to the stack request.

The retained pointer comes from the first global read, not the preparation-gate read. The function rereads the cell through that retained pointer for every lookup.

Consequently:

- Lookup context values are not cached across calls.
- Changes to the retained cell’s contents can change later lookup arguments.
- Replacing the global pointer after entry does not redirect this invocation’s lookup-context reads.
- The second global read can affect preparation without changing which cell supplies lookup context.

There are no further explicit reads of the global pointer-bearing location after the preparation gate.

### Result classification

A zero lookup return ends processing with a zero return. No result fields are read on that path.

For a nonzero lookup return, the function treats the value as a result address and reads a 32-bit field at byte offset 4.

If that field is zero, the result is terminal. The function reads the 32-bit payload at byte offset 12 and returns it unchanged. This path does not increment the indirect-result counter.

Any nonzero classification field selects the indirect path. Its magnitude and sign have no further visible effect.

### Indirection and traversal bound

For an indirect result, the function increments the counter and compares the incremented value against 10.

If it exceeds 10, the function returns zero immediately. It does not read that result’s payload and does not perform another lookup.

Otherwise, it reads the payload at result byte offset 12, writes those 32 bits to request offset 8, and performs another lookup.

This establishes the following boundaries:

- The first ten indirect results supply replacement lookup keys.
- Ten indirect results may be followed by a successful terminal result.
- The eleventh lookup may succeed if its result is terminal.
- An eleventh indirect result returns zero without a payload read.
- At most eleven lookup calls occur in a normally returning execution.
- A zero indirect payload becomes the next key; it does not trigger the entry input gate again.
- Repeated keys and cycles are not detected separately.

The counter ranges from 0 through 11. Its visible increment does not approach a 32-bit overflow boundary. Payload handling copies 32 bits without key arithmetic.

## Acceptance examples

These are conditional consequences of static evidence, not runtime test results.

1. **Zero first input.**  
   Given a readable global pointer-bearing location, zero returns without dependency calls, a second global read, or a context-cell dereference. The captured pointer need not identify readable memory on this path.

2. **Nonzero gate and immediate terminal result.**  
   Given a nonzero first input and a nonzero value in the cell selected by the second global read, preparation is skipped. The first lookup receives the current value of the cell selected by the entry read. A terminal result returns its payload unchanged.

3. **Different cells: preparation skipped, zero lookup context.**  
   Suppose the entry read selects one readable cell, the second global read selects another, the preparation-gate cell contains a nonzero value, and the retained lookup cell contains zero. Preparation is skipped and lookup receives zero. This scenario assumes the differing reads can occur in the execution environment; no intervening dependency call is implied.

4. **Different cells: preparation required despite nonzero lookup context.**  
   Suppose the second read selects a zero-valued gate cell while the entry-selected cell contains a nonzero value. Preparation is still attempted. If it returns zero, no lookup occurs.

5. **Preparation succeeds without establishing nonzero context.**  
   Given a zero gate value, a nonzero preparation return, and a retained lookup cell still containing zero, lookup occurs with zero as its first argument.

6. **Successful traversal boundary.**  
   Ten indirect results followed by a terminal result produce eleven lookup calls and return the terminal payload.

7. **Rejected traversal boundary.**  
   Eleven indirect results return zero after reading the eleventh classification field. The eleventh payload is not read.

8. **Zero replacement key.**  
   An indirect result among the first ten with payload zero causes another lookup with request offset 8 set to zero. It does not end traversal by itself.

9. **Context changes between lookups.**  
   If a dependency changes the retained cell, the next lookup reads the changed value. If it changes only the global pointer, later lookup reads still use the entry-retained pointer.

10. **Zero terminal payload.**  
    A terminal result containing zero returns zero, indistinguishably from other zero-return outcomes.
