# F-d2985e5d19b0

## Purpose

F-d2985e5d19b0 conditionally creates and initializes a 16-byte auxiliary block, conditionally invokes an object-associated callback, and assigns a final 32-bit value to the object’s field at byte offset +0x10. Certain branches also register the object in a context field at byte offset +0x24.

**Established behavior:** two independent inputs select whether auxiliary initialization occurs and whether the final field comes from a supplied reference or from F-f4c5ae40135d. The callback and context updates occur only when auxiliary initialization is requested.

**Inferred intent:** the routine resembles object setup with an optional auxiliary structure and a supplied or default association. The meanings of the object, context, auxiliary structure, and final association are not established. In particular, the value returned by F-f4c5ae40135d is not established to be a pointer, identifier, timestamp, or status.

| Callback payload | Opaque 32-bit value | Forwarded unchanged as the callback’s second argument when a callback occurs. Otherwise unused. |

A nonzero supplied reference is interpreted differently by branch. With auxiliary initialization disabled, it is stored without being dereferenced. With auxiliary initialization enabled, it must support a 32-bit read at +0x0C.

The final write to object +0x10 occurs only after the preceding operations on the selected path return normally. An exception, fault, termination, or nonreturning dependency may prevent it.

### Auxiliary initialization disabled

The routine first writes a 32-bit zero to object +0x0C.

If the supplied reference is nonzero, the routine then writes that exact 32-bit value to object +0x10 and returns. It does not dereference the supplied reference, invoke the callback, or call any listed dependency on this path.

If the supplied reference is zero, the routine calls F-f4c5ae40135d without explicit arguments. It stores the returned 32-bit value at object +0x10 and returns.

The zero write to object +0x0C precedes that dependency call. The routine does not restore or otherwise revisit +0x0C afterward; changes made by the dependency are not assumed away.

### Auxiliary initialization enabled

The routine calls F-638beded7699 with two arguments: the numeric value 16 and a zero-valued second argument.

If the returned address is zero, it calls F-49825a8405da with the numeric value 4 and a fixed opaque second argument. The contents and interpretation of that second argument are not available.

There is no explicit recovery branch after the notification. If F-49825a8405da returns normally, execution continues with the zero allocation result: the routine stores zero at object +0x0C and then attempts a 32-bit zero write at address 0x0C. The source does not establish that the notification returns, nor does it establish a platform-specific outcome for that write.

For a successful allocation, the routine performs these writes in order:

1. Stores the allocated address as a 32-bit value at object +0x0C.
2. Writes 32-bit zero at allocated-block +0x0C.
3. Writes 32-bit zero at allocated-block +0x08.
4. Writes 32-bit zero at allocated-block +0x04.
5. Writes an 8-bit zero at allocated-block +0x00.

Only 13 bytes are explicitly initialized. Bytes +0x01 through +0x03 are not written by this routine. Their values depend on allocation behavior or other effects and must not be described as zero-filled from this evidence alone.

The auxiliary address is published in the object before its explicit initialization finishes. No explicit release of the previous value at object +0x0C occurs.

### Enabled initialization with a zero supplied reference

After auxiliary initialization, the routine resolves the callback through the object’s current dispatch table and calls it with:

- The object address.
- The unchanged 32-bit callback payload.

Only after the callback returns does the routine call F-3fdd14ecd250, without explicit arguments.

It then unconditionally writes the object address to offset +0x24 of the returned context. It does not read or test the prior field value. An existing nonzero value is overwritten.

Next, the routine calls F-f4c5ae40135d, without explicit arguments. It writes that dependency’s 32-bit result to object +0x10 and returns.

The ordering is significant: the context provider runs after the callback, and the final-value provider runs after context registration. This routine does not reread or restore the context field after the final-value provider returns.

### Enabled initialization with a nonzero supplied reference

After auxiliary initialization and before the callback, the routine reads a 32-bit context reference from supplied-reference +0x0C. That reference is captured for later use.

It then resolves and invokes the callback with the object and unchanged callback payload.

After the callback returns, the routine reads the 32-bit field at captured-context +0x24:

- If the field is zero, the routine writes the object address there.
- If the field is nonzero, the routine leaves it unchanged.

The field-value test therefore observes the value after the callback. However, the context reference itself was obtained before the callback. A callback change to supplied-reference +0x0C does not redirect the subsequent context operation.

Finally, the routine writes the original supplied-reference value to object +0x10 and returns. Neither F-3fdd14ecd250 nor F-f4c5ae40135d is called on this path.

## Side effects

On every normally completing path, this routine writes object +0x0C and object +0x10.

On enabled-initialization paths it also explicitly initializes the allocated block and performs a context-field operation. All such direct writes and their ordering are described above.

The callback observes execution after the auxiliary address has been stored and the explicit block initialization has completed. The routine has not yet performed its final write to object +0x10 at callback entry.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

1. **Disabled initialization with a nonzero reference.** Given writable object fields and a nonzero supplied reference, object +0x0C becomes zero and object +0x10 receives that reference. No dependency or callback is invoked. The reference need not support dereferencing for this path.

2. **Disabled initialization with a default association.** Given a zero supplied reference, object +0x0C is cleared before F-f4c5ae40135d is called. If that dependency returns a 32-bit value, that value is subsequently written to object +0x10.

3. **Enabled initialization with a default context.** Given successful allocation and normally returning dependencies, the allocation receives the specified ordered writes, the callback runs once, F-3fdd14ecd250 runs afterward, and its context +0x24 is overwritten with the object even if previously nonzero. F-f4c5ae40135d runs after that write.

4. **Captured context remains selected.** Given a nonzero supplied reference initially identifying context A through its +0x0C field, a callback change of that field to context B does not redirect registration. The post-callback test and possible write still address context A.

5. **Post-callback occupancy controls insertion.** If the callback leaves the captured context’s +0x24 nonzero, this routine does not overwrite it. If the callback leaves it zero, this routine writes the object there, regardless of its value before the callback.

6. **Selector magnitude is irrelevant.** Subject to identical dependency behavior and memory conditions, any two nonzero auxiliary-selector values select the same path.

7. **Initialization is partial.** Successful allocation does not by itself establish zero values at block bytes +0x01 through +0x03. Acceptance must not require those bytes to be zero without an additional allocator guarantee.

8. **Failure notification is not established recovery.** If allocation returns zero, F-49825a8405da is invoked before publication and initialization writes. If it returns normally, the subsequent low-address write remains part of the represented execution; graceful failure is not an established outcome.
