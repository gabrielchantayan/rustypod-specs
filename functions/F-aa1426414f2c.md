# F-aa1426414f2c

## Purpose

F-aa1426414f2c calls one dependency and then performs three ordered 32-bit OR updates at addresses selected using the first argument and a shared base-address value. The first update incorporates a shifted form of the second argument. The second and third incorporate a shifted value of one. Normal completion returns a 32-bit zero.

**Established static behavior:** each shift separately evaluates the low eight bits of a local control object. The dependency receives that object’s address. No destination/control disjointness guarantee is supplied, so an earlier destination write can change the count used by a later shift.

The shared base is captured after the dependency returns. The first update additionally evaluates the shared base separately for its read and write addresses. **All explicit shared-base evaluations finish before the first destination store.** The second and third updates use the captured value; no destination store is followed by another shared-base evaluation in this function.

**Inferred intent:** the three destination regions resemble a value region and two flag regions. Their application-level meanings and permitted indices are not established.

This is a static behavioral contract. Acceptance examples are conditional predictions, not reports of runtime execution.

## Behavior

### Displacement selection

Before calling the dependency, the function derives an index by subtracting the first argument’s logical right shift by five from six. It then uses four times that index as the byte displacement.

The right-shift result ranges from zero through 134,217,727. The subtraction occurs in the unsigned 32-bit arithmetic context supplied by the first argument, with the result assigned to a represented signed 32-bit index. Under the apparent signed interpretation, the resulting selections are:

| First argument | Index | Byte displacement |
|---|---:|---:|
| 0–31 | 6 | 24 |
| 32–63 | 5 | 20 |
| 192–223 | 0 | 0 |
| 224–255 | −1 | −4 |
| 4,294,967,295 | −134,217,721 | −536,870,884 |

Four times every index in this range fits within signed 32-bit bounds. This does not establish that adding the displacement to a base is valid or free of address-arithmetic overflow.

Consecutive groups of 32 first-argument values select the same displacement. Increasing the first argument by 32 decreases the displacement by four bytes, provided both arguments remain in range. Equal displacements do not imply equal overall behavior: the dependency receives the full first argument.

No visible range check confines the index to an intended array or region.

### Dependency call

The local control object is initialized from the fourth argument. F-d1db756204ac is then called once with:

2. The address of the local unsigned 32-bit control object.

No dependency return value is consumed.

### Base capture and use

After the dependency returns, the function captures the shared base value.

That captured value supplies the address origins for the second and third updates, respectively 32 and 64 bytes below the captured base, before applying the common displacement.

The first update instead uses separate evaluations of the shared base for its destination read and destination write. The evidence does not establish a relative order between those two evaluations. If intervening external activity can change the shared value, the capture, first read address, and first write address need not agree.

The capture and both first-update address evaluations are completed before the first destination store. No shared-base evaluation occurs after that store.

### Shift-count evaluations

Each update independently evaluates the local control object and takes its low eight bits as the represented shift count:

- The first evaluation supplies the count for shifting the second argument.
- The second supplies the count for shifting one in the second update.
- The third supplies the count for shifting one in the third update.

The resulting count lies between zero and 255. The mask does not establish a byte-sized memory load or valid 32-bit shift behavior throughout that range.

The counts are not captured once after the dependency call. If destination storage overlaps the control object:

- The first write may change the second and third counts.
- The second write may change the third count.
- Any overlapping write may change the final contents of the control object.

For each update, its shift is evaluated before its completed store. Its store cannot retroactively change its own already evaluated shift, but it can affect later evaluations. The relative order of the destination read and control evaluation within an update is not established.

### First update

The function reads a 32-bit destination word, ORs it with the second argument shifted left by the first independently evaluated count, and writes the 32-bit result.

With a stable shared base, both addresses are:

**shared base + byte displacement.**

Without that stability assumption, the read and write addresses may differ because their expressions evaluate the shared base separately.

No field clearing occurs. The second argument is not restricted to one bit. Where the shift has defined 32-bit semantics, every set bit in its result can contribute to the written word.

### Second update

After the first update completes, the function accesses:

**captured base − 32 bytes + byte displacement.**

It reads a 32-bit word, evaluates the control object again, shifts one by the resulting count, ORs the shifted value with the word read, and writes the 32-bit result back to that destination.

The first store may have changed the control object. It cannot change the captured base value used for this address calculation.

### Third update

After the second update completes, the function performs the corresponding operation at:

**captured base − 64 bytes + byte displacement.**

It evaluates the control object again rather than reusing the second count. An overlapping second write can therefore determine the third count.

After the third write, the function returns zero. No destination readback or consistency check is visible.
