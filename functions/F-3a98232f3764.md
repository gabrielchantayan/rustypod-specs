# F-3a98232f3764

## Purpose

F-3a98232f3764 performs an ordered sequence of memory reads and writes, then transfers control to an unresolved indirect target with four arguments.

The established behavior is memory mutation followed by indirect dispatch. Incoming values and loaded words are used both as numeric data and as addresses. In particular, two write addresses are obtained by doubling loaded values without adding a separate base.

**Inferred intent:** the accesses may update linked records before dispatching another operation. Record types, field meanings, and a dispatch protocol are not established and are not requirements of this contract.

This specification describes static evidence. No runtime tests have been performed.

## Interface

### Explicit inputs

The supplied representation exposes four explicit inputs:

| Role | Width | Observable use |
|---|---:|---|
| Destination address | 32 bits | Base for a byte write at offset `0x01` |
| First byte | 8 bits | Written at destination address + `0x01` |
| Payload word | 32 bits | Written into context memory and supplied to the indirect target |
| Second byte | 8 bits | Written into context memory |

The destination address is represented as an integer used as an address. The function does not check whether it identifies valid writable memory.

### Additional incoming state

Three additional 32-bit values are consumed without being initialized in the supplied body:

- **Primary base:** supplies the address of an initial word read and two writes.
- **Secondary base:** supplies write addresses and is itself written as both a byte and a complete word.
- **Context base:** supplies several write addresses and two word-read addresses.

These role names do not establish object types, allocation boundaries, ownership, or a conventional parameter-passing mechanism. The three bases need not identify distinct regions.

An indirect control-transfer target is also required. Its identity, origin, and selection mechanism are unresolved.

### Outputs and completion

No explicit scalar return value is established. The directly observable outputs are:

- Eleven memory writes, interleaved with five memory reads.
- Four arguments presented to the unresolved indirect target.
- Any subsequent behavior of that target, which is outside the established local behavior.

The supplied representation shows an indirect invocation followed by a return, but also identifies that invocation as an interpretation of an unresolved indirect jump. A conventional returning call, a tail dispatch, and other control-transfer details cannot be distinguished conclusively here. Neither successful return nor a return-value convention is established.

### Preconditions for successful completion

Successful execution of the complete represented sequence requires:

- Every reached address to support its indicated access width.
- Usable incoming values for the primary, secondary, and context bases.
- Address calculations to yield usable addresses under the actual execution environment.
- A valid indirect target and a compatible invocation environment.

The body performs no visible validation. Alignment requirements, overflow behavior, and access permissions are environmental prerequisites rather than checked conditions.

Non-overlap is not an established precondition. If accessed regions overlap, the order below governs which writes can affect subsequent reads.

## Behavior

### Widths and arithmetic

Access widths are:

- Byte: 8 bits.
- Halfword: 16 bits.
- Word: 32 bits.

All offsets in this specification are byte offsets. In particular, `0x64` means 100 bytes and `0x74` means 116 bytes.

The following constants have distinct uses:

- `0x0065`, decimal 101: the value of a halfword write.
- `0x00000064`, decimal 100: the value of a word write.
- `0x72`, decimal 114: the first argument to the indirect target.

When a 32-bit value is written through a byte-sized access, only its low eight bits are written. This occurs for the secondary base, the primary word, and the linked base described below. No later signed interpretation of those stored bytes is established.

Both doubled-address writes use a loaded 32-bit value as their arithmetic input. They are not shown as an index multiplied by an element size and added to a separate base. The representation does not establish overflow behavior, wraparound, or final pointer conversion for every possible input. Consequently, unrestricted mathematical doubling and modulo-\(2^{32}\) doubling must not be treated as interchangeable guaranteed semantics.

### Ordered access contract

Each read observes memory at its position in the sequence, after preceding writes. Names assigned to read results denote captured values, not references that are refreshed later.

| Order | Access | Value written or captured |
|---:|---|---|
| 1 | Write 8 bits at destination address + `0x01` | First byte |
| 2 | Write 32 bits at context base + `0x54` | Payload word |
| 3 | Read 32 bits at primary base + `0x14` | Capture the **primary word** |
| 4 | Write 8 bits at context base + `0x11` | Second byte |
| 5 | Write 8 bits at primary base + `0x09` | Low eight bits of the secondary base |
| 6 | Write 32 bits at primary base + `0x44` | Complete secondary-base value |
| 7 | Read 32 bits at context base + `0x04` | Capture the **linked base** |
| 8 | Write 16 bits at twice the linked base | `0x0065` |
| 9 | Read 32 bits at linked base + `0x64` | Capture the **forward word** |
| 10 | Write 8 bits at secondary base + `0x11` | Low eight bits of the captured primary word |
| 11 | Write 32 bits at secondary base + `0x54` | Decimal 100 |
| 12 | Read 32 bits at linked base + `0x74` | Capture the **dispatch word** |
| 13 | Read 32 bits at context base + `0x64` | Capture the **destination base** |
| 14 | Write 8 bits at context base + `0x09` | Low eight bits of the captured linked base |
| 15 | Write 32 bits at destination base + `0x54` | Captured forward word |
| 16 | Write 32 bits at twice the forward word | Captured destination base |

The first doubled-address store, at step 8, is the sixth attempted write. Before it, the sequence contains **five writes and two reads**.

If all accesses complete, the entire sequence contains eleven writes and five reads before the indirect transfer.

### Indirect-transfer arguments

After step 16, the unresolved target receives these represented arguments, in order:

1. The constant `0x72`.
2. The forward word captured at step 9.
3. The original payload word.
4. The dispatch word captured at step 12.

The second and fourth arguments are not reread from their source addresses at dispatch time. The third argument is the explicit payload input, not a readback of context base + `0x54`.

The supplied representation establishes four argument positions and their values. It does not establish physical argument locations, a complete calling convention, target identity, or the target’s interpretation of those values.

### Aliasing and captured values

Aliasing can change read results and final memory contents without changing the represented access order.

Examples of consequential overlap include:

- Either of the first two writes can affect the primary-word read at step 3.
- Writes through the primary base can affect the linked-base read at step 7.
- The halfword write at step 8 can affect the forward-word read at step 9.
- Writes through the secondary base can affect the dispatch-word and destination-base reads.
- Later writes can overwrite earlier input stores, constants, or source locations.

Exact address equality is not required. A byte or halfword write may modify part of a later word read. Determining the resulting numeric word then requires the target’s byte order.

Captured values remain stable for later uses within this sequence. For example, overwriting primary base + `0x14` after step 3 does not change the byte written at step 10. Likewise, overwriting linked base + `0x64` after step 9 does not change the forward word used at steps 15 and 16 or supplied as the second indirect argument.

There are no visible branches, loops, retries, or validation paths in the local access sequence.

### Distinct accessed ranges

Assume all individual accessed ranges are mutually non-overlapping. Let:

- First byte be `0xA5`.
- Second byte be `0x7E`.
- Payload word be `0x12345678`.
- Primary-word read yield `0xABCDEF42`.
- Linked-base read yield `0x00001000`.
- Forward-word read yield `0x00002000`.
- Dispatch-word read yield `0x55667788`.
- Destination-base read yield `0x00003000`.

The required effects are:

| Location | Required stored value |
|---|---|
| Destination address + `0x01` | Byte `0xA5` |
| Context base + `0x54` | Word `0x12345678` |
| Context base + `0x11` | Byte `0x7E` |
| Primary base + `0x09` | Low byte of the secondary base |

### Payload write affects the primary-word read

Assume context base + `0x54` equals primary base + `0x14`, with a complete-word overlap and no intervening conflicting write.

Step 3 captures the payload written at step 2. Step 10 consequently writes the payload’s low byte at secondary base + `0x11`.

Using the pre-entry contents of the primary-word location instead would violate the represented ordering.

### A later overwrite does not refresh the forward word

Assume the forward-word read at step 9 succeeds and the word write at step 11 subsequently overwrites its complete source location. Assume other operations do not invalidate subsequent accesses.

Steps 15 and 16 and the second indirect argument still use the value captured at step 9, not the replacement value 100.

### Dispatch observes an earlier constant write

Assume secondary base + `0x54` equals linked base + `0x74`, with complete-word overlap.

Step 11 writes word 100 before step 12 reads that same word. The fourth indirect argument is therefore 100. Later changes to its source location would not refresh this captured argument.

### Invalid first doubled address

Assume the first seven accesses complete, but doubling the linked base produces an address at which the halfword write cannot complete.

The sequence reaches this attempted write **after five earlier writes and two reads**. It is the sixth attempted write, not a sixth already completed write.

Successful completion is not established. The evidence provides no rollback, defined error return, or guarantee that later accesses or the indirect transfer occur.
