# F-7a159c0a77ed

## Purpose

F-7a159c0a77ed performs an extensive, ordered sequence of indirect dependency invocations, transforms selected returned bit patterns, modifies shared addressable state through mixed-width accesses, and finishes with an indirect control transfer.

The supplied static representation establishes these mechanisms, but not an application-level purpose. It does not establish that the function initializes an object, formats text, manages a collection, or implements a particular protocol. Repeated field-like offsets and character-sized constants are insufficient to assign those meanings.

This contract distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.
- **Inferred intent:** possible interpretations that are not acceptance requirements.
- **documented_only:** unresolved interface, execution, or dependency behavior.

No runtime tests have been performed. The contract is conditional on the supplied representation accurately describing executable behavior.

## Behavior

### Invocation phase

Before the first explicit data-memory store, the function invokes a long sequence of indirect dependencies. Target addresses are derived from control-address-like values plus a fixed displacement of 0xFFE. The first target depends on incoming execution context; subsequent targets are predominantly tied to fixed locations in the represented instruction sequence.

These are invocations of computed code addresses, not visibly reads of function pointers from a conventional dispatch table.

The sequence is ordered. A dependency result may be transformed and supplied to a later invocation, sometimes after intervening calls. Calls with no displayed arguments remain observable events; the absence of displayed arguments does not establish that they consume no implicit machine state.

Visible argument patterns include:

- A returned low word shifted left by eight bits.
- A shifted low word accompanied by an unchanged high word.
- The same transformed value supplied in more than one argument position.
- Explicit zero arguments alongside returned or secondary values.
- Values derived from an earlier result rather than the latest result.

Dependencies cannot be assumed to preserve globals, memory, or secondary machine values. Consequently, an invocation with an unused displayed return value cannot be treated as behaviorally irrelevant.

The supplied representation does not provide trusted identities or contracts for the individual intermediate dependencies. Their complete semantic effects remain **documented_only**.

### Bit extraction and arithmetic

An early invocation receives bits 16 through 25 of an incoming 32-bit value, repositioned into bits 6 through 15. The argument is therefore a multiple of 64 between zero and 65,472.

Later transformations select or reposition fields of several widths, including 24, 22, 20, 19, 17, 14, 13, 12, and 11 bits. These operations establish numerical selection, not a named record or packet layout.

Important distinctions are:

- Shifting a low word left by eight discards its original highest eight bits under a 32-bit bit-pattern interpretation.
- Masking to 24 bits before shifting left by six limits the result to bits 6 through 29.
- A 64-bit result shifted right by 34, 36, or 44 selects, respectively, the high word shifted logically right by 2, 4, or 12.
- Masking before a shift is not interchangeable with masking afterward.
- Successive truncating left shifts can erase a value completely.

Several intermediate values are explicitly set to zero and then shifted. Their derived argument values remain zero in the visible dataflow. This does not make the calls receiving them optional.

The representation also includes a variable right shift whose count is the low byte of a computed address. Counts can therefore exceed 31. Exact target behavior for those counts, and the signedness of the shift, are **documented_only**.

### Transition into direct state mutation

For describing the direct-memory phase, the following are mathematical labels, not implementation identifiers:

- **Packed base:** a dependency-produced low word shifted left by 25.
- **Scaled base:** another dependency-produced word multiplied by 2²⁵.
- **Small base:** twice a value obtained by masking a left-shifted word to 15 bits and then shifting right by six.
- **Final pair:** the last visible 64-bit dependency result before direct stores begin.

Under 32-bit truncating semantics, the packed base and scaled base have their low 25 bits clear. Their low bytes are therefore zero. The small base is an even number from zero through 1,016.

The opening memory effects have a significant order:

1. A word store through the high half of the final pair occurs before either byte store at packed base plus 9.
2. The first of those byte stores uses the low byte of the final pair’s high half.
3. A word store through a base derived from the final pair’s low half occurs between the two byte stores.
4. The second byte store uses the low byte of the packed base.
5. A zero word is then stored at scaled base plus 0x14.

Those intermediate writes remain part of the contract even where a later write targets the same address.

A byte is subsequently read from scaled base plus 5. Before that byte is stored as a zero-extended word at scaled base plus 0x34, a zero word is written at small base plus 0x14.

The function then reads scaled base plus 0x14, repeats the zero word store at small base plus 0x14, and performs two byte stores at small base plus 0x15 using the low byte of the loaded word.

The loaded word cannot be assumed to be zero merely because scaled base plus 0x14 was cleared earlier. An intervening store may alias it, and the supplied material does not establish isolation from external mutation.

### Linked and overlapping state updates

The middle direct-memory region uses offsets that resemble object fields, but their meaning is not established:

| Offset | Visible access characteristics |
|---:|---|
| 0x04 | 32-bit read |
| 0x05 | 8-bit read |
| 0x09, 0x0D, 0x11, 0x15, 0x19 | 8-bit writes |
| 0x14, 0x24, 0x34, 0x44, 0x54 | 32-bit reads and/or writes |

The offset written in decimal as 100 is 0x64, not 0x100.

This region includes:

- Writing address-like values back into storage associated with those values.
- Loading words from offset 0x74 and using them as subsequent address bases.
- Using an unsigned byte read at offset 5 as a base for a word read at offset 0x74.
- Repeatedly writing the same byte or word.
- Replacing a word first with a shifted value and later with another value.
- Writing a byte at offset 0x15, which may overlap a word at offset 0x14.

No disjointness between these locations is established. The contract therefore preserves access widths and order rather than specifying only final field values.

The function also accesses fixed low addresses. The visible widths include:

- A byte read at 0x05 and byte stores at 0x01 and 0x15.
- Word stores at 0x54 and 0x60.
- A word read at 0xA9.
- Byte stores at 0x3A, 0x67, and 0x21.

These may represent ordinary storage, special mappings, or inaccuracies in the supplied representation. None of those interpretations is established.

### Literal-value writes

A later region writes the numerical constant 0x3A at three locations using different widths:

- One byte through a base multiplied by four.
- One halfword through the same underlying value multiplied by eight.
- One word at offset 0x20 from the four-times-derived base.

Another word-sized location at offset 0x20 receives, in order:

1. 0x20.
2. 0x2F.
3. A zero-extended byte read from offset 4 of that same base.
4. 0x20 again.

The byte read occurs after the first two stores. It is not an initial-state snapshot.

These constants do not establish text output, encoding, termination, or a formatting API.

### Repeated publication region

A shared word is loaded once and used as an address base for a long, explicitly repeated publication region.

Each repeated group retains the following write order:

- A 32-bit store at a scaled destination plus 0x54.
- An 8-bit store at the shared base plus 0x19.
- An 8-bit store at a second base plus 0x11.
- A 32-bit store at the shared base plus 0x34.

The initial group uses a different value for the last word store than the subsequent repeated groups. Later groups visibly reuse the same computed operands without intervening explicit reloads of the shared base.

The repetition must not be reduced to a single final-state update when stores are observable. The exact repetition count is **documented_only** in this contract; it is not replaced by an invented loop bound.

### Final mutation and handoff

After the repeated publication region, the function reads several words before issuing another series of overlapping updates.

A word read at fixed address 0xA9 supplies a low byte later stored at fixed address 0x67. That byte is then used for the store at fixed address 0x21. Later reads of fixed byte storage must not automatically be replaced with the earlier captured value when intervening writes could alias it.

The final region includes:

- A byte store of 0x6C at a computed base plus 8.
- Byte stores at offsets 9, 0x0D, 0x10, and 0x11.
- A word store that replaces the four bytes starting at offset 0x10.
- A variable-shift-derived byte store.
- Word updates at offsets 0x44, 0x54, and 0x74.
- A halfword store of 0x0065 at twice a loaded address-like value.
- A word store of decimal 100 at offset 0x54.
- A final word store at twice another loaded value.

The terminal indirect transfer follows these writes. It receives four displayed arguments: 0x72, a previously loaded word, an earlier saved word, and a word read from offset 0x74.

A return is represented after that invocation. Whether the actual transfer returns normally is **documented_only**.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

### Incoming field extraction

If the incoming register-carried value is 0x03FF0000, the early extracted argument is 0xFFC0. If only bits outside positions 16 through 25 differ, this particular argument is unchanged. Other behavior need not be unchanged.

### Low-word truncation

If a dependency result has low word 0x12345678, a visible 32-bit left shift by eight yields 0x34567800. A paired high word passed unchanged must not acquire the discarded 0x12.

### Byte widening

If the byte read from scaled base plus 5 is 0xFE, its subsequent word store at offset 0x34 carries 0x000000FE, provided execution reaches that store. Sign-extending it to 0xFFFFFFFE would violate the displayed widening.

### Ordered overwrites

If the word destination in the literal-value region is observable, acceptance requires the stores of 0x20 and 0x2F, the intervening byte-derived word, and the final 0x20 in that order. A final value of 0x20 alone does not demonstrate equivalent behavior.

### Mixed widths

If the 0x0065 halfword destination is ordinary writable memory, the access writes two bytes, not four. Surrounding bytes are not implicitly cleared.

### Aliasing

If small base plus 0x14 aliases scaled base plus 0x14, the intervening small-base store participates in the later read’s value. Acceptance must use ordered accesses, not independent object-field assumptions.

### Failure before handoff

If a direct store faults before the terminal transfer, the contract does not require F-U02 to be invoked or earlier writes to be undone.
