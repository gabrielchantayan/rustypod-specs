### Widths, arithmetic, and address notation

A selector read obtains one unsigned byte, in the range 0–255. A byte store retains the low eight bits of its value. Word accesses are 32 bits.

One dependency result is represented as 64 bits. Its low 32 bits become an unsigned quantity; its high 32 bits are converted to a signed 32-bit quantity. Neither the actual return convention nor the meaning of those halves is established.

For the descriptions below:

- A **selector transfer** reads a byte at a specified address and writes a byte at the address equal to that selector plus 17.
- A **word slot** indexed by \(x\) has calculated address \(4x+20\).
- A **wide-stride slot** indexed by \(x\) has calculated address \(16x+20\).
- A **scaled index** is the represented 32-bit result of multiplying an index by four.

These names describe arithmetic, not structures, object boundaries, or allocation.

Unsigned 32-bit multiplication, addition, and left shift use modulo-\(2^{32}\) arithmetic in the represented type model. Unsigned right shifts are logical. Several index calculations and shifts instead have signed operands; their overflow and negative-operand cases are not assigned unsigned wrapping semantics by this contract.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes preceding operations complete and relevant addresses are accessible.

1. **Byte truncation.** If D-01.1 supplies 65 and the first selector is 7, the first store writes 4 at address 24. The calculated value is 260; only its low byte is stored.

2. **High-field truncation.** If the initial value is `0x3ff00000`, the phase-2 mask and shift produce `0x3ff`. The byte store writes `0xff`, not a ten-bit value.

3. **Zero selector transfer.** If the phase-3 read at address one supplies 255, the zero byte is written at address 272. The representation does not first reject address one.

4. **High-half destination.** If D-04.9 has high half 3, phase 4 stores a 32-bit zero at address 32. This does not guarantee the location remains zero after later calls.

5. **Unsigned wrap.** If the low half is 16, phase 6’s first calculated destination is address 20 and its stored value is `0x40000000`, under the represented unsigned 32-bit arithmetic.

6. **Different stride addresses.** If D-06.10 supplies 2, phase 7 stores 8 at address 52. The following two read expressions address 28, not 52.

7. **Captured value survives later memory mutation.** If phase 10 captures `0x12345000`, its later extraction store writes `0x00012345`, even if dependencies subsequently change the original read location. The captured value, rather than a fresh read, supplies that store.

8. **Final selector reread.** If the phase-12 selector is 2 and dependencies change the same selector storage to 9 before phase 13, the two final byte destinations are 19 and 26 respectively. Both transfers remain present even when their calculated byte values happen to match.

9. **Conditional terminal boundary.** If every preceding operation completes, the represented path reaches the invalid-data marker. Acceptance cannot require a normal return or a specific physical exception beyond that marker.
