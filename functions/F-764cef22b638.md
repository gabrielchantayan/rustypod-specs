# F-764cef22b638

## Purpose

F-764cef22b638 inspects a byte-encoded table containing 16-bit range endpoints, adjustments, relative offsets, and optional indirect mapping words. It checks table structure, classifies selected ordering anomalies in permissive mode, and checks selected indirect mapping values in nonzero modes.

Its directly visible outcomes are:

- A 32-bit unsigned return mask describing certain ordering anomalies.
- Calls to F-7b0b9523800e with error code 8 or 16.
- Reads from the table, context, an externally referenced global, and reachable indirect storage.

An error report is not an explicit termination point. Subsequent behavior depends on whether F-7b0b9523800e returns and whether it changes accessible state.

The layout suggests a segmented mapping format. That is inferred intent, not a prerequisite for the behavioral contract.

## Interface

### Arguments and context

The two arguments are represented as 32-bit address-bearing integers:

- **B:** table base address.
- **C:** context base address.

The function directly uses these context fields:

| Offset from C | Width | Established use |
|---|---:|---|
| 4 | 32 bits | Upper address bound for accessible table storage |
| 8 | 8 bits | Validation mode |

Context fields are native scalar loads, unlike the table’s explicitly big-endian words.

Mode is read repeatedly. With stable context storage:

- **0:** classifies ordering anomalies into return bits; uses the context upper address bound for ordinary indirect storage; does not scan mapping values after successful bounds checks.
- **1:** reports ordering anomalies; uses the effective table extent for ordinary indirect storage; scans mapping values.
- **2–255:** additionally checks strict header conditions and a terminal word.

These classes do not imply that one mode snapshot governs the entire invocation.

### Table layout

Every table word below is an unsigned 16-bit value assembled from a high byte followed by a low byte.

Let **N** be the word at B+6 shifted right by one. Its range is 0–32,767.

| Address | Size | Role |
|---|---:|---|
| B+2 | 2 bytes | Declared length |
| B+6 | 2 bytes | Encoded entry count |
| B+8 | 2 bytes | First strict search parameter |
| B+11 | 1 signed byte | Strict search exponent |
| B+12 | 2 bytes | Second strict search parameter |
| B+14 | 2N bytes | Range ends |
| B+16+2N | 2N bytes | Range starts |
| B+16+4N | 2N bytes | Adjustments |
| B+16+6N | 2N bytes | Relative offsets |
| B+16+8N | — | Minimum accepted ordinary indirect-storage address |

The two bytes between the end array and the start array are not directly checked as padding. No direct validation of B+0 or B+10 is visible.

Adjustments are decoded as unsigned values from 0 through 65,535. Their later use is modulo 65,536.

### Return value

The result starts at zero. Only bits 0 and 1 are directly set.

For a noninitial entry whose start is at most the immediately preceding end, when the mode read for ordering is zero:

- **Bit 0:** the current start is strictly below the preceding start; otherwise, the current end is strictly below the preceding end.
- **Bit 1:** neither of those conditions holds.

Thus bit 0 is not restricted to strict containment. A range entirely below its predecessor can set it, as can a range with the same start and a smaller end.

Bits accumulate across entries. The result is not a general success indicator: structural and mapping errors may leave it unchanged, and a nonreturning dependency may prevent any result.

## Behavior

### Effective table extent

The function first reads the declared length at B+2. A value below 16 causes an error-8 call, without an explicit return.

It then compares B plus that cached length with the context bound at C+4. If the declared extent exceeds the bound:

1. A mode read determines whether error 8 is reported: nonzero reports; zero does not.
2. If execution continues, C+4 is read again.
3. The effective length becomes that newly read bound minus B.

Consequently, a returning error dependency may change the bound used for truncation. No separate check establishes that this bound is at or above B.

### Entry count and fixed storage

The count’s low byte at B+7 is read before its high byte at B+6. Those bytes remain the basis of the decoded count even if a subsequent error call changes the table.

If a fresh unsigned mode read exceeds 1 and the encoded count is odd, error 8 is reported. Continuing execution still derives N by shifting the encoded word right by one.

The effective length must be at least **16 + 8N**; otherwise error 8 is reported. For the maximum N, this expression is 262,152, within unsigned 32-bit range.

With an ordinary, unmodified 16-bit declared length, N greater than 8,189 cannot satisfy this fixed-storage requirement.

### Strict header checks

A fresh mode read greater than 1 enables the following reads, in this field order:

1. The word at B+8.
2. The signed byte at B+11.
3. The word at B+12.

An odd low bit in either word produces one error-8 call.

Let **P** and **Q** denote the two words shifted right by one, and **E** the signed exponent. For defined arithmetic, the subsequent combined check accepts only when:

- P ≤ N ≤ 2P.
- P + Q = N.
- A signed 32-bit one shifted left by E equals P.

Failure produces error 8. These comparisons use the captured header values, including after a returning parity-error call.

There is no preceding range check for E. Negative counts, excessive counts, or signed shifts without a defined result are **documented_only**. The shift is conditionally evaluated; failing earlier consistency conditions can bypass it.

### Array boundaries and terminal check

The function calculates the array addresses and the indirect-storage lower bound B+16+8N.

A fresh mode read greater than 1 also enables a two-byte read at **B+12+2N**. This is the final end-array entry when N is positive, but the header word at B+12 when N is zero.

The represented comparison tests that unsigned two-byte concatenation against negative one, reporting error 8 when unequal. Under ordinary promotion of an unsigned 16-bit value to a 32-bit integer, no encoded word equals negative one.

A maximum-value terminal sentinel is plausible intent, but replacing this comparison with equality to 65,535 is not established. The intended machine-level interpretation remains **documented_only**; strict-mode acceptance must retain this qualification.

### Entry traversal and ordering

Entries are visited in increasing index order. For each entry, the fields are read in this order:

1. Start.
2. End.
3. Adjustment.
4. Relative offset.

All four reads precede range validation. This describes field-level sequencing, not an independently established ordering between the two byte loads within every word expression.

An end below its start causes error 8. Continuing does not repair or discard the captured entry.

For every entry after the first, the function compares the current start with the immediately preceding end. If the current start is greater, no ordering action occurs. Otherwise, a fresh mode read selects:

- **Mode zero:** set bit 0 if the current start is strictly smaller than the preceding start. Only if it is not smaller does the current end determine the classification: a strictly smaller end sets bit 0; all remaining cases set bit 1.
- **Nonzero mode:** report error 8 without setting an ordering bit.

The first start comparison can decide bit 0 regardless of the current end. Equal starts therefore do not necessarily select bit 1. Equal ends do not necessarily select bit 1 either: a smaller current start still selects bit 0.

Only the immediately preceding entry participates. There is no running maximum end or comparison against every earlier range. After normal completion of an entry, its captured endpoints become the predecessor values, even if it caused a returning error call.

### Zero and special relative offsets

A zero offset bypasses indirect-storage bounds and mapping-value checks. Direct mappings implied by endpoints and adjustment are not checked here.

A nonzero offset is compared with an externally referenced global value. Equality selects a special path rather than address formation.

On that path, a fresh unsigned mode read must be below 2 to attempt special acceptance. The final-entry condition and endpoint comparisons are then evaluated as follows:

- An initial conjunction checks that this is the final entry, that the current start equals a fresh global reference, and that the current end equals another fresh global reference. Short-circuiting can omit endpoint references.
- The same conjunction is evaluated again, with fresh global references wherever reached.
- Only when this second conjunction succeeds is the adjustment comparison with 1 evaluated.
- If the second conjunction fails, the first conjunction’s result remains the acceptance decision.

With **stable global storage**, special acceptance therefore requires mode below 2, a final entry, both endpoints equal to the global, and adjustment 1.

With changing global storage, adjustment 1 is not an unconditional requirement. For example, a true first conjunction followed by a false second conjunction retains acceptance without evaluating the adjustment comparison.

Failure of special acceptance produces error 8. If that call returns, the function advances to the next entry; it does not reinterpret the special offset as an ordinary address.

### Ordinary indirect-storage bounds

For any other nonzero offset, the candidate address is the address of that entry’s offset word plus the unsigned offset.

The required exclusive upper address is:

**candidate + 2 × (end − start) + 2.**

For valid endpoints and nonwrapping arithmetic, this reserves one word for every value in the inclusive range.

The lower bound is B+16+8N. The upper bound depends on a fresh mode read:

- Zero uses C+4, read if the upper-bound comparison is reached.
- Nonzero uses B plus the cached effective length.

The lower-bound failure short-circuits the upper-bound comparison. A candidate below the lower bound or an exclusive upper address above the selected upper bound causes error 8. Equality passes either comparison.

After a successful zero-mode bounds path, no mapping scan occurs. After a bounds error, a returning dependency is followed by another mode read: zero skips scanning; nonzero proceeds to it. A successful nonzero-mode path proceeds directly to scanning without that additional mode read.

Thus a bounds report is not a memory-safety barrier. A handler that returns can permit subsequent reads outside the reported bounds.

If end is below start, the span subtraction is unsigned 32-bit arithmetic rather than a negative mathematical span. Such malformed input does not describe a meaningful safe storage requirement.

### Indirect mapping scan

The scan visits positions corresponding to range values from the start up to, but excluding, the end. Its pointer advances two bytes per iteration.

Therefore:

- Equal endpoints produce no mapping reads.
- A two-value inclusive range checks only its first word.
- The bounds calculation nevertheless reserves both words.

At each visited position:

- A zero word bypasses the mapping-limit comparison.
- A nonzero word is added to the adjustment and reduced modulo 65,536.
- An adjusted result greater than or equal to the unsigned limit at C+400 causes error 16.

The sum of two decoded 16-bit values fits within 32 bits before reduction.

The representation includes a second word reference for calculating a nonzero word’s adjusted result. It does not establish a stable word snapshot between the zero test and that calculation. The context limit is also referenced during scanning rather than cached for the invocation. The relative order of operand reads within the limit comparison is not independently established.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, assume stable readable storage, valid nonwrapping addresses, sufficient fixed-array extent, and an error dependency that returns without mutation.

1. **Empty permissive table.** Mode 0, N=0, length 16, and a sufficient context bound produce result zero without entry reads.

2. **Overlong permissive declaration.** In mode 0, a declared extent beyond C+4 is replaced by the available extent without an error for that mismatch. Insufficient fixed-array space can still produce error 8.

3. **Backward disjoint range.** In mode 0, [10,30] followed by [5,8], with zero offsets, produces bit 0. The current start is below the preceding start; geometric overlap is not required by this classification.

4. **Equal starts, smaller end.** [10,30] followed by [10,20] produces bit 0 in mode 0. [10,30] followed by [10,30] instead produces bit 1.

5. **Equal ends, smaller start.** [10,30] followed by [5,30] produces bit 0 in mode 0.

6. **Shared endpoint.** [10,20] followed by [20,30] produces bit 1 in mode 0. Mode 1 reports error 8 instead of setting an ordering bit.

7. **Nonoverlapping ascending ranges.** [10,20] followed by [21,30], with zero offsets, sets neither ordering bit.

8. **Exact storage fit.** An ordinary candidate equal to the indirect-storage lower bound, with its exclusive upper address equal to the applicable upper bound, passes bounds comparisons. A successful mode-0 path does not scan it.

9. **Unscanned final word.** In mode 1, [10,11] reserves two words but examines only the first. An excessive value solely in the second word does not cause error 16 through this scan.

10. **Modulo adjustment and zero exemption.** A scanned word of 65,535 with adjustment 1 yields zero. Limit 1 accepts that adjusted value; limit zero causes error 16. An original word of zero bypasses the comparison even with limit zero.

11. **Stable special entry.** With a stable global value from 1 through 65,535, a final entry whose endpoints and offset equal that value, adjustment 1, and mode below 2 takes the special acceptance path.

12. **Changing-global special acceptance.** If the offset matches its initial global reference, mode is below 2, the first endpoint conjunction succeeds, and the second fails because a later global reference differs, special acceptance retains the first result. Adjustment need not equal 1 on this path.
