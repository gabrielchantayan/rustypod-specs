# F-354391572878

## Purpose

F-354391572878 groups fixed-size input records by a signed 16-bit coordinate, builds a circular membership list for each group, installs record-to-group back-pointers, and derives per-group classification and neighboring-group information.

The grouping criterion is distance from a group’s stored coordinate, not distance from the most recently added member. The first matching group in storage order wins. Existing group coordinates are not updated when additional records join.

These statements describe behavior visible in the supplied static evidence. The application meaning of coordinates, classifications, and neighbor relationships is not established.

## Behavior

It also calculates the secondary-structure address and captures the context field at offset 0. It then writes zero to the selected context group-count field.

The function next captures the mode value:

### Distance threshold

### Group assignment and circular-list construction

Input addresses are visited in ascending 48-byte steps while the current address is below the captured end address under an unsigned comparison.

For each input record, the function searches groups from index zero upward. During this search, it rereads the context group count and obtains candidate addresses from the context group-array base. The group count is interpreted as signed for the loop comparison.

A candidate group matches when:

\[
|\text{record coordinate}-\text{group coordinate}| < \text{threshold}.
\]

Both coordinates are sign-extended from 16 bits before subtraction. Their difference and absolute value fit within signed 32 bits.

The inequality is strict. Equality with the threshold is not a match. A zero or negative threshold cannot match any coordinate distance.

If no group matches, F-f95622508985 receives:

- The address of the selected context block beginning at offset \(48+28s\).
- The record coordinate, sign-extended to 32 bits.
- The previously captured context value from offset 0.
- The address of the mutable descriptor-address slot.

A nonzero result ends the function immediately. On zero, the descriptor address currently held in that slot is used.

The new descriptor and record are then initialized in this observable order:

1. An unmapped dependency is called with the descriptor address and size 48.
2. The descriptor head is set to the current record.
3. The descriptor tail is set to the current record.
4. The descriptor coordinate is copied from the record.
5. F-74efb2674226 is called again, this time with two observed arguments: the sign-extended record coordinate and the captured mode value.
6. Its 32-bit result is written first at descriptor offset 8, then at offset 4.
7. The record’s membership successor is set to itself.

The unmapped dependency’s behavior is not established. In particular, clearing the descriptor cannot be assumed merely from its address-and-size arguments.

If a group matches, the function appends the record to its circular list:

1. The new record’s successor receives the group head.
2. The old tail’s successor receives the new record.
3. The group tail receives the new record.

This preserves input order within a well-formed group ring. The group coordinate and converted values are not recomputed.

### Membership back-pointers

After all input records have been considered, the function reads the selected group-array base and group count and derives a fixed end address for a 48-byte-stride group traversal.

For each group with a nonzero head, it follows membership successors and writes the group address at offset 8 of every visited record. Traversal stops when the successor returns to that group’s head.

All groups receive this back-pointer pass before relationship analysis begins. Consequently, relationship analysis can consult the group pointer of another record even if that record belongs to a later group.

There is no traversal bound, cycle validation, or null-successor handling. A malformed ring may fail to terminate or cause an invalid access.

### Per-group aggregation

The function then processes groups in ascending descriptor-address order.

Unlike the back-pointer pass, this pass does not skip a zero head. Every visited group must therefore have a valid, nonempty membership ring for defined successful operation.

For each member:

- Bit 0 clear at record offset 0 increments the clear-bit count.
- Bit 0 set increments the set-bit count.
- The signed difference between offsets 6 and 4 is calculated.
- If the byte at offset 1 equals the selected mode byte, the difference is added to the matching total.
- Otherwise, it is added to the other total.

Negative extent differences are retained. No absolute value, endpoint ordering check, or clipping is applied.

### Relationship selection

For each member, the second relationship candidate, at offset 20, is considered an external candidate when it is nonzero and its record-to-group back-pointer differs from the current group.

If such an external candidate exists, it takes precedence over the first relationship candidate at offset 16. Otherwise, the first candidate is considered if nonzero.

The two cases maintain separate selected-group fields:

- First-candidate path: group offset 24.
- External second-candidate path: group offset 28.

For the applicable field:

- If no group is currently selected, the candidate record’s back-pointer becomes the selection.
- Otherwise, the existing selection is replaced only when the absolute coordinate difference between the current member and candidate record is strictly smaller than the absolute coordinate difference between the current group and the already-selected group.

Thus, the comparison uses different pairs on its two sides. It is not simply a nearest-group search. Equal distances retain the existing selection.

The function does not explicitly clear either selected-group field before this processing.

On the external second-candidate path, bit 1 is ORed into byte 12 of the selected target group, including when the existing selection is retained. This write targets the selected group, not necessarily the candidate record’s group.

### Final classification and relationship conflict handling

After traversing a group’s members:

1. Byte 12 is written as zero.
2. It is written as one if the set-bit count is positive and at least as large as the clear-bit count.
3. Byte 13 is written as 4.
4. Byte 13 is then replaced according to the two extent totals:
   - Matching total greater: selected mode byte.
   - Matching total smaller: negation of that byte, stored in 8 bits.
   - Equal: zero.
5. If both selected-group fields are nonzero, offset 28 is cleared through two 16-bit zero writes, at offsets 28 and 30. Offset 24 remains unchanged.

The transient value 4 is therefore always overwritten on an ordinary completed group traversal. No synchronization makes intermediate writes atomic as a group.

A bit-1 mark previously placed in byte 12 is erased when that descriptor reaches its own classification step. Marks placed on already-processed descriptors can remain. Final flag values therefore depend on group processing order.

## Acceptance examples

These are conditional static acceptance cases, not results of runtime execution.

1. **Entry rejection.** If F-ed69baa5ffc4 returns −7, the function returns −7 without calling subsequent dependencies or performing its explicit context reset.

2. **Strict threshold boundary.** With threshold 5 and an existing group coordinate of 10, coordinate 14 matches; coordinate 15 does not match that group. A later group may still match.

3. **First matching group.** With threshold 4, groups stored at coordinates 10 and 12, and an input coordinate of 11, the first group wins despite both satisfying the criterion.

4. **No match at zero threshold.** With threshold zero, even an identical coordinate does not match an existing group. Every visited record takes the group-creation path unless a dependency fails.

5. **Circular append.** Given a valid one-member group containing record A, appending record B produces A → B → A, retains A as head, and makes B the tail.

6. **Classification tie.** A nonempty group with two set-bit members and two clear-bit members receives byte-12 classification 1 before any later incoming bit-1 marks. A group with one set-bit and two clear-bit members receives 0.

7. **Mode-dependent direction.** For selector zero, matching total 9 and other total 4 produce byte 13 equal to 2. Reversing the totals produces 254, the 8-bit representation of −2. Equal totals produce zero.

8. **Candidate precedence.** If both relationship pointers are nonzero but the second points to a record in another group, only the external second-candidate path is evaluated for that member.

9. **Conflicting selections.** If both group relationship fields are nonzero at finalization, the second is cleared. No corresponding reversal of earlier target flag writes occurs.

10. **Empty input.** If the captured input range is empty, no membership construction occurs. Zero return additionally requires that dependency effects leave no groups needing invalid traversal; the earlier reset alone does not guarantee the final group count.
