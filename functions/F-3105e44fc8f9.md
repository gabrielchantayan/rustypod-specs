# F-3105e44fc8f9

## Purpose

F-3105e44fc8f9 coordinates an initial operation and, only if that operation returns zero, a secondary operation. The secondary result selects between a conditional update of caller-provided 16-bit storage and a fallback call.

The function returns no value. Its observable behavior consists of ordered storage accesses, dependency calls, effects those dependencies may produce, and at most one direct 16-bit write through its fourth argument.

The established update rule uses a previously captured caller value and a previously captured shared comparison value. If those values differ, the function increments the captured caller value modulo 65536, replaces that incremented value with zero if it equals the comparison value, and writes the result. This does **not** universally prevent writing the comparison value: when that value is zero, the replacement can itself equal it.

The semantic purposes of the operation, its arguments, the shared value, and the dependency return codes are not established. Terms such as “success,” “retry,” or “reserved identifier” would describe inferred intent rather than proven behavior.

### Storage and widths

The fallback receives addresses of the two local slots. It does not receive the fourth argument in place of either slot address.

## Behavior

### Setup and read ordering

The function first calls F-5f5f14cedda3 with the second argument and retains its 32-bit result.

That dependency call precedes the relevant shared-storage, object-field, and caller-storage reads. Its effects can therefore influence the values subsequently captured; preservation of those locations must not be assumed.

After that call returns, the established read order is:

1. Read the shared 32-bit value and retain it as the comparison snapshot.
2. Read the unsigned 16-bit field at byte offset 16 from the second argument, zero-extend it, and place its pointer-form representation in the local pointer slot.
3. Read the shared 32-bit value again and place the complete result in the local value slot.
4. If the fourth argument is non-null, read its unsigned 16-bit value and replace the local value slot with that zero-extended value.

The two shared reads are separate. The contract does not collapse them into one read or require their results to match. Whether concurrent changes are supported is a separate, unresolved question.

The local slots initially receive copies of the third and fourth arguments before the derivation call. Both contents are overwritten by the setup described above before either slot address is exposed to the fallback. Those initial copies do not determine the fallback’s arguments.

### Secondary operation

Its result is represented as a 64-bit quantity. The low 32 bits select subsequent behavior:

- Low 32 bits equal to zero: take the optional-update path.
- Any nonzero low-32-bit pattern: call the fallback.

The low half is tested through a signed 32-bit interpretation, but only equality with zero matters. A value with its low-half sign bit set is still nonzero and selects the fallback.

The upper 32 bits are extracted, but they do not affect this function’s direct caller-storage update or select a branch:

- With a non-null fourth argument on the update path, the captured caller value replaces them before the update comparison.
- With a null fourth argument, no update is performed.
- On the fallback path, they are not supplied as an explicit fallback argument.

No semantic meaning for either half is established beyond these uses.

### Conditional caller-storage update

This path is reachable only when the initial operation returns zero and the secondary result’s low 32 bits are zero.

If the fourth argument is null, there is no direct caller-storage write.

Otherwise, the update uses the caller value captured during setup, not a fresh read after either operation. That value is zero-extended from 16 bits and compared with the **entire 32-bit comparison snapshot**.

If they are equal, the function performs no direct write.

If they differ, the replacement is determined as follows:

- Increment the captured value using unsigned 32-bit arithmetic.
- Clear bit 16 with mask 0xFFFEFFFF.
- Compare the resulting 32-bit value with the full comparison snapshot.
- Select zero if they are equal; otherwise select the resulting value’s low 16 bits.
- Write the selected value through the fourth argument using a 16-bit store.

Because the captured starting value lies between 0 and 65535 inclusive, the unmasked increment lies between 1 and 65536. Clearing bit 16 therefore produces exactly the increment modulo 65536. There is no 32-bit wraparound in this particular addition.

Both comparisons retain the snapshot’s full width. If the snapshot exceeds 65535, it cannot equal either the zero-extended captured value or the masked increment. Every non-null captured value then reaches a write of its ordinary modulo-65536 increment.

Replacing an increment equal to the snapshot with zero is the established rule. It is not a general guarantee that the stored result differs from the snapshot. In particular, snapshot zero and captured value 65535 produce a write of zero.

A store can also leave the numeric value unchanged. With snapshot 1 and captured value 0, the increment is replaced with zero, and a 16-bit store of zero still occurs.

The fallback’s return value is ignored. After it returns, this function does not inspect the slots, copy their contents back to caller storage, or perform the conditional increment.

## Acceptance examples

These are conditional consequences of static evidence, not runtime observations. Unless an example states otherwise, dependencies return normally and do not independently change the storage discussed. Update examples require a non-null fourth argument, a zero initial-operation return, and a zero secondary low half.

1. **Early stop.** If the initial operation returns any nonzero 32-bit value, neither subsequent dependency is called. There is no direct caller-storage write.

2. **Null fourth argument.** With a null fourth argument and both branch-controlling results zero, there is no access through that argument. The initial operation still receives the low 16 bits of the second shared read.

3. **Ordinary increment.** Snapshot 100 and captured caller value 7 produce a 16-bit write of 8.

4. **Captured value already equals snapshot.** Snapshot 100 and captured value 100 produce no direct write.

5. **Increment equals a nonzero snapshot.** Snapshot 100 and captured value 99 produce a write of zero, not 100.

6. **Wraparound with a different snapshot.** Snapshot 100 and captured value 65535 produce a write of zero.

7. **Zero snapshot can be written.** Snapshot zero and captured value 65535 reach the update branch. The masked increment is zero, its equality with the snapshot selects zero, and zero is written. The function therefore writes the snapshot itself in this case.

8. **Zero already captured.** Snapshot zero and captured value zero produce no direct write because the initial full-width comparison is equal.

9. **Store without numeric change.** Snapshot 1 and captured value zero produce a 16-bit store of zero. A write occurs even though the stored number matches the captured number.

10. **Snapshot is not truncated.** Snapshot 0x00010000 and captured value zero produce a write of 1. The snapshot is not treated as zero.

11. **Fallback receives the complete default.** With a null fourth argument and second shared read 0x12345678, the initial operation receives 0x5678. If the secondary low half is nonzero, the fallback receives a slot address whose 32-bit contents are 0x12345678.

12. **Separate shared reads.** If the first shared read is 10 and the second is 20, a null fourth argument causes the initial operation to receive 20. The earlier comparison snapshot does not replace the second read.

13. **Intervening caller-storage change.** With snapshot 100 and captured value 7, suppose a dependency later changes the referenced storage to 50. Reaching the update branch causes a write of 8, not 51.

14. **Secondary upper half does not select fallback.** A nonzero upper half combined with a zero low half takes the optional-update path. Conversely, any nonzero low half selects the fallback regardless of the upper half.

15. **Field width.** An object field of 0xFFFF produces pointer-form value 0x0000FFFF, not a sign-extended value. The initial operation receives that value; the fallback, if reached, receives the address of a slot containing it.
