# F-2f4a6c4b80c2

## Purpose

F-2f4a6c4b80c2 updates two adjacent signed-integer state elements using two integer inputs and a contribution obtained from F-870c4fcf7295.

The second state element, combined with the third argument, determines which of two global selector values is passed to the dependency. For a negative combined value, the dependency’s result is additionally transformed. The resulting contribution affects both state elements, but through different expressions.

The function has no explicit return value. Its direct outputs are two ordered memory writes. Observable behavior may also include effects of the dependency.

A possible interpretation is a paired accumulator or adjustment operation. That interpretation is inferred intent, not an established unit, encoding, or application-level meaning.

## Interface

### Arguments

The function accepts three arguments:

1. **State pointer.** A pointer to writable signed-integer storage containing at least two adjacent elements.
   - Element 0 is the first updated value.
   - Element 1 supplies the initial value used for branch selection and is subsequently replaced.
2. **First-element adjustment.** A signed integer added to the first element after the dependency-derived contribution.
3. **Second-element adjustment.** A signed integer added to the initially read second element before branch selection.

The two adjustments are passed by value. The function does not write back to the caller’s argument objects merely by updating its own argument values.

### Result

There is no explicit result value. A normal invocation returns after updating both elements.

## Behavior

The descriptions below use mathematical names for intermediate values. They are explanatory quantities, not additional interface fields.

### 1. Form the branch-driving sum

The function first reads state element 1 and adds the second-element adjustment.

Call this sum **S**.

This calculation precedes the dependency call. Subsequent dependency changes to element 1 do not cause S to be recomputed.

If evaluating the addition is not defined by the execution environment, the supplied representation does not establish a portable outcome for the rest of the invocation.

### 2. Select and invoke the dependency

The function chooses between two global selector objects according to S:

- If S is negative, it reads the **negative-case selector** and invokes F-870c4fcf7295 with S and that selector value.
- If S is zero or positive, it reads the **nonnegative-case selector** and invokes F-870c4fcf7295 with S and that selector value.

Exactly one of these calls is selected during a defined execution reaching this stage. Zero belongs to the nonnegative branch.

The selected selector is read as part of preparing the call. The other branch’s selector is not explicitly read by this function.

Call the dependency’s returned signed integer **R**. Define the contribution **C** as follows:

| Condition | Contribution |
|---|---|
| S < 0 | C = −(R + 1) |
| S ≥ 0 | C = R |

The negative-case transformation is specifically addition of one followed by negation. It is not simply negation, and it is not a general absolute-value operation.

No meaning is established for the selector values or the dependency’s result beyond their use in this calculation.

### 3. Update the first element

After the dependency returns and C has been obtained, the function reads state element 0.

Call that post-dependency value **A**. It stores the result of:

**(A + C) + first-element adjustment**

into element 0.

The addition groups left to right: A and C are added before the first-element adjustment. This matters when reasoning about intermediate overflow.

The relevant A is not necessarily the value present on entry. If the dependency modifies element 0 through global state or another alias, the subsequent read uses the modified value.

### 4. Update the second element

After the first-element store, the function reads a third global object, the **scale**, and stores the following value into element 1:

**S + ((scale × C) × 128)**

The multiplication groups as scale times C, followed by multiplication by 128. The final addition uses the previously calculated S.

Consequences:

- Element 1 is not reread to obtain the base of this final calculation.
- A dependency write to element 1 does not replace the saved S.
- A dependency change to the scale can affect the final result because the scale is read after the call.
- The first-element store precedes the scale read. If permitted aliasing makes that store affect the scale object, the subsequent scale read observes the value then present.

The function then returns without a further explicit read or write.

### Arithmetic boundaries

The arithmetic contains several distinct points at which range matters:

- Initial formation of S.
- Addition of one to R in the negative branch.
- Negation of that intermediate value.
- Both additions used for element 0.
- Both multiplications used for element 1.
- The final addition to S.

A representable mathematical final result does not establish that all intermediate operations are representable.

For example, under conventional 32-bit signed arithmetic, a negative-branch return of 2,147,483,647 makes the intermediate R + 1 exceed the signed range. The supplied representation does not justify replacing that evaluation with a guaranteed wrapping result.

Conversely, a negative-branch return of −2,147,483,648 produces a representable R + 1 and then a contribution of 2,147,483,647. Later operations can still exceed range.

Neither saturation nor checked arithmetic is visible. Wrapping behavior must not be assumed without separate evidence about the executable’s arithmetic semantics.
