# F-44482667e8c7

## Purpose

F-44482667e8c7 performs an ordered sequence of memory reads and writes using two explicit inputs, three additional entry-state values, several fixed low addresses, and pointers obtained from memory. It then invokes an unresolved indirect dependency.

The established behavior is memory mutation followed by indirect dispatch. No higher-level purpose—such as initialization, serialization, device control, or object management—is established. In particular, repeated stores cannot safely be reduced to a single final assignment: their order and multiplicity may be observable through overlapping addresses, mapped devices, or faults.

This contract distinguishes:

- **Established static evidence:** access widths, constants, ordering, and data dependencies visible in the supplied representation.
- **Inferred intent:** possible structure-like use of address values, without an established object model.
- **documented_only:** behavior requiring unavailable ABI, machine, memory-map, or indirect-target information.

No runtime tests have been performed.

## Behavior

### 1. Repeated opening writes

Let **x-byte** and **y-byte** denote the entry low bytes of X and Y.

The opening region contains eleven ordered write groups. Each group begins with these three writes, in order:

1. Store x-byte at Y offset `0x19`.
2. Store y-byte at X offset `0x11`.
3. Store a word at Y offset `0x34`.

The first group’s word is the secondary input. Each of the remaining ten groups instead stores twice X, represented as a 32-bit unsigned value.

The first ten groups additionally finish by storing the primary input as a word at address twice X plus `0x54`. The eleventh group has no such finishing store.

Consequently, this region establishes:

- Eleven byte stores to Y offset `0x19`.
- Eleven byte stores to X offset `0x11`.
- Eleven word stores to Y offset `0x34`.
- Ten word stores to address twice X plus `0x54`.

There are no visible memory reads between these opening stores. X, Y, and the explicit inputs remain entry values throughout this region.

These counts describe access events, not necessarily distinct memory locations. No non-aliasing relationship is established.

### 2. Initial snapshots and fixed-address updates

After the opening writes, the operation reads and retains:

- A word from absolute address `0xA9`, called the **fixed-address snapshot**.
- A word from the primary input at offset `0x74`, called the **primary snapshot**.

It next stores one byte at absolute address `0x3A`. The stored eight-bit result is twice x-byte plus `0x30`, reduced to its low byte. This byte result does not depend on whether the intermediate character value is interpreted as signed or unsigned.

It then reads and retains, in order:

- A word from Z offset `0x14`, called the **saved Z word**.
- A word from X offset `0x04`, called the **saved X word**.

These snapshots occur after all opening writes. If their source locations overlap earlier destinations, they observe the resulting memory, not necessarily entry memory.

### 3. Cross-linked byte and word mutations

The next region performs ordered mutations across X, Y, Z, and fixed low addresses.

First, it writes x-byte to Z offset `0x0D`, writes byte `0x6C` to X offset `0x08`, and writes y-byte to X offsets `0x0D` and `0x09`, in that order. It then stores Z itself as a word at Z offset `0x54`.

Next, it writes the low byte of the fixed-address snapshot to absolute address `0x67`, then reads a signed word from Z offset `0x44`. Call this value the **shift source**.

After that read, the byte at absolute address `0x67` is read and copied to absolute address `0x21`. This is a memory read, not an unconditional reuse of the earlier snapshot. Aliasing or memory-mapped behavior can distinguish those operations.

The shift source then drives three ordered writes:

- Its low byte goes to X offset `0x10`.
- Its full word goes to Y offset `0x54`.
- A byte derived by right-shifting it goes to Z offset `0x01`.

The shift count is the low eight bits of X. The signed-shift and large-count limitations are described under **Uncertainties**.

Y offset `0x54` is then overwritten with X as a word. The prior shift-source store remains part of the observable sequence.

The operation next reads a word from X offset `0x40`, called the **replacement word**, and performs these effects in order:

- Store the saved X word at Y offset `0x74`.
- Store the replacement word at X offset `0x10`.
- Store Z at Y offset `0x44`.
- Read the byte at absolute address `0x67` and store it at X offset `0x09`.
- Store x-byte at Z offset `0x09`.
- Store the fixed-address snapshot at X offset `0x44`.

The word store at X offset `0x10` covers offsets `0x10` through `0x13`. It therefore supersedes the earlier byte at offset `0x10` and intersects offset `0x11`. Its effects on individual byte values depend on endianness.

### 4. Pointer-derived mutations

A word is next read from X offset `0x54`; call its value **P**. It is subsequently used both as an address base and as a stored value.

After obtaining P, the operation again reads absolute address `0x67` and writes that byte to X offset `0x09`. It then stores the low byte of the primary snapshot at P offset `0x0D`.

The saved Z word is written to Z offset `0x54`. This is a write of the previously captured word, not a guarantee that the entire surrounding state is restored.

The operation then reads a word from X offset `0x14`, called the **late X snapshot**. Following that read:

- The low byte of the primary snapshot is written to Z offset `0x11`.
- The low byte of P is written to X offset `0x09`.
- P is written as a word to X offset `0x44`.

These later writes do not change the already captured primary snapshot, saved Z word, or P.

### 5. Final derived-address accesses and dispatch

The operation reads a signed word from Z offset `0x04`; call it **Q**.

It writes the halfword `0x0065` at address twice Q. It then reads a signed word from Q offset `0x64`; call it **R**. The halfword store precedes that read and may affect it if their address ranges overlap.

Next, it writes the low byte of the late X snapshot to P offset `0x11`, and writes the word value `100` to P offset `0x54`.

A word is then read from Q offset `0x74`; call it the **final Q snapshot**. Afterward, a signed word is read from Z offset `0x64`; call it **S**.

The final visible writes, in order, are:

- The low byte of Q to Z offset `0x09`.
- R as a word to S offset `0x54`.
- S as a word to address twice R.

Finally, the unresolved indirect dependency is invoked with four ordered arguments:

| Second | R |

## Side effects

### Memory and ordering

The operation visibly accesses:

- Fixed addresses `0x21`, `0x3A`, `0x67`, and the word beginning at `0xA9`.
- Locations relative to the primary input, X, Y, and Z.
- Locations relative to loaded values P, Q, and S.
- Arithmetic-derived locations involving twice X, twice Q, and twice R.

No supplied evidence establishes that these regions are separate, ordinary RAM, writable, aligned, or part of allocated objects.

Access ordering is therefore part of the contract. A later read can observe earlier writes through aliasing. Repeated stores and stores later overwritten must not be discarded merely because an ordinary non-aliasing final-state calculation would make them redundant.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

### Opening write trace

Given accessible destinations and an execution model in which individual writes are observable, an acceptable trace contains eleven opening groups with the widths and ordering specified above.

Y offset `0x34` first receives the secondary input, then receives twice X ten times. The derived destination twice X plus `0x54` receives the primary input ten times, not eleven.

A trace containing only the final value at each destination does not establish conformance to the ordered-access contract.

### Byte truncation

If x-byte is `0xE7`, the byte written to absolute address `0x3A` is `0xFE`, because the low eight bits of twice `0xE7` plus `0x30` are `0xFE`.

This example establishes the stored byte, not the signedness of intermediate character arithmetic or the accessibility of that address.

### Overlapping byte and word stores

If X-relative memory is ordinary writable memory and the operation reaches the replacement-word store, X offsets `0x10` through `0x13` receive that word’s byte representation at that point.

The earlier byte write at X offset `0x10` is not the lasting value at that position unless the word’s representation happens to contain the same byte there. Subsequent aliasing writes can still change the region.

### Snapshot preservation

If memory at Z offset `0x14` changes after the saved Z word is read, the later write to Z offset `0x54` and the third indirect argument still use the captured saved Z word.

Conversely, repeated accesses to absolute address `0x67` are fresh reads. They must not automatically be replaced with the original low byte captured from address `0xA9`.

### Dispatch arguments

If execution reaches the indirect invocation, its second argument is the word previously read from Q offset `0x64`, while its fourth argument is the later snapshot from Q offset `0x74`.

The word read from Z offset `0x64` is instead used in the final two word stores. Substituting it for the second argument would violate the visible data dependency.

### Fault boundary

If the halfword write at twice Q cannot complete, successful dispatch is not established. The contract does not promise rollback of the earlier opening writes, fixed-address updates, or cross-linked mutations.
