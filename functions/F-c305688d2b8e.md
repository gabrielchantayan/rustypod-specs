# F-c305688d2b8e

## Purpose

F-c305688d2b8e processes a caller-supplied cursor and signed amount. Depending on a nullable output-object pointer and the low bit of a mode argument, it either advances the cursor without inspecting input or traverses records through dependencies. Traversal can invoke an opaque external operation or recursively process a region.

The function returns a 32-bit value of exactly 1 or 0. Its own final write to the supplied cursor cell occurs only on success. Failure is not transactional: no explicit rollback of dependency effects occurs.

Two traversal completion policies are established:

- **Effective mode zero:** reaching a nonpositive remaining amount succeeds.
- **Effective mode one:** reaching a nonpositive remaining amount fails. Success instead requires a nonzero result from F-04d7b0f7c6e9.

Structured-input processing and optional output accumulation are inferred intent. The external operation’s implementation is unavailable: whether it copies anything, and whether its third argument measures bytes, are not established.

## Behavior

### Entry and path selection

The function first reads the caller’s cursor cell into a local cursor, then reduces the mode to its low bit.

Modes differing only in higher bits select the same behavior. For example, modes 0 and 2 select effective mode zero; modes 1 and 3 select effective mode one.

A null output pointer together with effective mode zero selects uninspected advancement. Every other combination selects traversal.

### Uninspected advancement

The function reads the caller’s cursor cell a second time, adds the signed amount to that reading, and makes the result its local cursor. It then writes that result to the caller’s cursor cell and returns 1.

This path calls none of the dependencies. It does not inspect input, reject negative amounts, or require positive progress.

The arithmetic uses the second cursor-cell reading, not necessarily the value read at entry. This distinction does not establish volatile-access or concurrency semantics.

A negative amount can move the cursor backward when the arithmetic has a defined, representable result.

### Traversal and initial dependency

Traversal executes while the signed remaining amount is positive. Each iteration saves the local cursor as the baseline for later consumption accounting.

F-04d7b0f7c6e9 receives, in order:

1. The address of the local cursor.
2. The current signed remaining amount.

Only zero versus nonzero is tested:

| Dependency result | Effective mode | Action |
|---|---|---|
| Zero | Either | Continue to record processing. |
| Nonzero | Zero | Report `(13, 106)` and return 0. |
| Nonzero | One | Write the current local cursor to the supplied cursor cell and return 1. |

A nonzero result bypasses record processing and the iteration’s consumption update. Successful mode-one completion therefore commits the cursor value present after this dependency returns.

“Stopping condition” describes the dependency’s control-flow role. No particular terminator encoding or recognition rule is established.

### Record processing and count evaluation

After a zero result from F-04d7b0f7c6e9, F-38f7a73546d9 receives eleven ordered arguments:

1. Address of a writable 32-bit count cell.
2. Zero.
3. Zero.
4. Address of a writable four-byte control area.
5. Address of a writable four-byte classification area.
6. Address of the local cursor.
7. Current signed remaining amount.
8. Context A.
9. Context B.
10. Zero.

Immediately after normal return, the wrapper evaluates the count cell and saves its value. **This evaluation precedes testing the dependency’s return value, including when that return value is zero.** This is an ordering property of the supplied representation, not a claim about a particular physical load instruction.

Subsequent decisions are:

- A zero result reports `(13, 106)` and returns 0.
- A nonzero result permits inspection of the first classification byte.
- A zero classification byte selects the direct-count branch.
- A nonzero classification byte selects recursion.

The classification byte is not inspected on the dependency-failure path. The first control byte is used only for recursion. The wrapper does not inspect the other bytes in either area.

### Direct-count branch

The saved count serves two established roles: it is the third argument to the opaque external operation, if that operation is reached, and it is later added to the local cursor.

With a non-null output pointer, the sequence is:

1. Read and save the output object’s first 32-bit word.
2. Evaluate the sum of that saved word and the count cell’s current value.
3. Call F-9a8ea7637eda with the output object and that sum.
4. If the result is zero, report `(13, 140)` and return 0.
5. Otherwise, call F-unmapped-external with three arguments:
   - The output object’s second word, read after F-9a8ea7637eda succeeds, plus the saved first-word value.
   - The local cursor evaluated for this call.
   - The previously saved count.

The sum supplied to F-9a8ea7637eda uses a fresh evaluation of the count cell, not the saved count. The first output word is saved before that dependency; the second is obtained afterward. Thus the dependency can replace the second word before the external-call argument is constructed.

The relative evaluation order of the three external-call arguments is not established. The external operation’s return value is ignored.

After the external operation returns, the wrapper evaluates the then-current local cursor and adds the saved count. That cursor evaluation is later than the one used for the external call’s second argument. Earlier dependencies received the cursor’s address; no contract establishes that callbacks or retained access cannot change it during subsequent calls.

With a null output pointer, F-9a8ea7637eda and F-unmapped-external are skipped. The saved count is still added to the local cursor.

The wrapper does not explicitly require a positive count or a count bounded by the remaining amount. It does not directly update either output-object word.

**Inferred interpretation:** the saved first word resembles an append offset, F-9a8ea7637eda resembles storage preparation, and the external arguments resemble destination, source, and count. These roles are not established by an external dependency contract. In particular, this branch does not by itself prove that bytes—or any data—are copied.

### Recursive branch

For a nonzero classification byte, the function invokes F-c305688d2b8e with:

- The same output pointer.
- The address of the parent’s local cursor.
- The count cell’s current value as the child’s remaining amount.
- The first control byte as the child’s mode argument.
- Context A.
- Context B.

This branch uses the count cell again rather than the saved count used in the direct-count branch. Only the control byte’s low bit ultimately affects child behavior.

A zero child result causes the parent to return 0 immediately. The parent adds no error-reporting call for this propagation.

A successful child writes its final cursor into the parent’s local cursor cell. The parent then performs iteration accounting.

Recursion does not necessarily inspect the nested region. A child with null output and an even control byte takes uninspected advancement.

### Consumption and final completion

After successful direct-count or recursive processing, consumption is calculated as the current local cursor minus the iteration’s saved baseline. The remaining amount is reduced by that displacement.

Consumption therefore includes cursor movement by both processing dependencies and the selected branch. It need not equal the record count.

If the updated remaining amount is positive, traversal continues. Otherwise:

- Effective mode zero commits the local cursor and returns 1.
- Effective mode one reports `(13, 106)` and returns 0.

The same completion rules apply if traversal starts with a nonpositive amount; no iteration then occurs.

There is no exact-exhaustion requirement. A representable overshoot can produce success in effective mode zero. There is no progress check: zero displacement can leave the loop repeating, and negative displacement can increase the remaining amount.

## Acceptance examples

These are conditional consequences, not runtime observations. They assume valid required accesses, defined representable arithmetic, normally returning dependencies, and no additional mutations beyond those stated.

4. **Empty mode-one traversal.**

5. **Successful stopping condition.**

6. **Rejected stopping condition.**  
   With non-null output, positive amount, and effective mode zero, the same dependency behavior reports `(13, 106)` and returns 0 without the final cursor write. Null output would instead select uninspected advancement.

7. **Opaque external invocation and cursor accounting.**  
   Start with non-null output, effective mode zero, amount 6, and cursor 1000. The first dependency returns zero without moving the cursor. Record processing moves it to 1002, establishes count 4 and classification byte zero, and succeeds.

11. **Overshoot and mode dependence.**
