## Behavior

### First suffix preparation

The function reads the first group of four 32-bit words into consecutive temporary word positions, in ascending position order.

It then transforms those positions in reverse order: fourth, third, second, first. Each transformation reads the position as an unsigned 32-bit word and replaces it with a logical right shift by one bit.

For an original unsigned value \(w\), the result is:

\[
\left\lfloor w/2 \right\rfloor
\]

Each transformation discards that word’s least-significant bit and clears its most-significant bit. No bit is carried between words.

After all four transformations, the function writes a zero byte at byte offset 16 from the beginning of the first suffix block. It does not explicitly initialize the remaining three bytes of the following storage.

The zero at offset 16 does not establish that the preceding 16 bytes are nonzero. If a dependency interprets this region as a zero-terminated byte sequence, an earlier zero may shorten the interpreted sequence.

### Second suffix preparation

Only after both first-candidate construction calls return does the function read the second group of four words.

Those words occupy four consecutive 32-bit positions. They undergo the same independent unsigned right shifts, again in fourth-to-first order.

The function then performs a distinct partial-word modification of the fourth shifted word:

- It obtains the **numerical low eight bits** of that shifted word.
- It zero-extends that value to 16 bits.
- It stores the resulting 16-bit value into the **two-byte subobject at byte offset zero** within the fourth word.
- The other two bytes of the fourth word are not overwritten by this store.

The destination is defined by its byte offset, not unconditionally by numerical bit significance. Without an established target byte order, it is incorrect to describe this operation simply as replacing the numerical low 16 bits.

Let \(s\) be the shifted fourth-word value and \(b=s\bmod256\). The layout-specific consequences are:

| Layout | Numerical effect on the fourth word | Byte-level consequence |
|---|---|---|
| Little-endian | Numerical bits 0–7 retain \(b\); bits 8–15 become zero; bits 16–31 remain as in \(s\) | Suffix byte 12 holds \(b\), and byte 13 becomes zero |
| Big-endian | Numerical bits 16–31 are replaced by the zero-extended value \(b\); bits 0–15 remain as in \(s\) | Suffix byte 12 becomes zero, and byte 13 holds \(b\) |

Equivalently, on little-endian storage the numerical result is the unchanged upper 16 bits combined with \(b\). On big-endian storage it is the unchanged lower 16 bits combined with \(b\) positioned in bits 16–23, with bits 24–31 cleared.

Thus, the operation establishes an internal zero byte under either conventional layout, but its position differs. It does not explicitly write a terminator after the second 16-byte suffix block. Earlier zero bytes may still occur.

The target byte order remains unresolved.
