# F-f4dc971d0511

## Purpose

F-f4dc971d0511 performs an ordered sequence of byte accesses and indirect calls, then enters an unconditional loop. The loop carries two values derived from dependency results and changes its first call target after the first iteration.

The visible behavior establishes:

- An initial byte write derived from the first and fourth explicit inputs.
- Repeated selector operations, each reading a byte and clearing a byte at a low address selected by that value.
- Ordered dependency calls, some receiving transformed inputs or earlier results.
- A distinct loop-entry dependency for the first iteration and a different dependency target for every subsequent iteration.
- No visible normal return or termination condition.

No application-level purpose is established. Initialization, decoding, or recurring state processing would be inferred intent, not part of the established contract.

The supplied representation reports invalid instruction data and removed unreachable regions. This specification describes the visible static behavior; it does not establish that the representation completely captures the original executable.

## Behavior

### Widths and derived quantities

The explicit unsigned inputs and unsigned carried state are 32 bits. Each direct memory access transfers exactly one byte.

The following descriptive quantities define the address and argument transformations:

- **Page component:** fourth input logically shifted right by 7.
- **Scaled selector address:** first input multiplied by `0x400` using 32-bit unsigned arithmetic, then increased by 1.
- **Initial extracted state:** bits 25 through 29 of D-12’s result, interpreted as an unsigned value.

The page component ranges from zero through `0x01FFFFFF`.

The scaled selector address is:

\[
S=((\text{first input}\times 1024)\bmod 2^{32})+1.
\]

The multiplication produces ten zero low bits. Its maximum 32-bit result is `0xFFFFFC00`, so the final addition does not overflow. Consequently, \(S\) lies between `0x00000001` and `0xFFFFFC01`, with low ten bits equal to 1.

Several dependency results are represented as signed 32-bit integers before left shifts. Their portable signed-arithmetic semantics are not established. Formulas describing discarded high bits for those shifts are conditional on 32-bit machine bit-vector execution.

### Dependency naming

D-01 through D-24 identify call positions, not asserted implementation identities.

The loop’s first call position has two separate dependency IDs:

- **D-15A:** first iteration only, target `0x08833787`.
- **D-15B:** second and all subsequent iterations, target `0x088337C5`.

These target expressions differ. Their implementations, side effects, and termination behavior must not be treated as interchangeable.

“No explicit arguments” means none are displayed in the supplied representation. It does not establish a zero-argument machine-level interface.

### Initial write and incoming-base selector operations

The first visible memory operation writes the low eight bits of the first input to:

\[
(\text{fourth input}\gg7)+\texttt{0x1C}.
\]

The destination ranges from `0x0000001C` through `0x0200001B`; this unsigned addition does not overflow.

The next operation is an **incoming-base selector clear**:

- Read one unsigned byte at the incoming address base plus 1.
- Write a zero byte at address `0x11` plus the byte value read.

Every selector clear uses an unsigned byte value from 0 through 255, so its write address ranges from `0x11` through `0x110`, inclusive. The selected address is not another pointer to dereference.

The initial write precedes the selector read. If their addresses overlap, the selector read observes memory after that write, subject to the actual memory system.

### Initial state and scaled selector operation

D-12’s result is treated as unsigned, masked with `0x3FFFFFFF`, and logically shifted right by 25:

\[
E=(\text{D-12 result}\mathbin{\&}\texttt{0x3FFFFFFF})\gg25.
\]

Thus \(E\) contains exactly result bits 25 through 29 and ranges from zero through 31. Bits 30 and 31 do not contribute.

Next, a **scaled selector clear** occurs:

- Read one unsigned byte at \(S\).
- Write a zero byte at address `0x11` plus that byte.

The read address and selected write address are independently derived. Reading \(S\) does not imply that \(S\) is the address cleared, although the two addresses can coincide.

Two more dependencies run before loop entry:

| Dependency | Explicit arguments | Result consumed |
|---|---|---|
| D-13 | \(E\) shifted left by 1 | No |
| D-14 | None shown | Yes |

D-13 receives a value from zero through 62; this unsigned shift does not overflow.

D-14’s result supplies the first carried value for the first iteration. \(E\) supplies the second carried value.

### Loop-entry target transition

The target-selection state immediately before the loop yields `0x08833787` for its first call. During the loop body, that state is overwritten. Its final value yields `0x088337C5`, and nothing resets it before the next iteration.

Accordingly:

- The first iteration invokes D-15A.
- Every later iteration invokes D-15B.
- The visible loop does not alternate between the targets or restore D-15A.
- D-15B is not invoked unless execution progresses beyond the first iteration’s state update into another iteration.

This target transition is separate from the transformations of the two carried arguments.

### Repeating call and memory order

Each iteration has the following ordered behavior:

| Position | Dependency or operation | Arguments or effect |
|---|---|---|
| 1 | D-15A on the first iteration; D-15B thereafter | Current first carried value; current second carried value logically shifted right by 8 |
| 2 | D-16 | No explicit arguments |
| 3 | D-17 | No explicit arguments |
| 4 | D-18 | No explicit arguments |
| 5 | D-19 | No explicit arguments; retain result |
| 6 | Scaled selector clear | Fresh byte read at \(S\), then selected zero-byte write |
| 7 | D-20 | D-19’s result shifted left by 2 |
| 8 | D-21 | No explicit arguments |
| 9 | D-22 | No explicit arguments |
| 10 | D-23 | No explicit arguments |

After D-24 returns, its result determines the next iteration’s carried state:

- First carried value: result shifted left by 2.
- Second carried value: result shifted left by 26, stored as unsigned 32-bit state.

No exit test intervenes before the next iteration.

For D-15A, the second explicit argument is necessarily zero because \(E\) is at most 31.

Under 32-bit bit-vector shift semantics, if \(R\) is the preceding D-24 result, D-15B receives:

\[
\text{first argument}=(R\ll2)\bmod2^{32},
\]

\[
\text{second argument}=(R\mathbin{\&}\texttt{0x3F})\ll18.
\]

The second argument therefore depends on the low six bits of \(R\), not its high byte. These formulas remain conditional because the left shifts originate from signed-result expressions.

## Side effects

### Direct memory effects

Before the loop, the visible body performs:

- One initial byte write.
- Two incoming-base selector clears, each with its own byte read.
- One scaled selector clear.

Each completed loop iteration adds one scaled selector clear.

Every selector clear orders its source-byte read before its zero-byte write. Repeated writes are present even when they select the same destination or store a value already present. If the memory is externally observable, those accesses may be significant independently of final contents.

Aliasing is not prevented. An earlier write or a dependency’s memory effects may change a later selector read. No caching of selector bytes across operations is established.

### Dependencies, ownership, and resources

There is no explicit allocation, deallocation, bulk copy, or resource-release operation in the visible body.

Dependency behavior is unknown. In particular, no supplied evidence establishes that dependencies:

- Preserve globals or other accessible memory.
- Preserve all hidden machine state.
- Allocate or release memory.
- Acquire or transfer ownership.
- Are idempotent, thread-safe, or reentrant.
- Provide synchronization or memory-ordering guarantees.

These limitations apply separately to D-15A and D-15B. Their different target addresses do not establish either equivalent effects or distinct ownership rules.

Numeric arguments must not be interpreted as owned pointers without additional evidence.

### Errors and interrupted progress

No visible error check, status interpretation, retry, cleanup, or recovery path exists. Unused results are not inspected for failure.

If an access faults or a dependency does not return, later actions on the visible path are not reached. The representation does not establish the resulting exception mechanism, fault type, or nonlocal transfer behavior.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not observed test results.

### Initial byte and shifted argument

Given first input `0x123456AB` and fourth input `0x00000100`, with the required memory and execution access:

- The first visible write stores `0xAB` at `0x1E`.
- D-01 receives 2.
- D-03 receives `0x00123456`.

Later memory contents depend on intervening writes and dependency effects.

### Fresh incoming-base reads

If the first incoming-base selector read yields `0x20`, its clear writes zero to `0x31`.

If a dependency changes that source byte to `0x21` before the second read, the second clear writes zero to `0x32`. Reusing the first selector value would violate the visible access sequence.

### Extracted initial state

If D-12 returns `0xFE000000`, masking produces `0x3E000000`, so \(E=31\).

D-13 receives 62. D-15A receives zero as its second argument, regardless of D-14’s result.

### Scaled unsigned address

For first input `0x00400000`, 32-bit unsigned multiplication by `0x400` wraps to zero, making \(S=1\).

If the byte read at address 1 is `0xFF`, the corresponding clear writes zero to `0x110`. Saturating arithmetic or an unbounded multiplication would not match this address calculation.

### First-to-later target transition

Suppose D-14 returns `0x00000010` and execution reaches the loop.

- The first loop-entry call is D-15A at `0x08833787`, with arguments `0x00000010` and zero.
- If the first D-24 returns `0x00000021`, then, under 32-bit bit-vector shifts, the next loop-entry call is D-15B at `0x088337C5`, with arguments `0x00000084` and `0x00840000`.
- If that later iteration completes, the following loop-entry call again uses D-15B, not D-15A.

The two targets must remain distinguishable even if an external environment happens to give them identical behavior.

### Non-returning dependency

If D-19 does not return, that iteration does not reach its scaled selector clear, D-20, D-24, or the next loop-entry call.

Likewise, if D-15A does not return, D-15B is never reached along the visible path. Later actions must not be performed eagerly.

## Evidence

**Established static evidence:** The supplied representation contains four 32-bit explicit input slots, byte-sized direct accesses, the ordered calls and selector operations described above, unsigned masking and shifting for initial extraction, and an unconditional loop.

**Target-transition evidence:** The loop-entry target selection is initialized before the loop, overwritten during the body, and not reinitialized at the back edge.
