# F-236828a00e9a

## Purpose

F-236828a00e9a dispatches a signed 32-bit event selector against a mutable object and shared storage. Recognized events perform association updates, cancellation-related calls, record draining and publication, conditional notification, or advancement of shared arithmetic state.

These are behavioral descriptions, not established application semantics. The supplied static representation does not identify the protocol, resource type, scheduling mechanism, or meaning of the output bytes.

Ordinary completion returns a 32-bit value. Some paths instead invoke a dependency designated non-returning. Two drain loops have no established iteration bound.

## Interface

### Arguments and result

The function receives:

1. **Object:** a pointer to mutable storage with 32-bit fields, byte flags, an indirect-call table pointer, and an embedded storage region passed to paired dependencies.
2. **Event:** a signed 32-bit selector. Recognized values are 1, 4, 8, 32, and 64.
3. **Argument:** a signed 32-bit event-specific value used as an identifier, comparison operand, or dependency argument.

The return value is 32 bits. Most ordinary paths return zero; others forward a dependency or indirect-call result. No common success/error interpretation is established.

The representation uses 32-bit addresses and pointer-sized fields. This function performs no explicit null, alignment, storage-extent, or lifetime validation. Safe execution requires every reached direct access and indirect call to have suitable storage and targets.

### Object storage

Offsets are bytes from the object base.

| Offset | Directly observed use |
|---|---|
| 0x000 | Indirect-call table pointer; table entry at offset 8 can be invoked |
| 0x2C8 | Identifier selecting event 32’s record branch |
| 0x2D0 | 32-bit association result |
| 0x2D4 | Active identifier; can receive 0x7FFFFFFF |
| 0x2DC | Embedded storage address passed to paired dependencies |
| 0x2FC | 32-bit state cleared by the timeout-related path |
| 0x300 | Single-byte flag tested and conditionally cleared |
| 0x307 | Single-byte gate tested or cleared |

The type and semantics of the region at 0x2DC are unknown. Its use does not establish that it is a synchronization object. Only the byte at 0x300, not its containing word, is treated as the flag.

### Shared storage

A shared control block supplies a 16-bit flags field at offset 0, a 32-bit referenced-object pointer at offset 4, a 32-bit handle at offset 8, and 32-bit comparison words at offsets 12 and 16.

A separate 36-byte state block has these arithmetic roles:

| Offset | Role |
|---|---|
| 0 | Position |
| 4 | Position step |
| 8 | Accumulator A |
| 12 | A step |
| 16 | Accumulator B |
| 20 | B step |
| 24 | Lower bound |
| 28 | Upper bound |
| 32 | Counter in the low 16 bits; upper 16 bits are not directly updated by counter writes |

Other shared inputs are an output-buffer pointer, a comparison table of three 8-byte entries, an initial record constant, a transition threshold, two endpoint constants, and an initial-endpoint constant. Their numeric values are unresolved.

Context objects returned by a dependency expose a byte at offset 0xD9. No identity relationship between successive returned contexts is established.

## Behavior

### Entry and dispatch

Every invocation first calls F-unmapped-01 to acquire a context. Only afterward does it capture the shared control-block pointer and initial record constant.

Unsupported events invoke F-a817d8d58c10, designated non-returning. There is no ordinary unsupported-event result.

### Event 1: gated cancellation-related action

If the initially acquired context’s byte at 0xD9 is zero, return zero.

Otherwise:

- Argument 6 reacquires a context, clears that context’s byte at 0xD9, calls F-618b1fec9f4a, and returns its result.
- Arguments 5, 7, and 8 acquire a service through F-unmapped-02, call F-23aadb16b673 with that service and the handle read from the captured control block, and return zero.
- Other arguments return zero.

The paths for arguments 5, 7, and 8 do not directly clear a context byte.

### Event 4: association update

If the initial context’s byte at 0xD9 is nonzero, perform these operations in order:

1. Acquire a service and call F-23aadb16b673 with the service and shared handle.
2. Reacquire a context and clear its byte at 0xD9.
3. Call F-unmapped-03 on the then-selected shared state block with byte count 36.

Then reacquire a context and call F-b37968c9f644 with the address four bytes into that context and the event argument. Store its 32-bit result at object offset 0x2D0.

A nonzero result additionally causes the argument to be stored at 0x2D4. If that result is nonzero and the argument is less than 3 under signed 32-bit comparison, clear byte 0x307 and return zero. This includes negative arguments, including the minimum signed 32-bit value.

Otherwise invoke F-a817d8d58c10. A zero result therefore reaches the non-returning path after updating 0x2D0 but without directly changing 0x2D4. A nonzero result with argument 3 or greater reaches that path after both word writes.

### Event 8: identifier reset and drain

Compare the argument with object offset 0x2D4. A mismatch invokes F-a817d8d58c10 without the following reset writes.

On a match, write, in order:

1. 0x7FFFFFFF to 0x2D4.
2. Zero to 0x2D0.
3. Zero to byte 0x307.

Repeatedly call F-704f99fd5e22 with the object, argument, and three 32-bit in/out slots. Before every call, initialize the first two slots to the captured initial record constant and the third to zero. A zero result repeats; a nonzero result ends draining.

Call F-f87d423afa3b. A zero result returns zero. Otherwise inspect the handle in the captured control block:

- A handle other than −1 bypasses creation.
- For handle −1, acquire a service, call F-c930571cdede with that service, 500, the control block’s pointer field, and zero, then store the result as the handle.
- A creation result of −1 invokes F-a817d8d58c10.

For a usable handle, acquire a service again, call F-8becc2a0337c with the service and the handle read after acquisition, and return zero.

### Event 64: conditional delegation

A nonzero byte at object offset 0x307 returns zero.

Otherwise reacquire a context and call F-d5cded701dac with that context and the active identifier read from object offset 0x2D4. Results other than 4 and 6 return zero. Results 4 or 6 cause F-3e988da5b41e to be called, and its result is returned.

### Event 32: record branch

This branch takes precedence when the argument equals object offset 0x2C8, including when it also equals a shared handle.

Acquire a context and classify the active identifier through F-d5cded701dac. Preserve this classification throughout the drain loop.

For each F-e08f888de5db call, initialize four 32-bit in/out slots in this argument order:

| Slot | Initial value |
|---|---|
| First | Current object field at 0x2D4 |
| Second | Captured initial record constant |
| Third | Captured initial record constant |
| Fourth | Zero |

Pass the object and addresses of those four slots.

#### Zero result: filter and publish

Use the third slot’s low 16 bits as the record code.

- Codes greater than 24 invoke F-a817d8d58c10.
- Code 3 is skipped unless the preserved classification equals 6.
- All other admitted codes are published.

Before publication, preserve the third slot’s value, then:

1. Call F-unmapped-03 on a 2048-byte temporary region with byte count 2048.
2. Write the preserved record value’s low byte at region offset 4.
3. Write 15 at offset 5.
4. Clear the first word’s low byte while retaining its upper 24 bits.
5. Call F-unmapped-04 with object address 0x2DC.
6. Call F-c6c589453fa8 with 9, zero, the temporary-region address, and 2048.
7. Call F-unmapped-05 with object address 0x2DC.

Resume draining afterward. Admission uses only the record value’s low 16 bits; emission uses only its low byte. Higher bits do not independently reject a record.

#### Nonzero result: optional timeout-related processing

If object byte 0x300 is zero, return zero.

Otherwise, the **second slot**, initialized from the record constant before the drain call, is the storage used for preparation, the subsequent indirect call, and finalization:

1. Call F-7a117b899bf6 with the second slot’s address.
2. Read the indirect-call target at offset 12 from the structure addressed by the second slot’s resulting value. Invoke it with the addresses of the second and fourth slots.
3. Call F-bf18a6a8124b with the fourth slot’s address, obtaining a 64-bit value.
4. Read a 32-bit reference at offset 0x2FC from the object addressed by the captured control block’s current pointer field.
5. Subtract the reference from the 64-bit result’s low half, modulo \(2^{32}\).

If that unsigned low-half difference exceeds 499, clear object byte 0x300 and then write zero to object offset 0x2FC.

Finally call F-ec22bd8215d3 with the **second slot’s address** and the 64-bit result’s high half minus the low-half subtraction’s borrow, using 32-bit arithmetic. Return zero.

The first, identifier-initialized slot is not the preparation or finalization argument. The comparison is not a full 64-bit elapsed-value comparison.

### Event 32: shared-handle branch

When the record branch does not apply, compare the argument with the handle reached through the **then-current global control-block pointer**. A mismatch invokes F-a817d8d58c10.

Subsequent accesses described below use the control-block pointer captured at entry. The two pointers need not be identical if an earlier dependency replaced the global pointer.

Call F-618b1fec9f4a and preserve its result as the provisional return value.

#### Conditional notification

Read the captured control block’s flags after that call.

If mask 4 is clear, skip notification. If mask 4 is set and mask 2 is clear, attempt notification directly. If both are set, inspect up to three table entries in ascending order, stopping at the first qualifying entry. Qualification requires:

- Bit 0 of the entry’s first byte is set.
- Its first 32-bit word matches control offset 12 under mask 0xFFFFFF0F.
- Its second word exactly matches control offset 16.

No qualifying entry suppresses notification.

Immediately before notification, assign 28 to a temporary 32-bit slot. No explicit argument connects that slot to the following call.

Call F-cd7e1905512f with the word at offset 0x2D0 of the object referenced by the captured control block, zero, 9, 13, and the current shared output-buffer address.

A nonzero result is passed to the object’s indirect entry at table offset 8, along with the object itself. That indirect call’s result replaces the provisional result. A zero notification result leaves it unchanged.

#### Transition selection and configuration timing

After notification processing, capture the second endpoint, first endpoint, and state-block pointer. Read the counter’s low 16 bits and zero-extend it.

Threshold equality has first priority. Equality selects position step 0xFFFFFFE1, A step 6, and B step 2.

Otherwise compare the threshold and zero-extended counter in signed 32-bit order:

| Condition | Counter | Transition |
|---|---:|---|
| Counter above threshold | 2100 | Position step 5, A step 2, B step 0 |
| Counter above threshold | 2700 | Position step 24, A step 2, B step 0 |
| Counter above threshold | 3600 | Special transition |
| Counter at or below threshold | 0 | Initialization transition |
| Counter at or below threshold | 900 | Special transition |
| Counter at or below threshold | 1320 | Position step 21, A step 2, B step 0 |

Other values retain existing steps. The unresolved threshold determines which named cases are reachable.

The initialization transition calls F-unmapped-03 on the globally selected state block with byte count 36. The state-block pointer and both endpoints were captured **before** this call. The initial-endpoint constant is read **after** the call.

Subsequent initialization writes target the previously captured state-block pointer: set position and upper bound from the post-call initial-endpoint value, lower bound from the captured first endpoint, position step to 0xFFFFFFF5, A step to 2, and B step to zero. Thus replacement of the global state pointer by F-unmapped-03 does not redirect these subsequent writes. Changes to the first endpoint’s backing global do not replace its captured value.

The special transition writes the first endpoint as position through the global state-block pointer, sets the captured block’s lower bound to the captured second endpoint and upper bound to the captured first endpoint, and selects position step 0xFFFFFF9A, A step 6, and B step 2. No intervening dependency call occurs between pointer capture and this transition.

#### Arithmetic, encoding, and final calls

Using the captured state-block pointer and 32-bit wrapping arithmetic:

1. Compute candidate position as position plus position step.
2. Store it as position only when it is within both bounds, inclusive, under unsigned comparisons.
3. Add A step to accumulator A and store it.
4. Add B step to accumulator B and store it.
5. Read the counter’s then-current low 16 bits, increment modulo \(2^{16}\), and write those 16 bits. If the incremented value exceeds 3599, overwrite those same 16 bits with 900.

The increment uses storage as it exists after transition processing, not necessarily the counter value used to select the transition. This matters if F-unmapped-03 changes it.

Read the shared output-buffer pointer and write:

- Offset 9: candidate-position bits 8–15.
- Offset 10: preserve its upper five bits; replace its low three bits with candidate-position bits 16–18.
- Offsets 17–19: accumulator A’s low 24 bits, least-significant byte first.
- Offsets 20–22: accumulator B’s low 24 bits, least-significant byte first.
- Offset 6: preserve its upper nibble and increment its low nibble modulo 16.

Output encodes the candidate even when bounds reject storing it.

Acquire a service and call F-871565b3c85d with that service, the handle read from the captured control block, and 1000. Acquire a service again and call F-8becc2a0337c with that service and the subsequently read handle. Return the provisional result.

## Side effects

Direct mutations affect object fields, returned contexts, the shared handle, arithmetic state, and output bytes. Dependency calls and indirect calls can have additional unknown effects. No rollback is established.

The publication pair establishes only call arguments and ordering. Mutual exclusion, blocking, recursion safety, and synchronization semantics remain unknown.

Temporary slots and the publication region belong to the invocation’s local storage. No explicit allocation or deallocation is visible. Whether dependencies copy, retain, mutate, or release referenced storage is unresolved; safe use requires compatible external lifetime contracts.

F-unmapped-03 is not established as zero-fill. In particular, publication retains bytes from the temporary region after that call, and state initialization does not itself assign every state byte.

Captured pointers and constants survive calls as captured values. Fields read later can reflect dependency mutations. Dependencies must not be assumed to preserve globals, return identical contexts or services, or preserve object fields.

## Acceptance examples

These are conditional static consequences, not executed tests. Unless stated otherwise, dependencies return as specified without interfering mutations.

1. **Signed association boundary:** A nonzero association result and argument 2 update both words, clear byte 0x307, and return zero. Argument 3 instead reaches the non-returning dependency after both word writes. A negative argument satisfies the signed bound.
2. **Reset mismatch:** Event 8 with a mismatching identifier performs none of its three reset writes.
3. **Record filtering:** Code 3 is skipped for classification 4 and published for classification 6. Code 25 reaches the non-returning dependency. A third-slot value of 0x00010003 is still code 3.
4. **Finalization slot identity:** On nonzero record termination with byte 0x300 set, preparation receives the second slot’s address; the indirect call receives second and fourth addresses; finalization receives the same second-slot address, not the identifier slot.
5. **Timeout boundary:** Wrapped low-half differences of 499 and 500 respectively preserve or clear byte 0x300 and word 0x2FC. The latter clears the byte before the word.
6. **Initialization mutation:** Suppose counter-zero initialization is selected. If F-unmapped-03 replaces the global state pointer, changes the first endpoint, and changes the initial endpoint, subsequent initialization writes still target the captured block and use the captured first endpoint, but obtain the initial endpoint after the call.
7. **Counter boundaries:** Without a transition changing counter storage, 3599 increments and is replaced by 900; 65535 wraps to zero.
8. **Rejected position:** An out-of-bounds candidate leaves stored position unchanged but is still encoded into output.
9. **Notification return:** A nonzero notification result invokes the object callback; its return replaces the provisional result, even if that return is zero. Skipped notification or a zero notification result preserves the provisional result.
