# F-9e49444243a3

## Purpose

F-9e49444243a3 conditionally updates a shared measurement field, prepares temporary descriptor storage, and invokes a mode-dependent sequence of allocation and construction dependencies. A context flag independently controls an additional final construction.

The established outputs are memory writes and dependency calls. There is no explicit returned object, status, or count.

**Inferred intent:** the allocation results appear to represent object storage, and the temporary regions appear to contain construction descriptors. Object types, registration, and the meanings of most fields are not established.

**Important dependency limitation:** an unmapped external dependency receives destination-like addresses, source-like addresses, and lengths. Its implementation and copy semantics are not supplied. This contract distinguishes its observed calls from the **unverified copy assumption** that each call copies the requested number of bytes from its second argument to its first. Descriptor contents attributed to those calls are conditional on that assumption.

Every construction call receives five arguments, in order:

1. The result of the immediately preceding allocation call.
2. A 32-bit zero.

5. An address of temporary descriptor storage.

The context is not passed directly to these construction dependencies.

### Preconditions and representation

The visible body performs no pointer-validity, bounds, allocation-success, or descriptor-validation checks. Normal completion therefore requires readable and writable storage for all accesses actually reached, together with dependency contracts permitting the supplied arguments.

Addresses and address-bearing results are represented as 32-bit values. Table entries, explicit descriptor fields, and the shared cache field are 32 bits. Context flags and one resource field are 8 bits. The final resource measurements are signed 16-bit values.

The context must remain readable at offset 4 whenever that byte is sampled. Temporary descriptor addresses are valid only during the invocation; the caller supplies no persistent descriptor storage.

The external dependency's length arguments do not, by themselves, establish accessible source ranges, initialized destination ranges, copying, or preservation of neighboring storage. Those properties require its missing contract.

## Behavior

### 1. Conditional shared-cache update

The function first captures the shared-state base global for the eventual write. It then separately evaluates that global to read the 32-bit field at offset 0x24 for the zero test. No dependency call separates these evaluations, but the evidence does not establish synchronization or require the evaluations to observe the same base under concurrent mutation.

If the tested field is nonzero, initialization is skipped. Negative values also skip it: this is a zero/nonzero test.

If the tested field is zero:

1. F-9d0ecc5f6adf is called without arguments, and its 32-bit result is retained.
2. F-ed4b1fd8953e is called with the context and a selector obtained from a global.
3. A 32-bit address is read at offset 8 of that result and retained as the resource-descriptor address.
4. F-5710a8628cba is called with the retained first result, another globally supplied selector, and the first 32-bit word of the resource descriptor.
5. After that call returns, the function obtains the resource descriptor's 32-bit word at offset 4, masks it to its low 16 bits, and obtains the byte at offset 12.
6. F-59c1430f85c2 receives temporary output storage, the result of F-5710a8628cba, the masked value, and the byte.
7. The first 32-bit output word is read and masked with 0xFFFFFFFE. The result is used as an address.
8. Signed 16-bit values at offsets 0x52 and 0x54 of that address are sign-extended and added. Their 32-bit sum is written at offset 0x24 of the base captured before the zero test.

The relative evaluation order of the two resource arguments in step 5 is not established. Neither is the relative order of the two signed measurement reads.

The sum ranges from −65,536 through 65,534, so signed 32-bit addition cannot overflow. A zero sum is stored as zero. A later invocation still observing zero repeats initialization; no separate initialized flag is visible.

The destination base is not refreshed after the dependencies return. The cache field is not rechecked before the write. Changes made by dependencies to the global base or cache field therefore do not redirect or cancel that write.

### 2. Common descriptor preparation

The function makes six calls to the unmapped three-argument dependency before choosing the mode branch. Each receives length 0x68, or 104 bytes, and a distinct temporary destination.

| Order | Temporary destination role | Second argument | Explicit subsequent store |
|---|---|---|---|
| 1 | Primary | Globally supplied template address | Selection word at offset 0x48 |
| 2 | Alternate primary | A fresh selection-base evaluation plus 0xCC0 | Selection word at offset 0x48 |
| 3 | Mode descriptor | Another globally supplied template address | Retained mode value at offset 0x40 |
| 4 | Optional descriptor | Another globally supplied template address | Conditional late store at offset 0x64 |
| 5 | Zero-mode trailing descriptor | Another globally supplied template address | None |
| 6 | Nonzero-mode trailing descriptor | Another globally supplied template address | None |

These calls occur in both mode branches, including calls for destinations not subsequently passed to a construction dependency.

**Under the unverified copy assumption**, each destination receives a 104-byte template image before its listed explicit modification. Without that assumption, only the calls and explicit stores are established; the remaining bytes' contents and initialization are **documented_only**.

#### Selection-base evaluations and flag reads

The selection operations have distinct base evaluations:

1. The first external template call returns.
2. The function reads and retains the selection-base global for the later, second selection.
3. It reads context byte offset 4 for the first selection decision.
4. It separately evaluates the selection-base global to fetch the first selected 32-bit entry.
5. It stores that entry at primary offset 0x48.
6. It freshly evaluates the selection-base global again to form the alternate-primary source argument at base plus 0xCC0, then makes the second external template call.
7. After that call returns, it reads context byte offset 4 again.
8. It fetches the second selected 32-bit entry using the base retained in step 2, and stores it at alternate-primary offset 0x48.

For each selection, the index is 1 only when the sampled byte has bit 0 set and mode is exactly 1. Otherwise the index is 0. The selected entry is the 32-bit word at base offset 4 or offset 0, respectively.

Thus the first selection, alternate-template source, and second selection do not all use one refreshed base. In particular, changes to the global during the second external call do not refresh the retained base used afterward.

The two flag samples are independent. Mode zero and nonzero modes other than 1 still perform these flag reads, although their selected index is always 0.

#### Mode-value reads and dependency boundary

After storing the second selection:

1. The function unconditionally reads the default mode-value global.
2. If mode is exactly 1, it also reads the alternate mode-value global, replacing the retained default value.
3. It calls the unmapped dependency with the mode-descriptor address, its template source argument, and length 104.
4. Only after that call returns does it store the retained selected value at mode-descriptor offset 0x40.

Mode 1 therefore does not bypass the default global read. Changes to either mode-value global during the external call do not change the retained value subsequently stored.

The optional and two trailing descriptor calls then occur in the table order.

### 5. Optional final construction

After the branch-specific trailing construction returns, the function reads context byte offset 4 again.

If bit 0 is clear, it returns without another allocation or construction.

If bit 0 is set:

1. A separate shared-data base global is evaluated.
2. The 32-bit word at that base plus 0x14 is read.
3. That word is stored at optional-descriptor offset 0x64.
4. F-8157a180d901 is called with 560 bytes.
5. F-60fe53f7ab39 receives that result and the optional-descriptor address.

This decision uses the late flag sample, not either selection sample. The replacement word is also obtained late, after all mandatory constructions. Dependencies between its store and construction may have undocumented effects; the body does not revalidate the descriptor.

## Side effects

### Direct effects

The function reads globals, context bytes, table entries, resource data, and dependency output. It conditionally writes the shared cache, explicitly writes temporary descriptor fields, and supplies temporary addresses to dependencies.

On normal return:

- Mode zero performs four mandatory allocations and constructions.
- Nonzero mode performs three mandatory allocations and constructions.
- A set final flag adds one allocation and construction.
- Six common calls reach the unmapped dependency, plus one branch-specific call.

The body contains no explicit deallocation, persistent store of allocation results, parent attachment, or rollback.

### Ownership and failure behavior

Allocation results are forwarded without a null or failure-marker check. Construction results are ignored. There is no visible status-dependent error branch.

Ownership transfer, registration, release, and allocation alignment remain **documented_only**. Passing an allocation result to a construction dependency does not establish that dependency's ownership policy.

Temporary descriptor retention is likewise **documented_only**. The visible body does not establish whether dependencies copy, borrow, mutate, or retain these addresses. The function itself does not extend their lifetime beyond return.

If a dependency fails to return normally, subsequent operations are not established to occur. Earlier writes and dependency effects have no visible compensating cleanup.

No dependency is assumed to preserve globals, resource data, context, or accessible temporary storage merely because of its apparent role.

## Acceptance examples

These are conditional static-contract examples, not runtime results. Unless a mutation is specified, assume normal dependency returns and stable data subsequently read. Claims about template-derived bytes additionally require the unverified copy assumption.

### Nonzero cache, mode zero, final flag clear

The four cache-initialization dependencies are skipped. Both selection stores use entry 0. Allocation requests are 560, 544, 164, and 560 bytes, with construction order F-60fe53f7ab39, F-7f6becd152e6, F-60d99bc349ed, F-60fe53f7ab39. No optional construction occurs.

### Mode one and mode-value mutation

Suppose the default global contains 10 and the alternate contains 20. Both are read, in that order. If the mode-descriptor external call changes those globals to 30 and 40, the subsequent offset-0x40 store still writes 20.

If later dependencies preserve that field and the extended-prefix call implements copying, extended offset 0x40 also contains 20.

### Selection-base replacement during the second external call

Suppose all selection-base evaluations before the second external call observe base A. That call changes the global to base B. The second selection still reads from A because its base was captured before that call. The alternate-template source argument was also formed before that mutation.

### Independently changing flags

For mode 1, suppose bit 0 is set at the first selection sample, clear at the second, and set at the final sample. The primary selection store uses entry 1, the alternate-primary selection store uses entry 0, and the optional construction occurs.

### Extended fields and missing copy semantics

The five extension stores precede the external prefix call. If that call implements an exact bounded copy, they remain outside its destination range. Without that contract, their survival is unresolved; a length argument of 104 alone is insufficient acceptance evidence for their final values.

### Signed measurements and zero sentinel

With an initially zero cache and resolved signed measurements −3 and 8, the retained destination receives 5. With measurements −8 and 8, it receives zero; a subsequent invocation still seeing zero repeats initialization.
