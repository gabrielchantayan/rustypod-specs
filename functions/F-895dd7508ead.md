# F-895dd7508ead

## Purpose

F-895dd7508ead copies two source flag bytes into snapshot fields, applies selector-dependent eligibility rules, and conditionally invokes indirect operations.

A four-byte object field selects between two paths:

- **Zero field:** eligible execution invokes a service operation with the saved service receiver and integer 1.
- **Nonzero field:** execution derives a classification byte, conditionally stores it, and, when eligible, obtains a four-byte service result and passes it to an object-specified callback.

Classification storage and dispatch eligibility are distinct. One combination stores the classification but performs no dispatch; other combinations dispatch without storing it.

These are established static behaviors. The application meanings of the flags, selector, classification, and operations are unknown.

## Interface

### Inputs and result

| Input | Recovered representation | Role |
|---|---|---|
| Object | Address of mutable byte-addressable storage | Supplies source flags, snapshot destinations, a linked-object reference, callback address, callback context, and classification destination. |
| Selector | 32-bit integer | Values 0 and 1 have distinct rules; all remaining values share a third rule. |
| Classification input | 32-bit integer | Determines a classification byte on the nonzero-field path; unused on the zero-field path. |

There is no explicit return value. Observable results consist of memory accesses, direct stores, dependency invocations, and dependency effects.

### Object layout

Offsets below are byte offsets from the supplied object address.

|---|---:|---|
| `+0x000` | 1 byte | First source flag |
| `+0x001` | 1 byte | Second source flag |
| `+0x004` | 1 byte | First snapshot destination |

The representation uses four-byte pointer-bearing fields. It does not establish a portable native ABI, endianness, or alignment policy.

### Service access

An external root supplies a four-byte service-receiver address from its field at offset `+0x004`. This receiver is captured once, after both snapshot writes and before the discriminator read.

The receiver supplies a dispatch-table address. Two table entries are used:

| Table offset | Dependency |
|---|---|
| `+0x0BC` | F-0000000000bc |
| `+0x0C4` | F-0000000000c4 |

The receiver address is saved before eligibility is determined. The relevant table and operation address are accessed only when dispatch is reached.

### Preconditions and aliasing

Normal execution requires readable source flags, writable snapshot destinations, a readable external receiver field, and a readable discriminator. Conditional accesses additionally require valid linked storage, service tables, callback fields, context storage, and callable targets as reached.

There is no explicit validation of null addresses, bounds, alignment, or callable targets.

**No disjointness precondition is established.** In particular, the linked-object reference may designate the input object or overlapping storage. Object-relative stores may therefore change bytes subsequently read through the linked-object reference.

A linked reference need not be dereferenceable when its conditional access is not reached. A nonzero callback field need not designate a valid callable target on a path that does not invoke it.

## Behavior

### Initial access order

Before evaluating eligibility, the function performs these actions in order:

1. Reads the byte at object offset `+0x000`.
2. Writes the captured byte to object offset `+0x004`.
3. Reads the byte at object offset `+0x001`.
4. Writes the captured byte to object offset `+0x005`.
5. Loads the service receiver from the external root’s field at `+0x004`.
6. Reads the four-byte discriminator at object offset `+0x1B8`.

Both snapshot stores occur on every ordinarily returning path, including paths with no dependency invocation.

Subsequent flag decisions use the two captured source bytes, not later rereads of the source fields. Any nonzero byte counts as set; values are not restricted to 1.

The stores precede subsequent memory observations. If other referenced storage overlaps a snapshot destination, a later read through that reference observes the resulting storage state, subject to any intervening external mutation. The source does not establish isolated objects or entry-time snapshots of all referenced memory.

### Conditional linked-object access

The linked-object reference is read only when all three conditions hold:

- Selector equals 1.
- The captured first flag is nonzero.
- The captured second flag is nonzero.

The function then reads the linked-object address at object offset `+0x01C`, followed by the byte at linked offset `+0x005`.

A zero linked byte rejects dispatch. A nonzero linked byte permits dispatch.

Neither the linked reference nor its target byte is consulted for eligibility in other flag/selector combinations.

The linked byte is read **after** the snapshot stores. If the linked reference designates the input object itself, its `+0x005` byte has already received the captured second flag. In the only combination that reaches this linked-byte read, that captured flag is nonzero. Thus, absent intervening mutation, self-aliasing makes the linked-byte test pass even if the snapshot destination contained zero at entry.

### Zero-field path

When the initial discriminator read is zero, eligibility is:

| Selector | Eligibility |
|---|---|
| 0 | First flag is zero, regardless of the second flag. |
| 1 | Both flags are zero, or the first flag is nonzero and either the second flag is zero or the linked byte is nonzero. |
| Any other value | Both flags are zero. |

Selector 1 therefore rejects a zero first flag paired with a nonzero second flag.

If eligible, the function invokes F-0000000000bc through the saved service receiver’s table. The represented explicit arguments are the saved receiver and integer 1. The operation’s return value is unused.

If ineligible, the function returns without invoking a dependency.

This path neither derives nor directly stores a classification, and it does not invoke F-0000000000c4 or the object callback.

### Nonzero-field path: classification

When the initial discriminator is nonzero, the function derives a classification byte:

| Full classification input | Derived byte |
|---|---:|
| 3 | 2 |
| 4 | 1 |
| 5 | 2 |
| Any other value | 0 |

The comparisons use the complete 32-bit integer input. They do not first truncate it to one byte. Negative values and values such as 259 therefore fall into the final row.

Every derived result is within 0–2. Storing that result in one byte loses no value. No arithmetic beyond the represented address-offset calculations is needed to derive the classification.

### Nonzero-field path: storage and eligibility

“Store” below means a direct one-byte write of the derived classification to object offset `+0x1C0`.

| Selector | First flag | Second flag | Store | Dispatch |
|---|---|---|---|---|
| 0 | Zero | Zero | Yes | Yes |
| 0 | Zero | Nonzero | Yes | Yes |
| 0 | Nonzero | Zero | No | No |
| 0 | Nonzero | Nonzero | Yes | No |
| 1 | Zero | Zero | Yes | Yes |
| 1 | Zero | Nonzero | No | No |
| 1 | Nonzero | Zero | No | Yes |
| 1 | Nonzero | Nonzero | No | Only if the subsequently read linked byte is nonzero |
| Other | Zero | Zero | Yes | Yes |
| Other | Zero | Nonzero | No | No |
| Other | Nonzero | Zero | No | No |
| Other | Nonzero | Nonzero | No | No |

For selector 0 with both flags nonzero, the classification is stored and the function returns without invoking either operation on this path.

For selector 1 with a nonzero first flag, eligible execution performs no classification store. The callback nevertheless receives the newly derived classification; that argument need not equal the existing byte at `+0x1C0`.

Where the linked-byte check is required, it precedes dispatch and no classification store is performed.

### Nonzero-field path: dispatch

Eligible execution proceeds in this order:

1. Performs any classification store required by the table.
2. Resolves F-0000000000c4 through the saved service receiver’s table and invokes it.
3. Receives a four-byte result.
4. Invokes the callback selected from object offset `+0x1B8`, passing:
   - The four-byte provider result.
   - The derived classification value.
   - The four-byte context from object offset `+0x1BC`.
5. Returns without using the callback’s result.

No explicit arguments to F-0000000000c4 are represented. An implicit receiver or other ABI-defined argument is not established.

The callback address and context are read for the invocation after the provider returns; they are not saved before that call. The provider can therefore change the callback target or context that will be used. The initial nonzero discriminator check is not repeated.

The relative order of the post-provider callback-address and context reads is not established. The classification argument remains the value derived before the provider call, even if the provider changes stored object state.

## Side effects

### Direct stores and overlapping storage

The directly represented stores are limited to:

- One byte at object offset `+0x004`.
- One byte at object offset `+0x005`.
- Conditionally, one byte at object offset `+0x1C0`.

There are **no stores issued through the linked-object reference**. This is not a guarantee that linked-object storage remains unchanged. Any of these object-relative stores may modify storage also designated by the linked reference.

In particular, when the linked reference equals the input object address, the unconditional snapshot store at object offset `+0x005` also writes the linked object’s `+0x005` byte. The later eligibility read uses that updated byte, not its entry value.

Likewise, no disjointness between object storage and externally referenced service storage is established. A claim that such storage is unchanged merely because it has another role would be unsupported.

The function does not directly assign the source-flag fields, callback-address field, or callback-context field through their object-relative offsets. Dependencies may change them.

### Dependency effects and state retention

Dependency side effects are unknown. They may mutate accessible memory, including the object, external root, receiver, and dispatch table.

The saved receiver address is not reloaded after a dependency invocation. This does not freeze the contents of the receiver or its table.

Classification stores precede provider dispatch. They are not restored afterward. If such a store overlaps storage used to resolve the service operation, resolution uses the storage available at that later access; no disjointness guarantee excludes that possibility.

No allocation, owned-object copy, release, ownership transfer, or reference-count adjustment is directly shown. The provider result is a four-byte value; its interpretation as a handle, address, number, or other representation is unknown.

### Errors and abnormal completion

There is no explicit error result, diagnostic, recovery handler, or rollback.

Invalid storage or callable targets may prevent normal completion. The precise failure mode is environment-dependent and not established.

If an access or dependency fails before return, later actions are not guaranteed. Earlier completed stores are not explicitly undone. A provider that replaces the callback address with zero or an invalid target does not trigger a second validity check in this function.

## Acceptance examples

These are conditional deductions from static evidence, not executed tests. Required storage and callable targets are assumed valid, and invoked dependencies return normally unless an example says otherwise.

1. **Snapshots despite rejection.**  
   With a selector other than 0 or 1 and a nonzero first flag, either discriminator path rejects dispatch. Both snapshot stores still occur. The function performs no classification store and invokes no dependency.

2. **Selector 0 ignores the second flag on the zero-field path.**  
   With discriminator zero, selector 0, first flag zero, and second flag `0x80`, F-0000000000bc is invoked once with the saved receiver and integer 1. The linked reference is not read, and no classification is stored.

3. **Asymmetric selector-1 rejection.**  
   With selector 1, first flag zero, and second flag nonzero, neither discriminator path dispatches. The linked reference is not consulted. The nonzero-field path performs no classification store.

4. **Distinct linked storage controls eligibility.**  
   With selector 1 and both flags nonzero, suppose linked offset `+0x005` does not overlap a snapshot destination and remains stable. A zero byte there rejects dispatch; a nonzero byte permits the appropriate operation sequence. Neither case performs a classification store.

5. **Self-aliasing changes the consulted linked byte.**  
   Let the linked reference designate the input object, with selector 1, both source flags nonzero, and object offset `+0x005` initially zero. The snapshot store replaces that zero with the captured nonzero second flag. The later linked-byte read is nonzero, so dispatch is eligible on either discriminator path. No classification store occurs.

6. **Classification store without dispatch.**  
   With a nonzero discriminator, selector 0, both flags nonzero, and classification input 4, the function stores 1 at `+0x1C0` and returns without invoking the provider or callback.

7. **Stored and callback classifications agree when undisturbed.**  
   With a nonzero discriminator, selector 0, first flag zero, second flag nonzero, and classification input 5, the function stores 2 before invoking the provider. The callback receives the provider result, classification 2, and the post-provider context. If dependencies do not alter the classification destination, its stored value remains 2.

8. **Dispatch without updating stored classification.**  
   With a nonzero discriminator, selector 1, first flag nonzero, second flag zero, classification input 3, and classification destination initially 9, the callback receives classification 2. The function makes no classification store; absent dependency mutation, the destination remains 9.

9. **Full-width comparison.**  
   On an eligible nonzero-field path, classification input 259 produces classification 0, not 2. Matching the low byte of 3 is insufficient.

10. **Provider changes callback selection.**  
    If the provider replaces the callback address and context with other valid values, the subsequent callback invocation uses those replacements. Its classification argument remains the value derived before the provider call.
