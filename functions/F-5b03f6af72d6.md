# F-5b03f6af72d6

## Purpose

F-5b03f6af72d6 exposes an ordered sequence of indirect dependency calls, calculated memory reads, byte writes, and 32-bit word writes. Its application-level purpose is not established. Initialization, clearing, or reconstruction of encoded state is **inferred intent**, not a supported functional guarantee.

Dependencies are unresolved. Their calls remain observable boundaries even where no outgoing arguments are displayed: they may change memory, fault, or fail to return.

### Outputs and widths

No explicit return value, status, error object, or normal return is displayed. Observable outputs are memory accesses, outgoing dependency values, dependency effects, and any fault or nonreturning behavior.

A **word** is 32 bits; a **byte** is eight bits. Selector reads are unsigned bytes. Byte writes retain the low eight bits of their payload. All right shifts specified below are logical.

For compactness:

- A source’s **scaled word** means four times that source.
- Its **high-field byte** means the low eight bits of the source masked with `0x3fffffff`, then shifted right by 20.
- **Reduced central value** means the central value masked with `0x3fffffff`, then shifted right by one.
- **Narrow reduced value** means the reduced central value masked with `0x3fffff`.

Unsigned 32-bit shifts and arithmetic have their represented unsigned widths. Some other scaling and address expressions use signed quantities. Low-32-bit wrapping is a possible machine interpretation, but is not established as a portable guarantee for every expression. Examples involving potentially overflowing signed expressions are therefore conditional on that interpretation.

Endianness, alignment rules, and memory mapping are unknown.

## Side effects

### Memory layout and ordering

The evidence establishes numeric relationships, not a coherent object or record layout:

- Byte selectors are read at calculated bases plus one.
- Selector-directed byte writes use selector plus 17.
- One direct byte clear uses reduced central value plus 15.
- Word stores use calculated addresses with offsets 20, 36, or 68.
- Word reads use scaled word plus 20 and sixteen times central value plus 116.
- Four separate word clears target absolute address 36.

An unsigned selector gives a selector-plus-17 address from 17 through 272. The retained-selector-plus-68 word clear starts from 68 through 323. These are absolute numeric addresses, not implicit offsets from entry base.

Some word addresses can be unaligned. Byte and word accesses may overlap, including the storage at address 36. Endianness determines the byte effects of overlapping word accesses but is unspecified.

No read or clear can be removed from this contract merely because its address repeats. Intervening calls may alter memory; accesses themselves may also be externally observable.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Fourth-argument shift.** Fourth arguments of 7, 8, and `0xffffffff` yield word payloads of zero, one, and `0x1fffffff`.

2. **Absolute selector addressing.** A selector of 255 directs a selector-plus-17 byte write to address 272, not entry base plus 272.

3. **Byte truncation.** A source of 65 has scaled value 260; its scaled-byte write stores 4. A source of `0x3fffffff` has masked high field `0x3ff`; its high-field byte write stores `0xff`.

4. **Fresh selector reads.** If successive reads return 2 and 9, the corresponding byte writes target addresses 19 and 26. No dependency-preservation assumption may force those selectors to match.

5. **Distinct payload and outgoing source.** If the initial source is `0x00100000` and **F-B09** returns 7, the second initial byte write stores 1; the following **F-B10** call receives 28.

6. **One unchanged pair, then transformation.** If **F-B24** selects 3, its two propagation writes store 12. If **F-B34** also selects 3, its first write stores 12 but the later transformed write stores 6.

7. **Mask after scaling.** If **F-B34** selects `0x10000001`, the scaled word is `0x40000004`. Masking that word and shifting right by one yields 2.

8. **Different write and read addresses.** If **F-C12** selects 3, the write targets address 68 and the following word read targets address 32. The write alone does not establish the read value.

9. **Central companion identity.** If **F-C32** returns 5 and **F-C39** returns 9, **F-C33** receives 20 and **F-C40** receives 36. **F-C45** receives three copies of `0x02800000`, followed by `0x0a000000`: all derive from 5.

10. **Final high-field call boundaries.** If **F-F11** returns 7, **F-F12** receives 28 after the second final-selector byte write. If **F-F23** returns 11, **F-F24** receives 44 after the last high-field byte write. Either call may prevent all subsequent operations by failing to return.

11. **Repeated clears and partial completion.** If a dependency writes nonzero data at address 36 between explicit clears, the next clear writes zero again. If an earlier selector read faults, preceding stores may remain visible; no rollback is established.
