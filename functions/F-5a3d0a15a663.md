# F-5a3d0a15a663

## Purpose

F-5a3d0a15a663 constructs two 32-bit words using a caller-supplied integer, source bytes reached through global state, and the result of dependency F-550be5ac61a3. It stores each constructed word twice, then stores a separate globally supplied 32-bit value.

The established behavior is ordered observation, word construction, and storage. Device-register meanings, operating modes, and relationships between the destination fields are not established.

The function has no explicit return value, validation branch, or error-reporting mechanism.

- **Input:** One integer, represented as a signed 32-bit quantity in the supplied representation.
- **Return:** No explicit value.
- **Observable outputs:** One dependency invocation and, if execution completes normally, five 32-bit stores.

The caller’s integer is overridden when the initially observed source byte at offset 7 equals 0, 1, 2, or 3. Other byte values leave the argument unchanged.

## Behavior

### Initial source observations

First, the function reads and retains the source-base slot’s value.

It then references that slot again to read the source byte at offset 7. This observation selects the effective integer:

| Initial byte at offset 7 | Effective integer |
|---:|---|
| 0 | 0 |
| 1 | 1 |
| 2 | 2 |
| 3 | 3 |
| Any other value | Caller’s argument |

Next, it references the source-base slot to read the byte at offset 6. This observation produces an initial Boolean contribution:

- Zero produces 0.
- Any nonzero value produces 1.

No other property of this byte contributes to the initial word.

Under stable global state, the retained source address and both initial byte addresses refer to the same source object. The representation does not justify replacing these separate slot references with one universal source-address observation when describing changing or specially observed storage.

### Dependency input

The dependency input is the bitwise OR of:

- The initial Boolean contribution.
- The effective integer shifted left by 6 bits.

There is no explicit mask restricting the effective integer to two bits. Effective integers 0 through 3 contribute only in bits 6 and 7, but an unrecognized selector allows the caller’s integer to contribute additional bits.

F-550be5ac61a3 is called once with this word. The initial word and initial Boolean contribution remain available for the later calculations.

### Post-dependency capture and first word

The post-call sequence is:

1. F-550be5ac61a3 returns its integer result.
2. The function reads the destination-base slot and retains that address.
3. It constructs the first output word by ORing the dependency input with the dependency result shifted left by 14 bits.
4. It obtains the first store’s address through another reference to the destination-base slot.
5. It writes the first word at that address plus 0x3C4.
6. It writes the same word at the retained destination address plus 0x3CC.

The retained destination address is therefore captured **before** the first-word calculation, not after it. The first store’s slot-based address and the second store’s retained address are distinct address sources.

No intervening dependency invocation occurs between these destination-slot references. With stable ordinary storage, they identify the same destination object. If the references observe different values under an applicable execution model, the first store can target a different object from all subsequent stores. Synchronization or concurrent-mutation semantics are not established here.

The first-word construction is an OR, not a field replacement. Existing bits in the dependency input are not cleared. No mask is applied to the dependency result before its shift.

Under a 32-bit bit-vector interpretation, only the dependency result’s low 18 bits survive the left shift by 14. This interpretation is conditional; the signed-shift qualification below still applies.

### Later source observations and second word

After both first-word stores, the function reads the source through the address retained before the dependency call:

1. Read the byte at offset 6.
2. Read the byte at offset 7.

Replacing the source-base slot during the dependency does not redirect these later reads. Modification or invalidation of the retained source object can nevertheless affect them.

The later offset-7 observation selects an upper contribution:

| Later byte at offset 7 | Upper contribution |
|---:|---:|
| 0 | 0 |
| Any nonzero value | 0x3000 |

This later selection differs from the initial argument override: all nonzero values have the same effect.

The later offset-6 observation selects a low contribution:

| Later byte at offset 6 | Low contribution |
|---:|---:|
| 0 | 8 |
| 1 | 7 |
| 2 | 1 |
| Any other value | Initial Boolean contribution |

For the last row, the function preserves the contribution derived from the **initial** offset-6 observation. It does not recompute a Boolean from the later byte. Thus an unrecognized later byte can produce either 0 or 1, depending on the earlier observation.

The second output word is the bitwise OR of the selected low and upper contributions. Its possible values, when the described calculation is reached, are 0, 1, 7, 8, 0x3000, 0x3001, 0x3007, and 0x3008.

### Remaining stores

The function then performs these stores, all through the retained destination address:

1. Second word at offset 0x3C8.
2. Same second word at offset 0x3D4.
3. Current final-value slot contents at offset 0x14.

The final-value observation belongs to the final assignment, after the preceding stores. It is not a value retained before the dependency or before the destination updates.

There is no further dependency invocation or explicit result.

### Integer and address arithmetic

The effective integer and dependency result are signed before their respective shifts. Consequently, the evidence does not establish portable wrapping behavior for every possible argument or dependency result:

Suppose the dependency replaces the source-base slot with another valid address but leaves the original retained object readable.

### Destination capture and first-store reference are distinct

Suppose the dependency changes the destination-base slot to address A and returns. The function captures A before constructing the first word.

If the slot remains A, all five stores use A as their base.

Conditionally, if the applicable execution model allows the first-store reference to observe address B instead, the store at offset 0x3C4 uses B. The stores at offsets 0x3CC, 0x3C8, 0x3D4, and 0x14 still use retained address A. This is a conditional address-selection consequence, not an established concurrency guarantee.
