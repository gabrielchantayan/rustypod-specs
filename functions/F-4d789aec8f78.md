# F-4d789aec8f78

## Purpose

F-4d789aec8f78 processes an outer node and its linked node using a mutable context, a requested destination, and an opaque option. The outer node’s kind selects evaluation, intermediate storage, and conversion behavior. Successful branch processing is followed by result-count reconciliation and, conditionally, metadata construction.

**Inferred intent:** the nodes describe compound-query operands, with ordering and limit restrictions, intermediate destinations, and column metadata. These interpretations do not establish the meanings of opaque dependencies or emitted operations.

The operation is not transactional. Errors can follow counter increments, emissions, allocation, and node mutations. Only explicitly described restoration writes are established.

## Interface

### Arguments and result

The four arguments are:

1. A mutable context pointer.
2. A nullable outer-node pointer.
3. A pointer to a readable and writable four-word requested-destination descriptor.
4. An opaque 32-bit option forwarded to evaluation.

The supplied representation uses 32-bit pointers and words. Byte fields and the explicitly identified 16-bit flag are exceptions.

The 32-bit return value is:

| Condition | Result |
|---|---:|
| Missing outer or linked node | `1` |
| Ordering or limit restriction | `1` |
| Emission-context acquisition returns zero | `1` |
| Intermediate preparation returns nonzero | `1` |
| Result counts differ | `1` |
| Metadata allocation returns zero | `7` |
| Evaluation returns nonzero | That evaluation status |
| Ordinary completion | `0` |

Other dependency results are used or ignored as described; they are not independently converted into errors. Memory faults and nonlocal exits have no established return contract.

### Requested destination

| Byte offset | Width | Role |
|---|---:|---|
| 0 | 32 bits | Control word; low byte selects destination behavior |
| 4 | 32 bits | Payload, including an intermediate-slot value |
| 8 | 32 bits | Copied tail word; initial candidate linked pointer |
| 12 | 32 bits | Copied opaque tail word |

All four words are read before testing the outer pointer. A null destination pointer is therefore not a supported no-op input.

A present outer node replaces the candidate linked pointer with its offset-32 pointer. Descriptor contents cannot compensate for a missing outer node.

Processing uses a local descriptor copy. Every normal return writes its current offset-8 and offset-12 words back to the caller, in that order. No explicit copy-back occurs for offsets 0 and 4. Dependencies receiving the local descriptor may change its contents, so the tail writes are not guaranteed to restore entry values.

### Accessed layouts

Offsets are in bytes; these are partial layouts, not complete types.

| Object | Offset | Observed role |
|---|---:|---|
| Context | 0 | Pointer used for allocation, configuration, and fallback values |
| Context | 68 | Intermediate-slot counter |
| Node | 0 | Result-structure pointer; its first word is the result count |
| Node | 4 | Kind byte |
| Node | 8 | Metadata-triggering byte |
| Node | 9 | Shared-path flag |
| Node | 28 | Auxiliary-object pointer |
| Node | 32 | Linked-node pointer |

| Node | 44, 48 | Transferred, temporarily cleared, or restored fields |

Auxiliary records have 12-byte stride, with a referenced-object pointer at offset 0 and a word at offset 8 whose low byte is consumed. Referenced objects provide a 16-bit flag at offset 2, a direct word at offset 4, and a signed 32-bit index at offset 40.

Storage must support all accesses actually reached. Pointer validity, sufficient allocation sizes, and terminating linked chains are not comprehensively checked.

## Behavior

### Entry and restrictions

Both the outer node and its saved linked node must exist. Otherwise the function returns `1` through the descriptor-tail write-back path.

For an existing pair, restrictions are checked in this order:

1. Nonzero linked offset 28 selects the ordering-related diagnostic.
2. Otherwise, nonzero linked offset 44 selects the limit-related diagnostic.
3. Otherwise, F-9b3ea8470521 obtains an emission context; zero produces return value `1`.

Each restriction diagnostic reads the outer kind byte, passes it to F-da98301c2095, then calls F-2022b0f73f3b with the context, the selected restriction-format address, and the formatter result. It then returns `1`.

After obtaining an emission context, requested control byte `9` causes F-887ba2404a49 to emit operation `0x70` with the requested payload and zero. Its returned handle becomes pending. The local requested control byte changes to `8`, preserving the upper 24 bits.

The outer kind and auxiliary pointer are then read. This saved auxiliary pointer controls branch selection and later metadata eligibility; it is distinct from later reads of the node’s current auxiliary pointer.

### Shared path: `j`, `l`, and `k` with saved auxiliary data

The intermediate type is `8` for `k`, otherwise `1`.

The requested payload is reused as the intermediate slot only if the requested control byte equals that type, the saved auxiliary pointer is null, and outer offsets 44 and 48 are both zero.

Otherwise, the current context counter supplies a fresh slot. The counter advances by one before F-91e520893aef receives context, outer node, and slot. Any nonzero preparation result becomes return value `1`, without reversing the increment.

Successful preparation is followed by operation `0x70` with the slot and zero. For type `8`, its handle becomes pending. For type `1`, the handle is written to outer offset 60, then byte 8 of the object referenced by outer offset 40 is set to `1`. F-927b7c5904b2 then receives context, outer node, and saved auxiliary pointer. Reuse skips preparation, this emission, and this callback.

F-1e7ea6aa642e receives a temporary-buffer address, intermediate type, and slot. Its complete initialization behavior is unknown. F-7a1ceda22360 evaluates the saved linked node with that buffer, three zero arguments, and the opaque option. A nonzero status returns immediately.

After linked success, the outer kind is reread. The replacement temporary-buffer control byte is `1` for `j`, `8` for `k`, `2` for `l`, and zero otherwise. Before outer evaluation:

- Outer offsets 32 and 28 are cleared, in that order.
- Byte 9 is set according to whether the saved auxiliary pointer is nonnull.
- Offset 44 is saved and cleared, followed by saving and clearing offset 48.
- The temporary buffer’s low control byte is replaced without changing its other bytes.

Outer evaluation uses the same evaluation interface. On normal return, including an error result, cleanup occurs in this order:

1. F-e5380ae57ea1 receives current outer offset 28.
2. The saved linked pointer and then saved auxiliary pointer are restored.
3. F-841dc33ee157 receives current outer offset 44.
4. Offset 44 is restored.
5. Offset 52 becomes `0xffffffff`.
6. Offset 48 is restored.
7. Offset 56 becomes `0xffffffff`.

Byte 9 is not restored. A nonzero evaluation status returns after this cleanup.

Conversion is skipped exactly when the local requested type equals the saved intermediate type and the requested payload equals the saved intermediate slot. The payload comparison matters only when the types match. Temporary-buffer contents do not determine this predicate.

When conversion is required, requested type `5` first triggers terminal-chain processing: follow current outer offset-32 links to the terminal node, then call F-bfa847659f8b with context, zero, and that node’s result-structure pointer.

Conversion obtains first and second markers through F-bb6565faa675. F-ce5e3d6d9ab0 receives context, outer node, and first marker. Operation `0x74` is emitted through F-2ea344827b50 with intermediate slot, first marker, and zero. The emission-context word at offset 12 is then saved.

2. Outer node.
3. Current outer result-structure pointer.
4. Intermediate slot.
5. Current outer result count.

The second marker is placed through F-2148ac0f693b; operation `0x67` uses the slot, saved emission-context word, and zero. The first marker is placed, then operation `0x20` uses the slot and two zeros.

### Kind `k` without saved auxiliary data

Outer offset 44 is copied to linked offset 44, then offset 48 is copied correspondingly. Linked evaluation receives the local requested destination.

After it returns, outer offsets 44 and 48 are cleared even on error. A nonzero status returns without outer evaluation.

On linked success, outer offset 32 is cleared. Linked offsets 52 and 56 are copied to the outer node. If the copied offset-52 value is signed-nonnegative, F-211638bb75da receives the emission context and operation `0x78`.

Outer evaluation uses the local requested destination. The saved linked pointer is restored before checking its status. After successful evaluation, a nonzero handle returned by F-211638bb75da is passed to F-a2b3e96577b2 with the emission context and **no count argument**.

The field transfers and outer clears are not generally reversed.

### Reconciliation and mismatch diagnostic

Unrecognized kinds skip branch evaluation but are not rejected solely for their kind.

The outer result count is read and saved, then compared against the count reached through the saved linked node’s current result-structure pointer. Comparison is equality of 32-bit values.

On mismatch, the diagnostic sequence is specifically:

1. Reread the outer kind byte.
2. Call F-da98301c2095 with that byte.
3. **After the formatter returns, read a diagnostic-format pointer from a global.**
4. Call F-2022b0f73f3b with context, that newly read pointer, and the formatter result.
5. Return `1` through descriptor-tail write-back.

The global format pointer is neither established as constant nor captured before formatting. F-da98301c2095 may affect that global; its implementation is unknown. The report therefore uses the pointer observed after that call.

Matching counts cause pending handles to be processed in reverse creation order through F-a2b3e96577b2, with emission context and the saved common count.

### Metadata construction

Metadata is required when the saved auxiliary pointer is nonnull or, otherwise, current outer byte 8 is nonzero. Let **N** be the saved reconciled count.

Three auxiliary-count observations are distinct:

- **Allocation count:** read through the saved auxiliary pointer before allocation; zero without that pointer.
- **Population count:** reread through the saved pointer after column population and chain-handle processing.
- **Handle count:** subsequently read through the outer node’s then-current auxiliary pointer.

F-f053f140662a receives the context’s first pointer and the 32-bit size expression `20 + 5 × (allocation count + N)`. Zero produces return value `7`.

After allocation succeeds, the context’s first pointer is reread. Its offset-8 pointer is followed, then that object’s offset-20 pointer; byte 89 of the resulting object is written to allocation offset 4. N is then written to allocation offset 8.

Column words begin at allocation offset 16. A signed loop from zero while less than signed N calls F-3327d2013945 with context, outer node, and index. Its result is written to the corresponding word. Zero is replaced by a fresh read of offset 44 through the context’s current first pointer.

The current outer linked chain is traversed. At each node, offsets 60 and 64 are inspected in order as signed handles. A negative handle stops that node’s processing, so a negative offset-60 value skips offset 64. Each accepted handle is passed first to F-a2b3e96577b2 with emission context and N, then to F-2b905b6e3991 with emission context, handle, allocation, and selector `0xfffffffa`. Its node slot is then set to `0xffffffff`.

With saved auxiliary data, population count and record-array pointer are now read. The relocated-column address is allocation base plus `16 + 4 × population count`; the byte area follows by `4 × N`.

The byte-area pointer is written to allocation offset 12 before an unidentified external transfer dependency receives relocated-column address, allocation base plus 16, and N shifted left two bits in 32 bits. Successful copying and overlap handling are not established.

A signed loop over population count fills the metadata prefix. Each record supplies either its referenced object’s offset-4 word, when flag `0x100` is set, or an indexed word from the calculated relocated-column address using the referenced object’s signed offset-40 index. The record’s offset-8 low byte is written to the byte area.

Outer offset 68 is saved as a handle. F-a2b3e96577b2 receives emission context, that handle, and the separately read handle count plus two. Allocation offset 8 is replaced by population count. F-2b905b6e3991 receives emission context, saved handle, allocation, and selector `0xfffffff7`.

Only this auxiliary path calls F-98dbd0a45e01 with context, outer node, emission context, current result count, and local requested destination. Finally, F-94cb53877c15 receives zero on this path, or the allocation pointer without auxiliary data. Neither argument establishes ownership or release.

## Side effects

Observable effects include descriptor-tail writes, counter advances, ordered dependency calls, diagnostics, global diagnostic-format reads, emissions, node mutations, allocation, and metadata writes.

There is no general rollback. Preparation failure retains counter advancement. Evaluation failures retain preceding effects except explicit restoration. Count mismatch occurs after branch processing and before pending-handle reconciliation. Allocation failure occurs after pending handles have been processed.

No dependency is assumed to preserve globals, descriptors, context, nodes, or allocated contents. Pointer passage alone establishes neither retention nor ownership transfer. Explicit restoration writes do not prevent subsequent dependency mutation.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, dependencies return normally without additional mutations.

1. **Missing outer:** a readable destination and null outer yield `1`, with ordered tail write-back and no emission-context request.

2. **Competing restrictions:** nonzero linked offsets 28 and 44 select the ordering diagnostic.

3. **Preparation failure:** fresh-slot allocation advances the counter before preparation; any nonzero preparation result becomes `1`.

4. **Conversion predicate:** matching requested type and slot skip conversion despite temporary-buffer changes. Matching payload alone is insufficient.

5. **Conversion arguments:** shared slot `12` and count `3` become arguments four and five respectively. For kind `m`, slots `20` and `21` with count `4` produce arguments four and five of `20` and `4`.

6. **Shared outer error:** pointer processing, restoration, and offset-52/56 resets precede return of the evaluation error.

7. **Kind-`k` linked error:** transfers remain, outer offsets 44 and 48 are cleared, and outer evaluation is skipped.

8. **Mismatch with formatter mutation:** if unequal counts are found and F-da98301c2095 changes the global format pointer from address A to address B, the subsequent global read supplies B to F-2022b0f73f3b. No pending-handle processing follows.

9. **Changing auxiliary counts:** allocation count `2` sizes the allocation; later population count `3` controls relocation and replacement metadata count. No resizing or consistency check is established. The separately observed handle count controls the count-plus-two argument.

10. **Ineffective transfer:** indexed selection still uses the calculated relocated-column address; valid copied values are not guaranteed.

11. **Negative first handle:** negative offset 60 skips offset 64 for that node.

12. **Allocation-time context mutation:** configuration traversal uses the context pointer reread after allocation, not an entry snapshot.

## Uncertainties

The following remain **documented_only**:

- Complete types, valid kind domains, diagnostic text, and operation meanings.
- Dependency implementations and temporary-buffer initialization.
- Global diagnostic-format pointer contents and possible formatter-induced changes.
- Ownership, lifetime, retention, release, and external-transfer semantics.
- Pointer validity, chain acyclicity, record validity, index bounds, and unwritten allocation fields.
- Effects of dependency mutations and aliasing.

Arithmetic uses 32-bit quantities without explicit overflow checks. Counter increments, allocation sizing, handle-count addition, scaled addresses, and shifted transfer sizes can exceed their mathematical ranges. No portable overflow or invalid-memory policy is established.

Reconciliation compares count bit patterns, while column and auxiliary-population loops use signed comparisons. High-bit counts therefore do not imply corresponding positive iteration counts. Allocation sizing does not establish that later writes are in bounds, particularly when counts change between observations.
