# F-f656fc898bc6

Its observable contract consists of ordered memory accesses and calls. There is no represented normal return, explicit success result, validation stage, or recovery path. A dependency, breakpoint, invalid access, or operation outside the defined arithmetic model can prevent later effects.

## Behavior

### Entry selection and initial effects

Selection depends on the selector’s upper 12 bits, not on whether the complete selector is zero.

When those bits are nonzero, a 32-bit store writes their value to the address obtained by multiplying Data by 256 and adding 32. Both address calculations are unsigned 32-bit operations.

This path selects control-address state `0x08790D52`. Its first inner-call argument is formed by converting the wrapped unsigned product of Data and 256 to signed 32-bit form, then shifting that signed value right by 29.

A software breakpoint with immediate value 4 occurs after the initial store. Only if execution continues does the numerical Destination address undergo conversion to signed 32-bit form and a signed right shift by 18. Conversion of that result to unsigned 32-bit form initializes the address base.

The pointer conversion, out-of-range unsigned-to-signed conversion, and signed right shifts require the actual target’s rules.

When the upper selector bits are zero, the operation instead:

- assigns zero to the shared reset cell;
- updates the accumulator using Data;
- stores the updated accumulator as 32 bits through Destination;
- enters inner processing with argument zero.

The accumulator addition is unsigned because Data is unsigned. It therefore wraps modulo \(2^{32}\), after which assignment converts the result to signed 32-bit storage. A result above the signed maximum raises an out-of-range conversion question, not signed-addition overflow.

This entry path bypasses the initial address-derived store, breakpoint, address-base initialization, and initial control-address assignment. It does not return.

### Inner processing: capture, accesses, and dependencies

Each inner cycle captures the current Data byte before calling any dependency or replacing Data. That captured value remains the source for the cycle’s later explicit byte effects.

The first dependency is **F-000000000001**. It receives the current signed 32-bit argument. Its target is obtained by adding `0xA1E` to the carried signed control-address state; that addition must be representable for an ordinary defined signed result.

The returned 64-bit carrier has two separate roles:

- conversion of the complete carrier to a pointer supplies the destination of a 16-bit store;
- its high word later contributes to the address of a pointer read.

The 16-bit store occurs first. Its value is the same carrier converted to signed 16-bit form; low-bit truncation is not independently established.

Before the pointer read derived from the carrier’s high word, the following memory effects occur in this order:

1. A 32-bit self-addressed store writes the unsigned product of the address base and 64 at the address numerically equal to that product.
2. A 32-bit read through the current auxiliary pointer replaces Data.
3. A 16-bit store at address base plus four records a value derived from the auxiliary pointer.

The product used for the self-addressed store does **not** replace the address base. Subsequent base-relative accesses still use the existing base.

For the third access, the auxiliary-pointer address is converted to signed 16-bit form, increased by four after integer promotion, then narrowed back to signed 16-bit form. The promoted addition itself fits within signed 32-bit range; the pointer conversion and final narrowing can still require target-specific behavior.

Only after these accesses is the auxiliary pointer replaced. Its replacement is read as a represented 32-bit pointer from the address obtained by converting the first carrier’s high word to signed 32-bit form and adding 80. This is signed addition, not unconditional wrapping address arithmetic. If the converted value is greater than `0x7FFFFFAF`, adding 80 exceeds the signed 32-bit maximum.

Calls then occur in this order:

**F-000000000002**, **F-000000000003**, **F-000000000004**, **F-000000000005**.

The first two have no explicit arguments. The third receives replacement Data. Before the fifth call, the control-address state becomes `0x0897EDF1`; the fifth receives Data logically shifted right by three.

### Repetition criterion

The high word returned by **F-000000000005** supplies a retained output pointer. Separately, the complete carrier is converted to signed 32-bit form and multiplied by 32. Only after that signed multiplication is the result assigned to unsigned 32-bit storage.

If the converted signed operand is \(n\), defined multiplication requires:

\[
-67{,}108{,}864 \le n \le 67{,}108{,}863.
\]

The unsigned destination does not make an overflowing signed multiplication wrap.

When multiplication is defined, the unsigned product is written as 32 bits at the address numerically equal to that product. This access precedes the unsigned comparison against 19.

A product greater than 19 leaves inner repetition. Otherwise, another cycle starts with argument zero. Every defined product is a multiple of 32, so zero is the only defined product that repeats. The write at address zero must occur before that repetition can proceed.

Defined negative products become large unsigned values and select the exit path. A retained output pointer from a repeating cycle is replaced by the next cycle’s result before post-inner effects can use it.

Following an ordinary repetition, the next first dependency call uses the updated control-address state rather than the initial entry state.

### Effects after inner exit

On exit, the address base is stored as 32 bits at product plus 88. A 16-bit conversion of the current auxiliary-pointer address is then stored at address base plus 14. Both address additions are unsigned and wrapping.

Data is replaced by the address base shifted left by two using unsigned 32-bit arithmetic. The shared reset cell is then assigned the byte captured at the beginning of the exiting cycle.

Next, **F-000000000006** receives the auxiliary-pointer address converted to unsigned 32-bit form and logically shifted right by two. The control-address state subsequently becomes `0x0897EE1D`, and **F-000000000007** is called without an explicit argument.

The reset assignment therefore uses the pre-read captured byte, not necessarily replacement Data’s low byte. Neither this assignment nor the earlier zero assignment guarantees the eventual reset-cell value: subsequent dependencies may modify that shared storage.

### Final output group

The high word returned by **F-000000000007** replaces Destination. Conversion of the complete carrier to a pointer supplies a distinct write base.

Four writes occur in this order:

| Order | Destination and contents |
|---|---|
| First | One captured byte at the address obtained by converting the write base to signed 32-bit form and multiplying by two |
| Second | One byte obtained by converting the carrier’s high word to character type, at write base plus eight bytes |
| Third | The retained output pointer, as a represented 32-bit pointer, at the address obtained by multiplying the signed accumulator by two |
| Fourth | The complete returned 64-bit carrier at the write base |

The second displacement is eight **bytes**, not eight carrier-sized elements. The final store writes the carrier value itself; it does not copy memory referenced by that value.

Each signed multiplication by two requires an operand between \(-1{,}073{,}741{,}824\) and \(1{,}073{,}741{,}823\), inclusive. A doubled address outside that range is not established by modular arithmetic.

After these writes, the accumulator is replaced using the retained output-pointer address converted to signed 32-bit form and shifted left by two. The address base is replaced using the auxiliary-pointer address converted to signed 32-bit form and shifted left by eight, followed by assignment to unsigned storage.

These shifts have signed operands. Under the ordinary defined signed-left-shift model, negative operands and nonrepresentable results are not valid. Assignment to unsigned storage after the second shift does not repair an invalid shift.

The retained output pointer then receives three consecutive 32-bit fields, in increasing-offset order:

| Byte offset | Contents |
|---|---|
| 0 | Current Data: the previous address base shifted left by two |
| 4 | The newly updated address base |
| 8 | The auxiliary-pointer address converted to unsigned 32-bit form |

The first field uses Data computed before the address-base replacement.

## Acceptance examples

These are conditional static criteria, not executed tests. Each assumes valid prior execution and suitable storage for every reached access.

1. **Upper-bit selection.** Selector `0xABC12345` with Data 1 produces an initial 32-bit store of `0xABC` at address `0x120`, before the breakpoint. Continuation beyond the breakpoint is a separate condition.

2. **Nonzero selector, alternate entry.** Selector `0x000FFFFF` takes the zero-upper-bits path. It assigns zero to the reset cell, updates and stores the accumulator, and enters inner processing with argument zero. Its first indirect target depends on incoming control-address state.

3. **Unsigned accumulator addition.** Accumulator −1 and Data 1 produce zero. Accumulator `0x7FFFFFFF` and Data 1 instead produce unsigned `0x80000000` before signed reassignment; that reassignment requires the target’s out-of-range conversion rule.

4. **Address base remains unscaled.** With address base `0x100`, the self-addressed store writes `0x4000` at address `0x4000`. The following base-relative 16-bit store is at `0x104`, not `0x4004`.

5. **Zero-product repetition.** A numerical carrier of zero from **F-000000000005** produces a zero product and attempts a 32-bit zero store at address zero. Another cycle occurs only if that access and subsequent execution proceed.

6. **Positive-product exit.** A numerical carrier of one produces product 32 and writes 32 at address 32 before exiting inner repetition. Its high-word output pointer is zero; later accesses are not thereby validated.

7. **Signed overflow is not wrapping.** If carrier conversion yields `0x08000000`, multiplication by 32 exceeds signed 32-bit range. A wrapped zero product, address-zero write, or repetition is not established.

8. **Captured byte survives Data replacement.** If entry Data ends in `0x7A` and the auxiliary read replaces it with a value ending in `0x03`, the later explicit reset assignment uses `0x7A`, if reached. A later dependency may overwrite it.

9. **Doubling boundary.** A write base converted to signed `0x40000000` cannot be unconditionally doubled to obtain address `0x80000000`; the signed multiplication is outside its defined range.

10. **Overlapping output writes.** If a final byte destination overlaps the later 64-bit destination, the byte write occurs first. Final contents depend on the subsequent carrier store, overlap, and target byte order.
