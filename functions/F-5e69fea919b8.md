# F-5e69fea919b8

## Purpose

F-5e69fea919b8 coordinates a gated operation through several dependencies. It first requests a four-byte value associated with an input object, creates an auxiliary context, and obtains a classification. Only classifications 2, 3, and 4 permit a preparation attempt. Successful preparation permits a final operation using a second context and both remaining caller-supplied arguments.

The function returns a four-byte zero only when the initial gate, preparation, and final operation each report zero, and the classification is supported. Every other normally returning path produces a four-byte one.

This is an orchestration contract. The supplied evidence does not establish the application meaning of the input object, classifications, selected global values, context storage, or final operation.

## Interface

### Inputs

The function accepts three arguments:

1. **Input-object address.** Represented by a 32-bit integer in the supplied evidence. It is passed unchanged to F-b6ed73c78832. On paths that pass the initial gate, the function also reads a four-byte field beginning four bytes after this address.
2. **First forwarded value.** An opaque four-byte value passed unchanged to F-e6be4b0a25d8 if the final operation is reached.
3. **Second forwarded value.** Another opaque four-byte value passed unchanged to F-e6be4b0a25d8 if the final operation is reached.

The second and third arguments are not otherwise interpreted by this function. Their values are not used to select a branch.

The input object’s complete layout is unknown. Only the four-byte field at byte offset 4 is directly accessed here. That field is read separately before classification, preparation, and final execution; it is not captured once for reuse.

### Return value

The function returns a four-byte status:

- **0:** the final operation returned zero after all preceding gates admitted execution, and both subsequent cleanup calls returned normally.
- **1:** the initial gate returned nonzero, the classification was unsupported, preparation returned nonzero, or the final operation returned nonzero, with any cleanup on that path having returned normally.

Dependency error values are not propagated. All nonzero gate, preparation, and final-operation results collapse to the same outward status, 1.

These return guarantees apply to normal completion. A dependency that does not return, a failing memory access, or another execution fault can prevent the function from returning either status.

## Behavior

### 1. Initial gate

The first dependency call is F-b6ed73c78832. It receives the original input-object address and the address of the four-byte gate output.

If its result is nonzero, the function returns 1 immediately. No context initialization, classification, configuration-global read, preparation, final execution, or cleanup call follows on that path.

If its result is zero, execution continues. The gate output is subsequently used as a four-byte argument, without local validation.

### 2. Auxiliary-context initialization and classification

F-a78f26e86530 receives the address of the four-byte auxiliary-context storage. Its return value, if any, is not used to choose a path.

The function next reads the input-object field at byte offset 4 and calls F-cc79b872f81c with:

- The auxiliary-context address.
- The four-byte field value just read.
- The gate output.

The returned classification is tested for exact equality with 2, 3, and 4. No range test or normalization is performed.

Any result other than those three values prevents preparation and final execution. That includes zero, one, negative results under the shown signed interpretation, and all other representable values.

### 3. Configuration selection

Two distinct global four-byte values participate in selection. Their contents and application meanings are unknown. This contract calls them the **primary configuration global** and the **secondary configuration global**.

The read order is significant:

- The primary configuration global is read after classification returns, regardless of the classification.
- If the classification is 2, that value is selected and the secondary global is not read.
- If the classification is not 2, the secondary configuration global is also read.
- For classification 3 or 4, the secondary value is selected for preparation.
- For every unsupported classification, neither value reaches preparation because preparation is skipped.

Thus, an unsupported classification still causes both global reads before auxiliary-context cleanup. The primary read must not be modeled as occurring only for classification 2.

These are reads of current global contents after classification returns. No evidence establishes that earlier dependencies preserve those globals or that the pair is read atomically.

### 4. Preparation

For classifications 2, 3, and 4, the function reads the input-object field at byte offset 4 again. It then calls F-a2123d550bfc with, in order:

1. The auxiliary-context address.
2. The newly read field value.
3. The gate output.
4. The selected configuration value.
5. The address of the four-byte prepared output.
6. The address of the separate four-byte additional preparation output.

If preparation returns nonzero, the operation context is not initialized and the final operation is not called. The function proceeds to auxiliary-context cleanup, then returns 1 if cleanup returns normally.

If preparation returns zero, execution continues. The additional preparation output is not directly examined afterward. Its contents do not independently influence this function’s return status.

### 5. Operation-context setup and final execution

F-41b37059d890 receives the address of the 12-byte operation-context storage and the supported classification. Its return value, if any, does not control execution.

After that setup call returns, the function reads the input-object field at byte offset 4 a third time and calls F-e6be4b0a25d8 with:

1. The operation-context address.
2. The latest field value.
3. The prepared output.
4. A literal zero in the fourth argument position.
5. The caller’s first forwarded value.
6. The caller’s second forwarded value.

The final operation’s result determines the eventual outward status: exactly zero selects success, and any nonzero result selects failure. Cleanup still occurs before either status is returned.

### 6. Cleanup and return

Whenever operation-context setup and final execution have returned normally, F-33f41a428c53 is called with the operation-context address. This occurs for both zero and nonzero final-operation results.

F-28346ad464bf is then called with the auxiliary-context address.

On unsupported-classification and failed-preparation paths, only F-28346ad464bf is called. On initial-gate failure, neither cleanup dependency is called.

Cleanup return values are not used to select the outward status. Their possible external effects, failure modes, and nonreturning behavior remain unknown.

## Side effects

### Direct reads and writes

The directly evidenced external-memory reads are:

- Up to three separate four-byte reads from input-object offset 4.
- One read of the primary configuration global after every completed classification.
- One additional read of the secondary configuration global whenever the classification is not 2.

The number of input-field reads depends on the path:

| Path | Input-field reads |
|---|---:|
| Initial gate rejects | 0 |
| Unsupported classification | 1 |
| Supported classification; preparation fails | 2 |
| Final operation reached | 3 |

The function does not directly assign to the input object or configuration globals in the supplied evidence. That does not imply they remain unchanged: dependencies may mutate them through aliases or other access.

Writes to local storage can occur through the addresses passed to dependencies. This function does not itself establish the internal contents of either context.

### Ordering and changing state

The three input-field reads need not produce the same value. Classification, preparation, operation-context setup, or another actor may change the field between reads. The behavior uses each value at its own read point.

Likewise, the configuration values are obtained after classification. Values observed before calling the function would not necessarily be the values forwarded to preparation.

The function establishes call order, not transactionality. It contains no explicit rollback, retry, locking, or restoration of earlier state. A failure return does not establish that earlier dependencies left no externally visible effects.

### Ownership and lifetime

The input-object address and forwarded values are not directly freed or retained by this function. No ownership-transfer convention for them is established.

Temporary-storage addresses refer to local storage whose lifetime ends when this invocation exits. Whether dependencies retain those addresses, allocate resources, release resources, or require additional cleanup is unknown.

The calls described as cleanup are established by their position in the control flow and the context addresses they receive. Their names in this contract do not guarantee deallocation, resource release, or restoration of state.

## Acceptance examples

These are conditional acceptance cases derived from static control flow, not executed tests. Each assumes valid memory accesses and normal dependency returns unless stated otherwise.

1. **Initial rejection.** If F-b6ed73c78832 returns any nonzero value, the result is 1. It is the only dependency called. No direct input-field or configuration-global read occurs.

2. **Unsupported classification.** If the gate returns zero and classification returns 5, both configuration globals are read, preparation is skipped, auxiliary-context cleanup runs, and the result is 1.

3. **Classification 2 succeeds.** If the gate returns zero, classification returns 2, preparation returns zero, and final execution returns zero, preparation receives the primary configuration value. The secondary global is not read. Operation-context cleanup precedes auxiliary-context cleanup, and the result is 0.

4. **Classification 3 or 4 succeeds.** Under otherwise successful conditions, both configuration globals are read, but preparation receives the secondary value. The exact classification, 3 or 4, is passed to operation-context setup.

5. **Preparation fails.** With a supported classification and any nonzero preparation result, neither operation-context setup nor final execution nor operation-context cleanup occurs. Auxiliary-context cleanup runs, and the result is 1. The preparation error value is not returned.

6. **Final execution fails.** After successful preparation, any nonzero final-operation result still leads to both cleanup calls, in operation-context-then-auxiliary-context order. The outward result is 1.

7. **Input field changes between calls.** If the field supplies value A before classification, value B before preparation, and value C after operation-context setup, the three respective dependencies receive A, B, and C. Reusing A for all three would not match the evidenced behavior.

8. **Auxiliary initializer reports a value.** If F-a78f26e86530 returns normally with any return value, classification still follows. No success check on that return value is established.

9. **Cleanup does not return.** Even when final execution returned zero, nonreturning operation-context or auxiliary-context cleanup prevents an outward return of 0.
