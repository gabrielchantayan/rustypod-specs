# F-efd491563f88

## Purpose

F-efd491563f88 derives a target position for a mutable, polymorphic object. Depending on that target and mode-dependent queries, it may change an offset, propagate a scaled displacement to an associated object and an embedded region, perform additional processing, and notify a recipient.

Its Boolean result reports only whether the first position returned by F-30ee4f4bfdfc differs from the derived target. It does not report whether the offset changed, whether notification occurred, or whether dependencies completed successfully.

“Position,” “offset,” “unit size,” and “displacement” are inferred semantic labels. The field accesses, arithmetic, branch conditions, and call relationships described below are established by the supplied static representation.

## Interface

### Input and result

The function receives a pointer to a mutable object. The supplied representation uses 32-bit integer fields and 32-bit pointer-bearing object slots.

The result is:

- **True** when the retained initial position differs from the retained target.
- **False** when those values are equal.

There is no explicit null-pointer check, object-size check, type validation, or structured error result.

The caller must supply valid storage and dispatch targets for every access reached. Dependencies may introduce additional requirements that are not established here.

## Behavior

### Entry observations and normalization

The function first reads the adjustment input at `0xC4`, negates it, and retains that value as the **adjustment**.

It then calls F-30ee4f4bfdfc with the input object and the additional visible arguments adjustment, `0`, `2`, and `2`. Its integer result becomes the retained **initial position**.

Only after that call does the function read `0xE8` and retain the **saved offset**. If this saved value is negative, it writes zero to `0xE8`.

A second call to F-30ee4f4bfdfc follows. Only the object argument is explicit for this invocation in the supplied representation. Its result plus the retained adjustment becomes the **candidate**.

Consequently:

- The saved offset is not necessarily the entry offset: the first dependency may have changed it.
- The second dependency runs after any initial normalization.
- The second dependency may change the offset again; normalization is not a lasting invariant.

### Target selection

After the second position call, the function obtains the current endpoint-minus-base difference, called the **span**.

The target is selected as follows:

- If candidate exceeds span, target is span.
- Otherwise, target is candidate when candidate is nonnegative, or zero when candidate is negative.

This is not an unconditional clamp to a nonnegative interval. A negative span can become the target when candidate exceeds that span.

The target is retained for the remainder of the function. Later dependency mutations do not cause it to be recalculated.

### Branch selection

The function compares target with:

**current unit size × current unit count + current offset**

If target is below this threshold, the mode-`2` query is skipped. Otherwise, the input object’s dispatch entry at `0xCC` is called with the object and mode `2`.

A nonzero mode-`2` result selects the **threshold-side update**. A skipped mode-`2` call or a zero result leads to the lower-side decision.

At that decision, target is compared with the then-current offset:

- If target is not below the offset, select the fallback path.
- If target is below the offset, call the input object’s dispatch entry at `0xCC` with mode `1`.
- A nonzero mode-`1` result selects the **lower-side update**; zero selects fallback.

A mode query may mutate the object. Reads after a query observe the state then present, not a guaranteed entry snapshot.

The static representation establishes sequencing across statements and calls. It does not establish a relative evaluation order among independent field reads within one expression.

### Lower-side update

The function reads the current offset, adds the retained adjustment, and writes the sum to `0xE8`. If that computed sum is negative, it writes zero to the same field.

It then captures the associated-object pointer from `0x118`.

If the pointer is null, associated displacement processing is skipped. The function proceeds to post-update processing.

If non-null, the following operations occur in order:

1. Call F-870c4fcf7295 with saved offset minus current offset, followed by current unit size.
2. Multiply its result by the scale factor read from `0xD8` after that call. Retain this product as the scaled displacement.
3. Add the scaled displacement to the current value at `0xE0` and write the result there.
4. Invoke the captured associated object’s dispatch entry at `0x144` with the associated object and additional arguments `0`, scaled displacement, `1`, `0`.
5. Call F-d156b0b83eb3 with the input object’s interior address at `0xF0`, `0`, and the negated scaled displacement.

The conversion difference uses the saved offset, even when that saved value was negative before normalization.

The associated-object pointer is captured before conversion and reused afterward. No lifetime-protection operation is visible.

### Threshold-side update

The function reads the current offset and writes that value plus the retained adjustment to `0xE8`.

It then reads and retains unit size, followed by unit count. Using these retained values, it compares the current endpoint-minus-base difference with:

**retained count × retained size + pre-addition offset + adjustment**

The additions in this comparison are grouped as product plus pre-addition offset, then plus adjustment. Representability must hold for those intermediates, not merely for the mathematical final total.

If the current span is smaller than that expression:

1. Call F-870c4fcf7295 with retained target and retained unit size.
2. Replace `0xE8` with:

   **(1 − retained count) × retained size + retained size × conversion result**

The retained size and count remain the operands of this replacement even if the conversion dependency changes the corresponding fields.

After the optional replacement, the function reads the offset and writes zero if it is negative.

It then captures the associated-object pointer. If null, it skips associated displacement processing. This does not skip any alignment conversion already required above.

If the pointer is non-null:

1. Call F-870c4fcf7295 with current offset minus saved offset, followed by current unit size.
2. Multiply its result by the scale factor read after that call.
3. Subtract this scaled displacement from the current value at `0xE0`.
4. Invoke the captured associated object’s dispatch entry at `0x144` with additional arguments `0`, negated scaled displacement, `1`, `0`.
5. Call F-d156b0b83eb3 with the interior address at `0xF0`, `0`, and the unnegated scaled displacement.

In both update branches, the associated-object operation and embedded-region operation receive opposite displacement signs.

### Processing after an update branch

- If its result is zero, proceed to finalization.
- Otherwise, call F-0d27caf8e50d, then F-92bea7c30bd6, each with the input object.

No returned-success condition from F-0d27caf8e50d gates the second call.

First call F-3fac671648b8. If its result is nonzero and initial position differs from target, call F-3ba0d8b4ad23 twice:

1. With the input object and initial position.
2. With the input object and target.

Call F-3fac671648b8 again regardless of the first result.

Only if this second result is nonzero and the saved offset is negative, call F-0d27caf8e50d followed by F-92bea7c30bd6.

The two query results are independent observations. Neither is assumed to predict the other.

The base is therefore read after any notification. Notification effects may change the coordinate used by this final update.

The return value is the retained initial-position-versus-target comparison, unaffected by dependency return values or later field changes.

## Acceptance examples

These are conditional static scenarios, not executed tests. Unless otherwise stated, dependencies return normally, leave relevant state unchanged, and arithmetic remains representable.

### Position changes without offset movement

Let adjustment be zero, initial position `5`, second position result `8`, span `20`, offset zero, and threshold `10`.

Target is `8`. Both mode queries are skipped: target is below threshold but not below offset. If both fallback queries return zero:

- No branch-specific offset write occurs.
- No offset notification occurs.
- Final position update receives current base plus `8`.
- The result is true.

### Normalization with a false result

Let saved offset be `−3`, initial position and target both be `4`, and fallback be selected. Let both fallback queries return zero and the recipient be nonzero.

Normalization writes zero. Finalization notifies with zero as argument 4, performs no final position update, and returns false.

### Negative span

With candidate `5` and span `−2`, target is `−2`, not zero. Subsequent behavior depends on the branch gates. The result is false only if initial position is also `−2`.

### Lower-side displacement

Suppose lower-side updating is selected with saved and current offset `12`, adjustment `−4`, and a non-null associated object. The new offset is `8`.

If F-870c4fcf7295 returns `2` for arguments `4` and current unit size, and the subsequently read scale is `3`:

- `0xE0` increases by `6`.
- Associated dispatch receives displacement `6`.
- The later embedded-region call receives displacement `−6`.

### Threshold alignment

Suppose threshold-side updating is selected with saved and current offset `6`, adjustment `5`, unit size `4`, unit count `3`, span `20`, and target `20`.

The first offset write is `11`. The comparison threshold is `12 + 6 + 5 = 23`, so alignment is required. If conversion of target `20` with size `4` returns `5`, the replacement offset is `12`.

A subsequent associated displacement conversion uses difference `12 − 6`, absent intervening mutations.

### Notification observes changed globals

Suppose finalization finds a changed offset and nonzero recipient. An earlier dependency has changed global source A from `7` to `9` and global source B from `11` to `13`, with no subsequent changes.

The notification receives `9` as argument 2 and `13` as argument 3. The contract does not require either global read to precede the other.

### Equality does not suppress offset effects

When initial position equals target, the result is false, paired fallback position calls are suppressed, and final position dispatch is suppressed.

Offset writes, associated displacement, processing calls, and offset notification can still occur.
