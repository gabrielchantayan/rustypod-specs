# F-7c508d5bec54

## Purpose

F-7c508d5bec54 conditionally translates an unsigned integer from one numeric region into another. An input qualifies only when shifting it right by 20 bits produces exactly `0x180`. A qualifying input is adjusted by subtracting one externally stored value and adding another. Every other input is returned unchanged.

The arithmetic is consistent with translating an address or offset between two bases. That interpretation is inferred intent, not an established requirement: the function does not dereference the input, check that it denotes memory, or validate that the translated result belongs to any region.

The supplied representation supports a 32-bit unsigned behavioral model. Under that model, qualifying inputs occupy the inclusive interval `0x18000000` through `0x180FFFFF`, and adjustment arithmetic wraps modulo \(2^{32}\). The missing type and data declarations limit how independently the machine widths and external storage layout can be established; those limits are recorded below.

## Interface

**Input:** One unsigned integer, passed by value.

**Output:** One unsigned integer. It is either the original input or the adjusted value, depending on the selection condition.

**External input state:** A globally referenced base supplies access to two stored integer values:

| Role | Location shown relative to the external base | Use |
|---|---:|---|
| Subtraction value | Offset `+4` | Subtracted from a qualifying input |
| Addition value | Offset `+8` | Added after the subtraction, in the arithmetic expression |

These roles describe arithmetic use, not ownership or a confirmed data-structure schema. The external base’s declaration, allocation, initialization, lifetime, and synchronization rules are not provided.

For the 32-bit model:

- The argument and result are 32-bit unsigned values.
- The selection shift is a logical right shift by 20 bits.
- The two external values are read through signed-integer access expressions.
- With 32-bit signed integers and ordinary unsigned conversion rules, each external value contributes its 32-bit residue to the unsigned calculation.
- The result is reduced modulo \(2^{32}\); overflow does not produce saturation or a separate error result.

There is no output pointer, status parameter, or separately represented error channel. All 32-bit result patterns can be ordinary arithmetic results.

## Behavior

### Selection

The function first evaluates the input shifted right by 20 bits and compares that result with `0x180`.

For a 32-bit unsigned input, the comparison examines all upper 12 bits. The lower 20 bits do not affect selection. Consequently:

- `0x18000000` qualifies.
- `0x180FFFFF` qualifies.
- `0x17FFFFFF` does not qualify.
- `0x18100000` does not qualify.

This is equality of the entire shifted value, not a test that some subset of bits is present. Inputs outside the selected interval do not qualify merely because they share individual set bits with `0x180`.

### Nonqualifying input

If the comparison fails, the function returns the original input without arithmetic adjustment.

The supplied body places both external integer accesses inside the qualifying branch. Thus, at the source-behavior level, a nonqualifying invocation does not require either external stored value to be read. There is no visible validation, fallback calculation, or secondary selection rule on this path.

The unchanged return is exact: it does not clear bits, normalize the value, or reinterpret it as an address.

### Qualifying input

If the comparison succeeds, the result is defined by:

\[
\text{result}
=
\bigl(\text{input}-\text{subtraction value}+\text{addition value}\bigr)
\bmod 2^{32}
\]

This formula uses the values obtained by the two external accesses during that invocation. It does not establish that those values came from one consistent snapshot.

The selection decision is made from the original input. There is no second selection check after adjustment. A translated result may therefore lie anywhere in the unsigned result range, including outside the interval that selected the branch.

No bounds checks constrain the external values. In particular:

- The subtraction value need not equal the beginning of the selected interval.
- The addition value need not designate a region of the same size.
- The subtraction value may exceed the input.
- Either arithmetic stage may wrap.
- The result may be zero.
- The result may equal the input.

Although the low 20 input bits do not affect selection, they still participate in the adjustment. The function does not explicitly preserve those bits by masking. They remain unchanged only for external values whose difference has the appropriate alignment.

### Signed external values

The external accesses are expressed as signed-integer reads, while the argument is unsigned. Under the stated 32-bit model, conversion to unsigned arithmetic makes a negative external value contribute its residue modulo \(2^{32}\).

For example, a subtraction value represented as signed `−1` contributes `0xFFFFFFFF`. Subtracting it is equivalent, modulo \(2^{32}\), to adding one. A negative external value is not visibly rejected or treated as an error.

### Access ordering and consistency

The selection condition must determine whether the adjustment path is taken. The adjustment expression then requires the two external integer values.

The supplied expression does **not** establish a left-to-right order for the two memory reads. Parenthesizing the subtraction establishes arithmetic grouping, not a guaranteed order in which its operand and the addition operand are fetched.

Accordingly, this contract does not promise that:

- The subtraction value is read before the addition value.
- The external base is captured once and reused.
- Both values come from the same backing object if the base can change.
- Concurrent updates are observed consistently.
- The reads have volatile, atomic, acquire, or other synchronization semantics.

With a stable base and stable readable storage, these ordering uncertainties do not change the numeric result. They matter if external state can change during evaluation or if accesses have effects beyond ordinary memory reads.
