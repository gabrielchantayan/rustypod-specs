# F-971745bb50d1

## Purpose

F-971745bb50d1 dispatches a 32-bit selector against a current mutable context. A recognized path sets a byte flag, updates a 32-bit bitfield, processes rectangle-like state, or invokes a dependency chain. An unrecognized path initializes the context’s first four-byte field to `0x500` if that field is zero.

These operations are established by the supplied static representation. Interpreting them as event handling, invalidation, or property updates is inferred intent only.

Six dispatch boundaries have unavailable values. Their repeated observations must be distinguished: an unsuccessful equality comparison does not constrain a boundary value read later. This contract therefore defines eligibility through ordered comparison outcomes, not through an assumed immutable partition of selector values.

## Interface

### Inputs and result

- One signed 32-bit integer selector.
- No exposed return value.
- F-7fba0909c452 is called without arguments to obtain the current context.
- If it returns null, the function returns without directly accessing context memory.

The context-acquisition call may itself have effects. A null result does not establish that the whole invocation is side-effect-free.

### Memory model and preconditions

Offsets in this contract are byte offsets from the acquired context unless explicitly identified as object offsets.

The representation establishes:

- One-byte flag stores.
- Four-byte integer loads, stores, and bitfields.
- A four-byte pointer-bearing field at `0xAE0`.
- Four-component records with four bytes per component.

The highest explicitly addressed fixed context field is `0xAE0`, occupying four bytes. This does not establish the allocation size. The indexed branch can address other locations.

The context and any referenced object must remain accessible for every selected access. The function receives no size, ownership token, or validity descriptor and performs no general memory validation.

## Behavior

### Dispatch entry and precedence

Context acquisition precedes all dispatch.

With a non-null context, the first comparison tests selector equality with A. If true, the first bitfield update occurs and the function returns.

If that equality test is false, a fresh observation of A is used to test whether the selector is less than A:

- True enters the lower route.
- False enters the alternative route.

The alternative route does **not** establish that the selector is strictly greater than the newly observed A. Equality with that later observation is possible.

Recognized operations return without executing fallback initialization. Within each list of literal cases below, comparisons occur in the listed order and the first match wins.

**`0x964` + 36 × index**

The stride is 36 bytes. The indexing calculation uses four-byte elements before the destination is treated as a byte address.

There is no visible index-range, sign, overflow, or allocation-bound check. Valid use requires representable address calculation and writable destination storage. Neither a valid index range nor wrapping behavior is established.

### Bitfield updates

| Operation | Field offset | Shift-count base |
|---|---|---|
| First | `0x2F4` | `0x3000` |
| Second | `0x89C` | `0x4000` |

Each operation derives its count by unsigned 32-bit subtraction of the indicated base from the selector, followed by retention of the low eight bits.

The shifted left operand is the **signed integer literal one**. Unsigned arithmetic in the count does not make that operand unsigned.

For counts from zero through 30, the direct four-byte read-modify-write sets the selected bit and preserves the other bits. The first operation expresses this through clearing and then setting the same mask; the second uses bitwise OR directly.

Two additional cases remain unresolved:

- **Count 31:** portable signed 32-bit C semantics do not establish a result for shifting signed one into the sign bit.
- **Counts 32 through 255:** the count is outside the width of the shifted operand; target-level behavior is not established.

The eight-bit count reduction is not a five-bit reduction. This contract does not assume hardware masking or substitute an unsigned shift.

Eligible explicit first-field literals select positions 0, 1, 2, 4, and 5. Eligible explicit second-field literals select positions 0, 1, 3, 4, 5, and 7. These counts avoid the signed-shift uncertainty. Unresolved equality boundaries A, D, and E need not do so.

Neither update is shown as atomic.

### Rectangle-related operation

The eligible `0x0C11` branch first stores one byte of value one at `0x130`, then reads the four-byte pointer-bearing field at `0xAE0`.

A zero pointer causes immediate return. The direct store at `0x130` remains, and this function does not directly modify the rectangle cache or result flag on that path.

For a nonzero pointer, the function reads the four-byte context field at `0x130`, narrows it to character size, and tests for zero. This is not an explicit byte load. On an ordinary little-endian target with stable memory, the preceding byte store makes the narrowed value nonzero. Target byte order is not established, so both represented branches remain documented.

The loaded object address is retained for subsequent object accesses; it is not visibly reloaded from `0xAE0` after dependency calls.
