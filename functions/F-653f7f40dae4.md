# F-653f7f40dae4

## Purpose

The supplied representation does not establish a higher-level purpose such as object initialization, allocation, serialization, or device configuration.

The visible sequence has three broad effects:

- Propagates incoming state and dependency-produced values into 32-bit fields.
- Writes and clears byte-sized fields selected through fresh byte reads.
- Clears several computed 32-bit fields and the 32-bit location at address `0x24`.

These are descriptions of the supplied static representation, not independently verified machine behavior. The representation explicitly reports invalid instruction data and overlapping global symbols. Its apparent control flow, signatures, and memory accesses therefore require qualification.

No normal return is visible. The represented sequence ends at an invalid-instruction boundary.

## Behavior

### Numeric and memory conventions

The representation uses 8-bit byte accesses, 32-bit word accesses, and one dependency result treated as 64 bits.

For describing address calculations below, “scaled” means multiplication by the stated factor before adding the stated offset. When interpreting this as a 32-bit machine operation, the address and value calculations retain their low 32 bits. That is an interpretation of the represented machine-width arithmetic, not a guarantee supplied by a language-level signed-overflow rule.

Unsigned right shifts are logical. In particular:

- Shifting the third input right by three discards its lowest three bits.
- Masking with `0x3fffffff` retains 30 bits.
- Masking with `0x003fffff` retains 22 bits.
- A byte write retains only the lowest eight bits of its computed value.

Some left shifts and multiplications are displayed with signed intermediate types. Their exact instruction semantics remain uncertain; they must not be specified as portable signed arithmetic.

The descriptions below use named result tokens for explanation. These names do not identify source variables or establish object types.

“No explicit arguments” describes the supplied representation only. It does not establish that the actual dependency consumes no registers or other incoming state. Calls whose results are not explicitly used remain observable and must not be discarded.

### Initial word-field propagation

The first indirect call receives the first and second inputs, the third input, and the additional incoming register value shifted right by three. Four calls with no explicit arguments follow.

The resulting first token selects a 32-bit write at four times that token plus `0x14`. The stored value is the other incoming register value.

A call receives four times the first token. After four further calls with no explicit arguments, a second token is obtained. A 32-bit write then stores four times that second token at sixteen times the second token plus `0x14`.

That four-times-scaled value is retained across another argument-bearing call and four further calls. The resulting third token selects a write at four times the third token plus `0x14`; the retained value is stored there.

The same call-and-four-calls pattern produces a fourth token. A word at sixteen times the fourth token plus `0x14` receives four times the fourth token.

The next call receives that four-times-scaled fourth token. A subsequent no-explicit-argument call produces an opaque value, which is passed to another call. Four further calls produce a fifth token.

Next, a 32-bit word is read at four times the sixth token plus `0x14`. Its unsigned value shifted right by three becomes the next call’s explicit argument. This read is not necessarily from the word just written: their base scales differ.

### Byte-selected writes and clearing

The function reads a byte at sixteen times the retained token plus one. That byte, interpreted as an unsigned number from 0 through 255, selects a byte-write address by adding `0x11`.

The written byte is the low eight bits of the retained token masked with `0x3fffffff` and shifted right by 20. Thus only original bits 20 through 27 reach the stored byte; bits 28 and 29 are lost through byte truncation.

A call receives four times the newly retained result. One call returns an opaque value, which is forwarded to another call; four more calls follow. The byte at sixteen times the retained token plus one is then read again, and zero is written at that newly selected byte address.

- Zero is written at the retained token masked with `0x3fffffff`, shifted right by one, plus `0x0f`.

A later call receives four explicit arguments: three copies of the earlier retained result shifted left by 23, and one copy shifted left by 25. An opaque result is obtained, forwarded to another call, and followed by four calls.

## Acceptance examples

These examples are conditional static expectations, not executed tests.

1. **Third-input address equivalence.**  
   With otherwise identical execution and third inputs `0x20` and `0x27`, the first third-input-derived word-write address is the same: both inputs shift right by three to four, selecting address `0x00200024`. The stored words remain different: `0x20` and `0x27`.

2. **Fresh selector semantics.**  
   If a selector read returns `0x12`, its byte-write target is `0x23`. If intervening dependencies change the selector to `0x34`, the subsequent fresh-read write targets `0x45`, not `0x23`.

3. **Byte truncation after shifting.**  
   A token of `0x3ff00000`, masked with `0x3fffffff` and shifted right by 20, yields `0x3ff`. The represented byte store writes `0xff`, not a wider value.

4. **Byte truncation after multiplication.**  
   If a final-stage token is `0x40`, its four-times-scaled byte value is zero after truncation to eight bits.

5. **Captured selector survives intervening calls.**  
   If the selector retained for the later `+0x44` word clear is `0xfe`, that clear targets `0x142`, even if a dependency subsequently changes the selector’s memory location.

6. **Repeated fixed-location clears remain distinct.**  
   If a dependency writes a nonzero value to address `0x24` between two explicit clears, the later clear must still occur. Treating the four clears as one final assignment loses observable ordering.

7. **Partial progress on failure.**  
   If a dependency does not return after an earlier store, the specification does not require subsequent stores or restoration of the earlier value.
