# F-029930293dcb

## Purpose

F-029930293dcb conditionally updates a 32-bit word within a caller-supplied object and, for a narrow set of resulting values, invokes an indirect function selected through the object’s first word.

The established behavior consists of three stages:

1. Test bit 1 of the byte at object offset 20.
2. If that bit is set, subtract four from the 32-bit word at offset 20 and store the result.
3. If the stored result has no bits set above bit 1, attempt an indirect call through a table referenced by the object’s first word.

An interpretation involving a packed counter and flags is plausible but **inferred intent**, not an established interface. The evidence does not identify the object type, the meaning of the tested bit, or the role of the indirect operation. In particular, it does not establish destruction, reference release, deallocation, or an ownership transfer.

## Interface

### Input

The function receives one object-address argument. No separate size, type tag, callback argument, or error-output parameter is visible.

The recovered access model uses 32-bit object words. The following offsets and widths describe that model:

| Object-relative offset | Access | Meaning established by the evidence |
|---|---|---|
| 0 | Read of the first 32-bit word, only on the indirect-call path | Supplies the base address used to locate the indirect target |
| 20 | One-byte read | Bit 1 determines whether further processing occurs |
| 20–23 | 32-bit read followed by a 32-bit write, when the gate passes | Value is reduced by four using modulo-\(2^{32}\) arithmetic |

On the indirect-call path, the function also reads a callable address from offset 4 relative to the base obtained from object offset 0. That base-relative address is not object offset 4.

Pointer representation, callable-address width, alignment requirements, and calling convention are not independently established by the supplied evidence. The 32-bit recovered layout must not be silently generalized to a layout with wider object words or differently spaced entries.

### Output

The function has no specified return value. Its observable results are:

- No write and no indirect call when the initial byte test fails.
- A 32-bit write at offset 20 when the initial byte test succeeds.
- A possible indirect call after that write.

There is no visible status code, exception translation, retry, or rollback mechanism.

### Preconditions

For the initial operation, the argument must identify storage readable at byte offset 20.

For the update path, the 32-bit word spanning offsets 20–23 must be readable and writable under the target’s memory and alignment rules.

For the indirect-call path, additional requirements apply:

- The first object word must be readable.
- Its value must support the table-relative access at offset 4.
- That access must yield a callable target.
- The target must be valid under the actual calling convention and machine state.

These requirements are not validated by this function. A null or invalid object address is not made safe by the later null comparison.

## Behavior

### Initial byte gate

The function first reads the byte at object offset 20 and tests it with the one-byte mask `0x02`.

If the tested bit is clear, the function returns immediately. On this path:

- It does not perform the subsequent full-word read at offset 20.
- It does not write the object.
- It does not read the object’s first word.
- It does not resolve or invoke the indirect target.

Other bits in the tested byte do not affect this initial decision.

The initial byte read and the later word read are distinct operations in the supplied representation. The evidence does not establish an atomic snapshot spanning them.

### Word update

When the initial byte test succeeds, the function reads the 32-bit word at offset 20, subtracts four, and writes the 32-bit result back to the same location.

The arithmetic is unsigned modulo \(2^{32}\). Underflow wraps rather than saturating, rejecting the operation, or producing an explicit error.

For example, a word value of two becomes `0xFFFFFFFE`. The function does not protect against a value smaller than four.

The initial gate is a byte-level condition; the subtraction affects the entire word. It is therefore incorrect to describe the operation as an isolated byte update or a guaranteed preservation of all adjacent flag bits. Any such interpretation requires additional invariants about the object representation.

### Post-update decision

The function tests the computed subtraction result with the 32-bit mask `0xFFFFFFFC`.

The indirect-call path is selected exactly when this masked result is zero. Equivalently, the computed result must be one of:

- Zero.
- One.
- Two.
- Three.

The predicate uses the locally computed result. It does not visibly reread the stored word to decide whether to call.

For the subtraction alone, those four results correspond to original word values four through seven. Reaching the call also requires that the earlier byte gate passed.

On a little-endian target, assuming the byte and word reads observe a consistent value, the combination of both conditions admits only original word values six and seven:

| Original word | Initial byte gate | Stored result | Indirect call |
|---|---|---|---|
| Four | Fails | No write | No |
| Five | Fails | No write | No |
| Six | Passes | Two | Yes |
| Seven | Passes | Three | Yes |

This table is conditional on byte order and stable storage. The evidence does not independently establish target endianness.

If the post-update predicate fails, the function returns with the subtraction already committed.

### Null comparison and indirect dispatch

After a successful post-update predicate, the function compares the original object address with null. If equal, it returns.

This comparison occurs only after the earlier byte read, word read, and word write. It is not an entry guard. Ordinary callers must not treat null as a supported no-op input.

If the address is non-null, the function:

1. Reads the first object word.
2. Uses that value as a table base.
3. Obtains the indirect target from table offset 4.
4. Invokes the target.
5. Returns if the target returns normally.

The object update precedes target resolution and invocation. A returning callee may observe the updated object if it has access to it, but the evidence does not establish how the object address is communicated to that callee.

No post-call restoration or additional object operation is visible. A callee’s failure, non-return, or further effects must not be replaced with an assumed normal return.

## Side effects

### Direct memory effects

The sole direct write established for F-029930293dcb is the 32-bit store at object offset 20.

That store occurs whenever the initial gate passes, including when:

- The subtraction wraps.
- The post-update predicate fails.
- A later table access fails.
- The indirect target does not return normally.

No rollback is visible.

There is no direct allocation, deallocation, buffer copy, logging, or global-variable write in the supplied body.

### Effects through the indirect target

The indirect target is unresolved. It may alter object storage, globals, external resources, or allocation state. It may also release memory or fail to return. None of those possibilities is established as required behavior, and none can be excluded from this evidence alone.

Consequently, callers cannot infer that the object remains live after an invocation that reaches the target. They also cannot infer that the target releases it.

## Acceptance examples

These examples are conditional contract checks, not reports of executed tests.

### Gate-clear object

Given valid storage whose byte at offset 20 has bit 1 clear, the function returns without changing the object or invoking F-unknown-indirect.

Readable table metadata is unnecessary for this path because target resolution is not reached.

### Ordinary decrement without dispatch

Assume a little-endian target, stable storage, and an initial word of ten at offset 20.

The gate passes. The function stores six. Because six has a nonzero intersection with `0xFFFFFFFC`, it returns without reading the dispatch table.

### Boundary values that dispatch

Under the same byte-order and stability assumptions:

- An initial word of six becomes two and reaches indirect dispatch.
- An initial word of seven becomes three and reaches indirect dispatch.

Acceptance additionally requires valid first-word and table accesses and a callable target. Merely supplying either numeric value does not make an otherwise invalid object safe.

### Boundary values excluded by the gate

On a little-endian target with stable storage, initial words four and five cause an immediate return. Although subtracting four would mathematically produce zero or one, that subtraction is not performed because the byte gate fails.

An implementation that unconditionally subtracts before checking the gate would violate this behavior.

### Unsigned wraparound

Assume a little-endian target with an initial word of two.

The gate passes. The function stores `0xFFFFFFFE` and returns without indirect dispatch. Treating this as saturation at zero or as an explicit underflow error would not match the established arithmetic.

### Invalid dispatch metadata after a valid update

Assume the gate passes and the subtraction produces two, but target resolution cannot complete successfully.

The update precedes the failing resolution. No restoration of the original word is specified. The precise fault or failure manifestation is platform-dependent and remains documented_only.

### Null input

Null input has no supported safe-return contract. The function attempts the initial offset-20 byte access before reaching its null comparison.

A platform-specific mapping that makes that access possible would not establish null as a generally valid input.
