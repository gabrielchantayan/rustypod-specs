# F-1862b8feb88c

## Purpose

F-1862b8feb88c selects a result-producing path using two dynamically dispatched operations on an input object.

One path conditionally rebuilds a shared sequence of linked-element pointers, then passes a freshly loaded sequence reference to F-358d46e6a52a. Rebuilding depends on a three-word key consisting of a collection-owner identity and two filter masks.

The other path invokes F-df2422ba76c2 on local temporary storage, obtains a result from F-8cb33c040d4d, and then invokes F-ccf4fcd3c34d on that storage.

“Cache,” “sequence,” and “temporary context” describe inferred roles. The established contract is the visible control flow, memory access, argument relationships, and return-value propagation. The application meanings of the selected elements and returned words remain unknown.

### Preconditions and ownership

There are no explicit pointer-validity, alignment, capacity-consistency, or linked-structure checks.

Every actually accessed location must support its access. Counted traversal requires a valid current element for each entered iteration, including its next-pointer field. Null does not act as a traversal terminator.

Ordinary sequence behavior requires coherent storage with four-byte entries and an end position between beginning and limit. Malformed descriptors are not a supported interface established by this evidence.

The function stores element pointers without directly allocating, retaining, destroying, or releasing elements. This does not establish borrowed ownership: dependency ownership effects remain unknown.

## Behavior

### Dispatch and the unconditional cache-reference capture

The first dependency invoked is the operation at dispatch-table offset 12.

If it returns zero, the function returns zero. The body does not then invoke the second dispatch operation, read the shared cache reference, or enter either result-producing path.

Otherwise, the function reloads the input object’s dispatch-table pointer and invokes the operation at offset 28. The first operation is not assumed to preserve the object or its dispatch table.

**Immediately after the second operation returns, the function loads and retains the shared cache reference, before selecting a path from that operation’s result.** This reference load occurs even when the temporary-context path is selected. That path does not visibly dereference the captured cache record.

A zero second result selects the collection path. A nonzero result selects the temporary-context path.

### Collection path: key comparison

The key comparison does not simply use the previously captured cache reference. Its cache-field accesses read the shared reference again.

The comparison proceeds in short-circuit stages:

1. Read the owner-key word through the shared cache reference, then compare it with the input object’s owner identity.
2. Only if those identities match, capture the input object’s filtering-state pointer, read the first-mask key through the shared cache reference, and read the first mask through that filtering-state pointer.
3. Only if the first-mask comparison also matches, compare the second mask from the same captured filtering-state pointer with the second-mask key reached through another shared-cache-reference access.

A full match skips rebuilding. Any mismatch triggers rebuilding.

Thus an owner mismatch avoids filter-mask reads during comparison, but not the mask reads required by rebuilding. The two comparison masks use the same captured filtering-state pointer; they are not necessarily contemporaneous snapshots of its contents.

Neither the incoming fourth argument nor an apparent incoming scratch value supplies an independent key criterion. When the owner matches, the relevant comparison values have been loaded from memory. When it does not match, short-circuit evaluation already forces rebuilding.

### Rebuild: reference identities and publication order

On mismatch, the visible order is:

1. Store the input object’s current owner identity at offset 4 of the record reached by accessing the shared cache reference again.
2. Capture the then-current shared sequence reference.
3. Read and retain the input object’s filtering-state pointer.
4. Read its first mask and store it at offset 8 of the **cache record captured immediately after the second dispatch**.
5. Read its second mask and store it at offset 12 of that same earlier captured cache record.
6. Clear the logical contents of the captured sequence descriptor.
7. Read the initial linked-element pointer and begin counted traversal.

The owner-key store and mask-key stores therefore need not target one record if shared-reference loads yield different addresses. The owner-key store uses the reference accessed at that store; both mask-key stores use the earlier captured reference.

Likewise, the sequence descriptor used for rebuilding is captured after the owner-key store but before the filtering-state pointer and snapshot masks are read.

These are concrete access distinctions, not a concurrency guarantee. There is no visible synchronization, transaction, or rollback. The key writes precede completion of the rebuilt sequence.

### Clearing the captured sequence descriptor

The function reads the captured descriptor’s end and then its beginning.

If they are equal, no clearing store is performed.

If they differ, the represented operation copies no sequence entries and does not erase entry bytes. It advances a local cursor from the captured beginning toward the descriptor’s end, rereading that end during the empty traversal. It then updates the descriptor’s end by subtracting:

\[
(\text{original end}-\text{original beginning})\mathbin{\&}\texttt{0xFFFFFFFC}
\]

from a newly read end value.

The address calculation is represented with 32-bit words; clearing the low two bits is not a bounds or alignment check. Under stable, coherent, four-byte-aligned storage, the result is an end equal to beginning. Storage is retained, and the former pointer entries are not visibly destroyed.

Malformed or changing ranges do not gain defined handling from this operation. In particular, the cursor traversal is not validation.

### Counted linked traversal and filtering

After clearing, the function reads the first-element pointer through the input object’s owner field.

An unsigned 32-bit index starts at zero. Each continuation check reloads the owner through the input object and reads that owner’s unsigned 32-bit count. The count and owner are not captured once for the whole traversal.

For each entered iteration, inclusion requires both:

\[
A=0\quad\text{or}\quad(T\mathbin{\&}A)\ne0
\]

\[
B=0\quad\text{or}\quad(T\mathbin{\&}(\mathop{\sim}_{32}B))\ne0
\]

Here \(A\) and \(B\) are the first and second filter masks. Each \(T\) denotes the element-flags value read for the corresponding test; there is no single shared flags snapshot.

Read order and short-circuiting matter:

- Read the filtering-state pointer through the input object and then the first mask.
- Read element flags for the first condition only if that mask is nonzero.
- Reach the second condition only if the first passes.
- For the second condition, reload the filtering-state pointer through the input object and read the second mask.
- Read element flags for that condition only if the second mask is nonzero.

The two conditions may therefore read masks from different filtering-state objects if the object field changes between those accesses. Neither condition uses the saved cache-key masks.

The second condition requires at least one flag outside a nonzero second mask. It does **not** require all flags inside that mask to be absent. Complementation is restricted to 32 bits.

### Appending: captured descriptor versus fresh shared references

For an accepted element, end and storage limit are read from the sequence descriptor captured during rebuild. This same captured descriptor remains the source for subsequent end/limit checks and direct appends.

If end differs from limit:

- Store end advanced by four bytes into the captured descriptor.
- If the old end address is nonnull, store the current element pointer there.

The new logical end is published before the entry write. A null old end suppresses only the entry write; it does not suppress the end update. The comparison is equality, not a check that end is below limit.

If end equals limit, invoke F-17a5ad49165b with:

- The **then-current shared sequence reference**, freshly accessed for this call.
- The end pointer obtained from the captured descriptor.
- The address of the function’s mutable current-element slot.

Consequently, a helper invocation can receive a different descriptor from the one supplying its end argument. If a dependency changes the shared sequence reference, later direct appends still use the captured descriptor, while later helper invocations use the newly current shared reference.

The helper may also change the captured descriptor’s fields, the current-element slot, or other state. No preservation contract is supplied.

After acceptance or rejection, the function reads the next pointer at offset 20 of the current element and replaces its current-element slot. After a helper call, this read uses the slot’s post-call value.

This link read occurs even after the final counted element. Under stable state and successful ordinary appends, accepted pointers retain traversal order; duplicates are not removed. Traversal is count-controlled, with no cycle or null-sentinel detection.

### Collection-path result

After either a key match or a rebuild, the function freshly loads the shared sequence reference and passes it to F-358d46e6a52a.

That argument is not necessarily the descriptor used during rebuilding. The dependency’s 32-bit result becomes this function’s result.

### Temporary-context path

After the already-established cache-reference capture, a nonzero second dispatch result produces this ordinary call order:

1. F-df2422ba76c2 receives the address of a 68-byte local area and two zero arguments.
2. F-8cb33c040d4d receives the shared alternate-result reference.
3. F-ccf4fcd3c34d receives the same local-area address.

The result from F-8cb33c040d4d is retained across the final call and returned. Neither surrounding dependency’s result controls this sequence.

The local-area pointer is not explicitly passed to F-8cb33c040d4d. Any indirect relationship is undocumented. The visible allocation size does not establish the initializer’s complete storage requirements.

## Side effects

Directly visible effects comprise dispatch calls, conditional key writes, logical sequence clearing, pointer appends, capacity-helper calls, result-producing calls, and the two calls surrounding the alternate operation.

The body does not directly modify owner fields, filter masks, element flags, or links. Dependencies may do so.

The key excludes count, links, element flags, and collection generation. Equal owner identity and masks therefore permit sequence reuse despite changes to collection contents.

Intermediate states are exposed in program order: key publication precedes rebuilding, and direct end advancement precedes entry storage. There is no visible locking or reentrancy protection.

No explicit error translation, exception handler, recovery, or rollback is established. Initial zero rejection is a branch result, not a general failure code. Finalization on the temporary path is established only after the result-producing dependency returns normally.

## Acceptance examples

These are conditional static deductions, not executed tests. Unless an example states otherwise, assume valid, stable relevant memory and ordinarily returning dependencies.

1. **Initial rejection.** If the first dispatch returns zero, return zero without second dispatch or shared-cache-reference capture.

2. **Alternate selection.** If both dispatch results are nonzero, load the shared cache reference before invoking F-df2422ba76c2, F-8cb33c040d4d, and F-ccf4fcd3c34d in that order. Return the middle call’s word.

3. **Complete key match.** If the second dispatch returns zero and all key comparisons match, do not clear or traverse. Pass a freshly loaded sequence reference to F-358d46e6a52a, even if collection contents changed without changing the key.

4. **Both masks zero.** During a rebuild, every counted element qualifies without filtering reads of its flags. Link reads and append behavior still apply.

5. **First-mask rejection.** First mask `0x00000002` and flags `0x00000004` reject the element without reading the second mask for that iteration.

6. **Mixed-bit acceptance.** With first mask zero, second mask `0x00000002`, and flags `0x00000006`, the element qualifies. Flags `0x00000002` alone fail.

7. **All-bits second mask.** Second mask `0xFFFFFFFF` rejects every element reaching its nonzero-mask test because its 32-bit complement is zero.

8. **Zero count.** Rebuilding publishes the key, clears the sequence, and reads the first-element field, but processes no element. F-358d46e6a52a is still called.

9. **Helper changes the shared sequence reference.** Suppose rebuilding captured descriptor A, and a helper redirects the shared reference to B. Later end/limit checks and direct appends still use A. Later helper calls receive B, but their end argument still comes from A. The final result-producing call receives B if it remains current.

10. **Different cache-reference observations.** As a conditional access trace, suppose the early cache capture yields record A but the reference used by the owner-key store yields B. The owner key is written to B; both mask snapshots are written to A. This specifies access targeting, not supported concurrent execution.

11. **Helper changes the current element.** If the helper replaces the supplied current-element slot, the subsequent next-link read uses that replacement. An unchanged traversal chain cannot be assumed.
