# F-293d7334961b

## Purpose

F-293d7334961b maps an unsigned integer to an unsigned result composed of an integer square-root portion and an eight-bit refinement portion.

Under the 32-bit unsigned arithmetic model described below, the result’s upper portion is exactly the floor of the input’s square root. The low eight bits are selected by an ordered residual-refinement procedure. Those bits must not be replaced with a conventional rounded or truncated fractional square root: the supplied behavior differs from both.

In particular:

- Input zero produces `0x00000080`, not zero.
- Input two produces `0x00000180`, not the truncated value of $256\sqrt{2}$.
- Every positive perfect square produces its integer square root multiplied by 256.

The likely intent is a square-root approximation with eight fractional bits. That interpretation is inferred; the numerical selection rules below define the behavior.

## Behavior

### Integer square-root portion

The first phase establishes:

$$
q=\lfloor\sqrt n\rfloor
$$

and the corresponding nonnegative remainder:

$$
r=n-q^2.
$$

The remainder satisfies:

$$
0\le r\le 2q.
$$

The integer-root decisions proceed from the highest candidate result bit to the lowest. Equality accepts a candidate: an input exactly equal to a candidate square includes that candidate bit and leaves the corresponding remainder at zero.

The highest root bit is selected precisely when:

$$
n> \texttt{0x3fffffff},
$$

equivalently when $n\ge 2^{30}$. That selection accounts for $2^{30}$ of the input. Subsequent decisions refine the root through its remaining 15 bits.

These are exact integer-root decisions. The approximation arises only in the later refinement phase.

### Eight-bit refinement portion

The refinement begins from two mathematical quantities:

$$
A_0=256q,\qquad R_0=256r.
$$

Here, $A$ is the evolving output value and $R$ is the scaled remainder.

There are eight decisions, ordered from output bit 7 down to output bit 0. For decision index $k$, from 0 through 7:

- The candidate output bit has value $2^{7-k}$.
- The comparison threshold is the current output value shifted right by $k$ bits:

$$
T_k=\left\lfloor\frac{A_k}{2^k}\right\rfloor.
$$

- The candidate bit is included exactly when $T_k\le R_k$.
- An accepted decision contributes its candidate bit to the output.
- For every accepted decision except the last, the threshold is deducted from the remainder before the next decision.

Equivalently, the output transition is:

$$
A_{k+1}=
\begin{cases}
A_k+2^{7-k},&T_k\le R_k,\\
A_k,&T_k>R_k.
\end{cases}
$$

For $k<7$, the remainder transition is:

$$
R_{k+1}=
\begin{cases}
R_k-T_k,&T_k\le R_k,\\
R_k,&T_k>R_k.
\end{cases}
$$

The returned value is $A_8$.

These equations define the refinement behavior rather than requiring a particular implementation. Each candidate bit is initially clear and is considered once, so adding its value is equivalent to setting that bit.

### Ordering requirements

The thresholds are not all computed from the initial value $256q$. Each decision uses the output value after all preceding, more-significant refinement decisions.

Likewise, each comparison uses the remainder after all preceding accepted deductions.

This ordering is material. Computing every threshold in advance, or evaluating the decisions independently, does not preserve the contract.

At the decision for output bit 1, the supplied body checks the same previously determined threshold twice: once to select the bit and once to decide the remainder deduction. Selecting that bit does not change the saved threshold or the remainder, so both comparisons have the same truth value. The contract requires the resulting selection and deduction, not an externally observable duplicate read.

At the final decision, output bit 0 may be selected, but the threshold is not subsequently deducted. No remainder is returned, so that omitted final deduction has no caller-visible numerical consequence.

### Zero and equality

All comparisons accept equality, including equality at a zero threshold.

For $n=0$, both the integer root and remainder are zero. The first refinement threshold is therefore zero, and the first refinement decision succeeds. This sets output bit 7. Every later threshold is positive while the remainder remains zero, producing:

$$
F(0)=128.
$$

This is established behavior, not an error case to normalize away.

For a positive perfect square, the initial refinement remainder is zero and every threshold is positive. No refinement bit is selected:

$$
F(q^2)=256q\qquad\text{for }1\le q\le65535.
$$
