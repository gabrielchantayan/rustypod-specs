## Behavior

The function first invokes F-87bda57f63f9 with three arguments, in this order:

2. The original initial extent.
3. The original destination base.

No explicit four-byte payload store precedes this call.

If this invocation returns zero, F-1e4d3448368d returns zero immediately. It does not invoke the dependency a second time and does not perform its final payload store.

This does not imply that the invocation left memory or global state unchanged. Its side effects are unspecified by the supplied evidence.

### Second dependency call

If the first result is nonzero, the function invokes F-87bda57f63f9 again. Its arguments are:

1. The original input base plus the first result.
2. The difference between the original initial extent and the first result, bitwise ANDed with hexadecimal `FFFF`.
3. The original destination base plus 32.

The mask applies to the subtraction result, not to either operand individually. The second argument consequently retains only the low 16 bits of that difference. Under the ordinary 32-bit interpretation, its resulting value lies between 0 and 65,535 inclusive.

The first dependency call receives the original extent without this mask. Consequently, an extent greater than 65,535 is not uniformly truncated across the two calls.

The first result is not visibly checked against the initial extent. A result larger than the extent does not itself prevent the second call. Likewise, a negative first result is not rejected: where arithmetic is defined, it decreases the second call’s input base and increases the pre-mask extent difference.

A masked extent of zero does not suppress the second call.

The offset of 32 is an address-like integer increment. No element-size scaling is visible. Interpreting it as a byte displacement depends on the target address model; it is not established as an array-element count.

### Final store and return

If the second dependency result is zero, the function returns zero without its final payload store.

If the second result is nonzero, the function writes the third argument as one four-byte value at the location designated by the original destination base plus 64. It then returns the second result.

The final store is relative to the original destination base, not to an address returned by either dependency call. It occurs after the second dependency call has returned.

The function does not return the first result, add the two results, or adjust the second result to account for the first call.

The listing establishes a four-byte store, but not its byte order, atomicity, or physical memory-transaction count.
