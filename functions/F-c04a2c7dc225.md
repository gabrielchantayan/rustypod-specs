# F-c04a2c7dc225

## Purpose

F-c04a2c7dc225 computes a terminator-inclusive size from a zero-terminated sequence of unsigned 16-bit units. Each nonzero unit contributes one, two, or three to the size, according to its numeric range. The function adds one to the accumulated contribution and returns the result.

A null input produces a result of one without reading input memory.

The weighting resembles the byte counts used when encoding individual values into a UTF-8-like representation. That interpretation is **inferred intent**, not an established encoding contract. The function does not produce encoded bytes, validate Unicode, or combine surrogate pairs. Its established behavior is a numeric calculation over individual 16-bit units.

## Behavior

### Null input

When the input pointer is null:

- No input unit is read.
- No scan occurs.
- The function returns one.

This is an explicit accepted case, not a reported failure.

### Non-null input

The function examines consecutive 16-bit units in increasing element order, beginning with the supplied address.

Each inspected unit is read and compared with zero. If it is zero, scanning stops. The terminating unit is read, but units after it are not read by this function.

For each inspected nonzero unit, the function increases its running total according to the numeric ranges in the interface table. Each unit is classified independently. A unit’s contribution does not depend on preceding or following units.

The scan has no explicit maximum length. A missing terminator does not cause a defined “unterminated input” result. Instead, scanning continues for as long as execution can proceed. If it reaches storage that cannot validly be read, normal behavior is not established by the supplied evidence.

After a terminating zero is observed, the function returns the running total plus one.

### Threshold behavior

The boundaries are exact:

- 127 contributes one; 128 contributes two.
- 2,047 contributes two; 2,048 contributes three.
- 65,535 contributes three, like every other value in the highest range.
- Zero stops scanning rather than contributing one.

Consequently, changing an already visited unit within the same range leaves its contribution unchanged. Crossing either nonzero threshold increases that unit’s contribution by one, provided the overall arithmetic remains representable.

An embedded zero ends the effective sequence. Later readable units have no effect on the result, even if an external allocation or container regards them as part of the same buffer.
