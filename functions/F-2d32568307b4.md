# F-2d32568307b4

## Purpose

F-2d32568307b4 delegates execution to a callable target selected through the first field of an input object or record. It reads that field as an address-bearing value, locates a dispatch entry at byte offset **292 (0x124)** from that value, loads the target stored there, and invokes it.

The established behavior is indirect dispatch, not a particular operation performed by the selected target. The supplied representation does not identify the target, its purpose, or its effects.

A virtual-method-style dispatch is a plausible interpretation of the layout. That interpretation is **inferred intent**, not an established requirement: the evidence does not prove an object model, inheritance relationship, table type, or method identity.

## Behavior

### Dispatch resolution

The observable dispatch sequence is:

1. Read the initial integer field through the input pointer.
2. Use the resulting value to locate the dispatch entry 292 bytes beyond the represented base.
3. Read the callable target from that entry.
4. Transfer control to that target.
5. If the target returns normally, return from F-2d32568307b4.

The first read supplies the information needed for the second read. The second read must resolve the target before the call can occur.

The input is therefore not itself treated as the callable target. Likewise, the initial field is not called directly: it supplies the base used to locate the target-bearing entry.

There is one explicit read of the initial field and one explicit read of the selected target entry. No loop, retry, alternative entry, or secondary dispatch is visible.

### Call interface

The indirect invocation contains no explicit argument expressions in the supplied representation.

This establishes only the absence of explicit arguments in that representation. It does **not** establish that the target receives no machine-level inputs. In particular, the available evidence does not resolve:

A compatible implementation must preserve the actual invocation convention. Replacing this uncertainty with an assumed receiver argument, or with an assumed argument-free ABI, would add an unsupported requirement.

### Completion and abnormal outcomes

If the target does not return, the wrapper has no subsequent normal-completion behavior. If the target terminates execution, raises an exception, transfers control elsewhere, or faults, the representation shows no local handler.
