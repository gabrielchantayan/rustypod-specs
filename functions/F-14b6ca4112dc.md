# F-14b6ca4112dc

## Purpose

F-14b6ca4112dc conditionally updates a one-byte state field, invokes an associated object’s indirect operation, and, when a separate flag is nonzero, performs an additional sequence of state changes and dependency calls.

The behavior has three normal-return outcomes:

- If the existing state byte equals the complete requested value, return the state byte without performing the transition sequence.
- If the values differ and the flag is zero after the indirect operation, return 0.
- If the values differ and the flag is nonzero after the indirect operation, complete the extended sequence and return 1.

These return values are path indicators, not an established success/error convention. In particular, an unchanged state can return values other than 0 or 1.

This contract describes static evidence in the supplied source representation. It does not establish application-level meanings for the state values, fields, dependencies, or indirect operation.

## Interface

### Inputs

The function accepts two inputs:

| Input | Represented width | Contract role |
|---|---:|---|
| Object address | 32 bits in the supplied representation | Base address for field accesses and addresses passed to dependencies |
| Requested value | Unsigned 32 bits | Compared in full against the zero-extended state byte; subsequently narrowed for storage |

The first input is used as an address despite its signed-integer representation. No null check, bounds check, lifetime check, or object-type check is visible.

The requested value is not restricted to the range 0–255. That distinction matters: the comparison and dispatch use the full 32-bit value, whereas the state write retains only its low eight bits.

### Result

The result is an unsigned 32-bit value:

- On the unchanged-state path, it is a newly read state byte, zero-extended to 32 bits.
- On the changed-state path with a zero flag, it is 0.
- On completion of the extended path, it is 1.

There is no explicit failure return for allocation failure, invalid dispatch data, or dependency failure.

## Behavior

### 1. Capture the dispatch constant and compare state

Before testing the state, the function reads a 32-bit value from an external data location. This contract calls that captured value **K**. Its actual value and semantic role are unknown.

The state byte at +0x1A is read and zero-extended for comparison with the complete unsigned 32-bit requested value.

If they are equal:

1. The state byte is read again.
2. That second byte value is returned as an unsigned 32-bit result.

The unchanged-state path performs no visible object writes and makes no visible dependency calls. It nevertheless performs the initial read of K.

The two state reads are distinct in the supplied representation. Without an independent stability assumption, the returned byte need not equal the byte used in the comparison. No synchronization or concurrency guarantee is established.

### 2. Store the narrowed state and invoke the associated operation

If the comparison differs, the function first writes the low eight bits of the requested value to +0x1A.

It then resolves an associated object by calling F-7d964f24a044 with the address at +0x28. The returned address is used directly to obtain the indirect-call target through the table layout described above. No null or validity checks are visible.

The indirect operation receives three arguments:

1. The associated object returned by F-7d964f24a044.
2. A 32-bit value selected below.
3. Another 32-bit value selected below.

| Complete requested value | Second argument | Third argument |
|---|---:|---:|
| 5 | K | 50 |
| 6 | 50 | K |
| Every other 32-bit value | 0 | 0 |

Selection uses the complete requested value, not its stored low byte. A request of 261 therefore stores 5 but selects the pair `(0, 0)`.

K is the value captured before the initial state comparison. A subsequent change to its external source by F-7d964f24a044 does not replace that captured argument.

The indirect operation’s return value is not used. Its effects on the object, other memory, or external state are unknown.

### 3. Test the flag after the indirect operation

After the indirect operation returns, the function reads the byte at +0x19.

- If zero, the function returns 0 immediately.
- If nonzero, the function enters the extended sequence.

This is a post-call read. The decision is not based on the flag’s entry value; either preceding dependency may have changed it.

### 4. Perform the extended sequence

The extended sequence has the following order:

1. Call F-4a19e3742733 with the address at +0x74.
2. Write the byte value 2 at +0x64.
3. Call F-fd58bea73663 with the address at +0x74.
4. Call F-5bcae2eff9a7 with the address at +0x70.
5. Read the 32-bit field at +0x80 and compare it with zero.

If that field is zero:

6. Call F-8157a180d901 with the integer argument 44.
7. Store its 32-bit result at +0x80.
8. Call F-861a66c91b48 with the enclosing object address, that same returned result, 0, and 0.

The value passed as the second argument in step 8 is the allocation call’s result, not a fresh read of +0x80. There is no visible check that it is nonzero before storage or the call.

Whether or not allocation occurred, execution then continues:

9. Call F-0f74a435a13f with the enclosing object address.
10. Reread +0x80 and pass its current 32-bit value to F-6904f7699031, together with 200.
11. Call F-a967c7d12f06 with the enclosing object address and 0.
12. Test that call’s result for zero.

If the result is nonzero:

Finally, on both outcomes of the result test:

## Side effects

### Direct memory effects

The visible direct writes are:

- The requested value’s low byte to +0x1A on every changed-state path.
- The byte value 2 to +0x64 on every extended path.
- The result of F-8157a180d901 to +0x80 when the field is zero at its extended-path test.

There is no visible rollback. The state-byte write precedes the associated-object resolution, indirect dispatch, and all extended work.

These writes do not establish final field values. Dependencies invoked afterward receive addresses or objects that may permit further mutation. In particular, the function does not restore the state byte if a dependency changes it.

### Ownership and allocation

F-8157a180d901 is called with 44, and its result is retained in the object and supplied to F-861a66c91b48. This is consistent with obtaining and initializing a resource, but allocation units, initialization semantics, and ownership transfer are not established.

No explicit release is visible. It is not safe to conclude that the stored resource remains alive, that a called dependency releases it, or that the enclosing object owns it. F-ec4cfa552cce’s effect is also unknown.

### Errors and preconditions

Normal completion requires the accessed object fields, dispatch object, dispatch table, callable entry, and dependency arguments to be valid for the operations performed.

The function contains no visible handling for:

- Invalid object or dispatch addresses.
- A zero result from F-7d964f24a044.
- A zero result from F-8157a180d901.
- An invalid indirect-call target.
- Dependency failures, nonlocal exits, or nonreturning calls.

The stated normal returns apply only when preceding operations complete normally. Dependency return values are ignored except for the resource result, the associated-object result, and the zero/nonzero result from F-a967c7d12f06.

## Acceptance examples

These are conditional contract examples, not executed tests. Unless stated otherwise, dependencies return normally and do not introduce additional mutations.

1. **Unchanged ordinary state.** With state byte 7 and requested value 7, the function reads K, compares the byte, rereads it, and returns 7. No dependency is called and no object field is written.

2. **Changed state with a zero flag.** With state byte 3, requested value 5, and a flag that is zero after indirect dispatch, the state is first written as 5. The associated operation receives K and 50. The function then returns 0 without entering the extended sequence.

3. **Reversed special arguments.** With a differing initial state and request 6, the associated operation receives 50 and K. The flag still controls whether extended processing occurs.

4. **Full-width request versus byte storage.** With state byte 5 and request 261, the comparison differs. The function writes 5 again, invokes the associated operation with 0 and 0, and then tests the flag. Repeating this request does not become an unchanged-state operation merely because the stored byte is 5.

5. **Flag changed by a dependency.** If the flag starts at zero but the indirect operation changes it to nonzero, extended processing occurs. If it starts nonzero but becomes zero before the post-call read, the function returns 0 instead.

6. **Existing resource.** If +0x80 is nonzero when tested during extended processing, F-8157a180d901 and F-861a66c91b48 are skipped. The later calls and final return of 1 still occur.

7. **Zero resource result.** If +0x80 is zero and F-8157a180d901 returns zero, zero is stored and passed to F-861a66c91b48. No local failure branch is taken. Continued execution is conditional on the dependencies accepting those arguments and returning normally.

8. **Resource replacement during processing.** If F-0f74a435a13f replaces +0x80, F-6904f7699031 receives the replacement. If the unmapped external dependency later replaces it again, F-ec4cfa552cce receives that newer value.

9. **Zero conditional result.** If F-a967c7d12f06 returns zero, the unmapped external dependency and F-ec4cfa552cce are skipped. F-8e0f0bc7dc60 is still called, followed by return 1.
