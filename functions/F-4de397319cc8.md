## Behavior

### Lookup sequence

The supplied representation establishes the following logical order:

1. Locate the pointer-bearing slot 2,184 bytes beyond the input base.
2. Read that slot to obtain the first link.
3. Read the integer-valued address at the location designated by the first link.
4. Locate the target-pointer slot 416 bytes beyond that address.
5. Read the selected target pointer and transfer control to it.

The first link is not itself used as the dispatch-table base. The additional read at the location it designates is material to the contract.

The target is selected using the table-base value obtained during this lookup. There is no visible loop, search, secondary selector, fallback entry, or conditional retry. The representation contains one indirect transfer site and no visible repetition.

This is a logical dependency order, not a specification of processor transactions or atomicity. The supplied material does not establish whether individual reads are atomic, whether the locations are volatile, or what synchronization applies to concurrent changes.

### Address arithmetic and widths

Both displacements are positive byte offsets:

- 0x888 equals 2,184.
- 0x1a0 equals 416.

The first displacement is added to the input’s represented integer value. The second is added to the integer-valued table base read from memory. The function does not visibly scale either displacement by a pointer size.

No bounds check, overflow check, or address normalization appears. The representation alone does not establish whether an overflowing addition wraps, faults, or falls outside the execution model’s defined behavior. Consequently, successful-use cases must keep both address calculations valid rather than rely on a particular overflow result.
