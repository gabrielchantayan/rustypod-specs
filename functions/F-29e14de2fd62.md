# F-29e14de2fd62

## Purpose

F-29e14de2fd62 performs a guarded operation on an object using a signed target selector, an 8-bit mode, and two unsigned position-like values. It returns a 32-bit zero when admission fails and a 32-bit one when admitted execution reaches normal completion.

The established behavior includes admission queries, a retained change-path decision, optional resolution of selector −1, temporary-region preparation, independent normalization of two positions, target application, path-specific updates, notifications, and finalization.

“Target,” “position,” “mode,” and “notification token” are descriptive labels. Interpreting the operation as selection or navigation is **inferred intent**, not an established application-level contract.

## Interface

| Target selector | Signed 32-bit integer | Used in admission, change-path selection, and target application |
| Mode | 8-bit value | Stored directly only on the change path |

The positions have no established unit or indexing convention. They need not be ordered.

The 32-bit result has two normal outcomes:

- **0:** an admission condition rejected the request.
- **1:** all reached dependencies returned and execution reached the normal completion point.

A result of one is not a verified success report from the dependencies. After admission, no dependency result is interpreted as an operation-success status.

## Behavior

### Admission

The embedded region at offset 0x060 is used for short-circuit admission:

1. F-b7abcf60c990 is called. A zero result returns zero immediately.
2. F-d5511c118375 is called. A zero result returns zero immediately.
3. F-d5511c118375 is called again. Admission succeeds only if this second result, interpreted as signed 32-bit, is strictly greater than the original signed selector.

The two calls to F-d5511c118375 are distinct. The first result establishes only nonzeroness; the second supplies the signed comparison. Stability between them is not required or established.

Rejection prevents all subsequent work in this function. It does not undo effects of admission dependencies already called.

Selector −1 is not resolved before admission. Other negative selectors are not explicitly rejected. A negative, nonzero first result from F-d5511c118375 passes its nonzero check; the subsequent result independently determines the comparison outcome.

### Preliminary calls and retained path selection

After admission, the function calls F-93eb550dc612 and then F-7b8e584345d2, each without explicit arguments.

It then selects one of two paths:

- The primary dispatch entry at byte offset 0x158 is called with the object.
- If its signed 32-bit result differs from the original selector, the **change path** is selected. The entry at 0x1A4 is not called for this decision.
- If the result equals the original selector, the primary entry at 0x1A4 is called with the object. A nonzero result selects the change path; zero selects the **unchanged path**.

This decision is retained. Later calls, state changes, and selector resolution do not cause it to be recomputed.

### Resolution of selector −1

If the original selector is −1, the primary dispatch entry at 0x158 is called again. Its signed 32-bit result becomes the selector supplied to the later target-application dependency.

This is a separate query from the path-selection query. Its result may differ. No consistency check or renewed admission check follows.

The retained path decision still reflects the comparison against the original −1. For any other selector, the original value remains the target-application argument.

### Temporary-region setup and preparation

An unresolved dependency first receives the embedded region at offset 0xA4C.

F-ba5a4c1e0746 then receives the 24-byte temporary region and two zero arguments. Next, the primary dispatch entry at 0x15C receives the object and the temporary region.

F-6e482452607b queries the temporary region:

- If the query returns zero, the field at offset 0x944 is not read for this decision.
- If the query returns nonzero, the 32-bit field at 0x944 is read and converted to an 8-bit value. Only whether the resulting low eight bits are zero affects the branch.

The ordered preparation calls are:

| Condition | Calls, in order |
|---|---|
| Query returns zero, or the extracted byte is zero | F-6ac70711bbb5; F-7027ea1c0db7 |
| Query returns nonzero and the extracted byte is nonzero | F-e8b332300a3f with the object; F-6ac70711bbb5; F-fb7062fdb8a9 |

Except for F-e8b332300a3f, these preparation calls have no explicit arguments in the supplied representation.

Upper bits of the field do not make a zero extracted byte nonzero. The branch depends on a 32-bit field read followed by conversion, not an established standalone byte read.

### Independent position normalization

F-ef9223740536 is called with the temporary region to obtain an unsigned 32-bit bound for the first position:

- If the bound is strictly less than the first position, that position becomes zero.
- Otherwise, the position is retained.

F-ef9223740536 is then called again with the temporary region. Its independently obtained unsigned 32-bit result is used in the same way for the second position.

Consequences:

- Equality with a bound is accepted.
- An excessive position resets to zero rather than being clamped to the bound.
- The two bounds need not be equal.
- The second query occurs even if the first position was reset.
- No ordering relationship between the positions is enforced.
- There is no subtraction or signed comparison in these checks.

### Target application and path-specific behavior

F-6542ebfeed7d receives the object and the selector after any −1 resolution. This call occurs on both paths, including the unchanged path.

On the **change path**, the function then:

1. Writes the supplied mode byte at offset 0x93C.
2. Writes byte value 1 at offset 0x93D.
3. Reads the 32-bit field at offset 0x054.
4. Calls F-0edcc41cb6b7 with that field value, the normalized first position, and the normalized second position.

The two byte writes occur after F-6542ebfeed7d returns. The field at 0x054 is read after those writes; no earlier cached value is established.

On the **unchanged path**:

1. If the normalized first position is nonzero, the primary dispatch entry at 0x100 receives the object and that position.
2. The primary dispatch entry at 0x194 receives the object.
3. If that result is nonzero, the primary dispatch entry at 0x0F0 receives the object.

This path performs neither direct mode-byte write nor direct flag-byte write. The second position was still queried and normalized, but is not subsequently supplied to another dependency on this path.

Both paths continue with the following ordered operations:

1. F-ec4cfa552cce receives the embedded region at offset 0x9B0.
2. The global 32-bit location is evaluated. This **first value is retained** for the later secondary notifications.
3. The same global location is evaluated again to supply the token argument to F-069a1d444a2d, which also receives the object.
4. F-4e292a3dd745 receives the temporary region.
5. A second unresolved dependency receives the embedded region at offset 0xA4C.
6. On the change path only, the secondary dispatch entry at offset 0x14 receives the secondary receiver at object offset 0x014 and the retained first value minus three.
7. On both paths, the secondary dispatch entry at offset 0x14 receives the secondary receiver, the retained first value, and an additional zero argument.

There is **no intervening dependency call between the two global evaluations**. Nevertheless, the supplied representation contains two evaluations, not one retained snapshot reused for both purposes. Equality requires an execution-model assumption that the location remains stable across those evaluations; the function itself does not establish that assumption.

The second value supplies F-069a1d444a2d only. Both later secondary notifications use the first retained value, regardless of changes to the global by F-069a1d444a2d or subsequent dependencies.

The first value is retained in a signed 32-bit quantity. Subtracting three has no explicit range check. Results within the signed 32-bit range are straightforward; behavior below that range depends on the underlying execution model. Arbitrary-precision subtraction and unconditional wraparound are not established.

The secondary dispatch-table field is consulted separately for the additional and common notifications. A single callback pointer is not explicitly retained across them.

## Side effects

The explicit writes to object data are the two change-path byte writes:

- The supplied mode at offset 0x93C.
- Value 1 at offset 0x93D.

Temporary storage is also supplied to dependencies for initialization and later use. Dependencies and dispatched methods may modify object state, globals, temporary contents, or externally visible resources. Their effects cannot be bounded from this function alone.

Dispatch lookups occur at their respective invocation sites. Intervening dependencies must not be assumed to preserve dispatch tables or other object fields.

The temporary region has local storage duration. F-ba5a4c1e0746 precedes its use, and F-4e292a3dd745 receives it during normal completion. That pairing does not establish resource ownership, allocation, release, or whether a dependency retains its address.

Likewise, the two calls involving offset 0xA4C are ordered before temporary setup and after the cleanup-stage call, respectively. Their placement does not establish locking, unlocking, transaction, or ownership semantics.

There is no explicit rollback or exceptional-exit cleanup in the supplied representation. If a dependency does not return normally, subsequent calls, cleanup, and either normal return value are not guaranteed.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. Completion examples assume all reached dependencies return normally and required storage remains valid.

1. **Immediate admission rejection.**  
   If F-b7abcf60c990 returns zero, the result is zero. Neither admission call to F-d5511c118375 nor any subsequent operation occurs.

2. **Admission results are not interchangeable.**  
   If the first F-d5511c118375 result is 8, its second result is 3, and the selector is 3, admission fails. The second result is not strictly greater than the selector.

3. **Negative selectors are not categorically rejected.**  
   If the selector is −2 and the final admission result is −1, the signed comparison permits admission, provided both preceding nonzero checks passed. No −1 resolution is performed for selector −2.

4. **Resolution follows path selection.**  
   With original selector −1, a first target query of 5 selects the change path. If the resolution query then returns 7, F-6542ebfeed7d receives 7. Admission and path selection are not repeated.

5. **Equal target can still select change.**  
   If the first target query equals the selector and the entry at 0x1A4 returns nonzero, the change path performs both byte writes and the additional secondary notification.

6. **Only the extracted byte controls preparation.**  
   With a nonzero temporary query, field value 0x00000100 selects the zero-byte branch; 0x00000101 selects the nonzero-byte branch. With a zero temporary query, the field is not read for this decision.

7. **Bounds are inclusive and independent.**  
   A first position of 9 remains 9 when its query returns 9. A second position of 10 becomes zero when its separate query returns 9. The first result does not supply the second bound.

8. **Unchanged-path zero position skips only its conditional call.**  
   A normalized first position of zero skips dispatch at 0x100. Dispatch at 0x194 still occurs, and its nonzero result still causes dispatch at 0x0F0.

9. **Stable global values may coincide without collapsing the evaluations.**  
   If both global evaluations yield 20, F-069a1d444a2d receives 20. Later secondary arguments use 17 on the change-only call and 20 on the common call. These equal inputs do not establish that the representation contains only one evaluation.

10. **Distinct global evaluations have distinct consumers.**  
    Under an execution model permitting the first evaluation to yield 20 and the second to yield 30, F-069a1d444a2d receives 30. The later notification values remain 17 and 20. This example does not assert that such an intervening change is possible in every execution model.

11. **Later global changes do not replace the retained value.**  
    If the first evaluation yields 20 and F-069a1d444a2d subsequently changes the global to 40, later notifications still derive from 20. The global is not reevaluated for those notifications.

## Uncertainties

The following remain **documented_only**:

- Application-level meanings of selectors, positions, modes, tokens, and embedded regions.
- Valid selector ranges beyond the observed signed admission comparison.
- Validity of a selector obtained through −1 resolution.
- Stability and side effects of repeated queries.
- Concrete dispatch implementations and complete calling conventions, including the differing explicit argument counts of the secondary notifications.
- Allocation, retention, release, and ownership behavior of all dependencies.
- Synchronization, reentrancy, and preservation of globals or dispatch tables.
- The global location’s volatility, asynchronous mutability, and execution-model rules governing the two evaluations.
- Whether the two global evaluations correspond to distinct machine loads.
- Signed subtraction behavior when the retained notification value minus three is outside the signed 32-bit range.
- Exception, fault, and nonlocal-exit behavior.

No dependency is assumed to preserve the global between calls. Equality of the adjacent global evaluations is also not guaranteed merely by the absence of an intervening call.
