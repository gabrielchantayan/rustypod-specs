# F-de8f0a879175

## Purpose

F-de8f0a879175 traverses a pointer-linked structure and then either returns a candidate entry or invokes F-ff82880cf2ca. On normal completion, it writes a 32-bit result word and a one-byte path indicator to caller-provided output storage.

The indicator distinguishes two paths:

- **`0`:** the final comparison returned zero; the result is a subsequently reread candidate pointer.
- **`1`:** F-ff82880cf2ca was invoked; the result is the word read from that call’s destination after return.

Indicator `1` does not establish successful insertion or even that the dependency initialized its destination.

The early insertion-like destination also serves as **indicator staging storage on every completion path**. After writing the result word to the output, the function overwrites that destination’s low byte with the selected indicator, then reads the staged byte to write output offset `4`. On the early insertion-like path, this mutation affects the same storage whose address was supplied to F-ff82880cf2ca.

Traversal, storage reuse, calls, and access order are established by static evidence. Ordered-tree search, predecessor selection, and insertion are inferred intent, not additional guarantees.

- **Early destination / indicator staging word:** a 32-bit word passed by address to the early F-ff82880cf2ca call. Its low byte is subsequently used to stage the indicator on every completion path, including paths that never pass its address to a dependency.

## Behavior

### Initial reads and traversal

The remembered comparison result begins at the 32-bit value `1`.

The function reads the container’s header pointer and then the header’s offset-`4` search entry. It separately rereads the container’s header-pointer field to initialize the remembered attachment position. No dependency call intervenes between these initial reads.

For each nonnull search node:

- Both destination words are cleared to 32-bit zero, early destination first.
- F-257a89ed2c43 receives the comparison-state address, incoming value, and current node’s payload address at offset `0x10`.
- The current node becomes the remembered attachment position.
- After the call, the function reads the node’s offset-`0xC` link if the comparison returned zero, or its offset-`8` link for any nonzero result.

The selected link becomes the next search node. Positive and negative nonzero results select the same branch.

Consequently, a nonempty search explicitly initializes both destination words. An empty search initializes neither through traversal. These are initialization histories, not guarantees against dependency effects.

The child-link read occurs after the comparison call. Changes made by that dependency can therefore affect the selected next node.

### Mode selection

After traversal, the function reads the container’s mode byte at offset `0x18`.

A nonzero mode selects the ordinary insertion-like call directly. It skips candidate-slot initialization, F-cb011f129d08, candidate adjustment, extraction, and final comparison.

A zero mode initializes the candidate slot with the remembered attachment position. The last search comparison then determines whether the additional check is required:

- Final comparison zero: skip the additional check and candidate adjustment.
- Final comparison nonzero: perform both the additional check and, conditionally, adjustment.

An empty search follows the nonzero case because the remembered comparison began at `1`.

### Additional check and early insertion-like path

The function reloads the header pointer, reads the header’s offset-`8` word, and stores it in the ordinary destination. It then calls F-cb011f129d08 with the candidate-slot address and ordinary-destination address.

If that dependency returns nonzero, F-ff82880cf2ca receives, in order:

1. The early destination’s address.
2. The container address.
3. Literal zero.
4. The remembered attachment position.
5. The incoming value.

The attachment argument is not reread from the potentially modified candidate slot.

After F-ff82880cf2ca returns:

1. The function reads the early destination as a 32-bit word and writes that value to output offset `0`.
2. It overwrites the early destination’s low byte with `1`.
3. It reads the staged byte and writes it to output offset `4`.

The result-word read precedes the low-byte mutation. The early destination’s remaining three bytes are not changed by the indicator-staging write. A retained address refers to this mutated storage, not an immutable copy of the result word.

After a nonempty search, the early destination was explicitly cleared during traversal. After an empty search, it has no established initialization before the call. The dependency’s receipt of its address does not prove that it writes a result.

### Candidate adjustment

If F-cb011f129d08 returns zero, adjustment uses the candidate slot’s contents after that call.

The function first reads the candidate’s marker byte. If it is zero, the function follows the candidate’s offset-`4` link and reads offset `4` from the referenced object. If this second link equals the candidate, adjustment replaces the candidate slot with the candidate’s offset-`0xC` link and finishes.

Otherwise, the function reads the candidate’s offset-`8` link into a working pointer, then reads that field again to choose ascent or descent.

If the second read is null, ascent begins through offset-`4` links. At each step, the parent’s offset-`8` link is compared with the candidate being left. The parent is then stored in the candidate slot, including on the terminating step. Ascent continues while the comparison is equal.

If the second read is nonnull, descent uses the pointer obtained by the first read. Each iteration stores that pointer in the candidate slot, reads its offset-`0xC` link into the working pointer, and rereads that field to decide whether another iteration occurs.

With stable links, descent selects the last nonnull object along offset-`0xC` links. The repeated reads are distinct accesses; consistency between them is not established under changing memory. No dependency is called during adjustment, and there is no null-parent or cycle guard.

After any required adjustment, the function reads the candidate slot and passes that pointer value to F-2c0c622dae0f.

Its returned 32-bit value is supplied to F-257a89ed2c43 with the comparison-state address and original incoming value. The argument order is:

- Search: comparison state, incoming value, node payload address.
- Final check: comparison state, extracted value, incoming value.

## Side effects

Direct writes affect temporary storage and the two output fields. The function does not directly update container fields or node links.

The early destination’s low-byte mutation is a required side effect, not merely a description of the final output. On the early insertion-like path, its address has already been supplied to F-ff82880cf2ca. The ordering is therefore significant:

- The full destination word is consumed for the result.
- The result is written to output.
- The same destination’s low byte is replaced by the indicator.
- That byte is consumed for the indicator output.

No dependency call intervenes in this finishing sequence. Retention does not establish that the local address remains valid after this function returns.

Other escaped-storage relationships also matter:

- F-cb011f129d08 may change the candidate before adjustment or extraction.
- Its second argument identifies the ordinary destination later reused by F-ff82880cf2ca.
- Later dependencies may affect storage through previously retained addresses.
- Existing-candidate completion uses a fresh candidate-slot read after extraction and comparison.

There is no direct allocation, deallocation, ownership transfer, or rollback. Dependencies may perform such operations; their contracts are unavailable.

Dependencies on the selected path return before the result and indicator output writes. Output aliasing is not checked. Supported aliasing, concurrency, and reentrancy guarantees are **documented_only**.

## Acceptance examples

These are conditional static consequences, not executed tests. Each assumes valid accesses, normally returning dependencies, and no unspecified intervening memory changes.

1. **Branch selection and ordinary completion.**  
   A zero search comparison selects offset `0xC`; a subsequent negative result selects offset `8`. If the latter link is null, the second node is the remembered attachment. With nonzero mode, the ordinary insertion-like call follows. If its destination remains at its last cleared value, output is word zero, then indicator `1`. The indicator is staged in the early destination, not the ordinary destination.

2. **Early result preserved before staging mutation.**  
   In zero mode, a final nonzero search comparison followed by a nonzero F-cb011f129d08 result selects the early call. If F-ff82880cf2ca supplies a result word whose low byte is not `1`, that entire supplied word is written to output first. The function then replaces the early destination’s low byte with `1` and emits indicator `1`. The result output is not reread from the modified word.

3. **Empty search and early call.**  
   The copied header word initializes the ordinary destination, not the early destination. If F-cb011f129d08 returns nonzero, the early call receives a destination with no established initialization. A dependency-written word can supply the result. Otherwise no defined result word is established. Subsequent indicator staging does not retroactively initialize the earlier full-word read.

4. **Empty search and nonzero mode.**  
   No search comparison occurs. The ordinary call receives the remembered header and an uninitialized ordinary destination. If the dependency writes a specified word, that word is output, followed by staging and emission of indicator `1`.

5. **Ordinary destination reused after the additional check.**  
   Suppose F-cb011f129d08 returns zero and writes word `H` through its second argument. If the final comparison is nonzero and later dependencies leave that word unchanged, the ordinary call receives `H`; if it also leaves the word unchanged, output is `H` with indicator `1`. Staging changes the early destination, not `H`’s storage.

6. **Candidate changed after extraction.**  
   Suppose F-cb011f129d08 retains the candidate-slot address. Extraction receives candidate `A`; a later dependency changes the slot to `B`; the final comparison returns zero. Output is `B`, then the early destination’s low byte is set to `0`, and indicator `0` is emitted. No re-extraction or comparison of `B` occurs.

7. **Final zero search comparison.**  
   With zero mode, the additional check and adjustment are skipped. If the candidate stays unchanged and the final comparison returns zero, output is the last visited node with indicator `0`. No insertion-like call occurs, but indicator staging still mutates the early destination’s low byte.

8. **Marker shortcut.**  
   With stable links, a zero marker and a two-step offset-`4` link returning to the candidate select its offset-`0xC` link without offset-`8` descent.
