# F-b486d6c857f4

## Purpose

F-b486d6c857f4 conditionally performs a halfword transfer, may perform a second halfword write and a machine-state assignment, and then enters a nonterminating sequence of indirect calls and software interrupts.

No application-level purpose is established. The supplied representation does not justify classifying the function as a decoder, allocator, serializer, or ordinary buffer transformation.

Under the 32-bit arithmetic model described below, the later arithmetic gate and all preparation memory operations following it are unreachable. Their presence in the representation does not establish executable pointer loads or paired 32-bit writes.

There is no visible normal return. Continued execution of the terminal loop depends on both indirect calls and the interrupt returning control to the next represented operation.

This contract rests on static evidence and arithmetic deductions. No runtime tests have been performed.

## Behavior

### Initial selection

The third argument is multiplied by 256 with 32-bit truncation. Call the resulting numeric address the **scaled base**.

A nonzero scaled base skips all preparation memory operations and leads to the terminal loop.

A zero scaled base selects the initial halfword transfer. Equivalently, the low 24 bits of the third argument must be zero. The complete argument need not be zero: any value confined to its highest byte also selects this path.

On that path, two further facts follow:

- Bit 22 of the third argument is clear.
- Multiplication of the third argument by 512 also produces zero modulo \(2^{32}\).

### Initial halfword transfer

When the scaled base is zero, the function reads an unsigned 16-bit halfword at the incoming source address and writes that halfword at:

\[
\text{source address}+\text{second auxiliary word}\pmod{2^{32}}.
\]

The displacement is measured in bytes. It is not doubled as a halfword index.

The working source address becomes that destination minus the source adjustment, modulo \(2^{32}\). This calculation does not itself cause another memory access.

An **argument-derived address** is also formed from the entry cursor, bit 22 of the third argument, and the argument-slot address shifted right by one. Because this path requires the scaled base to be zero, it simplifies to:

\[
\text{entry cursor}+(\text{argument-slot address}\mathbin{\text{ shifted right }}1)
\pmod{2^{32}}.
\]

The initial transfer occurs before the deeper conditions can stop progression. Failure of any later condition does not undo it.

### Conditions for the link-derived write

The zero-result checks following the transfer require, in order:

1. The entry cursor is zero.
2. The argument-derived address is zero.
3. The scaled base matches the argument-derived address.
4. The scaled base matches the doubled scaled base, through two successive checks.
5. The second auxiliary word equals the first auxiliary word.
6. The source adjustment equals the updated working source address.

The checks include shifts controlled by the low byte of an intermediate result. Whenever one of these checks is reached, that intermediate result is zero. The effective shift count is therefore zero. No oversized-shift interpretation is needed for these reachable checks.

The carried Boolean state is clear on entry to this progression and remains clear through these checks.

Two addition conditions follow:

- The addition word, plus 128 times the low 24 bits of the third argument, plus the carried bit, must have a zero 32-bit result.
- The argument-slot address, plus twice the second auxiliary word, plus the preceding carry-out, must have a zero 32-bit result.

The first addition simplifies to the addition word itself. Consequently, progression requires the addition word to be zero, and its carry-out is clear.

Together, the preceding conditions yield a stronger characterization of entry to the link-derived write:

- The scaled base is zero.
- The entry cursor is zero.
- The argument-slot address is zero.
- The first and second auxiliary words are equal.
- The second auxiliary word is either zero or 0x80000000.
- The addition word is zero.
- The source adjustment equals the source address plus the second auxiliary word minus the source adjustment, modulo \(2^{32}\).

The argument-slot conclusion follows from two constraints. With a zero entry cursor, a zero argument-derived address restricts the slot address to zero or one. The later zero-result addition requires that address plus an even quantity to be zero, excluding one.

These are arithmetic conditions within the supplied representation. They do not establish that a real calling convention can place an argument slot at address zero.

### Link-derived write and machine-state assignment

If all preceding conditions succeed, the function:

- Assigns the separate machine-state location a value equal to 64 times the argument-slot address, with 32-bit truncation.
- Calculates an updated entry cursor by adding the same byte displacement.
- Uses a halfword at the previous entry cursor both as data and as the numeric destination of a halfword write.
- Writes that halfword plus 15, truncated to 16 bits.
- Advances a separate scaled-base-derived address by one halfword, or two bytes.

Under the conditions just established, the machine-state assignment writes zero and the updated entry cursor remains zero. The source of the link-derived halfword is therefore address zero.

For stable ordinary memory, if the halfword at address zero is \(h\), the write stores:

\[
(h+15)\bmod 2^{16}
\]

at byte address \(h\), interpreting \(h\) as an unsigned 16-bit address value.

The representation references that source halfword in both the destination and value expressions. It does not establish independent sampling or evaluation-order guarantees for volatile or concurrently modified memory. The single-value description above is conditional on a stable source value.

The initial transfer precedes this operation. If that transfer writes address zero, the link-derived operation can observe the value written by the transfer.

### Why the remaining preparation is unreachable

Entry to the link-derived write requires both the scaled base and the argument-derived address to be zero. The write block changes the separate scaled-base-derived address from zero to two.

The immediately following progression cannot reach the later arithmetic gate:

- If the updated entry cursor were nonzero, progression would stop at its zero check.
- If it is zero, the next exclusive-or check produces the zero argument-derived address.
- The following check then produces two exclusive-or zero, which is two, not zero.

Under the stronger conditions above, the updated cursor is necessarily zero, so the second case applies. Either way, further progression stops.

If the link-derived write was not entered, the Boolean condition needed to enter this following chain is false. There is no alternate route around the contradiction.

Therefore the later self-dependent shift, pointer load, paired stores, and final write pair are unreachable in the supplied representation under the stated 32-bit model.

### Terminal loop

All normally continuing preparation paths enter the terminal loop.

Each iteration performs these operations in order:

1. Calls the code address 0xEB6 bytes beyond the working terminal cursor, with three 32-bit argument words: zero, zero, and 0xFFFFFFA5.
2. Calls the fixed code address 0x0857A94B, with no explicit arguments shown.
3. Issues a software interrupt with immediate value 0x5B.
4. Replaces the working terminal cursor with 0x083D4CC2.

The first call uses an arithmetic code address. There is no represented function-pointer load from that address.

Because all later cursor-changing preparation blocks are unreachable, and the reachable link-derived block leaves its cursor zero, the first iteration uses the incoming entry cursor plus 0xEB6.

If both calls and the interrupt return normally, the second and subsequent iterations use first-call address 0x083D5B78.

The absence of explicit arguments on the second call does not establish an argument-free ABI. Registers, memory, or other ambient state may remain relevant. Neither call nor the interrupt is assumed to preserve globals or other externally accessible state.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes that the accesses and control transfers actually reached are valid.

No preparation data-memory access occurs. The first terminal call targets the incoming entry cursor plus 0xEB6 and receives zero, zero, and 0xFFFFFFA5.

### High-byte-only argument

With third argument 0x01000000, both represented products by 256 and 512 are zero.

### Transfer followed by immediate rejection

No link-derived write or machine-state assignment follows. The terminal loop begins using the incoming entry cursor.

### Transfer aliasing

With a zero scaled base and a second auxiliary word of zero, the initial read and write address the same halfword.

The write remains an explicit effect even if it stores the value just read.

### Abstract link-derived write

Assume:

- The third argument, entry cursor, argument-slot address, both auxiliary words, and addition word are zero.
- The source address is 0x2000.
- The source adjustment is 0x1000.
- Address zero contains the stable halfword 0x1234.

The initial transfer reads and writes address 0x2000. The adjusted working source becomes 0x1000, satisfying its comparison.

The machine-state location is assigned zero. The link-derived operation writes halfword 0x1243 at byte address 0x1234. Preparation then stops progressing because the later comparison produces two rather than zero.

This example requires an environment permitting both the zero argument-slot address and the read at address zero. It is not evidence that an ordinary caller can realize those conditions.

### Absence of downstream memory effects

Even if all conditions for the link-derived write hold, the subsequent pointer load and paired 32-bit writes do not execute. Providing memory values that would satisfy their own internal conditions cannot bypass the earlier nonzero exclusive-or result.

### Continued terminal execution

No visible successful-return status or loop exit occurs.
