# F-6dc950274029

## Purpose

F-6dc950274029 coordinates operations on three-component caller-supplied structures, using two temporary objects and a temporary three-component aggregate. Its behavior is controlled by dependency results, including exact-zero status checks, signed comparisons, and one exact-one classification check.

The established contract is its allocation, initialization, dependency-call ordering, branching, cleanup, and two-word return behavior. The underlying mathematical or domain-specific operation is not established. Describing the routine as a particular arithmetic algorithm would require information not present in the supplied evidence.

A significant exceptional path bypasses cleanup: after all three allocations succeed, if the first classifier returns anything other than exactly one, the routine returns a global-derived word and the second argument without explicitly releasing its allocations.

## Interface

### Arguments

The interface has five arguments, in this order:

1. **Primary value:** a 32-bit opaque value passed to classification and object-operation dependencies.
2. **Auxiliary pointer:** a pointer-sized, 32-bit value passed to transformation and combination dependencies. The routine itself does not dereference it.
3. **Source triple:** a pointer to at least three consecutive 32-bit component references, at byte offsets 0, 4, and 8.
4. **Working triple:** a pointer to at least three consecutive 32-bit component references, likewise at offsets 0, 4, and 8.
5. **Operation context:** a 32-bit opaque value passed to transformation and combination dependencies.

“Component reference” describes how a word is used: each is supplied as an argument to object-operation dependencies. The evidence does not establish the complete layout, size, or ownership of the referenced component objects.

The source and working triple slots are read when their corresponding calls are reached, not all snapshotted at entry. Earlier dependencies may therefore affect values read for later calls if they can mutate or alias those structures.

### Return value

The routine returns a 64-bit value formed from two 32-bit words:

- **Low word:** ordinarily zero or one, but not on every path.
- **High word:** the bit pattern of one of the pointer arguments or the temporary aggregate pointer, depending on execution history.

The high word is not necessarily an owned result pointer. On some paths it identifies temporary storage that has already been passed to the release dependency.

The low word has these established meanings:

| Path | Low word |
|---|---|
| Direct component operations all return zero | 0 |
| Main processing reaches its designated zero-result termination check | 0 |
| Other ordinary processing exits after successful allocation | 1 |
| Any allocation fails | An exceptional instruction-related marker represented in the supplied source |
| First classifier returns something other than 1 | A word loaded from global storage |

The marker’s concrete numeric value and runtime validity are not established.

## Behavior

### Temporary storage and initialization

Allocation requests occur in this fixed order:

1. A 36-byte temporary object, called **A**.
2. A second 36-byte temporary object, called **B**.
3. A 120-byte aggregate, called **T**.

All three requests are attempted even if an earlier request returns null. The requested total is 192 bytes, excluding allocator overhead.

Each successfully allocated 36-byte object receives two explicit 32-bit writes:

- Offset 0: zero.
- Offset 4: a pointer to the same allocation at offset 8.

The remaining 28 bytes are not explicitly initialized by this routine.

T contains a three-word pointer table followed by three 36-byte embedded objects:

| T-relative offset | Established contents |
|---|---|
| 0 | Pointer to T + 12 |
| 4 | Pointer to T + 48 |
| 8 | Pointer to T + 84 |
| 12, 48, 84 | Zero, at the start of each embedded object |
| 16, 52, 88 | Pointer to the corresponding embedded object + 8 |

Initialization proceeds one embedded object at a time: publish its pointer in the table, write its zero word, then write its internal pointer. Other bytes remain unspecified by this routine.

If any allocation fails, no classifier or processing dependency is called. Non-null allocations are passed to the release dependency in the ordinary cleanup order described below. The return high word is the auxiliary pointer; the low word is the exceptional marker.

### Initial classification and cleanup-bypassing return

Once all allocations succeed, the routine calls F-d72f047fba8b with the primary value. It then loads a word from global storage.

If the classifier result is not exactly 1:

- No second classifier or component processing occurs.
- None of A, B, or T is explicitly released.
- The low return word is the loaded global word.
- The high return word is the auxiliary pointer.

This global read occurs after the classifier call. Its value must not be treated as an entry-time snapshot or assumed independent of that call.

If the first classifier returns exactly 1, processing continues with F-5395d095cd07 on the primary value.

### Direct three-component path

If the second classifier returns exactly 1, the routine invokes F-eee1239b9042 on corresponding working/source components in order:

1. Component 0.
2. Component 1, only if component 0’s call returned zero.
3. Component 2, only if component 1’s call returned zero.

The working component is the first argument; the source component is the second.

All three zero results select low return word 0. Any nonzero result stops further component calls and selects low return word 1. In either case, ordinary cleanup occurs and the high word remains the auxiliary pointer.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, dependencies return normally and allocations succeed.

1. **Direct completion:** Both classifiers return 1; the three working/source operations return zero. Expect three ordered component calls, cleanup T/B/A, low word 0, and high word equal to the auxiliary pointer.

2. **Direct short circuit:** Both classifiers return 1; component 0 returns zero and component 1 returns 2. Component 2 is not processed. Expect ordinary cleanup and low word 1.

3. **Allocation failure:** A’s allocation returns null; B and T succeed. All three allocation requests still occur. No classifier runs. Expect release calls for T then B, the exceptional low-word marker, and the auxiliary pointer as high word.

4. **Classifier bypass:** The first classifier returns 0. Expect the subsequent global-word read, no second classifier, no explicit release calls, and a return containing that global word below the auxiliary pointer.

5. **Preparation comparison boundary:** After earlier preparation succeeds, comparison returns −2. It does not enter the exact−1 retry path. The next operation is F-8a9589a9b71f. By contrast, −1 requires an increment-like call before another comparison.

6. **Immediate main termination:** Preparation and the initial T dispatch return zero. The first cycle-entry F-18cbf7a56e3c call returns zero. Expect low word 0 and source-triple pointer as high word, followed by ordinary cleanup.

7. **Temporary pointer in return:** Execution reaches an inline working-triple combination, which returns nonzero. Expect low word 1 and T as high word. T is passed to release before return; this is not evidence of a live returned allocation.

8. **Exact-one distinction:** At the later B check, result 1 immediately selects working-triple dispatch. Result 2 does not; it requires another signed comparison before dispatch can be selected.
