# F-94c32ed4e255

## Purpose

F-94c32ed4e255 performs an unconditional receiver-associated operation, then conditionally invokes an indirect dependency and performs measurement, accounting, and finalization-like operations.

The conditional path depends on a 32-bit address read from the receiver after the unconditional operation. When that address is nonzero, the function prepares a mutable argument carrier, resolves and invokes a callable through that carrier, measures another mutable carrier, and passes a calculated difference to an accounting-like dependency. Two further dependency calls complete this path.

Every normal return produces the 32-bit value zero. There is no explicit validation, alternate result, or translation of dependency failures into a return value.

“Preparation,” “measurement,” “accounting,” and “finalization” describe observed uses or inferred roles. They do not establish allocation, reference counting, resource ownership, release, or transactional behavior.

## Interface

### Inputs

The interface has four 32-bit input words:

| Position | Interpretation established by use |
|---|---|
| First | Original receiver address. Used for explicit reads at byte offsets `+0x04` and `+0x2C8`, and copied into the receiver carrier. |
| Second | Opaque word copied into the receiver carrier’s second slot. |
| Third | Initial first word of the callback carrier. Its current value after preparation is used as an address on the conditional path. |
| Fourth | Opaque word copied into the callback carrier’s second slot. |

The supplied representation uses 32-bit integer and address quantities. It does not establish an interface accepting wider addresses or define how wider values would be converted.

### Mutable carrier layouts

Two local carriers are initialized before the first dependency call:

| Carrier | Word at `+0x00` | Word at `+0x04` |
|---|---|---|
| Receiver carrier | First input | Second input |
| Callback carrier | Third input | Fourth input |

The represented local slots support an eight-byte, two-word layout for each carrier. No authoritative aggregate type, tag convention, or interpretation of the second words is provided.

Dependencies receive the address of a carrier’s first word. The carrier storage is mutable: later uses observe the state left by preceding operations, not necessarily the original inputs.

The original receiver address is distinct from the first word of the receiver carrier. Mutating that carrier word does not, by itself, redirect the explicit receiver-field reads.

### Output and unused results

The normal output is a 32-bit zero.

The three possible results of F-64595c3343d2 feed subsequent calls. The result of F-bf18a6a8124b supplies an arithmetic operand. No explicit use is made of the other dependency results or the indirect callable’s result.

### Preconditions for normal completion

The reached operations require:

- Readable receiver storage at `+0x2C8` for each scheduled read.
- Readable receiver storage at `+0x04` after the unconditional operation.
- On the conditional path, a readable word at `+0x08` from the saved nonzero address when that later read occurs.
- After callback-carrier preparation, a current first carrier word designating storage readable at `+0x0C`.
- A callable address at that location, compatible with invocation using the callback-carrier address followed by the receiver-carrier address.
- Valid arguments for every reached dependency, and normal completion of those dependencies.

The function does not validate these conditions. A nonzero address alone does not establish readable storage, a valid callable, or adequate lifetime. Alignment requirements and precise fault behavior are **documented_only**.

## Behavior

### Unconditional operation

The four inputs are copied into the two carriers before dependency invocation.

F-64595c3343d2 is then called without explicit arguments. After it returns, the function reads a 32-bit word from the original receiver at `+0x2C8`. F-23aadb16b673 receives:

1. The result of F-64595c3343d2.
2. The receiver word just read.

The context-producing call precedes the receiver-field read. Its effects on shared or reachable storage are unknown; the field value therefore must not be specified as necessarily equal to its value at function entry.

F-23aadb16b673 completes before branch selection.

### Branch selection and saved address

The function reads a 32-bit address from the original receiver at `+0x04`.

If the address is zero, the function returns zero immediately. None of the conditional-path dependencies is called.

If it is nonzero, the function retains that address for a later read at `+0x08`. It does not explicitly reload the receiver’s `+0x04` field for that later read.

Consequently, replacing the receiver’s field after branch selection does not, solely by that replacement, redirect the later read. Changes to the storage at the saved address can affect the value obtained, provided the storage remains valid.

### Callback-carrier preparation and indirect invocation

F-7a117b899bf6 receives the callback-carrier address.

After that call returns, the function reads the callback carrier’s current first word and treats it as an address. It obtains a callable address from `+0x0C` relative to that address.

The indirect dependency receives two arguments, in this order:

1. Callback-carrier address.
2. Receiver-carrier address.

Callback selection therefore depends on the carrier state after preparation. It need not use the third input’s original value.

Both carriers are exposed as mutable storage. The supplied body does not establish which carrier words the indirect dependency accesses or changes, what additional storage it follows, or what shared state it modifies.

### Measurement and saved-object read

After the indirect dependency returns, F-bf18a6a8124b receives the receiver-carrier address. Its 32-bit integer result becomes the measurement operand.

This dependency sees the carrier state present after the callback. It is not required to measure the original first and second inputs.

After F-bf18a6a8124b returns, the function reads a 32-bit integer from `+0x08` relative to the saved branch-selection address.

**This read observes the value present after F-bf18a6a8124b returns.** A value written there by the callback is observed only if it remains unchanged through the intervening measurement call and until the read. The measurement dependency’s effects on reachable storage are unknown; it must not be assumed to preserve the saved object merely because its explicit argument is a carrier address.

The saved address must also remain valid through this interval. Neither callback completion nor measurement completion establishes that lifetime.

### Difference and accounting-like operation

After capturing the saved-object integer, the function calls F-64595c3343d2 again. It then reads the original receiver’s `+0x2C8` word again.

F-871565b3c85d receives:

1. The new context result.
2. The newly read receiver-associated word.
3. The saved-object integer minus the measurement result.

The subtraction order is fixed: saved-object value less measurement, not the reverse. No visible clamp, saturation, range check, or special case for equal operands is present.

Both operands are represented as 32-bit integers. For mathematical differences within the signed 32-bit range, the resulting value is established directly. For differences outside that range, exact overflow behavior is **documented_only**. The evidence does not support promising unbounded arithmetic, saturation, or a particular wraparound rule.

The saved-object operand is read before this context-producing call. Changes made to that object during the context call do not alter the already captured operand. In contrast, the receiver-associated word is read after the context call and can reflect its effects.

### Final receiver-associated operation and carrier operation

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, they assume valid storage, compatible callables, no interfering concurrent mutation, and normal dependency returns.

### Zero branch is selected after the unconditional operation

If the receiver’s `+0x04` word is zero when read after F-23aadb16b673, the function performs the initial context call and receiver-associated call, then returns zero.

It does not prepare the callback carrier, invoke the indirect dependency, measure the receiver carrier, perform accounting, or call F-ec22bd8215d3.

An initially nonzero field is consistent with this example if an earlier dependency changes it to zero before branch selection.

### Preparation redirects callable selection

If the third input initially designates object A, but F-7a117b899bf6 changes the callback carrier’s first word to designate object B, the callable is read from B at `+0x0C`.

The callable associated with A is not selected merely because A was the original input.

### Callback changes the measured carrier

If the callback changes either receiver-carrier word, F-bf18a6a8124b receives the carrier containing those changes when invoked.

Later explicit receiver-field reads still use the original receiver address, not a replacement address written into the carrier.

### Saved address survives field replacement

Suppose branch selection saves address A, and the callback replaces the receiver’s `+0x04` field with B. The later integer read uses A at `+0x08`, provided A remains valid. It does not switch to B solely because of that field replacement.

### Intervening measurement can affect the observed object value

Suppose the callback writes 100 to A at `+0x08`.

- If that word remains 100 through F-bf18a6a8124b and until the subsequent read, the captured saved-object operand is 100.
- If F-bf18a6a8124b changes it to 80 and it remains 80 until the read, the captured operand is 80.
- If the intervening call invalidates A, this example’s normal-completion precondition fails; the function provides no visible recovery.

Callback ordering alone is therefore insufficient to promise observation of the callback-written value.

### Positive, zero, and negative differences
