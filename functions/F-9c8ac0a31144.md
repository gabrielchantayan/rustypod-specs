# F-9c8ac0a31144

## Purpose

F-9c8ac0a31144 performs a teardown-like operation on a caller-supplied address. For a nonzero input, it scans a counted sequence of 32-bit entries, invokes a dependency for each entry observed to be nonzero, adjusts global accounting, and conditionally updates allocator-like accounting before handing an allocation descriptor to another dependency.

The teardown and allocator interpretations are inferred intent. The established behavior is the sequence of reads, writes, branches, and dependency calls described below. The supplied evidence does not establish that any dependency destroys an entry, frees storage, acquires a lock, or releases a lock.

A zero input returns without further observable activity.

## Interface

### Input and result

The function accepts one 32-bit argument interpreted as an address, denoted **P**. It has no explicit result value.

For nonzero P, define:

- **H**: P − 4, the address of a 32-bit signed count.
- **N**: the signed 32-bit value read from H on entry.
- **B**: H minus the 32-bit displacement subsequently read from P − 8.

N is captured once. The displacement used to derive B is not read until after entry processing and the H-zero check.

The supplied representation uses 32-bit addresses, 32-bit words, and 16-bit unsigned fields. Address calculations require the target’s 32-bit machine semantics; this is not a portable high-level pointer interface.

### Input-adjacent layout

| Address | Width | Interpretation |
|---|---:|---|
| P − 8 | 32 bits | Displacement used to derive B; read after the scan |
| P − 4 | 32 bits | Signed count N, captured before the scan |
| P + 4k | 32 bits | Entry k, for k from 0 through N − 2 when N > 1 |

The function therefore examines **N − 1 entries**, not N entries, when N is positive and greater than one. The first entry is at P.

### Allocation-relative layout

Once B has been derived, these fields may be accessed:

| Address | Width | Interpretation |
|---|---:|---|
| B − 16 | 32 bits | Descriptor word, used for validation and masked-size accounting |
| B − 12 | 16 bits, unsigned | Index into an accounting table |
| B − 10 | 16 bits, unsigned | Index into another accounting table |
| B − 8 | 32 bits | Charge used for an earlier global accounting adjustment |

The charge at B − 8 and the masked descriptor size are separate quantities. The function does not establish that they are equal.

### Preconditions

For normal completion, all reached reads and writes must address valid memory. In particular:

- A nonzero input does not by itself establish a valid layout.
- The count must describe readable entry locations.
- The displacement must produce a B for which all reached metadata accesses are valid.
- Global state references and all computed accounting locations must be usable.
- Dependencies must return normally where execution is expected to continue.

There is no local bounds check for the count, the two 16-bit indices, or the index returned by a dependency. There is no local validation of alignment, allocation provenance, or aliasing between the input region and accounting state.

## Behavior

### 1. Null handling and entry processing

If P is zero, the function returns immediately. It does not read the count, invoke dependencies, or update accounting.

Otherwise, it reads N from H and scans entries in increasing address order. For each entry:

1. It reads the current 32-bit entry value.
2. If that value is nonzero, it calls F-94cb53877c15.
3. It proceeds to the next entry after that call returns.

No explicit argument is visible at this call site. The evidence does not establish how F-94cb53877c15 identifies an object or entry, if it does so at all.

The count is not re-read after a dependency call. Entry values are read when their individual positions are reached, rather than snapshotted before scanning. Consequently, if an earlier dependency call changes a later entry, that later entry is tested using its changed value.

For N ≤ 1, no entry is read. Negative counts do not trigger an unsigned, very large traversal.

The global accounting-state reference is sampled at every loop-condition evaluation, including the final evaluation that ends the scan. The sample retained at loop exit is used later as the destination reference for one accounting write. It is therefore not necessarily the reference that existed before entry processing.

### 2. Derived-header zero check

After entry processing, the function returns if H is zero.

This is not equivalent to the initial P-zero check. Under 32-bit address arithmetic, P equal to 4 produces H equal to zero. The function has already attempted to read N from H before reaching this later check, and it may already have processed entries.

Thus, this branch is not protection against reading address zero.

### 3. Global charge subtraction

If H is nonzero, the function reads the displacement at P − 8 and derives B. It then reads a 32-bit charge **Q** from B − 8.

Two adjacent words associated with the global accounting-state reference are updated:

- Offset 0x38 is treated as a low 32-bit word.
- Offset 0x3c supplies a high 32-bit word.

The low-word subtraction is modulo 2³². Its borrow is determined by the unsigned comparison of the original low word with Q.

The high-word calculation subtracts both:

- The sign contribution of Q interpreted as a signed 32-bit value: zero when bit 31 is clear, and −1 when bit 31 is set.
- The low-word borrow, either zero or one.

When the relevant references designate the same state object, this is equivalent to subtracting the **sign-extended 32-bit charge** from a two-word counter, modulo 2⁶⁴. It is not generally equivalent to subtracting an unsigned 32-bit charge.

The observable order is:

1. Read Q.
2. Read the low accounting word.
3. Form the current high-word location.
4. Write the adjusted low word.
5. Read the high-word source and write the adjusted high word.

The low-word access and high-word source use the global reference obtained for this phase. The high-word destination uses the reference retained at the final loop-condition evaluation. In an ordinary execution without an intervening reference change, these identify the same object. The supplied evidence does not justify erasing that distinction from the contract.

After these writes, F-2fd8826557a4 is called with no explicit argument.

### 4. Allocator-state selection and sentinel branch

After F-2fd8826557a4 returns, the function reads the allocator-state reference from a separate global location. Call this reference **A**.

If B equals 8, the function returns without descriptor validation, allocator-table updates, or further dependency calls.

This sentinel does **not** bypass the preceding work:

- The charge at B − 8 has already been read.
- Global accounting has already changed.
- F-2fd8826557a4 has already been called.
- A has already been read.

For B equal to 8, the charge read is therefore from address zero.

### 5. Descriptor validation

For B other than 8, the descriptor address is **D = B − 16**.

Before the next normal-path dependency call, the function checks the descriptor word:

- A zero word invokes F-a817d8d58c10.
- A word with bit 0 set invokes F-a817d8d58c10.
- A nonzero word with bit 0 clear passes this local validation.

F-a817d8d58c10 is marked as non-returning in the supplied evidence. There is no normal continuation from this error path and no returned error code.

This validation occurs after the global charge subtraction and F-2fd8826557a4. Failure therefore does not imply an unchanged state.

### 6. Allocator accounting updates

After descriptor validation, the function calls F-c0fc6d033caa with A.

It then reads the unsigned 16-bit index at B − 12 and reads the descriptor word again. Define **S** as that descriptor word masked with 0x3ffffffc.

S is a multiple of four, ranging from zero through 0x3ffffffc. Descriptor bits 0, 1, 30, and 31 do not contribute to S.

The following 32-bit subtractions occur in order:

1. Subtract S from the word at A + 0x224 + four times the first index.
2. Subtract S from the word at A + 0x30c.
3. Read the unsigned 16-bit index at B − 10.
4. Subtract S from the word at A + 0xe0 + four times the second index.
5. Subtract S from the word at A + 0x220.

These operations wrap modulo 2³². There is no local underflow detection, saturation, or rollback.

Next, the function calls F-09dcb55e8e0a with no explicit argument. Its result is used as an index, **R**, for further accounting:

1. Decrement the 32-bit word at A + 0x310 + four times R by one.
2. Decrement the 32-bit word at A + 0x390 by one.
3. Re-read the descriptor word at D, mask it with 0x3ffffffc, and subtract that value from the 32-bit word at A + 8.

The last subtraction need not use the same size as the earlier four subtractions. F-09dcb55e8e0a lies between them, and the descriptor is explicitly re-read afterward.

Finally, the function calls:

1. F-cc6c9b4a0f68 with A and D.
2. F-e586bff64fb7 with A.

If both calls return normally, this function returns.

## Side effects

### Direct writes

The function directly modifies:

- Two global accounting words.
- Two index-selected allocator accounting words.
- Allocator accounting words at offsets 0x30c, 0x220, 0x390, and 8.
- One accounting word selected by R at offset 0x310 plus four times R.

All listed allocator writes are 32-bit read-modify-write operations. If calculated locations alias, the writes accumulate in the stated order; the function does not operate on a snapshot of all counters.

There is no explicit direct write to the entry sequence, count, displacement, or descriptor word. Dependencies or aliases may nevertheless change those locations.

### Ownership and lifetime

The call pattern suggests release or teardown, but ownership transfer is not established by this function alone.

In particular:

- A nonzero entry does not prove that its storage is freed.
- Passing D to F-cc6c9b4a0f68 does not, without that dependency’s contract, prove deallocation.
- Returning does not prove that P or its entries remain valid.
- The function does not explicitly clear P, entries, or metadata.
- There is no locally enforced double-release protection beyond the descriptor checks described above.

Unknown dependencies must not be assumed to preserve globals, metadata, memory ownership, or allocation lifetime.

### Error and interruption behavior

There is no transactional boundary. Entry dependency calls, global accounting updates, and later allocator updates occur at different stages.

An invalid descriptor reaches the non-returning dependency only after earlier effects. Invalid addresses, out-of-range indices, dependency failures, and synchronization behavior have no locally defined recovery path in the supplied evidence.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, assume valid reached memory, non-aliasing accounting locations, stable relevant state, and normally returning dependencies.

### Null input

Given P equal to zero, the function returns without any memory read, accounting write, or dependency call.

### Entry count and order

Given N equal to 4 and successive entries at P, P + 4, and P + 8 containing zero, a nonzero value, and a nonzero value:

- Exactly those three entries are examined in address order.
- F-94cb53877c15 is called twice.
- No fourth entry is examined.

For N equal to 1, zero, or a negative signed value, no entry is examined, but later accounting still proceeds unless another branch prevents it.

### Entry mutation during processing

Given N equal to 3, a nonzero first entry, and an initially nonzero second entry, if the first call to F-94cb53877c15 changes the second entry to zero, no call is made for that second entry.

If the dependency changes the stored count, that change does not alter the captured traversal bound.

### Global subtraction with borrow

Given a low accounting word of 2, a high word of 7, and Q equal to 5, the resulting words are:

- Low: 0xfffffffd.
- High: 6.

This assumes the high source and destination designate the same state object.

### Sign-extended charge

Given a low word of zero, a high word of 7, and Q equal to 0xffffffff, the resulting words are low 1 and high 7.

Q represents −1 for this two-word subtraction. Treating it as the unsigned quantity 4,294,967,295 would produce different high-word behavior.

### Descriptor failure

Given B other than 8 and a descriptor word equal to zero, the function reaches F-a817d8d58c10 after the global accounting writes and F-2fd8826557a4.

F-c0fc6d033caa and the subsequent normal-path allocator updates are not reached.

### Nonzero descriptor with zero masked size

Given a descriptor word of 2, validation passes because the word is nonzero and bit 0 is clear. Its masked size is zero.

With stable descriptor contents, size-accounting subtractions leave their numeric values unchanged, while both count decrements still occur.

### Descriptor change across the index dependency

Given that the descriptor masks to 16 after F-c0fc6d033caa, but F-09dcb55e8e0a changes it to mask to 32:

- The first four size-accounting updates subtract 16.
- The later update at A + 8 subtracts 32.

The descriptor is not revalidated after either dependency.
