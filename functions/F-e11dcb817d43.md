# F-e11dcb817d43

## Purpose

F-e11dcb817d43 conditionally updates a single byte in a caller-supplied memory region and returns a 32-bit result.

Three selector values request an update: 0, 2, and 4. Each selects a different byte value. Every other selector returns a distinct result without accessing the supplied memory region.

The established behavior is a numeric mapping, not a named state transition. The meaning of the stored values and the interpretation of the return values are unknown. In particular, a nonzero return value does not uniformly mean failure: two update cases return 4, while selectors that cause no update return 1.

## Interface

The function has two inputs and one return value:

| Item | Contract |
|---|---|
| Memory base | An address-bearing argument identifying the base of a caller-supplied region. It is used only for selectors 0, 2, and 4. |
| Selector | An integer argument compared for exact equality with 0, 2, and 4. It is not treated as a mask or an index. |
| Return value | A 32-bit result whose only established values are 0, 1, and 4. |

The recovered interface represents both inputs as integer arguments. A 32-bit address-bearing interface is consistent with the supplied representation, but the original declaration, calling convention, and machine address model are not independently established. The memory base must not be assumed to denote a particular language-level object type.

The sole accessed location is at byte offset 116, equivalently hexadecimal offset 0x74, from the supplied base. The access width is exactly one byte.

For a normal completion on an updating selector, this address must be valid and writable. If the base identifies the beginning of a contiguous allocation, that allocation must include byte offset 116. The function does not inspect preceding bytes or require them to contain a recognized header.

For all other selectors, the supplied behavior does not access the base address. The argument need not designate writable storage merely to execute those paths. This is a property of this function’s memory accesses, not a guarantee that an external caller or language runtime permits every possible argument representation.

The function has no output buffer beyond the one-byte destination and establishes no ownership transfer.

## Behavior

The complete selection and result mapping is:

| Selector | Destination access | Stored byte | Return value |
|---:|---|---:|---:|
| 0 | One write at base + 116 | 4 | 0 |
| 2 | One write at base + 116 | 6 | 4 |
| 4 | One write at base + 116 | 1 | 4 |
| Any other representable integer | None | Unchanged by this function | 1 |

Selection depends only on the integer selector. The previous contents of the destination do not participate in the decision.

For selector 0, the function writes byte value 4 and then returns 0.

For selector 2, it writes byte value 6 and then returns 4.

For selector 4, it writes byte value 1 and then returns 4.

For every other selector, it returns 1 without reading or writing the destination. There is no fallback update and no normalization of the selector into one of the accepted values.

### Access ordering

On each updating path, the byte write precedes normal return. There is no established read of the destination before the write. Thus, the behavior does not depend on its initial contents and does not perform a read-modify-write operation.

On a non-updating path, there is no access to the caller-supplied region before return.

No intervening dependency calls appear in the supplied body. There is therefore no unknown callee between selection and the destination write whose effects must be incorporated into this function’s local behavior.

### Widths and arithmetic

The stored values 1, 4, and 6 all fit within an unsigned eight-bit byte. Their storage does not depend on truncating a larger, out-of-range value. The 32-bit return values are distinct from the stored byte values: for example, selector 0 stores 4 but returns 0.

The displacement is measured in bytes, not in elements of an inferred structure or array. Only the byte at offset 116 is assigned. A wider field assignment, neighboring-byte clear, or multi-byte encoding is not supported by the evidence. Endianness does not change the value of this single-byte store.

The function contains no explicit check for address overflow or an invalid effective address. The consequences of an unrepresentable base-plus-offset calculation are not established. Callers requiring normal completion must supply a base for which the destination is valid in the execution environment.

### Edge cases

A destination already containing the selected value still follows the updating path. There is no comparison that skips the assignment.

Negative selectors, where representable by the interface, belong to the non-updating case. So do positive values other than 2 and 4, with 0 separately handled as an updating case.

An invalid destination on an updating path has no defined recovery result in this contract. The listed return value describes normal completion after the write; it must not be promised when the write cannot complete.

## Side effects

The sole established caller-visible memory modification is the one-byte write on an updating path. The supplied body contains no other memory assignment.

It does not allocate, release, resize, or retain storage. The caller remains responsible for the destination’s lifetime and accessibility. The function neither initializes an entire region nor checks that the region represents a valid larger object.

No global access, logging, I/O, callback, lock operation, or synchronization operation appears in the supplied body.

These facts do not establish concurrency guarantees. In particular, the contract does not promise atomicity, inter-thread visibility, or ordering relative to accesses performed by other execution agents. Likewise, any additional effects caused by writing memory-mapped hardware are properties of the destination environment, not established behavior of this function.

## Dependencies

No called-function dependencies are present in the supplied body.

Normal completion on updating paths depends on the execution environment accepting a one-byte write at the computed address. The function provides no explicit validation or error-reporting mechanism for failure of that requirement.

## Acceptance examples

The following are conditional acceptance criteria derived from static evidence. They are not reports of executed tests.

1. **Selector 0 updates and returns 0.**  
   Given a valid writable destination at base + 116, a selector of 0 produces byte value 4 at that destination and returns the 32-bit value 0. The prior destination value does not affect the outcome.

2. **Selector 2 updates and returns 4.**  
   Given the same memory precondition, a selector of 2 produces byte value 6 and returns the 32-bit value 4.

3. **Selector 4 updates and returns 4.**  
   Given the same memory precondition, a selector of 4 produces byte value 1 and returns the 32-bit value 4. Its return value matches the selector-2 case, but its stored value differs.

4. **An unrecognized selector does not update.**  
   With selector 3 and an initially observable destination byte of 9, the function returns 1 without accessing that destination. In the absence of outside modification, the byte remains 9.

5. **Negative selectors do not select an update.**  
   If −1 is representable by the input interface, it returns 1 without accessing the supplied region. The function does not use its low bits to select a case.

6. **The assignment is byte-sized.**  
   Given ordinary writable memory and no concurrent modification, bytes immediately before and after the destination retain their initial values across an updating call. Only the byte at offset 116 is assigned.

7. **A non-updating selector does not require a successful destination write.**  
   Given selector 1, the function returns 1 without accessing the region, even if the supplied base would not support the updating paths. This criterion does not override argument-validity rules imposed outside the supplied body.

8. **An inaccessible updating destination has no specified normal result.**  
   Given selector 2 and an unwritable destination, acceptance must not require a return of 4. Fault handling and any subsequent control flow are unknown.
