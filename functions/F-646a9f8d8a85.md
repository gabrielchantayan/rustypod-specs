## Acceptance examples

These are conditional static acceptance examples, not executed tests. Each assumes valid accesses, the specified dependency results, and return from preceding calls.

1. **Packed argument versus aligned address.**  
   With third argument `0x00040007`, F-000000000003 receives `0x00010000`. The later third-argument-addressed store targets `0x00040018`. The two transformations are intentionally different.

2. **Different selector scales.**  
   If the first and second selector results are both 3, the inherited word is first stored at address 68 and later at address 32.

3. **Duplicated scaled argument.**  
   If F-000000000016 returns 7, the third-argument-addressed word store writes 28, and F-000000000017 receives 28 in both explicit positions.

4. **Split 64-bit result.**  
   If F-000000000030 returns high half 9 and low half 5, the routine stores 20 at address 56. F-000000000031 receives 20, 9, 20, and 20.

5. **Captured base, later sample.**  
   If the captured global base is 4096, later replacement of the global base slot does not redirect the explicit sample away from address 4116. A change to the word at address 4116 before the sample can change the sampled value.

6. **Byte extraction.**  
   For sampled word `0x2AC000AB`, the first byte write carries `0xAB`; the second carries `0xAB` from bits 22 through 29. Neither destination is determined by the sampled word.

7. **Aliasing table operations.**  
   If the first byte write targets the location subsequently used for the second table read, and no intervening call changes it, the second lookup observes the first write’s byte.

8. **Final zero address.**  
   If the retained low half from F-000000000040 is `0x00000180`, the final 16-bit zero store targets address 3. Whether that unaligned access succeeds is platform-dependent.

9. **No guaranteed completion.**  
   If the final call faults at address zero, the preceding global assignment and zero stores have already been attempted. The routine has no visible recovery path.
