# F-667717e3fb3e

## Purpose

F-667717e3fb3e conditionally selects a record from a fixed-stride table and returns its address, or returns zero when a selection condition fails.

Selection depends on:

- A nonnegative, signed index.
- An inclusive upper bound supplied by F-fd477cd1a249.
- A table-derived address that is not zero.
- A 32-bit field at record offset 24 that equals zero.
- When the requested mask is nonzero, an intersection between that mask and a 16-bit field at record offset 4.

F-4c6d30ac2311 is called before selection processing. F-cc60a532ba6c is called after selection processing and before the normal return. Their placement resembles entry/exit coordination, but locking, resource ownership, and synchronization guarantees are not established.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Inputs

**Index**

A signed 32-bit integer under the represented interface.

Negative values are rejected without calling F-fd477cd1a249. Nonnegative values are compared with that dependency’s signed result. Equality with the returned bound is permitted.

**Requested mask**

An unsigned 32-bit integer.

Zero disables the record-mask condition and avoids reading the 16-bit field at record offset 4. A nonzero mask requires at least one shared set bit with that field; it does not require all requested bits to be present.

Only the low 16 bits of the requested mask can overlap the record field. Consequently, a mask containing only bits 16 through 31 cannot select a record.

### Output

The represented return type is a signed 32-bit integer. Its successful value is the computed record address represented in that integer form. Zero denotes rejection.

The function does not return a copied record, a Boolean success value, or a separately allocated result. It exposes no separate error code distinguishing a negative index, an out-of-range index, a zero computed address, a nonzero status field, or a failed mask intersection.

The precise machine interpretation of address values with the high bit set is not independently established. Such values must not be treated as negative-index-style rejection merely because the declared return type is signed: the visible selection test checks whether the computed address is zero, not whether it is positive.

## Behavior

### Entry and bounds

On every normal invocation, F-4c6d30ac2311 is called before the index is tested.

The provisional result is then zero. A negative index leaves that result unchanged and bypasses the bound query, table-base read, address calculation, and record-field reads.

For a nonnegative index, F-fd477cd1a249 is called with no explicit arguments. The index is compared with its signed return value:

- An index greater than the returned value is rejected.
- An index equal to the returned value proceeds.
- An index smaller than the returned value proceeds.
- A negative returned bound excludes every nonnegative index.

The dependency is not called for a negative index. This conditional call is observable and must not be replaced with an unconditional query.

The returned bound’s meaning is unknown. The inclusive comparison is established; whether the dependency supplies a greatest valid index, a count, or another limit is not. In particular, interpreting its result as a count would require evidence outside this function.

### Candidate address

Only after the signed bounds comparison succeeds does the function read the shared table-base value.

It computes the candidate address using a displacement of 36 bytes multiplied by the index. The visible expression uses signed integer intermediates. No explicit overflow check, allocation-range check, or address-validity check accompanies this calculation.

The arithmetic contract is therefore conditional on the target’s integer and address semantics. The evidence does not justify inventing saturation, guaranteed wraparound, or a defined failure result for overflow.

The computed candidate address is checked against zero. The table base itself is not separately checked against zero.

This distinction matters: a zero base combined with a nonzero displacement is not rejected by a base-null guard, because no such guard is visible. Whether the resulting address is valid to read remains an external precondition.

### Record eligibility

For a nonzero computed address, the function reads the 32-bit field at offset 24.

If that field is nonzero, the record is rejected. The mask field is not read on this path.

If the field is zero, the requested mask determines the remaining work:

- A zero requested mask accepts the candidate without reading offset 4.
- A nonzero requested mask causes an unsigned 16-bit read at offset 4.
- The candidate is accepted if the bitwise intersection is nonzero.
- A zero intersection rejects the candidate.

The 16-bit field contributes no set bits above bit 15 when combined with the unsigned 32-bit mask. High mask bits do not create matches and do not prevent a match supplied by a low bit.

Acceptance requires any matching bit, not complete containment of the requested mask.

### Exit

On normal completion of selection processing, F-cc60a532ba6c is called whether the provisional result is zero or a selected address.

The function then returns the saved result. It performs no visible second bounds query, table-base read, status read, or mask read after that final dependency call.

The contract does not guarantee that the selected record remains eligible, readable, or allocated after F-cc60a532ba6c. That dependency’s effects are unknown. The returned numeric address reflects the earlier selection, not a post-call revalidation.

If a dependency does not return normally, or if an address calculation or memory access fails, the evidence does not establish a normal result or guaranteed execution of the final dependency.

## Side effects

### Direct effects and read order

The function contains no explicit writes to shared table storage or record fields. Its visible direct shared-data operations are reads.

Excluding operations performed inside dependencies, the established logical order is:

1. Call F-4c6d30ac2311.
2. For a nonnegative index, call F-fd477cd1a249.
3. For an index within the inclusive bound, read the table base.
4. Compute and test the candidate address.
5. For a nonzero candidate, read the 32-bit status field.
6. For a zero status and nonzero requested mask, read the 16-bit mask field.
7. Call F-cc60a532ba6c.
8. Return the saved result.

Short-circuiting is part of the behavior. A failing earlier condition suppresses later reads.

This is the ordering established by the supplied representation. It does not independently establish hardware memory barriers, atomicity, volatile access semantics, or concurrency guarantees.

No assumption is made that any dependency preserves globals, acquires or releases a lock, owns memory, or leaves returned storage alive.

## Acceptance examples

The following are conditional acceptance cases, not observed executions. Address examples assume representable arithmetic and valid readable storage wherever a read is required.

### Negative index

With index −1 and any requested mask:

- F-4c6d30ac2311 is called.
- F-fd477cd1a249 is not called.
- No explicit table-base or record-field read occurs.
- F-cc60a532ba6c is called.
- The result is zero.

### Inclusive bound

Suppose F-fd477cd1a249 returns 3.

Index 3 proceeds to candidate calculation. Index 4 returns zero without reading the table base or record fields.

The successful path for index 3 still requires a nonzero candidate address, zero status, and satisfaction of any enabled mask condition.

### Negative bound

With index 0 and a bound result of −1, selection is rejected before the table-base read. Both the entry and exit dependencies are still called if execution completes normally.

### Zero requested mask

Suppose the computed candidate is nonzero and its 32-bit field at offset 24 is zero.

A requested mask of zero selects that address without reading the 16-bit mask field. The value stored at offset 4 does not affect this decision.

### Nonzero status

Suppose the candidate is nonzero but its 32-bit field at offset 24 contains 1.

The result is zero for every requested mask. The mask field is not read, including when the requested mask is nonzero.

### Any-bit matching

Suppose the status is zero and the 16-bit mask field is 0x0004.

- Requested mask 0x0000000C selects the candidate: bit 2 matches, although bit 3 does not.
- Requested mask 0x00000008 rejects it.
- Requested mask 0x80000004 selects it because the low matching bit is sufficient.
- Requested mask 0x80000000 rejects it because the record field has no bit 31.

### Zero computed address

If valid address arithmetic yields a candidate address of zero, the result is zero. Neither record field is read.

This case is defined by the computed address, not merely by the table-base value.

### State changes during exit

Suppose a candidate is selected, and F-cc60a532ba6c subsequently changes its status or the shared base before returning normally.

The visible function still returns the previously saved address. Whether that address remains usable is outside the established contract.
