# F-1202a213d3b9

## Purpose

F-1202a213d3b9 prepares a request in one of two layouts, invokes an initial operation, optionally invokes an alternate operation, and publishes an accepted response to caller-provided storage.

Initial status zero permits publication without identity validation. The alternate operation is attempted only after initial status `0x20` and nonzero permission. Alternate status zero permits publication only when:

- A mode-specific decoder’s unsigned 32-bit result equals the **current contents of a retained identifier slot, read after the decoder returns**.
- A response selector byte, zero-extended to 32 bits, equals the full original selector argument.

The retained identifier slot initially contains the third argument. Its address is explicitly passed to a dependency during expanded request construction. Preservation of its original value is not established. Alternate acceptance therefore does not necessarily require equality with the original identifier argument.

The apparent intent is to normalize a compact response into the output shapes also used for an expanded response. Serialization, transfer semantics, and protocol meanings remain dependency-contract questions.

## Interface

The supplied representation has eight arguments and a signed 32-bit return value.

| Position | Role | Representation and requirements |
|---|---|---|
| 1 | Context | A 32-bit address-bearing value. The function reads a 16-bit discriminator at byte offset `2` and a 32-bit pointer at byte offset `0x154`, then dereferences that pointer to obtain a 32-bit handle. |
| 2 | Selector | Unsigned 32-bit value. Request construction uses its low eight bits. Alternate validation compares a zero-extended response byte against the full original argument. |
| 3 | Initial identifier | Unsigned 32-bit value copied into a mutable retained local slot before workspace initialization. Later construction and validation use that slot as described below. |
| 4 | Additional request value | Opaque 32-bit value copied into retained local storage. Compact construction takes a 16-bit value from that storage; expanded construction passes its address to a dependency. |
| 5 | Alternate permission | Signed 32-bit value tested for zero versus nonzero. Every nonzero value permits the alternate operation. |
| 6 | Primary output | Address targeting an apparent 12-byte output representation. Some or all publication is delegated, depending on mode. |
| 7 | Secondary output | Address targeting sixteen 32-bit entries, totaling 64 bytes. |
| 8 | Auxiliary output | Address of writable 32-bit storage. Written before context access and again on every normal return. |

There are no explicit checks for null pointers, accessibility, alignment, sizes, or overlap.

The context and auxiliary output are accessed regardless of operation success. Primary and secondary publication occurs only on accepted-response paths. This does not establish that rejected paths leave those regions unchanged when aliasing or dependency effects are possible.

Predictable independent outputs require suitably aligned, adequately sized, nonoverlapping storage that does not alias context or dependency-accessible state. The function does not enforce these conditions.

### Return representation

Each operation result is interpreted as signed 16-bit and widened to signed 32-bit.

- `0` denotes an accepted operation followed by publication.
- `0x20` is the initial status permitting an alternate attempt. It is also the rejection status after failed alternate identity validation and the replacement for alternate status `0x353`.
- Other operation statuses are propagated according to the branch rules below.

For example, the 16-bit pattern `0xffff` is returned as `-1`, not `65535`.

The auxiliary output is separate from the return status. Its semantic meaning is unknown.

## Behavior

### Entry ordering and mode selection

The directly established preparation order is:

1. Write 32-bit zero to the auxiliary output.
2. Read the pointer at context offset `0x154`, dereference it, and retain the resulting 32-bit handle.
3. Retain the context, selector, identifier, and additional request value in local storage.
4. Invoke F-6e3669b482ce with a local workspace address.
5. Store the original selector argument’s low byte in request-related storage.
6. Read the context discriminator at offset `2`.

Discriminator `0x4244` selects compact mode. Every other 16-bit value selects expanded mode.

Handle capture precedes workspace initialization; discriminator access follows it. The function does not recapture the handle after initialization. No preservation of shared state by F-6e3669b482ce is established.

The identifier slot is initialized from the third argument before that dependency call. Subsequent references to the **retained identifier** mean its contents at the specified time, not an immutable copy of the original argument.

### Initial operation

Both modes invoke F-7cae4aaa5e45 with these arguments, in order:

1. Retained handle.
2. Workspace address.
3. The 32-bit value `0xffffffff`.
4. Descriptor address.
5. A separate local storage address.
6. The same workspace address supplied as argument 2.

The alias between arguments 2 and 6 is explicit. The meanings of the all-ones value and separate local region are unknown.

The signed 16-bit result determines subsequent behavior:

| Initial result | Action |
|---|---|
| `0` | Publish using the selected mode, without identity validation. |
| `0x20`, permission zero | Skip the alternate operation and publication; retain status `0x20`. |
| `0x20`, permission nonzero | Invoke the alternate operation. |
| Any other value | Skip publication and propagate the signed result. |

### Alternate operation and validation

F-15d9d014c368 receives, in order:

1. Retained handle.
2. Value `2`.
3. Workspace address.
4. The same descriptor address.
5. The same separate local storage address.

The function does not reconstruct or reinitialize the request, descriptor, response region, or workspace between operations. Changes made during the initial operation remain available to the alternate operation.

Alternate results are handled as follows:

- `0x353`: skip publication and select return status `0x20`.
- Any other nonzero result: skip publication and propagate that signed result.
- Zero: perform mode-specific identity validation.

For compact mode, F-4055be9c3f18 receives the field at request-relative offset `2`. After it returns, its unsigned 32-bit result is compared with the **then-current retained identifier slot**.

For expanded mode, F-ef04bf9ca82f receives the field at request-relative offset `4`. After it returns, its unsigned 32-bit result is compared with the **then-current retained identifier slot**.

In either mode:

- If identifier comparison fails, the selector byte is not read for validation, publication is skipped, and status becomes `0x20`.
- If identifier comparison succeeds, the current response selector byte is read: compact offset `1` or expanded offset `2`.
- That byte is zero-extended and compared with the full original selector argument.
- Equality permits publication; inequality selects status `0x20`.

The comparison does not use an identifier value snapshotted before the decoder call. A change to the retained slot that is visible when the decoder returns affects the comparison.

Because the selector comparison uses a zero-extended byte, original selector values greater than `255` cannot pass alternate validation. They are nevertheless allowed during construction and do not prevent acceptance of initial status zero.

### Compact publication

The compact accepted-response path performs these actions in order:

1. Write 16-bit value `10` at primary output offset `0`.
2. Write the current compact selector byte at primary output offset `2`.
3. Write byte zero at primary output offset `3`.
4. Invoke F-42a35b3b505e with primary output offset `4` first and the current compact identifier-field address second.
5. Read the current compact 16-bit field at request-relative offset `6`, zero-extend it to 32 bits, and store it in a temporary slot.
6. Invoke F-42a35b3b505e with primary output offset `8` first and that temporary slot’s address second.
7. Read the six compact response fields individually and write their zero-extended values to secondary entries `0` through `5`, in ascending order.
8. Write zero to secondary entries `6` through `15`, in ascending order.

Publication uses current local fields, not guaranteed copies of the original arguments. The two field-helper calls precede all direct secondary-output writes.

The zero-fill loop uses unsigned 32-bit arithmetic. Its counter begins at `3`, advances through `7`, and reaches termination value `8`. An update mask clears bit 16 but has no effect on these values. Each iteration writes two consecutive entries, yielding exactly entries `6` through `15`.

There is no earlier direct bulk initialization of either caller output.

### Expanded publication

The expanded accepted-response path invokes F-70a021fc7c24 twice:

1. Expanded request-region address, primary output address, length `0x0c`.
2. Expanded response-region address, secondary output address, length `0x40`.

The first invocation returns before the second begins.

The apparent roles are source, destination, and byte count. Exact transfer direction, internal access ordering, overlap behavior, and failure behavior are not established by the supplied function alone.

### Completion

Every normal return path reads a 32-bit workspace slot, writes its value to the auxiliary output, and returns the selected signed status.

This final write follows any response publication. No status check guards it. The function does not directly initialize the workspace completion slot before invoking dependencies; its usable contents depend on dependency behavior.

## Side effects

### Caller-visible memory

Directly established writes are:

- Entry-time zero and normal-return completion value to the auxiliary output.
- Compact primary fields at offsets `0`, `2`, and `3`.
- Compact secondary entries `0` through `15`.

The other compact primary fields and both expanded outputs are handled through dependencies.

A rejected operation skips the publication paths. That is not an unconditional guarantee of unchanged primary or secondary storage: those regions may alias the auxiliary output or memory affected by dependencies.

The initial auxiliary write precedes context reads. Consequently, aliasing it with context storage can affect the handle or discriminator subsequently read. The final auxiliary write can overwrite previously published output when the regions overlap.

### Ownership and state

Request, response, descriptor, workspace, and temporary storage are local to the invocation. Their addresses are supplied to dependencies.

No direct heap allocation, deallocation, context-field write, or ownership transfer is visible. The source does not establish whether dependencies allocate or release resources, retain addresses, mutate shared state, or access memory beyond their apparent field roles. Retention of invocation-local pointers would require a separate lifetime contract; none is supplied.

There is no visible rollback. Partial dependency effects are not undone after an error.

### Abnormal completion

There is no explicit recovery for invalid addresses, insufficient storage, alignment faults, dependency faults, or nonreturning dependencies. The completion write is established only for normal returns.

## Acceptance examples

These are conditional criteria, not observed executions. Assume valid disjoint caller storage, normally returning dependencies, and initialized fields wherever the function consumes them. Any assumed encoding or transfer behavior is an additional dependency condition.

1. **Compact initial success.**  
   With discriminator `0x4244` and initial status zero, publish without invoking the alternate operation or either validation decoder. Six 16-bit response values become six zero-extended secondary entries; entries `6`–`15` become zero.

2. **Expanded initial success despite identity mismatch.**  
   With any other discriminator and initial status zero, invoke both expanded publication calls even if response identity differs from the original arguments or current retained identifier.

3. **Alternate disabled.**  
   Initial status `0x20` with permission zero causes no alternate call and no publication. Return `0x20` after the auxiliary completion write.

4. **Alternate acceptance with a preserved identifier.**  
   Initial status `0x20`, nonzero permission, and alternate status zero reach validation. If the retained identifier still equals the original identifier when read after decoding, the decoder must equal that original value; the response selector must also equal the full original selector.

5. **Alternate acceptance after identifier mutation.**  
   Suppose the original identifier is `0x11223344`, but the retained slot contains `0xaabbccdd` when read after the decoder returns. A decoder result of `0xaabbccdd` passes identifier comparison. With a matching selector byte, publication occurs despite disagreement with the original identifier.

6. **Original identifier is insufficient after mutation.**  
   Under the preceding slot contents, decoder result `0x11223344` fails identifier comparison. Skip the selector read for validation, skip publication, and return `0x20`.

7. **Decoder-time mutation matters.**  
   If the retained slot contains one value before decoding and another when decoding returns, comparison uses the latter. Acceptance cannot be determined from the pre-call value alone.

8. **Selector boundary.**  
   Original selector `0xff` can match response byte `0xff`. Original selector `0x100` cannot match any response byte, including zero, although construction stores its low byte as zero. Initial status zero remains acceptable in either case.

9. **Special alternate status.**  
   Alternate status `0x353` yields `0x20` without identity validation or publication.

10. **Signed propagation.**  
    Initial result pattern `0xffff` yields signed return `-1`, without an alternate call or publication.

11. **Compact truncation and widening.**  
    If the retained additional-value slot contains `0x12345678` when compact construction reads it, the compact field becomes `0x5678`. If that field remains unchanged until publication, the temporary supplied to the final primary-field helper contains `0x00005678`.

12. **Auxiliary completion on error.**  
    A propagated operation error still reaches the final workspace-derived auxiliary write. The auxiliary output need not retain its entry-time zero.
