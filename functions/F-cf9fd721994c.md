# F-cf9fd721994c

## Purpose

F-cf9fd721994c scans fixed-size records for a requested identifier and writes a value for every matching record. The value depends on a signed position and the record’s bounds:

- Below the lower bound: select the lower endpoint value.
- Otherwise, above the upper bound: select the upper endpoint value.
- Otherwise: obtain an adjustment from F-8f41f510c86c and add it to a lower endpoint value read after that call.

The lower-bound comparison has precedence. Bounds are neither validated nor reordered.

A match does not terminate the scan. Multiple matching records can cause multiple writes to the same output address.

The established behavior is a keyed scan with endpoint selection and a delegated calculation. Interpolation is inferred intent only; the dependency’s numerical behavior is not supplied.

## Interface

The function accepts four inputs and returns a 32-bit status.

| Input | Interpretation |

Identifier matching is equality of the represented 32-bit values. No signed ordering of identifiers is used.

## Behavior

### Initial selection

The first relevant data read obtains the collection reference from the object at offset `0x1E8`.

If this reference is zero, the function returns `6` without accessing a descriptor, selecting a record, calling the dependency, or writing the output.

Otherwise, that descriptor address is retained for the scan. The object’s collection-reference field is not reread. Changing that field during the invocation does not redirect the current scan.

### Scan extent

Scanning begins at index zero. Before each prospective iteration, the index is compared against the signed count read from descriptor offset `0x20`.

A zero or negative count prevents entry and produces a normal return of `0`, with no record selection or output write.

The count is not a scan-wide snapshot. Later loop conditions read it again. Changes visible at those conditions may shorten or extend the scan.

For every entered iteration, the function reads the storage address at descriptor offset `0x1C` and selects the record displaced by 20 times the index. That storage address is also not a scan-wide snapshot. A later iteration may therefore use a different storage address.

The selected record address is retained while that record is processed. Changing the descriptor’s storage-address field during a dependency call does not redirect the current record’s post-call endpoint read; it can affect subsequent iterations.

### Identifier filtering

The selected record’s identifier is read before its bounds or endpoint values.

If it differs from the requested identifier, the record causes no endpoint calculation, dependency call, or output write.

After either a mismatch or a completed match, the index advances by one and scanning continues. There is no early successful return.

### Lower endpoint selection

For a matching record, the lower position bound is read and retained for the current calculation.

If the position is strictly less than that bound, the lower endpoint value is read and written to the output. This path does not require an upper-bound comparison.

This precedence applies even when the lower bound exceeds the upper bound.

### Upper endpoint selection

If the position is not below the captured lower bound, the upper bound is read and compared with the position.

If the upper bound is strictly less than the position, the upper endpoint value is read and written to the output.

Equality with the upper bound does not satisfy this comparison. However, equality alone does not guarantee the delegated calculation: an inverted interval may already have selected the lower endpoint.

### Delegated calculation

The dependency is called only when neither outside-range comparison succeeds.

Its three signed 32-bit arguments, in interface order, are:

1. Position minus the captured lower bound.
2. Upper endpoint value minus lower endpoint value.
3. Upper bound minus the captured lower bound.

The lower bound used in both differences is the value captured before the branch decisions. The endpoint fields and the upper bound needed for these arguments are read before the call. The upper-bound field is referenced again for argument construction rather than being established as a retained result of its earlier comparison.

After F-8f41f510c86c returns, the function reads the current record’s lower endpoint value again, adds the dependency’s result, and writes the sum to the output.

The lower endpoint used after the call need not equal the one used to construct the second argument. No assumption that the dependency preserves record memory is justified.

### Ordered, zero-width, and inverted bounds

For stable bounds with the lower bound no greater than the upper bound, the delegated path includes both boundaries:

- At the lower bound, the first argument is zero.
- At the upper bound, the first argument equals the interval width, provided the subtraction is representable.
- If both bounds are equal and the position equals them, the first and third arguments are zero.

The caller supplies no zero-width guard.

For stable inverted bounds, where the lower bound is greater than the upper bound, no position reaches the delegated calculation:

- Every position below the lower bound selects the lower endpoint.
- Every other position is above the upper bound and selects the upper endpoint.

Consequently, with lower bound 20 and upper bound 10, position 10 selects the lower endpoint, while position 20 selects the upper endpoint. Neither boundary invokes the dependency.

These interval classifications assume stable field values. Mutations between individual reads can prevent the accesses from describing one consistent interval.

### Completion and duplicates

On normal scan termination, the function returns `0`.

With stable scanned state, a nonoverlapping output destination, and normally returning dependency calls, the final output is the value from the last matching record in scan order.

All earlier matching writes still occur. They are not combined or deferred.

If no identifier matches, the output remains untouched by this function’s explicit stores.
