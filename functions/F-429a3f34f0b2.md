# F-429a3f34f0b2

## Purpose

F-429a3f34f0b2 reads an initial byte, optionally accumulates a value from subsequent continuation-shaped bytes, and returns either that value or a shared replacement value. It also reports the address immediately following the bytes it consumed.

The operation resembles variable-length character decoding, but the established behavior is not strict UTF-8 decoding. It does not establish a continuation count from the initial byte, enforce a maximum sequence length, reject every isolated continuation byte, or restrict accepted results to the Unicode scalar-value range.

The contract below describes the supplied static representation. No runtime tests have been performed. The contents of the lookup table and replacement-value storage are unknown.

## Interface

The operation has three inputs:

- **Input address:** address of the first byte to inspect.
- **Boundary address:** address used to stop continuation-byte inspection.
- **Cursor-output address:** address of a writable four-byte location that receives the next input address.

The return value is an unsigned 32-bit integer.

Input bytes and lookup-table entries are unsigned eight-bit quantities. Accumulation uses unsigned 32-bit arithmetic. The supplied representation stores an address into a four-byte output location; this contract therefore describes a 32-bit cursor representation. Calling-convention details, alignment requirements, and byte order are not established.

The function also reads shared data:

- A lookup-table base address. Initial bytes from 192 through 255 select one of 64 byte entries.
- A 32-bit replacement value, read only when the accumulated result takes the replacement path.

### Preconditions for a normally completed call

The initial input address must identify a readable byte. This is required even if it equals the boundary address: no initial boundary check precedes the first read.

Every subsequently inspected input byte must be readable. The table-base storage and selected table entry must be readable when the initial byte exceeds 191. The replacement-value storage must be readable when replacement is required. The cursor-output location must be writable for four bytes.

The boundary is an equality sentinel, not a general range guard. Safe traversal requires the caller to arrange that continuation scanning either encounters that exact address or stops at a readable non-continuation byte before any invalid access.

No ownership transfer is established for the input, shared data, or output storage. No allocation or release operation appears in the supplied representation.

## Behavior

### Initial byte and direct-return path

The function first reads the initial byte and advances its internal cursor by one byte. This happens before any comparison with the boundary address.

If the initial byte is between 0 and 191 inclusive:

- Its unsigned numeric value is the result.
- No continuation bytes are examined.
- No lookup-table entry or replacement value is needed.
- The cursor output receives the address one byte after the initial input address.

Consequently, initial bytes from 128 through 191 are returned directly. Their resemblance to continuation bytes does not cause rejection on this path.

### Lookup-based accumulation

If the initial byte is between 192 and 255 inclusive, its value minus 192 selects a byte in the shared lookup table. The selected byte, zero-extended to 32 bits, becomes the accumulator.

The internal cursor already points one byte beyond the initial input address. Continuation scanning then proceeds subject to these rules:

1. The current cursor is compared with the boundary address.
2. If they are equal, scanning stops without reading a byte at that address.
3. Otherwise, the byte at the current cursor is read.
4. A byte from 128 through 191 inclusive is consumed. The accumulator is multiplied by 64, then increased by the byte’s low six bits. The cursor advances by one byte.
5. A byte outside that range stops scanning and is not consumed.

The accumulator update is modulo 2³². Overflow is not reported and does not itself stop scanning.

There is no observed limit on the number of continuation bytes consumed. The initial byte selects a seed but does not otherwise impose an expected continuation count. A selected seed can therefore be used with zero, one, or arbitrarily many continuation bytes, subject to readable memory and eventual termination.

Stopping on a non-continuation byte leaves the output cursor pointing at that byte. The byte has been read to determine its classification, but it remains unconsumed.

### Final acceptance and replacement

After continuation scanning, the function classifies the final 32-bit accumulator.

The accumulator is returned unchanged only when all of the following hold:

- Interpreted as a signed 32-bit integer, it is greater than 127.
- It is not in the inclusive interval from 0xD800 through 0xDFFF.
- It is neither 0xFFFE nor 0xFFFF.

Equivalently, the accepted unsigned range is 0x00000080 through 0x7FFFFFFF, excluding those specified values and interval.

All other accumulator values cause a read of the shared replacement value, which becomes the result. In particular:

- Values from 0 through 127 take the replacement path.
- Values with bit 31 set take the replacement path because their signed interpretation is negative.
- Values from 0xD800 through 0xDFFF take the replacement path.
- Values 0xFFFE and 0xFFFF take the replacement path.

This classification applies only to the lookup-based path. An initial byte of 0 through 127 returns directly instead of taking the replacement path.

The exclusion of 0xFFFE and 0xFFFF is exact. It is not a general rejection of values whose low 16 bits match either pattern. Likewise, values above 0x10FFFF are not categorically rejected: a result such as 0x110000 passes the stated classification.

The replacement value is returned without being classified again. Its actual value is unknown and may numerically coincide with an otherwise accepted or rejected accumulator.

### Cursor publication

After the return value has been selected, the function writes the internal cursor into the cursor-output location and returns the selected 32-bit result.

The cursor reflects bytes consumed during scanning, regardless of whether the accumulator was accepted or replaced. Replacement does not rewind the cursor.

There is no separate success flag, malformed-input status, or consumed-byte count. The reported address allows the caller to determine consumption when address subtraction is valid in the caller’s environment.

## Side effects

The only explicit memory write is the final four-byte cursor-output store. The function does not explicitly modify the input bytes, table contents, table-base storage, or replacement-value storage.

The established logical access order is:

- Read the initial input byte.
- For the lookup-based path, obtain the table base and read the selected table byte.
- The supplied representation also obtains the table-base value again before continuation scanning. That value does not affect the accumulator or return selection.
- During scanning, compare against the boundary before each possible continuation-byte read.
- If required by final classification, read the replacement value.
- Write the output cursor.

The additional table-base retrieval is present in the supplied static representation. Whether it corresponds to a distinct externally observable machine-memory transaction is not established. There is no evidence of volatile access, atomic access, or synchronization semantics.

Aliasing is not explicitly prohibited. If output storage overlaps input or shared data, the final store occurs after the reads needed to select the result. Such overlap may change memory that subsequent calls use. No overlap-safe API guarantee, concurrent-access guarantee, or transactional behavior is established.

Invalid reads, invalid writes, invalid address arithmetic, or failure to reach a stopping condition have no defined error response in the supplied representation. It would be incorrect to specify that such cases reliably return the replacement value.

## Dependencies

There are no calls to other functions in the supplied representation. No additional opaque function IDs are available or required.

The operation depends on two shared-data facilities:

- **Lookup-table storage:** provides an address and byte entries indexed by initial-byte values 192 through 255. Only the selected entry is used for a given call.
- **Replacement-value storage:** supplies the complete 32-bit return value on the replacement path.

Their initialization, lifetime, mutability, and synchronization requirements are not established. In particular, the table must not be presumed to contain conventional UTF-8 lead-byte masks, and the replacement value must not be presumed to be a particular Unicode character.

There is no identified callee whose global-state or memory-ownership behavior needs to be assumed.

## Acceptance examples

These examples are conditional specifications, not observed executions. Unless stated otherwise, the necessary memory is readable, the output location is writable, and the boundary is placed immediately after the listed input bytes. **R** denotes the value read from replacement-value storage.

### Direct byte

For an initial byte of 0x41:

- The result is 0x41.
- The output cursor advances by one byte.
- The lookup table and replacement value are not needed.

For an initial byte of 0x80, the corresponding result is 0x80 with the same one-byte consumption. The byte is not rejected as an isolated continuation byte.

### Ordinary lookup-based accumulation

For input bytes 0xC2, 0xA2, if the table entry selected by 0xC2 is 2:

- The continuation contributes 34.
- The final accumulator is 162, or 0xA2.
- The result is 0xA2.
- The output cursor advances by two bytes.

This example depends on the stated table entry; the entry’s actual value is not established.

### Non-continuation remains available

For input bytes 0xC2, 0xA2, 0x41, with the same seed of 2:

- The function consumes the first two bytes.
- It reads 0x41 to determine that scanning must stop.
- The result is 0xA2.
- The output cursor points at 0x41, not past it.

### Boundary prevents a continuation read

For a single listed byte 0xC2, if its selected seed is 2:

- The cursor reaches the boundary immediately after the initial read.
- No continuation byte is read.
- The accumulator remains 2 and takes the replacement path.
- The result is R, and the output cursor advances by one byte.

### Low accumulated value

For input bytes 0xC0, 0x80, if the selected seed is zero:

- Both bytes are consumed.
- The final accumulator is zero.
- The result is R.

This differs from a direct initial byte of zero, which returns zero without consulting replacement storage.

### Excluded interval

For input bytes 0xED, 0xA0, 0x80, if the selected seed is 13:

- The accumulator becomes 0xD800.
- All three bytes are consumed.
- The result is R.

### Exact excluded terminal values

For input bytes 0xEF, 0xBF, 0xBE, if the selected seed is 15, the accumulator is 0xFFFE and the result is R.

Changing the last byte to 0xBF produces 0xFFFF and also returns R. In both cases, all three bytes are consumed.

### Value above the Unicode scalar maximum

For input bytes 0xF4, 0x90, 0x80, 0x80, if the selected seed is 4:

- The accumulator becomes 0x110000.
- The result is 0x110000.
- All four bytes are consumed.

No general 0x10FFFF upper-bound rejection is present.

### Long sequence and wraparound

For an initial 0xC0 followed by six 0x80 bytes, if the selected seed is 1:

- All seven bytes are consumed.
- Repeated multiplication by 64 wraps the 32-bit accumulator to zero.
- The result is R.

The scan does not stop merely because the sequence exceeds a conventional encoding length.

No safe empty-input behavior is established. If the initial address equals the boundary, the function still attempts the initial read. After advancing, it may no longer equal the boundary; the boundary is not retroactively enforced.
