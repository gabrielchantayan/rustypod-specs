# F-1488711eb836

## Purpose

The function obtains an opaque value from F-aaf1c55e4172, calls F-be7d4809f6cf with that value and locally prepared storage, and conditionally calls F-db69801a27cf. Its Boolean return reports only whether F-be7d4809f6cf returned something other than −1. It does not independently establish that the follow-on operation succeeded.

## Behavior

### Preparation and provider call

Before calling any dependency, the function captures a 32-bit copy of the fourth argument for later local initialization.

It then calls F-aaf1c55e4172 without explicit arguments and saves its four-byte result as an opaque value. That same saved value is supplied to both later operations if both occur.

There is no visible validation of this value. In particular, the function does not compare it with zero, −1, or another failure sentinel before passing it onward.

The local words are initialized after F-aaf1c55e4172 returns normally:

1. The first word receives the fourth argument.
2. The second word receives the previously captured copy of that argument.

Thus, both words contain the same 32-bit input value immediately before the first operation. The earlier capture does not introduce a second interpretation or transformation of that value.

### Initial operation

The function calls F-be7d4809f6cf once with these arguments, in order:

1. The saved opaque result from F-aaf1c55e4172.
2. The third input argument, unchanged.
3. The address of the first local word.

The returned integer is saved and compared with −1.

The contract does not assume that F-be7d4809f6cf treats the supplied address as read-only, writes a fixed number of bytes, or preserves either local word. Nor does it assume that this dependency preserves globals, pointed-to resources, or other external state.

### Distinguished failure branch

If the initial operation returns exactly −1:

- F-db69801a27cf is not called.
- The second local word is not rewritten by this function after that result.
- The function returns false.

There is no visible retry, explicit cleanup operation, rollback, or attempt to translate another error representation into this result.

False does not imply that the initial operation had no side effects. Any effects performed by either dependency already called remain outside this function’s explicit rollback behavior.

### Conditional follow-on branch

If the initial operation returns anything other than −1, the function:

1. Writes the fourth argument into the second local word again.
2. Calls F-db69801a27cf.
3. Returns true if that call returns normally.

The follow-on dependency receives, in order:

1. The same saved opaque value previously passed to F-be7d4809f6cf.
2. The integer result returned by F-be7d4809f6cf.
3. The same address of the first local word.

The rewrite of the second word occurs after the initial operation and before the follow-on call. Consequently, any change to that word made by the initial operation is overwritten at this point.

There is no corresponding explicit rewrite of the first word. Any modification to that word that remains after the initial operation is therefore presented to the follow-on operation through the same address.

No return value from F-db69801a27cf is inspected. The final Boolean decision remains the comparison of the saved initial-operation result with −1.

### Comparison boundaries

The branch condition is equality with one sentinel, not a general negativity or nonzero test:

- Zero selects the follow-on branch.
- A positive result selects the follow-on branch.
- A representable negative result other than −1 also selects the follow-on branch.
- Only −1 selects the false-return branch.

The visible body performs no arithmetic on the four input words or on the dependency result. It introduces no visible addition, multiplication, range conversion, or overflow boundary beyond the dependency interfaces themselves.
