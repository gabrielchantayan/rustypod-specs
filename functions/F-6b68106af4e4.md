# F-6b68106af4e4

## Purpose

F-6b68106af4e4 scans four numbered positions for the first whose leading 32-bit word is zero. Upon finding one, it writes the first input into that position’s leading word, writes the second input into a corresponding trailing word, and returns the position number. If all four inspected leading words are nonzero, it returns −1 without performing either record write.

The apparent intent is to register a two-word record in a small fixed-capacity table. That intent is inferred, not an independently established API definition. In particular, zero is the only observed availability marker: the function does not reject a zero first input or maintain a separate occupancy flag.

An important distinction governs the actual behavior: leading-word accesses use the table-base value read at each access, while the trailing-word write uses a base value captured at function entry. These addresses identify one record only when the relevant base values agree.

## Interface

### Inputs

The function accepts two inputs, each four bytes wide:

- **First input:** the bit pattern written into the selected leading word.
- **Second input:** the bit pattern written into the selected trailing word.

Neither input is dereferenced, validated, transformed, or compared by this function. The available evidence does not establish whether either word represents an integer, pointer, handle, flag set, or another encoded value.

All 32 bits of each input participate in its corresponding store. No truncation within those four bytes is shown.

### Return value

The reported interface returns an integer:

- **0, 1, 2, or 3:** the position selected by the scan.
- **−1:** all four leading words examined by this invocation were nonzero.

The success value identifies the scan position, not a returned address or an independently allocated resource. The displayed representation uses an integer result; its exact machine-level return convention is not supplied.

### Referenced state and layout

The function uses a global table-base reference. Under the ordinary stable-base interpretation, it addresses four records with the following layout:

| Position | Leading word offset | Trailing word offset |
|---|---:|---:|
| 0 | 0 bytes | 4 bytes |
| 1 | 8 bytes | 12 bytes |
| 2 | 16 bytes | 20 bytes |
| 3 | 24 bytes | 28 bytes |

Each word access is four bytes wide. Records have an eight-byte stride. The entire stable-base region therefore spans 32 bytes.

A leading word equal to zero is eligible for selection. Every nonzero leading-word bit pattern is treated as unavailable. Trailing words do not affect eligibility.

### Preconditions

For normal completion:

- The global base reference must be readable.
- Every leading-word address actually inspected must support a four-byte read.
- If a position is selected, both destination addresses used for its writes must support four-byte stores.
- Address formation must produce valid addresses under the execution environment’s pointer, alignment, and arithmetic rules.

These are access requirements, not validation performed by the function. A fully writable 32-byte table is sufficient under a stable base, but an individual invocation need not access all 32 bytes.

## Behavior

### Initial state capture

Before inspecting any position, the function reads the global table-base reference and retains that value for a possible trailing-word write.

This initial capture occurs even if the scan ultimately finds no available position. It does not itself read any table word.

### Ordered scan

Positions are considered in ascending order: 0, then 1, then 2, then 3.

For each position reached, the function reads the global table-base reference and reads the four-byte leading word at that base plus eight times the position.

If the inspected leading word is nonzero, scanning advances to the next position. The trailing word at that position is neither read nor written.

If the inspected leading word is zero, scanning stops and the successful-write behavior below occurs. No higher-numbered position is inspected afterward.

After four nonzero observations, the function returns −1. There is no fifth probe, wraparound scan, waiting, or retry.

“First available position” therefore means the first position whose leading-word read returns zero during this invocation. It does not imply a consistent snapshot of all four positions.

### Successful writes

For a selected position, the observable record-access order is:

1. Read its leading word and observe zero.
2. Read the global table-base reference again for the leading-word destination.
3. Write the first input to that base plus eight times the selected position.
4. Write the second input to the entry-captured base plus eight times the selected position plus four bytes.
5. Return the selected position number.

The leading word is written before the trailing word. There is no reread of the eligibility word immediately before the leading-word store.

The two destination calculations intentionally remain distinct in this contract. The supplied representation does not use the entry-captured base for the leading-word store, nor does it refresh that captured base for the trailing-word store.

If the global base remains unchanged, both writes target the selected eight-byte record. If it changes between accesses, the eligibility read, leading-word write, and trailing-word write can refer to different regions.

### Zero first input

A zero first input is accepted without a special branch.

With a stable base, selecting an initially zero leading word and storing zero leaves that leading word zero. The second input is still written, and the selected position is returned as a success.

A later invocation can therefore select the same position again, provided its leading word is still zero. Successful return does not by itself establish persistent occupancy.

### Arithmetic and bounds

The position takes only the values 0 through 3 during record access. Consequently:

- The leading-word displacement is one of 0, 8, 16, or 24 bytes.
- The trailing-word displacement is one of 4, 12, 20, or 28 bytes.
- No large-index multiplication or index overflow is required by this scan.

This bounded arithmetic does not establish that adding a displacement to an arbitrary base is safe. Base-address validity, address-width overflow, and alignment behavior remain execution-environment requirements.

## Side effects

A normally completing successful invocation performs two four-byte record stores. A full-table invocation performs no explicit record stores.

The function does not explicitly:

- Clear any other position.
- Initialize or inspect a selected position’s previous trailing word.
- Change the global table-base reference.
- Allocate or release storage.
- Dereference either input as an address.
- Invoke a callback or another function.
- Provide rollback, locking, or an atomic two-word publication.

The first store can become visible before the second. The representation supplies no mechanism ensuring that an observer who sees the new leading word also sees the new trailing word.

If the second store faults after the first succeeds, no compensating write is shown. Fault handling and whether control returns to the caller are outside the established contract.

No ownership transfer is established. Copying an input that happens to encode an address does not prove that the referenced object is retained, owned, or eventually released.
