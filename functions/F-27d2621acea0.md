# F-27d2621acea0

## Purpose

F-27d2621acea0 examines a record’s signed 32-bit discriminator and returns a 32-bit value of either 0 or 1. Certain discriminators permit a secondary lookup and classification sequence. Discriminator 31 additionally permits a special branch that invokes several dependencies and dispatches an operation through the first input object.

The established behavior has two routes to a return value of 1:

- A special discriminator-31 match completes its dependency and dispatch sequence.
- An ordinary lookup succeeds, and a sequence of classification calls avoids three position-specific values.

A return value of 1 does **not** establish that the special operation occurred. The ordinary route can return 1 without invoking either indirect operation or the special branch’s other dependencies.

The business meaning of the discriminator values, lookup keys, classification values, and dispatched operation is unknown. Describing the result as “handled,” “accepted,” or “successful” would be inferred intent rather than an established semantic guarantee.

## Interface

### Inputs

The function receives two address-valued inputs:

1. **Receiver object.** Its first 32-bit word is used as a dispatch-table address, but only when the special discriminator-31 branch matches. That branch resolves an indirect callable at byte offset 184 (`0xB8`) in the table and invokes it with the receiver object and the integer value 16 (`0x10`).

2. **Record.** A signed 32-bit discriminator is read at byte offset 4 from this address on every invocation. The record address is also passed to F-682adfd5a561 when the discriminator permits further processing.

The supplied representation uses 32-bit integers and a 32-bit address layout. The contract therefore treats record fields and dispatch-table entries involved here as four-byte quantities. Porting the behavior to another address width would require an explicit layout decision; native pointer-size substitution is not established by the evidence.

### Output

The return value is a 32-bit quantity:

- **0:** unsupported discriminator, failed ordinary lookup, or a position-specific classification match in the ordinary route.
- **1:** completed special branch, or completion of all three ordinary classification comparisons without their respective matches.

These descriptions apply to normal completion. No recovery behavior is established for invalid memory, failed indirect dispatch, or dependencies that do not return normally.

### Memory and validity preconditions

For every invocation, the record must permit a four-byte read at offset 4.

Additional requirements are path-dependent:

- Lookup results used by the special branch must permit a four-byte read at offset 8.
- A nonzero ordinary lookup result must be valid for the classification dependency.
- A matching special branch requires the object returned by F-938c950e5046, its dispatch table, and its callable entry at offset 360 (`0x168`) to be usable.
- The same branch requires the receiver object, its dispatch table, and its callable entry at offset 184 to be usable.
- The global pointer used near the end of that branch must designate readable storage for the value passed to F-753a92eac2fa.

There are no visible null checks for the record, receiver object, object returned by F-938c950e5046, dispatch tables, or global pointer. A zero lookup result is explicitly handled, but that check does not establish the validity of other nonzero addresses.

The function specifies no buffer lengths, ownership transfer, address-overflow handling, or invalid-input error result.

## Behavior

### 1. Discriminator gate

The first established data access is the signed 32-bit discriminator read at record offset 4.

Only these values proceed:

| Decimal discriminator | Further processing |
|---|---|
| 6, 7, 8, 13, 21 | Ordinary route |
| 31 | Special lookup first; ordinary route if it does not match |

Every other signed 32-bit value returns 0 without invoking a dependency. This includes negative values and positive values outside the listed set.

The discriminator is not visibly read again after this gate. Later dependency mutations of the record therefore do not cause another discriminator decision in the supplied behavior.

### 2. Special processing for discriminator 31

For discriminator 31, the function first invokes F-682adfd5a561 with:

- The record address.
- The lookup key 2688 (`0xA80`).

A zero result fails the special match and proceeds to the ordinary route.

For a nonzero result, the function reads a 32-bit field at byte offset 8 of the returned object and compares it with a 32-bit global comparison value. Equality takes the special branch. Inequality proceeds to the ordinary route.

The lookup result is checked for zero before its offset-8 field is accessed. The supplied expression requires both comparison operands to be obtained after a nonzero lookup result, but does not provide a reliable lower-level ordering between the field read and global-value read.

On equality, the following operations occur in order:

1. F-938c950e5046 is invoked without explicit arguments.
2. Its returned address is treated as an object whose first word supplies a dispatch-table address.
3. The callable at table byte offset 360 is invoked. The supplied representation shows no explicit arguments for this call. Any implicit receiver or other ABI-level argument is unknown.
4. The first indirect call’s 32-bit result is retained.
5. F-7e4f952e879e is invoked without explicit arguments, producing another 32-bit result.
6. F-6aba4518acf0 is invoked with the result from F-7e4f952e879e first and the earlier indirect-call result second.
7. A value is obtained through a global pointer and passed to F-753a92eac2fa.
8. The receiver object’s current dispatch table is used to invoke the callable at byte offset 184, with the receiver object and the integer 16 as explicit arguments.
9. The function returns 1.

No ordinary lookup or classification call occurs on this matching branch.

The order matters. In particular, the global-pointer-based argument is obtained after F-6aba4518acf0 returns, and the receiver’s dispatch information is obtained after F-753a92eac2fa returns. The function does not visibly capture either of those values before the earlier calls. Dependencies must not be assumed to preserve the relevant globals or object fields.

The return values of F-6aba4518acf0, F-753a92eac2fa, and the final indirect invocation do not participate in a visible decision. If these calls return normally, the branch returns 1 regardless of those values.

### 3. Ordinary lookup

The ordinary route is reached for discriminators 6, 7, 8, 13, and 21, and for discriminator 31 when its special match fails.

It invokes F-682adfd5a561 with:

- The record address.
- The lookup key 2560 (`0xA00`).

A zero result causes an immediate return of 0. No classification call follows that result.

For discriminator 31, this is a separate lookup after the special lookup. A zero or mismatching special lookup result neither supplies nor substitutes for the ordinary lookup result.

### 4. Ordered classification checks

A nonzero ordinary lookup result is passed to F-11c1b7e655b3. The function may invoke that dependency up to three times, always passing the same lookup-result address.

The calls and decisions are:

| Call position | Compared value | Result if equal | Result if unequal |
|---|---:|---|---|
| First | 74 (`0x4A`) | Return 0 | Make second call |
| Second | 75 (`0x4B`) | Return 0 | Make third call |
| Third | 76 (`0x4C`) | Return 0 | Return 1 |

These are three separate invocations, not one invocation whose result is compared against a set.

Consequently, the observable rule is position-dependent. A first result of 75 does not stop processing. A second result of 74 does not stop processing. A third result of 75 permits a return of 1, provided the preceding checks also permitted continuation.

If F-11c1b7e655b3 is stable for a given input throughout the sequence, the result is 0 for a stable value of 74, 75, or 76 and 1 for any other stable value. Stability is not established, so this simplified interpretation is conditional only.

## Side effects

### Direct memory effects

The supplied body contains no direct writes to caller memory or global storage. Its visible memory operations are reads needed for:

- The record discriminator.
- The special lookup result’s offset-8 field.
- The global comparison value.
- Dispatch-table resolution.
- The global-pointer-based argument.

This does not make the function side-effect-free. Every invoked dependency, including F-11c1b7e655b3, may have effects not specified here.

### Call sequencing and state

Observable dependency activity varies by path:

- Unsupported discriminator: no dependency calls.
- Ordinary lookup failure: one lookup call.
- Ordinary classification: one lookup call and one to three classification calls.
- Discriminator 31 with no special match: an additional special lookup before ordinary processing.
- Discriminator 31 with a special match: the special lookup followed by the ordered special sequence, with no ordinary processing.

No rollback or compensating action is visible. If a dependency changes state before a later failure or abnormal exit, restoration is not established.

### Ownership and lifetime

The function does not visibly allocate, copy, retain, or release an object through an operation whose ownership semantics are established.

Passing an address to a dependency does not prove that ownership is retained or transferred. In particular, nothing here establishes whether a dependency mutates, consumes, releases, or preserves its arguments or global state.

The body reuses the ordinary lookup address across successive classification calls without visibly refreshing it. Correct execution therefore requires that address to remain usable whenever a later call is reached. Whether the dependency guarantees this is documented_only.

## Acceptance examples

These are conditional static acceptance examples, not results of executed tests. All require valid memory and normal return from every dependency actually reached.

4. **Second classification stop.**

5. **Third classification stop.**

6. **Position-dependent continuation.**  
   Given discriminator 7 and classification results 75, 76, then 74, the result is 1. None equals the prohibited value at its own call position.

7. **Special lookup miss with ordinary success.**  
   Given discriminator 31, a zero key-2688 lookup result, a nonzero key-2560 lookup result, and classification results 0, 0, 0, the result is 1. The special indirect operations do not occur.

8. **Special comparison mismatch.**  
   Given discriminator 31 and a nonzero special lookup result whose offset-8 field differs from the global comparison value, ordinary processing follows. A zero ordinary lookup result then produces 0.

9. **Special match.**  
   Given discriminator 31 and equality in the special comparison, the ordered special sequence occurs and the result is 1. The key-2560 lookup and all classification calls are skipped.

10. **Late global observation.**
