# F-142d16d49d0b

## Purpose

The represented function performs an ordered sequence of indirect calls and memory accesses. It writes one 32-bit value, obtains two 32-bit data words from dependencies, and uses selected portions of those words in four byte writes. Each byte-write destination is determined by a freshly read unsigned selector byte.

No application-level purpose is established. The accesses are not identified as serialization, buffer management, device operations, or protocol processing.

The represented path has no ordinary return. After the last indirect call returns, the static representation ends at an invalid-instruction boundary. Because the supplied material warns about invalid instruction data, this contract describes the represented path without claiming that it completely reconstructs executable behavior.

## Interface

### Explicit input and additional entry state

The explicit input is one signed 32-bit integer, called the **input index**. Four times this value contributes both to the initial write address and to the explicit argument of D01.

Two additional signed 32-bit values are obtained from entry state:

- The **entry register value** supplies the initial stored value and the base calculation for the first three selector reads.
- The **entry link value** contributes to D01’s indirect-call target.

The provenance, initialization, and calling-convention meaning of these additional values are unresolved. No validation of any input or entry-state value is represented.

### Widths and address expressions

The representation distinguishes:

| Value or operation | Width and interpretation |
|---|---|
| Input index and additional entry-state values | Signed 32-bit |
| Two data words returned by dependencies | Unsigned 32-bit |
| Two forwarding words returned by dependencies | Signed 32-bit |
| Two other forwarded results | Opaque 32-bit |
| Selector reads | Unsigned 8-bit |
| Initial memory write | 32-bit |
| Four subsequent memory writes | 8-bit each |

The **entry destination** is the integer address expression:

**4 × input index + 0x14.**

The **saved selector base** is:

**entry register value × 0x80000.**

The first three selector reads use the address derived from that base plus one. The base is retained, but the selector byte is read separately on each occasion.

These input- and entry-state-derived expressions use represented signed 32-bit arithmetic. Their behavior outside the representable signed range is not established. In particular, they must not silently be assigned an unsigned-wrap rule.

Every selector is between zero and 255. Its corresponding byte-write destination is the integer address **selector + 0x11**, ranging from `0x11` through `0x110`, inclusive. This addition does not overflow a 32-bit integer.

These are integer address expressions, not established offsets within an allocation. Address width, integer-to-address conversion, accessibility, and applicable alignment rules remain separate questions.

### Unsigned data arithmetic

For either unsigned 32-bit data word:

- A left shift by two retains the low 32 bits.
- The byte written from that shift is the low eight bits of four times the word.
- Masking with `0x3FFFFFFF`, shifting right by 20, and narrowing to a byte selects original bits 20 through 27.

The fourth selector’s integer address is:

**((second data word × 8) + 1) modulo 2^32.**

Both arithmetic operations have unsigned 32-bit semantics. However, only the multiplication can actually overflow:

- Its reduced result is a multiple of eight between `0x00000000` and `0xFFFFFFF8`.
- Adding one therefore produces a value between `0x00000001` and `0xFFFFFFF9`, without overflow.
- The final integer address is always congruent to one modulo eight.

The modulo formula remains correct even though the addition never needs reduction. It does not establish that the resulting address is accessible.

## Behavior

The first explicit memory operation writes the 32-bit entry register value to the entry destination. No preceding bounds, accessibility, or alignment check is represented.

D01 is then called through a target derived from the entry link value plus `0xFFE`. Its explicit argument is four times the input index.

After D05 returns, the saved selector base is calculated from the entry register value. The first selector read then uses that base plus one.

The following calls occur after this write:

| Call site | Explicit relationship |

### Second selector read and byte write

After D12 returns, the function reads another unsigned byte at the same saved-base-derived address. This is a fresh memory read, not reuse of the first selector.

The second byte write uses bits 20 through 27 of the first data word. Its destination is `0x11` plus the newly read selector.

The first forwarding word does not supply this byte. It is instead used by the following call group:

1. D13 receives the first forwarding word shifted left by two.

### Third selector read and byte write

After D17 returns, the function performs a third unsigned-byte read at the saved-base-derived address. The result is retained as the **third selector**.

The function writes the low eight bits of four times the second data word to `0x11` plus the third selector.

The subsequent calls are:

| Call site | Explicit relationship |

### Fourth selector read and byte write

After D24 returns, the function derives a new selector address from the retained second data word:

**((second data word × 8) + 1) modulo 2^32.**

The multiplication may wrap. The addition cannot overflow because the multiplication result is at most `0xFFFFFFF8`.

The function reads an unsigned byte through the address converted from this integer value. This address is independent of the saved selector base, although the two addresses can coincide for particular states.

The fourth byte write uses bits 20 through 27 of the second data word. Its destination is `0x11` plus this fourth selector.

The final calls are:

1. D25 receives the second forwarding word shifted left by two.
2. D26, D27, D28, and D29 execute in order without explicit arguments.

The signed-shift uncertainty applicable to D13 also applies to D25.

If D29 returns to the represented continuation, the path reaches an invalid-instruction boundary, not an established normal return.

### Observable ordering and aliasing

The explicit access order is:

1. Initial 32-bit write.
2. First selector read, then first byte write.
3. Second selector read, then second byte write.
4. Third selector read, then third byte write.
5. Fourth selector read, then fourth byte write.

The dependency calls intervene exactly as described above. Their internal reads, writes, and other effects are unknown and are not included in this access list.

No non-aliasing guarantee is established. The initial write, selector locations, and byte-write destinations can overlap. Earlier writes may therefore change later selector values. Dependencies may also change memory between selector reads.

Consequently:

- The first three selector reads cannot be replaced by one cached read merely because their address expression is unchanged.
- The fourth read cannot be replaced by the third selector even when the two address expressions resolve to the same location.
- If byte-write destinations coincide, later writes follow earlier writes in the stated order; this does not make the earlier accesses removable, particularly where memory has observable access semantics.

## Acceptance examples

These are conditional consequences of the static representation, not observed executions. Each assumes permitted accesses, meaningful address conversions, returning dependencies where needed, and defined interpretation of the signed arithmetic used.

### Entry write occurs before calls

For input index three and entry register value two:

- The initial write stores the 32-bit value two at integer address `0x20`.
- D01 subsequently receives 12.
- The saved selector base calculated after D05 is `0x100000`.
- The first three selector reads use integer address `0x100001`.

Moving D01 before the initial write would violate the represented order.

### First data-word extraction

If D05 supplies `0x12345678`, the first selector is `0x20`, and the second selector is `0x30`:

- The first byte write stores `0xE0` at `0x31`.
- D06 receives `0x48D159E0`.
- The second byte write stores `0x23` at `0x41`.

The second byte is the field starting at bit 20, not the most significant byte and not a value derived from D12.

### Fresh selector reads observe changes

If the first saved-base-derived read yields `0x20`, and an intervening dependency changes that location to `0x30`, the first two byte-write destinations are `0x31` and `0x41`.

Reusing the first selector would violate the represented behavior. The same requirement applies when a preceding explicit write changes the selector location through aliasing.

### Third selector forwarding and independent fourth address

If D17 supplies `0x00100001`, the third selector is `0xFF`, and the later read at `0x00800009` yields `0x02`:

- The third write stores `0x04` at `0x110`.
- D18 receives 255.
- The fourth selector is read at `0x00800009`.
- The fourth write stores `0x01` at `0x13`.

D18 does not receive `0x04`, and the fourth destination does not reuse `0xFF`.

### Multiplication wraps; addition does not

If D17 supplies `0x20000000`:

- The mathematical product by eight is `0x100000000`.
- Unsigned 32-bit multiplication reduces that product to zero.
- Adding one produces `0x00000001` without overflow.

The fourth selector read therefore uses the address converted from `0x00000001`, not from `0x100000001`. If that read is permitted and yields `0x02`, the fourth byte write stores zero at `0x13`.

If D17 instead supplies `0xFFFFFFFF`:

- Unsigned 32-bit multiplication by eight wraps to `0xFFFFFFF8`.
- Adding one produces `0xFFFFFFF9` without wrapping.

For comparison, `0x1FFFFFFF` produces the same final integer address, `0xFFFFFFF9`, but its multiplication by eight does not overflow. These cases distinguish modulo arithmetic semantics from an operation actually overflowing.

No second data word makes the subsequent addition of one overflow: its input is always a multiple of eight no greater than `0xFFFFFFF8`.

### Forwarding words remain separate

If D12 supplies seven and D24 supplies nine, D13 receives 28 and D25 receives 36.

Neither forwarding word replaces a data word used by the byte writes. Opaque results supplied by D07 and D19 are passed unchanged to D08 and D20, respectively.

### Failure and final continuation

If the first selector read cannot complete, the initial write and D01–D05 precede that attempted read. No rollback is represented.

If D29 returns, acceptance must not require normal successful return. The represented continuation reaches the invalid-instruction boundary.
