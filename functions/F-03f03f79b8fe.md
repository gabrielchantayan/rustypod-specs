# F-03f03f79b8fe

## Purpose

F-03f03f79b8fe conditionally produces a record for a nonzero, unsigned 32-bit selector. It first checks the selector against two unsigned 16-bit bounds in an indirectly referenced structure. For an accepted selector, it obtains a mapped index and then selects one of three output paths:

- A call requesting transfer of a 20-byte record.
- Expansion of an 8-byte record containing four signed 16-bit values into selected fields of a larger output area.
- Construction of selected output fields using the mapped index and a signed 16-bit step.

The function returns a 32-bit value of zero for a rejected selector and one after executing an accepted output path. A return value of one does not independently validate the mapped index, source storage, destination capacity, or the external transfer operation.

**Inferred intent:** the function appears to retrieve or synthesize a record from a bounded table-like context. Record meanings, selector meanings, and application-level field names are not established.

## Interface

### Inputs

The interface has three arguments:

| Argument | Representation | Role |
|---|---|---|
| Context | 32-bit address-bearing value | Identifies the structure containing bounds, mode fields, and dependency-specific state. |
| Selector | Unsigned 32-bit integer | Value to check against the inclusive bounds. |
| Output | Address of writable storage | Receives either a requested 20-byte transfer or several individual field writes. |

The supplied representation uses 32-bit integers and address-bearing values, 16-bit halfwords, and 8-bit bytes. Byte order is not specified by the supplied evidence.

### Context layout used directly

Offsets are byte offsets from the context address.

| Offset | Width | Interpretation |

| 78 | 8 bits | Zero selects stored-record handling; any nonzero value selects synthetic handling. |

The indirectly referenced bounds structure has:

| Offset | Width | Interpretation |
|---|---:|---|

These are observed access locations, not a complete declaration of either structure.

### Output layout

In compact-record and synthetic handling, the function directly writes the following fields:

| Output offset | Width | Compact-record value | Synthetic value |
|---|---:|---|---|
| 0 | 32 bits | Sign-extended first source halfword | Mapped index multiplied by the signed step |
| 4 | 32 bits | Sign-extended second source halfword | Product plus a separately read signed step |
| 12 | 16 bits | Third source halfword, unchanged bit pattern | Context halfword at offset 80, unchanged bit pattern |
| 16 | 16 bits | Fourth source halfword, unchanged bit pattern | Zero |

Those paths do not directly write output bytes 8–11, 14–15, or 18–19. They must not be described as initializing a complete 20-byte record.

The transfer path supplies the output address, a computed source address, and a length of 20 to an external dependency. The actual destination effects of that call depend on the external dependency’s undocumented contract.

### Result and preconditions

The result is a 32-bit zero or one on a normally completed path.

For accepted selectors, the output must support all accesses required by the chosen path. Compact and synthetic handling directly access bytes through output offset 17. The transfer path requests an operation of length 20.

The function performs no explicit null, alignment, address-range, capacity, index, or arithmetic-overflow checks. Invalid accesses and dependency failures have no specified local recovery behavior.

A zero selector returns before dereferencing the context or output. Other rejected selectors require valid storage for the bound reads they reach, but the function itself does not directly dereference the output on those rejection paths.

## Behavior

### 1. Reject zero and check the bounds

A selector of zero returns zero immediately, regardless of the context’s bounds.

For any other selector:

1. The function reads the bounds-structure address from context offset 92.
2. It reads the unsigned 16-bit lower bound at offset 8 in that structure and widens it for comparison with the full unsigned 32-bit selector.
3. If the selector is below that lower bound, it returns zero.
4. Otherwise, it reads the bounds-structure address from context offset 92 again and reads the unsigned 16-bit upper bound at offset 10.
5. If the selector exceeds the upper bound, it returns zero.

Both bounds are inclusive. There is no truncation of the selector before either comparison.

The repeated bounds-pointer access is part of the supplied operation order; the evidence does not establish one captured pointer shared by both bound reads. No dependency call occurs between these checks.

Any selector greater than 65,535 is rejected: it necessarily reaches the upper-bound comparison and exceeds every possible unsigned 16-bit upper bound. If the lower bound exceeds the upper bound, no selector can pass both comparisons. Zero remains rejected even when both bounds include it.

### 2. Obtain the mapped index

After both comparisons succeed, the function invokes F-28e2b31af69c with:

- The context.
- The low 16 bits of the selector minus the previously read lower bound.

For an accepted selector, that difference is already between zero and 65,535, so the explicit low-16-bit operation does not change its numeric value.

The returned value is consumed as a signed 32-bit mapped index. No validity or sign check follows. Negative values are not treated as errors locally.

The function then reads the mode byte at context offset 78. Because this read occurs after F-28e2b31af69c, mode changes made by that dependency can affect the selected output path. The evidence does not establish that the dependency preserves any context fields or global state.

### 3. Stored-record handling

If the mode byte is zero, the function next reads the 16-bit field at context offset 4.

#### Field equals 5: transfer path

The function calls F-ebfca7dad86d with the context and treats its return value as a base address. It computes a source address using a stride of 20 bytes and the mapped index.

It then calls the unidentified external transfer dependency with these arguments, in order:

- Output address.
- Computed source address.
- Length 20.

After that dependency returns normally, F-03f03f79b8fe returns one. It does not inspect a result from the transfer dependency.

The stride is fixed at 20; it is not read from the context. The equality-to-5 decision occurs before F-ebfca7dad86d is called and is not repeated afterward.

A conventional 20-byte copy is the apparent intent, but the supplied evidence establishes the call and its arguments, not the external operation’s complete semantics.

#### Field does not equal 5: compact expansion

The function calls F-ebfca7dad86d with the context and treats its return value as a base address. It computes a source address using an 8-byte stride and the mapped index.

The source record comprises four consecutive signed 16-bit fields at source offsets 0, 2, 4, and 6. The observable direct-access sequence is:

1. Read the first source halfword, sign-extend it to 32 bits, and write output offset 0.
2. Read the second source halfword, sign-extend it to 32 bits, and write output offset 4.
3. Read the third source halfword and write its 16-bit representation at output offset 12.
4. Read the fourth source halfword.
5. Write that fourth halfword’s representation at output offset 16.
6. Return one.

The source record is not copied into temporary storage as a whole before destination writes begin. If the source and destination overlap, an earlier destination write can affect a later source read. The function supplies no overlap protection.

### 4. Synthetic handling

If the mode byte is nonzero, the function does not call F-ebfca7dad86d and does not consult the field at context offset 4.

The direct read/write order is:

1. Read the raw 16-bit value at context offset 80 and write it to output offset 12.
2. Read context offset 80 again, this time as a signed 16-bit step.
3. Multiply the mapped index by that signed step, producing the 32-bit intermediate used for the following fields.
4. Write the product at output offset 0.
5. Read context offset 80 again as a signed 16-bit step.
6. Add this newly read step to the saved product and write the result at output offset 4.
7. Write a zero halfword at output offset 16.
8. Return one.

These separate step reads matter. If output storage aliases the context, the write at output offset 12 can affect the step used by the multiplication, and the write at output offset 0 can affect the step used by the addition. The copied halfword, multiplication step, and addition step are not established as one immutable snapshot.

For a stable, nonoverlapping context and output, the first two 32-bit fields represent the mapped index times the step and that product plus the step.

### Arithmetic limits

The index, multiplication intermediates, additions, and address-bearing values are represented at 32-bit width. Source halfwords used arithmetically are signed values from −32,768 through 32,767.

The function contains no explicit overflow checks. The supplied representation does not establish a portable signed-overflow policy. Ordinary mathematical descriptions of the product, sum, or record address apply without qualification only when those calculations remain representable and the resulting addresses are valid.

In particular, an accepted selector does not prove that either the 8-byte or 20-byte indexed source address is valid.

## Side effects

Direct effects are limited to the documented reads and output writes, but transitive effects are not limited by the available evidence.

- Rejected selectors cause no dependency calls and no direct output writes.
- Every accepted selector invokes F-28e2b31af69c before reading the mode byte.
- Stored-record handling additionally invokes F-ebfca7dad86d.
- The field-equals-5 path also invokes the external transfer dependency.
- Compact and synthetic handling leave the unlisted output bytes untouched by their direct stores.
- No direct allocation or release operation is visible.
- No direct global-variable access is visible.

These observations do not establish that dependencies avoid allocation, release, global mutations, context mutations, or additional output effects. Memory ownership and lifetime obligations remain unspecified beyond the need for valid storage during each reached access.

There is no rollback protocol. If an access or dependency fails after earlier effects, the function provides no visible mechanism to undo those effects.

## Acceptance examples

These are conditional contract examples, not executed tests. Unless an example concerns aliasing, assume valid, nonoverlapping storage, normally returning dependencies, stable fields, and representable arithmetic.

1. **Zero bypasses all storage access.**  
   Selector zero returns zero without reading the context, invoking dependencies, or writing the output.

2. **Inclusive bounds.**  
   With lower bound 10 and upper bound 12, selectors 10, 11, and 12 proceed to F-28e2b31af69c with normalized values 0, 1, and 2 respectively. Selectors 9 and 13 return zero without a dependency call or output write.

3. **Full-width selector comparison.**  
   With bounds 0 and 65,535, selector 65,536 returns zero. It is not truncated to zero for bounds checking.

4. **Signed compact expansion.**  
   Suppose stored-record handling selects compact expansion, the mapped index is 2, and the selected source halfwords are −2, 30, −7, and 9. The source begins 16 bytes after the returned base. Output offsets 0 and 4 receive signed 32-bit values −2 and 30. Offsets 12 and 16 receive the 16-bit representations of −7 and 9. Unlisted output bytes retain their previous values unless affected through aliasing or dependency side effects.

5. **Negative synthetic step.**  
   With a nonzero mode byte, mapped index 3, and stable step −4, output offset 0 receives −12, offset 4 receives −16, offset 12 receives the raw representation of −4, and offset 16 receives zero. F-ebfca7dad86d is not called.

6. **Transfer-path success is not independently checked.**  
   With zero mode, the field at context offset 4 equal to 5, and mapped index 2, the external dependency receives a source address 40 bytes after the returned base and length 20. If the dependency returns normally, this function returns one without checking a transfer result. Actual copied bytes require the dependency’s contract.

7. **Dependency mutation affects mode selection.**  
   If F-28e2b31af69c changes the mode byte from zero to nonzero before returning, the subsequent path is synthetic handling.

8. **Aliasing prevents snapshot assumptions.**  
   If a compact-record destination write overlaps a source halfword not yet read, later output values must reflect the specified access order, not an assumed pre-write snapshot of all four source fields.
