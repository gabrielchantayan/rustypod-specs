# F-7b8695fe16b3

## Purpose

F-7b8695fe16b3 synchronously dispatches a notification through a selected range of object references. After traversal finishes, it conditionally invokes F-d8a0e1b087cc with the collection base and buffer address.

The additional invocation requires all three conditions:

- The selector equals zero.
- The size value equals 20.
- The first buffer byte, inspected after traversal, is one of {0, 1, 2, 3, 4, 5, 6, 8, 9, 10, 11}.

Every execution that reaches a normal return produces the 32-bit value 1. This value does not distinguish an empty range, completed dispatch, skipped additional invocation, or completed additional invocation.

Traversal is not a snapshot operation. The endpoint is consulted again at successive traversal checks, and entries are read as they are visited. Dependencies may change either. Valid storage and normally returning dependencies alone do not guarantee that every initially selected entry is visited, or that a later entry still identifies its original receiver.

The dispatch and classification behavior is established by static evidence. Interpretations such as an event system, a message format, or a semantic meaning for the value 20 are not established.

## Behavior

### Descriptor selection

The function first selects the descriptor using the collection base and selector at a 12-byte stride. It then reads the initial cursor from the descriptor’s first word.

The descriptor address remains the selected descriptor address throughout the operation. The initial cursor is loaded once. A later change to the descriptor’s first word does not itself restart traversal or replace the local cursor.

The represented descriptor calculation uses 32-bit integer operands. The evidence does not establish a portable rule for signed overflow, address wraparound, or calculations outside valid storage. Defined normal behavior must not be assumed for an invocation whose descriptor calculation relies on such cases.

### Traversal checks and advancement

Before each possible callback, the function reads the selected descriptor’s endpoint field and compares it with the current cursor.

- Equality ends traversal.
- Inequality causes the current entry to be visited.
- After the callback returns normally, the cursor advances by four bytes.
- The advanced cursor is compared with the endpoint read for the next check.

Termination uses equality, not ordering. The function does not require or verify that the endpoint is numerically greater than the cursor. It does not check that the initial distance is a multiple of four.

The endpoint is not captured as an immutable initial bound. If a callback changes it, the next traversal check uses the changed field value. An initially nonempty range can therefore stop after fewer visits than its initial contents suggest. Extending or otherwise moving the endpoint may also change later traversal, subject to storage validity and eventual equality.

With a stable endpoint and valid reachable entries, visited entry addresses advance in four-byte steps. This is an ordering of entry addresses, not a guarantee about the identities initially stored there. Each later receiver depends on the entry value observed when that entry is visited.

### Callback lookup and invocation

For each visited entry, the function obtains the receiving object address, obtains its dispatch table through the object’s first word, and resolves the callback from the table slot at byte offset 4.

The callback receives these five logical arguments:

1. Receiving object address.
2. Original selector value.
3. Original context value.
4. Original buffer address.
5. Original size value.

Invocation is synchronous. The callback must return normally before cursor advancement and the next traversal check.

Callback return values do not control traversal and are not accumulated into the function’s result. No result-based early exit is shown.

No copy of the range, object contents, or buffer contents is made before dispatch. Dependencies can affect later behavior by changing shared storage. In particular:

- Changing the endpoint can alter whether another entry is visited.
- Changing a not-yet-visited entry can replace its eventual receiver.
- Changing an object or dispatch table can affect later callback resolution.
- Changing the first buffer byte can affect the post-traversal decision.

The evidence establishes the lookup dependencies, but not a complete machine-level ordering or exact count of repeated loads used to resolve a callback. It does not establish synchronization for concurrent mutation.

### Post-traversal gate

The selector and size checks occur only after traversal finishes.

If the selector is nonzero, the function returns 1 without directly inspecting the buffer byte or invoking F-d8a0e1b087cc.

If the selector is zero but the size value is not 20, the function likewise returns 1 without that direct byte inspection or additional invocation.

Neither condition suppresses traversal. On these paths, dependencies invoked during traversal may still inspect or modify the buffer.

When the selector is zero and the size value is 20, the function reads the first byte at the buffer address. This is the byte present after the callbacks have returned, not a pre-dispatch snapshot.

If this dependency returns normally, the function returns 1. Its result does not determine the caller’s result.

### Invalid or abnormal execution

### Dependency effects and state preservation

Neither dependency class is established to preserve globals, descriptor fields, range entries, objects, dispatch tables, or buffer contents.

4. **Nonzero selector with a stable two-entry range.**

Without endpoint stability, the second visit is not guaranteed.

5. **Size mismatch with stable traversal state.**  
   The selector is zero and size is 19. The endpoint and relevant not-yet-visited entries remain unchanged, and the initial valid range reaches its endpoint by four-byte advances. Every entry in that range is visited. No post-traversal buffer-byte read or additional invocation occurs. Without these stability assumptions, the callback sequence must instead be determined from subsequent endpoint checks and entry reads.

6. **Callback changes classification.**  
   The selector is zero, size is 20, and traversal terminates normally. The buffer starts with 7, but a callback changes it to 8 and it remains 8 until inspection. F-d8a0e1b087cc is selected. If the byte instead changes from 8 to 7 and remains 7 until inspection, the additional invocation is skipped.

   Two consecutive entries initially contain the same object address. The endpoint stays unchanged, and both entries retain that address until their respective visits. The receiver receives two separate callback invocations. The callback targets need not be identical if dispatch-table state changes.    Two consecutive entries initially identify the same receiver. The first callback leaves the endpoint unchanged but replaces the second entry with another valid receiver address. If that value remains until the second visit, the second callback is directed to the replacement receiver. No deduplication or receiver snapshot prevents this.

9. **Endpoint shortened.**  
   The first callback sets the endpoint to the address the cursor reaches after its four-byte advance. The next check observes equality and ends traversal, even if the initial range contained more entries.

10. **Initial-cursor field replaced.**  
    A callback changes only the descriptor’s initial-cursor field. Traversal continues from its existing local cursor after the ordinary advance; it does not restart from the replacement field value.

11. **Unused buffer on a nonqualifying empty range.**  
    The initial cursor equals the endpoint and the selector is nonzero. No callback occurs, and this function does not directly dereference the buffer address. This establishes no buffer-validity exemption for paths that invoke dependencies or inspect the byte.
