# F-070a473cf47a

## Purpose

F-070a473cf47a invokes one dependency using an address-like value derived from a field in the supplied object, selects a 32-bit result according to the dependency’s return value, and then clears one byte in the supplied object.

The established behavior is narrow:

- Read a 32-bit field at byte offset 12 from the supplied base.
- Add 4 to that field’s value and pass the result to F-682a0c9a8e8e.
- If the dependency returns the 32-bit value interpreted as −1, select the current contents of a global 32-bit slot. Otherwise, select zero.
- Write zero to the byte at offset 28 from the supplied base.
- Return the selected 32-bit value.

The meaning of the object, its field, the cleared byte, and the global slot is not established. In particular, the evidence does not establish that the dependency performs cleanup, that the byte is a validity flag, or that the global slot contains an error code.

- Zero when F-682a0c9a8e8e returns anything other than −1.
- The value read from a global 32-bit slot when F-682a0c9a8e8e returns −1.

The return value is not necessarily the dependency’s return value. Even on the −1 branch, the selected global value may itself be zero. Therefore, the outer function’s return value alone does not necessarily reveal which branch was taken.

## Behavior

### Established observable order

On an execution that completes normally, the direct operations occur in this order:

1. The function reads the 32-bit field at offset 12 from the supplied base.
2. It forms a dependency argument by adding 4 to the value just read.
3. It calls F-682a0c9a8e8e once with that derived argument.
4. It examines the dependency’s returned value.
5. If that value is −1, it reads the global 32-bit slot and selects that value as its result. Otherwise, it selects zero without directly reading that slot.
6. It writes a zero byte at offset 28 from the original supplied base.
7. It returns the selected result.

The field at offset 12 is read before the dependency call. There is no second direct read of that field afterward. A dependency-side change to the field therefore does not cause the already-issued argument to be recomputed.

The global-slot read, when required, occurs after the dependency returns. It is not a snapshot taken before the call. A change to that slot during the dependency call can affect the returned value.

The zero-byte write occurs after result selection. When the global slot is read, its selected value is captured before that final write.

### Derived dependency argument

The dependency receives the value stored at offset 12 plus 4. It does not receive the location of that field plus 4, nor does it necessarily receive the caller’s base plus a fixed offset.

This distinction matters when constructing acceptance conditions: the contents of the field determine the argument. The evidence does not establish that the contents denote an allocated object, that adding 4 skips a header, or that the resulting value is a valid address.

### Conditional result selection

Only the exact dependency result −1 selects the global-slot value. Other negative results, zero, and positive results all select zero.

There is no additional classification of dependency results, no retry, and no second dependency call in the visible behavior.

### Final byte clear

Both result-selection branches lead to the same one-byte zero write at offset 28.

The direct store affects one byte, not a 32-bit field. The function does not directly clear adjacent bytes or restore the previous value. This guarantee applies only when execution reaches the store and the destination remains writable.

If the dependency does not return normally, the evidence does not establish that the final store or outer return occurs.

## Side effects

The function has one unconditional direct write on its normal-return path: zero to the byte at offset 28 from the original base.

It also performs:

- One direct 32-bit read at offset 12.
- One call to F-682a0c9a8e8e.
- One conditional direct 32-bit read from a global slot.

The dependency may introduce other reads, writes, lifetime changes, or control-flow effects. None are specified here, and the dependency must not be assumed to preserve the supplied object or global state.

### Ownership and lifetime

No direct allocation, release, retain, or ownership transfer is visible in this function. Passing the derived value to the dependency does not establish any ownership rule.

For normal completion, the destination byte must remain writable after the dependency returns. If the dependency invalidates the object containing that byte, the subsequent store is not protected by any visible lifetime check.

### Aliasing

No non-aliasing guarantee is supplied.

If the final byte store overlaps the global result slot, the selected return value still reflects the slot’s value before that store. The store may then alter the overlapping global storage without changing the already-selected result.

If the dependency modifies the byte at offset 28 and returns normally, this function subsequently overwrites that byte with zero, provided the destination is still valid.

These observations follow from the visible ordering. They are not claims about which aliases occur in actual use.
