# F-7a78703416b1

## Purpose

F-7a78703416b1 performs a short, ordered state transition around two dependency calls and translates the second dependency’s result into a two-valued status.

On an ordinary completed execution, it:

- Captures a globally supplied state-object base.
- Reads and writes back a 32-bit field at byte offset +16.
- Sets a 32-bit state field at byte offset +8 to 1.
- Calls F-81f744505b98 with the caller’s argument and the value 1.
- Sets the same captured object’s state field to 2.
- Clears three bits in a 32-bit field at byte offset +24.
- Calls F-2706939fe3c5 with the caller’s argument and a separately obtained global value.
- Returns 0 if that call returns exactly 3; otherwise returns 89.

These are established operations in the supplied static representation. The meanings of the object, its fields, the two dependencies, and the returned status codes are not established. In particular, interpreting the values 1 and 2 as named lifecycle states, or interpreting 0 and 89 as success and failure, would be inferred intent rather than a demonstrated interface guarantee.

## Behavior

### 1. Capture the state-object base

Before either dependency call, the function reads the global state-object base and retains that value for subsequent writes at +8 and the read-modify-write at +24.

This captured base is significant. If F-81f744505b98 changes the global state-object base and returns, the later accesses at +8 and +24 still target the previously captured object. The function does not visibly refresh that captured base after the call.

This is a statement about address selection, not object validity. If the dependency releases or invalidates that object, the later accesses may no longer be valid.

### 2. Read and write back the field at +16

Before setting the state field to 1, the function visibly reads a 32-bit value at offset +16 through the global state-object base and writes that value back through an address derived from that global base.

When the global base is stable during this operation, the same field receives the same 32-bit value. Its final ordinary-memory contents are therefore unchanged by this assignment.

The operation is nevertheless present as a read and a write in the supplied representation. It must not be treated as a contractually absent access merely because the value is unchanged. Such accesses may matter for special memory, access faults, or external observers.

The addresses in this assignment are expressed through the global base, rather than solely through the retained base used later. With a stable global base, both refer to the same object. The supplied evidence does not define behavior when another execution agent changes that global during the assignment, nor does it establish an atomic snapshot spanning the global accesses.

### 3. Set the captured object’s state field to 1

The function writes the 32-bit value 1 at offset +8 of the captured object.

This is a full-width replacement, not a bitwise update. The prior value of that field is not preserved by this write.

The write occurs before the call to F-81f744505b98.

### 4. Call F-81f744505b98

1. The original opaque 32-bit argument.

### 5. Set the captured object’s state field to 2

After F-81f744505b98 returns, the function writes the 32-bit value 2 at offset +8 of the captured object.

This overwrites any value currently present in that field, including a value written there by the first dependency. It still uses the original captured base, even if the global state-object base has changed.

The write occurs before the flags update at +24 and before F-2706939fe3c5 is called.

### 6. Clear three bits in the captured object’s flags field

The function reads the current 32-bit value at offset +24 of the captured object, applies a bitwise AND with hexadecimal 0xFFFFEFF3, and writes the 32-bit result back to that field.

Numbering bits from zero at the least significant bit, the update clears:

- Bit 2, represented by 0x00000004.
- Bit 3, represented by 0x00000008.
- Bit 12, represented by 0x00001000.

All other bits retain their values from the read used for this update. Equivalently, the combined cleared-bit mask is 0x0000100C.

The operand is read after F-81f744505b98 returns. Consequently, changes that dependency makes to the flags field can affect the result. The function does not use a flags snapshot taken before the dependency call.

This is a 32-bit logical operation. No addition, subtraction, or arithmetic overflow is involved in the mask itself. The evidence does not establish an atomic read-modify-write or protection against concurrent updates.

### 7. Call F-2706939fe3c5

After the state and flags writes, the function calls F-2706939fe3c5 with:

1. The original opaque 32-bit argument.
2. The separately supplied global value.

The second argument is obtained at this later stage, rather than being captured alongside the object base at entry. A change to that global during F-81f744505b98 can therefore affect the value passed to F-2706939fe3c5.

No visible check constrains the global value before it is passed onward.

### 8. Translate the dependency result

If F-2706939fe3c5 returns exactly 3, F-7a78703416b1 returns 0. For every other normally returned value, it returns 89.

There is no visible rollback, retry, cleanup call, or additional state write after this dependency returns.
