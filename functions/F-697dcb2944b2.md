# F-697dcb2944b2

## Purpose

F-697dcb2944b2 traverses a byte region using classifications obtained from a caller-supplied table. Each classification determines whether traversal stops or advances by one or two bytes.

The established behavior is traversal with no published result. The function returns no value, does not update a caller-owned cursor, and contains no explicit writes to the context, input region, or classification table.

Three classification masks control traversal:

- `0x0020` selects a special rule that examines the following byte.
- `0x0307` permits ordinary one-byte advancement when `0x0020` is absent.
- `0x0008`, when present in the following byte’s classification on the special path, selects one-byte rather than two-byte advancement.

A current classification of `0x0008` alone causes an immediate return. Its role differs when it is obtained for the following byte: there it selects one-byte advancement, without immediately applying the stopping rule to that position.

Character classification, token scanning, and multibyte processing are possible interpretations of the table. These meanings are inferred intent, not established semantics.

## Behavior

### Classification roles and precedence

The relevant masks have distinct roles:

| Mask | Role |
|---|---|
| `0x0020` | Select the special current-byte path. |
| `0x0307` | Permit ordinary one-byte advancement if the special bit is clear. |
| `0x0008` | Select one-byte advancement when found in the following byte’s classification on the special path. |

The ordinary mask contains `0x0001`, `0x0002`, `0x0004`, `0x0100`, and `0x0200`. Any one of these bits suffices for ordinary advancement, provided `0x0020` is clear.

The special bit takes precedence. When a current classification contains `0x0020`, the function consults the following byte even if the current classification also intersects `0x0307`.

Other bits do not independently permit advancement. In particular, a current classification containing only `0x0008` satisfies the stopping rule.

### Ordinary current-byte decision

At a current position, the function reads the byte and obtains its table classification.

If `0x0020` is clear:

- An intersection of zero with `0x0307` causes an immediate return.
- A nonzero intersection with `0x0307` causes a one-byte advance.

After advancement, the resulting position is examined as a new current position. The function does not use the input byte’s numeric value directly as a stopping test.

### Special following-byte decision

If the current classification contains `0x0020`, the function obtains the classification of the byte immediately following the current position.

The following classification determines the advancement distance:

- If `0x0008` is set, advance by one byte.
- If `0x0008` is clear, advance by two bytes.

No other bit in that following classification changes this immediate choice. The following classification is not tested against the ordinary stopping rule during this decision.

This distinction permits a byte with a stopping classification to be passed over. For example, a following classification of `0x0000` selects a two-byte advance. It does not cause a return at that following position.

After a one-byte special advance, the previously following byte becomes the current byte and is classified again. The earlier classification is not retained as the next current-byte decision. Under stable memory, both classifications have the same value; without that assumption, equality is not established.

After a two-byte special advance, traversal resumes at the position two bytes beyond the original current position. The intervening byte was read and classified only for the special advancement decision.

### Termination

The sole explicit normal-return condition is a current classification for which both of these statements hold:

- `0x0020` is clear.
- The intersection with `0x0307` is zero.

Both `0x0000` and `0x0008` satisfy that condition when they are current classifications. A classification containing only other bits outside `0x0020` and `0x0307` also satisfies it.

There is no independent termination condition based on:

- A zero-valued input byte.
- A fixed traversal count.
- Reaching the end of a buffer or allocation.
- A null address.

A zero input byte selects table entry zero. That entry determines whether traversal stops or continues. A null address is not handled as a sentinel; attempting to use an invalid address violates the access preconditions.

Normal termination is not guaranteed. If every reached current classification permits advancement, the function continues attempting reads. Faults and invalid address calculations are not implemented error-reporting paths.

## Side effects

### Observable access ordering

At the source level, execution establishes this ordering between classification decisions:

1. Obtain the current byte’s classification.
2. If its special bit is set, obtain the following byte’s classification.
3. Return or advance according to the applicable decision.
4. After an advance, obtain the new current byte’s classification.

Every classification lookup includes a reference to the table-address field at context offset 4. The supplied body does not establish one table-address snapshot for the entire traversal.

Within a lookup, the input byte and table address are both needed to select the classification entry. Their relative read order is not established by the expression. The selected classification is then obtained through a 16-bit access.

A special one-byte advance therefore entails a following-byte classification followed by a separate current-byte classification of the same position. This is a source-level access distinction, not a guarantee of separate physical machine loads.

Exact instruction ordering, load counts, and compiler reuse of ordinary non-volatile reads are not established by the supplied material.
