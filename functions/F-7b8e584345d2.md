# F-7b8e584345d2

## Purpose

The established behavior is a sequencing contract: field accesses, dispatch-table offsets, argument relationships, captured values, and one explicit byte write. The supplied representation does not establish an application-level purpose such as initialization, shutdown, registration, or release.

Normal completion is conditional on valid storage, usable dispatch targets, and dependencies returning control. No dependency preservation, ownership, or error-handling guarantees are supplied.

### Initial query and primary-token capture

The query result is treated as a 32-bit integer and tested for zero:

- Zero skips the conditional sequence.
- Any nonzero 32-bit value enters it.

The condition is not a positivity test. A bit pattern interpreted as a negative integer still selects the conditional sequence.

After the query returns, the primary-token source is read and its value captured. This occurs on both paths, before any conditional dependency call. Every visible primary-object operation that uses the primary token receives this captured value rather than a later refresh of its source.

4. A primary-object operation through table offset `0x58` receives the primary-object pointer, captured primary token, and conditional payload 1.
5. The conditional-token source is read and captured.
6. A second primary-object operation through table offset `0x58` receives the primary-object pointer, a separate read of the conditional-token source, and conditional payload 2.
7. A third primary-object operation through table offset `0x58` receives the primary-object pointer, captured conditional token, and conditional payload 3.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests.

### Zero query result

Given valid storage and dependencies returning control, a zero query result skips every conditional operation. The state-byte assignment occurs, followed by the two unconditional primary-object operations, F-ac356e5603c7, and the three represented returned-object operations.

Exactly two primary-object operations through slot `0x58` are reached on this path.

### Nonzero query result

Under the same assumptions, any nonzero 32-bit query result selects the conditional sequence. This includes the all-ones bit pattern, whether interpreted as signed negative one or unsigned maximum.

Five primary-object operations through slot `0x58` are reached: three before the state-byte assignment and two afterward. F-6ac70711bbb5 and F-93bd7d506529 both precede the assignment.

### Associated-object replacement

If F-29eca01f3b88 replaces the associated-object field with another valid object, and that field remains stable during the subsequent dispatch’s reads, the operation at slot `0x24` uses the replacement. The initial query need not have used that object.

### Primary-token mutation

If a conditional dependency changes the primary-token source after its capture, the two unconditional primary-object operations still receive the captured value.

### Separate conditional-token reads

If the conditional-token capture obtains one value and the separate argument read obtains another, the second conditional primary-object operation receives the separately read value. The third receives the captured value.

If the source is stable across those reads, both receive equal tokens. Stability is an additional assumption.

### Separate returned-token reads

If the returned-token capture obtains value A and the first returned-object operation’s separate token read obtains value B, the first operation receives B. The second and third receive A.

If the first operation changes the backing source again, that mutation does not refresh the captured argument used by the second and third operations.

### Byte-width update

At the direct store, the byte at offset `0x2C` becomes `2`; neighboring bytes are not written by that store. Later dependencies may change any accessible storage, including that byte.

### Nonreturning dependency

If F-438680ffebfe does not return, the subsequent conditional primary-object operations, state-byte assignment, unconditional operations, and returned-object operations are not reached through the visible sequence.
