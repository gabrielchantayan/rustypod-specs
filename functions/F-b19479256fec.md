# F-b19479256fec

## Purpose

F-b19479256fec transforms a signed 32-bit input into an unsigned 32-bit result. Two input values have unconditional results. All other inputs take a table-seeded path with optional coefficient adjustment and exactly three dependent calls to F-e713aa9f4f3b, assuming normal completion.

The established contract is a word-level transformation, not a mathematical approximation guarantee. The constants and correction structure suggest a reciprocal-square-root calculation with 16 fractional bits, but that interpretation is **inferred intent**. Neither the dependency implementations nor the referenced numerical data are supplied.

This specification distinguishes the visible behavior from target-dependent arithmetic and unknown dependency effects. It does not promise a result where an invalid memory access, unsupported arithmetic operation, or dependency failure prevents normal completion.

## Interface

### Values and widths

The interface has:

- One signed 32-bit integer input.
- One unsigned 32-bit integer result.
- No explicit pointer argument, output buffer, length, status output, or ownership token.

The input’s signed interpretation matters to multiplication and right shifting. The result is a 32-bit bit pattern presented as unsigned; a result with its highest bit set is not independently identified as an error.

The supplied representation uses 32-bit working values and signed 64-bit multiplication intermediates. Calling convention, argument registers, and a complete external ABI are **documented_only**.

### Referenced storage

The general path references a stored table base and a coefficient.

A selected table entry is an unsigned 16-bit value occupying two bytes. Its byte displacement from the table base is twice an index between zero and seven. There is no visible entry header or additional field. Normal completion requires the selected two bytes to be readable; the body does not check the table’s allocation extent.

The coefficient is converted to signed 64-bit form before multiplication. Its original width, signedness, representation, and numerical value are not supplied. It must not be presumed to be a particular square-root-related constant.

Byte order, alignment requirements, relocation details, and storage-access atomicity are **documented_only**.

### Arithmetic qualifications

The word-level descriptions below use 32-bit bit patterns, modulo-\(2^{32}\) unsigned arithmetic, and a signed interpretation with range −2147483648 through 2147483647.

Several visible operations require additional care:

- An eight-bit shift-count mask does not make every resulting count valid for a 32-bit shift.
- Signed right-shift behavior requires the target’s signed-shift convention. Numerical examples below assume sign extension.
- Signed left shifts in the supplied representation do not establish portable behavior for negative operands or overflowing results.
- Some conversions from unsigned words to signed values require the target’s conversion convention.
- The subtraction used to obtain the scale is signed before its result is stored as an unsigned word. It is not unconditionally established as wrapping subtraction.

These qualifications are preconditions on interpreting the general path, not checks performed by the function.

## Behavior

### Unconditional results

Input zero returns exactly `0x7fffffff`.

Input `0x00010000` returns exactly `0x00010000`.

For either input, the visible body does not call either dependency or access the table or coefficient. There is no separate status indication. In particular, the zero-input result is not established to mean infinity, saturation, or an error.

### Table-seeded initial value

Every other input is supplied unchanged to F-38db3e9c0785. Its result is consumed as a signed 32-bit value and controls table selection, scaling direction, scaling magnitude, and coefficient use.

The table-selection shift count is the low eight bits of the unsigned 32-bit difference between 28 and that dependency result. The low three bits of the shifted original input select the table entry. Consequently, a defined selection addresses only entries zero through seven, even for negative inputs. Negative inputs are not rejected.

The selected unsigned 16-bit entry contributes twice its value to the initial estimate. Before scaling, that contribution is therefore between zero and 131070 inclusive and fits a nonnegative signed 32-bit value.

Scaling is governed by the dependency result minus 16:

| Scale interpretation | Effect on the doubled entry |
| --- | --- |
| Zero | No numerical change |
| Negative | Right shift by half the magnitude, rounded down for ordinary representable magnitudes |
| Positive | Left shift by half the magnitude, rounded up |

The actual shift count is masked to eight bits. This table summarizes ordinary values; it does not replace the exact count rules at arithmetic boundaries.

For the nonpositive branch, the count comes from unsigned word negation of the stored scale, conversion to signed form, signed right shift by one, and retention of the low eight bits. For the positive branch, the count is the low eight bits of half the signed scale plus its low bit. These details matter when negation cannot be represented as a positive signed value.

The scale subtraction itself has a separate boundary. If F-38db3e9c0785 returns less than −2147483632, subtracting 16 is outside the signed 32-bit range. The supplied representation does not establish a portable result for that subtraction. Storing the result in an unsigned object afterward does not make the preceding signed subtraction defined.

There is no saturation, range check, or validation of the dependency result.

### Parity-dependent adjustment

An odd scale enables coefficient adjustment; an even scale skips it.

On the adjusted path, the scaled word is interpreted as signed 32-bit and multiplied by the coefficient converted to signed 64-bit. The resulting estimate retains product bits 47 through 16 as a 32-bit word.

This extraction discards both the lowest 16 bits and any bits above bit 47. It does not round to nearest and does not saturate. The retained word can have a negative signed interpretation even when a caller expects a positive numerical estimate.

The supplied expression contains repeated coefficient-dependent product expressions. A description as one product followed by extraction presupposes a consistent coefficient value across those evaluations. Neither a single physical coefficient load nor atomic observation of mutable coefficient storage is established.

If the scale is even, the visible body does not require a coefficient access.

### Refinement contract

The general path performs three refinement calls without a convergence condition. Each returned word becomes the estimate used by the next call. The third return is the wrapper’s final result.

For each call, two arguments are derived from the current estimate and the original input:

- The first argument is the signed interpretation of the estimate, shifted right by one.
- The second argument is a 32-bit correction word. It is `0x00030000` minus a nested fixed-width product term, with unsigned subtraction wrapping modulo \(2^{32}\).

The nested product term has a specific truncation boundary. First, the signed estimate is multiplied by the original signed input, and product bits 47 through 16 are retained. That retained word is interpreted as signed and multiplied by the signed estimate again. Bits 47 through 16 of this second product supply the term subtracted from `0x00030000`.

The intermediate extraction is significant: this is not an unrestricted triple product rounded or truncated only at the end. Its signed interpretation can alter the second product.

Each refinement multiplication has two signed 32-bit operands. Their product fits signed 64-bit storage, including the product of two minimum signed 32-bit values. This establishes the multiplication range, not portable validity of every signed-shift expression used to assemble an extracted word.

F-e713aa9f4f3b’s operation is unknown. The wrapper does not establish that it multiplies its arguments, performs fixed-point arithmetic, preserves sign, or improves an approximation. Its return is consumed directly as a 32-bit word, including any bit pattern another contract might designate as an error.

A zero estimate does not stop refinement. No returned estimate causes an early exit.

## Side effects

### Ordering and state visibility

For a normally completing general-path call, the observable dependency order is:

1. One call to F-38db3e9c0785.
2. Selection and reading of a table entry.
3. Coefficient-dependent evaluation if scale parity requires it.
4. Three successive calls to F-e713aa9f4f3b.
5. Return of the last dependency result.

The table base and selected table contents are used after F-38db3e9c0785 returns. The function therefore does not guarantee use of their values from function entry. If that dependency changes relevant global storage, those effects cannot be dismissed without its separate contract.

The initial estimate is complete before the first refinement call. Subsequent refinement uses the original input and the preceding returned estimate; the visible body does not reselect a table entry between rounds.

This ordering does not specify physical memory-transaction counts, processor instruction counts, atomicity, or concurrency synchronization.

### Writes and ownership

The visible body contains no explicit externally directed memory write, allocation, release, or ownership transfer. Its working values are integers, not exposed resource handles.

That observation applies only to the wrapper. Neither dependency is established to preserve globals, avoid external I/O, retain memory, release memory, or return normally. No ownership behavior may be inferred from their opaque identifiers or from the arithmetic use of their results.

### Failure behavior

There is no explicit recovery or validation path for:

- Negative input.
- An unexpected normalization result.
- Unreadable table or coefficient storage.
- An oversized shift count.
- Signed arithmetic outside its defined range.
- A distinguished dependency error value.
- A dependency that traps, faults, or fails to return.

The function does not translate those conditions into a documented fallback result. Normal-return claims are conditional on reaching the return.

## Acceptance examples

These are conditional acceptance criteria derived statically. No runtime tests have been performed. General-path examples require readable storage and target arithmetic supporting the stated operations.

### Unconditional cases

For input zero, the result must be `0x7fffffff`, with neither dependency called and no visible table or coefficient access.

For input `0x00010000`, the result must be `0x00010000` under the same no-call and no-data-access conditions. Changes to table contents or the coefficient cannot alter these two visible results.

### Even scale and wrapped correction

Assume:

- Input is `0x00040000`.
- F-38db3e9c0785 returns 16.
- Table entry zero is `0x8000`.

The table-selection count is 12 and the selected index is zero. Doubling the entry gives `0x00010000`. The scale is zero, so there is no effective scaling and no coefficient adjustment.

In the first refinement, both product extractions yield `0x00040000`. F-e713aa9f4f3b receives first argument 32768 and second-argument bit pattern `0xffff0000`. The subtraction wraps; it does not clamp to zero.

If all three refinement returns are zero, the second and third calls each receive zero and `0x00030000`, and the final result is zero.

### Positive odd scale with coefficient adjustment

Assume:

- Input is `0x00040000`.
- F-38db3e9c0785 returns 17.
- Table entry zero is `0x4000`.
- The coefficient consistently converts to signed 64-bit value 32768.

The selection count is 11 and the selected index is zero. The doubled entry is `0x00008000`. Positive scale one requires a left shift by one, producing `0x00010000`.

Odd parity enables coefficient adjustment. Its retained product word is `0x00008000`. The first refinement call therefore receives first argument `0x00004000` and second argument `0x00020000`.

This criterion does not assert that 32768 is the actual stored coefficient.

### Zero seed does not terminate refinement

Assume a general-path input, a normalization result of 14, and a selected table entry of zero.

The scale is −2, its right-shift count is one, and the seed remains zero. Even parity skips coefficient adjustment. The first refinement call receives zero and `0x00030000`.

All three calls remain required if they return normally. Later arguments depend on their actual returns, not on the initial seed remaining zero.

### Unsupported counts and signed subtraction

A negative input is passed unchanged to F-38db3e9c0785 rather than rejected.

If that dependency returns 29, the table-selection count is 255. No portable 32-bit shift result is established for that count; acceptance must not silently substitute a shift by 31.

If the dependency returns −2147483648, the scale subtraction is outside signed 32-bit range. A modulo scale value is not an unconditional acceptance criterion.
