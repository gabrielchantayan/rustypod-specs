# F-bd6497c7b833

## Purpose

F-bd6497c7b833 dispatches a record using its signed 32-bit tag, ordered comparisons with an outer global discriminator, and, on one path, a nested tag and a second global discriminator.

Observable behavior includes dependency calls, indirect operations, one explicit byte-sized receiver update, and a 32-bit return value. Most selected paths return 1, including paths that perform no additional operation. Fallback returns 0 when neither of its supported tags matches. One dependency can supply a nonzero result that is returned unchanged.

The discriminator comparisons are not unconditional three-way partitions against captured global values. Each discriminator is read for equality and, if equality fails, read again for a subsequent ordered comparison. A simpler equal/below/above description is valid only when the applicable discriminator remains unchanged between those reads.

These conclusions describe the supplied static representation. No runtime behavior has been observed.

## Behavior

### Outer selection: ordered discriminator reads

The record tag is read once at entry and retained for the initial outer selection.

The function then:

1. Reads the outer discriminator and compares it for equality with the retained tag.
2. If equal, calls F-14c84657c3ea with the receiver and returns 1 after normal completion.
3. If unequal, reads the outer discriminator again and performs a signed comparison of the retained tag against this second value.

The second comparison selects:

- **Lower branch:** retained tag is strictly less than the second discriminator value.
- **Remaining branch:** retained tag is greater than or equal to the second discriminator value.

No dependency call occurs between these two discriminator comparisons. Nevertheless, the representation contains separate global references; it does not establish a captured value or a synchronization guarantee.

If the discriminator is unchanged, these predicates simplify to equality, strictly below, and strictly above one value. If it changes, a tag equal to the second discriminator value reaches the remaining branch, provided equality against the first value failed.

### Lower branch

Only retained tags `0x0F`, `0x16`, and `0x1E` receive dedicated processing. Other tags enter fallback.

#### Tag `0x0F`: delegated handling

F-fe275a486eee receives the receiver and record.

- A nonzero result is returned unchanged.
- A zero result causes fallback.

Fallback rereads record storage. It does not reuse the entry tag. A change made by F-fe275a486eee can therefore determine the fallback operation.

#### Tag `0x16`: nested dispatch

F-682adfd5a561 receives the record and integer `0xF00`.

After it returns, the function reads the returned object’s `+0x08` field to obtain the nested-object address, then reads the signed nested tag at that object’s `+0x04`. No failure result is checked before these dereferences.

The nested discriminator comparisons occur after this dependency call. Its effects on global state must not be assumed absent.

**First nested comparison: equality**

The function reads the nested discriminator and compares it for equality with the retained nested tag.

If equal:

1. Read and retain the payload address from nested offset `+0x0C`.
2. Read one byte at that address.
3. Call F-4f8ecc592e57 with receiver, byte, and flag 0.
4. Read one byte again from the retained payload address.
5. Call F-0152cdc5db1c with receiver, flag 0, and the newly read byte.
6. Return 1 after normal completion.

The byte is reread after the first call. The second dependency may therefore receive a changed value.

The payload address itself is retained. Changing the nested object’s address field during the first call does not redirect the second read.

**Second nested comparison: discriminator less than or equal to tag**

If equality fails, the function reads the nested discriminator again and compares whether this second value is signed-less-than-or-equal-to the retained nested tag.

When that predicate is true:

- If the nested tag is not `0xE0006`, return 1 without reading the payload.
- If the tag is `0xE0006`, read its payload address and read an unsigned 16-bit value from that address.
- Zero-extend that value and compare it with `0x000B`.
- If unequal, return 1.
- If equal, obtain the related-object reference at receiver offset `+0x20`, obtain its operation table, invoke the target at table offset `+0x70`, and return 1.

The indirect invocation has no explicit arguments in the supplied representation. An implicit object argument or other ABI behavior is not established.

This branch is not unconditionally “nested tag strictly greater than the discriminator.” It includes equality with the second discriminator read when equality with the first read failed. Strictly greater is the simplified description only when the two reads agree.

**When the second nested predicate is false**

The retained nested tag is then strictly less than the second discriminator value.

- If it is not `0xE0001`, return 1 without reading the payload.
- If it is `0xE0001`, perform the same retained-address, two-byte-read sequence as the equality path, using flag 1 in both calls.

The argument orders remain different:

- F-4f8ecc592e57 receives receiver, byte, flag.
- F-0152cdc5db1c receives receiver, flag, byte.

A successful first equality comparison always selects byte processing, including when the nested discriminator equals `0xE0006`.

#### Tag `0x1E`: state refresh

The observable source-level sequence is:

1. Read the 32-bit receiver field at `+0x44`.
2. Call F-f189a264acca with that value.
3. Store the returned byte at receiver offset `+0xA1`.
4. Read the 32-bit integer at receiver offset `+0xA0`.
5. Convert that integer to `char` and compare the converted value with zero.
6. If nonzero, reread the 32-bit field at `+0x44` and call F-f591b4c58273 with that fresh value and integer 1.
7. Call F-879d713f98bc with the receiver.
8. Return 1.

The condition is not an explicit byte dereference at `+0xA0`. It is a word access followed by conversion. The supplied material does not establish the complete integer-to-`char` conversion behavior for values outside the destination range, nor the correspondence between the converted value and a particular memory byte.

The condition is evaluated after F-f189a264acca returns and after the overlapping `+0xA1` store. Both dependency effects and that store must be accounted for when determining the subsequently read integer.

The optional second `+0x44` read is also fresh. Its value need not equal the value passed to F-f189a264acca.

### Remaining outer branch

This branch is reached when initial equality failed and the retained tag is greater than or equal to the second outer-discriminator value.

Its dedicated tags are:

- `0x80009`: return 1 without another call.
- `0x8000A`: return 1 without another call.
- `0x8000C`: call F-cefd52fab705 with the receiver, then return 1.

All other tags enter fallback.

The `0x8000A` recognition is represented by 32-bit subtraction of `0x80000` followed by comparison with decimal 10. Under 32-bit modular arithmetic, that equality identifies exactly `0x8000A`. The material does not establish a source-language signed-overflow policy; it supplies no basis for additional accepted tags.

### Fallback

Fallback performs these ordered checks:

1. Read the current record tag and compare it with `0x14`.
2. If equal, invoke the receiver-table operation at `+0x78` with the receiver and the three current 32-bit record words at `+0x08`, `+0x0C`, and `+0x10`. Return 1.
3. Otherwise, read the current record tag again and compare it with `0x13`.
4. If equal, invoke the receiver-table operation at `+0x5C` with the receiver and the two current 32-bit record words at `+0x08` and `+0x0C`. Return 1.
5. Otherwise, return 0.

No dependency call intervenes between the two tag checks. They remain distinct source-level reads, without an established concurrent-memory contract.

## Acceptance examples

These are conditional static expectations, not executed tests. Referenced storage and targets must be valid, and invoked dependencies must return normally.

1. **First outer equality takes precedence.**  
   With entry tag `0x1E` and first outer-discriminator read `0x1E`, call F-14c84657c3ea and return 1. Do not perform a second discriminator comparison or the state-refresh sequence.

2. **Second outer equality belongs to the remaining branch.**  
   With entry tag `0x80009`, first discriminator read `0x80008`, and second read `0x80009`, initial equality fails and signed less-than is false. Consume the tag and return 1 without another call.

3. **Non-Boolean delegation result survives.**  
   If tag `0x0F` reaches the lower branch and F-fe275a486eee returns `-3`, return `-3` without fallback.

4. **Fallback observes a modified record.**  
   If that dependency instead changes the record tag to `0x14` and returns zero, invoke the receiver-table target at `+0x78` using the current three payload words, then return 1.

5. **Nested equality rereads the byte, not its address field.**  
   On first nested equality, an initial payload byte `0x21` is passed to F-4f8ecc592e57 with flag 0. If that dependency changes the retained location to `0x42`, F-0152cdc5db1c receives flag 0 and byte `0x42`. Changing only the nested payload-address field does not redirect that read.

6. **Changed nested discriminator permits second-read equality.**  
   For nested tag `0xE0006`, first discriminator read `0xE0005` fails equality. A second read of `0xE0006` satisfies discriminator-less-than-or-equal-to-tag. Payload `0x000B` invokes the related-object operation; `0x010B` does not.

7. **Stable nested discriminator permits simplified regions.**  
   If both nested discriminator reads agree and `0xE0001` is below that value, the two byte-processing calls use flag 1. Another tag below that same value returns 1 without payload access.

8. **State condition uses the post-store word conversion.**  
   On applicable tag `0x1E`, store F-f189a264acca’s returned byte at `+0xA1`. If the subsequently read 32-bit integer at `+0xA0`, after conversion to `char`, equals zero, skip F-f591b4c58273 but still call F-879d713f98bc. A nonzero converted value requires the optional call with a fresh `+0x44` argument.

9. **Unrecognized fallback returns zero.**  
   If neither fallback tag read matches its respective comparison, invoke neither fallback operation and return 0.
