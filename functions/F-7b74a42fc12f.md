# F-7b74a42fc12f

## Purpose

F-7b74a42fc12f creates or obtains a dispatch object, offers it to an initial sequence of recipients, and, if none accepts it, uses either an explicitly supplied recipient or a default recipient chain. It then invokes a cleanup-like virtual operation on the dispatch object when that object is non-null and returns the dispatch result.

“Dispatch,” “recipient,” and “acceptance” describe the observed control flow, not established application semantics. Operationally, a recipient accepts when its invoked method returns any nonzero 32-bit value. That value is returned unchanged after object finalization.

The function has three ordered dispatch stages:

1. An optional preliminary iteration.
2. A single explicitly supplied recipient, if present.
3. A default chain, used only when the preliminary iteration produces no nonzero result and the explicit recipient is absent.

The function does not necessarily visit all recipients. Preliminary acceptance bypasses both later stages. An explicit recipient suppresses the default chain even when its result is zero.

### 3. Explicit-recipient dispatch

The two F-3fdd14ecd250 invocations are distinct. The function does not establish that they return the same context or observe unchanged global state.

- If the dispatch object is null, filtering is disabled.
- Otherwise, the function invokes the dispatch object’s virtual method at offset `0x14`.
- The low 32 bits of that method’s represented 64-bit result determine filtering: zero disables it; nonzero enables it.

The high 32 bits accompany intermediate pair-valued state in the supplied representation, but they do not establish an additional dispatch condition. The only established property decision uses the low 32 bits.

A null dispatch object therefore skips the property query but may still be passed to recipient methods.

### 5. Default-chain traversal

Traversal stops before processing a recipient if the current recipient pointer is null or the dispatch result is nonzero.

- With filtering disabled, the method is invoked without reading nested filtering metadata first.
- With filtering enabled, the function reads the pointer at recipient offset `0x0c`, then reads the 32-bit field at offset `0x0c` in that referenced object.
- If the nested field is zero, the recipient method is invoked.
- If the nested field is nonzero, F-35b8bd5fa9e0 is called with the dispatch object.

  - A zero return skips this recipient’s dispatch.

There is no visible null check between reading the recipient’s metadata pointer and dereferencing it for filtering. Enabled filtering therefore requires a valid referenced object for every visited recipient, even though null in the same recipient field has a later termination role.

An invoked slot-`0x30` method receives its recipient as receiver and the dispatch object as the other visible argument.

- A nonzero result stops traversal immediately.
- A zero result permits continuation checks.
- A skipped recipient leaves the dispatch result zero and also proceeds to continuation checks.

For continuation, the function reads the current recipient’s offset-`0x0c` field again:

- If that field is zero, traversal stops.
- Otherwise, the function invokes the recipient’s virtual method at offset `0x1c`.
- The low 32 bits of that operation’s represented 64-bit result become the next recipient pointer.

A nonzero continuation field does not itself identify the successor. The successor comes from the virtual operation.

The continuation field is read after any filtering helper and recipient callback. Consequently, their mutations may affect continuation. The function does not reuse the earlier filtering read as the continuation decision.

There is no visible cycle detection, visit bound, or maximum chain length.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. They assume valid objects and normally returning dependencies.

1. **Preliminary acceptance takes priority.**  
   If the preliminary source exists and its first dispatched recipient returns `7`, the iterator is finalized, neither the explicit recipient nor the default chain is visited, the dispatch object is finalized if non-null, and the return is `7`.

2. **Preliminary exhaustion permits the explicit recipient.**  
   If every preliminary callback returns zero and iteration then reports exhaustion, a non-null sixth input receives one slot-`0x30` call. Its result is returned after dispatch-object finalization.

3. **Explicit rejection does not trigger fallback.**  
   If the explicit recipient returns zero, the result is zero. The default-root lookup does not occur.

4. **An empty default chain still follows setup order.**  
   With no preliminary acceptance and no explicit recipient, a null default root prevents recipient dispatch. If the dispatch object is non-null, its property query still occurs before traversal recognizes the null root, followed eventually by its finalization.

5. **Disabled filtering bypasses nested metadata inspection.**  
   If the property query’s low word is zero, the current default recipient is called without a prior nested filtering-field read. A zero callback result is followed by the separate continuation-field check.

6. **A marked recipient can be skipped.**  
   With filtering enabled, valid metadata, a nonzero nested filtering value, and a zero result from F-35b8bd5fa9e0, that recipient’s slot-`0x30` method is not invoked. Traversal may continue through slot `0x1c` if the continuation field is nonzero.

7. **Metadata alone can permit dispatch.**  
   With filtering enabled and the nested filtering value zero, F-35b8bd5fa9e0 is not called for that recipient; slot `0x30` is invoked directly.

8. **A negative result is terminal.**  
   If a recipient returns `-3`, traversal stops and the final result remains `-3`, subject to normal completion of object finalization.

9. **Callback mutations affect continuation.**  
   If a default recipient returns zero after changing its offset-`0x0c` field to zero, traversal stops without calling that recipient’s successor operation.

10. **Null payload does not mean no dispatch.**  
    If object creation returns null, later dispatch stages may still pass null to recipient methods. The property query and final object method are omitted. Successful completion additionally depends on those recipients accepting null.
