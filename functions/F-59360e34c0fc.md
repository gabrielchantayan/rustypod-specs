# F-59360e34c0fc

## Purpose

F-59360e34c0fc classifies an input value using two bits in a caller-supplied state object. It may change those bits and conditionally forward the input to F-96b68e21fa81.

The established behavior distinguishes the numeric values 0x22 and 0x5C. Interpreting them as a double quote and a backslash, respectively, suggests processing of a quoted region with one-input escape handling. That interpretation is inferred intent, not an established encoding or parsing contract.

The function produces one of three 32-bit results on normal completion:

- **0:** The first state bit was clear on entry, and the input was not 0x22.
- **1:** The first state bit was set and the second was clear on entry, and the input was 0x22.
- **2:** Every other case.

These results describe entry-state classification and the selected branch. They do not necessarily describe the state after a dependency call, because that dependency’s effects are unknown.

## Behavior

### Initial observation and branch selection

The function first reads the 32-bit state word at offset 0x28. This initial observation determines the main branch and all tests of the two control bits.

Except for the post-forwarding backslash path described below, state stores are constructed from this initial word. They are not merges with a newly read word.

The escape bit affects branch selection only when the active bit was set on entry.

### Active bit clear on entry

If the active bit is clear in the initial word:

- For input **0x22**, the function writes the initial word with the active bit set and returns **2**.
- For every other input, it makes no explicit state write and returns **0**.

Neither case calls F-96b68e21fa81, even if the optional forwarding argument is nonzero.

Setting the active bit preserves every other bit from the initial word, including the escape bit. Consequently, an entry state with active clear and escape set is not normalized: input 0x22 leaves both bits set.

### Active set, escape clear on entry

If the active bit is set and the escape bit is clear in the initial word, the function selects return value **2** initially and then handles the input as follows.

#### Input 0x22

The function writes the initial word with the active bit cleared and returns **1**.

No dependency call occurs. The escape bit remains clear because it was clear in the initial word; all unrelated bits retain their initial values.

#### Input other than 0x22

If the optional forwarding argument is nonzero, the function calls F-96b68e21fa81 with:

1. The optional forwarding argument, unchanged.
2. The input value, unchanged.

If the optional forwarding argument is zero, the call is omitted.

The function then distinguishes input 0x5C:

- For **0x5C**, it reads the state word again, sets the escape bit in that newly read value, and writes the resulting 32-bit word.
- For any other value, it performs no explicit state read or write after the optional call.

The normal result is **2** in either case.

The ordering for 0x5C is significant: forwarding happens **before** the reread and before the function sets the escape bit. If the dependency changes the state word and returns normally, the subsequent store preserves its observed changes except that the escape bit is forced set. The function does not force the active bit to remain set.

With a zero forwarding argument, the same backslash state update still occurs. Suppressing forwarding does not suppress escape-bit maintenance.

### Active set, escape set on entry

If both bits are set in the initial word, the function:

1. Writes the initial word with the escape bit cleared.
2. Calls F-96b68e21fa81 with the optional forwarding argument and input value, in that order, if the optional forwarding argument is nonzero.
3. Returns **2**, if execution returns normally.

The active bit is preserved in the explicit store. Every unrelated bit is also preserved from the initial word.

There is no special comparison against 0x22 or 0x5C in this branch. Thus:

- An input of 0x22 does not cause this function to clear the active bit.
- An input of 0x5C does not cause this function to set the escape bit again.

The clear occurs before forwarding. If the dependency can observe the same state storage, the function’s clear precedes that observation. The dependency may subsequently change either control bit or any other accessible state; there is no restoring write after the call.

## Side effects

### Direct memory effects

The function always reads the state word once at entry.

It performs at most one explicit 32-bit state write during an invocation. The backslash path with active set and escape clear also performs one additional state read before that write.

The masks used by the explicit updates are:

- Set active: combine the selected word with **0x00010000**.
- Clear active: retain the selected word’s bits under **0xFFFEFFFF**.
- Set escape: combine the selected word with **0x00020000**.
- Clear escape: retain the selected word’s bits under **0xFFFDFFFF**.

These operations preserve the other 31 bits of their respective source word. That preservation is not a concurrency guarantee. Stores based on the entry snapshot do not incorporate intervening changes to the same storage.

No other direct memory access is visible in the supplied body.

The call may have effects beyond the explicitly accessed state word. No supplied evidence establishes that it preserves globals, preserves the state object, avoids aliases, leaves memory allocated, or returns normally.
