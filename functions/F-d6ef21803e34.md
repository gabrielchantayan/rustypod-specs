# F-d6ef21803e34

## Purpose

F-d6ef21803e34 examines a byte sequence beginning one byte after a supplied address, interprets an optional sequence of formatting flags and a numeric field, and writes a three-word result.

The apparent intent is to parse part of a formatting directive. That interpretation is inferred, not established by a caller contract. In particular, the observed handling of a period does **not** implement ordinary decimal precision parsing: with stable input and classification-table contents, a period terminates parsing without consuming any following digits.

The function also returns a packed 64-bit value containing the first output word and an address one byte beyond the terminal byte.

## Interface

### Inputs

Two arguments are visible:

- **Input address:** a 32-bit address represented through a signed 32-bit argument. Parsing begins at the following byte. The byte at the supplied address is not read by this function.
- **Output address:** a pointer to storage for three consecutive 32-bit words, totaling 12 bytes.

The first byte examined is therefore at input address plus one. No input length accompanies the address.

A global reference supplies a byte-classification table. Each examined byte is zero-extended to an index from 0 through 255. Bit `0x10` of its table entry controls membership in the numeric-scanning class.

### Output layout

The output comprises the following words:

| Offset | Width | Meaning |
|---|---:|---|
| 0 | 32 bits | Packed mode, presence indicator, address-derived byte, and terminal marker |
| 4 | 32 bits | Numeric field accumulated before any period handling |
| 8 | 32 bits | Secondary numeric field or default value |

The first word has these bit fields:

| Bits | Meaning |
|---|---|
| 7–0 | Mode |
| 15–8 | Presence indicator, initially zero and set to one by the period branch |
| 23–16 | Bits 23–16 of the output address |
| 31–24 | Terminal byte, or `0xFF` when the numeric field fails the upper-bound check |

These are bit positions within the 32-bit word. The supplied evidence does not independently establish the target’s byte order for expressing this word as four memory bytes.

The address-derived field is observable behavior, not a reserved field that can safely be zeroed. Its intended purpose is unknown.

### Return value

The return value is a packed 64-bit quantity:

- Bits 63–32 contain the first output word.
- Bits 31–0 contain the address immediately following the terminal byte.

On numeric-field rejection, the low half still identifies the byte after the first byte that ended numeric scanning. It does not identify where the numeric value first became too large.

### Preconditions

The function performs no visible validation of either address.

For a defined, terminating execution:

- Every input byte reached by scanning must be readable.
- The classification-table reference and each accessed table entry must be readable.
- The output must support three 32-bit stores at offsets 0, 4, and 8, with any alignment required by the target.
- Address arithmetic must remain meaningful in the target address space.
- Scanning must eventually encounter a byte that ends the applicable scanning phase.

A zero byte is not explicitly treated as a string terminator. Whether numeric scanning stops on it depends on the classification table. Outside numeric scanning, an unrecognized zero byte becomes a terminal byte.

## Behavior

### Initial state

The function initializes:

- Mode to `1`.
- Presence indicator to `0`.
- The address-derived packed byte from bits 23–16 of the output address.
- Both numeric output fields to zero.

It reads the byte at input address plus one.

### Immediate percent case

If this first examined byte is `0x25`, the function bypasses flag processing, numeric scanning, numeric validation, and secondary-field defaulting.

The result has:

- Mode `1`.
- Presence indicator `0`.
- Terminal byte `0x25`.
- First numeric field `0`.
- Secondary numeric field `0`.

The returned address is input address plus two.

This special case applies only to the first examined byte. A percent byte encountered after one or more flags follows the ordinary terminal-byte path instead.

### Flag processing

Unless the immediate percent case applies, the function consumes a contiguous sequence of recognized flags:

| Byte | Interpretation |
|---|---|
| `0x2D`, minus | Set mode to `0` |
| `0x30`, zero | Set mode to `2`, but only if the current mode is nonzero |
| `0x5F`, underscore | Set mode to `3` |

Each recognized flag is consumed before reading the next byte.

Flag order matters:

- A minus flag prevents subsequent zero flags from changing mode while mode remains zero.
- An underscore flag can replace mode zero with mode three.
- A subsequent zero flag can then replace mode three with mode two.
- Another minus flag resets any current mode to zero.

The zero byte in this table is the character `0`, not the byte value zero.

A leading sequence of character-zero bytes is consumed as flags rather than as part of the numeric field. Flag processing ends at the first byte other than minus, character zero, or underscore.

### First numeric field

Starting at the byte that ended flag processing, the function consults the classification table.

While the current byte has classification bit `0x10` set, it contributes to the first numeric accumulator:

- The prior value is multiplied by ten.
- The unsigned byte value is added.
- Forty-eight is subtracted.
- The input cursor advances one byte.

The transformation uses subtraction by the character-code value for `0`, but classification is table-driven. The function itself does not verify that accepted bytes lie between `0x30` and `0x39`.

The numeric accumulator is stored in a 32-bit signed field. The arithmetic expression includes an unsigned 32-bit byte value, so the supplied representation supports low-32-bit accumulation rather than an independently checked mathematical integer. There is no visible overflow detection.

After scanning stops, the function compares the accumulated field as signed 32-bit against `81`:

- Values less than `81` proceed.
- Values greater than or equal to `81` take the rejection path.

Consequently, this is not evidence of a complete range check for the mathematical interval zero through eighty. Negative 32-bit values produced by wrapping can pass the signed comparison.

The function consumes the entire classified sequence before making this comparison. It does not stop as soon as the running value exceeds eighty.

### Numeric-field rejection

If the signed numeric field is at least `81`:

- The terminal marker becomes `0xFF`, regardless of the actual terminal byte.
- The accumulated first numeric field is retained.
- The secondary numeric field remains zero.
- Mode remains whatever flag processing selected.
- Presence remains zero.

The returned address is one byte beyond the actual byte that ended numeric scanning. Rejection does not suppress output writes or produce a separate error return.

### Period branch

If the first numeric field passes the signed comparison and the current byte is `0x2E`, the function sets the presence indicator to one.

It then performs a classification-controlled secondary numeric scan beginning at that same period byte. It does **not** first advance past the period.

Under stable input and classification-table contents, the first numeric scan has already established that this period lacks classification bit `0x10`. The secondary scan therefore performs no iterations:

- The secondary numeric field remains zero.
- The cursor remains on the period.
- The terminal byte becomes the period.
- The returned address points immediately after the period, including when decimal-looking bytes follow it.

This observed behavior must not be replaced with conventional precision parsing in a behaviorally equivalent implementation.

If memory can change between classification reads, the second lookup could differ. The evidence provides no synchronization or concurrency contract for that situation.

### Ordinary completion

For a first numeric field that passes validation:

- The current byte becomes the terminal byte.
- If the presence indicator is zero, the secondary numeric field becomes `1`.
- If the presence indicator is one, the secondary numeric field retains its accumulated value.
- In that presence-enabled case only, mode `2` is normalized to mode `1`.

The terminal byte is included in the returned cursor advance even though it is not interpreted further here.

### Publication order

After all parsing and local result construction, the function writes:

1. The packed first word.
2. The first numeric field.
3. The secondary numeric field.

It then returns the packed 64-bit result.

No explicit input or classification-table reads occur after output publication begins.
