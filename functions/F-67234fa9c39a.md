# F-67234fa9c39a

## Purpose

F-67234fa9c39a dispatches a signed 32-bit selector to one of several dependency sequences. Depending on the selected route, it forwards a global value, obtains and publishes a dependency result, passes a temporary record between dependencies, or invokes an operation involving the supplied receiver and object.

Dispatch depends on multiple source-visible accesses to a global named **Boundary** in this contract. Those accesses must not be treated as one stable snapshot. The value initially captured for forwarding, the value referenced by the equality comparison, and the value referenced by the subsequent signed less-than comparison may differ.

The established contract covers argument relationships, route selection, source-visible access ordering, and normal completion. Application-specific meanings of selectors, objects, records, and results are unknown.

## Behavior

### Entry and Boundary accesses

Every invocation begins with the following observable ordering:

1. Initialize the record’s first word from Selector.
2. Initialize its second word from Payload.
3. Call **F-5b24edfb22c0** with the record address.
4. Read Boundary and retain that 32-bit value as the **initial forwarding sample**.
5. Separately reference Boundary for comparison with the original Selector.

The fifth step uses the **equality sample**, not the initial forwarding sample.

If Selector equals the equality sample, execution takes the equality route. Otherwise, the function separately references Boundary again and performs a signed less-than comparison. This third Boundary access supplies the **ordering sample**:

- If Selector is less than the ordering sample, execution enters the lower dispatch table.
- Otherwise, execution enters the upper dispatch table.

The ordering sample is not accessed on the equality route.

These are source-visible accesses and their order. They do not establish a particular number of machine instructions, atomic loads, or synchronization events. No assumption of unchanged global contents is permitted.

The entry dependency can affect Boundary before all these accesses. It can also modify the record. Dispatch nevertheless uses the original Selector argument, not the record’s current first word.

### Meaning of the dispatch gates

The three route conditions are:

| Route family | Established condition |
|---|---|
| Equality route | Selector equals the equality sample. |
| Lower table | Selector differs from the equality sample and is signed-less-than the ordering sample. |
| Upper table | Selector differs from the equality sample and is not signed-less-than the ordering sample. |

Upper-table selection therefore does **not** establish that Selector exceeds the initial forwarding sample. It does not even establish strict inequality against the ordering sample: Selector may equal that later sample after failing equality against an earlier, different value.

Only under an explicit stability condition—Boundary has the same value at every reached access—do these gates reduce to equality, strictly below Boundary, and strictly above Boundary.

### Equality route

When Selector equals the equality sample:

1. Form the address at Object address plus `0x44`.
2. Call **F-5813e5f90945** with that address.
3. Call **F-0fefb8900892** with Receiver and the initial forwarding sample.
4. Proceed to common completion.

The forwarded value comes from the first Boundary access. It is not reloaded after **F-5813e5f90945**, and it need not equal Selector or the equality sample.

Equality takes precedence over either fixed-selector table. A Selector that numerically matches a listed table entry still follows this route when the equality comparison succeeds.

## Acceptance examples

These are conditional specifications, not executed tests. Assume all reached dependencies return normally. Changing Boundary samples below describe possible access results; they do not assert that a particular concurrency mechanism exists.

1. **Stable equality overrides a table entry.**  
   Selector is `0x6D10`; both the initial forwarding sample and equality sample are `0x6D10`. The equality route calls **F-5813e5f90945**, then forwards `0x6D10` through **F-0fefb8900892**. There is no ordering access or lower-table record-processing call.

2. **Equality can forward a different value.**  
   Selector is `0x6D10`; the initial forwarding sample is `0x1234`; the equality sample is `0x6D10`. Equality succeeds, but the forwarded value is `0x1234`, not Selector.

3. **The equality helper does not refresh the captured value.**  
   Selector and both reached Boundary samples are `0x6D43`. If **F-5813e5f90945** subsequently changes Boundary, forwarding still supplies `0x6D43`.

4. **Lower-table selection ignores the initial sample’s ordering.**  
   Selector is `0x6D09`; the initial sample is `0x6D00`; the equality sample is `0x6D08`; the ordering sample is `0x6D20`. Equality fails and signed less-than succeeds. The function obtains and publishes the result from **F-44362605ab79**, despite Selector exceeding the initial sample.

5. **Upper-table selection can occur at later equality.**  
   Selector is `0x6D43`; the initial sample is `0x6D50`; the equality sample is `0x6D42`; the ordering sample is `0x6D43`. Both comparisons fail. The upper table forwards Forward-43 even though Selector equals the ordering sample and is below the initial sample.

6. **Stable Boundary gates table availability.**  
   With Selector `0x6D43` and all reached Boundary samples equal to `0x6D50`, execution enters the lower table and takes fallback. The upper-table entry for that selector is unavailable.

7. **Record mutation does not redirect dispatch.**  
   Selector is `0x6D10`, and Boundary is stable at `0x6D20` after entry. If the entry dependency changes the record’s first word, lower-table route `0x6D10` still executes. The modified record is passed onward without reset.

8. **Object-related changes precede forwarding-global reads.**  
   Selector is `0x6D49`, and Boundary is stable at `0x6D20`. **F-c47e858a3dad** receives Object address and zero. If it changes Forward-49, forwarding uses the value read after it returns.

9. **Unmatched and negative selectors use fallback.**  
   Selector `0x6D0A` with stable Boundary `0x6D20` takes lower-table fallback. Selector `−1` with stable Boundary zero also takes lower-table fallback under signed ordering. In each case, **F-c0b020cd3882** receives the original Selector, and the resulting publication precedes common completion.
