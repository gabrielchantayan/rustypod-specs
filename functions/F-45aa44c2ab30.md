# F-45aa44c2ab30

## Purpose

F-45aa44c2ab30 examines a length-described byte sequence, selects a prefix ending at the first line-feed byte when one exists, limits the requested transfer length using a caller-supplied capacity, and delegates the transfer to F-6aafd6657d59. It conditionally writes a zero byte into the destination after that dependency returns.

The function also updates the low four bits of a state word. It clears those bits on entry and, when a positive-length sequence contains no line feed, sets the low nibble to 9 before invoking the dependency.

This is a source-derived behavioral contract. The transfer semantics of F-6aafd6657d59 are unknown. In particular, the visible function does not establish that bytes are copied, consumed, or returned according to conventional string or stream rules.

3. **Capacity parameter.** A signed integer used to calculate an upper limit of capacity minus one.

## Behavior

### Initial flags update

The function first reads the unsigned flags word at state offset 20, clears its low four bits, and writes the masked value back to the same location.

That masked value is also retained for a possible later write. Consequently, the later no-line-feed update uses the value captured at entry, not a newly read flags word.

The initial flags write occurs before the sequence descriptor and sequence length are read. This ordering matters if the state layout overlaps other accessed storage.

### Length observation and nonpositive-length path

After the initial flags write, the function reads the descriptor pointer at state offset 32 and reads a signed length from the descriptor’s first four bytes.

If that length is zero or negative:

- No sequence byte is examined by the visible function.
- F-6aafd6657d59 is not called.
- A zero byte is written at destination offset zero.
- The function returns.

The capacity parameter does not affect this path. Even a zero or negative capacity does not prevent the destination write.

A negative length is treated the same as an empty sequence for this branch. No explicit error is reported.

### Positive-length scan

If the observed length is positive, the function scans from sequence offset zero toward that fixed length.

At each position, it first determines whether the position is still below the initially observed length. Only an in-range position causes a byte read. The scan stops at either:

- The first byte equal to line feed; or
- The original length boundary.

Zero bytes are ordinary scan data. They do not terminate the scan.

The scan’s upper bound is the length captured before scanning. The visible function does not refresh that length during the scan.

The descriptor pointer and the descriptor’s byte-buffer pointer are expressed as reads during each byte examination, rather than as one retained buffer pointer. Thus, the supplied representation does not support a contract that all examined bytes necessarily come from one immutable buffer if the descriptor can change during execution. No synchronization behavior is established.

### Selection of the requested prefix

If a line feed is found, the selected length includes it. A line feed at offset zero therefore selects one byte.

If no line feed occurs within the observed positive length:

- The selected length is the entire observed length.
- Before any capacity adjustment or dependency call, the function writes the retained masked flags value with bits 0 and 3 set.

For the latter write, the resulting low nibble is exactly 9. Bits 4 through 31 come from the entry-time flags read.

Finding a line feed causes no corresponding second flags write. The low nibble remains cleared by this function up to that point.

The no-line-feed decision concerns the entire scanned sequence, not merely the prefix allowed by capacity. The function scans before applying the capacity limit. A small capacity therefore does not limit how far it searches for a line feed.

### Capacity adjustment

After selecting the prefix length, the function compares it against capacity minus one, using signed integer comparison.

If capacity minus one is smaller, that value becomes the requested transfer length. Otherwise, the selected length is retained.

For capacities of at least one, this limits the request to at most capacity minus one. It does not guarantee that many bytes are transferred.

Important boundary cases:

- Capacity 1 produces a request of zero for every positive-length sequence.
- Capacity 0 produces a request of −1.
- A negative capacity generally produces a more negative request.
- A zero or negative resulting request does not bypass the dependency call.

Under the 32-bit signed interpretation, subtracting one from the minimum signed value, −2,147,483,648, is not representable. The supplied material does not establish a language-level overflow rule or independently verified machine-level outcome for that case. Its behavior is documented_only rather than assigned a presumed wraparound result.

The positive-length scan itself does not require a position beyond the signed positive maximum: its counter reaches at most the observed length, and including a found line feed produces at most that same length.

### Dependency call and destination termination

Every positive-length path calls F-6aafd6657d59 once, with:

- The original state address;
- The original destination address;
- The adjusted signed request length.

After that call:

- A positive result causes a zero byte to be written at destination offset equal to that result.
- A zero result causes no destination write by the wrapper after the call.
- A negative result also causes no destination write by the wrapper after the call.

The result is not checked against the requested length, capacity parameter, or available destination storage. A result larger than any of those values still determines the termination offset.

The destination’s usability after the call is therefore an external requirement. The visible function does not establish that the dependency preserves, retains, or releases the destination storage.

## Acceptance examples

These examples assume valid, stable, nonoverlapping storage; representable signed arithmetic; and completion of any dependency call. They describe observable requirements without assigning unspecified behavior to F-6aafd6657d59.

1. **Empty sequence.** With length zero and initial flags `0x1234567f`, the flags are first written as `0x12345670`, destination offset zero receives `0x00`, and no dependency call occurs. Capacity does not alter this outcome.

2. **Negative sequence length.** With length −3, the wrapper takes the same branch as for length zero. It does not reject the length separately or inspect sequence bytes.

3. **Line feed in the middle.** For a six-byte sequence containing `a`, `b`, line feed, `c`, `d`, `e`, with capacity 10, the scan reads offsets zero through two. It selects three bytes and calls the dependency with request 3. There is no no-line-feed flags write.

4. **No line feed.** For a three-byte sequence containing `a`, `b`, `c`, with capacity 10 and initial flags `0xa5a5a5a6`, the wrapper first writes `0xa5a5a5a0`, then writes `0xa5a5a5a9`, and calls the dependency with request 3.

5. **Capacity truncates before the line feed.** For the six-byte sequence in example 3 with capacity 2, the scan still reaches the line feed at offset two. The request is reduced to 1. The no-line-feed flags update does not occur, even though the requested prefix excludes the line feed.

6. **Embedded zero byte.** For bytes `a`, zero, `b`, line feed, the selected length is 4 before capacity adjustment. The zero byte does not stop scanning.

7. **Zero and negative requests.** For any positive observed length, capacity 1 produces request 0, and capacity 0 produces request −1. Both cases still invoke the dependency.

8. **Positive dependency result.** If the dependency returns 2, the wrapper subsequently writes `0x00` at destination offset two. This write is based on the result, not on the originally selected length.

9. **Oversized dependency result.** If the request is 1 but the dependency returns 5, the wrapper attempts termination at destination offset five. It performs no bounds rejection.

10. **Nonpositive dependency result.** If the dependency returns zero or a negative value, the wrapper performs no subsequent terminator write. A terminated destination cannot be promised from this wrapper alone.
