## Behavior

It then publishes two address-derived bytes:

- The low byte of the secondary base at primary base + 0x11.

Next, it writes the initial-destination value as four bytes at secondary base + 0x34.

The remaining repeated portion uses the doubled primary base instead of the initial destination. Each visible repetition preserves the following observable order:

### Snapshot acquisition and fixed-address updates

After the repeated portion, the function obtains several four-byte snapshots. Their acquisition order matters:

- First, the value at fixed address 0xA9.
- Next, the value at payload address + 0x74.
- After a byte update at fixed address 0x3A, the value at context base + 0x14.
- Finally, the value at primary base + 0x04.

The byte written at fixed address 0x3A is twice the primary base’s low byte plus 0x30, reduced to eight bits. Its low-eight-bit result is independent of whether the intermediate byte is interpreted as signed or unsigned.

The saved four-byte values remain snapshots. Subsequent overwrites of their original memory locations do not, by themselves, change the captured values.

### Initial context mutation

The next group of writes establishes the following order-sensitive state:

- Context base + 0x0D receives the primary base’s low byte.
- Primary base + 0x08 receives 0x6C.
- Primary base + 0x0D and then + 0x09 receive the secondary base’s low byte.
- Context base + 0x54 receives the context-base value as four bytes.
- Fixed address 0x67 receives the low byte of the earlier four-byte snapshot from 0xA9.

A four-byte value is then read from context base + 0x44. This contract calls it the **context word**.

After that read, the current byte at fixed address 0x67 is copied to fixed address 0x21. This is a memory-sourced value, not an independently guaranteed copy of the original snapshot’s low byte.

The context word supplies several subsequent writes:

- Its low byte goes to primary base + 0x10.
- Its full four bytes go to secondary base + 0x54.
- A shifted form supplies one byte at context base + 0x01.

The shift uses the low eight bits of the primary base as its count and operates on a value represented as signed. Arithmetic right-shift behavior and counts of 32 or greater are not sufficiently established for an unconditional numeric contract.

Immediately after the shifted-byte write, secondary base + 0x54 is overwritten with the full primary-base value. The intermediate context-word store remains part of the visible access sequence.

### Primary and secondary record mutation

The function next reads four bytes from primary base + 0x40. It then:

- Writes the earlier snapshot from primary base + 0x04 to secondary base + 0x74.
- Writes the newly read four bytes across primary base + 0x10 through + 0x13.
- Writes the context-base value to secondary base + 0x44.
- Copies the current byte at fixed address 0x67 to primary base + 0x09.
- Writes the primary base’s low byte to context base + 0x09.
- Writes the original four-byte snapshot from fixed address 0xA9 to primary base + 0x44.

The four-byte write at primary base + 0x10 overlaps the earlier byte writes at offsets +0x10 and +0x11. Consequently, those earlier bytes are not guaranteed final values.

The function then reads a four-byte address from primary base + 0x54. This contract calls it the **linked address**. After acquiring it, the function again copies the current byte at fixed address 0x67 to primary base + 0x09.

The low byte of the earlier payload-address + 0x74 snapshot is written to linked address + 0x0D. Context base + 0x54 is then overwritten with the earlier snapshot from context base + 0x14.

Next, the function reads four bytes from primary base + 0x14. It writes the payload snapshot’s low byte to context base + 0x11, writes the linked address’s low byte to primary base + 0x09, and writes the full linked address to primary base + 0x44.

This final write to primary base + 0x09 supersedes the earlier writes there when intervening aliasing or external mutation does not alter the scenario.
