# F-14f198eb9d56

## Purpose

F-14f198eb9d56 conditionally shifts a sequence of selected bytes toward higher addresses and clears the first selected byte. The selected bytes are spaced 48 bytes apart, beginning 29 bytes after the supplied base address.

The established behavior is a backward-ordered, in-place byte shift governed by a signed count stored at the base address. Interpreting those bytes as fields of records, queue entries, or status flags is inferred intent, not established behavior. The operation does not move complete 48-byte regions, allocate storage, or explicitly change the count.

Two distinguished pointer values cause an immediate return without a memory access: the null pointer and the pointer represented by the 32-bit address value `0xfffffff8`.

## Interface

**Input:** One pointer used as both a count address and the base address for subsequent byte accesses.

**Output:** No return value. Results are delivered through byte writes relative to the supplied pointer.

**Width model:** The supplied representation describes:

- A 16-bit signed count at offset 0.
- Signed 32-bit arithmetic for the promoted count and loop progression.
- Single-byte reads and writes for the shifted values.
- A 32-bit address representation for the exceptional pointer value and integer-based address calculations.

These are the widths expressed by the supplied static representation. Their correspondence to the original executable’s ABI is not independently established.

For describing the layout, let \(B\) be the supplied base address and let \(n\) be the signed 16-bit value read there. Define selected byte position \(S_k\), for nonnegative \(k\), as:

\[
S_k = B + 29 + 48k.
\]

This notation identifies byte addresses, not independent allocations or proven record boundaries.

| Location | Role |
|---|---|
| \(B\), spanning two bytes | Signed count, read once |
| \(S_0 = B+29\) | First selected byte; always cleared for a non-exempt pointer |
| \(S_1 = B+77\) | Second selected byte |
| \(S_2 = B+125\) | Third selected byte |
| Subsequent selected positions | Continue at a 48-byte stride |

For ordinary, non-wrapping address arithmetic, the count storage does not overlap any selected byte.

**Caller preconditions for a defined completion:**

- Either the pointer is one of the two exempt values, or its count storage supports a valid signed 16-bit read.
- Every byte address actually read or written must be accessible with the required permissions.
- The pointer and offset calculations must be valid under the applicable address and language model.
- Any alignment requirement imposed on the initial count read must be satisfied.
- The caller must not rely on synchronization or atomic publication of the resulting sequence.

The routine performs no general pointer, allocation-size, alignment, or bounds validation.

## Behavior

### Exempt pointer values

If the pointer is null or has the distinguished address representation `0xfffffff8`, the operation returns immediately.

For either value:

- The count is not read.
- No selected byte is read.
- No byte is written.
- No error or status is returned.

This exemption applies to those exact values. It does not establish a general rule that nearby addresses, negative-looking addresses, or other sentinel values are safe.

### Count acquisition

For any other pointer, the routine reads the signed 16-bit count at the base address and promotes it to the signed arithmetic width.

Only one count read is expressed. Subsequent traversal is governed by that captured value, not by repeatedly inspecting the count storage.

There is no unsigned reinterpretation, range normalization, or explicit rejection of a negative count.

### Positive counts greater than one

For \(n>1\), the operation copies selected bytes one position toward higher addresses.

For each selected position with index \(k\) from \(n-1\) down through 1, the byte at \(S_{k-1}\) is read and then written to \(S_k\). The highest destination is processed first.

After all such copies, the routine writes a zero byte to \(S_0\).

Under stable memory, valid addresses, and non-wrapping arithmetic, the final selected-byte contents are therefore:

- \(S_0\) contains zero.
- Each \(S_k\), for \(1 \leq k < n\), contains the pre-operation value of \(S_{k-1}\).
- The pre-operation value of \(S_{n-1}\) is not retained by this routine.
- Selected positions with index at least \(n\) are not explicitly accessed.

Descending traversal is behaviorally significant: a lower selected byte is read before that location is subsequently overwritten. The operation consequently preserves the original source bytes during an ordinary in-place shift rather than propagating one overwritten value through the sequence.

The routine does not read the previous contents of the highest destination merely to overwrite it. It also does not read the previous contents of \(S_0\) as part of the final clearing write; that byte is read only if a copy requires it.

### Counts of one, zero, or a negative value

For every \(n \leq 1\), there are no copy iterations. The routine still writes zero to \(S_0\).

Consequently:

- A count of one clears the sole selected byte.
- A count of zero does not mean “perform no memory writes.”
- A negative count does not produce a backwards traversal or an error return.
- Negative counts, including the minimum signed 16-bit value, take the same byte-clearing path as zero and one.

Even for a count of zero or a negative count, the caller must provide writable storage at offset 29 for normal completion.

### Access ordering

At the level expressed by the supplied representation, the memory-access order is:

1. Read the count, unless the pointer is exempt.
2. For each required copy, in descending destination order, read its source byte before writing its destination byte.
3. Write zero to the first selected byte.

The final clearing write occurs after all copies. This matters because the original first selected byte must remain available when it is copied to the second selected position.

This is a source-level ordering contract. It is not evidence of hardware barriers, volatile accesses, atomicity, or a cross-thread visibility guarantee.

### Arithmetic limits

The signed 16-bit count ranges from \(-32768\) through \(32767\). The first decrement is performed after promotion to the signed 32-bit arithmetic width, so the minimum count becomes \(-32769\), without signed 32-bit overflow.

The maximum count produces:

- 32,766 byte-copy operations.
- 32,767 byte writes, including the final clearing write.
- A highest destination at offset 1,572,797 from the base.
- A highest source at offset 1,572,749 from the base.

The stride multiplication and these offsets fit within signed 32-bit arithmetic. That fact does not establish that adding them to an arbitrary base address is valid.

For a valid non-exempt pointer, the number of copy operations is \(\max(n-1,0)\). The number of explicit byte writes is \(\max(n,1)\). These counts exclude the initial two-byte count read.

## Side effects

The direct side effects are limited to selected-byte writes relative to the supplied base address.

Under valid, non-wrapping addressing:

- The stored count is not modified.
- Bytes between selected positions are not explicitly read or written.
- No whole-region move or bulk clearing occurs.
- No selected position above the count-governed destination range is explicitly modified.
- There is no allocation, deallocation, ownership transfer, or retained pointer.

The routine operates on caller-supplied storage. The caller remains responsible for its lifetime and extent.

The operation is not transactional. No rollback path or recovery mechanism is shown. If an access cannot complete, the supplied evidence provides no guarantee that earlier writes will be undone.

Likewise, the lack of an error return does not establish successful completion for invalid storage. The concrete consequences of an invalid access depend on the execution environment and are not specified here.

## Acceptance examples

These examples are conditional static acceptance criteria, not reports of executed tests. Except for the exempt-pointer cases, they assume valid accessible storage, non-wrapping address calculations, and no concurrent modification.

### Exempt pointers

Given either a null pointer or the distinguished pointer value `0xfffffff8`, the routine returns without reading memory through that pointer and without writing memory.

### Count of three

Suppose the count is 3 and the selected bytes at offsets 29, 77, and 125 initially contain `0x12`, `0x34`, and `0x56`.

Required access sequence after the count read:

- Read offset 77 and write `0x34` to offset 125.
- Read offset 29 and write `0x12` to offset 77.
- Write `0x00` to offset 29.

The final selected bytes are `0x00`, `0x12`, and `0x34`. The count remains 3. The routine does not preserve `0x56` elsewhere.

### Count of two

Suppose the count is 2 and the bytes at offsets 29 and 77 initially contain `0xA5` and `0x7E`.

The byte at offset 29 is copied to offset 77 before offset 29 is cleared. The final pair is `0x00`, `0xA5`. Offset 125 is not accessed.

### Count of one

Suppose the count is 1 and offset 29 initially contains `0xFF`.

The only byte write is zero to offset 29. There is no selected-byte read, and offset 77 is not accessed.

### Zero or negative count

For counts 0, \(-1\), and \(-32768\), the routine reads the count and clears offset 29 without performing a copy.

An implementation that leaves offset 29 unchanged for these counts would not satisfy this contract.

### Distinguishing a byte shift from a region move

For a count of 3, bytes at offsets 30 through 76 and 78 through 124 are not explicitly moved or cleared.

A replacement that shifts every byte in the intervening 48-byte regions would introduce effects absent from the supplied behavior.

### Insufficient storage

If the pointer is not exempt and its count can be read, but offset 29 is not writable, even a count of zero does not make the invocation safe.

For larger positive counts, every specified source must additionally be readable and every specified destination writable. No controlled failure response is established when these conditions are violated.

## Uncertainties

The following remain **documented_only**:

- **Semantic meaning:** The count’s application-level meaning and the selected bytes’ roles are unknown. Record-field shifting is a plausible interpretation, not a proven purpose.
- **Sentinel rationale:** The reason for accepting `0xfffffff8` as an immediate-return value is unknown. No broader sentinel scheme is established.
- **Original ABI:** The widths above follow the supplied static representation; the original platform’s pointer conversion rules, alignment requirements, and endianness are not independently verified.
- **Address-edge behavior:** Behavior when address formation crosses the address-space boundary or violates object bounds is not established. This contract does not prescribe modular wrapping as a safe substitute.
- **Invalid memory:** Fault handling, termination, signals, and other responses to inaccessible memory are unspecified.
- **Concurrent or device-backed memory:** No guarantees establish a coherent snapshot, access atomicity, device semantics, or visibility to other observers.
- **Storage extent and ownership context:** The allocation size, enclosing layout, aliases, and caller lifecycle are not supplied.

These unknowns do not alter the established count handling, byte offsets, descending copy order, or final zero write for valid ordinary storage.

## Evidence

The supplied static body establishes:

- Two exact pointer-value exclusions before dereferencing.
- One signed count load.
- A decrement-before-condition traversal.
- Single-byte copies at a 48-byte stride, with sources one stride below destinations.
- Descending destination order.
- An unconditional final zero-byte write at offset 29 for every non-exempt pointer.
- No function calls, explicit allocation, explicit release, or count write.

The final-state relations, access counts, and maximum offsets are arithmetic consequences of that static behavior.
