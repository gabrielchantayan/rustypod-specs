# F-074b77674247

## Purpose

F-074b77674247 performs an ordered prefix of indirect dependency calls and computed-address memory operations, then enters an unconditional loop containing further calls and byte writes.

The supplied static representation does not establish a domain-level purpose. Initialization, serialization, device control, and object construction are not established interpretations.

The supported behavioral contract is conditional: an operation occurs only if all preceding calls return and all preceding accesses complete. Dependencies may prevent further execution, and the representation contains recovery warnings that limit confidence in its completeness.

### Widths, arithmetic, and layout

A **word** is 32 bits; a **byte** is 8 bits. Byte stores retain only the low eight bits. Right shifts of unsigned quantities are logical. Address offsets are measured in bytes.

Some indices and intermediate products are represented as signed quantities. Their overflow and signed-left-shift semantics are not established independently of the target. Expressions below involving such operations describe the recovered arithmetic; examples using wraparound explicitly assume 32-bit bit-vector arithmetic modulo \(2^{32}\).

A **selector write** comprises two observable accesses:

1. Read an unsigned byte from a specified selector address.
2. Write a byte to address `0x11` plus the byte read.

The destination therefore lies from `0x11` through `0x110`, inclusive. This is byte-valued address selection, not a full-width pointer load.

### 10. Loop initialization and recurrence

The fixed loop selector address is derived from the retained last byte value:

\[
((\text{last byte value}<<2)\times\texttt{0x400})+1.
\]

Under 32-bit wrapping arithmetic, this equals the last byte value shifted left by 12, plus 1.

Before the loop, the routine performs a selector write of zero using this address. A dependency receives twice the initial loop field. One further dependency supplies the **initial carried argument** directly: this initialization does not shift that result left by 2.

Each iteration starts with a dependency receiving:

- The current carried argument.
- The current loop field logically shifted right by 8.

Four calls with no explicit arguments follow. The routine rereads the fixed loop selector address and writes zero to its selected destination.

A dependency then receives the latest result shifted left by 2. Four more calls with no explicit arguments follow.

The final call’s **raw result** determines two separate next-iteration values:

- The next carried argument is the raw result shifted left by 2.
- The next loop field is the raw result shifted left by 26.

Neither value is the unshifted raw result. The loop repeats unconditionally.

The first iteration’s second argument is zero because the initial field is at most 31. Under 32-bit bit-vector semantics, later second arguments equal the preceding iteration’s raw result masked to six bits and shifted left by 18. The carried argument instead retains the raw result’s low 30 bits, shifted left by 2.

## Acceptance examples

These examples are conditional static expectations, not executed tests.

1. **Initial selection.** First argument `0x00001234` selects address `0x13` for the byte read. A selector byte of `0xA0` makes the destination `0xB1`.

2. **Fresh selector reads.** Selector readings of `0x20` and `0x40` produce destinations `0x31` and `0x51`. Reusing the first selector byte would change the behavior.

3. **Byte truncation.** An initial byte value of `0x12345678` produces first stored byte `0xE0` and later stored byte `0x23`.

4. **Repeated retained word.** Third argument `0x100` produces destination `0x1C`. Both stores use the quantity retained from the single read associated with `0x3C`, even if dependencies modify that source location.

5. **Snapshot aliasing.** Primary index zero makes both the initial primary store and following snapshot read address `0x14`. With ordinary coherent memory and no external interference, the read observes the zero just stored.

6. **High-bit destination.** Primary snapshots `0x7FFFFFFF` and `0x80000000` select `0x1C` and `0x1D`, respectively, for the direct last-byte store.

7. **Separate initialization.** If the dependency immediately before loop entry returns `1`, the first iteration receives first argument `1`, not `4`. Its second argument is zero for every possible initial loop field.

8. **Loop recurrence.** Under 32-bit wrapping semantics, a final raw iteration result of `1` produces next-iteration arguments `4` and `0x00040000`. A raw result of `64` produces arguments `0x100` and zero, demonstrating that the two transformations retain different bits.

9. **Nontermination.** If dependencies always return and accesses succeed, no finite iteration count reaches a normal return.
