# F-1948d97e66b3

## Purpose

F-1948d97e66b3 combines a dependency-mediated update of a three-word temporary record with a byte-table lookup and a conditional one-byte adjustment. It returns a packed 64-bit value containing:

- A 32-bit word taken from the temporary record after the dependency calls.
- A zero-extended byte obtained from the table, optionally decremented modulo 256.

The established behavior is mechanical. The supplied material does not establish what the table entries, record fields, or special selector value mean in the surrounding application.

### 3. Read a byte from the table

After the first dependency returns, the function obtains a table index from the middle record field’s least significant eight bits.

The index is therefore in the range 0–255. The remaining 24 bits do not contribute to the table address.

The function reads one byte at that index from a table reached through a global base value. The byte is interpreted without sign extension, producing a value from 0 through 255.

The global base is consulted after the first dependency call. Thus, a change to that base made by F-a062a6eb1219 can affect the selected table.

There is no visible bounds check, null check, table-size check, or fallback. Normal execution requires the effective address for the selected byte to be readable. ### 4. Conditionally invoke the second dependency

After the table byte has been read, the function checks whether the middle record field’s least significant byte equals 2.

When that byte is not 2:

- F-6985300e27da is not called.
- The table byte is retained unchanged.

When that byte is 2:

- F-6985300e27da is called once.
- Its argument is the middle record field’s upper 16-bit subfield, corresponding to bits 31–16.
- The middle field’s bits 15–8 are not part of this argument.

The supplied material establishes a 16-bit extracted value, but not the dependency’s complete declaration or the machine-level extension rules used to pass it.

The table-index extraction and the later conditional check are separate evaluations in the supplied representation. There is no intervening explicit function call between them. In ordinary sequential execution without an external modification, they observe the same low-byte value. Atomicity, concurrency behavior, and asynchronous modification guarantees are not established.

### 5. Apply the conditional byte adjustment

The second dependency’s result is compared with zero.

- A zero result causes the previously read table byte to be decremented modulo 256.
- Any nonzero result leaves that byte unchanged.

The comparison does not distinguish positive from negative nonzero values.

The adjustment has these boundary behaviors:

- A table byte of 1 becomes 0.
- A table byte of 0 becomes 255.
- A table byte of 255 becomes 254.

The intermediate subtraction is represented as unsigned 32-bit arithmetic, followed by retention of the least significant eight bits. This is wraparound, not saturation, and it does not create an error condition.

The table is not reread after F-6985300e27da returns. Changes that dependency makes to the table or its base do not replace the byte already obtained.

### 6. Construct the result

The function combines the final first record field with the selected or adjusted byte.

The upper 32 bits come from the first field as read during return construction, after any conditional call to F-6985300e27da. The lower 32 bits contain the zero-extended byte.

F-6985300e27da does not directly receive the record address. Nevertheless, the supplied material does not prove that the first field is unchanged by that call: for example, the earlier dependency’s handling of the supplied address is unknown. The contract therefore does not promise preservation of the record across an unknown callee.

The final record field has no direct use in lookup, branching, adjustment, or result construction. It remains observable to F-a062a6eb1219 through the supplied record address and cannot be discarded from the interface contract.
