# F-3475b4980949

## Purpose

F-3475b4980949 conditionally updates a 32-bit position field in a caller-supplied object. It selects an absolute or object-relative candidate position, applies a two-word arithmetic check, and writes the candidate only if its adjusted high word is zero and its low word does not exceed an object-supplied limit.

Two dependencies run before selector validation or position arithmetic. Either can divert execution to an early return. A finalization dependency is called on every explicit return path, using a value held in a writable local slot initialized from the fourth argument.

**Inferred intent:** this resembles a checked position-setting operation supporting absolute, current-relative, and limit-relative modes. The source establishes the arithmetic and field accesses, but does not establish an object type, position unit, resource type, or public meaning for the numeric result codes.

## Behavior

### Entry processing and early exits

The function first initializes a local 32-bit slot from the high component. It passes the slot’s address and the object address to F-3794f888f18b. The dependency’s return value is not used.

The candidate high word remains derived from the original high-component argument. It is not reloaded from the writable slot after this call. A dependency-written slot value therefore affects the later finalization argument, not the shown arithmetic.

The function next calls F-867a1fcaaaab with the object address.

- If its result is nonzero, the function calls F-fd58bea73663 with the current slot value and returns 2.
- If its result is zero, processing continues.

It then calls F-56e2874b0016 with the object address.

- If its result is zero, the function reads the 32-bit field at offset `0x1c`, saves that value as the result, calls F-fd58bea73663, and returns the saved value.
- If its result is nonzero, processing continues to selector handling.

The offset-`0x1c` read occurs before finalization. A change to that field during finalization does not change the already selected return value.

These checks take precedence over selector validation. An unsupported selector does not necessarily produce result 6: either earlier exit can determine the result first.

### Selector handling

After both checks permit continuation:

- **Selector 0:** use the supplied low and high components without adding an object-relative base.
- **Selector 1:** read the unsigned 32-bit field at offset `0x34` and add it to the low component.
- **Selector 2:** read the unsigned 32-bit field at offset `0x20` and add it to the low component.
- **Any other selector:** call F-fd58bea73663 and return 6 without performing the function’s direct position write.

For selectors 1 and 2, the addition produces a 32-bit low result and an unsigned carry-out bit. The low result is the sum modulo \(2^{32}\). The carry bit is added to the high component as a 32-bit word.

The selected base contributes only to the low word. There is no additional base high word.

This is not a saturating addition or a signed displacement comparison. A nonzero input high component is not rejected before the carry adjustment.

### Candidate validation

The candidate is accepted only if both conditions hold:

1. Its adjusted high word is zero.
2. Its unsigned low word is less than or equal to the 32-bit value read from offset `0x20`.

The high-word check comes first. If it fails, the function does not perform the bound read used by the second condition.

For selector 2, offset `0x20` is read once as the relative base. If the adjusted high word is zero, it is read again for the bound check. The body does not retain the first read as the bound.

Equality with the bound is accepted. There is no strict-less-than requirement and no separate lower-bound comparison.

If validation fails, the function calls F-fd58bea73663 and returns 5. It does not perform its direct write to offset `0x34`.

### Successful update

If validation succeeds, the function:

1. Writes the candidate low word to offset `0x34`.
2. Calls F-fd58bea73663 with the current local-slot value.
3. Returns 0.

The position write occurs before finalization. Consequently, finalization can observe the accepted value. Conversely, the supplied body does not establish that the same value remains in the object after finalization: the dependency’s effects are unknown.

### High-word wraparound

The carry adjustment has an important boundary case. An input high word with bit pattern `0xffffffff`, incremented by a carry of one, becomes zero under 32-bit machine-word arithmetic. Such a candidate can pass the high-word check.

For example, a low word of `0xffffffff` plus a relative base of 1 produces low word 0 and carry 1. With input high word `0xffffffff`, the adjusted high word becomes zero. Acceptance then depends on the unsigned bound comparison.

This behavior must not be replaced by a rule that rejects every nonzero input high word.
