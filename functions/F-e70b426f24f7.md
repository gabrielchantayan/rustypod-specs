## Behavior

### Established operation order

The adapter’s visible sequence is:

1. It initializes a separate, invocation-local 32-bit temporary to zero.
2. It reads the 32-bit value at the caller-supplied slot address while preparing the dependency call.
3. It calls F-40c2b44452d1 once, supplying:
   - the first direct value;
   - the second direct value;
   - the value read from the caller’s slot;
   - the address of the zero-initialized temporary.
4. If the dependency returns normally, it reads the temporary’s then-current 32-bit value and writes that value to the caller’s slot.
5. It returns without an explicit result.

The initial slot read therefore precedes execution of the dependency. The final slot write follows normal completion of that dependency call. No particular ordering among otherwise independent argument evaluations is needed to establish this behavior.

### Separate input and result storage

The dependency receives the initial slot contents by value. It does not receive the caller’s slot address through that third argument.

The fourth argument instead addresses separate temporary storage. Thus, the dependency’s supplied result location is not the caller’s slot. The adapter performs the transfer between those locations after the call.

This distinction does not prove that the dependency cannot access the caller’s slot through another route. For example, it could have access through unrelated shared state. Such access is neither shown nor excluded. On a normal return with valid storage, the adapter still performs its own subsequent writeback.
