# F-83ba6e6c8897

## Purpose

F-83ba6e6c8897 writes four 32-bit words into caller-supplied storage, performs two provider-selected indirect calls using interior addresses of that storage, and invokes two further dependencies. Between the final two calls, it writes a separately sampled global value to an address derived from a dependency result. It returns the last dependency’s result reduced by 8.

The first two reads access the same global location, but serve different purposes: the first supplies a retained value for three offset stores; the second supplies the store at the input address. Their values are not established to be equal.

A constructor-like initialization involving embedded object regions is an inferred intent, not an established type or lifecycle contract. The established behavior consists of the accesses, address relationships, call order, and return adjustment below.

This specification is based on static evidence only. No runtime tests have been performed.

## Behavior

### Initial reads and stores

The initial sequence is ordered as follows:

1. Read the initial global location and retain its value as G₁.
2. Read that same global location again, obtaining G₂.
3. Store G₂ as a four-byte word at P.
4. Store G₁ + 80 at P + 72.
5. Store G₁ + 204 at P + 96.
6. Store G₁ + 220 at P + 100.

All four stores complete before the first dependency call.

The first read is not the value source for the store at P. Only the three stores at nonzero offsets necessarily derive from G₁. The second read does not replace the retained value used by those three calculations.

There is no intervening dependency call between the two initial reads. Nevertheless, the supplied representation contains two reads, and this contract does not collapse them into one or assert equality without an additional stability assumption. If both reads observe the same value, all four stores have the corresponding common-base relationship. If they differ, the store at P reflects G₂ while the other three reflect G₁.

Later changes to the initial global do not cause the function to repeat these stores or recalculate their values. This does not prevent dependencies or aliased accesses from changing the destinations themselves.

No other input-relative word is directly initialized by the visible function.

### First provider and indirect call

After the initial stores, the function calls F-cdd33263ee89 without explicit arguments.

It interprets that result as a receiver address. It then:

- Reads the receiver’s leading word to obtain a dispatch-table address.
- Selects the callable entry at byte offset 4 from that table address.
- Invokes the selected target with the receiver and P + 96 as the two explicit arguments.

The second argument is the address of the word initially assigned G₁ + 204. It is not that word’s contents.

The indirect target’s return value is unused. Its side effects may affect later execution. There is no explicit receiver-null check, table validation, target validation, or recovery branch before invocation.

### Second provider and indirect call

### Final dependency sequence

After the second indirect target returns, the function calls F-f8a7a3a1008d with P + 72.

Let **R** denote that dependency’s returned 32-bit value. The function then performs this sequence:

1. Read the second global location, obtaining H.
2. Store H as four bytes at the address R − 72.
3. Call F-3197c19aeae2 with R − 64.

H is sampled after F-f8a7a3a1008d returns. It is not sampled alongside either initial global read. Any earlier dependency may therefore affect the value eventually observed as H, if that dependency can modify the relevant location.

The four-byte destination is derived from R. It is not established to equal P, lie within the input storage, or identify any particular field. The same limitation applies to the argument R − 64.

F-3197c19aeae2 is invoked only after the store at R − 72 in the normal execution sequence. Its side effects are not established to preserve that store.
