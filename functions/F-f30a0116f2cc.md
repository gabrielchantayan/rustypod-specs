# F-f30a0116f2cc

## Purpose

F-f30a0116f2cc performs two sequential, comparison-directed traversals of a linked structure and writes two selected address values into a caller-provided output area.

Both traversals obtain their starting node through a header referenced by the structure argument. Each traversal follows one of two node links according to whether F-257a89ed2c43 returns zero or nonzero. The argument order supplied to that dependency differs between traversals.

The selected values are not necessarily the last nodes compared. On a selection-updating branch, the function first loads a child link and then selects that child address, including zero if the link is null. This distinction is essential to the observable result.

**Inferred intent:** the layout and directional comparisons suggest a search over a tree-like container. Neither tree ordering nor conventional lower-bound, upper-bound, or range semantics are established. The contract below therefore describes the actual traversal and selection behavior without assigning those meanings.

| Comparison operand | Opaque 32-bit value forwarded to the comparison dependency. |

The supplied representation uses 32-bit integer and address-bearing slots. Arithmetic involving those address-bearing values is consequently described under that apparent 32-bit address model. The evidence does not independently establish the executable ABI, byte order, signed-overflow behavior, or behavior when address calculations wrap.

|---|---:|---|

## Behavior

### First traversal

The function first reads the header address from the structure at offset +16 and reads the starting-node address from that header at offset +4.

It then reads the structure’s header-address slot again and uses this second value as the initial first selection. Thus the initial selection comes from a separate header-slot read, not necessarily from the exact header value used to fetch the starting node.

For each nonzero current-node address, the function calls F-257a89ed2c43 with five arguments, in this order:

1. The structure address plus 25 bytes.
2. The current-node address plus 16 bytes.
3. The comparison operand.
4. The auxiliary operand.
5. A zero-valued final argument.

The dependency’s result is tested only for equality to zero.

- **Zero result:** after the dependency returns, read the child address at offset +8 of the current node. That child becomes both the next current node and the first selection.
- **Nonzero result:** after the dependency returns, read the child address at offset +12 of the current node. That child becomes the next current node; the first selection remains unchanged.

A child address of zero ends the traversal at its next termination check. If that zero was obtained through the zero-result branch, the first selection becomes zero as well.

If the starting-node address is zero, there are no dependency calls in this traversal, and the first selection remains the separately loaded header address.

### Second traversal

Only after the first traversal ends does the function initialize the second traversal.

It again reads the header address from the structure at offset +16 and then reads the starting-node address from that header at offset +4. It separately rereads the structure’s header-address slot to initialize the second selection.

These are fresh accesses. The second traversal does not reuse the first traversal’s initial header or starting node.

For each nonzero current-node address, the function calls F-257a89ed2c43 with:

1. The structure address plus 25 bytes.
2. The comparison operand.
3. The current-node address plus 16 bytes.
4. The auxiliary operand.
5. A zero-valued final argument.

Relative to the first traversal, the node-associated address and comparison operand exchange argument positions.

The result controls traversal as follows:

- **Zero result:** read the child address at offset +12 of the current node. That child becomes the next current node; the second selection remains unchanged.
- **Nonzero result:** read the child address at offset +8 of the current node. That child becomes both the next current node and the second selection.

Again, selecting the +8 child can select zero. A zero starting node skips all dependency calls for this traversal and leaves its selection equal to the separately loaded header address.

Negative and positive nonzero dependency results have the same effect. No ordering between nonzero result values is used.

### Output publication

After both traversals terminate, the function writes the first selection at output offset +0. It then writes the second selection at output offset +4.

The function performs no direct output writes before this point. In particular, it does not publish the first selection between traversals.

The two stores are separate and ordered, not an established atomic eight-byte update. If execution fails before publication, neither final output store has been reached. If the first store succeeds but the second fails, a partial result can remain.

### Mutation-sensitive behavior

A dependency call occurs before the branch-specific child read. Consequently, the child value used for the next step is read after any dependency effects. It is not a child link cached before the call.

Likewise, changes made during the first traversal can affect the header and starting node obtained for the second traversal. The function supplies the same structure-relative context address to every call, but does not establish that the memory there remains unchanged.

The contract does not assume that F-257a89ed2c43 preserves globals, leaves the linked structure unchanged, or refrains from accessing aliased output memory.

## Side effects

The function’s directly visible memory effects are:

- Repeated reads of the structure’s header-address slot.
- One starting-node read for each traversal.
- One child-link read after each normally returning dependency call.
- Two ordered 32-bit output writes after both traversals finish.

Each completed traversal reads the structure’s header-address slot twice: once to locate its starting-node slot, and once to initialize its selection. The supplied representation imposes no synchronization around these accesses.

The function itself contains no visible allocation, release, link update, or ownership transfer. Its two output values are copied addresses, not copies of the referenced records.

Ownership effects of dependency calls are unknown. In particular, validity cannot be justified by assuming the dependency will preserve or retain a node. If it invalidates the current node before the subsequent child read, the visible function has no recovery mechanism.

Output aliasing is not checked. If the output area overlaps the structure or linked records, the final stores can overwrite those objects after traversal. No further traversal reads occur after those stores begin. Dependency access through other aliases can still affect the output area earlier.

No status code, exception translation, retry, rollback, cycle detection, or iteration limit is visible. Cyclic links or state changes can prevent termination. An inaccessible header or node is not treated as an empty structure.

## Acceptance examples

The following are conditional acceptance cases, not reports of executed tests. Unless stated otherwise, assume valid memory, stable links and header values, normally returning dependency calls, and a disjoint output area.

### Empty starting structure

The structure references header **H**, and H’s starting-node slot is zero.

Both traversals skip their loops. No dependency calls occur. The output receives **H** at offset +0 and **H** at offset +4.

This case requires a readable header; it does not establish support for a null header address.

### One node with null children

Header **H** starts at node **A**, whose +8 and +12 child addresses are both zero.

The dependency is called once in each traversal, with the second and third arguments exchanged between those calls.

| First-call result | Second-call result | Output +0 | Output +4 |
|---|---|---|---|
| Zero | Zero | Zero | H |
| Zero | Nonzero | Zero | Zero |
| Nonzero | Zero | H | H |
| Nonzero | Nonzero | H | Zero |

This demonstrates that an output can remain the header or become zero even though a real node was visited.

### First traversal retains a previously selected child

Header **H** starts at **A**. A’s +8 child is **B**, and B’s +12 child is zero.

If the first traversal receives zero at A and nonzero at B, it selects B while moving from A to B, then terminates through B’s +12 link without changing that selection. The first output is **B**.

The selected value is the loaded child address from the earlier step, not an unconditional record of the most recently compared node.

### Second traversal retains a previously selected child

Header **H** starts at **A**. A’s +8 child is **B**, and B’s +12 child is zero.

If the second traversal receives nonzero at A and zero at B, the second output is **B**. The first step updates the selection; the second does not.

### A later selection update replaces a nonzero selection with zero

In the preceding first-traversal example, instead give B a zero +8 child and have its comparison return zero.

The traversal first selects B, then selects B’s null +8 child. The first output is zero, not B.

The corresponding replacement occurs in the second traversal when successive nonzero results follow +8 links ending at zero.

### Dependency changes the chosen link

At a node, suppose the dependency changes that node’s +8 child from **B** to **C**, returns zero during the first traversal, and leaves the node readable.

The function reads and follows **C**, and sets the first selection to C. Following the earlier value B would contradict the established read order.

### Header changes between traversals

Suppose a first-traversal dependency call changes the structure’s header reference from **H1** to **H2**, and the first traversal subsequently terminates.

The second traversal obtains its starting node through H2 under otherwise stable memory. It does not restart through a cached H1.

### Nonterminating cycle

Suppose the chosen child links repeatedly return to a previously visited node and the dependency continues returning outcomes that follow that cycle.

No cycle handling is established. If the first traversal never terminates, the second traversal and the function’s final output stores are never reached.
