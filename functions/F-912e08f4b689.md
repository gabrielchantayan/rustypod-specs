# F-912e08f4b689

## Purpose

F-912e08f4b689 dispatches a selected record according to a one-byte discriminator, performs branch-specific dependency calls, and optionally performs a final notification-like operation.

Three discriminator values have defined paths:

- **0:** Query a related object, then choose between `GotoSongs` and `GotoAlbums`.
- **1:** Perform a payload-dependent preparation sequence, then select `GotoSongs`.
- **2:** Pass the payload to a separate operation, then select `GotoNowPlaying`.

Other discriminator values skip the branch-specific work but still permit the optional final operation.

The names `GotoSongs`, `GotoAlbums`, and `GotoNowPlaying` are established literal inputs to a dependency. Their interpretation as navigation commands is inferred intent, not established behavior of the callees.

On every path that reaches the ordinary return, the function returns the 32-bit value **1**. It does not report branch selection or dependency success through its return value.

## Interface

### Inputs

The function receives three arguments:

| Argument | Representation | Established use |
|---|---|---|
| Receiver | Pointer to a word-addressed object | Supplies a context word at byte offset `0xBC` and, on recognized branches, an indirect-call table through its first word. |
| Selection token | Opaque 32-bit value | Passed unchanged to F-f953a0fa761b together with the receiver’s context word. |
| Final-operation flag | 32-bit integer | Compared with zero after branch-specific work. Any nonzero bit pattern enables the final operation. |

The selected-record pointer is obtained from F-f953a0fa761b. Its accessed layout is:

| Byte offset | Width | Meaning within this function |
|---|---:|---|
| `0` | 32 bits | Opaque payload, read only on discriminator paths 0, 1, or 2. |
| `4` | 8 bits | Discriminator. Values 0, 1, and 2 select the recognized paths. |

The function does not establish any record size beyond the locations it accesses. Padding, alignment guarantees, additional fields, and allocation ownership are unknown.

### Output

The ordinary return is a 32-bit value equal to **1**.

There are no explicit output-pointer arguments. Observable results instead arise from dependency calls, indirect calls, and any changes those operations make to objects or global state.

## Behavior

### Entry and record selection

The following order is established:

1. Call F-6a21f4f07f67 with no explicit arguments and retain its 32-bit result.
2. Read the receiver’s 32-bit context word at byte offset `0xBC`.
3. Call F-f953a0fa761b with that context word and the selection token.
4. Capture two global values: a pointer later used to read a text-source word, and a separate 32-bit value later supplied to F-e475f4597093.
5. Read the selected record’s discriminator byte at offset `4`.
6. Select a discriminator-specific path.

The two captured global values are obtained **after** record resolution, not at function entry. They are captured even for an unrecognized discriminator.

Capturing the text-source pointer does not also capture the word to which it points. That word is read later, on paths that invoke F-e475f4597093, after intervening dependency calls.

### Discriminator 0: query-dependent selection

First, read the receiver’s context word again and read the selected record’s payload word. Pass both to F-b37ec8581a14, together with local result storage.

Next:

1. Read the context word again.
2. Call F-539e23175fcb with separate local storage and that context.
3. Pass this storage to F-e38e6836b640 to obtain an object.
4. Read that object’s dispatch-table pointer, then invoke the entry at byte offset `0x110`.
5. Interpret the returned value as an **unsigned 32-bit quantity**.
6. Call F-561858688f94 on the storage supplied to F-539e23175fcb.

The query result is compared with 2 using unsigned ordering. Thus, precisely 0 and 1 select the lower branch. Every other 32-bit result, including values whose high bit is set, selects the upper branch.

#### Query result below 2

The function:

1. Reads the receiver context again and calls F-d2c4bc470bc1 with local result storage, that context, and a 32-bit zero.
2. Calls F-b9acea4b06ad using separate temporary storage and a source address four bytes beyond the local result-storage base used in the preceding step.
3. Calls F-664473a81df4 with the result retained from the entry call to F-6a21f4f07f67 and the temporary supplied to F-b9acea4b06ad.
4. Calls F-289ec4311c64 on that temporary.
5. Performs the shared publication sequence described below.
6. Constructs a value from `GotoSongs`, invokes the receiver’s indirect entry at byte offset `0x11C` with that value, and calls F-8a5aadac202f on the construction storage.
7. Calls F-ee5919ca4be6 on the local result storage used for F-d2c4bc470bc1.
8. Calls F-ee5919ca4be6 on the earlier storage used for F-b37ec8581a14.

The zero passed to F-d2c4bc470bc1 is independent of the selected record’s payload.

#### Query result at least 2

The function:

1. Calls F-b9acea4b06ad using temporary storage and a source address four bytes beyond the result-storage base previously supplied to F-b37ec8581a14.
2. Calls F-664473a81df4 with the retained entry result and that temporary.
3. Calls F-289ec4311c64 on the temporary.
4. Performs the shared publication sequence.
5. Constructs a value from `GotoAlbums`, invokes the receiver’s indirect entry at byte offset `0x11C` with that value, and calls F-8a5aadac202f on the construction storage.
6. Calls F-ee5919ca4be6 on the storage originally supplied to F-b37ec8581a14.

This branch does not invoke F-d2c4bc470bc1.

### Discriminator 1: payload-dependent preparation

2. Calls F-664473a81df4 with the retained entry result and that temporary.

This path does not perform the indirect query at offset `0x110`, and does not call F-b37ec8581a14.

### Shared publication sequence

Discriminator 0 and discriminator 1 paths use this sequence, after F-289ec4311c64 and before constructing their destination value:

1. Read the receiver context.
2. Call F-539e23175fcb with local wrapper storage and that context.
3. Pass the wrapper storage to F-e38e6836b640 and retain its result.
4. Read one 32-bit word through the text-source pointer captured near entry.
5. Call F-9b9c1c7483f4 with local construction storage, that word, and an auxiliary local-storage address.
6. Call F-e475f4597093 with:
   - the separate global value captured near entry;
   - the return value from F-9b9c1c7483f4;
   - the result obtained from F-e38e6836b640.
7. Call F-8a5aadac202f on the construction storage.
8. Call F-561858688f94 on the wrapper storage.
9. Read the receiver context again.
10. Call F-539e23175fcb using wrapper storage.
11. Obtain a global destination value and call F-4fbcfd10cfdf with that value and the wrapper-storage address.
12. Call F-561858688f94 on the wrapper storage.

The second wrapper preparation is a fresh dependency call. It is not replaced by reuse of the first extraction result.

For the subsequent destination construction, F-9b9c1c7483f4 receives the relevant literal, construction storage, and an auxiliary local-storage address. Its return value is passed to the receiver’s indirect entry at offset `0x11C`; the receiver itself is also an explicit argument to that call.

### Discriminator 2: direct payload operation

The function:

2. Calls F-8a3da6f5f0f8 with the receiver, payload, and a 32-bit zero.
3. Calls F-9b9c1c7483f4 using `GotoNowPlaying`, local construction storage, and auxiliary local storage.

### Other discriminator values

Every discriminator byte other than 0, 1, or 2 skips all recognized-branch work.

The selected payload is not explicitly read on this path. The initial service lookup, record resolution, two global captures, and discriminator read have already occurred.

### Optional final operation

After branch work and its explicit cleanup calls, the function checks the third argument.

If it is nonzero:

1. Read a 32-bit word at byte offset `8` through a global base pointer.
2. Call F-9b9c1c7483f4 with that word and local construction and auxiliary storage.
3. Call F-2b88fb7b0f1e with another global value, the construction helper’s return value, and a further local-storage address.
4. Call F-8a5aadac202f on the construction storage.

If the flag is zero, none of these calls occurs.

The function then returns 1. This final operation also applies to unrecognized discriminators.

## Side effects

### Direct accesses and indirect effects

The visible body reads receiver fields, selected-record fields, dispatch tables, and globals. It makes no explicit direct assignment to receiver fields, selected-record fields, or global storage.

This is not a guarantee that those locations remain unchanged. Any dependency or indirect call may mutate accessible objects or globals. In particular:

- The context word is read repeatedly; later calls can receive a different context from earlier calls if intervening dependencies change it.
- The text-source pointer and publication target captured near entry remain the captured values, but the word read through that pointer is obtained later.
- The publication destination and final-operation globals are used later in the sequence; they are not established as entry snapshots.
- The receiver’s dispatch table is accessed when each destination call occurs, after preceding dependency calls.

### Temporary storage and ownership

The function supplies local storage to several dependencies and later invokes paired operations on that storage. The observed pairs include:

- F-b9acea4b06ad followed by F-289ec4311c64.
- F-539e23175fcb followed by F-561858688f94.
- F-9b9c1c7483f4 followed by F-8a5aadac202f.
- F-b37ec8581a14 or F-d2c4bc470bc1 followed, on the relevant path, by F-ee5919ca4be6.

These pairings suggest construction/use/cleanup lifetimes. They do **not** establish allocation, reference counting, ownership transfer, or whether any operation frees memory.

No explicit deallocation of the selected-record pointer or receiver is shown. Dependencies may nevertheless affect their lifetimes; preservation is not established.

Several helper inputs are addresses into adjacent local storage, including addresses four bytes beyond earlier result-storage bases. Their semantic types and required initialization are unknown. The supplied representation does not justify treating every displayed local region as an independent complete object.

These examples are conditional static acceptance criteria, not executed tests. They assume valid memory and normal dependency returns.

1. **Discriminator 0, query returns 0 or 1, final flag zero.**  
   F-d2c4bc470bc1 receives zero, the shared publication sequence occurs, and the destination literal is `GotoSongs`. Its result storage is passed to F-ee5919ca4be6 before the earlier F-b37ec8581a14 storage. No final-operation calls occur. The return is 1.

3. **Discriminator 0, query returns `0xFFFFFFFF`.**  
   Unsigned comparison selects the same branch as a return of 2, not the branch for values below 2.

4. **Discriminator 1 with payload `0xFFFFFFFF`.**  
   F-d2c4bc470bc1 receives that 32-bit payload unchanged. No signed interpretation or payload-dependent branch is visible. The destination literal is `GotoSongs`.

5. **Discriminator 2 with a nonzero final flag.**  
   F-8a3da6f5f0f8 receives receiver, payload, and zero. The `GotoNowPlaying` destination call and its cleanup precede the optional final construction and F-2b88fb7b0f1e call.

6. **Discriminator 3 with final flag zero.**  
   Entry acquisition and record resolution occur, but there is no branch-specific payload read, publication, destination call, or final operation. The return is 1.

7. **Discriminator 255 with final flag nonzero.**  
   The discriminator is unrecognized regardless of whether the byte is represented as signed or unsigned. The final operation still occurs.

8. **An intervening dependency changes the receiver context.**  
   A later explicit context read observes the then-current word. Acceptance must not require all context-dependent calls to receive the original context.

9. **An intervening dependency changes the word behind the captured text-source pointer.**
