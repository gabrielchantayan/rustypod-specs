# F-5304459ebc2d

## Purpose

F-5304459ebc2d traverses a pointer-linked structure, optionally adjusts and checks a candidate position, and either returns that candidate or delegates an operation to F-bc5730ead9fe.

It writes a two-field result: a 32-bit word followed by a one-byte status. Status 0 identifies the existing-candidate path. Status 1 identifies a path that called F-bc5730ead9fe; it does not independently establish successful insertion, allocation, or any particular ownership transfer.

An ordered-tree search with optional duplicate detection is inferred intent. The established contract consists of the accesses, decisions, calls, and writes below. Dependency implementations and structural invariants are not supplied.

### Result layout

Normal completion writes:

1. The 32-bit result word at offset 0.
2. The status byte at offset 4.

The function does not directly write result bytes beginning at offset 5. It does not atomically publish the combined result.

Two distinct local 32-bit words can serve as delegated output storage:

- The **early-output word**, used only by the early delegation.
- The **final-output word**, used by the final delegation and also exposed to the boundary dependency.

Their initialization is path-dependent. An unwritten delegated output is therefore not universally indeterminate and not universally zero.

## Behavior

### Initialization and search

The initial decision is the 32-bit integer value 1.

The function first reads the context pointer at offset 0x10, then reads the referenced header’s pointer at offset 4 to obtain the current search position. It separately rereads context offset 0x10 to obtain the retained position. These are distinct context reads, not one guaranteed snapshot.

For every non-null search position, the following ordering applies:

1. Both the early-output word and final-output word are set to 32-bit zero.
2. F-3a00e7887b9d is called with:
   - context address plus 0x19;
   - the original supplied operand;
   - current position plus 0x10.
3. The current position becomes the retained position.
4. A link is read from that position:
   - zero comparison result selects offset 0x0c;
   - nonzero comparison result selects offset 8.
5. The selected link becomes the next search position.

The dependency result is used only as zero versus nonzero. Negative and positive nonzero results select the same branch.

The link read occurs after the comparison call. Mutations performed by that call can therefore affect the next position. No outgoing link is snapshotted beforehand.

If the initial search position is null, no search comparison occurs, neither output word is initialized by the loop, the decision remains 1, and the retained position remains the separately read header address.

There is no traversal limit or cycle detection.

### Mode selection

After traversal terminates, the function reads the byte at context offset 0x18.

A nonzero byte leads directly to final delegation. It skips the boundary dependency, candidate adjustment, extraction dependency, and final comparison.

A zero byte enables candidate checking. The initial candidate is the retained position.

Because mode is read after traversal, dependency changes to that byte during search can affect the selected path.

### Boundary dependency

This stage occurs only when mode is zero and the last search decision is nonzero. The initial decision of 1 also sends an empty search through this stage.

The function:

1. Rereads the header pointer from context offset 0x10.
2. Reads the 32-bit word at that header’s offset 8.
3. Stores that word into the final-output word, replacing any prior contents.
4. Calls F-f69853ed0279 with:
   - the address of the writable candidate-position slot;
   - the address of the final-output word.

These arguments are writable local-storage addresses, not merely position values. The dependency can modify either object.

If F-f69853ed0279 returns nonzero, the function immediately delegates using the early-output word. It passes the retained search position, not the candidate as potentially modified by the boundary dependency. No candidate adjustment, extraction, or final comparison follows.

If the dependency returns zero, adjustment starts with the candidate slot’s post-call contents. The final-output word retains the header-derived value or whatever value the dependency left there; it is not reset before final delegation.

Changing the candidate slot does not by itself change the separately retained position.

### Candidate adjustment

Adjustment occurs only after a zero boundary result.

First, the function reads the candidate’s byte at offset 0.

If that byte is zero, it follows the candidate’s pointer at offset 4 and reads the referenced object’s pointer at offset 4. If that second pointer equals the candidate, the candidate is replaced by its pointer at offset 0x0c.

Otherwise, including when the initial byte is nonzero, the function examines offset 8:

- It reads candidate offset 8 into a traversal position.
- It separately reads candidate offset 8 again to decide whether to ascend or descend.

With stable fields, a non-null offset-8 link leads to that object, followed by repeated offset-0x0c links until a null link is encountered. The last reached object becomes the candidate.

The descending path performs two offset-0x0c reads per visited object: one obtains the next traversal position, and another controls continuation. These are not a single cached read.

With a null offset-8 link, the function starts at candidate offset 4. At each ascent step, it:

- reads the upward object’s offset-8 pointer and compares it with the current candidate;
- replaces the candidate with the upward object regardless of the comparison result;
- continues through the upward object’s offset-4 pointer only if the comparison matched.

Thus, the candidate is updated even on the comparison that ends ascent.

There is no null check before dereferencing an upward object. Valid sentinel and upward-link invariants are prerequisites for this path.

The stable-field description does not promise coherent behavior under concurrent mutation. In particular, the repeated reads can observe different values.

### Final candidate comparison

This stage occurs with zero mode when either:

- the last search decision was zero; or
- the boundary dependency returned zero and adjustment completed.

F-c24fe29dbbd8 is called with the current candidate. Its returned 32-bit word is passed to F-3a00e7887b9d as follows:

1. Context address plus 0x19.
2. The word returned by F-c24fe29dbbd8.
3. The original supplied operand.

This operand order differs from search: search supplies the original operand second and an object-relative address third.

A zero final comparison causes the function to write the candidate as the result word and status 0. F-bc5730ead9fe is not called.

A nonzero final comparison leads to final delegation.

### Delegation and output initialization

Both delegation sites call F-bc5730ead9fe with five arguments:

1. Address of the selected 32-bit output word.
2. Original context address.
3. A literal zero.
4. Retained search position.
5. Original supplied operand.

The retained position is the last visited search object, or the separately read header address for an empty search. Candidate adjustment does not replace it.

The early site supplies the early-output word. The final site supplies the final-output word. After the dependency returns, the selected word is copied to result offset 0 and status 1 is written at offset 4. The dependency’s own return value is unused.

The selected output word’s prior contents are:

| Search and path | Selected word | Prior contents established by this function |
|---|---|---|
| Nonempty search, early delegation | Early-output word | Zero, initialized during the last search iteration. |
| Empty search, early delegation | Early-output word | No initialization. |
| Nonempty search, nonzero mode | Final-output word | Zero, initialized during the last search iteration. |
| Empty search, nonzero mode | Final-output word | No initialization. |
| Nonempty search, zero last decision, zero mode, nonzero final comparison | Final-output word | Zero; its address was not supplied to earlier calls on this path. |
| Boundary result zero, then nonzero final comparison | Final-output word | Later-read header-offset-8 word, subject to modifications by dependencies given access to it. |

The last row applies to both empty and nonempty searches. The boundary-stage assignment replaces the loop’s zero when the search was nonempty and supplies an initialized value when it was empty.

If F-bc5730ead9fe writes only some bytes, untouched bytes retain the selected word’s prior contents, insofar as those contents are established. Their numerical contribution depends on byte order. If it writes nothing, the entire prior word is copied.

The function does not check whether the dependency wrote the output. In particular, an empty-search early delegation or an empty-search nonzero-mode delegation has no established fallback value.

## Side effects

### Direct writes and read ordering

The function directly writes local storage and the caller’s two result fields. It contains no direct store to the context, header, or traversed objects.

Dependencies may nevertheless mutate those objects, other state, or memory reachable through their arguments. No dependency is established to preserve globals.

The result word is copied before the status byte is written. Internal preparation of the status does not replace or truncate the already copied 32-bit result.

Repeated header reads, post-comparison link reads, and repeated adjustment-link reads are separate accesses. The contract does not replace them with a stable snapshot.

### Ownership and lifetime

There is no explicit allocation or release in this function. Ownership of a returned position is not established.

Status 0 does not guarantee the selected object remained alive through dependency activity. Status 1 does not prove that the returned word identifies newly allocated memory.

Addresses of local candidate and output storage are valid during the relevant calls. Whether dependencies retain these addresses, access them again during later calls, or impose additional lifetime requirements is unknown. No permission for use after this function returns is established.

### Preconditions and failures

Normal completion requires readable selected-path fields, writable result storage covering offsets 0 through 4, terminating traversals, valid links for adjustment, and normally returning dependencies.

The function has no explicit:

- null-argument or storage-size checks;
- link validation;
- recoverable error channel;
- verification that delegated output was written;
- exception or nonlocal-exit handling.

The output word and context fields may alias; no non-aliasing guarantee is supplied. Final result writes can modify context or object storage if the caller overlaps them.

Address calculations use fixed byte offsets in a 32-bit address model. No checked-overflow behavior is established. Malformed addresses, invalid pointers, and inconsistent links have no documented successful outcome.

## Acceptance examples

These are conditional static contracts, not runtime observations. They assume valid memory, terminating links, normally returning dependencies, and no mutations beyond those specified.

1. **Search branch and initialization.**  
   For each visited object, both output words are zeroed before the search comparison. A zero comparison selects the subsequently read offset-0x0c link; a nonzero comparison selects offset 8.

2. **Nonzero mode bypass.**  
   If mode is nonzero after traversal, final delegation receives the retained position. Neither F-f69853ed0279 nor F-c24fe29dbbd8 is called. If the delegated dependency writes P, the result is P with status 1.

3. **Existing candidate.**  
   With zero mode and a zero last search decision, the retained position is checked without boundary processing or adjustment. If the final comparison returns zero, that candidate is returned with status 0 and no delegation.

4. **Untouched zero-initialized final output.**  
   A nonempty search ending with a zero decision, followed by zero mode and a nonzero final comparison, reaches final delegation with a zero-initialized output word not previously exposed by address. If F-bc5730ead9fe leaves it untouched, the result word is zero and status is 1.

5. **Untouched early output.**  
   After a nonempty search, a nonzero boundary result selects early delegation. If that delegation leaves its output untouched, zero is returned with status 1. The header-derived value placed in the other output word is not returned.

6. **Empty-search early output.**  
   With an empty search, zero mode, and a nonzero boundary result, early delegation uses an uninitialized output word. If the dependency leaves it untouched, no specific result word is established. Status 1 still identifies the delegated path.

7. **Boundary-derived final output.**  
   Suppose the boundary-stage header word is H, the boundary dependency changes the final-output word to Q and returns zero, and the eventual final comparison is nonzero. If later calls do not alter that word and final delegation leaves it untouched, Q is returned with status 1. Without the boundary modification, H would remain.

8. **Partial delegated write.**  
   On a zero-initialized output path, if delegation changes only one byte, every untouched byte remains zero. On a boundary-derived path, untouched bytes instead retain the corresponding bytes of the post-boundary word. No byte-order assumption is required for this bytewise rule.

9. **Adjusted candidate versus retained position.**  
   If adjustment changes candidate A to B and the final comparison is nonzero, delegation still receives retained search position A. If the final comparison is zero, B is returned with status 0.

10. **Result footprint.**  
    With ordinary non-overlapping result storage, the function writes four bytes at offset 0 followed by one byte at offset 4. It does not directly initialize a larger aggregate.

## Uncertainties

The following remain **documented_only**:

- Exact structure type, sentinel convention, ordering relation, and mode meaning.
- Representation and size of values addressed at object offset 0x10.
- Dependency mutation, allocation, release, ownership, exception, and output-completeness contracts.
- Whether previously exposed local storage is accessed again through retained aliases during later calls.
- Byte order, alignment requirements, malformed-address arithmetic, and concurrent-mutation behavior.
- The result word when delegation leaves bytes untouched that this function never initialized.

The last uncertainty is path-specific. Nonempty search paths establish zero initialization; boundary paths establish a header-derived word before possible dependency modification. Neither can be treated as universally uninitialized. Conversely, empty-search early delegation and empty-search nonzero-mode delegation have no established initial output value.
