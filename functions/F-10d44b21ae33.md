# F-10d44b21ae33

## Purpose

F-10d44b21ae33 processes selectors and publishes two staged four-byte values into an indexed slot of one of two destination banks. Each completed publication updates the selected bank’s signed high-water count.

Processing terminates when:

- The full selector equals 0x000000FF.
- Either result-producing call returns zero.
- A context status read following a nonzero result yields a nonzero value.

The terminal-selector path updates two context fields instead of publishing a slot.

These are established operations, not statements about application intent. The evidence does not establish that selectors are bytes, that result-producing calls allocate memory, or that publication transfers ownership.

## Behavior

### Initial calls and capture

The function first calls F-fbfa6017b0f5 three times, in order.

The first two results are discarded locally. Those calls still occur, and their side effects are not reversed. The third result becomes the first 32-bit selector.

Only after the third call returns does the function capture the external request value and then the external context address. Therefore, all three initial calls can affect the values subsequently captured.

No context status check precedes these calls or immediately follows capture.

### Terminal-selector path

At the beginning of each iteration, the full 32-bit selector is compared with 0x000000FF.

If equal, the function:

1. Reads the four-byte field at context offset 0x88.
2. Shifts that value left by eight bits, combines it with 0xFF using bitwise OR, and writes the resulting four-byte value to offset 0x88.
3. Reads the signed four-byte field at context offset 0x84.
4. Subtracts one and writes the result to offset 0x84.
5. Returns.

For values where the represented signed operations are defined, the accumulator receives an all-ones low byte after shifting, and the counter decreases by one. Signed shift and subtraction boundary cases remain unresolved.

This path does not directly inspect status, call F-638beded7699 or F-98f82ca8bdf3, access the destination, or fetch another selector.

The comparison is not confined to the low byte. Selector 0x000001FF is nonterminal.

### First result and first status checkpoint

For a nonterminal selector, the slot is established from its low four bits.

The function calls F-638beded7699 with:

- First argument: the captured four-byte request value.
- Second argument: zero.

After the call returns, its four-byte result is written to context offset 0x44. The returned result itself is then tested for zero.

If zero, the function writes decimal 12 to context offset 0x34 and returns. It does not first read status on this branch. Thus, status 12 replaces any status previously present or written by the dependency.

If the result is nonzero, the function reads status at context offset 0x34. A nonzero status causes immediate return. A zero status permits the second result call.

A nonzero entry status does not prevent the first result call. The first checkpoint occurs only after a nonzero result has been stored.

### Second result and second status checkpoint

The second F-638beded7699 call receives:

- First argument: decimal 436, equivalent to 0x1B4.
- Second argument: zero.

After this call returns, its four-byte result is written to context offset 0x48. The returned result itself is tested for zero.

If zero, status is assigned decimal 12 and the function returns without a status read.

If nonzero, the function reads status at context offset 0x34. Nonzero status causes return; zero permits preparation and publication.

The second dependency call may modify the first staging field before returning. The function does not restore context offset 0x44 after that call, regardless of whether the call returns zero or nonzero. Consequently, reaching either second-call exit does not guarantee that the original first result remains staged.

There is no explicit rollback or release operation on either result-failure path or either status-driven exit.

### Preparation and publication inputs

After both results are nonzero and both status reads yield zero, the function calls F-98f82ca8bdf3 with no explicit arguments.

After that call returns, it reads the destination address from context offset 0x20. This address is used for the current publication.

The function does not check status after preparation. A status change made by preparation therefore does not, by itself, stop publication.

Publication reads the staging fields from context memory rather than using only the original dependency returns. Preparation can change the destination address, either staged value, or other reachable state. Such changes can affect subsequent publication.

### Bank selection

The bank is selected using bits 4 through 7 of the selector:

- All zero: zero-high-nibble bank.
- Any nonzero value: nonzero-high-nibble bank.

No distinction is made between different nonzero high-nibble values.

Bits above bit 7 affect the earlier terminal equality test but do not affect bank or slot selection.

### Ordered destination writes

For the selected bank, the function:

1. Reads context offset 0x44 and writes that four-byte value to the first-value slot.
2. Reads context offset 0x48 and writes that four-byte value to the second-value slot.
3. Reads the bank’s signed 32-bit count.
4. Writes the greater of that count and `slot + 1` back to the count field.

The candidate count is between 1 and 16. It does not approach signed 32-bit overflow.

The count write occurs even when the existing count is retained. Negative counts become the positive candidate. Counts larger than 16 are not clamped.

The first slot write precedes the second staging read. If destination storage overlaps context offset 0x48, that first write can change the second published value. Earlier slot writes can likewise affect the later count read if storage overlaps. The function neither detects nor compensates for such aliasing.

After the count write, F-fbfa6017b0f5 is called once to obtain the next selector. Processing then returns to the full-width terminal comparison.

There is no explicit iteration limit.

## Side effects

### Direct writes and partial progress

The function’s direct writes depend on the path:

- After each first result call, it writes that call’s result to context offset 0x44.
- After each second result call, it writes that call’s result to context offset 0x48.
- On either zero-result branch, it writes decimal 12 to context offset 0x34.
- On each completed ordinary iteration, it writes two destination slots and the selected count.
- On the terminal path, it writes context offsets 0x88 and 0x84.

These statements identify direct operations, not preservation guarantees:

- On first-result failure, the function writes zero to offset 0x44 and then writes status 12. It does not directly write offset 0x48 on that path, but the first dependency call may have changed it.
- On second-result failure, the function writes zero to offset 0x48 and then status 12. It does not restore offset 0x44; the second call may already have changed that field.
- On a status-driven exit, the result write preceding the status read has occurred. Earlier staging writes are not explicitly rolled back, but intervening dependency mutations are not reversed.
- Completed iterations receive no explicit rollback. Their destination contents are not guaranteed to survive later dependency mutations, repeated-slot publications, or overlapping writes.

## Acceptance examples

These are conditional static consequences, not executed tests. Unless an example states otherwise, assume valid non-overlapping storage, defined arithmetic, normally returning dependencies, and no dependency mutations beyond those specified.

### Immediate terminal selector

If the third initial selector is 0xFF, accumulator offset 0x88 contains 0x00001234, and counter offset 0x84 contains 7:

- Exactly three selector calls occur.
- No result-producing or preparation call occurs.
- The accumulator becomes 0x001234FF.
- The counter becomes 6.
- The function makes no direct status or destination writes.

A nonzero status does not change this path.

### Zero-high-nibble publication

For selector 0x03, two nonzero results, zero status at both checkpoints, and an existing selected count of 2:

- The calls use the captured request and then 436, each with second argument zero.
- Preparation precedes publication.
- Slot 3 receives the staged values at destination offsets 0x124 and 0xE4.
- The count at offset 0xD4 becomes 4.
- One additional selector call occurs.

If the existing count is 9, the count is written back as 9. If it is negative, it becomes 4.

### Nonzero-high-nibble publication

For selector 0xA2 and successful checkpoint conditions:

- Slot 2 of the nonzero-high-nibble bank is selected.
- The first value is written at destination offset 0x9C.
- The second value is written at destination offset 0x5C.
- The count at offset 0x50 is updated to the signed maximum of its value when read and 3.

### First-result failure

For any nonterminal selector, if the first result is zero:

- Offset 0x44 is directly written with zero.
- Status is assigned 12 even if it previously held another nonzero value.
- No second result call, preparation call, destination publication, or next-selector call occurs.

No preservation claim is made for other fields that the first dependency call could mutate.

### Second-result failure with mutation

Suppose the first result is nonzero, its status checkpoint is zero, and the second dependency call changes offset 0x44 to another value before returning zero:

- Offset 0x48 is directly written with zero.
- Status is assigned 12.
- The function does not restore the original first result at offset 0x44.
- No preparation or publication occurs.
- No explicit resource release occurs.

Under the stated non-overlap and mutation assumptions, the dependency-written value remains at offset 0x44 on return.

### Status-driven exits

If the first call returns nonzero and the subsequent status read yields 5, its result is staged before return. The function does not directly replace status 5.

If the second call returns nonzero, changes offset 0x44, and leaves status nonzero, its result is written to offset 0x48 before return. The function neither restores offset 0x44 nor calls preparation.

### Preparation changes inputs

If preparation replaces the destination address and both staging values, publication uses the replacement address and the subsequently read staging values.

If preparation also sets status nonzero, publication still proceeds, provided subsequent accesses remain valid. There is no post-preparation status checkpoint.

### Wider selectors

Selector 0x000001FF is nonterminal and selects slot 15 of the nonzero-high-nibble bank. Successful publication proposes count 16.

Selector 0x00000100 is nonterminal and selects slot 0 of the zero-high-nibble bank.

### Later mutation of earlier publication

If a completed iteration publishes a slot and the next selector call changes that slot, the function does not restore the earlier publication. Likewise, a later successful iteration selecting the same bank and slot writes that slot again.
