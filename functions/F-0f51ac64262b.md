# F-0f51ac64262b

## Purpose

F-0f51ac64262b conditionally rewrites a structure consisting of a two-word descriptor and nodes linked through their first word. Its apparent intent is to unlink a specified node from a singly linked sequence, maintain a cached final-node reference, and clear the specified node’s link.

That intent is not the complete behavioral contract. Established behavior also includes:

- A null target causes an immediate return without accessing the descriptor.
- A nonnull target with a null descriptor head causes a return without clearing the target’s link.
- A target not found in a terminating, nonempty chain still has its first word cleared.
- The third argument does not affect the outcome.
- The function does not validate membership, descriptor consistency, address validity, or absence of cycles.

The linked-sequence interpretation is inferred from the accesses. The contract below distinguishes that interpretation from the actual reads, writes, and branches.

## Interface

### Arguments

The function accepts three pointer-valued arguments:

1. **Descriptor reference.** Identifies storage accessed as consecutive 32-bit words:
   - Offset 0: interpreted as the first-node reference.
   - Offset 4 bytes: interpreted as a cached final-node reference.

2. **Target reference.** Identifies the node whose first 32-bit word may be cleared. A null target is explicitly supported.

3. **Auxiliary reference.** Has no effect on observable behavior established by the supplied source. When the target is nonnull, this argument’s local value is replaced with the descriptor’s first-node reference before any consequential use. When the target is null, execution returns without using it.

The function has no explicit result value or status output.

### Node layout

Only the first 32-bit word of a node is accessed. That word is interpreted as the next-node reference. No payload, previous-node reference, size, allocation metadata, or ownership field is accessed.

The descriptor’s two words and each node’s first word are four bytes wide. Zero represents a null link in the supplied operations. Links are read from 32-bit storage and interpreted as references; the source does not independently establish a portable pointer representation or execution ABI.

### Access preconditions

The necessary storage depends on the path:

- With a null target, no descriptor or node storage is accessed.
- With a nonnull target, the descriptor’s first word must be readable.
- With a nonnull target and null first-node reference, no node storage or descriptor second word is accessed.
- Traversal requires each visited node’s first word to be readable.
- Clearing the target requires its first word to be writable.
- Successful removal may additionally require writable descriptor words or a writable predecessor link, as described below.

A nonnull target does not, by itself, guarantee that the target is dereferenced: the null-head return occurs first.

The source provides no recovery mechanism for invalid addresses, unsuitable alignment, inaccessible storage, or references that cannot be represented by the stored link format. Their exact execution consequences are outside the established contract.

## Behavior

### Initial gating

The target is checked before any descriptor access.

If the target is null, the function returns. This path does not read the descriptor, traverse nodes, or clear any link. The auxiliary argument cannot alter this result.

If the target is nonnull, the descriptor’s first 32-bit word is read and interpreted as the current first-node reference. This value replaces the local auxiliary reference.

If that first-node reference is null, the function returns immediately. In particular, the target’s first word is neither read nor cleared, and the descriptor’s second word is not inspected.

A nonnull target therefore does not make a null descriptor safe: the first descriptor read precedes the null-head decision.

### Target equals the first node

When the first-node reference equals the target:

- The target’s first word is read.
- That value is written to the descriptor’s first word.
- The descriptor’s second word is then read and compared with the target reference.
- If that comparison is equal, zero is written to the descriptor’s first word, followed by zero to the descriptor’s second word.
- Finally, zero is written to the target’s first word.

The second-word comparison occurs after the first descriptor write. This order matters if descriptor and node storage overlap.

For a conventional, consistent one-node sequence, both descriptor references equal the target. The final descriptor contains two zero words, and the target’s link is zero.

For a conventional sequence containing multiple nodes, removing the first node advances the descriptor’s first reference to the former successor and normally leaves the cached final-node reference unchanged.

The function does not verify that a descriptor whose second word equals the first node actually represents a one-node sequence. If the first and final references both identify the target while the target has a nonzero successor, the descriptor is nevertheless cleared to two zero words. The saved successor is not retained in the descriptor.

### Target differs from the first node

Traversal starts with the first node as the candidate predecessor. The first word of that node is read as its successor.

Traversal has three possible outcomes:

1. A successor equals the target.
2. A successor is null.
3. Traversal continues indefinitely or encounters storage that cannot be accessed.

The null-successor decision precedes the target comparison. The target is known to be nonnull on this path, so a null successor terminates the search without a match.

#### Target found through a predecessor

When a visited node’s successor equals the target:

- The target’s first word is read.
- That value is written into the predecessor’s first word.
- The descriptor’s second word is then read and compared with the target reference.
- If equal, the predecessor reference is written into the descriptor’s second word.
- Finally, the target’s first word is set to zero.

Under the conventional nonoverlapping layout, the descriptor’s first word is unchanged on this path.

A cached-final-reference update depends only on whether the second descriptor word equals the target. The function does not independently check whether the target’s successor is null.

Thus, if the descriptor identifies the target as the final node despite the target having a nonnull successor, traversal is rewired to that successor while the cached final reference is changed to the predecessor. The function does not repair that inconsistency.

#### Target not found before a null successor

When traversal reaches a null successor without encountering the target:

- No membership-related descriptor update occurs.
- No predecessor link is rewritten.
- The target’s first word is set to zero.

This is a significant externally visible behavior. Failure to find the target does not mean that the function is a no-op. A target belonging to another structure can have its link severed.

The descriptor’s second word is not read on this unsuccessful-search path. A stale final-node reference equal to the absent target is therefore not corrected.

#### Nontermination and inaccessible links

There is no cycle detection, iteration bound, or visited-node tracking.

A reachable cycle that does not contain the target can prevent completion indefinitely. In that case, the final target-clearing write is never reached.

If traversal encounters an invalid nonzero link, the function attempts to continue using it. The supplied source establishes no error return or alternate path for that condition.

### Completion and return

Every normal path that begins with a nonnull target and nonnull first-node reference eventually clears the target’s first word, provided traversal reaches either the target or a null successor.

The function returns no indication of:

- Whether the target was found.
- Whether descriptor words changed.
- Whether the target was initially the first or cached final node.
- Whether the structure was consistent.

## Side effects

### Memory changes

The function can write:

- The descriptor’s first 32-bit word.
- The descriptor’s second 32-bit word.
- A predecessor node’s first 32-bit word.
- The target’s first 32-bit word.

Only the applicable subset is written on a given path. No other node fields are accessed in the supplied source.

The order described in **Behavior** is the source-level order of accesses. It does not establish instruction-level access counts, atomicity, memory barriers, or guarantees for concurrent or memory-mapped observers.

### Aliasing

The source performs no overlap checks. It is unsafe to replace the ordered access contract with unconditional assertions that “the head changes,” “the tail changes,” or “only the target is detached.”

In particular:

- A descriptor write may change a node word if their storage overlaps.
- A predecessor-link write may change the descriptor’s second word before that word is compared with the target.
- The final target-clearing write may also alter descriptor storage if the target aliases it.
- Cyclic links may cause a node to act as its own predecessor.

For ordinary list-removal semantics, the descriptor should occupy storage distinct from node link words, and the reachable structure should be acyclic and internally consistent. These are inferred usage preconditions, not checks performed by the function.

### Ownership and lifetime

No allocation, deallocation, reference-count operation, callback, or external function call appears in the supplied body.

Clearing a link does not release the target’s storage. The function neither establishes ownership transfer nor invalidates the target reference through an explicit lifetime operation. Any wider ownership convention remains unknown.

### Arithmetic and width

There is no length calculation, counter, or arithmetic on link contents. The visible layout arithmetic selects the descriptor’s second 32-bit word at a four-byte offset.

The function does not check pointer representability, address-range overflow, or whether a stored 32-bit word is a valid node reference. These requirements belong to the execution environment and caller contract.

## Acceptance examples

These examples are conditional, source-derived expectations, not runtime observations. Except where stated otherwise, descriptor storage and node storage are distinct, references are valid, and execution is single-threaded. Letters identify nodes, and “next” means the first 32-bit node word.

### 1. Null target

Given any descriptor argument and any auxiliary argument, if the target is null:

- The function returns without descriptor or node accesses.
- No memory is changed.

A null descriptor is therefore harmless on this specific path.

### 2. Empty descriptor with a nonnull target

Given a readable descriptor whose first word is zero, and a nonnull target whose next word contains a nonzero reference:

- The function reads the first descriptor word and returns.
- The target’s next word retains its original value.
- The descriptor’s second word is not inspected.

This differs from an unsuccessful search through a nonempty chain.

### 3. Consistent one-node sequence

Given a descriptor whose first and final references both identify A, with A next equal to null, and target A:

- Both descriptor words become zero.
- A next becomes zero.
- No status is returned.

### 4. Removing the first node of a longer sequence

Given first A, final C, links A → B → C → null, and target A:

- First becomes B.
- Final remains C.
- A next becomes null.
- B and C links are unchanged.

### 5. Removing an interior node

Given first A, final C, links A → B → C → null, and target B:

- A next becomes C.
- B next becomes null.
- The descriptor remains first A, final C.

### 6. Removing the final node

Given first A, final C, links A → B → C → null, and target C:

- B next becomes null.
- Final becomes B.
- First remains A.
- C next is zero after completion.

### 7. Absent target in a terminating, nonempty sequence

Given first A, final B, links A → B → null, and a separate target X whose next is Y:

- The descriptor and the A/B links remain unchanged.
- X next becomes null.
- Y is not traversed merely because it was X’s successor.

This behavior does not establish that X was a member of the descriptor’s structure.

### 8. Inconsistent first/final references

Given first A, final A, A next equal to B, and target A:

- The initial first-word update temporarily installs B.
- The subsequent final-reference comparison causes both descriptor words to become zero.
- A next becomes zero.

The function does not retain B as the descriptor’s first node.

### 9. Unreachable target behind a cycle

Given first A, links A → B → A, and a distinct target X:

- Traversal repeatedly follows the cycle.
- There is no normal completion established by this body.
- The final write clearing X next is not reached.

### 10. Auxiliary argument independence

For otherwise identical valid inputs, changing only the auxiliary argument does not change branch selection or memory effects. This includes changing it between null and nonnull values.
