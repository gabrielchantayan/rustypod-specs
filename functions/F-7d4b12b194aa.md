### Affine byte operation

For a loaded byte value \(x\), the affine operation stores:

\[
T(x)=(99x-68)\bmod256.
\]

The reduction follows from storing one byte. It is neither saturation nor clamping.

Two states perform this operation. Each reads G-scale freshly within the state and multiplies that value by a working counter to obtain a 32-bit byte offset. The source load and destination store use that same offset.

Their subsequent progress calculations differ:

- One state reads G-stride after the store, scales the offset, and installs that product in another progress role.
- The other computes a counter decrement before the store. After the store, its next counter is formed from a fresh G-stride read, the G-scale value cached at dispatch entry, and the decremented counter.

The latter therefore uses both a fresh G-scale read for the current byte address and the older cached G-scale value for later progress. Those values are not established to be equal.

### Identity byte operation

Two other states store:

\[
C(x)=\bigl(75(99x-68)-20\bigr)\bmod256.
\]

Since

\[
75\cdot99\equiv1\pmod{256},
\qquad
-75\cdot68-20\equiv0\pmod{256},
\]

each individual store writes the loaded byte value unchanged.

The two addressing forms differ:

- One reads G-scale freshly within the state and multiplies it by a working counter to obtain the byte offset. After the store, a fresh G-stride read scales that offset for subsequent progress.
- The other uses an already retained offset directly. After the store, its next progress value is the product of a fresh G-stride read, the G-scale value cached at dispatch entry, and a working counter.

In the direct-offset form, the cached G-scale value is not replaced by a fresh G-scale read for that progress calculation.

This establishes identity only for each load/store pair. It does not establish whole-range copying, a source snapshot, or overlap-safe behavior. A later load can observe an earlier store.

The byte map \(y\mapsto(75y-20)\bmod256\) is mathematically inverse to \(T\), but no separately callable inverse operation is established.

3. **Affine values.** An affine byte operation stores 188 for source byte 0, 31 for source byte 1, and 89 for source byte 255.

4. **Identity value.** An identity byte operation loading 173 stores 173. This says nothing about later accesses to overlapping ranges.

5. **Cached direct-offset progress.** Suppose the direct-offset identity state has cached G-scale equal to 2, its working counter is 4, and its post-store G-stride read gives 3. Its resulting progress value is 24. A different current value of G-scale does not replace the cached 2 in that calculation.
