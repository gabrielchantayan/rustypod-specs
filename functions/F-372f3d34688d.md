# F-372f3d34688d

## Purpose

F-372f3d34688d conditionally submits an eight-bit value to F-b4c8a64376c1. Submission requires both a nonzero selector byte in an input object and a nonzero result from F-f864d4b0c549. Before submitting, the function repeatedly checks a byte in a separately referenced object, invoking an external dependency while that byte remains zero.

A separate external call may occur first, depending on a 32-bit field in the input object.

This is a source-facing behavioral contract derived from the supplied static material. Terms such as “selector,” “readiness byte,” and “submission” describe roles in the observed control flow; they do not establish application-level meanings.

## Behavior

### Initial condition and optional external call

The function first reads the 32-bit field at input-object offset `0x14`.

If that field is not `-1`, it invokes an unmapped external dependency, designated **U-01** in this document. No explicit arguments or consumed result are visible for this call.

If the field equals `-1`, U-01 is skipped.

The field is not checked again. The function does not directly modify it.

The later selector check occurs after U-01 returns, when U-01 is invoked. Consequently, the selector check can observe changes made during that call. The supplied evidence does not establish that U-01 preserves the input object, global storage, or other process state.

### Selector condition and temporary storage

The function next reads the byte at input-object offset `0x11`.

If the byte is zero, execution returns normally. This path does not initialize the temporary word, invoke F-f864d4b0c549, read the address-bearing global, poll a readiness byte, or invoke F-b4c8a64376c1.

If the byte is nonzero:

1. The fourth argument is stored into the first word of a temporary local region.
2. The selector byte at offset `0x11` is read again for use as a dependency argument.
3. F-f864d4b0c549 is invoked with that selector value and the address of the temporary region’s first word.

The initial nonzero test and the argument read are separate reads in the supplied representation. The first read is not retained as the argument value. If the byte changes between those reads, the value passed to F-f864d4b0c549 can differ from the value that satisfied the condition, including becoming zero. This observation does not establish a supported concurrent-access protocol.

The recovered temporary region contains two 32-bit words. Only its first word is explicitly initialized here. No evidence establishes that the second word is a supported input to F-f864d4b0c549, or that the dependency may access both words.

### Dependency result and global-address capture

After F-f864d4b0c549 returns, the function reads the address-bearing global and retains its value. This read occurs before the dependency’s return value controls entry into the remaining branch.

Accordingly:

- The global read occurs even if F-f864d4b0c549 returns zero.
- The value read can reflect global changes made by F-f864d4b0c549.
- The global is not read on the zero-selector path.

If F-f864d4b0c549 returns zero, the function returns normally after that global read. It does not read the readiness byte or invoke F-b4c8a64376c1.

Any nonzero result enters the remaining branch. The function does not distinguish among different nonzero result values.

### Value selection

For a nonzero dependency result, the function reads the first temporary word after the dependency call and retains only its low eight bits.

The selected value is therefore in the inclusive range `0` through `255`. The other 24 bits are discarded without validation or error reporting.

This is the post-call temporary value, not necessarily the original fourth argument. If F-f864d4b0c549 leaves the first word unchanged, the selected value equals the fourth argument modulo 256. If the dependency changes the word, the low byte of the changed value is used.

The masking occurs before the readiness loop. The function does not explicitly reread the temporary word after waiting.

### Readiness loop

The function reads the byte at offset `2` from the retained global-derived address.

- If the byte is nonzero, the loop ends without invoking the loop dependency.
- If the byte is zero, an unmapped external dependency, designated **U-02**, is invoked with explicit arguments `0` and `1`.
- After U-02 returns, the readiness byte is checked again.
- This repeats while the byte remains zero.

The same retained base address is used throughout the loop. Replacing the address-bearing global during a U-02 call does not redirect subsequent checks in this invocation. Changes to the byte in the originally selected object can affect later checks.

There is no explicit timeout, retry limit, cancellation check, error-result check, or alternate exit from the loop. U-02’s result is not consumed.

The constants passed to U-02 do not establish a delay duration, scheduling policy, or time unit. Those interpretations require information about the dependency.

### Final call and return

Once the readiness byte is nonzero, F-b4c8a64376c1 is invoked with:

- First argument: the previously selected value in the range `0` through `255`.
- Second argument: zero.

Its result, if any, is not consumed. If the call returns normally, F-372f3d34688d returns without further explicit work.

The function itself makes at most one call to F-f864d4b0c549 and at most one call to F-b4c8a64376c1 per invocation. U-02 can be called an unbounded number of times.

## Side effects

### Direct effects

The function explicitly:

- Reads the input-object field at offset `0x14`.
- Conditionally invokes U-01.
- Reads the selector byte at offset `0x11`, with a second read on the nonzero path.
- Writes the fourth argument into a local 32-bit word.
- Conditionally passes that word’s address to F-f864d4b0c549.
- Reads the address-bearing global after that dependency returns.
- On a nonzero result, reads the post-call temporary word and potentially reads the readiness byte repeatedly.
- Conditionally invokes U-02 and F-b4c8a64376c1.

It performs no explicit heap allocation, release, input-object write, global assignment, or readiness-byte write.

### Indirect effects and ownership

The dependencies’ side effects are not established. In particular, this contract does not assume that they preserve globals, preserve pointed-to storage, avoid reentrancy, or refrain from allocation and release.

The temporary address passed to F-f864d4b0c549 refers to local storage whose lifetime does not extend beyond this invocation. The caller performs no explicit ownership transfer or release. Whether the dependency retains that address is unknown; continued use after the local storage’s lifetime would require a separate, valid lifetime arrangement not shown here.

The function also does not establish that either the input object or the readiness object remains valid across dependency calls. Validity for subsequent accesses is a precondition of those accesses, not a guarantee provided here.

### Errors and termination

There is no explicit error return or local recovery path.

A zero result from F-f864d4b0c549 is treated as a reason not to submit, but the evidence does not establish whether it means failure, rejection, or an ordinary negative decision.

Normal termination requires every reached dependency call to return. On the polling path, it additionally requires some readiness check to observe a nonzero byte. A readiness byte that remains zero can prevent return indefinitely.

## Acceptance examples

These examples describe conditional expectations from the static control flow. They are not executed test results. Unless stated otherwise, all reached memory remains valid and all invoked dependencies return normally.

### Sentinel field and zero selector

Given a field value of `-1` at offset `0x14` and a zero selector at offset `0x11`:

- U-01 is skipped.
- Neither mapped dependency is called.
- The address-bearing global is not read.
- The function returns.

### Initial external call changes later selection

Given an initial field value other than `-1`, U-01 is invoked. If U-01 leaves the selector zero when the subsequent selector read occurs, the function returns without calling F-f864d4b0c549.

The selector’s value before U-01 does not determine this outcome.

### Zero dependency result

Given a nonzero selector and a zero return from F-f864d4b0c549:

- The fourth argument has been supplied through the initialized temporary word.
- The address-bearing global is read after the call.
- No readiness-byte read occurs.
- U-02 and F-b4c8a64376c1 are not invoked.

### Low-byte extraction without waiting

Given a nonzero dependency result, a post-call temporary value of `0x123456ab`, and an initially nonzero readiness byte:

- U-02 is not invoked.
- F-b4c8a64376c1 receives `171` and `0`.

Likewise, a post-call temporary value of `0xffffff00` produces a first argument of zero. There is no nonzero-value requirement for the submitted byte.

### Dependency modification takes precedence

Given a fourth argument of `0x12345678`, if F-f864d4b0c549 replaces the first temporary word with `0x00000102` and returns nonzero, the selected value is `2`, not `120`.

### Readiness changes after polling

Given a nonzero dependency result, if the first readiness check observes zero and the check after one returning U-02 call observes a nonzero byte:

- U-02 is called exactly once with `0` and `1`.
- F-b4c8a64376c1 is then called once with the previously selected byte and zero.

### Replacing the global does not redirect polling

Suppose the captured global value identifies object A. During a U-02 call, the global is changed to identify object B.

Subsequent readiness checks still address byte `2` of A. A nonzero readiness byte in B alone does not satisfy this invocation’s loop condition.

### Persistent unreadiness

If every readiness check observes zero and every U-02 call returns, the function continues polling and does not reach F-b4c8a64376c1 or normal return.
