# F-45258ee354fd

Its observable behavior includes publishing an input value twice, retaining a word for two byte publications, assigning a call result to global storage, clearing two additional locations, and attempting a final call to address zero.

The available static evidence does not establish an application-level purpose. In particular, it does not justify interpreting these operations as array management, serialization, allocation, device initialization, or a supervisor operation.

This contract describes the caller’s visible behavior. Dependency implementations, execution mappings, and several interface details are unavailable. All acceptance examples are conditional deductions; no runtime tests have been performed.

## Behavior

### Address and arithmetic model

Unsigned selections from the retained word and the split result use 32-bit arithmetic. The unsigned left shift used for one call argument discards bits shifted beyond bit 31.

Signed multiplication, signed left shifts, address addition, and conversion from global storage require separate qualification. The representation shows the calculations but does not settle overflow, negative-shift behavior, address wrapping, or all conversion rules. This contract neither assumes universal modular arithmetic nor substitutes portable-language failure rules for an unknown machine execution model.

All ordering below is conditional on reaching the operation concerned. A fault or non-returning call can prevent every later effect.

### Publication and capture boundary

The first externally visible memory update is a 32-bit write of the payload at the address calculated from the initial index.

Only after that write does the function capture the initial global’s value into its retained signed 32-bit base. Consequently, if the first write overlaps storage involved in the capture, it may affect the captured value. The unknown global access width prevents a complete overlap analysis.

Five calls then occur in order: F-00000001 through F-00000005. The first receives the payload, initial index, payload, and payload in its four explicit argument positions. The next three have no explicit arguments shown and no results subsequently consumed by this caller. F-00000005 supplies the signed 32-bit second index.

The function publishes the original payload again, this time at the address calculated from the second index. It then reads an unsigned 32-bit word at the retained base plus 20.

The base is not refreshed from the global after the calls. That retention does not imply preservation of the global or of memory reached through the base. The word read observes the memory state at this later point, after both payload publications and the first five calls.

The resulting word is retained for both byte publications. Later changes to its original memory location do not cause another word read.

### Split-result acquisition

F-00000006 through F-0000000A form the next ordered call group, after the retained-word read.

F-00000006 receives the second index multiplied by four. F-00000007, F-00000008, and F-00000009 have no explicit arguments shown and provide no result used by this caller. F-0000000A supplies a represented 64-bit result.

The high 32 bits and low 32 bits of that result have distinct roles. The high half is used only in repeated arguments to F-0000000B. The low half contributes to that call’s remaining argument, the second selector’s read address, and the final halfword-clear address.

These are numerical bit relationships, not evidence of a particular register-pair convention or in-memory 64-bit layout.

### First selected-byte publication

After F-0000000A returns, the function reads one unsigned byte at the implicit entry-register value plus one.

The byte’s numerical value selects a destination by adding 17. The function writes the low eight bits of the retained word to that destination.

Because the selector is an unsigned byte, the destination is between `0x11` and `0x110`, inclusive. The selector is not a pointer-sized load, a scaled index, or an offset relative to an independently supplied output buffer.

This read and write both precede F-0000000B. Their address validity is not established merely because the selected destination has a small numerical value.

### Calls between byte publications

The next call sequence is F-0000000B through F-00000011.

F-0000000B receives four explicit arguments. Its first three are the high half of the split result. Its fourth is the low half shifted left by two as an unsigned 32-bit value; the original top two bits are discarded.

F-0000000C supplies an opaque 32-bit value that becomes the sole explicit argument to F-0000000D. F-0000000E, F-0000000F, and F-00000010 have no explicit arguments shown. F-00000011 supplies a represented signed 32-bit result for a later call.

No return value from F-0000000B, F-0000000D, or F-0000000E through F-00000010 is subsequently used by this caller. That fact imposes no restriction on their effects.

### Second selected-byte publication

After F-00000011, the function derives a selector-read address from the retained low half of the split result:

- Bits 30 and 31 are excluded.
- Bits 21 through 29 become a value between zero and 511.
- Adding one gives a read address between 1 and 512, inclusive.

An unsigned byte read at that address selects the output destination, again by adding 17. The destination therefore lies between `0x11` and `0x110`.

The published byte is formed from bits 22 through 29 of the retained word, with bit 22 becoming the output’s least significant bit. Bits 30 and 31 of the retained word do not contribute.

The selector read occurs after the first byte publication and after the intervening calls. If its location overlaps the earlier publication destination, it can observe that earlier write, subject to any intervening changes. Likewise, equal selector values can cause the two byte publications to target the same address. They remain separate, ordered writes.

## Acceptance examples

These examples specify conditional consequences of the static evidence. They assume the relevant operations are reached, arithmetic has the stated interpretation, and required accesses and calls complete.

### Payload placement

For initial index 3, the first payload write is a 32-bit write at `0x20`.

If F-00000005 returns 7, the second payload write is at `0x30`, and F-00000006 receives 28. Both writes use the original payload.

### Capture timing

If the global capture produces the retained signed 32-bit value `0x1000`, the word read uses address `0x1014`.

Changing the global after capture does not replace the retained base. Changing memory at `0x1014` before the read can change the retained word. This example makes no assertion about the global’s own storage or read width.

### Byte contents and destinations

For retained word `0xA5C3B27E`, the first byte publication contains `0x7E`, and the second contains `0x97`.

A selector value of `0x20` chooses destination `0x31`; a selector value of `0xFF` chooses `0x110`. These are byte destinations, not addresses of 32-bit elements.

If both selectors have the same value when read, both publications target the same location. The second publication occurs later, with all intervening calls still required.

### Selector overlap

Suppose the first publication targets `0x31`, and the second selector read also uses `0x31`. If no intervening operation changes that byte, the second selector obtains the first publication’s byte value.

This is a conditional aliasing result, not a general dependency-preservation assumption.

### Split-result boundaries

- Its fourth argument is `0x01000200`.
