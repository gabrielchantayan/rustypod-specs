# F-2d50e69ee75e

## Purpose

F-2d50e69ee75e computes a signed 32-bit position-like value, invokes an object-associated callback, and then writes the computed value into an associated state record.

The computation has two modes selected by an 8-bit portion of an object field. One mode subtracts a derived amount from a queried value subject to a lower-bound-like condition; the other adds that amount subject to an upper-bound-like condition.

**Inferred intent:** the operation resembles directional movement within bounds, with an optional conversion from a caller-supplied quantity into an internal amount. The supplied evidence does not establish units, application domain, or whether the queried value is a position, size, offset, or another quantity.

The callback occurs **before** the final state write. The state record receiving that write is resolved after the callback, so it need not be the record used during the computation.

## Behavior

### 1. Capture the initial state reference

The function first reads the associated-state reference from object offset `0x04`.

This captured reference is used for the zero-quantity stored-amount read and for the first invocation of F-d4307b71d8ac. Later state accesses generally resolve the reference again through the object.

This distinction is observable if a dependency changes the object’s associated-state reference.

### 2. Determine the amount

If the requested quantity is exactly zero, the amount is the signed 32-bit value at offset `0x3C` of the initially captured state record. F-d7be9cfb4000 is not called on this path.

For any nonzero requested quantity, the function calls F-d7be9cfb4000 with:

1. A value obtained from a global location.
2. The original requested quantity.

The return is exposed as a 64-bit quantity. Its lower 32 bits become the initial 32-bit amount. If its upper 32 bits are nonzero, the amount is incremented by one.

Only a zero/nonzero test is applied to the upper half. The upper half is not added to the lower half, and no particular nonzero upper-half value is required.

**Inferred intent:** this resembles a quotient-and-remainder conversion with upward adjustment when a remainder exists. That interpretation is not established. The dependency’s actual operation, the global value’s meaning and width, and the units of the resulting amount are unknown.

### 3. Select a mode

After determining the amount, the function reads and narrows the mode field at object offset `0x1C`.

Consequently, on the nonzero-quantity path, effects of F-d7be9cfb4000 on that field can affect which mode is taken. The mode is not captured before that dependency call.

### 4. Subtractive mode

When the narrowed mode value is zero:

1. F-d4307b71d8ac is invoked with the initially captured state reference explicitly supplied.
2. Its signed 32-bit result is retained as the first queried value.
3. The function resolves the object’s current state reference and reads state offset `0x38`. This first lower-bound-like read becomes the tentative result.
4. For the comparison, it again resolves the object’s state reference and reads offset `0x38`.
5. It compares the amount with the first queried value minus this comparison-time lower-bound-like value, using a signed comparison.

If the amount is greater than that difference, the tentative result from the first lower-bound-like read remains the result.

If the amount is less than or equal to that difference, F-d4307b71d8ac is invoked a second time. The supplied representation shows **no explicit argument** for this second invocation. The final result becomes this second return value minus the amount.

The second dependency result is not assumed equal to the first. In particular, the first result determines whether subtraction is allowed, while the second result supplies the value from which subtraction is actually performed.

The evidence does not establish which argument, if any, the second invocation receives through the underlying calling convention. It must not be described as definitely receiving the original state reference.

### 5. Additive mode

When the narrowed mode value is nonzero:

1. F-d4307b71d8ac is invoked with the initially captured state reference explicitly supplied.
2. Its signed 32-bit result is added to the amount to form the tentative result.
3. The function resolves the object’s current state reference and reads state offset `0x3C`.
4. If that value is strictly less than the tentative result, the function resolves the current state reference again and rereads offset `0x3C`; this second value replaces the tentative result.
5. Otherwise, the tentative result is retained.

Equality does not take the replacement branch.

The two upper-bound-like reads are distinct in the supplied representation. If they can observe different values, the comparison value and the selected replacement value can differ. A single, stable upper bound is therefore an additional assumption, not an unconditional property.

### 6. Invoke the callback

After computing the result, the function resolves the dispatch-table reference from object offset `0x00`, obtains the entry at table offset `0x38`, and invokes it with:

1. The original object reference.
2. The original requested quantity.
3. The original auxiliary 32-bit value.

The derived amount and computed result are not supplied as explicit callback arguments.

The callback’s return value, if any, is not used.

### 7. Commit the result

After the callback returns, the function reads the associated-state reference from object offset `0x04` again and writes the computed 32-bit result at offset `0x5C` of that record.

The result is not recomputed after the callback. Therefore:

- A callback change to the associated-state reference redirects the final write.
- A callback write to the eventual destination field is subsequently overwritten.
- Changes to bounds or the mode during the callback do not trigger recalculation.
- Destruction or invalidation of the object or destination state can make the final access invalid.

### Arithmetic boundaries

The amount, dependency query results, bounds, and computed result are represented as 32-bit integers. Branch comparisons are signed.

Potentially overflowing arithmetic includes:

- Incrementing the lower half of the 64-bit dependency result.
- Subtracting a lower-bound-like value from the first queried value.
- Subtracting the amount from the second queried value.
- Adding the amount to the queried value in additive mode.

No widening, saturation, overflow check, or explicit error handling is shown. Exact out-of-range behavior is **documented_only**: the evidence does not justify assigning portable signed-overflow semantics or a particular machine-level wraparound rule.

Negative requested quantities and negative derived amounts are not rejected. A negative amount can reverse the apparent direction of the addition or subtraction. The bound-like logic does not establish a general invariant that the final value always lies within an interval.

## Acceptance examples

These are conditional specification examples, not executed tests. Unless stated otherwise, assume valid references, normally returning calls, stable bound fields, and arithmetic within the signed 32-bit range.

1. **Zero quantity bypasses conversion.**  
   With requested quantity zero and initial state offset `0x3C` equal to 6, the amount is 6. F-d7be9cfb4000 is not invoked. The callback still receives a requested quantity of zero.

2. **Only the upper-half zero/nonzero distinction matters.**  
   For a nonzero requested quantity, a dependency return with lower half 7 and upper half zero produces amount 7. Lower half 7 with upper half 1 or 9 produces amount 8 in either case.

3. **Subtractive branch retains the bound-like value.**  
   In subtractive mode, let the first queried value be 20, both lower-bound-like reads be 8, and the amount be 13. The comparison is against 12, so no second query occurs and the result is 8.

4. **Subtractive equality takes the second query.**  
   With first queried value 20, lower-bound-like value 8, and amount 12, the inclusive comparison succeeds. If the second query returns 25, the result is 13—not 8. This demonstrates that the second query is not interchangeable with the first.

5. **Additive replacement.**  
   In additive mode, queried value 20 plus amount 9 produces tentative result 29. If both upper-bound-like reads are 25, the result becomes 25.

6. **Additive equality avoids replacement.**  
   With tentative result 25 and comparison-time upper-bound-like value 25, the result remains 25 and the replacement read is not taken.

7. **Negative amount is not rejected.**  
   In additive mode, queried value 20 and amount −3 produce 17. If the comparison-time upper-bound-like value is 25, the result remains 17.

8. **Callback redirects the destination.**  
   Suppose computation uses one state record, but the callback changes the object’s state reference to another valid record. The computed result is written at offset `0x5C` of the second record. The final write does not use the initially captured reference.

9. **Narrowed mode differs from whole-word testing.**  
   A mode word with zero in the retained eight bits selects subtractive mode, even when other bits in that word are nonzero.
