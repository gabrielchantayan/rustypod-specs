# F-1911a8836dad

## Purpose

F-1911a8836dad conditionally processes a range of eight-byte records and records its resulting inclusive endpoint in a separate array of 16-bit indices.

Processing is enabled by a nonzero byte in the input object. On that path, the function selects a lower boundary, optionally removes one logical record when the two endpoint records compare equal, appends the resulting endpoint if the range remains nonempty, and clears the enabling byte.

“Record count,” “boundary depth,” and “pending flag” are descriptive names for observed fields. Their application-level meanings are inferred, not independently established. The function does not physically remove record bytes, search for repeated duplicates, or validate the supplied state.

## Interface

### Argument and result

The function accepts one argument represented as a 32-bit integer and used as the address of an input object. It has no explicit return value. Its observable results are memory reads and conditional writes.

The supplied representation uses:

- 32-bit integers and address-bearing fields.
- Signed 16-bit values for counts, depths, and stored boundary entries.
- An eight-bit enabling flag.
- Eight-byte records containing two four-byte words.

These are properties of the supplied representation, not a portability guarantee.

### Input object

| Byte offset | Width | Meaning in this contract |
|---|---:|---|
| `0x24` | 32 bits | Shared-state address |
| `0x28` | 8 bits | Pending flag; zero disables processing |

The shared-state address is fetched before the flag is tested. The address of the depth field is also formed before that test, but the disabled path does not read the depth or otherwise dereference shared-state storage.

### Shared state

| Byte offset | Width | Interpretation |
|---|---:|---|
| `0x34` | Signed 16 bits | Boundary depth |
| `0x36` | Signed 16 bits | Logical record count |
| `0x38` | 32 bits | Record-array address |
| `0x40` | 32 bits | Boundary-array address |

Each record occupies eight bytes. Its first comparison word is at record offset zero; its second comparison word is at record offset four.

Boundary entries occupy two bytes each. Reads interpret them as signed 16-bit values.

The second record word is converted to a pointer-typed value before equality comparison. It is not dereferenced. This operation does not establish that the word identifies valid storage, nor does it establish ownership of any referenced object.

### Access requirements

Successful execution requires accessible storage for every access selected by the actual values encountered:

- The input object must support the initial address-field read and flag read.
- Enabled processing requires readable shared-state fields and writable fields on the selected mutation paths.
- Positive depth requires a readable boundary entry at index depth minus one.
- Endpoint comparison requires readable selected record words.
- Boundary append requires writable storage at the index supplied by the current depth.
- Addresses, alignment, pointer conversions, and address arithmetic must be valid for the execution environment.

There are no explicit null, capacity, bounds, sign, or consistency checks.

Ordinary state-transition descriptions below assume stable, suitably nonoverlapping storage. The source does not establish synchronization or require such nonoverlap; the consequences of repeated reads and ordered writes remain relevant when those assumptions do not hold.

## Behavior

### Disabled path

The function reads the shared-state address from input offset `0x24`, forms the depth-field address, and reads the flag at offset `0x28`.

If the flag is zero, the function returns without writes. It does not read shared-state fields or either array.

Thus, the disabled path requires the input fields to be readable but does not require the shared-state object itself to be readable. Address formation remains subject to the execution environment’s address semantics.

### Initial count and lower boundary

For a nonzero flag, the function first reads the signed 16-bit record count and retains that value for the endpoint calculation and any count decrement.

The lower boundary initially has the integer value zero.

The function then reads the signed depth:

- If depth is zero or negative, the lower boundary remains zero.
- If depth is positive, the function obtains the boundary-array address and uses a further depth read to select the entry at depth minus one. That entry, read as a signed 16-bit value, becomes the lower boundary.

The positivity check and subsequent indexing do not constitute one atomic depth snapshot. Under stable storage they use the same value; the function itself provides no mechanism ensuring that stability.

The candidate last index is the captured record count minus one. This arithmetic occurs after promotion to the wider integer type, without an initial narrowing back to 16 bits.

### Conditional endpoint comparison

Endpoint records are examined only when the lower boundary is strictly less than the candidate last index. Equality of the two indices does not trigger comparison.

When comparison is selected, the source establishes this sequence:

1. Read the record-array address and resolve the lower-boundary record.
2. Read that record’s first 32-bit word.
3. Read the record-array address again and resolve the candidate-last record.
4. Read that record’s first 32-bit word.
5. If the first words match, read the lower record’s second word and then the last record’s second word, converting each to a pointer-typed comparison value.

If the first words differ, neither second word is read.

A match requires equal first words and equal pointer-typed values obtained from the second words. There is no dereference through the second words, deep comparison, comparison of intervening records, or ordering comparison of record contents.

For the apparent 32-bit address representation, this is an endpoint comparison using both four-byte words. The treatment of arbitrary bit patterns converted to pointer values remains dependent on the execution environment.

### Logical removal

If both endpoint comparisons succeed, the function:

- Changes the candidate last index to the captured count minus two.
- Writes the captured count minus one to the signed 16-bit record-count field.

The calculation uses the count captured before the boundary lookup, not a reread count.

This removes one record only from the logical count. The function does not move, clear, release, or overwrite that record’s eight bytes. It performs no second comparison after shortening the range.

If the lower boundary equals the original candidate last index, no endpoint comparison or removal occurs. A one-record range is not removed merely because its first and last positions coincide.

### Conditional boundary append

After the optional removal, the function tests whether the lower boundary is less than or equal to the resulting candidate last index.

If that condition is false, it does not write the depth or a boundary entry.

If the condition is true, the source establishes the following order:

1. Reread the signed 16-bit depth.
2. Write that depth plus one to the 16-bit depth field.
3. Read the boundary-array address.
4. Write the candidate last index as a 16-bit entry at the position selected by the depth read in step 1.

The destination uses the old depth, not the incremented depth. The stored value is an inclusive last index, not a range length or exclusive upper bound.

The depth update precedes the boundary-entry write. These writes are not an atomic publication of a complete new entry.

### Flag clearing

Every normally completed enabled invocation writes zero to input offset `0x28`, after all conditional count, depth, and boundary-entry writes.

This occurs even when there is no comparison, no removal, and no append. The original nonzero flag value is not preserved.

The flag write is not error recovery. An invalid earlier access can prevent execution from reaching it.

### Signed arithmetic and unusual values

Signed interpretation affects both branch selection and addressing:

- Negative depth skips the existing-boundary lookup.
- Negative boundary entries can select records before the supplied record-array base.
- Zero and negative record counts are not rejected.
- If an append occurs with negative depth, the destination boundary index is negative.

The scalar calculations fit within signed 32-bit range for all signed 16-bit input values. In particular, count −32768 produces an initial candidate last index of −32769, not 32767.

Some mathematically computed indices are outside signed 16-bit range, but the append guard constrains which can be stored. The lower boundary is always zero or a signed 16-bit entry. An appended candidate must be at least that lower boundary and is at most 32766. Therefore, any candidate actually appended is representable as signed 16 bits.

The decrementing count write is likewise representable on the path that reaches it. The strict endpoint-order condition prevents a count at the lowest signed 16-bit values from undergoing an out-of-range decrement.

Depth increment is different: depth 32767 produces the wider value 32768 before the 16-bit write. The supplied source does not independently establish the implementation’s result for this out-of-range signed conversion.

Representable scalar arithmetic does not establish valid array addressing. Negative indices, insufficient allocation, address overflow, invalid pointer conversions, and inaccessible memory remain separate concerns.

## Side effects

On a normally completed enabled path, the function can write, in order:

| Write | Condition |
|---|---|
| Logical record count | Both endpoint comparisons match |
| Boundary depth | The resulting range is nonempty according to the boundary comparison |
| One boundary entry | The same append condition |
| Pending flag, set to zero | Every enabled completion |

Each listed write occurs at most once. There is no record-array write.

No allocation, deallocation, callback, logging, explicit error report, or ownership transfer appears in the function.

### Repeated reads and overlap

The shared-state address is captured once. In contrast:

- Depth may be read for the positivity check, boundary lookup, and later append.
- The record-array address is read separately for the two endpoints.
- The boundary-array address used for append is obtained after the depth write.

The function does not prohibit overlap between the input object, shared state, records, and boundaries. An earlier write can therefore affect a later read or overwrite another logical field when storage overlaps.

For example, the append destination is resolved after depth has already changed. A contract that treats the operation as an ordinary stack append requires storage relationships under which this write does not corrupt the subsequently read boundary-array address.

The stated access order describes source-level sequencing. It does not establish a complete machine-load trace, hardware memory barriers, or concurrency safety.

The function does not acquire or release ownership. This absence does not identify the owner of any supplied region.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

**Every example except “Disabled invocation” requires a nonzero input flag.** All examples also assume stable, suitably nonoverlapping storage, valid selected accesses, sufficient boundary capacity, and representable depth updates unless an exception is explicitly described.

### Disabled invocation

Given a zero flag:

- The shared-state address field and flag are read.
- No shared-state field or array entry is read.
- No memory is written.
- The shared-state object need not be readable, subject to the environment’s address-formation rules.

### Empty collection with empty boundary stack

Given depth zero and count zero:

- The lower boundary is zero and the candidate last index is −1.
- No records are compared.
- No boundary is appended.
- Count and depth remain zero.
- The flag becomes zero.

### One record with empty boundary stack

Given depth zero and count one:

- Both boundaries are zero.
- No record word is read.
- Depth becomes one before boundary entry zero receives zero.
- Count remains one.
- The flag becomes zero.

### Distinct endpoint first words

Given depth zero, count three, and differing first words in records zero and two:

- The two first words are read.
- Neither second word is read.
- Count remains three.
- Depth becomes one, and boundary entry zero receives two.
- The flag becomes zero.

### Equal first words but unequal second values

Given depth zero and count three, with equal first words but unequal pointer-typed values obtained from the second words of records zero and two:

- Both second words are read.
- Count remains three.
- Depth becomes one, and boundary entry zero receives two.
- The flag becomes zero.

### Equal endpoint records

Given depth zero and count three, with both endpoint comparisons equal for records zero and two:

- Count becomes two.
- The resulting last index is one.
- Depth becomes one, and boundary entry zero receives one.
- Record two’s bytes remain unchanged.
- No further comparison against record one occurs.
- The flag becomes zero.

### Existing lower boundary

Given depth two, boundary entry one equal to four, and count seven:

- The selected comparison endpoints are records four and six.
- If either comparison differs, count remains seven and boundary entry two receives six.
- If both comparisons match, count becomes six and boundary entry two receives five.
- Depth becomes three in either case.
- Earlier boundary entries remain unchanged.
- The flag becomes zero.

### Lower boundary beyond the last index

Given depth one, boundary entry zero equal to five, and count three:

- The lower boundary is five and the candidate last index is two.
- No records are compared.
- Neither depth nor a boundary entry is written.
- Count remains three.
- The flag becomes zero.

The inconsistent boundary is not repaired.

### Negative depth

Given depth −1 and count one, with writable storage at boundary index −1:

- The existing-boundary lookup is skipped.
- The lower boundary is zero.
- No endpoint comparison occurs.
- Depth is written as zero.
- Boundary index −1 receives zero.
- Count remains one.
- The flag becomes zero.

The resulting depth being zero does not make the negative-index write safe without the stated storage precondition.
