# F-36b4327cf52e

## Purpose

F-36b4327cf52e is a state-dependent, non-returning dispatch routine. Its visible behavior consists of:

- A conditional 16-bit memory transfer derived from incoming machine state.
- An additional 16-bit memory update on an exceptionally constrained path.
- An indefinite sequence of two indirect calls followed by software interrupt `0x5B`.

No application-level purpose, data format, or supported calling convention is established. In particular, the evidence does not justify describing this routine as a parser, allocator, initializer, or ordinary callable API.

The supplied representation contains many conditional arithmetic and memory operations. Under its apparent 32-bit arithmetic model, most of those operations are unreachable. They are not requirements for successful execution merely because they appear textually.

This contract distinguishes the behavior established by that representation from assumptions needed to interpret machine addresses and from unknown runtime behavior.

## Behavior

### Initial path selection

The routine multiplies the control word by `0x1000` in 32-bit arithmetic and tests whether the result is zero.

Consequently:

- A control word with any nonzero bit among its low 20 bits takes the path without the initial memory transfer.
- A control word whose low 20 bits are all zero takes the transfer path.
- The control word itself need not be zero to select that transfer.

On the non-transfer path, no direct data-memory read or write is established before the first indirect call.

On the transfer path, the routine:

1. Reads one unsigned 16-bit value from the source address.
2. Writes that value as a 16-bit value at the source address plus the displacement, with 32-bit address wraparound.

The source read precedes the destination write. This remains true when the addresses overlap or are identical. A zero displacement does not eliminate the represented read or write.

The routine also forms an internal address equal to the destination address minus the adjustment. That calculation does not itself read memory.

There is no address validation, bounds check, null check, or error return associated with this transfer. Successful continuation requires the relevant memory operations to be permitted by the execution environment.

### Exceptional additional memory update

After the initial transfer, a chain of zero-result gates can admit an additional memory update. Under the 32-bit interpretation, reaching this update requires all of the following:

- The control word’s low 20 bits are zero.
- The incoming link address is zero.
- The stack reference is zero.
- The comparison word equals the displacement.
- The accumulator is zero.
- The displacement is either `0x00000000` or `0x80000000`.
- The source address plus the displacement equals twice the adjustment, modulo `2^32`.

These are reachability conditions, not evidence that any supported caller can provide such a state.

The conditions follow from the gates jointly. In particular, selecting the initial transfer also forces the control word’s tested bit 18 to be clear. Subsequent zero tests force the link address to zero and initially restrict the stack reference to zero or one. A later zero-result addition excludes one, leaving only a zero stack reference.

If the exceptional update is reached, the represented expression performs two 16-bit reads at the link address, which is zero on this path:

- One read supplies a 16-bit address value, zero-extended to 32 bits, for the destination.
- The other supplies a value to which `0x000F` is added before a 16-bit store.

The stored result is reduced to 16 bits. For example, a value operand of `0xFFF8` yields a stored value of `0x0007`.

The relative order of these two reads is not established by the expression. Both precede the store that uses their results. For ordinary stable memory, they obtain the same value. For volatile memory, device memory, or concurrently changing memory, equality must not be assumed.

The initial transfer occurs before these reads. Therefore, a transfer that modifies address zero can affect the exceptional update.

The representation also assigns a special machine-state location a value derived from the stack reference. Its exact architectural identity and external observability are unknown. On this exceptional path, the value assigned is zero.

A conventional environment that disallows a zero stack address or reads from address zero cannot complete this path. The contract does not impose that environmental restriction universally.

### Later memory operations are not reachable

The exceptional update advances one internal halfword-address value by two bytes. Continuing into the next group of gated operations would require that advanced value to equal zero. It is instead `0x00000002`.

Thus the subsequent chain fails before reaching the later arithmetic and memory-update blocks.

If the exceptional update is not entered, the gates leading into that same chain are already false.

Accordingly, under the stated arithmetic model, the later textually present operations do not execute. These include:

- A pointer-sized load through an address derived from a character-sized value.
- A signed-halfword load followed by two pointer-sized stores.
- A final signed-halfword load followed by two 32-bit stores.

They must not be presented as normal output layouts, required allocations, or supported record transformations. Their apparent offsets do not establish a reachable data structure.

### Indefinite dispatch sequence

After the conditional memory activity, the routine enters an unconditional loop.

The first iteration uses the incoming link address as its dispatch base. The exceptional path does not change that conclusion: it can occur only when both the link address and stack reference are zero, so its represented link adjustment remains zero.

Each iteration attempts the following actions in order:

1. Indirectly call F-000000000001 at the current dispatch base plus `0xEB6`.
2. If that call returns, indirectly call F-000000000002 at address `0x0857A94B`.
3. If that call returns, issue software interrupt `0x5B`.
4. If execution resumes normally after the interrupt, replace the dispatch base with `0x083D4CC2` and begin another iteration.

F-000000000001 receives three represented argument words:

- `0x00000000`
- `0x00000000`
- `0xFFFFFFA5`

The third word is the 32-bit two’s-complement representation of `−91`; whether the dependency interprets it as signed is unknown.

F-000000000002 has no explicit arguments in the supplied representation. That does not prove that its actual calling convention has no implicit inputs.

For the second and all subsequent iterations, the represented target address of F-000000000001 is `0x083D5B78`.

No target validation, retry limit, loop exit, or handling of dependency return values is visible. Behavior after a dependency or interrupt transfers control elsewhere is outside the established local flow.

## Acceptance examples

These examples are conditional static acceptance criteria, not reports of execution.

### Non-transfer entry

Given a control word of `0x00000001` and a link address of `0x10000000`:

- The initial multiplication is nonzero.
- No initial 16-bit transfer occurs.
- The first represented indirect target is `0x10000EB6`.
- Its explicit argument words are zero, zero, and `0xFFFFFFA5`.

Reaching the second call requires the first call to return.

### Transfer selected by a nonzero control word

Given:

- Control word `0x00100000`.
- Source address `0x00002000`.
- Displacement `0x00000006`.
- Source halfword `0xBEEF`.
- A nonzero link address.
- Valid readable and writable memory at the relevant addresses.

The multiplication wraps to zero. The routine reads `0xBEEF` at `0x00002000` and writes it as a halfword at `0x00002006`. The nonzero link address prevents the exceptional update.

### Same-address transfer

Given a transfer-selected state and zero displacement, the routine still reads and writes the source address. An implementation that silently omits the write would not preserve the represented observable behavior for device or otherwise externally observable memory.

### Exceptional update with stable memory

Given:

- Control word zero.
- Link address, stack reference, comparison word, displacement, and accumulator all zero.
- Source address `0x00002000`.
- Adjustment `0x00001000`.
- Stable halfword `0x0100` at address zero.
- All required accesses permitted.

The internal equality holds because `0x00002000` equals twice `0x00001000`.

After the initial same-address transfer, the exceptional operation reads address zero and stores `0x010F` as a halfword at address `0x00000100`. The later pointer-sized store blocks do not execute.

### Repeated dispatch

If both dependencies return and the interrupt resumes execution normally, the next F-000000000001 target is `0x083D5B78`, regardless of the incoming link address. The second target remains `0x0857A94B`, and interrupt `0x5B` follows it again.
