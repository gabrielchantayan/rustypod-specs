# F-796113959089

## Purpose

F-796113959089 modifies a caller-supplied, word-oriented numeric object in place according to a signed interpretation of a 32-bit displacement.

The established behavior separates into two directions:

- A strictly positive displacement selects movement toward higher word positions, with cross-word bit redistribution when necessary.
- Zero or a negative displacement selects movement toward lower word positions, again with cross-word bit redistribution when necessary.

The layout and operations are consistent with shifting a signed, multiple-precision magnitude whose first word encodes a signed length. That interpretation is **inferred intent**, not an unconditional mathematical guarantee. Global multipliers and two opaque dependencies affect the representation and result.

The return value is path-dependent. It is not uniformly a success flag, a length, or the final header.

The function accepts:

1. A pointer to writable storage organized as 32-bit words.

The storage is addressed as follows:

The caller must provide valid, suitably aligned storage for every read and write reached on the selected path. The required extent depends on the decoded header, displacement, global values, and dependency behavior.

The object is modified in place. No ownership transfer, allocation, or release by this function is visible. Ownership behavior inside dependencies is unknown.

### Arithmetic model

The visible representation uses 32-bit words and signed 32-bit comparisons.

- Displacement direction is determined by interpreting the input word as signed.
- Bitwise operations act on 32-bit word values.

## Behavior

### Entry observations and branch selection

Before choosing a direction, the function reads and retains entry values of \(L_c\) and \(R_c\).

A displacement whose signed interpretation is greater than zero takes the higher-position path. Every other input, including zero and every input with its high bit set, takes the lower-position path.

The source does not establish a zero-displacement fast return.

### Higher-position path: preparation

For a positive displacement:

- The whole-word distance is the unsigned displacement divided by 32.
- The residual bit distance is the displacement modulo 32.
- The initial payload count is obtained using a fresh read of \(L_c\) multiplied by the current header, followed by signed absolute-value handling.
- F-a6b5d842289c is called with the object pointer.
- After the dependency returns, the function reads \(L_e\), \(L_d\), and \(L_h\), in that order.

The payload count is determined before the dependency call. Payload reads and later header reads may observe dependency modifications.

If the computed count is not strictly positive, this function performs no subsequent object write and returns the dependency’s entire 32-bit result. The dependency may already have modified the object or globals.

### Higher-position path: whole-word movement

This path applies only when the residual bit distance is zero.

For a positive pre-call count \(n\) and whole-word distance \(q\):

1. Payload words are copied from source positions \(n\) down through 1.
2. Each source word is written to its original position plus \(q\).
3. Positions \(q\) down through 1 are then filled with zero.
4. The header is read after these payload operations.
5. A new header is computed and stored.

Descending copying permits the ordinary higher-position movement to overlap its source without destroying unread words.

The signed count used for the final header is not simply the earlier absolute count. It is recomputed from the current header using the **entry-saved** \(L_c\). The whole-word distance is added for a nonnegative decoded count and subtracted for a negative decoded count. The result is multiplied by the post-dependency \(L_h\).

The function returns the exact word stored in the header.

The result of F-a6b5d842289c does not participate in this branch’s final header calculation.

### Higher-position path: residual-bit redistribution

This path applies when the residual bit distance is between 1 and 31 inclusive.

For a pre-call count \(n\), whole-word distance \(q\), and residual distance \(r\):

- Processing proceeds from payload position \(n\) down to position 1.
- Each source word is first multiplied by the post-dependency \(L_d\).
- Its upper \(r\) bits contribute to a destination one position above the ordinary whole-word destination.
- Its remaining shifted bits are retained for combination with the next lower source word.
- Each combined output word is multiplied by the post-dependency \(L_e\) before storage.

The first destination is position \(n+q+1\). It is written even if its value is zero.

After all source words have been consumed:

1. The final retained shifted word is written at position \(q+1\), with the same output multiplication.
2. Positions \(q\) down through 1 are written as zero through that output multiplication.
3. The function rereads position \(n+q+1\).
4. It tests that word after multiplication by \(L_d\).

The candidate output count is \(n+q+1\). It is reduced by exactly one if the top-word test is zero. There is no repeated trimming of additional zero words.

The new header is the 32-bit product of:

- the resulting count,
- the complete return word from F-a6b5d842289c,
- the post-dependency \(L_h\).

That word is stored at position 0 and returned.

Consequently, a dependency return other than a conventional sign value directly changes this header. The function does not independently constrain that result to −1, 0, or 1.

### Lower-position path: preparation and dependency gate

For a nonpositive signed displacement, the function forms the 32-bit unsigned negation of the input. Its quotient and remainder on division by 32 provide the whole-word distance and residual bit distance.

This includes the input word representing −2³¹: its unsigned negation is still 0x80000000, yielding a whole-word distance of 67,108,864 and a zero residual distance.

Before calling the dependency, the function derives an absolute count using a fresh read of \(R_c\) and the current header.

It then calls F-3530d7b2a2e7 with the object pointer. After that call, it reads \(R_d\), \(R_e\), and \(R_h\), in that order.

If the dependency returns any nonzero value:

- No transformation write by F-796113959089 follows.
- The return value is exactly 1, not the dependency’s original nonzero value.

Dependency side effects remain observable.

### Lower-position path: complete removal

If F-3530d7b2a2e7 returns zero and the whole-word distance is greater than or equal to the pre-call absolute count:

- The header is set to zero.
- The function returns zero.
- No payload clearing is performed by this function.

Old payload words therefore remain in storage beyond the zero header.

### Lower-position path: whole-word movement

This path applies when the dependency returns zero, the whole-word distance is smaller than the pre-call count, and the residual bit distance is zero.

Let the surviving count be the pre-call absolute count minus the whole-word distance.

The observable order is:

1. The current header is read and multiplied by the **entry-saved** \(R_c\).
2. The whole-word distance is subtracted from a nonnegative decoded count, or added to a negative decoded count.
3. The adjusted count is multiplied by a **fresh read** of \(R_h\) and written to the header.
4. Payload words are copied in ascending order from the surviving source range into positions beginning at 1.
5. The surviving count is returned.

The fresh \(R_h\) read used here is distinct from the earlier post-dependency snapshot.

Ascending copying preserves unread words for ordinary overlapping movement toward lower positions.

Payload words above the surviving range are not cleared. A zero displacement still takes this path when the count is positive and the dependency returns zero: the header is rewritten, and the surviving payload words are read and written back to their own positions.

### Lower-position path: residual-bit redistribution

This path applies when the dependency returns zero, some words survive whole-word removal, and the residual bit distance is between 1 and 31 inclusive.

Processing proceeds in ascending destination order.

For each destination below the final surviving position:

- The corresponding lower source word is multiplied by \(R_d\) and shifted right by the residual distance.
- The next source word is multiplied by \(R_d\) and shifted left by the complementary distance.
- The contributions are combined with bitwise OR.
- The combination is multiplied by \(R_e\) and stored.

For each such output, both source values contribute before the destination write. Relative evaluation order of the two source reads is not established.

The final surviving position receives only the right-shifted contribution from the highest retained source word, followed by multiplication by \(R_e\).

That final output word is tested after multiplication by \(R_d\). If the test is zero, the surviving count is reduced by exactly one. No further normalization is performed.

After payload writes, the function reads the current header and multiplies it by the **entry-saved** \(R_c\):

- A strictly positive signed result selects the positive surviving count.
- A zero or negative signed result selects its negation.

The selected count is multiplied by the post-dependency snapshot of \(R_h\). The resulting word is stored as the header and returned.

Any discarded payload positions remain untouched unless they were also destinations.

## Side effects

Established direct effects are:

- Reads of global representation parameters, including reads both before and after dependency calls.
- Exactly one dependency call on every normal path.
- In-place header and payload writes on transformation paths.
- Possible writes beyond the original highest payload position on higher-position paths.
- Retention of stale payload words on lower-position paths.
- A top-payload reread after higher-position residual redistribution.

No direct allocation, deallocation, I/O, or explicit error reporting is visible.

The function exposes no rollback behavior. Dependencies may modify storage or globals before a later path returns without direct writes.

No atomicity, synchronization, or safety under concurrent mutation is established. The mixed use of entry snapshots, pre-call reads, post-call snapshots, and one later fresh global read is observable behavior, not evidence that globals remain stable.
