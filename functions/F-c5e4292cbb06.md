## Behavior

The phases below describe the represented order. Reads observe memory at their own execution points, not necessarily its entry contents. Once a value has been captured, later writes do not change that retained value.

### Initial repeated mutations

The first phase contains six groups, each containing four ordered stores.

The first group:

1. Stores the payload as a word at destination base plus `0x54`.
2. Stores the low byte of context A at context B plus `0x19`.
3. Stores the low byte of context B at context A plus `0x11`.
4. Stores the destination-base value as a word at context B plus `0x34`.

Each of the next five groups:

1. Stores the payload as a word at twice context A plus `0x54`.
2. Stores the low byte of context A at context B plus `0x19`.
3. Stores the low byte of context B at context A plus `0x11`.
4. Stores twice context A as a word at context B plus `0x34`.

All 24 stores are part of the represented sequence. They must not be reduced to final-state assignments when describing access behavior.

Without interfering overlap, the word at context B plus `0x34` ends this phase containing twice context A. With overlap, all intervening stores remain relevant.

### Early reads and captured state

After the repeated stores, the function reads a word from fixed address `0xA9`. This is the **fixed snapshot**. It then reads a word from payload plus `0x74`, the **payload-associated word**.

Next, fixed address `0x3A` receives a byte equal to twice the low byte of context A plus `0x30`, reduced to eight bits. The resulting stored byte is the same whether the intermediate character interpretation is signed or unsigned.

Only after that store does the function read:

- A word from context C plus `0x14`, the **C snapshot**.
- A word from context A plus `0x04`, the **early A snapshot**.

These names refer to values captured at those reads. In particular, the C snapshot is not necessarily the entry value at context C plus `0x14`. The initial stores or the store at `0x3A` can modify that location before it is read.

### Byte mutations and the first overlapping word updates

The next effects occur in this order:

- Context C plus `0x0D` receives the low byte of context A.
- Context A plus `0x08` receives byte `0x6C`.
- Context A plus `0x0D`, then context A plus `0x09`, receive the low byte of context B.
- Context C plus `0x54` receives context C as a word.
- Fixed address `0x67` receives the low byte of the fixed snapshot.

The function then reads a signed word from context C plus `0x44`, the **shift-source word**. After that read, it reads the byte at `0x67` and writes the observed byte to `0x21`.

The shift-source word supplies three subsequent stores, in order:

- Its low byte goes to context A plus `0x10`.
- Its complete word goes to context B plus `0x54`.
- A byte derived by right-shifting it goes to context C plus `0x01`.

The shift count is the low eight bits of context A, giving a represented count from 0 through 255. Only the low byte of the shift result is stored. Negative operands and counts of 32 or greater require unresolved platform semantics; no count masking rule is established.

Context B plus `0x54` is then overwritten with context A as a word. The earlier store of the shift-source word remains part of the observable access sequence.

### Further snapshots and overlapping replacements

The function next reads a word from context A plus `0x40`. It then performs these ordered effects:

- Stores the early A snapshot at context B plus `0x74`.
- Stores the word just read from context A plus `0x40` at context A plus `0x10`.
- Stores context C at context B plus `0x44`.
- Reads the byte at `0x67` again and writes that observed byte to context A plus `0x09`.
- Stores the low byte of context A at context C plus `0x09`.
- Stores the fixed snapshot at context A plus `0x44`.

The word store at context A plus `0x10` covers offsets `0x10` through `0x13`. It replaces both the earlier byte at `0x10` and the byte at `0x11` from the initial phase. Its exact byte layout depends on endianness.

The second read of `0x67` is a new memory observation. It is not necessarily equal to the low byte originally written there if intervening stores overlap that address.

### First loaded destination

A word is now read from context A plus `0x54`. Its value becomes the **first loaded destination**.

After this read, the function reads `0x67` for the third time and writes that byte to context A plus `0x09`. It then:

- Stores the low byte of the payload-associated word at the first loaded destination plus `0x0D`.
- Stores the C snapshot at context C plus `0x54`.
- Reads a word from context A plus `0x14`, the **later A snapshot**.
- Stores the low byte of the payload-associated word at context C plus `0x11`.
- Stores the low byte of the first loaded destination at context A plus `0x09`.
- Stores the complete first loaded destination at context A plus `0x44`.

Thus context A plus `0x44` receives the fixed snapshot earlier and the first loaded destination later. Neither store guarantees the final contents of that location if subsequent overlapping accesses or the indirect target modify it.

The C snapshot remains the value captured at its earlier read. Writing it to context C plus `0x54` does not reload context C plus `0x14`.

### Repeated stores remain distinguishable

- One payload-word store at destination base plus `0x54`.
- Five payload-word stores at twice context A plus `0x54`.
- Six byte stores at context B plus `0x19`.

- One destination-base word store followed by five doubled-context-A word stores at context B plus `0x34`.

### Stored byte arithmetic wraps

If context A’s low byte is `0xF0`, the store at fixed address `0x3A` writes `0x10`, provided execution reaches it.

This is the eight-bit reduction of twice `0xF0` plus `0x30`. It does not require selecting a signed character interpretation.

### Snapshot retention starts at the read, not at entry

Assume the read from context C plus `0x14` yields `0x12345678`, and execution reaches the final invocation. Its third argument is `0x12345678`, even if subsequent writes change that memory location.

Merely placing `0x12345678` there on entry is insufficient. For example, context B plus `0x34` can equal context C plus `0x14`. If the initial repeated stores complete and no other overlapping write changes those four bytes before the snapshot read, that read yields twice context A instead.

The invariant is retention of the observed snapshot, not preservation of entry memory.

### A later word replaces earlier byte fields

Assume the relevant context A storage is valid and does not overlap other accessed regions. The word store at context A plus `0x10` replaces four bytes, including the byte at `0x11` written during the initial phase.

An acceptance criterion must not preserve that earlier byte independently of the replacing word. Exact replacement bytes require endianness information.

### Final arguments use observed loaded values

Assume the linked-value read yields `0x2000` and the later fourth-argument read yields `0xABCDEF01`. The final invocation receives those values as its second and fourth arguments.

Before the invocation, the final word store targets address `0x4000` and contains the second loaded destination, assuming that doubling is valid and the address is writable. It stores the loaded destination value, not its source address.
