# F-76844f7f0c19

## Purpose

F-76844f7f0c19 selects a descriptor through a 16-bit address, updates an implicitly supplied state region, requests a software breakpoint, and then chooses between two indirect calls and a coprocessor operation.

The supplied static representation establishes an ordered sequence of memory accesses and three terminal paths. It does not establish a conventional application-level purpose, a normal return, or executable behavior beyond the reported invalid-instruction boundaries.

All behavior below is conditional on reaching the relevant operation. A failed memory access, nonresuming breakpoint, or nonreturning indirect call can prevent later effects. This is a source-facing static contract; no runtime tests have been performed.

## Behavior

### Descriptor selection and breakpoint prefix

The function first reads an unsigned 16-bit value at the address-bearing argument plus byte offset `0x2E`.

It zero-extends that value and uses it directly as a descriptor address. The value is not an offset relative to the argument. Consequently, the selected descriptor address is between `0x00000000` and `0x0000FFFF`, inclusive.

It then performs these operations in order:

1. Reads the descriptor’s 32-bit word at offset `0x00`, producing the **captured selector**.
2. Reads the descriptor’s 32-bit word at offset `0x08`.
3. Stores the second value into the state region at offset `0x78`.
4. Requests a software breakpoint with immediate `0xD9`.

No preceding null check, range check, alignment check, or descriptor validation is represented.

The store at state offset `0x78` occurs before the breakpoint. Breakpoint handling, resumption, and handler-induced changes to memory or machine state are not established.

### Common operations after breakpoint resumption

If execution continues past the breakpoint, the represented order is:

1. Store the captured selector’s low eight bits at state offset `0x08`.
2. Read the global 32-bit word, producing the **captured global word**.
3. Read a 32-bit **captured gate word** from the address formed by adding the workspace-base address to the address of descriptor offset `0x0C`.
4. Store the low 16 bits of the state-base address at the selector-derived address obtained by subtracting `0x1D` from the captured selector.
5. Read the 32-bit state word at offset `0x00`.
6. Read the 32-bit state word at offset `0x04`.
7. Read the 32-bit state word at offset `0x08`.
8. Form the address of state offset `0x0C`.

The three state reads produce the **captured first**, **captured second**, and **captured third state words**, respectively. Forming the address of state offset `0x0C` does not itself read that location.

The gate read is not merely a read of descriptor offset `0x0C`, nor merely workspace offset `0x0C`. Its address combines both address-like quantities. The signed and pointer-derived arithmetic in this computation is not established to have the same wrapping semantics as the unsigned link calculations.

The state byte store precedes the later full-word read at offset `0x08`. Without intervening aliasing effects or external mutation, that read includes the byte update; the corresponding numeric bit position depends on byte order.

The selector-derived halfword store is unconditional once this prefix is reached. For selector `0x4B`, it targets address `0x2E`. For selector `0x4C`, it targets address `0x2F`. These are direct addresses, not offsets into the state or workspace.

### Nonzero gate

A nonzero captured gate word selects this path before any selector-equals-`0x4B` decision.

The indirect target is the unsigned 32-bit incoming link value plus `0xBE6`, reduced modulo $2^{32}$. No low-bit clearing is represented on this path.

The function invokes that target. The represented call supplies no explicit arguments; this does not establish the actual machine-level argument contract.

If the call returns to the represented continuation, control reaches a bad-instruction boundary.

On this path, the represented caller does not:

- Write the seven-field workspace record.
- Perform the two derived-address halfword reads.
- Write the six-field terminal state record.
- Issue the terminal coprocessor operation.

These exclusions apply only to this caller’s represented operations, not to effects of the unknown target.

### Zero gate and selector other than `0x4B`

If the captured gate word is zero and the captured selector is not exactly `0x0000004B`, the function writes seven 32-bit fields into the workspace in ascending offset order:

| Workspace byte offset | Value |
|---:|---|
| `0x00` | Zero |
| `0x04` | Captured first state word |
| `0x08` | Captured global word |
| `0x0C` | Captured second state word |
| `0x10` | Workspace-base address |
| `0x14` | Captured third state word |
| `0x18` | Address of state offset `0x0C` |

The written span is 28 bytes. No allocation or capacity check is represented.

After those stores, the function clears the incoming link value’s low two bits, then adds `0xE54` using unsigned 32-bit arithmetic. The addition wraps modulo $2^{32}$. Masking precedes addition.

It invokes the resulting indirect target. If the target returns to the represented continuation, control reaches a bad-instruction boundary.

The record stores use previously captured values. Even if workspace storage overlaps the state or global source locations, the represented caller does not reread those sources between these seven stores.

### Zero gate and selector exactly `0x4B`

If the captured gate word is zero and the captured selector equals `0x0000004B`, the function derives an address by logically shifting the unsigned captured first state word right by 14 bits.

The result lies between `0x00000000` and `0x0003FFFF`. The low 14 bits of the original word do not contribute to the derived address.

The function then:

1. Reads an unsigned 16-bit value at derived-address offset `0x04`.
2. Reads an unsigned 16-bit value at derived-address offset `0x22`.
3. Writes six 32-bit state fields in ascending offset order.

| State byte offset | Value |
|---:|---|
| `0x0C` | Captured first state word |
| `0x10` | Captured global word |
| `0x14` | First derived halfword, zero-extended |
| `0x18` | Workspace-base address |
| `0x1C` | Second derived halfword, zero-extended |
| `0x20` | Address of state offset `0x0C` |

Both halfword reads precede all six stores.

Their maximum start addresses are `0x00040003` and `0x00040021`, respectively. These additions cannot overflow a 32-bit unsigned value. These bounds do not establish valid mappings or alignment; each read also accesses the byte following its start address.

After the stores, the function issues a coprocessor move-to operation with represented selector operands `0xB`, `1`, and `5`. Its remaining operands are, in order, the zero-extended second derived halfword and the two implicit coprocessor inputs in their represented operand order.

Control then reaches a bad-instruction boundary. The coprocessor operation’s architectural meaning, privilege requirements, and completion behavior are not established.

## Side effects

### Memory footprint and ordering

The common prefix can modify:

- Four bytes starting at state offset `0x78`.
- One byte at state offset `0x08`.
- Two bytes starting at the selector-derived address.

The mismatching-selector branch additionally writes 28 workspace bytes. The matching-selector branch instead writes 24 state bytes starting at offset `0x0C`.

No disjointness guarantee is established. Descriptor, state, workspace, global, and derived locations may overlap. Ordering therefore affects observable results:

- The descriptor word stored at state offset `0x78` is read before that store.
- The state byte store precedes the global and gate reads.
- The gate read precedes the selector-derived halfword store.
- The three state-word captures follow that halfword store.
- The derived halfword reads precede the six terminal state stores.

For example, if the selector-derived store changes gate storage, branch selection still uses the previously captured gate word. If it changes a state word read afterward, it may affect that captured state value.

These are represented access-order guarantees, not a supplied interthread synchronization or hardware memory-ordering contract.

## Acceptance examples

These cases specify conditional consequences of the static representation. They are not executed tests.

### Nonzero gate takes precedence

Given completed common-prefix accesses, resumed execution after the breakpoint, and a nonzero captured gate:

- The nonzero-gate indirect target is selected even if the selector equals `0x4B`.
- The selector-derived halfword store and all three state-word captures occur before the call.
- Neither record-writing branch nor the terminal coprocessor operation is reached by the represented caller.

### Unsigned target wrapping

Given an incoming link value of `0xFFFFFFFF`:

- With a nonzero gate, the target is `0x00000BE5`: adding `0xBE6` wraps modulo $2^{32}$, without first clearing low bits.
- With a zero gate and mismatching selector, masking produces `0xFFFFFFFC`; adding `0xE54` wraps to `0x00000E50`.

These target values are established arithmetic results. They do not establish executable mappings, instruction-set mode, successful calls, or returning continuations.

### Zero gate and mismatching selector

Given a zero captured gate and selector `0x4C`:

- The common halfword store targets address `0x2F`.
- If that store and the subsequent captures complete, the seven workspace fields are written in the specified order.
- Only after those stores does the masked-link indirect call occur.

Whether a halfword store at the odd address `0x2F` is supported remains environment-dependent.

### Matching selector and low-address access

Given a zero captured gate and selector `0x4B`, the earlier halfword store targets address `0x2E`.

If this store prevents continuation, neither derived halfword read nor the six-field state update is reached. If execution continues, the captured first state word—not a later reread of state offset `0x00`—determines the shifted address.

### Unsigned extraction and widening

Given that the matching-selector path is reached with captured first state word `0xFFFFFFFF`:

- The derived address is `0x0003FFFF`.
- The halfword reads start at `0x00040003` and `0x00040021`.

If the second read returns `0xFFFF`, state offset `0x1C` receives `0x0000FFFF`, not a sign-extended value. The same zero-extended value is supplied to the coprocessor operation.

### Interrupted breakpoint prefix

If the breakpoint does not resume, the state store at offset `0x78` has already occurred, assuming earlier accesses completed. No subsequent byte store, global read, gate read, selector-derived store, indirect call, or coprocessor operation is established.
