# F-44af41b28801

## Purpose

F-44af41b28801 performs an external call and, if that call returns normally, executes a fixed sequence of five memory assignments. Two assignments target global storage. Three target four-byte fields at fixed offsets from a caller-supplied base address.

The resulting field values are zero, zero, and two. The external call precedes every assignment visible in this function.

**Inferred intent:** the sequence resembles initialization or reset of an object together with associated global state. Neither the meaning of the fields nor the meaning of the value two is established. This contract therefore specifies the operations without assigning application-level names to them.

The supplied representation describes the argument as an integer, but its visible use is address formation rather than ordinary numeric computation. The source-level pointer type, calling-convention representation, and address width are not independently established.

The function performs no explicit null check, bounds check, alignment check, or address-overflow check.

## Behavior

### Normal execution sequence

The established sequence is:

1. Invoke dependency D-01 with three argument values, in argument order: one, zero, and one.
2. After D-01 returns normally, assign zero to G-01.
3. Assign zero to G-02.
4. Store a four-byte zero at base offset 0x40.
5. Store a four-byte zero at base offset 0x44.
6. Store the four-byte value two at base offset 0x48.
7. Return without a specified value.

This is an ordering contract for the operations visible in the supplied representation. It does not establish atomicity, synchronization, or an observation order available to other processors or devices.

There are no visible branches, loops, input-dependent choices, or checks of a dependency result.

### Dependency boundary

D-01 is called before either global is reset and before any of the three object-relative fields is assigned. Consequently, this function does not initialize those destinations before exposing execution to the dependency.

D-01's implementation is unavailable. It may read or modify global state, including the destinations later written by this function. It may also affect memory reachable by other means. Such behavior is neither established nor excluded here.

If D-01 changes G-01, G-02, or the three object-relative destinations and then returns normally with those destinations still writable, this function subsequently performs its own assignments in the stated order.

No explicit data argument derived from the supplied base is passed to D-01. This does not prove that D-01 cannot discover or affect the same object through global state or another alias.

### Object-relative writes

Each of the three object-relative stores has a width of four bytes. The stores are adjacent and do not overlap one another when the address calculations resolve conventionally without wrapping or other invalid-address behavior.

The assigned quantities are integer zero and integer two. Their exact byte encodings depend on the target representation, particularly byte order. For example, the location of the nonzero byte representing two cannot be specified from this excerpt alone.

The function does not directly read the previous contents of these fields. Their old values do not control the visible sequence. It also does not directly write the object prefix before offset 0x40 or any object-relative location beyond the final four-byte store.

These direct-access limits do not constrain accesses performed inside D-01.
