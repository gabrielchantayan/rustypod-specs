# F-7b7a605b7995

## Purpose

F-7b7a605b7995 performs an ordered sequence of indirect dependency invocations, derives fixed-width values from invocation results and incoming machine state, modifies fixed and computed memory locations, and ends with an unresolved indirect transfer.

The supplied static representation does not establish an application-level purpose. Character-valued constants do not establish a text-formatting interface, and pointer-like accesses do not establish an object model.

This contract distinguishes:

- **Established static evidence:** represented operations, access widths, value dependencies, and ordering.
- **[INFERENCE]:** possible intent, not an acceptance requirement.
- **documented_only:** behavior not resolved sufficiently to specify an executable requirement.

The contract describes state-dependent effects, not a pure transformation of explicit arguments. No runtime tests have been performed.

## Interface

### Inputs and outputs

The displayed interface has no explicit parameters and no explicit return value. Its effective inputs nevertheless include:

- Incoming control state determining the first indirect target.
- An incoming 32-bit value used for an early bit-field extraction.
- Primary and secondary machine-state results of dependency invocations.
- Memory at fixed addresses and at addresses derived from those results.
- A memory-resident address captured before the repeated-write region.
- The target and effective calling convention of the final transfer.

Secondary results are represented separately from ordinary declared return values. Consequently, the displayed interface is not a complete machine-level calling contract.

There is no established status result or application-level output. Outputs consist of dependency invocations, direct memory effects, and the final transfer.

|---|---:|---|
| Byte access | 8 bits | Stores retain the low eight bits. Unsigned byte reads yield 0–255. |

### Preconditions

Normal completion requires every earlier dependency to return and every reached access to be valid. The function supplies no visible validation of addresses, bounds, alignment, arithmetic overflow, or executable targets.

Storage at low fixed addresses is an execution prerequisite, not an allocation performed by this function. Null values have no established special failure meaning.

## Behavior

### Dependency invocation phase

The function starts with a long straight-line sequence of indirect invocations. The first target is obtained from incoming control state using displacement 0xFFE. Subsequent targets use embedded control-location values with the same displacement.

Displayed invocations have zero to four argument words. Their argument patterns do not establish common identity, signatures, or purpose. An invocation displaying no arguments may still consume ambient machine state and modify memory or globals.

Established value transformations include:

- Extracting incoming bits 16–25 and placing the resulting ten-bit field beginning at bit 6.
- Shifting primary results left by eight bits.
- Passing a shifted low result word alongside an unchanged high word.
- Shifting high words or secondary results independently.
- Masking selected low-bit fields before further shifts.
- Unsigned right shifts and extractions beginning at paired-result positions 34, 36, and 44.
- Passing the same derived word in multiple argument positions.
- Passing explicit zeros, including operands derived by shifting retained zero values.

Invocation order and retained-value dependencies matter. Unknown dependencies may alter storage read much later. Matching argument patterns do not justify invocation elimination or reordering.

**documented_only:** this document does not enumerate every invocation occurrence or every intermediate argument expression. It therefore does not supply a complete dependency-phase replay trace.

### Arithmetic requirements

Unsigned transformations support fixed-width bit-vector interpretation. Intermediate truncation matters: an eight-bit left shift followed by an unsigned eight-bit right shift need not recover the original word.

Some address-producing expressions are represented with signed operands, including large left shifts and multiplication. Their exact overflow behavior is not established by the supplied representation. Treating them as modulo-2³² arithmetic is a conditional machine model, not an unconditional language-level guarantee.

A late signed right shift uses the low eight bits of a derived address as its count. Behavior for counts of 32 or more, and the treatment of negative operands, remain documented_only.

### Initial writes, clears, and fixed-storage interaction

The direct-memory region first stores the packed base as a word at offset 0x14 from the high word of the last paired result. It writes that high word’s low byte at packed-base offset 9, stores the cleared base at offset 0x54 from the last low word scaled by 0x100, and overwrites packed-base offset 9 with the packed base’s low byte.

Next, the function clears the word at cleared-base offset 0x14 and reads an unsigned byte at cleared-base offset 5. Before storing that promoted byte at cleared-base offset 0x34, it clears doubled-base offset 0x14. It then reads back cleared-base offset 0x14, clears doubled-base offset 0x14 again, and performs two byte writes at doubled-base offset 0x15 using the captured word’s low byte.

The following fixed-storage boundary is explicit:

- An unsigned byte is read at absolute address **0x05**.
- A byte containing the doubled base’s low eight bits is written at absolute address **0x01**.
- The byte read at 0x05 supplies the numerical base for a byte store at offset 0x15, whose value is the field value’s low byte.

The byte write at 0x01 is therefore after the fixed byte read and before that computed byte store.

Subsequent effects include a payload byte at cleared-base offset 0x11, a payload word at offset 0x54 from the captured cleared-base word, and a zero-byte overwrite at cleared-base offset 0x11. The link seed is read from offset 0x54 of the byte-derived base before that location is replaced with the captured cleared-base word.

Further accesses store the field value at doubled-base offset 0x34, follow words at offset 0x74, and perform linked word stores, self-address stores, and repeated byte stores. Re-reading a cleared word cannot generally be replaced by a constant zero: intervening stores may alias it.

Two additional fixed effects occur within this computed-access sequence:

- After storing a retained result shifted by 26 bits at doubled-base offset 0x14, the function writes a **32-bit word at absolute address 0x54**, containing the link seed shifted left by one bit. It then stores the link seed at doubled-base offset 0x14 twice.
- After two byte writes of the fourfold base’s low byte at doubled-base offset 0x15, it writes a **byte at absolute address 0x15**, containing the doubled base’s low byte. This precedes the payload word store at fourfold-base offset 0x54 and the scaled-word store at doubled-base offset 0x34.

These are absolute-address effects, not merely additional object offsets.

### Scaled links and constant stores

The following region scales retained or loaded words by two, four, and eight, follows unsigned-byte-derived links, and mixes word and byte updates at offsets including 4, 5, 9, 0x0D, 0x14, 0x15, 0x34, 0x44, 0x54, 0x64, and 0x74.

A later word read at offset 4 supplies a base whose offset-5 byte is read more than once, with writes between those reads. Those byte reads must not be presumed equal. The later byte-derived offset-0x74 lookup supplies the selected link.

The constant-write portion includes, in order:

- A byte containing 0x3A at four times the selected link.
- A halfword containing 0x003A at eight times the selected link.
- A word containing 0x0000003A at offset 0x20 from four times the selected link.

At adjusted-base offset 0x20, successive word stores contain 0x20 and 0x2F, followed by a word containing the zero-extended byte read at adjusted-base offset 4, followed by another word containing 0x20. The byte read occurs after the first two stores; aliasing can affect its value.

### Repeated-write transition and region

The transition order is:

**The repeated base is loaded first. The 32-bit store of 0x00000020 at absolute address 0x60 occurs afterward. The repeated computed stores follow.**

The base load must not be moved across the store at 0x60. Its value is determined before that store and remains retained even if later writes overlap its backing storage.

Each recurring store group has four ordered effects:

- A word containing four times the selected link is stored at offset 0x54 from an eight-times-scaled seed.
- A byte containing the adjusted base’s low byte is stored at repeated-base offset 0x19.
- A byte containing the repeated base’s low byte is stored at adjusted-base offset 0x11.
- An eight-times-scaled seed is stored as a word at repeated-base offset 0x34.

The first group uses the link seed for both eight-times-scaled operands. Subsequent groups use the adjusted seed. Thus, the first group differs in both its initial destination and its final word value.

The byte values and repeated base are retained values, not fresh memory reads in each group. Nevertheless, repeated accesses are part of the represented trace and cannot be replaced by final-state assignments without an appropriate memory-observability model.

**documented_only:** an exact repetition count is not asserted here. No equivalence to one group, an arbitrary count, or a single final overwrite is established.

### Late captures and fixed-byte dependencies

After the repeated stores, the late region establishes several distinct capture times.

First, a **32-bit word is read at absolute address 0xA9**. A word is then read at offset 0x74 from four times the selected link. Only afterward does the function write a **byte at absolute address 0x3A**, containing the low eight bits of eight times the adjusted seed plus 0x30.

The function next captures:

- A word at offset 0x14 from twice the selected link; this becomes the final transfer’s third displayed argument.
- A word at adjusted-base offset 4.

These captures occur after the byte write at 0x3A. That write may therefore affect them if storage overlaps.

Before the next fixed-byte write, the function writes the adjusted base’s low byte at offset 0x0D from twice the selected link, writes 0x6C at adjusted-base offset 8, writes the repeated base’s low byte at adjusted-base offsets 0x0D and 9, and stores a self-address word at offset 0x54 from twice the selected link.

It then writes a **byte at absolute address 0x67**, using the low byte of the earlier word captured at 0xA9.

The subsequent fixed-byte accesses are fresh reads, not guaranteed uses of that retained low byte:

1. A computed word is read at offset 0x44 from twice the selected link.
2. A byte is read at absolute address **0x67** and written at absolute address **0x21**.
3. Computed writes use the captured offset-0x44 word: its low byte goes to adjusted-base offset 0x10, and its full word goes to repeated-base offset 0x54. A byte derived by the variable signed right shift goes to offset 1 from twice the selected link.
4. Repeated-base offset 0x54 is overwritten with the adjusted base. A word is read at adjusted-base offset 0x40; the earlier offset-4 capture is stored at repeated-base offset 0x74; the newly read word is stored at adjusted-base offset 0x10. A link word is stored at repeated-base offset 0x44.
5. Address **0x67 is read again** to supply a byte store at adjusted-base offset 9.
6. A byte store occurs at offset 9 from twice the selected link. The captured 0xA9 word is stored at adjusted-base offset 0x44, and a word is read at adjusted-base offset 0x54.
7. Address **0x67 is read a third time** to supply another byte store at adjusted-base offset 9.

Each read observes its own position in this sequence. Intervening computed writes can overlap 0x67; the three observed bytes need not agree. Likewise, the computed word read before the assignment to 0x21 remains before that assignment.

### Final linked updates and transfer

The word captured from adjusted-base offset 0x54 becomes a late linked base. The low byte of the earlier offset-0x74 capture is written at its offset 0x0D. The earlier offset-0x14 capture from twice the selected link replaces that location’s self-address word at offset 0x54.

A word is then captured from adjusted-base offset 0x14. Subsequent byte and word writes include the earlier offset-0x74 capture’s low byte at offset 0x11 from twice the selected link, and the late linked base at adjusted-base offsets 9 and 0x44, with their respective widths.

A word read at offset 4 from twice the selected link supplies another address. The function writes halfword 0x0065 at twice that address, reads its offset-0x64 word, writes the low byte of the adjusted-base offset-0x14 capture at late-linked-base offset 0x11, and writes word 100 at late-linked-base offset 0x54.

Finally, it captures the new address’s offset-0x74 word, reads another word at offset 0x64 from twice the selected link, performs a byte write at offset 9 from twice the selected link, and performs two linked word stores. One stores the previously read offset-0x64 word at offset 0x54 from the other loaded link; the other stores that other link at twice the previously read word.

The final unresolved dependency receives four displayed argument words:

1. 0x72.
2. The word read at offset 0x64 from the address obtained through the late offset-4 lookup.
3. The earlier capture at offset 0x14 from twice the selected link.
4. The late capture at offset 0x74 from the address obtained through the late offset-4 lookup.

A return is displayed after the transfer. Actual target return, termination, fault, or nonlocal control flow is unresolved.

## Side effects

Direct effects include byte, halfword, and word updates to fixed and computed storage. Fixed effects specifically include byte writes at 0x01, 0x15, 0x21, 0x3A, and 0x67, and word writes at 0x54 and 0x60.

Indirect dependencies may additionally modify globals, memory, and execution state. No preservation guarantee is available.

No explicit allocation, release, reference counting, or ownership transfer is established. Storing address-like words does not establish ownership or lifetime extension. Unknown dependencies may allocate or release storage; neither behavior is assumed.

No visible error status, rollback, cleanup branch, or transactional guarantee exists. A fault or nonreturning invocation can leave earlier effects completed. Environmental failure reporting is documented_only.

The represented ordering is not evidence of atomicity, synchronization, or a cross-thread memory-order guarantee.

## Acceptance examples

These are conditional static examples, not executed tests.

### Field extraction and truncation

For incoming word 0x03FF0000, the early ten-bit extraction produces 0x0000FFC0. Bits outside positions 16–25 do not affect this argument.

Under truncating 32-bit arithmetic, shifting 0xAB123456 left eight bits produces 0x12345600; a subsequent logical right shift by eight produces 0x00123456.

### Fixed-storage ordering

If execution reaches the fixed byte read at 0x05, a trace must place it before the byte write at 0x01, which in turn precedes the following byte-derived offset-0x15 store.

The fixed word write at 0x54 must remain between the preceding doubled-base offset-0x14 store and the following two stores of the link seed there. The fixed byte write at 0x15 follows the duplicate computed offset-0x15 byte stores.

### Repeated-base capture

If the repeated base is captured as address A, subsequent repeated stores use A even if the later word store at 0x60 or another computed store changes its backing location. Reloading the base after the 0x60 store is not equivalent without additional assumptions.

### Distinct reads of 0x67

If the write at 0x67 stores 0xB2, but an intervening aliased computed access changes it, the assignment to 0x21 uses the byte actually read after the computed offset-0x44 word read. The two later computed byte stores likewise use their own fresh reads of 0x67, not necessarily 0xB2 or the byte written to 0x21.

### Width and overwrite visibility

An unsigned byte observation of 0xE3 promotes to word 0x000000E3. The 8-, 16-, and 32-bit stores of 0x3A have different footprints.

Where accesses are observable, successive word values 0x20, 0x2F, the promoted byte, and 0x20 remain separate effects. A final-state-only implementation is insufficient.

### Final transfer

Conditional on all earlier operations completing normally, F-U003 receives the four words in the specified order, beginning with 0x72. No memory postcondition after that dependency is established.
