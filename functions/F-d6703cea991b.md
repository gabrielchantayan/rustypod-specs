# F-d6703cea991b

## Purpose

F-d6703cea991b conditionally updates a receiver after consulting an associated provider. A successful provider response produces two unsigned 32-bit bounds. The function then performs one-time guarded initialization and chooses between:

- Recording a deferred operation in receiver fields.
- Executing an immediate sequence of external and receiver-dispatched operations.

The provider’s initial response gates all subsequent work. A zero response causes return without the receiver-field writes or later calls described below. The provider call itself can still have side effects.

“Provider,” “bounds,” “initialization,” “deferred,” and “immediate” are descriptive terms inferred from the data flow. They do not establish application-level meanings, resource ownership, or the effects of opaque dependencies.

## Behavior

### 1. Provider consultation

The function obtains the provider reference from receiver offset `0x18`, obtains its dispatch table, and resolves the operation at dispatch-table byte offset `0x0C`.

It creates a local unsigned 32-bit selector initialized to the original flags. The initial provider operation receives, in order:

1. The provider reference.
2. The request.
3. The address of the mutable selector.
4. The resolved operation’s own function address.
5. The context.

The fourth argument is explicitly present in the supplied call representation. Its purpose is unknown.

If the returned 32-bit integer is zero, F-d6703cea991b returns immediately. In particular, it does not directly inspect the initialization guard, select a mode, or write the receiver operation fields.

If the response is nonzero, processing continues. Negative nonzero responses are not rejected.

The writable selector and the original flags are distinct values. Provider changes to the selector affect subsequent provider queries, but do not change the flags used for deferred byte storage or the immediate-path bit-mask test.

### 2. Bound queries and normalization

Following a nonzero response, the function calls the provider operation at dispatch offset `0x1C`, passing the provider reference and the current selector. Its result is interpreted as an unsigned 32-bit first bound.

It then calls the provider operation at dispatch offset `0x20` with the provider reference and current selector. Its result is interpreted as an unsigned 32-bit candidate second bound.

These calls occur in that order. The provider reference and dispatch entries are obtained again for the later calls; the function does not establish that they still identify the provider used for the initial consultation.

The second bound is normalized as follows:

- If the candidate is zero, the normalized second bound is `0x7FFFFFFF`.
- If the candidate is less than or equal to the first bound under unsigned 32-bit comparison, the normalized second bound is `0x7FFFFFFF`.
- Otherwise, the candidate is retained.

No further normalization follows. In particular, substituting `0x7FFFFFFF` does not guarantee that the normalized second bound exceeds the first bound. The first bound is never clamped by this logic.

### 3. Guarded initialization

The function next reads the byte at receiver offset `0x70`.

If it is zero, the function:

1. Writes `1` to that byte.
2. Calls F-c6490547a789 with the receiver.
3. Calls F-80a6c6456406 with the address at receiver offset `0x80`.
4. Calls F-ce2b98551acc with the result of F-80a6c6456406, the result of F-c6490547a789, and a final 32-bit zero argument.

The flag write precedes all three calls. There is no visible rollback if a dependency fails to return normally. A dependency can observe the flag as already set.

If the guard byte is any nonzero value, this entire initialization sequence is skipped. The guard is not normalized to `1` in that case.

The mode byte at `0x71` is read after this sequence. Consequently, changes made by initialization dependencies can affect which mode is selected.

### 4. Deferred recording

If the mode byte at `0x71` is zero when examined, the following direct writes occur in order:

1. Store the normalized second bound as 32 bits at `0x54`.
2. Store the first bound as 32 bits at `0x50`.
3. Store the request as 32 bits at `0x4C`.
4. Write zero to the byte at `0x58`.
5. Write the low eight bits of the original flags to `0x59`.
6. Write zero to the byte at `0x67`.

The function then returns. It does not execute the immediate-path external or receiver-dispatched calls.

The flags-to-byte conversion retains the low eight bits. For example, `0x00000180` produces the stored byte `0x80`. The later interpretation of that byte as signed or unsigned is not established.

### 5. Immediate execution

If the mode byte is nonzero, the function first stores the 32-bit all-ones value at receiver offset `0x4C`. This is represented as signed `-1`, with bit pattern `0xFFFFFFFF`.

It then performs this ordered sequence:

1. Call F-000000000007 with `(1, 4)`.
2. Call F-000000000008 with no arguments.
3. Call F-000000000009 with no arguments, obtaining a value.
4. Call F-00000000000a with that value, the context, and `1`.
5. If the context is nonzero:
   - Call F-00000000000b with no arguments.
   - Call F-00000000000c with its result, `1`, and `0`.
6. Read the receiver byte at `0x67`. If its value is exactly `1`:
   - Write zero to that byte.
   - Invoke the receiver operation at dispatch offset `0xD4` with the receiver, `0x7FFFFFFF`, and `0`.
7. Invoke the receiver operation at dispatch offset `0xCC` with the receiver, request, first bound, normalized second bound, and `0`.
8. Invoke the receiver operation at dispatch offset `0xC8` with the receiver, first bound, and normalized second bound. Interpret its result as an unsigned 32-bit mask.
9. If the bitwise intersection of that result and the original flags is nonzero:
   - Call F-000000000010 with no arguments.
   - Call F-000000000011 with its result and `1`.
10. Call F-000000000009 again, obtaining a fresh value.
11. Call F-000000000012 with that fresh value, `1`, and `1`.
12. Call F-000000000007 with `(0, 4)`.
13. Call F-000000000008 with no arguments.

The second call to F-000000000009 is not replaced by reuse of its earlier result.

The optional operation at receiver dispatch offset `0xD4` requires the byte at `0x67` to equal exactly `1`. Other nonzero values do not trigger that operation and are not cleared by this branch.

The byte at `0x67` is read after the preceding external calls, not at function entry. Dependencies can therefore affect whether the optional operation occurs.

Receiver dispatch operations are resolved at their respective call sites. Earlier dependencies may change the receiver’s dispatch table; this contract does not assume a stable table across calls.

## Side effects

### Direct mutations

On the successful deferred path, direct mutations are limited to the listed receiver writes and the optional initialization-guard write.

On the successful immediate path, the function directly writes:

- The initialization guard, if originally observed as zero.
- The all-ones request sentinel at `0x4C`.
- Zero at `0x67`, only if that byte is observed as exactly `1` at its conditional check.

The immediate path does not directly store either bound at `0x50` or `0x54`, or update bytes `0x58` and `0x59`. Dependencies may nevertheless modify those locations.

### Ownership and lifetime

No direct allocation, deallocation, ownership transfer, or reference-count operation is established by the visible body.

The initial provider operation receives an address into this invocation’s local storage. That address is usable during the call. No permission to retain it beyond the invocation is established.

The receiver, provider, dispatch tables, and receiver region beginning at `0x80` must remain valid for their respective accesses. No assumption is made that unknown dependencies preserve global state, preserve receiver state, or acquire or release memory.

### Errors and interruption

Only the initial provider response is explicitly checked as a success gate. Other call results are either forwarded, interpreted as unsigned values, tested as a mask, or ignored.

There is no visible exception handler, cleanup handler, retry, rollback, or guaranteed-finalization mechanism. If an intervening call does not return normally, later operations—including the final `(0, 4)` call—are not established to occur.

The paired `(1, 4)` and `(0, 4)` calls suggest a bracketed external-state change, but neither the state affected nor restoration semantics are established.

## Acceptance examples

These are conditional contract examples, not executed tests. Except where stated otherwise, dependencies return normally and do not independently alter relevant state.

1. **Provider refusal.**  
   If F-000000000001 returns zero, no bound queries, guarded initialization, deferred writes, or immediate operations follow. Side effects of the consultation itself remain possible.

2. **Provider-selected query value.**  
   With original flags `0x00000102`, if the provider changes the selector to `7` and returns nonzero, both bound-query calls receive `7`. Deferred flag storage still receives `0x02`; an immediate mask test still uses `0x00000102`.

3. **Ordinary deferred recording.**  
   With zero mode, first bound `10`, candidate second bound `20`, and request `42`, the function stores `20` at `0x54`, `10` at `0x50`, and `42` at `0x4C`, in that order, before its three byte writes.

4. **Equality is normalized.**  
   First bound `10` and candidate second bound `10` produce normalized second bound `0x7FFFFFFF`. A candidate of `11` is retained.

5. **Normalization does not ensure increasing bounds.**  
   First bound `0x80000000` and candidate `0` produce normalized second bound `0x7FFFFFFF`, which is smaller under unsigned comparison. No additional correction occurs.

6. **High unsigned candidate is valid.**  
   First bound `0x7FFFFFFF` and candidate `0x80000000` retain the candidate. The comparison is not signed.

7. **Initialization can select the mode.**  
   If the guard is zero, the function writes `1` before calling the initialization helpers. If a helper changes the mode from zero to nonzero, immediate execution is selected afterward.

8. **Exact byte condition.**  
   On the immediate path, a byte value of `1` at `0x67` causes a zero write followed by F-00000000000d. A value of `2` causes neither action at that check.

9. **Original flags control the optional mask action.**  
   If original flags are `0x04` and F-00000000000f returns `0x0C`, F-000000000010 and F-000000000011 execute. With result `0x08`, they do not. With original flags zero, they never execute through this condition.

10. **Zero context skips only its conditional pair.**  
    Zero context is still passed to the initial provider consultation and F-00000000000a. It skips F-00000000000b and F-00000000000c, not the remaining immediate sequence.
