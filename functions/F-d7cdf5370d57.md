# F-d7cdf5370d57

## Purpose

The supplied static representation establishes writes to byte-, halfword-, and word-sized locations, reads of pointer-like fields, accesses to fixed low addresses, and a final four-argument invocation. ## Behavior

### Initial repeated publication

The opening phase writes the payload into the destination’s word field at offset `0x54`.

It then establishes two byte values from the entry state:

- The low byte of the anchor.
- The low byte of the peer.

These are written to peer offset `0x19` and anchor offset `0x11`, respectively. The destination value is then written as a word to peer offset `0x34`.

The following recurring update uses a derived base equal to twice the unsigned anchor:

- The payload is published to the word at derived-base offset `0x54`.
- The anchor-derived byte is published at peer offset `0x19`.
- The peer-derived byte is published at anchor offset `0x11`.
- The doubled anchor replaces the word at peer offset `0x34`.

The supplied representation contains many consecutive occurrences of this same four-write ordering. They are unconditional; no intervening test, allocation, or explicit call is shown. The exact repetition count is `documented_only` in this contract and must not be inferred from a single collapsed update.

For ordinary, nonoverlapping memory, the later updates supersede the earlier peer word containing the destination. This does not make that earlier write unobservable or removable from the behavioral trace.

### Initial snapshots and fixed-address updates

After the repeated phase, the function captures:

- A word beginning at fixed address `0xA9`.
- A word at payload offset `0x74`.

It then writes a byte to fixed address `0x3A`. That byte is the low eight bits of twice the anchor-derived byte plus `0x30`. Any ambiguity over signed interpretation of the intermediate byte does not change those resulting eight bits.

Only after that fixed-address write does it capture:

- A word at context offset `0x14`.
- A word at anchor offset `0x04`.

These snapshots are later used even if subsequent writes change their original storage.

The function then modifies several small fields: context offset `0x0D` receives the anchor-derived byte; anchor offset `0x08` receives `0x6C`; and anchor offsets `0x0D` and `0x09` receive the peer-derived byte. A word at context offset `0x54` receives the context value itself.

Next, fixed address `0x67` receives the low byte of the earlier word snapshot from `0xA9`.

### Intermediate field replacement

A word is read from context offset `0x44`. Its low byte is written to anchor offset `0x10`, and its complete word is written to peer offset `0x54`.

Between that word read and those field updates, the byte at fixed address `0x67` is read and copied to fixed address `0x21`. This is a memory read, not an unconditional reuse of the earlier snapshot.

The function also writes a shifted byte to context offset `0x01`. The source is the signed word previously read from context offset `0x44`; the shift count is the low eight bits of the anchor.

The exact result is `documented_only` when that count is outside the supported word-shift range or when the source is negative and signed right-shift behavior matters. This contract does not silently impose count masking or an arithmetic-shift rule.

Peer offset `0x54` is subsequently overwritten with the full anchor value.

A word is then read from anchor offset `0x40`. The earlier snapshot from anchor offset `0x04` is written to peer offset `0x74`, after which the newly read word is written at anchor offset `0x10`.

That word write spans offsets `0x10` through `0x13`, replacing the earlier byte at `0x10` and potentially replacing the byte at `0x11` written during the opening phase.

Further updates:

- Peer offset `0x44` receives the context value as a word.
- Anchor offset `0x09` receives a fresh read of the byte at fixed address `0x67`.
- Context offset `0x09` receives the anchor-derived byte.
- Anchor offset `0x44` receives the complete earlier snapshot from fixed address `0xA9`.

### Loaded-address mutations

A word at anchor offset `0x54` is loaded and subsequently used as an address base, called the **selected address** here.

After that load, anchor offset `0x09` again receives a fresh read from fixed address `0x67`.

The low byte of the earlier payload-offset-`0x74` snapshot is written at selected-address offset `0x0D`. The previously captured word from context offset `0x14` then replaces context offset `0x54`.

A word is read from anchor offset `0x14`. The payload-derived byte is written at context offset `0x11`. Anchor offset `0x09` is then overwritten with the low byte of the selected address, and anchor offset `0x44` receives the complete selected address.

Thus, under nonaliasing conditions, neither the fixed-address byte nor the earlier peer-derived byte is the final value at anchor offset `0x09`.

### Final linkage and transfer

The function loads a word from context offset `0x04`, called the **node address** here. It writes the 16-bit value `0x0065` at twice that value.

It then reads a word from node-address offset `0x64`, called the **link value**.

The low byte of the earlier anchor-offset-`0x14` snapshot is written at selected-address offset `0x11`. The word at selected-address offset `0x54` receives decimal `100`, equivalent to `0x00000064`.

Next, the function reads a word from node-address offset `0x74`, followed by a word from context offset `0x64`. The latter becomes the **final destination**.

Context offset `0x09` is overwritten with the low byte of the node address. The link value is written to final-destination offset `0x54`. Finally, the final destination is written as a word at twice the link value.

The unresolved target is invoked after these writes, with arguments in this order:

1. `0x72`.
2. The link value.
3. The earlier snapshot from context offset `0x14`.
4. The later snapshot from node-address offset `0x74`.

No visible read occurs between the final word write and that invocation.

## Side effects

### Aliasing and access order

No nonaliasing guarantee is established.

Any explicit base, implicit base, derived address, loaded address, or fixed address may overlap another accessed region. Consequently:

- A write can change a later pointer-like read.
- A byte write can alter part of a later word read.
- A word write can replace previously written byte fields.
- A fixed-address access can overlap a base-relative access.
- A later store can overwrite an earlier store even when their nominal bases differ.

The access sequence, rather than a simplified final-field table, defines the static behavior. Values already captured remain snapshots; later reads observe memory at their actual position in the sequence.

The low fixed addresses are not established as ordinary globals, device registers, or invalid addresses. Their classification is `documented_only`.
