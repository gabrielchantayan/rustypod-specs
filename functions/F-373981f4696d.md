# F-373981f4696d

## Purpose

F-373981f4696d finalizes a block-oriented operation using mutable context storage, a destination address, and a result-length address.

**Established static behavior:** A nonzero mode selects a branch that can fill an internal block with repeated padding bytes and invoke an indirect callback. Zero mode selects a branch that can validate a retained block’s trailing bytes and copy its preceding bytes to the destination. Some branches succeed without producing output.

**Inferred intent:** These branches resemble padded encryption and decryption finalization, respectively. This interpretation does not establish an algorithm, public API identity, or the callback’s transformation.

The contract distinguishes direct effects from dependency effects. In particular, callback-target resolution occurs **after** padding writes. Neither the descriptor address nor the callback address is guaranteed to remain the one that existed before those writes.

## Interface

### Arguments and result

| Input | Established role |
|---|---|
| Context address | Addresses mutable state, internal byte regions, and a descriptor-address field. |
| Destination address | Passed to the callback or used for direct retained-byte output. |
| Result-length address | Addresses a writable unsigned 32-bit word. |

The represented interface uses 32-bit addresses and integer words. The function returns a signed 32-bit integer.

- Direct success paths return **1**.
- Directly detected recoverable errors invoke F-4fc89ec41a6d and return **0** if that dependency returns normally.
- The callback path returns the callback’s integer result unchanged. Nonzero callback results are not normalized to 1.

There is no explicit validation of null addresses, destination capacity, storage overlap, or callable-target validity.

|---|---:|---|

For widths up to 32 and nonnegative valid counts, internal padding writes stay within context offsets 48–79. Retained-block processing uses offsets 108–139. These bounds do not establish the complete context allocation size.

### Preconditions for defined access

Storage must be readable or writable for every access reached on the selected path. The destination must accommodate the actual direct copy or callback output; no capacity argument is supplied.

The callback path requires a valid target **at the time of the post-fill lookup**, not merely before entry. Its additional preconditions are unknown.

A buffered count between zero and the block width is an ordinary-use assumption, not an enforced invariant. Negative counts can write before the internal block, including into context fields. Counts equal to or greater than the width suppress padding writes.

Extreme address arithmetic, invalid storage, or an invalid late callback target has no established recoverable-error contract.

## Behavior

### Initial mode selection

The function first reads the 32-bit mode at context offset 8.

- Nonzero selects the padding-generation branch.
- Zero selects the retained-output branch.

On the callback path, the mode supplied as the fifth argument is this initially captured value. Later memory changes to the mode field do not replace that argument.

### Nonzero mode: width and early exits

The function reads the descriptor address from context offset 0, then the unsigned 32-bit width from descriptor offset 4.

A width greater than 32 invokes a dependency represented as non-returning. This check occurs before the padding-disable flag or buffered count can exempt the operation. Values with the high bit set also exceed this unsigned bound.

Width 1 is an immediate success case: the function writes zero to the result-length word and returns 1. It does not inspect the buffered count or flags on that path.

For every remaining width, it reads the signed buffered count and then checks flag mask 0x100.

### Nonzero mode: padding enabled

When mask 0x100 is clear, the function writes consecutive internal-block bytes beginning at the captured buffered count and ending immediately before the captured width.

Every written byte equals:

**captured width minus original buffered count, reduced modulo 256.**

The fill proceeds in increasing address order. The byte value does not change as the write position advances.

Consequences include:

- Count zero fills the entire block.
- A count strictly between zero and the width preserves the prefix and fills the suffix.
- Count equal to or greater than the width performs no fill.
- A negative count begins before context offset 48 and can overwrite context fields or aliased descriptor storage.
- Width zero still reaches the callback; a negative count can produce writes even at that width.

#### Post-fill callback lookup

Only after all padding writes finish does the function:

1. Reread the descriptor address from context offset 0.
2. Read the callback address at offset 24 of that newly observed descriptor.
3. Invoke that target.

The earlier descriptor address and any pre-fill callback address are not cached for this invocation. The late descriptor address can differ because a negative-count fill overwrote context offset 0. Even if the descriptor address is unchanged, aliased descriptor storage can have had its callback field overwritten by the fill.

The callback receives five arguments, in this order:

| Position | Argument |
|---|---|
| 1 | Original context address |
| 2 | Destination address |
| 3 | Internal-block address at context offset 48 |
| 4 | Width captured before the fill |
| 5 | Mode captured at function entry |

Thus, target selection uses post-fill memory, while width and mode remain captured values. The width is not reread from the late-selected descriptor for the callback argument.

If the callback returns nonzero, the function writes the captured width to the result-length word. If it returns zero, this branch performs no direct result-length write. The callback result is returned unchanged in either case.

### Nonzero mode: padding disabled

When mask 0x100 is set:

- A nonzero buffered count invokes F-4fc89ec41a6d with **(6, 127, 138, 0, 0)**, then returns 0 if the dependency returns normally. There is no direct result-length write.
- A zero buffered count causes a zero result-length write and return 1.

Neither case invokes the callback. The width-one exception and unsigned upper-bound check precede this processing.

### Zero mode: initial write and branch selection

The function writes zero to the result-length word **before** reading the descriptor address, descriptor width, or flags.

If that word aliases context or descriptor storage, subsequent reads observe storage after this write. The mode decision has already been made and is not revisited.

The function then reads the descriptor width and checks flag mask 0x100.

#### Padding disabled

A zero buffered count returns 1 without directly writing the destination.

A nonzero count invokes F-4fc89ec41a6d with **(6, 101, 138, 0, 0)** and returns 0 if it returns normally.

No width upper-bound check is performed on this path.

#### Padding enabled

The width is compared with 1 using its signed 32-bit interpretation.

A signed width at most 1 returns 1 without inspecting the buffered count or retained-block availability and without copying data. This includes widths zero and one, and all unsigned widths whose highest bit is set.

For a signed width greater than 1:

- The buffered count must be zero.
- Only if that count is zero is the availability indicator read.
- The availability indicator must be nonzero; it need not equal 1.

Failure of either state condition invokes F-4fc89ec41a6d with **(6, 101, 109, 0, 0)** and returns 0 if it returns normally.

Only after those state checks does an unsigned width greater than 32 reach the non-returning dependency. A positive signed width above 32 therefore takes the recoverable state-error path instead if the earlier state checks fail.

### Retained-block validation

On reaching validation, the initially captured width is between 2 and 32 inclusive.

The function reads the unsigned byte at context offset **108 + captured width − 1**. That byte proposes the padding count.

A proposed count greater than the captured width fails validation. Otherwise:

- Count zero is accepted immediately, with no suffix-comparison reads.
- A positive count requires that many trailing bytes to equal the proposed count.
- Comparison starts by reading the final byte again, then proceeds backward.
- The first mismatch stops validation.

Validation failure invokes F-4fc89ec41a6d with **(6, 101, 100, 0, 0)** and returns 0 if it returns normally. No direct destination copy precedes this error.

Acceptance of zero is established behavior, not a claim of conformance to an external padding standard.

### Successful retained output

After successful validation, the function rereads the descriptor address from context offset 0 and reads its width field again. It subtracts the accepted padding count using 32-bit arithmetic.

The resulting 32-bit value has two uses:

- Its signed interpretation controls the forward bytewise copy from context offset 108.
- Its complete 32-bit value is subsequently written to the result-length word.

A positive signed result causes that many bytes to be copied, in increasing address order. A zero or negative signed result causes no copy. Destination writes precede the final result-length write, then the function returns 1.

Under stable, disjoint storage, output length is the original width minus the accepted padding count. If the second width read differs, subtraction can wrap modulo 2³², and the reported unsigned length can differ substantially from the number of bytes copied.

## Side effects

### Ordered direct effects

| Path | Direct effect order |
|---|---|
| Nonzero mode, padding enabled | Padding writes; descriptor-address reread; callback-address read; callback invocation; result-length write only for a nonzero callback result |
| Nonzero mode, immediate success | Zero result-length write; return |
| Nonzero mode, count error | Error dependency invocation; return if it returns |
| Zero mode, all paths | Initial zero result-length write before subsequent descriptor and flag reads |
| Zero mode, successful retained output | Initial zero write; validation reads; descriptor/width reread; forward destination writes; final length write |

There is no explicit field-reset operation for the count, availability indicator, mode, or flags. Nevertheless, negative-count padding writes, aliases, and dependencies can modify these fields.

No direct erasure of either internal byte region occurs after use.

### Aliasing and late target selection

No disjointness checks protect context, descriptor, result-length storage, or destination.

The fill’s dependence on captured width and count does not protect the later callback lookup. Overwriting context offset 0 can redirect the descriptor lookup. Overwriting an aliased descriptor’s offset 24 can redirect the callback without changing the descriptor address. Both changes take effect before invocation.

The retained copy is forward bytewise copying, not general overlap-safe movement. A destination beginning within later source bytes can overwrite bytes before they are read.

The initial zero-mode result-length write can change fields needed by later reads. The final length write can overwrite destination or context storage if aliased.

### Ownership and failure

The visible body contains no explicit allocation or release. No ownership-transfer, retention, or release guarantee follows for any dependency.

Recoverable errors do not roll back prior writes. Callback failure leaves prior padding writes in place, and callback effects are not undone.

A zero-mode error occurs after the initial result-length zero write, but the error dependency may subsequently alter that location. Likewise, a failed callback may modify result-length storage even though this function does not directly write it on callback failure.

## Acceptance examples

These are conditional static examples, not executed tests. Unless an example specifies otherwise, assume valid disjoint storage, stable state, and dependencies without unrelated mutations.

1. **Ordinary fill and success.** Nonzero mode, width 16, count 5, and padding enabled produce eleven bytes of value 11 at internal positions 5–15. After filling, the function rereads the descriptor and callback target. A callback result of 1 produces result length 16 and return 1.

2. **Unnormalized callback result.** Under the same conditions, callback result −7 produces result length 16 and function result −7.

3. **Callback failure.** A zero callback result produces return zero and no direct result-length write. Padding writes have already occurred.

4. **Width-one exception.** Nonzero mode and width 1 produce result length zero and return 1 even with a nonzero count and padding disabled. No callback lookup occurs.

5. **Descriptor pointer overwritten by a negative count.** With nonzero mode, width 16, count −48, and padding enabled, the fill writes value 64 across context offsets 0–63. The descriptor-address word becomes 0x40404040. If that address denotes a valid descriptor with a valid callback at offset 24, that callback is selected. It still receives width 16 and the original mode, not the overwritten mode word. If the replacement address is invalid, no recoverable outcome is established.

6. **Callback field overwritten through descriptor aliasing.** Let the descriptor begin at context offset 24, with width 8 at context offset 28. With count zero and padding enabled, the fill writes eight bytes of value 8 at context offsets 48–55. This overwrites the descriptor’s callback field with 0x08080808. If callable, that post-fill address is invoked instead of the prior target.

7. **Valid suffix.** Zero mode, width 8, zero count, nonzero availability, and a retained suffix of three bytes equal to 3 produce five copied bytes, result length 5, and return 1.

8. **Zero padding count.** With the same state and final retained byte zero, all eight bytes are copied, including the final zero. Result length is 8.

9. **Invalid suffix.** With width 8 and final byte 3, a mismatch in the preceding two suffix bytes invokes **(6, 101, 100, 0, 0)**. No direct destination copy occurs. The initial result-length zero write has occurred.

10. **Full-block padding.** Eight retained bytes equal to 8 validate successfully, produce no destination writes, and report zero length.

11. **State error before width rejection.** Zero mode, padding enabled, width 64, and nonzero buffered count invoke **(6, 101, 109, 0, 0)** rather than the non-returning width dependency.

12. **Signed-width bypass.** Zero mode, padding enabled, and width 0x80000000 return 1 after the initial length-zero write, without retained-block processing.

13. **Changed width after validation.** If width 8 is used to validate a padding count of 3, but the later descriptor-width read yields 2, subtraction produces 0xFFFFFFFF. Its signed interpretation suppresses copying, while the result-length word receives 0xFFFFFFFF and the function returns 1.
