# F-abe00673b80c

## Purpose

F-abe00673b80c fills two destination regions with four-byte values obtained from a 16-element source sequence. The first region uses the source sequence in forward order across 16 rows; the second uses it in reverse order. Each row contains 148 selected destination elements within a stride of 180 elements.

An externally stored displacement positions the second region relative to the first. The regions may overlap. Source storage may also overlap destination storage, so the operation is not necessarily equivalent to copying an unchanged source pattern.

The mode input distinguishes values 2 and 3 from other values, but both alternatives specify the same memory accesses and transfers. No mode value visibly disables the operation.

**Inferred intent:** the opposing source orders suggest construction of two patterned bands. No graphical meaning, value encoding, or application purpose is established.

## Behavior

### Initial state capture

Before any destination write, the function obtains its addressing information in this order:

1. The external displacement.
2. The source address from the first object.
3. The destination address from the third object.

These values are retained throughout the invocation. There is no subsequent refresh of the displacement or either address field.

Consequently, a destination write that later overwrites one of these storage locations changes that storage but not the already captured addressing information. This protection does not extend to source contents, which remain subject to repeated reads.

The three initial reads are not established as an atomic or coherent snapshot in the presence of concurrent modification.

### Mode behavior

Modes 2 and 3 select one alternative; every other represented mode selects the other. Both alternatives have the same:

- Source-element selection.
- Destination layout.
- Row and position traversal.
- Four-byte transfer widths.
- Source-read and destination-write ordering.
- Normal completion behavior.

There is no visible invalid-mode error or early return before the fill. This equivalence concerns the specified data accesses, not execution timing or instruction identity.

### Pattern and observable access order

Rows are processed from the first through the sixteenth. Within each row, selected positions are processed in increasing order, beginning at position 16 and ending at position 163.

The first region uses one source element per row, beginning with source element 0 and ending with source element 15. The displaced region uses the opposite source element for the same row: element 15 for the first row, element 14 for the second, and finally element 0 for the sixteenth.

For each selected destination position, the relevant source read and write occur in this order:

1. Read the forward-selected source element.
2. Write that value to the first region.
3. Read the reverse-selected source element.
4. Write that value to the displaced region.

The second transfer uses the same logical row and position as the first, with the external displacement applied. It is not shifted to the next selected position.

The first destination write therefore precedes the reverse-selected source read. If that write changes the storage supplying the reverse-selected value, the second transfer can observe the changed value immediately.

Neither source element is visibly cached across positions. With stable source memory, a row repeats the same values. With overlapping or externally modified source memory, successive reads may obtain different values.

### Overlap and final contents

For ordinary memory without external interference, the latest write to a shared destination location determines its final value. Overlap may occur between transfers for the same selected position or between transfers belonging to different positions or rows.

Zero displacement makes both writes at each selected position target the same location. With stable, disjoint source storage, the reverse-selected value remains there because it is written second. Both writes are still part of the specified access sequence.

Source overlap introduces additional effects. A destination write can alter:

- The reverse-selected value read immediately afterward.
- Source values read at later positions in the same row.
- Source values used by later rows.

Accordingly, “forward pattern” and “reverse pattern” describe source selection, not an unconditional guarantee that destination contents reproduce the source’s initial values.

## Acceptance examples

These examples are conditional deductions from static evidence, not runtime observations. Unless stated otherwise, they assume ordinary memory, valid alignment and addressing, non-overflowing arithmetic, stable source contents, source storage disjoint from destination storage, and no external interference.

### Coincident regions

With zero displacement, each selected destination location receives the forward-selected value and then the reverse-selected value.

The first row finishes with source element 15, the second with source element 14, and the sixteenth with source element 0. An implementation that omits the first write would not preserve the specified access behavior, even though some final-content comparisons could miss the difference.

### Immediate source-overlap effect

For this example only, place the source address four bytes after the destination address, use zero displacement, and give source elements 0 and 15 different initial values.

The first selected destination location begins 64 bytes after the destination address. It is also the location of source element 15.

The first transfer writes source element 0 into that location. The following reverse-selected read therefore obtains the newly written value, not the initial value of source element 15. The second transfer writes that newly observed value to the same destination location.

Taking an initial snapshot of all source values would produce a different result and would not satisfy this case.

### Negative displacement

With a displacement of −16 elements, assuming the signed interpretation and resulting arithmetic are valid, the displaced first row selects destination element offsets 0 through 147. The first region selects offsets 16 through 163.

The displaced region therefore writes the nominal prefix at offsets 0 through 15. Within the shared interval from 16 through 147, displaced writes occur later than the corresponding first-region writes. With stable source storage, those shared locations finish with source element 15.

This example does not establish permission for every negative displacement or define wrapping-address behavior.

### Addressing storage overwritten

If a destination write overwrites the external scalar or either address field after the initial reads, later accesses continue using the captured displacement and addresses.

If the same write also changes source storage, later source reads still observe the contents present when those reads occur. Captured addresses do not imply captured data.

### Unselected storage

A location outside the union of both calculated write regions receives no explicit write from this function.

Being outside the first region alone is insufficient. In particular, row margins may be selected by the displaced region.
