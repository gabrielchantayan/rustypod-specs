# F-56fd8d6069bf

## Purpose

F-56fd8d6069bf returns one of two stored 32-bit values from a caller-supplied memory region. Bit 0 of a selector byte determines which value is returned.

The established behavior is selection and retrieval of raw bits. The available evidence does not establish what either stored value represents, whether the values are related, or why the selector chooses between them.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

The function accepts one argument used as the base address of a memory region. It does not receive a length, a separate selector, an output buffer, or an error-reporting parameter.

The relevant layout is:

| Offset from base | Access width | Role |
|---|---:|---|
| `0x2EC` | 32 bits, four bytes | Value selected when selector bit 0 is set |
| `0x5E4` | 32 bits, four bytes | Value selected when selector bit 0 is clear |
| `0x5F8` | 8 bits, one byte | Selector; only bit 0 affects the choice |

Offsets are byte offsets. The two candidate values are separated by `0x2F8` bytes. Neither candidate overlaps the selector byte.

The input is represented as a 32-bit integer-like argument in the supplied static representation and is used to form memory addresses. That representation does not establish a public pointer type, an ownership-bearing handle type, or a portable calling convention.

### Output

The function returns exactly one 32-bit value:

- Selector bit 0 clear: the value at base plus `0x5E4`.
- Selector bit 0 set: the value at base plus `0x2EC`.

The result preserves the selected 32-bit bit pattern. No evidence assigns it signed-integer, unsigned-integer, floating-point, pointer, or status-code semantics. There is no visible result conversion, masking, or arithmetic.

All 32-bit patterns are returned by the same mechanism. In particular, zero and values with their highest bit set do not trigger separate handling.

## Behavior

### Selection

The function first reads the byte at base plus `0x5F8` and tests its least significant bit.

Only that bit determines the selected offset. The other seven bits have no effect on the branch:

| Selector bit 0 | Selected offset |
|---|---|
| `0` | `0x5E4` |
| `1` | `0x2EC` |

This is a bit test, not a test of whether the entire selector byte is nonzero. For example, selector byte `0x02` chooses `0x5E4`, while selector byte `0x03` chooses `0x2EC`.

### Retrieval and return

After evaluating the selector, the function reads one 32-bit value at the chosen offset and returns that value.

The visible access order is:

1. Read the selector byte.
2. Read the selected four-byte value.
3. Return the selected value’s bit pattern.

There is no visible read of the other candidate value, no comparison between candidates, and no second selector read. The function does not validate the selected value before returning it.

The four-byte read is described here as a 32-bit value access, not as four independently ordered byte reads. The available evidence does not establish the machine instructions used to implement that access.

### Widths and arithmetic

The selector access is eight bits wide. The candidate access and return value are each 32 bits wide. Testing the selector does not sign-extend or otherwise transform the returned candidate.

The base participates in fixed-offset address formation. The function contains no visible address-overflow handling. This contract does not define wrapped addresses as valid inputs or infer a portable overflow rule from the supplied representation.

The byte order used to interpret four bytes as a 32-bit value is target-dependent and is not established by the supplied evidence. Examples below therefore express candidate contents as already-interpreted 32-bit values.
