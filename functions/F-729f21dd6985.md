# F-729f21dd6985

## Purpose

F-729f21dd6985 coordinates a preparation operation, a primary operation, an optional follow-up operation, and a conditional transfer of a 16-bit field between two addressable objects.

Its directly established behavior is:

- Obtain a 32-bit value from F-fdd8589eca2d and pass it, the first input, and a literal zero to F-3e5212464798.
- Invoke F-a3c410f12096 with both inputs and retain its 32-bit result.
- Invoke F-5c5958cfd5fe if the second input is nonzero.
- Under the field conditions described below, obtain another address from F-fdd8589eca2d and write a freshly read 16-bit value from the first input’s object to offset `0x80` of that address.
- Return the retained result of F-a3c410f12096.

A possible intent is to propagate an attribute from an input object to a current or shared object only when an existing field is zero. That interpretation is **inferred**, not established. In particular, the object whose field is checked need not be the object subsequently written.

## Behavior

4. The 32-bit result of F-a3c410f12096 is retained for the eventual return.

The result of F-3e5212464798 is not used locally. This does not make that call optional: its execution and possible effects precede the primary operation.

The initial result from F-fdd8589eca2d is not directly dereferenced by this function. Its meaning for F-3e5212464798 is unknown.

### Optional follow-up

- If the second input is nonzero, F-5c5958cfd5fe is invoked with no explicit arguments.
- If the second input is zero, that call is omitted.

This decision depends only on the original second input, not on the primary result or a field value.

When the follow-up call occurs, it precedes every direct field read described below. Its effects may therefore affect the values subsequently observed.

### First source-field observation

The function next reads the 16-bit field at offset `0xE6` from the first input’s address and compares it with zero.

This read occurs even when the second input is zero. A zero second input suppresses the optional follow-up and later destination processing; it does not suppress this source-field read.

If the observed source field is zero, no additional F-fdd8589eca2d invocation is made, and no direct field write occurs.

If the observed source field is nonzero but the second input is zero, no additional F-fdd8589eca2d invocation or direct field write occurs.

### Destination-field check

Only when both the first source-field observation is nonzero and the second input is nonzero does the function invoke F-fdd8589eca2d again.

The return from this invocation is used as an address. The function reads the 16-bit field at offset `0x80` from that address and compares it with zero.

- A nonzero destination-field observation prevents the direct write.
- A zero destination-field observation enables the final transfer sequence.

The field tested here belongs to the object returned by this particular invocation. There is no established guarantee that this object matches the one returned by the initial invocation or by any later invocation.

### Final transfer

When the destination-field observation is zero, the function invokes F-fdd8589eca2d a third time.

After that invocation returns:

- The source field at the first input address plus `0xE6` is read again.
- That newly read 16-bit value is written to offset `0x80` of the address returned by the third invocation.

The first source-field observation is therefore only a gate. It is not a cached payload.

Consequently:

- A source value that changes after the first observation can change the value written.
- The value ultimately written may be zero, despite the earlier nonzero source-field observation.
- The final target can differ from the object whose field was checked.
- The final target’s field is not independently checked before being overwritten.

After this sequence, or after any branch that omits it, the function returns the retained primary result.
