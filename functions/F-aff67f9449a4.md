# F-aff67f9449a4

## Purpose

F-aff67f9449a4 wraps a delegated numeric conversion with leading-byte classification, optional sign handling, end-position adjustment, and preservation of a shared status value.

The established behavior is narrower than a complete string-to-integer contract. This function does not itself recognize digits, validate a radix, determine overflow, or define conversion failure. Those decisions belong to F-eef3bf576bc2. The wrapper:

- Skips leading nonzero bytes whose classification entry has its low bit set.
- Removes at most one leading plus or minus byte after that scan.
- Clears a retrieved status cell before delegating.
- Changes a delegated “no progress” end position back to the original input address.
- Preserves status value 2, but otherwise restores the status saved before scanning.
- Negates the delegated result for a removed minus sign only when the subsequently observed status is not 2.

The likely intent is a signed conversion wrapper around a lower-level converter. That interpretation does not establish the conversion grammar, status-code meanings, or valid values of the third argument.

## Interface

### Inputs

**Input byte address**

The first argument identifies the beginning of an input byte sequence. Bytes are read as unsigned 8-bit values.

The wrapper requires readable memory for every byte visited by its leading scan. That scan stops at either:

- A zero byte; or
- A nonzero byte whose classification entry has bit 0 clear.

Consequently, the wrapper does not necessarily require a zero terminator before it delegates. Any additional readability or termination requirements are imposed by F-eef3bf576bc2.

There is no null-address check.

**Optional end-position destination**

The second argument is either null or an address of a writable 32-bit slot used to communicate an input position. It is passed unchanged to F-eef3bf576bc2.

If nonnull, the wrapper reads the slot after the delegated call and may overwrite it with the original input address. Its existing contents before delegation are not read by the wrapper.

The supplied representation uses a 32-bit slot to hold and compare an input address. Porting this behavior to a different pointer width requires an explicit representation decision; simply widening some values is not established behavior.

**Opaque conversion argument**

The third argument is a 32-bit value forwarded unchanged to F-eef3bf576bc2. The wrapper neither validates nor interprets it.

Its purpose may be related to numeric conversion configuration, but that is not established here.

### Output

The function returns the delegated 32-bit integer result, except that it may apply unary negation when a minus sign was removed.

No separate success flag is returned. Observable conversion information may also appear through the end-position destination and the shared status cell.

### Environmental preconditions

Successful execution requires:

- F-4af36158f863 to return an address from which a 32-bit status value can be read and to which a 32-bit value can later be written.
- Each required F-2a4c402ba617 call to return a readable reference containing a table base address.
- Each classification lookup at that base plus the unsigned input-byte value to be readable.
- The addresses used by the wrapper to remain valid until their last access.
- Any additional preconditions of F-eef3bf576bc2 to hold.

There are no explicit checks for invalid dependency results, inaccessible memory, or invalid third-argument values.

## Behavior

### 1. Capture the status location and its entry value

The wrapper first calls F-4af36158f863. It retains the returned status-cell address and reads the 32-bit value stored there.

This saved value is taken before input scanning and before any classification-provider calls. Later status operations use the retained address; the wrapper does not reacquire it.

This distinction matters if dependencies change a global mechanism used to locate status storage. Such changes do not redirect the wrapper’s later accesses to a newly selected cell.

### 2. Scan the leading classified bytes

The wrapper begins at the original input address and reads one byte at a time.

For each byte:

- A zero byte ends the scan without a classification-provider call for that byte.
- A nonzero byte causes a call to F-2a4c402ba617.
- The returned reference is dereferenced to obtain a table base.
- The entry at that base plus the byte’s unsigned value is read.
- If the entry’s low bit is set, scanning continues at the next input byte.
- Otherwise, that byte becomes the stopping byte.

Classification is therefore table-driven. The low bit alone controls skipping; other classification bits do not affect this wrapper.

The table base is obtained separately for every nonzero byte examined. The wrapper does not cache one table base for the whole scan. Dependency side effects or changes to the table reference can therefore affect later bytes.

The wrapper’s own status clear has not yet occurred during scanning. Classification dependencies can observe or modify state before that clear.

### 3. Choose the delegated input and record a possible minus sign

After scanning stops, the wrapper examines the stopping byte:

- If it is byte value 43, corresponding to plus, delegation begins immediately after that byte. No negative sign is recorded.
- If it is byte value 45, corresponding to minus, delegation begins immediately after that byte. A negative sign is recorded.
- Otherwise, delegation begins at the stopping byte itself.

This applies equally when the stopping byte is zero: delegation begins at the zero byte, not one byte beyond it.

Sign recognition happens only after classification has stopped. If a plus or minus byte has classification bit 0 set when examined, it is skipped as part of the leading scan rather than recognized as a sign at that position.

The wrapper removes at most one sign after the scan. It does not itself scan again after that sign. Any further signs, classified bytes, digits, or terminators are left for F-eef3bf576bc2.

### 4. Clear status and invoke conversion

The wrapper writes zero to the retained status cell, then calls F-eef3bf576bc2 with:

1. The selected delegated input address.
2. The original optional end-position destination.
3. The original 32-bit opaque argument.

The delegated integer result is retained.

Nothing in the supplied evidence establishes whether the converter allocates memory, modifies other shared state, changes classification state, or changes the mechanism that provides status storage.

### 5. Normalize a particular end-position result

After the converter returns, the wrapper checks the end-position destination if it is nonnull.

If its stored address equals the delegated input address, the wrapper overwrites it with the original input address.

Otherwise, the wrapper leaves the destination unchanged.

This is an address-equality rule, not an independent determination of whether any digits were converted. It can translate a delegated no-progress indication across both skipped leading bytes and a removed sign. It also applies when the delegated input equals the original input.

The wrapper does not check whether the reported position lies inside the input sequence, whether it advances, or whether it agrees with the returned number.

### 6. Read status, conditionally restore it, and choose the result sign

Only after the end-position adjustment does the wrapper read the retained status cell.

If that observed value is exactly 2:

- The wrapper does not restore the saved entry value.
- A recorded minus sign does not cause negation.
- The delegated integer result is returned unchanged.

If that observed value is anything other than 2:

- The saved entry value is written back to the retained status cell.
- A recorded minus sign causes negation of the delegated result.
- Without a recorded minus sign, the delegated result is returned unchanged.

The sign decision uses the status value read before restoration. For example, if the saved entry value was 2 but the post-conversion observation is zero, the saved 2 is restored and a recorded minus sign still causes negation.

Likewise, a nonzero status other than 2 is not preserved merely because it might represent an error. This wrapper singles out only the exact value 2.

## Side effects

### Ordered wrapper-visible accesses

The established order is:

1. Obtain the status-cell address and read its entry value.
2. Read input bytes and perform the required per-byte classification calls and table reads.
3. Write zero to the retained status cell.
4. Invoke F-eef3bf576bc2.
5. If the end-position destination is nonnull, read it and conditionally write the original input address.
6. Read the retained status cell.
7. Unless that read yields 2, restore its saved entry value.
8. Return the selected integer result.

This order is significant. In particular, the status observed after conversion is read after any end-position rewrite, not immediately when the converter returns.

### Aliasing

The wrapper contains no explicit disjointness checks.

If the end-position destination aliases the retained status cell, its read or rewrite participates in determining the later observed status. A subsequent status restoration can also overwrite the end-position output. The usual interpretation of these as independent outputs is therefore conditional on non-aliasing.

Similarly, if writable output or status storage overlaps input or classification storage, writes can affect subsequent observations wherever the stated ordering permits. The evidence does not establish whether such overlap is valid under the original execution environment’s memory-access rules.

### Ownership

The wrapper performs no explicit allocation, deallocation, or ownership transfer. It passes the input address and optional output destination to F-eef3bf576bc2.

That does not establish that dependencies preserve memory ownership or avoid allocation and release. Their contracts are not supplied.

### Errors

The wrapper has no explicit exceptional return path or invalid-argument recovery.

Status value 2 receives special treatment, but its semantic name is unknown. Other status values produced during conversion are replaced with the saved entry status whenever the final status observation is not 2.

Faults, non-returning dependencies, and invalid memory accesses have no specified recovery behavior here.

## Acceptance examples

These examples are conditional behavioral checks, not reports of executed tests. Unless stated otherwise, input, end-position storage, and status storage are distinct and valid.

1. **Leading classified bytes and a minus sign**

   Suppose the leading space byte has classification bit 0 set, minus has that bit clear, and the input is a space followed by “-12”. Delegation starts at “12”.

   If F-eef3bf576bc2 returns 12, advances the end position, and leaves the retained status cell at zero, this wrapper returns −12, preserves the advanced end position, and restores the entry status.

2. **Exact status value 2 suppresses negation**

   For an input whose recognized sign is minus, suppose the converter returns 12 and the status observed after end-position handling is 2.

   The wrapper returns 12 unchanged and does not restore the entry status.

3. **A different nonzero status is discarded**

   Suppose the entry status is 9, a minus sign is recognized, the converter returns 12, and the subsequent status observation is 7.

   The wrapper restores 9 and returns −12. It does not preserve 7.

4. **Saved status 2 does not suppress negation**

   Suppose the entry status is 2, a minus sign is recognized, and the converter leaves status zero while returning 12.

   The wrapper restores 2 and returns −12. Suppression depends on the post-conversion observation, not the saved value.

5. **No progress after a removed prefix**

   Suppose leading bytes and a sign are removed, and the converter writes its supplied input address to the end-position destination.

   The wrapper replaces that address with the original input address. This holds regardless of the converter’s returned integer.

6. **Zero-byte input**

   If the first byte is zero, the wrapper makes no classification-provider call for that byte and delegates at the original input address. Conversion outcome remains dependency-defined.

7. **A sign classified as skippable**

   Suppose plus has classification bit 0 set and the following digit has it clear. For input “+7”, plus is skipped during classification rather than handled by the sign-removal branch. Delegation begins at “7”.

8. **Only one sign is removed**

   If minus has classification bit 0 clear, input “--7” causes delegation at the second minus and records one negative sign. Whether the second minus is accepted is entirely delegated.

9. **Null end-position destination**

   With a null second argument, the wrapper passes null to the converter and performs no end-position read or correction. Status handling and conditional negation still occur.

10. **Negation boundary**

    For any delegated result whose mathematical negation fits the signed 32-bit range, a recognized minus with observed status other than 2 produces that negation. The most-negative signed 32-bit result requires the qualification in the following section.
