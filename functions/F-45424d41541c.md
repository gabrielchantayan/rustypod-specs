# F-45424d41541c

## Purpose

The constants seven, thirty-four, and thirty-five suggest a seven-position layout with fixed spacing. That interpretation is inferred intent, not an established interface requirement. The evidence does not identify the record’s semantic type, coordinate system, units, or valid selector range.

The established behavior is the sequence of calls, memory accesses, arithmetic, and final record updates described below. Dependency names are opaque; their effects are not inferred from their use.

## Behavior

That result is passed, together with the integer constant seven, to F-870c4fcf7295. The returned integer is retained as the **scale value**.

The same address at object offset `0x80` is then passed to F-19fde5f06ccc a second time. This second result is retained as the **extent value**.

The second call is observable and is not replaceable with reuse of the first result. Nothing establishes that F-19fde5f06ccc is pure, that the addressed record remains unchanged, or that the two results are equal.

Next, the function reads the address stored at object offset `0xec`, reads the four-byte value at offset `0xe8` from that addressed object, and passes the value to F-0a9a547c6b8c. The returned integer is the initial **adjustment value**.

These calls occur in this order:

1. F-19fde5f06ccc.
2. F-870c4fcf7295 with the first result and seven.
3. F-19fde5f06ccc again.
4. F-0a9a547c6b8c with the indirectly loaded value.

The later object reads occur after the preceding calls. There is no basis for treating the relevant object fields as a snapshot taken on entry.

### Conditional continuation

After F-0a9a547c6b8c returns, the function reads object offset `0x100`. It subtracts that field from the initial adjustment value and compares the result with seven.

If the difference equals seven, the initial adjustment value is retained.

If the difference does not equal seven, the function calls F-d7be9cfb4000 with no explicit arguments. If that dependency returns, the function replaces the adjustment value with the value exposed through the secondary result register identified in the supplied representation.

This is not an established ordinary return-value contract for F-d7be9cfb4000. Neither its purpose nor the meaning of that register value is supplied. It might terminate execution, transfer control elsewhere, or return; the available evidence does not resolve those possibilities. Any description of later behavior on this branch is conditional on it returning with a usable value.

The branch is controlled by the difference, not by whether the initial adjustment value itself equals seven.

### Derived arguments

The function adds the selector to the chosen adjustment value, then subtracts one. Call this result the **position value**.

It passes the position value and seven to F-870c4fcf7295. The returned integer is the **group value**.

The two calls to F-870c4fcf7295 have distinct inputs and roles. The evidence does not establish that this dependency implements division, quotient extraction, rounding, or any other specific mathematical operation.

For values whose intermediate arithmetic is representable, the two arguments later supplied to F-d156b0b83eb3 are:

- **First derived argument:** the scale value multiplied by the quantity “position value minus seven times the group value,” plus half of “extent value minus seven times the scale value,” plus two.

The halving operation is an explicit signed integer division by two. Under the represented signed-integer semantics, it truncates toward zero. It is not floating-point division and does not round negative odd values downward.

The first derived argument must not be characterized as a remainder-based calculation unless an independent contract for F-870c4fcf7295 establishes the necessary quotient behavior.

### Record transfer and dependency invocation

After obtaining the group value, the function reads the object’s record words in this order:

1. Offset `0x84`.
2. Offset `0x88`.
3. Offset `0x8c`.
4. Offset `0x80`.

The first three values are retained before the destination writes begin. The value from offset `0x80` is then written to destination word 0, followed by the retained values written to words 1, 2, and 3 in that order.

Thus, the transfer is neither an atomic snapshot nor an unspecified bulk copy. Its read/write ordering matters if storage overlaps or has externally observable access behavior.

After those four writes, the function calls F-d156b0b83eb3 with:

- The destination address.
- The first derived argument.
- The second derived argument.

The object field at offset `0xf8` is read after the four destination writes, while preparing this call. Consequently, destination overlap with that field can change the second derived argument.

F-d156b0b83eb3 receives the actual destination, not a private temporary record. Its return value is not used. Its effects on destination storage, other memory, or global state are unknown.

### Final destination updates

If F-d156b0b83eb3 returns, the function performs two further updates:

1. Read the current destination word 1, add the retained scale value and one, and write the result to destination word 3.
2. Read the current destination word 0, add thirty-five, and write the result to destination word 2.

These reads occur after F-d156b0b83eb3. They therefore use whatever values that dependency leaves in destination words 1 and 0, not necessarily the values copied from the object.

The write to word 3 precedes the read of word 0 and the write to word 2. The function then returns.
