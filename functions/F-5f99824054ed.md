# F-5f99824054ed

## Purpose

F-5f99824054ed modifies links and scores among records in a selected collection. Its observable work comprises three ordered passes:

1. Select primary partners using direction, position, interval overlap, and existing scores.
2. Reconcile certain nested reciprocal pairs, either clearing a pair or converting links associated with another pair into secondary links.
3. Account for remaining primary links and classify nonreciprocal relationships.

The function returns no value. Its results are mutations of collection records and, on some paths, records reached through existing pointers.

“Position,” “overlap,” “primary link,” and “secondary link” describe the observed operations. Their application-level meanings are not established. The function does not establish a general guarantee of symmetry, uniqueness, optimality, or acyclicity.

## Interface

### Inputs and result

The function accepts two 32-bit inputs:

- **Context address:** identifies storage containing collection descriptors and other fields.
- **Selector:** participates in descriptor addressing and chooses one of two dependency arguments.

There is no explicit return value, status code, or error output.

The selected descriptor base is the context address plus 28 times the selector. The selector is not range-checked. Every nonzero selector selects the same dependency-argument field, although different selector values produce different descriptor addresses.

### Preconditions and arithmetic

Every accessed address must identify readable or writable storage as required by its use. This includes linked targets outside the selected collection. There is no membership, alignment, null-context, or general pointer-validity check.

Ordinary finite traversal requires a coherent, nonwrapping address range. Zero count produces an empty range. Negative counts and overflowing address calculations are not rejected; unsigned endpoint comparisons may then produce an empty, invalid, or nonterminating traversal.

Signed 8-bit and 16-bit fields are sign-extended. Position differences and computed overlaps lie between −65,535 and 65,535. An eligible nonnegative distance multiplied by eight therefore fits in signed 32 bits.

Other products can exceed signed 32-bit range, notably the auxiliary value multiplied by eight, stored distance multiplied by seven or nine, and reconciliation scores multiplied by three or four. Portable behavior for these overflowing signed operations is not established.

The final classification differs: its target-distance multiplication uses unsigned 32-bit arithmetic. Its low 32 bits are interpreted as a signed comparison operand, with explicit subtraction-overflow handling.

## Behavior

### 1. Capture traversal parameters and obtain thresholds

Before calling the dependency, the function reads, in order:

1. First record address.
2. Required direction.
3. Count, from which it calculates the endpoint.
4. Auxiliary pointer and the signed value at auxiliary offset +32.
5. The context field selected as the dependency argument.

It forms the overlap threshold by multiplying the auxiliary value by eight, then applying a sign-dependent bias and arithmetic right shift equivalent to signed division by 2048 with truncation toward zero, provided the multiplication has a defined signed result.

Without multiplication overflow, the threshold equals the auxiliary value divided by 256, truncated toward zero. This simplification is not established for arbitrary 32-bit auxiliary values.

The function calls **F-73d099a86adb** exactly once, passing:

- First argument: 192.
- Second argument: the selected 32-bit context field.

The returned 32-bit value is subsequently used as a signed distance threshold.

The collection bounds, direction, and overlap threshold are captured before this call. The dependency is not known to preserve context storage, records, globals, or pointed-to objects. Subsequent record reads observe whatever contents are present after it returns.

### 2. Select primary links

The outer traversal visits records in increasing address order.

A record initiates a candidate scan only when:

- Its fields at +36 and +40 differ.
- Its direction equals the captured required direction.

The discriminator reads precede the direction check. No eligibility read uses +24. A record that does not initiate a search may still be selected as a candidate and modified.

Each initiating record scans the entire collection in increasing address order. A candidate proceeds only if:

- It is not the initiating record.
- The two signed directions sum to zero.
- Candidate position minus initiating position is nonnegative.

For a qualifying pair:

- **Distance** is candidate position minus initiating position.
- **Overlap** is the smaller upper endpoint minus the larger lower endpoint.

There is no interval-validity check and no clamp to zero. Negative overlap can qualify when the overlap threshold is sufficiently negative.

If overlap is at least the captured overlap threshold, each endpoint independently evaluates the proposed partner against its own stored scores. Acceptance requires:

- Eight times the new distance is strictly less than nine times the stored distance.
- Either eight times the new distance is strictly less than seven times the stored distance, or the stored overlap is strictly less than the new overlap.

On acceptance, writes occur in this order:

1. Primary link becomes the other endpoint’s address.
2. Stored distance becomes the new distance.
3. Stored overlap becomes the new overlap.

The initiating endpoint is evaluated and possibly written before the candidate endpoint is evaluated. Acceptance by one endpoint does not require acceptance by the other.

All updates are immediately visible to later scans. No initial-score snapshot is maintained. Zero stored distance has no special “uninitialized” treatment: even a zero-distance proposal fails the first strict comparison against a zero stored distance.

### 3. Reconcile certain reciprocal pairs

A fresh traversal starts at the captured first record.

A current record proceeds only if its primary link is nonnull and the linked record’s primary link points back to it. The linked record is its **partner**.

Further processing requires:

- Current position is strictly less than partner position.
- Current stored distance is strictly less than the dependency threshold.

For distinct-position reciprocal pairs, only the lower-position endpoint can initiate this processing.

The function scans the complete collection for a candidate record satisfying all of these conditions:

- Candidate position is no greater than current position.
- Candidate is not current.
- Candidate has a nonnull primary link, and that link is reciprocal.
- Current partner position is no greater than candidate partner position.
- The two pairs do not have identical endpoint positions.
- Current stored distance is strictly less than candidate stored distance.
- Candidate stored distance is strictly less than four times current stored distance.

No direction or interval-overlap eligibility test is repeated.

If current stored overlap is strictly less than three times candidate stored overlap, the function:

1. Clears the current partner’s primary link.
2. Clears the current record’s primary link.
3. Stops the candidate scan for this current record.

Scores, secondary links, and counters are not reset.

Otherwise, the function traverses the whole collection and performs the following conversions:

- A record whose primary link points to the candidate receives the current partner as its secondary link, then has its primary link cleared.
- Otherwise, a record whose primary link points to the candidate partner receives the current record as its secondary link, then has its primary link cleared.

The first matching condition takes precedence. Every matching traversed record is affected, not merely the candidate pair’s endpoints. Existing secondary links are overwritten.

Candidate scanning continues after this conversion. The function does not restart or revalidate the current pair before considering later candidates. It retains the current partner address obtained for this outer iteration, while later score and relationship tests read the then-current storage.

### 4. Account for and classify remaining primary links

A final traversal begins at the captured first record.

For each record, the function reads its primary link. A null link causes no counter or secondary-link operation.

For a nonnull target, the function:

1. Reads and increments the target’s counter at +24.
2. Reads the target’s primary link.
3. Checks whether that link points back to the current record.

The counter is not reset before incrementing. There is no saturation or overflow check.

If the relationship is reciprocal, processing of this record ends.

Otherwise, the function clears the current primary link before reading the target’s distance score for classification. It then decides whether to discard the relationship or preserve it as a secondary link.

Define the **scaled target distance** as the low 32 bits of four times the target-distance bit pattern, interpreted as a signed 32-bit value.

The relationship is discarded exactly when both hold:

- Target distance, interpreted as signed 32 bits, is at least the dependency threshold.
- Current stored distance is at least the scaled target distance in a signed comparison.

On discard, the target counter is read again and decremented by one. No secondary-link write occurs on this path.

In every other case, the increment remains and the current secondary link becomes the target’s **then-current primary link**. The target’s primary link is read again for this assignment; the function does not simply store the target’s address.

Consequently, the secondary value can be null, identify a third record, or reflect earlier mutations in this invocation.

For target distances whose multiplication by four fits in signed 32 bits, the scaled value is the ordinary mathematical product. At other values, the explicit unsigned multiplication matters. The signed comparisons account for subtraction overflow; testing only the sign of a wrapped subtraction would not preserve the behavior.

## Side effects

Direct writes affect:

- Primary links at +16.
- Secondary links at +20.
- Counters at +24.
- Distance scores at +28.
- Overlap scores at +32.

The function does not directly write the eligibility discriminators at +36 and +40.

Counter updates and reciprocal-pair clearing can write through pointers to records outside the collection. Transfer scans, by contrast, modify traversed records whose primary links match the selected addresses.

Pass order, traversal order, and write order are observable. Mutations are available to subsequent operations; independent or simultaneous per-record processing would not generally be equivalent.

There is no directly observed allocation, release, whole-record copy, I/O, or ownership transfer. Stored pointers do not establish ownership. Dependency behavior may introduce additional effects.

No error recovery is present. Invalid storage or malformed relationships are not converted into a returned failure status.

Fields retain their previous contents unless a described write occurs. In particular:

- Clearing a primary link does not generally clear its secondary link.
- Clearing links does not reset scores.
- Counters accumulate rather than being recomputed from zero.
- Secondary links are not globally initialized.

## Acceptance examples

These are conditional static expectations, not runtime results. Unless specified otherwise, storage is valid and nonoverlapping, arithmetic does not overflow, and the dependency returns normally without altering relevant storage. Examples describing a particular pass assume the stated conditions hold when that pass reaches the record.

1. **Empty collection.** A zero count still permits all initial context and auxiliary reads and the single dependency call. No record pass accesses a record.

2. **Eligibility uses +36 and +40, not +24.** Equal values at +36 and +40 prevent a record from initiating a search, regardless of its counter. Different discriminator values permit the direction check. Changing only +24 does not change this initial eligibility decision.

3. **Independent endpoint acceptance.** An initiating record and candidate have directions +1 and −1, positions 10 and 20, and overlap 20. The overlap threshold is 10. An endpoint with stored distance 100 accepts distance 10; an endpoint with stored distance zero rejects it. The first pass can therefore produce a nonreciprocal link.

4. **Zero direction and equal positions.** Distinct records with direction zero satisfy the direction-sum condition. Equal positions produce distance zero. Neither property independently excludes the pair; the existing scores still determine acceptance.

5. **Negative overlap.** Computed overlap −2 passes threshold −3. Requiring nonnegative overlap would change behavior.

6. **Clear a nested pair.** At reconciliation, the current reciprocal pair has positions 10 and 20, stored distance 10, and overlap 5. Another reciprocal pair has positions 0 and 30, stored distance 30, and overlap 2. With dependency threshold 100, the qualifying comparisons hold. Because 5 is less than three times 2, the current partner’s primary link is cleared before the current record’s primary link.

7. **Transfer at equality.** Under the preceding conditions, change current overlap to 6. The clearing comparison is false because it is strict. Records pointing to the candidate receive the current partner as their secondary link; records pointing to the candidate partner receive the current record. Each affected primary link is then cleared.

8. **Discard a nonreciprocal link.** At final classification, threshold is 10, target distance is 12, and current distance is 48. The target counter is incremented, the current primary link is cleared, and the target counter is decremented. The current secondary link is unchanged.

9. **Retain a nonreciprocal relationship.** Change current distance in the preceding example to 47. The increment remains, and the current secondary link receives the target’s current primary link. A target distance below the threshold also selects retention.

10. **Final multiplication wraps before comparison.** At final classification, let target distance be 1,073,741,824, threshold zero, and current distance zero. Four times the target-distance bit pattern has low 32 bits zero. Both signed comparisons therefore hold, selecting discard. An unbounded mathematical multiplication would give a different result.
