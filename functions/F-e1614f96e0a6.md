# F-e1614f96e0a6

## Purpose

F-e1614f96e0a6 transfers a bounded number of bits from a contiguous source byte stream into a destination organized as fixed-width logical rows. Source bits are consumed most-significant-bit first. Destination bytes are also assembled most-significant-bit first.

A row may occupy several destination bytes. Within a row, full bytes are written at consecutive addresses. At a row boundary, the persistent destination address advances by a configured stride rather than by the number of bytes just written. A partial destination byte is zero-padded in its unused low-order positions.

The operation does not merge output with existing destination bytes. It does not persist an unfinished byte, a partially consumed source byte, or progress within an unfinished row. Consequently, separate calls are not generally equivalent to one call over the concatenated input.

**Established behavior:** bounded bit consumption, byte assembly, row-boundary writes, stride-based destination progression, and limited state mutation.

**Inferred intent:** copying a packed bit stream into a strided, row-oriented destination.

**Not established:** any particular image format, ownership protocol, allocation policy, or intended treatment of invalid addresses and arithmetic overflow.

## Interface

### Inputs

The function has three arguments and no return value:

1. **State address:** a pointer to a structure represented by at least five consecutive 32-bit words.
2. **Source address:** the address of the first readable source byte.
3. **Source endpoint:** a 32-bit integer used as an address-like endpoint when calculating available source bits.

The endpoint is not dereferenced. Its role is arithmetic: the function subtracts the source address from it and multiplies the resulting byte distance by eight.

### State layout

The supplied representation establishes these field uses:

| Byte offset | Width | Role |
|---|---:|---|
| 0 | 32 bits | Persistent destination row-base address |
| 4 | 32 bits | Destination row stride |
| 8 | 32 bits | Configured row width, measured in bits |
| 12 | 32 bits | Not accessed |
| 16 | 32 bits | Maximum number of source bits to process |

The destination address is stored as an integer-valued word and used as a byte address. The stride is added to this stored address at each completed row.

The row width and bit limit participate in signed comparisons. Source bytes are read as unsigned 8-bit values. Output stores affect one byte at a time.

This layout describes the recovered 32-bit representation. It does not establish compatibility with a host ABI having wider pointers or a different integer representation. State-word byte order is not specified by the supplied evidence.

### Preconditions for defined, ordinary use

For the straightforward bounded-copy interpretation:

- The state fields that are read must be accessible.
- The endpoint must describe a nonnegative, representable source byte distance.
- Multiplying that distance by eight must remain within the positive signed 32-bit range.
- The source must provide enough readable bytes for the selected number of bits.
- Every destination address reached by byte progression or row-stride progression must be writable.
- Address additions and row-counter decrements must be representable in the recovered execution model.
- A positive row width is required for conventional row semantics.

The function performs no explicit validation of these conditions. It supplies no error result.

Overlap is not rejected. Its effects follow the read/write order described below and can differ from a nonoverlapping copy.

## Behavior

### 1. Select the bit count

The function first computes a candidate bit count from the endpoint-minus-source distance, multiplied by eight.

It then reads the state’s bit limit and compares that limit against the candidate interpreted as a signed 32-bit value. If the limit is smaller, it obtains the limit again and uses that value as the selected count.

For representable, nonnegative inputs, the selected count is the smaller of:

- the number of bits between the source address and endpoint; and
- the state’s bit limit.

The loop executes only while the selected count, interpreted as signed, is positive.

This signed interpretation matters. The implementation is not an unrestricted unsigned-size copy: a count with its high bit set does not cause a correspondingly large positive iteration count.

After selecting the count, the function reads the configured row width and the persistent destination row-base address. These reads occur even when the selected count causes no iterations.

The bit limit is not reduced or otherwise updated.

### 2. Initialize invocation-local packing state

Every invocation begins with:

- an empty output-byte accumulator;
- the destination bit position at the most significant bit;
- the row countdown initialized from the configured row width;
- a local destination address initialized from the persistent row-base address.

No existing destination byte is read to initialize the accumulator.

The initial source position is always the most significant bit of the first source byte. There is no input bit-offset parameter.

### 3. Read source bytes and consume bits

For a positive selected count, the first iteration reads one source byte and advances the local source address by one byte. Subsequent source-byte reads occur after each group of eight consumed bits.

For a selected count of \(N>0\), the function performs exactly:

\[
\left\lceil \frac{N}{8} \right\rceil
\]

source-byte reads, absent access faults or interfering memory changes.

Within each loaded source byte, bits are consumed in this order:

1. bit 7;
2. bit 6;
3. continuing through bit 0.

If processing stops partway through a source byte, its unused low-order bits are discarded. No residual source state is saved.

The source stream continues uninterrupted across destination row boundaries. Completing a row does not align the source to the next byte.

### 4. Assemble output and update the row countdown

For each consumed source bit, the function:

- decrements the local row countdown;
- incorporates the source bit at the current output-bit position;
- advances the output-bit position toward the least significant bit.

A source bit of one sets the corresponding accumulator bit. A source bit of zero leaves that accumulator bit zero.

The decision to finish a row is made after decrementing the row countdown. Row completion takes precedence over ordinary full-byte completion.

For a conventional positive row width \(W\), each row therefore receives exactly \(W\) source bits.

### 5. Commit a completed row

When the decremented row countdown is less than one, the function writes the current accumulator byte to the current local destination address.

This write occurs whether the byte is full or partial. If partial, its unused low-order bits are zero.

After the destination-byte write, the function performs the following relevant state accesses in order:

1. Reads the persistent destination row-base address.
2. Reads the configured row width and uses it to reload the row countdown.
3. Resets the output accumulator and output-bit position.
4. Reads the stride and stores the previously read row-base address plus that stride into the persistent row-base field.
5. Evaluates that same old row-base address plus a further stride read to obtain the next local destination address.

For ordinary stable state, the persistent row base and next local destination address therefore both become the old row base plus the stride.

The destination write precedes those field reads. If destination storage aliases state fields, values written by that byte store can affect the subsequent address, width, or stride reads.

The width is reloaded at each row boundary; it is not permanently cached for the whole invocation.

### 6. Commit a full byte within an unfinished row

If the row has not ended but all eight output-bit positions have been used, the function:

- writes the accumulated byte;
- advances the local destination address by one byte;
- clears the accumulator;
- resets the output-bit position to the most significant bit.

This ordinary byte completion does not update the persistent destination row-base field.

Accordingly, bytes within a row are consecutive, while successive row starts are determined by the stride. A row wider than eight bits can write beyond its stored row-base address without advancing that stored address until the row actually completes.

### 7. Finish the invocation

After all selected bits have been consumed, the function writes a final accumulator byte only if it contains bits not already committed by a full-byte or row-boundary write.

The final write zero-fills unused low-order positions. It does not preserve the destination’s previous low-order bits.

There is no extra write when processing ends:

- exactly at a row boundary; or
- immediately after a full-byte write within an unfinished row.

An unfinished row does not advance the persistent row base. Its remaining bit count and byte position are not saved.

### Nonpositive counts and unusual widths

If the selected signed count is zero or negative, there are no source-byte reads, destination-byte writes, or persistent row-base updates. The state reads used for setup still occur.

For a configured width of zero or a negative value whose decrement is representable, each consumed bit immediately satisfies the row-completion condition. Each such bit is written as a separate byte, either `00` or `80`, followed by a row-base stride update.

The most negative signed width requires a decrement outside the signed 32-bit range. Its behavior is not assigned a portable interpretation here.

## Side effects

### Memory reads

Observable reads include:

- the bit-limit field during count selection, potentially twice;
- the initial configured width and persistent row base;
- source bytes as required by the selected count;
- the persistent row base, configured width, and stride during row completion.

The function does not intentionally read destination bytes for preservation or merging.

### Memory writes

Writes are limited to:

- assembled destination bytes; and
- the persistent row-base field at each completed row.

The function does not explicitly write the configured width, stride, bit limit, or unused state word. Those fields can nevertheless be affected if destination writes alias their storage.

For stable, nonoverlapping state with positive width \(W\) and selected count \(N\), the persistent row base advances once for each of the \(\lfloor N/W\rfloor\) completed rows. This expression is explanatory, not permission to ignore address overflow.

### Overlap and persistence

A loaded source byte remains available locally for all of its consumed bits. A destination write cannot retroactively alter that already loaded value. It can alter a later source byte before that later byte is read.

A completed row advances from the persistent row-base value read after its final byte write, not necessarily from the local address of that final byte.

No allocation, release, resource transfer, callback, or external function call is present in the supplied body. Caller ownership is not changed by any explicit operation shown.

Invalid memory access has no specified recovery behavior.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not observed executions. Unless stated otherwise, assume stable, nonoverlapping memory, representable arithmetic, positive row width, and sufficient writable destination storage.

### Full-byte rows

Given source bytes `A5 3C`, an endpoint two bytes beyond the source, bit limit 16, row width 8, and stride 4:

- `A5` is written at the initial destination row base.
- `3C` is written four bytes after that base.
- The persistent row base ends eight bytes after its initial value.
- No intervening destination bytes are written by this operation.

### A row boundary inside a source byte

Given source byte `D6`, bit limit 8, row width 3, and stride 2:

- The source bit sequence is `11010110`.
- The first row receives `110` and writes `C0` at the initial row base.
- The second row receives `101` and writes `A0` two bytes later.
- The remaining `10` writes `80` four bytes after the initial base.
- The persistent row base advances by four bytes, not six, because the last row is unfinished.

### A row spanning multiple bytes

Given source bytes `FF FF`, bit limit 10, row width 10, and stride 4:

- `FF` is written at the initial row base.
- `C0` is written at the next byte.
- Completing the ten-bit row advances the persistent row base by four bytes.
- The six unconsumed source bits are not saved.

### Exact-byte completion without row completion

Given source byte `7E`, bit limit 8, and row width 16:

- `7E` is written at the initial destination address.
- No final duplicate write occurs.
- The persistent row base remains unchanged.
- A later call starts again from that unchanged base, not from the following byte.

### Partial output overwrites existing bits

Given source byte `A7`, bit limit 3, and row width 8:

- Only the leading source bits `101` are consumed.
- The destination byte becomes `A0`.
- Existing low-order destination bits are not preserved.
- The persistent row base remains unchanged.

### Zero stride

Given source bytes `AA 55`, bit limit 16, row width 8, and stride zero:

- Both row writes target the same destination byte.
- The final byte is `55`.
- The persistent row-base value remains numerically unchanged despite both row-completion updates.

### No selected work

Given a zero bit limit and an otherwise valid state:

- No source or destination byte is accessed.
- The row base is not updated.
- Setup reads of the state still occur.

A source endpoint equal to the source address likewise selects no positive work when the limit is nonnegative.
