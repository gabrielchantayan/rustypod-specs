# F-889d94ae5465

## Purpose

F-889d94ae5465 conditionally stores one of two accepted selector values into a caller-supplied object.

Acceptance requires all three of the following:

- The object pointer is non-null.
- The object’s first integer word equals a reference value read from global storage.
- The supplied selector is exactly 1 or 2.

On acceptance, the function stores the selector into the object’s eighth integer word and returns 0. Otherwise, it returns hexadecimal 0x1A, decimal 26, without performing that store.

This is a narrow state-setting operation. The supplied evidence does not establish what the object represents, what either selector means, or whether the reference value is a type marker, signature, or another kind of discriminator.

A pointer to integer-addressable storage. Null is an explicitly handled input.

For a non-null pointer, the first integer word must be readable because the function examines it before deciding whether the selector is acceptable. If the checks succeed, the eighth integer word must also be writable.

The operation does not normalize, clamp, mask, or translate the selector.

## Behavior

### Guard evaluation

The null-pointer check precedes any attempted access through the object pointer.

If the pointer is null, execution takes the failure path. The object is not dereferenced, the global reference value need not be read, and the destination word is not written.

If the pointer is non-null, the first integer word is compared with the global reference value. A mismatch takes the failure path without examining the selector as part of the acceptance expression.

If the first word matches, the function determines whether the selector is 1 or 2. Acceptance of either value leads to the same kind of store; the stored value is the selector itself.

These are short-circuit relationships established by the supplied expression. They are not a claim about instruction scheduling, speculative processor activity, or externally observable bus transactions.

### Successful transition

When all checks pass, the function performs one explicit assignment to the eighth integer word of the supplied storage. It then returns 0.

The destination’s old value is not used. There is no requirement that it differ from the selector. An accepted invocation still performs the assignment when the destination already contains the requested value.

There is no second validation after the assignment. No later explicit operation in this function can convert an accepted invocation into return value 26.

### Rejected transition

When any acceptance check fails, the function returns 26 without assigning the eighth word.

The function does not initialize or reset the destination on rejection. In ordinary, valid, non-overlapping storage, its previous value therefore remains unchanged.

An unsupported selector does not make an arbitrary non-null pointer safe: the first-word comparison occurs before selector acceptance is determined. A non-null pointer that cannot be read may fail at that access even when the selector is neither 1 nor 2.
