## Behavior

### Arithmetic and access notation

The following are specification terms, not recovered program identifiers.

- **Word** means 32 bits; **byte** means 8 bits.
- **W(address)** denotes a 32-bit memory access.
- **B(address)** denotes an unsigned 8-bit memory access.
- A byte store retains only the lowest eight bits of its value.
- **quad(value)** means four times the value.
- **sixteen(value)** means sixteen times the value.
- **field(value)** means `(value AND 0x3FFFFFFF) logically shifted right by 20`.
- **half(value)** means `(value AND 0x3FFFFFFF) logically shifted right by one`.

Unless otherwise qualified, computed arithmetic below describes 32-bit bit-pattern arithmetic with low-32-bit retention. This is the intended reading of the represented target-width operations, not a claim about portable signed-language overflow semantics. The exact target architecture and signed-overflow interpretation remain **documented_only**.

All right shifts applied to explicitly unsigned words or bytes are logical. Word byte order is not established.

### Dependency-call notation

Opaque dependency labels **F-D01** through **F-D43** identify call-site sequences in execution order. They are local reference labels, not verified identities of external functions.

Two sequence forms are used:

- **Five-call sequence:** the first call receives the listed arguments; four subsequent calls have no explicit arguments. The fifth call supplies the listed result, if any.
- **Relay pair:** the first call receives the listed arguments; the second has no explicit arguments and supplies an opaque token.

“No explicit arguments” does not establish that a callee consumes no register or global state. Every constituent call remains observable and must retain its position relative to memory operations.

### Ordering and aliasing requirements

Repeated reads must remain distinct. In particular, the context-byte reads, base-2 byte reads, scaled-half byte reads, and large-base byte reads are separated by calls that may change memory.

Conversely, captured bytes remain the values used at their later listed stores. For example, stage 22 uses byte 3 captured before F-D21; it does not reread the source byte.

Computed addresses may alias each other, the incoming context, or the absolute word at `0x24`. No disjointness is established. Consequently:

- A listed store may affect a later listed read.
- Two successive stores may target overlapping storage.
- Calls may observe intermediate values.
- Repeated clears of `W(0x24)` cannot be collapsed merely because they write the same value.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes execution reaches the relevant stage and the involved accesses are valid.

1. **Fourth-argument shift.** If the fourth argument is `0xFFFFFFFF`, stage 2 writes `0x1FFFFFFF`. It does not perform an arithmetic right shift.

2. **Byte truncation.** If seed 1 is `0x12345678`, stage 3 writes byte `0xE0`. Stage 4 writes byte `0x23`, because the field calculation produces `0x123` before byte truncation.

3. **Reread after callbacks.** If F-D03 changes the byte at incoming context plus one from `5` to `9`, stage 4 targets address `0x1A`, not `0x16`. Stage 5 subsequently uses the captured value `9`.

4. **Different stride expressions.** If selector 8 is `3`, stage 12 first writes `12` at address `0x44`, then reads the word at address `0x20`. Those addresses must not be conflated.

5. **Captured byte across calls.** If byte 3 is `7`, stage 22 clears the word at `0x4B`, even if F-D21 changes the byte at scaled half plus one.

6. **Field width.** The untruncated field calculation ranges from `0` through `0x3FF`. Its byte store retains bits 20–27 of the original word; bits 28–29 are discarded by truncation.

7. **Boundary masks.** Masked half is at most `0x003FFFFF`. Its multiplication by `0x80` is therefore at most `0x1FFFFF80`; its shift left by four is at most `0x03FFFFF0`.

8. **Interrupted execution.** If F-D22 never returns, the preceding byte-3 word clear and absolute `0x24` clear have occurred, but no subsequent operation is guaranteed.
