# F-dbd265464181

## Purpose

“Teardown,” “dispatch state,” and “collection” describe inferred intent. The established behavior consists of the reads, writes, calls, branches, and return described below. The supplied body does not establish concrete object types, ownership transfers, deallocation, or the continued validity of the returned address.

## Behavior

### 1. Initial state transition and early rejection

The function reads G-01 and writes the resulting four-byte value to input offset `0x00`. It then reads input offset `0x128`.

If that field is nonzero:

1. Call F-54385ab29a1f.
2. If it returns, call the non-returning F-feee9156a257.

This branch does not reach related-object resolution. The global read and initial state write occur before rejection.

If the field is zero, read G-02, write its current value to input offset `0x00`, and call F-7e3145ad059a with the input address.

### 2. Related-object resolution and association inspection

After F-7e3145ad059a returns:

1. Call F-230c59ef0030 with the embedded-subobject address.
2. Derive and retain the related-object address.
3. Read G-03 and write its current value to related-object offset `0x00`.
4. Call F-d277584d672d with the related object.

A zero result from F-d277584d672d skips association inspection. Otherwise, retain the returned association-object address and:

1. Read that object’s dispatch-table pointer.
2. Select the operation at table byte offset `0x80`.
3. Invoke it with the association object as an explicit argument.
4. Compare its result with the retained related-object address.

If the addresses differ, do not invoke the `0x7C` operation.

If they match, **reload the dispatch-table pointer from the retained association object after the `0x80` operation returns**. Select offset `0x7C` from this newly read table and invoke it with the association object and zero as explicit arguments. The first indirect operation is not established to preserve the table pointer; reusing the earlier table would not preserve the represented behavior.

After association handling, call F-a6fdc7050c77 with the related object, zero, and one.

### 3. Next state transition and notification

After that call returns, obtain a shared context through F-3fdd14ecd250. Call F-77781c8e0ff9 with:

1. The four-byte value from that context’s offset `0x1C`.
2. The four-byte value read from G-06.

## Acceptance examples

These are conditional static scenarios, not executed tests. Reached storage and call targets must remain valid, and calls are assumed to return unless stated otherwise.

1. **Early rejection:** A nonzero input field at `0x128` produces the G-01 read and first state write, then F-54385ab29a1f and F-feee9156a257. G-02 is not read on this path.

2. **Minimal completion:** With the initial gate zero, no association, zero side state, and zero final auxiliary field, the function returns the derived related-object address. It performs all five staged global-source reads and state writes, plus notification using G-06. It does not read the late invariant field.

3. **Changed later state value:** If an intervening dependency changes G-04, the subsequent G-04 state write uses its value at that later read, not a value captured before the dependency.

4. **Notification-source mutation:** If the notification context lookup changes G-06, the notification argument uses G-06 as read after that lookup. No ordering claim is made between that read and the context `0x1C` read.

5. **Association table replacement:** Suppose the `0x80` operation returns the related-object address and replaces the retained association object’s table pointer. The `0x7C` operation is selected from the replacement table, not the original table.

6. **Association mismatch:** If the `0x80` result differs from the related-object address, no `0x7C` operation occurs. F-a6fdc7050c77 still follows.

7. **Null traversal element:** A nonzero advancement result with a zero element skips only the element dispatch. Traversal continues until an advancement result is zero.

8. **Collection replacement:** If traversal changes the original side state’s collection field to another nonzero reference, the post-finalization dispatch uses that later reference.

9. **Duplicate token operation:** A nonzero active-state predicate and a later matching context `0x28` comparison cause two F-a82ec4b43e2f calls with the originally saved token.

10. **Auxiliary disappearance:** If F-c719314a16bb clears the auxiliary reference, its indirect operation is skipped, but the invariant field is still read.

11. **Invariant without auxiliary:** An initially zero final auxiliary field bypasses the late invariant check even if offset `0x08` is nonzero.

12. **Changing context:** If the `0x24` comparison succeeds on one context and the next lookup returns another, the clearing write targets the latter context.
