# F-14d1c687a87a

## Purpose

It selects among a state-1 transition, an alternate operation guarded by several object fields, and a no-operation branch. Every normally returning path ends by decrementing a 32-bit object field.

The established contract is the sequence of field accesses, dependency calls, state changes, and return-value selection described below. Interpreting these operations as lifecycle management, resource replacement, locking, or reference counting is **inferred intent**, not established behavior. In particular, the meaning of the decremented field is unknown.

## Interface

### Inputs

1. **Object-reference address.** The first argument identifies a readable slot containing the object’s base address. The function reads that slot once, before its first dependency call, and retains the resulting address for the rest of the invocation.
2. **Operation option.** The second argument is a 32-bit integer tested only for equality with zero. Any nonzero value enables one conditional dependency call. Its magnitude and sign otherwise have no established significance.

Changing the caller’s object-reference slot during a dependency call does not redirect subsequent accesses by this invocation: they continue to use the initially obtained base address.

## Behavior

### Entry and branch selection

The function captures the object address and initializes its eventual result to zero. It then calls F-b93e3fe564f6 with that object address. The dependency’s return value is not used.

Only after this call returns does the function read the state byte at `0x0E`. Consequently, any mutation made by that dependency can affect branch selection.

If the state byte equals 1, the function takes the state-1 branch. Otherwise, it considers the alternate branch. It does not reconsider this top-level choice after later calls or writes.

### State-1 branch with nonzero selector

When state is 1, the function reads the byte at `0x14`.

If that byte is nonzero, it performs these direct effects in order:

1. Writes 4 to the state byte at `0x0E`.
2. Reads the 32-bit value at `0x24` and writes it to `0x28`.

No other branch-specific dependency is called. The result remains zero, and execution proceeds to the common final decrement.

### State-1 branch with zero selector

If the byte at `0x14` is zero, the function reads the 32-bit value at `0x6C` and calls F-aa62419fe69f with that value and the integer constant 2.

A nonzero result from this call becomes the function’s result. The function performs none of the remaining state-1 actions described below and proceeds to the common final decrement.

If the dependency returns zero:

1. The function writes 2 to the state byte at `0x0E`.
2. It examines the operation option.
3. If the option is nonzero, it calls F-41010b2f183d with the object address and the integer constant 4.

If F-41010b2f183d is called and returns nonzero, that result becomes the function’s result. The byte at `0x12` is not directly cleared by this function on that path, and the final state-1 dependency is skipped. The earlier write of state 2 has already occurred; there is no visible rollback.

If the option is zero, or the optional call returns zero, the function:

1. Writes zero to the byte at `0x12`.
2. Reads the byte at `0x06`.
3. Only if that byte is nonzero, reads the byte at `0x0F`.
4. Only if the byte at `0x0F` is zero, reads the byte at `0x18`.
5. Only if the byte at `0x18` differs from 2, calls F-2642a413cd82 with the object address.

The result of F-2642a413cd82, if called, becomes the function’s result. If a gate prevents that call, the result remains zero.

These gates use short-circuit evaluation. Fields after a failed gate are not read by this sequence.

### Alternate branch

When the post-entry-call state byte differs from 1, the function tests these conditions in order:

1. The byte at `0x04` is nonzero.
2. The 32-bit field at `0x9C` equals zero.
3. The 32-bit field at `0x98` equals zero.

Each later read occurs only if the preceding condition passes. If any condition fails, the branch performs no further branch-specific action; the result remains zero.

If all conditions pass, the function performs the following sequence:

1. Calls F-f3192f39e4f6 with the object address. Its return value is not used.
2. Reads the 32-bit field at `0xE0`, subtracts one, and writes the result back.
3. Reads the 32-bit value at `0x24`.
4. Calls F-094b96da48ec with that value.
5. Writes the dependency’s 32-bit result to `0x54`.
6. Calls F-b93e3fe564f6 again with the same captured object address.
7. Rereads the 32-bit field at `0x54`.

If the reread value is zero, the function selects result 7.

If the reread value is nonzero, the function reads the current 32-bit value at `0x24`, copies it to `0x28`, and calls F-e6b20755bfcb with the object address. That dependency’s result becomes the function’s result.

The test at step 7 is not a test of a cached return value. The intervening dependency may have changed `0x54`. Likewise, the copy to `0x28` uses a fresh read of `0x24`, not necessarily the value previously passed to F-094b96da48ec.

### Common final decrement and return

Thus:

- Paths outside the accepted alternate branch contain one direct decrement.
- The accepted alternate branch contains two direct decrements, separated by dependency calls and other accesses.

Each decrement uses the field’s value at that point. If dependencies modify the field, the final value is not necessarily the entry value minus one or two.
