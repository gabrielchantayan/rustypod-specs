# F-be5408e44e9e

## Purpose

F-be5408e44e9e modifies a 32-bit position-related field in an object, applies one direction-dependent boundary rule, and uses a subsequently read input flag to decide whether further processing is permitted. When permitted, an equality condition selects either a short notification path or a longer embedded-operation setup path.

Every normally completed path invokes a final object-processing dependency and returns the 32-bit value 1. That return value does not identify which path ran or report a separately established success condition.

“Position,” “extent,” and “span” below name arithmetic roles. Scrolling, animation, timing, and completion signaling are possible interpretations, not established semantics.

## Behavior

### Observation boundaries and arithmetic inputs

Their difference, offset-12 value minus offset-4 value, is called the **dependency span**.

The visible representation does not establish the dependency’s complete output layout, required storage extent, or initialization guarantee. In particular, deterministic arithmetic requires both consumed words to have defined values.

After F-c24767c70ad0 returns, the object words at `0x80`, `0x84`, `0x88`, and `0x8C` are read in that order. The **object extent** is the captured `0x8C` value minus the captured `0x84` value. The other two reads have no later direct computational use in the supplied representation.

The extent is retained as a computed value. It is not recomputed from object fields after later calls. By contrast, the dependency span is calculated from its temporary words where needed: once for the positive-movement adjustment, if applicable, and again for the later equality test, if reached. Those calculations must not be described as an unconditionally immutable span snapshot. A dependency that retains valid access to that temporary storage could affect a later calculation; whether such retention occurs is unknown.

### Movement and boundary rules

The current position at `0x14C` is read, increased by twice the retained movement quantity, and written back immediately. This initial write occurs even if a boundary rule subsequently overwrites it.

For a movement quantity less than or equal to zero, the only boundary rule tests whether the updated position plus 4 is less than 1. If so, `0x14C` receives the 32-bit representation of −4. Thus zero movement can still repair an existing position below the lower boundary. At −4, the rule writes −4 again; at −3, it performs no boundary write.

For a strictly positive movement quantity, the dependency span is reduced by 8 for the boundary calculation. If the captured object extent is less than or equal to the updated position plus this reduced span plus 4, the position receives the extent minus the reduced span minus 4.

When all intermediate arithmetic is representable, the positive-direction condition can equivalently be expressed as:

- Updated position plus dependency span minus 4 is at least the captured extent.
- The replacement position is captured extent minus dependency span plus 4.

The comparison includes equality, so an already matching boundary value still causes a write.

These rules are direction-dependent, not an unconditional two-sided clamp. Positive movement does not invoke the lower-bound rule. Nonpositive movement does not invoke the span-based rule.

### Flag gating and equality selection

After movement processing, F-8bb3020950cd is called a second time with the input-record address. Only afterward is the flag word at `0x10` read and masked with `0x40000000`.

If the masked bit is set, both follow-up paths are skipped. Movement is not undone, and final object processing still occurs.

If the bit is clear, the function rereads the current position and evaluates whether current position plus the then-consumed dependency span minus 4 equals the captured object extent. Consequently, the second input-processing call can affect the decision through changes to the object or accessible temporary storage. Changes to the original extent fields do not by themselves replace the already computed extent.

On equality, F-957485a09c37 is called with 1. After it returns, the byte at `0x150` is written with 1. No direct setup-path writes occur on this path.

Neither the flag-suppressed path nor the setup path directly clears `0x150`. Its earlier value may persist, but dependency effects prevent a general return-time preservation guarantee.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless varied explicitly, all consumed temporary words are initialized, arithmetic intermediates are representable, addresses are valid, calls return normally, and dependencies do not alter relevant values.

1. **Zero movement still adjusts an invalid lower position.** With initial position −9 and movement zero, the first position write is −9 and the boundary write is −4. If the masked flag bit is subsequently set, neither follow-up path runs, but F-92bea7c30bd6 still receives the object.

2. **The lower-bound comparison is strict.** Starting at −4 with zero movement produces an initial write of −4 and another write of −4 because zero is less than 1. Starting at −3 produces no boundary write because 1 is not less than 1.

3. **Positive movement can reach equality through adjustment.** With extent 100, span 40, initial position 63, and movement 1, the initial update writes 65 and the positive-direction rule writes 64. With the flag clear and span unchanged, the equality expression is 100. F-957485a09c37 receives 1 before `0x150` receives byte 1.

4. **A position short of the boundary selects setup.** With extent 100, span 40, initial position 10, and movement 1, the position becomes 12 without adjustment. A clear flag selects setup. For this representable nonnegative shift input, `0xC8` receives `0x000C0000`.

5. **Positive movement does not repair the lower boundary.** With extent 100, span 40, initial position −20, and movement 1, the position becomes −18 and the positive-direction boundary test fails. No direct write of −4 occurs.

6. **The second input-processing call can change equality.** In the third example, if that call changes the position to 63, the equality test fails despite the earlier boundary write of 64. The extent remains the previously computed 100.

7. **A later span calculation can differ from the earlier one.** In the third example, suppose a dependency has valid retained access to the temporary output and changes the words so their difference becomes 44 before equality is evaluated. With position still 64, the expression becomes 104, selecting setup rather than equality. This example is conditional on that access being valid; retention is not established.

8. **Changing the global source does not redirect the later captured-pointer read.** Suppose the source initially identifies storage A. After pointer capture and the first dereference, an intervening dependency changes the source to identify B and changes A’s word to 11. The later F-e31e208b4293 call receives 11 from A, not B’s word, provided A remains valid.
