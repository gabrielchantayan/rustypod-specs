# F-f797e866e021

## Purpose

F-f797e866e021 scans a zero-terminated byte sequence, emits ordinary bytes through a dependency, and interprets percent-introduced directives using two externally supplied lookup tables. Directives can consume 32-bit argument words, configure formatting state, invoke numeric or string formatting dependencies, or emit individual values.

Its structure suggests a formatted-output engine. That intent does not establish compatibility with any standard formatting API. In particular, directive recognition is table-driven, some familiar-looking directives have unusual behavior, and output, padding, numeric conversion, and result accounting depend on unavailable implementations.

The established contract is therefore the scanner’s control flow, argument consumption, state preparation, and dependency-call ordering. Exact rendered output is conditional on the lookup tables, global defaults, and dependency behavior.

## Interface

The function accepts five inputs:

1. A first opaque 32-bit value.
2. A second opaque 32-bit value.
3. A third opaque 32-bit value.
4. A pointer to a zero-terminated byte sequence used as the format input.
5. A pointer to a sequence of 32-bit argument words.

It returns a 32-bit value held in its local formatting context. This value is initialized to zero. The visible function does not explicitly increment it or assign a replacement after initialization; dependencies receiving the context may modify it.

The first three inputs are copied into two distinct local representations:

- A formatting context, with a zero-initialized result slot between the second and third values.
- A consecutive three-word copy elsewhere in the local storage.

The purpose and subsequent use of the second representation are unknown. The visible body does not pass its address explicitly.

### Input widths and interpretation

- Format elements are read as 8-bit bytes and promoted to unsigned values for classification.
- Each consumed argument occupies one 32-bit word.
- Character conversion uses only the low eight bits of its argument word.
- Numeric conversions pass an entire 32-bit word to a dependency.
- String conversion interprets an argument word as a pointer. This establishes a 32-bit pointer representation for that operation in the supplied representation; it is not a portable host-pointer interface.
- Width and limit values are stored as 32-bit quantities. Subtraction in the visible string limit logic uses unsigned 32-bit arithmetic.

No argument count, format length, string length, or destination capacity is supplied explicitly.

### Preconditions

For defined, successful execution, callers must provide readable input and argument storage sufficient for the path actually taken. String arguments must identify readable storage as required by the string dependency and the subsequent byte loop.

There are no visible null-pointer checks or bounds checks. A terminating zero in the format is sufficient to stop scanning only when it is reached by the outer scanning loop; encountering a zero while parsing a directive does not trigger that loop’s termination check.

## Behavior

### Ordinary scanning and completion

At each outer iteration, the function obtains the current classification-table address, reads the current format byte, and checks that byte for zero.

- Zero returns the current result slot.
- A nonzero byte other than percent is passed to F-e5b1b048330a together with the formatting-context address.
- After ordinary emission, the format cursor advances by one byte.
- Percent begins directive processing without being emitted directly.

Consequently, literal output also goes through the formatting dependency. The visible body does not write output storage or update an output count itself.

### Directive initialization

On entering each percent directive, the function explicitly initializes:

- Dot-controlled phase: inactive.
- Padding byte: space.
- Alignment-related state: zero.
- Limit: the current value of an external default.
- Plus-related state: zero.
- Width-present indicator: zero.

It does not initialize the width-value or string-measurement slots at this point. Dependencies must not be assumed to ignore those slots merely because related flags are clear; their interpretation is unavailable.

### Classification and dispatch

Directive processing advances the cursor before inspecting each token.

A byte is first checked against the classification table. If the byte’s table entry has bit `0x10` set, it is treated as the beginning of a numeric field:

- Before the dot-controlled phase, a raw byte equal to ASCII zero selects zero padding. F-cf3df450b773 is then called with the address of the format cursor. Its returned word becomes the width, and width-present is set.
- After that phase has begun, the dependency’s returned word becomes the limit instead.
- Following the call, the function subtracts one byte from the cursor; the next parsing step advances it again.

Thus numeric parsing delegates both value production and cursor movement. The dependency’s behavior, including overflow handling and which characters it accepts, is unknown.

For a byte not classified this way, the function reads its entry in a separate dispatch table. Actions depend on that mapped value, not necessarily on the raw byte’s character.

The following descriptions name dispatch values by their ASCII labels for readability. They do not assert that the tables map raw bytes identically.

### State-setting tokens

- **Dot:** Activates the dot-controlled phase and sets the limit to one. A dot without a subsequent numeric field therefore does not visibly set a zero limit.
- **Asterisk:** Reads one argument word and advances the argument cursor. Before the dot-controlled phase, it sets width and width-present. After that phase, it sets the limit.
- **Plus:** Sets plus-related state to one.
- **Minus:** Sets alignment-related state to one.
- **Lowercase l:** Makes no explicit state change and continues directive parsing. It does not change argument-word width.

These tokens keep the same directive active.

No negative-width normalization, negative-limit normalization, or wider argument extraction is visible.

### Single-value and numeric conversions

The following actions end the current directive. The outer scanner then advances beyond the current token.

| Dispatch value | Argument consumption | Action |
|---|---|---|
| Percent | None | Emit percent through F-e5b1b048330a |
| Lowercase c | One word | Emit its low eight bits through F-e5b1b048330a |
| Lowercase d or i | One word | Call F-0c56f54da7dc with the word, radix 10, and context |
| Lowercase o | One word | Call F-0c56f54da7dc with the word, radix 8, and context |
| Lowercase u | One word | Call F-bf301e937cc5 with the word, radix 10, and context |
| Lowercase x or uppercase X | One word | Call F-bf301e937cc5 with the word, radix 16, and context |
| Lowercase f | None | Emit uppercase F through F-e5b1b048330a |

The distinction between the two numeric dependencies is established; their signedness rules are not. In particular, it would be unsupported to specify the octal path as unsigned merely because of conventional formatting behavior.

Uppercase and lowercase hexadecimal dispatches use the same dependency and radix. No separate case-selection state is explicitly set for them.

For numeric conversion, the current argument is read before the dependency call, but the local argument cursor is advanced after that call. For character conversion, the argument cursor advances before emission.

### String conversion

For a dispatch value of lowercase s, the function performs these operations in order:

1. Reads the current argument word and treats it as a string pointer.
2. Calls F-1cb585febd84 with that pointer, the raw format byte responsible for dispatch, and the current dispatch-table address.
3. Stores the dependency’s returned word in the measurement slot.
4. Computes a leading-side selector from alignment state: zero state produces one; one state produces zero; unsigned states greater than one also produce zero.
5. Calls F-104e665a1ba6 with that selector and the context.
6. Iterates over the string, emitting eligible characters through F-e5b1b048330a.
7. Calls F-1cb585febd84 again, this time with the current string pointer as the only explicit argument.
8. Replaces the measurement slot with this second return value.
9. Calls F-104e665a1ba6 with the current alignment-related state and context.
10. Advances the argument cursor by one word.

The string loop reads the current character to determine whether it is zero. For a nonzero character, it decrements the limit modulo \(2^{32}\), stores that result, and stops without emission if the result is `0xffffffff`. Otherwise, it emits the character and advances the string pointer.

With stable input and a limit unmodified by dependencies:

- An initial limit of zero emits no characters and leaves the limit at `0xffffffff` if the first character is nonzero.
- A limit of one permits one character.
- A limit of \(N\) permits up to \(N\) nonzero characters.
- A zero character stops the loop without decrementing the limit.

The function can inspect the next character even when the current limit allows no further emission. It also measures the string before this limiting loop. The limit therefore does not establish a bounded-read guarantee.

The measurement after the loop starts at the first un-emitted character or at the terminating zero, not necessarily at the original string pointer.

### Backslash-class dispatch

A dispatch value corresponding to backslash performs special emission based on the **raw current byte**:

- Raw lowercase a emits 7.
- Raw lowercase h emits 8.
- Raw lowercase n emits 13 followed by 10.
- Raw lowercase r emits 13.
- Any other raw byte emits its own byte value.

This dispatch remains inside directive parsing. After emission, it explicitly advances the cursor once; the next parser step advances it again. Therefore the byte immediately following the escape-class token is skipped without being inspected by the parser.

This behavior does not establish ordinary backslash escape syntax. Recognition still depends on the dispatch table, and the raw byte itself selects the listed special cases.

### Unrecognized dispatch values

Any dispatch value without a handled action ends the current directive without explicit emission or argument consumption. Scanning resumes after that raw byte.

There is no visible diagnostic, error return assignment, or literal fallback for such a token.

## Side effects

The visible function directly modifies only its own local storage and local cursors. It reads caller-owned format, argument, and string memory.

Externally observable effects can arise through dependencies:

- Emission and any result accounting.
- Numeric formatting.
- Leading or trailing string formatting.
- Cursor mutation during numeric-field parsing.
- Changes to shared globals or storage reachable through context fields.

No allocation, deallocation, transfer of ownership, or retention of pointers is explicitly performed by the visible body. This does not establish that dependencies allocate nothing, release nothing, or retain nothing.

The two lookup-table pointers and the default limit are external state. Their read timing matters:

- The classification-table address is obtained at each outer scanning iteration and retained for that directive’s classification steps.
- The default limit is read when a directive begins.
- The dispatch-table address is read during token dispatch and again when supplied to the first string measurement call.

Dependencies must not be assumed to preserve these globals. Nor may they be assumed to preserve context fields: subsequent decisions can observe fields changed through the context pointer.

No rollback is visible. If a dependency fails to return, accesses invalid memory, or partially emits output, this function provides no visible recovery mechanism.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless otherwise stated, assume conventional identity dispatch for the named tokens, stable readable inputs, and dependencies that do not unexpectedly alter formatting state.

1. **Empty format.** If the first format byte is zero, the function returns zero without an emission or formatting call. The outer iteration still obtains the classification-table address.

2. **Literal bytes.** For a format containing three non-percent bytes followed by zero, F-e5b1b048330a receives those bytes in order. The return value is whatever remains in the result slot after those calls, not necessarily three.

3. **Literal percent.** A percent-introduced token mapped to percent emits one percent and consumes no argument word.

4. **Character narrowing.** A character directive given argument word `0x12345641` passes `0x41` to the emission dependency.

5. **Numeric routing.** Decimal d and i dispatches each consume one word and select F-0c56f54da7dc with radix 10. Octal selects the same dependency with radix 8. Unsigned-decimal dispatch selects F-bf301e937cc5 with radix 10.

6. **Hexadecimal equivalence.** Lowercase and uppercase hexadecimal dispatches pass the same argument word and radix 16 to the same dependency. Different output case is not required by the visible function.

7. **Floating-looking token.** A token mapped to lowercase f emits uppercase F and leaves the argument cursor unchanged.

8. **Star consumption order.** A width asterisk followed by a decimal conversion consumes the width word first and the numeric word second. The width word is not normalized for signedness by this function.

9. **Dot default.** A dot followed directly by string conversion establishes a limit of one. If the string begins with two nonzero bytes, the loop emits only the first, subject to the intervening dependencies preserving that limit.

10. **Zero string limit.** With limit zero and a nonempty string, no string character is emitted by the loop. Both measurement calls and both side-formatting calls still occur.

11. **Empty string.** For an initially empty string, the loop emits nothing and does not decrement the limit. Measurement and side-formatting calls still occur.

12. **Escape-class newline.** If raw lowercase n maps to the backslash-class dispatch, emission calls receive 13 and then 10. The immediately following format byte is skipped before parsing continues.

13. **Unknown token.** A token whose dispatch entry has no recognized action consumes no argument and produces no explicit output, then returns control to ordinary scanning.

14. **Trailing percent.** A format ending immediately after percent is not guaranteed to terminate safely. The following zero is handled by directive classification and dispatch rather than by the outer zero check; behavior depends on the tables and subsequent readable storage.

## Uncertainties

The following remain **documented_only**:

- Actual lookup-table contents and therefore the raw syntax accepted for each action.
- The initial default limit and its intended sentinel meaning.
- Numeric signedness, prefix rules, digit case, padding, and overflow policy.
- Whether the return slot is a count, status, or another result.
- The actual purpose of the first three inputs and their duplicate local copy.
- Dependency ownership, allocation, retention, error, and global-mutation behavior.
- The precise string-measurement interface.
- Whether string bytes above `0x7f` are promoted as negative character values before emission; this depends on the target character interpretation.
- Safety or intended meaning of malformed, unterminated, or incomplete directives.

There is no established error code, null-string replacement, bounded-output guarantee, or standard-format compatibility.
