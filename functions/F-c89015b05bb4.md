# F-c89015b05bb4

## Purpose

F-c89015b05bb4 returns a 32-bit unsigned value derived from a requested quantity and a 32-bit baseline stored in a caller-supplied object. It may first update an auxiliary state word through F-f9a14c0f405b and subtract an adjustment supplied through that dependency. It then either returns the baseline directly or invokes F-d7be9cfb4000 and multiplies that dependency’s result by the captured baseline.

The established behavior is arithmetic and state manipulation. Interpreting the result as an allocation size, block count, alignment result, or capacity would require evidence not supplied here.

Two distinctions are essential:

- The comparison against the baseline uses the adjusted request, before any limiting to 262,144.
- The auxiliary state is not necessarily cleared whenever the effective request is small. Clearing occurs only in the explicit below-baseline branch.

## Behavior

### 1. Initialize the adjustment and inspect auxiliary state

The initial adjustment is copied into a local signed 32-bit object, regardless of whether the auxiliary state is zero.

The function reads the 32-bit word at object offset 40 and tests whether it is nonzero.

If that first read is zero:

- F-f9a14c0f405b is not called.
- The requested quantity is not adjusted.
- The initial adjustment has no further explicit effect.

If that first read is nonzero:

1. The auxiliary word is read again to obtain the first argument to F-f9a14c0f405b.
2. F-f9a14c0f405b is called with that word and the address of the local adjustment.
3. On normal return, the dependency’s 32-bit return value is stored at object offset 40.
4. The current local adjustment is subtracted from the requested quantity using 32-bit unsigned arithmetic.

The two reads of offset 40 are distinct in the supplied expression structure. This is not a synchronization guarantee, and it does not establish support for concurrent mutation.

The adjustment used in subtraction is the value present after the dependency returns. The dependency may replace the initial adjustment or leave it unchanged. The caller must not assume that it is nonnegative, bounded by the request, or representative of successful progress.

Subtraction wraps modulo 2³². In particular:

- A positive adjustment larger than the request produces a large unsigned result rather than a negative result or an error.
- A negative adjustment can increase the unsigned request, subject to the same wraparound.
- No saturation occurs.

### 2. Capture the baseline

After the optional dependency call, state replacement, and subtraction, the function reads the 32-bit unsigned baseline at offset 36.

That read captures the baseline used for the subsequent comparison, dependency argument, and final multiplication. The function does not explicitly reread the baseline later.

Consequently, if F-f9a14c0f405b changes offset 36 through some external means, that change can affect this invocation. The function does not capture the baseline before calling that dependency.

### 3. Handle an adjusted request below the baseline

If the adjusted requested quantity is strictly less than the captured baseline, using unsigned comparison:

1. The function writes a 32-bit zero at offset 40.
2. It returns the captured baseline.

F-d7be9cfb4000 is not called on this path.

This clearing write occurs even when offset 40 is already zero. It also replaces any auxiliary value just returned by F-f9a14c0f405b.

There is no explicit release operation associated with the clearing write. Clearing the word must not be interpreted as evidence that the prior value’s resources were freed.

Equality does not take this branch. An adjusted request exactly equal to the baseline proceeds to the dependency-call path.

### 4. Apply the conditional request limit

When the adjusted request is greater than or equal to the captured baseline, the function considers limiting it to 262,144, or 0x40000.

The limit applies only if both conditions hold:

- The adjusted request is strictly greater than 262,144.
- A fresh read of the auxiliary word at offset 40 yields zero.

The auxiliary-word read in this step occurs only when the request exceeds the limit. At or below 262,144, this condition does not read offset 40.

When both conditions hold, the quantity passed onward is replaced with exactly 262,144. Otherwise, it remains the adjusted request.

This auxiliary-state test observes the state after any earlier F-f9a14c0f405b return value has been stored. It is not based solely on whether auxiliary state existed at entry.

The baseline comparison is not repeated after limiting. Therefore, a request that originally met or exceeded the baseline can be reduced below it and still proceed to F-d7be9cfb4000.

### 5. Compute the returned product

F-d7be9cfb4000 is called with:

1. The adjusted and, when applicable, limited unsigned request.
2. The captured unsigned baseline.

The dependency’s result is represented as a signed 32-bit integer. For multiplication by the unsigned 32-bit baseline, its bit pattern participates in unsigned arithmetic.

The returned value is the product modulo 2³². There is no explicit check for:

- A negative dependency result.
- Overflow.
- A result below the request.
- A result below the baseline.
- A zero result.

The function performs no explicit object-field write after this dependency returns. If F-d7be9cfb4000 changes object storage or other state through an indirect channel, this body does not restore that state. Its returned product nevertheless uses the baseline already captured before the call.

## Side effects

### Explicit object effects

The function may write only the auxiliary word at offset 40 through its own explicit object accesses:

- It stores the return value of F-f9a14c0f405b when the initial auxiliary-state test is nonzero.
- It stores zero when the adjusted request is below the captured baseline.

The function does not explicitly write the baseline at offset 36.

### Dependency effects and ordering

Dependency effects are not constrained by the supplied material. Neither dependency may be assumed to preserve globals, preserve object contents accessible through other channels, allocate nothing, or release memory.

The important ordering on the auxiliary-processing path is:

1. Read auxiliary state for the nonzero test.
2. Read it again for the dependency argument.
3. Call F-f9a14c0f405b.
4. Store its return value into auxiliary state.
5. Read the updated local adjustment and subtract it from the request.
6. Read the baseline.
7. Select the below-baseline or dependency-call path.

Any dependency write to offset 40 before F-f9a14c0f405b returns is superseded by the explicit return-value store, assuming normal return and valid accesses.

### Ownership and lifetime

Passing auxiliary state to F-f9a14c0f405b does not establish ownership transfer. Replacing or clearing that state does not establish destruction or release.

The adjustment address refers to local storage used during this invocation. No contract supplied here authorizes retaining that address for later use.

### Errors and abnormal completion

There is no explicit error branch, recovery mechanism, or rollback. Invalid memory access, a dependency that does not return, or an invalid dependency argument is outside the demonstrated normal-return behavior.

If execution stops during a dependency call, the later state writes and arithmetic are not guaranteed to occur.

Its returned auxiliary state is stored and then overwritten with zero. The function returns 100 without calling F-d7be9cfb4000.

6. **Subtraction underflow is unsigned.**  
   With request 5 and an adjustment of 10 supplied by F-f9a14c0f405b, the adjusted request is 4,294,967,291. If the captured baseline is 100 and the returned auxiliary state is nonzero, F-d7be9cfb4000 receives that large request and 100. There is no underflow error path.

7. **A negative adjustment increases the request.**  
   With request 10 and a final adjustment of −3, the adjusted request is 13. Subsequent behavior depends on the captured baseline and auxiliary state.

8. **Limiting does not restart the baseline check.**

10. **Negative multipliers are not rejected.**
