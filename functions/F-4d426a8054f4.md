# F-4d426a8054f4

## Purpose

F-4d426a8054f4 performs in-place, comparison-directed insertion passes over fixed-width records. When the supplied record count exceeds ten, it first invokes F-f66aaed1491e with the original four arguments.

The directly visible passes compare an existing record with the next record, search backward while the comparison result is positive, and then move the next record into the selected position. Movement preserves the relative order of records displaced by that insertion.

This is not an unconditional guarantee of a sorted result. Such a guarantee requires valid address arithmetic, accessible memory, an appropriate comparator, and suitable behavior from F-f66aaed1491e when that dependency is invoked. Zero-count input has a particularly important unsigned-underflow behavior described below.

## Interface

The function accepts four 32-bit unsigned quantities and has no explicit return value:

| Position | Meaning |
|---|---|
| First | Base address of the record region. |
| Second | Record count. |
| Third | Record width in bytes. |
| Fourth | Encoded comparator address. |

The comparator is called indirectly after clearing the lowest two bits of the fourth argument. It receives two record addresses, in order:

1. The address of an earlier record being examined.
2. The address of the next record selected for insertion.

Its result is interpreted as a signed 32-bit integer. A strictly positive result causes the backward search to continue. Zero and negative results both stop that search.

The comparator calling convention, any additional implicit machine state, and the significance of the cleared address bits are not established. In particular, clearing those bits does not by itself establish any specific execution-mode convention.

The record representation is opaque. The function uses the width to identify record boundaries and move record contents; it does not interpret fields.

### Preconditions for ordinary record-array behavior

A caller seeking conventional in-place ordering needs all of the following:

- The record region is readable and writable for every address reached.
- The normalized comparator address identifies a callable target.
- Comparator calls obey the required calling convention and return meaningful signed comparison results.
- Address additions, record-span multiplication, and backward address steps do not wrap in ways that invalidate traversal.
- The comparator does not alter records in ways that invalidate the comparisons or pending movement.
- If invoked, F-f66aaed1491e leaves a state in which the subsequent insertion passes remain valid.

These are preconditions, not validations performed by this function.

## Behavior

### Width-zero exit

If the record width is zero, the function returns without:

- Calling F-f66aaed1491e.
- Calling the comparator.
- Reading record contents.
- Writing record contents.

This applies regardless of the count, base address, or comparator argument.

### Conditional preliminary dependency

For nonzero width, F-f66aaed1491e is called exactly once when the unsigned count is greater than ten.

The dependency receives all four original argument values, including the unmodified comparator argument. The enclosing function normalizes the comparator address only for its own indirect comparison calls.

The preliminary call precedes the directly visible insertion passes. Its effects are not specified by the supplied evidence. The subsequent passes operate on whatever contents and relevant execution state exist after that call returns normally.

Counts of ten or less do not trigger this dependency.

### Traversal bound and arithmetic

For nonzero width, the traversal starts with an address equal to the supplied base.

Its exclusive upper bound is the base plus the width multiplied by one less than the count. The decrement, multiplication, and addition use 32-bit unsigned arithmetic, with results reduced modulo \(2^{32}\).

The outer traversal continues only while its current address is numerically less than that bound.

For an ordinary, nonwrapping array with count at least two, this selects records in order beginning with the second record. The first pass examines the second record; the last pass examines the final record.

The next record address is obtained by adding one record width to the current traversal address. That next address becomes the traversal position for the following outer iteration, independently of how far backward the insertion search travels.

No count or extent validation precedes this arithmetic.

### Backward comparison search

For each selected next record:

1. Its address is fixed for the duration of the search.
2. The search begins at the preceding record’s address.
3. A comparison is attempted only while the search address is numerically greater than or equal to the base.
4. The comparator receives the search address first and the fixed next-record address second.
5. A strictly positive signed result moves the search address backward by one record width.
6. A zero or negative result ends the search immediately.

The next record is not first copied into a separate full-record buffer. All comparisons in this search refer to its original memory address. The function performs its own record movement only after the search ends.

If a backward step produces an address below the base without wrapping, the next comparison is suppressed. The insertion destination is then one width above that below-base address, ordinarily the base itself.

If subtraction wraps to a numerically large address, the base check may remain true. The function has no independent “beginning of array” index that would prevent a subsequent out-of-range comparison.

### Record movement

After the search, the insertion destination is one record width beyond the final search address.

The function then moves the selected record into that destination and shifts intervening records forward by one record position. Movement proceeds one byte lane or one four-byte lane at a time, rather than copying or shifting an entire record at once.

For each lane, in increasing offset order:

- The lane from the selected next record is read and retained temporarily.
- Source addresses are considered backward, one record width at a time.
- While a source address is numerically at or above the insertion destination, that source lane is read and written one record width forward.
- The retained lane is written at the insertion position.

Consequently, all reads and writes for one lane complete before the next lane begins. When records contain multiple lanes, intermediate memory can contain a mixture of old and moved portions of records.

The function does not call the comparator during its own movement phase.

### Transfer-width selection

The movement path is selected separately for each insertion:

- Four-byte transfers are used if both the record width and the selected next-record address are divisible by four.
- Otherwise, one-byte transfers are used.

In the four-byte case, offsets advance by four, beginning at zero and stopping before the record width. Because this path requires a width divisible by four, there is no trailing partial transfer.

In the byte case, every offset from zero through width minus one is processed.

This selection depends on numeric alignment, not on the contents or declared type of the records. Under nonwrapping arithmetic, a width divisible by four and an aligned next-record address also make the other record addresses in that insertion aligned.

### No-displacement insertions still access memory

A comparison that immediately returns zero or negative does not eliminate movement work.

In that case, the insertion destination is the selected next record’s existing address. Each lane is read from that record and written back to the same location. There are no intervening-record shifts, but the self-writes remain observable.

Thus, even an already ordered region requires writable storage whenever at least one insertion pass is reached.

### Ordering and stability

For the directly visible insertion passes, equal-comparing records are not deliberately crossed: a zero result stops the backward search.

With a coherent comparator, unchanged records during comparisons, valid arithmetic, and no preliminary dependency that disrupts stability, this gives the usual stable insertion behavior.

Whole-function stability is not established for counts greater than ten because F-f66aaed1491e may already have reordered equal records. Comparator side effects can also invalidate ordinary ordering arguments.

## Side effects

The function may:

- Invoke F-f66aaed1491e once.
- Invoke the normalized comparator repeatedly.
- Read and overwrite record storage.
- Perform writes that leave the stored value unchanged.

No allocation, deallocation, ownership transfer, or retained reference is directly visible. The supplied region is treated as caller-provided storage.

The function does not explicitly access a global object in the supplied body. This does not establish that its dependencies preserve global state. Neither F-f66aaed1491e nor the comparator can be assumed to avoid allocation, release memory, retain addresses, mutate unrelated state, or modify the records.

There is no explicit error status or recovery path. Invalid addresses, inaccessible storage, an invalid callback target, or incompatible dependency behavior are not converted into a reported error. Whether such conditions fault, corrupt memory, or have another effect depends on the execution environment.

Movement is not atomic at record granularity. Concurrent observation, memory-mapped storage, or asynchronously inspected memory could expose the lane-by-lane ordering. The evidence does not establish thread safety or synchronization.

## Acceptance examples

These examples describe conditional behavior derived from the supplied static evidence. They are not runtime test results.

### Zero width

Given any count and any address arguments, if width is zero:

- No preliminary dependency call occurs.
- No comparator call occurs.
- No record read or write occurs.
- The function returns without an explicit result.

Even a count greater than ten does not change this outcome.

### One record

Given nonzero width and count one:

- F-f66aaed1491e is not called.
- The computed bound equals the base.
- The initial traversal address is not less than that bound.
- No comparator call or record access occurs.

### Two already ordered records

Assume two valid records, nonwrapping addresses, and a comparator that returns zero or negative for the first record against the second.

Expected behavior:

- One comparator call occurs, with the first record address followed by the second.
- No earlier record is shifted.
- Every lane of the second record is read and written back.
- The first record is not read by the function’s movement phase, although the comparator may read it.

### Two reversed records

Assume two valid records, a pure comparator returning positive for the first against the second, and a base address large enough that subtracting one width does not wrap.

Expected behavior:

- The comparator is called once.
- The search steps below the base.
- The second record is inserted at the base.
- The first record moves to the second position.

For each lane, the old second-record lane is read first, the first-record lane is copied forward next, and the saved lane is written at the base last.

### Equal records after a larger predecessor

Assume three records whose comparison keys are \(2, 1_a, 1_b\), with a pure comparator treating \(1_a\) and \(1_b\) as equal, valid nonwrapping storage, and no preliminary dependency call.

The directly visible passes produce key order \(1_a, 1_b, 2\). The later equal record stops behind the earlier equal record rather than crossing it.

### Alignment-sensitive movement

With width eight and an aligned selected-record address, movement uses two four-byte lanes, at offsets zero and four.

With width six, movement uses six byte lanes even if the selected-record address is aligned.

With width eight but an unaligned selected-record address, movement uses eight byte lanes.

These alternatives preserve the same intended record permutation under ordinary-memory assumptions, but have different observable access widths and sequencing.

### Threshold behavior

With nonzero width:

- Count ten skips F-f66aaed1491e.
- Count eleven calls it before any directly visible comparator call or record movement.

No unconditional final ordering claim follows for the second case without that dependency’s contract.

### Zero count is not a general no-op

Take count zero, width one, and base address 4096.

The unsigned decrement produces \(2^{32}-1\). The resulting bound is 4095 after modular arithmetic. The initial address, 4096, is not less than 4095, so no insertion occurs.

In contrast, take count zero, width one, and base address zero. The bound becomes \(2^{32}-1\), so the outer traversal begins. Its first selected next-record address is one, and the comparator is initially called with addresses zero and one.

The second case demonstrates why zero count cannot be specified as an unconditional empty-range return.
