# F-71b688c6fe56

## Purpose

F-71b688c6fe56 repeatedly invokes a stateful dependency until either that dependency returns zero or a separate integer output becomes nonzero.

These conditions select different terminal paths:

- A zero dependency result selects a completion path: invoke a preparation dependency, perform an indirect operation on the supplied object, and return.
- A nonzero dependency result accompanied by a nonzero integer output selects an exceptional path: invoke an auxiliary dependency and then invoke a dependency represented as non-returning.

A nonzero dependency result accompanied by a zero integer output causes another iteration.

This control-flow description is established by the supplied static representation. Descriptions such as “iteration,” “completion,” and “exceptional” identify structural roles, not verified application semantics. In particular, the representation does not establish what is being traversed, what the integer output means, or whether the final indirect operation releases the object.

## Interface

### Input

The function accepts one pointer-like argument identifying an object or object-shaped memory region.

The function forwards that argument to F-794506715e88. On the completion path, it also uses the argument as the receiver of an indirect call.

For that indirect call, the represented layout is:

- The beginning of the supplied object contains a dispatch-base value.
- A callable address is obtained from the dispatch entry at byte offset 48 from that base.
- The original object pointer is passed as the sole explicit argument to the selected callable.

The offset is a byte offset, not an entry count. The representation does not establish the full size of the dispatch structure, its other entries, or the full layout of the object.

No explicit null check, object-type check, dispatch-table bounds check, or callable-address validation is visible.

### Result

No explicit return value is specified.

The function returns normally only through the completion path, after the indirect call returns. Its exceptional terminal dependency is represented as non-returning.

The supplied representation does not define any meaningful result-register value for callers.

### Local storage and widths

The function provides addressable local regions with these represented sizes:

| Role | Size | Use |
|---|---:|---|
| Stateful dependency storage | 4 bytes | Passed to initialization and every repeated dependency invocation |
| Opaque output storage | 4 bytes | Passed to every repeated dependency invocation |

The repeated dependency’s return value and the separately examined integer output are represented as 32-bit integers in the apparent target model. The control decisions depend only on zero versus nonzero, so signedness does not change the specified branch selection. Negative nonzero values are treated the same as positive nonzero values.

The supplied material is a recovered representation rather than a complete ABI declaration. Exact pointer width, stack alignment, calling convention, and original source-level types remain documented_only unknowns. The four-byte storage regions must not, by themselves, be taken as proof that their contents are pointers.

## Behavior

### Initialization

The function first invokes F-794506715e88 with:

1. The address of the four-byte stateful storage.
2. The supplied object pointer.

No explicit initialization of that storage is visible before this call. No separate initialization of the opaque output storage or integer output is visible.

The initialization dependency’s result is not used to select a path. If it returns normally, the function proceeds to the repeated operation.

The representation does not establish whether initialization reads or modifies the supplied object, retains any pointer, allocates resources, or establishes an ownership relationship.

### Repeated operation

The function invokes F-37f0845bb2ad with these arguments, in order:

1. The address of the same stateful storage used during initialization.
2. The address of the four-byte opaque output storage.
3. The address of the integer output storage.

At least one such invocation occurs if initialization returns normally. There is no preliminary integer-output check.

After each invocation returns, its result is tested first:

- If the result is zero, the function selects the completion path.
- If the result is nonzero, the function examines the integer output.

For a nonzero result:

- An integer output of zero causes another invocation.
- Any nonzero integer output ends repetition and selects the exceptional path.

The integer output is not consulted when the dependency result is zero. This ordering is significant: a zero result selects completion regardless of the integer output’s current contents, including any nonzero value left by an earlier invocation.

The opaque four-byte output is not directly inspected by F-71b688c6fe56. Its address is supplied again on subsequent iterations, but its contents do not directly determine this function’s branches.

The same local storage locations are reused across iterations. There is no visible reset of the stateful storage, opaque output, or integer output between calls. Consequently, the enclosing function does not ensure that the integer output is newly written on every invocation.

There is no visible retry bound, timeout, cancellation check, counter, or arithmetic on iteration state. If the dependency repeatedly returns nonzero while the examined integer output remains zero, repetition can continue indefinitely.

### Completion path

When F-37f0845bb2ad returns zero, the function performs these operations in order:

1. Invoke F-944b595e25e9 with the address of the 20-byte completion preparation storage.
2. Obtain the dispatch base from the supplied object.
3. Obtain the callable address at byte offset 48 from that dispatch base.
4. Invoke the selected callable with the supplied object pointer.
5. Return normally if that callable returns.

The dispatch resolution is represented after F-944b595e25e9 returns. The contract therefore does not treat the dispatch base as a value cached before that dependency call. Any relevant memory changes made by preceding dependencies can affect the dispatch resolution.

The completion preparation storage is distinct from the four-byte stateful storage. The visible argument does not establish that F-944b595e25e9 destroys or finalizes the stateful storage.

No explicit result from the preparation call or indirect call is used. If either fails to return normally, the subsequent operations are not reached.

### Exceptional path

When a repeated invocation returns nonzero and its integer output is also nonzero, the function:

1. Invokes F-unmapped-01, a document-local opaque identifier for the auxiliary dependency whose canonical opaque ID was not supplied.
2. If that invocation returns, invokes F-feee9156a257.

Neither call has explicit arguments in the supplied representation.

F-feee9156a257 is annotated as non-returning. No normal continuation after it is represented.

This path does not visibly invoke F-944b595e25e9 or the object’s indirect operation. The representation does not establish whether either exceptional-path dependency performs equivalent work internally.

## Acceptance examples

These are conditional static acceptance examples, not runtime test results. Each assumes valid memory, compatible calling conventions, and normal return from dependencies unless stated otherwise.

### Immediate completion

If the first repeated invocation returns zero, the required sequence is:

- Initialization.
- One repeated invocation.
- Completion preparation.
- Dispatch resolution and invocation.
- Normal return, if the indirect callable returns.

The integer output does not alter this selection.

### Continued repetition followed by completion

If two repeated invocations each return nonzero and leave the integer output zero, and a third returns zero:

- There are exactly three repeated invocations.
- The same storage addresses are supplied each time.
- Completion preparation occurs only after the third invocation.
- Neither exceptional-path dependency is invoked.

### Nonzero integer output

If a repeated invocation returns nonzero and leaves the integer output equal to negative one:

- Repetition stops.
- F-unmapped-01 is invoked.
- If it returns, F-feee9156a257 is invoked.
- The visible completion preparation and indirect call are not performed.

A positive nonzero integer output selects the same path.

### Zero result takes precedence

If a repeated invocation returns zero while the integer output contains a nonzero value, completion is selected. The integer output does not override the zero result.

### Reused integer output

If an invocation returns nonzero without writing the integer output, and that storage already contains a determinate value, the function examines that existing value. There is no visible reset.

If the value is indeterminate, the supplied representation does not establish a deterministic outcome.

### Dispatch mutation before completion

If F-944b595e25e9 changes the object’s dispatch base through some available mechanism and leaves a valid replacement, the later dispatch resolution uses the post-call object contents. The representation does not show an earlier cached dispatch target.

### Unbounded continuation

If every repeated invocation returns nonzero and the examined integer output remains zero, the function never reaches either terminal path through its own branch logic.
