# F-da1a289a3277

## Purpose

F-da1a289a3277 decrements a reference-count-like field in an object. A positive signed result ends processing. A zero or negative result initiates ordered processing of associated structures and resources, followed by global accounting updates and conditional backing-allocation handling.

“Reference count,” “cleanup,” and “allocator” are inferred roles. The established contract is the field access, call, arithmetic, and write behavior described below; dependency implementations and ownership contracts are unavailable.

The operation is not established as idempotent. Most processed fields are not cleared, and dependencies may invalidate storage. Repeating the call requires external lifetime and state guarantees.

## Interface

**Input:** One nullable object pointer.

**Output:** No explicit return value. Observable effects include memory writes, dependency calls, and a branch to a dependency identified as nonreturning.

The supplied representation uses four-byte object words and 32-bit pointer-bearing fields. Allocation metadata also includes unsigned 16-bit indices. Offsets below are byte offsets. Byte order, formal structure declarations, and alignment requirements are not independently established.

## Behavior

### Null handling and count transition

A null input returns without object accesses or dependency calls.

For nonnull input, the routine reads the count-like field at offset 0x1C and writes its value minus one back to that field. The positive-result decision uses the decremented value derived from that read. If the result is signed-positive, processing ends.

Zero and negative results both enter cleanup. An initially zero or negative count is not separately rejected.

The field and stored result are 32 bits. Ordinary nonoverflowing cases are established. The supplied representation does not settle source-language semantics for decrementing the minimum signed value; neither saturation nor an overflow exception is established.

### First linked structure

The first traversal starts from the object field at offset 0x10. Each nonnull node has these relevant fields:

- Offset 0x00: a 32-bit value retained for two dependency calls.
- Offset 0x20: the next pointer, retained before any calls for that node.
- Offset 0x24: a value read only after F-1cb585febd84 returns.

For each node, F-1cb585febd84 receives the retained offset-0x00 value. F-30162766ee7c then receives four arguments: the subsequently read offset-0x24 value plus 0x18, the retained offset-0x00 value, the result of F-1cb585febd84 plus one, and zero. F-732402c6dc47 then receives the current node pointer.

Traversal continues through the successor saved before those calls. A dependency’s change to the current node’s next field therefore does not replace that saved successor. Conversely, a change to offset 0x24 by F-1cb585febd84 can affect the following call.

Neither argument addition has a visible overflow check. The offset-0x24 value has no nonzero guard. The main object’s head is not explicitly cleared. Cycles have no termination safeguard.

### Second linked structure

The second traversal begins with the object field at offset 0x24. For each nonzero traversal address, the next pointer is read at node offset 0x04 before F-94cb53877c15 is invoked.

This call site shows **no explicit argument**. It does not establish that the current node is passed, freed, or otherwise owned by that dependency. The saved next pointer determines the following traversal step, including termination after the final invocation.

### Direct resource calls

After both traversals, the call order is:

1. F-a116356a135b with the main object.
2. F-94cb53877c15 with object offset 0x00.
3. F-94cb53877c15 with object offset 0x28.
4. F-6c7ac9769d41 with object offset 0x18.
5. F-841dc33ee157 with object offset 0x2C.

Each field argument is read at its own call site, after earlier calls return. These values are not captured together before F-a116356a135b. Earlier dependencies can therefore affect later arguments.

None of these calls has a caller-side nonzero guard.

### Conditional nested cleanup

A nonzero field at object offset 0x40 causes the routine to read the pointer at offset 0x4C, read a 32-bit value at offset 0x60 within that structure, and pass that value to F-b4822132d011.

After the dependency returns, object offset 0x40 is set to zero. The clear does not occur before the call and is not reached if the call does not return.

A zero indicator skips the nested access and call. A nonzero indicator does not trigger a separate check of the nested pointer.

### Optional array processing

A zero pointer at object offset 0x48 skips this phase entirely.

Otherwise, processing begins with a signed index of zero. Each iteration compares the index with the signed 32-bit bound currently read from offset 0x44. An admitted iteration reads the current pointer from offset 0x48, reads its four-byte entry at displacement four times the index, and passes that entry to F-94cb53877c15. The index then advances by one.

The bound and array pointer are reread for subsequent iterations. Dependency mutations can shorten, extend, or redirect processing; the initial nonzero pointer check does not freeze either field.

After the loop, F-94cb53877c15 receives the then-current field at offset 0x48. This final call occurs whenever the phase was entered, including when the initial bound was zero or negative. It may receive zero if a dependency has changed the pointer.

Individual entries have no nonzero guard. Neither the pointer nor the bound is explicitly cleared. Index arithmetic and address scaling have no visible overflow protection.

### Global accounting: acquisition and write order

Immediately after the resource phases, the routine reads the accounting-record global pointer and retains that value as the **captured destination base**.

Only then does the second null-input check occur. No visible assignment changes the input pointer between the first and second checks, so this is not an ordinary alternate exit for an invocation that began nonnull.

The allocation-related address is then recovered by subtracting the 32-bit displacement at object offset −0x04 from the object address. Call this the **recovered address**. The routine reads a 32-bit quantity, \(Q\), eight bytes before that address.

The accounting accesses that follow do **not** all use the captured destination base:

| Order | Established access |
|---|---|
| 1 | Reread the accounting global pointer and read its word at offset 0x38; retain this low-word value, \(L\). |
| 2 | Reread the accounting global pointer and retain the address at its offset 0x3C as the **high-word source address**. The high-word value is not yet read. |
| 3 | Reread the accounting global pointer to select the destination for the low-word write at offset 0x38. |
| 4 | Store \(L-Q\), reduced to 32 bits, at that low-word destination. |
| 5 | Read the high-word value, \(H\), through the previously retained high-word source address. |
| 6 | Store the adjusted high word at offset 0x3C of the **initially captured destination base**. |

Thus there are four distinct accounting-global-pointer acquisitions: the initial capture and three later reads. Their values are not established as identical.

The high-word adjustment is:

\[
H-\left(S+B\right)
\]

stored in 32 bits, where:

- \(B=1\) when the retained unsigned low value \(L\) is less than unsigned \(Q\), and otherwise \(B=0\).
- \(S\) is the arithmetic right shift by 31 of \(Q\) interpreted as signed. Its bit pattern is zero when the top bit of \(Q\) is clear and all ones when that bit is set.

The low-word write precedes the high-word **value read**, not merely the high-word write. If the low-word destination overlaps the retained high-word source, the high-word read can observe the preceding write. If the global pointer changes between acquisitions, sources and destinations can belong to different records.

Only under stable-global and noninterference conditions can this be described as subtraction of a sign-extended 32-bit quantity from one two-word counter. It is not generally unsigned 64-bit subtraction.

After both writes, F-2fd8826557a4 is called with no explicit arguments shown.

### Backing-allocation handling

After F-2fd8826557a4 returns, the routine obtains an allocator-state pointer by dereferencing a separate global pointer location. This captured allocator-state value is used for the remaining allocator operations; later dependency behavior is not assumed to preserve the global location.

If the recovered address equals the numeric value 8, the remaining allocator branch is skipped. This comparison occurs **after** the metadata read, accounting updates, F-2fd8826557a4, and allocator-state acquisition. It does not exempt earlier accesses from validity requirements.

Otherwise, the allocation header is located sixteen bytes before the recovered address.

Validation first reads the 32-bit header and tests for zero. If nonzero, another header read tests its least significant bit. A zero first read or an odd second read reaches F-a817d8d58c10, identified as nonreturning. Consequently, describing this as validation of one immutable header requires a stability assumption.

If validation permits continuation, F-c0fc6d033caa receives the captured allocator-state pointer. The subsequent accounting sequence is:

|---|---|
| 1 | Read the unsigned 16-bit index twelve bytes before the recovered address. |
| 2 | Reread the header and mask it with 0x3FFFFFFC; retain this quantity. |
| 3 | Subtract that quantity from the allocator word at offset \(0x224+4\times index\). |
| 4 | Subtract it from allocator offset 0x30C. |
| 5 | Read the unsigned 16-bit index ten bytes before the recovered address and subtract the same quantity from offset \(0xE0+4\times index\). |
| 6 | Subtract it from allocator offset 0x220. |
| 7 | Call F-09dcb55e8e0a with no explicit arguments shown. |
| 8 | Use its result to select offset \(0x310+4\times result\), and decrement that word. |
| 9 | Decrement allocator offset 0x390. |

The two metadata indices are zero-extended 16-bit values. No bounds check protects either indexed access or the index supplied by F-09dcb55e8e0a.

The first retained masked quantity is obtained after F-c0fc6d033caa, not during validation. The final masked quantity is read after F-09dcb55e8e0a. Neither dependency is assumed to preserve header contents.

Counter writes are 32 bits and have no visible underflow handling. Indexed counters may alias other accessed counters unless external layout constraints exclude that possibility; in that case, the stated access order remains significant.

## Side effects

Direct writes established by the representation are:

- The count-like decrement.
- The conditional clearing of object offset 0x40.
- The low- and high-word accounting writes, with independently selected sources and destinations.
- Allocator counter updates on the nonsentinel path.

The routine does not explicitly clear the linked-list heads, array pointer, array bound, or direct resource fields.

Dependencies may perform additional writes, release storage, transfer ownership, or fail. None of those effects is established merely by call position. In particular, no dependency may be assumed to release the main object while leaving later accesses valid.

There is no explicit rollback. Header failure can occur after resource processing and global accounting changes. The nonreturning failure branch is not evidence that those earlier effects are reversed.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests.

1. **Null input:** No object access, accounting-global acquisition, or dependency call occurs.

2. **Count initially two:** The field becomes one, and processing returns before any resource or accounting phase.

3. **Count initially one or zero:** One becomes zero and enters cleanup. Zero becomes negative one and also enters cleanup.

4. **First-node mutation:** If F-1cb585febd84 changes the current node’s offset-0x24 field while preserving its accessibility, F-30162766ee7c uses that changed field plus 0x18. Changing the current node’s successor does not replace the already saved successor.

5. **Second-chain termination:** For a final node whose offset-0x04 link is zero, that zero is read before one final no-explicit-argument invocation of F-94cb53877c15.

6. **Zero cleanup indicator:** This phase performs no nested offset-0x60 access and makes no F-b4822132d011 call.

7. **Negative array bound:** With an initially nonzero array pointer and a negative bound, no element is read. The final F-94cb53877c15 call still receives the then-current array pointer.

8. **Stable two-entry array:** With bound two and no relevant mutations, the calls receive entry zero, entry one, then the array pointer.

9. **Stable accounting record with borrow:** If all four accounting-global acquisitions identify the same stable record, \(L=3\), \(H=10\), and \(Q=5\), the low word becomes 0xFFFFFFFE and the high word becomes nine.

10. **Top-bit quantity:** Under the same stability conditions, \(L=0\), \(H=10\), and \(Q=0xFFFFFFFF\) produce low word one and high word ten. Sign extension and borrow cancel in the high adjustment.

11. **Distinct accounting pointer observations:** If the initial acquisition identifies one record and later acquisitions identify other records, the high destination remains in the initial record. The low source, retained high source, and low destination follow their respective later acquisitions; they must not be collapsed into the initial record.

12. **Low/high aliasing:** If the selected low destination overlaps the retained high source, the high value is read after the low write. A pre-write snapshot of both words is not equivalent.

13. **Invalid header:** A zero validation read, or a nonzero first read followed by an odd second read, reaches F-a817d8d58c10 before F-c0fc6d033caa. Earlier resource and global accounting effects have already occurred.
