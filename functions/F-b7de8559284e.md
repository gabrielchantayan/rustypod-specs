# F-b7de8559284e

## Purpose

F-b7de8559284e conditionally copies a 16-bit value, conditionally updates a special machine-state location and performs an indirect 16-bit write, then enters an unbounded dispatch loop.

The dispatch loop contains two indirect calls followed by software interrupt 0x5B. Continued iteration depends on both calls returning and execution resuming after the interrupt.

No application-level purpose is established. The supplied representation does not independently establish a valid executable function boundary or a conventional calling convention.

This contract distinguishes:

- **Established static evidence:** explicit operations and control relationships in the supplied representation.
- **Derived behavior:** algebraic consequences under the stated 32-bit arithmetic and literal-control-flow model.
- **documented_only:** unresolved architectural, dependency, and execution details.

No runtime tests have been performed.

## Behavior

### Copy selection

The initial copy occurs exactly when the control word’s low four bits are all zero, under the 32-bit model.

The selection comes from testing the control word multiplied by \(2^{28}\) for zero. Higher control bits are discarded by this multiplication and do not affect that test.

If any low control bit is set:

- No explicit prefix data-memory access occurs.
- The special-state assignment does not occur.
- The additional indirect update does not occur.
- Dispatch begins using the incoming link address as its base.

This describes explicit effects in the represented body, not instruction fetching or an external calling convention’s implicit accesses.

### Initial 16-bit copy

When the low four control bits are zero, the prefix performs:

1. An unsigned 16-bit read at the source address.
2. A 16-bit write of that value at the source address plus the offset word, with the destination address reduced modulo \(2^{32}\).

The displacement is in **bytes**, not 16-bit elements.

The source read precedes the destination write. No external call intervenes. If either access faults, later prefix effects are not reached through the represented normal control flow.

There is no requirement that source and destination be distinct. With a zero offset, the function still performs a read followed by a write to the same location. This can be observable even when ordinary memory retains the same value.

The prefix also derives an address:

\[
\text{adjusted address}
=
\text{source address}
+
\text{offset word}
-
\text{adjustment word}
\pmod {2^{32}}.
\]

This address participates in an equality test. No reachable prefix operation dereferences it merely because it was derived.

A nonzero incoming link address prevents the additional update but does not prevent the initial copy.

### Exact conditions for the additional-update branch

Under the stated model, the special-state assignment and additional indirect update are reached exactly when all these conditions hold:

- The control word’s low four bits are zero.
- The link address is zero.
- The stack anchor is zero.
- The offset word is either 0x00000000 or 0x80000000.
- The comparison word equals the offset word.
- The adjustment word equals the adjusted address defined above.
- The auxiliary word is zero.

These are derived reachability conditions, not validation checks with reported failures.

The adjustment condition can equivalently be expressed as:

\[
2 \times \text{adjustment word}
=
\text{source address}+\text{offset word}
\pmod {2^{32}}.
\]

Ordinary integer division by two is not equivalent to this modular condition. When solutions exist, values differing by 0x80000000 can both satisfy it.

The stack-anchor and offset restrictions follow jointly from two predicates. The earlier predicate requires the stack anchor shifted right by one to be zero, allowing only zero or one. The later predicate requires the stack anchor plus twice the offset word to be zero modulo \(2^{32}\). Twice a 32-bit value is even, so it cannot cancel a stack anchor of one. Thus the anchor must be zero, and the offset must be zero or 0x80000000.

The intervening carry predicates introduce no additional accepted cases: on this path the relevant earlier contributions are zero, and twice either permitted offset is zero at 32-bit width.

If any condition fails, the additional-update branch is skipped. The initial copy still occurs whenever its independent control-word condition holds.

### Ordered special-state assignment and indirect update

When the additional-update branch is reached, the observable ordering is:

1. The initial source read and destination write have already completed.
2. A special machine-state location is assigned the stack anchor multiplied by 64, interpreted under the stated width model.
3. Both represented unsigned 16-bit reads through the zero link address occur.
4. The additional indirect 16-bit write occurs after its address and value operands have been obtained.

The branch requires a zero stack anchor, so the special-state assignment writes a numerically zero value. The identity, width interpretation, and architectural consequences of that location remain **documented_only**.

The ordering of this assignment is significant. Under literal normal control flow, it occurs **before either read at address zero and before the indirect write**. If a later read or write faults, the assignment has already been performed in the represented sequence. This is an ordering guarantee of the model, not a guarantee about architectural fault rollback or externally visible commit behavior.

The indirect memory operation obtains two logical inputs from address zero:

- One unsigned 16-bit read supplies the destination address.
- Another unsigned 16-bit read supplies the arithmetic operand for the stored value.

The destination is the zero-extended address operand, so its numeric range is 0 through 65535.

The stored value is the arithmetic operand plus 15, reduced modulo \(2^{16}\). The unsigned 16-bit operand ranges from 0 to 65535; before narrowing, the sum ranges from 15 to 65550.

The representation does not establish the relative evaluation order of the two reads. They must not be collapsed into one read or assumed to produce equal values. For stable ordinary memory they have the same value; device-backed or concurrently modified memory may differ, subject to unresolved execution semantics.

The initial copy precedes both reads. If its destination is address zero, it can therefore affect the values consumed by this operation.

There is no null-address, alignment, range, or destination-object check. If address zero is inaccessible, the special-state assignment precedes the resulting read fault, assuming execution reaches and completes that assignment.

### Excluded later memory operations

The representation contains additional conditional pointer reads, record-like writes, signed 16-bit reads, and stores. They are unreachable under the stated model.

Outside the additional-update branch, the predicate enabling the next chain is false. Inside that branch, the already-established conditions make the relevant comparison address zero. A separate 16-bit-element address advances from zero to numeric address two. The next chain first accepts a zero comparison, then compares this address-two value against zero and produces a nonzero result. The remaining memory-effect branches consequently remain disabled.

These excluded operations do not establish a reachable record layout, serialization format, signed-load behavior, or ownership protocol for this contract.

The exclusion is conditional on the arithmetic model and faithful control-flow representation. It does not describe alternative entry points, omitted instructions, or other interpretations of the underlying executable.

### Dispatch loop

After the reachable conditional prefix, each normally progressing iteration has this order:

1. Invoke F-external-01 with three explicit arguments: 0, 0, and the 32-bit pattern 0xFFFFFFA5.
2. If it returns to the represented continuation, invoke F-external-02.
3. If that returns to the represented continuation, request F-external-03, software interrupt 0x5B.
4. If execution resumes past the interrupt, assign the fixed dispatch base 0x083D4CC2 and repeat.

The first F-external-01 target is:

\[
\text{incoming link address}+\text{0xEB6}
\pmod {2^{32}}.
\]

The displacement is 0xEB6 bytes because the represented target calculation advances by 0x75B elements of two bytes each.

The additional-update branch does not change this first-target formula: it requires a zero link address and leaves the relevant dispatch base zero.

Every later normally reached primary target is 0x083D5B78. F-external-02’s represented target is 0x0857A94B on each iteration.

The primary call’s third explicit argument is a bit pattern. Its signed 32-bit interpretation is −91, but the dependency’s parameter types are unknown.

The secondary call has no explicit arguments in the representation. This does not establish that incoming registers, stack contents, or shared state are irrelevant to it. Neither call’s return value is explicitly inspected.

## Side effects

### Reachable prefix effects

The maximum explicit prefix data-memory effects are:

- One 16-bit source read and one 16-bit destination write for the initial copy.
- Two represented 16-bit reads at address zero and one indirect 16-bit write for the additional update.

On the additional-update path, the special-state assignment occurs between the completed initial copy and both zero-address reads. All these prefix effects precede the first dependency call.

There is no visible allocation, release, ownership transfer, bounds check, rollback, or error-status write. Addresses are used directly. The additional destination is derived from a 16-bit memory value rather than a validated object reference.

### Failure ordering

A failed initial copy prevents the later special-state assignment through normal control flow.

A fault in either additional read or the indirect write occurs after the represented special-state assignment. The function contains no explicit restoration of that assignment or of the completed initial copy.

The exact persistence of effects across architectural faults remains **documented_only**. No transactional or all-or-nothing behavior is established.

## Acceptance examples

These examples are conditional static expectations, not observed executions. Each assumes the environment supports the operations needed to reach the stated point.

### Copy disabled

With low control bits equal to one, no explicit prefix data-memory access or special-state assignment occurs.

The first primary target is the incoming link address plus 0xEB6 modulo \(2^{32}\). If both calls return, interrupt 0x5B follows. Changing only higher control bits does not enable the copy.

### Byte displacement

With zero low control bits, source address 0x00001000, offset 6, a nonzero link address, and source value 0x1234:

- The function reads 0x1234 at 0x00001000.
- It writes 0x1234 at 0x00001006, not 0x0000100C.
- It skips the special-state assignment and additional update.

### Aliasing copy

With zero low control bits and zero offset, the source and destination addresses coincide. The read still precedes an actual write; the operation is not eliminated merely because ordinary stable memory retains its value.

### Additional update and state ordering

Suppose the low control bits are zero; link address, stack anchor, offset, comparison word, and auxiliary word are zero; the source address is 0x00002000; and the adjustment word is 0x00001000.

The modular adjustment equality holds. With stable value 0x0030 at address zero:

- The initial same-address copy at 0x00002000 completes.
- The special-state location is assigned zero.
- The two represented reads at address zero supply 0x0030.
- A 16-bit value 0x003F is written at address 0x00000030.
- The first primary target is 0x00000EB6.

### Fault after the state assignment

Use the preceding branch inputs, but make address zero unreadable while keeping the initial copy and special-state assignment executable.

The initial copy and special-state assignment precede the failing read. No completed additional write or dispatch call is implied. There is no represented rollback; architectural persistence remains unresolved.

### Narrowed addition

If both zero-address reads instead supply stable value 0xFFFF, the additional destination is 0x0000FFFF and the stored 16-bit value is 0x000E. Completion additionally requires that destination’s alignment and permissions be supported.

### Failed deep-path condition

With the successful additional-update inputs except for auxiliary word one, the initial copy still occurs, but neither the special-state assignment nor the additional memory operation occurs. The first primary target remains 0x00000EB6.

### Continued dispatch

If both calls return and interrupt 0x5B resumes normally, the next primary target is 0x083D5B78 with the same three explicit argument values. No fixed iteration count causes a normal exit.
