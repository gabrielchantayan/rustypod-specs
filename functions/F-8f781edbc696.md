# F-8f781edbc696

## Purpose

F-8f781edbc696 derives a signed candidate value from two fields of a caller-supplied object, conditionally changes status bits, and coordinates an update to another field through two dependencies.

The established behavior is an ordered state transition, not simply an assignment of the candidate to the destination field. One dependency can decide whether an update occurs; another is invoked after that update. Because either dependency may change accessible state, the function subsequently reads the destination field again and may perform a corrective write and set an additional status bit.

The names “candidate,” “threshold,” “destination,” and “status” below are descriptive labels for this contract. Their application-level meanings are not established. In particular, the evidence does not establish whether the values represent positions, sizes, bounds, counters, or another quantity.

## Behavior

### 1. Form one retained candidate

The function reads the signed 32-bit fields at offsets `0x4C` and `0x1C` and adds their values. The resulting candidate is retained for the remainder of the invocation.

The evidence establishes that both operand reads precede the subsequent comparisons and calls. It does not establish which of the two operand fields is read first.

Later changes to either operand field, including changes made by a dependency, do not cause the candidate to be recomputed.

The operands and retained result are represented as signed 32-bit integers. If the mathematical sum lies outside the range −2,147,483,648 through 2,147,483,647, the supplied representation does not establish a portable result. Neither wrapping, saturation, rejection, nor trapping should be promised without additional execution-model evidence.

All remaining arithmetic and comparison descriptions assume a defined candidate value.

### 2. Apply the threshold-related status change

The function reads the signed threshold at offset `0x18` and compares the candidate against it.

If the candidate is strictly less than the threshold, the function reads the current status word at offset `0x44` and writes a modified word with:

- Bit 20 cleared, corresponding to mask `0x00100000`.
- Bit 0 set, corresponding to mask `0x00000001`.
- Every other bit preserved from that status read.

Equality does not trigger this change. If the comparison is false, this stage performs no status-word access.

This modification occurs before the destination comparison and before either dependency can be invoked. A dependency reached later therefore runs after this write has occurred, although it may itself overwrite the status word.

### 3. Decide whether to write and notify

Next, the function reads the signed destination at offset `0x50` and compares the candidate against that value.

There are two decision paths:

- **Candidate strictly below the observed destination:** The function selects the write-and-notify action without calling F-900e57cefc4b.
- **Candidate equal to or above the observed destination:** The function calls F-900e57cefc4b with the original object argument and the integer argument `1`. A nonzero returned integer selects the write-and-notify action. Zero leaves that action unselected.

The dependency is therefore short-circuited when the candidate is below the destination. It is not an unconditional validation or preparation call.

Only zero versus nonzero matters for its returned value. Both positive and negative nonzero values select the same action.

When the write-and-notify action is selected, the function:

1. Writes the retained candidate to the signed destination at offset `0x50`.
2. Calls F-5ca9e0e7f0f2 with the original object argument, the integer argument `9`, and the retained candidate, in that argument order.

The destination write precedes this call. The candidate passed to the dependency is the originally computed value, not a fresh sum and not a value subsequently read from the object.

No return value from F-5ca9e0e7f0f2 is inspected.

When the action is not selected, this stage performs neither the destination write nor the call to F-5ca9e0e7f0f2. Any side effects already performed by F-900e57cefc4b still remain relevant.

### 4. Re-read the destination and conditionally raise it

After the decision stage and any selected notification have completed normally, the function reads offset `0x50` again. This is a fresh read, not reuse of the destination observed before the decision dependency.

If this newly observed signed destination is strictly less than the retained candidate, the function:

1. Writes the candidate to offset `0x50`.
2. Reads the then-current status word at offset `0x44`.
3. Writes that word with bit 1 set, corresponding to mask `0x00000002`, preserving all other bits from this later status read.

If the destination is equal to or greater than the candidate, this stage performs neither write.

This final stage is not another notification path: it does not call F-5ca9e0e7f0f2, even when it changes the destination.

The re-read is important on both dependency paths. F-900e57cefc4b may change the destination even when it returns zero; F-5ca9e0e7f0f2 may change it after the preceding candidate write. The function responds to the value actually observed afterward.

### 5. Complete without a reported result

After the final conditional stage, the function returns without an explicit value.

Subject to stable ordinary storage and normally returning dependencies, the final destination is at least the retained candidate under signed comparison. It need not equal the candidate: a destination greater than the candidate can remain unchanged.

This postcondition does not establish synchronization against concurrent writers or special behavior of memory-mapped storage.

## Side effects

**Direct writes** are confined to offsets `0x44` and `0x50` in the supplied body.

- Offset `0x44` can be written once during the threshold stage and once during the final correction stage.
- Offset `0x50` can be written before notification and again after notification if the destination is subsequently observed below the candidate.
- A selected write occurs even if it stores a value already present. In particular, an affirmative decision result can cause an equal destination to be written and then notified.

The two status modifications use separate reads at different times. They must not be collapsed into a single update based on the entry status value. If a dependency changes the status word, the final bit-1 update preserves that dependency-modified word except for setting bit 1.

There is no direct allocation, release, ownership transfer, or global-state access visible in this function body. This is a statement about direct operations only. It does not imply that either dependency avoids allocation, releases, global changes, or other external effects.

The function passes the object argument to both dependencies without visibly transferring or retaining ownership. Dependency ownership rules are unknown. If a dependency releases or invalidates the object and returns, the later object accesses have no established safe behavior.

No rollback, transaction boundary, explicit failure code, exception handler, or recovery action is visible. If a dependency does not return normally, subsequent operations described above are not established to occur.
