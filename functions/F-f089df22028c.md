# F-f089df22028c

## Purpose

F-f089df22028c interprets an integer encoding beginning at a supplied byte address and returns its numeric result. The leading byte selects either a one-byte calculation or a multi-byte, big-endian representation.

The function does not return a consumed-byte count, advance a caller-owned cursor, or distinguish successful decoding from insufficient trailing data. A supported multi-byte form whose length check fails returns zero. Several valid encodings also return zero.

**Established behavior:** byte-dependent selection, length checks for trailing bytes, integer calculations, and a single unsigned result.

**Inferred intent:** the function is a compact integer decoder. No format name, signed-result API, canonical-encoding requirement, or broader parsing policy is established.

## Interface

### Inputs

Two address values are supplied:

- **Start:** the address of the leading byte.
- **Limit:** the address against which the selected encoding’s end is compared.

The limit is used as an exclusive-end boundary: an encoding of total length three is accepted when the address three bytes beyond start is less than or equal to limit. Equality is sufficient.

The leading byte is read before any comparison with limit. Consequently, limit does not protect the first read. Calling with start equal to limit does not produce a reliably safe empty-input result; the leading-byte read must independently be valid.

The numeric results below use a **32-bit unsigned interpretation**, with values in the range 0 through 4,294,967,295. Negative mathematical results are represented modulo 4,294,967,296. For example, −108 is represented as 4,294,967,188.

### Unsigned 16-bit payload

A leading byte of 0x1C selects two following payload bytes.

When the three-byte boundary condition succeeds:

- The first payload byte supplies bits 15 through 8.
- The second supplies bits 7 through 0.
- Bits above bit 15 of the returned value are zero.

The result ranges from 0 through 65,535. A payload with its top bit set remains positive in the unsigned result; it is not sign-extended from 16 bits.

When the boundary condition fails, neither payload byte is read by this branch, and the result is zero.

### Unsigned 32-bit payload

A leading byte of 0x1D selects four following payload bytes.

When the five-byte boundary condition succeeds, their positional weights, in increasing address order, are:

- 16,777,216;
- 65,536;
- 256;
- 1.

Thus the payload is interpreted in big-endian order. Under the 32-bit model, all 32 result bits may be set, and the result ranges from 0 through 4,294,967,295.

A high first payload byte does not trigger a separate signed conversion. Any interpretation of the returned bit pattern as signed belongs to a caller and is not performed here.

When the boundary condition fails, no payload byte is read by this branch, and the result is zero.
