# F-d0468d561c19

## Purpose

F-d0468d561c19 is a conditional indirect-dispatch operation. It compares an integer field associated with its second argument against a global integer value. Only when those values are equal does it invoke an operation selected through its first argument.

A normally completed invocation returns:

- Zero when the comparison fails.
- Zero when the indirect operation returns zero.
- The indirect operation’s exact integer result when that result is nonzero.

The gate and result propagation are established by the supplied static representation. The meaning of the compared values, the identity of the selected operation, and any application-level interpretation of zero are not established.

## Interface

### Inputs

The function accepts two arguments:

1. **Receiver reference.** A pointer to an integer-sized storage location. When the comparison succeeds, the value stored at this location is used as the base address of a dispatch structure.
2. **Candidate address.** An integer-typed value used as an address. An integer field is read at a byte displacement of 4 from this address.

These names describe observable roles, not recovered application types. The evidence does not establish a class, a complete object layout, or an ownership model.

The indirect operation receives the original receiver reference and the original candidate-address value, in that order. It does not receive the dispatch-base value in place of the receiver reference.

### Output

The function returns an integer. It does not normalize every successful dispatch to one: any nonzero result from the indirect operation is propagated unchanged.

Consequently, a zero result does not distinguish between a failed comparison and an indirect operation that was called and returned zero.

### Widths and representation

The supplied representation uses an integer type for:

- The candidate-address argument.
- The field read at candidate-address offset 4.
- The global comparison value.
- The storage dereferenced through the receiver reference.
- The indirect operation’s result.
- The function’s result.

The representation is consistent with a 32-bit integer and address model, but it does not independently establish the target ABI or language data model. Under that interpretation, the candidate field is four bytes wide, and integer results retain their complete 32-bit value. Exact integer, pointer, and function-pointer widths remain **documented_only** until supported by target-type information.

The offsets 4 and 84 are byte displacements, not element indices. In particular, the dispatch location is 84 bytes from the loaded dispatch base. Its interpretation as a particular numbered table entry depends on an independently established function-pointer width.

### Preconditions

For normal completion:

- The candidate address must support the integer read at byte offset 4.
- The global comparison location must be readable.
- If the comparison succeeds, the receiver reference must support the initial integer-sized read.
- The value obtained from that read must identify storage from which a callable function pointer can be obtained at byte offset 84.
- The selected operation must accept the two supplied arguments and return a compatible integer result.

The wrapper contains no explicit null, alignment, range, lifetime, or dispatch-target validation. These are execution preconditions, not checked inputs.

The receiver reference need not be dereferenced by this wrapper when the comparison fails. This does not make an invalid candidate address acceptable: the candidate field participates in the gate regardless of whether dispatch will occur.

## Behavior

### Comparison gate

The function compares the integer at candidate-address offset 4 with a global integer value.

The comparison is equality, not ordering. Under a fixed-width integer interpretation, it compares complete integer values without masking or narrowing shown in the supplied representation.

If the values differ, the function returns zero without obtaining or invoking the indirect operation.

Both comparison operands must be evaluated before dispatch can be selected. The supplied expression does not establish an exact relative read order between the candidate field and the global value. A contract requiring one of those two reads to precede the other would exceed the evidence.

### Conditional dispatch

When the comparison succeeds, the wrapper obtains the indirect operation through two dependent accesses:

- It reads the integer-sized value stored at the receiver reference and treats that value as a dispatch base.
- It obtains a function pointer from byte offset 84 within the dispatch structure.

The dispatch-base read necessarily supplies the address needed for the function-pointer read. Both accesses belong only to the successful-comparison path.

The selected operation is then called once with the original two arguments. No retry, alternate target, or secondary dispatch is shown.

There is no independent recheck of the candidate field or global comparison value after the call. In particular, if the selected operation modifies either location, that does not trigger a second gate evaluation within this invocation.

### Result handling

After the selected operation returns normally:

- A zero result leads to a zero function result.
- A nonzero result is returned unchanged.

There is no sign restriction on propagated results. A negative nonzero result is not converted to zero or one.

Only one indirect call is shown. The subsequent nonzero decision uses the result of that call; it does not call the selected operation again.

### Arithmetic and address formation

The explicit address displacements are 4 bytes for the candidate field and 84 bytes for the dispatch location.

No bounds check, overflow check, or address-wrap recovery is shown. The evidence does not establish safe behavior when forming either displaced address exceeds a valid object or the target address range.

The function performs no visible arithmetic on the returned integer. Its result handling therefore does not introduce an additional arithmetic overflow condition.
