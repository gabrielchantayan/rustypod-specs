# F-22b82e19363e

## Purpose

F-22b82e19363e performs an ordered sequence of indirect calls, transforms primary and secondary call results, and then interleaves mixed-width stores with address-dependent reads. Its last represented operation is an unresolved indirect transfer receiving four explicit arguments.

The supplied static representation does not establish an application-level purpose. Character-valued constants, repeated offsets, and repeated stores do not establish string construction, object initialization, list management, or decoding.

This contract distinguishes:

- **Established static evidence:** accesses, transformations, and ordering represented in the supplied material.
- **[INFERENCE]:** conclusions conditional on an identified machine-model assumption.
- **documented_only:** unresolved behavior that must not be replaced with an invented guarantee.

The resulting contract is partial. It establishes important access and argument obligations, but unresolved dependencies and machine semantics prevent a claim of complete executable equivalence.

The represented interface has no explicit parameters and no explicit result. Its behavior nevertheless depends on:

## Behavior

### Ordered dependency calls

Before the first explicit data-memory store, the routine executes a long sequence of indirect calls. The first target depends on incoming machine context. Subsequent targets are formed from embedded address-like values or address-like references with a displacement of 0x0ffe.

The opening contains three calls before a fourth receives the preceding primary result shifted left by eight bits. Later calls receive varying combinations of:

- A primary result shifted left by eight bits.
- The separate low and high words of a paired result.
- Shifted or masked forms of either word.
- Earlier retained results.
- Secondary machine-result values.
- Explicit zero values.

Some calls have no explicit arguments; others have one through four. A discarded primary result does not make a call removable. No dependency is established to be pure, memory-preserving, or ownership-preserving.

The sequence is not one uniform repeated operation. Argument positions and transformations vary, including cases where the first argument is zero or a transformed high word rather than the usual shifted low word.

The complete call-by-call dependency trace is **documented_only** in this contract. The dependency labels below do not resolve individual targets.

### Arithmetic and retained values

The representation contains 32-bit left shifts, logical right shifts on unsigned values, multiplication by powers of two, masks of several widths, and extraction from represented 64-bit results.

These distinctions are required:

- Shifting the low 32-bit portion is not a shift of the entire paired result.
- Extracting the high word before a shift is distinct from shifting the full result.
- Intermediate narrowing can discard bits before a later right shift.
- Masking before shifting can change the result.
- Secondary results cannot be replaced with primary results.
- Explicitly zero-valued arguments do not eliminate the calls that receive them.

Some extractions shift the full unsigned paired result by 34, 36, or 44 bits before narrowing. These are not oversized shifts of a 32-bit operand.

**[INFERENCE]** Under modulo-2³² arithmetic, left-shifting a word by eight bits and then logically right-shifting the retained word by eight preserves only the original low 24 bits. Successive left shifts can erase all bits when their combined displacement reaches or exceeds 32 and truncation occurs between them.

Signed-looking shifts and multiplication also occur. Their overflow behavior is **documented_only**; unbounded mathematical arithmetic is not an established replacement.

### First explicit mutation boundary

The following names describe semantic roles, not source identifiers:

- **Packed base:** a retained call-result low word shifted left by 25 bits.
- **Scaled base:** a separate call result multiplied by 2²⁵.
- **Shifted word:** a retained primary result shifted left by eight bits.
- **Narrow index:** a shifted result masked with 0x7fff and logically shifted right by six.
- **Final pair:** the last represented paired result before explicit stores.

The first mutation boundary preserves these ordered relationships:

- A word containing Packed base is stored at Final pair high word + 0x14 before the first byte store at Packed base + 0x09.
- That byte store receives the low byte of Final pair’s high word.
- A word containing Scaled base is then stored at Final pair low word multiplied by 256, plus 0x54.
- A second byte store at Packed base + 0x09 receives the low byte of Packed base.
- A zero word is stored at Scaled base + 0x14 before reading the byte at Scaled base + 0x05.

The byte just read is retained across a zero word store at twice Narrow index + 0x14, then zero-extended into a word at Scaled base + 0x34.

The subsequent word reload from Scaled base + 0x14 is a fresh memory access. Another zero word store at twice Narrow index + 0x14 follows it. Two byte stores at twice Narrow index + 0x15 then receive the low byte of the retained reload.

The reload cannot unconditionally be replaced with zero: intervening stores may overlap its location.

### Dependent updates before publication

A byte read from fixed address 0x05 becomes an address base. Fixed address 0x01 receives the low byte of twice Narrow index.

The routine writes the low byte of Shifted word at Scaled base + 0x11, performs an intervening word store through the previously reloaded address-like value, and then clears Scaled base + 0x11.

A word read at the byte-derived base + 0x54 is saved before that location is overwritten. Call this saved word the **Retained root**. Later computations multiply Retained root by two, four, and eight. Its value is also stored at Retained root + 0x24 more than once.

Other required characteristics include:

- A word read at Scaled base + 0x74 supplies a later destination base.
- Two represented reads at twice Narrow index + 0x74 supply a destination and a stored value within one update. A stable shared result is not established.
- Fixed address 0x54 receives Retained root shifted left by one.
- The word at twice Narrow index + 0x14 is written repeatedly, with different intermediate values.
- Fixed address 0x15 receives the low byte of twice Narrow index.
- Reads at computed offsets 0x04, 0x05, 0x64, and 0x74 determine further destinations.

A byte at one computed offset 0x05 is read on separate occasions, with intervening writes. The later byte-derived word read at offset 0x74 is therefore not necessarily through the same address as an earlier one.

No evidence establishes valid heap objects, disjoint storage, or stable pointer-like contents.

### Constants and publication

For the publication region, define these retained roles:

- **Terminal link:** the word obtained through the later byte-derived offset-0x74 read.
- **Double base:** twice Terminal link.
- **Fourfold link:** four times Terminal link.
- **Adjusted origin:** four times Retained root, minus 0x96.
- **Work base:** four times Adjusted origin.
- **Publication base:** a word loaded from fixed-address storage.

These calculations retain the arithmetic uncertainties stated above.

The routine stores 0x3a as a byte at four times Terminal link, as a halfword at eight times Terminal link, and as a word at four times Terminal link + 0x20. These are distinct accesses, not equivalent constant assignments.

At Work base + 0x20, the successive word values are:

1. 0x20.
2. 0x2f.
3. The zero-extended byte freshly read from Work base + 0x04.
4. 0x20 again.

**The Publication base word is loaded before the word store of 0x20 at fixed address 0x60.** Publication therefore uses the retained load result. It is not defined by reloading the slot after the 0x60 store. Disjointness or independence of the storage is not an established optimization premise.

A long unrolled region then repeats a four-store publication group:

- A word at a scaled destination + 0x54 receives Fourfold link.
- A byte at Publication base + 0x19 receives the low byte of Work base.
- A byte at Work base + 0x11 receives the low byte of Publication base.
- A word at Publication base + 0x34 receives the scaled destination base.

The first group uses eight times Retained root as its scaled destination base. Subsequent groups use eight times Adjusted origin. The byte values and Publication base are retained values, not fresh loads within each group.

No destination cursor visibly advances. This is not established to be a bulk copy or traversal. The exact group count remains **documented_only** in this prose contract; collapsing the groups into one final-state update is unsupported for access-sensitive memory.

### Final memory phase: opening access order

After publication, the opening memory events have this specific order:

1. Read the word at fixed address 0xa9; retain it as the **Fixed word**.
2. Read the word at Fourfold link + 0x74; retain it as the **Saved link word**.
3. Store a byte at fixed address 0x3a, using the low-byte result of eight times Adjusted origin plus 0x30.
4. Read the word at Double base + 0x14; retain it as the **Saved state word**.
5. Read the word at Work base + 0x04; retain it as the **Saved field word**.

The 0x3a store intervenes between the offset-0x74 read and the offset-0x14 and offset-0x04 reads. Moving either later read before that store requires assumptions not supplied here.

The routine then performs byte updates at Double base + 0x0d and Work base + 0x08, +0x0d, and +0x09. The offset-0x08 byte receives 0x6c. A word at Double base + 0x54 receives Double base.

### Fixed address 0x67: publication and distinct reloads

The routine writes the low byte of Fixed word to fixed address 0x67. It then reads a word at Double base + 0x44. **Only after that computed word read does it freshly read the byte at 0x67 for the byte store at fixed address 0x21.**

Thus the 0x21 store is not unconditionally a copy of the saved low byte of Fixed word. The intervening word read can matter for access-sensitive memory, and stability is unresolved.

The word obtained at Double base + 0x44 also supplies a byte store at Work base + 0x10 and a word store at Publication base + 0x54. A byte store at Double base + 0x01 uses a signed-looking right shift of that word, with a count taken from Work base’s low eight bits. Counts can exceed 31; the resulting shift behavior remains **documented_only**.

Subsequently, Publication base + 0x54 receives Work base. A fresh word read at Work base + 0x40 supplies a word store at Work base + 0x10. Publication base + 0x74 receives Saved field word, and Publication base + 0x44 receives Double base.

There are then **two further, separate byte reads of fixed address 0x67**, each supplying a byte store at Work base + 0x09:

- The first precedes a byte store at Double base + 0x09 and a word store of Fixed word at Work base + 0x44.
- A word is then freshly read at Work base + 0x54.
- The second 0x67 read supplies another byte store at Work base + 0x09.

Neither read may be replaced unconditionally with the original saved byte or with the other read. The intervening accesses can overlap or have access-sensitive effects.

### Final updates and transfer

The word read at Work base + 0x54 becomes another destination base. Its offset 0x0d receives the low byte of Saved link word.

Double base + 0x54 receives Saved state word. A fresh word read at Work base + 0x14 is retained for a later byte store. Further byte and word stores affect Double base + 0x11 and Work base + 0x09 and +0x44.

A word loaded at Double base + 0x04 supplies a new address base. The routine stores the halfword 0x0065 at twice that base, then reads its offset 0x64 word. That retained offset-0x64 word supplies the second final argument.

Additional operations include a byte store using the earlier Work base + 0x14 result, a word store of 100 at a computed offset 0x54, a fresh read at the new base + 0x74, and a read at Double base + 0x64. The final word stores use these retained address-like values, including a store at twice the retained offset-0x64 word.

The final unresolved transfer receives, in order:

1. 0x72.
2. The retained word read at the new base + 0x64.
3. Saved state word, from the earlier Double base + 0x14 read.
4. The later word read at the new base + 0x74.

No explicit dependency calls intervene between the first explicit store and this final transfer.

## Acceptance examples

These are conditional static examples, not executed tests.

### Width and extension

If a byte store receives 0x123456ab, it writes 0xab. If the byte read at Scaled base + 0x05 is 0xe7, the associated word store receives 0x000000e7.

A halfword store of 0x0065 must remain a 16-bit access; replacing it with a byte store is not equivalent.

### Intermediate mutation and reload

If an intervening store overlaps Scaled base + 0x14, its later reload must use the memory state at reload time. The earlier zero store does not justify substituting zero.

### Publication load before 0x60

If the Publication base load yields one address and the subsequent 0x60 store changes what a later load would observe, publication still uses the originally retained address. Loading only after the 0x60 store does not satisfy the represented order.

### Intervening 0x3a store

If the byte store at 0x3a affects the later Saved state word or Saved field word read, those reads must observe their post-store state. Saved link word was read before the store.

### Fresh 0x67 values

Suppose the initial 0x67 store writes 0xab, but the intervening computed word read has an access-sensitive effect causing the subsequent 0x67 read to yield 0xcd. The 0x21 store receives 0xcd.

Likewise, if the two later 0x67 reads yield 0x11 and 0x22, their respective Work base + 0x09 stores receive those distinct values. Reusing 0xab or the first reload is unsupported.

### Arithmetic and completion

Under modulo-2³² arithmetic, shifting 0x12345678 left by eight and then logically right by eight yields 0x00345678.

If a required low address is inaccessible, graceful rejection is not specified. If execution reaches F-U003, omitting the transfer and reporting success is unsupported.
