# F-6b006275b56c

## Purpose

F-6b006275b56c converts an integer selector into a one-byte state value, writes that value at a fixed displacement from a caller-supplied base address, and returns whether the selector is nonzero.

The observable mapping is:

| Selector | Byte written | Boolean returned |
|---|---:|---|
| Zero | 1 | False |
| Exactly 2 | 7 | True |
| Any other nonzero value | 6 | True |

The Boolean result is not a success indicator. In particular, the zero-selector case performs a write and then returns false. All selectors select a write; there is no selector that requests a read-only operation or a no-op.

The meaning of the three stored values is not established. They may encode application states, but naming those states would require evidence beyond the supplied function.

## Interface

The function accepts two by-value arguments and returns a Boolean:

- **Base address carrier:** An integer-valued argument used to locate the destination. The destination is the address obtained by adding hexadecimal `0x74`, or 116 decimal, to this argument.
- **Selector:** An integer used only for equality comparisons against zero and two.
- **Result:** False if the selector is zero; true otherwise, provided execution reaches a normal return.

Both arguments are presented as `int` in the supplied representation. The working interpretation is a 32-bit signed integer representation. The exact machine ABI, pointer width, and rules for converting the first argument into an address are not independently established. The selector behavior does not depend on signed ordering: negative values, if supported by the actual argument representation, fall into the “other nonzero” case.

The destination access is explicitly one byte wide. It is not a word-sized assignment, and it does not require interpreting neighboring bytes as a larger integer. Endianness therefore does not change the byte value selected by this function.

For normal completion, the caller must supply an address carrier for which the destination calculation yields the intended address, and that address must permit a one-byte write. A conventional sufficient precondition is a writable object whose byte at offset 116 is accessible. The function itself does not establish an allocation boundary or verify that such an object exists.

No buffer length, object type, ownership token, or error-output argument is present.

## Behavior

### Selector mapping

The function distinguishes three cases using the selector’s full integer value:

1. A selector equal to zero selects byte value 1 and a false result.
2. A selector equal to two selects byte value 7 and a true result.
3. Every other nonzero selector selects byte value 6 and a true result.

This is an equality-based mapping, not a bit-field interpretation. It does not truncate the selector to one byte before deciding which value to store. A value whose low byte is two is not equivalent to the integer two unless the full argument value is also two.

There is no selector range rejection. Under the working 32-bit interpretation, the minimum signed value, maximum signed value, negative values, and positive values other than two all use the third case when they are nonzero.

### Destination layout

The only explicitly addressed storage is the byte at offset `0x74` from the supplied base. The offset is measured in bytes because the calculation adds the integer constant before treating the resulting address as a one-byte destination.

For an ordinary contiguous object, the selected location is its 117th byte when counting the base byte as the first byte. This describes the location, not a runtime size check.

The function does not consult a field containing a pointer, follow an indirect link, or obtain the destination from existing object contents. The base argument directly determines the destination address.

### Observable access order

On a normally completing invocation, the function:

- Determines the byte value from the selector.
- Performs one explicit one-byte write to the destination.
- Returns the Boolean result of the selector’s comparison with zero.

No explicit read of the destination precedes the write. Its previous value does not influence the selected byte or the returned result. The function does not explicitly read any neighboring field.

The store occurs even if the destination already contains the selected value. There is no comparison that suppresses a redundant store.

The return follows the write in the supplied representation. Consequently, false is not an indication that nothing was written. If execution cannot complete the write, the supplied representation does not establish a normal return.

The value 258 illustrates that the selector is not narrowed to its low byte before comparison. Although its low eight bits equal two, its full integer value does not.

Additional acceptance conditions:

- **Existing matching value:** If the destination already contains 7 and the selector is two, the function still performs the explicit store of 7 and returns true.
- **Existing unrelated value:** If the destination contains 255 and the selector is zero, it is overwritten with 1 and the result is false.
- **Repeated calls:** A call with selector two followed by a call with selector zero leaves the destination at 1. The first result is true and the second is false. The second call does not depend on the first stored value.

- **Signed extremes:** If selectors use the working 32-bit signed representation, both −2,147,483,648 and 2,147,483,647 select byte value 6 and return true.

Invalid or inaccessible destinations have no specified acceptance outcome here. In particular, the false result for selector zero must not be treated as an error return available when the write fails.
