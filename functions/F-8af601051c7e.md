# F-8af601051c7e

## Purpose

F-8af601051c7e initializes a caller-provided destination record using a source record and five dependencies. The visible destination layout spans 52 bytes.

The function samples a four-byte image-global value into the destination, establishes a backing-storage descriptor, copies two metadata words, initializes auxiliary state and a returned node, invokes an auxiliary operation, and finally copies a trailing metadata word. It returns the original destination address.

**Established static evidence:** the supplied body determines the explicit memory accesses, arithmetic, dependency arguments, and ordering described below.

**Inferred intent:** the operation resembles construction of an object containing contiguous storage and an auxiliary linked structure. The global-derived first word may serve as a type or dispatch value. These interpretations do not establish structure types, dependency semantics, or ownership.

The first destination word is **not established to be a constant**. It comes from a runtime read of an image-global location. Neither that location’s immutability nor a stable value across invocations is established.

## Behavior

### Initial global read and destination writes

Before any destination write and before any dependency call, the function reads one four-byte word from an image-global location.

It stores that sampled word at destination offset 0, then clears destination offsets 4, 8, and 12 in that order.

This sequence is a runtime read followed by a destination write; it is not established as assignment of an immutable marker. A change to the global before the read can change the value stored by this invocation. A later global change does not itself refresh destination offset 0: the body performs no second read of that global.

The destination has already been modified when the first dependency is called. There is no preliminary source validation or rollback preparation. Source/destination overlap can therefore affect later source reads.

### First count and capacity selection

The function calls F-cedf3cfba98d with the address of source offset 4.

Its returned word is interpreted as unsigned for capacity selection:

- Results from 0 through 31 select a capacity of 32.
- Results of 32 or greater select the returned value itself.

A result with its high bit set consequently selects a large unsigned capacity rather than being rejected as negative.

The selected capacity is retained for later use. The function shifts it left by two bits in a 32-bit unsigned representation and calls F-871e64ddc6de with that result and zero.

This request-size calculation is not widened or checked. Bits shifted beyond the 32-bit word are discarded. The nominal minimum request is 128 bytes for counts below 32, but large selected capacities can produce smaller request words, including zero, through truncation.

The returned word is stored at destination offset 4 without a visible validity or failure check.

### Range operation

### Second count and endpoint calculations

The second result determines the logical-end calculation. The function reads the current destination base/state word, adds four times the second result, and stores the result at destination offset 8.

It then reads the destination base/state word again, adds four times the capacity retained from the first query, and stores the result at destination offset 12.

Consequences established by the body:

- The two count results are separate observations.
- Their equality is neither required nor checked.
- The second result does not revise the selected capacity.
- The base is read after the second count call, so that dependency’s mutations can affect the calculation.
- The capacity calculation uses a fresh base read rather than an assumed copy of the allocation result.
- No comparison enforces that the logical end lies within the capacity end.

The second count is represented as signed 32-bit for its multiplication by four. Ordinary nonnegative values whose multiplication and subsequent signed addition remain representable have an unambiguous calculation. The body contains no check for a negative-looking result or signed overflow; behavior beyond those representable cases is **documented_only**.

The retained capacity is unsigned 32-bit. Its multiplication and capacity-end arithmetic use 32-bit unsigned word arithmetic, with high bits discarded. No overflow rejection is visible.
