# F-4ec500ac0e85

## Purpose

F-4ec500ac0e85 conditionally prepares an object-associated four-word record and passes it through a sequence of dependencies. Eligibility is controlled by a masked 32-bit object field and a separate byte. Additional processing requires a nonzero dependency result, a zero object byte, and a nonzero externally referenced byte.

The function returns a 64-bit value. Its meaning depends on the path taken:

- An ineligible object produces the incoming second argument in the upper half and a masked object-field value in the lower half.
- An eligible object with its processing byte clear produces the incoming second argument in the upper half and zero in the lower half.
- An eligible object with its processing byte set produces a value assembled from the first two words of a local record after any applicable dependency calls.

These return forms are established by the supplied static representation. A uniform interpretation as a status, pointer, or success indicator is not established.

## Behavior

### 1. Eligibility check and early return

The function first reads the 32-bit object field at offset `0x48` and masks it with `0x1800`.

Processing continues only when the masked value equals `0x0800`. Other bits in the field do not affect this comparison.

If the comparison fails, the function reads the field at offset `0x48` again. It returns:

- Upper word: the incoming upper word.
- Lower word: the second field read masked with `0x1800`.

The repeated read matters. The first read controls the branch; the second supplies the lower return word. The supplied representation does not establish atomicity, synchronization, or snapshot consistency between them.

On this path, the function does not explicitly read the processing byte at offset `0xBA` and invokes none of the listed dependencies.

### 2. Processing-byte check

If the eligibility comparison succeeds, the function reads the byte at offset `0xBA`.

If this byte is zero, it returns immediately with:

- Upper word: the incoming upper word.
- Lower word: zero.

No listed dependency is invoked on this path.

Any nonzero byte value enables the main path. No distinction is made among different nonzero values.

### 3. Optional preparation

The main path first invokes F-75c109def9d1 with the object address. Its result is treated as two 32-bit halves.

If the lower result word is zero:

- The function does not read storage through that word.
- It does not read the object field at offset `0xAC`.
- It does not invoke F-d5df03797d3d.
- The supplied third and fourth record words remain unchanged.

If the lower result word is nonzero, it is used as an address:

1. A 32-bit word is read at that address plus `4`.
2. The 32-bit object field at offset `0xAC` is read.

These reads occur in that order. The word at the returned address plus `4` is read even if the subsequent object-field read yields zero.

If both the lower result word and the field at offset `0xAC` are nonzero:

- The third record word is replaced with `0x80`.
- The fourth record word is replaced with `1`.
- F-d5df03797d3d is invoked with the field value from offset `0xAC` and the word read at the returned address plus `4`.

The replacements are selected before this call. Its result is not used by the enclosing function.

The upper half of F-75c109def9d1’s result does not influence a subsequent call argument or the final return in the supplied representation. In the only case that invokes F-d5df03797d3d, its second argument comes from the memory read, not from that upper half.

### 4. Record initialization and continuation decision

After optional preparation, the function initializes the four record words in layout order:

1. Object address.
2. Object address plus `0x80`.
3. Selected third word.
4. Selected fourth word.

It then invokes F-3fac671648b8. No explicit arguments are shown for this call. The record’s initialization before the call is established; a record-argument relationship is not.

The function proceeds to the later dependency sequence only if all three conditions hold, evaluated in order:

1. F-3fac671648b8 returns nonzero.
2. The object byte at offset `0xA0` is zero.
3. An externally referenced byte is nonzero.

Evaluation short-circuits:

- A zero result prevents the object-byte read and the external-byte read.
- A nonzero object byte prevents the external-byte read.
- No external-byte read is needed unless both earlier conditions permit it.

The external condition involves an external pointer/reference and the byte it designates. Its storage identity and ownership are not established.

- Upper word: record word at offset `0x04`.

That does **not** establish that the object or global state remains unchanged. Dependencies receive the object address, an interior object address, other address-like values, or the record address. Their memory effects are not supplied.

Observable ordering includes:

- A second eligibility-field read on the ineligible path.
- The processing-byte read before any dependency call.
- The returned-address-plus-`4` read before the offset-`0xAC` read.

No documented error result is established. Zero and nonzero dependency results control branches, but their broader error meanings remain unknown. Invalid accesses or dependency failures are not explicitly caught.

## Acceptance examples

These are conditional static acceptance cases, not runtime observations.

1. **Ineligible field, stable reads.**  
   Suppose both reads of the eligibility field yield `0x1000`, and the incoming upper word is `0x12345678`. The result is `0x1234567800001000`. No listed dependency is called.

3. **Other eligibility bits are irrelevant.**

   Suppose the eligibility field masks to `0x0800`, the byte at offset `0xBA` is zero, and the incoming upper word is `0x89ABCDEF`. The result is `0x89ABCDEF00000000`, with no dependency calls.
