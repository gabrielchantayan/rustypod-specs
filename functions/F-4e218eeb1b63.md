# F-4e218eeb1b63

## Purpose

F-4e218eeb1b63 performs an ordered sequence of memory reads and writes, followed by an unresolved indirect invocation. Its behavior depends on two explicit inputs, three implicit incoming values, values subsequently loaded from memory, and four fixed-address locations.

The established contract is an access sequence, not a final object state. Repeated writes, intermediate values, overlapping accesses, and the timing of reads can be observable. No higher-level purpose, object schema, or application domain is established.

This specification describes static evidence from the supplied representation. Whether that representation faithfully captures the original callable interface and final control transfer remains **documented_only**.

### Widths and arithmetic

Other address-bearing values are represented as signed 32-bit integers. Overflow in their additions or doubling is not assigned a portable wrapping rule by this contract. In particular, the doubled addresses derived from E and V below must not silently inherit the unsigned rule for base A.

## Behavior

The following phases describe the ordered memory-access contract. Captured values retain the values obtained at their specified reads; subsequent changes to their source locations do not refresh them.

### Prefix: fifteen complete repetitions and one fragment

The prefix contains **15 complete four-write repetitions**, followed by **one final two-write fragment**. Each complete repetition has this order:

| Position within repetition | Destination | Width | Value |
|---|---|---:|---|
| First | Base A + 0x11 | 8 bits | Low byte of base B |
| Second | Base B + 0x34 | 32 bits | Secondary input in repetition 1; twice base A in repetitions 2–15 |
| Third | Twice base A + 0x54 | 32 bits | Primary input |
| Fourth | Base B + 0x19 | 8 bits | Low byte of base A |

The final fragment performs only the first and second writes, in that order. Its second write stores twice base A.

Consequently, the prefix contains **62 write operations**:

| Destination expression | Number of writes | Value sequence |
|---|---:|---|
| Base A + 0x11 | 16 | Low byte of base B on every occurrence |
| Base B + 0x34 | 16 | Secondary input once, followed by twice base A 15 times |
| Twice base A + 0x54 | 15 | Primary input on every occurrence |
| Base B + 0x19 | 15 | Low byte of base A on every occurrence |

These are counts by destination expression. If expressions alias, one physical location may receive writes attributed to multiple rows.

No memory reads are visible in this prefix. Its values come from the incoming inputs and calculations on them, not from reloading the destinations. Collapsing the prefix to its final values would omit established access counts and ordering.

### Early snapshots and fixed-address update

Immediately after the fragment, the function captures a word from fixed address 0xA9, called the **fixed snapshot**, and then a word from primary input + 0x74, called the **primary-derived word**.

It next writes a byte at fixed address 0x3A. That byte is:

**(2 × low byte of base A + 0x30) modulo 256.**

This byte result does not require choosing whether the intermediate character representation is signed.

After that fixed-address write, the function captures a word from base C + 0x14, called the **saved C word**, and then a word from base A + 0x04, called the **saved A word**.

The following writes then occur in order:

| Destination | Width | Value |
|---|---:|---|
| Base C + 0x0D | 8 bits | Low byte of base A |
| Base A + 0x08 | 8 bits | 0x6C |
| Base A + 0x0D | 8 bits | Low byte of base B |
| Base A + 0x09 | 8 bits | Low byte of base B |
| Base C + 0x54 | 32 bits | Base C |
| Fixed address 0x67 | 8 bits | Low byte of the fixed snapshot |

The saved words are captured before these six writes. Aliasing can therefore make them differ from later contents at the same source addresses.

### Shift-derived update

The function reads a signed 32-bit word from base C + 0x44, called the **shift source**. It then reads the byte at fixed address 0x67 and writes that observed byte to fixed address 0x21.

The next writes, in order, are:

| Destination | Width | Value |
|---|---:|---|
| Base A + 0x10 | 8 bits | Low byte of the shift source |
| Base B + 0x54 | 32 bits | Shift source |
| Base C + 0x01 | 8 bits | Low byte of the right-shifted shift source |
| Base B + 0x54 | 32 bits | Base A |

The shift count is the low eight bits of base A, ranging from 0 through 255. The source has a signed 32-bit representation. Arithmetic right shift is suggested, but the exact rule for negative sources is **documented_only**. Counts from 32 through 255 also remain **documented_only**; no count masking, saturation, or zero-result behavior is established.

The two writes to base B + 0x54 remain distinct operations even though the later one ordinarily replaces the earlier word.

### Transfers into base-A and base-B storage

A word is next captured from base A + 0x40. The subsequent accesses have this order:

1. Write the saved A word to base B + 0x74.
2. Write the newly captured word to base A + 0x10.
3. Write base C as a word to base B + 0x44.
4. Read the byte at fixed address 0x67 and write the observed byte to base A + 0x09.
5. Write the low byte of base A to base C + 0x09.
6. Write the fixed snapshot as a word to base A + 0x44.

The word write at base A + 0x10 spans offsets 0x10 through 0x13. It therefore covers both the earlier byte at offset 0x10 and the prefix byte at offset 0x11. Their replacement byte values depend on target byte order.

The read at fixed address 0x67 is a new observation, not a contractual substitution of the fixed snapshot’s low byte.

### Loaded destinations and final updates

The function next reads a word from base A + 0x54. This captured address-bearing value is **destination D**.

Before using D for a store, it again reads fixed address 0x67 and writes the observed byte to base A + 0x09. Thus, this fixed-address read follows the read that establishes D.

The following transfers occur next, in order:

- The low byte of the primary-derived word is written to D + 0x0D.
- The saved C word is written as a word to base C + 0x54.
- A word is captured from base A + 0x14, called the **later A word**.
- The low byte of the primary-derived word is written to base C + 0x11.
- The low byte of D is written to base A + 0x09.
- D is written as a word to base A + 0x44.

A signed 32-bit address-bearing word is then read from base C + 0x04, called **base E**. The function writes the 16-bit value 0x0065 to the address obtained by doubling E. There is no additional object-relative offset on this doubled address.

After that halfword write, it reads a signed 32-bit word from E + 0x64, called **value V**. It then writes the low byte of the later A word to D + 0x11 and writes the 32-bit value 100, or 0x00000064, to D + 0x54.

The final captures and stores are ordered as follows:

| Order | Access |
|---|---|
| First | Read a word from E + 0x74, called the **dependency word**. |
| Second | Read an address-bearing word from base C + 0x64, called **destination H**. |
| Third | Write the low byte of E to base C + 0x09. |
| Fourth | Write V as a word to H + 0x54. |
| Fifth | Write H as a word to the address obtained by doubling V. |

The read of V follows the store through twice E. The reads establishing the dependency word and H follow both stores through D described immediately above. Aliasing must therefore be resolved using this timing, not entry-time contents.

## Side effects

### Aliasing and memory observability

No non-aliasing guarantee is established. Computed addresses can overlap other destinations, later read sources, or fixed-address storage. Even the four destination expressions in the prefix need not identify four disjoint regions.

The contract preserves distinct accesses without asserting that ordinary memory necessarily exposes every access to an external observer. Whether accesses are volatile, atomic, device-visible, or otherwise individually observable is **documented_only**.

In particular:

- The three reads of fixed address 0x67 occur at different points and must not be assumed to return identical bytes.
- The fixed snapshot is captured before subsequent fixed-address writes.
- D, E, V, the dependency word, and H reflect memory at their respective read points.
- Writes that appear to replace earlier values are still separate effects.
- Final byte layouts cannot be derived independently of byte order and aliasing.

## Acceptance examples

These are conditional expectations from static evidence, not runtime observations.

### Exact prefix trace

Assume the prefix completes and an observer distinguishes writes by destination expression.

The observer must record 62 writes: 15 complete four-write repetitions and a final two-write fragment. Base A + 0x11 receives 16 byte writes; base B + 0x34 receives 16 word writes; twice base A + 0x54 receives 15 word writes; base B + 0x19 receives 15 byte writes.

At base B + 0x34, the value sequence is the secondary input once, followed by twice base A 15 times. The final fragment does not write the primary input or the low byte of base A. A replacement that emits only 15 writes to base B + 0x34, or 16 writes to all four destinations, does not preserve this trace.

### Low-byte conversion

Assume the low byte of base A is 0xE0 and execution reaches the fixed-address update. The byte written at 0x3A is 0xF0, because twice 0xE0 plus 0x30 is 0x1F0.

### Overlapping byte and word writes

Assume no incidental aliasing or external mutation. The word captured from base A + 0x40 is written to base A + 0x10. The earlier bytes at offsets 0x10 and 0x11 are replaced by the corresponding bytes of that word. Their exact values require a specified byte order.

### Safe-range shift

Assume the low byte of base A is 4 and the captured shift source is positive 0x00000120. The shift-derived byte written to base C + 0x01 is 0x12.

This example makes no claim about negative sources or counts above 31.

### Fixed-address reads remain independent

Assume externally mutable storage at 0x67 returns different bytes at its three later reads. The byte written to 0x21 and the two corresponding writes to base A + 0x09 use their respective observed bytes, not a single cached byte. Other writes to base A + 0x09 still occur at their specified positions.

### Saved dependency argument

Assume execution reaches the indirect invocation. Its third argument is the early saved C word, even if base C + 0x14 has changed since that capture. Its fourth argument is the later dependency word captured from E + 0x74.

### Failure before invocation

Assume the store at H + 0x54 fails. No rollback is established for earlier writes. The subsequent store through twice V and the indirect invocation have not yet been reached in the represented sequence.
