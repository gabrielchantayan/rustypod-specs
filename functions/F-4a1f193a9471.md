# F-4a1f193a9471

## Purpose

F-4a1f193a9471 coordinates a guarded, two-stage operation over two nonzero handle-like values, an unsigned quantity, and a nonzero signed value. The first stage can replace both a signed working value and an unsigned working quantity. If that stage reports success by returning zero, the function halves the updated unsigned quantity, discards any remainder, and invokes the second stage. A closing dependency call follows either normal first-stage failure or normal second-stage completion.

This is an orchestration contract. The supplied evidence establishes argument flow, branching, temporary storage, and return propagation. It does not establish the application-level meaning of the values, the operations performed by the dependencies, or whether the opening and closing calls implement locking, reference management, or some other protocol.

| N | Unsigned quantity used to initialize an in/out working quantity; also passed unchanged by value to the first stage | No explicit restriction |

## Behavior

### Entry validation

The function rejects the call if any of A, B, or D is zero. A rejected call returns −50 and invokes none of the four dependencies.

N is not included in the rejection condition. In particular, N equal to zero is accepted when the other three arguments are nonzero.

Negative signed values are not rejected merely because they are negative. Subject to any requirements imposed by the dependencies, negative A, B, or D values take the same orchestration path as other nonzero values.

Validation performs scalar comparisons. There is no established dereference of A, B, or D in the wrapper, and no range, alignment, length, capacity, or object-state validation.

### Working state and opening operation

For a call that passes validation, the function creates two separate working cells:

- An unsigned quantity cell initialized to N.
- A signed value cell initialized to D.

These initializations occur before the opening dependency is called. The cells have distinct storage, and their addresses are subsequently supplied to the first stage. No aggregate structure, field offsets, padding requirements, or relative placement of the cells is established.

### First-stage operation

1. B.
2. The original N, passed by value.
3. The address of the signed working value.
4. The address of the unsigned working quantity.

The first-stage return value determines whether the second stage runs:

- **Zero:** The wrapper transforms the current unsigned working quantity and invokes the second stage.

### Quantity conversion and second-stage operation

After a zero first-stage result, the function reads the current unsigned working quantity and shifts it right by one bit. It stores that result back into the unsigned working cell.

For a 32-bit unsigned quantity Q, the transformation is:

**converted quantity = floor(Q / 2)**

Because the input is unsigned, this is a logical right shift, not a signed arithmetic shift. An odd quantity loses its low-order bit; the function does not round upward or report the discarded remainder.

The result ranges from 0 through 2,147,483,647 under the 32-bit interpretation. The conversion itself cannot overflow that unsigned range. No addition or multiplication participates in it.

Likewise, the converted quantity comes from the first stage’s resulting unsigned cell, not necessarily from the original N.

There is no post-first-stage validation before this call. A signed working value of zero or a converted quantity of zero is forwarded as-is. The second-stage return value becomes the result retained for return.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They are not reports of executed tests.

1. **Zero-gated rejection.**  
   If A is zero, the result is −50 and no dependency is invoked. The same outcome applies independently when B or D is zero, regardless of N.

2. **Zero quantity is accepted.**  
   With A, B, and D nonzero and N equal to zero, the opening and first-stage calls occur. If the first stage returns zero without changing either working cell, the second stage receives A, D, zero, and D.

3. **First-stage failure skips conversion and second-stage processing.**  
   If the first stage returns −7, the closing call occurs and the wrapper returns −7. Changes to either working cell do not cause the second stage to run.

4. **Positive first-stage result also skips the second stage.**  
   If the first stage returns 9, the closing call occurs and the result is 9. Zero alone selects the second-stage path.

5. **Updated values govern successful continuation.**  
   Suppose D is 80, and the first stage returns zero after setting the signed working value to 120 and the unsigned working quantity to 11. The second stage receives A, 120, 5, and 80, in that order. Its result is returned after the closing call.

6. **Original N remains the first-stage scalar input.**  
   If N is 20, the first stage receives 20 as its second argument and an unsigned cell initially containing 20 as its fourth argument. A change to that cell affects the later conversion, not the already-passed scalar argument.

7. **Odd quantities truncate.**  
   A successful first stage leaving the unsigned quantity at 1 causes the second stage to receive zero for its third argument. Leaving it at 3 causes that argument to be 1.

8. **Unsigned upper boundary.**  
   Under the 32-bit interpretation, a successful first stage leaving the unsigned quantity at 4,294,967,295 causes the second stage to receive 2,147,483,647. It does not receive a negative value from signed shifting.

9. **No repeated zero validation.**  
   If the first stage returns zero after replacing the signed working value with zero, the second stage is still invoked with zero as its second argument. Entry validation of D does not apply again to the updated working cell.

10. **Second-stage results propagate.**  
    If the second stage returns −50, the wrapper returns −50 after closing. Therefore, a returned −50 alone does not prove that entry validation rejected the call.
