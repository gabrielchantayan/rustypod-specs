# F-4e3673b4b1c8

## Purpose

F-4e3673b4b1c8 dispatches an integer request against a context object. Selected requests return fixed status values, copy and conditionally modify a 16-byte record, invoke context operations, produce a one-byte output, propagate object markers, or process candidate data.

Dispatch depends on repeated reads of five global values. Their numeric values and read-stability guarantees are unavailable. They are therefore identified as **B**, **T**, **L**, **K**, and **H**, not treated as immutable request constants.

**Evidence status:** This contract describes static evidence from the supplied representation. Dependency names are opaque identifiers, not semantic guarantees. No runtime tests have been performed.

## Behavior

### Dispatch reads and selection

The following order describes the visible global reads. Repeated occurrences denote distinct reads, not a captured constant.

1. Read **B** and compute an initial difference, **Request minus that B value**.
2. Read **B** again for equality with Request. Equality calls F-7d6ed32294de with Context and `1`, then returns zero.
3. Otherwise, read **B** again for the comparison determining whether to enter the lower branch.
4. In the lower branch, read **T** and compute a replacement difference, **Request minus that T value**, **before** testing equality or ordering against T.
5. Read **T** again for equality. Equality returns `0xFFFFFFFC`.
6. Otherwise, read **T** again for the lower-versus-upper subbranch comparison.

In the subbranch selected by Request being below the last-read T:

- Read **L** and test whether Request minus that value is zero. A zero result selects the record operation.
- Otherwise, read **L** again and read **K** to form the adjusted expression **(Request − L) + K**. The representation does not independently establish the relative evaluation order of these two global reads.
- An adjusted result of zero returns `0xFFFFFFFC`; `0x1822` returns zero; other results return `0xFFFFFFCE`.

In the other lower-branch subbranch, use the difference captured from the **first T read**, not a difference recomputed from either later T read:

- Difference `3` returns `0xFFFFFFFC`.
- Difference `4` returns zero.
- Otherwise, subtract `0x200` from that difference; a result of `3` returns zero.
- Other cases return `0xFFFFFFCE`.

The difference-`4` case does not depend on the later subtraction result being initialized: its return condition short-circuits.

If the B ordering comparison does **not** select the lower branch, retain the difference computed from the **initial B read**:

1. Read **H** for equality with that difference. Equality selects the two-call operation.
2. Otherwise, read **H** again for the threshold comparison.
3. If the newly read H is less than or equal to the captured difference:
   - Difference `0xE11` returns zero.
   - Difference `0xF10` selects the byte query.
   - Other values return `0xFFFFFFCE`.
4. Otherwise:
   - Difference `8` selects propagation and finalization.
   - Difference `0x801` returns zero.
   - Difference `0xE04` selects candidate processing.
   - Other values return `0xFFFFFFCE`.

**Conditional stable-value interpretation:** If each global remains stable throughout dispatch, arithmetic is defined for the operands, and comparisons have the represented signed interpretation, this simplifies to conventional request ranges around B and T. The lower difference `0x203` then satisfies the subtraction-based zero-return case. The operation at difference `0xF10` requires that difference to exceed H; the operations at differences `8` and `0xE04` require their differences to be below H.

Those simplified conditions are not unconditional guarantees. With changing global values, equality and ordering may use different boundaries, and a retained difference may no longer correspond to the boundary used by a later comparison. Even a path with no subsequent object access has already performed its applicable global reads and arithmetic.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Primary equality:** If Request equals the value from the second B read, F-7d6ed32294de receives Context and `1`, and the function returns zero. The initial B subtraction has already occurred.

2. **Changing dispatch boundaries:** Suppose defined arithmetic gives an initial B difference of `8`, later B reads reject equality and the lower branch, and both H reads yield `9`. Propagation is selected using the retained difference `8`, regardless of whether later B values would produce that difference.

3. **Masked record:** If the record operation is selected and F-98dadc910c53 returns nonzero, destination words zero and one become zero. If bytes `+8` and `+9` are both `0xFF` immediately after that call, their masked values become `0x38` and `0xFD`.

4. **Direct byte destination:** A byte-query result of `0xA5` writes `0xA5` at Arguments, not through the address stored there.

5. **Disabled propagation:** With flag `0x40` clear, indexed processing and enumeration are skipped. F-684e19c74234 still receives the subsequently read context `+0x40`.

6. **Marked peer:** An enumerated object other than Context with a nonzero marker has that marker cleared before F-1a4bd6c2e396 and F-df1f4510064d run, in that order.

7. **Empty candidate after preparation:** If F-1bcb8114d17f changes argument slot one to another readable address whose first 16-bit value is zero, the function checks that new address and returns zero. The slot’s pre-call value is not the checked address.

8. **Candidate-address replacement:** If comparison accepts an address from one slot-one read, but F-32d8393d25c1 subsequently replaces the slot with another valid address and returns a record, F-93583d17f15c receives the replacement address. No leading-zero check is repeated for it.

9. **No temporary record:** A zero F-32d8393d25c1 result skips record population and processing, but F-ceaf6045843e still runs; the return is zero.

10. **Saved direct result:** F-df1f4510064d runs after F-74b007a29cb7, and the latter’s saved 32-bit result is returned.
