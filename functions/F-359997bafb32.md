# F-359997bafb32

## Purpose

F-359997bafb32 conditionally refreshes a selected portion of caller-provided mutable storage from two input words. A cached copy of the requested pair controls whether any refresh occurs.

On a cache miss, the function:

- Stores the requested pair in the cache.
- Searches a shared collection for the first record with flag bit value 4 set.
- Optionally derives a replacement first value through dependencies.
- Publishes the effective pair to selected-region and top-level fields.
- Recomputes three-word records.
- Only when the full selector equals 1, recomputes seven-word records and conditionally adjusts their endpoints to a numerical grid.

The cache stores the original requested values, not the adjusted first value. An unchanged requested pair therefore suppresses recomputation even when shared records, transformation sources, or other relevant memory have changed.

These operations are established by the supplied static representation. Interpreting the values as coordinates, scaling factors, or fixed-point geometry is inferred intent, not an established interface guarantee.

Receiving an address does not establish ownership. Ownership, allocation provenance, and required storage lifetime are unknown.

### Integer and address model

All offsets below are byte offsets; each listed word is 32 bits.

The selected-region origin is the state address plus 392 times the signed 16-bit interpretation of the selector’s low 16 bits. The full selector is nevertheless used for the zero/nonzero tests and the exact comparison with 1.

Consequences include:

- Selector 65,536 has selected-region displacement zero but follows nonzero-selector behavior.
- A selector with a negative signed low-halfword produces a negative displacement.
- Selectors with identical low 16 bits can select the same region while taking different control-flow paths.

Explicit unsigned additions, negations, comparisons, and masks operate on 32-bit words. In particular, unsigned arithmetic wraps modulo \(2^{32}\).

The representation does not establish portable overflow behavior for signed arithmetic or address formation. Required ranges and target-specific behavior are **documented_only** where those operations can overflow.

## Behavior

### Cache comparison and early return

For a nonzero selector, the function reads the requested first value from input offset +8 before reading the cached first value. It then reads the requested second value from input offset +16.

For selector 0, it reads the cached first value before reading the requested first and second values from input offsets +4 and +12, respectively.

The cached second value is read only if the cached first value equals the captured requested first value.

When both cached words match, the function returns immediately. It performs no writes, invokes no dependencies, and reads none of the collection counts. Shared flags and record contents do not participate in cache invalidation.

On a cache miss, the function writes:

1. Requested second value to selected-region offset +424.
2. Requested first value to selected-region offset +420.

Both writes precede the shared-record search, dependency calls, and effective-pair publication. Later failure or interruption can therefore leave a matching cache with incomplete derived state.

### Shared-record search

The scan starts at unsigned index zero. Before inspecting each record, the current unsigned index is compared with the count read from state offset +640.

The count is reread for each comparison. It is not captured once at entry.

For each in-range record, the function reads its flags and tests bit value 4. The first record with that bit set stops the scan. Later records are not examined.

If the scan exhausts the current count without finding a match, the effective first value remains the captured requested first value.

The found-record address is also tested against zero before the adjustment call. Consequently, if address formation could produce a qualifying record address of zero, that match stops the scan but does not trigger adjustment. Whether such an address is valid or reachable under the intended address model is **documented_only**.

### Optional first-value adjustment

For a nonzero found-record address, F-74efb2674226 is called with:

- The shared record’s word at +12.
- A fresh read of input offset +8.

The relative evaluation order of those argument reads is not established.

The returned 32-bit word is treated as unsigned for grid formation: add 32 modulo \(2^{32}\), then clear the low six bits.

If the resulting grid candidate equals the original returned word, the requested first value is retained without another adjustment call.

Otherwise:

- **Selector 0:** compare the grid candidate and original return as signed 32-bit integers. Only if the candidate is smaller, call F-870c4fcf7295 with the captured requested first value and 50. Subtract that dependency’s result from the requested first value.
- **Nonzero selector:** call F-8f41f510c86c with the captured requested first value, grid candidate, and original returned word. Its result becomes the effective first value.

The second value remains the captured requested second value. It is not reread from the input after these calls.

No numerical interpretation, purity, memory-preservation guarantee, or failure convention is supplied for the dependencies.

### Effective-pair publication

The function performs these writes in order:

1. Captured second value to selected-region offset +40.
2. Effective first value to selected-region offset +36.
3. Effective first value to state offset +8 for selector 0, or +12 otherwise.
4. Captured second value to state offset +16 for selector 0, or +20 otherwise.

These are separate writes. If their addresses overlap other accessed fields, later operations observe the resulting memory contents; no disjointness enforcement is present.

### Three-word-record refresh

The function starts at unsigned index zero and compares the index against the count at selected-region offset +44 before each iteration.

For every entered iteration, it:

1. Reads the source word.
2. Calls F-74efb2674226 with that source and the effective first value.
3. Writes the returned word to the first destination.
4. Writes the same returned word to the second destination.

The count is reread at the next loop condition. Dependency side effects or overlapping writes can therefore affect subsequent traversal.

The effective first value passed to these calls is the captured or locally adjusted value, not a fresh read of the published field.

Unless the full selector equals 1, the function returns after this collection.

### Seven-word-record refresh

This stage occurs only for selector exactly 1. Its unsigned count, at selected-region offset +248, is checked before every iteration.

For each record, the function:

1. Reads the first source endpoint and calls F-74efb2674226 with it and the effective first value.
2. Adds the captured second value to the returned value.
3. Writes the sum to the first unadjusted result, then the first adjusted result.
4. Reads the second source endpoint and makes the corresponding dependency call.
5. Adds the captured second value to that return.
6. Writes the sum to the second unadjusted result, then the second adjusted result.
7. Reads the flags, clears bit 0, and writes them back.
8. Rereads both source endpoints and calls F-74efb2674226 with “first source minus second source” and the effective first value.

The relative read order of the endpoints within a subtraction expression is not established.

The final call qualifies the record for further adjustment if adding 48 to its returned word as unsigned 32-bit arithmetic produces a result less than 97. Equivalently, returned bit patterns with signed interpretations from −48 through +48 inclusive qualify.

Without qualification, there are no further explicit writes for that record. The adjusted results then retain their initially written values and bit 0 remains cleared, subject to aliasing and dependency effects.

### Qualifying-span adjustment

For a qualifying record, the source endpoints are reread. The function forms “second source minus first source,” retains the signed direction, and obtains a magnitude by conditional signed negation.

It calls F-74efb2674226 with that magnitude and the effective first value.

The returned word determines an unsigned span through signed threshold comparisons:

| Signed interpretation of return | Span before direction |
|---|---|
| Less than 32, including negative values | Zero |
| 32 through 63 | Subtract 16, clear the low five bits, then add 32 |
| At least 64 | Add 32, then clear the low six bits |

The arithmetic on this returned unsigned word wraps modulo \(2^{32}\).

Next, the function rereads the first unadjusted result, adds 32 with unsigned wraparound, and clears its low six bits. This becomes the adjusted first endpoint.

If the retained source difference was negative, the span is negated using unsigned arithmetic. The function then writes:

1. Adjusted first endpoint to the first adjusted-result field.
2. Adjusted first endpoint plus directed span, modulo \(2^{32}\), to the second adjusted-result field.
3. The currently read flags with bit 0 set.

The final flag update preserves other bits from that final read, not necessarily from the earlier clearing operation.

This adjustment does not explicitly rewrite the unadjusted-result fields.

## Side effects

The visible body reads and mutates addressed storage in place. It contains no explicit allocation, deallocation, ownership transfer, or returned memory object. This does not establish that dependencies avoid allocation or release.

Ownership and lifetime remain unknown for both state and input storage. Accessible storage is needed for each executed access; no stronger allocation or lifetime contract is established.

The update is not transactional:

- Cache writes precede adjustment and publication.
- Adjustment dependencies can observe already-updated cache storage.
- Three-word-record calls occur after effective-pair publication.
- Seven-word-record calls occur between progressive record writes.
- The magnitude-transform call occurs after flag bit 0 has been cleared.

Counts, later sources, flags, and the first unadjusted result are read at their described stages rather than snapshotted at entry. Dependency changes to this memory can affect subsequent behavior.

The visible body supplies no synchronization, null checks, bounds checks, selector validation, rollback, explicit error result, or dependency-failure recovery.

## Acceptance examples

These examples are conditional deductions from the static representation, not executed tests. Unless stated otherwise, assume valid accesses, representable signed arithmetic, normally returning dependencies, and no interfering memory changes.

1. **Cache hit.** If both cached words equal the selected requested pair, there are no writes, collection-count reads, or dependency calls. Changed shared flags alone do not force refresh.

2. **First cache word differs.** The cached second word is not read. The requested second word is written to the cache before the requested first word.

3. **Empty shared collection.** A zero shared count prevents shared-record inspection and the optional adjustment call. For selector 0, input offset +8 is not read by this stage; for nonzero selectors, it was already read as the requested first value.

4. **First qualifying record.** If records 1 and 3 have flag bit value 4 set and earlier records do not, record 1 ends the scan. Record 3 is not inspected.

5. **Selector-0 asymmetric correction.** A shared measurement of 65 produces grid candidate 64 and invokes F-870c4fcf7295. If the requested first value is 100 and that call returns 7, the effective first value is 93. A measurement of 96 produces candidate 128 and does not invoke that correction, because 128 is not signed-less-than 96.

6. **Nonzero correction.** A measurement of 96 invokes F-8f41f510c86c with the requested first value, 128, and 96. Its returned word becomes the effective first value.

7. **Selector narrowing.** Selector 65,536 selects displacement zero, reads requested values from input offsets +8 and +16, publishes to state offsets +12 and +20, and skips seven-word processing.

8. **Qualification boundaries.** Difference-transform returns −48 and +48 qualify. Returns −49 and +49 do not.

9. **Span boundaries.** For a qualifying record, magnitude-transform returns 31, 32, 47, 48, 63, 64, 95, and 96 produce spans 0, 32, 32, 64, 64, 64, 64, and 128 respectively.

10. **Direction and flags.** If the retained second-minus-first source difference is negative, the final adjusted second endpoint uses the negative directed span. Bit 0 is set after the adjusted endpoints are written.

11. **Mutable traversal count.** If a dependency reduces the three-word count to the next index, traversal stops at the next comparison. If it increases the count, additional records can be visited, provided their accesses are valid.
