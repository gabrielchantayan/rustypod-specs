# F-3909df3e135a

## Purpose

F-3909df3e135a coordinates range submission from a mutable context. It selects either a context-backed range or two bytes backed by the supplied argument, then uses a dependency-selected path to submit that range directly or through conversion. Successful processing updates context state and may reset buffer-position fields. A final dependency sequence supplies the completed-path return value.

The established contract covers explicit accesses, call order, branch conditions, arithmetic, and return propagation. It does not establish encoding, physical output delivery, transactionality, or the internal behavior of dependencies.

Buffered character output is inferred intent, not a requirement needed to describe the observed operations.

## Behavior

### Entry writes and initial gate

The first observable context operations are writes of zero to `+0x14`, `+0x18`, and `+0x1c`, in that order.

The function then reads the flag word at `+0x04`. If bit `0x08` is clear, it immediately returns `0xffffffff`. Thus rejection does not prevent the three entry writes.

Otherwise, it saves the supplied argument in its four-byte argument copy and calls F-5e4b6883dabd with the context address. The represented result is 64 bits; continuation depends only on whether its low 32 bits are nonzero. A zero low word causes immediate return of `0xffffffff`, regardless of the upper word.

The upper result word does not independently affect a subsequent decision. Where that carried value could otherwise be consulted, a fresh masked flag read replaces it.

### Source selection and eligibility

After initial preparation succeeds, the function reads bit `0x04` at `+0x10`.

If clear, the selected source start is read from `+0x08`, followed by the selected end from `+0x24`.

If set, the argument is copied into the separate four-byte source object. The selected range begins at that object and ends two bytes later. Only its first two bytes are selected. No byte-order conversion is visible; identifying those bytes with the argument’s numeric low 16 bits requires an additional byte-order assumption.

The function separately reads `+0x24` for the eligibility decision, even in argument-backed mode. This is a distinct read from the buffered source-end read.

Output preparation is eligible when either:

- That separately read value is nonzero; or
- It is zero and a fresh read of bit `0x04` at `+0x10` is set.

When neither condition holds, output preparation is skipped and buffer reset follows.

When output preparation is eligible, the saved eligibility value is compared with a read of `+0x28`. If unequal, F-078279ab0f90 is called with the context and full 32-bit argument.

A nonzero result permits processing to continue. A zero result causes a fresh read of bit `0x04` at `+0x10`:

- Set: processing continues.
- Clear: execution goes directly to final processing, bypassing both output processing and buffer reset.

The selected source addresses are not reloaded after this dependency call. A dependency’s changes to context fields do not, by themselves, replace the saved source range.

### State and position preparation

Once output preparation continues, the function copies the four-byte value at `+0x38` into temporary state and initializes the accumulated count to zero.

It then reads bit `0x01` at `+0x04`. If set, it calls:

1. F-5eb783ea358d with the eight-byte temporary area, the context, zero, and two.
2. F-dd25b8fb230c with destination `context + 0x34` and the eight-byte area as source.

Whether or not this optional sequence runs, F-dd25b8fb230c is then called with destination `context + 0x3c` and source `context + 0x34`.

No result from these calls is checked.

Next, F-74370bf369b4 receives `context + 0x2c`; its four-byte result becomes temporary conversion-context state. F-8a48b87c52f3 is then called without explicit arguments. Its zero/nonzero result selects converted or direct submission respectively.

The state copied from `+0x38` and the result obtained from F-74370bf369b4 are separate temporary objects with different roles.

### Converted submission

A zero result from F-8a48b87c52f3 selects conversion.

The function initializes the output-end value to zero, then the next-input address to zero. Neither is explicitly reset at the start of subsequent iterations.

The loop continues while the current next-input address differs from the selected source end. Each iteration has the following observable sequence:

1. F-605d034d51cf receives the current conversion-context value, the address of the temporary state copied from `+0x38`, the current source start, the selected source end, the next-input address’s storage address, the scratch-area address, the conversion-context storage address, and the output-end storage address.
2. If its result is exactly `2`, the function immediately returns `0xffffffff`.
3. Otherwise, the function reads output-end and subtracts the scratch-area address to obtain the count for this submission.
4. F-b734379b089d receives `context + 0x30`, the scratch-area address, unit size `1`, and that computed count.
5. If its result is zero, the function immediately returns `0xffffffff`.
6. After a nonzero result, the function reads output-end again and recomputes output-end minus the scratch-area address. This newly computed difference—not a saved copy of the submitted count—is added to the accumulated count.
7. The current source start is replaced with the then-current next-input address. The loop condition subsequently examines that next-input address against the selected end.

The two output-end reads are significant. F-605d034d51cf receives the output-end storage address. Unknown pointer retention or shared-state behavior could allow F-b734379b089d to affect that storage indirectly. Consequently, the count accumulated after a successful submission is not guaranteed to equal the count supplied to that submission.

Only conversion result `2` is rejected. Every other result proceeds to submission. Only a zero submission result is rejected; no comparison with the requested count is performed.

The initial loop condition compares a zero next-input address with the selected end, not the selected start with the selected end. Therefore:

- A zero selected end skips all conversion calls.
- Equal, nonzero selected start and end addresses do not prevent the first conversion call.

No explicit check establishes conversion progress, scratch bounds, output-end validity, or next-input membership in the selected range. Termination and safe use of the returned values depend on dependency behavior.

### Direct submission

A nonzero result from F-8a48b87c52f3 selects direct submission.

The function forms a signed 32-bit difference between the selected end and start addresses and shifts it right arithmetically by one. That result is both the accumulated count and the count passed to F-b734379b089d.

The submission arguments are `context + 0x30`, the selected source start, unit size `2`, and the computed count.

A zero result causes immediate return of `0xffffffff`; any nonzero result permits continuation. The returned value is not compared with the requested count.

For an ordinary representable, nonnegative even byte distance, the count is half that distance. Odd, negative, or overflowing differences receive no explicit validation. On this path the accumulated count is in two-byte units, rather than the byte-count differences accumulated on the converted path.

### Successful-path updates and buffer reset

After the selected output path completes without an explicit rejection, the function:

1. Reads the current four-byte word at `+0x34`, adds the accumulated count, and writes the result there.
2. Writes the temporary state originating from `+0x38` back to `+0x38`.
3. Freshly reads bit `0x04` at `+0x10`.

The `+0x34` increment uses a current field read, not a value saved before dependency calls. The state written to `+0x38` may have been modified through its temporary address during conversion or other indirect dependency activity.

If the freshly read bit is set, buffer reset is skipped. Otherwise, reset occurs. Reset is also reached directly when output preparation was skipped because the eligibility read of `+0x24` was zero and the subsequent mode-bit read was clear.

Reset performs these operations in order:

- Read the current base from `+0x08`.
- Write that base to `+0x24`.
- Write that base to `+0x20`.
- Read `+0x0c` and write base plus twice that value to `+0x28`.

These reset-time reads need not match values observed before intervening dependency calls.

### Final processing and return

Final processing calls F-078279ab0f90 with the context and full 32-bit argument.

If its result is zero, the function freshly reads bit `0x04` at `+0x10`. If that bit is also clear, F-61bf46f10b7c receives the context and the argument numerically masked with `0xffff`.

Next, F-7019e9c6c658 receives the context and `1`, regardless of whether that conditional call occurred. Neither dependency’s result is checked.

Finally, F-81441094a638 receives the address of the four-byte argument copy. Its 32-bit result is returned unchanged.

The explicit early-return paths bypass this entire final sequence.

## Side effects

The wrapper provides no established transactional guarantee. It performs no explicit rollback after conversion or submission failure. Dependency implementations could buffer, reverse, defer, or otherwise alter earlier submissions; persistence of submitted output is not established.

The entry writes occur before any rejection. Position-preparation dependencies and submission dependencies may also have effects before a later failure. An explicit failure does not visibly trigger buffer reset, successful-path state updates, or final processing.

On converted-path failure, earlier submission calls may already have returned nonzero. The wrapper does not then issue an explicit rollback, and it does not perform its accumulated-count increment at `+0x34` or its final state write to `+0x38`. This does not imply those fields remained unchanged: dependencies may have modified the context themselves.

The relevant arithmetic uses 32-bit values in the supplied representation: address differences, accumulated-count additions, the `+0x34` increment, and base plus twice capacity. There are no explicit overflow, sign, alignment, or range checks. Portable behavior for invalid addresses or overflowing signed arithmetic is not established.

## Acceptance examples

These are conditional expectations from static evidence, not executed tests.

1. **Initial rejection.** With valid writable context storage and initial bit `0x08` clear, the three entry fields are cleared in order. The result is `0xffffffff`, with no dependency called.

2. **Low-word gate.** If F-5e4b6883dabd returns a zero low word and a nonzero upper word, the function still returns `0xffffffff` before source selection.

3. **Skipped buffered processing.** If the eligibility read of `+0x24` is zero and the subsequent mode-bit read is clear, output preparation is skipped. Reset precedes final processing.

4. **Pre-output diversion.** If eligibility permits processing, `+0x24` differs from `+0x28`, and the conditional F-078279ab0f90 returns zero followed by a clear mode bit, output and reset are skipped. Final processing calls F-078279ab0f90 again.

5. **Direct count.** For a valid eight-byte range with representable subtraction and direct mode selected, submission receives unit size `2` and count `4`. On success, the explicit increment at `+0x34` is `4`, not `8`.

6. **Conversion rejection.** If F-605d034d51cf returns exactly `2`, that iteration has no subsequent submission call. The wrapper returns `0xffffffff` without successful-path updates or final processing.

7. **Later submission failure.** If one converted submission succeeds and a later one returns zero, the wrapper returns immediately without issuing explicit rollback or committing its accumulated count. Whether earlier submissions remain externally effective is unknown.

8. **Different submitted and accumulated counts.** Suppose output-end initially denotes scratch base plus `6`. Submission receives count `6`. If indirect dependency activity changes output-end to scratch base plus `10` before that successful call returns, the subsequent accumulated increment is `10`, assuming representable arithmetic.

9. **Loop entry boundary.** A zero selected end skips conversion. A nonzero selected end equal to the initial selected start still causes a first conversion call, because next-input was initialized to zero.

10. **Argument-backed input.** Selecting argument-backed mode exposes the first two bytes of a separate four-byte argument copy. This is distinct from the numeric `0xffff` mask used for the conditional final operation.

11. **Final return propagation.** If F-81441094a638 returns any particular 32-bit value, including `0xffffffff`, that value is returned unchanged.
