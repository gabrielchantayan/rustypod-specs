# F-f6afb94a2031

## Purpose

F-f6afb94a2031 performs two ordered collection-processing phases, then conditionally releases or updates a synchronization-like object.

The first phase dispatches one of two indirect operations on every item admitted by an iteration dependency. A 32-bit mode argument selects the operation. A one-byte global marker is set during this phase and cleared before the second phase.

The second phase processes a separate collection through F-2318d06eb0b2 and then passes that collection to F-42e20851b8e3, provided its initial 32-bit field at offset 20 is nonzero.

Finally, the function examines a previously captured object pointer, optionally invokes F-621dae46a146, compares a stored owner value with a value returned by F-196812b4b122, and may update a 16-bit counter and invoke F-259d2fe281b0.

These operations are established by static evidence. Descriptions such as “collection,” “owner,” “counter,” and “synchronization-like” identify structural roles; their application-level meanings are not established.

## Interface

### Arguments

The visible interface accepts four arguments:

1. **Mode:** a 32-bit integer. Zero selects indirect operation slot 0; every nonzero value selects slot 1. No further distinction among nonzero values is visible.
2. **Initial cursor value:** a pointer-sized, 32-bit value initially copied into local cursor storage. Before collection traversal, this value is unconditionally replaced by the first cursor obtained from the primary collection. No visible later behavior uses its original value.
3. **Initial predecessor value:** a pointer-sized, 32-bit value copied into separate local storage. It survives unless a traversal iteration overwrites it. It can therefore reach F-621dae46a146 if neither traversal executes an iteration.
4. **Initial boundary value:** an opaque 32-bit value initially copied into local boundary storage. The first iteration-predicate call is always preceded by replacement of this storage with the primary collection’s head-reference value. Its original value does not reach the later visible calls.

The source describes cursor and predecessor values as pointers to 32-bit words. This establishes access widths and offsets, not a complete public structure definition.

### Return value

The visible return is 64 bits. Its low and high 32-bit halves have branch-specific meanings:

| Condition | High 32 bits | Low 32 bits |
|---|---:|---:|
| Captured synchronization-like pointer is null | Final cursor value | 26 |
| F-621dae46a146 returns a value with a nonzero low half | Dependency-provided | Dependency-provided |
| Stored owner differs from the identity returned by F-196812b4b122 | Stored owner | 5 |
| Owner matches, counter category is selected, and the decremented counter is nonzero | Stored owner | 0 |
| Release dependency is invoked | Supplied by F-259d2fe281b0 | Supplied by F-259d2fe281b0 |

The function does not establish a uniform interpretation of the high half. In particular, it is not consistently an error payload, pointer, or owner identifier.

### Required memory layouts

All offsets below are byte offsets.

- **Collection object**
  - Offset 16: a 32-bit pointer to a head-reference object.
  - Offset 20: a 32-bit field tested only for the secondary collection.
- **Head-reference object**
  - Offset 0: a 32-bit initial cursor value.
- **Node admitted for processing**
  - Offset 0: a 32-bit next-cursor value.
  - Offset 8: a 32-bit payload/object pointer.
- **Primary payload/object**
  - Offset 0: a 32-bit pointer to an operation table.
  - Operation-table offset 0: first callable entry.
  - Operation-table offset 4: second callable entry.
- **Synchronization-like object**
  - Offset 0: a 32-bit discriminator.
  - Offset 4: a 32-bit owner value.
  - Offset 14: a 16-bit unsigned attribute field.
  - Offset 18: a 16-bit counter.
  - Offset 20: start of the subobject passed to F-259d2fe281b0.

Correctly accessible objects and callable table entries are preconditions. No general pointer validation is visible.

## Behavior

### 1. Capture and initialization

The function captures the current global synchronization-like pointer before calling an entry-time dependency whose opaque function ID is unavailable in the supplied mapping.

The entry-time dependency is called without explicit arguments. Its effects and return contract are unknown; its return is not explicitly tested.

After that call, the function captures the address of a global one-byte marker and writes the value 1 through it. It then captures the primary collection object address and obtains the initial cursor by:

- Reading the collection’s 32-bit field at offset 16.
- Treating that value as a pointer.
- Reading the first 32-bit word at that address.

This initial dereference occurs even if the primary collection will admit no items.

The synchronization-like pointer captured before the entry-time dependency is the pointer used during final processing. A later change to the global pointer does not replace that captured value.

### 2. Primary collection processing

The mode determines which operation-table slot is selected for all primary iterations:

- Mode zero: table offset 0.
- Mode nonzero: table offset 4.

Before every iteration-predicate call, including the call that terminates traversal, the function reloads the head-reference value from offset 16 of the captured primary collection object into local boundary storage.

F-0cb86028f147 receives the addresses of the local cursor and boundary storage. Its result is tested against zero:

- Zero ends primary traversal.
- Nonzero permits processing of the current cursor.

Because the dependency receives addresses rather than copies, the cursor and boundary used afterward may be values that the dependency has changed. The contract does not assume this dependency is a pure comparison.

For each admitted cursor, the function reads the object pointer at node offset 8, follows that object’s first word to its operation table, and invokes the mode-selected entry. The visible call expression supplies no explicit arguments. Any implicit receiver, calling-convention requirements, or operation signature are not established.

After the indirect call returns, the current cursor is copied into predecessor storage. The next cursor is then read from offset 0 of the current node.

Consequently, the next-link read occurs **after** the item operation. If that operation changes the current node’s next link, subsequent traversal observes the changed link. There is no visible snapshot of the next link before dispatch.

The function does not independently validate node type, detect cycles, enforce an item count, or establish a termination bound.

### 3. Marker clearing

When the primary predicate returns zero, the function writes 0 through the previously captured marker address.

This write occurs before testing or processing the secondary collection. The function does not restore the marker’s previous value; it explicitly writes 1 and then 0.

No cleanup path is visible for an indirect call or dependency that does not return normally.

### 4. Secondary collection processing

The function obtains the secondary collection object and tests its 32-bit field at offset 20.

If that field is zero, it skips both secondary traversal and F-42e20851b8e3. The cursor, predecessor, and boundary storage retain the values left by primary processing.

If the field is nonzero, the function obtains a fresh secondary initial cursor using the same two-read head-reference layout as the primary collection.

Secondary traversal uses F-0cb86028f147 with addresses of the same cursor and boundary storage. Before each predicate call, boundary storage is replaced with the head-reference value at offset 16 of the captured secondary collection object.

For every nonzero predicate result:

1. The payload at current-node offset 8 is passed to F-2318d06eb0b2.
2. After that call returns, the current cursor is copied into predecessor storage.
3. The next cursor is read from current-node offset 0.

As in the primary phase, payload processing precedes the next-link read.

After the secondary predicate returns zero, F-42e20851b8e3 is invoked with the then-current global secondary collection pointer. This pointer is read again at call time; it is not necessarily the collection address captured for traversal if a dependency has changed the global.

The initial nonzero field test is a gate, not a demonstrated item count. A nonzero value leads to F-42e20851b8e3 even if the first secondary predicate returns zero.

### 5. Final synchronization-like processing

If the pointer captured at entry is null, the function returns immediately with low half 26 and high half equal to the final cursor value. Collection processing and marker writes have already occurred.

Otherwise, it reads the captured object’s first 32-bit word and compares it with a global discriminator value read at this stage.

If the values match, it calls F-621dae46a146 with:

- The captured object pointer.
- A 32-bit zero argument.
- The current predecessor value.
- The current boundary value.

If the low 32 bits of that dependency’s 64-bit result are nonzero, that complete result is returned unchanged. A nonzero high half alone does not trigger this return.

If the discriminator differs, or the dependency returns a zero low half, processing continues.

The function next reads and retains the unsigned 16-bit attribute field at offset 14. It calls F-196812b4b122, then reads the 32-bit owner field at offset 4. Thus, the attribute snapshot precedes that dependency, while the owner read follows it.

If owner and returned identity differ, the result has low half 5 and high half equal to the observed owner. No direct counter or owner write follows on this branch.

If owner and identity match, the function derives a category from attribute bits 4 and 5. Other attribute bits do not affect the visible category decision.

- **Category other than 2:** release processing begins without a preliminary decrement.
- **Category 2:** the 16-bit counter at offset 18 is decremented by one and the narrowed 16-bit result is stored. Release processing occurs only if that result is zero.

For category 2, this is a 16-bit stored decrement, not saturating arithmetic. An initial counter bit pattern of zero becomes `0xffff`, which is nonzero and therefore does not release on that call. The signed interpretation shown for the counter does not change the zero test.

If the category-2 decrement is nonzero, the function returns low half 0 and high half equal to the previously read owner.

Release processing writes a 16-bit zero to offset 18, then a 32-bit zero to offset 4, in that order. It then invokes F-259d2fe281b0 with a pointer to offset 20 of the captured object and returns that dependency’s result.

Those object fields are already cleared when F-259d2fe281b0 executes. No rollback is visible if its result reports failure.

## Side effects

Directly established writes are:

- One byte of value 1 to the captured global marker address.
- One byte of value 0 to that same address after primary traversal.
- A conditional 16-bit decrement at synchronization-like offset 18.
- On release, a 16-bit zero at offset 18 followed by a 32-bit zero at offset 4.

F-0cb86028f147 can modify the local cursor and boundary through supplied addresses. Those modifications can affect later dispatch, traversal, dependency arguments, and the null-pointer return’s high half.

All invoked dependencies and indirect operations may have additional side effects. Their implementations are unavailable. No preservation of globals, memory, ownership, or collection links is assumed.

There is no direct allocation or deallocation visible in this function. Calls made for secondary payloads or collection completion do not, by themselves, establish destruction or ownership transfer. Likewise, passing the offset-20 subobject to F-259d2fe281b0 does not establish the lifetime of the enclosing object.

The visible code provides no atomic operations or memory-ordering guarantees for the marker, owner field, or counter.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless specified otherwise, dependencies return normally and do not introduce additional mutations.

1. **Mode selection.** Given one primary item admitted by F-0cb86028f147, mode zero dispatches table offset 0. Mode −1 dispatches table offset 4, as does every other nonzero 32-bit mode.

2. **Empty primary traversal.** If the first primary predicate returns zero, no primary operation executes. The initial head-reference dereference still occurs, and the marker is still written first to 1 and then to 0.

3. **Post-operation next-link observation.** If a primary operation changes its current node’s next link, traversal reads that changed link after the operation returns. A pre-operation next-link snapshot would not match the visible behavior.

4. **Secondary gate.** A zero secondary field at offset 20 suppresses both F-2318d06eb0b2 and F-42e20851b8e3. A nonzero field followed immediately by a zero predicate result suppresses payload processing but still invokes F-42e20851b8e3.

5. **Null captured object.** Even with a null synchronization-like pointer at entry, both collection phases run as applicable. The eventual return has low half 26 and high half equal to the final cursor, including any cursor modification made by the final predicate.

6. **Early dependency result.** If the discriminator matches and F-621dae46a146 returns high half 9 and low half 7, the full value is returned. If it returns high half 9 and low half 0, owner processing continues.

7. **Owner mismatch.** If F-196812b4b122 returns 3 and the subsequently read owner is 8, the result has high half 8 and low half 5. This branch performs no direct owner clearing or counter decrement.

8. **Remaining recursive count.** With matching owner, category 2, and counter 2, the counter becomes 1. F-259d2fe281b0 is not called; the result has low half zero and high half equal to the observed owner.

9. **Final counted release.** With matching owner, category 2, and counter 1, the decrement stores zero. The function then writes counter zero again, clears owner, and invokes F-259d2fe281b0.

10. **Zero-counter boundary.** With matching owner, category 2, and counter zero, the stored result becomes `0xffff`. No release call follows on this path.

11. **Other category.** With matching owner and any category other than 2, the prior counter value does not prevent release processing. Counter and owner are cleared before the release dependency runs.
