# F-04f46bd4cf22

## Purpose

F-04f46bd4cf22 delegates a calculation to F-870c4fcf7295 and places two components of its 64-bit result into consecutive 32-bit output slots. The first component is the low-order 32-bit word. The second is derived from the high-order 32-bit word by multiplication by 1000.

The established behavior is a representation transformation followed by two ordered stores. The supplied evidence does not establish the meaning or units of either component. In particular, the factor of 1000 does not by itself establish a time conversion.

This contract distinguishes:

- **Established static evidence:** behavior directly supported by the supplied function body.
- **Inferred intent:** plausible interpretation that is not required behavior.
- **documented_only:** an unresolved property that must not be replaced with an invented guarantee.

No runtime tests have been performed.

### First output store

No visible range check, status inspection, or comparison precedes this store. The low component is not multiplied, normalized, or combined with the high component.

The supplied representation includes a conversion through a signed integer before assignment to the 32-bit slot. ### Second output store

The wrapper derives the high component by logically shifting the 64-bit result right by 32 positions. This selects the upper 32 bits without propagating a sign bit from the original 64-bit quantity.

That component is then converted to a signed integer and multiplied by the integer constant 1000. The result is assigned to the destination slot at offset 4.

The multiplication belongs to the second component only. There is no visible:

- Carry from the first component into the second.
- Carry or normalization from the second component into the first.
- Saturation.
- Explicit overflow check.
- Division or remainder operation.
- Reinterpretation of the pair as one scaled 64-bit number.

The first store precedes the second store. The update is not established as atomic.

### Integer-width constraints

The output fields are 32 bits each. The intermediate dependency result is 64 bits. The supplied representation presents the second component’s multiplication as signed-integer arithmetic, rather than an explicitly widened 64-bit multiplication.

Under a 32-bit signed interpretation, a nonnegative high component no greater than 2,147,483 can be multiplied by 1000 without exceeding the signed maximum of 2,147,483,647. A high component of 2,147,484 would produce the mathematical value 2,147,484,000, which exceeds that maximum.

If conversion of the high word produces a negative signed value, multiplication is within the signed range only for values at least −2,147,483. The evidence does not supply the rule for converting high-word patterns above the signed maximum into signed values.

Consequently, this contract does not assert modulo-\(2^{32}\) multiplication, saturation, trapping, or any other overflow behavior. The exact result outside the defined signed-arithmetic range is documented_only.
