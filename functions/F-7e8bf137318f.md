# F-7e8bf137318f

## Purpose

F-7e8bf137318f transfers 36 consecutive 32-bit storage units from a caller-supplied source address to a destination address obtained from global state. The transfer covers 144 bytes.

The transfer is ordered: each source unit is read and then written to its corresponding destination position before the next source unit is read. The routine does not establish an independent snapshot of the entire source range. Consequently, overlapping ranges can produce results that differ from an overlap-safe block move.

The supplied representation organizes the transfer as nine groups of four units. Those groups introduce no gaps, padding, transposition, or change in transfer direction.

**Established behavior:** a fixed-size, ascending-address transfer with a globally selected destination.

**Inferred intent:** copying a fixed-size record or a nine-by-four collection of 32-bit entries. The representation does not establish any field meanings or require consumers to interpret the region as a matrix.

### Transfer order

For each position:

- It reads one 32-bit unit from the corresponding source address.
- It writes that unit to the corresponding destination address.
- It then advances to the next position.

The source and destination offsets are identical for every position. The first read is at S and its paired write is at D. The last read is at S plus 140 bytes and its paired write is at D plus 140 bytes.

### Overlapping regions

The body performs no overlap check and does not select a different direction for overlapping ranges.

Its general overlap rule is:

> Each destination unit receives the source unit’s contents at the time that particular source read occurs.

This rule can differ from copying the initial source contents.

If writes affect only source positions that have already been read, those writes do not change the values of later source reads.
