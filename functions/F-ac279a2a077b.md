# F-ac279a2a077b

## Purpose

F-ac279a2a077b selects a prefix of 16-bit input units, accumulates conversion lengths for that prefix, adjusts an output object, and converts the selected units again to emit bytes through an object-supplied callback.

The operation has two distinct passes. First-pass conversion results determine prefix selection and accounting. Second-pass results determine byte emission. The function does not require the two passes to produce identical results, and it does not reconcile accounting with the number of bytes actually emitted.

Before either pass, the function reads an address-source global, adds a fixed constant, and caches the resulting address. It reads an initialization word through that cached address twice: once during initial workspace setup and once after an intervening dependency call. The address is computed only once.

Length-aware formatted output is an inferred purpose. The established contract is the observable access, conversion, accounting, and callback sequence below.

## Interface

### Arguments and result

The supplied representation exposes three 32-bit arguments:

| Argument | Established use |
|---|---|
| Output-object address | Locates flags, callback information, a limit, and accounting fields. |
| Input address | Locates input units accessed at two-byte intervals. |
| Boundary value | Signed index threshold controlling zero termination; also copied into conversion workspace. |

The function returns without an explicit value. It provides no direct success indicator, failure code, or emitted-byte count.

Addresses and address-bearing fields are represented using 32-bit quantities. Input units are read using 16-bit accesses. Emitted payloads are read using 8-bit accesses. The signedness or promotion rules of the callback’s first parameter are not established.

### Output-object fields

Offsets are relative to the output-object address.

| Offset | Width | Observed role |
|---|---:|---|
| `0x18` | 32 bits | Flags; bit `0x20` enables limit-dependent selection. |
| `0x1c` | 32 bits | Encoded callback address; the lowest two bits are cleared before invocation. |

| `0x34` | 32 bits | Accounting field reduced by the first-pass accumulated length. |

The complete object size, field ownership, allocation discipline, and meanings outside this function are unknown.

### Address-source global and initialization word

The function reads a 32-bit address-source global and adds the fixed constant `0x080321b0`. It retains the resulting address for both initialization-word reads.

These are distinct observations:

- The address-source global is read once.
- The word at the derived address is read initially.
- That same derived address is used for another word read after F-be81034a42a8 returns.

The second word read neither rereads the address-source global nor recomputes the address. Dependencies can change the address-source global without redirecting that second read. Changes to the word at the cached address can change the refreshed workspace value.

No nonaliasing guarantee between these locations or other accessible storage is established.

### Conversion workspace

The workspace occupies 12 bytes, organized as three 32-bit words. Initial writes occur in this order:

1. The word read through the cached address is stored in the final workspace word.
2. The input address is stored in the first word.
3. The boundary value is stored in the second word.

After F-be81034a42a8 returns, only the final word is explicitly refreshed. The first two words are not restored.

The workspace is supplied to F-c5e54c1c1864. During emission, bytes are read starting at the beginning of that same workspace. It must not be described solely as immutable metadata or solely as an output buffer.

### Preconditions

Defined, bounded execution requires the caller and dependencies collectively to provide:

- Accessible object fields and address-source global.
- A valid derived address for both initialization-word reads.
- Readable input at every position reached by either pass.
- Valid callback addresses and contexts whenever bytes are emitted.
- Conversion writes and result lengths compatible with accessible workspace storage.
- Valid storage and usable address arithmetic throughout dependency calls and callbacks.
- A terminating selection sequence if finite completion is required.

The function explicitly checks none of these conditions. In particular, the boundary is not an input-length bound, and there is no null-pointer, alignment, callback-validity, or workspace-capacity check.

## Behavior

### 1. Cache the initialization-word address and initialize workspace

Before initializing the workspace or inspecting the output flags, the function reads the address-source global, adds `0x080321b0`, and retains the derived address.

It reads a 32-bit word through that address and initializes the workspace as described above. The selected-unit count and accumulated length both start at zero.

The address calculation is represented in a 32-bit environment. Behavior if the addition overflows or yields an invalid address is not established as a portable rule.

### 2. Determine whether another unit is eligible

At the start of each selection iteration, the function reads the flags at `0x18`.

- If bit `0x20` is clear, the top-of-loop guard permits further selection without reading the limit for that guard.
- If bit `0x20` is set, the function reads the limit at `0x38` and permits selection only when the accumulated length is less than that limit under a signed 32-bit comparison.

This guard precedes the next input read. An enabled zero or negative limit therefore prevents selection from starting when the accumulated length is initially zero.

If the guard permits an iteration, zero termination depends on the signed relationship between the current unit index and the boundary:

- Below the boundary, no zero-termination read is performed.
- At or above the boundary, the current 16-bit input unit is read, and a zero value stops selection.

The boundary is consequently a threshold for enabling zero termination, not a maximum unit count. A nonzero unit at the boundary remains eligible. A zero unit below a positive boundary remains eligible for conversion. A negative boundary enables zero termination starting at index zero.

For an eligible unit, the function reads its 16-bit value and calls F-c5e54c1c1864. When a zero-termination check has already read that position, the conversion argument is obtained by a separate read. Concurrent or dependency-induced changes are not resolved by a snapshot.

The first-pass call visibly supplies the workspace and the input unit. Its complete calling convention is unresolved because the second-pass call visibly supplies an additional argument.

### 3. Handle the first-pass conversion result

The all-one 32-bit result is the recognized failure sentinel.

For that result:

- Nothing is added to accumulated length.
- Selection does not stop merely because of the failure.
- The selected-unit count advances.

Every other result enters the length-accounting path. The function rereads the flags after conversion; it does not reuse the pre-conversion flags.

If bit `0x20` is now clear, the result is added to accumulated length, and the unit is accepted.

If the bit is now set, the function reads the current limit and forms a proposed total from the accumulated length plus the conversion result. The supplied representation compares the limit and proposed total as pointer-typed values. In the ordinary nonnegative range with conventional flat-address ordering:

- A proposed total below the limit is accepted.
- A proposed total equal to the limit is accepted.
- A proposed total above the limit stops selection.

On rejection, conversion has already occurred, but the current unit is not included in the selected prefix and its result is not accumulated.

After acceptance or conversion failure, the selected-unit count advances and the function returns to the top-of-loop guard. A zero-length success advances the count without advancing accumulated length. No independent finite iteration bound exists.

The pointer-typed rejection comparison must not be generalized into a portable signed comparison for every 32-bit pattern. Likewise, non-sentinel results are not explicitly checked for negativity or valid conversion-length range.

### 4. Apply the first accounting update and invoke preparation

Once selection stops, the function performs these operations in order:

1. Reads the field at `0x34`.
2. Subtracts the first-pass accumulated length.
3. Writes the result to `0x34`.
4. Calls F-be81034a42a8 with the output-object address.
5. Reads a 32-bit word through the previously cached address.
6. Stores that word into the final workspace word.

This sequence occurs even when no units were selected.

Step 5 does not reread the address-source global. If a dependency changed only that global, the read still targets the original derived address. If a dependency changed the contents at the cached address, the refreshed word reflects those contents.

There is no explicit restoration of the other workspace words.

### 5. Reconvert and emit the selected prefix

The second pass starts again at the original input address and visits exactly the selected number of units, in increasing index order. It does not repeat zero-termination or limit checks.

Each unit is reread using a 16-bit access and supplied to F-c5e54c1c1864. The visible second-pass call supplies:

- The workspace address.
- The input unit.
- The address of the workspace’s final word.

The all-one result suppresses emission for that unit. Every other result is interpreted as an unsigned 32-bit byte count.

For each byte position from zero up to, but not including, that count, the function:

- Reads the byte at that position relative to the workspace start.
- Reads the callback field at `0x1c` and clears its lowest two bits.
- Reads the callback context at `0x24`.
- Invokes the resulting callback with the byte and context.

The exact order of those argument and target reads within one invocation is not established. Each is nevertheless obtained for the individual invocation rather than cached for the entire operation. A callback can therefore change the target or context used by later invocations.

The byte count for the current conversion is retained for its emission loop. Callback return values are ignored.

There is no explicit workspace-size check. A non-sentinel result greater than 12 requests reads beyond the declared 12-byte workspace. There is also no comparison against the corresponding first-pass result, no second-pass limit enforcement, and no count of successful callbacks used for accounting.

### 6. Apply final accounting and complete

After revisiting all selected units, the function:

1. Reads the field at `0x3c`.
2. Adds the first-pass accumulated length.
3. Writes the result to `0x3c`.
4. Calls F-ea83ae94b50b with the output-object address.
5. Returns without a value.

The addition uses the field value present after conversion and callbacks, not an earlier snapshot.

This sequence occurs on the normal path even for an empty prefix or when every second-pass conversion fails.

## Side effects

The function directly reads the address-source global once and the word at the cached derived address twice. It also reads object fields, reads input units during selection, rereads selected units during emission, writes local workspace, updates `0x34` and `0x3c`, and invokes dependencies and byte callbacks.

No direct input-buffer write, explicit allocation, or explicit release is visible.

No ownership transfer is established for the object, input, context, or workspace. The workspace has local lifetime. Whether a dependency retains its address is unknown; no lifetime extension is visible.

Dependencies are not assumed to preserve globals, input, object fields, or workspace contents. Observable consequences include:

- Changing the address-source global does not by itself redirect the cached-address refresh.
- Changing the word at the cached address can affect that refresh.
- Preparation can change input subsequently read by the second pass.
- Conversion can change flags or limits before they are reread.
- Callbacks can change fields used by later callbacks or final accounting.

There is no rollback. If an invalid access occurs or a dependency does not return normally, earlier writes, conversions, and callbacks may already be observable. The recognized conversion sentinel does not produce a function-level error return.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless stated otherwise, assume valid memory, stable relevant fields and input, ordinary nonnegative lengths, no overflow, and normal dependency returns.

1. **Exact limit accepted.** With limit mode enabled, limit five, and successive first-pass lengths two and three, both units are selected. The next guard stops selection at five. Both accounting adjustments use five.

2. **Excess rejected after conversion.** With limit five and first-pass lengths two and four, the second conversion occurs but its unit is excluded. Only the first unit is revisited, and accounting uses two.

3. **Boundary does not cap input.** With limit mode disabled, boundary two, nonzero units at indices zero through two, and zero at index three, three units are selected.

4. **Early zero converted.** With boundary two and a zero first unit, that zero is supplied to F-c5e54c1c1864 rather than terminating selection.

5. **Immediate zero termination.** With boundary minus one and a zero first unit, selection performs no conversion. Initial address derivation and workspace setup still occur; both accounting updates and object-level dependencies occur on normal completion.

6. **Failure can still select a unit.** An eligible first-pass sentinel result advances the selected-unit count without adding length. If its second-pass conversion succeeds, bytes can be emitted without a matching first-pass length contribution.

7. **Second-pass failure preserves accounting.** A unit contributing three during selection but failing during emission produces no callbacks for that unit. Its contribution of three remains in both accounting adjustments.

8. **Preparation changes input.** If F-be81034a42a8 changes a selected input unit, the second pass supplies the changed value to conversion. Prefix length and accounting remain based on the first pass.

9. **Zero limit prevents selection reads.** With limit mode enabled and limit zero, selection reads no input units. This does not suppress the initial global read, either cached-address word read, or either object-level dependency.

10. **Callback context changes take effect.** If one callback updates `0x24`, the next callback obtains the updated context, provided execution continues normally.

11. **Address-source mutation does not redirect refresh.** Suppose the initial global value derives address A. If preparation changes that global so a fresh calculation would derive B, the refresh still reads A. A different word at B alone has no effect.

12. **Cached-word mutation affects refresh.** Under the same initial derivation of A, if preparation changes the word at A, the final workspace word receives that changed value. This remains true whether or not the address-source global also changes, subject to aliasing and valid access.
