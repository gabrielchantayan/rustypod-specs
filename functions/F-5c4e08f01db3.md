# F-5c4e08f01db3

## Purpose

F-5c4e08f01db3 searches a linked, ordered structure using F-31a0b2b5649a, then either returns an existing node or delegates insertion-like work to F-a189bf776c87.

The routine has two modes, selected by a byte in the supplied structure:

- **Zero mode byte:** perform an additional comparison intended to distinguish an existing equivalent entry from a location requiring insertion.
- **Nonzero mode byte:** delegate insertion after the initial search without performing that additional comparison.

The explicit result is a four-byte node-like value followed by a one-byte flag. A zero flag identifies the existing-node path. A flag of one identifies a path that called F-a189bf776c87; it does not independently prove successful allocation or insertion.

The ordered-tree interpretation is inferred from the link traversal and comparison patterns. The offsets, branch conditions, dependency arguments, and result writes are established by the supplied static evidence.

## Behavior

### Initial search

The routine initializes its remembered comparison outcome to nonzero.

It obtains the initial search node from offset 4 of the header referenced by structure offset 16. It then reads the header pointer from the structure again and uses that as the initial remembered node. These are distinct structure-field reads in the supplied representation; they are not established to be an atomic snapshot.

While the current search node is non-null:

1. F-31a0b2b5649a receives, in order:
   - The address at structure offset 25.
   - The supplied operand.
   - The address at offset 16 within the current node.
2. The current node becomes the remembered node.
3. The next node is loaded from:
   - Offset 12 if the dependency returned zero.
   - Offset 8 if it returned any nonzero value.

Only zero versus nonzero matters. Negative and positive nonzero results take the same branch. This routine does not interpret the result as a conventional three-way ordering value.

The child link is read after the dependency returns. A dependency that changes that link can therefore affect the next search step. The routine does not establish that comparisons are read-only.

When traversal reaches a null link, the remembered node is the last visited node. If the initial search node was null, the remembered node remains the separately loaded header pointer, and the remembered comparison outcome remains nonzero.

No cycle detection, traversal bound, or structural validation is present.

### Mode selection

After traversal ends, the routine reads the byte at structure offset 24.

A nonzero byte leads directly to the general F-a189bf776c87 path. The insertion dependency receives the remembered node from the search.

A zero byte enables the additional existing-entry check described below. The mode is read after all initial-search dependency calls, not before them. Changes to that byte during those calls can affect this branch.

### Candidate selection in zero mode

The remembered node initially serves as the candidate.

If the last comparison outcome is zero, no predecessor adjustment occurs. The candidate remains the remembered node.

If the last comparison outcome is nonzero, the routine reads the pointer at header offset 8, obtaining the header through a fresh read of structure offset 16.

If the remembered node equals that boundary pointer, the routine immediately invokes F-a189bf776c87. It performs no additional comparison and no predecessor traversal on this path.

Otherwise, it selects another candidate using the following link behavior.

#### Special predecessor case

The routine reads the byte at offset 0 of the remembered node.

If that byte is zero, it obtains the remembered node’s parent-like pointer from offset 4 and reads the pointer at offset 4 of that parent-like object.

If the byte was zero and this latter pointer equals the remembered node, the candidate becomes the remembered node’s offset-12 pointer. This candidate is used directly; the routine does not validate that it is non-null before forming the subsequent payload address.

#### Ordinary predecessor traversal

If the special case does not apply, the routine examines the remembered node’s offset-8 link.

- If that link is non-null, it starts there and follows offset-12 links until the current object’s offset-12 link is null. The terminal object becomes the candidate.
- If that link is null, it climbs through offset-4 parent-like links. It continues climbing while the object just left equals the parent’s offset-8 link. The first parent for which that equality is false becomes the candidate.

These walks rely on valid links and an appropriate sentinel or ancestor relationship. No explicit null guard protects the upward walk.

This behavior is consistent with predecessor selection in a sentinel-based ordered tree, but that interpretation is not needed to determine the actual accesses.

### Final existing-entry comparison

Unless zero-mode processing already took the boundary shortcut, F-31a0b2b5649a is called again with:

1. The address at structure offset 25.
2. The address at offset 16 within the selected candidate.
3. The original supplied operand.

This reverses the operand order used during the initial search.

If this comparison returns zero:

- The candidate address is written as the four-byte result.
- The flag byte is written as zero.
- F-a189bf776c87 is not called.

If it returns nonzero, the routine takes the general insertion-delegation path.

Under a strict-order comparison interpretation, this final zero result is consistent with accepting an equivalent existing entry. Equivalence is inferred intent; the established condition is simply a zero dependency result on the reversed operands.

### Insertion delegation

Every insertion-delegation path calls F-a189bf776c87 with five arguments:

1. The address of a temporary four-byte output location.
2. The original structure address.
3. A four-byte zero.
4. The remembered node from the initial search.
5. The original supplied operand.

The fourth argument remains the remembered search node even when predecessor selection produced a different candidate. The selected candidate is not substituted into that argument.

After the dependency returns normally, the routine copies the temporary four-byte output value into result offset 0 and writes one at result offset 4.

There are two internal delegation sites: the zero-mode boundary shortcut and the general path. They use different temporary output locations but have the same externally visible result format.

Initialization of those temporary locations is not a reliable failure fallback. Some paths initialize a temporary before delegation, while others can supply a location without an established prior value. A usable four-byte result therefore requires an adequate output contract from F-a189bf776c87. This routine does not check whether the dependency wrote the location.

## Side effects

### Direct effects

The routine directly writes only the two result fields described above, apart from its own temporary storage. It does not visibly modify structure or node fields itself.

Result writes occur after the relevant final dependency call returns. The four-byte result is written before the one-byte flag.

Aliasing can make those writes affect other objects. For example, a result destination overlapping the structure could overwrite structure fields at the end of the operation. The routine neither rejects nor manages such overlap. A nonoverlapping result destination is the straightforward safe calling convention; a universal nonaliasing requirement is not established by the source.

### Dependency effects

Both dependencies may have effects not visible in this body. No supplied contract establishes that either preserves globals, leaves the structure unchanged, allocates memory, or releases memory.

Consequently:

- Later link reads can observe changes made by earlier dependency calls.
- Later header, boundary, and mode reads need not match their earlier values.
- Payload and operand ownership cannot be inferred from the forwarding of addresses or values.
- A flag of one records delegation, not an independently verified structural change.

### Failure and termination

There is no explicit handling for invalid addresses, corrupt links, dependency failure, or allocation failure.

Malformed links can cause invalid accesses or nontermination. A dependency that does not return prevents subsequent result publication. If execution is interrupted between result writes, the first field may have changed while the flag has not.

No rollback or atomic publication guarantee is visible.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless otherwise stated, addresses are valid, dependency calls return normally, and their effects do not invalidate subsequent accesses.

1. **Nonzero mode, immediate null search link.**  
   The initial search node is null and the mode byte is nonzero. No comparison call occurs. F-a189bf776c87 receives the separately loaded header as its fourth argument. Its four-byte output is published with flag one.

2. **Zero-mode boundary shortcut.**  
   Search ends with a nonzero remembered comparison outcome, and the remembered node equals the freshly read boundary pointer. Delegation occurs without predecessor traversal or a reversed-operand comparison. The published flag is one.

3. **Existing candidate after a zero search outcome.**  
   Search ends with a zero comparison result. In zero mode, the remembered node is passed as the candidate to the final comparison, with its payload address before the supplied operand. If that call returns zero, the routine publishes the remembered node and flag zero without calling the insertion dependency.

4. **Candidate requiring delegation.**  
   Zero-mode candidate selection completes, and the final comparison returns nonzero. The routine delegates using the original remembered search node, even if candidate selection chose another node. It publishes the dependency output and flag one.

5. **Ordinary downward predecessor walk.**  
   The boundary shortcut and special predecessor case do not apply. The remembered node has a non-null offset-8 link. Candidate selection follows that link and then follows offset-12 links to a terminal node. That terminal node supplies the payload address for the final comparison.

6. **Ordinary upward predecessor walk.**  
   The ordinary path applies and the remembered node’s offset-8 link is null. Candidate selection climbs parent-like links while each departed object is its parent’s offset-8 child. The first parent breaking that relationship becomes the candidate.

7. **Special predecessor case.**  
   The remembered node’s first byte is zero, and its parent’s offset-4 pointer equals that node. The candidate is the remembered node’s offset-12 pointer, without the ordinary predecessor walk.

8. **Nonzero comparison values are interchangeable.**  
   A return value of minus one and a return value of one select the same search branch. Neither is treated as the opposite ordering direction merely because of its sign.

9. **Result field extent.**  
   With a nonoverlapping result destination containing unrelated bytes beyond offset 4, the routine’s direct publication writes replace offsets 0–3 and offset 4 only. No direct write initializes the remaining bytes of a larger enclosing result object.
