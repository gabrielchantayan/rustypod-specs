# F-200598445723

## Purpose

F-200598445723 traverses a linked structure using a comparison dependency, checks a traversal-derived candidate through two further dependency calls, writes either that candidate or a freshly read structure anchor to a caller-supplied destination, and returns a separate 64-bit composite value.

The established behavior is a conditional pointer-sized selection, not a conventional “find” result. In particular, one traversal branch records the link just read from offset 8 of a node, rather than recording the node being examined. The supplied evidence does not establish a standard search-tree operation, ordering relation, or meaning for the structure anchor.

This contract describes the visible behavior of the supplied static representation. No runtime tests have been performed.

## Interface

### Inputs

The function has four inputs:

| Input | Representation | Established use |
|---|---|---|
| Output destination | Address of a writable 32-bit slot | Receives one selected 32-bit value near the end of the function. Its incoming address also contributes to the return value when the traversal has no iterations. |
| Structure address | 32-bit address-bearing value | Supplies an anchor field at byte offset 16 and a dependency context address at byte offset 25. |
| Query | 32-bit value | Passed unchanged to the comparison dependency, but in different argument positions during traversal and final checking. |
| Auxiliary value | Opaque 32-bit value | Initially copied into temporary storage, then overwritten before that storage is passed to a dependency. No subsequent explicit use of the original auxiliary value is visible. |

The source-level types support a 32-bit address model. They do not establish portable behavior on a machine with wider pointers.

### Result channels

There are two distinct result channels:

1. **Output write:** one 32-bit store through the output destination.
2. **Return value:** a 64-bit concatenation of:
   - the final candidate slot in bits 63–32; and
   - a traversal marker in bits 31–0.

The traversal marker starts as the 32-bit representation of the output destination’s address. It becomes zero before the comparison call in every traversal iteration. Therefore, on an ordinary completed execution:

- no traversal iterations: the low return half is the output destination address;
- one or more traversal iterations: the low return half is zero.

The high return half is not necessarily the value written to the output destination. The output may instead receive a newly read anchor.

The concatenation is a bit-pattern construction. No signed-extension behavior should be inferred for either half.

### Referenced layout

Only the following fields and address computations are established:

| Object or address | Byte offset | Access |
|---|---:|---|
| Structure | 16 | Read a 32-bit anchor value, multiple times at different stages |
| Structure | 25 | Form an address passed as comparison context; no direct field read is visible |
| Anchor | 4 | Read a 32-bit initial traversal value |
| Nonzero traversal value | 8 | Read the next traversal value when comparison returns zero |
| Nonzero traversal value | 12 | Read the next traversal value when comparison returns nonzero |
| Nonzero traversal value | 16 | Form an address passed as a comparison operand; no direct payload read is visible |

The offsets are byte offsets. The context address at offset 25 is not necessarily word-aligned; this function passes that address without explicitly dereferencing it.

### Preconditions

For defined completion, every executed direct memory access must address valid memory with the required permissions:

- The structure’s 32-bit anchor field must be readable.
- The initially read anchor must support a readable 32-bit access at offset 4.
- Every nonzero traversal value reached must support whichever link access the comparison selects.
- The output destination must support a 32-bit write.

A zero initial traversal value is handled as loop termination. A zero anchor is not checked before the initial access at anchor offset 4.

The dependencies impose additional validity requirements that are not supplied here. Those requirements may apply to the context, query, candidate, and addresses of temporary slots.

Address computations must be valid in the intended 32-bit execution environment. The supplied representation does not establish overflow handling, bounds checks, or portable pointer-arithmetic semantics.

## Behavior

### 1. Initial reads and traversal state

The function first reads the structure’s anchor field and then reads the 32-bit value at offset 4 from that anchor. This becomes the initial traversal value.

It then reads the structure’s anchor field again, independently, to initialize the candidate.

These two anchor reads are observably separate. The contract does not collapse them into one snapshot. If the field changes between reads in an execution environment that permits such changes, the initial traversal value and initial candidate can originate from different anchor values.

The traversal marker is initialized to the output destination address.

### 2. Traversal

While the current traversal value is nonzero, the function:

1. Sets the traversal marker to zero.
2. Calls F-257a89ed2c43 with:
   - the structure address plus 25;
   - the current traversal value plus 16;
   - the original query.
3. Uses only whether the dependency’s 32-bit result equals zero.

If the result is zero, the function reads the 32-bit link at current traversal value plus 8. That newly read value becomes both:

- the next traversal value; and
- the candidate.

If the result is nonzero, the function reads the 32-bit link at current traversal value plus 12. That value becomes the next traversal value, while the candidate remains unchanged.

The selected link is read **after** the dependency returns. A dependency mutation to the selected link can therefore affect the traversal.

Negative and positive nonzero comparison results select the same branch. There is no visible less-than or greater-than distinction.

The loop stops only when the traversal value becomes zero. No visited-set, cycle detection, iteration limit, or structural validation is visible. A reachable cycle can prevent completion.

A zero-result branch that reads a zero link sets the candidate to zero and terminates traversal. This is materially different from retaining the node whose comparison produced zero.

### 3. Candidate boundary check

After traversal ends, the function reads the structure’s anchor field again and places that value in an addressable 32-bit temporary slot. It places the current candidate in another addressable 32-bit temporary slot.

It then calls F-cb011f129d08 with:

- the address of the candidate slot; and
- the address of the anchor-copy slot.

The dependency’s result is tested only for equality to zero.

Because addresses of these slots are passed to the dependency, their contents cannot be assumed unchanged. Subsequent behavior uses the candidate slot after this call, including any modification made through the supplied address.

The anchor-copy slot is not explicitly consulted again by this function after the call. That fact does not establish that the dependency ignores it or treats it as read-only.

### 4. Conditional final comparison

If F-cb011f129d08 returns nonzero, the function skips both remaining dependency calls and selects the fallback path.

If it returns zero, the function:

1. Calls F-2c0c622dae0f with the current candidate-slot value.
2. Takes the opaque 32-bit result of that call.
3. Calls F-257a89ed2c43 with:
   - the structure address plus 25;
   - the original query;
   - that opaque result.

This final comparison reverses the query’s argument position relative to traversal. During traversal, the query is third; here, it is second.

If the final comparison returns zero, the function selects the candidate slot for output. If it returns nonzero, the function selects the fallback path.

Neither a zero candidate nor any particular candidate provenance suppresses these calls. If the boundary check returns zero with a zero candidate, F-2c0c622dae0f is called with zero.

### 5. Output and return

On the fallback path, the function rereads the structure’s anchor field. This read occurs after the dependency calls taken on that path. The freshly read value, not the earlier anchor copy, is selected for output.

On the candidate path, the candidate slot is selected for output without another explicit anchor read.

The function then performs one explicit 32-bit write to the output destination.

Finally, it returns the 64-bit composite containing the candidate slot in the upper half and the traversal marker in the lower half. Selecting the fallback for output does not replace the upper return half with the fallback value.

If the output destination aliases the structure’s anchor field or another referenced field, the final write can mutate that field. The explicit traversal and selection reads have already occurred by then.

## Side effects

The function explicitly performs:

- reads of the structure anchor;
- the initial anchor-relative read;
- selected traversal-link reads;
- calls to dependencies in the order described above;
- one final 32-bit write through the output destination;
- writes to temporary storage used for traversal, dependency arguments, and return construction.

No allocation, deallocation, ownership transfer, reference-count update, or lock operation is directly visible.

Those absences do not constrain dependency behavior. In particular, the dependencies are not established to preserve global state, structure fields, memory ownership, or the lifetime of referenced objects.

The supplied representation shows no error code, exception handling, rollback, or recovery path. Invalid accesses and dependency failures are not converted into a documented failure result. If traversal or a dependency does not return, the final output write is not reached.

## Acceptance examples

These are conditional static examples, not observed executions. Unless stated otherwise, assume all accesses are valid, all calls return normally, and dependencies leave relevant state unchanged.

### Empty traversal with candidate accepted

Suppose the initial anchor-relative traversal value is zero and the independently read candidate anchor is A.

If F-cb011f129d08 returns zero and the final comparison returns zero:

- no traversal comparison occurs;
- F-2c0c622dae0f receives A;
- the output receives A;
- the return upper half is A;
- the return lower half is the output destination address.

### Traversal containing only nonzero comparisons

Suppose traversal visits one or more nodes, every comparison returns nonzero, and the offset-12 links eventually reach zero.

The candidate remains its independently read initial anchor value. The return lower half is zero, regardless of whether output ultimately selects the candidate or fallback.

### Zero comparison followed by a zero link

Suppose a traversal comparison returns zero and the node’s offset-8 link is zero.

The candidate becomes zero and traversal ends. If the boundary check then returns zero, F-2c0c622dae0f receives zero. The examined node is not retained as candidate.

### Candidate replacement followed by nonzero comparisons

Suppose a zero-result comparison reads a nonzero offset-8 link B. Later comparisons are all nonzero and eventually terminate traversal.

The candidate remains B unless F-cb011f129d08 modifies the candidate slot.

### Boundary check rejects the candidate

Suppose F-cb011f129d08 returns nonzero.

Neither F-2c0c622dae0f nor the final comparison is called. The output receives a fresh anchor-field read. The return upper half still contains the candidate-slot value, including any change made by the boundary dependency.

### Final comparison rejects after an anchor mutation

Suppose the boundary check returns zero, and a subsequent dependency changes the structure anchor from A to B before the final comparison returns nonzero.

The fallback read obtains B, so the output receives B. The earlier copied anchor A does not determine this output.

### Candidate-slot mutation

Suppose the traversal-derived candidate is A, but F-cb011f129d08 replaces its addressed slot with B and returns zero.

F-2c0c622dae0f receives B. If the final comparison returns zero, the output and return upper half contain B, assuming no further relevant mutation.
