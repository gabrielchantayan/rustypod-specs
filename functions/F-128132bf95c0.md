# F-128132bf95c0

## Purpose

F-128132bf95c0 searches for an overlap between values produced by an indirect callback and a sequence of 32-bit entries associated with a caller-supplied structure.

The callback receives the previously produced value as its continuation input, initially zero. Each nonzero result is searched for in the sequence. A match returns the 32-bit value one. A zero callback result terminates the operation and returns the 32-bit value zero without searching for zero.

This is a description of the supplied static evidence, not a guarantee that the callback implements an iterator or that the sequence remains stable. Interpreting the operation as a membership search over an enumeration is inferred intent.

## Interface

The function has two inputs and one 32-bit result:

| Item | Contract |
|---|---|
| First input | An address-like value identifying a structure. A field at byte offset 4 is read as the address of a sequence of entries. The address of that field is also supplied to F-168d7d8f17dc. |
| Second input | An opaque 32-bit value passed unchanged to F-6e90825b1a9f on every outer iteration. Its interpretation is delegated to that dependency. |
| Result | A 32-bit value: one after a matching entry is observed, or zero after a callback returns zero. These are the only explicit normal return values. |

The supplied representation uses 32-bit integer words and four-byte sequence entries. Its pointer-bearing operations are consistent with a 32-bit address model. A different pointer width or ABI is not established by the evidence.

The first input is not itself the sequence address. The sequence address is obtained by reading the field four bytes after it. No other fields of that structure are directly inspected.

F-6e90825b1a9f returns an object address. The object’s first word supplies a dispatch-table address, and the dispatch-table slot at byte offset 12 supplies a callable target. That target is invoked with:

1. The object address returned by F-6e90825b1a9f.
2. The current 32-bit continuation value.

Its 32-bit result becomes the continuation value for the next outer iteration and, when nonzero, the value searched for in the sequence.

The shown function performs no validity checks on structure addresses, object addresses, dispatch tables, callable targets, or entry storage. Successful execution requires each accessed location to be readable and each selected callback to be callable under the applicable ABI. Those requirements are conditional on the execution path: a callback returning zero avoids all sequence-related accesses for that iteration.

No ownership transfer is expressed by this interface. The function neither explicitly allocates nor explicitly releases storage.

## Behavior

### Initial state and callback acquisition

The continuation value starts at zero. The outer operation executes at least once; it does not first consult the sequence or its size.

Each outer iteration begins by calling F-6e90825b1a9f with the second input. The function does not retain an object from a previous iteration. Consequently, the dependency may return the same object or a different object on successive calls.

After that dependency returns, the function reads the returned object’s first word, uses it to locate the dispatch slot at byte offset 12, and invokes the selected callback. These dispatch reads occur again on each outer iteration; the shown function does not cache a callback target across iterations.

The callback receives the previous continuation value, not an entry index or a sequence address. On the first invocation that value is zero. On later invocations it is the nonzero result of the preceding callback invocation.

### Termination on zero

The callback result is tested immediately.

If it is zero, the function returns zero. In that iteration, it does not:

- Read the sequence-address field.
- Call F-168d7d8f17dc.
- Read a sequence entry.

Zero is therefore a termination marker, not a searchable candidate. The presence of zero in the sequence cannot cause a successful result.

### Searching a nonzero result

For a nonzero callback result, the function reads the sequence address from the field at byte offset 4 of the first input. This address is captured once for that scan.

The scan begins with an unsigned 32-bit index of zero. Before each possible entry read, F-168d7d8f17dc is called with the address of the sequence-address field. Its result is used as an unsigned 32-bit bound for the current comparison.

If the current index is not less than that bound, the scan ends without reading an entry at that index. The function then starts another outer iteration, using the same nonzero callback result as the next continuation input.

If the current index is less than the bound, the function reads the 32-bit entry at the current scan address and compares it for exact equality with the callback result.

- Equality causes an immediate return of one.
- Inequality advances the scan address by four bytes and increments the unsigned index by one. The bound dependency is then called again before another entry can be read.

The bound is not obtained once and reused. It is requested for every scan condition, including a condition that ends the scan. For a stable bound of \(N\), a complete unsuccessful scan performs \(N\) entry comparisons and \(N+1\) calls to F-168d7d8f17dc. A match at zero-based index \(k\) performs \(k+1\) such calls and returns without a further bound call.

### Ordering and mutable state

For each nonzero candidate, the observable ordering is:

1. Read the sequence-address field.
2. Call the bound dependency.
3. If the index is within that returned bound, read and compare the current entry.
4. After a mismatch, advance the address and index.
5. Repeat the bound call before any next entry read.

This order matters if dependencies modify shared state.

The scan uses its captured sequence address even if a later call to F-168d7d8f17dc changes the structure’s sequence-address field. That field is not reread during the same scan. It is read again after a subsequent nonzero callback result.

Sequence contents are not copied. Each entry is read only when its comparison is reached, after the corresponding bound call. Changes to still-unread entries can therefore affect the result.

A shrinking bound can stop a scan earlier than an initial bound would suggest. A growing bound can permit additional reads. The implementation provides no stable-snapshot guarantee tying the returned bound to the captured sequence address.

### Equality, arithmetic, and termination limits

Entry equality has no signed ordering component. Any nonzero 32-bit callback result can match an entry with the same 32-bit value, including values whose high bit is set.

The scan index is unsigned and 32 bits wide. Its increment has modulo-\(2^{32}\) behavior in the represented arithmetic. The function contains no overflow check, scan limit, or independent exhaustion guard.

Each ordinary advance moves the scan address by four bytes. The evidence does not establish portable behavior for invalid address arithmetic, inaccessible storage, or an address crossing the supported memory range.

Termination is not guaranteed. For example, an endless sequence of nonzero callback results that never match can keep the outer operation running indefinitely. Unstable bounds and invalid memory can introduce additional failure or nontermination conditions.

## Acceptance examples

These examples are conditional behavioral checks derived from static evidence. They are not runtime test results. Unless stated otherwise, assume valid storage, callable dependencies, stable bounds, and no dependency-induced mutation.

1. **Immediate termination.**  
   If the first callback receives zero and returns zero, the result is zero. There is one call to F-6e90825b1a9f and no call to F-168d7d8f17dc. The sequence-address field is not read.

2. **Match at the first entry.**  
   If the callback returns 17, the bound dependency returns three, and the first entry is 17, the result is one. Only one entry is read, and the bound dependency is called once.

3. **Mismatch followed by exhaustion.**  
   If the callback returns 17 and the stable two-entry sequence contains 4 and 9, both entries are compared. The bound dependency is called three times. The next outer iteration invokes a newly obtained callback with continuation value 17. If that callback returns zero, the result is zero.

4. **Zero-sized scan.**  
   If a callback returns 17 and the first bound is zero, no sequence entry is read. The sequence-address field has nevertheless already been read. The next callback receives 17.

5. **Zero entry is not a termination match.**  
   If the sequence contains zero and the callback returns zero, the result is zero without scanning. The zero entry does not produce a result of one.

6. **High-bit equality.**  
   If the callback returns the 32-bit pattern `0xFFFFFFFF` and a permitted entry read yields that same pattern, the result is one. Signed interpretation does not prevent equality.

7. **Bound shrinks during a scan.**  
   If the first bound is two, the first entry mismatches, and the next bound is one, the second entry is not read. The current index is already one, so that scan ends.

8. **Sequence field changes during a bound call.**  
   If the captured sequence address is A and the bound dependency changes the structure’s field to B, an admitted entry read still uses A. A later nonzero-candidate scan captures the field again and can use B. This example requires A to remain valid.
