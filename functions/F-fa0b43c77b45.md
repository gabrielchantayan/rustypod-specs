# F-fa0b43c77b45

## Purpose

F-fa0b43c77b45 conditionally scans a sequence of indirectly obtained entries. It returns normally when scanning is disabled, when the captured signed entry count is nonpositive, or when every examined entry begins with a zero-valued integer.

On the first entry whose leading integer is nonzero, the function stops scanning, calls F-a8c5a6e3974f, and, if that call returns, calls F-feee9156a257. The supplied static evidence marks the latter call as non-returning.

This establishes a conditional scan followed by an exceptional or terminal path. The meanings of the entries, the enable value, and the two direct dependencies are not established. In particular, describing this as validation, cleanup, assertion handling, or process termination would require evidence not supplied here.

## Behavior

### Initial gate

The first relevant object access is the enable-field read and character conversion.

If the converted value is zero, the function returns immediately. On this path, it does not read the count, resolve an entry target, inspect an entry, or explicitly call either direct dependency.

Consequently, a zero-converted enable value suppresses the scan even if the full integer field is nonzero.

If the converted value is nonzero, the function reads and captures the signed count. The initial enable condition is not checked again.

### Captured scan bound

The captured count remains the bound used for the entire scan. The function does not refresh it after any indirect call.

The index begins at zero. Before each entry request, the function compares the captured signed count with the current index:

- If the count is less than or equal to the index, it returns normally.
- Otherwise, it requests the entry at that index.

A zero or negative count therefore causes normal return without any entry request. Negative values are not interpreted as large unsigned counts.

With a positive count and no early match, the requested indices are exactly zero through one less than the captured count, in increasing order.

Under a signed 32-bit interpretation, the index cannot overflow on a normally progressing scan. Even with the maximum positive count, the final zero-valued entry advances the index only to that maximum; the next bound check returns before another increment.

### Entry retrieval and observation order

For every requested index, the function performs the following observable sequence:

1. It reads the dispatch-table address through the original input pointer.
2. It obtains the callable target from table offset 0x40.
3. It invokes that target with the input pointer and current index.
4. If the invocation returns, it reads the leading integer at the returned address.
5. It decides whether to continue scanning or enter the terminal path.

Dispatch is resolved anew for each entry request. It is not captured once alongside the count. Therefore, if an indirect call changes the object’s dispatch-table field or the relevant table slot, a later request uses the then-current dispatch state.

Conversely, a change to the stored count does not alter this invocation’s captured bound. A change to the enable field does not disable an already-started scan.

The entry integer is read after the indirect call returns. The supplied evidence does not establish any entry value before that call, nor any stability guarantee across calls.

### Entry outcomes

If an entry’s leading integer is zero, the function advances the index by one and repeats the bound check.

If that integer is nonzero, its particular value does not otherwise affect this function’s visible control flow. Positive and negative nonzero values select the same path.

The first nonzero entry ends scanning. No later index is requested.

The function then calls F-a8c5a6e3974f with no explicit arguments. If that dependency returns normally, it calls F-feee9156a257 with no explicit arguments. The latter dependency is marked non-returning in the supplied evidence.

This ordering does not imply that the second call is inevitably reached. F-a8c5a6e3974f may itself fail to return or transfer control by mechanisms not shown. Its behavior is not supplied.

No ordinary recovery path after F-feee9156a257 is established. If the non-returning annotation is inaccurate and that dependency returns, subsequent behavior is outside the established contract.
