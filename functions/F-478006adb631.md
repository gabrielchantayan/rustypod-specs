# F-478006adb631

## Purpose

F-478006adb631 is a non-returning sequence of indirect calls interleaved with byte and 32-bit memory accesses. It repeatedly derives addresses and stored values from call results, hidden entry state, explicit inputs, and one global-word read.

The supplied representation establishes the operations and their order, but not their application-level meaning. In particular, it does not establish that the addresses identify valid objects, that the calls implement allocation or dispatch, or that the byte stores represent flags.

There is no visible successful return, error return, termination condition, or recovery branch. If all calls return and all accesses complete, execution repeats indefinitely.

## Interface

### Explicit inputs

| Input | Represented width | Established use |
|---|---:|---|
| First input | 32 bits | Passed to the first indirect call of the initial iteration; subsequently stored as a 32-bit value. |
| Second input | 32 bits | Passed to that initial call. |
| Third input | 32 bits | Passed to that initial call. |
| Fourth input | 32 bits | Only its low eight bits are used, for four byte stores during the initial iteration. |

The explicit inputs are not sufficient to determine execution. Two additional entry-state values are consumed:

- A hidden 32-bit register value determines an initial memory-address base.
- A hidden continuation/link value determines the first indirect-call target.

Their valid values, initialization requirements, and calling convention are unknown.

### Output and completion

The represented interface has no return value. Observable outputs are:

- Indirect calls and their explicitly represented arguments.
- Byte and 32-bit memory writes.
- Reads from computed addresses and a global word.
- Repetition with replacement input state.

An exception, fault, non-returning dependency, or external interruption may prevent further progress. No behavior following such an event is established.

### Arithmetic notation

The behavioral trace below uses these descriptive labels:

- **Input base**: the hidden register value multiplied by \(2^{28}\).
- **Input byte**: the low eight bits of the fourth input.
- **S1–S23**: selected 32-bit dependency results, numbered in production order.
- **P1 and P2**: selected 64-bit dependency results, each split into low and high 32-bit halves.
- **W**: a word read from a computed address.
- **G**: the sampled global word.
- **T**: a retained, zero-extended byte read.
- **Q1–Q4 and V1–V5**: derived values defined below.

These are specification labels, not proposed object fields.

For describing the represented machine-width operations, multiplication, addition, and left shifts retain their low 32 bits. Right shifts of unsigned words are logical. A byte write retains only the low eight bits. The signed-looking operations in the supplied representation do not establish portable signed-overflow semantics; the machine-width interpretation is a reconstruction boundary, not a claim about portable source-language execution.

## Side effects

### Memory layout and access widths

Two access forms recur:

1. A 32-bit word at an arithmetic address ending in an added offset of 20.
2. A byte selector read, followed by a byte write at the selector’s zero-extended value plus 17.

The second form addresses the range 17 through 272. It does **not** add the original selector-storage base to the destination.

The retained-byte word store in phase 8 addresses the range 20 through 275. Its address need not be naturally aligned. Alignment support and fault behavior are unknown.

No containing allocation, structure size, field declaration, address-space mapping, or access permission is established. Repeated offsets do not prove a shared object layout.

### Ordering and aliasing

The trace specifies program order, not hardware memory-barrier guarantees.

Computed addresses may alias each other, the selector storage, the global word, or memory used by dependencies. Consequently:

- Equal-value stores remain observable operations.
- A selector must be reread wherever the trace specifies a read.
- Phase 8 must use the retained T even if intervening calls change selector memory.
- G is sampled once in phase 8 and used later; it is not resampled in phase 9.
- No dependency may be presumed to preserve global or addressed memory.

The representation also warns of overlapping global symbols. It does not establish that G occupies storage independent of other accessible state.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests. They assume all relevant calls return and accesses succeed.

1. **Fourth-input truncation.** If the fourth input is `0x123456AB`, all four direct input-byte stores in phases 2 and 3 write `0xAB`. The upper bits do not alter those writes.

2. **One-bit word production.** If S1 is odd, phase 4 writes `0x80000000`. If S1 is even, it writes zero. The destination remains \(16S4+20\).

3. **Selector indirection.** If phase 6 reads selector value 5, its destination is address 22, not input base plus 22. If S7 is 65, the stored byte is 4.

4. **Retained selector.** If phase 7 reads T equal to 9 and a phase-8 dependency changes selector storage to 12, the phase-8 word store still targets address 29.

5. **Fresh selector read.** If a dependency between phases 9 and 10 changes the selector from 9 to 12, phase 10’s zero-byte write targets address 29. It does not reuse phase 9’s destination.

6. **Word-read address range.** Phase 4’s W read uses addresses from 20 through 1043, because its masked and shifted address contribution ranges from 0 through 1023. No alignment correction is visible.

7. **Width-dependent zero argument.** Under the stated 32-bit interpretation, \(V2\ll28\) in phase 19 is zero: V2 already contains a 14-bit left shift. That fact does not eliminate the call or determine its second argument.

8. **Continued execution.** If phase 26 yields V5 equal to 12, the next iteration begins with three input states equal to 12, fourth-input state zero, and an input base derived from \(12\times2^{28}\). It does not return a success value.
