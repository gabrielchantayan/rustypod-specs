# F-6977f9f262ab

## Purpose

F-6977f9f262ab coordinates an initial context-dependent operation, a two-argument operation whose result it returns, and conditional propagation of a 16-bit field from an input object to a context object.

The established behavior is an ordered sequence of dependency calls and field accesses. The semantic meanings of the objects, fields, and second argument are not established. In particular, describing the second argument as a Boolean would be too restrictive: its full value is forwarded to one dependency, while its zero/nonzero status controls later behavior.

The conditional propagation does not necessarily target the context inspected for eligibility. Context acquisition occurs separately for the eligibility read and the eventual write. The function does not establish that those acquisitions return the same address.

### Eligibility evaluation

After the preceding operations, the function reads the 16-bit source field at input-object offset `0xE6` and compares it with zero.

This read occurs even when the control value is zero. The final condition evaluates the source-field comparison before checking the control value.

If the source field is zero, no further context acquisition or field access occurs in the visible function.

If the source field is nonzero but the control value is zero, no further context acquisition or field access occurs.

Only when both the source field is nonzero and the control value is nonzero does the function call F-fdd8589eca2d again. It reads the 16-bit field at offset `0x80` from the address returned by this acquisition.

If that inspected field is nonzero, the propagation step is skipped.

The comparisons are zero/nonzero tests. Although the supplied representation uses signed 16-bit reads for the conditions, no ordering comparison or signed arithmetic is involved. A bit pattern with the high bit set is nonzero and is not excluded.

### Conditional propagation

If the inspected context field is zero, the function calls F-fdd8589eca2d a third time.

After that acquisition completes, it reads the source field at input-object offset `0xE6` again and writes that 16-bit value to offset `0x80` from the newly returned address.

Several consequences are part of the contract:

- The source is not captured at the initial eligibility read. The write uses a later source read.
- The context used for the write is acquired separately from the context whose field was checked.
- The write target is not checked for a zero field before writing.
- The source is not checked again for nonzero after the final context acquisition.
- A zero source value can therefore be written if the source changes after the eligibility read.
- A nonzero target field can be overwritten if the final acquisition returns a different context, or if intervening effects change the target.

The direct write copies a 16-bit value. No widening, narrowing from a larger source, arithmetic transformation, or combination with the previous destination value is visible.

### Completion

### Full control-value forwarding
