# F-267fb48ee4d5

## Purpose

F-267fb48ee4d5 selects a 32-bit return value through two ordered dependency-result checks and a final field-based fallback.

The first check can terminate the operation without accessing the caller-supplied object. The second check uses a dependency invoked with an address derived from that object. If neither check produces an early return, the operation reads a field at byte offset 44 and chooses between a captured field value and a global fallback.

The established behavior is selection and precedence, not validation or allocation. The supplied evidence does not establish whether the returned value is a numeric setting, a handle, an address, or another encoded value. A history-related interpretation is plausible from the fixed text used in the first check, but that interpretation is not required by this contract.

### Output

The operation returns an integer represented as 32 bits. Its value comes from exactly one of these sources:

1. A global value selected by the first check.
2. A different global value selected by the second check.
3. The first captured value of the field at offset 44.
4. A global fallback selected when the second read of that field is zero.

These are source roles, not assertions that the underlying storage locations or values are distinct.

The return value is not accompanied by a success flag or error classification. Zero is not established as an error return: any selected source may potentially contain zero.

## Behavior

### Selection sources

For clarity, this contract names the three global value sources by role:

- **First-match value:** returned after a zero result from the first comparison.
- **Second-match value:** returned after a zero result from the second comparison.
- **Field fallback:** returned when the final field check observes zero.

These names do not imply when the globals were initialized or whether dependencies may modify them.

### First decision

The operation first invokes F-3ad65987df9a without arguments.

After that call returns, it invokes the comparison dependency with:

- The four-byte result of F-3ad65987df9a.
- A fixed operand associated with the text `CntrlHistoryFn`.

If the comparison dependency returns zero, the operation reads the first-match value and returns it immediately.

On this path:

- F-44362605ab79 is not invoked.
- The second comparison is not performed.
- The field at offset 44 is not read by this operation.
- Neither the second-match value nor the field fallback is selected.

The global return value is obtained after the comparison call. It must not be treated as a value captured before either dependency ran.

If the comparison result is any nonzero 32-bit integer, execution proceeds to the second decision. The sign and magnitude of that nonzero result do not affect this branch.

### Second decision

The operation invokes F-44362605ab79 with the address derived by adding 40 bytes to the input base.

After that call returns, it invokes the same comparison dependency with:

- The four-byte result of F-44362605ab79.
- An operand obtained from global storage.

If this comparison returns zero, the operation reads the second-match value and returns it immediately.

On this path, the final field selection is skipped. The supplied operation does not itself read the field at offset 44, although the behavior of dependencies is unknown and may include access to overlapping storage.

The global comparison operand is used after F-44362605ab79 returns. The second-match value is read after the comparison returns. Neither may be assumed to retain its entry-time value.

If the second comparison result is nonzero, execution proceeds to the field selection.

### Final field selection

The supplied representation contains two reads of the 32-bit field at offset 44:

1. An initial read whose value is retained as the candidate return value.
2. A subsequent read whose value determines whether to use the field fallback.

If the second read is zero, the operation reads and returns the field fallback.

If the second read is nonzero, the operation returns the value retained from the first read.

This distinction matters when the two observations differ. The operation is not represented simply as “read the field once and return it unless zero.” For example, if the first read is zero but the second is nonzero, the retained zero is returned rather than the fallback.

No dependency call appears between these two field reads. The evidence nevertheless does not establish volatile access, atomicity, concurrency rules, or the exact number of physical memory transactions in the executable. The two-read distinction is established at the supplied representation level.

### Precedence and completion

The order of selection is strict:

1. First comparison selects the first-match value.
2. Otherwise, the second comparison selects the second-match value.
3. Otherwise, the second field observation selects either the retained first observation or the field fallback.

An earlier selection prevents all later selection steps from occurring.

There is no visible retry, loop, cleanup phase, or recovery branch.
