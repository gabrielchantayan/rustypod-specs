# F-122dac9e32d5

## Purpose

F-122dac9e32d5 exposes a state-dependent sequence of indirect calls, integer transformations, and memory updates, followed by an unresolved indirect transfer.

**Established static evidence:** the supplied representation declares no explicit parameters and no return value. It shows a long, straight-line call sequence before a dense sequence of byte, halfword, and word accesses. The final transfer supplies four argument values.

**Inferred intent:** repeated masks, shifts, field-like offsets, and repeated stores suggest manipulation of packed state or an encoded execution environment. They do not establish a particular data structure, protocol, device, or application purpose.

This contract describes the evidence-supported observations and their limits. It does not treat the supplied representation as proof that every displayed operation is executable or that the apparent function boundary and calling conventions are correct.

## Behavior

### Call-driven phase

The opening phase consists of ordered indirect invocations. Most destinations are formed from distinct embedded control values plus 0xFFE; the first additionally depends on incoming control state.

Calls without displayed arguments remain observable events. Their lack of displayed arguments does not establish that they consume no machine state or produce no side effects.

The representation shows no explicit conditional branch or loop in this phase. Subject to each call returning, later calls occur after earlier calls. A replacement must not reorder calls merely because their displayed return values are unused.

The principal argument transformations are:

- A 32-bit result shifted left by eight.
- A previously shifted result shifted left by another seven, often supplied twice in one argument list.
- The incoming register-derived value shifted left by twelve.
- A result container’s low word shifted left, with its high word supplied independently.
- Multiple differently shifted views of one result in a single invocation.
- Explicit zero arguments, including complete zero-valued argument groups.

The supplied representation also retains intermediate values across intervening calls. That is evidence of displayed dataflow, not a guarantee that arbitrary callees preserve registers, globals, or memory.

The later part of this phase includes masks selecting 24, 22, 20, 19, 17, 14, 13, 12, 11, and smaller numbers of bits. Some masks precede shifts; others follow shifts. Those orders are significant.

For example, taking the low 24 bits before a right shift excludes all higher bits. Shifting a 32-bit value left and then right can lose upper bits and must not be treated as an inverse transformation.

### Arithmetic interpretation

For explicitly unsigned 32-bit expressions, left shifts and multiplication retain the low 32 bits; right shifts insert zeros. A shift applied to the 64-bit result container is evaluated before its subsequent narrowing.

Consequently:

- A container shifted right by 34 and narrowed to 32 bits yields its high word shifted right by two.
- Right shifts by 36 and 44 yield the high word shifted right by four and twelve, respectively.
- A masked 24-bit value shifted left by six occupies at most 30 bits.
- A masked 22-bit value shifted left by eight likewise occupies at most 30 bits.

Many other operands are displayed as signed 32-bit integers. Negative operands, overflowing multiplication, and signed left shifts cannot be assigned a portable language-level meaning from this representation alone. Their intended machine-bit behavior is **documented_only**. Conditional examples below explicitly identify when they use a 32-bit bit-vector interpretation.

The final memory phase also contains a signed right shift with a count obtained from the low byte of another value. Counts can therefore exceed 31. Neither sign propagation nor oversized-count behavior is established.

The earliest visible updates establish an important ordering boundary:

- A word at offset 0x54 from a base derived by multiplying the latest low word by 256 receives another retained value.

## Acceptance examples

These are conditional review criteria, not executed tests.

1. **Byte widening.** If an offset-5 byte read yields 0xE1 and execution reaches the corresponding offset-0x34 word store without a fault, that store carries 0x000000E1, not a sign-extended negative value.

2. **Composite result separation.** If a displayed result container has low word 0x00000123 and high word 0x89ABCDEF, an invocation using the low word shifted left by eight and the high word independently receives 0x00012300 and 0x89ABCDEF in those positions.

3. **Unsigned truncation.** Under 32-bit unsigned arithmetic, shifting 0x12345678 left by eight yields 0x34567800. A later logical right shift by eight yields 0x00345678, not the original value.

4. **Repeated writes.** If a destination is observable memory, successive stores of 0x20, 0x2F, a widened byte, and 0x20 remain four writes. The final value alone is insufficient evidence of equivalence.

5. **Overlapping fields.** If an offset-0x15 byte lies within a previously cleared offset-0x14 word, the byte write changes that word’s byte representation. Which numeric word bits change depends on byte order.

6. **Saved versus reread values.** If a word is captured before its storage is overwritten, subsequent uses of the captured value retain the earlier contents. A later explicit memory read instead observes the later memory state.

7. **Fault after mutation.** If a reached memory write succeeds and a subsequent dependency does not return, later writes and the final transfer need not occur. No rollback is promised.

8. **Final transfer.** If the entire displayed path completes its preceding accesses, the unresolved destination receives 0x72 as its first argument and the three specified captured or loaded words in their displayed order. No returned status interpretation is established.
