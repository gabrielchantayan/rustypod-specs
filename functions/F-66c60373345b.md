# F-66c60373345b

## Purpose

F-66c60373345b chooses a numbered object using either a linked reuse structure or a new-number calculation. It returns a status and can write both the chosen number and an object reference.

The visible operation includes candidate selection, dependency calls that appear to acquire and prepare objects, reuse-list updates, accounting changes, and reference cleanup. These actions are not visibly transactional: failure can occur after output assignments or mutation requests, without local rollback.

“Reuse list,” “node,” “acquisition,” and “preparation” describe inferred roles. Dependency implementations are not supplied. This contract distinguishes explicit assignments and call ordering from effects that require an unverified dependency contract.

## Interface

The result is a signed 32-bit status. The five arguments are:

| Input | Representation | Role |
|---|---|---|
| Context | Reference represented in the supplied 32-bit layout | Supplies resource, root, allocation state, and format fields. |
| Object output | Address of a 32-bit reference slot | Receives an object reference on applicable paths. |
| Number output | Address of an unsigned 32-bit slot | Receives a proposed or selected number. |
| Preferred number | Unsigned 32-bit value | Influences selection and optional exact searching. |
| Exact-search request | Signed 32-bit value | Any nonzero value enables an eligibility probe; it does not itself require exact selection. |

Neither output is initialized on entry. Zero denotes success for checked status-returning dependencies. Their nonzero statuses are propagated on the paths described below. The function independently produces status **11** for two visible rejection conditions.

## Behavior

### Initial dispatch

The function captures the root reference and calls F-d1e995cfb2d3 with the root-data address at offset 36. Its signed 32-bit result determines the branch:

- Below one: calculate a new number.
- At least one: use the linked structure.

Thus a negative returned availability value follows the new-number path rather than receiving a corruption error.

Descriptions of counts, links, and entries below refer to values returned by F-d1e995cfb2d3 at the corresponding addresses. Its interpretation as an encoded four-byte reader is inferred, not independently verified.

### New-number calculation

F-f3192f39e4f6 receives the context’s resource field. The function assigns its result plus one to the number output.

It then captures the allocation-number state. If that captured value is nonzero:

1. The number output receives the captured allocation state plus one.
2. F-d7be9cfb4000 receives **1,073,741,824** and the context’s two-byte field at offset 28.
3. The comparison uses the dependency result plus one and the **captured allocation state plus one**.
4. A match assigns the **captured allocation state plus two** to the number output.

Neither the comparison nor the matching assignment rereads the number output after F-d7be9cfb4000. A dependency-mediated change to that output is therefore not the comparison operand; on a match, the explicit assignment overwrites it.

Next, the context byte at offset 22 is tested. If nonzero, F-c76bdec3f9e1 receives the context and the number output’s current value. Immediately after that call, the function captures the number output again.

Only if F-c76bdec3f9e1’s result equals this captured post-call value does the function:

1. Assign the captured value plus one to the number output.
2. Call F-d7be9cfb4000 with the same constant and two-byte context field.
3. Compare that result plus one with the **captured post-F-c76bdec3f9e1 value plus one**.
4. On equality, assign the **captured value plus two**.

This second reserved-number call is skipped when the first comparison fails. Again, no number-output reread occurs between that reserved-number call and its comparison or matching assignment.

The allocation-number state is then reread. If nonzero at that time, it receives the current number output. This condition is independent of whether the earlier captured allocation state was nonzero.

F-14f40f321d22 is called with the context, current number output, object-output address, and mode **0**:

- Nonzero status returns directly, without a local cleanup call on the object output.
- Zero status leads to F-81c906bf6e3a using the bookkeeping field reached through the object output.
- Preparation failure causes F-6cc778185718 to receive the object output’s then-current reference.
- Following successful acquisition, common cleanup also calls F-6cc778185718 twice with zero local references.

The preparation status is returned. Number-output and allocation-state assignments are not locally reversed.

### Exact-search eligibility on the reuse path

Exact searching starts inactive.

If the request is nonzero, F-f3192f39e4f6 is called. When the preferred number is no greater than its unsigned result, F-4549cf6868d1 receives the context, preferred number, auxiliary-output address, and mode **0**.

A nonzero probe status returns immediately. Otherwise:

- Exact searching becomes active only when the auxiliary result’s low byte equals **2**.
- The number output receives the preferred number regardless of that classification.

If the request is zero or the preferred number exceeds the queried extent, neither the probe nor this assignment occurs.

### Availability update and traversal

F-81c906bf6e3a receives the captured root object’s bookkeeping field. Failure returns immediately.

On success, F-cfb711b78946 receives the root-data address at offset 36 and the **initially returned availability value minus one**. This is not based on a fresh availability read after preparation. Interpreting this call as an encoded count decrement depends on the helper contract.

Traversal begins with a call to F-d1e995cfb2d3 at the root’s first-link address. Continued exact searching instead uses the preceding node’s next-link address.

Each returned link value is passed to F-14f40f321d22 in mode **0**, with a local current-node output. The preceding current node is retained as predecessor. On acquisition failure, the current-node local is explicitly zeroed before cleanup; possible partial acquisition effects are unknown.

After successful acquisition, F-d1e995cfb2d3 is called at node-data offset 4. Its result is treated as a signed entry count.

Capacity is checked when the count is nonzero or exact searching is active. The rejection condition is:

**entry count > floor(unsigned 16-bit capacity parameter / 4) − 8**

The limit ranges from **−8** through **16,375**. Rejection returns status **11** through cleanup. Negative counts are not generally rejected.

### Ordinary selection of an empty node

1. Prepare the node.
2. Assign its cached link-derived number to the number output.
3. Invoke the unresolved external dependency with, in order, the root first-link address, the current node’s data-buffer reference, and **4**.
4. Assign the current-node reference to the object output.
5. Clear the current-node local before cleanup.

The external call resembles a four-byte link transfer, but neither copying behavior nor argument roles are established. The explicit output assignments do not depend on verifying such a transfer.

This branch bypasses the capacity check because the count is zero and exact searching is inactive.

### Array-entry selection

This path applies when the node has a nonzero count and exact searching is inactive, or when exact searching is active and the node’s cached number differs from the preferred number.

The node-data reference is captured before preparing the node and is reused afterward.

The initial selected index is zero. With preferred number zero, no distance scan occurs. Otherwise, the function compares the first entry and subsequent counted entries using signed 32-bit differences from the preferred number, followed by conditional negation. A later index replaces the current index only for a strictly smaller signed distance. Representable equal distances retain the earliest entry.

The selected location is read again through F-d1e995cfb2d3. In active exact searching, its low 32-bit value must equal the preferred number. A mismatch causes continuation after predecessor cleanup. This function performs no explicit entry-removal call on that branch, but preparation and unknown dependencies have already run; structural preservation is not guaranteed.

For an accepted entry:

1. Assign the selected low 32-bit value to the number output.
2. Call F-f3192f39e4f6.
3. Compare its unsigned result with the number output **reread after that call**.
4. Return status **11** through cleanup if that output exceeds the result.
5. If the selected index is before the final index, invoke the unresolved external dependency with two visible arguments: the selected-entry address, then the final-entry address.
6. Call F-cfb711b78946 with the captured node-data count address and captured count minus one.
7. Call F-14f40f321d22 with the then-current number output, object-output address, and mode **1**.

The two-argument external call does not establish stable compaction, last-entry replacement, or any particular number of bytes changed.

A successful mode-1 acquisition triggers bookkeeping. The function captures the acquired object’s bookkeeping reference and its owner-like reference, then calls F-b93e3fe564f6 with that owner-like reference.

Afterward, if owner byte 4 is nonzero, bookkeeping byte 31 is zero, and owner byte 19 is zero:

- F-469a239057a8 receives owner field 84 and bookkeeping field 4.
- Bookkeeping byte 28 is explicitly assigned **1**.
- Bookkeeping byte 32 is explicitly assigned **0**.
- If owner byte 9 is then nonzero, F-469a239057a8 receives owner field 88 and the bookkeeping identifier read again.

Acquisition or preparation failure does not cause a local reversal of the earlier count-update call.

### Selecting the node itself during exact searching

When active exact searching reaches a node whose cached link-derived number equals the preferred number, the function:

1. Deactivates exact searching.
2. Assigns the current-node reference to the object output.
3. Prepares the node.

This branch does not rewrite the number output. Its earlier preferred-number assignment may have been affected by intervening dependencies.

For count zero, the unresolved external dependency receives the incoming-link address, current node-data reference, and **4**. The incoming link is in the root or predecessor. No separate predecessor preparation occurs here.

For nonzero count:

1. Read the first entry through F-d1e995cfb2d3 and retain that returned number.
2. Acquire that numbered object in mode **0** as a replacement.
3. Prepare the replacement.
4. Invoke the unresolved external dependency with replacement-data reference, original node-data reference, and **4**.
5. Call F-cfb711b78946 with replacement-data offset 4 and original count minus one.
6. Invoke the unresolved external dependency with replacement-data offset 8, original node-data offset 12, and **four times original count minus one**.
7. Pass the replacement reference to F-6cc778185718.
8. If a predecessor exists, prepare it.
9. Call F-cfb711b78946 with the incoming-link address and retained replacement number.

The third argument in step 6 is **4 × (count − 1)**. For a valid positive count passing capacity validation, it is at most **65,496**. Negative counts lack equivalent protection.

These calls suggest promotion of the first entry into a replacement node. Actual replacement contents and relinking depend on unverified helper semantics. A successful path clears the selected current-node local before cleanup.

Replacement-acquisition failure goes directly to current/predecessor cleanup. Replacement-preparation failure first passes the replacement reference to F-6cc778185718.

## Side effects

Explicit effects include output assignments, allocation-state assignments, bookkeeping-byte assignments, and the owner accounting decrement. Additional effects are requested through dependencies at count, link, entry, and object-state locations.

No output is guaranteed unchanged on error. The object-output slot can retain a reference passed to F-6cc778185718; it is not cleared afterward.

Common error cleanup passes current-node and predecessor references to F-6cc778185718, including zero values. Paths passing through the traversal tail first clean up the predecessor, zero that local, and then either continue or enter common cleanup. Successful node-return paths clear the current-node local to avoid passing that reference through common cleanup.

This supports an inferred reference-transfer convention, not a proven ownership contract. Acquisition-failure ownership, zero-reference handling, and actual release effects remain unknown.

Captured references, counts, and data addresses survive intervening calls. No dependency is assumed to preserve globals, outputs, object fields, or buffer addresses. Post-call rereads and cached operands therefore remain distinct throughout this contract.

## Acceptance examples

These are conditional static expectations, not runtime observations.

1. **Simple new number.** With nonpositive availability, extent result 100, allocation state zero, and additional checking disabled, the function explicitly assigns 101 before mode-0 acquisition. Successful acquisition and preparation lead to status zero.

2. **Cached allocation operand.** With captured allocation state 40 and reserved-number result 40, the comparison matches and the function explicitly assigns 42—even if that dependency changed the number output to 900. Later calls may change it again.

3. **Cached additional-check operand.** Suppose F-c76bdec3f9e1 returns 50 and the immediately reread number output is 50. The function assigns 51. If the following reserved-number call returns 50 while changing the output to 900, the function assigns 52 from the cached 50.

4. **Equal-distance choice.** With stable entry-reader results 10 and 14, preferred number 12, and representable arithmetic, index zero remains selected. If its reread returns 10, the function explicitly assigns 10 before querying the extent.

5. **Ordinary empty node.** With inactive exact searching, cached node number 25, and count zero, successful preparation leads to number-output assignment 25, the three-argument external call, and object-output assignment. A resulting root link of 30 is expected only if the node contains that link and the external dependency implements the inferred transfer without intervening changes.

6. **Capacity rejection.** With capacity parameter 64 and returned entry count 9, status 11 follows the earlier availability-update call. An actual stored decrement additionally requires the inferred writer contract.

7. **Post-query output matters.** If selection assigns 101, the extent query returns 100, and the output remains 101, status 11 follows before the explicit entry-removal calls. If that query changes the output, the comparison uses the changed value.

8. **Exact mismatch.** With exact searching active and a selected reread unequal to the preferred number, traversal continues without this function issuing the entry-removal calls for that candidate. Node preservation is not an acceptance guarantee.

9. **Conditional replacement contents.** For a targeted node whose entry reads identify 40, 50, and 60, the function acquires 40 and issues the replacement-related calls in the specified order. Contents comprising the former next link and entries 50 and 60 require the inferred read, write, and transfer contracts, stable storage, and successful checked calls.
