# F-071d666c616a

## Purpose

F-071d666c616a performs an ordered sequence of memory reads and mixed-width writes, then transfers control through an unresolved indirect dependency.

Established effects include self-address stores, word copies, low-byte and low-halfword stores, repeated accesses to mutable address-bearing fields, and stores through addresses formed by addition or multiplication.

No application-level purpose is established. Constructor, parser, serializer, and object-management interpretations would be inferred intent, not demonstrated behavior. This contract therefore describes observable accesses without assigning structure types or ownership roles.

## Interface

### Explicit inputs

| Input | Width | Established use |
|---|---:|---|
| First argument | 32 bits | No visible use. |
| Second argument | 32 bits | No visible use. |
| Third argument, designated **P** | 32 bits | Address-bearing value; written to P+0x54 at entry. |
| Fourth argument | 8 bits | Written to C+0x11 near entry. |

P has a signed 32-bit representation but is used as an address. No validation precedes its first use.

### Implicit inputs

Three incoming machine-state values, designated **A**, **B**, and **C**, are used without visible initialization. They supply bases for memory accesses; their relationship to the explicit arguments is unknown.

Three external storage locations, designated **G1**, **G2**, and **G3**, supply separate 32-bit reads near the end. These labels identify storage locations, not immutable values. The contract does not assume they are disjoint from earlier writes.

### Result and control transfer

There is no represented return value.

The final represented invocation supplies three 32-bit arguments to **F-UNRESOLVED-01**. A return follows in the representation, but the actual transfer mechanism, calling convention, and destination’s return behavior are unresolved.

### Memory widths and address interpretation

All offsets are byte offsets:

- Byte accesses transfer 8 bits.
- Halfword accesses transfer 16 bits.
- Word accesses and address-bearing fields transfer 32 bits.

“Low byte” and “low halfword” mean the least significant 8 or 16 bits of a captured value. They do not mean the first byte or halfword in its in-memory representation.

Offset 0x64 equals decimal offset 100. This offset is distinct from stores of the numeric value 0x64.

Successful completion requires every address actually reached to support its specified access, including unusual computed addresses and potentially unaligned stores. Initial base validity alone is insufficient.

No null, bounds, alignment, or access checks are visible. Byte order, supported alignment, integer-to-address mapping, and permitted aliasing are not established.

## Behavior

### Ordering and captured values

The following phases preserve the represented order of memory accesses. Descriptive labels denote values captured at particular reads, not fields assumed to remain stable.

Any earlier store may affect a later read through aliasing. Conversely, changing a field does not change an address already captured from it. Repeated reads and stores remain distinct observable accesses, even when they appear to preserve bits.

### 1. Entry and initial captures

The first memory effect is a word store of P to P+0x54.

Next, an address is read from A+0x14. The fourth argument is written as a byte to C+0x11, then a word is read from C+0x14. Call this word **Initial-C**. Its low byte is written at offset 0x15 through the address obtained from A.

A fresh read of C+0x14 supplies address **N**. A word read from B+0x64 supplies **H**, which is immediately written back to B+0x64.

The subsequent accesses, in order, are:

- Byte 0x73 is written to N+0x0C, followed by the low byte of H to B+0x15.
- Initial-C is written to C+0x34, then N+0x74 is read and retained as **Early-Link**.
- N is written to N+0x54. The low byte of B is written to C+0x0D.
- Initial-C is written to C+0x54, then N is written to C+0x14.

The first and second C+0x14 captures need not agree: the intervening byte store may alias that field.

### 2. Mixed-width writes and the N+0x60 interleaving

A second word read from B+0x64 supplies **J**.

The function writes byte 0x74 to N+0x10, word 0x00000074 to B+0x54, and word 0x00000074 to N+0x10, in that order. It then rereads N+0x74, capturing **Retained-Link** independently of Early-Link.

Next come word stores of C to C+0x54 and 0x00000074 to N+0x30. The low byte of H is written to B+0x01, the low byte of J to H+0x09, and J as a word to B+0x74.

The next interleaving is significant:

1. Byte 0x74 is written to B+0x11.
2. A word is read from N+0x60.
3. The low byte of H is written to B+0x11.
4. J is written as a word to B+0x34.
5. The low byte captured from N+0x60 is written to N+0x10.

Thus, the N+0x60 read occurs between the two B+0x11 stores. Its value cannot generally be determined by moving it before both stores or after both.

The last N+0x10 access writes only one byte. The other bytes of the preceding word store remain subject to intervening aliasing effects.

### 3. Stores through B-derived addresses

An address is read from B+0x14; call it **First-Target**. The function then writes the low byte of Early-Link to C+0x11, C as a word to B+0x44, and the low byte of J to B+0x11.

A word read from B+0x74 supplies **Earlier-B-Link**. After that capture, the function writes the low byte of C to B+0x0D and word 0x00000066 to First-Target+0x10.

It writes C to B+0x44 again, byte 0x66 to First-Target+0x10, word 0x00000066 to B+0x54, and word 0x00000066 to First-Target+0x60.

A fresh read of B+0x74 supplies **Q**. B+0x74 is then replaced with C, but Q remains the captured address used next.

Word 0x00000066 is written to Q+0x40, followed by the low byte of Earlier-B-Link to B+0x0D. A word read from Q+0x44 supplies **Q-Word**.

The function writes B to B+0x54, then writes Retained-Link to Retained-Link+0x54. It reads Q+0x14, writes the low byte of Q-Word to C+0x11, and reads C+0x14. The low byte of this last read is written at offset 0x15 through the address captured from Q+0x14.

### 4. Distinct B+0x64 captures around the word-0x73 store

A fresh C+0x14 read supplies address **Current-C**. The following three accesses are distinct and ordered:

- B+0x64 is read, capturing **Before-73**.
- Word 0x00000073 is written to Current-C+0x20.
- B+0x64 is read again, capturing **After-73**.

The word store may overlap B+0x64, so these captures must not be merged.

The low byte of After-73 is written to Current-C+0x09. Current-C+0x74 is then read to obtain **D**.

At D, the function writes the low byte of B to offset 0x0D, reads the word at offset 0x54 and writes it back to that same field, then writes byte 0x74 to offset 0x09.

Before-73 is written as a word to B+0x44. B is written to D+0x34, and D+0x04 is read to obtain **E**.

After-73 is written as a word to E+0x24. The low byte of Before-73 is written to B+0x19.

Finally, E+0x74 is read and captured as **E-Link**, followed by a word read from E+0x04, captured as **E-Word**.

Accordingly, Before-73 supplies B+0x44 and B+0x19. After-73 supplies Current-C+0x09, E+0x24, and the duplicated byte stores described next.

### 5. Separate traversals through a reread B+0x74 address

B+0x74 is reread to obtain **Chain-Base**. Its offset 0x14 is read, and E-Link is written at offset 0x54 through that captured address.

A first read of Chain-Base+0x04 supplies **First-Branch**. The function then:

- Writes the low byte of After-73 to B+0x0D twice consecutively.
- Writes E-Word as a word to B+0x64.
- Writes word 0x00000074 to First-Branch+0x30.

Only after these stores does a fresh read of Chain-Base+0x04 occur. Offset 0x74 through this newly obtained address is then read to obtain **Z**.

The first and second Chain-Base+0x04 reads are not interchangeable. The second traversal does not reuse First-Branch; intervening stores may have changed the field.

A word is next read from B+0x64, and its low byte is retained as **Later-Byte**. Later-Byte is written to B+0x1D.

The function reads B+0x44, then reads offset 0x14 through that captured address to obtain **Replacement-Target**. E-Link is written to Z+0x34 **before** Replacement-Target is written to B+0x14.

Next, B+0x54 is read and retained as **Previous-B54**. The low byte of B is written to Replacement-Target+0x09.

### 6. Downstream captures and fresh acquisition of U

The function reads Z+0x04, then offset 0x74 through that captured address, obtaining **Downstream**.

The following order is preserved:

- The low byte of E-Link is written to Downstream+0x15.
- B is written as a word to B+0x54.
- The low byte of Z is written to B+0x11.
- The low byte of Previous-B54 is written to Downstream+0x11.
- A word is read from Downstream+0x64, captured as **Downstream-Word**.
- Later-Byte is written to B+0x09.
- A fresh read of Z+0x04 obtains **U**.

In particular, the B+0x11 store precedes both the Downstream+0x11 store and Downstream+0x64 read. The B+0x09 store precedes the read obtaining U. U need not equal the earlier Z+0x04 capture.

At U, the low byte of B is written to offset 0x09. A word is read from U+0x50 and retained as **U-Word**. The low byte of Downstream-Word is written to U+0x11, then the low byte of B is written to U+0x09 again.

Downstream-Word is written as a word to B+0x14. The low byte of U is written to B+0x0D, followed by the low byte of U-Word to U+0x00.

### 7. Final object-relative accesses

Z+0x74 is read and captured as **Tail-Link**. Z+0x14 is then read to obtain **Final-Base**.

U is written as a word to U+0x54. A read from Final-Base+0x04 supplies **V**.

The subsequent writes occur in this order:

- Byte 0x64 to V+0x10.
- Word 0x00000064 to B+0x54.
- Word 0x00000064 to V+0x40.
- The low byte of Downstream-Word to B+0x0D.
- The low byte of V to Final-Base+0x09.
- Downstream-Word as a word to B+0x24.
- The low byte of B to Final-Base+0x11.

### 8. Computed-address tail and terminal invocation

G1 is read as a 32-bit value. B+0x74 is then read again, capturing **W**.

The function performs these accesses in order:

1. Stores the low halfword of W at address W+B.
2. Stores the low halfword of captured G1 at address twice V.
3. Reads one character at address Tail-Link+B and converts it to an unsigned 32-bit value, **K**.
4. Stores the low halfword of W at address captured G1+W.
5. Repeats the halfword store of W at W+B.
6. Stores word 0x00000045 at K+0x45.

G2, G3, and B+0x44 are then read, in that order. The resulting captures are retained independently of subsequent stores.

Next, byte 0x44 is written to K+0x44. Captured G3 is written as a word at twice captured G2. The low halfword of captured G2 is written at E-Link+captured G2.

The terminal dependency receives:

| Argument | Value |
|---|---|
| First | K bitwise-inclusive-OR 0x44 |
| Second | Captured G2 |
| Third | The final captured B+0x44 word |

The first argument uses bitwise OR, not addition.

K is explicitly unsigned and 32 bits wide. Its offset additions therefore have represented unsigned 32-bit arithmetic. The other tail sums and products use signed 32-bit address-bearing representations; their overflow behavior must not be silently replaced by modular arithmetic. Mapping any resulting integer to an accessible address remains a separate unresolved requirement.

## Side effects

The visible body mutates memory reachable through explicit arguments, implicit bases, mutable chains, and computed addresses.

No allocation, deallocation, ownership transfer, synchronization, logging, or explicit error result is visible before the terminal invocation. This does not establish what F-UNRESOLVED-01 does.

The caller must ensure that storage required by reached accesses remains available. No visible operation establishes that an input is consumed or released.

There is no represented rollback path. If a later access fails, earlier writes have already occurred in the represented sequence. Exact fault delivery and partial-store behavior are documented_only.

Final memory cannot generally be described by choosing the last store to each named offset: different bases, external storage, and computed destinations may overlap.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes all preceding accesses complete.

1. **Entry effect.** If P+0x54 is writable, the first memory effect writes P there as a word. Neither unused explicit argument participates in that access.

2. **N+0x60 interleaving.** If N+0x60 overlaps B+0x11, its captured word reflects the preceding byte-0x74 store, subject to byte order and other overlapping bytes. The later low-H store cannot retroactively change that capture.

3. **Distinct captures around 0x73.** If Current-C+0x20 equals B+0x64 and Before-73 is 0x123456AB, the intervening word store makes After-73 equal 0x00000073. With no further relevant aliasing, B+0x44 receives 0x123456AB and B+0x19 receives 0xAB; E+0x24 receives 0x00000073 and the duplicated B+0x0D stores write 0x73.

4. **Fresh branch traversal.** If an intervening store changes Chain-Base+0x04, the word-0x74 store still uses First-Branch, while the later traversal obtaining Z uses the changed field value.

5. **Later read boundaries.** If Z+0x34 overlaps B+0x54, the Previous-B54 capture observes the intervening E-Link store, absent another overlapping write. If B+0x09 overlaps Z+0x04, the later read obtaining U observes that byte mutation.

6. **Partial overwrite.** Without other interference, the final byte write to N+0x10 changes only that byte. On a little-endian system, a captured low byte of 0xA5 changes the earlier word 0x00000074 to 0x000000A5.

7. **Character conversion.** A character byte of 0x7F produces K=127 under either ordinary character signedness. A byte of 0xFF may produce K=255 or K=0xFFFFFFFF. The supplied representation does not select character signedness.

8. **OR rather than addition.** If K=0x44, the first terminal argument is 0x44, not 0x88. This does not establish validity of the preceding K-relative accesses.
