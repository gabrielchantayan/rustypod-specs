# F-9c5459b25fbd

## Purpose

The supplied static representation describes indirect calls interleaved with byte and 32-bit memory accesses, scaling, masking, and transfers of call-produced values. Its application-level purpose is not established.

The visible behavior includes:

- Reading bytes and treating their unsigned values as small numeric address components.
- Reading 32-bit words and storing their low bytes elsewhere.
- Writing transformed values at computed addresses with offsets 13, 20, 36, and 52.
- Supplying transformed values and halves of wide results to unresolved dependencies.
- Writing directly to absolute addresses 13 and 17.

These operations do not establish an allocator, serializer, hardware interface, or conventional object initializer.

The representation reports unreliable control flow and ends at an invalid-instruction boundary. This contract therefore describes a **conditional static trace**: an operation applies only if execution reaches it, preceding dependencies return, and the supplied representation accurately describes execution. No normal completion is established.

## Interface

### Inputs

The displayed interface declares no explicit arguments and no return value. This does not establish an argument-free machine interface. The trace consumes:

- An incoming 32-bit address-like value, also used as an unsigned value shifted right by two.
- A second incoming 32-bit value supplying bits 22–29 for the first byte store.
- An incoming link-register-derived value used to construct the first indirect-call target.
- Bytes and words read from computed addresses.
- Ordinary 32-bit call results and results represented as 64 bits.
- Additional call-associated register values whose production and preservation contracts are not recovered.

No validation of these inputs is visible.

### Widths and arithmetic

A byte is 8 bits; a word is 32 bits. A represented 64-bit result has separately consumed low and high 32-bit halves.

Byte stores retain the low eight bits of their source. Byte loads used in address calculations are unsigned: 255 contributes positive 255. Explicit unsigned right shifts are logical.

For the arithmetic examples and computed addresses in this contract, 32-bit scaling, addition, and left shifting retain the low 32 bits. This is the contract’s reconstruction convention for the represented machine-width calculations, not proof that every signed-looking expression has defined language-level semantics.

In particular, clearing the top two bits of a 32-bit value changes neither its product by four nor its product by sixteen under this convention. That equivalence does not make distinct memory stores interchangeable.

Endianness, alignment requirements, pointer validity, and the complete calling convention are unknown.

### Outputs and prerequisites

No normal return value is established. Observable outputs are direct memory writes, indirect calls with their displayed arguments, dependency effects, and possible arrival at the invalid-instruction boundary.

Following the complete trace requires every reached access to be valid for its width and every reached dependency to return. These are unchecked execution prerequisites, not guarantees. There is no visible status result, recovery branch, rollback, or cleanup protocol.

## Behavior

### Reading conventions

The following descriptive names distinguish retained values; they do not identify recovered implementation symbols:

- **Entry address**: the first incoming address-like value.
- **Entry payload**: the incoming value supplying the first stored byte.
- **Quarter value**: entry address logically shifted right by two.
- **Selected destination**: address 17 plus a freshly loaded unsigned byte.

A selected destination is therefore between addresses 17 and 272 inclusive. It is not a pointer-sized address loaded from memory.

The phases below preserve the order of direct memory accesses and argument-bearing calls. Unresolved calls also occur between the described operations. They are not assumed harmless, memory-preserving, or normally returning. A retained scalar is distinguished from a later memory read; repeated address expressions do not permit reuse of an earlier loaded byte.

### 1. Initial selected writes

The quarter value is computed before the first call. Three indirect calls occur initially. The first target is formed from the incoming link-register-derived value plus 4094; the third call produces a result used by the next argument-bearing call.

Before that next call:

1. Read a byte at entry address plus 1.
2. Write the low byte of entry payload logically shifted right by 22 to the selected destination.

The next argument-bearing call receives the third result multiplied by four.

Following intervening calls, read a byte at quarter value multiplied by 524,288, plus 1, and write zero to its selected destination.

A call then receives, in order:

- Quarter value multiplied by eight.
- The same multiplied value.
- Quarter value.
- Zero.

After further calls, read the same quarter-derived byte address again. Retain this new byte and clear its selected destination. A subsequent argument-bearing call receives a recent result multiplied by four.

### 2. Initial word-to-byte transfers

After intervening calls, read a 32-bit word at retained byte plus 116 and write its low byte at retained byte plus 1.

The next argument-bearing call receives:

1. Quarter value multiplied by 1,048,576.
2. The retained quarter value.
3. The low 13 bits of quarter value shifted left by 17.
4. The retained byte.

A following call produces a wide result. Another call receives its low half, high half, low half again, and the low 12 bits of quarter value shifted left by 18.

After more calls, scale a result by four. Read a word at that base plus 116, write its low byte at base plus 1, and pass the base to a call.

Following additional calls, read a byte at quarter value multiplied by 1,048,576, plus 1, and clear its selected destination.

A later call receives an incompletely recovered register value. The next call result is retained and passed to another call; call it the **retained address result**.

After further calls, freshly read the same quarter-derived byte address. Write the low byte of the logical right shift by 24 of quarter value multiplied by 1,048,576 to the newly selected destination. A subsequent call receives a recent result multiplied by four.

### 3. Returned-value indirection

After more calls, multiply a new result by four; retain this as the **scaled indirection base**.

Read a word at retained address result plus 4. Read a byte at that word’s value plus 1 and clear its selected destination. A call receives the scaled indirection base three times.

After intervening calls, logically shift the loaded word right by two. Read a byte at that shifted value plus 1 and clear its selected destination. Retain this byte as a **small byte base**. A subsequent call receives a recent result multiplied by four.

Following more calls, perform these accesses in order:

1. Read a word at scaled indirection base plus 4; retain it as the **field-source word**.
2. Read a word at small byte base plus 116; retain it as the **transfer word**.
3. Write the transfer word’s low byte at small byte base plus 1.

A call receives the transfer word, two copies of scaled indirection base shifted left by 19, and a recent result multiplied by four.

The next call produces a result. Before that result is passed onward, the field-source word is logically shifted right by 22 and retained as the **field value**. The onward call receives the result and transfer word logically shifted right by two.

The field-source word and the earlier word read through retained address result are distinct reads with distinct roles.

### 4. Offset-20 word stores

After further calls, multiply a new result by four. Read a word at that base plus 116, write its low byte at base plus 1, and pass the base to a call.

Following intervening calls, write the entire loaded word at four times an incompletely recovered register value, plus 20. Pass that register value to a call.

A later call receives a recent result followed by two copies of the low nine bits of field value shifted left by 21.

After more calls, a result selects a destination at four times that result plus 20. Store field value shifted left by 23 there, then pass the scaled destination base to a call.

A subsequent result, the **scaling result**, is used for a separate word store:

- Destination: scaling result multiplied by sixteen, plus 20.
- Stored value: scaling result multiplied by four.

Retain the stored value as the **scaled payload**. Mask the scaling result to its low 30 bits, retain one quarter of that masked value, and pass the masked value to a call.

After another call group, write the masked value at four times a fresh result plus 20. Retain that fresh result as the **destination selector**, and pass its four-times base to a call.

These are separate stores in the displayed order. Under 32-bit arithmetic, masking the scaling result before calculating its products by four and sixteen would produce the same products. The evidence therefore does not establish an observable requirement to delay that mask; it does establish the two stores and their intervening call sequence.

### 5. Linked byte and offset-52 writes

## Acceptance examples

These are conditional static consequences, not executed tests.

1. **Initial selector.** If the first selector byte is 5 and the relevant shifted payload has low byte 171, the first direct store writes byte 171 at address 22.

2. **Unsigned addressing.** A selector byte of 255 selects address 272, not a negative address.

3. **Access width.** A word read yielding `0x123456AB` supplies byte `0xAB` to its paired byte store. The source access remains 32 bits wide.

4. **Fresh read after dependencies.** If a dependency changes a selector from 3 to 9, the next explicit read selects address 26 rather than reusing address 20.

5. **Mask equivalence and separate stores.** For scaling result `0xC0000001`, the phase-4 product-by-sixteen destination is address 36 and the product-by-four payload is 4 under 32-bit arithmetic. Masking to `0x00000001` before either multiplication produces the same destination and payload. The later store of masked value 1 remains a separate operation at the fresh-result-selected destination, after intervening calls.

6. **Absolute-address ordering.** Reaching both phase-8 absolute stores writes small selector to address 13 first and 192 later. If small selector is zero, the intervening doubled-small-base offset-13 store also targets address 13. Subsequent dependency effects remain unknown.

7. **Invalid access.** An inaccessible reached address has no visible checked fallback or recovery path. Actual fault behavior is platform-dependent.

8. **Termination.** Reaching the terminal boundary is not evidence of normal return or success.
