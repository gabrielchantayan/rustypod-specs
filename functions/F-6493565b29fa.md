# F-6493565b29fa

## Purpose

F-6493565b29fa searches an externally supplied table of 74 candidate pointers and returns either the index of an accepted candidate or the distinguished failure value 75.

The search has two stages:

1. Find the first table entry whose first byte equals the first byte at the caller-supplied input address.
2. Starting at that entry, ask dependency F-fca51b715561 to evaluate consecutive candidates with matching first bytes. Return the first index for which the dependency returns zero.

Once the second stage begins, a candidate with a different first byte terminates the entire search. The function does not resume scanning for a later matching group.

The apparent intent is a first-byte-grouped lookup with a delegated full comparison. Grouping, string semantics, and the meaning of the additional argument are not established by the available evidence.

## Interface

**Inputs**

- **Input address:** An address from which the function reads a first byte and which it also passes to F-fca51b715561. The visible implementation treats this as a character pointer, but establishes neither a length nor a requirement for a terminating zero byte.
- **Auxiliary argument:** An opaque 32-bit value passed unchanged to every invocation of F-fca51b715561. The visible implementation does not interpret it.

**External search data**

An external storage location supplies the table base address. The function reads that location once at entry and retains the resulting base address for this invocation.

The table is addressed as 74 consecutive pointer slots, each four bytes wide. The searchable indices are 0 through 73 inclusive. A pointer loaded from a slot identifies the candidate whose first byte is inspected and which may be passed to the dependency.

The source representation establishes a four-byte table-slot stride. Endianness and the broader platform ABI are not independently established here.

**Output**

The result is an unsigned 32-bit value:

- **0–73:** Index of a candidate for which F-fca51b715561 returned zero.
- **75:** No accepted candidate was found under the search rules.
- **74:** Not returned by any visible normal completion path.

The successful index is masked to its low eight bits before return. Because every successful index is already between 0 and 73, that mask does not change the numerical result.

**Dependency call interface**

For each candidate evaluated by F-fca51b715561, the arguments are supplied in this order:

1. The candidate address loaded from the table.
2. The original input address.
3. The unchanged auxiliary 32-bit value.

Only whether the dependency’s result equals zero is significant. Every nonzero result has the same effect on this function’s search progression.

## Behavior

### Entry and initial scan

The function first captures the table base address and initializes the search index to zero.

For each index examined during the initial scan, it obtains the candidate pointer from that table slot and compares the candidate’s first byte with the first byte at the input address.

- If the bytes differ, the index advances by one.
- If advancing would move the initial scan beyond index 73, the function returns 75.
- If the bytes match, the function enters the candidate-evaluation stage at that same index.

No invocation of F-fca51b715561 occurs for an entry skipped because of a first-byte mismatch during the initial scan.

The comparison is an equality test on individual bytes. No case folding, encoding conversion, locale processing, or multi-byte character interpretation is visible. Whether the source language treats a character as signed does not change equality between the two byte values.

### Candidate-evaluation stage

At the first matching index, the function reloads the candidate pointer from that slot and repeats the first-byte comparison before invoking the dependency. The initial matching comparison therefore does not eliminate this second lookup and check.

For each index in this stage:

- The candidate pointer is loaded from the current table slot.
- Its first byte is compared with the byte currently stored at the input address.
- If the bytes differ, the function immediately returns 75.
- If the bytes match, F-fca51b715561 is called with the candidate address, input address, and auxiliary argument.
- If the dependency returns zero, the function immediately returns the current index.
- If the dependency returns nonzero, the index advances and the same evaluation rules apply to the next entry.

A first-byte mismatch in this stage ends the search even if a later entry would have a matching first byte or would be accepted by the dependency.

If every candidate from the start of this stage through index 73 has a matching first byte and receives a nonzero dependency result, the function returns 75. It does not dereference a table slot at index 74.

### Bounds and arithmetic

All candidate-pointer loads made by the visible search occur at indices 0–73. With a four-byte stride, the last slot begins 292 bytes after the captured table base. A complete table of the represented layout therefore occupies 296 bytes of pointer slots, excluding the pointed-to candidate storage.

The internal index begins at zero and increases monotonically. On the visible paths it never approaches a signed or unsigned 32-bit limit. Consequently:

- The signed comparisons used for bounds checking do not change the outcome for any reachable index.
- Multiplication of a reachable index by four does not overflow a 32-bit integer.
- The return-value mask cannot truncate a successful index.

The bounded offset calculation does not by itself establish that adding the offset to the supplied table base produces a valid address. Valid table placement remains a precondition.

### Data changes during execution

The function does not take a snapshot of the table entries, candidate bytes, or input byte.

The captured table base remains the basis for later slot accesses even if a dependency changes the external storage location from which that base was originally obtained. In contrast, subsequent slot loads and byte comparisons use the contents available when those operations occur.

This distinction matters after a nonzero dependency result:

- A later table slot may contain a different pointer than it did at entry.
- A later candidate’s first byte may have changed.
- The input’s first byte may have changed, changing which following candidates pass the first-byte check.

The function does not recheck the current candidate’s first byte after a dependency returns zero. A zero result causes an immediate successful return for that index.

These statements describe the visible reads and control flow. They do not establish synchronization, atomicity, or safe behavior under concurrent mutation.

## Side effects

The visible body performs no explicit writes to the input, table, candidate storage, or external table-base storage. Its direct effects are reads, dependency invocations, and production of a return value.

The source establishes the following observable sequencing:

1. The external table base is read before scanning begins.
2. During the initial scan, the current candidate pointer is obtained before its first byte can be compared.
3. At the transition into candidate evaluation, the same slot is loaded again and its first-byte condition is checked again.
4. Each dependency invocation follows that candidate’s successful first-byte check.
5. After a nonzero dependency result, the next candidate’s reads occur before any dependency call for that next candidate.
6. A zero dependency result or an evaluation-stage first-byte mismatch prevents all later candidate evaluations.

The evidence does not establish a machine-level ordering between the two operand-byte reads within a single equality comparison. It also does not establish access atomicity or volatile-access semantics.

F-fca51b715561 may have side effects not shown here. No claim is made that it preserves global storage, the table, the input, candidate contents, or any ownership relationship.

There is no visible allocation, explicit release, ownership transfer protocol, or cleanup step in this function. Passing an address to the dependency does not establish whether that dependency retains, modifies, or releases the associated storage.

For normal completion, every pointer and byte actually accessed must remain readable when accessed. In particular, candidate storage and input storage required by later iterations must remain valid after earlier dependency calls.

Invalid addresses are not converted into the failure value 75 by any visible check. Their resulting platform behavior is unspecified by this contract.

1. **No matching first byte**

4. **Acceptance within a contiguous matching run**

   **Expected:** Return 75 upon checking entry 13. Do not call the dependency for entry 13 or entry 14.

6. **Final entry accepted**

   **Expected:** Return 73. Do not access a slot beyond index 73.

7. **Final entry rejected**

   **Expected:** Return 75, not 74. Do not access slot 74.

8. **Nonzero results are not ordered**

   Two consecutive eligible candidates receive dependency results of −1 and a positive nonzero value, respectively.

   **Expected:** Both are treated as rejections. Neither result’s sign nor magnitude creates a distinct branch.

9. **Input mutation changes the next check**

   A dependency call returns nonzero after changing the input’s first byte. The next candidate begins with the old byte but not the new byte.

   **Expected:** The next first-byte check fails and the function returns 75, provided all accesses remain valid.

10. **Zero first byte**

    **Expected:** Zero is treated as an ordinary equal first byte, so the dependency is invoked. An empty-string interpretation is not independently established.
