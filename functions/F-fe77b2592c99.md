## Behavior

The function first reads the dispatch-table reference from the object and resolves the callable entry at byte offset 196.

It invokes that operation with the same object reference supplied by the caller. It retains the operation’s 32-bit result without inspecting it.

This call occurs before the query. It is not conditional on the query result, and the function does not skip it when the eventual branch will discard its result.

A captured value of zero receives no special treatment. All 32-bit patterns are treated identically at this stage.

### Query and branch selection

After the initial indirect call returns, the function invokes F-a9f7d0b7f7ab with no explicit arguments.

Only the distinction between zero and nonzero matters:

- Zero selects the second object-associated operation.
- Any nonzero result selects F-8d197225a4c2.

Negative values and positive values therefore select the same nonzero branch under the represented 32-bit integer model. There is no separate error path for negative results.

The query is performed once on a normal execution path. No retry, polling loop, or alternative query is shown.

### Zero-result branch

If F-a9f7d0b7f7ab returns zero, the function resolves the dispatch-table entry at byte offset 184 and invokes it with:

1. The original object reference.
2. The numeric argument 16, hexadecimal 0x10.

The dispatch-table reference for this call is obtained from the object after the initial operation and the query have run. The supplied representation does not reuse a saved dispatch-table reference from the first call.

Consequently, if either earlier dependency changes the dispatch-table reference stored in the object, the zero-branch dispatch uses the reference present at this later lookup, provided that access remains valid.

The captured 32-bit value is not passed to this operation. No direct call to F-8d197225a4c2 occurs on this branch.

### Nonzero-result branch

This is the value produced by the initial indirect call, retained across the intervening query. The function does not recompute it or replace it with the query result.
