# F-363f884d7ae3

## Purpose

F-363f884d7ae3 conditionally constructs two related objects, configures the second, calculates a two-component placement, and publishes their handles into a mutable context.

Creation can be deferred by a relationship check, measurements, a shared counter, and a dependency’s secondary output. Creation resets the counter before allocating storage. Publication is staged: the first handle is stored before the second object is constructed; the second handle is stored only after placement submission and final configuration.

These operations are established by static evidence. “Object,” “measurement,” “direction,” and “placement” describe inferred roles, not established application semantics.

## Interface

### Input, result, and preconditions

The sole explicit input is a 32-bit address-like value identifying a mutable context. No explicit return value or error result is represented.

The function performs no visible validation of addresses, accessible extents, allocation results, or constructed handles. A normally completing execution requires all reached accesses and dependency calls to be valid. The required storage depends on the selected branches.

## Behavior

### Initial lookups and eligibility

F-5710a8628cba is called twice, in order. Each call receives the context fields at `0x38` and `0x44`, with an externally supplied selector between them.

The selectors are read from **two different external locations**. Their values are not established as different.

The context fields are read separately for each call. Consequently, effects of the first lookup can change the second lookup’s arguments. Relative evaluation order among arguments within a single call is not established.

After both lookups, the external shared-state reference is captured. If the second result is nonzero, its field at `0x04` is read. A zero second result or zero field causes immediate return.

This return performs no direct context or counter write and requests no allocation. Both lookup calls have nevertheless occurred and may have effects.

### Deferral gate

The function evaluates these conditions in order, stopping when one fails:

1. The first lookup result is nonzero.
2. F-8b354e218ab8 returns nonzero for the first result and the second result’s region at `0x98`.
3. The first result’s span, interpreted as unsigned 32 bits, is strictly less than the context’s first measurement plus unsigned 90.
4. The signed shared counter is less than 3.

For the third condition, the ending bound at `0x0c` is read first, then the starting bound at `0x04`, then F-19fde5f06ccc is called on the context region at `0x80`.

The span subtraction is represented as signed 32-bit arithmetic before unsigned interpretation. The threshold addition is unsigned 32-bit arithmetic, modulo \(2^{32}\). This is not a signed distance comparison; a representable negative span converts to a large unsigned value.

When all conditions hold:

- The counter is reread, incremented, and written.
- The ending and starting bounds are reread in that order.
- F-19fde5f06ccc measures the context again.
- If the new signed span is strictly less than this new signed measurement, the function returns.
- Otherwise F-eec8106f4698 is called, followed by F-870c4fcf7295 with its result and \(6-\text{counter}\).
- A nonzero 32-bit secondary output from F-870c4fcf7295 causes return.

The counter used in the subtraction is read **after** F-eec8106f4698 returns. It need not equal the value previously written by the increment.

Neither deferral return rolls back the increment. The secondary output’s meaning is unknown. In particular, no remainder or Boolean API contract is established.

### Construction and configuration

1. Requests `0xb8` bytes through F-8157a180d901.
2. Passes that result and the retained second lookup result to F-11198946fd75.
3. Stores the returned first handle at context offset `0x1b4`.
4. Requests `0x130` bytes through F-8157a180d901.
5. Calls F-ffe0d92c57b7 with the context.
6. Calls F-b07a62920ca7 with the second allocation result, the retrieved handle’s field at `0xf4`, the context’s current field at `0x1b4`, and constant 1.
7. Calls F-c57b56681a78 with the resulting second handle and 100.

No allocation or construction result is explicitly checked. The second handle is retained for later calls even if dependencies alter context fields.

### Mode selection

If the current field at `0x1dc` equals 1:

- Subtype 2 selects mode 6.
- Every other subtype selects mode 12.

Otherwise, subtype 2 bypasses the measurement comparison. For another subtype, F-b01436b9ce2b measures the context region first and the second lookup result’s region second. The retained signed results are compared.

If the context result is strictly smaller:

1. F-eec8106f4698 returns a 32-bit value.
2. The current mode byte at `0x1c4` is then read and zero-extended.
3. F-d7be9cfb4000 receives that byte value, plus the returned value’s low three bits, plus 2; its second argument is 12.
4. Its observed 8-bit secondary output is stored as the mode.

The mode input is therefore captured **after the value-source call**, not before it. The first argument lies between 2 and 264, so this addition does not overflow 32 bits.

If this calculated-selection branch is not taken, mode 6 becomes 0, and every other current byte value becomes 6.

A modulo-12 interpretation of F-d7be9cfb4000 is inferred intent only.

### Adjustment against the first lookup result

Adjustment requires, in order:

1. A nonzero current first direction.
2. A nonzero retained first lookup result.
3. A nonzero result from a fresh F-8b354e218ab8 call using the retained lookup results.

The ending bound is then read, followed by the starting bound, followed by a context measurement through F-19fde5f06ccc. The same unsigned span-versus-measurement-plus-90 comparison is applied.

If it succeeds, the first coordinate is replaced by:

\[
(A+w/2)-\left(S_{\mathrm{outer}}+(E-S_{\mathrm{inner}})/2\right).
\]

For this replacement:

- \(A\) is captured before an additional F-19fde5f06ccc call supplies \(w\).
- The first lookup result’s bounds are read after that call.
- \(S_{\mathrm{outer}}\) and \(S_{\mathrm{inner}}\) are two separate reads at offset `0x04`.
- \(E\) is a read at offset `0x0c`.
- Relative order among these three bound reads is not independently established.

Only when those bounds remain stable may the expression be simplified using a single starting-bound value.

The function then writes zero to the first direction and 12 to the mode, in that order. It does not recompute the second coordinate or change the second direction.

If the threshold comparison fails, the first direction is reread:

- A negative value selects the negation of the first result’s current starting bound as displacement.
- Otherwise, displacement is \(W\) minus its current ending bound.

That displacement is added to the first coordinate as unsigned 32-bit coordinate arithmetic, modulo \(2^{32}\). The earlier eligibility read does not guarantee the direction remains nonzero or has the same sign.

### Finalization

Bit 0 of the first coordinate is cleared, then bit 0 of the second coordinate. This makes their 32-bit patterns even; it is not signed rounding toward zero. Under two’s-complement interpretation, −3 becomes −4.

The function then:

1. Calls F-a19ace379809 with the retained second handle and the coordinate pair’s address.
2. Calls F-9b8f3181789f with that handle, 4, and 0.
3. Stores that handle at context offset `0x1b8`.
4. Returns.

No explicit release of prior published handles or either allocation appears. Allocation ownership, constructor ownership transfer, and eventual release obligations are unknown.

No rollback is represented. An abnormal dependency outcome can occur after counter reset, allocation, first-handle publication, or placement-state changes.

The coordinate pair has temporary lifetime. Whether F-a19ace379809 copies its contents or retains its address is unknown; safe long-term retention cannot be assumed.

The shared counter and repeated reads establish neither atomicity nor thread safety. No dependency is assumed to preserve context fields, referenced storage, or globals.

## Acceptance examples

These are conditional static examples, not executed tests. Unless stated otherwise, assume accessible objects, stable relevant storage across dependencies, normally returning calls, and no signed overflow.

1. **Absent eligible object.** If the second lookup returns zero, both lookups occur, but no direct counter or context write and no allocation request follows.

2. **Equal selector values.** Both external selector locations may contain the same value. This remains compatible with the observed lookup behavior; distinct locations do not require distinct values.

3. **Deferral retains increment.** With counter 1, a nonzero relationship result, span 80, and measurement 100 on both evaluations, the unsigned threshold succeeds, the counter becomes 2, and the signed comparison returns before construction.

4. **Counter boundary.** With counter 3 and all earlier gate conditions true, the incrementing branch is skipped. Creation resets the counter to zero without invoking the gate’s value-source calculation.

5. **Post-call mode input.** If calculated selection is reached, F-eec8106f4698 changes the mode from 1 to 9, and its result’s low three bits are 5, F-d7be9cfb4000 receives 16 and 12. Its first argument is not 8.

6. **Subtype-2 captured bound.** Force value 1 and subtype 2 select mode 6 and directions −1, 0. With \(A=100\), captured \(C=50\), \(H=40\), and \(h=20\), base placement is `(100, 40)`. A change of `0x80` to 900 during the call supplying \(h\) does not replace 50.

7. **Ordinary captured bounds.** Forced mode 12 with \(A=100\), \(C=50\), \(w=21\), \(h=11\), \(W=8\), and \(H=4\) produces `(106, 53)`, then `(106, 52)` after masking. Mutating `0x84` during the call supplying \(w\), or `0x80` during the call supplying \(h\), does not replace the captured bounds.

8. **Mode 3 preserves direction.** Selecting mode 3 while the first direction is −1 leaves it −1 and writes −1 to the second direction. Later adjustment remains eligible unless intervening effects change relevant state.

9. **Adjustment observes later object bounds.** Suppose successful adjustment captures \(A=100\). Its additional measurement returns 20 while changing `0x84` to 500 and setting stable object bounds to 20 and 40. The replacement first coordinate is \(100+10-(20+10)=80\). The context-bound mutation is excluded; the object-bound mutations are included. A prior second coordinate of 37 becomes 36 only through masking.

10. **Unsupported ordinary mode.** If an unsupported byte value persists through both coordinate selections, neither coordinate is initialized there. Adjustment might replace the first coordinate, but deterministic submission of the complete pair is not established.
