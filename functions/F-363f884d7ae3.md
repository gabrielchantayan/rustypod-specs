# F-363f884d7ae3

## Purpose

F-363f884d7ae3 conditionally constructs two related objects, configures the second object, derives a two-component placement, and publishes object handles into a mutable context.

Creation may be deferred through a shared counter, a relationship predicate, measurements, and a dependency’s secondary output. When creation proceeds, the function resets the counter, publishes the first constructed handle, selects placement state, computes coordinates, optionally adjusts the first coordinate against another object, clears both coordinates’ low bits, and submits the placement.

The operations and ordering below are established by the supplied static representation. “Object,” “measurement,” “direction,” and “placement” describe inferred roles; application-level meanings are not established.

## Interface

### Input and result

The sole input is a 32-bit address-like value identifying a mutable context. There is no explicit return value or direct error-reporting result.

The function does not validate the context address, accessible extent, referenced storage, allocation results, or constructed handles. Defined operation therefore requires readable and writable storage for the accesses reached on the selected path, together with dependency-compatible arguments.

### Other storage

The first lookup result, when nonzero, is passed directly to F-8b354e218ab8. Its 32-bit fields at `0x04` and `0x0c` supply a starting bound and ending bound. Their difference supplies a span.

The second lookup result must be nonzero, with a nonzero 32-bit field at `0x04`, to proceed. Its embedded region at `0x98` is used by relationship and measurement dependencies.

The first constructed object is measured through its region at `0x98`. A handle returned by F-ffe0d92c57b7 must support a 32-bit read at `0xf4`.

An externally referenced shared object contains a signed 32-bit counter at `0x04`. Its initialization, ownership, and synchronization are unknown.

The placement argument is temporary storage containing two consecutive 32-bit words: first coordinate, then second coordinate. Byte order is not independently established.

## Behavior

### 1. Lookups and eligibility

F-5710a8628cba is called twice in order. Each call receives the context fields at `0x38` and `0x44`, with a selector as its second argument.

The selectors are read from two different external locations. The supplied representation does **not** establish that their values differ.

The context arguments are read separately for each lookup; the first lookup may affect values observed by the second. No relative evaluation order between arguments of a single lookup is established here.

After the second lookup, the function captures the external shared-state reference. It then reads the second result’s field at `0x04` if that result is nonzero.

If the second result is zero, or that field is zero, the function returns. Both lookups have occurred, but no direct context or counter write has occurred. Effects performed by dependencies remain possible.

### 2. Conditional deferral

The deferral gate requires all of the following, evaluated in order:

1. The first lookup result is nonzero.
2. F-8b354e218ab8 returns a nonzero primary result when given the first result and the second result’s region at `0x98`.
3. The first result’s span, interpreted as unsigned 32 bits, is strictly less than the context’s first measurement plus unsigned 90.
4. The shared counter, interpreted as signed 32 bits, is less than 3.

For the threshold check, the ending field at `0x0c` is read before the starting field at `0x04`; both reads precede F-19fde5f06ccc on the context region.

The addition of 90 is unsigned 32-bit arithmetic. The span comparison is not a signed distance comparison. A negative representable span, converted to unsigned, becomes a large value.

On entering the gate:

- The function increments the shared counter.
- It rereads the ending bound, then the starting bound, and calls F-19fde5f06ccc again.
- If this newly calculated span is strictly less than the new measurement under signed comparison, it returns.
- Otherwise it calls F-eec8106f4698, then F-870c4fcf7295 with that result and `6 − current counter`.
- A nonzero 32-bit secondary output from F-870c4fcf7295 causes a return.

The counter used in `6 − current counter` is read **after** F-eec8106f4698 returns. It is not necessarily the value written by the earlier increment.

Neither deferral return rolls back the increment. The secondary output’s meaning is unknown; remainder, status, and Boolean interpretations are not established.

### 3. Construction and configuration

If creation proceeds, the function writes zero to the counter through the previously captured shared-state reference. It then performs these operations in order:

1. Requests `0xb8` bytes through F-8157a180d901.
2. Passes that result and the second lookup result to F-11198946fd75.
3. Publishes the returned handle at context offset `0x1b4`.
4. Requests `0x130` bytes through F-8157a180d901.
5. Calls F-ffe0d92c57b7 with the context.
6. Calls F-b07a62920ca7 with the second allocation result, the retrieved handle’s field at `0xf4`, the context’s current field at `0x1b4`, and constant 1.
7. Calls F-c57b56681a78 with the resulting second-object handle and 100.
8. Calls F-e694578895f8 with the same handle and 255.

The `0x1b4` argument is reread after F-ffe0d92c57b7; it is not guaranteed to equal the handle originally published there. Relative ordering of the two field reads used as arguments to F-b07a62920ca7 is not established.

No result is explicitly checked for failure. The first handle becomes visible before construction and configuration of the second object finish.

### 4. Mode selection

If the 32-bit field at `0x1dc` equals 1, subtype 2 selects mode 6; every other subtype selects mode 12.

Otherwise, a subtype other than 2 causes two ordered calls to F-b01436b9ce2b: first on the context region, then on the second lookup result’s region. Their returned signed measurements are compared.

If the context measurement is strictly smaller:

1. F-eec8106f4698 returns a 32-bit value.
2. The mode byte at `0x1c4` is then read and zero-extended to 32 bits.
3. F-d7be9cfb4000 receives that current byte value, plus the returned value’s low three bits, plus 2; its second argument is 12.
4. Its observed 8-bit secondary output is stored as the mode.

Thus the mode input is read **after** the value-source call. A dependency-induced mode change during that call affects the argument. The sum ranges from 2 through 264 and does not overflow 32 bits.

If the measurement branch is not taken, the current mode is toggled as follows: 6 becomes 0; every other byte value becomes 6.

A modulo-12 interpretation of F-d7be9cfb4000 is plausible intent, not established behavior.

### 6. Base coordinates

F-19fde5f06ccc measures the region at `0x98` of the object currently referenced by `0x1b4`. F-b01436b9ce2b then measures a region obtained through a fresh read of `0x1b4`.

Let \(W\) and \(H\) denote these respective results. They need not describe the same object if the first measurement changes the context.

For the formulas below:

- \(A\), \(B\): context fields at `0x84`, `0x8c`.
- \(C\), \(D\): context fields at `0x80`, `0x88`.
- \(w\), \(h\): fresh context results from F-19fde5f06ccc and F-b01436b9ce2b, respectively.

These symbols denote branch-specific reads, not a coherent snapshot.

After both object measurements, the subtype is read. For subtype 2:

- If the current first direction is negative, the first coordinate is \(A\).
- Otherwise it is \(B-W\).
- The second coordinate is \(C-((H-h)\mathbin{\text{>>}}1)\).

For that second coordinate, **\(C\) is captured before** F-b01436b9ce2b supplies \(h\). The already selected first coordinate is retained across that call.

Other subtypes use the following selections.

| Mode | First coordinate |
|---:|---|
| 0, 1, 2, 10, 11 | \(B-W+4\) |
| 4, 5, 6, 7, 8 | \(A-4\) |
| 3, 9 | \(A-((W-w)\mathbin{\text{>>}}1)\) |
| 12 | \(A+w/2-W/2\) |
| Other | Not initialized by this selection |

For modes 3, 9, and 12, **\(A\) is captured before** F-19fde5f06ccc supplies \(w\). Mutation of `0x84` during that call does not replace the captured value.

The mode is then read again for the second-coordinate selection.

| Mode | Second coordinate |
|---:|---|
| 0, 6 | \(C-((H-h)\mathbin{\text{>>}}1)\) |
| 1, 2, 3, 4, 5 | \(C-4\) |
| 7, 8, 9, 10, 11 | \(D-H+4\) |
| 12 | \(C+h/2-H/2\) |
| Other | Not initialized by this selection |

For modes 0, 6, and 12, **\(C\) is captured before** F-b01436b9ce2b supplies \(h\).

Consequently, a first-coordinate measurement may change the mode used for the second coordinate. Neither selection retroactively updates the direction fields.

Signed division by 2 truncates toward zero under the represented arithmetic model. Right shift by 1 is a distinct operation; its exact behavior for negative operands remains unresolved. Independently divided terms must not be replaced by a division of their difference.

### 7. Adjustment against the first lookup result

Adjustment eligibility is checked in this order:

1. The current first direction is nonzero.
2. The first lookup result is nonzero.
3. A fresh F-8b354e218ab8 call against the original second lookup result’s region returns nonzero.

The function then reads the first result’s ending bound, reads its starting bound, and calls F-19fde5f06ccc on the context. It applies the unsigned span-versus-measurement-plus-90 comparison described above.

If the comparison succeeds, the first coordinate becomes:

\[
A+w/2-\left(S+(E-S)/2\right),
\]

where \(S\) and \(E\) are the first result’s starting and ending bounds.

For this successful adjustment, **\(A\) is captured before an additional F-19fde5f06ccc call supplies \(w\)**. The first result’s bounds used in the center expression are read **after that call**, not reused from the preceding threshold check. The expression includes two starting-bound reads; their relative ordering with the ending-bound read is not independently established.

The function then writes zero to the first direction and 12 to the mode. It leaves the second coordinate and second direction untouched; there is no mode-12 recomputation of the second coordinate.

If the comparison fails, the first direction is reread:

- A negative direction adds the negation of the first result’s current starting bound.
- Otherwise, the function adds \(W\) minus the first result’s current ending bound.

The eligibility check’s earlier nonzero direction does not guarantee the same direction remains current after the intervening calls.

### 8. Finalization

The function clears bit 0 of each 32-bit coordinate. This makes both bit patterns even; it is not signed truncation toward zero. For a two’s-complement representation, −3 becomes −4.

It then:

1. Calls F-a19ace379809 with the retained second-object handle and the temporary coordinate pair’s address.
2. Calls F-9b8f3181789f with that handle, 4, and 0.
3. Publishes that handle at `0x1b8`.
4. Returns.

## Side effects

Direct writes affect the shared counter, context fields `0x1b4`, `0x1b8`, `0x1bc`, `0x1c0`, and `0x1c4`, and temporary coordinate storage. Dependencies may have additional effects.

The function does not explicitly release previously published handles or free either allocation. Dependency ownership, retention, transfer, and release behavior are unknown.

No rollback is visible. A dependency failure may occur after counter reset, allocation, partial publication, or placement-state changes.

The coordinate pair is temporary. It is available during F-a19ace379809, but the supplied material does not establish whether that dependency copies the pair or retains its address. Safe long-term retention cannot be assumed.

Repeated reads and a shared counter do not establish thread safety, atomicity, or reentrancy.

## Acceptance examples

These are conditional static examples, not executed tests. Except for mutations explicitly specified, assume dependencies preserve relevant state, return accessible objects, and avoid arithmetic overflow.

1. **Ineligible second result.** If the second lookup returns zero, both lookups occur, followed by no direct counter or context writes and no allocation request.

2. **Retained deferral increment.** With counter 1, a successful relationship predicate, span 80, and context first measurement 100 on both evaluations, the counter becomes 2 and the signed comparison causes return. No objects are created.

3. **Counter boundary.** Counter 3 bypasses the incrementing gate after its earlier conditions succeed. Creation resets it to zero without calling the gate’s value-source calculation.

4. **Mode read after value source.** Suppose the measurement comparison selects calculated mode selection. If F-eec8106f4698 changes the mode from 1 to 9 and returns a value whose low three bits are 5, F-d7be9cfb4000 receives 16 and 12, not 8 and 12.

5. **Forced subtype-2 placement.** Force field 1 and subtype 2 select mode 6 and directions −1, 0. With \(A=100\), captured \(C=50\), \(H=40\), and \(h=20\), base placement is `(100, 40)`. If the second-coordinate measurement changes `0x80` to 900, the captured 50 still applies.

6. **Centered placement with captured bounds.** Forced mode 12, \(A=100\), \(C=50\), \(w=21\), \(h=11\), \(W=8\), and \(H=4\) produce `(106, 53)`, then `(106, 52)` after masking. Changes to `0x84` during the first-coordinate measurement or to `0x80` during the second-coordinate measurement do not replace those captured bounds.

7. **Mode 3 preserves direction.** If the selected mode is 3 and the existing first direction is −1, the direction update retains −1 and writes −1 to the second direction. Later relationship adjustment remains eligible unless intervening effects change the relevant state.

8. **Adjustment uses post-measurement object bounds.** Suppose adjustment succeeds, captures \(A=100\), and its additional measurement returns 20 while changing `0x84` to 500 and the first result’s bounds to 20 and 40. The adjusted first coordinate is \(100+10-(20+10)=80\). The context-bound mutation is excluded; the object-bound mutations are included. A prior second coordinate of 37 becomes 36 only through final masking.

9. **Invalid ordinary mode.** If the mode remains outside 0–12 through both coordinate selections, neither table initializes its coordinate. Later adjustment may supply a first coordinate, but deterministic placement of the complete pair is not established.
