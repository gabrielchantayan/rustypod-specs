## Acceptance examples

These are conditional static consequences, not executed tests.

1. **Truncation without address truncation.** If the second input has bit pattern 0x12345678, its initial halfword store writes 0x5678. The destination still uses the represented full-width second input.

2. **Distinct fixed-location reads.** If the two reads of 0x087fc710 yield different values, doubling uses the first value, while the offset-0x54 halfword-store destination uses the second. That store occurs before either following fixed-location snapshot is read.

3. **Short-circuit behavior.** If the threshold-comparison read of 0x087fc6e4 yields 0xFFFFFFA7, the conditional carry-test read is omitted. If it yields 0xFFFFFFA6, another read is required; that later value, not necessarily 0xFFFFFFA6, supplies the addition operand.

4. **Stable carry boundary.** Conditional on the relevant reads yielding one stable value, 0xFFFFFFA6 plus 0x59 reaches 0xFFFFFFFF without carry, but adding a carry-in of one produces carry. A stable value of 0xFFFFFFA7 already exceeds the threshold.

5. **Doubling boundary.** A doubling operand of 0x80000000 produces carry. An operand of 0x7FFFFFFF with carry-in one produces 0xFFFFFFFF without carry.

6. **Transition aliasing.** If the transition-base halfword destination overlaps the source word, the source-anchor reload must observe that intervening store. Reusing the word loaded for the earlier byte-0x45 destination is not equivalent.

7. **Repeated reads and writes.** The two hub offset-0x44 reads remain distinct. Likewise, byte 0x74 followed by word 0x00000074 at the active child plus 0x10 is not a single byte mutation.

8. **Terminal provenance.** If the late main-anchor offset-0x44 read yields a different word from an earlier read, the late value supplies the third terminal argument, even if a subsequent final store changes that field again.

9. **OR, not addition.** A terminal character value of 0x44 produces first argument 0x44, not 0x88.

10. **Partial completion.** An invalid late destination does not imply that preceding writes are undone or that a clean error result is returned.

## Uncertainties

The following remain **documented_only**:

- Initialization and validity of the additional entry state and fixed-location words.
- Endianness, alignment support, permissions, address wrapping, and fault recovery.
- Character signedness. A high-bit character converted to unsigned 32-bit form may undergo sign extension before unsigned conversion rather than zero extension.
- Right-shift behavior for negative values and counts exceeding 31. Extracting eight count bits does not establish five-bit count masking.
- Signed arithmetic overflow and implementation-dependent integer conversions.
- The execution model for comparing the unresolved target against address 0x46.
- Actual access-side-effect behavior, object boundaries, and all aliases.
- F-U1’s identity, effects, ownership behavior, and normal return.
- Whether the apparent function boundary and straight-line control flow accurately represent executable control flow.

The link-like patterns support no stronger structural invariant. Apparent self-links and saved-field restorations may be affected by intervening aliases.
