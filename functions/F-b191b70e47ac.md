# F-b191b70e47ac

## Purpose

F-b191b70e47ac updates byte fields in a globally selected state object and dispatches four arguments through a separately selected global function pointer.

The low two bits of a state byte choose between two behaviors:

- If either bit is clear, record the low byte of the position input and dispatch the caller’s two payloads.
- If both bits are set, calculate a displacement from the position input and a stored byte, derive a cyclic amount and a sign classification, invoke two additional dependencies, and dispatch derived payloads.

The final dispatch target is obtained from a **separate global function-pointer slot after the common-tail state writes**. It is not captured before the dependency calls. An earlier dependency may replace that slot and thereby change which function receives the final dispatch.

A cyclic-position or phase-update interpretation is plausible but inferred. The application meaning of the state, arithmetic units, and dispatched arguments is not established.

This contract describes static evidence only. No runtime tests have been performed.

### Global inputs

Two distinct global selections are relevant:

1. **State-selection slot:** supplies the state pointers used by this function and several dependencies. It is read repeatedly rather than captured once at entry.
2. **Dispatch-target slot:** supplies the function pointer for the final indirect call. Its value is read at the final call, after the direct state updates.

These slots have different roles. Changing the state selection does not, by itself, establish any change to the dispatch target, or vice versa.

## Behavior

### Entry calls and retained state

The function first makes three calls, in this order:

1. An unresolved external entry-hook dependency receives 3.
2. F-a4ea0691ddc5 receives zero and the state pointer selected globally for that call.
3. F-847a2a401182 receives the state pointer selected globally for its call.

Only after these calls does the function retain a state pointer for later writes. This is the **retained state**.

No dependency is assumed to preserve the state-selection slot. Consequently, the pointers passed to the two identified entry dependencies and the pointer ultimately retained need not designate the same object.

The function then reads offset 11 through the global state selection and examines its low two bits:

- Low bits `11`: take the derived-displacement branch.
- Low bits `00`, `01`, or `10`: take the direct-payload branch.

Bits 2 through 7 do not affect this decision. The branch-selection read uses the global selection, rather than being expressed through the retained pointer. Without asynchronous mutation between those operations, both refer to the same state.

### Direct-payload branch

When either low flag bit is clear:

1. Store the low eight bits of the position input at offset 6 through the global state selection.
2. Select the original first dispatch payload as the final third argument.
3. Select the original second dispatch payload as the final fourth argument.
4. Select 3 as the final second argument.

Neither F-16ccc0212b5f nor F-3c3879b3cad3 is called.

The function then enters the common tail. The offset-6 write occurs before the offset-7 write, the flag update, and the final dispatch-target lookup.

### Derived-displacement branch

When both low flag bits are set, the function reads offset 6 through the global state selection. That byte is accessed as a character-valued operand and promoted for subtraction.

Let \(p\) be the full 32-bit position input, and \(b\) the promoted stored byte. The displacement is:

\[
d = p-b
\]

This subtraction uses the full input, not its low eight bits. The interpretation of stored bytes at or above `0x80`, and subtraction overflow at extreme inputs, remain unresolved as described under Uncertainties.

The function forms a signed remainder on division by 4 and multiplies that remainder by 15. It also evaluates a quotient-sign condition using signed shifts and a sign-derived adjustment.

Under truncation-toward-zero signed division, arithmetic right shift, and subtraction without overflow, the resulting values are:

| Displacement | Derived cyclic amount | Classification word |
|---|---:|---:|
| \(d \geq 0\) | \(15(d \bmod 4)\) | `0x00000000` |
| \(d < 0\), divisible by 4 | 0 | `0xFFFFFFFF` |
| \(d < 0\), not divisible by 4 | \(60 + 15r\), where \(r\) is the negative signed remainder | `0xFFFFFFFF` |

Thus the cyclic amount is one of 0, 15, 30, or 45. Negative nonmultiples of four receive an upward adjustment of 60. Negative exact multiples receive the all-one classification even though their remainder and cyclic amount are zero.

The classification distinguishes negative from nonnegative displacement under this interpretation. It does not convey displacement magnitude.

The signed remainder lies between −3 and 3, so multiplying it by 15 produces a value between −45 and 45. The later addition of 60 cannot overflow a 32-bit signed integer. The unresolved arithmetic boundary is primarily the initial subtraction, together with the target’s signed-operation interpretation.

The final fourth dispatch argument is set to zero, replacing the fourth input.

#### Branch-specific calls and writes

The function next calls F-16ccc0212b5f with:

1. A state pointer read from the global selection.
2. A state pointer read from the global selection again.
3. The 32-bit classification word.

No dependency call occurs between obtaining the two pointer arguments. Their relative evaluation order is not established. Without asynchronous changes, they designate the same state.

After F-16ccc0212b5f returns, the function:

1. Reads the global state selection and saves that pointer for the next dependency call.
2. Writes the low eight bits of the position input at offset 6 of the earlier retained state.
3. Calls F-3c3879b3cad3 with zero and the newly saved pointer.

The pointer supplied to F-3c3879b3cad3 is therefore obtained **before** the position-byte write. F-16ccc0212b5f may have changed the global selection, so that dependency can receive a different object from the one whose position byte is updated.

After F-3c3879b3cad3 returns, the final second dispatch argument is taken from the 32-bit value represented as remaining in the second argument/result register. The supplied material does not establish this as an ordinary declared return value. It is not established to equal zero, the classification word, or either original payload.

The third and fourth inputs do not supply the final payloads on this branch.

### Common tail and final target lookup

Both branches perform these operations against the retained state:

1. Write the associated-byte input at offset 7.
2. Read the byte at offset 11.
3. Write that byte back with bit 1 set.

All bits other than bit 1 are preserved from the **common-tail read**, not reconstructed from the earlier branch-selection value. A dependency’s intervening modification to that byte can therefore affect the written result.

After these writes, the function reads the separate global dispatch-target slot and invokes the target obtained from that read.

The target is not cached before the entry calls or the branch-specific calls. Any earlier dependency may change the slot. The value present at the final lookup determines the target, subject to unresolved concurrent behavior.

| 2 | 3 | Register-derived value following F-3c3879b3cad3 |

The state writes precede both the dispatch-target lookup and the dispatch itself. The supplied representation shows a return afterward, but does not independently establish the machine-level transfer form or guarantee that the selected target returns normally.

## Side effects

The function directly performs three state updates:

- Offset 6 receives the low byte of the position input.
- Offset 7 of the retained state receives the associated-byte input.
- Bit 1 at offset 11 of the retained state is set.

On the direct-payload branch, the offset-6 write uses the global state selection. On the derived-displacement branch, it uses the retained state. The latter branch places F-16ccc0212b5f before the position write and F-3c3879b3cad3 after it.

The function reads both the state-selection slot and the separate dispatch-target slot. No direct assignment to either global slot is shown. This does not prevent dependencies from changing them.

Setting bit 1 does not necessarily enable the derived-displacement branch on the next invocation. A flag byte with low bits `00` becomes `10`; bit 0 must be set by some other action before both bits are set.

No explicit allocation, release, ownership transfer, lock, or atomic operation is shown. Dependency ownership behavior is unknown. Passing a pointer does not establish whether it is borrowed, retained, consumed, or released.

The function continues to use the retained state after branch-specific dependency calls. Successful completion requires that object to remain accessible; the supplied dependency information does not guarantee its lifetime.

There is no rollback. Earlier writes and calls remain observable if a later dependency fails to return or an access or dispatch faults.

### State-selection replacement

Suppose the retained state is object A and F-16ccc0212b5f changes the state selection to object B:

- The next dependency pointer is obtained as B.
- The position byte is written to A.
- F-3c3879b3cad3 receives B.

This requires A to remain valid despite the dependency call.

### Dispatch-target replacement

Suppose the dispatch-target slot initially selects target X, and an entry dependency replaces it with target Y. If no subsequent operation changes that slot, the final dispatch selects Y, not X.

On the derived-displacement branch, the same rule applies if F-16ccc0212b5f or F-3c3879b3cad3 replaces the slot. A later replacement supersedes an earlier one. The lookup occurs only after the common-tail state writes; there is no entry-time target snapshot.

### Intervening flag mutation

Suppose branch selection observes low bits `11`, but a branch-specific dependency clears bit 0 before the common tail. If no other flag mutation occurs, the common-tail update sets bit 1 while preserving the cleared bit 0. The resulting low bits are `10`, even though this invocation took the derived-displacement branch.

## Uncertainties

The following remain **documented_only**:

- **Character signedness:** the offset-6 read uses a character-valued access. Bytes `0x80` through `0xFF` may require different promoted interpretations depending on the target model.
- **Subtraction overflow:** an extreme position input minus the promoted stored byte may exceed signed 32-bit range. No portable overflow result is established.
- **Signed-operation interpretation:** the arithmetic results above rely on truncating signed division and arithmetic right shift. Independent machine-level verification is unavailable.
- **Register-derived argument:** the final second argument on the derived-displacement branch lacks an established high-level return contract.
- **Dependency effects:** state mutations, global-slot replacements, allocation, release, and ownership behavior are unknown.
- **Concurrency:** no synchronization is established. Neither the state flag update nor either global selection is proven atomic or protected against concurrent mutation.
- **Dispatch ABI and control flow:** the selected target’s exact calling convention and normal-return behavior are not independently established.
- **Application semantics:** “position,” “associated byte,” “cyclic amount,” and “classification” are descriptive terms, not proven domain meanings.
