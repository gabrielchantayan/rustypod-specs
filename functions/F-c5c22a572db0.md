# F-c5c22a572db0

## Purpose

F-c5c22a572db0 conditionally transfers a sequence of four-byte elements from a source range to successive destination positions. It traverses the source in increasing element order and returns the destination position reached after traversal.

The destination is checked for null separately on every iteration. This is not a single check that disables the entire transfer: even when an iteration skips its transfer because the destination is null, the destination position still advances.

This contract describes static evidence from the supplied representation. No runtime tests have been performed. It does not establish a particular source language, application binary interface, address-space layout, or fault-handling environment.

## Interface

The function accepts three pointer-shaped inputs:

- **Source start:** the first position in a sequence of four-byte elements.
- **Source end:** the position at which traversal stops, excluded from the transfer.
- **Destination start:** the destination position associated with the first source element.

The result is a pointer-shaped destination position.

Each element occupies exactly four bytes in the supplied representation. The element type does not establish signedness, floating-point interpretation, ownership, or application-level meaning. The operation transfers a four-byte value without any visible arithmetic or conversion on that value.

Both source and destination positions advance by one four-byte element per completed iteration. This element width does **not** establish the width of a pointer or the width of address arithmetic.

For ordinary, valid range use, let **N** be the nonnegative number of four-byte element advances required to reach source end from source start. The function performs N iterations and returns destination start advanced by N elements, provided all required operations complete normally.

### Preconditions for a defined, successful transfer

The supplied representation contains no explicit validation of these conditions:

- Source end must be reachable from source start by repeated forward, four-byte element advances.

No allocation, capacity, length, status-output, or error-handler argument is present.

## Behavior

### Termination and range interpretation

The function compares its current source position with source end before each iteration.

If they are equal at entry, it returns destination start unchanged. It does not read a source element, write a destination element, or advance either position.

Otherwise, traversal continues until the current source position equals source end. The endpoint is excluded: reaching it ends traversal without an element read at that position.

Termination depends on equality, not on an ordering comparison or a validated element count. There is no visible rejection of a backward endpoint, a misaligned endpoint, or an endpoint unreachable by the specified advances. Such inputs are outside the successful-range contract; their outcome is not established here.

### Per-iteration access order

For each iteration whose source position differs from source end:

1. The current destination position is tested for null.
2. If it is non-null, the current four-byte source value is read and assigned to the current four-byte destination position.
3. If it is null, that iteration performs neither the source-element read nor the destination-element write.
4. The destination position advances by one four-byte element, regardless of whether a transfer occurred.
5. The source position advances by one four-byte element.
6. The next source-end comparison determines whether another iteration occurs.

The source value is obtained before it is written to the destination. An earlier iteration’s write precedes a later iteration’s source read in the supplied operation sequence. Consequently, overlapping storage can make later reads observe values written earlier by this same call.

This is the logical order supported by the supplied representation. Exact instruction selection, access atomicity, bus transactions, and behavior under unsynchronized concurrent access are not established.

### Null destination behavior

A null current destination suppresses only the transfer for that iteration. It does not cause an immediate return and does not prevent either position from advancing.

In particular, the supplied representation does not support the general claim that “a null destination discards the whole source range.” Later iterations inspect the destination position produced by the preceding advance.

The concrete meaning of advancing a null pointer is unresolved. In a language model where that operation is invalid, there is no defined successful result to promise. In an execution model that defines it as address advancement, a later position might be non-null and therefore become a write target. The contract does not assume that such a target is accessible.

### Overlapping ranges

There is no overlap detection, direction selection, or temporary buffer.

If the source and destination positions are identical and valid, each iteration still contains a read followed by a write to the same element.

If destination begins inside the source range at a higher address, an early write can replace a source value that has not yet been read. Later iterations then transfer the replacement value rather than the original value.

If destination begins at a lower position in the same valid element sequence, the forward order can preserve unread source values. This follows from the relative positions; it is not a separate overlap-handling path.

### Return and completion

On normal completion, the result is the destination position after one advance per iteration, including iterations that skipped their transfer.

For a conventional valid transfer of N elements, that position is immediately after the N-element destination span. The result is not a byte count, a success flag, or the original destination.

The returned position is not dereferenced merely to return it. For an empty source range, the original destination position is returned unchanged.

## Side effects

The directly visible memory side effects are four-byte writes at the current destination positions for iterations in which those positions are non-null. Corresponding source reads occur only on those iterations.

Writes occur incrementally. There is no visible transaction, rollback, or deferred commit. If execution fails after some successful transfers, the supplied representation contains no mechanism to undo them.

The pointer arguments are supplied as values. Advancing the function’s working positions does not itself update storage containing the caller’s pointer variables.

## Acceptance examples

The following are conditional acceptance criteria derived from static evidence, not observed test results. Each ordinary transfer example assumes valid, sufficiently large, properly aligned storage and representable pointer advances.

### Empty range

Given equal source-start and source-end positions, the result must equal destination start. No element read or write occurs, even if destination start is null.

### Separate three-element ranges

Given source values `[11, 22, 33]`, an endpoint three elements after source start, and a separate writable destination of three elements, normal completion must leave destination values `[11, 22, 33]`.

The result must be three four-byte elements beyond destination start. The source elements remain unchanged by the function’s direct writes.

### Exact source/destination identity

Given two valid elements `[7, 9]` and destination start equal to source start, normal completion leaves the values `[7, 9]` and returns the position two elements beyond the shared start.

Unchanged values do not imply absent accesses: the supplied sequence includes a read and write for each element.

### Destination one element ahead

Given one valid region initially containing `[10, 20, 30, 40]`, a source range covering its first three elements, and destination start at its second element, normal completion produces `[10, 10, 10, 10]`.

Each early write replaces the value read by the following iteration. A result of `[10, 10, 20, 30]` would instead require preservation behavior not present in the supplied representation.

### Destination one element behind

Given one valid region initially containing `[10, 20, 30, 40]`, a source range covering its last three elements, and destination start at its first element, normal completion produces `[20, 30, 40, 40]`.

The result points at the region’s fourth element: three advances from destination start.

### Initially null destination

Given a nonempty source range and a null destination, the first iteration must not read the source element or write a destination element before attempting the destination advance.

A successful return is not an unconditional acceptance requirement. Subsequent behavior depends on the environment’s treatment of null-pointer advancement and any resulting access targets.
