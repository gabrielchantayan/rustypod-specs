# F-b90a277afc03

## Purpose

F-b90a277afc03 is a side-effecting operation that interleaves unresolved indirect calls with byte, halfword, and word memory accesses. It derives addresses and call arguments from explicit inputs, implicit execution state, and dependency results.

The supplied representation establishes no reliable application-level purpose. Record linking, descriptor manipulation, or privileged dispatch would be interpretations rather than established behavior. In particular, apparent global names do not establish operating-system semantics.

This contract describes the visible operation order, data dependencies, access widths, and limits of the available evidence. It does not assume that unresolved dependencies preserve memory, preserve globals, allocate storage, release storage, or return normally.

## Interface

### Explicit inputs

The interface exposes four positional inputs:

| Input | Represented width | Established use |
|---|---:|---|
| First | 32 bits, uninterpreted | No explicit use in the visible body |
| Second | 32 bits, uninterpreted | Passed to the first indirect dependency |
| Third | 32 bits, represented as signed | Shifted left by 11 and by 12 for later call arguments |
| Fourth | 32 bits, unsigned | Logically shifted right by 23 for an early call argument |

“Unused” for the first input means only that no explicit use appears in this representation. It does not establish that the underlying calling convention or hidden dependency state makes the input irrelevant.

### Implicit inputs

The operation also depends on:

- A return-link-derived value used to form the first call target.
- Two register-derived values without visible definitions: one supplies an address for an early byte read; the other supplies bits for an early byte write.
- A pointer exposed through auxiliary dependency-return state near the end.
- Two global words and a three-byte global region.
- Memory reached through dependency-returned integers and the derived addresses described below.
- Executable targets formed through address arithmetic, including a final target at address zero.

These implicit inputs prevent the four explicit inputs from constituting a self-contained interface.

### Outputs

The represented return type is void. No explicit success value, error value, returned pointer, or returned ownership transfer is established.

Observable outputs consist of dependency invocations, memory writes, and any behavior performed by those dependencies. Normal return is conditional on all preceding accesses and calls—including the call to address zero—completing normally.

### Width and address conventions

This document uses:

- **Byte:** 8 bits.
- **Halfword:** 16 bits.
- **Word:** 32 bits.
- **Wide result:** 64 bits, separated into numerical low and high 32-bit halves.
- **Low byte:** the least significant eight bits of a value, not necessarily the byte at its lowest memory address.

The supplied representation contains signed left shifts and signed multiplication that are not defined for every operand under ordinary source-language rules. The intended machine behavior may be 32-bit truncating arithmetic, but that interpretation is not established for all inputs. Examples below use non-overflowing values unless explicitly conditional.

## Behavior

### Dependency notation

The identifiers F-U001 through F-U032 below are document-local opaque call-site identifiers. They do not assert resolved function identities or equivalence between targets.

Between these identified calls, the representation contains additional unresolved calls with no explicit arguments. Their counts and positions are specified below. “No explicit arguments” does not mean that a dependency cannot consume register state, stack state, or globals.

Every later step is conditional on earlier calls returning and earlier memory accesses completing.

### 1. Initial dispatch and first byte update

1. Invoke F-U001 with the second explicit input. Its target is formed from implicit return-link state.
2. Invoke F-U002 without explicit arguments and retain its 32-bit result.
3. Invoke F-U003 with that result and the fourth input logically shifted right by 23.
4. Invoke four unresolved dependencies without explicit arguments, in sequence. Retain the final result.
5. Read one unsigned byte at one byte beyond the implicit address-bearing register value. Zero-extend this byte to obtain the **small base**.
6. Write one byte at small base plus 17. The written value is bits 22 through 29 of the other implicit register-derived value.
7. Invoke F-U004 with the retained result shifted left by two.

The small base is an absolute numeric address component, not an offset added back to the original source address. Before any address-width complications, its range is 0–255; the byte destination is therefore in the range 17–272.

### 2. Supervisor-word update and first word-to-byte transfer

1. Invoke four unresolved no-explicit-argument dependencies. Retain the final result.
2. Invoke F-U005 with that result shifted left by two, supplied twice.
3. Invoke F-U006 without explicit arguments and retain its word result as the **supervisor value**.
4. Store the supervisor value into a global word, here called the **supervisor word**.
5. Invoke F-U007 with the saved supervisor value.
6. Invoke one unresolved dependency without explicit arguments.
7. Read a complete word at small base plus 116.
8. Store its low byte at small base plus one.
9. Invoke F-U008 with the third explicit input shifted left by 11.

The read in step 7 is word-sized even though only eight bits are subsequently stored. It must not be reduced to a byte read when specifying observable access behavior.

The supervisor value is retained locally for a later argument. A dependency’s modification of the supervisor word does not change that saved value.

### 3. Wide-result dispatch and repeated byte updates

1. Invoke F-U009 without explicit arguments and retain its wide result.
2. Invoke F-U010 with the numerical low word, numerical high word, and the saved supervisor value logically shifted right by 23.
3. Invoke four unresolved no-explicit-argument dependencies. Multiply the final result by four to obtain the **first scaled base**.
4. Read a word at first scaled base plus 116 and write its low byte at first scaled base plus one.
5. Invoke F-U011 with the first scaled base.
6. Invoke four further unresolved no-explicit-argument dependencies. Retain the final result as the **working value**, and form the **working base** by shifting it left by two.
7. Read another word at first scaled base plus 116 and again write its low byte at first scaled base plus one.
8. Invoke F-U012 with four arguments, in this order:
   - The third explicit input shifted left by 12.
   - The working base.
   - The working base again.
   - The working value shifted left by 18.

The second word read is a fresh read after intervening dependency calls. It is not interchangeable with reuse of the first read.

### 4. Capture a word and distribute it to scaled destinations

1. Invoke F-U013 without explicit arguments; pass its word result to F-U014.
2. Invoke F-U015 without explicit arguments; pass its word result to F-U016.
3. Invoke four unresolved no-explicit-argument dependencies.
4. Multiply the final result by four to obtain the **capture base**.
5. Read a word at capture base plus 116 and retain the complete word as the **captured word**.
6. Write its low byte at capture base plus one.
7. Invoke F-U017 with the capture base.
8. Invoke four unresolved no-explicit-argument dependencies.
9. Store the captured word at the final result multiplied by 16, plus 20.
10. Invoke F-U018 with the working base logically shifted right by two and then shifted left by 16.

Step 10 is an operation on the saved working base. It is not unconditionally equivalent to shifting the original working value left by 16: formation of the working base may already have discarded high bits under a truncating machine interpretation.

Continue as follows:

11. Invoke F-U019 without explicit arguments; pass its result to F-U020.
12. Invoke F-U021 without explicit arguments; pass its result to F-U022.
13. Invoke four unresolved no-explicit-argument dependencies.
14. Store the captured word at the final result multiplied by four, plus 20.
15. Invoke F-U023 with that same final result multiplied by four.
16. Invoke four unresolved no-explicit-argument dependencies.
17. Shift the final result left by two, producing the **link value**.
18. Store the link value as a word at the working base with its lowest two bits cleared, plus 20.
19. Invoke F-U024 with the link value twice.

The captured word survives as a saved value across all these calls. Later changes to its original memory location do not alter these specified stores.

### 5. Clear one destination and install two matching links

1. Invoke F-U025 without explicit arguments; pass its result to F-U026.
2. Invoke F-U027 without explicit arguments; pass its result to F-U028.
3. Invoke four unresolved no-explicit-argument dependencies.
4. Store a zero word at the final result multiplied by four, plus 20.
5. Invoke F-U029 with the final result multiplied by four.
6. Invoke four unresolved no-explicit-argument dependencies, retaining a wide result from the last.
7. Shift the low word of that result left by two, producing the **replacement link**.
8. Store the replacement link at the high word multiplied by four, plus 20.
9. Read a separate global word, here called the **saved-base global**, and retain its value as an address.
10. Invoke F-U030 with the replacement link, the unscaled high word, and the replacement link twice more.
11. Invoke four unresolved no-explicit-argument dependencies.
12. Store the replacement link at the final result multiplied by four, plus 20.
13. Read a word at the saved address plus 20. Retain this as the **selected word**.
14. Invoke F-U031 with the final result multiplied by four.

The saved-base global is sampled before F-U030 and the following four calls. The word at saved address plus 20 is sampled afterward. A change to the global itself during those calls does not retarget the later read; a change to memory at the saved address can affect its result.

### 6. Two nested byte-address updates

1. Invoke four unresolved no-explicit-argument dependencies, retaining a wide result from the last.
2. Retain its low word as the **final selector** and its high word separately.
3. Logically shift the captured word right by 23; add one; read an unsigned byte at that numeric address.
4. Zero-extend that byte, add 17, and write the low byte of the selected word there.
5. Invoke F-U032 with the retained high word three times, followed by the final selector shifted left by two.
6. Invoke one unresolved dependency without explicit arguments, then pass its result to another unresolved dependency.
7. Invoke four unresolved no-explicit-argument dependencies and retain the last result.
8. Mask the final selector to its low 30 bits, logically shift right by 21, add one, and read an unsigned byte at that address.
9. Zero-extend that byte, add 17, and write bits 22 through 29 of the selected word there.
10. Invoke an unresolved dependency with the result retained in step 7 shifted left by two.

The first lookup address ranges from 1 through 512. The second also ranges from 1 through 512. Both resulting byte-write addresses range from 17 through 272.

These are separate lookup reads at different points in execution. Earlier writes or intervening dependencies may affect the second lookup.

### 7. Terminal operations

1. Invoke four unresolved no-explicit-argument dependencies.
2. Invoke another dependency with the last result shifted left by two, supplied twice.
3. Invoke two dependencies without explicit arguments.
4. Pass the second result to another dependency.
5. Invoke a dependency that supplies a byte result and exposes an auxiliary pointer through implicit return state.
6. Write a zero byte through that auxiliary pointer.
7. Read the three-byte global region and combine it as the upper 24 bits of a word with the returned byte as the low eight bits.
8. Store that combined word into the supervisor word.
9. Mask the final selector to 30 bits, logically shift right by seven, and write a zero halfword at the resulting numeric address.
10. Attempt a call to address zero with three explicit zero arguments.
11. Return without a value if that call returns.

The halfword destination ranges from zero through 8,388,607 before architectural address interpretation. It is not forced to be aligned.

## Side effects

### Memory layout

The visible accesses establish offset relationships, not validated structures:

| Address construction | Width | Effect |
|---|---:|---|
| Implicit address plus 1 | Byte | Read small-base selector |
| Small base plus 17 | Byte | Write shifted implicit value |
| Selected scaled base plus 116 | Word | Read payload |
| Same scaled base plus 1 | Byte | Write payload’s low byte |
| Result scaled by 4 or 16, plus 20 | Word | Store captured word, link, or zero |
| Saved global-derived address plus 20 | Word | Read selected word |
| Lookup-derived byte value plus 17 | Byte | Write selected-word portion |
| Auxiliary returned pointer | Byte | Write zero |
| Masked final selector shifted right by 7 | Halfword | Write zero |

There is no explicit allocation, deallocation, ownership acquisition, or ownership release. None may be inferred for dependencies.

### Aliasing and ordering

All addresses may alias each other or globals unless the execution environment supplies stronger guarantees. The source warning specifically makes overlapping global storage plausible, but does not establish the exact overlap.

Consequently:

- The three-byte global region must be read after the auxiliary-pointer zero write.
- The second payload read must remain separate from the first.
- Global reads must retain their stated positions relative to calls.
- The terminal halfword write follows the supervisor-word reconstruction.
- Dependency calls cannot be treated as memory-preserving barriers with no effects.

### Errors and completion

No visible validation checks addresses, alignment, arithmetic range, dependency results, or call targets. No visible branch handles access faults or dependency failures. No rollback is established.

An execution that stops partway can leave preceding stores committed. The exact fault mechanism, exception behavior, and behavior of address-zero execution are environment-dependent.

## Acceptance examples

These are conditional acceptance criteria, not executed tests.

1. **Fourth-input extraction.** With a fourth input of hexadecimal FF800000, F-U003 receives 511 as its second argument, provided execution reaches that call.

2. **Unsigned selector byte.** If the initial selector byte is 200 and the shifted implicit value has low byte 53, the first direct byte write targets numeric address 217 and stores 53. The original selector-read address is not the destination base.

3. **Word read followed by byte write.** If a word read at a scaled base plus 116 returns hexadecimal 123456AB, the subsequent byte store at that base plus one writes hexadecimal AB. The read remains 32 bits wide.

4. **Fresh repeated read.** If the first scaled-base payload is hexadecimal 00000011, and an intervening dependency changes it to hexadecimal 00000022, the two corresponding byte stores write 11 and 22 respectively.

5. **Captured-word reuse.** If the captured word is hexadecimal A1B2C3D4, both later full-word distribution stores use that value even if dependencies subsequently modify its original memory location.

6. **Different scaling factors.** For dependency results of three, the scale-by-16 destination is address 68, whereas the scale-by-four destination is address 32. The two formulas must not be conflated.

7. **Wide-result link installation.** If the relevant wide result has low word three and high word five, the replacement link is 12 and its first destination is address 40. F-U030 receives 12, 5, 12, and 12.

8. **Saved global address.** If the saved-base global yields 4096, then changes to 8192 during intervening calls, the later selected-word read still targets 4116.

9. **Nested lookup.** If the captured word shifted right by 23 equals seven, the first nested lookup reads address eight. If that byte is nine, the resulting write targets address 26.

10. **Terminal reconstruction.** If the three-byte region contributes upper bits hexadecimal A1B2C3 and the final byte result is hexadecimal 7E, the supervisor-word store is hexadecimal A1B2C37E, subject to the represented concatenation semantics.

11. **Zero selector.** A zero final selector causes the terminal halfword zero write to target address zero. No null-address check is visible.
