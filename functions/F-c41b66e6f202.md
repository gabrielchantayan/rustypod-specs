# F-c41b66e6f202

## Purpose

F-c41b66e6f202 selects an indirect handler from an input record or performs a built-in operation selected by that record.

The two paths have different result contracts:

- **Indirect-handler path:** forward the handler’s complete 32-bit return value. No direct write to the caller’s output location is established.
- **Built-in path:** either initialize dependency-returned storage, copy a stored value, produce the constant one, or obtain a dependency result. Most built-in paths write a 32-bit output and return one. Two paths can return zero, with different output-write behavior.

These are observations from the supplied static body. The application meanings of the selectors, stored values, and descriptor are not established. In particular, the storage-initialization operation does not establish allocation, freshness, or exclusive ownership.

## Interface

### Inputs

The recovered interface exposes three incoming values:

1. **Output-location address:** identifies storage for a 32-bit result. It must be writable whenever execution reaches an output store.
2. **Input-record address:** identifies the record used for dispatch and built-in selection. A 32-bit field at byte offset 16 is read before any null check.
3. **Apparent incoming code address:** represented as an additional input, but its status as a public argument is unresolved. It is not an established fallback handler: a nonzero descriptor supplies a replacement handler address, while a zero descriptor forces built-in execution.

The calling convention, argument transport, and context available to an indirect handler are documented_only unknowns.

### Return value

The return is 32 bits.

For built-in execution:

- Effective selector negative four returns zero if F-43da6b23bd44 returns zero; otherwise it writes an output and returns one.
- Effective selectors one, five, and six write an output and return one, including when the written value is zero.
- Every other effective selector writes the result of F-f9450f0778b9, then returns zero for a zero result or one for any nonzero result.

For indirect-handler execution, the complete returned 32-bit value is forwarded without Boolean normalization.

### Preconditions

The following requirements are path-dependent:

- The input record permits the entry read of four bytes at offset 16.
- A nonzero descriptor address permits a four-byte read at offset eight.
- A nonzero selected handler address identifies a compatible callable target.
- Ordinary built-in execution permits the category-byte read at offset zero.
- If the category is not five, the record permits the selector read at offset four.
- Effective selector one permits a four-byte read at offset 20.
- Every reached output store has a writable four-byte destination.
- A nonzero result from F-43da6b23bd44 permits four-byte writes at offsets four and zero.

No visible validation enforces these requirements. Invalid accesses or incompatible indirect invocation are not converted into a specified zero return.

A null input record is not supported by the ordinary contract: its offset-16 field is accessed before the later null checks. The output address, by contrast, is not directly accessed on every path.

## Behavior

### Dispatch precedes built-in interpretation

The first observable data access is the 32-bit read of the descriptor address at input-record offset 16.

If that value is nonzero, the function reads a 32-bit handler address from descriptor offset eight. A nonzero handler selects indirect execution. The handler’s return value becomes this function’s return value.

On that path, this function does not directly read the category, selector, or stored-result fields and performs no direct output store. The handler’s own accesses and effects remain unspecified.

Built-in execution is selected when either:

- The descriptor address is zero; or
- The descriptor address is nonzero but its handler field is zero.

The apparent incoming code address does not change either condition. In particular, it cannot supply a fallback when the descriptor address is zero.

### Effective selector

For an ordinary valid record on the built-in path:

- The category byte is read.
- If it equals five, the effective selector is negative one, and the field at offset four is not read.
- Otherwise, the signed 32-bit field at offset four supplies the effective selector.

All operation descriptions below refer to this **effective selector**, not merely to the bytes stored at offset four.

The later null checks would also select negative one for a null record if execution reached them. They do not make the preceding unconditional record access valid.

### Effective selector negative four: initialize returned storage

The function invokes F-43da6b23bd44 with the numeric arguments eight, zero, and zero.

If the returned 32-bit address is zero, the function returns zero immediately. It performs neither initialization write nor a direct output-location write.

If the returned address is nonzero, the direct write order is:

1. Store the 32-bit value zero at returned-address offset four.
2. Store the 32-bit pattern `0xFFFFFFFF` at returned-address offset zero.
3. Store the returned address, represented as a 32-bit value, into the caller’s output location.
4. Return one.

The two initialization stores cover eight bytes. The first word’s pattern represents negative one under signed 32-bit interpretation. There is no intervening dependency call between these initialization stores and the output store.

The explicit argument eight and subsequent writes suggest an allocation-related purpose, but the body proves only the invocation and use of its result as writable storage. That storage may be new, reused, shared, or otherwise managed by the dependency; none of those alternatives is resolved here.

### Effective selector one: copy a stored value

The function reads the 32-bit value at record offset 20, writes it to the output location, and returns one.

The value is represented as address-shaped data but is not dereferenced by this operation. Zero is accepted and still results in return value one.

A null-record branch within this operation would write `0xFFFFFFFF` and return one. It is not an ordinary reachable fallback: entry already accesses the record, and the later null-record selector logic chooses negative one rather than one.

### Effective selector five: produce one

The function writes the 32-bit value one to the output location and returns one.

This is a literal result. The function does not dereference address one or establish that the value identifies an object.

A category byte of five does **not** select this operation. It forces effective selector negative one instead.

### Effective selector six: copy a dependency result

The function invokes F-83fcd2d25cd8 with the numeric argument zero.

After normal return, it writes the dependency’s complete 32-bit result to the output location and returns one. There is no zero-result failure check. A zero dependency result is therefore stored with return value one.

### Every other effective selector: conditional success

For effective selectors other than negative four, one, five, and six, the function invokes F-f9450f0778b9 with no explicit arguments shown.

After normal return, it:

1. Writes the dependency’s complete 32-bit result to the output location.
2. Returns zero if that result is zero.
3. Returns one otherwise.

This includes negative one, whether supplied by the selector field or forced by category five. Negative dependency results count as nonzero; their sign does not cause failure.

## Side effects

### Access ordering and state changes

The established direct ordering is:

1. Read the descriptor address.
2. If nonzero, read its handler address.
3. Either invoke the selected handler or enter built-in selection.
4. On the ordinary built-in path, read the category and, conditionally, the selector.
5. Perform the selected stored-value read or dependency invocation.
6. Perform the operation’s direct stores.
7. Return.

No direct write targets the record or descriptor by role. However, output storage or dependency-returned storage may alias them. The body establishes no non-aliasing guarantee.

Aliasing can affect final memory contents. For example, if the output location overlaps one of the initialized words in the negative-four operation, the later address publication can overwrite that word. The guaranteed behavior is the store sequence, not unconditional preservation of both initialization patterns afterward.

No direct output store occurs on the indirect-handler path or when F-43da6b23bd44 returns zero. This does not guarantee that the output bytes remain unchanged: the invoked dependency or handler may modify them through other access paths.

### Ownership and lifetime

For effective selector negative four, this function initializes dependency-returned writable storage and publishes its address. It performs no explicit release. It does not establish that the storage is fresh, exclusively owned, or transferred to the caller.

For effective selector one, the stored 32-bit value is copied without an explicit retain, release, or ownership-transfer operation.

For effective selector six and the default operation, any resource or ownership meaning of the dependency result is unknown.

The absence of an explicit release here does not prove that dependencies neither release memory nor alter resource ownership.

### Other effects and failures

Dependencies and the handler may modify globals, reachable memory, resource state, or error state. Their effects are not constrained by this body.

There is no visible logging, synchronization, cleanup, retry, or error-state update performed directly by this function. No behavior is specified for a dependency that fails to return normally or for an invalid memory access. Ordinary zero returns describe only the explicit checks above.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. Each assumes valid storage for all reached accesses and normal return from invoked dependencies.

1. **Handler precedence.** With a nonzero descriptor address and nonzero handler address, a handler return of `0xA5A50002` produces exactly that function return. This function performs no direct output store or built-in field reads. Handler effects remain unconstrained.

2. **Zero handler permits built-in execution.** With a readable descriptor containing a zero handler, a category other than five, and an offset-four selector of five, the function writes one and returns one.

3. **No incoming-handler fallback.** With a zero descriptor address, a category other than five, and an offset-four selector of five, a nonzero apparent incoming code address does not change the result: output one and return one.

4. **Category overrides the selector field.** During built-in execution, category five suppresses the offset-four read and selects F-f9450f0778b9. This remains true even if the offset-four bytes encode five or negative four.

5. **Storage initialization succeeds.** With effective selector negative four and a nonzero dependency-returned address, the function writes zero at offset four, then `0xFFFFFFFF` at offset zero, then publishes the address and returns one. If output storage is disjoint from those eight bytes, both initialized words remain after publication.

6. **Zero storage result.** With effective selector negative four and a zero result from F-43da6b23bd44, the function returns zero without direct initialization or output stores. Output preservation additionally requires that the dependency not modify it.

7. **Stored zero is successful.** With effective selector one and zero at record offset 20, the function writes zero and returns one.

8. **Literal one.** With effective selector five, the function writes one and returns one without calling a built-in dependency.

9. **Selector-six zero is successful.** With effective selector six and a zero result from F-83fcd2d25cd8, the function writes zero and returns one.

10. **Default zero is failure after publication.** With an effective selector outside negative four, one, five, and six, a zero result from F-f9450f0778b9 is written before the function returns zero.

11. **Default negative result is successful.** Under that same effective-selector condition, dependency result `0xFFFFFFFF` is written intact and produces return value one.

12. **Null record is not an accepted fallback.** A null record does not establish any successful output behavior because the offset-16 read precedes the null checks.
