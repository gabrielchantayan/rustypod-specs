# F-4a9a42cd22e3

## Purpose

F-4a9a42cd22e3 establishes a compound object through an initialization chain, acquires a collection using the sixth argument, populates records from selected collection entries, performs additional initialization and final field writes, and returns the object address combined with the fifth argument.

The initially stored entry count is capped at three. This is not an unconditional limit on execution: the loop rereads a writable object field, and the available evidence does not establish that dependencies preserve it.

**Established static behavior:** explicit access widths and offsets, dependency call sequence, argument forwarding, distinct reads of external initialization values, record population order, and numerical return-word composition.

**Inferred intent:** the function resembles a constructor importing a small collection of configuration records. Concrete types, application meanings, allocation behavior, and ownership are not established.

### 2. Acquire the collection and store its initial count

The function reads the word at sixth argument + `0x5C` and passes it to F-73d4385c28ec.

The result becomes the collection handle, replacing the local cell that initially held the fourth argument.

The function reads the collection’s 32-bit fields at offsets `0x18` and `0x14`. It subtracts the latter from the former and applies a signed right shift by two. The resulting 32-bit pattern is interpreted as unsigned for subsequent count handling.

The count field at object base + `0xA8` is updated as follows:

- First, write the calculated unsigned count.
- If that count exceeds three, overwrite the field with three.

The uncapped write is therefore part of the observable behavior even when immediately followed by the capped write.

For ordinary, nonnegative differences that do not encounter signed-overflow ambiguity:

| Endpoint difference | Initially selected count |
|---|---:|
| Zero through three bytes | Zero |
| Four through seven bytes | One |
| Eight through eleven bytes | Two |
| Twelve bytes or more | Three after capping |

There is no check that the difference is divisible by four. There is no check that the endpoint at `0x18` is greater than or equal to the endpoint at `0x14`.

A negative shifted result has a large unsigned interpretation and is capped at three. Signed subtraction overflow and malformed pointer relationships remain unresolved rather than being assigned a portable arithmetic meaning.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Each presumes readable and writable storage, valid reached arithmetic, and normal dependency returns.

1. **Distinct initialization-slot observations.** If the first external slot yields `0x00100000` on its first read and `0x00200000` on its second, acquisition address + `0x00` receives `0x00200000`, followed by acquisition address + `0xA4` receiving `0x00100128`. Using the second value for both writes, or reading the slot only once, does not match the established sequence.

2. **Equal initialization-slot observations.** If both reads yield `0x00100000`, the two writes receive `0x00100000` and `0x00100128`. Matching final values in this case does not eliminate the requirement for two distinct reads.

3. **Empty collection.** Equal endpoint fields produce zero. With no later count mutation, no entry-access or transformation calls occur; execution proceeds to additional initialization and final writes.

4. **Two entries.** An endpoint difference of eight produces two iterations if the count remains unchanged. Destination word pairs are `0xAC`/`0xB0` and `0xB8`/`0xBC`. Neither record’s third word has an explicit loop write.

5. **Count cap.** A difference of sixteen produces an uncapped count of four. The count field receives four and then three. With no later mutation, exactly three iterations occur.

6. **Negative difference.** A difference of negative four shifts to negative one. Its unsigned interpretation exceeds three, so the field receives that unsigned value and then three. The function does not reject this condition.

7. **Late payload read.** If a transformation dependency changes the payload’s second word before its read, the record receives the changed value, provided the payload remains readable.

8. **Mutable loop bound.** If a dependency changes the count from three to one during the first iteration and no later operation changes it again, the next comparison terminates at index one.

9. **Byte truncation.** If the input word at `0x60` is `0x123456AB` when read, the byte written at object offset `0x121` is `0xAB`.

10. **Return composition.** If the object base is `0x10203040` and the fifth argument is `0xAABBCCDD`, normal return produces the numerical value `0xAABBCCDD10203040`.
