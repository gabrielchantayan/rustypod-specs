# F-1f777e7d6df1

## Purpose

F-1f777e7d6df1 conditionally obtains an object address, checks preceding metadata, modifies seven 32-bit words through a captured shared-state address, and passes the metadata address to a dependency.

The established behavior is:

- Zero input returns immediately.
- A zero result from the object-address dependency also returns immediately.
- A nonzero result leads to a preliminary dependency call, capture of a shared-state address, and metadata validation.
- Accepted metadata leads to ordered accounting updates and subsequent dependency calls.
- Rejected metadata leads to a dependency annotated as nonreturning.

The subtractions and metadata handoff suggest allocation-accounting or release-related intent. That is **inferred intent**, not an ownership or deallocation contract. The available evidence does not establish that any dependency frees memory, transfers ownership, or completes a release.

## Interface

### Input and result

The function takes one 32-bit integer. It tests only whether that integer is zero.

Every nonzero input takes the same initial path. The input is not forwarded to the object-address dependency and is not used in the visible metadata or state-address calculations. It is therefore not established as an object address, size, or lookup key.

The function has no defined return value. Normal completion returns control without an explicit result.

### Referenced storage

A no-argument dependency returns a 32-bit address-like value, called the **object address** below.

After another dependency returns, the function reads a shared pointer slot and retains the resulting **state address**. Subsequent explicit state accesses and state arguments use this captured value.

The object-relative metadata is:

| Offset from object address | Access width | Use |
|---|---:|---|
| −8 bytes | 32 bits | Validation and masked accounting quantity |
| −4 bytes | Unsigned 16 bits | First index |
| −2 bytes | Unsigned 16 bits | Second index |

The object address minus eight bytes is the **header address**.

The explicitly updated state-relative locations are:

| Offset from captured state address | Width | Operation |
|---|---:|---|
| `0x224 + 4 × first index` | 32 bits | Subtract cached quantity |
| `0x30c` | 32 bits | Subtract cached quantity |
| `0xe0 + 4 × second index` | 32 bits | Subtract cached quantity |
| `0x220` | 32 bits | Subtract cached quantity |
| `0x310 + 4 × selector` | 32 bits | Decrement by one |
| `0x390` | 32 bits | Decrement by one |
| `0x008` | 32 bits | Subtract freshly obtained quantity |

These expressions identify effective addresses, not necessarily distinct fields. Indexed targets may coincide with fixed targets, each other, or other referenced storage. No separation between the state record and object metadata is established.

## Behavior

### Initial gates and state capture

If the input is zero, the function returns without calling a dependency or explicitly accessing shared storage.

For nonzero input, it calls F-0fe4d29cf9f4 with no arguments. If that call returns zero, the function returns without executing the subsequent helper calls, metadata reads, or state accesses. F-0fe4d29cf9f4 may itself have side effects.

For a nonzero object address, the function calls F-2fd8826557a4 with no arguments. Only after that call returns does it read and retain the shared state address. Consequently, changes that this dependency makes to the pointer slot affect the captured address.

The captured address is then used throughout this invocation’s explicit state operations. Later replacement of the shared pointer slot does not redirect those operations. This does not imply that the captured record’s contents or lifetime are preserved.

### Metadata validation

The function first reads the 32-bit header word and tests it for zero.

- If that read yields zero, it invokes F-a817d8d58c10.
- Otherwise, it reads the header word again and tests bit 0.
- If bit 0 is set in the second read, it invokes F-a817d8d58c10.
- Otherwise, execution proceeds.

The second header read is conditional: it does not occur when the first read yields zero.

For stable storage, validation accepts exactly nonzero even header values. It rejects zero and odd values. With changing storage, the zero test and low-bit test may observe different values. A nonzero first read followed by a zero second read passes these two tests.

F-a817d8d58c10 is annotated as nonreturning in the supplied static representation. The normal-flow contract has no continuation after that call. Its mechanism—termination, exception, or another nonlocal transfer—is unknown.

No explicit accounting write occurs before validation succeeds. Earlier dependencies may nevertheless have modified storage.

### Ordered accounting and handoff

After successful validation, the established operation order is:

1. Call F-c0fc6d033caa with the captured state address.

2. Read the unsigned 16-bit first index at object offset −4 and determine the first indexed state target.

3. Read the 32-bit header again. Mask it with `0x3ffffffc` and retain the result as the **cached quantity**.

4. Read the first indexed state word, subtract the cached quantity, and write the result to the same address.

5. Read the state word at offset `0x30c`, subtract the cached quantity, and write the result back.

6. Read the unsigned 16-bit second index at object offset −2 and determine the second indexed state target.

7. Read the second indexed state word, subtract the cached quantity, and write the result back.

8. Read the state word at offset `0x220`, subtract the cached quantity, and write the result back.

9. Call F-09dcb55e8e0a with no arguments. Use its 32-bit integer result as the selector for the state-relative target at `0x310 + 4 × selector`.

10. Read the selector-based target word, decrement it by one, and write it back.

11. Read the state word at offset `0x390`, decrement it by one, and write it back.

12. Update the state word at offset `0x008` by subtracting a freshly read header word masked with `0x3ffffffc`.

13. Call F-cc6c9b4a0f68 with the captured state address followed by the header address.

14. Call F-e586bff64fb7 with the captured state address.

15. Return normally if all preceding operations and dependencies complete normally.

For the update at offset `0x008`, the expression establishes a read of that state word and a fresh header read before the resulting write. It does not independently establish the relative order of those two operand reads.

### Widths and arithmetic

Both metadata indices are unsigned 16-bit values, widened before multiplication by four. Each therefore ranges from 0 through 65,535, with a scaled contribution from 0 through 262,140 bytes.

Before any machine-address wrap, the first index produces offsets from `0x224` through `0x40220`; the second produces offsets from `0xe0` through `0x400dc`. These ranges do not establish that the corresponding storage exists.

The 32-bit mask `0x3ffffffc` clears bits 31, 30, 1, and 0. A masked quantity is a multiple of four between zero and `0x3ffffffc`, inclusive.

Validation does not require a positive masked quantity. A stable header of 2 is nonzero and even, but its masked quantity is zero.

The visible accounting operations act on 32-bit words. At the represented machine-word level, subtraction and decrement produce the low 32 bits of the result; they are not saturating operations. For example, subtracting four from zero yields `0xfffffffc`, and decrementing zero yields `0xffffffff`. No explicit underflow branch is present.

The selector is returned through a 32-bit integer result and used directly in scaled address arithmetic. There is no visible conversion that restricts it to an unsigned 16-bit index, and no visible nonnegative or upper-bound check. Its valid semantic range is unknown. Neither its scaling nor address addition should be treated as unbounded mathematical arithmetic or as proof of a valid table access.

These machine-level observations do not establish how a reconstructed high-level implementation should handle signed overflow.

### Mutation and aliasing

Validation does not freeze the metadata. F-c0fc6d033caa runs before either index and the cached quantity are read. Its unknown mutation contract prevents carrying invocation-entry metadata or counter values forward as guaranteed update operands.

The first index is read before the cached quantity. The second index is read only after the first two counter writes. If those writes overlap the second index or header, they can affect later metadata consumption.

The first four quantity-based updates reuse the cached quantity. The final quantity-based update does not: it reads the header again after the selector dependency and both decrements. A dependency or an overlapping write can therefore make the final quantity differ from the cached quantity.

Every update uses the target value present when its own read executes. Overlapping targets accumulate effects in order rather than being independently derived from invocation-entry values.

## Side effects

On a normally completed accounting path, the function explicitly performs seven 32-bit read-modify-write updates. Even subtraction of zero includes the represented read and write; it does not make the whole invocation side-effect-free.

No atomicity, transaction, synchronization, or rollback guarantee is established. If execution stops after some writes, the visible function contains no compensating updates.

Dependencies may perform additional reads, writes, synchronization, allocation, deallocation, or nonlocal control transfer. Their absence cannot be assumed.

**Ownership:** The function passes the header address to F-cc6c9b4a0f68. That establishes neither ownership transfer nor reclamation. No explicit allocation or independently identifiable release operation appears in this function.

There is no further explicit metadata read after that handoff. The function does subsequently pass the captured state address to F-e586bff64fb7. The validity of that address at the later call depends on unavailable dependency contracts.

## Acceptance examples

These are conditional static consequences, not executed tests. Except for immediate-return cases, they assume valid storage for every executed access and normal return from dependencies unless explicitly stated otherwise.

1. **Zero input.** Input zero returns without invoking any listed dependency or explicitly reading the shared state pointer.

2. **Unavailable object.** With nonzero input and a zero result from F-0fe4d29cf9f4, that dependency is the only listed dependency invoked. Its own side effects remain possible.

3. **Rejected stable metadata.** If the header remains zero through validation, F-a817d8d58c10 is invoked after the preliminary helper and state-address capture, without the second validation read. A stable odd header invokes the same dependency after both validation reads. Neither case performs an explicit accounting write.

4. **Accepted zero quantity.** Suppose the header remains 2 through all relevant reads, the seven target addresses are distinct, and dependencies introduce no relevant mutations. Each quantity-based update subtracts zero from its read-time target value. Both decrement updates still decrement by one. This does not imply that dependencies have no other effects.

5. **Ordinary accounting.** Suppose the header remains `0x102`, all seven targets are distinct and disjoint from the metadata, and dependencies preserve the relevant metadata and counters. The masked quantity is `0x100`, or 256. Five target words decrease by 256 and two decrease by one, modulo 32 bits.

6. **Underflow at the actual update.** Suppose the cached quantity is four and the first indexed target contains zero **when that target’s read-modify-write executes**. That update stores `0xfffffffc`, without an explicit underflow branch. An invocation-entry value of zero is insufficient by itself: F-c0fc6d033caa runs before this update and may change the target.

7. **Overlapping counter targets.** A first index of 59 selects offset `0x310`. A selector of zero later selects that same offset. If no intervening operation modifies that word, its later value reflects subtraction of the cached quantity followed by decrement by one.

8. **Fresh final quantity.** Suppose the cached quantity is four, and F-09dcb55e8e0a subsequently changes the header so that its masked value is eight. If no later operation changes that header before the final quantity read, the first four quantity-based updates subtract four, while the update at offset `0x008` subtracts eight. No second validation is performed.

9. **Changed shared pointer.** If F-2fd8826557a4 changes the shared pointer slot before returning, the subsequent capture observes that changed slot. If a later dependency changes the slot again, explicit state operations still use the already captured address, subject to its continued validity.
