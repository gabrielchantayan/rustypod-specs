# F-ab0f19d2e216

## Purpose

F-ab0f19d2e216 samples a one-byte indication, conditionally clears it, and returns an eight-bit value combining the sampled indication with another byte.

The sampled indication contributes only to bit 0 of the result: any nonzero sampled value contributes 1, regardless of which bits were set. The other byte contributes all eight of its bits unchanged through a bitwise OR.

Under a stable-base, ordinary-memory interpretation, the function reads the byte at offset 3 of a referenced region, clears that byte if it was nonzero, and returns the byte at offset 2 with bit 0 additionally set when the sampled byte was nonzero. This is a description of the established operations, not evidence that the two bytes represent any particular protocol, event type, or device state.

## Interface

There are no explicit parameters.

The function obtains its inputs through a global address-bearing location and memory reached through that location:

| Location | Role | Access width |
|---|---|---|

| Base plus offset 3 | Supplies the indication tested for zero | One byte |
| Base plus offset 3, when the test succeeds | Receives a clearing write | One byte |
| Initially saved base plus offset 2 | Supplies the byte combined into the return value | One byte |

Offsets are byte offsets. The source representation uses an integer to hold the saved base; it does not establish a public pointer type or a complete object layout.

**Output**

The result is an eight-bit byte. Its value is the bitwise OR of:

- the byte read at offset 2 through the initially saved base; and
- 1 if the sampled offset-3 byte was nonzero, otherwise 0.

The returned indication is therefore normalized. For example, sampled values of 1, 2, and 128 all make the same contribution to the result: bit 0 is set.

**Preconditions for defined ordinary-memory behavior**

- The global address-bearing location must be readable.
- Each address used for an indirect byte read must be valid and readable at the time of that access.
- If the sampled indication is nonzero, the address selected for the clearing write must be writable.
- Address formation must be valid under the actual target’s address and integer model.
- If a caller requires the operations to concern one region, the global base must remain stable across the accesses.

No null check, bounds check, ownership check, or error-return mechanism is visible.

## Behavior

### Access sequence

The represented sequence is:

1. Read the global address-bearing value and retain it as the base for the eventual offset-2 read.
2. Evaluate the global address-bearing value for an offset-3 byte read.
3. Read that byte and classify it as zero or nonzero.
4. If it was nonzero, evaluate the global address-bearing value for an offset-3 byte write and write zero there.
5. Read one byte at offset 2 through the base retained in the first step.
6. Return that final byte ORed with the normalized result of the earlier zero/nonzero test.

This ordering matters. The offset-2 byte is read after the conditional clearing write, not before it.

The source representation refers to the global separately for the indication read and conditional write, while retaining an earlier base for the final read. It does not explicitly reuse one saved base for all three indirect operations. Consequently, a specification must not silently strengthen the behavior into “always access two fields of one immutable object.”

The precise number of machine-level global loads, instruction ordering, or bus transactions is not established by the supplied representation. In particular, no volatile or atomic qualification is shown.

### Stable-base case

If the base remains unchanged and the region behaves as ordinary memory:

- Offset 3 is read once by the represented behavior.
- If its sampled value is zero, no clearing write is performed.
- If its sampled value is nonzero, offset 3 is written with zero.
- Offset 2 is then read.
- The return value preserves bits 1 through 7 of that offset-2 byte.
- Return bit 0 is set if either the offset-2 byte already had bit 0 set or the sampled offset-3 byte was nonzero.

This does not make bit 0 an unambiguous report of the sampled indication. A result with bit 0 set can arise solely from the offset-2 byte.

### Changing-base and changing-memory cases

The saved base used for the final read is not updated when the global base changes later.

If an execution environment permits the separate global evaluations to observe different values, the indication read, clearing write, and final read need not address the same region. A nonzero indication sampled from one region could cause a zero write to another region, followed by a read from the initially selected region.

That is a limitation of the represented behavior, not a supported synchronization protocol. Whether such changes are legal or observable depends on the execution environment, memory qualifiers, and concurrency model, none of which are supplied.

Similarly, the conditional write is based on the earlier sample. There is no reread or compare-and-clear operation before writing zero. In an environment where an intervening update is possible, the write could clear a value installed after the sample.

### Widths and arithmetic

The two indirect reads and the conditional write operate on individual bytes. No multibyte field is decoded, so endianness does not affect the byte-selection behavior.

The zero/nonzero test is insensitive to whether the sampled character is interpreted as signed or unsigned: every nonzero byte produces the same true result.

The final combination is a bitwise OR, not addition. There is no carry into another bit and no returned count. With an eight-bit operand and a Boolean contribution of 0 or 1, the result remains in the range 0 through 255.

The supplied representation does not independently prove the address width, integer-overflow rules applicable to address formation, or wraparound behavior. Acceptance examples assume valid, representable addresses rather than relying on overflow.

## Side effects

The only explicit write is a one-byte zero store at offset 3, conditional on the earlier indication sample being nonzero.

The function does not explicitly:

- write offset 2;
- modify the global base;

- transfer ownership;

Ownership of the referenced storage remains outside this function. The observed accesses do not establish who owns that storage or how long it remains valid.

A zero sampled indication suppresses the clearing write entirely. For ordinary memory, writing zero to an already-zero byte might appear equivalent, but it is not the represented operation. This distinction can matter for protected or side-effecting memory.

## Acceptance examples

The following are conditional acceptance cases derived from static evidence, not executed tests.

Unless stated otherwise, assume a stable base, valid ordinary memory, no concurrent modification, and no side effects from memory access.

| Initial offset-2 byte | Sampled offset-3 byte | Returned byte | Offset-3 effect |
|---|---|---|---|
| `0x00` | `0x00` | `0x00` | No write |
| `0xA4` | `0x00` | `0xA4` | No write |
| `0xA4` | `0x02` | `0xA5` | Written to zero |
| `0xA4` | `0x80` | `0xA5` | Written to zero |
| `0xA5` | `0x01` | `0xA5` | Written to zero |
| `0xFF` | `0xFF` | `0xFF` | Written to zero |

Additional acceptance conditions:

- **Normalization:** A sampled indication of `0x80` contributes `0x01`, not `0x80`, to the return value.
- **Repeated call:** Starting with offset 2 equal to `0x20` and offset 3 equal to a nonzero byte, a first call returns `0x21` and clears offset 3. With no intervening changes, a second call returns `0x20`.
- **Ambiguous return bit:** With offset 2 equal to `0x21`, the return is `0x21` whether offset 3 was zero or nonzero. Only the conditional write distinguishes those cases.
- **Read-only indication storage:** A zero indication does not require a clearing write. A nonzero indication does. This does not guarantee successful execution on any particular protected-memory platform.
- **Changing base:** If the environment permits different global values to be observed, acceptance must account separately for the initially saved base, the indication-read base, and the clearing-write base. Requiring all three to match would add a guarantee absent from the supplied evidence.
