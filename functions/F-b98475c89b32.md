# F-b98475c89b32

## Purpose

F-b98475c89b32 conditionally allocates a 44-byte record, writes selected fields, obtains a Boolean through indirect dispatch, and submits the record to a dependency. It then checks allocation metadata, changes accounting words, and invokes two release-related dependencies.

A nonzero second argument disables the entire operation. A zero second argument enables an allocation attempt; allocation failure produces a silent return.

The interpretation as temporary-record submission followed by allocator accounting and release is **inferred intent**. The established behavior is the allocation request, ordered memory accesses, dependency calls, short-circuited metadata checks, and arithmetic described below. The dependency implementations and their ownership contracts are unavailable.

## Behavior

For a zero second argument, F-d33f6d597e5d is called with size 0x2C, or 44 bytes. A null result causes immediate return. There is no local retry, error report, submission, or caller-field read on allocation failure.

Following a nonnull allocation, the function reads the 32-bit caller field at offset 0x44 and writes it at payload offset 0x00. It then performs the zero halfword write at 0x06 and the byte writes at 0x08, 0x09, and 0x0C, in that order.

F-15643c36365d is called after those writes. From the returned object, the function reads a dispatch-table address at object offset zero, then obtains the callable entry at table offset 0x4C and invokes it.

The indirect operation’s argument convention is unresolved. The supplied representation shows no explicit receiver argument; this contract does not infer one.

After the indirect call returns, the function writes its nonzero comparison result as one byte at payload offset 0x0D. Zero produces zero; every nonzero 32-bit result, including a negative result, produces one.

The distinction between writes and later contents is material:

- The initial five fields are written before both intervening calls.
- The Boolean field is written after those calls.
- No dependency call is shown between the Boolean write and invocation of submission.
- There is no established exclusion of concurrent mutation.

Consequently, the earlier fields have their written values at submission only under suitable preservation assumptions. The Boolean write is established independently of whether the earlier bytes were changed.

### Metadata layout and short-circuited validation

The preceding allocation metadata is accessed as follows:

| Offset from payload | Width | Use |
|---|---:|---|
| −0x08 | 32 bits | Validation expressions and masked accounting magnitudes |
| −0x04 | Unsigned 16 bits | Index for the counter region based at context offset 0x224 |
| −0x02 | Unsigned 16 bits | Index for the counter region based at context offset 0x0E0 |

Validation consists of **two short-circuited read expressions**, not one captured header value:

1. The first expression reads the 32-bit word at offset −0x08 and tests whether it is zero.
2. Only if that test is false does the second expression read the word at the same address and test bit 0.

If the first read is zero, or if the second read has bit 0 set, F-a817d8d58c10 is invoked. That dependency is represented as nonreturning. No later accounting or release-related call is reached on this path.

If the header is stable across both expressions, validation rejects zero and odd values, while accepting nonzero even values. Without stability, acceptance requires only that the first observed value be nonzero and the second observed value have bit 0 clear. The two observations need not be equal. In particular, a second observation of zero does not itself cause rejection.

There is no explicit synchronization call between these two expressions. The representation establishes expression-level short-circuit behavior; it does not establish physical load behavior on a particular executable or exclude concurrent mutation.

### Widths, arithmetic, and aliasing

The accounting mask clears the low two and high two bits of a 32-bit word. Its result ranges from zero to 0x3FFFFFFC in multiples of four. A stable header of 2 passes validation but yields a zero magnitude.

Each metadata index is unsigned 16-bit, so its four-times-scaled displacement ranges from zero through 262,140 bytes. The function does not check table bounds.

The result from F-09dcb55e8e0a is represented as a 32-bit integer, not a zero-extended metadata halfword. No local range or nonnegativity check precedes its use as an index.

The accounting stores are 32-bit operations. At the represented machine-width level, subtraction and decrement retain the low 32 bits; no local overflow or underflow error path is provided. Address calculations also use the represented 32-bit address width. Validity of derived addresses is an operational requirement, not a guarantee supplied by these calculations.

The seven counter updates need not target seven distinct words. If addresses coincide, later updates operate on the effects of earlier writes. If counter destinations overlap metadata, earlier writes can also affect subsequent metadata reads. The function neither checks separation nor snapshots all counters or metadata in advance.

## Acceptance examples

These are conditional expectations from static evidence, not runtime observations.

### Disabled invocation and allocation failure

With any nonzero second argument, including a negative value, no dependency is called and the first argument is not dereferenced.

With a zero second argument and a null allocation result, the only dependency call is the 44-byte allocation request. The caller field is not read.

### Payload writes and submission contents

Given successful allocation and readable caller storage, the function performs the first five payload writes before invoking F-15643c36365d and the indirect operation.

If both intervening operations preserve those bytes, no other mutation changes them before submission, and the indirect result is zero, submission begins with the copied field, specified zeros, byte 20 at offset 0x09, and zero at offset 0x0D.

Under the same preservation conditions, an indirect result of −1 makes offset 0x0D equal one.

Without preservation by both intervening operations, only the individual writes are established for the earlier fields; their submission-time values are not guaranteed. Unspecified payload bytes remain unconstrained.

### Short-circuited rejection

If the first validation observation is zero, F-a817d8d58c10 is invoked without evaluating the bit-0 read expression.

If the first observation is nonzero and the second is 5, the second observation causes rejection. Submission and F-2fd8826557a4 have already occurred in either case.

### Changing validation observations

If the first observation is 2 and the second is zero, validation permits continuation: the first test is false and the second observation has bit 0 clear. This does not establish that later metadata reads remain zero.

Conversely, observations of 2 followed by 3 cause rejection. The first observation’s evenness does not determine the second test.

### Stable masked magnitude

Given a header stable at 0xC0000102 across validation and accounting reads, valid destinations, and no relevant interfering mutations, both validation expressions permit continuation and the masked magnitude is 0x100. Each of the five magnitude-based updates subtracts 256; the two count updates subtract one.

### Later metadata mutation

If F-c0fc6d033caa changes the header after validation, the first four subtractions use the masked post-call observation without revalidation.

If F-09dcb55e8e0a changes the header again, the final subtraction at context offset 0x08 uses the later observation. The two magnitudes need not match.

### Underflow and zero magnitude

A counter containing zero, updated with magnitude four, receives 0xFFFFFFFC at the represented 32-bit width. No error call is triggered solely by that underflow.

With a stable header of 2, the magnitude-based arithmetic subtracts zero, but the two count decrements still occur.
