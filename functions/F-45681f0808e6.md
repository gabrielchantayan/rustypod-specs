# F-45681f0808e6

## Purpose

F-45681f0808e6 determines whether a supplied 32-bit unsigned value has an eligible entry in any of a sequence of range descriptors, followed by an optional additional descriptor.

A descriptor is eligible when:

- Its inclusive range contains the supplied value.
- The corresponding 16-bit table entry is not the all-ones value, `0xFFFF`.

The function returns a 32-bit result of 1 for the first eligible descriptor found, or 0 if the examined descriptors provide no eligible entry.

The function calls F-4a19e3742733 before reading the collection count and calls F-fd58bea73663 before every normal return. Both receive the address at object offset `0x18`. Their placement suggests entry and exit operations for a protected region, but synchronization semantics are inferred intent, not established behavior.

## Interface

### Inputs

The function has two inputs:

| Input | Represented width | Interpretation |
|---|---:|---|
| Object address | 32 bits | Base address of a memory-resident object containing collection access information, a signed count, an optional descriptor pointer, and a dependency-specific region. |
| Query value | 32 bits, unsigned | Value tested against descriptor bounds and used to select a 16-bit table entry. |

The object address is used for address arithmetic and memory access. It is not validated.

The query is not truncated to 16 bits. Although descriptor bounds are only 16 bits wide, comparisons use the full unsigned query value.

### Result

On normal completion, the result is a 32-bit value:

- **1:** At least one examined descriptor contains the query and has a selected table entry other than `0xFFFF`.
- **0:** No examined descriptor satisfies both conditions.

There is no distinct result for invalid pointers, malformed tables, dependency failures, or memory-access errors. The supplied evidence does not define normal recovery from those conditions.

### Relevant object layout

Offsets are byte offsets from the object address.

| Offset | Observed use |
|---|---|
| `0x04` | Beginning of a collection-facing subobject. Its first 32-bit field supplies a dispatch-table address. |
| `0x08` | Signed 32-bit collection count, read once after F-4a19e3742733 returns. |
| `0x14` | 32-bit pointer to an optional additional descriptor. |
| `0x18` | Address passed to both named dependencies. The contents and extent of this region are unknown. |

The collection operation is selected through a 32-bit callable entry at byte offset `0x40` in the dispatch table. Its arguments are the subobject address at object offset `0x04` and the current zero-based index.

The collection operation returns an address. The first 32-bit field at that address supplies the descriptor pointer. The function does not treat the returned address itself as the descriptor.

### Descriptor layout

Each examined descriptor has these relevant fields:

| Offset | Width | Interpretation |
|---|---:|---|
| `0x00` | 16 bits | Unsigned inclusive lower bound. |
| `0x02` | 16 bits | Unsigned inclusive upper bound. |
| `0x04` | 32 bits | Address of a table of 16-bit entries. |

The selected table entry is at a byte displacement of twice the difference between the query and the descriptor’s lower bound.

The selected 16-bit entry is tested against signed 16-bit −1. For this comparison, that sentinel has the bit pattern `0xFFFF`. Every other bit pattern qualifies, including zero and values that would be negative under signed 16-bit interpretation.

### Preconditions for defined ordinary operation

The evidence contains no validation layer. Ordinary operation therefore requires:

- A usable object address and accessible object fields.
- Successful normal returns from the dependencies and collection operation.
- A valid dispatch-table address and callable entry for every indexed lookup actually performed.
- A valid returned wrapper address and descriptor pointer for every indexed lookup actually performed.
- Readable bounds for each examined descriptor.
- A usable table pointer and readable selected entry whenever a descriptor’s bounds contain the query.
- Memory and address arithmetic compatible with the represented 32-bit layout.

A non-null descriptor pointer is not sufficient by itself: the bounds and any selected table entry must also be accessible. No particular alignment guarantee or target byte order can be established from the supplied listing alone.

## Behavior

### Entry and count observation

The first observable external operation is a call to F-4a19e3742733 with the object address plus `0x18`.

Only after that dependency returns does the function read the signed 32-bit count at object offset `0x08`. The function retains that count for its traversal. Later changes to the count field do not change the retained traversal bound.

The dependency can therefore affect which count is observed. Nothing in the supplied evidence establishes that it preserves object state, global state, or memory ownership.

### Indexed descriptors and the optional descriptor

For a nonnegative count, indexed descriptors are considered in increasing index order, starting at zero. The optional descriptor is considered only after all indexed descriptors have failed to qualify.

Each indexed lookup uses the collection-facing subobject at offset `0x04`. The dispatch-table address and the callable entry are obtained for that lookup; they are not shown as being cached for the entire traversal. Consequently, an earlier callback’s mutation of collection dispatch state can affect a later lookup.

The collection callback’s returned address is dereferenced once to obtain the descriptor pointer. Neither the returned address nor this descriptor pointer is checked for null.

The optional descriptor differs in two respects:

- Its pointer comes directly from object offset `0x14`.
- A null pointer means there is no optional descriptor, and ends the search with no match.

That optional pointer is read when traversal reaches the optional position, not at function entry. Earlier dependency or callback activity can therefore affect which optional descriptor is observed.

Count edge cases are significant:

- **Negative count:** No descriptor is examined. The optional pointer is not read. Normal completion returns 0 after the exit dependency.
- **Zero count:** No indexed lookup occurs. The optional descriptor is the only possible candidate.
- **Positive count:** The indexed descriptors precede the optional descriptor.
- **Maximum signed 32-bit count:** A path that reaches the optional position, processes a non-null nonmatching descriptor, and continues would increment the signed traversal index beyond its representable maximum. The supplied listing does not establish a safe outcome for this case. A null optional pointer or an earlier match avoids that increment.

An earlier qualifying descriptor terminates the search. Later indexed callbacks and the optional-pointer read do not occur on that path.

### Range checks and table access

For each descriptor, eligibility is determined in this order:

1. The lower bound must not exceed the unsigned query.
2. The query must not exceed the upper bound.
3. The selected table entry must differ from `0xFFFF`.

The conditions are short-circuited. A query below the lower bound does not require the upper-bound or table-entry check. A query above the upper bound does not require the table-entry check. The table pointer and selected entry are accessed only when both bounds checks succeed.

The bounds are inclusive. A query equal to either endpoint is eligible for table inspection.

When both range checks succeed, the query and lower bound are each within the 16-bit unsigned range. Their difference is therefore between 0 and 65,535, and the byte displacement is between 0 and 131,070. This multiplication does not overflow 32-bit unsigned arithmetic on a successfully gated lookup. Adding that displacement to a table address must still produce a valid accessible address; the function does not check address overflow or allocation extent.

A query greater than 65,535 cannot satisfy any descriptor’s upper-bound comparison. Such a query does not cause a table-entry read, but it does not bypass collection traversal.

A descriptor with a lower bound greater than its upper bound cannot qualify for any query. It is not reported as malformed.

### Sentinel handling and completion

An in-range entry of `0xFFFF` rejects only that descriptor. The search continues, so an overlapping later descriptor may still produce success.

For the first qualifying descriptor, F-fd58bea73663 is called with the object address plus `0x18`, and the function then returns 1.

If traversal finishes without a qualifying descriptor, the same dependency is called with the same address, and the function then returns 0.

For any normal path on which all required calls return, each named dependency is called once. No cleanup behavior is established for abnormal termination, a failing memory access, or a dependency that does not return.

## Side effects

The function contains no explicit store to the object, descriptors, entry tables, or global memory.

Its observable actions nevertheless include:

- Calls to the entry and exit dependencies.
- Calls to the collection operation for each indexed descriptor reached.
- Reads of object dispatch state, the retained count, callback result wrappers, descriptor bounds, and selected table entries.
- A read of the optional pointer if traversal reaches it.
- Early termination that suppresses later calls and reads.

The named dependencies and collection operation may have side effects not visible in the supplied evidence. They must not be assumed to preserve globals, leave the object unchanged, or avoid allocating or releasing memory.

The function itself performs no explicit allocation, release, reference-count update, or ownership transfer. Ownership and lifetime rules for the object, wrappers, descriptors, and tables are undocumented. In particular, the absence of an explicit release does not establish whether a callback result is borrowed or owned.

No error reporting, retry, logging, or compensating action is visible.

## Acceptance examples

These examples are conditional specifications, not observed runtime results. Unless stated otherwise, all required memory is valid and all called dependencies return normally.

1. **Matching lower endpoint.**  
   An indexed descriptor covers 100 through 102. Its first table entry is 0. Query 100 returns 1 after the exit dependency. Entry value 0 is eligible.

2. **Matching upper endpoint.**  
   The same range has `0xFFFF` in its first two entries and `0x8000` in its third. Query 102 returns 1. A non-sentinel entry is eligible even when its signed 16-bit interpretation is negative.

3. **Sentinel followed by overlap.**  
   The first descriptor contains the query but selects `0xFFFF`. A later descriptor also contains the query and selects 7. Both descriptors are examined; the result is 1.

4. **Early success suppresses later work.**  
   The first indexed descriptor qualifies. No later indexed callback is invoked, and the optional pointer is not read.

5. **Optional-only success.**  
   The retained count is zero and the optional pointer is non-null. Its descriptor contains the query and selects a non-sentinel entry. No indexed callback occurs; the result is 1.

6. **Absent optional descriptor.**  
   No indexed descriptor qualifies, and the optional pointer is null when read. The result is 0. No descriptor is dereferenced through that null pointer.

7. **Negative count.**  
   The retained count is −1. The function performs no indexed lookup and does not read the optional pointer. It calls the exit dependency and returns 0.

8. **Query beyond all representable upper bounds.**  
   Query 65,536 is used with an ordinary finite traversal. Every reached descriptor fails its range test without a table-entry read. After traversal and the exit dependency, the result is 0.

9. **Reversed bounds.**  
   A descriptor has lower bound 20 and upper bound 10. It never qualifies, and its table is not accessed through the eligibility path.

10. **Count mutation during traversal.**  
    The count is read as 2. The first callback changes the object’s count field to zero. If the first descriptor does not qualify, the function still reaches indexed position 1 because traversal uses the retained count.

11. **Optional pointer changed by a callback.**  
    An indexed callback changes the optional pointer. If no indexed descriptor qualifies, the function uses the pointer present when the optional position is reached, rather than an entry-time snapshot.

12. **Invalid table avoided by range failure.**  
    A readable descriptor has an unusable table pointer, but its range excludes the query. That table pointer is not dereferenced on this descriptor’s evaluation. This does not establish that the entire traversal succeeds; later descriptors may require other accesses.
