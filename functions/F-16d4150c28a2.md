# F-16d4150c28a2

## Purpose

F-16d4150c28a2 conditionally resolves a 32-bit selector against an object-like reference and, when resolution produces a nonzero token, dispatches an operation to a prepared receiver.

Two incoming selector values suppress all further processing. Other selectors may first be replaced by a dependency’s result. Resolution uses an indirect probe followed, on a zero probe result, by a fallback resolver. Successful resolution is followed by receiver preparation, a receiver-state query, and one of two indirect actions.

This description establishes control flow, data widths, and observable accesses from the supplied static material. Interpretations such as “selector,” “reference,” “token,” and “receiver” are descriptive labels, not recovered application-level types. No runtime tests have been performed.

## Interface

The function has five inputs and no defined result value:

| Input | Representation | Established use |
|---|---|---|
| Payload | Opaque 32-bit value | Passed unchanged to the final action, if reached. |
| Selector | 32-bit integer | Checked for suppression, optionally replaced, then supplied to resolution dependencies. |
| Source reference | Pointer to readable 32-bit words | Its first word supplies a tagged address. Its second word is copied only after a nonzero direct probe result. Dependencies may introduce additional requirements. |
| Context | Pointer represented at the target’s pointer width | Passed unchanged to receiver preparation. Its first 32-bit word is read by this function only on the nonzero receiver-state branch. |
| Replacement flag | 32-bit integer | Zero retains the incoming selector; any nonzero value requests selector replacement. |

The observed address and word operations use a 32-bit model. The supplied material does not establish portability to another pointer width.

### Reference and object layouts

The source reference has at least the following caller-visible layout on the direct-success path:

| Byte offset | Width | Meaning established here |
|---|---:|---|
| 0 | 32 bits | Tagged address word; bit 0 is removed when constructing an object base. |
| 4 | 32 bits | Companion word copied into the temporary reference after direct success. |

Let the **original base** be the source reference’s initially read first word with bit 0 cleared. Depending on the path, the function accesses:

- A 32-bit value at original base plus `0x48`, used as a fallback argument.
- A 32-bit word at an adjusted address derived from the original base, used for indirect probe resolution when the descriptor’s low bit is set.

A temporary reference consists of two adjacent 32-bit words, both initially zero. Receiver preparation receives a pointer to its first word. Its final first word, with bit 0 cleared, supplies the action receiver.

The prepared receiver is treated as beginning with a 32-bit dispatch-table pointer. The table entries used here are at byte offsets `0x14`, `0x0c`, and `0x24`.

These are accessed layouts, not proof of complete object sizes or type identities.

## Behavior

### 1. Suppression precedes all dependency calls

Incoming selectors `0x200b` and `0x2060` cause an immediate return.

This decision uses the incoming selector, before any optional replacement. On either suppressed path, the function does not:

- Call the replacement dependency.
- Read the dispatch descriptor.
- Dereference the source reference or context.
- Prepare or invoke a receiver.

The subtraction used in the supplied material reduces to the second equality check under 32-bit target arithmetic. It does not establish a valid selector range.

### 2. Optional selector replacement

For an unsuppressed input, a nonzero replacement flag causes a call to F-e96652a26484 with no explicit arguments. Its returned word becomes the **effective selector**.

With a zero replacement flag, the effective selector is the incoming selector.

Suppression is not repeated after replacement. Consequently, a replacement result equal to either suppressed value still proceeds into resolution.

The replacement dependency executes before the dispatch descriptor and source-reference word are read. Changes it makes to that state can therefore affect subsequent processing. Its side effects are otherwise unknown.

### 3. Initialize temporary state and snapshot the probe descriptor

The two-word temporary reference is initialized to zero.

The function then reads a two-word shared dispatch descriptor:

1. The first word is retained as the **descriptor address**.
2. The second word is retained as the **adjustment word**.
3. The source reference’s first word is read and retained as the **original tagged address**.

The supplied material does not establish that the shared descriptor is immutable, atomically updated, or protected against concurrent access.

The adjusted probe receiver is formed by:

- Clearing bit 0 of the original tagged address.
- Interpreting the adjustment word as a signed 32-bit quantity and arithmetically shifting it right by one bit.
- Adding that signed displacement to the untagged base.

The displacement is in bytes; it is not multiplied by a word or element size.

### 4. Select and invoke the probe

The adjustment word’s low bit selects the probe mechanism.

- **Low bit clear:** the descriptor address itself is used as the callable address.
- **Low bit set:** the function reads a 32-bit word from the adjusted probe receiver, adds it to the descriptor address with its lowest two bits cleared, and reads the callable address from that resulting location.

The selected dependency, locally identified as F-U01, is invoked with:

1. The adjusted probe receiver.
2. The effective selector.

Its return is a 32-bit token candidate. The full returned word is retained in a separate temporary token slot.

Clearing two low bits applies only to indirect lookup through the descriptor. The direct-call path does not perform that clearing.

### 5. Resolve the token and temporary reference

#### Nonzero direct result

If F-U01 returns any nonzero 32-bit value:

- That full-width value becomes the resolved token.
- The source reference’s first word is read again and copied into the temporary reference.
- The source reference’s second word is then read and copied into the temporary reference.
- The fallback resolver is not called.

These reads occur after F-U01 returns. The prepared reference can therefore reflect mutations made during the probe, rather than the initially captured tagged address.

The token is not narrowed to 16 bits on this path.

#### Zero direct result

If F-U01 returns zero, F-b5164379c09e is called with:

1. The effective selector.
2. The 32-bit value read at original base plus `0x48`.
3. The captured descriptor address.
4. The captured adjustment word.
5. A pointer to the first word of the zero-initialized temporary reference.
6. A pointer to the temporary token slot, initially containing the probe’s zero result.

The field at original base plus `0x48` is read after the probe returns. Its address nevertheless uses the originally captured tagged address, not a fresh read of the source reference.

The fallback’s return value is interpreted as a zero/nonzero success indicator:

- Zero means resolution failed, regardless of writes to either temporary.
- Nonzero means the resolved token is the low 16 bits of the temporary token slot, zero-extended to a 32-bit value.

A successful fallback can therefore still produce a zero resolved token. For example, a token-slot value of `0x12340000` yields zero after masking.

The captured descriptor words remain the fallback arguments even if the probe changes the shared descriptor.

### 6. Stop if the resolved token is zero

A zero resolved token ends processing. Receiver preparation, receiver-state querying, context-derived argument construction, and final action invocation are skipped.

This includes both:

- A fallback reporting failure.
- A fallback reporting success but leaving the low 16 bits of the token slot zero.

There is no outward error result distinguishing these cases.

### 7. Prepare the reference

For a nonzero resolved token, F-ead3143314e1 is called with:

1. A pointer to the temporary reference’s first word.
2. The context pointer.

After it returns, the function reads the temporary reference’s first word, clears bit 0, and retains the resulting address as the **prepared receiver**.

The resolved token was selected before this call. It is not subsequently reloaded from the temporary token slot.

No preservation guarantee is established for the temporary reference, the context, globals, or other dependency-accessible state. In particular, the receiver comes from the post-call reference, not the pre-call reference.

### 8. Query receiver state and perform one action

The function reads the prepared receiver’s dispatch-table pointer, obtains the entry at byte offset `0x14`, and invokes that dependency, F-U02, with the prepared receiver.

The returned 32-bit value selects one final action:

| Receiver-state result | Action dependency | Arguments |
|---|---|---|
| Zero | F-U03, obtained from table offset `0x0c` | Prepared receiver, resolved token, payload |
| Nonzero | F-U04, obtained from table offset `0x24` | Prepared receiver, resolved token, payload, context-derived value |

The context-derived value is the context’s first 32-bit word plus eight. This is numeric addition to the word stored at the context address, not pointer advancement of the context argument itself. No pointed-to data at that resulting value is read by this function before passing it onward.

After the state query, the dispatch-table pointer is read again from the same retained prepared receiver. Thus a table change made by F-U02 can affect which action is invoked. The receiver itself is not recomputed from the temporary reference after that query.

There is no explicit overflow check for the addition of eight. The observed target-width operation supplies a 32-bit result; language-level guarantees outside the supplied target representation are not established.

The final action’s return value is ignored.

## Side effects

The function directly writes its own temporary reference and token storage. It contains no explicit allocation, deallocation, reference-count update, or direct write to caller-owned object fields.

Its externally observable effects can include:

- Calls to the replacement, probe, fallback, preparation, state-query, and action dependencies.
- Reads of shared dispatch state.
- Reads through the source reference, original object base, descriptor lookup, prepared receiver, dispatch tables, and context.
- Any mutations or other effects performed by dependencies.

No ownership transfer or release obligation is established merely by passing an address to a dependency. The preparation dependency’s name or position does not establish retaining, releasing, copying, locking, or validation behavior.

Pointers into the temporary reference and token slot are local to this invocation. The visible function supplies no mechanism extending their lifetime beyond its return; dependency retention or asynchronous use is unknown.

There is no visible error reporting, null-pointer check, alignment check, bounds check, or recovery path for invalid dispatch addresses. Valid readable storage and callable targets are required wherever a reached path performs those accesses. Suppressed paths do not impose those dereference requirements through this function.

The staged sequence above establishes ordering across calls and completed assignments. It does not establish a strict evaluation order among all reads within a single call expression, particularly the final dispatch-target lookup and context-derived argument read.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each presumes valid memory and callable dependencies for all reached operations.

1. **Incoming suppression overrides replacement.**  
   Given incoming selector `0x200b` and a nonzero replacement flag, the function returns without calling F-e96652a26484. The same holds for incoming selector `0x2060`.

2. **Replacement values are not suppressed again.**  
   Given an unsuppressed incoming selector, a nonzero replacement flag, and replacement result `0x200b`, F-U01 receives `0x200b`. Processing is not stopped by a second suppression check.

3. **Direct results retain their upper bits.**  
   If F-U01 returns `0x00010000`, the fallback is skipped and receiver preparation is reached. The final action receives token `0x00010000`, subject to the intervening calls completing normally.

4. **Direct success uses the post-probe reference.**  
   If F-U01 changes either source-reference word before returning a nonzero token, the subsequent copy observes the words read after that call. It is not required to reproduce the initially captured first word.

5. **Fallback field location uses the captured base.**  
   If the probe changes the source reference’s first word and then returns zero, the fallback field is still read at the original untagged base plus `0x48`. A changed field value at that original location may be observed.

6. **Fallback narrows the token.**  
   If the probe returns zero, the fallback returns nonzero, and the token slot becomes `0xabcd1234`, the resolved token is `0x1234`.

7. **Fallback success alone is insufficient.**  
   If the fallback returns nonzero but writes `0xabcd0000`, receiver preparation and final dispatch are skipped.

8. **Fallback failure overrides written output.**  
   If the fallback writes a nonzero token but returns zero, no receiver preparation or action follows.

9. **A negative adjustment is signed.**  
   With adjustment word `0xfffffffe`, arithmetic right shift produces a displacement of negative one byte. Its low bit is clear, so the descriptor address is used directly as the probe target. Validity of the resulting receiver remains a precondition.

10. **Preparation controls the receiver.**  
    If F-ead3143314e1 replaces the temporary reference’s first word, the state query and action use that replacement with bit 0 cleared.

11. **The state query can change final dispatch.**  
    If F-U02 replaces the receiver’s table pointer, the selected final action comes from the newly read table at the branch-specific offset.

12. **Extended action uses the post-query context value.**  
    If F-U02 returns nonzero and changes the context’s first word to `0x1000`, F-U04 receives `0x1008` as its fourth argument. On a zero state result, this function does not perform that context-word read.
