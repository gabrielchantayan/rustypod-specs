# F-864f3bf8be47

## Purpose

F-864f3bf8be47 traverses a linked structure using a supplied four-byte value and a comparison dependency. It then either reports a selected candidate or calls F-474b7e2941e6 and reports the contents of the local storage supplied to that dependency.

The direct result occupies five bytes:

- A four-byte value at result offset 0.
- A one-byte status at result offset 4.

Status 0 identifies candidate reporting without delegation. Status 1 identifies execution of F-474b7e2941e6; it does not establish that the dependency inserted anything, succeeded, or wrote its output storage.

An ordered-tree search followed by duplicate checking and insertion is inferred intent. The supplied evidence establishes field accesses and control flow, not the comparison relation, tree invariants, allocation policy, or delegated operation’s semantics.

### Local storage relevant to delegation

Two distinct four-byte local slots can serve as delegated output storage:

- **Immediate-delegation slot:** passed to F-474b7e2941e6 only when the boundary helper returns nonzero.
- **Common-delegation slot:** passed to F-474b7e2941e6 on the other delegated paths. This is also the boundary-value slot passed to F-50be1c0375de.

Neither slot is initialized at function entry. Both are explicitly cleared before every search comparison, but an empty traversal performs no such clearing. Their incoming contents are therefore part of the call-site contract, not guaranteed fresh output-only storage.

### Preconditions

Defined normal completion requires readable fields for every reached object, writable result storage, terminating traversals, and dependencies that return normally with subsequent accesses remaining valid.

The function supplies no null checks for the container or header, no general null-parent protection, and no cycle detection. A null initial traversal link is handled; a null header is not established as a valid empty representation.

No general non-aliasing, alignment, concurrency, or ownership guarantee is supplied.

## Behavior

### Search initialization and traversal

The remembered comparison outcome starts at the 32-bit integer value 1.

The function first reads the container’s header address and that header’s offset-4 field to obtain the initial traversal node. It separately reads the container’s header address again and retains that second value as the initial last-visited object. These header reads are not a single snapshot.

For each nonnull traversal node, the following order is established:

1. Write four-byte zero to the immediate-delegation slot.
2. Write four-byte zero to the common-delegation slot.
3. Call F-e2cfac22dfa4 with the container-plus-25 address, the supplied value, and the current node-plus-16 address.
4. Retain the current node as the last-visited object.
5. Read the next link from that node: offset 12 for a zero comparison result, offset 8 for a nonzero result.

Only zero versus nonzero matters. Negative and positive nonzero results select the same branch.

The next-link read occurs after the dependency returns. Dependency mutations can therefore affect traversal. Every visited node causes both local slots to be cleared again before its comparison.

Traversal ends when the selected link is null. If the initial link is null, no search comparison or slot clearing occurs, the retained object remains the header from the second read, and the remembered outcome remains 1.

### Control-byte decision

After traversal, the function reads the container’s offset-24 byte.

A nonzero byte selects common delegation immediately. No candidate slot is initialized, boundary helper called, or candidate extracted on this path.

A zero byte causes the candidate slot to receive the retained last-visited object. The remembered search outcome then determines whether boundary processing is necessary.

### Boundary processing

Boundary processing occurs only when the control byte is zero and the remembered search outcome is nonzero. This includes an empty traversal.

The function re-reads the container’s header address, reads that header’s four-byte offset-8 value, and writes it into the **common-delegation slot**, replacing any earlier zero. It calls F-50be1c0375de with:

1. The address of the candidate slot.
2. The address of the common-delegation slot.

The helper may modify either slot. Neither argument is established as read-only.

A nonzero helper result selects immediate delegation using the immediate-delegation slot. The retained search object, not the potentially modified candidate, remains the fourth argument to F-474b7e2941e6. No candidate adjustment, extraction, or final comparison occurs.

A zero helper result selects candidate adjustment using the candidate slot’s post-call contents. The common-delegation slot retains the boundary value or whatever the helper left there, subject to later indirect effects.

### Candidate adjustment

Adjustment begins by reading the candidate’s marker byte. Only zero versus nonzero is tested.

If the marker is zero, the function follows the candidate’s offset-4 link and reads that object’s offset-4 field. If this equals the candidate, adjustment replaces the candidate with its offset-12 link.

Otherwise, the function examines the candidate’s offset-8 link:

- It first loads that link into traversal storage.
- It separately reads the same field again for the null test.
- If the tested value is nonnull, it descends using offset-12 links.
- If the tested value is null, it ascends using offset-4 links.

For descent, each iteration makes the current traversal object the candidate, reads its offset-12 link into traversal storage, and separately reads the same field again to decide whether to continue. With stable links, the terminal candidate is the object whose offset-12 link is null.

For ascent, the initial parent comes from the candidate’s offset-4 field. Each step compares the parent’s offset-8 link with the child just left, then makes that parent the candidate. Equality continues ascent through the parent’s offset-4 link; inequality stops with that parent as candidate.

These transitions resemble an in-order predecessor operation, but that interpretation requires unprovided structural invariants. Repeated link reads are not guaranteed to agree under mutation. There is no general null-parent guard or cycle detection.

### Candidate extraction and final comparison

Candidate checking occurs when the control byte is zero and either:

- The final search outcome was zero, bypassing boundary processing; or
- The boundary helper returned zero and adjustment completed.

Before extraction, the body clears a separate four-byte temporary whose value is not subsequently used directly by the visible logic. This does **not** clear either delegated output slot.

The function calls F-486ccfed49f1 with the candidate value. Its four-byte return value becomes the second argument to F-e2cfac22dfa4, with the container-plus-25 address first and the original supplied value third.

Thus the final comparison uses different operand roles from search: extraction output precedes the supplied value.

If this comparison returns zero, the function writes the candidate to result offset 0 and prepares status 0. No delegated operation occurs.

A nonzero comparison result selects common delegation. The adjusted candidate does not replace the retained search object in the delegated arguments.

### Delegation and incoming slot contents

Every F-474b7e2941e6 call receives:

1. The address of the selected four-byte local slot.
2. The original container address.
3. A literal zero.
4. The retained last-visited search object.
5. The original supplied value.

The following table describes the selected slot’s state established by the body before delegation. Unknown indirect writes can alter these states.

| Delegated path | Selected slot | Body-established incoming contents |
|---|---|---|
| Nonzero control byte, nonempty traversal | Common | Zero from the last search iteration |
| Nonzero control byte, empty traversal | Common | Uninitialized |
| Nonzero boundary-helper result, nonempty traversal | Immediate | Zero from the last search iteration |
| Nonzero boundary-helper result, empty traversal | Immediate | Uninitialized |
| Nonzero final comparison, boundary processing bypassed | Common | Zero from the last search iteration |
| Nonzero final comparison after boundary processing | Common | Header offset-8 value, as possibly modified by the helper and later indirect effects |

These are not unconditional guarantees that the slot still holds the listed value: dependencies may have access through retained addresses or other aliases. In particular, the helper receives the common slot’s address, and subsequent extraction or comparison calls are not established to preserve that storage.

F-474b7e2941e6 is not established to overwrite the selected slot. It may read the incoming contents, partially write them, fully replace them, or return without writing.

After it returns, the function reads the selected slot and copies its four-byte contents to result offset 0. Status is 1 regardless of whether the dependency wrote the slot. If an uninitialized slot remains unwritten, no established four-byte result value exists; zero must not be substituted as an assumed default.

### Result publication

For every normally completing path with an established result value:

1. The four-byte result is written at offset 0.
2. A status byte is prepared in the low-address byte of the immediate-delegation slot.
3. That byte is written at result offset 4.

On immediate delegation, the four-byte contents of that slot are copied before its low-address byte is changed to 1. On other paths, the same byte is set to 0 or 1 according to the selected outcome.

This ordering can matter to a dependency retaining the slot address. It does not establish byte order for interpreting the slot numerically.

## Side effects

The body directly writes caller-visible result storage only at offsets 0–3 and offset 4, in that order. It does not directly update container fields or node links. Additional explicit writes target local storage.

Publication is not a single atomic operation. No synchronization is supplied.

Dependencies may mutate shared state, release referenced objects, retain passed addresses, or fail to return. Such behavior is neither established nor excluded by their opaque call sites. Retaining a local address does not grant it a valid lifetime beyond this invocation.

The function contains no explicit allocation or release operation. No ownership transfer, lifetime guarantee, or release obligation is established for its four-byte result.

There is no explicit error code, rollback, malformed-structure diagnostic, or delegated-success check. Invalid accesses, nontermination, dependency failure, and unwritten uninitialized output storage have no defined recovery in the supplied evidence.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless stated otherwise, they assume stable readable links, normal dependency returns, and no unmentioned indirect writes.

1. **Search direction and clearing order.** Before each search comparison, both delegated slots contain newly written four-byte zeros. A zero comparison selects offset 12; every nonzero result selects offset 8.

2. **Nonempty direct delegation without an output write.** After at least one visited node, a nonzero control byte selects the common slot. If F-474b7e2941e6 leaves it untouched, the four-byte result is zero and status is 1. This does not demonstrate insertion failure or success.

3. **Empty direct delegation without an output write.** With a null initial traversal link and nonzero control byte, common delegation receives uninitialized storage. If it returns without writing, status publication still selects 1, but no established four-byte result value exists.

4. **Boundary-selected immediate delegation.** With a nonempty search and nonzero helper result, immediate delegation receives its zeroed slot, absent indirect mutation. Even if the helper changes the candidate or boundary slot, the delegated fourth argument remains the retained search object.

5. **Empty boundary-selected immediate delegation.** An empty traversal and zero control byte still enter boundary processing. Loading the boundary initializes the common slot, not the immediate slot. If the helper returns nonzero, immediate delegation receives an uninitialized slot.

6. **Boundary state surviving into common delegation.** Suppose boundary processing loads a value, the helper replaces that slot with another four-byte value and returns zero, adjustment completes, and the final comparison is nonzero. If later dependencies leave the slot untouched, common delegation receives the replacement value. If delegation also leaves it untouched, that value is published with status 1.

7. **Candidate reporting.** With zero control byte and zero final search outcome, the retained node is checked without calling the boundary helper. A zero final comparison publishes that candidate with status 0 and never calls F-474b7e2941e6.

8. **Adjustment and insertion-position separation.** If adjustment selects a different candidate and final comparison is nonzero, delegation still receives the original retained search object as its fourth argument.

9. **Output padding and publication.** With nonoverlapping result storage and no dependency writes to it, only bytes 0–4 are changed. The four-byte value is written before the status byte; bytes beyond offset 4 are not initialized.
