### Ordered writes

   Destination: the third argument interpreted as an address base, plus `0x1A`.  
   Value: the first implicit machine-state value shifted right by twenty-two bits.

   The result is between `0` and `0x3FF`, so conversion to 16 bits loses no additional information.

2. **Second 16-bit write.**  
   Destination: X shifted right by twenty bits, plus `0x12`.  
   Value: H.

   This destination ranges from `0x12` through `0x1011`. H fits in 16 bits.

3. **First 32-bit record write.**  
   Destination: B.  
   Value: H.

4. **Second 32-bit record write.**  
   Destination: B plus `4`.  
   Value: the implicit stack-associated value.

5. **Third 32-bit record write.**  
   Destination: B plus `8`.  
   Value: the second implicit machine-state value.

6. **Final 16-bit write.**  
   Destination: A plus `10`, where `10` is decimal, equivalent to `0xA`.  
   Value: A shifted left by twelve bits.

   The destination ranges from `0xA` through `0xE`. Possible stored values are `0x0000`, `0x1000`, `0x2000`, `0x3000`, and `0x4000`.

The three 32-bit writes form a twelve-byte region with fields at offsets `0`, `4`, and `8`. There is no evidence that the region is allocated, exclusively owned, or suitable for ordinary RAM access.

The ordering matters when destinations overlap. In particular, when K is below sixteen, B is zero and A is zero. The final 16-bit write at address `0xA` then overwrites two bytes within the third 32-bit field at addresses `0x8` through `0xB`. Which portion of that field’s numeric value changes depends on target byte order.

The first write can also overlap later destinations if the third argument selects such an address. No non-aliasing precondition is shown.
