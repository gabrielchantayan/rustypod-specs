### Non-null dispatch

If the candidate address is non-null, the wrapper reads the initial integer-sized field at that address. It uses the resulting value as the base for locating a target slot 260 bytes later.

The wrapper then reads the callable address from that slot and transfers control to it. These operations have a data-dependent order:

1. The candidate address must be obtained before its null test.
2. A non-null candidate is required before the initial field is read.
3. That field’s value determines the address of the target slot.
4. The target slot supplies the address used for the indirect invocation.
5. If the target returns normally, its result becomes the wrapper’s result.

This is an ordering description of the visible access chain, not a claim about synchronization, atomicity, or the internals of either callee.

There is no visible second acquisition of the candidate address, repeated read of its initial field, or repeated selection of the target. There is also no visible retry or alternative dispatch path.
