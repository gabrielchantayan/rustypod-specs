## Behavior

### Arithmetic and access model

Addresses and ordinary arithmetic have 32-bit representations. Addition, subtraction, multiplication, and left shifts retain the low 32 bits. Signed comparisons interpret bit 31 as the sign bit. Arithmetic right shifts propagate that bit; logical right shifts insert zeros.

Halfword accesses are 16 bits; word accesses are 32 bits. Narrow stores retain only the destination width. Paired dependency results have lower and upper 32-bit components; this does not establish a particular source-level return convention.

Read and write order matters, including when addresses alias. Fixed addresses must be distinguished from values read at fixed addresses.

### Common setup

When the early branch is not selected, a word is read through the inherited word-access address. That word is added to the inherited address plus 8, and a signed byte is read at the resulting address.

The sign-extended byte becomes the **byte-derived base**, between −128 and 127.

F-I03 receives four explicit arguments, in order:

1. A fixed address.
2. A word loaded from the same shared argument global used by F-I02.
3. The byte-derived base.
4. The fourth-argument address plus 44.

This global read occurs after F-I01 and the byte read. It is a value load, unlike the first argument, which is a fixed address. The two branch-specific global loads do not imply that F-I01 preserves the global.

Four ordered word writes create a record at eight times the sum of 65 and the inherited word-address top nibble. Its address is therefore between 520 and 640, in steps of eight. The fields contain, in order:

- The inherited halfword-access address.
- The record’s own address.
- The inherited word-access address plus 8.

F-I04 receives the byte-derived base arithmetic-shifted right by 16, hence either −1 or zero.

If bit 26 of F-I04’s upper result is set, execution reaches the final invalid-instruction boundary. Otherwise, that upper component arithmetic-shifted right by 27 initially supplies the **displacement**. If F-I04’s lower component is nonzero, the displacement is instead replaced by the low byte of a halfword read at inherited halfword-address offset 12.

The displacement is consequently either −16 through 15 or zero through 255. Its addition to the byte-derived base cannot overflow signed 32-bit arithmetic. Unsigned carry remains possible.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Post-call global value:** If F-I01 changes the shared argument global from one word to another, the selected F-I02 or F-I03 argument uses the later load. An entry snapshot is not equivalent.

2. **F-I03 argument positions:** On common setup, the fixed address is first, the loaded global word second, the signed-byte-derived value third, and fourth-argument address plus 44 fourth. Substituting the global’s address for its loaded word is incorrect.

3. **Independent pointer reads:** If the output-path global-pointer reads yield addresses P and Q, the output pointer field contains P while the byte comes from Q plus 3. Using P for both requires an additional stability assumption.

4. **Carry without signed overflow:** Base −2 and replacement displacement 3 produce sum 1 with unsigned carry and clear signed overflow. Carry-selected preparation follows if preceding conditions permit it.

5. **Negative non-carry result:** Base −2 and displacement 1 produce −1 without unsigned carry or signed overflow. Execution reaches displacement-relative reads, not the displayed return.

6. **Pair versus working address:** With carried scalar 1 and F-I09 lower result 16, active base is 8 and working address is 24. The mandatory halfword store still targets 16 plus 40.

7. **Overflow replacement:** Loop sign decisions use overflow from current address minus 100, not the earlier necessarily clear addition overflow.

8. **Different terminal shifts:** For shift value `0x80000000`, the arithmetic shift gives −4096 and the initial read address is −4028 modulo 32 bits. The logical shift gives 4096; its negation supplies −4096 for the later word store.

9. **Output overlap:** The five output words precede the byte write at output offset 1. Acceptance preserves that partial overwrite without assuming byte order.
