# F-56683437372c

## Purpose

F-56683437372c interleaves indirect calls with computed-address memory writes, transitions from four-byte stores to byte-selected stores, and enters an unconditional loop. The supplied static representation establishes no application-level purpose.

The contract describes observable call ordering, argument relationships, arithmetic, memory accesses, and continuation behavior. It does not identify an encoder, allocator, device interface, object layout, or resource-management protocol.

No normal return appears on the represented path. Indefinite execution is conditional on reaching the loop and on all subsequent calls and memory accesses completing normally. Warnings about invalid instruction data and removed unreachable regions limit confidence in the completeness and accuracy of that path.

### Widths and arithmetic

Wide stores write 32 bits; narrow stores write eight bits. Lookup reads obtain unsigned eight-bit values, numerically 0–255. Byte stores retain only the low eight bits of their payload.

Right shifts of unsigned quantities are logical. Some multiplications and left shifts involve signed 32-bit values, including the transformations of the final result within each loop iteration. Exact signed-overflow and signed-left-shift semantics are not established.

Where examples use wrapping arithmetic, they explicitly assume 32-bit reduction modulo \(2^{32}\). That interpretation is not a claim that overflowing signed operations have portable language semantics.

Pointer width, integer-to-address conversion, endianness, alignment requirements, and fault behavior remain unknown. A four-byte store establishes payload width, not byte order.

## Behavior

### Entry and initial calls

The first explicit memory operation writes the entry payload to the entry address plus 20 bytes. It occurs before any displayed dependency call and has no preceding validity check.

The first indirect call receives the first explicit argument. Four calls with no displayed arguments follow; the last produces a result. That result determines the second wide store: the destination is sixteen times the result plus 20, and the payload is four times the result.

The next call receives that fourfold payload and eight times the unsigned entry quantity.

“No displayed arguments” describes the available representation only. It does not establish a zero-argument calling convention or the insignificance of other machine state.

### Lookup-directed byte stores

The fourfold payload retained from store 10 is masked with `0x7fffffff`, then logically shifted right by seven bits. This establishes the first lookup base.

A **lookup-directed store** consists of an unsigned byte read at a specified lookup base plus one, followed by a byte write to the address equal to the value read plus 17.

Thus, the selected destination is numerically between 17 and 272 inclusive, assuming ordinary address arithmetic. The lookup does not load a full-width pointer.

After store 13 and its following argument-bearing call, four calls obtain a fresh result. The routine:

- Performs a lookup-directed store using the low byte of that result shifted left by two bits.
- Calls a dependency with the full shifted value repeated as all three displayed arguments.

A result from the next call is passed onward. Four further calls obtain another result. Before forwarding that newer result shifted left by two bits, the routine performs another lookup-directed store. This store’s payload comes from the earlier result used for the first byte store: mask it with `0x3fffffff`, logically shift right by twenty bits, then retain the low eight bits.

The masked extraction can produce a ten-bit intermediate; the actual write remains eight bits.

Both stores independently read the lookup byte. Neither the selected destination nor the lookup byte is cached across them.

### Direct byte store and clearing phase

After the preceding forwarding call, four calls obtain a fresh result. The routine shifts this unsigned result left by two bits and writes its low byte directly to:

\[
(\text{unsigned entry quantity} \mathbin{\text{logical right shift}} 23) + 28.
\]

For a 32-bit entry quantity, that numerical address is between 28 and 539 inclusive, subject to the address-conversion caveat.

Immediately afterward, the routine performs a lookup-directed zero store using the first lookup base. The direct byte write precedes the lookup read, with no displayed dependency call between them. If the direct destination aliases the lookup source, the newly written byte selects the zero-store destination.

The next call receives the entry quantity shifted right by twenty-three bits. After one additional call, another receives the recent result masked with `0x3fffffff` and logically shifted right by six bits.

Four calls then obtain a fresh result. Another lookup-directed zero store occurs using the first lookup base, followed by a call receiving that fresh result shifted left by two bits.

Four further calls obtain a new unsigned result. Masking it with `0x3fffffff` and shifting logically right by twenty-five bits produces the initial loop quantity, in the range 0–31.

The lookup source now changes. The later lookup base is 1,024 times the retained fourfold value from the direct-byte-store phase. The routine reads a byte at this later base plus one and writes zero at the byte’s value plus 17.

A call receives twice the initial loop quantity. The following call produces the initial first argument for the loop.

### Unconditional loop

The loop has no displayed termination test, break, or return.

Each iteration contains the following observable sequence:

1. A call receives the carried first argument and the current unsigned loop quantity logically shifted right by eight bits.
2. Four further calls occur; the last produces a fresh result.
3. A byte is read at the later lookup base plus one, and zero is written at the byte-selected address plus 17.
4. A call receives the fresh result shifted left by two bits.
5. Four further calls occur; the last produces the final result of that iteration.
6. Two distinct transformations of that final result establish the next iteration’s arguments.

For the **first iteration**, the first displayed argument is the unscaled result of the dependency immediately preceding the loop. The initial loop quantity is 0–31, so the second displayed argument is zero.

For **subsequent iterations**:

- The next carried first argument is the preceding iteration’s final result shifted left by **two** bits.
- The next loop quantity is that same final result shifted left by **twenty-six** bits and held as an unsigned 32-bit quantity.
- The next second displayed argument is this loop quantity logically shifted right by eight bits.

These are separate transformations. The first argument is not carried unchanged, and it is not derived from the twenty-six-bit-shifted quantity.

Both left shifts originate from a displayed signed result; the signed-shift caveat applies. Under 32-bit wrapping semantics, a final result of 1 yields next-iteration arguments 4 and `0x00040000`. The second argument generally equals the preceding final result’s low six bits shifted left by eighteen bits.

Every iteration re-reads the lookup byte. Dependencies and earlier writes may redirect later zero stores.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Initial write precedes calls.** If entry memory is valid and the first dependency observes it, the entry payload must already be stored at the entry address plus 20.

2. **Third-argument extraction.** A third explicit argument of `0xffffffff` contributes `0x0003ffff` to the later fourth argument. A value of `0x00003fff` contributes zero.

3. **Entry-quantity extraction.** For an unsigned entry quantity of `0x12345678`, its right shifts by eight, sixteen, and twenty-three bits are `0x00123456`, `0x00001234`, and `0x00000024`. The direct byte-store address is therefore 64.

4. **Byte-selected destination.** Lookup bytes 0, 200, and 255 select addresses 17, 217, and 272 respectively.

5. **Fresh lookup required.** If an intervening dependency changes a lookup byte from 3 to 9, the corresponding stores target addresses 20 and 26. Reusing the earlier destination violates the represented access sequence.

6. **Byte payload narrowing.** A byte-phase unsigned result of `0x00000041`, shifted left by two, produces `0x00000104`. The byte written is `0x04`.

7. **Extraction narrowing.** An earlier byte-phase result of `0x3ff00000`, masked and shifted right by twenty, produces `0x000003ff`. Only `0xff` is written.

8. **Direct-write aliasing.** If the direct destination equals the first lookup source, and the direct write stores 4, the immediately following zero store reads 4 and targets address 21. It must not use the lookup byte’s overwritten value.

9. **Initial loop arguments.** If the immediately preceding dependency returns 7, the first loop call receives 7 as its first displayed argument, not 28. Its second argument is zero for every permitted initial loop quantity.

10. **Later loop arguments.** Under 32-bit wrapping shifts, an iteration’s final result of 1 produces next-iteration arguments 4 and `0x00040000`. A final result of 64 produces 256 and zero. Both arguments depend on the final result, through different shifts.

11. **No ordinary completion.** If every call returns normally and every access succeeds indefinitely, the represented path never reaches a normal return.
