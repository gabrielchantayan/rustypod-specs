# F-a3053ac6eb75

## Purpose

F-a3053ac6eb75 conditionally invokes an indirect callback using an object obtained from F-17be7b6b79ad.

The established behavior has two independently sourced inputs to that decision:

- A callback-table address captured from a nested structure before calling F-17be7b6b79ad.
- A 32-bit result obtained from F-17be7b6b79ad using a value from another nested structure and a fixed selector.

The callback is invoked only when the dependency’s lower 32-bit result, the previously captured table address, and the table’s first 32-bit entry are all nonzero. Its sole explicit argument is the dependency’s lower 32-bit result.

The apparent intent is to locate a service and apply a previously configured operation to it. That interpretation is inferred rather than required: neither the service’s semantic type nor the callback’s purpose is established by the supplied evidence.

### Output

The function has no explicit return value.

- Completion without invoking the callback; or

The function does not visibly validate these conditions.

## Behavior

### Initial callback-table capture

Before invoking F-17be7b6b79ad, the function follows the first pointer chain:

1. It reads the root-object address from the explicit input storage.
2. It reads the nested-structure address at root offset `0x28c`.
3. It reads the callback-table address at nested offset `0x7d4`.

This captures the table’s address, not its first entry. The callback target is not read at this stage.

The source contains no early return when the captured table address is zero. That case still proceeds through preparation and invocation of F-17be7b6b79ad.

### Dependency argument acquisition

The function separately reads the root-object address from the input storage, then follows the field at offset `0x60` and reads the 32-bit word at offset `0x04` in that structure.

That word becomes the first explicit argument to F-17be7b6b79ad. The second argument is a fixed selector address.

The selector’s symbolic label suggests the name “pshinter.” The supplied evidence does not independently establish its complete byte sequence, terminator, encoding, or the dependency’s interpretation of it. The established behavior is the passing of the fixed selector address.

The callback-table capture is complete before this dependency invocation. The source does not establish the machine-level order of preparing the dependency’s two arguments beyond the preceding expression having completed.

### Dependency result and callback decision

The supplied representation treats the dependency result as a 64-bit quantity and extracts:

- The lower 32 bits as the candidate callback argument.
- The upper 32 bits as a provisional code address.

Only the lower 32 bits determine whether the dependency result permits callback dispatch. This is an equality-to-zero check, not a positivity check or an explicit validity check.

If the lower 32 bits are zero, the function returns without reading the captured table’s first entry and without invoking a callback.

If the captured table address is zero, the function likewise returns without invoking a callback, even when the lower result is nonzero.

When both are nonzero, the function reads the first 32-bit word at the previously captured table address. That word replaces the provisional code address.

Consequently, the upper half of the dependency result never supplies an invoked callback on any visible path:

- Paths that retain it return without invoking it.
- The only path eligible for invocation replaces it with the table’s first entry.

A zero first entry causes return without callback invocation. A nonzero first entry is invoked with the dependency’s lower 32 bits as the sole explicit argument.

### Timing and mutation sensitivity

The table address and its first entry are observed at different times.

The address is captured before F-17be7b6b79ad runs. The entry is read afterward, only if dispatch remains eligible. Therefore:

- Changing the original field that held the table address during the dependency call does not redirect this invocation to a different table.
- Changing the first entry of the already captured table during the dependency call can change the callback selected afterward.
- Invalidating the captured table during the dependency call can make the subsequent entry read invalid.

These statements follow from the visible read order. They do not assume that F-17be7b6b79ad actually performs any such mutation.

Once the dependency returns, this function does not visibly reread the input storage or either root-object chain.
