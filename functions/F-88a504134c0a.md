# F-88a504134c0a

## Purpose

F-88a504134c0a stores the low eight bits of a supplied 32-bit unsigned value in a caller-provided object, then conditionally invokes F-231941f10f3a using a value held elsewhere in that object.

The operation is not transactional. Its first action is a byte write, including when it subsequently returns status 6. A dependency failure likewise does not cause an explicit rollback.

**Established behavior:** With ordinary, stable memory, a zero byte at offset 0x90 causes status 6. Otherwise, inputs from 0 through 255 return status 0 without invoking the dependency. Inputs above 255 enter a secondary path, where a nonzero byte at offset 0x98 enables the dependency call.

**Inferred intent:** The byte comparisons and secondary writes resemble a change-detection and notification mechanism involving three adjacent bytes. That interpretation does not establish the actual contract: the first byte is overwritten before comparison, while the other two bytes are compared with themselves. No intended field names or meanings are established.

## Behavior

### Initial mutation and early return

The function first writes the low eight bits of the unsigned input to offset 0x99. Any upper 24 bits are discarded for this store.

It then reads the byte at offset 0x90. If that byte is zero, the function returns 6 immediately. The initial write remains performed; the early gate does not protect the object from mutation.

On this early-return path, the visible body does not access offsets 0x94, 0x98, 0x9A, or 0x9B and does not call F-231941f10f3a.

### Comparison stage

If the early gate is nonzero, the function reads offset 0x99 as an unsigned byte and extends that value to 32 bits. It compares the extended byte with the complete 32-bit input, not merely with the input’s low byte.

This distinction is decisive:

- For an input at most 255, a stable read of the just-written byte equals the input.
- For an input above 255, no unsigned byte value can equal the complete input.

When this first comparison succeeds, the function reads offset 0x9A as an unsigned byte. It then compares the currently selected byte-derived value against another unsigned-byte read at offset 0x9A.

When the first comparison fails, that later comparison still evaluates against offset 0x9A, but its left-hand value remains the unsigned byte previously read from offset 0x99. Its result cannot make the overall comparison stage succeed: success also requires the first comparison to have succeeded.

If both preceding comparisons succeed, the function compares two byte reads from offset 0x9B. Otherwise, this final comparison is skipped.

Under ordinary, unchanged memory, the comparisons involving offsets 0x9A and 0x9B succeed because each compares the same location with itself. They must not be interpreted as checks against separately supplied target values.

The supplied expressions do not establish which operand of a same-location comparison is evaluated first. They also do not establish that an optimizing implementation must issue distinct physical reads for every displayed access. Exact hardware read counts, volatile semantics, and synchronization guarantees are unknown.

### Secondary mutation path

If the combined comparison stage fails, the function performs these source-level assignments in order:

1. Writes the low eight bits of the original input to offset 0x99 again.
2. Reads offset 0x9A and writes that byte back to offset 0x9A.
3. Reads offset 0x9B and writes that byte back to offset 0x9B.

The last two assignments do not intentionally change stable ordinary memory. They are nevertheless part of the supplied source-level access pattern; they are not evidence that these bytes are immutable, atomic, or safe for memory-mapped devices.

After these assignments, the function reads offset 0x98:

- If zero, it skips the dependency and returns 0.
- If nonzero, it reads the 32-bit field at offset 0x94 and passes that value to F-231941f10f3a.

A zero dependency result leads to status 0. A nonzero result leads to status 7.

If the comparison stage succeeds, the function skips the entire secondary mutation path, including the read at offset 0x98 and the dependency call, and returns 0.

4. **The 256 boundary enters the secondary path.**  
   With offset 0x90 nonzero and input 256, offset 0x99 receives zero. The widened byte cannot equal 256. The secondary assignments occur. If offset 0x98 is zero, the function returns 0 without reading the dependency argument.

   With offset 0x90 and offset 0x98 both nonzero and input 0xFFFFFFFF, offset 0x99 receives 0xFF. The dependency receives the 32-bit field at offset 0x94. If it returns any nonzero value, the function returns 7, not that value.

6. **Successful dependency completion does not undo writes.**
