## Behavior

### Entry initialization

Entry initializes the output slots, result slot, and numerous working slots to zero or null, and saves the three arguments.

A seed is calculated from the address of an automatic four-byte working slot multiplied by a global coefficient. A separate global read supplies the initial dispatch state. Generated data can therefore depend on automatic-storage placement and global values, not only on the public arguments.

Initialization does not clear the 16-byte workspace.

### Dispatch snapshots and global-read sequencing

The following labels describe recurring global-word roles, not known values:

- **Helper word:** used in dispatch-adjacent arithmetic and transfer-index updates.
- **Scale word:** used in arithmetic and as a signed-shift operand.
- **Coefficient word:** used in the seed and many scalar products.
- **Dispatch-offset word:** added to the current state for range checking and operation selection.

Each dispatch-condition evaluation has an established ordered prefix:

1. Snapshot the second intermediate pointer.
2. Snapshot the first intermediate pointer.
3. Snapshot the first count-like slot.
4. Read the helper word.
5. Read the scale word.
6. Read the coefficient word.
7. Read the dispatch-offset word and evaluate whether the unsigned dispatch index exceeds 40.

The snapshots are refreshed on every evaluation, including evaluations that fail the range check.

An out-of-range evaluation resets the transfer index to zero, reads a replacement state from a global word, and repeats the dispatch-condition evaluation. It does not directly return or call a dependency. A separate numbered operation performs the same reset-and-state-replacement behavior.

After an in-range check, the function reads the scale word again and performs a signed right shift by 27 bits. It then reads the dispatch-offset word again to select an operation.

Consequently:

- The three prefix global reads occur even when the selected operation is the return operation.
- The range-check displacement and operation-selection displacement are separate reads.
- The scale snapshot taken before the range check is distinct from the later signed-shift operand.
- Every out-of-range repetition repeats the snapshots and global reads.
- An immutable entry-time snapshot of globals would not reproduce the established read structure.

The numbered operation set spans 0 through 40. Equating the checked index with the selected index requires the dispatch-offset word to remain unchanged between those reads. Global stability is not established.

The source establishes sequencing between these explicit stages. It does not independently establish machine-level load ordering within every compound arithmetic expression.

## Acceptance examples

These are conditional static acceptance criteria, not observed executions.

1. **Return-path reads.**  
   If an in-range dispatch selects return, the pointer/count snapshots and three prefix global reads still precede the range check. The subsequent signed-shift operand read and operation-selection displacement read also occur before returning the result slot.

2. **Repeated out-of-range dispatch.**  
   If two successive range checks produce unsigned indices above 40, each repetition resets the transfer index and reads a replacement state. The next condition evaluation refreshes all three snapshots and repeats the prefix global reads. Immediate return is not implied.

3. **Count mutation during F-dc10f5d75f95.**  
   Suppose the first-count snapshot is 7. If the dependency changes that slot to 11 through a previously retained address, the subsequent working-scalar assignment receives 7, not 11. Reachability and such dependency behavior are not asserted.

4. **Pointer mutation during a one-pointer call.**  
   Suppose the applicable pre-dispatch pointer snapshot is address A. If F-5e3309c9d083 changes its corresponding automatic pointer slot to address B, the subsequent working-pointer assignment receives A. This says nothing about whether memory at A remains valid.

5. **Byte identity.**  
   At either transfer site, valid source bytes `0x00`, `0x80`, `0xA7`, and `0xFF` are stored unchanged at the selected destination offset.

6. **Same source and destination byte.**  
   If the selected read and write address are identical and valid, the byte is read and then written back unchanged. The write is still performed.

7. **Workspace-call forms.**  
   At the record-based site, the four-byte field comes from offset four and the address argument is base plus eight. At the zero-valued site, both corresponding arguments are zero and that site performs no field read.

8. **Return without result replacement.**  
   If return is reached without replacing the initialized result slot, the unsigned result is zero. No success interpretation follows.

9. **Unactivated destination.**  
   If the destination-null check occurs before argument activation, it observes null even when the saved third argument is non-null. This alone does not establish the subsequent path or safety of other accesses.
