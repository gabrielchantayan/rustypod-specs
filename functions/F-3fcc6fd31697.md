# F-3fcc6fd31697

## Purpose

F-3fcc6fd31697 transforms consecutive pairs of source rows into destination rows, then invokes an unresolved indirect dependency.

For each directly produced word, the function treats a 16-bit value as three independent unsigned fields of widths 5, 6, and 5 bits. Each output field is the downward-rounded weighted average of the corresponding current-row and next-row fields, with weights one and three respectively:

\[
\operatorname{output}(a,b)=\left\lfloor\frac{a+3b}{4}\right\rfloor.
\]

The supplied body implements that result through two successive downward-rounded averages. For nonnegative field values, the two-stage and single weighted descriptions are exactly equivalent.

For positive width and a row count of at least two, direct processing produces one fewer destination row than the supplied row count. The subsequent indirect invocation receives the advanced destination and source cursors and the width shifted left by one bit. Its behavior is unresolved; copying a remaining row is not an established part of this contract.

The packed-field interpretation is established by the arithmetic. A color format, channel order, or image-processing purpose is inferred intent, not an established interface requirement.

## Behavior

### Initial source-pointer formation

Before checking whether any rows will be processed, the function forms a second source cursor at an offset of `Width` words from the initial source pointer.

This operation does not itself read a source word. It nevertheless requires valid pointer arithmetic under the applicable execution model. A negative width moves the calculated cursor backward; a zero width leaves it at the initial source address.

Nonpositive dimensions therefore do not establish that null or otherwise invalid pointers are acceptable.

### Direct row selection

The outer loop compares its initially zero counter against the row count minus one.

Provided that subtraction is representable:

- Row counts of two or greater cause `Row count − 1` outer iterations.
- Row counts of one or less cause no outer iterations.

Within an outer iteration, word processing occurs only if width is positive. For zero or negative width, the outer loop can still iterate, but it performs no direct word reads, writes, or cursor advances.

With positive width, direct row index \(r\), starting at zero, combines source row \(r\) with source row \(r+1\) and writes destination row \(r\). Rows and words are processed in increasing order.

### Packed-word transformation

Each source word is divided into these unsigned fields:

| Field | Bit positions, least significant bit numbered zero | Value range |
|---|---|---|
| Low | 0–4 | 0–31 |
| Middle | 5–10 | 0–63 |
| High | 11–15 | 0–31 |

For each corresponding pair of fields:

1. The function forms their average, discarding any fractional half.
2. It averages that intermediate field with the next-row field, again discarding any fractional half.
3. It places the resulting field in its original bit positions.

Fields do not exchange contributions or carry into one another.

The packed arithmetic uses unsigned 32-bit intermediate calculations. A boundary mask suppresses contributions at bit positions 5 and 11 before right shifts, preventing bits from a higher field from shifting into the neighboring lower field. Its high-bit portion has no effect on the established 16-bit operand range.

The first-stage result also undergoes a mask that clears bit 16. That bit is already zero for the established input range, so this mask does not alter the first-stage value. The intermediate packed result remains within 16 bits.

The second stage combines the captured next-row word with that intermediate result. Its final mathematical value also fits within 16 bits. The destination assignment stores that result through a signed 16-bit element type. This is not signed saturation. Interpretation of patterns above `0x7FFF` depends on the target’s signed representation and conversion rules.

### Exact weighted interpretation

For nonnegative field values \(a\) from the current row and \(b\) from the next row:

\[
t=\left\lfloor\frac{a+b}{2}\right\rfloor,\qquad
r=\left\lfloor\frac{b+t}{2}\right\rfloor
 =\left\lfloor\frac{a+3b}{4}\right\rfloor.
\]

The equality holds for every valid field pair, not merely selected examples.

To see why, write \(a+b=2q+e\), where \(e\) is zero or one. The two-stage result is \(\lfloor(b+q)/2\rfloor\). The weighted expression is \(\lfloor(b+q)/2+e/4\rfloor\). The first term is an integer or a half-integer; adding zero or one quarter cannot change its floor.

Consequences include:

- Equal source fields are preserved.
- Each result lies between its two source fields.
- Reversing the rows can change the result.
- Rounding is downward, not toward the nearest integer.
- The weighted expression applies separately to the three fields, not to the complete packed word as one integer.

### Read and write ordering

For each processed word, the next-row word is captured before the current-row expression is evaluated. Both averaging stages use that captured next-row value.

The first-stage expression references the current-row word twice. The supplied representation does not establish an ordering between those references or a guaranteed number of physical loads. It does not establish volatile-access semantics.

The destination word is stored after the source values needed for that result have been evaluated. That store precedes processing of the following word. Neither a whole row nor the entire source is snapshotted.

Consequently, overlapping source and destination regions can change later inputs. An earlier destination write may overwrite a location that a subsequent iteration reads. The function provides no overlap detection or buffering to prevent this.

A reference calculation based on immutable original source rows is valid only when those source values remain unchanged until consumed.

### Cursor state after direct processing

For positive width and a row count of at least two:

- The source argument cursor advances by `Width × (Row count − 1)` words.
- The destination argument cursor advances by the same number of words.
- The source argument cursor points to the beginning of the final source row.
- The destination argument cursor points immediately beyond the directly written rows.

The separately maintained next-row cursor advances through the final source row during the last outer iteration.

If no word iterations occur, neither argument cursor advances. This includes all nonpositive widths and all row counts of one or less, subject to representable control arithmetic.

### Final target read and invocation

After all direct processing, the function reads a stored global function pointer and invokes the target obtained from that read. The target is designated **F-indirect-001** in this contract.

The target is not established as having been captured at entry. Its read occurs after all direct destination writes. If destination storage aliases the stored function-pointer object, those writes can affect the target subsequently used. The supplied body establishes no protection against that aliasing.

The invocation receives these arguments in order:

1. The current destination cursor.
2. The current source cursor.
3. The signed width shifted left by one bit.

For nonnegative widths whose doubled value is representable, the third argument equals twice the width. That is numerically consistent with a row length in bytes, but the dependency’s interpretation is unknown.

The invocation is unconditional on the path that reaches it, including when no direct words were processed. No direct transformation follows it, and no dependency return value is explicitly used.
