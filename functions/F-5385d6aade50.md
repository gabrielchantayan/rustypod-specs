# F-5385d6aade50

## Purpose

F-5385d6aade50 conditionally resolves a request against an indexed collection and delivers a 32-bit result to a separately acquired recipient.

The established behavior is a dispatch-and-search procedure. Depending on the request category, it delivers a fixed value, selects the last index under a previously obtained bound, searches for a matching item, or delivers an unresolved-result sentinel. When indexed selection occurs, the selection operation’s return value becomes the delivered result.

**Inferred intent:** the procedure may restore or apply a selection described by external state. The domain meanings of the modes, categories, items, recipient, and result values are not established.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Inputs and return

The procedure accepts:

- **Subject:** a pointer to an object whose leading field supplies the dispatch table used by the operations below.
- **Mode:** an unsigned 32-bit value controlling preparation and request processing.

Mode behavior:

| Mode | Conditional preparation | Request processing |
|---:|---|---|
| `0` | Enabled | Enabled |
| `1` | Enabled | Skipped |
| `2` through `4,294,967,295` | Skipped | Skipped |

Every normally returning path returns the 32-bit value `1`. This return does not indicate whether a recipient was found, a request matched, selection occurred, or delivery succeeded.

The procedure does not explicitly validate the subject, dispatch tables, or acquired objects. Invalid accesses and abnormal dependency exits are not translated into a documented error result.

### Local storage and value widths

For full-width comparisons, the first payload word supplies bits 0–31 and the second supplies bits 32–63. This establishes a logical 64-bit composition, not a serialization format or a general endianness guarantee.

## Behavior

### Entry and saved bound

Every invocation begins with the following ordered interactions:

1. Call F-c3a316e4c3b2 with no explicit arguments.
2. Call F-df2422ba76c2 with the 72-byte region and two zero arguments.
3. Invoke subject offset `0x160` with the subject to acquire a collection-like object.
4. Query that object through offset `0x30`, with no explicit arguments shown, and retain the returned unsigned 32-bit bound.

These interactions occur before mode filtering, including for modes greater than `1`.

The bound is saved once. Later calls do not cause it to be refreshed. Its continued suitability for subsequent item access is not checked.

### Conditional preparation

For mode `0` or `1`, the procedure acquires a collection-like object again through subject offset `0x160`, then invokes its offset `0x1C` state operation with no explicit arguments shown.

If the state is nonzero, it calls:

1. F-6a21f4f07f67.
2. F-814d4ee17e01.

No explicit argument conveys the first call’s return value to the second. Any relationship through implicit state is unknown.

Mode `1` proceeds to normal finalization after this preparation stage. Modes greater than `1` skip the stage entirely and also proceed to finalization.

The two collection acquisitions are distinct observable calls. They need not return the same object.

### Recipient acquisition and global-data read

Only mode `0` attempts to obtain a result recipient.

First, F-938c950e5046 returns a lookup-provider pointer. **After that dependency returns**, the procedure evaluates an opaque global-data operand for the provider’s offset `0xF8` lookup operation. That operation receives the provider and the value read from the global operand.

The lookup argument is not established as a constant or stable configuration value. Its value, domain type, and mutability are unknown. In particular, F-938c950e5046 must not be assumed to preserve it. The lookup uses the value evaluated after that call, rather than an established pre-call snapshot. The representation supplies it as one argument in the 32-bit environment; its declaration and independent storage contract are not provided.

Recipient acquisition then branches:

- A zero lookup result ends request processing without conversion, acquisition of a request, or result delivery.
- A nonzero lookup result is passed to F-682adfd5a561 with numeric argument `0x1700`.
- A null result from F-682adfd5a561 likewise ends request processing without request acquisition or delivery.
- A non-null result is retained as the recipient.

There is no visible provider-null check before provider dispatch. The meaning of `0x1700` is unknown.

### Request acquisition

After obtaining a recipient, the procedure establishes a pending 32-bit result of `0xFFFFFFFF`, used locally as `-1`.

It then directly stores zero into both payload words, calls F-7e4f952e879e, and passes that call’s result together with the address of the first payload word to F-8a44d1b81fa2.

The byte-sized return from F-8a44d1b81fa2 determines the category. Its actual payload-writing behavior is unknown. An unwritten payload word retains zero provided no intervening dependency changes it.

Payload contents are inspected by the search categories; fixed-result and unsupported categories do not require payload comparison.

### Category 2: full-width search

The procedure acquires another collection-like object through subject offset `0x160`, then queries its offset `0x1C` state operation with the collection explicitly supplied.

This acquisition and state query occur even when the saved bound is zero.

The state result selects one of two item sources for the entire scan:

- **Zero state:** for each examined index, collection offset `0x6C` receives the 20-byte item region, the collection, and the index.
- **Nonzero state:** for each examined index, F-6a21f4f07f67 is called afresh. F-21712eedaa5c then receives the item region, that call’s returned source value, and the index.

Indices are examined in ascending unsigned order, starting at zero and remaining strictly below the saved bound.

After each item-supplying operation, F-d3b5bb23607f receives the item region and supplies a 64-bit value. Equality requires all 64 bits to equal the composition of the two payload words.

F-c1466ea05103 receives the item region after every comparison. For a matching item, this call occurs before leaving the scan and before indexed selection. For a nonmatching item, it occurs before advancing to the next index.

The first matching index is selected; no later index is examined.

### Categories 5 and 6: value-and-predicate searches

These categories also examine ascending indices strictly below the saved bound. Each examined index causes:

- A fresh call to F-6a21f4f07f67.
- A call to F-21712eedaa5c with the item region, returned source value, and current index.
- A call to F-45ba275d4fcc with the item region to obtain a 32-bit comparison value.

The 32-bit extractor is called even when the payload’s upper word is nonzero.

A candidate can reach predicate evaluation only if:

- The upper payload word is zero.
- The extracted value equals the lower payload word’s 32-bit pattern.

The equality comparison does not introduce a signed-ordering condition. Equal 32-bit patterns match even when their high bit is set.

Only eligible candidates are passed to F-3f2e817b9ef7:

- Category `5` matches a zero predicate result.
- Category `6` matches a nonzero predicate result.

Every examined item is passed to F-c1466ea05103, including ineligible candidates and matching items. A match stops scanning after that call and before indexed selection.

### Search exhaustion and arithmetic limits

For categories `2`, `5`, and `6`, exhausting the saved bound without a match sets the pending result to `0` and suppresses indexed selection.

A zero bound performs no item-supplying, extraction, predicate, or item-finalization calls. Category `2` still performs its collection acquisition and state query.

All scan counters and bounds are unsigned 32-bit values. Even at bound `0xFFFFFFFF`, the largest examined index is `0xFFFFFFFE`. After a miss there, the counter reaches the bound and scanning ends; no wraparound iteration is required.

### Category 3: last-index selection

The candidate index is the saved bound minus one using unsigned 32-bit arithmetic.

- Bound zero yields `0xFFFFFFFF`. Selection is skipped, and the pending result remains `0xFFFFFFFF`.
- Every nonzero bound yields an index from `0` through `0xFFFFFFFE`, eligible for selection.

Thus an empty category-3 request delivers a different value from an exhausted search: `0xFFFFFFFF` rather than `0`.

### Indexed selection, delivery, and finalization

For a successful search or nonempty category-3 request, the procedure first checks that the pending result is still `-1`. If it is not, F-a817d8d58c10 is called. That dependency is statically annotated as non-returning.

The ordinary local assignments preserve `-1` on paths reaching selection, so they do not take this guard. Behavior involving external alteration of local state is not established.

Subject offset `0x12C` receives the subject and candidate index. Its 32-bit return replaces the pending result.

The recipient’s offset `0x174` operation then receives the recipient and pending result. Its return value is ignored. Delivery also occurs for fixed results, unsupported categories, empty category-3 requests, and exhausted searches whenever recipient acquisition succeeded.

All normally completing paths then call F-ccf4fcd3c34d with the 72-byte region and return `1`. No equivalent finalization guarantee is established for faults, nonlocal exits, or non-returning dependencies.

## Side effects

### Observable reads and call ordering

Established ordering includes:

- Entry dependency, then the first 72-byte-region call, then collection acquisition and bound query.
- Bound acquisition before mode filtering and any preparation.
- Provider acquisition before evaluation of the global lookup operand, and operand evaluation before the lookup invocation.
- Successful recipient conversion before direct payload initialization and request acquisition.
- Item supply before value extraction.
- Value eligibility checks before conditional predicate invocation.
- Item finalization before the next item or indexed selection.
- Indexed selection before result delivery.
- Result delivery before normal finalization of the 72-byte region.

The source does not establish additional ordering among the individual dispatch-address and argument reads used to form a single indirect call.

### Writes, lifetime, and ownership

The explicit direct stores to the described payload storage initialize its two 32-bit words. The procedure also maintains local control values such as the pending result and scan index.

The 20-byte and 72-byte regions are supplied by address to dependencies. Their modification, initialization completeness, and resulting contents are dependency-mediated and unknown. Calling a dependency with either region does not prove that every byte is initialized.

The item region is reused without a visible explicit clearing operation between iterations.

F-c1466ea05103 has a per-item finalization call pattern. F-df2422ba76c2 and F-ccf4fcd3c34d have an entry/normal-exit pairing. These patterns do not independently establish construction, destruction, allocation, ownership transfer, or release semantics.

No explicit direct field write to the subject or recipient is visible. Indirect operations and dependencies may mutate objects or global state.

No explicit release of acquired collection, provider, request-context, or recipient pointers is visible. Neither ownership nor preservation by dependencies can be inferred from that absence.

## Acceptance examples

These are conditional expectations, not executed tests. Except where stated otherwise, they assume valid dispatch targets, normally returning dependencies, and no external interference with local state.

1. **Mode `2`:** entry, the first 72-byte-region call, collection acquisition, and bound query occur. Preparation and recipient lookup do not. Normal finalization occurs; the return is `1`.

2. **Mode `1`, nonzero preparation state:** F-6a21f4f07f67 precedes F-814d4ee17e01. No request acquisition or delivery follows.

3. **Global lookup operand changed during provider acquisition:** if F-938c950e5046 changes that operand from value A to value B, with no further change before evaluation, provider lookup receives B. The contract does not require a fixed value or a pre-call snapshot.

4. **Zero provider lookup result:** F-682adfd5a561 is not called. No request is acquired or delivered. Normal finalization still occurs.

5. **Null conversion result:** request acquisition and delivery are skipped even though provider lookup returned nonzero.

6. **Category `4`:** the recipient receives `0`; no item scan or indexed selection occurs.

7. **Category `3`, bound zero:** the recipient receives `0xFFFFFFFF`; selection is skipped.

8. **Category `3`, bound three:** selection receives index `2`. If selection returns `17`, delivery receives `17`.

9. **Category `2`, first match at index two:** assuming bound exceeds two, indices zero, one, and two are inspected in order. All three items receive finalization calls. Selection receives `2`; no higher index is inspected.

10. **Category `2`, equal lower halves but unequal upper halves:** the item does not match.

11. **Category `5`, nonzero upper payload word:** each examined item still receives 32-bit extraction and finalization, but no predicate call occurs. Exhaustion delivers `0`.

12. **Category `6`, eligible value but zero predicate:** the item is finalized, and scanning continues.

13. **Unsupported category byte:** no scan or selection occurs; delivery receives `0xFFFFFFFF`.

14. **Zero bound, category `2`:** collection acquisition and its state query still occur, but no item operation occurs. Delivery receives `0`. Categories `5` and `6` likewise deliver `0` without item operations.

15. **Request dependency leaves both payload words untouched:** they remain zero absent other interference. No corresponding zero-content expectation is justified for either temporary byte region.
