## Behavior

### Interpretation and retained values

For clarity, this contract uses descriptive names for retained state:

- **Entry snapshot:** the unsigned 32-bit word read near entry.
- **Snapshot-derived base:** the entry snapshot logically shifted right by eight, then multiplied by eight.
- **First selector address:** an address derived from a retained four-times-scaled dependency result by masking with `0x7fffffff`, shifting right by seven, and adding one.
- **Loop selector address:** a later, separately derived address retained throughout the final loop.

These names identify values and roles, not inferred objects.

Unsigned right shifts are logical. Consequently:

- The later four-argument call receives the original third argument shifted right by 21.
- The entry snapshot shifted right by sixteen and then eight equals the original snapshot shifted right by 24.
- The entry snapshot shifted right by sixteen and then seven equals the original snapshot shifted right by 23.
- Masking an unsigned word with `0x3fffffff` and shifting right by 25 produces a value between 0 and 31.

The represented unsigned left shifts operate at 32-bit width. Signed multiplication, signed left shifts, and conversion of large unsigned results to signed representations require separate qualification. Portable signed-overflow behavior is not established. Algebraic simplifications that discard high bits are conditional on confirmed 32-bit machine-word execution semantics.

### Entry effects

The routine first writes the inherited 32-bit value at the address formed from four times the second argument, plus 20.

It then reads the entry snapshot from the inherited read base plus 20. The write precedes this read. If the accessed words coincide under ordinary memory semantics, the snapshot contains the value just written.

The first indirect invocation has four visible arguments, in order:

1. Four times the second argument.
2. The original second argument.
3. The original third argument.
4. The original second argument again.

Its target depends on the inherited control-address state. Subsequent indirect calls use represented target bases established within the routine. Several calls forward an opaque 32-bit result from one dependency into another.

After the initial dependency sequence, the inherited value is written again to the initial destination. Calls separate the two writes; the second is not redundant merely because the stored value is unchanged.

### Early word operations

The following stages occur in order. Each selected result belongs to its particular dependency invocation; similarly shaped calculations do not establish that results or destinations are equal.

1. **Scaled store and retained read.** After calls that include passing a result multiplied by four, a new result selects a destination at sixteen times that result, plus 20. The routine writes four times the result there. It reduces the third argument logically by seven and reads a word at four times the selected result, plus 20.

   A dependency receives the four-times-scaled value in both visible argument positions. Further calls intervene before the retained word, shifted right by eight, is written to the location from which it was read. This is snapshot-based writeback, not a new read after the calls.

2. **Separate scaled and self-base writes.** Another result selects a sixteen-times-scaled destination receiving four times that result. A dependency receives the entry snapshot shifted right by sixteen. After further calls, the routine writes the retained four-times-scaled base to that base plus 20.

   The initial destination in this stage uses sixteen-times scaling; the later destination uses four-times scaling. They must not be conflated.

3. **Repeated write to a retained destination.** A later result supplies a retained base equal to sixteen times the result. Four times the result is written at that base plus 20. The base is passed to a dependency. An intervening call sequence includes forwarding an opaque result together with the entry snapshot shifted right by sixteen.

   The original four-times-scaled value is then written again to the same retained destination. It is not replaced by a newly returned result.

4. **Snapshot-derived destination.** Another selected result supplies the usual sixteen-times-scaled destination and four-times-scaled stored value. The third argument undergoes its second seven-bit logical reduction.

   A dependency receives the four-times-scaled value followed by the snapshot-derived base. Later calls include an invocation with an opaque result and the entry snapshot shifted right by sixteen. After those calls, the retained four-times-scaled value is written at the snapshot-derived base plus 20.

5. **Four-argument call and self-base overwrite.** A further selected result causes another four-times-value store at a sixteen-times-scaled destination. A dependency then receives:

   - The snapshot-derived base.
   - The same base again.
   - The entry snapshot shifted right by sixteen.
   - The original third argument shifted right by 21.

   After intervening calls, the snapshot-derived base itself is written at that base plus 20. This overwrites the earlier direct value there if no aliasing or dependency effect has changed the interpretation of the location.

### Secondary-result and later word operations

After further calls, the routine consumes a secondary result-register value. It multiplies that value by \(2^{24}\), writes the product at an address formed from the same value multiplied by \(2^{26}\), plus 20, and passes the product to a dependency.

Both multiplications are represented as signed operations. Neither valid addressing nor portable behavior on signed overflow is established.

Subsequent stages, in order:

- Write four times another result at sixteen times that result, plus 20; pass the four-times value into a dependency sequence; then write that retained value at four times a later result, plus 20.
- Obtain and retain another four-times-scaled result, also writing it at its sixteen-times-scaled destination.

The retained scaled result from the last group supplies the first selector address. It is not replaced by the result selecting the destination of the shifted-snapshot write.

### Word overwrite immediately before byte effects

A further dependency result selects a base equal to sixteen times that result. The routine writes four times the result at that base plus 20.

The next relevant dependency invocation has three visible arguments:

2. The same base again.

### Byte-oriented effects

Each selector-based write consists of an unsigned byte read followed by a byte write at the read value plus 17. Its destination is therefore numerically between 17 and 272 inclusive. The read byte is an integer selector, not a pointer-sized field.

The first selector address remains fixed across its uses, but the byte stored there is reread for every selector-based write.

The ordered effects are:

1. Read the first selector byte and write the low byte of a newly returned unsigned result shifted left by two at the selected destination.

2. Call a dependency with three copies of that shifted value. After further calls, reread the first selector byte and write the low byte of the original unsigned result masked with `0x3fffffff` and shifted right by 20.

   This value uses the same retained result as the preceding byte-value write, not a newer result. Its intermediate value can occupy ten bits; the byte write retains only eight.

3. After more calls, obtain a newer unsigned result and shift it left by two. Write its low byte at the entry snapshot shifted right by 31, plus 28. This direct destination is either 28 or 29.

4. Immediately reread the first selector byte and write zero at the selected destination. No dependency invocation separates this zero write from the preceding direct byte write.

5. Invoke a dependency with the entry snapshot shifted right by 31. A later dependency receives the newer unsigned result masked with `0x3fffffff` and shifted right by six.

6. After further calls, reread the first selector byte and write another selected zero.

The destinations can alias. In particular, both 28 and 29 lie within the selector mechanism’s destination range. A write can also modify a selector location if computed addresses overlap, affecting later reads.

### Pre-loop state

After additional calls, another unsigned result is masked to 30 bits and logically shifted right by 25. The resulting five-bit quantity is retained.

The routine then:

- Calls a dependency with twice the five-bit quantity.
- Obtains the result supplying the first argument of the first loop invocation.

These are conditional static acceptance criteria, not executed tests. They assume reached accesses are valid, dependencies return, and arithmetic has the stated interpretation.

1. **Entry aliasing.** If the initial word destination equals the entry snapshot address, ordinary memory semantics require the snapshot to reflect the preceding inherited-value write.

2. **Snapshot writeback.** If a dependency changes the word retained for the early right-by-eight writeback, the later direct write still uses the earlier snapshot shifted right by eight.

3. **Third-argument reduction.** An original third argument of `0xffffffff` supplies `0x000007ff` as the fourth argument of the later four-argument invocation.

4. **Pre-byte overwrite.** If the selected result is 3 and the entry snapshot is `0x80000000`, the routine first writes 12 at address 68. The relevant call receives 48, 48, and 256. After the intervening calls, the routine directly writes 48 at address 68.

5. **Selector rereading.** Selector reads of 3 and then 9 select destinations 20 and 26. Caching destination 20 for both writes contradicts the represented accesses.

7. **Direct byte destination.** Entry snapshots `0x7fffffff` and `0x80000000` select direct byte destinations 28 and 29, respectively.

8. **Loop transition.** If the pre-loop result is 7, the first loop invocation receives 7 and zero at the initial represented target.
