## Acceptance examples

These are conditional static acceptance scenarios, not executed tests.

1. **Different paired-installation reads.** If a capture reads value A and the separate global reread reads value B, +0 receives B while +28 receives A plus the stage’s displacement: 236, 228, or 220 bytes. In the 228-byte stage, F-672ce4a07539 also receives A plus 228 when reached.

2. **Inactive storage with a populated head.** A zero active/root field skips its whole storage block despite a nonzero head. No drain or associated bookkeeping reset occurs.

3. **Single stable drain node.** Given one node with a null next word and no dependency mutation, the head becomes zero before the payload-associated call. The node-associated call follows.

4. **Preparation replaces the root.** If a preparation call replaces a root with another valid address, the subsequent root operation uses the reread replacement, not the pre-call tested value.

5. **Nonzero return without an output write.** If F-ebd94610a438 returns nonzero without changing an already nonzero address temporary, the caller invokes entry +4 through that retained address. It does not require a newly supplied address.

6. **Repeated unchanged temporary.** If successive nonzero returns leave the temporary unchanged, the same address is used repeatedly, provided it remains valid. No uniqueness or advancement guarantee follows.

7. **Zero temporary with nonzero return.** No callback occurs, but repetition continues. Conversely, a zero return stops repetition even if the temporary is nonzero.

8. **Repeated captured-word notification.** A nonzero predicate result plus a later manager +40 equality causes two F-a82ec4b43e2f calls with the originally captured word.

9. **Changing manager identity.** When successive manager retrievals differ, the +36 clearing write affects the additionally retrieved manager, not necessarily the one compared.

10. **Final branch gating.** An initially zero +4 field prevents the +8 read and non-returning branch. If +4 was initially nonzero but F-c719314a16bb clears it, the callback is skipped while the +8 check still occurs.
