# F-c70a8b6de265

## Purpose

F-c70a8b6de265 passes two argument copies to an adjustment dependency, initializes two globally addressed storage regions, and scans the initialized descriptor region for entries eligible for processing.

Its established direct behavior is:

- Initialize a calculated number of eight-byte descriptors, writing all ones to both 32-bit words of each descriptor.
- Initialize a calculated number of bytes in a second region, writing 255 to each byte.
- Scan the originally counted descriptors, skipping each descriptor whose first word is all ones.
- For any non-sentinel descriptor encountered, derive two indices and invoke a processing dependency while advancing an unsigned counter toward the stopping index.

If the initialized descriptor words remain unchanged except for the function’s own byte-initialization writes, every scanned descriptor remains a sentinel and no processing calls occur. This remains true when byte initialization overlaps any portion of those descriptors: writing all-one bytes over an all-one word preserves that word.

The shifts, descriptor layout, and sentinel may suggest bookkeeping for ranges or storage units. That interpretation is inferred intent, not an established semantic contract.

The adjustment dependency receives the address of the fourth-argument copy first and the address of the third-argument copy second.

The following descriptive terms identify values and storage without assigning domain meaning:

- **Descriptor address:** a global address-bearing value captured after the adjustment call.
- **Byte address:** a separate global address-bearing value read during descriptor initialization and again for each processing call.
- **Bias:** a signed 32-bit global value read during byte initialization and retained for subsequent starting-index calculations.

The supplied representation uses 32-bit address-bearing values. It does not establish a portable pointer interface, actual allocation sizes, or alignment guarantees.

There are no explicit capacity arguments, ownership handles, error outputs, or success indicators.

## Behavior

### Adjustment and initial capture

The function first prepares the two local argument copies and calls F-831eb8178d08 with their addresses.

Subsequent calculations use their post-call contents. The function performs no visible validation of either value and does not use a return value from the dependency.

After that call returns, the function captures the descriptor address and calculates a fixed descriptor count:

**Descriptor count = unsigned extent shifted right by 19 bits.**

For an unsigned 32-bit extent, this is division by 524,288 with the remainder discarded. The result ranges from 0 through 8,191.

The descriptor count and descriptor address are retained for both descriptor initialization and the final scan. Later changes to the globals or local extent do not cause those two captured values to be recomputed.

The adjustment dependency’s effects are unknown. In particular, pre-call global values cannot be assumed to survive the call.

### Descriptor initialization

The function initializes descriptors in increasing index order, starting at index zero and stopping before the captured descriptor count.

Each descriptor occupies eight consecutive bytes:

| Offset | Access width | Value written |
|---|---:|---|
| 0 | 32 bits | All-one bit pattern |
| 4 | 32 bits | All-one bit pattern |

For each descriptor, the offset-zero word is written first, then the offset-four word. Both writes complete before the next descriptor’s writes begin.

The descriptor storage written totals eight times the descriptor count, with a maximum of 65,528 bytes. A zero descriptor count produces no descriptor writes.

The byte-address global is read during every condition evaluation for this phase, before the descriptor-count comparison. This includes the terminating condition evaluation and the sole condition evaluation when the descriptor count is zero.

Consequently, on normal completion of this phase:

- The byte-address global has been read descriptor count plus one times.
- The value from the final read becomes the address used for byte initialization.
- That final address selection occurs after all descriptor-initialization writes.

If descriptor writes overlap the storage holding the byte-address global, they can affect the address selected for the next phase. No disjointness check prevents this.

### Byte initialization

The function next initializes consecutive bytes beginning at the byte address selected by the preceding phase.

At each condition evaluation, it:

- Reads the bias global, retaining the value obtained.
- Checks the current unsigned extent shifted right by 20 bits against the current byte offset.

When the condition permits another iteration, the function writes 255 to the selected byte and advances the offset by one.

If the extent remains unchanged throughout this phase, the byte count is:

**Byte count = unsigned extent shifted right by 20 bits.**

This is division by 1,048,576 with the remainder discarded, yielding a count from 0 through 4,095.

Unlike the descriptor count, this bound is evaluated from the local extent at each condition check. The supplied body does not prove that the adjustment dependency cannot retain or otherwise expose the address of that local storage. Whether any later modification is possible or valid remains unknown.

Byte writes proceed in increasing offset order. A zero byte count produces no byte writes, but the bias global is still read during the terminating condition evaluation.

The final bias value read in this phase is retained for the descriptor scan. The scan does not reread the bias global for each entry or processing call.

The byte address used for initialization is fixed for this phase. Changes to the byte-address global during byte initialization do not redirect subsequent writes within this phase.

### Descriptor scan

The function scans the captured number of descriptors in increasing index order, using the captured descriptor address.

For each descriptor, it first reads the 32-bit word at offset zero and interprets that word as signed.

If the word is −1, meaning the all-one bit pattern:

- The descriptor is skipped.
- Its second word is not read.
- No processing call is made for it.

Otherwise, the function reads the second 32-bit word and calculates the stopping index before calculating the starting index.

The calculations are:

- **Stopping index:** subtract the origin from the signed second descriptor word; convert the subtraction result to unsigned 32-bit form; shift right by 17 bits.
- **Starting index:** subtract the origin from the signed first descriptor word; add the retained bias; convert the resulting value to unsigned 32-bit form; shift right by 17 bits.

The bias affects only the starting index.

Both shifts are unsigned right shifts. Once valid 32-bit values have reached those shifts, each initial index lies between 0 and 32,767 inclusive. The shifts discard low bits; they do not round upward.

The signed subtraction and addition occur before the unsigned conversions. Overflow-dependent cases require additional arithmetic evidence; the unsigned conversion does not by itself establish that preceding signed overflow is defined.

### Processing an index interval

For a non-sentinel descriptor, the function compares the current unsigned 32-bit index with the stopping index.

If they are equal, the descriptor produces no processing calls.

Otherwise, it calls F-c2b0a9ee837a with:

1. A fresh read of the byte-address global.
2. The current unsigned 32-bit index.

After each returning call, the function increments the index by one and repeats the equality comparison.

The byte-address argument can differ from the address used for byte initialization. It can also differ between successive processing calls, including when the processing dependency changes that global.

The loop terminates on equality, not on an ordering comparison:

- Start below stop produces the ordinary half-open interval.
- Start equal to stop produces no calls.
- Start above stop advances through the unsigned maximum, wraps to zero, and continues toward stop.

Provided every call returns and execution remains valid, the number of processing calls is the stopping index minus the starting index modulo 2³².

The current descriptor’s two words and stopping index are not reread after each processing call. The starting calculation is also not repeated. Later descriptors are read only when reached, so dependency effects can affect their subsequent observations.

### Completion

After scanning the captured descriptor count, the function returns without an explicit result.

There is no returned count, success flag, or error code.

## Side effects

- Reading the descriptor-address global after that dependency returns.
- Repeatedly reading the byte-address and bias globals at the phase-specific points described above.
- Writing all-one words to descriptors.
- Writing all-one bytes to the byte region.
- Reading descriptor words during the scan.
- Conditionally calling F-c2b0a9ee837a.

There is no explicit allocation, release, ownership transfer, locking, bounds validation, or error recovery in the supplied body. This does not establish that either dependency lacks those effects.

### Overlap and sentinel preservation

Byte initialization cannot, by itself, change an initialized sentinel word into a non-sentinel word. Every byte of that word is already all ones, and every overlapping byte write also supplies all ones.

This applies to partial and complete overlap, to either descriptor word, and to overlap crossing descriptor boundaries. Therefore, non-overlap between the two initialized regions is not required for sentinel preservation.

Different consequences are possible when writes overlap other objects:

- Overwriting an address-bearing global can change a later address selection or processing-call argument.
- Overwriting the bias global can change its subsequently captured value.
- Overwriting other non-all-one data can change that data.

These effects are distinct from changing an unchanged sentinel descriptor. Independent mutation, dependency effects, or behavior outside valid memory execution could alter descriptor observations, but the all-one byte writes alone do not.

For valid execution, all selected accesses must address accessible storage with suitable permissions, alignment, and lifetime. Address formation must also be valid for the execution environment. No such requirements are checked by this function.

Passing local addresses does not establish ownership transfer or permission to use them after the function returns. The dependency’s actual retention behavior is unknown.

## Acceptance examples

These are conditional consequences of static evidence, not runtime observations. Unless an example states otherwise, assume valid memory accesses and arithmetic, stable local values after adjustment, no independent mutation, and returning dependencies.

### Extent below the descriptor threshold

For an extent of 524,287:

- Descriptor count is zero.
- Byte count is zero.
- Neither region is written.
- No descriptor is scanned.
- No processing call occurs.
- The adjustment call and the terminating-condition reads of the byte-address and bias globals still occur.

### One descriptor and no bytes

For an extent of 524,288:

- One descriptor is initialized.
- Its first word is written before its second word.
- No byte-region writes occur.
- The scan reads the first word as a sentinel and skips the descriptor.
- The second descriptor word is not read during scanning.

### Two descriptors and one byte

For an extent of 1,048,576:

- Two descriptors are initialized, totaling 16 bytes of descriptor writes.
- One byte-region write occurs.
- Both descriptors are skipped if no independent modification changes their first words.

This result also holds if that byte-region write overlaps a byte of either initialized first word: the overlapping write preserves the sentinel.

### Partial overlap preserves the sentinel

Suppose the selected byte region covers only the middle two bytes of an initialized descriptor’s first word.

Those bytes receive all ones, matching their existing contents. The first word remains all ones, so the scan skips the descriptor and does not read its second word.

Overlap alone is not a condition that activates processing.

### Maximum extent

For an extent of 4,294,967,295:

- Descriptor count is 8,191.
- Descriptor initialization writes 65,528 bytes.
- With a stable extent, byte initialization writes 4,095 bytes.
- Discarded remainders do not produce an additional descriptor or byte.

### Equal and forward indices

If a descriptor is non-sentinel when scanned and valid arithmetic produces starting and stopping indices both equal to 7, no processing call occurs.

If the indices are instead 3 and 6, the calls receive indices 3, 4, and 5, in that order.

If the first processing call changes the byte-address global, the next call uses the newly read value. The current descriptor’s stopping index remains fixed.

These examples require a non-sentinel descriptor at scan time. The function’s own all-one initialization writes, including overlapping byte writes, do not create that condition.

### Reversed indices

If a non-sentinel descriptor produces start 6 and stop 3, the function does not reject the interval.

Under unsigned 32-bit counter semantics, it makes 4,294,967,293 calls before reaching 3, provided execution remains valid and every call returns. The sequence passes through 4,294,967,295 and then zero.

## Uncertainties

The following are documented_only:

- Intended storage capacities, alignment, lifetimes, and overlap relationships.
- Whether independent or concurrent modification is possible or supported.
- Dependency effects on globals, memory ownership, pointer retention, failure signaling, and control flow.

Signed arithmetic precedes the conversions used in range calculations. The supplied representation establishes operand widths and conversion placement, but does not establish behavior for every signed-overflow case. Acceptance examples involving such overflow require additional evidence.

Unsigned counter wraparound is separate: the processing counter is explicitly unsigned 32-bit, and its loop uses inequality against a fixed stopping index.

The processing path may serve a context involving independent mutation or effects not supplied here. That possibility is inferred, not established. Descriptor/byte-region overlap alone does not explain activation of that path.
