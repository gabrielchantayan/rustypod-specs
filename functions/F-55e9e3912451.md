# F-55e9e3912451

## Purpose

F-55e9e3912451 dispatches a tagged record against a receiver object. It recognizes several record tags, compares a prepared pair of values and two supplied scalar values against receiver state, invokes direct dependencies or receiver-selected callbacks, and returns a 32-bit handled indicator.

**Established behavior:** tags 3 and 4 always return 1 if their dependencies return normally. Other tags generally return 0, even when they trigger callbacks or other side effects. Tag 19 can return 1 when one of two matching rules succeeds.

**Inferred intent:** the receiver appears to maintain a cached four-value selection, while the input record appears to represent an event or notification. These interpretations are descriptive only. Neither the domain meanings of the tags nor the meanings of the receiver fields are established.

## Interface

### Arguments and result

The function accepts four arguments:

| Argument | Observed use |
|---|---|
| Receiver | Address of an object accessed through 32-bit fields and a callback-table pointer. |
| Record | Address of a record containing a 32-bit tag at byte offset 4 and, on tag-19 paths, payload words at offsets 8 and 12. |
| Comparison value A | 32-bit value compared with the receiver word at offset 752. |
| Comparison value B | 32-bit value compared with the receiver word at offset 756. |

The result is a 32-bit value, explicitly either 0 or 1 on every visible normal return path. A result of 0 does **not** establish that the function had no side effects.

The supplied representation uses 32-bit words and pointer-valued fields. Pointer comparisons are address-equality comparisons; the function does not dereference the payload pointers used for tag-19 matching.

## Behavior

### Temporary comparison state

At entry, the function initializes two pointer-valued temporary values: the first from the receiver argument and the second from the record argument.

For tags 3 and 4, F-96217f78e268 receives the address of the first temporary and the receiver. After that call, the function uses the current temporary values in comparison operations.

The comparison against receiver state is ordered and short-circuiting:

1. Receiver word 744 must equal the first temporary.
2. Only if that matches, receiver word 748 must equal the second temporary.
3. Only if both match, receiver word 752 must equal comparison value A.
4. Only if all three match, receiver word 756 must equal comparison value B.

An earlier mismatch prevents the later comparison reads. The comparison values supplied as the third and fourth arguments are not added to the temporary state by any visible direct assignment.

The writable extent and representation of the temporary storage passed to dependencies are not established. In particular, the fact that two temporary values are subsequently compared does not independently establish a public two-word structure contract for every dependency.

### Tag 3

The function performs these operations in order:

1. Calls F-96217f78e268 with the temporary-storage address and receiver.
2. Calls F-3ee466182bff with that temporary-storage address.
3. If that result is zero, calls F-92bea7c30bd6 with the receiver and returns 1.
4. Otherwise, performs the four-part cached comparison described above.
5. If all four values match, returns 1 without further dependency calls.
6. On a mismatch, calls F-3ee466182bff with the address of receiver storage at offset 744.
7. If this second result is nonzero, calls F-12cb3c413baa with the temporary-storage address and the address of receiver storage at offset 744.
8. Calls F-d156b0b83eb3 with the temporary-storage address, receiver word 132, and receiver word 128, in that argument order.
9. Calls F-6d16652f2d03 with the receiver and temporary-storage address.
10. Returns 1.

The second F-3ee466182bff call occurs only after a cached-comparison mismatch. Its result controls F-12cb3c413baa, not the final two dependency calls.

The values at receiver offsets 132 and 128 are read for the F-d156b0b83eb3 call after the preceding dependencies have returned. They are not entry-time snapshots. The supplied evidence does not establish the relative order of those two argument reads.

### Tag 4

The function first calls F-d47df7e0a4d8 with no explicit arguments. It then calls F-96217f78e268 with the temporary-storage address and receiver.

It performs the same four-part cached comparison used for tag 3:

- A complete match returns 1 immediately.
- Any mismatch calls F-92bea7c30bd6 with the receiver and then returns 1.

Unlike tag 3, this path does not call F-3ee466182bff to qualify the prepared temporary state and does not perform the mismatch sequence involving F-12cb3c413baa, F-d156b0b83eb3, and F-6d16652f2d03.

### Tags 1 and 2

For tag 1, if receiver flag `0x10000000` is set, the function loads and invokes the receiver callback at table byte offset 328.

For tag 2, the same flag selects the callback at table byte offset 332.

Each callback receives the receiver as its sole explicit argument. Its return value is unused.

After the callback, or after deciding not to invoke it, processing proceeds to the final tag-19 check. Consequently, a tag-1 or tag-2 callback can run and the function can still return 0.

### Tag 15

The tag-15 work is suppressed if the low byte at receiver offset 644 equals 1.

Otherwise, the function:

1. Calls F-6904f7699031 with the address of receiver offset 688 and the integer value 50.
2. Calls F-ec4cfa552cce with the same subobject address.
3. Reads the low byte at receiver offset 668.
4. If that byte is nonzero, loads and invokes the receiver callback at table byte offset 340, passing the receiver.

The offset-668 gate is read **after** both direct dependency calls. Their effects can therefore affect whether the callback is invoked. The callback’s return value is ignored.

Whether suppressed or executed, this branch continues to the final tag-19 check.

### Final tag check

For paths that do not already return through tag-3 or tag-4 handling, the function reads the record tag again. If it is not 19, the function returns 0.

This is a fresh read. Dependencies or callbacks that can reach the record through aliases or other state are not assumed to preserve its tag. A path initially selected by tag 1, 2, or 15 can therefore reach tag-19 handling if an intervening call changes the record appropriately.

The supplied representation also contains a fallback for a later tag value of 3 or 4 that calls F-92bea7c30bd6 and returns 1. With stable record memory, the earlier tag-3 and tag-4 branches already cover those values.

### Tag-19 primary match

The function first reads the payload address at record offset 12.

If it equals receiver word 68, the function reads the identifier at record offset 8 and receiver word 64. The primary match succeeds when the identifier equals either:

- Receiver word 64; or
- A separate 32-bit global comparison value, read only when the identifier differs from receiver word 64.

On success, the function loads and invokes the receiver callback at table byte offset 212, passing the receiver, and returns 1.

If the payload address does not match, the primary identifier and global comparison value are not needed for this branch. If the primary match succeeds, the secondary matching rule is not evaluated.

### Tag-19 secondary match

If the primary match fails, the function reads receiver word 156.

When it is nonzero, the secondary match requires:

- The previously read record payload address to equal receiver word 152; and
- The 32-bit value at record offset 8 to equal a separate pointer-valued global comparison value.

The record word at offset 8 and the pointer-valued global are read only after the enable and payload-address conditions succeed.

On a secondary match, the function:

1. Calls F-5710a8628cba with no explicit arguments.
2. Takes its 8-bit result.
3. Loads the receiver callback at table byte offset 160.
4. Invokes that callback with the receiver and the 8-bit result.
5. Returns 1.

The callback-table lookup follows F-5710a8628cba. That dependency is not assumed to preserve the receiver’s callback-table pointer.

If neither matching rule succeeds, the function returns 0.

## Side effects

This does not make the function read-only:

- Dependencies receive addresses of temporary storage, receiver state, or a receiver subobject.
- Receiver callbacks may mutate the receiver, record, globals, or other reachable state.
- Parameterless dependencies may have externally visible effects.
- Dependencies may alter storage subsequently read by this function.

No allocation, release, ownership transfer, retention, or reference-count operation is established merely by passing these addresses. The function contains no explicit allocation or release operation of its own.

No explicit error result is defined. A zero result is a dispatch outcome, not evidence of a dependency failure. Results from most dependencies and all receiver callbacks are ignored; F-3ee466182bff controls branching, and F-5710a8628cba supplies an 8-bit callback argument.

No rollback, exception handling, or abnormal-return cleanup is visible. The stated return behavior is conditional on all invoked operations returning normally.

## Acceptance examples

These are conditional expectations derived from static evidence, not executed tests. Dependencies are assumed to return normally; stated comparisons refer to values at their actual read points.

1. **Tag 3, unqualified temporary state.** If the first F-3ee466182bff result is zero, F-92bea7c30bd6 is called and the result is 1. No cached comparison is required.

2. **Tag 3, exact cached match.** If the first predicate result is nonzero and all four comparison values match, the result is 1 without the second predicate or mismatch-processing calls.

3. **Tag 3, mismatch with zero second predicate.** F-12cb3c413baa is skipped, but F-d156b0b83eb3 and F-6d16652f2d03 still run, in that order. The result is 1.

4. **Tag 4, exact match.** F-d47df7e0a4d8 runs before F-96217f78e268. A complete comparison match returns 1 without calling F-92bea7c30bd6.

5. **Tag 1, enabled callback, unchanged tag.** The offset-328 callback runs. If the tag remains 1, the function returns 0.

6. **Tag 15, low byte equals 1.** A word whose low byte is 1 suppresses both subobject calls and the offset-340 callback, regardless of its upper bytes. If the tag remains 15, the result is 0.

7. **Tag 15, callback gate changed by a dependency.** If the offset-668 low byte is zero initially but nonzero after the two subobject calls, the offset-340 callback runs.

8. **Tag 19, primary alternate identifier.** When the payload address matches receiver word 68 and the identifier differs from receiver word 64 but equals the primary global comparison value, the offset-212 callback runs and the result is 1.

9. **Tag 19, both rules potentially match.** A successful primary match takes precedence. The secondary dependency and offset-160 callback do not run.

10. **Tag 19, secondary match.** With primary failure, nonzero receiver word 156, matching secondary payload address, and matching secondary global value, F-5710a8628cba runs before the offset-160 callback. The result is 1.

11. **Tag 19, disabled secondary match.** If the primary rule fails and receiver word 156 is zero, the result is 0 without reading the secondary global comparison value.

12. **Unrecognized stable tag.** Without a recognized preliminary action and with the final tag still not 19, the result is 0 and no dependency is visibly invoked.
