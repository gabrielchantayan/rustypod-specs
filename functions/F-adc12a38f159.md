# F-adc12a38f159

## Purpose

F-adc12a38f159 accepts seven arguments and exposes a signed 32-bit result. Its visible operations conditionally construct an intermediate object, invoke two further dependencies, and transfer individual bytes between temporary storage and a caller-supplied destination.

**Inferred intent:** a construction-and-derivation routine with byte-preserving transfers.

**Established limitation:** execution is controlled by a dispatcher whose seed, selector adjustment, transitions, arithmetic factors, and masks come from external 32-bit storage. Their values are not supplied. The evidence therefore establishes conditional operations and their local ordering, but not a complete execution path, output extent, termination guarantee, or application-level result meaning.

The contract below distinguishes reads of external storage from reuse of previously captured values. Dependencies are not assumed to preserve that storage.

## Behavior

### External-value labels

The following descriptive labels identify relationships between reads without assigning meanings to unknown values:

- **Entry seed:** read once to initialize dispatch state.
- **Primary factor:** read at every dispatcher entry and also read afresh by selected payload calculations.
- **Secondary factor:** likewise read at every dispatcher entry and independently by selected payload calculations.
- **Selector adjustment:** read when computing each selector.
- **Fallback transition:** read before executing each selected region.
- **Shared argument factor:** used during staging of argument seven and read again during construction of the argument-one-derived third-argument quantity.
- **Step adjustment:** used in several counter updates.
- **Transition values, predicate factors, and masks:** additional external values used by particular regions.

Repeated references to one label identify the same external storage, not a guarantee that successive reads return the same value.

### Entry and dispatcher timing

Entry initializes the result, several working integers, several pointers, and the offset field to zero. It captures arguments one through four. The three temporary byte regions are not explicitly cleared.

The entry seed is read **once**, before the first dispatcher iteration. Returning to dispatch does not reread that seed.

Every dispatcher iteration performs these reads in the established order:

1. Capture a primary-factor snapshot.
2. Capture a secondary-factor snapshot.
3. Read the selector adjustment and combine it with the current dispatch state.
4. Read the fallback transition into the next-state working field.
5. Execute the selected region.

These reads occur even when the selected region immediately replaces the fallback transition or returns the result. The terminal region therefore does not bypass that iteration’s dispatcher reads.

The default region returns to dispatch using the already captured fallback transition. Explicit no-payload regions either retain it or replace it with another externally read transition.

A snapshot is not automatically reused wherever the same external factor appears later. Some counter updates explicitly consume the dispatcher snapshots; other operations read the corresponding external storage again. Dependency-induced changes can therefore affect fresh reads without retroactively changing a captured snapshot.

The missing external values prevent determining reachable selectors, finite loop bounds, or whether the terminal region is reached.

### Input staging and read reuse

Whenever staging executes:

- Argument six is multiplied by a **fresh read** of the secondary factor.
- Argument two is multiplied by a **separate fresh read** of the secondary factor, after the preceding assignment.
- Argument seven is multiplied by a fresh read of the shared argument factor.
- Arguments four and five become retained opaque dependency inputs.
- The offset becomes two.
- Argument three becomes the pending destination.
- The captured first argument becomes a working unsigned quantity.

Neither secondary-factor multiplication reuses the secondary snapshot taken at dispatcher entry. The two fresh reads are also not a single shared staging snapshot.

The working quantities are mutable dispatcher state. Other regions can overwrite them before construction. Thus, a claim that a later dependency argument is derived from a particular input requires staging to have executed and the relevant working value to have remained intact.

### Byte reads, writes, and counter updates

Four visible transfer forms each read one byte, apply the same arithmetic transformation, and write one byte:

- A source and saved destination use an index computed once from a fresh primary-factor read and a signed working counter.
- A source and saved destination use separately expressed primary-factor reads for their indices.
- A source and offset destination use a retained unsigned index.
- A source and offset destination use an index computed once from a fresh primary-factor read and an unsigned working quantity.

For any input byte \(x\), the transformed value before narrowing is

\[
27(19x+124)-20=513x+3328.
\]

Its low eight bits equal \(x\). The byte transformation itself therefore preserves the value. It does not establish encryption or encoding.

For the form with separately expressed index reads, source and destination indices are not established to remain equal if the primary factor changes between those reads. The representation does not specify the relative evaluation order of those two index expressions. In all forms, the source byte used to calculate the assigned value is read before the resulting byte is stored.

Following the store:

- The two forms that compute one shared index replace a working counter using that index and a **fresh secondary-factor read**.
- The separately indexed saved-destination form updates its traversal counter using the **primary dispatcher snapshot**, a **fresh secondary-factor read**, and a **fresh step-adjustment read**.
- The retained-index offset-destination form updates its counter using **both dispatcher snapshots** and a **fresh step-adjustment read**.

These are distinct reuse rules. Replacing all factor accesses with one entry snapshot, one staging snapshot, or fresh reads everywhere would change the established behavior.

Other regions reset counters, initialize them from external values, or calculate indices and predicates. Their unknown factors and transitions prevent establishing the number or order of byte transfers.

### Transition arithmetic and result update

Several predicate regions calculate candidate transitions using an external transition value plus a fixed displacement, then independently reread that same external location for the other candidate. Equality of those reads is not established.

The result-update region reads the primary factor afresh and multiplies it by the retained derivation-related integer. It does not use the primary snapshot from dispatcher entry.

Arithmetic mixes signed and unsigned 32-bit quantities, multiplication, subtraction, complement, bitwise combinations, and shifts by 31. Unsigned right shifts extract a high bit; signed right shifts followed by addition are distinct operations. These predicates cannot be reduced to ordinary bounds checks without further evidence.

Unsigned 32-bit arithmetic has modular interpretation in the supplied representation. Assignment to an unsigned field does not by itself establish that an earlier signed multiplication was defined. Exact overflow-sensitive signed behavior remains unresolved.

## Side effects

Conditional on reachability, the function:

- Repeatedly reads external factors, masks, transitions, and opaque dependency inputs.
- Writes working state and temporary bytes.
- Reads temporary bytes and writes caller-selected storage.
- Passes temporary addresses to five dependencies.
- Returns the current signed 32-bit result field if termination occurs.

No direct assignment to external global storage is visible. This does not establish preservation: dependencies may modify it. The read timing and snapshot rules above determine which later calculations can observe such modifications.

No explicit rollback, atomic-output guarantee, timeout, or alternate checked-error exit is visible. Earlier writes are not visibly undone if a later operation fails externally or accesses invalid storage.

Per-byte operations are not established whole-buffer moves. If storage aliases, later reads may observe earlier writes according to the actual path and indices.

Temporary addresses cease to designate live invocation storage after return. Whether dependencies retain them is unknown; no extended lifetime is established.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Entry seed versus iteration reads.** If execution returns to dispatch three times after its initial dispatch, the entry seed is still read only once. Each of the four dispatcher entries performs its own primary snapshot, secondary snapshot, selector-adjustment read, and fallback-transition read.

2. **Independent construction multipliers.** Suppose the first numeric multiplication reads primary factor three, and the first F-ac44bee69173 call changes that factor to five. With no further change before the second multiplication, the second uses five, not three or the dispatcher snapshot.

3. **Shared storage, different sampling times.** Suppose staging reads shared argument factor two for argument seven. If dependencies change that storage to seven before the later argument-one-derived calculation, that calculation uses seven. It does not reuse two. Neither quantity is thereby proven to represent a length.

4. **Snapshot-sensitive update.** If a dispatcher captures primary factor four and the separately indexed transfer later reads primary factor six, its byte indices use the fresh reads. Its subsequent counter update still uses the captured four where specified.

5. **Byte preservation.** A valid transfer reading byte 0, 127, or 255 stores respectively 0, 127, or 255 at its calculated destination. This does not prove correct destination selection or traversal.

6. **Construction order.** On normal completion of a construction visit, the fixed-13 call precedes both numeric calls. The shared-factor read for the argument-one-derived quantity follows both numeric calls. The fixed-11 call follows both variable-quantity calls.

7. **Staged offset.** After staging, derivation receives intermediate storage plus two as its second argument. This does not establish that the dependency’s entire access fits within the remaining 18 bytes.

8. **Conditional return.** If an admissible path reaches termination without a result update, the result is zero. Reachability of such a path is not established.

9. **No guaranteed rejection or extent.** A null destination is not visibly rejected at entry. No claim of exactly 16 output bytes, or safe overlap handling, follows from the local region sizes.
