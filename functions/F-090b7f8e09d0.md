# F-090b7f8e09d0

## Purpose

F-090b7f8e09d0 exposes a call-driven sequence of byte and 32-bit word accesses, arithmetic-derived destinations, and bit-field forwarding to unresolved indirect dependencies.

The supplied representation does not establish an application-level purpose. Allocation, serialization, object construction, rendering, and device control are not supported interpretations of the visible operations alone.

This contract covers the **visible execution prefix**, conditional on the recovered operations accurately representing execution and control reaching each operation. The representation reports unreliable instruction data and terminates at an invalid-instruction boundary. It does not establish normal completion.

## Interface

### Explicit inputs

The apparent interface contains four input positions:

| Position | Represented width | Direct use in the visible prefix |
|---|---:|---|
| First | 32 bits | None shown |
| Second | 32 bits | Forwarded to the first dependency and subsequently stored as a word |
| Third | 32 bits | None shown |
| Fourth | Signed 32-bit integer | Shifted left by 10 and supplied twice to one dependency |

The lack of direct use of the first and third positions does not prove their irrelevance to execution. The actual calling convention and implicit state available to dependencies are unresolved.

### Implicit inputs

The prefix also depends on:

- An incoming return-link value used to calculate the initial indirect target.
- An incoming unsigned 32-bit register value whose upper 20 bits are forwarded.
- An incoming address-bearing register used for the first selector-byte read.
- An auxiliary unsigned register result exposed after an intermediate call.
- Dependency results represented as 32-bit quantities and, once, a 64-bit quantity.
- Contents of all directly accessed memory.
- Effects of dependencies on memory, globals, register state, ownership, and control flow.

No validation, permitted range, ownership, or lifetime contract is established for these inputs.

### Outputs and completion

No explicit return value or normal return is visible. Observable behavior includes the dependency calls, their effects, and the direct memory accesses described below.

The final visible operation is an invalid-instruction termination marker. Whether actual execution traps, terminates, transfers control to a handler, or behaves otherwise is **documented_only**.

### Width and arithmetic conventions

A **byte** is 8 bits. A **word** is 32 bits. Bit positions are numbered from zero at the least significant bit.

For the conditional arithmetic examples and address formulas:

- Unsigned right shifts insert zeros.
- Byte stores retain only the low eight bits.
- Word values retain 32 bits.
- Left shifts and products described under the **32-bit interpretation** discard bits above bit 31.
- Address formulas use this same interpretation where wrapping is relevant.

The representation mixes signed, unsigned, and address-bearing expressions. Unsigned 32-bit operations support modulo-2³² interpretation; signed overflow, signed left shifts, pointer arithmetic, and the actual machine address width require further confirmation. The formulas are not assertions that every expression has defined portable-language behavior.

Endianness and the transaction width of physical memory accesses are unresolved.

## Behavior

### Dependency-sequence convention

All unresolved dependencies are identified as **F-unknown**. Separate occurrences need not refer to the same target.

A **five-call sequence** means:

1. One call with the stated displayed arguments.
2. Three calls with no displayed arguments.
3. One further call with no displayed arguments whose result is retained.

Calls occur in that order. A missing displayed argument list does not prove the absence of meaningful machine-level arguments or implicit state. Unused explicit results do not make calls removable.

The semantic labels below distinguish values for this contract; they do not establish application-level object types.

### 1. Forwarding the second input

The first F-unknown call receives:

- The second explicit input.
- The incoming unsigned register value shifted right by 12.

Its target is calculated from the incoming return-link value plus 4094. It is not established as a fixed dependency address independent of entry state.

Three no-displayed-argument calls follow. A fourth supplies the **first index**.

The second input is stored as a word at **4 × first index + 20**.

A five-call sequence then begins with **4 × first index**, producing the **first token**. No allocation, bounds check, null check, or destination validation is visible before the store.

### 2. Publishing two token bytes

A selector byte is read at **incoming address + 1**. Its unsigned value determines the destination **selector + 17**. The low byte of **4 × first token** is stored there.

A five-call sequence beginning with **4 × first token** returns a temporary index.

Next, another selector byte is read at **64 × first token + 1**. A byte is written at **selector + 17**, using the first token masked to 30 bits and shifted unsigned right by 20.

The intermediate can contain ten significant bits, but the byte store retains only original token bits **20–27**. Original bits 28 and 29 are discarded by byte truncation.

A five-call sequence beginning with **4 × temporary index** returns a further index. The following call receives, in order:

1. Four times that further index.
2. The saved second selector.

One no-displayed-argument call follows.

### 3. Forwarding the fourth input and publishing zero

A call receives the fourth explicit input shifted left by 10 in both displayed argument positions. Another no-displayed-argument call follows.

An auxiliary unsigned register result is exposed at this point. Its precise producer and return convention are not established.

The next direct operation reads a selector byte at **absolute address 1** and writes a zero byte at **selector + 17**. The selector address reduces to 1 because its represented scaling input is zero.

This access does not use the incoming address from the first byte publication.

### 4. Processing the auxiliary result

A five-call sequence begins with:

1. The auxiliary result.
2. The same auxiliary result.
3. Sixteen times that result.

The retained result is another temporary index.

A selector byte is then read at **16 × auxiliary result + 1**. At **selector + 17**, a byte is stored from the auxiliary result shifted unsigned right by 22. Byte truncation retains original bits **22–29**.

A five-call sequence beginning with **4 × temporary index** returns a further index. The next call receives:

1. The saved selector.
2. Four times the further index.

This order differs from the earlier call that placed the scaled index first.

One no-displayed-argument call follows. Another call receives two zeros, and the next no-displayed-argument call supplies a represented **64-bit result**.

The repeated auxiliary value is a dependency shown by the representation, not an independently verified register-preservation guarantee across intervening calls.

### 5. Splitting and publishing the wide result

The represented 64-bit result is divided into a **low word** and a **high word**, each 32 bits.

The prefix then:

- Stores a zero word at **4 × high word + 20**.
- Runs a five-call sequence beginning with the high word.
- Stores the high word at **4 × returned index + 20**.
- Calls F-unknown with four times that returned index.
- Makes four further no-displayed-argument calls whose explicit results are not retained.

A separate word store then uses the saved low word:

| Property | Expression |
|---|---|
| Destination | **2²⁸ × low word + 20** |
| Stored value | **2²⁶ × low word** |

Under 32-bit arithmetic, the destination product depends only on the low four bits of the low word, and the stored product depends only on its low six bits. These expressions must not be treated as unbounded array offsets.

### 6. Publishing a low-word field

A five-call sequence begins with **2²⁶ × low word** and returns an index.

At **4 × returned index + 20**, the prefix stores the low word masked to 29 bits and shifted unsigned right by 9. The stored value contains original low-word bits **9–28**, yielding a range from zero through **0xFFFFF**.

A five-call sequence beginning with four times that index returns the first **record index**.

### 7. First strided-record publication

The **record value** is four times the record index. It is stored at **16 × record index + 20**.

The next call receives:

1. A word read at **record value + 20**, shifted unsigned right by 12.
2. The record value.
3. A word read at **record value + 20**, shifted left by 2.

The write destination uses stride 16 from the record index. The read address uses stride 4 from that index. They are not generally equal.

The representation contains two word-read expressions for the call arguments. Their relative evaluation order is unresolved; a contract cannot replace them with one guaranteed stable read.

Three no-displayed-argument calls follow, then a fourth returns an index. The preceding record value is stored at **4 × returned index + 20**.

### 8. Repeated record publications

The following publications occur in order:

1. A five-call sequence begins with four times the latest returned index. Its result becomes a new record index. Four times this new index is stored at **16 × new record index + 20**.
2. A five-call sequence begins with the new record value twice, followed by the saved low word shifted left by 26. The preceding record value is stored at **4 × returned index + 20**.
3. A five-call sequence begins with four times that returned index. Its result creates another record: four times the result is stored at **16 × result + 20**.
4. A five-call sequence begins with this record value alone. The preceding record value is stored at **4 × retained index + 20**.
5. A five-call sequence begins with four times that retained index. Its result creates another record, again storing four times the result at **16 × result + 20**.

These are separate writes separated by calls. Their ordering remains significant when destinations alias or dependencies modify relevant memory.

### 9. Capturing and publishing a shifted word

Immediately after the last stride-16 store, a word is read at **4 × current record index + 20** and captured.

A five-call sequence begins with four times the current record index and returns a **field index**. The captured word, shifted unsigned right by 12, is stored at **4 × field index + 20**.

The stored value comes from the earlier captured word, not a fresh read after those calls.

A five-call sequence beginning with **4 × field index** returns another record index. Four times that new index is stored at **16 × new record index + 20**.

### 10. Forwarding fragments

The next five-call sequence begins with:

1. The low six bits of **4 × field index**, shifted left by 14.
2. Four times the newest record index.
3. The field index shifted left by 30.

Under the 32-bit interpretation:

- The first argument places field-index bits **0–3** at bits **16–19**.
- The third argument places field-index bits **0–1** at bits **30–31**.

The preceding record value is stored at **4 × returned index + 20**.

A five-call sequence beginning with four times that returned index produces the **final token**.

### 11. Final byte publications

A selector byte is read at **2²⁸ × field index + 1**. At **selector + 17**, the low byte of **4 × final token** is stored.

The next call receives:

1. Four times the final token.
2. The same value again.
3. Sixteen times the final token.

Its visible target calculation uses an adjustment of **4076**, rather than the **4094** adjustment used by surrounding calls. The distinction must remain unresolved rather than being normalized into an assumed common dependency.

A no-displayed-argument call returns a 32-bit value, which is forwarded to the following call. Three more no-displayed-argument calls follow; another returns an index.

The selector byte is now **reread** at **2²⁸ × field index + 1**. At this newly selected destination plus 17, the prefix stores the final token masked to 30 bits and shifted unsigned right by 20, truncated to one byte. This retains final-token bits **20–27**.

A five-call sequence begins with four times the newly returned index. The next call receives four times that sequence’s retained result, followed by the newly read selector.

One final no-displayed-argument call precedes the invalid-instruction boundary.

## Side effects

### Memory layout and validity

The prefix establishes address patterns, not validated structures:

| Access pattern | Width | Established role |
|---|---:|---|
| Scaled value + 20 | 32 bits | Word store or word read |
| Selector-producing address + 1 | 8 bits | Unsigned selector read |
| Selector + 17 | 8 bits | Byte store |

Because a selector is an unsigned byte, its destination lies from **17 through 272**, inclusive, under ordinary address addition. No object base is added to these destinations.

The word-address formulas are multiples of four plus 20 under the stated arithmetic interpretation. This alone does not establish sufficient alignment for the actual environment, mapped memory, readability, or writability.

There are no visible direct checks establishing access validity. Reaching each access successfully requires an environment in which that access can occur; no particular failure response is established otherwise.

### Ordering, aliasing, and ownership

The ordering in the Behavior section is observable. In particular:

- Direct stores occur before the following calls.
- The captured record word is obtained before its intervening call sequence.
- The final selector is read twice, with calls and writes between the reads.
- The two argument word reads have no established relative evaluation order.

Different formulas may produce the same address. Dependencies may modify memory or invalidate addresses between accesses. No atomicity, synchronization, isolation, or transaction guarantee is visible.

**No rollback mechanism is visible in the recovered prefix; whether dependency behavior or external failure handling reverses earlier writes is unknown.**

No direct allocation or release operation is identified. Dependencies may allocate, release, retain arguments, alter globals, or affect memory lifetimes. Neither ownership transfer nor preservation can be inferred from the displayed arguments or unused return values.

## Dependencies

**F-unknown** denotes unresolved indirect dependencies only. It does not establish a shared identity, signature, implementation, or effect across occurrences.

The initial target depends on incoming return-link state. Later targets are derived from represented code-location values; one final-stage call uses a distinct adjustment. Exact dependency identities and relationships remain **documented_only**.

Displayed results include 32-bit values, an auxiliary register result, and one 64-bit quantity. These represented widths do not independently establish the real ABI.

Continuation through the prefix requires dependency behavior that allows execution to reach later operations. No explicit status check, error branch, exception handler, or recovery action is visible.

## Acceptance examples

These are conditional static examples, not executed tests. They assume execution reaches the relevant operation, required memory accesses succeed, and the stated 32-bit interpretation applies.

1. **Input-word publication.** If the first index is 3, the second input is stored at address **32**. The next sequence starts with argument **12**.

2. **Byte truncation.** If the first token is 65, its four-times value is 260. The first byte destination receives **4**.

3. **Token-field truncation.** A first token of **0x3FF00000** produces masked-and-shifted intermediate **0x3FF**, but the byte stored is **0xFF**.

4. **Absolute selector address.** If the byte at address 1 is 7 during the zero-publication phase, the direct store writes zero at address **24**, without adding an incoming object base.

5. **Auxiliary field.** An auxiliary result of **0xFFC00000** yields shifted intermediate **0x3FF** and stored byte **0xFF**.

6. **Different record locations.** For record index 2, the stride-16 store writes value **8** at address **52**. The subsequent call’s word-read address is **28**, not 52.

7. **Truncating destination arithmetic.** For low word **0x10**, multiplication by 2²⁸ yields zero modulo 2³². The special destination is therefore address **20**.

8. **Captured memory.** If the captured word is **0x12345000**, the later shifted publication is **0x00012345**, even if intervening dependencies alter the original location, provided the represented captured value remains the source used by execution.

9. **Selector reread.** If the final selector source initially contains 2 and later contains 9, the two final byte stores target addresses **19** and **26**, respectively.

10. **Fragment placement.** For field index 15, the fragment-forwarding call’s first argument is **0x000F0000** and its third argument is **0xC0000000**.

11. **Failure uncertainty.** If a dependency prevents continuation, later prefix operations are not guaranteed. The representation provides no guarantee that earlier writes remain in place or are reversed; dependency effects and external failure handling remain unknown.
