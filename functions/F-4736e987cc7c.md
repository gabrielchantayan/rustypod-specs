# F-4736e987cc7c

## Purpose

F-4736e987cc7c is a state-dependent dispatcher operating on a caller-supplied record. It selects one of two mutually exclusive paths:

- When the byte at record offset `0x10` is exactly `1`, it clears that byte, invokes a record-processing dependency, performs two external calls, reads a signed 32-bit value through an indirect record link, and submits a conditionally adjusted value to another dependency.
- Otherwise, when both the bytes at offsets `0x0C` and `0x0F` are nonzero, it clears one flag, sets another, invokes a notification dependency, and conditionally clears an additional flag before invoking another external dependency.

On every ordinary return, the result is the 32-bit value zero.

The supplied static evidence establishes these operations, but not their application-level meaning. Describing the paths as initialization, activation, shutdown, timing, or resource release would require information not present here.

## Interface

### Input

The function takes one argument: a 32-bit value used as the base address of a mutable record.

The argument is not checked for nullness, alignment, address-range validity, or record completeness. The caller must supply memory suitable for every access reached along the selected path.

The following record locations are observable:

| Offset | Width | Role established by use |
|---|---:|---|
| `0x08` | 32 bits | Address of a secondary record, loaded only on the first path |
| `0x0C` | 8 bits | First nonzero predicate for the alternative path |
| `0x0D` | 8 bits | Exact-one predicate, conditionally cleared on the alternative path |
| `0x0E` | 8 bits | Flag written to `1` on the alternative path |
| `0x0F` | 8 bits | Second nonzero predicate, conditionally cleared on the alternative path |
| `0x10` | 8 bits | Primary path selector, cleared when initially equal to `1` |
| `0x18` | Address only | Interior address passed to F-bbe368def7ad |

The secondary record is accessed at offset `0x1C`, where a signed 32-bit value is read.

Passing the interior address at offset `0x18` does not establish the size or layout of the data beginning there. Any memory requirements imposed by F-bbe368def7ad remain dependency-specific.

### Output

The ordinary return value is a 32-bit zero. It does not distinguish:

- Which path was selected.
- Whether a dependency reported success.
- Whether any record flag changed.
- Whether the signed value was adjusted.

All dependency return values are ignored except the result of the second invocation of F-X01, which is forwarded as an argument to F-X03.

## Behavior

### Primary dispatch

The function first reads the byte at offset `0x10`.

If that byte equals exactly `1`, it executes the primary path. Any other byte value, including a nonzero value such as `2` or `255`, selects the alternative path.

The paths do not fall through into one another. In particular, the function does not subsequently evaluate the alternative-path predicates after completing the primary path.

### Primary path: record processing and value submission

The following order is established:

1. Write zero to the byte at offset `0x10`.
2. Invoke F-bbe368def7ad with the record base address and the interior address at offset `0x18`, in that argument order.
3. Invoke F-X01 without explicit arguments. Ignore its return value.
4. Invoke F-X02 without explicit arguments. Ignore its return value.
5. Read the 32-bit address at record offset `0x08`.
6. Through that address, read the signed 32-bit value at secondary-record offset `0x1C`.
7. Determine the value to submit using the threshold rule below.
8. Invoke F-X01 again, without explicit arguments, and retain this invocation’s result.
9. Invoke F-X03 with that retained result as its first argument and the determined signed value as its second argument.
10. Return 32-bit zero if control returns normally from the dependencies.

The linked address and signed value are read only after the first three dependency invocations. Consequently, those dependencies may affect which secondary record and which value are observed. The function does not use a snapshot of those fields taken at entry.

Conversely, the signed value is sampled before the second invocation of F-X01. A change to the linked record during that invocation does not cause this function to reread the value before calling F-X03.

The two F-X01 invocations are distinct. The first result is discarded, and the second result supplies the first argument to F-X03. There is no established requirement that their results be equal.

### Signed threshold rule

Let the signed 32-bit value sampled from the secondary record be the input value.

- If the input value is less than `5000`, submit it unchanged.
- If the input value is at least `5000`, submit the input value minus `5000`.

Only one subtraction of `5000` is applied. This is not repeated reduction, modulo arithmetic, clamping to zero, or unconditional subtraction.

The evidence contains intermediate signed comparisons around `4096` and `5000`, together with signed-overflow indicators. Accounting for those indicators yields the threshold rule above over the complete signed 32-bit domain.

The resulting subtraction is representable whenever it is selected: its minimum result is `0`, and its maximum result is `2,147,478,647`. Negative input values remain unchanged, including the minimum signed 32-bit value, `−2,147,483,648`.

The function does not directly write the determined value back into the secondary record. Its direct use is as an argument to F-X03. Effects inside that dependency are unknown.

### Alternative path: gated flag transition

When the initial byte at offset `0x10` is not exactly `1`, the function proceeds as follows:

1. Read the byte at offset `0x0C`.
2. If that byte is zero, perform no further explicit record reads or writes and return zero.
3. Otherwise, read the byte at offset `0x0F`.
4. If that byte is zero, perform no explicit writes and return zero.
5. Otherwise, write zero to offset `0x0F`.
6. Write `1` to offset `0x0E`.
7. Read global slot G-A and invoke F-13ef3c7b2c3d with that value and a zero second argument.
8. After that dependency returns, read global slot G-B and retain its value.
9. Read the byte at offset `0x0D`.
10. If that byte is exactly `1`, write zero to it and invoke F-X04 with the retained G-B value.
11. Return zero if all invoked dependencies return normally.

The first two predicates use nonzero tests rather than exact-one tests. Thus any nonzero byte at `0x0C` or `0x0F` satisfies its predicate.

The predicate at `0x0D` is different: only exactly `1` triggers its write and F-X04. Other nonzero values do not.

G-B is read whenever the flag transition reaches that stage, even if the subsequent `0x0D` test does not lead to F-X04.

The read of `0x0D` occurs after F-13ef3c7b2c3d returns. Any mutation that dependency makes to the byte can therefore affect whether F-X04 runs. The function does not preserve an entry-time copy of this predicate.

## Side effects

### Direct record writes

The only direct writes established by the supplied body are:

- Primary path: offset `0x10` becomes zero.
- Alternative path with both nonzero predicates satisfied:
  - Offset `0x0F` becomes zero.
  - Offset `0x0E` becomes `1`.
  - Offset `0x0D` becomes zero only if its later read yields exactly `1`.

No direct write to offset `0x0C`, the link at `0x08`, or the signed value in the secondary record is shown.

These statements describe the function’s own accesses, not the total effects of its dependencies. A dependency may alter these same locations.

### Observable ordering

The primary-path flag clear precedes every dependency invocation on that path.

On the alternative path, clearing `0x0F` precedes setting `0x0E`, and both writes precede F-13ef3c7b2c3d. If F-X04 is called, clearing `0x0D` precedes that call.

There is no rollback in the shown behavior. If a dependency fails to return normally, earlier writes and calls have already occurred. The supplied evidence does not establish what form such a failure takes.

The access sequence does not establish atomicity, inter-thread synchronization, or protection against concurrent modification. No concurrency guarantee should be inferred from the flag writes.

### Ownership and lifetime

The function directly allocates and releases no memory in the supplied body.

It passes the record base and an interior address to F-bbe368def7ad. It also passes values obtained from globals or dependencies to other dependencies. None of those transfers establishes ownership transfer, retention rights, or release responsibility.

The record and any required secondary storage must remain usable through the accesses that reach them. Whether dependencies retain addresses or invalidate storage is unknown.

## Acceptance examples

These examples are conditional static acceptance criteria, not observed executions. Unless stated otherwise, required memory is valid and dependencies return normally.

### Primary-path selection and exclusivity

Given an entry byte of `1` at `0x10`, the function clears that byte before calling F-bbe368def7ad.

Even if `0x0C` and `0x0F` are both nonzero, the function does not execute the alternative-path flag transition during that invocation. Dependency-induced writes are outside this direct-access criterion.

### Threshold boundaries

When the signed value actually sampled after F-X02 has one of the following values, F-X03 receives the corresponding second argument:

| Sampled value | Submitted value |
|---:|---:|
| `−2,147,483,648` | `−2,147,483,648` |
| `−1` | `−1` |
| `0` | `0` |
| `4095` | `4095` |
| `4096` | `4096` |
| `4999` | `4999` |

| `10000` | `5000` |
| `2,147,483,647` | `2,147,478,647` |

In particular, the `4096` boundary does not itself cause subtraction, and `10000` does not reduce to zero.

### Distinct F-X01 results

If the first F-X01 invocation returns value A and the second returns value B, F-X03 receives B as its first argument. The function does not forward A merely because it came from the same dependency.

### Short-circuited alternative path

Given an initial `0x10` value other than `1` and a zero byte at `0x0C`, the function returns zero without reading `0x0F` or invoking any dependency.

Given nonzero `0x0C` but zero `0x0F`, it likewise performs no explicit record writes and invokes no dependency.

### Noncanonical nonzero flags

Given `0x10 = 2`, `0x0C = 255`, and `0x0F = 2`, the alternative transition is selected. The function clears `0x0F`, sets `0x0E` to `1`, and invokes F-13ef3c7b2c3d.

If the later `0x0D` read yields `2`, F-X04 is not invoked and this function does not clear `0x0D`.

### Dependency-mediated state changes

If F-13ef3c7b2c3d changes G-B or the byte at `0x0D`, the subsequent reads observe the state available after that call. If that later byte read yields `1`, F-X04 receives the newly sampled G-B value, after the byte is cleared.

Similarly, a primary-path dependency that changes the link at `0x08` before the linked-record read can change the source of the submitted value.
