# F-a5347e97e77b

## Purpose

F-a5347e97e77b selects or constructs a representation of a tagged object. Depending on the tag and, for one tag, payload flags, it:

- Returns an address obtained from the object or its payload.
- Invokes a formatting dependency with the supplied destination.
- Processes a sequence using formatting, length-like, and unmapped external dependencies, interspersed with direct byte stores.
- Returns the destination without modifying it directly.

“Representation,” “formatting,” and “length-like” describe inferred intent. Established behavior consists of field reads, dispatch, dependency arguments, direct stores, arithmetic, and return-component selection.

The function returns two independently selected 32-bit components packed into a 64-bit value. The upper component is not consistently a pointer, length, or status.

This contract is based on static evidence only. No runtime tests have been performed.

## Interface

### Inputs

| Input | Width and interpretation |
|---|---|
| Object address | 32-bit address. Supplies a payload address at byte offset 16 and a tag byte at byte offset 1. |
| Destination address | 32-bit address. Used as a byte-oriented destination despite some typed accesses in the evidence. |
| Capacity | Signed 32-bit integer. Forwarded to formatting calls and used in signed sequence comparisons. Not validated. |
| Auxiliary value | Opaque 32-bit value forwarded to formatting calls. |

The payload address is loaded before the tag byte. The function does not first test the object address or payload address for validity.

### Return value

The 64-bit result contains:

- Bits 0–31: the selected output address.
- Bits 32–63: a branch-dependent 32-bit value.

Both components initially select the destination address. Individual branches replace one component as described below.

Formatting results are ignored. The function does not independently report output length, truncation, or dependency failure.

### Payload and entry layouts

Offsets below are byte offsets from the initially loaded payload address.

| Selected branch | Accessed fields |
|---|---|
| `0xF3`, `0xF4` | 32-bit fields at offsets 0 and 4. |
| `0xF6`, `0xFC` | 32-bit field at offset 0. |
| `0xF8` | Unsigned 16-bit flags at offset 28; selected paths additionally read 32-bit fields at offsets 0, 4, 8, 12, or 20. |
| `0xFA` | Signed 32-bit count at offset 8; 32-bit optional flag-array address at offset 12; 32-bit entry addresses starting at offset 16 with stride 4. |
| `0xFB` | Signed 16-bit value at offset 0; payload address plus 28 is passed onward. |

For each non-null sequence entry, its first 32-bit field supplies an address argument to the length-like dependency. That field is read again when preparing a later external-operation call.

### Preconditions and ownership

Execution requires accessible memory for every selected read and direct write, plus satisfaction of each dependency’s contract. Those dependency contracts are unavailable. In particular, neither a nonnegative capacity nor successful completion of an earlier dependency establishes that subsequent accesses are safe.

No allocation or release is explicit in this function. Returning an existing address does not establish ownership transfer, lifetime extension, or permission to release it. Dependencies’ allocation, release, and ownership behavior remains unknown.

## Behavior

### Initial reads and dispatch

The function first reads the 32-bit payload address from object offset 16, then reads the tag byte from object offset 1.

The initially loaded payload address is retained for subsequent payload-relative accesses. Payload contents can nevertheless change between reads through aliasing or dependency effects.

### Default behavior

Tags not otherwise listed, including `0xF5`, `0xF7`, and `0xF9`, take the default path.

If the payload address is nonzero:

- The low return component becomes the payload address.
- The high component remains the destination address.
- No dependency is called and no destination byte is written by this function.

If the payload address is zero:

- The function directly writes one zero byte at the destination.
- Both return components equal the destination address.

Capacity is not checked before that zero-byte store.

### Formatting paths

Each formatting call invokes F-ea27adaa2931 with seven arguments:

1. Capacity.
2. Destination address.
3. Selected format-data address.
4. Branch-selected 32-bit value.
5. Branch-selected 32-bit value.
6. Branch-selected 32-bit value.
7. Auxiliary value.

The supplied evidence does not include the format-data bytes. Exact output, conversions, truncation, and termination cannot therefore be established.

| Tag or selected condition | Fourth argument | Fifth argument | Sixth argument | High return component |
|---|---|---|---|---|
| `0xF2` | Initial payload address | Destination address | Capacity | Destination address |
| `0xF3` | Initial payload address | Field at payload offset 0 | Field at payload offset 4 | Value loaded from offset 0 |
| `0xF4` | Initial payload address | Field at payload offset 0 | Field at payload offset 4 | Value loaded from offset 0 |
| `0xF6` | Initial payload address | Field at payload offset 0 | Capacity | Value loaded from offset 0 |
| `0xF8`, selected `0x0004` path | Initial payload address | Field at payload offset 0 | Field at payload offset 4 | Value loaded from offset 0 |
| `0xF8`, selected `0x0008` path | Initial payload address | Field at payload offset 8 | Field at payload offset 12 | Value loaded from offset 8 |
| `0xFB` | Initial payload address plus 28 | Sign-extended signed 16-bit field at offset 0 | Capacity | That sign-extended value |
| `0xFC` | Field at payload offset 0 | Destination address | Capacity | Destination address |

Every row leaves the low return component equal to the destination address.

Established format-address relationships are:

- `0xF3` and the selected `0xF8` `0x0004` path share a format-data address.
- `0xF4` and the selected `0xF8` `0x0008` path share another format-data address.
- `0xF2` uses an address eight bytes into the format data used for the initial sequence call.
- `0xF6`, `0xFB`, and `0xFC` each use separate format-data addresses.

For the two-field paths, the field supplying the fifth argument is loaded before the field supplying the sixth argument. The high return component retains the fifth-argument value loaded before the call; it is not obtained by rereading the payload afterward.

For `0xFB`, the signed 16-bit value is read and sign-extended to 32 bits. For `0xFC`, this function reads the field at payload offset 0 but does not itself dereference the address represented by that field.

### Flag dispatch for `0xF8`

The unsigned 16-bit flags at payload offset 28 select the following paths, in precedence order:

1. **Bit `0x0002` set:** Read the 32-bit field at offset 20. Return that value as the low component and the destination address as the high component. No formatting call or direct destination store occurs.
2. **Otherwise, bit `0x0004` set:** Take the corresponding formatting path using fields at offsets 0 and 4.
3. **Otherwise, bit `0x0008` set:** Take the corresponding formatting path using fields at offsets 8 and 12.
4. **Otherwise:** Return the destination address in both components without a dependency call or direct destination store.

Other flag bits do not affect dispatch. A zero value read from offset 20 is returned as zero; it does not trigger the default path’s zero-byte store.

### Sequence processing for `0xFA`

#### Initialization

The function calls F-ea27adaa2931 with:

1. Capacity.
2. Destination address.
3. Sequence-specific format-data address.
4. The 32-bit field at payload offset 8.
5. Destination address.
6. Capacity.
7. Auxiliary value.

It then calls F-1cb585febd84 with the destination address. The returned 32-bit value becomes the current output offset. Treating that result as a string length is inferred intent, not an independently established dependency guarantee.

The index starts at zero. Before each iteration, the function rereads the signed 32-bit count at payload offset 8 and continues only if the index is smaller. The count supplied to the initial formatter is therefore not necessarily the count later controlling iteration.

Each iteration reads an entry address at payload offset \(16 + 4 \times \text{index}\). Normal iteration increments the index by one. The overflow path described below exits without another iteration.

#### Null entry

For a zero entry address, the function compares:

\[
\text{current offset} + 4 < \text{capacity} - 6.
\]

If true, it calls the unmapped external dependency with:

- Destination argument: destination address plus current offset.
- Source argument: the address of a fixed data region.
- Count argument: 4.

If that call returns normally, the function increases the current offset by four, irrespective of any actual memory effect of the dependency.

If the comparison is false, the call and offset increase are skipped. Processing continues with the next index.

This path contains no separate comma or minus store. The fixed data bytes are unavailable. The call’s arguments do not establish that four bytes are copied.

#### Non-null entry: length acquisition

The function reads the entry’s first 32-bit field and passes that value to F-1cb585febd84. Its 32-bit result is used as the entry length in signed arithmetic and comparison.

The subsequent branch condition is:

\[
\text{capacity} - 6 < \text{current offset} + \text{entry length}.
\]

#### Non-null entry: threshold exceeded

If the condition is true, the function calls the unmapped external dependency with:

- Destination argument: destination address plus current offset.
- Source argument: a second fixed data-region address, distinct from the null-entry source.
- Count argument: 4.

If the call returns normally, the loop exits without changing the current offset.

The final suffix stores then directly write `0x29` and zero at the current offset and the following offset. These addresses are the first two byte positions in the requested four-byte destination range. The contents of the remaining two positions are not established.

Only under an additional copy-semantics assumption would the external call first copy the four source bytes into that range. Even under that assumption, the following direct stores replace the first two bytes; the last two retain the copied values only if no other relevant modification occurs.

#### Non-null entry: threshold not exceeded

Otherwise, the function performs these actions in order:

1. Directly writes `0x2C`, a comma, at the current output offset.
2. Reads the 32-bit optional flag-array address at payload offset 12.
3. If that address is nonzero, reads the byte at that address plus the current index.
4. If the flag-array address and selected byte are both nonzero, directly writes `0x2D`, a minus sign, immediately after the comma.
5. Rereads the entry’s first 32-bit field.
6. Calls the unmapped external dependency using that reread value as the source argument, a destination immediately after the comma or optional minus, and a count of entry length plus one.
7. If the call returns normally, sets the current output offset to the call’s destination offset plus the earlier entry-length result.

The source field used for the external call need not equal the value passed to the earlier length-like call. The count still derives from the earlier result.

No actual entry-content transfer or terminating-byte write is established by this function body. Under a copy-semantics assumption, the requested range includes one byte beyond the presumed entry content, and the updated output offset identifies that last requested byte’s position.

The comma is written before the optional flag-array address is read. Consequently, overlapping destination and payload storage can affect that later read. Likewise, the source field is reread after the comma and optional minus stores.

#### Final suffix

Following normal loop completion or the threshold-exceeded exit, the function directly writes:

- `0x29`, a closing parenthesis, at the current offset.
- Zero at the following offset.

There is no final capacity check. Both return components equal the destination address.

## Side effects

The established direct writes are:

- The default null-payload zero byte.
- Sequence commas and optional minus signs.
- The sequence’s final closing parenthesis and zero byte.

Calls to the unmapped external dependency are separate observable events. Their destination, source, and count arguments are established; their memory effects are not. In particular, this contract does not unconditionally attribute fixed-fragment or entry-content copies to those calls.

Formatting and length-like dependencies may also have side effects. Their supplied addresses do not prove restricted access, read-only behavior, preservation of globals, or preservation of reachable objects.

There is no visible error handling, rollback, or recovery. Dependency return values are either ignored or used directly in arithmetic. If a later read, write, or call fails, earlier direct writes and any dependency effects may remain.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. They assume accessible memory, normally returning dependencies, and representable arithmetic unless stated otherwise.

1. **Default tag, nonzero payload:** The low component is the payload address; the high component is the destination address. No dependency call or direct destination store occurs.

2. **Default tag, zero payload, zero capacity:** The function still directly writes zero at the destination. Both return components equal the destination address.

3. **`0xF8`, flags `0x000E`:** Bit `0x0002` takes precedence. The offset-20 field supplies the low component. Neither formatting path is called.

4. **`0xF8`, unrelated flags only:** Both components equal the destination address. The function makes no dependency call and leaves destination bytes untouched.

5. **`0xFB`, signed field equal to −1:** The formatter’s fifth argument and the high return component are `0xFFFFFFFF`. The fourth argument is the initial payload address plus 28.

6. **Sequence with nonpositive count:** If the count remains nonpositive through initialization, no entry is processed. An initial offset result of \(L\) leads to direct stores of `0x29` and zero at offsets \(L\) and \(L+1\).

7. **Null entry exactly at its threshold:** If current offset plus four equals capacity minus six, no external call occurs for that entry and the offset does not advance.

8. **Null entry below its threshold:** One external call requests count four at the current destination offset. After normal return, the offset advances by four even if the dependency did not copy bytes.

9. **Non-null entry exactly at its threshold:** Equality selects the accepted-entry path. The function stores a comma, optionally stores a minus, then calls the external dependency with count entry length plus one. Entry-content transfer remains conditional on that dependency’s semantics.

10. **Non-null entry exceeding its threshold:** The external call receives the second fixed-data address and count four. After normal return, direct suffix stores target the first two positions of that requested destination range. No contents are established for its remaining positions.

11. **Entry source changes during length acquisition:** If F-1cb585febd84 changes the entry’s first field, the later external call uses the reread source value but the previously returned length. No consistency repair occurs.
