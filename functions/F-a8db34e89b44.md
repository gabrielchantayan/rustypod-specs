# F-a8db34e89b44

## Purpose

F-a8db34e89b44 is a global-controlled dispatcher. Its established effects are pointer-field observations, arithmetic-state updates, individual byte overwrites, calls to two dependencies, and one state that clears an object field after a dependency returns.

Cleanup or disposal is **inferred intent**, not an established guarantee. The supplied representation does not establish complete overwrite coverage, storage release, ownership transfer, a fixed sequence of calls, or termination.

Selector numbers identify local behaviors, not their execution order. Global contents and changes determine the path.

### Dispatcher observations and resets

Each guard separately observes, in order:

1. Multiplier.
2. Arithmetic.
3. Selector adjustment.

It checks whether the unsigned 32-bit control-plus-adjustment result exceeds 25.

An out-of-range result causes this ordered reset:

1. Set the accumulator to 512.
2. Read **Reset/first-overwrite control** into the control word.
3. Restore the primary sequence from the entry seed.
4. Repeat the guard.

Selector 7 performs the same reset. Neither reset visibly replaces the secondary sequence, retained intermediates, working pointer, retained object, or destination base.

Following a successful guard, the function separately:

1. Captures the primary sequence’s low byte.
2. Observes Arithmetic and retains its signed-right-shift-by-29 result.
3. Observes Arithmetic again and retains its low byte.
4. Observes Selector adjustment again for switch selection.

These observations are not one snapshot. The guard and switch can select different ranges; the shifted quantity and captured arithmetic byte can come from different values.

There is no default switch state. If the later selector is outside 0–25, execution reaches the pointer-condition selection operation: false chooses the guard-captured Multiplier value; true retains the current control word. Before any pointer-test state, that condition is uninitialized. An unmatched switch therefore neither implies reset nor has an established safe initial outcome.

### Arithmetic preparation and branch selection

Selectors 5, 8, and 12 prepare arithmetic state and derive a branch bit from the most significant bit of a 32-bit mixed arithmetic/bitwise result. The extraction is logical and yields zero or one.

For each, zero chooses the adjusted candidate; one chooses the unadjusted candidate. Both candidates come from separate, ordered observations of one state-specific transition global.

The branch machinery combines modular subtraction, addition, unions, complements, and exclusive-or corrections. A conventional comparison, length check, or loop-bound interpretation is not established. The following describes its behavioral inputs and staging without treating the expression structure as a specification of intent.

**Selector 5**

- First form a product from Auxiliary shifted right by one, a fresh Arithmetic observation, and the current accumulator.
- Separately form an Auxiliary–Arithmetic–accumulator product plus one, using fresh observations.

### Byte overwrites

Selectors 1, 9, and 15 each perform one direct byte store.

Each first replaces the accumulator using fresh observations of Multiplier and two occurrences of Arithmetic. The new value is Multiplier times the sum of:

- Arithmetic times the previous accumulator; and
- another Arithmetic observation exclusive-or the dispatcher-captured signed-shift result.

The byte address is then formed from the destination base plus a fresh Multiplier–Arithmetic product times the **updated** accumulator. These address observations are not the guard captures.

Let \(x\) be the selected old sequence byte and \(c\) the dispatcher-captured arithmetic byte. The stored byte is equivalently:

\[
\operatorname{low8}\!\left((x-17)
\left[c\left((2x-1)\mathbin{\mathrm{OR}}139\right)+69+x\right]\right).
\]

This low-byte form absorbs two fixed negative factors whose product equals one modulo 256. It does not require choosing signed interpretations for the captured character bytes.

| 1 | Use the dispatcher-captured old primary byte; update accumulator; store; advance primary using the guard-captured Arithmetic and Multiplier; read **Reset/first-overwrite control** |
| 9 | Capture old secondary byte; update accumulator; advance secondary using fresh Arithmetic, retained unsigned intermediate, and fresh Multiplier; store; read **Secondary-cycle control** |

## Acceptance examples

These are conditional static criteria, not runtime observations.

- **Shared reset transition:** If selector 1’s store changes Reset/first-overwrite control, its following transition observes that global after the store. A later reset reads the same global again, not a separate reset-only value.
- **Shared cycle transitions:** Selectors 9 and 13 read Secondary-cycle control. Selectors 10 and 15 read Primary-cycle control. Intervening modifications can therefore change later transitions within either pair.
- **Ordered preparation:** In selectors 5 and 8, the separately formed product-plus-one quantity precedes the offset observation used to assign the retained sum.
- **Branch selection:** If selector 5’s branch bit is zero, the selected control is its first control observation plus 22; if one, it is the second observation. The corresponding adjustments are +13 for selector 8 and −12 for selector 12.
- **Destination direction:** Selector 12 copies the working pointer into the destination base after both candidate reads but before candidate selection. It does not replace the working pointer with the old destination base.
- **Fresh call argument:** If selector 17 precedes selector 18, selector 18 reloads offset 44. Its call need not receive selector 17’s earlier value.
- **Post-call clearing:** If selector 21 returns from its dependency with the retained object still writable, offset 0 is cleared before First-field call control is observed.
- **Captured overwrite operands:** If selector 1’s store changes Arithmetic or Multiplier, its primary update still uses guard captures. Later observations may see the modification.
- **Retained arithmetic:** Selector 15 uses the retained sum already present; selector 9 uses the retained unsigned intermediate already present. Neither requires freshly prepared values.
- **Divergent dispatch:** Different adjustment observations can produce a successful guard followed by an unmatched switch. Reset is not required in that case.
- **Return and progress:** Selector 25 establishes zero low result bits, not an entirely zero result. Repeated out-of-range guards may reset indefinitely.
