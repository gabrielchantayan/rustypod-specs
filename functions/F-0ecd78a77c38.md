# F-0ecd78a77c38

## Purpose

F-0ecd78a77c38 performs an ordered sequence of indirect calls, transforms dependency-produced values, updates memory through fixed and derived addresses, and finishes with an unresolved indirect control transfer.

No domain-level purpose is established. The supplied material does not justify classifying the operation as initialization, text generation, serialization, object construction, or list maintenance.

This contract distinguishes:

- **Established static evidence:** represented calls, data dependencies, access widths, and ordering.
- **[INFERENCE]:** consequences requiring a conventional 32-bit, truncating execution model.
- **documented_only:** behavior that remains unresolved or is not exhaustively specified here.

All described effects are conditional on execution reaching them. No runtime tests have been performed.

## Interface

### Inputs and outputs

The represented interface has no explicit parameters and no explicit return value. It nevertheless consumes implicit inputs:

- Incoming control-link state that determines the first indirect target.
- An incoming register-held word used in early shifted arguments.
- Primary, secondary, and 64-bit dependency results.
- Memory contents at fixed and derived addresses.
- A **32-bit global value read at address 0x087FBBBC**, retained as an address-like base for the repeated-store region and subsequent updates.
- An unresolved target for the final indirect transfer.

The global value at 0x087FBBBC is read during execution, after substantial dependency and direct-memory activity. It is neither an entry-time snapshot nor a dependency return value.

The complete machine-level entry and return conventions are **documented_only**. A parameterless declaration does not establish a safe ordinary invocation.

## Behavior

### Ordered indirect calls

The initial phase is a long straight-line sequence of indirect calls. No represented condition or loop selects among them. Reaching the direct-memory phase requires every preceding call to return.

The first target depends on incoming control-link state plus displacement 0xFFE. Later targets use embedded control-location or code-address values with the same displacement. These calculations do not resolve dependency identities or prove that different call sites invoke the same implementation.

Call order is observable. Calls must not be discarded or combined because they have no displayed arguments, ignore their primary result, receive zero, or resemble another call.

Early arguments include the incoming word shifted left by 10 bits, including duplicate arguments within one call, and later by 9 bits. Subsequent calls forward transformed primary results, secondary results, and portions of 64-bit results. Earlier values remain in use across intervening calls.

Transformations include:

- Fixed left shifts through counts from 1 to 31.
- Logical right shifts of unsigned words.
- Low-bit masking before subsequent shifts.
- Repeated argument values and explicit zeros.
- Successive transformations of already-shifted values.
- Retention and later extraction of earlier 64-bit results.

Secondary-result channels are represented without ordinary return assignments. Their physical origin, calling-convention guarantees, and preservation rules are **documented_only**. They cannot be assumed zero or interchangeable with primary results.

The complete per-call argument trace is **documented_only** in this contract. The established call sequence is not permission to substitute a smaller high-level algorithm.

### Integer constraints

Observed masks select low fields of 24, 22, 21, 20, 19, 18, 17, 16, 15, 14, 13, 12, 11, and one bit.

Masking and shifting order matters. Selecting the low 20 bits before logically shifting right by 10 produces 0 through 1023. Selecting the low 24 bits before shifting right by 20 produces 0 through 15. A left shift followed by narrowing, masking, or right shifting need not preserve the original value.

**[INFERENCE]** With 32-bit truncating bit-vector arithmetic, left shifts and multiplication by powers of two discard bits beyond bit 31. Successive left shifts totaling at least 32 can therefore yield zero. Several represented calculations have this form.

This inference does not resolve signed left-shift or multiplication overflow under an unknown execution model.

A closing signed-word right shift uses a count obtained from another value’s low byte. Counts can exceed 31. Oversized-count behavior, count masking, and signed right-shift semantics are **documented_only**; a five-bit count mask must not be silently introduced.

### Entry into direct-memory updates

The final call-phase results provide:

- A retained base formed by shifting a word left by 25 bits.
- A separate base formed by multiplying another word by 2²⁵.
- A retained word shifted left by 8 bits.
- A bounded index formed by selecting the low 15 bits of an already eight-bit-left-shifted word, then logically shifting right by 6.
- The low and high words of the last represented 64-bit result.

Under the 32-bit bit-vector interpretation, the bounded index ranges from 0 through 508 in multiples of four. Its doubled value ranges from 0 through 1016 in multiples of eight.

The first direct effects, in order, are a word store at offset 0x14 from the final result’s upper-word base, a byte store at offset 9 from the 25-bit-shifted base, a word store at offset 0x54 from the final result’s lower word multiplied by 256, and a second byte store to the earlier offset-9 destination. The latter byte comes from the retained shifted base rather than the upper word.

These accesses are separate even when a later store overwrites an earlier result.

Fixed-address activity before the repeated region includes a byte read at address 5, byte stores at addresses 1 and 0x15, and a word store at 0x54. These locations must not be treated as independent ordinary globals.

### Literal stores and the retained global base

The value 0x3A is stored through three widths: a byte at a four-times-scaled address, a halfword at an eight-times-scaled address, and a word at offset 0x20 from the four-times-scaled base. This establishes numeric memory effects, not text output.

A different offset-0x20 word destination receives, successively, 0x20, 0x2F, a widened byte read from offset 4 of the same base, and 0x20 again. The byte read and intermediate stores remain observable obligations.

**After those four word stores**, the operation reads the **32-bit word at 0x087FBBBC**. It retains the value as the **global-derived base**. The next fixed-address write stores the 32-bit value 0x20 at address 0x60. Only then does the first four-store group begin.

Consequently:

- The global read must reflect all preceding dependency and memory effects under the actual memory model.
- It must not be hoisted to function entry or before the four offset-0x20 stores.
- The write to 0x60 occurs after the global value has been captured.
- Later aliasing writes can change memory at 0x087FBBBC without automatically changing the retained base.

### Repeated-store region

For this region, the following descriptive roles identify retained values, not object types:

- **Original anchor:** an earlier loaded word subsequently used in scaled addresses.
- **Adjusted anchor:** four times the original anchor, reduced by 0x96.
- **Scaled base:** four times the adjusted anchor.
- **Link-derived base:** four times a later loaded word.
- **Doubled-link base:** twice that same later loaded word.
- **Global-derived base:** the captured word from 0x087FBBBC.

These arithmetic relationships remain subject to the width and overflow qualifications above.

The initial group writes a word at offset 0x54 from eight times the original anchor, a byte at global-derived offset 0x19, a byte at scaled-base offset 0x11, and a word at global-derived offset 0x34. The word at offset 0x54 contains the link-derived base. The bytes contain the low bytes of the scaled and global-derived bases respectively. The last word contains eight times the original anchor.

Subsequent groups preserve that four-access order but use eight times the adjusted anchor for both the offset-0x54 destination base and the value stored at global-derived offset 0x34.

The source establishes a long static repetition. Exact multiplicity is **documented_only** here. This is an explicit trace limitation, not permission to collapse the repetition. Aliasing, device memory, and external observers can distinguish repeated accesses.

### Closing fixed-address dependencies

The closing global-access trace has meaningful retained values and fresh reads.

First, a **32-bit word is read at fixed address 0xA9** and retained. This precedes both the word read at offset 0x74 from the link-derived base and the byte write at fixed address 0x3A. The latter store supplies the low byte of eight times the adjusted anchor plus 0x30.

The operation then retains words from doubled-link offset 0x14 and scaled-base offset 4. Derived stores follow, including byte 0x6C at scaled-base offset 8, bytes from retained base values, and a self-valued word store at doubled-link offset 0x54.

Only after these effects does it write the **retained low byte of the word previously read at 0xA9** to address **0x67**. It then reads a word from doubled-link offset 0x44. The assignment to fixed address **0x21 separately reads the byte at 0x67**; it is not specified as directly reusing the retained low byte from 0xA9.

Further derived effects precede the next read of 0x67:

- A byte store at scaled-base offset 0x10.
- Two successive word stores at global-derived offset 0x54, with the variable-count shifted-byte store between them.
- A word read at scaled-base offset 0x40.
- Word stores at global-derived offset 0x74, scaled-base offset 0x10, and global-derived offset 0x44.

The operation then **reads 0x67 again** to supply a byte store at scaled-base offset 9.

Before another fresh read of 0x67, it writes a byte at doubled-link offset 9, stores the full retained 0xA9 word at scaled-base offset 0x44, and reads a word from scaled-base offset 0x54. It then **reads 0x67 a third time after its initial write**, supplying another byte store to scaled-base offset 9.

The read supplying 0x21 and the two reads supplying scaled-base offset 9 are distinct. Intervening derived stores may alias 0x67. Their results therefore need not equal the retained low byte from 0xA9 or one another. No ordering-independent substitution is established.

The global-derived base also remains active in these closing updates: it supplies destinations at offsets 0x54, 0x74, and 0x44.

### Remaining closing effects and transfer

Later updates use the retained link-offset-0x74 word’s low byte, restore a previously retained word to doubled-link offset 0x54, read scaled-base offset 0x14, and overwrite scaled-base offset 9 again from a derived word. Thus neither of the fresh 0x67-based byte stores is necessarily the last write to that destination.

The closing region also writes a halfword containing 0x65 at twice a loaded base and a word containing decimal 100 at a derived offset-0x54 destination.

Two separate offset-0x64 reads near the end have different roles. One supplies a retained word; the other supplies the base for an offset-0x54 store of that retained word. A subsequent word store uses twice the retained word as its destination.

The final indirect transfer receives four represented arguments, in order:

1. 0x72.
2. The retained word from the first closing offset-0x64 read.
3. The earlier word retained from doubled-link offset 0x14.
4. A later word read at offset 0x74 from a loaded base.

The transfer is represented as a call followed by return. Its target and complete control-flow semantics remain unresolved. Normal function return is conditional on that transfer returning.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Unsigned extraction.** Selecting the low 20 bits of 0xFFFFFFFF and shifting logically right by 10 yields 1023; shifting that result left by 6 yields 65472.

2. **64-bit extraction.** For 0x123456789ABCDEF0, the upper word is 0x12345678. Unsigned whole-result shifts by 36 and 44 narrow to 0x01234567 and 0x00012345.

3. **Byte widening.** An explicitly unsigned offset-5 byte read of 0xFF becomes word value 255, not a sign-extended negative value.

4. **Late global capture.** If a preceding dependency or aliased store changes the word at 0x087FBBBC, the repeated region uses the value read after the four offset-0x20 stores. Using its entry-time value would violate the ordering contract.

5. **Retained base.** If the later write to 0x60 aliases the global word’s storage, the already-captured global-derived base is not implicitly reloaded.

6. **Retained fixed word.** If 0xA9 yields a word ending in 0xAB, the later direct write to 0x67 supplies 0xAB, regardless of intervening changes to 0xA9.

7. **Fresh byte reads.** If intervening derived effects change 0x67 between its later reads, the two scaled-base offset-9 stores use their respective read results. Equality is required only when memory behavior and alias conditions establish it.

8. **Intermediate effects.** Ordinary stable memory ends the four offset-0x20 stores with 0x20, but acceptance still requires the preceding stores and intervening byte read.

9. **Failure and return.** An early non-returning dependency prevents later effects on this path. An invalid destination has no specified local recovery. Normal return is conditional on completion of the final transfer.
