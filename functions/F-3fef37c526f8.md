# F-3fef37c526f8

## Purpose

F-3fef37c526f8 initializes a temporary 32-bit value from its fourth argument, passes that temporary by address to F-ff01e173816f with a fixed selector of 4, and, if the dependency returns normally, stores a three-bit extraction of the resulting value into the caller’s destination byte.

The extraction uses bits 5 through 7 of the temporary’s **numeric value**. It does not necessarily use the first byte at the temporary’s address: that correspondence depends on byte order.

The wrapper’s own final store produces a value from 0 through 7, inclusive. It does not preserve any bits of the previous destination byte.

This describes established behavior of the supplied static representation. The meaning of selector 4, the interpretation of the fourth argument, and the behavior of the dependency are not established.

## Behavior

### Observable sequence

On the visible, normally returning path, the wrapper performs these actions in order:

1. It initializes its 32-bit temporary from the fourth argument.
2. It calls F-ff01e173816f with selector 4 and the address of that temporary.
3. After the call returns, it obtains the temporary’s resulting value and narrows that value to an unsigned eight-bit quantity.
4. It shifts that eight-bit quantity right by five positions.
5. It writes the resulting value into the byte designated by the first argument.
6. It returns without an explicit result.

There is one visible dependency call and one visible destination-byte store. There is no visible loop, alternate selector, retry, validation branch, or error-handling branch.

This ordering describes the operations expressed by the supplied representation. It does not establish instruction-level load counts, volatile behavior, atomicity, memory barriers, or synchronization guarantees.

### Extraction and arithmetic

Narrowing to a byte discards bits 8–31 of the post-call temporary. The subsequent shift discards bits 0–4 of that byte.

Consequently:

- Only bits 5–7 affect the wrapper’s stored result.
- Bits 0–4 do not affect it.
- Bits 8–31 do not affect it.
- The result fits in a byte without further loss.
- No addition, multiplication, or overflow-sensitive arithmetic is involved.

The byte conversion occurs before the right shift. The shift therefore operates on a nonnegative quantity between 0 and 255; there is no dependence on right-shifting a negative 32-bit value.

This is a numeric bit selection. If the dependency modifies individual bytes of the temporary through its address, the resulting numeric value depends on the target’s byte order. The supplied wrapper does not establish that byte order or a portable byte-oriented layout for the temporary.
