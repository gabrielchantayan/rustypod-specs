# F-4e546c4bd649

## Purpose

F-4e546c4bd649 selects a record by following links, then either returns an encoding of that record’s address or performs a fixed sequence of dependency calls and record updates.

Two terminating paths are established:

- **Early return:** selection encounters a record with a zero link and nonzero status. The result contains the context input in its upper 32 bits and the selected record address in its lower 32 bits.
- **Update:** selection stops at a record with zero status. The function calls dependencies in a fixed order, conditionally clears two four-byte fields, writes a one-byte marker, and returns a 64-bit zero.

Before reading the initial record reference, the function writes a marker through the descriptor input. Descriptor and record storage are not established to be disjoint. That entry write can therefore also modify record storage, including the byte later used as the update-completion marker.

“Descriptor,” “record,” “link,” “status,” and “marker” describe observed roles. Their domain meanings are not established.

## Behavior

### Entry write and aliasing

The first visible memory operation writes one byte with value 4 at descriptor offset 12. The four-byte reference at descriptor offset 0 is read afterward.

This order matters when storage overlaps. The entry write may modify record fields or other storage used later. Selection operates on the values subsequently read, not necessarily the values present before entry.

No non-overlap requirement is established. In particular, the descriptor may begin eight bytes before a record. Its entry-marker address then coincides with that record’s offset 4.

### Record selection

For each current record, the link at offset 0x134 is tested first.

| Link test | Status test | Outcome |
|---|---|---|
| Zero | Nonzero | Return the current record encoding immediately |
| Zero | Zero | Select the current record for updating |
| Nonzero | Zero | Select the current record for updating without following its link |
| Nonzero | Nonzero | Continue at the reference obtained from the second link read |

When the initial link test is nonzero, the function reads that link field again before reading the current record’s status. The second read supplies the prospective successor.

Thus:

- A zero-link decision requires one link read, followed by a status read.
- A nonzero-link decision requires two link reads, followed by a status read.
- A nonzero link is read twice even when zero status prevents traversal.
- If the two link reads differ, the second value is the one available for traversal. No additional nonzero check of that second value is visible.

The source establishes these separate accesses, not synchronization or a concurrency protocol. Defined behavior under concurrent modification remains unresolved.

Selection has no visible traversal limit or visited-record tracking. A stable cycle whose records all have nonzero status and nonzero links does not reach either terminating path.

### Early return

A record with zero link and nonzero status causes the function to return the context/address concatenation immediately.

On this path:

- The descriptor entry write has already occurred.
- No update dependency is called.
- No additional record-relative store is executed after the descriptor entry write.
- The final update-path store at record offset 4 is not executed.

These facts do **not** guarantee that record storage is unchanged. The earlier descriptor write may alias the selected record, including its offset-4 marker. Any unchanged-marker assertion requires a non-overlap assumption.

## Side effects

### Direct caller-reachable writes

The function directly performs:

1. One byte with value 4 at descriptor offset 12.
2. On the update path with a nonzero probe result, four-byte zeros at record offsets 0xfc and 0x100, in that order.
3. On normal update completion, one byte with value 4 at record offset 4.

This list identifies store locations by the bases used to compute them. It does not imply distinct storage. The descriptor store may overlap record storage, and overlapping locations must be interpreted in execution order.

The one-byte stores do not themselves replace adjacent bytes. The conditional four-byte stores replace their complete respective fields.

Dependencies may perform additional writes. The direct-store list is therefore not a complete prediction of final memory state.

## Acceptance examples

These scenarios are conditional specifications derived from static evidence, not executed tests. Unless stated otherwise, required storage is valid and dependencies return normally.

### Terminal record without descriptor overlap

Suppose the initial record has zero link and nonzero status, and the descriptor entry byte does not overlap that record.

The descriptor marker becomes 4. No update dependency or record-relative store executes. The record’s offset-4 byte is unchanged by this function.

With context 0x89abcdef and record reference 0x12345678, the result is 0x89abcdef12345678.

### Early return with an aliased marker

Let the descriptor begin eight bytes before the initial record, and let its offset-0 reference identify that record. Suppose the record’s link is zero and its status is nonzero when selection reads them.

The entry write at descriptor offset 12 writes 4 at record offset 4. The function then returns early without executing the final update-path marker store.

This is an early return that nevertheless writes the selected record’s marker byte through descriptor aliasing.

### Zero status with a nonzero link

Suppose a current record has a stable nonzero link and zero status.

Its link is read twice before the status test stops selection. The successor is not followed. The update sequence uses the current record, and normal completion returns zero.

The successor need not be accessible solely because this unused link value is nonzero.

### Traversal to a terminal record

Suppose the first record has nonzero status and a stable link to a second record. The second record has zero link and nonzero status.

The function returns an encoding of the second record with the context in the upper half. Neither record enters the update sequence. Effects of the initial descriptor write remain possible.

### Probe outcomes

For a selected update record:

- If F-5552a4ebb581 returns nonzero, offsets 0xfc and 0x100 receive four-byte zeros in that order, followed by the final one-byte marker store.
- If it returns zero, neither conditional clearing store occurs, but the final marker store still occurs.

### Fresh reads after mutations
