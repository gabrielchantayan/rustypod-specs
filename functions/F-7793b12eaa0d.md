# F-7793b12eaa0d

## Purpose

F-7793b12eaa0d dispatches a named event against an object-like context. It recognizes fourteen event names and returns a 32-bit recognition result:

- **1:** The event name was recognized, including when an event-value guard suppresses its action.
- **0:** None of the event-name comparisons reported a match.

The dispatcher routes preset, seek, toggle, volume, timer, frequency, and tuning events to dependencies. Those descriptions express inferred intent from the event names. The established behavior is the comparison sequence, guard evaluation, dependency invocation, argument forwarding, and return value described below; the dependencies’ actual effects are not established.

## Interface

### Inputs

The function receives three machine-level inputs:

| Input | Established representation and use |
|---|---|
| Context | A 32-bit integer used as an address-bearing context value. It is passed to dependencies and, on some paths, used as the base address for a four-byte field read. |
| Event identifier | A 32-bit value passed unchanged as the first argument to each event-name comparison. Its underlying representation is not established. |
| Event value | A 32-bit integer compared with a shared guard value and otherwise passed unchanged to selected dependencies, except on the two timer-qualified preset paths. |

Although the context is represented as an integer in the supplied material, its address-based uses require readable storage on paths that access its fields. The material does not establish null handling, object allocation size, alignment requirements, or address-overflow behavior.

The event identifier is compared against named constants. A comparison result of zero selects that event; any nonzero result continues the search. String-like matching is plausible, but encoding, termination, case sensitivity, and the treatment of invalid identifiers remain **documented_only**.

### Output

The output is a four-byte value, always either 0 or 1 on an ordinary returning path.

The output is not an action-success result. Dependency return values do not affect the dispatcher’s result. In particular, an event can return 1 without invoking its action because its event value equals the guard.

### Relevant storage

Two context-relative locations are read directly:

| Byte offset from context | Width | Use |
|---|---:|---|
| +176 | 4 bytes | Supplies the argument to F-936a8728139d for an unguarded `HandleTimerDone` event. |
| +188 | 4 bytes | Supplies the argument to F-46c4c03e4abe or F-75a0062870a8 for the corresponding unguarded toggle event. |

These reads establish neither field type nor ownership. They may contain pointers, handles, or other four-byte values.

A separate shared 32-bit value supplies the equality guard. Its meaning, writer, lifetime, and synchronization requirements are not provided.

## Behavior

### Recognition order

The dispatcher compares the event identifier with these constants in order:

1. `TuneToNextPreset`
2. `TuneToPreviousPreset`
3. `TuneToNextPresetWithTimer`
4. `TuneToPreviousPresetWithTimer`
5. `SeekUpWithTimer`
6. `SeekDownWithTimer`
7. `TogglePreset`
8. `TogglePlayPause`
9. `HandleVolumeWheel`
10. `HandleVolumeChange`
11. `HandleTimerDone`
12. `HandleFrequencyChange`
13. `HandleTuning`
14. `HandleTuningSelect`

A zero comparison result selects the corresponding branch. Later comparisons are not performed after selection. If all fourteen comparisons return nonzero, the dispatcher returns 0 without invoking any listed action dependency.

Recognition is defined by the comparison results, not by an independently established interpretation of the identifier. If a comparator were capable of reporting matches for several names, the earliest zero result would take precedence.

### Guard-read timing

The shared guard is read after the first event-name comparison returns, whether or not that comparison matched. This produces a captured guard value used by every recognized branch except the first.

For `TuneToNextPreset`, the supplied representation shows a further read of the shared guard for the branch’s equality check. Thus:

- The initial capture occurs after the first comparison.
- The first event’s guard check uses a subsequent shared-value read.
- All thirteen later event branches use the initial captured value, even though additional comparisons occur before their checks.
- An unknown event still causes the initial guard capture, but no event-value equality check.

This timing matters if comparison calls or other agents can change the shared value. The dispatcher must not be described as taking its guard snapshot before the first comparison or refreshing it for every recognized event.

The equality check concerns two 32-bit values. There is no ordering comparison, range check, masking, or conversion visible in this guard.

### Guard suppression

For each recognized event, equality between the event value and that branch’s applicable guard value suppresses the branch action and returns 1.

Suppression prevents all action dependencies and context-field reads listed for that branch. It does not undo the event-name comparisons or shared guard reads already performed.

If the values differ, the selected action sequence is performed as follows.

### Read and call ordering

The toggle paths read context +188 **after** F-4af5c86658d8 returns. If that dependency changes the field, the subsequent dependency receives the newly read value, not a value captured before the call.

The timer-completion path reads context +176 **before** invoking F-936a8728139d. F-4af5c86658d8 is invoked only after that dependency returns.

For `HandleTuning`, F-951c4451e3f3 precedes F-950df84efc5a. The latter call cannot be moved ahead of the former while preserving the established ordering.

No preservation of shared state or context storage across any dependency call is established.

## Acceptance examples

These are conditional static acceptance cases, not reports of executed tests. Unless stated otherwise, comparisons identify only the named event, required memory is readable, and dependencies return normally.

1. **Unknown event.**  
   All fourteen comparisons return nonzero. The guard is captured after the first comparison. No action dependency is invoked, neither context field is read, and the result is 0.

2. **Recognized but suppressed frequency event.**  
   `HandleFrequencyChange` matches and the original event value equals the captured guard. F-ecf5ac36abd1 is not invoked. The result is 1.

3. **Timer-qualified next preset with a nonzero event value.**  
   `TuneToNextPresetWithTimer` matches, the event value is 7, and the captured guard differs from 7. F-950df84efc5a receives the context first. F-cec1d05e120d then receives the context and zero, not 7. The result is 1.

4. **Zero is not automatically suppressed.**  
   `TuneToPreviousPresetWithTimer` matches, the event value is zero, and the captured guard is nonzero. Both prescribed dependencies execute. Suppression depends on equality with the guard, not on zero alone.

5. **Toggle observes an intervening field change.**  
   `TogglePreset` is not suppressed. Context +188 initially contains one value, but F-4af5c86658d8 changes it before returning. F-46c4c03e4abe receives the value read after that change.

6. **Timer completion preserves call order.**  
   `HandleTimerDone` is not suppressed. The value from context +176 is supplied to F-936a8728139d before F-4af5c86658d8 is invoked.

7. **Later events retain the captured guard.**  
   The initial guard capture is 4. A later comparison changes the shared guard to 9 before `HandleVolumeWheel` matches. An event value of 4 remains suppressed because this branch uses the captured value.

8. **First event uses its later guard read.**  
   `TuneToNextPreset` matches. The initial capture is 4, but its subsequent guard read yields 9. With event value 9, the action is suppressed. With event value 4, it is not suppressed, provided the later read still yields 9.

9. **Action results do not define recognition.**  
   `HandleTuningSelect` is not suppressed and F-f5a89b495698 returns normally. Regardless of its returned value, the dispatcher returns 1.
