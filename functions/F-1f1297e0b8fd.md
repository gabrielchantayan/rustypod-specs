# F-1f1297e0b8fd

## Purpose

F-1f1297e0b8fd conditionally updates one byte in an indexed record collection associated with a caller-supplied object.

The operation first invokes F-cf176702439d. A nonzero result from that dependency prevents this function’s own object reads and record write, and is returned unchanged. A zero result permits an unsigned bounds check. An in-range index selects a record whose byte at offset 10 is replaced with the supplied byte; an out-of-range index produces −50.

This describes the behavior established by the supplied static representation. The semantic meaning of the records, the selected byte, and the preliminary dependency is unknown.

### Bounds decision

Following a zero dependency result, the function reads the 32-bit count at object offset 16.

It compares the index and count as unsigned 32-bit values. The accepted condition is strictly “index less than count.” Equality is rejected.

Consequences include:

- A zero count rejects every possible index.
- For a count of one, only index zero is accepted.
- A value whose high bit is set remains a large unsigned index; it is not treated as negative.
- A count with its high bit set is likewise a large unsigned count.
- Even the largest representable count, 4,294,967,295, does not admit index 4,294,967,295.

If the index is rejected, the function returns −50. This path does not read the record-storage address and does not perform the record-byte store.

The count is read after the dependency returns. If that dependency changes memory that will be used as the count, the comparison uses the subsequently read value, not a preserved pre-call value.

### Accepted-index update

For an accepted index, the function reads the 32-bit record-storage address at object offset 112.

It selects a destination using:

- the storage address just read;
- an index displacement of 20 bytes per record;
- an additional displacement of 10 bytes within that record.

It then stores the supplied 8-bit replacement value at that destination and returns zero.

There is no established read of the old destination byte. No comparison against its prior value is made. Supplying a byte equal to the existing byte still follows the store path.
