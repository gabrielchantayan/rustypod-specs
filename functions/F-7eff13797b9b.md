# F-7eff13797b9b

## Purpose

F-7eff13797b9b conditionally creates or adjusts a resource represented by a caller-owned integer slot.

The established behavior has two paths:

- If the slot contains zero, call a creation-like dependency with the supplied integer, store its result in the slot, and report whether that result was zero.
- If the slot contains a nonzero value, obtain a baseline from another dependency, request an adjustment using the baseline plus the supplied integer, and conditionally invoke a further helper after successful positive adjustment.

“Creation,” “resource,” “baseline,” and “adjustment” describe the apparent roles of the operations. The supplied fragment does not establish the underlying object type, allocation scheme, units, or helper semantics. In particular, it does not establish that the final helper clears memory.

This contract describes the wrapper’s calls, memory accesses, arithmetic, and returned values without assigning undocumented behavior to its dependencies.

## Interface

### Inputs

The function accepts two arguments:

1. **Slot address:** a pointer to a caller-provided integer slot. A null pointer is explicitly accepted as an error case. A nonnull pointer must identify readable storage and, on the initially-zero path, writable storage.
2. **Adjustment:** a signed integer. Its interpretation depends on the initial slot value:
   - For an initially zero slot, it is passed unchanged to F-c2a4e6949719.
   - For an initially nonzero slot, it participates in an addition with the result of F-48d3618d091a.

The slot is not consistently treated as a direct byte-buffer pointer. On the successful positive-adjustment path, its current value is used to locate another integer, whose value then participates in address-like arithmetic.

## Behavior

### Null slot address

The function checks the slot address before reading the slot.

If the address is null, it returns −50. It does not invoke any of the listed dependencies or access the slot.

### Initially zero slot

The function reads the slot to choose a path. If that read produces zero:

1. F-c2a4e6949719 is called with the adjustment unchanged.
2. Its integer result is classified as zero or nonzero.
3. That exact result is written into the caller’s slot.
4. The wrapper returns −108 for a zero result, or zero for any nonzero result.

No sign restriction is imposed on the adjustment in this path. A negative adjustment is forwarded rather than rejected.

Likewise, a negative nonzero result from F-c2a4e6949719 is stored and treated as success by this wrapper. There is no visible rule reserving negative dependency results for errors.

The slot write occurs after the dependency returns. If that dependency changes the slot through some external alias, the wrapper’s subsequent write replaces that change with the dependency’s return value.

No call to F-48d3618d091a, F-a5bc00364bd0, or F-c67cb20988a1 occurs on this path.

### Initially nonzero slot

If the initial slot read produces a nonzero value, the wrapper first calls F-48d3618d091a with no explicit arguments. Its result becomes the baseline used throughout this invocation.

The initial nonzero slot value is used only to select this path; it is not retained as the authoritative value for later operations.

#### Negative-adjustment guard

When the adjustment is negative, the wrapper computes baseline plus adjustment and tests whether that sum is negative.

If the sum is negative, the wrapper returns −50 without calling F-a5bc00364bd0 or F-c67cb20988a1.

This rejection happens **after** F-48d3618d091a has executed. It is not a side-effect-free validation failure.

When the adjustment is zero or positive, the wrapper does not apply this negative-total guard. A negative baseline can consequently produce a negative requested total that is still passed onward.

The guard checks the resulting value’s sign, not arithmetic overflow. It must not be interpreted as a general checked-addition operation.

#### Adjustment request

Unless the negative-adjustment guard returns early, the wrapper:

- Reads the caller’s slot again.
- Calls F-a5bc00364bd0 with that current slot value as the first argument and baseline plus adjustment as the second argument.

The later slot read occurs after F-48d3618d091a. If that dependency changes the slot, the new value is supplied to F-a5bc00364bd0. The wrapper does not require the later value to remain nonzero.

The status from F-a5bc00364bd0 becomes the wrapper’s eventual result.

An adjustment of zero still causes this dependency call. The wrapper does not optimize it into an immediate success or no-op.

#### Conditional post-success helper

F-c67cb20988a1 is invoked only when both conditions hold:

- F-a5bc00364bd0 returned exactly zero.
- The adjustment is strictly positive.

For that call, the wrapper performs an additional level of indirection:

1. It reads the caller’s slot again, after F-a5bc00364bd0 has returned.
2. It treats that current integer value as an address and reads an integer at that address.
3. It adds the previously obtained baseline to the integer just read.
4. It passes the resulting integer as the first argument to F-c67cb20988a1 and the original positive adjustment as the second argument.

The visible layout is therefore a caller slot containing an address-like value, followed by an integer field at the beginning of the addressed storage. No further fields or layout constraints are established.

The final addition is ordinary integer addition in the supplied representation. It is not visibly scaled by element size. Its interpretation as a byte address, offset, or other quantity depends on the undocumented callee interface.

The wrapper returns the status from F-a5bc00364bd0 after this helper returns. It does not convert the final helper’s result into a new status.
