# F-92e3b44ef325

## Purpose

F-92e3b44ef325 performs a two-phase update of a caller-supplied, word-addressed object, with an optional indirect call in each phase. On normal completion, it returns the same object address it received.

The established behavior is:

1. Replace the object's first 32-bit word with a first value obtained from global storage.
2. If the 32-bit pointer-valued field at byte offset 12 is non-null, invoke a target selected through that field's dispatch table.
3. Replace the object's first 32-bit word with a second value obtained from different global storage.
4. If the 32-bit pointer-valued field at byte offset 8 is non-null, invoke a target selected through that field's dispatch table.
5. Return the original object address.

The sequence resembles staged teardown involving two referenced objects and changing dispatch identity. That interpretation is inferred intent, not an established ownership or lifecycle contract. In particular, the visible behavior does not establish that either indirect call destroys, frees, or decrements a reference to anything.

## Behavior

### First phase

The function obtains a 32-bit value from the first global storage location and writes it to byte offset 0 of the input object.

This write precedes the examination of the pointer-valued field at offset 12. Consequently, even if that field is null, the first assignment still occurs.

The function next examines the offset-12 field.

- If it is null, the first indirect call is skipped.
- If it is non-null, dispatch proceeds through the referenced object's first word.

The dispatch chain consists of:

1. The non-null pointer-valued field.
2. A 32-bit table address read from the first word at that pointer.
3. A callable target read from byte offset 28 within that table.
4. An indirect invocation of that target.

Byte offset 28 is seven 32-bit word positions from the beginning of the table. This identifies a table location; it does not establish a complete table format or the number and meaning of other entries.

The recovered representation shows no explicit arguments attached to the indirect invocation. It therefore does not establish the full argument list, receiver placement, register state used as implicit input, or calling convention. In particular, the referenced object must not be specified as a proven receiver solely because the dispatch table is reached through it.

No result from this call is visibly assigned, tested, or returned.

### Transition between phases

After the first indirect call returns normally, or immediately if it was skipped, the function obtains a 32-bit value from the second global storage location and writes it to offset 0 of the input object.

This is a separate assignment after the first phase. The evidence does not show that both global values are captured at entry. An indirect target could therefore affect a later global-value read if it can modify the corresponding storage.

The second assignment is unconditional with respect to both pointer-valued fields. It occurs even if both are null, provided execution reaches this point.

There is no established requirement that the two global values differ. Their names, types beyond their visible 32-bit use, and semantic relationship are unknown.

### Second phase

After the second assignment, the function examines the pointer-valued field at offset 8.

- If it is null, the second indirect call is skipped.
- If it is non-null, the function follows the same dispatch-table shape used in the first phase: the referenced object's first word supplies a table address, and the target is selected at byte offset 28 within that table.

The second field is considered after the first call, not as a proven entry-time snapshot. If the first indirect target modifies the offset-8 field and returns normally, the second phase operates on the state present when it reaches that field.

As with the first dispatch, no explicit call arguments or use of a return value are established.

### Completion and ordering

The normal observable sequence is:

- First global-value read and first write to offset 0.
- Examination of the offset-12 field.
- First dispatch-table traversal and call, if enabled.
- Second global-value read and second write to offset 0.
- Examination of the offset-8 field.
- Second dispatch-table traversal and call, if enabled.
- Return of the original input address.

The two calls are not interchangeable. The offset-12 path precedes the offset-8 path, and the second global assignment separates them.
