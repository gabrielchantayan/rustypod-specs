## Acceptance examples

These are conditional static acceptance criteria, not execution results. Each assumes that relevant address calculations and accesses are supported by the environment and that no unmentioned external mutation intervenes.

### Selector width and scaling

A selector whose most significant byte is `0x00` yields scaled base `0`. A selector whose most significant byte is `0xFF` yields `1020`, not `255` or a negative value.

Changing only the lower 24 selector bits leaves the scaled base unchanged.

### Distinct base-cell reads

If the initial base-cell read yields one value and the later read yields another, the 32-bit store relative to the entry base contains the later value.

The following payload store still uses the initially captured base to locate its destination. Consolidating these observations would change behavior.

### Payload truncation

For captured payload `0x1234ABCD`, the initial 16-bit payload store has numeric value `0xABCD`.

Its byte ordering in memory remains dependent on the unresolved endianness.

### Genuine byte-store overlap

Suppose the scaled base is `20`, the data base is `16`, the entry byte is `7`, and the linked byte is `99`.

The first byte store writes `7` at address `45`, because `16 + 0x1D = 45`. The second writes `99` at the same address, because `20 + 0x19 = 45`.

Immediately after those two stores, that byte is `99`. This does not assert its value after later stores or dependency execution.

### Signed displacement

If the displacement halfword represents `−2`, the first final store targets object base minus `2`.

Its stored value is the low eight bits of object base. Interpreting the displacement as unsigned `65534` does not preserve the represented signed displacement.

### Four-byte final write

If the final byte is `255`, the last direct store writes the 32-bit numeric value `255` at object base plus `255`.

A one-byte write or a four-byte value of `0xFFFFFFFF` is not equivalent.

### Target-relative write and retained target

If the captured target has low 16 bits `0x5678`, the second final store writes the numeric halfword `0x5678` at the target-relative destination.

If a final store also changes the original target slot, invocation still selects the previously captured target.

### Late second argument and early third argument

If a final store changes the final-halfword source, argument three still carries the halfword captured before those stores.
