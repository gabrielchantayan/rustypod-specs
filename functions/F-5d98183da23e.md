# F-5d98183da23e

## Purpose

F-5d98183da23e performs ordered dispatch on an input object, using a context object that supplies callback addresses and a comparison value.

The function first attempts one of five specialized handlers. If no specialized handler applies, or the selected handler returns zero, it invokes a context-selected callback. If that callback also returns zero, a final callback may run when the input has a particular type and its payload matches a context field.

Every invoked handler or callback can terminate processing by returning a nonzero value. That value is returned unchanged. If processing reaches the end without a nonzero result, the function returns zero.

This describes dispatch and return-value propagation, not the domain meaning of the type values, selector values, or callbacks. Interpreting zero as “unhandled” and nonzero as “handled” is plausible intent, but the established behavior is only the branching on those values.

If that value is **0x15**, it invokes **F-d748e2b78ff6** with the context address and input address.

| 2 | 0x0D | 0x6E | F-0c4bae7d5241 |
| 3 | 0x0D | 0x59 | F-5f8d058d0659 |
| 4 | 0x0D | 0x5A | F-c5bdfcbc9451 |

Each selector-based check reads the input type anew. If that check sees type 0x0D, it invokes **F-468ee00d626a** with the input address and compares that invocation’s result against that position’s required selector.

If a check does not match, processing advances to the next check. Consequently:

- There may be up to four selector invocations.
- Selector results are not cached or reused between checks.
- A selector invocation occurs only when the type read for that particular check is 0x0D.
- A selector result is compared only against the selector assigned to its current position.
- Once a specialized handler is selected and invoked, the remaining specialized checks are skipped.

These repeated reads and invocations matter if a dependency changes the input or other state. This contract does not assume a stable selector result or an unchanged input.

A type observed during a later selector-based check does not restart dispatch. For example, if a selector call changes the input type to 0x15, subsequent selector-based checks do not invoke the 0x15 handler; that case was considered only at the beginning.

If a specialized handler returns nonzero, the function immediately returns that value.

If it returns zero, the function proceeds directly to fallback dispatch. It does not attempt any remaining specialized handlers.

If no specialized check matches, the function likewise proceeds to fallback dispatch.

### 2. Fallback callback selection

On entry to fallback dispatch, the function reads the input type again. This is a fresh read, including after a specialized handler returned zero.

If this type is **0x16**:

1. It reads the address-bearing word at input offset 8.
2. It reads the secondary discriminator at byte offset 4 from that address.
3. If the discriminator equals **0x2A**, it selects callback-table offset **0x10C**.
4. Otherwise, it selects callback-table offset **0x110**.

For every other fallback-stage type, it selects callback-table offset **0x110** without reading the input’s offset-8 field or a secondary discriminator for this selection.

After choosing the offset, the function reads the callback-table address from context offset 0, obtains the callback address at the selected table offset, and invokes that callback with the original context and input addresses.

If this callback returns nonzero, the function immediately returns that value.

If it returns zero, processing continues to the final conditional callback stage.

The callback table is obtained after the fallback discriminators have been read. There is no established cached table address from before specialized dispatch.

### 3. Final conditional callback

After the fallback callback returns zero, the function reads the input type again.

If this fresh type is not **0x0F**, the function returns zero without performing the final payload comparison.

If the type is 0x0F:

1. It reads the 32-bit value at input offset 8.
2. It reads the 32-bit value at context offset 0x50.
3. It compares those values for equality.

If they differ, the function returns zero.

If they are equal, the function obtains the callback-table address again from context offset 0, reads the callback address at table offset **0xE0**, and invokes that callback with the original context and input addresses.

A nonzero result from this callback is returned unchanged. A zero result leads to a zero return from F-5d98183da23e.

The final callback-table lookup is separate from the fallback lookup. If an earlier callback changes the context’s table address or a table entry, the later lookup is not specified to use the earlier value.
