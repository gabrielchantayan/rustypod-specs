# F-9d1ee3b6f380

## Purpose

F-9d1ee3b6f380 evaluates linked records using two external checks, a recursive traversal link, and a continuation link. It short-circuits on the first nonzero check result and returns a normalized 32-bit Boolean.

For each reached non-null record, the evaluation order is:

1. F-0496723df8b5.
2. F-99f93f555a97.
3. A recursive invocation of F-9d1ee3b6f380 through the field at byte offset +0x0C.
4. Continuation through the field at byte offset +0x08.

Each later operation occurs only if all preceding checks for that record return zero.

## Behavior

### Null handling

A zero starting record address immediately returns 0. This path performs no record-field read, external dependency call, or recursive invocation.

A zero continuation address ends the current invocation with 0. A recursive invocation given a zero address also returns 0 without accessing record fields.

### Ordered evaluation of a non-null record

For each non-null current record, the observable order established by the body is:

1. Read the 32-bit field at +0x38. Invoke F-0496723df8b5 with the unchanged search value and the value just read.
2. If that call returns zero, read the 32-bit field at +0x10. Invoke F-99f93f555a97 with the unchanged search value and this newly read value.
3. If the second call also returns zero, read the 32-bit field at +0x0C. Invoke F-9d1ee3b6f380 recursively with the unchanged search value and that address.
4. If the recursive invocation returns zero, read the 32-bit field at +0x08 and use its value as the next current-record address.

A nonzero result from either external dependency or the recursive invocation immediately produces 1 from the current invocation. The remaining operations for that record are skipped.

After adopting a continuation address, the function checks it against zero before accessing another record.

The +0x0C traversal is recursive. The +0x08 traversal repeats within the current invocation. A successful recursive result propagates outward as normalized success; continuation is not attempted at an enclosing record whose recursive invocation succeeds.

### Field reads are not a snapshot

Each field is read only when its corresponding operation is reached. The function does not capture all four fields before calling dependencies.

Consequently, assuming the relevant storage remains valid:

- A change to +0x10 during F-0496723df8b5 affects the subsequent argument passed to F-99f93f555a97.
- A change to +0x0C during either external call affects the recursive starting address.
- The recursive invocation finishes before the enclosing invocation reads +0x08.
- A change to the enclosing record’s +0x08 during recursion affects the eventual continuation address.

These statements specify read timing. They do not establish that any dependency actually makes such changes.

The current record address held by an invocation is not replaced merely because a dependency changes some external reference to that record. It changes when the invocation reads and adopts the continuation value. The validity and contents of storage at that address are separate concerns.

There is no established guarantee that dependencies preserve records, globals, or storage lifetime. If a dependency releases or invalidates storage required by a later read, no recovery path is visible in this function.

### Traversal order and repeated visits

For unchanged traversal links, a reached record’s external checks precede its recursive region, and that recursive region precedes its continuation.

The function maintains no visited-record set. The same record can be evaluated repeatedly when links converge or lead back to an earlier record. Calling the two links “child” and “sibling” is a possible interpretation, not an established record contract.

Short-circuiting can prevent traversal of existing links. A nonzero first external result suppresses the second external call, recursion, and continuation for that record. A nonzero second result suppresses recursion and continuation. A successful recursive search suppresses the enclosing continuation read.

These restrictions concern operations performed directly by the current invocation. They do not constrain memory accesses or calls performed internally by dependencies.

### Termination and abnormal execution

A sufficient condition for termination is all of the following:

- The reachable traversal structure is finite and acyclic.
- Its +0x08 and +0x0C traversal links remain unchanged throughout the invocation and its recursive work.
- Every reached read is valid when performed.
- Every invoked external dependency returns normally.
- Sufficient execution resources are available, including those needed for recursion.

Under these conditions, traversal either short-circuits with 1 or exhausts the reachable structure and returns 0.

Finiteness and acyclicity alone are insufficient when dependencies may mutate links. Even if every instantaneous structure remains finite and acyclic, mutations can continually direct execution toward a previously visited record. The function has no progress counter or history that would detect this.

Other nontermination or abnormal-execution possibilities include:

- A stable continuation cycle causing indefinite iteration when all checks return zero.
- A recursive cycle causing unbounded recursive descent.
- An external dependency that never returns.
- Invalid memory access or insufficient recursive execution resources.

No visible handling converts these situations into a defined failure return.

## Acceptance examples

These are conditional acceptance cases, not executed tests. Unless mutation is specified, assume unchanged traversal links, valid reached reads, normally returning dependencies, and sufficient execution resources.

### Null input

Given a starting record address of zero, the result is 0. Neither external dependency is called, and no record field is read.

### First external check succeeds

Given a non-null record whose +0x38 field contains value A, if F-0496723df8b5 returns nonzero for the search value and A, the result is 1.

The current invocation does not read that record’s +0x10, +0x0C, or +0x08 fields and does not call F-99f93f555a97.

### Second external check succeeds

If the first external call returns zero and the second returns nonzero, the result is 1.

The +0x38 read and first call precede the +0x10 read and second call. The current invocation does not read +0x0C or +0x08.

### An isolated record does not succeed

Given a record with null +0x0C and +0x08 fields, if both external calls return zero, the result is 0.

Its direct field-read order is +0x38, +0x10, +0x0C, then +0x08. The recursive invocation with a zero address completes before the continuation field is read.

### Recursive success suppresses continuation

If both external calls at a record return zero and its recursive search returns 1, the enclosing invocation returns 1 without reading that record’s +0x08 field.

Any record reachable only through that continuation is not evaluated by this invocation.

### Continuation follows recursive exhaustion

If both external calls and the recursive invocation return zero, the function reads +0x08 and adopts that address.

If it is zero, the invocation returns 0. Otherwise, evaluation begins at that record with its +0x38 field and first external check.

### Later reads observe mutations

If F-0496723df8b5 changes the current record’s +0x10 field and returns zero, F-99f93f555a97 receives the value present at the later read, provided the storage remains valid.

Similarly, if a recursive invocation changes its enclosing record’s +0x08 field and returns zero, continuation uses the value present after recursion finishes.

### Negative external result

If either reached external call returns a negative 32-bit integer, the function returns 1. The negative value is not propagated, and no separate error outcome is selected.

### Termination with fixed links

Given a finite acyclic reachable structure whose traversal links remain unchanged, valid reached reads, normally returning external calls, and sufficient resources, the invocation terminates. If every external result is zero, it returns 0 after exhausting the structure.

### Instantaneous acyclicity does not ensure termination

Consider two records, A and B, with null recursive links. Suppose all external results are zero. During processing of A, a dependency sets A’s continuation to B and clears B’s continuation. During processing of B, a dependency sets B’s continuation to A and clears A’s continuation.

Each mutation can clear the other record’s continuation before setting the current one, so the link structure remains acyclic throughout. Nevertheless, every reached continuation read directs execution to the other record. If this behavior continues and reads remain valid, traversal does not terminate.

This case does not satisfy the unchanged-traversal-links condition of the termination guarantee.
