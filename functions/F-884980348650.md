# F-884980348650

## Purpose

F-884980348650 selects between an immediate result, a prerequisite check, and one of two indirect operations on a supplied receiver.

Its decision depends on:

- A one-byte discriminator in a primary object.
- For discriminator value 2, a four-byte selector in global-associated storage.
- For every other discriminator value, the four-byte result of an indirect prerequisite operation obtained through F-b7af80e829ec.

The established behavior is dispatch and result propagation. The meanings of the discriminator, selector, prerequisite result, and receiver operations are unknown. In particular, a return value of 1 is not established to mean success, and a return value of 0 is not established to mean failure.

## Interface

### Inputs

The function has two inputs:

1. **Primary object address.** The supplied representation treats this input as a 32-bit integer used as a memory address. The function reads one byte at byte offset `0x2EC` from that address. No other part of this object is directly accessed.
2. **Receiver address.** This input points to storage whose first four bytes supply a dispatch-table address. On paths that dispatch an operation, the function selects a four-byte function-pointer entry from that table and invokes it with the receiver address as its sole explicit argument.

These descriptions follow the supplied 32-bit representation. The exact machine calling convention, pointer encoding, alignment requirements, and validity of converting arbitrary integer values into addresses are not independently established.

### Result

The result is four bytes wide and comes from exactly one of these sources:

- The constant 1.
- The constant 0.
- The four-byte result of a selected receiver operation, propagated without an explicit transformation.

The function does not normalize an indirect operation’s result to a Boolean. Its result type does not establish signedness or a semantic error domain.

### Path-dependent preconditions

Every invocation requires a readable discriminator byte.

Additional validity requirements depend on the chosen path:

- Discriminator 2 requires a readable global-associated selector.
- A receiver operation requires a readable receiver dispatch-table field, a readable selected function-pointer entry, and a callable target with a compatible calling convention.
- Any discriminator other than 2 requires F-b7af80e829ec to return a value that can be used to read the prerequisite dispatch-table field, followed by a readable and callable entry at `0x134`.

The receiver is neither dereferenced nor passed to a callee on immediate-return paths. Its validity is therefore not a demonstrated requirement for those paths.

## Behavior

### Initial discriminator read

The function first reads the byte at primary-object offset `0x2EC`.

Only equality with byte value 2 matters. Whether a source-level character type is signed does not change that comparison: all other byte values take the prerequisite path.

No global-selector read, helper call, or receiver-table access precedes this discriminator read in the supplied control flow.

### Discriminator equal to 2

The function reads the four-byte selector at offset `0x1C` in global-associated storage.

| Selector | Action |
|---:|---|
| 0 | Return 1 |
| 1 | Return 1 |
| 2 | Invoke the receiver operation selected at table offset `0x120` |
| 3 | Return 1 |
| 4 | Return 1 |
| Any other four-byte value | Invoke the receiver operation selected at table offset `0x110` |

For selectors 0, 1, 3, and 4, there is no receiver dispatch-table read and no indirect receiver invocation.

For selector 2, the function:

- Reads the dispatch-table address from the receiver’s first four bytes.
- Reads the function pointer at table offset `0x120`.
- Calls that target with the receiver address.
- Returns the target’s four-byte result.

For all remaining selector values, it performs the same sequence using table offset `0x110`.

F-b7af80e829ec is not invoked on any discriminator-2 path.

The selector classification is by exact values, not by an inferred signed range. For example, the four-byte pattern `0xFFFFFFFF` takes the default receiver operation regardless of whether another interface would interpret it as negative.

### Discriminator other than 2

The function invokes F-b7af80e829ec with no explicit arguments shown.

After that dependency returns, the function:

- Uses the returned address to read a dispatch-table address from offset `0x00`.
- Reads the function pointer at table offset `0x134`.
- Invokes that prerequisite operation with no explicit arguments shown.
- Tests its four-byte result against zero.

No explicit receiver argument is shown for this prerequisite invocation. A contract must not invent one from the table-based dispatch shape.

If the prerequisite result is nonzero, the function returns 0 immediately. The prerequisite result itself is not propagated. All nonzero four-byte results have the same effect.

If the prerequisite result is zero, the function invokes the receiver’s default operation at dispatch-table offset `0x110`, passing the receiver address, and returns that operation’s four-byte result.

The global-associated selector is not read on this path. A zero prerequisite result does not cause the selector to be consulted, and it never selects the alternate operation at `0x120`.

### Evaluation order and mutable state

The significant explicit sequencing is:

- The discriminator read precedes either the selector read or the helper invocation.
- On the non-2 path, F-b7af80e829ec completes before the returned object’s dispatch table is read.
- The prerequisite operation completes before the receiver’s dispatch table is read.
- The prerequisite result is checked before any receiver operation is selected on that path.
- Each receiver dispatch reads the receiver’s table address before reading the selected table entry.

Consequently, if either prerequisite dependency changes the receiver’s dispatch-table field, a subsequent default dispatch uses the field available after those calls. The function does not explicitly cache that field before invoking them.

The discriminator is read only once. A dependency changing its stored value does not cause this invocation to restart or enter the discriminator-2 branch.

Once a receiver-operation target has been selected, the function calls that target and returns its result. It performs no explicit post-call discriminator check, selector read, or receiver-table reread.

Address formation requires adding fixed offsets to the relevant bases. The function contains no explicit overflow or bounds checks for those additions. Portable wraparound behavior for an invalid or near-limit address is not established; valid addressed storage is a precondition for the applicable path.

## Acceptance examples

These are conditional contract examples derived from static evidence. They are not executed tests. Each assumes valid storage and normally returning callees for the accesses it requires.

1. **Immediate result for selector 0.**  
   With discriminator 2 and selector 0, the result is 1. Neither F-b7af80e829ec nor a receiver operation is called.

2. **Other immediate selectors.**  
   With discriminator 2 and selector 1, 3, or 4, the result is 1. The receiver’s dispatch-table field is not read.

3. **Alternate dispatch.**  
   With discriminator 2 and selector 2, only the receiver operation selected at `0x120` is invoked. If it returns `0x12345678`, the enclosing result is `0x12345678`.

4. **Default dispatch for an unlisted selector.**  
   With discriminator 2 and selector 5, the receiver operation selected at `0x110` is invoked. Neither the prerequisite operation nor the alternate receiver operation is invoked.

5. **Full-width selector classification.**  
   With discriminator 2 and selector pattern `0xFFFFFFFF`, the default receiver operation is selected. The selector is not treated as an error solely because of that pattern.

6. **Nonzero prerequisite suppresses receiver dispatch.**  
   With discriminator 0, if the prerequisite operation returns 7, the result is 0. The receiver’s dispatch-table field is not read.

7. **Any nonzero prerequisite has the same branch effect.**  
   With discriminator 255 and prerequisite result `0x80000000`, the result is 0. No sign-based distinction is made.

8. **Zero prerequisite enables default dispatch only.**  
   With discriminator 1 and prerequisite result zero, the receiver operation at `0x110` is invoked. Its result is returned unchanged. Even if the global-associated selector contains 2, that selector is not read and does not select `0x120`.

9. **Receiver-table mutation before dispatch.**  
   On a non-2 path, suppose a prerequisite dependency validly changes the receiver’s dispatch-table address and the prerequisite result is zero. The subsequent default operation is selected from the receiver’s table as read after those calls, not from an earlier snapshot.

10. **No discriminator re-evaluation.**  
    Suppose the discriminator initially differs from 2, and a prerequisite dependency changes it to 2 before returning zero. Execution still continues to the default receiver operation. It does not read the selector.

11. **Path-specific receiver validity.**  
    With discriminator 2 and selector 3, an unusable receiver address is not itself dereferenced by this function. With selector 2, the same address cannot satisfy the required receiver-dispatch preconditions.
