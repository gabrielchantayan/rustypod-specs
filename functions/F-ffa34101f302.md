# F-ffa34101f302

## Purpose

F-ffa34101f302 conditionally rebuilds an object’s bucket-based structure through a temporary structure, transfers nodes out of the existing buckets, exchanges selected object fields with temporary state, and invokes finalization and cleanup dependencies.

The decision to rebuild compares the object’s 32-bit field at offset `+0x18` with the result of F-0b31936eccf4 applied to the second input. Equality bypasses all directly visible mutation by this function. Inequality enters the transfer path.

**Inferred intent:** the bucket traversal, linked-node removal, and field exchanges are consistent with resizing or rehashing a container. The precise container type, key representation, allocation policy, and ownership rules are not established.

This contract describes the supplied static evidence. No runtime tests have been performed.

## Interface

### Inputs and result

The function accepts two inputs:

- **Object address:** an address represented by a 32-bit value in the supplied representation. The function reads and writes fields at fixed byte offsets from this address.
- **Request value:** an opaque 32-bit value passed to F-0b31936eccf4 during the initial decision.

The function has no explicit return value. Observable results consist of dependency calls, changes to object fields, changes to bucket and node memory, and any additional effects of the dependencies.

No null checks, bounds checks, allocation-failure checks, or explicit error returns are visible.

### Object layout accessed directly

| Byte offset | Width | Established access |
|---|---:|---|
| `+0x04` | 32 bits | Read after temporary initialization; used as an object-relative displacement in a dependency argument. |
| `+0x14` | 32 bits | Initially read as a bucket-array address; later exchanged with a temporary field. |
| `+0x18` | 32 bits | Read for the initial comparison and bucket-range endpoint; later passed by address to a dependency. |
| `+0x1c` | 32 bits | Read as the current bucket-slot address; advanced by four bytes after an empty bucket is observed; later exchanged with a temporary field. |
| `+0x20` | 32 bits | Decremented once per transferred node; later exchanged with a temporary field. |

The names “bucket-array address,” “current bucket-slot address,” and “count” describe uses visible here, not independently verified field declarations.

Each bucket slot is four bytes wide and contains either zero or a node address. A nonzero node address is used in three ways:

- The 32-bit word at the node address is read as a successor link.
- The 32-bit word 16 bytes before the node address is passed to a dependency.
- The 32-bit word 12 bytes before the node address is also passed to that dependency.

The supplied evidence does not establish the complete node allocation, the types of the two preceding words, or whether the link address is the beginning of an allocation.

### Temporary state

The rebuild path creates a local region consisting of a four-byte leading area followed by four consecutive 32-bit fields. Before initialization, the four fields receive, in increasing address order:

1. Zero.
2. The result of a second call to F-0b31936eccf4.
3. Zero.
4. Zero.

The leading four-byte area has no visible initialization before its address is passed to F-98edd7e2140f. Subsequent dependencies receive that same address.

The second invocation of F-0b31936eccf4 has **no explicit argument in the supplied representation**. It must not be specified as receiving the original request value or as necessarily returning the value used in the initial comparison.

## Behavior

### 1. Initial decision

The function first calls F-0b31936eccf4 with the request value. After that call returns, it reads the object field at `+0x18` and compares the two 32-bit values for equality.

If they are equal, the function returns without entering the rebuild path.

This is a narrow guarantee: the function itself performs no visible writes on that branch, but F-0b31936eccf4 has already run. Its effects on shared state, including any aliased object storage, are unknown.

### 2. Temporary initialization and traversal setup

On inequality, the function initializes the temporary fields in the order described above and calls F-98edd7e2140f with the address of the temporary region’s leading area.

Only after this initialization call does it read:

- The displacement at object offset `+0x04`.
- The bucket-array address at object offset `+0x14`.
- The value at object offset `+0x18` used to calculate the traversal endpoint.

The endpoint is the bucket-array address plus four times that `+0x18` value. It is calculated once for this traversal; the visible body does not recompute it after each dependency call.

The comparison field may therefore differ between its initial read and its use in endpoint calculation if an intervening dependency modifies it.

### 3. Bucket traversal

At the start of each outer iteration, the function reloads the current bucket-slot address from object offset `+0x1c` and compares it with the previously calculated endpoint.

- If they are equal, node traversal ends.
- Otherwise, the function processes the bucket slot at that address.

The stopping condition is equality, not an ordered bounds comparison. There is no visible check that the cursor starts within the bucket array or has not passed the endpoint.

For the selected bucket, the function repeatedly reads the slot’s 32-bit head value:

- A zero head ends processing of that bucket.
- A nonzero head starts one transfer sequence.

For a nonzero head, the visible sequence is:

1. Read the two 32-bit words at offsets `−0x10` and `−0x0c` from the observed node address.
2. Call F-58cc241cfb6b with four arguments:
   - The object address plus the cached displacement from `+0x04`.
   - A carried 32-bit value initially equal to the bucket-array address.
   - The word from node offset `−0x10`.
   - The word from node offset `−0x0c`.
3. Pass that dependency’s result, together with the temporary-region address, to F-d930d59892c3.
4. Reload the head address from the selected bucket slot.
5. Read the successor word at this newly loaded head address and write that successor into the bucket slot.
6. Read the object field at `+0x20`, subtract one, and write the result back.
7. Call F-e96639aeb0c2 with the temporary-region address, the node address removed in step 5, and the result of F-d930d59892c3.
8. Replace the carried value used as the second argument of F-58cc241cfb6b with an auxiliary register value exposed after this call sequence.
9. Re-read the selected bucket slot to decide whether another transfer is required.

The relative evaluation order of the two metadata-word reads is not established. Both values are supplied to F-58cc241cfb6b before that call proceeds.

A significant distinction is that the metadata is read using the head observed before the first two dependencies, while unlinking uses a fresh head read afterward. If either dependency changes that bucket slot, the node unlinked need not be the node whose metadata was inspected. The function contains no visible check for this situation.

After the bucket is observed empty, the function reads the object’s current `+0x1c` field, adds four, and writes it back. It does not necessarily advance from the cached bucket-slot address: an intervening dependency may have changed the object field.

### 4. Field exchanges

Once the outer traversal observes the endpoint, the function performs these operations in order:

1. Read the object field at `+0x14`.
2. Replace that object field with the first temporary 32-bit field.
3. Store the former object value into that temporary field.
4. Call F-f673c27f3127 with addresses of the second temporary field and object field `+0x18`.
5. Read the object field at `+0x1c`.
6. Replace that object field with the third temporary field.
7. Read the object field at `+0x20`.
8. Replace that object field with the fourth temporary field.
9. Store the former `+0x1c` and `+0x20` values into the third and fourth temporary fields, respectively.

The operation on `+0x18` is delegated rather than implemented as a visible exchange. F-f673c27f3127’s exact semantics are unknown.

The temporary fields used here are their values **at exchange time**, after traversal and dependency calls. They are not necessarily their initial zero or computed values.

### 5. Finalization

After the exchanges, the function calls:

1. F-92abe9aac9af with the object address.
2. F-a7a6c2777ab8 with the temporary-region address.

It then returns.

These calls occur even when the traversal transferred no nodes, provided the initial comparison selected the rebuild path and all earlier operations returned normally.

## Side effects

### Directly established effects

On the rebuild path, the function directly:

- Initializes local temporary fields.
- Replaces each processed bucket head with the successor read from the head reloaded after the preparatory dependency calls.
- Decrements `+0x20` once for each unlink-and-transfer sequence.
- Advances `+0x1c` by four after each observed-empty bucket.
- Exchanges the fields at `+0x14`, `+0x1c`, and `+0x20` with temporary fields.

It does not visibly clear or rewrite the removed node’s successor word before passing the node to F-e96639aeb0c2.

### Ownership and lifetime

The visible body does not directly allocate or release heap memory. Dependencies may do so, but their ownership contracts are unavailable.

In particular:

- Passing a node to F-e96639aeb0c2 does not independently prove adoption, copying, or release.
- Placing the former bucket-array address into temporary state before F-a7a6c2777ab8 suggests cleanup, but does not prove deallocation.
- The temporary region has local-call lifetime. Whether a dependency retains its address is unknown; safe retention is not established.
- Successful completion does not by itself establish preservation of all nodes or the final count. Those properties depend on the callees.

### Arithmetic and validity conditions

The visible representation uses four-byte words and four-byte bucket strides. Relevant arithmetic includes:

- Four times the `+0x18` field for endpoint construction.
- Object address plus the cached displacement.
- Bucket-cursor increment by four.
- Count decrement by one.
- Node-address subtraction by 16 and 12 bytes.

No overflow, underflow, or address-wrap checks are visible. Equality is unaffected by signed interpretation, but the supplied evidence is insufficient to assign portable behavior to overflowing address arithmetic.

For defined successful use, all accessed storage must be valid, suitably aligned for the target, and live for the required operations. The initial cursor and endpoint must support termination, and bucket links must permit progress. Cyclic links, unreachable endpoints, invalid metadata addresses, or dependency mutations that prevent progress can cause faults or nontermination; no recovery is shown.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests.

### Initial equality

If F-0b31936eccf4 returns the same 32-bit value subsequently read at `+0x18`, the function returns after that comparison. None of the rebuild-path dependencies are called, and this function performs no direct object writes.

This remains true if the field is zero. It does not imply that the initial dependency had no side effects.

### Rebuild with cursor already at endpoint

If the initial values differ and, after temporary initialization, the current cursor equals the calculated endpoint, no node metadata or bucket head is read by the traversal.

The function still performs the field exchanges, calls F-f673c27f3127, then calls F-92abe9aac9af and F-a7a6c2777ab8 in that order.

### Empty bucket before endpoint

If the cursor differs from the endpoint and its bucket head is zero, no node-transfer dependencies are called for that bucket. The function advances the object’s then-current cursor field by four and repeats the endpoint comparison.

### Single node with no interfering mutations

Assume a selected bucket contains one node whose successor is zero, the relevant dependencies return normally without changing that bucket or cursor, and all memory accesses are valid.

The function reads the node’s two preceding words, calls F-58cc241cfb6b and F-d930d59892c3, replaces the bucket head with zero, decrements `+0x20`, and calls F-e96639aeb0c2 with that node. It then observes the empty bucket and advances the cursor.

The count decrement is an intermediate observable write. The later field exchange and finalization may replace or change that value.

### Head changed by a preparatory dependency

Assume the initial head is one valid node, but a preparatory dependency replaces the bucket head with a different valid node before the unlinking read.

The metadata arguments correspond to the initial node. The unlinking operation and node argument to F-e96639aeb0c2 correspond to the replacement node. Acceptance must not require the function to detect or reconcile this difference.

If the replacement head is zero, the subsequent successor read is not guarded by a new zero check.
