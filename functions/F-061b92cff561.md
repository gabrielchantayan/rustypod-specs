# F-061b92cff561

## Purpose

F-061b92cff561 conditionally dispatches an operation through an object-associated indirect callable. It derives a small mode value from an object byte, invokes a prerequisite dependency, and, only when that dependency returns zero, performs a preparation call, the indirect operation, and a completion call.

The externally returned status is restricted to two established values on ordinary return:

- **0:** the prerequisite returned zero and the indirect operation returned zero.
- **3:** the prerequisite returned nonzero, or the indirect operation returned nonzero.

The indirect operation’s actual nonzero status is not propagated. The return value of the completion dependency does not affect the selected result.

These descriptions identify control-flow roles, not established domain meanings. In particular, the evidence does not establish that the preparation and completion calls acquire and release a resource, or that status 3 denotes any specific error category.

## Behavior

### 1. Derive a mode before calling dependencies

The function reads the byte at object offset `0x1398` and compares it with 2.

- If that read equals 2, the derived mode is 1, and the conditional second read is skipped.
- Otherwise, the function reads the same byte again.
  - If the second read equals 3, the derived mode is 2.
  - Otherwise, the derived mode is 0.

For storage that remains unchanged between these accesses, the mapping is:

| Stored byte | Derived mode |
|---|---|
| 2 | 1 |
| 3 | 2 |
| Any other byte value | 0 |

The intermediate mode has an established width of one byte. Its numeric values are limited to 0, 1, and 2. The exact calling-convention extension of this byte when passed to the indirect operation is not established; the semantic argument value is.

The distinction between one and two accesses matters when discussing the supplied static representation. For example, if the first read is not 2 but the second read is 3, the selected mode is 2. The evidence does not establish volatile storage, legal concurrent mutation, or a guarantee that compiled machine accesses preserve a particular concurrency-observable read count.

The mode is selected before any dependency call. Subsequent changes to the source byte by a dependency do not cause it to be recomputed.

### 2. Invoke the prerequisite

F-6b71c72d5449 receives the original object base as its sole visible argument.

Its result is tested against zero:

- **Nonzero:** return 3 immediately.
- **Zero:** continue to preparation and indirect dispatch.

On the nonzero branch, this function does not call F-f0216cff9365, the indirect callable, or F-2bb3dbfa7286.

The prerequisite may itself modify state. No preservation of the object, pointer fields, globals, or external resources can be assumed from the available evidence.

### 3. Invoke preparation

After a zero prerequisite result, the function reads the 32-bit field at object offset `0x1380` and supplies that value as the sole visible argument to F-f0216cff9365.

The field is read after the prerequisite returns. Consequently, a change made by F-6b71c72d5449 to this field can affect the preparation argument.

No result from F-f0216cff9365 is inspected. If this dependency returns normally, dispatch proceeds regardless of any value it may return.

### 4. Dispatch the indirect operation

After preparation returns, the function uses the field at object offset `0x107c` to select an indirect callable through the receiver’s table pointer and table offset `0x2c`.

The indirect operation receives four arguments, in this logical order:

1. The receiver obtained from object offset `0x107c`.
2. The original auxiliary 32-bit argument.
3. The previously derived mode, numerically 0, 1, or 2.
4. The address at object base plus `0x54`.

The table is selected through the object-associated receiver rather than through the original object base directly.

The receiver field appears separately in callable lookup and receiver-argument construction. The evidence does not establish the relative evaluation order of these component reads or a single atomic receiver snapshot. Under stable field contents, both uses refer to the same receiver. Behavior under mutation during expression evaluation is not a supported synchronization contract.

Preparation occurs before dispatch lookup and invocation. Therefore, changes made during preparation to the receiver field or reachable dispatch table can affect the selected callable.

The indirect result is tested against zero. Its precise nonzero value is not retained as an externally returned status.

### 5. Invoke completion and select the result

Following either a zero or nonzero indirect result, the function calls F-2bb3dbfa7286 with:

1. A newly read 32-bit value from object offset `0x1380`.
2. The address at object base plus `0x13a8`.

This completion call occurs exactly once on each dispatch path that reaches it normally. There is no additional completion call on the zero-result path.

The completion argument is not a saved copy of the preparation argument. The two values may differ if an intervening dependency changes the field. No equality, pairing, or resource-identity invariant is established.

After completion returns normally:

- A zero indirect result produces return value 0.
- A nonzero indirect result produces return value 3.

The completion dependency’s result is not tested. Its state changes do not cause the function to reconsider the already selected indirect-result branch.

- The function returns 0 after completion returns normally.
