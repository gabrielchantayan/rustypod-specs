# F-55b549ba70c6

## Purpose

F-55b549ba70c6 conditionally replaces a value in the last entry of an attached collection, then processes the nonzero input’s resources, accounting metadata, and allocator metadata.

The visible operation has three stages:

1. If an attachment exists, obtain a status and either issue a diagnostic or replace the selected entry’s value.
2. If the original input address is nonzero, process resource fields and update accounting.
3. Except for a particular adjusted-address sentinel, validate allocation metadata and perform allocator bookkeeping.

A returning diagnostic does not stop subsequent input processing. No rollback is visible.

The operation resembles replacement of a column default followed by input disposal. Those roles are inferred intent, not established ownership or release guarantees.

## Behavior

### Attachment selection

The attachment address is read before the input-null check. The fourth argument is then copied into the local word.

A zero attachment skips status evaluation and replacement. Otherwise, the entry-array address and count determine the selected location before any status call. Their relative read order is not established by the supplied expression.

The computed entry location is retained across subsequent dependencies. The attachment fields are not reread to choose another entry.

### Status and diagnostic

The local word is set to `2`. F-f59a6024d361 receives the original input address, fixed opaque data, and the local word’s address. Zero input is passed unchanged.

After that dependency returns:

- Status zero selects the diagnostic path.
- Any nonzero status selects replacement.
- Leaving the initialized value unchanged selects replacement.

On the diagnostic path, the selected entry’s word at offset `0x00` is read and passed to F-2022b0f73f3b together with the primary object and fixed diagnostic-format data.

This path makes no direct replacement write and no direct old-value call to F-841dc33ee157. That restriction describes this function’s explicit actions, not the diagnostic dependency’s possible effects.

If the diagnostic returns, execution proceeds to the original input-null check.

### Replacement

The replacement path performs these ordered actions:

1. Capture the context word at primary + `0x00`.
2. Read the selected entry’s value at offset `0x04` and pass it to F-841dc33ee157.
3. Call F-1a5398bcc6b3 with the captured context and original input.
4. Store the low 32 bits of its represented 64-bit result into selected entry + `0x04`.
5. If that low word is nonzero, call F-869c28ef7a31 with the captured context and replacement address + `0x1C`.

The captured context and selected location remain in use despite intervening dependency effects. The old-value call precedes construction.

A zero replacement is stored and suppresses F-869c28ef7a31. No restoration of the old value is visible. The high 32 bits of the construction result do not affect an observable argument or replacement write.

### Accounting

After resource processing, an early evaluation of the accounting-base global is retained for the eventual high-word destination. The displacement is then read, the adjusted address formed, and the quantity read at adjusted address minus `8`.

The subsequent accounting sequence is:

1. Evaluate the accounting-base global and read the low source word at base + `0x38`.
2. Evaluate it again and retain the high source address at base + `0x3C`.
3. Evaluate it again to select the low destination at base + `0x38`; write low source minus quantity.
4. Read the high source through the address retained in step 2.
5. Write the high result at the early captured base + `0x3C`.

Thus four separate global evaluations select the early high destination, low source, high source address, and low destination. Forming the high source address does not snapshot its value: that read occurs after the low write.

The low subtraction is reduced to 32 bits. The high subtraction removes both the unsigned low-word borrow and the quantity’s signed 32-bit arithmetic-right-shift result by 31 bits. That shift contributes zero for a nonnegative represented quantity and all one bits for a negative represented quantity.

If all four base evaluations select the same ordinary, nonoverlapping two-word counter, the combined effect is subtraction of the **sign-extended** 32-bit quantity modulo 64 bits. Low and high words occupy `0x38` and `0x3C`.

That interpretation is conditional. Different bases can combine unrelated sources and destinations. Even with stable bases, the two writes are not atomic.

F-2fd8826557a4 runs after both writes. After it returns, the allocator-state pointer is obtained through a separate global location and retained.

## Acceptance examples

These are conditional static consequences, not executed tests. They assume accessible storage, required lifetimes, and normal dependency returns unless specified otherwise.

1. **No attachment, zero input.** The attachment read occurs, and the fourth argument is copied locally. No dependency is called.

2. **Attachment, zero input.** Status evaluation receives zero input. Unchanged status `2` selects replacement, including construction with zero input. No later allocator-state overwrite occurs.

3. **Diagnostic continuation.** Status zero selects the diagnostic. If it returns and input is nonzero, resource processing follows.

4. **Replacement results.** A zero low result is stored and skips F-869c28ef7a31. A low result of `0x1000` is stored before that dependency receives replacement-relative address `0x101C`.

5. **Flag mutation.** If the first conditional resource call clears bit 0 at input + `0x18`, the later flag observation suppresses the second conditional call.

6. **Stable-counter borrow.** With stable accounting bases, low `3`, high `10`, and quantity `5` produce low `0xFFFFFFFE` and high `9`.

7. **Signed quantity.** Under the same condition, an initially zero counter and quantity `0xFFFFFFFF` produce low `1` and high `0`: subtraction of sign-extended negative one.

8. **Separate accounting locations.** Distinct source and destination bases need not update one coherent counter. If the high source address aliases the low destination, its later read observes the low write absent another intervening mutation.

9. **Sentinel skips local overwrite.** Adjusted address `8` still entails the quantity read at address zero, accounting writes, F-2fd8826557a4, and allocator-state lookup. It skips the allocator-state write into the status local, validation, and bookkeeping.

10. **Retained status address.** Suppose F-f59a6024d361 retains the supplied address, input is nonzero, and adjusted address is not `8`. After allocator lookup, that storage receives the allocator-state pointer before validation. A later dependency with access to the retained address could observe that value while the local is live; such access is not guaranteed.

11. **Overwrite before validation failure.** Under the same nonsentinel conditions, a zero first header read invokes F-a817d8d58c10 only after the local overwrite. A nonreturning validation failure does not undo that write.

12. **Validation rereads.** A nonzero first header read followed by an odd second read fails. A nonzero first read followed by zero passes the visible validation.

13. **Changing metadata.** If F-c0fc6d033caa changes the header to `0x15`, the first captured size is `0x14`; bit 0 is not revalidated. If the final masked observation is `0x28`, only the final size subtraction uses `0x28`. An earlier counter write can likewise affect the later second-index observation if storage aliases.
