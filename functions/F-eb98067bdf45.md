# F-eb98067bdf45

## Purpose

F-eb98067bdf45 conditionally discovers and invokes a callback associated with an input object. It initializes a caller-provided output word to zero and returns a 32-bit result: zero when no callback is invoked, or the callback’s result when an invocation returns normally.

Discovery is controlled by an object descriptor and an ordered sequence of reads of a distinguished global value. When that global remains stable and addition of 20 is well-defined, discovery is suppressed for descriptors equal to either the global value or that value plus 20. The complete decision also retains a comparison value between global reads; it is not generally equivalent to comparing against one snapshot.

The callback supplied as the third argument is never invoked directly. Invocation requires a non-null lookup result containing a non-null callback address in its first word. There is no fallback to the supplied callback.

Registry-based discovery of an optional operation is inferred intent. The domain meanings of the descriptor, distinguished global, lookup entry, and callback result are not established.

## Behavior

### Output initialization

The prospective return result is initialized to zero. The function then writes a 32-bit zero through the output reference.

This is the first explicit externally visible write. It precedes the descriptor read, all distinguished-global reads used by the decision, and all dependency calls.

The function does not later clear or restore the output. Changes made by dependencies or the callback can survive to the caller.

### Descriptor decision and retained comparison value

The descriptor is read once from byte offset 12 of the input object. That captured descriptor is used throughout the eligibility decision; the function does not reread the descriptor for each comparison.

After capturing the descriptor, the source establishes the following order:

| Order | Source-level action | Effect on the decision |
|---|---|---|
| 1 | Read the distinguished global. | Retain this value as the comparison value. |
| 2 | Read the distinguished global again. | Compare the captured descriptor with this second read. |
| 3, conditional | If the descriptor differs from the second read, read the global again and add 20. | Replace the retained comparison value with this read plus 20. If the descriptor equals the second read, this read and addition do not occur, and the initially retained value remains. |
| 4 | Read the distinguished global again for the final guard. | First compare the descriptor with this latest read. |
| 5, conditional | Only if the final guard finds them unequal, compare the descriptor with the retained comparison value. | Discovery occurs only if this comparison also finds them unequal. |

Thus, three source-level global reads occur when the adjustment is skipped, and four occur when it is taken. These counts concern the supplied source representation, not guaranteed physical memory loads.

The retained comparison value is not necessarily derived from the same global value used by either inequality against the global itself. In particular:

- Equality at the second read skips the adjustment; it does not by itself finish the entire eligibility decision.
- Equality at the final global read suppresses discovery and short-circuits the retained-value comparison.
- If the final global comparison is unequal, equality with the retained value also suppresses discovery.
- Discovery requires inequality with both the final global read and the retained value.

For a stable global and well-defined addition, this reduces to suppression when the descriptor equals the base or the base plus 20. That simplified rule is conditional, not a replacement for the ordered-read contract.

The addition is numerically 20, not scaling by an object or word size. It is expressed in a signed-integer-shaped representation. Overflow behavior at the signed boundary is unresolved. This contract does not select unsigned wraparound or unbounded arithmetic.

The source-level order does not establish atomicity, synchronization, a coherent snapshot, or defined behavior for concurrent modification.

### Lookup and callback selection

F-c79a29304dfd receives:

1. The token returned by F-17be7b6b79ad.
2. The fixed lookup name `tt_cmaps`.

Its result is treated as either null or a pointer to an entry containing a callback address in its first 32-bit word.

If the result is null:

- No entry word is read.
- No callback is invoked.
- The prospective return result remains zero.

If the result is non-null, its first word is read and used as the candidate callback address. No other entry field is directly read by this function.

A zero candidate address also suppresses invocation. The supplied callback argument is not used as a fallback in either case.

### Callback invocation and completion

A callback is invoked only when the lookup result and its first-word callback address are both non-null.

The callback receives the original input object reference followed by the original output reference. It does not receive an adjusted object address, the descriptor, token, lookup entry, or original callback argument as an additional explicit argument.

On normal callback return, its 32-bit result becomes the outer function’s result. No subsequent direct output write, result translation, or explicit resource release is shown.

There is no established relationship between the result and output contents. A callback may return zero after writing a nonzero output, or return nonzero while leaving the output unchanged.
