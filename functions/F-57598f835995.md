## Behavior

### Entry capture and dispatcher sampling

Global-read placement is part of the established behavior even though the values read are unavailable.

The first global read captures an arithmetic coefficient. That retained coefficient is reused throughout the invocation, including after calls to F-18a28d9bb6de. There is no visible refresh of this retained value.

A later entry-time global read obtains the initial dispatcher state. Thus the coefficient is captured before the initial dispatcher state is read; they are not a single atomic configuration snapshot.

Every dispatcher entry then performs these actions in the following established order:

1. Snapshots the current third working-area word.
2. Reads a fallback control word into temporary retained state.
3. Reads a live dispatch-origin word used with the current dispatcher state to select an operation.

The third-word snapshot precedes both global reads. The fallback sample precedes the dispatch-origin read. These actions occur again on each dispatcher entry, including entries following a dependency call.

Consequently:

- The arithmetic coefficient remains the entry-captured value.
- The initial dispatcher state is an entry-time value, not a continuously refreshed starting state.
- The fallback control sample is refreshed at every dispatcher entry.
- The dispatch-origin word is read live for every selection.
- Operation-specific global references are additional reads, not automatically uses of these retained samples.

The default dispatcher route performs arithmetic and selects another state. An unrecognized selection is not shown to return immediately or report an error.

### Fallback sampling versus rereading

Two arithmetic-selection operations specifically distinguish a dispatcher-entry fallback sample from a later read of the same global location.

One operation resets the separate address-like word and the first two working-area words, then computes a sign-bit-based selector. Its alternative target is obtained from a fresh read of the fallback global plus seven. A selector of zero chooses that alternative; a selector of one chooses the fallback value sampled at dispatcher entry.

Another arithmetic-selection operation derives a sign-bit selector from current working arithmetic. Its alternative target uses a fresh read of the same fallback global plus four. Again, zero chooses the freshly derived alternative and one chooses the earlier dispatcher-entry sample.

The fresh read occurs while computing the alternative even when the retained sample ultimately determines the next state. These operations do not justify replacing the earlier sample with the later value, or vice versa.

Other operation-specific selections also contain multiple reads of control globals. Unless a value is explicitly retained, separate references must not be collapsed into a single immutable value. Exact ordering between operands within an individual expression is not independently established by the supplied representation.

If setup has assigned the displacement four and no intervening effect changes it, this preparation places the source base four bytes above the destination base in 32-bit address arithmetic. That conditional relationship is not a global promise about every transfer.

A distinct comparison operation has an important read-before-write transition:

- The old third-word value has already been captured at dispatcher entry.
- The operation replaces the third working-area word with the fourth working-area word.
- Its unsigned comparison is between the fourth word and the captured old third word—not between the fourth word and the replacement third-word value.

When the fourth word is unsigned-less-than the captured third word, the true-side target contribution is selected. Otherwise, the false-side contribution is selected. Those contributions use separate reads of their control global; equality of the reads is not guaranteed by the evidence.

Replacing the third word does not visibly refresh the separately retained source base. The new third-word contents nevertheless affect later dispatcher snapshots and may be observable to subsequent dependency calls through the pointer to the working area. A later address-preparation operation can overwrite them again.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests.

1. **Retained coefficient across a call.** If the entry coefficient is captured as three, and F-18a28d9bb6de later changes that global location to nine, a subsequent second-output publication with first working word five uses the retained three and writes fifteen, provided no other relevant state changes occur.

2. **Fallback sample differs from reread.** Suppose a dispatcher entry samples fallback value one hundred. In the selective-reset operation, suppose the fresh fallback read is two hundred. A selector of one chooses one hundred; a selector of zero chooses two hundred seven. The read difference must not be erased by treating the global as constant.

3. **Other fallback alternative.** Under the same sample and reread values, the other fallback-based arithmetic selection chooses one hundred for selector one and two hundred four for selector zero.

4. **Comparison uses the old third word.** Suppose the dispatcher snapshots third-word value `0x2000`, and the fourth word is `0x1000`. The comparison operation writes `0x1000` into the third word but evaluates the unsigned comparison against the captured `0x2000`. The comparison is true, not an equality comparison against the replacement.

5. **Equality boundary.** If both the captured third word and current fourth word are `0x1000`, the unsigned-less-than comparison is false. The third word is still replaced.

6. **Selective reset preserves trailing words.** If the working area contains four nonzero words before selective reset, that operation clears its first two words but does not itself clear its third or fourth word.

7. **Address publication.** If the first-output publication executes with address-like word `0x12345678` and a valid destination, it writes that exact 32-bit value. Ownership does not follow from the store.

8. **Byte transfer.** If a transfer executes with valid source and destination addresses and the source byte is `0xA7`, the destination receives `0xA7`. That individual store does not write adjacent bytes.

9. **Unsigned wrapping.** In an unsigned 32-bit address calculation, adding four to `0xFFFFFFFE` yields `0x00000002`. This does not establish that the resulting address is valid.

10. **Unchanged return word.** If execution reaches return without updating the initialized return word, the result is zero. Zero is not thereby established as success.

11. **Null or aliased outputs.** A null pointer is acceptable only if the executed route avoids its store. If both outputs designate one word and both stores execute, the later applicable write determines its value absent intervening effects; their overall order is unresolved.
