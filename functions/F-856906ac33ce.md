# F-856906ac33ce

## Purpose

F-856906ac33ce obtains a wrapper, examines an attached record, conditionally updates an associated state object, and forwards the wrapper through a submission sequence. A non-null record also causes a second construction and a subsequent dependency call. A null record instead selects an indirect operation on the first wrapper.

“Wrapper,” “record,” “state,” and “submission” identify observable roles, not established application types. Queueing, synchronization, notification, and ownership transfer are inferred possibilities rather than guarantees.

The contract is based on static evidence. Its established behavior consists of memory-access order, branch conditions, direct writes, dependency calls, and indirect invocations. No runtime tests have been performed.

## Interface

**Input:** one 32-bit argument used as the address of an outer object.

**Output:** no explicit return value. Observable results are direct memory writes, calls, indirect invocations, and effects produced by those dependencies.

### Preconditions and failure boundaries

Normal completion requires valid storage and callable targets for every access and invocation reached on the selected path. The function performs no local validation of the outer pointer, state pointer, construction results, allocation result, dispatch tables, or payload pointer.

The first wrapper is dereferenced to obtain its attached record before the later wrapper-null check. That check therefore does not make a null first-construction result safe.

The eight-byte allocation is written without a preceding success check. No recoverable allocation-failure result is exposed.

Required alignment, byte order, address-overflow behavior, and concurrency rules are **documented_only**. The observed layout does not establish portable behavior for invalid addresses, overflowing address calculations, or misaligned storage.

## Behavior

### Initial construction and state acquisition

The initial ordering is:

1. F-0a77364c41cc is called with numeric size `12`.
2. After that call returns, the first descriptor is read from its external storage location.
3. F-afb630a7107c receives the preceding result, the descriptor value just read, and one zero argument.
4. Its result is treated as the first-wrapper pointer.
5. The state-object pointer is read from outer-object offset `+0x04`.
6. F-338d16f9ce72 receives the address of state offset `+0x10c`.
7. After that call returns, the attached-record pointer is read from wrapper offset `+0x08`.

The first descriptor read therefore follows the size-`12` dependency call and precedes both its construction invocation and the outer-object state-pointer read.

The descriptor is not established as a constant. F-0a77364c41cc may affect its external storage before it is read; preservation by that dependency is unknown. Effects of the construction dependency likewise precede acquisition of the state pointer.

The state pointer obtained here is retained for subsequent state-relative accesses. The function does not reload it from the outer object later.

### Null attached record

When the attached-record pointer is zero, the function checks whether the wrapper pointer is nonzero. If it is, the function reads the wrapper’s dispatch-table pointer and invokes the entry at byte offset `+0x04`, explicitly supplying the wrapper pointer.

Execution then proceeds to the terminal behavior below.

This path performs no direct mode, count, or payload update. It does not perform the eight-byte allocation, common submission sequence, second construction, or F-9a5c97dc580d call.

The indirect operation may serve a cleanup role. Destruction, deallocation, reference-count changes, and ownership consequences are not established.

### Dispatch selection for a non-null record

The function reads the signed 32-bit operation code from record offset `+0x04`.

It first reads the external comparison value and tests equality. Equality writes `1` to mode and bypasses all numeric-code cases.

If equality fails, the function separately accesses the comparison value for a signed less-than test:

- A true less-than result selects the lower partition.
- A false less-than result selects the remaining partition.

With a comparison value that remains stable across both accesses, these partitions are respectively “less than” and “greater than,” and equality has precedence over every specialized numeric case.

Without stability, the remaining partition is defined by failure of the second less-than test, not necessarily by strict greater-than against either observed comparison value. No single immutable threshold may be assumed.

Every normally completing non-null-record dispatch continues into common submission, whether or not its operation code receives specialized handling.

### Lower-partition operations

Only four numeric codes have specialized behavior in the lower partition.

| Operation code | Direct behavior |
|---|---|
| `0x6600000d` | Write count to `0`, then mode to `0` |
| `0x66000014` | Optionally initialize count, then increment it |
| `0x66000015` | Optionally initialize count, then conditionally decrement it |
| `0x66000017` | Write count to `0`, then mode to `0` |

Other lower-partition codes produce no direct write to mode, count, or payload.

For either count-adjustment code, the function first reads count and compares it with signed `-1`. Only that exact value triggers initialization:

- F-87be4aa684d1 is called.
- The returned object supplies a dispatch-table pointer.
- The table entry at byte offset `+0x16c` is invoked.
- Its four-byte result is stored in count.

No explicit arguments are shown for that indirect invocation. Its complete ABI is unknown.

For `0x66000014`, count is read after the initialization decision and any initialization store. One is added, and the result is stored in count. There is no visible upper-bound check. An initialization result of `-1` is not queried again; ordinary, nonoverflowing arithmetic would produce `0`.

For `0x66000015`, count is read for a signed-positive test. If positive, it is read again, reduced by one, and stored. If zero or negative at the test, the adjustment produces no store. An initialization result of `-1` is not retried.

The separate positivity-test and subtraction reads are relevant if storage can change between accesses. No atomic read-modify-write behavior is established.

Initialization and adjustment are distinct stores when both occur. For example, an initialization result of `7` on the increment path produces a store of `7` followed by a store of `8`.

The increment operates on a 32-bit signed field. Behavior beyond the representable signed range is not established as a portable contract; wrapping must not be assumed.

### Remaining-partition operations

Only three numeric codes have specialized behavior in the remaining partition.

| Operation code | Direct behavior |
|---|---|
| `0x6600001a` | Write mode to `0` |
| `0x6600001b` | Resolve a decision value and conditionally exchange `1` and `2` |
| `0x66000024` | Copy four bytes through the record’s payload pointer into payload |

Other codes in this partition produce no direct write to the three state fields.

For `0x6600001b`, mode is read first. If it is not `-1`, that value supplies the decision. If it is `-1`, F-87be4aa684d1 is called and the returned object’s dispatch-table entry at byte offset `+0x18c` is invoked. Its signed 32-bit result supplies the decision.

A decision of `1` writes mode to `2`. A decision of `2` writes mode to `1`. Every other decision produces no direct mode write.

The queried value is not unconditionally stored. If mode begins at `-1` and the query returns `0`, this function performs no mode store on that branch. This does not imply that the dependencies themselves leave mode unchanged.

For `0x66000024`, the function reads the pointer at record offset `+0x0c`, reads four bytes through that pointer, and writes those bits to state offset `+0x148`. It copies the pointed-to value, not the pointer. No length, address, or overlap validation is performed.

### Terminal behavior

Both principal paths reach the same terminal sequence:

- Read the pointer at state offset `+0x10c`.
- If null, return without the terminal indirect invocation.
- Otherwise, read the four-byte value at that pointer.
- If that value is zero, return without the invocation.
- Otherwise, invoke a target obtained through external storage and return if that invocation returns normally.

The state-field pointer is read after all earlier calls on the selected path. It is not the entry-time contents of that field.

The pointed-to value is a gate for the call, not the established call target. The target comes from separate external storage. No explicit arguments are shown, and its calling convention and effects remain unknown.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, assume valid storage, normally returning dependencies, stable comparison storage, and no intervening mutations affecting the example.

1. **First descriptor read timing.** If the first F-0a77364c41cc call changes first-descriptor storage before returning, the subsequent construction receives the value read after that return. The outer-object state pointer is read only after this construction returns.

2. **Second descriptor is independently obtained.** If first-descriptor storage contains one value and second-descriptor storage contains another at their respective read times, the constructions receive those respective values. A change to second-descriptor storage during the second F-0a77364c41cc call is visible to the later descriptor read.

3. **Equality overrides numeric specialization.** If the operation code and comparison value are both `0x66000014`, mode is written to `1`; the count-increment branch is not selected. Common submission follows.

4. **Ordered reset.** Code `0x6600000d` in the lower partition writes count to `0` before writing mode to `0`.

5. **Initialization followed by increment.** Code `0x66000014` in the lower partition, starting count `-1`, and query result `7` produce count stores of `7` and then `8`.

6. **Decrement boundary.** Code `0x66000015` in the lower partition with count `0` causes no query and no direct count store. If count instead starts at `-1` and initialization returns `-2`, `-2` is stored and no decrement follows.

7. **Mode query is not unconditional initialization.** Code `0x6600001b` in the remaining partition, mode `-1`, and query result `0` produce no direct mode write. A query result of `2` instead produces a mode write of `1`.

8. **Payload copies bits.** Code `0x66000024` in the remaining partition copies the four bytes referenced by the record’s payload pointer into state `+0x148`.

9. **Wrong partition suppresses specialization.** Code `0x66000024` in the lower partition does not copy payload. It still reaches common submission and second construction.

10. **Null record bypasses submission.** A valid non-null wrapper with a null attached record reaches its indirect entry at `+0x04` and then terminal behavior, without the eight-byte allocation or second descriptor read.

11. **Terminal gate is fresh.** If earlier dependencies leave state `+0x10c` pointing to a four-byte zero, the terminal target is not invoked. If the pointer and pointed-to value are both nonzero, invocation is attempted.
