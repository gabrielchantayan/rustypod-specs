# F-44af36bb90d9

## Purpose

F-44af36bb90d9 coordinates an ordered sequence of dependency calls around a supplied object, a signed selector, and a control value. It obtains a 32-bit token, prepares two local storage regions, queries an associated object, and selects one of two processing paths. Both paths end with the same ordered finalization calls when execution completes normally.

The contract establishes argument values, access ordering, branch conditions, and normal-path lifecycle. It does not establish application-level meaning. “Token,” “association,” “processing,” and “notification” are descriptive terms, not evidence of ownership or business semantics.

This specification rests on static evidence only. No runtime tests have been performed.

## Behavior

### Initial token acquisition

Token acquisition occurs before either local storage region is passed to its setup dependency.

If the selector equals −1:

- Call F-938c950e5046.
- Read the dispatch-table pointer from its returned object.
- Select and invoke the entry at table byte offset 0x168.
- Save the returned 32-bit word as the token.

Otherwise:

- Read the supplied object’s dispatch-table pointer.
- Select and invoke the entry at table byte offset 0x12c, explicitly passing the supplied object.
- Save the returned 32-bit word as the token.

The service-object dispatch at offset 0x168 has no explicit arguments in the supplied representation. Whether the actual ABI supplies an implicit receiver is unresolved.

Every later call to F-50afc298d6d3 receives this saved token. The function does not reacquire the token before that call. Saving the token here means preserving its value within this invocation; it does not imply retaining a reference or acquiring ownership.

### Common setup and query

After token acquisition, the following events occur in order:

1. F-1c06d0a5910b receives the address of the 20-byte local region and two zero arguments.
2. After that call returns, the globally named pointer expression is evaluated.
3. A 32-bit word is read through the resulting pointer and saved for possible use on the zero-predicate path.
4. F-f1a0113c72f4 receives the address of the four-byte local region and the supplied object.
5. F-e38e6836b640 receives the address of the four-byte region and returns an associated-object pointer.
6. The associated object’s dispatch-table pointer is read, and its entry at table byte offset 0x1f4 is invoked with the associated object and the address of the 20-byte region as explicit arguments.
7. F-7d1048432426 receives the address of the 20-byte region.

The last call’s signed integer result selects the branch: zero selects the first path below; every nonzero value selects the second.

The global-derived capture has two distinct semantic steps: obtaining the pointer value and reading its pointee word. Both occur after F-1c06d0a5910b and before F-f1a0113c72f4. The evidence does not establish a fixed pointee address.

Consequently:

- A change to the pointer before its evaluation can change which address supplies the captured word.
- A change to the selected pointee before the read can change the captured word.
- After the capture, changes to either the pointer or its pointee do not replace the saved word.
- Only the captured word is subsequently reused by this function; the pointer itself is not visibly retained for another read.

No dependency is assumed to preserve the pointer, its pointee, or any other global state.

### Zero-predicate path

If F-7d1048432426 returns zero:

1. Call F-e38e6836b640 again with the address of the four-byte local region.
2. Read the 32-bit word at byte offset 0x40 from this second returned pointer.
3. Call F-a73566bce62e with these four arguments, in order:
   - The saved word captured through the globally named pointer.
   - The original selector.
   - The word read at offset 0x40 from the second associated-object result.
   - The original control value.
4. Save the signed integer result of F-a73566bce62e.
5. Call F-7b5e4937c518 with the supplied object.
6. If the saved processing result is nonzero, call F-50afc298d6d3 with the saved token.
7. If the original control value is nonzero, call F-8d2a99b5c349 with the supplied object.

The second association lookup is required. Its result need not identify the same object as the first lookup. The field read at offset 0x40 uses the second result, not the earlier dispatch receiver.

F-7b5e4937c518 runs regardless of whether F-a73566bce62e returns zero. The notification condition uses the saved processing result despite the intervening call.

The control condition is independent of the processing result. A zero processing result suppresses F-50afc298d6d3 but does not suppress F-8d2a99b5c349 when the control value is nonzero. If both conditional calls occur, F-50afc298d6d3 precedes F-8d2a99b5c349.

### Nonzero-predicate path

2. Read the returned object’s dispatch-table pointer.
3. Invoke the entry at table byte offset 0xe4, with no explicit arguments shown.

The common setup still evaluates the globally named pointer and reads its pointee before the predicate is known, even though that captured word is not used by the branch-specific calls here.

When the selector is −1, this path includes two separate calls to F-938c950e5046. Their results are not assumed to identify the same object. The initial dispatch supplies the saved token; the later dispatch supplies the first argument to F-8f9bd59e3ec5.

## Side effects

### Direct accesses and call-mediated effects

The function visibly:

- Reads object dispatch-table pointers and the entries needed for indirect calls.
- Evaluates a globally named pointer and reads one 32-bit pointee word during common setup.
- Conditionally reads a 32-bit field at associated-object offset 0x40.
- Saves values and exposes local storage addresses to dependencies.
- Invokes the ordered operations described above.

It contains no explicit store to the supplied object, the associated objects, the globally named pointer, or that pointer’s pointee. This is not a preservation guarantee. Called dependencies and indirect targets may modify those locations or other state.

Changes to the global pointer and changes to its pointee are distinct possible effects. The function neither visibly refreshes the pointer nor rereads its pointee after the capture.

The visible call sequence does not establish whether these regions hold owning objects, references, handles, or other data. Allocation, reference acquisition, resource release, and ownership transfer inside dependencies remain unknown.

Likewise, no ownership policy is established for the supplied object, service objects, associated-object pointers, saved token, or captured word. The function itself has no visible allocation or deallocation operation beyond whatever its dependencies may perform.

### Preconditions and errors

- The global-derived pointer must support the common setup’s four-byte pointee read on both branches.
- The first associated object must support the dispatch-table access.

No explicit retry, error return, exception handler, or recovery path is shown. Predicate zero is a branch selection, not an established failure. Processing result zero suppresses one notification call, not subsequent normal completion.

6. **Pointer redirection before capture.** Suppose F-1c06d0a5910b changes the globally named pointer from address A to address B. If its subsequent evaluation yields B and the word read there is 23, processing receives 23. The function does not require a read from A.

9. **Invalid common capture prevents normal continuation.** If the pointer evaluated during setup does not permit the required read, normal continuation is not established—even if the eventual predicate would have selected the branch that does not use the captured value.
