# F-654ac210bb5a

## Purpose

F-654ac210bb5a conditionally OR-composites a packed bit image into a destination byte buffer. The image dimensions come from an object-associated descriptor; the destination layout comes from a separate object-associated record. The caller supplies the source byte range and placement coordinates.

The operation only sets destination bits. It does not clear existing bits, replace a rectangular region, allocate a destination, or return a new image.

The established behavior includes a significant boundary detail: a leading fragment at a non-byte-aligned horizontal coordinate is masked into the **low-order bits** of its destination byte. When that fragment fills the remainder of the byte, this agrees with the apparent placement intent. When the image width is smaller than that remainder, the placement differs from a conventional rectangular bit blit. That behavior is part of this contract, not corrected by an inferred interpretation.

## Interface

### Inputs

Five arguments are visible:

1. **Object address.** Identifies an object containing a readiness flag and pointers to destination and image metadata.
2. **Source start.** Address of the first packed source byte.
3. **Source limit.** Address used as the upper bound for the source range. The length check treats it as an exclusive limit.
4. **Horizontal coordinate.** A 32-bit unsigned argument whose sign bit is nevertheless tested through signed interpretation.
5. **Vertical coordinate.** A signed 32-bit argument.

The supplied representation uses 8-bit bytes and 32-bit integer and address-sized fields. Address arithmetic and conversions have target-specific limitations discussed under **Uncertainties**.

## Behavior

### 1. Readiness gate

The readiness byte is read first.

- If it is nonzero, the dependency is skipped.
- If it is zero, F-926016a18a4a is called with the object address.
- If that call returns nonzero, the function immediately returns that value.
- If it returns zero, processing continues.

The flag is not rechecked after the dependency returns. Its mutation, or lack of mutation, does not independently determine whether processing continues.

The dependency executes before destination metadata and image dimensions are loaded. Consequently, processing uses the metadata subsequently observed, not a snapshot taken before the call.

### 2. Metadata acquisition

After the gate permits processing, the visible acquisition order is:

1. Read the destination-layout record pointer.
2. Read the row-stride field.
3. Read the image width through the descriptor pointer.
4. Read the image height through the descriptor pointer.

The descriptor pointer is accessed separately for the width and height expressions. The function does not establish a single atomic descriptor snapshot.

The destination extents are then consulted as the validation conditions are reached. The destination buffer address is used only after all local validation conditions pass.

### 3. Validation

The checks are short-circuited in this order:

1. The horizontal coordinate must have a nonnegative signed 32-bit interpretation.
2. The horizontal coordinate plus image width, interpreted as a signed 32-bit result, must not exceed the destination horizontal extent.
3. The vertical coordinate must be nonnegative.
4. The vertical coordinate plus image height, interpreted as a signed 32-bit result, must not exceed the destination vertical extent.
5. Advancing the source start by the required byte count must produce an address no greater than the source limit.

The required source byte count is:

\[
\left\lceil \frac{\text{width}\times\text{height}}{8}\right\rceil.
\]

The product is at most 65,025 bits, so this count is at most 8,129 bytes. The width-height product and its rounding addition do not approach a 32-bit arithmetic limit.

Equality at the source limit is accepted. Extra source bytes are allowed and ignored.

A local validation failure returns 3 before directly reading source bytes or accessing destination buffer bytes. Metadata reads and the readiness dependency, where applicable, have already occurred.

These are the checks actually present, not a strengthened mathematical rectangle test. In particular, the coordinate sums are not protected against signed-range crossing. A large nonnegative coordinate can produce a negative signed interpretation of the sum and thereby pass an extent comparison. Safe callers must keep coordinate sums and address calculations representable.

### 4. Destination addressing and row traversal

After validation, the initial destination byte address is formed from:

- the destination buffer address;
- the vertical coordinate multiplied by the byte stride;
- the horizontal coordinate divided by eight.

Rows are processed in increasing image-row order. Each subsequent row begins one signed byte stride after the preceding row’s start. Negative or zero strides are not explicitly rejected.

Within each row, destination bytes are visited in increasing address order.

The horizontal coordinate’s low three bits determine whether a leading fragment is processed. Thereafter, complete eight-bit groups are processed, followed by a trailing fragment if necessary.

### 5. Packed source interpretation

The source represents a continuous sequence of packed image bits, with the high-order bit of a byte preceding its lower-order bits.

There is **no source-row padding**. When a row ends partway through a source byte, the unused bits carry into the next row. A new source byte is consumed only when the current operation needs more bits than remain buffered.

Two pieces of internal state persist across row boundaries:

- an unused-bit count, initially zero and maintained within 0 through 7;
- a 32-bit carrier holding the previously fetched source byte shifted left by eight bits.

The carrier is not reset at a new row. Under stable, nonoverlapping source storage, the total number of distinct source bytes consumed is exactly the rounded byte count checked during validation.

Unused low-order bits in the final source byte do not contribute to destination writes.

### 6. Destination updates

Every destination update has the form “existing byte OR contribution.” The existing destination byte is read and then written, even if the contribution is zero. Existing set bits remain set.

The following rules specify the contributions without assuming conventional image-placement behavior.

Let the horizontal bit offset be the horizontal coordinate modulo eight.

**Leading fragment.** If that offset is nonzero, the leading fragment contains the smaller of:

- the image width;
- eight minus the horizontal bit offset.

The next fragment’s worth of packed source bits is taken, fetching a source byte only when the buffered count is insufficient. Those bits are placed in the **low-order fragment-width bits** of the first destination byte. All other bits receive a zero contribution.

For a fragment that fills the remainder of the byte, this is consistent with the horizontal offset. For a narrower fragment, no extra shift moves it to the positions conventionally associated with that offset.

After this fragment, the destination position advances by one byte.

**Complete groups.** Each remaining complete group of eight source bits contributes a full destination byte. If the unused-bit count is nonzero, that group combines retained bits from the preceding source byte with bits from the next source byte. The unused-bit count remains unchanged.

For each complete group, the current source byte is visibly read twice: once to form the output combination, and once to update the carrier. Both reads precede that group’s destination write. Ordinary immutable source storage makes the reads equivalent; changing or special-access storage need not.

**Trailing fragment.** A final group of one through seven bits contributes to the **high-order bits** of the final destination byte. The lower destination bits receive a zero contribution. A source byte is fetched only if the buffered bits are insufficient.

These rules apply continuously across rows.

### 7. Empty dimensions

An image height of zero executes no row operations and returns 0 after successful validation. Metadata acquisition and destination-start address calculation still occur.

An image width of zero requires zero source bytes. Its destination behavior depends on horizontal alignment:

- At a byte-aligned horizontal coordinate, no destination byte is accessed.
- At a non-byte-aligned horizontal coordinate, each row still performs a leading-fragment read-modify-write with a zero contribution.

The latter case preserves destination values but still reads and writes one destination byte per row. It requires valid writable destination storage despite consuming no source data.

## Acceptance examples

These examples are conditional static predictions, not results of runtime tests. Unless stated otherwise, assume valid ordinary memory, stable source bytes, adequate destination extents, representable arithmetic, and a readiness gate that permits processing.

### Byte-aligned complete byte

For width 8, height 1, horizontal coordinate 0, source byte `0xA5`, and initial destination byte `0x10`:

- one source byte is consumed;
- the destination contribution is `0xA5`;
- the final destination byte is `0xB5`;
- the return value is 0.

### Byte-aligned short fragment

For width 3, height 1, horizontal coordinate 0, source byte `0xA0`, and a zero destination byte:

- the source’s first three bits contribute to the destination’s three high-order positions;
- the destination becomes `0xA0`;
- the low five destination bits are preserved.

### Continuous packing across rows

For width 3, height 2, horizontal coordinate 0, source byte `0xAC`, and two initially zero destination rows:

- the first row receives the first three source bits and becomes `0xA0`;
- the second row receives the next three source bits and becomes `0x60`;
- only one source byte is consumed.

A source format that pads each three-bit row to a byte boundary would not produce this behavior.

### Nonaligned fragment filling the byte remainder

For horizontal coordinate 3, width 5, height 1, source byte `0xA8`, and a zero destination byte:

- the first five source bits are `10101`;
- they contribute to the low five destination positions;
- the destination becomes `0x15`.

### Narrow nonaligned fragment

For horizontal coordinate 1, width 2, height 1, source byte `0xC0`, and a zero destination byte:

- the two source bits contribute to the low two positions;
- the destination becomes `0x03`, not `0x60`.

This distinguishes the established leading-fragment rule from a conventional coordinate-aligned blit.

### Insufficient source range

For width 9 and height 1, two source bytes are required. If the source limit is only one byte after the source start, the function returns 3 without directly reading source bytes or touching destination buffer bytes.

### Zero width with unaligned placement

For width 0, height 2, and horizontal coordinate 1:

- zero source bytes are required or consumed;
- each addressed destination-row byte is read and rewritten unchanged;
- the return value is 0 if validation and memory access succeed.

### Dependency rejection

If the readiness byte is zero and F-926016a18a4a returns a nonzero value, that value is returned immediately. No subsequent destination metadata acquisition or direct image processing occurs.
