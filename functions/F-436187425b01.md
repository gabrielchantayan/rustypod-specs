# F-436187425b01

## Purpose

F-436187425b01 conditionally transforms an eight-byte field within a caller-supplied object and replaces that field in place.

The established behavior is:

- If both 32-bit words of the field are observed as zero, write a 64-bit zero to the field without calling a dependency.
- Otherwise, construct a four-argument call to F-7071f254f784 using a decremented two-word quantity and a sign-extended 32-bit value read elsewhere in the object.
- Increment the dependency’s 64-bit result, multiply it by the saved signed 32-bit value, and store the resulting 64-bit value over the original field.

An inferred purpose is rounding a quantity to a multiple of another quantity. That interpretation depends on the arithmetic implemented by F-7071f254f784 and is not an established contract. In particular, this specification does not identify that dependency as signed division, unsigned division, or any particular rounding operation.

## Behavior

### Initial observation and branch selection

The function first reads the 32-bit word at `0x98` and saves that value.

It then reads the word at `0x9C`. The nonzero path is selected if either:

- This observation of the word at `0x9C` is nonzero; or
- The previously saved word from `0x98` is nonzero.

Zero testing is insensitive to whether a nonzero bit pattern is interpreted as signed or unsigned.

These are separate memory observations, not an established atomic read of a 64-bit quantity. If the object changes between observations, branch selection can reflect values that did not coexist as one stable eight-byte field.

### Zero path

When both tested words are zero:

- The word at `0xC0` is not read by this function.
- F-7071f254f784 is not called.
- A 64-bit zero is written at `0x98`.

There is no early return before the write. Consequently, even an already-zero field receives an explicit replacement store.

### Nonzero path: saved multiplier

On the nonzero path, the function reads the signed 32-bit word at `0xC0` and saves it.

This saved value serves two purposes:

1. It supplies the dependency’s third argument and determines its fourth argument.
2. It supplies the multiplier used after the dependency returns.

There is no visible reread of `0xC0` after the call. A change to that location during the dependency call therefore does not replace the saved multiplier used by the caller.

### Nonzero path: dependency arguments

The function reads `0x9C` again while preparing the dependency call. This later observation supplies the high-word arithmetic; the earlier observation supplied the branch decision.

F-7071f254f784 receives four arguments, in these positional roles:

| Position | Argument construction |
|---|---|
| First | Saved word from `0x98`, minus one |
| Second | Later word from `0x9C`, minus one, plus one if the saved word from `0x98` was nonzero |
| Third | Saved signed 32-bit value from `0xC0` |
| Fourth | Saved value from `0xC0` shifted right by 31 positions |

The second argument’s conditional increment depends on the saved low word, not on another read of `0x98`.

Under 32-bit wrapping arithmetic, the first two arguments form the low and high words of a 64-bit value decremented by one:

- A nonzero low word is decremented without changing the high word.
- A zero low word becomes all ones, and the high word is decremented.

Under the arithmetic-right-shift interpretation represented by the supplied source, the fourth argument is zero for a nonnegative multiplier and all ones for a negative multiplier. Together, the third and fourth arguments therefore have the shape of a sign-extended 32-bit value supplied as two words.

The decrement interpretation depends on width and overflow rules discussed under **Uncertainties**. It must not be used to silently assign an otherwise unknown arithmetic contract to the dependency.

### Nonzero path: result transformation

If F-7071f254f784 returns normally, its result is held as a 64-bit value. The function then:

- Adds one to that result.
- Multiplies the incremented result by the saved multiplier, converted to signed 64-bit form.
- Writes the resulting 64-bit value at `0x98`.

For values whose arithmetic is representable, the replacement is:

\[
(\text{dependency result} + 1)\times\text{saved signed multiplier}.
\]

There is no visible clamp, saturation, range check, or alternative result for exceptional inputs.

The final write replaces both original words. It does not preserve either word independently.

## Side effects

For the zero path, the visible order is:

1. Read the word at `0x98`.
2. Read the word at `0x9C`.
3. Write a 64-bit zero at `0x98`.

For the nonzero path, the visible order is:

1. Read and save the word at `0x98`.
2. Read the word at `0x9C` for branch selection.
3. Read and save the word at `0xC0`.
4. Read the word at `0x9C` again for argument construction.
5. Call F-7071f254f784.
6. If the call and subsequent arithmetic complete, write the transformed 64-bit result at `0x98`.
