# F-1d6c3229f8ff

## Purpose

F-1d6c3229f8ff selects and invokes operations on an embedded receiver according to a pointer obtained from shared state.

- A null pointer or an initially zero first byte selects a receiver-only operation through method-table offset 12.
- A nonnull pointer with an initially nonzero first byte selects a helper call followed by a receiver operation through method-table offset 8.
- If the offset-8 operation returns nonzero, the function then reads a separate global indirect-target reference and invokes the target with that result and the captured pointer.

The established contract is the selection, read ordering, argument construction, and conditional dispatch described below. An interpretation such as “clear or assign a string” is inferred intent only. Neither string semantics nor the effects of the indirect operations are established.

The function exposes no explicit return value.

## Interface

### Explicit input

The function accepts one address-bearing argument identifying an enclosing object. The embedded receiver begins 164 bytes from that address.

Both receiver-table operations receive the embedded receiver’s address, not the enclosing object’s base. This receiver address is calculated from the original argument and remains the receiver address used by this invocation.

The supplied representation expresses the argument as an integer. It supports an address-bearing interpretation but does not independently establish a portable pointer interface or a complete ABI.

### Shared input

A shared anchor supplies the base of another structure. The function reads the candidate pointer from the field at byte offset 4 from that base.

The pointer is captured once. The function does not reload this field after calling dependencies. If the captured pointer is nonnull, it reads one unsigned byte at that address to choose the branch.

A separate global reference supplies the final indirect target. This reference is read only after the offset-8 receiver operation returns a nonzero result. It is not read on either receiver-only path or when the offset-8 operation returns zero.

### Widths and arithmetic

The initial candidate-byte read is unsigned and 8 bits wide. Any value from 1 through 255 selects the nonzero-byte branch.

The helper result, calculated request, and offset-8 operation result are represented as integer-sized values. The supplied integer forms and layout are consistent with a 32-bit environment. They do not independently establish the ABI, address width, or argument-extension rules.

The request is formed by adding one to the helper result. No range check is visible. For a signed 32-bit interpretation:

- A helper result of negative one gives a request of zero.

## Behavior

### Initial selection

The function calculates the embedded receiver address, obtains the shared anchor’s base, and captures the candidate pointer from offset 4.

If the candidate pointer is null, the function does not read through it and selects the receiver-only branch.

Otherwise, it reads the candidate’s first byte as an unsigned value:

- Zero selects the receiver-only branch.
- Nonzero selects the helper and offset-8 branch.

This observation concerns only the first byte at the time of that read. It establishes neither the extent of the pointed-to memory nor any termination rule, encoding, or stability during subsequent dependency calls.

### Receiver-only branch

For a null candidate or an initially zero first byte, the function:

1. Reads the method-table address from the embedded receiver.
2. Reads the target at method-table byte offset 12.
3. Invokes that target with the embedded receiver address as its sole explicit argument.

The function does not call F-5cb57bbb2e0e, invoke the offset-8 operation, or read the separate final-target reference on this branch.

Any result from the offset-12 operation is unused. On ordinary return from that operation, the function completes.

The source does not establish whether this operation clears, resets, releases, or otherwise changes the receiver.

### Helper and offset-8 operation

For a nonnull candidate whose initially observed first byte is nonzero, the function calls F-5cb57bbb2e0e with the captured candidate pointer.

After the helper returns, the function forms the request by adding one to its integer-sized result. It then obtains the receiver’s current method-table address and resolves the target at byte offset 8.

The offset-8 operation receives, in order:

1. The embedded receiver address.
2. The calculated request.
3. Integer zero.

The method-table lookup occurs after the helper returns. The helper cannot be assumed to preserve the receiver’s method-table field or the table contents. Substituting a target cached before the helper call therefore requires an external invariant establishing equivalence.

The function does not reject zero or negative requests locally. The meaning and valid range of the request are unresolved dependency requirements.

### Offset-8 result and final-target read

The offset-8 operation’s integer-sized result is compared with zero.

If it is zero, the function completes immediately:

- No final-target reference is read.
- No final target is invoked.
- No receiver-only fallback occurs.
- No explicit error is returned.

If the result is nonzero, the function **reads the separate global indirect-target reference after the offset-8 operation has returned**, then invokes the target obtained from that read with:

1. The nonzero result from the offset-8 operation.
2. The previously captured candidate pointer.

The nonzero condition is not a positivity test. A negative result under a signed interpretation also reaches the final dispatch.

Neither F-5cb57bbb2e0e nor the offset-8 operation may be assumed to preserve the global final-target reference. Resolving or caching that target before either call is not an equivalent implementation without an external invariant proving that the earlier resolution selects the same effective target.

There is no visible null check or other validation of the final target after it is read. The nonzero check applies to the offset-8 result, not to the target reference.

The final operation’s result is unused. On ordinary completion of that operation, this function completes.

### Captured pointer and changing state

The function does not reload the shared candidate-pointer field or recheck the first byte before final dispatch. Changes made by dependencies do not cause branch selection to restart.

Thus:

- Replacing the shared candidate pointer does not replace the pointer argument already captured.
- Changing the candidate’s first byte does not reverse the selected branch.
- Changing the receiver’s method table during the helper can affect the subsequent offset-8 dispatch.
- Changing the global final-target reference during either preceding dependency can affect the final dispatch, because its read occurs afterward.

The captured pointer value is retained; continued validity of the memory it identifies is not established.

### Observable access order

The relevant ordering on the nonzero-byte path is:

1. Obtain the shared anchor’s base and read the candidate-pointer field.
2. Read the first candidate byte.
3. Call F-5cb57bbb2e0e.
4. Read the receiver’s method-table address and its offset-8 target.
5. Invoke the offset-8 target and receive its result.
6. If the result is nonzero, read the separate global final-target reference.
7. Invoke the target read in step 6.

A zero result stops the sequence before step 6. The receiver-only branch instead performs the offset-12 table lookup and invocation after initial selection.

No synchronization, lifetime acquisition, or snapshot mechanism is visible. These ordered accesses do not establish race safety or atomic consistency across the shared locations.

## Acceptance examples

These are conditional predictions from static evidence, not executed tests. Unless stated otherwise, they assume valid accessed addresses, compatible targets, ordinary dependency returns, and representable arithmetic.

### Null candidate

With a null candidate-pointer field:

- No candidate byte is read.
- The offset-12 target receives the embedded receiver.
- The helper and offset-8 operation are not invoked.
- The global final-target reference is not read.

### Initially zero byte

With a nonnull candidate whose first byte is zero, the function reads that byte and selects the offset-12 operation. Later candidate bytes do not affect this branch decision.

### Nonzero byte and nonzero result

Suppose the first byte is 128, the helper returns 7, and the offset-8 operation returns 25.

The helper receives the captured pointer. The offset-8 target receives the embedded receiver, request 8, and zero. After that operation returns 25, the function reads the global final-target reference and invokes the selected target with 25 and the captured pointer.

This example establishes no byte-copy count or resulting memory contents.

### Zero result suppresses the target read

Suppose the initial byte is nonzero and the offset-8 operation returns zero.

The function completes without reading the global final-target reference. Even if that reference is unusable, this path does not access it. This does not excuse invalid accesses earlier in the path.

### Final target changes during dependencies

Suppose the helper changes the global final-target reference, and the offset-8 operation subsequently changes it again before returning nonzero.

If the reference then remains stable through the final read, the function uses the value present after the offset-8 operation, not either earlier value. An implementation that cached the target before these calls would not satisfy this ordering without an additional preservation invariant.

### Candidate selection changes

Suppose the helper replaces the shared candidate-pointer field with a different pointer.

The final operation, if reached, still receives the originally captured pointer. Continued validity of that original memory is an unresolved dependency obligation.

### Receiver dispatch changes

Suppose the helper replaces the receiver’s method-table address and returns normally.

The offset-8 dispatch uses the method-table address read after the helper call. It does not use a table captured before the helper.

### Boundary results

If the helper returns negative one, a signed interpretation yields request zero. The offset-8 operation is still invoked.

If the offset-8 result is negative but nonzero, the final-target reference is read and the result is forwarded unchanged.

If the helper returns the maximum signed 32-bit value, the subsequent request is **documented_only** because the addition’s overflow behavior is unresolved.
