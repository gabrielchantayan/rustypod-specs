# F-307749a82038

## Purpose

F-307749a82038 conditionally processes an input object, collection members, and writable coordinate records. A mode byte chooses between:

- Traversing the input object’s collection and then processing eligible members against generated coordinate records.
- Selecting a positional member from an associated object’s collection, updating that member’s association, and conditionally processing it against generated coordinate records.

Both modes use temporary accumulator storage and explicit finalization calls.

“Rectangle,” “member record,” “accumulator,” “translation,” and “association” describe apparent roles. They do not establish application semantics, dependency algorithms, or ownership.

## Behavior

### Entry reads and gates

The function first captures the global anchor value, reads and masks the input flags, and reads the mode byte.

Processing requires the masked flags to equal `0x0800`. Masked values `0`, `0x1000`, and `0x1800` return before setup. Other flag bits do not affect this gate.

In nonzero mode, after passing the flag gate, the function reloads the global anchor and reads its `0x04` slot. A zero slot causes immediate return. The reloaded anchor itself is not null-checked.

This reload does not replace the entry-captured anchor. Later nonzero-mode accesses use the captured address:

- Initial iterator construction follows its then-current `0x04` slot to an object’s `0xA8` field.
- Selected-member rectangle generation rereads its `0x04` slot.

Consequently, the gate and later operations can observe different associated objects. Replacing the global anchor does not redirect accesses through the captured address. Mutating that captured anchor’s slot can redirect them. Later slot dereferences have no corresponding null check.

### Common setup

1. F-a4c26c2b4842 with temporary accumulator storage.

### Rectangle pointer identities and conversion

Both modes apply the following rules.

The rectangle advance receives the address of an output-pointer slot. Immediately after each advance, the function copies that slot’s value into a separate saved pointer, before testing the advance result. Successful advancement and a nonnull output pointer are required to enter the body.

F-d7be9cfb4000 is then called four times:

1. Left through the output-pointer slot, paired with the input’s current `0xC8` field.
2. Right through the saved pointer, paired with a fresh `0xC8` read; one is subtracted from the return.
3. Top through the saved pointer, paired with the current `0xC4` field.
4. Bottom through the saved pointer, paired with a fresh `0xC4` read; one is subtracted from the return.

Each coordinate is read when preparing its respective call. Earlier calls can change coordinate memory before later reads. The conversion arguments likewise are not a single snapshot.

The output-pointer slot has escaped by address to the advance dependency. Preservation of its contents by later dependencies is not established. A changed slot can diverge from the saved pointer, which retains the originally captured address. No new null check protects subsequent accesses after such a change.

The conversion results are stored temporarily, but the shown body does not subsequently consume them as values. The calls themselves may have effects and are not behaviorally removable on that basis.

### Rectangle expansion

Expansion accesses coordinates through the output-pointer slot, not through the saved pointer:

1. Call F-90fdfddd003d with the input.
2. Store left plus that return minus the current margin.
3. Store top plus the current vertical displacement minus the current margin.
4. Call F-90fdfddd003d again.
5. Store right plus that return plus the current margin.
6. Store bottom plus the current vertical displacement plus the current margin.

These are four ordered, non-atomic coordinate stores. Coordinates are read for the updates rather than restored from conversion inputs. Margin is read separately for each update; vertical displacement is read separately for top and bottom. The second displacement call occurs after the first two stores and need not return the same value as the first.

Changes to the escaped output-pointer slot can affect the destination of subsequent accesses. The representation does not establish an evaluation order among independent operand reads within an individual update expression.

### Nonzero mode: positional selection

## Acceptance examples

These are conditional static scenarios, not executed tests.

1. **Flag rejection:** masked flags `0x1800` cause return after anchor capture and mode read, without accumulator setup.

2. **Distinct anchors:** if entry captures anchor A but the nonzero-mode gate reload observes B, B’s nonzero slot permits setup. Initial collection access still follows A’s current slot.

3. **Changed associated object:** if A’s slot changes from X to Y before selected-member rectangle generation, generation receives Y, assuming execution reaches that call.

4. **Endpoint mutation:** if the first coordinate conversion changes the saved rectangle’s right word, the second conversion receives the changed word rather than an entry snapshot.

5. **Pointer divergence:** if the first conversion changes the escaped output-pointer slot from valid rectangle R to valid rectangle S, subsequent conversions still read right, top, and bottom from R. Expansion uses S unless another change intervenes.

6. **Expansion arithmetic:** with stable fields and pointer, coordinates `(10, 20, 30, 40)`, margin `2`, vertical displacement `5`, and displacement returns `7` then `9` become `(15, 23, 41, 47)`.

7. **Record-extent boundary:** a dependency contract for F-69f22b9cce64 is not rejected merely for lacking an exactly-four-word output. It must instead support the reached caller reads and downstream dependency requirements. Those full requirements are unresolved; neither the rectangle copy nor the separate 16-byte result buffer supplies them.

8. **Negative eligibility:** an inner-enumeration byte `0xFF` skips per-rectangle member processing. It does not govern the earlier initial traversal.

9. **Selection and clearing:** with stable ordinal `2`, the third successful yield is selected, but traversal continues. If its subsequent association lookup returns zero, zero is stored at `0x2C`, and selected-member rectangle generation is skipped.

10. **Predicate polarity:** zero from F-ddca41e891a8 enables F-826b12ce4466; any nonzero value suppresses that call. Dependency changes to the selected-mode output pair remain available to later translations.
