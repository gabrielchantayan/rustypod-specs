# F-22d5d80d8e4d

## Purpose

F-22d5d80d8e4d conditionally updates a caller-supplied record and dispatches further processing according to a dependency result, a byte in an indirectly selected object, and a 16-bit discriminator.

The established outcomes are:

- If the consumed signed 16-bit preliminary result is nonzero, return that value sign-extended to 32 bits without performing this function’s later flag checks or record update.
- If the consumed signed 16-bit preliminary result is zero and the selected object’s byte at offset `0x0C` has bit `0x80` clear, return zero.
- If the consumed signed 16-bit preliminary result is zero and that bit is set, set the high eight bits of the record’s initial 16-bit field, then perform the conditional dispatch described below.

A preliminary result of zero is a branch condition, not established evidence of success. The meanings of the dependency results, record fields, object flag, and discriminator are unknown.

“Preliminary,” “specialized,” and “fallback” identify positions in this function’s control flow. They do not establish validation, error handling, cleanup, or other domain semantics.

The function returns a signed 32-bit integer in the supplied representation. Both result-producing dependency calls have their results consumed as signed 16-bit quantities. Those consumed values, rather than any unspecified wider dependency result, determine the propagated return value.

## Behavior

### Preliminary lookup and call

The function first resolves the selected object through the record field at offset `0x154`, then calls F-437f1518621b with the selected 32-bit value.

It consumes the result as a signed 16-bit quantity.

If that consumed result is nonzero, the function immediately returns its sign-extended 32-bit value. On this path, this function does not directly:

- Read the selected object’s byte at offset `0x0C`.
- Read or write the initial flags field.
- Read the discriminator.
- Traverse the specialized payload chain.
- Call F-f74a051f9415 or F-df2603d65e78.

These exclusions describe this function’s own operations. They do not restrict accesses or side effects inside F-437f1518621b.

### Selected object flag

If the consumed preliminary result is zero, the function reads one byte at offset `0x0C` from the retained selected object address.

If bit `0x80` is clear, it returns zero. Other bits do not affect this decision: bytes `0x00` and `0x7F` select the return path; bytes `0x80` and `0xFF` permit continuation.

The selected object address is retained across the preliminary call. The function does not repeat the lookup through record offset `0x154` before this byte read. Consequently, changing that lookup field during F-437f1518621b does not redirect this read.

The byte itself is read after the dependency returns. A change to the retained object’s contents can therefore affect the branch. No assumption is made that the dependency preserves the object or its lifetime.

### Flags update and high-byte condition

When the object byte has bit `0x80` set, the function reads the initial 16-bit flags field and writes back a value with every bit selected by `0xFF00` set.

For the value read by this update:

- Bits `0` through `7` are preserved.
- Bits `8` through `15` become one.
- The direct write covers the initial 16-bit field, not a wider field.

The update is a read-modify-write operation. Atomicity, synchronization, and protection from concurrent modification are not established.

After the write, the supplied representation evaluates whether the flags field masked by `0xFF00` is nonzero.

With ordinary stable memory, the preceding write makes this condition true. The represented false branch nevertheless returns zero without either later dependency call. Its presence does not establish a supported way to alter the field between the update and this condition.

### Discriminator-based dispatch

If the high-byte condition is true, the function compares the 16-bit discriminator at record offset `0x002` with `0x482B`.

If the first comparison does not match:

- F-df2603d65e78 is called with no explicit arguments.
- Its result, if any, is not used.
- If the call returns normally, this function returns zero.

If the first comparison matches, the supplied representation evaluates the same discriminator comparison again.

If the second comparison also matches:

- The specialized payload chain beginning at record offset `0x158` is traversed.
- Its final 32-bit payload is passed to F-f74a051f9415.
- That dependency’s result is consumed as signed 16 bits and returned after sign extension to 32 bits.

If the first comparison matches but the second does not, the function returns `33`. Neither later dependency is called on that branch.

No explicit write or dependency call appears between the two discriminator comparisons. Under ordinary stable-memory conditions they have the same outcome. The represented branch to `33` does not prove that two distinct physical reads occur or that concurrent mutation is supported.

### Completion and abnormal control flow

There is no direct restoration of the flags field after either later dependency call.

In particular, a negative or other nonzero consumed result from F-f74a051f9415 is returned after the flags update has occurred. This function shows no rollback based on that result.

Descriptions of operations after a dependency call assume normal return from that dependency. Exceptions, nonlocal transfers, termination, and other abnormal control flow are not specified by the supplied evidence.

## Side effects

The sole direct memory write shown is the 16-bit flags update at record offset zero. It is reached only when:

- F-437f1518621b returns a consumed signed 16-bit value of zero; and
- The subsequent byte read from the retained selected object has bit `0x80` set.

Even when all high-byte bits are already set, the supplied representation still contains the update. This is a source-level access description, not a guarantee about the number of physical memory transactions.

The significant access and call ordering is:

1. Resolve the selected object.
2. Call F-437f1518621b.
3. If its consumed result is zero, read the retained object’s flag byte.
4. If the tested bit is set, update the record flags and evaluate the high-byte condition.
5. If that condition is true, evaluate the discriminator-based dispatch.
6. Only if both discriminator comparisons match, resolve the specialized payload and call F-f74a051f9415.

Thus, the selected object address is captured before preliminary processing, while the specialized payload chain is resolved afterward.

No independence among the record, selected object, and pointer-chain storage is established. Aliasing may affect later accesses. For example, the flags write precedes the specialized lookup and can affect that lookup if its storage overlaps the written field under an otherwise valid memory arrangement.

No allocation, deallocation, reference-count adjustment, ownership transfer, or resource release is directly shown. The dependency calls may perform such operations; their ownership behavior is unknown.

The final contents of the record are not guaranteed solely by the direct flags write. Either later dependency may change accessible state, and the function does not restore it afterward.
