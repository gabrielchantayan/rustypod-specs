# F-406131d78552

## Purpose

F-406131d78552 conditionally updates a signed 32-bit field in a caller-provided state object and returns a 32-bit status of 0 or 1.

The initial mode byte selects one of two behaviors:

- **Adjustment:** invoke F-385944bb3b6e and, unless its result is exactly 1, perform a direction-dependent check and possible change of one.
- **Replacement:** copy a direction-selected value from an associated object into the state, evaluate a rejection condition, and clear a separate state field only when that condition does not reject the replacement.

The status is not a reliable indication that memory changed. Some paths write the position and then return 0. Conversely, a dependency result of exactly 1 leads to return 1 without further local processing of the position.

“Position,” “direction,” “lower,” “upper,” and “replacement” are descriptive labels for the observed operations. Their application-level meanings are inferred intent, not established semantics.

## Behavior

### Initial selection and dependency gate

The first local access reads the mode byte at state offset 0x32.

A nonzero initial mode selects replacement. That path does not invoke F-385944bb3b6e.

A zero initial mode invokes F-385944bb3b6e once, passing the original state address. After a normal dependency return:

- A result of exactly 1 bypasses all remaining local adjustment work and leads to return 1.
- Any other result continues to adjustment, beginning with a direction-byte read.

The dependency result is compared with 1, not tested for general truthiness. Results such as 0, 2, and −1 all permit adjustment.

Adjustment uses memory as it exists after the dependency returns. There is no established guarantee that the dependency preserves the state, associated object, addresses, globals, or object lifetimes.

The initial mode decision is not repeated. If the dependency changes the mode byte to nonzero and returns a value other than 1, execution still continues with adjustment rather than replacement.

### Adjustment with zero direction

This path first compares the signed position with the signed lower value at associated offset 0x38.

- If the position is less than or equal to the lower value, return 0 without a local position write.
- Otherwise, read the position again, subtract one, write the result to state offset 0x08, and return 1.

The comparison therefore precedes the decrement write. Equality with the lower value rejects the operation.

The comparison and decrement use distinct position reads in the supplied representation. With stable memory, both reads observe the same value. No agreement between them is established under external mutation.

The exact ordering of the position read relative to the associated-address read and lower-value read within the preliminary comparison is not established.

This path does not consult the upper value and does not explicitly clear offset 0x18.

Under stable memory and representable arithmetic, a position one greater than the lower value is accepted and becomes equal to that lower value.

### Adjustment with nonzero direction

This path reads the position, adds one, and writes the computed value to state offset 0x08 before obtaining the associated address and upper comparison value.

The computed incremented value is then compared with the signed upper value at associated offset 0x3c:

- If the incremented value is greater than the upper value, return 0.
- Otherwise, return 1.

Equality with the upper value is accepted. The comparison uses the incremented value retained from the calculation, not a reread of the position.

A rejecting comparison does not undo the position write. This path does not consult the lower value or explicitly clear offset 0x18.

The associated-address lookup occurs after the position write. The write cannot itself overwrite that address field because their state storage regions are distinct.

### Replacement: common ordering

Replacement first reads and retains the associated address from state offset 0x04, then reads the direction byte.

The selected replacement and relevant comparison field are:

| Direction | Replacement source | Rejection condition |
|---|---|---|
| Zero | Associated offset 0x44 | Replacement equals the value at associated offset 0x38 |
| Nonzero | Associated offset 0x40 | Replacement is greater than the signed value at associated offset 0x3c |

Both branches have these ordering constraints:

1. Read the selected 32-bit replacement through the retained associated address.
2. Write that value to state offset 0x08.
3. Read the relevant comparison field through the same retained address.
4. Evaluate rejection using the replacement obtained before the position write.
5. On rejection, return 0 without clearing state offset 0x18.
6. Otherwise, write a four-byte zero to state offset 0x18 and return 1.

The replacement write remains in place on both accepted and rejected paths. There is no rollback and no position reread for the comparison.

### Replacement with zero direction

Rejection depends only on equality with the lower comparison value.

This is not a lower-bound range check. A replacement below the lower value is accepted if unequal. A replacement above it is also accepted if unequal.

Equality returns 0 after the position has already been written. Inequality clears offset 0x18 and returns 1.

### Replacement with nonzero direction

Rejection uses signed ordering against the upper comparison value.

A replacement greater than the upper value returns 0 after the position write. A replacement equal to or less than the upper value is accepted, clears offset 0x18, and returns 1.

### Aliasing and retained values

Associated fields may share storage with state fields if the address arrangement permits valid accesses. That possibility matters where the position is written before a comparison field is read.

With stable memory:

- If the upper comparison field aliases the position during nonzero-direction adjustment, the comparison reads the incremented value just written. Equality is accepted.
- If the lower comparison field aliases the position during zero-direction replacement, the comparison reads the replacement just written. Equality causes rejection.
- If the upper comparison field aliases the position during nonzero-direction replacement, the comparison reads the replacement just written. Equality is accepted.

Replacement retains the associated address across the position write and does not obtain it again before reading the comparison field.

Aliasing does not create additional write destinations. All direct associated-object accesses are reads. An associated field changes locally only if its storage also occupies an explicit state write destination.

In particular, aliasing cannot independently modify state offset 0x18 when its clearing write is omitted. The other explicit local write targets offset 0x08, a separate storage region.

### Widths and arithmetic

Signed ordering and position arithmetic use 32-bit values, with the representable range −2,147,483,648 through 2,147,483,647. Values with the high bit set are negative in signed comparisons.

Replacement transfers all 32 bits of the selected value. Zero-direction replacement uses equality; nonzero-direction replacement uses signed ordering.

The clearing operation writes zero across all four bytes at state offset 0x18.

The supplied representation does not establish runtime behavior for signed arithmetic overflow. Incrementing 2,147,483,647 therefore has no specified wrapped result, saturation behavior, completed write, or return value in this contract.

Under stable memory, zero-direction adjustment cannot reach a decrement of −2,147,483,648: acceptance requires the position to exceed a representable signed lower value. That argument does not resolve behavior if external mutation changes the position before its second read.

The function does not validate that the lower value is less than or equal to the upper value. No branch checks a proposed position against both comparison values.
