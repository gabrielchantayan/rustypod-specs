# F-87a6e9da35b1

## Purpose

F-87a6e9da35b1 performs one of three operations against a caller-supplied context:

- For a zero request value, it visits a dynamically bounded sequence of entry indices, excluding index 1.
- For a nonzero request without qualifying descriptor flags, it first attempts an existing-entry lookup, then falls back to resource acquisition and registration.
- For a nonzero request with qualifying descriptor flags, it obtains an entry index and an updated acquisition value through a descriptor-dependent helper, then acquires and registers a resource using metadata from that entry.

An initial dependency can suppress all three operations.

These are descriptions of the established control flow. Terms such as “entry,” “resource,” and “registration” describe apparent roles, not independently established application semantics. The function returns no result and does not explicitly report failures.

## Interface

### Inputs

The function accepts four arguments:

1. **Context reference.** An address from which the function immediately reads one 32-bit value, subsequently used as an object address. Several dependencies receive the original context reference rather than this captured object address.
2. **Request value.** A signed 32-bit value. Zero selects the entry-iteration path. Every nonzero value, including a negative value, selects a request-processing path.
3. **Optional descriptor address.** A 32-bit address-like value. Zero means absent. When the request is nonzero and the descriptor is present, the function reads a 32-bit flags word at descriptor byte offset 4.
4. **Auxiliary word.** An uninterpreted 32-bit value. The function copies it into local storage. The descriptor-dependent helper can replace that local value through an address supplied by this function.

The supplied representation uses 32-bit integers and four-byte words. Addresses are carried through those values in the supplied source representation; a different host ABI must not be substituted without further evidence.

## Behavior

### 1. Entry capture and suppression

The function first reads and retains the object address from the context reference. It also makes a local copy of the auxiliary word. It then calls F-10ba02f1ed27 with no arguments.

If that dependency returns any nonzero signed 32-bit value, F-87a6e9da35b1 returns immediately. It does not inspect the descriptor, read the iteration bound, perform lookup, or acquire a resource.

A zero result enables further processing.

The retained object address is not refreshed from the context reference after this dependency or any later dependency. Consequently, later operations can use the original object while dependencies receiving the context reference observe a changed context.

### 2. Zero-request iteration

When the request equals zero, descriptor routing and resource processing are bypassed entirely.

Iteration starts at index 0. Before each prospective iteration, the function reads the signed 32-bit bound at captured-object offset 4 and compares the current index against that bound using a signed comparison.

For every index below the current bound:

- Index 1 produces no dependency call.
- Every other index is passed, together with the original context reference, to F-ce8825624b38.
- The index then advances by one.

The bound is not captured once. It is read again after each iteration, including the skipped iteration at index 1. Changes made by F-ce8825624b38 can therefore shorten or extend the traversal.

A zero or negative bound produces no F-ce8825624b38 calls. A bound of 1 produces a call for index 0. A stable bound of 2 still produces only the call for index 0.

This path does not inspect the descriptor even if its address is nonzero. It does not use the auxiliary word after the initial local copy.

### 3. Routing a nonzero request

For a nonzero request, an absent descriptor is treated as having zero flags. A present descriptor supplies its flags from byte offset 4.

Descriptor-dependent processing is selected only when the descriptor is present and at least one flag bit other than bit 0 is set. The deciding mask is `0xfffffffe`.

Accordingly:

- Flags 0 select ordinary lookup.
- Flags 1 also select ordinary lookup.
- Any set bit from bit 1 through bit 31 selects descriptor-dependent processing.
- Bit 0 does not independently affect this branch decision.

The descriptor-dependent path does not first try the ordinary lookup dependency.

### 4. Descriptor-dependent acquisition

The function calls F-9c6e06f5ecb8 with:

- The original context reference.
- The nonzero request value.
- The descriptor address.
- The address of the local auxiliary-word copy.

The dependency’s signed 32-bit return is interpreted as an entry index. A negative result causes an immediate return. There is no resource acquisition or explicit cleanup by this function on that outcome, regardless of any effects the dependency already caused.

For a nonnegative index, the function performs these operations in order:

1. Reads the table address at captured-object offset 8.
2. Reads the 32-bit metadata word at the returned index with a 24-byte entry stride.
3. Calls F-e7c4e7dd076d with the captured object address and the current local auxiliary word.

The local auxiliary word may differ from the fourth argument if F-9c6e06f5ecb8 changed it.

There is no direct table-length check. In particular, the iteration-bound field at object offset 4 is not consulted to validate this index.

The metadata word is loaded before F-e7c4e7dd076d is called and retained for the subsequent registration call. Changes to the table during acquisition do not change that already-loaded word.

A zero acquisition result causes an immediate return. Every nonzero result, including a negative signed value, proceeds to the shared registration sequence.

### 5. Ordinary lookup and fallback acquisition

The function calls F-d34857dd0073 with the captured object address and the request value.

If the signed result is nonnegative, it calls F-ce8825624b38 with the original context reference and that result, then returns. Index 0 is accepted. The index-1 exclusion belongs only to zero-request iteration; a lookup result of 1 is forwarded normally.

If the lookup result is negative, the function calls F-e7c4e7dd076d with the captured object address and the original request value.

A zero acquisition result causes an immediate return. Any nonzero result proceeds to registration with a metadata word of zero. This fallback does not use the auxiliary word or read the entry table.

### 6. Shared registration and release sequence

After either acquisition path returns a nonzero value, the function calls F-3747d6ba198f with:

- The original context reference.
- A literal zero as its second argument.
- The acquisition result.
- The selected metadata word: table-derived for descriptor-dependent processing, zero for ordinary fallback.

It retains the registration result, then calls F-94cb53877c15 with the acquisition result.

This call occurs before the function decides whether to forward the registration result. It occurs even when registration returned zero.

If the registration result is zero, the function returns after F-94cb53877c15 completes. If it is nonzero, the function calls F-0b2822e11091 with the original context reference and the registration result, then returns.

The final test is zero versus nonzero, not negative versus nonnegative. A negative registration result is therefore forwarded to F-0b2822e11091.

Its local auxiliary-word copy is writable by F-9c6e06f5ecb8. That local storage is distinct from the caller’s original by-value fourth argument. No direct write-back to caller-owned storage for that argument is shown.

All other observable state changes arise through dependencies. Those dependencies may alter the context, referenced objects, globals, tables, or other state; preservation is not established.

- The initial context-word read precedes the suppression dependency.
- Descriptor flags are inspected only after suppression permits processing and only for a nonzero request.

- Registration precedes F-94cb53877c15.
- F-94cb53877c15 precedes any F-0b2822e11091 call.

No allocation is directly visible. The role of F-94cb53877c15 is consistent with releasing or relinquishing an acquired resource, but that ownership interpretation is not established. The evidence proves only that it receives the nonzero acquisition result after registration. It does not prove whether registration retains, copies, consumes, or borrows anything.

No rollback is visible for earlier dependency effects when a later operation fails or returns zero.

## Acceptance examples

These are conditional acceptance scenarios derived from static evidence, not executed tests. Each assumes valid memory and dependencies that return normally.

1. **Suppression still requires the initial context read.**  
   If F-10ba02f1ed27 returns 7, the context’s first word has already been read. No other dependency is called by this function.

2. **Stable zero-request traversal.**  
   With request zero and a bound that remains 4, F-ce8825624b38 receives indices 0, 2, and 3, in that order. It never receives index 1 from this traversal. The descriptor is not inspected.

3. **Traversal responds to a changed bound.**  
   If the initial bound is 5 and the call for index 0 changes the bound to 1, the next condition fails and traversal ends. Indices 2 through 4 are not visited.

4. **Bit 0 alone does not select descriptor processing.**  
   With a nonzero request and descriptor flags equal to 1, F-d34857dd0073 is used. If it returns 1, F-ce8825624b38 receives index 1 and the function returns without acquisition.

5. **Descriptor output controls acquisition.**  
   With flags equal to 2, suppose F-9c6e06f5ecb8 returns index 3 and replaces the local auxiliary word. The metadata is read at table byte offset 72, and F-e7c4e7dd076d receives the replacement word rather than the original fourth argument.

6. **Negative descriptor result stops the path.**  
   If F-9c6e06f5ecb8 returns −1, there is no subsequent table read, acquisition, registration, or F-94cb53877c15 call by this function.

7. **Fallback uses zero metadata.**  
   If ordinary lookup returns a negative value and acquisition returns nonzero, F-3747d6ba198f receives zero as both its second argument and its metadata argument. F-94cb53877c15 follows registration.

8. **Zero registration still has a subsequent release-like call.**

9. **Negative nonzero registration is forwarded.**
