# F-e2f9fb470912

## Purpose

F-e2f9fb470912 enumerates unsigned 32-bit item values, conditionally obtains a 16-bit associated value for each item, and submits both values to an output dependency.

**Within each item, the second submission address is two bytes after the first. Corresponding submission addresses in successive items are four bytes apart.** The first submission address is one byte after the supplied base address.

The spacing and value widths suggest four-byte records containing two 16-bit fields, preceded by one reserved byte. This is **inferred intent**, not an established memory format: the output dependency’s implementation is unavailable, so its actual write width, byte order, and other effects remain unknown.

After enumeration, the function directly assigns an eight-bit extent-like result through a separate destination address. It then invokes F-feee9156a257 with an object acquired during initialization. That invocation is marked non-returning in the supplied static evidence; no normal return to the caller is established.

## Behavior

### Initialization

The function first calls F-bff5c64148c3 with input 1.

Using the returned object, it selects the operation at dispatch offset 0x34 and invokes it with the four arguments listed above. The selected function address is also passed as an argument. The supplied expression contains dispatch-entry accesses for both target selection and that argument; their relative evaluation order is not established.

The returned secondary-object reference is retained. The function immediately invokes that object’s offset-0x00 operation and retains the 32-bit result as a gate:

- Zero disables associated-value lookups.
- Any nonzero result enables them.

The gate is queried once, before the count is obtained. It is not refreshed during enumeration.

Next, the function calls F-bff5c64148c3 again with input 1. It invokes this newly resolved object’s offset-0x20 operation and retains the result as an unsigned 32-bit count.

The two initial resolutions are distinct calls. The function does not establish that they return the same object, nor does it require their dispatch tables to match.

After the count query, the function forms the initial output address by adding one to input 5. This arithmetic occurs even when the count is zero.

### Enumeration and per-item ordering

A zero count skips enumeration. Otherwise, indices are processed in ascending unsigned order from zero through one less than the saved count.

For each index, the observable sequence is:

1. Establish a pending associated value of zero at 16-bit width.
2. Call F-bff5c64148c3 with input 1.
3. Select and invoke the newly resolved object’s offset-0x24 operation with that object reference and the current index.
4. Retain the item result as an unsigned 32-bit value.
5. Invoke F-3a7a47316439 with the current output address and the item’s low 16 bits.
6. If the saved gate is nonzero, select and invoke the retained secondary object’s offset-0x08 operation with that object reference and the **full 32-bit item value**. Retain only the result’s low 16 bits as the pending associated value.
7. Invoke F-3a7a47316439 with an address two bytes after the current output address and the pending associated value.
8. Advance the current output address by four bytes.

The associated-value lookup therefore occurs **after** the first output submission, not before it. When the gate is zero, the second submission still occurs and carries zero.

Each item operation uses a freshly resolved object. Associated-value operations continue to use the secondary-object reference acquired during initialization, but their dispatch targets are selected when those operations are reached. The function does not establish that earlier dependencies leave that object or its dispatch table unchanged.

The saved count controls the complete loop. The count-producing operation is not called again.
