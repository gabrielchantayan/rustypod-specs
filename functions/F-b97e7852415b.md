# F-b97e7852415b

The sequence uses two unsigned 32-bit inputs both as values and as components of addresses. It also requires execution-context values absent from the explicit parameter list. Several writes install self-referential values or right-shifted values into memory.

## Behavior

1. Write `payload` at `record + 0x14`.
2. Write `x` at `context + x`.

The first and third writes target the same address. Without aliasing, concurrent observation, or unusual memory semantics, the third replaces the first. Nevertheless, the first write is part of the specified sequence and cannot be omitted merely because it is later overwritten.

No result from this dependency is consumed by the visible body. Its memory effects, ownership behavior, and return behavior are unknown.

This is an address formed with the shifted numeric value of `y`, not with the original `y`.

### 5. Writes following the third indirect call

1. Write the 32-bit representation of `offset` at the address formed by adding `offset` to the address value of `link`.
2. Write `node-result` at `node-result + 0x18`.
3. Write `link` as an address word at `context + y-quarter`.
4. Write `y-quarter` at `y-quarter + 0x18`.

The third write repeats the earlier write to `context + y-quarter`. It is not redundant as an observable contract: the intervening dependencies may have changed that memory.

### 6. Fourth indirect call

The function invokes unresolved dependency **F-U04** with four arguments:

1. `x-sixteenth`;
2. `node-result` shifted left by two bits;
3. `x-quarter`;
4. `x-sixteenth`.

The first and fourth arguments are the same unsigned value.

The second argument requires special care. The supplied representation applies the left shift to a signed integer result. It establishes a two-bit left-shift expression, but does not establish portable behavior for negative operands or overflowing signed values. A universal modulo-\(2^{32}\) interpretation is therefore not part of the proven contract.

The result of F-U04, called `final-result` here, is used as an address base.

### 7. Final memory updates

If F-U04 returns normally, the function performs:

1. A 32-bit write of `x-quarter` at `link`.
2. A 32-bit write of `x-sixteenth-via-quarter` at `final-result + 0x3C`.
3. A write using the late global word associated with absolute address `0x3C`: its value supplies an address base, and its value is stored at that base plus `0x18`.

For the final operation, if the global word has a stable value `g` throughout its evaluation, the effect is a 32-bit write of `g` at `g + 0x18`.

The representation uses that global value in both the destination calculation and the stored value. It does not establish whether the implementation performs one load or multiple loads, nor their relative order if multiple loads occur. Consequently, a single stable `g` must not be assumed under concurrent or externally changing memory.

This global access occurs after the write at `final-result + 0x3C`. If that write overlaps the global storage, it can change the value used by the final operation.

### 8. Terminal behavior

The visible loop contains no further calls, memory accesses, exit condition, or return. Scheduling, interrupts, instrumentation, and other external execution effects are outside the supplied evidence.
