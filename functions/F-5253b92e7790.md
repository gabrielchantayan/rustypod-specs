### Initial input propagation

The first call receives P. A four-call result sequence then obtains R1.

After that sequence, the function writes P as four bytes at address Q(R1) + 0x14. The next dependency receives Q(R1), rather than the address of that write.

A second result sequence obtains R2. The function writes Q(R2) as four bytes at address T(R2) + 0x14, then passes Q(R2) to the following dependency.

A third result sequence obtains R3. The function writes the previously computed Q(R2) as four bytes at address Q(R3) + 0x14, then passes Q(R3) onward.

These operations establish two distinct address scales: some destinations use four times a result, while others use sixteen times a result. The evidence does not justify replacing these with one common record layout.

### Word capture

A fourth result sequence obtains R4.

The function then performs, in order:

1. A four-byte write of Q(R4) at T(R4) + 0x14.
2. A four-byte unsigned read from Q(R4) + 0x14, captured as S.
3. A dependency call receiving Q(R4).

There is no represented call between this write and read. The addresses may nevertheless coincide under the applicable arithmetic. Earlier writes may also overlap them.

S is the value actually read at this point. It is not necessarily P, a prior dependency result, or the immediately preceding stored value.

### Shifted-word propagation

A fifth result sequence obtains R5.

The function writes S logically shifted right by 12 bits as a four-byte value at Q(R5) + 0x14. The following dependency receives Q(R5).

The shifted result has at most 20 significant bits. This is an unsigned right shift; no sign extension is represented.

A sixth result sequence obtains R6. The function writes Q(R6) as four bytes at T(R6) + 0x14.

The next dependency receives three explicit arguments, in this order:

- The low six bits of Q(R5), shifted left by 14.
- Q(R6).
- R5 shifted left by 30, retaining the low 32 bits under the machine interpretation.

The first argument is derived from the computed quantity Q(R5), not from S or the shifted value written to memory. Under 32-bit arithmetic it is a multiple of 65,536 and cannot exceed 0xF0000.

The third argument depends only on the low two bits of R5 under that same interpretation.

### Further word propagation

A seventh result sequence obtains R7.

The function writes Q(R6) as four bytes at Q(R7) + 0x14. The next dependency receives Q(R7).

An eighth result sequence then obtains R8.

No evidence establishes that these computed destinations are allocated objects, distinct records, or addresses returned by an allocator. The dependency results are simply used in address calculations.

### First byte update

The first byte operation uses the retained R5, not R7 or R8.

The function reads one unsigned byte at H(R5), producing B1. It then writes one byte at address B1 + 0x11. The stored value is the low byte of Q(R8).

Consequences of this layout are:

- B1 is zero-extended before participating in the destination address.
- The destination is between 0x11 and 0x110 inclusive.
- The destination is derived from the byte’s value, not from a multi-byte pointer read.
- The stored value is a multiple of four, reduced to one byte.

The next dependency receives three explicit arguments:

- Q(R8).
- Q(R8) again.
- The low 32 bits of R8 shifted left by four.

This call uses the distinct target-displacement form noted in the interface. It must not be silently treated as another instance of the prevailing target calculation.

### Opaque-result forwarding

The following call has no explicit arguments and produces the four-byte opaque result R9. The next call receives R9 unchanged.

The evidence establishes only forwarding. It does not establish whether R9 is a pointer, status, handle, scalar, or ownership-bearing value.

Another four-call result sequence obtains R10.

### Second byte update

After obtaining R10, the function reads one unsigned byte from H(R5) again, producing B2.

This is a new read. The contract must not reuse B1: intervening dependencies, aliasing, or externally changing memory may alter the byte.

The function writes one byte at B2 + 0x11. Its value is formed by:

- Retaining the low 30 bits of R8.
- Logically shifting that value right by 20.
- Retaining only the low eight bits for the byte write.

The stored byte therefore corresponds to bits 20–27 of R8. Bits 28–29 survive the intermediate shift but are discarded by the byte-width store; bits 30–31 are removed before the shift.

The next dependency receives Q(R10).

### Final calls and endpoint

The next dependency receives Q(R11) and the zero-extended B2, in that order. B2 is the byte captured before the second byte write, not a subsequent reread and not that write’s payload.

One last call follows with no explicit arguments. The supplied representation then reaches the invalid-instruction endpoint. No cleanup, return-value construction, or normal return is represented after that call.

Both byte reads address 0x10000001. The first byte write stores 0x0C at 0x31. The second stores 0xAB at 0x32.
