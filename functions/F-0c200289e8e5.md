# F-0c200289e8e5

## Purpose

F-0c200289e8e5 conditionally performs an ordered series of indirect dependency invocations, byte reads, byte writes, and four-byte memory accesses. It publishes an input payload and derived values to computed addresses, clears selected locations, and explicitly clears the four-byte location at address 0x24 four times.

No application-level purpose is established. The evidence does not identify an allocator, initializer, serializer, decoder, or cleanup operation. The supplied representation reports invalid instruction data and ends at an invalid-instruction stop. This contract describes the represented behavior, conditional on reaching each operation; it does not establish that a valid executable can complete the path.

Established behavior, possible intent, and unresolved machine semantics are distinguished below. No runtime tests have been performed.

## Behavior

### Invocation convention used in this contract

A **five-invocation sequence** consists of one indirect invocation with the stated explicit arguments, followed by four indirect invocations with no displayed explicit arguments. Its “result,” when consumed, is the fifth invocation’s result.

This grouping records ordering only. It does not establish a shared target, calling convention, or purpose. An invocation without displayed arguments may still consume machine state and affect memory.

All stages below are conditional on preceding invocations returning and preceding accesses completing. Retained values mean values explicitly carried forward in the representation, not assumptions that dependencies preserve arbitrary registers or globals.

### 1. Opening selector and initial payload publication

The opening five-invocation sequence receives three explicit arguments: the first additional unsigned input shifted right by three, the payload, and the address-like input shifted left by two. Retain the sequence’s final result as the **opening result**.

After that sequence, read a byte at the address-like input plus one. Retain it as the **initial selector**. Publish the low eight bits of the second additional unsigned input shifted right by 22 to byte address 0x11 plus the initial selector.

A further five-invocation sequence receives the opening result shifted left by two. After it completes, write the payload as four bytes at:

**0x14 + 4 × initial selector.**

This write uses the retained initial selector; it does not reread the original byte.

### 2. Second payload publication

The next five-invocation sequence receives four arguments: the initial selector three times, followed by the initial selector shifted right by one.

Write the payload as four bytes at 0x14 plus four times the sequence’s final result. This result is an unchecked selector; no validation precedes the write.

### 3. First two scaled publications

A five-invocation sequence receives four times the preceding selector. Retain its result as the **first scale selector**. Write four times that selector as a four-byte value at 0x14 plus sixteen times the selector.

The next five-invocation sequence receives the value just stored. At 0x14 plus four times its final result, write that same retained value.

Another five-invocation sequence receives four times this latest result. Retain its result as the **second scale selector**. Write four times that selector at 0x14 plus sixteen times the selector. Retain the written value as the **second scaled value**.

### 4. Masked publication

Invoke one dependency with the second scaled value, then another with no displayed explicit arguments. Pass the latter result into a five-invocation sequence.

At 0x14 plus four times the sequence’s final result, write the four-byte value obtained by masking the second scaled value with 0x3fffffff and then shifting right by one, unsigned.

The mask is applied before the shift.

### 5. Scaled publication followed immediately by a read

A five-invocation sequence receives four times the preceding final result. Retain its result as the **third scale selector**, and retain four times that selector as the **third scaled value**.

The observable memory and invocation order is:

1. Write the third scaled value as four bytes at 0x14 plus sixteen times the third scale selector.
2. Read four bytes at 0x14 plus four times the third scale selector.
3. Shift the read value right by three, unsigned, and supply it to the next five-invocation sequence.
4. After that sequence, write the retained third scaled value at 0x14 plus four times its final result.

There is **no intervening dependency invocation between the first store and the read**. The read occurs before the next invocation receives its argument.

The store and read use different address formulas, but those formulas may designate the same address. Neither disjointness nor substitution of the stored value for the read is generally justified.

### 6. Main selector and selector publications

A five-invocation sequence receives four times the preceding final result. Retain its result as the **main selector**.

Write the initial selector as four bytes at:

**0x24 + 0x80000 × (initial selector shifted right by three).**

Define the **main base** as sixteen times the main selector. Define the **half-selector** as the main selector masked with 0x3fffffff and then shifted right by one, unsigned.

A five-invocation sequence receives the main base and the main selector shifted left by two. After it completes, write the retained initial selector as four bytes at the main base plus 0x24.

### 7. Main-base byte publications and clears

Read four bytes at the main base plus 0x74 and pass that value to a five-invocation sequence. Retain its final result as the **retained shift source**.

Next, read a byte at the main base plus one. At 0x11 plus that byte, write the low eight bits of the main selector masked with 0x3fffffff and shifted right by 20. This publication may be zero.

Invoke a dependency with the retained shift source shifted left by two, then invoke another with no displayed arguments. Pass the latter result to a five-invocation sequence.

After this sequence, reread the byte at the main base plus one and clear the byte at 0x11 plus the newly read value. This is a fresh selector read, not reuse of the earlier byte.

Another five-invocation sequence receives the preceding sequence’s final result shifted left by two. Afterward:

- Clear one byte at the half-selector plus 0x0f.
- Define the **intermediate base** as 0x400 times the half-selector.
- Read a byte at the intermediate base plus one, then clear the byte at 0x11 plus that value.

The first clear precedes the intermediate-base read, so aliasing between them matters.

### 8. Retained byte selector and first paired word clear

Invoke a dependency with four arguments: the retained shift source shifted left by 23, repeated three times, followed by that source shifted left by 25. Invoke another dependency without displayed arguments, and pass its result to a five-invocation sequence.

Read a byte at the intermediate base plus one. Retain it as the **clear selector**, then clear the byte at 0x11 plus that selector.

A five-invocation sequence receives the preceding sequence’s final result shifted left by two. After it completes, perform these four-byte writes in order:

1. Zero at 0x44 plus the retained clear selector.
2. Zero at address 0x24.

The first address uses the unscaled byte selector. It is not 0x44 plus four times that selector.

### 9. Three additional paired word clears

Invoke a dependency with arguments zero, 0x98, the intermediate base, and 0x98. Invoke another without displayed arguments, pass its result to a further dependency, then invoke another without displayed arguments. Pass that latest result to a five-invocation sequence.

Using the sequence’s final result, clear four bytes at 0x44 plus four times the result, then clear four bytes at 0x24.

The next five-invocation sequence receives four times that result and produces the represented 64-bit result. Retain both 32-bit portions. Invoke a dependency with the lower portion shifted left by two. After that invocation, clear four bytes at 0x44 plus twice the retained upper portion, then clear four bytes at 0x24.

The upper portion belongs to the earlier 64-bit result; it is not a fresh post-invocation register read.

The intervening dependency also exposes an additional machine-register result. Invoke another dependency with zero, that additional result, and that result shifted left by two. Invoke one more dependency without displayed arguments.

A five-invocation sequence then receives the half-selector masked with 0x3fffff and shifted left by seven. Clear four bytes at 0x44 plus four times its final result, then clear four bytes at 0x24.

Including stage 8, this establishes four explicit four-byte zero writes to address 0x24. Dependencies may modify that location between writes.

### 10. Two payload-location clears

A five-invocation sequence receives four times the preceding result. Invoke a further dependency with its final result shifted left by two. Retain this further dependency’s result as the **clear index**.

Clear four bytes at 0x14 plus four times the clear index.

A five-invocation sequence receives the clear index three times, followed by the half-selector masked with 0x3fffff and shifted left by seven. Clear four bytes at 0x14 plus four times its final result.

### 11. Rebuilt scaled publications

A five-invocation sequence receives four times the preceding result. Write four times its final selector at 0x14 plus sixteen times that selector.

Pass the written value to another five-invocation sequence. Write that same retained value at 0x14 plus four times the new final result.

Another five-invocation sequence receives four times this latest result. Write four times its final selector at 0x14 plus sixteen times that selector.

Invoke a dependency with two arguments: four times and sixteen times this final selector. Invoke another dependency without displayed arguments.

The next five-invocation sequence receives that latest dependency result and the half-selector masked with 0x3fffff and shifted left by four. At 0x14 plus four times the sequence’s final result, write the half-selector masked with 0x3fffff and multiplied by 0x80.

This last stored value is at most 0x1fffff80; that masked multiplication does not overflow 32 bits.

### 12. Final byte publications and stop

A five-invocation sequence receives four times the preceding result. Retain its result as the **first final value**. Define the **final base** as 0x4000000 times the half-selector, subject to the unresolved arithmetic semantics.

Read a byte at the final base plus one. At 0x11 plus that byte, write the low eight bits of the first final value shifted left by two.

Invoke a dependency with that shifted value, then another without displayed arguments. Pass the latter result to a five-invocation sequence. Reread the byte at the final base plus one. At 0x11 plus the new byte, write the low eight bits of the first final value masked with 0x3fffffff and shifted right by 20.

The next five-invocation sequence receives the preceding sequence’s final result shifted left by two. Retain its result as the **second final value**.

Reread the byte at the final base plus one, retain it, and write the low eight bits of four times the second final value at 0x11 plus that byte.

Invoke a dependency with the retained byte zero-extended to 32 bits, then another without displayed arguments. Pass the latter result to a five-invocation sequence.

Read a byte at one plus eight times the second final value. At 0x11 plus this byte, write the low eight bits of the second final value masked with 0x3fffffff and shifted right by 20.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes that the relevant path is reached and accesses complete.

1. **Byte truncation.** With the second additional unsigned input equal to 0xffffffff and the initial selector equal to 2, the first byte publication writes 0xff at 0x13. The shift produces 0x3ff; the byte write retains eight bits.

2. **Initial-selector addresses.** An initial selector of 255 places the first payload write at 0x410 and the stage-6 selector publication at 0x00f80024.

3. **Mask before shift.** A second scaled value of 0xfffffffc produces the stage-4 stored value 0x1ffffffe. Omitting the mask changes the result.

4. **Read-before-call with aliasing.** If the third scale selector is zero, both stage-5 address formulas yield 0x14. With ordinary stable memory and no external writer, the four-byte zero store is followed by a read of zero, then the next dependency receives zero. No dependency executes between that store and read.

5. **Fresh main-base selector.** If the stage-7 selector byte changes from 3 to 7 between its two reads, the first byte publication targets 0x14 and the later byte clear targets 0x18. The first publication’s value may itself be zero.

6. **Unscaled word clear.** A clear selector of 3 makes stage 8 clear four bytes starting at 0x47, followed by four bytes at 0x24. No alignment repair is specified.

7. **Zero is not a skip marker.** A zero result used as a selector for an address of 0x14 plus four times that result causes an access at 0x14; no conditional skip is represented.

8. **Final byte truncation.** A second final value of 0x40000041 produces 0x04 for its four-times byte publication. Its later masked-and-shifted publication produces zero, using a separately read address selector.
