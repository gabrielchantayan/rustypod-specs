# F-48c3742cecc7

## Purpose

F-48c3742cecc7 performs an ordered sequence of memory writes and indirect calls. Its directly visible work includes:

- Writing an incoming 32-bit value into a caller-selected memory region.
- Capturing a 32-bit word for later extraction of two separate bytes.
- Using byte-sized lookup results to select two byte-write destinations.
- Passing selected dependency results, including values scaled by four, to later dependencies.
- Clearing one byte and one 16-bit region near the end of execution.
- Attempting a final call to address zero with three zero arguments.

No application-level purpose is established. In particular, the evidence does not establish that this is an initializer, serializer, allocator, device operation, or valid standalone routine. The unusual entry-state dependencies, small derived addresses, and final zero-address call make the correctness of the recovered function boundary and calling convention material uncertainties.

This contract describes the visible sequence conditionally: each later action is reached only if earlier memory accesses and calls complete and control returns normally.

## Behavior

The routine first stores the incoming payload as a 32-bit value at object base plus `0x14`.

It then reads a 32-bit word from source base plus `0x14`. This read supplies a **saved word** used later. It is not visibly reloaded.

The order matters if the two regions overlap. If their four-byte addresses are identical, the read follows the write and therefore observes that written value, provided the memory behaves as ordinary writable and readable storage. Partial overlap requires the actual byte order and memory behavior to determine the saved word.

No null, bounds, alignment, or accessibility check precedes either access.

### 3. First lookup-directed byte write

After F-D05 returns, the routine reads an unsigned byte at selector base plus `1`.

It adds `0x11` to that byte’s numeric value and uses the sum itself as an address. It does not visibly add the selector base again.

At that destination, it writes the low eight bits of the saved word.

Consequently:

- The lookup value ranges from 0 through 255.
- The destination ranges from `0x11` through `0x110`.
- The written value is saved-word bits 0–7.

This lookup happens after the first five calls. Its result therefore cannot be specified as the selector byte’s entry-time value: any preceding dependency may have changed that memory.

### 4. Four-argument call and forwarding

The routine invokes **F-D06** with four explicit arguments:

1. High word.
2. High word.
3. High word.
4. Low word shifted left by two within its 32-bit unsigned width.

For the fourth argument, bits shifted beyond bit 31 are discarded. It is equivalent to multiplying the low word by four modulo \(2^{32}\).

The routine then calls **F-D07**, receiving a 32-bit result, and passes that result to **F-D08** as its sole explicit argument.

It next calls **F-D09**, **F-D10**, **F-D11**, and **F-D12**, in that order. F-D12 supplies another 32-bit result, represented as signed in the supplied material.

### 5. Second lookup-directed byte write

Before consuming F-D12’s result in the next call, the routine performs another byte lookup and write.

The lookup address is:

\[
1 + ((\text{low word} \mathbin{\&} \texttt{0x3FFFFFFF}) \gg 21)
\]

Only bits 21–29 of the low word contribute to this address. Its range is `0x1` through `0x200`.

The routine reads an unsigned byte from that address. It then writes one byte at the address equal to that lookup byte plus `0x11`.

The stored byte is:

\[
(\text{saved word} \gg 22) \mathbin{\&} \texttt{0xFF}
\]

Thus, this write uses saved-word bits 22–29. Bits 30–31 do not contribute to the byte.

As with the first lookup-directed write, the destination ranges from `0x11` through `0x110`. The two destinations may coincide. If they do, the second write occurs later and replaces the first byte, unless intervening effects or unusual memory behavior change the outcome.

### 6. Further scaled-result calls

It then calls **F-D14**, **F-D15**, **F-D16**, and **F-D17**, in order. F-D17 supplies a further 32-bit result, also represented as signed.

The routine invokes **F-D18** with two explicit arguments, both obtained by shifting F-D17’s result left by two. Both arguments derive from the same returned value.

For nonnegative results no greater than `0x1FFFFFFF`, the shift has the unambiguous arithmetic value four times the result. ## Acceptance examples

These examples are conditional static expectations, not executed tests. They assume all required accesses are valid, earlier calls return, and unspecified dependency effects do not invalidate the stated conditions.

### Initial aliasing

If object base and source base are identical and ordinary memory semantics apply, the saved word equals the incoming payload because the 32-bit store precedes the 32-bit read.

An implementation that captures the old word before storing the payload would violate the visible order.

### First byte selection

If the saved word is `0xA5C3E27B` and the selector byte is `0x20` when read, the first lookup-directed write places `0x7B` at address `0x31`.

Writing through selector base plus `0x31` would not match the evidence.

### Unsigned scaling and half selection

If F-D05 supplies high word `0x11223344` and low word `0xC0000001`, F-D06 receives three copies of `0x11223344`, followed by `0x00000004`.

The discarded upper bits of the low word do not carry into the fourth argument.

### Derived lookup boundaries

A low word of zero makes the second lookup read address `0x1` and the final 16-bit clear address zero.

A low word of `0x3FFFFFFF` makes those addresses `0x200` and `0x7FFFFF`, respectively. Setting low-word bits 30 or 31 does not change either address.

### Second byte extraction

For saved word `0xA5C3E27B`, the second written byte is `0x97`.

If its lookup byte is also `0x20`, both lookup-directed writes target address `0x31`. The second direct write places `0x97` there after the earlier write of `0x7B`.

### Safe signed-scaling range

If F-D12 returns `3`, F-D13 receives `12`.

If F-D17 returns `5`, both explicit arguments to F-D18 are `20`.

These examples do not define behavior for signed operands outside the unambiguous range.

### Interrupted execution

If F-D13 does not return, neither the later dependency calls nor the final clears nor the zero-address call is reached. Earlier direct writes are not visibly undone.

If address zero is not callable, reaching F-D23 does not constitute a successful normal return, even if all preceding effects completed.
