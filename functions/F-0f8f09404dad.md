# F-0f8f09404dad

## Purpose

F-0f8f09404dad performs an ordered operation on a caller-supplied object address and a 32-bit payload. It invokes four direct dependencies, writes the payload into storage returned by the second dependency, and then conditionally invokes an indirect dependency.

The indirect operation is controlled by two values read after the direct dependencies return: a pointer held at object offset 12 and the first 32-bit word at that pointer. Neither value supplies the indirect destination. When both are nonzero, the routine separately reads a global function-pointer location and uses the resulting target for the indirect operation.

An allocation followed by insertion and notification is a possible interpretation. Those semantic roles are **inferred intent**, not established guarantees. The contract below specifies the visible operations without assigning unavailable dependency semantics.

### Final gate reads

After F-acda426cbea1 returns, the routine reads the pointer field at object offset 12.

- If the pointer is zero, it skips the pointed-to word read, the global target read, and the indirect operation.
- If the pointer is nonzero, it reads the first 32-bit word at that address.
- If that word is zero, it skips the global target read and the indirect operation.
- If that word is nonzero, it proceeds to read the indirect target.

The gate uses zero versus nonzero, not positivity or equality to one. A word whose only set bit is its highest bit passes the gate.

A nonzero pointer must reference readable storage for the four-byte word read. An unreadable nonzero pointer is not treated as a false gate.

These reads observe the state reached after the direct dependencies complete, not an entry-state snapshot. A dependency may change the pointer field or the pointed-to word before the routine inspects them.

### Conditional global target read and indirect operation

Only after both gate conditions pass does the routine read the separate global function-pointer location.

This is an additional visible memory read after gate evaluation. Its position matters:

- It follows all four direct dependency calls.
- It follows the object pointer-field read.
- It follows the pointed-to gate-word read.
- It does not occur on either gate-failing path.

The value obtained from this global location supplies the indirect destination. The gate word is not the destination.

The dependencies must not be assumed to preserve the global target. An entry-time cached target, or a target captured before the last direct dependency, is not equivalent to the visible late read when intervening operations can change that location.

No explicit null or validity check is shown for the target itself. Once the gate passes, a usable target is required for normal execution of the indirect operation.

The supplied representation expresses the transfer as a call, but does not reliably establish its arguments, receiver, calling convention, or return behavior. The absence of displayed arguments is not sufficient to promise a zero-argument interface.

On a gate-failing path, the routine returns without the target read or indirect operation. On the gate-passing path, the represented flow returns if the indirect operation returns normally. No further local data access is shown after that operation; this does not constrain accesses performed by the indirect dependency itself.
