# F-78dab3e3795a

## Purpose

The supplied static representation has an early sign-dependent invalid-instruction termination and a final invalid-instruction termination. It establishes no normal return.

Its application-level purpose is **documented_only**. The evidence does not establish initialization, exception handling, relocation, device control, or another caller-visible service.

This contract describes the supplied representation, not a verified executable interpretation. Invalid-instruction warnings, overlapping global storage, incomplete global declarations, and two shifts by 32 on apparently 32-bit operands limit what can be established.

The following descriptive quantities are used:

- **Unsigned difference:** the unsigned 32-bit first argument minus `0xE0`.

- **Reduced quantity:** the masked quantity logically shifted right by one; its range is `0` through `0x3FFFFFFF`.
- **First ambiguous destination:** the fourth argument shifted left by two, then right by 32, and interpreted as a word pointer.

### 2. First dependency and early termination

F-e47d7b2e9c88 contributes its address as data; it is not visibly called.

The function obtains the dependency-derived base and a sign-derived halfword. The latter is the low 16 bits of the signed dependency address arithmetically shifted right by 31.

Before testing the address’s sign, the function writes this halfword at the dependency-derived base plus four.

If the dependency address interpreted as signed 32-bit is negative, execution then reaches the early invalid-instruction termination. None of the later operations are represented on that branch.

Otherwise, the following sequence occurs:

1. Write the sign-derived halfword at the dependency-derived base plus `0x12`.
2. Store the dependency’s 32-bit address at the address numerically equal to that address.
3. Read a signed halfword at the dependency-derived base plus the reduced quantity.
4. Repeat the halfword write at base offset `0x12`.
5. Repeat the dependency-address self-store.
6. Sign-extend the loaded halfword, arithmetically shift it right by 16, and store the 32-bit result at base offset eight.

Under the represented arithmetic-right-shift interpretation, the last value is zero for a nonnegative loaded halfword and `0xFFFFFFFF` for a negative loaded halfword. The halfword load occurs between the two pairs of repeated writes; the repetitions are separate effects.

## Acceptance examples

These are conditional static deductions, not executed tests. Each assumes preceding operations are reachable and succeed, together with any stated arithmetic and storage conditions.

1. **Zero unsigned difference.** With first argument `0xE0`, the unsigned difference, halfword base, masked quantity, and reduced quantity are zero. The first difference is `0xA8`; its byte store targets `0xAE` with byte `0xA8`. This does not make accesses near zero valid.

2. **Unsigned underflow.** With first argument zero, the unsigned difference is `0xFFFFFF20`, the masked quantity is `0x7FFFFF20`, and the reduced quantity is `0x3FFFFF90`. Signed division is not a substitute for the masking and logical shift.

3. **Early negative-address termination.** If the first dependency address has bit 31 set, its sign-derived halfword is written at dependency-derived base plus four before termination. Later self-address writes and final assignments are not reached.

4. **Signed halfword reduction.** On the continuing path, a loaded halfword of `0x7FFF` produces a word zero at dependency-derived base plus eight. A loaded halfword of `0x8000` produces `0xFFFFFFFF`, under the represented arithmetic-right-shift interpretation.

5. **Late captured value.** If an earlier write changes `0x0897EA50`, section 4 uses the value present at its late read. Once captured, that value supplies the subsequent calculations even if the global itself changes later.

6. **Distinct reads of `0x0897EA80`.** If its destination-address read yields `0x4000` and its stored-value read yields `0x5000`, the represented store writes word `0x5000` at `0x4000`. No order between those two reads is asserted. If the subsequent read yields `0x6000`, the reduced quantity is stored at `0x6004`, not necessarily at the originally assigned address plus four.

7. **Independent product self-store.** With incoming pointer `0x1000` and captured `0x0897EA50` value `0x2000`, the assignment to `0x0897EA80` is `0x4000`, while the independent product self-store writes `0x8000` at address `0x8000`. The latter destination is not the incoming-pointer-derived `0x4000`.

8. **Intermediate writes remain effects.** Replacing the incoming-pointer halfword and successive word writes with only the final contents would omit represented accesses. Likewise, the repeated first-dependency writes cannot be collapsed under this contract.

9. **Ambiguous shifts remain unresolved.** A claimed result of zero, sign filling, or an unchanged operand for either shift by 32 requires additional instruction-level evidence.
