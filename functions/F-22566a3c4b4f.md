# F-22566a3c4b4f

## Purpose

F-22566a3c4b4f conditionally processes a 32-bit request value against a caller-supplied state object.

An entry-state byte selects between two paths:

- A short path that stores the request value and returns without calling any dependency.
- A processing path that records an input byte, resolves the request, invokes a sequence of dependencies, constructs temporary state, optionally dispatches an operation, stores the request value, and invokes temporary-state cleanup.

These are established structural behaviors. Interpreting the request as a particular application command, the entry-state byte as a particular kind of lock, or the temporary state as a named application object would require evidence not supplied here.

## Behavior

### Entry-path selection

The first direct state access is an 8-bit read at offset `0xEC`.

If that byte is nonzero:

1. The function writes the 32-bit request value at offset `0xE4`.
2. It returns.

This path does not directly write the recorded byte at `0xE8`, read the halfword at `0xEA`, construct temporary state, or call any dependency. The selector is not read again.

If the entry byte is zero, processing continues as described below.

### Request resolution and preliminary operations

The function first writes the supplied recorded byte at offset `0xE8`.

It then calls F-1f46730b1ced with:

- The state address plus `0xB4`.
- The 32-bit request value.

The dependency’s result is retained for subsequent calls. It is tested for zero.

For a zero result, the function calls F-a817d8d58c10. The supplied static representation identifies this call as nonreturning. Under that control-flow assumption, neither the final request-value write nor temporary-state cleanup is reached.

For a nonzero result, the following calls occur in order:

1. F-d2f99870cc43 receives the retained result and returns a 32-bit value.
2. F-bf557f07179f receives the state address and that returned value.
3. F-fa8898fa75ae receives the retained result.

There is no direct state-field access between these three calls. Their internal accesses and side effects are unknown.

The retained result is used again later if optional dispatch occurs. Therefore, the position of F-fa8898fa75ae does not establish that it destroys or invalidates that result. Conversely, this function alone does not establish that the result remains valid: that depends on the dependencies’ contract.

### Temporary-state construction

The function reserves a local region represented as 92 bytes and passes its address to construction and cleanup dependencies. The exact logical object size and layout within that region are not established.

Construction arguments are obtained in this order:

1. Call F-fdd8589eca2d.
2. Read one byte at offset `0x2C` from the returned address.
3. Call F-fdd8589eca2d again.
4. Read one 32-bit value at offset `0x28` from this second returned address.
5. Call F-2c5a9f9c1eb3 with the local-region address, the 32-bit value from step 4, and the byte from step 2.

The first captured byte is retained across the second context call. It is not refreshed afterward.

No equivalence between the two returned context addresses is established. In particular, the construction inputs may originate from different objects or different versions of shared state.

The function does not explicitly initialize the local region before passing it to F-2c5a9f9c1eb3. Whether that dependency initializes all bytes later needed by dispatch or cleanup is outside this function’s established behavior.

### Optional dispatch

After temporary-state construction, the function calls F-5c5958cfd5fe and compares its 32-bit result with exactly `8`.

If the result is `8`, dispatch is skipped entirely:

- No third context call occurs.
- The dispatch argument and modifier do not affect this decision.
- No direct read at state offset `0xEA` occurs.

If the result differs from `8`, the function calls F-fdd8589eca2d a third time. This call occurs regardless of whether either dispatch-control argument is zero.

A 16-bit dispatch value is then selected:

| Dispatch modifier | Dispatch argument | Selected 16-bit value |
|---|---|---|
| Nonzero | Any value | Zero |
| Zero | Zero | Zero |
| Zero | Nonzero | Halfword read from state offset `0xEA` |

The third context call precedes the conditional halfword read. Consequently, if a dependency changes the state halfword before that read, the value passed to dispatch is the value present when the read actually occurs, not an entry-time snapshot.

The function then calls F-818c773e8c8a with five arguments, in this order:

1. The address returned by the third context call.
2. The address of the constructed local region.
3. The retained nonzero result from request resolution.
4. The original 32-bit dispatch argument.
5. The selected 16-bit value.

The dispatch argument is passed unchanged, including when it is zero or is a noncanonical nonzero value. The dispatch modifier is not itself forwarded.

The source establishes the fifth argument as a 16-bit quantity. Its wider calling-convention representation is not independently established.

### Completion and cleanup ordering

After dispatch returns, or immediately after dispatch is skipped, the function:

1. Writes the original 32-bit request value at state offset `0xE4`.
2. Calls F-920630e53283 with the local-region address.
3. Returns.

The final request-value write precedes cleanup. Cleanup therefore runs after that direct write has occurred.

This does not guarantee that `0xE4` still contains the request value when the function returns: F-920630e53283 may have side effects not described here. Likewise, no field value is guaranteed to remain unchanged across any unknown dependency.

There is no visible conditional check of a construction, dispatch, or cleanup status. Returned values from these calls, if any, are not used by this function.

## Side effects

On the short path, the only direct write is the 32-bit request-value write at `0xE4`.

On the processing path:

- The recorded byte is written at `0xE8` before request resolution.
- The halfword at `0xEA` is read only when dispatch is enabled, the dispatch modifier is zero, and the dispatch argument is nonzero.
- The request value is written at `0xE4` after optional dispatch and before cleanup.

If request resolution produces zero and the nonreturning dependency does not return, the recorded-byte write has already occurred, but the later request-value write has not.

These statements describe direct accesses by this function, not all accesses performed transitively by dependencies.
