## Acceptance examples

These examples are conditional contract cases, not executed tests. Assume valid memory and normal dependency returns unless stated otherwise.

1. **Initial rejection.**  
   If the initial gate returns zero, the function returns false after the two reverse-order exit calls. No resource attempt occurs, and this function does not explicitly write `0x4c`.

2. **Negative but nonzero gate.**  
   A gate result of `−2` proceeds into context preparation. The gate is not a positive-only success test.

   If `0x2c` is zero at the check, F-409402753026 receives the state address. The check does not read `0x30`. No submission occurs. The function writes zero at `0x4c`, performs both exit calls, and returns false.

4. **First field nonzero, second field zero.**  
   Both checked fields are read in order. F-409402753026 is called, followed by the common failure tail.

5. **Zero resource results with retained valid fields.**  
   Suppose both resource results are zero, but the fields at `0x2c` and `0x30` remain nonzero after all intervening calls. Both resource-result fields are stored as zero, yet submission is still reached. This case must not be rejected solely because a resource result was zero.

6. **Submission returns `−1`.**  
   With both checked fields nonzero, a submission result of `−1` causes false to be returned. This branch does not call F-409402753026, invoke the indirect method, or explicitly write `1` at `0x14`.

7. **Submission returns another negative value.**  
   A submission result of `−2` is accepted. If subsequent calls return normally, the indirect method and notification occur, `0x14` is written to `1`, and the result is true.

8. **Notification input changes during the indirect call.**  
   If the indirect method changes `0x0c`, F-3cd5bc80f1ac receives the new value. The earlier submission retains the value read before that method call.

9. **Final state changed by exit dependencies.**  
   If an exit dependency modifies `0x14` or `0x4c`, the final memory may differ from this function’s preceding explicit writes. Acceptance must distinguish the observed write sequence from unsupported final-state preservation assumptions.
