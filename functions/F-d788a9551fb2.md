# F-d788a9551fb2

## Purpose

F-d788a9551fb2 transforms an unsigned 32-bit input and a signed 32-bit input into one signed 32-bit argument supplied to an unresolved indirect transfer.

The visible computation has three stages:

1. Select a normalization shift from selected bits of the first input.
2. Interpolate between adjacent entries in a first unsigned 16-bit table, then combine that result with the second input and the normalization shift.
3. Interpolate between adjacent entries in a second unsigned 16-bit table, right-shift the result, and supply it to the indirect destination.

The combination of normalization, two lookup tables, and fixed-point arithmetic suggests a nonlinear numerical transformation. Its mathematical purpose, units, and intended input domain are not established. In particular, the evidence does not establish that either table represents a logarithm, exponential, or any other named function.

Three input conditions produce an immediate return without table access or indirect transfer.

The visible interface has no declared result value. On the non-early-return path, a computed argument is supplied to an unresolved indirect destination. That argument is not an established return value of F-d788a9551fb2.

### External data

The computation uses two externally supplied table bases:

- **Table A:** entries read as unsigned 16-bit integers.
- **Table B:** entries read as unsigned 16-bit integers.

For each table access, an index from 0 through 7 is selected, and both that entry and its immediate successor are read. Consequently, nine readable entries, occupying 18 bytes, are sufficient to support every possible index in each table.

Entries are spaced two bytes apart. Their byte order is the execution environment’s native interpretation of an unsigned 16-bit read; no independent serialized byte order is established.

The table bases need to designate valid readable storage for the selected entries. Alignment requirements, fault behavior, and whether the underlying platform permits unaligned reads are not established.

### Arithmetic notation

This contract uses:

- **wrap32(value):** retain the low 32 bits.
- **signed32(word):** interpret a 32-bit word as a two’s-complement signed integer.
- **floor(value):** round toward negative infinity.
- **high-product extraction:** retain bits 16 through 47 of a 64-bit product and interpret the resulting 32-bit word as signed.

Within the established product ranges below, high-product extraction has the same numerical result as dividing the signed product by 65,536 and rounding toward negative infinity.

These definitions describe the visible fixed-width dataflow. They do not establish portable source-language behavior for signed overflow, signed shifts, or shifts by excessive counts.

## Behavior

### 1. Early-return conditions

The function returns without proceeding to normalization, either table, or the indirect destination when any of these conditions holds:

- The second input is zero.
- The first input is exactly 65,536.
- The first input is zero.

The comparison with 65,536 is an exact 32-bit comparison. It is not a test that the low 16 bits are zero.

For example, 131,072 does not satisfy that early-return condition.

### 2. Normalization-shift selection

A shift amount starts at 15. A working value starts as the first input.

The following tests occur in order:

| Tested part of the current working value | Effect when nonzero |
|---|---|
| Bits 8–15 | Set the shift amount to 7; replace the working value with the original first input interpreted as signed and right-shifted by 8. |
| Bits 4–7 | Decrease the shift amount by 4; signed-right-shift the working value by 4. |
| Bits 2–3 | Decrease the shift amount by 2; signed-right-shift the working value by 2. |
| Bit 1 | Decrease the shift amount by 1. |

The selected shift is always between 0 and 15.

For first inputs from 1 through 65,535, it places the highest set bit at bit 15 when the original input is subsequently left-shifted. Equivalently, within that domain, the shift is 15 minus the index of the highest set bit.

That equivalence must not be generalized to arbitrary 32-bit values. The selection tests inspect only the low 16 bits. If those bits are all zero and the input has not already triggered an early return, the shift remains 15.

The original first input is then shifted left by the selected amount, retaining only 32 bits. Call this word the normalized word.

### 3. First table selection and interpolation

The first table index is bits 12–14 of the normalized word. Bit 15 does not participate in the index.

The fractional field is bits 0–11 of that word, interpreted as an integer from 0 through 4,095.

The function reads:

1. Table A at the selected index.
2. Table A at the immediately following index.

Let the two unsigned entry values be the lower-index sample and the following sample. The interpolated value is:

**lower-index sample + floor(fractional field × (following sample − lower-index sample) / 4,096).**

The following details are significant:

- Both samples are zero-extended from 16 bits before use.
- The effective difference is signed and ranges from −65,535 through 65,535.
- The visible implementation scales the fractional field by 16, multiplies in signed 64-bit arithmetic, and extracts the product at a 16-bit binary boundary.
- That sequence produces the interpolation above, including downward rounding for negative differences.
- The fractional field never reaches 4,096. It therefore does not directly select the following endpoint, except where equal samples or rounding make the values coincide.
- The interpolated value remains within the unsigned 16-bit range.

No monotonicity requirement is established for Table A.

### 4. Scaled intermediate word

The first interpolated value is multiplied by the signed second input in signed 64-bit arithmetic.

The product is divided by 65,536 with downward rounding using high-product extraction. Call the resulting signed integer the scaled interpolation.

The intermediate word is then:

**wrap32(selected shift × second input + scaled interpolation).**

The multiplication by the selected shift and the addition have 32-bit wrapping behavior in the visible unsigned expression. This matters for large positive or negative second inputs. The intermediate word must not be treated as an unbounded integer sum.

The signed 64-bit interpolation product cannot overflow: the second input is signed 32-bit and the first interpolated value is between 0 and 65,535. Its extracted value also fits signed 32 bits.

### 5. Second table selection and interpolation

The second table index is bits 13–15 of the intermediate word. It ranges from 0 through 7.

The second fractional field is bits 0–12 of the intermediate word. It ranges from 0 through 8,191.

The function reads:

1. Table B at the selected index.
2. Table B at the immediately following index.

The second interpolated value is:

**lower-index sample + floor(fractional field × (following sample − lower-index sample) / 8,192).**

As in the first interpolation:

- Samples are unsigned 16-bit values.
- The effective difference is signed.
- A signed 64-bit product and high-product extraction implement downward rounding.
- Descending table segments are permitted by the visible arithmetic.
- The result remains between 0 and 65,535.

Here the fractional field is first multiplied by 8 before the product extraction, giving the denominator of 8,192.

### 6. Final shift and indirect transfer

The final shift count is bits 16–23 of the intermediate word, interpreted as an unsigned integer from 0 through 255.

The second interpolated value is converted to signed 32-bit form and right-shifted by that count. Since the value is between 0 and 65,535, its sign bit is clear.

For shift counts from 0 through 31, the supplied argument is therefore the nonnegative integer quotient obtained by division by the corresponding power of two. Counts from 16 through 31 necessarily produce zero.

For counts of 32 or greater, the result is **documented_only**: the available evidence does not establish the execution target’s excessive-shift semantics. Do not assume either automatic masking of the count or an unconditional zero result.

The computed argument is supplied to an unresolved indirect destination, identified in this contract as **F-unknown-1**. The source representation shows one explicit argument, but does not establish the complete machine-level calling convention.

The evidence does not resolve whether this transfer behaves as an ordinary returning call, a tail transfer, or another control-flow mechanism. A subsequent return is represented, but successful return from the destination is not an established guarantee.

## Acceptance examples

These are conditional acceptance cases derived from static arithmetic. No runtime tests have been performed.

### Early return does not require readable tables

For any first input, a second input of zero must cause return without either table read or the indirect transfer.

Likewise, first inputs of zero or exactly 65,536 must return for any second input. Invalid table storage would not be reached on those paths.

### First input of one selects the first sample

With first input 1 and any nonzero second input:

- The selected shift is 15.
- The normalized word is 32,768.
- The first table index is 0.
- The first fractional field is 0.
- The first interpolated value equals Table A entry 0.

The representation still reads entry 1. A zero fractional field does not eliminate that access.

### Constant tables can produce an exact argument

Suppose:

- The first input is 32,768.
- The second input is 1.
- Table A entries 0 and 1 are both zero.
- Table B entries 0 and 1 are both 8,192.
- Both table bases and the indirect destination are valid.

Then:

- The normalization shift is zero.
- The first interpolation is zero.
- The intermediate word is zero.
- The second interpolation is 8,192.
- The final shift count is zero.
- F-unknown-1 receives 8,192.

This case establishes the supplied argument, not any behavior after the destination receives it.

### Descending segments round downward

Suppose the first input is 49,152, making the first table index 4 and its fractional field zero. Let the second input be 2,048, and let Table A entry 4 be 1,024. Entry 5 must also be readable.

The scaled interpolation and intermediate word are both 32. If Table B entries 0 and 1 are respectively 100 and 99:

- The second interpolation is 100 + floor(−32 / 8,192), which is 99.
- The final shift count is zero.
- The supplied argument is 99, not 100.

This distinguishes downward rounding from truncation toward zero.

### Higher input bits do not introduce a general range rejection

A first input of 131,072 with a nonzero second input is not rejected by the explicit early-return checks.

Its low 16 bits are zero, so the selected shift is 15. Its wrapped normalized word is zero, selecting Table A index 0 and fractional field 0.

This behavior does not establish that such an input is intended or meaningful to callers.

### Excessive final shift remains unresolved

Suppose the first input is 32,768, the second input is 2,097,184, and Table A entry 0 is 65,535. The first fractional field is zero, so the first interpolation equals that entry.

The intermediate word is 2,097,151, whose bits 16–23 equal 31. The final shifted argument is therefore zero for any valid Table B samples.

Increasing the second input to 2,097,185 makes the intermediate word 2,097,152 and the final shift count 32. The final argument then falls within the documented-only excessive-shift uncertainty; it must not be pinned to a value without additional target evidence.
