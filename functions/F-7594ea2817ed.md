# F-7594ea2817ed

## Purpose

F-7594ea2817ed destructively links reachable records into a singly linked prefix anchored by a caller-supplied control field.

Under a finite, non-overlapping binary-tree interpretation, the function processes the second child, prepends the current record to the destination head, and then processes the first child. The resulting prefix has first-child/current/second-child structural order. Its final link contains the destination head value that existed before the call.

**Preserving that head value is not the same as preserving the chain it originally identified.** The original head may identify a record whose link this function overwrites. Preservation of the previous chain’s contents requires the additional condition that all of its link storage remain unaffected by the function’s writes.

The binary-tree and destination-chain roles are **inferred intent**. Established behavior consists of ordered field reads, recursive calls, and field writes. The function neither validates a tree nor detects repeated records.

The transformation is destructive: each processed record’s offset-12 field changes from a recursive input into a destination link. Its offset-8 field is not a direct write target.

## Behavior

### Empty input

A zero initial record causes immediate return. The function does not read, clear, initialize, or validate the destination head.

### Ordered processing

For each nonzero current record, the established sequential order is:

1. Read its four-byte offset-12 field.
2. Invoke F-7594ea2817ed recursively with the unchanged control address and the value just read as the recursive record address.
3. After that invocation returns, read the current record’s four-byte offset-8 field and retain it as the continuation.
4. Read the four-byte destination head at control offset 4.
5. Write that head value into the current record’s offset-12 field.
6. Write the current record address into the control-head field.
7. Continue with the retained continuation. A zero continuation ends that invocation.

Every nonzero current record reaches a recursive invocation before its own linking phase, even when its offset-12 field is zero. Such a zero-input invocation returns without memory accesses.

Several ordering properties are significant:

- Recursive processing completes before the offset-8 continuation is read.
- The continuation is captured before either local write.
- The destination head is read after recursive processing, not cached from before it.
- The link write precedes the control-head write.
- The recursive input is not reread after the offset-12 field has become a destination link.

These are properties of the supplied sequential logic, not guarantees of atomic memory transactions or cross-thread visibility.

### Conditional tree-to-prefix interpretation

The structural ordering guarantee requires:

- The initial offset-8 and offset-12 relationships form a finite binary tree.
- Each reachable record occupies distinct, non-overlapping storage.
- Record storage does not overlap the control-head field.
- No external agent changes relevant memory during execution.
- All accesses and recursive calls complete successfully.

Under these conditions, linking occurs in second-child/current/first-child order. Because each linked record is prepended, the final prefix has first-child/current/second-child order.

Let H denote the destination head value before the call. The resulting link relationships are the tree’s structural in-order sequence, with each record linked to the next and the last record linked to **the value H**.

This statement remains a link-value guarantee when H identifies one of the transformed records. In that case, the final link can return into the newly constructed prefix and form a cycle. It does not imply that the previous chain remains intact or that the output is an ordinary finite chain.

To conclude that the entire previous chain is preserved after the new prefix, an additional condition is required: the storage determining that previous chain’s links must be unaffected by every write performed during the call. This includes writes to processed offset-12 fields and the control-head field, including any partial storage overlap. For a conventional chain whose successor is stored at offset 12, keeping all existing successor fields disjoint from those write regions is a sufficient condition.

The function does not inspect payloads or comparison keys. Its ordering is structural, not a sorting guarantee.

### Treatment of the existing destination head

The current head is copied as a four-byte value during each linking phase. The function does not dereference a value merely because it was read as the destination head.

A preexisting head may therefore be zero, an inaccessible address, an address inside the transformed tree, or the head of a cyclic structure without being validated in that role.

This does not mean the same value can never be dereferenced during the overall call. If it also appears in an input child relationship, or is later encountered through a rewritten field during repeated processing, it may become a recursive or continuation address.

### Captured continuation and aliasing

The continuation is the offset-8 value present **after** recursive processing returns. It is not necessarily that field’s entry value.

With disjoint tree storage, recursive writes do not affect the current record’s offset-8 field. With overlapping storage, a recursive write may change the bytes subsequently read as the continuation.

Once captured, the continuation remains the value used for the next iteration even if either local write overwrites its source storage.

There are no alias checks. If the control-head field and the current record’s offset-12 field are the same four-byte region, the link write occurs first and the subsequent head write replaces it with the current record address. Other overlaps can similarly alter later reads or erase earlier results. Non-overlap is a condition for the conventional interpretation, not a checked restriction.

### Repeated records and cycles

The function maintains no visited-record set.

An offset-12 self-reference causes recursive descent into the same record before that record reaches its own linking phase. Without an intervening failure or external mutation, the function does not reach a normal return on that path.

An offset-8 self-reference causes the same record to be processed again after a linking phase. The next pass can recurse through an offset-12 value written by an earlier pass. Consequently, behavior on shared or cyclic inputs is not equivalent to traversing an immutable graph.

No general uniqueness, termination, or tree-order guarantee applies to those inputs.

## Side effects

### Direct memory writes

Each current record that reaches its linking phase causes two direct four-byte writes, in order:

1. Its offset-12 field receives the destination head read at that phase.
2. The control-head field receives the current record address.

Recursive invocations may perform additional writes before these two.

The offset-8 field is not directly written. It can nevertheless be changed when its storage overlaps a write target. No separate payload write or global write is explicit in the body, but accessible storage—including global storage—can be affected if supplied or reached addresses identify it.

### Ownership and lifetime

The body contains no allocation, deallocation, reference-count operation, or ownership callback. Its only explicit call is recursive invocation of F-7594ea2817ed.

The function relinks existing storage. It does not establish ownership transfer, shared ownership, or reclamation obligations. All storage required for reached accesses must remain available throughout those accesses.

The original offset-12 child relationship is destroyed when its field is overwritten. Callers requiring that original structure must preserve it separately.

### Resource use and failure

Offset-8 continuation is iterative within an invocation; offset-12 continuation is recursive. Stack demand therefore depends on nested recursive processing rather than simply on the number of records reached through offset 8.

There is no explicit error result, recovery branch, rollback, or synchronization. A later access failure or resource exhaustion may occur after earlier records have already been modified. The body establishes no transactional boundary.

## Acceptance examples

These are conditional criteria derived from static evidence, not runtime test results.

### Empty input leaves memory untouched

Given a zero initial record address, the function returns without reading or writing any record or control field. An inaccessible control address does not matter on this path because it is not dereferenced.

### One record prepends a head value

Given a valid record A with both child fields zero, a disjoint control field, and initial head H:

- The final head is A.
- A’s offset-12 field becomes H.
- A’s offset-8 field remains zero.
- H is not dereferenced merely to perform this insertion.

If H is zero, the resulting offset-12 chain consists only of A.

If H identifies a separate existing chain whose link storage is unaffected by all writes, that chain remains unchanged after A.

### Three records establish structural order

Given a disjoint tree with root A, first child B at offset 8, second child C at offset 12, and zero child fields in B and C:

- Linking occurs in the order C, A, B.
- The final head is B.
- B’s offset-12 field identifies A.
- A’s offset-12 field identifies C.
- C’s offset-12 field contains the original head value H.
- A’s offset-8 field still identifies B.

These assertions concern the newly written links. They do not assert that traversing H reaches the chain that existed before the call.

### Existing-head alias destroys the old termination

Given one record A with both child fields zero, a disjoint control field, and an initial head equal to A:

- The function terminates.
- The final head is A.
- A’s offset-12 field becomes A.

Before the call, the offset-12 chain starting at A terminated immediately. Afterward, it is self-linked. Thus a finite, disjoint input tree and preservation of the original head value do not suffice to preserve the previous chain.

### A head inside a larger input produces a cycle

Use the three-record tree above, but let the original head H equal A.

The final links are B to A, A to C, and C to A. The structural prefix relationships are established, but following links from the final head enters the A–C cycle. No acyclicity guarantee applies.

### An arbitrary head value is copied without validation

In the one-record case with zero child fields, H may be any four-byte value representable in the field. Subject to successful input-field accesses, the function copies H into A’s offset-12 field without accessing the storage H might identify.

### A recursive self-link prevents local insertion

Given a record A whose offset-12 field equals A and no external mutation, recursive invocations repeatedly receive A. A linking phase cannot be reached until a nested call returns. There is no explicit cycle error or bounded-recursion response.
