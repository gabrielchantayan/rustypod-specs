# F-3edb5a885790

## Purpose

F-3edb5a885790 returns a 32-bit unsigned value selected from a descriptor-backed table or constructed from a shared fallback word. Table values may be converted to zero according to a mode and a 16-bit threshold stored in the descriptor.

The function does not establish that the descriptor, index, or table storage is valid. Its initial comparison distinguishes only indices that are greater than or equal to a signed count. Negative indices are not independently rejected.

The established behavior is selection and conditional transformation of integer words. Interpreting the words as identifiers, positions, generations, handles, or another application-specific encoding would be inferred intent, not part of the established contract.

## Interface

### Inputs

The function takes three arguments:

1. **Descriptor address.** An address interpreted as referring to the layout below.
2. **Index.** A signed 32-bit integer.
3. **Mode.** A signed 32-bit integer. Values zero and two select filtering rules. One and every other value leave a successfully loaded table word unchanged.

The descriptor is interpreted using this layout:

| Byte offset | Width | Interpretation |
|---|---:|---|
| 0 | 32 bits | Address of the table storage |
| 4 | 32 bits | Signed count used by the initial comparison |
| 8 | 16 bits | Unsigned threshold used by the filtering rules |

Only the 16-bit field at byte offset 8 is relevant to filtering. The evidence does not establish a minimum complete descriptor-object size beyond the storage required for the fields actually accessed on a particular path. It also does not establish the meaning of any adjacent bytes.

The table is interpreted as a sequence of 32-bit unsigned words, with a four-byte stride. The selected word is at the table address plus four times the index, subject to the address-arithmetic qualifications in **Uncertainties**.

A separate shared 32-bit word supplies the fallback value. It is not part of the descriptor.

### Output

The return value is a 32-bit unsigned integer. There is no separate status result.

Zero is an ordinary possible result. It can be:

- A table word that was already zero.
- A table word replaced by zero by either filtering rule.
- A fallback result when both contributing bit patterns are zero.

The function provides no way to distinguish these cases from the return value alone.

### Preconditions

For a defined, normally returning invocation, every location actually read must be accessible with the required width and appropriate alignment for the target execution environment.

The necessary readable storage is path-dependent:

- Every path requires the descriptor’s signed count.
- The fallback path requires the shared fallback word, but does not require the table address, table entry, or threshold.
- A table path requires the descriptor’s table address and the selected four-byte table entry.
- A table path in mode zero or two additionally requires the 16-bit threshold.
- A table path in any other mode does not require a threshold read.

These are access requirements, not validations performed by the function.

## Behavior

### Initial selection

The first data-dependent operation reads the descriptor’s count and compares it with the index using signed ordering.

If the count is less than or equal to the index, the function takes the fallback path. Otherwise, it takes the table path.

Consequently:

- An index equal to the count uses the fallback path.
- An index greater than the count uses the fallback path.
- A negative index can take the table path.
- A negative count is not normalized to zero.
- This comparison is not a complete array-bounds check.

For example, a count of three and an index of negative one select the table path. A count of negative two and an index of negative one select the fallback path.

### Fallback path

The function reads the shared fallback word and returns its bitwise OR with the index shifted left by 16 bit positions in the observed 32-bit result model.

Under that bit-pattern interpretation:

- Result bits 0 through 15 equal fallback-word bits 0 through 15.
- Result bits 16 through 31 are the bitwise OR of the fallback word’s upper half and the index’s lower 16 bits.
- No fallback bits are cleared.
- Index bits above the lower 16 do not contribute to the resulting 32-bit pattern.

This is an OR operation, not replacement of the fallback word’s upper half. Existing one-bits in that half remain set regardless of the index.

The mode has no effect on this path. Neither filtering rule is applied to the fallback result.

The signed-shift and overflow limitations of the supplied representation are documented in **Uncertainties**. In particular, the bit-pattern description does not by itself establish portable high-level-language behavior for negative or excessively large indices.

### Table entry acquisition

If the index is strictly less than the signed count, the function reads the table address from the descriptor and then reads one complete 32-bit unsigned table word at the selected address.

There is no additional check that:

- The index is nonnegative.
- The table address is nonzero.
- The count matches the actual allocation.
- The selected address lies within a valid object.
- Address calculation remains within the representable range.

A negative index therefore selects storage before the table address under ordinary nonwrapping address arithmetic. This is not an explicit error path; whether the access is valid depends on the caller’s storage and execution environment.

### Mode zero

After loading the table word, the function reads the descriptor’s unsigned 16-bit threshold.

It compares the table word’s upper 16 bits with that threshold, using unsigned numeric ordering:

- If the upper half is less than or equal to the threshold, the result is zero.
- If the upper half is greater than the threshold, the complete original 32-bit table word is returned.

The lower 16 bits do not influence this comparison. When the word is retained, those lower bits are preserved unchanged.

The boundary is inclusive: equality produces zero.

### Mode two

After loading the table word, the function reads the same unsigned 16-bit threshold.

Unlike mode zero, this mode compares the **entire 32-bit unsigned table word** against the threshold:

- If the full word is greater than the threshold, the original word is returned unchanged.
- If the full word is less than or equal to the threshold, the transformation in the evidence produces zero.

The latter result follows from the widths, not from assuming that the mode’s apparent intent was to clear the entry. A 32-bit unsigned word no greater than a 16-bit unsigned threshold cannot have any nonzero bits above bit 15. The supplied transformation selects bits 16 through 23, so all selected bits are necessarily zero whenever that transformation is reached.

Thus the observable mode-two rule is: return zero for words at or below the threshold; otherwise return the complete original word.

### Other modes

For mode one, and for every signed mode value other than zero and two, the function returns the loaded table word unchanged.

No threshold read is established for these modes. Negative mode values do not introduce an error or another filtering rule.

## Side effects

The function performs reads but contains no explicit writes to the descriptor, table, shared fallback word, or other memory.

The established path-dependent read order is:

1. Read the descriptor’s signed count.
2. On the fallback path, read the shared fallback word and return the constructed result.
3. On the table path, read the descriptor’s table address.
4. Read the selected 32-bit table entry.
5. For mode zero or two only, read the unsigned 16-bit threshold.

This ordering matters when describing the source-level dependencies: the table entry is acquired before the threshold is consulted, and the threshold does not participate in deciding whether to take the fallback path.

No allocation, deallocation, ownership transfer, reference-count change, or callback appears in the supplied function. The descriptor and table are borrowed for reading; the function does not establish how their lifetimes are managed elsewhere.

There is no explicit error return, exception handling, or recovery path. Invalid accesses may fail according to the execution environment, but a specific fault type or recovery behavior is not established.

The evidence does not establish atomic reads, synchronization, a consistent snapshot across fields, or behavior under concurrent mutation.

## Acceptance examples

These are conditional behavioral examples derived from static evidence, not recorded executions. They assume readable storage, stable input data, and address arithmetic valid for the target environment.

### Index equal to count

Given count three, index three, and fallback word `0x00001234`, the result is `0x00031234`.

The fallback path is selected even if a physically accessible fourth table entry exists. Changing the mode does not change this result.

### Fallback preserves upper bits

Given count one, index two, and fallback word `0x80010005`, the result is `0x80030005`.

The index contributes `0x00020000`. The fallback’s existing upper bits remain present because the operation is bitwise OR.

### Mode-zero equality

Given a selected table word of `0x00051234` and threshold five:

- Mode zero returns zero.
- The lower half, `0x1234`, does not affect the filtering decision.

### Mode-zero value above threshold

Given a selected table word of `0x00061234` and threshold five, mode zero returns `0x00061234` unchanged.

The result is not reduced to its upper half.

### Different comparisons in modes zero and two

Given a selected table word of `0x00010000` and threshold `0xFFFF`:

- Mode zero returns zero because the upper half is one.
- Mode two returns `0x00010000` because the full unsigned word is 65,536, greater than 65,535.

This difference is required by the two comparison widths.

### Mode-two boundary

Given threshold seven:

- A selected word of seven produces zero in mode two.
- A selected word of eight produces eight in mode two.

The equality case is filtered.

### Unrecognized mode

Given a selected word of `0x89ABCDEF`, modes one, three, and negative one each return `0x89ABCDEF`.

This remains true regardless of the threshold’s value. The established path does not read that field.

### Negative index

Given count three and index negative one, the function selects the table path rather than the fallback path.

If the address four bytes before the table address is valid readable storage containing `0x11223344`, and the mode is one, the result is `0x11223344`. Without valid storage at that address, normal return is not guaranteed.
