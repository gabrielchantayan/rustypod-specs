# F-5f1f20605f4f

## Purpose

F-5f1f20605f4f conditionally updates a receiver using a supplied 32-bit selection value.

The supplied static representation establishes two paths:

- When a receiver flag is nonzero, the function records the selection value and returns without invoking dependencies.
- Otherwise, it stores an option byte, resolves the selection through an embedded receiver region, performs several dependency calls, constructs temporary state, optionally submits an operation, records the selection, and invokes temporary-state cleanup.

The names “selection,” “submission,” and “cleanup” describe apparent roles, not independently verified subsystem semantics. The available evidence does not establish what is selected, whether submission changes a display or another subsystem, or whether the final recorded selection denotes a successfully completed operation.

## Behavior

### Initial flag and early return

The first visible operation is an 8-bit read at receiver offset `0xEC`.

If that byte is nonzero:

- The selection value is written as a 32-bit value at receiver offset `0xE4`.
- The function returns.

On this path, the function does not directly write the option byte, read the additional halfword, construct temporary state, or invoke any dependency. Neither integer control argument affects this path.

A nonzero flag includes every nonzero byte representation; the test does not distinguish positive from negative character interpretations.

### Full-processing prefix

If the initial flag is zero, the function directly writes the option byte at receiver offset `0xE8`.

It then calls F-1f46730b1ced with:

1. The address of the receiver region beginning at `0xB4`.
2. The selection value.

The result is used as a handle-like 32-bit value.

If this result is zero, the function calls F-a817d8d58c10. The supplied representation marks that dependency as nonreturning. Under that assumption, this invocation never reaches the remaining processing, the recorded-selection write, or temporary-state construction. The earlier option-byte write has already occurred.

If the resolver result is nonzero, the following dependency calls occur in order:

1. F-d2f99870cc43 receives the resolved value and produces a 32-bit result.
2. F-89eab22346b0 receives the receiver address plus `0x94` and that result.
3. F-81a479b6091f receives the receiver address.
4. F-fa8898fa75ae receives the resolved value.

Results from the latter three calls are not used by this function. Their names, ownership effects, and mutations cannot be established from their call sites alone.

In particular, F-fa8898fa75ae must not be assumed to release or invalidate the resolved value: the caller retains that value and may pass it to a later dependency. Conversely, this later use does not prove that F-fa8898fa75ae leaves it valid; that is a dependency-contract question.

### Temporary-state construction

After that prefix, F-818c773e8c8a is called twice, separately.

The ordering is significant:

1. Call F-818c773e8c8a.
2. Read one byte at offset `0x2C` from its returned address.
3. Call F-818c773e8c8a again.
4. Read a 32-bit word at offset `0x28` from the second returned address.
5. Call F-2c5a9f9c1eb3 with the temporary-storage address, the word from the second lookup, and the byte saved from the first lookup.

The two returned addresses need not be equal. The byte and word can therefore originate from different context objects or different context states. Replacing these calls with a single lookup would not preserve the established call and read sequence.

The saved byte is read before the second lookup. The word is read after that lookup and before F-2c5a9f9c1eb3 is called.

### Mode-dependent submission

After temporary-state construction, F-5c5958cfd5fe is called, and its integer result is compared with exactly `8`.

If the result equals `8`, submission is skipped. This path performs no third F-818c773e8c8a call and no direct read of receiver offset `0xEA`.

For every other result, the function calls F-818c773e8c8a once more. Its returned value becomes the first submission argument.

The final submission argument is selected as follows:

| Suppression argument | Operation argument | Final submission argument |
|---|---|---|
| Zero | Nonzero | The 16-bit value read from receiver offset `0xEA`. |
| Zero | Zero | A 16-bit zero. |
| Nonzero | Any value | A 16-bit zero. |

The receiver halfword is read only in the first row. That read occurs after the third context lookup returns. Accordingly, if that lookup changes the receiver through some external alias, the read observes the later receiver state rather than an earlier snapshot.

F-fdd8589eca2d is then called with five arguments:

1. The result of the third context lookup.
2. The temporary-storage address.
3. The original resolved value.
4. The original 32-bit operation argument.
5. The selected 16-bit value.

The operation argument is forwarded unchanged, not converted to a Boolean. For example, a negative nonzero operation argument takes the nonzero branch and remains that same value in the submission call.

The suppression argument is not forwarded. Its only visible role is the zero/nonzero decision governing the additional halfword.

### Completion sequence

1. The selection value is written as a 32-bit value at receiver offset `0xE4`.
2. F-920630e53283 is called with the temporary-storage address.
3. The function returns normally if that dependency returns normally.

The recorded-selection write therefore occurs after submission, when submission is performed, but before finalization. A finalization dependency can observe or modify receiver state through means not visible here; no preservation guarantee is established.

The initial flag is not reread. Changes to that flag during dependencies do not cause the function itself to switch to the early-return path.
