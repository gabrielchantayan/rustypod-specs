# F-5c468e0d5d59

## Purpose

F-5c468e0d5d59 selects one of two embedded state regions, passes that region and two writable 32-bit working values to F-34ea3c5c30f1, then calls F-94964b40d6d6 using the resulting working values. It replaces bit 5 of a byte in the input object with the least significant bit of the latter dependency’s byte-valued result.

The supplied static representation establishes this data flow. It does not establish the semantic meaning of the selected regions, the working values, or the resulting flag. Describing the operation as a calculation, classification, or status update would be inferred intent, not a demonstrated domain-level contract.

The function has no explicit return value. Its directly visible output is the updated flag byte, together with any effects produced by its dependencies.

## Interface

### Arguments

Four argument positions are present:

| Position | Contract |
|---|---|
| First | Address of a readable and partly writable object. The function accesses fields at byte offsets 0, 21, 44, and 48, subject to the branch taken. |
| Second | An uninterpreted 32-bit value. The supplied body does not read or forward it. |
| Third | An unsigned 32-bit value used to initialize a writable working word. It is not the effective branch selector. |
| Fourth | An uninterpreted 32-bit value used to initialize a second writable working word. |

The representation uses 32-bit integer slots and address-bearing words. Offsets below are byte offsets, avoiding dependence on native host pointer sizes.

The first argument is not checked for nullness, validity, alignment, accessibility, or sufficient extent. Those properties are caller preconditions for every access that the chosen path performs.

### Input-object layout

Only the following fields are established:

| Byte offset | Width | Use |
|---|---:|---|
| 0 | 32 bits | Address-bearing word referring to a related object. |
| 21 | 8 bits | Read and rewritten after both dependency calls; only bit 5 is directly replaced. |
| 44 | 32 bits | Fallback control value passed to F-34ea3c5c30f1. |
| 48 | 32 bits | Initial control value and first branch condition. |

The initial and fallback control values are represented as 32-bit integers. The branch tests the initial value for zero versus nonzero; it does not test positivity. A negative nonzero value therefore selects the same initial branch as any other nonzero value.

### Related-object layout

The address-bearing word at input offset 0 identifies a related object. The following locations are relevant:

| Location | Use |
|---|---|
| Related object + 8 | A 32-bit address-bearing word used only when the initial control value is nonzero. |
| Address obtained from related object + 8, then + 2,831 | An unsigned selector byte. |
| Related object + 280 | Address passed to F-34ea3c5c30f1 on the fallback path. |
| Related object + 368 | Address passed to F-34ea3c5c30f1 when both the initial control value and selector byte are nonzero. |

Computing either region address does not itself establish that the region’s contents are read by this function. The size, alignment, accessibility requirements, and interpretation of those regions depend on F-34ea3c5c30f1.

The selector byte is zero-extended to a 32-bit unsigned value before its zero/nonzero test. Its magnitude otherwise has no established effect.

## Behavior

### 1. Read the initial control value

The function first reads the 32-bit value at input-object offset 48.

This read determines whether the selector-byte lookup occurs. The third argument does not determine that lookup or the eventual region selection.

### 2. Select a region and a control value

There are three cases.

**Initial control value is zero**

The selector lookup is skipped. The function:

1. Reads the fallback control value at input offset 44.
2. Reads the related-object address from input offset 0.
3. Selects the region beginning 280 bytes after that address.

The fallback control value is passed to F-34ea3c5c30f1 even if it is zero or negative.

**Initial control value is nonzero, selector byte is nonzero**

The function:

1. Reads the related-object address from input offset 0.
2. Reads the address-bearing word at related-object offset 8.
3. Reads the selector byte 2,831 bytes after that second address.
4. Selects the region beginning 368 bytes after the related-object address already obtained.

The original control value from input offset 48 is passed to F-34ea3c5c30f1. The fallback control field at offset 44 is not read on this path.

**Initial control value is nonzero, selector byte is zero**

The function performs the same related-object and selector reads described above, then takes the fallback path:

1. Reads the fallback control value at input offset 44.
2. Reads the related-object address from input offset 0 again.
3. Selects the region beginning 280 bytes after this later address.

The repeated read of input offset 0 is part of the supplied representation. The fallback address is not expressed as reuse of the earlier address.

No concurrency or volatile-access contract is established. In particular, this read structure does not establish support for concurrent mutation of the object.

### 3. Initialize writable working values

Two separate 32-bit working words are initialized:

- One receives the third argument, unchanged.
- The other receives the fourth argument, unchanged.

The selector lookup does not replace either initial value. In particular, the third argument remains the initial value of its working word regardless of the selected region or selector-byte magnitude.

### 4. Invoke F-34ea3c5c30f1

The first dependency receives, in argument-position order:

1. The selected region address.
2. The selected 32-bit control value.
3. The address of the working word initialized from the fourth argument.
4. The address of the working word initialized from the third argument.

Both working words may be modified through those addresses. Their values after this call, rather than necessarily their original argument values, drive the subsequent operation.

The wrapper does not inspect an explicit result from this dependency. There is no visible success/failure branch, retry, rollback, or fallback after the call.

The order of argument positions is established. A lower-level order for evaluating individual argument expressions is not established and is not needed to describe the dependency interface.

### 5. Halve the unsigned working word

After F-34ea3c5c30f1 returns, the working word initialized from the third argument is shifted right by one bit as an unsigned 32-bit value.

This is a logical right shift:

- The top bit becomes zero.
- The former low bit is discarded.
- The result is the floor of the current unsigned value divided by two.
- The result lies between 0 and 2,147,483,647 inclusive.

This operation uses the value left by F-34ea3c5c30f1. It is not necessarily a transformation of the original third argument.

### 6. Invoke F-94964b40d6d6

The second dependency receives:

1. The current 32-bit working value initialized from the fourth argument.
2. The shifted unsigned working value.
3. The fixed value 29.

The wrapper consumes a byte-valued result from this call. Only its least significant bit affects the wrapper’s direct output.

The supplied representation does not establish the dependency’s complete return convention or behavior. It establishes only the byte result consumed here and the use of that byte’s low bit.

### 7. Replace bit 5 of the flag byte

After the second dependency returns, the function reads the byte at input-object offset 21.

It then writes that byte with:

- Bit 5 cleared if the dependency result is even.
- Bit 5 set if the dependency result is odd.
- Bits 0–4 and 6–7 preserved from the byte read at this final stage.

Equivalently, the write retains the old byte under mask 223 and inserts either 0 or 32.

Preservation is relative to the value read **after both dependency calls**, not necessarily the value present on entry. If a dependency changes this byte through an alias or other accessible state, that change can affect the final value.

The function then returns without an explicit result.

## Side effects

The only direct write to caller-visible storage shown in the wrapper is the final one-byte update at input offset 21. The read and write form a read-modify-write sequence; no atomicity or synchronization guarantee is established.

Additional effects may occur inside either dependency. This specification does not assume that either dependency:

- Preserves globals or other shared state.
- Leaves the input object or related objects unchanged.
- Avoids allocation or deallocation.
- Preserves the selected region.
- Returns normally.
- Leaves the two working words unchanged.

The wrapper itself shows no allocation, release, ownership transfer, logging, explicit error report, or exception handling.

The working words are local to the invocation. Passing their addresses permits access during the call, but does not establish an ownership transfer or permission to use those addresses after their storage lifetime ends. Whether F-34ea3c5c30f1 retains either address is unknown.

For a normal, defined completion, all accesses must remain valid when they occur. Entry-time validity alone is insufficient if a dependency invalidates storage that the wrapper later accesses, especially the input-object flag byte.

## Acceptance examples

These examples are conditional consequences of the supplied static representation, not executed tests. Each assumes valid required storage and normal return from both dependencies.

### Zero initial control skips selector access

Given an initial control value of zero:

- The address-bearing word at related-object offset 8 and the selector byte are not read by this wrapper.
- F-34ea3c5c30f1 receives the fallback control value and the region at related-object offset 280.
- Changing the third argument from zero to a nonzero value does not change this selection.

The related-object address at input offset 0 is still required.

### Nonzero selector selects the alternate region

Given an initial control value of −7 and a selector byte of 128:

- The initial control is nonzero.
- The unsigned selector byte is nonzero.
- F-34ea3c5c30f1 receives control value −7 and the region at related-object offset 368.
- The fallback control field is not read.

Neither value must equal one.

### Zero selector forces fallback

Given a nonzero initial control and a zero selector byte:

- The selector lookup still occurs.
- The fallback control value is read afterward.
- The related-object address is read again for the region at offset 280.
- The original nonzero control is not the control passed to F-34ea3c5c30f1.

### Dependency mutation controls subsequent arguments

Suppose F-34ea3c5c30f1 leaves:

- The fourth-argument working word equal to 18.
- The third-argument working word equal to 4,294,967,295.

F-94964b40d6d6 then receives 18, 2,147,483,647, and 29. These values follow from the dependency’s resulting working words, regardless of their initial argument values.

If the unsigned working word instead becomes 2,147,483,649, the shifted argument is 1,073,741,824. A sign-extending shift would not satisfy this behavior.

### Flag replacement preserves the other seven bits

If the flag byte read after the second dependency is 255:

- An even dependency result produces 223.
- An odd dependency result produces 255.

If that byte is zero:

- An even result produces zero.
- An odd result produces 32.

Results 1, 3, and 255 all set bit 5; result 2 clears it.

### Dependency changes precede preservation

Suppose the flag byte is zero on entry, a dependency changes it to 129, and the second dependency returns an odd byte. The wrapper’s final write is 161: it preserves the later value’s bits 0 and 7 and sets bit 5.

Preserving only the entry-time byte would not match the shown access order.
