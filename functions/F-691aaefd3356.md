## Behavior

### 1. Obtain the context

F-ecd921e533b1 is called exactly once in the visible body, before any argument-dependent early return.

This happens even for negative arguments and arguments that will later fail the bound comparison. Consequently, “rejected argument” does not mean “no dependency call” or “no observable effects”: the dependency may itself have effects.

There is no explicit null-result check before eligible context accesses.

### 2. Classify the argument

The argument’s numeric representation is interpreted as signed.

If it is negative, the function returns without loading either context field and without reading a table entry. Neither F-4e292a3dd745 nor F-feee9156a257 is called by this path.

Under the 32-bit interpretation, argument representations from `0x80000000` through `0xFFFFFFFF` are negative and follow this path. This remains true even if such a representation would denote a valid address in some other use.

### 3. Read and apply the bound

For every nonnegative argument, the function loads the field at context offset `0x94`.

That load occurs even when the argument is zero. A preliminary null comparison does not remain an independent exclusion on this path.

The selected entry is read only if both conditions hold:

- The argument differs from the loaded bound.
- The argument is less than or equal to that bound under signed comparison.

Together, for this nonnegative path, these conditions establish the effective eligibility rule:

**The index must be nonnegative and strictly less than the signed bound.**

Consequences include:

- A zero or negative bound admits no index.
- An argument equal to a positive bound is excluded.
- A nonnegative argument greater than the bound is excluded.
- A zero argument is admitted whenever the bound is positive.
- Bound representations with the sign bit set do not act as large positive capacities.

If the argument is excluded, the function returns without loading the table-base field or reading an entry.

### 4. Read the selected entry

For an eligible index, the function loads the table base from context offset `0x90`, then reads the four-byte entry at the base plus four times the index.

The visible order of body-level reads is therefore:

1. Bound field.
2. Table-base field.
3. Selected entry.

The table-base field is not loaded on excluded paths. Only the selected entry is inspected; there is no scan or adjacent-entry check.

The entry’s value is tested only for equality with zero:

- Zero causes normal return without either subsequent dependency call.
- Any nonzero value triggers the call sequence below.

No particular nonzero value has special meaning in this function. Under the represented 32-bit model, a high-bit-set entry is as nonzero as a positive entry.

### 5. Handle a nonzero entry

For a nonzero selected entry:

1. F-4e292a3dd745 is called without explicit arguments.
2. If it returns normally, F-feee9156a257 is called without explicit arguments.

No context field or table entry is reread between these calls. The entry value, index, and context address are not passed as explicit arguments.

The second call is marked nonreturning in the supplied representation. This supports describing the represented path as having no normal return, but does not establish whether the dependency exits a process, transfers control, raises an exception, or behaves otherwise.

If F-4e292a3dd745 does not return normally, the evidence does not establish execution of the second call.
