# F-9647f90132cc

## Purpose

F-9647f90132cc recognizes a restricted decimal prefix, conditionally writes a signed 32-bit result, and returns a 64-bit value containing a success indicator in its low 32 bits.

The established behavior is narrower than a general-purpose integer parser:

- One optional leading ASCII sign is recognized.
- Any zeros immediately following that sign, or at the beginning of unsigned input, are skipped.
- At most eleven subsequent decimal digits are examined.
- Acceptance requires fewer than eleven digits in that bounded digit scan and a value within the signed 32-bit range.
- A decimal digit is not required. Empty input and several malformed prefixes are accepted as zero.
- Trailing nondecimal bytes are neither rejected nor consumed by any externally visible cursor.

The return value is not a conventional 64-bit Boolean. Its upper 32 bits depend on the accepted value or the rejection path. In particular, an accepted negative, nonzero number does not return the whole-number value one.

The apparent intent is signed 32-bit decimal conversion. That intent is inferred; the prefix rules, write behavior, and return layout below are established by the supplied static evidence.

- Bits 31–0 contain exactly one on acceptance and zero on rejection.

- Nonnegative accepted values use their ordinary unsigned bit representation.
- Negative accepted values use their 32-bit two’s-complement representation.
- Negative zero is written as zero.

On rejection, the output location is not written.

No consumed-length result, end pointer, or diagnostic category is exposed.

## Behavior

### 1. Initial sign and zero prefix

The first input byte is read to determine whether it is ASCII minus or ASCII plus.

Only an ASCII minus in this first position selects negative conversion. ASCII plus advances past the sign without selecting negative conversion. No other sign position is recognized.

After this optional sign, the function skips consecutive ASCII zero bytes. Without a sign, it performs this same zero skipping from the original input position.

Consequences include:

- Leading whitespace is not skipped.
- Leading zeros do not count against the later eleven-digit limit.
- A second sign is a nondigit, not another sign operator.
- A sign need not be followed by a digit.
- An arbitrarily long readable sequence of leading zeros can be traversed before the bounded scan begins.

The zero-skipping phase stops on the first byte other than ASCII zero. That byte becomes the first candidate for the bounded digit scan.

### 2. Bounded decimal scan

Starting at the end of the zero prefix, the function examines bytes as unsigned 8-bit values.

Only bytes in the inclusive ASCII range `0` through `9`, numerically 48 through 57, are decimal digits. A zero byte, a space, punctuation, a second sign, and bytes outside this range terminate the scan.

The scan accumulates the magnitude represented by consecutive digits. It stops in either of two ways:

1. A nondigit is encountered before eleven digits have been accumulated.
2. Exactly eleven digits have been accumulated.

In the second case, the function rejects immediately. It does not read a twelfth candidate byte to determine whether the digit run continues.

Because leading zeros were already removed, an eleven-digit run reaching this limit begins with a nonzero digit. A long zero prefix followed by a short nonzero decimal sequence does not reach the limit merely because the complete textual prefix contains eleven or more digits.

If the first candidate is a nondigit, the accumulated magnitude remains zero and the accumulated digit count is zero.

### 3. Magnitude arithmetic and widths

Magnitude accumulation uses two 32-bit words rather than a single signed 32-bit running total.

Let:

- \(B = 2^{32}\).
- \(L\) be the current low word.
- \(H\) be the current high word.
- \(d\) be the next decimal digit, from zero through nine.

The represented magnitude is \(HB + L\). Each accepted digit extends that magnitude by multiplication by ten and addition of \(d\).

A separate intermediate high word is retained during each digit step:

\[
Q = 10H + \left\lfloor \frac{10L}{B} \right\rfloor.
\]

The updated low word is \((10L+d) \bmod B\). The updated high word is \(Q\), plus any carry produced when adding \(d\) to the low word of \(10L\).

The distinction between \(Q\) and the completed high word matters to the return value on eleven-digit rejection.

For all magnitudes reachable through this scan, these calculations represent the decimal magnitude exactly. Eleven digits are at most 99,999,999,999, which fits within 64 bits. The high-word arithmetic also remains far below 32-bit overflow in the reachable domain.

### 4. Acceptance range

When fewer than eleven digits have been accumulated, acceptance depends on the sign selected by the initial byte.

| Initial sign selection | Accepted magnitude |
|---|---|
| No minus sign | 0 through 2,147,483,647 inclusive |
| Minus sign | 0 through 2,147,483,648 inclusive |

Thus the stored result lies in the inclusive signed 32-bit interval:

\[
-2,147,483,648 \leq x \leq 2,147,483,647.
\]

The sign selection remains relevant even when no digits were scanned. Nevertheless, both positive zero and negative zero are accepted and stored as zero.

For an accepted negative, nonzero magnitude, the output word is the magnitude negated modulo \(2^{32}\). No output store occurs before the acceptance decision.

### 5. Return on acceptance

The exact accepted return patterns are:

| Stored result | 64-bit return pattern |
|---|---|
| Zero or positive | `0x0000000000000001` |
| Negative and nonzero | `0xFFFFFFFF00000001` |

The second pattern, interpreted as signed 64-bit, is −4,294,967,295.

The upper word is therefore consistent with sign extension of the stored 32-bit result, but the lower word is a success indicator rather than the stored result.

### 6. Return on rejection

All rejection paths return zero in the low 32 bits and leave output memory unchanged.

There are two distinct upper-word rules.

**Eleven-digit rejection.** The upper word is \(Q\) from the eleventh digit step: the intermediate high word before the carry from adding that digit. It is not necessarily the completed magnitude’s high word.

**Range rejection after fewer than eleven digits.** Let \(H,L\) be the completed magnitude words, and let \(s\) equal one if the first byte was minus and zero otherwise. Define:

- \(a = 1\) when \(L < s\), otherwise zero.
- \(b = 1\) when \((L-s) \bmod 2^{32}\) exceeds 2,147,483,647, otherwise zero.

The returned upper word is:

\[
-(H-a+b) \pmod {2^{32}}.
\]

This formula describes the observable rejection value; it is not an additional success criterion for callers to reconstruct.

No separate error code identifies missing digits, trailing characters, or malformed sign sequences. Those conditions can be accepted as zero or as a shorter numeric prefix.

## Side effects

### Observable memory access order

The established order is:

1. Read the first input byte for sign classification.
2. Traverse the optional sign and leading-zero prefix.
3. Read digit candidates in increasing address order.
4. Either reject without an output store, or perform one 32-bit output store after all input reads needed for that result.

There are relevant repeated reads:

- Without an initial sign, the first byte is read again when testing the zero prefix.
- The nonzero byte that ends zero skipping is read again as the first digit candidate.
- A nondigit encountered during digit scanning is read but does not contribute to the magnitude.

No input byte beyond the eleventh accumulated digit is read on the digit-limit path.

These details matter if input resides in volatile or externally changing storage. The simple decimal-prefix interpretation assumes stable input during the call. Behavior under concurrent mutation cannot be replaced with an assumption that each position is sampled only once.

### Ownership and aliasing

The function does not allocate or release memory, retain either address, or invoke a dependency that might do so.

Input storage is not written through the input address. Output storage may overlap input storage: the supplied evidence shows that the output store occurs only after scanning is finished. Such overlap can therefore modify the input bytes after their use, provided the resulting 32-bit store is otherwise valid.

No global-state reads or writes are visible in the supplied function.

### Errors

Invalid or inaccessible memory is not converted into an ordinary rejection result. The function contains no explicit recovery mechanism for access faults.

A readable sequence consisting indefinitely of zeros has no internal zero-prefix length limit. Execution continues reading until a nonzero byte is encountered or the environment prevents further progress.
