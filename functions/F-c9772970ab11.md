# F-c9772970ab11

## Purpose

F-c9772970ab11 modifies selected words in caller-supplied storage, then uses an unresolved dependency to obtain temporary data and submit a constructed two-word result.

Two stages are established by the supplied static representation:

1. Eight selected 32-bit words are individually byte-reversed in place.
2. Eight calls obtain data through invocation-local addresses. Selected byte lanes from that temporary storage form two result words, which are supplied to a ninth call.

The first stage does **not** reverse either selected 16-byte group as a whole: word positions remain fixed, and only the byte order within each word changes.

**Inferred intent:** The dependency resembles an eight-byte copying operation. Under an exact-copy contract, stable source contents, suitable temporary layout, and defined 32-bit evaluation, the second stage reverses the trailing eight-byte region as a whole. This interpretation is conditional; the dependency’s implementation is unavailable.

## Behavior

### Direct transformation stage

Words are processed in this order:

**0, 1, 2, 3, 5, 6, 7, 8.**

For each position, the current word is read and its replacement is written to the same position before the next selected word is processed. There is no whole-input snapshot and no deferred batch of writes.

Each replacement reverses the four numeric byte lanes:

| Original numeric byte lane | Replacement numeric byte lane |
|---|---|
| Most significant | Least significant |
| Second most significant | Second least significant |
| Second least significant | Second most significant |
| Least significant | Most significant |

For example, a word containing `0x12345678` is replaced with `0x78563412`.

These direct operations use unsigned 32-bit values. The byte lanes do not overlap in the result, and no carry between lanes is involved. The numeric transformation is independent of host byte order; relating numeric lanes to increasing memory addresses requires the platform’s byte-order convention.

Word 4 is skipped. The eight direct writes all precede the first dependency call.

### Width and signed-operation boundary

The direct word stage uses unsigned 32-bit arithmetic. The assembly stage differs: the full word supplying the highest byte of each result is represented as a signed 32-bit operand before a 24-bit left shift.

For a literal interpretation with ordinary signed-shift rules, each of those two full operands must be between **0 and 127 inclusive** for that operation to be defined. This restriction applies to the full operand, not merely its least significant byte.

A positive operand larger than 127 can overflow the signed result even if its selected byte looks harmless. A negative operand also lacks a defined result under those rules.

Therefore, arbitrary 32-bit temporary values do not have an unconditional, fully defined language-level result. An authoritative fixed-width execution model could establish the intended bit-pattern behavior more broadly, but that model was not supplied.
