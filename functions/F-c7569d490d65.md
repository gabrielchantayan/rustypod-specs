# F-c7569d490d65

## Behavior

### Lookup-table selection precedes normalization

The function selects a lookup-table address before consulting the context flags or calling another function:

- Selector `0x58` selects one table-address calculation.
- Every other selector selects the alternative calculation.

Each calculation combines an opaque stored value with a fixed address base. The supplied material does not establish either resulting table’s contents.

For clarity, this contract calls the first selection **table U** and the alternative **table D**. These labels do not assert uppercase or lowercase contents.

The table address is selected once. It is not recomputed after F-def43b609842 returns. This distinction matters because that dependency’s effects on global state are unknown. Selecting an address early does not snapshot the bytes stored at that address: table-byte reads occur later.

### Effective value selection

The function reads the 32-bit flags field at context offset `0x18`.

- If bit `0x80` is set, the incoming low and high words remain the effective value.
- If bit `0x80` is clear, the function calls F-def43b609842 with the incoming low word followed by the context address. Its returned 32-bit value becomes the effective low word, and the effective high word becomes zero.

The original high word is therefore discarded whenever bit `0x80` is clear, regardless of its value.

No preservation guarantee for F-def43b609842 is established. In particular, it must not be assumed to preserve context fields, lookup-table contents, global state, or memory ownership.

### Prefix selection and selector-specific context updates

After optional normalization, the function reads the flags field again and tests bit `0x08`. This is a fresh read, not reuse of the earlier flags value. Changes made by F-def43b609842 can therefore affect this decision.

There are four distinct prefix-data addresses in the visible logic. This contract names them **P0**, **P1**, **P2**, and **P3**. Their contents and allocation extents are unknown.

The prefix pointer initially selects P0, and the prefix length initially equals zero.

For selector `0x70`, the function performs another flags read for the update, writes that value ORed with `0x20` back to offset `0x18`, and then writes the 32-bit value eight to offset `0x38`. The two writes occur in that order and precede digit generation.

The update preserves the bits present in the value read for that update. It is not established to be atomic or safe against concurrent modification.

The value eight is a context-field assignment. The local conversion does not itself produce eight digits, add zeroes, or enforce a minimum digit count.

### Digit-byte generation

The function uses a temporary buffer with a capacity of 32 bytes. It generates bytes only while the effective two-word value is nonzero.

Each generated byte corresponds to the current least-significant four bits. Those four bits select an index from zero through fifteen in the previously selected table. The selected byte is appended to the temporary buffer.

The effective value then advances by an unsigned four-bit right shift across the two-word boundary. Bits from the high word enter the upper end of the low word, and the high word shifts right with zero fill. The individual operations have 32-bit unsigned semantics; shifted-out bits do not enlarge the value.

Consequently:

- Bytes are stored least-significant nibble first.
- The first initialized byte corresponds to the original effective value’s lowest nibble.
- A nonzero value produces no extra most-significant zero nibble.
- An effective zero produces zero digit bytes, not an explicit digit for zero.
- A retained 64-bit value produces at most sixteen bytes.
- A value replaced by a 32-bit dependency result produces at most eight bytes.

The visible algorithm therefore cannot exhaust the 32-byte temporary buffer under its established word widths.

The function does not append a terminator. Only the generated byte range is initialized by this conversion. For a zero-length result, none of the temporary digit buffer is initialized by the conversion.

The table byte is read before its corresponding temporary-buffer byte is written. Successive digit bytes are generated in increasing buffer position.

### Final delegation

After all local context updates and digit generation, the function calls F-a65df3f1d4a0 exactly once on every normally completing path.

The call occurs even when:

- The effective value is zero.
- The digit count is zero.
- The prefix length is zero.
- Selector `0x70` has changed the context but produced no digit bytes.

The temporary-buffer pointer and a prefix-data pointer are supplied even when their corresponding lengths are zero. The caller does not establish whether F-a65df3f1d4a0 refrains from reading such pointers in that case.

No local work follows the dependency call other than returning. Any result produced by that dependency is not exposed as an explicit return value here.
