# F-bf5fc0e57292

## Purpose

F-bf5fc0e57292 invokes an ordered chain of indirect dependencies, transforms returned machine words, and performs mixed-width memory accesses through fixed and computed addresses. Its visible endpoint is an unresolved indirect transfer with four supplied arguments.

The supplied static representation does not establish an application-level purpose. Character-like constants and self-referential stores do not establish text processing, record initialization, or a particular data structure.

This contract distinguishes:

- **Established static evidence:** explicitly represented calls, value dependencies, access widths, and ordering.
- **[INFERENCE]:** interpretations conditional on a stated machine model.
- **documented_only:** behavior not resolved into an executable requirement by the available evidence.

No runtime tests have been performed.

## Interface

### Inputs and outputs

The visible interface declares no explicit arguments and no return value. It nevertheless depends on incoming execution state and shared memory.

Implicit inputs include:

- An incoming return-link value used to derive the first indirect target.
- Primary and secondary results of indirect invocations.
- Memory reached through fixed addresses, returned words, scaled words, and loaded words.
- A separate shared word loaded late and used as a publication base.
- The unresolved final transfer target.

Some dependency results are represented as 64 bits, with independently consumed low and high 32-bit halves. Other invocations supply a primary 32-bit result or an additional secondary word. The actual calling convention is **documented_only**.

There is no explicit success indicator, error result, output object, or output length. If the final transfer returns, the visible routine subsequently returns without an explicit value. Whether that transfer returns is unresolved.

## Behavior

### Indirect-invocation prefix

The first phase is a long straight-line sequence of indirect invocations. The initial target depends on incoming return-link state plus 4094. Subsequent targets use embedded continuation-like values with the same displacement.

This mechanism does not establish target identity or equivalence. Invocations with unused results remain observable events. A displayed call without explicit arguments does not prove that its target consumes no implicit execution state.

The contract preserves:

- Invocation order and explicitly supplied argument positions.
- Repeated arguments and explicit zeros.
- Distinctions between earlier captured results and later results.
- Low-word, high-word, and secondary-result provenance.
- Intervening invocations even when a derived argument is provably zero.

Common transformations shift primary results left by eight bits. Other arguments place bits at positions through 31, repeat shifted low words, or combine a high word with shifted derivatives of that same high word.

Unsigned operations include masks selecting low fields of widths 11 through 14, 16 through 22, and 24 bits. Particular distinctions include extracting bits 10–19 before further shifting, masking to 24 bits before a shift, and masking a high word to 22 bits before shifts by 3, 7, or 8.

Unsigned extraction from a 64-bit result by 34, 36, or 44 bits is equivalent to logically shifting its high 32-bit half by 2, 4, or 12 bits. These are not signed extractions.

### Arithmetic model

Unsigned masks and logical right shifts establish bit-field behavior directly.

**[INFERENCE]** Under a 32-bit machine-word model, left shifts discard bits leaving the word and scaled addresses retain the low 32 bits. Address formulas and bounded-index examples below are conditional on that model where overflow matters.

This does not establish portable semantics for signed left shifts, signed overflow, or signed address arithmetic. A late signed right shift uses the low eight bits of a computed address as its count. Counts above 31 and right shifts of negative values remain **documented_only**; count masking must not be invented.

### Entry to direct memory access

For describing the access groups:

- The **shifted destination** is an earlier result shifted left by 25 bits.
- The **sample base** is a different captured result multiplied by \(2^{25}\).
- The **small index** comes from a primary result shifted left eight bits, masked to 15 bits, then logically shifted right six bits.
- The **small base** is twice that index.
- The **shifted payload** is another captured primary result shifted left eight bits.

Under the conditional 32-bit model, the small index is a multiple of four from 0 through 508; the small base ranges from 0 through 1016.

The last dependency result supplies two 32-bit halves. Before the first byte sample, the function stores the shifted destination as a word at high-half-plus-20, writes the high half’s low byte at shifted-destination-plus-9, stores the sample base at low-half-times-256-plus-84, overwrites the earlier byte destination with the shifted destination’s low byte, and clears the word at sample-base-plus-20.

These are separate ordered accesses, including both writes to the same byte destination.

### Early sampling, fixed accesses, and cross-reference updates

The function samples the byte at sample-base-plus-5, clears the word at small-base-plus-20, and publishes the sample as a zero-extended word at sample-base-plus-52. It then captures the word at sample-base-plus-20, repeats the small-base word clear, and performs two identical byte stores at small-base-plus-21 using the captured word’s low byte.

The next fixed access is an unsigned byte read at **address 5**. That byte becomes another base. Immediately afterward, a byte store at **address 1** receives the small base’s low byte. The function then writes the small index’s low byte at byte-derived-base-plus-21.

Further updates write the shifted payload’s low byte at sample-base-plus-17, store the shifted payload through captured-word-plus-84, and clear the byte at sample-base-plus-17. The old word at byte-derived-base-plus-84 is captured before that location is replaced with the earlier captured word. This old value is the **retained scale value** used throughout the next phase.

Subsequent operations publish the small index at small-base-plus-52, follow offset-116 words, and perform repeated self-reference and low-byte writes. Reloads through offset 116 remain reads; equality with an earlier capture is not guaranteed.

A significant fixed-access interleaving occurs during these updates:

- A word at small-base-plus-20 first receives a shifted derivative of the earlier sample-base result.
- A **32-bit write at address 84** receives twice the retained scale value.
- The small-base-plus-20 destination then receives the retained scale value twice.
- Two byte stores at small-base-plus-21 receive the low byte of four times the retained scale value.
- A **byte write at address 21** then receives the small base’s low byte.

The address-84 word write and address-21 byte write are not interchangeable with the surrounding computed-address stores. Aliasing and device-memory effects remain possible.

### Scaled-address and constant-write phase

The retained scale value generates four-times and eight-times addresses. The function mixes word links, byte samples, and low-byte stores through those addresses and through words loaded from them.

A byte sampled at offset 5 is used as an address component for an offset-116 word read. It is not established as a length or tag. A later byte sample from a loaded base is followed by another such offset-116 read; that later read supplies a value whose double becomes the **late linked base**.

Repeated stores at offsets 9, 13, 20, 21, 68, and 84 remain distinct accesses. Captured values survive intervening stores, but explicit later loads cannot be replaced merely because addresses appear related.

The value underlying the late linked base also supplies the constant-write destinations:

- Byte value 58 at its four-times address.
- Halfword value 58 at its eight-times address.
- Word value 58 at offset 32 from its four-times address.

The **adjusted scale value** is four times the retained scale value minus 150. The **adjusted base** is four times that adjusted scale value.

At adjusted-base-plus-32, four word writes occur in order: 32, 47, a zero-extended byte sampled from adjusted-base-plus-4, and 32 again. The byte sample occurs after the write of 47 and before the sampled-value write. These intermediate events are part of the behavior.

### Publication run

The function next loads the separate shared word that becomes the **publication base**. After that load, but before any publication group, it performs a **32-bit write of 32 at address 96**.

The publication run is finite and statically expanded. Each group contains, in order:

- A word store at offset 84 through an eight-times-scaled destination.
- A byte store at publication-base-plus-25 containing the adjusted base’s low byte.
- A byte store at adjusted-base-plus-17 containing the publication base’s low byte.
- A word store at publication-base-plus-52 containing the scaled destination.

The first group uses eight times the retained scale value. Subsequent groups use eight times the adjusted scale value. Every offset-84 destination receives four times the value underlying the late linked base.

The exact cardinality of this expanded run is **documented_only in this contract**. It must not be interpreted as an infinite loop or collapsed into a single group. “Publication” describes the repeated stores, not a synchronization guarantee.

### Final fixed-access interleaving

After the publication run, the function captures the **32-bit word at address 169**, then captures the word at offset 116 from the four-times-scaled constant-write base.

Only after those two reads does it write the byte at **address 58**, using eight times the adjusted scale value plus 48, truncated to eight bits.

The next reads capture:

- The word at late-linked-base-plus-20, retained for the final transfer’s third argument.
- The word at adjusted-base-plus-4, retained for a later publication-base-plus-116 store.

Thus, the offset-20 and offset-4 reads occur **after** the address-58 byte write, not before it.

Following several computed-address byte stores and a self-reference word store at late-linked-base-plus-84, the function writes the address-169 capture’s low byte to **address 103**.

It then reads the word at late-linked-base-plus-68 before explicitly reading the byte at **address 103** to supply a byte write at **address 33**. The address-33 value is therefore the result of that later byte read, not an unconditional reuse of the original address-169 capture.

### Final computed-address updates

The captured offset-68 word supplies a byte store at adjusted-base-plus-16 and a word store at publication-base-plus-84. It also supplies the signed variable-count right shift whose result is truncated into a byte at late-linked-base-plus-1. The count is the adjusted base’s low eight bits. Publication-base-plus-84 is subsequently overwritten with the adjusted base.

The function reads adjusted-base-plus-64 before publishing the earlier offset-4 capture at publication-base-plus-116 and storing the offset-64 capture as a word at adjusted-base-plus-16. The earlier byte store at that offset and this word store are distinct overlapping accesses.

The next address-103 observations are separate:

- After the publication-base-plus-68 store, an explicit byte read at **address 103** supplies a store at adjusted-base-plus-9.
- Between that read and the next address-103 read, the function writes a byte at late-linked-base-plus-9, stores the original address-169 word capture at adjusted-base-plus-68, and reads adjusted-base-plus-84.
- A second explicit byte read at **address 103** then supplies another store at adjusted-base-plus-9.

Including the read supplying address 33, there are three explicit address-103 byte reads after its initial write. Their results need not agree if aliasing, device behavior, or external mutation intervenes.

The adjusted-base-plus-84 capture becomes another destination base. The function publishes low-byte fragments through that base and the late linked base, restores the retained offset-20 word at late-linked-base-plus-84, and separately reads adjusted-base-plus-20. It later writes the adjusted-base-plus-84 capture’s low byte at adjusted-base-plus-9 and the full capture at adjusted-base-plus-68.

### Final argument provenance and transfer

A word read at late-linked-base-plus-4 supplies the **halfword base**. The function writes halfword value 101 at twice that base, then reads the word at halfword-base-plus-100. This is the **retained second argument**.

After that capture, the function writes a low-byte fragment through the adjusted-base-plus-84 capture and writes word value 100 at offset 84 from that same destination. It then reads halfword-base-plus-116, retaining the result for the final fourth argument.

A later, distinct word read at **late-linked-base-plus-100** supplies the **later destination value**. It does not replace the retained second argument. After a byte store at late-linked-base-plus-9:

- The retained second argument is stored at later-destination-value-plus-84.
- The later destination value is stored as a word at twice the retained second argument.

The final indirect transfer receives:

1. Integer 114.
2. The retained word from **halfword-base-plus-100**.
3. The earlier retained word from **late-linked-base-plus-20**.
4. The word from **halfword-base-plus-116**.

## Acceptance examples

These examples are conditional requirements, not executed tests.

### Unsigned split-result extraction

If a 64-bit result has high word 0x80000010, unsigned extraction by 34 bits yields 0x20000004. Sign extension is incompatible with the represented extraction.

### Small-index bounds

Under the 32-bit model, the small index is divisible by four and lies between 0 and 508. Its doubled base lies between 0 and 1016.

### Fixed-write ordering

If the relevant path completes, an access observer sees the address-5 byte read before the address-1 byte write. Later, the address-84 word write precedes the address-21 byte write. The publication-base load precedes the address-96 word write of 32, which precedes the first publication group.

### Final interleaving

An observer sees the address-169 word read and constant-base offset-116 read before the address-58 byte write. The late-linked-base offset-20 read and adjusted-base offset-4 read follow that write.

### Fresh address-103 samples

Suppose the explicit address-103 reads return 0x41, 0x42, and 0x43, and execution otherwise proceeds. Address 33 receives 0x41; the two corresponding adjusted-base-plus-9 stores receive 0x42 and 0x43. Substituting the initial address-103 write’s value for all three reads is incorrect.

### Distinct offset-100 captures

Suppose halfword-base-plus-100 yields 0x1000, while the later late-linked-base-plus-100 read yields 0x2000. Under valid, nonfaulting address conditions, the final transfer’s second argument remains 0x1000. The later stores place 0x1000 at 0x2054 and 0x2000 at 0x2000. The later load does not become the second argument.

### Intermediate writes and truncation

The adjusted-base offset-32 write sequence includes 32, 47, the sampled byte widened to a word, and 32. A byte-store input of 0x123456AB stores 0xAB; adjacent bytes are not thereby specified.
