# F-a980b3403655

## Purpose

F-a980b3403655 has no established application-level purpose. The supplied static representation describes:

- An optional 16-bit memory transfer selected by the second explicit argument.
- A chain of conditional arithmetic and memory operations.
- A terminal loop containing two indirect calls and software interrupt 91.

The evidence does not establish initialization, decoding, allocation, error handling, or another higher-level role.

Under a conventional valid-frame interpretation, the conditional operations after the initial transfer are excluded by an early address-dependent gate. The resulting behavior is an optional 16-bit transfer followed by the terminal execution sequence. This reduction depends on the represented address arithmetic and the fifth argument having valid, nonzero, suitably aligned storage; it is not a runtime observation.

## Behavior

### Initial selection

The second argument is multiplied by 4096 using the represented 32-bit arithmetic. The product selects the initial path; it is not itself unconditionally dereferenced.

The product is zero exactly when the second argument’s low 20 bits are zero. Thus all 4096 values of the form \(k \times 2^{20}\), for \(0 \leq k < 4096\), select the initial transfer.

The representation also inspects bit 18 of the second argument. That bit is necessarily zero whenever the transfer is selected. Replacing the selection rule with “the second argument equals zero” would change behavior.

### Initial 16-bit transfer

If the product is zero:

1. The destination address is formed by adding the inherited byte displacement to the inherited source address.
2. One unsigned 16-bit value is read from the inherited source address.
3. The source-address working state is changed to the destination address minus the inherited subtraction operand.
4. The captured 16-bit value is written to the destination.

The explicit read precedes the explicit write. The working-state update lies between them in the representation, but its observability as a register change depends on the unresolved ABI.

The displacement is measured in bytes. It is not scaled by the size of the transferred value.

The transfer is not omitted when source and destination are equal. No explicit null, range, alignment, access-permission, or overlap check precedes either access.

This path also forms:

- An address-shaped value equal to the inherited link-like address plus half the unsigned address of the fifth argument’s storage. The inspected argument bit contributes zero on this path.
- The second argument multiplied by 8192, which is also zero whenever this path is selected.

After the transfer, the working value used by the first continuation gate is the inherited link-like address.

### Address-dependent continuation

The conditional continuation is a chain: failure of a zero-result gate prevents the later gates in that chain from executing. Later blocks are not independent alternatives.

The first gate requires both selection of the initial transfer and a zero inherited link-like address. With a nonzero link-like address, the chain stops immediately.

With a zero link-like address, the next significant zero test reduces to testing half the unsigned fifth-argument storage address. Therefore:

> If the fifth argument has a nonzero, at-least-two-byte-aligned storage address in the represented 32-bit address space, the subsequent conditional memory blocks do not execute.

For example, storage at byte address `0x00002000` produces `0x00001000`, which fails the required zero test.

If unconventional argument-storage addresses are admitted, that early reduction alone does not settle every later gate. The representation includes additional comparisons, shifts, unsigned carry calculations, and address arithmetic. The corresponding memory blocks are documented below as `documented_only`; listing their effects does not establish that they are jointly reachable.

In particular, this contract does not turn the exceptional blocks into independently selectable behaviors or assume that satisfying one visible condition satisfies the whole preceding chain.

### Terminal execution sequence

After the conditional sections, the represented loop has this order:

1. Invoke F-unknown-01 with three explicit 32-bit arguments: 0, 0, and `0xffffffa5`.
2. If that call returns, invoke F-unknown-02 with no explicit arguments shown.
3. If that call returns, execute software interrupt `0x5b`, decimal 91.
4. If execution continues, replace the first call’s working base with `0x083d4cc2`.
5. Repeat.

The represented target of F-unknown-01 is its current working base plus `0xeb6` bytes. This displacement accounts for the representation’s 16-bit pointer scaling.

On the conventional valid-frame path, the first iteration uses the inherited link-like address as that base. The exceptional conditional blocks contain assignments that can alter the represented first-iteration base; their reachability is not established here.

The represented numeric target of F-unknown-02 is `0x0857a94b`. Neither target expression establishes a load of a function-pointer value from the target address.

If both calls and the interrupt return, the first target from the second iteration onward is `0x083d5b78`.

The third argument to F-unknown-01 has the exact 32-bit pattern `0xffffffa5`: −91 if interpreted as signed, or 4,294,967,205 if interpreted as unsigned. The dependency’s interpretation is unknown.

No call return value is explicitly used. There is no normal loop exit.

## Side effects

### Conventional valid-frame paths

If the second argument’s low 20 bits are nonzero, the represented body performs no explicit data-memory access before the terminal call sequence.

If those bits are zero, it performs the initial 16-bit read and write before entering that sequence.

This statement excludes instruction fetching, ABI-imposed argument handling, and dependency effects. It does not assert that the indirect calls or interrupt leave memory unchanged.

### Exceptional conditional blocks

The following effects are present in the static representation. Their status is `documented_only`: they are conditional on the complete preceding gate chain, and their executable reachability has not been demonstrated.

**Special machine-state assignment.** A block assigns the fifth argument’s storage address multiplied by 64 to a special machine-state location. The same block computes a link-derived address with the corresponding 64-times-storage-address byte displacement.

A later block explicitly reads the special location, shifts the represented value right by one, and uses it in address arithmetic. Every represented path reaching that read first executes the assignment. The incoming contents of the special location are therefore not an established entry dependency. The location’s architectural meaning and the executable semantics of its access remain unresolved.

**Two-read indirect 16-bit store.** After the special-state assignment, the representation contains two separate unsigned 16-bit reads through the then-current link-like address:

- One read supplies the destination address. Its unsigned 16-bit result is used as the numeric address.
- The other read supplies the value calculation. Fifteen is added, and the result is truncated to 16 bits for the store.

Both reads precede the store. Their relative evaluation order is not established by the representation.

The two observations need not be equal. The destination must not be specified as necessarily derived from the value used in the addition, or vice versa. Collapsing these accesses into one captured read would change behavior for volatile, device, or concurrently modified memory.

The block subsequently updates the link-like working address and advances another address-shaped working value by two bytes.

**Narrowed-address pointer read.** A later block reads a 16-bit value through its current link-like address, narrows it to a character-sized value, adds four, and performs a pointer-sized, 32-bit read at the resulting address.

Whether narrowed values with bit 7 set become negative before the addition is unresolved. The 16-bit read precedes the pointer-sized read because it determines that read’s address.

This block also changes inherited working arithmetic values by 8 and 10 and forms a destination-related address 13 bytes beyond the current link-like address. These are represented working-state changes, not established writes to caller-owned storage.

**First pair of 32-bit stores.** Another gated block:

- Reads a 16-bit value from a computed source address and interprets it as signed.
- Writes its sign-extended 32-bit value at a computed destination base.
- Writes a previously obtained pointer-sized value four bytes beyond that base.

The source read precedes both stores. The store at the base precedes the store at base plus four. The block also changes the working base that can feed the first terminal call.

**Final pair of 32-bit stores.** A final gated block forms a signed 16-bit source address 13 bytes beyond the then-current working base and advances that working base by 27 bytes. It then:

- Reads and sign-extends the 16-bit source value.
- Stores that 32-bit value at the address obtained by subtracting `0x08574200` from it.
- Stores a previously obtained pointer-sized value four bytes beyond that destination.

The signed read precedes both stores, and the first store precedes the second. No address validation is represented.
