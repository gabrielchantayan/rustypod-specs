# F-9e74050178b9

## Purpose

F-9e74050178b9 performs a fixed sequence of memory reads and writes across an incoming object graph, then invokes an unresolved indirect dependency with three arguments.

The supplied static representation establishes memory mutation and argument construction, but not an application-level purpose. Most accesses use fixed field offsets. Later accesses use sums of addresses, doubled values, and an address derived from a single byte. These operations must not be replaced with conventional object-management behavior merely because that would appear more plausible.

This is a source-facing contract for the supplied representation, not a runtime-validated specification. Its applicability to an actual executable depends on the accuracy of that representation, particularly its recovered entry state and indirect control transfer.

## Behavior

### Reading conventions

The following description preserves the represented access order. Intermediate names identify values captured at particular times; they do not imply ownership, stable object identity, or non-aliasing.

When a field is explicitly reread, the later read is significant. Earlier writes may affect it through aliasing. A field that is read once and retained is not implicitly refreshed after subsequent writes.

### 1. Entry writes and initial graph traversal

The function first writes the full second input to primary object offset `0x24`. It then writes the entry byte to working object offset `0x19`.

It next reads, in order:

1. A 32-bit value from primary object offset `0x74`, designated **source value**.
2. A 32-bit value from primary object offset `0x04`, designated **initial payload**.
3. An address from working object offset `0x74`, designated **initial root**.

From initial root offset `0x14`, it reads a destination address and writes source value to that destination's offset `0x54`.

It then reads an address from initial root offset `0x04`, designated **initial child**.

The next writes occur in this order:

- The low byte of the second input to working object offset `0x0D`.
- The same byte to the same location again.
- Initial payload, as a full word, to working object offset `0x64`.
- The word value `0x74` to initial child offset `0x30`.

The two consecutive byte writes are both present in the supplied representation. Their duplication must not be silently removed from a contract concerning observable access order.

### 2. Derived links and byte fields

The function rereads initial root offset `0x04`, then reads offset `0x74` through that newly obtained address. The resulting address is designated **intermediate node**.

It reads a full word from working object offset `0x64`, retains its low byte as **payload byte**, and writes that byte to working object offset `0x1D`. This is a real reread, not an unconditional reuse of initial payload.

It then reads working object offset `0x44` as an address and follows that address's offset `0x14`. The result is designated **holder**.

Next, it:

- Writes source value to intermediate node offset `0x34`.
- Writes holder to working object offset `0x14`.
- Reads the word at working object offset `0x54`, retaining it as **previous field value**.
- Writes the low byte of the working object's address to holder offset `0x09`.

The function reads intermediate node offset `0x04` as an address and follows its offset `0x74`, obtaining **leaf**.

It then performs these writes in order:

- Low byte of source value to leaf offset `0x15`.
- Working object's address, as a word, to working object offset `0x54`.
- Low byte of intermediate node's address to working object offset `0x11`.
- Low byte of previous field value to leaf offset `0x11`.

It reads the full word at leaf offset `0x64`, retaining **leaf payload**, then writes payload byte to working object offset `0x09`.

### 3. Child mutation and replacement fields

The function rereads intermediate node offset `0x04`. This address is designated **current child** and need not equal the address obtained from that field earlier.

It writes the low byte of the working object's address to current child offset `0x09`, then reads the full word at current child offset `0x50`, designated **child payload**.

The next writes, in order, are:

- Low byte of leaf payload to current child offset `0x11`.
- Low byte of the working object's address to current child offset `0x09` again.
- Full leaf payload to working object offset `0x14`.
- Low byte of current child's address to working object offset `0x0D`.
- Low byte of child payload to current child offset `0x00`.

The function next reads:

1. A word from intermediate node offset `0x74`, designated **byte displacement**.
2. An address from intermediate node offset `0x14`, designated **secondary object**.

It writes current child's own address to current child offset `0x54`, then reads secondary object offset `0x04` as an address, designated **secondary child**.

The subsequent writes occur in this order:

| Destination | Width | Value |
|---|---:|---|
| Secondary child + `0x10` | 8 bits | Decimal 100 |
| Working object + `0x54` | 32 bits | Decimal 100 |
| Secondary child + `0x40` | 32 bits | Decimal 100 |
| Working object + `0x0D` | 8 bits | Low byte of leaf payload |
| Secondary object + `0x09` | 8 bits | Low byte of secondary child's address |
| Working object + `0x24` | 32 bits | Leaf payload |
| Secondary object + `0x11` | 8 bits | Low byte of the working object's address |

The earlier self-address write to working object offset `0x54` is therefore explicitly replaced with decimal 100. Further changes through aliasing remain possible.

### 4. Arithmetic-address accesses

The function reads global slot A as a 32-bit value, designated **first global value**. It then rereads working object offset `0x74`, obtaining **late root**.

It writes the low halfword of late root to the address formed by adding late root and the working object's address.

Next, it writes the low halfword of first global value to the address formed by doubling secondary child's address-valued quantity. This calculation doubles the value itself; it is not a read through secondary child.

It then reads one byte from the address formed by adding byte displacement and the working object's address. The representation converts this byte through a plain character type and then to an unsigned 32-bit value, designated **byte-derived value**.

The exact signedness of that character type is unresolved:

- For byte values `0x00` through `0x7F`, the resulting value is the same under signed and unsigned character interpretation.
- For byte values `0x80` through `0xFF`, zero extension and sign extension produce different 32-bit results.

The function next writes the low halfword of late root:

1. To the address formed by adding first global value and late root.
2. Again to the address formed by adding late root and the working object's address.

It then writes the 32-bit value `0x45` at byte-derived value plus `0x45`. This is a four-byte write, not a byte write. Alignment and address validity are not checked in the supplied body.

### 5. Final reads, writes, and indirect invocation

After the preceding word write, the function reads:

1. Global slot B, designated **second global value**.
2. Global slot C, designated **third global value**.
3. Working object offset `0x44`, designated **late field value**.

These reads occur late enough that earlier writes could affect them if the corresponding storage aliases an earlier destination.

The final explicit writes are:

- Byte value `0x44` at byte-derived value plus `0x44`.
- Third global value, as a full word, at the address formed by doubling second global value.
- Low halfword of second global value at the address formed by adding source value and second global value.

The byte write at displacement `0x44` occurs after the word write at displacement `0x45`. With ordinary non-wrapping address arithmetic, these writes occupy adjacent, non-overlapping ranges.

The unresolved indirect dependency is invoked with three arguments, in this order:

1. Byte-derived value combined with `0x44` by bitwise inclusive OR.
2. Second global value.
3. Late field value.

The first argument is not an addition. For example, a byte-derived value of `0x01` produces `0x45`, while `0x44` remains `0x44`.

No explicit memory operations follow the invocation in the supplied representation. If the invocation returns normally, F-9e74050178b9 returns.

## Side effects

### Memory mutation

The function mutates the primary object, working object, multiple objects reached through fields, and several arithmetic-derived addresses.

There is no established non-aliasing guarantee. Consequently:

- A write may alter a pointer or value read later.
- Repeated reads of the same field may return different values.
- Repeated writes to one destination remain distinct operations.
- Apparently unrelated arithmetic destinations may overlap earlier fields or global slots.

A final-state description alone is insufficient to capture the represented behavior.

### Ownership and lifetime

Writing an address into another object's field does not establish retention or ownership. Writing a self-address does not establish a list, cycle, or lifetime protocol.

The indirect dependency's memory and ownership behavior is unknown. It must not be assumed to preserve globals, retain arguments, release objects, or leave prior mutations intact.

Normal completion requires every reached access to be supported by the execution environment, and the indirect transfer target to be valid. If an access or the invocation fails, earlier writes may already have occurred. No transactional behavior is established.

## Acceptance examples

These examples are conditional static expectations, not reports of executed tests.

### Explicit-input truncation

Given a second input of `0x123456AB`, execution initially writes `0x123456AB` as a word to primary object offset `0x24`, and later performs two consecutive byte writes of `0xAB` to working object offset `0x0D`.

That byte field is subsequently overwritten. The example establishes the early writes, not its final value.

### Read-after-write aliasing

If initial child offset `0x30` aliases working object offset `0x64`, and no intervening operation changes that word, the later read producing payload byte observes the word value `0x74`. Payload byte is then `0x74`, regardless of initial payload.

This distinguishes the required reread from substituting the previously captured payload.

### Conditional ordinary-field result

If all relevant object fields and arithmetic destinations are disjoint, execution completes, and the indirect dependency does not modify the working object, then working object offset `0x54` ends as the 32-bit value 100.

Its earlier self-address value is not retained.

### Halfword truncation

If late root is `0x12345678` and both relevant calculated addresses support halfword writes, each write carrying late root in the arithmetic-address phase stores the numeric halfword `0x5678`. It does not store the full address value.

The byte ordering of that halfword remains environment-dependent.

### Byte-derived address boundary

If the displacement-based byte read returns `0x7F`, byte-derived value is `0x0000007F` under either character interpretation. The word value `0x45` is written at address `0xC4`, and the later byte value `0x44` is written at address `0xC3`, provided those addresses are accessible.

If the byte is `0x80`, the exact destinations remain `documented_only`: they depend on whether the character conversion yields `0x00000080` or `0xFFFFFF80`, as well as the applicable address arithmetic rules.

### Indirect argument construction

If byte-derived value is `0x01`, second global value is `0x2000`, and the late read of working object offset `0x44` yields `0x3000`, the indirect dependency receives `0x45`, `0x2000`, and `0x3000`, in that order.

This does not establish what that dependency does with those values.
