# F-96c51729fd03

## Purpose

F-96c51729fd03 scans a byte sequence as endian-selected, 16-bit units. It advances by two bytes for an ordinary unit and by four bytes whenever the first unit lies in the inclusive range 0xD800–0xDFFF. A nonnegative limit bounds the number of these scan iterations; a negative limit requests scanning until a zero unit is encountered.

The result is declared pointer-shaped, but the visible return calculation subtracts the numerical starting address from the ending address. Under the apparent 32-bit address-arithmetic model, its numerical value represents a byte displacement, excluding an encountered two-byte terminator. It is not ordinarily a pointer into the supplied buffer.

The apparent intent is a byte-length calculation for UTF-16-like data. That intent is an inference, not a validity guarantee: the routine accepts either half of the surrogate range as a four-byte leader and does not validate the following unit.

## Interface

### Inputs

- **Starting address:** an address of bytes to scan. The routine performs byte accesses; no explicit two-byte alignment requirement appears.
- **Scan limit:** a signed 32-bit integer in the supplied representation.
  - Zero permits no scan iterations.
  - A positive value permits at most that many iterations.
  - Any negative value disables the limit.

The routine also consumes external state:

- **Byte-order selector:** one byte accessed indirectly through an external pointer. Zero selects big-endian interpretation; any nonzero value selects little-endian interpretation.
- **Replacement value:** an external value referenced by a recovery branch after four-byte combination. Under the visible byte widths and arithmetic, that branch is unreachable.

No explicit buffer length is supplied.

### Output

The declared output is a byte pointer. Its visible construction combines:

1. The address immediately after the last consumed unit or four-byte group.
2. A two-byte backward adjustment if the last decoded value was zero.
3. Subtraction of the starting address after conversion of that address to a signed integer.

Under ordinary 32-bit flat-address arithmetic, the numerical result is the consumed byte count, excluding a terminating zero unit. For example, a two-byte payload followed by a zero unit produces a pointer-shaped value numerically equal to 2, not the address two bytes beyond the input.

The portable meaning of this construction is not established. Callers must not assume that the returned value is dereferenceable.

### Preconditions

For defined scanning behavior:

- The external selector pointer must permit a one-byte read, including when the scan limit is zero.
- Every executed iteration must have at least two readable bytes at its current position.
- An iteration whose first decoded unit lies in 0xD800–0xDFFF must have four readable bytes at that position.
- A scan without a finite stopping bound must encounter a zero unit before exhausting readable memory or exceeding the supported arithmetic domain.
- Pointer movement, integer counting, and the return-address calculation must be valid under the actual execution model.

A zero limit avoids input-byte reads, but does not establish that every possible starting-address value is valid for the final pointer/integer calculation.

## Behavior

### Byte-order selection

The routine first reads the external byte-order selector and chooses one of two scan paths.

- Zero: the first byte is the high byte of each 16-bit unit.
- Nonzero: the first byte is the low byte.

The chosen path remains fixed for the call. There is no visible selector reread during scanning, and no byte-order-mark detection or special handling.

### Limit handling

The iteration count starts at zero. Before each prospective iteration, the routine checks whether the limit is nonnegative and has already been reached.

Consequences:

- A zero limit stops before reading input bytes.
- A positive limit is measured in scan iterations, not bytes or 16-bit units.
- A four-byte group consumes one iteration.
- A negative limit is not a request to scan a negative number of elements; it disables this stopping condition.
- Once a positive limit is reached, the routine does not inspect the next unit for a terminator.

The initial decoded-value state is nonzero. Therefore, a zero-limit call does not take the terminator-adjustment path.

### Ordinary two-byte units

At each permitted iteration, the routine reads two bytes and interprets them as an unsigned 16-bit quantity according to the selected byte order.

If that quantity is outside 0xD800–0xDFFF:

- The cursor advances by two bytes.
- The iteration count increases by one.
- A zero quantity ends scanning.
- Any other quantity allows another iteration, subject to the limit.

There is no general content validation. Values outside the surrogate interval are not rejected because of their Unicode meaning.

### Four-byte groups

If the first quantity lies anywhere in 0xD800–0xDFFF, the routine consumes a second two-byte quantity in the same byte order and advances by four bytes in total.

Both 0xD800–0xDBFF and 0xDC00–0xDFFF trigger this behavior. The routine does not require a high-surrogate leader.

The second quantity is not checked for membership in 0xDC00–0xDFFF. Only its low ten bits contribute to the combined value. A zero second quantity is therefore consumed as part of the group; it is not treated as a terminator.

For a first quantity \(A\) and second quantity \(B\), the combined value is:

\[
0x10000
+ 0x400 \times (A \mathbin{\&} 0x3FF)
+ (B \mathbin{\&} 0x3FF)
\]

This expression describes the arithmetic effect rather than prescribing an implementation.

The resulting range is 0x10000–0x10FFFF:

- Each masked contribution is at most 0x3FF.
- The largest scaled contribution is 0xFFC00.
- The complete sum fits in unsigned 32-bit arithmetic.

Accordingly, a four-byte group cannot produce zero and cannot itself terminate scanning.

### Replacement branch

After combining a four-byte group, the routine tests whether the result shifted right by 16 bits is zero. If so, it would substitute the external replacement value.

Under the established operand widths, the combined value is always at least 0x10000. The condition is therefore false for every possible four input bytes.

The replacement branch does not provide reachable malformed-input handling in the supplied representation. In particular, it does not reject an isolated low surrogate, an invalid following unit, or a truncated buffer before reading it.

### Stopping and result formation

Scanning stops either:

- Before an iteration because a nonnegative limit has been reached; or
- After an iteration whose ordinary two-byte quantity was zero.

At either point, the cursor is already positioned after everything consumed by completed iterations.

When termination was caused by a zero quantity, the routine subtracts two bytes in its final result calculation. Thus the terminator is read and counted internally as an iteration, but excluded from the returned displacement.

When termination was caused by the limit, no two-byte adjustment is applied.

Under the apparent displacement interpretation:

- Each completed nonterminating ordinary iteration contributes two bytes.
- Each completed four-byte iteration contributes four bytes.
- An encountered zero terminator contributes no bytes to the result.

The zero terminator is excluded even if it is encountered on the last iteration allowed by the limit.

## Side effects

### Observable reads

The visible read sequence is:

1. Read the external pointer used to locate the byte-order selector and read its selector byte.
2. Check the limit before reading any input bytes.
3. For each permitted iteration, read the two bytes of the first unit.
4. If that unit is in the surrogate interval, read the next two bytes before advancing to another iteration.
5. Repeat until the limit or a zero ordinary unit stops scanning.

The supplied expression structure does not establish a universal machine-level order between every pair of byte loads used as arithmetic operands. It does establish the unit-level dependency: the decision to consume a second unit depends on the decoded first unit.

No read beyond the four bytes of a surrogate-triggered iteration is needed to complete that iteration. Conversely, the routine does not check readability before attempting those four bytes.

### Writes and ownership

No writes to the input buffer or external state are visible. Cursor, counter, and decoded-value changes are internal.

There are no visible allocations, releases, callbacks, or ownership transfers. The function neither demonstrates ownership of the input nor releases it. The unusual result representation provides no evidence of a newly allocated object.

### Errors

There is no explicit error result or validation failure path.

Insufficient readable input, an invalid selector pointer, or arithmetic outside the supported execution model is not converted into a documented return value. The exact fault or other consequence is not established by the supplied material.

## Acceptance examples

These examples are static consequences, not runtime observations. They assume valid readable storage, stable external state, and the apparent 32-bit displacement interpretation of the return value.

### Zero limit

For any buffer contents and a limit of zero:

- The selector is read.
- No input bytes are read.
- The numerical result is zero.

This example does not waive the requirements of the final address calculation.

### Empty sequence

Given an initial zero unit and a limit of one or any negative limit:

- Two input bytes are consumed.
- Scanning stops immediately afterward.
- The numerical result is zero because the terminator is excluded.

### One ordinary unit followed by termination

With big-endian selection, bytes 00 41 00 00, and a negative limit:

- The first iteration consumes 00 41.
- The second consumes the zero unit.
- The numerical result is 2.

With little-endian selection, bytes 41 00 00 00 produce the same result.

### Limit reached before termination

With big-endian bytes 00 41 00 42 00 00 and a limit of one:

- Only the first two bytes are read.
- Neither the second unit nor the terminator is inspected.
- The numerical result is 2.

With a limit of two, the result is 4 and the terminator remains unread.

### Conventional surrogate pair

With big-endian bytes D8 3D DE 00 00 00 and a limit of one:

- The first four bytes are consumed as one iteration.
- The computed combined value is 0x1F600.
- The zero unit following the group is not read.
- The numerical result is 4.

With a negative limit, the following zero unit is read and excluded, leaving the same numerical result.

### Low-surrogate leader

With big-endian bytes DC 00 00 41 and a limit of one:

- The first unit triggers four-byte consumption despite being in the low-surrogate subrange.
- The second unit is accepted without validation.
- The numerical result is 4.

This behavior distinguishes the routine from a strict UTF-16 validator.

### Zero in the second unit

With big-endian bytes D8 00 00 00 00 41 00 00 and a negative limit:

- The first four bytes form one group; their combined value is 0x10000.
- The embedded zero second unit does not terminate the scan.
- The next ordinary unit is consumed.
- The final zero unit terminates scanning.
- The numerical result is 6.

### Truncated four-byte group

If only two bytes are readable and they decode into the surrogate interval, even a limit of one requires two additional byte reads. No bounded-buffer error result is established.

## Uncertainties

### Established static behavior

The supplied representation establishes endian selection, pre-iteration limit checking, two- versus four-byte advancement, permissive surrogate handling, terminator exclusion, and the absence of visible writes or calls.

### Inferred intent

A UTF-16-like byte-length operation is a plausible interpretation. The four-byte combination resembles surrogate decoding, but the lack of pair validation prevents treating Unicode validity as part of the contract.

The pointer-shaped result likely carries a numerical byte length under a particular machine representation. That interpretation must remain conditional.

### documented_only

The following are not established:

- The authoritative machine ABI, pointer width, and pointer-to-integer conversion rules.
- Whether the declared pointer return type matches the original interface.
- Portable semantics of subtracting the converted starting address through pointer arithmetic.
- Behavior if the signed iteration count exceeds 0x7FFFFFFF during an unbounded scan.
- Behavior when signed intermediate arithmetic in result formation overflows.
- Buffer extent, selector lifetime, and concurrent mutation guarantees.

- Fault behavior for unreadable memory.

These unknowns must not be resolved by assuming saturation, wrapping, recovery, validation, or a different return type.

## Evidence

The evidence consists solely of the supplied static function representation.

Its distinguishing observations are:

- One external selector determines byte order before the limit check.
- The scan limit is signed and checked before every iteration.
- The surrogate trigger covers the full 0xD800–0xDFFF interval.
- A triggered iteration consumes four bytes without validating the second unit.
- The combination arithmetic yields only 0x10000–0x10FFFF, making the replacement branch unreachable.
- The cursor advances before zero termination is acted upon.
- Final result formation removes the two-byte terminator and subtracts the starting address numerically.
- No function calls, memory writes, allocations, or releases are visible.

No runtime tests have been performed. The acceptance examples are conditional arithmetic and control-flow consequences, not observed execution results.
