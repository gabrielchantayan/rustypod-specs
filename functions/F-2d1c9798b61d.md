# F-2d1c9798b61d

## Purpose

F-2d1c9798b61d performs an ordered prefix of indirect calls and byte writes, then repeatedly executes a call-and-write cycle with no visible termination condition.

The repeating cycle carries three independent components of state: two values used to construct call arguments and a base used to select an indirect-call target. The first cycle uses a different target base from subsequent cycles.

The supplied static representation establishes these operations, not their application-level purpose. It does not establish device initialization, serialization, decoding, allocation, or protocol handling.

This contract covers the represented path. Reported instruction-data and reachability problems limit conclusions about the complete executable behavior. No runtime tests have been performed.

| Second argument | No explicit use in the represented body. |

The first and fourth arguments are represented as unsigned 32-bit values. The other two slots are uninterpreted 32-bit quantities.

The absence of explicit uses for the second and third arguments does not establish that they are irrelevant to the actual machine-level calling convention.

### Implicit entry state

These are entry-state dependencies, not established public-interface fields.

### Result and completion

No explicit result or reachable normal return appears on the represented path.

The cycle continues indefinitely provided that invoked dependencies return, memory accesses complete, and no fault or other control transfer prevents progress. No success result, failure status, completion notification, or cancellation interface is established.

### Widths and arithmetic

Direct data-memory accesses are one byte wide. Selector reads interpret the byte as an unsigned value from 0 through 255. Values retained from calls and used in arithmetic are represented as 32-bit quantities.

The contract distinguishes:

- Unsigned right shifts, masks, and byte truncations established by the representation.
- Left shifts and multiplication involving signed-looking intermediates, whose overflow behavior requires additional machine-level evidence.

Where stated, **32-bit wrapping interpretation** means retaining the low 32 bits of a calculation. Conditional examples using that interpretation are not claims that every signed-looking expression has independently verified wrapping semantics.

Address-space validity, address overflow behavior, and the execution platform’s treatment of indirect targets are not established.

## Behavior

### Initial context-selected write

Before the first visible call:

1. Read one unsigned byte at the context address plus one.
2. Add `0x11` to that byte’s value.
3. Write the low eight bits of the first argument to the resulting address.

The selector is used directly to construct an address. No separate buffer base is established. The resulting destination is between `0x11` and `0x110`, inclusive.

Every later context-selected write performs another selector read. A selector value must not be treated as cached across calls or preceding writes.

### Establishing cycle state

Form the initial **secondary argument state** by masking the result of F-000000000024 with `0x3FFFFFFF` and logically shifting right by 25. Its range is 0 through 31.

Next perform a seed-selected zero write:

1. Multiply the retained shifted address seed by `0x400`.
2. Add one to obtain a selector-read address.
3. Read one unsigned byte at that address.
4. Add `0x11` to the loaded value.
5. Write zero to the resulting destination.

Under the 32-bit wrapping interpretation, the selector-read address is the address seed shifted left by 12, plus one, reduced to 32 bits. Its low 12 bits are `0x001`.

This selector source differs from the context-based source. Its selected destination still ranges from `0x11` through `0x110`.

Invoke F-000000000025 with the initial secondary argument state shifted left by one. This argument is even and ranges from 0 through 62.

Establish the initial **target-base state** as `0x08832789` before invoking F-000000000026. Retain the result of F-000000000026 as the initial **primary argument state**. The represented path carries the target-base state into the first cycle.

### Repeating cycle

Each cycle has the following observable sequence:

1. Invoke F-000000000027 through the current target-base state plus `0xFFE`. Pass the current primary argument state and the current secondary argument state logically shifted right by eight.
2. Invoke F-000000000028.
3. Invoke F-000000000029.
4. Invoke F-000000000030.
5. Invoke F-000000000031 and retain its 32-bit result.
6. Reread the seed-derived selector byte, using the address calculation described above, and write zero to its selected address.
7. Invoke F-000000000032 with the result of F-000000000031 shifted left by two.
8. Invoke F-000000000033.
9. Invoke F-000000000034.
10. Invoke F-000000000035.
11. Set the target-base state to `0x088327C7`, then invoke F-000000000036 and retain its result.
12. Replace the primary argument state with that result shifted left by two.
13. Replace the secondary argument state with that same result shifted left by 26.
14. Continue at the beginning of the cycle, carrying all three state components across the back edge.

F-000000000027 therefore has two represented target expressions:

| Invocation | Target base | Target expression |
|---|---:|---:|
| First cycle | `0x08832789` | `0x08832789 + 0xFFE = 0x08833787` |
| Every subsequent cycle | `0x088327C7` | `0x088327C7 + 0xFFE = 0x088337C5` |

These are different target values. Their relationship to underlying executable functions is unknown. They must not be assumed to identify the same function.

The target-base state is independent of the primary and secondary argument states. Changing the result of F-000000000036 changes the next argument states, not the represented assignment of the next target base.

On the first cycle, F-000000000027’s second explicit argument is necessarily zero because the initial secondary argument state is at most 31.

On subsequent cycles, under 32-bit wrapping shifts, that argument is the preceding F-000000000036 result’s low six bits shifted left by 18. It ranges from zero through `0x00FC0000` in multiples of `0x00040000`.

The seed-derived selector address remains based on the retained address seed, not either changing argument state or the target-base state. The selector byte is nevertheless reread every cycle.

## Side effects

### Direct memory effects

The finite prefix performs **six byte writes**, in this order:

1. First-argument low byte through the context selector.
2. First-argument bits 22 through 29 through a fresh context selector read.
3. Shifted address-seed low byte at the fourth-argument-derived address.
4. Zero through a fresh context selector read.
5. Zero through another fresh context selector read.
6. Zero through the seed-derived selector.

These involve five explicit selector-byte reads: four context-based reads and one seed-derived read. The fourth-argument-directed write does not require a selector read.

Each completed cycle adds one seed-derived selector read and one zero write. Calls remain interleaved with these accesses exactly as described in Behavior.

No direct allocation, deallocation, bulk copy, ownership transfer, or wider data-memory write is visible. This does not constrain effects inside dependencies.

### Aliasing and ordering

No non-aliasing guarantee is established. A destination may overlap a selector source or memory used by a dependency.

Consequently:

- Selector reads cannot be merged or hoisted across intervening operations.
- Equal-valued zero writes cannot be removed merely because earlier writes also stored zero.
- Calls cannot be reordered around the represented reads and writes.
- Earlier selector values do not determine later destinations.

The contract specifies access order, not a verified concurrency, synchronization, or memory-mapped-I/O model.

### Ownership and failures

The body does not visibly establish ownership of accessed memory or explicitly acquire or release storage.

Dependencies may affect globals, memory, ownership, or control flow. Their behavior and machine-state preservation must not be assumed.

There is no explicit validation, error-reporting, recovery, or rollback path. An inaccessible selector source, unwritable destination, invalid indirect target, or nonreturning dependency may prevent further progress. The resulting platform behavior is undocumented.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Each assumes execution reaches the stated operations and the relevant calls and accesses complete.

### First-argument extraction

For a first argument of `0xABCDEF12`:

- The initial write stores `0x12`.
- The later extraction write stores `0xAF`.
- If their respective selector reads yield 3 and 8, their destinations are `0x14` and `0x19`.

Using the first selector for both writes would not preserve the required reads.

### Fourth-argument calculation

For a fourth argument of `0x00000100` and an address seed of `0x0000003F`:

- The fourth-argument-directed write targets `0x1E` and stores `0xFC`.
- F-000000000013 receives 2.
- F-000000000015 receives zero.

### Mask boundary

For an address seed of `0xC0000000`, F-000000000015 receives zero because the mask removes both high bits.

Under wrapping arithmetic, the seed-derived selector-read address is 1. This calculation does not establish that address 1 is readable.

### First-cycle arguments and target

If F-000000000024 returns `0x3E000000`:

- The initial secondary argument state is 31.
- F-000000000025 receives 62.
- The first F-000000000027 invocation receives zero as its second explicit argument.
- Its represented target expression evaluates to `0x08833787`.

### Independent target and argument transitions

If the first F-000000000036 invocation returns `0x00000041`, then under wrapping shifts:

- The next primary argument state is `0x00000104`.
- The next secondary argument state is `0x04000000`.
- The next F-000000000027 invocation receives `0x00040000` as its second explicit argument.
- Its represented target is `0x088337C5`, not the first-cycle target.

Even if that result were zero, the next target would still be `0x088337C5`; zero argument states do not reset the target-base state.
