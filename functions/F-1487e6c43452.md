# F-1487e6c43452

## Purpose

F-1487e6c43452 generates packed 16-bit values from consecutive pairs of source rows. For every position in each row except the last, it combines the current-row value with the value at the same position in the next row. The current row receives three times the weight of the next row.

The established arithmetic treats each value as three unsigned fields of widths 5, 6, and 5. Each output field is the rounded-down result of the weighted combination.

After filtering, the function reads a globally stored function pointer and invokes the target obtained from that read. The invocation receives the remaining destination position, the remaining current-source position, and a doubled-width expression. The target is obtained at this final stage, not captured before filtering.

**Inferred intent:** vertically biased RGB565 blending followed by copying the last row. The field layout and final argument pattern support this interpretation. Neither the color interpretation nor copying by the selected dependency is established.

## Interface

The represented interface has four inputs and no explicit return value.

| Input | Represented type | Meaning |
|---|---|---|
| Source | Pointer to unsigned 16-bit elements | Initial current-row position |
| Destination | Pointer to signed 16-bit elements | Initial output position |
| Width | Signed 32-bit integer | Elements per row and inner-loop bound |
| Height | Signed 32-bit integer | Row-count control |

These widths describe the supplied representation. Pointer width and the complete calling convention are not independently established.

### Layout and interpretation

Source rows are contiguous. There is no separate row-stride parameter. One row spans Width elements, each occupying two bytes.

The output calculation is a packed-bit operation, not signed averaging. A stored 16-bit pattern with its highest bit set may be interpreted as negative through the destination’s signed element type; that does not change the field arithmetic.

No external byte order is selected. The function accesses native 16-bit elements, so interpreting raw bytes requires knowledge of the execution environment.

### Preconditions for ordinary defined operation

For a conventional positive-size transformation:

- Width and Height are positive.
- Source and Destination satisfy the alignment and memory-access requirements of the represented element types.
- Every filtering read and write is within valid storage.
- The initial pointer one Width beyond Source, and all subsequent pointer advances, are valid.
- Height minus one is representable as a signed 32-bit integer.
- Width is at most 1,073,741,823, so doubling it by signed left shift remains within the nonnegative signed 32-bit range.
- The final global function-pointer read is valid.
- The target obtained by that read is callable with the supplied arguments.
- Any additional requirements imposed by that target are satisfied.

For positive dimensions, filtering reads across Height source rows and writes Width × (Height − 1) destination elements. Any additional destination capacity requirement depends on the selected target.

These are preconditions, not checks. The function does not validate dimensions, buffer lengths, pointers, or the selected target.

## Behavior

### Traversal

Before deciding whether to filter, the function forms a following-row pointer one Width beyond Source.

Filtering proceeds when Height minus one is positive. Within each selected row, element processing proceeds only when Width is positive.

For positive Width and Height greater than one:

- Exactly Height minus one rows are generated directly.
- Rows are processed in increasing order.
- Elements within each row are processed in increasing order.
- Each output uses the current source position and the position one Width later.
- After each output, Destination and both source positions advance by one element.

The filtering phase therefore writes Width × (Height − 1) elements. This expression describes the mathematical extent; the function does not compute a total-size product or validate it.

The final source row contributes to the preceding generated row. Filtering does not directly generate an output from the last row alone.

### Packed arithmetic

For stable current and following values, the calculation consists of two packed averaging stages:

- First, average the current value with the following-row value.
- Then, average the current value with that intermediate result.

Each stage uses common bits and a shifted differing-bit contribution. The differing-bit contribution excludes zero-based bit positions 5 and 11 before shifting. This keeps the calculation independent across these fields:

| Field | Bit positions | Unsigned range |
|---|---|---|
| Low | 0–4 | 0–31 |
| Middle | 5–10 | 0–63 |
| High | 11–15 | 0–31 |

For corresponding current and following field values \(a\) and \(b\), the final field is:

\[
\left\lfloor\frac{a+\left\lfloor(a+b)/2\right\rfloor}{2}\right\rfloor
=
\left\lfloor\frac{3a+b}{4}\right\rfloor.
\]

This equivalence applies independently to all three fields.

There is no rounding to nearest, saturation operation, signed-field interpretation, or color-space conversion. Each result stays within its field’s original range.

The first stage additionally clears bit 16 of its widened result. For stable unsigned 16-bit inputs, the packed average already fits within 16 bits, so that clearing does not alter the result. Narrowing the intermediate value to 16 bits likewise loses no significant bits under these conditions.

### Access ordering within filtering

For each generated element:

1. The current source value is read and retained.
2. The following-row expression is evaluated using that retained value.
3. The final result is stored at the current destination position.
4. Processing continues at the next element.

The following-row element appears twice in the intermediate expression. The representation does not establish two separately observable physical loads or an ordering between those expression operands.

The weighted-field formula therefore assumes stable ordinary memory. It does not establish a contract for concurrent modification, volatile storage, or memory-mapped devices.

The destination store follows the source evaluations needed for that output. Later iterations can observe changes caused by earlier stores. The function does not snapshot the image or either row.

### Final global read and indirect invocation

After filtering completes normally, including when filtering performs no element accesses, the function obtains its call target by reading a globally stored function pointer.

This global read occurs after the filtering phase and its destination stores. The target is not saved before filtering. Consequently, the contract cannot assume that dispatch uses whatever target was stored at function entry.

The selected target is referred to here as **F-INDIRECT-01**, an opaque dependency-role label. This label does not identify a guaranteed fixed function.

The invocation supplies these arguments in order:

1. Destination after all directly generated elements.
2. The current-source position after all directly generated elements.
3. Width shifted left by one.

For ordinary positive dimensions, the first two arguments identify the beginning of the last output row and the last input row. The third argument is numerically twice Width.

The representation does not establish whether the global function-pointer storage is immutable, writable, or protected from overlap with destination writes. If preceding stores can affect that storage, the subsequent target read uses its then-current contents, subject to the execution environment’s memory rules. No entry-time target guarantee applies.

The function does not inspect a result from the selected target or convert it into a status. It returns normally only if the selected target returns normally.

### Zero and negative dimensions

**Height equal to one:** filtering performs no element reads or writes. After the initial following-row pointer calculation, the function reads the global target and invokes it with the original Destination, original Source, and doubled Width.

**Height equal to zero or a negative value other than the signed minimum:** filtering is skipped. The final global target read and invocation still occur, provided preceding arithmetic and pointer operations are valid. Nonpositive Height is not a no-op convention.

**Width equal to zero:** filtering performs no element accesses. If Height exceeds one, the outer row control still advances through Height minus one iterations. Source and Destination do not advance. Final dispatch receives the original pointers and a third argument of zero. Neither the global target read nor effects of the selected target are eliminated.

**Negative Width:** the inner filtering body does not execute, but the initial following-row pointer is still formed. The final signed left shift has no portable defined meaning for a negative operand. Negative Width is not an established empty-image convention.

**Minimum signed Height:** subtracting one exceeds the signed 32-bit range. No portable behavior is specified.

**Excessively large positive Width:** a value above 1,073,741,823 cannot be doubled by the represented signed left shift within the nonnegative signed 32-bit range. The function does not guard against this.

## Side effects

### Direct memory and global effects

Filtering directly reads unsigned 16-bit source elements and writes 16-bit destination elements.

After filtering, the caller explicitly reads global storage to obtain the indirect-call target. This is a direct global access by F-1487e6c43452, independent of any global accesses performed by the selected dependency.

There is no explicit assignment to a named global in the supplied body. That does not establish global-state preservation:

- Destination writes are address-based; their possible overlap with global storage is not ruled out.
- The selected target may read or modify globals.
- The mutability and protection of the target-pointer storage are unknown.

The visible body performs no explicit allocation, release, resource acquisition, or ownership transfer.

### Aliasing

The visible interface does not require distinct source and destination buffers. Nevertheless, arbitrary overlap can alter later filtering inputs.

A destination store that overlaps a future current-row or following-row element can change a later result. The resulting behavior follows traversal and access order, not an original-image snapshot.

For exact Source/Destination equality, valid positive dimensions, and stable ordinary memory, the filtering phase reads the current and following values before overwriting the current position. Earlier filtering stores do not overwrite source positions needed later in that exact-alias arrangement.

This does not establish complete in-place support. Final dispatch receives equal source and destination positions, and the selected target’s equal-pointer and overlap rules are unknown. Any interaction with the global target-pointer storage must also satisfy the actual environment’s memory rules.

### Errors and ownership

There is no explicit error return, null check, bounds check, target validation, or recovery path.

Invalid accesses can fail during filtering, during the final global target read, or inside the selected target. An invalid target can prevent a valid invocation. If the selected target fails to return, this function does not return normally.

The visible body neither acquires ownership of the buffers nor releases them. No ownership, retention, release, or global-preservation guarantees are established for the selected dependency.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Filtering-result examples assume valid dimensions and pointers, stable ordinary source memory, and destination stores that do not corrupt inputs needed later.

### Equal neighboring values

For Width one, Height two, and both source values 0xFFFF:

- Filtering stores 0xFFFF in the first destination element.
- The final global target read occurs after that store.
- The selected target receives Destination advanced by one element, Source advanced by one element, and 2.

The last destination element becomes 0xFFFF only if the selected target performs the inferred copy or an equivalent write.

### Maximum current value, zero following value

For current value 0xFFFF and following value 0x0000:

- The high, middle, and low output fields are 23, 47, and 23.
- The generated bit pattern is 0xBDF7.

The destination’s signed interpretation does not turn the field calculation into signed averaging.

### Zero current value, maximum following value

For current value 0x0000 and following value 0xFFFF:

- The high, middle, and low output fields are 7, 15, and 7.
- The generated bit pattern is 0x39E7.

This distinguishes the transformation from equal-weight averaging.

### Field isolation and rounding

For current value 0xF800 and following value 0x001F, the generated result is 0xB807: high field 23, middle field zero, low field 7.

For current value 0x0001 and following value 0x0000, the generated result is zero. The fractional contribution is discarded.

### Multiple rows

For Width two and Height three:

- Two outputs combine the first and second source rows.
- The next two combine the second and third source rows.
- After those four stores, the global target is read.
- The selected target receives Destination advanced by four elements, Source advanced by four elements, and 4.

The original-row interpretation requires that preceding destination stores have not changed later source inputs.

### Empty filtering phase

For Height one, there are no direct filtering reads or stores, but final target selection and invocation remain required.

For Width zero and valid preceding operations, final dispatch receives the original pointers and zero. This does not imply total memory inactivity: the caller still reads the global function pointer, and the selected target may access memory.

### Target selection after writes

If the actual environment permits filtering stores to change the global function-pointer storage, and those stores leave a valid callable pointer there, final dispatch selects the pointer present after those stores—not a value captured at entry.

If that storage is immutable or cannot overlap the destination, this particular redirection scenario does not arise. Neither storage condition is established by the supplied representation.
