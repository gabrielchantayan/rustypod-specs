# F-d204a1130613

## Purpose

F-d204a1130613 validates a six-byte request, selects one of nine operation descriptors, and conditionally invokes the selected operation against an adjusted context receiver and an acquired object.

Its directly visible responsibilities are:

- Reject an unexpected request length or unsupported selector values.
- Decode a 32-bit request operand through a dependency.
- Acquire an object and require successful initialization.
- Select an operation descriptor, with additional behavior for selectors 5 and 8.
- Invoke a present descriptor using its receiver-adjustment and direct/indirect dispatch encoding.
- On a zero callback result, clear a shared-state byte and, for most selectors, call a completion dependency.
- Pass the acquired-object slot to a finalization dependency before an ordinary return.

The apparent intent is a command dispatcher. The meanings of the nine commands, the operand, and the shared-state fields are not established.

## Interface

### Arguments and representation

The function takes two arguments represented as 32-bit address-bearing values:

| Argument | Required accessible data |
|---|---|
| Context | A byte at offset `0x2EC` on certain branches, plus whatever storage the selected callback descriptor requires for receiver adjustment and dispatch. |
| Request descriptor | A two-byte length field at offset `0x0C`; when that field equals 6, a four-byte payload pointer at offset `0x08`. |

The payload layout is:

| Offset | Width | Meaning established here |
|---|---:|---|
| `0x00` | 1 byte | Operation selector. Accepted values: 1 through 9. |
| `0x01` | Decoder-defined access | Start address passed to F-c25a2fcc75b5 to obtain a 32-bit operand. |
| `0x05` | 1 byte | Secondary selector. Accepted values: 0 through 9, or `0xFF`. |

Although the arrangement suggests a four-byte operand occupying offsets 1–4, the decoder’s implementation and actual read extent are unavailable. Its byte order, alignment requirements, and memory-access behavior are **documented_only**.

The length field is interpreted as a 16-bit value and compared with 6. Whether described as signed or unsigned does not change that equality test.

The visible representation uses four-byte object pointers, descriptor words, shared-state pointer fields, and callback-related words. It does not establish portability to a different pointer-width model.

### Return value

The function returns a 32-bit status:

| Status | Established condition |
|---:|---|
| 0 | A selected callback returned zero, and subsequent visible processing returned normally. |
| 1 | Initial setup succeeded, but the selected descriptor was absent. |
| 2 | A selected callback returned a nonzero low 32-bit result. |
| 4 | The length or selector validation failed, or selector 5’s unsigned operand bound check failed. |

Acquisition or initialization failure does not produce an ordinary error return in the supplied representation: it enters F-a817d8d58c10, represented as non-returning.

These statuses describe this function’s branches. They do not establish application-level meanings such as “unsupported,” “completed,” or “retry.”

### Preconditions

The function performs no visible null-pointer or accessibility checks for the request descriptor, accepted payload, context, global configuration bases, virtual tables, or selected dispatch targets.

Callers must provide storage sufficient for the path taken. In particular:

- A length other than 6 requires only the length-field access before return.
- Length 6 requires the payload-pointer load, payload reads, and decoder call even if the selector will later be rejected.
- An accepted selector requires usable acquisition and initialization dependencies.
- A present callback descriptor requires a valid adjusted receiver and callable target.
- Selector-specific virtual calls require a valid acquired object and corresponding virtual-table entries.

Failures of these preconditions have no defined recovery behavior in the supplied evidence.

## Behavior

### 1. Length gate and payload interpretation

The first visible operation is the request length read at offset `0x0C`.

If it is not 6, the function returns 4. It does not visibly load the payload pointer, decode an operand, acquire an object, or finalize an acquired-object slot on that path.

For length 6, the visible order is:

1. Load the payload pointer from request offset `0x08`.
2. Read the operation byte at payload offset 0.
3. Call F-c25a2fcc75b5 with the address at payload offset 1.
4. Read the secondary-selector byte at payload offset 5.
5. Validate both selector bytes.

The accepted operation range is 1–9 inclusive. The accepted secondary-selector set is 0–9 inclusive plus `0xFF`.

An invalid operation or secondary selector returns 4, but only after the decoder has been called. Consequently, malformed selectors do not imply an absence of dependency side effects.

### 2. Object acquisition and shared-state snapshots

For accepted selectors, the function initializes an empty callback descriptor and calls F-be45cd43f92d with argument zero.

The returned object pointer is stored in an addressable local slot. This same slot is later passed to F-54033250428c on ordinary accepted-request paths.

If the returned pointer is null, the function calls F-a817d8d58c10. Initialization is skipped on that branch.

Otherwise, the function:

1. Calls F-b7af80e829ec.
2. Captures the current shared-state base.
3. Captures the current operation-table base.
4. Tests whether initialization returned zero.

A zero initializer result enters F-a817d8d58c10. The supplied representation includes the two global-base captures before that zero-result test.

For successful initialization, the initial ordinary-return status becomes 1.

Two distinctions matter:

- Most selectors fetch their descriptor through the operation-table global as accessed in their branch.
- Selector 5 fetches its descriptor through the operation-table base captured immediately after initialization.

Likewise, the later success-byte clear uses the captured shared-state base, whereas selector 8’s earlier four-byte write uses the shared-state global accessed in that branch. No assumption that intervening dependencies preserve those globals is warranted.

### 3. Selector-specific processing

A callback descriptor consists of two four-byte words at the listed operation-table offsets.

| Operation | Descriptor offsets | Additional behavior |
|---:|---|---|
| 1 | `0x4C`, `0x50` | Operand `0xFFFFFFFF` is replaced with zero before callback dispatch. |
| 2 | `0x54`, `0x58` | Contains the conditional context read described below; no operand transformation is visible. |
| 3 | `0x5C`, `0x60` | Same conditional context-read behavior as operation 2. |
| 4 | `0x64`, `0x68` | Same conditional context-read behavior as operation 2. |
| 5 | `0x6C`, `0x70` | Requires an unsigned bound check; may make an additional virtual call before descriptor selection. Uses the captured operation-table base. |
| 6 | `0x74`, `0x78` | No additional selector-specific behavior is visible. |
| 7 | `0x7C`, `0x80` | A zero callback result does not trigger the completion dependency. |
| 8 | `0x84`, `0x88` | May write shared state and make a virtual call before dispatch. |
| 9 | `0x8C`, `0x90` | No additional selector-specific behavior is visible. |

#### Operations 2, 3, and 4

When the secondary selector equals `0xFF`, the function reads the context byte at offset `0x2EC` and compares it with 2. When the secondary selector is not `0xFF`, that context read is skipped.

The supplied representation then distinguishes operand values 0–4 without any visible branch-specific effect. It establishes no changed operand, state write, dependency call, or alternative descriptor from those distinctions.

A behavioral contract must therefore not assign special transformations to operand values 0–4.

#### Operation 5

The function first calls the acquired object’s virtual entry at byte offset `0x108`, passing the object itself.

Its 32-bit result is used as an unsigned bound. The request operand is also compared as an unsigned 32-bit value.

- If the operand is greater than or equal to the bound, the status becomes 4. No descriptor is selected.
- If the operand is less than the bound, processing continues.

On a successful bound check with secondary selector `0xFF`, the function stores the 32-bit value 1 in temporary addressable storage and calls the object’s virtual entry at byte offset `0xAC`, passing the object and the temporary storage’s address.

The descriptor is fetched afterward from the captured operation-table base. The temporary argument’s contents are not subsequently inspected here. The callee’s contract, including whether it writes through or retains the pointer, is unknown; this function supplies no durable-storage guarantee.

A failed bound check still reaches finalization and ordinarily returns 4.

#### Operation 8

The descriptor is fetched before the context-mode test.

If the context byte at offset `0x2EC` equals 2:

1. Write the four-byte value 3 at offset `0x1C` from the shared-state base accessed at that point.
2. Call the acquired object’s virtual entry at byte offset `0x74`, passing the object.

Both actions precede callback dispatch and can occur even when the selected descriptor is absent.

### 4. Descriptor presence and dispatch

Let the descriptor’s first word be the target word and its second word be the adjustment/tag word.

The descriptor is treated as present when either:

- The target word is nonzero; or
- The adjustment/tag word has its low bit set.

An even, nonzero adjustment/tag word does not by itself make a zero-target descriptor present.

For a present descriptor, the receiver address is obtained by adding to the context address the result of an arithmetic right shift by one of the adjustment/tag word interpreted as signed 32-bit.

This is a signed, encoded adjustment, not an unsigned offset. Negative adjustments are therefore representable. The evidence does not establish checked address arithmetic or bounds validation.

Dispatch then depends on the low bit:

- **Low bit clear:** use the target word directly as the callback address.
- **Low bit set:** read the first four-byte word at the adjusted receiver; add the target word with its low two bits cleared; load the callback address from that computed location.

The callback receives, in order:

1. The adjusted receiver.
2. The acquired object.
3. The 32-bit operand, including operation 1’s sentinel-to-zero conversion where applicable.

No secondary-selector argument is visibly forwarded to this callback.

The status is set to 2 before invoking it.

### 5. Callback result and completion

Only the low 32 bits of the callback result determine success here.

For a nonzero low word, status remains 2.

For a zero low word:

1. Write one zero byte at offset 4 from the shared-state base captured after initialization.
2. For operations other than 5 and 7, call F-c5890456f563 with the original, unadjusted context and the acquired object.
3. Return status 0 if the remaining processing returns normally.

Operations 5 and 7 skip F-c5890456f563 but still perform the shared-state byte clear and produce status 0.

The representation exposes a wider callback result, but its upper 32 bits have no established consumer-visible use in this function.

### 6. Finalization

After selector processing and any callback/completion work, F-54033250428c receives the address of the slot holding the acquired object pointer.

This occurs for ordinary accepted-request paths including:

- An absent descriptor.
- A failed operation-5 bound check.
- A nonzero callback result.
- A zero callback result.

There is no visible finalization call on selector-validation failure or before the non-returning failure dependency.

## Side effects

Directly established writes are limited to:

- Temporary local storage used for the acquired-object slot and operation-5 argument.
- Operation 8’s four-byte shared-state write of 3.
- The one-byte shared-state clear following a zero callback result.

There is no explicit write to the request descriptor or payload.

Dependencies and dynamic callbacks may have additional effects. Their effects on globals, object lifetime, memory, exceptions, or control flow are unknown unless described above.

The acquisition/finalization pattern suggests managed ownership, but it does not prove allocation, reference counting, release, destruction, or ownership transfer. In particular, passing a pointer-slot address to F-54033250428c does not by itself establish what that dependency does with the object.

The visible order is significant: operation-8 effects precede dispatch; success clearing precedes completion; finalization follows completion. No rollback is visible if an intervening dependency does not return normally.

## Acceptance examples

These are conditional behavioral examples, not executed tests. Each assumes accessible storage and normal dependency returns unless stated otherwise.

1. **Wrong length:** A request length of 5 returns 4 without loading the payload pointer or calling the decoder.

2. **Invalid operation with valid length:** Length 6 and operation 0 still cause operand decoding and the secondary-byte read, then return 4 without object acquisition.

3. **Secondary-selector boundary:** Secondary values 9 and `0xFF` pass validation. Values 10 and `0xFE` return 4 after decoding.

4. **Acquisition failure:** A valid request whose acquisition dependency returns null enters F-a817d8d58c10 without calling initialization or ordinary finalization.

5. **Operation-1 sentinel:** With operation 1 and decoded operand `0xFFFFFFFF`, a present callback receives operand zero. Other operand values are unchanged.

6. **Unsigned bound equality:** For operation 5, operand 12 and bound 12 fail the strict comparison, skip descriptor dispatch, finalize the acquired-object slot, and return 4.

7. **Operation-5 special call:** With operand 11, bound 12, and secondary selector `0xFF`, the virtual entry at `0xAC` receives a pointer to a four-byte value initially equal to 1 before descriptor fetching.

8. **Absent descriptor:** A zero target word and an even adjustment/tag word produce no callback. After otherwise successful setup and selection, finalization occurs and status 1 is returned.

9. **Indirect descriptor with zero target word:** A zero target word and an odd adjustment/tag word still select dispatch. Callback lookup uses offset zero from the first word read at the adjusted receiver.

10. **Nonzero callback result:** A callback low result word of 7 produces status 2 and does not cause the success-byte clear or completion call.

11. **Successful operation 7:** A zero callback result clears the captured shared-state byte at offset 4, skips F-c5890456f563, finalizes, and returns 0.

12. **Operation 8 without a callback:** Context byte 2 causes the four-byte state write and virtual call even if the descriptor is absent; normal completion then returns 1 after finalization.
