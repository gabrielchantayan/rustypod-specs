# F-f91d703874b1

## Purpose

F-f91d703874b1 describes an operation that interleaves four selector-addressed character stores with 24 indirect calls. Store values depend on an unsigned 32-bit input and an unsigned 32-bit result obtained during the call sequence.

Each destination is the numerical value of an unsigned selector byte plus 17. Nothing establishes that these destinations are offsets within a buffer, members of a structure, or valid writable addresses.

The supplied representation uses conversions to a **plain character type**, whose signedness is unspecified. Consequently, the stores cannot unconditionally be described as low-eight-bit truncations. Conversion behavior can affect both stored values and whether execution continues.

No higher-level purpose is established. The visible sequence ends at a bad-instruction boundary, not an established normal return.

This contract distinguishes:

- **Established static evidence:** represented operations, widths, dependencies, and ordering.
- **Conditional interpretation:** consequences requiring additional arithmetic or character-conversion assumptions.
- **documented_only:** behavior that the supplied material does not resolve.

## Interface

### Explicit input

The sole explicit input is an unsigned 32-bit **input word**.

The complete input word is passed to F-000000000001. It also supplies the first two character-store values:

- The first attempts to convert the complete input word to the plain character type.
- The second attempts to convert the input word shifted right by 22 to that type.

The second conversion’s operand is between 0 and 1,023 inclusive. It is not already restricted to eight bits.

### Implicit inputs

The operation also depends on:

- An incoming signed 32-bit value used to calculate the primary selector address.
- An incoming signed 32-bit link-related value used to calculate the first call target.
- Selector memory contents at each read.
- Selected dependency results.
- Plain-character signedness and conversion rules.
- Address mapping, indirect-call conventions, and the execution environment.

No initialization or caller-established range restrictions for the incoming signed values are supplied.

### Outputs and completion

No return payload or normal completion path is established.

If execution reaches and completes every represented operation, the direct observable sequence contains four selector reads, four character stores, and 24 indirect calls, followed by the terminal boundary. Dependency internals may add arbitrary effects.

This is not an unconditional promise that all four stores occur. Arithmetic uncertainty, character-conversion signaling, invalid accesses, invalid targets, or a nonreturning dependency may interrupt the sequence.

No output object, allocation result, ownership transfer, or returned buffer is identified.

## Behavior

### Character-conversion rules and conditional byte model

Every direct store assigns through the plain character type. Its signedness is not supplied.

If that type is unsigned and eight bits wide, conversion reduces an integer modulo 256. If it is signed, an in-range value is preserved; conversion of an out-of-range value is implementation-defined and may raise an implementation-defined signal. The supplied material does not select a result or signal behavior for those cases.

In particular, a large unsigned value is not made representable merely because its low eight bits describe a small positive number. The conversion receives the complete value.

The following **truncating-byte interpretation** is used only where expressly stated:

- Character storage has eight bits.
- Each completed character conversion retains the low eight bits of its operand.
- Character representation and promotion are consistent with that retained-bit interpretation.
- The conversions do not interrupt execution.

Under this interpretation, the four stored byte patterns are:

| Store | Conditional byte pattern |
|---|---|
| First | Input word modulo 256 |
| Second | Input word shifted right by 22, then reduced modulo 256 |
| Third | Four times the derived word, reduced modulo 256 |
| Fourth | Derived word shifted right by 20, then reduced modulo 256 |

These formulas are not unconditional conversion guarantees. They hold directly for an unsigned eight-bit plain character type, and conditionally for other implementations satisfying the stated interpretation.

### Address calculations

The first three selector reads use a retained **primary selector address**, calculated from the incoming signed operand by multiplying it by 524,288 and then adding 1.

The recovered arithmetic is signed 32-bit. The multiplication is representable for incoming values from −4,096 through 4,095 inclusive; the subsequent addition is also representable throughout that range. No supplied precondition limits the incoming value to this range.

Outside it, the calculation’s behavior is documented_only. Under an additional wrapping-machine assumption, the address bit pattern is the mathematical expression reduced modulo \(2^{32}\).

The first indirect-call target is calculated by adding 4,080 to the incoming signed link-related value. The greatest incoming value for which the sum remains representable is 2,147,479,567, hexadecimal `7FFFF00F`. Addition cannot cause signed underflow.

For larger incoming values, the calculation is documented_only. A modulo-\(2^{32}\) target pattern requires a separate wrapping-machine assumption. Arithmetic representability does not establish that any resulting target is callable.

The fourth selector uses a **secondary selector address**, calculated from the unsigned 32-bit **derived word**:

\[
(8 \times \text{derived word}+1)\bmod 2^{32}.
\]

Unlike the signed calculations, this unsigned arithmetic establishes modulo-\(2^{32}\) behavior independently of character conversion.

### Dependency handles

F-000000000001 through F-000000000024 identify call occurrences in execution order. They do not establish 24 distinct functions; occurrences may resolve to the same target.

“No explicit argument” means only that none is represented. It does not exclude hidden register inputs, global inputs, or other calling-convention state.

### First store and calls 1–7

The first store obtains an unsigned selector byte from the primary selector address and uses its value plus 17 as the destination. The assigned value is the input word converted to the plain character type.

A completed store requires a usable destination and completion of that conversion. For a signed eight-bit plain character type, input values greater than 127 require implementation-defined conversion behavior.

The subsequent calls occur in this order:

1. F-000000000001 receives the complete input word.
2. F-000000000002 produces an opaque 32-bit result.
3. F-000000000003 receives that result unchanged.
4. F-000000000004, F-000000000005, and F-000000000006 are invoked.
5. F-000000000007 produces a signed 32-bit result retained for later use.

The first store precedes F-000000000001. That call uses the incoming-link-derived target described above.

### Second store and calls 8–12

After F-000000000007 returns, another selector byte is read from the primary selector address. Its value plus 17 selects the second destination.

The assigned value is obtained by unsigned right shift of the input word by 22, followed by conversion to the plain character type. The pre-conversion value is between 0 and 1,023. For signed eight-bit character storage, values above 127 are not covered by a value-preserving conversion guarantee.

Only under the truncating-byte interpretation does this store contain input bits 22–29, independently of input bits 30–31.

Next:

- F-000000000008 receives the result of F-000000000007 shifted left by two.
- F-000000000009, F-000000000010, and F-000000000011 are invoked.
- F-000000000012 returns the unsigned 32-bit derived word.

The left shift is represented as signed 32-bit arithmetic. For nonnegative results no greater than 536,870,911, it produces four times the result within the signed range. Negative operands and operands outside that range are not assigned a portable result by this contract. A wrapping-machine interpretation is conditional.

### Third store and calls 13–19

After F-000000000012 returns, a third selector byte is read from the primary selector address. Its value plus 17 determines the third destination.

This store has **two character-conversion stages**:

- First, the complete unsigned derived word is converted to the plain character type.
- That character value is promoted to a signed 32-bit integer and multiplied by four.
- Assignment converts the product to the destination’s plain character type.

For eight-bit character values, the multiplication itself fits signed 32-bit arithmetic. Its possible products lie within −512 through 1,020, depending on signedness and the first conversion’s result. The unresolved operations are the character conversions, not overflow of this multiplication.

If plain character is signed, the first conversion may already be implementation-defined. Even when it is value-preserving, the final assignment can be out of range: derived word 32 becomes character value 32, then product 128, which is outside the signed eight-bit range.

Thus “four times the derived word modulo 256” and “only derived bits 0–5 matter” are conditional on the truncating-byte interpretation.

After the store:

- F-000000000013 receives the third selector byte, zero-extended to unsigned 32-bit.
- F-000000000014 produces an opaque 32-bit result.
- F-000000000015 receives that result unchanged.
- F-000000000016, F-000000000017, and F-000000000018 are invoked.
- F-000000000019 produces a signed 32-bit result.

F-000000000013 receives the retained selector, not the selected destination, stored character, or a new memory read. Its target construction uses a different fixed displacement from the ordinary fixed-target pattern; target equivalence must not be assumed.

### Fourth store and calls 20–24

After F-000000000019 returns, the operation reads a selector byte at the secondary selector address. Its value plus 17 determines the fourth destination.

The conversion operand is obtained by retaining derived-word bits 0–29 and then shifting right by 20. This produces an unsigned value between 0 and 1,023, containing original bits 20–29.

That complete value is converted to the plain character type. Only under the truncating-byte interpretation does the stored pattern contain precisely derived-word bits 20–27, with bits 28–29 discarded independently of conversion policy.

Then:

- F-000000000020 receives the result of F-000000000019 shifted left by two.
- F-000000000021 through F-000000000024 are invoked in order.
- Execution reaches the represented bad-instruction boundary.

The signed-shift qualification is the same as for F-000000000008.

Selector locations and destinations are not proven disjoint. Stores can affect later selectors, and several stores can target the same address. Dependencies or external actors may also alter either location.

## Acceptance examples

These are conditional static consequences, not observed executions. Each assumes the relevant operations are reached and required accesses and calls are valid.

### Representable character values

For input word 42 and derived word 3:

- The first conversion produces 42.
- The second conversion produces 0.
- The third first converts 3, multiplies it by four, and assigns 12.
- The fourth conversion produces 0.

All these character values are representable with either signed or unsigned eight-bit plain character. No out-of-range character-conversion assumption is needed.

### Conditional input extraction

For hexadecimal input `A5C0007E`, under the truncating-byte interpretation:

- The first stored pattern is `7E`.
- The second stored pattern is `97`.
- F-000000000001 receives `A5C0007E`.

The second conversion operand is `297`, not `97`. Both this operand and the complete first-store input exceed the signed eight-bit range. Without the stated interpretation, those stored patterns and continued execution are not guaranteed.

Changing only input bits 30–31 leaves both patterns unchanged under that interpretation; this is not an unconditional independence guarantee.

### Fresh selector reads

If the first three selector reads yield 2, 9, and 255, their destinations are addresses 19, 26, and 272. If the third store completes and the next call is reached, F-000000000013 receives 255.

### Conditional derived-word extraction

For derived word `123456C3`, under the truncating-byte interpretation:

- The third stored pattern is `0C`.
- The secondary selector address is `91A2B619`.
- The fourth stored pattern is `23`.

The third store first converts the complete derived word before multiplication. The fourth conversion receives `123`, not merely `23`. Without the interpretation, both character results remain unresolved. The unsigned secondary-address calculation does not depend on that interpretation.

If the secondary selector is 7, the fourth destination is address 24.

### Unsigned address wraparound

For derived word `20000000`, the secondary selector address is 1 by unsigned 32-bit arithmetic.

Under the truncating-byte interpretation, both derived-word-based stored patterns are zero. Without it, those character results are not guaranteed: the third store starts with an out-of-range conversion for signed character, and the fourth conversion operand is 512.

### Conversion boundary within the third store

For derived word 31, the third store’s intermediate character value is 31 and its product is 124, representable with either character signedness.

For derived word 32, the intermediate value is 32 and the product is 128. Unsigned eight-bit character stores 128; signed eight-bit character requires implementation-defined out-of-range conversion behavior, potentially signaling.

### Signed arithmetic boundaries

Incoming link-related value `7FFFF00F` plus `FF0` gives representable result `7FFFFFFF`. The next incoming value, `7FFFF010`, exceeds the representable addition range. Result pattern `80000000` requires a wrapping-machine assumption.

A result of 3 from F-000000000007 supplies argument 12 to F-000000000008. Negative or excessively large results remain subject to the signed-shift uncertainty. The same applies to F-000000000019 and F-000000000020.

### Repeated destinations and interruption

If all four selector reads yield 5 and all stores complete, every destination is address 22. Absent intervening modifications, each later store replaces the previous value. Final contents after subsequent calls still depend on those calls.

If F-000000000012 does not return, the first two completed stores precede that interruption; the third and fourth are not reached. No rollback is shown.

## Evidence

Established claims come solely from static inspection of the supplied representation: an unsigned 32-bit input, signed incoming address operands, four selector-addressed plain-character assignments, 24 ordered indirect calls, the stated dataflow, and a terminal bad-instruction boundary.

The third assignment visibly converts the derived word to the plain character type **before** promotion and multiplication, then converts again on assignment. The other stores likewise require character conversion. Static evidence therefore supports their conversion operands and sequencing, but not unconditional low-eight-bit results for out-of-range signed-character conversions.

Arithmetic examples follow from the represented widths, with character truncation and signed wrapping explicitly qualified. The supplied overlap warning prevents assuming independent storage merely from global-symbol presentation.

No runtime tests, instrumentation, or experimental verification have been performed. No higher-level intent, dependency ownership contract, or successful normal completion has been observed.
