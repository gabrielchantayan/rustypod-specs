# F-88e8ca916d2a

## Purpose

F-88e8ca916d2a examines a byte-sized tag in a mutable state object and selects one of two processing paths:

- **Tag 1:** invoke three dependencies, store an intermediate result in the state object, and conditionally obtain two outputs and a return value through dependency-controlled references.
- **Tag 2:** initialize a table scan, search entries for a matching key, and produce record data from the first matching entry whose associated count is nonzero.

Other tag values return zero without explicit state or output writes.

The routine is not a Boolean success predicate. A producing path can return zero. A non-producing path can change state. Nonzero return values are data whose application-level interpretation is not established.

All behavior below is derived from static evidence. No runtime tests have been performed.

## Interface

### Arguments and return value

| Input | Width or representation | Observed role |
|---|---|---|
| State address | Four-byte address representation | Identifies the tagged, mutable state object. |
| Search value | 32 bits | Forwarded to a dependency on tag 1; compared with entry keys on tag 2. |
| First output address | Four-byte address representation | Destination of a four-byte output; also initializes a local reference slot on tag 1. |
| Second output address | Four-byte address representation | Destination of a four-byte output; also initializes another local reference slot on tag 1. |

The return value is a 32-bit integer:

- Unsupported tag: zero.
- Tag 1, final dependency returns zero: zero.
- Tag 1, final dependency returns nonzero: the second word reached through the first local reference.
- Tag 2, no producing match: zero.
- Tag 2, producing match: the sum of a descriptor value and a record value, subject to the arithmetic qualifications below.

No separate error output, status enumeration, or local exception-handling mechanism is established.

### State layout

All offsets are byte offsets from the state address.

| Offset | Width | Meaning established by use |
|---|---:|---|
| 0 | 1 byte | Dispatch tag. |
| 4 | 4 bytes | Tag-1 dependency input or tag-2 descriptor address. |
| 12 | 4 bytes | Tag-2 entry cursor. |
| 16 | 4 bytes | Tag-1 intermediate result or tag-2 record index. |
| 20 | 4 bytes | Tag-2 remaining associated-record count. |

Tag 2 accesses state through byte offset 23. Tag 1 explicitly accesses the tag and the words at offsets 4 and 16. Unlisted bytes have no established role in this routine.

### Tag-2 descriptor layout

| Offset | Width | Observed use |
|---|---:|---|
| 0 | 4 bytes | Record-address base. |
| 8 | 4 bytes | Additive return-value base. |
| 12 | 4 bytes | Table entry count, captured as unsigned. |
| 16 | 4 bytes | Initial entry address. |

The **table entry count** controls how many entries can be scanned. It is distinct from an entry’s **associated count**, which controls whether that entry produces a record and initializes state offset 20.

### Entry and record layouts

Entries have a 16-byte stride:

| Entry offset | Width | Observed use |
|---|---:|---|
| 0 | 4 bytes | Search key. |
| 4 | 4 bytes | Associated count. |
| 8 | 4 bytes | Not explicitly read. |
| 12 | 4 bytes | Displacement added to the record-address base. |

Associated records have a 12-byte stride:

| Record offset | Width | Observed use |
|---|---:|---|
| 0 | 4 bytes | First output value. |
| 4 | 4 bytes | Return-value addend. |
| 8 | 4 bytes | Second output value. |

On an ordinary producing call, the index is zero, so all three values come from the first record. Under aliasing, the second output still comes from offset 8 of the unindexed associated-record address, while later reads can use a changed index.

### Preconditions

Every accessed location must have adequate extent, accessibility, alignment, and lifetime for its particular read or write. The routine performs no explicit validation of pointers, counts, displacements, object sizes, or address ranges.

Output addresses need writable storage only on paths that actually write through them. Dependency behavior can impose additional requirements on tag 1 because those addresses are also supplied indirectly through mutable reference slots.

Disjoint storage is not checked. Outputs may overlap each other or other accessed objects, but such overlap can change subsequent observations. The access ordering below governs those cases; ordinary non-overlapping outcomes are conditional deductions, not universal guarantees.

## Behavior

### Dispatch

The default return value is zero.

The routine reads the state tag and compares it with 1. If that comparison fails, another tag read is expressed for comparison with 2. No guarantee establishes a single synchronized tag snapshot.

Only tag 1 invokes dependencies.

### Tag 1: dependency sequence

Two local four-byte reference slots are initialized, one from each output address.

The following interactions then occur in order:

1. F-8157a180d901 is called with the integer value 24.
2. After that call returns, the state word at offset 4 is read. F-99bb1fbf801b receives the preceding dependency result, that state word, and the search value, in that order.
3. The result from F-99bb1fbf801b is stored as a four-byte word at state offset 16.
4. F-37f0845bb2ad receives that result, the address of the slot initialized from the second output address, and the address of the slot initialized from the first output address, in that order.
5. The return from F-37f0845bb2ad is tested for zero versus nonzero.

There is no intervening failure check on the results of the first two dependencies. No assumption that either dependency preserves global or shared memory is warranted. In particular, the state input for the second call is read after the first call.

If F-37f0845bb2ad returns zero, the routine returns zero without further explicit state or output writes. The state-offset-16 write has already occurred. The dependency may itself have changed that field or other memory, so its final contents are not guaranteed solely by the preceding store.

### Tag 1: output extraction

For a nonzero return from F-37f0845bb2ad, define:

- **First reference:** the current contents of the slot originally initialized from the first output address.
- **Second reference:** the current contents of the slot originally initialized from the second output address.

The routine performs these actions in order:

1. Store the four-byte Second reference value itself at the first output address.
2. Read the word addressed by First reference and store it at the second output address.
3. Read the word at First reference plus 4 and return it.

The first output is not a dereference of Second reference. It receives the reference value itself.

The two output stores precede the final return-word read. Overlapping destinations and referenced storage can therefore affect later reads. A nonzero dependency return does not prove that First reference points to two readable words or that the outputs are writable.

### Tag 2: scan initialization

The descriptor address is read from state offset 4 and retained for subsequent descriptor accesses that explicitly use this captured address.

Initialization proceeds in this order:

1. Read the initial entry address at captured descriptor offset 16 and store it at state offset 12.
2. Read the table entry count at captured descriptor offset 12 and capture it as an unsigned 32-bit scan limit.
3. Clear state offsets 20, 21, 22, and 23 using four successive one-byte zero writes.
4. Start an unsigned 32-bit scan counter at zero.

The cursor write occurs before the table entry count is read. If those locations overlap, the count observation can be affected.

The captured scan limit is not reread during traversal. A zero limit skips all entry-key reads.

State offset 16, the record index, is not reset by initialization. It is reset only when an entry key matches.

### Tag 2: traversal

For each position whose unsigned scan counter is below the captured limit:

- Read the current entry address from state offset 12 and retain that address for this scan position.
- Read the key at entry offset 0 and compare it with the search value.
- If the key matches:
  - Clear state offsets 16 through 19 with four successive one-byte zero writes.
  - Read the associated count at offset 4 of the retained entry.
  - Store that count as a four-byte word at state offset 20.
  - If the captured associated count is nonzero, produce a result as described below.
- If no result was produced, store the retained entry address plus 16 at state offset 12, then advance the scan counter.

The associated-count read follows the index-clearing writes. Overlap between state and entry storage can affect that count.

A matching entry with associated count zero does not terminate traversal. Later entries, including duplicate keys, remain eligible.

The associated count is tested for nonzero, not positivity. A 32-bit value interpreted as negative by signed arithmetic still takes the producing branch.

If traversal finishes without a producing match, the return is zero and neither output is explicitly written. With disjoint storage and valid arithmetic, the cursor is one entry beyond the scanned range. The record index retains its incoming value if no key matched; if any key matched without producing, it was reset to zero.

### Tag 2: producing a record

A nonzero associated count causes immediate result production, without scanning later entries.

First, an associated-record address is formed from two operands:

- The record-address base read at offset 0 of the captured descriptor.
- The displacement read at offset 12 of the entry reached by rereading the cursor at state offset 12.

**The relative evaluation order of these operands is not established.** The base read and the cursor/displacement reads belong to opposite operands of one addition expression. Both operands are obtained before their sum becomes the associated-record address. No base-first or displacement-first guarantee is part of this contract.

After that address has been obtained, the following statement ordering is established:

1. Read the word at associated-record address plus 8 and store it at the second output address.
2. Reread the descriptor address from state offset 4, then read its word at offset 8 as the return-value base.
3. Read the index at state offset 16 and use its 12-byte scaling to read the return addend at indexed record offset 4.
4. Read the index at state offset 16 again and use its 12-byte scaling to read the first output value at indexed record offset 0; store that value at the first output address.
5. Reread the index at state offset 16, add one, and store the result there.
6. Reread the remaining count at state offset 20, subtract one, and store the result there.
7. Return the sum of the previously captured return-value base and return addend.

The second output is written before the first. The descriptor pointer used for the return-value base is reread from state, rather than necessarily being the captured descriptor pointer.

The associated-record address is retained after its computation. Changing a descriptor or displacement through a later output write does not recompute that address, although changing the index can affect indexed reads.

With valid, non-overlapping storage and representable arithmetic:

- Both indexed reads use index zero.
- The outputs come from offsets 0 and 8 of the first associated record.
- The final index is 1.
- The remaining count is the matching entry’s **associated count minus one**, not the table entry count minus one.
- The cursor stays at the producing entry.

These outcomes depend on non-aliasing. The second-output store can alter a subsequently read descriptor pointer, return base, or index. The first-output store can alter state before its final updates.

A later invocation with tag 2 initializes the cursor from the descriptor again. The previously saved cursor and index do not make this function resume at the next record.

### Widths and arithmetic

Tags and explicit clearing stores are one byte. Other observed fields, pointer representations, outputs, counters, and return components are four bytes.

The scan counter and scan limit use unsigned 32-bit comparison. Entry advancement uses a 16-byte stride; record indexing uses a 12-byte stride.

The supplied representation uses signed 32-bit integer operations for several address calculations, index updates, associated-count updates, and the return sum. It supplies no overflow checks. Signed overflow, invalid computed addresses, and the exact machine interpretation of those operations are not resolved here. Modulo wrapping must not be assumed as a general guarantee.

For example, a negative nonzero associated count takes the producing branch, but decrementing the minimum signed value is outside the representable signed range.

Byte order is not established. Clearing all four bytes establishes a zero word regardless of byte order; this does not establish a serialization format.

## Side effects

- **Unsupported tag:** none.
- **Tag 1:** state offset 16 is written before the final dependency call. The two output stores occur only when that call returns nonzero.
- **Tag 2:** initializes the cursor and remaining count; resets the index on matches; stores each matching associated count; advances the cursor after non-producing positions; and, on production, writes both outputs and updates index and remaining count.

The four-byte clearing operations are expressed as four ordered byte stores. No atomic publication or intermediate-state invisibility is established.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, storage is valid and disjoint, dependencies have only the effects specified in the example, and arithmetic is representable.

1. **Unsupported tag.** A stable tag of 3 produces return zero, no dependency calls, and no explicit state or output writes.

2. **Tag-1 non-producing dependency result.** If the second dependency returns T and the final dependency returns zero without changing state, state offset 16 contains T. The routine returns zero without its own output writes.

3. **Tag-1 producing result.** If the final dependency returns nonzero, First reference designates consecutive words A and B, and Second reference contains Q, the first output receives Q, the second receives A, and the return is B.

4. **Empty table.** A tag-2 table entry count of zero still initializes the cursor and clears the remaining count. The index is unchanged, outputs are untouched, and the return is zero.

5. **No matching key.** With two nonmatching entries, the cursor advances by 32 bytes from its initial address. Remaining count is zero, the index is unchanged, and outputs are untouched.

6. **Zero-count match followed by a usable duplicate.** Suppose the table entry count is 2. The first entry matches but has associated count zero; the second matches and has associated count 3. The second entry produces. For record words A, D, B and return base R, outputs are A and B, return is R + D, index becomes 1, and remaining count becomes 2. The remaining count derives from associated count 3, not table entry count 2.

7. **Overlapping output destinations.** If both outputs designate one otherwise independent word, tag 2 first stores the record’s offset-8 value there, then overwrites it with the offset-0 value. The latter remains.

8. **Produced result with return zero.** Return base zero and return addend zero still permit both output writes and both state updates. The returned zero does not mean that no record was produced.

9. **Repeated invocation.** With unchanged tag, descriptor, and table, another tag-2 call restarts at the initial entry and can produce the same first record again.

10. **Second output changes the index.** If the second output address is state offset 16 and the unindexed record’s offset-8 word is 2, subsequent indexed reads use index 2. If no later write changes that field, the final index becomes 3. This differs from ordinary first-record behavior.

No acceptance condition requires the captured descriptor’s record base to be read before the cursor/displacement operand, or vice versa.
