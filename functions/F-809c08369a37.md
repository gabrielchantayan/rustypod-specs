# F-809c08369a37

## Purpose

F-809c08369a37 conditionally executes a receiver-state transition after an associated object accepts an initial request. Acceptance leads to two ordered queries, normalization of the second result, direct receiver updates, external operations, and receiver callbacks. A callback result intersected with the original input mask controls an additional external-operation pair.

The initial request is the sole explicit gate for this sequence. A zero result skips every subsequent operation performed directly by this function.

“Request,” “acceptance,” and “transition” describe control-flow roles. Business meanings for the values, fields, and operations are not established.

## Behavior

### 1. Initial request and writable local

The function reads the associated-object reference from receiver offset `0x18` and selects its dispatch entry at `0x0C`. It initializes a separate unsigned 32-bit local value from the original mask.

F-U01 receives these arguments in order:

1. The associated object.
2. The original request value.
3. The address of the writable local value.
4. The callable address selected for this invocation.
5. The original mode value.

The third argument addresses local storage, not the caller’s mask argument. Changes through this address can affect later query inputs without changing the original mask used for the final bitwise test.

The fourth argument is a callable-address value. This function does not independently invoke that value again merely because it was supplied as an argument.

If F-U01 returns zero, this function performs no further calls or direct receiver writes. Effects already produced by F-U01 are not undone.

Any nonzero return, including a negative signed result, enters the accepted sequence.

### 2. Separately sampled query inputs

After acceptance, the function invokes F-U02 through associated-object dispatch offset `0x1C`, then F-U03 through offset `0x20`.

Each receives the associated object and a value read from the writable local. These are separate reads at separate call sites:

- F-U02 receives the local value available after F-U01 returns.
- F-U03 receives the local value available after F-U02 returns.

The local remains alive throughout this function’s execution. F-U01 may retain its address, and F-U02 may modify the local through that retained address before returning. The supplied body does not establish whether such modification occurs. Consequently, the two queries are **not guaranteed to receive identical values**, even though this function performs no direct assignment to the local between them.

The associated-object reference and dispatch information are also obtained anew for each query. F-U01 can therefore replace the receiver’s associated object before F-U02, and F-U02 can replace it before F-U03. The two query calls need not use the initial object or the same object as each other.

Both query results are treated as unsigned 32-bit values. The first result is retained unchanged. The second is replaced with `0x7FFFFFFF` if it is:

- Zero; or
- Less than or equal to the first result under unsigned comparison.

Otherwise, the second result is retained.

This substitution does not guarantee an increasing interval. A first result of `0x7FFFFFFF` or greater can leave the normalized second value equal to or less than the first. No increment, subtraction, wrapping calculation, or further ordering repair occurs.

### 3. Conditional helper and receiver marker

The function reads the receiver word at `0x70`, converts it to the character type represented in the source, and compares that converted value with zero.

If the converted value is zero, F-ea67aeaf4d96 receives the receiver. Otherwise, that helper is skipped.

After the helper returns, or immediately if skipped, the function writes the 32-bit all-ones value to receiver offset `0x4C`. Its signed interpretation is `−1`.

This write follows the helper invocation. It is not an earlier effect of this invocation that the helper can observe. The helper’s own effects remain unspecified.

### 4. Mode-related external operations

The function calls F-U04 with no explicit arguments. Its opaque 32-bit result is passed to F-U05, followed by the original mode value and the integer constant one.

If the mode is nonzero, the function then:

1. Calls F-U06 with no explicit arguments.
2. Calls F-U07 with that result, one, and zero.

A zero mode skips only this conditional pair. It does not skip F-U04, F-U05, or the later accepted-path sequence.

### 5. Exact-byte transition

After the mode-related operations, the function reads the byte at receiver offset `0x67`.

If and only if the byte equals one, it:

1. Writes zero to that byte.
2. Resolves receiver dispatch slot `0xD4`.
3. Calls F-U08 with the receiver, `0x7FFFFFFF`, and zero.

The clearing write precedes dispatch resolution and callback invocation. No intervening explicit dependency call appears between the write and F-U08. Absent another mutation, F-U08 observes the cleared byte.

Any other byte value, including a nonzero value other than one, skips both the write and F-U08.

The condition uses the value present at this point in execution, not an entry-time snapshot. Earlier dependencies may affect it.

### 6. Receiver callbacks and original-mask test

The function resolves receiver dispatch slot `0xCC` and invokes F-U09 with:

1. The receiver.
2. The original request value.
3. The retained first query result.
4. The normalized second query result.
5. Zero.

After F-U09 returns, the function resolves receiver dispatch slot `0xC8` and invokes F-U10 with the receiver and the same two query values.

F-U10’s result is treated as an unsigned 32-bit value. The function intersects it bitwise with the **original mask**, not with the writable local’s initial or current value.

If the intersection is nonzero:

1. F-U11 is called with no explicit arguments.
2. F-U12 receives its result and the integer constant one.

If the intersection is zero, both calls are skipped.

Receiver dispatch entries are resolved at their use sites. An earlier dependency may therefore affect a later callback target. The retained query values are not recomputed following those calls.

### 7. Final external operation

Regardless of the mask-test outcome, the accepted path ends with:

1. Another invocation of F-U04.
2. F-U13 receiving this new result, one, and one.

The earlier F-U04 result is not reused. Equality of the two results, or stability of any state accessed by F-U04, is not established.

All statements about later operations assume earlier dependencies return normally.

### Local lifetime and retained aliases

A dependency may retain that address and access the still-live local during subsequent calls before this function returns. In particular, F-U02 may change it through a retained alias, changing the value subsequently supplied to F-U03.

The established storage lifetime does not establish an alias-retention policy, synchronization contract, or actual dependency behavior. Those contracts are unknown. Access through a retained address after F-809c08369a37 returns is outside this local’s lifetime.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. Each assumes valid storage, compatible calls, and normally returning dependencies unless stated otherwise.

1. **Rejected request.** F-U01 returns zero. Neither query runs, neither direct receiver write occurs, and no later dependency is called. F-U01’s own effects remain.

2. **Modified query input with no intervening modification.** The original mask is `0x00000001`. F-U01 sets the local to `0x00000004` and accepts. If the local remains unchanged through F-U02’s return and F-U03’s argument read, both queries receive `0x00000004`. If F-U10 returns `0x00000004`, F-U11/F-U12 are skipped because the original mask has no overlapping bit.

3. **Retained alias changes the second query input.** F-U01 retains the local address and leaves its value at four. F-U02 receives four, changes the still-live local to eight through that address, and returns normally. With no further modification before the next argument read, F-U03 receives eight. The original mask remains the operand of the later mask test.

4. **Second result retained.** The queries return 10 and 11. F-U09 and F-U10 receive 10 and 11.

5. **Equal or zero second result.** Results of 10 and 10 become 10 and `0x7FFFFFFF`. A zero second result is likewise replaced regardless of the first result.

6. **Unsigned comparison without ordering repair.** The first result is `0xFFFFFFFF` and the second is one. Later callbacks receive `0xFFFFFFFF` and `0x7FFFFFFF`; the first is not reduced.

7. **Exact-byte condition.** At the byte-check step, a value of two at `0x67` skips F-U08 and causes no direct write there. A value of one is cleared before F-U08.

8. **Negative mode.** A mode of `−1` is forwarded unchanged to F-U05 and causes F-U06/F-U07 to run.

9. **Zero original mask.** With acceptance and an original mask of zero, every F-U10 result skips F-U11/F-U12. The final F-U04/F-U13 pair still runs.

10. **Associated-object replacement.** F-U01 replaces the associated-object reference with another valid object. F-U02 uses the replacement. If F-U02 replaces it again, F-U03 uses that later replacement.

11. **Word-to-character condition.** If conversion of the word at `0x70` produces zero, F-ea67aeaf4d96 precedes the marker write. This criterion does not require assuming that only a zero word can convert to zero.
