# F-ad38d6d41e75

## Purpose

F-ad38d6d41e75 processes one expression-like node in a mutable context. Its one-byte kind selects name resolution, subquery delegation, parameter-restriction checking, function lookup and authorization, or no further processing.

The function marks previously unvisited nodes, records selected function-call errors, and changes certain node kinds and context flags. Its 32-bit integer result is branch-dependent control information, not a uniform success status. Diagnosed errors can return zero; name-resolution dispatch and some rejected operations return one.

“Expression,” “name,” “subquery,” and “aggregate” are inferred semantic roles. The access widths, branch conditions, dependency calls, and direct mutations described below are established by the supplied static body.

## Interface

### Inputs and memory requirements

The function receives:

1. A pointer to a mutable context.
2. A pointer to a mutable node, which may be null.

The represented interface uses 32-bit addresses and words, 16-bit node flags, and 8-bit kind and context fields. For every selected branch, the caller must provide accessible storage for all reached fields and indirect objects. No general layout, pointer-validity, or bounds validation is visible.

A null node requires no context access. A non-null node requires at least a readable context word at offset 0, even if the node is already marked visited.

### Context layout

Offsets are in bytes.

### Result

The result is always zero or one on a normal return:

- **One:** null node; already-visited node; delegated name resolution; nonzero authorization result; or completion while retaining the local aggregate classification.
- **Zero:** other paths, including unhandled kinds and several diagnosed errors.

Dependency return values are not forwarded. Lookup results and authorization results determine branches; other dependency results are ignored.

## Behavior

### Entry and visitation

A null node returns one without reading the context.

For a non-null node, the processing-object pointer is read from context offset 0 before the node’s 16-bit flags are checked. If flag `0x0004` is already present, the function returns one without reading the node kind.

Otherwise, the function sets `0x0004`, preserving the remaining flag bits, and then reads the kind. Every dispatched path therefore begins with visitation already recorded. There is no later direct clearing of that bit or rollback on an error.

### Subquery-bearing kinds

Kinds `0x11`, `0x40`, and `0x6e` share one path.

The initial 32-bit read at node offset 56 gates entry: if it is zero, the function returns zero without reading the subquery state or restriction fields.

If the initial reference is nonzero:

- Context offset 12 is saved.
- The restriction byte at context offset 22 is read.
- A nonzero restriction invokes F-2022b0f73f3b for a subquery-prohibited-in-CHECK diagnostic.
- Node offset 56 is read again, and F-f1d95153eae8 receives the cached processing object, this reloaded reference, and the context.
- Context offset 12 is compared with the saved value. A difference causes flag `0x0020` to be added to the node’s then-current flags.
- The result is zero.

The initial nonzero test does **not** guarantee that F-f1d95153eae8 receives a nonzero reference. The optional diagnostic call intervenes before the reload and may change node offset 56, including changing it to zero. There is no second nonzero check and no cancellation of delegation.

The state comparison spans both dependency calls when a diagnostic occurs. A detected difference cannot be attributed exclusively to subquery processing. This path does not directly increment context offset 16.

### Simple and conditionally quoted names

Kind `0x17` delegates name resolution directly.

Kind `0x58` first reads the token address at node offset 20 and dereferences its first byte. An apostrophe causes a zero return without name-resolution delegation. Every other first byte selects the same delegation as kind `0x17`.

F-de09489c25ab receives, in order:

1. The cached processing object.
2. Zero.
3. Zero.
4. The address of the token descriptor beginning at node offset 20.
5. The context.
6. The original node.

After delegation, the function returns one regardless of the dependency’s result.

### Qualified names

Kind `0x70` first reads the nested-node pointer at offset 12 and then that nested node’s kind.

If the nested kind is `0x17`, the selected name components are:

- First qualifier: zero.
- Second qualifier: the original node’s field at offset 8, advanced by 20 bytes.
- Token descriptor: the nested node’s address plus 20.

For every other nested kind:

- The initially selected nested node’s field at offset 8 is read.
- Its further nested-node pointer at offset 12 is read.
- The original node’s field at offset 8 is read.
- First qualifier: the original node’s offset-8 value plus 20.
- Second qualifier: the initially selected nested node’s offset-8 value plus 20.
- Token descriptor: the further nested node’s address plus 20.

F-de09489c25ab receives the cached processing object, the two qualifiers, the token-descriptor address, the context, and the original node. The function returns one.

No null checks protect the nested-node accesses. The non-`0x17` branch does not validate a particular alternative kind.

### Parameter kind

Kind `0x80` reads context byte 22. A nonzero value invokes F-2022b0f73f3b for a parameter-prohibited-in-CHECK diagnostic. Either way, the result is zero.

This path does not directly increment the error count.

### Function-call kinds

Kinds `0x94` and `0x98` share the following processing.

#### Captured arguments and name information

The argument-list pointer is read from node offset 16 and retained locally. A null pointer yields a cached count of zero; otherwise, the list’s first 32-bit word supplies the cached count.

Before lookup, the function reads the configuration byte through the handle chain described above, the name address at node offset 20, and the unsigned metadata at offset 24.

The name length is the metadata shifted logically right by one. Its range is zero through `0x7fffffff`; the low metadata bit does not contribute.

#### Lookup and fallback

F-d92bc662c47a first receives:

1. The handle from the cached processing object’s first word.
2. The cached name address.
3. The shifted length.
4. The cached argument-count bit pattern.
5. The cached configuration byte.
6. Zero.

If this returns null, a second lookup uses count selector `0xffffffff`. The handle is read again from the cached processing object; the name, length, and configuration byte are reused.

The outcomes are:

| Outcome | Local classification and subsequent handling |
|---|---|
| Both lookups return null | Non-aggregate; missing-function diagnostic, then direct error-count increment |
| Only fallback succeeds | Non-aggregate; remember argument-count mismatch and proceed to authorization |
| Primary lookup succeeds | Aggregate-like exactly when descriptor offset 16 is unsigned zero; otherwise non-aggregate |

A fallback descriptor’s classification field is not used to promote it to the aggregate path.

#### Authorization

Whenever a descriptor is found, F-0055bebe0706 receives the cached processing object, action `0x1f`, zero, descriptor address plus 28, and zero.

A nonzero authorization result ends processing:

- Exactly one invokes an unauthorized-function diagnostic using descriptor address plus 28, followed by a direct error-count increment.
- Any other nonzero value causes neither of those direct operations.
- The node kind is then changed to `0x5c`.
- The function returns one.

No arguments are traversed. Aggregate marking, aggregate-permission diagnostics, and argument-count diagnostics are bypassed.

#### Permission, diagnostics, and aggregate marking

After authorization returns zero, a locally aggregate-like call reads context byte 20. If that byte is zero, the function reports aggregate misuse, clears its local aggregate classification, increments the error count, and proceeds toward the argument loop without aggregate marking.

Otherwise, a remembered fallback-only lookup causes a wrong-argument-count diagnostic and a direct error-count increment.

The missing-function, aggregate-misuse, and wrong-argument-count diagnostics receive the cached name length and name address in that order. Each direct error-count increment reads and updates context offset 16 **after** the diagnostic returns. A diagnostic’s mutation of that field is therefore not ignored.

If the local aggregate classification remains true, the function performs these writes before argument traversal:

1. Node kind becomes `0x96`.
2. Context byte 21 becomes one.
3. Context byte 20 becomes zero.

These writes occur even when the error count was already nonzero.

#### Argument traversal and completion

Argument indices begin at zero. Before each traversal, the current error count must equal zero, and the index must be less than the cached count using a signed 32-bit comparison.

For every admitted index, the function rereads the entry-array pointer at offset 12 of the retained list object, selects the entry at a 12-byte stride, reads its first 32-bit word, and invokes F-f59a6024d361 with:

- That entry value.
- F-ad38d6d41e75 as callback.
- The context.

The traversal result is ignored. The error count is checked again before another argument is selected.

The node’s argument-list pointer and the list count are not reloaded. Changes to them do not redirect this loop. Changes to the retained list’s entry-array pointer can affect later selections.

After the loop, a still-true local aggregate classification causes context byte 20 to be written as one and the function to return one. Otherwise, it returns zero.

This final write is not restoration of a saved value: an incoming permission byte of two becomes one. It also occurs if argument traversal stopped because the error count became nonzero.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Except where a mutation is explicitly specified, assume dependencies return normally without changing relevant storage. Assume accessible layouts and representable arithmetic.

1. **Null node:** A null node returns one even with an unusable context pointer; no context access occurs.

2. **Already visited:** With a readable context word and flag `0x0004` present, the function returns one without reading the kind or invoking dependencies.

3. **Unhandled kind:** An unvisited, unhandled node gains `0x0004`, preserves other flags, and returns zero.

4. **Quoted token:** Kind `0x58` with an apostrophe as the token’s first byte is marked visited and returns zero without name resolution.

5. **Initially absent subquery:** A zero initial reference at offset 56 causes a zero return without consulting the restriction byte or invoking either subquery-related dependency.

6. **Restricted subquery changed to zero:** Suppose the initial reference is nonzero and restriction byte 22 is nonzero. If the diagnostic changes node offset 56 to zero, F-f1d95153eae8 is still called, with zero as its reference argument. There is no second guard. Assuming both calls return normally, the function then compares context offset 12 and returns zero.

7. **State change caused by diagnostics:** If the restriction diagnostic changes context offset 12 and subquery processing leaves that changed value intact, the function sets node flag `0x0020`. This does not establish that subquery processing caused the difference.

8. **Missing function:** With two null lookup results, initial error count zero, and no diagnostic mutation, the diagnostic precedes the increment to one. No arguments are traversed; the result is zero.

9. **Authorization rejection:** An authorization result of two rewrites the kind to `0x5c` and returns one without a direct diagnostic or error-count increment. A result of one additionally causes those operations before the rewrite.

10. **Fallback descriptor:** If only fallback lookup succeeds, authorization allows it, and the descriptor’s classification field is zero, it still follows the wrong-argument-count path rather than aggregate marking.

11. **Allowed aggregate:** With primary classification zero, authorization allowed, permission byte two, and error count zero, the node becomes `0x96`; byte 21 becomes one; byte 20 is zero during argument traversal and one afterward. The result is one.

12. **Disallowed aggregate:** With the same lookup but permission byte zero and initial error count zero, aggregate misuse is reported and the count becomes one. No aggregate-kind rewrite or argument traversal occurs; the result is zero.

13. **Traversal interruption:** If the first traversal leaves the error count nonzero, no second argument is selected. A locally aggregate call still writes byte 20 to one and returns one.

14. **High-bit count:** A cached count with its high bit set is passed to primary lookup unchanged, but its signed interpretation admits no argument from index zero.
