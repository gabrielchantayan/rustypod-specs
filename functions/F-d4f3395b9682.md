# F-d4f3395b9682

## Behavior

The order below is the represented sequence, not a guarantee of physical bus ordering or inter-thread synchronization. Labels **F-indirect-01** through **F-indirect-37** identify indirect call sites, not proven distinct target functions.

### One-time memory writes

The function retains the numeric address of **F-84afe689f0fe** and performs two 32-bit stores at that address plus `0x260000`:

1. Store `0x00260000`.
2. Store the dependency address.

Both stores belong to the observable sequence. The second overwrites the first if both complete and no intervening external effect changes the location.

The function then captures the initialization global as a 32-bit value and forms the dependency address multiplied by `0x200`.

The remaining three word stores require a distinction between **the captured global value** and **later references to the global**:

1. Store the initialization global at an address consisting of the initialization global plus the dependency address multiplied by `0x100`. Both the destination-base expression and the stored-value expression reference the global again; neither is explicitly expressed using the earlier capture.
2. At the captured global value plus the dependency address multiplied by `0x200`, store that product.
3. At the same captured-base destination, store the captured global value.

The first scaled-address store does not establish an evaluation order between its address and stored-value expressions. It also does not establish a particular number of physical global loads. Describing both references as equal to the earlier capture is valid only if the global remains unchanged across the relevant evaluations.

The final two stores explicitly use the captured value even if an earlier write aliases and changes the global’s storage. All initialization destinations may overlap. No dependency invocation is represented during this sequence.

### Opening calls and early writes

Each iteration establishes a zero-valued byte working value before **F-indirect-01**. That call receives two explicit zero arguments; its target is the current link-register-derived value plus `0xFFE`.

A second zero-valued byte working value is established after that call and before its later use.

The function invokes **F-indirect-02** and **F-indirect-03**, then captures the first loop-global word.

It invokes **F-indirect-04**, followed by **F-indirect-05**. The latter supplies a represented 64-bit result.

**F-indirect-06** receives:

- The high word plus the low word plus the second zero-valued byte.

The sum has a 32-bit represented destination; its signed-overflow interpretation remains unresolved. An auxiliary byte output associated with **F-indirect-06** is stored at the captured first loop-global value plus `0x11`.

After **F-indirect-07**, the first zero-valued byte is stored at the same captured base plus `0x15`. The global is not explicitly reread for either destination.

**F-indirect-08** supplies a 16-bit result and an auxiliary register-derived destination base. The result is stored as a halfword at that base plus `0x0C`.

### Two-word result and fixed-address halfword

2. Stores its low word logically shifted right by 26 bits as a word at the current register-derived base plus `0x26C`.

The numeric constant `0x21C48960` is retained for later calculations. After **F-indirect-10**, the function reads a word at the register-derived base plus `0x320`, capturing another address base.

It invokes **F-indirect-11** and **F-indirect-12**, then stores the low word from **F-indirect-09**, shifted left by two bits as an unsigned 32-bit value, at that captured base plus `0x54`. This unsigned shift discards the original upper two bits.

Calls **F-indirect-13**, **F-indirect-14**, **F-indirect-15**, **F-indirect-16**, and **F-indirect-17** follow in order.

The function reads an unsigned halfword at `0x21C48994`, equal to the retained constant plus `0x34`. Its zero-extended value becomes an address base for later accesses. This is a 16-bit load used numerically as a base, not a pointer-width load.

After **F-indirect-18**, the function reads a word at the register-derived base plus `0x280` and passes it to **F-indirect-19**.

### Breakpoint and middle accesses

It reads a word at the earlier fixed-address halfword’s zero-extended value plus `0x44`. This captured word serves as a base for several late stores.

The function invokes **F-indirect-20**, then **F-indirect-21**. It invokes **F-indirect-22** with:

- A word read at the earlier fixed-address halfword’s zero-extended value plus `0x04`.

After **F-indirect-22**, the function captures the second loop-global word and invokes **F-indirect-23**.

It stores a halfword at the captured second global value plus the scaled result of **F-indirect-19**. The stored value is the low 16 bits of that captured global value.

After **F-indirect-24**, the function reads a word at `0x2218`, equal to `0x21C4 + 0x54`.

**F-indirect-25** supplies a 32-bit address-like result. The halfword `0x21C4` is stored at that result plus `0x04`.

The function invokes **F-indirect-26** and **F-indirect-27**, then reads an unsigned halfword at the word captured from `0x2218` plus `0x34`. This halfword supplies a later index-like numeric value.

### Late result processing and base adjustment

**F-indirect-28** supplies a represented 64-bit result.

The low word is stored at the current register-derived base plus `0x258`. The function then reads an unsigned halfword at the high word plus `0x14`.

The low result word is scaled by 64 using a represented signed left shift. The high result word is multiplied by four. Overflow behavior for these signed expressions is not established.

The register-derived base is explicitly decreased by `0xF4`. This adjustment occurs after the store at offset `0x258` and after the halfword read.

The halfword obtained through `0x2218` is multiplied by four. Because its range is 0 through 65535, this product is at most `0x3FFFC`.

A word containing the low result word of **F-indirect-28** is stored at that fourfold value plus `0x74`.

After **F-indirect-29**, the zero-extended halfword read from the high result word plus `0x14` is stored as a full word at the captured middle-stage base plus `0x54`.

After **F-indirect-30**, the same captured halfword value is stored as a full word at that base plus `0x64`. No second halfword load is represented between these stores.

After **F-indirect-31**, the function stores a halfword at the sum of:

- The low result word of **F-indirect-28**, scaled by 64.
- An auxiliary register output associated with **F-indirect-31**.

The stored value is the low 16 bits of the captured middle-stage base.

### Final transfer and iteration closure

The function invokes **F-indirect-32** and **F-indirect-33**.

It reads a byte at five times the unsigned halfword obtained through `0x2218`: the original halfword value plus its fourfold value. This numeric address is between 0 and `0x4FFFB`.

After **F-indirect-34**, the captured byte is stored at the sum of:

- The zero-extended halfword read from the high result word of **F-indirect-28** plus `0x14`.
- The incoming register-derived address contribution.
- `0x19`.

After **F-indirect-35**, the high result word of **F-indirect-28**, multiplied by four, is stored as a word at the captured middle-stage base plus `0x44`.

The closure sequence is exactly:

1. Invoke **F-indirect-36**.
2. Assign `0x08712031` to the link-register-derived working value.
3. Read a word at the scaled high result word plus `0x44` and supply it to **F-indirect-37**, the final call.

There is no additional call between **F-indirect-36** and the assignment.

The loop repeats without an exit condition. In the represented carried state, the next **F-indirect-01** target is formed from the assigned value rather than the original entry value. The arithmetic gives `0x0871302F`. Actual register preservation across the final call is not independently established.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Repeated initial destination:** If both first stores complete without intervening external modification, the destination ends with the dependency address. Omitting the first store would fail to preserve the represented write sequence.

2. **Stable initialization global:** If the initialization global remains equal to `0x1000` from its capture through the first scaled-address store’s evaluations, that store writes `0x1000` at `0x1000` plus 256 times the dependency address, assuming valid arithmetic and accessible memory.

3. **Changed initialization global:** If the captured value is `0x1000`, but the global is stably `0x2000` during both references in the first scaled-address store, that store uses `0x2000` for its base and value. The following two stores still use captured base `0x1000`. If the global changes between the first store’s expression evaluations, this evidence does not determine a unique address/value pair or physical-load sequence.

4. **Six-bit extraction:** A low result word of `0xFC000000` from **F-indirect-09** produces 63 at register-base offset `0x26C`; `0x03FFFFFF` produces zero.

5. **Narrowing:** A captured second loop-global value of `0x12345678` produces a halfword value of `0x5678` at the middle-stage computed destination.

6. **Zero-extension:** A halfword value of `0xFFFF` read from the high result word of **F-indirect-28** plus `0x14` produces later word values of `0x0000FFFF`, not `0xFFFFFFFF`.

7. **Breakpoint stops continuation:** If the breakpoint prevents resumption, none of the subsequent reads, stores, or calls occurs. No ordinary error return is provided.

8. **Base-adjustment boundary:** With a stable register-derived base across the relevant calls, the low-word store at offset `0x258` uses the base before its explicit `0xF4` decrease.

9. **Captured byte:** If the fivefold-halfword address yields byte `0xA5`, the store after **F-indirect-34** uses that captured byte, even if the dependency changes the source memory.

10. **Closure order:** A fully continuing iteration has 37 indirect calls. Following **F-indirect-35** and its subsequent word store, **F-indirect-36** occurs, then the working-value assignment, then **F-indirect-37** with the final loaded-word argument.
