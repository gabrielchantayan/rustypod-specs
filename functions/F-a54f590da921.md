# F-a54f590da921

## Purpose

The supplied static representation describes a state-mutating operation that interleaves indirect calls with byte and 32-bit memory accesses. It repeatedly transforms values into addresses, copies low bytes from words, writes selected bit fields, and forwards dependency results into later calls.

No application-level purpose is established. In particular, the evidence does not establish that these operations implement a collection, allocator, serializer, device protocol, or object lifecycle.

The representation begins with a warning about invalid instruction data and ends at an invalid-instruction termination marker. Consequently, this contract distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.
- **Inferred interpretation:** a 32-bit bit-vector interpretation needed to describe address arithmetic consistently.
- **documented_only unknowns:** actual instruction validity, calling conventions, dependency behavior, memory mapping, and successful termination.

The contract is conditional on execution reaching each described operation. It does not claim that the entire represented sequence is executable.

### Memory and arithmetic notation

The following notation describes behavior, not implementation structure:

- **byte at an address:** an 8-bit read or write.
- **word at an address:** a 32-bit read or write.
- **low byte:** the least significant eight bits of a value.
- **scaled value:** a value multiplied by a stated power of two.
- **selected-byte destination for a base:** read the byte at base plus `0x01`, zero-extend it, then add `0x11`.

A selected-byte destination lies between `0x11` and `0x110`, inclusive. It is not a pointer-sized value loaded from memory.

Unsigned right shifts discard low bits and insert zeros. Byte writes retain only eight bits. Several left shifts and multiplications operate on values represented as signed integers. Their machine-level overflow behavior is not independently established. Examples involving such operations assume 32-bit wrapping arithmetic; they are not claims about portable signed-language semantics.

## Behavior

### General ordering

The visible body is a single linear sequence, without represented conditional branches or loops. Calls occur between memory operations and can affect subsequent execution.

Many call groups contain an argument-bearing call, several calls with no explicitly displayed arguments, and a final call whose result is used later. “No explicitly displayed arguments” does not establish that a call consumes no register or stack state.

The phases below preserve the order of the visible memory effects and identify the principal value dependencies. Phase names are descriptive only; they are not established transaction boundaries.

### 1. Entry-byte updates and initial result forwarding

The first operation reads the byte at the entry base plus `0x01`. It then writes the low byte of the entry payload to that byte-selected destination.

The first indirect call receives, in order:

1. The second explicit argument shifted left by three.
2. The same shifted value.
3. The unshifted second argument.
4. The first explicit argument.

After four further indirect calls, the byte at the entry base plus `0x01` is read again. The entry payload shifted right by 22 is truncated to a byte and written to the newly selected destination.

This is a fresh read. Intervening dependencies can change the selector; the two writes are not guaranteed to target the same address.

A later call receives four times the preceding call result. Following four more calls, the function reads a word at the saved selector value plus `0x74`, then writes that word’s low byte at the selector value plus `0x01`.

### 2. Entry-base scaling and selected-byte clearing

A call receives:

- Twice the entry base.
- The second explicit argument.
- The entry base shifted right by two.
- The saved selector value.

The next call supplies a represented 64-bit result. Its low word, high word, repeated low word, and the entry base masked with `0x7fffffff` then shifted right by one are passed to the following call.

After another four calls, a returned value scaled by four becomes a new base. A word is read at that base plus `0x74`; its low byte is written at base plus `0x01`.

Following five further calls, the byte at twice the entry base plus `0x01` is read, and zero is written to its selected-byte destination.

A call then consumes an unresolved secondary-register value. The following call returns a value retained as a later word-read base. After five more calls, the byte at twice the entry base plus `0x01` is read again. The high eight bits of twice the entry base are written to its selected-byte destination.

### 3. Word-derived selectors

After a call using four times a result and four further calls, the final result scaled by four is retained as an **indexed base**.

A word is read at the retained word-read base plus `0x04`. Treating that word as a base, the function reads its byte at `0x01` and clears the selected-byte destination.

A call receives the indexed base three times. After four further calls, the earlier loaded word is shifted right by two; a byte is read at that shifted address plus `0x01`. Zero is written at this new selector plus `0x11`.

After another five-call group:

- A word is read at indexed base plus `0x04`, retained as the **field source**.
- A word is read at the newest selector plus `0x74`, retained as the **copied word**.
- The copied word’s low byte is written at that selector plus `0x01`.

The next call receives the copied word, the indexed base shifted left by 19 twice, and four times the preceding result.

### 4. Field extraction and indexed word stores

A returned word and the copied word shifted right by two are forwarded to a call. The field source is shifted right by 22 and retained.

After four further calls, a result scaled by four identifies another base. A word is read at base plus `0x74`, and its low byte is written at base plus `0x01`.

Following five more calls:

- That full word is written at four times an unresolved secondary-register value plus `0x14`.
- The same secondary-register value is passed to a call.
- A subsequent result is passed onward with two copies of the field source’s extracted low nine bits shifted left by 21.

After four further calls, the extracted field shifted left by 23 is written at four times a returned index plus `0x14`. The scaled index is then passed to a call.

After another four calls, a new returned value determines two related effects:

- Four times the value is retained as a **scaled anchor**.
- That scaled anchor is written at sixteen times the unmasked value plus `0x14`.

Only afterward is the returned value masked with `0x3fffffff`. The masked value and its right shift by two are retained. The masked value is passed to a call.

### 5. Paired stores and overlapping updates

After four more calls, the retained masked value is written at four times the returned index plus `0x14`. That index is retained as the **layout index**, and four times it is passed to a call.

After four additional calls, a result becomes a **layout token**:

1. Eight times the layout index is truncated to a byte and written at copied word plus `0x01`.
2. Four times the layout token is written at eight times the layout index plus `0x34`.
3. Four times the layout token is passed to a call.

Following another result-forwarding call group, a represented 64-bit result is obtained. Before its low word is forwarded, the function:

- Writes the low byte of eight times the layout index at the masked layout token plus `0x01`.
- Replaces the earlier word at eight times the layout index plus `0x34` with the high word of this result.

Thus, the word at that computed address is visibly written twice, with calls in between.

After another call group:

- The low byte of sixteen times the layout index is written at the masked layout token shifted right by 20, plus `0x11`.
- The low byte of the scaled anchor is written at sixteen times the layout index plus `0x0d`.

A call receives four times the latest result twice. A subsequent result is forwarded together with its unsigned right shift by three.

After four more calls, the low byte of sixteen times the layout index is written directly to address `0x11`. The byte write of the scaled anchor at sixteen times the layout index plus `0x0d` is then repeated.

### 6. Record-like writes and narrowed addressing

- The low byte of twice the masked layout token is written at masked layout token plus `0x0d`.

A new returned value determines a **record base** equal to 32 times that value and a **record word** equal to that value shifted left by seven. The value masked with `0x07ffffff` and shifted right by 17 is retained as a **narrow selector**.

After three calls:

- Four times the latest result is truncated to a byte and written at record base plus `0x0d`.

After five further calls:

The next call receives three copies of the earlier result shifted left by 21.

### 7. Selector-derived small base and fixed-address writes

Following five further calls:

- The retained selector byte is written directly to address `0x0d`.
- Twice that selector byte, the literal `0x98`, and the literal `0x260` are passed to a call.

Twice the retained selector byte becomes the **small base**, ranging from zero through 510.

After a call consuming another unresolved secondary-register value shifted right by three, and several further calls, a returned value scaled by four is passed into a distinct indirect call.

Then:

1. The previously retained truncated byte is written at small base plus `0x0d`.
2. Address `0x0d` is overwritten with `0xc0`.
3. Four times the distinct call’s result is forwarded.

These direct writes are not represented as accesses relative to an input pointer.

### 8. Linked word updates

After four further calls, four times the returned result is written at small base plus `0x24`. A word is then read at small base plus `0x74` and retained as the **linked base**.

A call receives that word, twice that word, the preceding result shifted left by five, and the word masked with `0x7fffffff` then shifted right by two.

After four further calls, the earlier result shifted left by five is written at linked base plus `0x24`.

The function reads a word at linked base plus `0x74` and passes it to a call. Four further calls produce a represented 64-bit result:

- Its low word scaled by four becomes the **forwarded scaled value**.
- The later token shifted right by three is written at four times its high word plus `0x14`.

The next call receives three copies of the forwarded scaled value and the high word shifted right by three.

Another 64-bit result is forwarded as low word, high word, repeated low word, and high word shifted right by three. After four further calls, the forwarded scaled value is written at four times a returned index plus `0x14`.

### 9. Final selector writes and termination boundary

After another five-call group, a returned value becomes the **final token**, and four times it becomes the **final scaled value**.

The function reads the byte at linked base plus `0x01` and writes the low byte of the final scaled value to its selected-byte destination.

After three more calls, the selector byte is read again. The final token masked with `0x3fffffff`, shifted right by 20, and truncated to a byte is written to the newly selected destination.

## Acceptance examples

These are conditional acceptance examples, not executed tests.

1. **Entry payload truncation.** If the entry selector byte is `0x20` and the entry payload is `0x89abcdef`, the first direct write targets `0x31` and stores `0xef`.

2. **Fresh selector after calls.** If intervening dependencies change that selector to `0x21`, the next entry-payload write targets `0x32`, not `0x31`. For the same payload, the stored byte is `0x26`, obtained by shifting right by 22 and retaining eight bits.

3. **Selector range.** A selector byte of `0xff` produces destination `0x110`; it does not produce an address derived from an eight-bit wrapping addition.

4. **Word-to-byte copy.** If a reached copy reads the word `0x12345678`, the destination receives `0x78`. This describes numeric low-byte extraction; it does not establish memory byte order.

5. **Field extraction.** If the field source is `0xffc00000`, its right shift by 22 is `0x3ff`. The low-nine-bit extraction shifted left by 21 is `0x3fe00000`. The later shift left by 23 yields `0xff800000` under 32-bit wrapping arithmetic.

6. **Small-base derivation.** If the retained selector byte is `0x7f`, the small base is `0xfe`. Its byte update occurs at `0x10b`, independently of the subsequent direct write of `0xc0` to address `0x0d`.

7. **Intervening mutation matters.** If a dependency changes the selector between the two final linked-base reads, the two writes use different destinations. Combining them into one destination violates the represented read ordering.

8. **No successful-return guarantee.** Observing all preceding writes does not establish successful completion. The supplied representation ends at an invalid-instruction boundary rather than a demonstrated return.
