# F-60acb9520432

## Purpose

F-60acb9520432 distinguishes an empty state from a nonempty state using the first integer cell of a caller-supplied region.

For the empty state, it returns the original pointer without writing to that region or invoking either identified dependency.

For the nonempty state, it obtains an integer from an address derived from the first cell, stores that integer in the second cell of the caller-supplied region, and invokes two dependencies in a fixed order, subject to the first dependency returning normally. The supplied artifact marks the second dependency as nonreturning. No normal return value is established for the nonempty path.

A possible intent is preparation of state before a terminal or exceptional operation. That interpretation is inferred, not established: neither the meaning of the stored integer nor the purpose of either dependency is available.

## Behavior

### Empty state

The function first reads the first integer cell of the input region.

If that read produces zero, it returns the original input pointer immediately. On this path:

- The second cell is not read or written.
- No indirect source address is dereferenced.
- Neither dependency is invoked.
- No explicit mutation is performed by this function.

The empty decision is based on the integer value read, not on whether the input pointer itself is null.

### Nonempty state

If the initial integer is nonzero, the function uses that already-read value as an encoded address base.

It obtains an integer from the address 12 bytes beyond that base, then stores the fetched integer into the second cell of the input region. The store precedes both dependency calls.

The fetched integer is not itself checked for zero or otherwise classified. Its value does not change which dependency is called next. A zero fetched value is still stored and followed by the same dependency sequence.

After the store, F-289ec4311c64 is invoked without explicit arguments in the supplied representation. Its return value, if any, is not used.

If F-289ec4311c64 returns normally, F-feee9156a257 is invoked, also without explicit arguments in the supplied representation. This second call is marked nonreturning.

If F-289ec4311c64 instead terminates execution, raises an exception, transfers control elsewhere, or does not finish, the second call is not reached through the visible sequence.

### No established traversal or repeated update

Although the artifact contains a repetition-shaped control structure, the visible conditions do not establish repeated processing.

The nonempty path rechecks the same already-read integer after the second-cell store. That saved value was required to be nonzero to reach the store. There is no intervening reassignment of that value.

Consequently, under the represented control flow:

- The empty path returns on its first decision.
- The nonempty path leaves the repetition-shaped region after one fetch and one store.
- There is no reachable direct assignment that advances the first cell to the contents of the second cell.
- No list walk, retry, or repeated removal is established.

Changing memory at the first cell after the initial read does not, by itself, change this saved discriminator. Unsupported memory corruption or execution outside the representation’s defined semantics cannot be used to establish a different supported path.

## Acceptance examples

These examples are conditional behavioral criteria, not executed tests. Examples using byte offsets assume the 32-bit integer layout described above.

### Empty input state

Given a readable first cell containing zero, with the second cell containing an arbitrary sentinel:

- The result is the original input pointer.
- The sentinel is unchanged by this function.
- Neither dependency is called.
- No validity requirement for an indirect source is introduced by this path.

The second cell need not be accessed merely to return from this path.

### Nonempty state with a readable source

- F-289ec4311c64 is called after that write.
- F-feee9156a257 is called only if the first dependency returns normally.
- No normal function result is required on this path.

The value 37 is illustrative; it has no special control meaning.

### Zero fetched from a nonzero base

Given a nonzero initial discriminator and a valid indirect source containing zero:

- Zero is stored into the second cell.
- The dependency sequence still begins.
- The function does not take the empty return merely because the fetched value is zero.
- No direct first-cell update is performed.

### Source equal to destination

Given that the calculated indirect source is exactly the second cell, and all accesses are valid:

- The cell is read before being written.
- Its fetched value is stored back.
- The first dependency is still invoked.

A numerically unchanged destination does not imply that the write was skipped.

### First dependency does not return normally

- The visible sequence does not reach the second dependency.
- No rollback is provided by this function.

### Invalid indirect source

- No recovery behavior is specified.
- The contract does not promise a returned error value.
