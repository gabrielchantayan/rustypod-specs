# F-18b9c1b33f18

## Purpose

F-18b9c1b33f18 performs two ordered, in-place transfers of four-byte values through a global pointer:

- The value at byte offset 0 is copied to byte offset 4.
- The value at byte offset 12 is then copied to byte offset 8.

In the ordinary case of a stable global pointer and ordinary readable/writable memory, the four slots change from **[A, B, C, D]** to **[A, A, D, D]**.

The supplied representation establishes these transfers, but not their application-level meaning. An interpretation such as synchronizing paired fields is inferred intent only. No field names, data format, initialization purpose, or larger state-machine role are established.

## Behavior

### Address selection and operation order

The established sequence is:

1. The global pointer value is captured.
2. A four-byte value selected through the global pointer at byte offset 0 is transferred to byte offset 4 through that global pointer.
3. A four-byte value at byte offset 12 through the captured pointer is transferred to byte offset 8 through the captured pointer.
4. The function returns without a value.

The first transfer completes before the second transfer is evaluated at the supplied representation’s statement level. Within each transfer, the source value must be obtained before its corresponding destination is updated.

This establishes an ordered data dependency, not a complete hardware access trace. The representation does not establish the exact number of machine-level pointer loads, instruction selection, access atomicity, or externally observable bus ordering.

The first transfer uses the global pointer directly rather than the captured pointer. The order of the pointer evaluations within that transfer is not established sufficiently to define behavior under concurrent pointer modification. A stable pointer is therefore a precondition of the simple four-slot transformation.

### Ordinary stable-pointer result

When the global pointer remains unchanged and the storage behaves as ordinary memory:

- The first slot retains its original value.
- The second slot receives the original value of the first slot.
- The third slot receives the original value of the fourth slot.
- The fourth slot retains its original value.

The prior values of the second and third slots do not contribute to the result. No explicit reads of those destination values are present.

The second source is read after the first transfer, rather than being captured together with the first source before any write. For four separate, ordinary memory slots, this distinction does not alter the result because the first destination and second source do not overlap. It can matter if the addresses have unusual aliasing or device-defined behavior.

### Captured-pointer consequences

The second transfer uses the pointer value captured at entry; it does not explicitly reload the global pointer.

Consequently, a later change to the global pointer does not, by itself, redirect the second transfer in the supplied representation. This includes a hypothetical arrangement in which an earlier write changes storage containing the global pointer itself. Whether such an arrangement is valid for the target’s memory and typing rules is not established.

This distinction does not provide a concurrency guarantee. No synchronization protects the pointer or the referenced storage, and the first transfer still uses the global pointer directly.
