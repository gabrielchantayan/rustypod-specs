# F-16f7173b5128

## Purpose

F-16f7173b5128 performs an ordered, unchecked mutation of memory selected by arguments, implicit entry state, global storage, and previously read values. It then invokes an entry-supplied callback, invokes F-cdec09f5d432, and reaches a facility designated non-returning if both calls return.

No application-level purpose is established. Repeated field offsets and address-valued stores do not establish a constructor, allocator, collection operation, or ownership transfer.

This contract describes static evidence only. It does not establish that arbitrary inputs permit defined execution or that every represented operation corresponds to a separately observable machine access.

## Behavior

### Access and arithmetic model

A **word** access is four bytes; a **halfword** access is two bytes; a **byte** access is one byte. All offsets below are byte offsets.

Halfword reads are signed 16-bit reads widened for subsequent calculations. A representation of 0xFFFF therefore contributes negative one. Character reads have unresolved signedness; a high-bit character may affect both address selection and subsequent halfword conversion.

References to a value’s “byte” or “halfword” mean the represented narrowing conversion. Low-eight-bit and low-sixteen-bit interpretations are conditional on the applicable conversion model. Byte order is not independently established.

Address arithmetic uses represented 32-bit integer operations, including addition, multiplication, doubling, and left shifts by one, four, and eight. No bounds check or overflow recovery appears. Unlimited-precision arithmetic and universally defined modulo-\(2^{32}\) arithmetic must not be substituted for unresolved signed overflow or shift behavior.

The body has one visible forward path. The ordering below is the represented ordering between operations; it does not impose an otherwise unspecified operand-evaluation order within an expression, atomicity, or synchronization.

### Retained roles

Several retained values cross stage boundaries:

- **Working base:** first obtained during stage 3 and subsequently replaced at specified points.
- **Anchor:** obtained during stage 2 and retained through the mutation region.
- **Bridge:** initially obtained from a stage-2 offset-0x74 read, then replaced during stage 6.
- **Carry:** a retained word supplied to the next stage’s offset-0x14 store.
- **Saved byte source:** a retained word whose narrowed value supplies later byte writes.

These roles describe dependencies, not object types. A later reread does not retroactively change a retained value.

### Entry effects

The initial word read at primary + 0x14 is retained before the fourth argument is written as a byte at secondary + 0x11. Its halfword conversion is then written at primary plus the third argument.

Only afterward is primary + 0x44 read. Thus an overlapping halfword write can affect this read. Secondary is then written as a word at secondary + 0x54.

The initial 0x14 value selects stage 1’s first offset-0x44 destination. The primary + 0x44 result supplies its initial carry.

### Twelve global stages

Each stage independently evaluates its designated global **twice**:

1. The first evaluation is retained as that stage’s global-derived base.
2. A separate evaluation of the same global supplies a word written through the stage-specific offset-0x44 destination.
3. The incoming carry is then written at the retained global-derived base + 0x14.

The second evaluation is not a reuse of the first. The stages below specify each destination and the intervening accesses that establish the next stage’s inputs.

#### Stage 1 — G1

G1 is retained as the stage base. Its separate evaluation is written at the initial primary + 0x14 result’s offset 0x44. The initial carry is written at G1’s retained base + 0x14.

Secondary + 0x11 receives the byte conversion of doubled secondary. A word at first argument + 0x64 is retained, followed by a word read at secondary + 0x44 and a signed halfword read at secondary plus the retained stage base.

Secondary is written at the initial carry’s offset 0x54. The retained first-argument-derived byte is written at secondary + 0x11. The retained secondary + 0x44 destination then receives the retained stage base at offset 0x44.

A word read at the signed-halfword-derived base + 0x44 supplies a lookup base used during stage 2. The stage base’s 0x14 word is read; the retained byte is written again at secondary + 0x11; and that 0x14 word’s halfword is written at the signed halfword plus the stage base.

Finally, the stage base’s 0x44 word becomes the carry, and secondary receives its self-address at offset 0x54. The retained 0x14 word selects stage 2’s first destination.

#### Stage 2 — G2

G2 is retained; its separate evaluation is written at the preceding retained 0x14 word’s offset 0x44. The incoming carry is written at the retained G2 base + 0x14.

After a doubled-secondary byte write, the **anchor** is obtained by reading a signed halfword at secondary plus this stage base, then reading a word at that signed value + 0x44. The stage base’s 0x14 word is retained for stage 3’s first destination.

Secondary + 0x11 receives a byte from the stage-1 lookup base’s 0x64 word. A word from anchor + 0x04 is retained. The **bridge** is then read from the stage base + 0x74.

The anchor + 0x04 value is written at secondary + 0x54. The retained stage 0x14 word is narrowed and written at twice secondary plus the stage base. The stage base’s 0x44 word becomes the carry, followed by secondary’s self-address store.

#### Stage 3 — G3

G3 is retained; its separate evaluation is written at the preceding retained 0x14 word’s offset 0x44. The incoming carry is written at G3’s retained base + 0x14.

Secondary + 0x11 receives a byte from the retained anchor + 0x04 value. A fresh anchor + 0x64 word becomes a saved byte source. The body reads secondary + 0x44 and a signed halfword at secondary plus the stage base, then writes the bridge at anchor + 0x54.

The **working base** is obtained by reading the stage base + 0x14. Its offset 0x0D receives the stage base’s byte. The retained secondary + 0x44 word is narrowed into the halfword destination formed by the signed halfword plus the stage base.

The stage base’s 0x44 word becomes the carry. The working base receives its self-address at offset 0x54. The retained secondary + 0x44 word selects stage 4’s first destination.

#### Stage 4 — G4

G4 is retained; its separate evaluation is written at that retained secondary-field destination + 0x44. The incoming carry is written at the retained G4 base + 0x14.

The working base’s 0x11 byte receives the saved byte source. Its 0x44 word and a signed halfword at working base plus stage base are read. The bridge is again written at anchor + 0x54.

The working base is replaced by the stage base’s 0x14 word, then receives the stage base’s byte at offset 0x0D. A separate word read at incoming carry + 0x14 supplies a reached base. Anchor is written at bridge + 0x54.

The retained working-field word is narrowed into a halfword at the signed value plus that reached base. The reached base’s 0x44 word becomes the carry. The replaced working base receives its self-address store.

#### Stage 5 — G5

G5 is retained; its separate evaluation is written at the preceding retained working-field word’s offset 0x44. The incoming carry is written at G5’s retained base + 0x14.

After a doubled-working-base byte write, a signed halfword is read at working base plus stage base. A character is then read at that signed value plus the incoming carry.

The stage base’s offset 0x1D receives the bridge’s byte. The character is converted to a halfword and written at the signed value plus the stage base. The stage base’s 0x44 word becomes the carry, followed by the working-base self-address store.

The retained character selects stage 6’s first destination.

#### Stage 6 — G6

G6 is retained; its separate evaluation is written at the preceding character-derived base + 0x44. The incoming carry is written at G6’s retained base + 0x14.

Following another doubled-working-base byte write, a signed halfword and then a character are read using working base plus stage base, and signed value plus incoming carry, respectively.

A fresh anchor + 0x64 word is written at signed value + 0x54. The character-derived base’s offset 0x0D receives the incoming carry’s byte.

The **bridge is replaced** by a word read at this stage base + 0x64. Subsequent bridge uses refer to this replacement, not the earlier stage-2 offset-0x74 value.

The character is narrowed into the halfword destination at signed value plus stage base. The stage base’s 0x44 word becomes the carry, followed by a working-base self-address store.

#### Stage 7 — G7

G7 is retained; its separate evaluation is written at the preceding character-derived base + 0x44. The incoming carry is written at G7’s retained base + 0x14.

After a doubled-working-base byte write, a fresh anchor + 0x64 word becomes the saved byte source. A signed halfword and character are obtained through the same two-level addressing pattern as stage 6.

Anchor + 0x01 receives the stage base’s byte; stage base + 0x0D receives the incoming carry’s byte. The replacement bridge is written at stage base + 0x44. The character-derived base + 0x0D receives the stage base’s byte, followed by the character-to-halfword write.

Only then is stage base + 0x44 reread as the new carry. This reread follows the explicit bridge replacement and any overlapping intervening writes. A working-base self-address store follows.

#### Stage 8 — G8

G8 is retained; its separate evaluation is written at the preceding character-derived base + 0x44. The incoming carry is written at G8’s retained base + 0x14.

The working-base byte receives the saved source. A fresh anchor + 0x64 read replaces that saved source. The working base’s 0x44 word and a signed halfword at working base plus stage base are retained.

A reached base is read at incoming carry + 0x74. The working base is then replaced by its own 0x14 word. The retained 0x44-derived base + 0x0D receives the reached base’s byte. The retained word is narrowed into a halfword at signed value plus reached base.

The reached base’s 0x44 word becomes the carry. The new working base receives its self-address store.

#### Stage 9 — G9

G9 is retained; its separate evaluation is written at the preceding retained 0x44-derived base + 0x44. The incoming carry is written at G9’s retained base + 0x14.

After the saved-source byte write, the working base’s 0x44 word and a signed halfword are read. Incoming carry + 0x15 receives the stage base’s byte, potentially overlapping a word beginning at incoming carry + 0x14. The incoming carry is also written at stage base + 0x44.

A reached base is read from the retained working-field value + 0x74. The retained working-field value is narrowed into a halfword at signed value plus reached base. That reached base’s 0x44 word becomes the carry, followed by the working-base self-address store.

#### Stage 10 — G10

G10 is retained; its separate evaluation is written at the preceding retained working-field value + 0x44. The incoming carry is written at G10’s retained base + 0x14.

After a doubled-working-base byte write, a fresh anchor + 0x64 word becomes the saved source. The working base’s 0x44 word and a signed halfword are read. The working base is replaced by the word at signed value + 0x14.

The retained working-field value receives its self-address at offset 0x54. The bridge is written to the sum of stage base and incoming carry, with no fixed field offset. The retained working-field value replaces stage base + 0x14.

A byte from a fresh bridge + 0x44 word is written at stage base + 0x0D. The replaced working base + 0x0D receives the retained working-field value’s byte. That value is also narrowed into the halfword destination at signed value plus stage base.

Stage base + 0x44 becomes the carry; the replaced working base receives its self-address store.

#### Stage 11 — G11

G11 is retained; its separate evaluation is written at the preceding retained working-field value + 0x44. The incoming carry is written at G11’s retained base + 0x14.

The working-base byte receives the saved source. A fresh anchor + 0x64 word is retained for stage 12. The working base’s 0x44 word and a signed halfword are read.

The current working base is written at incoming carry + 0x54. Its offset 0x11 then receives the first byte lacking visible initialization. The retained working-field destination + 0x44 receives the retained stage base.

The working base is replaced by the word at signed value + 0x14. The remaining cross-address sequence matches stage 10: retained-field self-address store, bridge store at stage base plus incoming carry, replacement of stage base + 0x14, bridge-derived byte, working-base byte, and halfword store. Stage base + 0x44 is freshly retained as carry, followed by the working-base self-address store.

#### Stage 12 — G12

G12 is retained; its separate evaluation is written at the preceding retained working-field value + 0x44. The incoming carry is written at G12’s retained base + 0x14.

The retained stage-11 anchor read now supplies the byte written at working base + 0x11. This later assignment does not initialize the earlier unresolved use retroactively.

The working base’s 0x44 word and a signed halfword at working base plus stage base are retained. The signed value receives its own value at offset 0x54. The stage base’s 0x11 byte receives the working base’s byte. These two stores are then repeated in the same order.

### Product-derived continuation

The signed value multiplied by the retained working-field word selects a 0x44 word read. Its result selects a 0x74 word read, whose result selects a 0x14 word read. The resulting destination’s own 0x14 word is retained before replacement with doubled working base.

That retained old word selects another 0x14 read. Multiplying this read by the signed value produces a new product. After a signed-value self-address store, the final stage base’s 0x11 byte receives the old word’s byte.

The new product’s 0x74 word is retained. The product is multiplied again by the signed value. After another self-address store, the final stage base’s 0x11 byte receives the second byte lacking visible initialization.

The resulting product’s 0x44 word and anchor + 0x74 word are retained. The retained product-selected 0x74 word is written at final stage base + 0x64. Its offset 0x09 receives the retained product-field byte.

Product + 0x11 receives a byte from a **fresh** product + 0x44 read. This reread follows intervening writes and need not equal the retained read.

After another signed-value self-address store, twice product + 0x11 receives the retained product-selected 0x74 word’s byte. A further word read uses signed value times product + 0x44. Anchor + 0x14 supplies a final destination.

The retained 0x74-derived base + 0x01 receives the anchor + 0x74 byte. The final destination receives the further product-read byte at offset 0x11 and doubled product’s byte at offset 0x09.

### Calls and terminal boundary

Before the callback, represented local storage receives anchor shifted left by four and eight, copies of derived values, and four word-sized zeros. No public record layout relative to the fifth argument is established.

The callback receives the fifth argument’s storage address, zero, and zero. Its result is not consumed.

If it returns, the seventh argument’s represented storage receives zero. Other represented storage receives 0x08400E1C and three additional word-sized zeros.

F-cdec09f5d432 is then called with a freshly evaluated global value and three zeros. The global evaluation occurs after callback return.

If F-cdec09f5d432 returns, the terminal facility is invoked with **zero and 0x08401154**. It is designated non-returning. A represented indirect transfer through its result does not establish an ordinary reachable continuation or normal return.

## Acceptance examples

These are conditional static criteria, not executed tests.

- **Early overlap:** If the initial word is 0x12345678, low-bit halfword narrowing yields 0x5678. If its destination overlaps primary + 0x44, the subsequent word read uses post-write memory; exact bytes depend on byte order and overlap position.
- **Separate global evaluations:** If a stage’s first global evaluation yields one base and its second yields another value, the offset-0x14 destination uses the retained first value while the preceding derived offset-0x44 store carries the second.
- **Bridge replacement:** After stage 6 reads its stage base + 0x64, stage-7 and later bridge-dependent stores use that retained replacement, not stage 2’s offset-0x74 result.
- **Signed addressing:** A halfword representation of 0xFFFF contributes negative one. A character representation of 0x80 remains conditional on character signedness.
- **Retained versus reread:** Replacing the product-selected destination’s 0x14 field does not replace the old word used for the next lookup. Conversely, the later explicit product + 0x44 reread follows any intervening overlapping writes.
- **Uninitialized bytes:** Neither unresolved byte write has a concrete expected value. Its later assignment is not an oracle for its earlier use.
- **Callback mutation:** If the callback changes the final dependency’s global source and returns, the subsequent call uses the post-callback evaluation.
- **Terminal operands:** If all accesses and both calls complete, the terminal invocation supplies zero and 0x08401154; an ordinary function return is not established.
