# F-07e65cc048f4

## Purpose

F-07e65cc048f4 performs three ordered 32-bit writes, calls two dependencies, and returns an address derived from the first dependency’s result.

Its established behavior is structural: it obtains table pointers from external state, initializes caller-supplied storage with a table-selected word, obtains an address from F-075c80dad330, performs two writes relative to an adjusted form of that address, and calls F-95ac4f08c8c7 with a freshly calculated address and the caller’s second argument.

An object-layout initialization or adjustment operation is a plausible interpretation. The supplied evidence does not establish an object type, construction or destruction phase, ownership convention, or semantic meaning for either dependency.

## Interface

### Inputs

- **Storage address:** an address supporting an initial 32-bit write. The address four bytes beyond it is passed to F-075c80dad330.
- **Opaque argument:** a four-byte value passed to F-95ac4f08c8c7 without an explicit transformation. Its interpretation and signedness are not established.

The function also reads an **external table-pointer location**. This is an implicit input, not a caller argument. The function reads this location twice before the initial write. One pointer value is retained for later table accesses; the other selects the word used for the initial write.

### Output

On normal return, the function returns the address obtained by subtracting four bytes from the 32-bit result of F-075c80dad330.

This returned address, called the **derived base** below, is also the base for the two later writes and the final dependency’s address calculation.

The returned address need not equal the input storage address. Equality requires the first dependency to return a value representing the address four bytes above that storage address.

## Behavior

### Initial external reads and storage write

Before calling either dependency, the function performs the following ordered accesses:

1. It reads the external table-pointer location and saves that pointer for later use.
2. It independently reads the same external location again.
3. Through the pointer obtained by the second read, it reads the first 32-bit table word.
4. It writes that word to the caller’s storage address.

The initial word is therefore not selected through the saved pointer as a matter of data dependency. It is selected through the result of the second external read.

With unchanged external state, the two pointer values identify the same table. The body neither compares the values nor establishes their equality independently of that condition. This distinction does not establish supported concurrent-update behavior; it preserves the two accesses without resolving the concurrency model.

After the initial write, the function’s later table accesses use the pointer saved by the first external read. They do not use the pointer obtained by the second read and do not explicitly reread the external table-pointer location.

### First dependency and base derivation

The function calls F-075c80dad330 with the address four bytes beyond the caller’s storage address.

The initial storage write has already completed when this call begins. The dependency may therefore observe that write, subject to its own behavior and the execution environment.

When the dependency returns, the function consumes its result as a 32-bit integer and subtracts four bytes to derive the base address.

There is no explicit check that:

- the result is nonzero;
- the subtraction is representable;
- the resulting address belongs to the original storage;
- the resulting address has sufficient surrounding readable or writable storage.

Boundary-crossing arithmetic and invalid integer-to-address conversions remain documented_only. No wrapping behavior is added to this contract.

### Refreshed table read and base write

After the first dependency returns, the function reads the first 32-bit word through the pointer saved by the first external read. It writes this freshly read word at the derived base.

This is a new table-content read. It is not a reuse of the word written before the dependency call.

Consequently, the initial write and the base write can differ if relevant table contents change. They can also be selected from different tables if an externally defined execution permits different values from the two initial pointer reads.

Changing only the external table-pointer location during F-075c80dad330 does not redirect the saved pointer. Changing or invalidating the saved table itself can affect the later accesses.

The input storage address and derived base may coincide, differ, or refer to overlapping storage. No separation check is present.

### Offset-directed write

The first word freshly read from the saved table has two roles:

- it supplies the value written at the derived base;
- interpreted as an address, it selects displacement metadata twelve bytes before that address.

The function reads a 32-bit displacement from that metadata location and adds it, in bytes, to the derived base. At the resulting destination, it writes the saved table’s second 32-bit word, located four bytes after the first word.

The second table word supplies the value being written, not the displacement.

The metadata address for this write is formed from the freshly read table word. It is not obtained by rereading the derived base at this stage.

The reads needed to obtain the displacement and second table word both precede completion of the write. The supplied expression does not establish a total order between those independent reads. The contract therefore does not impose one.

No explicit restriction requires a positive, nonzero, or allocation-local displacement. In particular:

- zero directs the write to the derived base;
- a negative displacement directs it below the base;
- a positive displacement directs it above the base.

These cases still require valid arithmetic and valid destination storage.

### Fresh calculation for the final dependency

After the offset-directed write, the function reads the current first 32-bit word at the derived base.

It interprets this current word as an address, reads a 32-bit displacement from twelve bytes before it, and adds that displacement to the derived base. The resulting address is the first argument to F-95ac4f08c8c7. The unchanged opaque four-byte argument is the second argument.

This is a fresh read chain. The function does not simply retain the destination calculated for the preceding write.

The final dependency’s first argument can therefore differ from that write destination. Relevant aliasing includes the preceding write replacing:

- the first word at the derived base;
- the displacement metadata subsequently read;
- other storage that determines the later read chain.

The final address calculation does not itself establish that the dependency’s argument points to a valid object or to storage owned by the caller.

### Return

If F-95ac4f08c8c7 returns normally, the function returns the previously derived base.

The final dependency’s return value, if any, has no use in the supplied body. The returned address is not replaced with the address passed to that dependency.

No further explicit memory write occurs after the final call.

## Side effects

The function explicitly performs three 32-bit writes, in this order:

1. At the caller’s storage address, using the first word selected through the second external pointer read.
2. At the derived base, using a fresh first-word read through the pointer saved by the first external read.
3. At the displacement-directed destination, using the saved table’s second word.

These are three operations, not necessarily three distinct destinations.

F-075c80dad330 executes between the first and second writes. F-95ac4f08c8c7 executes after all three writes.

The body does not explicitly assign to the external table-pointer location. Nevertheless, an explicit write could affect that location or table storage through aliasing. Either dependency may also modify external state.

No explicit allocation, release, synchronization, ownership transfer, or rollback operation appears in the body. This does not establish that the dependencies avoid such effects.

Completed writes are not transactional. If a later access fails or a dependency does not return normally, no local rollback or error translation is established.

No final memory contents are guaranteed independently of dependency effects. In particular, the last dependency could modify or release relevant storage before returning.
