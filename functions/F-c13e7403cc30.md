# F-c13e7403cc30

## Purpose

F-c13e7403cc30 performs an inclusive range check on an integer selector. When the selector is within the configured range, it returns one byte from an address formed by adding the selector directly to a stored integer address value. Otherwise, it returns a zero byte.

The lower bound is a gate, not an indexing origin. The accepted selector is not adjusted by subtracting the lower bound.

This is a source-facing contract based solely on the supplied static representation. It does not establish that the descriptor or selected address is valid, that the memory access is safe, or that a zero result means rejection.

## Interface

The function accepts:

- **A descriptor pointer:** points to consecutive signed-integer slots. The first slot supplies the lower bound, the second supplies the upper bound, and the third supplies an integer used to form the byte address.
- **A selector:** a signed integer compared against the two bounds and, if accepted, added directly to the third slot’s value.

The result is a **one-byte value**:

- On rejection, the result is zero.
- On acceptance, the result is the byte read from the computed address, including zero if that byte is zero.

There is no separate success indicator, error code, returned pointer, or output parameter.

### Widths and layout

The supplied representation identifies the descriptor slots and selector as signed `int` values. It does not independently establish the target ABI, integer width, pointer width, alignment requirements, or byte order.

Accordingly:

- Both comparisons use the signed-integer interpretation shown by the representation.
- Descriptor slots are consecutive at offsets of zero, one integer width, and two integer widths from the descriptor address.
- On a target with 32-bit integers and eight-bit bytes, these are three 32-bit slots at byte offsets 0, 4, and 8.
- The result is represented as one byte. On an eight-bit-byte target, it contains eight bits, with possible bit patterns corresponding to 0 through 255. A caller’s later signed or unsigned interpretation is outside this function.
- The third slot is an integer, not a separately loaded pointer-width field. A wider pointer ABI must not be assumed to widen this stored field.

The descriptor’s interpretation is therefore partly established, while its concrete ABI layout remains conditional on the target.

### Preconditions for defined access

The descriptor must permit the first integer read on every invocation.

Further accessibility requirements depend on the path taken:

- If the selector is below the lower bound, no second or third slot is needed by the represented evaluation.
- If the lower-bound comparison succeeds, the second slot must be readable.
- If both comparisons succeed, the third slot must be readable, address formation must have valid target semantics, and the resulting byte address must be readable.

No source-visible validation enforces these requirements.

## Behavior

### Range decision

The function first obtains the lower bound from the descriptor and tests whether that bound is less than or equal to the selector.

If that comparison fails, it returns zero. The upper-bound slot, address-forming slot, and payload byte are not evaluated on this path.

If the first comparison succeeds, the function obtains the upper bound and tests whether the selector is less than or equal to it.

If this second comparison fails, it returns zero. The address-forming slot and payload byte are not evaluated on this path.

Both endpoints are inclusive. A selector equal to either bound passes the corresponding comparison.

For a stable descriptor whose lower bound exceeds its upper bound, no selector satisfies both conditions. Such a descriptor produces zero without a payload read, provided the descriptor reads themselves are valid. Some selectors are rejected after the first comparison; others require the second.

### Accepted access

If both comparisons succeed, the function reads the third integer slot, adds the selector to that integer value, interprets the resulting value as a byte address, and reads one byte there.

The addition uses the selector itself. It does not use the selector’s distance from the lower bound. Thus a lower bound of 100 does not make selector 100 refer to the unadjusted stored address value; it refers to that value plus 100.

There is no multiplication by an element size. The final access is a byte access.

Negative selectors are not rejected merely for being negative. They can pass when the bounds admit them. On an accepted path, a negative selector participates directly in address formation.

The represented addition has integer operands. It must not silently be specified as arbitrary-precision arithmetic, pointer-width arithmetic, or unsigned modular arithmetic. Overflow behavior and integer-to-pointer conversion depend on semantics not established by the supplied material. Acceptance claims involving those cases require additional target evidence.

### Access order

The static representation establishes this logical evaluation order:

1. Read the lower-bound slot.
2. If the lower-bound comparison succeeds, read the upper-bound slot.
3. If both comparisons succeed, read the address-forming slot.
4. Form the address and read its byte.
5. Return that byte, or return zero on rejection.

This is an evaluation contract, not evidence of exact machine instructions, physical bus transactions, synchronization, or speculative-access behavior.

The function does not take an atomic snapshot of all descriptor fields. Concurrent changes to those fields are not assigned deterministic semantics here.

## Side effects

The function contains no explicit memory writes, allocation, release, ownership transfer, callback, or invocation of another function.

Its direct memory effects are reads:

- One descriptor read on the earliest rejection path.
- Two descriptor reads when the upper-bound comparison is reached but rejects.
- Three descriptor reads and one byte read on acceptance.

These are logical reads in the supplied representation. They do not establish exact hardware transaction counts.

The descriptor remains caller-provided storage. The function does not explicitly retain it or release it. The same applies to the memory supplying the returned byte.

The selected byte could reside within the descriptor or overlap other storage; no disjointness check appears. Such overlap does not introduce a source-visible write.

If any address refers to memory-mapped devices or other read-sensitive storage, environmental effects of reading it are outside the established contract.

Invalid memory access is not converted into a zero result. The zero return is the defined rejection result, not a general fault-handling mechanism.
