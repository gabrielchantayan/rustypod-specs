# F-d5511c118375

## Purpose

F-d5511c118375 conditionally retrieves a 16-bit field from an indirectly referenced record.

The function first invokes an indirect operation associated with its input object. If that operation returns zero, the function returns zero without reading the object’s secondary-record pointer. If the operation returns nonzero, the function reads that pointer. A null secondary-record pointer also produces zero. Otherwise, the function follows another pointer and returns the 16-bit field at a fixed offset from that final pointer.

This establishes a gated field lookup, not the meaning of the retrieved field. Interpreting the indirect operation as a validity check, or the field as a status, identifier, or count, would be inferred intent rather than established behavior.

## Interface

**Input:** One pointer to an object whose relevant representation consists of 32-bit words and byte-addressed fields.

**Output:** One 16-bit value. The available evidence establishes the returned bit pattern, not whether callers interpret it as signed, unsigned, or another 16-bit type.

The relevant object layout is:

| Location | Width | Role |
|---|---:|---|
| Input object, offset `0x00` | 32 bits | Address of a dispatch structure |
| Dispatch structure, offset `0x0C` | 32-bit callable-address representation | Indirect operation invoked by this function |
| Input object, offset `0x04` | 32 bits | Secondary-record pointer, read only after a nonzero indirect result |
| Secondary record, offset `0x40` | 32 bits | Pointer to a final record |
| Final record, offset `0x2E` | 16 bits | Field returned on the successful lookup path |

All offsets are byte offsets. The layout follows the supplied 32-bit representation; it must not be silently widened to a layout with eight-byte pointer fields.

The indirect operation receives the original input-object pointer as its sole explicit argument. Its result is treated as a 32-bit integer for a zero-versus-nonzero decision.

## Behavior

### Dispatch and gating

The first established data access is the 32-bit read at input-object offset `0x00`. The resulting address locates the dispatch structure. The function obtains the callable target from that structure at offset `0x0C`, then invokes it with the original input pointer.

The input object is not checked for null before dispatch lookup. Likewise, neither the dispatch pointer nor the callable target is explicitly checked for null.

The indirect call precedes every read of the secondary-record pointer and final-record data. This ordering is significant because the indirect operation may change memory.

If the indirect operation returns zero:

- The function returns the 16-bit value zero.
- It does not read the secondary-record pointer at input-object offset `0x04`.
- It does not access either downstream record.

A nonzero result permits the lookup to continue. The magnitude and sign of that result do not otherwise affect the outcome. A negative 32-bit result is nonzero and therefore takes the same path as a positive result.

### Secondary-record selection

After a nonzero indirect result, the function reads the 32-bit value at input-object offset `0x04` and treats it as the secondary-record pointer.

This is a post-call read. The contract therefore uses the pointer value present after the indirect operation returns, not a value captured before that operation.

If this pointer is zero, the function returns the 16-bit value zero. No read at secondary-record offset `0x40` occurs on that path.

If the pointer is nonzero, the lookup continues. Nonzero is the only established check on this pointer; it does not establish that the referenced storage is accessible or correctly formed.

### Final field retrieval

For a nonzero secondary-record pointer, the function reads a 32-bit pointer from secondary-record offset `0x40`.

It then reads exactly 16 bits at offset `0x2E` from that final pointer and returns those bits.

There is no explicit null check on the final pointer. In particular, a zero final pointer is not converted into the function’s ordinary zero-result case. It instead leads to an attempted field access at the corresponding offset, with consequences determined by the execution environment.

The selected field is returned without an established mask, range check, scaling operation, or semantic conversion. All 16 bits are significant. A stored zero is therefore indistinguishable in the return value from either gated-zero path.

### Address arithmetic and access boundaries

The arithmetic consists of fixed byte offsets from pointer values. The evidence establishes no bounds checks, overflow checks, or recovery from invalid effective addresses.

The last access covers the two bytes beginning at final-record offset `0x2E`, namely offsets `0x2E` and `0x2F`. The source representation does not establish byte order, so the relationship between individual stored bytes and the returned numerical value remains target-dependent.

## Side effects

F-d5511c118375 contains no explicit stores to the input object, downstream records, or globals. It performs no explicit allocation, release, or ownership transfer.

The indirect call is nevertheless an externally observable action. Its effects are unknown. It must not be assumed to preserve globals, retain object contents, avoid allocation, or leave ownership unchanged.

In particular:

- A dependency may replace the secondary-record pointer before the function reads it.
- A dependency that invalidates the input object can make the subsequent read unsafe when it returns nonzero.
- Returning zero suppresses downstream reads but does not undo effects already performed by the dependency.
- The function provides no explicit cleanup or rollback following the indirect call.

The pointer arguments and record references are used for access, not explicitly acquired or released by this function. Any ownership implications of the indirect operation are outside the established contract.
