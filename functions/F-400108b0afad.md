# F-400108b0afad

## Purpose

F-400108b0afad initializes a caller-provided result slot from a container’s distinguished node, then selects between two behaviors:

- A conditional bulk operation followed by explicit restoration of an empty-looking container state.
- Repeated advancement of a caller-supplied cursor and a per-item operation until a comparison dependency returns exactly 1.

The structure is consistent with range removal from a linked container. That interpretation is **inferred intent**, not an established semantic guarantee: the supplied evidence does not define the comparison, advancement, bulk-operation, or per-item dependencies.

The function also returns a packed 64-bit value. That value is not uniformly the contents of the result slot, a count, or a success status. Its two 32-bit components depend on the path taken and, on the iterative path, on values writable by a dependency.

## Interface

### Inputs

The function has four arguments:

1. **Result slot**: an address at which the function writes a 32-bit value.
2. **Container address**: a 32-bit address-bearing value used to access container fields.
3. **Cursor address**: an address whose first 32-bit word is read during iteration; it is also passed to comparison and advancement dependencies.
4. **Boundary operand**: a 32-bit value passed to the comparison dependency. Its representation and whether it denotes an address, cursor, or other object are not established here.

The visible representation uses 32-bit integer and field accesses and a 64-bit return value. Address-bearing values are represented through 32-bit quantities in the supplied source. This establishes the apparent source-level layout, not a portable ABI for other pointer widths.

No argument is explicitly validated.

### Output

The function returns a 64-bit concatenation:

- The high 32 bits come from one address-bearing local word.
- The low 32 bits come from another address-bearing local word.
- Concatenation preserves the component bit patterns; it is not a signed arithmetic combination.

For discussion, these two local words are called the **upper-return word** and **lower-return word**. These labels describe their role in this contract, not source identifiers.

Initially:

- The upper-return word contains the container address.
- The lower-return word contains the result-slot address.

On ordinary loop completion, those current local words form the return value. On the early bulk return, the high half instead contains a newly read distinguished-node address.

There is no explicit error-status return.

## Behavior

### 1. Initialization and first comparison

Before any dependency call, the function:

1. Reads the 32-bit distinguished-node address from container offset 0x10.
2. Writes that value to the result slot.
3. Reads container offset 0x10 again.
4. Reads the 32-bit field at offset 0x08 of the node obtained by that second read.
5. Saves that field in a temporary comparison word.
6. Initializes the upper-return word to the container address and the lower-return word to the result-slot address.
7. Calls F-f689f7569c43 with the cursor address and the address of the temporary comparison word.

The second read of container offset 0x10 matters if the result slot aliases that field or related storage. The function does not establish a cached, immutable distinguished-node identity.

The first comparison’s result is interpreted as **zero versus nonzero**:

- Zero skips the bulk-path checks.
- Any nonzero value proceeds to the second comparison.

The temporary is supplied by address. The dependency may modify it. No later direct use of that temporary is visible.

### 2. Conditional bulk path

If the first comparison returns nonzero, the function reads container offset 0x10 again and places that node address in another temporary word. It then calls F-f689f7569c43 with:

- The boundary operand as the first argument.
- The address of this second temporary as the second argument.

This comparison also uses a **zero versus nonzero** decision.

- If the second comparison returns zero, the function enters the iterative path.
- If it returns nonzero, the function reads the 32-bit field at container offset 0x14.
- If that field is zero, the function enters the iterative path.
- Only a nonzero second comparison and a nonzero offset-0x14 field select the bulk operation.

The offset-0x14 field is not directly read for this decision when the second comparison returns zero. It is tested for nonzeroness, not positivity. A bit pattern interpreted as a negative signed integer still satisfies the test.

When selected, the bulk operation proceeds as follows:

1. Read container offset 0x10.
2. Read the 32-bit field at offset 0x04 of that node.
3. Call F-d407263631bd with the original container address and the field value just read.
4. Set the offset-0x08 field of the node currently obtained from container offset 0x10 to that currently obtained node address.
5. Clear the offset-0x04 field of the node currently obtained from container offset 0x10.
6. Set the offset-0x0c field of the node currently obtained from container offset 0x10 to that currently obtained node address.
7. Clear container offset 0x14.
8. Read container offset 0x10 and write that value to the result slot.
9. Return immediately, placing the value from step 8 in the high 32 bits and the lower-return word in the low 32 bits.

The container’s distinguished-node field is reloaded after the bulk dependency. Consequently, the reset is not guaranteed to target the node observed before that call. The dependency’s effects on container storage are unknown.

The reset statements occur in the order listed. The evidence does not establish a finer machine-level ordering among multiple reads within one assignment expression.

Absent indirect modification of the lower-return word, the low half of this early return is the original result-slot address. It is not the value written to that slot.

### 3. Iterative path

The iterative path is used whenever the bulk path is not selected. It first calls F-f689f7569c43 with the cursor address and boundary operand.

This comparison has a different acceptance rule from the earlier comparisons:

- A return value of **exactly 1** terminates iteration.
- Every other value, including 0, 2, and negative values, enters the loop body.

Each loop body performs these actions in order:

1. Read the first 32-bit word at the cursor address and retain it as the current item value.
2. Call F-195567ecfcce with the cursor address.
3. Store the retained, pre-advancement item value in the lower-return word.
4. Call F-4d4572315288 with:
   - The address of the upper-return word.
   - The original container address.
   - The address of the lower-return word.
5. Write the current upper-return word to the result slot.
6. Repeat the loop comparison.

The retained item comes from before the advancement call. Even if F-195567ecfcce changes the cursor’s first word, the subsequent per-item call receives the previously captured item through the lower-return word.

Both return words are passed by address to F-4d4572315288. Either may be changed by that dependency. The result-slot write uses the upper-return word **after** the call, not the original container address unconditionally.

The upper-return word is initialized only once. It is not reset at the beginning of each iteration. The lower-return word is overwritten with the newly captured item on every iteration before the per-item call.

After a loop comparison returns exactly 1, the function returns the current upper-return and lower-return words as the high and low halves, respectively. There is no additional result-slot write at loop termination.

### 4. Empty iteration and termination limits

If the first loop comparison returns exactly 1:

- No advancement call occurs.
- No per-item call occurs.
- The function performs no further direct result-slot write after initialization.
- The returned high half is the initialized container address.
- The returned low half is the initialized result-slot address.

These statements describe direct local operations; comparison dependencies may have their own observable side effects.

No iteration limit, progress check, or fallback termination condition is visible. If the loop comparison never returns exactly 1, normal termination is not established.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, storage is valid, arguments do not overlap, dependencies return normally, and dependencies make no unmentioned modifications.

1. **Immediate loop completion.**  
   The first comparison returns 0; the first loop comparison returns 1. The result slot receives the distinguished-node address during initialization. Neither the bulk dependency nor either loop-body dependency is called. The return packs the container address above the result-slot address.

2. **Complete bulk selection.**  
   Both preliminary comparisons return nonzero, and container offset 0x14 contains a nonzero word. F-d407263631bd is called once. The node’s offset-0x08 and offset-0x0c fields become self-addresses, its offset-0x04 field becomes zero, and container offset 0x14 becomes zero. The final result-slot value and return high half are the subsequently read distinguished-node address. No loop comparison is performed.

3. **Noncanonical preliminary truth value.**

4. **Zero state blocks the bulk operation.**  
   Both preliminary comparisons return nonzero, but container offset 0x14 is zero. The bulk dependency and explicit reset sequence do not execute. Control proceeds to the loop comparison.

5. **Capture precedes advancement.**  
   The cursor’s first word is A when a loop body begins. F-195567ecfcce changes that word to B. F-4d4572315288 nevertheless receives a lower-return word initially containing A.

6. **Per-item outputs govern the observable result.**  
   On a single iteration, F-4d4572315288 writes X to the upper-return word and Y to the lower-return word. The result slot is then written with X. If the next comparison returns exactly 1 without further side effects, the return has high half X and low half Y.

7. **Bulk dependency changes the distinguished node.**  
   F-d407263631bd changes container offset 0x10 from node A to valid node B. Subsequent direct reset operations use reloaded addresses and therefore target B if that field remains stable. The final result-slot write and return high half use the later read of B, not a cached A.
