# F-0dc217271a8a

## Purpose

F-0dc217271a8a updates caller-provided state from an input record. It always copies two input fields and invokes a preparation dependency. It then compares two captured input values with cached state. A cache hit ends processing; a cache miss updates the cache, optionally adjusts a working value using the first marked record, publishes working values, and processes two embedded collections.

For each record in the second collection, the function directly stores two pairs of derived values, clears a flag bit, and conditionally replaces one output in each pair with a quantized result. These are descriptions of this function’s direct operations, not unconditional final-state guarantees: intervening dependencies may modify the same storage.

The semantic units are unknown. Terms such as “primary,” “secondary,” “source,” and “anchor” identify operational roles, not established domain meanings.

## Behavior

### 1. Unconditional prefix

The direct sequence is:

1. Read input byte `0x14` and write state byte `0x18`.
2. Read input word `0x00` and write state word `0x04`.
3. Call **F-359997bafb32** with the state address, input address, and zero.

The word read occurs after the byte write. If the regions alias, that write can affect the subsequent read.

No preservation guarantee is established for the preparation dependency. All later reads observe storage after it returns, including any mutations it completed.

### 2. Cache decision and update

After preparation returns, the function:

1. Captures input word `0x08` as the requested primary value and initial working primary value.
2. Reads the primary cache at state `0x32C`.
3. Captures input word `0x10` as the secondary value.
4. Reads the secondary cache at state `0x330` only if the primary comparison matched.

If both comparisons match, the function returns. The initial copies and preparation call have already occurred.

Otherwise, it writes the captured secondary value to `0x330`, then the captured requested primary value to `0x32C`.

The cached primary value is the request, not a subsequently adjusted working value. These cache writes precede the marked-record scan and all remaining dependency calls. Aliasing can make them affect later input, count, source, or flag reads.

### 3. Preliminary record selection

The function scans the second collection in increasing unsigned index order.

Before inspecting each candidate, it reads the current count at state `0x280` and checks whether the index is below that count. For an in-range candidate, it reads the flags and tests mask `0x00000004`.

The first record with bit 2 set is selected. The scan then stops; later marked records do not participate in preliminary processing. If the count is exhausted without a selection, the optional preliminary calls are skipped.

The scan itself makes no direct writes and invokes no dependencies. The count is read repeatedly rather than captured for the whole scan.

### 4. Optional working-primary adjustment

For a selected record, the function calls **F-74efb2674226** with visible operands including:

- The selected record’s second source.
- A fresh read of input `0x08`.
- The address of state `0x1AC`.
- The selected record’s address.
- Three additional recovered operands whose origins and meanings are unresolved.

The supplied representation does not establish an ordering between the individual argument reads within this call.

The fresh primary read occurs after the cache writes. It can differ from the captured request if an intervening write aliases that input field. Separately, external mutation could cause a difference, but no concurrency contract is established. Preparation’s completed mutations alone do not explain a difference: both primary reads occur after preparation returns.

For the 32-bit result \(p\), the function computes:

\[
r=(p+32)\mathbin{\&}\texttt{0xFFFFFFC0}
\]

The addition is unsigned and wraps modulo \(2^{32}\).

If \(r=p\), no further adjustment dependency is called. Otherwise, **F-8f41f510c86c** receives the current working primary value, \(r\), and \(p\), in that order. Its result replaces the working primary value.

Neither dependency is established to preserve state, input, globals, or ownership.

### 5. Publish captured and working values

The function directly writes, in order:

1. Captured secondary value to state `0x1B0`.
2. Working primary value to state `0x1AC`.
3. Working primary value to state `0x0C`.
4. Captured secondary value to state `0x14`.

The subsequent calculations use the retained working primary and captured secondary values; they do not reload those values from the published fields.

### 6. Process the first collection

Records are visited in increasing unsigned index order. Each loop condition reads the current count at `0x1B4`.

For each record:

- Its source is read and supplied to F-74efb2674226 with the working primary value.
- After the call returns, the returned word is written to record offset `0x04`, then to `0x08`.

Both direct stores use the same returned word. The function does not directly rewrite the source. Dependency effects on sources, counts, earlier records, or other state remain possible.

### 7. Process the second collection

Records are visited in increasing unsigned index order. Each loop condition reads the current count at `0x280`.

For each record, the dependency boundaries and direct operations are:

1. Read the first source and call F-74efb2674226 with it and the working primary value.
2. Add the captured secondary value to the returned value. Store the sum to the first unadjusted output, then the first adjusted output.
3. Read the second source **after the first call and both stores**, and call F-74efb2674226 with it and the working primary value.
4. Add the captured secondary value to this result. Store the sum to the second unadjusted output, then the second adjusted output.
5. Read the current flags and write them back with bit 0 cleared.
6. Read both sources anew and call F-74efb2674226 with “first source minus second source” and the working primary value.

Thus, the second source-value call may modify the previously stored first outputs. The eligibility call occurs after all four initial output stores and the flag clear, and may modify those fields again.

Let \(e\) be the eligibility-call result as a 32-bit word. Adjustment is eligible exactly when:

\[
(e+48)\bmod 2^{32}<97
\]

Equivalently, the signed interpretation of \(e\) lies from −48 through +48, inclusive.

**On rejection, this function performs no further direct writes for that record.** Equality between adjusted and unadjusted outputs, or a cleared final bit 0, requires relevant preservation by the intervening dependencies and absence of other mutation.

### 8. Eligible adjustment and quantization

After the eligibility call returns successfully, the function reads both sources again and computes “second source minus first source.” This difference need not be the negation of the earlier difference: the eligibility dependency may have changed either source.

The sign of this newly computed difference is retained. Its absolute magnitude is supplied to F-74efb2674226 with the working primary value.

Let \(m\) be the returned 32-bit word. Comparisons interpret it as signed; the quantization arithmetic uses unsigned words.

| Signed interpretation of \(m\) | Quantized magnitude |
|---|---|
| Less than 32 | Zero |
| 32 through 63 | Subtract 16, clear the low five bits, then add 32 |
| At least 64 | Add 32, then clear the low six bits |

Consequently, 32–47 produces 32, and 48–63 produces 64. Any returned word with its sign bit set takes the zero branch. A nonnegative result is not guaranteed merely because the supplied operand represented an absolute magnitude.

After the magnitude call returns, the function **reads the first unadjusted output from memory** and rounds that observed value:

\[
a=(\text{observed first unadjusted output}+32)
  \mathbin{\&}\texttt{0xFFFFFFC0}
\]

This addition is unsigned. The observed output may differ from the value initially stored because of dependency mutations.

If the retained source difference was negative, the quantized magnitude is negated using unsigned arithmetic. The function then directly:

1. Writes \(a\) to the first adjusted output.
2. Writes \(a\) plus the signed-direction displacement to the second adjusted output, using unsigned 32-bit arithmetic.
3. Reads the flags **after both output stores**, and writes the observed flags with bit 0 set.

There are no dependency calls between the magnitude call and these final operations. Their ordering still matters if storage aliases.

The eligible adjustment makes no direct stores to either unadjusted output. This does not imply that dependencies preserved those outputs.

## Side effects

Direct writes target the initial copied fields, caches, published working fields, collection outputs, and second-collection flags.

Additional consequences and limits:

- A cache hit does not suppress preparation or undo its effects.
- Bit 2 is not explicitly cleared. Each flag operation preserves the other bits from its own contemporaneous read.
- Every processed second-collection record undergoes the bit-0 clear, regardless of preliminary selection.
- Counts are reread at loop conditions. Dependency mutations can change how many records are subsequently processed.
- There is no visible allocation, deallocation, ownership transfer, retained-pointer assignment, synchronization, or rollback in this body.
- Dependencies may have ownership or lifetime effects; none are established.
- If a dependency fails to return normally, earlier completed writes remain observable. No recovery path is visible.
- Aliasing, dependency mutations, and collection overlap can invalidate simple final-state descriptions without changing the direct operation sequence.

## Acceptance examples

These are conditional deductions, not execution results. Except where mutation is explicitly described, assume valid nonoverlapping storage, stable counts, normally returning dependencies, no external mutation, and preservation of relevant memory by dependencies. Signed arithmetic examples stay within representable range.

1. **Cache hit.** If both captured input values match the caches after preparation, no collection processing follows. The initial byte copy, word copy, and preparation call still occur.

2. **Secondary-only miss.** A matching primary cache and differing secondary cache cause a full update. The secondary cache is written before the primary cache.

3. **Empty collections.** With both counts zero on a cache miss, no record is accessed and no record-derived call occurs. Cache and published-field writes still occur.

4. **Selection order.** If records 1 and 3 are marked and record 0 is not, record 1 supplies the preliminary operands. Record 3 is irrelevant to preliminary selection, but may still be processed in the later traversal.

5. **Preliminary rounding.** A preliminary result of 128 remains 128, so F-8f41f510c86c is skipped. A result of 100 rounds to 128, causing that dependency to receive the working primary, 128, and 100. Its result becomes the working primary; the cache still records the request.

6. **Eligibility boundaries.** Results −48 and +48 are eligible; −49 and +49 are rejected. Under the preservation assumptions, rejection leaves the paired outputs equal and bit 0 clear.

7. **Positive and negative displacement.** If eligible, with magnitude result 40 and first unadjusted output 100, the anchor is 128 and magnitude is 32. A positive retained source difference produces adjusted outputs 128 and 160; a negative one produces 128 and 96. Bit 0 is set.

8. **Zero quantization.** An eligible magnitude result below 32 under signed comparison produces two adjusted outputs equal to the anchor. This includes sign-bit-set results. Bit 0 is still set.

9. **Rounding wraparound.** Preliminary result `0xFFFFFFF0` rounds to zero. Because the result changes, F-8f41f510c86c is called.

10. **Mutation before rejection.** If the eligibility dependency writes an adjusted output and sets bit 0, then returns a rejecting result, this function makes no further writes for that record. It does not restore the earlier output or clear the bit again.

11. **Source reread after eligibility.** If eligibility changes the sources before returning an accepting result, the subsequent magnitude and direction use the changed sources, not the earlier difference.

12. **Anchor reread after magnitude.** If the magnitude dependency changes the first unadjusted output to 164 and returns 40, the anchor becomes 192. With positive retained direction, the adjusted outputs become 192 and 224. The anchor is not derived from the earlier output value.
