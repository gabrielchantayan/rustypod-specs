# F-972e87e86ceb

## Purpose

F-972e87e86ceb conditionally performs a sequence of dependency calls using a byte reached through an input object, an interior address of that object, and a 32-bit word reached through a shared-base global.

The established behavior is:

- An initial dependency determines whether the remaining work occurs.
- On a nonzero gate result, the function reads a nested byte and supplies it to a dependency.
- After that dependency returns, the function independently reads the nested address and byte again.
- Unless the second byte equals `k`, an interior-address dependency is called. A nonzero result causes a second invocation of that dependency, followed by another invocation of the byte-consuming dependency without an explicit argument.
- Every active path that completes normally ends with two external calls. Between those calls, the function retrieves the current shared base from global storage and then reads a 32-bit word at that base plus 8.

These are observable roles, not established application semantics. Logging, dispatch, notification, rendering, and cleanup are not established purposes.

## Behavior

### Initial gate

F-0a3684290038 is invoked without explicit arguments.

A zero result causes immediate return. On that path, this function performs none of the following:

- Reads the input object’s nested-address field.
- Reads a nested byte.
- Calls F-72d62dc6ffb5 or F-3c0bc7d198b5.
- Calls F-X01 or F-X02.
- Retrieves the shared base from global storage.
- Reads the word at shared base plus 8.

Any nonzero gate result enters the active path. The decision is zero versus nonzero, not positive versus nonpositive.

### First nested read and byte-consuming call

On the active path, the function reads the 32-bit address at input base plus 32, then reads one byte at that address plus 5.

It invokes F-72d62dc6ffb5 with the byte as its sole explicit argument. The return value is not used.

The memory access is eight bits wide. The evidence does not establish how the byte is extended into an ABI argument slot or register; neither sign extension nor zero extension is promised.

### Independent reread and branch

After F-72d62dc6ffb5 returns, the function again reads the 32-bit nested address from input base plus 32. It reads a byte at that newly obtained address plus 5 and compares that second byte with `k`.

Neither the nested address nor the byte is visibly reused from the first read. The intervening dependency may therefore affect:

- The byte subsequently used for the branch.
- The stored nested address.
- Which nested object supplies the branch byte.
- Whether the later access remains valid.

If the second byte equals `k`, the entire F-3c0bc7d198b5 sequence is skipped. Execution proceeds to the final external sequence.

For an ASCII-compatible execution character encoding, `k` corresponds to 0x6B. The comparison is expressed as a character literal; the target character encoding is not independently supplied.

### Conditional interior-address sequence

If the second byte is not `k`, F-3c0bc7d198b5 is called with input base plus 4.

This argument is an interior address. Passing it does not establish that this function reads a field at that offset. Any reads or writes performed through it by the dependency remain unspecified.

If the first F-3c0bc7d198b5 result is zero, the optional inner sequence is skipped.

If that result is nonzero:

- F-3c0bc7d198b5 is called again with the same calculated interior address.
- Its second result is ignored.
- F-72d62dc6ffb5 is called without an explicit argument in the supplied representation.

The two interior-address calls are distinct invocations. The second is not replaced by reuse of the first result, and effects from the first may influence the second.

A zero result from the second invocation does not suppress the subsequent F-72d62dc6ffb5 call. The nested byte is not rechecked after either interior-address call.

The differing explicit argument counts for F-72d62dc6ffb5 are unresolved interface evidence. The optional invocation is not specified to receive the earlier byte, the second interior-address result, a default value, or any particular machine-state value.

### Final external sequence and shared-base retrieval

Every active path reaching this point normally performs the following ordered operations:

1. Calls F-X01 without explicit arguments and retains its 32-bit result.
2. Reads the shared-base global storage to obtain its then-current 32-bit address-like value.
3. Reads a 32-bit word at the obtained base plus 8.
4. Calls F-X02 with four explicit arguments, in order:
   - The retained 32-bit result from F-X01.
   - The word read through the then-current shared base.
   - The integer constant 2.
   - An address into the current invocation’s stack frame.

Both shared-state reads occur after F-X01 returns. The pointed-to word cannot be identified solely from the base value that existed at entry: the base is retrieved at this later point.

Earlier dependencies, including F-X01, may change the stored shared base itself. If such a change is observed by the global read, the subsequent word read targets the replacement base plus 8. Earlier dependencies may also change the word at whichever base is subsequently obtained.

There is no visible snapshot of either the global base or the pointed-to word before F-X01. Nor is there a dependency call visibly placed between retrieving the base and reading the word. This ordering does not establish synchronization or atomicity against concurrent activity.

The stack argument’s pointee type, extent, initialization state, and input/output role are unknown. The visible function does not subsequently consume data through that address.

After F-X02 returns, F-972e87e86ceb returns.

## Acceptance examples

These examples are conditional consequences of static evidence, not executed tests. Unless stated otherwise, required memory is valid and dependencies return normally.

1. **Zero gate result.**  
   Only F-0a3684290038 is invoked. This function does not dereference the input, retrieve the shared base, or read the pointed-to word. An otherwise invalid input address is therefore not accessed by this body on this path.

2. **Second nested byte equals `k`.**  
   The initial F-72d62dc6ffb5 call receives the first byte read. Neither F-3c0bc7d198b5 invocation occurs. F-X01, shared-base retrieval, the word read, and F-X02 still occur.

3. **Second byte differs from `k`; first interior-address result is zero.**  
   F-3c0bc7d198b5 is called exactly once with input base plus 4. The optional F-72d62dc6ffb5 call is skipped. The final external sequence still occurs.

4. **First interior-address result is nonzero; second result is zero.**  
   Provided the second byte differs from `k`, both interior-address calls occur. The optional F-72d62dc6ffb5 call follows despite the second result being zero.

5. **The first byte-consuming call changes the branch byte.**  
   If the first byte differs from `k` but the second read observes `k`, the interior-address sequence is skipped. Branching on the original byte would not match the established behavior.

6. **The first byte-consuming call replaces the nested address.**  
   The branch byte comes from the address obtained by rereading the input field. It need not come from the object used for the first argument.

7. **F-X01 replaces the shared base.**  
   Suppose global storage initially names one object and F-X01 changes it to name another. If the subsequent global read observes the replacement, F-X02 receives the word from the replacement object’s offset 8. Using the former base would not match the established read sequence.

8. **The shared base is unchanged, but F-X01 changes its pointed-to word.**  
   If the later word read observes that update, the changed value is supplied to F-X02. No earlier word snapshot is used.

9. **F-X01 leaves the shared-base storage unreadable or stores an invalid base.**  
   Successful completion is not promised. The function attempts the global read and subsequent word access required by its sequence, with no visible validation or recovery.

10. **A dependency invalidates the next nested access.**  
    The later nested-address or byte read is still part of the active path. The evidence supplies no fallback behavior.
