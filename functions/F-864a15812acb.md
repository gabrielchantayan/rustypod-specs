## Behavior

### Resolution order

The represented data dependencies require three successive memory reads:

1. Read P from the field at B + 136.
2. Read T from the beginning of the storage addressed by P.
3. Read Q from the dispatch slot at T + 32.

Only after resolving Q does the function invoke it.

Each later read depends on the value obtained by the preceding read. The intermediate dereference is significant: P is not itself used as the base of the final dispatch slot. Instead, the value stored at P supplies that base.

The visible behavior contains no alternate dispatch path, loop, fallback target, or conditional selection. There is one indirect invocation in the supplied representation.

This ordering describes the logical accesses expressed by the evidence. It does not establish atomicity, processor memory-ordering guarantees, or synchronization with concurrent writers.
