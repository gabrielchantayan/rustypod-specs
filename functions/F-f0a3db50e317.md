## Behavior

### Dispatch order

At each dispatch step, the function:

1. Reads the current object’s discriminator byte.
2. Initializes private integer result storage from the current invocation’s fourth input.
3. Selects behavior using the sampled discriminator.
4. Reads a branch-specific field only if the selected branch requires it.

The initialization is repeated when `V` traversal returns to dispatch. Following a `V` link does not visibly change the current invocation’s fourth input.

The discriminator is sampled once per step. No second discriminator read is visible before branch selection. There is no guarantee of an atomic snapshot encompassing that byte and a subsequently read field.

### `V`: iterative traversal

For `V`, the function reads a pointer-typed field at offset 8 and makes that value the current object address. It then begins another dispatch step.

The access is pointer-sized, with its byte width unresolved. It is not unconditionally a four-byte access.

A `V` step:

- Does not create a recursive invocation.
- Does not directly write the caller’s result storage.
- Does not read the offset-20 field.
- Does not validate the destination.
- Does not record visited objects or impose a traversal limit.

A finite chain is followed until a non-`V` discriminator is reached, assuming every required access is valid. A stable, readable cycle consisting entirely of `V` objects has no visible terminating condition. Invalid link storage or an invalid destination may cause a failure outside the explicit zero/one status mechanism.

### `U`: recursive evaluation and conditional negation

For `U`, the function reads exactly four bytes at offset 8 and supplies that value as the recursive child argument. It supplies the address of its private integer result storage as the recursive output destination.

Before that call, the private storage has been initialized from the enclosing invocation’s fourth input.

After the recursive call:

- A zero status causes the enclosing invocation to return zero without directly assigning its caller’s result storage.
- A nonzero status causes the enclosing invocation to read the private result, negate it arithmetically, write the negated integer to its caller’s result storage, and return one.

The enclosing output write occurs after recursive success. No enclosing output assignment occurs before the recursive call.

For representable negation, zero remains zero and nonzero values change sign. This is arithmetic negation, not a logical operation.

The minimum signed value requires separate treatment. Under a signed 32-bit interpretation, negating −2,147,483,648 has no representable positive signed 32-bit result. The supplied expression does not independently establish wrapping, trapping, or another outcome. Exact boundary behavior is **documented_only** pending execution-semantics evidence.

Each `U` introduces recursion. No depth check is visible. Cycles involving `U` can therefore have different resource consequences from a purely iterative `V` cycle.

### `|`: delegated result production

For `|`, the function reads the four-byte field at offset 20 and invokes F-9647f90132cc with:

- The field value.
- The result-storage address supplied to the current invocation.

It returns zero if the dependency returns zero and one if the dependency returns nonzero.

There is no direct output assignment by this branch. The dependency receives the output address itself, not a private copy. Any dependency write made before either success or failure is not restored by the wrapper.

The field’s interpretation and acceptable values are unknown.

### Other discriminator values

For any discriminator other than `U`, `V`, or `|`, the function returns zero.

This branch performs no visible read at offset 8 or offset 20, invokes neither dependency, and performs no direct output write. Subject to valid initial access and no external interference, the caller’s output remains unchanged.
