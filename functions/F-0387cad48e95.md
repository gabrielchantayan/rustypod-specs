# F-0387cad48e95

## Purpose

F-0387cad48e95 initializes selected fields in a caller-supplied record, invokes an ordered sequence of dependencies using that record and six global configuration slots, and returns the original record pointer.

The established behavior is partial record initialization followed by dependency calls. The interpretation of those calls as resource selection, configuration, or final setup is inferred intent only. No particular subsystem, resource type, or meaning for the numeric selectors is established.

This contract describes normal execution through the supplied body. It does not establish how dependencies behave internally, whether they succeed, or whether they preserve the record or global state.

## Behavior

### 1. Partial record initialization

Before calling any dependency, the function performs these stores in the evidenced order:

1. Store the 8-bit tag at byte offset 4.
2. Store an 8-bit zero at byte offset 10.
3. Store the first 16-bit field value at byte offset 6.
4. Store the second 16-bit field value at byte offset 8.
5. Store an 8-bit zero at byte offset 11.

There is no whole-record initialization. In particular, the function does not directly initialize bytes 0–3 or byte 5.

The two zero stores are distinct operations at different points in the sequence. The body does not establish atomic publication of the initialized record, a synchronization barrier, or protection against another observer seeing partially updated state.

### 2. First dependency call

After all five stores, the function invokes F-c27be7e58664 with:

- First argument: numeric value 1.
- Second argument: the original record pointer.

Any return value is unused.

This dependency receives the record address, not a copy. Its effects are unknown. Subsequent behavior must therefore be described using the record state after it returns, rather than assuming the five initialized fields or the leading 32-bit word remain unchanged.

### 3. Capture a global value and pass the leading record word

For clarity, the six global slots used by this function are designated G1 through G6. These are distinct observed storage locations, not claims about their semantic roles.

After F-c27be7e58664 returns:

1. The function reads the 32-bit value in G1 and retains that value for four later calls.
2. It invokes F-d6b9c0ce66d0 with:
   - A separately read value from G1.
   - The 32-bit word currently stored at record byte offset 0.

The retained G1 value is not replaced by later reads. Conversely, the G1 value supplied to F-d6b9c0ce66d0 is a separate access; the contract does not collapse it into the retained read.

No intervening dependency call occurs between those two G1 accesses. In ordinary stable storage they produce the same value. Equality is nevertheless conditional on the absence of concurrent changes, special memory-read behavior, or other environmental effects.

The leading record word is read after F-c27be7e58664 has returned. It is not captured at function entry.

Any return value from F-d6b9c0ce66d0 is unused.

### 4. Four ordered calls using the retained global value

The function next invokes F-9db809c408f4 four times, in this order:

| Call | First argument | Second argument | Third argument |
|---|---|---|---|
| 1 | Retained G1 value | Current G2 value | 0x2600 |
| 2 | Retained G1 value | 0x2800 | 0x2600 |
| 3 | Retained G1 value | Current G4 value | Retained G3 value |
| 4 | Retained G1 value | Current G5 value | Retained G3 value |

The timing of the global reads is significant:

- G2 is read for the first call, after F-d6b9c0ce66d0 returns.
- The second call has no additional global-derived argument beyond retained G1.
- G3 is read and retained after the second call returns.
- G4 is read for the third call.
- G5 is read for the fourth call, after the third call returns.

Consequently, dependency-driven changes to G1 do not change the first argument of these four calls: all four use the earlier retained value. Changes to G3 after its capture likewise do not change the third argument of calls three and four.

By contrast, changes to G2, G4, or G5 made before their respective reads can affect the corresponding call.

The constants 0x2600 and 0x2800 are numeric arguments. Their meanings as selectors, sizes, flags, or enumeration values are not established.

All four return values are unused. There is no visible branch, retry, or rollback based on those values.

- Second argument: 0x2200.
- Third argument: the current 32-bit value of G6.
