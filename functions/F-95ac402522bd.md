# F-95ac402522bd

## Purpose

F-95ac402522bd coordinates a status-dependent sequence of helper calls, selects a 32-bit outcome, and returns that outcome together with a second 32-bit value.

Its established behavior has three principal parts:

- Obtain three working values through pointer-taking dependencies.
- Select an action and outcome from particular bits of those values.
- Check a terminal condition, either immediately or after the selected action, and perform associated object-state updates when that condition is present.

The routine does not contain a polling loop. A path that performs an action makes one subsequent terminal-condition check and then returns.

The meanings of the status bits, outcome numbers, object fields, and helper commands are not established. Describing them as device states, success codes, errors, or resource-management operations would be inferred intent rather than a supported contract.

## Interface

### Inputs

The interface has four 32-bit arguments:

| Argument | Established use |
|---|---|
| First argument | Not referenced by the visible routine. |
| Second argument | Initializes a mutable 32-bit working value, called the **selector word** in this contract. |
| Third argument | Initializes a mutable 32-bit working value, called the **control word**. |
| Fourth argument | Initializes a mutable 32-bit working value, called the **condition word**. |

These names describe their use here, not their domain meaning.

Each working word occupies a distinct 32-bit local object. Dependencies receive addresses of these objects and therefore can modify them. The routine does not establish that a dependency must overwrite the complete word; an unchanged input or a partially modified word remains relevant to subsequent behavior.

The first argument has no visible effect on the routine’s decisions, calls, or return construction.

### Output

The return value is a 64-bit concatenation:

- Bits 63–32 contain the selector word as it stands at return.
- Bits 31–0 contain the selected 32-bit outcome.

This specifies bit placement, not byte order in memory or assignment to machine return registers. No signed interpretation of either half is established.

The visible routine selects outcomes from 0 through 11 inclusive, subject to the branch conditions described below. It does not return a separate error indicator.

### Preconditions and execution assumptions

For ordinary completion:

- Each dependency reached on the selected path must return normally.
- The global object-base value captured by the routine must support the field accesses performed if the terminal path is reached.
- Pointer-taking dependencies must use the provided local-object addresses in a manner compatible with their lifetime and size.

There is no visible null check, range check, ownership validation, or exception recovery for the object-base value.

The caller does not directly supply the object-base value through these arguments. It is read from global storage after the initial dependency calls.

## Behavior

### Initial acquisition and object-base capture

The routine initializes the outcome to zero and copies the second, third, and fourth arguments into the selector, control, and condition words, respectively.

It then performs these calls in order:

1. F-ff01e173816f with numeric argument 4 and the address of the condition word.
2. F-ff01e173816f with numeric argument 6 and the address of the control word.
3. F-3fef37c526f8 with the address of the selector word.

Only after these calls does it read a global 32-bit object-base value and retain that value for possible later field accesses.

Consequently, the initial dependencies can affect which object base is captured if they modify that global storage. Later changes to the global base do not cause the routine itself to recapture it.

The first branch examines the control word masked with 3:

- If either of its two least-significant bits is set, execution proceeds directly to terminal handling.
- Otherwise, the routine selects one of the action paths below.

The control word’s other bits do not participate in this first test.

### Action selection when the terminal condition is absent

The routine next tests bit 3 of the control word, using mask 8.

#### Control bit 3 clear

When control bit 3 is clear, bit 0 of the condition word has priority over bit 2.

**Condition bit 0 set**

The routine selects outcome 1 and calls F-dca87c20e061 with argument 2. It then proceeds to the shared post-action check.

Condition bit 2 does not alter this selection, even if it is also set.

**Condition bit 0 clear and condition bit 2 set**

The routine performs this sequence:

1. Call F-21b925c3866f with argument 1.
2. Call F-d49bbe387b2a with argument 12.
3. Call F-21b925c3866f with argument 2.
4. Call F-ff01e173816f with argument 4 and the address of the condition word.
5. Re-examine condition bit 2.

If the refreshed condition bit 2 is clear, it calls F-fede798223e7 with argument 0. The outcome remains zero.

If the refreshed condition bit 2 is set, it selects outcome 3 and does not make that F-fede798223e7 call at this point.

This decision depends on the refreshed bit, not solely on the condition word obtained during initial acquisition. Other refreshed condition bits do not affect this decision.

Both alternatives proceed to the shared post-action check.

**Condition bits 0 and 2 both clear**

The routine selects outcome 11, calls F-21b925c3866f with argument 3, and then calls F-dca87c20e061 with argument 32.

It then proceeds to the shared post-action check.

#### Control bit 3 set

When control bit 3 is set, the routine performs this sequence:

1. Call F-d49bbe387b2a with argument 10.
2. Call an unmapped helper with argument 50.
3. Call F-ff01e173816f with argument 4 and the address of the condition word.
4. Examine the selector word’s low eight bits and the refreshed condition bit 2.

The selected outcome is:

| Selector low byte | Refreshed condition bit 2 clear | Refreshed condition bit 2 set |
|---:|---:|---:|
| 4 | 2 | 4 |
| 3 | 6 | 5 |
| 1 | 7 | 8 |
| 2 | 9 | 10 |
| Any other value | 0 | 0 |

Only the low eight bits of the selector word determine this selection. Its upper 24 bits are not masked out of the returned high half.

The condition word’s bit 0 is irrelevant on this path. No F-dca87c20e061 or F-21b925c3866f call is directly selected by this path.

### Shared post-action check

Every action path above reaches the following sequence:

1. Call the same unmapped helper with argument 10.
2. Call F-ff01e173816f with argument 6 and the address of the control word.
3. Test the control word masked with 3.

If both tested bits are clear, the routine returns the selected outcome and selector word.

If either tested bit is set, the routine enters terminal handling. This discards any previously selected nonzero outcome.

There is no repeat of action selection after this check. In particular, a refreshed control bit 3 does not trigger another action.

### Terminal handling

Terminal handling is reached either:

- Immediately after initial acquisition, when the initial control word has either low bit set; or
- After an action and the shared post-action check, when the refreshed control word has either low bit set.

The routine performs these operations in order:

1. Set the outcome to zero.
2. Call F-fede798223e7 with argument 0.
3. Write the 32-bit value 1 to the captured object base at byte offset 28.
4. Read the 32-bit field at byte offset 12 from that same captured base.
5. If that field is zero, omit the remaining conditional operations.
6. If that field is nonzero:
   - Call an unmapped external helper with no explicit argument.
   - Read the field at offset 12 again.
   - Pass this newly read 32-bit value to a second unmapped external helper.
   - After that helper returns, write the 32-bit value zero to offset 12.

The field value passed to the second external helper is not necessarily the nonzero value that caused entry into this conditional sequence. The first external helper may change the field, and the routine explicitly reads it again afterward. A change to zero does not cancel the second call.

Likewise, if the second external helper modifies the field and returns normally, the routine’s final zero write follows that modification.

The outcome remains zero through the visible terminal path. The selector word still supplies the high half of the return.

## Side effects

### Direct writes

The routine directly writes its local working words during initialization and its local outcome during selection.

Its visible nonlocal writes occur only in terminal handling:

- A 32-bit write of 1 at captured-base offset 28.
- A conditional 32-bit write of 0 at captured-base offset 12.

The latter write requires that the first read of offset 12 after the offset-28 write be nonzero and that both external helpers return normally.

On a nonterminal path, the routine makes no direct writes to these two object fields. Its dependencies may still modify them or other state.

### Observable ordering

The following ordering constraints are established:

- All three initial pointer-taking calls precede capture of the global object base.
- F-fede798223e7 precedes the terminal write at offset 28.
- The offset-28 write precedes the first offset-12 read.
- The first external helper precedes the second offset-12 read.
- The second external helper precedes the final zero write.

The terminal F-fede798223e7 call can therefore affect the object fields before they are accessed, even though the base value has already been captured.

On the condition-bit-2 refresh path, F-fede798223e7 may be called once because the refreshed bit clears and then a second time if the subsequent control check selects terminal handling.

### Ownership and failures

No allocation or ownership transfer is directly established. The offset-12 field is treated as a 32-bit value tested against zero and passed onward; its interpretation as a pointer, handle, or resource identifier is unknown.

Clearing that field does not prove that either external helper releases a resource. Similarly, no assumption is made that any helper preserves globals, object fields, or other accessible state.

There is no visible validation of helper results and no explicit recovery path. A fault, nonlocal exit, or nonreturning dependency can prevent later calls, field writes, and the return itself.

The unmapped helper called with 50 and 10 may have timing-related intent, but neither a delay operation nor any time unit is established.

## Acceptance examples

These are conditional static examples, not runtime test results. Unless an example specifies otherwise, dependencies return normally and make no additional changes that affect the described decisions or return.

1. **Immediate terminal condition**

   If the initial control acquisition leaves its low two bits equal to 1, terminal handling occurs immediately. There is no action selection, no argument-10 shared helper call, and no second control acquisition. The returned low half is zero.

2. **Condition bit 0 takes priority**

   If the initial control word is zero, the condition word is 5, and the final control acquisition leaves both low bits clear, F-dca87c20e061 receives 2 and the returned low half is 1. The condition-bit-2 refresh sequence does not occur.

3. **Refreshed condition bit 2 remains set**

   If the initial control word is zero and the condition word has bit 2 set but bit 0 clear, the ordered arguments are 1 to F-21b925c3866f, 12 to F-d49bbe387b2a, and 2 to F-21b925c3866f, followed by condition acquisition. If refreshed bit 2 remains set and the final terminal check is clear, the returned low half is 3.

4. **Refreshed condition bit 2 clears**

   Under the preceding initial conditions, if refreshed bit 2 clears, F-fede798223e7 receives 0. If the final terminal check is clear, the returned low half is zero without terminal object-field writes.

5. **Neither condition bit selects a special path**

   If the initial control word is zero and condition bits 0 and 2 are clear, F-21b925c3866f receives 3 before F-dca87c20e061 receives 32. A clear final terminal check preserves outcome 11.

6. **Low-byte selection preserves the full selector**

   If the selector word is `0xA1B2C304`, the control word has bit 3 set and both low bits clear, refreshed condition bit 2 is clear, and the final terminal check is clear, the return is `0xA1B2C30400000002`.

   Setting refreshed condition bit 2 instead changes only the selected low-half outcome to 4 under the stated assumptions.

7. **Unrecognized selector byte**

   On the control-bit-3 path, selector low byte 5 selects outcome zero regardless of refreshed condition bit 2. The argument-50 call, condition refresh, and shared post-action check still occur.

8. **Terminal check overrides an action outcome**

   If an action selects outcome 11 but the final control acquisition sets either low bit, terminal handling replaces the outcome with zero and performs its calls and field updates.

9. **External helper changes the field**

   If terminal handling first reads offset 12 as 9, then the first external helper changes that field to zero, the second external helper is still called, with zero. A final zero write follows its normal return.
