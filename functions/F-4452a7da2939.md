## Behavior

### Interpretation and ordering

The following phases describe the displayed straight-line order, followed by the loop. Calls between accesses are observable events and must not be treated as inert padding.

For calculations involving unsigned values, right shifts are logical. Narrow byte stores discard higher bits. Several scaling operations instead use values displayed as signed integers. For those operations, this contract preserves the represented scale and displacement but does not assert portable signed-overflow or signed-left-shift semantics.

Where the text describes low-32-bit arithmetic, that is a conditional machine-width interpretation, not a resolution of those signed-operation uncertainties.

### 1. Entry and first byte-store pair

The routine first invokes an indirect dependency with the first input. Four further indirect calls follow. The last supplies a result used as a word index.

The incoming register value is stored as a 32-bit word at an address equal to four times that result, plus 20. The scaled result is then passed to another indirect call.

After a further call sequence, an unsigned 32-bit result is obtained. Two stores use this same saved result:

1. Read an unsigned byte at the address equal to the first input shifted right by eight, plus one.
2. Add 17 to the lookup byte and store the low byte of the result shifted left by two.
3. Perform intervening indirect calls.
4. Repeat the lookup read at the original lookup address.
5. Store the low byte of the saved result after masking with `0x3fffffff` and shifting right by 20.

The second stored byte therefore selects original result bits 20 through 27. The first stored byte selects original bits zero through five, shifted into byte positions two through seven.

The lookup is repeated rather than cached. Intervening calls can change it, so the two stores need not reach the same destination. A later call receives four times a separate call result, not necessarily the saved value used for these two byte stores.

### 2. Fixed-location snapshot and repeated store

After another call sequence, the routine reads a value from a fixed global location into a 32-bit unsigned quantity. The original global object’s width and extension semantics are not established by the displayed cast.

The destination for the next word stores is:

- The third input shifted right by seven;
- Multiplied by four;
- Then increased by 20.

The global-derived snapshot is written there. A call receives that snapshot, followed by further calls. The same saved snapshot is then written again to the same computed address.

There is no second global read between these stores. Consequently, the second store repeats the captured value even if an intervening dependency changes the global or the destination.

The third input’s bottom seven bits do not affect this address. Its maximum represented address is `0x08000010`, before any environment-specific address interpretation.

### 3. First pair of captured words

A later call result determines two scaled quantities: four times the result and sixteen times the result.

The routine:

- Stores the fourfold quantity at the sixteenfold quantity plus 20.
- Reads a 32-bit word at the fourfold quantity plus 20, retaining it as the **first captured word**.
- Forms an unsigned quantity from the result shifted left by 26.
- Invokes a dependency with the sixteenfold quantity, the fourfold quantity, the shifted quantity, and the fourfold quantity again.

A sequence of calls follows, including calls that pass an opaque returned 32-bit value onward. After those calls, the earlier fourfold quantity is stored again at the earlier sixteenfold quantity plus 20. A subsequent dependency receives four times a newer call result.

A new call-derived result then produces another fourfold quantity. The routine shifts the earlier unsigned shifted quantity right by seven, stores this new fourfold quantity at sixteen times the new result plus 20, and reads a word at the new fourfold quantity plus 20. This becomes the **second captured word**.

After further dependency calls, the second captured word shifted right by eight is stored back to that latter read address.

These read addresses may alias preceding write addresses. No distinct-object assumption is supported.

### 4. Processing derived from the first captured word

The next call-derived result causes a fourfold value to be stored at sixteen times that result plus 20. A dependency then receives the first captured word shifted right by 16.

After intervening calls, the previously computed fourfold value is stored at its own value plus 20. A later call receives four times another result.

Another call result supplies a fresh sixteenfold destination and fourfold stored value. The routine performs that store, calls a dependency with the sixteenfold value, and passes opaque intermediate results through additional calls. One later call receives both an opaque value and the first captured word shifted right by 16. The earlier store is then repeated with its retained destination and value.

For the next result, the routine:

- Stores its fourfold value at its sixteenfold value plus 20.
- Shifts the earlier unsigned shifted quantity right by another seven.
- Computes eight times the first captured word shifted right by eight.
- Calls a dependency with the new fourfold value and that eightfold quantity.
- Performs further calls, including another call supplied with the first captured word’s upper 16 bits.
- Stores the retained fourfold value at the eightfold quantity plus 20.

Another result then causes a further fourfold-at-sixteenfold word store. A dependency receives four arguments: the eightfold quantity twice, the first captured word shifted right by 16, and the earlier shifted quantity shifted right by another seven.

Following more calls, the eightfold quantity is stored at its own value plus 20.

The eightfold quantity uses the entire upper 24 bits of the first captured word, not just the immediately adjacent byte.

Under 32-bit unsigned truncation, the three successive seven-bit right shifts of the earlier left-by-26 quantity yield the originating result’s low six bits shifted left by five.

### 5. Secondary register output and further word stores

A later indirect call supplies secondary register output. The routine multiplies that output by `0x01000000` and stores the result at an address formed from the same output multiplied by `0x04000000`, plus 20.

This is not interchangeable with using the call’s displayed ordinary return value.

Subsequent operations include:

- Passing the `0x01000000`-scaled value to a dependency.
- Storing that retained value at four times a later result plus 20.
- Forming another fourfold value and storing it at the corresponding sixteenfold address plus 20.
- Passing that fourfold value into a dependency chain.
- Storing the retained fourfold value at four times a newer result plus 20.
- Forming a further fourfold value, storing it at its corresponding sixteenfold address plus 20, and passing it through another dependency chain.
- Storing the first captured word shifted right by 24 at four times another result plus 20.

The routine retains that top-byte value for a later direct byte-store address.

A subsequent result yields a sixteenfold value. Its fourfold value is first stored at that sixteenfold value plus 20. A dependency receives the sixteenfold value twice and the first captured word shifted right by 23. After further calls, the sixteenfold value itself is stored at that same sixteenfold value plus 20.

### 6. Final byte operations before the loop

A lookup base is computed from an earlier fourfold value by clearing bit 31 and shifting right by seven. This base is retained across subsequent calls.

For a new unsigned call result, the routine reads a byte at the lookup base plus one, adds 17 to the byte, and writes the low byte of the result shifted left by two. A dependency receives that shifted result three times.

After intervening calls, it repeats the lookup and writes the low byte selected by masking the saved result with `0x3fffffff` and shifting right by 20.

Another unsigned call result is then obtained. Its value shifted left by two supplies a saved scaled quantity. The routine:

1. Stores its low byte at an address equal to the retained top byte of the first captured word shifted right by seven, plus 28.
2. Repeats the lookup at the retained lookup base plus one and writes zero to the selected destination plus 17.
3. Calls a dependency with the retained top byte shifted right by seven.
4. Later calls a dependency with the new result masked by `0x3fffffff` and shifted right by six.
5. After more calls, repeats the lookup and writes zero again.

Because the retained top byte is between zero and 255, the direct byte store in step 1 targets address 28 or 29.

A further result is masked with `0x3fffffff` and shifted right by 25. The resulting unsigned value is between zero and 31.

The routine then reads a byte at an address equal to the saved scaled quantity multiplied by 1024, plus one, and writes zero at the lookup byte plus 17. A dependency receives twice the zero-to-31 value, followed by a call producing the initial loop-carried result.

### 7. Unconditional loop

Every displayed iteration has this order:

1. Call a dependency with the loop-carried result and the current unsigned loop value shifted right by eight.
2. Perform four further calls, retaining the last displayed result.
3. Re-read the byte at the saved scaled quantity multiplied by 1024, plus one.
4. Write zero at the lookup byte plus 17.
5. Call a dependency with the retained result shifted left by two.
6. Perform four further calls.
7. Replace the loop-carried result with the last result shifted left by two.
8. Replace the unsigned loop value with that same result shifted left by 26.

The first iteration’s second argument is zero because the initial unsigned loop value is at most 31. This does not imply that the second argument remains zero in later iterations.

The lookup address remains based on the saved pre-loop scaled quantity. The lookup byte is read afresh each iteration. No counter, termination condition, or explicit return appears.

## Acceptance examples

These examples are conditional consequences of the static representation, not runtime test results.

1. **Third-input address grouping.** Third-input values from zero through 127 select word address 20. Values from 128 through 255 select address 24. Both stores use the same captured global-derived value unless execution does not reach the second store.

2. **Lookup redirection between stores.** If the first entry lookup reads 5, the first byte store targets address 22. If intervening calls change that lookup byte to 9, the second store targets address 26. Reusing address 22 would not preserve the represented read order.

3. **Byte extraction.** If the saved result for a byte-store pair is `0x12345678`, the first stored byte is `0xe0`, and the later stored byte is `0x23`, subject to independently repeated destination lookups.

4. **Captured-word shifts.** If the first captured word is `0x89abcdef`, its right-by-16 value is `0x000089ab`; its right-by-24 value is `0x89`; and eight times its right-by-eight value is `0x044d5e68`.

5. **Direct byte address.** A retained top byte of `0x7f` selects address 28. A retained top byte of `0x80` selects address 29.

6. **Loop initialization.** Any result used for the masked right-by-25 calculation produces a value from zero through 31. The first loop call consequently receives zero as its second argument. Later iterations require their own calculation.

7. **Aliasing.** If a computed word-store address equals the address of an immediately following word read, the read observes the stored word under ordinary memory semantics. Distinct buffers are not an acceptance precondition.
