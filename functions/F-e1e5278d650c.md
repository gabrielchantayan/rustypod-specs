# F-e1e5278d650c

## Purpose

F-e1e5278d650c conditionally records a 32-bit value in a caller-supplied object or performs a lookup-driven update followed by optional dispatch.

The established behavior has two paths:

- If the object's byte at offset `0xE8` is nonzero, the function writes the supplied 32-bit value at offset `0xE0` and returns without calling dependencies.
- Otherwise, it records an input byte, resolves an entry through an embedded object, invokes an update using a value obtained from that entry, prepares temporary state, optionally dispatches, records the supplied 32-bit value, and invokes cleanup for the temporary state.

The apparent intent is to defer work while an object flag is set and otherwise apply or announce a selection. That interpretation is inferred. The meanings of the stored value, flag, lookup entry, temporary state, and dispatch operation are not established.

This contract describes the supplied static representation. No runtime tests have been performed.

## Behavior

### 1. Initial branch

The first explicit object access is a one-byte read at offset `0xE8`.

If that byte is nonzero:

1. Write the recorded value as four bytes at offset `0xE0`.
2. Return.

This path does not explicitly read or write `0xE4` or `0xE6`, does not create temporary state, and calls no dependencies. All nonzero flag-byte values select this path.

If the byte is zero, continue with the active path. The function does not explicitly reread the byte later. A subsequent change to it therefore does not alter the function's own branch selection.

### 2. Store the byte and resolve an entry

The active path first writes the stored byte at offset `0xE4`.

It then calls F-1f46730b1ced with:

1. The object address plus `0xB0`.
2. The recorded value.

The returned 32-bit address-like value is tested against zero.

If the result is zero, the function calls F-a817d8d58c10. The supplied representation marks that dependency as nonreturning. Under that contract, no subsequent operation in this function occurs.

The write at `0xE4` precedes this failure check and is not rolled back by this function. The function has not yet performed its normal write at `0xE0`.

Behavior if F-a817d8d58c10 unexpectedly returns is not established.

### 3. Invoke the lookup-driven update

For a nonzero lookup result, the function performs these calls in order:

1. F-d2f99870cc43 receives the lookup result and returns a 32-bit value.
2. F-bf557f07179f receives the original object address and that returned value.
3. F-fa8898fa75ae receives the original lookup result.

No explicit conditional checks are made on the results of the latter two calls.

F-fa8898fa75ae must not be assumed to release, retain, invalidate, or transfer ownership of the lookup result. Its name and placement do not establish those semantics. The same lookup result is subsequently supplied to optional dispatch; any validity obligation across these calls belongs to the dependency contracts.

### 4. Prepare temporary state from two accessor calls

1. Call F-fdd8589eca2d.
2. Read one byte at offset `0x2C` from the returned address and retain that byte.
3. Call F-fdd8589eca2d again.
4. Read four bytes at offset `0x28` from the second returned address.
5. Call F-2c5a9f9c1eb3 with the temporary-storage address, the four-byte value, and the retained byte, in that argument order.

### 5. Decide whether to dispatch

After the temporary-state initialization call, the function calls F-5c5958cfd5fe and compares its result with the integer value `8`.

If the result equals `8`:

- Skip dispatch entirely.
- Do not make the additional F-fdd8589eca2d call associated with dispatch.
- Do not explicitly read the 16-bit field at `0xE6`.
- Continue to the final write and cleanup.

Any other result proceeds toward dispatch. There is no special handling for negative values, zero, or other result values.

For a result other than `8`, the function calls F-fdd8589eca2d once more. Its returned value becomes the first dispatch argument.

The dispatch payload is then selected:

- If the dispatch modifier is nonzero, use 16-bit zero.
- Otherwise, if the dispatch argument is zero, use 16-bit zero.
- Otherwise, read the current 16-bit value at object offset `0xE6` and use it.

The accessor call occurs before the conditional read at `0xE6`. Consequently, mutations by that call can affect the value read. The function does not capture this field earlier.

F-818c773e8c8a is then called with five arguments:

1. The value returned by the additional F-fdd8589eca2d call.
2. The temporary-storage address.
3. The original nonzero lookup result.
4. The original 32-bit dispatch argument, unchanged.
5. The selected 16-bit payload.

No return value from dispatch is explicitly checked.

### 6. Final write and cleanup

After skipped or normally returning dispatch:

1. Write the recorded value as four bytes at object offset `0xE0`.
2. Call F-920630e53283 with the temporary-storage address.
3. Return if cleanup returns normally.

The write precedes cleanup. It is therefore not an unconditional guarantee about the value visible after return: the cleanup dependency could modify that object through otherwise unknown access.

Likewise, on the dispatch path, dispatch runs before this final write. The function does not itself pre-store the recorded value at `0xE0` before dispatch.

- The one-byte write at `0xE4` on the active path.
- The four-byte write at `0xE0` near the end of the active path.
