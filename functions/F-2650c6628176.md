# F-2650c6628176

## Purpose

The established behavior is a short, partially recovered sequence of memory transfers followed by an indirect control transfer. It reads a 16-bit value, performs a separate 16-bit write using ambient execution state, writes the low eight bits of the previously read value to another address, and invokes a target derived from an ambient link value.

The available representation ends at an invalid-instruction boundary. It does not establish successful completion, a normal return, or the behavior of the indirect target.

No higher-level purpose is established. Interpreting the sequence as an object update, buffer operation, device transaction, or complete callable routine would require evidence not supplied here.

This contract separates the visible prefix from behavior that remains documented_only.

## Behavior

### Address relationships

Three data addresses are used:

1. **Read address:** the fourth explicit input plus eight address units.
2. **Halfword-write address:** twice the ambient address factor.
3. **Byte-write address:** the second explicit input plus the ambient offset.

The address units are consistent with byte-addressed memory. No additional base is visible in the halfword-write address calculation. In particular, that calculation must not be reinterpreted as indexing into an unstated array or object.

The indirect target is formed by adding hexadecimal `DE2`, equivalent to decimal 3554, to the ambient link-related value. The evidence shows a fixed positive displacement, not a table lookup or a target loaded from memory.

Whether these calculations wrap, fault, or have another consequence when they exceed the applicable integer or address range is not established.

### Established operation order

For executions in which each preceding operation completes, the visible sequence is:

1. Read a 16-bit value from the read address.
2. Write the ambient 16-bit payload to the halfword-write address.
3. Write the low eight bits of the value obtained in step 1 to the byte-write address.
4. Invoke the derived indirect target.
5. If that invocation returns into the represented continuation, encounter the boundary identified as invalid instruction data.

This order matters. The byte write uses the value captured by the first operation. It does not reread its source after the halfword write.

The halfword payload is independent of the value read in step 1. There is no established transformation connecting those two values.

### Width and truncation

The initial read and first write are each 16 bits wide. The second write is eight bits wide.

The byte-write value is the least significant eight bits of the captured 16-bit value. For example, a captured value of hexadecimal `12AB` yields a byte-write value of hexadecimal `AB`.

The representation’s character conversion does not justify a signed numeric interpretation of that stored byte. The established result is an eight-bit pattern.

The initial read’s interpretation as a numeric 16-bit value depends on the target’s byte order. Consequently, the routine cannot be described unconditionally as copying the byte at the lower source address. On a little-endian target, the low numeric byte is at the lower address; on a big-endian target, it is at the higher address.

No additional read is established for the other byte during the final write beyond the original 16-bit access.

### Overlapping addresses

No non-overlap check is visible.

If the halfword write overlaps the initial read location, the later byte write still uses the value captured before that overwrite.

If the byte-write location overlaps the halfword-write location, the byte write occurs later and can replace one byte of the preceding halfword result. The exact byte replaced depends on the addresses and target byte order.

If the byte-write location overlaps the initial read location, the captured value remains the source for the write. There is no established reread or iteration.

These statements describe the represented sequence. They do not establish atomicity or behavior under concurrent modification.

### Failures and incomplete execution

There is no visible input validation, error return, recovery branch, or rollback.

If an operation cannot complete, the supplied evidence does not define exception handling or a returned error. Later operations cannot be assumed to occur.

The sequence is not established as transactional. In particular, a failure at the byte-write stage does not imply restoration of the earlier halfword write. Likewise, failure to invoke the indirect target does not imply restoration of either completed write.

The invalid-instruction boundary is evidence of incomplete or problematic recovery, not sufficient evidence for a portable “abort” operation. It must not be replaced in the contract with successful return, a particular exception, or a specific process-termination mechanism.
