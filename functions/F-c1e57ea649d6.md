# F-c1e57ea649d6

## Purpose

F-c1e57ea649d6 examines a fixed sequence of eight candidate records through dependency F-5cdddd9b4e5e. It supports two modes:

- **Count-only mode:** examine all eight candidates and report how many dependency results are nonzero.
- **Collection mode:** store candidate addresses for nonzero dependency results, stopping when either all eight candidates have been examined or the supplied collection capacity has been reached.

The established selection rule is strictly “dependency result is nonzero.” The meaning of that result—such as eligibility, equality, or availability—is not established.

The function returns the fixed 32-bit value 1 after writing the result count. That return value does not distinguish zero matches, truncated collection, or complete collection.

## Behavior

### Initial state and base capture

Before choosing a mode, the function reads the candidate base from global storage and retains that value for the duration of this invocation. It initializes the examined-position counter and accepted-result count to zero.

The global base is therefore read even when collection mode has a nonpositive capacity and no candidate is examined.

Later changes to the global base do not change which base this invocation uses for subsequent candidate-address calculations. This remains true if a dependency call changes that global. It does not imply that other global state or candidate contents remain unchanged.

### Count-only mode

A zero collection destination selects count-only mode.

The function invokes F-5cdddd9b4e5e exactly eight times on ordinary completion, once for each candidate position in ascending order. Every invocation receives:

1. The address for the current candidate, computed from the captured base and the fixed stride.
2. The unchanged second input.

Each nonzero dependency result increases the accepted-result count by one. Zero results leave the count unchanged. Negative nonzero results count in the same way as positive nonzero results.

The capacity input is ignored in this mode. In particular:

- Zero capacity does not suppress dependency calls.
- Negative capacity does not suppress dependency calls.
- Capacity smaller than the number of nonzero results does not limit the reported count.

The function performs no collection-destination writes in this mode. After all eight calls, it writes the final count, between zero and eight inclusive, to the count destination and returns 1.

### Collection mode

A nonzero collection destination selects collection mode.

Before each prospective dependency call, the function compares the signed capacity with the current accepted-result count. If capacity is less than or equal to that count, examination stops immediately.

Consequences of this pre-call comparison include:

- Capacity zero produces no dependency calls.
- Negative capacity produces no dependency calls.
- Positive capacity limits the number of accepted candidates, not the number of examined candidates.
- After a successful candidate fills the final available entry, no later candidate is examined.

If examination is allowed, the dependency receives the current candidate address and the unchanged second input.

For a zero dependency result, the function performs no collection write and advances to the next candidate position.

For a nonzero dependency result, the function:

- Writes the current candidate address into the collection entry indexed by the current accepted-result count.
- Increases that count by one.
- Advances to the next candidate position.

Collection entries are four bytes wide and densely packed. Their order follows candidate examination order. Failed candidates do not create gaps.

The stored value is the candidate address computed by this function, not the dependency’s return value and not a copy of candidate contents.

Examination also stops after candidate position 7. On ordinary completion, the function writes the accepted-result count to the count destination and returns 1.

For positive capacity, the reported count cannot exceed either the capacity or eight. Capacity greater than eight does not create additional candidates.

### Final count write

The final count write occurs after all dependency invocations and collection-entry writes made by this invocation.

The function does not initialize the caller’s count storage before calling the dependency. Thus a dependency that can access that storage through some external route may observe its earlier contents rather than an intermediate count.

Likewise, collection storage is not cleared in advance. Entries beyond those actually written remain untouched by the direct writes shown here, unless they overlap another written region or are changed by the dependency.

## Side effects

### Direct effects

The established direct memory effects are:

1. One read of the global candidate-base storage.
2. In collection mode, zero to eight four-byte candidate-address writes.
3. One four-byte count write on ordinary completion.

The function makes no explicit allocation, deallocation, record copy, or ownership-transfer operation.

A collected address identifies an existing candidate position. Storing that address does not establish that the recipient owns the candidate, may release it, or may retain it indefinitely.

### Dependency effects and ordering

F-5cdddd9b4e5e is called sequentially. Each call finishes before the function evaluates its result and, where applicable, writes a collection entry.

The dependency may have side effects not visible in the supplied body. Its name and call pattern provide no basis for assuming that it:

The first argument to later calls remains based on the captured base even if prior calls mutate global base storage. However, mutation of candidate contents, collection storage, or other accessible state may affect later observations.

### Aliasing

No explicit non-overlap check is present.

If the count destination overlaps a collection entry, the final count write occurs last and can overwrite all or part of the previously stored address, according to the overlap.

If collection storage overlaps candidate storage or global state, an address write can change data observed by a subsequent dependency invocation. The function does not isolate or snapshot candidate contents.

Such overlap is not established as supported usage. Where overlapping memory remains valid under the execution environment, the ordering above describes the direct writes shown. Broader validity depends on alignment, object-access rules, and dependency behavior.

## Acceptance examples

These examples are conditional on valid relevant memory, normally returning dependency calls, and no interfering side effects except where explicitly stated. Dependency results are listed in candidate order.

### Count-only ignores capacity

With a zero collection destination, capacity −3, and dependency results of zero, positive nonzero, zero, negative nonzero, zero, zero, positive nonzero, zero:

- All eight candidates are examined.
- The count destination receives 3.
- No collection entry is written.
- The return value is 1.

Changing capacity alone does not change this mode’s call count or counting rule.

### Collection stops after filling capacity

With capacity 2 and results for the examined candidates of zero, nonzero, zero, nonzero:

- Candidate positions 0 through 3 are examined in that order.
- Collection entry 0 receives the address at base offset 104.
- Collection entry 1 receives the address at base offset 312.
- Candidate positions 4 through 7 are not examined.
- The count destination receives 2.

The count is a collected-result count, not necessarily the total number of matching candidates among all eight positions.

### Capacity limits accepted results, not examinations

With capacity 1 and results of zero for the first seven candidates followed by nonzero for the eighth:

- All eight candidates are examined.
- The first collection entry receives the address at base offset 728.
- The count destination receives 1.

With the same capacity and eight zero results, all eight candidates are still examined, no collection entry is written, and the count destination receives zero.

### Nonpositive collection capacity

With a nonzero collection destination and capacity zero or −1:

- The global candidate base is still read.
- No dependency call occurs.
- No collection entry is written.
- The count destination receives zero.
- The return value is 1.

### Oversized capacity

With capacity 20 and eight nonzero dependency results:

- Exactly eight candidates are examined.
- Eight consecutive collection entries receive their addresses in ascending candidate order.
- No ninth entry is written.
- The count destination receives 8.

### Captured base survives global replacement

Suppose a dependency call replaces the global candidate base with a different address. Subsequent candidate addresses in this invocation still use the originally captured base. No claim follows about whether either candidate region remains valid.

### Final count overwrites an aliased entry

If capacity is 1, the first candidate succeeds, and the count destination is exactly the same four-byte location as the first collection entry:

- The candidate address is written first.
- The final count write replaces it with 1.
- No later candidate is examined.

This example describes write ordering, not an endorsement of overlapping output storage.
