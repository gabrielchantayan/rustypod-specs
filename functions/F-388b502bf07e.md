# F-388b502bf07e

## Purpose

F-388b502bf07e conditionally performs a 16-bit memory transfer, may perform a further narrowly gated 16-bit update, and then enters an unconditional dispatch-and-interrupt loop.

No successful return, completion status, or error result is shown. The application-level purpose of the memory operations and dispatch loop is unknown.

This contract distinguishes the literal behavior supported by the supplied representation from reductions that depend on a flat, 32-bit address model. In particular, extensive conditional regions do not become reachable merely because they appear in the supplied representation.

## Behavior

### 1. Initial selection and memory transfer

The routine first examines bit 30 of the control word and whether the selector is zero.

If the selector is nonzero:

- The initial memory transfer is skipped.
- The downstream conditional memory-update regions are also skipped.
- Execution reaches the terminal dispatch loop with the original continuation base.

If the selector is zero:

- The routine forms an auxiliary numeric address from the continuation base, the initial control bit, and the stack anchor logically shifted right by one.
- It calculates a transfer destination by adding the displacement to the source address, in **bytes**, not in 16-bit elements.
- It reads one unsigned 16-bit value from the source address.
- It writes that value to the transfer destination.
- It retains the destination minus the adjustment as an intermediate address-like value.

The source read precedes the destination write. The read value is retained across that write, so identical source and destination addresses do not change the value selected for this transfer.

No bounds, alignment, null-pointer, or permission checks precede this access.

### 2. Zero-result gates

After the initial selection, further processing depends on a sequence of zero-result conditions. A failed condition disables the remaining conditional regions; it does not cause an error return. Execution still proceeds to the dispatch loop.

Under the flat 32-bit interpretation, the first additional conditions require:

- The selector was zero.
- The original continuation base was zero.
- The auxiliary numeric address was zero.
- The comparison word equaled the displacement.
- The updated intermediate address equaled the adjustment.
- The auxiliary word was zero.
- The stack anchor plus twice the displacement, including the relevant carry input, produced zero.

The initial control bit is cleared on the zero-selector path before the relevant arithmetic carry chain. The reachable zero-result gates therefore do not justify retaining that bit as a later carry input.

Several displayed shift-and-exclusive-or expressions simplify on these paths: their shift count is taken from an intermediate value already known to be zero. They must not be interpreted as independent, arbitrary variable-shift operations on reachable executions.

### 3. Reduction of the exceptional path

The additional conditions are much narrower than a general address-processing algorithm.

With a zero continuation base, the auxiliary numeric address is the sum of:

- The initial control bit, either zero or one.
- The stack anchor logically shifted right by one.

For that sum to be zero under the stated model, the control bit must be zero and the stack anchor must be either zero or one.

A subsequent condition requires the stack anchor plus twice a 32-bit displacement to be zero. That condition excludes an odd stack anchor. Consequently, reaching the exceptional update requires the stack anchor to be zero.

The resulting displacement is either `0x00000000` or `0x80000000`. The comparison word must match it. The intermediate-address condition must also hold after the initial transfer-address calculation.

These are algebraic reachability conditions, not evidence that such an entry state is possible in the actual execution environment.

### 4. Exceptional 16-bit update

If all preceding gates succeed, the routine:

- Sets a represented special machine-state location to a value derived from the stack anchor multiplied by 64.
- Derives a new continuation base by adding that same byte-scaled contribution to the previous continuation base.
- Evaluates two 16-bit reads through the previous continuation base.
- Uses one read value, zero-extended to an address, as a 16-bit write destination.
- Uses the other read value plus 15 as the value to write, truncated to 16 bits.

The supplied expression does not establish which of the two reads occurs first. They must not be collapsed into a single read when volatile memory, device memory, or concurrent modification could make the distinction observable.

Under the normalized reachability conditions above, both the old and new continuation bases are zero. Thus this exceptional path attempts reads through address zero.

The initial transfer happens before these reads. If its destination aliases address zero, it can affect the values subsequently observed.

### 5. Later conditional regions

The exceptional path also advances an internal 16-bit-pointer-derived value by one element, producing numeric address `0x00000002` from a zero selector.

A later zero-result gate then compares that value against an auxiliary value already constrained to zero. The result is nonzero. Consequently, the remaining conditional memory-read and multiword-write regions are unreachable under the normalized 32-bit model.

Those later regions are not specified here as optional observable features. Their presence in the supplied representation does not establish executable behavior.

This reachability conclusion is conditional on the stated interpretation of pointer widths, arithmetic, and represented machine state.

### 6. Terminal dispatch loop

Every path that reaches the bottom of the routine enters the same unconditional loop.

Each iteration performs, in order:

1. An indirect call to the current continuation base plus `0xEB6` bytes.
2. A call through fixed target value `0x0857A94B`.
3. A software interrupt with immediate value `0x5B`.
4. Replacement of the continuation base with `0x083D4CC2`.

The first indirect call receives three displayed arguments:

- `0x00000000`
- `0x00000000`
- `0xFFFFFFA5`

The third argument is a 32-bit bit pattern. It is −91 if interpreted as a signed 32-bit integer, but the callee’s parameter interpretation is unknown.

No explicit arguments are shown for the second call. This does not establish that inherited machine state is irrelevant to that callee.

On the first iteration:

- Ordinary paths use the original continuation base.
- The exceptional path uses its derived continuation base, which reduces to zero under the normalized conditions.

If the first iteration completes, subsequent iterations use first-call target `0x083D5B78`.

There is no visible exit condition. A callee that does not return, an interrupt that transfers control elsewhere, or a memory or execution fault can prevent later operations.

## Side effects

The exceptional path performs additional 16-bit reads and a 16-bit write to an address selected by a read value. That write address is therefore limited to `0x00000000` through `0x0000FFFF` under zero extension.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

### Nonzero selector

Given a nonzero selector and an executable first-call target:

- No conditional memory transfer occurs before the dispatch loop.
- F-UNRESOLVED-01 is invoked at the original continuation base plus `0xEB6`.
- Its displayed arguments have the exact bit patterns listed above.
- F-UNRESOLVED-02 follows only if the first call returns.
- The interrupt follows only if the second call returns.

### Zero selector with nonzero continuation base

Given a zero selector, a nonzero continuation base, and valid transfer addresses:

- One 16-bit source value is read.
- The same value is written at source address plus displacement.
- No exceptional update occurs.
- Dispatch starts from the original continuation base.

### Identical transfer source and destination

Given a zero selector and zero displacement:

- The source read still occurs before the destination write.
- The initially read halfword is written back to the same address.
- This must not automatically be treated as side-effect-free for device or volatile memory.

### Failed exceptional gate

Given a zero selector and zero continuation base, but a nonzero auxiliary numeric address:

- The initial transfer still occurs.
- The exceptional 16-bit update does not occur.
- The first dispatch target is `0x00000EB6`, if execution reaches the call.

### Exceptional update with stable reads

Assume all exceptional-path conditions hold, address zero is readable, and both exceptional reads return `0xFFF8`:

- The exceptional destination is address `0x0000FFF8`.
- The written halfword is `0x0007`, because addition of 15 is truncated to 16 bits.
- The later conditional multiword-write regions remain unreachable under the normalized model.

This example additionally requires that the destination be writable.

### Repeated dispatch

If both dependencies and the interrupt return normally on every iteration:

- The first iteration uses the path-selected continuation base.
- Every later iteration calls F-UNRESOLVED-01 at `0x083D5B78`.
- The loop does not terminate normally.
