# F-6713ff3ef489

## Purpose

F-6713ff3ef489 performs an ordered sequence of indirect invocations, derives address-bearing values from their results and ambient machine state, mutates memory at several widths, and reaches an unresolved four-argument indirect transfer.

No application-level purpose is established. Character-like constants do not establish text generation. Address-bearing fields and self-address stores do not establish an object model, collection type, or ownership protocol.

This contract separates:

- **Established static evidence:** invocation boundaries, represented widths, arithmetic dependencies, and ordered memory accesses visible in the supplied representation.
- **[INFERENCE]:** interpretations requiring an additional arithmetic or execution model.
- **documented_only:** behavior not resolved sufficiently to prescribe an executable replacement.

No runtime tests have been performed.

## Interface

### Inputs and outputs

The represented interface has no explicit parameters. Execution nevertheless depends on:

- Incoming link-related machine state used to form the first invocation target.
- An incoming register-derived value whose low eight bits contribute to an early argument.
- Primary invocation results represented as 32-bit words or 64-bit pairs.
- Secondary post-invocation machine values used independently of primary results.
- Fixed-address storage and memory reached through returned, extracted, sampled, and scaled values.

The actual calling convention and required incoming machine state are **documented_only**. A conventional parameterless signature is not a complete invocation specification.

There is no explicit scalar result or status code. Observable outputs are dependency invocations, memory accesses and mutations, and the terminal transfer. A return is represented after that transfer; whether the underlying transfer returns is **documented_only**.

## Behavior

### Invocation phase

Before the direct mutation region, execution follows a long ordered sequence of indirect invocations without a visible data-dependent branch or loop. The first target derives from incoming link-related state plus 4094. Later targets predominantly derive from fixed continuation-like values plus 4094. No intervening load of a stored function pointer is shown for those target expressions.

Invocations display zero through four arguments. A site displaying no arguments does not establish a verified parameterless signature or cleared argument registers.

Arguments depend on shifted primary results, separately forwarded upper words, secondary machine values, explicit zeros, repeated equal arguments, and values retained across intervening invocations. Ignored results do not make their invocations optional.

Arithmetic includes masks, logical right shifts, left shifts, and power-of-two scaling. Field extraction includes bits 10–19, low-24-bit fields followed by further shifts, and narrower masked fields.

Under the wrapping model, shifting left by eight and then logically right by eight retains the original low 24 bits. Successive 32-bit left shifts by 25 and seven, or by 28 and 28, yield zero. These simplifications are not portable conclusions about signed overflow.

### Opening mutations

The opening mutations store the payload as a word at upper-final-pair + 0x14, then the upper word’s low byte at payload + 9. High base is stored as a word at 256 times the final pair’s low word + 0x54. Payload + 9 is subsequently overwritten with the payload’s own low byte.

High base + 0x14 is cleared as a word. The unsigned byte at high base + 5 is sampled before narrow base + 0x14 is cleared. That sampled byte is zero-extended into high base + 0x34. Only then is the cleared-field sample read from high base + 0x14.

Another word clear at narrow base + 0x14 precedes two separate stores of the cleared-field sample’s low byte at narrow base + 0x15. Fixed storage at 0x05 is sampled afterward. Its underlying read width is **documented_only**; its conversion to an unsigned 32-bit value is represented.

The subsequent byte destinations, in order, are fixed address 0x01 with the narrow base’s low byte, small-storage base + 0x15 with the narrow field’s low byte, and high base + 0x11 with the shifted word’s low byte. A full shifted-word store at cleared-field sample + 0x54 follows, then high base + 0x11 receives zero.

The saved link is read from small-storage base + 0x54 before that word is replaced with the cleared-field sample. Narrow base + 0x34 receives the narrow field as a word.

A word read at high base + 0x74 supplies the **opening destination**. Its offset-0x54 word receives the high-producing word shifted left by 26.

A separate mutation reads narrow base + 0x74 twice: one read supplies a destination base and the other its offset-0x54 word payload. These are distinct reads; their relative expression-evaluation order is **documented_only**.

The saved link is stored at saved link + 0x24. Opening destination + 9 then receives its low byte, and opening destination + 0x54 receives the shifted word. The saved-link self-store and opening-destination byte store are repeated, in that order.

Narrow base + 0x14 next receives the high-producing word shifted left by 26. Fixed address 0x54 receives a word equal to the saved link shifted left by one. ### Linked mutations and distinct lookups

Fourfold link + 0x54 receives the shifted word. Narrow base + 0x34 receives the fourfold link. A fresh word read at narrow base + 0x74 is doubled to produce the **intermediate doubled base**. Fourfold link + 0x54 is then overwritten with the fourfold link itself.

Fourfold link + 0x15 receives the eightfold link’s low byte. Saved link + 0x44 receives the intermediate doubled base as a word.

The **first byte-based lookup** reads the unsigned byte at fourfold link + 5, then reads a word at that byte’s value + 0x74. This word is the **earlier lookup base**. Earlier lookup base + 0x44 receives the intermediate doubled base.

The next linked mutations have a definite order:

- Immediately after that offset-0x44 word store, fourfold link + 0x15 receives the **fourfold link’s low byte**.
- Fourfold link + 0x0D receives the earlier lookup base’s low byte.
- Fourfold link + 0x14 receives the fourfold link as a word.
- Fourfold link + 0x54 receives the fourfold link as a word.

**Only after those four stores** is the word at fourfold link + 0x64 sampled. The resulting **sampled linked base** receives the earlier lookup base’s low byte at offset 0x0D, followed by its own address as a word at offset 0x14.

Thus, the two self-address word stores have specific destinations and payloads: fourfold link at fourfold link + 0x14, and sampled linked base at sampled linked base + 0x14. The offset-0x54 overwrite precedes the offset-0x64 sample and both sampled-base mutations. Neither alias freedom nor permission to reorder these accesses is established.

A word is then sampled at fourfold link + 4 to obtain the **byte-source base**. Intermediate doubled base + 9 receives the earlier lookup base’s low byte, and its offset-0x44 word receives the eightfold link.

The unsigned byte at byte-source base + 5 is sampled. Fourfold link + 9 receives the intermediate doubled base’s low byte before that sample is zero-extended into earlier lookup base + 0x44. Fourfold link + 0x14 receives the eightfold link. Intermediate doubled base + 0x15 receives the byte-source base’s low byte, and its offset-0x44 word receives the fourfold link.

The byte at byte-source base + 5 is then read **again**. Fourfold link + 0x15 receives the eightfold link’s low byte before a word is read at the later byte’s value + 0x74. This result is the **later lookup word**.

Twice the later lookup word is the **link-derived base**, retained through the repetition region and used throughout the final region. It is neither the earlier lookup base nor the unscaled later lookup word.

Before the constant stores, fourfold link + 0x15 receives the byte-source base’s low byte; its offset-0x54 word receives the fourfold link; its offset-9 byte receives the link-derived base’s low byte; and its offset-0x14 word receives the eightfold link.

Computed destinations may overlap each other or fixed storage. An intervening write can change a subsequent read, including a read following an explicit clear. The linked stores preceding the fourfold-link offset-0x64 sample are therefore observable ordering requirements, not interchangeable setup operations.

Access offsets do not establish complete records or ownership of intervening bytes. No allocation, release, reference counting, synchronization, or ownership transfer is explicitly identifiable. Unknown dependencies may perform such operations; their absence cannot be inferred.
