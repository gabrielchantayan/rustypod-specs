# F-6ca4c3b0a247

## Purpose

F-6ca4c3b0a247 is a condition-dependent dispatcher. It selects helper operations from a 32-bit selector, with three additional behaviors visible directly:

- A bounded search that can invoke a method on an implicit receiver.
- A method invocation followed by storage of a supplied 32-bit value into that receiver.
- A zero return for selectors that reach an unhandled branch.

The dispatch depends on incoming processor condition flags, not solely on the five explicit arguments. The supplied representation therefore does not establish a self-contained, ordinary five-argument API. Correct use requires the implicit entry state described below.

The numeric selectors are established evidence. Their application-level meanings—such as event types, commands, or notification categories—are not established.

### Result

- Unhandled branches return zero explicitly.
- Most handled branches return the implicit result word.

No visible assignment initializes or changes the implicit result word. Its relationship to success, failure, or “handled” status is unknown. In particular, a handled branch is not guaranteed to return nonzero.

## Behavior

### 1. Entry-condition routing

Entry flags take precedence over selector interpretation:

1. If the incoming zero flag is set, invoke F-f4c9f8a20a8f and return the implicit result word. This occurs regardless of the selector.
2. Otherwise, if the incoming negative and overflow flags differ, use the threshold-based dispatch below.
3. Otherwise, use the fixed-selector dispatch below.

The function does not visibly calculate these flags from an explicit argument. A contract that substitutes a comparison of the selector for the incoming flags would add unsupported behavior.

### 2. Threshold-based dispatch

Let **T3** denote the represented 32-bit expression D plus 3, and **T4** denote D plus 4. Their values and overflow behavior cannot be resolved without additional provenance. The following order is significant, including if D makes a threshold coincide with a fixed selector.

First, compare the selector with T3:

- Equality invokes F-54cafacaf6bc and returns the implicit result word.
- Otherwise, a signed comparison selects either the below-T3 branch or the above-T3 branch.

#### Selector below T3

Apply these decisions in order:

1. Selector `0x52800000`: perform the bounded search described below.
2. Otherwise, selector equal to D: invoke F-f4c9f8a20a8f and return the implicit result word.
3. Otherwise, selector `0x63800002`: invoke F-3ec82bbbf5c6 and return the implicit result word.
4. Otherwise, selector `0x63800003`: invoke F-040d2feec936 and return the implicit result word.
5. Otherwise, return zero.

Consequently, a fixed selector in this list is not necessarily reachable for an arbitrary value of D. Its threshold relation and all earlier equalities must permit that branch.

#### Selector above T3

Apply these decisions in order:

1. Selector equal to T4: invoke F-f4c9f8a20a8f and return the implicit result word.
2. Otherwise, selector `0x63800006`: invoke F-716481da7646 and return the implicit result word.
3. Otherwise, selector `0x63800007`: invoke F-c5849f62ea69 and return the implicit result word.
4. Otherwise, selector `0x63800008`: perform the method-and-store behavior below.
5. Otherwise, return zero.

Equality with T4 takes precedence over the fixed-selector checks.

### 3. Bounded search

This behavior is reachable only through the corresponding threshold-dispatch branch.

#### Source acquisition

The visible read and call order is:

1. Read the pointer at byte offset 12 of argument 1.
2. Read the first 32-bit word at that pointer.
3. If this word is zero, return the implicit result word immediately.
4. Invoke F-938c950e5046 to obtain an object.
5. Read that object’s method-table pointer and invoke the method at byte offset 232, supplying the object and K as visible arguments.
6. Invoke F-682adfd5a561 with the preceding method’s result and `0x1700`.
7. Invoke F-0f333381a04d with the source word obtained in step 2.
8. On the object returned by F-0f333381a04d, invoke the method at method-table byte offset 20. Preserve its 32-bit result as the comparison target.
9. On the object returned by F-682adfd5a561, invoke the method at method-table byte offset 368, visibly supplying that object. Interpret its 32-bit result as an unsigned starting position.

No null-result checks are visible between these calls and their dependent dereferences. The recovered invocation at offset 20 does not establish its complete argument convention.

The two returned objects are not interchangeable: one supplies the target word; the other supplies the starting position.

#### Candidate range and arithmetic

The upper bound is the unsigned 32-bit starting position plus 5, with 32-bit wraparound. Each iteration tests whether the current position is strictly below this bound before attempting a candidate.

This is not an unconditional five-candidate search:

- Starting positions from zero through `0xFFFFFFFA` produce a nonwrapped bound.
- Starting positions `0xFFFFFFFB` through `0xFFFFFFFF` produce a wrapped bound that is already less than or equal to the starting position. No candidate comparisons occur.
- A current position of zero is skipped without invoking the comparison helper.
- Otherwise, the comparison-helper index is the current position minus 1.

For an ordinary nonzero starting position with a nonwrapped bound, at most five comparisons occur. With starting position zero, only four comparisons occur: current positions 1 through 4, corresponding to indices 0 through 3.

#### Comparison and match

For each eligible, nonzero current position:

1. Read the 32-bit word at byte offset 48 of the implicit receiver.
2. Invoke F-c47b877c6f23 with that word and the unsigned current position minus 1.
3. Compare the returned 32-bit word with the previously obtained target.
4. If equal, stop searching and invoke the implicit receiver’s method at method-table byte offset 116.
5. Return the implicit result word after that method returns.

If unequal, increment the current position by one using unsigned 32-bit arithmetic and repeat the bound test.

The receiver field at offset 48 is read again for each comparison. It is not visibly cached across helper calls. Changes made by an earlier helper can therefore affect later comparisons.

On exhaustion, return the implicit result word without invoking the method at offset 116. There is no visible distinction in the returned word between a match and exhaustion.

### 4. Method-and-store behavior

For selector `0x63800008`, when reached through threshold dispatch:

1. Read argument 1’s method-table pointer.
2. Invoke the method at byte offset 8.
3. After that call returns, write argument 5 as a 32-bit word at byte offset 1840 of the implicit receiver.
4. Return the implicit result word.

The write follows the method call; it is not performed first. No conditional check of the method’s return value is visible.

Argument 1 and the implicit receiver are separate inputs. They must not be assumed to identify the same object. The method’s complete argument list is not established by the recovered call.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

1. **Entry-zero precedence.** Given a set zero flag and selector `0x63800011`, the visible action is F-f4c9f8a20a8f followed by the implicit result-word return. The fixed-selector zero-return behavior does not apply.

2. **Fixed-selector no-action case.** Given a clear zero flag, equal negative and overflow flags, and selector `0x63800012`, the function returns zero without any visible helper invocation.

3. **Threshold precedence.** Given threshold dispatch and selector equal to T3, F-54cafacaf6bc is selected even if that selector also equals one of the fixed constants appearing later in the decision tree.

4. **Zero search source.** Given a reachable search branch and a zero word behind argument 1’s offset-12 pointer, the function returns the implicit result word before calling F-938c950e5046.

5. **Search from zero.** Given completed setup, starting position zero, and no matches, F-c47b877c6f23 receives indices 0, 1, 2, and 3 in that order. No comparison is made for current position zero, and no match method is invoked.

6. **Early search match.** Given starting position 2 and a match on the second comparison, the comparison indices are 1 and 2. The receiver’s offset-116 method is then invoked once; later candidates are not examined.

7. **Wrapped search bound.** Given starting position `0xFFFFFFFB`, setup calls have already occurred, but no comparison-helper call or match-method call occurs. The unsigned upper bound is zero.

8. **Ordered store.** Given a reachable `0x63800008` branch and a normally returning offset-8 method, argument 5 is written at implicit-receiver offset 1840 after that method returns. A method that reads the destination before returning observes the pre-store state, subject to its own intervening effects.
