# F-0a49880cf1fe

## Purpose

F-0a49880cf1fe conditionally updates geometry and complementary level settings for two objects referenced by a caller-supplied state record. It then invokes two further operations pairing those objects with other stored values.

The update is gated by two current 32-bit values and their cached counterparts. If both current values match the cache, the function performs no dependency calls or explicit state writes and returns the 32-bit value 1.

The apparent intent is a visual transition involving centered geometry and complementary 8-bit levels. That interpretation is inferred, not established: the meanings of the referenced objects and the dependency operations are unavailable.

## Interface

### Input and result

The sole input is an address identifying a mutable state record.

The normal return value is always 1, represented in 32 bits. It does not report whether an update occurred, whether a dependency succeeded, or whether geometry was usable.

There is no explicit validation of the state address, nested addresses, object references, dimensions, arithmetic ranges, or dependency results.

## Behavior

### 1. Read current values and evaluate the cache gate

The function first reads:

1. The address stored at state offset +0x44, then its 32-bit field at offset +4.
2. The address stored at state offset +0x48, then its 32-bit field at offset +4.
3. The cached first value at state offset +0x4c.

Call the first two sampled words the **first current value** and **second current value**.

Only if the first current value equals its cached value does the function read the cached second value at +0x50 for comparison.

If both values match their caches, the function returns 1 immediately. In particular, this path does not read the base dimensions, selector byte, or object references.

Changes to fields other than the two sampled current values do not independently trigger an update.

### 2. Compute initial target dimensions

On a cache miss, the function reads the base height at +0x2c and then the base width at +0x28. Denote these by **H** and **W**.

The initial target width is derived from the first current value:

- Add 0x7fff.
- Arithmetic-right-shift by 16.
- Clear the lowest two bits using the 32-bit mask 0xfffffffc.
- Treat the resulting word as unsigned for subsequent width comparisons.

For ordinary nonnegative, non-overflowing inputs, this is a biased 16-bit fixed-point conversion followed by alignment downward to a multiple of four. It is not a general nearest-multiple-of-four operation.

The function then calls F-d7be9cfb4000 with:

1. The 32-bit product of the initial target width and H.
2. W.

The returned 32-bit word becomes the initial target height. The dependency’s operation is unknown; division must not be assumed.

### 3. Limit the target dimensions

Width and height limits are applied independently to the initial targets.

For width:

- If the unsigned value of four times W is less than the initial target width, the target width becomes W shifted left by two.
- Otherwise, the function computes a quarter-width bound by interpreting W as signed and dividing by four with truncation toward zero. Its resulting word is compared as unsigned.
- The retained target width is the greater of the initial target width and that quarter-width bound, using unsigned comparison.

For height:

- If the unsigned word produced by four times H is less than the initial target height, the target height becomes H shifted left by two.
- Otherwise, a quarter-height bound is computed from signed H with truncation toward zero.
- If the initial target height is unsigned-less-than that bound’s word, the bound replaces it.

For ordinary positive dimensions without overflow, these operations constrain each target dimension to approximately one-quarter through four times its corresponding base dimension. They do not establish a safe range for arbitrary signed inputs or wrapped products.

### 4. Optionally convert enlargement into a cropped geometry

The function initializes:

- A horizontal crop-related quantity to zero.
- A vertical crop-related quantity to zero.
- A retained width to W.
- A retained height to H.

It enters the crop-adjustment branch only when W is unsigned-less-than the limited target width.

Within that branch, the order is:

1. Calculate a horizontal half-difference: logical half of the target width minus signed, truncating half of W.
2. Call F-d7be9cfb4000 with that half-difference multiplied by W, followed by the current target width.
3. Save the returned word as the horizontal crop-related quantity.
4. Reduce the target width by twice the horizontal half-difference.
5. Reduce the retained width from W by twice the horizontal crop-related quantity.
6. Calculate a vertical half-difference: logical half of the target height minus signed, truncating half of H.
7. Call F-d7be9cfb4000 with that half-difference multiplied by H, followed by the current target height.
8. Save the returned word as the vertical crop-related quantity.
9. Reduce the target height by twice the vertical half-difference.
10. Reduce the retained height from H by twice the vertical crop-related quantity.

There is no separate test requiring the target height to exceed H. Width enlargement alone causes both horizontal and vertical adjustments.

If the width-enlargement test fails, both crop-related quantities remain zero, both retained dimensions remain their base dimensions, and the limited target dimensions remain unchanged.

### 5. Compute placement and commit the cache

Horizontal placement is computed as:

- Signed W divided by 2, truncating toward zero;
- Minus the logical half of the current target width;
- With the resulting word interpreted as signed;
- Replaced by zero if that signed value is negative.

Before invoking any of the object-update dependencies, the function explicitly writes:

1. The sampled second current value to +0x50.
2. The sampled first current value to +0x4c.

Vertical placement is computed analogously from signed H and the logical half of the current target height, then clamped to zero if negative.

The level value is derived from the sampled second current value by:

- Adding 0x7fff using unsigned arithmetic;
- Keeping only the lowest 24 bits;
- Logical-right-shifting by 16.

The result is necessarily between 0 and 255. This is a masked extraction after addition, not saturation. Values outside an intended fixed-point range can wrap into that range.

### 6. Submit geometry

2. Horizontal placement.
3. Vertical placement.
4. Vertical crop-related quantity.
5. Horizontal crop-related quantity.
6. Current target width.
7. Current target height.
8. Retained width.

The fourth and fifth positions are significant: the vertical crop-related quantity precedes the horizontal one.

No return value from this dependency is inspected.

### 7. Submit complementary levels

After the geometry call returns, the function reads the selector byte at +0x3c.

If the byte is zero:

1. Call F-460b2abbbbbe with the object freshly read from +0x20 and the derived level.
2. Read the object at +0x24.
3. Call F-460b2abbbbbe with that object and 255 minus the level.

If the byte is nonzero:

1. Call F-460b2abbbbbe with the object freshly read from +0x20 and 255 minus the level.
2. Read the object at +0x24.
3. Call F-460b2abbbbbe with that object and the original level.

## Side effects

The only explicit writes to caller-owned state are the two cache writes at +0x50 and +0x4c.

These occur before the geometry, level, and final-operation calls. Consequently:

- The cache is not evidence that those later calls succeeded.
- There is no explicit rollback.
- A reentrant invocation after those writes may see matching cache values and skip its update, provided nothing else changes them.

F-d7be9cfb4000 is called before the cache writes and may have undocumented side effects. It must not be assumed to preserve the input record or other global state. Dimensions and current values already sampled by this function remain represented by those samples, while later explicit field reads may observe changes.

Likewise, the geometry dependency can affect the subsequently read selector and object fields. The first level call can affect the object reference subsequently read at +0x24. Final-operation arguments can reflect changes made by preceding dependencies.

There is no explicit allocation, release, ownership transfer, or reference-count operation in this function. Passing an object reference to a dependency does not establish that the dependency borrows, retains, consumes, or releases it.

No local error handling or recovery path is shown.

- A zero selector sends 64 to the first object and 191 to the second.
- A nonzero selector sends 191 to the first object and 64 to the second.

### Level extraction wraps rather than clamps

### Dependency mutation affects later reads

If the first level dependency changes +0x24 before returning, the second level call uses the changed object reference.

Neither example implies that such mutation is intended; both follow from the visible read order.
