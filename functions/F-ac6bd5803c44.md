# F-ac6bd5803c44

## Purpose

The supplied static representation describes a sequence of indirect calls interleaved with byte reads, byte writes, and 32-bit writes. The visible sequence initializes several locations to zero, writes scaled call results into other locations, and extracts portions of incoming or returned words into byte-sized storage.

No application-level purpose is established. In particular, the evidence does not establish that the affected locations are ordinary objects, tables, device registers, or valid writable memory.

The representation ends at an invalid-instruction boundary rather than a demonstrated normal return. Its own warnings identify unreliable instruction decoding and overlapping global symbols. This contract therefore specifies the visible sequence conditionally: it applies where the represented instructions and call boundaries are accurate and execution reaches them.

## Side effects

### Direct memory effects

The visible body contains:

- Five unsigned byte reads: one initial read, three reads from the context-derived selector location, and one read based on the final packed result.
- Five byte writes.
- Fourteen 32-bit writes.
- Four separate zero-word writes to absolute address `0x24`.

The first byte selector is retained for a later word clear. Later byte selectors are read afresh at their specified points.

Because a selector is an unsigned byte:

- selector-plus-`0x11` destinations range from `0x11` through `0x110`;
- the initial selector-plus-`0x44` word-start address ranges from `0x44` through `0x143`.

Those are absolute address expressions in the supplied representation, not established offsets within an allocated object.

### Aliasing and observable order

No disjointness guarantee is available. Byte destinations, word destinations, selector-read locations, and address `0x24` can overlap.

For example, selector value `0x13` makes a selector-plus-`0x11` byte write target `0x24`. A later zero-word write to `0x24` can therefore replace that byte along with adjacent bytes.

Word-store alignment is not checked. A failure or device-specific effect at an unaligned address is not excluded.

Each dependency may introduce additional memory effects or change memory that subsequent direct reads observe. The listed stores are not guaranteed to remain the final contents after later calls.

## Acceptance examples

These are conditional specification examples, not runtime results. Each assumes execution reaches the relevant operations and that necessary accesses and calls complete.

1. **Initial packed-byte extraction.** If the incoming packed word is `0xABCDEF01`, the first byte write carries `0xAF`. Its destination is the byte read from the incoming address/context word plus one, then increased by `0x11`.

2. **Retained initial selector.** If the initial selector read returns `0x20`, the first byte destination is `0x31`, and the later initial-selector word clear starts at `0x64`. Changing the original selector-read memory during F-d008–F-d012 does not change that retained word-clear address.

3. **Index-based clearing.** If F-d021 returns three, the next indexed zero-word write starts at `0x50`. The following direct write clears the word at `0x24`, and F-d022 receives 12.

4. **Saved payload versus later index.** If F-d050 returns three and F-d055 returns five, the first payload write stores 12 at `0x44`; the later payload write stores the same 12 at `0x28`. F-d056 receives 20. No arithmetic overflow occurs in this example.

5. **Fresh selector reads.** If the selector read following F-d072 yields `0x20`, but the read following F-d079 yields `0x30`, the corresponding byte destinations are `0x31` and `0x41`. Reusing the first selector would not satisfy the represented behavior.

6. **Packed-result truncation.** If F-d072 returns `0xABCDEF01`, its first byte write carries `0x04`, and its later high-field byte write carries `0xBC`. F-d073 receives `0xAF37BC04` under a 32-bit wrapping-shift interpretation.

7. **Final result-derived lookup.** If F-d084 returns five, the last selector read occurs at address 41. The final byte value is zero because bits 20–27 of five are zero. The destination still depends on the byte read at address 41.

8. **Nonreturning dependency.** If F-d027 does not return, the subsequent high-half-based zero store and F-d028 call are not reached. No rollback of earlier effects is specified.
