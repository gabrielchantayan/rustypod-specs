# F-23fb0cd90586

## Purpose

F-23fb0cd90586 conditionally scans an object-associated sequence in increasing index order. It stops at the first entry whose leading integer value is nonzero and passes that value to two dependencies, in order. The second dependency is marked as non-returning in the supplied static evidence.

The function returns without selecting an entry when either:

- The object’s enable indicator is zero after conversion to a character-sized value.
- Every entry within the captured bound has a zero leading value, including the case where the bound permits no entries.

The apparent intent is to find the first actionable entry and initiate a terminal operation for it. That interpretation is **inferred intent**, not an established description of what the dependencies actually do. The supplied evidence does not identify the values as handles, pointers, error codes, or resource identifiers.

## Behavior

### Enable gate

The first explicit object-field read is object word 10. Its value is converted to a character-sized value and compared with zero.

If the converted value is zero, the function returns immediately. It does not read the iteration bound, resolve the accessor, or invoke either named dependency on this path.

This is a narrowed-value test, not a full-integer nonzero test. Under an 8-bit truncating interpretation, only the low eight bits determine whether the object is enabled. A full integer can therefore be nonzero while the function remains disabled. Signed versus unsigned interpretation of a retained nonzero byte does not change this zero/nonzero decision.

The indicator is checked once. No subsequent iteration or callback return causes it to be checked again.

### Captured bound and index range

If enabled, the function reads object word 1 and retains that value as its bound. Iteration begins at index zero.

Before each accessor call, the current index is compared with the captured bound using a signed comparison. If the index is greater than or equal to the bound, the function returns.

Consequences include:

- A zero bound produces no accessor calls.
- A negative bound also produces no accessor calls.
- A positive bound permits indices from zero through one less than the bound.
- A later change to the object’s bound does not alter the retained bound used by this invocation.

Under the recovered signed 32-bit interpretation, the loop’s own increment does not overflow for any representable bound. At the largest positive bound, the last potentially accessed index is 2,147,483,646. After a zero candidate at that index, the index becomes 2,147,483,647 and the next comparison ends the scan before another increment.

### Accessor resolution and invocation

For every reached index, the function obtains an indirect-call target from the table slot at displacement 0x40 from the address-bearing value in object word 0. It calls that target with:

1. The original object reference.
2. The current index.

This dynamically selected dependency is designated **D-01** in this contract. Its implementation identity is not supplied.

The dispatch lookup occurs for each reached index. The function does not establish a single cached accessor target for the entire scan. If an earlier dependency call changes dispatch-related state and then returns, a later iteration can observe that changed state.

After D-01 returns, the function reads the leading integer at the returned address. It does not first test the returned address for null or otherwise validate it.

The returned address itself is not the candidate. The integer read through that address is the candidate.

### Zero candidates

If the candidate equals zero, the function increments the index by one and repeats the bound comparison.

For a zero candidate:

- Neither F-2a6f4da25e2a nor F-feee9156a257 is called.
- No later field of the returned entry is explicitly read.
- The function performs no explicit release, removal, or modification of that entry.

The next iteration uses the captured bound, but resolves the dispatch target again.

### First nonzero candidate

Any nonzero candidate ends the search immediately. Positive and negative integer values both qualify; the test is not a positivity test.

The function first calls F-2a6f4da25e2a with the captured candidate. If that dependency returns normally, it then calls F-feee9156a257 with the same captured value.

There is no explicit candidate reread between the two calls. Thus, if the first dependency changes the entry’s leading integer, that change does not select a different argument for the second call. The argument is retained by value according to the recovered interface.

No later index is visited after a nonzero candidate has been selected. The function does not search for a “better” value, process all nonzero entries, or resume scanning after the first named dependency returns.

If F-2a6f4da25e2a does not return normally, the supplied control flow does not establish execution of F-feee9156a257.
