# F-bb4733438006

## Purpose

F-bb4733438006 reads structured input into an existing destination using a destination-associated working context. It checks a fixed-size header, processes a nonzero declared record count, dispatches two recognized record types to specialized dependencies, and skips other record types.

After successful processing, it traverses destination-associated objects, invokes an external operation on a destination-resident field, and writes `1` to the destination’s byte at offset `0x05`. On a post-open failure, it instead calls F-c67cb20988a1 with that field’s address and a captured opaque value, then writes `0` to byte `0x05`. **Whether F-c67cb20988a1 clears, releases, or otherwise changes the addressed field is unknown.** Both paths subsequently close the temporary input object, clear its published context pointer, and invoke finalization.

“Input,” “import,” “conversion,” “skip,” and “loaded marker” describe apparent roles. The binary format, public object types, and full dependency semantics are not established.

## Behavior

If argument 5 is non-null, the function first writes 16-bit zero to its target, then 16-bit zero to argument 6’s target. These writes precede destination validation.

F-cd52fcefba54 receives the destination. A zero result causes immediate return of `-50`, without reading destination word `0x08`. A nonzero result permits that word to be read; a nonzero word also causes immediate return of `-50`.

F-0659384c4c8f then receives the destination and an output location for the context address. A nonzero status is returned immediately.

There is no caller-side close, failure operation, or finalization on that path. The earlier context-byte write is not undone.

After opening succeeds, the function writes the temporary object’s address to context word `0x0000`, then writes argument 2 to context word `0x8020`.

- The second queried information word is zero.
- Header word `0x08` equals the first queried information word.

Next, the full 32-bit header word `0x0C` must be zero, and the unsigned record count must be nonzero. Failure selects `-208`. A zero low halfword alone does not satisfy the full-width zero requirement.

## Side effects

The operation is not visibly transactional. Optional results and metadata can be written before failure. Record handlers and other dependencies may make additional changes. No rollback of metadata, argument 2’s stored value, or context mode bytes is visible.

The function directly writes only the loaded marker during its failure-completion sequence; changes to the destination-resident field at `0x8C6` depend on F-c67cb20988a1 and are unknown.

No direct allocation or release of the destination or working context is visible. Publishing the temporary input-object address does not establish ownership transfer. Dependencies’ retention, allocation, release, and global-preservation behavior are unknown.

No synchronization or reentrancy protection is visible. Safe concurrent or nested use requires an external contract.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, they assume accessible storage and no dependency or aliasing effects that change the specified premises.

1. **Rejected destination:** With enabled outputs and a zero validator result, both outputs are cleared in order, then `-50` is returned. Destination word `0x08` is not read.

2. **Disabled outputs:** If argument 5 is null, argument 6 is neither cleared nor populated.

3. **Opening failure:** If flags bit 0 is set, context acquisition succeeds, and opening returns a nonzero status, context byte `0x000E` has already been written as `1`. That status is returned without caller-side closing or post-open finalization.

4. **Header-read failure:** After a successful information query, a failed header read still precedes capture of the native-signature snapshot. Its nonzero status then selects failure handling; header recognition and result publication are not reached.

5. **Size inconsistency:** If recognition succeeds **and the post-publication signature comparison against the captured native signature passes**, a nonzero second information word or mismatching first word produces `-39`. Optional header results have already been published.

6. **Unsuccessful alternate normalization:** If alternate recognition succeeds but conversion leaves a signature different from the captured native signature, the result is `-208`, even when the queried size information would also fail. Size checking is not reached.

7. **Distinct native observations:** If the header matches the recognition-time native value but differs from the earlier snapshot, initial recognition succeeds and outputs are published, but the later signature check produces `-208`.

8. **Full-width rejection:** With preceding checks satisfied, header word `0x0C` equal to `0x00010000` publishes zero as the first result but fails the 32-bit zero requirement with `-208`.

9. **Unknown record type:** A valid record of type `-1`, or any type other than `1` and `2`, uses total extent minus header extent through F-22914e190356. The type alone is not rejected.

10. **Failure after metadata:** A record-handler error invokes F-c67cb20988a1, writes zero to byte `0x05`, closes, clears the context pointer, and finalizes before returning that error. The earlier metadata writes are not directly undone; the descriptor field’s resulting contents remain dependency-defined.

11. **Success:** If every checked operation succeeds and traversal terminates, the external success operation precedes writing `1` to byte `0x05`; closing precedes clearing the context pointer; finalization precedes return of zero.
