# F-736e2d3b9a3e

## Purpose

The supplied static representation describes a state-mutating routine with three explicit argument slots, additional entry-register dependencies, numerous indirect calls, word-sized stores, byte-indexed stores, and an unconditional repeating tail.

No application-level purpose is established. In particular, the evidence does not justify describing this routine as a serializer, allocator, device driver, decoder, or collection operation.

This contract records the visible execution sequence conditionally: each described step is reached only if preceding memory accesses and indirect calls complete and return normally. The representation includes warnings about invalid instruction data and removed control-flow regions. Consequently, it is evidence for the displayed operations, not proof that the original executable follows a complete, correctly recovered function boundary or calling convention.

No runtime tests have been performed.

## Behavior

### Ordering conventions

Every dependency invocation is potentially observable. A call with no displayed arguments does not mean that the dependency has no implicit inputs or side effects.

The following recurring sequence is used to describe the ordering without assigning semantics to unknown callees:

- A **four-call group** consists of four consecutive indirect calls with no displayed arguments.
- The first three results are not used by visible subsequent expressions.
- The fourth result is retained where identified below.
- The four targets need not be identical.

All described values are the values supplied by the representation at the indicated point. No dependency is assumed to preserve global memory, release resources, or leave unrelated registers unchanged.

### 1. Initial stores and first derived word

Let \(P\) be the first argument and \(R\) the entry word.

1. Store \(P\) as a 32-bit word at address \(4P+20\).
2. Invoke the initial dependency with four displayed arguments: \(4P\), \(P\), the original third argument, and \(R\) shifted left by three bits. Its target is derived from the entry link register plus a fixed displacement.
3. Make a no-displayed-argument call and pass its 32-bit result to a one-argument call.
4. Make another no-displayed-argument call and pass its result, together with \(R\) logically shifted right by eight bits, to a two-argument call.
5. Execute a four-call group. Call its final result \(A\).
6. Store \(P\) again at address \(4P+20\).
7. Call another dependency with \(4A\).
8. Execute another four-call group. Call its final result \(B\).
9. Logically shift the third argument right by seven bits.
10. Store \(4B\) at address \(16B+20\).

The repeated store in step 6 is a distinct observable write. It cannot be removed on the assumption that intervening calls left the location unchanged.

### 2. Entry-word-indexed updates

Continue with the derived value \(4B\):

1. Call a dependency with \(4B\) and \(8R\).
2. Perform two no-argument-result forwarding pairs: the first result is passed to a one-argument call; the second result is passed to a two-argument call whose other argument is \(R \mathbin{\gg} 8\).
3. Execute a four-call group, retaining result \(C\).
4. Store \(4B\) at address \(8R+20\).
5. Call a dependency with \(4C\).
6. Execute a four-call group, retaining result \(D\).
7. Store \(4D\) at address \(16D+20\).
8. Call a dependency with four displayed arguments: \(8R\), \(8R\), \(R \mathbin{\gg} 8\), and the already-shifted third argument shifted right by seven more bits.
9. Execute a four-call group, retaining result \(E\).
10. Store \(8R\) at address \(8R+20\).
11. Call a dependency with \(E\) shifted left by two bits.
12. Execute a four-call group.

The third-argument component in step 8 is therefore the original unsigned third argument shifted right by fourteen bits. It is not a seven-bit field extraction and is not masked to seven bits.

### 7. Unconditional repeating tail

Each iteration performs:

1. A two-argument call using the current loop-carried word and the current loop quantity logically shifted right by eight bits.
2. A four-call group, retaining its last result.
3. A fresh byte read from \(1024W+1\), followed by a zero-byte store at the read value plus 17.
4. A one-argument call using the group result shifted left by two bits.
5. Another four-call group, retaining its last result.
6. Replacement of the loop-carried word by that result shifted left by two bits.
7. Replacement of the loop quantity by that same result shifted left by twenty-six bits.
8. Immediate repetition, without a visible termination condition.

The initial loop quantity \(B_0\) is between 0 and 31, so its first right shift by eight bits is necessarily zero.

Under 32-bit machine-shift behavior, subsequent loop quantities retain only the low six bits of the latest result, positioned in bits 26–31. Signed-shift interpretation remains an uncertainty where the displayed operand is signed.

## Side effects

### Memory layout and aliasing

No enclosing allocation, object header, array size, or ownership relationship is established.

The repeated displacement of 20 bytes does not prove a field layout. The visible word stores use several distinct address forms, including fourfold, eightfold, sixteenfold, and much larger scaling.

Each byte-selector operation has two distinct accesses:

1. Read one unsigned byte at the selector address.
2. Write one byte at an address equal to that byte’s value plus 17.

The second access is not a write through a full-width pointer loaded from memory. Its destination lies between addresses 17 and 272 inclusive.

All addresses may alias unless an external memory model rules this out. In particular, a selector-driven store may overwrite a later selector byte. Consecutive zero stores therefore cannot be collapsed merely because their expressions look identical.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Initial store ordering.** If the first argument is 3 and the initial access succeeds, the first visible write stores the 32-bit value 3 at address 32. It occurs before the initial dependency call. The same write occurs again only after the intervening call sequence completes.

2. **Third-argument reduction.** If the original third argument is `0x00004000`, the four-argument call in the entry-word-indexed phase receives 1 in its fourth displayed position. The initial call still receives `0x00004000`.

3. **Fresh selector reads.** Suppose the selector byte is 5 for one byte-store event and becomes 9 before the next. The destinations are respectively 22 and 26. An implementation that caches the original selector value would not match the displayed behavior.

4. **Byte truncation.** If \(X=\text{0x12345678}\), the first selector-driven byte store writes `0xe0`. The later masked-and-shifted store writes `0x23`, provided both events are reached. Their destinations are independently resolved.

5. **Entry-word-derived byte destination.** If \(R=\text{0x01800000}\), the direct byte store before the zero-store sequence targets address 31, because \(R \mathbin{\gg} 23=3\).

6. **Initial loop argument.** Any unsigned result used to construct \(B_0\) produces a value no larger than 31. The second displayed argument to the first loop call is therefore zero.

7. **No successful-return criterion.** If every access succeeds and every dependency returns normally forever, execution remains in the repeating tail. Returning after one iteration would not match the displayed control flow.
