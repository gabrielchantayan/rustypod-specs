# F-ad8749a23e45

## Purpose

F-ad8749a23e45 performs ordered dispatch over a context and an input record. It can invoke an initial conditional dependency, one of two indirectly selected dependencies, and a final conditional dependency. The first invoked dependency that returns a nonzero result determines the function’s result. If no invoked dependency returns nonzero, the function returns zero.

The dispatch decisions use record tags, record payloads, context fields, and a context-referenced dispatch table. Decisions made after a dependency returns use newly read state rather than a snapshot taken at entry.

The supplied representation establishes this control flow, but does not establish the application-level meaning of the tags, payloads, context fields, or results. Descriptions such as “handled,” “success,” and “failure” would therefore be inferred intent, not established semantics.

## Behavior

### 1. Initial conditional dispatch

The function first reads the record tag at byte offset 0x04.

If that value is not 0x0F, it skips the initial conditional dependency. This decision does not require a record-payload read or a read of the context comparison field at offset 0xB0.

If the tag is 0x0F, the function reads:

1. The record value at offset 0x08.
2. The context value at offset 0xB0.

It compares these two integer values for equality. A mismatch skips the initial conditional dependency.

A match invokes F-811b21c0e819 with the context and record arguments. If its result is nonzero, F-ad8749a23e45 immediately returns that exact result. No middle or final dispatch is then performed.

If F-811b21c0e819 returns zero, processing continues. Its return does not establish that any context or record contents remain unchanged.

### 2. Mandatory middle dispatch, unless already returned

The function reads the record tag at offset 0x04 again. This is a fresh decision input, including when F-811b21c0e819 was invoked and returned zero.

The selected dispatch-table slot depends on that tag and, conditionally, a nested discriminator:

- If the tag is not 0x16, select slot 0x110.
- If the tag is 0x16:
  1. Read the value at record offset 0x08 as an address.
  2. Read the integer discriminator at offset 0x04 from that addressed object.
  3. Select slot 0x10C if the discriminator equals 0x2A.
  4. Otherwise select slot 0x110.

The nested-object read occurs only for a tag of 0x16. There is no independent validation of the payload address before that read.

After selecting the slot, the function reads the dispatch-table address from context offset 0x00 and obtains the callable from the selected slot. It invokes that callable with the original context and record arguments.

If the callable returns nonzero, the function immediately returns the exact result. The final conditional dispatch is not evaluated.

If the callable returns zero, processing continues.

Exactly one of the two middle slots is invoked on a normally continuing execution that reaches this stage. A zero result from slot 0x10C does not cause a subsequent attempt through slot 0x110.

### 3. Final conditional dispatch

After a zero result from the middle dependency, the function reads the record tag at offset 0x04 again.

If the tag is not 0x0F, the function returns zero without reading the final comparison field or invoking the final dependency.

If the tag is 0x0F, the function reads:

1. The record value at offset 0x08.
2. The context value at offset 0x50.

It compares these values for equality. A mismatch produces a zero return.

A match causes a fresh read of the dispatch-table address from context offset 0x00, followed by resolution and invocation of the callable at table offset 0xE0. The arguments are again the original context and record.

A nonzero result is returned unchanged. A zero result leads to the function returning zero.

### Dispatch bounds and precedence

On a normally completing invocation:

- The initial dependency is called zero or one times.
- Exactly one middle dependency is called unless the initial dependency returned nonzero.
- The final dependency is called zero or one times, and only after a zero middle result.
- At most three dependency calls occur.
- Earlier nonzero results take precedence over all later decisions.

The initial and final equality checks use different context fields. Satisfying one comparison does not establish that the other is satisfied.
