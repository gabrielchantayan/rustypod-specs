## Interface

**Output on normal completion:** the same address supplied as input. There is no separate success value or explicit error result.

All offsets in this contract are relative to that input address:

- A **word slot** is a location numbered in hexadecimal, with a stride of four bytes.
- Slot `0x00` begins at byte offset `0x000`.
- Slot `0xB7` begins at byte offset `0x2DC`.
- A word write affects exactly four bytes.
- A byte write affects exactly one byte, not an entire word slot.

The direct accesses therefore require writable storage through byte offset `0x2DF`, inclusive: at least `0x2E0` bytes, or 736 bytes, from the supplied address. This is a lower bound for the visible accesses, not a complete size requirement. The dependency may require additional storage or other preconditions.

The address arithmetic is expressed in a 32-bit target context in the supplied evidence. This contract does not extend it into a portable promise about pointer truncation, address wraparound, or behavior at an address-space boundary. Valid, non-wrapping accesses are the safe precondition.

### Final-state limits

On an ordinary call with independently writable storage, post-call writes replace any values the dependency left at those locations. Pre-call writes have a different guarantee: their values are established at dependency entry, but the dependency may overwrite them.

Consequently, the visible body alone does **not** establish that every pre-call initialization value remains present at function return. A final-state assertion about those locations must either account for the dependency’s effects or explicitly assume that it does not modify them.

Likewise, a location absent from the write schedule is only **not directly written by this function**. It is not necessarily unchanged across the entire invocation.
