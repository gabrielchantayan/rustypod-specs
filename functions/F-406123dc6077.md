# F-406123dc6077

## Purpose

F-406123dc6077 positions a context-associated cursor, validates the selected record’s identity, and produces either compact output or a caller-supplied full result.

A captured 16-bit context discriminator selects between two record layouts:

- **Distinguished layout:** discriminator equals `0x482B`.
- **Other layout:** discriminator differs from `0x482B`.

Compact output consists of a 16-bit kind and a 32-bit value. Full output includes dependency-populated record data, a decoded identity, and a text-storage pointer. Text output initially targets inline storage and can trigger allocation and one retry.

The operation is not transactional. Positioning dependencies can change state before an error. After successful identity validation, the function explicitly writes the requested cursor position before processing output. Later failures do not trigger explicit rollback or release.

This contract distinguishes visible operations from inferred purpose and unresolved dependency behavior. No runtime tests have been performed.

## Interface

### Arguments and result

The supplied representation uses 32-bit addresses and a signed 32-bit return value.

| Argument | Contract |
|---|---|
| Context | Supplies the layout discriminator, an indirect operation handle, and an initialization-associated value. |
| Cursor | Mutable object containing a 16-bit position and a 32-bit identity. |
| Requested position | 32-bit input. Its low 16 bits determine movement and the explicit position write. |

## Behavior

### Capture and descriptor preparation

Before its first dependency call, the function reads the context discriminator and follows the address at context offset `0x158` to read the 32-bit operation handle. The resulting layout choice and handle are retained; neither is refreshed after dependency calls.

F-5e41885f6cfa receives the cursor and record workspace.

The function then initializes the mutable descriptor:

| Output mode | Initial buffer | Capacity argument |
|---|---|---:|
| Compact | Temporary 32-byte buffer | `0x20` |
| Full, other layout | Full result plus `0x0FC` | `0x66` |
| Full, distinguished layout | Full-result base | `0x238` |

Another descriptor field is set to one. Positioning dependencies receive the descriptor’s address and may replace its buffer pointer. Capacity units and the additional field’s meaning are unresolved.

### Optional initialization

The cursor position is read after F-5e41885f6cfa. If it is nonzero, initialization is skipped.

If it is zero:

1. F-f987e285db03 receives the cursor identity, the context value at `0x18C`, and the address of the lookup-result pointer scratch slot.
2. If the lookup returns zero, the function reads a 32-bit value through the address currently stored in that slot. Otherwise, it uses `0xFFFFFFFF`.
3. F-7cae4aaa5e45 receives the captured handle, workspace, selected lookup value, mutable descriptor, and auxiliary storage. The workspace appears in two argument positions.
4. Its signed 16-bit status is checked. A nonzero status terminates under the positioning-error rule.
5. On zero, F-e2628760344a receives the workspace and cursor.
6. F-af25767f2ba8 receives freshly read values from context offset `0x18C` and cursor offset `0x18`, together with workspace offset four.

The final call’s arguments need not equal the earlier lookup arguments: intervening dependencies may have changed the underlying objects.

Lookup failure is not itself returned. Lookup success followed by an invalid returned pointer results in an unchecked read. No initial null write to the lookup-result pointer scratch slot is visible before the lookup.

### Movement

After optional initialization, the function reads the current unsigned 16-bit cursor position again.

The movement distance is the signed 16-bit interpretation of the low 16 bits of requested position minus current position. Therefore:

- Upper requested-position bits do not affect movement.
- The effective subtraction wraps modulo 65,536.
- The distance ranges from −32,768 through 32,767.
- Initialization-dependent position changes affect the calculation.

F-15d9d014c368 receives the captured handle, a selector, workspace, mutable descriptor, and auxiliary storage.

| Distance | Calls if every status is zero |
|---|---|
| Zero | One call with selector `4`. |
| Positive | Distance-many calls with selector `1`. |
| Negative | Magnitude-many calls with selector `2`. |

For nonzero distance, preliminary calls precede one final call with the same selector. Every status is interpreted as signed 16 bits and checked before another call. The first nonzero status stops positioning.

The selectors’ meanings as “current,” “forward,” or “backward” are inferred, not established dependency contracts.

### Positioning errors

For nonzero statuses from F-7cae4aaa5e45 or F-15d9d014c368:

- Status `0x20` returns as `0x30`.
- Every other status returns as its sign-extended 16-bit value.

This translation does not apply to text-conversion statuses. No explicit undo follows a positioning failure.

### Identity validation and position commit

After successful final movement:

1. F-4055be9c3f18 receives workspace offset 30.
2. Its 32-bit result is compared with the cursor identity read after the call.
3. On mismatch, F-4eafee6a9cd5 receives the cursor, and the function returns `0x30`.
4. On match, F-e2628760344a receives the workspace and cursor.
5. The descriptor’s current buffer pointer is captured for full-result processing.
6. The requested position’s low 16 bits are written to cursor offset `0x0C`.

There is no second identity check after the export dependency. Output processing begins after the explicit position write.

### Compact output

A null full-result destination selects this path.

For the other layout:

| First 16-bit record value | Kind written | Value |
|---|---:|---|
| `0x0200` | `2` | Direct 32-bit read at buffer offset 20. |
| `0x0100` | `1` | Result of F-4055be9c3f18 applied at buffer offset six. |

The kind write precedes the value read or decoding call. The value write follows. Successful completion returns zero. This ordering matters if arguments overlap or a dependency can observe previously exposed storage.

### Common full-result initialization

For non-null full output:

1. F-4055be9c3f18 is called again on workspace offset 30.
2. Its result is written at full-result offset `0x20C`.
3. The address of inline storage at `0x214` is written into the pointer field at `0x210`.

The second decoded identity is not compared with the cursor or the earlier decode. Dependencies have run between the two decoding calls.

These writes occur before other-layout kind validation. They do not clear the flag at `0x208` or release any previously stored pointer.

### Other-layout full output

The captured record’s first 16-bit value must be `0x0100` or `0x0200`. Any other value returns `0x30`.

For a supported value:

1. F-c158f6e5f468 receives the context, captured record buffer, and full-result destination.
2. F-03ee4c791a9a receives the context, the address of workspace offset 34, capacity `0x20`, the output-count address, and the inline text address.
3. If its signed 16-bit status is not `0x3F`, that status returns directly.

On `0x3F`, the function evaluates the current output count plus one and passes that value to the allocation dependency. The returned address is written to result offset `0x210`, including when it is null.

A null result returns `-108`. This branch does not perform the flag-setting operation.

For non-null allocation, the function reads the 16-bit field at `0x208` and writes it back with bit zero set. It then calls F-03ee4c791a9a again, using:

- The workspace-quantity address again.
- Count-plus-one evaluated again from the current output count.
- The output-count address again.
- The retained allocation-return address as destination.

The final signed 16-bit status returns directly. No additional retry occurs.

The allocation request and retry capacity are separate evaluations. The allocation dependency is not established to preserve the previously exposed count. Neither conversion is guaranteed to observe the original workspace quantity.

### Distinguished-layout full output

Immediately before the initial F-8a6756c94146 call, the function explicitly writes a 32-bit null pointer into the **lookup-result pointer scratch slot**.

This is the same slot whose address was passed to F-f987e285db03 if initialization ran. The clear occurs even when initialization was skipped. It does not clear the full-result pointer field at `0x210`, which was explicitly assigned the inline-storage address during common full-result initialization.

F-8a6756c94146 then receives:

- Workspace source address at offset 36.
- Twice a fresh unsigned 16-bit read from workspace offset 34.
- Inline text storage.
- The output-count address.
- Capacity `0x20`.
- Selector `0x3A`.

If its signed 16-bit status is not `0x3F`, that status returns directly. The first scratch-slot clear has already occurred.

On `0x3F`, F-54585861452f receives the source address, twice another unsigned 16-bit read from workspace offset 34, selector `0x3A`, and zero. Its 32-bit result replaces the output count.

The function evaluates the resulting count plus one for allocation. It writes the returned address into result offset `0x210`. Null returns `-108`, before flag setting and before the second scratch-slot clear.

After non-null allocation:

1. The 16-bit result field at `0x208` is read and rewritten with bit zero set.
2. The function explicitly writes a 32-bit null pointer into the same lookup-result pointer scratch slot again.
3. Immediately following that clear, the final F-8a6756c94146 call receives the source address, twice a fresh unsigned 16-bit quantity read, the retained allocation-return address, the output-count address, freshly evaluated count-plus-one, and selector `0x3A`.

The final signed 16-bit status returns directly.

Thus the two scratch-slot clears are separate ordered writes: one before initial conversion, and one after successful allocation and flag setting, before retry conversion. A dependency that retained the lookup-output address could observe them during the invocation. The second write remains explicit even if the slot already contains null.

There are three independent quantity reads on the retry path. Each doubled length lies between zero and 131,070 in the represented 32-bit arithmetic. The lengths need not agree. Allocation size and retry capacity also need not agree absent an external preservation guarantee.

## Side effects

Established explicit effects include:

- Exposing workspace, cursor, descriptor, auxiliary storage, output count, and result storage to dependencies.
- Exposing the lookup-result pointer scratch address during initialization.
- Cursor export calls and the mismatch-related cursor call.
- Writing the requested 16-bit cursor position before output completion.
- Compact kind and value writes.
- Full-result identity and pointer writes.
- Replacing the full-result pointer with an allocation result, including null.
- Setting result flag bit zero after non-null allocation.
- Clearing the lookup-result pointer scratch slot before distinguished initial conversion and again before distinguished retry conversion after successful allocation and flag setting.

The scratch clears neither free a lookup result nor clear the full-result pointer field. No ownership transfer follows merely from writing null to that temporary slot.

No explicit operation clears the allocation flag before use, releases an old result pointer, releases a new allocation after conversion failure, restores earlier state, or verifies allocation extent against retry capacity.

The final conversion receives the retained allocation-return address, not a reread of the result pointer field. Dependencies may nevertheless mutate exposed storage or affect ownership. Consequently, the function’s last explicit pointer and flag writes do not guarantee their final values.

Temporary addresses are valid only for the invocation’s storage lifetime. Whether dependencies retain them, and whether such retention is valid beyond return, is unresolved.

## Acceptance examples

These are conditional static consequences, not executed tests.

1. **Zero distance:** If the movement-time position equals the requested low 16 bits, one selector-`4` call occurs. Successful positioning still requires identity validation.

2. **Wrapped movement:** Position `0xFFFF` and requested low bits zero produce distance positive one. Position zero and requested low bits `0x8000` produce 32,768 selector-`2` calls if all succeed.

3. **Positioning error:** Status `0x20` from positioning returns `0x30` without reaching identity validation or the explicit position commit. Prior dependency effects remain possible.

4. **Identity mismatch:** Unequal decoded and current cursor identities cause F-4eafee6a9cd5 and return `0x30`, without the explicit requested-position write.

5. **Compact other-layout record:** Kind `0x0200`, successful positioning, and matching identity produce kind `2`, the value from record offset 20, and return zero.

6. **Unsupported full record:** An unsupported other-layout kind returns `0x30` after the explicit position, result-identity, and inline-pointer writes.

7. **First scratch clear:** On distinguished full output, initial conversion observes a preceding null write to the lookup-result pointer scratch slot. If lookup previously exposed that slot’s address, retained-address observation can detect the clear. The clear itself does not change result offset `0x210`.

8. **Allocation failure:** After status `0x3F`, null allocation is written into the result pointer field and returns `-108`. On the distinguished path, the first scratch clear occurred, but the second is not reached.

9. **Second scratch clear:** Distinguished retry with non-null allocation explicitly writes the allocation pointer, sets flag bit zero, clears the lookup-result pointer scratch slot again, and calls final conversion. The second clear does not replace the allocation destination or clear the result pointer field.

10. **Changing quantities and counts:** Distinguished quantity readings of 5, 7, and 9 produce length arguments 10, 14, and 18. A count of 12 at allocation requests 13; if the count becomes 20 before retry-capacity evaluation, retry capacity is 21. No consistency check repairs either difference.

11. **Conversion failure:** A final conversion error returns directly without explicit release or rollback. Conversion status `0x20` remains `0x20`, rather than becoming `0x30`.
