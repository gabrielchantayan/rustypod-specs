# F-077fd7994521

## Purpose

F-077fd7994521 dispatches category `0x16` inputs against a mutable context containing two object slots. It handles event codes `0x202`, `0x204`, `0x205`, `0x206`, and `0x207`; it declines `0x203` and every other event code.

Established behavior includes setting a flag, selecting objects by identifier, invoking dependencies, clearing slots and object fields, and reporting whether either object matches a payload. Four handled events use common entry and completion calls. The remaining handled event reports a match result without those calls.

“Event,” “object,” “identifier,” and “cleanup” describe visible usage, not established domain types or ownership guarantees. Event-driven object management is inferred intent. Locking, destruction, reference counting, and resource ownership are not established.

## Behavior

### Category filtering and event acquisition

The category read occurs first. A category other than `0x16` returns `0` without a visible context access or dependency call.

For category `0x16`, the function invokes the indirect input operation at dispatch offset `0x14` with the input and `0xF00`. It then obtains the event address from the returned structure’s `+0x08` field and reads the event code.

Event `0x203` and unrecognized codes return `0` after this acquisition. They do not invoke either context-bracketing dependency.

### Common entry and completion

Events `0x202`, `0x204`, `0x205`, and `0x207` invoke F-338d16f9ce72 with context `+0x38` before examining their relevant slots or payload comparisons.

Their ordinary completion invokes F-1333331b2da1 with context `+0x38`, then returns `1`. Empty slots, failed identifier comparisons, and retained objects can all reach this completion.

The calls suggest bracketing, but no locking semantics are established. Completion is not guaranteed if an intervening operation fails to return or invalid memory is accessed.

### Event `0x202`: mark A

A zero A slot after entry produces ordinary completion without a decision call.

For nonzero A, F-0cde56e61f4c supplies a zero/nonzero decision. A nonzero result produces ordinary completion without a direct flag write.

For a zero result, the function uses the then-current A slot to update the object’s 32-bit flags by setting mask `0x200` while retaining the other bits. It subsequently obtains the identifier through the then-current A object’s associated-record address and passes that identifier to F-5c33d20156b2.

A is re-read after the decision dependency; the earlier nonzero test does not freeze the selected object or ensure that the later address remains nonzero. The identifier access likewise uses the slot’s subsequently observed value. The associated-record address has no null guard.

### Event `0x204`: process or remove B

A zero B slot after entry produces ordinary completion. Otherwise, F-0cde56e61f4c supplies the branch decision.

**Zero decision.** F-70f203df26ce receives, in argument positions:

- Context.
- Then-current B object.
- That object’s word at `+0x08`.
- `1`.
- `0`.

After the call, B is read again and captured. Its associated-record field at `+0x1C` is read without a preceding null check on the captured address.

If this field is nonzero, the function completes without directly clearing B or invoking its object operation.

If the field is zero, the function clears context B first. It then reads the captured object’s flags. Mask `0x100` causes a call to F-b8a325ddd21b with no explicit argument established at this call site. After that conditional call, a nonzero captured object address causes its indirect object operation to be invoked with that address explicitly supplied. Ordinary completion follows.

The captured object remains the target even if a dependency changes B. Clearing B inside F-70f203df26ce does not create a safe empty-slot outcome: the subsequently captured address is dereferenced before the later nonzero check.

**Nonzero decision.** The function re-examines B and, if nonzero, invokes its indirect object operation. No explicit argument is shown for this invocation. After the operation returns, B is cleared, F-b8a325ddd21b receives context `+0x60`, and ordinary completion follows.

The post-operation clear overwrites any replacement B value installed by that operation.

### Event `0x205`: process or remove A

A zero A slot after entry produces ordinary completion. Otherwise, F-0cde56e61f4c supplies the decision.

A zero decision invokes F-62a009f696fe with the context, followed by ordinary completion. Any object processing or slot changes in that dependency are outside this caller’s established behavior.

A nonzero decision causes the function to re-examine A and invoke its indirect object operation if nonzero. No explicit argument is shown. After that invocation returns, A is cleared, F-b8a325ddd21b receives context `+0x4C`, and ordinary completion follows.

As with B’s corresponding path, a replacement A installed by the indirect operation is overwritten by the subsequent clear.

### Event `0x206`: report whether either object matches

This event invokes neither context-bracketing dependency.

The function first captures the dereferenced 32-bit payload. It examines A before B:

- A nonzero A slot causes F-9aba3d980fa9 to receive A and the captured payload.
- A nonzero match result selects outcome `1` and skips B.
- Otherwise, B is examined. A nonzero B slot causes the same dependency to receive B and the captured payload.
- If neither invoked match operation returns nonzero, the outcome is `0`.

F-1099b027807c receives the captured payload and normalized outcome, after which the function returns `1`.

B is read only when needed and after any A match call. Changes made by that call can therefore affect which B is examined. The reporting payload remains the captured value even if payload storage changes during matching.

### Event `0x207`: select by identifier and remove

After entry, the function considers A first. A matches only when its slot is nonzero and its associated-record identifier equals the dereferenced event payload. The associated-record address is not checked for zero.

If A is zero, its identifier comparison and corresponding payload read are skipped. If A does not match, B is captured and considered. A zero B ends processing normally; otherwise B’s associated-record identifier is compared with a freshly read payload value. The two comparisons do not share a guaranteed payload snapshot. The relative evaluation order of the identifier and payload reads within an individual comparison is not established.

**Matching B.** The function invokes the captured B object’s indirect operation, with no explicit argument shown. It then clears B, calls F-b8a325ddd21b with context `+0x60`, and completes normally. F-0cde56e61f4c is not called on this selection path.

**Matching A.** B is not considered. F-0cde56e61f4c is called, and the current A slot is captured after that call.

For a nonzero decision, the captured object’s indirect operation is invoked if its address is nonzero; no explicit argument is shown. A is then cleared, F-b8a325ddd21b receives context `+0x4C`, and ordinary completion follows.

- A is captured again, and context A is cleared.
- After that slot clear, the arguments for F-d7901cd15a43 include reads of the captured object’s words at `+0x08` and `+0x0C`, and a read of the stored static/global value.

Earlier unknown calls must not be assumed to preserve that storage. No relative evaluation order is established among this global read and the two object-field argument reads.

The object-field reads for F-d7901cd15a43 occur before the later captured-address check. That check does not make argument acquisition null-safe.

## Acceptance examples

These are conditional static criteria, not executed tests. Accessed memory must be valid, and dependencies must return and preserve relevant state unless a scenario says otherwise.

1. **Rejected category.** A category other than `0x16` returns `0` without event acquisition or a context access.

2. **Declined event.** Category `0x16` resolving to `0x203` performs acquisition, returns `0`, and does not enter the context bracket.

3. **Flag preservation.** For `0x202`, unchanged A, a zero decision, and initial flags `0x100`, the caller writes `0x300`. F-5c33d20156b2 receives the associated identifier.

4. **Empty B.** For `0x204`, B zero after entry skips the decision and object operations, then completes with `1`.

5. **Retained B.** For `0x204`, a zero decision and a nonzero associated-record field on the post-processing B object produce no direct B clear or object invocation.

6. **Short-circuit match.** For `0x206`, a nonzero A match result prevents B examination. Reporting receives the captured payload and `1`; the function returns `1`.

7. **No objects.** For `0x206`, both slots zero produce reporting with payload and `0`, while the function still returns `1`.

8. **B removal ordering.** For `0x207`, A not matching and B matching causes B’s operation before the B clear, then cleanup with context `+0x60`, then completion.

9. **A precedence.** If both identifiers would match during `0x207`, selecting A prevents a B comparison and B removal.

10. **Nonreturning auxiliary path.** Matching A, a zero decision, and a nonzero auxiliary word cause that word to be cleared before F-8ad439e5daa6 and F-feee9156a257. Ordinary completion is not established.

11. **Late static/global value.** On the continuing zero-auxiliary A-removal path, suppose an earlier dependency changes the relevant static/global storage from value X to value Y, with no later change before argument acquisition. F-d7901cd15a43 receives Y as its third argument. The read occurs after A is cleared; no ordering relative to the two object-field argument reads is required.

12. **Replacement overwritten.** On `0x205`’s nonzero-decision path, an indirect operation that installs a replacement A does not preserve that replacement: the caller clears A after the operation returns.
