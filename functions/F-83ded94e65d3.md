## Behavior

### Indirect invocation phase

The initial phase is a long straight-line chain of indirect invocations. The first target depends on incoming execution context. Later targets are represented using address-like values and a fixed displacement of 0xFFE.

No explicit loop or conditional branch governs this phase in the supplied representation. Dependencies may nevertheless branch, block, fail, mutate memory, or not return.

The chain exchanges:

- Individual 32-bit results.
- Low and high halves of paired 64-bit results.
- Secondary call-produced values with incomplete provenance.
- Literal zero arguments.
- Shifted, masked, and retained earlier values.

Some arguments duplicate the same transformed value. Others reuse a result across many intervening invocations. Neither duplicated arguments nor ignored results justify removing an invocation.

The final result-producing invocation supplies a paired value used immediately in the direct-memory phase.

### Arithmetic boundaries

Explicit masks establish bounded intermediate values. Represented masks include widths of 24, 22, 21, 20, 19, 18, 17, 16, 15, 14, 13, 12, and 11 bits, together with a one-bit mask.

Examples of established extraction bounds include:

- A 24-bit masked value: 0 through 16,777,215.
- A 22-bit masked value: 0 through 4,194,303.
- A 19-bit masked value: 0 through 524,287.
- A 13-bit masked value: 0 through 8,191.
- A 20-bit masked value subsequently shifted right by ten: 0 through 1,023.
- An 18-bit masked value subsequently shifted right by eleven: 0 through 127.

These bounds apply at the stated extraction point, not automatically after subsequent left shifts.

Explicit unsigned right shifts discard low bits and insert zeros. Some 64-bit results are shifted by more than 32 bits before narrowing; those operations must not be confused with oversized shifts of a 32-bit value.

Under a 32-bit modular machine-value interpretation, left shifts and multiplication discard bits above bit 31. Two successive left shifts by 28 therefore produce zero, rather than retaining an unbounded 56-bit intermediate.

Some represented operations have signed-looking operands. Authoritative overflow behavior, address wraparound, and the late variable right-shift semantics remain **documented_only** where target-level evidence is absent.

A field read after being cleared is not unconditionally specified to return zero. Intervening accesses may alias it, and the representation does not establish ordinary, unobserved storage.

### Early fixed-address ordering

The function reads a byte at absolute address **0x05** before writing a byte at absolute address **0x01**. The read byte is widened and retained as an address component. The write to 0x01 carries the low byte of a doubled small index.

This is an ordered read/write dependency, not an entry-time snapshot of fixed storage. Earlier indirect dependencies and earlier derived-address writes may already have changed 0x05.

The widened byte then participates in accesses at offsets 0x15 and 0x54. A word at that byte-derived base plus 0x54 is retained before the field is overwritten. Call this retained value the **saved link word**; the name describes provenance, not an object type.

Later in the same direct-memory phase:

- A derived word field at offset 0x14 receives another result-derived value.
- Absolute address **0x54** receives a **32-bit store** of the saved link word shifted left by one.
- The derived offset-0x14 field subsequently receives the saved link word twice.
- Two derived byte stores at offset 0x15 follow.
- Absolute address **0x15** receives an **8-bit store** of the low byte of the doubled small index.

The fixed word write at 0x54 precedes the fixed byte write at 0x15. Neither is merely a field-offset description.

2. A 16-bit store to that value scaled by eight.

These are three address expressions, not three proven-distinct destinations. Effective addresses may alias or overlap.

Another derived destination receives ordered word stores of **0x20**, **0x2F**, a zero-extended byte read from the corresponding base plus 0x04, and **0x20** again. The byte read occurs after the first two stores.

After this series, the function reads a stored address. Absolute address **0x60** then receives a **32-bit store of 0x20**, before the repeated-write region begins. Thus the named fixed writes occur in the order: word at 0x54, byte at 0x15, word at 0x60, with substantial derived-memory activity between them.

## Acceptance examples

These are conditional static examples, not executed tests.

### Widening

If a represented byte load returns 0xE2, its word-sized forwarding store contains 226. Sign extension violates the represented conversion.

### Intermediate width

Under 32-bit modular machine arithmetic, successive left shifts by 28 produce zero. Retaining a wider intermediate changes the behavior.

### Fixed-address chronology

If execution reaches the relevant accesses, the byte read at 0x05 precedes the byte write at 0x01. The fixed word write at 0x54 precedes the fixed byte write at 0x15, which precedes the fixed word write of 0x20 at 0x60.

### Aliasing constant destinations

If the address expressions for the three 0x3A stores overlap, acceptance depends on preserving their byte, halfword, then word order. Requiring separate allocations or distinct destinations adds an unsupported precondition.

### Repeated-group expressions

If the initial and later publication expressions evaluate to equal values, that equality does not violate the contract. Their different expressions do not require different runtime values.

### Fresh reads at 0x67

Suppose an intervening derived write changes 0x67 after its value is copied to 0x21. The next derived offset-0x09 store must use the subsequent read of 0x67, not the previously copied byte. The same requirement applies between the two later reads.

### Late retained word

If the 0xA9 word read yields 0x123456E2, the explicit byte subsequently written to 0x67 is 0xE2. Later reads of 0x67 equal 0xE2 only if intervening effects leave that byte unchanged.

### Overlapping field widths

A late word store at offset 0x10 covers four bytes beginning there, including the destination of the preceding byte store. Those accesses cannot be treated as permanently independent fields.

### Failure and continuation

An invalid derived destination does not require a structured error or normal return. If execution reaches the final invocation, its first represented argument is 0x72; return remains conditional on that target.
