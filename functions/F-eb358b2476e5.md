## Behavior

### Preconditions and address validity

No argument validation, bounds checking, null checking, alignment checking, allocation, or error reporting is visible.

Successful execution requires all effective addresses actually encountered to support the indicated access widths. This includes addresses obtained from later memory reads, not merely the explicit inputs and three implicit bases.

### Repeated initialization-like prefix

The prefix writes the input word to the four-byte location at initial base plus `0x54`.

It then establishes two recurring byte values:

- The low byte of base A.
- The low byte of base B.

The recurring destination group consists of:

| Destination | Width | Stored value |
|---|---:|---|
| Base B plus `0x19` | 1 byte | Low byte of base A |
| Base A plus `0x11` | 1 byte | Low byte of base B |
| Base B plus `0x34` | 4 bytes | Initially the initial base; in subsequent groups, twice base A |

Each later group is preceded by a four-byte write of the input word to twice base A plus `0x54`. Within each group, the byte at base B plus `0x19` is written before the byte at base A plus `0x11`, which is written before the four-byte field at base B plus `0x34`.

These are repeated accesses to the same computed destinations, not evidence of an iteration over advancing elements. The stores remain distinct ordered events. Their effects may differ if addresses overlap or refer to access-sensitive storage.

The exact numeric repetition count is **documented_only** in this contract; it must not be replaced by a claim that one execution of the destination group is behaviorally equivalent to the supplied repeated prefix.

For base A, multiplication by two is unsigned 32-bit arithmetic. The resulting value is reduced modulo \(2^{32}\). Unsigned addition of `0x54` is likewise reduced modulo \(2^{32}\) before interpreting the result as an address.

### Fixed-address snapshot and initial field updates

After the repeated prefix, the function captures:

1. A four-byte value from fixed address `0xA9`.
2. A four-byte value from input word plus `0x74`.

It next writes one byte at fixed address `0x3A`. This byte is the low eight bits of twice the low byte of base A plus `0x30`. Although the evidence passes through a character value, signed versus unsigned character interpretation does not change these final eight bits.

The function then captures:

- Four bytes from base C plus `0x14`.
- Four bytes from base A plus `0x04`.

Those captured values are used later, rather than being reloaded from their original locations at the point of use.

The subsequent ordered mutations are:

- Base C plus `0x0D` receives the low byte of base A.
- Base A plus `0x08` receives `0x6C`.
- Base A plus `0x0D`, then base A plus `0x09`, receive the low byte of base B.
- Base C plus `0x54` receives the complete base C value.
- Fixed address `0x67` receives the low byte of the earlier snapshot from `0xA9`.

The fixed-address read occurs after the repeated prefix. If the prefix overlaps `0xA9`, the captured word reflects the preceding writes, not necessarily function-entry memory.

### Field exchange and overlapping writes

A four-byte value is read from base C plus `0x44`; call this the **shift-source word**.

Next, the current byte at fixed address `0x67` is copied to fixed address `0x21`. This is a memory read of `0x67`, not an unconditional use of the earlier snapshot’s low byte.

The low byte of the shift-source word is written at base A plus `0x10`. Its complete word is then written at base B plus `0x54`.

A byte derived by right-shifting the shift-source word is written at base C plus `0x01`. The requested shift count is the low eight bits of base A. The shift-source word is represented as signed. Negative operands and counts outside the conventional 0–31 range require target-specific interpretation; this contract does not assign a portable result to those cases.

Base B plus `0x54` is then overwritten with the complete base A value.

The following transfers occur in order:

- Capture four bytes from base A plus `0x40`.
- Write the earlier snapshot from base A plus `0x04` to base B plus `0x74`.
- Write the newly captured word to base A plus `0x10`.
- Write base C to base B plus `0x44`.
- Read the current byte at `0x67` and write it at base A plus `0x09`.
- Write the low byte of base A at base C plus `0x09`.
- Write the original four-byte snapshot from `0xA9` to base A plus `0x44`.

The four-byte write at base A plus `0x10` covers offsets `0x10` through `0x13`. It therefore overlaps both the preceding byte write at offset `0x10` and the prefix’s byte write at offset `0x11`.

### Dynamically selected destinations

The function reads a four-byte address value from base A plus `0x54`; call this the **selected base**.

After that read:

- The current byte at `0x67` is again read and written to base A plus `0x09`.
- Selected base plus `0x0D` receives the low byte of the earlier input-word-plus-`0x74` snapshot.
- Base C plus `0x54` receives the earlier snapshot from base C plus `0x14`.
- A four-byte value is captured from base A plus `0x14`.
- Base C plus `0x11` receives the low byte of the input-word-plus-`0x74` snapshot.
- Base A plus `0x09` receives the low byte of selected base.
- Base A plus `0x44` receives selected base.

The last operation replaces the earlier word copied from fixed address `0xA9`, unless aliasing changes the relevant relationship.

The captured value from base C plus `0x14` remains significant even if its original location has since changed: that snapshot supplies both the write at base C plus `0x54` and the third indirect-call argument.

### Final pointer-derived writes and invocation

A four-byte value is read from base C plus `0x04`; call this the **secondary base**.

The final memory activity has the following ordering constraints:

1. A two-byte value `0x0065` is written at twice secondary base.
2. A four-byte value is read from secondary base plus `0x64`; call it the **transfer word**.
3. Selected base plus `0x11` receives the low byte of the snapshot from base A plus `0x14`.
4. Selected base plus `0x54` receives the four-byte value `100`, equivalent to `0x00000064`.
5. Four bytes are captured from secondary base plus `0x74`.
6. A four-byte address value is read from base C plus `0x64`; call it the **final base**.
7. Base C plus `0x09` receives the low byte of secondary base.
8. Final base plus `0x54` receives the transfer word.

The indirect dependency is then invoked with:

| Argument position | Value |
|---|---|

| Third | Earlier four-byte snapshot from base C plus `0x14` |

## Acceptance examples

These examples are conditional static expectations, not executed tests.

### Low-byte arithmetic

If the low byte of base A is `0x90`, and the write to `0x3A` is reached, that write stores `0x50`: the low eight bits of `2 × 0x90 + 0x30`.

This does not establish that the byte remains `0x50` after later potentially overlapping writes or D-01.

### Snapshot versus reread

Suppose the word at base C plus `0x14` is `0x12345678` when captured, and a later operation changes that location. Provided execution reaches D-01 without changing the captured execution value, the third argument remains `0x12345678`; it is not a fresh read of that location.

### Overlapping byte and word fields

If base A’s fields are ordinary writable memory and no other destination aliases them, the four-byte write at offset `0x10` replaces the earlier byte at offset `0x10` and the earlier byte at offset `0x11`. The resulting bytes depend on target byte order.

### Defined shift example

If the shift-source word is positive `0x00000100` and the low byte of base A is `8`, the shift-derived byte written at base C plus `0x01` is `0x01`.

A count of `32` has no established portable expected value in this contract.

### Final invocation

If the transfer word is `0x00001000`, the saved base-C-plus-`0x14` word is `0x22334455`, and the secondary-base-plus-`0x74` snapshot is `0x66778899`, D-01 receives those values after first argument `0x72`, provided all preceding operations succeed.

Before that invocation, final base is written as a four-byte value at address `0x00002000`. This example assumes the doubled signed value is representable and the address is writable.
