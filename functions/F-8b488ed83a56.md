# F-8b488ed83a56

## Purpose

F-8b488ed83a56 selects one of three outcomes after invoking a lookup-like dependency:

- Report an unsuccessful lookup and return a zero-valued 32-bit result.
- Invoke a no-argument handler when a field in the returned object falls within a particular numeric interval.
- Otherwise, invoke a two-argument handler using the original first input and the potentially updated second input.

The numeric interval is **50 through 149 inclusive**. Selection depends on a 32-bit field at byte offset 20 from the nonzero lookup result.

These are established control-flow properties. “Lookup,” “object,” and “handler” describe their structural roles, not established application semantics. The available evidence does not identify the application meaning of the inputs, the field, or either handler.

## Interface

### Inputs

The function accepts two 32-bit values.

| Input | Established treatment |
|---|---|
| First input | Retained for possible use as the first argument to F-0c0339d89def. Its interpretation is not established. |
| Second input | Copied into a writable 32-bit local cell. The address of that cell is passed to F-a5c9f72dee73. The cell’s post-call contents may later become the second argument to F-0c0339d89def. |

Neither input is established to be a pointer, signed integer, handle, or enumeration. Their behavioral contract is therefore expressed in terms of 32-bit values rather than a guessed semantic type.

The caller does not directly supply the writable cell used for the second input. Updating that cell does not, by itself, update a caller-owned argument variable. If the input value designates some external resource, effects on that resource depend on the dependencies and remain unknown.

### Result

The function returns a 32-bit value:

- Exactly zero after the unsuccessful-lookup reporting call returns normally.
- The result of F-264b01a51544 on the in-range branch.
- The result of F-0c0339d89def on the out-of-range branch.

No conversion, masking, or independent interpretation of either handler’s result is visible.

### Temporary storage

The function provides F-a5c9f72dee73 with:

1. The address of the writable 32-bit cell initialized from the second input.
2. The address of a separate 36-byte local storage region.

The 36-byte region is not explicitly initialized before that call. Its internal layout, required initial contents, and read/write protocol are unknown. Calling it temporary storage does not establish that the dependency only writes to it.

Both regions have local invocation lifetime. Their addresses are not returned directly by this function. Whether the dependency retains either address is unknown; any use after the regions’ lifetime would require guarantees not supplied by this evidence.

## Behavior

### Initial dependency interaction

F-a5c9f72dee73 is invoked before any branch-specific dependency. It receives the two addresses described above, not the first input as an explicit argument.

Its result is used as a zero-or-nonzero discriminator. A nonzero result is also treated as the base address for a subsequent field read. There is no visible validation of alignment, accessible extent, object identity, or ownership.

The writable second-input cell must be treated as potentially changed by this call. Later behavior does not assume that its initial value was preserved.

### Zero lookup result

If F-a5c9f72dee73 returns zero:

- No field is read through the returned value.
- F-4fc89ec41a6d is invoked with five argument values, in this order: **13, 175, 173, 0, 0**.
- If that call returns normally, F-8b488ed83a56 returns the 32-bit value zero.

The reporting dependency’s return value is not used to determine this function’s result.

Changes to the writable second-input cell do not alter this branch selection or its normal return value. Such changes could still matter through dependency-internal effects, which are not established here.

Neither F-264b01a51544 nor F-0c0339d89def is directly invoked on this branch.

### Nonzero lookup result and field layout

If F-a5c9f72dee73 returns nonzero, the function reads a four-byte field at **byte offset 20**, equivalently hexadecimal offset **0x14**, from the address represented by that result.

The established layout is limited to:

| Location relative to returned base | Interpretation used here |
|---|---|
| Bytes 0–19 | No direct read by this function is shown. |
| Bytes 20–23 | One 32-bit field used for dispatch. |
| Later bytes | No direct read by this function is shown. |

This does not establish a complete object size or structure. It establishes only the offset and width of the accessed field.

For an ordinary valid memory access, the address calculation must identify four readable bytes at that offset. A nonzero result alone does not satisfy that requirement. Fault behavior for an invalid address is not handled locally.

### Range decision and arithmetic width

The range decision uses 32-bit unsigned arithmetic. The field’s 32-bit bit pattern is reduced by 50 modulo \(2^{32}\), and the resulting unsigned value is compared with 100 using a strict less-than comparison.

Consequently, the in-range branch is selected exactly when the field’s unsigned value is between **50 and 149 inclusive**.

Important consequences:

- 50 is included.
- 149 is included.
- 49 and 150 are excluded.
- Zero is excluded.
- Values with the high bit set are excluded.
- A field bit pattern that might be interpreted elsewhere as a negative signed integer is not accepted merely because it is numerically below 150 under a signed interpretation.
- Subtraction below 50 wraps in the unsigned arithmetic domain; it does not make those values pass the comparison.

The use of a signed-looking field access does not turn this into a signed range test. The unsigned subtraction and comparison govern the decision.

### In-range branch

For field values 50 through 149 inclusive, F-264b01a51544 is invoked without explicit arguments.

If it returns normally, its 32-bit result becomes this function’s result. The first input, updated second-input cell, returned base address, and field value are not passed as explicit arguments on this branch.

That absence of explicit arguments does not establish absence of shared state. The dependency may use globals or other execution context; its behavior is unknown.

### Out-of-range branch

For every other 32-bit field value, F-0c0339d89def is invoked with:

1. The original first input.
2. The contents of the writable second-input cell after F-a5c9f72dee73 returns.

If F-0c0339d89def returns normally, its 32-bit result becomes this function’s result.

The second argument is not necessarily the original second input. Forwarding the original value unconditionally would change the established behavior whenever F-a5c9f72dee73 updates the cell.
