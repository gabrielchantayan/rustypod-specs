# F-244747dcf861

## Purpose

F-244747dcf861 derives a 32-bit result from a position-like input and a mutable state record. Depending on comparisons with the record’s origin and span, it:

- Rejects certain positions preceding the origin by writing a zero result.
- Adjusts other preceding positions using an external rollover value.
- Evaluates a position through F-a04224da5d98.
- Processes a reached span through F-d7be9cfb4000 when the mode is nonzero.
- Writes terminal state, notifies F-03b9616af95f, and optionally invokes a callback when the mode is zero.
- Reflects an evaluated result when the mode subsequently read from the record exceeds two.

“Position,” “origin,” “span,” “mode,” “rollover,” and “terminal” are descriptive labels. Their application-level meanings and units are not established. The behavioral requirements below describe the supplied static evidence, not observed runtime execution.

## Behavior

### Arithmetic and comparison rules

Position, retained origin, retained span, mode, and the crossing result participate in unsigned 32-bit arithmetic and comparisons unless stated otherwise. Unsigned additions, subtractions, and multiplications retain the low 32 bits.

In particular:

- Origin plus span can wrap before the rollover comparison.
- Rollover adjustment can wrap.
- Crossing-result times span can wrap.
- The origin update and remaining-position subtraction can wrap.
- Multiplication by 65 produces a low-32-bit value for the evaluation temporary.

The rollover half-threshold is different: the rollover value is interpreted as signed 32-bit, shifted right by one, and assigned to an unsigned 32-bit quantity. With the high bit clear, this gives division by two rounded down. Behavior for negative signed values depends on the signed-right-shift interpretation; arithmetic sign extension is not independently established by runtime evidence.

The final reflection is represented as signed 32-bit subtraction from 65,536. Its value is unambiguous when that subtraction is representable. Signed-overflow behavior remains unresolved.

### Origin handling and rejection

The function first reads and retains the origin.

When the position is at least the retained origin, it subtracts the origin from the position. If crossing processing is later reached, its third argument will be the auxiliary input.

When the position is below the retained origin, acceptance requires both of the following:

- The unsigned 32-bit sum of the retained origin and a span read is greater than the rollover value read for that comparison.
- The unsigned half-threshold derived from a subsequent rollover read is greater than the original position.

The checks are ordered and short-circuited. If the first condition fails, the second check is not reached. Failure of either condition writes zero to the result and returns.

A rejected execution invokes no dependency or callback. Its only explicit record write is the zero result.

If both checks succeed, the position becomes the low 32 bits of the original position minus the retained origin plus the rollover value read for adjustment. On this accepted preceding-origin path, the half-threshold—not the auxiliary input—becomes the third crossing argument if crossing processing is subsequently reached.

The span read during this acceptance check is not the span read used by the next stage. The rollover reads likewise need not observe the same value if external storage changes.

### Span comparison

After origin handling, the function reads and retains the span. It compares the adjusted position with this span.

- Strictly below the span: proceed directly to evaluation.
- Equal to or greater than the span: read and retain the mode, then select terminal or crossing processing.

Direct in-span processing does not read the mode before evaluation. Equality is a reached-span condition.

**Zero-span qualification:** if execution reaches this comparison and the span read there is zero, no unsigned adjusted position can be strictly below it. Execution therefore proceeds to mode-zero terminal handling or nonzero-mode crossing handling. A zero span does not bypass preceding-origin rejection.

### Reached span with mode zero

When the retained mode is zero, the observable sequence is:

1. Write 65,536 to the result.
2. Write the byte value one to the terminal flag.
3. Obtain the notification argument through the external pointer and call F-03b9616af95f with that value followed by the state address.
4. After that call returns normally, read the callback-object address.
5. If it is nonzero, invoke the callback selected through that object’s dispatch structure, passing the object address and the record’s callback argument.
6. After a normally returning callback, clear the callback-object address to zero.
7. Return.

The callback selection requires the object’s first word to identify a dispatch structure whose first callable slot supplies the target. Validity of the object, dispatch structure, and target is a precondition of successful callback execution.

The callback-object address and callback argument are read after F-03b9616af95f returns. That dependency can therefore affect callback selection and the argument supplied. The exact relative order of dispatch-data reads and the callback-argument read is not established.

The result and flag writes are not repeated after external execution. They need not retain their written values at function return if the dependency or callback modifies them.

If the callback replaces the record’s callback-object address and then returns normally, the replacement is still cleared. If it does not return normally, the subsequent clear is not reached. A zero callback-object address skips both invocation and clearing.

Neither F-d7be9cfb4000 nor F-a04224da5d98 is called on this terminal path.

### Reached span with nonzero mode

For a nonzero retained mode, F-d7be9cfb4000 receives these five arguments in order:

1. Adjusted position.
2. Retained span from the span comparison.
3. Auxiliary input on the ordinary-origin path, or half-threshold on the accepted preceding-origin path.
4. Context input.
5. Auxiliary input.

Its return is treated as an unsigned 32-bit crossing quantity. No validation establishes that it is a quotient, bounded count, or suitable reduction factor.

Only retained modes two and four are eligible for a direct mode change:

- An odd crossing quantity changes retained mode two to four.
- An odd crossing quantity changes retained mode four to two.
- An even crossing quantity causes no mode write.
- Other retained nonzero modes cause no mode write, regardless of parity.

The written value is derived from the mode retained before the dependency call. Thus, a qualifying odd result overwrites any mode mutation made by that dependency. Otherwise, this function does not restore or rewrite the mode.

Next, the function writes the origin as the retained original origin plus the low-32-bit product of crossing quantity and retained span. It subtracts the same product from the adjusted position and proceeds to evaluation.

These calculations use retained values, not origin or span values reloaded after the dependency. Dependency mutations of those record fields do not change the arithmetic operands. The explicit origin write can overwrite a dependency’s origin mutation.

There is no second span comparison and no crossing loop. Even a zero crossing quantity or a remaining position still at least as large as the span proceeds directly to evaluation.

### Evaluation and reflection

Evaluation is reached either directly from the span comparison or after nonzero-mode crossing processing.

The function places the low 32 bits of remaining position multiplied by 65 into a local four-byte temporary. It calls F-a04224da5d98 with:

1. The address of that temporary.
2. The 32-bit evaluation argument read from the record.

The dependency’s four-byte return value is then written to the result.

After that write, the function reads the current mode from the record. This is a fresh read, not necessarily the mode retained for crossing selection.

- If the unsigned mode is at most two, no further direct result write occurs.
- If it exceeds two, the function reads the stored result and replaces it with the signed subtraction of that value from 65,536, subject to the overflow uncertainty above.

Consequently, a crossing-mode update or an evaluation dependency’s mode mutation can determine whether reflection occurs. No evaluation-output range check is visible.

## Acceptance examples

These are conditional static examples, not executed tests. Unless a variation says otherwise, assume valid storage, stable external values, normally returning dependencies, and no dependency mutations beyond those specified.

### Rejection occurs before zero-span handling

Given origin 100, span zero, position 90, and rollover 1,000:

- Position precedes origin.
- Origin plus span is 100, no greater than 1,000.
- The function writes result zero and returns.
- No span-crossing dependency, evaluation dependency, notification, or callback is reached.

A zero span therefore does not imply that crossing handling is always reached.

### Zero span after origin acceptance

Given origin 100, position 100, and span zero:

- The ordinary-origin path produces adjusted position zero.
- Zero is not strictly below the span.
- Mode zero selects terminal handling.
- A nonzero mode instead calls F-d7be9cfb4000 with adjusted position zero and span zero.

If that dependency returns normally with any 32-bit value, the product with the retained zero span is zero. The explicit origin write consequently uses 100 and the remaining position stays zero. Any subsequent mode change still depends on retained mode and return parity. The dependency’s actual behavior for a zero span is unknown.

### Accepted rollover adjustment

Given origin 990, span 20, rollover 1,000, and position five:

- Origin plus span is 1,010, greater than rollover.
- Half-threshold 500 is greater than position five.
- Adjusted position becomes 15.
- Since 15 is below 20, evaluation receives a pointer to the 32-bit value 975.
- Crossing processing is not called.

With origin 990, span 800, rollover 1,000, and position 600, the first acceptance condition succeeds, but the half-threshold condition fails. The result becomes zero without evaluation.

### Accepted rollover crossing argument

Given origin 990, span 20, rollover 1,000, position 15, and nonzero mode:

- Adjusted position becomes 25.
- Crossing processing is reached.
- Its arguments are 25, 20, 500, the context input, and the auxiliary input.

The third argument is the half-threshold even when the auxiliary input differs from 500.

### Evaluation and fresh-mode reflection

Given origin 100, position 103, and span ten, evaluation receives a pointer to 195.

If it returns 1,000:

- A subsequently read mode of two leaves result 1,000.
- A subsequently read mode of four produces result 64,536.

These outcomes depend on the post-evaluation mode, including any mutation made during evaluation.

### Exact terminal boundary

Given origin 100, position 110, span ten, and mode zero:

- Equality selects terminal handling.
- Result 65,536 and terminal flag one are written before notification.
- A callback object installed by notification can be invoked.
- Crossing and evaluation are skipped.

If the callback installs a replacement callback object and returns normally, the record’s callback-object field is nevertheless cleared afterward.

### Crossing does not repeat

Given origin 100, position 125, span ten, and retained mode two, suppose the crossing dependency returns one:

- Mode is written as four.
- Origin becomes 110.
- Remaining position becomes 15.
- Evaluation receives a pointer to 975.

Although 15 is still at least the span, crossing processing does not repeat.

If the dependency instead returns two, no mode write occurs, origin becomes 120, and evaluation receives a pointer to 325. A mode mutation made by that dependency is not restored by the even-result path.
