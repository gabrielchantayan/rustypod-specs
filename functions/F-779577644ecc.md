# F-779577644ecc

## Purpose

F-779577644ecc answers whether two integer fields located at fixed byte displacements from a supplied base address have equal values.

For a valid invocation with stable, ordinary readable storage, the result is true when the two field values are equal and false when they differ. Equality is the entire visible decision criterion. The routine does not establish that the containing object is valid, that either field has an acceptable application-level value, or that any broader state invariant holds.

The fields’ meanings are unknown. Describing them as counters, positions, capacities, identifiers, or lifecycle states would go beyond the supplied evidence.

This contract describes behavior supported by the supplied static representation. It does not claim runtime verification or independently verified target metadata.

## Acceptance examples

These examples are conditional consequences of the static evidence, not executed tests. Unless stated otherwise, they assume valid address formation, ordinary stable storage, valid integer representations, and no overlapping mutation.

1. **Equal positive values**  
   If both fields contain 17, the result is true. Their absolute location does not add another comparison criterion once both accesses are valid.

2. **Unequal values in either order**  
   If the first field contains 17 and the second contains 18, the result is false. Exchanging those values also produces false.

3. **Both values zero**  
   If both fields contain zero, the result is true. Zero is not visibly treated as an invalid or uninitialized value.

4. **Negative values**  
   If both fields contain a valid representation of negative one, the result is true. If one contains negative one and the other contains zero, the result is false.

5. **Representable extremes**  
   Two fields containing the same minimum representable integer produce true. A minimum representable integer and a distinct maximum representable integer produce false. The decision requires no difference calculation.

6. **Changes outside the compared fields**  
   Two valid objects with matching corresponding comparison values produce the same result even if unrelated ordinary bytes differ. This condition excludes changes that invalidate an address, representation, lifetime, or synchronization requirement.

7. **Change between completed invocations**  
   If both fields contain 5, one invocation returns true. If the second field is then changed to 6 before a later invocation, with valid synchronization and no overlapping mutation, the later invocation returns false.

8. **Conditional four-byte layout**  
   On a target with four-byte integer accesses, complete valid storage for offsets 2232–2235 and 2240–2243 satisfies the field-extent requirement. Providing only the first byte at either field start does not.

9. **Invalid or incomplete storage**  
   If either complete integer access is invalid, no result is promised. False is not an established error response.

10. **Mutation during the invocation**  
    No single-snapshot result is required without additional guarantees. Read order cannot be used to predict which state will be compared.
