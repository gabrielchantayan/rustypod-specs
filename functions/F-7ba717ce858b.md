# F-7ba717ce858b

## Behavior

### Dependency result and adjustment

F-b7af80e829ec is invoked before the visible dispatch-table accesses.

If its result is non-null, the function moves backward by five integer-sized elements. All subsequent object-related accesses use that adjusted address.

If its result is null, the function retains null and continues to the dispatch-table access. The null check guards only the adjustment. It is not an early return, an error result, or a fallback selection.

### Query dispatch

The next visible operation reads the dispatch-table reference from the adjusted address. It then obtains the callable entry at byte offset 0x1A0 and invokes that entry with the adjusted address as an explicit argument.

The query result is treated as an integer and compared with zero:

- Exactly zero selects the operation at byte offset 0x10C.
- Any nonzero result selects the operation at byte offset 0xFC.

The selection is not restricted to a result of exactly one. If the actual result representation supports negative integers, negative results also take the nonzero branch.

No other property of the query result is used. There is no visible range check, normalization, retry, or interpretation as an error code.

### Selected dispatch

After the query returns, the selected operation is looked up through another read of the dispatch-table reference at the same adjusted address.

This second lookup is significant. The evidence does not justify treating the table reference used for the query as an immutable snapshot. If the query changes the reference stored at the adjusted address, the selected operation is obtained from the replacement table, provided that subsequent access remains valid.

Conversely, the function does not visibly invoke F-b7af80e829ec again. It retains the adjusted address derived from the original result. A change to some separate global “current object” does not by itself cause this function to reacquire an object.

The selected dispatch is represented without explicit arguments. The evidence does not establish that it receives the adjusted address as a receiver. It also does not establish a portable zero-argument ABI: implicit machine state and limitations of the recovered indirect transfer remain relevant.

Only one selected operation is visible on a normally returning path. The function does not invoke both alternatives, and it does not repeat the query after selection.
