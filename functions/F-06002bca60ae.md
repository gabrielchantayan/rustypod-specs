# F-06002bca60ae

## Purpose

F-06002bca60ae routes a non-null address through one of two release-like paths:

- A matching-region path links the supplied address into a singly linked list maintained by a descriptor.
- A fallback path checks preceding metadata, adjusts accounting fields, and delegates further processing to opaque dependencies.

“Release-like” describes inferred intent, not a proven ownership contract. The visible operations establish list insertion, metadata validation, accounting changes, and dependency calls. They do not establish that storage is returned to an allocator or that the caller may subsequently reuse or access it.

A descriptor-acquisition dependency is invoked even when the supplied address is null.

## Interface

### Inputs and result

The function accepts:

1. **Storage address:** a pointer represented as a 32-bit address in the supplied source model. The matching-region path writes one 32-bit word at this address. The fallback path reads metadata immediately before it.
2. **Selector:** a 32-bit integer compared for equality with a descriptor field. It does not otherwise affect the visible fallback behavior.

There is no explicit return value. Ordinary paths return without a status. One metadata-failure path calls a dependency marked non-returning. An optional indirect dispatch occurs after matching-region insertion; if that dispatch returns, this function returns.

### Descriptor layout

The descriptor returned by F-f2ddcdbfb0c6 is accessed at the following byte offsets:

| Offset | Width | Visible role |
|---|---:|---|
| `0x00` | 32 bits | Address of an optional object whose first word controls indirect dispatch |
| `0x08` | 32 bits | Selector used in matching-region eligibility |

| `0x14` | 32 bits | Region base |
| `0x18` | 32 bits | Linked-list head |

These roles do not establish the descriptor’s full layout or the units or provenance of its region fields beyond their use in address arithmetic.

### Fallback metadata layout

Relative to the storage address:

| Relative offset | Width | Visible role |
|---|---:|---|
| `−8` | 32 bits | Header checked for validity and masked to obtain an accounting quantity |
| `−4` | 16 bits | First accounting index |
| `−2` | 16 bits | Second accounting index |

The two index reads are explicitly 16-bit reads at distinct addresses. No byte order is specified here. In particular, this contract does not identify either halfword with the numeric high or low half of a separately loaded 32-bit word.

The quantity used for most accounting updates is the header masked by `0x3ffffffc`. This removes the lowest two bits and highest two bits, yielding a multiple of four between zero and `0x3ffffffc`, inclusive. Calling this quantity a byte size is an inference, not established behavior.

### Preconditions

For defined execution, all memory actually accessed along the selected path must be valid for the stated operation. In particular:

- A non-null input requires a readable descriptor from F-f2ddcdbfb0c6.
- Matching-region insertion requires a writable word at the supplied address and a writable descriptor head.
- Fallback processing requires readable preceding metadata and valid accounting destinations.
- Any nonzero optional dispatch-object address must support a readable first word.
- A taken indirect dispatch requires a valid executable target and an appropriate calling convention.

The function does not visibly validate these conditions. There are no explicit bounds checks on accounting indices, alignment checks, or checks for accounting underflow.

## Behavior

### 1. Descriptor acquisition and null handling

The first visible operation is a call to F-f2ddcdbfb0c6. Its result is retained as the descriptor address.

Only after that call does the function test the storage address for null.

If the address is null, the function returns. It does not visibly dereference the returned descriptor or access fallback metadata on this path. Any effects of F-f2ddcdbfb0c6 have nevertheless already occurred.

### 2. Matching-region eligibility

For a non-null address, the function evaluates these conditions in order, with short-circuiting:

1. The descriptor’s 32-bit selector field equals the supplied selector.
2. The descriptor’s region base, interpreted as a signed 32-bit address value, is less than or equal to the supplied address interpreted the same way.
3. The supplied address, under signed 32-bit interpretation, is less than the exclusive upper bound.

The upper bound is formed by adding the descriptor’s region base and its quantity field using the shown 32-bit unsigned word arithmetic, then interpreting the result as signed for comparison.

Consequences:

- A selector mismatch avoids evaluation of both range conditions.
- Failure of the lower-bound comparison avoids evaluation of the upper bound.
- The lower bound is inclusive; the upper bound is exclusive.
- This is not an unsigned address-range test.
- The upper-bound addition may wrap at 32 bits. No separate overflow rejection is visible.
- The base is read for both the lower-bound comparison and upper-bound construction; no persistent snapshot across those expressions is established.

### 3. Matching-region insertion

If all eligibility conditions succeed, the visible sequence is:

1. Call F-338d16f9ce72 with the descriptor address.
2. Read the descriptor’s current head and write that 32-bit value into the first word at the supplied storage address.
3. Write the supplied storage address into the descriptor head.
4. Read the optional dispatch-object address from descriptor offset `0x00`.
5. If that address is nonzero, read its first 32-bit word.
6. If both the object address and that first word are nonzero, invoke the target held in an external indirect-dispatch slot.
7. Return.

The descriptor is not visibly requalified after F-338d16f9ce72. Values used for insertion and optional dispatch are read after that dependency returns. The dependency is not assumed to preserve descriptor contents.

The object’s first word is a dispatch gate. The visible source does not establish that this word itself is the indirect target; the target comes from a separate slot.

Insertion precedes optional dispatch. No rollback is visible if dispatch fails or does not return.

There is no duplicate-insertion check. For ordinary non-overlapping storage, inserting an address already equal to the current head writes that same address into its first word, producing a self-link.

### 4. Fallback setup and header rejection

If matching-region eligibility fails, the function takes the fallback path. A repeated null check appears before fallback setup, but the input has already been found non-null and has not been visibly reassigned.

The fallback sequence begins:

1. Call F-2fd8826557a4 without explicit arguments.
2. Read a 32-bit context address from an external global slot.
3. Locate the header eight bytes before the supplied address.
4. Reject the header if it is zero or if bit zero is set.

Rejection calls F-a817d8d58c10 without explicit arguments. The supplied evidence marks that call non-returning. No accounting update or later fallback dependency call is shown after rejection.

The validation is narrower than a general metadata-integrity check:

- A nonzero header with bit zero clear passes.
- Bit one may be set.
- Either of the highest two bits may be set.
- The masked accounting quantity may be zero.

The preliminary dependency call and global-context read occur before header rejection.

### 5. Fallback accounting and delegated processing

For a header that passes the visible check:

1. Call F-c0fc6d033caa with the captured context address.
2. Read the unsigned 16-bit index at storage offset `−4`.
3. Read the header again and mask it with `0x3ffffffc`. Retain this quantity for the next four subtractions.
4. Subtract that quantity from the 32-bit field at context offset `0x224 + 4 × first index`.
5. Subtract the same quantity from the 32-bit field at context offset `0x30c`.
6. Read the unsigned 16-bit index at storage offset `−2`.
7. Subtract the retained quantity from the field at context offset `0xe0 + 4 × second index`.
8. Subtract the retained quantity from the field at context offset `0x220`.
9. Call F-09dcb55e8e0a without explicit arguments and use its integer result as another index.
10. Decrement the field at context offset `0x310 + 4 × returned index` by one.
11. Decrement the field at context offset `0x390` by one.
12. Read the header again, mask it with `0x3ffffffc`, and subtract this newly read quantity from the field at context offset `0x08`.
13. Call F-cc6c9b4a0f68 with the captured context address and the header address.
14. Call F-e586bff64fb7 with the captured context address.
15. Return.

All listed accounting updates are 32-bit read-modify-write operations. No saturating subtraction, zero guard, atomic operation, or rollback is visible.

The captured context address remains the argument and address-arithmetic base throughout this sequence. Changes to the external context slot by later dependencies do not cause it to be reread. Changes to the memory addressed by the captured context can still affect subsequent reads and writes.

The header check precedes F-c0fc6d033caa, but the first retained masked quantity is read after that dependency returns. No header revalidation follows the call. Similarly, the final subtraction uses a header read after F-09dcb55e8e0a, so its quantity need not equal the one used for the first four subtractions.

### Arithmetic and aliasing

The two metadata indices are zero-extended 16-bit values. Their scaled contributions range from zero through `0x3fffc`. These bounded indices still do not prove that the resulting accounting addresses belong to valid arrays.

The index returned by F-09dcb55e8e0a has no visible range or sign validation. Negative or excessive values are not explicitly rejected.

For ordinary in-range arithmetic, the listed additions and subtractions have their direct mathematical meaning. The source exposes 32-bit destinations and no underflow handling, but includes signed intermediate expressions. Exact overflow semantics for every such expression require target-level confirmation and are documented_only.

The sequence is not a simultaneous vector update. If destinations alias, later updates read the results of earlier writes. For example, a second metadata index of 80 makes its indexed field coincide with context offset `0x220`; absent intervening changes, that location receives two consecutive subtractions.

## Side effects

### Established direct effects

The matching-region path:

- Overwrites the supplied storage’s first 32-bit word.
- Replaces the descriptor head.
- May invoke indirect dispatch after insertion.

The fallback path:

- Reads metadata before the supplied address.
- Performs four quantity subtractions, two single-unit decrements, and one separately sourced quantity subtraction.
- Passes the header address, rather than the supplied storage address, to F-cc6c9b4a0f68.

A metadata failure occurs after fallback setup but before the visible accounting writes.

### Ownership and synchronization

The insertion path uses the supplied storage itself to hold a list link, destroying its previous first-word contents.

No explicit allocation is visible. The fallback delegation may perform storage-management operations, but ownership transfer, reclamation, and lifetime termination are not established by the supplied source.

Dependency calls surround important mutations, but their synchronization semantics are unknown. The visible function alone does not establish thread safety, exclusion, reentrancy safety, or protection against concurrent metadata changes.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless otherwise stated, memory is valid, accounting locations are distinct, arithmetic remains in range, and dependencies return without altering relevant state.

1. **Null storage address.** F-f2ddcdbfb0c6 is called once, then the function returns. No descriptor dereference or fallback processing follows.

2. **Inclusive lower bound.** With selector equality, base `0x1000`, quantity `0x100`, and address `0x1000`, the matching-region path is selected. The previous head is written at `0x1000`, then the descriptor head becomes `0x1000`.

3. **Exclusive upper bound.** Under the same descriptor, address `0x1100` selects fallback rather than insertion. The outcome then depends on its preceding metadata.

4. **Signed range interpretation.** Base `0x7ffffff0` and quantity `0x20` produce upper bound `0x80000010`. An address equal to the base fails the signed upper-bound comparison, despite its apparent inclusion in an unsigned wrapping interval.

5. **Rejected fallback headers.** A zero header or header `0x101` invokes F-a817d8d58c10 after fallback setup. No visible accounting mutation follows.

6. **Ordinary accounting.** Header `0x102` passes validation and supplies masked quantity `0x100`. With metadata indices 3 and 5 and dependency-returned index 2, quantity subtraction targets include offsets `0x230`, `0x30c`, `0xf4`, `0x220`, and `0x08`; single-unit decrements target `0x318` and `0x390`.

7. **Passing header with zero quantity.** Header `0x2` passes validation but masks to zero. Quantity-update operations still occur, both single-unit decrements still occur, and both trailing dependencies are called.

8. **Header mutation during index acquisition.** If the retained quantity is `0x100`, but F-09dcb55e8e0a changes the header so its masked quantity becomes `0x200`, the first four quantity subtractions use `0x100`; the final subtraction at context offset `0x08` uses `0x200`.

9. **Optional dispatch ordering.** With a nonzero dispatch-object address and nonzero first word, indirect dispatch occurs after both insertion writes. A zero object address avoids its dereference; a zero first word suppresses dispatch.
