# F-670f7bf1f272

## Purpose

F-670f7bf1f272 searches a word-addressed collection for a requested value and, if that value is absent, attempts to place it in the first zero-valued slot within a bounded search range.

The established behavior is narrower than a conventional insertion operation:

- An existing occurrence of the requested value causes an immediate return of −1.
- Equality between two descriptor fields triggers F-1ee6cb5fd8a8 before the search for a zero slot.
- The zero-slot search uses a bound read after that dependency returns.
- A successful insertion increments the descriptor’s third word, writes the requested value into the selected slot, and returns the slot’s zero-based index.
- If no zero slot is found, the function returns −1 without a direct insertion write.

The descriptor’s second word is not directly incremented. The function does not directly append outside the searched range. Consequently, interpreting the second and third words as conventional “length” and “capacity” fields would introduce semantics not established by the supplied evidence.

The supplied representation uses four-byte integer slots and four-byte descriptor fields. Slot index \(k\) addresses the word at storage address plus \(4k\). No larger record, terminator beyond the explicit bound, or per-slot metadata is established.

## Behavior

### 1. Duplicate search

The function begins at slot index zero and visits increasing indices while the index is less than the descriptor’s search-bound word, using a signed comparison.

For each visited index, it obtains the storage address from the descriptor and reads the corresponding four-byte slot. If the slot equals the requested value, the function immediately returns −1.

This return precedes:

- The comparison that can invoke F-1ee6cb5fd8a8.
- The search for an empty slot.
- Any direct counter or slot write by this function.

Thus duplicate detection has precedence over both the dependency call and insertion.

The initial search does not establish a single retained bound for the entire scan: its loop condition references the descriptor’s search-bound word on successive iterations. The storage-address word is also used afresh for successive slot accesses. These are source-level access properties, not a guarantee of atomic or volatile machine accesses.

A negative or zero search bound causes the initial search to examine no slots.

### 2. Conditional dependency call

If the duplicate search finishes without a match, the function compares the counter word with the search-bound word.

- If they are equal, it calls F-1ee6cb5fd8a8 with the descriptor reference.
- If they differ, it proceeds without that call.

Equality alone controls this call. There is no visible requirement that either value be positive, that the counter be less than the bound, or that the storage contain any particular number of zero slots.

The caller-visible meaning of the dependency is unknown. It may be intended to adjust storage or descriptor state, but that interpretation is not an established guarantee.

After the call, the function does not repeat duplicate detection. If the dependency introduces the requested value into the collection, that new occurrence does not cause a second duplicate-rejection pass.

### 3. Zero-slot search

After the optional dependency call, the function reads the search-bound word and retains that value for the second search.

It searches from index zero upward for the first slot whose integer value is zero. The search considers only indices strictly below the retained bound.

For each examined slot, the function obtains the storage address through the descriptor. It does not retain the pre-call storage address as the required backing storage.

Two outcomes are possible:

- **A zero slot is found.** Its index is selected.
- **No zero slot is found.** The selected result becomes −1.

If the retained bound is zero or negative, no slot is examined and the result is −1.

The second search is bounded by its retained value, rather than by repeated reads of the search-bound field. Changes to that field after the retained read do not alter the source-level bound used by this search.

### 4. Successful insertion

For a stable, valid descriptor and storage range, a selected slot satisfies:

\[
0 \leq \text{selected index} < \text{retained search bound}.
\]

The function’s subsequent conditions permit the insertion for every such index, including index zero.

On this path, the observable source-level update order is:

1. Read the current counter word.
2. Add one to that value.
3. Write the incremented value back to the counter word.
4. Read the storage-address word.
5. Write the requested value into the selected slot using that address.
6. Return the selected index.

The counter update precedes the slot write. There is no visible rollback if a later access fails.

The storage address used for the final write is read after the counter update. The contract therefore must not assume that the final write necessarily uses a previously retained address. This matters if the descriptor and backing storage overlap or if the environment permits intervening mutation.

The function does not directly change the search-bound word on this path.

### 5. Unsuccessful zero-slot search

When no zero slot is found, the function returns −1 without directly modifying the counter or any slot.

This does not imply the entire invocation was side-effect free: F-1ee6cb5fd8a8 may already have run and changed state.

### Requested value zero

Zero is both a permitted comparison value and the marker sought during the second search.

With stable state and no intervening dependency mutation:

- If the initial search sees any zero slot, it treats that slot as an existing occurrence of the requested value and returns −1.
- If the initial search sees no zero slot, the later search cannot find one in the same unchanged range.

Consequently, inserting zero successfully requires a relevant change between the two searches, such as a dependency changing the storage contents or search range. On such a successful path, the function increments the counter and writes zero back into the selected zero slot.

There is no explicit prohibition against requesting zero.

## Side effects

A successful insertion directly performs two writes, in this order:

1. Counter word increased by one.
2. Requested value written to the selected storage slot.

Duplicate rejection performs no direct writes and does not call the dependency.

Failure to find a zero slot performs no direct insertion writes, but may follow a dependency call.
