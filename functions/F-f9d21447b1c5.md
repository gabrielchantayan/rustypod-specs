# F-f9d21447b1c5

## Purpose

F-f9d21447b1c5 writes two byte-sized fields in a dependency-selected destination, forwards fields from an owner-linked record through eight ordered dependency calls, and conditionally copies a record byte into nested context state before setting a flag.

The established behavior consists of memory accesses, dependency calls, and branch-dependent writes. Configuration synchronization is a plausible interpretation, not an established application-level contract. The meanings of the fields and flag remain unknown.

## Interface

- **Owner address:** used to read a four-byte address-like field at byte offset `0x378`.
- **Selector:** compared at full width against `-1`. On the non-sentinel branch, its low eight bits are stored in a destination field.

The represented interface has no return value, error-output parameter, length, or capacity. Results are observable through memory writes and dependency effects.

## Behavior

### Initial dependency and destination writes

The function first reads four bytes at owner offset `0x378` and passes that value to F-fdd3c46f3034. The dependency result supplies the destination address.

After the dependency returns, the function performs these byte writes in order:

| Full-width selector condition | Destination `+0x06` | Destination `+0x10` |
|---|---:|---:|
| Equals `-1` | `0xFF` | `0x19` |
| Does not equal `-1` | `0xFE` | Selector’s low eight bits |

The `+0x06` write precedes the `+0x10` write. Neither destination byte is read before being overwritten, and neither write depends on its previous value.

The sentinel comparison is not a low-byte comparison. For example, selector `255` takes the non-sentinel branch even though its low byte matches that of the represented 32-bit value `-1`.

These writes can affect subsequent behavior through aliasing. A destination byte may overlap owner-linked storage, record contents, context-selection storage, or nested state. Valid addresses and nonmutating dependencies alone do not exclude those effects.

### Record and context selection

After both destination writes, the function rereads the four-byte owner field at `+0x378`. This second value becomes the retained associated-record address.

It then reads the global root slot and obtains the selected-context value from root offset `0x30`.

Consequently:

- The retained record can reflect changes made by F-fdd3c46f3034.
- It can also reflect changes caused by the function’s own destination writes.
- Context selection occurs after those same operations and can observe their effects.

The function retains the selected record and context values for the remaining operations. It does not explicitly reload the record address through the owner or reselect the context through the global root between forwarding calls.
