# F-731584f3d537

## Purpose

F-731584f3d537 is a globally configured, state-dispatched routine. Its operations select storage addresses, derive arithmetic state from three dependent byte reads, transform individual bytes in an invocation-local workspace, call five dependencies, and conditionally assign and return a 32-bit result.

**Established static behavior:** global words govern operation selection, arithmetic, indices, and transitions. The supplied representation does not establish their values, a fixed processing sequence, termination, or a successful outcome.

**Inferred intent:** the workspaces and transformations are consistent with a processing or validation pipeline. No particular algorithm, format, or validation guarantee is established.

This contract describes conditional behavior of the supplied representation. It does not assert that every operation is reachable under the unavailable global configuration.

Saving the address does not copy its contents. No caller-storage length is supplied. There is no visible entry validation of the address, readable extent, or opaque word.

The returned value has a signed 32-bit representation. A pending result starts at zero. Selector 3 replaces it with the product of the captured signed multiplier and the current unsigned 32-bit arithmetic accumulator, converted to the signed result representation. Selector 4 returns the pending result.

Consequently:

The multiplication involves signed and unsigned operands. It is not an unbounded mathematical product; finite-width arithmetic and conversion to the signed result representation matter.

1. The first read supplies an alternate candidate after adding the displacement below.
2. The second read supplies the base candidate without that displacement.
3. Control one selects the base candidate; control zero selects the alternate candidate.

| Selector | Displacement applied to first read |
|---|---:|
| 0 | +1 |
| 2 | −3 |
| 5 | +15 |

Thus, “alternate equals base plus displacement” is valid **only if both reads return the same value**. The routine does not establish a shared snapshot. Both reads occur even when only one candidate determines the transition.

For selectors 0, 2, 5, 10, 11, and 17, control calculation precedes these candidate reads. Selector 2 copies the dependency-facing address into the active source **after both candidate reads**, before applying the selected transition.

Selector 18 has an intervening state update: it calculates the alternate candidate from the first read, updates retained loop state, then performs the second read for the base candidate.

The chosen state is still subject to a fresh dispatch-offset read at the next selection. Candidate arithmetic, state combination, and dispatch addition retain the representation’s width and signedness constraints; mathematical integer arithmetic is not an unconditional substitute.

### Three-byte derivation

Selector 0 performs three ordered, dependent reads from the active source. It does not establish an adjacent-field layout.

The first byte is read at the initial source-index selector. Its transformed value determines the second index; the second byte’s transformed value determines the third index.

For each byte, the initial transformation multiplies the unsigned loaded byte by **245** and retains the low eight bits. Expansion then uses multiplication by **93**, complement, an OR with hexadecimal **FF**, and global coefficients. The OR sets the low eight bits; it is not equivalent to retaining only those bits.

The first and second stages:

- Apply global arithmetic and the captured values.
- Use signed remainder with divisor **256**.
- Apply scaling and retain the low **16** bits.
- Expand that value using global coefficients and a complemented product ORed with hexadecimal **FFFF**.

The first stage includes an additional global bias. The second includes twice a shared global additive value. Their expansions are temporary first and second components.

The second index includes both captured arithmetic values and a remainder derived from the temporary first component minus a global bias. The third index similarly uses the temporary second component plus another global bias. These expressions are not established bounds checks.

The third byte receives a related transformation, but its corresponding scaled remainder is **not immediately truncated to 16 bits**. Its expansion is combined with both temporary components and another global additive value. This combination is globally scaled and then reduced to its low 16 bits.

The operation subsequently replaces the retained components:

- The retained first component becomes the global-coefficient expansion of that masked combination.
- The retained second component becomes the captured multiplier times the sum of the new first component and a global bias, minus another global value.

The two temporary components therefore do not remain as the pair used by later workspace operations.

A further bit-level calculation uses the new first component, biased and scaled forms, configured masks, hexadecimal **1FC0**, **1FC1**, and **B3354000**, and an arithmetic right shift of a global word. Its full final 32-bit word replaces the accumulator. Its unsigned high bit supplies control, followed by the two next-state reads described above.

### Single-byte workspace transformation and accumulator update

Selector 13 performs these byte accesses in order:

1. Read the active source at the captured multiplier times the sum of the retained components.
2. Read the 240-byte workspace at the captured multiplier times the retained second component.
3. Write one byte at that same workspace position.

Both loads are unsigned. Each byte is multiplied by 245, reduced to its low eight bits, and expanded using multiplication by 93, complement, an OR with FF, and global coefficients.

The operation calculates a **full 32-bit word** consisting of:

- The expanded source contribution,
- Minus the expanded old-workspace contribution,
- Minus the retained second component.

**This full word replaces the accumulator before byte conversion.** The destination byte is obtained by converting that word to a byte-width representation, multiplying by **−65**, and retaining the stored byte representation. The accumulator is neither reduced to a byte nor replaced by the stored byte.

The old destination byte affects the replacement. Both reads precede the write, including when valid source and destination addresses alias. Exactly one workspace byte is directly written by this selector.

After the store, the loop-related arithmetic value is recalculated from retained loop state and global factors, retaining only the low 16 bits. The operation then reads its configured next state. These later actions do not replace the accumulator.

### Loop arithmetic and accumulator update

Selector 15 sets only the loop-related arithmetic value to zero, then reads the same configured next-state global used by selector 13. It does not visibly reset the retained components, retained loop state, accumulator, or pending result.

Selector 18 expands the incoming loop-related value using global coefficients, complement, and an OR with FFFF. This replaces the **retained second component**, leaving the retained first component unchanged.

It then calculates a bit-level control word using a global-scaled form of the new second component, configured bit patterns, and constants **238**, **239**, and hexadecimal **FFFFFF0F**.

**The complete final 32-bit control-calculation word replaces the accumulator.** Branch control is derived separately by interpreting that word as signed, shifting right arithmetically by 31, and adding one:

- Negative signed interpretation gives control zero.
- Nonnegative signed interpretation gives control one.

This differs from the unsigned high-bit extraction used by selectors 0 and the dependency operations.

After the first next-state read and alternate-candidate calculation, retained loop state becomes the incoming loop-related value plus hexadecimal **C741**, ANDed with hexadecimal **FFFEFFFF**. The second next-state read follows that update.

FFFEFFFF clears bit 16 and retains the other bits. It is not a low-16-bit mask. Neither the constants nor workspace size prove 240 iterations or safe indices.

### Width and conversion requirements

Byte loads are unsigned; the intermediate signed-16-bit conversion shown for loaded bytes does not make values from 0 through 255 negative.

Explicit low-eight-bit and low-16-bit truncations apply only at their stated stages. An OR with FF or FFFF must not be substituted for an AND mask, or vice versa.

Complements, products, bitwise operations, and high-bit extraction require the represented word width. Unsigned arithmetic has finite-width behavior. Signed remainder by 256 is not interchangeable with nonnegative modulo for negative operands. Arithmetic and logical right shifts are distinct.

Signed overflow, out-of-range signed conversions, and target-specific signed-shift details require target evidence. These uncertainties do not justify removing explicit truncations or substituting arbitrary-precision arithmetic.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Independent entry reads.** If the dispatch-seed reads yield 20 and then 31, fallback is 16 and initial state is 31, assuming representable subtraction.

2. **Independent transition candidates.** For selector 0, first next-state read 20 and second read 31 produce alternate 21 and base 31. Control zero chooses 21; control one chooses 31. Neither candidate is reconstructed from the other.

3. **Loop-transition ordering.** For selector 18, first read 20 produces alternate 18. Retained loop state is updated before the second read. If that read yields 31, base is 31, not 20.

4. **Captured versus live state.** A dependency changing the dispatch seed does not change fallback or the arithmetic captures. Changes to dispatch offset or later-read next-state globals can affect subsequent selection.

5. **Unmatched selector.** An unmatched selection clears the accumulator and resumes at fallback; it does not directly return an error.

6. **Selection versus activation.** Selector 7 changes dependency-facing selection but leaves the active source unchanged. A source read before selector 2 has activated an address can therefore use the initially null source.

7. **Component replacement.** Following selector 0, later indexing uses the final combined expansion and its derived companion, not the first two temporary components. Selector 18 subsequently replaces only the companion.

8. **Full-word byte-transform result.** If selector 13’s full-word difference is hexadecimal 00000100, the stored byte is zero, but the accumulator remains hexadecimal 00000100. A following selector 3 uses that full word, not zero.

9. **Full-word loop-control result.** If selector 18’s final control word is hexadecimal 80000000, it retains that entire accumulator and derives control zero. A following selector 3 uses the full accumulator, not the branch control.

10. **Pending result isolation.** If selector 3 assigns a result and selector 13 later changes the accumulator, selector 4 still returns the assigned result unless selector 3 executes again.

11. **Read-before-write and loop mask.** Valid aliasing does not eliminate either pre-store read in selector 13. Separately, bit 17 survives the FFFEFFFF loop-state mask; substituting FFFF changes behavior.

12. **Dependency status is arithmetic.** A nonzero dependency return alone establishes neither failure nor its transition. The prescribed products, complement, accumulator update, and control extraction remain required.
