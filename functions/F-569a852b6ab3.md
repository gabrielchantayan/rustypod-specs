# F-569a852b6ab3

## Purpose

The supplied static representation describes a procedure that interleaves numerous unresolved indirect calls with byte, halfword, and word memory accesses. Its established behavior is a sequence of address calculations, field transfers, zero stores, and writes to shared storage, ending with an attempted call to address zero.

A higher-level purpose—such as initialization, object registration, dispatch, or device control—is not established. Repeated access offsets do not prove the existence of any particular object type or table.

This contract describes the visible operations conditionally: an operation is reached only if all earlier calls and memory accesses complete and execution continues as represented. It does not establish that the procedure successfully returns in a real environment.

## Interface

### Explicit inputs and output

The represented interface has four 32-bit input slots:

| Input | Established use |
|---|---|
| First input | Used as an address, stored as a full word, and truncated to a byte. |
| Second input | Forwarded to the first indirect call. |
| Third input | No explicit use is visible. |
| Fourth input | Forwarded to the first indirect call. |

No return value is declared. A return appears after the final indirect call, but that call targets address zero; normal return is therefore conditional on the execution environment and that target’s behavior.

The first input is not merely a numeric identifier. At minimum, the visible path writes at its byte offset 9 and reads a word at its byte offset 52.

### Implicit inputs

Execution also depends on:

### Width and notation

This document uses descriptive mathematical labels for captured values, not implementation identifiers.

- **W(address)** means a 32-bit memory access.
- **B(address)** means an 8-bit memory access.
- **H(address)** means a 16-bit memory access.
- **low8(value)** means the least significant eight bits.
- A right shift of an unsigned word is logical.
- A split 64-bit result yields its numerical low and high 32-bit halves; this alone does not establish memory byte order.

Address scaling by four or sixteen is literal scaling. It does not establish that the operand is a valid array index.

The representation mixes signed 32-bit arithmetic with unsigned bit operations. Where multiplication, addition, or signed left shift exceeds its representable range, exact machine behavior is **documented_only** pending instruction-level or ABI evidence. This contract does not silently impose unbounded arithmetic or portable-language overflow rules.

## Behavior

### Execution ordering

The visible path has no explicit conditional branches or loops. Calls and accesses occur in a fixed order, although any call may fail, not return, alter memory, or otherwise invalidate later assumptions.

There are unresolved call sequences between most operations below. A value explicitly captured before such a sequence remains the value used later in the represented computation; a later memory read is a fresh read and must not be replaced by an earlier snapshot.

### 1. Entry and initial first-input transfers

1. The initial indirect call receives the first, second, and fourth inputs, in that order. Its target depends on incoming link state.
2. Subsequent calls include a producer whose 32-bit result is immediately passed to another call.
3. A later call supplies a 64-bit result.
4. The byte at first-input address plus 9 is written with the low eight bits of the first input itself.
5. After that byte write, the word at first-input address plus 52 is read. A call receives:
   - The low half of the 64-bit result shifted left by two.
   - The high half.
   - The freshly read word.

The byte store precedes the word read. If their effective addresses overlap because of address arithmetic or unusual mapping, the read observes memory after the store.

### 2. Initial indexed word writes and chained reads

After further calls, a call-associated 32-bit value supplies an index-like quantity:

1. Store the first input at address four times that quantity plus 20.
2. Read a word at the unscaled quantity plus 20; retain this as the **first link word**.
3. Invoke a call with the unscaled quantity.

A later returned word supplies another index:

4. Store the first input at four times that returned word plus 20.
5. Read a word at the first link word shifted right by 22, plus 20; retain it as the **second link word**.
6. Invoke a call with four times the returned index.

After another call sequence produces a word, retain that result as the **payload word**:

7. Store the payload word shifted left by two at four times the second link word shifted right by one, plus 20.
8. Read a word at the original, unshifted second link word plus 20; retain it as the **third link word**.
9. Invoke a call with the second link word shifted right by one.

These two uses of the second link word are distinct: the store uses a shifted and scaled address; the read uses the unshifted value.

Another returned index then selects a word destination:

10. Store the same shifted payload at four times that index plus 20.
11. Read G-A and retain this **early shared snapshot**.
12. Invoke a call with four times that index.

### 3. Reduced fields and zero-valued writes

Following further calls:

1. Reduce the third link word by a logical right shift of 22; call the result the **reduced link**.
2. Reduce the early shared snapshot by a logical right shift of 23; call the result the **reduced shared value**.
3. Using another call-associated index, store the reduced link at four times that index plus 20.
4. Invoke a call with four arguments: that index twice, the reduced shared value, and the reduced link.

A later producer result is forwarded to a consumer. Between those calls, the reduced shared value is shifted right by another 23 bits. Because the original snapshot is only 32 bits, this twice-shifted result is necessarily zero.

After further calls:

5. Store the reduced link at another returned index scaled by four, plus 20; pass the scaled index to a call.
6. Using another call-associated word, store a zero word at its four-times-scaled address plus 20; pass its unscaled value to a call.
7. After another producer/consumer sequence, store the twice-shifted shared value—therefore zero—at another returned index scaled by four, plus 20.

The call-associated word used for the first zero store is also used to select a later read:

8. Mask it with `0x1fffffff`, shift right by 19, add 20, and read a word. Retain this as the **selected word**.
9. Pass the scaled destination of the preceding store to a call.
10. After intervening calls, shift the selected word right by 22; retain the result as the **selected upper field**.
11. Read a byte at address one plus the twice-shifted shared value. Consequently, this is a read of address 1.
12. Add 17 to that byte value and write the low eight bits of the selected upper field at the resulting address.

The destination byte therefore lies between addresses 17 and 272, inclusive. Its value depends only on bits 22 through 29 of the selected word.

### 4. Byte clears and another result chain

A call next receives a call-associated word three times and zero as its fourth argument. After more calls, another call receives zero.

Then:

1. Read a byte at four times the selected upper field plus 1.
2. Write zero to the byte at the resulting byte value plus 17.
3. Pass a returned word shifted left by two to a call.
4. Later, pass another returned word shifted left by two twice to another call.
5. Obtain a new 32-bit result and pass it to another call.
6. Read G-B and clear the byte at that byte value plus 17.

A later call receives another call-associated word three times. Retain that word as the **late context value**.

A subsequent producer’s result is passed to a consumer together with the prior 32-bit result shifted right by 23.

After further calls:

7. Read G-B again, independently of the earlier read; retain this **captured byte base**.
8. Clear the byte at the captured byte base plus 17.
9. Pass another returned word shifted left by two to a call.
10. Later, pass a further returned word shifted left by two twice to another call.

The two G-B reads are not interchangeable. Calls between them may change address 1.

### 5. Shared-word publication and low-byte field copies

A call produces a 32-bit **published word**:

1. Write the published word to G-C.
2. Pass the same captured word to a call.
3. After another call, read W(captured byte base + 116).
4. Write its low byte to B(captured byte base + 1).
5. Invoke a call with the late context value shifted left by 11.

A subsequent call returns 64 bits. Another call receives its low half, its high half, and the published word shifted right by 23.

Later:

6. Multiply a returned index by four; retain this as the **first field base**.
7. Read W(first field base + 116), and copy its low byte to B(first field base + 1).
8. Pass the first field base to a call.
9. After more calls produce another index, retain four times that index as the **retained scaled index**.
10. Read W(first field base + 116) again and again copy its low byte to B(first field base + 1).

The second copy is a fresh read, not reuse of the first word. Intervening calls may change that field.

A call then receives:

- The late context value shifted left by 12.
- The retained scaled index twice.
- The underlying index shifted left by 18.

### 6. Full-word retention and further stores

After additional result-forwarding calls:

1. A returned index is multiplied by four to produce a **second field base**.
2. Read W(second field base + 116); retain the full word as the **retained field word**.
3. Write its low byte to B(second field base + 1).
4. Pass the second field base to a call.
5. After further calls, store the full retained field word at sixteen times a newly returned index plus 20.
6. Invoke a call with the retained scaled index logically shifted right by two, then shifted left by 16.

After another series of calls:

7. Store the retained field word at four times a returned index plus 20.
8. Pass that scaled index to a call.
9. Obtain another returned word, shift it left by two, and retain it as the **link payload**.
10. Store the link payload at the retained scaled index masked with `0xfffffffc`, plus 20.
11. Invoke a call with the link payload twice.

The sixteen-times-scaled destination is distinct from the surrounding four-times-scaled destinations.

### 7. Final link transfers and byte routing

After more calls:

1. Store a zero word at another returned index scaled by four, plus 20.
2. Pass that scaled index to a call.
3. Obtain a 64-bit result.
4. Shift its low half left by two; retain this as the **final payload**.
5. Store the final payload at four times its high half plus 20.
6. Read G-A again; retain this **late shared snapshot**.
7. Invoke a call with the final payload, the high half, and the final payload twice more.

Following more calls:

8. Store the final payload at another returned index scaled by four, plus 20.
9. Read W(late shared snapshot + 20); retain this as the **final routed word**.
10. Pass the scaled index to a call.
11. Obtain another 64-bit result, retaining its low half as the **routing selector**.

Then perform two separately timed byte routes:

12. Read B((retained field word shifted right by 23) + 1).
13. Write low8(final routed word) to that byte value plus 17.
14. Invoke a call with the new 64-bit result’s high half three times and its low half shifted left by two.
15. After more calls, read B(((routing selector masked with `0x3fffffff`) shifted right by 21) + 1).
16. Write low8(final routed word shifted right by 22) to that byte value plus 17.
17. Pass a returned word shifted left by two to a call.
18. Later, pass another returned word shifted left by two twice to another call.

Both selector-byte reads range over addresses 1 through 512. Their destination-byte writes range over addresses 17 through 272.

### 8. Terminal updates

The final call sequence includes a producer whose word result is passed to a consumer, followed by a call yielding a byte and an associated destination address.

The remaining visible effects, in order, are:

1. Store zero through that associated byte destination.
2. Replace G-C with a word constructed from three bytes of another represented storage region as its upper 24 bits and the returned byte as its low eight bits.
3. Store a zero halfword at the routing selector masked with `0x3fffffff`, then logically shifted right by seven.
4. Attempt a call to address zero with three zero arguments.
5. Return only if that call returns.

The halfword address ranges from zero through `0x007fffff`. It need not be aligned.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **First-input truncation.** If the first input is `0x12345678` and the byte store is reachable and writable, B(`0x12345681`) receives `0x78`. Full-word stores of the first input retain all 32 bits.

2. **Repeated-shift zero.** For every 32-bit early shared snapshot, shifting right by 23 and then by 23 yields zero. The corresponding word store and later zero argument must not depend on the original high bits.

3. **Upper-field truncation.** If the selected word is `0xffc00000`, its right-shift-by-22 result is `0x3ff`. The routed byte store writes `0xff`, not a widened 10-bit value.

4. **Fresh shared-byte read.** If G-B changes between its two late reads, the two byte clears may target different addresses. Reusing the first byte value would violate the represented behavior.

5. **Fresh field read.** If an intervening call changes W(first field base + 116), the second low-byte copy uses the changed word.

6. **Stride distinction.** A returned index of 3 selects address 68 for the sixteen-times-scaled word store, but address 32 for a four-times-scaled word store.

7. **Full-word retention.** If the retained field word is `0xa1b2c3d4`, its immediate byte copy writes `0xd4`; subsequent full-word transfers use `0xa1b2c3d4`.

8. **Terminal reachability.** If the final destination store faults, neither the subsequent G-C reconstruction nor the halfword clear is established as occurring. If address zero is not callable, successful normal return is not an acceptance requirement.
