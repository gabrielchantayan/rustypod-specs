### Common conversion and initial stores

The function reads record `0x08`, converts it, and writes the 16-bit result to output `0x0C`. It then reads record `0x0C`, converts it, and writes the 16-bit result to output `0x0E`.

For each conversion, the supplied representation adds 32 to a signed 32-bit input, multiplies by 1024, converts the result to unsigned 32 bits, and selects its upper 16 bits.

The corresponding 32-bit bit-vector transformation is:

\[
C(x)=
\left(
\left((x+32)\times1024\right)\bmod 2^{32}
\right)
\mathbin{\text{logical shift right}}16.
\]

The stored pattern is 16 bits wide. This formula describes the finite-width transformation, not a language-level guarantee for overflowing signed addition or multiplication.

When those signed operations are representable, the stored pattern is also the 16-bit representation of:

\[
\left\lfloor\frac{x+32}{64}\right\rfloor.
\]

For negative results, interpreting the stored pattern as signed 16 bits recovers that signed quantity. Output-field semantic signedness is otherwise not established.

The two conversions are not a snapshot of both record fields. The first output store precedes the second record-field read; overlapping storage can therefore affect the second conversion.
