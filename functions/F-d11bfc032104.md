# F-d11bfc032104

## Purpose

F-d11bfc032104 performs an ordered transformation of memory addressed through integer-valued inputs and implicit context state. It then prepares internal four-byte storage, invokes dependencies, and reaches a terminal operation if the preceding calls return.

No application-level purpose, successful completion condition, or ordinary return value is established.

The central behavioral constraint is **preservation of observation boundaries**. Writes may affect later reads through overlapping addresses. A previously captured value, however, is not automatically refreshed when its source changes. In particular, one word location is sampled twice with intervening writes; those observations may differ.

This contract describes static evidence, not demonstrated execution. It does not establish that arbitrary inputs produce valid addresses or that any dependency returns.

## Behavior

### Address selection and overlap-sensitive ordering

The transformation begins by capturing the signed word at primary-context offset 0x14 and replacing that field with the fourth input. The captured word becomes the basis of a second word read, also at offset 0x14.

The replacement precedes that second read. If the two addressed fields overlap, the second observation must reflect the effects of the replacement. It is not a second use of the original field contents.

A **selection basis** is formed by multiplying the third input by the second observed word. The signed word at selection-basis offset 0x74 becomes the **selected value**.

Two writes separate formation of that basis from observation of the selected value:

- A four-byte write places the third input at third-input offset 0x54.
- A subsequent byte write at secondary-context offset 0x11 derives from the initial primary-context observation.

The selected-value read occurs after both writes. Either write can therefore affect selection through overlap.

A **working basis** is then formed by multiplying the third input by the selection basis. Before subsequent sampling, the third-input-offset-0x54 word is written again, followed by another byte assignment at secondary-context offset 0x11. This later byte derives from the selected value rather than the initial context observation.

These products are integer arithmetic. They do not establish arrays, element scaling, or valid object membership.

### Sampling and capture boundaries

The sampling stage distinguishes four payload observations:

| Observation | Address relationship | Required timing |
|---|---|---|
| Early sample | Working basis plus 0x44 | After the second secondary-context-offset-0x11 update. |
| Retained payload | First input plus 0x74 | After the early sample. |
| Refreshed sample | Working basis plus 0x44 | After the intervening secondary-context writes described below. |
| Late payload | Product of the third input and working basis, plus 0x44 | After the later repeated word write and doubled-basis byte write. |

Between the early and refreshed samples, the selected value is written as a word at secondary-context offset 0x64. A byte derived from the early sample is then written at secondary-context offset 0x09.

The refreshed sample supplies the byte written at working-basis offset 0x11. It must be a fresh word observation: substituting the early sample is not equivalent when either intervening write overlaps the sampled word.

The retained payload is captured before those intervening writes. Its later use does not imply another read at first-input offset 0x74.

After the working-basis-offset-0x11 byte assignment, the third-input-offset-0x54 word receives its third write of the third input. A byte derived from the selected value is then written at twice the working basis plus 0x11. Both writes precede the late-payload observation.

### Final destination capture and write precedence

After the late payload is captured, the signed word at first-input offset 0x14 is observed as the **destination basis**. Thus, this observation follows all earlier addressed writes and may reflect their overlap effects.

The final three byte assignments have a fixed precedence:

| Precedence | Destination | Value supplying the conversion |
|---|---|---|
| First | Selected value plus 0x01 | Retained payload |
| Second | Destination basis plus 0x11 | Late payload |
| Third | Destination basis plus 0x09 | Twice the working basis |

The late payload is captured before the destination basis, and both captures precede this final group.

Changing the original destination-basis source during the first final write does not itself redirect the remaining writes: the basis has already been captured. This guarantee is conditional on the retained representation itself remaining intact.

The doubling used to address the earlier byte write and the doubling supplying the last byte value are separate represented evaluations. Treating them as one retained calculation requires preservation of the relevant arithmetic and state.

## Acceptance examples

These examples are conditional static obligations, not executed tests. They assume valid accesses, supported arithmetic, and intact relevant retained storage. Any proposed overlap must satisfy the stated address relationships.

### Replacement affects dependent addressing

If the initial primary-context word equals the primary-context base, the dependent read addresses the field that has just been replaced. It must observe the fourth input’s replacement rather than an automatically preserved copy of the old field contents.

### Selection includes preceding writes

If selection-basis offset 0x74 coincides with third-input offset 0x54, and the intervening byte assignment does not modify that word, the selected value is the third input written there. Reading selection before that word write would violate the contract.

### Two observations of one word can differ

Suppose the early sample is 0x11223344 and the intervening selected-value word write replaces the sampled word with 0x55667788. Suppose the intervening secondary-context-offset-0x09 byte write does not overlap that word.

Conditional on low-eight-bit character conversion, secondary-context offset 0x09 receives 0x44, while working-basis offset 0x11 receives 0x88. Reusing the early sample for both writes fails this case.

### Captures survive changes to their original sources

If first-input offset 0x74 changes after retained-payload capture without damaging the retained representation, the byte written at selected-value plus 0x01 still derives from the captured payload.

If that byte write changes first-input offset 0x14, the remaining final writes still use the destination basis captured before the group, provided its retained representation remains intact.

### Coincident destinations preserve access order

If the first two final byte destinations coincide and the third is distinct, the second byte assignment replaces the first at their shared destination. Matching only the surviving byte is insufficient: both accesses and their precedence remain part of the contract.

### Shifts are independent

If the first input is 1 at both preparation evaluations, the two initial shift results are 0x10 and 0x100. Obtaining 0x1000 by shifting the first result again does not satisfy this behavior.

### Calls determine reachability

If the fifth input contains 0x123456ab, F-unknown-01 receives its storage address, not that contents value.

If F-unknown-01 does not return, the represented continuation does not reach seventh-input clearing or F-cdec09f5d432.

If it returns after changing the external operand’s source, the later call has no guarantee of receiving that source’s earlier contents. If F-cdec09f5d432 does not return, the terminal operation is not reached through the displayed continuation.
