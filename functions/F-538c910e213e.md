# F-538c910e213e

## Purpose

F-538c910e213e conditionally initializes shared configuration, caches a provider handle, requests an object, and delegates processing when a 32-bit field immediately preceding that object is nonzero.

Three local conditions determine whether delegated processing occurs:

- The initialization guard determines whether initialization runs.
- A cached handle equal to 0xFFFFFFFF suppresses the object request.
- A zero field four bytes before the requested object suppresses delegation.

The function returns zero when either suppression condition applies. Otherwise, it returns the exact 32-bit result of F-f62e01cd4112, retained across a subsequent cleanup-shaped call. Delegation does not imply a nonzero result.

Environment lookup, text parsing, allocation, construction, and cleanup are inferred dependency roles. Their complete semantics, ownership effects, and effects on shared state are not established by this body.

## Behavior

### Initialization guard and text selection

After the selector reads described above, a nonzero guard field skips initialization. Execution proceeds to the cached-handle read through the captured configuration pointer.

A zero guard field enters initialization. The function calls F-f37f1ac64985 with a fixed key-data address. A zero return selects fallback text at byte offset +12 of the captured configuration record. Any nonzero return becomes the selected text address directly. No text copy is performed by this body.

F-3df2c2cdc615 receives the selected text address and the value 0x3A. This value corresponds to an ASCII colon; delimiter searching is an inferred role.

Immediately after that call, the function reads a separate global 32-bit word. This read occurs whether the delimiter result is zero or nonzero. If parsing follows, this retained word becomes the parser’s third argument.

### Delimiter modification and configuration correction

A zero delimiter result skips parsing and skips local correction of configuration offset +4.

For a nonzero delimiter result, the function overwrites the byte at the returned address with zero. It then calls F-8cfd5431cd53 with:

1. The address one byte after the overwritten byte.
2. A fixed format-data address.
3. The previously loaded global word.

Only a parser return equal to 1 selects the signed configuration-field check.

- If the return is not 1, configuration offset +4 is assigned the 32-bit value 1 without reading its previous value for this decision.
- If the return is 1, the field is read as a signed 32-bit integer. Values below 1 are replaced with 1; values at least 1 are left unchanged by this correction.

The parser’s third argument is a loaded word. It is not established to be the address of configuration offset +4, so parser success does not establish that the parser wrote that field.

The overwritten delimiter byte is not restored. The body does not verify that the returned address lies within the selected text.

### Cached-handle decision and request preparation

After initialization, or immediately after a nonzero initialization guard, the function freshly reads the handle from offset +8 of the captured configuration record.

A handle equal to 0xFFFFFFFF causes a zero return without request preparation or an object request. This is the 32-bit representation of signed −1. Zero and every other handle representation pass this local check.

For an allowed handle, the function reads configuration offset +4. The handle and configuration word are retained for the request. Preparation dependencies do not cause these fields to be reread for the request’s arguments.

Request preparation consists of:

The result of F-9b9c1c7483f4 is stored locally, but it is not an explicit argument in the displayed object-request call. No hidden argument or ownership relationship is established by that storage.

### Object request and delegated result

After request preparation, the function resolves the provider dispatch entry at byte offset +16 and clears its lowest two bits. The resulting target receives:

1. The address of a local output slot.
2. The captured provider pointer.
3. The retained handle.
4. The retained configuration word.
5. The original third argument.

The request’s direct return value does not determine the subsequent branch. After the request returns, F-8a5aadac202f receives the request-preparation destination temporary.

Only after this cleanup-shaped call does the function obtain the object address from the output slot and read the 32-bit field four bytes before that address.

- A zero field suppresses delegation. F-8a5aadac202f receives the output-slot address, and the function returns zero.
- A nonzero field permits F-f62e01cd4112 to receive the original first argument, original second argument, object address, and original fourth argument. The delegated result is retained across F-8a5aadac202f receiving the output-slot address, then returned.

Negative field values qualify because the test is for nonzero, not positivity. The field is not established to be a length, reference count, or success indicator.

## Acceptance examples

These are conditional static consequences, not executed tests. Except where stated otherwise, dependencies return normally and leave the state relevant to each example unchanged.

1. **Selector-read distinction.** The provider selector is read first, the configuration selector second, and the configuration selector again for the initialization guard. Subsequent configuration accesses use the pointer captured by the second operation. This ordering does not require different selector values.

2. **Nonzero guard and disabled handle.** A nonzero guard skips initialization. If the captured configuration record contains handle 0xFFFFFFFF, the function returns zero without request preparation.

3. **Nonzero guard and zero handle.** A zero cached handle permits the object request. Zero is not locally treated as disabled.

4. **No delimiter and negative configuration.** During initialization, a zero delimiter result skips local correction. If configuration offset +4 contains −7 and remains unchanged, an allowed request receives that 32-bit representation.

5. **Unaccepted parser result.** A writable nonzero delimiter result is overwritten with zero. Parser returns of zero, −1, or 2 each cause configuration offset +4 to become 1.

6. **Accepted parser result.** A parser return of 1 causes a signed field check: −7 and zero become 1; 6 remains 6. This consequence does not assume that parsing populated the field.

7. **Allocation failure.** A zero allocation result skips all construction-block writes and calls. Handle acquisition still follows.

8. **Late global reads.** If allocation changes the header global, the later header write uses the value read after allocation and the first two allocation writes. If construction-temporary cleanup changes the metadata global, the final metadata write uses its value after that cleanup.

9. **Different construction result.** If construction returns an address other than allocation-plus-16, metadata is still written at returned-address-minus-16, provided that location is valid.

10. **Marker changed by a dependency.** A dependency may change configuration offset +0 before publication. If execution reaches publication, this body then overwrites it with the selected text address after handle storage and both cleanup-shaped calls. Continuous visibility of zero is not required.

11. **Acquisition returns −1.** The handle is stored, both cleanup-shaped calls occur, and the selected text address is published. If the handle remains 0xFFFFFFFF, the fresh handle check returns zero.

12. **Request preparation changes configuration.** Changes to configuration offsets +4 or +8 after their request values were retained do not alter those arguments. Dispatch resolution still occurs after preparation.

13. **Zero object-preceding field.** After request-temporary cleanup, a zero field at object-minus-4 suppresses delegation. Output-slot cleanup still occurs.

14. **Negative object-preceding field.** A field of 0xFFFFFFFF permits delegation. Its exact 32-bit result, including zero, is returned after output-slot cleanup.
