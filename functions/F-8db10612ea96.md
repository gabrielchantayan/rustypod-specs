# F-8db10612ea96

## Purpose

## Behavior

### Initial rejection

The object-address check precedes object-field access. If the address is zero, the function returns zero without invoking F-266f529b8bb5 or reading the object.

For a nonzero object address, a nonpositive requested position also produces zero. This includes the most negative signed 32-bit value, −2,147,483,648.

The supplied representation expresses the nonpositive case through subtraction and signed-overflow information. It must not be interpreted as a simple test of a wrapped subtraction result. Accounting for overflow, no nonpositive position reaches the dependency call or table retrieval.

### Signed upper-bound check

For a positive requested position, the function obtains the signed 32-bit bound at object offset `0x34`.

The requested position is accepted exactly when it is less than or equal to that signed bound, assuming the bound remains stable while evaluated.

Consequences include:

- Equality is accepted.
- A zero bound rejects every requested position.
- A negative bound rejects every requested position.
- A field whose high bit is set is a negative signed bound, not a large unsigned capacity.
- The largest position that can pass is 2,147,483,647, and it passes only with an equally large signed bound.

The comparison is represented using a subtraction result together with signed-overflow information. Its meaning is a signed comparison, including when the subtraction would overflow a signed 32-bit result.

If the check fails, the function returns zero. It does not invoke F-266f529b8bb5 and does not read the table-address field.

### Dependency invocation

After acceptance, the function invokes F-266f529b8bb5 with the original object address as its sole visible argument.

The invocation occurs before reading the table address used for retrieval. Any return value from the dependency is ignored by this function.

The bound is not checked again after the invocation. In particular, this function does not establish that the accepted position remains within a bound changed by the dependency.

No preservation guarantee is available for object fields, globals, backing storage, or memory ownership across this call.

### Post-call retrieval

If F-266f529b8bb5 returns normally, the function reads the 32-bit table address from object offset `0x3c`.

It then selects a word using the original requested position:

- Position one uses byte displacement zero.
- Position two uses byte displacement four.
- Each successive position advances the displacement by four bytes.

The function reads one 32-bit word from the computed address and returns that word unchanged.

There is no explicit check that the post-call table address is nonzero. There is also no post-call validation of the selected entry address, table length, or object lifetime.

### Address arithmetic

The represented address calculation uses 32-bit quantities. The byte displacement corresponds to four times the requested position, minus four, with 32-bit wrapping arithmetic. Adding the table address likewise operates in the represented 32-bit address domain.

A successful signed bounds check does not prevent displacement or address wraparound. For example, position 1,073,741,825 produces a displacement whose low 32 bits are zero. If that position passes the bound check, its computed entry address coincides with the table base under the represented arithmetic.

This describes address computation, not proof that such an access is valid or meaningful. An implementation using wider host arithmetic must not silently substitute a different address calculation if exact compatibility is required.
