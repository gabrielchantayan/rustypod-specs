## Acceptance examples

These examples are conditional static consequences, not executed tests.

1. **Initial narrowing.** If the first scaled base is accessible and its offset-116 word is `0x123456ab`, the direct byte store at offset 1 writes `0xab`.

2. **Entry arithmetic collapse.** If the 32-bit machine interpretation applies, every possible entry fragment makes both large products in the early fixed-address store zero. That store therefore writes zero at address 20, regardless of whether the fragment is zero or 127.

3. **Selector reread.** If the first selector read yields 8 and an intervening dependency changes the same selector source to 12, the first selected write targets address 25 and the later selected write targets address 29. Caching the first selector would not conform.

4. **Byte truncation.** If a payload is `0x00000041`, its four-times byte write stores `0x04`, not a wider value of 260.

5. **Extraction truncation.** If a payload is `0x3ff00000`, masking and shifting produces `0x3ff`; the byte store retains `0xff`.

6. **Different scaled fields.** If a result is 1, its sixteen-scaled-field write begins at address 36, while the subsequent quarter-scaled-field read begins at address 24. Acceptance must not assume those accesses refer to the same word.

7. **Repeated clears.** If a dependency writes a nonzero value at address 36 between two represented clears, the later clear still writes zero. Coalescing the clears changes observable behavior.

8. **Interrupted execution.** If an early indirect call does not return, later stores are not required to occur. The represented prefix does not guarantee completion despite dependency failure.
