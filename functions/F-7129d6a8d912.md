# F-7129d6a8d912

## Purpose

F-7129d6a8d912 invokes F-5fba96760515 and conditionally stores the one-byte value 1 at byte offset 30 from its first input.

The store occurs only when both of these conditions hold:

- The second input is nonzero.
- F-5fba96760515 returns an integer result equal to zero.

The dependency is invoked regardless of whether the second input is zero. A zero second input suppresses the subsequent store, not the invocation.

**Inferred intent:** the destination byte may be a flag. Neither its meaning nor the significance of a zero dependency result is established. This contract does not interpret that result as success or failure.

## Behavior

### Invocation and ordering

On entry, F-7129d6a8d912 invokes F-5fba96760515 with:

1. The second input as the first argument.
2. The third input as the second argument.

The first input is not explicitly forwarded.

This invocation precedes the conditional store. In particular, the second input being zero does not cause an early return before the invocation. Any observable effects of the dependency can therefore occur even when no store follows.

The supplied body contains one dependency invocation and no retry or loop. If the dependency does not return normally, the fragment does not establish any subsequent action by this function.

### Conditional destination update

After a normal dependency return, a nonzero second input permits consideration of the result. An exactly zero dependency result then causes the destination byte to be assigned 1.

The complete decision table is:

| Second input | Dependency result | Explicit destination action |
|---|---|---|
| Zero | Zero | No store |
| Zero | Nonzero | No store |
| Nonzero | Zero | Store one byte containing 1 at base plus 30 |
| Nonzero | Nonzero | No store |

The comparison with the second input is a zero/nonzero distinction, not a positive/nonpositive distinction. A negative second input, if representable by the actual integer type, qualifies as nonzero.

Likewise, any nonzero dependency result suppresses the store. There is no distinction between positive and negative nonzero results.

### Store semantics

The qualifying operation is an assignment, not an increment, toggle, bitwise merge, or read-modify-write operation. The function does not explicitly read the old destination byte.

Consequently:

- An old value of 0 becomes 1.
- An old value other than 0 or 1 also becomes 1.
- An old value of 1 remains numerically 1, but the qualifying path still specifies a store.

No adjacent-byte write is shown. Endianness does not affect the value of this single-byte store.

The effective destination is formed using the first input plus 30. The integer width and overflow rules for that address calculation are not independently established. This contract does not assume wrapping arithmetic, rejection on overflow, or a defined result for an invalid address calculation. Examples below assume that the destination calculation is valid on the actual target.
