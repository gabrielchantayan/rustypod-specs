# F-fd4d7060ab73

## Purpose

F-fd4d7060ab73 evaluates a pattern against a candidate character sequence. Its visible behavior combines an optional leading-character rejection gate, optional wildcard processing, dependency-mediated comparisons, and an in-place rewrite of one exact pattern.

The function is not a read-only predicate. Before applying the rejection gate or matching, it rewrites an exact `*.*` pattern to `*` by replacing its second character with a zero terminator.

Filename-style wildcard matching is inferred intent, not a complete established contract. The supplied static evidence does not establish ordinary literal equality, case folding, path rules, or Boolean-only results from delegated matching.

## Interface

### Inputs

Four inputs are supplied, in order:

1. **Pattern address.** Points to a zero-terminated character sequence. The examined storage must be readable. Its second character must also be writable when the sequence is exactly `*.*`.
2. **Candidate address.** Points to a zero-terminated character sequence whose examined storage must be readable.
3. **Wildcard control.** A signed integer tested for zero versus nonzero. Zero disables special handling of asterisk and question mark. Any nonzero value enables that handling and is forwarded unchanged to F-a7d0f4365c39.
4. **Leading-character exclusion control.** A signed integer tested for zero versus nonzero. A nonzero value enables rejection when the first candidate character compares equal to −27.

No length, capacity, encoding, ownership, or error-output argument is supplied.

### Output

The result is an unsigned integer.

Direct acceptance and rejection paths return one and zero, respectively. The enabled-asterisk path returns the bitwise OR of unsigned dependency results. Consequently, callers must not assume that every nonzero result is exactly one.

## Behavior

### Initial inspection and normalization

Pattern inspection precedes the leading-character gate, regardless of either control value.

The inspection has the following conditional read order:

- Read the first pattern character.
- If it is an asterisk, read the second character.
- If the first two characters are asterisk and period, read the third character.
- If those three characters are asterisk, period, and asterisk, read the fourth character.

Only a zero fourth character triggers normalization. The function then writes zero to the second pattern position. It does not directly overwrite the third or fourth positions.

Thus, exact `*.*` becomes the visible zero-terminated sequence `*`. A longer sequence such as `*.*x` is not rewritten.

This write occurs even when wildcard processing is disabled. It also occurs before an immediately following leading-character rejection. Later dependency calls can overwrite the rewritten storage; persistence through such calls is not guaranteed.

If another invocation uses the same storage, it observes whatever contents remain at that time, including the shortened pattern if nothing has restored or otherwise changed it.

### Leading-character gate

After normalization:

- A zero exclusion control bypasses the gate without reading the candidate through this gate.
- A nonzero exclusion control causes a read of the first candidate character.
- If that character compares equal to −27, the function returns zero immediately.
- Otherwise, matching begins.

Bypassing the gate does not imply that the candidate is never read; later matching still examines it.

The exclusion control is not passed to F-a7d0f4365c39. No corresponding gate on delegated candidate suffixes is established here.

### Sequential matching

Matching begins at position zero in both sequences. Each ordinary iteration reads the current pattern character.

A zero pattern character ends ordinary iteration and leads to the final candidate-termination check. For a nonzero pattern character, processing follows the precedence below.

#### Enabled asterisk

An asterisk with nonzero wildcard control immediately enters delegated matching. This decision precedes the ordinary current-candidate exhaustion check.

After delegated matching, this invocation returns its aggregate result. It does not resume ordinary iteration.

#### Candidate exhaustion

If the enabled-asterisk branch was not taken, the function reads the current candidate character.

When that character is zero, it rereads the current pattern character. If the reread character is an asterisk, it also reads the following pattern character.

This branch returns one only if:

- The reread pattern character is an asterisk.
- Its following character is zero.
- Wildcard control is nonzero.

Every other outcome returns zero.

With stable storage, an enabled asterisk would already have entered delegation earlier in the iteration. This later branch is therefore not the ordinary mechanism for accepting a trailing enabled asterisk. In particular, it does not make a disabled asterisk match an empty candidate.

#### Enabled question mark

For a nonempty current candidate position, a question mark with nonzero wildcard control bypasses the comparison dependency.

It consumes exactly one nonzero candidate character. It cannot consume a terminator because candidate exhaustion has already been checked.

Both matching positions then advance by one.

#### Dependency-mediated comparison

All other nonzero pattern characters take the comparison path. This includes asterisk and question mark when wildcard control is zero.

The observable sequence is:

1. Call F-b09a805215af with no explicit argument shown.
2. Read the current candidate character and pass it as the explicit argument to a second call to F-b09a805215af.
3. Compare the two signed integer results.
4. Return zero if they differ.
5. Otherwise, advance both matching positions by one character.

No explicit pattern-character argument is shown for the first call. The evidence therefore does not establish direct character equality or equality after a particular transformation.

The first call occurs before the candidate-character read used for the second call. If the first call changes candidate storage, the second call can receive a different value from the one previously read during the exhaustion check, including a zero character.

Equality of the dependency results permits advancement; it does not independently prove any relation between the visible pattern and candidate characters.

### Pattern termination

When an ordinary iteration reads a zero pattern character, the function reads the candidate character at the current candidate position.

- A zero candidate character produces one.
- A nonzero candidate character produces zero.

Outside delegated matching, a remaining candidate suffix is therefore rejected even if all preceding comparison decisions allowed advancement.

### Delegated asterisk matching

At an enabled asterisk, the function forms a pattern-continuation address immediately after that asterisk. It uses an unsigned accumulator initially equal to zero.

Starting at the current candidate position:

- Read the candidate character.
- If it is nonzero, call F-a7d0f4365c39 with the pattern-continuation address, the current candidate-suffix address, and the original wildcard-control value.
- Bitwise-OR the result into the accumulator.
- Advance the candidate position by one and repeat the candidate-character check.

When a candidate-character check encounters zero, the function makes one additional call to F-a7d0f4365c39 using that terminating position. It returns the bitwise OR of this final result and the accumulated earlier results.

With stable candidate storage, every suffix is attempted in increasing position order, including the empty suffix. For remaining candidate text `ab`, the attempts use `ab`, `b`, and the empty sequence.

There is no success short circuit. An earlier nonzero result does not suppress later calls.

These suffix descriptions are conditional on storage stability. Candidate checks occur between dependency calls, and those calls are not known to preserve the candidate. They may change where a later zero is encountered. Likewise, the final call is selected because the caller just observed a terminator; the dependency is not known to preserve that terminator during its own execution.
