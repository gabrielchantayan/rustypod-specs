# F-9c4863050cb8

## Purpose

F-9c4863050cb8 conditionally invokes an indirect operation on an address derived from a resolved descriptor. Dispatch requires an available selection, an initially nonzero selection value, approval from a gating dependency, nonnegative range arguments, and a successful unsigned range-end comparison.

The callable target is obtained from a shared indirect-target slot on the successful dispatch path. It is not established as a fixed operation. Earlier dependency calls may change that slot; the function does not visibly capture its value before those calls.

On local rejection, the function may record a diagnostic in the supplied context. It writes only when the selected diagnostic is nonzero and the context’s existing diagnostic word is zero.

The operation’s meaning is unresolved. Its arguments do not establish whether it reads, writes, fills, transfers, or performs some other action.

This contract describes static evidence. No runtime tests have been performed.

## Behavior

### 1. Obtain a selection

The function first invokes F-b44c6ce96792 with no explicit arguments.

If that dependency returns null, the function returns immediately. On this path, the function itself does not read either diagnostic source, inspect the context, invoke the gate or resolver, or read the shared indirect-target slot. Effects performed inside F-b44c6ce96792 remain possible.

For a nonnull result, the function:

1. Reads the default shared diagnostic source.
2. Reads the selection result’s first word.

If the selection word is zero, execution proceeds to diagnostic handling using the captured default diagnostic. No gate, resolver, or indirect operation is invoked.

### 2. Gate the operation

An initially nonzero selection word causes a call to F-5028f4afa8de, with no explicit arguments. A zero result rejects the operation; any nonzero result permits resolution.

After the gate returns, the function rereads the default diagnostic source. This reread occurs whether the gate approves or rejects.

Consequently, the diagnostic used on gate rejection is the value captured after the gate, not necessarily the earlier value. The gate’s preservation of shared diagnostics, selection storage, the indirect-target slot, or context memory is not established.

If the gate rejects, execution proceeds to diagnostic handling without resolution.

If the gate approves, the function rereads the original selection result’s first word for the resolver argument. There is no second nonzero check. A selection changed to zero by the gate is therefore forwarded as zero.

### 3. Resolve a descriptor

On approval, F-a01d4dfb5f88 receives:

1. The context-derived interior address at integer-word displacement 690.
2. The selection word reread after the gate.

The resolver’s result becomes the descriptor used for subsequent accesses. No local null or validity check is performed.

After the resolver returns, the function reads the alternate diagnostic source. This occurs before either range-sign check. Resolution and the alternate diagnostic read therefore occur even when a range input is negative.

Effects of the resolver may include changes to shared diagnostics, the shared indirect-target slot, or other reachable memory. No preservation guarantee is established.

### 4. Evaluate the range

The checks proceed in this order:

1. The extent must be nonnegative.
2. The offset must be nonnegative.
3. The unsigned interpretation of their sum must be no greater than the unsigned interpretation of the descriptor’s second word.

A negative extent skips the offset check and descriptor-bound read. A nonnegative extent with a negative offset also skips the descriptor-bound read.

When both inputs are nonnegative, the descriptor’s second word is read for the comparison. Equality is accepted. Zero extent is permitted and does not independently suppress dispatch.

The bound is interpreted as unsigned for comparison. Its high bit does not cause rejection merely because the same word would be negative under a signed interpretation.

#### Arithmetic limits

The supplied representation adds the signed range inputs before converting the result to unsigned.

Under the apparent 32-bit model, when both inputs are nonnegative and their mathematical sum is at most 2,147,483,647, the comparison is straightforward: the sum must be at most the descriptor’s unsigned 32-bit bound.

Larger sums exceed the signed 32-bit range. The supplied representation does not independently establish the original execution semantics for that overflow. Under an explicitly assumed wrapping 32-bit execution model, the resulting bit pattern would be compared as unsigned. That conditional interpretation is not a guaranteed behavior of the supplied signed expression.

The subsequent base-plus-offset addition has a separate unresolved overflow issue. Passing the range comparison does not prove that address construction is representable.

### 5. Dispatch through the shared target slot

If the range checks succeed, the indirect operation receives:

1. The descriptor’s first word plus the offset.
2. The fifth input, unchanged.
3. The extent, unchanged.

No element-size scaling is visible in the first argument’s addition.

The function obtains the callable target through a shared indirect-target slot as part of this successful dispatch. This is an additional global read, distinct from the diagnostic-source reads.

The slot is not visibly read or captured before selection acquisition, gating, or resolution. Those dependencies may change it. The target used must therefore not be assumed to be the slot’s entry-time value or a fixed target identified independently of the slot.

The supplied representation does **not** establish an evaluation order between reading the target slot and evaluating the call arguments, including reading the descriptor’s first word. This contract requires those reached accesses but imposes no relative order between them.

The reached target must be callable with the supplied arguments for normal completion. There is no visible target-null check, initialization check, or fallback.

The supplied representation models the transfer as an indirect call followed by return, while explicitly indicating uncertainty in recovery of that transfer. No operation result is inspected. If the operation returns normally under that model, the function returns without local diagnostic handling.

### 6. Handle local rejection

All local rejections except the initial null-selection return reach conditional diagnostic handling.

| Rejection | Captured diagnostic used |
|---|---|
| Initial selection word is zero | Default diagnostic read before that selection-word read |
| Gate returns zero | Default diagnostic reread after the gate |
| Range rejected after resolution | Alternate diagnostic read after the resolver |

If the captured diagnostic is zero, the function returns without reading the context’s diagnostic word.

Otherwise, it reads the context’s first word:

- If that word is zero, the function writes the captured diagnostic there.
- If that word is nonzero, it leaves it unchanged.

The diagnostic source is not reread during this final step. An existing nonzero context diagnostic is preserved by this local logic, but dependencies may already have modified the context.

Rejection therefore does not guarantee a new diagnostic write.
