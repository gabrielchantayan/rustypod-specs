## Behavior

### Widths and ordering rules

Visible memory accesses are 8, 16, or 32 bits. Byte stores retain the low eight bits; halfword stores retain the low sixteen bits. Neither necessarily replaces an enclosing word.

Halfword loads are signed 16-bit values widened for arithmetic. Character signedness is unresolved. A high-bit-set character may therefore produce different address operands and widened halfword payloads depending on the actual character interpretation.

Address calculations are represented using 32-bit integer operations, including multiplication, doubling, and left shifts. Overflow, signed-shift behavior, address wrapping, and faults are documented_only; this contract does not replace them with unlimited-precision arithmetic or assume modular behavior.

All ordering below matters when accesses alias. A previously captured value remains distinct from a later reread of its source. No disjointness, atomicity, volatility, or concurrent-memory model is established.

### Initial mutations

The initial boundary comprises three stores, in order:

- A word containing entry base B at entry base A plus `0x44`.
- A word containing the second argument at entry base B plus `0x14`.
- The fourth argument’s byte at entry base C plus `0x11`.

A signed halfword is then read at entry base C plus entry base B. Its widened value, added to the second argument, selects a character read.

The entry-supplied byte is subsequently written at entry base B plus `0x1D`. The character, widened to a halfword, is stored at the signed-halfword value plus entry base B. Finally, a word is read at entry base B plus `0x44`.

The first three stores can affect either initial read through overlap. All preceding writes can affect the final word read.

### Repeated global-access boundary

Each G1–G7 stage starts with the same ordered boundary, using the roles identified below:

1. The working base receives its own address as a word at offset `0x54`.
2. That stage’s global is captured as a 32-bit value.
3. A separate reference to the same global supplies the word stored at the propagation base plus `0x44`.
4. The incoming word is stored at the captured-global value plus `0x14`.

The capture and payload reference are not one entry-time snapshot. The working-base self-address store precedes both global references and may overlap their source. The propagation store follows the payload reference and precedes the captured-global-derived `0x14` store; it can overlap the global location or that later destination.

### G1: retained traversal source

Entry base C plus `0x11` receives the low byte of twice entry base C. A signed halfword at entry base C plus captured G1 then selects a character read when added to the incoming word.

A fresh word from the first argument plus `0x64` is stored at this signed-halfword value plus `0x54`. The new character-derived base plus `0x0D` receives the incoming word’s low byte.

A word read from captured G1 plus `0x64` becomes the **retained G1 word**, preserved for later sum-addressed stores and traversals. The character is then stored as a halfword at the signed-halfword value plus captured G1. Only afterward is the next incoming word read from captured G1 plus `0x44`.

### G2: overwrite and reread

Entry base C plus `0x11` again receives the low byte of twice entry base C. A fresh first-argument `0x64` word is captured before the signed-halfword read at entry base C plus captured G2 and the character read at that halfword value plus the incoming word.

The subsequent writes, in order, are:

- Captured G2’s low byte at first argument plus `1`.
- Incoming word’s low byte at captured G2 plus `0x0D`.
- Retained G1 word at captured G2 plus `0x44`.
- Captured G2’s low byte at the new character value plus `0x0D`.
- The character as a halfword at the signed-halfword value plus captured G2.

The next incoming word is then reread from captured G2 plus `0x44`. Intervening byte or halfword writes may prevent it from equaling the retained G1 word.

### G3: changed traversal roles

Entry base C plus `0x11` receives the low byte of the first-argument `0x64` word captured during G2. A new first-argument `0x64` word is then captured for G4.

The ensuing reads occur in this order: entry base C plus `0x44`; the signed halfword at entry base C plus captured G3; incoming word plus `0x74`; and entry base C plus `0x14`.

The loaded `0x44` value becomes the G3 field base. The loaded `0x74` value supplies both its `0x0D` byte payload and the second operand of the halfword-store destination. That halfword store carries the low sixteen bits of the G3 field base.

The next incoming word is read from the loaded `0x74` value plus `0x44`. The loaded entry-base-C `0x14` value becomes G4’s working base.

### G4: byte mutation before traversal reads

The working base plus `0x11` receives the low byte of the first-argument `0x64` value freshly captured during G3. This store precedes both the word read at working base plus `0x44` and the signed-halfword read at working base plus captured G4.

The incoming word plus `0x15` then receives captured G4’s low byte. The incoming word itself is stored at captured G4 plus `0x44`.

Only after these mutations is a word read at the newly loaded field base plus `0x74`. Its value participates in the destination of a halfword store containing the field base’s low sixteen bits. The next incoming word is read from that traversal value plus `0x44`.

### G5: sum-addressed retained-word storage

The working base plus `0x11` first receives the low byte of twice that base. A fresh first-argument `0x64` word is then captured for G6.

Next come the working-base `0x44` word read and the signed-halfword read at working base plus captured G5. The next working base is read at that signed-halfword value plus `0x14`.

After that read, the newly loaded `0x44` field base receives its own address at `0x54`. The retained G1 word is then stored at captured G5 plus the incoming word. Captured G5 plus `0x14` is subsequently overwritten with the field base.

A fresh read at retained G1 word plus `0x44` supplies the byte written at captured G5 plus `0x0D`. The next working base plus `0x0D` receives the field base’s low byte, followed by a halfword store containing that field base at the signed-halfword value plus captured G5.

The next incoming word is finally read from captured G5 plus `0x44`.

### G6: intervening mutations before the next-base read

The old working base plus `0x11` receives the low byte of the first-argument `0x64` word captured during G5. A new first-argument `0x64` word is captured; its low byte is retained for this stage and G7.

The old working base’s `0x44` word and the signed halfword at old working base plus captured G6 are then read.

Before reading the next working base, three mutations occur in order:

- The old working base is stored at incoming word plus `0x54`.
- The newly captured byte is written at old working base plus `0x11`.
- Captured G6 is stored at the loaded field base plus `0x44`.

Only then is the next working base read from the signed-halfword value plus `0x14`. Those mutations can therefore affect that read.

The loaded field base next receives its own address at `0x54`. This precedes the retained-G1-word store at captured G6 plus incoming word. Captured G6 plus `0x14` is then replaced with the field base.

A fresh retained-G1-word `0x44` read supplies the byte for captured G6 plus `0x0D`. The next working base plus `0x0D` receives the field base’s low byte. A halfword containing the field base follows at the signed-halfword value plus captured G6, before the final word read from captured G6 plus `0x44`.

### G7 and arithmetic traversal

The working base plus `0x11` receives the byte retained during G6. A word is read at working base plus `0x44`, followed by a signed halfword at working base plus captured G7.

Before product-addressed traversal, two identical store pairs occur. Each pair stores the signed-halfword value as a word at that value plus `0x54`, then writes the working base’s low byte at captured G7 plus `0x11`. Both pairs belong to the represented sequence.

The signed halfword multiplied by the loaded working-base `0x44` word selects a word read at product plus `0x44`. Its result selects a `0x74` word read; that result selects a `0x14` word read, yielding a traversal base.

The traversal base’s `0x14` word is saved before the field is overwritten with twice G7’s working base. The saved word then selects another `0x14` word read. Multiplying this newly read value by the signed halfword produces the **retained-value product**.

Before reading that product plus `0x74`, the function stores the signed-halfword value at its own `0x54` field and writes the saved traversal word’s low byte at captured G7 plus `0x11`. The following product-derived `0x74` read yields the **final retained value**.

Multiplying the retained-value product by the signed halfword produces the **arithmetic base**. Before reading its `0x44` word, another signed-halfword self-address store occurs, followed by a captured-G7 `0x11` byte store containing the final retained value’s low byte.

The arithmetic-base `0x44` word is then read, followed by the first argument’s `0x74` word. The final retained value is stored at captured G7 plus `0x64`, and the earlier arithmetic-base `0x44` word’s low byte is written at captured G7 plus `9`.

A fresh arithmetic-base `0x44` read supplies a byte store at arithmetic base plus `0x11`. Another signed-halfword self-address store follows, before the final retained value’s low byte is written at twice the arithmetic base plus `0x11`.

Finally, a word is read at signed halfword multiplied by arithmetic base, plus `0x44`; then the first argument’s `0x14` word is read. Subsequent byte stores place:

- The saved first-argument `0x74` word’s low byte at final retained value plus `1`.
- The last product-addressed word’s low byte at the newly loaded first-argument `0x14` base plus `0x11`.
- The low byte of twice the arithmetic base at that same base plus `9`.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Initial signed addressing.** A loaded halfword of `−2` selects the character address using second argument minus two, subject to actual arithmetic semantics. Unsigned `65534` is not interchangeable.

2. **Global observation boundary.** If a stage’s working-base `0x54` store overlaps its global, the capture and separate payload reference occur after that mutation. Entry-time global contents are not the required values.

3. **G4 byte-before-read aliasing.** If G4’s `0x11` byte store overlaps its subsequent `0x44` word read, that read observes the resulting memory state. Its byte payload comes from the G3 first-argument `0x64` capture.

4. **G5 ordering.** G5’s doubled-working-base byte store precedes its fresh first-argument `0x64` read. Its loaded field-base self-address store follows the next-working-base read and precedes the retained-word sum-addressed store.

5. **G6 traversal boundary.** If one of G6’s three intervening mutations overlaps the signed-halfword-derived `0x14` word, the next-working-base read reflects that mutation, rather than an earlier memory snapshot.

6. **G7 repeated effects.** The initial G7 sequence contains two self-address word stores and two corresponding byte stores, not a single pair.

7. **Product-read aliasing.** If the self-address or saved-traversal-word byte store overlaps the retained-value product’s `0x74` word, the final retained-value read occurs after those stores.

8. **Late reread.** If intervening stores modify arithmetic base plus `0x44`, its later byte payload comes from the reread, not the previously captured word.

9. **Dependency mutation and cutoff.** If F-indirect-entry changes G8 and returns, the subsequent call receives the later read value. If it does not return, post-call clearing and the second call are not reached.

10. **Partial fault.** If the initial three stores succeed and the following halfword read faults, no rollback or normal error return is established.
