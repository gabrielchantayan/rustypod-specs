# F-6824980c644b

## Purpose

F-6824980c644b evaluates a context, a state structure, and an optional linked sequence of candidate records. It returns an opaque 64-bit value and writes three 32-bit outputs: a selected-record word, status flags, and an item position.

The visible control flow evaluates candidates but never adopts them. Both preliminary and linked-candidate adoption require conditions that are visibly false. Consequently, normal completion reports selected record zero and position zero, and returns the baseline established before candidate evaluation. Candidate-related dependency calls and external reads still occur.

This contract preserves that distinction. Apparent ranking or selection intent does not establish a functioning selection algorithm.

## Behavior

### Entry and empty-result shortcut

The function initializes internal selected-record, position, and accumulated-status values to zero; these initializations are not output writes.

It then reads, in order:

1. The state’s lookup key.
2. The low and high external words of the initial baseline.
3. The container address and its candidate-chain head.

The lookup key and head are captured for subsequent processing. The head is not refreshed from the container after dependency calls.

Only a captured zero head permits the empty-result shortcut. F-7c42676bf762 is called with the explicit arguments:

- Context address, captured key, `0xffffffff`, zero, zero, zero, selector `0x3f`, zero.

If that lookup returns zero, A7 equal to zero qualifies immediately. Otherwise, when A7 is nonzero, F-79ce46539395 receives the captured key, A7, a freshly read context word at `+0x04`, and a temporary’s address. Its zero return qualifies.

On qualification, the function writes zero to A9, then A8, then A10. Only afterward does it read the dedicated external 64-bit result pair and return that value.

A nonzero captured head skips both shortcut dependencies. A successful shortcut lookup, or a nonzero optional-check result, continues evaluation.

### Baseline lookup

F-7c42676bf762 next receives:

- Context address, captured key, `0xffffffff`, zero, A5, A6, selector `0x03`, zero.

A zero result retains the initial baseline and zero accumulated status.

For a nonzero result, the function:

1. Writes zero to A8.
2. Loads the matched-baseline external 64-bit pair.
3. Sets accumulated status to `0x100`.
4. Reads the result’s 16-bit flags.

If flag `0x0002` is set, it writes `0x400100` to A9 and one to A10, then reads and returns the dedicated external result pair. No preliminary or linked-candidate processing follows.

Otherwise, it examines the associated object’s optional pointer at `+0x10`. If nonzero, the referenced first word is supplied to F-b3a54d881220. F-600a7e8b5f6d is then called with no explicit arguments. F-c4b34006a13c receives the latter result’s low/high halves followed by the former result’s low/high halves. Its result replaces the baseline.

The optional pointer is read for its test and read again for dereferencing on the nonzero path; the representation does not establish a single cached pointer value.

### Preliminary candidate computation

The function always reads an external fallback word at this point. If the captured head is nonzero, it subsequently reads that head’s value-array pointer and first element, replacing the fallback word. Thus the fallback read occurs even when its value is discarded.

The baseline is saved before F-9e5e664c8ae7 converts the chosen word into a preliminary 64-bit intermediate.

A sentinel-key lookup with selector `0x3c` follows, using the same eight-argument pattern as the baseline lookup, with A5/A6 retained.

- If it fails, preliminary flags are zero; selectors `0x18` and `0x24` are skipped.
- If it succeeds, selector `0x18` is queried. Immediately after that query, the external replacement-flag word is read **regardless of whether the query succeeded**. Flags initially become `0x200`.
- A successful `0x18` query invokes F-596e18a33aec on the intermediate and an external 64-bit operand, and replaces the flags with the previously read replacement word.
- Selector `0x24` is queried whenever the outer `0x3c` query succeeded, independently of the `0x18` outcome. Success ORs in `0x20000` and invokes F-596e18a33aec again, with another read of the external operand.

When A7 is nonzero, F-79ce46539395 is called with the captured key, A7, a newly read context word, and the temporary’s address.

- Zero return invokes F-600a7e8b5f6d, F-c4b34006a13c, then F-1b22d7e17791. These calls transform the preliminary intermediate while retaining its pre-sequence halves as operands.
- Nonzero return ORs in `0x100200`, or `0x300200` when the temporary is nonzero.

F-11ed8242c40c receives the intermediate halves followed by the saved baseline halves. No return value is visibly consumed.

The adoption condition is false: the controlling boolean is always true, while adoption requires false. Neither the preliminary flags nor its intermediate replaces the saved baseline or accumulated output status.

### Suffix capture and traversal entry

After preliminary processing, the state byte at `+0x15` is read once:

- Bit `0x08` clear selects suffix `0x83`.
- Bit `0x08` set selects suffix `0x03`.

A separate external 64-bit starting-value pair is loaded **before every candidate-head test**. This includes:

- The initial test, even when the captured head is zero.
- Each test that enters a candidate.
- The final test after reading a zero next pointer.

For a terminating chain containing N processed candidates, this pair is loaded N + 1 times. The last loaded value is unused. These loads initialize candidate computation; they do not replace the saved baseline.

### Item scan

Each candidate begins with unsigned 32-bit item position zero and temporary flags zero.

Every scan-condition check freshly reads the candidate’s signed 32-bit count. Scanning continues while that count exceeds the position interpreted as signed 32 bits.

For each attempted item, the function reads the current item-array pointer and element. F-7c42676bf762 explicitly receives the context address, captured key, and item word. The surrounding representation associates these calls with the captured suffix and A5/A6, but does not establish a complete effective signature.

A zero lookup result stops scanning without incrementing the position.

A successful result ORs `0x1000` into temporary flags. If its 16-bit flags include `0x0001`:

1. Temporary flags become exactly `0x5000`, replacing their previous value.
2. The associated object’s word at `+0x38` is read.
3. If that word is zero, its optional pointer at `+0x10` is read.
4. A zero optional pointer skips this item’s combination call.
5. A nonzero optional pointer causes its first word, incremented by one in a 32-bit expression, to be supplied to F-b3a54d881220 with explicit second argument zero.
6. Except for the skip above, F-c4b34006a13c is called, and its result becomes the intermediate. That call exposes no explicit arguments.

The position increments after every successful lookup, including the skip case.

After scanning, F-600a7e8b5f6d receives the current intermediate halves. The function then reads the candidate’s current value-array pointer and element at the final position and supplies that word to F-9e5e664c8ae7. Two F-c4b34006a13c calls combine the converted value, scan intermediate, and F-600a7e8b5f6d result, in that order of stages.

### Completion flags and incomplete-item queries

After those dependencies, the candidate byte at `+0x18` is read. If it is nonzero and `0x4000` is absent, the count is read again. Equality between that count’s 32-bit representation and the position adds `0x400000`.

The incomplete-scan check independently rereads the signed count and compares it against the signed interpretation of the position. It does not reuse the scan’s last count or the completion-check count.

If incomplete, the current item-array pointer and element at the final position are read again. Item-specific queries follow, associated with selectors `0x3c`, `0x18`, and `0x24`:

- Failure of the outer query skips the remaining two.
- Outer success followed by `0x18` failure ORs `0x2000` into the prior scan flags.
- `0x18` success instead ORs `0x12000` into the prior scan flags and invokes F-596e18a33aec.
- After outer success, `0x24` success additionally ORs `0x20000` and invokes F-596e18a33aec again.

Each transformation reads its external operand pair at the call site. The full effective signatures of these item-specific queries remain unresolved.

### Mask processing and non-adoption

Only candidates with nonzero temporary flags enter mask processing.

The state mask’s high word is first read to test its top bit. If that bit is clear:

1. The low mask word is loaded.
2. The high mask word is loaded again.
3. The candidate’s signed count is captured once.
4. A signed index traverses from zero while below that captured count.

Unlike the item scan, this traversal does **not** reread the count across helper calls. It does read the candidate’s item-array pointer and current element during each iteration. A helper can therefore affect later array reads without changing the captured iteration bound.

Each unsigned item value below `0x3f` causes F-5bbdce2c8eb3 to be called with explicit arguments **1 and 0**. The complement of its returned low/high halves is ANDed into the corresponding local mask halves. No current-item argument is explicit; a bit-shift interpretation is not established.

If the resulting local mask is zero, `0x80000` is ORed into candidate flags and F-9f634613286e receives the intermediate halves and `0xffffffff`. No mask writeback is visible.

F-11ed8242c40c receives the candidate intermediate and saved baseline. Adoption remains impossible: the tested top-bit branch already has a true controlling boolean; the other branch explicitly makes it true. Saved record, position, flags, and baseline remain unchanged.

The next-candidate pointer is read after candidate processing. The external starting pair is then loaded before testing that pointer.

### Normal completion

The function writes, in order:

1. Zero to A8.
2. Accumulated baseline status, either zero or `0x100`, ORed with the captured suffix, to A9.
3. Zero to A10.

It returns the saved baseline.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, storage is disjoint and dependencies leave relevant inputs unchanged.

1. **Empty shortcut:** Zero head, failed `0x3f` lookup, and A7 zero produce writes A9 = 0, A8 = 0, A10 = 0, followed by the dedicated result read. No preliminary fallback or traversal-starting-pair read occurs.

2. **Immediate flagged return:** Baseline lookup success with flag `0x0002` produces A8 = 0, A9 = `0x400100`, A10 = 1, and returns the dedicated result without candidate computation.

3. **Nonzero head:** Preliminary computation still reads the external fallback word before replacing it with the head’s first value-array word.

4. **Failed `0x18`:** After successful preliminary `0x3c`, a failed `0x18` still precedes a replacement-flag-word read. Flags remain `0x200` before the subsequent `0x24` outcome.

5. **Traversal reads:** One processed candidate followed by zero causes two starting-pair loads. A zero captured head on a non-shortcut path causes one such load.

6. **Normal outputs:** Failed baseline lookup and clear suffix-control bit produce A8 = 0, A9 = `0x83`, A10 = 0, returning the initial baseline. A matched baseline and set suffix-control bit produce status `0x103`.

7. **Array boundary:** Count two with two successful lookups reaches value-array index two, not index one.

8. **Count mutation:** If the first successful item lookup changes count from two to one, the next scan check uses one and stops at position one. Later completion checks use whatever count exists after intervening transformations.

9. **Mask snapshot:** If mask processing captures count two and the first helper changes the candidate count to zero, the mask loop still reaches index one. Its array pointer and element are read at that later iteration.

10. **Mask threshold and selection:** Item `0x3e` invokes the mask helper with 1 and 0; item `0x3f` does not. Neither helper activity nor comparison outcomes visibly selects a candidate.
