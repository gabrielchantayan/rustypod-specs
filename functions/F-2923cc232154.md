# F-2923cc232154

## Purpose

F-2923cc232154 performs a two-write link update between two caller-supplied memory locations. It copies a four-byte value from offset 12 of the first location into offset 16 of the second location, then stores the second location’s address representation at offset 12 of the first location.

The ordering matters: the copied value is obtained before the first location’s link field is replaced.

**Inferred intent:** this resembles inserting an element at the front of a singly linked structure. Under that interpretation, the first location contains a current-head field and the second location contains a next-link field. The supplied evidence does not establish those object types, the meaning of the previous value, or any surrounding container invariants.

The established contract is the memory transformation, not successful construction of a valid list.

## Behavior

### Successful execution

For valid memory accesses, the function performs these observable field operations in order:

1. Reads the four-byte value at offset 12 of the first location.
2. Writes that value to the four-byte field at offset 16 of the second location.
3. Writes the second argument’s 32-bit address representation to the four-byte field at offset 12 of the first location.

The final operation does not reread the original field. No access through the copied value is shown.

When the two field ranges do not overlap, the resulting state is:

- The second location’s field contains the first location’s previous four-byte value.
- The first location’s field contains the second location’s address representation.
- All other memory is unchanged by the explicit operations shown.

The previous contents of the second location’s field are discarded without being read by this function.

### Aliasing and overlap

- The original four bytes at offset 12 are copied to offset 16.
