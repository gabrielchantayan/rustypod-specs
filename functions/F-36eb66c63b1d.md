# F-36eb66c63b1d

## Purpose

F-36eb66c63b1d performs conditional preliminary notification and state-dependent entry actions, then dispatches an event through an object’s method table. If the primary handler returns zero, a later condition may select a fallback handler.

The labels `EnterDefault` and `EnterVolume` suggest entry-related actions. Their application meaning is inferred, not established. Event types, nested subtypes, object states, and flags are specified numerically below.

One entry-related dependency receives a value read from an external global datum **when that call is reached**. This is not an established constant or entry-time snapshot. Earlier dependencies may change the global before the read.

This contract describes static evidence only. No runtime tests have been performed.

## Interface

### Arguments and result

The function receives four arguments:

| Argument | Established role |
|---|---|
| Object | Address of mutable object storage containing a method-table reference and fields used below. |
| Event | Address of an event record, carried in a 32-bit integer-shaped argument in the supplied representation. |
| Auxiliary A | Opaque 32-bit value copied into addressable temporary storage. |
| Auxiliary B | Opaque 32-bit value copied into addressable temporary storage. |

The result is a 32-bit integer:

- A nonzero primary-handler result is returned unchanged.
- If the primary result is zero and fallback runs, a nonzero fallback result is returned unchanged.
- Otherwise, the result is zero.

Negative handler results count as nonzero; they are not normalized or interpreted as a separate error category.

## Behavior

### Preliminary notification

The function first reads the event type.

For type `0x16`, it reads the nested-record address, then the nested subtype. If that subtype is `0x2503`, it reads the object word at `0x184`, converts that word to a character, and calls F-26bcb12c385a with the object and converted value.

The condition also excludes subtype `0x2502`. That exclusion adds no further restriction once equality with `0x2503` is required. Subtype `0x2502` does not trigger notification.

The dependency’s result is ignored. Notification does not consume the event or bypass later processing.

Because subsequent stages reread the event, mutations made by this dependency can affect the special-event path, primary dispatch, and eventual fallback.

### Temporary argument storage

After preliminary processing, the function initializes four addressable local storage locations from the object argument, event argument, auxiliary A, and auxiliary B.

These are local copies, not the caller’s argument slots. Later dependencies receive their addresses on particular paths.

The original object and event argument values remain the values used for field access and dispatch. Overwriting either corresponding local copy does not by itself redirect subsequent dispatch. A dependency may still affect reachable object or event storage through pointers contained in those copies.

### Special-event state selection

The function reads the event type again. Only type `0x70001` receives state-specific processing.

For that type, the function reads the object word at `0x140`, converts it to a character, and selects one path:

| Selected state | Actions before ordinary dispatch |
|---|---|
| `0` | No state-specific action. |
| `1` | Volume-entry sequence. |
| `2` | Dynamic entry `0x158`, then conditional default entry and volume entry. |
| `3`, `4`, `6` | Conditional default entry and volume entry. |
| `5` | Call F-979606fd565e using a reached-call read of the external global datum. |
| Other converted values | No state-specific action. |

The selected path is not restarted if a dependency changes the state field.

For state `2`, dynamic entry `0x158` receives the object and runs before the default-entry flag is read. Its result is ignored.

### Conditional default entry

For selected states `2`, `3`, `4`, and `6`, the function reads the object word at `0xB0` and converts it to a character.

If the converted value equals `1`, the following calls occur in order:

1. F-9b9c1c7483f4 receives the address of the local event copy, the label `EnterDefault`, and the address of the local object copy.
2. Dynamic entry `0x11C` receives the original object argument and the opaque 32-bit result returned by F-9b9c1c7483f4.
3. F-8a5aadac202f receives the same local-event-copy address used by the first call.

If the flag does not equal `1`, all three calls are skipped.

Both outcomes continue to volume entry. For state `2`, changes made by dynamic entry `0x158` can therefore determine whether default entry occurs.

### Volume entry and external-global read

For selected states `1`, `2`, `3`, `4`, and `6`, the function performs this sequence:

1. F-9b9c1c7483f4 receives the address of the local auxiliary-B copy, the label `EnterVolume`, and the address of the local auxiliary-A copy.
2. Dynamic entry `0x11C` receives the original object argument and that dependency’s opaque 32-bit result.
3. F-8a5aadac202f receives the same local-auxiliary-B-copy address used by the first call.
4. The function writes byte value `5` at object offset `0x140`.
5. The function reads the external global datum and calls F-979606fd565e with the original object argument and the value obtained by that read.

The global read occurs **after** the preceding dependency calls and **after** the one-byte state write. It must not be modeled as a value captured at function entry or before the entry sequence. Any earlier dependency may change the global; preservation is not established.

The concrete global value, access width, application meaning, and ownership implications are unknown. No additional ordering between the global read and unrelated argument preparation is established.

For selected state `5`, the function proceeds directly to the global read and F-979606fd565e call. It performs neither entry-label sequence nor the explicit state-byte write on that path. The argument is still read at the reached call, not taken from an assumed immutable or entry-time value.

F-979606fd565e’s result is ignored.

### Primary dispatch

After special processing, the function reads the event type again.

If the current type is `0x16`, it reads the current nested-record address and then the current nested subtype. It chooses:

- Dynamic entry `0x10C` for type `0x16` with subtype `0x2A`.
- Dynamic entry `0x110` otherwise.

The selected handler receives the original object and event argument values.

A nonzero result is returned immediately. On that path, the function performs no fallback-condition reads.

Earlier event or subtype observations are not reused for this decision. Entry dependencies, preliminary notification, or F-979606fd565e may have changed the event before dispatch.

### Conditional fallback

If the primary handler returns zero, the function reads the event type again.

Only when this current type equals `0x0F` does it read the event word at `0x08`, followed by the object word at `0x50`.

If those 32-bit values are equal, it calls dynamic entry `0xE0` with the original object and event arguments. A nonzero fallback result is returned unchanged.

The function returns zero if:

- The current event type is not `0x0F`.
- The comparison values differ.
- The fallback handler runs and returns zero.

The fallback decision therefore uses post-primary-handler state, not the state observed before primary dispatch.

## Side effects

### Direct storage changes

The only explicit write to object storage is the one-byte store of `5` at `0x140` on the volume-entry path.

The function also initializes local copies and exposes their addresses to dependencies. Those dependencies may modify the copies or storage reachable through their contents.

No explicit event-store or external-global-store operation appears in this function. Dependencies may nevertheless modify event storage, the global datum, method tables, or other reachable state.

The external global read is itself part of the reached F-979606fd565e call sequence. Its value is not established as invariant across calls or across an invocation.

### Ordering and continuation

For a path performing both entry actions, the established sequence is:

1. Dynamic entry `0x158`, for selected state `2` only.
2. Default-entry flag read.
3. Optional default-entry dependency, dynamic entry `0x11C`, and F-8a5aadac202f.
4. Volume-entry dependency, dynamic entry `0x11C`, and F-8a5aadac202f.
5. One-byte state write.
6. External-global read and F-979606fd565e call.
7. Fresh event reads and primary dispatch.
8. Fallback eligibility reads and possible fallback call, if primary dispatch returns zero.

No return-value check on an entry-related dependency suppresses the subsequent sequence. This statement assumes those calls return normally.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless specified otherwise, assume valid storage, compatible call targets, normally returning dependencies, and no relevant dependency mutations.

1. **Ordinary primary result:** For an event type other than `0x16` or `0x70001`, primary dispatch uses entry `0x110`. If it returns `7`, the function returns `7` without reading fallback eligibility fields.

2. **Nested primary selection:** Type `0x16` with subtype `0x2A` selects entry `0x10C`. It does not trigger preliminary notification.

3. **Preliminary notification:** Type `0x16` with subtype `0x2503` calls F-26bcb12c385a before later processing. If the event remains unchanged, primary dispatch selects `0x110`. Subtype `0x2502` does not trigger notification.

4. **State `1`:** Type `0x70001` with selected state `1` performs volume entry without reading the default-entry flag. After the volume calls return, the function writes state byte `5`, reads the external global, and calls F-979606fd565e.

5. **State `2` flag mutation:** If entry `0x158` changes the converted default-entry flag from `1` to `0`, default entry is skipped. Volume entry still occurs.

6. **Both entry labels:** For selected state `3` with converted flag `1`, the complete `EnterDefault` call sequence precedes the `EnterVolume` sequence.

7. **Changed global during volume entry:** Suppose the global has value A at function entry, and a reached volume-entry dependency changes it to B. If no later action changes it again, F-979606fd565e receives B. Supplying cached A would not match the represented behavior.

8. **State `5`:** Type `0x70001` with selected state `5` reads the external global for the reached F-979606fd565e call. Neither entry-label sequence nor this function’s explicit state-byte write occurs.

9. **Matching fallback:** If primary dispatch returns zero and the subsequently read type is `0x0F`, equal 32-bit comparison values cause entry `0xE0` to run. A result of `-3` is returned unchanged.

10. **Post-dispatch mutation:** If primary dispatch changes the event to type `0x0F`, makes the comparison values equal, and returns zero, fallback runs even when the event had another type before primary dispatch.

11. **Byte-granular update:** On a volume-entry path, this function overwrites only the byte at `0x140`. Clearing the other bytes of the state word is not part of the explicit store.
