# F-834cd4b2002a

## Purpose

F-834cd4b2002a returns either a stored 32-bit word or the 32-bit result of a dependency-call sequence.

The initial choice depends on the second input with bit 31 cleared. Values above `0x3e3fffff` enter the longer computation directly. Values at or below that boundary first invoke a predicate dependency; a zero predicate result selects the stored-word return.

The longer computation retains and combines dependency-produced word pairs. A stored signed threshold selects between two final-pair construction paths. One path additionally selects an adjustment using the fixed boundary `0x3fe90000`. Both paths end by passing two pairs to F-387e686c467e and returning its result unchanged.

This contract specifies word-level behavior. A numerical interpretation is plausible but unestablished. No floating-point encoding, mathematical operation, rounding rule, or accuracy guarantee is inferred.

## Behavior

### Initial decision and shortcut

The masked input is compared with `0x3e3fffff` using unsigned ordering.

If it is greater than that boundary, execution enters the longer computation without calling F-baa332e06e32 and without performing the initial shortcut-word read.

Otherwise, the established sequence is:

1. Invoke F-baa332e06e32 with the first and original second inputs.
2. Read the shortcut word.
3. Use the predicate result to choose the return path.

A zero predicate result returns the word just read. A nonzero result enters the longer computation.

The shortcut-word read occurs even when the predicate result is nonzero. It follows the predicate invocation, so a change to that storage by the predicate can affect the observed word. The read is not conditional on the predicate returning zero.

### Shared longer-path computation

Every longer-path execution constructs the same retained values before the threshold decision.

**Initial pair.** F-c4b34006a13c receives the first and original second inputs. Both words of its result are retained as the initial pair.

**Selector-derived pair.** After the initial-pair call returns, the offset-like storage is read. Its value is added to `0x080337d0`. F-7fd6c3e1c305 receives, in order:

- The computed value.
- The literal value `6`.
- The initial pair’s low word.
- The initial pair’s high word.

The complete width, overflow behavior, and address interpretation of the addition remain unknown. The hexadecimal constant does not by itself establish that the computed value is a pointer.

F-c4b34006a13c then receives the selector result’s low and high words, followed by the initial pair’s low and high words. Both words of this new result are retained as the selector-derived pair.

**Four-input word.** The next F-c4b34006a13c invocation receives all four original inputs in their original order. Only its low 32-bit contribution is retained, as the four-input word.

**Correction pair.** A fourth F-c4b34006a13c invocation receives the initial pair followed by the selector-derived pair, each in low/high order. Its third and fourth arguments therefore come from the selector-derived pair, not from the immediately preceding four-input call.

F-8a693c103d1c then receives exactly three visible arguments:

- The fourth F-c4b34006a13c result’s low word.
- That result’s high word.
- The four-input word.

Both words of its result are retained as the correction pair. This descriptive name does not establish an arithmetic operation. In particular, the three-argument call does not establish an implicit fourth argument or a zero-extended second pair.

**Second base pair.** F-9f634613286e receives the initial pair’s low and high words followed by the 32-bit pattern `0xffffffff`. Both result words are retained as the second base pair.

The third argument is the all-ones 32-bit pattern. Its interpretation as an integer, flag, or other value belongs to the unknown dependency contract.

### Signed threshold decision

The signed threshold is read only after F-9f634613286e returns.

The masked input is interpreted as a signed 32-bit value for this comparison. Because its top bit is clear, it remains nonnegative.

- A masked input strictly less than the signed threshold selects the below-threshold path.
- Equality or a greater masked input selects the adjustment-selection path.

A zero or negative threshold therefore cannot select the below-threshold path.

### Below-threshold path

F-8a693c103d1c receives the second base pair followed by the correction pair. Its result becomes the first final pair.

After that call returns, the shortcut word and shortcut-pair high word are read to form the second final pair, with the shortcut word in the low position.

These are fresh reads. Any shortcut-word read made during initial selection does not replace the later read.

Both constituent reads occur after the preceding dependency returns. Their relative order within the pair-construction expression is not established.

### Adjustment selection

The adjustment-selection path chooses one of two adjustment pairs.

For masked inputs at or below `0x3fe90000`:

- The adjustment low word is zero.
- The adjustment high word is the masked input minus `0x00200000`, retained as a 32-bit result.

For masked inputs above `0x3fe90000`:

- The stored adjustment low word is read first.
- The stored adjustment high word is read second.
- Both values are retained before the next dependency invocation.

The stored-adjustment reads are separately sequenced. Their low-before-high order is established, unlike the uncertain ordering of shortcut-related reads grouped within one expression.

The intermediate condition involving `0x3effffff` does not create a third observable adjustment category. Over the masked input’s established range, the signed-condition logic selects the constructed adjustment through `0x3fe90000`, inclusive, and the stored adjustment above it.

The constructed high word uses 32-bit wraparound, not saturation or checked subtraction. A masked input below `0x00200000`, if it reaches this path, produces a high word in the upper portion of the 32-bit range.

### Applying the adjustment

Once selected, the adjustment words are retained across three F-8a693c103d1c invocations:

1. The second base pair followed by the adjustment pair produces a retained intermediate pair.
2. A freshly read shortcut-related pair followed by the retained adjustment pair produces the second final pair.
3. The retained intermediate pair followed by the correction pair produces the first final pair.

Each pair is supplied low word first, high word second.

The shortcut-related words used by the second invocation are read after the first invocation returns. Changes to that storage by the first invocation can therefore affect the second invocation’s arguments.

The adjustment words are not reread between these invocations. A dependency’s later modification of stored adjustment locations does not replace the already retained values.

The order between the two shortcut-related reads within the second invocation’s argument expression is not established.

### Final return

Both longer-path branches converge on F-387e686c467e. Its four arguments are:

1. First final pair, low word.
2. First final pair, high word.
3. Second final pair, low word.
4. Second final pair, high word.

Its explicit 32-bit result is returned without further visible transformation or validation.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless stated otherwise, they assume reached dependencies return normally and reached storage accesses are valid.

1. **Initial inclusive boundary.** With masked input `0x3e3fffff`, the predicate is invoked. If it returns zero, the subsequently read shortcut word is returned; no longer-path dependency is reached.

2. **Predicate bypass.** With masked input `0x3e400000`, the predicate and initial shortcut-word read are skipped.

3. **Original second input preserved.** Second inputs `0x3e3fffff` and `0xbe3fffff` select the same local predicate branch. The predicate nevertheless receives different second-argument bit patterns; equal predicate results are not guaranteed.

4. **Nonzero predicate still precedes a read.** For a masked input within the predicate range and a nonzero predicate result, the shortcut word is read before the initial-pair invocation begins.

5. **Intermediate provenance.** If the selector-derived pair differs from the four-input call’s result, the fourth F-c4b34006a13c invocation still receives the selector-derived pair in its third and fourth positions. The four-input word instead becomes the third argument of the shared F-8a693c103d1c invocation.

6. **Threshold equality.** If the signed threshold equals the masked input, adjustment selection is taken. The below-threshold branch requires strict inequality.

7. **Nonpositive threshold.** A threshold of zero or any negative signed 32-bit value selects adjustment selection for every masked input that reaches the comparison.

8. **Inclusive adjustment boundary.** At masked input `0x3fe90000`, if adjustment selection is reached, the adjustment is low `0x00000000`, high `0x3fc90000`. Neither stored adjustment location is read.

9. **First stored-adjustment case.** At masked input `0x3fe90001`, if adjustment selection is reached, the stored low word is read, then the stored high word, then the first adjustment invocation occurs. Reversing those reads or postponing either until after that invocation violates the established order.

10. **Wrapping subtraction.** If masked input zero reaches adjustment selection, the adjustment high word is `0xffe00000`. This requires a nonzero predicate result and a nonpositive threshold.

11. **Fresh shortcut state, retained adjustment.** If the first adjustment invocation changes shortcut-related storage, the second invocation uses newly read shortcut-related words. If it changes stored adjustment locations, the retained adjustment arguments are not refreshed.

12. **Transparent final return.** Any 32-bit pattern returned normally by F-387e686c467e is returned unchanged. This does not exclude additional dependency effects or status communicated through other state.
