# F-77f8ead60110

## Purpose

F-77f8ead60110 performs configuration-controlled operations on an object obtained through an external dependency. Its visible operations include resolving an input-derived word, reading object fields, calling dependencies with those fields, obtaining two auxiliary outputs through address arguments, and passing auxiliary values to further dependencies.

The function uses an arithmetic dispatcher. Configuration contents are not supplied, so the reachable operation sequence, termination conditions, and domain-level success or failure meanings remain unknown.

This contract describes the represented operations and their conditional effects. It does not assume that dependencies preserve shared configuration, object storage, or auxiliary output slots whose addresses have escaped.

**Additional inputs:** shared 32-bit configuration words. Some are cached at entry; others are read during individual state visits. Repeated reads of one location are not assumed to return equal values.

### Entry configuration and initialization

The multiplier is read and cached before the companion is read and cached. The length slot is then cleared before the opaque slot. The object and carrier start at zero; both accumulators and the saved result also start at zero.

One configuration location supplies three entry reads:

1. Its first value, minus one, becomes the anchor.
2. Its next value, arithmetically shifted right by 29, contributes to the scale.
3. Its final value becomes the initial selector.

The scale subtracts a fresh read of the companion’s configuration location from the shifted value. This fresh read is distinct from the cached companion. Relative operand-read order within that subtraction expression is not independently established.

The anchor calculation precedes the scale calculation, which precedes the initial-selector read. If all three reads of the anchor configuration location agree, the initial decoded state is 1, including across 32-bit wraparound.

### Selector decisions and read ordering

The tests below concern bit 31, not zero versus nonzero:

- **State 0:** if the product OR has bit 31 clear, use the second, unadjusted configuration read. If bit 31 is set, use the first read minus 6. Both reads occur, in that order.
- **State 10:** if its final OR has bit 31 clear, use the first configuration read plus 5. If bit 31 is set, use the second, unadjusted read. Both reads occur, in that order.
- **State 13:** if its product OR has bit 31 set, use the anchor, making the next decoded state 0. Otherwise, use the configured alternative. The configuration read still occurs in the anchor-selecting case.

State 11 uses a different condition:

- A zero object makes the selector equal to the read contributing the minus-seven alternative, minus 7.
- A nonzero object makes the selector equal to the read contributing the unadjusted alternative.
- Both reads address the same configuration location, regardless of the object result. Their relative evaluation order is not established.

These arithmetic selections must not be modeled as conditional expressions that omit reads from unused alternatives.

### State 10 arithmetic

The object byte is zero-extended. Multiplication by 141 followed by retention of the low eight bits yields a value between 0 and 255.

Multiplying that reduced value by 69, complementing the 32-bit product, and ORing with `0x000000ff` produces a mask. The intervening signed 16-bit conversion of the reduced value does not make it negative.

A signed intermediate is formed from one bias-source read arithmetically shifted right by 31, minus another read of that same location. Those two reads need not agree; their relative evaluation order is not established.

The carrier combines:

- The reduced byte value multiplied by the byte coefficient.
- Subtraction of a third bias-source read.
- Addition of multiplier × complemented mask.
- Addition of signed intermediate × mask.

The byte-coefficient read and third bias read belong to the same compound expression; their relative evaluation order is not independently established.

A factor is formed by arithmetically shifting the signed intermediate right by one and XORing with `0xfffffffe`. Another word is formed by subtracting one from companion × carrier and ORing with `0xfffffffe`. Multiplying that word by the factor, then adding the factor, produces an intermediate used by both scale and companion multiplications.

The OR of those two products becomes the first accumulator and controls the state 10 transition. The second accumulator becomes zero.

The byte-times-141 product is at most 35,955; the reduced-byte-times-69 product is at most 17,595. Later arithmetic is 32-bit and may wrap.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Stable entry configuration.** Equal anchor-source entry reads produce initial state 1, including when subtraction crosses zero.

2. **Carrier is not the return value.** If default processing reaches state 9 without state 2 having executed, the return is zero even when the carrier is nonzero.

3. **Saved result persists.** After state 2 saves a product, later working-state changes do not replace that result unless state 2 executes again.

4. **Shared state 3/6 configuration.** If state 3 reads a selector value and an intervening dependency changes that location before state 6, state 6 reads the new value from the same location.

5. **State 11 reads both alternatives.** A zero resolver result still entails both represented configuration reads. Only the minus-seven contribution determines the resulting selector. The reads’ relative order remains unspecified.

6. **State 13 reads its unused alternative.** With a product OR of `0x80000000`, the selector becomes the anchor, but the configured-alternative read still occurs. With an OR of `0x00000001`, the configured alternative determines the selector.

7. **State 12 rereads the slot.** If its first dependency receives opaque value 17 and changes the escaped slot to 23 before returning, F-5e3309c9d083 receives 23, absent another intervening modification.

8. **Zero slots do not suppress calls.** With both slots zero at state 12 entry and no modification during argument evaluation, the first dependency receives zero opaque and scaled-length arguments. The second dependency is still called; its argument is zero only if the subsequent opaque-slot read yields zero.

9. **Byte reduction.** A byte of zero reduces to zero. A byte of 255 reduces to 115 after multiplication by 141 and low-byte retention. Neither input is sign-extended.

10. **No forced termination.** A configuration-driven cycle excluding state 9 has no visible timeout or fallback return.
