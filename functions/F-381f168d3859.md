# F-381f168d3859

## Purpose

F-381f168d3859 performs a configuration-dependent transformation of caller-supplied storage. It first constructs selected entries of a private 16-word intermediate array using byte lookups, word lookups, and an optional call to F-f080501f3176. After that phase exits, it combines intermediate words and emits individual bytes through addresses derived from the original input base.

The supplied static representation does not establish a fixed input size, output size, iteration count, or named algorithm. Constants resembling conventional table or block dimensions do not establish those properties without the configuration values.

This contract distinguishes established operations from conditional mathematical consequences and **documented_only** unknowns. No runtime tests have been performed.

## Interface

The interface has six 32-bit word arguments and no explicit return value.

| Argument | Established role |
|---|---|
| A1 | Address base for initial byte reads and subsequent byte writes. |
| A2 | Selector used in calculating a byte-table bank address. |
| A3 | Address of the repeatedly read route-selection word. |
| A4 | Address base for word lookups on the dependency route. |
| A5 | Address base for banked byte lookups. |
| A6 | Address base for word lookups on the direct route. |

The representation uses 32-bit signed and unsigned words, byte loads, four-byte word strides, and single-byte stores. Address arguments participate directly in word-sized arithmetic. There are no lengths, capacity arguments, ownership flags, or error-result parameters.

Normal completion requires accessible storage for every actual read, writable storage for every actual write, valid intermediate-array indices, initialization of every intermediate word subsequently consumed, defined arithmetic for the execution environment, and terminating configuration-dependent loops. The function does not validate these requirements.

No allocation, release, or ownership transfer is visible in this function. Argument-backed storage remains caller-provided from the perspective of its direct operations. F-f080501f3176’s ownership behavior is unknown.

Alignment requirements, memory byte order, and handling of inaccessible addresses are not supplied.

## Behavior

### Configuration and arithmetic

Seventeen global word locations participate:

| Label | Uses |
|---|---|
| G0 | Entry complement, initial first-phase position, inner progression, emitted-byte adjustment. |
| G1 | Position and address adjustments, route predicate, progression, signed high-bit calculations. |
| G2, G3 | First-phase termination arithmetic and mask. |
| G4 | First-phase termination arithmetic and second-phase initial position. |
| G5 | Second-phase bounds, grouping, combination, inner initialization, and output addressing. |
| G6 | Outer second-phase termination mask. |
| G7 | Value captured by each outer condition and reused by the inner conditions. |
| G8, G9 | Freshly read operands in inner termination expressions. |
| G10 | Output shift-count adjustment. |
| G11 | Address base of a four-byte-entry offset table. |
| G12, G13 | Direct-route multiplication and subtraction. |
| G14 | Dependency-route word-index adjustment. |
| G15, G16 | Dependency-argument multiplication and subtraction. |

These labels identify locations, not known constants.

Word widths matter. Unsigned operations wrap modulo \(2^{32}\); byte reductions retain the low eight bits. Signed comparisons inspect 32-bit signed results. Explicit signed shifts by 28 operate on signed interpretations of the relevant words. Signed overflow, other signed operations, and shifts outside their supported range require target semantics not supplied here.

Global declarations are absent. Consequently, signedness of expressions depending on uncast global operands must not be inferred solely from the signed local receiving their result.

The configuration is not snapshotted at entry:

- The complement of G0 is captured once; the initial first-phase position comes from a separate G0 read.
- First-phase progression uses an early per-iteration G1 capture, while index, address, predicate, and other expressions separately read G1.
- Each outer second-phase condition captures G7 for that outer iteration’s inner conditions.
- Each admitted outer iteration captures the complement of G5 shifted left by one for all three combinations.
- Other occurrences of G5 remain separate reads.
- Inner predicates reuse the captured G7 but separately read G8 and G9.

Multiple reads within one compound expression do not have a completely established relative evaluation order. Separate statement ordering is established. Concurrent mutation and synchronization semantics are not supplied.

### First phase: intermediate construction

The local intermediate array contains 16 words and is not visibly initialized as a whole.

The first-phase position begins with the separate entry read of G0. At each condition evaluation, the function captures G1 for later progression and computes an intermediate index from the current position plus another G1 read.

Admission depends on the sign of a word expression involving the position, G2, G3, and G4. The expression contains subtraction by 16, complementary mask terms, and the mask \(0xffffffef\). These constants do not establish 16 iterations or a particular range of admitted positions.

For each admitted iteration, the relevant memory-access order is:

1. Read the selected offset-table word.
2. Read an A1-derived input byte.
3. Compute the byte-table displacement and bank base.
4. Read the route-selection word at A3.
5. Read the first A5-derived byte.
6. Evaluate the route predicate and perform the chosen route.
7. Store the result in the selected intermediate-array entry.

Computing the A5 address is not an A5 byte read. In particular, the A3 word read precedes the first A5 byte read.

Let \(j\) denote the computed intermediate index. The offset-table word is read at G11 plus \(4j\).

A signed adjustment \(h\) is formed by arithmetic-right-shifting a signed G1 read by 28 and subtracting a separate G1 read. With stable G1 this is \(\operatorname{ASR}_{28}(G1)-G1\); stability is not guaranteed. The input-byte address adds A1, the selected offset word, \(h\), and another G1 read.

For describing the byte arithmetic, let:

\[
T(b)=\operatorname{low}_8(b+135).
\]

Let \(c\) be the entry-cached complement of G0, and define the word-valued expressions:

\[
K(u)=((134-u)\mathbin{\mathrm{OR}}255)
       \mathbin{\mathrm{XOR}}(-135u+c),
\]

\[
L(u,h)=(134-u)\mathbin{\mathrm{OR}}(135u+h)
                         \mathbin{\mathrm{OR}}255.
\]

These expressions describe width-sensitive arithmetic, not unbounded integer identities.

For \(u=T(\text{input byte})\), the first A5 displacement is:

\[
2L(u,h)-133+K(u)-134u+G1,
\]

using the G1 read made when that displacement is captured. The bank base is separately calculated as:

\[
A5+(A2-1+G1)\,4096+256j.
\]

Thus, 4096-byte selector and 256-byte position strides are established. Neither accessible bank extents nor confinement of the displacement to 0–255 is established.

### Route selection and route-specific work

The selector address is the base of A3 on every iteration: its visible word index remains zero. Multiple iterations therefore reread one location rather than traversing selector words.

The selector value is first adjusted by \(h\). The branch then tests the signed result of a complement-and-addition expression involving that adjusted value, \(h\), and a fresh G1 read. It is not established as a zero/nonzero selector test or a test of the selector word’s sign alone.

The first A5 byte is read before the branch is taken, including on the direct route.

**Dependency route.** Let \(w=T(\text{first A5 byte})\). The A4 word index is:

\[
-134w+G14+K(w)+2L(w,h).
\]

The selected word is multiplied by G15 and reduced by G16. F-f080501f3176 receives:

- A lane argument consisting of signed \(j\) remainder four, plus \(h\), plus a G1 read.
- The scaled and adjusted A4 word.

The returned word is adjusted by adding \(h\), then stored at intermediate index \(j\). This route has no visible A6 lookup.

The remainder operation has signed operands. For negative indices, replacing remainder by a low-two-bit mask is not generally equivalent.

**Direct route.** The function performs a second A5 byte read. Its address reuses the previously computed bank base and the previously computed byte-arithmetic components, but reconstructs the displacement using a later G1 read.

The two A5 addresses are equal if the relevant G1 values agree under the address arithmetic. Equality is not unconditional. The second read supplies the byte used for the A6 lookup, regardless of whether its address or value matches the first read.

For \(w=T(\text{second A5 byte})\), the A6 word address is:

\[
A6+1024(j\bmod 4+h)+1028G1
      -536w-532+4K(w)+8L(w,h).
\]

Here, G1 is read for this address expression. The loaded word is multiplied by G12 and reduced by G13, and the result is stored at intermediate index \(j\). There is no dependency call on this route.

After either route stores the intermediate result, the first-phase position advances by one, the early per-iteration G1 capture, and \(h\). Unit progression and termination require additional configuration assumptions.

### Second phase: grouping and combination

The second phase starts only after the first-phase loop exits. Its outer position begins at a fresh G4 read minus 14.

Each outer condition first captures G7. Its signed admission expression uses the outer position, G5, G6, a signed high-bit adjustment, and the mask \(0xfffffffb\). A terminating outer condition still performs its G7 capture.

For an admitted outer iteration, the function calculates and retains two position products:

- A product using the outer position and a value formed from G5 XOR the signed right shift by 28 of another G5 read plus five.
- A product using the outer position and a separate G5 read plus five.

It then captures:

\[
C=\mathord{\sim}(G5\ll1).
\]

That single captured \(C\) is reused in three nested combinations. Other G5 occurrences, including each final subtraction and the index calculations, are separate reads.

For fixed operand values and a particular subtraction operand \(d\), the pairwise arithmetic is:

\[
N_{C,d}(x,y)=x+y+
 \left((-2x-C)\mathbin{\mathrm{OR}}(-2y-C)\right)-d.
\]

The first combination consumes two selected array operands. The second combines its result with a third selected operand. The third combines that result with the existing destination word and writes back to the destination entry.

Selection uses the retained position products, the grouping value, and expressions involving G5 multiplied by two or three, shifted left by one or two, and shifted right by 31 or 30. The destination index is retained for subsequent byte emission. These expressions do not establish four fixed groups or four distinct source locations. Repeated array expressions and repeated global operands must not be treated as entry snapshots when mutation is permitted.

When G5 is stably zero, \(C=0xffffffff\). The operation is **not XOR**. Under modulo-\(2^{32}\) arithmetic:

\[
N_{0xffffffff,0}(0,0)=1.
\]

For four zero-valued operands, the three nested results are respectively 1, 0, and 1. The destination therefore becomes 1 under those assumptions.

### Inner loop and byte emission

After combination, the inner position is initialized from G5 OR another G5 read shifted right by 26.

Each inner condition uses the G7 capture from the enclosing outer condition and fresh G5, G8, and G9 reads. Its signed termination arithmetic includes the mask \(0xfffffffb\).

Let \(k\) denote the inner position before progression. Before deciding whether to leave the inner loop, the function calculates address and shift components using that position:

- \(k+4G1\), with a fresh G1 read.
- \(kG1\), with a separate G1 read.
- \(k(G5+9)\), with a fresh G5 read.

These global accesses still occur on the terminating path, although no byte is stored on that path.

On an admitted inner iteration, the inner position advances by:

\[
1+\text{fresh }G1+\text{fresh }G0
\]

**before** the output store. Nevertheless, the retained address component and multiplication components use the old \(k\), not the advanced inner position.

The destination address adds A1, the retained \(k+4G1\) component, both retained outer-position products, and a further G1 read.

The shift count is the low eight bits of:

\[
G10-k(G5+9)-kG1,
\]

where the two products are the previously calculated components. G10 is read in the output expression.

The value shifted is the destination intermediate word plus another G1 read. The stored byte is equivalent, modulo 256, to its shifted low byte plus the low byte of a G0 read, minus 127.

The count is reduced to eight bits, not explicitly to 0–31. Counts from 32 through 255 have no established behavior here. The global declarations needed to settle the signedness of the final shifted expression are absent; arithmetic versus logical right shift must therefore remain **documented_only**.

On inner termination, a fresh G1 read supplies \(G1\mathbin{\mathrm{OR}}1\). Its signed right shift by 28 controls the subsequent outer increment:

\[
\text{outer position}+1+
\operatorname{ASR}_{28}(G1\mathbin{\mathrm{OR}}1).
\]

It is not an unconditional increment by one. The next outer condition captures G7 again.

## Side effects

Direct caller-visible writes are single-byte stores through A1-derived addresses. The function also writes its private intermediate array during both phases.

No direct writes to A3, A4, A5, A6, the offset table, or configuration globals are visible. They can nevertheless change through aliasing with output storage, external mutation, or dependency effects.

All first-phase reads precede the first direct output-byte store. This does not promise that caller storage remains unchanged throughout the first phase: F-f080501f3176’s effects are unknown.

Output is incremental. No rollback, validation failure result, diagnostic, exception handler, or recovery path is visible. A failure after some stores need not undo earlier stores.

The intermediate-array address is not visibly supplied to F-f080501f3176. The absence of such an argument does not establish the dependency’s complete accessible-memory set.

## Acceptance examples

These are conditional acceptance obligations, not executed tests.

1. **Selector precedes byte-table access.**  
   For an admitted first-phase iteration, the A3 word read precedes the first A5 byte read. Merely calculating the A5 address earlier does not satisfy that read.

2. **Two direct-route reads with stable G1.**  
   If the G1 values used in the two displacements agree, the direct route reads the same A5 address twice. If its contents change between those reads, the second byte controls the A6 lookup.

3. **Direct-route address change.**  
   If those G1 reads differ, the second A5 address must be reconstructed using the later value. Reusing the captured first displacement is not generally equivalent.

4. **Dependency route.**  
   Its A4 lookup precedes its dependency call. It requires no A6 lookup, and its returned result is adjusted by the retained \(h\).

5. **Zero-valued combination.**  
   If G5 remains zero, all four consumed operands are zero, and modulo-word arithmetic applies, the nested combination writes 1, not the XOR result 0.

6. **Captured versus fresh configuration.**  
   Within one outer iteration, inner predicates reuse that outer condition’s G7 capture but reread G8 and G9. The next outer condition captures G7 anew.

7. **Progression before output.**  
   On an admitted inner iteration, progression reads G1 and G0 before the byte store. The destination and shift products still use the pre-progression inner position.

8. **Output aliases configuration.**  
   If a byte store changes configuration storage, later fresh reads can observe that change. Already captured G7 and the retained combination complement are not retroactively updated.

9. **Outer transition.**  
   If the terminating inner path captures \(G1\mathbin{\mathrm{OR}}1=0xffffffff\), its signed shift by 28 is −1, making the subsequent outer increment zero, subject to defined arithmetic.

10. **Unsupported execution conditions.**  
    An uninitialized intermediate read has no promised deterministic result. A calculated shift count of 40 does not authorize silently substituting 8.
