# F-eb55389a9b45

## Purpose

F-eb55389a9b45 exchanges successive one-byte elements between two caller-supplied memory regions.

The operation is an ordered sequence of individual exchanges, not a snapshot-based exchange of two complete regions. This distinction is observable when the regions overlap: a write from an earlier iteration can supply the value read by a later iteration.

The supplied representation establishes a post-tested loop. The function performs one exchange before deciding whether to continue. Consequently, a count of zero does not request an empty operation.

This contract distinguishes behavior directly established by the supplied representation from conclusions requiring assumptions about integer width, overflow, pointer validity, or the execution environment. No runtime tests have been performed.

## Interface

### Inputs

The function receives three values:

- **First address:** the starting address of the first sequence of one-byte elements.
- **Second address:** the starting address of the second sequence of one-byte elements.
- **Count:** an integer value that is decremented once per iteration and tested after that iteration.

Both addresses are used for reading and writing. Neither is treated as read-only.

The supplied element type represents a one-byte storage unit. Under the conventional eight-bit-byte interpretation, each exchanged element contains eight bits. The operation performs no character decoding, numeric conversion, sign extension, or interpretation of element contents.

The supplied count type is an integer, but the provided text does not independently establish its bit width or the target’s overflow semantics. A 32-bit wrapping interpretation is described conditionally below; it must not be mistaken for independently verified target behavior.

### Output

There is no result value carrying data or status. On ordinary completion, the externally visible output is the modified memory.

The address values and count are passed as values. Advancing the function’s working addresses and decrementing its working count do not, by themselves, update caller-owned variables containing the original arguments. If an addressed region overlaps such a variable’s storage, however, the ordinary memory writes can modify that storage. The function provides no protection against that aliasing.

### Preconditions for defined, ordinary completion

For a positive count:

- Every element visited through either address must be readable and writable.
- Each working address must support the successive one-byte advances performed by the function.
- The caller must permit the effects of any overlap between the regions.
- Any required synchronization with other readers or writers must be supplied externally.

The function contains no explicit checks enforcing these conditions.

For zero or negative counts, the required accessible extent cannot be determined solely by interpreting the count as an ordinary requested length. Continuation depends on decrement and overflow semantics.

No alignment requirement beyond the requirements of the actual one-byte accesses is established by the supplied representation.

## Behavior

### Per-iteration exchange

Each iteration has the following source-established ordering:

1. Read one byte through the current first address and retain that value.
2. Decrement the working count by one.
3. Read one byte through the current second address.
4. Write the value read from the second address to the first address.
5. Write the retained original first-address value to the second address.
6. Advance the first working address by one byte.
7. Advance the second working address by one byte.
8. Continue if the decremented count is nonzero; otherwise return.

The second-address read precedes the first-address write. The retained first-address value survives that write and is then used for the second-address write.

The count decision occurs only after both writes and both address advances. There is no initial zero-count check and no early termination based on byte contents.

This ordering describes the supplied representation. It is not independent evidence of the exact machine-access trace under optimization, concurrent mutation, or device-memory semantics.

### Positive counts

For a positive count whose decrements remain representable, the function performs exactly that many iterations.

Each iteration visits the next byte of each region. For nonoverlapping regions, the final state is a byte-for-byte exchange of the two regions over the requested length. Bytes outside the visited locations receive no direct write from this function.

The function does not search for a terminator. Zero-valued bytes are exchanged like every other byte.

### Identical addresses

The supplied representation does not special-case equal addresses.

With ordinary stable memory, each iteration reads the same byte through both addresses and writes that same value back twice. The final contents are unchanged, but the representation still specifies the accesses.

Equal addresses therefore do not establish a no-access operation. Read or write side effects, access restrictions, or faults may matter even when the intended final contents would be unchanged.

### Partially overlapping regions

Partial overlap is processed in increasing address order for both sequences. There is no temporary copy of either complete region and no attempt to select an overlap-safe direction.

Each iteration exchanges the values present at that time. Earlier writes can change later inputs. The result must therefore be derived from the ordered exchanges, not from the regions’ original contents alone.

The per-iteration saved byte protects the original first-address value only for that iteration. It does not preserve a region-wide snapshot.

### Zero and negative counts

A zero count still enters the body. The first decrement makes the working count negative under ordinary signed arithmetic, and the first exchange is attempted.

A negative count also enters the body. Further decrements move it away from zero until some additional arithmetic rule becomes relevant.

Under a **conditional fixed-width wrapping model** with a count width of \(w\) bits, the number of iterations is the least positive number of decrements needed to reach the all-zero count representation:

- A positive signed count takes its ordinary positive number of iterations.
- An initial zero takes \(2^w\) iterations.
- An initial negative value \(c\) takes \(2^w+c\) iterations.

Under that model with a 32-bit count, zero implies 4,294,967,296 iterations, while negative one implies 4,294,967,295 iterations. These figures assume execution can continue through all intervening memory accesses and address advances.

The supplied text alone does not establish wrapping overflow. If signed overflow instead invalidates execution, the function has no established normal-completion behavior after the overflow point. Neither interpretation supports treating nonpositive counts as harmless empty requests.

### Final address advances

Both working addresses advance after the final exchange, before the termination decision.

These advanced addresses are not returned or subsequently dereferenced on that successful final iteration. Nevertheless, the supplied representation includes their formation. Whether an otherwise invalid terminal address is permitted depends on the applicable pointer or machine-address semantics.

## Side effects

### Memory access

For each completed iteration, the supplied representation specifies:

- One read through the first address.
- One read through the second address.
- One write through the first address.
- One write through the second address.

Aliasing can cause these accesses to refer to the same storage location. No atomic exchange, transaction, lock, or memory barrier is shown.

### Partial modification

The function provides no rollback. If execution is interrupted or an access fails, earlier writes may remain visible.

An interruption between the two writes of an iteration can leave that pair only partially exchanged. For example, after the first write but before the second, both locations may contain the value obtained from the second location, while the original first value exists only in the function’s temporary storage.

The exact fault mechanism and post-fault control flow are not established.
