# F-f2b5bf2508e3

## Purpose

F-f2b5bf2508e3 performs a long, ordered sequence of unresolved indirect invocations, derives address-like quantities from their results, mutates memory through explicitly sized accesses, accesses undeclared named globals, and finishes with an unresolved indirect invocation carrying four displayed arguments.

**Established static evidence:** four 32-bit inputs; no explicit value result; mixed-width result transformations and memory operations; repeated accesses; captured values reused after their sources may change; and a terminal indirect transfer.

**Inferred intent:** recurring offsets resemble linkage or state publication. These descriptions do not establish objects, ownership relationships, synchronization, or application-level success. Numeric literals resembling characters do not establish text output.

This contract distinguishes expression-value widths from storage-access widths. In particular, a conversion applied to a named global does not establish the width or signedness of the underlying global access. Missing declarations and unresolved machine behavior remain **documented_only**. No runtime tests have been performed.

## Behavior

### Widths, conversions, and addressing

Explicit pointer-based accesses distinguish 8-bit bytes, 16-bit halfwords, and 32-bit words. Some dependency results are represented as 64-bit quantities. Their low and high 32-bit portions are used independently; other extractions shift the complete 64-bit quantity by 34, 36, or 44 bits.

Explicit byte and halfword stores retain the corresponding low bits. Explicit unsigned byte loads used in word expressions are zero-extended. A word store remains a four-byte access even when its value is small.

**Named globals are different:** their declarations are absent. Their underlying access widths, signedness, and assignment conversions are **documented_only**. This applies to globals associated with fixed addresses 0x01, 0x05, 0x15, 0x21, 0x3A, 0x54, 0x60, 0x67, and 0xA9, and to the global supplying the later publication base.

For example, conversion of the global associated with 0x05 to a 32-bit unsigned value establishes the resulting expression’s width and unsigned interpretation. It does not establish an unsigned byte load or a result limited to 0–255. Likewise, assignment of an explicitly eight-bit-converted value to a named global does not establish a one-byte destination access.

Arithmetic examples use a conditional **32-bit bitvector model**: addition, subtraction, multiplication, and left shifts retain their low 32 bits; explicitly unsigned right shifts are logical. This model does not resolve signed overflow or signed-shift behavior in the underlying environment. Address formulas below use the same model unless qualified.

### Indirect dependency phase

The opening invocation receives the first input unchanged and the fourth input shifted left by 7. Its destination depends on incoming continuation-related state.

Later invocations use continuation-derived destination expressions and previously captured results. Displayed arguments include shifted primary results, high result words, secondary result channels, masked fields, duplicate transformed values, and explicit zeros. Masks select low 24-, 22-, 21-, 20-, 19-, and 17-bit fields, among smaller selections.

The represented flow is straight-line, without an input-controlled loop or displayed conditional branch. Invocation order and multiplicity matter. Identical argument expressions do not justify merging calls. No displayed arguments does not establish the absence of implicit inputs.

Sequential shifts must retain their widths. Under the bitvector model, shifting a 32-bit quantity left by 25 and subsequently left by 11 eliminates all bits.

Dependency bodies, resolved identities, failure behavior, and implicit state consumption are unavailable. Their application-level computation remains **documented_only**.

## Acceptance examples

These are conditional static examples, not executed tests.

### Input transformation

Inputs differing only in the fourth input’s bits 25–31 have equal left-by-7 and left-by-25 expressions. This does not prove equal complete executions or implicit machine state.

### Explicit widths versus undeclared global types

If H is 0x123456AB, the first explicit byte store at R + 9 carries 0xAB; the later overwrite carries zero. Both accesses remain distinct.

By contrast, assigning T converted to eight bits to the global associated with 0x01 does not prove a one-byte write.

If the global associated with 0x05 were a signed 16-bit value of −1, its conversion to 32-bit unsigned would yield 0xFFFFFFFF. A contract restricting C to 0–255 would therefore require evidence not supplied here.

### Readback and literal widths

With stable ordinary RAM and no external mutation or access-triggered effects, J is zero. P + 0x34 cannot overlap P + 0x14 under the stipulated model.

The explicit 0x3A literal group requires byte, halfword, and word accesses. Three byte writes are not equivalent.

This requirement does not depend on assuming word-sized underlying global accesses.
