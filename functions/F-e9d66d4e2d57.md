# F-e9d66d4e2d57

## Purpose

F-e9d66d4e2d57 conditionally removes one trailing record from a logical sequence, then updates the boundary entry associated with the current nesting level.

Removal occurs only when:

- The signed record count is greater than one.
- The trailing record matches a selected comparison record in both of its 32-bit words.
- The trailing record’s associated byte is exactly 1.

Removal changes the logical count only. No record or associated byte is erased, moved, or freed by this function.

The apparent intent is to eliminate a redundant trailing record and refresh a nesting boundary. That interpretation is inferred. The observable contract is the conditional count decrement and subsequent boundary write described below.

## Interface

### Input and result

The function receives one address-bearing argument identifying an outer object. It produces no explicit return value.

The outer object contains a nested-state pointer at byte offset 20. The function reads that pointer immediately:

- If the pointer is null, the function returns without further state access.
- Otherwise, the function uses the nested state and its referenced storage as described below.

There is no null check for the outer-object address itself.

### Preconditions

For defined operation, every address actually accessed must designate suitably aligned, readable or writable storage for the access in question.

In particular:

- The outer object must permit the pointer read at offset 20.
- A non-null nested state must permit the field accesses reached by the relevant branch.
- Record storage must cover both selected records whenever the record count exceeds one.
- Boundary storage must cover the comparison-boundary read when the level count exceeds one and the record count exceeds one.

## Behavior

### Null nested state

A null nested-state pointer is an immediate no-op after the outer-object pointer read.

The function does not inspect the record count, level count, or any subordinate pointer on this path.

### Selection of records

The function first reads the signed record count.

If that count is at most one, it skips all duplicate-detection work. In particular, this path does not require access to record storage or associated-byte storage.

If the count exceeds one, the function selects:

- The trailing record at index `record count − 1`.
- A comparison record determined by the signed level count.

The comparison record is selected as follows:

| Level count | Comparison-record index |
|---|---|
| At most one, including zero and negative values | 0 |
| Greater than one | The signed boundary entry at index `level count − 2`, plus 1 |

The boundary entry is sign-extended before adding one. Negative entries are not treated as unsigned values and are not rejected.

For example:

- A boundary entry of −1 selects record 0.
- A boundary entry of 0 selects record 1.
- A boundary entry of −2 selects record −1, an address before the supplied record-array base.

The function does not require the comparison record to precede the trailing record. It does not prevent both selections from naming the same record.

### Conditional duplicate detection

The function compares the selected records in two stages:

1. It reads and compares their first 32-bit words.
2. Only if the first words are equal does it read and compare their second words.

The second words are interpreted as pointer values for equality comparison. They are not dereferenced. Equality is not a comparison of the contents of any pointed-to object.

If either word differs, the count is unchanged and the associated-byte array is not accessed.

If both words compare equal, the function reads the associated byte at index `record count − 1`. It requires that byte to be exactly 1. Other nonzero values do not qualify.

Only when both record words match and the associated byte equals 1 does the function decrement the nested state’s record count by one.

This is a single conditional removal. The function does not loop or continue removing additional matching records.

### Final boundary update

After the duplicate-detection phase, the function tests the nested state’s level count again.

If that value is positive, it writes the current record count minus one into boundary entry `level count − 1`.

Consequences:

- A successful count decrement affects the value written to the boundary.
- A boundary write can occur even when duplicate detection was skipped.
- A boundary write can occur when the record count is zero or negative.
- A zero or negative level count suppresses the final boundary write.
- Suppressing the final boundary write does not suppress duplicate detection when the record count exceeds one.

The final phase uses fresh field accesses rather than relying solely on the earlier selection values. This distinction matters if storage aliases or another actor changes memory during execution. No synchronization or concurrent-access guarantee is supplied.

### Arithmetic and narrowing

Signed 16-bit fields and boundary entries are promoted to integer values for arithmetic.

Under the represented 32-bit integer model:

- A record count greater than one lies between 2 and 32,767.
- The trailing-record index therefore lies between 1 and 32,766.
- A signed boundary entry plus one lies between −32,767 and 32,768.
- The corresponding record displacement is eight times that index.
- A positive level count selects a final boundary index between 0 and 32,766.

These index calculations fit in signed 32-bit arithmetic. They do not establish that the resulting addresses belong to valid allocations.

The conditional decrement is representable in signed 16 bits: it changes a count in the range 2 through 32,767 to a count in the range 1 through 32,766.

The final boundary value is different. Subtracting one from a signed 16-bit count of −32,768 produces −32,769 before storage, which is outside the signed 16-bit range. The supplied representation does not independently establish the language-level result of that narrowing conversion. A low-16-bit machine store would encode this as 32,767 when subsequently interpreted as signed 16 bits; that outcome is conditional on the target’s narrowing behavior.

### Access ordering

The established ordering is:

1. Read the nested-state pointer.
2. If non-null, read the record count used to decide whether duplicate detection is necessary.
3. If that count exceeds one, obtain the record base and level-dependent comparison selection.
4. Read the first words of the selected records.
5. Only if those compare equal, read their second words.
6. Only if both comparisons succeed, read the trailing associated byte.
7. Only if that byte equals 1, update the record-count field.
8. Test the current level count and, if positive, perform the boundary write using the current record count.

The supplied expression structure does not establish a strict order between the two operand reads within an equality comparison. It also does not establish a complete instruction-level order for the individual address and value reads that make up the final store.

### Aliasing

No non-aliasing checks or guarantees are present.

If the boundary array overlaps the nested state, the final write may also change a field occupying the same bytes. Likewise, a count-field write can affect later accesses if subordinate storage or pointer fields overlap that location.

The ordinary interpretation—separate state fields, record storage, associated-byte storage, and boundary storage—is a useful layout assumption, not an enforced property. Acceptance examples below assume that ordinary layout unless stated otherwise.

## Acceptance examples

These examples are conditional on valid storage, the stated 32-bit representation, no concurrent modification, and non-overlapping storage except where explicitly noted.

### Null nested state

Given an outer object whose nested-state pointer is null:

- The function returns without reading nested-state fields.
- No store occurs.

### Matching trailing record at level one

Given:

- Level count 1.
- Record count 4.
- Records 0 and 3 equal in both words.
- Associated byte 3 equal to 1.

The function changes the record count to 3, then writes 2 to boundary entry 0. Record 3 and its associated byte remain physically unchanged.

### First-word mismatch

Given a positive level count and a record count greater than one, with different first words in the selected records:

- The second words are not read for comparison.
- The associated byte is not read.
- The count is unchanged.
- The current level’s boundary is updated to the unchanged count minus one.

### Matching words with a nonqualifying byte

Given a level count of 1, record count 3, matching records 0 and 2, and associated byte 2 equal to 2:

- The record count remains 3.
- Boundary entry 0 receives 2.

The byte must equal 1, not merely be nonzero.

### Selection through an earlier boundary

Given:

- Level count 3.
- Record count 6.
- Boundary entry 1 equal to 2.

The comparison uses records 3 and 5. If both words match and associated byte 5 equals 1, the count becomes 5 and boundary entry 2 receives 4.

Boundary entry 1 is read for selection; boundary entry 2 is written during finalization.

### Comparison record equals trailing record

Given:

- Level count 2.
- Record count 4.
- Boundary entry 0 equal to 2.
- Associated byte 3 equal to 1.

Both selections name record 3. Under stable memory, both comparisons succeed. The function decrements the count to 3 and writes 2 to boundary entry 1.

No distinct-record requirement prevents this removal.

### Count one or zero

With level count 1:

- A record count of 1 causes no record comparison and writes 0 to boundary entry 0.
- A record count of 0 causes no record comparison and writes −1 to boundary entry 0.

Record and associated-byte storage are not accessed on these paths.

### Nonpositive level count

Given level count 0, record count 2, equal records 0 and 1, and associated byte 1 equal to 1:

- The count becomes 1.
- No boundary entry is read or written.

A negative level count follows the same comparison-record selection rule and likewise suppresses the final boundary write.
