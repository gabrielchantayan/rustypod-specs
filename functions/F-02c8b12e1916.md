# F-02c8b12e1916

## Purpose

F-02c8b12e1916 specifies an operation that publishes argument values, performs mixed-width writes through computed addresses and stored address chains, and finishes with an unresolved indirect transfer.

The supplied static representation establishes substantial access ordering and saved-value dependencies. It does not establish an application-level purpose, valid object model, allocation policy, or ordinary input domain that permits successful completion. Interpreting the operation as initialization, collection maintenance, string construction, or callback dispatch would add unsupported requirements.

This contract distinguishes established represented behavior from inferred intent and documented_only unknowns. No runtime tests have been performed.

## Behavior

### Access model

A **byte**, **halfword**, and **word** mean 8, 16, and 32 bits respectively. Address-shaped stored values are represented as 32 bits. Narrow stores retain the low bits of their operands.

The representation contains one long sequence without a visible validation branch, loop, or early return. Comparisons generally produce arithmetic bits. The explicitly described carry predicate has short-circuit behavior.

Access order matters:

- Different roles may alias.
- A later read may observe an earlier write.
- Reloading a field is distinct from reusing a saved value.
- Repeated stores, including identical stores, remain represented operations.
- Reading a word and writing it back remains a read followed by a write.

### Carry-dependent construction and entry into reached records

E13 is saved. A separate E13 reference supplies the base whose offset 0x54 receives the halfword previously obtained from E08. E14 and then E15 are loaded and saved.

The next arithmetic explicitly uses unsigned 32-bit carries:

- **Incoming** is the comparison bit Operand≤ArithmeticBase.
- **DoubleExternal** is twice saved-E13 plus Incoming, retaining the represented 32-bit result.
- **Carry** is carry-out from doubling saved-E13, or, only if needed, carry-out from adding Incoming to the doubled result.
- One E16 reference supplies **MarkerBase**, equal to that value plus Carry.
- A separate predicate first checks whether E16 exceeds 0xffffffa6. Only if false does it reference E16 again to test carry-out from adding Carry to E16+0x59.
- **Offset** is saved-E08 plus DoubleExternal plus that predicate bit.

The E16 references are not assumed equal. Their containing expressions occur in the stated sequence; no additional ordering is imposed among operands within an expression.

E14 is reread for the comparison Operand≤E14, independently of its saved halfword payload.

## Acceptance examples

These are conditional static criteria, not executed tests.

- **Initial low address:** If Context+0x05 contains 3, Small is address 3. Subject to valid accesses, the early word destinations include 3+0x64 and 3+0x54, not a scaled structure lookup.
- **Saved versus reread E01:** If the first E01 read yields X and the destination-forming read yields Y, the A3-relative halfword destination uses Y, while the later Work-relative halfword arithmetic uses X.
- **E16 short circuit:** If the predicate’s first E16 reference exceeds 0xffffffa6, its carry-producing alternative is not evaluated. If it does not, the alternative may consume another E16 value. Neither is required to equal the earlier MarkerBase reference.
- **Overlapping widths:** If the saved Work word has low halfword 0x1234 and A4 has low byte 0xaa, the A2+0x45 halfword is written before its first byte is replaced. Without other alias effects, little-endian bytes become 0xaa, 0x12; big-endian bytes become 0xaa, 0x34.
- **Distinct 0x66 snapshots:** Before66 supplies the later Central+0x0d byte. Former74 is read only after the 0x66 record writes and supplies the offset-0x40 destination. Aliasing may make these snapshots differ.
- **Late external ordering:** E21 is read before E22 and TransferWord. The final stores use those saved values; an aliasing write does not retroactively alter them.
- **Transfer arithmetic:** If FinalCharacter is 0x20, the first transfer argument is 0x64, by bitwise OR rather than addition.
- **Partial failure:** If a late reached-memory access faults, earlier publications and record mutations need not be undone.
