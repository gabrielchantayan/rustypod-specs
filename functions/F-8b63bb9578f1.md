# F-8b63bb9578f1

## Purpose

F-8b63bb9578f1 conditionally processes a mutable object, performs mode-dependent preparation, coordinates against an externally referenced record, publishes one byte into the object, and conditionally invokes a target obtained from a separate global slot.

The eligibility check uses an object-relative displacement **read from a global source**, not a displacement established as a fixed constant. The final indirect invocation uses a **separate global call-target slot**, read only after the completion-pointer checks succeed.

“Mode,” “selector,” “preparation,” and “completion” are descriptive roles inferred from use. They do not establish application semantics, a synchronization protocol, or ownership rules.

This contract describes the supplied static representation. No runtime tests have been performed.

## Behavior

### Eligibility gate

The routine first reads the global eligibility-displacement source. It uses that value to locate and read one byte relative to the supplied object.

If the byte is not 3, the routine returns. This path performs no dependency calls and no explicit writes. It does not proceed to the mode fields, external-base source, completion pointer, or global call-target slot.

If the byte is 3, processing continues. Neither the displacement source nor the eligibility byte is explicitly read again during this invocation. Later dependencies may modify either without causing another eligibility check.

### Mode-dependent preparation

The routine next reads the mode byte at `0x264`.

**Initial mode zero.** Indexed preparation begins with index zero. F-67b5db3dc22a receives the object address and current index. A zero result terminates this preparation loop. Each nonzero result is followed by F-cf4ff229c311 and then F-38c4e07bf57b, both receiving the object address. The index increases only after those two calls return.

After the terminating zero result, F-53c49ac07f32 receives the object address, followed by F-3b847a021d74.

There is no explicit iteration bound and no mode recheck controlling this loop. A dependency changing `0x264` does not directly terminate indexed preparation; a subsequent zero result from F-67b5db3dc22a does.

**Initial mode nonzero, secondary flag zero.** The routine reads `0x265`. If it is zero, the routine writes byte value 8 to `0x245` and enters the shared stage. This path skips F-3b847a021d74 and all indexed preparation.

**Initial mode nonzero, secondary flag nonzero.** The routine calls F-3b847a021d74 with the object address and enters the shared stage. No direct write to `0x245` occurs on this path.

These choices use the initial mode observation. Later mode reads can observe a different value.

### Shared coordination and selection

Every eligible path that completes preparation calls F-338d16f9ce72 with the interior address at `0x230`.

Only after that call returns does the routine read the global external-record base. Thus, a change to that source made by F-338d16f9ce72 can affect the record selected for this invocation.

The captured base is retained throughout the subsequent comparisons and selected-byte read. Changes to the global base source during wait calls do not themselves replace the retained base.

The routine compares the selector byte at object offset `0x22c` with the byte at retained-record offset `0x3c`. Their relative read order within a comparison is not independently established.

For a mismatch, the routine reads the current mode at `0x264`:

- If nonzero, selection proceeds directly from external offset `0x3f`, without another explicit mode read before that value read.
- If zero, F-162a41bac6a7 receives the interior address at `0x238`. After it returns, the selector comparison repeats.

Each repeated comparison obtains fresh selector-field values from the object and retained record.

For a matching comparison, the routine reads the current mode. Zero selects the byte at external offset `0x3e`; nonzero selects the byte at `0x3f`.

Consequently, unequal selectors delay publication only while the relevant mismatch-path mode observations remain zero. Selector equality alone does not determine which external byte is selected.

### Publication and conditional invocation

The routine reads the selected external byte and writes it to object offset `0x22d`. It then calls F-b8a325ddd21b with the interior address at `0x238`.

After that dependency returns, the routine reads the pointer stored at `0x230`.

- A null pointer suppresses both the referent read and indirect invocation.
- A non-null pointer causes an integer read from the pointer’s base.
- A zero integer suppresses indirect invocation.
- A nonzero integer permits the separate global call-target slot to be read, followed by invocation of the loaded target.

The order is significant: publication precedes F-b8a325ddd21b; that dependency precedes the completion-pointer read; the non-null check precedes the referent read; and both successful completion checks precede the global target read.

The completion pointer and referent are not explicitly rechecked after target resolution. No separate null or validity check on the loaded call target is shown. A non-null completion pointer with a nonzero referent therefore does not establish that invocation is safe.

The representation shows no explicit arguments supplied to the indirect target. Its complete machine-level ABI is unknown. If that invocation returns normally, this routine returns.

## Side effects

### Direct writes

Two direct writes are established:

1. Byte value 8 to `0x245`, only for an initially nonzero mode and zero secondary flag.
2. The selected external byte to `0x22d`, on every path reaching publication.

No direct write to any of the three global sources is shown. There is no direct allocation, deallocation, completion-pointer replacement, or completion-field clearing in the visible body.

The byte written to `0x22d` is not necessarily its value at return. F-b8a325ddd21b or the indirect dependency may subsequently change it.

### Dependency-mediated changes

Dependencies receive either the whole object or interior addresses. Their write sets and ownership effects are unknown. No preservation guarantee is established for:

- Object fields or object lifetime.
- The eligibility-displacement source.
- The external-base source or retained record contents and lifetime.
- The completion pointer or its referent.
- The global call-target slot or target lifetime.

These possible changes have different consequences according to read timing. A later displacement-source change does not trigger a new eligibility read. A base-source change after capture does not retarget the retained record. A target-slot change before its late conditional read can affect the invoked target.

### Errors and termination

No explicit error result, recovery path, timeout, or cancellation handling is shown.

The indexed loop can continue without a terminating zero result, subject to unresolved index-exhaustion behavior. The selector loop can continue while selectors remain unequal and each relevant mode read remains zero. Dependencies may also fail to return.

Invalid addresses, expired storage, an invalid target, and dependency-specific failures have no visible handling here. Call ordering alone establishes no lock, atomicity, memory-order, visibility, or wakeup guarantee.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless a case specifies otherwise, dependencies return normally and preserve the storage and values relevant to that case.

### Globally selected eligibility location

Suppose the global displacement identifies a readable object byte containing 2. The routine reads the displacement, reads that byte, and returns without dependency calls or direct writes.

If a later invocation observes a different displacement, eligibility is determined from that newly selected location. The displacement is not specified as an immutable constant.

### Two successful preparation iterations

Given eligibility 3 and initial mode zero, suppose F-67b5db3dc22a returns nonzero for indices 0 and 1, then zero for index 2.

Each of the first two indexed calls is followed by F-cf4ff229c311 and F-38c4e07bf57b, in that order. The indexed call for 2 is followed by neither per-iteration call. F-53c49ac07f32 and then F-3b847a021d74 run before the shared-stage call.

If the first indexed result is zero instead, both per-iteration calls are skipped, but those two post-loop calls still occur.

### Nonzero mode with zero secondary flag

Given eligibility 3, initial mode nonzero, and secondary flag zero, the routine writes 8 to `0x245` before F-338d16f9ce72. It does not call F-3b847a021d74 on this preparation path.

### External-base changes at different times

If F-338d16f9ce72 replaces the global external base, the subsequent capture uses the replacement. If a later F-162a41bac6a7 call changes only that global source, subsequent comparisons still use the previously captured record, provided it remains valid.

### Selector and mode outcomes

If selectors match and the following mode read is zero, the routine selects external byte `0x3e` without a wait call.

If selectors differ and the mismatch-path mode read is nonzero, it selects external byte `0x3f` without a wait call for that comparison.

If a wait call leaves selectors unequal but makes mode nonzero, the next mismatch-path mode read permits selection from `0x3f`; a second wait call is unnecessary.

### Completion pointer changed after publication

Suppose the completion pointer starts null. F-b8a325ddd21b replaces it with a valid pointer to a nonzero integer. The later checks use the replacement, after which the global target slot is read and its target invoked.

Conversely, if F-b8a325ddd21b clears the pointer, neither a referent read nor a target-slot read occurs.

### Late target resolution

Suppose F-b8a325ddd21b changes the global target slot, and the subsequent pointer and integer checks both pass. Invocation uses the target obtained from the post-check slot read, not a target captured before publication.

If the completion pointer is non-null but its integer is zero, the global target slot is not read. Its contents do not affect that path.
