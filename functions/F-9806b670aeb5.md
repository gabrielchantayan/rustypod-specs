Some destination addresses are inherently small:

- An unsigned-byte-derived destination plus 0x11 lies between 0x11 and 0x110.
- Small index plus 7 lies between 7 and 1030.
- Masked base shifted right by 20, plus 0x11, lies between 0x11 and 0x410.

These accesses must not be silently reinterpreted as fields within an ordinary allocated object. A platform-specific low-address mapping, a different underlying interpretation, or invalid execution remains possible.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Each assumes that execution reaches the relevant operation and that required accesses and calls are valid.

1. **Full-width versus byte input use.**  
   With third argument 0x123456ab, the stores at sixteenfold base plus 0x0d write byte 0xab. The four-byte store at masked base plus 0x14 writes the complete bit pattern 0x123456ab. Byte order remains unspecified.

2. **Unsigned second-argument transformation.**  
   With second argument 0xffffffff, its retained right-shifted value is 0x3fffffff. The later byte store at small index plus 7 writes 0xfe.

3. **Width truncation.**  
   A first index of 0x20 gives an eightfold base of 0x100. Its byte stores write 0x00, not a wider representation of 0x100.

4. **Observable replacement.**  
   If the second value is 3, the initial word at eightfold base plus 0x34 is 12. If the first pair’s high half is subsequently 0x11223344, that later word replaces it. The intervening dependencies must still occur between the stores.

5. **Fresh byte lookup.**  
   If the two record-base-plus-1 loads yield 2 and 7, the small-index byte targets address 0x13, while the later zero targets 0x18. Reusing the first loaded byte is not equivalent.

6. **Unsigned-byte boundary.**  
   A saved byte of 255 gives doubled-byte base 510. F-D14.1 receives 510, 0x98, and 0x260; the saved-field-byte store later targets address 0x20b.

7. **Split-result ordering.**  
   For second-pair high half 3, the corresponding four-byte store targets 0x20. F-D20.1 receives three copies of four times the low half, followed by zero because 3 shifted right by three is zero.

8. **Repeated terminal clearing.**  
   If a dependency changes the byte used to select the terminal clearing destination, the two zero stores may target different addresses. Both fresh loads are required.

9. **Incomplete execution.**  
   If an earlier dependency does not return, no later store is required to occur. Reaching the visible endpoint does not establish successful normal completion.
