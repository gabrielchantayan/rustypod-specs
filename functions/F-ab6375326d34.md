1. Store the second argument’s low 16 bits at the first argument plus 4.
2. Read a 32-bit word beginning at `0x0000008b`.
3. Store five words through the third argument, in increasing offset order.
4. Read a signed halfword at the current register-derived read base plus `0x27`.
5. Test signed subtraction overflow for the third argument’s address minus `0x2c`.

The five-word layout is:

| Offset | Stored word |
|---:|---|
| 0 | Current second argument |
| 4 | Current third-argument address |
| 8 | Current saved register-derived data word |
| 12 | `0x27` |
| 16 | The word just read from `0x0000008b` |

The loop exits when the subtraction overflows. For a 32-bit signed subtraction by positive `0x2c`, the qualifying address bit patterns are `0x80000000` through `0x8000002b`, inclusive. This is not an unsigned lower-bound check.

On continuation, the first argument becomes the incoming alternate base; the third becomes that base plus `0x32`; the second becomes the captured global word’s top byte, zero-extended. Both the saved data word and the halfword-read base become the captured global word.

The alternate base has no represented update. Consequently, after one continuation, the tested pointer remains fixed. If its subtraction does not overflow, the loop can continue indefinitely, subject to successful accesses.

All accesses are ordered, not transactional. Aliasing can make earlier stores affect later reads.
