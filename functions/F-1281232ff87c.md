# F-1281232ff87c

## Purpose

F-1281232ff87c is a selector-driven dispatcher over shared state and an associated object. Its visible responsibilities are:

- Comparing object-reported 32-bit values with four cached bytes.
- Conditionally preparing those bytes through a check and a subsequent paired dependency call.
- Propagating selected values and argument pointers to dependencies.
- Invoking operations through an object dispatch table.
- Conditionally invoking a common completion dependency.

These are structural descriptions, not established application semantics. “Cache,” “preparation,” and “completion” describe visible roles without assigning ownership, locking, or domain meaning.

Every visible normal return is the 32-bit value zero. The return value does not distinguish an ignored selector, an unchanged value, a completed operation, or an early return.

### Pointer selection and validity

The entry-captured state base remains the base for later cache accesses and object-pointer reloads. Gate reads instead obtain their base through the global shared-state pointer at the time of the gate check.

The entry-captured object is retained for selectors 3, 4, 7, 13, 15, 21, and 24. Other operations described below reload the object from offset 4 of the captured state.

All accessed storage must remain valid for its actual use. In particular:

- Even inactive and unmatched selectors require the entry state and object-pointer-field reads to be valid.
- Each indirect operation requires a readable object, readable dispatch table, and callable selected entry.
- Each direct byte destination must be writable.
- Selector 3’s zero-result path additionally requires a readable global pointer and a readable 32-bit word at its resulting target.

No null checks, bounds checks, allocation-lifetime checks, or explicit concurrency controls are visible.

## Behavior

### Synchronization selectors: common rules

Selectors 0, 1, 2, and 6 use the following resources:

| Selector | Cache offset | Gate offset | Getter table offset | Value recipient |
|---:|---:|---:|---:|---|
| 0 | 0 | 16 | 164 | F-ba751bebfb5c |
| 1 | 2 | 24 | 172 | F-78e5494d5952 |
| 2 | 3 | 28 | 172 | F-749e6a2776e3 |
| 6 | 1 | 20 | 168 | F-66f0d279d88f |

Selectors 1 and 2 share a getter-table offset, but have distinct cache bytes, gate words, global argument sources, and value recipients.

**Every synchronization getter invocation independently resolves its target.** Immediately before each getter call, the function reloads the object pointer from offset 4 of the entry-captured state, reads that object’s current dispatch-table pointer, and selects the entry at the applicable offset. This applies to:

- The preparation getter after a successful check.
- The subsequent comparison getter.
- The additional mismatch getter used by selectors 0, 1, and 2.

Neither the entry object, an earlier object reload, nor an earlier dispatch-table entry is reused for these calls. An intervening dependency can therefore change which object or table supplies a later getter. No explicit arguments are shown for these getter calls; hidden receiver or ABI details remain unresolved.

Preparation proceeds conditionally:

1. Read the applicable gate word through the global shared-state reference.
2. If bit 0 is set, skip preparation, including both paired dependencies.
3. Otherwise, read the applicable selector-specific global argument source and pass that value to F-b255b26284e6.
4. If the check returns zero, skip the preparation getter, preparation write, and paired call.
5. If it returns nonzero, resolve and invoke the preparation getter.
6. Write the cache byte as 1 if the full unsigned 32-bit getter result is zero; otherwise write 0.
7. Read the same selector-specific **global source again**, and pass its then-current value to F-d08d3ca17b81.

The two dependencies share an argument source, not a retained argument value. F-b255b26284e6 or the preparation getter may change that source before the later read. The cache write precedes the later source read and paired call.

The preparation result is exactly 1 for getter result zero and 0 for every other 32-bit result. It is not inversion of the getter’s low bit.

Whether preparation runs or is skipped, the function next resolves and invokes the comparison getter. It compares the getter’s full unsigned 32-bit result with the current cached byte, promoted to a value between 0 and 255. The cache read follows the getter call, so getter-side cache mutation can affect equality.

Getter calls are distinct observable operations and need not return equal values.

### Selector 0

If the comparison result equals cache byte 0, there is no further branch-specific action.

On mismatch, the order is:

1. Invoke F-9cc71512e54b.
2. Reload the object and its current table, then invoke the getter at offset 164.
3. Store the low eight bits of this new result in cache byte 0.
4. Reload the object pointer from offset 4 of the captured state.
5. Call F-ba751bebfb5c with that object and the full new 32-bit result.

The result that triggered the mismatch is not the value necessarily stored or forwarded. Both F-9cc71512e54b and the additional getter can change state relevant to later accesses.

### Selector 1

On equality with cache byte 2, there is no further branch-specific action.

On mismatch, reload the object and its current table and invoke the getter at offset 172 again. Store the low eight bits of this new result in cache byte 2. Then reload the object pointer from the captured state and pass it, with the full new result, to F-78e5494d5952.

There is no F-9cc71512e54b call on this path.

### Selector 2

Synchronization follows selector 1’s ordering, using cache byte 3 and F-749e6a2776e3.

After synchronization, including any value-recipient call, read cache byte 3 again:

- Zero causes an immediate normal zero return.
- Nonzero causes F-86af3805fd91 to be invoked before returning zero.

This decision uses the final cache read, not a retained getter result. Mutation by the getter, paired dependency, or value recipient can affect the decision. The final read also occurs when the comparison was equal.

### Selector 6

The comparison getter result is retained and reused on mismatch; there is no additional mismatch getter.

On mismatch:

1. If the retained full result is nonzero, invoke F-9cc71512e54b.
2. Store the low eight bits of the retained result in cache byte 1.
3. Reload the object pointer from the captured state and call F-66f0d279d88f with that object and the full retained result.
4. If the retained result is zero, call F-UNKNOWN-1 with 1000, then invoke F-9cc71512e54b.

Both zero/nonzero decisions use the retained full-width result, even if dependencies alter the cache. The value 1000 is an established argument, not an established duration or unit.

On equality, none of these mismatch actions occurs.

### Selector 3

After F-e77fb9edce7e returns:

- If the retained result is zero, read the separate global pointer, dereference its then-current target for one 32-bit word, and call F-4c05775b039e with that word and zero. Then return zero.

## Side effects

Direct writes are limited to the four cache bytes and, for selector 15, one byte at object offset 36. Narrowing stores preserve only the low eight bits; they do not restrict the full-width values forwarded to dependencies.

Dependencies and indirect operations may independently modify globals, state, tables, objects, or argument storage. No preservation guarantee is supplied. The contract’s explicit reloads matter because later operations can observe these changes.

No allocation or release is directly visible. Passing an object or argument pointer does not establish ownership transfer, borrowing duration, retention rights, or preservation of allocation lifetime. Paired call placement does not prove acquisition/release semantics.

There is no visible transaction, rollback, retry, or exception recovery. A cache write precedes its corresponding downstream call and is not visibly undone if later execution fails.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless explicitly varied, dependencies return normally and leave relevant storage valid and unchanged.

1. **Gate suppression:** For selector 0 with gate bit 0 set, neither preparation dependency executes, but the comparison getter still executes.

2. **Independent argument reads:** For selector 1, suppose the global argument source initially contains value A. F-b255b26284e6 receives A, changes the source to B, and returns nonzero. If the preparation getter then changes it to C, F-d08d3ca17b81 receives C, not A or B.

3. **Object replacement during preparation:** For selector 2, if the successful check replaces the object pointer at captured-state offset 4, the preparation getter resolves through the replacement’s current table. If the paired call replaces it again, the comparison getter resolves through that later object.

4. **Table replacement between getters:** For selector 1, if the comparison getter changes its object’s table and produces a mismatch without replacing the object pointer, the additional getter resolves through the changed table.

5. **Preparation forces comparison:** For selector 1, successful preparation with all getter results equal to 1 writes cache byte 2 as 0. Comparison then mismatches; the additional getter result 1 is stored and forwarded.

6. **Full-width comparison and truncation:** For selector 1 with preparation skipped, cache byte 2 equal to zero, and getter results 256, comparison mismatches. The cache receives zero and F-78e5494d5952 receives 256. An identical later invocation can mismatch again.

7. **Repeated values differ:** For selector 0, comparison result 1 against cache zero triggers F-9cc71512e54b. If the subsequent getter returns zero, zero is stored and forwarded.

8. **Selector-2 final reread:** If selector 2 stores zero but F-749e6a2776e3 changes cache byte 3 to a nonzero value, F-86af3805fd91 executes. Conversely, a nonzero full getter result does not force completion when the final cache byte is zero.

9. **Selector-6 zero ordering:** With preparation skipped, cache byte 1 nonzero, and comparison result zero, the order is cache write, F-66f0d279d88f, F-UNKNOWN-1 with 1000, then F-9cc71512e54b.

10. **Selector-3 pointer replacement:** If the operation result is zero and F-e77fb9edce7e redirects the separate global pointer from a word containing 7 to a word containing 9, F-4c05775b039e receives 9 and zero.

11. **Selector-15 truncation:** An argument word of 0x123456AB causes object byte offset 36 to receive 0xAB before F-9ebbb41fe4b5.

12. **Inactive selector:** Selector 23 returns zero without branch-specific calls, provided the initial state and object-pointer-field reads are valid.
