# F-ac48cbf12373

## Purpose

F-ac48cbf12373 performs a table-directed initialization of caller-supplied storage, invokes two dependencies in sequence, and optionally invokes a third dependency to adjust the returned result.

Its established behavior is structural: it selects a table, copies three table-derived values into destination locations, and passes adjusted addresses or address-like values to dependencies. The evidence does not establish the higher-level object type, the meaning of the copied values, or whether successful execution creates an owned resource.

The mode argument has two effects:

- Zero selects the caller-supplied table and returns the second dependency’s result directly.
- Any nonzero value selects a table through a global pointer slot and enables a final dependency call and result adjustment.

An object-construction or subobject-initialization role is plausible, but remains inferred intent rather than a guaranteed interface meaning.

## Interface

### Inputs

The function accepts three arguments:

1. **Destination address.** A pointer to writable storage. The function directly writes at the destination’s beginning, at a table-directed byte displacement from that beginning, and at byte offset 8.
2. **Mode.** An integer tested only for equality or inequality with zero. Positive and negative nonzero values take the same branch.
3. **Caller table address.** A pointer to a table of integer-sized words. It is selected only when mode is zero. When mode is nonzero, a pointer obtained from a global slot replaces this argument before any table dereference.

For this contract, **D** denotes the destination address and **T** denotes the selected table address. These are descriptive contract labels, not identifiers from the implementation.

### Widths and layout

The recovered representation uses integer words with a four-byte stride and treats integer values as addresses in several expressions. Its evident layout is:

| Location | Role in this function |
|---|---|
| T + 0 bytes | First table word; copied to D and used as an address-like value |
| T + 4 bytes | Start of the table region passed to the second dependency |

The behavior below uses this recovered four-byte, 32-bit integer/address model. The supplied evidence does not independently establish a machine ABI, byte order, alignment policy, or language-level rules for integer-to-pointer conversions. A portable implementation cannot infer those properties merely from the recovered declarations.

### Output

The result is an integer-sized value derived from dependency results:

- With nonzero mode, it is the result of F-1de9cff4fc92 minus 60.

The result may be address-like, but the evidence does not establish that it is a valid pointer, an allocation handle, a status code, or a pointer into D.

### Preconditions

## Behavior

### 1. Select the table

With zero mode, T is the caller table.

With nonzero mode, T is obtained from a global pointer slot. The caller table is not dereferenced by this function on that path.

Selection occurs before the first table read. Later operations use the selected pointer; the function does not visibly reload the global slot.

### 2. Read and install the first table word

The function reads the word at T and writes that value to D.

The value read is also retained for use as an address-like value in the displacement lookup. That lookup uses the retained value, not a fresh read from D.

This distinction matters when storage overlaps: modifying D does not, by itself, change which address is used for the displacement lookup.

### 3. Perform the displacement-directed write

The function obtains:

- A displacement word from 12 bytes before the address represented by the retained first table word.
- A payload word from T + 32.

It writes the payload to the address formed by adding the displacement to D in bytes. The displacement is not multiplied by the word size.

Both reads occur after the initial write to D and before the displacement-directed write. The supplied expression does not establish their relative order. A contract must therefore not require the displacement read to precede the payload read, or vice versa.

The displacement is represented as an integer. The evidence imposes no bounds check and no requirement that it be positive, nonzero, or contained within a known destination allocation. A negative displacement can designate storage before D, subject to the target’s address and arithmetic rules.

### 4. Write the fixed-offset field

After the displacement-directed write, the function reads the word at T + 36 and writes it to D + 8.

This is a later read, not part of a snapshot taken when T was selected. If an earlier destination write overlaps T + 36, the value subsequently read there can reflect that earlier write.

The direct writes therefore have this order:

1. First table word to D.
2. Payload from T + 32 to the displacement-selected destination.
3. Value read from T + 36 to D + 8.

If destination locations coincide, the later write takes precedence at that location, unless execution is interrupted.

### 5. Invoke the first dependency

After all three direct writes, the function invokes F-d22dfb665fd5 with D + 12.

Its returned integer-sized value becomes the basis for the next call. There is no visible result validation, error classification, or fallback branch.

### 6. Invoke the second dependency

The function invokes F-7f75b2158dce with three arguments, in this order:

1. The first dependency’s result minus 12.
2. Integer zero.
3. T + 4.

The third argument is an address into the selected table, not the word stored at that address. The function does not visibly copy this table region before passing its address.

The first dependency may have changed memory reachable through T or other shared state. No preservation guarantee is established. The selected pointer value remains the one chosen earlier, but the contents at that address are not guaranteed unchanged.

### 7. Select the return path

With zero mode, the function returns the second dependency’s result without calling F-1de9cff4fc92.

With nonzero mode, it:

1. Adds 60 to the second dependency’s result.
2. Passes that adjusted value to F-1de9cff4fc92.
3. Subtracts 60 from that dependency’s result.
4. Returns the adjusted result.

There is no visible check for a null-like value, error sentinel, or arithmetic boundary before these adjustments. The second dependency’s result is not necessarily the nonzero-mode return value.

## Side effects

The function itself visibly performs three word stores before invoking any dependency. Their addresses are D, a table-directed displacement from D, and D + 8.

It also visibly reads:

- The global table-pointer slot in nonzero mode.
- The selected table’s first word.
- The displacement word associated with that first word.
- The selected table’s words at byte offsets 32 and 36.

No direct write to the global pointer slot is shown. This does not establish that dependencies preserve that slot or any other global state.

There is no explicit allocation, deallocation, ownership transfer, reference-count operation, synchronization operation, or rollback in the visible body. Such effects remain possible inside dependencies. Passing D + 12 or T + 4 does not, by itself, establish ownership transfer or permission to release either region.

The direct stores are not transactional. If a later access faults or a dependency fails to return, earlier stores may already have occurred. No recovery path is visible.

Aliasing is not rejected. Its consequences follow the access order above, provided the target permits the accesses. For example, a displacement-directed write can overwrite either an earlier destination field or a table word that has not yet been read.

Concurrent mutation and memory-mapped I/O semantics are not established. The recovered representation contains no explicit synchronization or volatile-access contract.

## Acceptance examples

These examples are conditional consequences of the static evidence, not runtime observations. Each assumes valid accesses, returning dependencies, and representable arithmetic.

### Zero mode with distinct storage

Suppose the caller table supplies:

- A first word representing an address with displacement 20 stored 12 bytes before it.
- Payload 81 at byte offset 32.
- Value 93 at byte offset 36.

With no relevant aliasing, the direct effects are:

- D receives the first table word.
- D + 20 receives 81.
- D + 8 receives 93.

F-d22dfb665fd5 receives D + 12. If it returns 1,000, F-7f75b2158dce receives 988, zero, and the caller table address plus 4. If that dependency returns 2,000, the function returns 2,000. F-1de9cff4fc92 is not called.

### Nonzero mode selects the global table

For mode −1, the table is obtained from the global slot. The caller table is not dereferenced by this function.

If F-7f75b2158dce returns 2,000, F-1de9cff4fc92 receives 2,060. If it returns 3,060, the function returns 3,000.

The same branching rule applies to mode 1 or any other nonzero value.

### Coincident destination writes

If the displacement is 8, the second direct store targets D + 8. The third direct store then targets that same location.

Assuming the second store does not alter the later table read, D + 8 contains the value read from T + 36 immediately before the first dependency is called.

If the displacement is zero, the second store overwrites the initial value at D. The displacement lookup still used the retained first table word.

### A write changes a later table read

If the displacement-selected destination is T + 36, the second store changes the word that the next step reads. Subject to valid aliasing, the value copied to D + 8 is consequently the newly stored payload, not an assumed original table value.

### Negative displacement

A displacement of −4 designates a word immediately before D. The function performs no visible rejection of that displacement. Whether the access is valid depends on the available storage and target execution rules.
