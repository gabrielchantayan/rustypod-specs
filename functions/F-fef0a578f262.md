# F-fef0a578f262

## Purpose

The available static representation describes a context-dependent routine that performs a sequence of indirect calls, writes one 32-bit word, and later performs two byte writes whose destinations depend on separately read selector bytes. Several call results are scaled or forwarded to subsequent calls.

No application-level purpose is established. In particular, the evidence does not identify the writes as device operations, table updates, memory allocation, or serialization. Those interpretations would require information not supplied here.

The representation explicitly reports invalid instruction data and ends at a truncated control-flow boundary. Consequently, this contract describes the represented execution prefix, conditional on that representation being faithful. It does not establish a complete executable function, a successful return, or the behavior of an actual processor at the endpoint.

## Behavior

### Dependency naming

The opaque IDs F-indirect-01 through F-indirect-20 identify call occurrences in execution order. They are local contract labels for unresolved dependencies, not assertions of recovered function identity. Different labels are not proof that the underlying callees are distinct.

### 1. Obtain an index and write the incoming payload

The routine first invokes F-indirect-01 without explicit arguments in the available representation. Its target is computed from the incoming link-address value plus 4,094 bytes.

The returned value is interpreted as a signed integer and scaled by four. The routine then stores the incoming 32-bit payload at the address obtained by adding 20 bytes to that scaled value.

This is an address computation, not an established access through a known array base. No independent base pointer is shown.

For a nonnegative result whose arithmetic does not overflow, a result of three therefore yields a destination address of 32. The available representation does not justify extending mathematical signed multiplication to every possible returned bit pattern without qualifying overflow and address semantics.

After the store, the routine invokes F-indirect-02 with the scaled result as its sole explicit argument.

### 2. Execute the initial call chain

The routine next invokes, in order:

1. F-indirect-03.
2. F-indirect-04.
3. F-indirect-05.
4. F-indirect-06.

No explicit arguments are represented for these four calls. Only the result of F-indirect-06 is subsequently consumed in this portion of the prefix. That result is treated as an unsigned 32-bit value, referred to here as the **control word**.

“No explicit arguments” does not establish that a callee has no implicit inputs. It also does not establish that any return value unused here is absent from the underlying calling convention.

### 3. Perform the first selector read and byte write

The routine computes the control word shifted left by two bits. Under 32-bit unsigned arithmetic, this is multiplication by four modulo \(2^{32}\).

It then:

1. Reads one unsigned byte from the incoming base address plus one byte.
2. Adds 17 to that byte value to obtain a destination address.
3. Writes the low eight bits of the shifted control word to that destination.

The destination is derived directly from the selector value. It is **not** the incoming base plus the selector plus 17.

Because an unsigned byte ranges from zero through 255, the destination address ranges from 17 through 272. The expression gives no evidence of an additional memory-region base.

Under eight-bit truncation, the written value is four times the control word modulo 256. Its low two bits are always zero.

The routine next invokes F-indirect-07 with three explicit arguments:

- The control word shifted left by two.
- The same shifted value again.
- The control word shifted left by four.

The unsigned shifts discard bits beyond the 32-bit word boundary in the represented 32-bit model.

### 4. Forward a result and execute the middle call chain

The routine invokes F-indirect-08 and treats its result as a four-byte value.

It immediately invokes F-indirect-09 with that value as its sole explicit argument. The value is forwarded without an explicit transformation in the supplied representation.

The routine then invokes:

1. F-indirect-10.
2. F-indirect-11.
3. F-indirect-12.
4. F-indirect-13.

No explicit arguments are represented for these four calls. The result of F-indirect-13 is retained as a signed integer for a later scaling operation.

### 5. Re-read the selector and perform the second byte write

After F-indirect-13 returns, the routine reads the selector byte again from the incoming base address plus one.

This is a distinct read. The contract does not replace it with the earlier selector value. Intervening dependencies or other permitted memory activity may have changed the byte.

Using this newly read selector, the routine computes another destination address as selector plus 17 and writes a byte derived from the original control word:

- Clear bits 30 and 31 of the control word.
- Shift the remaining value right by 20 bits.
- Retain only the low eight bits for the store.

The final stored byte is therefore control-word bits 20 through 27. Although the intermediate right-shifted value can contain ten bits, the byte store discards its upper two bits.

There is no explicit dependency call between this second selector read and the corresponding byte write.

The second selector value is retained for a later call. It is not read from memory a third time in the represented prefix.

### 6. Execute the final call chain

After the second byte write, the routine invokes F-indirect-14 with the result of F-indirect-13 shifted left by two bits.

It then invokes, in order:

1. F-indirect-15.
2. F-indirect-16.
3. F-indirect-17.
4. F-indirect-18.

No explicit arguments are represented for these four calls. F-indirect-18 returns another value interpreted as a signed integer.

The routine invokes F-indirect-19 with two explicit arguments:

- The result of F-indirect-18 shifted left by two bits.
- The second selector byte, zero-extended to an unsigned word.

The second argument is the selector captured before F-indirect-14, not a newly observed selector value.

Finally, the routine invokes F-indirect-20 without explicit arguments in the representation.

### 7. Reach the truncated endpoint

This establishes neither an intentional application-level halt nor a particular processor exception. It also does not establish any return, cleanup, retry, or further memory access.

## Acceptance examples

These are conditional acceptance examples derived from the representation, not executed tests. Unless stated otherwise, they assume valid targets, returning dependencies, permitted accesses, and no additional effects that obscure the observations.

### First word store

If F-indirect-01 returns three:

- The scaled value is 12.
- The four-byte payload is written at address 32.
- That write precedes F-indirect-02.
- F-indirect-02 receives 12.

This example avoids signed overflow. It does not establish the byte order of the payload.

### Different selectors

Suppose the control word is `0x12345678`, the first selector is five, and the second selector is nine.

Then:

- The first byte destination is address 22.
- The first byte value is `0xE0`.
- F-indirect-07 receives `0x48D159E0` twice and `0x23456780` as its third argument, under 32-bit unsigned shift semantics.
- The second byte destination is address 26.
- The second byte value is `0x23`.
- F-indirect-19 receives nine as its second explicit argument.

Using five for both stores would violate the represented second read.

### Same-selector overwrite

Suppose both selector reads yield five and the control word is `0x12345678`.

The routine writes `0xE0` and later `0x23` to address 22. With no subsequent overlapping modification, the final byte there is `0x23`. Both writes remain part of the observable sequence.

### Selector boundary

A selector value of 255 produces destination address 272. The addition is not represented as an eight-bit wrapping addition; destination 16 is not supported by the shown expression.

### High control-word bits

For control word `0xFFFFFFFF`:

- The first byte store writes `0xFC`.
- The second byte store writes `0xFF`.

The second extraction has a ten-bit intermediate value, but only its low byte is stored.

### Retained second selector

If the second read yields nine and a later dependency changes the selector memory to 12, F-indirect-19 still receives nine as its second argument according to the represented data flow.

### Non-returning dependency
