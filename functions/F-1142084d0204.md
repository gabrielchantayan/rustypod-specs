# F-1142084d0204

## Purpose

F-1142084d0204 performs a signed, bounds-checked lookup through a two-word descriptor. When the requested position is nonnegative and strictly below the descriptor’s signed bound, it reads and returns the pointer-sized value stored at that position in a separate table. Otherwise, it returns zero.

The established behavior is a lookup, not an allocation, mutation, or ownership transfer. A plausible interpretation is access to an element of a pointer collection, but the source does not establish the collection’s type, the meaning of its entries, or whether its bound describes the actual allocation.

A zero result is ambiguous: it can indicate a rejected position or a selected table entry whose stored value is zero.

## Interface

### Inputs

The function has three arguments:

| Argument | Role | Interpretation |
|---|---|---|
| Descriptor address | Supplies the bound and, when needed, the table address | Address of a two-word layout |
| Requested position | Selects a table entry | Signed 32-bit integer |
| Auxiliary argument | No effect on the result or memory accesses | Presented as an integer; its incoming value is unused |

The descriptor layout, relative to its supplied address, is:

| Byte offset | Width | Meaning |
|---|---|---|
| 0 | 4 bytes | Table base address |
| 4 | 4 bytes | Signed upper bound, exclusive |

Table entries are spaced four bytes apart. Each selected entry is read as a pointer value and returned through an integer-valued interface.

The source representation uses four-byte words, four-byte entry spacing, and conversions between pointers and integers. This supports a 32-bit address/value interpretation. The precise target ABI, pointer representation, byte order, and alignment requirements are not independently established.

### Output

The result is one of:

- Zero, if the requested position is negative.
- Zero, if the requested position is greater than or equal to the signed bound read from the descriptor.
- The raw value of the selected table entry, otherwise.

The function returns the entry’s stored value, not the address of the entry and not the descriptor address. It does not dereference the object, if any, designated by that stored value.

No separate status result, exception contract, or error-message channel is established.

### Preconditions

Memory requirements depend on the path taken:

- For a negative requested position, the descriptor is not read. The lookup itself therefore requires no readable descriptor or table memory on that path.
- For a nonnegative requested position, the word at descriptor offset 4 must be readable.
- For a nonnegative position strictly below the bound, the word at descriptor offset 0 must also be readable, and the selected four-byte table entry must be readable.
- The referenced object represented by a nonzero table entry need not be readable merely to execute this function; that object is not accessed here.

These are requirements for completing the represented reads normally. The source does not define the execution environment’s response to an invalid address, an unsuitable alignment, or an invalid pointer representation.

## Behavior

### Signed bounds decision

The requested position is interpreted as signed.

A negative position produces zero without reading either descriptor word. The auxiliary argument does not affect this decision.

For every nonnegative position, the function first reads the signed bound from descriptor offset 4. This read occurs even when the requested position is zero. There is no special rule rejecting position zero before reading the bound.

The lookup is rejected when the position is equal to or greater than that bound. Consequently:

- A zero bound rejects every position.
- A negative bound also rejects every position: negative positions are rejected immediately, while all nonnegative positions exceed the negative bound.
- A positive bound permits exactly the signed positions from zero through one less than the bound, subject to valid address formation and readable memory.

The bound is not converted into an unsigned length for comparison. Treating a negative bound as a large positive capacity would change the established behavior.

### Accepted lookup

For a nonnegative position strictly below the bound, the logical read order is:

1. Read the bound at descriptor offset 4.
2. Read the table base address at descriptor offset 0.
3. Read the entry at a displacement of four times the requested position from that table base.
4. Return the entry’s value.

The descriptor’s base-address word is not read on a rejected lookup. In particular, equality with the bound rejects the lookup without consulting the base address.

The accepted path does not check the base address for zero and does not validate the selected entry’s address. A zero or otherwise unusable base does not trigger a defined fallback result; the function instead attempts the selected entry read.

The entry value itself is not validated. A stored zero returns zero. A nonzero stored value is returned without checking whether it identifies a live object, a readable address, or an object of any particular type.

### Widths and address arithmetic

The table displacement is four times the requested position. The source representation forms this displacement and the table address using integer arithmetic associated with a 32-bit address model.

The logical bounds check does not prove that the address calculation is safe. For example, a large positive bound can admit positions whose four-byte displacement exceeds the positive range of a signed 32-bit integer. Even a representable displacement can produce an address outside the table’s actual allocation.

The available evidence does not settle overflow semantics for those cases. A faithful contract must not silently replace the calculation with unlimited-precision arithmetic, promise checked overflow rejection, or assert a particular wraparound result without additional target evidence.

### Auxiliary argument

The incoming auxiliary argument has no behavioral role. It does not supply a fallback bound or participate in the selected-address calculation.

For otherwise identical inputs and stable readable memory, changing only this argument does not change the result or the path’s memory accesses.
