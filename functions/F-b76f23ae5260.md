# F-b76f23ae5260

## Purpose

F-b76f23ae5260 updates two numeric accumulator components from unsigned bytes and returns a 32-bit result. The input state supplies a lower 16-bit component and an upper 16-bit component. Each consumed byte increases the lower component; that updated lower value contributes to the upper component.

Different length ranges select different reduction behavior. The function is not established to implement one uniform mathematical reduction across all inputs.

**Inferred intent:** the structure resembles an Adler-style checksum update. Compatibility with a particular checksum algorithm depends on unavailable global values and the semantics of F-d7be9cfb4000.

This contract distinguishes:

- **Established static evidence:** operations, branches, constants, accesses, and call ordering present in the supplied representation.
- **Conditional behavior:** conclusions requiring explicitly stated configuration, dependency, or arithmetic assumptions.
- **documented_only:** behavior not resolved by the available evidence.

No runtime tests have been performed.

## Interface

### Inputs

| Input | Width and interpretation |
|---|---|
| Packed state | Unsigned 32-bit value. Bits 0–15 initialize the lower component; bits 16–31 initialize the upper component. |
| Buffer | Pointer to unsigned 8-bit elements. Readability requirements depend on the selected path and block configuration. |
| Length | Unsigned 32-bit value controlling path selection and remaining-length accounting. |

Both initial components are between 0 and 65,535. Their extraction is numeric; it does not depend on host byte order.

### Output

The represented result composition combines the lower working component with the upper working component shifted left by 16 positions, using bitwise OR.

There is no final mask restricting the lower component to 16 bits. Consequently:

- High bits of the lower component can contribute to the returned upper half.
- The combination is not necessarily a clean concatenation of two bounded components.
- On paths using an unsigned upper component, its left shift is a 32-bit unsigned operation.
- The short-input path instead shifts a dependency result represented as signed. Its portable arithmetic requirements are discussed below.

The null-buffer special case returns the unsigned numeric value **1**.

## Behavior

### Entry and branch precedence

The represented entry sequence reads the block threshold, then the reduction parameter, and extracts the two initial components.

Path selection then follows this order:

1. Length exactly one.
2. Null buffer.
3. Non-null buffer with length greater than fifteen.
4. Non-null buffer with length zero through fifteen, excluding one.

The one-byte branch therefore takes precedence over null handling.

These are access occurrences in the supplied representation. Exact physical load execution and externally observable ordering require additional information about memory qualifiers and the execution environment.

### One-byte path

For length one, the function reads the byte at the supplied address and adds its unsigned value to the lower component.

The subsequent reduction-global accesses are distinct:

1. Read the reduction parameter for the lower-component comparison.
2. If that comparison succeeds, **read the reduction parameter again** and subtract this newly read value from the lower component.
3. Add the resulting lower component to the initial upper component.
4. Read the reduction parameter again for the upper-component comparison.
5. If that comparison succeeds, subtract the fixed constant **65,521** from the upper component.
6. Combine the components and return.

Every comparison is inclusive: equality triggers its associated subtraction.

The comparison value and lower-subtraction value need not be equal. Neither must equal the entry-captured reduction parameter. The upper comparison also has its own read. Thus, after the entry capture, this path has three represented reduction-global reads if the lower comparison succeeds, and two if it fails.

The lower subtraction uses a global value; the upper subtraction uses a literal. Neither subtraction repeats. A changing parameter can cause subtraction by a value larger than the component, producing unsigned underflow.

No dependency call occurs.

A null buffer with length one reaches the byte access. No defined null-specific result or recovery is established.

### Null-buffer path

For a null buffer and any length other than one, return **1**.

This path reads no buffer bytes and makes no dependency call. The packed state does not affect its result. The entry configuration reads precede this branch in the representation.

The meaning of this special result—initialization convention, sentinel, or otherwise—is not established.

### Accumulation rule

For each consumed unsigned byte:

- The lower component increases by the byte value.
- The upper component receives the updated lower value.

Accordingly, a sequence contributes all successive lower values to the upper component, not just the final lower value.

Expanded groups read sixteen consecutive bytes in ascending address order. Their upper accumulation incorporates the sixteen successive lower values. Arithmetic and intermediate-conversion qualifications appear under “Arithmetic widths and conversions.”

No buffer writes appear.

### Short-input path

For a non-null buffer and length zero through fifteen, excluding one, the function consumes exactly that many consecutive bytes.

After consumption:

1. Read the reduction parameter and compare it with the lower component.
2. If the lower component is at least that value, subtract the fixed constant **65,521** once.
3. Read the reduction parameter again for the dependency invocation.
4. Invoke F-d7be9cfb4000 with the upper component and this newly read parameter.
5. Use the secondary result as the upper contribution to the final combination.

The comparison read and dependency-argument read are separate. They are not guaranteed equal. The lower subtraction uses a fixed literal, not either freshly read global value.

Only the upper component is passed to the dependency. The lower component receives no dependency-based reduction.

The unsigned loop counter reaches 4,294,967,295 through its terminal decrement. That local wrap causes no extra byte access and is not returned.

Length zero still performs the lower comparison and the upper dependency call. It is therefore not unconditionally an identity operation.

### Long-input path

For a non-null buffer with length greater than fifteen, the entry-captured reduction parameter is used for all dependency calls on this path.

#### Full-block processing

A full-block iteration is selected whenever the captured block threshold is no greater than the remaining unsigned length.

Each iteration:

- Deducts **5,552** from the remaining unsigned length.
- Reads the signed block repetition count.
- Enters a sixteen-byte-group loop that decrements this signed count before processing each group.
- Calls F-d7be9cfb4000 for the lower component, then for the upper component.
- Uses the two secondary results as the new components.

Both calls use the entry-captured reduction parameter. The upper call receives the accumulated upper value, not a value recomputed using the lower call’s result.

For a positive repetition count, the group loop processes exactly that many sixteen-byte groups. A count of zero does not skip the loop: the first decrement produces negative one and the first group is processed.

Zero and negative counts do not establish a safe finite group count under portable signed arithmetic. Repeated decrement can reach signed overflow before reaching zero. In particular, the minimum signed value overflows on the first decrement, before the first group’s byte reads.

The threshold, fixed deduction, and repetition count have independent sources.

**Conditional regular configuration:** a threshold of 5,552 and a repetition count of 347 make each full-block iteration consume exactly the 5,552 bytes deducted from the remaining length.

If eligibility permits entry with fewer than 5,552 remaining bytes, the unsigned subtraction wraps. This can invalidate buffer-size and termination expectations.

#### Residual processing

After full-block processing:

- A remaining length of zero returns the current combined components without further dependency calls.
- A nonzero remaining length is consumed as successive sixteen-byte groups followed by individual bytes.
- After that nonzero residual is consumed, the dependency is called for the lower component and then for the upper component.
- Both secondary results replace their respective components before return.

This stage consumes exactly its incoming residual length, provided the required accesses and arithmetic are valid.

A nonzero residual that is an exact multiple of sixteen still receives the final dependency pair. Its individual-byte loop reads no bytes; its terminal unsigned decrement still wraps locally.

### Arithmetic widths and conversions

The supplied representation uses unsigned 32-bit state, length, working components, and long-path dependency results. Bytes are unsigned 8-bit values. Expanded-group intermediate lower sums and the repetition counter are represented as signed 32-bit values.

These signed declarations have different consequences:

**Unsigned group additions.** The first byte-to-lower addition contains the unsigned lower component. Each subsequent expanded addition contains an explicitly unsigned byte operand. These additions therefore use unsigned 32-bit arithmetic, including conversion of any signed intermediate operand to unsigned.

**Intermediate assignments.** Several unsigned addition results are assigned to signed intermediate storage. Results within the signed range are representable without ambiguity. Results outside that range require the applicable unsigned-to-signed conversion behavior; the representation alone does not establish the target’s rule. This is a conversion issue, not signed addition overflow.

**Unsigned upper accumulation.** The expanded upper expression starts with the unsigned upper accumulator. Its successive additions therefore remain unsigned, even though several operands are held in signed intermediates. Exceeding the signed maximum is not itself signed overflow in this expression.

**Signed repetition decrement.** The repetition counter’s decrement is genuinely signed arithmetic. Decrementing the minimum signed 32-bit value is not defined as portable wrapping arithmetic.

**Short-path result shift.** The short-path secondary result is represented as signed, and its left shift occurs before combination with the unsigned lower component. Under conventional 32-bit signed-shift rules, a nonnegative result no greater than 32,767 permits this shift without exceeding the signed range. Negative or larger values do not establish a portable defined shift. Subsequent unsigned combination does not retroactively make the shift unsigned. Target bit-pattern behavior remains documented_only for those cases.

A useful conditional magnitude bound follows when both starting components are at most 65,535 and no more than 5,552 bytes are accumulated before reduction:

- Maximum lower value: **1,481,295**.
- Maximum upper value: **4,294,773,495**.

The lower bound is within signed 32-bit range, so the expanded lower intermediates are also representable under these conditions. The upper bound fits unsigned 32-bit range but exceeds signed range; that is compatible with the unsigned upper accumulation and is not a signed-overflow objection.

These bounds do not constrain arbitrary dependency results or arbitrary block configurations.

### Distinct one-byte global reads

Take initial lower 10, upper 0, and byte 0. Suppose:

- The fresh lower-comparison read is 10.
- The subsequent lower-subtraction read is 4.
- The upper-comparison read is 100.

### One-byte equality and fixed upper reduction

With both initial components 65,520, byte 1, and every fresh reduction read equal to 65,521, the lower component becomes zero and the upper remains 65,520. The result is **0xFFF00000**.

Separately, initial lower 1, upper 65,520, and byte 0 yield upper 65,521. With comparison reads of 65,521, the lower comparison fails and the upper comparison succeeds. Subtracting the fixed 65,521 produces return value **1**.

Successive lower values are 66 and 132; the upper becomes 198. The result is **0x00C60084**. There is exactly one dependency call, for the upper component. Its result also satisfies the signed-shift representability condition.
