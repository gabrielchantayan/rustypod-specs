# F-0e9b7551ba6d

## Purpose

F-0e9b7551ba6d transforms selected unsigned 32-bit values and writes a supplementary 16-bit value through a supplied pointer.

Two numeric regions receive special handling:

- `0x00C0`–`0x00FF`: a primary byte table determines the return value; its value also controls whether a supplementary byte table is consulted.
- `0x3001`–`0x30FF`: a membership bitmap gates an anchor-based transformation with selector-dependent exceptions.

Other inputs return unchanged after the supplementary output is cleared.

The numeric patterns suggest character decomposition or normalization. That is **inferred intent**, not an established encoding or semantic guarantee. This contract describes numeric results, conditional accesses, and writes.

### Arithmetic and interpretation

Unsigned 32-bit subtraction and addition wrap modulo \(2^{32}\). Explicit low-16-bit reductions retain values modulo \(2^{16}\), then return them as unsigned 32-bit values.

Pivot and selector ordering comparisons use signed 32-bit interpretations. For inputs admitted to the second region, the input itself is positive under that interpretation. Configured pivots or selectors can nevertheless have their high bit set.

Two supplementary forms are used:

- **Base supplementary value:** the anchor read at the final base-value write, converted to signed 16-bit.
- **Incremented supplementary value:** an earlier anchor read converted to signed 16-bit, incremented by one, and stored in signed 16-bit storage.

Under conventional low-bit-preserving narrowing, these yield the anchor’s low 16 bits and its increment modulo \(2^{16}\), respectively. Exact out-of-range signed-conversion behavior is not independently established. Examples using values above `0x7FFF` require that additional conversion assumption.

## Behavior

### Initial output clear and early returns

The first visible operation writes 16-bit zero to the output destination.

The explicit early-return branches perform no later output write:

- A primary byte greater than `0x7A`.
- An input outside both supported numeric regions.
- A clear membership bit in the second region.

This restriction concerns control flow, not equality between the result and the input. An exceptional replacement constant can equal the input while the function still performs a final supplementary write.

### Primary byte-table region

Inputs from `0x00C0` through `0x00FF`, inclusive, use the primary byte table. The index is the input minus `0x00C0`, ranging from zero through 63. An explicit low-16-bit reduction in the index calculation does not change any admitted index.

The primary byte is read and zero-extended to the 32-bit result.

- If it exceeds `0x7A`, that result is returned immediately. The output remains zero, and the supplementary table is not read.
- Otherwise, the supplementary byte at the same index is read. Its zero-extended value plus `0x0300` is written to the output, and the primary byte is returned.

The supplementary value therefore lies in `0x0300`–`0x03FF`. A primary byte of exactly `0x7A` takes the supplementary-producing path.

This region does not consult the membership bitmap, anchor, selectors, or replacement constants.

### Second-region gate and bitmap

After excluding the primary region, only inputs from `0x3001` through `0x30FF`, inclusive, proceed. Every other input returns unchanged with the initial zero output.

For an admitted input, its bitmap offset is the input minus `0x3000`, hence 1–255. The selected word and bit are:

- Word index: offset divided by 32, rounded down.
- Bit position: 31 minus the offset’s remainder modulo 32.

Bits are numbered from zero at the least-significant position. Thus the layout is most-significant-bit-first within each word.

| Input | Offset | Word index | Bit position |
|---|---:|---:|---:|
| `0x3001` | 1 | 0 | 30 |
| `0x301F` | 31 | 0 | 0 |
| `0x3020` | 32 | 1 | 31 |
| `0x30FF` | 255 | 7 | 0 |

Word zero’s bit 31 corresponds to excluded offset zero and is never selected.

A clear selected bit returns the original input with output zero. A set bit permits anchor and selector processing. The displayed signed-division adjustments in word selection reduce to the layout above because the validated offset is positive.

### Anchor preparation and pivot precedence

After a set membership bit, the displayed reference order is:

1. Read the anchor and add `0x3E` using unsigned 32-bit arithmetic to form a pivot.
2. If the input equals that pivot, read the anchor again and add `0x3C` to prepare the equality-case result.
3. Read the anchor to prepare the incremented supplementary value.
4. If the input equals the already-computed pivot, write the prepared incremented supplementary value and return the prepared equality-case result.

The replacement-producing anchor reference on the equality path therefore precedes the supplementary-preparation reference. On a non-equality path, the replacement-producing anchor reference does not occur.

The pivot is retained for subsequent comparisons; it is not recomputed from a later anchor reference. Distinct anchor references must not be collapsed into a stable snapshot without an environmental stability guarantee.

Pivot equality has precedence over every selector and fixed-input exception. The equality path does not read either selector or their replacement constants.

### Selector partitions and changing references

If pivot equality failed, signed comparison with the retained pivot selects the lower or upper partition.

Each partition first reads its selector-equality replacement constant, then reads its selector for equality. If equality fails, it reads that selector again for the signed-order comparison.

Consequently:

- R-lower-selector is referenced before the lower-selector equality read.
- R-upper-selector is referenced before the upper-selector equality read.
- The equality-test selector value and the later ordering-test selector value are not necessarily identical.
- Failed equality does not establish strict inequality against the later selector value.

The following tables distinguish those references. “Ordering selector” means the value from the second selector reference. All fixed-input rows require the earlier selector-equality test to have failed.

These are displayed source-reference orderings. Whether each reference becomes a distinct externally observable machine access is unresolved.

### Lower partition

This partition applies when the input is signed-less-than the retained pivot.

First, R-lower-selector is read. If the subsequent lower-selector equality read equals the input, that replacement is returned with the prepared incremented supplementary value.

Otherwise, the lower selector is reread for signed ordering:

| Condition using ordering selector | Fixed input | Result | Supplementary form |
|---|---|---|---|
| Ordering selector is signed-less-than input | `0x3094` | R-3094 | Base |
| Same | `0x30D1` | R-30D1 | Incremented |
| Same | `0x30D4` | R-30D4 | Incremented |
| Ordering selector is not signed-less-than input | `0x3071` | R-3071 | Incremented |
| Same | `0x3074` | R-3074 | Incremented |
| Same | `0x3077` | R-3077 | Incremented |
| Same | `0x307A` | R-307A | Incremented |

The second group includes equality with the ordering selector. Only when both selector references are stable does failed selector equality make this group equivalent to input being strictly less than the selector.

Replacement references precede their corresponding fixed-input tests. In the first group, their order is R-3094, R-30D1, R-30D4. In the second group, it is R-3071, R-3074, R-3077, R-307A. A successful test stops that sequence.

### Upper partition

This partition applies when the input is signed-greater-than the retained pivot; equality has already returned.

First, R-upper-selector is read. If the subsequent upper-selector equality read equals the input, that replacement is returned with the base supplementary value.

Otherwise, the upper selector is reread for signed ordering:

| Condition using ordering selector | Fixed input | Result | Supplementary form |
|---|---|---|---|
| Ordering selector is signed-less-than input | `0x30F8` | R-30F8 | Base |
| Same | `0x30F9` | R-30F9 | Base |
| Same | `0x30FA` | R-30FA | Base |
| Ordering selector is not signed-less-than input | `0x30DA` | R-30DA | Incremented |
| Same | `0x30DD` | R-30DD | Incremented |
| Same | `0x30F4` | R-30F4 | Base |

Again, the second group includes equality with the ordering-selector reread.

Candidate replacement references occur in table order within the chosen group, before each associated input test. A match prevents later candidate references. Failure of both `0x30DA` and `0x30DD` tests leads to the R-30F4 reference and test.

With stable selectors, selector equality wins over a fixed-input exception at the same numeric input.

### Default accepted-member result

If no applicable exception matches, the result is the low 16 bits of input minus one. Within the admitted region, this produces `0x3000`–`0x30FE`, so the explicit reduction does not further change the value.

The function then reads the anchor for the base supplementary value, writes that value, and returns.

All base-supplementary paths make this final anchor reference, including base-form exceptional mappings. Incremented-supplementary paths instead use the value prepared before selector dispatch. Every accepted-member path prepares that incremented value, even if it is later unused.

Results are not recursively processed.

## Side effects

The only explicit writes in the supplied body target the output destination:

- One initial zero write on every path.
- One additional supplementary write on a transforming path.

A later write may itself write zero; the presence of the write is determined by the selected path, not by its numeric value.

The significant displayed access order is:

1. Output clear.
2. Primary-table lookup, or second-region validation and bitmap lookup.
3. For accepted bitmap members, pivot anchor reference.
4. Conditional equality-result anchor reference.
5. Incremented-supplementary anchor reference.
6. Selected partition’s candidate replacement reference, selector equality reference, and, after failed equality, selector ordering reread.
7. Applicable fixed-input candidate references.
8. Final base anchor reference if that supplementary form is selected.
9. Final output write.

Unused replacement values can therefore be read on paths that ultimately choose another replacement or the default.

If the output overlaps backing data, the initial clear can affect subsequent reads. The final write can also alter backing state. The source does not establish that such aliasing is supported, nor does it establish synchronization, atomicity, reentrancy, or safety under concurrent modification.

No rollback or recovery behavior is present for inaccessible output or backing memory.

## Acceptance examples

These are conditional consequences of static evidence, not runtime observations. Unless otherwise stated, accesses are valid, backing data is stable and nonoverlapping, and the conventional width interpretation above applies.

1. **Ordinary unchanged input.** Input `0x0041` returns `0x0041` after writing zero. No backing-table or scalar reference is required.

2. **Primary lower boundary.** For input `0x00C0`, primary entry zero equal to `0x61` and supplementary entry zero equal to `0x05` produce result `0x61` and supplementary output `0x0305`.

3. **Primary threshold and upper boundary.** Input `0x00FF` uses index 63. A primary byte of `0x7A` requires the supplementary lookup; `0x7B` returns immediately with output zero. Input `0x0100` bypasses these tables and returns unchanged.

4. **Bitmap boundaries.** Inputs `0x3000` and `0x3100` return unchanged without bitmap access. Input `0x3020` selects word 1, bit 31; if clear, it returns `0x3020` with zero.

5. **Stable pivot equality.** Anchor `0x3099` gives pivot `0x30D7`. With membership set for that input, the result is `0x30D5` and supplementary output is `0x309A`. Selectors are not referenced.

6. **Distinct anchor references on equality.** If the pivot-forming anchor reference yields `0x3099`, input `0x30D7` enters equality handling. If the next anchor reference yields `0x4000` and supplementary preparation then yields `0x1234`, the result is `0x403C` and output is `0x1235`. The replacement reference precedes supplementary preparation.

7. **Default member.** With anchor `0x3099`, membership set for `0x3001`, and lower-selector equality failing, the result is `0x3000` and output is `0x3099`. This input matches none of the fixed exceptions.

8. **Partition-dependent exception.** With anchor `0x3099`, lower selector `0x3080`, and membership set for `0x3094`, the result is R-3094 and output is `0x3099`.

9. **Selector reread equals input.** For member input `0x3071` and pivot `0x30D7`, suppose the lower-selector equality reference yields `0x3080`, but its ordering reread yields `0x3071`. Equality first fails; the later selector is not less than the input. The R-3071 case applies and writes the prepared incremented supplementary value.

10. **Unchanged numeric result with a later write.** With anchor `0x3099`, member input `0x3080`, lower selector `0x3080`, and R-lower-selector equal to `0x3080`, the result equals the input. Nevertheless, output is first cleared and then written as `0x309A`.
