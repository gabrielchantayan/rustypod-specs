# F-12451f0d5857

## Purpose

F-12451f0d5857 selects the first available entry in an indexed group, marks that entry as occupied, initializes selected fields, and returns its address. If all sixteen entries are occupied, it returns a null pointer without calling its dependency or writing entry storage.

The established selection criterion is a zero-valued status byte. The interpretation of that byte as “available,” and of the operation as reserving an entry, is inferred intent. The function itself establishes only the byte tests, writes, dependency call, and returned address described below.

This is a source-facing static contract. No runtime tests have been performed.

## Interface

### Input

The function accepts one signed 16-bit integer, referred to here as the **group index**.

The group index has two distinct uses:

- Its signed value selects a group using a stride of 396 bytes.
- Its low eight bits are written into the selected entry as a group tag.

The function performs no explicit range check on the group index. In particular, negative indices are not rejected.

### External storage

A global base-address value identifies the storage from which group addresses are calculated. For a group index \(g\), the selected group begins at:

\[
\text{base} + 396g
\]

The multiplication uses the signed group index, not its eight-bit tag representation. Over the complete signed 16-bit input range, the byte displacement ranges from −12,976,128 through 12,975,732. Those displacements fit within a signed 32-bit integer. This does not establish that the resulting addresses are valid or that base-address addition cannot overflow the target address space.

The observed layout is:

| Region | Offset from group start | Size or spacing | Observed use |
|---|---:|---:|---|
| Group value | 0 | 4 bytes | Read before searching; later passed to the dependency if an entry is selected |
| Remaining header | 4–11 | 8 bytes | Not directly accessed |
| Entry area | 12 | Sixteen entries, 24 bytes apart | Searched in ascending entry order |

For entry ordinal \(i\), where \(0 \leq i < 16\), the entry address is:

\[
\text{group start} + 12 + 24i
\]

The fields directly used within an entry are:

| Offset from entry start | Width | Observed use |
|---:|---:|---|
| 0 | 32 bits | Written as zero |
| 4 | 32 bits | Written as zero |
| 8 | 32 bits | Written as zero |
| 12 | 8 bits | Tested for availability; written as one when selected |
| 13–15 | 3 bytes | Not directly written |
| 16 | 32 bits | Receives the dependency’s return value |
| 20 | 8 bits | Receives the low eight bits of the group index |
| 21–23 | 3 bytes | Not directly written |

The sixteen-entry area occupies 384 bytes. Together with the 12-byte header, it accounts for the 396-byte group stride. This layout consistency does not prove that the underlying allocation contains any particular number of groups.

### Output

The function returns either:

- The address of the selected entry, pointing at its offset-zero 32-bit field; or
- A null pointer if none of the sixteen status bytes is zero.

The result is an address within the indexed storage, not a separately allocated copy. The function does not establish ownership transfer, a release obligation, or a lifetime guarantee for that address.

## Behavior

### Initial address calculation and read

The function locates the group using the signed group index and the 396-byte stride. It then reads the 32-bit value at group offset zero.

That read occurs before the availability search. It occurs even when all sixteen entries are occupied and the eventual result is null.

The captured value is retained for a possible dependency call. It is not reread from the group header after the search.

### Availability search

The function examines entry status bytes in increasing ordinal order, beginning with entry zero and ending, if necessary, with entry fifteen.

For each examined entry:

- A status byte equal to zero selects that entry immediately.
- Any nonzero byte causes the search to continue.

Selection is therefore based on exact equality to zero. Values such as 2, 128, or 255 are unavailable just as a value of 1 is unavailable. Any signed interpretation of the byte does not change this zero-versus-nonzero decision.

The search stops at the first zero status byte. Status bytes belonging to later entries are not directly read by the function once a selection has been made.

If no zero status byte is found, the function returns null. In that case, it performs no direct writes and makes no dependency call.

### Reservation and initialization

For a selected entry, the direct operations occur in this order:

1. Write the value 1 to the eight-bit status field at entry offset 12.
2. Write a 32-bit zero at entry offset 0.
3. Write a 32-bit zero at entry offset 8.
4. Write a 32-bit zero at entry offset 4.
5. Call F-a0f78003cb6f, passing the previously captured 32-bit group value.
6. Write the dependency’s 32-bit return value at entry offset 16.
7. Write the low eight bits of the group index at entry offset 20.
8. Return the selected entry address.

The zero writes have a specific observed order: offset 0, then offset 8, then offset 4. They must not be described as an unordered bulk clear when the distinction matters to observers or dependency-visible state.

The function does not directly initialize every byte of the entry. In particular, offsets 13–15 and 21–23 are not written by this function. Offset 16 and offset 20 retain their earlier contents until their respective post-call writes occur.

### State at the dependency boundary

When F-a0f78003cb6f is called, the selected entry has already received the status write and all three zero writes. The result field and tag have not yet received this invocation’s post-call values.

The dependency receives the captured group value, not an explicit entry address. This does not establish that the dependency cannot discover or alter the entry through other state.

The function does not recheck the selected status byte after the call. It also does not recalculate the selected entry address from a potentially changed global base value. On normal return from the dependency, its remaining writes target the already selected entry address.

No preservation guarantees for globals or entry contents may be inferred for F-a0f78003cb6f. Consequently, the status and three zeroed fields are not unconditional final-state guarantees if that dependency can modify them. Their writes before the call are established; their persistence across the call is not.

### Tag conversion

The tag records only eight bits of the group index. It is not a lossless copy of the signed 16-bit input.

For example, indices 1 and 257 produce the same tag byte, although they select groups 101,376 bytes apart. A group index of −1 produces the byte pattern 255 in the tag field.

Whether another consumer interprets the stored tag as signed or unsigned is outside this function’s established behavior.

## Side effects

The function’s direct read footprint consists of the base-address state, the selected group’s first 32-bit value, and the status bytes examined before selection or exhaustion.

On successful selection, its direct write footprint consists of:

- One status byte;
- Three 32-bit zero fields;
- One 32-bit dependency-result field;
- One tag byte.

It does not directly write other entries or the group header.

The dependency may have additional side effects. Those effects are not bounded by this function’s visible call interface.

The operation is not established as atomic. The availability test and status write are separate operations, and no lock, atomic reservation, or synchronization mechanism is visible. Concurrent callers could therefore interfere unless an external synchronization contract prevents that interference.

The function does not directly allocate or release storage. Whether the dependency allocates, retains, transfers, or releases resources is unknown.

There is no visible rollback path. If execution fails or the dependency does not return after selection, the status and zero writes may already have occurred, while the result field and tag have not received their post-call values.

## Acceptance examples

These are conditional acceptance examples derived from static evidence, not executed test results.

### First entry available

Given valid accessible storage and a zero status byte in entry zero:

- Entry zero is selected regardless of later status values.
- Later status bytes are not directly examined.
- Its status is written as 1.
- Its fields at offsets 0, 8, and 4 are zeroed in that order.
- F-a0f78003cb6f receives the group’s initially captured 32-bit value.
- On normal return, the dependency result and low-eight-bit group tag are written.
- The returned pointer addresses entry zero, 12 bytes after the group start.

If the dependency leaves the entry unchanged, the final status is 1 and the three zeroed fields remain zero. Without that condition, only the pre-call writes are guaranteed.

### Earlier entries unavailable

Given nonzero status bytes in entries zero through four and a zero status byte in entry five, entry five is selected.

Its address is 132 bytes after the group start. The function directly reads six status bytes and does not directly read the remaining ten. A nonzero status value other than 1 still prevents selection.

### All entries unavailable

Given sixteen nonzero status bytes:

- The group’s first 32-bit value is still read.
- All sixteen status bytes are examined.
- No entry bytes are directly written.
- F-a0f78003cb6f is not called.
- The return value is null.

### Last entry available

Given nonzero status bytes in entries zero through fourteen and a zero status byte in entry fifteen, the function selects the entry at group offset 372.

Its status is at group offset 384, its dependency-result field at offset 388, and its tag at offset 392. These accesses fit within the observed 396-byte group layout.

### Dependency changes the header

If the dependency changes the group header after receiving its argument, that change does not alter the argument already passed. The argument came from the read performed before the search.

### Dependency changes selected-entry state

If the dependency changes the selected entry’s status to zero and returns normally, the function does not restore that status to 1. It still writes the result field and tag and returns the selected address, provided those writes remain valid.

### Negative group index

For group index −1, address selection uses a displacement of −396 bytes from the base. If that location is valid and an entry is selected, the tag byte is 255. The function does not reject the input merely because it is negative.
