# F-47ce25a252ab

## Purpose

F-47ce25a252ab dispatches a descriptor-selected evaluation against a record. Depending on the selector, it delegates evaluation of a buffer-like field, delegates evaluation of a numeric value, delegates evaluation of a single bit, or performs a two-word identifier membership check directly.

The function returns a 32-bit status and uses a caller-provided byte as an output channel. It clears that byte before selecting an operation. Unsupported selectors return −50 after that clearing.

The field names and business meanings are not established. Descriptions such as “buffer-like,” “numeric,” and “identifier” characterize the visible access patterns, not a recovered application schema.

## Interface

### Arguments

The visible interface has five arguments:

1. **Descriptor address.** Refers to storage whose first 32-bit word is a selector. Some paths also read the second 32-bit word as flags. Dependencies may require additional descriptor contents.
2. **Record address.** Refers to a mixed-width record containing 32-bit words, 16-bit fields, byte fields, and pointer-valued fields. Its first 32-bit word is read unconditionally as a base address.
3. **Opaque 32-bit argument.** Not visibly read or forwarded.
4. **Numeric-evaluation context.** A 32-bit value forwarded to F-5670512d89b6 on numeric paths. No local interpretation is visible.
5. **Output-byte address.** Receives an unconditional initial zero. It may subsequently receive a direct membership result or be passed to another evaluator.

The address calculations and word indexing in the supplied representation use a 32-bit address model. Record offsets below are byte offsets. A record “word” is four bytes.

### Return value

The visible return is a signed 32-bit status:

- **−50:** unsupported selector, or the explicit null-argument rejection on a bit-evaluation path.
- **0:** direct membership evaluation, including an absent or zero identifier.
- **Dependency result:** numeric, buffer-like, and bit-evaluation paths return the corresponding evaluator’s result.

There is no local translation of dependency errors and no general rule that a nonzero return restores or clears the output byte.

### Preconditions

For ordinary defined execution:

- The record’s first word must be readable.
- The output-byte address must be writable immediately on entry.
- The descriptor selector must be readable after that output write.
- Additional selected fields and transitively followed addresses must be readable.
- Any dependency-specific requirements must also hold.

The later bit-path null checks do not make null descriptor or output arguments safe: both have already been dereferenced before those checks.

No allocation, ownership transfer, or release is explicit in this function.

## Behavior

### Entry sequence and dispatch

The externally relevant entry order is:

1. Read the record’s first 32-bit word.
2. Write zero to the output byte.
3. Read the descriptor’s first 32-bit word as the selector.
4. Read the selector-specific data and execute the selected path.

This order matters if the arguments overlap. For example, the record base is captured before the output byte is cleared, but the descriptor selector is read afterward.

Selectors are tested as signed 32-bit values. Only the selectors listed below are supported. All others, including negative values, produce −50 without an evaluator call.

### Single-bit evaluation

Selectors 29 and 31 use a separate evaluator:

- **29:** extract bit 2 from the byte at record +0x14.
- **31:** extract bit 1 from the byte at record +0x15.

The extracted value is exactly zero or one. The extraction uses 32-bit unsigned shifts, discarding all other input bits.

After extraction:

1. The function checks the descriptor and output addresses for null.
2. If either is null, it selects status −50.
3. Otherwise, it calls F-3ab3b7d5de7e with the descriptor and an address of local storage.
4. It then reads the descriptor flags word.
5. It calls F-fec92d58725e with those flags, the extracted bit, the low eight bits of the local result, and the output-byte address.
6. It returns F-fec92d58725e’s status.

No result status from F-3ab3b7d5de7e is checked. Valid consumption of the local result depends on that dependency initializing the relevant storage. Only its low eight bits are forwarded; no further interpretation is justified.

The record bit is captured before the first helper call, whereas the descriptor flags are read afterward.

### Direct identifier membership: selector 40

Selector 40 is supported only when bit 0 of the descriptor flags is set. Otherwise, it returns −50 and leaves the initial output clearing as the only explicit output write.

With bit 0 set:

1. Call F-145ff188377a with the descriptor and local result storage.
2. Treat two 32-bit result words as an identifier pair.
3. If both words are zero, skip membership lookup and inversion.
4. Otherwise, read the list-head address from record +0x24.
5. Traverse until a match or a null link.
6. Apply optional inversion using descriptor flag 0x02000000.
7. Write one to the output byte only if the resulting membership value is true.
8. Return zero.

For each node:

- The node’s first word addresses a payload.
- The payload word at +0x34 is compared with the identifier’s second word.
- Only if that comparison succeeds is the payload word at +0x30 compared with the identifier’s first word.
- Both equalities are required for a match.
- A match ends traversal immediately.
- Otherwise, the next-node address is read from node +0x28.

There is no cycle detection or traversal bound.

For a nonzero identifier, membership is zero or one. Flag 0x02000000 reverses that value. The flags are read again after traversal; the initial flag check is not a snapshot used for inversion.

An all-zero identifier bypasses inversion entirely. Even when inversion is enabled, this path does not explicitly write one.

This branch performs no numeric or buffer evaluation. It returns zero regardless of whether a match was found. It does not check a status from F-145ff188377a.

## Side effects

The function itself:

- Writes zero to the output byte on every normally reached entry.
- May write one later on the direct membership path.
- Reads descriptor, record, nested-object, and list storage as selected.
- Does not explicitly modify the descriptor, record, or list.
- Does not explicitly allocate or free memory.

Dependencies may have additional effects. Their global-state behavior, mutation of passed objects, ownership behavior, and memory-release behavior are unknown. In particular, an initial zero output is not guaranteed to remain zero across an opaque dependency call.

Aliasing is observable. The initial output write may alter a later selector, flags word, record field, or list datum if those storage regions overlap. The ordinary field descriptions assume the caller supplies stable, suitably separated storage, unless overlap behavior is intentionally being exercised.

Malformed pointers, insufficient storage, list cycles, and dependency failures are not converted into local recoverable errors. No rollback is visible.

## Acceptance examples

These are conditional static acceptance examples, not runtime test results. Unless stated otherwise, storage is valid and nonoverlapping, dependencies initialize required results, and dependency side effects do not alter the illustrated inputs.

1. **Unsupported selector.** A selector of 15 clears the output byte and returns −50. It does not call an evaluator.

2. **Unsigned halfword.** Selector 5 with the field at +0x78 equal to 0xFFFF supplies numeric value 65535: low word 0x0000FFFF, high word zero.

3. **Signed halfword.** Selector 7 with the field at +0x7A encoding −1 supplies low and high words both equal to 0xFFFFFFFF.

4. **Signed byte.** Selector 25 with byte 0x80 at +0x7E supplies the 64-bit representation of −128, not positive 128.

5. **Unsigned full word.** Selector 10 with 0xFFFFFFFF at +0x6C supplies low word 0xFFFFFFFF and high word zero. Its auxiliary mode differs from the ordinary numeric mode, but the effect of that mode remains unresolved.

6. **Fallback based on companion.** Selector 19 with zero at record +0x30 selects base +0x118 and the companion at +0x2C, regardless of the bytes at base +0x170.

7. **Bit isolation.** Selector 29 supplies extracted bit one for a source byte of 0x04 or 0xFF, and zero for 0x02. Selector 31 uses bit 1 of its different source byte.

8. **Membership success.** Selector 40, initial flag bit 0 set, a nonzero identifier, a matching node, and inversion clear cause an explicit output write of one and return zero.

9. **Inverted absence.** Under the same enabled selector, a nonzero identifier absent from a finite list produces an explicit output write of one when inversion is set.

10. **Zero identifier exception.** If the identifier helper produces two zero words, no list-head read is needed and no inversion-driven write of one occurs. With no dependency modification of the output, it remains zero.

11. **Disabled membership.** Selector 40 with initial flag bit 0 clear returns −50 without calling the identifier helper.

12. **Dependency error.** If the buffer evaluator returns a particular error status, that status is returned unchanged. The caller does not restore the output byte afterward.
