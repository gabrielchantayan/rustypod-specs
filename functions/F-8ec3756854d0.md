The division here denotes the displayed logical right shift.

The selector byte is **read again for each store**. It is not a single cached destination.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Initial write ordering.** If the first argument is 3 and the initial store is valid, the first explicit operation writes the 32-bit value 3 at address 32. F-U001 occurs afterward. A second explicit store of 3 to address 32 occurs only after the intervening dependency sequence completes.

2. **Third-argument extraction.** For an original third argument of `0xffffffff`, the later four-argument invocation receives `0x0003ffff` in its fourth displayed position. Using a signed right shift or shifting by only seven would not match the visible extraction.

3. **Selector rereads.** If one selector-byte read yields 10, its associated store targets address 27. If an intervening dependency changes that byte to 20, a later selector-based store targets address 37. Reusing address 27 would not preserve the visible read sequence.

4. **Truncated byte value.** If the retained value for the first byte-store phase is `0x12345678`, four times that value has low byte `0xe0`. The later masked-and-shifted store writes `0x23`.

5. **First loop argument.** Any result entering the final mask-and-right-shift produces a control quantity no greater than 31. Therefore, if execution reaches the first loop invocation, its second displayed argument is zero.

6. **No completion inference.** If all accesses and dependencies continue successfully, reaching the end of a loop iteration transfers control to the next iteration. It does not return success or restore prior stores.
