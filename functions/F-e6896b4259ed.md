# F-e6896b4259ed

## Purpose

F-e6896b4259ed populates a two-word destination using a value returned by an indirect call and a value read from a supplied state region after that call.

The established behavior is narrower than a semantic description such as “copy a pair” or “retrieve a property”:

- Resolve an indirect callable through the state region.
- Invoke that callable.
- Read a 32-bit word from the state region after the invocation returns.
- Store the invocation result in the second destination word.
- Store the state word in the first destination word.

The output layout and the output write order differ: the first word in memory is written last. The state read must not be treated as a pre-call snapshot.

The meanings of the two result words, the state region, and the indirect operation are unknown.

## Behavior

### Ordered operation

The following order is established for the function’s own accesses and invocation:

1. Read the pointer-bearing value at state offset 0x40.
2. Follow that pointer and read the pointer-bearing value at the beginning of the referenced region.
3. Read the callable address at offset 0x38 within the resulting dispatch region.
4. Invoke the resolved callable.
5. If the invocation returns normally, obtain its 32-bit result and read the 32-bit word at state offset 0x44.
6. Write the saved invocation result to destination offset 4.
7. Write the saved state word to destination offset 0.
8. Return normally.

This ordering is not a claim about atomicity, hardware memory barriers, or inter-thread visibility. The supplied evidence establishes no synchronization protocol.

### Post-call state sampling

The word at state offset 0x44 is read only after the indirect invocation has returned.

Consequently, if the callee changes that word and leaves it readable, the first destination word receives the changed value. Reading the word before invocation would not preserve the established behavior.

The pointer chain used to resolve the callable is not visibly traversed again after the invocation. Changes to that chain during the call do not cause this invocation to be repeated or redirected by F-e6896b4259ed.

### Saved values and aliasing

Both output values are obtained before either destination write occurs.

If destination storage overlaps the state word at offset 0x44, the value used for destination offset 0 is still the value obtained by the post-call read. An intervening destination write can alter the underlying storage, but it does not cause another read of that state word.

Likewise, writing destination offset 4 does not visibly trigger a new invocation or a new dispatch lookup.

There is no explicit non-aliasing check or overlap-rejection path. This absence does not establish that every possible overlap is valid under the original language or runtime rules. For valid overlapping storage, the required distinction is between the already-obtained values and the later stores.

The function performs address displacement and pointer indirection but no visible arithmetic on either payload value. Signedness does not affect the specified bit patterns written to the destination.

No widening, saturation, scaling of payload values, or byte-order conversion is present. Endianness is not independently established; the contract describes 32-bit words rather than an ordered sequence of individual bytes.

## Acceptance examples

These are conditional specification examples, not executed tests. Each assumes accessible storage, a compatible callable, and normal completion unless stated otherwise.

### Distinct state and destination

Suppose the indirect call returns `0x12345678`, and the subsequent read at state offset 0x44 produces `0x90ABCDEF`.

The destination must finish with:

- Offset 0: `0x90ABCDEF`.
- Offset 4: `0x12345678`.

The write to offset 4 precedes the write to offset 0.

### State changed by the dependency

Suppose state offset 0x44 initially contains `0x11111111`. During the indirect invocation, the callee replaces it with `0x22222222` and returns `0x33333333`.

If the state word remains readable, the final destination must contain `0x22222222` at offset 0 and `0x33333333` at offset 4. Using the initial state value would violate the required read order.

### Output overlapping the sampled state word

Suppose destination offset 4 identifies the same storage as state offset 0x44. The post-call state read produces `0xAAAAAAAA`, and the invocation result is `0xBBBBBBBB`.

Under valid aliasing conditions, the first output write replaces the shared word with `0xBBBBBBBB`. The subsequent write to destination offset 0 still uses the previously sampled `0xAAAAAAAA`; it does not resample the overwritten word.

### Failure between destination writes

Suppose destination offset 4 is writable, but writing destination offset 0 fails.

The second destination word may already contain the invocation result. An implementation that promises all-or-nothing output would add a guarantee absent from this contract.
