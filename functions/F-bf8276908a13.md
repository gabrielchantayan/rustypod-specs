# F-bf8276908a13

## Purpose

F-bf8276908a13 performs two ordered indirect invocations associated with a caller-supplied object. The first invocation receives a value selected from two global 32-bit data cells according to an object-resident state field. The second receives a different pair of global values.

The established behavior is dispatch and argument selection. The supplied evidence does not establish whether these invocations set properties, emit messages, register resources, or perform another operation. Such interpretations are not part of this contract.

This specification distinguishes:

- **Established static evidence:** behavior directly represented by the supplied function body.
- **Inferred intent:** a plausible interpretation that is not required behavior.
- **documented_only:** unresolved behavior, including effects of unavailable indirect targets and uncertainty in the recovered control flow.

No runtime tests have been performed.

## Behavior

### 1. Select the first value

The function first reads the default value into a local four-byte temporary.

It then reads the object’s state field and compares the field with zero:

- A zero value retains the previously read default value.
- Any nonzero value causes the alternate value to be read and substituted.

This is a zero-versus-nonzero distinction. There is no visible restriction to one particular nonzero value, no range check, and no normalization of the state field.

The default read precedes the state test in the supplied representation. Consequently, the default cell is read even on the branch that subsequently replaces its value. The alternate cell is read only on the nonzero branch.

The selected value is retained locally for the first invocation. A later modification of its source global cell does not, in the represented sequential behavior, cause the function to select or fetch that argument again.

### 2. Perform the first indirect invocation

The function obtains a dispatch-table base from the beginning of the object and obtains an indirect target from the table location at byte displacement 88.

It invokes that target with three arguments, in this positional order:

1. The original object reference.
2. The value read from the first-selector global cell.
3. The selected four-byte value.

Call this dependency **F-indirect-01**. This identifier denotes the target reached by the first dispatch event; it does not establish a particular implementation or a stable address.

Any result produced by this invocation is ignored by the visible body.

The evidence establishes argument positions, but not a total ordering among every load needed to evaluate this invocation. In particular, it does not justify requiring the first-selector read to occur before or after the dispatch-table reads.

### 3. Perform the second indirect invocation

If the first invocation returns control normally to this function, execution proceeds to the second dispatch.

The object reference is used again to obtain a dispatch-table base, and the target at byte displacement 88 is obtained again. The function then invokes that target with:

1. The original object reference.
2. The value read from the second-selector global cell.
3. The value read from the second-value global cell.

Call this dependency **F-indirect-02**. It denotes the second dispatch event, not necessarily a different implementation from F-indirect-01.

The second invocation does not reuse the first invocation’s selected third argument. It also does not repeat the state-field test.

Both dispatch expressions use the same object reference and table displacement, but the evidence does not establish that they reach the same target. The first dependency may change the object’s leading dispatch reference, the table entry, or other relevant state. The second dispatch uses the state available after the first invocation returns.

The second-selector and second-value arguments are likewise obtained for the second invocation, after the first invocation returns. They are not visibly snapshotted before the first call. Their order relative to each other and to the second dispatch-target reads is not established.

### 4. Return

The recovered representation shows return without a value after the second invocation.

There is a material qualification: the supplied evidence explicitly flags uncertainty in recovering the second indirect control transfer and represents that transfer as a call. Thus, the shown behavior is a second invocation followed by return, but whether the underlying transfer has ordinary call-and-return mechanics is **documented_only**.

## Acceptance examples

These examples are conditional behavioral criteria, not executed tests. They assume readable memory, an appropriate ABI, and dependencies that return normally unless stated otherwise.

### Zero state

Given a zero state field, a default value of 17, and an alternate value of 29:

- The first invocation receives 17 as its third argument.
- The alternate value is not needed on this branch.
- The second invocation receives the second-selector and second-value contents, independently of that selection.

### Nonzero state

Given a nonzero state field, a default value of 17, and an alternate value of 29:

- The default cell is still read before the state decision.
- The alternate cell is then read.
- The first invocation receives 29 as its third argument.

This applies equally to a state value of one and any other nonzero bit pattern within the represented field width.

### First dependency changes later argument cells

Suppose F-indirect-01 changes the second-value global cell before returning, and no other actor changes it afterward.

The second invocation uses the updated cell contents. A version that had captured that argument before the first invocation would not match the represented behavior.

### First dependency changes dispatch

Suppose F-indirect-01 changes the object’s dispatch reference so that the entry at displacement 88 identifies a different valid target.

The second invocation resolves through that updated reference. Reusing the first resolved target without another dispatch lookup would not match the supplied representation.

### First dependency changes the state field

Suppose F-indirect-01 changes the state field before returning.

That change does not cause this function to repeat the first selection or to choose the second invocation’s third argument from the default and alternate cells. The second invocation uses its separately designated global value.

### First dependency does not return

If F-indirect-01 terminates execution or otherwise never returns control to this function, no second invocation follows along the represented sequential path.

This is not evidence of an error-handling policy; it is a condition on reaching the later operation.
