# F-307b5e43b9f5

## Purpose

F-307b5e43b9f5 coordinates an operation on a caller-supplied object. It invokes an initial dependency, waits for an object byte to become zero by repeatedly invoking another dependency, performs the principal delegated operation, conditionally invokes an additional operation, and invokes a final dependency.

The established contract is an ordering contract. The supplied static evidence does not establish what the delegated operations accomplish. In particular, it does not establish that the initial and final calls acquire and release a lock, that the repeated call waits or yields, or that the principal operation succeeds.

On every execution that reaches its explicit return, the function returns a 32-bit zero. It does not visibly propagate any dependency result.

## Behavior

### Initial call and status loop

The first observable delegated action is a call to F-338d16f9ce72 with the derived address at offset `0x78`.

Only after that call returns does the function read the byte at offset `0x1BD`. Thus, the initial dependency can affect the first loop decision by changing that byte or changing other state that influences access to it.

If the observed byte is zero, the function leaves the loop without calling F-162a41bac6a7.

If the observed byte is nonzero, the function calls F-162a41bac6a7 with the derived address at offset `0x80`. After that call returns, the function reads the byte at offset `0x1BD` again. It repeats this behavior until a read observes zero.

The status is a one-byte zero/nonzero condition. Every nonzero byte value takes the same branch; the function does not distinguish a particular active, failed, or terminal nonzero value.

There is no visible iteration limit, elapsed-time check, sleep, or explicit backoff. A dependency may provide such behavior internally, but that is not established here. If every status read remains nonzero and the repeated dependency keeps returning, the principal operation is never reached.

The loop does not cache its first status observation. A status change during a repeated dependency call can affect the next decision.

### Principal delegated operation

Once a status read observes zero, the function calls F-e2303c7cb41c with all five original arguments in their original order.

The function does not visibly inspect that dependency’s return value. It also does not recheck the loop status afterward. Consequently, a later change to the byte at offset `0x1BD` does not cause this invocation to reenter the loop.

The state used by the subsequent conditional decision is read after F-e2303c7cb41c returns. It is not a snapshot taken before that call.

### Conditional additional operation

After the principal dependency returns, the function reads the external byte through the globally referenced address.

The remaining reads are short-circuited in this order:

1. If the external byte is nonzero, the function skips the additional operation. Neither the byte at offset `0x09` nor the byte at offset `0x08` is read by this decision.
2. If the external byte is zero, the function reads the byte at offset `0x09`.
3. If the byte at offset `0x09` is nonzero, the function skips the additional operation without reading the byte at offset `0x08`.
4. If both preceding bytes were observed as zero, the function reads the byte at offset `0x08`.
5. If that byte is anything other than `0x05`, the function calls F-8c761d2d09dc with the original object address. If it equals `0x05`, the additional call is skipped.

Thus, the additional dependency is called exactly once on a normally progressing invocation when these three observations hold:

- The external byte is zero.
- The object byte at offset `0x09` is zero.
- The object byte at offset `0x08` is not `0x05`.

These are sequential observations, not an established atomic snapshot. The function does not reread the external byte after reading either object byte, and it does not reevaluate the condition after the additional call.

Signedness does not change these branch outcomes: the relevant comparisons distinguish zero, nonzero, and the byte value `0x05`.

### Final call and return

After the conditional operation is either performed or skipped, the function calls F-1333331b2da1 with the derived address at offset `0x78`.

After that dependency returns, the function returns 32-bit zero.

The final dependency is reached on every path that completes the loop, completes the principal operation, and completes any selected additional operation. The evidence does not establish exception-safe, fault-safe, or cancellation-safe finalization. If an earlier call does not return, or an earlier memory access prevents continued execution, no final call is established.

## Acceptance examples

These are conditional acceptance scenarios derived from static evidence, not executed tests. Each normal-completion example assumes valid accesses and returning dependencies.

### Additional operation selected

F-8c761d2d09dc is called once after those reads and before F-1333331b2da1. The function returns zero after the final call returns.

### Discriminator exclusion

With the same first two zero observations, an offset-`0x08` value of `0x05` suppresses F-8c761d2d09dc. A value of zero, `0x04`, or `0xFF` does not suppress it.

### State changed by the principal dependency

Suppose the external byte is nonzero before F-e2303c7cb41c but is zero when read afterward. The later zero observation governs the decision. The earlier value is not read or preserved by this function.

Likewise, changing the loop-status byte back to nonzero during the principal call does not restart the completed loop.

### Persistent nonzero status
