# F-55d5389b3f44

## Purpose

The established behavior is an ordered mutation of a caller-supplied memory graph, followed by an unresolved indirect transfer. The function performs byte, halfword, and word accesses; follows mutable links; writes constants and address-derived values; accesses addresses formed by addition and doubling; and supplies three arguments to the indirect target.

No application-level purpose is established. The supplied representation does not justify describing this function as initialization, serialization, list maintenance, allocation, or destruction.

This contract describes the visible access sequence, not a validated executable interpretation. In particular, several required inputs are absent from the displayed formal interface, and the final target is unresolved.

## Interface

### Explicit inputs

| Input | Displayed width | Established use |
|---|---:|---|
| First input | 8 bits | Initially written to one byte of the primary object. |
| Second input | 32 bits | Stored repeatedly, narrowed to a byte, and subsequently interpreted as an address through a memory reload. |
| Third input | 32 bits | Used as a base address for a self-address word store at offset `0x54`. |
| Fourth input | 8 bits | Written to a byte of a context-supplied object. |

The second input is not merely an opaque scalar: absent intervening alias effects, its value becomes a dereferenced address. The third input must identify writable storage at the accessed offset if execution is to proceed normally.

### Additional required execution context

The visible body depends on values not established by its formal parameters. This contract names them by role:

- **Primary base:** an incoming address used for most initial writes.
- **Auxiliary base:** an incoming address read at offset `0x60` and written at offset `0x10`.
- **Peer base:** an incoming address stored into the primary object and used for linked accesses.
- **Context byte:** an incoming 8-bit value written into the primary object.
- **External word A:** a 32-bit externally stored value used as an address component and narrowed for a halfword store.
- **External word B:** another 32-bit externally stored value used as an address component and passed to the indirect target.
- **External payload:** a 32-bit externally stored value written through a doubled address.
- **Indirect target:** an unresolved executable destination.

Their acquisition, validity, and calling convention are not established.

### Output and completion

No explicit result value is established. The displayed interface has no return value, but that does not establish the complete machine-level return convention.

If every prior access succeeds and the unresolved target returns normally under a compatible calling convention, the visible body then returns. No status code, failure flag, or output-length convention appears.

### Memory widths and notation

Offsets below are byte offsets. A **byte**, **halfword**, and **word** mean 8, 16, and 32 bits respectively.

A “link at offset” means a 32-bit memory read whose value is subsequently used as an address. This terminology does not assert ownership, object type, or structural validity.

Byte and halfword narrowing retain the low 8 and low 16 bits respectively. Signed interpretation of a later byte read is addressed separately under uncertainties.

## Behavior

### General sequencing rule

The following phases occur in the stated order. Within each phase, the prose identifies ordering that affects reads, writes, and retained values.

Every link is obtained from memory when described. A previously stored address is not a substitute for a later reload. Likewise, repeated reads can observe different values when earlier writes overlap their source locations.

Objects are not established to be disjoint. Consequently, final-state descriptions are conditional: an intervening access through another base may alter an earlier field, including a field later used as a link.

### 1. Initial field publication and first linked-object updates

The function first stores the second input as a word at primary offset `0x74`, then stores the first input as a byte at primary offset `0x11`.

It reads a word at auxiliary offset `0x60`. Before using that word, it overwrites primary byte `0x11` with the context byte and stores the second input as a word at primary offset `0x34`. It then writes the low byte of the auxiliary word to auxiliary offset `0x10`.

Next it captures the link at primary offset `0x14`. It writes the fourth input to peer byte `0x11`, publishes the peer base at primary word `0x44`, and replaces primary byte `0x11` with the low byte of the second input.

A fresh read of primary word `0x74` is retained for later byte narrowing. The low byte of the peer base is written to primary offset `0x0d`.

Through the previously captured primary link, the function:

- Writes word `0x00000066` at offset `0x10`.
- After another publication of the peer base at primary word `0x44`, writes byte `0x66` at linked offset `0x10`.
- Writes word `0x00000066` at linked offset `0x60`, after writing that same word value to primary offset `0x54`.

The word and byte writes at linked offset `0x10` are distinct events. They must not be reduced to one store merely because their low bytes agree.

### 2. Reinterpreting the published value as an address

The function reloads primary word `0x74` as an address, then replaces that field with the peer base. The reloaded address remains the base for the next linked operations.

It writes word `0x00000066` at that captured address plus `0x40`. Primary byte `0x0d` then receives the low byte of the earlier retained read of primary word `0x74`.

A word read at captured offset `0x44` supplies the next value written to peer byte `0x11`. Between that read and write, the function writes the primary base to primary word `0x54`, writes the third input to the word at third-input address plus `0x54`, and reads the link at captured offset `0x14`.

The object reached by that link receives, at byte offset `0x15`, the low byte of a word freshly read from peer offset `0x14`.

The peer link at `0x14` is then read again. The function reads primary word `0x64`, retains that first value, writes word `0x00000073` at peer-linked offset `0x20`, and reads primary word `0x64` a second time. The low byte of the second value is written to peer-linked offset `0x09`.

The two primary reads at `0x64` are not interchangeable: the intervening linked write may alias their source.

### 3. Deeper links, a read-and-write-back, and retained payloads

From the peer-linked object, the function follows the link at `0x74`.

The resulting object receives the low byte of the primary base at offset `0x0d`. Its word at `0x54` is then read and written back unchanged. This is an actual memory read followed by a memory write, not an absence of activity. Byte `0x74` is written at its offset `0x09`.

Primary word `0x44` receives the first retained read from primary offset `0x64`. The deeper object receives the primary base as a word at `0x34`, after which its link at `0x04` is followed.

That next object receives the second retained primary `0x64` value as a word at `0x24`. Primary byte `0x19` receives the low byte of the first retained value.

Two values are then captured from this next object:

- The link-sized word at `0x74`, retained as a later payload.
- The word at `0x04`, retained for publication into the primary object.

A fresh read of primary word `0x74` establishes another working base. Through that base’s link at `0x14`, the function writes the retained payload at offset `0x54`.

It follows the working base’s link at `0x04`. Before writing through that link, it performs two consecutive identical writes to primary byte `0x0d`, each using the low byte of the second retained primary `0x64` value. It then replaces primary word `0x64` with the captured word from the preceding object’s offset `0x04`.

The linked object receives word `0x00000074` at offset `0x30`.

### 4. Primary-link replacement and another traversal

The function rereads the working base’s link at `0x04` and follows that object’s link at `0x74`. The resulting object is the **branch object** for the remainder of the graph traversal.

The low byte of the now-current primary word `0x64` is captured and written to primary offset `0x1d`.

Separately, the function reads primary word `0x44`, interprets it as an address, and reads its link at `0x14`. Before publishing that link, it writes the retained payload from the preceding phase to branch word `0x34`.

The newly obtained link is stored at primary word `0x14`. Primary word `0x54` is read and retained, and the object addressed by the newly obtained link receives the low byte of the primary base at offset `0x09`.

A further traversal follows branch link `0x04`, then that object’s link `0x74`. This resulting object receives:

- At byte offset `0x15`, the low byte of the retained payload.
- At byte offset `0x11`, the low byte of the retained read of primary word `0x54`.

Between these writes, primary word `0x54` is reset to the primary base, and primary byte `0x11` receives the low byte of the branch address.

The function reads word `0x64` from the resulting object. It also writes the previously captured low byte of primary word `0x64` to primary byte `0x09`.

### 5. Branch-child updates and final graph accesses

The branch link at `0x04` is read again, establishing a **child object**.

The child receives the low byte of the primary base at byte offset `0x09`. Its word at `0x50` is read. The child then receives the low byte of the preceding phase’s object word `0x64` at byte offset `0x11`, followed by another write of the primary-base low byte at offset `0x09`.

Primary word `0x14` is replaced with that full object word `0x64`. Primary byte `0x0d` receives the low byte of the child address. Child byte `0x00` receives the low byte of its captured word `0x50`.

The function captures branch word `0x74` for a later summed-address read, then follows branch link `0x14`. It writes the child’s own address at child word `0x54`.

Through the branch-linked object’s link at `0x04`, another object is reached. That object receives byte `0x64` at offset `0x10`. Primary word `0x54` receives word `0x00000064`; the same reached object receives word `0x00000064` at offset `0x40`.

Primary byte `0x0d` receives the low byte of the earlier captured object word `0x64`. The branch-linked object receives the low byte of the newly reached object’s address at byte offset `0x09`.

Primary word `0x24` receives the full captured object word `0x64`. The branch-linked object receives the low byte of the primary base at byte offset `0x11`.

### 6. Arithmetic-address accesses and indirect transfer

The function reads external word A, then reloads primary word `0x74`.

The low 16 bits of that primary word are written to the address formed by adding its full value to the primary base. Next, the low 16 bits of external word A are written to twice the address of the object most recently reached through a `0x04` link.

A byte is read at the address formed by adding the previously captured branch word `0x74` to the primary base. Its conversion to a 32-bit value may depend on signed-byte interpretation.

The following accesses occur before external word B is read:

- A halfword store of the primary-word low 16 bits to external word A plus the reloaded primary word.
- A second halfword store of those same bits to the primary base plus the reloaded primary word.
- A word store of `0x00000045` at the converted-byte value plus `0x45`.

External word B is then read, followed by the external payload and a fresh read of primary word `0x44`.

Next, byte `0x44` is written at the converted-byte value plus `0x44`. The external payload is written as a word at twice external word B. Finally, the low 16 bits of external word B are written at the retained graph payload plus external word B.

The unresolved target is invoked with three visible arguments, in this order:

1. The converted-byte value bitwise-ORed with `0x44`.
2. External word B.
3. The freshly read primary word `0x44`.

The first argument uses bitwise OR, not addition.

## Acceptance examples

These examples are conditional static consequences, not runtime observations.

1. **Initial overwrite sequence.** With disjoint objects and successful ordinary memory accesses, primary byte `0x11` is written first with the first input, then with the context byte, then with the second input’s low byte. A later write uses the branch address’s low byte. Acceptance requires preserving these intermediate writes, not merely producing the final byte.

2. **Different reads from primary offset `0x64`.** If the intervening store of word `0x73` aliases primary offset `0x64`, the second read may differ from the first. The first value feeds primary word `0x44`; the second feeds the later word store at linked offset `0x24`. An implementation that reuses one read for both does not satisfy the visible sequence.

3. **Word followed by byte.** For a valid first linked object, its offset `0x10` receives a word store of `0x66` and later a byte store of `0x66`. The byte store does not replace the requirement for the word store.

4. **Low-bit narrowing.** If a captured word is `0x123456ab`, a byte store derived from that capture writes `0xab`. A halfword store derived from `0x1234abcd` writes the 16-bit value `0xabcd`; byte order in memory remains architecture-dependent.

5. **Read-and-write-back.** The deeper object’s word at `0x54` is read and then written with the captured value. On ordinary unchanged RAM the resulting bits match the initial bits, but omitting both accesses would not preserve the access sequence.

6. **Final first argument.** If the converted byte value is `0x01`, the indirect target’s first visible argument is `0x45`. If it is `0x44`, that argument is `0x44`, not `0x88`.

7. **High-bit byte.** If the arithmetic-address byte read obtains `0x80`, signed and unsigned interpretations produce different 32-bit values and therefore different later addresses and first arguments. Acceptance for that case is documented_only until byte signedness is resolved.

8. **Invalid address.** If an early dereference is invalid, no normal error return is established. The contract does not require later writes or the indirect invocation to occur.
