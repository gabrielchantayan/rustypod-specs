# F-12200b6df1e9

## Purpose

F-12200b6df1e9 prepares a 16-byte local payload from four external 32-bit values, transforms that payload, invokes three dependencies in a fixed order using a shared 40-byte work area, and stores a one-byte result at displacement 13 from an externally selected destination base.

The established contract is the transformation and call sequence. A text reference suggests an association with a device-control operation, but that is inferred intent. The supplied material does not establish the operation performed by the dependencies or the meaning of the final byte.

The fourth payload word spans a three-byte scalar region and an adjacent byte. Its transformation therefore requires a layout distinction: the independent unsigned shift is established, but the subsequent numerical mask depends on byte order. Little-endian and big-endian interpretations produce different results.

This specification describes static evidence only. No runtime tests have been performed.

## Behavior

### 1. Read and initialize the payload

The function reads the first external word and assigns it to payload offset 0, then does the same for the second, third, and fourth words at offsets 4, 8, and 12.

Each payload assignment covers 32 bits, including the fourth assignment, which spans the three-byte region and its adjacent byte.

All four initial assignments precede the transformation loop and all dependency calls. There is no visible reread, retry, or consistency check of the external payload values.

The established ordering is the ordering of accesses represented in the supplied body. It does not establish hardware atomicity, synchronization, or a guarantee against concurrent modification of the external sources.

### 2. Shift four independent unsigned words

The function processes the payload words in reverse address order:

1. Fourth word, offset 12.
2. Third word, offset 8.
3. Second word, offset 4.
4. First word, offset 0.

For each word, it reads the 32-bit unsigned value, shifts it logically right by one bit, and writes the 32-bit result back to the same word.

Consequences:

- The original least significant bit is discarded.
- Zero enters bit 31.
- No bit is transferred between neighboring words.
- Each result is between 0 and 2,147,483,647 inclusive.

This is four independent 32-bit shifts, not a single 128-bit shift. The local position immediately after the payload is used as the traversal starting boundary; it is not an additional payload word to transform.

No dependency call occurs between these updates, and the payload address has not yet been supplied to a dependency.

### 3. Narrow and reassign the fourth word’s three-byte region

After all four shifts, the function takes the unsigned value of the three-byte region at payload offsets 12–14, narrows it to 16 bits, and assigns that value back to the same three-byte region.

At the three-byte scalar level:

- Its numerical bits 0–15 are retained.
- Its numerical bits 16–23 become zero.
- The adjacent byte at payload offset 15 is outside this assignment and remains unchanged by this operation.

The resulting interpretation of the encompassing fourth word is conditional on layout. The three-byte region must not be identified unconditionally with the encompassing word’s numerical low 24 bits.

#### Conventional little-endian layout

Under little-endian interpretation, offsets 12–14 hold the encompassing word’s low 24 bits. Narrowing and reassignment therefore:

- Preserve encompassing-word bits 0–15.
- Clear encompassing-word bits 16–23.
- Preserve encompassing-word bits 24–31.

The numerical transformation is the shifted word bitwise-ANDed with hexadecimal FF00FFFF. The byte cleared is at payload offset 14. The preserved adjacent byte at offset 15 is the word’s highest-order byte.

Because the earlier shift was logical, bit 31 is already zero.

#### Conventional big-endian layout

Under big-endian interpretation, offsets 12–14 hold the encompassing word’s high 24 bits. Narrowing and reassignment therefore:

- Preserve encompassing-word bits 0–23.
- Clear encompassing-word bits 24–31.

The numerical transformation is the shifted word bitwise-ANDed with hexadecimal 00FFFFFF. The byte cleared is at payload offset 12. The preserved adjacent byte at offset 15 is the word’s lowest-order byte.

#### Unresolved layout

The supplied material does not independently establish target byte order. Consequently, neither numerical mask is an unconditional requirement.

The unconditional requirement is the sequence of an encompassing 32-bit logical shift followed by narrowing and reassignment of its first three-byte region, leaving the adjacent fourth byte unchanged by that reassignment. The exact encompassing-word result remains documented_only until layout is established.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Payload expectations describe the state immediately before the first dependency call, not necessarily the state after dependencies have had access to the payload.

### Independent unsigned shifts

Given initial words:

| Position | Initial value | Prepared value |
|---|---:|---:|
| First | 00000003 | 00000001 |
| Second | 80000000 | 40000000 |
| Third | FFFFFFFF | 7FFFFFFF |
| Fourth | 00000000 | 00000000 |

All values are hexadecimal. These results hold under either conventional byte order.

An arithmetic shift producing C0000000 for the second word, or FFFFFFFF for the third, would violate the unsigned-shift requirement.

### Fourth-word result depends on layout

Given a fourth input word of hexadecimal FFFFFFFF, the encompassing logical shift produces 7FFFFFFF.

- With established little-endian layout, the prepared fourth word is 7F00FFFF.
- With established big-endian layout, the prepared fourth word is 00FFFFFF.
- Without established layout, selecting either result as unconditional would exceed the evidence.

The little-endian result preserves the shifted word’s highest byte. The big-endian result clears that byte instead.

### A second layout-sensitive value

Given a fourth input word of hexadecimal 02460000, the encompassing shift produces 01230000.

- Under little-endian layout, narrowing the three-byte region produces 01000000.
- Under big-endian layout, it produces 00230000.

These distinguish the location of the cleared byte. They do not represent two optional behaviors on a target whose layout is already known.

### Returned byte is not normalized

If F-f20739aca2fe supplies captured byte A5 and the destination base read afterward is valid, the function writes A5 at displacement 13.

A write of 01 instead would not satisfy this forwarding behavior. A captured zero similarly produces a zero byte, without a separate visible branch.

### Destination changes during a call

Suppose a dependency changes the externally stored destination base from one valid region to another, and the new value remains in place when the final base lookup occurs.

The final byte targets displacement 13 in the newly selected region. Using the original base cached before the calls would not preserve the observed ordering.
