# F-67c3164f8af5

## Purpose

F-67c3164f8af5 accepts a state-object address and three 32-bit payload words. It compares two addresses stored in the state object. If they differ, it advances one stored address by a three-word record size and, unless the original destination is null, writes the payload there. If the addresses are equal, it delegates to F-ee9d9ff120bd using a temporary payload record.

The apparent intent is to append a fixed-size record to a managed sequence, using a direct path when space remains and a helper when the current position reaches a limit. That interpretation is inferred, not established. The supplied representation does not identify the object type, prove that the second address denotes an allocation boundary, or expose the helper’s behavior.

The contract below distinguishes direct effects visible in the supplied representation from behavior delegated to the unknown dependency.

## Behavior

### Initial state observation

The function obtains the current destination from state offset +4 and compares it with the pointer-valued field at offset +8.

Both values are needed before the branch is selected. The supplied statement structure places capture of the current destination before the comparison with the boundary. No local state or payload write occurs before that comparison.

Selection uses address equality only. There is no visible ordering comparison, byte-count calculation, or check that 12 bytes remain available.

Consequently:

- Equal addresses select the dependency path.
- Unequal addresses select the direct path.
- A current address beyond the apparent boundary still selects the direct path.
- A current address less than 12 bytes before the apparent boundary still selects the direct path.
- Null has no special effect on branch selection beyond participating in equality.

These distinctions are established behavior. They must not be replaced by a stronger “sufficient capacity” condition.

### Equal-address path

When the two observed addresses are equal, the function prepares a temporary record containing the three payload words in argument order.

It then calls F-ee9d9ff120bd with:

1. The original state address.
2. The current destination captured from state offset +4.
3. An address referring to the temporary three-word record.

The temporary is prepared before the call. The function returns after the dependency returns; no subsequent direct update of the state object or destination storage is visible.

No direct advance of the stored current destination occurs before delegation. Whether the helper advances that field, changes the boundary, allocates storage, copies the payload, or performs some different operation is unknown.

The temporary provides payload storage for the duration of this call. Persistent use of its address after the function returns is not supported by its visible lifetime. Whether the dependency copies the record, modifies it, or retains its address is not established.

The dependency receives the original state address and the previously captured current destination. The supplied representation does not establish a new read of that destination field immediately before the call.

### Unequal-address path

When the two observed addresses differ, the function first updates the field at state offset +4. The stored value is the original destination advanced by three four-byte elements: a represented displacement of 12 bytes.

This metadata update occurs before the original destination is checked for null and before any payload write.

If the original destination is non-null, the function then writes:

1. The first payload word at the original destination.
2. The second payload word four bytes after the original destination.
3. The third payload word eight bytes after the original destination.

Those are the write order and record offsets shown by the supplied representation. The writes use the captured original destination, not the newly stored advanced destination.

If the original destination is null, all three payload writes are skipped. The earlier metadata update is not skipped or undone.

No dependency call occurs on this path. No explicit rollback, error report, or final boundary check is visible.

### Arithmetic and invalid states

The advance is three elements of four bytes each, not three bytes. The normal intended destination range is therefore the half-open 12-byte region beginning at the original destination.

The supplied representation does not establish behavior for address overflow, invalid pointer arithmetic, or addresses outside a valid storage object. In particular, it shows an advance attempted before the null test, but does not establish a portable result for advancing a null pointer.

The null case must therefore be described narrowly: the metadata assignment is reached, and the payload stores are bypassed. A guaranteed final numeric address cannot be inferred without the target’s pointer-arithmetic semantics.

Likewise, no recovery is visible for unreadable state fields, unwritable metadata, insufficient destination storage, or a fault during a payload write.

## Side effects

### Direct memory effects

On the unequal-address path, the explicit external writes are:

- One pointer-valued update at state offset +4.
- If the original destination is non-null, three 32-bit payload writes at record offsets +0, +4, and +8.

The boundary field at state offset +8 is read but is not an explicit direct-write target. Other state fields are not explicitly accessed by this function.

Those statements describe access targets, not unconditional final values. The destination may alias the state object. No non-aliasing check is visible.

For example, if a payload destination overlaps state offset +4, a payload write may overwrite the metadata update performed earlier. If it overlaps state offset +8, a payload write may change the boundary field even though that field is not otherwise a direct-write target.

Accordingly, the usual final-state description—advanced current destination, unchanged boundary, and a newly stored record—requires valid, suitably non-overlapping storage. It is not guaranteed for arbitrary aliasing inputs.

### Ownership and lifetime

The direct path contains no visible allocation, deallocation, ownership transfer, or payload interpretation. Pointer-like bit patterns inside payload words are stored as opaque words; no referenced object is visibly copied or released.

The function uses caller-supplied state and destination storage. Their ownership cannot be inferred from these accesses.

On the dependency path, allocation, release, ownership transfer, global-state changes, and retention of supplied addresses are unknown. None may be ruled out merely because the dependency is called from an apparent append operation.

### Partial updates and synchronization

The direct path publishes the advanced destination before storing the payload. There is no visible transaction, synchronization operation, or rollback mechanism.

If a later write cannot complete, the supplied representation provides no mechanism for restoring the prior state. It also provides no concurrent-access contract. The shown operation order must not be treated as an atomic record insertion or as sufficient publication synchronization for another thread.

### 5. Unequal addresses with insufficient apparent space

Assume the current destination is 0x3000 and the boundary is 0x3004.

### 6. Payload overlaps state metadata
