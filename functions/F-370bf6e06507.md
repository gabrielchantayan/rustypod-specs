# F-370bf6e06507

## Purpose

## Behavior

### Acquisition and null decision

F-370bf6e06507 first invokes F-6fe6e440b0b4. There is one visible invocation per invocation of F-370bf6e06507.

After that dependency returns, its result is compared with a null pointer.

If the result is null:

- No object-header read is performed by the visible dispatch logic.
- No table-slot read is performed by that logic.
- No indirect target is invoked.
- The function returns the 32-bit value zero.

This branch does not establish why acquisition returned null. Absence, initialization state, failure, or another meaning remains unspecified.

The zero result is not evidence that the invocation had no side effects: F-6fe6e440b0b4 has already executed and may have changed state.

### Non-null dispatch

If the acquired pointer is non-null, the visible operation proceeds in this dependency order:

1. Read the first four-byte word at the acquired address.
2. Use that word as the base for a lookup displaced by 236 bytes.
3. Read the callable target stored at the resulting location.
4. Transfer control to that target.
5. If the target returns normally, return its 32-bit result.

The header read must precede the target-slot read because it supplies the base for that read. The target-slot read must precede the transfer because it supplies the destination.

No second acquisition, retry, alternate slot selection, or fallback target is visible. The acquired pointer is checked for null, but the loaded table base and loaded target are not separately checked for null.

The visible logic does not inspect the target’s result before returning it.

### Address arithmetic

The lookup uses a fixed displacement of 236 bytes from the loaded base. There is no visible bounds check or validation of the resulting address.

The supplied representation does not independently establish machine behavior for address overflow, misalignment, or unmapped storage. A portable behavioral contract therefore cannot promise successful dispatch when forming or accessing that address is invalid.

The displacement must not be interpreted as 236 four-byte elements. Such an interpretation would select a different location and would not match the established lookup.
