# F-66002730a5cb

## Purpose

F-66002730a5cb visits indexed candidates, selects candidates associated with a caller-supplied subject, and applies one of three selector-dependent behaviors:

- **Selector 1:** invoke an opaque operation for each matching visit; return −1 if that operation returns zero.
- **Selector 2:** count matching visits whose payload word is nonzero.
- **Selector 3:** invoke a different opaque operation for each matching visit.
- **Other selectors:** retain traversal and association checking, without selector-specific work.

The subject used for association comparison remains unchanged. In contrast, the argument supplied to the traversal-bound dependency changes according to the preceding visit. Consequently, this is not established to be traversal of a fixed subject-owned collection.

“Candidate,” “association,” and “payload” describe observable roles, not established domain types. Collection traversal and operation dispatch are inferred intent; the contract below concerns the visible behavior.

## Interface

### Inputs and result

| Item | Representation and meaning |
|---|---|
| Subject | A 32-bit pointer-shaped value. It is the fixed association-comparison target and the initial argument to F-fd477cd1a249. |
| Selector | A signed 32-bit integer. Only exact values 1, 2, and 3 select additional behavior. |
| Result | A signed 32-bit integer. Normal termination returns the accumulated count; selector-1 failure returns −1. |

The routine does not use the input subject directly as the base of a memory read. Dependencies may use it, and addresses obtained during traversal may alias it. A zero subject is not explicitly rejected; whether dependencies accept it is unknown.

For a defined, normally returning execution:

- Selector 1 returns either zero or −1.
- Selector 2 returns a value from zero through 2,147,483,647.
- Selector 3 and all unsupported selectors return zero.

There is no explicit error result for an unsupported selector.

### Memory layout

The supplied representation uses four-byte words and 32-bit pointer-shaped values. The directly inspected layout is:

| Object role | Byte offset | Four-byte value used |
|---|---:|---|
| Candidate | 0 | Association address |
| Candidate | 20 | Payload value, used only for a matching selector-2 visit |
| Association | 0 | Subject identifier, compared by value with the original subject |

No intervening candidate fields are inspected. A selector-2 payload is tested for zero and passed onward as a pointer-shaped argument; this routine does not dereference the payload itself.

F-667717e3fb3e supplies a represented 64-bit result. Its low 32 bits provide the candidate address. Its high 32 bits do not provide an alternative usable association or affect qualification.

The native calling convention and the physical implementation of that 64-bit return remain **documented_only**.

### Preconditions

Defined execution requires:

- Every invoked dependency to accept the arguments supplied on that path.
- Each nonzero candidate to support a valid four-byte read at offset 0.
- Each nonzero association address obtained from a candidate to support a valid four-byte read at offset 0.
- Each matching selector-2 candidate to support a valid four-byte read at offset 20.
- Memory accesses to satisfy the target’s applicable lifetime, alignment, access, and synchronization requirements.

These requirements are conditional. For example, a candidate with a zero association requires no association-object read, and an unmatched candidate requires no payload read.

Zero checks do not validate nonzero addresses. In particular, a valid candidate record does not establish that its association address is valid.

## Behavior

### Traversal and progress

Traversal begins at index zero with count zero. The first bound query receives the original subject.

Every candidate lookup is authorized by a fresh call to F-fd477cd1a249. Its signed 32-bit result must be strictly greater than the current index for that visit to occur. A result less than or equal to the index ends traversal and returns the count.

Consequences include:

- An initial zero or negative bound returns zero without a lookup.
- A later negative bound also ends traversal.
- Equality ends traversal; it does not permit a visit at that index.
- The bound is not cached.
- A terminating bound query is not followed by a lookup or candidate-memory read.

Each authorized lookup calls F-667717e3fb3e with the current index and a second argument of zero. Completed visits advance the index by exactly one. Selector-1 failure instead returns immediately.

Changing bound arguments and dependency side effects can change which visits occur. They do not remove the finite progress limit established by the signed 32-bit comparison. An authorized index cannot exceed 2,147,483,646, because no signed 32-bit bound can be greater than 2,147,483,647.

Accordingly, if all invoked dependencies return and all required accesses remain defined:

- At most 2,147,483,647 candidate lookups occur.
- The index can reach 2,147,483,647 but cannot advance beyond it.
- A bound query at that index necessarily terminates traversal.
- At most 2,147,483,648 bound queries occur, including the final terminating query.

There is no separate cancellation mechanism or smaller explicit traversal limit.

### Association eligibility

Qualification depends on the original subject, not on the changing bound-query argument.

A candidate qualifies only when all of the following hold:

- The lookup’s low 32-bit portion is nonzero.
- The association address stored at candidate offset 0 is nonzero.
- The subject identifier stored at association offset 0 equals the original subject.

The comparison is equality of represented pointer values, not comparison of subject contents.

For a nonzero candidate, the association address comes exclusively from candidate offset 0. For a zero candidate, there is no candidate or association dereference. The high half of the lookup result cannot rescue a zero candidate or supply a fallback association.

Eligibility checking applies to every selector, including unsupported values. A matching record therefore does not imply that a selector-specific operation will occur, and an unsupported selector does not bypass the association reads.

### Selector outcomes and subsequent bound arguments

The next bound-query argument is determined by the visit outcome:

| Visit outcome | Selector-specific effect | Argument supplied to the next bound query |
|---|---|---|
| Candidate does not qualify | None | Candidate address from the lookup, including zero |
| Candidate qualifies; unsupported selector | None | Candidate address |
| Candidate qualifies; selector 1 returns nonzero | Invoke F-a97e4a8e33df; count unchanged | That dependency’s returned pointer-shaped value |
| Candidate qualifies; selector 1 returns zero | Invoke F-a97e4a8e33df; return −1 immediately | No next query |
| Candidate qualifies; selector 2 | Read payload at candidate offset 20; increment count exactly when it is nonzero | Payload value, including zero |
| Candidate qualifies; selector 3 | Invoke F-b3f16c6113a2; count unchanged | That dependency’s returned pointer-shaped value, including zero |

Both selector-specific dependencies are called without explicit arguments. The candidate is not explicitly passed to either one. Their relationship to the matching candidate, including any dependence on ambient state, is unknown.

A zero selector-2 payload or selector-3 result does not itself terminate traversal. It causes a subsequent bound query with zero. Whether that query is valid, returns, or permits another visit depends on F-fd477cd1a249.

After any nonmatching visit, the candidate address supplies the next bound argument even if earlier visits supplied a payload or selector-specific return value. The original subject nevertheless remains the association-comparison target.

### Counting and integer bounds

Only selector 2 changes the count. Each qualifying visit contributes either zero or one according to the payload’s zero/nonzero value.

The count measures visits, not distinct records or distinct payloads. Repeated lookup of the same qualifying candidate can contribute repeatedly.

The represented signed arithmetic does not require an overflow policy for ordinary defined execution. Before each visit, the count is no greater than the number of completed visits. The traversal permits at most 2,147,483,647 visits, so neither count advancement nor index advancement exceeds the signed 32-bit maximum.

This bound does not assert safety against invalid memory, nonreturning dependencies, or other behavior outside the established execution contract.

## Side effects

### Observable reads and call order

For each visit, the bound dependency returns before candidate lookup occurs. Lookup returns before any candidate or association read.

The source-level memory-read order for a qualifying candidate is:

1. Candidate offset 0.
2. Association offset 0.
3. Candidate offset 20, only for selector 2.

The association read requires a nonzero association address. The payload read additionally requires a successful subject comparison and selector 2.

For selectors 1 and 3, the relevant opaque operation occurs only after the association reads and successful comparison. Selector 2 invokes neither selector-specific dependency.

On selector-1 failure, no index advancement, later bound query, or later lookup occurs.

These ordering statements describe the supplied representation’s observable access dependencies. They do not establish atomic accesses, synchronization, or hardware memory-order guarantees.

### Mutation and ownership

No direct store to the subject, candidate, association, or payload object is visible. The routine maintains its traversal index, count, and changing bound argument internally.

No explicit allocation, release, reference-count operation, or ownership transfer is visible. This does not establish ownership neutrality of dependencies. A dependency may mutate shared state, change later lookup results, allocate memory, or invalidate previously reachable objects.

No dependency may be assumed to preserve globals or object lifetimes. The routine does not establish snapshot semantics or an ownership protocol for returned and loaded addresses.

### Failure behavior

The sole explicit failure-like return is −1 following a zero result from F-a97e4a8e33df.

None of the following directly produces −1:

- A zero candidate.
- A zero association address.
- A subject mismatch.
- A zero selector-2 payload.
- A zero selector-3 result.
- An unsupported selector.
- A bound that ends traversal.

No visible recovery path handles invalid reads, dependency exceptions or faults, or a dependency that does not return.

## Acceptance examples

These are conditional acceptance criteria, not executed tests. Unless stated otherwise, required memory is valid and invoked dependencies return normally.

### Immediate bound termination

If the initial bound is zero or negative, the result is zero. F-667717e3fb3e is not called, and no candidate or association memory is read.

### One counted visit

With selector 2, suppose index zero is authorized and lookup supplies a qualifying candidate with a nonzero payload.

The count becomes one. The next bound query receives the payload. If that query returns one, the result is one because the current index is also one.

### Zero payload without direct termination

For a qualifying selector-2 candidate with a zero payload, the count remains unchanged and the next bound query receives zero.

If that dependency accepts zero and returns a value greater than the next index, traversal continues. The payload’s zero value alone is not a stop condition.

### Selector-1 failure and success

For a qualifying selector-1 visit:

- A zero F-a97e4a8e33df result produces immediate −1, without another bound query.
- A nonzero result supplies the next bound argument. If that next query ends traversal, the final result is zero, not a count of successful operations.

### Zero selector-3 result

For a qualifying selector-3 visit, a zero F-b3f16c6113a2 result leads to a bound query with zero. It does not directly produce −1 or a normal return.

### Unsupported selector still reads associations

With selector −4 and a qualifying candidate, the candidate’s association address and the association’s subject identifier are read. The payload is not read, and neither selector-specific dependency is called. The candidate address supplies the next bound argument.

### Zero candidate despite nonzero high half

If lookup’s low half is zero and its high half is nonzero, no candidate or association dereference occurs. The candidate does not qualify, and the next bound argument is zero.

### Mismatch preserves the original comparison target

Suppose an earlier visit supplied a payload as the bound argument. A later candidate identifies that payload rather than the original subject.

Unless those values are equal, the later candidate does not qualify. Its own candidate address, not the previous payload, supplies the following bound argument.

### Repeated candidate visits

If two authorized selector-2 lookups return the same qualifying candidate and each payload read is nonzero, those visits contribute two. No identity-based deduplication occurs.

### Maximum progress boundary

Even if every bound query returns 2,147,483,647, the final authorized index is 2,147,483,646. After that visit, the index is 2,147,483,647, and the next bound query must terminate traversal.

If every visit qualifies under selector 2 and has a nonzero payload, the result is 2,147,483,647. Neither increment overflows.

The following remain **documented_only**:

- Domain meanings of the subject, associations, payloads, and selector-specific operations.
- Whether changing the bound-query argument is intentional domain behavior.
- The native calling convention and physical form of the represented 64-bit lookup return.
- Dependency acceptance of zero or arbitrary pointer-shaped bound arguments.
- Dependency effects on globals, memory, object validity, allocation, release, and ownership.
- Hidden context used by dependencies called without explicit arguments.
- Concurrency, synchronization, and platform-specific access requirements.
- Outcomes of dependency faults, nonreturning calls, or invalid memory accesses.

Overall termination remains conditional on dependencies returning and accesses remaining defined. Within those conditions, traversal has the finite signed-width bound described above; changing bound arguments alone cannot produce unbounded traversal.
