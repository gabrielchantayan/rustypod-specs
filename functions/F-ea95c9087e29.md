# F-ea95c9087e29

## Purpose

The available static representation establishes a fragmentary, state-dependent routine that can invoke either of two indirectly addressed dependencies, write narrow portions of a dependency result into several memory locations, and construct an overlapping memory record on one exit path.

A higher-level purpose is not established. In particular, the evidence does not justify describing the routine as a parser, allocator, serializer, or object initializer.

Every represented path eventually reaches an invalid-instruction or undecodable-control-flow boundary, unless an indirect dependency does not return or an earlier memory access fails. No ordinary return is visible. These boundaries limit the contract: they do not establish a deliberate abort API, a particular exception, or the absence of further behavior in the original executable.

The behavior below is a contract for the visible fragment, not a claim that the recovered control flow is complete.

## Behavior

### 1. Entry and iteration priority

Each iteration first examines the negative-condition state. This check takes priority over the first input’s value and the overflow condition.

If the negative condition is set:

1. Clear the low two bits of the current link-like value.
2. Add `0xCD8` to obtain an indirect target.
3. Read one byte at offset `8` from the current third input.
4. Invoke dependency **F-indirect-01** with that byte as its sole visible argument.
5. If the dependency returns, reach an undecodable-control-flow boundary.

No subsequent loop test or visible memory write occurs on this path before that boundary. The byte read must succeed for the call to occur.

### 2. Loop-exit decision

When the negative condition is clear, execution leaves the loop if either:

- the current first input is zero; or
- the sign bit of the current first input differs from the overflow-condition state.

The second condition is not an ordinary positive-value test. Specifically:

- With overflow clear, a nonzero nonnegative first input continues into the loop body; a negative first input exits.
- With overflow set, a negative first input continues into the loop body; a nonnegative first input exits.
- Zero exits regardless of overflow.

The carry condition does not control this decision. It is used after loop exit.

### 3. Working-word scaling and early boundary

If the loop continues, the working word is multiplied by eight. Under the represented unsigned 32-bit interpretation, only the low 32 bits are retained.

The next decision uses the existing overflow-condition state. The visible representation does not update that condition from the multiplication.

If overflow is clear, execution reaches an undecodable-control-flow boundary immediately after scaling. The result-producing dependency is not invoked, and none of the loop body’s subsequent memory writes occurs.

Thus a clear negative condition, a clear overflow condition, and a nonzero nonnegative first input select this early-boundary path.

### 4. Result-producing indirect call

If overflow is set after the scaling step:

1. Clear the low two bits of the current link-like value and add `0x7A4` to form an indirect target.
2. Replace the visible link-like working value with `0x083FDFB3`.
3. Invoke dependency **F-indirect-02** with the current first input.

The target is derived from the link-like value before its replacement. Later target calculations use the replacement value unless the represented state is otherwise changed.

If the dependency returns a represented 48-bit result:

1. Replace the current first input with the result’s low 32 bits.
2. Write the result’s high 16 bits at offset `0x16` from the fourth input.
3. Write the result’s low 16 bits at offset `10` from the implicit address base.
4. Write the result’s low 8 bits at offset `0x18` from the scaled working word.

These three writes occur in the listed order. They are not interchangeable when addresses overlap. No visible validation, allocation, rollback, or capacity check precedes them.

### 5. State refresh after the result writes

After the three writes, the represented state is updated as follows:

- Carry becomes true exactly when the scaled working word is greater than `13` under an unsigned 32-bit comparison.
- Overflow becomes the signed-overflow condition for subtracting `14` from that working word.
- Negative becomes the sign bit of the 32-bit subtraction result.
- The third input is replaced by the 32-bit value read at offset `100` from the implicit address base.

The subtraction is used to derive conditions; it does not replace the working word.

For the represented 32-bit subtraction, signed overflow occurs when the working word’s bit pattern lies from `0x80000000` through `0x8000000D`, inclusive. This differs from unsigned wraparound.

The read at offset `100` follows all three result writes. If a preceding write aliases that location, it can affect the value loaded. The next iteration then restarts with the negative-condition check, using the refreshed third input.

### 6. Processing after loop exit

Loop exit reaches a carry-controlled branch.

If carry is set, the routine reaches an undecodable-control-flow boundary without performing the record construction below.

If carry is clear, the routine:

1. Computes a record destination by doubling the fourth input.
2. Writes the low 16 bits of the current first input at offset `0x10` from the current third input.
3. Captures the global address-bearing word.
4. Reads a byte at offset `3` through an evaluation of that global address-bearing location.
5. Performs five consecutive 32-bit record writes.
6. Overwrites one byte inside the first record word.
7. Reaches an undecodable-control-flow boundary.

There is no visible normal return after record construction.

The global word is evaluated when captured and again as the base expression for the byte read. Without stability guarantees, the captured address and the address used for the byte read must not be assumed identical.

### 7. Record layout and overlap

Let the doubled fourth input be the record destination. The ordered full-word writes are:

| Offset | Width | Written value |
|---|---:|---|
| `0` | 32 bits | Incoming stack-derived word |
| `4` | 32 bits | Current third input |
| `8` | 32 bits | Global-derived byte, zero-extended |
| `12` | 32 bits | Previously captured global address-bearing word |
| `16` | 32 bits | Record destination itself |

After those writes, an 8-bit write places the same global-derived byte at record offset `1`.

The first record word therefore does not necessarily retain the incoming stack-derived word unchanged. Its byte at offset `1` is replaced. The numeric value of the resulting word depends on endianness, which is not established here.

The earlier 16-bit write through the third input precedes the global byte read and every record write. Aliasing can therefore affect both the byte obtained from global-referenced memory and the final memory contents.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes required memory accesses and indirect calls are valid.

### Negative-condition priority

Given an initially set negative condition and a zero first input:

- Read the byte at third-input offset `8`.
- Invoke **F-indirect-01**.
- Do not take the zero-controlled loop exit before that call.
- If the call returns, reach the undecodable boundary.

### Scaling without a result-producing call

Given negative clear, overflow clear, and first input equal to `1`:

- Multiply the working word by eight.
- Do not invoke **F-indirect-02**.
- Reach the early undecodable boundary.

### Exit without record construction

Given negative clear, first input zero, and carry set:

- Leave the loop immediately.
- Perform none of the record-construction writes.
- Reach an undecodable boundary.

### Record construction with a final overlapping byte

Given negative clear, first input zero, carry clear, distinct valid destination regions, and stable global state:

- Write zero as a 16-bit value at third-input offset `0x10`.
- Populate the five record words at the doubled fourth input.
- Write the global-derived byte at record offset `1` after the word writes.
- Do not require the first record word to remain equal to the original stack-derived word.

### Result splitting followed by the byte-consuming call

Given negative clear, overflow set, a negative first input, and an initial working word of `1`, suppose **F-indirect-02** returns the 48-bit value `0x123489ABCDEF`.

Provided the destinations are valid and non-overlapping:

- Scaling produces `8`.
- The fourth-input-relative 16-bit write stores `0x1234`.
- The implicit-base-relative 16-bit write stores `0xCDEF`.
- The working-word-relative byte write stores `0xEF`.
- Carry becomes clear, overflow becomes clear, and negative becomes set because the 32-bit result of `8 − 14` is negative.
- The third input is refreshed from implicit-base offset `100`.
- The next iteration selects **F-indirect-01**, using a byte read through that refreshed address.
