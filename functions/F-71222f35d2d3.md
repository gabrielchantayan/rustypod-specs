# F-71222f35d2d3

## Purpose

F-71222f35d2d3 processes a request against a selected channel record. It checks eligibility and a two-byte prefix, invokes validation, and handles either a short operation or a segmented-data operation. Most ordinary exits update channel state and submit a response; initial ineligibility returns without those calls.

Established behavior includes accumulator acquisition and ingestion, completion-mask checking, preliminary response submission, and construction of a final response in temporary storage. Selected failures invoke a nonreturning dependency.

“Channel,” “fragment,” “accumulator,” and “trailer” describe observed uses. Their external protocol meanings are not established.

## Interface

The inputs are:

- An opaque 32-bit context value.
- A pointer to a request descriptor.

The result is a 32-bit integer. It is distinct from the response status: an error response can accompany zero, and some failures do not return.

## Behavior

### Entry, saved addresses, and prefix checking

The function reads the descriptor length, saves the descriptor’s offset-zero value, and calls F-5f5f14cedda3 for the channel index. It then loads the channel-record base and forms the selected-record address **before** checking whether the index exceeds 2. Such an index invokes F-a817d8d58c10, which is represented as nonreturning.

Initial result, response kind, and status are 62, 22, and 4.

Eligibility requires length at least 2 and channel offset 4’s low byte equal to 3. For a shorter length, that channel byte need not be read. Ineligibility returns 62 without common finalization.

For an eligible request:

1. The final-state selector becomes the 32-bit all-ones value and response length becomes 1.
2. The payload pointer is read from the descriptor.
3. Both prefix bytes are read from the payload.
4. A 32-bit validator-output word is initialized to zero, and the response pointer selects the status word.
5. The auxiliary global word is copied into automatic storage.
6. Status becomes 8.
7. Channel offset 28 is read and compared with the saved first prefix byte. Offset 29 is read only if that comparison matches.

Thus both payload-prefix reads precede the auxiliary global read. A prefix mismatch reaches common finalization with result 62.

The saved payload pointer, length, prefix bytes, selected-record address, and auxiliary-word copy are not refreshed from their original sources. Later channel-field reads use the saved record address, even if a dependency changes the global record base.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless specified otherwise, storage is valid, eligibility and validation succeed, and dependencies preserve relevant exposed storage.

1. **Ineligible request:** Length 1 returns 62 without prefix reads or common finalization.

2. **Prefix mismatch:** A first-byte mismatch still occurs after both payload-prefix reads and the auxiliary-word copy. Result is 62; finalization receives all-ones state, kind 22, length 1, and status storage containing 8.

3. **Unsupported operation:** A matching, validated first byte other than 1 or 2 gives the default response and result zero.

4. **Stable short-operation count:** With length 2 and output low byte remaining 16, successful calls produce kind 23, length 17, population count 16, and trailer offset 16.

5. **Changed short-operation count:** A checked value of 16 can later become 255 before length selection, then 7 during context access, then 9 during population. The resulting length is zero, population count 7, and trailer offset 9. The earlier range check does not prevent this.

6. **Invalid short-operation count:** A low byte of 15 or 21 at the range check is fatal before preliminary submission.

7. **Nonfinal first fragment:** Indices 0 and 2 with successful ingestion select state 3, store next index 1, and submit two bytes of the saved auxiliary word. Trailer zero wraps to 255.

8. **Continuation failure:** An expected-index mismatch avoids continuation ingestion and selects status 4 with result zero. A called continuation-ingestion dependency returning 7 instead selects status 4 and result 7.

9. **Missing required bits:** Available mask 1 and required mask 3 select status 11 and result zero, without completed-response preparation.

10. **Length boundaries:** Lengths 503 and 504 both read payload indices and admit them only when current does not exceed final. Length 505 does not enter the segmented region.

11. **Completed segmented count changes:** Length selected from low byte 255 is zero. Later population, accumulator processing, and trailer placement may use different low bytes without changing that length.

12. **Late handle disappearance:** If the handle is absent after completed-buffer population, result is 11 and status becomes 10, but final response kind remains 23 and its pointer remains the buffer.
