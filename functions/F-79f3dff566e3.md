# F-79f3dff566e3

## Purpose

F-79f3dff566e3 conditionally retrieves three or four 32-bit words from a computed source address and writes them through a destination-pointer slot supplied to a dependency. It explicitly returns a 32-bit status of zero or three.

Zero requires both preliminary dependencies to return zero, the discriminator’s low byte to select a supported branch, and the second source word captured during the transfer to be at most `0x80000` when interpreted as unsigned. The final check occurs **after all selected stores**. Status three therefore does not imply unchanged memory.

A contiguous 12-byte or 16-byte destination record is conditional, not unconditional. Each store uses the destination-pointer slot again; the function does not establish a separate, immutable destination base. If a permitted alias allows a store to change that slot, later stores can use a different pointer.

Backward indexing into fixed-size records is an inferred purpose. The established behavior is the dependency sequence, address arithmetic, individual accesses, and status selection below.

## Interface

The function receives four inputs:

| Input | Representation in the supplied body | Role |
|---|---|---|
| Context | Pointer to four-byte words | Supplies two preliminary arguments, is passed directly to another dependency, and initializes the destination-pointer slot. |
| Selector | Unsigned 32-bit value | Passed to the first dependency and initializes the discriminator slot. |
| Object | Pointer whose first word supplies an indirect-dispatch base | Provides callback dispatch and is passed to the selected destination dependency. Also initializes the index-carrying slot. |
| Address seed | Signed 32-bit value | Initializes a writable address slot used by the first dependency. |

The return value is 32 bits. Only zero and three are explicitly returned.

The supplied representation uses four-byte words and signed 32-bit arithmetic for source-address calculation. It treats the index-carrying pointer’s bits as a signed integer during that calculation. This is target-specific behavior, not a portable pointer-to-integer contract for arbitrary pointer widths.

Four separate mutable slots are initialized:

- Destination pointer: the context pointer.
- Discriminator: the selector.
- Index-carrying value: the object pointer.
- Address value: the address seed.

The original object argument, rather than the index-carrying slot, supplies subsequent callback dispatch and destination-dependency arguments.

The context words used by the first dependency are at byte offsets `0x1060` and `0x1394`. The indirect callback entry is at byte offset eight from the dispatch base obtained from the object’s first word. These accesses do not establish the complete layout or allocation size of either structure.

### Preconditions for defined completion

There are no explicit null, alignment, extent, permission, or address-range checks. Every executed access and call must be valid under the target execution model.

In particular:

- The two context words and dispatch data must be readable.
- The indirect target must be callable with the observed arguments.
- Dependencies must satisfy their own requirements.
- The arithmetic and integer-to-address conversion must be meaningful for the supplied values.
- Every source read must be valid when performed.
- Every destination address evaluated for an individual store must be writable when used.

A writable initial destination range alone is insufficient if a store can alter the destination-pointer slot. Conversely, source and destination disjointness is not explicitly required or checked. Any aliasing example below is conditional on that aliasing being permitted by the target memory model.

No allocation, ownership, lifetime extension, or release guarantee is established.

## Behavior

### Preliminary address dependency

The first call is to F-d34fa71e963d. Its arguments, in argument-position order, are:

1. The context word at byte offset `0x1060`.
2. The address of the writable address slot.
3. The original selector.
4. The context word at byte offset `0x1394`.

The relative evaluation order of the two context-word reads is not established by the supplied representation.

Any nonzero result immediately produces status three. There are no later calls or explicit transfer stores on that path. Effects already performed by the dependency are not undone.

After a zero result, the function adds `0x80000` to the current address-slot value and saves the result as the adjusted base. This happens before the second dependency call. The address used need not equal the original seed because the first dependency can modify the address slot.

The addition is expressed using signed 32-bit arithmetic. Its behavior outside the representable range is not established.

### Index dependency

The second call is to F-fc6790129708, with:

1. The original context pointer.
2. The address of the index-carrying slot.

That slot was initialized from the object pointer. Any nonzero result produces status three without callback dispatch or explicit transfer stores.

After a zero result, execution continues. The index-carrying slot is later interpreted as a signed 32-bit integer for source addressing; it need not then contain a usable object pointer.

The adjusted base is not explicitly recomputed from the address slot after this call. The index value, however, is consumed only during the later source-address calculation. The body does not establish that a dependency retaining access to an exposed slot cannot modify it again before that use.

### Discriminator callback

The function dispatches through the original object:

- Read the dispatch base from the object’s first word.
- Obtain the callback target at byte offset eight from that base.
- Invoke the target with the original object pointer and the address of the discriminator slot.

The callback’s return value is not inspected.

The discriminator slot initially contains the selector. Branch selection uses only its low eight bits at the relevant evaluation:

| Low byte | Behavior |
|---|---|
| Zero | Select the three-word branch. |
| One | Select the four-word branch. |
| Any other value | Return three without a destination-dependency call or explicit transfer accesses. |

Upper discriminator bits do not affect selection. If the callback leaves the slot unchanged and no other permitted effect modifies it, the selector’s low byte determines the branch. No explicit full-width write by the callback is required.

### Destination dependency

The three-word branch calls F-0a14bde72a48. The four-word branch calls F-e2669f32f0eb.

Each receives:

1. The original object pointer.
2. The address of the destination-pointer slot.

The selected dependency’s return value is ignored. There is no explicit validation of the resulting destination pointer.

The slot was initialized to the context pointer. If it remains unchanged, subsequent stores initially address the beginning of the context. The dependency is not established to allocate a buffer, return fresh storage, preserve an earlier destination, or provide a non-overlapping region.

Importantly, passing the slot’s address exposes the slot itself to the dependency. The body does not establish that the returned destination cannot overlap that storage.

### Source-address calculation

The source address is calculated after the selected destination dependency returns.

Let:

- \(B\) be the saved adjusted base.
- \(I\) be the signed 32-bit interpretation of the index-carrying slot when used.
- \(\operatorname{trunc}_0\) mean signed division rounded toward zero.

The three-word branch uses:

\[
S = B + \left(\operatorname{trunc}_0\left(\frac{12I+28}{4}\right)\right)(-4).
\]

The four-word branch uses:

\[
S = B + \left(\operatorname{trunc}_0\left(\frac{16I+32}{4}\right)\right)(-4).
\]

If every relevant signed intermediate is representable, these simplify respectively to:

\[
S = B - 12I - 28
\]

and

\[
S = B - 16I - 32.
\]

These simplifications do not establish wraparound behavior for overflowing inputs. The multiplication, addition before division, multiplication by negative four, and combination with the adjusted base all require attention under the applicable arithmetic model.

There is no explicit rejection of negative indices. For example, under representable arithmetic, index negative three places the three-word source eight bytes above \(B\); index negative two places the four-word source exactly at \(B\).

### Transfer accesses and destination-pointer reevaluation

The transfer consists of individual four-byte accesses, not an atomic block copy.

For each numbered destination store, let \(D_k\) denote the pointer value obtained from the destination-pointer slot for that particular store. The destination addresses are:

| Store | Destination address |
|---|---|
| First | \(D_0\) |
| Second | \(D_1 + 4\) |
| Third | \(D_2 + 8\) |
| Fourth, four-word branch only | \(D_3 + 12\) |

The body does not establish \(D_0=D_1=D_2=D_3\).

The transfer sequence is:

1. Read source word zero and store its value at the first destination address.
2. Read source word one into a retained unsigned 32-bit value.
3. Store that retained value at the second destination address.
4. Read source word two and store its value at the third destination address.
5. In the four-word branch, read source word three and store its value at the fourth destination address.
6. Perform the final comparison using the retained second-word value.

The supplied representation establishes this sequence of transfer operations. It does not establish the evaluation order between the source read and destination-pointer evaluation within an individual assignment.

If the destination-pointer slot remains stable, the stores address consecutive words starting at its value. Only under that condition is the destination footprint the conventional contiguous 12-byte or 16-byte range.

If a permitted alias makes the first destination store overwrite the destination-pointer slot, the second store uses the modified pointer plus four, not necessarily the initial pointer plus four. The same issue applies to later stores. The function contains no explicit protection against such redirection.

Ordinary source/destination overlap also matters. An earlier store can alter a source word that has not yet been read. This is not a snapshot-copy or overlap-preserving move guarantee.

### Final status

After all selected stores, the retained unsigned second-word value is compared with `0x80001`:

- Values from zero through `0x80000`, inclusive, produce status zero.
- Values from `0x80001` through `0xFFFFFFFF` produce status three.

The comparison does not explicitly reread the second source word or its destination location. Later changes to those memory locations do not themselves replace the retained comparison value.

## Side effects

The function explicitly performs three or four destination-word stores on a supported branch, provided execution reaches and completes those accesses. Those stores need not occupy a single contiguous destination range if the destination-pointer slot changes between them.

Other observable consequences include:

- Preliminary failure preserves any effects already performed by dependencies.
- Unsupported discrimination occurs after both preliminary dependencies and the callback have executed.
- Final value rejection occurs after the complete selected store sequence.
- No explicit rollback occurs.
- No explicit allocation, release, reference retention, or ownership transfer occurs.
- A destination overlapping the destination-pointer slot can change later store targets, where the target model permits that alias.
- A destination overlapping unread source data can change later copied values.

The address, index, discriminator, and destination arguments expose writable internal slots. Dependency effects are not limited to the intended output role merely by this body. No dependency-wide guarantee about globals, unrelated memory, retained addresses, or ownership is established.

Memory faults, invalid indirect calls, invalid pointer conversions, arithmetic failures, and dependency failures to return normally are not explicitly converted to status three.

## Acceptance examples

These are conditional static consequences, not executed tests. Except where an example explicitly concerns aliasing, assume valid accesses, representable arithmetic, normal dependency returns, stable internal state, and a destination-pointer slot that remains unchanged throughout the transfer.

### Three-word success at the accepted boundary

Both preliminary dependencies return zero. The address slot becomes zero, so \(B\) is `0x80000`. The index is zero. The discriminator low byte is zero.

F-0a14bde72a48 supplies a writable destination disjoint from the source and internal slots. The source address is `0x7FFE4`. Its three words are `0x11223344`, `0x80000`, and `0x55667788`.

The destination receives those three words consecutively. Status is zero: `0x80000` is accepted.

### Four-word rejection after stores

With the same base and zero index, discriminator low byte one selects source address `0x7FFE0`.

If the second source word is `0x80001`, all four stores occur before status three is returned. With a stable destination-pointer slot, those stores cover four consecutive destination words. Rejection does not undo them.

### Discriminator width and unchanged output

A discriminator of `0x12340001` selects four words. A discriminator of `0xABCD0000` selects three words. A discriminator of `0x00000102` returns three without calling either destination dependency.

If the selector is `0x00000201` and the callback leaves the discriminator unchanged, the four-word branch is selected.

### Preliminary failure

If F-d34fa71e963d returns nonzero, no later dependency or callback is invoked.

If it returns zero but F-fc6790129708 returns nonzero, there is no callback or transfer. Earlier dependency effects remain possible in either case.

### Overlap with unread source data

For the three-word branch, suppose the stable destination pointer is one word above the source and does not overlap internal slots. The original first source word is seven.

The first store overwrites source word one with seven. The second read captures seven, and its store overwrites source word two. The third read therefore also obtains seven.

All three destination words become seven. The retained second word is seven, so status is zero.

### Destination-pointer slot overwritten by the first store

This example applies only if the target model permits the returned destination to overlap the pointer slot and permits the stored word to become the pointer encoding described here.

Suppose the three-word destination dependency sets the destination pointer to the address of that slot itself. The source is disjoint from the slot and subsequent store locations. The source words are:

- `0x00102000`, a valid writable pointer encoding in this scenario.
- Seven.
- Nine.

The first store replaces the destination-pointer slot with `0x00102000`. The second store consequently writes seven at `0x00102004`; the third writes nine at `0x00102008`, assuming neither store further changes the slot.

The stores do not form a contiguous three-word record beginning at the original destination. Status is zero. This conditional example establishes why destination stability cannot be silently assumed; it does not establish that every target ABI permits such aliasing.
