# F-752e730d86f4

## Purpose

F-752e730d86f4 updates a caller-supplied context and fixed-address register locations. When its second input is zero, it also updates an associated record, invokes dependencies, and conditionally writes through an externally supplied configuration-object pointer.

**Established static behavior:** the function selects between zero and nonzero mode, performs the ordered accesses described below, and returns a 64-bit value whose low 32 bits are zero. The high 32 bits depend on the selected path and observed register values.

**Inferred intent:** the fixed addresses and masks suggest register-oriented device control. No device identity, protocol, success convention, or synchronization guarantee is established.

This contract describes normal completion of the supplied static body. It does not assign undocumented behavior to dependencies or hardware.

## Interface

### Inputs

The function has two source-visible 32-bit inputs:

- **Context address:** identifies an object containing the fields listed below.
- **Mode input:** tested for equality to zero. Zero selects zero mode; every other 32-bit value selects nonzero mode.

The representation uses 32-bit addresses and pointer-sized values. Some pointer-shaped values are used as selectors or return payloads rather than dereferenced addresses.

### Context and associated record

Offsets are in bytes. Each access in this table is 32 bits.

### Configuration-pointer global

The location `0x08107CFC` holds a 32-bit configuration-object address. Zero mode accesses this global as follows:

1. After writing associated record + `0x38`, read the global and use the resulting address for a one-byte read at object offset `0x04`.
2. Only if the early-exit condition holds, read the global again and use this second address for a 32-bit write at object offset `0x18`.

These are separate pointer reads. The address used for the write is not taken from the earlier pointer snapshot. The two accesses are not established to target the same object.

The complete configuration-object layout is unknown. Only the byte at `0x04` and the conditional 32-bit destination at `0x18` are exposed by this function.

## Behavior

### Common entry sequence

The function first reads the 32-bit value at context + `0xB4` and retains it as an entry snapshot.

It next reads context + `0xA0`. If that field is zero, it performs these 32-bit writes in order:

1. Zero to context + `0x98`.
2. The saved `0xB4` value to context + `0x9C`.

A nonzero field at `0xA0` skips both writes.

The function then reads the associated-record address from context + `0x34`.

Next, it captures a 32-bit control snapshot:

- From `0x38400900` in zero mode.
- From `0x38400B00` in nonzero mode.

Later uses of this entry control snapshot do not refresh it after calls or writes.

### Nonzero mode

The function performs the following operations after the common sequence:

1. Write the entry control snapshot with `0x04000000` set to `0x38400B00`.
2. Read a 32-bit word from `0x38400900`.
3. Write that word to `0x38400900`.
4. Return a 64-bit zero.

No dependency invocation is visible on this path.

The read followed by an equal-value write is part of the contract. Numeric equality does not establish that the write is externally inert.

### Zero-mode preparation

Zero mode performs these operations in order:

1. Invoke F-8f180221fee0 without source-visible arguments.
2. Write its 32-bit result to the captured associated-record address plus `0x80`.
3. Write the 32-bit constant `0x20080000` to `0x38400910`.
4. Read the 32-bit register offset at `0x08107CF8`.
5. At that offset relative to `0x38400000`, write the entry context snapshot with bit 31 cleared, using mask `0x7FFFFFFF`.
6. Invoke F-d7be9cfb4000 with arguments zero and `0x40`.
7. Add three to the call’s secondary 32-bit result modulo \(2^{32}\), clear the low two bits, and write the resulting 32-bit value to associated record + `0x38`.

The associated-record destination remains based on the address captured before either call. The programming value remains based on the entry `0xB4` snapshot, not a later context read.

The transformation in step 7 rounds ordinary unsigned values upward to a multiple of four, but wraps at the upper boundary:

- `0xFFFFFFFC` remains `0xFFFFFFFC`.
- `0xFFFFFFFD`, `0xFFFFFFFE`, and `0xFFFFFFFF` each produce zero.

No primary result from F-d7be9cfb4000 is visibly consumed. The calling-convention meaning and validity of the secondary result are unresolved.

### Configuration read and early-exit decision

Only after the associated-record + `0x38` write, the function:

1. Reads the 32-bit pointer global at `0x08107CFC`.
2. Reads one byte at offset `0x04` from the address just obtained.

The early exit is selected exactly when:

- That byte equals zero; and
- The entry control snapshot, masked with `0x03CC0000`, equals `0x000C0000`.

A nonzero byte disables the early exit regardless of the snapshot.

If selected, the function performs this sequence:

1. Read the 32-bit pointer global at `0x08107CFC` again.
2. Write the 32-bit value `0x00000080` at offset `0x18` from this newly obtained address.
3. Write `0x00000039` to `0x38400810`.
4. Write the entry control snapshot with `0x04000000` set to `0x38400900`.
5. Return `0x3840090000000000`.

The second pointer-global read is established behavior, not merely a possible implementation choice. If its value differs from the first read, the byte test and the 32-bit write target different objects.

This early exit performs neither F-9c06a5856a0f nor the later status reads.

### Optional dependency invocation

If early exit is not selected, the function examines bits 18 and 19 of the entry control snapshot. If both are set, it invokes F-9c06a5856a0f with:

- First argument: snapshot bits 22 through 25, interpreted as an unsigned value from zero through fifteen.
- Second argument: zero.

No result from this invocation is visibly consumed.

This condition is distinct from the early-exit comparison. In particular, a nonzero configuration byte can prevent early exit while leaving the optional invocation enabled.

### Ordinary zero-mode completion

Following the optional invocation, or immediately when it is not selected, the function:

1. Reads a 32-bit word from `0x38400B10`.
2. Clears bit 31 and shifts right by 29, extracting bits 29 and 30 as a status from zero through three.
3. Reads a candidate 32-bit control word from `0x38400900`.

If the first status is zero, one, or two, the candidate is written unchanged to `0x38400900`. The return’s high word is the first status.

If the first status is three, further accesses occur:

1. Read `0x38400B10` again and extract the same two status bits.
2. Read `0x38400900` again and form a candidate by setting `0x84000000`.

If the second status is also three, write that candidate to `0x38400900` and return with high word three.

If the second status is not three:

1. Read `0x38400900` once more.
2. Set `0x8C000000` in that last word.
3. Write the resulting word to `0x38400900`.
4. Use that same resulting word as the return’s high word.

Every described read occurs, including reads whose values are superseded. In particular, the control read with the `0x84000000` candidate occurs even when the second status is not three and a subsequent control read determines the final write.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Required accesses and invoked dependencies are assumed to complete normally.

1. **Context initialization preserves the top bit.**  
   With context + `0xA0` equal to zero and entry `0xB4` equal to `0x92345678`, write zero to `0x98`, then `0x92345678` to `0x9C`. A nonzero `0xA0` suppresses both initialization writes.

2. **Every nonzero mode selects the same path.**  
   Given a nonzero mode and entry `0x38400B00` value `0x00000005`, write `0x04000005` there, then read and rewrite `0x38400900`. Return zero. No dependency is invoked.

3. **Zero-mode programming clears only the top bit of the saved value.**  
   An entry context snapshot of `0x92345678` produces `0x12345678` at the externally selected register offset. The conditional context copy, if performed, remains unmasked.

4. **Secondary-result boundary behavior.**  
   A secondary result of five produces eight at associated record + `0x38`. A result of `0xFFFFFFFC` remains unchanged; a result of `0xFFFFFFFD` produces zero.

5. **Early exit with an unchanged configuration pointer.**  
   Suppose both pointer-global reads yield the same address, its byte at `0x04` is zero, and the entry control snapshot is `0x000C0000`. After preparation, read the pointer global for the byte test, reload it for the write, write `0x80` at object + `0x18`, then write `0x39` to `0x38400810` and `0x040C0000` to `0x38400900`. Return `0x3840090000000000`.

6. **Early exit with different configuration pointers.**  
   Suppose the first pointer-global read yields object A, whose byte at `0x04` is zero, and the masked entry snapshot satisfies the early-exit comparison. If the second pointer-global read yields object B, the `0x80` write targets B + `0x18`, not A + `0x18`. There is no additional byte test through B. Subsequent register writes and the return match the early-exit sequence.

7. **Nonzero configuration byte prevents the reload path.**  
   With snapshot `0x000C0000` and a nonzero byte obtained through the first pointer-global read, do not perform the early-exit pointer reload or configuration write. Invoke F-9c06a5856a0f with zero and zero, then proceed to ordinary completion.

8. **First status below three.**  
   A first status word of `0xC0000000` yields extracted status two because bit 31 is cleared. Read and rewrite the candidate control word without adding a mask. Return `0x0000000200000000`.

9. **Both statuses equal three.**  
   If both extracted statuses are three and the control read after the second status yields `0x00000011`, write `0x84000011`. Return `0x0000000300000000`. The earlier control read does not determine the write.

10. **Status changes away from three.**  
    If the first status is three and the second is below three, the final control read determines the write and return payload. A final read of `0x00000011` produces write `0x8C000011` and return `0x8C00001100000000`. The preceding control reads still occur.
