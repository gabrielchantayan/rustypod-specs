# F-9fdbd5232f27

## Purpose

F-9fdbd5232f27 is a configuration-driven control routine that conditionally invokes F-2e110a0c2be5, transforms its result, and returns an integer.

The established behavior is a nested state machine controlled by externally stored configuration words. It can:

- Return zero without invoking the dependency.
- Invoke the dependency with six zero arguments.
- Invoke the dependency with a scaled third input and a permutation of the other five inputs.
- Invoke the dependency repeatedly, including with repeatedly scaled first arguments.
- Repeat an enclosing processing phase.
- Fail to terminate for some configurations.

The application-level meaning of the configuration, arguments, and returned integer is unknown. A dispatch or control-flow role is an inference, not an established semantic purpose.

## Behavior

### Initial state

On entry:

- The prospective return value is zero.
- The outer selector is read from the entry-selector configuration.
- Five captured opaque words are zero.
- The captured integer input is zero.

The supplied arguments are **not** initially installed into the captured state.

This delay is observable: processing reached immediately from the entry selector uses zero captured inputs, not the caller’s supplied inputs.

### Outer decision and processing phases

Each outer decision performs two logically separate operations:

1. Subtract the outer reference from the current outer selector and retain the difference.
2. Compare the current outer selector with the outer reference.

The source expresses a configuration reference in each operation. It does not establish an atomic snapshot shared by them.

If the comparison is equal, a processing phase begins. When that phase completes, the routine performs another outer decision. Equality can therefore cause multiple consecutive processing phases without capturing the supplied inputs between them.

If the comparison is unequal, the routine:

1. Reloads the outer selector from the outer reference.
2. Captures all six supplied inputs.
3. Repeats the enclosing cycle only if the previously calculated difference equals exactly one.

If that difference is anything other than one, the routine returns its current prospective return value.

Under stable configuration and defined arithmetic, an initial entry selector that is neither equal to the outer reference nor exactly one greater than it causes an immediate zero return. The argument capture still occurs before that return, but there is no visible dependency call or use of the captured values.

### Captured argument arrangement

Once the supplied inputs have been captured, the five-word tuple used by the inner state machine is ordered as:

1. Fourth input.
2. Sixth input.
3. Second input.
4. First input.
5. Fifth input.

The third input is captured separately for multiplication.

Capture occurs only when an outer comparison is unequal. Consecutive equal outer decisions continue using the previously captured values, which may still be the initial zeros.

### Processing-phase initialization

At the beginning of each processing phase, the routine:

- Resets the phase’s dependency-derived accumulator to zero.
- Multiplies the input factor by the currently captured integer input, retaining that product.
- Resets the five-word working tuple to zero.
- Loads the inner selector from the inner-entry configuration.
- Resets the carried integer to zero.

The product of the input factor and captured integer is computed once per phase. Later default transitions reuse that product; they do not recalculate it.

A configuration change made by a dependency call therefore cannot retroactively change this phase’s already computed input product. It can affect a later phase.

### Inner classification

At each inner decision, the routine first establishes the current working tuple and current carried integer from the preceding transition. It then adds the inner bias to the current inner selector.

The resulting classification has three behaviors:

| Classification | Behavior |
|---|---|
| Zero | Exit the inner state machine |
| Two | Invoke F-2e110a0c2be5 |
| Any other value | Take the default transition without a dependency call |

One is therefore an ordinary default-transition value. It is not an exit condition or a dependency-call condition.

Every non-exiting inner step first reads the default successor and prepares a default next state consisting of:

- The phase’s input product as the next carried integer.
- The captured five-word permutation as the next working tuple.

For classification two, the call-specific transition then replaces this prepared state as described below. The default-successor read still precedes the dependency call in the supplied sequence, even though the call successor subsequently replaces its value.

### Default transition

For a nonzero classification other than two:

- No dependency is called.
- The next selector is the default successor.
- The next carried integer is the phase’s input product.
- The next working tuple is the captured permutation.

Repeated default transitions keep reinstalling the same phase product and captured tuple.

A default transition does not clear a result accumulated from an earlier dependency call in the same phase.

### Dependency-call transition

For classification two:

1. The argument factor is multiplied by the carried integer that existed on entry to this inner decision.
2. F-2e110a0c2be5 is invoked with that product as its first argument and the current five-word working tuple as its remaining arguments.
3. The returned integer is multiplied by the dependency-result factor.
4. That scaled result replaces the phase’s dependency-derived accumulator.
5. The next selector is read from the call successor.
6. The next carried integer is the product passed as the dependency’s first argument.
7. The next working tuple remains the tuple used for this call.

The dependency-result factor and call successor are read after the dependency returns. They must not be assumed to retain their pre-call values.

An immediate call at the start of a phase uses a zero carried integer and a zero tuple. With ordinary defined multiplication, its six arguments are all zero, irrespective of the supplied inputs.

A call reached after a default transition instead uses the phase product and the captured permutation. Its first argument is the argument factor multiplied by the previously computed input-factor product.

Consecutive calls multiply the carried integer again on each call. They preserve the working tuple across those calls. A subsequent default transition resets the carried integer to the phase product and replaces the tuple with the captured permutation.

### Phase completion

When the inner classification is zero, the routine calculates the prospective return value by:

1. Multiplying the first output factor by the phase’s dependency-derived accumulator.
2. Multiplying that intermediate result by the second output factor.

This association matters when evaluating intermediate representability. The contract does not replace these operations with an unrestricted mathematical product.

If the phase made no dependency call, the accumulator remains zero. Under ordinary defined arithmetic, the resulting prospective return is zero.

If the phase made several calls, only the most recent call’s scaled result contributes to phase completion. Earlier dependency effects remain possible, but earlier numeric results are overwritten.

The outer selector is then loaded from the outer successor, and the next outer decision occurs.

## Acceptance examples

These are conditional behavioral examples, not executed tests. Unless stated otherwise, they assume stable configuration reads, returning dependencies, and arithmetic values whose intermediate results are representable.

### 1. Immediate return without a dependency call

Suppose the entry selector is 12 and the outer reference is 10.

The initial comparison is unequal and the retained difference is two. The routine reloads the outer selector, captures its inputs, and returns zero. No processing phase or dependency call occurs.

### 2. One-step entry into processing with captured inputs

Suppose the entry selector is 11 and the outer reference is 10.

The first unequal outer decision retains a difference of one, so the routine captures the supplied inputs and repeats. The next outer selector equals the reference, causing processing with the captured inputs available.

This differs from starting with equal selectors: that starts processing before input capture.

### 3. Immediate inner call uses zeros

Suppose processing starts before argument capture, and the inner entry selector plus bias equals two.

The first dependency call receives six zero arguments. The result can nevertheless be nonzero because the dependency’s behavior is unknown.

If the call successor plus bias is zero, the inner machine then exits.

### 4. Default transition installs the supplied tuple

Suppose argument capture has occurred. The third input is 7, the input factor is 3, and the argument factor is 5.

If the first inner classification is a nonzero value other than two, and the default successor produces classification two, the following dependency call receives:

- First argument: 105.
- Remaining arguments: fourth, sixth, second, first, and fifth supplied inputs, in that order.

This result depends on the intervening default transition. An immediate phase-entry call would receive zeros instead.

### 5. Consecutive calls rescale the carried argument

Continue with a call whose first argument is 105 and an argument factor of 5.

If the call successor again produces classification two, the next call’s first argument is 525. The five-word tuple is unchanged.

This example requires the intermediate products to remain representable.

### 6. Final scaling and return

Suppose the last dependency return in a phase is 7, the dependency-result factor is 3, and the output factors are 2 and 5.

The phase’s prospective return becomes 210.

If the outer successor then differs from the outer reference by two, the following unequal outer decision causes the routine to return 210. If that difference is one, processing can continue instead, potentially replacing 210.

### 7. Configuration-induced nontermination

Suppose the inner entry classification is one, and the default successor also always produces classification one.

The routine repeatedly takes the default transition. It neither calls the dependency nor completes that phase.

Likewise, an outer successor that repeatedly compares equal to the outer reference can cause repeated phases without reaching the return decision.
