# F-6da76fc58c80

## Purpose

F-6da76fc58c80 conditionally updates a 32-bit field and returns a subsequent read of that field. It takes no explicit arguments.

The function evaluates a global reference twice before deciding whether to initialize anything. The first evaluation selects the storage used for the conditional write and final return read. The second evaluation selects the storage whose field is checked against zero. These selections coincide only if the reference evaluates to the same location both times.

If the checked field is zero, the function invokes F-8157a180d901 with the numeric argument 88, invokes F-f44c97c056ab, and writes the latter dependency’s 32-bit result into the field selected by the first reference evaluation. It then reads that first-selected field for its return value. If the checked field is nonzero, it skips both calls and the write, but still reads the first-selected field for the return.

**Inferred intent:** with a stable global reference, this resembles lazy initialization of a cached value using zero as an initialization trigger. The supplied evidence does not establish resource construction, successful initialization, or the meaning of the stored bits.

## Behavior

### Established access and call order

On a normally completing invocation, the supplied representation establishes this logical order:

1. Evaluate the global reference and capture its value.
2. Separately evaluate the global reference again.
3. Using the second evaluation, read the 32-bit field at byte offset 4 and test it against zero.
4. If that checked value is zero:
   - Invoke F-8157a180d901 with the explicit argument 88.
   - After that call returns normally, invoke F-f44c97c056ab with no explicit arguments.
   - After that call returns normally, write its 32-bit result at byte offset 4 in the captured storage.
5. Read the 32-bit field at byte offset 4 in the captured storage and return that read’s value.

This describes the logical evaluations, accesses, and calls visible in the supplied representation. It does not specify instruction counts, distinct physical loads, atomicity, or memory barriers.

### Nonzero checked field

If the field selected by the second reference evaluation is nonzero, neither dependency is called and the function performs no field write.

The return still comes from the captured storage. Therefore, even without a change to either field’s contents, the returned value need not equal the checked value if the two reference evaluations selected different locations.

If the reference is stable across both evaluations, both accesses select the same field. With stable field contents as well, the returned value equals the nonzero value that caused initialization to be skipped. Any nonzero bit pattern takes this path, including patterns with the high bit set.

### Zero checked field

If the field selected by the second reference evaluation is zero, both dependencies are called in order, provided each preceding call returns normally.

The first dependency’s result is not visibly inspected, retained, or passed explicitly to the second dependency. There is no visible success check between the calls.

The second dependency’s 32-bit result is written without validation to the captured storage. A zero result is stored just as a nonzero result is. There is no recheck of either selected field before this write.

The captured field need not have been zero. If the two reference evaluations selected different locations, a zero checked field can trigger replacement of a nonzero captured field.

The final return is a read after the write, not an unconditional return of the dependency result. With valid ordinary storage and no intervening modification, the read yields the stored result. No stronger equality is established under interference.

### Reference changes and dependency effects

Neither dependency is followed by a visible reevaluation of the global reference. The conditional write and final read continue to use the initially captured reference.

Consequently, a dependency’s change to the global reference does not by itself redirect those operations. This remains true whether the two earlier reference evaluations selected the same storage or different storage.

If a dependency changes the captured field, the function’s later write replaces that change after F-f44c97c056ab returns normally. If a dependency instead changes only a distinct checked field, the function does not visibly write that checked field.

Neither dependency is known to preserve globals, field contents, or storage lifetime. Invalidation of the captured storage defeats the requirements for the later write or read; this function provides no visible protection against that outcome.

### Repeated calls

With a stable global reference and unchanged field contents between invocations:

- A nonzero stored value causes a later invocation to skip both dependencies.
- A zero stored value causes a later invocation to invoke both dependencies again.

There is no visible separate initialized flag, in-progress marker, or retry limit.

These properties do not extend unconditionally to changing references. A later invocation makes its own two reference evaluations; its initialization decision depends on the field selected by its second evaluation, not necessarily the field previously written.
