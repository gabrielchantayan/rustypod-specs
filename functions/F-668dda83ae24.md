# F-668dda83ae24

## Purpose

F-668dda83ae24 prepares a four-word record for one of two supported selectors, then invokes a downstream operation for that selector and slot.

The record contains two operand words, a linkage word, and a packed control word. An operand-classification dependency determines whether each operand is stored with its high bit cleared or used as an index into a word table. The classification also determines two flags incorporated into the control word.

This is an established description of the visible accesses and calls, not a claim about the underlying device or subsystem. Whether the record represents a transfer, descriptor, queue entry, or another object is unknown.

The function is not transactional. It can overwrite part or all of the record before invoking the downstream dependency, and no rollback is visible.

## Interface

### Inputs

The interface has six 32-bit arguments:

| Position | Contract name | Interpretation established by the supplied representation |
|---|---|---|
| 1 | First operand | Unsigned 32-bit value. Either stored after clearing bit 31 or used as a word-table index. |
| 2 | Second operand | Unsigned 32-bit value. Either stored after clearing bit 31 or used as a word-table index. |
| 3 | Packed value | Unsigned 32-bit value shifted right and narrowed to twelve bits for the control word. Also passed to the classification dependency. |
| 4 | Mode | Signed 32-bit input. Passed twice to the classification dependency. Its equality to zero independently controls the linkage word. |
| 5 | Selector | Signed 32-bit input. Only values 1 and 2 proceed to dependency calls and record updates. |
| 6 | Slot | Signed 32-bit input used in address calculations and passed unchanged to the downstream dependency. No range check is visible. |

The signedness above follows the supplied representation. It does not establish a higher-level type system or a validated input domain.

### Result

The result is a 32-bit value:

- For a selector other than 1 or 2, the function returns `0x00000013`.
- For selector 1 or 2, it returns the result of F-dbb1e1e8544e unchanged.

No result-code interpretation is established. In particular, a zero result cannot be independently labeled “success” from this function alone.

### Global configuration and memory layout

The function uses six global configuration values. Their symbolic names here describe their roles without identifying storage locations:

- **Record base:** used to calculate the target record.
- **Selector-1 control base:** selects the control entry for selector 1.
- **Selector-2 control base:** selects the control entry for selector 2.
- **Operand-table base:** supplies indexed operand words.
- **Control-retention mask:** selects bits retained from the control entry.
- The selected control entry itself supplies a shift field and retained control bits.

The target record address is:

**Record base + (selector − 1) × 128 + slot × 16**

This is an algebraic description of the resulting address. The visible calculation forms an intermediate address using `selector × 128`, then addresses the record 128 bytes before that intermediate address.

The selected control-entry address is:

**Selected control base + slot × 32**

Only the first 32-bit word at that address is visibly read.

The target record has this layout:

| Byte offset | Width | Meaning |
|---|---:|---|
| 0 | 32 bits | First operand word |
| 4 | 32 bits | Second operand word |
| 8 | 32 bits | Linkage word |
| 12 | 32 bits | Packed control word |

The record stride is 16 bytes. The control-entry stride is 32 bytes. These different strides are part of the visible behavior.

## Behavior

### 1. Establish the record and select the control region

The function reads the record base and calculates the record location using the selector and slot.

It then selects the control base:

- Selector 1 uses the selector-1 control base.
- Selector 2 uses the selector-2 control base.
- Every other selector returns `0x00000013`.

The unsupported-selector path is not free of global accesses: the record-base read and address calculation occur first, and the selector-2 control base is read on the path that subsequently rejects a selector other than 1 or 2.

No dependency call or record write is visible on that rejection path.

For a supported selector, the record location and control-entry location are established before the first dependency call. A dependency changing the global record or control-base configuration therefore does not cause those already-established locations to be recomputed.

### 2. Obtain the operand classification

The function calls F-afd2ad8e8485 with five arguments, in order:

1. First operand.
2. Second operand.
3. Packed value.
4. Mode.
5. Mode again.

The fourth argument to F-668dda83ae24 is deliberately duplicated in this call. The supplied representation does not establish why.

After that call returns, the function reads and captures the operand-table base. This read occurs regardless of the returned classification.

Four classification values receive special handling:

| Classification | First operand word | Second operand word | Added flags |
|---|---|---|---|
| `0x00000000` | First operand with bit 31 cleared | Second operand with bit 31 cleared | `0x04000000` and `0x08000000` |
| `0x00000800` | First operand with bit 31 cleared | Word indexed by second operand | `0x04000000` |
| `0x00001000` | Word indexed by first operand | Second operand with bit 31 cleared | `0x08000000` |
| `0x00001800` | Word indexed by first operand | Word indexed by second operand | Neither |
| Any other value | No write to this field | No write to this field | Neither |

Clearing bit 31 means retaining exactly the low 31 bits with mask `0x7FFFFFFF`. It is not a signed absolute-value operation.

A table lookup uses the full unsigned operand as a word index:

**Operand-table base + operand × 4**

There is no visible index mask or bounds check.

The two table-base uses are observably different:

- A first-operand lookup reads the operand-table-base global again when forming that lookup address.
- A second-operand lookup uses the base captured immediately after F-afd2ad8e8485 returned.

Consequently, the two lookup addresses must not be specified as necessarily sharing one base snapshot. This distinction can matter if the global is volatile, asynchronously modified, or aliased by a preceding write.

For any recognized classification, the first operand word is written before the second operand word. In the `0x00001800` case, the first lookup and its record write occur before the second lookup.

For an unrecognized classification, both existing operand fields remain untouched by this function’s direct writes. Processing still continues to linkage and control construction, followed by the downstream call.

### 3. Read the control entry and write linkage

After operand handling, the function reads the selected control-entry word once. This first value supplies the shift count used later.

It then writes the linkage word:

- If mode is zero, the field receives the 32-bit address of the target record itself.
- If mode is nonzero, the field receives zero.

Every nonzero mode, including negative values, follows the second case.

The linkage destination is offset 8 in the target record. The address written for zero mode is the record’s offset-0 address, not the address of the linkage field.

### 4. Construct and write the packed control word

The function reads the selected control-entry word a second time. This second value supplies the retained control bits.

The shift count comes from bits 21 through 23 of the **first** control read:

**Shift count = (first control read AND `0x00E00000`) shifted right by 21**

The resulting count is between 0 and 7 inclusive.

The packed-value contribution is:

**(Packed value logically shifted right by the shift count) AND `0x00000FFF`**

The final control word is the bitwise union of:

- The **second** control read, masked by the control-retention mask.
- The twelve-bit packed-value contribution.
- The classification-dependent flags.

That result is written to record offset 12.

This construction does not separately clear flag bits or the low twelve bits from the retained control contribution. If the retention mask preserves such bits, they remain set through the bitwise union. Likewise, a classification that adds neither flag does not guarantee that the corresponding final control bits are clear.

The two control reads straddle the linkage write. They must not be collapsed into a single read in the behavioral contract. If the control entry changes between reads, the shift and retained-bit contributions can reflect different values. Configured aliasing between the linkage destination and control entry can also make that ordering significant.

The supplied representation does not establish a finer ordering between the second control-entry read and the read of the retention-mask global. Both contribute to the final control write.

### 5. Invoke the downstream operation

After the final control-word write, the function calls F-dbb1e1e8544e with:

1. Selector.
2. Slot.

It then returns that dependency’s 32-bit result without visible translation.

There is no visible conditional suppression of this call based on the classification, including unrecognized classification values. There is also no visible rollback if the returned value indicates a failure under some external convention.

## Side effects

1. Configuration reads and address calculations.
2. A call to F-afd2ad8e8485.
3. An operand-table-base capture.
4. Zero, one, or two table reads, depending on the classification.
5. Two operand-field writes for recognized classifications, or none for an unrecognized classification.
6. The first control-entry read.
7. A linkage-field write.
8. The second control-entry read and retention-mask read.

10. A call to F-dbb1e1e8544e.

For every recognized classification, exactly two operand-field writes are visible. Table reads can be interleaved with those writes as described above.

No explicit synchronization, locking, memory barrier, rollback, or memory release is visible. Ordinary program-order accesses are established by the supplied representation; hardware visibility and concurrency guarantees are not.

Dependency side effects are additional to these direct effects. Neither dependency may be assumed to preserve globals, leave memory untouched, or maintain ownership.

## Acceptance examples

These are conditional specifications derived from static evidence, not executed tests. Unless an example states otherwise, assume stable configuration, valid nonoverlapping storage, and address calculations that remain within the intended address space.

### Unsupported selector

With selector 3:

- The result is `0x00000013`.
- Neither dependency is called.
- No target-record field is written.
- The earlier configuration reads are still permitted and expected.

### Direct operands with zero mode

Suppose F-afd2ad8e8485 returns zero, the operands are `0x80000005` and `0xFFFFFFFF`, mode is zero, and both control reads and the retention mask are zero.

For packed value `0x00001234`:

- Offset 0 becomes `0x00000005`.
- Offset 4 becomes `0x7FFFFFFF`.
- Offset 8 becomes the record’s own address.
- Offset 12 becomes `0x0C000234`.
- F-dbb1e1e8544e is called with the original selector and slot.

The final result is whatever that downstream call returns.

### Mixed direct and indexed operands

Suppose the classification is `0x00000800`, the first operand is `0x80000009`, the second operand is 3, and the captured table base identifies a valid fourth word.

The first field becomes 9. The second field receives the 32-bit word at captured table base plus 12 bytes. The function adds `0x04000000`, but not `0x08000000`, through classification handling.

The second flag can nevertheless be present in the final control word if retained from the control entry.

### Indexed operands use full indices

For classification `0x00001800`, an operand with bit 31 set is not reduced to its low 31 bits before indexing. Such an input is acceptable only if the actual resulting address is valid under the target’s address arithmetic and memory configuration.

No safe bounds behavior is established.

### Unrecognized classification

Suppose F-afd2ad8e8485 returns `0x00000001`.

The existing words at offsets 0 and 4 remain unchanged by direct operand writes. Offset 8 is still rewritten according to mode, offset 12 is still reconstructed, and F-dbb1e1e8544e is still called.

### Different control snapshots

Suppose the first control read is `0x00600000`, the second is `0x000000A0`, the retention mask is `0x000000F0`, the packed value is `0x00001234`, and classification handling adds no flags.

The first read selects a shift count of 3. The packed contribution is `0x246`. The retained contribution is `0xA0`. Their bitwise union is `0x2E6`, which is written at offset 12.

Using only the first or only the second control read would not satisfy this case.
