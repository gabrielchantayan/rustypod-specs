# F-5415e7ab2b10

## Purpose

F-5415e7ab2b10 invokes F-4e6cefe281de to obtain or retain a record address, evaluates fields in that record, and conditionally updates it. Normal completion returns one of three unsigned 32-bit values:

| Return value | Established meaning within this function |
|---|---|
| **0** | The accepted update path completed. |
| **3** | F-4e6cefe281de returned zero; this function performed no subsequent record-field access. |
| **5** | F-4e6cefe281de returned nonzero, but the decision observations selected rejection; this function performed no direct record writes. |

On acceptance, the function stores the requested 32-bit value, clears an adjacent 32-bit field, and sets bit 7 of a byte.

With stable decision-field observations, a nonzero field at **0x2C** permits acceptance regardless of the request. A zero field there permits acceptance exactly when the unsigned request is **less than or equal to** the unsigned field at **0x28**.

An upper-bound check with an override is therefore a plausible interpretation. It is not an established domain meaning. The full contract includes repeated reads and their ordering; the stable-field interpretation does not replace those details.

## Behavior

### Ordered decision observations

After a nonzero dependency result, the represented record reads occur in this order:

1. Read the 32-bit field at **0x2C**, retaining whether this first observation is zero.
2. Read the 32-bit field at **0x2C** again, retaining whether this second observation is nonzero.
3. If the second observation at **0x2C** is zero, read the unsigned 32-bit field at **0x28**. Determine whether that observation is less than or equal to the request. This comparison replaces the retained zero test from the first observation at **0x2C**.
4. Read the unsigned 32-bit field at **0x28** unconditionally. Determine whether this final observation differs from the request.

Consequently, the supplied representation contains two reads at **0x2C** and either one or two reads at **0x28**. The conditional read at **0x28** occurs exactly when the second observation at **0x2C** is zero.

The final read at **0x28** occurs even when its value cannot alter the outcome. The conditional ordering comparison and the final equality comparison need not describe the same observed value.

These are ordered read occurrences in the supplied representation. Their correspondence to separate physical memory transactions, and the possibility of observing intervening changes in a particular execution environment, remain unresolved.

### Exact acceptance decision

The decision follows this table:

| Second observation at 0x2C | Relevant additional observations | Outcome |
|---|---|---|
| Nonzero | First observation at 0x2C was nonzero | Accept. |
| Nonzero | First observation at 0x2C was zero | Reject. |
| Zero | Conditional observation at 0x28 was greater than the unsigned request | Accept, regardless of the final observation at 0x28. |
| Zero | Conditional observation at 0x28 was less than or equal to the request, and the final observation equaled the request | Accept. |
| Zero | Conditional observation at 0x28 was less than or equal to the request, and the final observation differed from the request | Reject. |

When the second observation at **0x2C** is zero, the conditional comparison replaces the first observation’s contribution to the decision. In that case, the first observation at **0x2C** no longer affects acceptance.

When the second observation at **0x2C** is nonzero, the conditional read at **0x28** is omitted. Acceptance then depends on the first observation at **0x2C**; the unconditional read at **0x28** still occurs.

### Rejected outcome

On rejection, the function:

- Returns **5**.
- Performs no direct record writes.
- Does not read the byte at **0x1C**.

The decision-field reads have already occurred. Rejection does not undo dependency effects or imply that the invocation was otherwise side-effect-free.

### Accepted outcome

On acceptance, the represented accesses occur in this order:

1. Write the original requested value as 32 bits at **0x20**.
2. Write a 32-bit zero at **0x24**.
3. Read the byte at **0x1C**.
4. Write that observed byte back to **0x1C**, with bit 7 set.
5. Return **0**.

The byte operation preserves bits 0 through 6 from the byte actually read after the two 32-bit writes. It does not preserve an earlier snapshot. If bit 7 was already set, the resulting byte has the same value, but the represented write still occurs.

The acceptance decision is retained from the earlier observations. The function does not reread the decision fields between the two 32-bit writes and the byte update.

### Stable-observation simplification

If both observations at **0x2C** agree and all observations at **0x28** agree:

- A nonzero value at **0x2C** selects acceptance for every unsigned request.
- A zero value at **0x2C** selects acceptance exactly when the request is **less than or equal to** the unsigned value at **0x28**.
- A zero value at **0x2C** selects rejection when the request is **greater than** the unsigned value at **0x28**.

For the zero case, a field value greater than the request selects acceptance through the first acceptance alternative. Equality selects acceptance through the equality alternative. A field value less than the request selects rejection.

This simplification is conditional on stable observations. It does not authorize omitting any represented read.
