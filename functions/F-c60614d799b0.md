# F-c60614d799b0

## Purpose

F-c60614d799b0 exposes a 32-bit result and two optional pointer/metadata pairs from a shared, indexed record structure. Its two control inputs determine which record is selected and whether selection also changes shared state.

The established behavior includes:

- An unconditional call to obtain a context.
- A special response when both controls are nonzero.
- A record-availability check using two 32-bit context fields.
- Selection either at one index or one position beyond the other index.
- Optional consumption of the selected record.
- Conditional population of caller-supplied outputs.
- A conditional dependency call when a selected payload is not requested.

Interpreting the structure as a sixteen-slot queue, the controls as “consume” and “alternate selection,” or the conditional dependency as a memory-release operation is inferred intent, not an established contract. The precise behavior below does not depend on those interpretations.

## Interface

### Inputs

The function has six inputs:

| Input | Representation | Meaning established by use |
|---|---|---|
| First control | 32-bit integer | Zero disables consuming mutations; nonzero enables them unless both controls are nonzero. |
| Second control | 32-bit integer | Zero selects a successor of the first stored index; nonzero selects the second stored index, except in the both-nonzero branch. |
| First pointer output | Optional address of a writable 32-bit word | Receives the first associated address value, but only when the first metadata output is also supplied on the normal record path. |
| First metadata output | Optional address of a writable 32-bit word | Receives the first associated metadata value, subject to the same pairing requirement. |
| Second pointer output | Optional address of a writable 32-bit word | Receives the second associated address value. Its absence also controls conditional cleanup behavior. |
| Second metadata output | Optional address of a writable 32-bit word | Receives second metadata only when the second pointer output is supplied on the normal record path. |

Controls are tested for equality to zero. Values other than zero are not otherwise distinguished.

Address values and metadata occupy 32-bit words. Although some source-level storage is presented as signed integer storage, the function transfers pointer and metadata words without interpreting their numerical values, except that a stored pointer word of zero means “absent.”

### Return value

The return value is a 32-bit word:

- `0x44` when both controls are nonzero.
- Zero when the two stored indices are equal.
- Otherwise, the selected record’s result word as captured before consuming mutations or output writes.

A selected record may itself contain a zero result. Therefore, return value zero alone does not distinguish an unavailable record from an available record whose result word is zero.

### Sentinel address values

Two distinct fixed address values are observable:

- **Sentinel A:** used for both pointer outputs in the both-nonzero branch and for an absent second associated pointer.
- **Sentinel B:** used for an absent first associated pointer on the normal record path.

Their contents, lengths, mutability, and lifetime are not established. In particular, they are not established to be empty strings, allocated buffers, or interchangeable values.

### Preconditions

Every nonnull output address that is actually written must permit a 32-bit write.

The context returned by F-035afcc6e793 must support every context access reached by the selected branch. The function performs no explicit context-validity, index-range, or storage-size check.

For ordinary sixteen-slot operation, stored indices must produce a valid selected slot. Behavior outside that condition is not converted into an error response.

## Behavior

### 1. Context acquisition

The function first calls F-035afcc6e793 without explicit arguments and retains its return value as the context base.

This call occurs on every path, including the both-nonzero special response. Its side effects therefore precede all output writes and all context reads performed directly by F-c60614d799b0.

The special-response path does not subsequently dereference the returned context.

### 2. Both controls nonzero

When both controls are nonzero, the function performs these conditional writes in this order:

1. If the first pointer output is supplied, write Sentinel A.
2. If the first metadata output is supplied, write zero.
3. If the second pointer output is supplied, write Sentinel A.
4. If the second metadata output is supplied, write zero.

It then returns `0x44`.

Each output is independent on this path. For example, a supplied metadata output is written even when its corresponding pointer output is absent.

No direct indexed-context access or conditional cleanup call occurs on this path. This does not imply that context acquisition itself has no side effects.

### 3. Context layout and availability

On all remaining paths, the function reads:

1. A 32-bit index at context offset `0x148`.
2. A 32-bit index at context offset `0x144`.

These are called **index A** and **index B**, respectively.

If their raw 32-bit values are equal, the function returns zero immediately. It performs no output writes, record reads, consuming mutations, or conditional cleanup call on that path.

If they differ, a record is selected.

The accessed layout is:

| Context offset | Role |
|---|---|
| `0x004 + 4 × slot` | Result word |
| `0x044 + 4 × slot` | Second associated pointer word |
| `0x084 + 4 × slot` | Second metadata word |
| `0x0c4 + 4 × slot` | First associated pointer word |
| `0x104 + 4 × slot` | First metadata word |
| `0x144` | Index B |
| `0x148` | Index A |

For slot values zero through fifteen, each group is a sixteen-element region of 32-bit words. This describes the directly accessed storage, not an independently established allocation boundary.

### 4. Record selection and arithmetic

When the second control is nonzero, the selected slot is index B without reduction or validation. Because the both-nonzero case has already returned, the first control is necessarily zero on this path.

When the second control is zero:

- Index A is incremented using 32-bit unsigned arithmetic.
- The incremented word is interpreted as a signed 32-bit value.
- Its signed remainder upon division by sixteen determines the selected slot representation.

For valid indices zero through fifteen, this selects the next slot and wraps fifteen to zero.

This is not unconditionally equivalent to taking an unsigned value modulo sixteen. If the incremented word has its high bit set, its signed interpretation is negative. Signed remainder can then be negative, with its 32-bit representation subsequently used in address arithmetic. No explicit rejection of such an index is present.

The indexing arithmetic uses a four-byte stride and 32-bit address calculations. The function does not provide a safe out-of-range fallback.

### 5. Capturing the result and consuming the record

After selecting the slot, the function reads its result word and retains that value for the eventual return.

If the first control is nonzero, it then:

1. Writes the selected slot value to index A at context offset `0x148`.
2. Writes zero to the selected result word.

These mutations occur before either output pair is processed.

Consequently, a consuming call returns the captured result even though the stored result has already been cleared. Output aliases or later dependency side effects do not cause a fresh result read.

No corresponding write to index B is present.

### 6. First pointer/metadata pair

The first pair is processed only if both of its output addresses are nonnull. If either is absent, neither output is written and the first associated pointer and metadata are not read for this pair.

When both are supplied:

- If the selected first associated pointer is zero, write Sentinel B to the first pointer output, then write zero to the first metadata output.
- Otherwise, write the selected first associated pointer to the first pointer output, then read and write the selected first metadata word.

On the nonzero branch, the pointer field is read for the zero test and read again for the output assignment. The metadata read follows the pointer-output write.

This function does not explicitly clear either first-pair field.

### 7. Second pointer/metadata pair and conditional cleanup

Behavior depends first on whether the second pointer output is supplied.

**Second pointer output absent, first control zero:**

No second-pair output, second-pair context access, or cleanup mutation occurs. Supplying only the second metadata output does not change this.

**Second pointer output absent, first control nonzero:**

The function tests the selected second associated pointer.

- If it is nonzero, the function reads the selected second metadata word.
- If that metadata has bit zero set, it calls F-5990a26eaaa3 without explicit arguments, then writes zero to the selected second pointer field.
- Regardless of whether the pointer was zero or the dependency was called, it finally writes zero to the selected second metadata field.

A nonzero pointer with bit zero clear is left stored, while its metadata is cleared.

**Second pointer output supplied:**

- If the selected second associated pointer is zero, write Sentinel A to the second pointer output. If the second metadata output is also supplied, write zero there.
- Otherwise, write the selected second associated pointer to the second pointer output. If the second metadata output is also supplied, read and write the selected second metadata.

On the nonzero branch, the pointer field is read for the zero test and again for the output assignment. The metadata read, when requested, occurs after the pointer-output write.

Supplying the second pointer output suppresses the cleanup branch, including during consuming calls. This path does not explicitly clear the selected second pointer or metadata.

The function then returns the previously captured result word.

## Side effects

### Direct context changes

Outside output aliasing and dependency side effects, direct context mutations are limited to:

- Updating index A during consumption.
- Clearing the selected result during consumption.
- Clearing selected second metadata when consuming without a second pointer output.
- Clearing the selected second pointer after the conditional call to F-5990a26eaaa3.

A non-consuming call has no direct context writes, but may write outputs and always calls F-035afcc6e793.

### Output aliasing and access order

There is no visible alias restriction or defensive copy of the entire record. Output addresses may coincide with one another or with context storage, subject to accessibility.

The stated write order therefore matters:

- In the special response, later output writes can overwrite earlier ones.
- In the first normal pair, the pointer-output write precedes the metadata read on the nonzero branch.
- First-pair writes occur before second-pair reads.
- In the second normal pair, its pointer-output write precedes its metadata read on the nonzero branch.
- Consuming context writes occur before all normal output processing.

For example, if the first pointer output aliases the selected first metadata field, its pointer write changes the word subsequently read as metadata.

Examples assuming separate output storage do not define behavior for aliased storage.

### Ownership and dependency effects

Returning a stored address does not, by itself, establish transfer of ownership or permission to modify or release the referenced object.

The call to F-5990a26eaaa3 is conditioned on a nonzero second pointer, metadata bit zero being set, consumption being enabled, and the second pointer output being absent. Those conditions suggest cleanup intent, but do not establish what the dependency releases or changes. No explicit argument identifying the pointer is visible.

No guarantee is made that either dependency preserves globals, outputs, or context storage. After F-5990a26eaaa3 returns, this function directly clears the selected second pointer and metadata using the already selected addresses.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, outputs use distinct valid storage, context indices are valid, and dependency effects do not interfere with the described accesses.

1. **Both controls nonzero.**  
   With all outputs supplied, they receive Sentinel A, zero, Sentinel A, and zero in that order. The return is `0x44`. Context acquisition still occurs.

2. **Special-response metadata supplied alone.**  
   With both controls nonzero and only the first metadata output supplied, that output becomes zero. The normal-path pairing restriction does not apply.

3. **Equal indices.**  
   With both stored indices equal and the controls not both nonzero, the return is zero. All supplied output words retain their previous values, absent changes made by context acquisition.

4. **Successor selection without consumption.**  
   With index A equal to five, index B equal to nine, and both controls zero, slot six is selected. Its result is returned, while this function does not update index A or clear the result.

5. **Wraparound consumption.**  
   With index A equal to fifteen, index B equal to three, first control nonzero, and second control zero, slot zero is selected. Index A becomes zero and slot zero’s result is cleared before outputs are processed. The original result is returned.

6. **Selection through index B.**  
   With index A equal to two, index B equal to seven, first control zero, and second control nonzero, slot seven is selected directly. The function does not consume it.

7. **Incomplete first output pair.**  
   On a selected-record path, supplying only the first pointer output leaves it unchanged. Supplying only the first metadata output likewise leaves it unchanged.

8. **Absent associated pointers.**  
   With both output pairs fully supplied and both stored associated pointers zero, the first pair receives Sentinel B and zero; the second receives Sentinel A and zero. Stored metadata does not replace either zero output.

9. **Conditional cleanup call.**  
   During consumption without a second pointer output, a nonzero second pointer and second metadata equal to three cause one call to F-5990a26eaaa3. After that call returns, the selected second pointer and metadata are explicitly zeroed.

10. **Unrequested pointer without the low metadata bit.**  
    Under the same conditions but with metadata equal to two, the dependency is not called. The second pointer remains stored, and its metadata becomes zero.

11. **Requested second pointer during consumption.**  
    Supplying the second pointer output suppresses conditional cleanup. The pointer is returned, and metadata is returned if requested. Consumption still updates index A and clears the result.

12. **Aliased special-response outputs.**  
    If all four output addresses identify the same word and both controls are nonzero, the final word is zero because the fourth write follows the two sentinel writes.
