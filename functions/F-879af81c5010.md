# F-879af81c5010

## Purpose

F-879af81c5010 repeatedly transfers an item, updates descriptor bookkeeping, and consumes records from a pending chain. Consuming a record supplies the next item and advances a descriptor index. A zero transfer mode suppresses transfers after the initial pass but does not suppress record consumption or bookkeeping.

The only visible return path occurs when a pending-head read yields zero. That path conditionally invokes one terminal dependency, unconditionally invokes another, and returns a 32-bit zero if control returns normally.

A queue service or circular-storage operation is inferred intent, not an established external API. The supplied representation has unexplained incoming execution state and an initial descriptor calculation that can produce zero without preventing subsequent descriptor accesses. This contract preserves those limitations.

### Memory layouts

All offsets are in bytes. Address-bearing fields are represented as 32-bit words. These object names identify access roles; they do **not** establish separate allocations, non-overlap, ownership, or external type definitions.

The first state object contains a byte at +1 and a 32-bit value at +8. The latter participates both in terminal selection and in conditional record relinking. The second state object contains 32-bit values at +8 and +12.

### Access and arithmetic preconditions

Every actual access requires appropriately readable or writable storage for its width. No explicit bounds, null, alignment, capacity, or chain-integrity checks are visible.

The descriptor address is constructed from the initial numeric input multiplied by 4,194,304. The representation uses 32-bit integers and addresses but does not establish portable signed-overflow or pointer-construction semantics. Under a 32-bit wrapping interpretation, only the low 32 bits survive, and different numeric inputs can produce the same descriptor address, including zero. That interpretation is conditional.

Counter increments, index increments, destination calculations, and address offsets have the same unresolved overflow and address-validity constraints. The maximum comparison is explicitly unsigned. Wrap detection for the index is equality-only.

No non-aliasing guarantee is supplied. Unless an example expressly assumes otherwise, overlapping objects can make an earlier write affect a later read. Dependency calls can also mutate reachable state; later field reads are not entry-time snapshots.

## Behavior

### Initial transfer

The first branch tests whether the calculated descriptor address is zero. It does not first test whether the transfer mode equals one.

**Zero descriptor address:** read one byte directly from the initial item address and write it at the initial numeric input plus the incoming slot index. Bookkeeping follows without a null rejection. Consequently, this is not an established safe null case: descriptor accesses through the zero address are subsequently attempted.

**Nonzero descriptor address:**

- Mode two: read the descriptor backing address and obtain the payload address from item +16; transfer a 16-bit value from the payload to backing storage plus twice the incoming index.
- Mode four: use the corresponding 32-bit transfer and four times the index.
- Every other mode, including zero and one: call F-2489d48d501c with two visible argument values: backing storage plus mode times index, and the 32-bit value read from item +16.

For direct transfers, the payload value is read before the destination value is written. The representation does not establish a complete order between independent address-producing reads within one expression.

The F-2489d48d501c call does not establish copying semantics, a transfer length, overlap behavior, or ownership effects. In particular, mode zero does not establish that this initial call has no effect.

### Bookkeeping pass

After a transfer, and on each transfer-suppressed continuation, the routine:

1. Reads descriptor +44, increments it, and writes the result there.
2. Reads descriptor +16 as the count sample.
3. Reads descriptor +48.
4. If the maximum is smaller than the count sample under unsigned 32-bit comparison, writes the sample to +48.
5. If the count sample equals one, reads descriptor +32. When that field is nonzero, calls F-6ad030b1b8cc.
6. Reads descriptor +20 as the pending-head address.

The maximum comparison uses the count sampled before record consumption. It does not resample the count after a dependency or after the subsequent increment.

F-6ad030b1b8cc precedes the pending-head read. Its effects are unknown, so the pending head is whatever that later read observes, not necessarily the value present before the call.

### Empty pending chain and return

When the pending-head read yields zero, the routine selects whether to call F-unmapped-01:

1. Read first-state +8.
2. If nonzero, call F-unmapped-01 with that value.
3. Otherwise, read second-state +8 and then second-state +12.
   - If they differ, call F-unmapped-01 with the sampled value from second-state +8.
   - If they are equal, read the byte at first-state +1. Call F-unmapped-01 with its zero-extended value only when the byte is nonzero.

F-unmapped-01 can therefore receive zero: second-state +8 may be zero while second-state +12 is nonzero.

The second state object is not consulted on the branch where first-state +8 is nonzero. The byte at first-state +1 is consulted only when first-state +8 is zero and the two second-state samples are equal.

After the conditional call, or after deciding not to make it, the routine calls F-unmapped-02. It returns zero if that call returns normally.

### Removing a pending record

For a nonzero pending head, that sampled address identifies the current record. The removal sequence distinguishes two separate reads of current-record +0:

1. Read current-record +0 and retain that next-address sample.
2. Write that sample to descriptor +20.
3. Test the retained sample for nonzero.
4. If the retained sample is nonzero, **read current-record +0 again**.
5. Write the address of descriptor +20 to the location four bytes beyond the address obtained by this second read.

The condition in step 3 does not test the second read. The destination in step 5 does not necessarily use the retained next-address sample.

Without a non-overlap guarantee, the descriptor-head write can affect storage subsequently read as current-record +0. The fresh address is not separately checked for zero or validity. Even where the two reads ordinarily agree, a contract must preserve their distinction and order.

The current record’s own +4 field is not explicitly cleared.

### Status update and conditional relinking

After the removal sequence, the routine reads current-record +28, clears bit 7 using the 32-bit mask 0xFFFFFF7F, and writes the result back.

The relinking decision uses that computed result, not a fresh status read. If the entire result is zero:

1. Read first-state +8.
2. Write the sampled value to current-record +0.
3. Write the current-record address to first-state +8.

Other status bits prevent this relinking when they remain set. The condition is not simply whether bit 7 was originally set.

These are ordered memory operations, not an atomic list operation. Their effects under overlapping storage follow those operations rather than an assumed disjoint-object model.

### Record dependency and next item

The routine next reads current-record +8.

- If zero, it neither calls F-f46257aeeddc nor explicitly replaces that field.
- If nonzero, it calls F-f46257aeeddc and, after normal return, writes the incoming replacement value to current-record +8.

It then reads current-record +16 as an intermediary address and reads intermediary +4 as the next item address. These reads occur after the optional call and replacement write. They must not be treated as values captured before them.

The routine writes the replacement value to next-item +4.

### Count and index advancement

After the item-field write:

1. Read descriptor +16 again, increment the observed value, and write the result to +16.
2. Read descriptor +12, increment that observed value, and write the result to +12.
3. Compare that computed incremented value with the incoming wrap limit.
4. If equal, write the replacement value to descriptor +12.
5. Read descriptor +12 again to obtain the index for subsequent transfers.

The count increment does not use the earlier bookkeeping sample. The index increment does not use the incoming slot index or a value sampled before record processing.

Consequently, dependency effects and overlapping-memory writes before these reads can change the values incremented. An earlier observed count or index is insufficient to predict the later increment without an additional preservation assumption.

The wrap comparison uses the computed increment, not a fresh read. An increment greater than the limit does not trigger replacement merely because it exceeds the limit.

### Continuation

If the mode is zero, execution immediately performs another bookkeeping pass. It does not transfer the newly obtained item between these passes.

For nonzero modes, another transfer occurs:

- Mode one: first read the payload address from next-item +16, then read the descriptor backing address. Read a byte from that payload and write it at backing storage plus the current index.
- Modes two and four: perform the corresponding indirect 16-bit or 32-bit transfer.
- Other nonzero modes: call F-2489d48d501c as described above.

Thus mode one is asymmetric: an initial nonzero-descriptor pass calls F-2489d48d501c, while subsequent passes perform an indirect byte transfer.

## Side effects

Established writes include destination data, descriptor bookkeeping and head fields, successor linkage, record status and conditional relinking, conditional replacement of record +8, and replacement of next-item +4.

The writes are not transactional. Earlier operations precede later faults or calls, and no rollback is shown. A later write through an overlapping address or an unknown dependency can overwrite a previously written value; a specified store does not guarantee that value remains the final memory contents.

Removing or relinking a record does not establish deallocation or ownership transfer. Replacing item or record fields does not establish resource release. Allocation, ownership, lifetime, synchronization, and reentrancy rules remain documented_only.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Accesses must be valid, calls mentioned as returning must return normally, and no concurrent mutation is assumed. Object-role names alone do not imply non-overlap.

1. **Initial 16-bit transfer and termination.** With a nonzero descriptor and mode two, the initial direct transfer reads a 16-bit payload value and writes it to the calculated destination. If the later pending-head read yields zero, terminal selection follows. A zero return requires the selected dependencies to return.

2. **Maximum sample versus later increment.** If bookkeeping reads count seven and maximum five, it writes seven to the maximum. If the *later count-increment read* also yields seven, it writes eight to the count. That second condition cannot be derived from the first sample: F-f46257aeeddc, other intervening operations, or overlapping storage may change the count. Absent later interfering writes, eight is considered for maximum tracking only on a subsequent pass.

3. **Fresh successor-address read.** If the first current-record +0 read yields a nonzero address, descriptor +20 is written before current-record +0 is read again. The linkage store uses the second address plus four. Only with appropriate storage-preservation and non-overlap assumptions may both addresses be treated as equal. If the second address is zero, the retained nonzero sample still selects the linkage store; there is no second null check.

4. **Status condition.** A sampled status of 128 produces a zero masked result and selects relinking. A sampled status of 129 produces one and does not select relinking. These decisions use the computed result even if an overlapping write changes stored status.

5. **Replacement is not necessarily zero.** With replacement value nine and a nonzero current-record +8 sample, a returning F-f46257aeeddc call is followed by a store of nine to that field. This does not assert that later overlapping writes preserve nine.

6. **Exact wrap at the actual index read.** If the index-increment read observes three, the limit is four, and the replacement value is nine, the routine writes four and then nine to descriptor +12. This criterion does not infer three from an earlier index observation. If the incremented value is five instead, limit four does not select replacement. Under valid non-overlapping ordinary storage and no concurrent mutation, the subsequent index read observes the last index store.

7. **Zero terminal argument.** If first-state +8 reads zero, second-state +8 reads zero, and second-state +12 reads one, F-unmapped-01 receives zero. The first-state byte is not read on this branch.

8. **Zero mode continuation.** For an initial nonzero descriptor and mode zero, F-2489d48d501c is called initially. Each subsequently consumed record leads directly to bookkeeping without another transfer.

9. **Mode-one asymmetry.** For an initial nonzero descriptor and mode one, the initial transfer calls F-2489d48d501c. After a record supplies another item, the next transfer reads its payload address at +16 and performs a byte transfer.

10. **Zero descriptor is not rejection.** If descriptor construction yields zero, the initial byte-write branch is selected and descriptor bookkeeping is subsequently attempted. No graceful null rejection or early error result is established.
