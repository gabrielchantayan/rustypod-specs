# F-2929739c9813

## Purpose

F-2929739c9813 conditionally processes a mutable object, rejects it against up to six enabled four-component tests, prepares additional data, updates selected output slots, optionally submits a calculated scalar, and dispatches a final indirect operation.

This is a behavioral contract derived from the supplied static evidence. The apparent geometric and fixed-point roles are inferred intent, not established domain semantics. In particular, the four-component tests resemble clipping tests, but their operands and helper are not independently specified.

The routine has no explicit return value. Its observable results are memory accesses, calls, mutations performed by dependencies, its own output-slot writes, and whether processing terminates before final dispatch.

## Interface

### Inputs

The routine receives four arguments:

1. **Object address:** a 32-bit address used as the base of a mutable memory layout.
2. **Context word:** an opaque 32-bit value forwarded to an optional callback and to F-148f046b5d07.
3. **Unused word:** a 32-bit argument with no established read or forwarding in this routine.
4. **Initial callback word:** a 32-bit value copied into temporary writable storage before any callback selection.

The object address must support the accesses described below. There is no null check, object-size check, index-bound check, or indirect-target validation.

The temporary callback word is passed by address only to the entry callback. The static evidence does not establish permission to retain that address after the callback returns.

### Integer interpretation

Signed comparisons use 32-bit signed interpretation. Masks and bit extraction use 32-bit words. The four-component helper produces a 64-bit result, and the explicit scalar multiplications are signed 32-by-32-bit multiplications yielding 64-bit products.

For describing extraction, define \(E(x)\) as the signed 32-bit interpretation of bits 16 through 47 of a 64-bit quantity \(x\). This is a bit-selection operation: it discards the bottom 16 bits and all bits above bit 47. It is not saturating conversion.

## Behavior

### 1. Entry callback selection

The routine first copies the fourth argument into temporary 32-bit storage.

It then reads the enable word at `0x208`:

- If zero, it reads the word at `0x8E0`.
- If nonzero, it resolves and invokes the entry callback.

For entry callback resolution:

- Interpret the word at `0x204` as signed and shift it right arithmetically by one.
- Add that adjustment to the object address plus `0x1F0` to obtain the callback receiver.
- If bit 0 of the adjustment word is clear, use the target stored at `0x200`.
- If bit 0 is set, read a table pointer from the adjusted receiver, then obtain the target from that table at the byte offset formed by clearing the lowest two bits of the word at `0x200`.

The callback receives, in order, the adjusted receiver, the context word, and the address of the temporary callback word.

After the callback, the routine reads that temporary word. However, neither the value read from `0x8E0` nor the callback’s resulting temporary value has an established downstream effect on this routine’s decisions or final arguments. The callback itself remains observable and may affect subsequent processing through memory or other state changes.

There is no established validation of the receiver adjustment, table, offset, or target.

### 2. Initial preparation and processing gate

Next, F-148f046b5d07 is called with the object address and context word.

Only after that call returns does the routine inspect `0xBE4`. If any bit selected by mask `0xFC` is set, it returns immediately.

Consequently, bits 2–7 inhibit every later stage, but do not inhibit the entry callback or F-148f046b5d07. Bits 0 and 1, and bits above bit 7, do not independently trigger this gate.

The flag read observes the object after the preparation call. No preservation of flags by that dependency is assumed.

### 3. Optional six-record rejection pass

If the processing gate permits continuation, the routine reads the test mask at `0x2F4`.

A zero value skips the rejection pass. Otherwise, records 0 through 5 are considered in ascending order. Before each record’s computation, the corresponding mask bit is tested by reading the mask again. Thus, this is not necessarily a snapshot of the mask taken before the pass.

For each selected record, the routine calls F-8b06a3108459 four times, in this component order:

1. Working word at `0xB60` and record word at `0x2A0`.
2. Working word at `0xB5C` and record word at `0x29C`.
3. Working word at `0xB58` and record word at `0x298`.
4. Working word at `0xB54` and record word at `0x294`.

The record offsets above increase by `0x10` for each subsequent record.

Each component’s operands are obtained for its own call; the routine does not establish an immutable snapshot of all eight input words before calling the helper. Changes made by an earlier helper invocation can therefore affect later reads.

The four 64-bit results are summed with the bias `0x8000`. The routine applies \(E\) to the resulting 64-bit quantity and tests that extracted value as signed:

- Negative: return immediately.
- Zero or positive: continue to the next selected record.

This is not simply a test of the full 64-bit sum’s sign. Overflow or large values can make the extracted 32-bit sign differ from that of an unbounded mathematical sum.

Mask bits above bit 5 do not select additional records. A nonzero mask containing only higher bits enters the six-position pass but makes no component-helper calls.

### 4. Working-block preparation

After every selected record has passed, F-0a29566d2e48 is called with:

- The object address.
- The address of the working block at `0xB54`.

Subsequent stages observe memory after this call. The contract does not assume the helper preserves metadata, flags, working words, or other object fields.

### 5. First indexed-output path

The routine reads the metadata pointer at `0xA90`, then reads the signed index at metadata offset `+4`.

A negative index skips this entire path.

For a nonnegative index, the one-byte selector at `0x8FD` determines the path.

**Zero selector:**

- The source passed to F-02a35f55d6ef is the object address plus `0xB90`.
- Its second argument is the output-slot address calculated from the already-read index.

**Nonzero selector:**

- Inspect bit 0 of `0xBE4`.
- If that bit is clear, resolve and invoke the indexed-output callback.
- After that callback returns, read the current word at `0xBE4`, set bit 0, and write the resulting word back.
- Re-read the metadata pointer and the signed index at metadata offset `+4`.
- Call F-02a35f55d6ef with source address `object + 0xBA0` and the output-slot address calculated from this re-read index.

The indexed-output callback uses the same adjustment-and-dispatch encoding pattern as the entry callback, but with differences in location and arguments:

- The adjustment word is at `0xA98`.
- The receiver anchor is the object address itself, not `object + 0x1F0`.
- The direct target or encoded table offset is at `0xA94`.
- Its arguments are the adjusted receiver, the working-block address, and the integer value 1.

The index re-read on the nonzero-selector path is not checked again for negativity. A callback that changes it to a negative value can therefore cause a slot address below `object + 0xBC0`.

F-02a35f55d6ef’s implementation is unavailable. Its name or call shape does not establish copy direction, byte count, ownership transfer, or exact writes.

### 6. Second indexed-output path

The routine next reads the current metadata pointer and tests the signed index at metadata offset `+8`.

If that index is negative, this path is skipped.

Otherwise:

1. Read the signed word at `0xB5C`.
2. If negative, apply 32-bit negation; otherwise retain it.
3. Call F-96ada6d600f3 with the object address and that resulting 32-bit value.
4. Re-read the metadata pointer and its index at `+8`.
5. Store the helper’s 32-bit return value directly into the slot selected by the re-read index.

The final index is neither checked again for negativity nor bounded.

The negation must not be specified as an always-representable mathematical absolute value. For input `0x80000000`, 32-bit negation retains the same bit pattern; a wider positive value `2147483648` is not established.

### 7. Optional scalar processing

If the byte at `0x8FC` is nonzero, the routine performs additional calculation and calls F-b19479256fec.

It again reads `0xB5C` and applies the same conditional 32-bit negation. This read occurs after the second indexed-output path; it need not match the value used there.

Let the resulting signed value be \(m\). The routine obtains:

- A signed 64-bit product of \(m\) and the signed word at `0x8F4`.
- The signed additive word at `0x8F0`.
- The extraction \(E(m \times m)\), supplied as the second argument to F-e713aa9f4f3b, whose first argument is the word at `0x8F8`.

F-b19479256fec receives the 32-bit sum of:

- The extracted first product.
- The additive word.
- The return value of F-e713aa9f4f3b.

No saturation, range check, or overflow reporting is present. The intended scalar meaning and the treatment of signed-overflow cases beyond the observed 32-bit operations remain undocumented.

### 8. Final dispatch

If processing has not returned at either earlier rejection point, the routine performs an indirect call using the current receiver pointer at `0xA8C`.

It reads that receiver’s table pointer, obtains the target at table byte offset `0x4C`, and calls the target with:

1. The receiver.
2. The working-block address.

There is no final-dispatch null check and no explicit status returned to the caller.

## Side effects

Directly established mutations are:

- Creation and possible callback mutation of the temporary entry word.
- Setting bit 0 of `0xBE4` after the indexed-output callback returns.
- Writing the 32-bit result of F-96ada6d600f3 into an indexed output slot.

Setting bit 0 uses the flag word read after the callback, retaining its other then-current bits. It is not established as an atomic operation.

All dependencies can have additional effects not described by the supplied evidence. In particular, passing an object or interior address does not establish whether a dependency reads, writes, retains, releases, or invalidates it.

No allocation, deallocation, reference-count operation, or ownership transfer is directly visible here. That absence must not be extended to the dependencies.

The source establishes phase and call ordering. It does not establish a total order between independent argument-expression reads within a single call.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

1. **Processing gate:** If F-148f046b5d07 leaves `0xBE4` equal to `0x04`, the routine returns after that call. No rejection helper, working-block preparation, indexed processing, scalar submission, or final dispatch follows.

2. **Non-gating flags:** If the flags are `0x03`, the processing gate alone does not reject the object.

3. **No enabled low records:** With mask `0x80000000`, no F-8b06a3108459 call occurs. Processing advances to F-0a29566d2e48.

4. **Rounding boundary:** If a selected record’s four helper results sum to `-32768`, adding `0x8000` yields zero and the record passes. If they sum to `-32769`, the biased value is `-1`, its extraction is negative, and processing returns.

5. **Early rejection:** If record zero rejects, no later record is evaluated, and F-0a29566d2e48 is not called.

6. **Callback-completed flag:** With a nonnegative first index, nonzero selector, and bit 0 already set, the indexed-output callback is skipped. F-02a35f55d6ef still receives the `0xBA0` source and a slot based on a newly read index.

7. **Changed first index:** If the indexed-output callback changes metadata index `+4` from 2 to 5, the subsequent slot argument is `object + 0xBD4`, assuming the metadata remains valid. The original index does not determine that address.

8. **Changed second index:** If F-96ada6d600f3 changes metadata index `+8`, its result is stored using the post-call index, not necessarily the one that passed the initial nonnegative check.

9. **Scalar disabled:** A zero byte at `0x8FC` suppresses both scalar-related dependency calls, but does not suppress final dispatch.
