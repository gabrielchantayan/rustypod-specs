# F-aa9261f70de5

## Purpose

F-aa9261f70de5 obtains a link-slot address from a dependency, reads the slot, and conditionally replaces a nonzero node reference with that node’s successor. On the nonempty path it returns a 32-bit word read from the selected node after the link replacement. On the empty path it returns zero and increments a separate context field.

The nonempty path also invokes a dependency, increments a success-associated field, decrements a count-like field, and conditionally invokes two further dependencies.

“Node,” “link,” “counter,” and “maintenance” describe access patterns or inferred roles. They do not establish a particular container abstraction, ownership policy, release operation, or resizing algorithm.

The selection dependency receives the address of a local auxiliary copy. Its returned link-slot address is not established to be distinct from that address. Consequently, a dependency modification of the auxiliary copy can affect subsequent behavior through the returned address.

### Selected link slot and node

F-1074569f7759 returns an address that is immediately dereferenced as a 32-bit link slot. There is no visible null-address or validity check before this dereference.

The slot may be external storage, context storage, the local auxiliary copy, or another aliased location compatible with the reached accesses. The body does not establish disjointness.

A nonzero slot value is interpreted as a node address. The following node words are accessed:

| Node offset | Width | Use |
|---|---:|---|
| 0 | 32 bits | Read as the eventual return value, after replacing the selected link. |
| 4 | 32 bits | Read as the successor and written into the selected link slot. |

These accesses do not establish a complete node layout.

### Output

The function returns one 32-bit value:

- Zero when the first read through the selected link-slot address yields zero.
- Otherwise, the node’s first word as observed after the successor has been written into the selected slot.

A nonempty selection can return zero. The result alone therefore does not distinguish an empty selection from a nonempty selection whose captured return word is zero.

### Preconditions

Normal completion requires accessible memory for every read and write reached on the selected path, supported address calculations, and dependency behavior compatible with continued execution.

In particular, the selected slot must be readable. On the nonempty path it must also be writable, and the selected node’s two accessed words must be readable when used.

No visible validation enforces these requirements. No recovery protocol is shown for invalid memory, unsupported arithmetic, or a dependency that fails to return normally.

## Behavior

### Initialization and selection

The first visible state change is a 32-bit zero write at context offset 0x5C.

The auxiliary input is then copied into local 32-bit storage. F-1074569f7759 is called with:

1. The context address.
2. The selection value.
3. The address of that local auxiliary copy.

The function subsequently reads a 32-bit word through the returned address. That word determines whether the empty or nonempty path is taken and, on the nonempty path, supplies the node address.

There is no subsequent direct read explicitly naming the auxiliary copy. This does **not** establish that modifications to the copy are unused. F-1074569f7759 receives its address and could return that same address as the selected link slot. In that case:

- The immediate slot read observes the auxiliary copy’s value after the dependency returns.
- A dependency-written zero selects the empty path.
- A dependency-written nonzero node address selects the nonempty path.
- On the nonempty path, the later successor write targets the auxiliary copy itself.

Other valid aliasing arrangements can likewise make the local storage relevant to subsequent indirect accesses. The body does not exclude them.

The initial zero write at context offset 0x5C does not guarantee that the field remains zero. Dependencies or subsequent aliased writes may change it.

### Empty selection

If the first selected-slot read yields zero, the function:

- Reads the current 32-bit value at context offset 0x4C.
- Adds one and writes the result to that field.
- Returns zero.

There are no visible calls on this path to F-5990a26eaaa3, F-d7be9cfb4000, or F-f02b062450f6.

There is no explicit selected-link replacement or explicit update of context offsets 0x48 and 0x24 on this path. This does not establish that those locations are unchanged overall: F-1074569f7759 may have modified them, and storage aliasing is not excluded.

If the selected slot is the local auxiliary copy, its post-dependency value—not necessarily the original auxiliary input—determines entry to this path.

### Nonempty selection

When the first selected-slot read yields a nonzero node address, the visible order is:

1. Read the node’s successor word at node offset 4.
2. Write that successor into the selected link slot.
3. Read the node’s first word and retain it as the eventual return value.
4. Call F-5990a26eaaa3, with no explicit arguments shown.
5. Read context offset 0x48, add one, and write the result back.
6. Read context offset 0x24, subtract one, retain the computed value, and write it back.
7. Evaluate the conditional maintenance behavior.
8. Return the retained node word if all intervening operations complete normally.

The link replacement precedes the node-value read. For ordinary nonoverlapping storage, this removes the selected node from the selected chain and captures its original first word. The original-word interpretation requires a suitable non-aliasing condition.

For example, if the selected link slot overlaps the node’s first word, the successor write changes the word subsequently captured for return. The function therefore does not unconditionally return the node’s pre-update first word.

If the selected slot is the local auxiliary copy, the successor write updates that local copy. This need not change a persistent external chain head. “Detachment” is an inferred interpretation for a conventional external link slot, not an unconditional guarantee about the dependency’s selection policy.

The counter increment and count decrement use values read after F-5990a26eaaa3 returns. They are not necessarily based on function-entry values.

There is no separate explicit write that clears or resets the node’s successor. Aliasing may nevertheless cause the selected-slot write or another reached write to affect node storage.

### Conditional maintenance

After storing the decremented count, the function reads context offset 0x0C as unsigned 32-bit data.

If that value is at most 16, neither F-d7be9cfb4000 nor F-f02b062450f6 is called.

If it is greater than 16:

- The retained decremented count is multiplied by 256.
- F-d7be9cfb4000 receives that product.
- Its result is interpreted as an unsigned 32-bit quantity.
- Context offset 0x20 is then read as unsigned 32-bit data.
- F-f02b062450f6 is called with the context address if the dependency result is less than or equal to the observed bound.

Equality triggers the final call.

The multiplication uses the retained decrement result. The body does not show a fresh read of context offset 0x24 to obtain the multiplication input.

The comparison bound at offset 0x20 is read after F-d7be9cfb4000 returns. A dependency modification to that field can therefore affect the decision. The qualifying value at offset 0x0C has already been read and is not visibly rechecked.

The eventual returned node word was captured before these calls. There is no visible later reread of that node word.

No rollback or retry is shown if an operation after link replacement fails to complete normally.

### Arithmetic boundaries

The counter updates, count decrement, and multiplication are expressed using signed 32-bit arithmetic. The two maintenance comparisons use unsigned 32-bit values.

For arithmetic that does not overflow signed 32-bit range:

- Each incremented counter must be below 2,147,483,647 immediately before its increment.
- The count must be above −2,147,483,648 immediately before its decrement.
- If multiplication is reached, the decremented count must be between −8,388,608 and 8,388,607 inclusive.

The multiplication factor is 256, applied to the decremented count. It is not division, a percentage computation, or multiplication of the original count.

No check excludes zero or negative counts. A count of zero becomes −1; if multiplication is reached, the argument is −256, which is representable as signed 32-bit arithmetic. The dependency’s interpretation of that argument is unknown.

Behavior outside the safe arithmetic ranges is documented_only. The supplied evidence does not establish wrapping, trapping, saturation, or another overflow policy.

## Side effects

### Direct writes

The body explicitly performs:

- A zero write to context offset 0x5C.
- Initialization of the local auxiliary copy.
- On the empty path, an incrementing write to context offset 0x4C.
- On the nonempty path, a successor write through the selected link-slot address.
- On the nonempty path, an incrementing write to context offset 0x48.
- On the nonempty path, a decrementing write to context offset 0x24.

The successor write can target the auxiliary copy if its address is returned as the link-slot address. It can target other overlapping storage when such aliasing is compatible with the required accesses.

No general non-aliasing invariant is established among context storage, selected-slot storage, node storage, and the address-exposed auxiliary copy. A write may consequently affect a later read.

### Dependency effects and ownership

Dependencies may have effects beyond the explicit operations listed above. No dependency is assumed to preserve context fields, globals, node contents, or ownership state.

Neither returning the first node word nor replacing the selected link establishes ownership transfer. The evidence does not determine whether the node remains allocated, is reused, is released, or remains reachable elsewhere.

The auxiliary copy has local lifetime. Returning its address as a slot permits indirect use during the remaining invocation; such use is not excluded by the body. There is no established contract authorizing use of that address after this function returns.

No locking, atomic update, synchronization guarantee, or reentrancy protection is visible.

## Acceptance examples

These are conditional consequences of the static evidence, not executed tests. Except for explicitly stated aliases or mutations, they assume valid nonoverlapping storage, arithmetic within range, normal dependency returns, and no additional dependency effects.

1. **Empty selected slot.**  
   F-1074569f7759 returns a readable slot containing zero. If context offset 0x4C contains 7 after the call, the function writes 8 there and returns zero. None of the three nonempty-path dependencies is called.

2. **Ordinary detachment without maintenance evaluation.**  
   The selected slot points to a node with first word 42 and a valid successor. Context offset 0x0C is 16 when inspected. The slot receives the successor, 42 is captured, F-5990a26eaaa3 is called, and the success-associated counter and count are updated. Both maintenance dependencies are skipped. The result is 42.

3. **Nonempty selection returning zero.**  
   The selected node’s first word is zero when read after link replacement. The nonempty-path operations occur, but the returned value is zero. The return value alone does not identify which branch ran.

4. **Equality triggers maintenance.**  
   The decremented count is 3, and offset 0x0C is greater than 16. F-d7be9cfb4000 receives 768. If it returns 100 and the subsequent read at offset 0x20 yields 100, F-f02b062450f6 is called.

5. **A greater result skips the final dependency.**  
   With the same qualifying condition at offset 0x0C, a result of 101 and a subsequently observed bound of 100 skip F-f02b062450f6.

6. **Dependency changes affect later counter reads.**  
   If F-5990a26eaaa3 leaves offsets 0x48 and 0x24 containing 20 and 9 respectively, the subsequent explicit writes are 21 and 8. Earlier values do not determine those writes.

7. **The selected slot aliases the node’s first word.**  
   A readable and writable slot coincides with the selected node’s first word, whose initial value identifies that node. The successor write changes that word before value capture. The captured return value is therefore the successor word, subject to all required accesses remaining valid.

8. **Auxiliary mutation selects the empty path.**  
   F-1074569f7759 changes the auxiliary copy to zero and returns its address. The immediate indirect read observes zero, even if the original auxiliary input was nonzero. The empty-path counter is incremented and the result is zero.

9. **Auxiliary mutation selects a node.**  
   F-1074569f7759 writes a valid nonzero node address into the auxiliary copy and returns its address. The function follows the nonempty path. It writes the node’s successor into the local auxiliary copy and captures the node’s first word afterward. No persistent external link replacement follows merely from this local-slot case.
