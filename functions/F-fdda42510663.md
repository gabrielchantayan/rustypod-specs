# F-fdda42510663

## Purpose

F-fdda42510663 conditionally invokes a preliminary helper, then dispatches an input through up to three indirect callbacks. A nonzero callback result ends processing immediately and becomes the function’s result. If no callback returns nonzero, the function returns zero.

The established behavior is conditional dispatch over numeric tags and object fields. Interpreting the first input as an object and the second as an event or message is inferred intent, not an established application-level meaning. The meanings of the tags, payload values, callbacks, and return codes are unknown.

A central behavioral requirement is that dispatch decisions use fields read at their respective stages. The function rereads the input’s tag and, where applicable, its payload after calls that may have changed them. It does not establish an immutable classification at entry.

## Behavior

### 1. Preliminary helper decision

The function first reads the input tag at offset `0x04`.

If the tag is not `0x16`, it skips this stage’s nested-record access and helper invocation.

If the tag is `0x16`, it reads the nested-record address from input offset `0x08`, then reads the nested discriminator at offset `0x04`. The supplied representation subtracts `0x2500` from that discriminator and compares the result with `2`.

For ordinary 32-bit arithmetic, the matching discriminator is `0x2502`. This comparison is not evidence that the entire surrounding discriminator range has special meaning.

On a match, the function:

1. Reads the object’s 32-bit field at offset `0x10C`.
2. Converts that value to the representation’s character type.
3. Calls F-4fd087f2325e with the object reference and converted value.

The full object field is read before conversion; it is not shown as a byte load. Character width, signedness, and out-of-range conversion behavior depend on the target language and ABI. Consequently, an exact numerical argument for arbitrary 32-bit field values is not established.

The helper’s return value is ignored. If the helper returns normally, execution continues without restoring any state it may have changed.

### 2. Optional first indirect callback

The function rereads the input tag at offset `0x04`. It does not reuse the preliminary stage’s tag value.

If this tag is `0x16`, it rereads the nested-record address and nested discriminator. If that discriminator is zero, the function:

1. Reads the object’s indirect-call table reference.
2. Resolves the entry at table offset `0x124`.
3. Calls that entry with the object reference and input-record address.

A nonzero result is returned immediately. A zero result allows execution to continue.

If the tag is not `0x16`, or the nested discriminator is not zero, this callback is skipped.

Thus, the preliminary helper can affect whether this callback runs by changing the input tag, nested address, or nested discriminator. It can also affect which target is invoked by changing the object’s table reference or table contents.

### 3. Mandatory selected indirect callback

Unless an earlier callback has returned nonzero, the function rereads the input tag.

For tag `0x16`, it rereads the nested address and discriminator. It then selects:

- The table entry at offset `0x10C` when the current tag is `0x16` and the current discriminator is `0x2A`.
- The table entry at offset `0x110` in every other case.

The function reads the object’s table reference, resolves the selected entry, and calls it with the object reference and input-record address.

Exactly one of these two entries is invoked on every execution that reaches this stage and can perform the required accesses and call.

A nonzero result is returned immediately. A zero result permits the final stage.

Selection reflects state at this stage, including changes made by an earlier dependency. For example, a callback selected by a zero discriminator at the preceding stage may change that discriminator to `0x2A`, causing this stage to use entry `0x10C`.

### 4. Optional final indirect callback

After the selected callback returns zero, the function rereads the input tag.

If the tag is `0x0F`, it reads:

1. The 32-bit field at input offset `0x08`.
2. The 32-bit object field at offset `0x50`.

If those values are equal, it resolves and invokes the indirect-call table entry at offset `0x0E0`, again passing the object reference and input-record address.

A nonzero result is returned unchanged. A zero result leads to the final zero return.

If the tag is not `0x0F`, neither comparison field is read by this stage. If the tag is `0x0F` but the values differ, the final callback is skipped.

### 5. Completion and arithmetic boundaries

If execution reaches the end, the function returns zero.

The comparisons operate on full 32-bit fields, except for the explicit character conversion used for F-4fd087f2325e. There is no visible narrowing of tags, discriminators, or callback results.

The subtraction in the preliminary stage does not justify imposing an additional input-range check. Exact overflow treatment outside ordinary defined arithmetic is not established by the supplied representation.

These are conditional behavioral examples, not executed tests. Assume valid storage, valid call targets, normal dependency returns, and no mutation except where stated.

1. **Ordinary unmatched tag.**  
   With a stable tag other than `0x16` or `0x0F`, the preliminary helper and entry `0x124` are skipped. Entry `0x110` is called. If it returns zero, the function returns zero without calling entry `0x0E0`.

2. **Preliminary helper match.**

3. **Zero discriminator with early termination.**  
   With tag `0x16` and discriminator zero, entry `0x124` runs. If it returns a nonzero value, that exact value is returned. Neither selected callback nor the final callback runs.

4. **Zero discriminator with continuation.**  
   Under the same input, if entry `0x124` returns zero without changing relevant state, entry `0x110` runs next. A zero result from that callback leads to zero because the unchanged tag is not `0x0F`.

5. **Special selected callback.**  
   With stable tag `0x16` and discriminator `0x2A`, entry `0x10C` runs instead of entry `0x110`. A nonzero result is propagated unchanged.

6. **Mutation changes callback selection.**  
   Begin with tag `0x16` and discriminator zero. If entry `0x124` changes the discriminator to `0x2A` and returns zero, the next stage selects entry `0x10C`.

7. **Matching final comparison.**  
   With stable tag `0x0F`, entry `0x110` runs first. If it returns zero and the input field at `0x08` equals the object field at `0x50`, entry `0x0E0` runs. Its result is the function’s result, including zero.

8. **Mismatching final comparison.**  
   Under the preceding conditions but with unequal comparison fields, entry `0x0E0` is skipped and the function returns zero.

9. **Mutation enables the final callback.**  
   If the selected callback changes the tag to `0x0F`, establishes equality between the comparison fields, and returns zero, entry `0x0E0` runs regardless of the original tag.

10. **Unused nested address.**  
    With a stable tag other than `0x16`, no nested-record dereference is performed. For tag `0x0F`, input offset `0x08` is instead read as the direct comparison value.
