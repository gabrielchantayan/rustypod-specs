# F-82b48670ff73

## Purpose

F-82b48670ff73 updates destination coordinates and processing flags for a selected collection of 48-byte records.

Its established behavior comprises dependency-based copying, paired placement, 64-unit grid rounding, a selector-specific symmetry adjustment, and a conditional pass over unresolved records. A flags-byte bit with mask `0x04` generally excludes a record from ordinary scan processing, but does not prevent writes through references or fixed-index adjustments.

**Inferred intent:** fit related coordinates to a grid while retaining selected spacing, alignment, and ordering relationships. Coordinate units and application-domain meanings are unknown.

This contract is based on static evidence only. No runtime tests have been performed.

## Interface

### Arguments and result

The routine receives:

- A 32-bit context address.
- A signed 32-bit selector.

It has no explicit return value or error result.

The selected descriptor location is the context address plus 28 times the selector. The routine accesses:

| Descriptor-relative offset | Width | Meaning in this contract |
|---|---:|---|
| `0x3C` | 32 bits | Extent used to calculate the collection byte span |
| `0x44` | 32 bits | Collection starting address |

The starting address is read first. The ending address is then calculated as the start plus 48 times the extent. These bounds are retained across dependency calls; later descriptor changes do not redirect traversal.

Scans advance by 48 bytes and continue while the current address is unsigned-less-than the saved ending address. This is an address-bounded traversal, not an independently checked iteration count.

The selector is not validated. Selector one enables the preliminary pass; selector zero enables the conditional symmetry adjustment. Other selectors still select descriptor fields and undergo ordinary processing.

### Record layout

| Record-relative offset | Width | Meaning in this contract |
|---|---:|---|
| `0x04` | 32 bits | Source coordinate |
| `0x08` | 32 bits | Destination coordinate |
| `0x0C` | 8 bits | Flags; `0x04` is the processed bit |
| `0x14` | 32 bits | Dependency reference |
| `0x18` | 32 bits | Partner reference |
| `0x1C` | 32 bits | Placement reference |

Nonzero references are interpreted as addresses. A dependency reference supplies a destination at offset `0x08`; partner and placement references expose the corresponding record fields.

There is no check that references point inside the collection, identify distinct objects, or form reciprocal relationships.

### Zero addresses and preconditions

Zero has two distinct roles:

- A zero dependency, partner, or placement reference means that reference is absent.
- A zero saved anchor address means no anchor exists.

The collection starting address is not required to be nonzero. If the execution environment permits accesses to the relevant storage at address zero, a scan can visit a record there. Such a record is nevertheless subject to explicit zero-address selection checks and cannot establish a persistent anchor by storing its address: storing zero leaves the anchor absent.

Successful execution requires accessible descriptor fields, all accessed record storage, and every dereferenced nonzero reference. Destination fields and flags that are written must be writable. Dependencies may impose additional unknown requirements.

No explicit checks cover invalid selectors, invalid storage, overflow, misalignment, overlapping objects, traversal wraparound, or dependency-induced invalidation.

### Arithmetic

Address representations and unsigned computations are 32-bit. Coordinate comparisons, width thresholds, and neighbor-coordinate comparisons are signed. Flags accesses are byte-wide.

For ordinary nonoverflowing coordinate calculations, define:

**R(x) = (x + 32), with the low six bits cleared in its 32-bit representation.**

Within the ordinary signed range, this rounds to a multiple of 64, with half-grid ties going toward the numerically higher grid point.

Midpoint calculations use a signed arithmetic right shift by one. Narrow-pair spacing uses signed division by two, truncating toward zero. These differ for negative odd values.

Signed overflow, including negating the most negative signed value during distance calculations, has no portable mathematical interpretation established here. Such cases are **documented_only**. The unresolved-record counter is also subject to unchecked signed increment.

## Behavior

### 1. Initialization and selector-one preliminary pass

Initially, the anchor is absent and the unresolved-no-partner counter is zero.

For selector one, records are scanned in increasing unsigned address order. A record whose processed bit is set is skipped. Otherwise, its dependency reference and partner reference are read.

Selection follows these rules:

- If the current dependency reference is nonzero, the current record is selected **only if its own address is nonzero**.
- If the current dependency reference is zero, a nonzero partner is selected when that partner’s dependency reference is nonzero.
- Otherwise, no copy occurs.

In particular, a current record at address zero with a nonzero dependency does not receive the preliminary copy. The routine does not fall back to selecting its partner in that case.

For a selected record, operations occur in this order:

1. Read the referenced dependency’s destination and copy it to the selected destination.
2. Freshly read the selected flags byte and write it with `0x04` set.
3. Consider the opposite record: the partner when the current record was selected, or the current record when the partner was selected.
4. If the opposite address is nonzero and its dependency reference is zero, call F-449adf349cf2 with the context and selector one, then freshly read and set the opposite record’s processed bit.
5. If the anchor is absent, assign the current scan address to it.

Anchor assignment uses the scan record, not necessarily the record that received the copy. Assigning scan address zero leaves the anchor absent. Likewise, when a partner is selected on behalf of a scan record at zero, the zero opposite address suppresses the optional call and opposite-record flag update.

### 2. Main scan

Every selector undergoes a new scan from the saved collection start.

The current flags byte is read first. Processed records are skipped. An unprocessed record with a zero partner increments the unresolved-no-partner counter; this branch makes no direct destination or flag change.

For a nonzero partner, paired placement requires both:

- The partner’s dependency reference is zero.
- The unsigned current address is no greater than the partner address.

The partner dependency is inspected before the address-order condition determines eligibility. There is no partner-processed check or distinctness check.

If paired placement is ineligible, F-449adf349cf2 is called with context and selector. The current flags byte is then freshly read and written with `0x04` set.

#### Eligible pair with no anchor

The routine reads the source difference:

**d = partner source − current source.**

F-d14620fdf8dc receives context, selector, d, the current flags captured at iteration start, and the partner flags read for the call. Its signed 32-bit result is called **w**.

For **w < 96**, the current source is read again after the call, and the midpoint is:

**m = current source + arithmetic-half(d).**

Thus d is retained from before the call, while the current source may reflect dependency changes.

Candidate centers are:

| Width condition | Lower candidate | Higher candidate |
|---|---|---|
| w < 65 | R(m) − 32 | R(m) + 32 |
| 65 ≤ w < 96 | R(m) − 38 | R(m) + 26 |

The candidate nearest m is selected. Equal distances select the higher candidate. The routine writes:

1. Current destination = selected center − truncating-half(w).
2. Partner destination = selected center + truncating-half(w).

For **w ≥ 96**, it instead reads the current source after the call and writes only:

**current destination = R(current source).**

This branch makes no direct partner-destination assignment.

Both branches then freshly read and set the current processed bit, call F-449adf349cf2, and assign the current address to the anchor. They do not directly set the partner’s processed bit.

If the current address is zero, the final anchor assignment leaves the anchor absent. Later eligible records therefore still take the no-anchor branch unless another path establishes a nonzero anchor.

#### Eligible pair with an anchor

Before the width call, the routine calculates:

- **d = partner source − current source**
- **p = current source − anchor source + anchor destination**
- **m = p + arithmetic-half(d)**

F-d14620fdf8dc receives the same argument categories as above.

For **w < 96**, the saved m determines candidate centers using the same thresholds, offsets, distance comparison, and tie rule. Current destination is written first, then partner destination.

For **w ≥ 96**, source and anchor coordinates are reread. The routine recomputes p, d, and m, then calls F-d14620fdf8dc again, this time with freshly read current and partner flags. Call the second signed result **v**.

The second call’s result is not tested against 96. Instead, two candidate lower endpoints are formed from the values saved before that second call:

- **L₁ = R(p)**
- **L₂ = R(p + d) − v**

Each candidate’s implied midpoint is its lower endpoint plus arithmetic-half(v). The endpoint whose midpoint is nearer m wins; equal distances select L₂.

Current destination is written with the selected endpoint, followed by partner destination with that endpoint plus v.

After either width branch, the current flags and then partner flags are freshly read and written with `0x04` set. If the current address exceeds the collection start, its destination is compared as signed with the preceding record’s destination. A smaller current destination is raised to that preceding value. The partner destination is not recomputed.

The existing anchor is retained.

### 3. Conditional symmetry adjustment

After the main scan, F-870c4fcf7295 is called with the 32-bit saved end-minus-start difference and the constant 48. This call occurs even when no records were traversed.

Its result is not assumed to be a quotient. For selector zero, results exactly 6 or 12 select these zero-based indices:

| Result | First | Middle | Last |
|---:|---:|---:|---:|
| 6 | 0 | 2 | 4 |
| 12 | 1 | 5 | 9 |

The routine checks whether:

**absolute value of (2 × middle source − first source − last source) < 8.**

If true, it calculates:

**correction = last destination − (2 × middle destination − first destination).**

It then performs these ordered updates:

1. Subtract the correction from the last destination.
2. Read the last record’s partner reference; if nonzero, subtract the correction from that partner’s destination.
3. For result 12, subtract the correction from destinations at indices 8 and 11, in that order.
4. Freshly read and set the last record’s processed bit.
5. Reread its partner reference; if nonzero, freshly read and set that partner’s processed bit.

These are sequential accesses, not a simultaneous transformation. Aliasing can produce repeated subtraction or make later reads observe earlier writes. No duplicate-address suppression occurs.

The selected indices are not independently checked against the saved collection bounds.

### 4. Final unresolved-record pass

This pass runs only when the main scan counted at least one unprocessed record with no partner, or the anchor remains absent.

It scans the saved collection bounds and skips processed records. For each remaining record:

- With a nonzero placement reference: destination becomes current source minus referenced source plus referenced destination.
- Without a placement reference, but with an anchor: destination becomes R(current source − anchor source) plus anchor destination.
- Without either: destination becomes R(current source), then the current address is assigned to the anchor.

Again, assigning address zero leaves the anchor absent. A later unresolved record can consequently be rounded independently rather than placed relative to the record at zero.

After the destination write and any anchor assignment, the processed bit is set using the flags byte captured at the start of this iteration, not a fresh read.

Two clamps follow:

1. If a preceding collection record exists and its signed destination is greater, raise the current destination to that value.
2. If a following collection record exists, is processed, and has a smaller signed destination, lower the current destination to that value.

The following record’s processed bit is read twice in the supplied body before its destination is conditionally read. The second clamp can undo the first. No subsequent conflict repair occurs.

## Side effects

Direct writes affect destination fields and flags bytes of scanned or referenced records, including the fixed-index symmetry targets.

The routine directly sets, but does not directly clear, `0x04`. Fresh flag updates preserve other bits as read at that update. Final-pass updates preserve other bits from the iteration-start flags snapshot.

Processed records can still be modified through partner references, symmetry adjustment, aliases, or dependencies.

There is no explicit allocation, release, ownership transfer, logging, rollback, or error reporting in this body. Dependency ownership and lifetime effects are unknown. Partial updates remain observable if a later access or call fails.

Only selected values are retained across calls. The routine does not snapshot complete records, and dependencies are not assumed to preserve context contents, referenced storage, globals, or ownership.

## Acceptance examples

These are conditional static expectations, not observed executions. Unless stated otherwise, storage is valid and nonaliasing, arithmetic does not overflow, and dependencies preserve relevant data.

1. **Independent rounding.** One unprocessed record without partner or placement reference reaches the final pass. Source 95 produces destination 64; source 96 produces 128. The processed bit is set.

2. **Narrow first pair.** Sources 0 and 64 yield d = 64 and midpoint 32. With width 40, R(32) = 64, so the centers are 32 and 96. Center 32 wins. Destinations written before F-449adf349cf2 are **12 and 52**.

3. **Center tie.** Sources 0 and 128 with width 40 yield midpoint 64 and candidate centers 32 and 96. The tie selects 96, producing destinations 76 and 116 before F-449adf349cf2.

4. **Odd width.** Width 65 uses offsets −38 and +26 and truncating half-width 32. The two destination writes differ by 64, not 65.

5. **Wide first pair.** With no anchor and width 96, only the current destination is directly rounded. The current processed bit is set before F-449adf349cf2. The partner’s eventual destination remains dependency-dependent.

6. **Second width result.** With an existing anchor, first result 96 causes a second width call. A second result of 40 still uses the wide-branch endpoint formulas; it does not switch to narrow-center placement.

7. **Strict symmetry threshold.** Selector zero and span-helper result 6 permit correction for absolute source deviation 7, but not 8.

8. **Conflicting clamps.** A preceding destination of 100 and processed following destination of 80 leave a final-pass current destination at 80, even if the first clamp raised it to 100.

9. **Zero-address preliminary exclusion.** Assume readable record storage at zero, selector one, and an unprocessed record there with a nonzero dependency. The preliminary pass does not copy its dependency destination, set its flag, or establish an anchor for it. A nonzero partner does not bypass this exclusion.

10. **Partner selection from address zero.** If that current record instead has zero dependency and a nonzero partner with nonzero dependency, the partner receives the copy and processed bit. The zero opposite address prevents the optional opposite-record call, and anchor assignment remains zero.

11. **Zero-address final-pass anchor.** With selector two, records at addresses zero and 48, sources 95 and 100, unset processed bits, and no partner or placement references, the main scan counts both records. The final pass writes destinations 64 and 128. The first record cannot establish a nonzero anchor; the second is independently rounded.

12. **Empty traversal.** Equal start and end addresses produce no scan visits, but F-870c4fcf7295 is still called. If selector zero and its result selects symmetry adjustment, fixed-index accesses can still occur.
