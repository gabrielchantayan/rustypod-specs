After another indirect call:

1. A byte is read at one plus that multiplied value.
2. Zero is written to the address equal to the loaded byte plus 17.
3. A call receives zero, the first secondary-register value, and the multiplied value.
4. Several further calls occur.

## Acceptance examples

These examples are conditional static consequences, not executed tests. Unless stated otherwise, they assume wrapping 32-bit arithmetic, valid accesses, and returning dependencies.

1. **Third-argument truncation:** For third arguments zero, one, and all bits set, shifting left by 26 and then multiplying by 1,024 produces zero. The corresponding initial selector reads therefore use address 1.

2. **Initial load address:** For a third argument of one, the initial two word-load expressions address `0x0400001C`. This does not make either load safe.

3. **Unsigned byte selection:** A selector byte of 255 directs a byte store to address 272, not to an address below 17.

4. **Re-reading matters:** If an intervening dependency changes address 1 from 3 to 9, two initial selector-based writes can target addresses 20 and 26. Reusing the earlier selector would not match the represented behavior.

5. **Byte truncation:** If the first packing word is 65, four times it is 260. Its corresponding byte store writes 4, while the associated call receives the full 32-bit value 260.

6. **Masked extraction:** If the first packing word has bits 20 through 29 all set, the extraction produces 1,023 before truncation. The byte store writes 255.

7. **Paired result:** If the represented 64-bit result has pair-high equal to 3 and pair-low equal to 2, the first pair-high-indexed store writes zero at address 32. The later pair-low-scaled store writes `0x08000000` at address `0x20000014`.

8. **Independent word loads:** If the two load expressions in the first scaled stage observe different values, the dependency arguments must reflect their respective observations. Acceptance must not require both arguments to derive from a single cached value.

9. **Partial effects:** If a dependency fails after a byte write, that earlier write remains an observable effect unless some separately established mechanism reverses it. No such mechanism is shown.
