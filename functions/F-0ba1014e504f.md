# F-0ba1014e504f

## Purpose

F-0ba1014e504f changes one bit in a descriptor-backed byte sequence and, on paths that reach the bit write, removes trailing zero bytes from its recorded length.

The established behavior includes:

- Clearing the low four bits of a descriptor control word before checking whether the descriptor address is null.
- Treating a zero requested value as “clear” and every nonzero requested value as “set.”
- Numbering bits within each byte from most significant to least significant.
- Requesting storage when a set operation targets a byte outside the recorded length or when the backing address is zero.
- Returning success without a bit write when a clear operation meets either of those storage conditions.
- Scanning backward after a bit write and shortening the recorded length while its final byte is zero.

**Inferred intent:** the descriptor represents a dynamically stored bit sequence with a length normalized to exclude trailing zero bytes. The contracts of the allocation-related dependencies and the external range operation are not supplied, so storage ownership, initialization, and failure guarantees remain partly unknown.

## Interface

The function receives four arguments:

| Argument | Representation | Established use |
|---|---|---|

| Bit position | 32-bit unsigned word | Supplies the within-byte bit position, but is interpreted as signed for byte-index calculation. |

| Auxiliary value | Opaque 32-bit word | Passed twice to F-43da6b23bd44 when that dependency is selected. Otherwise unused directly. |

The supplied representation uses 32-bit integer words and stores the backing address in a 32-bit descriptor field.

### Descriptor layout

Offsets are byte offsets from the descriptor address.

| Offset | Width | Meaning established by use |
|---|---:|---|
| 0 | 32 bits | Recorded byte length, read and compared as signed. |
| 4 | 32 bits | Not directly accessed by this function. |
| 8 | 32 bits | Backing byte-storage address; zero means absent for branch selection. |
| 12 | 32 bits | Control word whose low four bits are cleared on entry. |

The recorded length is not established to be an allocation capacity. Shortening it does not directly release or resize storage.

### Output

The return value is a 32-bit word:

- **1:** the function reaches a successful no-write clear path, or completes the bit write and trailing-zero scan.
- **0:** a selected storage dependency returns zero, or the explicit null-address return is reached.

The explicit null return is not a safe null-input guarantee: the control word is accessed first.

No distinct error codes are provided.

### Preconditions for ordinary defined use

For the intended nonnegative-index use:

- The descriptor must be readable and writable at the accessed offsets.
- Any nonzero backing address must identify storage accessible for every byte read or written on the selected path.
- A positive recorded length must not exceed the accessible backing storage.
- Successful dependencies must provide storage suitable for the subsequent range operation, selected-byte update, and backward scan.
- Address and range arithmetic must identify valid memory rather than wrap into unrelated storage.

The function does not validate these conditions.

## Behavior

### Index and mask calculation

Let the signed interpretation of the bit-position word be \(s\), in the 32-bit two’s-complement range.

The selected byte index is:

\[
q = \operatorname{trunc}(s / 8)
\]

where truncation is toward zero. For ordinary positions below \(2^{31}\), this is the usual unsigned byte index. For words with the top bit set, it is a signed calculation rather than an unsigned division.

The bit mask is:

\[
m = 2^{\,7-(\text{bit position}\mathbin{\&}7)}
\]

Thus positions 0 through 7 select masks `0x80`, `0x40`, `0x20`, `0x10`, `0x08`, `0x04`, `0x02`, and `0x01`.

These two calculations are not equivalent to a conventional unsigned bit-vector index for all inputs:

- Signed interpretations −1 through −7 produce byte index zero.
- Signed interpretation −8 produces byte index −1.
- No negative-index rejection is present.

The possible byte indices range from −268,435,456 through 268,435,455. Consequently, the derived target length \(q+1\) ranges from −268,435,455 through 268,435,456 and does not itself overflow a signed 32-bit integer.

### Entry control-word update

Before the null-address check, the function reads the 32-bit word at descriptor offset 12, clears its low four bits, and writes it back. Its upper 28 bits are retained.

This write precedes all ordinary success and storage-failure returns. It also precedes the attempted null rejection. Under ordinary memory protection, a null descriptor can fault during this access instead of returning zero.

No meaning for the four cleared bits is established.

### Storage-path selection

The function tests whether either:

1. The signed recorded length is less than \(q+1\), or
2. The backing address is zero.

The first comparison precedes the backing-address test. The latter need not be evaluated when the length comparison already selects this path.

If either condition holds and the requested value is zero, the function returns 1 immediately. On that path it does not directly:

- Request storage.
- Write the selected byte.
- Scan or normalize the recorded length.
- Change the recorded length or backing address.

The entry control-word update has already happened.

If storage is needed and the requested value is nonzero, dependency selection is based on the backing-address field:

- A zero backing address selects **F-43da6b23bd44**.
- A nonzero backing address selects **F-06ed623de53f**.

A zero dependency result causes an immediate return of 0. The function does not install that result or continue to the selected-byte write. This is not a rollback guarantee: the entry control-word change and any dependency side effects remain.

### Successful storage result

After a nonzero storage result, the function calculates a range size using the descriptor’s recorded length as read after the dependency returns:

\[
d = q - \text{current recorded length}
\]

If \(d+1\) is positive as evaluated by the supplied 32-bit arithmetic, it invokes an external two-argument range operation with:

- An address formed from the returned storage address plus a read of the current recorded length.
- A size of \(d+1\).

The range begins at the recorded-length offset, not at offset zero. When dependencies leave the descriptor unchanged and arithmetic is valid, it spans from the old logical end through the selected byte, inclusive.

**The external operation’s effect is unknown.** Its call shape is consistent with a range-initialization operation, but the supplied evidence does not establish that it writes zeros or even that it only affects that range.

After that call, or immediately if the range size is not positive, the function writes:

1. The returned storage address to descriptor offset 8.
2. \(q+1\) to descriptor offset 0.

The return from the external range operation is not checked.

The descriptor reads after dependency calls matter. The supplied evidence does not establish that those dependencies preserve the descriptor, aliased memory, or global state. The function therefore cannot be specified as retaining an immutable snapshot of the pre-call descriptor.

### Selected-byte update

On paths that reach the bit write, the function reads the byte at backing address plus \(q\), replaces the selected bit, and writes the byte back.

For a set operation:

\[
\text{new byte} = \text{old byte} \mathbin{|} m
\]

For a clear operation:

\[
\text{new byte} = \text{old byte} \mathbin{\&} (255-m)
\]

Only the selected bit changes in this byte transformation. Other bytes can still be affected by dependencies or aliasing.

There is no check that \(q\) is nonnegative before the byte access.

### Trailing-zero normalization

After the byte write, the function repeatedly:

- Reads the recorded length.
- Stops if it is not positive.
- Otherwise reads the byte at backing address plus recorded length minus one.
- Stops if that byte is nonzero.
- Otherwise decrements the recorded length and repeats.

A zero byte is the sole trimming condition; signed versus unsigned byte interpretation does not affect it.

The scan does not directly clear bytes, release storage, or change the backing address. It can reduce the recorded length to zero while leaving a nonzero backing address installed.

For an isolated, valid descriptor, a successful path that reaches this scan ends with either:

- A nonpositive recorded length, or
- A nonzero last recorded byte.

This invariant does not apply to the early successful clear path, which skips normalization.

## Side effects

Directly established writes are:

1. Entry masking of the control word.
2. Conditional installation of a successful storage result.
3. Conditional assignment of the target recorded length.
4. A selected-byte read-modify-write.
5. Zero or more recorded-length decrements.

The order above is significant. In particular, storage fields are installed after the external range operation, and the selected-byte update precedes trimming.

There is no direct release operation in the supplied body. Whether F-06ed623de53f releases, replaces, or retains its input storage is unknown. Ownership transfer cannot be inferred merely from the caller replacing its backing-address field.

The function contains no explicit global-variable access. That does not establish that its dependencies preserve globals or have no other side effects.

There is no synchronization. Concurrent mutation of the descriptor or backing bytes is outside any established safety guarantee. Aliasing between backing storage and descriptor fields can also make a byte write affect later descriptor reads; no guard prohibits such aliasing.

## Acceptance examples

These are conditional contract examples, not executed tests. Unless stated otherwise, they assume valid, nonaliasing memory and no concurrent mutation.

1. **Set the first bit without storage growth.**  
   With length 1, a valid backing byte of `0x00`, position 0, and a nonzero requested value, the byte becomes `0x80`. The length remains 1, the function returns 1, and the low four control bits are cleared.

2. **Clear the last remaining bit.**  
   With length 1 and backing byte `0x01`, clearing position 7 produces `0x00`. The backward scan reduces the length to zero. The backing address remains unchanged, and the function returns 1.

3. **Trim more than the selected byte.**  
   With recorded bytes `[0x40, 0x00, 0x01]`, clearing position 23 changes the third byte to zero. The scan removes both trailing zero bytes from the recorded length, leaving length 1.

4. **Clear beyond the recorded end.**  
   With length 1 and a nonzero backing address, clearing position 16 returns 1 without a selected-byte write, storage call, or trim. The entry control-word update still occurs.

5. **Clear with absent backing storage.**  
   With a zero backing address, clearing position 0 returns 1 even if the recorded length is positive. The function does not repair that inconsistent descriptor.

6. **Set requiring storage, dependency failure.**  
   With zero backing address and position 8, F-43da6b23bd44 receives target length 2. If it returns zero, this function returns 0 without installing storage or writing the selected byte. Dependency side effects are not excluded.

7. **Set requiring storage, conditional initialization outcome.**  
   With length 1, position 8, and a successful storage result, the range operation is requested for one byte beginning at offset 1, assuming dependencies preserve the descriptor. If that operation initializes the new byte to zero and the resulting storage is valid, the selected byte becomes `0x80` and the recorded length ends at 2.

8. **High-bit input with byte index zero.**  
   Position `0xFFFFFFFF` has signed interpretation −1, yielding byte index zero and mask `0x01`. With valid length-1 storage, setting it changes the low bit of the first byte. It does not address a very large unsigned byte index.

9. **Null descriptor.**  
   A null address does not require a clean zero return. The preceding control-word access can fault.

## Uncertainties

The following remain **documented_only**:

- The descriptor’s public type, field names, and control-bit meanings.
- Whether recorded length also serves another role, such as allocation size.
- The exact contracts of both mapped dependencies.
- The external range operation’s identity and effects.
- Backing-storage ownership before and after dependency calls.
- Behavior after invalid pointer access.
- Intended support for high-bit-set positions and negative derived byte indices.
- Exact overflow behavior for expressions involving arbitrary descriptor lengths and derived addresses.

The target-length calculation has a bounded signed range, but subtracting an arbitrary signed recorded length or adding lengths to addresses can exceed ordinary signed or address limits. The supplied evidence does not justify treating every such case as portable mathematical arithmetic.
