# F-226e963e6ba7

## Purpose

F-226e963e6ba7 updates a caller-supplied mutable record. It copies selected bytes from a globally selected reference record, invokes an initialization dependency, restores selected reference-derived fields, and computes a 16-bit result from a seed byte, a count byte, and a byte table.

The computation has one conditional substitution: at table index 1, a zero result from a classification dependency causes the function to add 28 instead of reading and adding that table byte.

The reference record’s semantic role, the meaning of the computed result, and the meanings of individual flag bits are not established. Descriptions such as “initialization” and “classification” identify observable roles in this function, not independently verified dependency behavior.

## Behavior

### Reference-derived writes before the first dependency

The function first captures the reference-record address. It then performs these destination writes in order:

1. Replace destination byte 11 with reference byte 11.
2. Replace destination byte 6 with reference byte 6.
3. Replace destination byte 7 with reference byte 7.

Each copy reads a source byte for its corresponding write; the three reference bytes are not visibly captured as one atomic snapshot.

The initial byte-11 source access is expressed through the global reference address source, whereas the byte-6 and byte-7 accesses use the captured reference address. No dependency call occurs between the capture and these copies. In a stable single-threaded environment, they therefore select the same reference record. Behavior under asynchronous changes to that global is not established.

The function next invokes F-a4ea0691ddc5 with:

- A first argument equal to zero.
- The supplied record address as its second argument.

At this call boundary, the three writes above have occurred. No other record fields are explicitly initialized by F-226e963e6ba7 before the call.

### Reference-derived writes after the first dependency

If F-a4ea0691ddc5 returns normally, the function performs these operations in order:

1. Replace destination byte 6 with a fresh read of byte 6 from the captured reference record.
2. Replace destination byte 7 with a fresh read of byte 7 from that same captured reference record.
3. Update destination byte 11 by combining:
   - Every bit other than bit 1 from the destination’s then-current byte 11.
   - Bit 1 from a fresh read of reference byte 11.

Bit numbering is zero-based: bit 1 has mask value 2. The merge clears that bit in the destination value before inserting the reference bit.

Consequently, changes made by F-a4ea0691ddc5 to destination bytes 6 and 7 are overwritten on normal return. Changes to destination byte 11 outside bit 1 survive this merge, subject to aliasing and subsequent dependency effects. Bit 1 is taken from the captured reference record at the time of the merge.

The reference bytes are reread after the call. Changes to the referenced storage made by the dependency can therefore affect these post-call writes. A change to the global reference address alone does not redirect them.

The supplied expression does not establish which operand of the byte-11 merge is read first. It does establish that both reads contribute to the resulting byte write.

### Seed capture and classification call

After the post-call writes, the function reads destination byte 3 as an unsigned byte and subtracts one. This initializes a 16-bit signed accumulator.

Before any table additions, the initial mathematical value lies between −1 and 254 inclusive:

- Seed 0 gives −1.
- Seed 1 gives 0.
- Seed 255 gives 254.

The function then reads the 16-bit field at destination offset 0 and passes it to F-7264181a6e68. The returned integer is retained for the later zero comparison.

This ordering is significant:

- F-a4ea0691ddc5 can affect both the seed and the classification argument.
- The seed is captured before F-7264181a6e68 executes.
- Changes by F-7264181a6e68 to byte 3 do not replace the captured seed.
- The count byte is not captured before that call; its first loop-condition read occurs afterward.
- F-7264181a6e68 may also alter destination bytes previously written by this function. Those bytes are not restored again.

The only distinction made about the classification result is whether it equals zero. All nonzero results take the same accumulation path.

### Count-controlled accumulation

The loop index starts at zero. Before every iteration, the function rereads unsigned destination byte 2 and compares the index with that byte minus one.

The subtraction is not an 8-bit wrapping subtraction. In particular, count zero produces a comparison bound of −1, not 255.

For each iteration:

- If the index is 1 and the retained classification result is zero, add 28 to the accumulator. Do not read the table address source or table byte for that iteration.
- Otherwise, obtain the byte-table address, read its unsigned byte at the current index, and add that byte to the accumulator.
- Advance the index by one.

For a count byte that remains stable during the loop:

| Count byte | Iterations | Indices processed |
|---:|---:|---|
| 0 | 0 | None |
| 1 | 0 | None |
| 2 | 1 | 0 |
| 3 | 2 | 0 and 1 |
| 255 | 254 | 0 through 253 |

The special addition therefore occurs only if index 1 is reached and the classification result is zero. A zero classification result does not suppress the table read at index 0.

There are no dependency calls inside the loop. The count and ordinary-path table address nevertheless appear as repeated reads, not as explicitly cached values. No concurrent-access guarantees are supplied.

### Arithmetic and final result

Each table element contributes an unsigned value from 0 through 255. The special contribution is 28.

The accumulator is 16-bit signed storage in the supplied representation, and each addition is assigned back to that storage. An intermediate mathematical total can exceed the positive range of a signed 16-bit value.

Under conventional target narrowing that retains the low 16 bits, the final result is the low 16 bits of:

- The captured unsigned seed minus one;
- Plus every selected table byte;
- With 28 substituted for table index 1 when the special condition applies.

This low-16-bit interpretation is a target-representation inference, not a language-independent guarantee about out-of-range conversion to signed 16-bit storage.

With a stable count, the largest unsubstituted mathematical total is 65,024: seed 255, count 255, and 254 table contributions of 255. Thus a signed accumulator can become negative even though the seed-adjusted value and additions are otherwise nonnegative. The loop does not branch on the accumulator’s sign.

After loop termination, the function writes the accumulator’s 16-bit representation to destination offsets 4–5 and returns. It performs this write even when the loop executes zero times.
