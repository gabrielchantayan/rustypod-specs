# F-641936cb8a81

## Purpose

F-641936cb8a81 returns a nonzero value from an indexed table when the supplied index is below the table’s recorded bound and the selected entry is nonzero. Otherwise, it returns the result of F-6553c4e9e5b8.

The fallback covers two distinct cases:

- The index is not below the recorded bound.
- The index is below the bound, but the selected table entry is zero.

A negative selected value is nonzero and is returned directly. A zero returned by the fallback is also returned directly; the function does not repeat the fallback call.

This is a source-facing contract. The supplied representation establishes the selection logic and visible memory accesses, but does not establish the meaning of table entries, the ownership of returned values, or the behavior of the fallback.

## Behavior

### Bounds decision

The function compares the unsigned index with the unsigned bound stored at context byte offset 12.

The comparison is strict: an index equal to the bound is out of range. If the bound is zero, every possible unsigned index is out of range.

Both operands are unsigned 32-bit values. A bit pattern whose signed interpretation would be negative remains a large unsigned index for this comparison. No signed-negative-index check is present.

The bounds decision requires a read through the context-reference address, a bound-field read, and an index read. The supplied expression does not establish a left-to-right ordering between the comparison’s operands. A contract requiring the index read to precede the context read, or the reverse, would exceed the evidence.

### In-range selection

If the comparison succeeds, the function reads the table-address field at context byte offset 8 and uses the index to select a four-byte entry.

The effective entry location is the table base plus four times the index. The read produces a signed 32-bit value.

The supplied representation expresses another read of the context reference and another read of the index for this selection. It does not explicitly retain the values used for the earlier bounds decision. Consequently, the source-facing contract does not guarantee that validation and selection use an immutable snapshot of the context and index.

For stable, valid input storage, the expected relationship is straightforward: index zero selects the first entry, index one selects the entry four bytes later, and so on. If externally changed storage, special memory semantics, or permitted aliasing causes later reads to differ, the supplied function provides no synchronization, revalidation, or snapshot mechanism. Whether such a change constitutes a valid execution depends on the surrounding execution model, which is not supplied.

A nonzero selected entry is returned directly. The function performs no normalization and does not require the entry to be positive.

### Out-of-range handling

If the unsigned index is not below the unsigned bound, no table entry is selected. The value used for the subsequent fallback decision is zero.

On this path, the function does not explicitly read the context’s table-address field. Thus, subject to a valid context-reference read and bound-field read, the out-of-range path does not itself require a usable table address or a readable table allocation.

This distinction does not imply that invalid context pointers are safe. The context is already needed to obtain the bound before the out-of-range decision can be made.

### Fallback selection

After either obtaining an entry or choosing the out-of-range zero value, the function tests that value for equality with zero.

If it is nonzero, the function returns it without calling F-6553c4e9e5b8.

If it is zero, the function calls F-6553c4e9e5b8 once, with no explicit arguments, and returns its result. The fallback result is not subjected to another zero test or another fallback invocation.

There is no local error-recovery branch. If the dependency does not return normally, the supplied function establishes no alternative completion behavior.

### Widths and address arithmetic

The represented interface uses four-byte integer and table-entry widths, with context addresses carried in 32-bit words. This is not a portable layout specification for environments with different integer or pointer widths.

The index multiplication is unsigned 32-bit arithmetic. Multiplication by four can therefore wrap modulo \(2^{32}\). For example, an index of \(2^{30}\) produces a zero scaled offset under that arithmetic.

The bound comparison alone does not prevent this wrap: a sufficiently large unsigned bound can admit such an index. Accordingly, being below the bound is not by itself proof that selection addresses a distinct, valid table entry.

The supplied address expressions mix address-bearing integer values with unsigned offsets. They do not establish a general, safe address-overflow policy for all pointer calculations. Callers must not infer memory safety from modular arithmetic alone; the accessed location must still be valid under the actual execution environment.
