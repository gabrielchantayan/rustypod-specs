# F-c73847cd39ec

## Purpose

F-c73847cd39ec performs a capacity-limited, zero-terminated byte copy, then delegates processing of the unconsumed source suffix to F-1cb585febd84. Its result is the number of bytes copied plus the dependency’s returned integer.

The established behavior resembles a bounded string-copy operation that reports the full source length. That interpretation is **conditional**, not established: it requires F-1cb585febd84 to return the length of the suffix it receives. The supplied evidence does not define that dependency.

The function does not allocate storage, report truncation separately, or establish that its dependency is read-only. In particular, the copy capacity limits this function’s direct copying; it does not establish a bound on the dependency’s accesses.

## Interface

**Inputs**

- **Destination:** a byte-addressed writable location. When capacity is positive, the function directly writes at least a zero terminator here, unless execution fails before reaching that write.
- **Source:** a byte-addressed location used both for direct byte reads and as the basis of the pointer passed to F-1cb585febd84.
- **Capacity:** an unsigned integer controlling destination writes. A positive capacity reserves one byte for a terminator. Zero disables this function’s direct destination writes.

The destination and source are passed as character pointers. Elements occupy one character-sized byte; zero is the terminator value. Copying does not interpret encoding, character boundaries, or multibyte sequences.

**Output**

The function returns an integer formed by adding:

1. its signed integer count of copied bytes; and
2. the integer returned by F-1cb585febd84.

The terminator is not included in the copied-byte count.

**Integer widths**

The supplied representation identifies capacity as an unsigned integer and both the count and return values as signed integers. It does not independently provide an ABI, an explicit integer-width declaration, or the definition of the unsigned type alias.

For a 32-bit interpretation, capacity ranges from 0 through 4,294,967,295, while the signed count and result range from −2,147,483,648 through 2,147,483,647. These numerical widths are **documented_only**, not independently established by the supplied evidence.

Regardless of the exact widths:

- Capacity is decremented only when it is greater than one, so the decrement does not underflow.
- The copied-byte count is incremented once per copied byte.
- No check protects the signed count from overflow.
- No check protects the final signed addition from overflow.

A guaranteed numerical result therefore requires both the count and final sum to remain representable. No portable wraparound behavior is established.

**Memory preconditions**

For defined direct execution, every byte actually read must be readable and every byte actually written must be writable. Pointer advancement must also remain valid under the applicable execution model.

Sufficient destination storage is determined by the writes actually performed, not merely by the declared capacity. If capacity is positive and the copy count is representable, the function directly writes no more than capacity bytes, including the terminator.

The dependency imposes additional, unknown preconditions on the source-suffix pointer. Capacity zero does not eliminate those preconditions.

## Behavior

### Copy limit and stopping conditions

The initial copied-byte count is zero.

Copying continues only while both of these conditions hold:

- Remaining capacity is greater than one.
- The byte at the current source position is nonzero.

The capacity condition is evaluated first. If remaining capacity is zero or one, the loop condition does not directly read the current source byte.

Each completed copy consumes one byte of remaining capacity, writes one source byte at the current destination position, and advances both positions by one byte. Consequently, a positive initial capacity permits at most capacity minus one copied bytes.

When copying stops, the current source position identifies the first byte not copied. This can be:

- A zero byte encountered while there was room to continue;
- A nonzero byte left unread by the loop condition because only the terminator slot remains; or
- The original source position when no bytes were copied.

### Observable read and write order

For each iteration, the source byte is first read to decide whether it is zero. A successful iteration then obtains the source byte for the destination assignment. The supplied representation therefore contains a condition read followed by a copy-value read at that source position, with the destination write afterward.

This is an ordering description of the supplied representation, not a guarantee of two distinct hardware loads. The pointers are not declared volatile, and compiler or machine-level access behavior is not supplied.

Under ordinary stable-memory conditions, the value copied is the nonzero byte that permitted that iteration. No snapshot of the source is taken. Writes through overlapping destination storage can affect source bytes examined later.

After copying stops:

- If remaining capacity is nonzero, a zero byte is written at the current destination position.
- If remaining capacity is zero, no terminator is written by this function.

Because copying never reduces a positive capacity to zero, the distinction is exact: an initially positive capacity leads to a direct terminator write, while an initial capacity of zero leads to no direct destination writes.

### Dependency invocation and return

After the optional terminator write, F-1cb585febd84 is invoked with the current source position as its sole visible argument.

The dependency is invoked even when:

- Capacity is zero;
- Capacity is one;
- The source begins with zero;
- No source byte was copied; or
- Copying stopped because the available copy space was exhausted.

The pointer passed to the dependency is advanced by exactly the number of bytes copied. It is not necessarily the original source pointer, and it is not advanced past a terminating zero.

The dependency’s returned integer is added to the copied-byte count. The sum becomes this function’s result. There is no special treatment of negative dependency results, no distinct truncation status, and no retry or fallback path.

If the dependency does not return normally, no normal return from this function is established.

### Aliasing and changing memory

No explicit overlap check or rejection exists. The behavior is sequential byte copying, not an overlap-safe snapshot operation.

In particular, the terminator write precedes the dependency call. If destination storage overlaps the suffix supplied to the dependency, that write may change what the dependency observes. Thus, even a length-counting dependency would not necessarily measure the suffix of the original source contents.

The evidence does not establish behavior for concurrent modifications, device-backed storage, or asynchronous mutation. Such cases cannot be treated as ordinary stable-string inputs.

## Side effects

The function’s direct memory modifications are:

- One destination-byte write for each copied byte; and
- One zero-byte write following those bytes when initial capacity is positive.

For disjoint source and destination storage, these direct writes do not modify source bytes. For overlapping storage, they may.

There are no explicit direct writes to global state and no explicit allocation or release operations in this function. This does **not** establish that the complete call is free of such effects: F-1cb585febd84 has an unknown contract.

No ownership transfer, source retention policy, or memory-release policy is established for the dependency. Callers must not infer from this wrapper alone that the dependency preserves globals, leaves memory unchanged, or refrains from retaining or releasing storage.

There is no rollback. Destination writes precede the dependency call and are not explicitly undone if the dependency fails.

## Acceptance examples

These examples are conditional acceptance criteria, not executed tests. Unless stated otherwise, they assume stable, readable zero-terminated source storage, sufficient writable destination storage, disjoint buffers, normal dependency return, and representable arithmetic.

### Complete copy

Given source bytes `cat` followed by zero and capacity five:

- Three bytes are copied.
- A zero is written immediately after them.
- The fifth destination byte is not directly written.
- The dependency receives the pointer to the source’s zero byte.
- The result is three plus the dependency result.

If the dependency returns suffix length, the result is three.

### Truncated copy

Given source bytes `cat` followed by zero and capacity three:

- Only `c` and `a` are copied.
- The destination’s third byte is set to zero.
- The dependency receives the pointer to `t`, not the source terminator.
- The result is two plus the dependency result.

If the dependency returns suffix length, the result is three, while the destination contains `ca` followed by zero.

### Capacity one

Given source bytes `cat` followed by zero and capacity one:

- No source byte is directly read by the loop condition.
- No source byte is copied.
- The first destination byte is set to zero.
- The dependency receives the original source pointer.
- The result equals the dependency result.

The absence of a direct source read does not remove the dependency’s source-access requirements.

### Capacity zero

Given capacity zero:

- No destination byte is directly written.
- No source byte is directly read by the copying loop.
- The dependency still receives the original source pointer.
- The result equals the dependency result.

A null destination is therefore not directly dereferenced on this path. This observation does not establish that a null source is acceptable to the dependency.

### Empty source

Given a source whose first byte is zero and capacity greater than one:

- The loop reads that zero and copies nothing.
- The first destination byte is set to zero.
- The dependency receives the original source pointer.
- The result equals the dependency result.

### Identical source and destination

Given one buffer containing `abcd` followed by zero, used as both source and destination, with capacity three:

- The first two byte assignments write `a` and `b` back to their existing positions.
- The terminator write replaces `c` with zero.
- The dependency receives a pointer to that newly written zero.
- The result is two plus the dependency result.

If the dependency returns suffix length, the result is two, not the original length four. This demonstrates why full-original-length semantics require additional noninterference assumptions.

### Negative dependency result

If two bytes are copied and the dependency returns −5, the result is −3, provided the addition is representable. The function does not recognize or propagate −5 as a distinguished error code.
