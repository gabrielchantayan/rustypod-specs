# F-11ca14d3e1f7

## Purpose

This function repeatedly invokes dependencies and distributes values among indirectly addressed memory locations. Its visible control flow is an unconditional loop with no normal return. Each iteration includes a software breakpoint.

The established contract concerns call order, access widths, address calculations, captured values, and a recurring base adjustment. An application-level purpose—such as initialization, device control, or record processing—is not established.

Every operation below is conditional on execution reaching it. A dependency, invalid memory access, or breakpoint disposition may prevent later operations from occurring.

## Interface

**Explicit arguments:** None.

**Explicit result:** None. No normal return path is visible.

**Implicit inputs and state:**

- An incoming link-like value used to calculate the first dependency target.
- An incoming signed 32-bit register value used in the final byte-store address.
- A register-like address base used for fixed-offset accesses and decreased during each continued iteration.
- Two global address-bearing values, captured at different points.
- Dependency results, including paired results and additional register outputs.
- Memory addressed through these values.

Dependencies are identified as **D-01** through **D-37**, in call-site order within an iteration. These opaque identifiers distinguish call sites; they do not establish distinct implementations, public interfaces, or ownership rules.

Arithmetic must be classified expression by expression:

- D-09’s low component is explicitly treated as unsigned for both its right shift by 26 and its left shift by two.
- The constant-derived right shift by 18 and subsequent multiplication by four are unsigned 32-bit operations. Their result is `0x21C4`.
- Multiplication of the later address halfword by four is unsigned 32-bit arithmetic. Its result is at most `0x3FFFC` and is representable as signed 32-bit when retained for later use.
- Adding that halfword to its fourfold value to form the byte-source address is unsigned 32-bit arithmetic. Its maximum is `0x4FFFB`; no wrap occurs for the established halfword range.
- The final byte-store address is calculated by adding the propagated halfword, the incoming register value, and `0x19` using unsigned 32-bit arithmetic. The incoming register value is converted to unsigned for this calculation, including when its signed interpretation is negative.
- D-06’s second argument first adds the signed interpretations of the pair’s high and low components. Only afterward is that intermediate result added to an unsigned zero contribution. The final addition is unsigned; it does not remove uncertainty from an overflowing initial signed addition.

Actual signed subexpressions include D-19’s left shift by two, D-28’s low-component left shift by six, D-28’s high-component multiplication by four, the base decrement, and address additions whose operands remain signed. Signed overflow and problematic signed shifts are unresolved in the supplied representation. This contract does not assign them blanket wraparound behavior.

The earlier fixed-address halfword becomes an address through ordinary integer promotion: its additions of `0x44` and `0x04` are signed but remain representable throughout its possible range.

Integer-to-address conversion, memory validity, alignment, and byte order are separate uncertainties. A fully determined unsigned integer address does not establish that an access through it is valid.

## Behavior

### Entry and first captured global

Each iteration establishes a zero byte for a later store. D-01 receives two explicit zero arguments.

On the first iteration, D-01’s target is calculated from the incoming link-like value plus `0xFFE`. Near the end of a continued iteration, the represented link-like value is assigned `0x08712031`. Subsequent iterations use that value in the same target calculation. The first target need not equal later targets. The target addition is represented as signed arithmetic.

After D-01, a separate zero contribution is established for D-06’s argument calculation.

D-02 and D-03 execute next. The function then captures the first global address-bearing value. D-04 executes after this capture.

D-05 supplies a paired result. D-06 receives:

1. The low 32-bit component.
2. The signed high-component-plus-low-component result, subsequently combined with the unsigned zero contribution.

The first addition has signed-overflow uncertainty. If it is representable, the subsequent unsigned addition preserves its 32-bit residue.

A byte associated with an additional register output from D-06 is written at captured-first-global offset `0x11`. D-07 then executes, followed by a zero-byte write at offset `0x15` from that same captured base.

Neither write reloads the global slot. Changing that slot after capture does not retarget these writes in the represented dataflow. Changing the memory or lifetime behind the captured address can still affect execution.

### Initial halfword and paired-result distribution

D-08 supplies a 16-bit result and an additional address-bearing output. The result is written as a halfword at offset `0x0C` from that output.

D-09 supplies another paired result. The function then:

- Writes a zero halfword at the signed interpretation of its high component plus `0x2C`.
- Writes its unsigned low component shifted right by 26 as a word at current-base offset `0x26C`.

The shifted word is between 0 and 63 inclusive.

The function establishes the unsigned constant `0x21C48960` and calls D-10. It then reads a word at current-base offset `0x320`, retaining that word as a destination base.

D-11 and D-12 execute before a word write at captured-destination offset `0x54`. Its value is D-09’s unsigned low component shifted left by two, with bits above bit 31 discarded.

The destination is captured after D-10 and before D-11 and D-12. Later changes to its source location do not retarget this write in the represented dataflow. The retained D-09 pair supplies both shifted values; no replacement pair is visibly acquired.

### Fixed-address read and breakpoint

D-13 through D-17 execute in order.

The function reads an unsigned halfword at `0x21C48994`, obtained by unsigned addition of `0x34` to the established constant. This halfword is retained and later used as an address value, not as an index relative to the original constant.

D-18 executes. A word is then read at current-base offset `0x280` and supplied to D-19. D-19 returns a signed 32-bit result.

A software breakpoint with immediate `0x92` occurs next. All operations described below require continuation beyond this breakpoint. Whether it traps, resumes, terminates execution, or receives other environment-specific handling is unresolved.

### Post-breakpoint address construction

After continuation, D-19’s result is shifted left by two using a signed expression. This supplies an offset for a later halfword write; invalid signed-shift cases remain unresolved.

Separately, the unsigned constant `0x21C48960` is shifted right by 18 and multiplied by four using unsigned arithmetic. The result is `0x21C4`, which is then retained in a signed 32-bit quantity without changing its value.

Using the earlier fixed-address halfword as a zero-extended address value, the function reads a word at offset `0x44`. That word becomes the retained **distribution base**.

D-20 executes, followed by D-21, which supplies a 32-bit result. The function then reads another word at offset `0x04` from the same halfword-derived address. D-22 receives D-21’s result first and this newly read word second.

The second global address-bearing value is captured after D-22. D-23 executes before a halfword write whose:

- Destination is the signed sum of the scaled D-19 result and the captured second global value.
- Payload is the low 16 bits of that captured global value.

The scale factor is four, but the write width is two bytes. No four-byte record layout or preservation rule for adjacent bytes is established.

### Low-address accesses and final pair

D-24 executes. The function reads a word at `0x2218`, which is `0x21C4 + 0x54`, retaining it as another base.

D-25 supplies an address-bearing result. A halfword containing `0x21C4` is written at offset `0x04` from that result.

D-26 and D-27 execute before an unsigned halfword is read at offset `0x34` from the base captured at `0x2218`. This is the **address halfword**.

These low-address accesses are part of the supplied representation. No omitted higher-order base is established.

D-28 supplies the final paired result. Its low component is written as a word at current-base offset `0x258`. The function then reads an unsigned halfword at the signed interpretation of the pair’s high component plus `0x14`. This is the **propagated halfword**.

Next, in order, the function derives:

1. D-28’s signed low component shifted left by six.
2. D-28’s signed high component multiplied by four.
3. The register-like base decreased by `0xF4`.
4. The address halfword multiplied by four using unsigned 32-bit arithmetic.

The first two derivations and the base decrement retain their signed-expression uncertainties. The fourth calculation is exact throughout the halfword range.

D-28’s low component is then written as a word at four times the address halfword plus `0x74`. This destination does not use the adjusted register-like base. Its offset addition is representable throughout the established range.

The earlier `0x258` write uses the base before adjustment. No inverse adjustment is visible before repetition. If the represented state persists without external alteration and the arithmetic remains defined, every iteration reaching this point decreases that base again.

### Final propagation and repetition

D-29 executes before the zero-extended propagated halfword is written as a word at distribution-base offset `0x54`.

D-30 executes before the same retained value is written as a word at distribution-base offset `0x64`. There is no intervening reread of the halfword.

D-31 executes. A halfword containing the low 16 bits of the distribution base is then written to the signed sum of:

- D-28’s low component shifted left by six.
- An additional address-bearing output associated with D-31.

D-32 and D-33 execute in order.

The function reads a byte at the unsigned sum of the address halfword and its fourfold value: five times the address halfword. The multiplication and this addition are exact for the established range.

D-34 executes after the byte read. The captured byte is then written at the address formed by unsigned 32-bit addition of:

- The zero-extended propagated halfword.
- The incoming register value converted to unsigned 32-bit.
- `0x19`.

This calculation reduces modulo \(2^{32}\), even when the incoming register value is negative as a signed integer. Address conversion and validity remain separate conditions.

D-35 executes before four times D-28’s signed high component is written as a word at distribution-base offset `0x44`.

D-36 executes. The represented link-like value is assigned `0x08712031`. The function then reads a word at the signed fourfold high-component value plus `0x44` and passes it to D-37.

Control returns unconditionally to the start of the loop.

## Acceptance examples

These are conditional static criteria, not runtime results. They assume execution reaches the operations, accesses are valid, and required breakpoint continuation occurs.

1. **Unsigned paired-result shifts.** If D-09’s low component is `0xFC000003`, the write at base offset `0x26C` receives `63`. The later captured-destination write receives `0xF000000C`.

2. **Mixed arithmetic in D-06.** If the signed high and low components are −2 and 1, their initial signed sum is −1. Adding the unsigned zero yields the 32-bit argument pattern `0xFFFFFFFF`. If instead the initial signed addition overflows, its behavior is documented_only; the later unsigned addition does not establish a result.

3. **Unsigned constant derivation.** The constant-derived shift and multiplication yield `0x21C4`; the subsequent read is at `0x2218`. No signed-overflow caveat is needed for that derivation.

4. **Address-halfword boundary.** If the address halfword is `0xFFFF`, its unsigned fourfold product is `0x3FFFC`, the low-component word-write address is `0x40070`, and the byte-source address is `0x4FFFB`. These calculations do not overflow their represented widths.

5. **Negative incoming register value.** If the propagated halfword is `0x0020` and the incoming register value is −48, the final byte-store integer address is `0x00000009`: unsigned addition wraps modulo \(2^{32}\). Whether address 9 is writable remains unresolved.

6. **Captured global.** If D-07 changes the first global slot, the zero-byte write still targets captured-base offset `0x15`, provided that storage remains writable.

7. **Breakpoint boundary.** If execution does not resume beyond the breakpoint, no subsequent address construction, post-breakpoint read or write, or call D-20 through D-37 is reached. Earlier effects are not undone.

8. **Unsigned propagation and truncation.** A propagated halfword of `0xFFFF` produces word payloads `0x0000FFFF` at distribution-base offsets `0x54` and `0x64`. A distribution base of `0x12345678` produces halfword payload `0x5678` after D-31.

9. **Byte capture timing.** If the byte captured before D-34 is `0x7A`, changing its source during D-34 does not change the represented payload of the subsequent byte write.

10. **Repeated adjustment and accounting.** Starting at base `0x2000`, two completed adjustments produce `0x1E18` if nothing else changes the represented base. Each fully continued iteration issues seven word, five halfword, and three byte writes, regardless of aliasing.
