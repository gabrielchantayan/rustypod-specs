# F-38f7a73546d9

## Purpose

F-38f7a73546d9 obtains a descriptor from either a parsing dependency or a caller-supplied cache, optionally checks two descriptor attributes, and publishes the resulting extent, attributes, flags, and updated cursor.

The function supports three result classes:

- **Success:** returns the 32-bit value 1 and publishes outputs.
- **Ordinary failure:** returns the 32-bit value 0, generally after invoking a diagnostic dependency.
- **Nonreporting attribute mismatch:** returns the 32-bit value `0xffffffff` without invoking the diagnostic dependency for that mismatch.

A cache can retain a parsed descriptor across a nonreporting mismatch or across successful calls that bypass attribute checking. A successful checked match invalidates the cache before publishing outputs.

These are observations from the supplied static representation, not verified runtime behavior. The descriptor’s application-level meaning is unknown.

## Interface

### Representation model

The supplied representation uses 32-bit words for cursor values, extents, attributes, flags, and arithmetic involving addresses. Byte outputs and the cache-valid marker are 8 bits.

Several descriptor values are represented with pointer-like types in the supplied material. This contract treats them as opaque 32-bit quantities unless they participate in cursor arithmetic. Their apparent pointer types do not establish additional indirection or an ownership relationship.

The interface has eleven positional arguments:

| Position | Contract role |
|---|---|
| 1 | Optional address for a 32-bit extent output. |
| 2 | Optional address for a 32-bit first-attribute output. |
| 3 | Optional address for an 8-bit second-attribute output. |
| 4 | Optional address for an 8-bit remainder-mode flag output. |
| 5 | Optional address for an 8-bit secondary flag output. |
| 6 | Required address of a 32-bit cursor slot, read on entry and updated on success. |
| 7 | A 32-bit available-length value, used with signed comparisons and cursor-relative arithmetic. |
| 8 | A 32-bit expected first attribute. Its signed interpretation enables or disables checking. |
| 9 | A 32-bit expected second attribute, consulted only when checking is enabled. |
| 10 | A 32-bit mismatch-policy selector: zero reports a mismatch; any nonzero value returns the nonreporting mismatch result. |
| 11 | Optional address of a mutable cache record. |

Arguments 1–5 may independently be absent. Argument 6 is dereferenced unconditionally before cache selection and therefore must identify readable storage even on a later failure path. Successful execution also requires it to be writable.

The function does not directly inspect the data addressed by the cursor. Any such inspection belongs to F-fa1c60bee3f0.

### Cache layout

When argument 11 is present, the following byte offsets are used:

| Offset | Width | Meaning |
|---|---:|---|
| 0 | 1 byte | Valid marker; zero means parse afresh, any nonzero value means reuse. |
| 1–3 | 3 bytes | Not directly accessed. |
| 4 | 4 bytes | Descriptor flags. |
| 8 | 4 bytes | Raw extent. |
| 12 | 4 bytes | First attribute. |
| 16 | 4 bytes | Second attribute. |
| 20 | 4 bytes | Cursor displacement relative to the entry cursor. |

The highest accessed byte is at offset 23. The cache must support the indicated byte and word accesses. Alignment and byte order follow the target environment; neither is independently established by the supplied material.

A reused cache is trusted without validating its origin, consistency, or relationship to the current input. Its stored displacement is added to the cursor read on this invocation, rather than treated as an absolute address.

### Return value

The return width is 32 bits:

- `0x00000001`: success.
- `0x00000000`: ordinary failure.
- `0xffffffff`: nonreporting attribute mismatch.

Whether a caller interprets the last value as signed −1 or unsigned 4,294,967,295 is outside this function.

## Behavior

### 1. Entry and descriptor selection

The function first reads the entry cursor from argument 6. If a cache is present, it then reads the cache-valid byte.

It invokes F-fa1c60bee3f0 when either:

- no cache is supplied; or
- the supplied cache-valid byte is zero.

Before that call, a private cursor slot is initialized with the entry cursor. The dependency receives addresses for that cursor and three descriptor fields, together with argument 7. The function uses the dependency’s 32-bit return value as flags.

The three descriptor fields have no established initialization before the dependency call. Defined subsequent behavior therefore requires the dependency to supply every field that the selected path reads.

When the cache-valid byte is nonzero, the function does not invoke the parsing dependency. Instead, it reads cached fields in this order:

1. Flags at offset 4.
2. Raw extent at offset 8.
3. Second attribute at offset 16.
4. First attribute at offset 12.
5. Displacement at offset 20.

It reconstructs the working cursor by adding the displacement to the entry cursor.

### 2. Fresh-cache publication and preliminary bound check

After a fresh parse, if a cache exists, the function writes:

1. Flags at offset 4.
2. Raw extent at offset 8.
3. Second attribute at offset 16.
4. First attribute at offset 12.
5. Working-cursor displacement at offset 20.
6. The value 1 to the valid byte at offset 0.

The displacement is the working cursor minus the entry cursor.

Only this fresh-parse, cache-present path performs the preliminary bound check. The check applies when both flag bit `0x80` and flag bit `0x01` are clear.

Under that condition, the function compares argument 7 with:

**working-cursor displacement + raw extent**

The comparison is signed. If argument 7 is less than that sum, it invokes F-4fc89ec41a6d with the five numeric arguments:

**13, 104, 155, 0, 0**

If that dependency returns, the function clears the cache-valid byte and returns 0.

Consequences:

- No equivalent bound check is directly performed when no cache is supplied.
- Reusing a valid cache bypasses this bound check.
- Flag bit `0x01` bypasses it.
- Flag bit `0x80` bypasses this particular check and is handled separately.
- A failed preliminary check leaves the newly written descriptor fields in the cache; only the valid marker is cleared.

### 3. Fatal descriptor flag

After obtaining the descriptor, the function tests flag bit `0x80`.

If set, it invokes F-4fc89ec41a6d with:

**13, 104, 102, 0, 0**

If the dependency returns:

- A present cache has its valid marker cleared.
- The function returns 0.
- No ordinary result output or final cursor write occurs.

This path precedes attribute matching and success publication.

### 4. Optional attribute matching

When bit `0x80` is clear, argument 8 is interpreted as a signed 32-bit value.

If it is negative, attribute checking is skipped entirely. Argument 9 has no effect on this path.

If argument 8 is nonnegative, the function requires both:

- Argument 8 equals the descriptor’s full 32-bit first attribute.
- Argument 9 equals the descriptor’s full 32-bit second attribute.

The second comparison is relevant only after the first matches. Matching uses the complete second attribute, not the byte eventually published through argument 3.

On mismatch:

- If argument 10 is zero, a present cache is invalidated **before** the diagnostic call. The function invokes F-4fc89ec41a6d with **13, 104, 168, 0, 0**, then returns 0 if that dependency returns.
- If argument 10 is nonzero, the function returns `0xffffffff` without a mismatch diagnostic and without directly changing the cache-valid marker.

Neither mismatch path publishes ordinary outputs or updates the caller’s cursor slot.

On a successful checked match, a present cache is invalidated before output processing. A success that skipped checking does not directly invalidate the cache.

### 5. Extent selection and successful publication

If flag bit `0x01` is set, the published extent is:

**argument 7 − working-cursor displacement**

Otherwise, the published extent is the raw descriptor extent.

The function then performs the following writes, omitting each optional write whose destination is absent:

1. Argument 4 receives `flags & 0x01` as one byte: either 0 or 1.
2. Argument 5 receives `flags & 0x20` as one byte: either 0 or 32.
3. Argument 1 receives the selected extent as a 32-bit word.
4. Argument 3 receives the low eight bits of the second attribute.
5. Argument 2 receives the full 32-bit first attribute.
6. Argument 6 receives the working cursor as a 32-bit word.

It then returns 1.

The secondary flag output is a bit mask, not a normalized Boolean.

### Arithmetic boundaries

Cursor subtraction, displacement storage, cursor reconstruction, extent adjustment, and the preliminary bound expression operate on 32-bit quantities in the supplied representation. Length comparisons and the checking-enable test use signed interpretations.

There is no explicit overflow check, negative-length rejection, or check that the working cursor is at or beyond the entry cursor.

The supplied representation alone does not establish a portable overflow rule for every signed arithmetic expression. Acceptance expectations involving out-of-range signed intermediates remain undocumented beyond the visible 32-bit operations; they must not be replaced with an assumed wider calculation.

## Side effects

### Direct memory effects

The function directly accesses:

- The required cursor slot.
- Optional output destinations on success.
- The cache-valid byte and cache fields when a cache is supplied.
- Private temporary storage passed to the parsing dependency.

It performs no explicit allocation or release. This does not establish that its dependencies allocate nothing, release nothing, or retain no references.

Failure does not imply absence of side effects. A fresh parse may already have occurred, and a cache may already have been populated or invalidated. Dependencies may also have effects not visible in the supplied body.

### Ordering and aliasing

The read and write orders above matter if caller-provided regions overlap.

In particular:

- The entry cursor is captured before any direct cache write.
- Fresh-cache payload fields are written before the valid marker is set.
- A checked match clears the marker before optional output writes.
- A reporting mismatch clears it before the diagnostic call.
- A fatal descriptor or preliminary bound failure clears it after the diagnostic call returns.
- The final cursor write follows every optional output write.

No aliasing checks are present. With overlapping destinations, later writes can overwrite earlier results. A cache marker cleared during matching can also be overwritten by a later successful output if the regions overlap.

The independent-field meanings in this contract assume nonoverlapping storage. For overlapping storage, the ordered accesses are the applicable description.

### Ownership and concurrency

No direct ownership transfer is established for any argument. The function itself stores no caller pointer in persistent storage visible in the supplied body.

Dependency retention and ownership behavior are unknown. No synchronization is visible; a valid marker is not evidence of atomic publication or thread-safe cache sharing.

## Acceptance examples

These are conditional contract examples, not executed tests. Unless stated otherwise, storage is valid and nonoverlapping, arithmetic remains within signed 32-bit range, and dependencies return without modifying unrelated caller storage.

### Fresh cached success with checking disabled

Suppose the entry cursor is 1,000 and the cache-valid byte is zero. F-fa1c60bee3f0 produces:

- Working cursor: 1,004.
- Raw extent: 12.
- First attribute: 7.
- Second attribute: `0x123`.
- Flags: `0x20`.

Let available length be 20 and argument 8 be negative.

The preliminary bound passes because 20 is not less than 4 + 12. The function returns 1, publishes extent 12, first attribute 7, second-attribute byte `0x23`, remainder flag 0, secondary flag 32, and cursor 1,004.

The cache remains valid and stores displacement 4.

### Reused cache with a relocated entry cursor

Suppose a valid cache stores displacement 4, raw extent 12, first attribute 7, second attribute `0x123`, and flags `0x20`.

With entry cursor 2,000, available length 1, and checking disabled, the function does not parse or perform the fresh-cache bound check. It returns 1, publishes extent 12, and updates the cursor to 2,004.

This example demonstrates the absence of that bound check on reuse; it does not establish that the cached descriptor is safe for the new input.

### Nonreporting mismatch retains a fresh descriptor

Suppose a fresh parse passes the preliminary check but produces first attribute 7 while argument 8 is 8. Argument 10 is nonzero.

The function returns `0xffffffff`, invokes no mismatch diagnostic, leaves ordinary outputs and the cursor slot unwritten, and retains the newly valid cache for possible reuse.

### Reporting mismatch invalidates before reporting

With the same mismatch but argument 10 equal to zero, the function clears the cache-valid byte, invokes F-4fc89ec41a6d with the mismatch arguments, and returns 0 if it returns.

No ordinary outputs are published.

### Full-width match, truncated output

Suppose the descriptor’s second attribute is `0x123`.

An expected second attribute of `0x23` does not match. An expected second attribute of `0x123` can match, provided the first attribute also matches. On successful publication, argument 3 still receives only `0x23`.

### Remainder-mode extent

Suppose the entry cursor is 1,000, the working cursor is 1,006, available length is 20, and flags include `0x01` but not `0x80`.

The raw extent is ignored for successful extent publication. The published extent is 14, and the remainder flag output is 1. A fresh supplied cache bypasses the preliminary bound check because bit `0x01` is set.

### Preliminary bound failure

Suppose a fresh cached parse produces displacement 4, raw extent 12, and flags zero, with available length 15.

The function first writes the cache payload and marks it valid. It then invokes the bound-failure diagnostic because 15 is less than 16. If that call returns, it clears the marker and returns 0 without publishing ordinary outputs.

### Fatal descriptor

If obtained flags contain `0x80`, the function invokes the fatal-descriptor diagnostic, then clears a present cache marker and returns 0 if the dependency returns. Attribute expectations and mismatch policy do not change this result.
