# F-d48e36e343d0

## Purpose

F-d48e36e343d0 performs four ordered 32-bit memory writes using two externally held base pointers.

Its established behavior is to:

- Store the first input word at offset 0 from the first base.
- Store the second input word at offset 12 from a previously captured first base.
- Copy the word at offset 0 of the second base to offset 4.
- Copy the word at offset 12 of the captured second base to offset 8.

The function does not return a result. Its externally visible result is the changed memory.

A possible intent is to update the outer words of one four-word region and populate the inner words of another region from its outer words. That interpretation is not needed to describe the behavior and does not establish that either region is an array, record, device register block, or particular application object.

## Behavior

### First-base stores

Before either input is written, the function computes and retains an address three words beyond the first base. Three words means 12 bytes; the calculation does not scale by either input value.

It then writes the first input word through the first base holder at offset 0.

Next, it writes the second input word through the previously retained offset-12 address.

The retention of that second destination is significant. The offset-12 destination is selected before the first input store, rather than recalculated after that store. If the first store changes the first base holder through aliasing, the retained destination does not follow the changed holder.

The supplied representation separately references the first base holder when forming the retained destination and when selecting the offset-0 destination. Under ordinary sequential execution with no intervening external mutation, these references yield the same base. The evidence does not establish a synchronization or volatile-access contract governing concurrent changes.

### Second-base copies

Only after both input stores does the function capture the second base.

Consequently, the second-base operations use the holder’s state at that later point. They are not guaranteed to use its entry value: either input store could affect the second base holder if the memory layout permits such aliasing.

The function then copies the 32-bit word at offset 0 of the second base into offset 4 of that base.

After that copy completes, it reads the word at offset 12 of the captured second base and writes that value to offset 8 of the captured second base.

The captured second base is retained across these two copy operations. The last copy therefore does not reload its base from the global holder.

The first copy expression also references the second base holder directly for its source and destination. With a stable holder, the direct references and the captured pointer identify the same region. The supplied evidence does not establish a stricter ordering among those direct holder reads, nor a machine-level guarantee about how many physical pointer loads occur.

### Ordering and aliasing

The established order of destination writes is:

1. First input at the first base’s offset 0.
2. Second input at the retained first-base offset 12.
3. Second-base offset 0 copied to offset 4.
4. Captured second-base offset 12 copied to offset 8.

The source read for the final copy occurs after the preceding copy, not as part of an entry-time snapshot. Likewise, the second-base source values are read after both input stores.

The function provides no non-overlap check or temporary snapshot of all source words. If the regions overlap, later reads may observe values written earlier in the same invocation. A contract requiring copies of the original entry-state values would therefore be incorrect.

Aliasing with the pointer holders themselves requires additional care. Such a write can change an address used later in the invocation. Ordinary overlapping data regions and overlap with a pointer-bearing location are different cases; the latter can affect control of subsequent memory accesses, not merely their payloads.

### Arithmetic and boundary behavior

The only explicit address adjustment before the stores is three 32-bit words. The later indexed accesses use offsets of one, two, and three such words.

There is no loop, input-dependent iteration count, comparison, or numeric boundary case for either input word. Zero, all-one bits, and values with the high bit set follow the same store operations.

The evidence does not define behavior for address overflow or pointer arithmetic outside a valid region. It would be unsupported to promise modular address wrapping.
