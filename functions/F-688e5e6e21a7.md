# F-688e5e6e21a7

## Purpose

F-688e5e6e21a7 performs ordered action recognition and conditionally invokes one operation on a receiver. Its normal result reports recognition, not operation success.

The recognized action tokens, in precedence order, are:

1. `HandleNextDay`
2. `HandlePreviousDay`
3. `HandleSelect`

Recognition is determined by a comparison dependency: a zero result selects the corresponding branch; any nonzero result continues recognition. Exact string matching, case sensitivity, and input encoding are not established.

Each recognized branch compares the supplied candidate with external sentinel state. Equality suppresses the operation but still produces a result of `1`. Inequality causes one indirect operation call, followed by a result of `1` if that call returns normally. Failure to recognize any token produces `0`.

The token names suggest calendar navigation and selection. That is inferred intent only. The established behavior does not increment or decrement the candidate, validate a date, or establish what any selected operation does.

### Referenced state

Two external integer state locations are designated **G1** and **G2** in this contract. These are descriptive labels, not dependency identifiers.

- **G1** supplies navigation suppression values.
- **G2** supplies the selection suppression value.

Their application meanings, initialization, lifetime, synchronization, and permitted writers are unknown. They participate in equality comparisons with the 32-bit candidate in the supplied representation.

G1 has two distinct read roles:

1. Immediately after the first comparison returns, G1 is read unconditionally and its value is saved.
2. If the first comparison returned zero, G1 is read again for the next-action suppression comparison.

Only the previous-action branch uses the saved first value. The next-action branch uses the second read instead. The two reads must not be assumed to observe the same value.

Consequently, the explicit G1 read counts are:

| Recognized outcome | G1 reads |
|---|---:|
| Next action | Two |
| Previous action | One |
| Selection | One |
| No recognized action | One |

G2 is read once if and only if selection is recognized.

## Behavior

### Recognition and initial state read

Every invocation that reaches normal recognition first calls F-00000001 with the unchanged action value and the `HandleNextDay` token.

After that call returns, the function reads G1 and saves the value. This read occurs whether the comparison result is zero or nonzero.

The comparison result then determines the branch. Recognition stops at the first zero result; later token comparisons are not performed.

### Next-action branch

If the first comparison returns zero:

- The function reads G1 a second time.
- It compares the candidate with this second value, not with the saved first value.
- Equality returns `1` without a receiver dereference, table lookup, or operation call.
- Inequality causes the function to read the operation-table base from the receiver, read the operation address at byte offset `0x134`, and invoke F-00000002 with the receiver and original candidate.
- If that operation returns normally, the function returns `1`.

The first G1 read still occurs on this path, but its saved value does not determine suppression.

There is no visible dependency call between the two G1 reads. Nevertheless, the contract does not collapse them into one read or require equal observations. Concurrent-state behavior and the underlying memory semantics remain unspecified.

### Previous-action branch

If the first comparison returns nonzero, the function calls F-00000001 with the unchanged action value and the `HandlePreviousDay` token.

If this second comparison returns zero:

- The candidate is compared with the G1 value saved after the first comparison.
- Equality returns `1` without dispatch.
- Inequality causes the function to read the receiver’s operation-table base, read the operation address at byte offset `0x138`, and invoke F-00000003 with the receiver and original candidate.
- If the operation returns normally, the function returns `1`.

There is no second G1 read on this branch. A change to G1 during the previous-token comparison does not replace the already saved value used for suppression.

### Selection branch

If both navigation comparisons return nonzero, the function calls F-00000001 with the unchanged action value and the `HandleSelect` token.

If this third comparison returns zero:

- The function reads G2.
- It compares the candidate with that value.
- Equality suppresses dispatch.
- Inequality causes the function to read the receiver’s operation-table base, read the operation address at byte offset `0x12C`, and invoke F-00000004 with the receiver and original candidate.
- After suppression or normal operation return, the function returns `1`.

The relevant G2 observation occurs after the selection comparison returns. No earlier G2 capture is visible.

This path also includes the initial G1 read, although that saved value does not determine selection behavior.

### Unrecognized action

If all three comparisons return nonzero, the function returns `0`.

The visible sequence on this path includes:

- Three comparison calls, in next, previous, selection order.
- One G1 read, between the first and second comparison calls.
- No G2 read.
- No receiver dereference or operation-table lookup.
- No selected-operation call.

The candidate does not affect this outcome.

### Integer and address behavior

The candidate participates only in equality or inequality decisions. Signed minimum, signed maximum, zero, and negative values have no distinct treatment in the visible logic. Equality does not require a signed ordering interpretation.

No candidate arithmetic creates an overflow or underflow case within this function. Dispatch forwards the original 32-bit candidate without a visible adjustment or truncation.

Operation lookup uses the fixed byte offsets listed above. The representation contains no visible checks for address overflow, an invalid table base, insufficient table storage, a null target, or a target with an incompatible callable interface. Address-arithmetic and invalid-access behavior are not independently established.

- The next-action branch makes a second G1 observation; its suppression decision depends on that observation rather than the first.

- Changes to G2 before its selection-path read can affect selection suppression.
