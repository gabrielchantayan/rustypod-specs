# F-9cb625e2e9a1

## Purpose

F-9cb625e2e9a1 prepares a temporary record in one of two layouts, obtains a destination value indirectly through a caller-supplied object, and calls F-b0987b51cfe6 with that destination and the record address. It returns the captured dependency result after signed 16-bit conversion and extension to a signed 32-bit result.

The layout decision uses the 16-bit field at object byte offset 2, read after an initialization dependency returns:

- Exactly 0x4244 selects the layout called **compact** in this contract.
- Every other 16-bit pattern selects the layout called **alternate**.

These names describe the visible construction paths, not established protocol terminology. Submission, encoding, and initialization are likewise descriptive roles. Whether the operation transmits data, persists it, queues it, or accesses a device is not established.

### Initialization and layout selection

The following ordering is established:

1. Local payload copies are prepared.
2. F-6e3669b482ce is called with the record base.
3. After that call returns, the 16-bit object field at offset 2 is read.
4. The field is compared for exact equality with 0x4244.

Initialization is not proven to clear the record or establish any particular field values. Its return value is not used.

The layout field is not visibly captured before initialization. If initialization changes memory relevant to that field, the later read can observe the changed value. This contract does not assume that the dependency preserves the object or shared state.

The equality comparison has no mask, range check, or secondary condition. Although the read is represented as a signed 16-bit access, 0x4244 is positive and exactly representable; the branch distinction is the exact 16-bit pattern.

### Compact layout

When the post-initialization layout field equals 0x4244, the function performs these observable operations in order:

1. Stores a 16-bit field at record offset 28.
2. Calls F-946cac4b59bc with the first local payload value and the address at record offset 30.
3. After that call returns, stores the low 16 bits of the second local payload value at record offset 34.

The first field has numerical value:

$7 + 256 \times (\text{selector value modulo } 256)$

Thus, its low-order byte is 0x07 and its high-order byte is the selector argument’s low 8 bits. The value is always representable in 16 bits. Higher selector bits do not contribute to this store.

The first payload is supplied by value to F-946cac4b59bc, not by passing the address of its local copy. The dependency also receives a record-relative address, but its input interpretation, memory-access direction, and access extent are unknown.

The second payload’s explicit store occurs after the helper call. If the helper wrote bytes 34–35, the later store replaces those bytes. Such overlap is conditional: it is neither established nor authorized merely by the visible call.

There is no explicit compact-branch store to offset 31. No contractually established output area extends from offset 30 through offset 31.

### Alternate layout

For every other layout-field pattern, the function performs these operations in order:

1. Stores the 16-bit numerical value 10 at record offset 28.
2. Stores zero at record offset 31.
3. Stores the selector argument’s low 8 bits at record offset 30.
4. Calls F-42a35b3b505e with destination address offset 32 and the address of the first local 32-bit payload copy.
5. Calls F-42a35b3b505e with destination address offset 36 and the address of the second local 32-bit payload copy.

The zero store at offset 31 precedes the selector-byte store at offset 30. Both precede either helper call.

The two payload addresses identify separate local storage locations. Passing these addresses permits the dependency to access that storage according to its own contract; read-only use is not established. No payload-type interpretation follows from the address passing alone.

The first helper call completes before the second begins. Neither return value is inspected. There are no explicit record stores after these two calls and before submission. Consequently, dependency changes to earlier fields are not repaired or validated by this function.

### Destination lookup and final call

After completing either branch, the function obtains the first argument for F-b0987b51cfe6 through two dependent reads:

- A 32-bit pointer is read from object offset 0x154.
- A 32-bit value is read from the address designated by that pointer.

The second read’s value is passed as the first argument. The temporary record base is passed as the second argument.

Both reads occur after initialization and all branch-specific helper calls. The destination is not visibly cached before record preparation. Changes made by dependencies to the pointer field or its pointed-to storage can therefore affect the destination observed at submission.

There is no visible direct write to the caller-supplied object or destination storage.

Directly stored field values describe the state at those stores. They are not unconditional guarantees about the record’s contents when F-b0987b51cfe6 begins, because intervening dependencies may modify reachable memory.

The record and address-passed payload copies are temporary local storage, not caller-provided persistent storage. Pointer retention and the validity of any later use require separate dependency contracts; this function establishes no persistent lifetime guarantee.

The final result is returned without interpretation beyond the signed 16-bit conversion. Dependency exceptions, faults, nonreturning behavior, and invalid-memory consequences are not given a recovery protocol by this function.

### Alternate construction order

Then the alternate branch:

- Stores 10 at offset 28 as a 16-bit value.
- Stores zero at offset 31 before storing 0xFE at offset 30.
- Calls F-42a35b3b505e first with offset 32 and the first payload’s address.

### Initialization affects branch selection

If the layout field initially differs from 0x4244 but F-6e3669b482ce changes it to 0x4244 before returning, the compact branch is selected. The earlier field value is not the branch-selection snapshot.

### Late destination resolution

If a branch helper changes the pointer at object offset 0x154, the subsequent lookup uses the pointer observed after that helper returns.

If the pointer remains unchanged but its pointed-to 32-bit value changes before the final read, the first submission argument is the value observed by that read.

### Signed result conversion

Conditionally, if a wider dependency result of 0x00018001 is captured through its low 16 bits, the returned value is −32767. The original wider value is not preserved.
