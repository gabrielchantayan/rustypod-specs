# F-2ed72e31a28f

## Purpose

F-2ed72e31a28f transfers a rectangular sequence of 16-bit units between two memory regions, using independent source and destination coordinates and row strides.

The established behavior is an ordered sequence of individual source reads and destination writes. It is not a snapshot copy or an overlap-safe block transfer. A destination write can change the value obtained by a later source read.

The apparent intent is a two-dimensional data copy. The evidence does not establish that the units are pixels, that the buffers have a particular allocation type, or that the stride dependency is pure.

This contract describes static evidence. No runtime tests have been performed.

Starting columns and the row width are measured in two-byte units. Returned strides are used as byte displacements. The original units and meaning of the layout quantities are not established beyond their use as inputs to a one-bit left shift.

The interface supplies no buffer lengths, allocation boundaries, clipping rectangle, or address-space identifier.

## Behavior

### Dependency calls

The function first invokes F-082b668da333 with the source layout quantity shifted left by one bit and the source dependency parameter. Its result is retained as the source stride.

It then invokes F-082b668da333 with the destination layout quantity shifted left by one bit and the destination dependency parameter. Its result is retained as the destination stride.

For values where ordinary doubling is representable and the shift has that interpretation, the first argument of each call is twice the corresponding layout quantity. Negative or overflowing shift operands require the arithmetic qualifications in **Uncertainties**.

The two calls are ordered and distinct. Equal arguments do not establish equal results: no purity, determinism, or result reuse is shown.

There is no early dimension check. Both calls precede the function’s first explicit copy read, even when a dimension is zero or negative. Operations performed inside the dependency are not constrained by that statement.

### Initial addresses and signed displacements

The initial source address combines:

- The source base address.
- The source starting row multiplied by the returned source stride.
- Twice the source starting column.

The initial destination address combines the corresponding destination values independently.

For each region, the row displacement is the product of its starting row and returned stride. The column displacement is twice its starting column. Their sum determines the displacement relative to that region’s base, subject to arithmetic and address-representation limitations.

A negative coordinate alone does not determine whether the resulting address is before the base. A negative row multiplied by a negative stride contributes a positive displacement. Row and column contributions can reinforce, oppose, or cancel one another.

There is no explicit clipping, normalization, or bounds check.

### Per-unit transfer order

Each iteration reads one 16-bit unit from the current source address and then writes that value to the current destination address.

Within a row, successive source addresses differ by two bytes, and successive destination addresses differ by two bytes. The function does not read an entire row before writing it.

Thus, the explicit copy-access order is:

1. Read the first source unit.
2. Write its value to the first destination unit.
3. Read the next source unit.
4. Write its value to the next destination unit.
5. Continue in the same order.

The read for a particular transfer precedes its write. Its write precedes the next transfer’s read. This ordering describes the supplied function’s operations; it does not establish atomicity or a cross-thread memory-ordering guarantee.

### Ordinary rectangular traversal

For positive dimensions, valid accesses, and arithmetic without overflow, let:

- \(B_s\) and \(B_d\) be the source and destination bases.
- \(X_s,Y_s\) and \(X_d,Y_d\) be their starting columns and rows.
- \(P_s\) and \(P_d\) be the returned byte strides.
- \(W\) and \(H\) be the width and row count.

For row \(r\), where \(0 \le r < H\), and unit \(c\), where \(0 \le c < W\), the accessed addresses are:

\[
S(r,c)=B_s+(Y_s+r)P_s+2(X_s+c)
\]

\[
D(r,c)=B_d+(Y_d+r)P_d+2(X_d+c)
\]

Rows are processed in increasing row-index order, with increasing unit indices within each row. Actual addresses need not increase between rows: that depends on the returned strides.

### Row transitions

After each row’s final unit transfer, each running address has advanced by twice the positive width. The function then adds that region’s stride and subtracts twice the original width.

For an ordinary positive-width row, this places the next row start exactly one stride beyond the preceding row start. Source and destination strides may differ.

These adjustments also occur after the final row’s last write. No additional copy access is made through the resulting final addresses.

The inner countdown is reset from the original width for each row.

There is no requirement that a stride equal or exceed the copied row size. A smaller positive stride can make adjacent rows overlap. A zero stride repeats a row start. A negative stride places successive row starts at lower addresses, assuming nonwrapping arithmetic. None of these stride cases establishes memory validity.

### Dimension and countdown behavior

Both loops execute their bodies before testing their decremented counters.

Consequently:

- Width one transfers one unit per row.
- Row count one processes one row.
- Width zero still enters the first unit transfer.
- Row count zero still enters the first row.

Under a 32-bit modular countdown interpretation, a counter initially containing zero requires \(2^{32}\) decrements to reach zero again. An all-ones initial bit pattern requires \(2^{32}-1\) decrements. Other negative signed inputs likewise correspond to large iteration counts under that interpretation.

These totals are conditional, not unconditional completion guarantees. They require the modular model, normal dependency completion, and continued valid accesses. The exact arithmetic and fault semantics are not independently established.

The ordinary rectangular address formulas above apply to positive dimensions without overflow. They must not be used to treat zero width as an empty row.

### Overlap

There is no overlap detection, direction selection, or temporary source snapshot.

If the destination starts one unit after the source, an early write can overwrite the next source unit before it is read. This can propagate an earlier value through later transfers.

The same issue applies across rows. A write in one row can change source data read in a later row. Results are determined by the actual access sequence, not solely by the source region’s contents on entry.

- Row zero reads source-start offsets 0, 2, and 4.
- Row zero writes destination-start offsets 0, 2, and 4.
- Row one reads source-start offsets 10, 12, and 14.

### Positive coordinate displacement

With source starting row three, source stride sixteen bytes, and source starting column two, the first source read is 52 bytes beyond the source base:

\[
3 \times 16 + 2 \times 2 = 52
\]

### Negative row with negative stride

\[

### Opposing contributions and cancellation

With starting row negative three, stride sixteen bytes, and starting column twenty-five, the displacement is positive two bytes:

\[
(-3)\times16+2\times25=2
\]

Changing only the starting column to twenty-four makes the displacement zero. These cases demonstrate that the combined contributions, not a coordinate’s sign alone, determine the final position relative to the base.

### Forward-overlap propagation

Suppose three consecutive source units initially contain distinct values A, B, and C. With width three, one row, and destination beginning one unit after source:

- The first transfer reads A and overwrites B with A.
- The second reads the overwritten location and overwrites C with A.
- The third reads that overwritten location and writes A to the next destination unit.

The destination sequence becomes A, A, A. A snapshot-style result of A, B, C is not required.

### Zero and negative strides
