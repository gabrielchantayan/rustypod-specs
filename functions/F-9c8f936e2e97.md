# F-9c8f936e2e97

## Purpose

F-9c8f936e2e97 performs three preparatory calls, then searches a mutable sequence for a pattern and delegates handling of each match to a replacement dependency.

The established behavior differs from a conventional “replace all” contract:

- Searching starts at byte offset zero.
- After replacement returns, searching resumes at the same numeric offset.
- Pattern information is cached for one search pass but refreshed before replacement and on the next pass.
- Replacement metadata and the replacement address are obtained through separate descriptor-entry reads.
- Sequence addresses and lengths are repeatedly read through caller-supplied mutable indirection.
- Several descriptor-related addresses originate from separate evaluations of a global value, not one shared snapshot.
- The all-ones 32-bit position is a return sentinel.

**Inferred intent:** repeated substitution or normalization of a mutable byte sequence.

That intent does not establish dependency semantics, ownership, encoding, memory safety, or termination.

The second input identifies a slot containing an address, not the sequence payload itself. Dependencies receiving this slot may change which sequence subsequent reads observe.

There is no visible returned status, count, error object, or resulting sequence address. Any externally visible sequence result must be obtained through dependency-defined mutation, including possible changes to the supplied slot.

## Behavior

### 1. Ordered preparation

F-70b23748c374 is called three times before descriptor capture.

Each call receives the original opaque input and the original sequence-slot address. Its third argument is derived from a distinct global value:

1. First global value minus 20.
2. Second global value plus 24.
3. Third global value plus 4.

Each global is evaluated for its respective call. There is no joint snapshot before preparation begins. An earlier call may therefore affect a global read for a later call, the sequence, or descriptor state.

No preparatory return value is inspected. A dependency failure or nonlocal transfer is not handled by an explicit local recovery path.

The underlying global declarations are not supplied. These offsets establish the argument derivations, not a broader guarantee about their types, meanings, or overflow safety.

### 2. Separate descriptor-global evaluations

After all preparatory calls return, the function performs the following ordered setup:

1. Evaluates the descriptor-address global and retains that result as the **replacement-entry location**.
2. Evaluates the same global again and adds one four-byte entry to obtain the **pattern-entry location**.
3. Initializes the search position to zero.
4. Initializes one diagnostic context value to the captured pattern-entry location.
5. Evaluates the descriptor-address global a third time and retains that result as the other initial diagnostic context value.

These are three separate global evaluations. The final evaluation supplies the initial diagnostic context; it is not necessarily equal to the first evaluation used for the replacement-entry location.

If the global remains stable throughout setup, the two captured entry locations identify consecutive entries in one table, and the final context equals that table’s base. Without that stability assumption, those identities do not follow.

The replacement-entry and pattern-entry locations remain captured for subsequent accesses. Later changes to the descriptor-address global alone do not redirect them. Changes to the contents stored at those locations can affect later reads.

### 3. Load and check the pattern

At the start of every outer iteration, the function:

1. Reads the pattern address from the captured pattern-entry location.
2. Reads its unsigned 32-bit length four bytes before that address.
3. Compares the length against `0xfffffff1`.

A length strictly greater than `0xfffffff1` triggers F-5829ec5988c0. Thus `0xfffffff2` through `0xffffffff` trigger the call; `0xfffffff1` does not.

The diagnostic call receives ten visible arguments:

- The value 8.
- The same static diagnostic address twice.
- The loaded pattern length.
- The threshold `0xfffffff1`.
- Two diagnostic context values.
- Three additional machine-state values whose origins and meanings are not established.

On the first iteration, the context pair consists of the captured pattern-entry location and the result of the third descriptor-global evaluation.

After a replacement has returned, the pair is instead zero and the replacement metadata word saved before that replacement call.

There is no explicit local return or rejection immediately after the diagnostic call. If it returns normally, searching proceeds with the pattern address and length already loaded for this iteration. The function does not refresh them merely because the diagnostic dependency may have modified accessible state.

### 4. Search from the current position

For each candidate position, the function evaluates whether the 32-bit sum of the position and cached pattern length is no greater than the current sequence length.

Obtaining that length requires:

1. Reading the current sequence address from the caller’s slot.
2. Reading the unsigned length four bytes before that address.

When the bound admits a candidate, F-7f14f1ab6851 receives:

- A sequence address freshly read through the slot, plus the current position.
- The cached pattern address.
- The cached pattern length.

A zero result selects a match. Any nonzero result advances the position by one and causes another bound evaluation.

The sequence-slot read for the bound and the sequence-slot read for the comparison argument are distinct. No single sequence-address snapshot covers both operations. Nor is a sequence address retained across candidate comparisons.

The pattern address and length, by contrast, remain cached throughout this search pass. Changes to the pattern entry or its metadata during comparison do not refresh those cached values before the next candidate in the same pass.

If the bound fails, the function assigns the all-ones sentinel to the position.

### 5. Return on the sentinel

After candidate searching stops, the function checks whether the position equals `0xffffffff`.

If so, it returns without replacement. This applies both when the bound failed and when a comparison selected a match whose position representation is all ones.

The sentinel therefore cannot also serve as an ordinary replacement offset.

### 6. Read replacement metadata before forming call arguments

For a nonsentinel match, the function first:

1. Reads an address from the captured replacement-entry location.
2. Reads the raw 32-bit metadata word four bytes before that address.
3. Saves that word as the second diagnostic context value.
4. Sets the first diagnostic context value to zero.

These operations precede evaluation of the replacement-call argument expressions. Their ordering is not subject to the uncertainty about ordering among those later expressions.

In particular, the address used to locate the saved metadata is not retained as the eventual replacement-address argument.

### 7. Form and invoke replacement

The subsequent call to F-07b885b63fa9 receives five arguments:

1. The original sequence-slot address.
2. The matching position.
3. A newly read pattern metadata word.
4. A newly read replacement address.
5. The replacement metadata word saved in the preceding step.

Obtaining the third argument requires rereading the captured pattern entry and then reading four bytes before the resulting address. It does not simply reuse the cached search length.

Obtaining the fourth argument requires rereading the captured replacement entry. This is separate from the earlier entry read used to locate replacement metadata.

Consequently:

- The pattern metadata passed to replacement can differ from the length used to find the match.
- The saved replacement metadata can have been read before a different replacement address from the one ultimately passed.
- Neither descriptor is consumed as an atomic snapshot.

The supplied representation does not establish the relative evaluation order of the replacement-address argument and the refreshed pattern-metadata argument. It does establish that the saved replacement metadata and zero diagnostic context were assigned before those argument evaluations.

No replacement return value is inspected.

### 8. Restart at the same position

After replacement returns, the function starts another outer iteration without advancing the position.

It reloads the pattern address and length, performs the diagnostic check again, and searches using freshly read sequence state.

This permits a replacement to expose or create another match at the same offset. It does not cause positions earlier than that offset to be rescanned.

No iteration limit, progress check, or intrinsic termination guarantee appears.

### Integer and address arithmetic

Lengths and descriptor entries are 32 bits. The search-bound expression uses unsigned 32-bit arithmetic because the pattern length is unsigned.

The bound must not be interpreted as an unbounded mathematical sum: wrapping can make a position-plus-length result satisfy the comparison despite the corresponding mathematical sum exceeding the sequence length.

The position is also represented in a 32-bit integer-sized quantity. The supplied representation does not independently establish language-level signed-overflow semantics for its increment.

Neither the large-pattern diagnostic nor the bound proves that a candidate address is valid. Exact exceptional behavior for extreme positions, pointer arithmetic, and allocation extents remains documented_only.

## Acceptance examples

These are conditional consequences of static evidence, not observed executions.

For the ordinary search examples below:

- The stated sequence and descriptor state exists **at the start of searching, after preparation and descriptor capture**.
- Memory is valid and sizes do not overflow.
- Comparison returns zero exactly for equal byte ranges and preserves the sequence slot, sequence bytes, descriptors, and relevant metadata.
- Replacement and diagnostic behavior is constrained explicitly where needed.
- Returning dependencies do not invalidate storage required by later accesses.

Preparation is not assumed to preserve any state that existed before its calls.

Offsets 0, 1, and 2 are compared in that order. The bound then fails at offset 3. No replacement occurs, and the function returns.

### Pattern longer than sequence

The initial bound fails. No comparison or replacement occurs, and the function returns.

### Final-offset match and restart

At search start, the sequence is `abx` and the pattern is `x`.

Offsets 0, 1, and 2 are compared, with a match at 2. Equality in the bound permits that final offset.

Assume replacement changes only the matched `x` to `y`, leaving the sequence length, slot, descriptors, and relevant metadata otherwise unchanged. The next search begins at 2, compares `y` against `x`, then fails the bound at 3 and returns.

### Deletion exposes another match

At search start, the sequence is `xx` and the pattern is `x`.

Assume each replacement removes exactly the matched byte, updates the sequence slot and length as necessary, preserves the pattern and descriptors, and makes no other relevant changes.

Replacement occurs twice at offset 0. After the second removal, the nonempty pattern does not fit the empty sequence, so the function returns.

### No-progress replacement

At search start, a match exists. Assume replacement returns while leaving all relevant sequence and descriptor state unchanged.

The next pass selects the same match at the same position. Under these continuing assumptions, replacement repeats indefinitely.

### Zero-length pattern

At search start, the pattern length is zero. Do not impose the ordinary example’s equality rule on the comparator for this case; its zero-length result is an explicit condition.

If comparison returns zero and replacement preserves relevant state, repeated replacement can occur at the same position indefinitely.

If comparison always returns nonzero and preserves relevant state, positions advance through the sequence length inclusive before the bound fails, for ordinary non-overflowing sequence lengths.

### Diagnostic boundary

A loaded pattern length of `0xfffffff1` does not trigger diagnostics. A loaded length of `0xfffffff2` does.

If the diagnostic dependency returns and preserves the relevant memory, search continues with the already cached pattern address and length. This example asserts no safe payload access or eventual termination for such large lengths.

### Pattern metadata changes during comparison

As an exception to the ordinary examples’ preservation assumption, suppose a successful comparison changes only the pattern metadata from the searched length to another value and leaves the required storage valid.

The replacement call receives that subsequently read metadata value, not the cached search length.

### Replacement-entry changes between reads

If the replacement entry yields one address when its metadata is saved and a different address when the call argument is evaluated, replacement receives the earlier saved metadata together with the later address.

This is a conditional read-order consequence. It does not establish that such an intervening change occurs in ordinary execution.

### Descriptor-global evaluations differ

If the three capture-time global evaluations yield different values, the replacement-entry location comes from the first, the pattern-entry location from the second plus four bytes, and the initial second diagnostic context from the third.

No single-table interpretation is required by that trace.
