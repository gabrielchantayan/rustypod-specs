# F-82ac7de68a61

Addresses and payloads depend on explicit arguments, additional incoming machine state, global sources, an indirectly loaded word, an indirectly loaded byte, and the address associated with F-c0fbccd0fda8.

The contract describes the supplied static representation; it does not establish that every represented access is executable or reachable on an actual target.

### Primary-base phase

The primary-base source is first read into a retained signed 32-bit value, called the **retained primary base**.

The next byte store does **not** use that retained value as its destination base. It references the primary-base source again:

- Its destination is the newly referenced primary-base value plus the ambient offset.
- Its payload is the low eight bits of the ambient halfword.

The retained value and the value used by this byte store may be equal under ordinary, stable-memory assumptions. Their equality is not an unconditional property of the representation. The two source references must remain distinct in this contract; physical load count and compiler treatment depend on memory and volatility semantics that are not supplied.

After this byte store, the remaining primary-phase accesses occur in order:

1. Capture the byte-source value as a retained 32-bit value.
2. Read a signed 32-bit word at the retained primary base plus 89 bytes. This is the **loaded word**.
3. Store the halfword value 89 at the retained primary base plus the shifted value.
4. Store the low 16 bits of the loaded word at the loaded word plus 89 bytes.
5. Store the ambient halfword at twice the retained primary base.
6. Store the loaded word as a 32-bit word at twice the address associated with F-c0fbccd0fda8.

Thus, subsequent primary-phase operations use the **retained** primary base, not a fresh primary-base reference.

The loaded word is both data and an address component. Nothing checks that the resulting destination is writable. Likewise, using the address associated with F-c0fbccd0fda8 does not invoke that dependency or establish that the doubled address belongs to valid writable storage.

### Secondary-base phase

The secondary-base source is captured into a retained signed 32-bit value, called the **retained secondary base**.

Next, one byte is read from the address obtained by unsigned 32-bit doubling of the ambient word. This is the **loaded byte**. Its integer interpretation depends on plain-character signedness:

- Signed eight-bit interpretation yields values from −128 through 127.
- Unsigned interpretation yields values from 0 through 255.

A halfword store follows. It contains **two further references to the secondary-base source**:

- One supplies the destination base, to which the integer-converted loaded byte is added.
- The other supplies the payload, narrowed to 16 bits.

Neither reference is replaced by the earlier retained secondary base in the supplied representation. Evaluation order between the destination-base reference and the payload reference is not established. Equality among these two values and the retained secondary base is conditional on the source’s memory semantics and stability.

After that halfword store:

- A byte at twice the **retained secondary base** receives the low eight bits of the retained byte-source value.
- A byte at the terminal-base value plus the loaded word plus the terminal offset receives the low eight bits of the ambient word.

The terminal-base source is referenced for this final store after the preceding stores. Earlier writes may affect it through aliasing; an entry-time snapshot must not be substituted.

### Indirect transfer

After all thirteen stores, the unresolved target receives three represented arguments:

1. The loaded byte converted to a signed integer, subject to its original character interpretation.
2. The dispatch-data value.
3. Twice the shifted value, combined by addition with a Boolean increment.

The increment is:

| Condition | Increment |
|---|---|
| Shift count is zero and second argument is zero | 1 |
| Shift count is zero and second argument is nonzero | 0 |
| Shift count is nonzero | Bit at position one less than the shift count in the third argument |

For a zero count, short-circuit evaluation avoids the bit-extraction branch involving count minus one. This does not protect the separate right shift used to form the shifted value, nor does it define oversized shifts.

The doubling of the shifted value is represented as signed arithmetic **before** its addition to the explicitly unsigned Boolean value. Consequently, unsigned final addition does not retroactively make an overflowing signed multiplication defined. Where the signed shift and doubling are defined, conversion for the final unsigned addition gives a 32-bit unsigned result.

The dispatch-data reference occurs as part of the call expression after the preceding stores. Its order relative to evaluation of the other argument expressions is not established. Those other expressions contain no additional explicit memory reads.
