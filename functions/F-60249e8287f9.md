# F-60249e8287f9

## Purpose

F-60249e8287f9 implements an ordered protocol of memory accesses and dependency invocations. Two comparisons on implicit execution-state values select between:

- A **return-capable continuation**, which updates two global destinations, consumes a byte through a retained pointer, and invokes a completion sequence.
- A **terminal continuation**, which performs additional word and halfword accesses and reaches an endpoint designated nonreturning.

The evidence establishes this protocol, not an application-level purpose. It does not establish initialization, exception handling, object construction, or resource management.

All behavior below is conditional on preceding accesses and invocations completing. “Return-capable” identifies a represented ordinary return, not a guarantee that execution reaches it.

## Interface

### Inputs and outputs

The represented interface has no explicit parameters and no explicit return value. Its effective inputs are implicit execution state, global storage, addressed memory, and dependency outputs.

| Contract role | Meaning |
|---|---|
| Primary base | An unsigned 32-bit value used for addressing; its signed 32-bit interpretation also controls continuation selection |
| Secondary base | An unsigned 32-bit value used for addressing and the first selection comparison |
| Control link | An incoming value from which the first invocation target is derived |
| Source datum | Global storage converted to the byte written during the common prefix |
| Captured word | A retained signed 32-bit value read during the common prefix |
| Returned pointer | The high 32 bits of F-f96e6bdb2333’s 64-bit result, interpreted as a pointer |

The initial invocation occurs before the source datum is read and before either direct common-prefix memory access. Consequently, the source datum is not necessarily its entry-time value.

Dependency contracts are unavailable. The representation’s continued use of implicit state does not independently prove that dependencies preserve that state.

### Widths and layout

The represented widths are:

- Byte: 8 bits.
- Halfword: 16 bits.
- Word and pointer representation: 32 bits.
- Split dependency result: 64 bits.

Splitting a result into low and high 32-bit portions is a numerical operation; it does not establish memory byte order.

The common memory locations are:

| Location | Access |
|---|---|
| Secondary base plus `0x3c` | Byte write |
| Primary base plus `0x34` | Signed word read |

The terminal continuation additionally accesses a word at primary base plus `0x10`, a signed word at captured word plus `0x30`, and an unsigned halfword at the resulting nested base plus `0x43`. Other destinations are fixed or derived as described below.

Two global destinations are assigned on the return-capable continuation. A supplied overlap warning means these destinations must not be assumed independent of smaller symbols at their addresses. Their full declarations and storage extents are unavailable.

## Behavior

### Common protocol and continuation selection

The first dependency, F-opaque-01, is invoked through a target derived from the control link plus `0xea8`, without explicit arguments.

After that invocation returns, the function retains the result of comparing the secondary base against `0xffffffc7` as unsigned 32-bit values. This decision precedes the byte write and is not recomputed later.

The common protocol has the following observable ordering:

| Order | Required event |
|---:|---|
| 1 | Convert the source datum to a byte and write it at secondary base plus `0x3c` |
| 2 | Read and retain the signed word at primary base plus `0x34` |
| 3 | Invoke F-f96e6bdb2333 without explicit arguments |
| 4 | Store its high 32 result bits, interpreted as a pointer, at primary base plus `0x28` |

The source datum’s original storage width is unavailable. The represented byte conversion supplies only the byte-sized value to the destination.

F-f96e6bdb2333’s low 32 result bits are also retained for one terminal route. Neither continuation performs its continuation-specific direct effects before the common pointer store.

Selection is determined as follows:

| Secondary-base condition | Signed primary-base condition | Selected continuation |
|---|---|---|
| At most `0xffffffc7` | Irrelevant | Terminal, selector `0x08573680` |
| Greater than `0xffffffc7` | At most `0x59` | Terminal, selector `0x2b` |
| Greater than `0xffffffc7` | Greater than `0x59` | Return-capable |

The qualifying secondary-base range contains 56 values: `0xffffffc8` through `0xffffffff`. A primary-base pattern with its top bit set is negative under the represented signed interpretation and cannot select the return-capable continuation.

The captured word reflects memory after the common byte write. If those locations overlap, the read can observe the write. Subsequent uses consume the retained word rather than rereading its original location.

### Return-capable continuation

F-opaque-02 is invoked before the continuation’s direct global and byte accesses. After it returns, the following ordering is required:

1. The first global destination receives the captured word reduced by `0x5a`.
2. A byte is read through the returned pointer and retained.
3. The second global destination receives the transformed pointer value.

The pointer transformation uses its signed 32-bit interpretation, shifts right by 16, and then shifts left by 20. Its result depends on unresolved signed-shift and overflow semantics. An unconditional wrapping interpretation is not established.

This ordering matters when storage aliases. For example, the first global assignment can change the byte subsequently read through the pointer. Neither global assignment replaces the retained pointer used for later arguments.

The remaining dependency protocol is ordered by the rows below:

| Dependency | Explicit input and result use |
|---|---|
| F-opaque-03 | Receives the transformed pointer value, then the original returned pointer |
| F-opaque-04 | Receives an unsigned 32-bit secondary-channel observation available after F-opaque-03, logically shifted right by 17 |
| F-opaque-05 | Supplies a 32-bit primary result |
| F-opaque-06 | Receives that primary result, then the retained byte promoted to an integer and shifted right by nine |
| F-opaque-07 | Invoked without explicit arguments |
| F-opaque-08 | Receives a signed 32-bit secondary-channel observation available after F-opaque-07, shifted right by 18; supplies a signed 32-bit primary result |
| F-opaque-09 | Receives F-opaque-08’s result, then that same result shifted right by 14 |
| F-opaque-10 | Invoked without explicit arguments |
| F-opaque-11 | Invoked without explicit arguments |
| F-opaque-12 | Invoked without explicit arguments |
| F-opaque-13 | Unresolved indirect transfer represented as an invocation without explicit arguments |

For F-opaque-06’s second argument, byte signedness matters. Unsigned promotion produces zero for every possible byte after the nine-bit shift. Signed promotion with arithmetic right shift produces negative one for negative byte values and zero otherwise. Neither interpretation is established unconditionally.

No further direct data-memory access is represented once F-opaque-03 begins. This does not restrict memory effects inside dependencies.

An ordinary return follows F-opaque-13 in the representation. Its unresolved target and behavior prevent any guarantee that the function actually returns.

### Terminal continuation

The terminal selector determines an early halfword destination and a later word value:

| Selector | Early zero-halfword destination | Later word value |
|---|---:|---:|
| `0x08573680` | `0x0857371a` | `0x085736ea` |
| `0x2b` | `0x000000c5` | `0x00000095` |

These are respectively selector plus `0x9a` and selector plus `0x6a`.

#### Initial storage and halfword phase

The primary base is written as a word at primary base plus `0x10`. A signed word is then read at captured word plus `0x30` and retained as the nested base. If these locations overlap, the nested-base read occurs after the write.

F-opaque-14 receives an unsigned 32-bit quantity shifted left by 20:

- For selector `0x08573680`, the quantity is F-f96e6bdb2333’s low 32 result bits.
- For selector `0x2b`, the quantity is the primary base logically shifted right by eight.

F-opaque-15 follows without explicit arguments.

After both invocations return, the required access order is:

| Order | Access |
|---:|---|
| 1 | Write a zero halfword at the selector-derived destination |
| 2 | Read and zero-extend the unsigned halfword at nested base plus `0x43` |
| 3 | Write a 16-bit secondary-channel value at absolute address `0x20` |

The halfword read is therefore between the two writes. The value written at `0x20` is not established as zero, nor is its producer established by a dependency contract.

#### Result-dependent storage phase

F-opaque-16 receives `0x21`, followed by F-opaque-17 receiving zero. F-opaque-18 receives F-opaque-17’s signed 32-bit primary result reduced by `0x71` and supplies a 64-bit result.

Two independent portions of that result are used:

- Its high 32 bits, interpreted as signed, are multiplied by `0x10000000` to form the computed address base.
- Its low 32 bits, interpreted as signed, become the first argument to F-opaque-19.

Before F-opaque-19, a zero halfword is written at the retained unsigned halfword plus `0x20`. Zero extension is significant: this destination lies between `0x20` and `0x1001f`, inclusive.

F-opaque-19’s second argument is the signed high result portion shifted right by 20. After this invocation returns, the selector-derived word value is written at computed address base plus `0x54`. The computed address base remains a retained value; it is not recomputed from a subsequent dependency result.

This endpoint is designated nonreturning. The representation contains no ordinary return on this continuation. It does not establish whether runtime handling traps during F-opaque-23, reaches F-opaque-24, redirects execution, or terminates through another mechanism.

### Arithmetic constraints

Explicit unsigned 32-bit additions and shifts have modulo-\(2^{32}\) behavior. This includes primary- and secondary-base offsets in the common protocol, the primary-base word destination on the terminal continuation, and the transformation supplied to F-opaque-14.

An unsigned left shift by 20 retains only the input’s low 12 bits. On the selector-`0x2b` route, these originate from primary-base bits 8 through 19.

Signed operations must not silently be replaced with unsigned wrapping operations. Unresolved cases include:

- Captured-word subtraction by `0x5a`.
- Signed pointer interpretation and transformation.
- Right shifts of negative signed values.
- Dependency-result adjustments by `-0x71` and `+0x59`.
- Multiplication forming the computed address base.
- Address calculations based on signed values.
- Control-link-relative target derivation.

For the computed-base multiplication, high result portions from negative eight through seven have products within signed 32-bit range. Products outside that range require overflow semantics not established here.

Under an additional wrapping interpretation, the computed base would depend only on the high result portion’s low four bits. That is a conditional observation, not an unconditional requirement.

Important observable ordering constraints include:

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes that preceding dependencies return and that relevant accesses and arithmetic permit progress.

1. **Unsigned selection boundary.** Secondary base `0xffffffc7` selects the terminal continuation with selector `0x08573680`, regardless of the primary base’s signed interpretation.

2. **Wrapped common address.** Secondary base `0xffffffc8` satisfies the high-range comparison. Its common byte destination is `0x00000004` under unsigned 32-bit addition.

3. **Signed selection boundary.** With a high-range secondary base, primary base `0x59` selects the terminal continuation with early halfword destination `0xc5` and later word value `0x95`. Primary base `0x5a` selects the return-capable continuation. Both first perform the common pointer store.

4. **Negative primary-base pattern.** With a high-range secondary base, primary pattern `0x80000000` selects the terminal continuation. Its logical right shift by eight is `0x00800000`; the subsequent unsigned left shift by 20 gives zero for F-opaque-14’s argument.

5. **Common-storage overlap.** If the common byte destination overlaps the captured-word source, the word read must reflect storage after the byte write. The exact word depends on overlap position and byte order.

6. **Global-to-pointer overlap.** If the first global destination overlaps the byte addressed by the returned pointer, the retained byte is obtained after that global assignment. An entry-time byte value is not sufficient to predict it.

7. **Unsigned halfword boundary.** A retained halfword of `0xffff` produces destination `0x1001f` for the later zero-halfword write. Destination `0x1f` would incorrectly treat the retained value as negative one.

8. **Defined computed-base case.** If F-opaque-18’s high result portion is three, the computed base is `0x30000000`, and the later word destination is `0x30000054`. The low portion independently supplies F-opaque-19’s first argument.

9. **Unresolved byte interpretation.** Retained byte pattern `0xff` gives F-opaque-06 a second argument of zero under unsigned promotion, or negative one under signed promotion with arithmetic right shift. Neither outcome is unconditional.

10. **Partial completion.** If F-f96e6bdb2333 does not return, the common byte write and captured-word read precede that invocation, but the common pointer store has not occurred.

11. **Endpoint limits.** Reaching F-opaque-13 does not prove ordinary return. Reaching F-opaque-23 does not prove a particular trap mechanism or execution of F-opaque-24.
