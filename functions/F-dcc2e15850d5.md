# F-dcc2e15850d5

## Purpose

F-dcc2e15850d5 conditionally processes an input object, then examines and potentially modifies a shared record whose pointer was captured at entry. It returns a 32-bit value.

The established behavior consists of:

- Capturing a shared-record pointer before testing the first argument.
- For a nonzero first argument, invoking preliminary dependencies and inspecting an object field.
- If the captured record pointer is non-null, optionally invoking a discriminator-selected dependency.
- Comparing a record field with another dependency’s result.
- Depending on that comparison and a captured two-bit mode, decrementing a 16-bit state field or clearing record fields and invoking a final dependency.

Object cleanup, reference counting, and ownership release are possible **inferred intent**, not established semantics. The supplied representation does not establish that any dependency frees storage, releases a lock, or preserves globals.

Return values are described only by their numerical values and control-flow effects. Neither zero nor nonzero is assigned a success or failure meaning.

## Behavior

### Entry capture and zero first argument

The function first reads the global location containing the shared-record pointer and retains that pointer.

It then tests the first argument. If the argument is zero, the function returns 0 without calling dependencies, accessing the object field, or dereferencing the captured record pointer.

The global pointer-location read still occurs on this path. The captured pointer may be null or may identify inaccessible record storage without causing a record access on this path.

### Nonzero first argument

For a nonzero first argument, the function invokes a preliminary dependency for which the supplied dependency map provides no opaque ID.

After that dependency returns, the function reads the 32-bit object field at offset 8:

- Zero skips F-8f27efea2b2d.
- Any nonzero value invokes F-8f27efea2b2d.

No explicit arguments or consumed return value are established for F-8f27efea2b2d.

The object-field read occurs after the preliminary dependency. A mutation made by that dependency can therefore change which branch is taken, provided the object remains accessible.

The function next calls F-c67cb20988a1 with the original first argument and the constant 28, represented by `0x1c`. Its return value does not control subsequent local behavior.

These object-processing calls occur before the captured record pointer is tested for null. They are not skipped merely because that pointer is null.

### Captured-record check

After the object-processing sequence, the function tests the pointer retained at entry.

If it is null, the function returns 26.

If it is non-null, record processing continues. The global pointer location is not reloaded. A preceding dependency’s replacement of that global pointer does not redirect the accesses performed by this invocation.

This retained-pointer behavior does not guarantee that the original record remains alive. Continued validity is a precondition for later accesses, not a lifetime guarantee supplied by this function.

### Discriminator-selected dependency

For a non-null captured record, the function compares its 32-bit field at offset 0 with a separate global discriminator value. This comparison occurs after the object-processing dependencies.

If the values differ, F-621dae46a146 is skipped.

If they match, F-621dae46a146 is called with the represented argument sequence:

- The captured record pointer.
- Zero.
- The third entry argument.
- The fourth entry argument.
- Four additional machine-context values whose interface meaning remains unresolved.

If the dependency returns nonzero, the function immediately returns that result. No subsequent local mode-field read, identity dependency call, decrement, clearing write, or final dependency call occurs.

If the dependency returns zero, processing continues. Its zero return does not establish that it preserved the record, globals, or storage lifetime.

The supplied comparison establishes which values are compared, but does not independently establish the relative machine-level order of the two operand reads.

### Mode capture and identity comparison

After the discriminator stage permits continuation, the function reads the unsigned 16-bit field at record offset 14 and retains it.

It then calls F-196812b4b122.

After that call returns, it reads the 32-bit field at record offset 4 and compares that field with the dependency’s result.

Consequently:

- The mode source is captured before F-196812b4b122.
- The identity field is read after F-196812b4b122.
- Any mode-2 state-field read also occurs after F-196812b4b122.

These accesses do not form a guaranteed record-wide snapshot. The decision can combine an earlier mode with later identity and state values.

If the identity comparison does not match, the function returns 5. No direct record write occurs on that path. Earlier dependencies may nevertheless have modified memory or external state.

### Mode-dependent transition

For a matching identity, the retained mode source is masked with `0x3f` and shifted right by four bits. Only bits 4 and 5 affect the resulting mode, which ranges from 0 through 3.

If the mode is 0, 1, or 3, the function enters the finalization path without first reading or decrementing the state field at offset 18.

If the mode is 2, the function reads the signed 16-bit state at offset 18, subtracts one, narrows the result to the represented signed 16-bit value, and writes that value back. It then tests the resulting 16-bit value against zero.

- A nonzero result causes return value 0, with no local identity clear and no F-259d2fe281b0 call.
- A zero result enters the finalization path.

For ordinary representable results, an initial state of 2 becomes 1, an initial state of 1 becomes 0, and an initial state of 0 becomes −1.

No positivity check, saturation, or underflow rejection is shown. At an initial state of −32768, the mathematical subtraction produces −32769, outside the signed 16-bit range. The exact target-level narrowing result at that boundary remains **documented_only**; this contract does not silently substitute saturation or a portable signed-conversion rule.

### Finalization path

The finalization path performs these operations in order:

1. Writes zero to the 16-bit state field at offset 18.
2. Writes zero to the 32-bit identity field at offset 4.
3. Calls F-259d2fe281b0 with the interior address at record offset 20.
4. Returns that dependency’s result.

When a mode-2 decrement produces zero, the state field receives two writes: the decrement’s zero write and the finalization path’s zero write.

Both clearing writes precede the final dependency call. No local restoration follows a nonzero result from that dependency.

“Finalization” names this control-flow path only. It does not establish that storage is released or that a resource changes ownership.

## Acceptance examples

These examples are conditional consequences of the supplied static representation, not executed tests. Unless a mutation is explicitly specified, assume accesses remain valid, dependencies return normally, and dependency effects do not change the stated branch conditions.

1. **Zero first argument.**  
   The global record-pointer location is read, then the function returns 0. No dependency is called and no record field is accessed.

2. **Nonzero object, null captured record.**  
   The preliminary dependency runs, the object’s offset-8 field controls the optional F-8f27efea2b2d call, and F-c67cb20988a1 receives the object and 28. The function then returns 26.

3. **Global pointer replaced during object processing.**  
   If the captured pointer is null and an object-processing dependency installs a non-null global pointer, this invocation still returns 26 after object processing. It does not reload the new pointer.

4. **Discriminator mismatch.**  
   Different record and global discriminator values skip F-621dae46a146. The function proceeds to capture the mode source and call F-196812b4b122.

5. **Nonzero discriminator-selected result.**  
   With matching discriminators, suppose F-621dae46a146 returns −7 in the represented 32-bit return convention. The function returns −7 without the later local mode read, identity call, or record writes.

6. **Identity mismatch.**  
   If F-196812b4b122’s result differs from the subsequently read offset-4 field, the function returns 5 without a local decrement or clear.

7. **Mode 2, state 2.**  
   With matching identity, state 2 is written as 1. The function returns 0 without locally clearing identity or calling F-259d2fe281b0.

8. **Mode 2, state 1.**  
   The decrement writes zero. Finalization writes zero to that field again, clears identity, calls F-259d2fe281b0 with the offset-20 address, and returns its result.

9. **Mode 2, state 0.**  
   The decrement writes −1. The function returns 0 without local finalization. No zero-state rejection is shown.

10. **Mode other than 2.**  
    With matching identity, mode 0, 1, or 3 selects finalization without reading the old state value. The two clears precede the final dependency call.

11. **Mode changed during identity lookup.**  
    Suppose the captured mode is 2, but F-196812b4b122 changes the stored mode to 0 and leaves matching identity and state 2. The captured mode still selects decrement, producing state 1 and return value 0.

12. **Final dependency returns nonzero.**  
    If F-259d2fe281b0 returns a nonzero value, that value is returned. Both clearing writes have already occurred; no local restoration follows.
