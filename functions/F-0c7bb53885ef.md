# F-0c7bb53885ef

## Purpose

F-0c7bb53885ef resolves an operation against an object, selector, and context. It returns a one-byte success indicator and uses caller-provided storage for a 32-bit result.

The result has no single established application-level type. Depending on the selected path, it is a descriptor value, a Boolean, an unchanged input value, a context field, a dependency-produced value, or the address of shared four-byte storage.

**Established static evidence:** the function performs an initial descriptor lookup, classifies the operation using global configuration, and selects among direct results, indirect dispatch, shared-payload handling, and descriptor-based resolution. Some failures return zero; specified missing handles instead reach a dependency marked nonreturning.

**Inferred intent:** several paths resemble property retrieval, and the shared payload resembles a three-channel value with a fixed fourth byte. Neither interpretation establishes application-level names, units, freshness, or ownership.

## Interface

The seven arguments have the following order and observable uses:

| Argument | Representation and use |
|---|---|
| Object | Address whose first 32-bit word supplies a dispatch-table address. Passed to preparation and lookup dependencies. A 32-bit field at byte offset `0xb8` is read by one special operation. |
| Operation | Signed 32-bit discriminator used in equality tests, signed comparison, arithmetic classification, and dependency calls. |
| Selector | Signed 32-bit value used for initial lookup, eligibility checks, object-field comparison, and the first indirect call’s additional arguments. |
| Auxiliary value | Uninterpreted 32-bit value forwarded to indirect dispatch. |
| Index/value | Signed 32-bit input. Negative values bypass indexed resolution on descriptor-based paths. One special operation returns its bit pattern unchanged. |
| Context | Address with observed fields at byte offsets `0x30`, `0x8c`, and `0x94`. |
| Result storage | Address writable for one 32-bit result. Reset after initial preparation, lookup, and classification reads; subsequently written on specified paths. |

Normal returns are exactly zero or one:

- **One:** the selected path reports success, including when the stored result is zero.
- **Zero:** the selected path reports ordinary failure.
- **No normal return:** a specified missing handle reaches F-a817d8d58c10.

## Behavior

### Entry ordering and operation classification

The function first reads the context byte at `0x94`. A nonzero byte causes F-592d2f9d8db6 to receive the object and context. It then calls F-ed4b1fd8953e with the object and original selector, retaining the resulting initial descriptor address.

After that lookup, the representation contains **three separate Baseline reads**, in this order:

1. A read saved for the later signed comparison of Operation against Baseline.
2. A read used immediately to compute whether Operation equals Baseline.
3. A read used to compute Operation minus Baseline.

Only after all three does the function write zero to result storage. It then captures Route operation, followed by Shared selector, for possible use in the **second** indirect invocation.

The equality result has first precedence. If false, the saved value from the first Baseline read controls the signed lower-versus-nonlower branch. The difference from the third read supplies subsequent upper-branch arithmetic.

Consequently, “equal,” “lower,” and “higher” are not necessarily relationships to one common Baseline value. If the reads differ, the equality branch may win despite a conflicting saved comparison, or the nonlower branch may be reached even though Operation equals the saved comparison value.

Every ordinary route performs the initial lookup, including routes that ultimately return an input or context field. Initial accesses and calls have no local null-pointer or bounds validation.

### Equality-selected direct result

When the saved equality result is true:

- A null initial descriptor returns zero.
- Otherwise, the descriptor word at `0x08` is read and retained as a candidate result.
- That same location is read again to decide whether to substitute Default direct value.
- If the second read is zero, Default direct value is read and selected.
- Otherwise, the first read remains the selected value.

The selected value is written to result storage, and the function returns one. The two descriptor reads are distinct in the supplied representation; a single stable-value interpretation requires that location to remain unchanged between them.

### Signed-lower branch

This branch is selected only when equality was false and Operation is signed-less-than the value from the first Baseline read.

The first classification tests Operation plus a read of Lower bias for zero. A match selects the first special route.

Otherwise, Lower bias is read again and combined with Operation and Lower adjustment. The resulting classification value is held as a 32-bit unsigned value. Zero selects shared-payload handling. A nonzero value equal to a read of Route mask selects indirect dispatch. All other values select general descriptor resolution.

The first test has precedence. Its Lower bias read is not a snapshot reused by the second calculation.

#### First lower special route

F-ed4b1fd8953e is called again, using the object and a read of Shared selector. The returned descriptor’s byte at `0x04` is passed with the object and context to F-a53eee269985.

Neither this descriptor nor the returned record is checked for null before dereference. The record’s first word is passed to F-283eda65a14c, and that result is queried through F-682adfd5a561 with numeric selector `5`.

A zero query result reaches F-a817d8d58c10. Otherwise, F-5710a8628cba receives the resulting handle and original Operation. Its 32-bit return is stored, and the function returns one.

Index/value does not select indexed resolution on this route.

#### Shared-payload route

F-9d0ecc5f6adf is called without visible arguments. Zero reaches F-a817d8d58c10.

For a nonzero result, F-5710a8628cba receives that result, Shared lookup key, and a read of the context word at `0x8c`. After this call returns, the function captures Payload address.

If the returned record is nonnull, the context word at `0x8c` is read again. A null record or a zero second context read selects descriptor fallback. The value originally passed to the dependency does not determine this later eligibility by itself.

For an eligible record:

- Bit zero is examined through Guard address.
- If that bit is set, no refresh dependency or payload write occurs.
- If clear, F-b255b26284e6 is called using **a fresh read of Payload address, minus four bytes**.
- If that call returns zero, no payload write or completion call occurs.
- If it returns nonzero, the record’s first word is read. Its bits `23:16`, `15:8`, and `7:0` are written, respectively, to bytes zero, one, and two of the **previously captured** payload address. Byte three is then written as `0xff`.
- F-d08d3ca17b81 is called with the captured payload address minus four bytes.

The captured payload address is then stored as the result, and the function returns one, whether or not a refresh occurred.

The address supplied to F-b255b26284e6 need not equal the address supplied to F-d08d3ca17b81 if the global payload address changes between reads. This function does not reconcile them.

**Descriptor fallback:** a null initial descriptor causes another explicit zero write and returns zero. Otherwise, its discriminator must be `9`, `10`, or `11`, mapped respectively to `33`, `34`, or `35`. Other values return zero.

F-a53eee269985 receives the object, context, and mapped discriminator. A null record returns zero. The record byte at `0x08` must equal the mapped discriminator; mismatch returns zero. A matching record proceeds to descriptor value resolution.

#### Two-attempt indirect dispatch

Each invocation obtains its target through the object’s first word and the dispatch-table slot at byte offset four.

The first invocation receives ten arguments:

1. Object.
2. **A fresh read of Route operation.**
3. **The bitwise AND of fresh reads of Shared selector and Route mask.**
4. Auxiliary value.
5. Index/value.
6. Context.
7. Result storage.
8. Original Object.
9. Original Operation.
10. Original Selector.

The operation and selector inputs for this first invocation are **not** the values captured immediately after the result reset. Its Route mask read is also separate from the earlier dispatch-route comparison. The representation does not establish an evaluation order among the first invocation’s argument expressions.

Any nonzero first return produces immediate return one. If it returns zero, a second invocation receives seven arguments:

1. Object.
2. **The previously captured Route operation.**
3. **The previously captured Shared selector.**
4. Auxiliary value.
5. Index/value.
6. Context.
7. Result storage.

The second target is obtained through the object again. The first call may therefore affect both subsequent target selection and pointed-to state. Changes to the corresponding globals do not replace the second call’s saved argument values.

The second invocation’s nonzero return is normalized to one; zero produces zero. There is no result reset between calls and no local final-result write on this route.

### Nonlower branch

When equality was false and the signed-lower comparison was false, the function adds Upper adjustment to the difference calculated using the **third** Baseline read.

The following cases have precedence in the listed order:

| Condition | Behavior |
|---|---|
| Adjusted difference is zero | Compare the object word at `0xb8` with original Selector. Store one for equality or zero otherwise; return one. |
| Adjusted difference equals a read of Upper match | Require Selector to equal Required selector. Mismatch returns zero; match stores Index/value unchanged and returns one. |
| Adjusted difference minus another read of Upper match equals `0x0bf90000` | Require the same selector eligibility. Mismatch returns zero; match reads context `0x30`, stores it, and returns one. |
| None matches | General descriptor resolution |

Upper match is read separately for its equality test and later subtraction. No coherent configuration snapshot is established.

### General descriptor resolution

A null initial descriptor returns zero. Otherwise, its byte at `0x04` is passed with the object and context to F-a53eee269985. A null returned record also returns zero.

A nonnull record proceeds to descriptor value resolution. Unlike shared-payload fallback, this path does not validate the record byte at `0x08`.

### Descriptor value resolution

The record’s first word is transformed by F-283eda65a14c. F-682adfd5a561 queries that result with selector `5`. Zero reaches F-a817d8d58c10; otherwise, the query result becomes the value-resolution handle.

For negative Index/value, F-5710a8628cba receives that handle and original Operation. Its result is stored, and the function returns one. No selector-`6` query occurs.

For nonnegative Index/value, F-682adfd5a561 queries the handle with selector `6`:

- Zero selects the same F-5710a8628cba route.
- Nonzero causes a **second** selector-`6` query against the same handle.

After the second query, the record word at `0x04` is read. F-9dfe5f6048f1 receives the second query result, original Operation, that record word, and Index/value. Its return is stored, and the function returns one.

There is no zero check on the second selector-`6` result, and no record-word snapshot taken before those calls.

## Side effects

Direct writes consist of:

- The common 32-bit result reset.
- Final 32-bit writes on local success paths.
- The additional zero write for a null initial descriptor during shared-payload fallback.
- Up to four ordered byte writes to captured shared storage.

Preparation and lookup precede the common reset. A failure during those earlier accesses or calls therefore has no established result-reset guarantee.

A normal return of zero also does not universally imply a zero result: later dependencies and indirect dispatch can mutate accessible state, and dispatch failures do not restore the result.

No local allocation or deallocation is visible. Descriptor and record addresses are retained and dereferenced without visible release. Returning the shared payload address does not copy its contents or establish ownership transfer, lifetime, permission to modify, or permission to free it.

No dependency is assumed to preserve globals, object contents, context, descriptors, records, or result storage. Captured scalar values remain distinct from subsequent reads, but retaining an address does not freeze the addressed contents.

No non-aliasing requirement is established. Result storage overlapping later-read state can make the reset or final write affect subsequent observations.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, memory is valid and dependencies do not introduce additional mutations.

1. **Ordinary direct result:** If the equality test succeeds and both descriptor reads at `0x08` yield `17`, store `17` and return one.

2. **Separate direct-value reads:** If the first descriptor read yields `17` and the second yields zero, store Default direct value, not `17`. If the first yields zero and the second yields `17`, retain zero and still return one.

3. **Separate Baseline observations:** With Operation `100`, suppose the saved comparison read is `200`, the equality read is `100`, and the subtraction read is `90`. The equality-selected path wins; the saved lower comparison does not select a lower route.

4. **Nonlower is not necessarily greater:** With Operation `100`, Baseline reads of `100`, `101`, and `90` produce false equality, false signed-lower comparison, and difference `10`. If Upper adjustment is `-10`, the object-field comparison case is selected.

5. **Boolean result versus status:** On that object-field comparison case, a selector mismatch stores zero but returns one.

6. **Unchanged negative value:** The selector-restricted Index/value-returning case stores `-1` unchanged when eligible. Its negative sign does not trigger descriptor resolution.

7. **Repeated selector query:** If the first selector-`6` query returns nonzero and the second returns zero, indexed resolution still receives zero as its first argument.

8. **Shared-byte extraction:** An eligible record word of `0x12345678`, with a clear guard bit and nonzero F-b255b26284e6 return, produces payload bytes `0x34`, `0x56`, `0x78`, `0xff`, in that order.

9. **Successful stale payload:** Eligibility plus a set guard bit returns the captured payload address with success, without refreshing payload bytes.

10. **Distinct payload addresses:** If the captured payload address is A but the fresh address read for F-b255b26284e6 is B, that dependency receives B minus four. Authorized writes and the completion call still use A and A minus four.

11. **Fallback validation:** Descriptor discriminator `10` maps to `34`. A nonnull resolved record with a different byte at `0x08` returns zero before handle transformation.

12. **Dispatch snapshots differ:** Suppose entry captures Route operation R0 and Shared selector S0, while the first call’s reads yield R1, S1, and mask M1. The first call receives R1 and S1 AND M1. If it returns zero, the second receives R0 and S0, even if the first call changes those globals.

13. **Dispatch failure preserves no zero guarantee:** If both indirect calls return zero after writing result storage, the function returns zero without restoring the common reset.

14. **Missing required handle:** A zero selector-`5` result reaches F-a817d8d58c10 rather than ordinary failure.
