# F-8455b1076d3e

## Purpose

F-8455b1076d3e coordinates an ordered sequence of field-emission operations, prepares a closing dictionary fragment in an object-local scratch region, and conditionally copies that fragment into a destination buffer.

The field labels and closing-fragment reference suggest structured serialization of a display or rendering format. That interpretation is inferred intent. The established behavior is the dependency-call sequence, the conditions controlling optional calls, and the final buffer-accounting operations. The supplied evidence does not establish the complete serialized representation.

This function has no explicit return value. Its observable results consist of dependency effects, writes to object-owned storage, a possible write through a stored destination address, and an update to one of two 32-bit accounting fields.

### Final space decision

After the length operation returns, the function reads the capacity-like and position-like fields at `+0x14` and `+0x18`.

The comparison is strict:

- The left operand is the measured length plus one, evaluated with unsigned 32-bit arithmetic.
- The right operand is the difference between the capacity-like and position-like fields, converted to unsigned 32-bit form.
- The copy branch is selected only when the left operand is smaller than the right operand.

For a nonnegative length and a nonnegative, representable remaining-space difference, copying therefore requires at least two more available bytes than the measured length. A remaining space of exactly length plus one does not pass.

This is not an ordinary “length plus terminator fits” test. Replacing the strict comparison with a non-strict comparison changes the accepted boundary.

The field subtraction is represented as signed 32-bit arithmetic before conversion. If that signed subtraction overflows, the supplied representation alone does not establish a portable language-level result. The unsigned conversion also means that a representable negative difference becomes a large unsigned value; the function does not explicitly reject a position greater than capacity.

### Copy branch

When the comparison passes:

1. The function loads the destination base at `+0x10` and the position at `+0x18`.
2. It calls F-93c705790509 with the destination base plus position as its first argument and the scratch address as its second argument.
3. After that call returns, it reads the position field again.
4. It adds the previously measured fragment length to that current position and writes the result to `+0x18`.
5. It returns.

The explicit position increment excludes the extra one used in the capacity test.

The post-copy position read matters: the function does not explicitly restore or increment a saved pre-copy position. Any dependency-induced change to that field can affect the final value.

There is no explicit write to the `+0x1c` accumulator on this branch. That does not imply that dependencies preserve it.

### Non-copy branch

When the comparison fails, the function reads the accumulator at `+0x1c`, adds the measured fragment length, writes the result back to that field, and returns.

This branch makes no explicit call to F-93c705790509 and no explicit final-phase write to the position field. It nevertheless follows all field-emission and scratch-preparation operations; failure to copy the final fragment does not undo those earlier effects.

Neither branch provides an explicit success or failure return value.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Arithmetic examples assume representable signed arithmetic, a nonnegative measured length, and dependencies that return normally.

1. **All optional controls disabled.**  
   With inputs 4, 13, 14, and 17 equal to zero, the four corresponding optional calls are absent. Every unconditional field call remains, in the stated order, between the opening and closing operations.

2. **Nonzero controls are predicates, not payloads.**  
   With input 4 negative and input 13 positive, both `DisplayWidth` and `Rotation` calls occur. No requirement follows that either control value is serialized.

3. **Level propagation.**  
   With input 16 equal to 3, the opening and closing operations receive 3. Each ordinary field call carrying an explicit level receives 4. The four shorter conditional calls have no established explicit level argument.

4. **Copy accepted above the strict boundary.**  
   Suppose the length operation returns 10, the capacity-like field is 100, and the position-like field is 88. The comparison is 11 against 12, so the copy branch occurs. If the copy dependency preserves position, the final position is 98.

5. **Exact terminator-sized space rejected.**  
   With length 10, capacity 100, and position 89, the comparison is 11 against 11. No final copy call occurs. If the accumulator was 7 when read, it becomes 17.

6. **Empty fragment still encounters a strict reserve rule.**  
   With length zero and remaining space one, the comparison fails. With remaining space two, it passes. The zero increment does not eliminate the selected branch’s dependency call or direct field write.

7. **Post-copy state is used.**  
   If the comparison passes with length 10 but the copy dependency changes the position to 40 before returning, the function’s subsequent position update produces 50, provided the addition is representable.

8. **Invalid accounting is not explicitly rejected.**  
   If capacity is 10, position is 20, and length is 3, the representable difference is negative ten. Its unsigned conversion is 4,294,967,286, so the comparison passes. This establishes a missing validation check, not a guarantee that the resulting destination access is valid.
