# F-f4153521a5d3

## Purpose

F-f4153521a5d3 performs an ordered sequence of byte, halfword, and word accesses through explicit and ambient inputs, then makes an unresolved indirect control transfer.

The established behavior is memory mutation and indirect dispatch. An application-level purpose is not established. Self-address stores suggest pointer-bearing structures, but do not establish list operations, ownership, allocation, or object lifetimes.

This contract describes the supplied static representation, conditional on execution reaching each operation and that operation being valid. It does not establish that the representation forms a correctly recovered, independently callable routine.

## Interface

### Explicit inputs and result

| Input | Width | Established use |
|---|---:|---|
| First argument | 8 bits | Written twice at entry-target offset `0x00`. |
| Second argument | 8 bits | Written to two indirectly reached byte fields. |
| Third argument | 32 bits | No visible use. |
| Fourth argument | 8 bits | Written at initial-branch offset `0x11`. |

No return value is exposed. A return appears after the unresolved invocation; whether that invocation returns is unknown.

### Ambient inputs

Three incoming values are used without visible initialization:

- **Entry target:** an address initially used for byte writes.
- **Entry anchor:** a 32-bit address-bearing value; its low byte is stored, and a word is read at its offset `0x14`.
- **Entry context:** an address used for a byte write and word reads.

Three ambient 32-bit words are read near the end: the **first late word**, **second late word**, and **late payload**. Their meanings and initialization are unknown. An unresolved control-transfer destination is also required.

Supplying only the explicit arguments is insufficient to determine behavior.

### Widths, layout, and terminology

A **byte**, **halfword**, and **word** mean 8, 16, and 32 bits respectively. Offsets are byte offsets. Address-bearing word values are treated as 32-bit quantities in the supplied representation.

“Low byte” and “low halfword” describe truncation of a captured value, not a memory read from that value’s address. A word store writes all four bytes of its representation. Byte order is unresolved.

The following names identify captured addresses:

- **Primary region:** the word read at entry-anchor offset `0x14`.
- **Initial auxiliary:** the word read at entry-context offset `0x74`.
- **Initial branch:** the word read at entry-context offset `0x14`.

These are descriptive labels, not recovered object types. Captured addresses remain captured values even if their originating fields are subsequently overwritten.

No non-aliasing guarantee exists. Required memory extents are determined by the individual accesses below; no enclosing allocation size is established.

## Behavior

### Ordering and execution conditions

The visible body has no explicit conditional branch, loop, bounds check, validation failure, or error-return path before the unresolved transfer.

The ordering below is part of the contract. Reads repeated at the same offset are distinct reads. Stores repeated with the same value remain distinct stores. Aliasing, external observation, or faults can distinguish operations that otherwise appear redundant.

All outcomes are conditional on valid accesses and the absence of unspecified external interference. No atomicity or synchronization is established.

### Entry writes and initial traversal

The function first writes the first argument at entry-target offset `0x00`, then the entry anchor’s low byte at entry-target offset `0x09`.

It reads the primary-region address, writes the entry target’s low byte at entry-context offset `0x11`, stores the primary-region address as a word at entry-target offset `0x44`, and writes the first argument again at entry-target offset `0x00`.

It reads the initial auxiliary before reading the initial branch. Entry-target offset `0x54` then receives the entry target’s full address.

A word read at initial-branch offset `0x04` supplies a destination. In order:

1. Its byte `0x11` receives the second argument.
2. Its byte `0x10` receives 100.
3. Primary-region word `0x54` receives 100.
4. Destination word `0x60` receives 100.

The address at primary-region offset `0x74` is captured, that field is replaced with the initial-branch address, and the captured old destination receives word 100 at offset `0x30`.

### Initial child and retained values

A word read at initial-branch offset `0x14` supplies the **first child**. Its byte `0x09` receives the second argument. Primary-region word `0x54` receives the primary-region address.

A word store then writes initial-auxiliary minus `0x74` at address initial-auxiliary minus `0x20`.

The function reads an address at first-child offset `0x14`, writes the fourth argument at initial-branch byte `0x11`, and rereads initial-branch word `0x14`. That captured word’s low byte is written at offset `0x15` of the destination reached through the first child.

Another read of initial-branch word `0x14` supplies the **current child**. Primary-region word `0x64` is read and immediately written back unchanged. Call this capture the **early link**.

The current child receives byte `0x73` at `0x0c`. Primary-region byte `0x15` receives the early link’s low byte. Initial-branch word `0x34` receives the earlier capture of its `0x14` field.

Current-child word `0x74` is read; call this the **first child-link capture**. Current-child word `0x54` receives the current child’s address. Initial-branch byte `0x0d` receives the primary region’s low byte. Initial-branch word `0x54` receives the earlier captured `0x14` value, and its word `0x14` receives the current-child address.

### The `0x74` phase

Primary-region word `0x64` is read again; call this the **replacement link**. It need not equal the early link.

The following occur in order:

1. Current-child byte `0x10` receives `0x74`.
2. Primary-region word `0x54` receives `0x74`.
3. Current-child word `0x10` receives `0x74`.
4. Current-child word `0x74` is read, producing the **second child-link capture**.
5. Initial-branch word `0x54` receives the initial-branch address.
6. Current-child word `0x30` receives `0x74`.

Primary-region byte `0x01` receives the early link’s low byte. The early link is also used as an address: its byte `0x09` receives the replacement link’s low byte.

Primary-region word `0x74` receives the replacement link, then primary-region byte `0x11` receives `0x74`.

Current-child word `0x60` is read. Primary-region byte `0x11` receives the early link’s low byte; primary-region word `0x34` receives the replacement link; current-child byte `0x10` receives the captured `0x60` value’s low byte.

The last write changes only one byte of the earlier word store at current-child offset `0x10`.

### The `0x66` phase

Primary-region word `0x14` is read to obtain a new destination. Initial-branch byte `0x11` receives the first child-link capture’s low byte.

Primary-region word `0x44` receives the initial-branch address. Primary-region byte `0x11` receives the replacement link’s low byte. Primary-region word `0x74` is read and retained. Primary-region byte `0x0d` receives the initial branch’s low byte.

The next five stores have this exact order:

1. New-destination word `0x10` receives `0x66`.
2. Primary-region word `0x44` again receives the initial-branch address.
3. New-destination byte `0x10` receives `0x66`.
4. Primary-region word `0x54` receives `0x66`.
5. New-destination word `0x60` receives `0x66`.

In particular, the primary-region `0x54` store precedes the destination `0x60` store.

Primary-region word `0x74` is read again, producing the **replacement destination**. Primary-region word `0x74` receives the initial-branch address, and replacement-destination word `0x40` receives `0x66`.

Primary-region byte `0x0d` receives the low byte from the preceding, earlier `0x74` read. Replacement-destination word `0x44` is read. Primary-region word `0x54` receives the primary-region address.

The address held by the second child-link capture—not necessarily the first—receives its own address as a word at offset `0x54`.

### Further descendants and link replacement

Replacement-destination word `0x14` supplies a descendant. Initial-branch byte `0x11` receives the replacement destination’s captured `0x44` low byte. A fresh read of initial-branch word `0x14` supplies the low byte written at descendant offset `0x15`.

Initial-branch word `0x14` is read again to obtain another reached region. Primary-region word `0x64` is read, producing the **first recent link**. Reached-region word `0x20` receives `0x73`.

A second read of primary-region word `0x64` produces the **second recent link**. Its low byte is written at reached-region offset `0x09`.

Reached-region word `0x74` supplies a further region. In order:

- Its byte `0x0d` receives the primary region’s retained low byte.
- Its word `0x54` is read and written back unchanged.
- Its byte `0x09` receives `0x74`.
- Primary-region word `0x44` receives the first recent link.
- Its word `0x34` receives the primary-region address.

Following that region’s word `0x04` supplies another region. Its word `0x24` receives the second recent link. Primary-region byte `0x19` receives the first recent link’s low byte.

The new region’s word `0x74` is read before its word `0x04`. Retain these as the **retained address** and **retained word**, respectively.

Primary-region word `0x74` supplies a **routing region**. Reading routing-region word `0x14` identifies a destination whose word `0x54` receives the retained address.

Routing-region word `0x04` then supplies another destination. Primary-region byte `0x0d` receives the second recent link’s low byte twice consecutively. Primary-region word `0x64` receives the retained word. The destination’s word `0x30` receives `0x74`.

### Late branch and final target

Routing-region word `0x04` is freshly read, and the resulting region’s word `0x74` supplies the **late branch**. This is not a reuse of the earlier `0x04` capture.

Primary-region word `0x64` is read. Its low byte, retained as the **late link byte**, is written at primary-region offset `0x1d`.

Primary-region word `0x44` is read, followed by word `0x14` of the resulting region. Late-branch word `0x34` receives the retained address. Primary-region word `0x14` receives the newly obtained address.

Primary-region word `0x54` is read and retained. The newly obtained destination receives the primary region’s low byte at offset `0x09`; this uses the captured destination, not a fresh read of primary-region `0x14`.

Reading late-branch word `0x04`, then word `0x74` of that result, supplies another destination. In order:

1. Destination byte `0x15` receives the retained address’s low byte.
2. Primary-region word `0x54` receives the primary-region address.
3. Primary-region byte `0x11` receives the late branch’s low byte.
4. Destination byte `0x11` receives the captured primary-region `0x54` low byte.
5. Destination word `0x64` is read, producing the **late destination value**.
6. Primary-region byte `0x09` receives the late link byte.

A fresh read of late-branch word `0x04` supplies the **final target**. Its byte `0x09` receives the primary region’s low byte. Its word `0x50` is read. Its byte `0x11` receives the late destination value’s low byte. Its byte `0x09` again receives the primary region’s low byte.

Primary-region word `0x14` receives the late destination value. Primary-region byte `0x0d` receives the final target’s low byte. Final-target byte `0x00` receives its captured `0x50` low byte.

Late-branch word `0x74` is read and retained as the **late branch link**. Late-branch word `0x14` then supplies the **terminal parent**. Final-target word `0x54` receives the final-target address.

Terminal-parent word `0x04` supplies the **terminal child**. In order:

- Terminal-child byte `0x10` receives 100.
- Primary-region word `0x54` receives 100.
- Terminal-child word `0x40` receives 100.
- Primary-region byte `0x0d` receives the late destination value’s low byte.
- Terminal-parent byte `0x09` receives the terminal child’s low byte.
- Primary-region word `0x24` receives the late destination value.
- Terminal-parent byte `0x11` receives the primary region’s low byte.

### Arithmetic-addressed tail and dispatch

The first late word is read. Primary-region word `0x74` is then read, producing the **tail offset**.

The tail offset’s low halfword is written at primary-region address plus tail offset. The first late word’s low halfword is written at twice the terminal-child address.

A byte is read at late-branch-link plus primary-region address. Its character interpretation is converted to an unsigned 32-bit **dispatch value**. Signed-character interpretation remains unresolved.

The following occur in order:

1. The tail offset’s low halfword is written at first-late-word plus tail offset.
2. The same halfword is written again at primary-region address plus tail offset.
3. Word `0x45` is written at dispatch value plus `0x45`.
4. The second late word is read.
5. The late payload is read.
6. Primary-region word `0x44` is read and retained.
7. Byte `0x44` is written at dispatch value plus `0x44`.
8. The late payload is written as a word at twice the second late word.
9. The second late word’s low halfword is written at retained-address plus second-late-word.

The unresolved dependency is then invoked with three visible arguments:

1. Dispatch value bitwise-OR `0x44`.
2. Second late word.
3. The final captured primary-region `0x44` word.

The first argument uses OR, not addition. The dispatch-value additions are unsigned 32-bit arithmetic. Overflow behavior for address expressions represented with signed arithmetic is not established.

## Acceptance examples

These are conditional static criteria, not executed tests.

1. **Unused third argument.** With otherwise identical inputs and ambient state, changing only the third explicit argument changes none of the visible pre-dispatch operations.

2. **Truncation.** An entry anchor of `0x123456ab` causes the initial entry-target `0x09` write to store `0xab`.

3. **Correct `0x66` ordering.** After the repeated primary-region `0x44` store, the destination byte `0x10` store occurs, then primary-region word `0x54`, then destination word `0x60`. If the last store faults, the preceding primary-region store has already occurred. Reversing these stores is not equivalent.

4. **Distinct captures.** If the two current-child `0x74` reads produce different addresses, the later self-address store targets the second captured address. The earlier capture still supplies the byte written to initial-branch `0x11`.

5. **Old destination retained.** Replacing primary-region `0x74` with the initial-branch address does not redirect the subsequent word-100 store at old-destination offset `0x30`.

6. **Overlapping widths.** The current-child word store at `0x10` is later followed by a byte store there. That byte store replaces only the addressed byte, not the entire word.

7. **Character conversion.** A dispatch byte of `0xff` yields `0xffffffff` under signed 8-bit character interpretation, or `0x000000ff` under unsigned interpretation. The supplied evidence does not select one.

8. **Addition versus OR.** For dispatch value `0x44`, the byte-store address is `0x88`, while the first indirect argument is `0x44`.
