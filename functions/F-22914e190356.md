# F-22914e190356

## Purpose

F-22914e190356 selects between two behaviors according to the sign bit of a 32-bit control value:

- With the sign bit clear, it issues bounded requests through F-74745fd09174 until the requested amount has been scheduled or a dependency returns a nonzero status.
- With the sign bit set, it obtains a mutable value through F-cdf60417d657, combines that value with the control value using explicit low-word addition and carry handling, and conditionally invokes F-f7e2f4cd400d.

The established behavior is dispatch, arithmetic, request partitioning, and status propagation. The application-level meanings of the referenced object, the requests, and the calculated words are not established.

A signed displacement applied to a two-word quantity is a plausible interpretation of the sign-bit-set path. That interpretation is not required to describe or accept the observable call behavior.

## Behavior

### Branch selection and arithmetic model

The branch is determined by interpreting the 32-bit control value as signed:

- Values from `0x00000000` through `0x7FFFFFFF` take the bounded-request path.
- Values from `0x80000000` through `0xFFFFFFFF` take the arithmetic path.

All word additions described below retain only their low 32 bits. Carry is separately determined from the unsigned addition of two 32-bit operands. Overflow is not reported as an error by this function.

The lower-word seed is copied into temporary storage before branch processing. This initialization does not make the seed behaviorally relevant to the bounded-request path.

### Bounded-request path

A zero control value returns zero immediately. No dependency is called.

For a positive control value, the function maintains an internal remaining amount. Each iteration:

1. Selects a planned request equal to the smaller of the remaining amount and 32,768.
2. Reduces the internal remaining amount by that planned request.
3. Reads the current record value.
4. Calls F-74745fd09174 with:
   - the freshly read record value;
   - the address of a mutable 32-bit temporary containing the planned request;
   - the address at byte offset 20 from the object-record address.
5. Examines the dependency’s return status.

A nonzero status terminates processing immediately and becomes the function’s return value. A zero status permits the next iteration. Once the internal remaining amount is zero, the function returns zero without another dependency call.

The subtraction occurs before the dependency call. It uses the planned request, not any value the dependency later stores through the temporary pointer.

Consequently, a dependency-written request value does not alter the remaining amount. A successful dependency return accompanied by a reduced, increased, or zero written-back amount still causes the wrapper to proceed according to the original planned request. Whether that behavior is valid for the dependency’s actual contract is unknown.

The record value is read again for every call. It is not cached across iterations. If a dependency changes the record’s first four bytes, a later iteration uses the changed value, provided the record remains valid.

The lower-word and upper-word seeds do not affect the requests or statuses in this path.

### Arithmetic path

This path makes at most two dependency calls.

First, the function initializes an upper-word temporary from the upper-word seed and calls F-cdf60417d657 with:

- the record value read at that point;
- the address of the mutable 32-bit temporary initially containing the lower-word seed.

If F-cdf60417d657 returns nonzero, that status is returned immediately. F-f7e2f4cd400d is not called.

If F-cdf60417d657 returns zero, the function uses the lower-word temporary as it exists after the call. Let:

- \(L\) be that post-call lower word;
- \(D\) be the original 32-bit control value;
- \(U\) be the upper-word temporary used after the call;
- \(C\) be one when the unsigned sum \(L + D\) exceeds `0xFFFFFFFF`, and zero otherwise.

The calculated words are:

\[
R_{\mathrm{low}} = (L + D) \bmod 2^{32}
\]

\[
R_{\mathrm{high}} = (U - 1 + C) \bmod 2^{32}
\]

The subtraction of one follows from the sign extension of the control value: this branch only handles values whose signed arithmetic right shift by 31 yields all one bits.

The function then calls F-f7e2f4cd400d with four arguments, in these positional roles:

1. A newly read record value.
2. The upper-word temporary \(U\).
3. The calculated low word \(R_{\mathrm{low}}\).
4. The calculated high word \(R_{\mathrm{high}}\).

The second argument is the unadjusted upper-word temporary, not the calculated high word. Both are supplied separately.

The return status of F-f7e2f4cd400d becomes the function’s return value without further interpretation or retry.

The wrapper explicitly initializes the upper-word temporary but does not explicitly assign it again before the final call. This does not establish the memory extent that F-cdf60417d657 may access through its pointer argument. In particular, a two-word output convention and a particular adjacency of temporary storage must not be assumed from this function alone.

### Observable ordering

The established ordering constraints are:

- Branch selection precedes any dependency call.
- In each bounded-request iteration, request selection and remaining-amount reduction precede the call.
- Each dependency call completes before its status determines further processing.
- F-cdf60417d657 must return zero before the final call can occur.
- The record value for the final call is read after F-cdf60417d657 returns.
- No additional dependency call occurs after a nonzero status.

The evidence does not establish a total evaluation order among separate argument expressions belonging to the same call. The argument listing above specifies positions, not an additional sequence of observable reads.

## Side effects

Dependency effects remain visible and are not rolled back:

- F-74745fd09174 receives a writable temporary and an address inside the record.
- F-cdf60417d657 receives a writable temporary.
- Every dependency receives a value read from the record.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Each assumes valid memory and dependencies that return normally.

### Zero control

Given control `0x00000000`, the result is zero. There are no dependency calls and no record read. The seed values do not change that outcome.

### One bounded request

Given control 32,768 and a zero return from F-74745fd09174:

- Exactly one call occurs.
- Its request temporary initially contains 32,768.
- Its third argument is the record address plus 20 bytes.
- The final result is zero.

### Request boundary

Given control 32,769 and zero returns from both calls, the planned requests are 32,768 followed by 1. The second call reads the record value again.

If the first call returns a nonzero status, only that call occurs and its status is returned.

### Written-back amount does not control progress

Given control 40,000, suppose the first F-74745fd09174 call receives 32,768, writes zero into that temporary, and returns zero.

The next planned request is still 7,232. The write-back does not restore or reduce the already scheduled amount.

### Maximum nonnegative control

Given control `0x7FFFFFFF` and zero returns throughout, there are 65,536 calls: 65,535 planned requests of 32,768, followed by one request of 32,767.

### Arithmetic without low-word carry

Given control `0xFFFFFFFF`, suppose F-cdf60417d657 returns zero and leaves the lower word at zero and the upper temporary at 7.

The final dependency receives 7 as its second argument, `0xFFFFFFFF` as its third, and 6 as its fourth. Its first argument is read from the record after the first dependency returns.

### Arithmetic with low-word carry

With the same control, a post-call lower word of 1 and upper temporary of 7 produce a calculated low word of zero and calculated high word of 7. The unsigned low-word addition generates a carry that cancels the upper-word decrement.

### Upper-word wraparound

Given control `0xFFFFFFFF`, a post-call lower word of zero, and an upper temporary of zero, the calculated high word is `0xFFFFFFFF`. No overflow status is generated by the wrapper.

### Minimum signed control

Given control `0x80000000`, a post-call lower word of `0x80000000`, and an upper temporary of 7, the calculated low word is zero and the calculated high word is 7.

This control takes the arithmetic path, not the bounded-request path.

### First-call failure

For any sign-bit-set control, if F-cdf60417d657 returns a nonzero status, that exact status is returned and F-f7e2f4cd400d is not invoked.
