## Behavior

The ordering below concerns represented memory accesses. Captured values remain the values obtained at their specified read points; they are not fresh reads when subsequently published or passed to the target.

No non-aliasing guarantee is established. Earlier writes can therefore change later reads, including reads used to calculate destinations or invocation arguments. Conversely, an overwritten store remains part of the represented trace even when it contributes nothing to final ordinary-memory contents.

These ordering requirements do not establish hardware atomicity, barriers, or inter-thread synchronization.

The first memory operation stores the payload’s low byte at the original third input plus `0x15`. Only afterward is the captured scalar read from the second input plus `0x74`. If these locations overlap, the scalar is read from memory already affected by the payload-byte store.

The next mutations occur in this order:

- The implicit byte replaces the byte at the original third input plus `0x15`.
- The implicit word is stored at the original third input plus `0x54`.
- The low byte of the doubled scalar address is stored at the first input plus 9.
- The full payload is stored at the original third input plus `0x14`.

The last word store overlaps the two earlier offset-`0x15` byte stores. Which payload byte occupies that offset depends on byte order.

The scalar then determines three stores, in the following order:

### Scaled-base updates and selector capture

1. `0x00000020`.
2. `0x0000002F`.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

### Initial aliasing

If the original third input plus `0x15` overlaps the scalar-read word, the scalar capture must occur after the payload-byte store. Reading the original word first would violate the represented ordering.

### Scalar-derived destinations

If the captured scalar is 3 and arithmetic and mappings permit progress, the early scalar-derived stores target addresses 12, 24, and 44. Their widths are one, two, and four bytes, respectively. Each stores `0x3A` at its specified width.

The first-input offset-9 byte receives 6 during the initial phase. Later aliases may overwrite it.

### Absolute mutation before argument capture

If the word at the doubled scalar address plus `0x14` includes address `0x3A`, the preserved argument is captured after the byte mutation there. It must not be taken from the pre-mutation word. The earlier absolute capture and early linkage capture remain values read before that mutation.

### Overlapping publication destinations

If the selected base plus `0x74` and scaled base plus `0x10` identify the same writable word, the offset-4 capture is stored first and the offset-`0x40` capture second. Immediately after these two stores, ordinary memory contains the latter value, absent external interference.

### Distinct late reads of `0x67`

If an intervening publication changes address `0x67`, the second later read must obtain its value after that publication. Reusing the value sampled for the first later store to scaled-base offset 9 would not preserve the represented trace.

### Fourth-argument aliasing

If loaded-destination offset `0x54` aliases the chain-base offset-`0x74` word exactly, the fourth-argument read follows the word store of decimal 100. For ordinary memory without external interference, it reads 100.

### Captured third argument and partial completion

Later changes to the preserved argument’s original storage do not cause it to be re-read for invocation. If execution instead fails at an intervening access, no rollback or eventual invocation is required.
