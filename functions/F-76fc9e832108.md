# F-76fc9e832108

## Purpose

F-76fc9e832108 consumes bits from shared state, extends a 32-bit code until a signed table threshold accepts it, and returns a 32-bit word selected through length-dependent table adjustments.

The structure is consistent with variable-length prefix decoding and a special input-escape rule involving the value 255. That interpretation is inferred intent; the external format, meaning of returned words, and symbolic meaning of status value 14 are not established.

A return value of zero is ambiguous. It can indicate an early status exit or be an ordinary word read from the result table. No separate success indicator is returned.

### State-object selection

The function captures the global selector’s value at entry. Call that address the **captured object**. It nevertheless rereads the selector for several initial accesses.

The following accesses use a fresh selector value rather than necessarily using the captured object:

1. The initial decoding-table-reference read at +0x48.
2. If that reference is zero, the status write at +0x34.
3. Otherwise, the initial bit-position read at +0x70.
4. On an initial refill, the input-mode read at +0x04.
5. On the initial buffered path, the buffered-word read at +0x6C and the subsequent position write at +0x70, each through its own selector read.

All later state-field accesses use the captured object. This includes initial-refill writes and status checking, accesses after dependency calls, extension-bit processing, and table-reference reads.

Without selector stability, the captured object, the object checked for a missing table, and the objects supplying or receiving the first buffered bit can differ.

## Behavior

### Initial reads and missing-table exit

The first operation relevant to object selection captures the selector value. The function then rereads the selector and reads +0x48 from that selected object.

If that decoding-table reference is zero:

- The selector is read again.
- Status 14 is written at +0x34 of the object selected by that read.
- The function returns zero.

This path performs no dependency call, buffer write, position update, or result-table access. The status-write target need not be the captured object or the object whose table reference was checked.

If the reference is nonzero, the selector is read again to obtain the initial bit position. The initially checked table reference is not retained as the table base for decoding.

### Initial buffered-bit path

If the initial position has a nonnegative signed interpretation:

1. The selector is reread to obtain the buffered word.
2. A single-bit mask selects a bit using the position’s low eight bits as the shift count.
3. The selector is reread again, and the previously read position minus one is written to +0x70 of that selected object.
4. The selected bit becomes code zero or one.
5. Length is 1, and threshold processing uses the captured object.

The position decrement is unsigned 32-bit subtraction. Position zero therefore becomes 0xFFFFFFFF, whose signed interpretation is −1.

The buffer read and position write are distinct accesses through distinct selector reads. They are not established as an atomic operation on one object.

No status check occurs on this path.

### Refill behavior

A negative signed position requests refill. For the initial bit, input mode is read through a fresh selector read. For every extension bit, input mode is read from the captured object.

The remaining refill behavior is shared:

- If mode is nonzero, the candidate buffered word is zero, with no dependency call.
- If mode is zero, F-fbfa6017b0f5 is called.
- A first result other than exactly 255 becomes the candidate word unchanged.
- A first result of exactly 255 causes a second call:
  - A second result of exactly zero accepts candidate word 255.
  - Any nonzero second result selects candidate word zero and writes status 14 to the captured object.

Both comparisons concern complete 32-bit results. A first result of 0x000001FF does not trigger the second call. A second result with any set bit rejects the sequence.

The function then:

1. Writes the candidate word to the captured object’s buffer.
2. Reads status from the captured object.
3. Returns zero immediately if that status is nonzero.
4. Otherwise uses candidate bit 7 as the requested bit and writes position 6 to the captured object.

The buffer write precedes the status read. An early status exit does not perform the successful-refill position write of 6. It does not undo dependency consumption or dependency-induced state changes.

The function does not clear status. A previously nonzero status causes an exit if it remains nonzero when checked. Conversely, preservation of that status across dependency calls cannot be assumed.

The requested bit comes from the locally retained candidate, not from rereading the buffer field after storing it.

### Extension bits and threshold acceptance

The first bit establishes code zero or one and length 1.

The function reads the captured object’s decoding-table reference and obtains the length-1 threshold. A code is accepted when the signed threshold is greater than or equal to the signed interpretation of the 32-bit code.

If the threshold is smaller, another bit is obtained using the captured object:

- A nonnegative position selects a buffered bit using the low eight position bits as the shift count, then stores the unsigned position decrement.
- A negative position follows the refill behavior above.

Each additional bit doubles the code and adds zero or one. These operations retain the low 32 bits. The function then increments the signed length, rereads the captured object’s decoding-table reference, and tests the threshold for the new length.

There is no explicit length limit, invalid-code return, or independent termination check. A refill status exit can interrupt extension.

Once code bit 31 is set, threshold comparison treats the code as negative. Long codes therefore do not retain an unbounded nonnegative mathematical interpretation.

For ordinary positions 7 through 0, buffered consumption proceeds from bit 7 toward bit 0. Other position values are not normalized to that range.

### Final selection and unsigned wraparound

After acceptance, the function rereads the captured object’s decoding-table reference and combines it with four times the accepted length to locate the two adjustment words.

Let:

- \(C\) be the unsigned 32-bit code.
- \(I\) be the index-adjustment word’s unsigned 32-bit interpretation.
- \(J\) be the code-adjustment word’s unsigned 32-bit interpretation.
- \(B\) be the result-base field’s unsigned 32-bit interpretation.

The selected index is:

\[
K = (I + C - J) \bmod 2^{32}.
\]

The final address representation is:

\[
A = \left(B + (4K \bmod 2^{32}) + 0x90\right) \bmod 2^{32}.
\]

The adjustment addition, adjustment subtraction, multiplication by four, result-base addition, and addition of 0x90 all use unsigned 32-bit arithmetic. Signed reads of adjustment words or the result base do not make these final operations signed.

The function reads one 32-bit word at the resulting address and returns it unchanged.

No result-base null check, index bounds check, minimum-code check, or wrapped-address rejection is visible. Defined unsigned wraparound does not establish that the resulting address is accessible.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, the selector is stable, the dependency does not interfere with state, all accesses and shifts are valid, and status is zero.

### Missing decoding table

With a zero initial decoding-table reference, the function returns zero and writes status 14 through the next selector read. No bit or dependency result is consumed. If the selector changes between those accesses, the checked object and written object can differ.

### Initial buffered accesses across objects

Suppose successive selector reads yield distinct accessible objects:

- Entry capture selects object A.
- Initial table check selects object B, whose table reference is nonzero.
- Initial position read selects object C, whose position is zero.
- Initial buffer read selects object D, whose bit 0 is clear.
- Initial position write selects object E.

The function writes 0xFFFFFFFF to E’s position, obtains code zero, and uses A’s decoding-table reference for the length-1 threshold. It does not substitute B’s checked table reference for A’s reference.

### One buffered zero bit

With position zero, buffer bit 0 clear, length-1 threshold zero, index adjustment 5, and code adjustment zero:

- Code zero is accepted.
- Position becomes 0xFFFFFFFF.
- No dependency call occurs.
- The result is read at result base +0xA4, provided that addition does not wrap in this example.

### Two-bit extension

With position 1 and low buffer bits binary 10, thresholds zero at length 1 and two at length 2:

- First code 1 is rejected.
- Extended code 2 is accepted.
- Position becomes 0xFFFFFFFF.

Length-2 index adjustment 7 and code adjustment 2 select index 7.

### Successful refill

With negative position, zero mode, and first dependency result 128:

- One call occurs.
- Buffer becomes 128.
- First code bit is 1.
- Position becomes 6.

A length-1 threshold of at least 1 accepts immediately.

With results 255 and zero instead, two calls occur, buffer becomes 255, and the same first bit and position result.

### Rejected special sequence

With negative position, zero mode, and results 255 then 3:

- Two calls occur.
- Status becomes 14.
- Buffer becomes zero.
- Return value is zero.
- No threshold is read and no successful-refill position of 6 is written.

### Status depends on the bit path

A buffered bit can satisfy its threshold and return a table word despite nonzero status.

A refill stores its candidate before checking status. If status is nonzero at that check, it returns zero without completing the position update.

### Nonzero input mode

With negative position, nonzero mode, and captured-object status zero, no dependency call occurs. The captured buffer becomes zero, the requested bit is zero, and captured position becomes 6.

### Wrapped final selection

With accepted code zero, index adjustment zero, and code adjustment one, the index is 0xFFFFFFFF. Scaling gives 0xFFFFFFFC.

If the result-base representation is 0x00001000, the final address is 0x0000108C after unsigned wraparound. If that address is accessible, its 32-bit word is returned. The arithmetic does not itself report an error.
