# F-09f149a3091f

## Purpose

F-09f149a3091f configures a register-backed operation, submits a command, transfers up to four complete 32-bit payload words, and polls two successive status conditions. It uses one timeout reference for both polling phases.

The operation is not established to complete within a bounded time. The requested payload size is bounded, but polling can continue indefinitely if status remains incomplete and timeout checks continue returning zero.

The interpretation as a hardware transfer is inferred from the access pattern and diagnostics. The established contract is the sequence of memory accesses, dependency calls, decisions, and return values described below; no particular device or protocol is assumed.

Requested sizes need not be multiples of four. The original size is written to one register, while command construction and payload transfer discard its lowest two bits. The function does not reject this mismatch.

## Interface

### Inputs

The function accepts three 32-bit arguments:

| Argument | Representation | Established use |
|---|---|---|
| Selector | Unsigned 32-bit integer | Bits 2–7 contribute to the command. The original value is supplied to the command-failure diagnostic. |
| Payload address | Signed 32-bit integer used as an address | Identifies the first source word for direct four-byte reads. |
| Requested size | Unsigned 32-bit integer | Values above 16 are rejected. Accepted values determine the size-register write, command size field, and number of payload words. |

The function performs no explicit validation of the selector, payload address, alignment, readable extent, or size divisibility by four.

For a request that reaches payload transfer, the caller must provide accessible storage for exactly the words the function reads: four times the integer quotient of requested size divided by four. The source addresses are the supplied address plus offsets 0, 4, 8, and 12, as applicable.

Sizes below four cause no direct payload reads. This does not eliminate the need for valid shared context and register accesses on accepted requests.

### Result

The result is a signed 32-bit integer:

- Zero after rejection of an oversized request.
- Zero after command-submission failure.
- Zero after either polling phase selects timeout.
- Otherwise, the exact result returned by F-472f505654a1, which is called only after final-phase completion is observed.

A zero result from F-472f505654a1 also triggers a transfer-error diagnostic. A nonzero result is returned unchanged, including a negative result if the dependency produces one.

The function therefore does not provide a distinct return code for each failure category, nor does it normalize nonzero completion results to one.

These return guarantees assume the relevant dependencies return normally and required memory accesses complete.

### Shared-state and register layout

A shared root reference supplies a context address. The function captures that reference on entry and separately reads it again for initial setup.

| Context offset | Width | Established use |
|---|---:|---|
| +0x04 | 32 bits | Register-block address |
| +0x14 | 32 bits | Fourth command-submission argument; separately reread later for timeout checks |

Direct register-block accesses have the following layout:

| Register offset | Width | Direct writes |
|---|---:|---|
| +0x04 | 32 bits | First 3 during setup; later 16 after successful command submission |
| +0x38 | 32 bits | 1 after first-phase status becomes ready |
| +0x3C | 32 bits | Retained dependency result with bit 0 cleared; later the full retained result |
| +0x40 | 32 bits | Each complete payload word, repeatedly to the same address |
| +0x48 | 32 bits | Original requested size |
| +0x4C | 32 bits | Zero |

These offsets identify observed access locations. Their hardware meanings, permissions, and device-side effects are not independently established.

## Behavior

### Entry and size rejection

The function reads and retains the shared root reference before checking size.

The comparison is unsigned. Any requested size greater than 16 causes an oversized-write diagnostic through F-1b7fa166ef25 and a zero return.

This rejection path performs no direct context-field dereference, register write, payload read, command submission, or status polling. The diagnostic dependency’s own effects are unknown.

### Initial setup

For an accepted size, the function reads the shared root reference again and obtains the register-block address from that context’s +0x04 field.

Using this setup address, it performs three four-byte writes in order:

1. The original requested size to +0x48.
2. Zero to +0x4C.
3. Three to +0x04.

It then calls F-2b86f305a556 and retains its 32-bit result.

After that call, the function obtains a register-block address through +0x04 of the context captured on entry. It writes the retained result with bit 0 cleared to register offset +0x3C. Bits 1–31 remain unchanged.

The setup context and entry-captured context are not assumed identical. Their selection comes from separate shared-root reads.

The evidence does not establish that F-2b86f305a556 reads +0x3C or returns its previous contents. Consequently, the later full-value write is a restoration of the dependency’s returned value, not a proven restoration of the register’s original state.

### Command construction and submission

The 32-bit command contains these nonoverlapping fields:

| Command bits | Content |
|---|---|
| 31 | One |
| 18–23 | Selector bits 2–7 |
| 2–7 | Requested-size bits 2–7 |
| All remaining bits | Zero |

Selector bits 0–1 and 8–31 have no effect on the command. For accepted sizes, the size contribution equals the requested size rounded down to a multiple of four.

F-6e46c43c3113 receives four arguments in this order:

1. A value read from a separate shared command-target location.
2. The constructed command.
3. Zero.
4. The 32-bit value read from +0x14 of the entry-captured context.

No ordering between the individual argument reads is established beyond their being supplied to this call.

If command submission returns zero, the function calls F-1b7fa166ef25 with a command-failure diagnostic and the original selector and requested size. It then performs the final +0x3C write and returns zero.

This failure path does not write 16 to +0x04, transfer payload words, acquire a timeout reference, or poll status.

Any nonzero command-submission result permits continuation. Its magnitude and sign do not determine the eventual return value.

### Payload transfer

After successful command submission, the function rereads the register-block address through the entry-captured context and writes 16 to offset +0x04.

It then transfers the integer quotient of requested size divided by four words:

- Each source read is four bytes wide.
- Source addresses increase by four bytes.
- Each source read is followed by a four-byte write to register offset +0x40.
- Every destination write uses the same address.
- The register-block address obtained before the loop remains in use throughout that loop.

Accepted requests therefore transfer zero through four words. There is no explicit trailing-byte transfer, partial-word read, or byte-swapping operation.

For sizes zero through three, setup and command submission still occur. If command submission succeeds, the function writes 16 to +0x04 and proceeds to polling without reading payload storage.

### Timeout-reference acquisition

After all payload writes, the function rereads +0x14 of the entry-captured context and retains that 32-bit value for timeout checks.

It then calls F-UNRESOLVED-01 and retains its 32-bit result.

Every subsequent timeout check receives:

1. The retained F-UNRESOLVED-01 result.
2. The retained later reading of context +0x14.

The command argument and timeout argument come from separate +0x14 reads. They need not match if shared state changes between them.

The timeout reference is acquired after command submission and payload transfer, not at entry. It is not refreshed when polling advances to the second phase.

### First polling phase

Each iteration first calls F-849e39a4f74b.

If bit 0 of its result is set:

- The function rereads the register-block address through the entry-captured context.
- It writes 1 to register offset +0x38.
- It immediately enters the final polling phase.

No timeout check occurs between observing this status condition and the first final-phase status call.

If bit 0 is clear, the function calls F-UNRESOLVED-02 with the retained timeout arguments:

- Zero repeats the first-phase status check.
- Any nonzero result selects timeout.

On timeout, the function emits a timeout diagnostic, performs the final +0x3C write, and returns zero. It does not call F-472f505654a1.

Only bit 0 of the first-phase status result affects control flow.

### Final polling phase

Each iteration begins by calling F-a63d7d1563a4.

If all four low bits are zero, final-phase completion has been observed. The function calls F-472f505654a1:

- If its result is zero, the function emits a transfer-error diagnostic.
- Whether zero or nonzero, its result is retained for return after the final +0x3C write.

Bits above bit 3 do not prevent completion.

If any of the low four status bits is set, the function calls F-UNRESOLVED-02 using the same arguments as in the first phase:

- Zero permits another final-status call.
- Nonzero selects the timeout diagnostic, final +0x3C write, and zero return.

Status therefore takes precedence over timeout in both phases. An iteration that observes its required status condition does not consult timeout before advancing or completing.

Successful command submission and completed payload writes do not establish eventual final-phase completion. Either phase can time out, and either can continue indefinitely.

### Final retained-value write

Every explicit normal-return path after F-2b86f305a556 returns converges on a final write:

1. Reread the register-block address through the entry-captured context.
2. Write the complete retained F-2b86f305a556 result to +0x3C.
3. Return the selected result.

This address may differ from the address used for the earlier bit-cleared write if a dependency or concurrent actor changes the context field.

The function does not explicitly undo the size, control, payload, or +0x38 writes. The final write is not guaranteed after a memory fault, nonreturning dependency, or other abnormal exit.

## Side effects

Established direct effects include shared-state reads, four-byte register writes, four-byte payload reads, dependency calls, and diagnostics.

The function does not explicitly allocate or release memory, write to the payload buffer, or transfer ownership of that buffer. It does not explicitly pass the payload address to a dependency; it transfers the read contents to the register block.

No unknown dependency is assumed to preserve globals, context fields, register state, or memory ownership. Continued execution requires that the entry-captured context remain accessible for its later dereferences, regardless of changes to the shared root reference.

Register addresses are refreshed at specified points rather than before every write. In particular, setup uses one address for three writes, and payload transfer retains one address for the control write and entire word loop.

The final +0x3C write can overwrite changes made by dependencies. No synchronization, locking, explicit delay, cancellation mechanism, or fixed polling-iteration limit is present.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. They assume dependencies return normally and required memory accesses succeed. Shared addresses are stable unless an example states otherwise.

1. **Oversized request.** With requested size 17, emit the oversized-write diagnostic and return zero. Apart from the entry root read, perform no direct context-field reads, register writes, or payload reads.

2. **Maximum payload, independently of completion.** With requested size 16 and nonzero command-submission result, write 16 to +0x04 and transfer four source words, in increasing source-address order, to +0x40. This establishes the payload behavior only. It does not require polling to complete or F-472f505654a1 to be called.

3. **Completion after maximum payload.** Under the preceding conditions, if first-phase status eventually has bit 0 set and final-phase status subsequently has its low four bits clear, without an earlier timeout, call F-472f505654a1. On normal return, perform the final +0x3C write and return its exact result.

4. **Timeout after maximum payload.** With size 16 and successful command submission, if the first status call has bit 0 clear and its following timeout check returns nonzero, the four payload words have already been written. Emit the timeout diagnostic, perform the final +0x3C write, and return zero without calling F-472f505654a1.

5. **Indefinite polling.** After successful submission and payload transfer, if first-phase status always has bit 0 clear and every timeout check returns zero, continue first-phase polling indefinitely. No normal return or final +0x3C write is reached.

6. **Nonmultiple-of-four size.** With size 7 and successful submission, write 7 to +0x48, encode size 4 in the command, and transfer one word. Do not read the final three requested bytes. Device acceptance of this mismatch remains unknown.

7. **Zero size.** With size zero, perform setup and command submission with zero encoded size. On successful submission, write 16 to +0x04 and enter polling without a direct payload read.

8. **Selector masking.** Selectors 0x00000004 and 0xFFFF0007 produce the same command selector field. On command failure, the diagnostic receives the respective original selector.

9. **Command failure.** If submission returns zero, emit its failure diagnostic, perform the final +0x3C write, and return zero without payload transfer or polling.

10. **Status precedence.** A first-phase result with bit 0 set causes the +0x38 write followed by an immediate final-status call, without an intervening timeout check.

11. **Final-status masking.** A final-status result of 0x10 calls F-472f505654a1 without a timeout check. A result of 0x01 instead requires a timeout check before another final-status attempt.

12. **Final result propagation.** If completion is observed and F-472f505654a1 returns −1, perform the final +0x3C write and return −1 without the zero-result transfer-error diagnostic. If it returns zero, emit that diagnostic, perform the final write, and return zero.
