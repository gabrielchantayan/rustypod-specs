# F-8996df13e56e

## Purpose

F-8996df13e56e coordinates an operation between two descriptor-backed objects. It initializes associated state, checks eligibility, processes indexed units, and selects a completion path according to whether two cached unit widths match.

“Destination” denotes the first argument; “source” denotes the second. These names express **inferred intent**, not established copying semantics. The observable contract consists of memory accesses, dependency calls, address calculations, status propagation, and explicit state changes.

The operation is not established to be transactional. An unsuccessful return can follow initialization writes, unit operations, transfers, and finalization mutations.

## Interface

### Arguments and result

The inputs are two descriptor pointers in a represented 32-bit address model. The result is a 32-bit status:

- **1:** either eligibility tag differs from 2.
- **5:** both tags pass, but the destination’s blocking field is nonzero.
- **0:** the selected completion path reports success.
- **Other values:** propagated status-producing dependency results.

A dependency-produced status is preserved across error cleanup. Cleanup’s result does not replace it.

### Accessed memory

Offsets are byte offsets. These are partial layouts, not complete object definitions.

### Preconditions and ownership

There are no explicit null, alignment, accessible-extent, disjointness, or arithmetic-safety checks. Both descriptors and contexts must already support initialization accesses before eligibility can be evaluated. Subsequent dependency outputs must support the accesses taken on their paths.

No allocation, ownership transfer, reference-count meaning, or release guarantee is established. In particular, the dependency used after acquisitions must not be assumed to free or release its argument.

## Behavior

### Initialization and eligibility

The source context pointer is captured before the destination context pointer. These captured pointers remain the contexts used throughout the operation; changing a descriptor’s context pointer later does not redirect those accesses.

Before validation, destination-context +4 receives destination-descriptor +0, followed by the corresponding source write. The destination width is then cached, the destination tag is obtained, and the source width is cached. The source tag is read only when the destination tag equals 2.

Either tag failure returns 1. With both tags equal to 2, a nonzero destination-context +8 returns 5. Neither direct return invokes error cleanup, and neither undoes initialization.

Aliasing is permitted by the visible checks. Consequently, an earlier write can affect a later read.

Let \(w_d\) and \(w_s\) denote the cached unsigned 16-bit destination and source widths. They remain fixed for width comparisons, products, transfer-address calculations, and cursor advances, regardless of later field changes.

### Counts and reserved positions

F-f3192f39e4f6 is queried first with the destination’s current underlying-object reference, then with the source’s. Their 32-bit results are treated as unsigned counts \(n_d\) and \(n_s\).

After both calls, F-d7be9cfb4000 receives 0x40000000 and the freshly read destination width field narrowed to signed 16 bits. Its result, incremented modulo \(2^{32}\), becomes the destination reserved index.

This fresh argument need not equal \(w_d\). Count-query side effects can change it without changing the cached width.

The source extent is the full unsigned 64-bit product

\[
e=w_s n_s.
\]

F-7071f254f784 receives the low and high words of \(e+w_d-1\), followed by \(w_d\) and zero. Numerator formation includes carry and borrow and is modulo \(2^{64}\). Its 32-bit result becomes the target destination count \(t\).

**Inferred intent:** this resembles a ceiling-division calculation. Division semantics, exceptional behavior, and the meaning of a zero width are not established.

### Destination coverage

Destination traversal starts at unsigned index 1 with status zero. It finishes only when the index is strictly greater than **both** \(n_d\) and \(t\). Equality with either bound remains eligible for processing. The index advances modulo \(2^{32}\), so termination is not guaranteed for all returned counts.

The destination reserved index receives neither existing-unit preparation nor population.

For another index within \(n_d\), an output reference is initialized to zero and supplied to F-133a6620fb39 with the current destination object reference, index, and trailing zero. Acquisition success permits F-81c906bf6e3a to prepare that reference. Successful preparation additionally permits F-9390b54527db when the destination index exceeds \(n_s\).

Every successful acquisition in this existing-unit phase is followed by F-44d249c54e70, including when preparation fails. Acquisition and preparation results control status; the other two results are ignored. Failed acquisition has no corresponding guaranteed post-use call.

A nonreserved index within \(t\) is populated if status remains zero. This uses a separate destination acquisition and preparation. Thus an index within both counts can undergo two distinct acquisition/preparation sequences; the first acquired reference is not reused for population.

A tracked failure ends traversal and selects error cleanup.

### Population coverage and source selection

Population initializes its destination output reference to zero. Acquisition success permits preparation; either failure suppresses the inner population work.

For destination index \(i\), the source-position cursor initially has high word zero and low word

\[
a=w_d(i-1)\pmod {2^{32}}.
\]

The interval end used by this loop is only the low word

\[
z=w_di\pmod {2^{32}}.
\]

An iteration requires zero status and a signed cursor high word less than 1 when the unsigned low word is below \(z\), or less than 0 otherwise. This is not a general full-width interval comparison after low-word wraparound.

Each iteration obtains a 32-bit arithmetic result from F-7071f254f784 using the cursor’s low and high words, \(w_s\), and zero. Incrementing that result modulo \(2^{32}\) produces the source index.

The source reserved index is recomputed for every iteration. Its calculation rereads source-context +28 **after** the arithmetic dependency returns, calls F-d7be9cfb4000 with 0x40000000 and that field, and increments the result modulo \(2^{32}\). Therefore, arithmetic-dependency side effects can change reservation selection without changing \(w_s\).

A reserved source index skips acquisition and transfer. Other source indices are acquired through F-133a6620fb39 using the current source object reference. There is no explicit \(n_s\) bound in this population path.

Successful source acquisition permits the external transfer and is followed by F-44d249c54e70. Failed acquisition sets status without a guaranteed post-use call, even if it produced a nonzero output reference.

The cursor advances by cached \(w_s\), carrying from its low word into its high word. Reservation skips also advance it. A zero source width can therefore prevent progress unless another condition intervenes.

### Transfer addressing and destination post-use handling

Let \(q\) be the arithmetic result before its increment into a source index. All address arithmetic below is modulo \(2^{32}\).

| Width relation | Destination transfer address | Source transfer address |

| \(w_s<w_d\) | Destination data address plus \(w_sq-a\) | Source data address |

The unidentified external transfer visibly receives two addresses. No explicit length argument is established, and its result does not enter tracked status. Length, overlap behavior, hidden calling-convention inputs, and error signaling remain **documented_only**.

After population, a nonzero destination output reference causes F-44d249c54e70 to be called. This includes acquisition failure that nevertheless writes a nonzero reference, and preparation failure after acquisition. The supplied representation does **not** resolve the argument of this particular call; it cannot be contracted as a release of that reference.

### Equal-width completion

Following successful traversal, equal cached widths select F-b73a5da2c7c4 with the current destination object reference and \(t\).

Zero status clears captured destination-context +21 and returns zero. Nonzero status invokes error cleanup and is returned unchanged.

### Unequal-width completion: saved state and boundary

For unequal widths, the operation saves the destination’s current underlying-object reference and that object’s +108 reference. It forms the unsigned 64-bit target extent

\[
h=w_d\max(t,n_d).
\]

A second destination reservation calculation then rereads the destination field at +28 and supplies its signed-16-bit interpretation to F-d7be9cfb4000. This fresh value may differ from both \(w_d\) and the earlier reservation argument.

The returned 32-bit pattern determines boundary \(b\). If that unsigned pattern is \(r\), and the full unsigned product \(w_dr\) has words \(p_{\mathrm{high}}:p_{\mathrm{low}}\), then:

- \(b\)’s low word is \(p_{\mathrm{low}}\).
- Its high word is \(p_{\mathrm{high}}\) for \(r<\text{0x7fffffff}\).
- Otherwise its high word is \(p_{\mathrm{high}}-w_d\), modulo \(2^{32}\).

The correction includes **0x7fffffff** and **0xffffffff**. Neither an ordinary unsigned product nor a rule correcting only negative signed inputs is equivalent.

After this helper returns, destination-context +4 is rewritten from the original destination descriptor’s current +0 value. F-e02868207737 then receives the previously saved destination object reference and arguments zero, zero, and one. Its status becomes tracked status.

### Unequal-width finalization

Finalization reloads the underlying-object reference from the captured destination context and supplies it to F-b93e3fe564f6. That result is ignored.

Afterward, the same object’s current +108 reference and +13 byte supply F-b6413637baad. Their relative read order is not established. The object pointer is not refreshed between these calls.

## Side effects

The explicit mutations are:

- Both context +4 initialization writes, even on eligibility failure.
- A second destination-context +4 write during unequal-width completion.
- A decrement of object +224 whenever unequal-width finalization reaches it.
- Clearing destination-context +21 only on final success.

Dependencies and transfers can introduce additional effects before failure. No rollback, restoration, synchronization, or isolation is established.

Post-validation tracked failures invoke F-94e2e30e208d with the original destination descriptor pointer. Direct returns 1 and 5 do not. Successful completion does not.

Captured context pointers, cached widths and counts, saved object references, and freshly read fields are distinct state categories. Dependency mutations do not automatically refresh cached values. Conversely, later reads must not be assumed to retain earlier values.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Rejected destination tag.** With valid initial memory and destination low tag byte unequal to 2, both context initialization writes occur before return 1. Both initial widths are obtained; the source tag is not read. Error cleanup is absent.

2. **Blocked destination.** With both tags equal to 2 and destination-context +8 nonzero, return 5 follows initialization. Neither count query occurs.

3. **Fresh signed destination field.** If a count dependency changes destination-context +28 so its low 16 bits are 0xffff, the next destination reservation helper receives the signed value −1. Extent arithmetic still uses the earlier unsigned cached width.

4. **Source-field mutation.** If F-7071f254f784 changes the captured source context’s width field, the immediately following reservation calculation sees that change. Cursor advancement retains cached \(w_s\). Redirecting the source descriptor’s context pointer does not redirect this read.

5. **Overlapping destination coverage.** A nonreserved index within both \(n_d\) and \(t\), with successful dependencies, receives separate existing-unit and population acquisitions. The first successful acquisition receives its post-use call before population begins.

6. **Reservation versus source count.** A population source index matching its freshly calculated reserved index is skipped and still advances the cursor. A nonreserved population index is not rejected merely for exceeding \(n_s\); the additional unequal-width source loop does impose that bound.

7. **Boundary threshold.** With \(w_d=1\), reservation result 0x7ffffffe produces boundary 0x00000000:0x7ffffffe. Result 0x7fffffff produces 0xffffffff:0x7fffffff. Result 0xffffffff produces 0xffffffff:0xffffffff.

8. **Failed acquisition with output.** If population destination acquisition fails but writes a nonzero output reference, the conditional post-use call occurs, although its argument remains unresolved. Equivalent cleanup is not guaranteed for failed source acquisition.

9. **Finalizer failure.** If F-b6413637baad returns nonzero, object +224 is nevertheless decremented from its value after that call. Error cleanup follows, the saved status is returned, and no explicit success-marker clear occurs.

10. **Degenerate arithmetic.** Eligibility success with a zero width does not establish safe arithmetic-helper behavior or loop progress. A traversal bound of 0xffffffff does not permit an index strictly greater than that bound before unsigned wraparound.
