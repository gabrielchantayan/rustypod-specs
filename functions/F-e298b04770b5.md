# F-e298b04770b5

## Purpose

F-e298b04770b5 replaces the first 32-bit word of a caller-supplied object with a value read from global storage. After that replacement, it examines a 32-bit field located through an address-bearing word in the object. Depending on the field value and a subsequent check of the address-bearing word, it either returns the original object address or invokes two dependencies in sequence.

Two ordering constraints define the behavior:

- The replacement occurs before the indirect field is examined. If the field aliases the replacement destination, the comparison uses the replacement value, not the field’s value on entry.
- The indirect field is read before the address-bearing word is checked for zero. The later check does not protect the indirect access.

A lifecycle or dispatch-related purpose is possible, but is inferred intent only. The supplied evidence establishes memory accesses and control flow, not a higher-level object role.

## Behavior

### Replacement precedes condition evaluation

The function first obtains the 32-bit global source value and writes it to object offset 0.

This operation is independent of the later branch condition. Subject to successful accesses, it occurs on every path before the address-bearing word or indirect field is evaluated.

The global value is read during the invocation. No fixed value, semantic interpretation, initialization discipline, or immutability is established.

### Indirect field evaluation

After the replacement, the function uses the 32-bit word at object offset 16 to derive an address 32 bytes beyond the address it carries. It then reads a 32-bit field from that derived location and compares it with zero.

The branch depends on the value observed by this read, after the replacement. An entry-state field value is insufficient to determine the branch if the field overlaps the replacement destination.

The comparison divides all 32-bit patterns into zero and nonzero. Signedness does not change that classification: a pattern with all bits set is nonzero.

If the observed field is nonzero:

- The remaining condition operand is skipped.
- Neither dependency is invoked.
- The function returns the original object address, provided execution completes normally.

If the observed field is zero, the function subsequently evaluates whether the word at object offset 16 is nonzero.

### Later address-bearing-word check

The check of object offset 16 follows the indirect field read. It is not a prior validity check.

If this later evaluation produces zero, neither dependency is invoked and the function reaches its ordinary return.

If it produces a nonzero value, the dependency path is selected.

The representation uses the object word once to derive the indirect address and again in the second condition operand. For stable ordinary memory, those uses obtain the same value. ### Aliasing

No disjointness requirement between the global source, object, and indirect field is established.

If the derived field address equals object offset 0, the indirect read follows the replacement write and therefore observes the replacement value under stable, valid memory semantics.

This has two important consequences:

- An initially nonzero field can become zero through the replacement and select the dependency path, provided the later address-bearing-word check is nonzero.
- An initially zero field can become nonzero through the replacement and select the ordinary return path.

The condition therefore cannot be specified using an immutable entry-state snapshot.
