# F-84f8a0152639

## Purpose

F-84f8a0152639 conditionally processes a source record into a destination object. It first checks a one-byte eligibility field and a selector-dependent admission condition. If admitted, it invokes a destination-preparation dependency, classifies the previously captured selector using subsequently read global values, and may invoke a formatter followed by an external transfer-like dependency. One classification additionally copies two 32-bit fields from the source to the destination.

The observable return values are the 32-bit patterns `0x00000000` and `0xFFFFFFCE`. The latter represents −50 when interpreted as a signed 32-bit integer. No named error meaning is established.

The apparent intent is to support two source-record variants with optional formatted content. That interpretation is inferred; the established behavior is the conditional calls, memory accesses, field transfers, and return values described below.

## Interface

### Inputs

The function receives two address-bearing arguments:

- **Source address:** identifies a record containing eligibility, selector, formatting, and transferable fields.
- **Destination address:** identifies the object passed to dependencies and, in one branch, directly updated by this function.

The visible representation uses 32-bit address-bearing arguments and 32-bit field accesses. These arguments are used as addresses, not validated as handles. No null, allocation-size, alignment, or accessibility checks are visible.

There is no visible error propagation from dependencies: their return values are not used.

## Behavior

### Arithmetic and comparison model

Selector calculations are 32-bit additions followed by zero comparisons. Acceptance conditions are expressed here in terms of 32-bit result patterns, including wraparound. For example, adding `0xFFFFFFFF` and `0x00000001` produces a zero pattern.

The supplied representation uses signed-looking integer types for some intermediate values. It does not independently establish a source-language overflow contract. The 32-bit bit-pattern interpretation describes the represented operations without imposing an additional requirement that intermediate mathematical sums remain within the signed 32-bit range.

### 1. Check eligibility

The function first reads the single byte at source offset `0x16`.

If that byte is not exactly `0x01`, it returns `0xFFFFFFCE`. On this path, the visible body does not read the selector, evaluate admission globals, invoke dependencies, or write destination fields.

A different nonzero value, such as `0x02`, does not qualify.

### 2. Capture the selector and check admission

If eligibility succeeds, the function reads the 32-bit selector at source offset `0x0C`. This captured value is retained for later classification; the selector field is not visibly reread.

It adds the admission bias to the captured selector:

- If the resulting 32-bit pattern is zero, admission succeeds.
- Otherwise, it reads the alternate-admission adjustment and adds that adjustment to the preceding result. Admission succeeds only if this second result is zero.

The alternate-admission adjustment is not needed or visibly read when the first admission result is zero.

If both alternatives fail, the function returns `0xFFFFFFCE` without invoking any dependency or directly writing destination fields.

### 3. Prepare the destination before classification

After admission succeeds, the function establishes a prospective success result and calls F-c67cb20988a1 with:

1. The supplied destination address.
2. The numeric argument `0x204`, equal to 516 decimal.

The meaning of `0x204` is not established. It must not be treated as a proven allocation size, clear length, object type, or capacity.

This call occurs before classification. Consequently, an invocation can modify state through this dependency and still ultimately return `0xFFFFFFCE`.

After F-c67cb20988a1 returns normally, the function:

1. Reads and captures the 32-bit external-call argument.
2. Reads the primary classification bias and adds it to the original captured selector.

Thus, destination preparation precedes both of these global reads. Any changes the preparation dependency makes to those globals can affect the invocation. A change it makes to the source selector field does not change the selector already captured by this function.

### 4. Select the primary classification

If the selector plus the primary classification bias is zero, the primary classification is selected.

The function then reads the formatting-enable byte at source offset `0xE5`:

- If zero, it makes no formatting or external-transfer call.
- If nonzero, it performs the optional call sequence described below.

After the optional sequence, if any, completes normally, the function returns `0x00000000`.

This classification does not directly copy the source fields at `0xE8` and `0xEC`.

### 5. Select the alternate classification

If the primary classification result is nonzero, the function reads the alternate-classification adjustment and adds it to that result.

If this adjusted result is zero, the alternate classification is selected. The function first reads the formatting-enable byte and performs the same optional call sequence as for the primary classification.

After that sequence completes—or immediately if formatting is disabled—the function performs these accesses in order:

1. Reads 32 bits from source offset `0xE8`.
2. Writes that value to destination offset `0x10C`.
3. Reads 32 bits from source offset `0xEC`.
4. Writes that value to destination offset `0x110`.

It then returns `0x00000000`.

The two source fields are not captured together before the first destination write. If the address ranges overlap, the first write may affect what the second source read observes. Similarly, any preceding dependency effects can affect the values subsequently copied.

### 6. Reject an unrecognized classification

If neither classification result is zero, the function returns `0xFFFFFFCE`.

On this path:

- F-c67cb20988a1 has already been called.
- The external-call argument and classification globals have already been read as required by the branch.
- The formatting-enable field is not visibly read.
- The formatter and external transfer-like dependency are not called.
- Neither destination field is directly written by this function.

This is not a rollback path.

### Optional call sequence

For either accepted classification, a nonzero formatting-enable byte causes:

1. A call to F-32b90d7f6546 with the address at source offset `0xC0` and the address of a 260-byte temporary buffer.
2. After that call returns normally, a call to an unmapped external dependency with the destination address, the temporary-buffer address, and the previously captured external-call argument.

The external-call argument is not visibly reread after formatting. A formatter-induced change to its global storage therefore does not change the argument passed by this invocation.

The temporary buffer is not visibly initialized before formatting. The visible body does not establish that the formatter writes all 260 bytes, appends a terminator, respects a particular capacity, or produces any particular encoding. It also does not establish that the subsequent external dependency is a string-copy operation.

## Acceptance examples

These examples are conditional on valid accesses and normally returning dependencies. Unless explicitly relevant to an example, assume dependency effects do not change the values used by that example.

1. **Eligibility rejects another nonzero value.**  
   With the eligibility byte equal to `0x02`, the result is `0xFFFFFFCE`. No dependency is invoked.

2. **Admission rejects before preparation.**  
   With eligibility equal to `0x01`, a selector of 10, an admission bias of 1, and an alternate-admission adjustment of 2, the admission results are 11 and 13. The result is `0xFFFFFFCE`, without destination preparation.

3. **Primary classification, formatting disabled.**  
   With successful admission, a selector of 5, a primary classification bias of `0xFFFFFFFB`, and a zero formatting-enable byte, the classification sum is zero. Preparation occurs, formatting does not, no direct field copies occur, and the result is zero.

4. **Alternate classification, formatting enabled.**  
   With successful admission, a selector of 5, a primary classification bias of zero, an alternate-classification adjustment of `0xFFFFFFFB`, and a formatting-enable byte of `0x80`, the alternate classification is selected. The order is preparation, formatter, external dependency, first field read/write, second field read/write, then a zero result.

5. **Admission succeeds but classification fails.**  
   If admission succeeds while both classification results are nonzero, preparation still occurs. The result is `0xFFFFFFCE`, without the optional calls or direct field copies.

6. **Primary classification takes precedence.**  
   If the primary classification result is zero, the alternate-classification adjustment is not read. Even if an alternate calculation could also yield zero, the two direct field copies do not occur.

7. **Preparation changes classification inputs.**  
   If preparation changes the primary classification bias, classification uses its post-call value. If preparation instead changes only the source selector field, classification still uses the selector captured before preparation.

8. **Formatting changes transferable fields.**  
   In the alternate classification, if the formatter changes the source field at `0xE8`, the later copy reads that changed value, subject to any subsequent external-dependency effects.

9. **Wraparound produces a zero result.**  
   A selector pattern of `0xFFFFFFFF` plus a bias of `0x00000001` produces zero under the stated 32-bit arithmetic model. It is not rejected merely because the operands have different signed interpretations.
