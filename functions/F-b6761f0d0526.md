## Behavior

The following order is established by the supplied static representation:

1. Compute the input value plus four.
2. Call F-39e6664876a4 once with that computed value.
3. Read the integer field at byte offset four from the dependency’s returned base and retain that value as the candidate result.
4. Read the same field again and compare this second value with zero.
5. If the second value is zero, read the shared fallback location and replace the candidate with that value.
6. Return the selected value.

The dependency call precedes both field reads. The fallback read, when selected, follows the second field read. There is no explicit reread of the field after the fallback decision.

### Stable field behavior

When the field remains unchanged between its two reads:

- A nonzero field value is returned directly.
- A zero field value causes the fallback to be read and returned.

Negative values are not treated specially. A negative, nonzero second reading takes the non-fallback branch.

The fallback is not itself checked for zero or any other property. It can therefore produce zero, a negative value, or any other representable integer value.

### Changing field behavior

If the first read is nonzero and the second is zero, the candidate is discarded and the fallback is returned.

If the first read is zero and the second is nonzero, the function returns zero from the first read. The second value is used only for the branch decision; it is not returned.

If the two readings are different nonzero values, the first value is returned.
