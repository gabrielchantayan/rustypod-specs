# F-66819ba2201a

## Purpose

F-66819ba2201a conditionally inserts a caller-supplied record at the front of a list-like structure selected through shared state.

The established normal-return behavior has two cases:

- A null input returns null immediately, with no dependency calls or memory accesses through the input.
- A non-null input causes an initial dependency call using the record’s second word, captures a shared pointer to a head-storage location, invokes an entry dependency, links the record through its first word, invokes an exit dependency, and returns null.

The interpretation as a list insertion is inferred from the two linking writes. The source does not establish the surrounding allocator, pool, synchronization, or ownership protocol.

The supplied representation also contains an allocation-like alternative guarded by a second null-input check. That alternative is unreachable through ordinary control flow: null input has already returned, and the input pointer is not subsequently assigned. It is therefore not part of the reachable behavioral contract.

## Interface

### Input

One pointer, either null or pointing to a record with at least two accessible integer-word fields:

| Relative position | Role in this function | Required access |
|---|---|---|
| First word, offset zero | Receives the previous value of the selected head-storage location | Writable |
| Second word, one integer word after the start | Supplies the argument to F-25bf76bbe81a | Readable |

The input pointer is passed by value. The function does not directly assign to the caller’s variable holding that pointer.

For non-null input, the second word must be readable when the initial dependency argument is evaluated. The first word must remain writable until the later linking operation. Whether the initial dependency can invalidate the record is unknown; callers need an external guarantee that it does not do so on the intended path.

### Output

The result has pointer type. Every reachable normal return produces a null pointer.

Null is not a success-versus-failure discriminator:

- Null input returns null without performing the insertion sequence.
- Non-null input also returns null after completing that sequence.

A fault or a dependency that fails to return normally can prevent a result from being produced. No separate error result is established.

### Shared state

The function uses a shared pointer-valued location that selects another memory location. The selected location serves as head storage.

These locations are distinct concepts:

- **Head selector:** shared state containing the address to use.
- **Head storage:** the location at that captured address, whose previous contents are copied into the record and whose new contents become the record’s address.

The selector is read after F-25bf76bbe81a returns and before F-4c6d30ac2311 is invoked. The contents of the selected head storage are read after F-4c6d30ac2311 returns.

### Width and representation constraints

The supplied representation uses integer-word record fields and converts the record pointer to an integer when storing it in head storage. It therefore requires compatible pointer and integer representations for the intended linked structure.

Under a 32-bit integer, 32-bit pointer ABI:

- Each referenced word is four bytes.
- The second word begins at byte offset four.
- The first two words occupy eight bytes.
- Storing the record address in an integer word preserves all address bits.

Those concrete widths are conditional on the target ABI; the supplied fragment does not independently establish its ABI. If pointers are wider than the integer fields, the pointer-to-integer conversion needs implementation-specific interpretation and may not preserve the address. This specification does not silently generalize the operation into a width-independent pointer store.

No arithmetic is performed on the second-word value in this function. It is passed as represented to the dependency. There is no visible range check or overflow-handling path.

## Behavior

### Null input

When the input is null, the function returns null immediately.

On this path it does not:

- Read either record word.
- Invoke any dependency.
- Read the head selector.
- Read or write head storage.
- Attempt an insertion or removal.

This early return is established behavior, not merely a defensive precondition.

### Non-null input: preparation

The function first reads the record’s second word and supplies that value as the sole visible argument to F-25bf76bbe81a.

This read occurs before this function accesses the shared head selector. Consequently, any normal-return effects of F-25bf76bbe81a on the selector can affect which head-storage location is subsequently captured.

No meaning for the second-word value is established. In particular, the function itself does not prove that the value is a size, category, index, handle, or ownership token.

The input is not otherwise validated. Non-nullness alone does not establish that the record is accessible, aligned, live, or suitable for insertion.

### Non-null input: selecting and updating head storage

After F-25bf76bbe81a returns, the function captures the current head selector.

It then invokes F-4c6d30ac2311 with no explicit arguments. The selected head-storage address has already been captured at this point. If that dependency changes the selector, the function nevertheless continues using the previously captured address.

After F-4c6d30ac2311 returns normally, the function performs the linking accesses in this order:

1. Read the current word from the captured head-storage location.
2. Write that word into the record’s first word.
3. Write the integer representation of the record’s address into the captured head-storage location.

The old contents of the record’s first word are not read by this function before replacement.

The head value copied into the record is the value present after the entry dependency returns, not necessarily the value present when the selector was captured. Changes to the selected head storage made by that dependency can therefore affect the link written into the record.

The function next invokes F-cc60a532ba6c with no explicit arguments. If it returns normally, the function returns null.

### Postconditions and dependency interference

Immediately after the two explicit linking writes, and before the exit dependency runs:

- The selected head-storage word contains the record’s address in the integer representation used by this operation.
- Unless those locations alias, the record’s first word contains the previous head-storage value.

These are intermediate postconditions. F-cc60a532ba6c runs afterward, and its effects are not provided. Without its contract, those same memory values cannot be guaranteed at function return.

Likewise, the record’s second word is not directly written by this function, but dependencies may modify it. “No direct write” does not establish preservation across the complete call.

### Aliasing and repeated insertion

No alias check or membership check is present.

If the captured head-storage location is the record’s first word, the first linking write copies that word back to itself. The following write replaces it with the record’s own address representation.

If a record is already the head and the old head value represents that same record, an insertion into distinct head storage writes the record’s own address into its first word. This creates a self-link under the inferred list interpretation.

More generally, this function does not prevent duplicate membership, cycles, or corruption arising from an unsuitable input record. Any prohibition on such inputs belongs to an external protocol.

## Side effects

For a non-null input that reaches normal completion, the direct effects are:

- One read of the record’s second word for the initial dependency argument.
- One read of the head selector.
- One read from the captured head-storage location.
- One write to the record’s first word.
- One write to the captured head-storage location.
- Calls to F-25bf76bbe81a, F-4c6d30ac2311, and F-cc60a532ba6c, in that order.

The function does not directly allocate, clear a record, release memory, or report an error on any reachable path. This does not establish that its dependencies lack those effects.

Ownership transfer is not established. Linking a record into shared storage suggests enrollment in an external structure, but it does not prove who may subsequently access, reuse, or release the record. The caller cannot infer continued exclusive ownership from the null return.

Synchronization is also not established. The entry and exit dependency positions are consistent with a protected update, but their names, pairing, and placement do not prove locking semantics. In particular, the selector capture occurs before the entry dependency, and the second-word read occurs before both.

There is no visible recovery or rollback. If the record write succeeds and the subsequent head-storage write fails, no compensating action is specified. If a dependency does not return normally, later accesses and calls are not guaranteed.

## Acceptance examples

These are conditional acceptance criteria derived from static inspection, not executed tests. Address-valued examples assume a compatible integer-and-pointer representation.

### Null input

Given null input, the expected result is null. None of the dependencies is invoked, and no head-selector or record access occurs.

### Inserting into empty head storage

Given a valid record, selected head storage containing zero, and dependencies that return normally without interfering with the relevant memory:

- F-25bf76bbe81a receives the record’s initial second-word value.
- The record’s first word becomes zero.
- Head storage becomes the record’s address representation.
- The result is null.

The original first-word contents do not affect these writes.

### Inserting before an existing head

Given selected head storage containing the address representation of another record, with distinct storage and no dependency interference:

- The input record’s first word receives that existing head value.
- Head storage receives the input record’s address representation.
- The result is null.

The function does not dereference the previous head record.

### Selector changed by the initial dependency

Given that F-25bf76bbe81a changes the selector from one valid head-storage location to another, the function captures and uses the new location after that dependency returns. The old location is not selected by this function merely because it was current at entry.

### Selector changed by the entry dependency

Given that F-4c6d30ac2311 changes the selector after capture, the linking accesses still target the captured location. If it instead changes that location’s contents, the changed contents are the value copied into the record.

### Self-aliasing storage

Given that captured head storage is exactly the record’s first word, with no dependency interference, that word contains the record’s own address representation after the linking writes. Acceptance must not require preservation of its earlier value as a separate next-link field.
