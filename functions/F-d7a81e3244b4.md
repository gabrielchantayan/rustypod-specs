# F-d7a81e3244b4

## Purpose

F-d7a81e3244b4 performs an ordered object-state update followed by dependency calls. It clears one object byte, invokes a preliminary dependency, reads a value from a referenced global location, obtains an opaque result using that value and two addressable argument copies, delivers the result through an object-selected callable, and invokes a final dependency on one of the copies.

The established contract is the sequence, memory accesses, and argument flow. The application-level purpose is unknown. The evidence does not establish text processing, display behavior, allocation, resource release, or ownership transfer.

This specification is based on static evidence only. No runtime tests have been performed.

| Second argument | An opaque 32-bit value with no explicit use in the function body. |

## Behavior

### Initial write and local copies

The first explicit object-memory operation stores zero into the byte at offset 177. It occurs before any dependency invocation.

The function then initializes two distinct addressable 32-bit local cells: one from the third argument and one from the fourth argument. These initializations precede the preliminary dependency.

The source establishes the cells’ distinct identities and initial values. It does not establish a public aggregate layout, a required address difference between them, or a caller-visible storage arrangement.

### Preliminary dependency

F-dc842e45211e is invoked with the original object reference as its sole explicit argument.

The object byte has already been cleared when this invocation begins. There is no second direct clear after the dependency returns.

The dependency’s effects are unknown. In particular, it is not established to preserve:

- The cleared object byte.
- The object’s leading dispatch word or dispatch storage.
- The referenced global location.
- Other accessible object or global state.

Consequently, neither the entry value of the global nor an entry-time dispatch target determines the later calls. The function does not capture either before invoking this dependency.

### Ordered global read and value generation

After F-dc842e45211e returns normally, the function reads the referenced global location to obtain the second argument for F-9b9c1c7483f4.

A change made to that location by F-dc842e45211e can therefore affect the argument supplied. The function does not use a global value saved before the preliminary call and does not establish that the value is a constant.

F-9b9c1c7483f4 receives, in argument-position order:

1. The address of the cell initially populated from the fourth argument.
2. The value obtained by the post-preliminary-call global read.
3. The address of the cell initially populated from the third argument.

Argument-position order does not establish an additional evaluation order among otherwise independent argument expressions. The established global-read ordering is that it follows return from F-dc842e45211e and supplies the subsequent F-9b9c1c7483f4 invocation.

Both local addresses refer to writable local storage. The call site does not impose an input-only contract. Whether the dependency reads, modifies, or retains either address is unknown.

The function retains F-9b9c1c7483f4’s 32-bit result for the indirect call. There is no explicit conversion, validation, zero check, or status interpretation.

### Object-selected indirect call

After F-9b9c1c7483f4 returns, the function reads the object’s leading word as the dispatch base. It then reads the callable entry at byte offset 284 from that base.

Dispatch resolution therefore occurs after both preceding dependency calls. A valid change to the dispatch base or entry made by either dependency can affect the selected target. The function does not use a target cached at entry.

The selected callable receives:

1. The original object reference.
2. The exact 32-bit result returned by F-9b9c1c7483f4.

The result is passed by value. Neither local cell’s contents nor the global location’s address are substituted for it.

No explicit check validates the dispatch base or callable entry. Any result from the indirect call is ignored by this function.

### Final dependency and return

If the indirect callable returns normally, F-8a5aadac202f receives the address of the same local cell initially populated from the fourth argument and passed as the first argument to F-9b9c1c7483f4.

This preserves cell identity, not merely equality of values. The function does not restore the fourth argument’s original value before this call. If the cell has changed, F-8a5aadac202f receives access to its current contents.

There is no corresponding explicit F-8a5aadac202f invocation on the third-argument cell.

After the final dependency returns normally, the function returns without an explicit result.
