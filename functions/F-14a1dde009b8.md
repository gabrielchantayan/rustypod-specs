# F-14a1dde009b8

## Purpose

F-14a1dde009b8 selects between an immediate status return and one of three indirect operations on a caller-supplied receiver.

The selection depends on:

- A one-byte field in a context object.
- For one context-field value, a 32-bit selector obtained through a global reference.
- For all other context-field values, the result of an indirect eligibility operation reached through F-b7af80e829ec.

The established behavior is dispatch and return-value forwarding. The meanings of the context field, selector, eligibility result, and receiver operations are not established. Descriptions such as “mode,” “selector,” and “eligibility” are descriptive labels, not claims about application semantics.

## Interface

### Inputs

The function has two explicit inputs:

1. **Context address.** An address used to read one byte at displacement `0x2EC`. No other context field is directly accessed.
2. **Receiver address.** An address whose first machine word is interpreted as an operation-table address when a receiver operation is selected. The selected table entry is invoked with the receiver address as its sole explicit argument.

The supplied representation uses 32-bit integers, 32-bit return values, and four-byte pointer-table entries. This contract describes that represented 32-bit layout; it does not establish compatibility with another pointer width or calling convention.

Although the context input is represented as an integer, the function uses it as an address. No numerical interpretation of the context address is otherwise established.

### Result

The result is a 32-bit value:

- Exactly `0` when the eligibility operation returns a nonzero 32-bit result.
- Exactly `1` when the context byte equals `2` and the selector equals either `0` or `4`.
- Otherwise, the selected receiver operation’s 32-bit return value, forwarded without normalization or interpretation.

A forwarded value need not be Boolean. Any 32-bit pattern returned by a normally completing receiver operation is preserved.

### Relevant layouts

| Object or table | Displacement | Read and interpretation |
|---|---:|---|
| Context | `0x2EC` | One byte, compared for equality with `2` |
| Global-selected object | `0x1C` | One 32-bit selector |

The global reference supplying the selector object is separate from both explicit inputs. The supplied evidence does not establish its initialization, ownership, lifetime, or relationship to either input.

### Preconditions

The context byte must be readable on every invocation.

Additional requirements are path-dependent:

- A context byte equal to `2` requires a usable global reference and a readable 32-bit selector at displacement `0x1C`.
- Any other context byte requires F-b7af80e829ec to return an address from which the eligibility operation can be resolved and invoked.
- A receiver-dispatch path requires a readable receiver table pointer, a readable selected table entry, and an executable target compatible with the invocation.
- Normal return requires every invoked dependency to return normally.

There are no explicit null, bounds, lifetime, alignment, or executable-target checks. On a path returning before receiver dispatch, the function does not dereference the receiver.

## Behavior

### Initial decision

The first direct data access is a one-byte read at context displacement `0x2EC`.

Only equality with the byte value `2` matters. Byte signedness does not affect that equality test. Every other byte value takes the eligibility path.

The function does not subsequently reread this context byte. A dependency changing it does not restart or revise the decision already made by this invocation.

### Context byte equal to `2`

The function obtains the selector through the global reference and reads one 32-bit value at displacement `0x1C`.

The selector determines the result or operation as follows:

| Selector | Behavior |
|---:|---|
| `0` | Return `1` immediately |
| `1` | Invoke the default receiver operation |
| `2` | Invoke the receiver operation at table displacement `0x11C` |
| `3` | Invoke the receiver operation at table displacement `0x128` |
| `4` | Return `1` immediately |
| Any other 32-bit value | Invoke the default receiver operation |

The default receiver operation is at table displacement `0x10C`.

This path does not call F-b7af80e829ec or the eligibility operation. Selector values `0` and `4` return without reading the receiver or its operation table.

The selector is tested against the listed constants rather than used as a table index. Values outside `0` through `4`, including values whose top bit is set, select the default operation; they do not cause selector-dependent indexing.

### Context byte other than `2`

The function calls F-b7af80e829ec with no explicit arguments.

From the returned address, it reads an operation-table address at displacement zero. It then reads the function address at table displacement `0x134` and invokes that target with no explicit arguments shown in the supplied representation.

The eligibility operation’s 32-bit result controls the next action:

- A nonzero result causes an immediate return of `0`.
- A zero result causes invocation of the default receiver operation at table displacement `0x10C`.

The nonzero eligibility result itself is not forwarded. For example, results of `1`, `2`, and `0xFFFFFFFF` all produce the same outer result, `0`.

This path does not read the global selector. A selector value that would otherwise choose an alternate operation or an immediate return is irrelevant on this path.

### Receiver dispatch

For any selected receiver operation, the function:

- Reads the operation-table address from the receiver’s first word.
- Resolves the function address at the selected fixed table displacement.
- Invokes that function with the receiver address as the sole explicit argument.
- Returns the operation’s 32-bit result unchanged.

There is at most one receiver-operation invocation per call to F-14a1dde009b8.

On the eligibility path, receiver-table resolution occurs only after the eligibility operation returns zero. Consequently, changes made by F-b7af80e829ec or the eligibility operation to the receiver’s table pointer or table entries can affect the subsequent dispatch. The function does not capture the receiver operation before making those calls.

Once the selected function address has been loaded, the invocation uses that loaded address. No additional table lookup is shown before the call.

### Arithmetic and width boundaries

All exposed displacements are fixed byte offsets. There is no caller-controlled index multiplication, count computation, allocation-size calculation, or selector-derived address arithmetic.

The selector and indirect return values are 32-bit quantities. The context comparison uses one byte rather than a 32-bit context field.

The evidence provides no defined recovery for an invalid effective address, an address calculation outside a valid object, or an incompatible indirect target. These cases are outside the established normal-return contract.

## Side effects

### Direct effects

The function contains no explicit writes to caller memory or global data.

Its direct memory reads are limited to those required by the selected path:

- The context byte on every invocation.
- The global reference and selector on the context-byte-equals-`2` path.
- The helper-returned object’s table pointer and eligibility-operation entry on the other path.
- The receiver’s table pointer and one selected receiver-operation entry when dispatch occurs.

The function performs no explicit allocation, deallocation, ownership transfer, reference-count update, or cleanup.

### Dependency effects

Absence of direct writes is not a purity guarantee. F-b7af80e829ec and all indirect targets may have effects not visible in this function.

In particular, the evidence does not establish that any dependency:

- Preserves global state.
- Preserves the receiver or context.
- Leaves operation tables unchanged.
- Retains, releases, or avoids retaining supplied objects.
- Avoids allocation, deallocation, I/O, synchronization, or nonlocal control transfer.

The receiver address is explicitly passed to a selected receiver operation. It is not explicitly passed to F-b7af80e829ec or the eligibility operation in the supplied representation. That distinction does not prove that those dependencies cannot access the receiver through other state.

The returned object from F-b7af80e829ec is used to resolve the eligibility operation. F-14a1dde009b8 does not explicitly release it. Whether a release is required, performed elsewhere, or inappropriate is unknown.

### Failure handling

There is no explicit error-reporting channel beyond the 32-bit result, and no established interpretation of that result as an error code.

The function does not explicitly catch dependency failures, repair invalid pointers, retry calls, or substitute fallback targets. If a dependency does not return normally, the corresponding normal-return behavior cannot be assumed.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They are not reports of executed tests.

1. **Immediate result for selector zero.**  
   Given a readable context byte equal to `2` and a readable selector equal to `0`, the function returns `1`. It does not call F-b7af80e829ec, invoke the eligibility operation, or read the receiver’s table pointer.

2. **Immediate result for selector four.**  
   Under the same conditions with selector `4`, the result is also `1`, with no receiver dispatch.

3. **Default selection for selector one.**  
   Given context byte `2`, selector `1`, and a valid default receiver operation returning `0x81234567`, the function passes the receiver to that operation and returns `0x81234567` unchanged.

4. **Alternate receiver operations.**  
   Given context byte `2`, selector `2` selects table displacement `0x11C`; selector `3` selects `0x128`. Neither case invokes the helper or eligibility operation.

5. **Unrecognized selector.**  
   Given context byte `2` and selector `0xFFFFFFFF`, the default operation at `0x10C` is selected. The value does not index outside the table.

6. **Eligibility rejection.**  
   Given context byte `0`, a valid helper result, and an eligibility result of `7`, the function returns `0`. It does not read the receiver table or global selector.

7. **Eligibility acceptance.**  
   Given any context byte other than `2` and an eligibility result of zero, the default receiver operation is invoked. Its return value is forwarded even if the global selector would have selected a different operation.

8. **Receiver-table mutation before dispatch.**  
   If the eligibility operation returns zero after replacing the receiver’s table pointer with another valid table pointer, dispatch resolves the default entry through the replacement table.

9. **Context mutation after the initial read.**  
   If the initial context byte is not `2` and a dependency later changes it to `2`, the invocation remains on the eligibility path. It does not then read the global selector.

10. **Unused receiver on an immediate-return path.**  
    If all accesses and calls required before an immediate return are valid, receiver-table readability is not required for that path because the receiver is not dereferenced.

## Evidence
