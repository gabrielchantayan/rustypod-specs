# F-414082ff6ca6

## Purpose

F-414082ff6ca6 conditionally obtains a 32-bit value associated with the position immediately preceding a stored position in an object.

The established behavior is narrower than a conventional “read last element” contract: the function enters an object-associated operation, queries a condition, and either returns zero or constructs and adjusts a four-word position descriptor before reading one 32-bit word through a derived address. It invokes a corresponding closing operation before returning normally.

The descriptor arithmetic is consistent with moving backward across fixed-size blocks of four-byte elements. That interpretation is inferred intent, not a guarantee supplied by the dependency implementations. In particular, the condition query is not independently established to mean “empty,” the arithmetic dependency is not independently established to perform division, and the entry and closing operations are not independently established to acquire and release a lock.

## Interface

**Input**

One object address, interpreted using the supplied 32-bit address and integer model.

The function forms and passes three addresses associated with that object:

| Object-relative location | Use |
|---|---|
| Offset 0 | Input to the condition dependency |
| Offset 16 bytes | Source supplied to the first descriptor operation |
| Offset 44 bytes | Argument to both the entry and closing dependencies |

These uses do not establish the complete object layout or the sizes of the corresponding subobjects.

**Output**

One 32-bit word:

- If the condition dependency returns any nonzero value, the function returns zero after invoking the closing dependency.
- If the condition dependency returns zero, the function obtains its return word by a final indirect 32-bit read, then invokes the closing dependency and returns the already-obtained word.

Zero is therefore not an unambiguous status indication. The value-reading path may also produce zero.

**Temporary storage and descriptor layout**

The function supplies three separate 16-byte temporary areas to descriptor operations. Two are involved in obtaining a working descriptor; the third receives the final descriptor operation.

The working descriptor is treated as four consecutive 32-bit words:

| Byte offset | Operational role |
|---|---|
| 0 | Current element address |
| 4 | Block-start address |
| 8 | Block-end address |
| 12 | Address of a block-map entry |

These role names describe the visible arithmetic and dereferences. They do not establish an external type definition.

The pointer returned by the second descriptor operation is the working descriptor address. The function does not explicitly require that this pointer equal the destination temporary supplied to that operation.

**Preconditions for normal completion**

The applicable dependencies must accept their supplied addresses and return normally. On the value-reading path:

- The second descriptor operation must return a descriptor address supporting the reads and writes described below.
- Every block-map entry actually dereferenced must be readable as a 32-bit address.
- The first word of the final temporary must identify readable storage for a 32-bit value.
- Address arithmetic and signed arithmetic must remain meaningful under the applicable execution model.

The function performs no explicit null, alignment, range, descriptor-consistency, or arithmetic-overflow checks. The supplied representation alone does not establish portable behavior outside valid arithmetic and memory-access cases.

## Behavior

### 1. Enter the object-associated operation

The function forms the address at object offset 44 and invokes F-4a19e3742733 with that address.

It then invokes F-be518f1dc9cf with the original object address. Its result controls the only top-level branch.

No descriptor preparation is visible before this query.

### 2. Handle a nonzero condition result

If F-be518f1dc9cf returns any nonzero value:

1. Invoke F-fd58bea73663 with the previously formed address at object offset 44.
2. Return the 32-bit value zero.

This branch makes no calls to the descriptor, geometry, or arithmetic dependencies. It does not perform the final indirect value read.

Calls on this branch may nevertheless read or modify state internally; their implementations are not supplied.

### 3. Obtain a working descriptor

If the condition result is zero:

1. Invoke F-92a3b44cff14 with the first 16-byte temporary as destination and object offset 16 as source. Its return value is not used.
2. Invoke F-92a3b44cff14 again, with the second 16-byte temporary as destination and the first temporary as source.
3. Use the second call’s returned pointer as the working descriptor address.

This establishes a two-stage descriptor operation. It does not establish that either operation is a plain memory copy, that it initializes every destination byte, or that it returns its destination.

### 4. Derive a predecessor coordinate and movement value

From the working descriptor’s current-address and block-start words, calculate a signed coordinate by:

- Subtracting the block-start word from the current-address word.
- Applying a signed right shift by two bits to that difference.
- Subtracting one.

Thus, for aligned, nonoverflowing addresses within a block, a current address twelve bytes after the block start produces coordinate 2. A current address equal to the block start produces coordinate −1.

The coordinate is retained across the following dependency calls.

**For a nonnegative coordinate:**

1. Invoke F-5d8a0091da0c once.
2. Invoke F-d7be9cfb4000 with the coordinate as its first argument and that dependency result as its second argument.
3. Use the arithmetic dependency’s result as the signed movement value.

**For a negative coordinate:**

1. Invoke F-5d8a0091da0c once and retain its 32-bit result for the second argument of F-d7be9cfb4000.
2. Invoke F-5d8a0091da0c a second time.
3. Form the first arithmetic argument by subtracting the coordinate from the second result, then subtracting one.
4. Invoke F-d7be9cfb4000 with that first argument and the retained result from the first call.
5. Negate the returned signed result to obtain the movement value.

The two geometry results in the negative case are obtained by separate calls. They must not be assumed equal or interchangeable.

If the geometry dependency returns a stable positive block capacity, and the arithmetic dependency performs the expected positive-integer division, this calculation is consistent with selecting a block displacement for a predecessor position. Those dependency semantics remain conditional.

### 5. Adjust the working descriptor

The function branches on whether the movement value is zero.

**Zero movement**

Read the working descriptor’s current-address word at this point, subtract four bytes, and retain that address as the new current position.

This read occurs after the preceding dependency calls. It is not necessarily a reuse of the current-address value originally used to calculate the coordinate.

The function itself does not write the block-start, block-end, or map-entry words on this branch.

**Nonzero movement**

Perform these operations in order:

1. Read the descriptor’s map-entry address and add four times the signed movement.
2. Write that resulting address to the descriptor’s map-entry word.
3. Read one 32-bit address through the newly computed map-entry address.
4. Write the loaded address to the descriptor’s block-start word.
5. Invoke F-5d8a0091da0c.
6. Read the descriptor’s block-start word and write the block-end word as that address plus four times the dependency result.
7. Invoke F-5d8a0091da0c again.
8. Read the descriptor’s block-start word and calculate the new current address as that address plus four times the difference between the retained coordinate and the movement multiplied by this latest dependency result.

The block-end calculation and the new-current calculation use distinct calls to F-5d8a0091da0c. Neither call is established to preserve globals or descriptor-reachable memory. In particular, the later block-start reads must not be treated as permanently cached copies of the earlier map-entry load.

**Common completion**

Write the new current address to the descriptor’s first word.

For nonzero movement, this first-word write occurs after the map-entry, block-start, and block-end writes. For zero movement, it is the only descriptor-word write explicitly performed by this function.

### 6. Materialize and read the result

Invoke F-92a3b44cff14 a third time:

- Destination: the third 16-byte temporary.
- Source: the working descriptor.

The return value of this third call is not used.

Read the first 32-bit word of the third temporary as an address. Read one 32-bit word through that address and retain it as the function’s return value.

Then invoke F-fd58bea73663 with the saved address at object offset 44, and return the retained word.

The final value load precedes the closing call. Changes made by that closing call to the value’s original storage do not trigger a second load.

## Side effects

**Direct memory effects**

The function exposes three temporary destinations to F-92a3b44cff14. On the value-reading path, it also writes through the working descriptor pointer returned by the second descriptor operation.

Those descriptor writes may affect only temporary storage, or they may affect aliased object or shared storage. The supplied material does not establish the returned pointer’s aliasing relationship.

On nonzero movement, direct descriptor writes occur in this order:

1. Map-entry address.
2. Block-start address.
3. Block-end address.
4. Current address.

On zero movement, only the current-address word is directly written.

The function directly reads a block-map entry only on nonzero movement. It directly reads the returned value only after the third descriptor operation.

**Dependency effects**

Every dependency may have additional effects not visible here. The entry/closing pairing suggests synchronization or scoped state management, but that role is not established.

**Ownership and lifetime**

No explicit allocation or deallocation appears in the function. This does not establish that dependencies allocate nothing or release nothing.

Temporary addresses are passed to dependencies. Their validity after this invocation, whether dependencies retain them, and whether descriptor operations create objects requiring destruction are unknown. No explicit descriptor-destruction call appears.

**Failure and cleanup**

There is no visible error translation, retry, or alternate cleanup path.

Both ordinary branches invoke the closing dependency once. If a dependency does not return normally, or an invalid access interrupts execution before closure, no exceptional-cleanup guarantee is established.

## Acceptance examples

The following are conditional acceptance cases, not runtime observations.

### Nonzero query result

Given that the entry dependency returns normally and the condition dependency returns −1:

- The closing dependency is invoked with object offset 44.
- The function returns zero.
- No descriptor, geometry, or arithmetic dependency is invoked by this function.

The same branch applies to every other nonzero query result.

### Predecessor within the current block

Assume:

- The condition result is zero.
- The working descriptor initially has block start 4096 and current address 4108.
- Relevant dependencies do not modify that descriptor unexpectedly.
- The geometry call returns 8.
- The arithmetic dependency returns zero for arguments 2 and 8.
- The final descriptor operation makes its destination’s first word equal the adjusted current address.

The coordinate is 2. Zero movement changes the current address to 4104, without this function writing the other three descriptor words. The final value read is the 32-bit word at address 4104.

### Predecessor across a block boundary

Assume:

- The current address equals the block-start address.
- Each geometry call returns 8.
- The arithmetic dependency returns 1 for arguments 8 and 8.
- The original map-entry address is 8196.
- The 32-bit word at map-entry address 8192 is 12288.
- Dependencies do not alter the relevant descriptor fields.
- The final descriptor operation exposes the adjusted current address.

The coordinate is −1 and the movement is −1. The descriptor receives:

- Map-entry address 8192.
- Block-start address 12288.
- Block-end address 12320.
- Current address 12316.

The returned word is read from address 12316.

### Distinct geometry observations

For a negative coordinate, the first two geometry calls return 8 and 16 respectively. The arithmetic dependency receives the first result, 8, as its second argument. Its first argument is calculated using 16.

An implementation that merges these calls or substitutes one result for the other does not preserve the established call and arithmetic behavior.

### Return value loaded before closure

Assume the final indirect read obtains 37, and the closing dependency subsequently changes the same storage to 99. The function returns 37, provided the closing dependency returns normally.

## Uncertainties

The following remain **documented_only**:

- The semantic identity of the object and the condition being queried.
- Whether entry and closure provide synchronization, and whether they are balanced under abnormal exits.
- Whether descriptor operations are copies, constructors, adapters, or something else.
- Whether the working descriptor aliases an object field, temporary storage, or other memory.
- The geometry dependency’s meaning, stability, signedness contract, and permitted result range.
- The arithmetic dependency’s operation, rounding rules, and invalid-input behavior.
- Callee effects on global state, descriptor memory, allocation, and ownership.
- Behavior for null addresses, malformed descriptors, unmapped block entries, unaligned accesses, or an unavailable predecessor.
- Exact overflow behavior for subtraction, multiplication by four, negation, and address addition.
- Treatment of negative shifted values beyond what the signed-shift representation suggests.

Four-byte scaling and four-word descriptor accesses establish the relevant layout in the supplied 32-bit model. They do not justify treating arithmetic as unbounded mathematical integer arithmetic or assigning portable overflow semantics.

## Evidence

Established static evidence consists of the supplied function representation: dependency call sites, branch conditions, temporary sizes, four-word descriptor accesses, address calculations, direct dereferences, and return-value ordering.

The block-based predecessor interpretation is inferred from four-byte element scaling, map-entry movement, block-bound updates, and the final indirect value load. It is not independently confirmed by dependency implementations.

No runtime tests have been performed. The acceptance examples state conditional consequences of the visible behavior and explicitly supplied dependency assumptions; they are not execution results.
