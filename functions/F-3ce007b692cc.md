## Behavior

### Initial state and primary delegation

The fourth argument initializes a call-local state object. The function then calls F-34a22f177269 with these three arguments, in order:

1. The first argument’s opaque value.
2. The second argument’s signed integer value.
3. The address of the initialized call-local state.

F-34a22f177269 receives writable access to the local state. It can therefore determine the state subsequently used by this function. If the dependency leaves that object unchanged, its value remains the fourth argument.

The primary dependency’s return value is captured as the function’s eventual direct result. No success classification or error decoding is applied to that value.

### Conditional secondary invocation

After F-34a22f177269 returns normally, the function checks whether the local state is zero. Only when it is zero does the second argument’s strict-positivity condition matter.

The secondary dependency, labeled F-unmapped-1 in this document, is invoked exactly when both conditions hold:

- The local state observed for the condition equals zero.
- The second argument is greater than zero under signed comparison.

The dependency receives the captured primary result followed by the second argument. It does not receive the output destination or local-state address as an explicit argument.

A zero second argument does not satisfy the condition. Neither does a negative second argument, even if its underlying bit pattern would be large when interpreted as unsigned.

Any nonzero local-state value suppresses the secondary invocation, regardless of the sign or magnitude of the second argument. Positive and negative nonzero state values are treated alike.

There is at most one secondary invocation along the visible normal-return path. Its return value, if any, is not used.

### Final publication and return

After the conditional invocation has either completed or been skipped, the function reads the local state for publication and writes it to the caller’s output destination. It then returns the captured primary result.

Publication occurs after the secondary dependency returns, not before it is called.

For example, F-34a22f177269 could make the supplied local-state address available to the secondary dependency through another channel. If that dependency changes the local state while it remains valid, the final publication uses the later value. No preservation guarantee for unknown dependencies is established.

The function itself performs no arithmetic transformation of its integer inputs: there is no visible addition, subtraction, multiplication, scaling, truncation, or saturation. The relevant integer operations are copying, equality with zero, and signed comparison with zero.
