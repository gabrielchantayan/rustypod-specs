# F-40d83a28ddf3

## Purpose

F-40d83a28ddf3 is a state-driven routine that transforms a signed 32-bit input, accesses caller-supplied 16-bit storage, and invokes F-870c4fcf7295 and F-531bdc62ac41.

Its established behavior is a dispatch machine with ten numbered categories and a shared default action. Externally supplied values determine dispatch, arithmetic, transitions, and storage addresses. The supplied evidence does not establish an application-level purpose, a required buffer size, a fixed traversal, or termination.

This contract describes static evidence only. Acceptance examples are conditional consequences of that evidence; no runtime tests have been performed.

## Interface

The explicit inputs are:

- One pointer to unsigned 16-bit elements, with no accompanying length.

There is no explicit return value. Observable outputs are memory accesses and modifications, dependency calls, dependency effects, and whether the routine returns.

## Behavior

### Entry, dispatch, and arithmetic model

Before dispatch begins, the routine reads the initialization-transition seed, primary seed, selector component, and initial state, in that order.

The active storage pointer starts null. Both counters, saved adjustment, saved triple, retained data, secondary and tertiary seeds, and all four transition components start at zero.

Every dispatch reads, in order:

1. An entry multiplier.
2. A signed entry index scale.
3. The dispatch base.

The dispatch category is the current state minus the dispatch base, using unsigned 32-bit subtraction modulo \(2^{32}\). Differences zero through nine have explicit cases. Difference three and every other unmatched difference execute the shared action. Difference four returns, but only after these dispatch-entry reads.

Arithmetic is not uniformly mathematical-integer arithmetic or uniformly unsigned arithmetic. The representation includes signed 32-bit operations, unsigned 32-bit operations, signed 16-bit conversions, and explicit narrowing. A later unsigned assignment or 16-bit store does not make an earlier signed overflow valid.

### Classification and arithmetic transitions: categories zero and nine

Both categories construct a 32-bit classification pattern from scaled counter projections, an external adjustment, and category-specific external masks. The construction includes addition, subtraction, inclusive-or, complement, and exclusive-or. A correction term depends on the low two bits of a decremented projection.

The resulting pattern is interpreted as signed 32-bit data, shifted right by 31, increased by one, and retained as an unsigned 32-bit transition weight, denoted \(w\).

The shift behavior is essential:

- A nonnegative classification gives \(w=1\).
- With **sign-propagating right shift**, a negative classification gives \(w=0\).
- With **zero-filling right shift**, a negative classification gives \(w=2\).

Negative signed-right-shift behavior is not resolved by the supplied evidence. Therefore, describing this weight as an unconditional binary selector would be incorrect.

The downstream transitions are arithmetic combinations, not conditional branches. Each uses \(w\) and its bitwise exclusive-or with one. For binary weights, this behaves as selection. For \(w=2\), that exclusive-or is three, so both alternatives contribute. The resulting transition arithmetic is unsigned 32-bit arithmetic.

The classification is not established to test only counter sign, parity, or range. Its external coefficients and masks matter, and its signed intermediate operations have independent validity requirements.

**Category zero** uses the first counter, an additive external adjustment, and its own masks. After computing the weight, it saves the first counter minus a separate external adjustment.

Two candidate transition values are formed by XORing the retained selector component with two different external modifiers. Call them the negative-side and nonnegative-side alternatives. The next state is:

\[
(\text{negative-side alternative})(w\mathbin{\mathrm{xor}}1)
+
w(\text{nonnegative-side alternative})
\pmod{2^{32}}.
\]

Thus, under sign-propagating shift, negative classification chooses the negative-side alternative and nonnegative classification chooses the nonnegative-side alternative. Under zero-filling shift, negative classification instead produces three times the negative-side alternative plus twice the nonnegative-side alternative, modulo \(2^{32}\).

Category zero makes no dependency call.

**Category nine** uses the indexing counter and a different mask pair. It forms the first scaled projection, then saves three times the indexing counter using signed multiplication. Its classification directly subtracts an external adjustment from the first projection; it does not first negate that adjustment.

The weight is computed before either dependency call. F-870c4fcf7295 is then called twice, each time with the tertiary seed minus a separate external adjustment and with second argument 2,147,483,647. The second adjustment is read after the first call.

If the two secondary results are \(R_1\) and \(R_2\), in call order, the next state is:

\[
R_1w+R_2(w\mathbin{\mathrm{xor}}1)\pmod{2^{32}}.
\]

Under sign-propagating shift, nonnegative classification chooses \(R_1\), and negative classification chooses \(R_2\). Under zero-filling shift, negative classification instead yields \(2R_1+3R_2\) modulo \(2^{32}\).

Both calls occur for every weight. Dependency effects can change the second adjustment read, but cannot change the already computed weight.

### Categories one, five, six, and seven

**Category one** obtains the next state by XORing its transition component with a freshly read external modifier.

**Category five** resets the indexing counter to zero, then obtains the next state by XORing its transition component with an external modifier.

**Category six** calls F-870c4fcf7295 with the secondary seed minus an external adjustment and second argument 2,147,483,647. After the call, an external modifier XOR-updates the category-one transition component. The call’s secondary result becomes the next state.

**Category seven** replaces the first counter with the saved adjustment multiplied by one external factor and then by another. The first multiplication precedes the second. These factors are fresh reads, not reuse of dispatch-entry captures. The next state is its transition component XOR an external modifier.

Categories five and seven neither narrow retained data nor update the selector component.

### Category eight: initialization

Category eight multiplies the explicit integer input by an external coefficient and retains the resulting 32-bit value, subject to intermediate arithmetic validity.

Before calling a dependency, it calculates the next state by XORing the entry-captured initialization-transition seed with an external modifier. It then calls F-870c4fcf7295 with the primary seed plus an external adjustment and second argument 2,147,483,647.

After the call, external initialization values are read in this order:

1. Secondary seed.
2. Category-five transition component.
3. Category-seven transition component.
4. Category-two transition component.
5. Category-one transition component.

The caller’s pointer is then installed as the active pointer. The routine subsequently reads the tertiary seed and captures a selector-component modifier.

Finally, it replaces the primary seed with the call’s secondary result, reduces retained data to its low 16 bits, and XOR-updates the selector component with the captured modifier.

The next-state calculation precedes the dependency call, while the listed initialization reads follow it and can observe dependency effects. Re-entering this category is not equivalent to restarting the routine: several retained values are not reset.

### Category two: paired storage update

This category first reads element zero, multiplies its unsigned value by an external coefficient, and retains the low 16 bits for argument construction.

From that reduced value and another external coefficient, it derives a complemented 32-bit mask whose low 16 bits are all set. Further terms scale the mask’s complement, the mask itself, and the reduced value.

F-531bdc62ac41 receives three derived arguments:

1. A product of two external coefficients and an accumulated sum, reduced to 16 bits after the complete product. The coefficient product precedes multiplication by the sum. The sum incorporates the saved triple, an external offset, the first counter, and the three derived terms.
2. A separate read of one of those coefficients, increased by 3,968.
3. A freshly read external scale multiplied by an adjusted sum of derived terms and another external coefficient. The external adjustment is subtracted inside the scaled quantity. There is no explicit 16-bit mask on this argument.

This description does not authorize reassociation of intermediate arithmetic or a common snapshot of external values. A total evaluation order among argument subexpressions is not established.

The helper result is consumed as signed 16-bit data. Two external result-scaling coefficients are separately converted to signed 16 bits. Their product is formed first, then multiplied by the signed helper result. The final store narrows to 16 bits; that narrowing does not define overflow in an earlier promoted signed multiplication.

#### Destinations and access order

Both destination indices use the signed scale captured at dispatch entry. Their common contribution is formed by:

- Multiplying that scale by the indexing counter, then multiplying the result by three.
- Separately multiplying the scale by the first counter.
- Adding those two contributions.

The first destination adds one; the second adds ten. Tripling the indexing counter before multiplying by the scale is not an equivalent arithmetic contract.

The observable sequence is:

1. Read element zero and construct the helper arguments.
2. Call F-531bdc62ac41.
3. Capture an external counter-update coefficient.
4. Read the result-scaling coefficients and store the scaled helper result at the first destination.
5. Read element zero into retained data.
6. Read element zero again and store that value at the second destination.
7. Update the indexing counter.
8. Read a transition modifier and XOR it with the category-two transition component to obtain the next state.

The relative evaluation order of the two result-scaling coefficient reads is not established. The two later element-zero reads are distinct.

The counter update right-shifts the entry scale by 30, XORs that result with the captured unsigned coefficient, multiplies by the scale, and then multiplies by the old indexing counter minus the captured coefficient.

The coefficient’s unsigned type makes the XOR, subsequent products, and counter difference unsigned 32-bit operations. Converting an out-of-range result back to the signed counter remains target-dependent.

With sign-propagating shift, the scale shifted by 30 can be negative two, negative one, zero, or one. With zero-filling shift, it can be zero through three. This shift is not merely a sign test.

The pre-store coefficient capture and post-store transition read are distinct boundaries: aliasing stores can affect the latter without changing the former.

After that call, the first counter is reset to zero. Retained data is formed from the call’s secondary result, the dispatch-entry multiplier, and two coefficients read after the call. The low 16 bits are stored to element zero. Intermediate product ordering remains significant.

Three further F-870c4fcf7295 calls follow:

- Call two uses the primary seed minus an external adjustment.
- Call three uses the secondary seed plus an external adjustment.
- Call four uses the tertiary seed plus an external adjustment.

Each has second argument 2,147,483,647.

A selector-component modifier is captured between calls two and three. Between calls three and four, external modifiers XOR-update the category-one and category-five transition components, in that order. ## Acceptance examples

These criteria assume the specified category is reached, relevant dependencies return, and all required accesses and intermediate arithmetic are valid.

### Dispatch and return

A current state of zero and dispatch base of one produce unsigned difference 4,294,967,295 and enter the shared action.

Difference four returns after the dispatch-entry external reads, without category-specific calls or array accesses.

### Shift-dependent transitions

A nonnegative classification gives weight one under either sign-propagating or zero-filling right shift. Category zero therefore uses its nonnegative-side alternative; category nine uses the first call’s secondary result.

For a negative classification **and sign-propagating right shift**, the weight is zero. Category zero uses its negative-side alternative; category nine uses the second call’s secondary result. Both category-nine calls still occur.

For a negative classification **and zero-filling right shift**, the weight is two and its XOR with one is three. If category zero’s negative-side and nonnegative-side alternatives are five and seven, its next state is 29, not either alternative. If category nine’s secondary results are ten and twenty, its next state is 80, not either result.

Without a resolved negative signed-shift rule, negative classification alone does not determine either transition.

### Subtraction and destination grouping

In category nine, a first projection and directly subtracted adjustment both equal to the minimum signed 32-bit value produce zero for that subtraction. No unrepresentable negation of the adjustment is required. Other classification operations retain their independent validity conditions.

A valid common destination contribution of 20 produces stores to elements 21 and 30, in that order.

With entry scale zero and indexing counter one billion, the indexing contribution is formed as zero multiplied by three. It does not require calculating three billion first. This does not establish validity of category nine’s separate saved-triple calculation for that counter.

### Aliasing and retained state

If the first destination is element zero, its helper-derived store precedes both later source reads. Without intervening changes, the second destination receives the newly stored pattern.

A store overlapping the counter-update coefficient does not alter its already captured value. A store overlapping the later transition modifier can affect that subsequent read.

Category five resets the indexing counter regardless of its prior value. Category seven, with saved adjustment two and successive factors three and four, replaces the first counter with 24.

In the shared action, distinct secondary results from calls two, three, and four become the next state, secondary seed, and tertiary seed respectively.

### Narrowing and null storage

A valid final store value of 65,537 stores pattern one. A valid final store value of negative one stores pattern 65,535. Neither example defines overflowing intermediate arithmetic.

A path that returns without dereferencing storage may avoid an invalid access despite a null pointer. Every reached access still requires valid storage.
