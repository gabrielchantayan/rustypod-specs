# F-1ad02ec5946e

## Purpose

- If the 32-bit field at byte offset 4 from the first argument initially equals 4, it transfers one 32-bit word from the third argument’s address to the address returned by F-4e1ae5394b9d.
- Otherwise, it invokes an unresolved indirect dependency with the helper’s result, the third argument, and a fresh 32-bit read of that same field.

This is the established control-flow distinction. Interpreting the field as a byte count, the helper as an allocator, or the indirect dependency as a general memory-copy operation is **inferred intent**, not an established contract.

The function has no explicit result value or success indicator.

## Behavior

### Initial decision

The function first reads the 32-bit field at byte offset 4 from the object address and compares its value with 4.

This read determines the branch before F-4e1ae5394b9d is invoked. A later change to the field does not cause the branch decision to be repeated.

There is no visible null check, bounds check, sign check, or validity check before the field read.

### Direct-transfer path

When the initial field value equals 4:

1. F-4e1ae5394b9d is invoked with the object address.
2. Its result is used as a destination address.
3. One 32-bit value is read from the source address.
4. That value is written to the returned destination address.
5. The function returns.

The direct operation transfers exactly four bytes’ worth of scalar value. No byte-order conversion, arithmetic transformation, or additional copy is visible.

The helper completes before the source value is read. Consequently, the source value used is the value available after the helper returns, not necessarily the value present when F-1ad02ec5946e was entered. The helper is not known to preserve the source storage, object storage, or other reachable state.

The field at object offset 4 is not read again by this path. If the helper changes it to a value other than 4, the selected direct transfer still occurs, provided execution can otherwise continue.

No unresolved indirect dependency is invoked by this branch.

### Delegated path

When the initial field value does not equal 4:

1. F-4e1ae5394b9d is invoked with the object address.
2. After that helper returns, the function obtains the value of the 32-bit field at object offset 4 again.
3. An unresolved indirect dependency is invoked with these arguments, in this order:
   - the helper’s returned value;
   - the original source address;
   - the newly read 32-bit field value.
4. If the dependency returns normally, F-1ad02ec5946e returns without consuming a result.

The second field read is not interchangeable with the first. A helper-induced change can alter the third argument supplied to the indirect dependency without changing which branch is taken.

The helper result is forwarded as a value on this path. The visible body does not itself dereference it. Likewise, the visible body does not itself read the source’s contents on this path.

The indirect call target is obtained through a stored function-pointer reference. The supplied representation does not establish an ordering between obtaining that target and reading the third argument. Both belong to the indirect-call expression after the helper invocation; no stronger ordering between them is claimed.

There is no visible special treatment for zero, negative-looking values, very large values, or values that become 4 after the helper returns.
