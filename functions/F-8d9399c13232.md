# F-8d9399c13232

## Purpose

F-8d9399c13232 performs an ordered sequence of dependency calls on selected fields of an input record. If the record contains a nonzero secondary-object address, it also processes that object's fields, adjusts allocation-related accounting, validates allocation metadata, and invokes a final sequence of context-associated dependencies.

The established behavior is the sequence of reads, calls, arithmetic, and writes described below. Interpreting this operation as object destruction or allocation release is **inferred intent**, not a demonstrated ownership contract. In particular, the available evidence does not establish which dependencies release memory, invalidate their arguments, acquire synchronization, or preserve global state.

The function has no explicit return value. It neither clears the input record nor explicitly clears its secondary-object reference.

## Behavior

### 1. Process input-record fields in fixed order

The function reads a field and invokes its corresponding dependency before proceeding to the next field:

1. Input `+0x00` through F-e5380ae57ea1.
2. Input `+0x0c` through F-ed9979230848.
3. Input `+0x10` through F-841dc33ee157.
4. Input `+0x14` through F-e5380ae57ea1.
5. Input `+0x18` through F-841dc33ee157.
6. Input `+0x1c` through F-e5380ae57ea1.
7. Input `+0x20` through F-6c7ac9769d41.
8. Input `+0x2c` through F-841dc33ee157.

These calls are unconditional. A zero field value is still passed to its dependency.

The fields are not captured as an initial snapshot. Each later field is read after preceding calls return. Consequently, a dependency that changes an unread field can affect a later argument.

Only after all eight calls does the function read input `+0x30`. If it is zero, the function returns without processing secondary metadata or updating the accounting described below.

### 2. Process the secondary object

For a nonzero secondary-object address, operations occur in this order:

1. Read the 32-bit flag word at secondary `+0x20`. If bit 0 is set, read secondary `+0x1c` and pass it to F-94cb53877c15.
2. Read the flag word at secondary `+0x18`. If bit 0 is set, read secondary `+0x14` and pass it to F-94cb53877c15.
3. Read secondary `+0x08` and call F-841dc33ee157.
4. Read secondary `+0x0c` and call F-841dc33ee157.
5. Read secondary `+0x10` and call F-e5380ae57ea1.
6. Read secondary `+0x38` and call F-6c7ac9769d41.

Only bit 0 controls each conditional call. Other flag bits do not affect the branch. A selected argument is passed even when its value is zero.

The flag at `+0x18` is read after the first conditional call, if that call occurs. A mutation by that call can therefore alter whether the second conditional call occurs. The same read-after-call principle applies to subsequent fields.

### 3. Derive the allocation address and update global accounting

After secondary-field processing, the function captures a global accounting-object address. It then reads the secondary displacement at `−0x04` and derives the allocation address.

It reads the 32-bit quantity at allocation `−0x08`. Call this quantity the accounting quantity. The global accounting object's adjacent words at `+0x38` and `+0x3c` are then updated as low and high components:

- Read the old low word.
- Write the low word minus the accounting quantity, modulo \(2^{32}\).
- Read and update the high word by subtracting the sum of:
  - the accounting quantity's arithmetic sign-extension term, which is zero when bit 31 is clear and `0xffffffff` when bit 31 is set; and
  - an unsigned borrow indicator, equal to one when the old low word is less than the accounting quantity.

The high-word arithmetic is also modulo \(2^{32}\). As a combined two-word operation, this subtracts the **sign-extended 32-bit accounting quantity**, not necessarily its zero-extended unsigned value.

The low-word write precedes the high-word write. No intervening dependency call occurs between them.

The function next calls F-2fd8826557a4 with no explicit argument. Only after that call returns does it read a separate global reference to obtain the context address used for the remaining operations.

### 4. Recognize the derived-address sentinel

This sentinel check occurs **after**:

- both global accounting writes;

Thus, the sentinel does not bypass all metadata access or accounting. With a derived address of `8`, the accounting-quantity read addresses numeric address zero. Whether such an access is valid is environment-dependent and not established here.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. They assume all reached accesses are valid and dependencies return unless explicitly nonreturning.

1. **Absent secondary object.** If input `+0x30` is zero when read, the eight input-field calls occur in their specified order, followed by return. No secondary-field call, accounting adjustment, or context lookup occurs.

2. **Flag ordering.** If secondary `+0x20` has bit 0 set and secondary `+0x18` has bit 0 clear when each is read, only the `+0x1c` argument is passed to F-94cb53877c15. If that first call changes `+0x18` to an odd value, the second conditional call must also occur.

3. **Unsigned borrow.** With accounting quantity 8 and old accounting words high 5, low 3, the new words are high 4, low `0xfffffffb`.

4. **Signed accounting quantity.** With accounting quantity `0xffffffff` and old words high 5, low 3, the new words are high 5, low 4. This demonstrates subtraction of sign-extended negative one, rather than unsigned subtraction of 4,294,967,295.

5. **Rejected header after accounting.** A zero header or an odd header reaches F-a817d8d58c10 after the global update and F-2fd8826557a4. It does not reach F-c0fc6d033caa or the subsequent counter updates through normal control flow.

6. **Header masking.** A header of `0xc0000012` passes the bit-0 check and yields quantity `0x10` when masked. If unchanged through the relevant reads, that quantity is subtracted at all five quantity-adjustment sites.

7. **Late header mutation.** If F-09dcb55e8e0a changes a previously captured masked quantity from 16 to 32 in the header, the earlier four subtractions remain 16 each, while the subtraction at context `+0x08` uses 32.

8. **Counter wraparound.** A selected decrement counter containing zero becomes `0xffffffff`. A quantity counter smaller than its subtraction amount wraps modulo \(2^{32}\); no error branch is established.
