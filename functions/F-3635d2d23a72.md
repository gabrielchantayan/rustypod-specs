# F-3635d2d23a72

## Purpose

F-3635d2d23a72 performs an ordered, teardown-like sequence on a mutable object. On normal completion, it returns the original object address.

Established behavior includes replacing dispatch words, checking invariants, conditionally calling an associated object, calling several opaque dependencies, processing an auxiliary record, and conditionally clearing a shared-context reference. Destruction, detachment, notification, and iteration are inferred interpretations, not established dependency semantics.

The function does not directly release the input object’s storage. No called function is assumed to release memory, preserve globals, maintain pointer validity, or write through its arguments unless that behavior is independently established.

Two explicit invariant-failure paths call an opaque dependency and then, if that dependency returns, call F-feee9156a257, which is marked non-returning in the supplied representation.

**Input:** one pointer to a mutable object.

**Normal result:** the identical pointer value supplied as input. No alternate success value or explicit error status is visible.

**Representation:** pointers and accessed words are 32 bits. Offsets below are byte offsets. The input object must support the selected accesses through offset `0xBF`, giving a directly accessed extent of at least `0xC0` bytes.

**Conditions for defined ordinary completion:**

## Behavior

### Entry dispatch writes and invariant checks

The function first reads a global dispatch value and retains that 32-bit observation. It separately reads the same global again and writes the second observation to object offset `0x00`. It then writes the first observation plus `0x124` to object offset `0xA4`.

The two global reads are distinct. Equality between them is not established. In particular, the secondary word is derived from the first read, not from the value necessarily written to the primary word.

The addition is an address-like byte displacement in a 32-bit representation, not an increment by `0x124` words. The evidence does not settle signed-overflow semantics or the validity of a wrapped address. Ordinary completion requires a valid dispatch configuration; overflow behavior is documented only.

Next, the function checks offsets `0xA8`, `0xAC`, `0xB0`, `0xB4`, `0xB8`, and `0xBC`, in that order. At the first nonzero word:

1. F-163ea045cd81 is called with no visible arguments.
2. If it returns, F-feee9156a257 is called.

Later invariant words and subsequent teardown stages are not reached through that path. The function does not clear the invariant words. Both entry dispatch writes precede any such failure.

No diagnostic effect of F-163ea045cd81 is established by its invocation alone.

### Association-dependent calls

After all six entry invariants pass, another global dispatch value is read and installed at object offset `0x00`.

F-d277584d672d is called with the input pointer. A null result skips the association-dependent indirect calls.

For a non-null result, the function invokes its dispatch entry at byte offset `0x80`, visibly passing the associated-object pointer. The returned pointer is compared with the original input pointer.

Only on equality does the function invoke the associated object’s dispatch entry at byte offset `0x7C`, visibly passing that object and a 32-bit zero. The associated object’s dispatch word is read again for this second call; it need not still contain the table used for the first call.

Clearing an association is plausible intent. The established contract is the lookup, pointer comparison, and conditional indirect invocation.

1. F-3fdd14ecd250 is called, and the returned context’s field at `0x28` is tested against zero.
2. If nonzero, F-3fdd14ecd250 is called again. The object referenced by this new context’s `0x28` field supplies an indirect target at dispatch offset `0x48`, which is invoked with no explicit arguments shown.

2. Object offset `0x04` is reread and tested.

## Side effects

- Four staged assignments to object offset `0x00`, provided execution reaches each stage;
- One assignment to object offset `0xA4`;
- A conditional zero assignment to a returned context’s offset `0x24`.

All dependency and indirect-call effects remain opaque. No memory-release or ownership transfer follows merely from a cleanup-shaped call or a particular dispatch offset. Retained pointers must remain valid for subsequent accesses, but the function does not enforce that requirement.

There is no visible rollback, synchronization, or general exception handling. Earlier writes and calls precede any later failure. Safe repetition, concurrent use, and temporary-storage cleanup after abnormal exits are not established.

## Acceptance examples

These are conditional static examples, not executed tests. They assume valid storage and returning callees except at designated non-returning endpoints.

1. **Distinct entry observations.** If the first dispatch-global read yields address A and the second yields address B, the primary word receives B and the secondary word receives A plus `0x124`, assuming valid arithmetic and addresses. Equality is not required.

2. **Entry failure.** If the first three entry invariants are zero and the fourth is nonzero, both entry writes occur before F-163ea045cd81. If it returns, F-feee9156a257 follows. No association lookup is reached.

3. **Changed notification global.** If an earlier dependency changes the notification-argument global and no later change intervenes before its read, F-77781c8e0ff9 receives that changed value, not an assumed original constant.

4. **Association mismatch.** If the association’s `0x80` call returns a pointer unequal to the input, the `0x7C` call is omitted.

5. **Absent auxiliary record.** A null auxiliary pointer at capture skips all auxiliary calls and context reconciliation. Earlier notification and final attachment processing remain eligible.

6. **Null loop result pointer.** A nonzero F-ebd94610a438 return followed by a valid zero first result word causes no item call. The next loop-control call still occurs.

7. **Unwritten result storage.** A nonzero loop-control return does not alone prove a valid result. If the dependency has not supplied a suitable first word and no valid prior value exists, safe item processing is not established.

8. **Two handle calls.** A nonzero auxiliary predicate plus a later context `0x28` equal to the input causes two F-a82ec4b43e2f calls with the retained handle.

9. **Replacement collection.** If F-944b595e25e9 leaves a different valid non-null pointer at auxiliary `0x08`, subsequent collection dispatch uses that current pointer.

10. **Attachment removal.** If the initial attachment is non-null but F-c719314a16bb clears it, attachment dispatch is skipped while the late invariant is still checked.

11. **Skipped late invariant.** If the initial attachment test is zero, a nonzero object field at `0x08` does not independently trigger failure.

12. **Normal completion.** When selected accesses and calls are valid and applicable invariants pass, the returned pointer equals the input, regardless of dependency changes to object contents.
