# F-e4e2db384d33

## Purpose

F-e4e2db384d33 accepts one 32-bit word and produces one 32-bit word. Its established behavior combines:

- Two input-based early exits.
- A call to F-f2b8ff34d9f0.
- Bit-field extraction and integer shifting of that dependency’s result.
- Sign-dependent limiting results.
- Configuration-dependent exceptional dispatch through an unresolved control-transfer target.

The bit patterns are consistent with a conversion involving an IEEE 754 binary32 representation and a signed 32-bit destination. That interpretation is **inferred intent**, not an established interface guarantee. In particular, neither the input’s numeric representation nor F-f2b8ff34d9f0’s semantics are supplied.

This contract therefore defines behavior in terms of 32-bit words, signed interpretations, masks, and observable call boundaries. It does not promise a complete mathematical conversion for all inputs.

## Behavior

### 1. Ordered entry checks

The entry threshold is consulted first.

If the entry threshold is less than or equal to the signed interpretation of the input word, the function returns `0x7fffffff` immediately.

Only if that comparison is false does the function perform the unsigned comparison against `0xc6ffffff`.

If the unsigned input word is greater than `0xc6ffffff`, the function returns `0x80000000` immediately.

Consequences of this ordering:

- The first check has precedence if both conditions would otherwise be true.
- Neither early exit calls F-f2b8ff34d9f0.
- Neither early exit reaches the visible configuration-dependent dispatch.
- The exact set of inputs reaching the dependency cannot be enumerated without the entry threshold and its comparison semantics.

The supplied representation explicitly casts the input to signed form for the first check, but does not supply the threshold declaration. A signed threshold comparison appears intended; its exact type remains an uncertainty.

### 2. Dependency call and derived fields

If neither entry check returns, F-f2b8ff34d9f0 is called with two arguments, in order:

1. The unchanged input word.
2. The value 16.

Its returned 32-bit word is called the **converted word** below. This name does not assert that the dependency performs a numeric conversion.

The function derives:

- An **exponent/sign field**, obtained by interpreting the converted word as signed 32-bit and shifting it right arithmetically by 23 positions.
- A **shifted payload**, obtained by shifting the converted word left by eight positions, retaining only 32 bits.

If the exponent/sign field is nonzero, bit 31 of the shifted payload is set.

The exponent/sign field retains sign extension. It is not merely an unsigned eight-bit exponent. Its low eight bits can, however, be used independently as a field value.

There is no visible reapplication of the input checks after the dependency call.

### 3. Negative-field conversion path

If the exponent/sign field has a negative signed interpretation, the function compares the converted word, unsigned, against `0xcf000001`.

When the converted word is less than that boundary:

- If the low eight bits of the exponent/sign field are zero, bit 31 of the shifted payload is cleared.
- A shift distance is formed by subtracting those low eight bits from 158 and retaining the low eight bits of the difference.
- The shifted payload is shifted right logically by that distance.
- The arithmetic negation of that result is returned as a 32-bit word.

For this branch, the accepted converted-word range is `0x80000000` through `0xcf000000`, inclusive. Its low-eight-bit field values range from 0 through 158, so the computed distance ranges from 158 down to zero.

For distances from zero through 31, the visible operations determine the result directly. For larger distances, the result depends on shift semantics not established by the supplied material.

The return is a raw 32-bit result. Negation must not be interpreted as an unbounded mathematical operation with a wider result.

If the converted word is `0xcf000001` or greater, this conversion path does not return; processing continues to the fallback classification.

### 4. Nonnegative-field conversion path

If the exponent/sign field is nonnegative, this path returns only when both conditions hold:

- The field is less than 159.
- Subtracting the field from 158 does not produce zero.

These conditions select field values 0 through 157. Field value 158 deliberately does not return through this branch.

The function returns the shifted payload shifted right logically by the low eight bits of the difference between 158 and the field.

The resulting shift distances are 158 through 1. As in the negative path, distances above 31 are not assigned an assumed result by this contract.

A zero exponent/sign field does not receive the additional high bit used for nonzero fields. This distinction affects zero-like and subnormal-like bit patterns if the converted word is interpreted as binary32.

### 5. Fallback classification and limiting return

If neither conversion path has returned, the converted word is doubled with 32-bit wraparound. The result is called the **doubled word**.

If the doubled word is less than or equal to `0xff000000`, the function returns:

- `0x7fffffff` when the converted word’s sign bit is clear.
- `0x80000000` when the converted word’s sign bit is set.

The supplied representation separates equality with `0xff000000` from lower values, but both cases compute the same result. No different externally visible result is established for equality.

The doubling is not a widening multiplication. Overflow is discarded before the unsigned comparison. For example, doubling `0x80000000` produces zero as a 32-bit word.

Under a binary32 interpretation, the condition for proceeding beyond this fallback comparison corresponds to an all-ones exponent with a nonzero fraction. This supports a NaN-related interpretation of the remaining dispatch, but does not prove a public NaN-handling contract.

### 6. Configuration-dependent exceptional dispatch

This stage is reached only when the doubled word is greater than `0xff000000`.

The low four bits of a configuration-word read select a mode. Later configuration tests are separate source-level reads, not an established immutable snapshot.

All targets in this stage are unresolved. The supplied representation presents them as indirect calls followed by return of their result. It does not establish whether the machine behavior is actually a normal call, tail transfer, exception return, or another control-flow mechanism.

#### Mode 9

The function next tests configuration bit `0x00100000`.

- If clear, the apparent transfer receives one explicit argument: zero.
- If set, it receives two explicit arguments:
  1. The value 8.
  2. A word formed by shifting a configuration-word read left 15 positions, complementing all 32 bits, then shifting left one position with 32-bit truncation.

The value used to construct the second argument is not established to be the same read that selected the mode or tested the bit.

#### Mode 10

The configured result word is read first.

Configuration bit `0x40` is then tested. If set, the selected argument is replaced by `0x80000000`; otherwise the previously read configured result word is retained.

The apparent transfer receives that selected word as its single explicit argument.

The configured result word is read even when the subsequent configuration test causes its value to be discarded.

#### Mode 8

Configuration bit `0x40` is tested first.

If set, the apparent transfer receives two zero arguments.

If clear:

- Auxiliary word A is read.
- Configuration bit `0x10` is tested.
- If bit `0x10` is clear, the apparent arguments are auxiliary word A and the doubled word.
- If bit `0x10` is set, auxiliary word B is read, and the apparent arguments are zero and auxiliary word B.

Thus auxiliary word A is read even when bit `0x10` later causes it to be discarded.

#### Other modes

For low-four-bit modes other than 8, 9, or 10, the representation shows an unresolved transfer with no explicit arguments.

This establishes neither that all argument registers are cleared nor that the actual target accepts no parameters.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **First-check precedence.** If the threshold comparison succeeds, the result is `0x7fffffff`, even if the unsigned input also exceeds `0xc6ffffff`. No dependency call occurs.

2. **Second-check exit.** If the threshold comparison fails and the input is `0xc7000000`, the result is `0x80000000`. F-f2b8ff34d9f0 is not called.

3. **Second-check boundary.** If the threshold comparison fails and the input is exactly `0xc6ffffff`, the second check does not return. The dependency is called with that input and 16.

4. **Positive unit pattern.** If both entry checks permit progress and the dependency returns `0x3f800000`, the field is 127, the shifted payload is `0x80000000`, and the right-shift distance is 31. The result is `0x00000001`.

5. **Negative unit pattern.** Under the same entry condition, a dependency result of `0xbf800000` produces `0xffffffff`, the 32-bit representation of −1.

6. **Negative conversion boundary.** A dependency result of `0xcf000000` enters the negative conversion branch with shift distance zero and returns `0x80000000`.

7. **Positive fallback boundary.** A dependency result of `0x4f000000` has field value 158, so it bypasses the positive shifting return. Its doubled word is `0x9e000000`; the result is `0x7fffffff`.

8. **Infinity-like patterns.** Dependency results `0x7f800000` and `0xff800000` both produce doubled word `0xff000000`. They return `0x7fffffff` and `0x80000000`, respectively, without exceptional configuration dispatch.

9. **Exceptional mode 10.** If the dependency returns `0x7fc00000`, the doubled word is `0xff800000`, so exceptional dispatch is reached. If the selecting configuration read has low four bits equal to 10, the configured result word is read. If the later bit-`0x40` test is set, the apparent transfer argument is `0x80000000`, regardless of the configured result word.

10. **Wide-shift limitation.** A dependency result of zero selects a right-shift distance of 158. This contract does not assert that the result is zero without additional target shift semantics.
