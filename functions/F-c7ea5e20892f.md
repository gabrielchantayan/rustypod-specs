# F-c7ea5e20892f

## Purpose

F-c7ea5e20892f replaces selected fields in one shared 32-bit state word according to four inputs, preserving every bit outside those fields. It then returns a 64-bit value whose upper 32 bits equal the first input and whose lower 32 bits are zero.

The established behavior is a masked read-modify-write. The meanings of the selected fields are unknown. Interpreting them as device settings, operating modes, or enable flags would be inferred intent, not an established contract.

The update is unconditional: every invocation reaching the end performs a state-word write, including invocations whose resulting word equals the original word.

| 2 | Secondary selector | Signed 32-bit integer | Exactly 1 selects state bit 28. |

## Behavior

### State transition

Let the original state word be the 32-bit value read from the target address.

Six fields are replaced:

| State field | Cleared mask | Replacement rule |
|---|---:|---|
| Bit 29 | `0x20000000` | Set when the primary selector is nonzero; otherwise clear. |
| Bit 28 | `0x10000000` | Set only when the secondary selector equals 1. |
| Bits 25–24 | `0x03000000` | Low-byte selector 1 selects `01`; 2 selects `10`; every other value selects `00`. |
| Bits 21–20 | `0x00300000` | Middle-byte selector 1 selects `01`; every other value selects `00`. |
| Bits 17–16 | `0x00030000` | High-byte selector 1 selects `01`; 2 selects `10`; every other value selects `00`. |
| Bit 0 | `0x00000001` | Set only when the final selector equals 1. |

For each two-bit field, the displayed binary value is ordered from its higher-numbered bit to its lower-numbered bit.

The combined replacement mask is `0x33330001`. All state bits selected by its complement, `0xCCCCFFFE`, retain their values from the initial read.

This preservation applies to the sampled word, not necessarily to changes another actor makes after that read.

### Exact selector matching

Only the primary selector uses a general nonzero condition.

The secondary and final selectors require exact equality to 1. Values such as 2, −1, and the minimum signed 32-bit value clear their respective bits.

Packed-byte selectors likewise use exact matches:

- A low or high byte of 1 selects the lower bit of its two-bit field.
- A low or high byte of 2 selects the upper bit.
- Any other byte, including `0x03`, `0x80`, and `0xFF`, clears both bits.
- A middle byte of 1 sets bit 20.
- Every other middle byte, including 2, clears both bits 21 and 20.

No combination of inputs makes either bit of a two-bit field inherit its previous value. The entire field is replaced.

Bit 21 is always zero in the stored result. The other two-bit fields can become `00`, `01`, or `10`, but never `11`.

### Observable operation order

The visible routine performs the following externally relevant actions:

1. Reads the target 32-bit state word.
2. Computes its replacements using the arguments and the sampled value.
3. Writes the resulting 32-bit state word.
4. Returns the constructed 64-bit result.

The intervening field changes are local computations. They are not separate writes to shared state. An observer therefore must not expect to see six successive field updates caused by this routine.

The field computations appear in this order: bit 29, bit 28, bits 25–24, bits 21–20, bits 17–16, and bit 0. Because these fields do not overlap and there are no intervening visible calls or state-word writes, this ordering does not create additional intermediate shared states.

The read and write each address the word through the global base reference. Stability of that reference throughout the invocation is a precondition for interpreting the operation as an update to one particular storage location. The supplied representation does not establish how often that reference is physically loaded.
