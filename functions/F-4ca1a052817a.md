# F-4ca1a052817a

## Purpose

F-4ca1a052817a copies and numerically filters byte samples from two source address sequences into two destination address sequences. Each active outer iteration produces three destination positions per sequence, with a configurable byte count at each position.

The established behavior is address arithmetic, ordered byte reads, a direct byte copy, and five fixed-point filtered writes. Interpreting the sequences as image rows or interlaced fields is plausible intent, not an established format contract. No particular image format, channel arrangement, or coefficient values are supplied.

The function has no explicit return value, validation result, allocation, or cleanup operation.

## Interface

The function accepts two descriptor addresses:

- **Source descriptor:** supplies two source base addresses, a value passed to a dependency, and a source stride.
- **Destination descriptor:** supplies two destination base addresses, two factors determining the byte count, and a destination stride.

Descriptor fields occupy 32-bit slots. Addresses are represented by 32-bit values in the supplied representation.

| Byte offset | Source descriptor use | Destination descriptor use |
|---|---|---|
| 0 | First source base | First destination base |
| 4 | Second source base | Second destination base |
| 8 | First argument to F-870c4fcf7295 | No direct field read |
| 12 | No direct field read | First byte-count factor |
| 16 | Source byte stride | Destination byte stride |

Fields not directly read here may still be inspected or modified by dependencies receiving a descriptor address. The table does not establish either descriptor’s complete size or layout.

## Behavior

### Setup and dependency order

The observable setup sequence is:

1. Read the source descriptor’s field at byte offset 8 and call F-870c4fcf7295 with that value and the constant 5.
2. Treat the returned 64-bit quantity as two 32-bit portions:
   - The low portion, interpreted as signed, determines the outer-loop bound after multiplication by 5.
   - The high portion, interpreted as signed, is divided by 2 with truncation toward zero.
3. Read and retain the source stride.
4. Call F-c8a7bc15a71d with the source descriptor address.
5. Add that dependency’s 32-bit result to the product of the retained source stride and the halved high portion.
6. Read the first and second source bases, in that order, and add the common adjustment to each.
7. Read and retain the destination stride.
8. Call F-c8a7bc15a71d with the destination descriptor address.
9. Read and retain, in order, the first destination base, second destination base, byte-count factor at offset 12, and byte-count factor at offset 32.

This timing matters if a dependency changes descriptor fields. In particular, each stride is captured before its corresponding F-c8a7bc15a71d call, while the associated base addresses are read afterward.

Use the following mathematical labels:

- \(A\), \(B\): adjusted first and second source bases.
- \(s\): retained source stride.
- \(D\), \(E\): first and second destination bases.
- \(d\): retained destination stride.
- \(z\): destination-side result from F-c8a7bc15a71d.
- \(L\): 32-bit outer-loop bound derived from five times the first dependency result’s signed low portion.

These labels describe the contract, not a public data structure.

### Byte count

The two destination factors are multiplied using the represented 32-bit arithmetic. Let the signed interpretation of that product be \(p\).

The inner byte count is:

\[
N=\operatorname{trunc}(p/8)
\]

The supplied signed-bias-and-shift expression implements division by 8 with truncation toward zero, rather than rounding negative values downward.

The multiplication occurs before division. An unbounded mathematical product followed by division is therefore not an equivalent model when the product exceeds 32 bits.

Each outer iteration processes byte offsets \(j=0,\ldots,N-1\). If \(N\leq0\), it performs no sample reads or destination writes, but still performs that outer iteration’s dependency call and address calculations.

### Outer iteration and placement

A 32-bit unsigned position starts at zero and increases by 5 after every outer iteration. The continuation test interprets that position as signed and compares it with \(L\).

For each entered iteration, with position \(u\):

1. Call F-870c4fcf7295 with the 32-bit product \(6u\) and the constant 10.
2. Interpret the returned low 32 bits as signed; call this value \(q\).
3. Establish destination starts:

\[
X=D+z+dq,\qquad Y=E+z+dq
\]

The six writes for each byte offset target, in order:

\[
X+j,\quad Y+j,\quad X+d+j,\quad Y+d+j,\quad X+2d+j,\quad Y+2d+j
\]

No particular relation between \(q\) and \(u\) is established without the dependency’s behavior. In particular, contiguous output groups are not guaranteed by this function alone.

Under ordinary, nonoverflowing conditions with a nonnegative low dependency result, \(L\) is a multiple of 5 and there is one outer iteration per unit of that result. Outside those conditions, the exact signed comparison and 32-bit counter arithmetic govern execution; a simple iteration-count formula is not safe.

### Source selection and boundary handling

Let \(t=\operatorname{trunc}(\operatorname{signed}(u)/2)\).

For an even \(u\), choose the two principal source starts as:

\[
P=A+st,\qquad Q=B+st
\]

For an odd \(u\), choose:

\[
P=B+st,\qquad Q=A+s(t+1)
\]

Because the position advances by 5, parity alternates during ordinary nonwrapping traversal.

The additional source starts are initially:

- Earlier boundary sample: \(P\).
- First sequence’s next sample: \(P+s\).
- First sequence’s second-next sample: \(P+2s\).
- Second sequence’s next sample: \(Q+s\).
- Second sequence’s second-next sample: \(Q+2s\).
- Later boundary sample: \(P+3s\).

Two boundary rules modify these starts:

- On every iteration with \(u\neq0\), the earlier boundary sample becomes \(Q-s\).
- If that nonzero position also equals the 32-bit unsigned value \(L-5\), both the later boundary sample and the second sequence’s second-next sample become \(P+2s\).

The second rule is not applied at position zero. Consequently, a single ordinary iteration retains the initial later boundary address \(P+3s\); it does not receive the final-iteration substitution.

Negative or zero strides are not explicitly rejected. Address validity, not a positive-stride assumption, determines whether such inputs are usable.

### Byte acquisition

For each byte offset \(j\), the function reads eight unsigned 8-bit samples in this order:

1. Earlier boundary sample, denoted \(v\).
2. Second sequence’s second-next sample, denoted \(w\).
3. Principal sample at \(P+j\), denoted \(a\).
4. Principal sample at \(Q+j\), denoted \(b\).
5. Sample at \(P+2s+j\), denoted \(c\).
6. Sample at \(P+s+j\), denoted \(e\).
7. Sample at \(Q+s+j\), denoted \(f\).
8. Later boundary sample, denoted \(g\).

All eight reads precede all six writes for that byte offset. Coincident addresses still correspond to separate reads in this sequence; the contract does not replace them with a single shared read.

### Filtering and output order

Nine global coefficient storage locations are referenced. Denote them \(K_0\) through \(K_8\). Their numeric values are not supplied.

Define the output conversion:

\[
H(x)=
\begin{cases}
0 & x<0\\
255 & x>267386880\\
x\mathbin{\mathrm{div}}1048576 & \text{otherwise}
\end{cases}
\]

Here \(x\) is the signed interpretation of the completed 32-bit accumulator. The upper clamp is \(255\cdot2^{20}\). Once clamped, division by \(2^{20}\) discards fractional bits; there is no rounding-to-nearest bias.

For each byte offset, the writes occur in the following order:

1. **At \(X+j\):** write \(a\) unchanged.
2. **At \(Y+j\):** write the converted accumulator

   \[
   H\!\left(K_3e+K_2b+\operatorname{s16}(K_0)v
   +64\operatorname{s16}(K_1)a\right)
   \]

   where \(\operatorname{s16}\) means signed interpretation of the low 16 bits.

3. **At \(X+d+j\):** write

   \[
   H\!\left(K_5e+K_4a+393216b-131072f\right)
   \]

4. **At \(Y+d+j\):** write

   \[
   H\!\left(K_7(e+f)+K_6(b+c)\right)
   \]

5. **At \(X+2d+j\):** write

   \[
   H\!\left(\widehat K_4w+\widehat K_5f-131072e+393216c\right)
   \]

6. **At \(Y+2d+j\):** write

   \[
   H\!\left(K_2c+\widehat K_3f+64K_1w+8K_8g\right)
   \]

The hats identify retained coefficient reads, not different coefficient locations:

- \(\widehat K_4\) is read after the second write and before evaluation of the third write.
- \(\widehat K_5\) is read after the third write and before evaluation of the fourth write.
- \(\widehat K_3\) is read after the fourth write and before evaluation of the fifth write.

The third write independently reads \(K_4\); it does not necessarily use the earlier retained \(\widehat K_4\). Likewise, other unmarked coefficients are read for their associated expressions rather than uniformly captured at function entry.

The first filtered write uses signed 16-bit interpretations of \(K_0\) and \(K_1\). The last filtered write uses the full 32-bit \(K_1\). Treating both occurrences of \(K_1\) as the same signed 16-bit value would change behavior.

### Arithmetic width

Samples are unsigned bytes promoted for arithmetic. Accumulators and intermediate coefficient arithmetic are 32-bit, with signed and unsigned participation in the supplied expressions. The resulting accumulator is interpreted as signed for clamping.

For a fixed-width execution model, overflowed expressions must be evaluated in that model before clamping. Computing an unlimited-precision weighted sum and then clamping can produce a different result.

The supplied representation does not independently establish portable language-level semantics for every signed overflow case. A contract requiring cross-platform overflow equivalence needs additional execution-model evidence.

### Aliasing

The function does not stage an entire source region before writing output.

All eight samples for one byte offset are captured before that offset’s writes. However:

- A write may affect samples read at later byte offsets.
- A write may affect samples read by later outer iterations.
- Coincident destination addresses are written repeatedly in the stated order.
- If destination memory overlaps coefficient storage, earlier writes can affect subsequent coefficient reads.

Thus arbitrary overlap is not equivalent to processing an immutable source snapshot. Overlap is neither rejected nor given an alternative safe-copy path.

No explicit error notification exists. Invalid memory, dependency failure, or invalid arithmetic has no local recovery path.

## Acceptance examples

These examples are conditional static consequences, not runtime observations. Unless otherwise stated, assume valid memory, stable coefficients, and no relevant overflow.

1. **Zero outer bound.**  
   If the first F-870c4fcf7295 result has low portion zero, setup still calls F-c8a7bc15a71d for both descriptors and reads the listed fields. There are no per-iteration dependency calls, sample reads, or output writes.

2. **Byte count below one.**  
   If the destination factor product is 7, then \(N=0\). Entered outer iterations still call F-870c4fcf7295, but write no bytes. A product of \(-7\) also gives \(N=0\), not \(-1\).

3. **One ordinary outer iteration.**  
   If the initial low portion is 1, the initial high portion is zero, and the source adjustment dependency returns zero, then \(L=5\). At position zero:
   - \(P=A\), \(Q=B\).
   - The earlier boundary sample comes from \(A\).
   - The later boundary sample comes from \(A+3s\).
   - The second sequence’s second-next sample comes from \(B+2s\).

   The final-iteration substitution does not apply because the position is zero.

4. **Second and final iteration of a two-iteration case.**  
   If \(L=10\), the second position is 5. Then:
   - \(P=B+2s\).
   - \(Q=A+3s\).
   - The earlier boundary sample comes from \(A+2s\).
   - Both the later boundary sample and second sequence’s second-next sample come from \(B+4s\).

5. **Clamp boundaries.**  
   A completed signed accumulator of \(-1\) produces 0. An accumulator of \(1048575\) produces 0; \(1048576\) produces 1. An accumulator of \(267386880\) produces 255, as does a larger positive accumulator.

6. **Coincident output starts.**  
   If all six destination addresses for a byte coincide, all six writes still occur. With stable, nonoverlapping coefficient storage, the byte remaining afterward is the sixth result, not the initial direct copy.
