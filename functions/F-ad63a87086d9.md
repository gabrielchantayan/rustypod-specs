# F-ad63a87086d9

## Purpose

F-ad63a87086d9 coordinates an initial dependency call, an operation on a caller-supplied object, an optional additional call, and a conditional transfer of a 16-bit field into a dependency-selected object.

The function returns the 32-bit result of the central operation. Later calls and field updates do not replace that result.

**Established static behavior:** the function uses the second argument both as an unchanged argument to the central operation and as a zero/nonzero gate for subsequent behavior. A nonzero 16-bit source field may be copied to a 16-bit destination field, but only after a separate destination-field read observes zero.

**Inferred intent:** the field transfer resembles initialization of an unset destination value from an available source value. This interpretation is not a guarantee of initialization semantics: the object checked for zero and the object subsequently written are obtained through separate dependency calls and need not be identical.

## Behavior

The following order describes normal execution when dependencies return normally and memory accesses complete.

### Initial dependency sequence

1. F-fdd8589eca2d is called without explicit arguments. Its 32-bit result is retained for the immediately following call.
2. F-3e5212464798 is called with that result, the object argument, and a literal zero, in that order. Its return value is not used.
3. F-a3c410f12096 is called with the object argument and the unchanged mode argument. Its 32-bit result is retained as the eventual return value.
4. If the mode argument is nonzero, F-5c5958cfd5fe is called without explicit arguments. Its return value is not used.

No local branch tests the result of any of these calls. A result that a dependency might conventionally use to report failure does not, by itself, prevent the remaining work.

### Conditional field transfer

After the initial sequence, the function reads the 16-bit source field at object offset `0xE6` and tests it against zero.

This read occurs before the mode test in the compound condition. Consequently, a zero mode does **not** suppress this source-field read. The read also occurs after F-a3c410f12096 and, for nonzero mode, after F-5c5958cfd5fe. Any changes those dependencies make to the source field may therefore affect the decision.

Further work occurs only if both the observed source field and the mode are nonzero:

1. F-fdd8589eca2d is called again.
2. The function reads the 16-bit field at offset `0x80` from this call’s result.
3. If that field is nonzero, no transfer occurs.
4. If that field is zero, F-fdd8589eca2d is called once more.
5. After this final call returns, the source field at object offset `0xE6` is read again.
6. Those 16 bits are written to offset `0x80` from the final call’s result.

The source value used for the initial condition is not reused for the write. There is no second nonzero check on the newly read source value. A source field that changes to zero between the two reads can therefore cause zero to be written.

Likewise, the destination base used for the zero check is not reused automatically. The final call independently supplies the write base. There is no check that these two bases match, and no zero check is performed on the final write destination after that call.

### Return

After the optional transfer, the function returns the saved result of F-a3c410f12096.

On normal completion, F-fdd8589eca2d is called:

- Once if the mode is zero or the initial source-field read observes zero.
- Twice if both gates are nonzero but the checked destination field is nonzero.
- Three times if both gates are nonzero and the checked destination field is zero.

## Acceptance examples

These are conditional acceptance scenarios derived from static evidence, not executed tests. Each assumes normal dependency returns and valid storage for all reached accesses.

### Zero mode still reads the source

Given mode zero, the function performs the three unconditional calls, skips F-5c5958cfd5fe, and reads the source field once. It makes no conditional destination lookup and performs no direct store. The central operation’s result is returned.

An implementation that skips the source read solely because mode is zero does not preserve the supplied access order.

### Nonzero mode with a zero source

Given a nonzero mode and a source field observed as zero after F-5c5958cfd5fe returns, the optional call occurs, but no conditional F-fdd8589eca2d call occurs. There is no direct store.

This applies equally to mode one and other nonzero 32-bit mode values; those values are still forwarded unchanged to the central operation.

### Nonzero checked destination

Given nonzero mode, a nonzero initial source observation, and a nonzero field at the checked destination, the function makes two total F-fdd8589eca2d calls. It does not reread the source for copying and performs no direct store.

### Stable destination and source

Suppose the two conditional lookups return the same valid base, its checked field is zero, and the source field remains `0x1234`. The function writes the 16-bit value `0x1234` at that base’s offset `0x80` and returns the central operation’s saved result.

### Different check and write destinations

Suppose the check lookup returns one base with a zero field, while the final lookup returns a different base whose field is already nonzero. The function writes to the latter base without checking that field. It does not write to the former base merely because that was the object checked.

### Source changes before the transfer

Suppose the initial source observation is nonzero, the checked destination is zero, and the final lookup changes the source field to zero. The subsequent source reread obtains zero, and the function writes zero. There is no final source-validity gate.

### Uninterpreted operation result

Suppose the central operation returns a bit pattern that an external convention treats as an error. This function still performs the mode-dependent call and eligible field transfer. If execution completes normally, it returns that same bit pattern.
