# F-440b561b4c78

## Purpose

F-440b561b4c78 constructs a three-word result selected by an unsigned byte in an input record. Depending on that byte, the result is assembled from input words, assembled from a selected external descriptor and an input word, or copied from a selected external descriptor.

The established behavior is a transformation of raw 32-bit words. The meanings of the selector values, descriptor contents, and resulting words are not established. In particular, the source does not justify interpreting the result as an address, tagged pointer, ownership token, or particular application-level object.

Selectors 0 through 10 have explicit handling. All other byte values invoke F-a817d8d58c10, a dependency identified in the supplied source as not returning.

## Interface

The function accepts two pointer arguments and has no explicit return value:

- **Input record:** a pointer used for reading two 32-bit words and a selector byte at byte offset 8.
- **Result record:** a pointer used for writing three consecutive 32-bit words at byte offsets 0, 4, and 8.

Offsets are measured from the beginning of the corresponding record. A word is four bytes in the supplied representation.

The relevant input layout is:

| Byte offset | Width | Role |
|---|---:|---|
| 0 | 32 bits | Input word used as the third result word for selectors 0 through 6 |
| 4 | 32 bits | Input word used as the first result word for selectors 1 through 4 |
| 8 | 8 bits | Unsigned selector; read again on the selectors 1 through 4 path |

The selector occupies only one byte. The function does not read the other three bytes of the four-byte region beginning at offset 8.

The output layout is:

| Byte offset | Width | Role |
|---|---:|---|
| 0 | 32 bits | First result word |
| 4 | 32 bits | Second result word |
| 8 | 32 bits | Third result word |

The result pointer must support all three writes for a supported selector. Input readability depends on the selected path:

- Every invocation requires the selector byte to be readable.
- Selectors 0, 5, and 6 additionally require the input word at offset 0.
- Selectors 1 through 4 additionally require the words at offsets 0 and 4.
- Selectors 7 through 10 do not read either input word.

Any alignment requirements of the target’s word accesses remain applicable. The source does not establish that unaligned accesses are supported.

There is no null-pointer check, bounds check, destination-capacity check, or explicit validation of selected external descriptor pointers.

## Behavior

### Selector dispatch

The function first reads the unsigned byte at input offset 8. This initial read determines the selected path.

| Initial selector | Result construction |
|---|---|
| 0 | First two words from external descriptor A; third word from input offset 0 |
| 1–4 | First word from input offset 4; second word calculated from another selector-byte read; third word from input offset 0 |
| 5 | First two words from external descriptor B; third word from input offset 0 |
| 6 | First two words from external descriptor C; third word from input offset 0 |
| 7 | Three words from external descriptor D |
| 8 | Three words from external descriptor E |
| 9 | Three words from external descriptor F |
| 10 | Three words from external descriptor G |
| 11–255 | Invoke F-a817d8d58c10 |

Descriptors A through G are labels used by this contract to distinguish seven selected external pointer sources. They do not imply different allocation identities, immutable storage, distinct contents, or application-level types.

### Selectors 0, 5, and 6

The selected external pointer is obtained for descriptor A, B, or C respectively. The function then:

1. Reads the descriptor’s 32-bit word at offset 0.
2. Reads the descriptor’s 32-bit word at offset 4.
3. Reads the input’s 32-bit word at offset 0.
4. Writes those three captured values to result offsets 0, 4, and 8, in that order.
5. Returns.

The third descriptor word is not read on these paths. The input word at offset 4 is also not read.

The descriptor’s second word is transferred without a visible arithmetic transformation. Although the supplied representation routes it through a signed-width temporary, the established output is its 32-bit word value; no sign test or numeric conversion affecting the result is shown.

### Selectors 1 through 4

After dispatching on an initial selector in this range, the function:

1. Reads the input word at offset 4.
2. Reads the unsigned selector byte at offset 8 again.
3. Forms the second result word from that second byte value.
4. Reads the input word at offset 0.
5. Writes the captured input-offset-4 word to result offset 0.
6. Writes the calculated word to result offset 4.
7. Writes the captured input-offset-0 word to result offset 8.
8. Returns.

Let \(b\) be the value obtained by the second selector-byte read. The calculated word has the 32-bit bit pattern

\[
0x80000010 + 256b.
\]

The source expression combines an unsigned selector-derived value with a negative constant. The result must not be specified as a positive mathematical value stored in an arbitrarily wide signed integer: the output is a 32-bit word.

For a stable input selector, the calculated values are:

| Selector | Second result word |
|---|---|
| 1 | `0x80000110` |
| 2 | `0x80000210` |
| 3 | `0x80000310` |
| 4 | `0x80000410` |

The multiplication by 256 fits within 32 bits for every possible unsigned byte. Adding `0x80000010` also fits within the unsigned 32-bit range for every such byte. Thus no unsigned wraparound is needed to obtain the stated bit patterns.

The second read is not a second dispatch. If a supported execution environment permits the selector to change between reads, the first value determines the path and the second determines the calculated word. No subsequent range check limits the second value to 1 through 4. This observation does not establish that concurrent or externally changing input is valid under the original execution environment.

### Selectors 7 through 10

The function selects descriptor D, E, F, or G respectively. Its read order differs from the order of the resulting words:

1. Read descriptor offset 4.
2. Read descriptor offset 8.
3. Read descriptor offset 0 as the value for the first result write.
4. Write that offset-0 value to result offset 0.
5. Write the previously captured offset-4 value to result offset 4.
6. Write the previously captured offset-8 value to result offset 8.
7. Return.

The final result is the selected descriptor’s three-word sequence in its original word order.

Neither input offset 0 nor input offset 4 is read on these paths. The selector byte is not reread.

### Unsupported selectors

No result write is shown before this call. No input word other than the selector byte is read by F-440b561b4c78 on this path.

Behavior if it unexpectedly returns is not established and must not be specified as ordinary successful completion.

## Side effects

For supported selectors, the function visibly performs exactly three 32-bit destination writes, ordered by increasing result offset: 0, then 4, then 8.

There is no transactional or atomic-result guarantee. An observer capable of observing individual writes may see a partially updated result. If execution is interrupted or a memory access fails, the source supplies no rollback mechanism.

All result-producing source words are read before the first result write on their respective paths. Consequently, under ordinary stable-memory assumptions and valid accesses, overlap between the result storage and the input or selected descriptor does not cause a later source-word read to consume an earlier destination write. This is narrower than a general guarantee for every possible pointer overlap, target memory model, or memory-mapped device.

The function makes no explicit allocation, deallocation, reference-count operation, or ownership transfer. Input and descriptor words are copied as values. Copying a word that happens to encode a pointer does not establish ownership of its referent.

There are no explicit writes to external pointer slots or descriptor storage, except where that storage is also the supplied result destination. Whether such aliasing is valid depends on the storage’s writability and the execution environment.

On the unsupported-selector path, F-a817d8d58c10 may have additional side effects. Its effects on memory, global state, and resource ownership are unknown; preservation must not be assumed.
