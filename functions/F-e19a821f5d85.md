# F-e19a821f5d85

## Purpose

F-e19a821f5d85 selects a fixed record configuration from a 32-bit selector and passes a 32-byte, stack-backed record to an external dependency. A separate 32-bit input is forwarded unchanged.

**Established behavior:** some selectors produce fully assigned named fields; other selectors leave most fields unassigned. Two 32-bit fields are always explicitly zeroed. The dependency is called once on every visible control-flow path that reaches the call.

**Inferred intent:** the combinations of dimensions, doubled values, and values such as 12, 16, and 32 suggest a format or surface-description record. That interpretation is not required by this contract. Field names below describe position and width, not presumed application meaning.

This function does not itself report whether the external operation succeeds.

## Behavior

### Entry and common processing

Before selector-specific assignments, the function:

1. Assigns zero to the 32-bit field at offset 16.
2. Assigns zero to the 32-bit field at offset 20.
3. Obtains T0 from G0.

The G0 access occurs even when the selected configuration ultimately uses another global for Field F, or leaves Field F unassigned.

The function then selects field values using the full 32-bit selector. All numeric constants in the following table are decimal; selector labels are hexadecimal.

### Global-access and assignment order

At the supplied representation’s level, the common zero assignments precede the G0 access. Selector-specific assignments follow that access.

For the configurations using other globals:

- `0x3FB` and `0x3FE`: A, B, D, E, and C are assigned before G3 supplies F.
- `0x3FC` and `0x3FF`: A and D are assigned first; B and E follow; G4 supplies F before C is assigned.
- `0x428`: A, B, D, E, and C are assigned before G5 supplies F.
- `0x42B`: A, B, D, and E are assigned before G1 supplies C; G2 then supplies F.

Thus `0x42B` obtains G0, then G1, then G2. There is no visible operation that obtains an atomic snapshot of those locations.

For the remaining assigned configurations, F receives the already captured T0. There is no second visible G0 read.

## Acceptance examples

These examples are conditional static acceptance criteria, not reports of executed tests. They describe the state presented to the dependency and assume the required accesses complete.

1. **Ordinary assigned configuration.** With selector `0x3F1` and T0 = `0x1234`, the invocation presents A = 30, B = 41, C = 84, D = 0, E = 16, and F = `0x1234`. Both zero fields are zero. Gap contents remain unconstrained.

2. **Nonzero 16-bit field.** With selector `0x3F5`, D is 270, not zero and not truncated to eight bits. The configuration uses T0 for F. Selector `0x3FC` has the same A through E values but uses T4 instead.

3. **Distinct global source.** With selector `0x3FB`, F receives T3 even if T0 differs. G0 is nevertheless accessed first. A is 480; changing the selector to `0x3FE` changes A to 576 while retaining the other listed values.

4. **No inferred doubling rule.** Selector `0x425` presents B = 55 and C = 112. A result with C = 110 does not match the established mapping.

5. **Different element-size-like field.** Selector `0x428` presents E = 32 and C = 1280, not the E = 16 and C = 640 configuration associated with `0x400`. F comes from G5.

6. **Two selector-specific data reads.** For `0x42B`, C receives V1 and F receives T2. E is 12. The global-access sequence is G0, G1, G2; the evidence does not guarantee mutually consistent values under concurrent mutation.

7. **Recognized but incomplete selector.** For `0x401`, the dependency is still invoked with size 32 and the unchanged forwarded value. The two zero fields are established as zero. No expected numeric values may be assigned to A through F from this function alone.

8. **Unrecognized selector.** Selector `0x00000000` follows the same incomplete-record behavior. It is not visibly rejected, normalized, or mapped to `0x3F1`.

9. **Full-width selector comparison.** `0x000103F1` is not the listed selector `0x3F1`; it follows the incomplete path. Matching only the low 16 bits would change behavior.

10. **Low-16-bit global value.** If the value obtained from G0 has low 16 bits `0xFEDC`, an assigned configuration using T0 stores the pattern `0xFEDC` in F. This establishes neither a signed interpretation nor the neighboring gap bytes.
