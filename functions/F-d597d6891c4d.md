# F-d597d6891c4d

## Purpose

This is a source-facing behavioral contract. The supplied static evidence establishes access offsets, operand widths, call order, and selection rules. It does not establish the meanings of the numeric fields or the behavior of the dependencies. Terms such as “context,” “object,” “slot,” and “working record” describe structural roles, not verified application concepts.

## Behavior

### 1. Optional initial operation

The function first reads the byte at context offset `0x903`.

- If the byte is zero, it proceeds without an initial dependency call.
- If the byte is nonzero, it calls F-e1c4e131e7b7 with no explicit arguments.

This decision uses the byte’s zero/nonzero status, not a particular nonzero value.

The function does not first cache the remaining context or object fields. Consequently, changes made by this initial dependency can affect later preparation, adjustment, and slot-selection behavior. Its lack of explicit arguments does not establish that it is free of global or indirect side effects.

### 2. Prepare the first three working-record words

The selector controls this preparation independently of its use in destination addressing.

- If the selector equals exactly one, the function copies three consecutive words from object offsets `0x30`, `0x34`, and `0x38` into local working storage.
- For every other selector value, it calls F-b9d144e0e393 with a local three-word output region and the address at object offset `0x30`. After that call returns, it copies three words from the local output region into the working record.

The alternate path is not a general “false” interpretation of the selector: zero, negative values, and positive values other than one all take it.

The direct path copies raw words without a visible conversion. The alternate path delegates any conversion or preparation to F-b9d144e0e393. Its behavior is unknown. In particular, the evidence does not independently establish that it initializes every output word; normal use of the subsequent three-word copy requires those words to be valid.

### 3. Prepare the remaining four working-record words

The function performs three calls to F-e713aa9f4f3b in this order:

1. Object word at `0x3C`, together with context word at `0x87C`.
2. Object word at `0x40`, together with context word at `0x880`.
3. Object word at `0x44`, together with context word at `0x884`.

Each call supplies two 32-bit values and produces a 32-bit result. Those results become the fourth, fifth, and sixth working-record words, respectively.

After the third call returns, the function reads the object word at `0x48` and uses it as the seventh working-record word.

These source values are not all captured before the dependency calls. The first call may therefore affect fields read for the second or third call, and any of the three calls may affect the later read at object offset `0x48`. The evaluation order between the two argument reads within a single call is not established here.

The combination operation itself is unknown. Multiplication, addition, scaling, and any particular numeric encoding must not be assumed.

2. The address of the fourth working-record word.

At that point, the latter address begins a four-word region containing the three combination results followed by the copied object word from `0x48`.

No explicit status is checked after F-3f35b3cd17e1.

### 5. Apply three adjustments

After F-3f35b3cd17e1 returns, the function updates the selected destination in this order:

1. Add the current context word at `0x868` to the current destination word at offset zero; store the result back.
2. Add the current context word at `0x86C` to the current destination word at offset four; store the result back.
3. Add the current context word at `0x870` to the current destination word at offset eight; store the result back.

These are separate read-modify-write operations, not an atomic three-word update. The first store precedes the second update, and the second store precedes the third update. Within an individual update, the relative order of its destination and context reads is not established.

The fields are read after the destination-population call. They are not preserved copies of context values from function entry.

The arithmetic operands and stored results are 32 bits. There is no explicit overflow check, saturation, or wider result in the supplied evidence. Exact overflow semantics remain documented_only: the evidence is insufficient to select a portable signed-overflow rule or a verified target wraparound rule.

### 6. Process selected slots in ascending order

The function examines eight slot positions, numbered zero through seven. Their selection bits are, respectively:

`0x01`, `0x02`, `0x04`, `0x08`, `0x10`, `0x20`, `0x40`, and `0x80`.

For each slot, it reads the context word at `0x89C` and tests the corresponding bit. If that bit is set, it calls F-f35484ed231a with six arguments, in this order:

1. Context address + `0x2F8` + slot × `0xA8`.
2. Object address.
3. Starting address of the seven-word local working record.
4. Context address + `0x838`.
5. Object address + `0x3C`.
6. Selected destination address.

Selected calls occur in ascending slot order. Each of the eight bit positions is considered once. Bits above bit seven do not directly select additional calls.

The selection word is read anew for each slot. It is not captured once before the loop. A selected-slot dependency can therefore change whether a later slot is processed by modifying the selection word. Changes to already-considered bits do not revisit earlier slots.

Every selected call receives the same local working-record address and the same previously calculated destination address. The function does not rebuild the record between calls. Whether an earlier call changes the record or other supplied storage is a dependency-level unknown.

### 7. Final operation

After all eight slot positions have been considered, the function calls F-3e0c716bf179 with the selected destination address.

This call occurs even if no slot was selected, provided all preceding operations return normally. The function then returns without an explicit result.

## Acceptance examples

These examples are conditional static acceptance criteria, not observed runtime results.

1. **Selector one.**  
   With selector one and valid storage, the selected destination is object address + `0x4C`. The first three record words are copied directly from object offsets `0x30` through `0x38`; F-b9d144e0e393 is not called.

2. **Selector zero and a stable zero mask.**  
   The alternate preparation call occurs. The selected destination is object address + `0x3C`. If the mask remains zero at every slot check, no F-f35484ed231a calls occur. Destination population, the three adjustments, and the final operation still occur.

3. **A stable mask of `0x85`.**  
   If no dependency changes the mask, slots zero, two, and seven are processed, in that order. Their first argument addresses use context offsets `0x2F8`, `0x448`, and `0x790`, respectively.

4. **Only high mask bits set.**  
   If the mask remains `0x100`, none of the eight slot tests selects a call. There is no ninth slot check.

5. **Mask changes during processing.**  
   Suppose slot zero is selected and its dependency sets bit seven. If that bit remains set until the seventh-slot check, slot seven is processed even if bit seven was clear before slot zero ran.

6. **Selector two.**  
   The alternate preparation path is used, and the selected destination is object address + `0x5C`. The function does not reject this selector. Whether that destination is valid is a caller-side precondition.

7. **Nonzero initial flag.**  
   Any nonzero flag byte causes the initial dependency call before the object preparation reads. If that call changes an object source word, the subsequent preparation can observe the changed value.

8. **Adjustment arithmetic without overflow.**  
   If destination population leaves the first three destination words as 10, 20, and 30, and the corresponding context adjustment words read during the updates are 1, 2, and 3, those words become 11, 22, and 33 before slot processing.
