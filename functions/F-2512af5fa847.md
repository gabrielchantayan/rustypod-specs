# F-2512af5fa847

## Purpose

F-2512af5fa847 consumes bytes from a caller-supplied range, advancing a mutable cursor until it encounters a delimiter, a designated termination byte, or the range boundary.

The stopping conditions have different status effects:

- Space and horizontal tab stop scanning without an explicit status write.
- Semicolon stops scanning and assigns status 1.
- Carriage return or line feed stops scanning and assigns status 2.
- Byte 0x1A or exhaustion of the available range stops scanning and assigns status 3.

Every byte actually read is consumed, including a stopping byte. End-of-range detection consumes no byte.

An unconditional call to F-e4a5df3be823 precedes all direct state access. If status is strictly positive after that dependency returns, scanning is suppressed and the function returns zero.

Otherwise, the return value is the cursor captured at scan entry minus one address unit. It is not the final cursor, the stopping-byte address, or a consumed-byte count.

The delimiter selection suggests text-oriented scanning. This is inferred intent, not evidence of a particular encoding, grammar, file format, or token representation.

## Interface

The function accepts one pointer to mutable state represented by integer-indexed slots:

| Slot | Established role | Direct access |
|---|---|---|
| 0 | Current byte cursor, held as an integer and interpreted as a byte address | Read and, when a byte is available, written |
| 1 | No role established | None |
| 2 | End boundary, held as an integer and interpreted as a byte address | Read |
| 3 | Signed status controlling entry and recording selected stopping conditions | Read and conditionally written |

Under the apparent 32-bit integer/address model, the slots occupy byte offsets 0, 4, 8, and 12. Each is a distinct integer slot. In particular, a write to slot 0 does not write slots 1, 2, or 3.

This physical layout is conditional on that model. The supplied static representation does not independently verify the target ABI, native pointer width, alignment requirements, or integer-to-address conversion rules.

The range is treated as half-open: the current cursor identifies an available byte only when it compares strictly below the boundary under the represented address comparison. The function does not establish that this comparison has defined meaning for arbitrary unrelated addresses.

### Byte and sentinel widths

An input read produces an unsigned byte value from 0 through 255. That value is widened for classification.

The no-byte case is represented separately by 0xFFFFFFFF, a 32-bit all-ones value. No unsigned input byte can equal that value. In particular, byte 0xFF is ordinary input, not end of range.

The cursor, boundary, status, saved return basis, and result appear to use 32-bit integer slots or values. Exact ABI-level widths remain conditional on the supplied representation.

### Return value

There are two return relationships:

| Condition after the dependency returns | Result |
|---|---|
| Status is strictly positive | Zero |
| Status is zero or negative, and scanning completes normally | Scan-entry cursor minus one |

The saved scan-entry cursor is not updated as scanning progresses.

The subtraction is integer-valued. It does not establish a valid pointer to an accessible byte. Even when the arithmetic is representable, the result can identify a location before the scanned range.

The static representation does not establish wraparound semantics at signed arithmetic limits. No modulo-2³² result is promised for overflow cases. The result is also not a unique success indicator: if a permitted scan begins with integer cursor value 1 and otherwise completes validly, its return relationship also yields zero.

## Behavior

### Dependency and entry gate

F-e4a5df3be823 is called before the function directly reads or writes the supplied state. No explicit arguments are shown, and its return value is not used.

After the dependency returns, slot 3 is read and tested as signed:

- A value greater than zero causes an immediate zero return.
- Zero permits scanning.
- Any negative value also permits scanning.

The suppression condition is not restricted to statuses 1, 2, and 3. Any strictly positive status suppresses scanning.

On the suppression path, this function performs no direct state write and does not directly read the cursor or boundary. These restrictions do not constrain effects performed by the dependency.

The dependency may alter state or its validity through mechanisms not visible here. All subsequent behavior is therefore conditional on the post-dependency state.

### Scan-entry capture

When scanning is permitted, slot 0 is read once to capture the basis for the eventual return value.

The function then obtains the current cursor again for the first availability check. On later attempts, it obtains the cursor and boundary again rather than relying on a boundary saved at entry.

For ordinary nonoverlapping memory without external mutation, the entry capture equals the first current cursor. They remain distinct observations in the access pattern.

### Availability and byte consumption

Each attempt compares the current cursor with the current boundary.

When the cursor is strictly below the boundary, the observable order is:

1. The cursor slot is updated to the address one byte after the current address.
2. The byte at the previous cursor address is read as unsigned.
3. The observed byte value is classified.

The cursor update therefore precedes the byte read. By the time a stopping byte is classified, the cursor already points to the next byte.

When the cursor is equal to or above the boundary:

- No input byte is read on that attempt.
- No cursor increment is written on that attempt.
- The condition leads to status 3 and termination.

A cursor above the boundary is not reported separately from a cursor exactly at the boundary. The function does not repair or normalize an inverted range.

These orderings describe normal execution. If a memory access faults, the source does not establish rollback or recovery. In particular, a byte-read fault can occur after the corresponding cursor update.

### Classification and termination

| Observed byte or condition | Consumption | Explicit status effect | Next action |
|---|---|---|---|
| Space, 0x20 | One byte | None | Return saved cursor minus one |
| Horizontal tab, 0x09 | One byte | None | Return saved cursor minus one |
| Carriage return, 0x0D | One byte | Write 2 | Return saved cursor minus one |
| Line feed, 0x0A | One byte | Write 2 | Return saved cursor minus one |
| Semicolon, 0x3B | One byte | Write 1 | Return saved cursor minus one |
| Byte 0x1A | One byte | Write 3 | Return saved cursor minus one |
| Cursor not below boundary | No byte on this attempt | Write 3 | Return saved cursor minus one |
| Any other byte | One byte | None at that point | Continue scanning |

For terminal-status outcomes, the status write occurs before the return expression is evaluated. Space and tab return without such a write.

A zero byte does not terminate scanning. Byte 0xFF likewise does not terminate scanning unless a later condition does so.

Carriage return and line feed are independent stopping bytes. A carriage-return/line-feed pair is not consumed as a unit. After consuming the carriage return, **the following line feed remains unread at the updated cursor**.

If the last available byte is an ordinary, nonstopping byte, it is consumed first. A subsequent attempt detects the exhausted range and writes status 3.

### Persistence across calls

This function does not clear a positive status.

After a call assigns status 1, 2, or 3, a later call whose dependency leaves that status unchanged will return zero without scanning. Resuming scanning requires some external action, including possible dependency behavior, to make status nonpositive.

Space and tab do not explicitly latch a terminal status. With ordinary nonoverlapping state and no external changes, an initial zero or negative status remains unchanged when either delimiter stops the scan.

## Side effects

### Direct memory effects

The function directly performs only the following categories of memory access:

- Reads status after the dependency returns.
- Reads the scan-entry cursor when the gate permits scanning.
- Reads the current cursor and boundary for scan attempts.
- Writes one cursor increment for every byte consumed.
- Reads each consumed byte after its cursor increment.
- Writes status for semicolon, carriage return, line feed, byte 0x1A, or range exhaustion.

It does not directly access slot 1 or write the boundary slot.

Its visible body does not explicitly allocate, release, or transfer memory, perform I/O, or write through the input-byte address. These observations do not constrain F-e4a5df3be823.

### Ownership and overlap

Caller-supplied state and byte storage are accessed without an established ownership transfer. No release obligation or retained reference is shown.

For ordinary delimiter-based interpretation, state storage and input storage should not overlap. This is a usage assumption, not an enforced check.

If they do overlap, writing the cursor slot can change input bytes, including the byte about to be read. Because the cursor write precedes that read, classification can observe the changed byte rather than its earlier contents. The function does not preserve an input snapshot.

This overlap does **not** establish that a cursor write modifies another state slot. Under the described layout, slots 0, 1, 2, and 3 are distinct: updating slot 0 does not update slots 1, 2, or 3. A terminal write to slot 3 may separately alter overlapping input storage, but scanning then terminates.

The source establishes no supported general aliasing contract, synchronization, or atomicity guarantee. Concurrent mutation and memory-mapped side effects cannot be assigned ordinary buffer semantics from this evidence alone.

### Errors and exceptional behavior

There is no explicit error return separate from the return relationships above. Range exhaustion is recorded as status 3, not reported through a dedicated error result.

The behavior of invalid accesses, nonreturning dependency execution, arithmetic overflow, or invalid address conversions is not established. The absence of a local error branch is not a promise that these conditions are recoverable.
