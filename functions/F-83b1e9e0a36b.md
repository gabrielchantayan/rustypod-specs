# F-83b1e9e0a36b

## Purpose

F-83b1e9e0a36b computes a Boolean-like relationship between two pairs of scalar inputs. Each pair contains an unsigned position and a signed extent. The result is a 32-bit value: either 0 or 1.

The established behavior is an order-dependent comparison against one calculated endpoint. The function first compares the positions. It then uses the extent associated with the position selected by that comparison. It never needs both extents for a single invocation.

An inferred purpose is to determine whether two ranges overlap, with endpoint contact treated as non-overlap. That interpretation is reliable only under additional input restrictions, particularly positive extents and endpoint calculations that do not wrap. The implementation does not validate those restrictions. Its full contract is therefore the unsigned, modular comparison behavior below—not an unrestricted mathematical interval-overlap predicate.

No pointer, buffer, object, handle, or explicit state argument is present. No input denotes storage to be read or written by this function.

### Arithmetic interpretation

When a position and an extent are added, the signed extent is converted to unsigned 32-bit form. The addition then takes place modulo 4,294,967,296.

Consequently:

- A nonnegative extent retains its numerical value during conversion.
- A negative extent is converted to its unsigned residue. For example, −1 becomes 4,294,967,295.
- A sum exceeding 4,294,967,295 wraps into the unsigned 32-bit range.
- The endpoint comparison is unsigned.
- The operation is not signed addition followed by signed-overflow handling.

There are no established domain preconditions beyond supplying values representable by the argument types. Positive extents and nonwrapping endpoints are useful restrictions for the inferred range interpretation, but the function does not enforce them.

## Behavior

### Position selection

The initial comparison is an unsigned comparison between the first position and the second position.

**When the first position is strictly smaller:**

- The function calculates the first position plus the first extent, using the unsigned modular arithmetic described above.
- It returns 0 if that endpoint is less than or equal to the second position.
- Otherwise, it returns 1.
- The second extent does not participate in the result.

**When the first position is greater than or equal to the second position:**

- The function calculates the second position plus the second extent, using the same arithmetic rules.
- It returns 0 if that endpoint is less than or equal to the first position.
- Otherwise, it returns 1.
- The first extent does not participate in the result.

Equality between positions therefore selects the second extent. There is no separate equal-position case.

### Endpoint contact

The endpoint comparison is inclusive on the zero-result side. If the calculated endpoint exactly equals the other position, the result is 0.

Under the restricted interpretation of positive, nonwrapping ranges, this corresponds to treating two ranges that merely touch at an endpoint as non-overlapping. The same comparison applies without adjustment when an extent is zero, negative, or produces a wrapped endpoint.

### Ignored arguments

For a fixed pair of unequal positions, changing the extent associated with the later position cannot affect the result. That extent is not part of the selected calculation.

For equal positions, changing the first extent cannot affect the result. Only the second extent contributes to the endpoint calculation.

This is a property of the function body, not a promise about how a caller evaluates expressions used to supply arguments.

### Zero extents

A zero extent does not universally force a result of 0.

If the selected extent is zero, its endpoint equals the selected position. Because that position is no greater than the other position, the function returns 0.

If the unselected extent is zero, it has no effect. The function may return 1 even though one of the pairs would describe an empty range under a conventional half-open-range interpretation.

### Negative extents and wraparound

Negative extents are accepted without an error path. Their unsigned conversion can produce either a small wrapped endpoint or a very large endpoint, depending on the position.

Likewise, a positive extent can produce a small endpoint if addition wraps. Such a result may cause a return value of 0 even where an unbounded mathematical addition would place the endpoint beyond the other position.

The function does not saturate endpoints, detect wraparound, normalize ranges, or reject negative extents.

### Argument-pair exchange

For distinct positions, exchanging the two complete position/extent pairs preserves the result: the extent associated with the numerically smaller position remains selected.

For equal positions, that symmetry is not guaranteed. Exchanging the pairs changes which extent occupies the selected second-extent argument. Different extents can therefore produce different results after exchange.
