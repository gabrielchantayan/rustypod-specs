# F-661c43d68306

## Purpose

F-661c43d68306 performs a fixed initialization sequence, checks a prerequisite, and then repeatedly requests a status word until one of three conditions occurs:

- A required operation reports failure.
- A timeout-related dependency returns a nonzero result.
- Following a wait, neither bit selected by mask `0x88` is set in the status word.

The routine returns the 32-bit value `1` only for the last condition. All explicit failure exits return the 32-bit value `0`.

Diagnostic strings suggest an ATA-related status check and a wait for a busy condition to clear. That interpretation is inferred intent, not an established hardware contract. The supplied evidence establishes numeric selectors, masks, dependency calls, and control flow; it does not establish the underlying device protocol.

## Interface

### Inputs

The routine has no explicit arguments.

Its effective inputs are:

- A readable 32-bit value at offset `0x14` from a globally supplied base.
- A globally supplied argument passed to F-6e46c43c3113.
- A globally supplied base, captured after the initial time-related call, from which a 32-bit value at offset `0x18` is read during every loop iteration that reaches the timeout check.
- Return values and output-memory effects of its dependencies.
- Any external state consulted or changed by those dependencies.

For clarity, this contract calls the two offset-based locations:

- **Initial-status location:** the location read once at offset `0x14`.
- **Timeout-argument location:** the location read repeatedly at offset `0x18` from the captured base.

These names describe their use in this routine, not a proven structure layout or field type.

### Output

The return value is a 32-bit quantity:

| Value | Established meaning |
|---|---|
| `1` | A status request succeeded, execution continued past the timeout check and wait call, and the status word then had no bits selected by `0x88`. |
| `0` | The prerequisite check failed, a primary status request failed, an error-detail request failed, or the timeout-related check returned nonzero. |

A return of `1` does **not** establish that no error indication was observed. An error indication can cause a diagnostic and still be followed by success.

The routine has no caller-supplied output buffer.

### Widths and storage

The routine uses two addressable 32-bit working words:

- A **status word**, initially seeded from the initial-status location.
- A **detail word**, initially seeded with zero.

F-03fd77b56fa0 receives the address of one of these words, depending on the selector.

The routine also retains a 32-bit opaque value returned by a time-related dependency. Its units, arithmetic interpretation, and wraparound behavior are unknown.

Dependency results used as success predicates are compared with zero. Any nonzero result follows the nonzero branch; the routine does not require a particular positive success value.

### Preconditions

Defined execution requires the accessed global storage, captured bases, and offset-based locations to be valid for the observed reads. Dependencies must also respect whatever pointer and calling contracts are necessary for execution to continue safely.

No local validation of those addresses is visible. No exception handling, recovery from invalid memory, or dependency-failure convention beyond the explicit zero/nonzero checks is established.

## Behavior

### 1. Fixed initialization sequence

Before checking its prerequisite, the routine performs these calls in this exact order:

1. F-17d6434f9fa3 with arguments `(0x48, 1, 0)`.
2. F-U01 with argument `1`.
3. F-17d6434f9fa3 with arguments `(0x48, 1, 1)`.
4. F-U01 with argument `1`.
5. F-17d6434f9fa3 with arguments `(0x48, 3, 0)`.
6. F-U01 with argument `1`.

F-U01 is a document-local opaque label for an unmapped external dependency.

None of these calls has its return value tested. Their externally visible effects, if any, occur even when the later prerequisite fails. The routine provides no rollback for them.

The argument pattern may represent control-line transitions separated by waits, but neither the control semantics nor the unit represented by `1` is established.

### 2. Initial read and prerequisite

After the fixed sequence, the routine reads a 32-bit value from the initial-status location.

It then calls F-6e46c43c3113 with:

- The globally supplied argument.
- A second argument of zero.

If this dependency returns zero, the routine returns `0` immediately. It does not call the time-start dependency or enter the status loop.

If the dependency returns nonzero, the routine initializes its addressable working words:

- The detail word becomes zero.
- The status word receives the value captured before the prerequisite call.

This ordering matters. A change to the initial-status location during F-6e46c43c3113 does not cause that location to be reread for the seed value.

### 3. Time-related setup and base capture

The routine calls F-U02 without explicit arguments and retains its 32-bit result.

After that call returns, it captures a globally supplied base used for subsequent reads of the timeout-argument location.

The distinction between base capture and field reads is observable:

- The base is captured once at this point.
- The 32-bit value at offset `0x18` from that captured base is read again on each iteration that reaches the timeout-related check.

Consequently, changing the global base after capture does not, by itself, redirect later reads. Changing the field at the captured base may affect a later check.

The routine does not assume the global base remained unchanged across F-U02: its capture occurs afterward.

### 4. Primary status request

Every loop iteration begins by calling F-03fd77b56fa0 with selector `0x0f` and the address of the status word.

If this call returns zero, the routine returns `0` immediately. There is no local diagnostic on this branch, no timeout-related check, and no subsequent wait call.

If the call returns nonzero, the routine inspects bit `0` of the status word.

The visible caller does not verify that a successful dependency call actually wrote the word. A dependency contract guaranteeing a fresh complete status value is not supplied. The initial seed and any prior word contents therefore cannot be dismissed as irrelevant solely from this evidence.

### 5. Optional error-detail request and diagnostic

If bit `0` of the status word is clear, the detail request is skipped.

If bit `0` is set, the routine calls F-03fd77b56fa0 with selector `9` and the address of the detail word.

If that call returns zero:

- The routine calls F-1b7fa166ef25 with a fixed diagnostic indicating that error-detail retrieval failed.
- The routine returns `0`.

If that call returns nonzero:

- The routine calls F-1b7fa166ef25 with an error-code diagnostic and the detail word masked by `0xff`.
- Execution continues to the timeout-related check.

The mask produces a value in the range `0` through `255`. It does not sign-extend the low byte. Upper bits of the detail word are not included in the diagnostic argument.

A successfully reported error code is not itself a terminal failure. Bit `0` also is not part of the later `0x88` completion mask. Subject to the intervening dependency effects, the routine can report an error code and return `1` in the same iteration.

The detail word is initialized only once, not before every detail request.

### 6. Timeout-related check

After any optional successful error reporting, the routine:

- Reads the 32-bit timeout argument from offset `0x18` of the captured base.
- Calls F-U03 with the retained result from F-U02 and that freshly read argument.

If F-U03 returns nonzero, the routine emits a fixed timeout-related diagnostic through F-1b7fa166ef25 and returns `0`.

This branch takes precedence over the completion test. Even if the status word has no `0x88` bits set, a nonzero timeout-related result prevents success.

The timeout comparison algorithm, units, boundary inclusiveness, and overflow handling belong to F-U03 and are not visible here.

### 7. Wait and completion test

If F-U03 returns zero, the routine calls F-233fe84cf225 with argument `0x32`, decimal `50`.

Only after that call returns does the routine test the status word against mask `0x88`:

- If the masked result is zero, it returns `1`.
- Otherwise, it begins another iteration with a new primary status request.

The mask selects bits `3` and `7` of a 32-bit word. All other bits are ignored by this completion test.

There is no fresh primary status request between the wait and this test. Thus, under a dependency contract that does not retain and later modify the status-word address, the test uses the status obtained before the wait. Without that dependency contract, preservation of the word across intervening calls remains unknown.

Even an immediately clear status requires the timeout-related check and the wait call before success.

There is no explicit iteration limit. If status requests keep succeeding, timeout-related checks keep returning zero, and the completion mask remains nonzero, the routine continues looping.

## Side effects

### Observable ordering

The significant visible ordering is:

1. Three initialization calls, each followed by F-U01.
2. The initial-status read.
3. The prerequisite call.
4. Working-word initialization, if the prerequisite succeeds.
5. F-U02 and then base capture.
6. Repeated primary status request.
7. Conditional detail request and diagnostic.
8. Timeout-argument read and F-U03.
9. Either timeout diagnostic and failure, or F-233fe84cf225.
10. Completion test and either success or repetition.

The routine performs no visible direct write to global or device storage. Its dependencies may perform such writes; their scope is unknown.

### Memory and ownership

The routine passes addresses of its own working storage to F-03fd77b56fa0. These are not heap allocations and are not transferred to the caller.

No allocation, deallocation, ownership-transfer operation, or explicit cleanup is visible in the routine. This does not establish that its dependencies neither allocate nor release other resources.

Whether F-03fd77b56fa0 retains the supplied addresses is unknown. The addresses refer to routine-owned temporary storage and do not remain valid after return. Safe dependency behavior must account for that lifetime.

The routine neither restores initialization effects on failure nor visibly restores device state after success.

### Diagnostics

Three diagnostic situations are visible:

- Failure to retrieve error details.
- Successful retrieval of an error-detail value, reported using its low eight bits.
- A nonzero timeout-related result.

Primary status-request failure and prerequisite failure have no local diagnostic call.

The diagnostic sink, formatting behavior, synchronization, and failure behavior of F-1b7fa166ef25 are unknown.

## Acceptance examples

These are conditional contract examples, not executed tests. Except where stated otherwise, they assume dependencies return normally, perform complete indicated output writes, and do not later modify the working words.

1. **Prerequisite failure.**  
   If F-6e46c43c3113 returns zero, the result is `0`. All six initialization-sequence calls and the initial-status read have already occurred. No loop request occurs.

2. **Primary request failure.**  
   If the prerequisite succeeds but the first selector-`0x0f` request returns zero, the result is `0`. There is no local diagnostic, timeout-related check, or F-233fe84cf225 call.

3. **Clear status.**  
   If a successful primary request writes zero and F-U03 returns zero, F-233fe84cf225 is called with `50`, then the routine returns `1`.

4. **Timeout takes precedence.**  
   If a successful primary request writes zero but F-U03 returns nonzero, the routine emits the timeout-related diagnostic and returns `0`. It does not call F-233fe84cf225.

5. **Error indication followed by success.**  
   If the primary request writes `0x01`, the detail request succeeds with `0x1234abcd`, and F-U03 returns zero, the diagnostic receives `0xcd`. After F-233fe84cf225 returns, the routine returns `1`, because `0x01` has no bits selected by `0x88`.

6. **Error-detail failure.**  
   If the primary request sets bit `0` and the selector-`9` request returns zero, the error-detail-failure diagnostic is emitted and the result is `0`. No timeout-related check follows.

7. **Busy-mask repetition.**  
   If one iteration writes `0x80` and the next writes `0x08`, with both timeout-related checks returning zero, neither iteration completes successfully. Each performs F-233fe84cf225 before repeating.

8. **Unselected bits do not block completion.**  
   A primary status of `0x100` does not trigger the detail request and does not block completion. With a zero timeout-related result, it leads to success after the wait call.

9. **Updated timeout argument.**  
   If the value at the captured base plus `0x18` changes between iterations, the next reached F-U03 call receives the updated value. The routine does not cache that field.
