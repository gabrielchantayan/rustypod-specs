## Behavior

### 1. Capture the seed words

The function reads the first global seed into the first local payload word, then the second global seed into the second word, then the third global seed into the third word.

These are three separate reads. The supplied source establishes neither an atomic snapshot nor synchronization with concurrent writers. If another execution context can modify the seeds, consistency requirements are external to this function.

The words used for the transformation are the captured local values. A later change to a seed global does not, by itself, replace its already copied local word.

### 2. Transform the captured values

The function processes the three local words in reverse address order:

1. Third word, at payload offset 8.
2. Second word, at payload offset 4.
3. First word, at payload offset 0.

Each word is replaced by its unsigned 32-bit value logically shifted right by one bit. Numerically, the transformed value is the original unsigned value divided by two, with any fractional remainder discarded.

Consequences of this width and operation include:

- The original least significant bit is discarded.
- A zero bit enters the most significant position.
- The transformed value is between 0 and 2,147,483,647 inclusive.
- An original high bit does not cause sign extension.
- There is no addition or multiplication that could overflow during this transformation.

The three words retain their original order in memory. Reverse processing order does not reverse the payload.

The source does not establish target byte order. The word values are defined by the transformation, but their four-byte encodings must remain target-dependent in this contract.

### 3. Set the trailing byte

This write establishes one zero byte, not an independently established textual terminator. Earlier bytes in the transformed words may already be zero, and no text encoding or string-processing contract is supplied.
