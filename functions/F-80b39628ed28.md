# F-80b39628ed28

## Purpose

F-80b39628ed28 requests storage using the numeric size argument 8, writes two initial 32-bit fields, and passes the resulting address together with two caller-supplied values to a dependent operation. A nonzero result from that operation causes the original storage address to be returned. A zero result causes an indirectly selected callback to be invoked before returning null.

The apparent purpose is object creation followed by initialization, with a cleanup-like operation when initialization fails. That is **inferred intent**, not an established allocation or ownership contract. The available evidence does not establish that the storage provider allocates heap memory, that the callback releases storage, or that a non-null result transfers ownership.

This contract describes the visible operations and their ordering. Normal completion is conditional on valid memory accesses and on the invoked dependencies returning where required. Unknown dependency behavior is not replaced with preservation, allocation, or cleanup guarantees.

## Behavior

### Storage request and initialization

The first visible dependency call is F-8157a180d901 with the numeric argument 8. Its returned address is retained as the region address.

After that call returns, the function performs these operations in order:

1. Reads a 32-bit value from a shared location.
2. Writes that value into the first field of the returned region.
3. Writes a 32-bit zero into the second field.
4. Compares the returned address with null.

There is no retry, alternate storage source, or check of the supplied region’s size.

The shared value is read after F-8157a180d901 returns. It is not an entry-time snapshot. If that dependency changes the shared location, initialization uses the subsequently read value.

The two writes establish initial contents only. F-4f1f8618b6f1 may subsequently change either field; this function does not restore them.

### Delayed null handling

The null comparison occurs after both field writes.

If the address is null and execution reaches the comparison, the function calls F-a817d8d58c10 without visible arguments. The supplied representation marks this dependency as non-returning.

This ordering does not provide a protected storage-failure path. In an environment where writing through a null address is invalid, execution may fail during the first write, before the null comparison or F-a817d8d58c10 call.

If an environment allows the preceding accesses with a null base, the null comparison and non-returning call can be reached. Whether such an environment is intended is unknown. Behavior if F-a817d8d58c10 returns contrary to its annotation is **documented_only**.

2. The first caller-supplied 32-bit value.
3. The second caller-supplied 32-bit value.

The returned 32-bit integer is tested for equality with zero. No other result classification is visible.

No dependency preservation guarantees are established. In particular, F-4f1f8618b6f1 is not known to preserve:

### Nonzero result

If F-4f1f8618b6f1 returns any nonzero integer, the function returns the original region address.

On this path, the function does not reread the fields, perform the callback lookup, or undo dependency mutations. It does not validate that the returned address is still usable.

### Zero result and callback selection

If F-4f1f8618b6f1 returns zero, the function performs a fresh read of the region’s first field. Callback selection then follows this order:

1. Read the current first field as a 32-bit integer.
2. Add the integer constant 4 in the represented 32-bit integer domain.
3. Convert the resulting integer to the pointer used for reading a callback address.
4. Read the callback address from that converted location.
5. Invoke the selected callback with the original region address as its sole visible argument.

The first field is not converted to an address before the addition. The established sequence is **integer addition, then integer-to-pointer conversion, then callback-address read**.

The supplied integer typing is signed. The evidence does not establish the outcome when adding 4 exceeds the signed 32-bit range. In particular, this contract does not promise modulo-\(2^{32}\) wrapping, conversion to a wider arithmetic domain, saturation, or a recoverable error. The mapping from an integer sum to a pointer is also unestablished.

For sums representable as signed 32-bit integers, the addition itself has no overflow concern. For example, a field value of 4096 produces the integer sum 4100. Whether converting 4100 designates readable storage containing a callable address remains an environmental prerequisite.

The callback lookup uses the field’s value **after** F-4f1f8618b6f1 returns. A dependency mutation can therefore change callback selection. There is no saved initialization value used for this lookup.

No local check validates the current field, the arithmetic outcome, the converted pointer, the readability of callback-address storage, or the callability of the retrieved target.

After the callback returns normally, the function returns null. It performs no further access to the region. No callback return value is used.
