# F-3bf7747d55d8

## Purpose

F-3bf7747d55d8 conditionally invokes a dependency, transforms two 32-bit words in a selected memory region, and optionally copies eight 32-bit words from that region into fields of its input object.

The transformations use unsigned 32-bit addition followed by masking. They are consistent with rounding a value to a multiple of 64, with halfway cases rounded upward, but they are not saturating and do not establish that the values represent addresses, sizes, or coordinates.

The function returns a 32-bit zero if execution reaches its normal return. It does not return the transformed data directly.

This contract describes behavior established by the supplied static material. It does not assume that the dependency leaves the object, referenced storage, or global state unchanged.

## Behavior

### 1. Inspect the initially selected word

The function reads the base field at object offset `0x84` and the unsigned 16-bit index at `0x7c`, forms a selected anchor, and reads the 32-bit word at anchor offset `-0x20`.

Define the transformation on an unsigned 32-bit value as:

\[
R(x)=((x+32)\bmod 2^{32})\mathbin{\&}\texttt{0xffffffc0}.
\]

The function compares this transformation of the inspected word with the original word.

- If they differ, it invokes F-a8771a2dd698.
- If they are equal, it skips that invocation.

Equality holds exactly when the inspected word’s low six bits are zero. Consequently, the call condition is equivalent to testing whether that word is not a multiple of 64.

The inspected word is not directly overwritten by this stage. The function neither substitutes its transformed value nor repeats the condition after the dependency returns.

The dependency is called at most once by this function invocation. No explicit argument is supplied in the available call representation, and no returned value is consumed.

### 2. Transform the first writable selected word

After the conditional call has completed or been skipped, the function rereads the object’s base and index fields and forms a new selected anchor.

It then:

1. Reads the 32-bit word at anchor offset `-0x18`.
2. Applies \(R\).
3. Writes the resulting 32-bit value back to that same address.

This selection is not guaranteed to match the selection used for the initial condition. The dependency may have changed either selector field or the referenced memory.

### 3. Transform the second writable selected word

The function again rereads the base and index fields and forms another selected anchor.

It then reads, transforms with \(R\), and overwrites the 32-bit word at anchor offset `-0x04`.

The first transformation and its write occur before this new selection. If selected storage overlaps the selector fields, that write can affect which address is used for the second transformation. The function does not retain a single anchor across these two updates.

### 4. Decide whether to copy

Only after both transformation writes does the function read the byte at object offset `0x41`.

- A nonzero byte suppresses all eight destination writes.
- A zero byte enables the copy described below.

The decision uses the byte’s value at this stage, not a value captured on entry. Earlier writes or dependency effects can therefore influence it where storage overlaps.

### 5. Copy selected words when enabled

If copying is enabled, the function rereads the base and index fields and forms one selected anchor for the entire copy phase.

The copy mapping is:

| Source offset from selected anchor | Destination offset from object |
|---|---|
| `-0x20` | `0x44` |
| `-0x1c` | `0x48` |
| `-0x18` | `0x4c` |
| `-0x14` | `0x50` |
| `-0x10` | `0xa8` |
| `-0x0c` | `0xac` |
| `-0x08` | `0xb0` |
| `-0x04` | `0xb4` |

These are four sequential pairs, not a single atomic snapshot. Within each pair:

1. The higher-addressed source word is read and retained.
2. The lower-addressed source word is read.
3. The lower-addressed destination word is written.
4. The higher-addressed destination word is written with the previously retained value.

The pairs execute in table order. Thus the first pair finishes before either source read for the second pair, and so forth.

This ordering matters if sources and destinations overlap. An earlier destination write may change a source read in a later pair. However, it cannot change the higher-addressed source value already retained for its own pair.

The anchor is retained throughout this phase. Destination writes that alter the object’s selector fields do not trigger another selection within the copy phase.

### 6. Return

After the optional copy, the function returns zero. It performs no further explicit validation or recovery.
