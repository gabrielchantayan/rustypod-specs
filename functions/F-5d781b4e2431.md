# F-5d781b4e2431

## Purpose

F-5d781b4e2431 conditionally records the return of a non-null address to the first matching descriptor in a linked collection. Depending on the descriptor’s updated count and its position in that collection, it either:

- Prepends the supplied address to a descriptor-local, singly linked list; or
- Attempts to unlink and release the descriptor, updating allocator-like accounting along the way.

The interpretation as a return-to-pool or deallocation operation is inferred intent. The established behavior is address-range lookup, counter modification, conditional list insertion, and conditional descriptor cleanup.

This is not a general-purpose validated deallocation interface. The visible implementation does not establish address alignment, object boundaries, uniqueness of returns, ownership of the supplied address, or consistency of descriptor counts.

## Interface

**Input:** One pointer-sized argument identifying a writable location. The visible representation uses 32-bit pointers and 32-bit integer words.

**Output:** No explicit return value.

**Null input:** Returns immediately, without reading the visible global context or calling a dependency.

**Normal-path input requirements:**

- The supplied address must be safe to compare with descriptor range endpoints.
- If the list-insertion path is reached, at least four bytes at the supplied address must be writable.
- Context, descriptor, owner, metadata, and accounting addresses reached during execution must be valid for their respective reads and writes.
- Descriptor chains must permit traversal to terminate or reach a matching descriptor. Cycle detection is absent.
- Callers must provide any synchronization or structural invariants not supplied by the dependencies. The wrapper itself establishes no visible synchronization around descriptor lookup, count modification, or list insertion.

An address that falls within a descriptor’s recorded range is not otherwise validated before being used.

## Behavior

### 1. Initial eligibility and lookup

For non-null input, the function first captures the collection-context pointer from the global anchor. It then calls F-8ff94386ac71 with no explicit arguments.

If that dependency returns zero, the function returns. It performs no descriptor lookup or wrapper-issued descriptor modification on that path. Side effects of the dependency itself remain possible.

For any nonzero result, traversal starts from the head at offset +12 of the previously captured context. The function does not visibly reload that context pointer from the global anchor after the dependency call.

Descriptors are visited in next-pointer order. A descriptor matches when the supplied address is between its lower and upper bounds, inclusive. The first match wins. No smallest-range, closest-range, or unique-owner rule is established.

If traversal reaches a null pointer without a match, the function returns without a wrapper-issued write to the supplied address or to a descriptor.

The exact numeric ordering used by the pointer comparisons is not independently specified beyond the comparisons shown in the supplied representation. Ordinary valid, consistently ordered addresses are the intended operating case; addresses crossing representation-dependent ordering boundaries require separate confirmation.

### 2. Count update

For the matching descriptor, the function reads the current count, adds one, and stores the result back at offset +16.

It then compares that updated value with the threshold at offset +12. This is an equality test, not a greater-than-or-equal test.

If the updated count does not equal the threshold, execution proceeds directly to list insertion.

There is no visible guard against overflow or against a count already exceeding its threshold. The arithmetic operands are 32-bit values in the supplied representation. Exact signed-overflow behavior is not established by this static material; there is no visible saturation or explicit overflow-error branch.

### 3. Retaining the sole descriptor

When the updated count equals the threshold, the function rereads the collection’s head pointer using the captured collection context.

Descriptor release is bypassed only when both conditions hold:

1. The matching descriptor is that current head.
2. Its next-descriptor pointer is null.

That case proceeds to list insertion. Thus a sole descriptor is retained even when the equality condition is reached.

Every other head/next configuration proceeds toward descriptor release. This decision is based on the reread head and the matching descriptor’s next pointer, not on an independent full count of descriptors.

### 4. Descriptor-release checks and unlinking

Before unlinking, the descriptor’s marker at offset +0 must equal a global expected marker. A mismatch causes an immediate return.

At this point the count increment has already occurred. A marker mismatch does not roll it back and does not insert the supplied address into the descriptor-local list.

The owner pointer at descriptor offset +4 identifies the context whose chain is modified. This is distinct from the context used for the original search; the function does not visibly check that they are equal.

If the owner’s head is the matching descriptor, the owner’s head is replaced by the matching descriptor’s next pointer.

Otherwise, the owner’s chain is traversed until a predecessor whose next pointer equals the matching descriptor is found. That predecessor’s next pointer is then replaced by the matching descriptor’s next pointer.

If this traversal reaches null without finding such a predecessor, cleanup still continues. Failure to find the descriptor in its owner’s chain is not an error return and does not prevent the later release-related calls.

A cyclic owner chain that never produces the required predecessor can cause nontermination.

### 5. Preliminary cleanup and metadata validation

After the unlink attempt, the function calls F-2fd8826557a4 with no explicit arguments.

Only after that call does it read the accounting-context pointer through a separate global pointer location. Consequently, changes made by F-2fd8826557a4 to that location may affect which accounting context is used.

The metadata word eight bytes before the descriptor is then validated:

- Zero is invalid.
- Any value with its least significant bit set is invalid.

Either invalid condition invokes F-a817d8d58c10. The supplied representation marks that call as non-returning. No ordinary recovery, reinsertion, or rollback is visible.

This validation occurs after the count increment, attempted unlink, and F-2fd8826557a4 call. A fatal metadata failure therefore does not imply that earlier state changes were avoided.

### 6. Accounting updates and release handoff

For valid metadata, F-c0fc6d033caa is called with the captured accounting-context pointer.

After that dependency returns, the function reads the unsigned 16-bit index at descriptor offset −4. It obtains an accounting quantity by masking the header at offset −8 with `0x3ffffffc`.

This mask retains bits 2 through 29 and excludes the lowest two and highest two bits. The resulting quantity is a multiple of four. It is not necessarily positive: a nonzero, even header can pass validation while yielding a masked quantity of zero.

Using that quantity, the function performs these 32-bit accounting updates in order:

1. Subtract from the word at accounting-context offset `0x224 + 4 × first index`.
2. Subtract from the word at offset `0x30c`.
3. Read the unsigned 16-bit index at descriptor offset −2, then subtract from the word at offset `0xe0 + 4 × second index`.
4. Subtract from the word at offset `0x220`.

It then calls F-09dcb55e8e0a with no explicit arguments. Its result selects the next accounting word:

5. Decrement the word at offset `0x310 + 4 × returned index` by one.
6. Decrement the word at offset `0x390` by one.
7. Reread the header at descriptor offset −8, mask it with `0x3ffffffc`, and subtract that result from the word at offset +8.

The function then calls, in order:

8. F-cc6c9b4a0f68 with the accounting-context pointer and the address of the metadata word at descriptor offset −8.
9. F-e586bff64fb7 with the accounting-context pointer.

It then returns.

The last quantity is reread rather than necessarily reusing the earlier masked quantity. If F-09dcb55e8e0a changes the header, the final subtraction can differ from the preceding four quantity-based subtractions.

No range checks are visible for any accounting index, no underflow checks are visible for accounting subtraction, and no error results are inspected from the release-related dependencies.

### 7. Descriptor-local list insertion

When release is not selected, including the sole-descriptor case:

1. The existing list-head value at descriptor offset +28 is written into the first four bytes at the supplied address.
2. The supplied address is stored as the descriptor’s new list head.

The supplied storage therefore becomes a link-bearing node. Its previous first word is overwritten.

There is no duplicate-address detection. Repeatedly supplying an address already in this list can create a self-link or another cycle, depending on the prior list state.

## Side effects

The wrapper’s visible side effects depend on the selected path:

- **Null input:** none.
- **Eligibility dependency returns zero:** dependency effects only.
- **No matching descriptor:** dependency effects and descriptor reads, but no wrapper-issued state writes.
- **Ordinary list insertion:** descriptor count increment, supplied-storage overwrite, descriptor list-head replacement.
- **Marker rejection:** descriptor count increment remains; no list insertion or unlink.
- **Release path:** descriptor count increment, possible chain unlink, dependency calls, metadata reads, accounting writes, and a metadata-address handoff.

On the release path, the function does not directly write a list link into the supplied address.

The visible code does not itself establish that the descriptor or supplied storage has been freed, unmapped, retained, or transferred to a particular owner. F-cc6c9b4a0f68 receives the metadata address, but its ownership and reclamation contract are unknown.

There is no visible transactional rollback. Failures, abnormal termination, invalid addresses, or non-returning dependencies may leave earlier writes in place.

Accounting fields are updated sequentially. If unusual indices cause fields to overlap, each later operation acts on the value resulting from earlier operations; the updates must not be treated as simultaneous independent assignments.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless otherwise stated, all accessed memory is valid, chains are well formed, arithmetic remains representable, and dependencies return normally without altering the relevant state.

1. **Null address**  
   A null input returns without calling F-8ff94386ac71 or touching the collection.

2. **Eligibility denied**  
   For a non-null input, if F-8ff94386ac71 returns zero, no descriptor traversal or supplied-storage overwrite follows.

3. **No containing range**  
   If every visited descriptor excludes the address and the chain terminates, all descriptor counts and list heads remain unchanged by the wrapper.

4. **Inclusive boundary match**  
   An input equal to a descriptor’s lower bound or upper bound qualifies for that descriptor. If an earlier descriptor also includes it, the earlier descriptor wins.

5. **Nonthreshold insertion**  
   With count 2 and threshold 5, the count becomes 3. If the old descriptor-local head is address A, the supplied location receives A and becomes the new head.

6. **Threshold reached in a sole descriptor**  
   With count 4, threshold 5, and the matching descriptor both the current collection head and terminal node, the count becomes 5 and list insertion occurs. Descriptor-release dependencies are not called on this path.

7. **Threshold reached with another descriptor present**  
   With count 4 and threshold 5, release is selected if the matching descriptor is not the current head, or if it is the head with a non-null next pointer. Given a valid marker and metadata, unlinking and accounting follow; the supplied address is not inserted into the local list.

8. **Invalid marker after count increment**  
   If release is selected but the descriptor marker differs from the expected global marker, the updated count remains stored. The function returns before unlinking and before F-2fd8826557a4.

9. **Descriptor absent from owner chain**  
   If the owner chain terminates without containing the descriptor, release processing still advances to F-2fd8826557a4 and metadata validation.

10. **Invalid metadata after unlink**  
    A header value of zero or any odd value invokes F-a817d8d58c10 after the preceding unlink attempt and preliminary dependency call. No ordinary return is expected.

11. **Valid header with zero accounting quantity**  
    A header value of 2 passes validation and masks to zero. Quantity-based subtractions therefore subtract zero, but both unit-count decrements still occur.

12. **Header changed by the index dependency**  
    If F-09dcb55e8e0a changes the masked header quantity from 16 to 32, the first four quantity-based updates use 16, while the final subtraction at accounting-context offset +8 uses 32.
