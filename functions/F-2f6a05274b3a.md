# F-2f6a05274b3a

## Purpose

F-2f6a05274b3a advances a mutable context and reports an outcome through two separate channels: a 32-bit return status and a writable 32-bit output word.

The established behavior distinguishes two modes using a descriptor byte. Zero mode derives addresses in backing data and passes them through two dependencies. Nonzero mode uses a completion query and a transition dependency to obtain a position below a descriptor count.

“Position,” “completion,” “preparation,” and “transition” are inferred role descriptions, not independently established domain meanings. Direct output writes suggest that zero means continued processing or an intermediate transition, while one reports completion. A zero return alone does not distinguish those outcomes.

This contract describes static evidence only. Dependency internals, ownership rules, and runtime guarantees are not supplied.

## Interface

### Inputs and return value

The function receives:

- A reference to a mutable context.
- A reference to a writable 32-bit output word.

It returns a 32-bit status. Locally successful paths return zero. Certain dependency results are returned unchanged; a different dependency’s nonzero result is consumed as a completion condition rather than propagated.

The function directly writes only zero or one to the output word. Some return paths perform no direct output write, so callers cannot assume every invocation initializes it.

## Behavior

### Preparation and inactive handling

Each outer iteration begins by reading the activity byte as unsigned.

- Values zero and one skip preparation.
- Values two through 255 cause a call to **F-f2de7328b737** with the context.

A nonzero preparation result is returned unchanged. This function makes no direct output write on that return path.

After skipped or successful preparation, the function loads the descriptor reference from context offset `0x18`, then reads the activity byte again. The second activity read is not replaced by the first: preparation may have changed the context.

If this second read is zero, the function writes one to the output word and returns zero. It does not directly clear the pending indicator, advance the position, or reset the auxiliary fields. The descriptor reference has been loaded, but the inactive branch does not itself dereference that reference.

### Pending-indicator handling

For an active context, the function reads the signed 32-bit pending indicator and then writes zero to its storage.

If the previously read value was strictly positive, the function writes zero to the output word and returns zero.

Zero and negative values do not take this early return. They are still cleared before further processing. The condition is therefore not equivalent to testing whether the field is nonzero.

### Position advancement

The function reads the signed 32-bit position, adds one, and stores the incremented value back to the position field. It then clears the 16-bit field at `0x3e`, followed by the byte at `0x42`.

The incremented value is compared, as signed, with the unsigned 16-bit descriptor count widened to a nonnegative integer. That count lies between zero and 65,535.

The descriptor reference used here is the one loaded before the second activity read. No dependency call intervenes between that reference load and this comparison. The comparison uses the incremented value already obtained, rather than requiring a fresh position-field read after the auxiliary resets.

The supplied high-level representation does not establish the behavior of incrementing the maximum signed 32-bit position. Checked, saturating, or wrapping semantics must not be invented.

### Position below the count

If the incremented position is strictly below the count, the function writes zero to the output word before reading the selected descriptor’s mode byte.

A nonzero mode causes an immediate zero return. No backing-data dependency is called.

A zero mode enters a repeated backing-data processing path. Each repetition:

- Reloads the current descriptor reference from the context.
- Reads that descriptor’s mode byte.
- Returns zero immediately if the mode is now nonzero, without another direct output write.
- Otherwise derives a backing-data address and invokes the processing dependencies.

The derived address uses:

- The 32-bit backing-data base from the reloaded descriptor.
- The unsigned 16-bit table offset from that descriptor.
- A fresh signed 32-bit position read from the context.
- A two-byte entry selected at table offset plus twice that position, relative to the backing-data base.

The two entry bytes form an unsigned 16-bit displacement: the byte at the lower address supplies the high eight bits, and the next byte supplies the low eight bits. The displacement is added to the backing-data base.

This establishes high-byte-first interpretation of table entries, not machine byte order for other fields. The representation does not establish which of the two entry bytes is read first. It likewise does not establish an evaluation order between the table-offset and position reads used in the indexing expression.

The derived address is passed to **F-d1e995cfb2d3**. Its 32-bit result is passed with the context to **F-f5f7d8715f96**.

- A nonzero result from F-f5f7d8715f96 is returned unchanged.
- A zero result repeats from the descriptor reload.

There is no local position increment or count recheck within this loop. Any progress through position changes, mode changes, or other dependency effects is outside the visible local logic.

A negative incremented position can satisfy the signed “below count” condition. No visible lower-bound check prevents subsequent table addressing with a negative position.

### Position at or beyond the count: zero mode

If the incremented position is at least the count and the selected descriptor’s mode byte is zero, the function derives a boundary-processing address:

- The descriptor’s backing-data base.
- Plus its unsigned byte at `0x08`.
- Plus eight.

The relative evaluation order of the base-field and byte-field reads is not established by their arithmetic expression.

The address is passed to **F-d1e995cfb2d3**, and its result is passed with the context to **F-f5f7d8715f96**.

If F-f5f7d8715f96 returns nonzero, that exact status is returned. This branch has not directly written the output word.

If it returns zero, the function calls **F-ef0e6e1f8310** with the context. After that call returns, the function writes zero to the output word and returns that dependency’s result unchanged.

Thus this path can return a nonzero status while directly writing output zero. Position advancement, auxiliary resets, and earlier writes are not rolled back.

### Position at or beyond the count: nonzero mode

For nonzero mode, each iteration first calls **F-d758d63f3254** with no explicit arguments.

Any nonzero result, positive or negative, causes the function to:

1. Write one to the output word.
2. Clear the context’s activity byte.
3. Return zero.

The dependency’s result is not propagated.

A zero result instead causes a call to **F-64e63ffb6e8f** with the context. No return value from this call is visibly tested.

After the transition call, the function reloads the descriptor reference. It then compares that descriptor’s unsigned 16-bit count with the context’s signed 32-bit position. **The relative order of the count-field read and position-field read is not established.** Both belong to the comparison after the descriptor reload; neither is specified to precede the other.

The loop repeats while the count is less than or equal to the position. Each repetition begins with another F-d758d63f3254 call.

Once the comparison establishes that the position is strictly below the count, the function writes zero to the output word. It then reads byte `0x06` using the descriptor reference loaded after the most recent transition call:

- Zero causes a zero return.
- Nonzero begins another outer iteration, including a fresh activity check and any required preparation.

The established sequence is therefore: transition call, descriptor reload, comparison using the two unordered operand reads, output-zero write, then descriptor-byte-`0x06` read. There is no additional descriptor-reference reload between that output write and the byte read.

## Side effects

Direct writes are confined to:

- The caller’s 32-bit output word.
- The 32-bit pending-indicator field.
- The 32-bit position field.
- The 16-bit auxiliary field at `0x3e`.
- The auxiliary byte at `0x42`.
- The activity byte on alternate-mode completion.

These writes are not transactional. A later nonzero dependency result does not undo earlier changes.

Observable ordering includes:

- Pending-indicator read before its clearing write.
- Position update before the two auxiliary resets.
- Output zero before the initial in-range mode read.
- F-ef0e6e1f8310 returning before the zero-mode boundary output write.
- Output one before the alternate-mode activity clear.
- Successful alternate-mode comparison before output zero, and output zero before reading descriptor byte `0x06`.

Output aliasing can affect later reads. For example, an output write overlapping descriptor byte `0x06` may affect the outer-repeat decision. Overlap with the context’s descriptor-reference field does not itself cause a fresh reload where none is specified.

No allocation or release is directly visible. This does not establish that dependencies allocate nothing, release nothing, retain no references, or preserve global state. No ownership transfer or lifetime extension is established for any passed reference or intermediate result.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, assume valid nonoverlapping storage, no concurrent mutation, representable arithmetic, and dependencies with only the stated effects.

1. **Inactive entry.** Activity is zero. The descriptor reference is loaded, output becomes one, and the function returns zero. Pending, position, and auxiliary fields receive no direct writes.

2. **Preparation changes activity.** Activity is two. F-f2de7328b737 returns zero and changes activity to zero. The subsequent activity read selects the inactive path, producing output one and return zero.

3. **Preparation failure.** Activity is 255 and F-f2de7328b737 returns a nonzero status. That status is returned unchanged. No direct output write or later field update occurs.

4. **Positive pending indicator.** Activity is one and pending is three. Pending becomes zero, output becomes zero, and the function returns zero without advancing position.

5. **Negative pending indicator.** Activity is one and pending is negative. Pending is cleared, but processing advances the position rather than taking the pending early return.

6. **In-range nonzero mode.** Position starts at zero, count is three, and mode is nonzero. Position becomes one, both auxiliary fields are cleared, output becomes zero, and the function returns zero without backing-data calls.

7. **High-byte-first displacement.** An accessed entry contains `0x12` at its lower address and `0x34` at the next address. F-d1e995cfb2d3 receives the backing-data base plus `0x1234`, not plus `0x3412`. Either temporal order of the two byte reads is consistent with this contract.

8. **In-range processing failure.** F-f5f7d8715f96 returns nonzero during table processing. That status is returned unchanged. The preceding output-zero write and context updates remain in effect.

9. **Boundary processing failure before output.** Zero mode is selected at or beyond the count, and F-f5f7d8715f96 returns nonzero. The status is propagated without a direct output write on this branch.

10. **Boundary continuation failure after output.** Boundary processing returns zero, then F-ef0e6e1f8310 returns nonzero. Output is written zero after the latter call, and its nonzero status is returned.

11. **Alternate-mode completion.** The advanced position is at or beyond the count, mode is nonzero, and F-d758d63f3254 returns a negative value. Output becomes one before activity is cleared; the function returns zero.

12. **Successful alternate-mode transition.** F-d758d63f3254 returns zero. F-64e63ffb6e8f leaves position four and installs a descriptor with count five. After reloading that descriptor, the function compares count and position without a specified relative read order, writes output zero, then reads descriptor byte `0x06`. Zero ends the call; nonzero restarts the outer iteration.

13. **Transition still beyond the bound.** After a transition, position equals the reloaded count. The function repeats the alternate-mode loop without first writing output zero or reading byte `0x06`.

14. **Unbounded table repetition.** Table-processing dependencies repeatedly return zero and leave mode zero. The function keeps repeating; no local count recheck or iteration limit forces termination.
