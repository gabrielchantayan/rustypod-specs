# F-fe74d8804c95

## Purpose

F-fe74d8804c95 performs ordered memory writes interleaved with indirect calls, then enters a repeating call-and-write sequence with no visible exit.

Its directly represented behavior consists of:

- Two 32-bit writes to the same first-input-derived address.
- Byte reads that select low-valued byte-write destinations.
- A byte write to a fourth-input-derived address.
- Ordered indirect calls whose results supply later arguments, stored values, and address calculations.
- A loop whose first call uses one indirect target on its first iteration and a different target on subsequent iterations.

No application-level purpose is established. Interpreting this as a parser, allocator, device controller, or other domain-specific operation would exceed the evidence.

This contract describes the supplied static representation. Warnings about invalid instruction data and excluded control-flow regions leave the completeness and fidelity of that representation unresolved.

## Behavior

### Arithmetic and naming conventions

All word calculations are represented at 32-bit width. Byte reads are unsigned; byte writes retain the low eight bits of the represented value.

The following descriptive names identify values in this contract:

- **Scaled first input:** four times the first input, calculated as signed arithmetic.
- **Entry selector base:** the implicit unsigned entry value shifted right by eight.
- **Fourth-input base:** the fourth input shifted logically right by seven.
- **First result word:** the unsigned result consumed from F-00000000000a.
- **Second result word:** the unsigned result consumed from F-000000000016.
- **Loop seed:** an unsigned state value, initially extracted from F-000000000022.
- **Loop carry:** the signed value passed as the first argument of F-000000000025.

A **selected write** means a byte read from a stated selector address, followed by a byte write to the numeric address equal to that byte plus hexadecimal 11. Its destination therefore lies between hexadecimal 11 and hexadecimal 110, inclusive. It is not inherently a write back to the selector location.

Unsigned shifts have 32-bit unsigned semantics. Signed multiplication, signed addition, signed left shifts, and conversion of an out-of-range unsigned word to a signed word require separate qualification. The supplied representation does not establish a general wrapping interpretation for them.

In particular, assigning a signed shift result to unsigned storage does not make the preceding shift unsigned.

The entry selector base is established before the first call. The following calls then occur in order:

| Dependency | Explicit arguments | Result use |

| F-000000000005 | None shown | Retained as a signed 32-bit result |

After F-000000000005 returns, the routine writes the scaled first input as a 32-bit word to the same address as the first write.

The two word stores remain distinct observable events, separated by five calls. Equal stored values would not justify merging them.

### First selected data writes

The routine reads a selector byte at the entry selector base plus one. It writes the low byte of the first result word shifted left by two to the selected destination.

The shift is unsigned. Its 32-bit result is also converted to a signed word for subsequent arguments; conversion outside the signed range is not resolved by the artifact.

The next calls are:

| Dependency | Explicit arguments |
|---|---|
| F-00000000000b | Three equal signed-word arguments obtained from that shifted first result word |
| F-00000000000c | None shown |
| F-00000000000d | The opaque 32-bit result of F-00000000000c |
| F-00000000000e through F-000000000011 | None shown, in ascending order |

The result of F-000000000011 is retained as a signed 32-bit value.

The selector byte at the entry selector base plus one is read again. The selected destination receives the low byte of the first result word masked to 30 bits and logically shifted right by 20. The stored byte therefore contains original first-result bits 20 through 27. Original bits 28 and 29 survive the extraction but not the byte truncation.

This second selector read is a separate observable read. Dependencies or earlier aliased writes may have changed its value.

### Fourth-input write and two selected clears

F-000000000012 receives the signed result of F-000000000011 shifted left by two. F-000000000013 through F-000000000016 then execute in ascending order, with no explicit arguments shown. The last result becomes the second result word.

The routine next performs, in order:

1. A byte write at the fourth-input base plus hexadecimal 1c, storing the low byte of the second result word shifted left by two.
2. A selector read at the entry selector base plus one, followed by a selected zero-byte write.
3. F-000000000017, receiving the fourth-input base.
4. F-000000000018, with no explicit arguments shown.
5. F-000000000019, receiving the second result word masked to 30 bits and logically shifted right by six.
6. F-00000000001a through F-00000000001d, in ascending order, with no explicit arguments shown.

The argument to F-000000000019 is unsigned and lies between zero and hexadecimal ffffff.

The fourth-input-derived write occurs before the first selected clear in this phase. Aliasing can therefore make that clear overwrite the data byte. Aliasing with selector storage can instead change which destination the clear selects.

The second result word shifted left by two is an unsigned 32-bit result. A signed-word conversion of this value is retained for later selector-address calculation; its interpretation outside the signed range is unresolved.

### Entry into the loop

F-00000000001e receives the signed result of F-00000000001d shifted left by two. F-00000000001f through F-000000000022 then execute in ascending order, with no explicit arguments shown.

The unsigned result of F-000000000022 is masked to 30 bits and logically shifted right by 25. This establishes the initial loop seed, between zero and 31 inclusive.

A different selector address is then used for a selected zero-byte write. This **loop selector address** is formed from the retained signed conversion of the second result word shifted left by two: multiply that signed value by hexadecimal 400, then add one.

Consequently, this address calculation depends on both the unsigned-to-signed conversion and signed arithmetic. It is not unconditionally equivalent to wrapping the second result word shifted left by twelve and adding one.

F-000000000023 receives twice the initial loop seed, an unsigned argument between zero and 62. F-000000000024 follows with no explicit arguments shown. Its signed 32-bit result initializes the loop carry without an intervening shift.

Within each iteration, the observable order is:

The loop selector address remains derived from the second result word. It does not follow the evolving loop carry or seed.

The first invocation of F-000000000025 receives zero as its second argument because the initial seed is at most 31.

Later second arguments require arithmetic qualification:

- For a nonnegative F-00000000002e result from zero through 31, both signed shifts are representable. The next second argument equals that result multiplied by hexadecimal 40000, ranging through hexadecimal 7c0000.
- Under an additional **32-bit wrapping/bit-vector assumption**, the next carry is the low 32 bits of the result shifted left by two, and the next second argument is its low six bits shifted left by 18. That conditional range is zero through hexadecimal fc0000, in multiples of hexadecimal 40000.
- Without that assumption, the full low-six-bit recurrence is not established. A result of 32 already makes the signed left shift by 26 unrepresentable. Negative signed operands also lack an established left-shift interpretation here.

## Side effects

The directly represented accesses are:

- Two 32-bit writes to one first-input-derived address.
- Four entry-selector reads, each followed by a selected byte write: two data writes and two zero writes.
- One fourth-input-derived byte write.

## Acceptance examples

These are conditional static consequences, not executed tests.

### Separated word writes

With first input 3, valid arithmetic, and writable storage, the first word write stores 3 at hexadecimal 20. After F-000000000005 returns, the second stores 12 at the same address. The five intervening calls remain observable.

### Selected data and rereading

With first result word hexadecimal 12345678 and selector byte hexadecimal 20, the first selected data write stores hexadecimal e0 at hexadecimal 31.

If the later selector read also returns hexadecimal 20, the second selected data write stores hexadecimal 23 there. If dependencies change the selector to hexadecimal 21, that second write instead targets hexadecimal 32.

### Fourth-input write and aliasing

With fourth input hexadecimal 100, the fourth-input base is 2 and its byte-write address is hexadecimal 1e. With second result word 3, that write stores decimal 12.

If the following selector read selects hexadecimal 1e, the subsequent zero write overwrites that byte before F-000000000017. This conclusion requires that any aliasing with selector storage still produces that destination.

### Loop targets

If execution reaches the loop and calls return normally, the first F-000000000025 invocation uses represented target hexadecimal 08833787. After the first iteration’s final-call setup and state update, the next invocation uses hexadecimal 088337c5. Further iterations use the latter target under the visible state flow.

### Defined and conditional seed updates

If F-000000000022 returns hexadecimal 3fffffff, the initial seed is 31. F-000000000023 receives 62, and the first F-000000000025 receives zero as its second argument.

If F-00000000002e returns 1, the next carry is 4 and the next second argument is hexadecimal 40000, with no signed-overflow ambiguity.

If it returns 32, the signed shift by 26 is unrepresentable. The next seed and second argument are unresolved without additional arithmetic semantics. Under an explicit 32-bit wrapping assumption only, they are hexadecimal 80000000 and hexadecimal 800000 respectively.

### Interrupted execution

If a selected write faults, later operations on the visible path are not reached unless an external mechanism changes execution. No local recovery is established.
