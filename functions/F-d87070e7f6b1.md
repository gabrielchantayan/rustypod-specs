# F-d87070e7f6b1

## Purpose

F-d87070e7f6b1 performs an indexed traversal whose continuation is controlled by F-fd477cd1a249. For each visited index, it obtains a candidate through F-667717e3fb3e, follows up to two pointer-sized fields, and compares the resulting pointer value with the original input. A match triggers F-b3f16c6113a2 with no explicit arguments.

The original input remains the comparison target throughout the invocation. A separate working pointer changes during traversal and supplies the argument to the next continuation query. These two roles must not be conflated.

The apparent intent is to find entries associated with the supplied target and trigger an action for each match. That intent is inferred, not established. The available evidence does not identify the entries, the action, or whether any dependency mutates a collection.

The established normal return value is a 32-bit zero. It does not report how many entries were visited or matched.

## Interface

### Input

The function accepts one pointer-valued argument, treated as 32 bits in the supplied representation.

The argument has two observable roles:

- It is passed to F-fd477cd1a249 on the first continuation query.
- Its original value is retained as the target for every candidate comparison.

The function itself does not dereference the original input merely because it is the input. A dependency may dereference it, and candidate-derived memory accesses may happen to address the same storage.

No explicit non-null check is applied before the first dependency call. A null input is therefore not rejected locally. Whether it is acceptable to F-fd477cd1a249 is unknown.

### Output

On every normal exit shown by the supplied representation, the function returns a 32-bit value of zero.

There is no local error result, match count, or early-success result. A triggered action does not by itself end traversal.

## Behavior

### Continuation and traversal order

At entry, the working pointer equals the original input and the signed index equals zero.

Before any candidate is requested, F-fd477cd1a249 is called with the current working pointer. Its returned signed value is compared with the current index. Traversal proceeds only when the index is strictly less than that value.

This query occurs on every continuation decision, including the final decision that ends the traversal. The function does not obtain a single bound and reuse it.

For each accepted index, the observable local sequence is:

1. Call F-667717e3fb3e with that index and zero.
2. Extract the candidate pointer from the low 32 bits of its result.
3. If the candidate is non-null, read its first 32-bit word.
4. If that word represents a non-null pointer, read the first 32-bit word at that second address.
5. Compare the final word, as a pointer value, with the original input.
6. If equal, call F-b3f16c6113a2 with no explicit arguments.
7. Increment the index once.
8. Query F-fd477cd1a249 again using the resulting working pointer.

The continuation query therefore precedes each candidate request. Both candidate-chain reads, when required, precede the match-triggered call.

### Working-pointer transitions

The argument to the next continuation query depends on what happened in the current iteration:

| Current iteration outcome | Working pointer for the next query |
|---|---|
| Candidate pointer is null | Null |
| Candidate is non-null but its first word is null | Candidate pointer |
| Both chain addresses are non-null, but the final value does not match | Candidate pointer |
| Final value matches the original input | Pointer-valued result of F-b3f16c6113a2 |

The second-level pointer is not itself used as the next continuation argument.

This changing argument is part of the contract. Replacing every continuation argument with the original input, or caching the first bound, would change observable dependency calls.

### Null handling and comparisons

A null candidate prevents both candidate-chain reads and prevents the action call.

A non-null candidate whose first word is zero causes exactly one local chain read. It prevents the second read and the action call.

When both chain addresses are non-null, the function reads the final word and compares it directly with the original input. It does not dereference that final value.

Consequently, a null original input can match: a non-null candidate may point to a non-null second location whose first word is zero. Subject to dependency behavior and continuation permitting that iteration, this triggers F-b3f16c6113a2.

There is no special handling for repeated candidates or repeated matches. Each visited index is processed independently. Multiple matches can cause multiple action calls.

### Dynamic bounds and termination

For the initial query, a returned bound of zero or any negative signed value prevents all candidate requests. A positive bound permits index zero.

Later continuation decisions use newly returned bounds. A returned value equal to the current index stops traversal; only a strictly greater value continues it. Bound changes can therefore shorten or extend traversal.

The index is not reset after an action call. It advances once after every completed iteration, regardless of null candidates, mismatches, or matches.

Under the shown signed 32-bit interpretation, an executed iteration cannot start with an index greater than 2,147,483,646: continuation requires a strictly larger signed 32-bit bound. Incrementing that index produces 2,147,483,647, after which no signed 32-bit bound can permit another iteration. Thus the visible control flow does not require signed index overflow. This conclusion assumes ordinary completion of dependency calls and no external corruption of local execution state.

## Acceptance examples

These examples are conditional specifications, not recorded executions. Each assumes that all stated dependency calls return normally and all required memory reads are valid.

### No accepted index

Given any original input, if the first F-fd477cd1a249 call returns zero or a negative signed value:

- No call to F-667717e3fb3e occurs.
- No candidate-chain memory is read.
- F-b3f16c6113a2 is not called.
- The function returns 32-bit zero.

### Null candidate with a nonzero upper result half

The function performs no candidate-chain read and no action call. The next F-fd477cd1a249 call receives null, not the upper-half value or the original input.

If that next bound is one, traversal stops because the current index is one.

### Null first field

Suppose index zero is permitted, its candidate pointer is non-null, and the candidate’s first word is zero.

The function reads that word but does not read address zero. It does not call the action dependency. Its next continuation query receives the candidate pointer.

### Nonmatching chain

Suppose a candidate and its first-field pointer are both non-null, and the final word differs from the original input.

Both chain reads occur in order. The action dependency is not called. The next continuation query receives the candidate pointer, not the second-level pointer or the final word.

### Matching chain

Suppose both chain addresses are non-null and the final word equals the original input.

F-b3f16c6113a2 is called once after the comparison. If it returns a pointer value R, the next continuation query receives R. The index still advances by exactly one.

### Null target match

Suppose the original input is null, the first continuation query permits traversal, and a visited candidate leads through two non-null addresses to a final zero word.

That word equals the original input, so the action dependency is called. A null target is not an automatic mismatch.

### Bound contraction after a match

Suppose index zero matches and the action dependency returns R. If the next continuation query with R returns one, traversal ends at index one. No candidate for index one is requested, even if the first query returned a much larger bound.

### Maximum signed bound

If the bound is always 2,147,483,647 and all iterations complete normally, the visited indices are zero through 2,147,483,646. The next query occurs at index 2,147,483,647 and cannot permit another iteration under signed 32-bit comparison.
