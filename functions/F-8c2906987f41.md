# F-8c2906987f41

## Purpose

F-8c2906987f41 selects a location in a context-associated table, obtains a 32-bit value through a dependency or a fallback table read, and publishes the resulting address/value pair in two ways:

- As two consecutive 32-bit words in caller-provided output storage.
- As a packed 64-bit return value, with the address in the low 32 bits and the value in the high 32 bits.

The established behavior is an orchestration sequence involving three dependencies, context-field reads, conditional fallback, and final output writes. A lookup, hash-table, or sentinel-selection interpretation is plausible, but those meanings are not established. In particular, neither the table’s indexing rules nor the semantic meaning of the fallback position can be inferred safely from this function alone.

No runtime tests have been performed.

## Behavior

### 1. Prepare and invoke the initial dependency

The function reads the context word at offset +4 and the first two 32-bit words at the input address. It invokes F-58cc241cfb6b with eight arguments, in this positional order:

1. The context address plus the context word read at offset +4.
2. The context address.
3. The first input word.
4. The second input word.
5. The output address.
6. The context address again.
7. The input address.
8. The opaque fourth argument.

The first argument is address-relative: the field at +4 is added to the context address rather than used directly as an absolute address.

The duplicate context arguments and the distinction between copied input words and the input address are observable parts of the dependency interface. They must not be collapsed merely because two positions initially contain the same address.

The relative order of the individual field and input-word reads used to prepare this call is not established. They occur before control enters the dependency.

F-58cc241cfb6b supplies a 32-bit result used in the next call. This function does not inspect that result for a success or failure condition.

### 2. Invoke the index-producing dependency

After F-58cc241cfb6b returns, the function reads the context word at offset +24 and invokes F-d7be9cfb4000 with:

1. The 32-bit result from F-58cc241cfb6b.
2. The newly read context word at +24.

The timing of this read matters. A change to context offset +24 made by F-58cc241cfb6b can affect the argument passed to F-d7be9cfb4000.

Following F-d7be9cfb4000, the supplied representation exposes a 32-bit value in the auxiliary register r1. The function uses that value as the candidate position.

This is a machine-level data dependency, not proof of a conventional source-language return type. The arithmetic performed by F-d7be9cfb4000 is unknown. In particular, its output must not be specified as a remainder, quotient, hash reduction, or bounds-checked index without additional evidence.

### 3. Form the candidate address

After F-d7be9cfb4000 returns, the function reads the context word at offset +20 as the table base.

The candidate address is formed by adding four times the auxiliary position to that table base. The factor of four establishes a four-byte stride. It does not establish the table’s element count or prove that the position is valid.

The function then calls F-e1a0d3f7ef55 with:

1. The context address.
2. The candidate address.
3. The input address.

No direct read of the candidate table word by this function is visible before this call. The candidate address is supplied to the dependency, whose own accesses are unknown.

F-e1a0d3f7ef55 supplies a 32-bit result. This result controls fallback.

### 4. Select the dependency result or fallback

If the result from F-e1a0d3f7ef55 is nonzero:

- The selected address remains the candidate address supplied to that dependency.
- The selected value is the dependency’s 32-bit result.
- The function performs no further direct context or table reads before publishing the result.

Every nonzero 32-bit result takes this path. The function does not distinguish positive from negative values.

If the result is zero:

- The function reads the context word at +20 again as the table base.
- It reads the context word at +24 again as the fallback position.
- It forms a fallback address by adding four times that position to the newly read base.
- It reads the 32-bit word at the fallback address.
- That address and loaded word become the selected pair.

The fallback uses fresh context reads after F-e1a0d3f7ef55 returns. It does not reuse the candidate table base or the value previously passed to F-d7be9cfb4000.

Consequently, changes made by F-e1a0d3f7ef55 to either context field can affect fallback. The relative order of the two context-field reads used to form the fallback address is not established.

A zero word loaded from the fallback location is a valid final value in the visible behavior. There is no second fallback, retry, or error conversion.

### 5. Publish and return

Once the selected address and value have been obtained, the function:

1. Writes the selected address to the first output word.
2. Writes the selected value to the second output word.
3. Returns the packed 64-bit pair.

The address write precedes the value write. There is no visible atomic pair update or synchronization.

The return is formed from the selected pair, not by rereading the output buffer. Thus the return does not depend on the contents of output storage after those stores, provided execution reaches the return normally.
