# F-27684eb6b19e

## Purpose

F-27684eb6b19e selects between two behaviors:

- Dispatch through an entry obtained from the first argument’s dispatch structure.
- Obtain a size from F-39c23d4da3e4, request a destination through another dispatch entry, invoke an external operation with one less than that size, and write a trailing zero byte.

The selection depends on both the second argument and the 32-bit representation of the third argument. The third argument is not invoked on the second path; it acts as part of the selection condition.

**Inferred intent:** The second path resembles copying a zero-terminated byte sequence into a destination supplied by an object. Neither the size helper’s meaning nor the external operation’s copy semantics is established by the available evidence. Those interpretations are not unconditional requirements of this contract.

## Interface

### Explicit inputs

The supplied representation exposes three inputs:

| Input | Representation | Established use |
|---|---|---|
| Object reference | Pointer to a structure whose first field is a dispatch-table reference | Passed as the first explicit argument to either indirect operation; also dereferenced to locate the selected entry |
| Source token | 32-bit integer | Tested against zero; passed unchanged to F-39c23d4da3e4 and, on the destination path, to the external operation |
| Selector value | Code-pointer-shaped 32-bit value | Tested for zero and for a negative signed interpretation; not itself invoked on either established path |

“Source token” describes its role in this function, not its type outside this function. It may encode an address, but that interpretation requires dependency information absent here.

The analysis uses the 32-bit model expressed by the supplied representation: integer values and dispatch references occupy four bytes. Actual calling-convention details and the recovered declaration’s fidelity remain documented uncertainties.

### Output

There is no explicit return value.

A destination-provider result of zero causes an ordinary return. No distinct error code, exception, or diagnostic is produced by the visible function body.

### Dispatch layouts

Only these layout requirements are established:

- The object’s dispatch-table reference is read at byte offset 0.
- The fallback operation’s entry is read at byte offset 12 within that table.
- The destination-provider entry is read at byte offset 8 within that table.

The evidence does not establish the meaning, size, or layout of other object or table fields.

### Preconditions

These are caller/dependency preconditions, not conditions validated by F-27684eb6b19e.

## Behavior

### 1. Select the path

The destination path is selected only when both conditions hold:

1. The source token is nonzero.
2. The selector’s signed 32-bit interpretation is strictly positive.

All other combinations select the fallback path.

In particular:

- A zero source token selects fallback regardless of the selector.
- A zero selector selects fallback regardless of the source token.
- A selector with bit 31 set selects fallback, even when nonzero.
- A negative source token does not itself select fallback. It qualifies as nonzero.

The selector’s positive range under this model is 1 through 2,147,483,647. The selector is not checked for executable-address validity because it is not used as the call target in the established behavior.

### 2. Fallback path

The visible memory and call sequence is:

1. Read the dispatch-table reference from the object’s first word.
2. Read the indirect target at byte offset 12 from that table.
3. Invoke that target with the original object reference as the sole explicitly recovered argument.
4. Return after the invocation returns.

This path does not invoke F-39c23d4da3e4, obtain a destination, invoke the external operation, or perform the explicit trailing-byte store.

There is no null check for the object, table, or selected target.

The supplied representation also exposes incoming register state whose role is not fully recovered. Assignments involving that state appear before the indirect transfer. Consequently, the single explicit argument does not establish that all other machine-level argument registers are irrelevant, nor does it establish a complete callable signature for this target.

### 3. Obtain a size on the destination path

F-27684eb6b19e first invokes F-39c23d4da3e4 with the source token.

Its result is treated as a 32-bit integer size value. No local check establishes that the result is positive, includes a terminator, fits an allocation, or matches the amount of accessible source data.

No dispatch-table entry for the destination provider is loaded before this helper invocation in the supplied behavior. The subsequent object and table reads therefore occur after any effects of F-39c23d4da3e4.

This ordering matters if that dependency modifies memory reachable through the object, changes shared state, or otherwise affects later dispatch. The function must not be specified as caching the destination-provider target before calling the helper.

### 4. Request a destination

After F-39c23d4da3e4 returns:

1. Read the object’s current dispatch-table reference.
2. Read the target at byte offset 8 from that table.
3. Invoke that target with three explicit arguments, in this order:
   - The original object reference.
   - The size returned by F-39c23d4da3e4.
   - A 32-bit zero.

The result is treated as a 32-bit destination value.

If that result is zero, the function returns immediately. In that case:

- The size helper has already run.
- The destination provider has already run.
- The external operation is not invoked.
- No explicit destination byte is written by this function.

A nonzero result is accepted without further validation. In particular, the visible function does not reject a destination merely because its signed interpretation is negative.

### 5. Invoke the external operation

For a nonzero destination, the function invokes an unidentified external dependency with:

1. The destination value.
2. The original source token.
3. The size result minus one.

The supplied evidence establishes this argument relationship, not the dependency’s semantics. It does not independently establish that the operation copies bytes, that its third argument is unsigned, or that it preserves either object state or destination storage.

No explicit result from this external operation is inspected.

If the operation does not return normally, the final byte store and normal return are not reached.

### 6. Store a zero byte

After the external operation returns normally, the function writes one zero byte at the address formed by:

- Destination plus size minus one.

The write width is exactly one byte. The function does not explicitly clear the full destination, write a four-byte integer zero, or inspect the byte previously stored there.

The external operation precedes this store. The function does not reload the destination from the object or request another destination between the two actions.

### Arithmetic boundaries

The visible arithmetic supplies no local range protection:

- A size of 1 produces an external-operation count of 0 and places the explicit zero byte at the destination itself.
- A size of 0 produces a count of −1 in the recovered signed representation and places the nominal final store one byte before the destination.
- A negative size is not rejected.
- Subtracting one from the minimum signed 32-bit value exceeds the mathematical signed 32-bit range.
- Combining a destination with the size may exceed the representable address range.

The available material does not establish the correct execution-level overflow model for these cases. This contract does not impose wrapping, trapping, saturation, or a particular compiler-language interpretation. A safe successful-use contract requires representable arithmetic and valid accessed addresses unless additional execution evidence supplies a different rule.

## Acceptance examples

These examples are conditional specifications, not reports of executed tests. Unless stated otherwise, assume readable dispatch structures, compatible callees, valid arithmetic, and normal dependency returns.

### Zero source token

Given a zero source token and any selector:

- F-INDIRECT-01 is selected through table offset 12.
- It receives the original object reference.
- No size-helper call or explicit destination-byte store occurs.

### Zero selector

Given a nonzero source token and a zero selector, the same fallback behavior is required. A nonzero source token alone is insufficient to select the destination path.

### High-bit-set selector

Given a nonzero source token and selector representation 0x80000000, fallback is required because the signed selector interpretation is negative.

Given selector representation 0x7FFFFFFF instead, the destination path is selected. Selection does not entail calling that selector address.

### Destination unavailable

Given a nonzero source token, positive selector, helper result 6, and destination-provider result zero:

- F-39c23d4da3e4 runs first.
- F-INDIRECT-02 receives the object, 6, and zero.
- The function then returns without invoking F-EXTERNAL-01 or performing its explicit zero-byte store.

### Ordinary nonzero destination

Given the same selection conditions, helper result 6, and valid nonzero destination:

- F-EXTERNAL-01 receives that destination, the original source token, and 5.
- After normal return, the function writes a zero byte at destination offset 5.

Only if F-EXTERNAL-01 is independently established to copy five bytes may this example additionally require the corresponding five source bytes at destination offsets 0 through 4.

### Size of one

Given helper result 1 and a valid nonzero destination:

- F-EXTERNAL-01 is invoked with a third argument of zero; it is not skipped locally.
- After its normal return, the first destination byte is set to zero.

### Helper changes dispatch state

If F-39c23d4da3e4 changes the object’s dispatch-table reference before returning, the destination-provider lookup observes the post-helper reference. An implementation that loads and retains the earlier table entry would not preserve the established ordering.

### Size of zero

Given helper result zero and a nonzero destination, there is no local early return based on size. The external count is formed as zero minus one, and the nominal final store address is one byte before the destination. Successful completion is conditional on the external signature, arithmetic model, and address validity; it is not guaranteed.
