# F-427a209fe6ff

## Purpose

F-427a209fe6ff repeatedly invokes indirect dependencies and performs ordered memory reads and writes using implicit machine state, two global values, dependency results, and fixed numeric addresses.

**Established static evidence:** each complete iteration contains 37 indirect invocation sites, one software breakpoint, 15 explicit stores, and an explicit decrease of a context-base value by `0xF4` bytes. Four explicit context-relative memory accesses precede that decrease.

There is no visible normal return, error result, recovery branch, or cleanup path. The unconditional repetition does not guarantee continued execution: an inaccessible address, nonreturning dependency, or breakpoint handler can prevent progress.

**Inferred intent:** the transfers may coordinate several records or machine-state structures. Their application domain and purpose are not established.

## Behavior

### 1. Initial invocations and first-record writes

F-D001 is invoked with two explicit zero arguments. Its target is the incoming link/control value plus `0xFFE`.

F-D002 and F-D003 follow. The routine then reads anchor A and saves its value as the **first-record address**, before invoking F-D004.

F-D005 supplies the first paired result. F-D006 receives two 32-bit arguments:

- The low portion of that result.
- Its high portion plus its low portion, with an additional zero-valued byte term.

The addition is signed-looking; overflow behavior is unresolved.

An additional byte output associated with F-D006 is written at first-record offset `0x11`. F-D007 follows, then a zero byte is written at first-record offset `0x15`.

Both writes use the saved first-record address. Neither reloads anchor A.

F-D008 then supplies a halfword result and an additional address-like register output. The halfword is written at offset `0x0C` from that additional address.

### 2. Second paired result and the first two context accesses

F-D009 supplies the second paired result. The routine:

1. Writes a zero halfword at the result’s high portion plus `0x2C`, treating that portion as an address.
2. Writes the unsigned low portion shifted right by 26 as a word at context offset `0x26C`.
3. Invokes F-D010.
4. Reads a word at context offset `0x320` and saves it as an address.
5. Invokes F-D011 and F-D012.
6. Writes the unsigned low portion shifted left by two at saved-address offset `0x54`.

The first context write contains a value from 0 through 63. The later left shift discards bits above the 32-bit result width.

The context-relative address read occurs after F-D010. F-D011 and F-D012 occur after that address has been captured; their effects do not cause an explicit reload.

### 3. Fixed-address read, third context access, and breakpoint

F-D013 through F-D017 execute in order.

The routine then reads an unsigned halfword from numeric address `0x21C48994`. Its zero-extended value becomes the **narrow base**.

After F-D018, a word is read at context offset `0x280` and passed to F-D019. Its 32-bit result is retained.

Software breakpoint `0x92` occurs next. No post-breakpoint operation is reached unless execution resumes. The representation does not specify the handler, whether it returns, or what state it may alter.

### 4. Narrow-base accesses and address-derived halfword writes

After resumption, the F-D019 result is shifted left by two to form the **first displacement**. This shift is signed-looking and has unresolved overflow semantics.

A second displacement is formed by shifting unsigned constant `0x21C48960` right by 18 and multiplying by four. Its exact value is `0x21C4`.

The following operations occur in order:

1. Read a word at narrow-base offset `0x44`; save it as the **destination-record address**.
2. Invoke F-D020.
3. Invoke F-D021 and retain its word result.
4. Read a word at narrow-base offset `0x04`.
5. Invoke F-D022 with the F-D021 result first and the just-read word second.
6. Read and save anchor B.
7. Invoke F-D023.
8. Write the low 16 bits of saved anchor B at saved anchor B plus the first displacement.
9. Invoke F-D024.
10. Read a word at numeric address `0x2218`; save it as an address.
11. Invoke F-D025 and retain its address-like result.
12. Write halfword `0x21C4` at that result plus `0x04`.
13. Invoke F-D026 and F-D027.

The read at `0x2218` derives from second displacement plus `0x54`.

The narrow base is a zero-extended halfword, not a full-width pointer loaded from the fixed address. It ranges from 0 through 65,535. Its two relative word reads therefore use correspondingly low numeric addresses unless an external address-space interpretation applies.

The anchor-B-derived write uses the same captured value both as an address component and as the source of truncated data. F-D023 is not followed by another anchor-B read.

### 5. Third paired result, fourth context access, and context decrease

An unsigned halfword is read at offset `0x34` from the address saved from `0x2218`. Its zero-extended value becomes the **record index**.

F-D028 supplies the third paired result. The routine then:

1. Writes its low portion as a word at context offset `0x258`.
2. Reads an unsigned halfword at its high portion plus `0x14`; the zero-extended result becomes the **field value**.
3. Forms the low portion shifted left by six.
4. Forms the high portion multiplied by four.
5. Explicitly decreases the context-base value by `0xF4`.
6. Forms the record index multiplied by four, designated the **index displacement**.
7. Writes the third result’s low portion as a word at index displacement plus `0x74`.

The context write at `+0x258` is the fourth and final explicit context-relative memory access in the iteration. It precedes the decrease, as do the earlier write at `+0x26C` and reads at `+0x320` and `+0x280`.

The index-derived write is not context-relative.

The record index is at most 65,535, so its multiplication by four is exact within 32 bits and is at most 262,140. The third result’s left shift by six and high-portion multiplication are signed-looking operations whose overflow semantics remain unresolved.

No explicit context-base restoration appears before repetition. Unknown dependency effects prevent a guarantee about the net machine-state change across an iteration.

### 6. Destination updates and repetition

The remaining operations occur in this order:

1. Invoke F-D029.
2. Write the zero-extended field value as a word at destination-record offset `0x54`.
3. Invoke F-D030.
4. Write the same saved field value as a word at destination-record offset `0x64`.
5. Invoke F-D031.
6. Write the low 16 bits of the destination-record address at the sum of the shifted third-result low portion and an additional address-like output associated with F-D031.
7. Invoke F-D032 and F-D033.

9. Invoke F-D034.

11. Invoke F-D035.
12. Write the multiplied third-result high portion as a word at destination-record offset `0x44`.
13. Invoke F-D036.
14. Assign link/control value `0x08712031`.
15. Read a word at offset `0x44` from the multiplied high portion, treating that quantity as an address base.
16. Invoke F-D037 with the word just read.

The late byte-store address expression includes the unsigned 32-bit field value. At the represented arithmetic level, its addition uses unsigned 32-bit arithmetic. This does not establish that the resulting address is valid.

The final read is not from the destination record merely because the preceding store used destination-record offset `0x44`.

The field-value writes use a captured, zero-extended halfword. The byte write uses the byte captured before F-D034, even if that dependency changes its source memory.

The assigned link/control value makes the next represented first-target calculation `0x0871302F`. Whether this corresponds directly to actual control-register state across F-D037 remains unresolved.

## Acceptance examples

These are conditional static consequences, not executed tests.

1. **Four context accesses:** if execution reaches the context decrease, the explicit context-relative memory accesses have occurred in this order: word write at `+0x26C`, word read at `+0x320`, word read at `+0x280`, and word write at `+0x258`. Each uses the context-base state applicable at that access; the routine’s explicit decrease follows all four.

2. **Store widths:** a complete iteration performs three byte, five halfword, and seven word stores. Both the F-D008-result write and destination-address truncation write are halfword stores.

3. **Unsigned shifts:** if the second paired result’s low portion is `0xFC000003`, the context write at `+0x26C` supplies 63, and the later saved-address write at `+0x54` supplies `0xF000000C`.

4. **Captured anchor:** if anchor A supplies address A and F-D007 changes the global to B, the zero-byte write still targets A plus `0x15`, provided the captured address remains usable.

5. **Address-derived truncation:** if anchor B supplies `0x12345678` and the first displacement is eight, the halfword write targets `0x12345680` and supplies `0x5678`, assuming valid arithmetic and memory access.

6. **Narrow base:** if the fixed-address halfword read supplies `0xFFFF`, the destination-record address is read from numeric address `0x10043`. No unobserved upper pointer bits are added.

7. **Field extension:** if the field halfword is `0xFFFF`, both destination-record field writes supply word `0x0000FFFF`.

8. **Captured byte:** if the read at five times the record index supplies `0xA5`, and F-D034 then changes the source byte to zero, the explicit subsequent byte write still supplies `0xA5`.

9. **Distinct final base:** if the multiplied high portion is `0x1000` and the destination-record address is `0x2000`, the final argument read is from `0x1044`, not `0x2044`.

10. **Breakpoint and repetition:** if the breakpoint does not resume, none of the subsequent explicit operations occurs. If all calls return, accesses succeed, arithmetic is meaningful, and the breakpoint resumes, F-D037 is followed by repetition rather than normal return.
