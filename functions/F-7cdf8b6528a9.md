# F-7cdf8b6528a9

“Big-endian serialization” is a descriptive interpretation of this behavior, not evidence of a particular protocol, file format, or caller purpose.

## Behavior

### Encoding rule

Let the unsigned 32-bit input be \(V\), and number destination offsets from zero.

On normal completion, the four destination bytes are:

| Destination offset | Input bits represented | Byte value |
|---|---|---|
| 0 | 31 through 24 | \(\lfloor V / 2^{24} \rfloor\) |
| 1 | 23 through 16 | \(\lfloor V / 2^{16} \rfloor \bmod 256\) |
| 2 | 15 through 8 | \(\lfloor V / 2^8 \rfloor \bmod 256\) |
| 3 | 7 through 0 | \(V \bmod 256\) |

Each stored byte contains exactly eight bits. Higher-order bits not belonging to that byte are discarded.

The input is treated as unsigned before right shifts. Consequently, extraction does not depend on arithmetic right-shift behavior for negative signed integers. The shift distances are 24, 16, and 8 bits; none reaches or exceeds the 32-bit width.

The function performs no addition or multiplication on the input. There is no input-dependent arithmetic overflow case. All \(2^{32}\) possible input bit patterns have a defined four-byte encoding under the stated width model.

2. Destination offset 1 receives the next byte.
3. Destination offset 2 receives the next byte.
