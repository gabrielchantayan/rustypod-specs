# F-fce65b18a380

## Purpose

F-fce65b18a380 consumes bytes from a caller-held input cursor, skips six specific separator values, and classifies other eligible bytes through an indirectly addressed lookup table. Accepted classifications are four-bit values, packed high half first into caller-provided output storage.

The function updates the caller’s input cursor on completion and returns the number of output bytes touched. An invalid nonseparator stops processing without being consumed. Previously consumed input and output writes are not rolled back.

The established behavior is table-driven nibble packing. Hexadecimal text decoding is inferred intent only: the supplied evidence does not establish the lookup-table contents.

The lookup address is not fixed by this contract. Each eligible nonseparator causes a read of externally stored lookup-base information, followed by a read of the selected table entry through that base. Changes to the base storage can therefore change subsequent classifications within one invocation.

This specification derives from static evidence. No runtime tests have been performed.

## Interface

### Arguments

| Argument | Contract |
|---|---|
| Input-cursor storage | Address of a readable and writable four-byte slot containing the initial input address. Read at entry and written with the stopping address at completion. |
| Exclusive input-end address | Upper bound used in the input-cursor comparison. Ordinary scanning does not read the byte at this address. |
| Output address | Start of writable output storage. No independent output-storage length is supplied. Completing a pair also requires reading the current output byte. |
| Count | Signed 32-bit quantity shifted left by one bit to obtain an unsigned accepted-value limit. Its ordinary, unambiguous range is zero through 1,073,741,823. |

The four-byte cursor slot establishes a 32-bit stored-address representation for this interface. It does not establish a portable interface for environments with wider pointers.

Within the unambiguous count range, the function accepts at most twice the supplied count in four-bit values and touches at most the supplied count in output bytes. Separators do not count toward this limit.

The input-end argument is an address bound, not a separately validated byte length. The function does not establish that the cursor and end belong to the same allocation.

### Return value

The return value is an unsigned 32-bit count of output bytes touched, including an incomplete final pair. Within the ordinary count range, it equals the accepted-value count divided by two, rounded upward:

- Zero accepted values return zero.
- One or two accepted values return one.
- Three or four accepted values return two.

It is not a count of consumed input bytes. Separator consumption can advance the input cursor without increasing the return value.

There is no separate success, invalid-input, capacity-exhaustion, or input-exhaustion status.

### Preconditions

For ordinary, isolated decoding behavior:

- The cursor slot must be readable at entry and writable at completion.
- The cursor and end address must support the comparison and traversal used by the execution environment.
- Each input byte reached before stopping must be readable.
- Each output byte written must be writable.
- An output byte receiving the second value of a pair must also be readable.
- The external lookup-base storage must be readable whenever an eligible nonseparator is classified.
- Each base value read must identify storage from which the selected table entry is readable.
- Output capacity must cover every output byte touched.

The source establishes no argument-validation or recoverable-error convention for invalid memory.

Disjoint input, output, cursor storage, lookup-base storage, and table storage are sufficient to exclude the aliasing interactions described below. Disjointness is a condition for the ordinary examples, not an established requirement enforced by the function.

## Behavior

### Entry and stopping checks

The function initializes an unsigned 32-bit accepted-value counter to zero and reads its working input cursor from the caller’s four-byte cursor slot.

Before each possible input-byte read, it checks:

1. Whether the accepted-value counter remains below the count-derived unsigned limit.
2. If so, whether the working cursor is strictly below the exclusive end address.

The limit check precedes the end-address comparison. Neither check requires reading an input byte.

For a count of zero, the function still reads the initial cursor slot and writes the unchanged cursor back at completion. It performs no input-byte, lookup-base, table-entry, or output-byte access.

If the initial cursor is equal to or greater than the end address under the applicable comparison, no input byte is read.

### Separator handling

Exactly these six byte values are recognized directly as separators:

| Byte | Conventional name |
|---|---|
| 0x00 | NUL |
| 0x09 | Horizontal tab |
| 0x0A | Line feed |
| 0x0C | Form feed |
| 0x0D | Carriage return |
| 0x20 | Space |

A separator advances the working input cursor by one byte. It does not:

- Read the external lookup-base storage.
- Read a table entry.
- Increment the accepted-value count.
- Read or write output.
- Change which half of the next output byte is due.

NUL is therefore skippable input, not a terminator.

The byte 0x0B, conventionally vertical tab, is not a directly recognized separator. Its treatment depends on lookup classification.

### Nonseparator classification

A nonseparator above 0x7F stops processing immediately. The function does not consume that byte, read the lookup base, read a table entry, or produce output for it.

For every other nonseparator, classification has two distinct memory reads:

1. Read the externally stored lookup-base address.
2. Read the one-byte entry at that base plus the input byte’s seven-bit index.

The index is masked to seven bits, but bytes above 0x7F have already been rejected. Such bytes do not wrap into the lower half of a table.

The base is evaluated anew for each eligible nonseparator. Neither the base nor table entries are established as an invocation-wide snapshot. An earlier output write can change a later lookup by modifying the base storage or the table storage.

The entry is loaded as a character value and converted to an unsigned 32-bit candidate. Only candidates from zero through 15 are accepted. Larger candidates stop processing at the current input byte without consuming it.

The evidence does not settle whether the character load is signed or unsigned. The acceptance boundary is nevertheless unchanged: raw entry bytes 0x00 through 0x0F are accepted; raw bytes 0x10 through 0xFF are rejected under either interpretation.

No particular character-to-value mapping is established.

### Output packing

Accepted values are numbered from zero for each invocation. Separators do not affect that numbering.

An even-numbered accepted value starts a new output byte:

- Its value occupies the high four bits.
- The low four bits are zero.
- The complete byte is written immediately.
- The output address remains on that byte.

An odd-numbered accepted value completes the current byte:

- The function reads the byte currently stored at the output address.
- It adds the accepted value to that live byte.
- It writes the resulting character byte.
- The output address advances by one byte.

Each accepted value increments the accepted-value counter and causes an output write. A lone final value therefore already has an output byte; it is not buffered pending another value.

With ordinary disjoint storage and no intervening mutation, the first write leaves the low four bits zero, so the second write produces the expected packed pair. The second operation is nevertheless addition to a fresh memory read, not combination with a privately retained high half. No overflow error is reported if the live output byte has been changed.

### Cursor advancement and completion

After a separator or accepted value, the working input cursor advances by one byte. An invalid nonseparator leaves the cursor at that byte.

Processing ends when the first applicable condition occurs:

- The accepted-value limit has been reached.
- The cursor is no longer below the end address.
- A nonseparator is rejected.

A limit stop occurs before examining the next input byte. Thus, separators following the last permitted value remain unconsumed.

At completion, the function stores the stopping cursor into the caller’s four-byte slot, then returns the rounded-up output-byte count. The cursor slot is not progressively updated during scanning.

### Integer widths and arithmetic

The accepted-value counter and return arithmetic are unsigned 32-bit operations. The count argument is signed 32-bit, and its left-shift result is converted to the unsigned limit.

For counts from zero through 1,073,741,823, doubling is representable as signed 32-bit arithmetic. In this range:

- At most 2,147,483,646 values are accepted.
- The return calculation’s addition of one does not overflow.
- At most the supplied count in output bytes is touched.

Negative counts and larger positive counts fall outside the range in which the supplied signed-shift expression establishes an unambiguous portable result. This contract does not replace that uncertainty with an assumed wrapping-machine interpretation.

The displayed return arithmetic adds one to the unsigned accepted-value counter before shifting right by one bit. Its usual rounded-up interpretation is established for the ordinary count range. Extraordinary-count behavior remains dependent on the unresolved limit calculation.

## Side effects

### Observable memory-access order

The established logical sequence is:

1. Read the initial input address from the cursor slot.
2. Check the accepted-value limit, then the end-address condition.
3. Read the current input byte when both checks permit it.
4. For a recognized separator, bypass classification and output.
5. For a nonseparator above 0x7F, stop without classification.
6. For another nonseparator, read the external lookup-base storage.
7. Read the indexed character through the base just obtained.
8. If classification is accepted, write output; completing a pair first reads the current output byte.
9. Advance the working input cursor after a consumed byte.
10. Repeat until a stopping condition applies.
11. Write the final cursor to the caller’s slot.

This order distinguishes the external base-storage read from the table-entry read. A valid table elsewhere does not eliminate the need for readable base storage when classification occurs.

Even when nothing is consumed, ordinary completion writes the cursor slot.

### Aliasing

No nonaliasing guarantee is established.

- **Output overlapping unread input:** An output write can change a byte that a later iteration reads.
- **Output overlapping table storage:** An output write can change a later candidate value.
- **Output overlapping lookup-base storage:** An output write can modify the address used by a later eligible nonseparator, redirecting subsequent table-entry reads. A partially overwritten base is not validated.
- **Output overlapping cursor storage:** Output can overwrite the caller’s stored cursor during scanning, but this does not replace the already loaded working cursor.
- **Final cursor store overlapping output:** The final four-byte cursor write can overwrite packed output.
- **Final cursor store overlapping lookup-base storage:** The final write can change the externally stored base. That change occurs after this invocation’s classification reads and may affect later use.
- **Final cursor store overlapping table or input storage:** The final write can modify those regions after scanning has stopped.

A lookup’s base is read before its entry, and the entry is read before output is written for that accepted value. An output write that modifies base storage therefore affects subsequent lookups, not the already completed classification for that value.

These consequences are access-order behavior, not guarantees of safe in-place decoding. No synchronization or atomicity contract is established.

### Ownership and lifetime

The function accesses caller-supplied memory and external lookup-related storage. No allocation, deallocation, ownership transfer, or external function invocation appears in the supplied routine.

That absence does not establish who owns the base storage or table, how they are initialized, or whether another component may modify them.

## Dependencies

There are no external function calls in the supplied evidence, so there are no additional opaque function IDs to enumerate.

There are two distinct external data dependencies:

| Dependency | Required behavior |
|---|---|
| Lookup-base storage | Supplies the address used for each eligible nonseparator’s classification. Read separately on each such occurrence. |
| Table entry reached through that base | Supplies a one-byte candidate value at the input-selected offset. Its contents determine acceptance and the packed value. |

Recognized separators and nonseparators above 0x7F bypass both dependencies.

The evidence does not establish the exact declared width of the external base storage, its initialization, a fixed address throughout the call, or bounds covering all possible indices. Validity is required for every base and entry actually read.

The execution environment also supplies address comparison, byte-addressed traversal, and character conversion semantics. Behavior of the signed count shift outside its ordinary range remains unresolved.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless stated otherwise, memory is valid and disjoint, no concurrent mutation occurs, the count is in its ordinary range, and the end address immediately follows the described input.

Let **A**, **B**, and **C** denote distinct eligible nonseparator bytes whose entries through the bases read at their respective classifications are 0xA, 0x3, and 0x5. These labels do not assert mappings for literal letters.

| Scenario | Required result |
|---|---|
| A, then B; count at least one | Write 0xA3, consume both bytes, return one. Each classification separately reads the base and then its entry. |
| A only; count at least one | Write 0xA0, reach the end, return one. |
| A, space, NUL, B; count at least one | Write 0xA3 and consume all four bytes. Space and NUL perform neither base nor entry reads. |
| Only the six recognized separator values; positive count | Consume through the end, leave output untouched, return zero, and perform no lookup-base or entry reads. |
| First byte 0x80; positive count | Leave the cursor on that byte, leave output untouched, return zero, and read neither base nor entry. |
| First eligible nonseparator selects raw entry 0x10 | Read the base and selected entry, reject the byte, leave the cursor there, and return zero. |
| A, B, C; count one | Write 0xA3, stop on C without examining it, and return one. |
| A, B, space; count one | Write 0xA3, leave the trailing space unconsumed, and return one. |
| A followed by an invalid nonseparator | Preserve 0xA0, stop on the invalid byte, and return one. |
| A, B, C followed by an invalid nonseparator; count at least two | Write 0xA3 and 0x50, stop on the invalid byte, and return two. |
| Count zero | Read and rewrite the initial cursor slot; perform no input, base, entry, or output access; return zero. |
| Initial cursor equals the end | Read and rewrite the cursor slot, perform no input or lookup reads, leave output untouched, and return zero. |

Further conditional criteria cover the external base dependency:

- If an output write overlaps base storage and leaves it representing a different valid base, the next eligible nonseparator must be classified through that newly read base. An intervening separator does not read the changed base.
- If the final cursor slot overlaps base storage, completion writes the stopping cursor there. The function does not restore the previous base.
- If base storage is inaccessible but the invocation reaches only separators, a byte above 0x7F, or an immediate limit/end stop, the ordinary path does not read that storage. This does not waive the cursor or input-access requirements.
- For 0x0B, read the base and selected entry. Accept it only if that entry yields a value from zero through 15; otherwise stop on it.

## Evidence

The supplied static routine establishes:

- A four-byte initial cursor load and final cursor store.
- A signed 32-bit count-derived limit and unsigned 32-bit accepted-value accounting.
- Limit checking before the end-address condition.
- Exactly six directly recognized separators.
- Rejection of nonseparator bytes above 0x7F before lookup.
- A separate external base-storage evaluation for every eligible nonseparator.
- An indexed character read through that evaluated base.
- Acceptance only for candidates from zero through 15.
- Immediate high-half-first output writes and live output-byte reads when completing pairs.
- Cursor advancement only for consumed bytes.
- Retention of invalid input as the stopping cursor.
- Rounded-up output-byte reporting within the ordinary arithmetic range.
- No external function calls or explicit memory-management operations.

No table image, external base declaration, caller contract, instruction-level resolution of exceptional shifts, or runtime observations were supplied. The acceptance examples are static consequences of the routine under their stated conditions.
