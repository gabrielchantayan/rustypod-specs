# F-a79fcb30d189

## Purpose

F-a79fcb30d189 implements a nonterminating interaction protocol involving indirect calls, byte-selected writes, and computed 32-bit memory accesses. Returned values influence later addresses, stored data, call arguments, and the state used by the next repetition.

No application-level purpose is established. The evidence does not identify an allocator, decoder, device interface, collection operation, or object constructor. Numeric address patterns alone do not establish valid objects or a particular memory map.

This contract distinguishes:

- **Established static evidence:** represented access widths, ordering, value dependencies, indirect invocations, and repetition.
- **Conditional deductions:** arithmetic consequences under a 32-bit wrapping execution model.
- **documented_only:** unresolved behavior that must not be filled in by assumptions.

No runtime tests have been performed.

There is no represented normal completion, success result, error result, or termination condition. Outputs are the ordered memory effects, dependency interactions, and state carried into subsequent repetitions.

### Width and address model

Explicit data accesses are either one byte or one 32-bit word. A selector read produces an unsigned value from 0 through 255. Some dependency results are represented as 64 bits and consumed through their low and high 32-bit halves.

Arithmetic deductions below assume:

- Values and addresses wrap modulo \(2^{32}\).
- Left shifts discard bits above bit 31.
- Unsigned right shifts insert zeros.
- Byte writes retain only bits 0 through 7.

The representation includes signed arithmetic and signed left shifts. It does not establish original-language overflow semantics or independently prove the machine-level execution model. Wrapping arithmetic is therefore a stated condition, not an assertion about a valid source-language implementation.

The recurring address forms have distinct meanings:

| Access | Address interpretation |
|---|---|
| Selector read | One byte at the relevant base plus 1 |
| Selector-directed write | One byte at 17 plus the selector |
| Indexed word access | Four bytes beginning at 20 plus the specified scaled index |
| Retained-selector word write | Four bytes beginning at 20 plus a previously captured selector |

Selector-directed destinations are absolute numeric addresses from 17 through 272. They do **not** include the base used to obtain the selector. Retained-selector word destinations begin between 20 and 275.

Byte order, address-space interpretation, alignment requirements, and access permissions are **documented_only**. A computed address must not be silently rounded to alignment.

## Behavior

### Protocol boundaries and ordering

Entry performs two indirect invocations before the repeating protocol. The first target is derived from the incoming control-flow address with a displacement of 4094 bytes. The second uses an internal anchor with the same displacement; its consumed 32-bit result provides the first repetition’s opening index.

Each completed repetition begins another without a represented exit test. The dispatch receiving the opening shifted argument has different anchor provenance on entry and on later repetitions. The first repetition uses an initial anchor; completed repetitions install a different, fixed boundary anchor. A single invariant target from initial entry onward is not established.

The following descriptions specify value lifetimes and observable ordering, not permission to collapse the intervening calls:

- An explicitly fresh selector read is a new observation.
- A retained selector or result continues to supply its later use without an implicit reread.
- Equal-address writes remain separate events.
- Intervening invocations remain observable even when their return values are unused.
- A fault or nonreturning invocation prevents obligations that occur later on that execution path.

### Opening publication and first word transfer

The opening selector is read at the incoming selector base plus 1. Its selected destination receives bits 20 through 27 of the opening data value. Although the represented intermediate calculation retains two additional bits, conversion to a byte discards them.

The opening dependency exchange includes these ordered argument relationships:

- The opening argument value shifted left by 12.
- A returned 32-bit response followed by the fourfold opening index shifted left by 28.
- A returned 64-bit value supplied as low half followed by high half.

After intervening invocations, the selector is read again at the same base and its newly selected destination is cleared. This second write is not tied to the first selector value.

A later response is forwarded after multiplication by four. Subsequent interactions produce the **first transfer word**, also four times a returned value. Its primary destination begins at 20 plus 4096 times the fourfold opening index.

The next argument-bearing invocation receives, in order:

1. 1024 times the fourfold opening index.
2. The same value again.
3. The opening index shifted left by 14.
4. The first transfer word.

A later dependency-selected destination receives that same word at its scale-4 address. Four times that destination index is then passed onward. The word is retained across intervening calls rather than recovered from its primary destination.

### Self-derived transfers and persistent addressing

Two consecutive transfers derive their payload from their own primary destination index. For each:

- The primary destination uses scale 16.
- The payload is four times that primary index.
- The next argument-bearing invocation receives three copies of the payload.
- A later scale-4 destination receives the retained payload.
- Four times that later destination index is passed onward.

These are distinct transfers using independently obtained results.

The primary index of the second transfer also determines a **persistent selector base** by multiplication by \(2^{30}\). Under wrapping arithmetic, only its low two bits matter; the possible bases are 0, 0x40000000, 0x80000000, and 0xc0000000.

The second transfer’s scale-4 destination index is retained for another purpose: its parity determines a later word payload.

A subsequent dependency result becomes the **lookup seed**. Before its fourfold value is forwarded, two direct byte clears occur at the persistent base: offset 17 first, then offset 1. These are not selector-directed destinations.

Following additional interactions, including forwarding an unscaled returned response, another index is obtained. The same two direct clears occur again, in the same order, before that index’s fourfold value is forwarded. Calls separate the two clear pairs; their effects cannot be presumed redundant.

### Lookup-dependent transfer and selector updates

A later primary index selects a scale-16 word destination. Its payload is the retained second-transfer destination index shifted left by 31. With wrapping arithmetic, the payload is zero for an even retained index and 0x80000000 for an odd one.

Only after this write does the routine read a lookup word. The lookup address is 20 plus the lookup seed’s low 30 bits shifted right by 20. Consequently, the word begins at an address from 20 through 1043 and may be unaligned. Overlap with the preceding word write can affect the read.

Four times the latest primary index is passed onward. A following result becomes the **saved response**. Another invocation receives the lookup word shifted right by 22 and then left by 28. Under the stated arithmetic model, only lookup-word bits 22 through 25 survive.

A later scale-4 word destination is cleared, after which its fourfold index is forwarded.

Another result becomes the **selector-update value**. It supplies two byte publications:

| Publication | Selector observation | Payload |
|---|---|---|
| First | Read at persistent base plus 1 | Low byte of four times the selector-update value |
| Second | Fresh read at persistent base plus 1 | Bits 20 through 27 of the same retained value |

Between these publications, invocations receive the fourfold selector-update value and, later, an intermediate response followed by the selector-update value shifted left by 30.

The selector used by the second publication is retained. After further invocations, a **word**, not a byte, is written at 20 plus that captured selector. Its payload is four times the saved response. Changes to selector memory after capture do not select a different destination for this word.

### Global snapshot and middle transfer

Immediately after the retained-selector word write, the routine reads one 32-bit global value. The global’s address and meaning are unresolved. If it overlaps the preceding destination, the write precedes the snapshot.

The next argument-bearing invocation receives four times the primary index used for the parity-dependent scale-16 write. Subsequent calls yield a 64-bit result whose low half, multiplied by four, becomes the **middle index**.

Before the high half is passed onward, a fresh selector read at persistent base plus 1 directs a byte write containing bits 22 through 29 of the global snapshot. This publication uses the retained snapshot, not a later global read.

Later interactions include:

- An intermediate response followed by the middle index shifted left by 28.
- A fresh selector-directed byte clear.
- Forwarding four times a returned value.
- Supplying four times another returned value as two equal arguments.

A further returned value, multiplied by four, becomes the **middle transfer word**. Its primary destination begins at 20 plus 4096 times the middle index. The next argument-bearing invocation receives the middle index shifted left by 14.

A later scale-4 destination receives the retained middle transfer word, and four times that destination index is passed onward.

### Closing observations and recurrence

A later 64-bit result supplies the **closing index**, defined as four times its low half. Before its high half is forwarded, a selector is read at 1 plus 16384 times the middle index. The selected byte receives bits 20 through 27 of the middle transfer word.

Further interactions forward an intermediate response and another 64-bit result, the latter as low half followed by high half.

After another destination index is returned, a selector read at 1 plus \(2^{28}\) times the closing index directs a byte clear. Four times the returned destination index is then forwarded.

A later result supplies the **final source value**. The selector base carried into the next repetition becomes four times the closing index. At that base plus 1, a selector is read and its selected byte is cleared.

Subsequent invocations receive the closing index shifted left by 10 and, later, an intermediate response followed by the saved response shifted left by 28. After more interactions, a fresh selector read at the next-repetition base plus 1 directs another byte clear. A subsequently returned index is forwarded after multiplication by four.

The **final transfer word** is the final source value shifted left by 14. Its primary destination begins at 20 plus 4096 times the fourfold final source value. The next argument-bearing invocation receives the fourfold final source value shifted left by 14.

Both opening data roles for the next repetition receive the final transfer word. A later two-argument invocation receives that word shifted left by 28, followed by an additional 32-bit register-derived value. Under wrapping arithmetic, the first argument is necessarily zero; the second argument’s provenance remains unresolved.

After further invocations, a scale-4 destination receives the retained final transfer word. Its fourfold index is passed onward. The closing dependency sequence supplies the next opening index and establishes the later-repetition dispatch anchor.

## Side effects

The explicit effects are byte writes, 32-bit word writes, selector reads, one computed word lookup per completed repetition, one global word snapshot per completed repetition, and indirect invocations.

Memory aliasing is not excluded. In particular:

- A word destination can overlap selector storage or a selected byte destination.
- A selected byte write can affect a later lookup.
- A word write can affect the immediately following global snapshot.
- Separate computed destinations can denote overlapping or identical storage.

Therefore, widening byte writes, aligning word accesses, removing repeated clears, rereading retained values, or reordering accesses across calls can change behavior.

No explicit allocation, release, synchronization, rollback, ownership transfer, or error-reporting operation is established. Dependencies may have such effects, but their contracts are unknown. Numeric arguments must not be interpreted as ownership-bearing pointers without additional evidence.

No atomicity, volatile-access guarantee, thread-safety rule, or concurrency protocol is established. Interrupted execution can leave partial updates.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Arithmetic examples assume 32-bit wrapping behavior.

1. **Absolute selected destination.** A selector of 5 directs a byte write to address 22, regardless of where the selector was read.

2. **Fresh read after calls.** If the opening selector is initially 5 and becomes 9 before the opening clear’s selector read, that clear targets address 26.

3. **Byte truncation.** Opening data 0x3ff00000 produces byte 0xff. Intermediate bits above the low byte are not written.

4. **Persistent-base reduction.** A second self-derived primary index with low two bits equal to 3 produces persistent base 0xc0000000, regardless of its higher bits.

5. **Parity payload.** An even retained second-transfer destination index produces zero in the later parity-dependent word write; an odd index produces 0x80000000.

6. **Unaligned lookup.** Lookup seed 0x00100000 selects a word beginning at address 21. Rounding to address 20 is not equivalent. Successful access remains platform-dependent.

7. **Captured selector.** If the second selector-update observation yields 7, the retained-selector word write begins at address 27 even if a dependency subsequently changes selector memory.

8. **Snapshot retention.** Global snapshot 0x3fc00000 supplies byte 0xff. Later global mutation does not change that retained payload.

9. **Direct-clear ordering.** Each persistent-base clear pair writes offset 17 before offset 1. An intervening dependency mutation can make the second pair observably necessary.

10. **Final transfer arithmetic.** Final source value 1 produces final transfer word 0x00004000 and primary destination 0x00004014.

11. **Different shifts, different outcomes.** That final transfer word shifted left by 28 is zero, while its next-repetition opening argument shifted left by 12 is 0x04000000.

12. **Interrupted protocol.** If a dependency does not return, no later write or subsequent repetition is required on that path.
