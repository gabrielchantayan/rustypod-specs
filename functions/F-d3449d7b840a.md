# F-d3449d7b840a

## Purpose

F-d3449d7b840a scans unsigned candidate positions in ascending order and selects a candidate according to the number of nonzero results previously returned by dependency F-2534ccb803dc.

The requested ordinal is zero-based among candidates for which the dependency returns nonzero. For example, an ordinal of zero selects the first such candidate; an ordinal of one selects the second.

If the scan reaches its current bound without selecting a candidate, the function returns a value read from the bound location. The interface has no separate success flag. Consequently, a returned unsigned value alone does not universally distinguish selection from exhaustion, particularly if the bound can change during dependency calls.

This describes the supplied static representation. No runtime tests have been performed.

## Behavior

### Scan order and bound observations

The initial candidate position is zero. The initial count of earlier nonzero dependency results is also zero.

Before each possible dependency call, the function reads the bound through the state pointer. If that observed bound is less than or equal to the current candidate position, scanning ends.

On this exhaustion path, the supplied representation performs another read of the bound to obtain the return value. Thus, the source-level sequence contains a bound read for the termination decision followed by a bound read for the result. It does not explicitly return a saved copy of the first observation.

For stable ordinary memory, both observations have the same value. If the environment permits the value to differ between them, the representation does not require the returned value to equal the value that caused termination. Exact physical load counts and behavior for concurrent mutation are not established without additional memory-model and compilation information.

If the current candidate position is strictly less than the observed bound, the function calls F-2534ccb803dc with:

1. The original state pointer.
2. The current unsigned candidate position.

Candidate positions are presented in ascending order, starting at zero, with an increment of one after each dependency call that does not select a result.

### Dependency-result classification

The dependency’s signed return value is classified only as zero or nonzero:

- Zero does not qualify the candidate and does not change the qualifying-result counter.
- Any nonzero value qualifies the candidate, including a negative value.

No negative dependency result is interpreted here as a distinct error code. Whether such values represent errors within the dependency is unknown; this function nevertheless treats them as qualifying results.

### Ordinal comparison and counter update

For each qualifying candidate, the function compares the qualifying-result counter’s existing value with the requested ordinal.

The counter is then incremented. This increment occurs even when the comparison identifies the selected candidate.

If the comparison matched, the function stops and returns the current candidate position. It does not perform another bound check before that return.

If the comparison did not match, the function advances to the next candidate. The next iteration reads the bound again rather than using a bound cached before the dependency call.

For a nonnegative requested ordinal and representable counter arithmetic, this selects the qualifying candidate with that zero-based ordinal. Dependency results equal to zero do not consume an ordinal.

### Effects of a changing bound

The bound is not captured once at entry. Changes made by F-2534ccb803dc can affect subsequent iterations.

In particular:

- A reduced bound can end scanning at the next loop check.
- An increased bound can allow additional candidate calls.
- A dependency call that changes the bound and also selects the current candidate causes the current candidate to be returned immediately. The changed bound is not checked before that return.

The condition that admitted a dependency call concerns the bound observed **before** that call. Selection does not establish that the returned position remains below the bound afterward.

### Arithmetic boundaries

The candidate position uses unsigned arithmetic. Under a stable, valid bound read and the declared unsigned comparison, a dependency call is made only for a candidate strictly below a representable bound. Consequently, a call cannot be admitted at the maximum unsigned value.

Advancing from the next-to-maximum candidate can produce the maximum unsigned value. At the following loop check, every representable bound is less than or equal to that candidate, so the function exits rather than advancing again. Ordinary execution therefore does not require candidate wraparound.

The qualifying-result counter is different: it is signed and increments for every nonzero dependency result.

The increment on a selecting call matters at the upper boundary. If the requested ordinal equals the largest representable signed value and that comparison is eventually reached, the same qualifying call also attempts to increment the counter beyond that value. The representation does not justify describing that case as a clean, defined selection under signed arithmetic that forbids overflow.

Negative ordinals cannot match the counter while it progresses normally from zero through nonnegative representable values. Such a request may end through bound exhaustion, but a sufficiently long sequence of qualifying results can instead encounter the unresolved signed-overflow boundary. Negative ordinals must not be assigned a specified wraparound-selection meaning.
