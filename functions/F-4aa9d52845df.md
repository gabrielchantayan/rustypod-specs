# F-4aa9d52845df

## Purpose

F-4aa9d52845df resolves an address through a two-byte offset table, decodes metadata at that address, and writes a result containing the calculated address, decoded values, and four 16-bit quantities.

Established behavior includes address calculations, conditional dependency calls, ordered output writes, signed and unsigned comparisons, and truncation. “Record,” “prefix,” and “header consumption” are descriptive labels, not established format terminology.

The resolved address is a 32-bit calculation from a backing-region base and a table-derived displacement. The function does not establish the backing allocation’s extent or verify that the calculated address belongs to it. Address validity and allocation membership are separate preconditions, not consequences of the calculation.

The prefix value written early to the output is a snapshot. A dependency can receive the prefix temporary’s address; if that address is retained and used during a later call, subsequent accumulation can use a different value.

This contract is based on static evidence only. No runtime tests have been performed.

## Interface

### Return, ownership, and preconditions

There is no defined return value or explicit error result.

The function directly performs no allocation or release. The value written at output offset 0 is the backing-region base plus the table-derived displacement, calculated in the observed 32-bit address representation. No record copy or ownership transfer is established.

That calculated address is **not guaranteed to point within the backing allocation**. No allocation extent, membership check, or address-validity check is supplied. A nonnegative displacement alone does not establish membership, and 32-bit address addition can wrap.

Execution requires readable storage for the descriptor, both table bytes, the record bytes actually examined, and conditionally the secondary object. It also requires writable output storage through offset 31 and whatever additional storage dependencies access. These requirements are not checked by the function.

Ordinary predictions below assume valid, stable, nonoverlapping storage unless stated otherwise. Nonoverlap is not enforced. Earlier output writes can affect later input reads when storage overlaps.

Dependencies receive addresses of temporary storage. The evidence does not establish that those addresses are used only during the receiving call. Retention can affect later calls within the same invocation; safe post-return use is not established.

## Behavior

### Address resolution and initialization

The function reads the unsigned halfword at descriptor offset 14 and combines it with twice the record index using 32-bit arithmetic. It also reads the backing-region base at descriptor offset 68.

At the base plus the calculated table position, it reads two adjacent bytes. The unsigned displacement is the first byte multiplied by 256 plus the second byte. The relative evaluation order of those two reads is not separately established.

The record address is the backing-region base plus that displacement. This calculated address is written to output offset 0 before metadata decoding.

Neither the table position nor the resulting record address is bounds-checked. A successful address calculation or output write does not prove that later record reads are valid.

The function then reads the unsigned initial cursor at descriptor offset 9. Before prefix decoding, it initializes:

- The prefix temporary with the table-derived displacement.
- A separate second-decoding temporary with the output-address bit pattern.

### Prefix decoding and snapshot

The function examines descriptor offset 7.

If it is zero, the prefix temporary becomes zero. The cursor does not advance, and no prefix byte is read.

If it is nonzero, the function examines the byte at the calculated record address plus the cursor:

- If the tested byte is below 128, it reads that position again for the prefix value and advances the cursor by one.
- Otherwise, it calls F-887200f76f20 with that position and the address of the prefix temporary. The returned 32-bit quantity is added to the cursor as consumption.

The direct-byte case contains a test read followed by a value read. With stable ordinary memory, both observe the same byte. Equivalence under changing or specially behaving memory is not established.

The helper path has no successful-write check. If F-887200f76f20 leaves the temporary unchanged, the table-derived displacement remains its value.

The current prefix temporary is then written to output offset 16. This is a snapshot, not a guarantee that the temporary will retain that value.

### Second decoding stage

Descriptor offset 3 is read after the prefix snapshot write.

#### Zero mode: single-value decoding

The function examines the byte at the current record position:

- If the tested byte is below 128, it reads the position again into the second-decoding temporary and assigns consumption of one.
- Otherwise, F-887200f76f20 receives the current position and the address of that temporary. Its return supplies consumption.

The temporary was initialized with the output address before prefix decoding. No check verifies that the helper replaces it. If its initialization survives the intervening calls and the helper leaves it unchanged, those address bits become the decoded value.

The function writes the current decoded value to output offset 8, then writes zero to offset 12.

It then adds the decoded value to the **then-current prefix temporary**, with 32-bit wraparound. This produces the accumulated value.

If prefix decoding previously exposed the prefix temporary’s address, the second helper may change it through a retained address. Accumulation therefore need not equal the earlier offset-16 snapshot plus the decoded value.

#### Nonzero mode: delegated decoding

F-174052de586c receives the current record position and the output address plus 8. Its returned 32-bit quantity supplies consumption.

The caller makes no direct writes to output offsets 8 or 12 on this path. It does not read those fields into its accumulation.

After the call, the accumulated value is the current prefix temporary. If an earlier prefix helper retained that temporary’s address, the delegated call may change it. Equality with the offset-16 snapshot is conditional on preservation.

### Common completion

The function writes the accumulated value to output offset 20.

It adds second-stage consumption to the current cursor using 32-bit arithmetic. This full sum includes the initial cursor and any prefix consumption. Its low 16 bits are written to output offset 24 and retained for later calculations.

Consumption values are not checked for zero, negative interpretations, excessive magnitude, or consistency with accessed bytes.

### Threshold selection

After writing output offset 24, the function reads the unsigned threshold at descriptor offset 10. It compares the accumulated value with that zero-extended threshold as unsigned 32-bit quantities.

#### Accumulated value at or below the threshold

The accumulated value’s low 16 bits are written to output offset 26.

The function adds the accumulated value to the full, untruncated header-consumption sum using 32-bit arithmetic. It interprets the resulting bit pattern as signed:

- A signed result below 4 is replaced with 4.
- Otherwise, the result is retained.

It writes zero to output offset 28, then writes the selected result’s low 16 bits to offset 30.

The minimum comparison precedes truncation. It does not guarantee that the stored final halfword is at least four. A retained positive result can truncate below four; a result with its sign bit set is replaced with four.

#### Accumulated value above the threshold

The function reads the unsigned adjustment at descriptor offset 12. It also obtains the secondary-object address from offset 64 and reads that object’s unsigned halfword at offset 30.

- The accumulated value minus the adjustment, using 32-bit arithmetic.
- The secondary halfword minus four.

The second argument has a mathematical range of −4 through 65,531, represented in the observed word width. Its interpretation by the dependency is unknown.

The caller uses a 32-bit result observed in a secondary result register. It adds the previously read adjustment with 32-bit wraparound, producing a candidate interpreted as signed.

If the candidate is greater than the zero-extended threshold under signed comparison, output offset 26 receives the adjustment. Otherwise, it receives the candidate’s low 16 bits. A negative candidate takes the latter alternative; there is no lower-bound check.

## Side effects

The direct output-write order is:

1. Calculated record address at offset 0.
2. Prefix snapshot at offset 16.
3. In zero mode only, decoded value at offset 8, then zero at offset 12.
4. Accumulated value at offset 20.
5. Header-consumption halfword at offset 24.
6. Effective-value halfword at offset 26.
7. Intermediate quantity or zero at offset 28.
8. Final halfword at offset 30.

Dependencies execute between these writes. Their writes may affect output, shared state, or previously exposed temporary storage.

The descriptor is not captured as an immutable snapshot:

- Initial cursor and prefix mode are read after the record-address write.
- Second-stage mode is read after prefix decoding and its snapshot write.
- Threshold is read after the header-consumption write.
- Adjustment, secondary-object address, and secondary halfword are read only on the above-threshold path.

Changes before these reads can affect behavior. The backing-region base and calculated record address are captured earlier rather than reloaded for later decoding.

There is no visible rollback, retry, error translation, or failure marker. Invalid table or record addresses, faults, or dependency failures can leave partial output. In particular, offset 0 can already contain an invalid or out-of-allocation address before a later record access fails.
