# F-2277b3f29f2d

## Purpose

F-2277b3f29f2d has an established visible prefix consisting of two global assignments followed by a computed-address, 16-bit memory write. The supplied representation then ends at an explicitly reported invalid-instruction boundary.

This contract describes that prefix and its limits. It does not establish that the function returns normally, that the final instruction boundary represents an intentional halt, or that the supplied representation captures all executable behavior.

The apparent intent is to initialize or modify low-level state before reaching an exceptional or undecodable execution boundary. That interpretation is inferred, not an established functional purpose. In particular, symbolic names in the supplied material do not establish a reset operation, an exception-handler installation, or a hardware protocol.

## Behavior

### Established visible sequence

The supplied representation establishes the following order:

1. Assign zero to global destination A.
2. Assign the third explicit argument to global destination B.
3. Calculate an address and a 16-bit payload from the implicit 32-bit word, then write the payload at that address.
4. Reach the boundary reported as invalid instruction data.

This is the represented execution order. It is not a guarantee about cross-core observation, device ordering, atomicity, or memory barriers.

The supplied material contains no explicit conditional branch, loop, validation, or recovery path before that boundary.

### First global assignment

The first represented operation assigns zero to global destination A.

The storage width is not supplied. Consequently, this contract does not assert that the operation clears exactly four bytes, an entire object, or every overlapping symbol. It also does not assert that the destination is ordinary writable RAM.

If the access faults or otherwise prevents continued execution, the later operations are not established to occur. There is no visible error handling around this assignment.

### Second global assignment

The next represented operation assigns the third 32-bit argument to global destination B.

The input value is established as 32 bits, but the destination type and write width are not. A full-width four-byte store cannot be asserted from the available evidence alone. The intended assigned value is the third argument; the precise stored byte representation remains dependent on the destination’s actual type and platform representation.

This operation follows the assignment to global destination A. If the destinations overlap, the second assignment may modify bytes affected by the first. Their names do not establish that they are independent storage objects.

### Computed address

The computed address depends only on the top ten bits of the implicit 32-bit word:

- Shift the unsigned word right by 22 bit positions.
- Multiply the resulting value by 256.
- Interpret that result as the destination address for the 16-bit write.

The right shift is logical because the represented input is unsigned.

The arithmetic bounds are:

| Quantity | Minimum | Maximum |
|---|---:|---:|
| Value after shifting | 0 | 1,023 |
| Computed byte address | `0x00000000` | `0x0003FF00` |

The multiplication cannot overflow a 32-bit unsigned value. Every resulting address is a multiple of 256, so every destination satisfies at least two-byte alignment numerically.

The calculation contains no base-address addition. The destination is the calculated numeric address itself. It is not established to be relative to an array, a supplied pointer, or an allocated object.

An address of zero is possible and is not rejected by the visible prefix. Whether zero or any other computed address is accessible is an environmental precondition, not something the function checks.

### Computed payload

The payload is the low 16 bits of the same implicit 32-bit word, represented as a 16-bit quantity for storage.

This gives the implicit word three distinct roles by bit range:

- Bits 31 through 22 select the destination.
- Bits 15 through 0 supply the stored payload.
- Bits 21 through 16 affect neither the destination nor the payload.

The destination is treated as a pointer to a short-sized object, and the represented operation is a 16-bit store. Endianness is not supplied, so this contract specifies the halfword value rather than the order of its two bytes.

The signed interpretation of a payload with bit 15 set does not change the intended low-16-bit pattern. Exact language-level conversion rules and target-language portability are outside the established evidence.

### Terminal boundary

After the computed write, the representation reports invalid instruction data and truncates the remaining control flow.

The terminal marker does not establish a normal return, an intentional infinite loop, a particular processor exception, process termination, or a callable error handler. It also does not establish that no further machine instructions execute.

The behavioral contract ends at that boundary. Any subsequent behavior is documented_only until additional evidence establishes it.

| 1 | Global destination A | Zero | Unknown |
| 2 | Global destination B | Third explicit argument | Unknown; source argument is 32 bits |

No explicit read of either global destination’s previous contents is visible. The implicit machine-register value is consumed by the address and payload calculations.

The supplied material warns that global symbols overlap smaller symbols at the same addresses. Therefore, a global write may affect storage exposed under another symbol. The warning does not identify which objects overlap or prove that global destinations A and B overlap each other.
