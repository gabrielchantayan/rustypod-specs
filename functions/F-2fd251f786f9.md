# F-2fd251f786f9

## Purpose

F-2fd251f786f9 prepares object-associated state, examines a status word, and conditionally inserts an embedded record into a linked chain. Executions that pass the status check finish with a dependency call and a conditional indirect continuation.

The established contract concerns memory accesses, dependency calls, branch conditions, and their order. A timer-registration or delayed-work role is **inferred intent**, not established behavior. The evidence does not establish time units, an ordering relation for the chain predicate, or the continuation’s purpose.

A zero status permits further processing; it does not prove that the embedded record is absent from the chain. No membership check prevents reinserting an already-linked record or creating a self-link.

## Behavior

### Preparation before the status check

The following operations occur in order:

1. Read the designated source word and copy it to the designated destination word.
2. Invoke F-bd1d23e27781 with the object base.
3. Read the object word at `0x148`.
4. Invoke F-6904f7699031 with the embedded-record address, that word, the third and fourth explicit inputs, and the represented execution-context values.
5. Invoke F-936a8728139d without explicit arguments.
6. Write the designated external word to object offset `0x13C`.
7. Read object offset `0x138`.

If the status read is nonzero, return immediately. The remaining dependencies, quantity processing, traversal, insertion, and common tail are not reached.

This is a post-preparation status check, not an entry guard. The initial copy, three calls, and `0x13C` write already occurred. The checked status may reflect dependency mutations or aliasing effects rather than its entry-time value.

### Processing after a zero status

If the status read is zero:

1. Invoke F-338d16f9ce72 with its designated external argument.
2. Invoke F-add44d4e9aaa with the embedded-record address.
3. Read the signed 32-bit quantity at object offset `0x120`.

The quantity is read after both dependencies. Its value on entry is not decisive if intervening effects change it.

If the quantity is zero, skip the calculation, traversal, and insertion phases. Continue directly to the common tail.

### Calculation for a nonzero quantity

Every nonzero quantity, including a negative quantity, takes this path:

1. Invoke an unmapped dependency with no explicit arguments; use its integer result.
2. Obtain the designated chain-head-word address.
3. Write the integer result plus the retained quantity multiplied by decimal `1000` to object offset `0x124`.
4. Write the designated external word to object offset `0x134`.
5. Read the chain head through the previously obtained head-word address.

The quantity used in the calculation is the value read before the integer-producing dependency. A later change to `0x120` does not replace that retained operand.

The calculation uses a signed 32-bit quantity, integer multiplication and addition, and a 32-bit destination. Where both arithmetic operations are representable in signed 32 bits, the stored result is their exact mathematical result. Overflow behavior outside that range is **documented_only**. A modular wraparound rule is not established by the supplied representation.

The head-word address is obtained before the `0x124` and `0x134` writes, but its contents are read afterward. If the head word aliases a written location, traversal starts from the contents present after those writes, not from an earlier head snapshot.

### Traversal

Traversal starts at the head just read, with no predecessor.

For each non-null current entry, invoke F-0d70d6f9010c with:

- The current entry’s address plus eight bytes.
- The address of object offset `0x124`.
- The third and fourth explicit inputs.
- The represented execution-context value.

A nonzero predicate result stops traversal at that entry. Only zero versus nonzero matters; a negative nonzero result also stops traversal.

After a zero result, read the current entry’s successor word, retain the current entry as predecessor, and continue from that successor. Thus the successor read occurs **after** the predicate call and can observe mutations made by it.

Reaching a null entry stops traversal without invoking the predicate for null. An empty chain therefore produces no predicate calls.

The predicate receives an address into the object, not a copied calculated value. Later predicate calls may observe changes to that field made by earlier calls.

No ordering relation is established. A finite chain with all-zero predicate results is traversed to its end. A cycle may prevent termination if the predicate continues returning zero. Dependency mutation can also change the traversal route or whether it terminates.

### Ordered insertion writes

When traversal stops, insertion performs these writes in order:

1. If no predecessor was retained, write the embedded-record address to the selected chain-head word. Otherwise, write that address to the retained predecessor’s first word.
2. Write the 32-bit value `1` to object offset `0x138`.
3. Write the stopped-at entry address to the embedded record’s first word at object offset `0x11C`.

If traversal stopped at null, the third write stores a null successor.

The record is published through the head or predecessor link before its status and successor writes complete. No atomic insertion, synchronization, or observer-safe publication guarantee follows from this sequence.

There is no second status check and no check that the record is absent from the chain. If the initial head equals the embedded-record address and the first predicate result is nonzero, the stopped-at address is that same embedded-record address. The final write then makes the record its own successor, potentially replacing its previous successor.

More generally, aliasing can make later writes affect locations also serving other roles. Ordinary claims such as “the old head is unchanged” are valid only with explicit non-aliasing conditions.

### Common tail and continuation

Both the zero-quantity path and a completed insertion reach this sequence:

1. Invoke F-5bcae2eff9a7 with its designated external argument.
2. Read a pointer through the designated dispatch-root location.
3. If that pointer is non-null, read its first signed 32-bit word.
4. If the pointer and the word read are both nonzero, invoke the designated indirect continuation without explicit arguments.
5. Return normally if control returns.

The dispatch-root access occurs after F-5bcae2eff9a7. It is not established as using a cached entry-time root or preserving the earlier argument supplied to F-338d16f9ce72.

A null pointer prevents the pointed-to read. A non-null pointer whose first word is zero prevents the continuation. Any nonzero first word satisfies the visible condition, including a negative value.

The pointed-to word is a condition, not the continuation address. The continuation target comes from a separate binding.

## Side effects

### Direct writes

The routine directly performs:

- The initial external word copy.
- The write to object offset `0x13C` before the early-return check.
- On a nonzero quantity, the writes to `0x124` and `0x134`.
- On insertion, the head-or-predecessor write, status write, and embedded-successor write.

For a zero quantity, the routine does not directly perform the calculation or insertion writes. Dependencies may nevertheless modify the same storage.

These are descriptions of access locations and conditions, not guarantees that all named locations are distinct. Aliasing may cause one role’s write to alter another role’s contents.

Continued access through the chain requires the embedded storage to remain valid, but the supplied evidence provides no lifetime-management mechanism.

## Acceptance examples

These are conditional static examples, not executed tests. Assume valid storage, normally returning dependencies, and representable arithmetic. Where an example specifies ordinary distinct storage, assume that its object fields, external words, and separate chain entries do not overlap, and that dependencies do not mutate the stated scenario.

1. **Nonzero status after preparation.**  
   If the status read yields `2`, the initial copy, first three calls, and `0x13C` write have already occurred. F-338d16f9ce72 and the common tail are not reached.

2. **Zero quantity.**  
   If the status read is zero and the quantity read after F-add44d4e9aaa is zero, there is no integer-producing call, traversal, or insertion. F-5bcae2eff9a7 and dispatch inspection still occur.

3. **Empty-chain insertion.**  
   With ordinary distinct storage, quantity `3`, integer-producing result `400`, and a null head, `0x124` receives `3400`. No predicate call occurs. The head receives the embedded-record address, status receives `1`, and the embedded successor receives null, in that order.

4. **Insertion before a distinct head.**  
   With ordinary distinct storage and an old head different from the embedded record, a nonzero first predicate result stops at that head. The head word is redirected to the embedded record; status is written next; the embedded successor is then set to the old head. The old head’s own successor word is not directly written under these non-aliasing conditions.

5. **Head already equals the embedded record.**  
   A zero status does not exclude this case. If the head read equals the embedded-record address and the first predicate result is nonzero, traversal stops there. The routine writes that same record address to the head, writes status `1`, and writes the record address into its own successor word. A previous different successor is replaced by a self-link.

6. **Insertion between distinct entries.**  
   With ordinary distinct storage, a zero result for the first entry and nonzero result for the second redirect the first entry’s successor to the embedded record. After the status write, the embedded successor is set to the second entry.

7. **Append to a finite distinct chain.**  
   If all predicate results are zero and traversal reaches null, the last visited entry becomes the predecessor. Its successor is redirected to the embedded record, status is written, and the embedded successor is written null.

8. **Negative quantity.**  
   Quantity `-2` and integer-producing result `5000` produce `3000`. Negativity alone does not suppress insertion.

9. **Mutation-sensitive traversal.**  
   If a predicate changes the current entry’s successor and returns zero, the subsequent successor read observes the then-current word. Traversal is not required to follow the previous link.

10. **Conditional continuation.**  
    After the tail dependency, a null dispatch pointer causes no pointed-to read. A non-null pointer with first word zero causes no continuation. A non-null pointer with a nonzero first word causes the indirect call.
