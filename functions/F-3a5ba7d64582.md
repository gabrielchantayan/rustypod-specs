# F-3a5ba7d64582

## Purpose

F-3a5ba7d64582 captures selected fields of a mutable object, obtains a provider, and calls a dependency that receives the address of the object’s active-state byte. A subsequent read of that byte selects one of two paths:

- Zero selects direct field reset, followed conditionally by notification processing.
- Nonzero selects provider-based field refresh, ending in a transfer represented as non-returning rather than an ordinary return.

“Synchronization,” “notification,” and “delay” describe inferred roles. The supplied body establishes field accesses, calls, branches, and ordering, not an application-level protocol.

Notification processing can observe values different from those directly written by the reset. Dependencies run before the later reads, and their mutation effects are unknown. In particular, notification processing for an active object is reachable if an intervening dependency changes the active byte after the reset.

## Interface

### Arguments and result

The interface has two 32-bit arguments:

1. An address identifying mutable object storage.
2. A request value distinguished only as zero or nonzero.

The ordinary result is a 32-bit value:

- Zero when no submission replaces the initial result and no mode rejection occurs.
- Eleven when the reset path observes a signed mode value of at least three.
- Otherwise, the result of the most recent completed notification submission.

Submission results replace one another. They are not combined, and a nonzero submission result does not itself prevent later stages.

Explicit failure paths transfer to F-a817d8d58c10, represented as non-returning. The provider-refresh path can transfer to F-feee9156a257, also represented as non-returning. Neither establishes an ordinary error return.

## Behavior

### Entry capture and initial calls

Before dependency calls, the function captures object fields in this order:

1. Primary numeric field.
2. Active byte.
3. Secondary numeric field.
4. Delayed numeric field.
5. First flag.
6. Second flag.

It establishes an initial result of zero and a separate zero-valued 32-bit helper-output cell.

F-b7af80e829ec supplies a provider pointer. A null pointer selects F-a817d8d58c10 without calling the next helper.

For a nonnull provider, F-d266e8cfbbe8 receives the object address, helper-output address, and active-byte address. A nonzero result selects F-a817d8d58c10. After a zero result, the active byte is read again. The helper-output cell is not subsequently inspected by this function.

### Reset and notification eligibility

A zero active-byte read selects these direct writes, in order:

1. Primary becomes `0xFFFFFFFF`.
2. Secondary becomes `0xFFFFFFFF`.
3. Delayed becomes `0xFFFFFFFF`.
4. First flag becomes zero.
5. Second flag becomes zero.
6. Pending marker becomes zero.

The saved timing words are not directly cleared, and the active byte is not directly changed.

The function captures a global context pointer and reads a signed 32-bit mode at offset `+0x2C` through that pointer.

- Mode at least three produces result eleven.
- Mode below three with a zero request produces result zero.
- Mode below three with a nonzero request permits context acquisition.

Negative modes satisfy the “below three” condition; no lower bound is checked.

Context acquisition first calls F-unknown-01. F-b37968c9f644 then receives that result plus four and a fresh 32-bit mode read through the previously captured context pointer. The second mode read need not equal the threshold observation. Replacing the global context pointer during F-unknown-01 does not, by itself, replace the retained pointer used for this reread.

The result of F-b37968c9f644 is retained as the construction context. No explicit null check is established for it. The active byte is then reread.

### Inactive notification branch

If this later active-byte read is zero:

- An entry active byte of zero produces an immediate ordinary return of zero.
- A nonzero entry active byte causes a zero tag-byte write, followed by one-byte construction and submission.

Numeric and flag stages do not execute on this branch.

### Active notification branch

A nonzero active-byte reread selects the stages below, in order. Each stage reads fields when reached. There is no coherent post-reset snapshot and no further active-byte gate among these stages.

#### Primary stage

The current primary field is compared with its entry value. Equality skips the stage.

On a difference, another primary read is checked against `0xFFFFFFFF`. That value selects F-a817d8d58c10. Otherwise:

- Tag one is written.
- F-b9d9c0b9bfab receives the address immediately following the tag and another 32-bit primary-field read.
- Five-byte construction is requested from the tag address.
- A successful construction is submitted.

The comparison, special-value check, and helper argument are separate reads; equality among their observations is not guaranteed.

After submission returns, the delayed field is read. Its 32-bit bitwise complement replaces the delayed comparison baseline. Before this replacement, the baseline is the entry delayed value. Submission-side mutation can therefore affect the replacement baseline.

#### Delayed stage

The delayed stage is entered only if a delayed-field read is not `0xFFFFFFFF` and a separate read differs from the current delayed baseline. The pending marker is then read.

With a zero pending marker:

1. F-abdfc193d880 receives the address of temporary storage.
2. Dispatch through the first 32-bit word of that storage, at table offset `+0x0C`, invokes F-unknown-07 with the temporary-storage address and the object’s saved-pair address.
3. The pending marker is written to one.
4. The delayed field is overwritten with the comparison baseline.
5. F-ec22bd8215d3 receives the same temporary-storage address.

These calls do not independently establish initialization, finalization, destruction, or resource cleanup. The writes made by F-unknown-07 through the saved-pair address are unknown. No delayed notification is constructed on this branch.

With a nonzero pending marker:

1. F-abdfc193d880 receives another temporary-storage address.
2. A global adjustment is read into a signed 32-bit captured value.
3. F-unknown-07 is dispatched through that temporary storage and receives local pair-result storage.
4. The saved unsigned first word is read.
5. The saved signed second word is read and added to the captured adjustment.
6. A loop adjusts the local comparison pair.

The type of the global supplying the adjustment is not declared in the excerpt; the captured value used afterward is signed 32-bit. The initial second-word addition uses signed 32-bit operands. Behavior outside their representable sum is not established.

The loop’s operation ordering is established:

- The unsigned 32-bit first word is incremented before every condition evaluation, including the exiting evaluation. This increment wraps modulo \(2^{32}\).
- The condition reads a separate global step and right-shifts that value by one.
- It subtracts the shifted value from the captured adjustment and compares the result with the signed second-word accumulator using “less than or equal.”
- If the condition is true, the accumulator is updated by adding a fresh read of the step and assigning the result back to the signed 32-bit accumulator.
- The condition read and update read are distinct.

The step global’s type is absent. Consequently, the shift’s type and signedness, subtraction conversions, comparison conversions, update arithmetic, and conversion back to the accumulator are not fully determined.

**Conditional signed interpretation:** if the step is signed 32-bit, the relevant operations remain signed, the shift has the assumed semantics, and no signed arithmetic overflows, continuation means that the captured adjustment minus the shifted step is less than or equal to the signed accumulator. This mathematical interpretation is conditional, not an unconditional timing rule.

After loop exit, the current pair supplied through local result storage is compared with the adjusted pair. The function takes the no-notification branch when:

- The current unsigned first word is smaller; or
- The first words are equal and the current signed second word is less than or equal to the adjusted signed second word.

That branch writes the delayed baseline back to the delayed field without directly clearing the pending marker or saved pair.

Otherwise, tag five is written, F-b9d9c0b9bfab receives the following address and a fresh delayed-field value, and five-byte construction and submission are attempted. After submission returns, direct clearing occurs in this order:

1. Pending marker.
2. Saved first timing word.
3. Saved second timing word.

After either completed branch, F-ec22bd8215d3 receives the temporary-storage address. Construction failure transfers to F-a817d8d58c10 before that later call. No cleanup guarantee follows from either placement.

#### Secondary stage

A secondary-field read differing from the entry value causes:

- F-b9d9c0b9bfab to receive the following address and a fresh secondary-field read.

There is no explicit rejection of `0xFFFFFFFF`.

#### Flag stages

If the current first flag is zero and its entry value was nonzero, tag two is written and one-byte construction and submission are attempted.

Next, a nonzero current second flag returns the accumulated result. If the current second flag is zero but its entry value was also zero, the result is likewise returned. Otherwise, tag three is written, one-byte construction and submission are attempted, and the resulting value is returned.

These stages recognize observed nonzero-to-zero transitions only. Rising transitions do not trigger them.
