# F-a92212b36fcf

## Purpose

F-a92212b36fcf invokes a preparation dependency, computes a source address from a source-view record and a descriptor, and selects one of three behaviors:

- Transfer pairs of 32-bit words into destination records spaced 16 bytes apart.
- Narrow consecutive 32-bit source words into consecutive 16-bit destination elements.
- Delegate the transfer to F-ae01a3c327d3.

The direct paths are layout conversions, not general contiguous byte copies. The paired-word path normally leaves eight-byte gaps between written pairs. The narrowing path retains the low 16 bits of each source word.

These layout descriptions require that transfer writes do not overwrite the function’s exposed local pointer slot or other live local state. The preparation dependency receives the slot’s address, and its unknown contract does not exclude returning a destination that aliases it. Without a non-aliasing condition, the explicit operation order remains established, but fixed destination progressions and final local-state values are not generally established.

## Behavior

### Preparation and subsequent reads

F-918901543e8e is invoked before source calculation or branch selection, with:

1. A.
2. The byte at C + 20.
3. The address of the local pointer slot initially containing C.

The eight-bit payload of the second argument is established. Its exact widened value when the high bit is set is not: character signedness and the dependency’s parameter declaration are not supplied.

No dependency return value is explicitly used. Subsequent behavior uses the pointer slot’s contents.

Preparation occurs even when a later direct-path loop count is zero. The function does not establish that preparation preserves the descriptor, source-view record, globals, or other reachable state. Fields read afterward therefore reflect whatever values exist after that call.

### Source-address calculation

After preparation returns, the function calculates a source address S corresponding to:

\[
I=(\text{32-bit position at }C+4-D)-\text{32-bit origin at }B+0
\]

\[
S=\text{address-valued base at }B+12+4I
\]

The factor of four makes the index a count of 32-bit source words.

The contributing record fields are read after preparation and before branch selection. The supplied representation does not establish a total order among independent operand reads within this calculation.

The calculation uses 32-bit integer fields. There are no explicit checks for negative indices, overflow, invalid addresses, or insufficient storage. The equations describe the relationship for representable arithmetic and valid addresses; they do not establish portable wraparound behavior for signed overflow or exceptional address calculations.

### Branch selection

After calculating S, the function reads the descriptor byte at offset 0.

| Descriptor mode | Additional comparison | Selected behavior |
|---|---|---|
| Zero | Byte at E + 5 equals exactly 1 | Paired-word transfer |
| Zero | Byte at E + 5 differs from 1 | Delegated transfer |
| Nonzero | Byte at C + 21 equals exactly 1 | Narrowing transfer |

The comparisons with 1 are exact, not general truth-value checks.

The nonzero-mode branch does not directly read E. The zero-mode branch does not read C + 21 for branch selection.

### Paired-word transfer: setup and operation order

This path first adds the 32-bit displacement at C + 12, in bytes, to the exposed pointer slot and stores the resulting pointer back into that slot. It then reads the unsigned 32-bit quantity at C + 16 and shifts it right by three to initialize the loop count.

The slot update precedes the quantity read. If the exposed slot overlaps descriptor storage, this ordering can affect the quantity subsequently obtained.

For each entered iteration, the established sequence is:

1. Capture the address of the second source word, four bytes beyond the current source position.
2. Capture the second destination address, four bytes beyond the current value of the exposed pointer slot.
3. Read the first 32-bit source word and write it through the current destination pointer.
4. Advance the source cursor by eight bytes.
5. Advance the exposed pointer slot by sixteen bytes.
6. Read the second 32-bit source word through the previously captured source address and write it through the previously captured destination address.
7. Decrement the loop counter and continue if it remains nonzero.

The second source word is read after the first destination write and after the exposed pointer-slot advance. It is not established to have been prefetched.

The second destination address is captured before the first write. Thus, the second write does not ordinarily use the newly advanced slot. However, unrestricted writes into live local storage could corrupt the stored captured addresses themselves; their survival is not guaranteed for every admitted alias.

The slot advance is an intervening state change, not merely an end-of-iteration bookkeeping description. If the first destination write overwrites the slot, the subsequent advance cannot generally be modeled as adding sixteen to its pre-write value.

### Paired-word transfer: conditional fixed-layout description

Assume that transfer writes do not alias the exposed pointer slot or any other live local state, and that no external agent changes that state during execution. Let:

\[
T=P+\text{byte displacement at }C+12
\]

\[
N=\text{unsigned quantity read at }C+16\mathbin{\gg}3
\]

For iteration \(j\), starting at zero:

- The word at \(S+8j\) is written to \(T+16j\).
- The word at \(S+8j+4\) is then written to \(T+16j+4\), with the pointer-slot advance occurring between the two transfers.

Under these assumptions:

- Exactly N iterations occur.
- The path performs \(8N\) bytes of source reads and \(8N\) bytes of destination writes.
- Each 16-byte destination record receives writes only in its first eight bytes.
- For positive N, the final written byte is at offset \(16N-9\) from T.
- The exposed pointer slot finishes at \(T+16N\).

These formulas specify addresses and access widths, not snapshot-copy values. Source/destination overlap can change later source values.

A quantity below eight produces no loop iterations. Preparation, source calculation, selection, displacement handling, and the quantity read still occur. In particular, the paired-word path updates the exposed slot to the displaced address even when its loop count is zero.

### Narrowing transfer

This path computes a separate destination cursor by adding the byte displacement at C + 12 to the pointer slot’s value. It does not explicitly assign the displaced address back into the exposed slot.

It then reads the unsigned quantity at C + 16 and shifts it right by one.

Assuming transfer writes do not alias live local state, let T be the initial separate destination cursor and:

\[
M=\text{unsigned quantity read at }C+16\mathbin{\gg}1
\]

For iteration \(j\):

- Read a 32-bit source word at \(S+4j\).
- Write its low 16 bits as a 16-bit element at \(T+2j\).
- Advance the source cursor by four bytes and the destination cursor by two bytes.

Under that assumption, the path reads \(4M\) source bytes and writes \(2M\) destination bytes. Destination elements are contiguous. There is no saturation or range rejection.

The function makes no explicit loop assignment to the exposed pointer slot on this path. Its final value remains P only if transfer writes and other activity do not overwrite it. A destination that aliases the slot can change its contents despite the absence of an explicit slot update.

Quantities zero and one produce no source-word reads or destination writes. Odd quantities round down; no extra one-byte transfer occurs.

The evidence supports the narrowed 16-bit values. It does not independently establish target byte order.

### Delegated transfer

When neither direct-transfer condition holds, the function calls F-ae01a3c327d3 with:

1. S.
2. C.
3. The pointer value in the exposed slot.

The caller does not add the descriptor displacement before this call. It does not explicitly read the quantity at C + 16 on the delegated path.

After the dependency returns normally, the function returns without using or forwarding an explicit result.

Established direct effects include:

- Initializing local state and exposing the pointer slot’s address to F-918901543e8e.
- Updating that slot during paired-word setup and between the two word transfers of each iteration.
- Performing the selected direct-path memory reads and writes.
- Invoking F-ae01a3c327d3 on the fallback path.

There is no explicit allocation, deallocation, ownership transfer, global write, synchronization, or status reporting in the function body. This does not constrain dependency effects.

The function does not validate null pointers, alignment, record sizes, source availability, destination capacity, or overlap. Memory must support the accesses actually taken for normal completion.

Ordinary source/destination overlap is processed in the established forward access order, without snapshot or move semantics. Earlier writes can change later source reads.

Aliasing with the exposed pointer slot or other live local state is a separate issue. Such writes can alter destination progression, captured addresses, source progression, or iteration control. The unrestricted outcome is documented_only; the fixed-layout formulas are not guarantees for that case.

No explicit error code is returned. Invalid accesses, arithmetic exceptions, dependency failures, or abnormal termination have no established translation into caller-visible status.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless explicitly discussing unrestricted aliasing, they assume normal dependency returns, valid aligned memory, representable arithmetic, and transfer destinations disjoint from the function’s exposed pointer slot and other live local state.

1. **Source indexing.** With post-preparation position 40, D equal to 7, and origin 5, the source index is 28. S is 112 bytes beyond the stored source base.

2. **Paired layout.** With mode zero, auxiliary flag 1, displacement 12, and quantity 16, two iterations transfer source words at offsets 0, 4, 8, and 12 from S to offsets 0, 4, 16, and 20 from \(P+12\). The exposed slot finishes at \(P+44\). This function does not write the gaps between those pairs.

3. **Paired rounding and zero count.** Quantities 8 through 15 produce one iteration. Quantity 7 produces none, but the exposed slot is still displaced during setup. No partial pair is transferred.

4. **Intervening slot update.** In one paired iteration, the second destination address is captured before the first write. The first write precedes the sixteen-byte slot advance; that advance precedes the second source read and second write.

5. **Narrowing values.** With nonzero mode, offset-21 flag 1, and quantity 6, source values `0x12345678`, `0x0000FFFF`, and `0xABCDEF01` produce 16-bit destination values `0x5678`, `0xFFFF`, and `0xEF01`. With destination storage disjoint from local state, the exposed slot remains P.

6. **Odd narrowing quantity.** Quantity 5 produces two 16-bit writes, not five destination bytes.

7. **Conditional auxiliary access.** With nonzero mode, this function does not directly access E. E need not support a direct read by this function on that branch; dependency requirements remain unknown.

8. **Fallback arguments.** With mode zero and auxiliary flag 2, fallback receives S, C, and P rather than a displaced destination. Flag 2 does not select paired transfer.

9. **Ordinary overlap.** If the first paired destination equals the second source-word address, the first write can change the second value read. Acceptance must not require preservation of the original second word.

10. **Destination aliases exposed slot.** If preparation returns a destination overlapping the pointer slot, acceptance must not require the paired slot to finish at \(T+16N\), fixed destinations \(T+16j\), or narrowing to leave the slot equal to P. The explicit ordering remains evidence; the resulting corrupted-state trajectory is not established.
