# F-f59a6024d361

## Purpose

F-f59a6024d361 performs a callback-controlled traversal starting from a nullable node reference. It visits the current node first, conditionally traverses two ordered child references using itself, and conditionally delegates a third reference to F-eafc02ff245a.

The result is a normalized Boolean-like value: 1 reports that a stopping condition was encountered; 0 reports that this invocation completed without encountering one. A callback can suppress descent from a particular node without causing the enclosing traversal to stop.

This is not an unconditional traversal of every reachable object. Callback results determine whether descendants are considered, and an earlier positive traversal result prevents later branches from being accessed.

## Interface

### Inputs

The function accepts three arguments:

1. **Node reference.** A 32-bit, nullable address-like value identifying the current node. Zero represents an absent node. A nonzero value must identify storage suitable for whichever reads the execution path actually reaches.
2. **Callback.** An indirectly invoked function accepting two arguments, in this order:
   - the unchanged 32-bit context value;
   - the current node reference.

   Its result is interpreted as a signed 32-bit integer.
3. **Context.** An opaque 32-bit value forwarded to the callback and to traversal dependencies. The function does not inspect or dereference it.

The callback receives the context first, even though the node reference is the traversal function’s first argument.

### Output

On every normal return visible in the supplied body, the function returns a 32-bit value equal to either 0 or 1.

- **0:** no stop was reported along the path actually explored.
- **1:** the current callback returned a signed value greater than 1, or a reached traversal dependency returned a nonzero value.

A result of 0 does not prove that every descendant was visited, that all references were valid, or that the callback approved every node. Descent can be skipped.

## Behavior

### Empty input

A zero node reference returns 0 immediately.

For this case, the function does not invoke the callback, read node storage, or invoke F-eafc02ff245a. Consequently, an otherwise unusable callback value is not exercised by this invocation.

### Current-node callback

For every nonzero node reached by F-f59a6024d361, the callback is invoked before any of this function’s three node-field reads.

The callback result has three distinct interpretations:

| Signed callback result | Descend from this node? | Result at this node |
|---|---|---|
| 0 | Yes, subject to ordered short-circuit traversal | Determined by reached descendants and delegation |
| Greater than 1 | No | 1 |
| Any negative value, or exactly 1 | No | 0 |

Thus, exactly 1 is not a global stop signal. It suppresses this node’s descendants and returns 0 to its caller. Negative results have the same local control effect. If an enclosing invocation has later branches, it can continue into them after receiving this 0.

Signed interpretation matters. Under the supplied 32-bit signed interpretation, a result with its high bit set is negative and therefore suppresses descent while returning 0; it is not treated as a large positive stop value.

### Ordered descendant processing

Only a callback result of exactly zero enables descendant processing.

The observable order is:

1. Read the 32-bit reference at offset +8 from the current node.
2. Invoke F-f59a6024d361 with that reference, the same callback, and the same context.
3. If that invocation returns nonzero, return 1 immediately.
4. Otherwise, read the 32-bit reference at offset +12.
5. Invoke F-f59a6024d361 with that reference, the same callback, and the same context.
6. If that invocation returns nonzero, return 1 immediately.
7. Otherwise, read the 32-bit reference at offset +16.
8. Invoke F-eafc02ff245a with that reference, the same callback, and the same context.
9. Return 1 if that dependency returns nonzero; otherwise return 0.

The reads are not established as an upfront snapshot. Each later field is read only after the preceding call has returned zero.

The two self-recursive branches therefore have current-node-first, depth-first ordering. The traversal behavior inside the third dependency is unknown; it cannot be assumed to follow the same rules.

### Short-circuit effects

A nonzero result from the first recursive branch prevents both later field reads and both later calls.

A nonzero result from the second recursive branch prevents the third field read and the call to F-eafc02ff245a.

These omissions are externally relevant when callbacks or dependencies have side effects, modify references, or encounter invalid storage. An unread later reference need not be usable for an execution that stops earlier.

### Mutation visibility

Because the callback precedes the first field read, a callback modification to the current node’s +8 field can affect which first branch is traversed.

Likewise:

- modifications to the current node’s +12 field during the first branch can affect the second branch;
- modifications to the current node’s +16 field during either preceding branch can affect the delegated branch.

These statements require that the node remains valid and that the modifications are visible under the execution environment’s memory rules. The supplied body does not establish synchronization or concurrent-access guarantees.

A reference already read and supplied to a call is not retroactively changed by later mutation of its originating field. This does not imply that the referenced object itself is immutable.

There is no visible check that adding an offset stays within an allocated object or valid address range. Wrapped or otherwise invalid address calculations have no defined recovery behavior in this contract. Callers must provide valid reachable storage rather than rely on address overflow behavior.

## Acceptance examples

These are conditional expectations derived from static control flow, not results of executed tests.

### Empty root

Given a zero node reference, the result is 0. Neither the callback nor any traversal dependency is called.

### Immediate stop

Given a valid nonzero node whose callback returns 2, the result is 1. None of the three reference fields is read by this function.

The same outcome applies to any other signed callback result greater than 1.

### Local pruning without stopping the enclosing traversal

Given a valid nonzero node whose callback returns exactly 1, the result is 0 and no descendant fields are read.

If that node was reached through an enclosing node’s first branch, the enclosing traversal may proceed to its second branch. This callback result does not terminate the whole traversal.

### Negative callback result

Given a callback result of −1, the function returns 0 without reading descendant fields.

The most negative representable signed 32-bit result has the same control effect. It is not a stop merely because its underlying unsigned representation is nonzero or large.

### Stop in the first branch

Given a zero callback result at the current node and a first recursive branch that returns 1:

- the +8 field is read and its branch is explored;
- the current node’s +12 and +16 fields are not read;
- the second recursive call and F-eafc02ff245a are not invoked;
- the current invocation returns 1.

### Delegated nonzero result

### All three references zero

F-eafc02ff245a is then called with a zero first argument. The final result depends on that dependency’s result; it cannot be concluded to be 0 from the three null references alone.

### Reference mutation during traversal
