# F-1b4d515699ed

## Purpose

F-1b4d515699ed selects a 32-bit value, obtains a starting object, and visits a chain of objects through an indirectly dispatched callback. Each callback receives the selected value, a separately captured 32-bit context value, and access to a local output location.

Traversal stops when a callback returns a nonzero status or when the chain reaches a null pointer. The function returns the current contents of the output location—not the callback status.

This is a source-facing behavioral contract based on the supplied static evidence. The meanings of the selector values, selected values, objects, context value, and callback results are not established. No runtime tests have been performed.

## Interface

### Entry and return

The function takes no explicit arguments and returns one 32-bit value.

The return value is treated as an uninterpreted 32-bit quantity. The evidence does not establish whether callers interpret it as a signed integer, unsigned integer, handle, address, or some other representation.

There is no explicit error return separate from this value. In particular, a zero return does not establish whether traversal succeeded, failed, visited no objects, or completed without any callback changing the output.

### Implicit inputs

The function consumes four global 32-bit value sources:

- **Baseline selection value:** captured before calling F-c2c99938e56f.
- **Selector-1 value:** read after F-c2c99938e56f returns.
- **Selector-3 value:** read only when that dependency returns exactly 3.
- **Traversal context value:** captured after F-9d0ecc5f6adf returns.

These labels describe their roles in this function, not their application-level meanings.

The function also consumes:

- A selector result from F-c2c99938e56f.
- A starting-object pointer from F-9d0ecc5f6adf.
- Object dispatch and link fields.
- Callback statuses and callback modifications to the local output location.

### Object layout and callback interface

The supplied representation uses 32-bit integer and pointer fields. The relevant object layout is:

| Object-relative byte offset | Width | Role |
|---|---:|---|
| 0 | 32 bits | Dispatch-table base address |
| 20 | 32 bits | Next-object pointer |

The callback address is obtained from a 32-bit entry at byte offset 100 from the dispatch-table base. The offset is in bytes, not a count of entries.

Each callback receives four arguments, in this order:

1. The current-object pointer.
2. The captured traversal context value.
3. The selected 32-bit value.
4. A pointer to the function’s local output location.

The callback produces a status represented as an integer. Only equality with zero matters to traversal.

The local storage shown by the evidence consists of two adjacent 32-bit words. Only the first word is explicitly initialized and returned. The second word is not initialized by this function. This storage shape does not, by itself, establish that callbacks are authorized to access both words.

### Preconditions

For normal completion:

- The selected callback must accept the four arguments described above.

Null dispatch-table addresses, invalid function pointers, dangling objects, and invalid callback accesses are not checked or recovered from here.

## Behavior

### Selection and capture order

The function first captures the baseline selection value. It then invokes F-c2c99938e56f without explicit arguments.

After that dependency returns, the function reads the selector-1 value. The selected value is determined by the dependency’s exact result:

| Result from F-c2c99938e56f | Selected value |
|---|---|
| Exactly 1 | Selector-1 value read after the dependency returns |
| Exactly 3 | Selector-3 value read after the dependency returns |
| Any other result | Baseline selection value captured before the dependency call |

The selector-1 source is read even when its value is not selected. The selector-3 source is read only for result 3.

No range check, normalization, or arithmetic transformation is applied to the selector result. Negative values and values other than 1 and 3 all select the baseline snapshot.

This timing matters if F-c2c99938e56f changes global state. Such a change does not replace the already captured baseline value. It can affect the subsequently read selector-1 or selector-3 value. The dependency is not assumed to preserve any global.

### Starting object and context

After selecting the value, the function calls F-9d0ecc5f6adf without explicit arguments and uses its return as the starting-object pointer.

Only after that call returns does the function capture the traversal context value. Thus, any changes that dependency makes to the context source can affect the value passed to callbacks.

The selected value is already captured at this point. Changes to its underlying global source during F-9d0ecc5f6adf do not cause a new selection-source read.

The function then initializes the first local output word to zero. This happens even when the starting pointer is null.

### Traversal and dispatch

For each non-null current object, the function obtains the callback through that object’s dispatch-table field and invokes it with the four arguments specified in the interface.

The same captured context value, selected value, and local output address are supplied throughout the traversal. They are not recaptured from their global sources between callbacks.

After the callback returns:

- A nonzero status ends traversal immediately.
- A zero status causes the function to read the current object’s next pointer and continue from that pointer.

The next pointer is read **after** the callback. It is not prefetched from the object before the call. Consequently, if a callback modifies the current object’s next field and returns zero, the subsequent traversal follows the modified field value, provided the object remains valid.

If the callback returns nonzero, this function does not read the current object’s next field.

A null current pointer ends traversal without dispatching a callback. There is no cycle detection, visit limit, or timeout. A cycle whose callbacks always return zero can therefore prevent normal completion.

### Output accumulation and return

The output word starts at zero and is not reset between callbacks.

A callback may change it regardless of whether that callback returns zero or nonzero. The function does not enforce a relationship between callback status and output contents.

On normal completion, the function returns the output word’s final 32-bit contents:

- With a null starting pointer, the return is zero.
- If callbacks leave the output unchanged, the return remains zero.
- If an earlier callback changes the output and later callbacks leave it unchanged, that earlier value remains the return value.
- A stopping callback may replace the output before returning nonzero.
- Exhausting the chain does not clear a value written by an earlier callback.

There is no success flag accompanying the result and no separate indication of why traversal stopped.

## Side effects

The function explicitly writes its local output word during initialization. It exposes the address of that word to each callback.

The supplied body contains no explicit allocation, deallocation, reference-count adjustment, global write, or object-field write. This does not establish that the dependencies or callbacks are free of those effects.

In particular:

- Neither dependency is assumed to preserve globals.
- Callbacks may modify reachable state, including the current object or the output word.
- Ownership of the starting object and subsequent objects is unspecified.
- This function performs no explicit ownership transfer or release.
- It does not preserve a callback-safe next pointer before dispatch.

A callback that frees or invalidates the current object and then returns zero leaves the function attempting a next-field read through that object. Returning nonzero avoids that particular read, but does not establish a general ownership convention.

The output pointer refers to local storage and has no valid post-return lifetime guaranteed by this function. Whether a callback retains it is unknown; such retention cannot be treated as a supported persistent-output mechanism.

The described read ordering is the ordering represented by the supplied static body. It is not a claim about volatile accesses, synchronization, atomicity, or concurrent visibility.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Empty chain.**  
   If F-9d0ecc5f6adf returns null, no object callback is invoked. The traversal context is still captured, the output is initialized to zero, and the function returns zero.

2. **Selector 1.**  
   If F-c2c99938e56f returns 1, callbacks receive the selector-1 value read after that call, irrespective of the earlier baseline value.

3. **Selector 3.**  
   If the selector result is 3, callbacks receive the selector-3 value. The selector-1 source is read first but does not supply the selected value.

4. **Other selector result with baseline mutation.**  
   Suppose the baseline is 10 when captured, F-c2c99938e56f changes its source to 20, and that dependency returns 2. The selected value remains 10.

5. **Context mutation during object acquisition.**  
   If F-9d0ecc5f6adf changes the context source before returning, callbacks receive the value captured after that change, assuming no intervening change affects that read.

6. **Immediate stop without output write.**  
   If the first callback returns any nonzero status and leaves the output unchanged, the function returns zero and does not read that object’s next field.

7. **Output survives chain exhaustion.**  
   If a callback writes 42 and returns zero, and the subsequent traversal reaches null without another output write, the function returns 42.

8. **Later callback replaces output.**  
   If one callback writes 42 and a later callback writes 99 before stopping, the function returns 99.

9. **Callback changes the link.**  
   If a callback changes its current object’s next pointer to null and returns zero, the function reads that null pointer and terminates, assuming the object remains valid.

10. **Cyclic traversal.**  
    If links form a cycle and every callback returns zero while preserving usable objects and links, the function does not terminate through any built-in cycle check.
