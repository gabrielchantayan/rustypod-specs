# F-57b7285eb010

## Purpose

F-57b7285eb010 specifies a state-dependent routine with two principal behaviors:

- A conditional sequence of memory writes resembling record construction.
- A processing sequence that scales a carried value, invokes a computed dependency, distributes portions of its result to memory, and either repeats or invokes a second computed dependency.

The supplied static representation does not establish an application-level purpose, a normal return, or valid execution beyond its invalid-instruction boundaries. Repetition is possible; termination is not guaranteed.

This contract describes the represented operations and their ordering. It does not establish that the recovered control flow accurately models an executable routine.

## Behavior

### Entry predicate

At the beginning of every pass, the routine selects its first branch if either:

- The current first argument is zero; or
- Its signed-negativity condition differs from the Boolean interpretation of the current overflow indicator.

This is not a sign test independent of the incoming overflow state.

Consequently:

- Zero selects the branch regardless of overflow.
- A negative nonzero value selects it when overflow is clear.
- A positive value selects it when overflow is set.

Once selected, the branch distinguishes zero carry from nonzero carry.

### Selected branch with zero carry

The record destination is twice the fourth argument, reduced to 32 bits.

Subject to successful accesses, the following operations occur in order:

1. Store the low 16 bits of the current first argument at the current third argument plus 16 bytes.
2. Read the global address slot as a 32-bit value. Retain this **first global observation** for a later record field.
3. Independently read the same global address slot again as a 32-bit value. This **second global observation** supplies the address base for the next operation.
4. Read one byte at the second global observation plus 3 bytes. Retain that byte.
5. Write the additional stack-sourced 32-bit value at record offset 0.
6. Write the current third argument as a 32-bit value at record offset 4.
7. Write the retained byte, zero-extended to 32 bits, at record offset 8.
8. Write the first global observation as a 32-bit value at record offset 12.
9. Write the record destination’s own 32-bit address at record offset 16.
10. Write the retained byte at record offset 1.

The resulting layout, before considering overlaps with other addressed regions, is:

| Record offset | Width | Written value |
|---|---:|---|
| 0 | 32 bits | Stack-sourced value, subsequently modified by the byte write at offset 1 |
| 4 | 32 bits | Current third argument |
| 8 | 32 bits | Zero-extended retained byte |
| 12 | 32 bits | First global observation |
| 16 | 32 bits | Record destination address |
| 1 | 8 bits | Retained byte; written last |

The two global reads are distinct represented observations with different uses. The first supplies the value stored at record offset 12. The second supplies the address used for the byte read. Equality between them is not guaranteed by the supplied material.

Both global observations and the byte are obtained before the record writes. The first observation and the byte are retained rather than reread during record construction. The second observation need not remain available after supplying the byte-read address.

After the final byte store, the representation reaches an invalid-instruction boundary. No cleanup or normal return is shown.

### Selected branch with nonzero carry

The representation reaches an invalid-instruction boundary without the record-writing sequence.

This path does not perform the initial 16-bit store, either global read, the addressed byte read, or any record store.

### Unselected branch: scaling and overflow gate

When the entry predicate is false:

1. Replace the carried unsigned value with eight times its previous value, modulo \(2^{32}\).
2. Test the existing overflow indicator.

The represented multiplication does not recompute that indicator.

If overflow is zero, execution reaches an invalid-instruction boundary without either computed dependency invocation or any processing-result store.

A processing invocation therefore requires a negative first argument and set overflow. Zero selects the earlier branch; a positive first argument with set overflow also selects that branch.

### First computed dependency

If the overflow gate permits processing:

1. Clear the two least significant bits of the current link/address value.
2. Add 0x7A4 using 32-bit address arithmetic to obtain the target for **F-unresolved-01**.
3. Replace the represented link/address value with 0x083FDFB3.
4. Invoke F-unresolved-01 with the current first argument as the one explicitly shown 32-bit argument.

The target calculation uses the link/address value from before its replacement.

If the dependency returns, its represented result is 48 bits. The routine then performs these actions in order:

1. Replace the first argument with result bits 0–31.
2. Store result bits 32–47 as a 16-bit value at the fourth argument plus 22 bytes.
3. Store result bits 0–15 as a 16-bit value at the additional address base plus 10 bytes.
4. Store result bits 0–7 as one byte at the scaled carried value plus 24 bytes.
5. Set the represented carry indicator according to whether the scaled unsigned value is greater than 13.
6. Set the represented overflow indicator to the signed-subtraction overflow condition for subtracting 14 from that scaled 32-bit value.
7. Read a 32-bit value at the additional address base plus 100 bytes and replace the third argument with it.

The three result stores precede the 32-bit load. An overlapping store can therefore affect that load.

No preservation of global memory or pointed-to objects by F-unresolved-01 is established.

### Repetition

Subtract 14 from the scaled carried value modulo \(2^{32}\), then interpret the result as signed. Repeat when that result is nonnegative.

This is not equivalent to an unsigned comparison against 14:

- A scaled value of zero produces −14 and exits.
- A scaled value of 16 produces 2 and repeats.
- A scaled value of 0x80000000 produces 0x7FFFFFF2 and repeats despite signed-subtraction overflow.

On repetition:

- The first argument contains the dependency result’s low 32 bits.
- The third argument contains the subsequent 32-bit memory load.
- Carry and overflow contain the newly calculated indicators.
- The scaled carried value is retained and can be multiplied by eight again.
- The represented link/address value is 0x083FDFB3.

If another processing invocation is reached, its represented target is therefore 0x083FE754. Reaching it still requires passing the next entry predicate and overflow gate; repetition alone does not imply another call.

### Loop exit and second computed dependency

When the wrapped subtraction result is negative:

1. Read one byte at the current third argument plus 8 bytes.
2. Calculate the target for **F-unresolved-02** by clearing the current link/address value’s two lowest bits and adding 0xCD8.
3. Invoke F-unresolved-02 with the loaded byte as the one explicitly shown byte-sized argument.

Along this represented path, the link/address value is 0x083FDFB3, giving target 0x083FEC88.

No result from F-unresolved-02 is used. If it returns, the representation reaches an invalid-instruction boundary.

## Side effects

### Memory requirements

Every reached access requires suitable mapped memory, permissions, and any target-specific alignment. No null checks, bounds checks, allocation checks, or recoverable error handling are shown.

The record path requires:

- Two writable bytes at the current third argument plus 16.
- Two ordered 32-bit reads of the global address slot.
- One readable byte at the address obtained by the second global read plus 3.
- Writable locations for the five 32-bit record fields and the overlapping byte store.

The first global observation is stored as data. This path does not independently dereference it. Readability at that first observed address plus 3 is therefore not required unless the second observation supplies the same address.

The processing path requires:

- Two writable bytes at the fourth argument plus 22.
- Two writable bytes at the additional address base plus 10.
- One writable byte at the scaled carried value plus 24.
- Four readable bytes at the additional address base plus 100.
- On exit, one readable byte at the newly loaded third argument plus 8.

The scaled value is used directly as an address base. No enclosing allocation or index interpretation is established.

### Aliasing, repeated observations, and partial effects

No non-aliasing or global-stability guarantee is supplied.

The initial 16-bit store precedes both global reads. If it overlaps the global slot or the eventual addressed byte, it can affect later observations.

The global reads must not be collapsed into one contractual observation. If they yield different values, record offset 12 receives the first value while the byte is obtained through the second. Whether and how such differing observations can arise in a valid execution is not established.

Record stores occur after both global reads and the addressed byte read. If they overwrite the global slot or the byte’s source location, the already retained first observation and byte are not refreshed.

The final byte store overwrites one byte of the first 32-bit record field. Its effect on that field’s numerical interpretation depends on byte order.

Processing stores can overlap one another or the subsequent 32-bit load. Dependencies can also affect memory later read by the routine.

If execution stops during an access sequence, earlier effects are not shown as rolled back. No transactional behavior is established.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, reached accesses succeed and invoked dependencies return.

### Zero selects the record path only with zero carry

For a first argument of zero and zero carry:

- The initial 16-bit store writes zero.
- The global slot is read twice, in order.
- The byte is read using the second observation.
- Record offset 12 receives the first observation.
- The record stores occur in their specified order, ending with the byte overwrite at offset 1.
- No processing dependency is invoked.

With the same first argument and nonzero carry, none of those accesses occurs before the invalid-instruction boundary.

### Different global observations have different roles

Conditionally suppose the first global read yields 0x1000, the second yields 0x2000, and the byte at 0x2003 is 0xAB.

Then:

- The addressed byte read is at 0x2003, not 0x1003.
- Record offset 8 receives the 32-bit value 0x000000AB.
- Record offset 12 receives 0x00001000.
- Record offset 1 receives 0xAB.

This expectation does not assert a concurrency mechanism or that differing observations are permitted by an otherwise unspecified execution model. It defines their uses if those observations occur.

### Positive input with clear overflow stops after scaling

For a positive first argument and clear overflow:

- The entry predicate is false.
- The carried value is multiplied by eight modulo \(2^{32}\).
- The overflow gate reaches an invalid-instruction boundary.
- No dependency invocation or processing-result store occurs.

### Processing once and exiting

Suppose the first argument is negative, overflow is set, and the carried unsigned value is zero.

The scaled value remains zero. If F-unresolved-01 returns 0x123489ABCDEF:

- The next first-argument value is 0x89ABCDEF.
- The store based on the fourth argument receives 0x1234.
- The additional-base store receives 0xCDEF.
- The byte store receives 0xEF at address 0x18.
- Carry and subtraction overflow become clear.
- The subtraction result is −14, selecting loop exit.

After the third argument is loaded, a byte at that loaded address plus 8 is supplied to F-unresolved-02. Address 0x18 must be writable; no low-address protection is shown.

### Repetition need not produce another dependency call

Suppose a processing pass has scaled value 16 and returns a result whose low 32 bits are zero.

Carry becomes set, subtraction overflow is clear, and the subtraction result is 2, so execution repeats. The zero first argument selects the entry branch. Set carry then leads directly to an invalid-instruction boundary without record accesses or another dependency call.

### Multiplication wraps before addressing

An initial carried value of 0x20000000 becomes zero after multiplication by eight modulo \(2^{32}\).

If processing is otherwise permitted, the result byte is stored at address 0x18 and the subsequent subtraction selects loop exit. Unbounded multiplication would not match this behavior.
