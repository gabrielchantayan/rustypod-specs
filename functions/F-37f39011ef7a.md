## Acceptance examples

These are conditional static criteria, not executed tests.

### Forwarding and extraction

Under 32-bit truncation, input one produces initial arguments one and `0x04000000`; input 64 produces 64 and zero.

An applicable early result of `0x00f80000` produces five-bit field 31 and the derived bit-16 value `0x00010000`. Changing only bits 24–31 does not change that field.

### Compact index and byte handling

An applicable result of `0x7f` produces compact index 508 and doubled index 1016. An explicit unsigned byte load of `0xfe` widens to 254. Storing `0x123456ab` as a byte stores `0xab`.

### Early fixed capture

If `0x05` supplies address ingredient `0x200`, subsequent captured-base accesses use `0x215` and `0x254`, even if an intervening write changes `0x05`. This assumes the read conversion yields `0x200` and those addresses are valid.

### Association sequencing

If the initial eightfold destination plus `0x54` overlaps association-base plus `0x19`, the word store precedes the overlapping byte store. An implementation reversing them does not preserve the represented access trace.

The next group uses the adjusted eightfold destination and `+0x34` payload, not the initial unadjusted pair.

### Fixed-state publication and reload

If the captured `0xa9` word ends in `0xab`, publication initially stores `0xab` at `0x67`. The later copy to `0x21` must read `0x67` after the intervening computed word read. It must not substitute the retained `0xab`.

If an intervening computed write changes `0x67` to `0xcd`, a subsequent fresh read copies `0xcd`, assuming ordinary readable byte storage.

### Overlap and failure

Clearing a word and then writing an overlapping byte can make a later word read nonzero; its numeric value depends on byte order.

An inaccessible dependency-produced address need not produce a clean error return or rollback, even when the explicit input is valid.
