# F-1364fd0753bc

## Purpose

F-1364fd0753bc performs a long ordered sequence of indirect calls, transforms returned and ambient machine values, and then mutates memory through computed addresses and fixed low addresses. Its terminal action is an unresolved four-argument indirect transfer.

**Established static evidence:** the supplied representation exposes call ordering, mixed-width arithmetic, saved results, address calculations, overlapping memory accesses, repeated stores, and terminal argument provenance.

**Inferred intent:** some transformations resemble packed-field processing, and some stores resemble maintenance of address relationships. These similarities do not establish an encoding, container, ownership model, or application purpose.

This contract describes recoverable behavior without repairing unusual addresses or unresolved control flow into a conventional API. It does not establish that the representation faithfully recovers the original executable.

The opening phase is straight-line in the supplied representation. The first target depends on incoming state; subsequent targets are predominantly formed from continuation-like values adjusted by `0xFFE`.

### Arithmetic constraints

Most scalar transformations operate on represented 32-bit values. They include shifts, masks, multiplication by powers of two, and subtraction. Masks retain fields of several widths, including 11 through 14 bits, 17 through 22 bits, and 24 bits.

Mask placement and intermediate width matter. Extracting the low 32 bits before shifting does not permit discarded bits to carry into the high portion of a combined result. Unsigned right shifts introduce zeros. Successive truncating left shifts can remove every original bit.

For example, a 32-bit value shifted left by eight, then eighteen, then eight becomes zero under a truncating bitvector interpretation. It is not an unbounded mathematical product.

Several operands are represented as signed-looking 32-bit quantities. Their left shifts and multiplications may exceed the signed range. Exact executable overflow behavior requires instruction evidence; modular interpretations below are conditional.

A late small-address calculation first shifts a result left by eight, masks with `0x7FFF`, and shifts right by six. Under 32-bit bitvector arithmetic, the result ranges from zero through `508` in steps of four. Its doubled address base ranges from zero through `1016` in steps of eight. Another base is formed by scaling a late result by `0x02000000`.

### Post-publication observations and fixed-global reads

- **Working base:** the scaled base used for the offset-`0x20` write sequence.

- **Late base:** the value eventually loaded from the linked base plus `0x04`.

After the repeated region, the fixed 32-bit read at `0xA9` precedes a computed offset-`0x74` load and then the fixed byte write at `0x3A`. The `0x3A` byte is derived from the adjusted scaled-address value multiplied by eight and increased by `0x30`, subject to the represented narrowing.

The linked base plus `0x14` is then loaded and saved. This saved value becomes the terminal third argument. The working base plus `0x04` is also loaded before several intervening stores.

The fixed write at `0x67` occurs later, receiving the low byte of the earlier `0xA9` result. After a computed offset-`0x44` load, `0x67` is read for assignment to fixed `0x21`.

Further computed writes intervene before subsequent copies from `0x67`. The supplied representation explicitly shows **two later computed-address byte stores** that each read `0x67` anew, both targeting the working base plus `0x09` at different points. Thus the visible sequence contains three explicit reads of `0x67` overall: one for `0x21`, followed by two computed-address copies.

### Final updates and terminal argument capture

The closing region includes these observable relationships:

- A byte store at the working base plus `0x10` precedes a 32-bit store beginning at that same offset.
- The publication base plus `0x54` first receives a loaded address-like value and later receives the working base.

- The working base plus `0x44` receives the earlier fixed `0xA9` result and is later overwritten with a loaded address-like value.

The terminal argument ordering is recoverable and is not an ABI unknown:

The **third argument** is the older saved 32-bit value from the linked base plus `0x14`, captured shortly after the repeated region. Later writes do not replace that saved operand with current memory contents.

Much later, a 32-bit load from the linked base plus `0x04` establishes the **late base**. A 16-bit store of `0x65` through twice that base occurs before the 32-bit load from the late base plus `0x64`. The latter load supplies the **second argument**.

After that second-argument load, a byte store and a 32-bit store of decimal `100` occur through another previously loaded base. Only then is the late base plus `0x74` loaded to capture the **fourth argument**.

A subsequent 32-bit load from the linked base plus `0x64` supplies another address-like value. Following a byte write at the linked base plus `0x09`, this value identifies the base of an offset-`0x54` store receiving the saved second argument. Finally, a 32-bit store through **twice the second argument** receives that same subsequently loaded address-like value.

The terminal transfer then receives `0x72`, the saved second argument, the older saved third argument, and the saved fourth argument. Neither the final store nor potential aliasing authorizes reloading these arguments from memory.

## Acceptance examples

These examples are conditional static obligations, not observed executions.

### Combined-result splitting

If a relevant result has low portion `0x12345678` and high portion `0x9ABCDEF0`, forwarding the low portion shifted left by eight and the unchanged high portion produces `0x34567800` and `0x9ABCDEF0` under truncating 32-bit shifts. Carrying discarded bits into the high portion is incorrect.

### Masked arithmetic

Retaining the low 24 bits of `0xFF123456` and shifting left by six produces `0x048D1580` under the stated width interpretation. An unbounded product of the original unmasked value is not equivalent.

### Unknown fixed-load width

If the fixed `0x05` declaration permits values greater than `255`, its unsigned 32-bit conversion need not produce a byte-sized address. Restricting that base to `0` through `255` requires evidence absent here.

### Fresh fixed-global observations

Suppose the byte initially written to `0x67` is `0xAA`, but an intervening computed write changes it to `0xBB` before a later copy. That copy must use the value observed at its own read, not necessarily `0xAA`. Each subsequent represented read has the same independent requirement.

### Saved terminal arguments

Suppose the early linked-base offset-`0x14` load captures `0x11111111`, the late-base offset-`0x64` load captures `0x2000`, and the later late-base offset-`0x74` load captures `0x33333333`. If execution reaches the transfer, its arguments are `0x72`, `0x2000`, `0x11111111`, and `0x33333333`.

Under non-overflowing address arithmetic, the final doubled-address 32-bit store targets `0x4000`. Its payload is the subsequent linked-base offset-`0x64` load, not the third or fourth argument.

### Observable writes and failure

A write-observable offset-`0x20` destination must expose the four ordered publications described above. Retaining only the final `0x20` is insufficient.
