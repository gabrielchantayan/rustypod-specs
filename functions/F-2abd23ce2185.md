# F-2abd23ce2185

## Purpose

The established behavior has three stages:

1. Invoke F-148f046b5d07 with an address selected from a regularly spaced region of the object.
2. Read a state field, optionally invoke F-06da8c0216dc, and write the next state.
3. Read and increment a selector field, replacing an incremented value of exactly four with zero.

The record spacing and selector transition suggest a four-position rotating arrangement. That interpretation is **inferred intent**, not a demonstrated record type or enforced selector range. In particular, this function does not validate that the incoming selector is between zero and three.

## Behavior

### 1. Select an address and invoke the first dependency

Before reading the state field for its branch decision, the function reads the 32-bit selector at offset `0xAB4`.

The selected address is the object base plus `0xB54`, plus the selector multiplied by `0x94`. For selectors zero through three, this produces the four fixed addresses listed in the interface.

F-148f046b5d07 is then invoked with five arguments, in this positional arrangement:

| Position | Argument |
|---|---|
| 1 | Object base |
| 2 | Second input |
| 3 | Selected address |
| 4 | Fourth input |
| 5 | Fourth input again |

The address is determined using the selector read before this call. Changes to the selector during the call do not retroactively change the address already passed.

The function does not visibly clamp, normalize, or reject the selector before forming this address. A selector outside zero through three therefore does not automatically select one of the four listed record addresses.

### 2. Read the state after the first dependency returns

Only after F-148f046b5d07 returns does the function read the state at offset `0xAB0`.

Consequently, the branch decision uses the state present after that dependency call, not necessarily the state present on entry. No preservation of either state field by F-148f046b5d07 may be assumed.

There are three cases.

#### State equals five

F-06da8c0216dc is called with the object base followed by these four addresses, in order:

1. Base plus `0xB54`.
2. Base plus `0xBE8`.
3. Base plus `0xC7C`.
4. Base plus `0xD10`.

After the call returns, the function writes three to the state field.

This write is unconditional within this branch. If the dependency changes the state field, that change is replaced by the subsequent write of three. There is no intervening state reread used to calculate this branch’s final state.

#### State equals three

F-06da8c0216dc is called with the object base followed by a different ordering:

1. Base plus `0xC7C`.
2. Base plus `0xD10`.
3. Base plus `0xB54`.
4. Base plus `0xBE8`.

After the call returns, the function rereads the state field, increments that newly read value by one, and writes the result to the state field.

This is not an unconditional transition from three to four. It produces four only when the reread state is still three. A dependency mutation of this field affects the result.

#### State is neither three nor five

No call to F-06da8c0216dc occurs.

The value already read for the branch decision is incremented by one and written back to the state field. There is no additional dependency call or state reread in this branch.

### 3. Advance the selector

After the state write, the function rereads the selector at offset `0xAB4`. This is separate from the selector read used to choose the address for the first dependency.

The newly read selector is incremented by one, and that incremented value is written to the selector field.

If the incremented value equals exactly four, the function performs another write to the same field, replacing four with zero. Otherwise, the incremented value remains.

Two consequences are observable:

- The final selector update incorporates any selector mutation made by either dependency.
- Rollover is an equality check against four, not a general modulo-four reduction.

For an increment from three, the direct write sequence is four followed by zero. The function does not merely calculate zero and perform one final selector write.
