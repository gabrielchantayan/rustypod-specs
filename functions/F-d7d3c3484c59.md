# F-d7d3c3484c59

## Purpose

F-d7d3c3484c59 transfers selected fields between two memory regions, rearranges their locations, writes two constants, and conditionally subtracts four from one transferred character-sized value.

The established behavior is a sequence of accesses, not a whole-record copy:

- Two 16-bit quantities exchange relative positions.
- Five source bytes are transferred individually.
- One transferred byte controls whether another transferred value is adjusted.
- Destination offset 2 receives zero.
- Destination offset 11 receives three.
- Destination offset 3 is not directly written.

Field meanings, units, and the reason for the constants are not established. Interpreting the operation as a format conversion or record initialization is inferred intent, not part of the established contract.

## Behavior

### Access order

The two 16-bit transfers occur first. The quantity at source offsets 2–3 is read and written to destination offsets 0–1 before the quantity at source offsets 0–1 is read and written to destination offsets 4–5. Each transfer obtains its source quantity before its destination store.

Next, destination offset 2 is set to zero. Three individual-byte transfers follow in this order: source offset 6 to destination offset 8, source offset 5 to destination offset 9, and source offset 4 to destination offset 10. Each source byte is read before its corresponding store; the later source reads do not precede the earlier stores.

The character at source offset 7 is then read, retained, and stored at destination offset 6. After that store, the character at source offset 11 is read, retained, and stored at destination offset 7.

The retained character from source offset 11 determines whether the additional store occurs. If it is nonzero, the function subtracts four from the retained character originally read at source offset 7 and stores the character-sized result at destination offset 6. Neither source offset 7 nor destination offset 6 is reread for this calculation. The condition is likewise not reread after its transfer.

Finally, destination offset 11 is set to three, and the function returns without a value.

Consequently:

- Destination offset 6 receives one store on the zero-condition path and two on the nonzero-condition path.
- The initial store to destination offset 6 remains part of the represented access sequence even when the conditional store replaces it.
- The constant at destination offset 11 is written after the condition has been read and acted upon.

This is the order represented by the supplied body. It is not a guarantee about individual machine instructions, physical memory transactions, or observations by concurrent agents.

### Transfer semantics

The 16-bit operations transfer quantities without an explicit arithmetic conversion or byte-order reversal. Both ends use the same access width.

On a target with a consistent representation for ordinary memory in both regions, each transfer preserves the corresponding two-byte representation. The evidence does not identify a particular byte order.

The single-byte transfers do not combine adjacent bytes or extract selected bits. Every nonzero condition value selects the adjustment; the condition is not restricted to the value one.

### Arithmetic width and conversion

Only the retained character from source offset 7 participates in the subtraction. The operation does not subtract from a 16-bit field, an address, or the condition value.

The subtraction is evaluated before conversion back to the character-sized destination representation. The represented character participates in promoted arithmetic rather than an explicitly specified 8-bit wrapping subtraction.

Two matters must remain separate:

- **Established:** a nonzero retained condition selects subtraction by four, followed by a character-sized store.
- **Unresolved:** plain-character signedness and the target’s narrowing behavior when the result is outside the destination type’s range.

For source offset 7 containing a byte numerically between 4 and 127 inclusive, subtraction produces the same nonnegative result under ordinary signed-character and unsigned-character interpretations. Those cases do not depend on an out-of-range conversion.

Other cases require target information. For example, input zero with a nonzero condition produces a mathematical result of negative four before narrowing. A stored byte of FC is consistent with low-eight-bit retention, but that representation is not established as a target-independent guarantee.

A high-bit condition still selects the adjustment if its character value is nonzero. Its possible negative interpretation does not change the zero-versus-nonzero decision.

### Overlap

The function does not check overlap or capture all source fields before writing. Earlier destination stores can therefore alter later source reads.

When the two base addresses are identical:

- The first 16-bit store replaces source offsets 0–1 before the second 16-bit read.
- The second transfer consequently obtains the newly written quantity, not the original quantity at offsets 0–1.
- Its store to offsets 4–5 occurs before the individual-byte reads at source offsets 5 and 4.
- Those later byte transfers therefore obtain the updated contents of offsets 5 and 4.

Other relative overlaps can change different later reads, including the retained character or condition. In particular, a later write to a source location does not retroactively change an already retained value.

These are consequences of the represented access order. They do not establish that every possible overlapping object arrangement is valid under an otherwise unspecified target object model.
