# F-aa00c04e52a2

## Purpose

F-aa00c04e52a2 traverses a linked structure using an opaque comparison dependency. After traversal, it either selects an existing candidate or delegates to an opaque insertion-like dependency.

The caller receives a four-byte result word followed by a one-byte indicator:

- **0:** the function selected a candidate without calling F-8f9e086a477b.
- **1:** the function called F-8f9e086a477b and copied its output word.

Indicator 1 establishes delegation, not successful insertion, allocation, or creation of a new entry.

An ordered-tree insertion operation is **inferred intent**. The established contract consists of the accesses, decisions, dependency calls, temporary-state transitions, and output writes below.

### Relevant temporary storage

The following descriptive names distinguish storage locations, not source identifiers:

- **Early-delegation word:** four-byte output storage used when F-e1c8edf49b9a selects immediate delegation.
- **General-delegation word:** separate four-byte storage passed to F-e1c8edf49b9a and used as output storage on the final delegation path.
- **Candidate slot:** four-byte pointer-bearing storage whose address is passed to F-e1c8edf49b9a.
- **Additional scratch word:** four-byte storage cleared before the final candidate comparison.

The two delegation words are not interchangeable. Their initialization histories can affect the copied result if F-8f9e086a477b does not write its output.

Null containers, null headers, malformed parent chains, cycles, and invalid links are not validated. A null link is accepted only where an explicit null decision is described below.

## Behavior

### 1. Establish the initial search state

The remembered comparison outcome starts as nonzero.

The function then:

1. Reads the header pointer from container +0x10.
2. Reads the initial search entry from that header’s +0x04 field.
3. Reads container +0x10 again, retaining this second header address as the initial remembered entry.

The two header reads are distinct. Their agreement is not established.

If the initial search entry is null, the search loop is skipped. Neither delegation word is initialized by that loop, the remembered comparison remains nonzero, and the remembered entry remains the second header value.

### 2. Search through nonnull entries

For every nonnull search entry, the function performs these operations in order:

1. Clears the early-delegation word to four-byte zero.
2. Clears the general-delegation word to four-byte zero.
3. Calls F-31a0b2b5649a with:
   - container address +0x19;
   - the incoming value;
   - current entry address +0x10.
4. Retains the current entry as the remembered entry.
5. Reads the next link selected by the comparison result:
   - zero selects +0x0c;
   - any nonzero result selects +0x08.

A negative and a positive nonzero result take the same branch.

The selected link is read after the comparison dependency returns. Changes made by that dependency can therefore affect traversal.

The loop ends when the selected next entry is null. For a nonempty search, the remembered entry is the last visited entry and the remembered comparison is its comparison result.

Both delegation words have been cleared before the last search comparison, but their subsequent contents are not guaranteed if dependencies can modify them through accessible aliases.

### 3. Read the control byte

After traversal, the function reads container +0x18.

- **Nonzero:** bypass candidate setup, F-e1c8edf49b9a, candidate adjustment, and the final candidate comparison. Proceed to general delegation.
- **Zero:** copy the remembered entry into the candidate slot and continue below.

The control byte is not captured at entry. Search dependencies may affect the value observed here.

### 4. Handle a nonzero remembered comparison

With control zero and remembered comparison nonzero, the function:

1. Reads container +0x10 again.
2. Reads the four-byte word at the newly obtained header’s +0x08 field.
3. Overwrites the general-delegation word with that value.
4. Calls F-e1c8edf49b9a with the candidate-slot address and the general-delegation-word address.

Both supplied storage locations are mutable through those arguments.

If the helper returns **nonzero**, the function immediately:

1. Calls F-8f9e086a477b with the early-delegation word’s address, container address, a zero argument, the original remembered entry, and the incoming value.
2. Copies the early-delegation word to result offset +0.
3. Sets the indicator to 1 and writes it at result offset +4.
4. Returns.

There is no candidate adjustment or candidate comparison on this path. A helper change to the candidate slot does not replace the original remembered-entry argument.

The early-delegation word is not cleared again before this call. A nonempty search previously cleared it; an empty search did not. The helper’s initialization and modification of the **general-delegation word** do not initialize the separate early-delegation word.

If the helper returns **zero**, adjustment starts from the candidate-slot value left by the helper.

### 5. Adjust the candidate

This stage occurs only after the helper returns zero.

First, read the candidate’s tag byte at +0x00. If it is zero, read the candidate’s +0x04 link and then the linked record’s +0x04 link. If this second address equals the candidate, replace the candidate slot with the candidate’s +0x0c link and finish adjustment.

A nonzero tag skips the parent-chain special-case test.

If the special case does not apply, the function reads the candidate’s +0x08 field twice:

1. The first read supplies a prospective next record.
2. The second read determines whether to take the upward or downward path.

These observations must not be collapsed into one guaranteed value.

**Second read is null: upward path.** Discard the first +0x08 observation and read the candidate’s +0x04 link as the first ancestor. For each ancestor:

- Compare its +0x08 link with the current candidate-slot value.
- Replace the candidate slot with the ancestor, regardless of whether the comparison matched.
- If they matched, obtain the next ancestor through that ancestor’s +0x04 field and repeat.
- Otherwise, stop.

Thus the ancestor becomes the candidate even on the terminating iteration.

**Second read is nonnull: downward path.** Use the value from the first +0x08 read as the next record. Each iteration:

- Replaces the candidate slot with that record.
- Reads the candidate’s +0x0c field as a prospective next record.
- Reads the same +0x0c field again for the continuation decision.
- Continues with the first observation if the second is nonnull; otherwise stops with the current candidate.

With stable links, this selects the terminal record reached by following +0x0c after the initial +0x08 descent. Without stability, the first observation controls the next record while the second independently controls continuation.

For example, a nonnull continuation observation does not ensure that the separately loaded prospective address was nonnull. No protective validation repairs such disagreement.

### 6. Compare the candidate and select or delegate

This stage is reached when control is zero and either:

- The remembered comparison was zero, so the helper and adjustment were skipped; or
- The helper returned zero and adjustment completed.

Before the comparison, the function:

1. Clears the additional scratch word to four-byte zero.
2. Clears the general-delegation word to four-byte zero.
3. Computes the stored-value operand from the candidate slot’s current value plus +0x10.
4. Calls F-31a0b2b5649a with the context address, that stored-value address, and the incoming value.

The operand order is reversed relative to search comparisons.

If the comparison returns **zero**, the function reloads the candidate slot after the call and writes that value to result offset +0, then writes indicator 0.

The comparison operand therefore derives from the **pre-call candidate**, but the result derives from the **post-call candidate slot**. F-e1c8edf49b9a previously received the slot’s address and may have retained it. If F-31a0b2b5649a can access such a retained alias, it can change the slot during comparison. No subsequent validation or dereference of the returned candidate value is established on this branch.

If the comparison returns **nonzero**, proceed to general delegation.

### 7. Perform general delegation

F-8f9e086a477b receives:

1. The general-delegation word’s address.
2. The container address.
3. A zero-valued argument.
4. The original remembered entry.
5. The incoming value.

The adjusted or subsequently modified candidate is not substituted for the remembered entry.

After return, the function copies the general-delegation word to result offset +0, then writes indicator 1 at offset +4.

The output word’s pre-call state depends on the path:

| Path | Established initialization history |
|---|---|
| Nonempty search, nonzero control | Cleared before the final search comparison; not cleared again before delegation. |
| Empty search, nonzero control | No initialization of this word is established before delegation. |
| Candidate comparison returns nonzero | Cleared immediately before that comparison, after the additional scratch-word clear. |
| Helper followed by candidate comparison | The header-derived/helper-modified value is overwritten by that pre-comparison clear. |

Because the helper received this word’s address, the candidate comparison may modify it through an accessible retained alias after the clear. If F-8f9e086a477b leaves its output untouched, the subsequent copy observes the word’s actual post-dependency contents—not necessarily zero.

## Side effects

The function directly writes temporary storage and caller result storage. It performs no direct container-field or tree-link update.

The early-delegation word’s low byte is also used to stage the final indicator. On delegation paths, the four-byte result is copied before this indicator staging and the caller’s indicator write. Reusing that byte does not change the result already copied.

Dependencies may mutate reachable container records, comparison context, globals, and exposed temporary storage. Their implementations and preservation guarantees are unavailable.

Important ordering boundaries include:

- Both delegation-word clears precede each search comparison.
- Search-link reads follow the comparison.
- The control-byte read follows traversal.
- A fresh header read precedes helper-argument initialization.
- Both pre-candidate-comparison clears precede that comparison.
- Existing-entry output reloads the candidate slot after comparison.
- Every completed output path writes the result before the indicator.

No locking, atomic publication, rollback, or concurrent-mutation protocol is established.

The function contains no direct allocation or release operation. Dependency allocation, release, ownership transfer, and pointer retention remain unknown. Temporary addresses have no established valid lifetime after this invocation returns.

Result storage is not checked for overlap with the container or entries. Its writes can modify overlapping structure memory; no overlap-safe semantics are promised.

## Acceptance examples

These are conditional static cases, not executed tests. They assume valid accesses and normally returning dependencies.

### Existing candidate without helper use

Given control zero, a final search comparison of zero, and a candidate comparison of zero:

- Do not call F-e1c8edf49b9a or F-8f9e086a477b.
- Clear the additional scratch word, then the general-delegation word before candidate comparison.
- Compare using the pre-call candidate’s stored-value address.
- Return the post-call candidate-slot value, then indicator 0.

If dependencies preserve the candidate slot, that result is the last search entry.

### Retained candidate alias changes the result

Given helper return zero, successful adjustment, and a candidate comparison that returns zero while changing the candidate slot through a retained alias:

- The comparison still receives the address derived from the pre-call candidate.
- The output is the replacement slot value.
- No second comparison validates that replacement.
- Indicator is 0.

### Immediate delegation without an output write

Given a nonempty search, control zero, helper return nonzero, no intervening modification of the early-delegation word, and F-8f9e086a477b leaving its output untouched:

- The copied result is zero, from the last search-iteration clear.
- Indicator is 1.

With an empty search instead, no initialized early-delegation result value is established.

### General delegation observes retained output storage

Given helper return zero and a nonzero candidate comparison:

- The header-derived helper word is cleared before candidate comparison.
- If that comparison writes a distinct value through the retained word address and F-8f9e086a477b leaves output untouched, that distinct value is copied.
- Delegation still receives the original remembered entry.

### Nonzero control after an empty search

No search comparison or delegation-word clear occurs. The second initial header read supplies the remembered entry. General delegation occurs directly. If its output is not written, no initialized result value is established.

### Paired downward reads disagree

Given that a downward iteration’s first +0x0c read is nonnull but its second is null, adjustment stops at the current candidate; it does not visit the prospective next record.

Conversely, a null first observation with a nonnull second observation attempts continuation with null, without a protective null check.
