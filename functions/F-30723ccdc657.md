The arithmetic consequences below use 32-bit wrapping operations: multiplication, addition, and left shifts retain the low 32 bits; logical right shifts insert zeros. Byte writes retain the low eight bits. These conventions describe a machine-level reading, not portable signed-language semantics.

A **byte-selected write** means an eight-bit read from the stated source, zero-extension of that byte, and an eight-bit write at its unsigned value plus `0x11`. Thus the destination lies between `0x11` and `0x110`; no surrounding object base is visible.

“Four intervening calls” below means exactly four indirect calls with no displayed explicit arguments. A result attributed to such a group comes from its last call. These calls remain observable operations; their omitted argument displays do not establish argument-free machine interfaces.

## Acceptance examples

These are conditional static examples, not runtime observations. Each assumes execution reaches the operation and required accesses succeed.

1. **Unsigned byte selection.** Source bytes `0x00` and `0xff` select destinations `0x11` and `0x110`. Signed-byte addressing is incompatible with the representation.

2. **Truncated packing.** Four times packing result `0x41` writes byte `0x04`, not the wider value `0x104`.

3. **Bit extraction.** Extracting bits 22–29 from `0x3fc00000` writes `0xff`; the same extraction from `0xc0000000` writes zero.

4. **Post-global selector transfer.** If the second-primary-result store uses selector 3, it writes at `0x20`. Both global reads occur before the subsequent call receiving 3. That call does not receive slot base `0x0c` or address `0x20`.

5. **Slot-base transfer.** If the later shifted-result store uses selector 3, its following call receives `0x0c`, after the four-byte write at `0x20`.

6. **Collapsing arithmetic.** Any 32-bit value shifted left by 26 and then multiplied by `0x400` becomes zero. The subsequent byte-clear source is address 1. This does not simplify the earlier shifted-base word reads to `0x1c`.

7. **Split-result ordering.** With high half 2 and low half 1, the first split-result store writes zero at `0x1c`; the next call receives 2. The later low-derived store writes `0x04000000` at `0x10000014`, then a call receives `0x04000000`.

8. **Different scaled layouts.** Construction selector 3 causes value `0x0c` to be stored at `0x44`. Its associated word read, where present, accesses `0x20`, not `0x44`.

9. **Fresh repeated selection.** If a byte source changes from `0x05` to `0x09` between two accesses, the writes select `0x16` and `0x1a`. Reusing the first byte would discard an observable read.

10. **Named dependency.** Dependency operand `0x12345678` is passed twice to F-674e75a953e8. No return, preservation, allocation, or release behavior follows from that invocation alone.
