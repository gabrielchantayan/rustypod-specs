To describe the repeated call structure without inventing dependency identities:

- A **four-call result group** consists of four successive indirect calls, with the fourth supplying the scalar result used afterward.
- A **five-call result group** consists of five successive indirect calls, with the fifth supplying the result used afterward.

### 1. Initial argument transformation and first byte writes

The fourth input is logically divided by eight, discarding its low three bits.

The first indirect call receives:

1. The third input shifted left three bits.
2. The same shifted value.
3. The divided fourth input.

A four-call result group follows. Before the next call, the function:

1. Reads a byte at the incoming ambient address plus `0x01`.
2. Uses that byte, zero-extended, as an absolute address component.
3. Writes one byte at that value plus `0x11`.

The stored byte is bits 22–29 of the incoming ambient 32-bit value. This is not a write relative to the original ambient address.

The next call receives the preceding scalar result shifted left two bits.

A four-call result group then supplies a new scalar. Let the **first scaled base** denote four times that result, reduced to 32 bits. The function reads a 32-bit word at this base plus `0x74`, then writes its low byte at this base plus `0x01`.

A following call receives a fresh word read from base plus `0x74`, followed by two copies of the divided fourth input. The second read must not be replaced with the earlier value without additional memory assumptions.

A forwarding pair and a four-call result group follow. Four times the latter result forms a **second scaled base**. The function copies the low byte of the word at second scaled base plus `0x74` into second scaled base plus `0x01`, then calls a dependency with the second scaled base.

### 2. Derived fields and a fixed-address write

After four further calls, the representation uses a secondary register output as a word index.

Let the **top-seven value** be the first scaled base logically shifted right by 25. It is between 0 and 127.

The function writes:

- At four times the secondary index plus `0x14`: the top-seven value shifted left 19 bits.

A subsequent call receives that secondary index. Another call produces a represented 64-bit result. Its low word, high word, and low word again are passed to the next call.

A four-call result group follows. At four times its result plus `0x14`, the function stores the relevant secondary register output shifted left three bits. A call then receives four times the group result.

After four more calls, the function performs a write whose arithmetic collapses under 32-bit reduction:

- The intermediate value is the top-seven value shifted left 20 bits.
- Multiplying it by `0x200000` yields zero modulo \(2^{32}\).
- Multiplying it by `0x80000` also yields zero modulo \(2^{32}\).

Thus the represented store writes a zero word at absolute address `0x14`. The following call receives three zero arguments.

This is an arithmetic consequence of the represented expressions, not evidence that address `0x14` is valid or intentionally used.

A four-call result group follows. At four times its result plus `0x14`, the function stores the top-seven value shifted left 20 bits. The next call receives four times that result.

### 3. Byte-selected destinations and linked word writes

A four-call result group produces a new 32-bit value. Its four-times-scaled value is retained.

Using the earlier top-seven value shifted left 20 bits as an address base, the function:

1. Reads a byte at base plus `0x01`.
2. Writes the low byte of the retained scaled value at the loaded byte plus `0x11`.
3. Calls a dependency with the loaded byte divided by eight, the retained scaled value, and four times the address base.

After another four-call result group, the function rereads the byte at base plus `0x01`. This second byte is retained separately. At that byte plus `0x11`, it writes the low eight bits of the earlier unscaled result after masking to 30 bits and shifting right 20.

The next call receives four times the latest group result.

After four more calls:

- At four times the retained byte plus `0x14`, the function stores the retained scaled value.
- A call receives three copies of the retained byte and the byte divided by two.

A four-call result group follows. At four times its result plus `0x14`, the function stores the same retained scaled value, then calls a dependency with four times that result.

Two further result stages perform these writes in order:

1. A four-call result group supplies an index; at sixteen times that index plus `0x14`, store four times the index.
2. Call with that four-times-scaled value.
3. A four-call result group supplies another index; at four times that index plus `0x14`, store the preceding scaled value.
4. Call with four times the latest index.

During this sequence, the retained byte divided by eight becomes a separate address quantity used later.

### 4. Additional scaled-index fields

A call receives the four-times-scaled index. A forwarding pair and a four-call result group follow. At four times the new group result plus `0x14`, the function stores:

A four-call result group follows. The function reads a byte at working base plus `0x01`, then writes at that byte plus `0x11` the truncated result of masking the working-base source value to 30 bits and shifting right 20.

The next call receives four times the latest group result. After a forwarding pair and a four-call result group, the function rereads the byte at working base plus `0x01` and writes zero at the newly selected byte plus `0x11`.

A call receives four times the latest result. After four more calls, the function:

## Side effects

Direct effects include byte stores, word stores, repeated absolute-address clears, and indirect calls throughout the sequence.

The observed offsets `0x01`, `0x0f`, `0x11`, `0x14`, `0x24`, `0x44`, and `0x74` do not establish a structure definition. Some accesses use four-times scaling, others sixteen-times scaling, and byte-selected destinations are absolute low addresses between `0x11` and `0x110`.

No allocation, ownership transfer, release, lock, or transaction boundary is established. In particular:

- Passing a value to a dependency does not prove ownership transfer.
- Repeated writes do not prove reference-count maintenance.
- Zeroing does not prove destruction or successful cleanup.
- Earlier writes need not survive later calls or aliasing accesses.

## Acceptance examples

These examples are conditional static-contract checks, not executed tests.

1. **Fourth-input truncation.** Fourth inputs from 0 through 7 produce zero as the explicitly computed divided argument. A fourth input of 8 produces one. This does not guarantee otherwise identical execution because ambient state remains relevant.

2. **Word-to-byte copy.** If a phase-1 word load yields `0x123456ab`, its associated byte store writes `0xab`. The full word is not stored at offset `0x01`.

3. **Absolute byte-selected address.** If a selector-byte read yields `0x20`, the corresponding selected store targets absolute address `0x31`, not the selector’s source base plus `0x31`.

4. **Truncation after masking.** A value of `0x3ff00000`, masked to 30 bits and shifted right 20, yields `0x3ff`. A byte store retains `0xff`, not the full ten-bit result.

5. **Fixed-address arithmetic.** Under 32-bit reduction, every possible top-seven value makes the phase-2 store target `0x14` and write zero.

6. **Reread across calls.** If an intervening dependency changes a selector byte, a later explicit reread uses the changed byte. Retaining the earlier selector is not equivalent.

7. **Partial effects on failure.** If a later word store faults, preceding writes may already have occurred. No rollback is specified.

8. **Terminal outcome.** If the entire represented trace executes, acceptance does not require a normal return; the available representation terminates at an invalid-instruction halt.
