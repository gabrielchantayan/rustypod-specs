# F-be1254801757

## Purpose

F-be1254801757 transforms three consecutive caller-owned integer words in place using one shared signed multiplier. It returns no value and reports neither numerical range loss nor discarded fractional information.

Under the conditional numerical model defined below, each output is the 32-bit pattern corresponding to its signed input multiplied by the multiplier, divided by 65,536 with rounding toward negative infinity, and reduced modulo \(2^{32}\).

This is not saturating arithmetic. Large results can change apparent sign or become zero when reduced to the stored width.

Scaling a three-component fixed-point quantity is plausible intent, not an established interface requirement. Component meanings, units, coordinate systems, and the interpretation of the original words as fixed-point quantities are unknown.

## Behavior

### Numerical result

For each stable position, let \(x\) denote the signed interpretation of its input and \(m\) the signed multiplier. Under the conditional model, the final stored pattern is

\[
\left\lfloor\frac{x\,m}{2^{16}}\right\rfloor \bmod 2^{32},
\]

with the modulo result chosen from \(0\) through \(2^{32}-1\).

This formula specifies the conditional external result, not a required implementation sequence. It also does not establish portable execution for inputs affected by unresolved conversion or signed-shift rules.

Equivalently, the stored result retains product bits 16 through 47 under a 64-bit two’s-complement interpretation. The lower 16 bits do not affect the output. Higher product bits do not trigger saturation or a reported error.

### Width and range

Under the assumed operand widths, every exact product fits in signed 64-bit range. The largest positive product is

\[
(-2^{31})(-2^{31})=2^{62}.
\]

Thus multiplication itself needs no greater precision under this model.

The scaled result can nevertheless exceed 32-bit range. Reduction to the stored width has several observable consequences:

- A positive mathematical result can produce a word with its sign bit set.
- A negative mathematical result can produce a word with its sign bit clear.
- A nonzero product can produce a zero output.
- Distinct products can produce the same output.
- Return from the function does not certify exact representability.

Product representability does not resolve the separate signed-conversion and signed-shift limitations described under Uncertainties.

### Rounding

The conditional result rounds downward before reduction to the stored width. It is not round-to-nearest, and negative fractions are not generally truncated toward zero.

| Exact product | Exact scaled value | Integer before word reduction |
|---:|---:|---:|
| 1 | \(1/65{,}536\) | 0 |
| −1 | \(-1/65{,}536\) | −1 |
| −65,536 | −1 | −1 |
| −98,304 | −1.5 | −2 |

For nonnegative products, downward rounding agrees with truncation toward zero. For negative products with a fractional remainder, it does not.

The caller cannot select another rounding policy.

### Independence and access ordering

The abstract replacements occur in position order: first, second, then third. Completion of an earlier replacement precedes evaluation of the next position.

The operation therefore does not capture all three originals before writing any result. Changes to a later position before its evaluation can affect the value subsequently used there; the function supplies no snapshot mechanism.

With stable ordinary storage, each result depends only on that position’s input and the common multiplier. There is no cross-position accumulation, carry, normalization, or numerical dependence on an earlier replacement.

Each position has two value uses in its replacement expression. Their relative evaluation order is not established, and no single captured observation is guaranteed. The stable-input formula applies when these observations agree. If the storage changes during evaluation, the contract does not choose one observation as the authoritative input or promise a result corresponding to any single observed value.

Those abstract uses do not establish an exact number of physical loads. Likewise, the ordered replacements do not establish hardware transaction order, write atomicity, or visibility to another thread or device.

There is no value-dependent normal early exit. Zero inputs, zero multipliers, and zero or wrapped outputs do not suppress later replacements.
