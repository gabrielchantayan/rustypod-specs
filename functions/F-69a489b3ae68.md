# F-69a489b3ae68

## Purpose

F-69a489b3ae68 updates selected control bits in a caller-supplied memory object and conditionally invokes F-21a58352eb84 before synchronizing several 32-bit fields.

The established behavior has three phases:

1. Clear control bit 5.
2. If the 32-bit fields at offsets `0x18` and `0x28` differ, invoke the dependency, adjust additional control bits, and perform three field copies.
3. Clear control bits 6 and 14.

The conditional phase is selected using field values observed **before** the dependency call. The values copied during that phase are read **after** the dependency returns.

An interpretation such as “reconcile active and desired state” is plausible, but not established. The available evidence supplies no authoritative names or meanings for the fields or bits.

## Behavior

### 1. Initial control-word update

Before testing the comparison fields, the function reads the 32-bit control word at offset `0x0C`, clears bit 5, and writes the resulting 32-bit value back to the same location.

The mask is `0xFFFFFFDF`. This update preserves every other bit of the value read at this step.

This is a read followed by a write, not an established atomic bit-clear operation. A write occurs even if bit 5 was already clear.

### 2. Branch selection

After the initial control-word update, the function compares the 32-bit fields at offsets `0x18` and `0x28`.

The evidence establishes that both values are obtained for the comparison at this point. It does not establish the relative order of the two operand reads.

If the values are equal, the function skips the dependency and all conditional field copies, proceeding directly to the final control-word update.

If the values differ, it enters the conditional phase. This decision is not reconsidered after the dependency call.

### 3. Conditional dependency call

On the unequal path, the function calls F-21a58352eb84 with the same base-address argument.

At dependency entry, the initial control-word write has already occurred. The conditional control-word adjustment and the three copies described below have not yet occurred.

No dependency result is used to select subsequent actions. If the dependency returns normally and subsequent accesses remain valid, the function proceeds with the conditional writes.

The dependency may change fields, globals, or other state. Its implementation and preservation guarantees are not available. Consequently, post-call operations must be described using the values actually read after the call, rather than assuming the pre-call values survive.

### 4. Conditional control-word adjustment

After the dependency returns, the function reads the control word at `0x0C` again. It then:

- Clears bit 12.
- Clears bit 13.
- Sets bit 4.
- Preserves all other bits from this particular read.

The clearing mask is `0xFFFFCFFF`; the setting mask is `0x00000010`.

The result is written back to `0x0C`.

This operation does not independently clear bit 5. If the dependency has restored bit 5, this conditional adjustment preserves it.

### 5. Conditional field copies

The following copies occur in order after the conditional control-word write:

1. Read 32 bits from `0x28`, then write that value to `0x18`.
2. Read 32 bits from `0x10`, then write that value to `0x2C`.
3. Read 32 bits from `0x10` again, then write that value to `0x04`.

The source at `0x28` is read after the dependency call. The value copied is not necessarily the value used in the earlier comparison.

The two reads from `0x10` are distinct source-level reads. A single captured value is not specified for both destinations. If the source remains stable, both destinations receive the same 32-bit pattern. If valid execution semantics permit the source to change between those reads, the two destinations can differ.

No arithmetic, byte swapping, sign extension, truncation between different widths, or content interpretation is shown for these copies.

### 6. Final control-word update

Both paths reach a final read-modify-write of the control word at `0x0C`, provided execution has continued normally.

This update clears:

- Bit 6, represented by `0x00000040`.
- Bit 14, represented by `0x00004000`.

The combined preservation mask is `0xFFFFBFBF`. All other bits from this final read are preserved.

The function then returns.

### Stable-memory consequences

If there are no intervening changes to the relevant memory:

- On the equal path, the final control word is the entry control word with bits 5, 6, and 14 cleared.
- On the unequal path, if the dependency also leaves the relevant control bits unchanged, the final control word has bits 5, 6, 12, 13, and 14 cleared, and bit 4 set.

The second statement is conditional on dependency behavior. Without that condition, bit 5 need not remain clear at return.

Likewise, post-return equality between copied fields assumes no later interference. The established operations are the ordered reads and writes, not an unconditional synchronization guarantee.
