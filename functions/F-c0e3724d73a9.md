# F-c0e3724d73a9

## Purpose

F-c0e3724d73a9 scans a byte sequence and returns a Boolean-valued, 32-bit result. It succeeds when it encounters a zero byte at a scan position. It fails when a byte selected for continuation checking does not have its two most significant bits equal to `10`.

The established behavior is narrower than full UTF-8 validation in some respects and more permissive in others:

- Nonzero bytes below `0x80` advance the scan by one byte.
- Bytes from `0xC0` through `0xDF` introduce a two-byte group whose second byte is checked.
- Bytes from `0xE0` through `0xEF` introduce a three-byte group whose second and third bytes are checked.
- Every other byte with its high bit set introduces a three-byte group whose following two bytes are read but not checked.

Consequently, success does not establish that the input is valid UTF-8, that every byte before the stopping point is nonzero, or that the bytes represent valid Unicode scalar values.

**Inferred intent:** The grouping and continuation-bit checks suggest a UTF-8-related structural check. That interpretation does not strengthen the actual acceptance conditions.

## Behavior

### Scan positions and termination

The first scan position is the supplied pointer.

At each scan position, the function first reads the current byte. A value of `0x00` immediately produces result `1`. No subsequent input read is reached on that path.

A zero byte has this terminating meaning **only when it is read as the current byte at a scan position**. A zero in a following-byte position may instead cause failure or be ignored, depending on the current byte’s class.

For a nonzero current byte, the function selects one of the following behaviors.

### Single-byte advancement

For current-byte values `0x01` through `0x7F`, the function advances to the immediately following byte and repeats the scan.

No additional byte is read as part of processing the current byte. The next byte is read when the next scan iteration begins.

There is no additional restriction on this range. Control bytes, whitespace, and printable characters receive the same treatment.

### Checked two-byte groups

For current-byte values `0xC0` through `0xDF`:

1. The byte immediately following the current byte is read.
2. That following byte must be in the inclusive range `0x80` through `0xBF`.
3. A value outside that range produces result `0`.
4. A value inside that range moves the next scan position forward by two bytes from the original position.

The accepted range is exactly the range with high-bit pattern `10`. The function does not reconstruct a character value or impose restrictions dependent on the particular leading byte.

In particular, `0xC0` and `0xC1` are accepted as leading bytes when followed by a byte in the required continuation range. Success on such a group does not establish shortest-form Unicode encoding.

A zero in the second position fails the continuation check; it does not terminate successfully.

### Checked three-byte groups

For current-byte values `0xE0` through `0xEF`:

1. The byte one position after the current byte is read.
2. The byte two positions after the current byte is read.
3. The first following byte is checked for membership in `0x80` through `0xBF`.
4. If that check succeeds, the second following byte is checked against the same range.
5. Any failed check produces result `0`.
6. If both checks succeed, the next scan position is three bytes after the original position.

The read order matters: **both following bytes are read before either continuation check can return failure**. An invalid first following byte therefore does not make the second following-byte location unnecessary.

The two checks are otherwise independent. There are no special restrictions for particular leading bytes or for combinations of the three bytes. The function does not reject overlong three-byte representations or surrogate encodings when their continuation-bit patterns satisfy these checks.

A zero in either following-byte position fails rather than terminates.

### Unchecked three-byte groups

For current-byte values in either of these ranges:

- `0x80` through `0xBF`;
- `0xF0` through `0xFF`;

the function:

1. Reads the byte one position after the current byte.
2. Reads the byte two positions after the current byte.
3. Advances the next scan position by three bytes.
4. Resumes scanning without validating either following byte.

These leading-byte classes are not rejected merely because they fall outside the checked two-byte and three-byte classes.

Both following bytes can have any value, including `0x00`. Their contents do not affect the branch outcome, but their reads still require accessible memory.

This is not four-byte sequence processing. In particular, a current byte from `0xF0` through `0xF7` does not cause the function to validate or consume a four-byte group. The fourth byte becomes the next scan-position byte.

### Repetition and bounds

Scanning continues until a scan-position zero yields `1`, a continuation check yields `0`, or execution cannot proceed normally.

There is no maximum iteration count or byte count. A readable region without a reachable terminating zero or failing continuation check need not yield a normal return.

All advances are byte offsets of one, two, or three. No character count or decoded code point is accumulated. The evidence does not establish pointer width, address-wrap behavior, or a supported maximum input extent. The contract requires valid pointer progression rather than assuming modular address arithmetic.
