# F-cde148df0583

## Purpose

F-cde148df0583 returns a 32-bit integer derived from two indirectly referenced collections of structured entries.

Its established comparison priority is:

1. Compare collection counts.
2. If the initially queried counts agree, scan entries in descending index order, comparing descriptor information and then an entry-level discriminator.
3. Only after that entire pass completes without a difference, perform a separate descending pass comparing entry first words.
4. Return zero if the second pass also completes without a difference.

An ordering operation is **inferred intent**, not a guaranteed mathematical contract. Results are not normalized to −1, zero, or +1. Some paths return arithmetic differences; others return dependency results unchanged. Dependencies can affect subsequent reads, counts are queried repeatedly, and some decisions depend only on the left entry.

The special byte-comparison branch is particularly mutation-sensitive: it retains descriptor addresses but reloads their fields during traversal. Initially equal quantities do not establish an immutable traversal length.

## Interface

### Inputs and representation

The function accepts two addresses, designated **left input** and **right input**. Each addresses a readable 32-bit word containing a collection reference.

The input words are reloaded for collection-count and entry-lookup calls. The function does not capture a single collection reference for the entire operation.

An entry returned by F-6bbddce1b930 must support these accesses:

A referenced descriptor must support:

| 4 | 32 bits | Signed type value |

These are access layouts, not complete object definitions. Allocation sizes, alignment requirements, domain meanings, and lifetime protocols are not established. Address-bearing fields are 32 bits in the supplied representation; compatibility with wider-pointer environments is not established.

### Result

The result is represented as a signed 32-bit integer. It can be:

- A difference between a second pair of count results.
- A descriptor-type difference.
- A descriptor-quantity difference.
- A difference between byte-transformation results.
- An entry-discriminator difference.
- An unchanged result from F-4d3d7560af30, F-7f14f1ab6851, or F-9878699bd825.
- Zero after completion without a decisive difference.

There is no separate error channel. A nonzero dependency result is returned as comparison-controlling data, without determining whether it represents an ordering result or an error.

### Preconditions

There are no visible null, bounds, allocation, or dependency-error checks.

Successful execution requires every input word, entry, descriptor, and selected byte to remain accessible when read. Collection references and indices must be acceptable to the relevant dependencies. Dependencies must return normally.

These requirements continue across calls. In particular, changing a retained descriptor’s data-address field can redirect later byte accesses, but releasing that descriptor can invalidate subsequent reads even if the entry now references a replacement.

Arithmetic and address calculations must also be supported by the execution model. Overflow behavior is not established.

## Behavior

### Count comparison and traversal bounds

The first count query uses the current left collection reference. The next uses the current right collection reference.

If these initial results differ, the function makes two more count queries: left first, then right. It returns the left result of this second pair minus the right result of this second pair. The initial values select the path but do not supply the returned difference.

Consequently, initially unequal counts can lead to a zero result if the repeated queries agree. This path performs no entry lookups.

If the initial counts agree, another left-count query establishes the first pass’s traversal bound. For an ordinary nonnegative result of \(n\), the pass selects indices \(n-1\) through zero. There is no fresh right-count check protecting these accesses.

After the first pass completes, another left-count query independently establishes the second pass’s bound. The two passes can therefore select different sets of indices.

Each pass decrements its index before checking whether it is negative. Under ordinary signed arithmetic, a zero count selects no entries. A negative count other than the minimum signed value also selects no entries. Decrementing the minimum signed 32-bit value raises an unresolved overflow issue.

### First-pass entry selection and type priority

For each selected index, the function looks up the left entry and then the right entry. Those returned entry addresses are retained for that iteration.

After both lookups, it reads descriptor references and compares descriptor types at offset 4. A nonzero left-type-minus-right-type result is returned immediately.

If the type difference is zero, the previously read left type selects the descriptor rule. The function does not revalidate the type after a later dependency call.

The retained entry addresses matter: a lookup or later dependency can change memory reachable through them. The function does not repeat entry lookup during that iteration.

### Matching type 19

The function passes the left entry’s descriptor reference to F-4d3d7560af30.

Only one descriptor argument is supplied. The right descriptor is not supplied to this dependency. No symmetric two-descriptor comparison may be assumed.

A nonzero result is returned unchanged. A zero result permits the entry-discriminator comparison.

### Matching type 22 and left classification 48

For matching type 22, the function calls F-2eb743f270d1 with the left entry’s first word. The special byte rule is selected only if that result is exactly 48. The right entry is not classified.

#### Descriptor capture and initial quantity comparison

After classification returns, the function obtains the descriptor addresses from the retained left and right entries and captures those addresses for this branch.

This timing has two consequences:

- Classification can change which descriptors this branch captures.
- Once captured, replacing an entry’s descriptor reference does not retarget this branch’s descriptor accesses.

The right descriptor’s signed quantity is read and retained for the initial comparison. The left descriptor’s quantity is then read for equality against that value.

If unequal, the descriptor result is a left-quantity-minus-retained-right-quantity difference. The left quantity is read again for that subtraction. No transformation dependency is called on this path.

If equal, traversal begins at byte offset zero. Equality establishes only the initial comparison outcome; it does not capture a fixed byte count.

#### Changing bound and byte sources

Every loop-condition check rereads the signed quantity at offset 0 of the **captured left descriptor**. The current byte offset must be less than that newly read quantity for an iteration to proceed.

For each admitted offset, the observable sequence is:

1. Read the current byte-data address from offset 8 of the captured left descriptor, read the selected byte, and call F-1aef7372e8d8 with that byte.
2. After the left transformation returns, read the current byte-data address from offset 8 of the captured right descriptor, read the selected byte, and call F-1aef7372e8d8 with that byte.
3. Compare the returned transformation results.

Thus the byte-data addresses are not captured for the whole traversal. Each is reloaded for its respective byte access.

The left transformation can change the right descriptor’s data address or its byte contents before the right byte at the **same offset** is read. Either transformation can change data addresses or contents used at later offsets.

Either transformation can also change the left quantity used at the next loop-condition check. Shrinking that quantity does not cancel the current iteration’s right-byte access: the current offset has already been admitted. Increasing it can admit later offsets beyond the initially equal quantity, provided those accesses remain valid.

The right quantity is not rechecked as a traversal bound. Changes to it alone do not shorten or extend the loop.

If transformation results differ, their left-minus-right difference becomes the descriptor result immediately. Otherwise, the offset advances and the left quantity is checked again. Exhausting the current bound produces a zero descriptor result.

Each byte load is one byte wide. The supplied representation does not fully establish how byte values with the high bit set are converted into dependency arguments.

With stable quantities, equal zero or negative quantities admit no byte accesses. Under mutation, the controlling fact is the left quantity observed at each condition check, not merely its initial value.

### Other descriptor cases

The general descriptor rule applies to:

- Matching types other than 19 and 22.
- Matching type 22 when left classification does not return 48.

It subtracts the right descriptor’s signed quantity from the left descriptor’s signed quantity. A nonzero difference is returned immediately.

If the difference is zero, F-7f14f1ab6851 receives the values at offset 8 of the descriptors then referenced by the entries. These values are not established to be strings, buffers, handles, or owned objects.

For type 22, these reads occur after classification. Classification can therefore affect the quantities, descriptor references, and offset-8 values used by this rule.

A nonzero dependency result is returned unchanged. A zero result permits discriminator comparison.

### Entry-discriminator comparison

Whenever the selected descriptor rule produces zero, the function subtracts the right entry’s 32-bit discriminator at offset 8 from the left entry’s corresponding word.

These reads use the retained entry addresses and occur after any classification, descriptor, or transformation calls on that path. Changes made by those calls can therefore affect the result.

A nonzero discriminator difference is returned. A zero difference permits the next lower first-pass index.

### Separate second pass

The second pass starts only after every first-pass entry produces both a zero descriptor result and a zero discriminator difference.

Using a fresh left-count result, it traverses downward. At each index it looks up the left entry, then the right entry, and calls F-9878699bd825 with their first 32-bit words.

The first nonzero result is returned unchanged. If all selected comparisons return zero, the function returns zero.

First-word comparison is not interleaved with the first pass. A first-word difference at a high index cannot outrank a descriptor or discriminator difference found at a lower first-pass index.

### Integer boundaries

Counts, types, quantities, transformation results, and dependency comparison results appear as signed 32-bit integers. Discriminators occupy 32-bit words, but their subtraction’s signed interpretation is not fully established.

Subtraction, index decrement, byte-offset increment, and address arithmetic can encounter representation limits. The supplied material does not establish wrapping, trapping, or other overflow semantics. No overflow-safe mathematical ordering is promised, and arithmetic differences must not be replaced by normalized comparisons as though that were equivalent behavior.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless stated otherwise, assume valid stable memory, normal dependency returns, and arithmetic within representable bounds.

1. **Repeated unequal counts.** Initial and repeated counts are left 5 and right 3. Return 2 without entry lookup.

2. **Initially unequal, subsequently equal counts.** Initial counts are 5 and 3; repeated counts are both 4. Return zero without either entry pass.

3. **Empty collections.** All count results are zero. Neither pass accesses entries; return zero.

4. **Descending type priority.** A first-pass bound of 3 selects index 2 first. Types 7 and 9 produce −2 immediately.

5. **Unary type-19 dependency.** Matching type 19 and F-4d3d7560af30 result 6 produce return value 6. No discriminator is read on that path.

6. **Special branch compares quantities first.** Matching type 22, classification 48, and stable quantities 2 and 5 produce −3 without byte transformations.

7. **First transformed difference.** Equal quantities are 3. Offset 0 transformations agree; offset 1 transformations return 70 and 90. Return −20 without inspecting offset 2.

8. **Bound shrinks during transformation.** Initial quantities are both 3. At offset 0, the left transformation changes the captured left descriptor’s quantity to zero. The right byte at offset 0 is still read and transformed. If the results agree, the next condition check ends traversal.

9. **Bound grows during transformation.** Initial quantities are both 1. During offset 0, a transformation changes the captured left quantity to 2. If results remain equal and both byte sources support the access, offset 1 is examined. The right quantity need not change.

10. **Current right source changes.** During the left transformation at offset 0, the captured right descriptor’s data-address field is redirected to another valid region. The right transformation receives offset 0 from that new region.

11. **Descriptor reference replacement does not retarget capture.** After special-branch capture, a transformation replaces an entry’s descriptor reference. Subsequent byte-loop accesses still use the captured descriptor address. If that address becomes invalid, successful execution is no longer guaranteed.

12. **Stable nonpositive quantities.** Equal special-branch quantities of zero or −2 cause no byte reads. Discriminator comparison follows.

13. **General descriptor dependency.** Matching ordinary types and equal quantities cause F-7f14f1ab6851 to receive the descriptor offset-8 values. Its result of −7 is returned unchanged.

14. **Discriminator decides.** A zero descriptor result followed by discriminators 11 and 4 produces 7.

15. **Entire first pass outranks first-word comparison.** Index 2 has matching descriptor information and discriminator but differing first words. Index 1 has a nonzero descriptor result. Return the index-1 result without calling the final-pass dependency.

16. **Fresh second-pass bound.** The first pass completes with bound 2; the next left count is 1. Only index 0 is selected in the second pass.

17. **Complete equality.** Both passes complete with zero results at every selected position. Return zero.
