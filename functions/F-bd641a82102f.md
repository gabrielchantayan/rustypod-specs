# F-bd641a82102f

## Purpose

F-bd641a82102f coordinates two dependent lookups, acquisition of an interface-like value, preparation of a mutable input copy, and conditional indirect calls.

Its established behavior is to:

- Obtain a shared lookup context.
- Perform two lookups using values read from two distinct global storage locations.
- Transform the second input and request an interface using selector 5.
- If that interface is non-null, expose a mutable copy of the third input to a helper.
- Dispatch through the resulting mutable value after clearing its low bit.
- If that operation returns nonzero, invoke a second indirect operation through the acquired interface.
- If the fourth input is nonzero, invoke a final dependency with the original third input and the first indirect operation’s result.

“Lookup,” “context,” “interface,” and “notification” describe inferred roles. The observable contract is the sequence of reads, calls, branches, and argument values specified below.

## Behavior

### Lookup sequence and global-read timing

After initializing the local copies, the function calls F-9d0ecc5f6adf without explicit arguments. Its result is retained as the context for both lookup calls.

After that dependency returns, the function reads the first global location. It calls F-5710a8628cba with:

1. The retained context.
2. The value read from the first global location.
3. The original first input.

The first global read therefore observes the location after F-9d0ecc5f6adf has completed, not an entry-time snapshot. Any change that dependency makes to the location can affect the lookup argument.

After the first lookup returns, two reads provide arguments for the second lookup:

- The value at the second global location.
- The 32-bit word at offset 0 of the first lookup result.

Both reads occur after the first lookup returns and before the second lookup is invoked. **The supplied representation does not establish an evaluation order between these two reads.** Neither is required to precede the other.

The second call to F-5710a8628cba receives:

1. The same context obtained from F-9d0ecc5f6adf.
2. The value read from the second global location.
3. The offset-0 record word.

The second global value is not an earlier cached value. Changes made by F-9d0ecc5f6adf or the first lookup can affect what is read. The first lookup may also change the first global location, but the function does not explicitly read that location again.

The first lookup result is not checked for null before its offset-0 word is accessed. The second lookup result is retained without a visible validity check.

### Interface acquisition

After the second lookup returns, the function calls F-283eda65a14c with the original second input. Its result is passed to F-682adfd5a561 together with selector 5.

No check of the transformation result is shown before it is passed onward.

If F-682adfd5a561 returns null, the function performs no further explicit work. In that case:

- The two global reads and both lookup calls have already occurred.
- The offset-0 record word has already been read.
- The offset-4 record word is not read.
- F-59c1430f85c2 is not called.
- Neither indirect operation occurs.
- F-0caebad51de4 is not called, regardless of the fourth input.

The null-interface branch is not an early guard for the preceding lookup accesses.

### Mutable-value preparation

For a non-null interface result, the function reads the 32-bit word at offset 4 of the first lookup result and extracts its low 16 bits.

F-59c1430f85c2 receives:

1. The address of the mutable local word initially containing the third input.
2. The retained second lookup result.
3. The extracted value, numerically between 0 and 65,535 inclusive.

The extraction establishes 16 significant bits in this argument. It does not establish that the dependency’s formal parameter occupies only 16 bits.

The offset-4 read occurs after both F-283eda65a14c and F-682adfd5a561 return. It is separate from the earlier offset-0 read. Consequently, the two record words are not captured as one early snapshot. Intervening dependencies may change the record before the later read.

The function does not inspect a return value from F-59c1430f85c2. It uses the mutable local word as it exists when that call returns. The helper may leave the word unchanged or modify it; neither behavior is guaranteed here.

### First indirect operation

The function clears bit 0 of the post-helper local word using the 32-bit mask 0xFFFFFFFE. It uses the resulting value as an address, reads a dispatch-table address there, and selects a callable entry at byte offset 0x28 in that table.

The selected entry is invoked, and its represented 32-bit signed integer result is retained.

The low-bit clearing applies only to address derivation. No explicit write of the cleared value back to the local word is shown. The original third input is not replaced by either the helper-modified value or the bit-cleared address.

No explicit arguments are shown for this invocation. Whether the actual calling convention supplies an implicit receiver or other state remains documented_only.

No null, alignment, table-validity, or callable-entry check precedes this dispatch.

### Conditional interface operation

If the first indirect result is nonzero, the function reads the dispatch-table address from the previously acquired interface and invokes the entry at table byte offset 0x54.

The explicit arguments are:

1. The acquired interface address.
2. The original third input.

The second argument remains the original input even if the helper changed its mutable local copy.

Any nonzero first indirect result enables this call, including a negative result. The condition is not restricted to 1 or to positive values.

If the result is zero, the interface header and its offset-0x54 entry are not read by this branch. The interface operation’s return value is not used.

### Optional final call

After the conditional interface operation, the function tests the fourth input against zero.

When it is nonzero, F-0caebad51de4 receives:

1. The original third input.
2. The retained first indirect result.

This call occurs for either a zero or a nonzero indirect result. If the interface operation is also enabled, that operation precedes the final call.

When the fourth input is zero, the final call is skipped.

All later actions depend on earlier calls returning normally. No visible recovery, error conversion, or cleanup path handles an invalid access, exceptional transfer, or non-returning dependency.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. Except where invalid access is the subject, each assumes required memory is valid and invoked dependencies return normally.

### Global values changed by preceding calls

Suppose F-9d0ecc5f6adf changes the first global location before returning. The first lookup receives the value subsequently read from that location, not its value at function entry.

Suppose the first lookup changes the second global location before returning. The second lookup receives the subsequently read value from that second location. The two global values may happen to be equal or different; neither relationship is required.

An implementation must not impose a contract that the second global read occurs before—or after—the offset-0 record read. Only their placement after the first lookup and before the second lookup is established.

### Null interface

If interface acquisition returns null, both global reads, both lookups, the offset-0 record read, and the second-input transformation have already occurred.

The offset-4 record read, helper, both indirect operations, and final call are skipped. A nonzero fourth input does not change this outcome.

### Zero indirect result with final call enabled

If interface acquisition succeeds, the first indirect operation returns zero, and the fourth input is nonzero:

- The helper precedes the first indirect operation.
- The interface operation is skipped.
- F-0caebad51de4 receives the original third input and zero.

### Negative indirect result

If the first indirect result is a negative represented 32-bit integer, it enables the interface operation. If the fourth input is zero, no final call occurs. If the fourth input is negative, the final call occurs after the interface operation.

### Helper changes the dispatch source

If the original third input is 0x00001001 and the helper changes its local copy to 0x00002001, the first dispatch reads the object header at 0x00002000.

Any subsequent interface operation or final call still receives 0x00001001 as its third-input-derived argument.

### Record masking and late mutation

If the offset-4 word is 0xABCD1234 when read, the helper’s third argument is 0x1234.

If an intervening dependency changes that word before this read, the later value supplies the argument. The earlier offset-0 read does not freeze the record.

### Invalid first lookup result

A null interface result cannot protect an invalid first lookup result: its offset-0 word is accessed before interface acquisition. No particular error return or recoverable failure is established for an invalid access.
