# F-2a7a72e5df47

## Purpose

F-2a7a72e5df47 returns a Boolean indicating whether a value read indirectly through the input equals the original input. The read occurs between two dependency calls. Both calls receive the same derived address.

The established behavior is an ordered sequence of two direct memory reads and two dependency calls, followed by an equality result. The dependency calls are observable parts of the operation, not optional implementation details.

A possible intent is to inspect a relationship while participating in some coordination protocol. That interpretation is **inferred**, not established: the supplied evidence does not identify either dependency as acquiring or releasing a lock, managing a reference, or enforcing any other protocol. This contract therefore describes their call order without assigning those meanings.

## Interface

### Input

The function accepts one integer-valued input, which is also used as a memory address. It is not treated merely as an identifier.

For the descriptions below:

- **Input address** means the original argument.
- **Referenced base** means the integer value obtained by the first direct memory read.
- **Dependency address** means the referenced base plus 4 bytes.
- **Observed value** means the integer value read at the referenced base plus 32 bytes.

These are descriptive terms for values in the contract, not additional parameters or externally visible fields.

### Memory layout accessed

The function directly accesses two locations:

No complete structure layout is established. In particular, the supplied evidence does not establish the size of either containing object, the meaning of intervening bytes, or whether the two locations belong to distinct allocations.

### Output

On normal completion, the function returns true exactly when the observed value equals the original input under the represented integer equality operation. Otherwise, it returns false.

It does not return the referenced base, the dependency address, or either dependency’s result.

### Preconditions

Normal completion requires that the input support the initial read at offset 4, and that the later read at offset 32 from the saved referenced base be valid when that read occurs.

The derived addresses must also be usable under the target’s addressing and arithmetic rules. Alignment requirements are target-dependent and are not supplied.

The first dependency may affect the validity of the later read. An initially valid referenced object is therefore not, by itself, sufficient evidence that the entire operation can complete safely.

## Behavior

### Required sequence

The following order is established for a normally completing invocation:

1. Read the integer at the input address plus 4 bytes. Retain that value as the referenced base.
2. Derive the dependency address by adding 4 bytes to that saved base.
3. Invoke F-4a19e3742733 with the dependency address.
4. After that call returns normally, read the integer at the saved referenced base plus 32 bytes. Retain it as the observed value.
5. Invoke F-fd58bea73663 with the same dependency address used for the first call.
6. After the second call returns normally, return the result of comparing the saved observed value with the original input.

The comparison does not depend on a return value from either dependency.

### Saved addresses and values

The initial reference is read once by this function. A dependency that changes the integer at the input address plus 4 does not redirect the later direct read: that read uses the previously obtained referenced base.

Likewise, the dependency address is determined before the first call. Both calls receive that same derived address even if intervening activity changes the memory from which the referenced base was originally obtained.

The observed value is read after the first call but before the second. Consequently:

- A change made by F-4a19e3742733 to the location at the saved referenced base plus 32 can affect the result.
- A change made by F-fd58bea73663 to that location does not cause this function to reread it.
- A normal-returning second dependency cannot alter which equality result follows merely by changing the memory location after its value has been saved.

These statements describe the direct data flow. They do not assert that either dependency is free of other effects, unusual control transfer, or invalid memory operations.

### Equality and branch behavior

Both dependency calls occur on the normal path whether the observed value matches or differs from the input.

There is no established early false return, special null-input branch, retry, range validation, or alternate lookup path. A mismatch is a normal Boolean outcome; an invalid access is not specified as a false result.

Equality is between the observed integer value and the original integer argument. The function does not compare the observed value with the referenced base or with the dependency address.

### Address arithmetic and overlap

## Side effects

### Direct effects

The function performs two direct integer reads and no direct memory writes.

That narrow statement does **not** make the overall operation read-only. It invokes two dependencies whose transitive reads, writes, resource effects, and external interactions are unknown.

No direct allocation, deallocation, resource acquisition, or resource release is established.

### Dependency-mediated effects

The first dependency executes before the observed-value read. Its changes may therefore affect the loaded value or whether that read remains valid.

The second dependency executes after the observed value has been saved. Its effects occur even when the saved value already determines that the eventual result will be false.

No assumption may be made that either dependency preserves globals, preserves the contents or lifetime of addressed memory, or owns or releases an allocation. The equality result does not establish that the inspected relationship still exists when control returns to the caller.

### Failure and interruption

The function contains no explicit error-result protocol. There is no established conversion of an access fault or dependency failure into false.

If the first dependency does not return normally, the later read and second call are not reached through the shown normal path. If the intermediate read cannot complete, there is no established guarantee that the second dependency runs as cleanup. If the second dependency does not return normally, no Boolean return is established.

Exception unwinding, signal recovery, nonlocal transfer, and cleanup guarantees are documented_only.

## Acceptance examples

These are conditional behavioral examples, not reported executions. Each assumes valid address calculations and accesses, ordinary completion of both dependencies, and a target representation consistent with the values used.

### Matching value

Both dependencies must receive address 8196. If the integer read at address 8224 after F-4a19e3742733 returns is 4096, the function returns true after F-fd58bea73663 returns.

### Nonmatching value

With the same initial addresses, suppose the post-first-call read at address 8224 produces 4100.

The function returns false, but still invokes F-fd58bea73663 with address 8196 before returning.

### First dependency changes the observed location

Suppose address 8224 initially contains a nonmatching value. If F-4a19e3742733 changes that location to 4096 before returning, and the subsequent read obtains 4096, the result is true.

The initial contents of that location do not determine the result; the intermediate read does.

### First dependency changes the initial reference

Suppose the initial read at address 4100 produces 8192, but F-4a19e3742733 later changes address 4100 to 12288.

The direct observed-value read still uses address 8224. The second dependency still receives address 8196. No second read of address 4100 is established.

### Second dependency changes the observed location

Suppose the intermediate read obtains 4096. If F-fd58bea73663 changes that location to another value and returns normally, the result remains true because the comparison uses the saved value.

Conversely, changing a previously read nonmatching value into a matching memory value does not make the result true.

### Invalid reference

If the first read produces a value that cannot support the later access or dependency calls, no successful Boolean outcome is specified. A conforming account must not substitute false, skip a dependency, or invent recovery behavior.
