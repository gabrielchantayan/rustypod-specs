# F-a21141daa905

## Purpose

F-a21141daa905 searches a sequence of candidate positions for the first position at which a comparison dependency reports equality. It returns that position’s traversal index, or −1 if no position is accepted.

The supplied static representation establishes a search over a zero-terminated, byte-addressable region. It does not establish that positions correspond to bytes, characters, Unicode code points, or any particular encoding. Position advancement and the measurements used to limit searching are delegated to dependencies.

The apparent intent is a substring-like search with an initial position to skip. That interpretation is inferred, not a complete established contract: the measurement, comparison, and advancement dependencies are not supplied.

This specification describes the visible behavior of this function, conditional on its dependencies returning and its memory accesses being valid. It does not assign undocumented behavior to those dependencies.

## Interface

### Inputs

The function accepts three inputs:

1. **Container reference.** An address identifying storage with a pointer-valued field at byte offset +4. The function reads that field to obtain the initial search cursor.
2. **Search operand.** A 32-bit value passed unchanged to F-d8cbf9aa79a9 and F-7f14f1ab6851. Although its apparent role is a search pattern, this function does not directly dereference or validate it.
3. **Requested starting index.** A signed integer used to control how many advancement operations precede searching. Under the apparent 32-bit integer model, its range is −2³¹ through 2³¹−1.

The representation explicitly identifies the second input and the field value passed to the measurement dependency as four-byte values. It also presents the other scalar integers and pointers in an apparent 32-bit address model. The original declarations and ABI are not available; width-sensitive behavior below is stated for that apparent model.

### Container layout

Only the pointer-valued field beginning at offset +4 is observed directly. No meaning is established for preceding or subsequent container bytes.

The function does not check whether the container reference itself is null or otherwise readable before accessing this field. A valid container reference is therefore a precondition for defined execution.

A null value in the field is handled: the function returns −1 without invoking any dependency.

### Output

The result is a signed integer:

- A nonnegative traversal index when F-7f14f1ab6851 returns zero at an eligible candidate position.
- −1 when the initial cursor is null, the initial skip encounters a zero byte too early, or searching finishes without a reported equality.

The index counts advancement operations completed since the initial cursor was captured. It is not established as a byte offset.

There is no separate output describing why −1 was returned, and no visible error object or status channel.

### Preconditions

For ordinary completion:

- The container field reads must be valid.
- Every cursor value inspected by this function must permit reading one byte.
- Dependencies must accept their supplied arguments and return normally.
- Arithmetic must remain within the defined range of its signed intermediates.
- Dependency-driven cursor changes must leave subsequent accesses valid.

The function does not enforce these requirements.

## Behavior

### Initial reads and measurements

The function first reads the pointer-valued field at offset +4 and retains that value as its cursor.

If the captured cursor is null, execution ends with −1. Otherwise, two dependency calls occur in this order:

1. F-d8cbf9aa79a9 receives the search operand.
2. After that call returns, the container field at offset +4 is read again, and its then-current value is passed to F-d8cbf9aa79a9.

The first returned word is retained as a signed measurement. The second is retained as an unsigned measurement.

The second field read is significant. The function does not simply measure the captured cursor. If the first dependency call changes the container field, the second measurement receives the changed field value, while traversal still begins from the originally captured cursor.

There is no second null-field check before the second measurement call. Consequently, if the first call makes the field null, that null value is still passed to F-d8cbf9aa79a9.

Both measurements occur before any initial cursor-byte check or starting-index skip. They occur even when the captured cursor already points to a zero byte, and even when the requested starting index is negative.

### Initial position skipping

A traversal counter starts at zero.

While the counter is less than the requested starting index, the function:

- Reads the byte at the current cursor.
- Returns −1 immediately if that byte is zero.
- Otherwise calls F-d3922c7fe0ec with the address of its local cursor slot.
- Advances the traversal counter by one after the call returns.

F-d3922c7fe0ec can replace the cursor through that slot. The function uses the resulting cursor on the next byte check.

A zero or negative requested starting index performs no initial advancement. In particular, a negative input is not rejected and is not interpreted as an index relative to the end; searching begins with counter zero.

If the requested number of advancement calls is completed, the search phase begins at that resulting cursor. Reaching a zero byte exactly after the final requested advancement does not trigger the skip phase’s early-return path. Instead, the search phase observes that zero byte and finishes with −1.

The counter records calls to the advancement dependency, not the physical distance moved. If that dependency leaves the cursor unchanged, a positive requested starting index still consumes the corresponding number of calls.

### Candidate eligibility

Each search iteration first reads the byte at the current cursor.

If the byte is zero, searching ends with −1. The measurement-based eligibility expression is not evaluated on that iteration.

If the byte is nonzero, the function adds the signed traversal counter to the signed search-operand measurement. It then interprets the sum as unsigned and compares it with the unsigned second measurement.

The candidate is eligible only when that unsigned sum is less than or equal to the second measurement. Equality is accepted.

This is not a separately guarded “remaining length” calculation. In particular:

- The search-operand measurement is held as signed.
- The second measurement is held as unsigned.
- The addition occurs before unsigned interpretation.
- Negative measurements are not explicitly rejected.
- Signed overflow is not explicitly prevented.

Under the apparent 32-bit model, a representable negative sum converts to its corresponding unsigned value modulo 2³². If the signed addition itself overflows, the supplied representation does not establish a portable result. Neither wraparound nor saturation should be assumed.

If the eligibility comparison fails, searching stops immediately with −1. The function does not advance and try later positions after that failure.

### Comparison and continued traversal

At an eligible candidate, F-7f14f1ab6851 receives, in order:

1. The current cursor value.
2. The original search operand.
3. The signed measurement obtained from the first F-d8cbf9aa79a9 call.

A return value of exactly zero accepts the candidate. The function immediately returns the current traversal counter, without another advancement call.

Any nonzero return value rejects that candidate. Positive and negative nonzero results have the same visible effect.

After rejection, F-d3922c7fe0ec receives the address of the local cursor slot. Once it returns, the traversal counter is incremented and eligibility is evaluated again, beginning with another cursor-byte read.

The function therefore returns the first accepted candidate in its dependency-defined traversal order, beginning after the initial skip. It does not establish the first match in byte-address order unless the advancement dependency establishes that ordering.

## Side effects

The function has no explicit write to the container field, the search operand’s storage, or the searched region.

Its direct state changes are confined to its local cursor and traversal bookkeeping. It exposes the address of its local cursor slot to F-d3922c7fe0ec, allowing that dependency to modify the cursor used by subsequent operations.

Observable dependency order is:

- Search-operand measurement.
- Fresh container-field read and second measurement.
- Zero or more skip-phase advancement calls.
- Zero or more candidate comparisons, each rejected comparison followed by an advancement call.

The following effects are not ruled out:

- A measurement dependency changes the container field or other shared state.
- A comparison dependency changes memory inspected on a later iteration.
- An advancement dependency changes shared state in addition to replacing the cursor.
- A dependency allocates, releases, retains, or invalidates memory.

No dependency contract is supplied that would justify assuming any of these effects absent. In particular, retaining an old cursor across a dependency call does not establish that its storage remains live.

No allocation, release, ownership transfer, or resource cleanup is directly visible in F-a21141daa905. This does not prove that its dependencies perform none.

The local cursor-slot address is valid during the call. Whether F-d3922c7fe0ec retains that address is unknown; this specification does not grant it a usable lifetime after the enclosing invocation returns.

## Acceptance examples

These examples are conditional contracts, not observed executions. Measurement examples use small nonnegative values so that signed overflow is excluded.

1. **Null initial field.**  
   Given a readable container whose field at offset +4 is null, the result is −1. No dependency is called.

2. **Negative starting index.**  
   Given a nonnull initial cursor and requested starting index −3, both measurement calls occur, but no initial advancement occurs. If the initial byte is nonzero, measurements permit that candidate, and the first comparison returns zero, the result is 0.

3. **Skipping encounters termination.**  
   Given requested starting index 2, an initially nonzero byte, and an advancement dependency that moves directly to a zero byte, the result is −1 after one skip-phase advancement. No comparison occurs.

4. **Skip ends exactly at termination.**  
   Given requested starting index 1 and an advancement that moves from a nonzero byte to a zero byte, one advancement completes. The search phase then returns −1 without comparison.

5. **Inclusive measurement boundary.**  
   Given counter 4, first measurement 3, second measurement 7, and a nonzero current byte, the candidate is eligible because 4 + 3 equals 7. If comparison returns zero, the result is 4.

6. **Boundary failure stops searching.**  
   Given counter 5, measurements 3 and 7, and a nonzero current byte, the candidate is ineligible. The result is −1, with neither comparison nor advancement at that position.

7. **First accepted traversal position.**  
   Given starting index 0, eligible nonzero positions at counters 0 and 1, a nonzero comparison result at 0, and zero at 1, the result is 1. Exactly one search-phase advancement occurs before success.

8. **Zero first measurement.**  
   A zero first measurement does not itself produce success. At a nonzero eligible cursor, the comparison dependency is still called with extent zero. At a zero-byte cursor, no comparison is called and the result is −1.

9. **Container changes during measurement.**  
   Suppose the initial field contains address A, and the first measurement call changes that field to address B. The second measurement receives B, but the retained traversal cursor remains A. This function does not reconcile those two values.

10. **Non-progressing advancement.**  
    If advancement leaves a valid nonzero cursor unchanged, the counter still increases. A later success can therefore return a larger index while comparing the same address.

## Uncertainties

The following remain **documented_only**:

- Whether traversal indices represent bytes, characters, or another unit.
- Whether the two measurements use units consistent with traversal.
- Whether the second measurement describes the retained cursor’s region.
- Original ABI details and authoritative scalar declarations.
- Dependency error, mutation, allocation, release, and aliasing contracts.
- Behavior after invalid accesses, dependency nonreturn, or signed arithmetic overflow.
- Required synchronization when another actor can change the container or searched storage.
- Exact empty-search-operand semantics.

The apparent search intent does not resolve these gaps. In particular, this contract does not promise ordinary string-library behavior, bytewise advancement, successful empty-pattern matching, or dependency purity.
