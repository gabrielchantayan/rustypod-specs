# F-dc4105936e51

## Purpose

The significant ordering constraint is that the associated object’s address is selected **before** the dependency is invoked, while the three values used for the updates are read **after** that invocation. Consequently, the dependency can affect the values subsequently read, but changing the association alone does not redirect those reads.

## Behavior

### Association selection

Before invoking the dependency, the function reads the 32-bit value at destination offset 0. It uses that value as the base of an intermediate region and reads another 32-bit value at intermediate offset 140.

That second value selects the source object for the remainder of the invocation. It is retained across the dependency call. The function does not visibly reload the destination’s association afterward.

This distinction is observable if the dependency changes either address-bearing field. Such a change may affect later invocations, but the current invocation continues using the already selected source address.

Selection does not snapshot the source object’s contents. Only its address-bearing value is retained at this stage.
