# F-181865856679

## Purpose

F-181865856679 performs an initial indirect memory write and then repeatedly processes dependency results, writes to computed addresses, updates carried state, and invokes further dependencies. No normal termination is represented.

The established behavior is an ordered sequence of memory accesses and calls. An application-level purpose is not established. In particular, address-bearing results and three-word storage regions do not establish allocation, object construction, queue management, hardware initialization, or ownership transfer.

This contract describes static evidence. Some arithmetic expressions lack independently established machine semantics, and several incoming state values have no visible initialization. Execution beyond such operations is conditional on the environment supplying meaningful semantics and valid memory.

### Results, storage, and widths

The representation distinguishes:

- 16-bit reads and stores;

- 64-bit dependency results;
- one complete 64-bit store on the larger-address path.

For a 64-bit result, **low word** means bits 0–31 and **high word** means bits 32–63. These are numeric positions, not memory byte order.

Addresses are represented through 32-bit values and pointer conversions. Byte order, alignment requirements, multibyte-access atomicity, and the complete pointer model are not supplied.

### Arithmetic preconditions

Unsigned 32-bit operations have modulo-\(2^{32}\) behavior. Assignment to an unsigned destination does **not** make preceding signed arithmetic unsigned.

In particular, the first-result scaling converts the dependency result to a signed 32-bit integer and then multiplies that signed value by 32. Conversion to unsigned storage occurs afterward. Overflow of the signed multiplication has no established wrapping interpretation.

Other operations involving signed multiplication, signed left shifts, signed address addition, conversion to signed integers, or right shifts of negative values likewise require appropriate environmental semantics. These limitations apply throughout the contract, not only to the explicitly ambiguous branch calculation.

## Behavior

### Initial indirect write

Before the first dependency call, the routine adds the base input and initial offset state using the represented signed arithmetic. At the resulting address it reads an unsigned 16-bit value.

That halfword is zero-extended and used as a destination address for a 32-bit store of the incoming link state. Thus, if the address computation and accesses succeed, the destination’s numeric value lies between 0 and 65,535 inclusive. The four-byte write can extend beyond that range.

There is no visible validation between the read and the indirect write. Zero is not rejected as a destination.

The request word for the first iteration is then set to zero.

### Iteration entry and first-result scaling

Each iteration captures the low eight bits of the current byte-source word before calling F-000000000001 with the request word.

The returned 64-bit result has two separate uses:

- Its high word supplies an address used later on the larger-address path.
- The complete result is explicitly converted to a signed 32-bit integer, which is multiplied by 32 using signed arithmetic. The product is then assigned to an unsigned 32-bit request variable. This assigned value is called the **scaled address**.

The representation alone does not establish a general rule that this calculation multiplies the low word modulo \(2^{32}\). Conversion of an out-of-range result to signed 32 bits requires applicable conversion semantics. Even when that conversion is unambiguous, the signed multiplication can overflow.

If a signed product is representable, subsequent conversion to unsigned is modulo \(2^{32}\). An independently established wrapping machine interpretation could also yield a low-32-bit product, but that is an additional condition, not a consequence of the destination type.

The routine next stores the scaled address as a 32-bit word at the address numerically equal to that value. Only after this self-addressed write does it compare the scaled address, as unsigned, with 20.

For a defined signed multiplication, the unsigned result is a multiple of 32, so a result less than 20 must be zero. The same conclusion holds under an independently established low-32-bit wrapping interpretation. It must not be used to assign behavior to an otherwise unresolved overflowing expression.

### Smaller-address path

If the scaled address is less than 20, the routine selects:

- common-stage argument: zero;
- common-stage dependency: F-000000000004.

It then proceeds to the common stage without the larger-address path’s intervening operations.

This path contains no explicit assignment to the carried word, address state, word-pointer state, link state, or reset object before the common-stage call. Dependency side effects remain possible.

### Larger-address path: preparation and second result

If the unsigned scaled address is at least 20, the following observable operations occur in order:

1. A 32-bit store writes the current address state at scaled address plus 88.
2. A 16-bit store writes the low-width representation of the numeric word-pointer state at address state plus 14.
3. The carried word becomes address state shifted left by two, using unsigned 32-bit arithmetic.
4. The reset object is assigned the captured byte.
5. F-000000000002 is called with the numeric word-pointer state converted to unsigned 32 bits and logically shifted right by two.
6. F-000000000003 is called without explicit arguments.

The result of F-000000000002 is not explicitly consumed.

For the 64-bit result of F-000000000003, this contract names the low word the **payload address** and the high word the **result-word address**. These names distinguish uses; they do not establish object types.

### Larger-address path: ordered stores and state replacements

Following the second result, the represented order is:

1. Store the captured byte at twice the payload address, where the address calculation uses a signed integer conversion followed by signed multiplication by two.
2. Store the low eight bits of the result-word address at payload address plus eight.
3. Store the first dependency result’s high-word pointer representation as a 32-bit value at twice the current link state. This address multiplication is signed.
4. Store the complete 64-bit second result at the payload address.
5. Replace link state with four times the signed integer conversion of the first result’s high-word pointer.
6. Replace address state with the numeric word-pointer state converted to signed integer and shifted left by eight, then assigned to unsigned state.
7. At the first result’s high-word address, store three consecutive 32-bit words: the carried word, the newly assigned address state, and the numeric word-pointer state.

The full 64-bit payload store therefore occurs **before both state replacements and before all three consecutive word stores**. It occurs immediately after the 32-bit pointer store at twice the old link state, with no intervening memory operation.

The link replacement’s signed multiplication and the address replacement’s signed left shift are not established as wrapping operations. In particular, unsigned storage of the new address state does not resolve an overflowing or otherwise invalid signed left shift.

All destinations may overlap. The earlier byte stores may be overwritten by the 64-bit store, and that store may in turn overlap the later three-word region. The specified access order remains significant.

### Derived branch value

After the three consecutive word stores, the numeric word-pointer state is used in a sequence consisting of:

- conversion to signed integer;
- signed left shift by 31;
- signed right shift by 32;
- conversion to unsigned;
- logical right shift by 20.

The signed right-shift count equals the represented operand width. The supplied representation does not establish its result. The signed left shift also has unresolved validity for many inputs.

The resulting value is called the **derived branch value** only to describe subsequent control flow. No reliable input-to-result formula is asserted.

#### Zero-derived path

If the derived branch value is zero:

- The reset object is assigned zero.
- Link state is updated by adding the carried word.
- The resulting 32-bit link representation is stored at the result-word address.
- The common-stage argument is zero.
- The common-stage dependency is F-000000000005.

The addition involves an unsigned carried word, so its 32-bit arithmetic result is modulo \(2^{32}\); assigning that result to signed link state can require implementation-specific conversion semantics. Its stored bit representation must be interpreted under the applicable model.

The reset-to-zero assignment follows the earlier captured-byte assignment, with dependency calls and memory operations between them. The reset object is not assumed to retain the captured byte during that interval.

#### Nonzero-derived path

If the derived branch value is nonzero:

1. Store it as a 32-bit word at 256 times the carried word, plus 32.
2. Form the common-stage argument by converting the unsigned 32-bit product of the carried word and 256 to signed integer, then shifting right by 29.
3. Execute a software breakpoint with immediate value 4.
4. If execution continues, replace address state with the result-word address converted to signed integer and shifted right by 18.
5. Use F-000000000006 as the common-stage dependency.

The carried-word multiplication and addition in the store address are unsigned 32-bit operations. Conversion to signed integer and right-shift behavior require the applicable machine semantics.

The breakpoint is not established as fatal or resumable. Operations after it are conditional on continuation.

### Common stage and iteration transition

The selected common-stage dependency receives the selected argument and supplies a 64-bit result. The following memory operations and calls then occur in order:

1. Store the result’s low 16 bits at the address supplied by its low word.
2. Multiply current address state by 64 using unsigned 32-bit arithmetic, and store that value as a 32-bit word at the address equal to the computed value.
3. Read a 32-bit word through the current word-pointer state. This is the **sampled word**.
4. Store a 16-bit value derived from the numeric current word pointer plus four at address state plus four. The represented calculation narrows the pointer value to a signed halfword before adding four; the destination retains a halfword representation.
5. Read a 32-bit pointer at the common-stage result’s high-word address plus 80, and replace word-pointer state with that pointer.
6. Call F-000000000007 without explicit arguments.
7. Call F-000000000008 without explicit arguments.
8. Replace the byte-source word with the current carried word.
9. Call F-000000000009 with the sampled word.
10. Set the next request word to the sampled word logically shifted right by three.
11. Replace the carried word with the sampled word.

The next iteration then begins.

The pointer-field address in step 5 is formed through signed integer conversion and addition; it is not established as an unrestricted unsigned address addition.

The sampled word is read before the pointer replacement. The halfword store also uses the previous pointer’s numeric value. Conversely, the next iteration’s byte comes from the carried word copied before the final dependency call, not from the sampled word assigned afterward.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests.

### Initial destination is zero-extended

If the initial read succeeds and yields 65,535, the subsequent 32-bit link store targets address 65,535, assuming that destination is writable. The halfword is not sign-extended into a negative address.

### Zero scaling still writes to address zero

If F-000000000001 returns exactly zero, signed conversion and multiplication produce zero. The routine writes a 32-bit zero at address zero before selecting F-000000000004 with argument zero.

If that write faults, the common-stage call is not established as reached.

### Signed overflow does not establish wrapping

If the first dependency returns exactly 134,217,728, conversion to signed 32 bits is representable, but multiplication by 32 produces the mathematical value 4,294,967,296, outside signed 32-bit range.

The supplied representation alone does **not** establish a scaled address of zero or selection of the smaller-address path.

Only if independently established machine semantics retain the product’s low 32 bits does this case yield zero, followed by the address-zero write and smaller-address selection.

### Representable scaling selects the larger path

If the first dependency returns exactly one, scaling produces 32 without signed overflow. A 32-bit value of 32 is stored at address 32 before the larger-address path begins, provided the access succeeds.

### Payload storage precedes state replacement

If the larger-address path reaches the pointer store at twice the old link state, its next memory operation is the complete 64-bit store at the payload address.

Only afterward are link state and address state replaced, followed by the three consecutive word stores. Those words contain the carried word, newly assigned address state, and numeric word pointer, respectively, subject to the required arithmetic semantics.

### Overlapping writes retain their sequence

If twice the old link state equals the payload address, the 32-bit pointer store occurs first and the full 64-bit second-result store follows at the same address.

If the three-word destination also overlaps that region, its later stores can overwrite part or all of the payload representation. No disjointness exception changes the order.

### Zero-derived behavior remains conditional

If the environment gives the ambiguous shift sequence a zero result and preceding operations complete, the routine resets the global object, updates and stores link state, and calls F-000000000005 with zero.

This does not identify which pointer values produce zero.

### Next byte source differs from the sampled word

If the carried word at the trailing copy is 0x12345678 and the sampled word is 0x00000028:

- F-000000000009 receives 0x00000028.
- The next request word is 5.
- The next carried word is 0x00000028.
- The next iteration captures byte 0x78 from its byte-source word.

### Breakpoint continuation is conditional

On the nonzero-derived path, the derived-value store precedes breakpoint 4. The later address-state replacement and F-000000000006 call occur only if execution continues.
