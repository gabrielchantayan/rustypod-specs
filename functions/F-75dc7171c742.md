# F-75dc7171c742

## Purpose

F-75dc7171c742 conditionally transfers control through a global function-pointer value. The dispatch condition depends on a pointer chain rooted in the supplied input and a 32-bit integer reached through that chain.

The established behavior is:

- Return if the pointer-valued field at input byte offset 8 is null.
- Otherwise, obtain a terminal pointer from the beginning of the intermediate storage identified by that field.
- Return if the terminal pointer is null.
- Otherwise, read the terminal storage’s first 32-bit integer and return if it is zero.
- Only after satisfying the nonnull-pointer and nonzero-integer guard, evaluate the global function-pointer value and transfer control through it.

The apparent intent is guarded dispatch. The evidence does not establish what the input represents, why the terminal value controls dispatch, or what operation the target performs.

All behavior below is derived from the supplied static representation. Acceptance examples are conditional requirements, not runtime observations.

## Behavior

### Ordered accesses and early returns

The following order describes evaluation in the recovered representation, not exact physical machine-load counts.

**Initial field evaluation.** The function reads the pointer-valued field at input byte offset 8 and compares it with null.

If that value is null, the function returns. It does not access intermediate storage, read a terminal integer, or evaluate the global target expression.

**Intermediate access.** If the initial field value is nonnull, the representation evaluates the input-relative field again. It reads the four-byte value at the beginning of the intermediate storage designated by that later field value and interprets the result as the terminal pointer.

The initial check therefore does not establish that all subsequent operations use a retained copy of the initially observed intermediate pointer. In particular, the representation contains no second null check on the intermediate pointer obtained by the later field evaluation before dereferencing it.

**Conditional terminal read.** If the terminal pointer is null, no terminal integer is read, and the dispatch condition fails.

If the terminal pointer is nonnull, the function reads its first 32-bit integer. A zero value causes the dispatch condition to fail. Any nonzero value satisfies the integer part of the condition.

**Conditional global target evaluation.** Only after obtaining the terminal pointer, conditionally reading its integer, and satisfying both parts of the guard does the function evaluate the global function-pointer value.

The global target expression is not evaluated on any ordinary early-return path:

- Null input-relative field.
- Null terminal pointer.
- Zero terminal integer.

This distinction covers the target access itself, not merely whether the target is invoked.

**Indirect transfer.** After evaluating the global target value on the selected branch, the function transfers control through that value. There is no visible target-validity or target-null check.

The visible wrapper contains no loop, retry, alternative target, or second dispatch operation.

### Integer widths and arithmetic

The terminal integer is represented as 32 bits and is used only in a comparison with zero. Both positive and negative nonzero values select dispatch. Its magnitude is not used as a count, address displacement, selector index, or arithmetic operand.

The only explicit address displacement is the addition of 8 bytes to the input address. The evidence does not establish overflow behavior for that calculation. A contract requiring 32-bit modular wrapping would exceed the supplied evidence, despite the recovered input width.

No byte order is specified. The zero/nonzero requirements concern the values produced by the target environment’s accesses, not a separate serialized encoding.

### Dispatch and return behavior

The global target is independent of the terminal integer in the visible expression: the integer gates dispatch but is not used to calculate the target.

No explicit arguments appear in the recovered indirect invocation, and no target result is consumed. This does not establish a complete calling convention or exclude meaningful register, stack, or global state at the destination.

The supplied warning says the indirect transfer was represented as a call because its control flow could not be fully recovered. Accordingly:

- Conditional reachability of the indirect transfer is established.
- An ordinary call-and-return mechanism is not fully established.
- If control returns as represented, the wrapper then returns.
- If the target does not return, no alternative wrapper continuation is shown.

### Mutation and synchronization

No locking, atomic access, memory barrier, or snapshot mechanism is visible.

The repeated evaluation of the input-relative field matters if its contents change between evaluations. The contract does not require the second evaluation to reproduce the first value. A later null or invalid intermediate address need not produce a clean early return.

Likewise, the terminal storage or global target can change outside this function unless an external contract prevents it. The function establishes no synchronization or lifetime protection for those locations.

The global target is evaluated on the dispatch branch rather than captured before the guard. This specifies the recovered evaluation structure; it does not establish atomicity, instruction-level ordering, or a safe concurrent-update protocol.

## Acceptance examples

These examples assume stable storage and valid accesses unless stated otherwise. They describe recovered-representation behavior, not measured instruction traces.

### Null input-relative field

Given a readable four-byte field at input byte offset 8 containing null:

- The initial field evaluation occurs.
- The function returns without accessing intermediate or terminal storage.
- The global target expression is not evaluated.
- No indirect transfer or direct memory write occurs.

An invalid value in the global target location does not create a target access on this path.

### Null terminal pointer

Given a stable nonnull input-relative field pointing to readable intermediate storage whose first four bytes represent a null terminal pointer:

- The input-relative field is evaluated for the initial check and again for the intermediate access.
- The terminal pointer is obtained.
- No terminal integer is read.
- The global target expression is not evaluated.
- The function returns without dispatch.

### Zero terminal integer

Given valid, stable nonnull intermediate and terminal pointers, with a terminal integer equal to zero:

- The terminal integer is read.
- The global target expression is not evaluated.
- The function returns without dispatch.

Target validity is not exercised on this path because neither target evaluation nor transfer is reached.

### Positive or negative nonzero integer

Given valid, stable pointers and a terminal integer equal to either 1 or −1:

- Either value satisfies the integer guard.
- The global function-pointer value is evaluated after the terminal integer read and successful guard.
- Control transfers through that target.
- The wrapper contains no repeated dispatch operation.
- Subsequent state and completion depend on the target.

### Target access unavailable

Given valid pointer-chain accesses and a nonzero terminal integer, but an inaccessible global target location:

- Evaluation reaches the global target access.
- Successful dispatch and normal return are not guaranteed.
- No wrapper recovery or error result is specified.

With the same unavailable target location but a zero terminal integer, the recovered representation does not evaluate that location.

### Target does not return

Given a satisfied guard and a valid target that never returns:

- The function reaches the indirect transfer.
- No subsequent wrapper action is established.
- Eventual return to the original caller is not required.

### Input-relative field changes

If the initial field evaluation is nonnull but the later evaluation yields null or another address, use of the initially observed address is not guaranteed.

The later value governs the represented intermediate access. An invalid later address is not required to produce a clean no-dispatch return.
