# F-d343b6628b56

The established behavior is an ordered sequence of four unit transfers, not a source snapshot followed by a bulk replacement. This distinction matters when the regions overlap: an earlier destination write can change a value read by a later transfer.

The apparent intent is to copy a fixed-size, 16-byte payload. The supplied representation does not establish a particular record type, field meaning, byte order, or application-level purpose.

## Behavior

### Established transfer order

| Stage | Source read | Destination write |
|---|---|---|
| 1 | Read the unit at byte offset 0 | Write that value at byte offset 0 |
| 2 | Read the unit at byte offset 4 | Write that value at byte offset 4 |
| 3 | Read the unit at byte offset 8 | Write that value at byte offset 8 |
| 4 | Read the unit at byte offset 12 | Write that value at byte offset 12 |

Each stage obtains its value from source storage as encountered during that stage. All four source values are not visibly collected before destination modification begins.

For non-overlapping ordinary memory, and without concurrent modification, successful completion leaves the four destination units equal to the corresponding source units. The destination’s previous contents are not used to calculate the transferred values.

There are no value-dependent branches. Zero, all-one bit patterns, and other 32-bit values follow the same represented transfer sequence.

### Overlapping regions

The representation contains no overlap check, no direction selection, and no temporary four-unit snapshot.

If a destination write affects storage that a later source read will access, that later read observes the storage after the earlier write, subject to the execution environment’s ordinary memory rules. Consequently, overlap can propagate a value across multiple destination units rather than preserve the source region’s entry-state contents.

If the source and destination start at the same address, each represented stage reads a unit and writes that value back to the same location. In stable ordinary memory, the final contents are unchanged. That final-state result does not establish that writes are absent from the represented behavior, or that accesses to device-backed storage would be harmless.

An overlap arrangement in which writes affect only source units already read does not, by itself, disturb subsequent reads. The relevant distinction is whether a write reaches a future source unit, not merely whether the overall regions intersect.

These overlap observations apply to valid accesses under the execution environment’s memory and aliasing rules. They do not establish support for misaligned, invalid, or otherwise prohibited pointer arrangements.
