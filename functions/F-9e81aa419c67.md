# F-9e81aa419c67

## Purpose

F-9e81aa419c67 performs a fixed sequence of field initialization and dependency calls against a caller-supplied object. It selects one of three label sources according to a discriminator, records byte-sized results from three dependency calls, and derives a 32-bit field from a caller-supplied value that a dependency may modify.

**Established behavior:** the routine makes explicit stores at fixed object-relative offsets and invokes four opaque dependencies in a defined order.

**Inferred intent:** the label-source names suggest filesystem classification, while the byte fields appear to represent flags or capabilities. Neither interpretation is necessary to describe the observable behavior.

The routine exposes no return value or explicit success status. Its effects are object writes and whatever additional effects its dependencies perform.

## Behavior

The following ordering describes the routine’s own operations. It does not assume that dependencies preserve the object, global state, or other memory.

### 1. Initial byte stores

1. Store 1 at +0x310.
2. Store 1 at +0x313.
3. Store 0 at +0x311.
4. Store 0 at +0x314.
5. Store 0 at +0x312.
6. Store 0 at +0x315.

These are individual byte stores, not an established atomic update of a six-byte region. The order differs from ascending address order.

The routine next copies the initial quantity into a temporary 32-bit unsigned storage location. This occurs before the label-selection dependency call. There is no direct read of any preexisting object field in the supplied body.

### 2. Discriminator-dependent label selection

Exactly one call to F-7cfd4da96bb8 occurs on a normally progressing invocation. All branches pass:

- the object-relative destination +0x2FC;
- the numeric argument 20;
- one of three source references.

The branches are:

| Discriminator | Selected source identifier | Store after the call returns |

The branch-specific flag store follows the dependency call. Thus, if that call modifies +0x312 in the discriminator-1 branch, the routine subsequently overwrites that byte with 1. The analogous rule applies to +0x315 in the discriminator-2 branch. No corresponding post-call reset occurs in the default branch.

All discriminator values other than 1 and 2 use the same default branch, including zero and negative signed values. There is no explicit rejection path.

Only the byte-sized values assigned by these calls are established. The body does not normalize them to Boolean values, reject values other than 0 and 1, or branch on their contents. Their signedness, meaning, and any wider return representation are not established.

### 5. Quantity transformation and final store

The routine calls F-831eb8178d08 with:

- numeric first argument 0;
- the address of the temporary 32-bit quantity as the second argument.

After that call returns, the routine reads the temporary quantity, performs an unsigned right shift by 20 bits, and stores the 32-bit result at +0x31C.

The final stored value is therefore determined by the temporary’s **post-call** contents, not necessarily by the original fourth argument.

For a post-call value \(q\) in the unsigned 32-bit range:

\[
\text{stored value}=\left\lfloor\frac{q}{2^{20}}\right\rfloor
\]

Consequently, this store writes a value from 0 through 4095 inclusive. The lower 20 bits of \(q\) do not affect it. No rounding upward, signed extension, saturation, or additional scaling is shown.

There are no further explicit object writes or dependency calls after this store. The routine then returns without a value.
