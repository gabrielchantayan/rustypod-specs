# F-b0b7323f724e

## Purpose

F-b0b7323f724e updates control flags in a caller-supplied object and, unless an early-exit condition applies, prepares an embedded record for possible insertion into a global singly linked list. A nonzero interval causes the record to receive a calculated deadline and to be inserted at a position selected by an external comparison function. The function subsequently performs a global notification step and may invoke an indirect callback.

**Established behavior:** byte and word writes, dependency-call order, early-return conditions, list traversal, and list-link updates are visible in the supplied static material.

**Inferred intent:** the embedded record appears to represent a scheduled operation. Some dependencies appear consistent with initialization, synchronization, and wake-up behavior. Those interpretations are not guarantees.

The function has no explicit return value. Its observable results are object mutations, global-list mutations, dependency calls, and any effects produced by those dependencies.

## Behavior

### 1. Initial flags and first early exit

The function performs these operations in order:

1. Write the byte value 1 at B + 0x69.
2. Write the byte value 1 at B + 0x6A.
3. Read the 32-bit word at B + 0xD0 and call F-342542431c39 with that value.
4. Return immediately if the result equals 0x6038.

The equality check uses that exact value. No other result is treated as this early-exit condition.

On this path, the function itself does not clear B + 0x68 or access the embedded-record fields. F-342542431c39 may have effects not described by the supplied material.

### 2. Preliminary operations and second early exit

If the first result is not 0x6038, the function:

1. Calls an unresolved dependency with arguments B, 1, and 1.
2. Calls another unresolved dependency with arguments 0 and 0x20.
3. Calls a third unresolved dependency with no explicit arguments.
4. Writes the byte value 0 at B + 0x68.
5. Calls F-c60499d3eebf.
6. Returns if that call’s result is nonzero.

The byte clear therefore precedes the second early-exit decision but follows all three unresolved calls. There is no visible rollback when this return occurs.

### 3. Embedded-record preparation and membership gate

If F-c60499d3eebf returns zero, the function:

1. Calls F-936a8728139d with B + 0x98.
2. Obtains the 32-bit selection default.
3. Reads the byte addressed by the selection flag pointer.
4. Uses the 32-bit value 200 instead of the default only if that byte equals exactly 1.
5. Calls F-6904f7699031 with B + 0x98 and the selected value.
6. Calls F-936a8728139d again. No explicit argument is shown for this invocation.
7. Reads the record-state source and writes it to B + 0xB8.
8. Reads the 32-bit word at B + 0xB4 and returns if it is nonzero.

The selection default is obtained before testing the flag, including when the flag causes that default to be replaced. A flag byte of 2, 255, or any other value besides 1 does not select 200.

The record-state write precedes the membership check. A record that already has a nonzero membership field still undergoes the preceding calls and receives the write at offset 0xB8.

The second invocation of F-936a8728139d has an unresolved argument contract. It must not be silently treated as an established repeat of the first invocation.

### 4. Entry operation and interval-dependent insertion

If the membership field is zero, the function calls F-338d16f9ce72 with the current entry/terminal cell pointer, then calls F-add44d4e9aaa with B + 0x98.

Only after both calls does it read the 32-bit interval at B + 0x9C. Consequently, the interval used is not an entry-time snapshot; earlier dependencies can affect the value observed here.

If the interval is zero, the function skips deadline calculation and list insertion and continues with the notification phase.

For a nonzero interval:

1. Call the unresolved time-like dependency.
2. Capture the current list-head cell pointer.
3. Calculate the deadline-like word from the dependency result plus the interval multiplied by 1000.
4. Write the calculated word at B + 0xA0.
5. Read the insertion-state source and write it at B + 0xB0.
6. Read the list head through the captured head-cell pointer.
7. Traverse the list and insert the embedded record.

The calculation uses the interval value read before the time-like call, not a later reread. The visible operands and destination are 32 bits. No widening, overflow check, saturation, or range rejection is shown. Negative nonzero intervals are not excluded.

For values whose mathematical result exceeds the representable 32-bit range, the supplied material does not establish a portable arithmetic contract. The exact target overflow behavior is **documented_only**.

### 5. List traversal and insertion

Traversal begins with the captured head value and no predecessor.

For each non-null candidate, F-0d70d6f9010c receives:

- The candidate address plus 8 bytes.
- B + 0xA0.

A zero comparison result means “continue traversal.” Any nonzero result means “stop at this candidate.” The visible code does not distinguish positive from negative results.

After a zero result, the next candidate is read from the current candidate’s first 32-bit word, and that candidate becomes the predecessor. This next-link read occurs after the comparison call. The link is not cached before the call.

Traversal stops at either a null candidate or the first candidate yielding a nonzero result. Insertion then performs these writes in order:

1. If there is no predecessor, write B + 0x98 into the captured head cell. Otherwise, write B + 0x98 into the predecessor’s first word.
2. Write the 32-bit value 1 at B + 0xB4.
3. Write the stopped-at candidate, possibly null, into B + 0x98.

Thus the record is published through the head or predecessor link before its membership field and next link are written. The function itself does not show atomic publication, memory barriers, or a concurrency guarantee. Any safe concurrent interpretation depends on external behavior not supplied here.

No built-in ordering relation is established beyond the comparison result convention. Equal-deadline placement, signed ordering, wrap-aware ordering, and tie stability depend on F-0d70d6f9010c.

### 6. Notification and final indirect call

After the zero-interval path or completed insertion, the function:

1. Calls F-5bcae2eff9a7 with the current notification argument.
2. Reloads the entry/terminal cell pointer and reads the pointer stored in its addressed cell.
3. If that stored pointer is non-null, reads its first 32-bit word.
4. Returns if the stored pointer is null or its first word is zero.
5. Otherwise, calls the current indirect target with no explicit arguments, then returns.

The entry/terminal cell pointer is read again after notification. It is not necessarily the same value previously passed to F-338d16f9ce72.

The first word read from the pointed-to object is only a nonzero gate. It is not the call target. The call target comes from a separate global function pointer.

## Side effects

Direct side effects include:

- The two initial flag writes on every normally entered path.
- Clearing B + 0x68 only after the first early-exit condition has been bypassed.
- Writing B + 0xB8 before testing membership.
- For nonzero intervals with zero membership, writing the deadline, insertion-state field, membership field, and next link.
- Updating either the global head cell or a predecessor node’s link.
- Invoking dependencies in the order specified above.

There is no visible allocation, release, list removal, retry, rollback, or explicit error report. This does not establish that dependencies avoid such effects.

The function does not visibly clear B + 0xB4 on any path. A zero interval leaves that field zero only if no dependency changes it.

No dependency is assumed to preserve globals, object fields, or memory ownership. Statements about fields remaining unchanged refer only to direct writes by F-b0b7323f724e.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless a case says otherwise, assume valid memory, returning dependencies, and no dependency mutation of the fields or globals relevant to the example.

1. **First early exit.**  
   If F-342542431c39 returns 0x6038, offsets 0x69 and 0x6A have each been written to 1. No subsequent dependency is called by this function, and offset 0x68 is not directly cleared.

2. **Second early exit.**  
   If the first result differs from 0x6038 and F-c60499d3eebf returns a nonzero value, all three preliminary calls occur, offset 0x68 is cleared, and embedded-record preparation does not begin.

3. **Exact selection flag.**  
   With a selection default of 75, flag byte 1 causes F-6904f7699031 to receive 200. Flag byte 2 causes it to receive 75.

4. **Existing membership.**  
   If offset 0xB4 is nonzero when tested, the preparation calls and offset 0xB8 write still occur. F-338d16f9ce72, insertion, notification, and the final indirect call do not occur.

5. **Zero interval.**  
   With membership zero and interval zero, F-338d16f9ce72 and F-add44d4e9aaa occur, but the time-like call, comparisons, and direct insertion writes do not. Notification and the final gate still occur.

6. **Insertion into an empty list.**  
   With a nonzero interval and null head, no comparison is needed. The head cell receives B + 0x98, membership becomes 1, and the embedded next link becomes null, in that order.

7. **Insertion before the head.**  
   If the first comparison returns any nonzero value, the embedded record becomes the head and its next link receives the former head.

8. **Insertion after traversed nodes.**  
   If comparisons return zero for two nodes and nonzero for a third, the second node links to the embedded record, which links to the third. If traversal instead reaches null, the embedded record is appended.

9. **Representable deadline.**  
   With interval 3 and a time-like result of 10,000, offset 0xA0 receives 13,000.

10. **Final callback gate.**  
    A null terminal pointer suppresses the pointed-to word read and indirect call. A non-null pointer with first word zero suppresses only the indirect call. A non-null pointer with a nonzero first word permits the separate indirect target to be called.
