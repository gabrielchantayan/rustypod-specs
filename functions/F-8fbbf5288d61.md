# F-8fbbf5288d61

## Purpose

F-8fbbf5288d61 locates a 32-bit value within a caller-supplied collection and reports a position through the low 32 bits of its recovered return value.

Two modes are selected by a field in the collection descriptor:

- A zero callback field selects a forward scan using exact 32-bit equality.
- A nonzero callback field selects preparation through F-d796b23b1c27, followed conditionally by a search through F-fee6c1b981c0 and a backward adjustment using the descriptor’s callback.

The backward adjustment is broader than a search for equal predecessors: it continues whenever the callback returns a nonnegative signed result. Describing this operation as “find the first equal element” would require additional comparator and ordering guarantees that the supplied evidence does not establish.

The recovered return is 64 bits wide, but only its low 32 bits consistently represent a result. Its upper half has path-dependent provenance and must not be treated as a uniform success indicator.

## Interface

### Inputs

The function receives two arguments:

1. **Collection descriptor address.** A nullable pointer to storage viewed as 32-bit words.
2. **Requested value.** A 32-bit integer used as the exact-match target in scan mode and as the initial contents of a temporary search key in callback mode.

The descriptor has the following directly observed layout:

| Byte offset | Width | Observed use |
|---|---:|---|
| 0 | 32 bits | Element count; interpreted as signed by the forward-scan condition |
| 4 | 32 bits | Base address of element storage |
| 8 | 32 bits | No direct access by this function |
| 12 | 32 bits | No direct access by this function |
| 16 | 32 bits | Callback address; zero also selects scan mode |

The supplied representation uses 32-bit address-bearing words and four-byte elements. It does not establish a portable representation for platforms with wider pointers.

Each element occupies four bytes. No element structure beyond that width is established.

### Output

The recovered output is a 64-bit quantity composed of two 32-bit halves:

- **Low half:** a located or calculated position, or the bit pattern representing signed −1.
- **High half:** an incoming stack-associated value on paths that do not explicitly assign it; on a path that invokes F-fee6c1b981c0, the callback word captured immediately before that invocation.

For ordinary callers interested in location results, the relevant interpretation is the low half as a signed 32-bit integer. A low-half value of −1 is the explicit failure result, but malformed search results or unsupported arithmetic can also produce that bit pattern.

The full 64-bit return is not established as a clean signed index, a Boolean, or a stable pair of public API fields.

## Behavior

### Null descriptor

The descriptor address is tested first.

If it is null:

- No descriptor field or element is read.
- Neither dependency is called.
- The low return half is −1.
- The upper return half is not explicitly initialized by this path.

### Mode selection

For a nonnull descriptor, the callback word at byte offset 16 is read.

A zero word selects exact forward scanning. A nonzero word selects callback-based processing.

This initial choice is not revisited after F-d796b23b1c27 runs. In particular, callback mode does not switch to the forward scan if preparation changes the callback field to zero.

### Exact forward scan

The scan begins at position zero and visits positions in increasing order.

For each candidate position:

1. The current position is compared with the descriptor’s count using a signed comparison.
2. If the position is below the count, the element-storage address is obtained from the descriptor.
3. The four-byte element at that position is read and compared with the requested value.
4. Equality ends the scan immediately and returns that position in the low half.

The scan returns the earliest exact match encountered in increasing index order.

If the count is zero or negative, no element is read and the low-half result is −1. If all inspected elements differ from the requested value, the low-half result is also −1.

A requested value of zero is fully searchable in this mode. It is not treated as a sentinel.

The descriptor’s count and storage address are expressed as field accesses during the scan rather than as an explicit immutable snapshot. There are no intervening calls in this path. The evidence does not establish synchronization or supported behavior under concurrent modification.

### Callback-mode preparation

Before calling F-d796b23b1c27, the function places the requested value into a local 32-bit key object.

F-d796b23b1c27 is then called with the descriptor address. This call occurs even when the requested value is zero, the count is zero, or the count is negative.

The dependency’s body is unavailable. Preparation may affect descriptor fields, element storage, global state, ownership, or other state; none of those effects may be assumed absent.

After preparation returns, the temporary key is checked against zero.

- If it is zero, no search dependency or callback is invoked by this function, and the low-half result is −1.
- If it is nonzero, callback-mode processing continues.

The directly shown initialization makes a requested value of zero take the no-search path under ordinary execution in which the preparation dependency does not alter the local key through an otherwise unavailable alias. The established behavioral condition is the key’s value at the post-preparation check.

### Search invocation

For a nonzero temporary key, the current callback word is captured from the descriptor.

F-fee6c1b981c0 is invoked with six arguments, in this order:

| Position | Argument |
|---|---|
| 1 | Address of the local four-byte key |
| 2 | Current descriptor element-storage address |
| 3 | Current descriptor count word |
| 4 | Element width, exactly 4 |
| 5 | Captured callback word |
| 6 | Descriptor address |

The source establishes this argument list, but not the ordering of individual field-load instructions used to prepare it.

The count is forwarded without a visible positivity check. This includes zero and negative count bit patterns. The signedness and meaning assigned to that argument inside the dependency are unknown.

The key is supplied by address. Its preservation cannot be assumed: later callback calls use the same local object, including any changes made by the search dependency.

No null-callback check is performed here. If preparation changed the callback field to zero, zero is passed as the fifth argument.

A zero return from F-fee6c1b981c0 produces low-half −1.

### Converting a nonzero search result

A nonzero search result is treated as an address-like 32-bit value.

The descriptor’s element-storage address is read again after the dependency returns. The function derives a position by subtracting that current address from the search result, then applying a signed right shift by two bits.

This is not necessarily relative to the base address passed into the dependency. If that dependency changes the descriptor’s base, the changed base participates in the conversion.

For a valid result pointing to a four-byte element in the unchanged array, this yields its zero-based index. Outside that condition:

- No alignment check is performed.
- No containment check is performed.
- No check against the descriptor count is performed.
- A nonpositive derived position can be returned without any callback invocation.
- An unaligned displacement is shifted rather than rejected.

The recovered operations are 32-bit subtraction followed by signed shifting. Ordinary index interpretation requires a representable displacement under the actual target arithmetic. Exact overflow and invalid-pointer semantics are not independently established by the supplied representation.

### Backward adjustment

If the derived position is positive, the function examines the immediately preceding element through the callback currently stored in the descriptor.

Each callback receives:

1. The address of the four-byte element immediately before the current position.
2. The address of the temporary key.

The callback result is interpreted as a signed 32-bit integer:

- A negative result stops adjustment.
- Zero or a positive result decreases the position by one.
- Reaching position zero stops adjustment without inspecting a predecessor before the array base.

The result does not need to be exactly zero to continue. A positive result also causes movement toward the beginning.

The callback address and element-storage base are obtained from the descriptor for callback evaluation. They are not guaranteed to remain the same as the callback and base passed to F-fee6c1b981c0. Changes made by preparation, search, or a prior callback can therefore affect later behavior.

There is no forward adjustment, no validation that the element at the final position equals the key, and no final bounds check.

That direct-access description is not a purity or ownership guarantee:

- F-d796b23b1c27 receives the descriptor.
- F-fee6c1b981c0 receives the descriptor, element-storage address, and a writable-looking key address.
