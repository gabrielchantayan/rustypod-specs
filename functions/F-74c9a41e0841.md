# F-74c9a41e0841

## Purpose

The supplied static representation describes a procedure that performs ordered 32-bit and byte-sized memory writes, interleaves them with opaque indirect calls, and enters an unconditional repeating call-and-write sequence.

No application-level purpose is established. The evidence does not identify object initialization, serialization, device control, or a recognized algorithm.

This contract distinguishes:

- **Established static evidence:** explicit accesses, call ordering, result forwarding, and address-state transitions in the supplied representation.
- **Conditional interpretation:** arithmetic outcomes under the 32-bit machine interpretation defined below.
- **Unknowns:** actual dependency behavior, memory validity, calling convention, and executable behavior where recovery is unreliable.

The representation includes warnings about invalid instruction data and removed unreachable regions. This contract describes the visible recovered behavior, not a verified execution of the original executable.

### Result, preconditions, and termination

If every call returns normally and every access succeeds, execution enters and remains in an unconditional loop. A fault, nonreturning dependency, or discrepancy in recovered control flow can prevent that continuation.

### Arithmetic and access conventions

For conditional arithmetic statements:

- Words and numeric addresses are 32-bit bit patterns.
- \(M_k(x)\) denotes multiplication by \(k\), retaining the low 32 bits.
- Address additions retain the low 32 bits.
- \(\operatorname{low8}(x)\) denotes the least significant eight bits.
- Right shifts of unsigned quantities are logical.
- A word write transfers 32 bits; a selector read and a byte write each transfer eight bits.

These conventions do not establish portable language semantics for signed overflow or signed left shifts. Endianness and alignment requirements remain unknown.

## Behavior

### Ordered dependency notation

Dependencies have opaque call-site IDs. Different IDs do not prove different function identities, and one recurring call-site ID does not guarantee an unchanged target.

Two notation patterns describe repeated sequences without introducing additional callable functions:

- **\(T_n\):** invoke `F-Dnn-0` with the listed arguments, then `F-Dnn-1` through `F-Dnn-4` in order, each with no explicit arguments. The sequence result is the ordinary result of `F-Dnn-4`.
- **\(Q_n\):** invoke `F-Dnn-0` with the listed arguments; invoke `F-Dnn-1`; pass its result to `F-Dnn-2`; invoke `F-Dnn-3`; pass its result to `F-Dnn-4`; then invoke `F-Dnn-5` through `F-Dnn-8`. Calls without a stated argument receive no explicit arguments. The sequence result is the ordinary result of `F-Dnn-8`.

“No explicit arguments” does not exclude implicit register or memory inputs. All calls remain ordered operations, including calls whose ordinary results are discarded.

### Loop-target transition

The first call in the loop, `F-D17-0`, does **not** have one invariant numeric target.

Its target expression adds \(\texttt{0xFFE}\) to address state. That state has different values on initial entry and on the back edge:

| Entry into `F-D17-0` | Address state used | Resulting numeric target |
|---|---:|---:|
| First iteration | \(\texttt{0x08832789}\) | \(\texttt{0x08833787}\) |
| Every subsequent iteration | \(\texttt{0x088327C7}\) | \(\texttt{0x088337C5}\) |

The initial address state is established before loop entry. The later value is established during the second tail sequence and remains the relevant address state at the next iteration.

Under the stated 32-bit interpretation, these target expressions differ by \(\texttt{0x3E}\), or 62 bytes. This transition is independent of the loop’s argument-state transition.

`F-D17-0` therefore denotes a recurring invocation site, not a proven single dependency identity. The two numeric targets must not be assumed behaviorally equivalent. Whether they ultimately represent distinct executable functions, aliases, alternate entries, or invalid targets remains unknown.

2. Let \(\pi\) be the result of `F-D17-4`.
3. Read one unsigned byte at the preserved address \(K\).
4. Write zero at that byte’s value plus 17.
5. Invoke \(T_{18}(M_4(\pi))\), producing \(\rho\).
6. Carry \(M_4(\rho)\) as the next loop input.
7. Carry \(M_{2^{26}}(\rho)\) as the next loop state.
8. Re-enter the loop with the later-iteration target state described above.

There is no visible termination condition.

Because the initial state \(S\) is at most 31, the shifted-state argument to the first `F-D17-0` invocation is zero. On subsequent iterations it is:

\[

=
(\rho\mathbin{\&}63)\times2^{18}.

The multiplication is truncated to 32 bits before the logical right shift. It is not an unbounded multiplication followed by division.

## Side effects

### Explicit memory effects

The visible normal path performs:

- Twelve word writes before the byte phase.
- Six byte writes before loop entry.
- Five selector-byte reads before loop entry.
- One selector-byte read and one zero-byte write per loop iteration.

The six pre-loop byte writes comprise two writes through \(J+1\), one direct write based on \(H\), two further zero writes through \(J+1\), and one zero write through \(K\).

Every selector-based write uses a fresh byte read. Neither the destination nor the selector value is cached across these accesses.

No address validation, alignment check, ownership check, or overlap check is visible. The recurring offset 20 does not establish an object layout or field boundary.

### Aliasing and observation

The representation establishes no disjointness among word destinations, byte destinations, selectors, dependency-accessible memory, or executable memory.

An explicit write can therefore affect a later selector read if the addresses overlap. Dependencies can also change selectors or previously written locations; their preservation is not assumed.

The procedure provides no visible atomicity or rollback. Earlier effects remain possible when a later call fails to return or an access faults. Repeated zero writes cannot be omitted merely because their payloads match.

### Ownership and errors

## Acceptance examples

These are conditional static consequences, not runtime observations.

1. **Initial effect survives unsuccessful continuation.**  
   If the first word write succeeds and `F-D00-0` then fails or never returns, \(A\) has already been written at \(M_4(A)+20\). No rollback is visible.

2. **Unused explicit argument.**  
   Changing only \(B\) changes no explicit expression listed here. Identical overall behavior is not guaranteed because opaque dependencies may inspect additional machine state.

3. **Unsigned shift boundary.**  
   For \(C=127\), the fourth argument to `F-D02-0` is zero. For \(C=128\), it is one.

4. **Byte truncation.**  
   If \(\lambda=65\), the first byte payload is four: multiplication produces 260, whose low eight bits are four.

5. **Reloaded selector.**  
   If the first read at \(J+1\) yields 3, that write targets address 20. If the next read yields 9, its write targets address 26. Reusing the earlier destination would contradict the visible accesses.

6. **Mask, shift, then truncate.**  
   If \(\lambda=\texttt{0x3FF00000}\), the second byte payload is 255. The masked shift produces 1023 before byte truncation.

7. **Loop target changes despite equal arguments.**  
   If execution reaches a second iteration and both invocations happen to have identical argument values, the first invocation of `F-D17-0` still uses numeric target \(\texttt{0x08833787}\), while the second uses \(\texttt{0x088337C5}\). Argument equality does not remove the target transition.

8. **Loop argument-state transition.**  
   The first shifted-state argument is zero. If the first \(T_{18}\) result is 1, the second iteration receives loop input 4 and shifted-state argument \(\texttt{0x00040000}\), at the later-iteration target.

9. **No normal finite completion.**  
   If all calls return and accesses succeed, iteration continues. Returning after one iteration, or retaining the initial `F-D17-0` target indefinitely, would contradict the visible control flow and address-state transition.
