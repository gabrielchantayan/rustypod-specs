# F-e03b1f76037b

## Purpose

F-e03b1f76037b performs a fixed sequence of raw memory transfers and overwrites, then invokes an unresolved indirect dependency with four arguments. Its meaningful output is the resulting memory state and the effects of that invocation, not a returned value.

The supplied static representation establishes access widths, offsets, data dependencies, and ordering. It does not establish a domain-level purpose, valid object types, or a conventional public calling interface. In particular, three incoming machine-state values are used without being supplied by the two declared parameters.

This contract therefore describes the observed memory protocol without assigning application meanings to its fields. All behavior is conditional on the required accesses being valid and on the unresolved indirect invocation being executable.

## Behavior

### 1. Repeated entry writes

The first phase contains eight complete four-write groups followed by a two-write partial group. The repetitions are observable behavior and must not be collapsed when access order matters.

The first complete group performs these writes in order:

1. One byte, b, to A plus `0x11`.
2. One word, Q, to B plus `0x34`.
3. One word, P, to D plus `0x54`.
4. One byte, a, to B plus `0x19`.

Each of the next seven complete groups performs the same four writes in the same order, except that the word written to B plus `0x34` is D rather than Q.

The final partial group writes:

1. One byte, b, to A plus `0x11`.
2. One word, D, to B plus `0x34`.

Thus this phase contains 34 stores:

- Nine byte stores to A plus `0x11`.
- Nine word stores to B plus `0x34`, the first carrying Q and the remaining eight carrying D.
- Eight word stores of P to D plus `0x54`.
- Eight byte stores of a to B plus `0x19`.

There are no displayed intervening memory reads in this phase. Q is overwritten at its destination, but its initial store is still part of the contract. Aliasing, memory-mapped destinations, or faults can make the intermediate writes significant.

### 2. Initial captures and state updates

The following accesses occur in order:

1. Read a word from absolute address `0xA9`; retain it as W.
2. Read a word from P plus `0x74`; retain it as X.
3. Write one byte to absolute address `0x3A`, equal to twice a plus `0x30`, truncated to eight bits.
4. Read a word from C plus `0x14`; retain it as Y.
5. Read a word from A plus `0x04`; retain it as Z.
6. Write a to C plus `0x0D`.
7. Write byte `0x6C` to A plus `0x08`.
8. Write b to A plus `0x0D`.
9. Write b to A plus `0x09`.
10. Write the full value C to C plus `0x54`.
11. Write the low byte of W to absolute address `0x67`.
12. Read a word from C plus `0x44`; retain it as T.
13. Copy the current byte at absolute address `0x67` to absolute address `0x21`.
14. Write the low byte of T to A plus `0x10`.
15. Write T as a word to B plus `0x54`.
16. Write one byte to C plus `0x01`, derived by right-shifting T by a.
17. Write A as a word to B plus `0x54`, replacing the preceding T store at that location.

The shift is represented as a signed right shift. Exact behavior for negative T and for counts of 32 or more is not established by the supplied evidence. For nonnegative T and counts from 0 through 31, the byte is the low byte of the ordinary right-shift result.

The copy through absolute address `0x67` is a memory read, not an unconditional reuse of the low byte of W. Any relevant aliasing or externally changing memory must be respected.

### 3. Cross-object word transfers and byte overwrites

Execution continues in this order:

1. Read a word from A plus `0x40`; retain it as U.
2. Write Z to B plus `0x74`.
3. Write U to A plus `0x10`.
4. Write C to B plus `0x44`.
5. Copy the current byte at absolute address `0x67` to A plus `0x09`.
6. Write W to A plus `0x44`.
7. Read a word from A plus `0x54`; retain it as R.
8. Again copy the current byte at absolute address `0x67` to A plus `0x09`.
9. Write the low byte of X to R plus `0x0D`.
10. Write Y to C plus `0x54`.
11. Read a word from A plus `0x14`; retain it as V.
12. Write the low byte of X to C plus `0x11`.
13. Write the low byte of R to A plus `0x09`.
14. Write R as a word to A plus `0x44`.

Several overwrites are structurally important:

- The word store at A plus `0x10` covers bytes `0x10` through `0x13`, including the earlier byte destinations at offsets `0x10` and `0x11`.
- A plus `0x09` receives multiple values before receiving the low byte of R.
- A plus `0x44` first receives W and later R.
- C plus `0x54` first receives C and later the earlier captured word Y.

Which byte values survive overlapping word stores depends on byte order. Additional overlaps are possible because no distinctness constraints for A, B, C, or the derived addresses are established.

R is read from memory at this point; it is not established to equal P. The earlier stores of P used D plus `0x54`, which is generally a different address.

### 4. Final pointer-dependent transfers

The remaining accesses before the indirect invocation occur in this order:

1. Read a word from C plus `0x04`; retain it as S.
2. Write halfword value `0x0065` to the address obtained by doubling S.
3. Read a word from S plus `0x64`; retain it as K.
4. Write the low byte of V to R plus `0x11`.
5. Write word value `0x00000064` to R plus `0x54`.
6. Read a word from S plus `0x74`; retain it as L.
7. Read a word from C plus `0x64`; retain it as N.
8. Write the low byte of S to C plus `0x09`.
9. Write K to N plus `0x54`.
10. Write N as a word to the address obtained by doubling K.

The two doubled-address destinations are literal arithmetic address derivations. The supplied representation does not show a further scale factor for the halfword or word width.

Unlike D, which arises from explicitly unsigned arithmetic, S and K are represented as signed integers. Overflow behavior for doubling them is not established. Cases requiring signed overflow are documented_only rather than assigned a guessed wrapping rule.

### 5. Indirect invocation

After all preceding accesses, the function invokes an unresolved indirect target with these four argument values, in order:

1. `0x72`
2. K, captured from S plus `0x64`
3. Y, captured earlier from C plus `0x14`
4. L, captured from S plus `0x74`

These are captured values, not fresh reads at invocation time. In particular, the third argument is not necessarily the current contents of C plus `0x14`.

No return value from the dependency is consumed.

## Acceptance examples

These examples are conditional static consequences, not results of execution.

### Repeated-write trace

Given valid destinations and no premature interruption, an access observer should see 34 stores before the word read at absolute address `0xA9`.

At B plus `0x34`, the observed word-write sequence is Q followed by eight instances of D. A final-memory-only comparison cannot establish this behavior.

### Byte truncation

If the low byte of A is `0xF0`, the byte written to absolute address `0x3A` is `0x10`: twice `0xF0` plus `0x30` is `0x210`, whose low byte is `0x10`.

This does not imply that A is restricted to a digit or that the destination stores a printable character.

### Defined-range shift

Suppose a is 3 and the read from C plus `0x44` produces nonnegative T equal to `0x00000128`. Subject to valid accesses, the byte written to C plus `0x01` is `0x25`.

The word-write trace at B plus `0x54` still contains T followed by A. The final replacement does not erase the first write from the behavioral contract.

### Captured invocation arguments

Suppose the relevant reads produce Y equal to `0x11223344`, K equal to `0x00000200`, and L equal to `0x55667788`, and all subsequent accesses succeed.

The indirect invocation receives `0x72`, `0x00000200`, `0x11223344`, and `0x55667788`, in that order. A later change to the original storage for Y does not itself alter the already captured third argument.

### Width-sensitive final store

If K equals `0x00000200`, the last direct store targets address `0x00000400` and writes four bytes carrying N.

By contrast, the earlier store at twice S writes only two bytes carrying numeric value `0x0065`. Neither operation licenses treating both destinations as the same kind of array element.

### Overlapping fields

A byte previously written at A plus `0x11` is subsequently covered by the word store at A plus `0x10`. Determining its resulting byte value requires the word U and the platform’s byte order.

An implementation that preserves that earlier byte unconditionally would not match the displayed access behavior.
