# F-f523a2ef5e05

## Purpose

F-f523a2ef5e05 conditionally delegates an operation involving two byte-addressed objects. Each object supplies an unsigned one-byte header. The function captures the second object’s header and compares it with the first object’s header. It calls F-22361c6b4773 only when the captured second value is no greater than the first value used for comparison.

The delegated operation receives two calculated addresses, two identical unsigned numeric arguments derived from the captured second header, and an unchanged opaque caller-supplied value.

For stable headers, the address selection is consistent with aligning a region associated with the second object to the end of a nominal payload in the first object. This is inferred intent, not an established copying or mutation operation. The dependency’s implementation is unavailable.

The wrapper returns no value, reports no explicit rejection status, and directly updates neither header.

## Behavior

### Header capture and branch selection

The function first accesses the second object’s initial byte and captures its unsigned value as a 32-bit unsigned quantity.

It then accesses the first object’s initial byte for comparison.

- If the captured second-header value exceeds the first-header value used in this comparison, the function returns without calling F-22361c6b4773.
- Otherwise, it proceeds to a single dependency invocation.

Equality therefore selects delegation. A captured second-header value of zero also selects delegation for every possible first-header comparison value.

The branch decision does not inspect payload bytes, the opaque input, a terminator, or an explicit external status value.

The second header is not accessed again to obtain either numeric argument. Both numeric arguments use its originally captured value.

### Dependency arguments

For description, let:

- **B** denote the captured second-header value.
- **C** denote the first-header value used in the comparison.
- **A** denote the first-header value accessed later for address calculation.

These are descriptive values, not additional inputs. Delegation is selected when **B ≤ C**. The supplied representation does not require **A = C**.

On the accepted path, F-22361c6b4773 receives five arguments in this positional order:

| Position | Required value |
|---|---|
| 1 | An address calculated from the first object by the staged arithmetic described below. |
| 2 | **B**, as an unsigned 32-bit quantity. |

The first address is calculated in three conceptual stages:

1. Subtract **B** from **A** using unsigned 32-bit integer arithmetic.
2. Use that subtraction result in a pointer addition from the first object’s address.
3. Advance the resulting byte pointer by one additional byte.

Only the subtraction is established as unsigned 32-bit integer arithmetic. The final one-byte advance is a separate pointer addition; it is not an unsigned 32-bit integer increment of the subtraction result.

The first header’s additional access belongs to the accepted branch. The supplied representation does not establish a total evaluation order among independent dependency argument expressions. All required argument evaluations precede the invocation.

### Stable-header address geometry

When the first header remains stable between its comparison and address-calculation uses, **A = C**. On an accepted path:

**0 ≤ B ≤ A ≤ 255.**

The unsigned subtraction result is then **A − B**, in the range 0 through 255. After the two pointer additions, the first dependency address has the ordinary object-relative offset:

**A − B + 1 bytes.**

This combined formula is valid under the stable, accepted-header assumptions and subject to valid pointer arithmetic. Its range is 1 through 256, inclusive. The offset is therefore not restricted to an 8-bit quantity.

If the dependency interprets its first numeric argument as a byte extent beginning at its first pointer:

- For positive **B**, the selected extent begins at first-object offset **A − B + 1**.
- Its last byte would be at first-object offset **A**.
- When **B = A**, the starting address is immediately after the first header.
- When **B = 0**, the starting address is immediately after the nominal first payload.

This describes conditional geometry only. It does not establish that the dependency reads or writes an extent of **B** bytes, nor that the header actually denotes a payload length.

### Changing headers and arithmetic boundaries

Acceptance depends on **C**, while address calculation depends on the later value **A**. The wrapper does not check the relationship between **A** and **B** again.

If **A < B**, the header subtraction wraps as an unsigned 32-bit operation. The large resulting integer is then used in pointer arithmetic. The separate one-byte pointer advance must not be folded into a modulo-32-bit integer-offset calculation.

- That result is used in a pointer addition from the first object’s address.
