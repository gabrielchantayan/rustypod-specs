# F-1e06ba66d3c3

## Purpose

F-1e06ba66d3c3 processes a byte sequence as an optionally signed decimal magnitude, writes a two-word result, and returns a 32-bit acceptance indicator.

The result is written **before** acceptance is decided. Rejection does not leave the destination unchanged: malformed, empty, or excessively long input still produces the value accumulated from its decimal prefix, subject to the memory-access preconditions below.

Two distinctions are essential:

- Leading zero bytes are skipped before digits are counted. An input containing only a sign and/or zero digits is rejected.
- Nineteen counted digits require a dependency-specific decision. The available evidence does not establish that dependency’s meaning or any particular numeric bound.

The arithmetic produces a value modulo \(2^{64}\). Acceptance is a separate decision, not a general arithmetic-overflow check.

## Interface

### Inputs

1. **Input address:** a pointer to bytes.
   - Each examined byte is interpreted as an unsigned value from 0 through 255.
   - There is no explicit length argument.
   - A zero byte terminates the numeric portion only if earlier scanning has not skipped it.
   - The function may examine bytes beyond an embedded zero if the classification table marks that zero byte as skippable.

2. **Destination address:** a pointer to storage for two consecutive 32-bit words.
   - The first word receives the low-order 32 bits.
   - The second word receives the high-order 32 bits.
   - These are two ordered word stores, not an established atomic 64-bit store.
   - The evidence establishes word order, not byte endianness.

### Return value

The return is a 32-bit value:

- **1:** the explicit acceptance conditions succeed.
- **0:** they do not.

No separate error code, stopping address, digit count, or overflow flag is returned.

### Preconditions and access requirements

For a defined execution:

- Every byte reached by classification, sign handling, zero skipping, and decimal scanning must be readable.
- The classification dependency must provide a usable address-bearing cell and a readable table entry for every byte classified.
- Both destination words must be writable under the target platform’s access and alignment rules.
- When the nineteen-digit dependency is called, its own access requirements must also hold. Those requirements are not supplied.
- The counted digit length must remain representable by the signed 32-bit scan index. Behavior after an index overflow or address-space exhaustion is not established.

There are no explicit checks for null pointers, inaccessible memory, invalid classification storage, or inadequate destination capacity. Memory faults are not converted into a return value of 0.

The interface does not establish a prohibition on input/destination overlap. Such overlap has observable consequences described below.

## Behavior

### 1. Obtain classification data and skip classified bytes

The function first calls F-2a4c402ba617 with no explicit arguments.

Its result is used as the address of a cell containing a 32-bit classification-table base address. For the current input byte, the function reads the corresponding table byte and tests its least significant bit.

While that bit is set, the input position advances by one byte. This phase stops at the first byte whose classification entry has that bit clear.

The observed rule is **table-defined skipping**, not an established list of whitespace characters. In particular:

- No specific space, tab, or line-ending behavior is known without the table.
- Any byte whose entry has the bit set is skipped, even if it would otherwise be a sign, decimal digit, or terminator.
- If the zero-byte entry has the bit set, this phase does not respect the first zero byte as an input boundary.

The table base is obtained through the returned cell during classification; it is not established as a permanently cached table address.

### 2. Recognize one optional sign

At the first non-skipped byte:

- Byte `0x2D`, the minus sign, selects negative-result handling and is consumed.
- Otherwise, byte `0x2B`, the plus sign, is consumed.
- Otherwise, scanning continues from that byte without consuming a sign.

There is no second classification pass after the sign. A classified space after a sign is therefore not skipped by this function.

Only one sign is recognized. A second sign is a non-digit stopping byte.

### 3. Skip leading zero digits

Starting immediately after the optional sign, or at the first non-skipped byte when there is no sign, the function advances past every byte equal to `0x30`.

These zero digits do not contribute to the later digit count.

Consequences:

- Arbitrarily many accessible leading zeros do not, by themselves, increase the count used for the acceptance limit.
- An all-zero input reaches the end with a counted digit length of zero.
- Once a nonzero decimal digit begins accumulation, subsequent zero digits do count.
- A sign occurring after skipped zeros is not recognized as a sign.

### 4. Accumulate the decimal prefix

The function scans consecutive bytes in the inclusive range `0x30` through `0x39`. It stops at the first byte outside that range.

For each counted digit, it extends an initially zero 64-bit magnitude by decimal multiplication and addition:

\[
M_{\text{next}}=(10M_{\text{current}}+d)\bmod 2^{64},
\]

where \(d\) is the digit value from 0 through 9.

This is implemented through unsigned 32-bit low and high words, with the low-word carry incorporated into the high word. The resulting behavior is modulo-\(2^{64}\) accumulation, including for digit sequences that will later be rejected.

The scan retains:

- The accumulated magnitude.
- The signed 32-bit count of digits following the skipped leading zeros.
- The unsigned value of the first non-digit byte.

The input address supplied later to F-b553d13469e5 is the beginning of this counted digit sequence—not the original input address and not the address of the stopping byte.

### 5. Write the result before checking acceptance

For a nonnegative input, the destination receives the magnitude directly.

For a negative input, it receives:

\[
R=(-M)\bmod 2^{64}.
\]

The low word is written first, followed by the high word. Negative handling includes the borrow between words, so this is a full-width modular negation rather than two independent word negations.

If no digits were counted, the accumulated magnitude is zero. Both sign choices therefore write zero in that case.

The function performs these stores even when:

- No counted digit exists.
- A nonzero non-digit stops the scan.
- The digit count is twenty or greater.
- A subsequent nineteen-digit dependency check rejects the input.

### 6. Determine acceptance

After writing both words, the function returns 1 only when all applicable conditions hold:

1. The retained stopping byte is zero.
2. At least one digit was counted after leading-zero skipping.
3. Fewer than twenty digits were counted.
4. If exactly nineteen digits were counted, F-b553d13469e5 returns a qualifying signed 32-bit value.

The last condition depends on the sign:

| Counted digits | Nonnegative input | Negative input |
|---|---|---|
| 0 | Reject | Reject |
| 1–18 | Accept if the stopping byte is zero | Accept if the stopping byte is zero |
| 19 | Accept if the stopping byte is zero and dependency result is less than 0 | Accept if the stopping byte is zero and dependency result is less than 1 |
| 20 or more | Reject | Reject |

Thus, for nineteen digits:

- A negative dependency result permits either sign.
- A zero dependency result permits only negative input.
- A positive dependency result permits neither sign.

F-b553d13469e5 is called only when the stopping byte is zero and the count is exactly nineteen. It is not called for trailing junk, a zero count, shorter accepted values, or twenty-or-more-digit inputs.

There is no acceptance path for trailing whitespace unless it was already consumed during the initial classification phase. Whitespace after digits is a nonzero stopping byte and causes rejection.

- For nineteen digits, the dependency receives an address into input storage **after** the stores. It can therefore observe overwritten digits or an overwritten terminator.

The function also does not establish that the destination is disjoint from classification storage or other shared state.
