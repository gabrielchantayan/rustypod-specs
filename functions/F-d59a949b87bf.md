# F-d59a949b87bf

## Purpose

F-d59a949b87bf performs a caller-requested number of iterations using an opaque context. Each iteration requests 24 bytes into temporary storage, optionally invokes a transformation, validates a marker, and performs an ordered sequence of movement or processing calls.

The function stops at the first checked nonzero dependency result or marker mismatch. It returns zero only when all requested iterations complete, including when the requested count is zero. It provides no explicit rollback.

“Header,” “boundary,” “extent,” and “movement” are descriptive labels for observed uses. The supplied material does not establish a record format, movement semantics, or the processing performed by dependencies.

The temporary header is **not established as an immutable snapshot** after acquisition or transformation. Both dependencies receive its address; their retention and aliasing behavior are unknown. Later calls therefore cannot be assumed to preserve its contents. Field values must be specified at their actual uses.

## Behavior

### Iteration control

An unsigned 32-bit completion counter starts at zero. Before acquisition, the function compares this counter with the requested count. If the requested count has been reached, it returns zero.

The counter advances only after final movement returns zero. Acquisition, transformation, marker validation, first movement, or body processing alone does not complete an iteration.

The maximum request is 4,294,967,295 iterations. If every iteration succeeds, the counter reaches that value and processing terminates at the next comparison. Counter wraparound is not needed to complete that request.

For each attempted iteration, F-c02571304c5c receives the context, the temporary header address, and the amount 24.

If acquisition returns nonzero, that result is returned immediately. The function does not subsequently read the context flag, invoke transformation, validate the marker, or perform movement for that iteration.

After acquisition returns zero, the function reads one byte at context offset 13:

- A zero byte omits transformation.
- Any nonzero byte invokes F-58734d45a018 with the temporary header address.

The transformation’s result, if any, is not checked. If it returns normally, marker validation follows.

The flag is observed after each successful acquisition, not cached at function entry. Acquisition and earlier iterations may therefore affect later transformation decisions. No direct write to the flag is visible in this function.

### Marker validation

After optional transformation, the 32-bit header marker is compared with the global expected marker.

A mismatch returns −208 immediately. No movement or delegated processing follows for that iteration.

The expected marker is consulted at this comparison; no earlier snapshot is visible. Acquisition and transformation cannot be assumed to preserve that global. The supplied expression does not establish a relative read order between the header marker and the global value.

Passing marker validation establishes no relationship among boundary, extent, type, or byte amount. The function performs no separate range or structural validation of those fields.

**First movement amount = boundary − 24.**

This argument is evaluated **before** F-22914e190356 is invoked with the context and the calculated amount. Changes made during that call cannot change the already-supplied argument, but may affect later header uses.

2. Context-flag observation.

4. Marker comparison.
5. First-boundary argument evaluation.
