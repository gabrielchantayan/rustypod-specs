# F-1918c28bbbe3

## Purpose

F-1918c28bbbe3 performs an ordered sequence of indirect calls, computed-address 32-bit stores, selector-byte reads, and eight-bit stores. It then enters an unconditional loop containing further calls and selector-based zero stores.

No application-level purpose is established. The supplied representation does not establish a particular object model, protocol, allocation scheme, or ownership discipline.

## Behavior

### Call-group conventions

The following conventions describe observable call boundaries without assigning functionality to unknown callees:

- A **five-call group** begins with a call receiving the listed arguments. Four calls with no displayed explicit arguments follow. The group’s named result is the ordinary 32-bit result captured from the fifth call.
- A **nine-call relay** begins with a call receiving the listed arguments. A second call has no displayed arguments and returns a word; a third call receives that word. A fourth call has no displayed arguments and returns another word; a fifth call receives that second word, optionally accompanied by H logically shifted right by eight. Four more calls with no displayed arguments follow. The named result is captured from the ninth call.

A call without displayed arguments is not established to consume no machine state. All calls remain observable boundaries and may have unknown side effects.

Named results **R0 through R13** identify distinct capture events. They need not be numerically distinct.

### Selector-addressed byte writes

For an S-based write, the function:

- Reads one unsigned byte at address S + 1.
- Uses that byte value plus 17 as the destination address.
- Writes one byte at that destination.

Thus the selected destination lies between addresses 17 and 272 inclusive. This is a byte-derived address, not a pointer-sized value loaded from memory.

Each represented selector access is a fresh read. Calls, earlier writes, or external changes may alter later selector values. In particular, no non-aliasing guarantee separates selector storage from selected destinations.

### Six byte stores before the loop

Exactly **six explicit byte stores** occur after the word-store phase and before loop entry.

1. **First T-derived selected write.** Read the selector at S + 1 and write the low byte of T shifted left by two to its selected destination.

   A call then receives that shifted 32-bit quantity three times. A following argumentless call returns a word that is passed to another call. Four further argumentless calls follow; the last ordinary result is captured.

2. **Second T-derived selected write.** Reread the selector at S + 1 and write the low byte of  
   **(T AND 0x3fffffff) logically shifted right by 20**.

   A five-call group receives four times the most recently captured result. Its final result is captured as unsigned 32-bit **U**.

3. **Direct U-derived write.** At address  
   **(H logically shifted right by 23) + 28**,  
   write the low byte of U shifted left by two.

4. **First S-based zero write.** Reread the selector at S + 1 and write zero to its selected destination. No dependency call separates this write from the preceding direct write.

   A dependency receives H shifted right by 23. One argumentless call follows. Another dependency receives  
   **(U AND 0x3fffffff) logically shifted right by 6**.  
   Four argumentless calls follow, with the final ordinary result captured.

5. **Second S-based zero write.** Reread the selector at S + 1 and write zero to its selected destination.

   A five-call group receives four times the latest captured result. Its final result is captured as an unsigned word and reduced to  
   **K = (result AND 0x3fffffff) logically shifted right by 25**.  
   Consequently, K lies between 0 and 31 inclusive.

6. **U-selector zero write.** Read a byte at the U-derived selector address described below and write zero at that byte value plus 17.

   A dependency receives twice K. One argumentless call follows, and its ordinary result becomes the initial carried result for the loop.

The U-derived selector address uses the represented signed 32-bit intermediate holding the bit pattern of **U shifted left by two**. That intermediate is multiplied by 1024, then one is added. Signed interpretation and overflow remain unresolved; the computation must not silently be replaced with an unbounded unsigned formula.

### Unconditional loop

Every represented iteration contains ten calls and one selector-based zero write, in this order:

- A five-call group receives the carried ordinary result and K logically shifted right by eight.
- The U-derived selector byte is reread. Zero is written at that byte value plus 17.
- A second five-call group receives four times the result captured from the first group.
- Four times the second group’s result becomes the next carried ordinary result.
- K becomes the unsigned word assigned from that result shifted left by 26.
- Execution repeats unconditionally.

On the first iteration, the second argument of the first call is zero because initial K is at most 31.

Under a conditional 32-bit bit-vector interpretation, subsequent K values contain only the producing result’s low six bits, positioned in bits 26 through 31. The represented signed left shift does not itself establish that interpretation for every input.

The U-derived selector-address expression remains unchanged throughout the loop, but its byte contents are reread each iteration.

## Acceptance examples

These are conditional static examples, not executed tests.

### Initial stores use different addresses

For A = 4, with accessible addresses and successful intervening calls:

- Store 1 writes the 32-bit value 4 at address 36.
- Store 2 writes the 32-bit value 4 at address 24.
- Five calls occur between these stores.

Combining the two address formulas would violate the represented behavior.

### C undergoes two right shifts

For C = 0x00004000, the fourth argument of the four-argument call after store 7 is 1.

For C = 0x00003fff, that argument is 0.

A single seven-bit shift does not satisfy these cases.

### Byte truncation

For T = 0x00000043, its unsigned left shift by two is 0x0000010c. The first T-derived byte store writes 0x0c.

For T = 0x3ff00000, the second T-derived expression is 0x000003ff; its byte store writes 0xff.

### Fresh selector reads

If S + 1 contains 0x20, the next S-selected write targets address 0x31.

If an intervening dependency changes that selector to 0x80, the next S-selected write targets address 0x91. Reusing the earlier destination is incompatible with the represented read order.

### Mask before address selection

For retained M = 0x80000080, clearing the high bit and shifting right by seven yields S = 1. The selector is read at address 2.

This example assumes M has already been obtained as the represented unsigned bit pattern.

### Pre-loop byte-store count

Conditional on all preceding operations completing, reaching the loop requires six explicit byte stores: two T-derived selected writes, the direct U-derived write, two S-selected zero writes, and one U-selected zero write.

The loop’s first zero write is an additional store, not a seventh pre-loop store.

### Loop entry and continuation

For every possible initial K, the first loop call’s second explicit argument is zero.

If all calls return and all accesses succeed, execution continues issuing ten calls and one explicit zero-byte store per iteration. A normal return after a fixed iteration count is unsupported.
