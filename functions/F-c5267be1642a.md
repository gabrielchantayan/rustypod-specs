# F-c5267be1642a

## Purpose

F-c5267be1642a initializes two fields in a caller-supplied object, obtains a two-word working descriptor, and repeatedly dispatches according to an unsigned 16-bit value read through that descriptor.

The visible dispatch families are:

- `0x0023`: invoke a dedicated handler.
- `0x0030` through `0x0039`, inclusive: obtain a second signed dependency result; invoke another dedicated handler when that result is at least eight, otherwise consider an optional callback.
- All other values: consider the optional callback directly.

After every completed dispatch, including one that skips an absent callback, the function reacquires both working-descriptor words from the object. It terminates normally only when the loop-entry dependency returns zero.

**Established static evidence:** field offsets, access widths, dependency order, dispatch boundaries, callback resolution, and descriptor replacement are visible in the supplied body.

**Inferred intent:** the distinguished values resemble a number sign and decimal digits in common character encodings. This resemblance does not establish an encoding, grammar, or parsing contract.

**Unknown:** the object’s semantic type, descriptor invariants, dependency implementations, and ownership arrangements.

## Interface

| Input | Representation and visible role |
|---|---|
| Object address | A 32-bit address-like value. Identifies writable four-byte fields at byte offsets `0x18` and `0x1C`; the address at offset `0x48` is passed to a dependency. |
| Context word | An uninterpreted four-byte value stored at object offset `0x18`. |

### Preconditions

Successful execution requires:

- Writable object fields at offsets `0x18` and `0x1C`.
- Readable input-descriptor words.
- Valid initialization and receiver-adjustment arithmetic under the target’s execution rules.
- Storage and arguments satisfying the unavailable dependency contracts.
- A readable unsigned 16-bit element through the descriptor after every nonzero loop-entry result.
- For indirect callback resolution, a readable signed four-byte receiver word and a readable four-byte callback slot at the address obtained from the specified integer calculation.
- A valid callable target whenever invocation is selected.

The function does not visibly check these conditions.

The indirect callback-slot calculation has defined unsigned 32-bit conversion and modular-addition semantics. That does **not** establish that the resulting integer denotes a valid address or that an access through it is permitted.

## Behavior

### Initialization

The first direct object effect is a four-byte write of the context word at offset `0x18`.

The function then constructs an initial temporary descriptor:

1. Read the input descriptor’s second four-byte word.
2. Read its first four-byte word.
3. Add twice the signed starting displacement to that first word.
4. Use the resulting address-like value and the copied companion word as the temporary descriptor.

The displacement is measured in bytes after multiplication by two. A negative displacement is not rejected.

F-64292cfbfab8 receives the address of this temporary descriptor. After it returns, its four-byte result is written to object offset `0x1C`.

These operations have observable ordering when memory aliases. For example, the context write precedes both input-descriptor reads, so overlapping input storage may supply values affected by that write. The result write at offset `0x1C` occurs after F-64292cfbfab8 returns. No general non-aliasing requirement or guarantee is established.

Next, F-868e5d53f111 receives:

- Temporary result storage for a two-word descriptor.
- The address of the object region beginning at offset `0x48`.

After this call, the function computes the adjusted callback receiver and copies the two acquired words into the working descriptor. The descriptor initially supplied to F-64292cfbfab8 is not continued directly; its working contents are replaced by the acquired descriptor.

### Adjusted callback receiver

The adjusted receiver is the original object address plus a signed byte adjustment.

To obtain the adjustment, the function interprets the adjustment and mode word as signed 32-bit and performs an arithmetic right shift by one. The low bit independently selects direct or indirect callback resolution.

| Adjustment and mode word | Byte adjustment | Callback mode |
|---|---:|---|
| `0x00000000` | 0 | Direct |
| `0x00000001` | 0 | Indirect |
| `0x00000002` | +1 | Direct |
| `0x00000003` | +1 | Indirect |
| `0xFFFFFFFF` | −1 | Indirect |

The adjustment is not scaled by the width of a word.

The adjusted receiver address is computed once, after the initial acquisition call. It is not recomputed after subsequent dependency or callback calls. In indirect mode, however, the word at that address is read anew on each selected callback invocation.

Dedicated handlers receive the original object address, not this adjusted receiver.

### Loop-entry check

At the beginning of every iteration, F-d5d68dc4e17c receives the address of the working descriptor.

- If its signed 32-bit result is zero, the function returns immediately.
- Any nonzero result, including a negative result, permits dispatch.

A terminating result causes no dispatch-element read and no further descriptor acquisition.

For a nonzero result, the function reads an unsigned 16-bit value through the working descriptor’s current first word. This access occurs **after** the dependency call and therefore uses any descriptor changes made by that call.

The dispatch value is obtained once for family selection. It is not reread after the optional second dependency call described below.

### Dedicated dispatch for `0x0023`

For `0x0023`, the function calls F-c7fd6e1c8e70 with:

1. The original object address.
2. The working descriptor address.

This branch makes neither the second F-d5d68dc4e17c call nor a callback invocation.

After the handler returns normally, descriptor acquisition and replacement occur.

### Conditional dispatch for `0x0030`–`0x0039`

For every value from `0x0030` through `0x0039`, inclusive, the function calls F-d5d68dc4e17c a second time with the working descriptor address.

Its signed 32-bit result determines the action:

- At least eight: call F-e9ba69bfc4f5 with the original object address and working descriptor address.
- Less than eight: enter optional callback dispatch.

Zero and negative second-call results therefore select optional callback dispatch; they do not terminate the function.

The family remains selected by the earlier 16-bit read. If the second dependency call changes the descriptor to refer to a different value, the function does not reclassify that value. The selected handler or callback nevertheless receives the descriptor in its post-call state.

### Dispatch for all remaining values

Any other unsigned 16-bit value enters optional callback dispatch without the second F-d5d68dc4e17c call.

There is no additional local default handler.

### Optional callback dispatch

#### Direct mode

When the adjustment and mode word has low bit zero:

- A zero callback representation skips invocation.
- A nonzero representation supplies the callable address directly.

No receiver-word or callback-slot read is performed for direct resolution.

#### Indirect mode

When the adjustment and mode word has low bit one, callback resolution is attempted even if the supplied callback representation is zero.

Resolution has the following observable sequence:

1. Clear the callback representation’s low two bits, yielding an unsigned 32-bit byte offset.
2. Read a signed 32-bit word from the adjusted receiver address.
3. Convert that signed word to unsigned 32-bit.
4. Add the unsigned word and masked offset using arithmetic modulo \(2^{32}\).
5. Interpret the resulting integer as the callback-slot address.
6. Read the callable address from that four-byte slot.
7. Invoke that callable address.

For a negative receiver word, conversion to unsigned produces the corresponding value modulo \(2^{32}\). The subsequent addition also wraps modulo \(2^{32}\). These integer semantics are established; they are not dependent on the sum remaining in signed range.

For example, a receiver word of −16 converts to `0xFFFFFFF0`. With a masked callback offset of `0x00000020`, the slot-address integer is `0x00000010`.

Conversion of that integer to an address, alignment requirements, and validity of the resulting memory access remain separate conditions. Modular arithmetic neither rejects an unusable address nor makes it readable.

The low-bit-one mode necessarily has a nonzero adjustment and mode word. The additional visible nonzero condition on that word does not restrict this branch further.

There is no visible null check on the callable address read from the slot.

#### Invocation arguments

Every selected callback receives exactly:

1. The adjusted receiver address.
2. The working descriptor address.

Any callback return value is unused by the visible caller. Memory effects may still affect later acquisition and dispatch.

### Descriptor replacement and repetition

After any normally completed dispatch branch, the function calls F-868e5d53f111 with temporary descriptor-result storage and the object-region address at offset `0x48`.

Both returned descriptor words replace the working descriptor. The next action is another loop-entry check.

This replacement also occurs when direct callback invocation was skipped because its representation was zero.

The function does not itself increment the working pointer or decrement the companion word. A handler’s temporary descriptor mutation does not independently guarantee progress because acquisition subsequently replaces both words. Persistent progress depends on effects reflected in later dependency behavior.

There is no independent iteration limit.

## Acceptance examples

These are conditional criteria derived from static evidence, not executed tests. Unless stated otherwise, they assume valid memory, valid callable targets, and normally returning dependencies.

1. **Immediate termination.** If the first loop-entry result is zero, initialization and initial descriptor acquisition have already occurred. No dispatch read, handler, callback, or post-dispatch acquisition follows.

2. **Dedicated handler.** A nonzero loop-entry result followed by `0x0023` invokes F-c7fd6e1c8e70 with the original object and working descriptor. Acquisition follows its return.

3. **Threshold boundary.** With dispatch value `0x0035`, a second result of seven selects optional callback dispatch; eight selects F-e9ba69bfc4f5.

4. **Call-site-dependent zero.** Zero at loop entry terminates. Zero from the second check selects optional callback dispatch, followed by acquisition.

5. **Negative results.** A negative loop-entry result still permits the dispatch read. A negative second result selects optional callback dispatch.

6. **Exact range.** `0x0030` and `0x0039` require the second check. `0x002F` and `0x003A` reach optional callback dispatch without it.

7. **No reclassification.** If the first read yields `0x0030` and the second check changes the descriptor to reference `0x0023`, a second result of eight still selects F-e9ba69bfc4f5, not the `0x0023` handler.

8. **Absent direct callback.** Direct mode with callback representation zero performs no callback invocation or indirect-resolution reads, but still reacquires the descriptor.

9. **Zero indirect representation.** Mode word `0x00000001` and callback representation zero cause a receiver-word read at the original object address, followed by a callable-slot read at the address represented by that word’s unsigned conversion.

10. **Low-bit masking.** In indirect mode, callback representations `0x00000020` and `0x00000023` supply the same offset. Given the same receiver word, they resolve the same slot.

11. **Unsigned wraparound.** A signed receiver word of −16 and callback representation `0x00000023` produce masked offset `0x00000020` and slot-address integer `0x00000010`. Invocation is required only under the additional assumptions that this integer converts to a readable slot address and the slot contains a valid callable target.

12. **Byte adjustment.** Mode word `0x00000002` makes a direct callback receive an address one byte beyond the object. Dedicated handlers still receive the original address.

13. **Descriptor replacement.** A handler’s descriptor changes are superseded by both words supplied by the following F-868e5d53f111 call. Subsequent behavior uses that replacement.
