# F-f389c53533f7

## Purpose

F-f389c53533f7 configures an existing object, invokes dependencies on embedded regions, replaces three stored references, computes a rank from three unsigned words, and conditionally inserts an embedded node into a table.

The established contract is the ordered sequence of accesses and calls below. “Configuration,” “rank,” “node,” and “table” describe observable layouts and access patterns; their application-level meanings remain inferred.

The function returns no explicit result. Skipping insertion does not undo configuration, dependency calls, reference replacement, or rank storage.

### Widths and arithmetic

Direct accesses use 32-bit words except for the status and flag bytes.

Rank comparisons are unsigned 32-bit comparisons. The insertion gate interprets the recovered index as a signed 32-bit value. Rank increment, index recovery, and address calculations use 32-bit results; arithmetic can wrap.

In particular:

- Incrementing `0xffffffff` produces zero.
- Subtracting one from zero recovers `0xffffffff`.

### 5. Calculate rank and recover an index

After replacement, the function reads these unsigned 32-bit inputs, in order:

1. Object `+0x070`.
2. Object `+0x100`.
3. Retained configuration pointer `+0x08`.

It selects their unsigned maximum and writes that maximum plus one, modulo \(2^{32}\), to object `+0x1a0`.

Next, it dereferences the pointer retained from the **first** root-pointer-global read to obtain the table base for possible insertion. It does not reread the root-pointer global at this point. This table-base read occurs even if insertion will be skipped.

Consequently:

- F-03b9616af95f’s first argument came through the second root-pointer-global read.
- The insertion table base comes through the originally retained pointer.
- Even when those pointers are equal, intervening dependencies may have changed the word they address.

The function then rereads object `+0x1a0` and subtracts one modulo \(2^{32}\) to obtain the candidate index. Without relevant intervening mutation or alias effects, this recovers the unsigned maximum.

### 6. Gate insertion

If the candidate index has its high bit set, insertion is skipped. The eligibility path does not read the flag byte in this case.

Otherwise, the function reads object `+0x1ac` and tests bit 0:

- Bit 0 set: skip insertion.
- Bit 0 clear: perform insertion.

Both skip paths occur after the rank write and the later table-base read. They do not undo earlier work.

### 7. Perform insertion

For an eligible index, the selected slot address is the insertion table base plus four times the index, using 32-bit address arithmetic.

The direct operations occur in this order:

1. Write zero to object `+0x1a4`.
2. Read the selected table slot.
3. Write that value to object `+0x1a8`.
4. Write object `+0x198` to the selected table slot.
5. Read object `+0x1ac`, set bit 0, and write the byte back.
6. Read object `+0x1a8` to test whether it is nonzero.
7. If nonzero, read object `+0x1a8` again to obtain the destination reference and write object `+0x198` at that reference plus `0x0c`.

The flag update preserves the other bits of the byte read at step 5, not necessarily those observed during eligibility if aliasing or external mutation has changed it.

The final destination is obtained by a second read of the saved-entry field on the nonzero path. It is not explicitly a retained copy of the value used for the condition.

This resembles insertion at the head of a linked chain. Only these accesses are established.

## Acceptance examples

These are conditional static expectations, not runtime results. Unless stated otherwise, dependencies return normally, accesses are valid, and no relevant mutation or aliasing changes the described values.

### Ordinary insertion and flag preservation

With rank inputs 3, 7, and 5, flag byte `0xa4`, and prior slot value P:

- Object `+0x1a0` becomes 8; candidate index is 7.
- Object `+0x1a4` becomes zero.
- Object `+0x1a8` receives P.
- Slot 7 receives object `+0x198`.
- The flag becomes `0xa5`.
- If P is nonzero and remains the saved reference, P `+0x0c` receives object `+0x198`.

### Existing flag

With the same ranks and flag `0x81`, rank storage still becomes 8. Configuration, calls, reference replacement, and the insertion table-base read still occur. The insertion stage performs none of its writes.

### Signed boundary and wraparound

For unsigned maximum `0x80000000`, stored rank-plus-one is `0x80000001`; insertion is skipped without reading the eligibility flag.

For unsigned maximum `0xffffffff`, stored rank-plus-one is zero, but the recovered candidate is `0xffffffff`. Insertion is skipped; stored zero does not select slot zero.

### Shared-descriptor mutation between reads

Suppose the shared-descriptor global contains D when configuration `+0x40` is written. If an intervening dependency changes it to E before the third F-470fed045f43 call, that call receives E, while the earlier configuration write supplied D. No equality between those supplied values is required.

Likewise, if the first initialization call changes initialization global B, the second call receives its updated value.

### Distinct root-pointer reads

Suppose the first root-pointer-global read yields address R1 and the second yields R2. F-03b9616af95f receives the word read through R2. Later insertion uses the word then read through R1.

If both reads yield R1, the two dereferences can still observe different table-base words because dependency calls intervene.

### Sequential conditional calls

If the fields are nonzero, zero, and nonzero when checked in order `+0x1b8`, `+0x1b0`, `+0x1b4`, F-029930293dcb is called twice. If the first call changes the next field, its changed value determines the next check. All three replacement writes follow.
