# F-c7d7171a1ea8

## Purpose

F-c7d7171a1ea8 performs an ordered sequence of direct memory updates, captures several values from mutable memory, and ends by transferring control through an unresolved indirect target.

The supplied representation establishes memory operations, not an application-level purpose. It does not establish that the affected locations form valid objects, that the constants represent text, or that the repeated writes implement a collection operation. Such interpretations are not part of this contract.

This is a static, source-facing contract. Its guarantees are conditional on execution reaching each operation with valid addresses and supported arithmetic. No runtime tests have been performed.

### Implicit inputs

Execution also depends on three incoming machine-state values that have no visible initialization. This contract calls them the **anchor**, **owner**, and **peer**. These names describe their use here, not established object types.

Other implicit inputs are:

- A globally stored 32-bit value used as a memory base, called the **loaded base**.
- A four-byte value read at absolute address 0xA9.
- Contents of all dynamically addressed read locations.
- An unresolved indirect control-transfer target.

The location of the global holding the loaded base is not exposed as a private source identifier in this contract.

### Arithmetic and notation

For describing layouts:

- The **adjusted index** is the third argument minus 77.
- The **indexed base** is four times the adjusted index, represented as a 32-bit unsigned value.
- The **indexed link** is eight times the adjusted index.
- The **doubled owner** and **doubled peer** are twice their respective incoming values.
- “Low byte” means the least significant eight bits of a value, independent of byte order in memory.

These are specification terms, not recovered source identifiers.

The representation contains signed subtraction, multiplication, address addition, and signed right shift. It does not establish a complete overflow or shift model. In particular, assignment into an unsigned value does not by itself establish that preceding signed multiplication wraps.

Examples below use values that avoid signed overflow and unsupported shift counts. Any modulo-32-bit interpretation outside that range is **documented_only**, not a guaranteed behavior.

## Behavior

### Observable ordering model

The following phases preserve the order expressed by the supplied representation. They are not a claim about instruction-level atomicity, compiler barriers, or device-bus transactions.

Aliasing matters. An earlier write may change a later read, including the loaded base itself if its storage overlaps an earlier destination. Values already captured are reused without being refreshed unless an explicit later read is described.

### Initial marker and indexed writes

The initial memory effects are:

| Region | Width | Ordered effect |
|---|---:|---|
| Twice the anchor | 2 bytes | Store 0x003A |
| Anchor + 0x20 | 4 bytes | Store 0x0000003A |
| Indexed base + 0x20 | 4 bytes | Store 0x20, then 0x2F |
| Indexed base + 4 | 1 byte read | Read an unsigned byte |
| Indexed base + 0x20 | 4 bytes | Store that byte zero-extended, then store 0x20 |

The byte read occurs after the first two indexed writes, not before them. It is an unsigned byte read: a value of 0xFF contributes 255 to the following four-byte store.

Only after these effects is the loaded base fetched from its global storage. A store of 0x20 to absolute address 0x60 follows. That global store’s width is not established explicitly by the supplied declaration context.

The visible result at indexed base + 0x20 is therefore 0x20 immediately after this phase, assuming ordinary memory and successful completion. This is not necessarily its final value for the entire function because later destinations may overlap it.

### Repeated relationship writes

A four-byte store first places the doubled owner at doubled peer + 0x54.

The function then repeatedly writes a compact set of relationships involving the loaded base and indexed base:

- Loaded base + 0x19 receives the low byte of the indexed base.
- Indexed base + 0x11 receives the low byte of the loaded base.
- Loaded base + 0x34 receives a four-byte link value.
- Indexed link + 0x54 receives the doubled owner as a four-byte value.

The first relationship group uses the doubled peer as the link value at loaded base + 0x34. Subsequent groups use the indexed link there. The recurring order is the two byte stores followed by the loaded-base link store, with the indexed-link destination written before the next group’s byte stores.

These are repeated writes to the same calculated locations, not evidence of advancing through an array. The final visible group ends with the four-byte store of the indexed link at loaded base + 0x34.

The fixed repetition count is **documented_only** in this contract: it is not independently enumerated here. No input-dependent loop bound or termination condition is visible. Exact write-count conformance, particularly for device-backed memory, cannot be accepted solely from this document.

### Captured state and overlapping fields

After the repeated region, the function captures the four-byte value at absolute address 0xA9 and the four-byte value at doubled owner + 0x74.

It then updates the byte at absolute address 0x3A with the low-byte result of eight times the adjusted index plus 0x30. The representation expresses this through character-width arithmetic; behavior where character signedness or out-of-range conversion matters is not fully established.

Next, four-byte values are captured from owner + 0x14 and indexed base + 4, in that order.

The following layout changes occur before the next major read:

| Destination | Width | Value |
|---|---:|---|
| Owner + 0x0D | 1 byte | Low byte of indexed base |
| Indexed base + 8 | 1 byte | 0x6C |
| Indexed base + 0x0D | 1 byte | Low byte of loaded base |
| Indexed base + 9 | 1 byte | Low byte of loaded base |
| Owner + 0x54 | 4 bytes | Owner |
| Absolute 0x67 | 1 byte | Low byte of the captured value from 0xA9 |

A signed four-byte value is then read from owner + 0x44. This contract calls it the **shift source**.

The byte at absolute address 0x67 is read and copied to absolute address 0x21. The shift source’s low byte is stored at indexed base + 0x10, and the full shift source is stored at loaded base + 0x54.

Owner + 1 receives the low byte of the signed shift source right-shifted by the low byte of the indexed base. The count is masked to eight bits, not explicitly to the word’s five-bit shift range. Counts from 32 through 255 therefore have no portable established result. Right shift of a negative signed value also requires target-specific interpretation.

The four-byte value at loaded base + 0x54 is then replaced by the indexed base.

### Further field replacement and indirect-base discovery

A four-byte value is read from indexed base + 0x40. Subsequently:

- Loaded base + 0x74 receives the previously captured word from indexed base + 4.
- Indexed base + 0x10 receives the word just read from indexed base + 0x40.
- Loaded base + 0x44 receives the owner.
- Indexed base + 9 receives a newly read byte from absolute address 0x67.
- Owner + 9 receives the low byte of the indexed base.
- Indexed base + 0x44 receives the captured four-byte value from absolute address 0xA9.

The four-byte store at indexed base + 0x10 covers offsets 0x10 through 0x13. It therefore replaces both the earlier byte at +0x10 and the repeatedly written byte at +0x11, subject to the target’s byte order.

A four-byte value is then read from indexed base + 0x54 and used as another memory base, called the **discovered base**. After this read:

- Indexed base + 9 again receives a newly read byte from absolute address 0x67.
- Discovered base + 0x0D receives the low byte of the earlier capture from doubled owner + 0x74.
- Owner + 0x54 receives the earlier capture from owner + 0x14.
- A four-byte value is captured from indexed base + 0x14.
- Owner + 0x11 receives the same low byte used at discovered base + 0x0D.
- Indexed base + 9 receives the low byte of the discovered base.
- Indexed base + 0x44 receives the discovered base as a four-byte value.

The repeated reads of absolute address 0x67 are significant: intervening writes may alias that address. They must not be assumed to return the originally stored byte.

### Terminal updates and handoff

A signed four-byte value read from owner + 4 becomes a further base, called the **terminal base**.

The terminal phase has these ordering constraints:

1. A two-byte store of 0x0065 at twice the terminal base precedes the four-byte read at terminal base + 0x64. That read supplies the **terminal link**.
2. Discovered base + 0x11 receives the low byte of the captured word from indexed base + 0x14. Discovered base + 0x54 then receives the four-byte value 100.
3. A four-byte value is captured from terminal base + 0x74, followed by a four-byte read at owner + 0x64 supplying the **terminal destination**.
4. Owner + 9 receives the low byte of the terminal base.
5. Terminal destination + 0x54 receives the terminal link as a four-byte value.
6. Twice the terminal link receives the terminal destination as a four-byte value.

The unresolved indirect target is then invoked with four represented argument values, in order:

| Position | Value |
|---|---|
| 1 | 0x72 |
| 2 | Terminal link |
| 3 | Earlier four-byte capture from owner + 0x14 |
| 4 | Later four-byte capture from terminal base + 0x74 |

No visible memory operations follow that invocation before the represented return.

## Side effects

The direct side effects are memory reads, byte stores, two-byte stores, four-byte stores, and an indirect invocation. No direct allocation, deallocation, ownership transfer, locking, rollback, or error reporting is visible.

The function uses existing storage without establishing ownership. A stored address-like value is not evidence that ownership is transferred.

Overlapping locations must be treated as one underlying memory state, not independent fields. Byte order determines how multi-byte writes affect later overlapping byte reads. Alignment requirements, atomicity, volatile behavior, and concurrency guarantees are unknown.

Failure during a later access does not visibly undo earlier writes. There is no established recoverable error result. Faults, traps, or nonreturning behavior remain environment-dependent.

The indirect target may introduce additional effects. This contract does not assume it preserves globals, preserves referenced memory, returns, or refrains from releasing resources.

## Acceptance examples

These examples are conditional static acceptance criteria, not executed tests.

### Ordinary arithmetic and isolated storage

With third argument 78, the adjusted index is 1, the indexed base is 4, and the indexed link is 8.

If the corresponding low addresses are valid and do not alias other relevant storage:

- The indexed marker writes target address 0x24.
- The initial unsigned byte read targets address 8.
- The repeated byte destination indexed base + 0x11 is address 0x15.
- The repeated four-byte destination indexed link + 0x54 is address 0x5C.
- The byte written at absolute address 0x3A is 0x38.

Any later overlapping write must still be applied; these are not unconditional final-state assertions.

### Unsigned byte widening

If indexed base + 4 contains byte 0xFF when the initial byte read occurs, the intervening four-byte marker store carries 0x000000FF, not a sign-extended negative value. The following marker store replaces it with 0x20.

A final-memory-only observation cannot prove that the intervening store occurred.

### Defined shift case

If the indexed base’s low byte is 4 and the shift source is positive 0x00000120, the shift-derived byte written to owner + 1 is 0x12.

If the count is 32, no expected shift result is established here. Applying an implicit five-bit count mask would add an unsupported assumption.

### Preserved capture despite overwrite

If owner + 0x14 contains value V when captured, and execution subsequently changes that location through aliasing, the third indirect argument remains V. There is no later refresh of that captured argument.

Likewise, the fourth indirect argument comes from the later read at terminal base + 0x74, not the earlier read at doubled owner + 0x74.

### Partial execution

If the first two-byte write succeeds but the subsequent anchor-relative four-byte write faults, the contract establishes no rollback of the first write and no indirect invocation. It does not establish the environment’s fault-delivery mechanism.
