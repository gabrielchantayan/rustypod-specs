# F-34db3b761c5c

## Purpose

F-34db3b761c5c performs an ordered sequence of indirect calls interleaved with word, byte, and halfword memory writes. Its explicit third input participates in address formation and an argument transformation. Additional behavior depends on incoming machine state, values returned by dependencies, a global pointer-like value, and memory reached through small integer addresses.

The supplied static representation establishes these operations but does not establish a higher-level purpose. In particular, it does not justify describing the routine as an allocator, serializer, device initializer, or collection operation.

This contract describes the visible operation sequence, not a claim that the routine can execute successfully in an ordinary process. Several accesses target low addresses, and the final call targets address zero. Successful execution requires an environment in which the reached addresses and call targets have appropriate meanings.

## Interface

### Explicit inputs and return

The represented interface has three 32-bit inputs:

| Input | Established use |
|---|---|
| First word | No explicit use in the visible body. |
| Second word | No explicit use in the visible body. |
| Third word, called **P** below | Treated as an unsigned 32-bit value; used in a shift transformation and to form a word-store address. |

The declared return is void. There is no explicit status result, success flag, or error object.

Absence of an explicit use of the first two inputs does not establish that callees cannot observe their incoming register values. Several indirect calls have no displayed arguments, and their actual calling conventions are unavailable.

### Additional incoming state

The body also depends on:

- An incoming 32-bit register value, called **R** below. It supplies two word-store values and selects one byte-table entry.
- An incoming link-state value used to form the first indirect-call target by adding 4,094.
- A readable global word whose contents are later used as a base address.
- A writable global word receiving the result of a late dependency.
- An auxiliary pointer-valued machine result used for a final byte clear.
- All state consumed or modified by the unresolved dependencies.

These are behavioral dependencies, not additional parameters established by the declared interface.

### Widths and notation

The visible accesses use:

- Word: 32 bits.
- Halfword: 16 bits.
- Byte: 8 bits.
- Paired result: 64 bits, split into low and high 32-bit halves.

“Scaled by four” means the 32-bit bit-pattern transformation corresponding to a two-bit left shift. “Scaled by sixteen” means the corresponding four-bit shift. Address arithmetic is described at the apparent 32-bit machine width; carry beyond that width is not an additional address bit.

Some intermediates are represented as signed integers. Their overflow and signed-left-shift behavior are not independently established by the supplied representation. This contract therefore distinguishes the apparent machine-width transformation from a portable language-level arithmetic guarantee.

No byte order is needed to specify the individual access values. The effect of overlapping word, halfword, and byte accesses depends on the execution environment’s byte order.

## Behavior

### Dependency notation and execution conditions

The dependency IDs below are opaque, document-local labels for successive call sites. They do not assert that every call site reaches a distinct function. Except for the first call and the final zero-address call, targets are formed from fixed code-related values plus offsets.

A call described as having “no displayed arguments” has no explicit argument expressions in the supplied representation. That wording does not establish a zero-argument ABI.

The sequence below assumes that each preceding call returns normally and each preceding memory operation completes. A fault, nonreturning dependency, or dependency-induced control-flow change can prevent all later operations.

### Initial calls and first word store

The routine invokes F-01 and then F-02, each with no displayed arguments. F-01 uses the incoming-link-derived target.

F-03, also called with no displayed arguments, supplies a 32-bit result **A**. The routine then stores R as a word at the address obtained by scaling A by sixteen and adding 20.

Only after that store, F-04 receives a 32-bit transformation of P:

- P is shifted right logically by two.
- That result is shifted left by sixteen at 32-bit width.

Consequently, only original bits 2 through 17 of P contribute to this argument. Its low sixteen bits are zero.

F-05 returns a word that is passed to F-06. F-07 returns another word that is passed to F-08. F-09, F-10, and F-11 then run in that order with no displayed arguments.

### Second word store and P-derived store

F-12 returns a 32-bit result **B**. The routine stores R as a word at the address obtained by scaling B by four and adding 20. F-13 then receives B scaled by four.

F-14, F-15, and F-16 run in order with no displayed arguments.

F-17 returns a 32-bit result **C**. The routine forms **C4**, the result of scaling C by four, and stores that word at:

- P with its bottom two bits cleared;
- followed by addition of 20.

The destination is therefore word-aligned under the apparent 32-bit address model. This is not evidence that P denotes an allocated object.

F-18 receives two explicit arguments, both C4.

F-19 returns a word forwarded to F-20. F-21 returns a word forwarded to F-22. F-23, F-24, and F-25 then run in order with no displayed arguments.

### Zero store and paired-result stores

F-26 returns a 32-bit result **D**. The routine stores a zero word at the address obtained by scaling D by four and adding 20. F-27 then receives D scaled by four.

F-28, F-29, and F-30 run in order with no displayed arguments.

F-31 returns a represented 64-bit value. Let:

- **L** be its low 32-bit half;
- **H** be its high 32-bit half;
- **L4** be L scaled by four.

The routine stores L4 as a word at the address obtained by scaling H by four and adding 20.

After that store and before F-32, it reads the global pointer-like word and retains its value as **G**. This timing matters: later changes to that global by dependencies do not, by themselves, change the retained base G.

F-32 receives four explicit arguments, in order:

1. L4;
2. H;
3. L4;
4. L4.

F-33, F-34, and F-35 run in order with no displayed arguments.

F-36 returns a 32-bit result **E**. The routine stores L4 as a word at the address obtained by scaling E by four and adding 20.

Immediately after this store, and before F-37, it reads a word from G plus 20. Call this captured word **V**. G was captured earlier, but the contents at G plus 20 are read now, after the intervening calls and store.

F-37 receives E scaled by four. F-38, F-39, and F-40 then run in order with no displayed arguments.

### First byte-table update

F-41 returns a represented 64-bit value. Let **Q** be its low 32-bit half and **T** its high 32-bit half.

Before F-42, the routine:

1. Forms a table address by shifting R right logically by 23 and adding one.
2. Reads one unsigned byte from that address.
3. Adds 17 to the byte value to obtain a destination address.
4. Stores the low eight bits of V at that destination.

The table address is between 1 and 512 inclusive. The byte-derived destination is between 17 and 272 inclusive. No larger base address is visible in this address construction.

F-42 receives four explicit arguments: T, T, T, and Q scaled by four.

F-43 returns a word that is forwarded to F-44. F-45, F-46, and F-47 then run in order with no displayed arguments.

### Second byte-table update

F-48 returns a 32-bit result **J**.

Before using J as a call argument, the routine performs a second table-mediated byte write:

1. It clears the top two bits of Q.
2. It shifts the remaining value right logically by 21 and adds one.
3. It reads one unsigned byte from that table address.
4. It adds 17 to the byte value to obtain a destination address.
5. It stores bits 22 through 29 of V at that destination.

This table address also lies between 1 and 512 inclusive. Its destination also lies between 17 and 272 inclusive.

The table lookup occurs after F-48. It is not a reuse of the earlier table byte. Dependencies between the two updates can change the table or either destination. The first byte write can itself affect a later table read if their addresses overlap.

F-49 receives J scaled by four.

F-50, F-51, and F-52 then run in order with no displayed arguments.

### Final calls, global assignment, and clears

F-53 returns a 32-bit result **K**. F-54 receives two explicit arguments, each K scaled by four.

F-55 runs with no displayed arguments. F-56 returns a word forwarded to F-57.

F-58 runs with no displayed arguments, and its returned word is assigned to the writable global word.

After that global assignment, the routine performs these operations in order:

1. Stores a zero byte through the auxiliary pointer-valued machine result.
2. Forms an address by clearing Q’s top two bits and shifting right logically by seven, then stores a zero halfword there.
3. Invokes F-59 at address zero with three explicit zero arguments.

The halfword destination ranges from zero through 8,388,607 inclusive. It is not necessarily halfword-aligned.

The body has an ordinary return after F-59. Reaching that return requires F-59 to return normally.

## Side effects

The visible body contains eleven direct memory stores:

- Seven word stores, including the late global assignment.
- Three byte stores, including the final pointer-directed clear.
- One halfword store.

It also contains four explicit memory reads outside dependency execution:

- The global pointer-like word producing G.
- The word at G plus 20 producing V.
- The first byte-table lookup.
- The second byte-table lookup.

There is no visible bulk copy, allocation, release, bounds check, alignment check, null check, retry, rollback, or error-reporting branch.

All direct writes occur immediately at their stated positions. There is no visible transaction boundary. If execution stops partway through, earlier writes and dependency effects remain unless the environment independently reverses them.

The memory locations can alias. In particular, table storage, byte destinations, scaled-index destinations, globals, and the final clear destinations are not proven disjoint. Consequently:

- A later write can overwrite an earlier write.
- A preceding write can alter a later explicit read.
- Dependency effects can alter any subsequently accessed memory unless external guarantees prohibit that.

No ownership transfer is established by passing a word to a dependency. The routine does not visibly release memory, but dependencies may do so. A retained address such as G is not evidence that the addressed storage remains valid across calls.

No synchronization or atomicity guarantee is established for these accesses.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Each assumes that preceding operations complete and that the relevant addresses are valid in the target environment.

### P transformation and aligned destination

If P is 262,151, its value is hexadecimal 0x00040007.

- F-04 receives 65,536: the high set bit does not survive the 32-bit shift transformation.
- The P-derived word-store address is 262,168: clear the low two bits, then add 20.
- If F-17 returns 3, that store writes the word 12, and F-18 receives 12 twice.

This distinguishes the transformed argument from the address calculation; they are not interchangeable encodings of P.

### Index scaling

If F-03 returns 2, the first direct word store writes R at address 52.

If F-12 returns 2, the second direct word store writes R at address 28, after which F-13 receives 8.

The two sites therefore use different scaling factors.

### Captured global base versus delayed memory read

Suppose the global pointer-like word contains 4,096 when G is captured. A subsequent dependency changes that global to 8,192 before V is read.

The explicit V read still uses address 4,116. Its value is whatever occupies that address at the time of the read, not necessarily what occupied it when G was captured.

### Byte extraction and aliasing

Suppose V is hexadecimal 0x2AC000AB.

- The first byte update writes hexadecimal 0xAB.
- The second byte update writes hexadecimal 0xAB, obtained from bits 22 through 29 rather than from V’s low byte.

If the first lookup returns 32, its destination is address 49. If address 49 is also the location of the later table lookup, the second lookup observes the effects of that earlier write unless an intervening dependency changes it again.

### Final clear and zero-address call

If Q is 384, the halfword-clear address is 3. The routine does not round this address to an even boundary.

If the environment rejects that unaligned halfword store, F-59 is not reached through normal continuation. If the store succeeds, the next visible action is the zero-address call with three zero arguments.
