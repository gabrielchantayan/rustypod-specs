# F-869b6ddb54d2

## Purpose

F-869b6ddb54d2 determines whether the first matching entry in a fixed collection of 13 records has a nonzero status byte.

The function examines records in ascending index order. Matching compares a record’s 32-bit integer field against an ambient comparison value. The first equality terminates the search, regardless of that record’s status:

- A zero status produces result 0.
- A nonzero status produces result 1.
- If no candidate matches, the function returns 0.

Consequently, result 0 does not distinguish an unsuccessful search from a successful search whose selected status is zero. A later matching record cannot override an earlier match.

“Record,” “comparison value,” and “status” describe their observed structural roles. Their application-specific meanings are not established. A fixed-table status lookup is inferred intent, not an independently established application contract.

## Behavior

### Candidate selection

The search starts at index 0 and proceeds in ascending order.

For each visited candidate, the function evaluates equality between its four-byte integer match field and the ambient comparison value.

A mismatch advances the search. That candidate’s status byte does not participate in the decision and is not read by the supplied logic.

A match selects that candidate immediately. The function then reads the status byte at offset 16 for the selected index and returns:

- 0 when the byte equals zero.
- 1 otherwise.

Both outcomes terminate the function. In particular, a zero status does not cause the search to continue looking for another matching record with a nonzero status.

If candidates 0 through 12 all fail to match, the function returns 0. Index 13 is not examined.

Under stable ambient inputs and record contents, the selected candidate is exactly the lowest-index record whose match field equals the comparison value. The function does not combine statuses, count matches, check uniqueness, or search specifically for a nonzero-status match.
