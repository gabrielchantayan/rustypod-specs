# F-07752de7b4a6

## Purpose

F-07752de7b4a6 conditionally performs a 16-bit memory transfer, may perform a further address-derived 16-bit write, and then enters a nonterminating sequence of two indirect calls and a software interrupt.

No application-level purpose is established. The available evidence does not identify a protocol, record format, allocation service, or conventional library operation.

Under the represented 32-bit arithmetic model, the additional preparation operation **does not change the first indirect-call target**. Its enabling conditions force both the incoming call base and the fifth argument’s storage address to zero. The apparent base adjustment therefore adds zero, and the first call target on that path is `0x00000EB6`.

An unusual machine-state assignment remains separately unresolved. Its presence does not establish a different call target.

This contract distinguishes:

- **Established static evidence:** represented operand widths, control dependencies, memory accesses, call operands, and interrupt selection.
- **Model-dependent deductions:** reachability and address constraints derived using wrapping 32-bit arithmetic and two-byte scaling for 16-bit-element address arithmetic.
- **documented_only unknowns:** actual ABI, memory mappings, dependency behavior, and the execution meaning of unusual represented machine state.

No runtime tests have been performed.

## Behavior

### Arithmetic and address interpretation

Unless otherwise stated, arithmetic conclusions below use 32-bit results modulo \(2^{32}\). High bits discarded by multiplication or addition do not automatically become carry inputs; explicit carry calculations are separate.

Address arithmetic over 16-bit elements advances by two bytes per element. The initial transfer displacement, by contrast, is applied in bytes.

The second argument is multiplied by `0x1000`, retaining the low 32 bits. Consequently:

- Preparation occurs exactly when the second argument’s low 20 bits are zero.
- Otherwise, execution bypasses preparatory memory operations.
- A nonzero argument can select preparation. `0x00100000` is one such value.

An implementation that tests only whether the second argument is zero would not preserve this boundary.

### Path without preparation

When the selection result is nonzero, the function performs no preparatory memory read or write before the call loop.

The initial call base is the incoming call base. The shifted selection result does not replace it.

The represented later preparation gates also remain inactive on this path.

### Initial preparation transfer

When the selection result is zero, the function:

1. Reads an unsigned 16-bit value at the source address.
2. Writes that value as 16 bits at the source address plus the transfer displacement.

The destination address wraps to 32 bits. The displacement is measured in bytes, not 16-bit elements.

The source read precedes the destination write. Equal source and destination addresses still require the represented read followed by write; equality does not eliminate either access. Partial overlap likewise introduces no additional copying operation.

The function also derives an address equal to the transfer destination minus the subtraction quantity. That calculation does not itself access memory.

No bounds, null, alignment, or permissions check protects the transfer. If the read faults, the destination write is not reached. If the write faults, no successful completion or recovery is promised.

### Enabling conditions for the additional preparation operation

After the initial transfer, a sequence of zero-result gates determines whether the additional operation occurs.

Under the represented arithmetic model, the chain requires:

- The incoming call base to be zero.
- The argument-storage address shifted logically right by one bit to be zero.
- The transfer displacement to equal the comparison quantity.
- The subtraction quantity to equal the derived address: transfer destination minus subtraction quantity.
- The accumulator to be zero.
- The argument-storage address plus twice the transfer displacement, with the incoming carry, to have a zero 32-bit result.

On this chain, the selection result and the other early zero-result intermediates are zero. The relevant shifts therefore have zero shift counts. The carry propagated through these gates is zero. The accumulator-stage addition adds only zeros when its gate succeeds, so the carry entering the final enabling addition is also zero.

Let \(A\) denote the argument-storage address and \(D\) the transfer displacement. The final constraint is therefore:

\[
A + 2D \equiv 0 \pmod {2^{32}}.
\]

The earlier condition \(A \mathbin{\gg} 1 = 0\) restricts \(A\) to zero or one. Since \(2D\) is even and the wrapped result is zero, parity excludes one. Thus:

\[
A = 0,\qquad D \in \{0,\ \texttt{0x80000000}\}.
\]

The displacement restriction follows from the wrapped multiplication; it must not be narrowed to zero alone.

The subtraction condition can also be expressed as the transfer destination equaling twice the subtraction quantity modulo \(2^{32}\).

These gates do not report validation errors. Failure of any gate skips the additional operation and proceeds toward the call loop. The initial transfer has already occurred.

### Additional preparation operation

When the entire chain succeeds, both the incoming call base and the argument-storage address are zero.

The represented additional operation includes:

- An unusual machine-state assignment whose assigned numerical value is 64 times the argument-storage address.
- Calculation of a candidate call base equal to the old base plus 64 times that address.
- Two represented 16-bit read occurrences through the old call base.
- A 16-bit write whose destination comes from one read and whose value comes from the other read plus 15.
- Adoption of the candidate call base for subsequent represented control flow.

The candidate base is zero: the old base is zero and the added quantity is zero. **This operation does not alter the represented first-call target.**

The machine-state assignment likewise has a calculated value of zero on this path. Its actual execution effect is **documented_only**. It must not be dismissed as an ordinary harmless local assignment.

Both read occurrences address zero. One supplies a zero-extended destination address in the range `0x00000000` through `0x0000FFFF`. The other supplies an unsigned 16-bit value to which 15 is added; the stored result is truncated to 16 bits.

For stable memory, both reads yield the same value. If that value is \(q\), the operation writes the low 16 bits of \(q+15\) at numerical address \(q\).

The representation does not establish a dependable relative evaluation order for these two reads or justify treating them as one atomic sample. Read-sensitive or concurrently changing memory can therefore make the destination-producing and value-producing observations differ. The destination write follows the observations needed to determine its address and value.

An inaccessible address zero can fault before the additional write or either indirect call. No null-address protection is represented.

### Fully enabled additional operation

Assume accessible memory and argument storage, with:

- Second argument zero.
- Incoming call base and argument-storage address zero.
- Transfer displacement, comparison quantity, and accumulator zero.
- Source address `0x2000`.
- Subtraction quantity `0x1000`.

### Argument-storage address one

Assume the preceding gates succeed and the argument-storage address is one. Although shifting that address right by one produces zero, adding twice any 32-bit displacement produces an odd result, never zero modulo \(2^{32}\).

The additional operation cannot execute. No base adjustment by 64 and no corresponding target change is established.

### High-bit displacement

For example, source address `0x2000` produces destination `0x80002000`. Subtraction quantity `0x40001000` satisfies the subtraction equality. If all other conditions and memory prerequisites hold, the additional operation is enabled and still leaves the call base zero.

### Failure and nonreturning dependencies

If F-000000000001 does not return, F-000000000002 and the interrupt are not reached in that iteration.
