# F-007ca869e9c9

## Purpose

F-007ca869e9c9 updates a shared configuration record and, for supported modes, selected fields of a separate output record. Its behavior combines eight scalar inputs, existing record contents, a global numeric operand, and opaque dependency calls.

The supported full-width mode values are zero and one. Both return the 32-bit value zero after completing their output operations. Other modes return `0xffffffff`, but rejection occurs **after** configuration mutation and common dependency calls. Rejection is not transactional.

The relationships among the inputs and outputs suggest dimension or scaling calculations. That is **inferred intent**, not an established mathematical specification. The supplied evidence does not establish the numeric meanings of the dependencies or how argumentless dependencies receive their effective inputs.

## Behavior

A separate global 32-bit value is called the **global factor**. Each described read obtains its value at that use site; it is not an entry-time snapshot.

### Common preparation

The following phases precede mode validation.

**Measure preparation.** The function calls U on Second measure, then U on First measure, then P with the converted First measure first and the converted Second measure second. The P result is the **measure token**.

**Previous-value preparation.** The function captures the configuration pointer, then separately rereads the configuration-reference global. Through the pointer obtained by that second read, it loads the old `0x10` field. It calls S on that value, then Q with the S result first and the measure token second. This produces the **previous-extent token**.

**Configuration mutation.** Through the captured configuration pointer, the stores occur in this order:

1. First extent to `0x10`.
2. Second extent to `0x14`.
3. Low eight bits of Mode to `0x00`.
4. First attribute to `0x01`.
5. Second attribute to `0x02`.

**Axis preparation.** The function reads captured configuration `0x1c` and calls U on it. It then calls S on Second extent and P with that S result first and the converted field second. The P result is the **second-axis token**.

Next, it calls S on First extent. It then reads captured configuration `0x18` and calls P with the First-extent S result first and that raw field second. This produces the **first-axis token**.

The two extent S results are retained independently of the axis tokens.

**Prepared-token calculation.** The function calls Q with converted First measure first and the first-axis token second. It then calls P with that Q result first and converted Second measure second. This produces the **prepared token**.

### Branch selection and equality replacement

The branch-selection flag is true when:

- Comparison control is zero; or
- Comparison control is nonzero and Second measure is less than or equal to First measure under unsigned 32-bit comparison.

Only when Comparison control is nonzero and the measures are equal, three retained values are replaced:

| Retained value | Replacement |
|---|---|
| Measure token | Raw pattern `0x3f800000` |
| Prepared token | First-axis token |
| Previous-extent token | S result for First extent |

The earlier calls producing the replaced values still occur. The replacement pattern’s association with floating-point one does not establish its interpretation here.

### Final common preparation

The function reads configuration `0x20`, calls U on it, and calls P with the retained S result for Second extent first and that conversion result second.

It then reads configuration `0x24`, calls U on it, and calls P with the current previous-extent token first and that conversion result second.

F-13e966bdb827 receives the result associated with `0x24` as its first argument and the result associated with `0x20` as its second argument. Its explicit return is unused.

Only after that call does the function capture the output pointer. Full-width Mode then selects completion or rejection.

### Mode zero: true branch-selection flag

The function reads configuration `0x28` and calls Q with that field first and the measure token second. It then reads the global factor and calls Q with the preceding Q result first and the factor second.

P receives the retained S result for Second extent first and this second Q result second. Its result becomes the **first final token**.

A further P call receives the same Second-extent S result first and the first Q result second. Its explicit return is discarded. F-eb34c4d75211 is then called without explicit arguments.

The extractor’s result is stored to output `0x4c`. Output `0x44` is then calculated from First extent minus that extracted value: the difference is converted to unsigned 32 bits, logically shifted right by one, and shifted left by four with a 32-bit result. Output `0x48` is then set to zero.

The **second final token** is the previously prepared second-axis token.

### Mode zero: false branch-selection flag

The function rereads configuration `0x1c` and calls U on it, then reads configuration `0x28`.

It calls Q with the retained S result for First extent first and the read `0x28` value second. A second Q receives that result first and the measure token second. P then receives the second Q result first and the converted `0x1c` value second. This P result becomes the second final token.

Next, Q receives the First-extent S result first and the measure token second. Another Q receives that result first and the already-read `0x28` value second. The latter return is discarded.

F-eb34c4d75211 is called without explicit arguments. Its result is stored to `0x50`. Output `0x48` then receives Second extent minus the extracted value, converted to unsigned 32 bits and logically shifted right by one. Output `0x44` is then set to zero.

The first final token remains the first-axis token.

### Mode-zero completion

Following either branch, the explicit store order is:

1. Zero to `0x54`.
2. Zero to `0x58`.
3. `0x000002d0` to `0x5c`.

The function then rereads captured configuration `0x1c` and copies that raw 32-bit pattern to output `0x60`.

Only one of output `0x4c` and `0x50` is explicitly written. The other is not cleared.

### Mode one: true branch-selection flag

The function reads the global factor and calls P with the retained S result for First extent first and the factor second. The result becomes the first final token.

It stores zero to output `0x54`, then performs this ordered dependency sequence:

1. P with the Second-extent S result first and the prepared token second.
2. A fresh configuration `0x1c` read, followed by U on that value.
3. F-36fc8318175d with the converted field first and the preceding P result second.
4. F-f2b8ff34d9f0 with the F-36fc8318175d result first and `0xffffffff` second.
5. F-c9e0501fef5b without explicit arguments.

The last result is stored to `0x58`. The second final token is the prepared token.

### Mode one: false branch-selection flag

Dependency order in this branch is contractual, including the order of intermediate P calls:

1. Read configuration `0x1c` and call U on it.
2. Read and retain the global factor for later use by F-65f7a4af79d5.
3. Obtain configuration `0x28` and a second global-factor value as the first and second operands, respectively, of Q.
4. Call P with that Q result first and the converted `0x1c` value second. Retain this result as the **field-derived intermediate**.
5. Call P with the second-axis token first and the measure token second. Retain this result as the **axis-derived intermediate**.
6. Call P with the axis-derived intermediate first and the field-derived intermediate second. Its result becomes the first final token.
7. Call P with the First-extent S result first and the first final token second.
8. Call F-65f7a4af79d5 with the preceding P result first and the earlier retained global-factor value second.
9. Call F-f2b8ff34d9f0 with that dependency’s result first and `0xffffffff` second.
10. Call F-eb34c4d75211 without explicit arguments.

Thus, the field-derived intermediate is produced **before** the axis-derived intermediate, but their results are supplied to the combining P call in **reverse production order**. Reordering the intermediate calls is not justified.

The final extractor result is stored to `0x54`, followed by zero to `0x58`. The second final token is the second-axis token.

The two operand reads used by Q in step 3 belong to one supplied expression; their relative evaluation order is not independently established. Both are distinct from the earlier retained factor read.

### Mode-one completion

The function calls P with the First-extent S result first and the first final token second, discarding its explicit return. It then calls F-c9e0501fef5b and stores the result to `0x5c`.

It calls P with the Second-extent S result first and the second final token second, again discarding its explicit return. It then calls F-c9e0501fef5b and stores the result to `0x60`.

Mode one makes no explicit stores to `0x44`, `0x48`, `0x4c`, or `0x50`.

1. Call F-f2b8ff34d9f0 with the first final token and the 32-bit value nine.
2. Call F-c9e0501fef5b and store its result to `0x64`.
3. Call F-f2b8ff34d9f0 with the second final token and the 32-bit value eight.
4. Call F-c9e0501fef5b and store its result to `0x68`.

## Side effects

- Configuration mutation precedes mode validation.
- Record stores are ordered but are not shown to be atomic as a group.
- The initial previous-value read uses a separately reread configuration reference. Subsequent explicit configuration accesses use the captured pointer.
- Explicit output stores use the output pointer captured after F-13e966bdb827. Later changes to that global reference do not redirect these stores.
- Configuration fields and the global factor are read at individual use sites, not snapshotted comprehensively.
- Dependencies may change memory or global references. An unwritten field therefore need not retain its entry value.
- No explicit rollback, synchronization, allocation, or release is present.
- Safety under concurrency, reentrancy, or overlapping records is not established.

Placement right shifts are logical, not arithmetic. A representable subtraction result of minus one becomes `0xffffffff` on unsigned conversion; it is not clamped to zero.

The subtraction expressions have signed-looking operands before unsigned conversion. Behavior when their mathematical difference exceeds the signed 32-bit range remains unresolved. The subsequent unsigned conversion does not by itself prove how an overflowing subtraction behaves.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Full-width mode rejection.** With Mode 256 and normal common preparation, configuration `0x00` receives zero, but the result is `0xffffffff`. No explicit output store occurs.

2. **Separate configuration-reference reads.** If the initial capture obtains one record and the next reference read obtains another, the old `0x10` operand comes from the second record. Configuration writes and subsequent configuration reads target the first, subject to valid storage and normal continuation.

3. **Disabled comparison.** Comparison control zero selects the true branch even when First measure is smaller than Second measure. Equal measures do not cause token replacement in this case.

4. **Enabled equality.** Nonzero Comparison control with equal measures selects the true branch and applies all three replacements. Earlier preparation calls still occur.

5. **Unsigned boundary.** With nonzero Comparison control, First measure zero, and Second measure `0xffffffff`, the false branch is selected.

6. **Mode-one false-branch ordering.** Its call trace must produce the field-derived P result before the axis-derived P result, then combine them with the axis-derived result first. Matching final values under pure test doubles would not justify reversing these calls.

7. **Mode-zero true placement.** If First extent is 100 and the applicable F-eb34c4d75211 result is 40, the branch stores 40 to `0x4c`, 480 to `0x44`, then zero to `0x48`.

8. **Mode-zero false placement.** If Second extent is 100 and the extractor returns 41, the branch stores 41 to `0x50`, 29 to `0x48`, then zero to `0x44`.

9. **Negative difference without subtraction overflow.** If the applicable extent is zero and the extracted value is one, the difference is representable as minus one. The true branch writes `0xfffffff0` to `0x44`; the false branch writes `0x7fffffff` to `0x48`.

10. **Fresh raw copy.** In mode zero, if the final configuration `0x1c` read yields `0x81234567`, output `0x60` receives exactly that pattern, regardless of earlier reads.

11. **Conditional write preservation.** With noninterfering dependencies and nonoverlapping storage, mode one leaves `0x44` through `0x50` unchanged. In mode zero, the unselected field among `0x4c` and `0x50` remains unchanged.
