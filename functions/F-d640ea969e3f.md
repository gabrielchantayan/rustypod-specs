# F-d640ea969e3f

## Purpose

F-d640ea969e3f conditionally dispatches a supplied record through one of two indirect operations associated with a supplied object. It returns the first nonzero result produced by an eligible indirect operation, or zero if no such result is produced.

Two routing conditions are visible:

- A record whose 32-bit field at byte offset `+4` equals `13` is eligible for the first indirect operation only when F-468ee00d626a returns `110`.
- A record whose subsequently read field at byte offset `+4` equals `15` is eligible for the second indirect operation only when its 32-bit field at byte offset `+8` equals the object’s 32-bit field at byte offset `+80`.

The second condition is evaluated after the first route has either been skipped or returned zero. Consequently, changes made by a dependency can affect subsequent routing.

The interpretation of these values as event types, commands, ownership identifiers, or other application concepts is unknown. “Object,” “record,” and “operation table” below describe observed structural roles, not established domain meanings.

## Behavior

### 1. Initial discriminator read

The function first reads the 32-bit field at record offset `+4` and compares it with decimal `13`.

If the value differs from `13`, it skips F-468ee00d626a and the first indirect operation. Execution continues to the second routing stage.

If the value equals `13`, the function calls F-468ee00d626a with the record reference.

The helper result is compared with decimal `110`. Any other result skips the first indirect operation and continues to the second routing stage.

The first discriminator comparison is not repeated before the first indirect operation. If F-468ee00d626a changes the record discriminator but returns `110`, the first indirect operation remains eligible.

### 2. First indirect operation

When the initial discriminator was `13` and F-468ee00d626a returned `110`, the function obtains an indirect target through the object’s operation table at byte offset `+248`.

The displayed call supplies:

- The object reference.
- The record reference.

The operation-table lookup occurs after F-468ee00d626a returns. There is no basis for treating the table address as a value captured before the helper call.

If this indirect operation returns nonzero, the function immediately returns that result. No second-stage discriminator or comparison-field reads are then performed by the visible body.

If it returns zero, execution continues. Zero does not establish that the operation had no side effects or that it left the object and record unchanged.

### 3. Second discriminator read

After the first route has been skipped or has returned zero, the function reads the 32-bit discriminator at record offset `+4` again.

This is a fresh read. It is not a reuse of the initial discriminator value.

The second route is considered only if this newly read value equals decimal `15`.

If it differs from `15`, the function returns zero without reading the record field at `+8`, the object field at `+80`, or the second operation-table slot.

### 4. Comparison-field reads

When the second discriminator read yields `15`, the visible sequence reads:

1. The 32-bit field at record offset `+8`.
2. The 32-bit field at object offset `+80`.

The two values are then compared for equality.

No signed ordering, range comparison, masking, truncation to a smaller field, or arithmetic transformation is visible. Equality concerns the full 32-bit values.

If they differ, the function returns zero and does not invoke the second indirect operation.

The routing decision uses the values obtained by these reads. The body does not visibly revalidate the discriminator after reading the comparison fields.

### 5. Second indirect operation

When the second discriminator is `15` and the comparison fields match, the function invokes the operation associated with operation-table byte offset `+224`.

The displayed call has eight argument positions:

1. The object reference.
2. The record reference.
3. A target value obtained from the same operation-table slot used for this dispatch.
4. The fourth formal argument.
5. An unresolved incoming machine-state value.
6. Another unresolved incoming machine-state value.
7. A third unresolved incoming machine-state value.
8. An unresolved value associated with incoming return-link state.

Only the first two arguments have straightforward structural roles. The displayed third argument is another access to the dispatch-slot value, not an established independent application input.

The true signature and validity of the additional argument positions are **documented_only**. They may reflect calling-convention reconstruction rather than eight intentional application-level parameters. The visible material is insufficient to replace them with invented meanings or to specify their widths beyond what the representation exposes.

If this operation returns nonzero, its result is returned directly. If it returns zero, the function returns zero.

### 6. Routing and arithmetic boundaries

The body has no loop or retry mechanism. Each dependency can be invoked at most once per invocation of F-d640ea969e3f.

Both indirect operations can execute during one invocation, but only if the first returns zero and the second routing conditions subsequently hold. With stable record contents, the initial `13` discriminator and later `15` discriminator cannot both hold. Dependency-induced changes can make both routes execute.

Visible address calculations use fixed byte offsets. No input-dependent multiplication, size accumulation, numeric increment, or overflow-sensitive business calculation is present. Address validity and the target machine’s address arithmetic remain preconditions.
