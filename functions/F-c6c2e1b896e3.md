# F-c6c2e1b896e3

## Purpose

F-c6c2e1b896e3 conditionally changes a globally addressed selection, compares fields of selection records, and invokes dependencies in a defined sequence.

A zero request disables the operation. Otherwise, the function derives a target index by subtracting one from the request, calls an initial dependency, and obtains the old index. If the indices differ, it writes the target before processing records.

The function returns a 32-bit word combining the initial dependency’s result with packed status predicates and an incoming byte. This result is not established to indicate success or to describe the final selection.

**Inferred intent:** the comparisons and ordered operations resemble coordinated adjustment when switching configurations. The meanings of the fields, operations, and constant 1200 are not established.

## Behavior

### 1. Disabled request

Read the request word.

If it is zero, return exactly zero. This path contains no dependency call, selection-pointer capture, selection-cell access, table access, or selection write.

### 2. Target derivation and selection observation

For a nonzero request, the established order is:

1. Derive the 32-bit target index from the request minus one.
2. Call F-f120802e6343 and retain its 32-bit result.
3. Read the selection-pointer source and retain that pointer.
4. Reference the selection-pointer source again and load the old index through the address supplied by that reference.
5. Compare the saved target and old index.

Thus, the old index is observed after F-f120802e6343 returns. No preservation of globals by that dependency is assumed.

The pointer used to load the old index is obtained through the global source, rather than being expressed as a dereference of the captured selection pointer. No dependency invocation intervenes between pointer capture and the old-index load, but the supplied evidence does not establish protection against other mutation of the pointer source.

For ordinary positive requests, subtraction maps one-based requests to zero-based indices. The representation mixes signed request arithmetic with unsigned index storage; signed-boundary behavior is discussed under **Uncertainties**.

### 3. Unchanged selection

If the saved target equals the saved old index:

- Do not write a selection cell.
- Do not capture or access the record table.
- Do not invoke any later dependency.
- Return the retained initial result combined with the status contribution.

This decision concerns the two saved indices. It does not establish that the cell addressed by the captured selection pointer contains that index.

The constructed status predicates are negative false, zero true, carry/no-borrow true, and signed overflow false.

### 4. Changed-selection write and optional preliminary operation

If the indices differ, reference the selection-pointer source again and write the target through the address it supplies.

This write is not expressed through the captured selection pointer. No dependency invocation occurs between pointer capture, old-index loading, and this write. Nevertheless, stability of the pointer source against other mutation is not established. The capture, load, and write therefore cannot unconditionally be described as accessing one cell.

The write precedes every subsequent dependency invocation.

If the saved target is zero, call F-unmapped-01 with 1200 immediately after the write and before table-base capture.

No rollback is shown if a later call fails, does not return, or changes shared state.

### 5. Table-base capture and first Field A comparison

After the optional preliminary call, read the table-base source and retain its value as the captured table base.

The first comparison then references the table-base source again for **each** of its two record addresses:

- The current-side address uses a table base obtained from the global source and an index read through the captured selection pointer.
- The old-side address uses a table base obtained from the global source and the saved old index.

Read Field A at those addresses and compare the values as unsigned 32-bit quantities. If current Field A is strictly smaller than old Field A, call F-4e12fc80816d with the two shown arguments, 0 and 3.

The captured table base does not govern this comparison. The capture and the two comparison-side references are distinct accesses in the supplied representation. Without a stability guarantee, the two sides need not use the same base, and neither need use the captured base.

The relative evaluation order of the two comparison operands, including their global references, is not established.

### 6. Remaining record operations

All remaining record addresses use the captured table base, not fresh reads of the table-base source.

The saved old index remains fixed. A “current index” below is loaded through the captured selection pointer, not through a fresh read of its global source.

The sequence is:

1. **Establish the saved old-record address.** After the first Field A comparison and any resulting notification, form the old-record address from the captured table base and saved old index. Retain this address for the Field D checks.

2. **First Field D comparison.** Read old Field D through that saved address and current Field D using the captured base and a current-index reload. If old Field D is strictly smaller, call F-4e12fc80816d with the two shown arguments, 8 and 3.

3. **Fields B and C operation.** Reload the current index once and form its record address using the captured base. Read the 32-bit Fields B and C from that record, mask each to its low eight bits, and call F-unmapped-02 with those values in B-then-C argument positions. The two field reads share the formed record address; their relative read order is not established.

4. **Second Field D comparison.** Reload the current index and compare current Field D against old Field D through the saved old-record address. If current Field D is strictly smaller, call F-4e12fc80816d with 8 and 3.

5. **Last Field A comparison.** Reload the current index and retain its Field A value using the captured base. Read old Field A using that same captured base and the saved old index. If old Field A is strictly smaller than the retained current value, call F-4e12fc80816d with the three shown arguments, 0, 3, and the retained value’s low eight bits.

All comparisons are strict and unsigned. Equality does not trigger a notification.

The two Field D checks are separate reads on opposite sides of F-unmapped-02. The two Field A checks also use separate reads and, importantly, different base-selection rules.

Dependencies may change the captured-pointer cell or record contents between stages. A saved address remains the same address; its contents are not a snapshot. Changing either global pointer source does not redirect an already captured pointer or base.

### 7. Optional final operation

After record processing:

- A saved target of zero suppresses the final operation.
- A nonzero saved target with saved old index zero causes a read of the final-operation argument followed by F-unmapped-01 with that value.
- Nonzero saved target and nonzero saved old index cause no final call.

These decisions use saved indices, not the current contents of any selection cell. Dependency mutations do not change the condition, and the function performs no later write to restore the target.

### 8. Return construction

Every non-disabled return is the retained result of F-f120802e6343 bitwise-ORed with a packed contribution.

The constructed byte assigns:

| Byte bit | Predicate | Result bit after the 32-bit shift |
|---|---|---|
| 4 | Negative | 31 |
| 3 | Zero | 30 |
| 2 | Carry/no-borrow | 29 |
| 1 | Signed overflow | 28 |
| 0 | No independently constructed predicate | 27 |

The constructed byte is ORed with the incoming status byte, reduced to eight bits, and shifted left by 27 into the 32-bit result. Only byte bits 0–4 survive. Incoming bits 5–7 have no effect. Incoming bits 0–4 can set result bits even when the corresponding constructed predicate is false. No bits from the initial dependency’s result are cleared.

Constructed predicates depend on the path:

| Path | Negative | Zero | Carry/no-borrow | Signed overflow |
|---|---|---|---|---|
| Unchanged selection | False | True | True | False |
| Changed selection, zero target under ordinary request-one arithmetic | True | False | False | False |
| Changed selection, nonzero target | Sign bit of 32-bit old index minus one | Old index equals one | Old index is nonzero | Old index equals `0x80000000` |
