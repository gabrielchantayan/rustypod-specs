# F-853dcd8e6902

## Purpose

F-853dcd8e6902 searches forward from a caller-supplied 32-bit position for a nonzero 16-bit result in blocks obtained through F-2a608085a170. On success, it replaces the caller’s position with the position associated with that result and returns the result’s 16-bit bit pattern. If the search terminates without a result, it writes zero to the caller’s position and returns zero.

The search is strictly forward relative to the supplied position except when the initial 32-bit increment wraps. Blocks contain a starting offset, an entry count, an additive adjustment, a displacement, and two-byte entries. A zero entry is skipped. A nonzero entry whose adjusted result becomes zero after 16-bit truncation is also skipped.

The apparent intent is enumeration of mapped positions in a nominal 16-bit search space. That intent does not establish that blocks are limited to 256 entries, that positions remain within that space during a block scan, or that every intervening block is visited.

## Interface

### Inputs

The function receives two arguments:

- **Context reference:** An address represented by a 32-bit argument in the supplied evidence. A four-byte value is read at byte offset 16 from this address. That value is passed as the first argument to F-2a608085a170.
- **Position reference:** A readable and writable reference to a 32-bit unsigned value. Its initial value establishes where the search begins. The same storage receives the final position or zero.

The context value is fetched before the initial position is read. It is fetched once and retained for subsequent dependency calls. The initial position is also read once by this function; subsequent changes to that storage do not directly change the local search position.

### Return value

The return value is a signed 16-bit quantity:

- Zero indicates that no qualifying result was returned.
- A nonzero value carries the low 16 bits of an accepted adjusted entry.

Bit patterns from `0x8000` through `0xFFFF` therefore represent negative signed results. They remain successful results; success is not restricted to positive values.

The supplied evidence establishes the returned 16-bit representation, not any wider-register sign-extension convention imposed by a particular calling environment.

### Block layout

A non-null result from F-2a608085a170 is treated as a byte-addressed block with the following fields. Every two-byte field and entry is interpreted in big-endian byte order.

| Byte offset | Width | Meaning |
|---|---:|---|
| 0 | 2 bytes | Starting offset |
| 2 | 2 bytes | Entry count |
| 4 | 2 bytes | Additive adjustment |
| 6 | 2 bytes | Entry displacement |
| Variable | 2 bytes per entry | Entry values |

All four header fields are unsigned 16-bit quantities when used in calculations.

For entry index \(i\), the entry address is:

\[

The displacement is relative to byte offset 6, not to the end of the eight-byte header. A displacement of 2 places entry zero immediately after the header. A displacement of 1 produces an odd byte address. Neither case is rejected by this function. A displacement of zero disables scanning of that block.

## Behavior

### Initialization and outer search

The function captures the context’s four-byte dependency argument, initializes its result to zero, and forms the first candidate by adding one to the initial position using 32-bit unsigned arithmetic.

Consequently:

- An initial position of `0xFFFFFFFF` produces candidate zero.
- Initial positions from `0x0000FFFF` through `0xFFFFFFFE` produce candidates outside the admitted outer-search range and cause no dependency call.
- An initial position of `0x0000FFFE` produces candidate `0x0000FFFF`, which is admitted.

An outer-search iteration is entered only when the current candidate is less than `0x00010000`.

For each admitted candidate, the function calls F-2a608085a170 with:

1. The previously captured four-byte context value.
2. The full current 32-bit candidate.

The dependency receives the candidate itself, not a value with its low eight bits cleared.

A null result causes that iteration to proceed directly to outer advancement.

### Selecting the first entry in a block

For a non-null block, the function reads the starting offset and then the entry displacement.

A zero displacement causes the block to be skipped without scanning entries.

For a nonzero displacement, define:

- \(B\): the current candidate with its low eight bits cleared.
- \(L\): the current candidate’s low eight bits.
- \(S\): the block’s 16-bit starting offset.

The first entry index and the candidate associated with that entry are:

| Condition | First entry index | Associated candidate |
|---|---:|---:|
| \(L < S\) | 0 | \(B + S\) |
| \(L \geq S\) | \(L - S\) | \(B + L\) |

Thus, a starting offset greater than the current low byte advances the candidate to the block’s stated start. The starting offset is not truncated to eight bits. Values greater than 255 can move the candidate beyond the nominal 256-position region.

The entry pointer is formed using the selected index and the displacement formula above. Entry scanning proceeds only while the index is less than the block’s entry count. If the first index already equals or exceeds the count, no entry is read.

### Evaluating entries

Entries are considered in increasing index order, with the associated candidate increasing by one after each rejected entry.

For each reached entry:

1. Its two bytes determine an unsigned 16-bit raw value.
2. If the raw value is zero, the entry is rejected without applying the adjustment.
3. Otherwise, the raw value and the header’s unsigned 16-bit adjustment are added.
4. The sum is reduced to its low 16 bits and treated as the signed 16-bit result.
5. A zero reduced result is rejected. Any other result is accepted.

For example, raw value `0xFFFF` plus adjustment `0x0001` is rejected because its low 16 bits are zero. Raw value `0x8000` plus zero is accepted and returned with signed value −32768.

On acceptance, scanning stops immediately. The current associated candidate is written to the caller’s position, and the accepted result is returned.

A candidate of zero can be accepted after initial unsigned wraparound. Therefore, an output position of zero alone does not distinguish success from failure; the return value does.

The block’s entry count is expressed as a fresh header read in each scan-condition evaluation. The adjustment is read when evaluating a nonzero entry. The evidence does not establish a single immutable snapshot of the block.

### Advancing after a block does not produce a result

When an outer iteration finishes without acceptance, the next outer candidate is formed by clearing the low eight bits of the **current** candidate and adding 256.

The current candidate may already have changed while selecting the block’s start or scanning its entries. Advancement is not necessarily based on the candidate originally passed to the dependency.

In particular:

- With a null block, advancement uses the unchanged lookup candidate.
- With zero displacement, advancement also uses the unchanged lookup candidate.
- With a nonzero displacement, even an empty scan can use a candidate changed by the starting-offset calculation.
- After rejected entries, advancement uses the candidate one position beyond the last rejected entry.

This can skip a nominal 256-position region. If rejection of an entry advances the current candidate from `0x00FF` to `0x0100`, the subsequent outer advancement produces `0x0200`, not `0x0100`.

The outer limit is checked only before a dependency call. There is no equivalent limit check for each entry. A block can therefore lead to acceptance at a position of `0x10000` or greater, despite dependency calls being restricted to candidates below `0x10000`.

### Exhaustion

If an outer-range check fails before a result is accepted, the function writes zero to the position reference and returns zero.

The function does not return the last examined position or an end sentinel such as `0x10000`. It overwrites the caller’s original position even when no dependency call occurred.

## Side effects

### Reads and writes

The established logical access order is:

1. Read the four-byte context field.
2. Read the caller’s initial four-byte position.
3. For each admitted outer candidate, invoke F-2a608085a170.
4. For each non-null block, read the starting offset and displacement.
5. For a block with nonzero displacement, evaluate entry-count bounds and read reached entries; read the adjustment for nonzero entries.
6. Write the final four-byte position.

This function performs one explicit write to caller-provided storage, at termination. It does not explicitly modify block storage, allocate memory, or release memory.

This description concerns the accesses represented by the supplied source evidence. It does not establish exact machine-load counts, atomicity, or ordering guarantees suitable for concurrently changing or device-backed memory.

Returned blocks are used as readable storage. The function does not explicitly release them. That observation does not establish that ownership is transferred, that blocks remain valid indefinitely, or that the dependency never allocates or releases memory internally.

F-2a608085a170 may have side effects not shown here. In particular, its effects on globals, context storage, caller storage, previously returned blocks, and memory lifetime are unknown.
