# F-dc0922e5ec14

## Purpose

F-dc0922e5ec14 is a conditional dispatcher over a caller-supplied object and a record addressed by its second argument.

It recognizes two record discriminators:

- **0x13:** optionally offers the complete record to a preliminary handler, then dispatches two record fields to another handler if the preliminary handler did not return a nonzero result.
- **0x14:** dispatches three record fields to a handler.

The function returns zero when neither discriminator is recognized at the final dispatch checks. A normal dispatch returns one regardless of the dispatched handler’s result. A preliminary handler can instead supply any nonzero return value directly.

These are structural descriptions. The application meanings of the discriminators, fields, and global comparison value are not established.

## Interface

### Inputs

The function receives two arguments:

1. **Receiver:** a pointer to an object whose first machine word supplies the address of an indirect-call table.
2. **Record address:** an integer-valued argument used as the base address for fixed-offset memory accesses.

The second argument is used as an address, not merely as a numeric identifier. There is no null check, range check, size check, or explicit alignment check for either argument.

### Record layout

The following locations are accessed relative to the record address:

| Byte offset | Accessed width | Role |
|---|---:|---|
| +0x04 | 32 bits | Discriminator |
| +0x08 | 32 bits | Comparison field and first dispatched payload |
| +0x0C | 32 bits | Preliminary-selection field and second dispatched payload |
| +0x10 | 32 bits | Third payload for discriminator 0x14 |

No direct access to record offset +0x00 is shown.

The fields at +0x08, +0x0C, and +0x10 are forwarded as four-byte quantities. Their meanings and signedness are not established by forwarding alone. The +0x0C field also participates in signed-looking integer arithmetic during preliminary selection.

A contiguous, readable record of at least 20 bytes is sufficient for the shown direct record accesses, but not necessarily for accesses performed by dependencies. The wrapper does not read every field on every path.

### Receiver layout

The receiver’s first word is read to obtain a table address. The following byte offsets within that table select indirect dependencies:

| Table byte offset | Dependency |
|---|---|
| +0x9C | F-000000000001 |
| +0x78 | F-000000000002 |
| +0x5C | F-000000000003 |

These dependency IDs are contract-local opaque labels for call roles. They do not establish independently verified identities or prove that the three table entries contain different function addresses.

The table is resolved at each call site. A table pointer obtained for the preliminary call is not explicitly retained for a subsequent call.

### Output

The result is an integer:

- A nonzero result from F-000000000001 is returned unchanged.
- A completed call to F-000000000002 or F-000000000003 is followed by return value **1**.
- If neither final discriminator check matches, the return value is **0**.

The visible representation supports a 32-bit integer interpretation. Exact calling-convention and pointer-width details remain subject to the representation limits described below.

### Preconditions

For a path to complete normally:

- Every memory location actually read must be valid and readable when accessed.
- A selected table entry must identify a callable dependency with the expected argument and return conventions.
- The receiver and record must remain usable for every access occurring after a dependency returns.
- Arithmetic used in preliminary selection must have defined behavior under the applicable execution model.
- Dependencies must return normally if a normal wrapper return is expected.

The function does not enforce these conditions.

## Behavior

### 1. Preliminary selection

The function first reads the discriminator at record offset +0x04.

If that value is not **0x13**, it does not perform the preliminary-selection arithmetic and does not call F-000000000001.

If the initial discriminator is **0x13**, it reads the field at +0x0C, subtracts **0x6300**, and tests whether the result equals **0x81**.

Only if that arithmetic comparison succeeds does it compare the field at +0x08 with a separately stored global comparison value. Call that global value **G1**. It is read as a 32-bit comparison operand; its address and application meaning are outside this contract.

Thus the preliminary call requires all three conditions:

1. The initial discriminator is 0x13.
2. The arithmetic selection test succeeds.
3. The +0x08 field equals G1.

For values where the subtraction has ordinary defined 32-bit signed behavior, the arithmetic condition selects a +0x0C value of **0x6381**, decimal **25473**. This equivalence does not establish behavior for inputs that cause signed overflow.

The +0x08 field and G1 are not compared unless the preceding discriminator and arithmetic conditions succeed.

### 2. Preliminary call and early return

When preliminary selection succeeds, the function resolves table offset +0x9C and calls F-000000000001 with:

1. The original receiver.
2. The original record address.

If that dependency returns a nonzero integer, the wrapper immediately returns exactly that integer. No subsequent discriminator read or normal dispatch occurs on this path.

If it returns zero, execution continues to the final dispatch checks.

A zero result does **not** imply that the dependency preserved the receiver, record, table pointer, G1, or other state. Subsequent accesses must be understood in terms of the state that exists after the dependency returns.

### 3. Final 0x14 check

The function reads the discriminator at +0x04 again. It does not rely on the initial discriminator value.

If this read yields **0x14**, it resolves table offset +0x78 and invokes F-000000000002 with:

1. The receiver.
2. The current four-byte field at record offset +0x08.
3. The current four-byte field at record offset +0x0C.
4. The current four-byte field at record offset +0x10.

After the dependency returns normally, the wrapper returns **1**. Any result supplied by that dependency is ignored.

This branch ends processing. The later 0x13 check is not reached.

### 4. Final 0x13 check

If the final 0x14 check did not match, the function performs another read of the discriminator at +0x04.

If this read yields **0x13**, it resolves table offset +0x5C and invokes F-000000000003 with:

1. The receiver.
2. The current four-byte field at record offset +0x08.
3. The current four-byte field at record offset +0x0C.

After the dependency returns normally, the wrapper returns **1**, ignoring any dependency result.

If this discriminator read is not 0x13, the wrapper returns **0** without making a normal dispatch call.

### Read ordering and mutation sensitivity

The established control-flow order is:

1. Initial discriminator read.
2. Conditional arithmetic-field read.
3. Conditional comparison involving +0x08 and G1.
4. Conditional preliminary call.
5. Fresh discriminator read for 0x14.
6. If necessary, fresh discriminator read for 0x13.
7. At most one normal dispatch call.

The supplied representation does not establish an exact machine-level order among the individual payload reads and table-lookup reads used to prepare a single indirect call. Likewise, it does not establish which comparison operand is loaded first when comparing +0x08 with G1.

There is no visible synchronization. Repeated reads must not be replaced in this contract by an assumed immutable discriminator. Behavior involving concurrent modification, memory-mapped side effects, or unusual memory semantics is documented_only rather than specified as a portable guarantee.

## Side effects

### Direct effects

The wrapper shows memory reads and indirect calls, but no direct stores to the receiver, record, global comparison value, or other data.

It shows no direct allocation, deallocation, ownership transfer, or reference-count operation.

Passing the receiver and record to a dependency does not prove that those arguments are borrowed, retained, released, or consumed. Dependency ownership rules are unknown.

### Dependency effects

All three dependencies may have side effects not visible in the supplied material.

F-000000000001 is especially significant because its return is followed by further wrapper accesses when it returns zero. For example, it may change:

- The record discriminator.
- Payload fields.
- The receiver’s table pointer.
- G1 or unrelated global state.

Such changes are not prohibited by the visible wrapper. A dependency that invalidates memory needed by later accesses can prevent normal completion; no recovery is shown.

After F-000000000002 or F-000000000003 returns normally, the wrapper performs no further shown record or table access before returning one.

### Errors

There is no explicit error-reporting branch for invalid pointers, unreadable fields, invalid call targets, arithmetic failures, or dependency failures.

A result of zero is therefore a dispatch outcome, not a demonstrated general-purpose error code. Likewise, one indicates that a normal handler returned control, not that its application-level operation succeeded.

## Dependencies

### F-000000000001

- Selected through table byte offset +0x9C.
- Receives the receiver and record address.
- Has an integer result consumed by the wrapper.
- A nonzero result terminates the wrapper with that exact result.
- A zero result permits subsequent dispatch using freshly accessed state.

Its mutation, ownership, exception, and failure behavior are unknown.

### F-000000000002

- Selected through table byte offset +0x78.
- Receives the receiver and three four-byte payload values.
- Is called when the relevant final discriminator read yields 0x14.
- Its result, if any, is ignored.
- Normal return is followed by wrapper result one.

### F-000000000003

- Selected through table byte offset +0x5C.
- Receives the receiver and two four-byte payload values.
- Is called when the later final discriminator read yields 0x13.
- Its result, if any, is ignored.
- Normal return is followed by wrapper result one.

No dependency implementation is available. None is assumed to preserve globals or manage memory in a particular way.

## Acceptance examples

These are conditional contract examples, not executed tests. Unless stated otherwise, memory remains valid and stable, arithmetic is defined, table entries are callable, and dependencies return normally.

| Conditions | Required outcome |
|---|---|
| Discriminator remains 0x14 | No preliminary call. F-000000000002 receives the receiver and the fields at +0x08, +0x0C, and +0x10. Wrapper returns 1. |
| Discriminator remains 0x13; +0x0C is 0x6380 | Preliminary arithmetic test fails. F-000000000003 receives the two payload fields. Wrapper returns 1. |
| Discriminator remains 0x13; +0x0C is 0x6381; +0x08 differs from G1 | No preliminary call. F-000000000003 is called. Wrapper returns 1. |
| Preliminary conditions match; F-000000000001 returns 7 | Wrapper returns 7. Neither normal handler is called. |
| Preliminary conditions match; F-000000000001 returns −3 | Wrapper returns −3 unchanged. Neither normal handler is called. |
| Preliminary conditions match; F-000000000001 returns zero without relevant mutation | F-000000000003 is subsequently called. Wrapper returns 1. |
| Preliminary handler changes the discriminator to 0x14, then returns zero | The fresh final read selects F-000000000002, using payload values accessed after the preliminary call. Wrapper returns 1. |
| Preliminary handler changes the discriminator to 0x12, then returns zero | With that discriminator stable thereafter, neither normal handler is called. Wrapper returns 0. |
| Discriminator remains 0x12 throughout | No dependency is called. Wrapper returns 0. |
| A normal handler returns a numeric failure indication | The wrapper still returns 1 after normal return; the indication is not propagated. |

If the preliminary handler changes the receiver’s table pointer and returns zero, the next handler is selected through the receiver’s then-current table, provided the resulting accesses remain valid.

No accepted outcome is specified for an unreadable required field, an invalid indirect target, or arithmetic overflow whose execution semantics have not been established.

## Uncertainties

The following remain **documented_only**:

- The application purpose and names of the receiver and record fields.
- The identity, value, initialization, and mutability rules of G1.
- The concrete identities and full contracts of the indirect dependencies.
- Whether any table slots resolve to the same implementation.
- The precise ABI, endianness, pointer width, alignment requirements, and indirect-call representation.
- The behavior of signed-looking subtraction outside its representable range.
- Exact machine-level ordering of reads within call preparation and comparison expressions.
- Concurrency, volatile-access, exception, and nonlocal-exit semantics.
- Ownership and lifetime rules imposed by dependencies.

The offsets and four-byte payload annotations strongly support a 32-bit-oriented layout. That is an interpretation of the supplied representation, not independently verified ABI evidence.

The preliminary dependency appears intended to have first refusal over a selected subtype of 0x13 records. “First refusal” is inferred intent; the established behavior is its conditional invocation and nonzero-result early return.

## Evidence

The supplied static material establishes:

- Record accesses at byte offsets +0x04, +0x08, +0x0C, and +0x10.
- Discriminator comparisons against 0x13 and 0x14.
- Preliminary subtraction by 0x6300 and comparison against 0x81.
- Conditional equality comparison with a global value.
- Indirect calls through table byte offsets +0x9C, +0x78, and +0x5C.
- Propagation of a nonzero preliminary result.
- Fresh discriminator checks after a zero preliminary result.
- Constant result one after either normal dispatch and zero after neither matches.
- No direct memory stores or explicit allocation operations in the wrapper.

No runtime tests have been performed. Dependency implementations, live memory observations, and independent ABI evidence were not supplied.
