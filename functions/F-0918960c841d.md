# F-0918960c841d

## Purpose

F-0918960c841d performs an ordered sequence of indirect calls, computed-address byte and word accesses, and an unconditional repeating suffix. The supplied static evidence does not establish an application-level purpose.

No normal return path is visible. If execution reaches the repeating suffix and its calls keep returning normally, execution continues indefinitely.

This contract describes the supplied representation, not independently verified machine behavior. Warnings about invalid instruction data, excluded unreachable regions, and overlapping global storage limit confidence in the recovered interface and operations. No runtime tests have been performed.

## Behavior

### Ordering and execution conditions

The visible control flow consists of a straight-line prefix followed by an unconditional loop. There are no visible validation branches, bounds checks, return-status tests, or recovery paths.

Every described operation is conditional on execution reaching it. An unresolved call may fail to return, fault, transfer control elsewhere, or change memory. Calls with no retained result still constitute observable ordering boundaries.

Repeated stores and selector reads are distinct operations. They must not be merged merely because their represented addresses or payloads match.

### Initial calls and byte transfer

The first call uses an entry-state-relative indirect target. A second indirect call produces a result.

Before passing that result scaled by four to another call, the function reads one byte at the incoming address-like value plus one. It then writes the incoming eight-bit payload at the address obtained by adding \(0x11\) to that unsigned selector byte.

The selector-derived destination therefore lies from \(0x11\) through \(0x110\), inclusive. The selector is one byte, not a full-width pointer.

The scaled-result call is followed by four further represented calls before the global-dependent operations.

### Global-dependent stores

The function reads global storage associated with address \(0x3c\) and converts the result to an unsigned 32-bit value, here called \(G\). The original storage width and extension rule are unresolved.

The third argument selects:

\[
A_P=4(P\gg7)+0x14.
\]

The function writes \(G\) to \(W(A_P)\), calls an unresolved target with \(G\), and makes four further calls. It then writes the same saved \(G\) to \(W(A_P)\) again.

The second store does not visibly reread the global. A change to the global during intervening calls does not replace the retained payload.

For unsigned 32-bit \(P\), this address calculation does not overflow:

\[
0x14\le A_P\le0x08000010.
\]

The low seven bits of \(P\) do not affect the address.

After the second store, the most recently produced call result is passed to another call as \(S(\text{result})\). Four further calls lead into the first result-derived word phase.

### Result-derived word phases

Let \(r_1,\ldots,r_9\) denote separately obtained results initiating the nine ordinary word phases below. These symbols do not imply equal values or common producer identities.

Two captured words have persistent roles:

- \(X\): the word read during phase 1.
- \(Y\): the word read during phase 2.

Also define:

\[
D=8(X\gg8),\qquad H=\operatorname{low}_{32}(r_1\ll26).
\]

The calculation of \(D\) uses all 24 bits remaining after the shift, not merely one selected byte. Its maximum is \(0x07fffff8\).

In the table, calls are listed in their observed order within each phase. “Forwarding” means that a represented 32-bit result from one call becomes an explicit argument of a subsequent call; it does not imply anything about dependency semantics.

| 2 | Write \(S(r_2)\) at \(T(r_2)+0x14\); read \(Y\) at \(S(r_2)+0x14\); later write \(Y\gg8\) at that read address. | First call receives two copies of \(S(r_2)\). Two result-forwarding pairs follow. |

Following each phase’s listed argument-bearing sequence, four calls with no represented explicit arguments produce the result available before its concluding store. After that store, the result is passed scaled by four to another call. Four further calls lead to the next phase, subject to the secondary-result interval described below.

The retained value \(H\) is actually shifted right by seven during phase 2 and again during phase 5. The fourth argument in phase 6 applies another right shift by seven to that already-shifted value, yielding \(H\gg21\). Truncation occurs before these right shifts.

Read and write addresses may alias. In particular, \(r_1=0\) makes phase 1’s initial store and following read both access \(0x14\). No distinct-buffer or structure-layout interpretation is established.

### Secondary-result interval

Between phases 6 and 7, the function consumes a secondary register result, here denoted \(E\). Its provenance and complete producer contract are unresolved.

The function forms:

\[
J=\operatorname{low}_{32}(E\,2^{24})
\]

and writes \(J\) at:

\[
\operatorname{low}_{32}(E\,2^{26}+0x14).
\]

A call receives \(J\). Four calls with no represented explicit arguments follow, the last producing a fresh result \(c\). The function then writes the same saved \(J\) at \(S(c)+0x14\), calls another target with \(S(c)\), and continues through four calls leading into phase 7.

No reread of \(E\) or reconstruction from the new ordinary result is represented for the second payload.

### Byte-oriented suffix

The selector base for this suffix comes from phase 8:

\[
Q=(S(r_8)\mathbin{\&}0x7fffffff)\gg7.
\]

Clearing bit 31 occurs before the shift and is significant.

After phase 9 and its subsequent calls, a fresh result \(R\) supplies the first byte payload. The function reads \(B(Q+1)\), then writes:

\[
\operatorname{low}_{8}(R\ll2)
\]

at \(0x11+B(Q+1)\), using that particular selector read.

Immediately after this store, an unresolved target receives **three copies of the full 32-bit value** \(S(R)\). These arguments are not narrowed to the stored byte.

A result-producing call and a call forwarding that result follow, then four more calls. The selector at \(Q+1\) is then reread, and the function writes:

\[
\operatorname{low}_{8}((R\mathbin{\&}0x3fffffff)\gg20)
\]

through the newly read selector. The payload contains original bits 20 through 27 of \(R\). The expression before eight-bit narrowing can contain ten bits.

The most recent call result is subsequently passed scaled by four. Four more calls produce a new result \(N\).

The next two direct stores are adjacent, with no intervening call:

1. Write \(\operatorname{low}_{8}(N\ll2)\) at \(0x1c+((X\gg24)\gg7)\).
2. Read \(B(Q+1)\) again and write zero at \(0x11\) plus that selector.

The first address is exactly \(0x1c\) or \(0x1d\).

After both stores, a call receives:

\[
(X\gg24)\gg7.
\]

One call with no represented explicit arguments follows. The next argument-bearing call receives:

\[
(N\mathbin{\&}0x3fffffff)\gg6.
\]

Four further calls occur before another fresh selector read at \(Q+1\) and another selector-derived zero-byte write. Thus both known argument-bearing calls occur after the adjacent stores and before this later zero write.

The most recent result is then passed scaled by four, and four further calls produce a result used to initialize the repeating suffix.

### Repeating suffix and both loop-carried values

The repeating suffix uses a different selector address:

\[
Z=\operatorname{low}_{32}(N\ll12)+1.
\]

This follows from scaling the already-truncated \(S(N)\) by \(0x400\), then adding one. The shifted value has twelve zero low bits, so the final addition does not itself overflow.

A later result initializes:

\[
L=(\text{result}\mathbin{\&}0x3fffffff)\gg25,
\]

giving \(0\le L\le31\). Before entering the loop, the function reads \(B(Z)\), writes zero at \(0x11\) plus that selector, and calls a target with \(2L\). A subsequent call produces the first loop-carried ordinary result, denoted \(C\).

**The first iteration receives \(C\) unscaled.**

Each iteration has the following observable structure:

- Its first call receives the current first-argument carrier and \(L\gg8\).
- Four calls with no represented explicit arguments follow; the last produces a fresh result.
- The function rereads \(B(Z)\) and writes zero through that selector.
- A call receives the fresh result scaled by four.
- Four more calls follow; the last produces the iteration’s final result, denoted \(F\).

For the next iteration, the two carried values are separately constructed:

\[
\text{next first-argument carrier}=S(F),
\qquad
\text{next }L=\operatorname{low}_{32}(F\ll26).
\]

The first iteration therefore has a zero second argument, because its initial \(L\) is at most 31. Later second arguments need not be zero.

The address \(Z\) remains fixed in the represented loop, but its selector byte is read afresh on every iteration. There is no visible loop exit.

## Acceptance examples

These are conditional static examples, not executed tests. Each assumes execution reaches the relevant operations and the representation accurately describes them.

1. **Third-argument boundaries.** \(P=0\) and \(P=127\) select \(0x14\); \(P=128\) selects \(0x18\). The selected location receives saved \(G\) twice, separated by calls.

2. **Saved global payload.** If \(G=0x12345678\), changing its source storage during an intervening call does not change the second represented payload.

3. **Read-after-write aliasing.** With \(r_1=0\), phase 1 writes zero at \(0x14\) before reading \(X\) there. For ordinary stable memory without an intervening external modification, \(X=0\).

4. **Saved shifted replacement.** If phase 2 captures \(Y=0xa1b2c3d4\), its concluding write contains \(0x00a1b2c3\), not a shift of a newly read word.

5. **Full-width repeated arguments.** With \(R=0x40000041\), the first suffix byte payload is \(0x04\), while the following three arguments are each \(0x00000104\).

6. **Byte narrowing.** With \(R=0xffffffff\), the first suffix payload is \(0xfc\), and the later masked-and-shifted payload is \(0xff\).

7. **Adjacent stores and later arguments.** If \(X=0x80000000\) and \(N=0xffffffff\), the adjacent payload store writes \(0xfc\) at \(0x1d\), followed by a selector-derived zero store. The subsequent argument-bearing calls receive 1 and, after one intervening call, \(0x00ffffff\), before the later selector-derived zero store.

8. **Fresh selectors.** Selector reads yielding 3 and later 9 produce destinations \(0x14\) and \(0x1a\). Reusing the first selector for the later write would violate the represented ordering.

9. **First versus subsequent loop arguments.** If the pre-loop producer returns 3, the first iteration’s first call receives 3, not 12, and its second argument is zero. If that iteration’s final result is 1, the next iteration’s first call receives \(4\) and \(0x00040000\).

10. **Nontermination.** If the prefix completes and every loop call returns normally, calls and fresh-selector zero writes continue without a normal return.
