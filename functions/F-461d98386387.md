# F-461d98386387

## Purpose

F-461d98386387 conditionally obtains a 32-bit result from one dependency and then, independently of whether that dependency was invoked, offers the result to an optional dynamically dispatched operation.

The established behavior has three stages:

1. Resolve an object from a handle stored in the input structure.
2. Invoke an operation on that object and, if it reports a nonzero low-order result and two signed 32-bit fields satisfy a strict ordering, obtain a replacement result from F-b3f4a7a52609.
3. Resolve another object from a field of the first object and, when successful, return the result of an operation on that second object.

The initial result is the 32-bit pattern `0xFFFFFFFF`. It is not established that this pattern means an error, nor that either dynamically dispatched operation performs validation, cleanup, or result translation. Those interpretations are inferred intent at most.

This contract describes the supplied static representation. No runtime tests have been performed.

## Behavior

### Initial result and first resolution

The selected result begins as `0xFFFFFFFF`.

The function reads the input structure's field at offset `0x38`.

- If that field is zero, it returns the initial result without invoking any dependency.
- If the field is nonzero, the function obtains the handle from that field and calls F-682adfd5a561 with the handle and the constant `0x1700` (5888).

The supplied representation accesses the input field once for the zero check and again to obtain the call argument. It does not establish a single captured value shared by both operations. If the field can change between accesses, the value passed to the dependency need not equal the value that passed the zero check. Compiler-level load merging and concurrency guarantees are not established.

If F-682adfd5a561 returns a null address, the function returns `0xFFFFFFFF`. No dynamic operation, comparison-field read, or second resolution is then performed.

Otherwise, the returned address becomes the first resolved object.

### First dynamic operation

The function reads the first object's dispatch-table address and invokes the callable entry at table offset `0x188`, passing the first object as its sole explicit argument.

The supplied representation treats the operation's result as 64 bits:

- The low-order 32 bits determine whether subsequent comparison-field reads occur.
- The high-order 32 bits do not affect any established output or subsequent call.

A low-order value is considered true whenever its 32-bit pattern is nonzero. The test is not restricted to the value one and is not a positivity test. For example, low-order `0x80000000` is nonzero and therefore enables the comparison.

If the low-order 32 bits are zero, the function skips both comparison-field reads and does not call F-b3f4a7a52609. It nevertheless continues to the second-resolution stage.

### Signed comparison and conditional replacement

When the first dynamic operation's low-order result is nonzero, the function reads:

1. The signed 32-bit field at offset `0x104` from the first object.
2. The signed 32-bit field at offset `0x100` from the first object.

These reads occur after the dynamic operation returns. The contract does not assume that the operation preserved either field.

F-b3f4a7a52609 is invoked exactly when the value read at `0x104` is strictly greater than the value read at `0x100`, using signed 32-bit ordering. The first object is its sole explicit argument.

The subtraction and signed-overflow checks in the supplied representation implement that ordering. They must not be replaced semantically with a test of whether the wrapped 32-bit difference is positive: a wrapped-difference test alone would give incorrect results near the signed limits.

Consequences include:

- Equal operands do not qualify.
- A positive value at `0x104` and a negative value at `0x100` qualify.
- A negative value at `0x104` and a nonnegative value at `0x100` do not qualify.
- The signed interpretation matters even when the corresponding unsigned ordering is different.

If F-b3f4a7a52609 is invoked and returns normally, its 32-bit return value replaces the selected result. Otherwise, the selected result remains `0xFFFFFFFF` at this stage.

There is no additional check on the returned value.

### Second resolution

It calls F-682adfd5a561 with that field value and the constant `6`.

This stage is reached whenever the first resolution succeeded and the preceding calls returned normally. It does not depend on:

- The first dynamic operation returning a nonzero low-order value.
- The signed comparison succeeding.
- F-b3f4a7a52609 being invoked.
- The selected result differing from `0xFFFFFFFF`.

Unlike the input structure's handle, this handle is not checked for zero before the resolution call. A zero value is passed to F-682adfd5a561.

The handle is read after any conditional call to F-b3f4a7a52609. If that dependency changes the field, the second resolution uses the value subsequently read, not an earlier snapshot. The same principle applies to changes made by the first dynamic operation.

If this resolution returns null, the function returns the currently selected result unchanged.

### Final dynamic operation

The explicit arguments are, in order:

2. The currently selected 32-bit result.

There is no special treatment of zero, `0xFFFFFFFF`, or any other returned pattern. There is no visible retry or alternate dispatch.
