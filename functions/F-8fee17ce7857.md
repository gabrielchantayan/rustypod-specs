## Acceptance examples

These are conditional static acceptance examples, not executed tests.

### Input publication precedes dependency execution

If the input word is 3 and the first store succeeds, the first visible store writes the word 3 at address `0x20`. F-D01 receives 3 afterward. Moving that store after F-D01 would violate the displayed ordering.

### Scaled store and following read remain distinct

If R4 is 2, the routine stores 8 at address `0x34`, then reads W from address `0x1c`. A reconstruction that reads W from `0x34` would not match the evidence.

### Logical word shift

If the captured W is `0xabcdefff`, the later word store at A(R5) contains `0x000abcde`. Intervening changes to the memory location from which W was read do not change this captured value.

### Three-argument bit extraction

If R5 is `0x00000013` and R6 is 2, F-D31 receives:

- `0x00030000`;
- `0x00000008`;
- `0xc0000000`.

This example assumes the displayed 32-bit arithmetic and successful completion of preceding operations.

### Byte truncation differs from call arguments

If R8 is `0x00000041`, the first byte store writes `0x04`. F-D41 nevertheless receives `0x00000104`, `0x00000104`, and `0x00000410`. Truncating the call arguments to match the byte store would be incorrect.

### Destination selector is reread

Suppose the first read at C yields `0x20`, the second yields `0x80`, and R8 is `0x0ab00041`.

The first byte store targets `0x31` and writes `0x04`. The second targets `0x91` and writes `0xab`. F-D53 later receives `0x80` as its second argument. Reusing the first selector would violate the visible behavior.

### Failure preserves only a reached prefix

If F-D01 does not return, no later operation is established to occur. The initial word store has already been attempted and, if successful, is not visibly undone.
