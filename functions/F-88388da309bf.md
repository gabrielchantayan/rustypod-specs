# F-88388da309bf

## Purpose

F-88388da309bf conditionally invokes a two-stage operation on a caller-supplied context and returns a packed 64-bit result.

The established behavior is:

- Invoke a gate dependency with the context.
- If the gate returns any nonzero 32-bit value, skip the remaining dependencies and return that value together with the second input.
- If the gate returns zero, read two 32-bit fields from the context at different stages, invoke two further dependencies, and return zero together with the context value.

The roles “gate,” “preparation,” and “dispatch” describe the visible call structure only. Validation, allocation, resource creation, and successful completion are not established semantic meanings.

## Interface

The function accepts four inputs, each occupying 32 bits:

| Input | Contract-level role | Established use |
|---|---|---|
| First input | Opaque payload | Passed unchanged to the final dependency on the zero-gate path. |
| Second input | Opaque alternate result or payload | Passed unchanged to the final dependency; also becomes the upper return word on the nonzero-gate path. |
| Third input | Context address/value | Passed to the gate and final dependency; used as the base for two field reads; becomes the upper return word on the zero-gate path. |
| Fourth input | Initial in/out word | Copied into a local 32-bit slot whose address is passed to the preparation dependency. |

The second and third inputs are represented as 32-bit integers in the supplied evidence. Their bit patterns matter to forwarding and result construction; there is no visible signed comparison or signed arithmetic involving the second input.

The context must be usable as an address if execution reaches the field reads. Its required visible layout is:

| Byte offset from context | Width | Use |
|---|---:|---|
| `0xF4` | 32 bits | Sixth argument to the final dependency |
| `0xFC` | 32 bits | Second argument to the preparation dependency |

These are separate four-byte reads. The function does not visibly interpret intervening bytes or establish a complete context structure.

The return value is a 64-bit concatenation:

- Bits 63–32 contain the selected upper word.
- Bits 31–0 contain the gate result, or zero on the zero-gate path.

This is a bit-pattern contract, not a sign-extension contract. For example, a nonzero gate result whose 32-bit pattern is `0xFFFFFFFF` occupies only the lower 32 bits; it does not force the upper 32 bits to all ones.

The physical register convention and byte representation of the returned value in memory are not established by the supplied evidence.

## Behavior

### Entry and local state

Before invoking the gate, the function establishes:

- An upper-result candidate containing the second input.
- A local 32-bit slot initialized from the fourth input.

The local slot is distinct from any caller storage from which the fourth input originated. Passing the fourth input by value does not itself expose that caller storage for mutation.

### Gate invocation

The function invokes F-46b69b47db18 with the third input as its sole visible argument.

The returned 32-bit value is compared with zero. Every nonzero bit pattern takes the same branch; there is no visible distinction between positive values, negative values, or particular error codes.

The dependency executes before either visible context-field read. Its effects on the context, globals, or other reachable state are not constrained by this wrapper.

### Nonzero-gate path

If F-46b69b47db18 returns a nonzero value:

- F-1da10e16bcee is not called.
- F-bdd5a1b1c4e8 is not called.
- Neither context field is read by this function.
- The upper return word is the second input.
- The lower return word is the exact 32-bit gate result.

The third input need not be dereferenceable merely for this wrapper’s skipped field reads. The gate may nevertheless require it to identify valid memory or state; that requirement is unknown.

### Zero-gate path

If F-46b69b47db18 returns zero, the function performs the following observable sequence:

1. Read the 32-bit word at context offset `0xFC`.
2. Invoke F-1da10e16bcee with:
   - The value one.
   - The word just read from offset `0xFC`.
   - The address of the initialized local 32-bit slot.
3. After that dependency returns, use its 32-bit return value as the first argument to F-bdd5a1b1c4e8.
4. Supply the current local-slot contents and the word at context offset `0xF4` as further arguments to F-bdd5a1b1c4e8, together with the first three original inputs.
5. After the final dependency returns normally, construct a result with the third input as the upper word and zero as the lower word.

The complete final-dependency argument order is:

| Position | Value |
|---|---|
| 1 | Return value from F-1da10e16bcee |
| 2 | Current 32-bit contents of the local slot |
| 3 | First input |
| 4 | Second input |
| 5 | Third input |
| 6 | Current 32-bit word at context offset `0xF4` |

The local slot initially contains the fourth input. If F-1da10e16bcee changes that slot through the provided address, the final dependency receives the changed contents rather than necessarily receiving the original fourth input.

The `0xFC` read precedes F-1da10e16bcee. The `0xF4` read occurs after that dependency returns. Consequently, changes to the latter field during either preceding dependency may affect the final call. There is no evidence of a snapshot taken at entry.

The exact relative evaluation order of the local-slot read and the `0xF4` read is not established. Both provide arguments to the final dependency after the preparation dependency returns.

No visible branch checks the preparation dependency’s result. Zero, nonzero, and other 32-bit patterns are forwarded identically as the first final-call argument.

The final dependency’s return value does not influence the wrapper’s returned bit pattern. A zero lower return word therefore establishes that the zero-gate path completed its visible calls normally; it does not establish that either later dependency achieved an application-level success condition.

### Arithmetic and layout boundaries

The context-field addresses are formed using byte offsets `0xF4` and `0xFC`; these are not element indexes. Each access has a width of four bytes.

The evidence uses a 32-bit address-like context value. Callers must supply a context for which the required effective addresses are valid under the execution environment. Safe arithmetic near the address-space boundary, overflow handling, and behavior for unmapped or misaligned addresses are not established.

## Side effects

It visibly reads context fields but contains no direct write to those fields. This does not imply that the context is unchanged: all dependencies must be treated as capable of side effects allowed by their unknown contracts.

No explicit allocation, release, reference-count operation, or ownership transfer is established. In particular:

- The preparation dependency’s returned word is forwarded without a visible release operation.
- Its type and ownership significance are unknown.
- The local-slot value may be an integer, identifier, address, or other opaque word.
- Passing the local-slot address does not establish that a dependency owns that storage or may retain it.

The slot is temporary storage associated with this invocation. Retention or asynchronous use of its address is not authorized by the visible wrapper contract and would require an independently established lifetime arrangement.

No wrapper-level rollback, cleanup handler, retry, or error translation is visible. If a dependency does not return normally, the evidence does not establish a completed wrapper result or compensating action.

## Acceptance examples

These are conditional acceptance criteria derived from the static evidence, not executed tests.

1. **Nonzero gate preserves both result words.**  
   Given a second input of `0x11223344` and a gate result of `0x00000007`, the returned value is `0x1122334400000007`. Neither later dependency is invoked, and neither context-field read is performed by the wrapper.

2. **A high-bit gate result is not sign-extended.**  
   Given a second input of `0x12345678` and a gate result of `0xFFFFFFFF`, the returned value is `0x12345678FFFFFFFF`. The gate result remains a lower-word bit pattern.

3. **The zero path selects the context for the upper word.**  
   Given a third input of `0x20001000`, a zero gate result, valid required field accesses, and normal returns from both later dependencies, the returned value is `0x2000100000000000`, regardless of the second input.

4. **The local in/out word reaches the final dependency.**  
   Given a fourth input of `0x01020304`, if the preparation dependency writes `0xAABBCCDD` into the provided slot, the final dependency receives `0xAABBCCDD` as its second argument.

5. **The later field is read after preparation.**  
   If the preparation dependency changes the field at offset `0xF4` from `0x11111111` to `0x22222222`, with no intervening change, the final dependency receives `0x22222222` as its sixth argument.

6. **Preparation results do not add a branch.**  
   If the preparation dependency returns zero normally, the final dependency is still invoked with zero as its first argument. If the final dependency also returns normally, the wrapper still returns the context in the upper word and zero in the lower word.
