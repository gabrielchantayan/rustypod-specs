# F-b775eff8d313

## Purpose

F-b775eff8d313 coordinates two input conversions, selects one of two operation modes, optionally retries an operation after a specific failure, and commits bookkeeping after success.

The established behavior includes:

- Clearing two caller-provided output slots before invoking any dependency.
- Performing both conversions before checking whether the context permits an operation.
- Selecting an effective operation argument from either the caller or a context field.
- Retrying only when the selected operation returns −34.
- Running an additional dependency after a successful operation in the nonzero mode.
- Updating a cached context value, a remaining-quantity field, and flag bits only after the selected path completes successfully.

The interpretation of these values as allocation, storage, range selection, or another domain-specific operation is not established. Such interpretations are not part of this contract.

## Behavior

### Output initialization and conversions

The function first writes zero to the primary output slot, then writes zero to the quantity output slot.

It next invokes F-3594f32e3fe8 twice, in this order:

1. With the first pair of conversion inputs and the current 32-bit value at context offset `0x160`.
2. With the second pair of conversion inputs and a fresh read of the value at context offset `0x160`.

The first conversion’s low 32 bits become the first converted value. The second conversion’s low 32 bits become the second converted value.

Both calls occur before the eligibility gate. Consequently, an invocation that ultimately returns −34 without attempting an operation has still initialized the outputs and performed both conversions.

The second conversion does not necessarily receive the same context value as the first. For example, the first dependency could affect storage underlying that field. This contract does not assume dependencies preserve context or other memory.

There is no explicit conversion-error branch. The conversion results are consumed as values rather than checked against an error sentinel.

### Eligibility gate

After both conversions, the function reads the 32-bit field at context offset `0x168`.

If that field is zero, it returns −34 without calling either operation dependency.

If the field is nonzero:

- In zero mode, the function proceeds without comparing either converted value against the field.
- In nonzero mode, the function compares the first converted value against a fresh read of the field, using an unsigned 32-bit comparison. It proceeds only if the converted value is less than or equal to that bound.

Failure of this comparison returns −34.

The second converted value and the upper portion of the second conversion result do not determine eligibility.

The initial output writes are not repeated on these rejection paths. Thus, although this function has initialized both outputs to zero, any intervening changes made indirectly by a dependency are not explicitly undone.

### Effective selector

Only after passing the gate does the function determine the effective selector.

- If the requested selector is nonzero, that value is used.
- If the requested selector is zero, the function reads the 32-bit field at context offset `0x16C` and uses that value.

The function separately retains whether substitution was requested. That condition controls a later cache update, even if the substituted value itself is zero.

### Zero-mode operation and retry

In zero mode, the function calls F-b3c0bd8ea84a with these logical arguments, in order:

1. Context.
2. Effective selector.
3. Current 32-bit value at context offset `0x164`.
4. Second converted value.
5. Primary output address.
6. Quantity output address.

If this call returns exactly −34, the function calls the same dependency once more with:

1. Context.
2. Zero.
3. Effective selector.
4. Second converted value.
5. Primary output address.
6. Quantity output address.

The retry therefore changes two argument positions: the second becomes zero, and the third becomes the effective selector. It does not simply repeat the initial call with a zero selector and an unchanged context-derived third argument.

The output slots are not cleared between attempts. The retry receives whatever contents remain after the first attempt.

No other status triggers a retry, and no third attempt is made. The final operation status is the first status unless a retry occurred, in which case it is the retry’s status.

If the final status is nonzero, the function returns it immediately. It does not explicitly clear the outputs on this path and does not call F-c7fef7dba7a3.

### Nonzero-mode operation, retry, and post-operation dependency

In nonzero mode, the function calls F-4b79b63abc57 with:

1. Context.
2. Effective selector.
3. Current 32-bit value at context offset `0x164`.
4. First converted value.
5. Second converted value.
6. Primary output address.
7. Quantity output address.

If the result is exactly −34, it retries once with the second argument replaced by zero. The value at context offset `0x164` is read again for the retry; it is not necessarily the value supplied on the first attempt.

The converted values remain the previously obtained values. The outputs are not reinitialized before retrying.

If the final operation status is nonzero:

- F-c7fef7dba7a3 is not called.
- The primary output is explicitly set to zero.
- The quantity output is explicitly set to zero, after the primary output write.
- The operation’s nonzero status is returned.

If the final operation status is zero, the function calls F-c7fef7dba7a3 with:

1. Context.
2. The primary output value read after the operation.
3. The quantity output value read after the operation.

The relative evaluation order of these argument reads is not established by the supplied representation.

If F-c7fef7dba7a3 returns nonzero, the function clears the primary output and then the quantity output and returns that status.

If it returns zero, the function proceeds to success bookkeeping. The output values are not snapshotted for that bookkeeping: later accesses read the output slots again. No preservation guarantee is assumed for the dependency.

### Success bookkeeping

Both modes converge on the following sequence after successful completion of their required dependencies:

1. If the original requested selector was zero, read the current primary output and write it to the 32-bit context field at offset `0x16C`.
2. Read the current remaining-quantity field at offset `0x168` and the current quantity output, subtract the latter from the former, and store the 32-bit result back at offset `0x168`.
3. Read the 16-bit flags at offset `0x000`, set every bit selected by `0xFF00`, and write the 16-bit result back.
4. Return zero.

The flag update sets bits 8 through 15 and preserves bits 0 through 7 of the value read at this step. It is a 16-bit write; this function does not explicitly replace the adjoining two bytes.

There is no check that the quantity output is positive, fits within the remaining quantity, or agrees with the first converted value. The eligibility comparison is not a post-operation quantity bound.

The subtraction uses 32-bit fields and a signed-integer presentation in the supplied evidence. There is no explicit underflow, overflow, saturation, or rejection handling. Mathematical results outside the signed 32-bit range require the target arithmetic interpretation discussed under Uncertainties; unbounded-integer behavior must not be assumed.

## Side effects

The function directly writes:

- Both output slots at entry.
- Both output slots again on nonzero-mode operation or post-operation failure.
- Context offset `0x16C` on successful calls that originally requested selector substitution.
- Context offset `0x168` on every successful call.
- Context offset `0x000` on every successful call.

It also exposes the context and, for operation calls, both output addresses to dependencies. Their additional effects are not specified here.

There is no explicit resource release, rollback, or restoration of dependency-modified context. Clearing an output does not establish that any resource represented by the previous value has been released.

On failure, success bookkeeping is skipped. This means only that this function does not perform those final writes; it does not guarantee that dependencies left the context unchanged.

Overlapping storage can make the sequence materially different from the independent-field model. For example, clearing an output that aliases a context field can affect later conversion or eligibility reads. The supplied evidence does not establish that such overlap is supported by callers.

## Acceptance examples

These are conditional static acceptance scenarios, not executed tests. Unless stated otherwise, they assume distinct output slots, no relevant indirect memory changes, and arithmetic within the signed 32-bit range.

1. **Zero remaining quantity:** If offset `0x168` is zero after the conversions, both conversions have occurred, neither operation is called, and the return value is −34. The entry-initialized outputs remain zero under the stated assumptions.

2. **Unsigned boundary accepted:** In nonzero mode, a first converted value of 9 and a bound of 9 pass the gate. A value of 10 against that bound returns −34 before an operation call.

3. **Unsigned interpretation matters:** In nonzero mode, a first converted bit pattern of `0xFFFFFFFF` exceeds a bound of `0x7FFFFFFF`; the gate rejects it. It is not treated as a negative quantity that passes the comparison.

4. **Zero mode bypasses the converted-value bound:** With nonzero remaining quantity, zero mode proceeds even if the first converted value is greater than that quantity.

5. **Zero-mode retry changes the third argument:** Suppose the effective selector is 12 and offset `0x164` contains 80. The initial zero-mode operation receives second and third arguments 12 and 80. If it returns −34, the retry receives 0 and 12.

6. **Nonzero-mode retry rereads context:** Suppose offset `0x164` is 80 for the first operation, which returns −34 and changes that field to 81. The retry receives zero as its second argument and 81 as its third.

7. **Zero-mode failure preserves operation-written outputs:** If the final zero-mode operation writes primary output 100 and quantity 3, then returns 7, this function returns 7 without clearing those outputs or performing success bookkeeping.

8. **Nonzero-mode operation failure clears outputs:** If the final operation returns 7, this function clears both outputs, skips F-c7fef7dba7a3, and returns 7.

9. **Post-operation failure clears outputs:** If the nonzero-mode operation succeeds but F-c7fef7dba7a3 returns 5, both outputs are cleared and the function returns 5 without success bookkeeping.

10. **Successful substitution updates the cache:** With requested selector zero, successful final outputs of 100 and 3, remaining quantity 20, and flags `0x1234`, success stores 100 at offset `0x16C`, stores 17 at offset `0x168`, changes flags to `0xFF34`, and returns zero.

11. **Successful explicit selection skips the cache write:** With a nonzero requested selector, success does not explicitly update offset `0x16C`, even if the primary output differs from that field.
