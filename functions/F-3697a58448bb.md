# F-3697a58448bb

## Purpose

F-3697a58448bb scans an indexed collection of fixed-stride records and returns the index of the first record accepted by its selection rules. It returns the 32-bit value `0xFFFFFFFF` when the current collection bound is reached without acceptance.

There are three acceptance paths:

- A record whose flag byte contains bit `0x08` is accepted immediately.
- With a non-null comparison context, a record is accepted when dependency F-4a6c0bf0740c returns zero.
- With a null comparison context and a nonzero requested-bit mask, a record is accepted when its flag byte contains every requested bit.

With a null context and a zero mask, records lacking `0x08` are skipped.

These are established selection rules. The application-level meaning of the records, flags, comparison context, and dependency result is unknown. In particular, the immediate-accept bit is not established to mean “unused,” “available,” or “end of list.”

## Interface

### Inputs

The function has three inputs:

1. **Collection descriptor address.** A pointer to storage containing at least the two 32-bit fields described below.
2. **Comparison context address.** A nullable address. When non-null, a 32-bit value is read at offset `+4` and passed to F-4a6c0bf0740c.
3. **Requested-bit mask.** An unsigned 32-bit value. This participates in selection only when the comparison context is null.

The supplied representation uses 32-bit integer values and address arithmetic. The descriptor’s first field is used as a record-storage address, even though the supplied declaration represents the descriptor as a pointer to integers. No portable host-language pointer representation is established beyond that supplied model.

### Collection descriptor layout

| Byte offset | Width | Established use |
|---|---:|---|
| `+0` | 32 bits | Base address used to locate records |
| `+4` | 32 bits | Record count, interpreted as unsigned |

No additional descriptor fields are read directly.

A count with its highest bit set is still treated as an unsigned count. It is not rejected as a negative signed value.

### Record layout

Records have a stride of 24 bytes. For a candidate index, the record address is the current base address plus 24 times that index.

| Byte offset within record | Width | Established use |
|---|---:|---|
| `+6` | 8 bits | Flag byte |
| `+7` | Address only | Passed as the second argument to F-4a6c0bf0740c |

The function itself does not read the bytes beginning at `+7`. Their representation, length, termination convention, and required accessibility depend on F-4a6c0bf0740c and are not established here.

### Output

The return value is an unsigned 32-bit integer:

- A zero-based index identifying an accepted record; or
- `0xFFFFFFFF` when the current bound excludes the next candidate.

There is no separate error channel and no established exception or diagnostic mechanism.

### Preconditions

For defined memory access under the supplied model:

- The descriptor must be readable at the fields actually accessed.
- Whenever an index passes the bound check, the computed record flag address must be readable.
- Whenever a record reaches the dependency path, context offset `+4` must be readable, and the dependency’s own argument requirements must hold.

A zero count avoids record and context reads, but it does not avoid the descriptor count read. Null or invalid descriptors are not explicitly handled.

## Behavior

### Scan initialization and bound checking

The candidate index begins at zero.

At the start of each iteration, the function reads the descriptor’s count field and compares it to the candidate index using an unsigned 32-bit comparison. If the count is less than or equal to that index, the function immediately returns `0xFFFFFFFF`.

This check occurs before reading the record base, the record flag, or the comparison-context payload for that iteration.

The count is not a captured initial scan limit. It is read again on every iteration that begins.

### Record selection and immediate acceptance

If the candidate is within the current bound, the function reads the descriptor’s base field and computes the candidate record address using the 24-byte stride. It then reads the single flag byte at record offset `+6`.

If bit `0x08` is set, the function returns the candidate index immediately.

This rule takes precedence over both other selection modes:

- A non-null comparison context does not cause a dependency call for such a record.
- A requested-bit mask does not need to be satisfied for such a record.
- Context offset `+4` is not read for such a record.

The flag byte is an unsigned 8-bit value. Its promotion for the mask calculation does not sign-extend bit `0x80`.

### Null-context mode

When the comparison context is null and the immediate-accept bit is absent, the requested-bit mask controls further selection.

If the mask is zero, the record is skipped. Zero is therefore not treated as an automatically satisfied request in this mode.

If the mask is nonzero, the record is accepted exactly when no requested bit is missing from the flag byte. The flag byte is zero-extended to 32 bits before this calculation. Thus:

- All requested bits in positions zero through seven must be set in the flag byte.
- Any requested bit in positions eight through thirty-one prevents acceptance through this mask rule.
- Additional bits in the flag byte do not prevent acceptance.

A high requested bit does not prevent acceptance through the earlier `0x08` rule.

If the mask rule fails, scanning continues with the next index. F-4a6c0bf0740c is never called in null-context mode.

### Non-null-context mode

When the comparison context is non-null and the immediate-accept bit is absent, the function:

- Reads the 32-bit value at context offset `+4`.
- Calls F-4a6c0bf0740c with that value as its first argument and the current record address plus seven as its second argument.
- Accepts the current index if the dependency returns zero.
- Continues scanning if the dependency returns any nonzero value.

The requested-bit mask is irrelevant in this mode, including when it is zero or contains bits above the low byte.

Only zero versus nonzero is significant in the dependency result. No ordering, magnitude, or signed interpretation is used.

### Iteration and mutable state

After a rejected record, the candidate index increases by one and the next iteration begins with another count read.

The base field is also read anew for each candidate that passes its bound check. Consequently, if an external effect changes the descriptor between iterations, a later index can be evaluated against a different count or record-storage base.

Within one iteration:

- The current record address is determined before the dependency call.
- The flag byte is read before the dependency call.
- Neither the flag nor the current bound is reread after that call.
- A zero dependency result returns the current index even if the dependency has changed the descriptor so that this index is no longer within its new count.

The function does not establish a stable snapshot of the collection.

### Integer and address boundaries

The candidate index, unsigned count comparison, mask operation, and return value use 32-bit quantities.

The index cannot increment from `0xFFFFFFFF` back to zero: at that index, every possible unsigned 32-bit count is less than or equal to it, so the bound check returns first. The largest potentially accepted index is therefore `0xFFFFFFFE`. The failure sentinel cannot also be a successfully returned index under the established control flow.

Record-offset multiplication and address addition have no explicit overflow checks. Large counts or unsuitable bases can produce wrapped or otherwise invalid computed addresses in the supplied 32-bit representation. The function does not validate that the record storage covers the declared count.

## Side effects

The visible body performs no direct memory writes, allocations, deallocations, or ownership transfers.

Its direct observable accesses are:

1. A count read at each iteration.
2. A base read after a successful bound check.
3. A flag-byte read for the selected record.
4. A context payload read only on the non-null-context path without immediate acceptance.
5. A dependency call on that same path.

The function returns immediately after an acceptance decision. It does not read later records as part of the visible logic.

F-4a6c0bf0740c may have effects not shown here. It must not be assumed to preserve global state, preserve descriptor contents, leave record storage untouched, or retain or release no memory. Passing an address is not evidence of an ownership transfer, but the absence of the dependency’s contract also prevents asserting borrowed-only lifetime behavior.

Invalid accesses and dependency failures are not converted into the failure sentinel by any visible handling. `0xFFFFFFFF` specifically represents reaching the collection bound, not a general catch-all error result.

Concurrent modification has no established synchronization contract. Per-iteration rereads do not themselves make concurrent access safe.

## Dependencies

**Arguments, in argument order:**

1. The 32-bit value read from context offset `+4`.
2. The address seven bytes into the current record.

**Result interpretation:** Zero accepts the current record; every nonzero result rejects it.

**Unknown contract:** The first argument’s semantic type, the second argument’s data layout and accessible extent, side effects, ownership rules, error behavior, and termination behavior are not provided.

## Acceptance examples

These examples are conditional static expectations, not runtime test results. Unless specified otherwise, assume readable storage, stable descriptor contents, valid address arithmetic, and dependency calls that return normally.

| Conditions | Required result and observable behavior |
|---|---|
| Count is zero | Return `0xFFFFFFFF`; do not read a record base, flag, or context payload, and do not call the dependency. |
| Count is one; record zero has flag `0x08` | Return zero, regardless of mask or whether the context is null; do not read context offset `+4` or call the dependency. |
| Count is one; flag is `0x00`; context is null; mask is zero | Skip the record, then return `0xFFFFFFFF` at the next bound check. |
| Count is one; flag is `0x03`; context is null; mask is `0x01` | Return zero because the requested bit is present. |
| Count is one; flag is `0x01`; context is null; mask is `0x03` | Return `0xFFFFFFFF` because one requested bit is absent. |
| Count is one; flag is `0xF7`; context is null; mask is `0x100` | Return `0xFFFFFFFF`; an 8-bit flag cannot satisfy bit eight, and the immediate-accept bit is absent. |
| Count is one; flag is `0x08`; context is null; mask is `0x100` | Return zero because immediate acceptance precedes mask evaluation. |
| Count is one; flag is `0x00`; context is non-null; dependency returns zero | Return zero even if the requested mask is unsatisfied. |
| Count is one; flag is `0x01`; context is non-null; mask is `0x01`; dependency returns nonzero | Return `0xFFFFFFFF`; a satisfied mask does not override the dependency in this mode. |

Additional ordering and mutation cases:

- **First accepted record wins.** With count three, null context, zero mask, and flags `0x00`, `0x08`, `0x08`, return one. The third record’s flag is not read.
- **Count shrink after rejection.** If a dependency rejects index zero while changing the count to zero, the next iteration returns `0xFFFFFFFF` without accessing index one.
- **Descriptor change after acceptance.** If a dependency returns zero while changing the count to zero, return the current index without a further bound check.
- **Base replacement after rejection.** If a dependency rejects index zero and changes the base, the next in-bound candidate uses the replacement base with index one and the same 24-byte stride.
- **Unsigned count interpretation.** A count field containing `0x80000000` does not reject index zero merely because the same bit pattern could represent a negative signed integer. Safe record access remains a separate precondition.
