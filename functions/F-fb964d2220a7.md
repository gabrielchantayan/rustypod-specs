# F-fb964d2220a7

## Purpose

F-fb964d2220a7 conditionally sets a byte within a caller-supplied object and invokes a dependency with that object and an interior address. It then invokes a second dependency using a value read from the object.

The conditional action requires two strict, signed 32-bit comparisons to succeed:

- The value at offset `0x158` is less than the value at offset `0x160`.
- The value at offset `0x154` is less than the value at offset `0x15C`.

The second comparison’s operands are read only when the first comparison succeeds. The final dependency invocation is not conditional on either comparison.

**Established static behavior:** the function returns the 32-bit value `1` whenever execution reaches its normal return. The comparisons control a side effect, not the returned value.

**Inferred intent:** the paired values may describe bounds, and the byte may mark an active or pending condition. No semantic meaning for those fields is established; this contract does not require a bounds interpretation.

## Behavior

### Comparison and access order

The function first reads a signed 32-bit value at offset `0x158`, then a signed 32-bit value at offset `0x160`.

If the value read at `0x158` is greater than or equal to the value read at `0x160`, the conditional action is skipped. The function does not directly read the second pair of comparison fields on this path.

If the value read at `0x158` is strictly less than the value read at `0x160`, the function reads the signed 32-bit value at `0x15C`, followed by the signed 32-bit value at `0x154`. The conditional action occurs only if the value read at `0x154` is strictly less than the value read at `0x15C`.

Thus, both comparisons must be true. Equality in either pair prevents the conditional action.

The comparison decisions use the values obtained by these reads. There is no visible retry or reread of a comparison field.

### Signed arithmetic

Each comparison uses signed 32-bit ordering, with representable values from −2,147,483,648 through 2,147,483,647.

The supplied representation includes subtraction-result and signed-overflow information in the final branch decision. Together, these establish a strict signed greater-than comparison of the corresponding operands, equivalent to the strict inequalities described above. The condition must not be reduced to checking the sign of a wrapped subtraction alone.

This distinction matters at the signed extremes. For example, a value of −2,147,483,648 is less than 2,147,483,647 even though a 32-bit subtraction between those values can overflow. Unsigned ordering would also give a different result for some negative operands and is not the established behavior.

No arithmetic result is stored back into the comparison fields.

### Conditional action

When both comparisons succeed, the function performs these actions in order:

1. It writes the one-byte value `1` at offset `0x150`.
2. It invokes F-6d16652f2d03 with the object address as its first argument and the object address plus `0x154` as its second argument.

The second argument is an address, not a copy of the four-byte value stored at `0x154`. It aliases the same object passed as the first argument.

The write occurs before the dependency invocation. The function does not inspect the previous byte value, so an existing value of `1` does not suppress the write or the invocation.

When either comparison fails, this function neither writes nor clears the byte at `0x150`, and it does not invoke F-6d16652f2d03. This says nothing about changes made by the later dependency.

### Final dependency and return

After the conditional action has completed—or immediately after that action has been skipped—the function reads the four-byte value at offset `0x1AC`. It passes that value as the sole visible argument to F-ec4cfa552cce.

The timing of this read is significant. On the path that invokes F-6d16652f2d03, the read occurs after that dependency returns. If that dependency changes the field at `0x1AC`, the subsequent invocation uses the value present at the later read, not a value captured before the conditional call.

After F-ec4cfa552cce returns, this function returns `1`.

“Final dependency is unconditional” applies to ordinary forward execution. If an earlier access faults or F-6d16652f2d03 does not return normally, the final read, invocation, and return are not established to occur.
