# F-7560febb34c7

## Purpose

F-7560febb34c7 performs a mode-selected configuration sequence followed by a common configuration sequence. Each sequence obtains a 32-bit value from F-8157a180d901 and forwards that value, two caller-supplied values, and a temporary configuration pointer to another dependency.

Mode zero selects F-7f6becd152e6. Every nonzero mode selects F-4a73b9be0f3a. After the selected dependency returns normally, the common sequence invokes F-60fe53f7ab39.

A byte in the caller-referenced object and the exact mode value determine whether the first or second 32-bit entry of a globally addressed table contributes to the initial configuration. The supplied representation establishes these two possible access locations, not the table’s total extent.

**Established static evidence:** branch conditions, explicit reads and writes, relative temporary-storage offsets, dependency arguments, call order, and absence of local result checking.

**Inferred intent:** the external three-argument operation appears intended to transfer configuration data; F-8157a180d901 appears allocation-like; the three dependencies receiving configuration pointers appear initializer-like. These interpretations do not establish their actual contracts.

## Behavior

The first dependency call is to an external operation for which no opaque function ID was supplied. Its three arguments are:

1. A pointer to the initial temporary configuration region.
2. A reference obtained from the first global template location.
3. The integer count 104.

The count is established. Its interpretation as a byte count, and the operation’s interpretation as a copy, remain conditional on the unavailable dependency contract.

This call occurs before the object-byte read and table access. Consequently, changes made by this operation to the object or relevant globals can affect subsequent reads. The function does not take a prior snapshot of those values.

### Object flag and table adjustment

After the initial external operation returns, the function reads one byte at offset 4 from the object reference and examines bit 0. Other bits do not affect the visible selection logic.

| Object byte, bit 0 | Mode | Selected 32-bit entry |
|---|---|---|
| Clear | Any value | First entry, at table-base offset 0 |
| Set | Exactly 1 | Second entry, at table-base offset 4 |
| Set | Any value other than 1 | First entry, at table-base offset 0 |

The object-byte read occurs even for mode zero and for modes other than 1.

The function accesses a table whose first or second 32-bit entry is selected. Entry spacing is four bytes. The table’s total extent is unknown; nothing establishes that it contains exactly two entries.

The selected 32-bit entry is interpreted as an integer for subtraction of 20. The result is written as a 32-bit word at byte offset 72 from the initial temporary region’s base.

This is an adjustment, not a clamp or validation. For example, a selected value of 100 produces 80, and a selected value of 10 produces −10; both subtractions are representable in a signed 32-bit integer. At the lower signed boundary, the supplied representation does not establish the overflow contract. No saturation, rejection, or diagnostic is visible.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, accessed memory is valid and every dependency returns normally.

### Zero mode does not skip the object read

Given mode zero and either state of object flag bit 0:

- The initial external operation precedes the object-byte read.
- The first table entry is selected.
- The adjusted word is written at initial-region offset 72.
- F-8157a180d901 receives 544, and its result is forwarded to F-7f6becd152e6.
- The common sequence subsequently uses 560 and F-60fe53f7ab39.

Skipping the object read merely because the mode is zero would not match the established behavior.

### Exact mode 1 selects the second entry only when flagged

Given mode 1, flag bit 0 set, and a selected table value of 100:

- The entry at table-base offset 4 is read.
- The adjusted word is 80.
- The nonzero-mode sequence runs.
- Under exact 104-byte copying semantics without other relevant effects, the adjusted word reaches second-region offset 72.
- The explicit offset-48 zero write follows that transfer.
- F-4a73b9be0f3a precedes the common sequence.

With flag bit 0 clear, the same mode instead selects the first entry.

### Other nonzero modes select the first entry

Given mode 2 or a negative nonzero mode, with flag bit 0 set, the nonzero sequence runs but reads the first table entry. Nonzero mode alone is insufficient to select the second entry.

A table containing additional entries does not change this selection: no index beyond the first two is established. The example does not assert that such additional entries exist.

### Reads observe dependency ordering

If the initial external operation changes the object’s flag byte, selection uses the byte read afterward.

If the second external operation changes the global argument subsequently passed to F-8157a180d901, the later read can observe that change. The extension value at offset 108 was already sampled before this operation.

If the branch-specific dependency changes the global reference for the common template operation, no established preservation rule requires use of an earlier value.

### Results are forwarded without validation

If F-8157a180d901 returns zero normally, the next configuration-consuming dependency receives zero as its first argument. F-7560febb34c7 does not substitute a value, skip that call, or emit its own failure status.
