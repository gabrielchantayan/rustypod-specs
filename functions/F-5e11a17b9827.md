### Shared successor weighting

Actions 5, 6, and 7 use the same arithmetic transition.

Let \(S\) denote the unsigned 32-bit selector, \(R\) the reduced alternative, and \(N\) the other alternative. The unsigned 32-bit transition value is:

\[
T = R \times (S \mathbin{\mathrm{XOR}} 1) + S \times N
\pmod{2^{32}}.
\]

The signed alternatives are converted as required by the unsigned arithmetic. The resulting unsigned value is then converted on assignment to the signed 32-bit dispatch state. Conversion of values outside the signed range remains target-dependent.

The first weight is **the selector bitwise-XORed with one**, not one minus the selector.

- For \(S=0\), the weights are one and zero.
- For \(S=1\), the weights are zero and one.
- For \(S=\text{0xffffffff}\), the weights are **0xfffffffe** and **0xffffffff**.

Consequently, the Boolean cases select an alternative’s 32-bit residue. The all-one-bits case instead produces the unsigned modular value corresponding to negative twice the reduced alternative minus the other alternative. It is not a two-way selection.

After computing the next state, the shared transition copies the fallback candidate into the retained candidate. That clears the candidate for action 5 and preserves it for actions 6 and 7.
