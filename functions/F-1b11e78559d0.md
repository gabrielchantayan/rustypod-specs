# F-1b11e78559d0

## Purpose

F-1b11e78559d0 conditionally forwards a value stored in a caller-supplied object to F-61361e57c83d. A first indirect callback determines whether the object’s stored value is considered at all. If that callback returns a nonzero value, an initially zero stored value causes a second indirect callback to run before the value is reconsidered.

The function returns the 32-bit value 1 on every normal completion, including paths that do not call F-61361e57c83d. That return value does not distinguish whether either optional call occurred.

**Established static behavior:** conditional callback invocation, conditional forwarding of an object field, and an unconditional normal return value.

**Inferred intent:** the first callback may act as an eligibility check, and the second may make a value available on demand. These interpretations are not required behavior of the callbacks. The available evidence establishes neither what the stored value represents nor whether the second callback actually initializes it.

## Behavior

### Initial gate

The function first reads the object’s table reference and resolves the indirect callable entry at table offset 0x13C. It invokes that entry with the object reference.

This call precedes every explicit access to the stored-value field shown for F-1b11e78559d0. The callback itself may access that field or other state; its internal behavior is unknown.

If the callback returns zero:

- The stored-value field is not explicitly read by this function.
- The callback at table offset 0x128 is not invoked.
- F-61361e57c83d is not invoked.
- The function returns 1.

Thus, a nonzero stored value does not by itself cause forwarding. The first callback’s nonzero result is required.

### Stored-value check

If the first callback returns nonzero, the function reads the 32-bit field at object offset 0xC8 and compares it with zero.

If the field is nonzero, the second callback is skipped. The function proceeds to the forwarding call.

If the field is zero, the function resolves and invokes the indirect callable entry at table offset 0x128, passing the original object reference.

The second callback is resolved through the object’s table reference at this later point. The evidence does not establish that the table reference remains unchanged after the first callback. A behavioral description must therefore not require both calls to use the same table instance.

### Reconsideration after the second callback

After the second callback returns normally, the function reads the stored-value field again.

- If the new field value is zero, forwarding is skipped.
- If the new field value is nonzero, forwarding occurs.

The callback’s own return value does not decide this branch. Only the subsequent field read does.

There is no retry loop. If the field remains zero, the second callback is not invoked again during this invocation of F-1b11e78559d0.

### Forwarding

When the field check permits forwarding, the function supplies the stored 32-bit field value to F-61361e57c83d.

The supplied representation contains a field access for the nonzero condition and another field access for the forwarding argument. It does not explicitly capture the tested value in a local snapshot.

Consequently, two levels of claim must remain separate:

- **Established source-facing evaluation:** the condition uses the stored field, and the call argument is also obtained from that field.
- **Not established:** the exact number of physical memory reads, atomicity, synchronization, or guaranteed equality of the tested and forwarded values under concurrent mutation.

For an ordinary stable object with no intervening mutation, the forwarded value is the nonzero value that satisfied the relevant field check. No concurrent-access contract is supplied.

F-61361e57c83d is invoked at most once per invocation of this function. After it returns normally, the function returns 1 without inspecting its result.

### Width and arithmetic constraints

All field decisions are zero/nonzero tests on 32-bit values. There is no range restriction, sign-based branch, masking, increment, or numerical transformation of the stored value.

The visible calculations are fixed layout displacements: table offsets 0x13C and 0x128, and object offset 0xC8. No input-dependent arithmetic or overflow-handling path is shown.

The evidence does not justify widening the stored value to a native pointer-sized quantity in a different environment. Whether the 32-bit value denotes a pointer, handle, identifier, or another representation is unknown.
