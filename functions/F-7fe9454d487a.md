# F-7fe9454d487a

## Purpose

F-7fe9454d487a performs an ordered sequence of unresolved indirect invocations and direct memory transactions. Its observable work includes publishing 32-bit values, refreshing byte fields from word reads, accessing low absolute addresses, replacing a global word twice, and finally invoking address zero.

No application-level purpose is established. Descriptions such as initialization, allocation, serialization, or hardware control would require evidence not present here.

This contract describes the visible path conditionally: each later event requires all earlier calls to return and all earlier accesses to complete. It does not establish that any particular environment can execute the entire path.

## Interface

### Explicit and implicit inputs

The explicit interface accepts one uninterpreted 32-bit value and declares no return value. That value is supplied to the first indirect invocation.

Execution also depends on incoming state outside the explicit parameter:

- A control-address value from which the first invocation target is derived.
- An address-like 32-bit value used both numerically and as a memory address.
- A 32-bit payload used in two early word stores.
- Secondary-result state exposed after selected invocations.
- Several results represented as 64 bits and consumed as separate low and high 32-bit portions.

These additional inputs are not established as public parameters. Their availability, validity, and calling-convention interpretation remain unresolved.

### Access widths and address conventions

A **byte**, **halfword**, and **word** mean 8, 16, and 32 bits respectively. A **word slot selected by an index** means the address obtained by multiplying that index by four and adding `0x14`. This terminology does not imply an allocated array or an independently known object base.

A **scaled base** is a particular captured result multiplied by four or shifted left by two, according to the operation described. Equal numerical values do not establish equal ownership or object identity.

Byte stores retain the low eight bits of their source. Byte reads used for address selection are zero-extended before adding `0x11`; that addition is not an eight-bit addition.

Unsigned shifts are logical. Some address calculations and left shifts use signed 32-bit operands in the supplied representation. Overflow behavior for those operations is not established. A wrapping machine interpretation must not be silently substituted for that uncertainty.

### Completion conditions

Successful completion requires valid executable targets, valid direct-memory addresses, and an environment supplying the implicit state. Normal return additionally requires the final invocation of address zero to return.

There is no visible argument validation, address validation, error result, or recovery protocol. No ownership rights are granted merely because a value is used as a pointer.

## Behavior

### Ordering model

The following regions describe memory behavior and the dependency boundaries separating it. They are not independent operations: values captured in an earlier region remain inputs to later regions.

For compactness, a **four-call interval** means four consecutive indirect invocations with no explicit arguments; where a result is mentioned, it belongs to the fourth invocation. A **forwarding pair** means an argument-free invocation whose 32-bit result is passed as the explicit argument to the next invocation. These descriptions specify only visible arguments and result use, not dependency semantics.

All nonterminal indirect invocations are covered by opaque dependency reference **F-000000000001**, with occurrences distinguished by their position in this contract. This reference does not assert a shared target or implementation.

### Entry and initial descriptor capture

The explicit input goes to the first invocation. Four argument-free invocations follow, with an apparent 64-bit result obtained from the last.

The first direct memory transaction writes the low byte of the incoming address-like value nine bytes beyond that same address. A word is subsequently read at offset `0x34` from it. The next invocation receives the apparent result’s low 32 bits shifted left by two, its high 32 bits, and the word just read.

After a four-call interval, secondary-result state supplies an index. The incoming payload is written to the word slot selected by that index. The **initial descriptor** is then read from the index itself plus `0x14`, without the multiplication by four. The write therefore precedes the read, and the two addresses need not coincide.

That index is then passed to an invocation.

### Linked descriptor publication

A forwarding pair followed by a four-call interval supplies a new index. The incoming payload is published to its word slot. Only afterward is the **second descriptor** read at the initial descriptor logically shifted right by 22, plus `0x14`.

The new index multiplied by four is passed onward. Another four-call interval supplies a value whose left-shift-by-two form becomes a retained **shifted publication value**.

That value is written to the word slot selected by the second descriptor logically shifted right by one. The **third descriptor** is then read at the unshifted second descriptor plus `0x14`. Thus the publication uses a reduced, scaled index, whereas the read uses the unreduced descriptor directly.

The half-shifted second descriptor is passed onward. A forwarding pair and a four-call interval provide another index, whose word slot receives the retained shifted publication value.

The first read of **global region A**, a 32-bit global storage region, occurs after this store. Its captured value is not interchangeable with a later read of that region.

### Reduced descriptors and zero publication

The latest index multiplied by four is passed onward, followed by a four-call interval.

The third descriptor is reduced by a logical right shift of 22. The captured global-region-A value is reduced by a logical right shift of 23. A secondary-result index selects a word slot receiving the reduced third descriptor. The next invocation receives that index twice, then the reduced global value and reduced third descriptor.

A forwarding pair follows. The reduced global value is also subjected to another logical right shift of 23. Because its original width is 32 bits, this twice-reduced value is necessarily zero.

After a four-call interval, the reduced third descriptor is published again, this time to the returned index’s word slot. That index multiplied by four is passed onward.

A further four-call interval exposes another secondary-result index. Its word slot is cleared, and the index is passed onward. A forwarding pair and another four-call interval then supply an index whose word slot receives the twice-reduced global value: zero.

The **fourth descriptor** is read only after this last publication. Its address is obtained by masking the earlier clearing index with `0x1fffffff`, logically shifting right by 19, and adding `0x14`. There is no further multiplication by four.

### Low-address byte selection

The latest publication index multiplied by four is passed onward, followed by a four-call interval. The fourth descriptor is reduced by a logical right shift of 22.

The first byte-selected write reads the byte at absolute address 1 and uses its zero-extended value plus `0x11` as the destination. The stored byte is the low byte of the reduced fourth descriptor.

An invocation then receives one secondary-result value three times and zero as its fourth argument. An argument-free invocation follows, then an invocation explicitly receiving zero. After a four-call interval, another byte-selected write occurs: its selector byte is read at four times the reduced fourth descriptor plus one, and its selected destination receives zero.

The last returned value shifted left by two is passed onward. Another four-call interval produces a value whose shifted form is passed twice to an invocation. A fresh 32-bit result is then obtained, forwarded, and followed by one argument-free invocation.

Only then is address 1 read again for another byte-selected zero write. This is a fresh memory read, not reuse of the first selector byte.

### First global replacement and retained-base refresh

A secondary-result value is captured for later shifted arguments and supplied three times to an invocation. The next argument-free result is forwarded together with the recently obtained 32-bit result logically shifted right by 23.

After a four-call interval, the byte at address 1 is read again. Its zero-extended value becomes the **retained low-address base**. Zero is written at that base plus `0x11`.

The latest returned value shifted left by two is passed onward. A four-call interval supplies another value, whose shifted form is supplied twice to an invocation. The next argument-free invocation supplies a fresh 32-bit result.

That complete result replaces **global region B** before being forwarded to another invocation. One further argument-free invocation intervenes before the next direct memory transaction.

The retained low-address base is then used to read a word at offset `0x74` and write that word’s low byte at offset one. This operation does not reread address 1. The earlier captured secondary-result value shifted left by 11 is subsequently passed onward.

### Repeated refreshes and full-word retention

An apparent 64-bit result is obtained. Its low and high halves are supplied to the next invocation together with the most recent 32-bit result logically shifted right by 23.

A four-call interval supplies an index. At its scaled base, a word is read at offset `0x74`, and the low byte of that word is written at offset one. The scaled base is passed onward.

After another four-call interval, the same refresh is repeated at the previous scaled base. The word is read again; the first word value is not cached for this refresh.

The newly returned value establishes a separate retained shifted value. An invocation receives:

- The retained secondary-result value shifted left by 12.
- The new shifted value twice.
- The unshifted new value shifted left by 18.

Two forwarding pairs and a four-call interval follow. At the resulting index’s scaled base, another word is read at offset `0x74`. This time the **entire word is retained**, in addition to its low byte being written at offset one. The scaled base is passed onward.

After a four-call interval, the retained full word is published at sixteen times the returned index plus `0x14`. This publication has a stride of sixteen, unlike the conventional word-slot stride of four.

### Further publications and second global read

The earlier retained shifted value, logically shifted right by two and then shifted left by 16, is supplied to an invocation.

Under an explicitly assumed 32-bit wrapping interpretation, this argument equals the original pre-scaled value shifted left by 16 modulo \(2^{32}\): the discarded top two bits would not survive the final shift either. That arithmetic observation does not establish that the preceding signed left shift is defined.

Two forwarding pairs and a four-call interval lead to another publication of the retained full word, now to an ordinary word slot. The selected index multiplied by four is passed onward.

A four-call interval supplies another value. Its left-shift-by-two form is stored at the earlier retained shifted value masked with `0xfffffffc`, plus `0x14`. The newly shifted value is then passed twice to an invocation.

Two forwarding pairs and a four-call interval lead to a word-slot clear. The clearing index multiplied by four is passed onward.

A four-call interval then yields an apparent 64-bit result. Its low half shifted left by two is published to the word slot selected by its high half. Only after that store does the function read global region A for the second time.

The next invocation receives the shifted low half, the high half, and the shifted low half twice more. A four-call interval supplies another index, whose word slot receives the same shifted low half.

The **final descriptor** is then read at the freshly captured global-region-A value plus `0x14`. No index scaling is applied to that address. The latest publication index multiplied by four is passed onward.

### Final selected writes and terminal invocation

A four-call interval supplies the final apparent 64-bit result.

The retained full word from the refresh region is logically shifted right by 23. A byte is read at that result plus one; its zero-extended value plus `0x11` selects a destination receiving the final descriptor’s low byte.

An invocation receives the final apparent result’s high half three times and its low half shifted left by two. A forwarding pair and a four-call interval follow.

The next selector address is formed from the final apparent result’s low half masked with `0x3fffffff`, logically shifted right by 21, plus one. The byte read there selects a destination, again by adding `0x11`. That destination receives the low byte of the final descriptor logically shifted right by 22.

The latest returned value shifted left by two is passed onward. A four-call interval supplies another value, whose shifted form is passed twice to an invocation. An argument-free invocation follows. Another argument-free invocation uses a distinct target-offset form, and its result is forwarded.

The following invocation supplies an eight-bit result and exposes a writable pointer through secondary-result state. The final direct-memory ordering is significant:

- A zero byte is written through that pointer.
- A separate 24-bit value associated with absolute address 9 is read.
- Global region B is replaced with a 32-bit value consisting of that 24-bit value as the upper bits and the returned byte as the low eight bits.
- A zero halfword is written at the final apparent result’s low half masked with `0x3fffffff` and logically shifted right by seven.

Finally, **F-000000000002**, the target at absolute address zero, is invoked with three explicit zero arguments. The enclosing function returns only if that invocation returns.

## Side effects

All direct writes are immediately observable subject to the actual memory model. No rollback or transactional boundary is visible.

Potential aliasing is unrestricted. Selected destinations, descriptor addresses, globals, refresh sources, and secondary-result pointers may overlap. In particular:

- A preceding store may change a following read.
- Intervening dependencies may change memory before it is read again.
- The final pointer store may affect the subsequent 24-bit read if their storage overlaps.
- The two writes to global region B are separate full-word replacements, not a guaranteed preservation of its previous upper bits.

The supplied representation warns of overlapping global symbols. It does not establish disjoint storage for named regions or smaller portions.

There is no directly visible allocation, release, ownership transfer, synchronization, cleanup, or error-status publication. Dependencies may perform such actions; neither their occurrence nor their absence is guaranteed.

A failed access or nonreturning dependency may leave any preceding writes in place.

## Acceptance examples

These are conditional static criteria, not executed tests.

- **Unscaled versus scaled addressing:** With an early secondary-result index of three, the payload store targets `0x20`, while the following descriptor read targets `0x17`. Treating both as word-slot accesses is incorrect.

- **Required zero result:** For every possible 32-bit global-region-A value, two successive logical right shifts of 23 produce zero. Publications and arguments derived from that twice-reduced value must reflect zero.

- **Selector addition width:** A selector byte of `0xff` chooses address `0x110`, not `0x10`. Byte-selected destinations range from `0x11` through `0x110`.

- **Refresh versus retention:** If a retained refresh word is `0x123456ab`, its byte update writes `0xab`; later full-word publications write `0x123456ab`. A repeated refresh instead observes whatever word is present when its new read occurs.

- **Retained base:** If address 1 contains `0x20` when the retained low-address base is captured, its later refresh uses addresses `0x94` and `0x21`, even if a dependency subsequently changes address 1.

- **Distinct publication stride:** With a stride-sixteen publication index of three, the destination is `0x44`, not the conventional word-slot address `0x20`.

- **Final replacement:** If the final 24-bit read yields `0x123456` and the byte result is `0xab`, global region B receives `0x123456ab`. A prior value of global region B does not determine those upper bits.

- **Terminal failure:** If address zero cannot be executed, normal return is not established. Earlier stores are not required to be undone.
