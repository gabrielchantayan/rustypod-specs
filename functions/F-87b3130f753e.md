# F-87b3130f753e

## Purpose

F-87b3130f753e performs a sequence of memory reads and mutations, then invokes an unresolved indirect target with four arguments. No application-level purpose is established. The evidence does not justify interpreting the operation as text processing, object construction, serialization, list manipulation, or device control.

This contract describes the supplied static representation, conditional on that representation accurately reflecting executable behavior. It distinguishes:

- **Established static evidence:** represented access widths, address relationships, constants, captured values, and access ordering.
- **Inferred intent:** no higher-level intent is adopted as required behavior.
- **documented_only:** unresolved machine, calling-context, memory-map, ownership, and dependency behavior.

The contract is not a claim that the operation can complete on an ordinary process memory map.

## Interface

### Explicit inputs and result

Four positional inputs are visible:

| Input | Represented width | Visible use |
|---|---:|---|
| First input | 32 bits | Address base for writes at offsets 1, 0x15, and 0x54 |
| Second input | 32 bits | Address base for the nested lookup at offset 0x74 and writes at offset 0x14; its low byte is written to first input plus 1 |
| Third input | 32 bits | Stored at second input plus 0x14 before replacement |
| Fourth input | 32 bits | Stored at two address-derived destinations before subsequent writes may replace it |

There is no visible write to second input plus 1.

The first two inputs have signed integer presentation but serve as addresses. This establishes neither a validated numeric range nor a conventional pointer interface.

No explicit return value is established. The operation reaches a visible return only if the final indirect invocation returns. That invocation’s result, if any, is not visibly used.

### Additional entry state

Three further 32-bit values are consumed without visible initialization:

- **Ambient base:** used directly as an address.
- **Ambient scale:** used as an address, a scaling source, and a source of truncated bytes.
- **Ambient double-source:** doubled to form an address base.

Their calling-convention locations and initialization are **documented_only**. They must not be assumed to be ordinary explicit parameters.

A separate global word is read partway through execution. Its captured value becomes the **global-derived base**. Earlier writes could affect that read if their destinations overlap its storage.

### Widths, layouts, and preconditions

Byte, halfword, and word accesses are respectively 8, 16, and 32 bits. Address-bearing values are represented as 32-bit quantities. Byte reads used in selection are unsigned and widen to values from 0 through 255. Byte stores retain the low eight bits; halfword stores retain the low sixteen bits.

Offsets describe accessed locations, not established object fields or allocation boundaries. Successful completion requires every reached access to be supported with its represented width, address, alignment, and permissions. No such validity is checked visibly.

Arithmetic includes doubling, multiplication by four and eight, left shifts, subtraction of 0x96, and a signed right shift. There are no visible overflow checks. Mathematical address relationships below apply where these operations are defined and representable. Overflow, negative signed left shifts, address wrapping, and exceptional shift counts are **documented_only**; unconditional modulo-32-bit behavior is not established.

Endianness is unknown. Consequently, this contract identifies affected byte ranges but does not assign an endian-specific byte layout to word values.

## Behavior

### Ordering and aliasing model

The representation contains a linear sequence of accesses before the indirect invocation, with no visible validation, recovery, or rollback branch.

Ordering below is the represented access order. Its correspondence to hardware transactions, compiler ordering guarantees, or memory-mapped I/O behavior remains **documented_only**.

No disjointness is assumed among inputs, derived addresses, global storage, or absolute low addresses. Earlier writes can change later reads. A captured value remains distinct from a fresh read of its former location. Repeated writes remain represented effects even when their values agree.

### Initial mutation and input replacement

The opening mutation uses two word reads from second input plus 0x74: one supplies a destination base, and the other supplies the value written at that base plus 0x54. Both precede the resulting store. Their mutual evaluation order is not independently established, and their values need not agree under external mutation.

The ambient scale is then stored as a word at its own offset 0x24, followed by its low byte at ambient base plus 9. Next, ambient base is stored at first input plus 0x54, and the fourth input at ambient base plus 0x54. The ambient-scale self-store and its byte store to ambient base plus 9 occur again.

The third input is subsequently stored at second input plus 0x14. Twice ambient scale replaces first input plus 0x54; ambient scale replaces second input plus 0x14. The second input’s low byte is then stored at first input plus 1, followed by another word store of ambient scale at second input plus 0x14.

Thus the third input has a represented write, despite having no established persistent destination. Its transient store is not interchangeable with omission.

### Derived bases and early selection

The following descriptive relationships apply subject to the arithmetic qualifications above:

| Name | Relationship |
|---|---|
| Fourfold base | Four times ambient scale |
| Eightfold base | Eight times ambient scale |
| Doubled entry base | Twice ambient double-source |
| Adjusted base | Fourfold base minus 0x96 |
| Working base | Four times adjusted base |
| Repeated-region base | Eight times adjusted base |

The representation obtains some numerically related values through distinct multiplication and shift expressions. Treating them as these common mathematical relationships is conditional on the relevant arithmetic being defined.

The fourfold base’s low byte is written twice consecutively at doubled entry base plus 0x15. The doubled entry base’s low byte is then written at first input plus 0x15.

The fourth input is stored at fourfold base plus 0x54, followed by a word containing fourfold base at doubled entry base plus 0x34. A word read from doubled entry base plus 0x74 is doubled; call the result the **early doubled value**.

Next, fourfold base plus 0x54 receives fourfold base itself. Its offset 0x15 receives the eightfold base’s low byte, and ambient scale plus 0x44 receives the early doubled value.

An unsigned byte read from fourfold base plus 5 supplies an address base for a word read at offset 0x74. Call that word the **early selected base**. The selected word-read address lies between 0x74 and 0x173 inclusive; this is not established as an array-index operation.

Early selected base plus 0x44 receives the early doubled value. Fourfold base plus 0x15 is then replaced with fourfold base’s low byte. Fourfold base receives early selected base’s low byte at offset 0x0d, itself as a word at offset 0x14, and itself again at offset 0x54, in that order.

A word read at fourfold base plus 0x64 supplies another destination base. That destination receives early selected base’s low byte at offset 0x0d, followed by its own base value at offset 0x14.

A word read from fourfold base plus 4 supplies the **intermediate base**. Early doubled value plus 9 then receives early selected base’s low byte, and early doubled value plus 0x44 receives the eightfold base.

### Fresh selection and the intervening store

An unsigned byte is read from intermediate base plus 5. Before the next read of that location:

- Fourfold base plus 9 receives early doubled value’s low byte.
- Early selected base plus 0x44 receives the selected byte widened to a word.
- Fourfold base plus 0x14 receives the eightfold base.
- Early doubled value plus 0x15 receives intermediate base’s low byte.
- Early doubled value plus 0x44 receives the fourfold base.

These effects occur in the listed order.

Intermediate base plus 5 is then read again. **After this fresh byte read but before its selected word read**, fourfold base plus 0x15 receives the eightfold base’s low byte. Only then is the word at the fresh byte-valued base plus 0x74 read. Call this word the **late selected value**, and twice it the **late doubled base**.

The intervening byte store matters if it overlaps the selected word. The selection byte is already captured, but the selected word is not.

After that word read, fourfold base plus 0x15 receives intermediate base’s low byte; fourfold base plus 0x54 receives fourfold base; fourfold base plus 9 receives late doubled base’s low byte; and fourfold base plus 0x14 receives the eightfold base.

### Ordered late captures

After the repeated region, five accesses have this exact order:

1. Capture the word at absolute address 0xa9.
2. Capture the word at four times late selected value plus 0x74.
3. Write a byte at absolute address 0x3a, containing the low eight bits of repeated-region base plus 0x30.
4. Capture the word at late doubled base plus 0x14.
5. Capture the word at working base plus 4.

The write at 0x3a can affect either subsequent capture through overlap. It cannot retroactively change the first two captured values.

The following mutations then occur in order: working base’s low byte is written at late doubled base plus 0x0d; byte 0x6c at working base plus 8; global-derived base’s low byte at working base plus 0x0d and then plus 9; and late doubled base as a word at its own offset 0x54.

Absolute address 0x67 then receives the low byte of the captured word from 0xa9.

### Late field, word copy, and distinct absolute-byte reads

A word read at late doubled base plus 0x44 supplies the **late field value**. After that read, a byte read from 0x67 supplies a byte store to 0x21.

Late field value’s low byte is stored at working base plus 0x10, followed by its full word at global-derived base plus 0x54. A byte derived from signed right-shifting late field value is then stored at late doubled base plus 1. The shift count is working base’s low byte, ranging from 0 through 255. Machine handling of counts outside the supported word-shift range, and of negative shifted values, remains **documented_only**.

Global-derived base plus 0x54 is next replaced with working base. The word at working base plus 0x40 is captured. **Before that captured word is copied**, the previously captured working-base-plus-4 word is stored at global-derived base plus 0x74. Only afterward is the captured working-base-plus-0x40 word stored at working base plus 0x10.

This preserves both capture and write ordering even if these locations overlap. The latter word store affects four bytes beginning at offset 0x10, including the earlier byte destination.

Global-derived base plus 0x44 then receives late doubled base. The subsequent sequence contains two distinct later reads of 0x67:

- The **first later read** supplies a byte store to working base plus 9.
- Late doubled base plus 9 receives working base’s low byte.
- Working base plus 0x44 receives the captured word from 0xa9.
- A word read at working base plus 0x54 captures the **terminal base**.
- The **second later read** of 0x67 supplies another byte store to working base plus 9.

These are fresh reads at different positions, not a cached-byte reuse. In particular, intervening stores can change 0x67 through aliasing.

### Terminal links and indirect invocation

After the second later 0x67 read and its store, terminal base plus 0x0d receives the low byte of the earlier captured word from four times late selected value plus 0x74.

Late doubled base plus 0x54 then receives the earlier captured word from its offset 0x14. A fresh word read at working base plus 0x14 is captured for a later byte store. Late doubled base plus 0x11 receives the same captured low byte just written to terminal base plus 0x0d.

Terminal base is then stored as a byte at working base plus 9 and as a word at working base plus 0x44.

A word read at late doubled base plus 4 supplies the **final link base**. A halfword containing 0x0065 is stored at twice final link base. The word at final link base plus 0x64 is then read as the **final destination**.

Terminal base plus 0x11 receives the low byte of the captured working-base-plus-0x14 word. Terminal base plus 0x54 then receives a word containing decimal 100.

Next, a word is captured from final link base plus 0x74. A word read at late doubled base plus 0x64 supplies the **final linked value**. Final link base’s low byte is written at late doubled base plus 9; final destination is stored as a word at final linked value plus 0x54; and final linked value is stored as a word at twice final destination.

The unresolved indirect invocation receives, in order:

1. Numeric constant 0x72.
2. Final destination.
3. The earlier captured word from late doubled base plus 0x14.
4. The captured word from final link base plus 0x74.

## Side effects

Absolute-address effects include byte writes at 0x21, 0x3a, and 0x67; a word write at 0x60; and a word read at 0xa9. The latter is not naturally four-byte aligned. Selected-byte lookups also read words in the low-address interval 0x74–0x173.

## Acceptance examples

These are conditional static criteria, not executed tests. Each assumes execution reaches the relevant phase and that the stipulated accesses are supported.

1. **Input roles:** The second input’s low byte is stored at first input plus 1. A store at second input plus 1 is not a substitute. Its visible write-base role is at offset 0x14.

2. **Truncation and transient replacement:** If ambient scale’s low sixteen bits are 0x1234, its byte stores carry 0x34. The third input must nevertheless appear earlier in the store trace at second input plus 0x14 before replacement by ambient scale.

3. **Unsigned selection:** A selected byte of 0xfe produces word-read address 0x172, not a negative displacement.

4. **Intervening selection store:** If fourfold base plus 0x15 overlaps the freshly selected word, that word is read after the eightfold-low-byte store. Moving the word read earlier can change the late selected value.

5. **Width-sensitive constants:** The three 0x3a stores affect one, two, and four bytes respectively. They are not interchangeable byte writes.

6. **Capture barrier at 0x3a:** A late doubled base of 0x26 places its offset-0x14 capture at 0x3a. That capture follows the absolute byte write. The earlier capture from four times late selected value plus 0x74 precedes that write.

7. **Overlapping late destinations:** If global-derived base plus 0x74 and working base plus 0x10 coincide, the captured working-base-plus-4 word is stored first, then replaced by the captured working-base-plus-0x40 word. Both stores remain represented effects.

8. **Fresh reads of 0x67:** The first later read precedes the late-doubled-base-plus-9 store, the captured-0xa9 store, and terminal-base capture. The second follows all three. If an intervening alias changes 0x67, the second read uses the changed byte.

9. **Captured call argument:** The third indirect-call argument is the earlier captured late-doubled-base-plus-0x14 word, even if later writes change that location.

10. **Partial failure:** A fault at a later low-address access does not imply restoration of earlier successful writes. No successful-completion criterion applies to an incompatible memory map.
