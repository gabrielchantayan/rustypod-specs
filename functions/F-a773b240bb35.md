# F-a773b240bb35

## Purpose

The supplied static representation describes a state-mutating routine that interleaves indirect calls with byte and 32-bit memory accesses, then enters an unconditional loop.

No application-level purpose is established. In particular, the evidence does not justify describing the routine as a serializer, allocator, decoder, device driver, or initialization procedure. Its observable contract is an ordered sequence of calls, value transformations, reads, and writes—not a demonstrated higher-level operation.

The visible path has no normal return. Completion, fault behavior, and the effects of its dependencies are unknown. The supplied representation also reports invalid instruction data and omitted unreachable regions, so this contract is conditional on the represented path accurately reflecting executable behavior.

## Behavior

The following ordering applies when all preceding operations complete and the indirect calls return. Calls between two direct memory operations remain observable events; they must not be treated as inert spacing.

### 1. Entry and initial byte updates

The first indirect call receives the first argument. Four more calls follow; the final one supplies a value used as an index.

The routine writes the incoming, otherwise uninitialized register-sized value to the four-byte destination at:

`4 × returned index + 0x14`

It then calls a dependency with four times that index. Four further calls follow, with the last supplying a new 32-bit value.

A byte is read from:

`(first argument >> 8) + 1`

That byte is interpreted directly as an address component. The routine writes the low eight bits of the new value shifted left by two to:

`byte value + 0x11`

This is a byte-selected absolute address, not an established pointer-table lookup. Its destination lies between `0x11` and `0x110`, inclusive.

The shifted value is also passed to a dependency. After four further calls, including a result-producing call, the routine repeats the byte read from `(first argument >> 8) + 1`. It writes to the newly selected destination using the earlier captured value masked with `0x3fffffff`, shifted right by twenty bits, and truncated to eight bits.

The second byte read is independent of the first. Intervening dependencies may change the selector byte. The later write is not guaranteed to target the earlier destination.

### 2. Global capture and repeated selected-word write

A result from the preceding call sequence is shifted left by two and passed to a dependency. Four more calls occur.

The routine then reads the global symbol at absolute address `0x3c` and converts its value to unsigned 32 bits. The underlying width and extension behavior of that symbol are not established by the supplied declaration.

The captured value is written to:

`4 × (third argument >> 7) + 0x14`

The captured value is passed to a dependency. Four further calls occur, with the last supplying another result. The routine then writes the same captured value to the same selected-word destination.

There is no intervening direct reread of `0x3c`. Even if a dependency changes that global, the second explicit write uses the saved capture. Conversely, a dependency may change the destination between the two writes, making the repetition observable.

### 3. First captured word and scaled-record updates

The latest call result, shifted left by two, is passed onward. Four more calls supply another index.

For that index, the routine:

1. Writes four times the index to the four-byte destination at sixteen times the index plus `0x14`.
2. Reads a 32-bit word from four times the index plus `0x14`.
3. Retains the read word as the **first captured word**.
4. Retains the index shifted left by twenty-six bits as a separate 32-bit bitfield value.

The store precedes the read. If their addresses alias, the read observes the preceding store under ordinary sequential memory semantics. The read is not a snapshot taken before the store.

A dependency receives four arguments: sixteen times the index, four times the index, the retained shifted bitfield, and four times the index again. Additional result-producing and forwarding calls follow.

After a later result-producing call, the routine repeats the original scaled-record store using the previously saved index-derived address and value. It does not substitute the latest result for that saved destination.

### 4. Second captured word and its shifted rewrite

The latest result is multiplied by four and passed to a dependency. Four further calls supply a new index.

The routine writes four times this new index at sixteen times the index plus `0x14`, then reads a 32-bit word at four times the index plus `0x14`. This read becomes the **second captured word**.

The retained bitfield from the preceding phase is logically shifted right by seven bits. A dependency receives four times the new index twice, followed by a sequence of result-producing and forwarding calls.

After that sequence, the routine writes the second captured word shifted right by eight bits to the previously selected four-times-index destination plus `0x14`.

That write uses the earlier capture, not a fresh read of the destination.

### 5. Uses of the first captured word

Further result-driven call sequences and stores follow in this order:

- A new index causes a store of four times the index at sixteen times the index plus `0x14`.
- A dependency receives the first captured word shifted right by sixteen bits.
- After intervening calls, four times that index is written at four times the same index plus `0x14`.
- Another index causes a scaled-record store at sixteen times the index plus `0x14`.
- A dependency receives the sixteen-times-index address component. Later calls include a two-argument call carrying a forwarded result and the first captured word shifted right by sixteen bits.
- The scaled-record store is repeated using its saved address and value.
- Another index causes another scaled-record store. The retained bitfield is shifted right by seven bits a second time.
- A dependency receives four times this index and eight times the first captured word shifted right by eight bits.
- Later calls again carry a forwarded result and the first captured word shifted right by sixteen bits.
- The routine writes four times the index to the address formed by eight times the first captured word shifted right by eight bits, plus `0x14`.

These scaled word-derived destinations are computed addresses. No allocation size, object type, or validated array bound is established.

A subsequent call sequence produces another index and scaled-record store. A four-argument dependency then receives:

- Eight times the first captured word shifted right by eight bits, twice;
- The first captured word shifted right by sixteen bits;
- The retained bitfield shifted right by another seven bits.

After further calls, the word-derived address receives its own pre-offset address component as a 32-bit value.

### 6. Secondary-register-dependent stores

After another sequence of calls, a secondary register result is used without an ordinary explicit return-value assignment.

The routine writes:

- The secondary value multiplied by `0x1000000`;
- At the destination formed by the secondary value multiplied by `0x4000000`, plus `0x14`.

It then passes the `0x1000000`-scaled value to a dependency. After four further calls, that same saved value is written at four times a newly returned index plus `0x14`.

The routine also derives the high byte of the first captured word by shifting its already sixteen-bit-shifted form right by eight more bits.

Further call sequences cause:

1. A scaled-record store for a new index.
2. Calls using four times that index and forwarded results.
3. A store of the saved four-times-index value at four times a later returned index plus `0x14`.
4. Another scaled-record store, retaining its four-times-index value.
5. More calls using that retained value.
6. A store of the first captured word’s high byte, as a 32-bit value, at four times a later returned index plus `0x14`.

### 7. Final byte-update sequence

A further index produces another scaled-record store. The retained four-times-index value from the preceding phase is masked with `0x7fffffff` and logically shifted right by seven bits. This derived quantity selects a later byte-read address.

A dependency receives the sixteen-times-index component twice and the first captured word shifted right by twenty-three bits. After intervening calls, the scaled-record destination is overwritten with its own sixteen-times-index component.

Another sequence returns a 32-bit value. The routine reads a selector byte at the derived byte-read address plus one and writes the low byte of that return value shifted left by two to selector plus `0x11`.

The shifted value is passed three times in one dependency invocation. After more calls, the selector byte is reread, and the routine writes the low byte of the earlier return value masked with `0x3fffffff` and shifted right by twenty bits.

A subsequent result supplies a new shifted-by-two value. The routine then:

1. Writes its low byte to `(high byte of first captured word >> 7) + 0x1c`.
2. Rereads the selector byte and writes zero at selector plus `0x11`.
3. Calls a dependency with the high byte of the first captured word shifted right by seven bits.
4. Makes additional calls, including one receiving the new result masked with `0x3fffffff` and shifted right by six bits.
5. Rereads the selector byte and writes zero again at selector plus `0x11`.

The direct destination in step 1 is either `0x1c` or `0x1d`.

Another sequence returns a value that is masked with `0x3fffffff` and shifted right by twenty-five bits. This produces a quantity from 0 through 31.

Before entering the loop, the routine reads a different selector byte, at `0x400` times the saved shifted-by-two value plus one, and writes zero at that selector plus `0x11`. It then calls a dependency with twice the newly derived 0–31 quantity, followed by a result-producing call.

### 8. Unconditional loop

Every visible loop iteration:

- Calls a dependency with the current call-result value and the current unsigned control quantity shifted right by eight bits.
- Performs four further calls, retaining the last result.
- Rereads the loop’s selector byte and writes zero at selector plus `0x11`.
- Calls a dependency with the retained result shifted left by two.
- Performs four further calls.
- Uses the final result to form the next current value by shifting left by two, and the next unsigned control quantity by shifting left by twenty-six bits.
- Repeats without a visible condition or exit.

On the first iteration, the second argument of the first loop call is zero because the initial control quantity is at most 31. Later iterations need not pass zero.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

- **Selector reread:** If the initial selector read returns `0x20`, the first byte destination is `0x31`. If an intervening dependency changes the selector to `0x40`, the later byte destination is `0x51`, not `0x31`.

- **Byte truncation:** If the first byte-producing call result is `0x12345678`, its shifted low-byte write is `0xe0`. Its later masked-and-shifted byte write is `0x23`, provided execution reaches both writes.

- **Third-argument selection:** Third-argument values from 0 through 127 select destination `0x14`. Values from 128 through 255 select `0x18`. Both explicit stores use the same captured global value, regardless of later changes to `0x3c`.

- **Store/read alias:** If the index in the first captured-word phase is zero and address `0x14` is ordinary writable memory, the scaled-record store writes zero there before the captured-word read. The read therefore obtains zero.

- **Distinct word projections:** If the first captured word is `0x12345678`, its sixteen-bit projection is `0x1234`, its high byte is `0x12`, and its eight-times-eight-bit-shifted address component is `0x0091a2b0`. The corresponding offset destination is `0x0091a2c4`.

- **Repeated zero writes:** If a dependency changes a selector byte between two zero-write operations, those writes can clear different destinations. Correct behavior does not require them to revisit the same address.

- **Loop entry:** If the pre-loop masked shift produces 31, the preparatory dependency receives 62, while the first loop call’s second explicit argument is zero.

- **No normal completion:** If every dependency returns and every memory access succeeds, the represented path continues looping. Returning normally would not match the visible path.
