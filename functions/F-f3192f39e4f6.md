# F-f3192f39e4f6

## Purpose

F-f3192f39e4f6 derives a 64-bit working quantity from a context, optionally caches its low 32 bits, applies a dependency-defined collision adjustment, conditionally updates a tracking field, and returns the resulting low 32 bits.

Two explicit early-exit paths return `0xffffffff`: a nonzero context gate and a nonzero status from F-da5096269123. The same bit pattern can also arise from an ordinary result, so the return value alone does not uniquely identify an error.

The static evidence establishes the field accesses, branch conditions, calls, and arithmetic described below. It does not establish the application-level meaning of the quantity or the mathematical operations performed by the opaque dependencies.

## Interface

### Input and result

The function accepts one context address represented in a 32-bit argument.

It returns an unsigned 32-bit value. Successful completion returns the low 32 bits of the final working quantity; it does not return the full 64-bit quantity.

There is no explicit null check, bounds check, or structured error result.

## Behavior

### 1. Initial gate

After zero-initializing the working area, the function reads the 32-bit field at `0x20`.

If it is nonzero, the function returns `0xffffffff`. This path makes no dependency calls and performs no context writes.

If it is zero, processing continues by inspecting the signed 32-bit field at `0x24`.

### 2. Negative selector/value path

A negative value at `0x24` selects the acquisition path.

The function obtains the address from `0x6c` and inspects the first 32-bit word of the addressed object.

- If that word is zero, F-da5096269123 is skipped. The working area remains zero at this point.
- If that word is nonzero, F-da5096269123 is called with the object address and the address of the 8-byte working area.

The address field is read again for the dependency argument in the supplied representation. A single captured object address is not established across the gate inspection and the call.

#### Nonzero acquisition status

If F-da5096269123 returns a nonzero 32-bit status:

1. The current field at `0x48` is read, increased by one, and written back as a 32-bit value.
2. F-60ee867dc1bd is called with the context address and that status.
3. After the call returns, the then-current field at `0x48` is read, decreased by one, and written back.
4. The function returns `0xffffffff`.

The decrement is not a restoration from a saved value. If F-60ee867dc1bd changes the field, the decrement applies to its changed value. No overflow check or recovery path is shown for either 32-bit update.

No cache write, later adjustment call, or tracking-field update is performed by this function on this exit path.

If F-60ee867dc1bd does not return normally, the evidence does not establish that the decrement occurs.

#### Zero acquisition status, or skipped acquisition

Processing continues with the 64-bit working quantity. For the following comparisons, that quantity is interpreted as signed 64-bit.

A further dependency call is selected when either:

- the working quantity is less than or equal to zero; or
- the working quantity is greater than or equal to the sign-extended signed 32-bit field at `0x40`.

The first condition is evaluated first. When it is true, the comparison-related read of `0x40` is skipped.

If either condition holds, F-7071f254f784 is called with four 32-bit arguments:

1. The working quantity’s low word.
2. Its high word.
3. A read of the field at `0x40`.
4. The sign-extension word derived from a read of the field at `0x40`: zero for a nonnegative value, all ones for a negative value.

The 64-bit return replaces the working quantity.

The supplied representation contains separate reads of `0x40` for the last two arguments. It does not establish an evaluation order between those argument expressions. Under stable memory they describe the signed 64-bit extension of one field value; with intervening changes, that consistency is not guaranteed.

If neither condition holds, the working quantity is replaced with exactly one. Thus, when a stable value at `0x40` is positive, a working quantity strictly between zero and that value takes this replacement path.

After this selection, the byte at `0x0e` is read. If nonzero, the low 32 bits of the current working quantity are written to `0x24`. This occurs before the later collision adjustment and before the tracking-field update.

### 3. Nonnegative selector/value path

If the initial signed test of `0x24` is nonnegative, acquisition, range selection, and optional caching are skipped.

The field at `0x24` is read again and sign-extended from 32 bits to form the 64-bit working quantity. With stable memory, its range is zero through `2147483647`.

Because the test and assignment use separate reads, the evidence does not guarantee that a concurrently changed value remains nonnegative on the second read.

### 4. Dependency-defined collision adjustment

Both paths that reach this stage call F-870c4fcf7295 with:

- the 32-bit constant `0x40000000`; and
- a current 32-bit read of the field at `0x40`.

Its 32-bit return is interpreted as signed and sign-extended for comparison with the 64-bit working quantity.

The function reads the working quantity after this call. If it equals the sign-extended dependency result, the final quantity is the working quantity plus one. Otherwise, the final quantity is unchanged.

This increment cannot overflow signed 64-bit arithmetic: the equality condition restricts the value being incremented to the signed 32-bit range.

The evidence does not identify the dependency result as a quotient, limit, or reserved value. What is established is the equality test and one-unit adjustment.

### 5. Tracking-field update and return

The current field at `0x50` is read as an unsigned 32-bit integer and widened without sign extension.

If that widened value is strictly less than the signed 64-bit final quantity, the low 32 bits of the final quantity are written to `0x50`. Equality does not cause a write.

Consequences include:

- A negative final quantity never causes this update.
- A final quantity of zero never causes this update.
- A positive final quantity within the unsigned 32-bit range updates the field only when it is larger.
- A final quantity greater than `4294967295` always satisfies the comparison, but only its low word is stored. The stored value can therefore decrease numerically.

The function returns the final quantity’s low 32 bits.

## Side effects

### Direct writes

The function itself can write only these context fields in the supplied evidence:

- `0x48`: immediately before and after the nonzero-status call to F-60ee867dc1bd.
- `0x24`: on the negative path, when the byte at `0x0e` is nonzero.
- `0x50`: after collision adjustment, when the strict comparison succeeds.

The cache write precedes F-870c4fcf7295. The tracking-field read and possible write follow that call. A cached quantity may therefore differ from the final returned quantity even without any dependency modifying the context.

### Dependency effects and ownership

F-da5096269123 receives both an object address and the address of the working area. F-60ee867dc1bd receives the context address. Those dependencies may have effects not specified here.

The two arithmetic-looking dependencies receive only 32-bit value arguments at their visible interfaces. That does not prove that they preserve globals, previously reachable memory, or context state.

No allocation, release, or ownership transfer is explicitly performed by F-f3192f39e4f6. The evidence does not establish whether any dependency retains an address, releases an object, or mutates aliased storage. Safe lifetime requirements for such behavior remain undocumented.

In particular, treating dependencies as pure is an additional assumption, not an established property. Acceptance examples below state that assumption where needed.

## Acceptance examples

These are conditional static acceptance examples, not observed test results. Unless an example says otherwise, assume stable context memory, valid accesses, normal dependency returns, and no dependency side effects beyond the stated working-area output.

1. **Gate rejection.**  
   With `0x20` nonzero, the result is `0xffffffff`. No dependency is called and no context field is written by this function.

2. **Direct value without adjustment.**  
   With `0x20` zero, `0x24` equal to 7, F-870c4fcf7295 returning 3, and `0x50` equal to 5, the result is 7 and `0x50` becomes 7. The byte at `0x0e` does not enable a cache write on this path.

3. **Equality adjustment precedes tracking.**  
   With a direct value of 7 and F-870c4fcf7295 returning 7, the final quantity is 8. A tracking value of 7 becomes 8; a tracking value of 8 is not written.

4. **Strictly interior acquired value becomes one.**  
   Suppose the negative path acquires 4 with zero status and `0x40` is 10. F-7071f254f784 is not called; the working quantity becomes 1. If caching is enabled and F-870c4fcf7295 returns 1, `0x24` receives 1, but the final result is 2.

5. **Boundary invokes the replacement dependency.**  
   Suppose the acquired quantity is 10 and `0x40` is 10. Equality satisfies the range condition, so F-7071f254f784 is called. The quantity is not automatically replaced with one.

6. **Zero object gate still reaches replacement.**  
   On the negative path, if the addressed object’s first word is zero, acquisition is skipped and the working quantity remains zero. Zero satisfies the first range condition, so F-7071f254f784 is called. Skipping acquisition does not by itself imply an error return or a final value of zero.

7. **Nonzero status brackets handling.**  
   If acquisition returns status 9 and `0x48` is initially 2, the handler observes 3. If it leaves the field unchanged, the subsequent decrement produces 2. If it instead leaves 20, the decrement produces 19. Both cases return `0xffffffff`.

8. **Low-word storage is not saturation.**  
   If the replacement dependency supplies `4294967296` and no equality adjustment applies, any unsigned 32-bit tracking value compares smaller. The function writes zero to `0x50` and returns zero.

9. **The sentinel is not unique to an early exit.**  
   If the replacement dependency supplies signed 64-bit −1 and F-870c4fcf7295 returns 0, there is no equality adjustment. The tracking field is not updated, and ordinary completion returns `0xffffffff`.
