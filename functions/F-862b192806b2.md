# F-862b192806b2

## Purpose

F-862b192806b2 uses an indirect callback to obtain a selector, chooses one of two records embedded in a caller-supplied context, optionally increments a field in that record, and invokes F-2bb3dbfa7286 with a context-held value and an address within the selected record.

The selector’s low eight bits determine whether processing continues:

- `0` selects the record at context byte offset `0x648`.
- `1` selects the record at context byte offset `0x628`.
- Any other value returns `3` without the subsequent record update or dependency invocation.

A supported selector leads to return value `0` if execution reaches the normal return. This does not establish that the downstream operation succeeded: no result from F-2bb3dbfa7286 is inspected.

These are statically established behaviors. The meanings of the records, counter-like fields, context-held value, and suppression byte are not established.

## Behavior

### Callback precedes selection

Every invocation first initializes the temporary selector slot from the fourth input and invokes the indirect callback. There is no validation of the initial selector before the callback.

Selection uses the value remaining in the slot after the callback returns, not necessarily the original input. A callback can therefore change an initially unsupported selector into a supported one, or the reverse.

The selector test examines the numeric low eight bits. The upper 24 bits do not affect selection. This is a bit-selection rule, not a claim about which addressed byte contains those bits.

Because the callback runs first, context contents used later are not established as snapshots of their entry values. In particular, if the callback can reach the context or aliased storage, it may change the suppression byte, selected field, or context-held value before this function accesses them.

### Unsupported selector

If the selector’s low eight bits are neither `0` nor `1`, the function returns `3`.

On this branch, the function performs no explicit context-field read, record-field increment, or invocation of F-2bb3dbfa7286. The earlier callback invocation still occurred and may have had side effects.

An unsupported selector does not make the whole invocation side-effect-free. Nor does this branch establish that the context address was valid: the function itself does not dereference that address on this path.

### Supported selector and record choice

A selector with low eight bits equal to `0` chooses the record beginning at context offset `0x648`. A selector with low eight bits equal to `1` chooses the record beginning at offset `0x628`.

Record choice occurs before the conditional increment. The same chosen record supplies both the potentially incremented field at record offset `0x0C` and the address at record offset `0x04` passed downstream.

There is no fallback record for other selector values.

### Conditional increment

The increment has two gates, evaluated in order:

1. The third input must be nonzero.
2. The byte at context offset `0x6A9` must equal zero.

If the third input is zero, the suppression byte is not read by this function. If the third input is nonzero but the suppression byte is nonzero, the selected 32-bit field is neither read nor written for the increment.

When both gates permit the update, the function reads the selected field at record offset `0x0C`, adds one, and writes a 32-bit result back to the same field. Thus:

- Selector `0` updates context offset `0x654`.
- Selector `1` updates context offset `0x634`.

The operation is an ordinary read, arithmetic operation, and write. No lock, atomic operation, saturation, or overflow check is shown. The source representation uses a signed 32-bit field. Ordinary, nonoverflowing increments are established; behavior at the signed overflow boundary requires additional execution-model evidence and must not be assumed to be portable wraparound.

### Downstream invocation and return

After the optional increment, the function reads the 32-bit value at context offset `0x624` and invokes F-2bb3dbfa7286 with:

1. That value.
2. The address at offset `0x04` within the selected record.

The second argument is an address into the context, not a copy of the data stored there.

The conditional increment, when performed, precedes this invocation. The downstream dependency therefore receives control after the field update. There is no rollback in the visible function if that dependency subsequently fails or exits abnormally.

If F-2bb3dbfa7286 returns normally, the function returns `0`. Its return value, if any, is ignored.
