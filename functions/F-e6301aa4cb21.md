# F-e6301aa4cb21

## Purpose

F-e6301aa4cb21 obtains an object address, initializes selected object fields, conditionally requests backing storage, obtains additional resource-like values, and performs two final configuration calls. On normal completion, it returns the original object address.

The established contract is the ordering of dependency calls, memory accesses, arithmetic, and branches described below. “Storage,” “resource,” and “configuration” are descriptive roles, not established semantics of the dependencies. An image-related interpretation is plausible from the dimensions and size factors, but is inferred intent only.

This specification rests on supplied static evidence. No runtime tests have been performed. Dependency implementations and the meanings of the referenced global values are unavailable.

## Behavior

### 1. Obtain the object and query two values

F-d339f4e17efe is called with four arguments: the first input, the second input, zero, and zero. Its result becomes the retained object address.

F-4100b60c14d9 is then called twice, sequentially:

- The first call receives the original second input and a value read from one referenced global source.
- The second call receives the original second input and a value read from a different referenced global source.

The referenced values and their meanings are unavailable. They are not established as immutable constants. In particular, the second query’s global argument is obtained after the first query returns. The first query result is retained across the second call.

Only after both queries return does the function directly perform these writes, in order:

1. Four-byte zero at `0x8C`.
2. Four-byte zero at `0x90`.
3. First full-width query result at `0x94`.
4. Second full-width query result at `0x98`.
5. One-byte zero at `0xA0`.

These explicit initialization writes do not precede either query call.

### 2. Select and request backing storage

The function reads the four-byte field at `0x98` and retains its low 16 bits. It then reads the four-byte field at `0x94` and retains its low 16 bits. These are full-width reads followed by masking, not established two-byte memory reads.

The selector at `0x65` is evaluated as follows:

- A first byte read equal to zero selects a size factor of two.
- Otherwise, a second byte read equal to one selects a size factor of four.
- If the first comparison fails and the second read is not one, no storage dependency is called, and zero is written to `0x70`.

On either supported path, F-fab3799b3190 receives the calculated 32-bit size. Its result is written to `0x70` without a success check.

For a stable selector byte, zero selects factor two, one selects factor four, and every other value skips the request. The second selector read is a distinct access; the function does not retain the first read for both comparisons.

Each masked operand is unsigned and lies from 0 through 65,535. Their product fits in unsigned 32 bits. Applying the factor can overflow that width. The observable size is the low 32 bits of the scaled product; there is no widening or overflow rejection. The receiving dependency’s interpretation of that bit pattern, including signedness, remains unknown.

A selected path still calls F-fab3799b3190 when the calculated size is zero.

### 3. Store the input-derived flag and another result

The function writes one byte at `0xA1`:

- Third argument equal to zero: 1.
- Any other unsigned 32-bit value: 0.

This is a full-width zero decision. A nonzero argument whose low byte is zero does not produce 1.

It then calls F-bb50a072e902 with zero. The result is passed to F-5b4ae75440ab together with one. The latter result is written as four bytes at `0x84`.

### 4. Expose two writable object fields

2. The address of object field `0x74`.

The clears establish the fields’ contents before this call, not their contents afterward. The dependency may change those fields or other reachable state.

**If that read is zero:**

- The first resource call receives zero as argument six.
- Its result is written at `0x7C`.
- The second resource call also receives zero as argument six.

In this branch, `0x78` is not read to obtain the second resource argument. Changes to `0x74` or `0x78` during the first resource call do not cause the branch to be reconsidered.

- The first result is written at `0x7C`.
- The function then reads `0x78` for the second resource call’s sixth argument.

The repeated `0x74` read need not equal the branch-selecting read if memory changes between accesses. Likewise, the `0x78` value is obtained after the first resource call and the explicit `0x7C` write, not immediately after F-220eb07542db.

Neither resource result is explicitly checked.

### 6. Conditionally replace a configuration field

After both resource results have been stored, the function reads one byte from offset `0x64` of the original second argument.

If that byte is exactly 5, the function reads `0x80`, calls F-6d4e5f4e1b57 with that value and 4, and writes the result at `0x68`.

For every other byte value, this transformation and write are skipped. The first final configuration call still reads `0x68`, so that field must then obtain its value from earlier state or dependency effects.

The byte is read at this late stage. Its entry-time value does not determine the branch if it has changed.

### 7. Perform the final configuration sequence

One shared 32-bit global source is read twice before the first configuration call. The reads serve different purposes.

First, the function reads and retains the shared global value for use in the **second** configuration call.

It then initializes a contiguous 16-byte temporary record. The direct write order is:

1. Four-byte value 240 at record offset `0x0C`.
2. Four-byte zero at record offset `0x00`.
3. Four-byte value 320 at record offset `0x08`.
4. Four-byte zero at record offset `0x04`.

After initialization, the record’s four fields in ascending offset order are 0, 0, 320, and 240. A rectangle interpretation is inferred, not established.

For the **first** call to F-c41a20765e01, the function reads the shared global again. That call receives:

1. The object address.
2. The value read from object field `0x68`.
3. Zero.
4. The later, second read of the shared global.
5. The temporary-record address.

The source establishes that the second global read follows the record initialization. It does not require an ordering between that read and the `0x68` read within preparation of this call.

After the first configuration call returns, the function reads object field `0x7C` and calls F-6d4e5f4e1b57 with that value and 4.

The second call to F-c41a20765e01 then receives:

1. The object address.
2. The result of this intervening transformation.
3. Zero.
4. The value retained from the **earlier, first** shared-global read.
5. The same temporary-record address.

The two fourth arguments are therefore equal only if the two global reads yield equal values. Remaining unchanged between those reads is sufficient; immutability is not established. Changes to the global after the later read do not replace the earlier retained argument used for the second configuration call.

The function does not directly restore the temporary record between configuration calls. Its contents at the second call are nevertheless **not guaranteed to equal its contents immediately after the first call**. F-6d4e5f4e1b57 intervenes, and its preservation behavior is unknown. The first configuration dependency could retain or expose the record address, making indirect modification during the intervening call possible.

Similarly, the `0x7C` read occurs after the first configuration call. It is not guaranteed to yield the initially stored first resource result.

On normal completion, the function returns the retained original object address.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Conditions apply at the specified accesses; they do not imply that dependencies preserve unrelated state.

1. **Two-factor sizing.** If the size reads yield low halves 320 and 240 and the first selector read is zero, F-fab3799b3190 receives 153,600. Its result is explicitly written at `0x70`.

2. **Four-factor sizing.** If those low halves are unchanged, the first selector read is nonzero, and the second is one, the requested size is 307,200.

3. **Upper halves excluded.** Values `0xABCD0140` at `0x94` and `0x123400F0` at `0x98` supply sizing operands 320 and 240. Their upper halves do not contribute.

4. **Unsupported selector.** A stable selector of 2 causes no F-fab3799b3190 call and an explicit zero write at `0x70`. Processing continues.

5. **Changing selector.** A first selector read of 2 followed by a second read of 1 selects factor four. A single retained-selector implementation would not reproduce this access behavior.

6. **Zero-size request.** If either masked operand is zero and a supported path is selected, the storage dependency is still called with zero.

7. **Size wrap.** With both masked operands equal to 65,535 and factor four selected, the passed 32-bit pattern is `0xFFF80004`. No overflow-rejection branch occurs; receiver acceptance remains unknown.

8. **Full-width flag.** Third arguments 0, 1, 2, 256, and `0xFFFFFFFF` produce explicit byte writes of 1, 0, 0, 0, and 0 at `0xA1`.

9. **Zero resource branch.** If the branch-selecting `0x74` read is zero, both resource calls receive zero as argument six, even if `0x78` is nonzero or the first call changes either field.

10. **Late second resource argument.** On the nonzero branch, a change to `0x78` during the first resource call affects the second call if it remains present when the subsequent read occurs.

11. **Late input selector.** A byte value of 5 at the late input read triggers the transformation of `0x80` and replacement of `0x68`. Any other value skips that replacement.

12. **Distinct global observations.** If the earlier shared-global read yields 7 and the later read yields 9, the first configuration call receives 9 as argument four and the second receives 7. A subsequent global change alone does not alter the retained 7.

13. **Record initialization order.** Before the first configuration call, the direct record writes occur at offsets `0x0C`, `0x00`, `0x08`, and `0x04`, with values 240, 0, 320, and 0 respectively.

14. **Record reuse without preservation.** If the first configuration call changes the record and no intervening effect changes it again, the second call sees those changes at the same address. If the intervening transformation modifies exposed record storage, the second call instead sees the contents present after that modification. No direct restoration by this function occurs in either case.
