# F-1e2086823720

## Purpose

F-1e2086823720 selects between two immediate-return paths and a conditional search, then returns two packed 32-bit words.

F-6944981dc714 supplies the classification:

- Exactly 2: return zero in the low-order word.
- Exactly 1: return the value from the **second** global read in the low-order word.
- Any other value: prepare bounds and examine successive signed integer indices until a comparison returns nonzero or the range is exhausted. The low-order word is the value from the **first** global read on a nonzero comparison, or zero on exhaustion.

The high-order word comes from mutable local storage initialized with the second argument. Each comparison receives writable access to that storage after it has been reset to the original second argument.

**Readiness: documented_only.** The supplied static representation establishes the wrapper’s control flow, explicit data flow, and two distinct global-read positions. Missing dependency contracts prevent an independently interoperable implementation. No runtime tests have been performed.

### Result

The function returns a 64-bit value:

- Bits 63–32 contain the final 32-bit contents of the mutable result storage.
- Bits 31–0 contain the selected 32-bit low-order value.

Packing preserves the two words’ bit patterns. It does not sign-extend either word into the other half and does not establish a memory or transmission byte order.

The result is not established to be a Boolean, address, status code, or count. In particular, a zero low-order word does not uniquely identify exhaustion.

## Behavior

### Initialization and classification

Before invoking any dependency, the wrapper initializes:

- The mutable result word from the second argument.
- The local upper-bound word from the third argument.
- The local lower-bound word from the fourth argument.

It then invokes F-6944981dc714 with the context interior address at byte offset 268.

After that call returns, the wrapper reads a global 32-bit value. This is the **first global read**. Its captured value is retained for the possible nonzero-comparison result on the search path.

If the classification is not 2, the wrapper reads the same global again. This is the **second global read**. It occurs before distinguishing classification 1 from the search path.

The reads are separate source-level operations. Their values must not be assumed equal. The global’s mutability, access semantics, and concurrent behavior are unavailable.

### Classification exactly 2

This path performs the first global read but not the second.

It does not invoke range preparation, entry lookup, comparison, or the post-search dependency. The result contains:

- High-order word: the original second argument.
- Low-order word: zero.

The first global value is not used in the returned words.

### Classification exactly 1

This path performs both global reads, in order, after classification.

It does not invoke any search-path dependency. The result contains:

- High-order word: the original second argument.
- Low-order word: the **second** global read.

The first global read does not supply the low-order result on this path, even if it happens to have the same value as the second.

### All other classifications: range preparation

Every classification other than 1 and 2 follows the search path, including negative classification results.

Both global reads have already occurred when F-80474946e6fd is invoked. Its arguments are:

1. The original context.
2. A writable reference to the lower-bound word, initially the fourth argument.
3. A writable reference to the upper-bound word, initially the third argument.

No return value from this dependency is checked.

After the call, the wrapper copies the current lower-bound value into the signed 32-bit iteration index. The lower-bound storage is not explicitly consulted again.

The upper-bound storage is consulted by the loop condition. It is not explicitly copied into a separate fixed limit. If dependencies can later modify that storage through retained references or other access, the effective limit can change. The source does not establish whether they do so.

### Search condition and low-order selection

Each evaluation of the search condition first sets the prospective low-order result to zero, then checks whether the signed current index is less than or equal to the signed current upper bound.

Consequences:

- A lower bound initially greater than the upper bound produces no lookup or comparison.
- Equality permits one entry examination at that index.
- Ordinary exhaustion leaves the low-order word zero.
- The second global read occurs on this path, but its value does not survive as the low-order result: the first condition evaluation replaces it with zero.

With unchanged bounds and representable index increments, examination proceeds in increasing order across an inclusive range.

### Entry examination

For each index admitted by the condition, the wrapper performs these operations in order:

1. Reads the context’s 32-bit field at byte offset 188.
2. Invokes F-3593620aad0a with that field value and the current signed index.
3. Resets the mutable result word to the original second argument.
4. Invokes F-86e59aee734e with the opaque 32-bit lookup result and a writable reference to the mutable result word.
5. Selects the captured **first** global-read value as the prospective low-order result.
6. Stops immediately if the comparison return is nonzero; otherwise advances the index and evaluates the search condition again.

Both positive and negative nonzero comparison returns stop the search.

The context field is read afresh before every lookup. A value observed at one iteration is not explicitly cached for later iterations.

The mutable result word is reset **after** lookup and **before** comparison. Therefore, earlier comparison output is not carried into the next comparison. If a later comparison leaves the word untouched, it retains the original second argument rather than the previous comparison’s output.

After a zero comparison, the next condition evaluation clears the low-order selection to zero. If that condition rejects the next index, exhaustion therefore returns zero rather than the captured first global value.

### Post-search call and return

After a nonzero comparison or ordinary exhaustion, including an initially empty range, the wrapper invokes F-a9fdcbf82580 with:

1. The context interior address at byte offset 268.
2. The original second argument.

It does not pass the comparison-modified word as the second argument. No return value from this dependency contributes to the packed result.

The result is packed after this call:

| Search outcome | Low-order word |
|---|---|
| A comparison returns nonzero | First global-read value |
| The condition rejects an index before any comparison | Zero |
| All examined comparisons return zero and the condition eventually rejects an index | Zero |

The high-order word is read from the mutable local storage at packing time. The wrapper itself does not reset that storage after the final comparison or during an empty search.

Absent additional indirect modifications by dependencies, this means:

- Nonempty search: the high-order word is the word left by the final comparison.
- Empty search: the high-order word is the original second argument.

Because a writable address escapes to comparison dependencies, the supplied evidence alone does not prove that later dependencies cannot indirectly modify it before packing.

### Arithmetic and termination limits

Index comparisons are signed 32-bit comparisons. Negative bounds and indices are not locally rejected.

A zero comparison at the maximum signed 32-bit index requires another increment before the next condition evaluation. The supplied evidence does not establish a portable overflow rule for that operation. Do not promise wrapping, termination, or an error result in that case.

The context-address additions also lack a specified overflow or invalid-address policy. No local check makes arbitrary first-argument bit patterns safe.

## Side effects

### Explicit wrapper effects

The established source-level sequence includes:

- Initial writes to three local 32-bit words.
- One classification call on every invocation.
- One global read immediately after classification.
- A second global read if and only if classification is not 2.
- On the search path, one range-preparation call exposing both bound words.
- For each admitted index, one context-field read, one lookup call, a reset of the mutable result word, and one comparison call exposing that word.
- One post-search call after a normally completed search, including an empty search.
- A final read of the mutable result word for packing.

There is no explicit wrapper write to persistent context memory or to the global.

The first global read may be unused in the eventual result. The second may also be unused, notably on every search-path outcome. Lack of result use does not erase their distinct positions in the supplied representation.

### Dependency-mediated effects and failures

The dependencies’ persistent effects are unknown. The wrapper does not establish absence of global mutation, context mutation, allocation, release, I/O, synchronization, or retained references.

No local recovery, exception handling, rollback, or dependency-status translation is shown. All subsequent sequencing and return guarantees assume dependencies return normally and required operations remain valid.

Classification 1, classification 2, exhaustion, and a nonzero comparison are control outcomes, not established error categories.
