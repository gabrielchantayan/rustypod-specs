### First repeated-value capture and arithmetic-word write

### Final carry-dependent byte write

A **comparison bit** is one if the incoming comparison word is unsigned-less-than-or-equal-to the captured destination value, and zero otherwise.

A separate **carry bit** is one when either:

- Doubling the second snapshot produces an unsigned 32-bit carry; or
- Adding the comparison bit to the low-32-bit doubled result produces an unsigned 32-bit carry.

This is a Boolean combination, not a count of carries.

An **address-adjustment bit** is one when either:

- The unsigned prefix value exceeds `0xffffffb3`; or
- Adding the carry bit to the low-32-bit result of the prefix value plus `0x4c` produces an unsigned 32-bit carry.

Otherwise it is zero.

The final byte’s bit pattern is the low 8 bits of the prefix value plus `0x4c` plus the carry bit.

The destination expression combines, in the represented additive order:

- A value obtained from final-base storage.
- The captured destination value.
- Twice the second snapshot.
- The comparison bit.
- The address-adjustment bit.

The second-snapshot doubling is unsigned 32-bit arithmetic. The entire destination expression cannot be promised to be a low-32-bit sum solely from the supplied evidence: the declaration of final-base storage is missing and can affect the surrounding arithmetic and address conversion. Under a 32-bit unsigned interpretation of that operand and address expression, the destination is the low-32-bit sum of the listed terms.

Final-base storage is evaluated after the preceding byte write. That write may therefore affect the destination if it changes data consumed by the final-base evaluation. The effect depends on the unknown source access width, conversion, and byte order.

### Arithmetic threshold and defined shift count

An incoming arithmetic word of `0x53` contributes no threshold increment to its halfword destination; `0x54` contributes one. Both imply shift counts above 31, so this comparison example does not establish the stored halfword.

For an incoming arithmetic word of `1`, the shift count is one and the shifted value is zero. The halfword data is therefore `0x0001`, and there is no threshold increment.

### Separate converted snapshots

If the first repeated-value snapshot is `0x1234` and the second is `0x5678`, the combined-address halfword write stores `0x1234`. The subsequent byte write at twice the second snapshot stores `0x34`.

These are local-value conditions. They neither require four-byte source accesses nor determine the value used by the intervening direct-reference halfword operation.

### Carry changes data independently of address adjustment

If the second snapshot is `0x80000000`, doubling it produces a carry and a low-32-bit result of zero.

With a prefix value of zero, the final byte is `0x4d` and the address-adjustment bit is zero. The comparison bit still contributes separately to the destination.

### Prefix boundary

For a prefix value of `0xffffffb3`:

- Carry bit zero gives byte `0xff` and address-adjustment bit zero.
- Carry bit one gives byte `0x00` and address-adjustment bit one.

For a prefix value of `0xffffffb4`, the address-adjustment bit is one for either carry-bit value.

These conditions establish the byte and adjustment bit, not the complete destination when final-base expression rules remain unknown.

Whether the argument changes, and how, depends on the source access width, signedness, byte order, overlapping position, and calling convention. Overlap with a presumed four-byte region is insufficient to determine the result because no four-byte dispatch access is established.
