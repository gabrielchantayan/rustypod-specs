# F-d11a98379331

## Purpose

F-d11a98379331 coordinates four dependencies, retains arithmetic and pointer state across dispatched actions, and conditionally transfers individual bytes into invocation-local storage. It returns an unsigned 32-bit value held in a publication field. The meaning of that value is unresolved; zero is not established as success or failure.

The supplied static evidence does not identify a conventional copying, initialization, cryptographic, or hashing interface. None of the integer arguments is established as a buffer length.

Fixed-word contents determine action selection and continuation. Because those contents are unavailable, this contract specifies conditional action behavior, state persistence, and observation boundaries rather than a single entry-to-exit sequence.

- **Established** means supported by the supplied static representation.

- **Inferred intent** is explanatory, not an acceptance requirement.

## Behavior

### Dispatch and retained state

A fixed word supplies initial control state. Every dispatch iteration first reads an **indexing word**, retaining that observation for the iteration, and then reads a **dispatch-offset word** used with the control state to select an action. Both observations precede even an immediate return.

Other indexing-word references are fresh observations unless explicitly identified as the iteration-entry snapshot. A recurring **scaling word** is likewise read separately at each represented occurrence. Repeated observations must not be collapsed: dependencies may modify their underlying locations, and no immutability or synchronization contract is available.

The important retained roles are distinct:

- the **current arithmetic value**;
- the **shared publication operand**;
- the **published result field**;
- mutable pending first and third arguments for F-2c46a02c25e3;
- an offset base and argument-2-derived arithmetic state;
- a transfer counter and progression state;
- a saved refresh value and a dependency intermediate;
- working, transfer-source, transfer-destination, comparison, and dependency pointers.

In particular, the current arithmetic value, shared publication operand, and published result are not interchangeable.

Unrecognized dispatch selections execute the same transfer action as one explicit selection. They are not rejected. No iteration bound, transfer count, progress condition, or termination guarantee is established.

### Argument installation

Installation derives the pending third dependency argument from argument 1 and a scaling-word read. It derives the current arithmetic value from argument 5 and a separate scaling-word read. The pending first dependency argument is argument 6 multiplied by another fixed word.

Both retained pointer roles originating from argument 4 are installed before the continuation-word read. After that read, the offset base becomes unscaled argument 6, the working pointer becomes argument 3, and the argument-2-derived state becomes argument 2.

Installation does not publish a result or replace the shared publication operand. Later preparation actions can replace the pending arguments, offset base, argument-2-derived state, and other retained state.

### Byte transfers

Each reached transfer action reads one source byte and then writes one destination byte at the same unsigned 32-bit index. Its byte arithmetic reduces to

\[
-767v+1280\equiv v\pmod{256}.
\]

The written byte therefore equals the read byte. This is a single-byte preservation guarantee, not a whole-buffer copy contract.

**Counter-based mode.** A fresh indexing observation multiplied by the entering transfer counter determines the accessed index. The shared publication operand becomes that index. After the store, the next counter and current arithmetic value become the product of:

- a fresh scaling observation;
- the iteration-entry indexing snapshot;
- the entering counter plus another fresh scaling observation.

Both scaling observations occur after the store; their relative evaluation order within the expression is unresolved. A continuation read precedes installation of the new counter.

**Pending-argument-based mode.** A fresh indexing observation multiplied by the pending third dependency argument determines the accessed index and shared publication operand. After the store, a fresh scaling observation multiplies that already calculated index into the current arithmetic value. A continuation read precedes saving that product as progression state.

A separate action resets the counter to zero after its continuation read. Another seeds progression from the same fixed location used for offset adjustment.

No represented check restricts transfer indices to the 128-byte destination region.

### Arithmetic preparation

#### Counter-derived preparation

This preparation uses the entering counter without changing it. Let the **basis** mean counter multiplied by the counter multiplier.

The pending third dependency argument becomes basis plus 127. The pending first argument becomes basis plus a dedicated fixed-word observation. The argument-2-derived state becomes basis plus 126.

For offset preparation, a second counter-derived term is formed by multiplying the counter by the progression multiplier, adding one, and ORing with a fixed mask. The offset base becomes the argument-2-derived state minus the OR of:

- the pending first argument plus that masked term;
- the pending third argument.

The first continuation observation follows this offset preparation. The current arithmetic value then combines:

- −129 minus the OR of basis minus one with **0xFFFFFF7F**;
- XOR of the offset base with the complement of the pending third argument ORed with another fixed mask.

Those two parts are added. A negative signed result gives control zero; a nonnegative result gives control one. The second continuation observation follows the control calculation. The shared publication operand finally becomes the current arithmetic value, not the binary control.

#### Progression-derived preparation

This preparation leaves the entering progression unchanged. Define the **indexing product** as progression multiplied by a fresh indexing observation. A second term is progression multiplied by the progression multiplier, plus one.

The argument-2-derived state becomes a fixed-word observation minus the indexing product.

The counter is replaced by an expression that subtracts the second term ORed with a fixed mask from the indexing product, adds a mixing-word observation, XORs the complement of a second observation of that mixing word, and adds one. The addition precedes that XOR.

The pending first argument is the OR of:

- the argument-2-derived state plus the second term ORed with a complemented shifted word;
- the indexing product minus one.

The complemented shifted word uses a **second observation of the location used for the earlier subtraction**, shifted left by one and then complemented.

The offset base becomes the new counter plus the XOR of the pending first argument and two complemented masked forms of indexing product minus one. Each masked form ORs that value with its respective fixed mask before complementing.

The pending third argument becomes entering progression plus a fixed-word observation. The current arithmetic value becomes offset base minus indexing product. Its unsigned high bit supplies the continuation control. Both continuation candidates are read after these calculations; the shared publication operand finally becomes the current arithmetic value.

### Refreshes and pointer decisions

One refresh multiplies the saved refresh value by fresh scaling and indexing observations, replacing the current arithmetic value and shared publication operand.

Another does the same using the dependency intermediate, then reads its continuation and saves the resulting current value as the saved refresh value. It does not replace the dependency intermediate itself.

The dependency actions distinguish these refresh sources: F-6c2a60ff6df7 and F-570a46b7d56c save their final arithmetic product as the dependency intermediate; F-6b5ae5017b36 saves its product **before the second scaling** there, while saving its final current value separately as the saved refresh value.

Other actions load the shared publication operand directly from a fixed word or rescale the pending third argument by a fresh indexing observation before testing the comparison pointer.

Pointer decisions do not replace the shared publication operand with the current arithmetic value.

### Publication, continuation, and return

Publication has three ordered effects:

1. The current arithmetic value is replaced by the shared publication operand multiplied by a fresh indexing observation.
2. A continuation word is read.
3. The result field is replaced with that current arithmetic product.

**The shared publication operand remains unchanged.** Consequently, publication affects a subsequent F-6b5ae5017b36 first argument, even without another preparation action. Repeated publication multiplies the unchanged shared operand by each new indexing observation; it does not automatically compound the previous published result.

Return yields the last published field, or zero if no publication occurred.

Some actions only read a continuation. Several locations are shared: one serves a refresh and the direct operand loads; another serves two continuation-only actions; progression seeding shares the pending-argument transfer continuation; counter reset shares the counter-transfer continuation. Shared locations do not authorize merging observations across actions.

## Acceptance examples

These are conditional static criteria, not executed tests. Arithmetic examples use 32-bit reduction and require valid storage wherever memory is accessed.

1. **Byte identity.** A reached transfer reading 0 or 255 stores 0 or 255 respectively. This does not require another transfer.

2. **Iteration snapshot.** With iteration-entry indexing 2, transfer-time indexing 3, and counter 4, counter mode accesses index 12. Post-store scaling observations 5 and 7 produce next counter \(5\times2\times(4+7)=110\), not 165.

3. **Pending-argument progression.** Pending third argument 4, fresh indexing 3, and post-store scaling 5 give accessed index 12 and progression 60. The entry snapshot does not replace that index.

4. **Displacement persists as current arithmetic.** Offset base 9, adjustment 2, and indexing 3 produce displacement 21. Before F-2c46a02c25e3, the current arithmetic value is already 21; afterward it remains 21. If F-6b5ae5017b36 is subsequently reached without replacement of that value and its pre-call multiplier is 5, its first argument is 105.

5. **Publication updates current arithmetic.** Shared operand 3 and publication indexing 4 produce current arithmetic 12 and published result 12, while leaving the shared operand 3. A later F-6b5ae5017b36 action with multiplier 5 receives first argument 60, absent intervening replacement.

6. **Repeated publication is not compounding.** Continuing the preceding publication state, another publication with indexing 5 produces current arithmetic and result 15, not 60. Returning then yields 15.

7. **Signed shift matters.** If F-6b5ae5017b36 returns 1, its three post-call indexing observations are 0, 0, and 0x80000000, and all scaling observations are one, the intermediate and current value are zero. The signed shift yields −2 and continuation control zero. An unsigned shift would give the wrong control.

8. **Fresh observations remain distinct.** If progression preparation’s subtraction-word and later shift-word observations differ, each expression uses its own observation. Likewise, the repeated dedicated-word reads in the F-570a46b7d56c action cannot be merged.

9. **Publication width.** Shared operand 2 multiplied by publication indexing \(2^{31}\) makes both current arithmetic and published result zero. The shared operand remains 2.

10. **Call and return boundaries.** Global changes during F-2c46a02c25e3 do not cause displacement recomputation. An immediate return still follows entry indexing and dispatch-offset observations and returns zero if no publication occurred.
