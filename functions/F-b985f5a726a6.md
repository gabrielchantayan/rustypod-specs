# F-b985f5a726a6

## Purpose

F-b985f5a726a6 updates one flag in a global-backed word according to whether its input is zero.

The flag has mask **0x00000100**, corresponding to bit 8 when the least significant bit is numbered 0:

- A zero input sets the flag.
- Any nonzero input clears the flag.
- Every other bit is retained from the value read before the update.

The function returns zero after the write. It does not return the previous flag value, the updated word, or an indication that the flag changed.

The established behavior is a bit update. Whether this bit represents an enable state, a disable state, a hardware control, or another condition is unknown.

## Behavior

### Flag transformation

The update first removes bit 8 from the word read from memory. It then restores that bit only when the input equals zero.

For a stable target location, let the initial word be the value actually read by the function. The resulting word is:

- For a zero input: the initial word with bit 8 set.
- For a nonzero input: the initial word with bit 8 cleared.

The relevant 32-bit masks are:

| Mask | Meaning |
|---|---|
| 0xFFFFFEFF | Retains all bits except bit 8 |
| 0x00000100 | Selects bit 8 |

No other bit is intentionally changed. This preservation is relative to the value read, not necessarily to the memory contents immediately before the subsequent write.

### Observable access order

The supplied representation establishes the following order:

1. Resolve the global-backed base for the target read.
2. Read the word at byte offset 8.
3. Derive the replacement value using the zero/nonzero classification of the argument.
4. Resolve the global-backed base for the target write.
5. Write the replacement word at byte offset 8.
6. Return zero.

There is one explicit target-word read and one explicit target-word write. The write is unconditional after a successful read and value computation. In particular, an already-set flag is still written for a zero input, and an already-clear flag is still written for a nonzero input.

The source representation refers to the global-held base separately for the read and the write. It does not establish a guarantee that one captured address is used throughout. With a stable base, both accesses address the same word. If another actor can change the base between accesses, the representation does not establish that the read and write reach the same object. Exact machine-level reads of the base storage are not independently available as evidence.

### Width and arithmetic

The supplied representation describes a 32-bit word transformation and a 32-bit result. The masks operate on that word; there is no visible narrowing to a byte or halfword.

The offset is eight bytes, not eight words. No arithmetic is performed on the input other than comparing it with zero.

No bounds check, pointer-overflow check, or alignment check is visible. Behavior for an invalid base or an invalid computed address is not defined by this contract beyond the absence of a local error-handling path.

### Repeated calls

For a stable, ordinary-memory target with no intervening modification:

- Repeated zero inputs leave the flag set.
- Repeated nonzero inputs leave the flag clear.
- Switching between zero and nonzero inputs changes only bit 8.

These are idempotence properties of the stored value, not of the access trace. Every completed call still performs a word write.

## Side effects

The explicit side effect is a full-word write to the target address. Although the intended value change concerns one bit, the operation writes the replacement 32-bit word rather than exposing a dedicated bit-write operation.

This distinction matters in two cases:

- **Concurrent access:** An unrelated-bit change made after the read can be overwritten by the later full-word write. The function provides no visible atomic read-modify-write primitive, lock, retry, or conflict detection.
- **Device-backed memory:** If the address refers to a register or another special memory region, the read and write may have effects beyond retaining or changing stored bits. The supplied evidence does not establish such a mapping or its access semantics.

There is no explicit allocation, deallocation, ownership transfer, callback, logging operation, or separate update to the global-held base. The function uses pre-existing state; it does not visibly create or release the target object.

The zero result is not a verification that the target accepted the value. There is no readback after the write.
