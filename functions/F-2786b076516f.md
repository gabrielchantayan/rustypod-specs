# F-2786b076516f

## Purpose

F-2786b076516f classifies an unsigned input against a sequence of fifteen unsigned 16-bit thresholds. It reports the index of the first threshold strictly greater than the input. If no such threshold occurs within the fifteen entries, it reports fifteen.

The threshold sequence is obtained through dependency F-af09788000fd. The result is written through a caller-supplied output pointer; it is not returned as the function’s direct return value. On the established normal-completion path, the direct return value is a 32-bit zero.

This is a positional search, not an unconditional count of thresholds less than or equal to the input. Those descriptions coincide for a nondecreasing sequence, but ordering is not checked or otherwise established by the supplied evidence.

## Interface

### Inputs

- **Query:** one unsigned 32-bit integer, with representable values from 0 through 4,294,967,295.
- **Output destination:** a pointer to storage for one 32-bit signed integer. On normal completion, the function writes a value from 0 through 15 to that storage.

The output destination’s existing value is not used by the function’s own logic. It need not contain an initialized integer, provided the destination is valid for the eventual write.

### Direct return

The function returns a 32-bit zero after writing the result. The evidence does not establish a distinct error return, an exception-to-status conversion, or a result-bearing alternative return.

### Threshold representation

F-af09788000fd is invoked without explicit arguments. Its result is interpreted as the base address of a threshold sequence with this layout:

- Exactly fifteen candidate positions, numbered 0 through 14.
- One unsigned 16-bit value per position.
- A two-byte stride between consecutive positions.
- Position zero at the returned base address.
- No header, count field, terminator, or per-entry metadata used by this function.

The supplied representation performs native unsigned 16-bit memory reads. It does not establish a portable byte order or an external serialization format.

### Preconditions for normal completion

The dependency must return an address suitable for every threshold read actually reached. The output destination must be writable for one 32-bit integer when the final write occurs. Alignment, address validity, and platform access rules must permit those operations.

The function performs no explicit validation of these conditions. A caller requiring normal completion for every possible query should provide a readable fifteen-entry threshold region. For a particular query that stops early, later entries are not read by this function.

## Behavior

### Dependency invocation precedes threshold inspection

The function calls F-af09788000fd once before reading any threshold. No explicit arguments are passed.

The dependency’s effects, if any, occur before the caller-visible result write performed by this function. The evidence does not establish that the dependency is pure, that it leaves global state unchanged, or that its returned storage is independent of the output destination.

### Ordered threshold search

The search begins at position zero. Each visited position contributes one unsigned 16-bit threshold read, in increasing position order.

For each visited position:

- If the unsigned 32-bit query is strictly less than the threshold, that position is selected and the search stops.
- Otherwise, the search advances to the next position.
- After a non-stopping comparison at position fourteen, the selected result is fifteen.

Equality does not stop the search. A threshold equal to the query is passed over, just like a threshold smaller than the query.

At least one threshold is read on every normal execution. At most fifteen thresholds are read. A result below fifteen requires a stopping read at that result’s position, so the number of threshold reads is one greater than the result. A result of fifteen requires all fifteen reads.

Position fifteen is never read. It is a valid output value representing exhaustion of the candidate positions, not an additional table entry or an error indicator.

### Comparison widths and arithmetic

The query remains an unsigned 32-bit value during comparison. Each threshold contributes an unsigned value from 0 through 65,535. There is no query truncation to sixteen bits and no signed interpretation of threshold values.

Consequently, a query of 65,535 or greater cannot be strictly less than any threshold. If all required accesses complete normally, every such query produces fifteen.

The search position ranges only from 0 through 15. Threshold offsets range from zero through twenty-eight bytes, in increments of two. These bounded position and offset calculations do not themselves overflow a 32-bit signed integer. That does not establish that an arbitrary returned base address can safely support the resulting accesses.

### Result publication

After the search finishes, the selected position is written once through the output destination as a 32-bit signed integer. The function then returns 32-bit zero.

There is no intermediate result publication by this function. In particular, it does not initialize the output destination before calling the dependency or before beginning the scan.

If the output destination overlaps threshold storage, the function’s own result write occurs only after its final threshold read. It therefore cannot change a threshold that this invocation subsequently reads: this invocation has no subsequent threshold reads. Whether the overlap is valid for both access types is a separate platform and storage-validity precondition.

## Acceptance examples

These examples are conditional specifications, not observed executions. Each assumes the dependency returns the stated readable thresholds, values remain stable during the scan, the output destination is valid, and execution completes normally.

### First position selected

If the first threshold is 10 and the query is 9, the output becomes 0 and the direct return is zero. Only position zero is read; later thresholds do not affect this result.

### Equality advances

If the first thresholds are 10, 20, and 30, and the query is 20, the output becomes 2. Positions zero and one do not stop the search; position two does. Positions three through fourteen are not read.

### Duplicate thresholds

If the first thresholds are 5, 5, and 8, and the query is 5, the output becomes 2. Equal values do not form a stopping boundary.

### Last position selected

If positions zero through thirteen contain values no greater than 100, position fourteen contains 101, and the query is 100, the output becomes 14. All fifteen thresholds are read.

### Exhaustion

If every threshold is at most 100 and the query is 100, the output becomes 15. There is no read beyond position fourteen, and the direct return remains zero.

### Maximum threshold boundary

For a query of 65,535, the output becomes 15 regardless of the fifteen unsigned 16-bit threshold values. The same holds for 65,536 and 4,294,967,295. These larger query values are not narrowed to sixteen bits.

### Unordered thresholds

If the first thresholds are 8, 2, and 9, and the query is 5, the output becomes 0. The function stops at 8 without inspecting 2 or 9. It does not count qualifying values across the whole sequence.

### Zero-valued thresholds

For a query of zero, an initial threshold of zero is passed over. If the next threshold is one, the result is 1. If all fifteen thresholds are zero, the result is 15.
