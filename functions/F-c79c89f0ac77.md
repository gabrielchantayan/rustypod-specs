# F-c79c89f0ac77

## Purpose

The supplied static representation describes a state-mutating routine that interleaves unresolved calls with byte and 32-bit memory accesses. Its visible actions include storing the second and third arguments, transforming dependency results into addresses and values, updating indirectly selected byte locations, and passing derived values to further dependencies.

A higher-level purpose—such as allocation, object construction, registration, or serialization—is not established. None of those interpretations is part of this contract.

**Evidence status:** the behavior below is conditional on the supplied representation accurately describing the executable path. ## Side effects

### Memory and layout

The visible accesses use offsets `1`, `7`, `0x0d`, `0x11`, `0x14`, `0x24`, `0x34`, and `0x74` from several unrelated computed bases.

These do **not** establish a single structure layout. The same offset can belong to different address domains, and computed regions can alias.

Particularly significant effects are:

- Explicit byte writes to absolute addresses `0x0d` and `0x11`.
- Byte-selected stores whose addresses range from `0x11` through `0x110`.
- Selector-based addressing derived from a 10-bit quantity.
- Word stores through dependency-returned values.
- Fresh memory reads after calls that may mutate their source locations.

The writes are ordered, not transactional. No rollback is visible. If execution stops at an intermediate call or access, earlier side effects may already have occurred.

## Acceptance examples

These are conditional review examples, not executed tests.

1. **Full-width second-argument storage.**  
   If the initial index is three and the relevant address is writable, the first word store writes the complete second argument at address `0x20`, before F-d006.

2. **Byte truncation without truncating the later word store.**  
   If the third argument is `0x123456ab`, its stores at the sixteenfold index plus `0x0d` write `0xab`. Its store at the masked base plus `0x14` writes `0x123456ab`.

3. **Maximum selector.**  
   If the record seed’s low 27 bits are all ones, the selector is `0x3ff`. The selector-plus-seven byte store therefore targets `0x406`. The earlier selector-derived byte value is `0xff`.

4. **Dependencies can change indirect destinations.**  
   If the first record-base-plus-one read yields two and the later read yields nine, the selector byte is stored at `0x13`, while the later zero is stored at `0x1a`. Reusing the first read would violate the visible sequence.

5. **Low-address stores remain separate.**  
   If the saved byte is `0x7f`, absolute address `0x0d` first receives `0x7f` and later receives `0xc0`, with calls between them. Retaining only the final value would lose observable behavior.

6. **Repeated final clears use fresh reads.**  
   If the two final indirect reads yield four and five, the zero stores target `0x15` and `0x16`, respectively. Equality of the read addresses does not guarantee equality of their contents.

7. **No guaranteed completion.**  
   If a dependency does not return, no later phase is required to occur. Even if all calls return and all accesses succeed, the supplied representation does not establish normal return.
