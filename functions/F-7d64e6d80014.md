# F-7d64e6d80014

## Purpose

F-7d64e6d80014 conditionally obtains two descriptor references, stores their results in a destination object, and, when a primary descriptor is present, selects a name and invokes three dependencies with descriptor-derived values and destination-relative addresses.

The established behavior is the sequence of reads, writes, branches, and dependency invocations described below. The supplied body does **not** establish that the final three dependencies successfully construct, transfer, or configure anything. Those interpretations require unavailable dependency implementations.

The selected names suggest font-related intent. That is an inference, not an additional behavioral guarantee. This contract is based on static evidence only; no runtime tests have been performed.

## Behavior

### 1. Setup and acquisition-selector capture

The function first calls F-8157a180d901 with the integer argument `4`. Its result is unused.

It then calls F-c623e5784aa3 without visible arguments. After that call returns, the function reads a 32-bit external value, designated **acquisition selector**, and then writes the result of F-c623e5784aa3 to destination offset `0xC0`.

This ordering matters: the acquisition-selector read follows both setup calls and precedes the destination write. The acquisition selector is captured for the acquisition stage rather than reloaded between the two possible acquisition calls.

Neither setup result is checked for failure.

### 2. Conditional descriptor acquisition

Primary acquisition occurs only when the primary acquisition input is nonzero:

- If the lookup context is zero, F-8967e4fb3bba receives the captured acquisition selector followed by the primary acquisition input.
- If the lookup context is nonzero, F-5710a8628cba receives the lookup context followed by the captured acquisition selector. The primary acquisition input serves only as an enabling condition on this branch.

The returned 32-bit value is stored at destination offset `0x1C4`, including when it is zero.

Secondary acquisition follows and is independently enabled by a nonzero secondary acquisition input:

- With zero lookup context, F-8967e4fb3bba receives the captured acquisition selector followed by the secondary acquisition input.
- With nonzero lookup context, F-5710a8628cba receives the lookup context followed by the captured acquisition selector. The secondary acquisition input is not forwarded.

Its result is stored at destination offset `0x1C8`, including when zero.

A disabled acquisition skips its call and direct field write; it does not clear the corresponding field. Thus an existing primary reference can drive subsequent processing even when primary acquisition is disabled.

These are direct effects of this function, not guarantees that the dependencies leave other destination fields or shared state unchanged.

### 3. Primary-reference check and temporary storage

After both acquisition opportunities, the function reads a second 32-bit external value, designated **name selector**, and retains it. It then reads the primary reference from destination offset `0x1C4`.

If that reference is zero, the function returns immediately. The name-selector read and any enabled secondary acquisition therefore occur even on this early-return path.

For a nonzero primary reference, the function retains that descriptor address and forms destination-relative addresses for `0xC4` and `0x1CC`. It reads the descriptor identifier at offset `0x00`, then initializes two adjacent address-sized locations in temporary storage:

1. The embedded destination address at `0xC4`.
2. The destination byte address at `0x1CC`.

The address of the first temporary location is later passed to F-59c1430f85c2 and F-8e04864cbbaa. Each initialized entry is 32 bits in the supplied representation; the dependencies’ interpretation and access extent are unknown.

The primary descriptor address is retained. Later writes to destination field `0x1C4`, including dependency-driven writes, do not cause this function to reload that field.

### 4. Identifier-to-name selection

Three unavailable external comparison values are designated **K1**, **K2**, and **K3**. Their numeric values and ordering must not be assumed.

Equality comparisons use the 32-bit identifier value. Ordering comparisons interpret the identifier and comparison values as signed 32-bit integers, except for the expressly unsigned test below.

Selection follows this precedence:

1. Equality with K1 selects **Osaka**.
2. Otherwise, an identifier signed-greater than K1 enters the upper table.
3. Otherwise, equality with K2 selects **AppleGothic**.
4. Otherwise, an identifier signed-greater than K2 enters the middle table.
5. Otherwise, equality with K3 selects an externally stored name of unavailable contents.
6. Otherwise, an identifier signed-less than K3 selects that same external name only when its unsigned value is greater than `0xFFFFFFFD`.
7. On the remaining signed-greater-than-K3 branch, `0x80B5` selects **Charcoal**, and `0x80B6` selects **Chicago**.
8. Other cases enter dynamic name resolution.

The unsigned test in step 6 admits only `0xFFFFFFFE` and `0xFFFFFFFF`, and only when earlier branch conditions permit reaching that test. It is not a general rule for all negative identifiers.

### 5. Dynamic name resolution

Dynamic resolution proceeds through these ordered fallbacks:

1. Read the current external name selector and pass it as the single visible argument to F-8967e4fb3bba.
2. If that result is nonzero, use it as the selected name.
3. Otherwise, call F-9d0ecc5f6adf without visible arguments.
4. After that call returns, reread the identifier at the retained descriptor address. Call F-5710a8628cba with the result of F-9d0ecc5f6adf, the earlier retained name selector, and this newly read identifier.
5. If that result is zero, read destination offset `0x38` and call F-5710a8628cba with that field followed by the retained name selector.
6. Use the resulting value, including zero, as the selected name.

The first fallback uses a fresh external selector read. The later fallbacks use the selector retained before the primary-reference check. These values may differ after intervening dependency activity.

Likewise, the identifier supplied to the three-argument fallback can differ from the initial identifier. A changed identifier is not subjected to the selection tree again.

### 6. Final reads, byte write, and ordered dependency calls

After selecting a name, the function reads the 32-bit descriptor value at `0x04`.

If the complete 32-bit value is zero, it substitutes `6`. The value forwarded later is the selected value masked with `0xFFFF`. Defaulting therefore precedes narrowing: a nonzero value with zero low 16 bits forwards zero, not `6`.

Next, the function reads the byte at descriptor offset `0x0D` and writes it to destination offset `0x1CC`.

After that write, it reads the 32-bit descriptor word at `0x0C` for conversion to a character-sized argument. The body does not establish the target’s character signedness or its exact argument-promotion rules.

It then invokes, in order:

1. **F-59c1430f85c2**, with the temporary-storage address, selected name, masked size-like value, and character-sized conversion.
2. **F-8e04864cbbaa**, with the retained embedded destination address and the same temporary-storage address.
3. **F-ccb5d9751852**, with the retained embedded destination address and the retained descriptor address plus `0x08`.

This sequence establishes arguments and invocation order only. No explicit destruction, rollback, or recovery follows them.

## Side effects

The function’s direct destination writes are:

- A 32-bit write at `0xC0` on every path reaching that instruction.
- A 32-bit write at `0x1C4` when primary acquisition is enabled and returns normally.
- A 32-bit write at `0x1C8` when secondary acquisition is enabled and returns normally.
- A byte write at `0x1CC` when primary processing reaches the final stage.

Temporary storage is initialized before name selection and passed by address to two dependencies. Its initial contents must not be assumed to survive either call unchanged.

Additional writes, allocations, releases, global-state changes, and retained references may occur inside dependencies; none is established by this body. In particular, passing an embedded destination address does not itself prove that the callee modifies it.

No transaction or synchronization mechanism is visible. Earlier writes are not explicitly undone when later processing is skipped. If a dependency fails to return normally, this function provides no visible recovery path.

Aliasing can affect later reads. For example, if destination offset `0x1CC` aliases descriptor storage at `0x0C`, the byte write occurs before the subsequent word read. No non-aliasing guarantee is established.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless specified otherwise, assume valid storage, normally returning dependencies, and no unmentioned mutation.

1. **Both acquisitions disabled; primary field zero.**  
   Both setup calls occur. The acquisition selector is read and `0xC0` is written. Neither descriptor field is directly replaced. The name selector and primary field are read, then processing returns without the final three dependency calls.

2. **Primary acquisition disabled; existing descriptor nonzero.**  
   The existing reference at `0x1C4` is processed. Disabling acquisition does not disable name selection or the final call sequence.

3. **Nonzero lookup context; both acquisitions enabled.**  
   F-5710a8628cba receives the same visible argument pair twice: lookup context and captured acquisition selector. Primary acquisition precedes secondary acquisition. Their results need not be equal.

4. **Primary acquisition returns zero; secondary remains enabled.**  
   Zero is stored at `0x1C4`. Secondary acquisition and its field write still occur before the primary-reference early return, provided no dependency changes the primary field again.

5. **Reachable explicit-name entry.**  
   If identifier `0x80BE` reaches the upper table, Helvetica is selected without dynamic resolution. Matching that identifier alone does not establish table reachability without K1.

6. **Defaulting before masking.**  
   Descriptor size-like values of zero, `0x00010000`, `0x00010007`, and `0xFFFFFFFF` forward `6`, `0`, `7`, and `65535`, respectively.

7. **All name fallbacks return zero.**  
   F-59c1430f85c2 is still called with a zero name argument. The body does not reject it or establish whether the dependency accepts it.

8. **Selector changes during acquisition.**  
   A dependency changing external acquisition-selector storage does not change the selector already captured for the remaining acquisition. A later name-selector read still observes its own then-current storage value.

9. **Descriptor changes during fallback.**  
   If F-9d0ecc5f6adf changes the retained descriptor’s identifier, the three-argument fallback receives that changed value. Initial name-selection branching is not repeated.

10. **Final ordering without assumed effects.**  
    The destination byte write precedes F-59c1430f85c2. F-8e04864cbbaa follows, then F-ccb5d9751852. Acceptance requires these arguments and this order, not successful construction, transfer, or configuration.
