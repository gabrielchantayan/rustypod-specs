# F-63f9fc38d281

## Purpose

F-63f9fc38d281 conditionally updates eight-byte records using a lookup result and shared tracking state. When a descriptor’s enable bit is set and lookup succeeds, it either selects a record through an insertion-related operation for a changed key or uses the existing shared selection. It then increments the selected record’s second 32-bit word.

An optional entry check can reject processing. If that check permits processing, the function resets the shared key and index before examining the descriptor’s enable bit.

The 64-bit return value has two fields:

- **Bits 0–31:** zero when the optional entry check rejects; one on every other normal return.
- **Bits 32–63:** the final value of a 32-bit local payload, initially supplied by argument two and explicitly replaced on the changed-key path.

The low field is not a general success indicator: disabled processing and unsuccessful lookup both return one.

“Record,” “counter,” “key,” and “insertion” describe observed access patterns or inferred roles. Their application-level meanings are not established.

## Behavior

### Entry and optional rejection

The function first captures the shared-state base and initializes the payload and companion locals from arguments two and three.

When the entry-check selector is nonzero:

1. The check seed is assigned to the scratch local.
2. F-8180d7378e16 is called with the sequence object address, at context offset `0xEE0`.
3. A nonzero result causes an immediate return with low field zero.
4. A zero result is followed by a write of `0xFFFFFFFF` to the shared key, then a write of zero to the shared index.

The scratch assignment does not establish that the entry dependency receives the seed: only the sequence object address is an explicit argument to that call.

On rejection, no explicit descriptor access or shared reset follows the call. Dependency side effects are not excluded. The payload local still contains the initial payload under the visible accesses on this path; its address has not been explicitly passed out.

When the selector is zero, the entry call and both reset writes are skipped.

### Enable-bit decision

After the optional entry phase, the function reads the descriptor pointer from the holder and tests bit zero of the descriptor’s first byte.

If that bit is clear, the function returns with low field one. It performs no lookup or explicit record-counter access.

If the bit is set, lookup follows. Other bits in the byte do not affect this branch.

### Lookup

The scratch local is assigned zero. F-70c1bc95b9e0 then receives the lookup input and the scratch address.

- A nonzero result bypasses key comparison, insertion handling, and counter increment.
- A zero result permits the current scratch value to be used as the lookup key.

Both outcomes normally return low field one.

If the dependency returns zero without changing scratch, the key used is zero. No stronger output guarantee is visible.

The shared key is read after lookup returns. The comparison therefore uses the then-current shared field, not a value saved before the dependency call. The dependency is not assumed to preserve that field or other global state.

### Successful lookup with an unchanged key

If the lookup key equals the shared key, neither insertion dependency is called. Processing proceeds directly to the common counter increment.

The function reads the sequence base and shared selected index to locate a 32-bit counter at the sequence base plus eight times the index plus four bytes.

This path does not validate the selected index or establish that the corresponding record exists. It also does not explicitly replace the payload or companion locals after their initialization.

### Successful lookup with a changed key

If the keys differ, the following ordered actions are visible:

1. Store the lookup key in the shared key field.
2. Assign zero to the companion local.
3. Read the descriptor pointer again from the holder.
4. Load the descriptor word at offset `0x20` into the payload local.
5. Read the current insertion address.
6. Compare that address with the boundary.

The second descriptor-pointer read occurs after lookup and the shared-key write. Consequently, the enable byte and descriptor payload need not come from the same descriptor if intervening effects alter the holder.

The companion assignment does not establish a zero second word at the payload address plus four. The locals’ relative layout is unresolved.

The address comparison selects one dependency:

- **Equal addresses:** F-7226c5f9cc42 receives the sequence object address, the insertion address, and the payload local’s address. No explicit insertion-field advance precedes this call.
- **Unequal addresses:** the insertion field is first assigned the original insertion address plus eight. F-d0393e5b7842 then receives the sequence object address, the original insertion address, and the payload local’s address.

The unequal branch tests only inequality. It does not establish that the insertion address is below the boundary, aligned, or followed by eight writable bytes.

The selected dependency’s return value is not explicitly inspected. Its actual reading, copying, mutation, retention, allocation, or relocation behavior is unknown.

After that dependency returns:

1. F-8180d7378e16 is called with the sequence object address.
2. Its result minus one is stored in the shared index.
3. The sequence base is read, and the counter addressed using that same derived index is assigned zero.

For this zeroing operation, the index comes from the dependency result rather than a fresh read of the shared index. If the shared-index write affects aliased storage, that distinction can matter.

The common increment follows the zeroing operation.

### Common counter increment

Every lookup returning zero reaches one explicit counter increment, regardless of whether the key changed.

The function obtains the sequence base and shared index afresh, calculates the counter address, reads its 32-bit value, adds one, and writes the result to that address. The supplied expression does not establish a relative evaluation order between the base read and index read; both supply this address calculation.

On the changed-key path, these reads follow the zeroing write. The zeroed counter and incremented counter can therefore differ if aliasing or intervening effects change the base or shared index.

With valid, stable, nonaliasing structures and representable arithmetic, the changed-key path zeroes the selected counter and then makes it one.

### Final return

Every non-rejection normal return has low field one. The high field is taken from the payload local when the return value is formed.

Outside the changed-key path, no explicit assignment replaces the initial payload. On the changed-key path, the descriptor load supplies an intermediate value, not an immutable final result.

The insertion dependency receives the payload address and may modify it. A later dependency could also modify it through a retained pointer made available by dependency behavior. Dependency-established aliasing could make a later explicit counter write affect the payload.

A concrete high-field expectation therefore requires that the expected value survive until return-value formation, not merely until the insertion dependency returns.
