# F-3b7d63490d61

## Purpose

F-3b7d63490d61 dispatches a record through an ordered sequence of indirectly selected handlers associated with an object. It returns the first nonzero handler result, or zero when every handler actually invoked returns zero.

The established behavior consists of three stages:

1. An optional preliminary handler for record type `0x12`.
2. One mandatory main handler, selected using the record type and, conditionally, a nested discriminator.
3. An optional final handler for record type `0x0F` whose associated value matches an object field.

The routine re-reads relevant object and record state after callbacks. Consequently, handler mutations can change later dispatch decisions. It does not implement dispatch from a single immutable snapshot.

Describing the inputs as an “object” and a “record,” and zero as “not handled,” is inferred intent. The established contract is indirect invocation, conditional continuation, and propagation of nonzero results; the domain-specific meaning of those results is unknown.

## Interface

### Inputs

The function receives two inputs:

- **Object address:** identifies storage containing a dispatch-table address and a comparison field.
- **Record address:** identifies storage containing a type field and a conditionally interpreted field.

Every handler invoked by this function receives these same two input addresses, in object-then-record order. The routine does not substitute the nested address or the object’s comparison field as an argument.

### Width and representation

The supplied static representation uses 32-bit integer values and represents addresses through 32-bit quantities. The following layout therefore describes the represented 32-bit model:

| Storage | Byte offset | Width | Use |
|---|---:|---:|---|
| Object | `0x00` | 32 bits | Dispatch-table address |
| Object | `0x50` | 32 bits | Comparison value for the final-stage condition |
| Record | `0x04` | 32 bits | Type discriminator |
| Record | `0x08` | 32 bits | Nested address or comparison value, depending on type |
| Nested storage | `0x04` | 32 bits | Secondary discriminator for main-handler selection |

No field at record offset `0x00` is directly inspected.

The dispatch table contains callable entries at these byte offsets:

| Dispatch-table offset | Dependency label | Role |
|---:|---|---|
| `0x124` | F-D1 | Preliminary handler |
| `0x10C` | F-D2 | Special main handler |
| `0x110` | F-D3 | Ordinary main handler |

F-D1 through F-D4 are opaque labels for unresolved callable targets, not established identities of distinct implementations. Different entries may resolve to the same implementation.

The exact platform ABI, alignment requirements, and callable-entry representation are not independently established. The offsets above must not be silently scaled for a different pointer width.

### Output

The output is a 32-bit integer:

- A nonzero result from any invoked handler is returned unchanged and immediately.
- Otherwise, the result is zero.

No result is converted to a Boolean or normalized to a fixed success value. Negative nonzero results also cause immediate return. The routine performs no sign-based classification.

### Preconditions

For normal completion, every memory access reached during execution must be valid, and each selected callable entry must be invocable under the applicable ABI.

Required validity is path-dependent:

- Reading the record type is always required.
- Reading record offset `0x08` as a nested address, and reading that address at offset `0x04`, is required only when the main-stage type read equals `0x16`.
- Reading the object comparison field is required only when the final-stage type read equals `0x0F`.
- The object’s dispatch-table address and a selected entry must be readable whenever a handler is about to be invoked.

The function performs no explicit null, bounds, lifetime, table-size, or callable-target checks.

## Behavior

### 1. Preliminary dispatch

The routine first reads the 32-bit type at record offset `0x04`.

If this value is `0x12`, it resolves F-D1 using the object’s dispatch-table address and the entry at table offset `0x124`. It invokes that target with the original object and record addresses.

- A nonzero result ends the function immediately with that exact result.
- A zero result allows processing to continue.

If the first type read is not `0x12`, F-D1 is not resolved or invoked.

### 2. Main-handler selection

After the preliminary stage has either been skipped or returned zero, the routine reads the record type again. It does not reuse the first type read.

If this new type is `0x16`, the routine:

- Reads the 32-bit quantity at record offset `0x08` as a nested address.
- Reads the 32-bit discriminator at nested offset `0x04`.
- Selects F-D2 only if that discriminator equals `0x2A`.

For every other main-stage case, it selects F-D3. This includes both:

- A record type other than `0x16`.
- A record type of `0x16` with a nested discriminator other than `0x2A`.

When the main-stage type is not `0x16`, the routine does not read record offset `0x08` or dereference nested storage for this selection.

After deciding which entry to use, the routine reads the object’s dispatch-table address and obtains the selected callable entry: offset `0x10C` for F-D2 or `0x110` for F-D3.

It invokes exactly one of these main-handler entries, passing the original object and record addresses.

- A nonzero result is returned immediately, unchanged.
- A zero result allows the final stage to run.

Subject to valid accesses and callbacks returning normally, a main handler is always invoked unless F-D1 has already returned nonzero.

### 3. Final matching-record dispatch

After the main handler returns zero, the routine reads the record type again.

If the type is not `0x0F`, it returns zero without reading the final-stage comparison fields.

If the type is `0x0F`, it reads:

1. The 32-bit value at record offset `0x08`.
2. The 32-bit value at object offset `0x50`.

It compares these values for equality. Their signed interpretation does not change an equality comparison between equal-width values.

If they differ, the function returns zero.

If they match, the routine resolves F-D4 from the object’s current dispatch table at offset `0x0E0` and invokes it with the original object and record addresses.

- A nonzero result is returned unchanged.
- A zero result produces a final return value of zero.

The final-stage type test and comparison are performed only once. Mutations made by F-D4 do not cause dispatch to restart.

### Read ordering and mutable state

The directly expressed order is:

- Initial record-type read.
- Optional F-D1 resolution and invocation.
- Fresh main-stage record-type read.
- Conditional nested-address and nested-discriminator reads.
- Main-handler resolution and invocation.
- Fresh final-stage record-type read.
- Conditional record-value read, followed by object comparison-field read.
- Conditional F-D4 resolution and invocation.

Each handler resolution reads the dispatch-table address from the object again. There is no single table snapshot held across all stages.

Therefore:

- A zero-returning F-D1 can change which main handler is selected.
- A zero-returning main handler can change whether the final handler is eligible.
- A callback can replace the object’s dispatch-table address, affecting later resolutions.
- Changes made after a stage’s selection reads do not cause that stage to repeat its selection.

This describes the accesses expressed in the supplied static representation. It does not establish volatile-memory semantics, synchronization, atomicity, or a physical hardware access trace.
