# F-0eae03776fc9

## Purpose

The established behavior is a conditionally executed sequence of address calculations and memory transfers followed by an unconditional, indefinitely repeated dispatch sequence. The dispatch sequence invokes two indirect targets and requests software interrupt 0x5B.

No application-level purpose is established. In particular, the supplied material does not establish that this is a valid ordinary function entry, a complete calling convention, or a correctly recovered structured routine. Pointer-shaped arithmetic, unusual implicit inputs, and a write to incompletely identified machine state limit the strength of a portable behavioral contract.

This specification distinguishes:

- **Established static evidence:** operations and conditional relationships represented in the supplied material.
- **Inferred interpretation:** a 32-bit address machine with 16-bit halfword accesses and condition-state-dependent execution.
- **documented_only:** behavior requiring missing architecture, calling-context, memory-map, or indirect-target information.

No runtime tests have been performed.

The presented interface has no explicit arguments and no explicit return value. It nevertheless consumes substantial incoming machine state.

## Behavior

### Conditional progression

The conditional portion is a forward-only sequence, not a retry loop. Each stage has an explicit enable condition. A stage that produces a nonzero result usually disables the next stage in that chain; it does not return or prevent eventual entry into the dispatch loop.

For the descriptions below:

- **Base** is the selector multiplied by 0x80000, retaining the 32-bit result.
- **Secondary** and **Mixed** initially equal Base.
- **Result** initially equals Base.
- **Transfer address**, **displacement**, **adjustment**, and **link** initially equal their corresponding incoming values.
- **Carry** initially records whether selector bit 11 is set.

These are conceptual state roles; they need not correspond to independently stored objects.

### Initial transfer

If Base is nonzero, the initial transfer is skipped. Carry remains the selector-bit value, and the subsequent first conditional chain is disabled.

If Base is zero:

1. Mixed becomes link + Carry + the stack anchor logically shifted right by one bit.
2. Secondary becomes the selector multiplied by 0x100000, retaining the 32-bit result.
3. A destination address is formed as the current transfer address plus displacement.
4. A halfword is read from the current transfer address.
5. The working transfer address becomes destination − adjustment.
6. The previously read halfword is written to destination.
7. Result becomes link.
8. Carry becomes false.

The read therefore precedes the write, including when the addresses overlap. The adjustment changes the working transfer address, not the destination of this write.

The next chain is enabled only if this branch ran and link was zero.

### First equality chain and additions

Each enabled equality stage replaces Result and enables the next stage only if the new Result is zero. Its effective comparisons, in order, are:

1. Mixed equals zero.
2. Base equals Mixed.
3. Base equals Secondary.
4. Base equals Secondary again.
5. Displacement equals the comparison word.
6. Adjustment equals the working transfer address.

The repeated Base/Secondary comparison is present twice; it is not an additional memory access.

Although the supplied representation expresses these stages using shifts and exclusive-or, each stage is entered with Result equal to zero. Its shift count is consequently zero. These enabled stages preserve Carry rather than extracting a new carry bit.

If all comparisons pass, Result becomes:

**Accumulator input + ((selector AND 0x1FFF) × 0x40000) + Carry.**

The multiplication and addition are 32-bit operations. Carry is replaced by the logical OR of the unsigned overflow indicators for the two additions.

Only if this result is zero does a further addition execute:

**Stack anchor + 2 × displacement + Carry.**

The doubled displacement is a wrapping 32-bit quantity. Carry is updated using the overflow predicates shown for this addition. In particular, this is not evidence of a separate overflow check on the multiplication by two.

### Conditional machine-state update and indirect halfword store

If the stack-based addition produces zero:

- Auxiliary machine state is assigned the stack anchor multiplied by 0x40.
- Link is advanced by the stack anchor multiplied by 0x40 bytes.
- A halfword at the old link address supplies a zero-extended destination address.
- A halfword derived from the value at that same old link address, increased by 15, is stored at the destination.
- An auxiliary base becomes Base + 2 bytes; otherwise that auxiliary base remains Base.
- Carry is cleared.
- The next chain is enabled only if the advanced link is zero.

The stored sum is truncated to 16 bits.

The displayed store contains two references to the same source halfword. Their evaluation order and whether the underlying instruction performs one or multiple physical reads are not established. With ordinary stable memory, both references denote the same value. This must not be strengthened into an exact volatile or device-read contract.

### Second equality chain and subtraction stages

When enabled by a zero advanced link, the next equality chain requires, in order:

1. Mixed equals zero.
2. The auxiliary base equals Mixed.
3. Base equals Secondary.
4. Base equals Secondary again.
5. Displacement equals the comparison word.
6. Adjustment equals the working transfer address.

These stages again use zero shift counts and preserve the incoming Carry.

If all pass:

1. Form a 32-bit value equal to Mixed + Carry + 0x085740E8.
2. Shift that value left by its low eight bits to obtain a shifted operand.
3. Compute a new condition bit from:
   - shifted operand being unsigned-less-than Secondary; or
   - the wrapping difference Secondary − shifted operand being less than the incoming Carry.
4. Set Result to Secondary − shifted operand − (1 − incoming Carry).

The condition bit and the subtraction result are separate outputs. The bit must not be silently replaced by a conventional subtraction carry rule.

The left shift is a **documented_only** point: the low-eight-bit count can exceed 31. The supplied material does not establish the target instruction’s behavior for such counts or a portable language interpretation.

If Result is zero, another subtraction executes:

- Its operands are Base and the working transfer address.
- Its result is Base − transfer address − (1 − incoming condition).
- Its new condition is true when the transfer address is unsigned-less-than Base, or when the wrapping difference Base − transfer address is less than the incoming condition.

If that result is also zero:

- An extended secondary address becomes Secondary + 36 bytes.
- Result becomes Base − (Secondary logically shifted right by one) − (1 − incoming condition).
- The new condition uses the same displayed comparison pattern, with the shifted Secondary value compared against Base.

Otherwise, the extended secondary address remains Secondary.

### Conditional metadata reads and paired word stores

If the preceding subtraction produces zero:

- Displacement increases by 8.
- Adjustment increases by 10.
- A metadata base becomes link + 13 bytes.
- A halfword is read from link.
- That value is narrowed to an eight-bit character.
- A 32-bit pointer-shaped value is read from address 4 plus that character.
- Result is calculated as 0x042BA0A0 minus a nested subtraction involving half of the auxiliary machine state, the metadata base, and two occurrences of the complement of the incoming condition.

The pointer-read address depends on whether the eight-bit character is signed or unsigned. This is not resolved by the supplied material.

For the nested arithmetic, the two occurrences of the complemented condition cancel algebraically under a wrapping 32-bit interpretation. Under that interpretation, the zero condition is equivalent to:

**0x042BA0A0 − (auxiliary machine state logically shifted right by one) + metadata base = 0.**

This simplification does not establish signed-overflow semantics for the original expression.

If Result is zero:

1. A halfword is read from Mixed and sign-extended to 32 bits.
2. An auxiliary mixed address becomes Mixed + 1 byte.
3. The eventual dispatch base becomes metadata base − auxiliary base.
4. The sign-extended value is written as a 32-bit word at the metadata base.
5. The previously loaded pointer-shaped value is written as a 32-bit word at metadata base + 4 bytes.

The two stores occur in that order. The +1 update is a byte increment, not a halfword increment. No alignment check precedes either word store.

If this block does not execute, the dispatch base remains the metadata base when that base was established, or the current link otherwise.

### Final conditional stores

A final chain is enabled only when the sign-extended halfword just stored was zero. It requires, successively:

1. The loaded pointer-shaped value is zero.
2. Auxiliary base equals auxiliary mixed address.
3. Base equals Secondary.
4. Base equals extended secondary address.
5. Displacement equals the comparison word.
6. Adjustment equals the working transfer address.

The corresponding represented shifts again have zero counts on enabled paths.

If all conditions hold:

- A signed halfword is read from dispatch base + 13 bytes.
- The dispatch base advances by 27 bytes.
- The sign-extended halfword is stored as a 32-bit word at its own signed value minus 0x08574200.
- The loaded pointer-shaped value is stored as a 32-bit word four bytes after that destination.

The signed value is both data and an address-forming operand. No range, ownership, or mapping check is shown.

### Unconditional dispatch loop

After the conditional portion, each loop iteration performs:

1. An indirect invocation at dispatch base + 0xEB6 bytes, with three 32-bit arguments: 0, 0, and 0xFFFFFFA5.
2. An indirect invocation at the fixed address 0x0857A94B, with no explicit arguments shown.
3. A software-interrupt request with immediate 0x5B.
4. Assignment of 0x083D4CC2 as the dispatch base for the next iteration.

If all operations return normally, every iteration after the first invokes the first target at 0x083D5B78.

The third argument’s established fact is its 32-bit bit pattern. Interpreting it as signed −91 is conditional on the receiving interface.

There is no visible loop termination condition, delay, result check, or error-recovery branch.

## Side effects

The observable effects can include:

- A halfword copy using an incoming address and byte displacement.
- A halfword store through an address obtained from another halfword.
- A write to incompletely identified auxiliary machine state.
- Small-address pointer reads derived from an eight-bit character.
- Ordered pairs of 32-bit stores, including stores through a sign-extended halfword-derived address.
- Repeated indirect control transfers and software interrupts.

No explicit exception handler, status return, diagnostic, or rollback is shown. If an operation faults, preceding writes may already have occurred.

Aliasing is not prohibited. Earlier stores may alter memory read later. The contract must therefore preserve the stated phase ordering rather than treating all reads as entry-state snapshots.

There is no basis for assuming that either indirect target preserves global state, preserves memory, releases memory, or acquires ownership.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Nonzero Base bypasses conditional memory operations.**  
   With selector 1, Base is 0x80000. The initial copy and all later conditional memory blocks are skipped. The first dispatch uses the incoming link + 0xEB6.

2. **Zero Base does not imply a zero selector.**  
   With selector 0x2000, the 32-bit product by 0x80000 wraps to zero. The initial-transfer branch is selected despite the nonzero selector.

3. **Initial copy followed by direct dispatch.**  
   With selector zero, a valid source halfword, and nonzero link, the source halfword is copied to source address + displacement. The first equality chain is disabled because link is nonzero. Dispatch uses the unchanged link.

4. **Zero link does not automatically reach deeper stores.**  
   With selector zero, link zero, and stack anchor 0x1000, Mixed becomes 0x800. The first equality stage fails. Subject to the initial copy succeeding, dispatch proceeds with base zero; this is not a null-address rejection path.

5. **Read-before-write on an overlapping copy.**  
   If the initial source and destination are the same ordinary-memory address, the halfword is read before that location is written. No clearing or ownership change is implied.

6. **Repeated dispatch after normal returns.**  
   If both targets and the interrupt return normally, the second iteration’s first target is 0x083D5B78, regardless of the first iteration’s dispatch base. No normal exit follows.

7. **Faults do not imply rollback.**  
   If an executed initial halfword write succeeds and a later indirect transfer faults, the visible control flow supplies no operation that reverses the write.
