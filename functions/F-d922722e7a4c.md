# F-d922722e7a4c

## Purpose

F-d922722e7a4c coordinates a sequence of calls governed by a zero-terminated table, records a 16-bit input field into a 32-bit output field, conditionally invokes two additional dependencies, and finally passes a previously captured input value to another dependency.

The table determines whether another iteration occurs. Its nonzero entries are not passed to the dependency invoked by the loop. The same second input is supplied on every iteration.

An empty table and a zero result from any loop invocation select the same two-call branch. A nonempty table whose loop invocations all return nonzero bypasses that branch.

These are established control-flow properties. The semantic purpose of the table, the copied field, and the dependency calls is unknown. In particular, interpreting the final dependency as restoring state is inferred intent, not an established effect.

## Behavior

### Initial capture and field update

Before scanning the table, the function performs these observable operations in order:

1. Reads the global table base and retains that address for this invocation.
2. Reads the 32-bit value at offset `0x5c` of the second object and retains that value.
3. Reads the unsigned 16-bit value at offset `0x44` of the second object.
4. Writes that value, zero-extended to 32 bits, at offset `0x20` of the first object.

The copied value therefore lies between `0` and `65535`, inclusive. A source value with its high bit set remains positive in the 32-bit destination. For example, `0xffff` becomes `0x0000ffff`, not `0xffffffff`.

The destination write replaces the full 32-bit field. It is not a 16-bit update preserving the destination’s upper half.

The captured offset-`0x5c` value is obtained before this write. If the objects overlap and the write changes the storage from which that value was captured, the final dependency still receives the previously captured value, provided execution reaches that call.

### Table-controlled invocation sequence

Scanning begins at entry index zero. Before each possible invocation of F-663114c0fbf3, the function reads the current four-byte table entry and tests it against zero.

For a zero entry:

- F-663114c0fbf3 is not called for that entry.
- Scanning ends.

For a nonzero entry:

- F-663114c0fbf3 is called with the second object as its sole explicit argument.
- Its result is tested against zero.
- A zero result immediately leaves the loop and selects the conditional two-call branch.
- A nonzero result permits advancement to the next table index.

The entry’s nonzero value is not otherwise used by this function. In particular, it is not passed as an argument or used as a call target.

The function initially retains a loop-result value of zero. Consequently:

- If entry zero is already the terminator, the loop dependency is never called and the conditional branch is selected.
- If one or more calls occur and each returns nonzero, reaching a table terminator leaves a nonzero result and bypasses the conditional branch.
- If any call returns zero, the conditional branch is selected without inspecting the following table entry.

The table is read incrementally, not copied or counted in advance. A dependency can therefore affect later decisions if it changes entries that have not yet been read. Modifying the global table-base location does not itself redirect this invocation’s reads: the base was already captured. Modifying memory reachable through that captured base can affect later reads.
