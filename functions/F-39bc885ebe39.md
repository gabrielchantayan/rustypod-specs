# F-39bc885ebe39

## Purpose

F-39bc885ebe39 conditionally transfers the low bit of a source byte into bit 2 of a destination byte and reports whether its update path was selected.

The operation is gated by bit `0x100` in a source control word. When that gate is enabled, the update path is selected if either:

- The entire source byte differs from the Boolean value represented by destination bit 2.
- A separate force input is nonzero.

Selection produces two report values: `0x60` and `0x100`. These report selection of the update path, not necessarily a change in the destination byte.

The apparent intent is to synchronize a one-bit property while preserving the destination’s other bits. That intent is inferred. The established behavior compares the **full source byte**, although it transfers only that byte’s low bit.

## Behavior

### Gate and report defaults

Each invocation begins with prospective report values of zero.

The function reads the 32-bit source control word and tests bit `0x100`. Other control-word bits do not affect the decision.

If that bit is clear:

- The source data byte is not read by the decision logic.
- The destination byte is not read or modified by the decision logic.
- The force input does not cause an update.
- The prospective report values remain zero.

Optional report writes still occur after this gate is evaluated.

### Comparison when enabled

If source control bit `0x100` is set, the function reads:

- The unsigned, 8-bit source value at source offset `0x16`.
- The unsigned, 8-bit destination value at destination offset `0x14`.

The destination’s bit 2 is converted to the numeric value zero or one:

- Destination bit 2 clear: comparison value zero.
- Destination bit 2 set: comparison value one.

The source byte is compared against that value **without first being reduced to its low bit**.

Consequently:

- Source byte `0` matches a clear destination bit 2.
- Source byte `1` matches a set destination bit 2.
- Every source byte from `2` through `255` differs from both possible comparison values.

The update path is selected when this comparison differs or the force value is nonzero. The force input does not bypass the source control gate.

### Width-sensitive interpretation

The supplied shift expression operates through a 32-bit unsigned shift, a signed interpretation, an arithmetic right shift, and negation. Under the represented 32-bit semantics, its result is exactly zero or one according to destination bit 2.

In particular, it does not extract bit 0, compare the destination’s complete byte, or produce `0x04` as the comparison value.

The source byte is treated as an unsigned value from 0 through 255. Bytes with their high bit set are not interpreted as negative comparison values.

### Destination update

When the update path is selected:

- The prospective report-pair second word becomes `0x60`.
- The prospective standalone report word becomes `0x100`.
- The destination byte is updated so that bit 2 equals the low bit of the source byte.
- Every other destination bit is preserved from the destination byte read for this update.

Equivalently, the destination byte is masked with `0xFB`, then receives either `0x00` or `0x04` according to source bit 0.

The update expression contains fresh reads of the source and destination bytes. It is not specified as reusing the values read during comparison.

An update-path selection does not guarantee that the stored byte differs from its previous value. A forced update can rewrite the same value. A source byte greater than one can also cause a comparison mismatch even when its low bit already agrees with destination bit 2.

If the update path is not selected, there is no direct store to the destination byte.

### Output publication

After the gate, comparison, and any destination update have completed, the optional outputs are written in this order:

1. If the report-pair address is non-null, its first 32-bit word receives zero.
2. If that address is non-null, its second 32-bit word receives the selected report value: zero or `0x60`.
3. If the report-word address is non-null, its 32-bit word receives the selected report value: zero or `0x100`.

These are assignments, not bitwise additions to existing output values. Prior output contents are not read or preserved.

Both output addresses may be null. That suppresses reporting, not the destination operation.

## Side effects

The explicit memory effects are limited to:

- A 32-bit source control-word read.
- Conditional byte reads from the source and destination.
- A conditional byte write to the destination.
- Up to three 32-bit output writes.

There is no explicit allocation, deallocation, ownership transfer, external call, global-variable access, logging, or error reporting.

The function does not return a success indicator. The report masks distinguish update-path selection from nonselection; they are not evidence that a recoverable failure protocol exists.

### Ordering and repeated reads

The source control-word read precedes any conditional data-byte access. The destination update, when selected, precedes every output write. The output writes have the order specified above.

The supplied expression does not establish a relative evaluation order between the two operand reads used in the comparison. It likewise does not establish a relative order between the source-byte and destination-byte reads used to calculate the replacement byte. Neither pair should be contracted as source-first or destination-first.

The comparison reads and update reads are separate. Without a stability precondition, the value that triggers selection need not be the value whose low bit is transferred.

### Aliasing

No non-overlap check is present. Where overlapping addresses remain valid for the execution environment, output-store ordering determines the final contents.

For example, if both optional output addresses identify the same two-word buffer and the update path is selected, the stores leave:

- First word: `0x100`, because the final standalone report overwrites the earlier zero.
- Second word: `0x60`.

An output may also overlap source or destination storage. Such writes occur after the conditional destination operation and may overwrite its result or alter the source region. Therefore, “source is read-only” and “only destination bit 2 changes” are valid descriptions of the direct data operation, not unconditional guarantees about final memory under arbitrary output aliasing.

The function provides no transactional behavior or rollback. Invalid memory can interrupt execution after earlier stores have occurred.
