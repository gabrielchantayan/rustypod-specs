# F-a4714a07693f

## Purpose

F-a4714a07693f is a globally controlled, state-dispatched operation accepting one signed 32-bit value and returning one unsigned 32-bit value. Its visible operations include obtaining an object address, processing an object field, constructing and transferring temporary data, writing status bytes, copying or filling individual bytes, and passing five object fields to a dependency.

**Established static evidence:** These operations belong to separate dispatcher states. Some states contain an established sequence of calls and memory accesses, but the supplied global values do not establish a complete path from entry to return. Operations may be skipped or repeated; termination is not established.

**Inferred intent:** The object layout and call pattern suggest an update operation with result reporting and resource-related handling. Neither those meanings nor a successful high-level outcome are established.

The contract below preserves state-local ordering without assuming a conventional acquisition, processing, cleanup, and return sequence.

## Interface

### Input and result

The sole input is represented as a signed 32-bit integer. It is saved at entry and can subsequently participate in multiplication by a freshly read global word. That product becomes a working argument that may later be passed to F-5e11a17b9827.

The input is not directly dereferenced. No valid range, handle interpretation, special invalid value, or restriction on negative values is established.

The result is an unsigned 32-bit word. Its storage starts at zero. A dedicated state replaces it with the product of a working word and a freshly read global multiplier. Another state returns the stored result.

Consequently, conditional on reaching return:

- Without a preceding result assignment, the result is zero.
- With preceding assignments, the result is the last stored product.
- Zero is not established as failure.
- Nonzero is not established as success, an address, or an ownership-bearing value.

## Behavior

### Entry and global sampling

Entry initializes result storage, the two output slots, the object-address word, and the explicitly initialized arithmetic working words to zero. It reads the initial dispatcher seed once.

Each dispatch iteration then performs the following established sampling sequence:

1. Preserves the previous carried word.
2. Captures two arithmetic globals in separate working values.
3. Computes the state selector from the current dispatcher word and a freshly read dispatcher-offset global.
4. Reads a default next-dispatch word and a default next-carried word.
5. Executes the selected state, which may replace those defaults.

For clarity, the two captured arithmetic values are called the **first captured multiplier** and **second captured multiplier** below. These are descriptive roles, not additional storage or stable configuration values.

The initial seed is not reread at every iteration. The arithmetic captures, dispatcher offset, and defaults are reread at every iteration, including an iteration that selects return. An unrecognized state performs no state-specific operation and continues dispatch using the defaults.

Some states reuse the previous carried word; others replace it with a computed value, zero, or the default sampled for that iteration. Arithmetic states can also replace the dispatcher word using a zero test, pointer comparison, or sign-bit-derived selection. The carried word and dispatcher word are distinct state.

Capturing the two multipliers does not make all arithmetic within the state use those captures. Several states read the same global locations afresh. In particular:

- Constant-byte writing uses the second captured multiplier in arithmetic performed after its store.
- One byte-copy state uses the first captured multiplier after its store.
- Processing reads its arithmetic globals after F-85722d246d84 returns.
- Construction reads its multipliers after F-ed485a8933da returns.

Dependencies may change globals between these sampling points. No stability across calls or iterations is assumed. Where multiple global reads occur within one arithmetic expression, their relative evaluation order is not independently established.

### Acquisition and result assignment

One state multiplies the saved input by a freshly read global multiplier and saves the resulting working word. Other states can further change working words before acquisition.

The acquisition state calls F-5e11a17b9827 with the current working argument and a second argument of zero. It stores the returned word as the object address, tests it against zero, and selects one of two dispatcher alternatives.

This zero test establishes a branch distinction, not a proof that all object accesses are protected. The supplied globals do not establish that acquisition precedes every dereference or that a zero result leads directly to return.

A separate state multiplies a working unsigned word by a freshly read global multiplier, replaces that working word with the product, and stores the product as the eventual result. The multiplication has 32-bit unsigned-word behavior. Return occurs only if dispatch reaches the dedicated return state.

### Processing

The processing state:

1. Reads the address-bearing value at object offset +0xAC into the left comparison pointer.
2. Calls F-85722d246d84 with:
   - The first four-byte output-slot address.
   - The value just read from +0xAC.
   - The object-relative address +0x28.
   - The second four-byte output-slot address.
3. After the dependency returns, reads arithmetic globals and combines them with its returned word.
4. Uses the resulting working words and high-bit information to affect subsequent dispatch.

The arithmetic uses fresh global reads, not a promise of entry-to-dispatch snapshots. A global changed by F-85722d246d84 can therefore affect this post-call computation.

The output slots are not reset immediately before this call. Their entry values are zero, but a repeated processing call may receive slots containing earlier results.

No meaning such as length, count, allocation size, or success code is established for either output slot or the returned word.

### Individual byte transfers and constant writing

### Arithmetic and access preconditions

Unsigned 32-bit arithmetic wraps modulo \(2^{32}\). Logical shifts by 31 extract the high bit. Some branch computations instead convert a word to signed form and shift right by 31; interpreting that as sign propagation depends on the signed-shift model.

Some intermediate arithmetic is signed. Portable signed-overflow behavior is not established. Neither hidden loop bounds nor ordinary counter behavior can be recovered merely by treating every expression as unbounded integer arithmetic.

A memory-safe execution requires every reached access to have a valid address, adequate extent, appropriate alignment for four-byte fields, and a live underlying object. The visible zero tests and dispatcher structure do not independently establish those conditions.

## Acceptance examples

These are conditional static examples, not executed tests or complete input/output cases.

1. **Return without assignment.** If dispatch reaches return before any result-assignment state, the result is zero. That return iteration still performs its preceding dispatcher-global sampling.

2. **Zero acquisition result.** If F-5e11a17b9827 returns zero, the zero-result dispatcher alternative is selected. Immediate return and absence of later dereferences do not follow.

3. **Processing changes globals.** If F-85722d246d84 changes a global used by the processing state’s post-call arithmetic, that arithmetic reads the changed value rather than relying on the earlier dispatch capture.

4. **Construction changes multipliers.** If F-ed485a8933da changes either multiplier used for the next computed argument, construction reads those globals after the call. If all three construction dependencies return normally, the subsequent direct writes are +0x8C = 1, then +0x8D = 0.

5. **Captured multiplier remains relevant.** In the constant-writing state, the store occurs first; its following arithmetic uses the second captured multiplier from that iteration and a fresh read of another multiplier. In the second copy state, the post-store multiplication uses the first captured multiplier.

6. **Comparison before preparation.** If comparison executes before any assignment to either comparison pointer, both operands are null. If processing executes first, the left operand may instead be the value read from +0xAC while the right remains null. Neither case is a buffer-length check.

7. **Cleanup argument mutation.** If the first F-324d80067c36 call changes +0xA4, the second call receives the subsequently read value. If all five fields retain one equal value, the dependency receives that value five times.

8. **Saved destination is not active.** If preparation selects +0x78, cleanup-like handling later saves +0x8E, and a byte-write state executes before destination activation, the write still uses the previous active base, +0x78. No fixed index or resulting field overlap is implied.

9. **Uninitialized source content.** If preparation’s dependency leaves a subsequently selected source byte unspecified, the evidence does not establish the copied byte’s value.
