# F-1c05648c2dbf

## Purpose

The supplied representation establishes memory-access behavior, not an application-level purpose. It does not support identifying this operation as initialization, serialization, rendering, object linking, or any other domain operation.

This contract distinguishes:

- **Established static evidence:** accesses, widths, data dependencies, and sequencing visible in the supplied representation.

## Behavior

### Initial repeated mutation region

The opening region repeatedly updates four destinations:

| Destination | Width | Value |
|---|---:|---|
| First base + 0x11 | 1 byte | Second-base byte |
| Second base + 0x34 | 4 bytes | Secondary input on the first occurrence; doubled first base thereafter |
| Doubled first base + 0x54 | 4 bytes | Primary input |
| Second base + 0x19 | 1 byte | First-base byte |

Within each complete occurrence, the ordering follows the table from top to bottom. The final occurrence in this region stops after the four-byte write at second base + 0x34; it does not include the latter two writes.

The region is a fixed sequence in the supplied representation, not an input-controlled loop. Its repeated stores must not be reduced to final values when an observer can distinguish individual writes. The exact repetition count is **documented_only** in this contract.

There are no visible memory reads within this region. The written values derive from entry-state inputs. Overlap can alter the final memory image, but does not visibly replace those captured inputs.

For ordinary, nonoverlapping memory, second base + 0x34 ultimately contains the doubled first base rather than the secondary input. This does not make the first write unobservable.

### Initial snapshots and absolute-byte update

After the repeated region, the function captures:

1. A four-byte value from absolute location 0xA9.
2. A four-byte value from primary input + 0x74.

It then writes one byte at absolute location 0x3A. That byte is the low eight bits of twice the first-base byte plus 0x30. This is arithmetic on a truncated byte value; it is not evidence of decimal conversion, digit validation, or text formatting.

Next it captures, in order:

1. A four-byte value from third base + 0x14.
2. A four-byte value from first base + 0x04.

These snapshots remain the sources for later operations even if intervening writes change their original locations.

### Base-relative state mutation

The next group writes:

- The first-base byte to third base + 0x0D.
- The byte 0x6C to first base + 0x08.
- The second-base byte to first base + 0x0D, then first base + 0x09.
- The third base as a four-byte value to third base + 0x54.
- The low byte of the captured value from absolute location 0xA9 to absolute location 0x67.

A signed four-byte value is then read from third base + 0x44. The function copies the byte at absolute location 0x67 to absolute location 0x21 before writing the low byte of the newly read signed value to first base + 0x10.

The signed value is written as four bytes to second base + 0x54. A shifted version of that same captured value supplies a byte written to third base + 0x01. The shift count is the low eight bits of the first base.

The function next overwrites second base + 0x54 with the full first base. The preceding word write remains part of the observable sequence.

The precise signed-right-shift behavior is not established for all inputs. In particular, counts of 32 or greater and negative operands require target-specific interpretation. For nonnegative operands and counts from 0 through 31, the represented shift has its ordinary numerical meaning.

### Mixed-width overwrite and pointer acquisition

A four-byte value is read from first base + 0x40. The function then:

- Writes the earlier snapshot from first base + 0x04 to second base + 0x74.
- Writes the newly captured word to first base + 0x10.
- Writes the third base to second base + 0x44.
- Reads the byte at absolute location 0x67 and writes it to first base + 0x09.
- Writes the first-base byte to third base + 0x09.
- Writes the complete earlier snapshot from absolute location 0xA9 to first base + 0x44.

The word write at first base + 0x10 covers bytes at offsets 0x10 through 0x13. It therefore supersedes the earlier byte writes at offsets 0x10 and 0x11, subject to later aliasing effects.

A four-byte address-bearing value is then read from first base + 0x54. This contract calls it the **linked destination**.

After acquiring it, the function again reads absolute location 0x67 and writes that byte to first base + 0x09. This is a separate read, not necessarily reuse of the previous byte value.

### Linked-destination updates

The low byte of the snapshot from primary input + 0x74 is written to linked destination + 0x0D.

The earlier snapshot from third base + 0x14 is written as four bytes to third base + 0x54. Thus the earlier self-reference at that location is replaced on an ordinary nonoverlapping execution.

The function then captures a four-byte value from first base + 0x14. It subsequently writes:

- The low byte of the primary-input snapshot to third base + 0x11.
- The low byte of the linked destination to first base + 0x09.
- The complete linked destination to first base + 0x44.

Consequently, the word previously copied from absolute location 0xA9 to first base + 0x44 is not its final visible value under nonoverlapping conditions.

### Final pointer-derived accesses

The function reads an address-bearing signed word from third base + 0x04. This contract calls it the **terminal base**.

A two-byte value, numerically 0x0065, is written at the address obtained by doubling the terminal base. The representation uses signed arithmetic for this doubling; behavior outside the nonoverflowing range is **documented_only**.

A signed word is then captured from terminal base + 0x64. This contract calls it the **terminal link**.

The following operations occur before the indirect invocation:

- The low byte of the snapshot from first base + 0x14 is written to linked destination + 0x11.
- The four-byte value 100 is written to linked destination + 0x54.
- A four-byte value is captured from terminal base + 0x74.
- An address-bearing word is captured from third base + 0x64; this is the **final destination**.
- The terminal-base low byte is written to third base + 0x09.
- The terminal link is written as four bytes to final destination + 0x54.
- The final destination is written as four bytes at the address obtained by doubling the terminal link.

The last doubling also uses a signed interpretation. Signed overflow behavior is not established.

### Indirect invocation

After the final store, the unresolved indirect dependency is invoked with four arguments in this order:

1. The numeric constant 0x72.
2. The terminal link.
3. The snapshot originally captured from third base + 0x14.
4. The value captured from terminal base + 0x74.

No use of a returned value is visible. No subsequent memory operation is shown in this function.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

### Secondary input is transient

Assume valid, disjoint, ordinary writable locations and no external mutation. Let the secondary input differ from the doubled first base.

An observer of writes to second base + 0x34 must see the secondary input first and the doubled first base in subsequent writes. A final-memory-only observer sees the doubled first base after the repeated region.

### Byte truncation

Assume the first base has low byte 0xF0.

The value written to absolute location 0x3A is 0x10, because twice 0xF0 plus 0x30 is 0x210 and the destination is one byte. No rejection of the non-digit input is visible.

### Word replacement of earlier bytes

Assume no aliasing beyond overlapping offsets within the first-base region.

After the word from first base + 0x40 is written at first base + 0x10, the four bytes at offsets 0x10 through 0x13 reflect that captured word in the target byte order. The previous single-byte values at offsets 0x10 and 0x11 are no longer independently preserved.

### Snapshot survives destination mutation

Assume the word initially read from third base + 0x14 differs from the third base.

Third base + 0x54 first receives the third base and later receives the captured word. The third indirect-call argument is that same captured word, not a new read of either location.

### Safe shift case

Assume the first-base low byte is 4 and the signed word captured from third base + 0x44 is positive 0x1234.

The byte written to third base + 0x01 is 0x23. This example does not establish behavior for excessive shift counts or negative operands.

### Failure before dispatch

The indirect invocation is not established as occurring. Earlier stores have no visible rollback path. The platform’s exact fault mechanism remains unspecified.

### Final dependency arguments

Assume all accesses succeed, and the terminal link, saved third-base word, and captured terminal-base word are respectively 7, 0x11223344, and 0x55667788.

The final invocation receives 0x72, 7, 0x11223344, and 0x55667788 in that order. This says nothing about the dependency’s resulting side effects.
