# F-fa21c588278d

## Purpose

F-fa21c588278d conditionally constructs and publishes a sequence of dependency-produced 32-bit values into a selected slot of an object.

Processing is gated by an initial dependency result, a descriptor-to-object count comparison, and a selector restricted to 1 through 48 inclusive. When those gates pass, the function invokes a preparation dependency, obtains a destination, processes descriptor entries in increasing index order, and stores the destination address into the selected object slot.

The function’s return value does **not** distinguish successful publication from most forms of noncompletion. Every normally returning path after an initial zero result returns zero, including rejected inputs, destination-acquisition failure, and entry-processing failure.

This contract describes behavior established by the supplied static evidence. The application-level meanings of the descriptor, object, selector, and dependency-produced values remain unknown.

## Behavior

### Initial dependency and immediate return

The first action is a call to F-ccb28d079bbc with the context token, descriptor address, and auxiliary token, in that order.

If its result is nonzero, F-fa21c588278d returns that result unchanged. On this path, the supplied body performs no direct descriptor reads, object metadata reads, destination writes, or publication.

The initial dependency may itself have side effects. Its nonzero return does not establish that it left memory or global state unchanged.

If its result is zero, processing continues. Every subsequent normal return from this function is zero.

### Selector and metadata acquisition

After the initial zero result, the function:

1. Reads the descriptor’s 32-bit word at offset `0x00`.
2. Calls F-5f26c7ef61cd with that word.
3. Retains the dependency’s 32-bit result as an unsigned selector.
4. Obtains the comparison count:
   - For a zero object address, the count is zero and no object metadata is read.
   - For a nonzero object address, the function reads a 32-bit metadata address from object offset `0x40`, then reads a 16-bit unsigned count from metadata offset `0x2e`.

The metadata accesses occur after F-5f26c7ef61cd returns. Changes made by that dependency can therefore affect the metadata address and count subsequently observed.

For a nonzero object address, the metadata reads occur even if the selector is outside the accepted range. An invalid selector does not protect an invalid metadata address from being accessed.

### Eligibility

The function next reads the descriptor’s 32-bit count at offset `0x04`.

Further work occurs only if:

- That count equals the comparison count; and
- The unsigned selector is nonzero and less than `0x31`.

Thus the accepted selectors are exactly 1 through 48 inclusive. An all-ones 32-bit selector is rejected; it is not treated as a negative index.

If either condition fails, the function returns zero without invoking the preparation, destination-acquisition, entry-processing, or cleanup dependencies.

At this eligibility check, a matching descriptor count cannot exceed 65,535, because the object comparison count is either zero or a zero-extended 16-bit value. This limit does **not** establish a permanent bound on later loop iterations: the descriptor count is reread during processing.

### Preparation and destination acquisition

For an eligible request, the function calls:

- F-38564a73f0ac with the object address and retained selector.
- Then F-ec96abf5fded with the object address and the 32-bit constant `1`.

The result of F-38564a73f0ac is not used. No preservation or rollback of its effects is established.

If F-ec96abf5fded returns zero, processing stops and the function returns zero. There are no direct entry writes or final publication on this path. The supplied body does not call F-d4e440af2e49 for a zero destination.

If the destination is nonzero, entry processing begins.

### Entry processing

The entry index starts at zero. Before every iteration, the function rereads the descriptor count at offset `0x04` and compares the unsigned index against that current 32-bit count.

Consequently, the loop is not governed by a count snapshot from the eligibility check or destination acquisition. Mutations by dependencies, shared-memory writers, or overlapping destination writes can affect subsequent iteration decisions. The supplied evidence establishes no synchronization guarantees for concurrent access.

For each admitted index:

- The function reads the descriptor entry at byte offset `0x30 + 4 × index`.
- It calls F-f8ec0897aceb with the object address, the 32-bit constant `1`, the 32-bit constant `0`, and that entry value.
- If the result is nonzero, it writes that 32-bit result to destination offset `0x10 + 4 × index`.
- It then advances the index and reevaluates the descriptor count before any next entry.

Each successful entry write therefore occurs after its corresponding dependency call and before the next count read.

If F-f8ec0897aceb returns zero:

- No destination write is made for that failed entry.
- F-d4e440af2e49 is called with the destination.
- The function immediately returns zero.
- No final publication write is performed by this invocation.

Earlier successful entry writes have already occurred. The supplied body does not individually undo them, and the cleanup dependency’s treatment of the destination is unknown.

### Publication

When the loop terminates normally, the function writes the nonzero destination address to the 32-bit slot at:

**Object address + `0x3ac` + 4 × retained selector**

For accepted selectors, the slot offsets range from `0x3b0` through `0x46c`, inclusive.

The retained selector is the original result of F-5f26c7ef61cd. It is not recomputed after subsequent dependency calls. Object contents, however, are not restored to earlier values before publication.

The publication write is also performed when the loop processes zero entries. No final count comparison against metadata is made.

The function then returns zero.

## Side effects

Direct writes by F-fa21c588278d consist of:

- One 32-bit destination write for each successful entry-processing call.
- One 32-bit object-slot publication write after normal loop termination.

The supplied body does not initialize other destination fields, clear unused entries, check an existing publication-slot value, or release a previously stored slot value. The preparation dependency may affect that slot or related state, but its behavior is not established here.

Dependency side effects occur in the ordering described above. In particular:

- Initial dependency effects can precede every direct read.
- Selector-dependency effects can alter later descriptor and metadata observations.
- Preparation occurs before destination acquisition.
- Entry-processing effects occur before the corresponding destination write.
- Cleanup occurs only on a zero entry-processing result after a nonzero destination has been acquired.

The supplied evidence does not establish non-aliasing among the descriptor, object, metadata, and destination. If these regions overlap, a direct write may change a field read later. No extra snapshotting is present to prevent that interaction.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, they assume valid memory, normally returning dependencies, no relevant aliasing, and stable descriptor contents.

4. **Destination acquisition returns zero**

7. **Empty sequence**
