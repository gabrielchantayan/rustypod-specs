# F-b5a7190f43fd

## Purpose

On finding such a value, it invokes F-57e36fb68b0b and returns 1 if that invocation returns normally. Otherwise, it returns 0 without invoking the dependency.

The selection is controlled by a separate unsigned starting field. Only starting values 0 through 3 permit candidate inspection. Larger values produce a normal result of 0 without any candidate reads.

This is a search-and-dispatch contract, not a resource-acquisition guarantee. The evidence does not establish what the candidate values represent, what the dependency accomplishes, or whether any application-level operation succeeds. The function itself does not mark a candidate as consumed or persist its search progress.

## Behavior

### Selection and observation order

The starting field is observed before any candidate. Its value determines the entire candidate suffix for this invocation:

| Starting field | Permitted candidate observations |
|---:|---|
| 0 | Candidates 1, 2, 3, 4 |
| 1 | Candidates 2, 3, 4 |
| 2 | Candidates 3, 4 |
| 3 | Candidate 4 |
| 4 through 0xFFFFFFFF | None |

Within a permitted suffix, observations occur in increasing candidate order and stop at the first non-sentinel value. Candidates earlier than the suffix are not inspected. Candidates later than a qualifying candidate are not inspected.

This selection rule has several important boundaries:

- A starting value of 0 includes Candidate 1.
- A starting value of 1 excludes Candidate 1, regardless of its contents.
- A starting value of 3 permits exactly one candidate observation.
- An all-ones starting value is outside the accepted range; it does not select a position before Candidate 1.
- There is no wraparound search.
- The field at offset 0x110 is never treated as a fifth candidate.
- No direct field read occurs at offset 0xFC.

The starting field is not reread. Changes to it after its initial observation do not alter the selected suffix through any further direct read by this function.

### Match and exhaustion

A candidate qualifies solely by differing from 0xFFFFFFFF. There is no positivity, nonzero, range, or validity check on the qualifying value.

A qualifying observation commits the function to one invocation of F-57e36fb68b0b. If that invocation returns normally, the function returns 1 without reading another candidate or rechecking the qualifying field.

If the selected suffix contains only sentinel values, the function returns 0 without invoking the dependency. A sentinel observation at Candidate 4 ends the search; no additional candidate read is required.

An out-of-range starting value likewise returns 0 without dependency invocation, but unlike exhaustion it requires no candidate observations.

### Access bounds and arithmetic

Under the stated 32-bit field interpretation, the function performs:

- Exactly one direct starting-field read.
- No candidate reads for an out-of-range starting value.
- Between one and four candidate reads for an accepted starting value.
- At most five direct field reads overall.

These counts exclude any accesses performed inside F-57e36fb68b0b.

The accepted search positions are bounded by four. Search-position advancement therefore does not overflow a 32-bit unsigned value on a normal accepted path. Large initial values are excluded before such advancement.

That bound does not establish safety of adding offsets to an arbitrary base address. Address-space boundaries, integer-to-address interpretation, and invalid address formation remain target-dependent.
