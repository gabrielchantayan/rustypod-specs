# F-401747d6f0eb

## Purpose

F-401747d6f0eb performs a small sequence of memory reads and writes while forwarding an incoming 64-bit value as its result. Its memory effects depend on whether its second explicit argument is zero.

The ordinary, nonzero-argument path copies an unsigned 16-bit value from storage addressed by an ambient base into a 32-bit destination at another offset from that same base. The zero-argument path additionally updates several global storage locations, writes the sampled value to a potentially unaligned destination, and changes both the address and value used by the final write.

This is a source-facing contract based solely on the supplied static representation. It does not establish that either path executes successfully on an actual target. In particular, the second argument is used for a memory read **before** it is tested for zero.

No application-level purpose, such as initialization, exception handling, or object maintenance, is established. Names attached to global storage are not sufficient evidence of such a purpose.

## Behavior

### Initial reads

Before the branch, the represented operation order is:

1. Read an unsigned 16-bit value from the address formed by adding four to the second explicit argument. Retain this as the **first sample**.
2. Read an unsigned 16-bit value from offset `0x28` relative to the ambient base. Zero-extend it to 32 bits and retain it as the **second sample**.

Both reads precede the test of the second argument.

Consequently, a zero second argument does not bypass the first read. It instead selects a read whose nominal address is four. Whether that address is readable is an environmental condition, not a property guaranteed by this function.

The retained samples are used by subsequent operations. The represented body does not reread either source location later.

### Nonzero second argument

When the second argument is nonzero:

- The final destination base remains the original ambient base.
- The final value remains the zero-extended second sample.
- A 32-bit write places that value at offset `0x30` from the ambient base.
- The function returns the incoming fifth argument.

The first sample is still read, even though this branch does not subsequently use its value.

There are no represented global assignments on this path.

The destination receives four bytes, not two. For example, a second sample numerically equal to `0xFFFF` produces a 32-bit stored value of `0x0000FFFF`, not a sign-extended value. Byte order is not established by the supplied evidence.

### Zero second argument

When the second argument is zero, the represented body performs additional effects before the final write.

For this contract, the five global destinations are called **G1** through **G5**. These are descriptive storage labels, not dependency identifiers, and do not assert that the destinations are disjoint.

The represented sequence is:

1. Assign to G1 the result of subtracting five from the ambient base.
2. Assign to G2 the result of multiplying the value of G1 by `0x100`.
3. Write the zero-extended second sample as a 32-bit value at offset `0x3B` from the original ambient base.
4. Select `0x8D` as the value for the final write.
5. Select the ambient base shifted left by eight bits as the base for the final destination.

7. Assign the original ambient base to G4.
8. Assign the auxiliary ambient word to G5.
9. Write the selected final value as a 32-bit quantity at offset `0x30` from the selected final base.
10. Return the incoming fifth argument.

The selections in steps 4 and 5 are internal state changes, not additional memory writes.

The final stored numeric value on this path is `0x0000008D`. Its destination is based on the shifted ambient base, not the original base.
