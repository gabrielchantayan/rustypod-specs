# F-92dc38b16a13

## Purpose

F-92dc38b16a13 obtains a small record through F-226e963e6ba7, applies a conditional fallback, writes selected fields into caller-provided storage, and returns a packed 64-bit result.

The established behavior is record conversion with partial initialization. The function does **not** initialize every byte of the destination. In particular, one output byte is written only when a flag is set, and several other bytes are never written directly.

The meanings of the record fields are unknown. Interpreting the two control bits as validity and optional-field indicators is inferred intent, not an established semantic contract. A return value whose low 32 bits are zero is not, by itself, evidence of failure.

## Interface

The function accepts one pointer to writable caller-provided storage. All output offsets in this document are byte offsets relative to that pointer.

No destination length is supplied. The visible function performs no null, length, alignment, or writability checks.

The destination is not passed directly to F-226e963e6ba7. Instead, that dependency receives the address of a separate, initially zeroed, 12-byte temporary record.

### Temporary record

For specification purposes, the temporary record consists of three consecutive 32-bit words:

| Word | Byte range | Visible use |
|---|---:|---|
| Value word | 0–3 | Supplies two output bytes, a 16-bit output field, and the high half of the return value |
| Auxiliary word | 4–7 | Supplies an unsigned 8-bit multiplier and an unsigned 8-bit Boolean-like input |
| Control word | 8–11 | Supplies three output bytes and two control bits |

These names describe roles only; they do not imply domain meanings.

All three words are zero before the dependency is called. Subsequent behavior uses their contents after that call, subject to the fallback transformation described below.

### Output storage

The function directly writes the following fields:

| Destination offset | Width | Value |
|---:|---:|---|
| 0 | 16 bits | Zero |
| 2 | 8 bits | Bits 16–23 of the effective control word |
| 3 | 8 bits | Bits 8–15 of the effective control word |
| 4 | 8 bits | Bits 0–7 of the effective control word |
| 5 | 8 bits | Bits 24–31 of the effective value word |

The table specifies numeric values for multibyte fields. Their physical byte order follows the implementation’s native storage convention; the supplied material does not independently establish a portable byte-order contract.

### Return value

The return is a 64-bit packed value:

- Bits 32–63 contain the effective value word.
- Bit 0 is one if control bit `0x02000000` is set, and zero otherwise.
- Bits 1–31 are zero.

Equivalently, the numeric result is the effective value word multiplied by \(2^{32}\), plus either zero or one.

The low half is a flag projection, not an established success or error code.

## Behavior

### 1. Obtain the temporary record

The function initializes all 12 bytes of the temporary record to zero and calls F-226e963e6ba7 once, passing its starting address.

No direct destination writes precede this call.

There is no visible branch on a return status from the dependency. Normal continuation relies on the contents of the temporary record. If the dependency does not return normally, the subsequent behavior described here is not established.

Zero initialization matters when the dependency leaves some record fields unchanged. However, the dependency’s own contract is unavailable; it must not be assumed to restrict its accesses to this record or to preserve unrelated state.

### 2. Apply the fallback when required

After the dependency returns, the function tests control bit `0x01000000`.

If that bit is set:

- The value word remains as supplied through the temporary record.
- The control word remains unchanged.
- The fallback global value is not read by the visible path.

If that bit is clear:

- Bits 0–23 of the control word are cleared.
- Bits 24–31 of the control word are preserved.
- The value word is replaced with a value whose upper 16 bits are `0x0101` and whose lower 16 bits come from a global source.

Thus, in the fallback path, the effective value word lies between `0x01010000` and `0x0101FFFF`, inclusive.

Only the low 16 bits obtained from the global source affect the replacement. The supplied material does not establish that source’s complete declared width or semantic meaning.

The global read occurs after the dependency call and only on the fallback path. Consequently, if F-226e963e6ba7 changes that global source, the fallback uses the subsequently observed value, not a value captured before the call.

The fallback preserves control bit `0x02000000`. Optional auxiliary output can therefore remain enabled even when the value word has been replaced.

### 3. Write the primary output fields

Using the effective words after the fallback decision, the function performs these direct destination writes in order:

1. Write bits 16–23 of the value word to offset 6.
2. Write bits 24–31 of the value word to offset 5.
3. Write the low 16 bits of the value word as a 16-bit field at offset 8.
4. Write bits 0–7 of the control word to offset 4.
5. Write bits 8–15 of the control word to offset 3.
6. Write bits 16–23 of the control word to offset 2.
7. Write a 16-bit zero at offset 10.

This is not increasing-address order.

On the fallback path, offsets 5 and 6 both receive `0x01`, and offsets 2, 3, and 4 all receive zero.

### 4. Conditionally write auxiliary output

The function next tests control bit `0x02000000`.

If the bit is clear:

- The 16-bit field at offset 10 remains zero from the preceding write.
- Offset 12 receives no direct write.

If the bit is set:

1. Extract bits 16–23 of the auxiliary word as an unsigned 8-bit value.
2. Multiply that value by decimal 15.
3. Replace the 16-bit field at offset 10 with the product.
4. Inspect bits 24–31 of the auxiliary word.
5. Write zero to offset 12 if that byte is zero; otherwise write decimal 60.

The scaled input is in the range 0–255. The product is therefore in the range 0–3825 and fits in 16 bits without truncation. An input byte of `0xFF` produces 3825, not a negative value.

The byte used for offset 12 is treated as zero versus nonzero. Its magnitude is otherwise irrelevant: values 1 and 255 both produce 60.

The low 16 bits of the auxiliary word do not affect any visible output or the return value.

### 5. Finish the output and return

After the optional auxiliary writes, the function:

1. Writes a 16-bit zero at offset 0.
2. Writes a 32-bit zero at offset 16.
3. Returns the packed 64-bit result.

There is no visible additional dependency call, retry, or error-reporting branch.

### Primary value retained; optional output disabled

### Fallback with optional output enabled

- The fallback source’s low 16 bits are `0xBEEF`.
- Auxiliary bits 16–23 are 7.
- Auxiliary bits 24–31 are 2.

Suppose both control bits are set, auxiliary bits 16–23 are `0xFF`, and auxiliary bits 24–31 are zero.

The field at offset 10 ends as 3825, offset 12 becomes zero, and the return’s low 32 bits equal one. No fallback read occurs.

### Dependency leaves the zeroed record unchanged

Offsets 2–4 and the field at offset 10 become zero. Offset 12 is not directly written. The return’s low 32 bits are zero; this alone does not establish failure.
