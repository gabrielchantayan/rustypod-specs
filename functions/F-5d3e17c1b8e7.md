# F-5d3e17c1b8e7

## Purpose

F-5d3e17c1b8e7 conditionally traverses records associated with an input object, writes cursor-and-value fields into an indexed table, and terminates either on a specially marked record or on a nonzero traversal status.

On the specially marked path, it directly writes a selected cursor, invokes an unidentified dependency with the selected-state destination, temporary-state source, and count 20, then directly writes a selected 16-bit value. The supplied body does **not** establish that this dependency copies data, completes a transfer, or confines its writes to 20 bytes.

On other normal exits, the function clears designated output fields and returns either an entry-time global value or the status that terminated traversal.

“Cursor,” “descriptor,” and “record state” describe observed storage uses. Their application-level meanings are not established. This contract distinguishes direct operations from dependency effects; unknown dependencies are not presumed to preserve globals, exposed local storage, or caller-accessible memory.

## Behavior

### Entry and traversal gate

The function first reads a 32-bit value from global storage. Later global changes do not, by themselves, replace this captured return value.

It then reads the input object’s 16-bit field at byte offset 2:

- Zero skips traversal.
- Every nonzero bit pattern enables traversal, including values represented as negative signed 16-bit numbers.

If traversal is enabled, the function reads the 32-bit cursor from input-object offset 12, then initializes slot zero with these direct writes, in order:

1. A 32-bit zero at table offset 0.
2. A 16-bit zero at table offset 4.

These operations do not directly initialize table bytes 6 and 7 or any other slot.

The initial cursor read precedes table initialization. Thus overlapping table and input-object storage can alter the object after its initial cursor has already been captured.

### Record acquisition

Each iteration calls F-5f9a16493218 with the input object, current cursor value, and temporary-state address.

If its status is nonzero, processing leaves the loop without reading a descriptor or writing an indexed slot for that iteration. The function clears the designated selected outputs and returns the status.

If its status is zero, the function reads the first 32-bit element of temporary state and supplies that value as the descriptor argument to F-8a92d5d60703. The other arguments are the input object, context, and working-value address.

The returned status controls later branching. It is distinct from the working value supplied through storage.

### Descriptor rereads and slot selection

After F-8a92d5d60703 returns, the function performs the following ordered operations:

1. Rereads the first 32-bit element of temporary state.
2. Reads the unsigned byte at offset 9 from that observed descriptor address.
3. Uses that byte as the slot index and writes the current 32-bit cursor into the selected slot.
4. Rereads the first 32-bit element of temporary state again.
5. Reads the signed byte at offset 8 from that newly observed descriptor address.

The descriptor supplied to F-8a92d5d60703, the descriptor supplying the index, and the descriptor supplying the marker are not established to be identical. F-5f9a16493218 has received the state address; dependencies may retain or expose aliases to it. The cursor-slot write may also affect aliased storage before the marker-address reread.

The index is retained for the subsequent value-slot write; it is not recomputed from the marker descriptor.

An index \(k\) selects a cursor field at table offset \(8k\) and a value field at offset \(8k+4\). Since \(k\) is an unsigned byte, its range is 0 through 255. The largest direct write reaches byte offset 2045 inclusive. Consequently, 2046 addressable bytes cover all possible direct table writes; a complete 256-slot layout occupies 2048 bytes.

The marker byte is interpreted as signed and extended before comparison. Only byte value `0xFF`, representing minus one, selects the special path.

### Specially marked path

For marker `0xFF`, the function performs these operations in order:

1. Reads the working value and writes its low 16 bits into the retained index’s value field.
2. Reads the current cursor and writes it to the selected-cursor output.
3. Calls F-U1 with the selected-state destination, temporary-state source, and count 20.
4. Rereads the working value and writes its low 16 bits to the selected-value output.
5. Returns `32` if the earlier F-8a92d5d60703 status was zero, otherwise `0`.

The selected-value output is **not guaranteed to equal** the value previously written into the slot. F-U1 executes between those reads. The working-value address was previously exposed to F-8a92d5d60703, and no dependency-preservation contract excludes later mutation through a retained or exposed alias.

Similarly, the count 20 establishes a call argument, not a completed 20-byte copy or a bounded write footprint. F-U1’s return value, if any, is ignored. The steps after its invocation apply if it returns normally.

No decrement is applied on this path. F-f66a00df5276, F-42a35b3b505e, and F-b0f922796692 are not called for this selected record.

### Ordinary-record path

For every other marker, normalization depends on the saved F-8a92d5d60703 status:

- Status exactly `1`: retain the working value without normalization.
- Any other status: inspect the working value’s low 16 bits.
  - If nonzero, replace the full 32-bit working value with that unsigned 16-bit quantity minus one.
  - If zero, leave the full working value unchanged.

The subtraction input ranges from 1 through 65535, so its result ranges from 0 through 65534. This operation does not underflow. A zero low half does not become 65535, and existing high bits are not necessarily cleared in that case.

The function then:

1. Writes the working value’s low 16 bits to the retained index’s value field.
2. Calls F-f66a00df5276 with the object, a newly read first element of temporary state as descriptor, the working value masked to 16 bits, and three local output addresses.
3. Calls F-42a35b3b505e with the cursor address and the 32-bit contents of the middle output area.
4. Calls F-b0f922796692 with the object and temporary-state address.

The descriptor for F-f66a00df5276 is read **after** the value-slot write. It therefore need not match any descriptor observed earlier. Its masked-value argument is also obtained after that write. No ordering among evaluation of arguments within this call is established here.

The first and third output areas from F-f66a00df5276 are not subsequently consumed by this body. Its middle output is consumed without intervening initialization or validation. The return values of F-f66a00df5276 and F-42a35b3b505e are ignored.

If F-b0f922796692 returns zero, another acquisition begins using the then-current cursor. Otherwise, output clearing occurs and its status is returned. No iteration bound or guaranteed cursor progress is established.

### Nonselection output clearing

1. A 32-bit zero to the selected-cursor output.
2. A 32-bit zero at selected-state offset 0.

## Side effects

### Direct writes and observable ordering

Direct table writes affect only the four-byte cursor and two-byte value fields of each addressed slot. The function does not directly write the two trailing bytes through the table-field operations. Repeated indices overwrite the same fields rather than append entries.

These are direct-write statements, not unconditional final-memory guarantees. Dependencies and overlapping destinations can modify the same storage.

Aliasing can expose several ordering effects:

- Initial table writes occur after the initial object-cursor read.
- The cursor-slot write precedes the marker descriptor reread.
- The value-slot write precedes the descriptor read used for F-f66a00df5276.
- Selection writes the cursor output before F-U1, then writes the selected value after F-U1.
- Nonselection output clearing can overwrite earlier table data when destinations overlap.
