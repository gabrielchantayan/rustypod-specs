# F-6c307b8a818e

## Purpose

F-6c307b8a818e prepares boot-record-like fields and partition entries, invokes an interface-provided operation with a buffer address, and reports success when that operation returns zero. Buffer acquisition failure produces a zero result without construction or submission.

Offsets, constants, and a FAT32 format label suggest filesystem initialization. This is **inferred intent**, not evidence that the resulting storage contains a valid or complete filesystem.

The construction is not unconditionally confined to one buffer. The function repeatedly obtains its buffer base from an address-bearing descriptor word, while retaining entry-destination addresses across dependency calls. If a dependency changes that descriptor word, subsequent operations can address different storage.

This contract distinguishes:

- **Established static evidence:** visible accesses, arithmetic, branches, call arguments, and ordering.
- **Inferred intent:** interpretations such as template copying, partition construction, and storage writing.
- **documented_only:** behavior not established without dependency implementations, platform information, or constant data.

No runtime tests have been performed.

A two-word local descriptor is passed by address to F-d9e0ae06e54d without visible prior initialization. That dependency must establish the descriptor state subsequently read and passed to cleanup. The second word’s meaning is **documented_only**.

For execution without access faults, each buffer-derived address must support its particular operation. ## Behavior

### Interface queries and independently refreshed dispatch

The function first reads the context’s interface pointer at `+4`, reads that object’s dispatch-table pointer, and invokes the entry at table offset `+0x2C`. Its signed 32-bit result is retained as the first query result.

After that call returns, the function independently rereads both:

1. The context’s interface pointer at `+4`.
2. The dispatch-table pointer obtained through that interface object.

It then invokes the entry at table offset `+0x28`, retaining its signed 32-bit result as the second query result.

The second query therefore need not use the first query’s object or table. The first dependency can change the context field, the object’s dispatch-table pointer, or both.

Neither query has explicit arguments in the supplied representation. Receiver conventions and implicit arguments are **documented_only**.

### Size selection and initial calculation

A nonzero requested size is retained unchanged.

For a zero requested size, the function loads a global 32-bit default. If flag `0x2` is set, it references that global again and selects its value shifted left by one bit. The two references are not established as an atomic snapshot. There is no overflow check or saturation.

The first query result is transformed into a quotient equivalent to signed division by 512 with truncation toward zero. The negative-input adjustment is 511 before an arithmetic right shift by nine. The resulting bit pattern is subsequently treated as unsigned 32-bit.

Examples:

| First query result | Derived unsigned value |
|---:|---:|
| 1024 | 2 |
| 511 | 0 |
| −511 | 0 |
| −512 | `0xFFFFFFFF` |

F-d7be9cfb4000 receives the selected size and the derived value. Its 32-bit result is retained for optional-entry arithmetic. Its mathematical operation is unknown.

### Acquisition and buffer-address semantics

F-d9e0ae06e54d receives the descriptor’s address and the first query result. The function then examines the descriptor’s first word as a buffer pointer.

If that word is zero, the function invokes F-cc6f52873d53 on the descriptor and returns zero. It performs no construction or submission.

If the word is nonzero, construction proceeds. This check does **not** establish that later accesses use the same address:

- Most buffer-relative operations reread the descriptor’s first word.
- Passing the descriptor’s address to acquisition permits that dependency to retain access to it; subsequent stability is not established.
- An operation’s already-computed destination remains its argument for that call. A changed descriptor word affects later address calculations, not that previously computed argument.
- Entry destinations have separate retention rules, described below.

References to an offset in the following field layout mean that offset from the descriptor-derived base used for the particular access, not necessarily one immutable allocation.

### Entry destinations and optional-entry arithmetic

After the final string-oriented call returns, the function captures an entry-destination address equal to the then-current descriptor word plus `0x1BE`. This address is retained independently of subsequent descriptor reads.

If the selector equals `−1`:

- Optional geometry reads and F-870c4fcf7295 are skipped.
- The retained destination remains unchanged.
- The final starting position is the initial position.
- Flag `0x1` has no alignment effect.

For every other selector, the function reads an unsigned 16-bit quantity at descriptor-derived offset `0x18`, followed by another at descriptor-derived offset `0x1A`. These are reads of current memory, not substitutions of the earlier stored constants.

If the relevant base and bytes remain unchanged, these values are 63 and 255 on a little-endian platform, or 16128 and 65280 on a big-endian platform. Native byte order is not independently established.

F-870c4fcf7295 receives:

- The first halfword plus the retained result of the initial F-d7be9cfb4000 call.
- The product of the two halfwords.

The halfword product is at most 4,294,836,225 and therefore fits unsigned 32-bit arithmetic. Subsequent additions and multiplication use 32-bit results without an overflow check. The calculated next position is the halfword product multiplied by one more than the adjustment helper’s result, retaining the 32-bit position pattern.

The optional F-998d5729bf44 invocation receives:

- The context.
- The requested selector.
- The **previously retained** entry destination.
- A **freshly read** descriptor-derived buffer base.
- The original initial position.
- The calculated next position minus one.

Consequently, F-870c4fcf7295 can change the descriptor pointer between destination capture and construction. The constructor may receive an entry destination derived from one base and a buffer-base argument derived from another.

After the optional constructor returns, the function replaces the retained destination with the **then-current descriptor word plus `0x1CE`**. It does not merely advance the old destination by 16.

If flag `0x1` is set, the calculated next position is rounded by adding 15 and clearing the low four bits. This unsigned 32-bit operation wraps rather than saturates. It occurs after the optional constructor has received its endpoint, so alignment does not change that earlier argument.

F-998d5729bf44 is always invoked for the final entry, with:

- The context.
- Selector `0x0B`.
- The retained entry destination.

After the constructor returns, the two-argument external operation receives addresses 16 and 32 bytes after the retained destination, each with a length-like argument of 16. If the optional entry was absent, it also receives the address 48 bytes after that destination with 16.

These addresses remain based on the retained destination, even if the final constructor changes the descriptor word.

Only under a stable descriptor-pointer assumption do these targets form the conventional buffer-relative ranges:

- Optional entry absent: `0x1CE–0x1FD`.
- Optional entry present: `0x1DE–0x1FD`.

Clearing unused slots is inferred intent. Actual writes depend on the external operation.

### Submission, publication, and cleanup

1. An interface object read from the context.
2. Zero.
3. The buffer address freshly read from the descriptor.
4. One.
5. Zero.

The representation does not establish a complete evaluation order among the target expression and argument reads. It does establish that submission does not simply reuse an earlier query object or the retained entry destination.

In particular, trailing operations can change the descriptor word before submission. The submitted buffer can differ from buffers previously modified.

## Side effects

Established effects include descriptor-address exposure, explicit memory stores, helper calls, interface dispatches, and success-only output publication.

The output store occurs after successful submission but before cleanup. A fault at the output destination or a failure during cleanup has no visible rollback. A zero result does not establish that submission caused no partial external changes.

F-cc6f52873d53 is called on every explicit normal-return path, including acquisition failure. Its placement does not prove allocation release, ownership transfer, descriptor invalidation, or destruction. Buffer retention by dependencies and the lifetime of every referenced allocation are **documented_only**.

Failure paths have no direct output store. Dependencies and aliasing can nevertheless change the output destination. No dependency is assumed to preserve globals, interface pointers, dispatch tables, the descriptor, or buffer contents.

## Acceptance examples

These are conditional examples, not executed tests. Each assumes execution reaches the described point and dependencies return normally.

1. **Interface replacement between queries.** If the first query replaces the context’s interface pointer, the second query uses the replacement object’s table. If only the original object’s table pointer changes, the second query uses that newly read table instead.

2. **Acquisition failure.** If acquisition leaves the descriptor’s first word zero, no field construction or submission occurs. Cleanup receives the descriptor, and the function returns zero.

3. **Single-entry success with stable storage.** With selector `−1`, initial position 2048, stable descriptor pointer, and submission result zero, the final constructor receives destination `0x1BE` relative to that buffer and start 2048. The output receives 2048 before cleanup; the result is one. Flag `0x1` does not alter this start.

4. **Optional entry and alignment.** If optional arithmetic yields position 1001 and flag `0x1` is set, the optional constructor receives endpoint 1000. The final constructor receives start 1008. With stable storage, its destination is buffer offset `0x1CE`.

5. **Descriptor change during arithmetic.** Suppose the initial entry destination was captured from allocation A, but F-870c4fcf7295 changes the descriptor to allocation B. The optional constructor receives a destination in A and buffer-base argument B. If that constructor changes the descriptor to C, the final destination is captured at C plus `0x1CE`.

6. **Descriptor change during final construction.** If the final constructor changes the descriptor to allocation D, trailing operations still use the retained entry destination. Submission later obtains D, unless an intervening dependency changes the descriptor again.

7. **Alignment wraparound.** A calculated position of `0xFFFFFFF8`, with alignment enabled, becomes zero after adding 15 and clearing the low four bits. No local overflow error is produced.

8. **Submission failure.** Any nonzero submission result leads to cleanup and return zero, with no explicit output store. This does not exclude partial storage modification.

9. **Explicit size precedence.** Any nonzero requested size, including a negative value, bypasses default selection regardless of flag `0x2` and is supplied to the initial F-d7be9cfb4000 call.
