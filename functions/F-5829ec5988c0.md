# F-5829ec5988c0

## Purpose

F-5829ec5988c0 conditionally dispatches a request described by four 32-bit inputs. Dispatch is enabled by a nonzero word reached through a global pointer-valued datum. A signed comparison of the first input against four selects either a direct callback or an object-mediated sequence.

The global datum and the selection word it points to are distinct state. The function first saves a pointer obtained from the global datum, then separately evaluates that datum to locate the gate word. Direct dispatch evaluates the global datum again; object-mediated dispatch instead uses the saved pointer. These accesses must not be collapsed into access to one assumed-stable slot.

On normal completion, the function returns a 64-bit value assembled from two local words initially containing the first and second inputs. Callback return values do not directly supply this result. On the object-mediated path, a dependency receives access to those local words, so their final contents are not necessarily their initial contents.

The request’s application-level meaning, the callback’s purpose, and the object’s ownership model are unknown. A dispatch role is inferred from the visible call structure, not established as an application protocol.

## Interface

### Inputs

| Position | Width and established use |
|---|---|
| First | Signed 32-bit integer. Compared against four and passed to the selected callback and an object-processing dependency. Its bit pattern initializes the low return word. |
| Second | Opaque 32-bit word. Initializes the high return word and the first payload word. |
| Third | Opaque 32-bit word. Initializes the third input-block word and the second payload word when dispatch is enabled. |
| Fourth | Opaque 32-bit word. Initializes the fourth input-block word and the third payload word when dispatch is enabled. |

No further interpretation of the opaque words is established. In particular, the function does not visibly distinguish numeric values from encoded addresses, flags, or handles.

### Return value

The result is a 64-bit bit pattern:

- Bits 31–0 contain the final contents of the first local input-block word.
- Bits 63–32 contain the final contents of the second local input-block word.

If neither word changes after initialization, the result is the second input’s unsigned 32-bit pattern multiplied by \(2^{32}\), plus the first input’s unsigned 32-bit pattern.

This is concatenation, not signed extension. A first input of −1 contributes `0xFFFFFFFF` only to the low half; the second input still determines the high half.

The function has no visible separate error result. Failure to complete an indirect call or memory access does not select an established alternative return value.

### Relevant state and layouts

**Global pointer-valued datum.** This contains a pointer to a selection word. The function reads the datum more than once on some paths. Its immutability is not established.

**Selection word.** Each selection location used by the function contains a 32-bit word. The gate tests the full word against zero. For an indirect callback, the function clears its lowest two bits using the 32-bit mask `0xFFFFFFFC`.

**Local input block.** Four consecutive 32-bit words hold the four inputs in order. The first two words are initialized before the gate. The last two are initialized only when the gate is nonzero. F-15e3b8a10073 receives the address of the first word on the object-mediated path.

**Local payload block.** Three consecutive 32-bit words hold the second, third, and fourth inputs. This block is initialized when the gate is nonzero. F-ad07f589e909 receives its address on the object-mediated path. It is distinct from the input block.

**Object-associated dispatch structure.** The object’s first 32-bit word provides the address used to locate indirect operation entries. The function reads one 32-bit target word at byte offset eight and another at byte offset zero. It clears the lowest two bits of each target word before invocation.

The representation establishes 32-bit data words and target-word masking. It does not independently establish the width of the global pointer-valued datum, the complete target ABI, or platform address-overflow rules.

## Behavior

### Entry and gate

The established order is:

1. Read the global pointer-valued datum and save the resulting pointer for possible later use.
2. Initialize the first two local input-block words from the first and second inputs.
3. Evaluate the global pointer-valued datum separately, then read the 32-bit gate word through the pointer obtained by that evaluation.
4. Test that gate word against zero.

The saved pointer is not used to perform the gate read. If the global datum can change between evaluations, the saved pointer and the pointer used for the gate need not identify the same selection location.

If the gate word is zero:

- No dependency or indirect operation is invoked.
- The saved pointer is not dereferenced by the visible continuation.
- The function returns the concatenation of the original second and first input words.
- The third and fourth inputs have no observable role in this path.

If the gate word is nonzero, the function initializes the remaining two words of the input block and all three words of the separate payload block, then selects a path using the original first input.

The gate tests the word before target masking. A nonzero gate word does not establish that any subsequently selected masked target is nonzero or callable.

### Direct path: first input less than four

The comparison is signed. Every negative first input, zero, one, two, and three takes this path.

For dispatch, the function:

1. Evaluates the global pointer-valued datum again.
2. Reads a 32-bit selection word through the pointer obtained from this new evaluation.
3. Clears the selection word’s lowest two bits.
4. Invokes that target with the original first input and a 32-bit zero.

This is a third evaluation of the global datum in the visible sequence: the initial pointer capture, the gate evaluation, and the direct-dispatch evaluation.

The direct callback is not selected through the saved pointer. It is also not necessarily selected from the location used by the gate. Neither pointer stability nor selection-word stability is established.

The direct dispatch has no second zero check. If the direct-path selection word is zero, or masks to zero, the function still attempts the resulting indirect call.

The direct path does not call F-15e3b8a10073, F-abf1a5a8a699, or F-ad07f589e909. It ignores the callback’s return value and, if the callback returns normally, returns the two local return words.

### Object-mediated path: first input at least four

The following order is established:

1. Call F-15e3b8a10073 with the integer value eight and the address of the four-word input block.
2. Set the candidate object pointer to zero.
3. If F-15e3b8a10073 returned a nonzero 32-bit result, call F-abf1a5a8a699 without visible arguments and use its result as the object pointer.
4. Call F-ad07f589e909 with the object pointer, the original first input, and the address of the separate three-word payload block.
5. Read the object’s first word to obtain a dispatch-structure address.
6. Read the 32-bit target word at byte offset eight, clear its lowest two bits, and invoke that target with the object pointer.
7. Retain that operation’s 32-bit result.
8. Read a selection word through the pointer saved at function entry. Clear the word’s lowest two bits and invoke the resulting callback with the original first input and the retained result.
9. After the callback returns, read the object’s first word again. From the resulting dispatch structure, read the target word at byte offset zero, clear its lowest two bits, and invoke that target with the object pointer.
10. After the final operation returns, assemble the 64-bit result from the first two local input-block words.

Step eight does **not** obtain a new pointer from the global datum. A change to that datum does not redirect this selection read away from the saved pointer. A change to the selection word at the saved location can change the selected target.

The return values of F-ad07f589e909, the selected callback, and the final object-associated operation are not used in the visible result computation.

### Mutation boundaries

F-15e3b8a10073 receives the input-block address before the later calls. Changes to that block can therefore affect the returned words, subject to the dependency’s unknown write contract.

The later calls that visibly receive the first input receive the original argument, not a reread of the first input-block word. Changing that local word does not itself change those visible argument values.

The payload block is initialized separately before F-15e3b8a10073 runs. A write confined to the input block does not also update the payload block.

The final object dispatch-structure address is freshly read after the selected callback. The function does not preserve the earlier dispatch-structure address for that final operation.

## Side effects

### Local storage and exposed addresses

The function writes its local blocks as described above. It exposes:

- The input-block address to F-15e3b8a10073.
- The payload-block address to F-ad07f589e909.

These addresses refer to invocation-local storage. The supplied evidence does not establish a valid lifetime for accessing that storage after this function returns, nor does it establish that either dependency discards the address.

The constant eight passed alongside the input-block address does not, by itself, establish an eight-byte readable or writable extent.

### External state

The visible function contains no explicit write to the global pointer-valued datum, any selection word, or object memory. Invoked operations may nevertheless affect those locations.

No dependency is established to preserve:

- The global pointer-valued datum.
- Selection words, including the word at the saved location.
- Object contents or dispatch entries.
- Memory reachable through supplied addresses.

Likewise, no dependency is established to allocate, retain, transfer, or release ownership. The final object-associated operation must not be treated as proven destruction or release.

### Validity and failures

Normal completion requires each accessed location and invoked target to be valid at its actual use point.

This includes the distinct requirements that:

- The pointer obtained for the gate supports its selection-word read.
- A direct-path pointer obtained later supports its own selection-word read.
- On the object-mediated path, the saved pointer remains usable until the late selection read.
- The object and its dispatch structures remain usable across the dependency calls, selected callback, and final indirect operation.

The saved pointer need not be dereferenceable on a gate-zero path because that path does not visibly dereference it.

If the selected callback invalidates the object, the subsequent object read is unprotected. If F-15e3b8a10073 returns zero, the candidate object remains zero, but the visible continuation still passes it to F-ad07f589e909 and subsequently attempts an object read.

No explicit null handling, exception recovery, invalid-target handling, or alternate cleanup path is established.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests.

### Disabled dispatch

If the gate evaluation obtains a valid pointer to a zero selection word, with first input −1 and second input `0x12345678`:

- No dependency or indirect operation is invoked.
- The result is `0x12345678FFFFFFFF`.
- The initially saved pointer is not subsequently dereferenced.

The saved pointer need not equal the pointer used by the gate.

### Signed boundary and direct arguments

With a nonzero gate and valid subsequent accesses and targets:

- First input −1 takes the direct path.
- First input three takes the direct path.
- First input four takes the object-mediated path.

For first input two, the direct callback receives two and zero, not two and the second input. Its return value does not determine the function’s returned halves.

### Pointer replacement before direct dispatch

Suppose the initial pointer capture obtains location A, the gate evaluation obtains location B, and the direct-dispatch evaluation obtains location C.

If B contains a nonzero gate word and the first input is below four, the callback target comes from C. Neither A nor B supplies that target merely because it was accessed earlier.

This case is conditional on the environment allowing the global datum to change between evaluations; such changes are not established to occur.

### Saved-pointer selection on the object path

Suppose the initial pointer capture obtains A and the gate evaluation obtains B. B contains a nonzero word and the first input is four.

After the object-processing calls and offset-eight operation, the callback selection is read from A. Changing the global datum to point to C during those calls does not redirect that read to C. Changing the word at A can change the callback target.

A later zero word at A does not disable dispatch gracefully: the function attempts the masked zero target without another gate.

### Object-mediated sequencing

Given a nonzero result from F-15e3b8a10073 and a valid object from F-abf1a5a8a699:

- F-ad07f589e909 receives that object and the payload initialized from inputs two through four.
- The offset-eight operation precedes the selected callback.
- If that operation returns `0x89ABCDEF`, the callback receives the original first input and `0x89ABCDEF`.
- The offset-zero operation follows the callback and uses a fresh object dispatch-structure read.

### Return-storage mutation

If F-15e3b8a10073 changes the first two input-block words to `0x10203040` and `0x50607080`, and later operations leave them unchanged and complete normally, the returned value is `0x5060708010203040`.

Such writes do not by themselves change the original first input passed to later calls or the separate payload block. Whether these writes are permitted is **documented_only**.

### Zero object candidate

If F-15e3b8a10073 returns zero:

- F-abf1a5a8a699 is skipped.
- F-ad07f589e909 receives a zero object pointer.
- The continuation attempts to read the object’s first word through that zero pointer.

No graceful failure result is established. Normal completion requires additional environmental or dependency behavior making the subsequent accesses valid.
