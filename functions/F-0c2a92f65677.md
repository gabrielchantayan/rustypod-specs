# F-0c2a92f65677

## Purpose

F-0c2a92f65677 dispatches a 32-bit operation selector using an object, a 32-bit qualifier, and a caller-provided output slot. Supported operations expose scalar fields, perform resource lookups, manipulate shared state through dependencies, inspect records, and invoke service-related dependencies.

The return value is a status, separate from the requested value. Every explicit normal return is zero or one. Status one does not guarantee an output write; status zero does not guarantee absence of side effects.

“Resource,” “text,” “provider,” and “service” describe inferred roles. The established behavior consists of the accesses, conditions, calls, writes, and returns below.

## Interface

### Arguments and representation

| Item | Established representation |
|---|---|
| Object | Pointer to storage containing 32-bit words, byte fields, embedded storage, and dispatch pointers. |
| Qualifier | 32-bit value interpreted through equality and arithmetic predicates. |
| Operation | 32-bit selector; explicit cases are `0x6201`–`0x621b`. |
| Output | Address of a writable 32-bit slot on paths that write a result. |
| Return | 32-bit status, explicitly zero or one. |

The supplied representation uses 32-bit pointer-valued words. Output writes replace exactly four bytes; byte results are zero-extended.

No general null checks, table-bound checks, or output validation are present. Required preconditions depend on the selected path. Dependency results that are subsequently dereferenced must designate suitable storage for execution to remain valid.

### Symbolic shared storage

Concrete shared values are unavailable. The following names identify storage roles, not immutable values:

- **Shared**: shared-object pointer used by many dependencies.
- **Qbase**, **Qnumber**, **Qbyte**: qualifier-comparison words.
- **Qfallback**, **Qalternate**: arithmetic comparison adjustments.
- **Qservice-A**, **Qservice-B**: adjustments used by `0x6208`.
- **Default key**: resource key captured during dispatch preparation.
- **Common word**: shared word captured during preparation and reread for common completion.
- Operation-specific keys, destinations, descriptors, and initialization operands.

Different names do not establish distinct addresses or values. Aliasing is unresolved.

## Behavior

### Entry initialization and captures

Every invocation first reads a shared base pointer and tests bit zero of the 32-bit word eight bytes beyond it.

If the bit is set, the initialization gate and its following operand loads are skipped. If clear:

1. Read the initialization token and call F-b255b26284e6.
2. After that call returns, load the initialization operand, then capture Shared. These loads occur even if the gate returned zero.
3. If the gate returned zero, perform no initialization-body writes or further initialization calls.
4. Otherwise, freshly read Shared and write the initialization value to the first word of that freshly obtained object.
5. Write zero to the second word of the previously captured object.
6. Call F-804adc29bbfb with the captured object, the shared descriptor, and the captured operand.
7. Read the initialization token again and pass that current value to F-d08d3ca17b81.

The first-word write is therefore not specified to use the captured pointer used by the second-word write and F-804adc29bbfb. The token supplied to the closing dependency is not an entry snapshot.

After initialization, capture Common word, then Default key, then Qbase. Separately read Qbase to compute the qualifier difference used by `0x6211` and `0x6212`. These are distinct source-level reads, although no dependency call separates them.

Unsupported operations still perform this entry processing.

### Shared reads, arithmetic, and completion

Shared is loaded at each call site that uses it. It is not universally captured at entry. In particular, a dependency updating one Shared object can be followed by an accessor receiving a different pointer if shared storage changes.

Other shared arguments are likewise loaded where specified below. Captured values remain captured across intervening calls; later loads must not be replaced by those captures. Ordering among argument reads within a single call expression is not independently established.

Arithmetic uses 32-bit operands. No overflow rejection is shown. Wrapped-word outcomes describe the machine-width interpretation; original signed-language overflow semantics remain unresolved. Index arithmetic and pointer additions have no visible overflow checks.

Two recurring completion forms are:

- **Shared accessor completion:** freshly load Shared, call F-44362605ab79, write its returned word, return one.
- **Common completion:** reread Common word, pass that current value and `0x32` to F-5f48d80484be, then write the entry-captured Common word and return one.

The value passed during common completion can differ from the value subsequently written.

For `0x6206` and `0x6213`–`0x6217`, a non-Qnumber qualifier takes the numeric fallback: compare its 32-bit difference from Qnumber with Qfallback, write zero, and return one on equality or zero otherwise. Other operations do not inherit this fallback.

### Operations `0x6201`–`0x6207`

**`0x6201`:** Compare the qualifier with a dispatch-time read of Qbase. A mismatch writes zero and returns one. Otherwise call F-d7e2779d5ed0 with the object and current Shared. Then reload Shared, call F-ecd1af0519f9, write its result, and return one.

**`0x6202` and `0x6204`:** Obtain a provider through F-9d0ecc5f6adf, then read the operation-specific key and resolve it through F-c0b020cd3882. Call F-7afe554bcf62 with an eight-byte temporary and the resolved word. Pass its returned word—not necessarily the temporary’s address—to F-46f0b3cb316e with current Shared. Call F-289ec4311c64 on the temporary. Reload Shared, call F-ecd1af0519f9, write its result, and return one. The operations use different key storage.

**`0x6206`:** For Qnumber, read the object word at `0x50`, add two, write the result, and return one. Otherwise use the numeric fallback.

**`0x6203`, `0x6205`, and `0x6207`:** Return zero without an explicit output write.

### Operations `0x6208`–`0x620c`

**`0x6208`:**

1. Invoke object entry `0xc0`. A zero result returns zero without writing output.
2. Pass the record word at `0x08` and the currently loaded operation-specific destination to F-dee541b2a059.
3. Reload that destination value for a potential output.
4. If qualifier plus Qservice-A is zero, write the reloaded destination and return one.
5. Otherwise, if qualifier plus Qservice-A plus Qservice-B is nonzero, return zero without writing output.
6. Otherwise obtain a provider, call F-682adfd5a561 with it and `0x80`, then call F-9b45bb70831a.
7. Perform common completion.

Rejected qualifiers can therefore still cause record selection and F-dee541b2a059 side effects.

**`0x6209`:** Invoke entry `0xc0`; a zero record returns one with output untouched. Otherwise pass its `0x08` word and the current destination to F-dee541b2a059. Obtain a provider and call F-682adfd5a561 with `0x80`. Treat its result as an object and invoke indirect entry `0x88`, explicitly supplying that object, freshly loaded Shared, one, and a freshly loaded destination. This destination load occurs after both service-acquisition calls; it need not equal the destination previously supplied to F-dee541b2a059. Finish with Shared accessor completion.

**`0x620a`:** A zero selected record also returns one without an output write. Otherwise call F-dee541b2a059 with the record’s `0x08` word and current destination. Afterward, reload the destination pointer and read its byte at offset three. Pass that byte, current Shared, and the address of a shared descriptor to F-1f62160dfd52. Finish with Shared accessor completion.

**`0x620b` and `0x620c`:** First require qualifier equality with a dispatch-time read of Qbase; only then invoke entry `0xc0`. A qualifier mismatch or zero record writes zero and returns zero.

On success, capture the record index at `0x04`, obtain a provider, then read the object’s table pointer at `0xa0` and the indexed key. Use the first word of the eight-byte pair for `0x620b`, the second for `0x620c`. Resolve the key through F-c0b020cd3882, call F-151ab4bfe553 with current Shared and the resolved word, and finish with Shared accessor completion. No table-index bound check is shown.

### Operations `0x620d`–`0x6210`

`0x620d`, `0x620e`, and `0x620f` first write zero to output, then invoke entry `0xc0`. A zero record returns zero. Otherwise compare the qualifier with the entry-captured Qbase; mismatch returns zero. These checks occur after the initial output write, so aliased object or shared storage can already have changed.

Successful paths differ:

- **`0x620d`:** Test the record word at `0x14` before obtaining a provider. Its zero/nonzero result selects which shared key storage will be used. Call F-9d0ecc5f6adf, then load the selected key value from that storage. Resolve it and call F-151ab4bfe553 with current Shared. The branch decision precedes provider acquisition, but the key-value load follows it.
- **`0x620e`:** Capture the record word at `0x18`, obtain a provider, then read the shared key base and add the captured word’s low eight bits. Resolve that key and call F-151ab4bfe553 with current Shared.
- **`0x620f`:** Call F-b9acea4b06ad with an eight-byte temporary and the record address plus `0x20`. Pass the temporary’s address with current Shared to F-46f0b3cb316e, then call F-289ec4311c64 on it.

Each successful path finishes with Shared accessor completion, overwriting the earlier zero.

**`0x6210`:** Return zero without explicitly writing output.

### Operations `0x6211` and `0x6212`

**`0x6211`:** Require an unsigned comparison in which the object index at `0x48` is below the bound at `0x94`, and require the preparation-time qualifier difference to be zero. Failure writes zero and returns zero.

Then read the index for a zero/nonzero branch:

- If zero, obtain a provider, resolve the entry-captured Default key, call F-151ab4bfe553 with current Shared, and finish with Shared accessor completion.
- If nonzero, obtain a provider, read and resolve the format key, construct an eight-byte temporary through F-7afe554bcf62, and call F-44362605ab79 on the temporary. After all those calls, reread both the object index and the table pointer at `0x90`. Read the second word of the resulting eight-byte entry. Pass current Shared, the temporary accessor result, and that entry word to F-1f62160dfd52. Finalize the temporary through F-289ec4311c64, then finish with Shared accessor completion.

The later table index is not the retained checked index. No second bound check or zero check is shown after the intervening dependencies.

**`0x6212`:** No unsigned bound check is performed.

For a zero preparation-time qualifier difference:

- A zero object index uses the Default-key path above.
- A nonzero index with zero at `0xb0` immediately uses Shared accessor completion, with no explicit preceding Shared update.
- Otherwise call F-5710a8628cba with the `0xb0` word and two shared operands. Retain its result across provider acquisition, format-key lookup, temporary construction, and the temporary’s F-44362605ab79 call. Pass current Shared, the temporary accessor result, and the retained conversion result to F-1f62160dfd52. Finalize the temporary, then use Shared accessor completion.

For a nonzero qualifier difference, adding Qalternate and obtaining zero returns one without an output write. Otherwise write zero and return zero.

For Qnumber:

### Operations `0x621a` and `0x621b`

Both interpret the word at `0x60` as signed. If below one, return one without writing output. Otherwise call F-82c63e47892d with the embedded collection at `0x5c` and index zero, then dereference its returned address to obtain a record pointer. Neither operation checks the qualifier.

**`0x621a`:** If the byte at record offset `0x2c` is zero, call F-3c6b67b2a91d with its `0x30` word. Otherwise capture its `0x04` index, obtain a provider, then read the object table pointer at `0xa0` and the second key of the indexed eight-byte pair; resolve that key. Write the resulting dependency return and return one.

**`0x621b`:**

1. Pass the record’s `0x0c` word and a four-byte local destination to F-dee541b2a059.
2. Obtain a provider, call F-682adfd5a561 with `0x80`, then obtain a base address from F-9b45bb70831a.
3. Call F-3ec7d07fef90 with base plus `0x32f` and a shared descriptor’s address.
4. If the result is nonzero, form its displacement from the retained base. Invoke an unmapped external copy dependency targeting a 32-byte local area, sourcing from base plus `0x32f`, with length displacement minus `0x32f`. Then call F-e7c5183babcf with a destination formed by adding the displacement to a separate 807-byte local area, and a source three bytes beyond the search result.
5. Perform common completion regardless of whether the search returned zero.

No validation of the copy length or displacement is shown.

## Side effects

Direct writes include initialization-object words and operation-dependent output writes. Dependencies receive shared objects, object storage, and local destinations and may have additional effects.

Initial output clearing in `0x620d`–`0x620f` precedes record selection. Output aliasing can therefore affect subsequent reads. Likewise, an explicit “untouched output” path guarantees only absence of a direct output write, not absence of dependency writes through aliases.

Eight-byte temporaries exhibit construction, use, and finalization-shaped calls. This does not establish allocation, ownership transfer, retention, release, or output lifetime. No explicit release of output words is shown.

There is no visible rollback, general dependency-failure handling, or synchronization around later shared-state use.

## Acceptance examples

These are conditional static examples, not executed tests. Assume valid accesses and normal dependency returns. Assume relevant values remain unchanged except where mutation is explicitly stipulated.

- `0x6203` returns zero without directly replacing an output sentinel; entry initialization can still occur.
- A clear initialization bit followed by a zero gate result still causes the operand and Shared loads, but no initialization-body writes.
- If F-804adc29bbfb changes the initialization-token storage, F-d08d3ca17b81 receives the changed token.
- In `0x620d`, if the record condition selects one key storage and provider acquisition changes that storage, lookup receives the changed key. The record condition is not retested.
- In `0x6209`, changing destination storage during service acquisition changes the destination passed to entry `0x88`; it does not retroactively change the earlier F-dee541b2a059 argument.
- In `0x620a`, if F-dee541b2a059 changes the destination pointer, the byte comes from offset three of the replacement destination.
- In `0x6211`, an initially checked index of two below bound ten can later be changed to twelve by a dependency. The table access uses twelve without another bound check, provided that access is valid.
- `0x6206` with Qnumber and `0xffffffff` at `0x50` produces one under 32-bit wrapping arithmetic.
- `0x6209` with a zero selected record returns one without directly writing output.
- `0x620d` with a zero selected record writes zero before returning zero.
- `0x6217` maps indirect results zero, one, and five to zero, zero, and four.
- `0x6218` with Qbyte and byte `0xfe` writes `0x000000fe`; qualifier mismatch returns one without a direct write.
- `0x621a` with count negative one skips collection access and returns one without a direct write.
- If Common word changes after its entry capture, common completion passes the current word to F-5f48d80484be but writes the captured word to output.

- Dependency mutation, failure, exception, allocation, ownership, retention, and release behavior.

- Complete indirect-call conventions, especially the argument-free shown invocation for `0x6217`.

- External copy identity, exact semantics, and recovered local-area layout.
- Safety of `0x621b`: the first copy is not visibly limited to 32 bytes, and the displacement-derived destination is not visibly constrained to the 807-byte area. This establishes missing visible checks, not a definitive runtime overflow.
- Thread safety, reentrancy, and initialization-gate guarantees.
