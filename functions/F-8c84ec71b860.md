# F-8c84ec71b860

## Purpose

F-8c84ec71b860 transforms two scalar inputs into a table-derived integer and supplies that integer to an unresolved indirect-transfer dependency. Three input conditions cause an immediate return without table access or indirect transfer.

The visible transformation combines:

- A normalization count derived from the low 16 bits of the first input.
- Linear interpolation between adjacent unsigned 16-bit entries in a first table.
- Signed scaling by the second input.
- Linear interpolation in a second unsigned 16-bit table.
- A final right shift whose count comes from the intermediate scaled value.

**Inferred intent:** the arrangement resembles a fixed-point power or related nonlinear transform implemented through two lookup tables. Neither that mathematical interpretation nor the contents of either table are established. The behavioral contract is the integer transformation described below, not a particular real-valued function.

## Behavior

### Early-return precedence

The function returns immediately if any of the following holds:

1. \(e=0\).
2. \(x=65536\).
3. \(x=0\).

The first two conditions are evaluated before the separate zero check for \(x\). All three produce the same visible outcome: no table access and no indirect transfer.

In particular, \(x=65536\) is an explicit bypass, not an ordinary normalization case. No equivalent bypass is established for other values whose low 16 bits are zero.

### Arithmetic conventions

The following notation describes observable values without relying on a high-level mathematical approximation:

- \(\operatorname{wrap}_{32}(v)\) retains the low 32 bits of \(v\).
- \(\operatorname{signed}_{32}(v)\) interprets a 32-bit word as signed two’s-complement.
- \(\lfloor v/d\rfloor\), for positive \(d\), rounds toward negative infinity.

The product extraction in the supplied representation takes bits 16 through 47 of a signed 64-bit product and interprets the resulting word as signed 32-bit. This corresponds to a signed right shift by 16 followed by retention of 32 bits. For the operand ranges here, the extracted values fit in signed 32 bits, so the formulas below can use floor division directly.

This distinction matters for negative products: extraction is not division rounded toward zero.

### Normalization

Let \(u\) be the low 16 bits of \(x\).

If \(u\ne0\), let \(h\) be the position of its highest set bit, numbered from 0 through 15. The normalization count is:

\[
s=15-h.
\]

If \(u=0\), the normalization count is \(s=15\).

Thus \(s\) is always between 0 and 15. For ordinary positive inputs below 65536, shifting left by \(s\) puts the highest set bit at position 15.

The normalized word is:

\[
n=\operatorname{wrap}_{32}(x\,2^s).
\]

The first lookup uses only the low 15 bits of this word. The supplied representation does not reject larger first inputs, clamp them to 16 bits, or normalize according to their highest set bit across all 32 bits.

Although the normalization operations include signed right shifts, the inspected bit groups produce the low-16-bit count specified above.

### First interpolation

Let \(A[k]\) denote unsigned 16-bit entries in the first table.

The selected index and interpolation fraction are:

\[
i=(n\bmod32768)\mathbin{\mathrm{div}}4096,
\qquad
f=n\bmod4096.
\]

Their ranges are:

- \(0\le i\le7\).
- \(0\le f\le4095\).

The function reads \(A[i]\), then \(A[i+1]\). Both reads occur even when \(f=0\).

The first interpolated value is:

\[
a=A[i]+\left\lfloor
\frac{f\left(A[i+1]-A[i]\right)}{4096}
\right\rfloor.
\]

Important properties:

- Each table entry is zero-extended from 16 bits.
- The difference between adjacent entries is signed; it does not wrap as a 16-bit unsigned subtraction.
- Descending adjacent entries are supported by the arithmetic.
- The interpolation rounds downward, including when the difference is negative.
- No monotonicity assumption is required.
- \(a\) remains between the two adjacent entries, inclusive, and therefore lies in \(0\ldots65535\).

The highest possible referenced table entry is \(A[8]\).

### Scaling and combination

The first interpolated value is multiplied by signed \(e\), using a signed 64-bit product. The extracted scaled contribution is:

\[
q=\left\lfloor\frac{e\,a}{65536}\right\rfloor.
\]

The intermediate 32-bit word is then:

\[
w=\operatorname{wrap}_{32}(s\,e+q).
\]

This combination is modulo \(2^{32}\), not saturating arithmetic. Negative second inputs participate in this same computation; there is no sign-based rejection.

The two products have adequate 64-bit range:

- The first interpolation product uses a fraction multiplier no greater than 65520 and a signed difference of magnitude no greater than 65535.
- The scaling product uses signed 32-bit \(e\) and \(a\) in \(0\ldots65535\).

No signed 64-bit overflow is needed to describe either product.

### Second interpolation

Let \(B[k]\) denote unsigned 16-bit entries in the second table.

The second lookup uses only the low 16 bits of \(w\):

\[
j=(w\bmod65536)\mathbin{\mathrm{div}}8192,
\qquad
g=w\bmod8192.
\]

Their ranges are:

- \(0\le j\le7\).
- \(0\le g\le8191\).

The function reads \(B[j]\), then \(B[j+1]\), including when \(g=0\).

The second interpolated value is:

\[
b=B[j]+\left\lfloor
\frac{g\left(B[j+1]-B[j]\right)}{8192}
\right\rfloor.
\]

The same signed-difference and downward-rounding rules apply. Consequently, \(b\) lies in \(0\ldots65535\). The highest possible referenced entry is \(B[8]\).

### Final shift and indirect transfer

The encoded shift count is bits 16 through 23 of \(w\):

\[
r=(w\mathbin{\mathrm{div}}65536)\bmod256.
\]

The supplied representation obtains this byte through a signed right shift followed by masking. The resulting byte is the same for either signed or unsigned interpretation of \(w\).

For \(0\le r\le31\), the argument supplied to F-unresolved is:

\[
y=b\mathbin{\mathrm{div}}2^r.
\]

The final operation is represented as a signed 32-bit right shift. Since \(b\) is nonnegative, arithmetic and logical right shifts agree for these counts. In particular, every count from 16 through 31 produces zero.

For \(32\le r\le255\), the argument is **documented_only**: the supplied representation does not establish the target’s effective oversized-shift semantics. This contract does not assume count masking, a zero result, or a fault.

After computing the argument, the visible representation performs one unresolved indirect transfer. No earlier dependency invocation is visible.

## Acceptance examples

These are conditional acceptance criteria derived statically. They are not runtime observations.

### Bypass conditions

- For any \(x\), \(e=0\) must cause return without either table being read and without the indirect transfer.
- For \(x=65536\), any signed \(e\) must take the same bypass.
- For \(x=0\) and nonzero \(e\), the function must also return without table access.

These conditions do not depend on table contents.

### Ordinary normalization

With \(x=32768\) and \(e=1\):

- \(s=0\), \(n=32768\).
- The first lookup selects entries 0 and 1 with fraction zero.
- \(a=A[0]\).
- Because \(A[0]\le65535\), \(q=0\), so \(w=0\).
- The second lookup selects entries 0 and 1 with fraction zero.
- The outgoing argument is \(B[0]\).

Both successor entries are still read despite the zero fractions.

With \(x=1\) and \(e=1\), the corresponding count is \(s=15\), the first fraction is zero, and \(w=15\). The second lookup therefore uses entries 0 and 1 with fraction 15 and shift count zero.

### Interpolation rounding

If a selected first-table pair is 100 followed by 99, and its fraction is 1, the first interpolated value is 99, not 100:

\[
100+\lfloor-1/4096\rfloor=99.
\]

The analogous descending second-table pair with fraction 1 also produces 99. Implementations that truncate negative interpolation terms toward zero do not satisfy this behavior.

### Signed scaling

For \(x=32768\), \(e=-1\), and \(A[0]=1\):

- The scaled contribution is \(-1\), not zero.
- \(w\) is the 32-bit word with all bits set.
- The second index is 7 and the fraction is 8191.
- The encoded final shift count is 255.

The lookup behavior is established. The final argument remains documented_only until oversized-shift semantics are established.

### Inputs above the nominal normalization range

With \(x=131072\) and \(e=1\):

- The explicit 65536 bypass does not apply.
- The low 16 bits are zero, so \(s=15\).
- The normalized 32-bit word is zero after wrapping.
- The first lookup selects entries 0 and 1 with fraction zero.
- \(w=15\).

Rejecting this input or treating it as the 65536 bypass would add behavior absent from the supplied representation.
