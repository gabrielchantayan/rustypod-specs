# F-e409dfa213c9

## Purpose

F-e409dfa213c9 conditionally updates two signed state fields from a current-state value and a signed quantity obtained through an indirect reference.

The established behavior is a gated state transformation:

- A dependency is invoked before any explicit access to the supplied record.
- A zero dependency result suppresses all subsequent record accesses and updates by this function.
- A nonzero result enables a branch-dependent update of two fields.
- The values −2 and −3 receive special treatment.
- Other current-state values are processed using successor and predecessor arithmetic.

**Inferred intent:** the two output fields resemble forward and backward navigation states, and the indirect quantity resembles a collection size. The supplied evidence does not establish those meanings. This contract therefore uses neutral field names and specifies the numeric behavior without assigning application semantics.

## Interface

The function accepts one pointer-like argument identifying a mutable record. It has no explicit return value. Its observable results are its dependency invocation, memory accesses, and record writes.

The record contains at least four consecutive signed-integer slots:

| Slot | Contract name | Access by this function |
|---|---|---|
| 0 | Indirect reference | Read to locate the quantity |

The contract names identify positions and uses; they do not establish domain meanings.

The indirect reference is interpreted as an address. A signed integer is read at byte displacement +4 from that address. This is the **quantity**.

## Behavior

### Gate and initial observations

The function first calls F-392d97f6cbd4 without explicit arguments.

If its result equals zero, the function returns immediately. It performs no explicit record read or write on that path.

If the result is nonzero, the function observes inputs in this order:

1. It reads the current-state field.
2. It reads the indirect-reference field and obtains the quantity at displacement +4 from the referenced address.

The current state and initial quantity are then retained for branch selection and, except where stated otherwise, for subsequent calculations. They are observed after the dependency call, not before it.

No claim is made that the dependency leaves memory or global state unchanged.

### Initial quantity less than one

This branch covers every initial quantity less than or equal to zero.

If the captured current state is not −2:

- The forward output is written as −3.
- The backward output is then written as −3.
- The function returns.

This includes current state −3 and every ordinary numeric current-state value. Neither arithmetic nor a second quantity lookup is required on this path.

If the captured current state is −2:

- The forward output is written as −2.
- The backward output is then written as −2.
- The function returns.

The magnitude of a nonpositive quantity does not otherwise affect the selected outputs.

### Positive initial quantity and current state −2

When the initial quantity is positive and the captured current state is −2:

- The forward output is written as zero.
- The backward output is then written as −2.
- The function returns.

This path does not reread the indirect reference or quantity. The initial positive quantity only selects the branch; its exact value does not otherwise influence the outputs.

### Positive initial quantity and current state −3

When the initial quantity is positive and the captured current state is −3:

- The forward output is written as −3.
- The indirect-reference field is read again.
- The quantity at displacement +4 from that newly read reference is read again.
- One is subtracted from the second quantity.
- That result is written to the backward output.
- The function returns.

The backward output therefore depends on the **second** quantity observation, not necessarily on the positive quantity that selected the branch.

The second lookup occurs after the forward-output write. This ordering is significant if the record and referenced storage overlap. For example, if the quantity location is the forward-output location, the forward write changes the quantity to −3 before the second lookup; the backward output consequently becomes −4.

There is no second positivity check. A zero or negative second quantity is still decremented, subject to arithmetic being defined.

### Positive initial quantity and every other current state

For a positive initial quantity and a captured current state other than −2 or −3, the function uses the following update sequence:

1. Compute the successor, equal to the captured current state plus one.
2. Write that successor to the forward output.
3. Compare the captured initial quantity against the successor.
4. If the quantity is less than or equal to the successor, overwrite the forward output with −3.
5. Compute the predecessor, equal to the captured current state minus one.
6. Write that predecessor to the backward output.
7. If the predecessor is negative, overwrite the backward output with −2.

Thus, when the arithmetic is defined:

- The final forward output is the successor if it is strictly less than the initial quantity; otherwise it is −3.
- The final backward output is the predecessor if it is nonnegative; otherwise it is −2.

These final-value rules do not replace the write-order requirements. An output may receive an intermediate value before being overwritten.

There is no general check that the current state lies within a valid range. In particular:

- A current state of zero produces backward output −2.
- A current state of one produces backward output zero.
- A current state of −1 enters this ordinary arithmetic branch.
- Other negative values, except the two special values, also enter this branch.
- An oversized positive current state can produce forward output −3 while retaining a large nonnegative predecessor.

### Arithmetic boundaries

The visible arithmetic consists of adding one or subtracting one from signed values.

The supplied evidence does not establish overflow behavior. Consequently:

- For an ordinary current state at the maximum representable signed value, the successor computation is not covered by a portable defined-result guarantee.
- For an ordinary current state at the minimum representable signed value, the predecessor computation is not covered by such a guarantee.
- In the special −3 branch, a second quantity at the minimum representable signed value presents the same decrement issue.

Under a signed 32-bit interpretation, these boundaries are 2,147,483,647 and −2,147,483,648. Those numbers are conditional on the width interpretation.

No wraparound, saturation, trapping, or recovery rule is established. In particular, the function must not be described as a safe range-clamping operation for arbitrary signed inputs.

## Side effects

### Record writes

On every enabled path that completes normally, both output fields are written.

The forward output is written before the backward output. Additional writes can occur:

- The ordinary branch can overwrite the forward successor with −3.
- The ordinary branch can overwrite a negative backward predecessor with −2.

The function does not explicitly assign the current-state or indirect-reference fields.

That statement is about designated destinations, not an unrestricted noninterference guarantee. Storage aliasing, concurrent changes, and dependency effects can alter what is observed.

### Read/write ordering and aliasing

Two distinctions are externally important:

- The ordinary branch compares against the initially captured quantity, even if its forward-output write changes aliased quantity storage.
- The special −3 branch rereads the indirect quantity after its forward-output write.

The current state is not reread after its initial capture. The indirect reference is reread only in the special −3, initially positive-quantity branch.

These are the source-level access sequences established by the supplied representation. It does not establish volatile accesses, atomic operations, synchronization, memory barriers, or machine-level observability of every intermediate store.
