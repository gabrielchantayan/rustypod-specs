# F-74309d0b2815

## Purpose

F-74309d0b2815 conditionally produces a 64-bit result using a caller-supplied object reference, a signed selector, and a temporary 24-byte workspace.

The established behavior is a gated dependency sequence:

- Require a nonzero 32-bit field at byte offset 12 from the supplied object address.
- Require a nonnegative selector.
- Prepare temporary state through F-88e2e41f5074.
- Require nonzero results from F-93c11d1bbd21 and then F-d188b04cd865.
- Obtain the result from F-c7d9600c0979 only when both checks succeed.
- Invoke F-4e292a3dd745 after the preparation call and subsequent checks complete normally, including when either check fails.

The default result is the all-zero 64-bit value. The available evidence does not identify the result as an integer quantity, pointer, handle, or other domain value. In particular, zero is an established return value for several paths, not a proven error code.

A plausible intent is to prepare, validate, extract from, and finalize temporary state. Those descriptions are inferred roles, not established contracts of the dependencies.

## Behavior

### Initial field access and selector gate

The first externally relevant operation established by the body is a 32-bit read at byte offset 12 from the object address. This read occurs before the selector is used to decide whether to continue.

If the value read is zero, the function returns the all-zero 64-bit result. No dependency is invoked.

If the value is nonzero, the function checks whether the selector is nonnegative. A negative selector also produces the all-zero result without invoking any dependency.

Consequently, a negative selector does not prevent the initial object-field access. A caller cannot use a negative selector to make an otherwise invalid object reference safe.

The field test is a zero/nonzero test, not a positivity test. A field value with its sign bit set still satisfies this initial gate.

### Workspace preparation

When both initial conditions pass, the function supplies a temporary 24-byte workspace to F-88e2e41f5074.

The dependency receives four arguments, in this order:

1. The workspace address.
2. A freshly read 32-bit value from the object field at offset 12.
3. The original signed selector.
4. A zero-valued argument.

The body does not visibly initialize the workspace bytes before this call. It therefore does not establish that the workspace initially contains zeros or any other meaningful pattern.

There are two distinct source-level reads of the object field on this path: one for the gate and another for the preparation argument. No dependency is called between them, and the body does not write that field between the reads.

The preparation argument is not explicitly cached from the first read. Under ordinary stable-memory conditions, the two reads provide the same value. If the environment permits intervening changes, the supplied evidence does not establish synchronization, atomicity, or a concurrency contract. In particular, the wrapper does not visibly recheck the freshly read value before passing it onward.

The return value of F-88e2e41f5074, if any, is not used by this function. Normal return from that dependency is followed by the first check.

### Ordered checks

F-93c11d1bbd21 receives the workspace address and produces a 32-bit check result.

If that result is zero:

- F-d188b04cd865 is not called.
- F-c7d9600c0979 is not called.
- The selected result remains the all-zero 64-bit value.
- Execution proceeds to F-4e292a3dd745.

If the result is nonzero, F-d188b04cd865 receives the same workspace address and produces another 32-bit check result.

If the second result is zero:

- F-c7d9600c0979 is not called.
- The selected result remains all zero.
- Execution proceeds to F-4e292a3dd745.

If the second result is nonzero, execution proceeds to result acquisition.

Both checks use zero versus nonzero semantics. Negative results count as passing these gates; the function does not treat them as errors merely because they are negative. The check results are not returned to the caller.

### Result acquisition

F-c7d9600c0979 is called only after both checks have returned nonzero. It receives the workspace address.

Its eight-byte result becomes the selected return value. The wrapper applies no visible transformation, range check, null check, decoding, or interpretation to that value.

There is no retry or alternate acquisition path.

### Finalization and return

After F-88e2e41f5074 has returned normally, every visible normal path reaches one call to F-4e292a3dd745 with the workspace address.

This includes paths where:

- The first check returns zero.
- The second check returns zero.

The selected 64-bit result is not visibly replaced by a finalization status. This establishes which value is returned on normal completion; it does not establish that finalization preserves globals, keeps referenced resources alive, or cannot fail.
