# F-4a2dd7568c54

## Purpose

F-4a2dd7568c54 validates a size-request descriptor and chooses one of three operations on a supplied object:

- Delegate to an installed callback.
- Match and select a bitmap strike when the object’s flags satisfy a particular condition.
- Invoke a fallback operation and report success.

This purpose is inferred from the request validation, dispatch structure, and bitmap-strike diagnostic. The established behavior is the branching, memory access, dependency invocation, and result propagation described below. The physical meaning of the requested dimensions, request categories, and fallback operation is not established.

Validation precedes all dispatch. An installed callback takes precedence over flag-based bitmap selection and fallback processing.

### Output

The result is a 32-bit integer:

- **35** if the first argument is zero.
- **6** if the first argument is nonzero but the request pointer is null or a locally checked request field is invalid.
- The callback’s result, unchanged, if a callback is installed.
- A nonzero bitmap-matching result, unchanged, if matching fails.
- The bitmap-selection result, unchanged, if matching succeeds.
- **0** after invoking the fallback operation.

There is no local conversion or normalization of dependency results.

The function does not visibly check object type, object lifetime, alignment, nested-pointer validity, or callback signature compatibility. Invalid memory can cause a memory-access failure rather than one of the returned validation values.

## Behavior

### Validation and its ordering

The first decision tests whether the object argument is zero. If so, the function returns 35 without reading the request or any object field.

For a nonzero object argument, a null request pointer causes result 6. No object-field access is visible on this path.

For a nonnull request pointer, the validation reads are ordered as follows:

1. Read the signed 32-bit field at request offset 4.
2. Only if that field is nonnegative, read the signed 32-bit field at request offset 8.
3. Only if both fields are nonnegative, read the unsigned byte at request offset 0 and require it to be less than 5.

Failure at any stage returns 6. Consequently, a negative field at offset 4 prevents reads of both the offset-8 field and the category byte. A negative field at offset 8 prevents the category-byte read.

Zero is accepted for both signed fields. The largest accepted value for either field is 2,147,483,647. A 32-bit pattern with its sign bit set is rejected when interpreted as either signed field. No local check relates the two fields or relates their values to the category.

### Callback lookup and priority

After successful validation, the function traverses the nested dispatch structure and reads the callback address. This lookup occurs before it considers the object’s flags.

The fourth argument is then copied into a local 32-bit slot.

If the callback address is nonzero:

- The function reads the 32-bit value at object offset 88.
- It invokes the callback with that value as the sole explicitly supplied argument visible in the evidence.
- It immediately returns the callback result.

Neither the request pointer nor the third or fourth argument is visibly supplied as a callback argument. The function performs no local flag test, bitmap matching, bitmap selection, fallback call, or diagnostic operation on this path.

A null callback address is supported. A null intermediate dispatch address is not explicitly supported, because the lookup dereferences intermediate addresses without checks.

### Flag-controlled path without a callback

If the callback address is zero, the function examines the flags at object offset 8.

The bitmap path requires both of these observations:

- Mask 1 is clear.
- Mask 2 is set.

The source expresses these as two accesses to the same flags field, with the second conditioned on the first test succeeding. If mask 1 is set in the first observation, the second test is skipped.

For an unchanged flags value, the resulting classification is:

| Mask 1 | Mask 2 | Path |
|---|---|---|
| Clear | Clear | Fallback |
| Clear | Set | Bitmap matching |
| Set | Clear | Fallback |
| Set | Set | Fallback |

Other bits do not affect these local decisions. The table assumes the flags do not change between observations; the visible function supplies no synchronization or atomic-snapshot guarantee.

### Bitmap matching and selection

On the bitmap path, F-e2c2ee4f661d is called with:

- The original object argument.
- The original request pointer.
- A literal zero.
- The address of the local 32-bit slot initialized from the fourth argument.

This dependency can write the slot through the supplied address.

If matching returns a nonzero result, the function returns that result immediately. It does not read the diagnostic level, emit the visible diagnostic, or invoke selection.

If matching returns zero:

1. The function reads a signed 32-bit diagnostic-level field at byte offset 28 from a globally referenced diagnostic object.
2. If that field is greater than 2, it invokes F-4457a9a44a68 with a fixed bitmap-strike diagnostic format and the slot’s current 32-bit value.
3. It invokes F-891fd9332cbe with the original object argument and the slot’s value as read for that call.
4. It returns the selection result unchanged.

The diagnostic therefore precedes selection. Its condition is a signed comparison: levels 2 and below do not trigger the diagnostic, while levels 3 and above do.

The matching call’s zero result is the only visible gate to diagnostic processing and selection. The function does not independently check that the output slot was written, that its value denotes a valid strike, or that it is in range. If matching returns zero without changing the slot, the value initialized from the fourth argument remains available for subsequent use.

No result from the diagnostic call is used. There is also no visible snapshot protecting the selection argument from effects an unknown dependency might have through previously exposed state.

### Fallback

If no callback is installed and the flag condition does not select bitmap matching, the function calls F-25956899d179 with the object argument.

After that call returns normally, F-4a2dd7568c54 returns zero. No return value from the fallback call is inspected or propagated.

This establishes a success result from this wrapper, not proof that the fallback completed a particular size change.

## Acceptance examples

These examples are conditional behavioral expectations derived from static evidence. No runtime tests have been performed. Except where an example deliberately stops before an access, all required memory and dependency calls are assumed valid.

1. **Zero object takes precedence.**  
   With a zero object argument, the result is 35 even if the request pointer is null or unreadable. The request is not accessed.

2. **Null request is rejected before dispatch lookup.**  
   With a nonzero object argument and a null request pointer, the result is 6. No object field or dependency is accessed.

3. **First negative field short-circuits later validation.**  
   If request offset 4 contains −1, the result is 6 without reading request offset 8 or offset 0.

4. **Second negative field prevents category access.**  
   If offset 4 contains zero and offset 8 contains −1, the result is 6 without reading the category byte.

5. **Category boundary is exclusive at five.**  
   With both signed fields nonnegative, category 4 passes local validation. Category 5 returns 6. Passing validation alone does not establish the final result.

6. **Zero dimensions are locally acceptable.**  
   Category 0 with both signed fields zero reaches dispatch lookup. A dependency can still reject the request.

7. **Callback overrides bitmap flags.**  
   Given a valid request and an installed callback, even flags with mask 1 clear and mask 2 set do not cause bitmap matching. If the callback returns −7, this function returns −7.

8. **Matching failure prevents selection.**  
   With no callback and stable flags value 2, matching is invoked. If it returns 9, the result is 9, with no diagnostic-level read and no selection call.

9. **Matching success uses the output slot.**  
   If matching writes 12 into the slot and returns zero, selection receives 12, provided no intervening dependency changes the accessible slot state. If selection returns 4, the final result is 4.

10. **Unchanged output retains the fourth argument.**  
    If matching returns zero without writing the slot, a fourth argument of 23 supplies the slot value for subsequent processing, absent other mutation.

11. **Diagnostic threshold affects call order.**

12. **Fallback result is not propagated.**
