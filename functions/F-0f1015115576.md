# F-0f1015115576

## Purpose

F-0f1015115576 obtains a signed 32-bit baseline result from an indirect operation on an object, then returns that result unchanged or reduced by one, two, three, or four. The adjustment depends on a discriminator read from the object **after the indirect operation returns**. One discriminator value additionally selects a width classification of a second 32-bit field.

The established behavior is a numerical adjustment, not an encoding operation: this function does not itself emit bytes, validate a character, allocate storage, or explicitly update the object.

The thresholds used for the additional classification resemble UTF-8 encoded widths. That resemblance is inferred intent only. The observable classification includes mixed signed and unsigned comparisons and is not equivalent to Unicode scalar-value validation.

## Interface

**Input**

One object address. The supplied source describes a 32-bit layout with the following relevant fields:

| Byte offset from object | Width | Role |
|---|---:|---|
| +0 | 32 bits | Address used as the base of an indirect-operation table |
| +4 | 32 bits | Signed discriminator, read after the indirect call |
| +8 | 32 bits | Classification value, read only when the discriminator is exactly 100 |

The operation-table entry at byte offset +12 supplies the callable target. In the supplied 32-bit model, this is a pointer-sized entry. The object address is passed to that target as its sole explicit argument.

**Output**

A signed 32-bit integer derived from the indirect operation’s signed 32-bit return value.

Let **B** denote that returned baseline. For executions whose subtraction is representable in signed 32-bit arithmetic, the result is either B or B minus the selected adjustment.

The supplied evidence does not establish a portable overflow rule for subtraction below −2,147,483,648. Such executions are `documented_only`; acceptance of wraparound would require additional evidence.

**Preconditions for an ordinary return**

- The input address supports the initial 32-bit field read.
- The address obtained from that field supports fetching the callable entry at offset +12.
- The fetched entry is a valid callable target with a compatible calling convention and result representation.
- The indirect operation returns normally.
- After that return, the original object address still supports reading the discriminator.
- If the post-call discriminator is 100, the object also supports reading the classification value.

These are access and callability requirements, not checks performed by F-0f1015115576. No null-pointer, object-size, target-validity, or lifetime validation is visible.

## Behavior

### Observable sequence

For a normal execution, the relevant ordering is:

1. Read the operation-table address from the object at offset +0.
2. Fetch the callable target from that table at offset +12.
3. Invoke the target, passing the original object address.
4. Retain its returned signed 32-bit baseline.
5. Read the signed 32-bit discriminator from the original object at offset +4.
6. Only if that discriminator is 100, read the 32-bit classification value at offset +8.
7. Select the adjustment and return the adjusted baseline.

The object’s discriminator and classification value are not captured before the call. Changes made by the indirect operation therefore affect the classification performed by this function.

The target is selected using the operation-table address read before the call. There is no second operation-table lookup after the call. Changes to that address during the call do not cause another dispatch within this invocation.

The retained baseline remains the basis for the final result even when the indirect operation changes object fields.

### Discriminator selection

The discriminator is interpreted as a signed 32-bit integer.

| Post-call discriminator | Adjustment subtracted from B |
|---|---:|
| 0 | 0 |
| 1 | 1 |
| 2 | 1 |
| 3 | 2 |
| 4 | 1 |
| 5 | 2 |
| 6 | 3 |
| 100 | Determined by the classification value |
| Every other signed 32-bit value | 0 |

In particular:

- Negative discriminator values return B unchanged.
- Values between 7 and 99 return B unchanged.
- Values above 100 return B unchanged.
- An unsupported discriminator does not trigger a visible error response.
- For every discriminator except 100, the field at offset +8 is unnecessary to the visible computation and is not read by this function.

### Classification when the discriminator is 100

The classification value is a 32-bit bit pattern. Its first comparison is unsigned; subsequent relevant comparisons use its signed 32-bit interpretation.

The complete classification is:

| Classification-value bit pattern, shown as an unsigned value | Adjustment |
|---|---:|
| 0 through 127 | 1 |
| 128 through 2,047 | 2 |
| 2,048 through 65,535 | 3 |
| 65,536 through 1,114,111 | 4 |
| 1,114,112 through 2,147,483,647 | 0 |
| 2,147,483,648 through 4,294,967,295 | 2 |

The final row is important. These bit patterns fail the initial unsigned comparison against 128, but their signed interpretations are negative and therefore less than 2,048. They receive an adjustment of two, not zero.

Equivalent hexadecimal boundaries are:

- 0x00000000–0x0000007F: subtract one.
- 0x00000080–0x000007FF: subtract two.
- 0x00000800–0x0000FFFF: subtract three.
- 0x00010000–0x0010FFFF: subtract four.
- 0x00110000–0x7FFFFFFF: no adjustment.
- 0x80000000–0xFFFFFFFF: subtract two.

This classification does not reject surrogate-range values. For example, values from 0xD800 through 0xDFFF receive an adjustment of three. Other values inside the stated ranges are likewise classified solely by the comparisons, without an additional validity check.

### Arithmetic and return behavior

The adjustment is selected independently of the sign or magnitude of B. There is no visible saturation, lower-bound guard, or alternate treatment for negative baselines.

For representable results:

- B = 0 with an adjustment of three returns −3.
- A negative B is reduced further by a nonzero adjustment.
- An adjustment of zero returns B exactly.

No positive adjustment is performed. Consequently, the identified arithmetic concern is underflow below the signed 32-bit minimum, not overflow above the signed maximum.

If an adjustment of **d** is nonzero, ordinary signed arithmetic is representable when B is at least −2,147,483,648 + d. The evidence does not settle behavior below that bound.
