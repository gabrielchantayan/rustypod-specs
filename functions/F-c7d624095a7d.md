# F-c7d624095a7d

## Purpose

F-c7d624095a7d copies a 16-by-16 array of opaque 32-bit elements into four destination bands. Within each destination row, each source element is written once near the beginning of the row and once at the horizontally reflected position in a 180-element row. A second destination region receives the same arrangement using source rows in reverse order.

The displacement between the two destination regions is read from external state. Its value is not established by the supplied evidence. Consequently, the operation does not establish that the regions are disjoint, adjacent, or parts of a particular image.

The second argument selects between two statically identical execution paths. Values equal to 2 or 3 select one path; every other value selects the other. Both paths have the same reads, writes, bounds, and ordering.

An image-border or symmetry operation is plausible inferred intent. The established behavior is copying and reflecting 32-bit elements; element interpretation, image dimensions beyond the observed row stride, and application-level purpose remain unknown.

## Interface

The function takes three arguments and has no explicit return value.

| Input | Established role |
|---|---|
| First argument | Address of an object containing the source base address in its four-byte field at byte offset `0x10C` (268). |
| Second argument | Integer selector, compared with 2 and 3. It does not change the resulting memory-operation sequence. |
| Third argument | Address of an object containing the destination base address in its four-byte field at byte offset 4. |

One additional input comes from external state:

- A four-byte global value supplies a destination-region displacement.
- The displacement is used in **elements**, not bytes.
- Each element is four bytes.

For the descriptions below:

- \(S\) is the source base address captured from the first argument’s object.
- \(D\) is the destination base address captured from the third argument’s object.
- \(K\) is the captured global displacement, measured in four-byte elements.
- \(r\) and \(c\) denote row and column coordinates, each ranging from 0 through 15.

These are descriptive symbols, not additional parameters.

### Widths and representation

The supplied representation uses 32-bit integer/address quantities and four-byte element transfers. The function treats element contents as opaque 32-bit values. It performs no element-value arithmetic, conversion, masking, comparison, or byte-order transformation.

The selector is represented as a 32-bit integer. Only equality with the integer values 2 and 3 is inspected; its sign and magnitude otherwise have no effect.

The global displacement participates in integer address calculations. Its permissible range and intended signedness are not independently documented. The mathematical formulas below describe ordinary valid-address executions; they do not establish portable behavior for overflowing arithmetic.

### Preconditions for a fully defined copy

A caller must provide:

- Readable four-byte fields at the two object offsets specified above.
- Readable storage for every source element actually accessed.
- Writable storage for every destination element actually accessed.
- Addresses and arithmetic compatible with the target’s pointer representation, alignment requirements, and memory model.

For a conventional, nonwrapping source layout, the accessed source data occupies 256 consecutive four-byte elements, or 1,024 bytes.

Aliasing is not checked or rejected. Source/destination overlap can change later reads. Therefore, interpreting the result as a transformation of an unchanged original source additionally requires that destination writes not modify source locations before those locations are read, or that any such modifications be irrelevant to the expected values.

No ownership transfer is evidenced.

## Behavior

### Input capture

Before processing elements, the function performs these reads in the order shown:

1. Reads the global destination-region displacement.
2. Reads the source base address from byte offset 268 of the first argument’s object.
3. Reads the destination base address from byte offset 4 of the third argument’s object.

These three values are retained for the remainder of the operation. The function does not reload either object field or the global displacement during the copy.

It then selects a path according to the second argument. One path is selected for 2 or 3 and the other for all remaining values. The two paths implement the same behavior described below.

### Traversal and read order

Rows are processed in ascending order, from 0 through 15. Within each row, columns are processed in ascending order, from 0 through 15.

At each coordinate \((r,c)\), two four-byte source reads occur before any of that coordinate’s destination writes:

1. Read the element at source index \(16r+c\).
2. Read the element at source index \(16(15-r)+c\).

Thus, one read traverses source rows forward and the other traverses them backward, both using the same column.

These reads are separate operations. The function does not first snapshot the complete source array. Values loaded for the current coordinate are reused for that coordinate’s writes, but subsequent coordinates perform fresh reads.

### Destination layout and write order

For each coordinate, let \(A\) be the value obtained by the first source read and \(B\) the value obtained by the second source read. The function issues four four-byte writes, in this order:

| Write order | Destination element index relative to \(D\) | Value |
|---|---:|---|
| 1 | \(180r+c\) | \(A\) |
| 2 | \(K+180r+c\) | \(B\) |
| 3 | \(180r+179-c\) | \(A\) |
| 4 | \(K+180r+179-c\) | \(B\) |

An element index \(j\) denotes byte address \(D+4j\).

The row stride is 180 elements, or 720 bytes. In each row of each logical region, the function targets:

- Columns 0 through 15.
- Columns 164 through 179.

The right-hand band reverses the order of the source columns: source column 0 goes to destination column 179, and source column 15 goes to destination column 164.

Relative to each region separately, columns 16 through 163 are not targeted. This is not an unconditional guarantee that those physical addresses remain unchanged: the other region may overlap them.

### Completion and operation counts

On an execution that completes normally, the function performs:

- One global-value read.
- Two object-field reads.
- 512 four-byte source-element reads.
- 1,024 four-byte destination-element writes.

These are operation counts, not counts of distinct addresses. Overlap can make multiple operations access the same location.

There is no early exit based on element contents, selector value, or displacement value. Normal completion returns without producing a result value or status.

### Range and arithmetic boundaries

The first destination region targets indices from 0 through 2,879, with substantial gaps between its two bands in each row. The maximum index is:

\[
180 \times 15 + 179 = 2879.
\]

A contiguous allocation covering that region’s entire extent would require 2,880 elements, or 11,520 bytes, starting at \(D\). The function does not write every byte in that extent.

The second region targets the same pattern shifted by \(K\) elements. Its indices run from \(K\) through \(K+2879\). A negative displacement would mathematically place some or all of that region before \(D\); the function contains no explicit rejection of such a value.

If both regions lie within one contiguous allocation and address arithmetic does not wrap, their combined extent runs from element index \(\min(0,K)\) through \(\max(2879,K+2879)\). This describes an enclosing range, not a claim that every enclosed element is accessed.

The row, column, and source-index calculations are bounded by the fixed iteration limits. Arithmetic involving \(K\), either base address, or four-byte address scaling can exceed representable ranges if unsuitable inputs are supplied. Overflow and invalid-address behavior are documented_only rather than assigned a guessed result.

## Side effects

The explicit side effects are destination memory writes. There are no explicit allocations, releases, callbacks, global writes, or updates to either object’s stored pointer field.

Those statements concern explicit operations. Physical aliasing can produce additional effects:

- A destination write can modify source storage and thereby affect later source reads.
- A destination write can overwrite either object’s pointer field. The already-captured base addresses remain in use.
- A destination write can overwrite the global displacement storage. The already-captured displacement remains in use.
- The two destination regions can overlap, making later stores replace earlier values.

Overlapping writes are resolved by execution order: row order, then column order, then the four-write order above. No conflict detection, temporary destination, or restoration is present.

The routine does not claim ownership of either object or either data region. The evidence contains no ownership annotations, lifetime management, or release operation. Callers must arrange for accessed storage to remain usable throughout execution.

There is no explicit validation or error-reporting path. Null pointers, inaccessible memory, insufficient storage, incompatible alignment, and invalid address arithmetic are not converted into a status result. Their exact failure behavior depends on the execution environment and is not established here.

The access order described is the order visible in the supplied static representation. Atomicity, synchronization, inter-thread visibility, and memory-mapped I/O guarantees are not established.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. They are not reports of executed tests.

### Disjoint source and destination, nonoverlapping regions

Assume valid nonwrapping addresses, immutable source data throughout the operation, and destination regions that do not overlap.

For every \(r,c\) from 0 through 15:

- Destination index \(180r+c\) receives source index \(16r+c\).
- Destination index \(180r+179-c\) receives that same source value.
- Destination index \(K+180r+c\) receives source index \(16(15-r)+c\).
- Destination index \(K+180r+179-c\) receives that same reverse-row source value.

For row 0 specifically, the first region uses source row 0, while the shifted region uses source row 15.

### Column reflection endpoints

Under the same assumptions:

- Source element at row 0, column 0 appears at first-region indices 0 and 179.
- Source element at row 0, column 15 appears at first-region indices 15 and 164.
- Source element at row 15, column 0 appears at first-region indices 2,700 and 2,879.

This establishes reflection across the 180-column row, rather than reversal only within the initial 16-column band.

### Selector equivalence

Given identical initial memory, valid accesses, and no external interference, selector values 2, 3, 0, and any other representable integer produce the same source-access and destination-write sequence.

Acceptance must not require a different arrangement for the 2-or-3 branch.

### Zero displacement

Assume \(K=0\), valid destination storage, and source storage disjoint from destination storage.

For each coordinate, the second write replaces the first, and the fourth replaces the third. Both destination bands therefore end with values from source row \(15-r\), not source row \(r\).

The function still performs all four writes per coordinate. Equal destination addresses do not eliminate the observed operations.

### Untargeted storage

Assume a destination location belongs to neither region’s target set, does not alias source or object metadata in a way that changes the scenario, and is not modified externally.

Its contents remain unchanged by this function. In particular, a middle-column location in the first region is preserved only if the shifted region does not also target that physical address.

### Source/destination overlap

If destination writes overlap source storage, acceptance follows the ordered reads and writes, not a full-source snapshot model. A later read may observe a value written earlier by this invocation.

A blanket requirement that the output always equal a transformation of the source’s entry-time contents would exceed the established behavior.
