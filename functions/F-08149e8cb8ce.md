# F-08149e8cb8ce

## Purpose

F-08149e8cb8ce searches a linked sequence for the first entry whose one-byte discriminator equals a requested selector and whose embedded candidate is accepted by an indirect predicate. It returns a value derived from that entry’s payload and flag bits, or zero when traversal reaches a null link without an accepted entry.

The entry’s payload is interpreted in one of two ways: directly, or as an offset added to a base value in the input context. The source establishes this selection mechanism, but not the application-level meaning of the resulting value.

“Search,” “predicate,” “payload,” and “base” are descriptive terms. They do not establish a particular container API, allocation scheme, ownership model, or application domain.

## Interface

### Inputs

The function has three inputs:

| Input | Representation | Role |
|---|---|---|
| Context | Pointer to storage accessed as 32-bit integer fields | Supplies the initial link and, conditionally, a base value |
| Selector | Unsigned 32-bit integer | Passed to F-ab6062dd4d3b and compared with entry discriminators |
| Auxiliary value | Uninterpreted 32-bit value | Forwarded unchanged to each predicate invocation |

There is no explicit context validation, selector range check, or auxiliary-value validation.

The selector is not narrowed to eight bits for the discriminator comparison. Consequently, a selector above 255 cannot equal any entry’s one-byte discriminator, although it is still passed to F-ab6062dd4d3b.

### Output

The result is represented as a signed 32-bit integer in the supplied source:

- Zero if traversal reaches a null link before an entry is accepted.
- Otherwise, either the accepted entry’s payload or the sum of its payload and the context’s base value.

Zero is not an unambiguous “not found” result. An accepted entry can also produce zero.

The source uses integer-held values as addresses. This contract describes the visible 32-bit fields and byte offsets; it does not independently establish a portable pointer ABI or the application-level type of the returned value.

## Behavior

### Resolution precedes traversal

The first explicit operation is a call to F-ab6062dd4d3b with the full unsigned 32-bit selector.

Only after that call returns does this function read the context’s initial link at offset 16. Therefore:

- Resolution occurs even if the sequence is empty.
- Effects of resolution can precede, and potentially influence, the initial-link read.
- This function does not cache the initial link before resolution.
- A null initial link does not bypass resolution.

The returned object reference is retained for predicate dispatch during this invocation. F-ab6062dd4d3b is not called again for subsequent entries.

### Traversal and filtering

A zero current link terminates the search and returns zero without dereferencing an entry at that link.

For a nonzero link, the function reads the entry’s unsigned one-byte discriminator at offset 200 and compares it with the full selector.

If the discriminator differs, the predicate is not invoked. The function reads the successor link at offset 4 and continues there.

If the discriminator equals the selector, the function invokes the indirect predicate using:

1. The retained object returned by F-ab6062dd4d3b.
2. The address eight bytes beyond the current entry’s beginning.
3. The original auxiliary value, unchanged.

The predicate result is tested for zero versus nonzero. Any nonzero result, including a negative result under the displayed signed return representation, accepts the entry.

A zero predicate result rejects that entry. The successor link is then read from the entry at offset 4, and traversal continues.

This is a first-accepted-entry search in link order. Matching the discriminator alone does not suffice. Once a predicate accepts an entry, no successor is read for purposes of continuing the search, and no later entry is considered.

### Predicate dispatch and mutation visibility

For each matching entry, the function obtains the callable through the retained object’s dispatch-table reference and the callable slot at offset 4. The supplied source does not cache the dispatch-table reference or callable across predicate invocations.

No preservation guarantee is established for either dependency. In particular:

- A rejecting predicate may modify the current entry’s successor before this function reads it.
- A rejecting predicate may change later entries before they are examined.
- A predicate may modify the retained object or dispatch table, affecting a later dispatch.
- An accepting predicate may modify the flags, payload, or context base before result construction.

The current entry’s discriminator is not rechecked after the predicate returns. Acceptance remains based on the earlier discriminator match and the predicate’s nonzero result.

The current entry reference is retained across the predicate call; this function does not reload it from the context. If the dependency invalidates the referenced storage, safe continuation is not established.

### Result construction

After acceptance, the function reads the entry’s 32-bit flags at offset 196 and tests bit `0x2`.

- **Bit `0x2` set:** Return the 32-bit payload at offset 188 directly. The context base is not needed on this path.
- **Bit `0x2` clear:** Return the sum of the context base at offset 0 and the entry’s 32-bit payload at offset 188.

Other flag bits do not affect this function’s result selection.

The flags and payload are accessed after predicate acceptance; they are not snapshots taken before the call. Likewise, the base, when needed, is read after acceptance rather than at function entry.

The source establishes that the flag decision precedes the selected result expression. It does not establish an ordering between the base read and payload read within the addition expression. Consumers must not depend on one of those two reads occurring first.

### Widths and arithmetic

The discriminator is an unsigned eight-bit value. Its comparison with the unsigned 32-bit selector preserves the selector’s full range; there is no modulo-256 matching rule.

The flag test examines a 32-bit value and only bit `0x2`.

The base and payload are represented as 32-bit integers. The source provides no explicit widening, saturation, overflow detection, or checked arithmetic for their addition. Signed-overflow behavior is not resolved by the supplied material. A portable contract must not promise wraparound for overflowing sums.

The address formed at entry offset 8 and the addresses used for field accesses must be valid in the applicable execution model. The source supplies no pointer-overflow, bounds, or alignment checks.

## Acceptance examples

These examples are conditional on valid required storage, normally returning dependencies, and arithmetic within the representable range where addition is involved.

1. **Empty sequence.** F-ab6062dd4d3b returns, and the subsequently read initial link is zero. The function returns zero. No discriminator or predicate dispatch is accessed.

2. **Selector above the discriminator range.** The selector is 256, and a finite valid sequence ends in a null link. No discriminator can match. Resolution still occurs, no predicate is invoked, and the result is zero.

3. **Discriminator mismatch.** The selector is 7 and an entry’s discriminator is 8. That entry’s predicate is not called; its successor determines the next entry.

4. **Matching but rejected entry.** An entry has discriminator 7 for selector 7, but its predicate returns zero. The function continues using the successor read after that call.

5. **First accepted entry wins.** Two entries match the selector and would both be accepted. If the first predicate returns nonzero, the second entry is not examined.

6. **Direct payload result.** An accepted entry has flags containing `0x2` and payload 4096. The result is 4096, regardless of the context base.

7. **Base-relative result.** An accepted entry has flags with `0x2` clear, base 4096, and payload 24. The result is 4120.

8. **Successful zero result.** An accepted entry has `0x2` set and payload zero. The result is zero, indistinguishable by return value alone from exhausted traversal.

9. **Mutation after rejection.** A matching entry initially links to one successor, but its rejecting predicate changes that link to another valid entry. Traversal uses the changed link because the successor is read after rejection.

10. **Mutation before result construction.** An accepting predicate changes the entry’s flags and payload. Result construction uses those post-call fields, not their pre-call values.

11. **Cycle without acceptance.** A valid linked cycle contains no accepted entry. The function has no visited-entry tracking or traversal bound, so termination is not guaranteed.
