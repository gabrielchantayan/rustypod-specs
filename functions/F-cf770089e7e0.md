# F-cf770089e7e0

## Purpose

F-cf770089e7e0 resolves a record pointer from a context and a descriptor. It returns either a pointer value or null, without a separate status code.

Static evidence establishes three resolution paths:

- A zero descriptor key delegates resolution to F-90be72a33f67.
- A nonzero key can be searched in a cached pointer index.
- A nonzero key can instead be searched in a forward-linked record chain.

An eligibility dependency gates every path. A separate availability dependency gates both nonzero-key lookup paths.

The apparent purpose of the cached index is faster lookup. Whether its preparation dependency orders entries, and whether the surrounding dependency pair provides synchronization, remain inferred intent rather than established contracts.

## Interface

### Inputs and representation

The function receives two values used as addresses:

| Input | Interpretation |
|---|---|
| Context | Structure containing a mode byte, chain head, synchronization-related value, and cached-index pointer. |
| Descriptor | Object passed to the eligibility dependency and subsequently read for resolution fields. |

The visible address model is 32-bit. Explicit pointer slots and ordinary structure words used by this function are four bytes wide. Lookup keys are unsigned 32-bit values; index counts and search bounds use signed 32-bit arithmetic.

No explicit null, alignment, range, or lifetime validation precedes the relevant accesses. Required readability depends on the path taken. Lazy construction additionally requires a writable cached-index slot.

### Context fields

Offsets are byte offsets from the context address.

| Offset | Width | Observed use |
|---|---:|---|
| 0x006 | 1 byte | Zero selects the indexed path; any nonzero value selects direct chain lookup. |
| 0x00C | 4 bytes | Chain-head pointer. |
| 0x9D0 | 4 bytes | Value captured and passed to the paired dependencies. |
| 0x9D4 | 4 bytes | Cached-index pointer; read and potentially overwritten. |

### Descriptor fields

| Offset | Width | Observed use |
|---|---:|---|
| 0x0F0 | 4 bytes | Unsigned lookup key. |
| 0x110 | 4 bytes | Third argument to zero-key resolution. |
| 0x114 | 4 bytes | Fourth argument to zero-key resolution. |

The last two fields are not directly read on a nonzero-key path.

### Records and index

A chain record provides a four-byte next pointer at offset 0x00 and an unsigned four-byte key at offset 0x0C.

An index provides a signed four-byte count at offset 0x00, followed immediately by consecutive four-byte record pointers. Indexed lookup reads each referenced record’s key at offset 0x0C; it does not use that record’s next pointer.

A separate global value, identified by address 0x08050548, supplies the third argument to index preparation. The supplied body does not include its declaration, so its exact storage width and type are not independently established. In particular, neither immutability nor callback identity is established.

### Output and ownership

The returned value is one of:

- A selected record pointer.
- The pointer value returned by F-90be72a33f67.
- Null following rejection, unavailable lookup, or a completed search without a match.

The function does not explicitly copy a record, allocate or release storage, or adjust a reference count. Those observations do not establish ownership or lifetime: dependencies may have such effects, and the returned pointer may be affected by the final dependency call.

## Behavior

### Eligibility and key capture

The first dependency call is F-724e1e872fe7 with the descriptor address.

If its result is zero, the function returns null without directly reading the descriptor key or any context field.

Otherwise, it reads the unsigned key at descriptor offset 0x0F0. Because this read follows the dependency call, mutations made by that dependency can affect the selected route.

For nonzero-key lookup, this observed key is retained. The function does not reread the descriptor key during subsequent lookup.

### Zero-key delegation

If the captured key is zero, F-90be72a33f67 receives:

1. The context address.
2. Zero.
3. The descriptor word at offset 0x110.
4. The descriptor word at offset 0x114.

Both descriptor words are obtained before the call. Their relative read order is not established by the supplied expression.

The dependency’s result is returned without inspection. This path does not directly call the availability dependency, inspect the context mode, access the cache, or traverse the chain.

### Nonzero-key availability and mode selection

For a nonzero key, the function calls F-cd52fcefba54 with no explicit arguments.

A zero result causes an immediate null return. This rejection applies even if the context would select chain lookup or already contains a usable index.

After a nonzero result, the function reads the byte at context offset 0x006:

- Nonzero selects chain lookup directly.
- Zero enters the indexed path.

Direct chain selection does not directly read context offsets 0x9D0 or 0x9D4 and does not call the paired dependencies.

### Indexed-path entry

The function reads the four-byte value at context offset 0x9D0, retains it, and calls F-338d16f9ce72 with that value. Its return value is unused.

Only after that call returns does the function read the cached-index slot at offset 0x9D4.

If the observed pointer is nonnull, construction and preparation are skipped. The cache slot is subsequently read again to obtain the index used for search.

No synchronization guarantee follows solely from this call pattern. In particular, a nonnull observation does not itself guarantee that a later cache read remains nonnull or refers to the same index.

### Lazy construction and global argument read

If the cache slot is null, the function calls F-f16e3e6dbf6b with the context address. Its returned pointer is written to context offset 0x9D4, including when the returned pointer is null. This write occurs after the builder returns and can overwrite a value the builder itself installed in that slot.

A null builder result skips preparation. The function calls F-1333331b2da1 with the previously captured value from offset 0x9D0, then proceeds to chain lookup.

For a nonnull builder result, F-b4b5aa4c2f83 receives:

1. The address four bytes after the returned pointer, corresponding to the entry-array start.
2. The first four-byte word at the returned pointer.
3. The value read from the global at address 0x08050548.
4. Zero.

The header-word read and global-value read both occur as part of obtaining arguments for this call, after the builder result has been stored in the cache. Their relative evaluation order is not established by the supplied expression.

The global value is read on this successful lazy-construction path; it is not established as a fixed constant. Earlier dependencies may have changed it. The supplied body also does not establish that it denotes a callback.

The return value of F-b4b5aa4c2f83 is unused. After it returns, the function checks the context’s cached-index slot again:

- Null causes F-1333331b2da1 to be called, followed by chain lookup.
- Nonnull permits indexed search, which obtains its index pointer through another cache-slot read.

Thus preparation may leave a replacement index installed. The search is not necessarily performed against the builder’s returned pointer.

### Indexed search

The search reads the selected index’s first word as a signed 32-bit count.

For stable, valid storage and arithmetic within representable bounds, the candidate interval initially extends from entry zero through count minus one.

While the upper bound minus the lower bound exceeds one, the function chooses the midpoint by signed division of the bounds’ sum by two. For a valid nonnegative interval, this selects the lower midpoint.

At each midpoint:

- The function reads the indexed record pointer and its unsigned key.
- Equality with the captured descriptor key selects a pointer obtained again from that midpoint’s pointer slot.
- Otherwise, it reads the midpoint record key again for an unsigned ordering comparison.
- If the target key is less than that second observed key, the upper bound becomes the midpoint.
- Otherwise, the lower bound becomes the midpoint.

The midpoint remains within the narrowed interval; it is not excluded by adding or subtracting one.

Repeated accesses matter if storage changes: the equality check, ordering check, and selected pointer need not reflect one immutable observation. There is no direct write or intervening dependency call within these search steps, but the body alone does not exclude external mutation.

When the interval contains at most two entries, the function examines candidates in increasing index order. For each candidate, it loads the record pointer and checks that record’s key. The first equality in this final scan selects that pointer. Exhausting the interval selects null.

For a count of zero, the initial interval is empty, so no entry pointer or record key is read.

After either an indexed match or miss, F-1333331b2da1 is called with the retained value originally read from context offset 0x9D0. The selected result is then returned. The cache and descriptor key are not reread to validate that result after this call.

An indexed miss does not cause chain lookup.

Ascending unsigned-key order is a precondition for ordinary binary-search completeness, not a property this body independently validates. Duplicate keys need not produce the earliest matching index entry because a midpoint match returns immediately.

### Chain lookup

Chain lookup begins by reading the current head pointer at context offset 0x00C. On fallback from unsuccessful index preparation, this read occurs after F-1333331b2da1 returns, so effects of that dependency can influence the head observed.

For each nonnull record, the function reads its unsigned key at offset 0x0C:

- Equality returns that record.
- Inequality causes the next pointer at offset 0x00 to be read and followed.

A null head or a null next pointer reached without a match produces null.

The first matching record in traversal order wins. A matching record’s next pointer is not read. No cycle detection or traversal limit is present; a cycle without a matching key can prevent termination.

## Side effects

The only explicit memory write in this function is storing the builder result into the context’s cached-index slot.

Dependency effects are not bounded by the supplied body. No dependency is assumed to preserve global values, context contents, index contents, records, or memory ownership.

On normally returning indexed paths, F-338d16f9ce72 is followed by exactly one F-1333331b2da1 call using the same captured argument. This includes paths that abandon indexed preparation and continue through the chain. The fallback traversal occurs after that second call, not inside the visible pair.

The selected indexed pointer is retained across the closing call, but the function does not ensure that the pointed-to storage remains valid. The closing dependency may have effects not visible here.

There is no explicit recovery for invalid memory, malformed metadata, dependency nonreturn, or arithmetic outside the safely representable range.

## Acceptance examples

These are conditional static expectations, not executed tests. All accessed memory is assumed valid, dependencies return normally, relevant data remains stable during search, and required arithmetic is representable.

For examples reaching nonzero-key lookup, **both F-724e1e872fe7 and F-cd52fcefba54 return nonzero**, except where an example explicitly specifies rejection. Normal return alone does not satisfy either gate.

1. **Eligibility rejection.** If F-724e1e872fe7 returns zero, the result is null. There is no direct descriptor-key read, context-field read, or subsequent dependency call.

2. **Zero-key delegation.** If eligibility succeeds and the key read afterward is zero, F-90be72a33f67 receives the context, zero, and the two additional descriptor words. Its result is returned unchanged. The availability dependency is not called.

3. **Availability rejection.** If the captured key is 42 but F-cd52fcefba54 returns zero, the result is null even if the chain contains key 42. Neither lookup path is entered.

4. **First chain match.** With successful gates, nonzero mode, and chain keys 7, 42, 42, a target of 42 selects the second record. Its next pointer is not read.

5. **Empty chain.** With successful gates, direct chain selection, and a null head, the result is null.

6. **Existing ordered index.** With successful gates, zero mode, an existing index containing keys 10, 20, 30, and target 20, the middle entry is selected. F-1333331b2da1 is called before return. Construction, preparation, and the preparation-argument global read are skipped.

7. **Indexed miss.** Under the same gate and index conditions, target 25 returns null after F-1333331b2da1. A matching chain record would not change this result.

8. **Builder failure.** With successful gates and an initially null cache, a null builder result is written into the cache. Preparation is skipped. The closing dependency runs before the current chain head is read.

9. **Mutable global argument.** On successful lazy construction, if an earlier dependency changes the global preparation argument from value A to value B and B remains present until its argument read, preparation receives B. No callback interpretation is required.

10. **Preparation replacement or removal.** If preparation installs another valid index, subsequent cache reads can select that replacement. If preparation instead leaves the cache null, the closing dependency runs before chain lookup.

11. **Empty index.** With successful gates and an existing index count of zero, the result is null after the closing dependency. No entry pointer is read and no chain traversal occurs.

12. **Duplicates and unsigned ordering.** In a five-entry ordered index whose middle entry matches a duplicated target, that midpoint can win over earlier duplicates. Separately, key 0xFFFFFFFF orders above 0x7FFFFFFF; signed-key ordering does not satisfy the unsigned ordering precondition.
