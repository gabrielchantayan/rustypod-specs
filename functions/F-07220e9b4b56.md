# F-07220e9b4b56

## Purpose

F-07220e9b4b56 selects a three-byte descriptor using a code from an indexed record, then converts that descriptor into a signed integer result. Twenty-one code values are recognized. Two of those values select the same descriptor.

An unrecognized code returns −1 without accessing descriptor bytes, provided the code-discrimination arithmetic has defined behavior under the applicable execution model. A recognized descriptor can also decode to −1, so the return value alone does not distinguish rejection from successful decoding.

This contract describes the supplied static evidence. It does not establish what the record codes or descriptor values mean to the surrounding application.

### Descriptor decoding

Let \(a\), \(b\), and \(c\) denote the unsigned numeric values of the descriptor bytes at offsets 0, 1, and 2, respectively. Each is in the range 0 through 255.

The mathematical value before final narrowing is:

\[
Q = 1024(a-96) + 32b + c - 3168.
\]

An equivalent expression, useful for understanding the offset, is:

\[
Q = 1024(a-96) + 32(b-96) + (c-96).
\]

The latter does not imply that the bytes are validated against 96 or against any encoding alphabet. No such validation is visible. Every readable byte value participates numerically in the conversion.

Under the apparent 32-bit execution model, the final result is the signed interpretation of the low sixteen bits of \(Q\):

- Residues from 0 through 32767 return unchanged.
- Residues from 32768 through 65535 return that residue minus 65536.

Thus, decoding wraps at sixteen bits; it does not saturate or reject out-of-range values.

Across all possible byte triples, the mathematical intermediate \(Q\) ranges from −101472 through 168063. It is therefore not always already a signed 16-bit value.

### Width and conversion requirements

The visible arithmetic includes unsigned conversion of the second and third bytes. On a 32-bit integer model, this makes the subsequent combined arithmetic unsigned. Multiplication by 65536 then retains the low sixteen bits of the value in the upper half of a 32-bit word, with unsigned wraparound.

The final signed conversion and right shift produce the stated signed 16-bit result if the target:

- Uses 32-bit integers for these operations.
- Interprets the converted bit pattern as a two’s-complement signed value.
- Uses arithmetic right shift for negative signed integers.

Those properties are strongly indicated by the visible operation, but are target-model assumptions rather than a portable guarantee of the supplied language representation.

The index calculation has a separate width concern. Multiplying an unrestricted signed index by twelve can overflow before address formation. This function contains no explicit protection against that condition. A negative index is not automatically rejected; whether it identifies readable memory depends on the table base, surrounding allocation, and arithmetic model.
