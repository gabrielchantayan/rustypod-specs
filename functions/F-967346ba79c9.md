# F-967346ba79c9

## Purpose

F-967346ba79c9 transforms an input value into a fixed-width output using a caller-supplied object, temporary numeric values, a context, and one of two object-provided operations.

The established behavior is a pipeline:

1. Acquire a context and determine an output width from the object.
2. Allocate a temporary byte buffer and populate it using the selected input mode.
3. Import that buffer into a temporary numeric value and require it to compare below an object-held reference value.
4. Prepare or select auxiliary state, when required.
5. Invoke one of two object-provided operations.
6. Optionally apply an auxiliary-state operation to the result.
7. Export the result into the caller’s output area and zero-fill its leading unused portion.
8. Perform ordered cleanup.

The intended result appears to be a right-aligned, zero-prefixed representation whose width is determined by the object. That interpretation is inferred from the destination calculation and prefix writes. Correct serialization, valid output size, and valid arithmetic depend on contracts of dependencies that are not supplied.

## Behavior

### 1. Initialize temporary values and acquire context

The function initializes two separate 20-byte local storage regions through F-163f35978c12:

1. The temporary input numeric value.
2. The temporary result numeric value.

It then calls F-2a7d78c39bfc to obtain a context.

If the context is zero, the function skips all object processing and buffer allocation. It proceeds directly to finalization of the result temporary followed by the input temporary, then returns `-1`.

No error-reporting call is visible for this case.

### 2. Determine the nominal byte width and allocate a buffer

With a nonzero context, the function reads the object field at `+0x10` and passes it to F-ae3bc1bfd2a8.

The returned signed 32-bit value is converted to a byte count. For nonnegative values with representable intermediate addition, the conversion is the usual upward rounding of a bit count to whole bytes: add seven, then divide by eight.

More precisely, the visible calculation adds seven, applies a sign-dependent bias, and performs an arithmetic right shift by three. When the addition is representable, this corresponds to division of the incremented signed value by eight with truncation toward zero. Negative inputs are not rejected. Behavior outside the representable arithmetic domain must not be replaced with an assumption of mathematically unbounded arithmetic.

The resulting byte count is passed to F-43da6b23bd44 with two additional zero arguments.

If the returned buffer address is zero, the function calls F-4fc89ec41a6d with arguments `4` and `102`, then proceeds toward cleanup if that call returns.

### 3. Populate and import the temporary input

With a nonzero temporary buffer:

- Mode `1` calls F-1d3d7f6db100 with the buffer, byte count, and second function argument.
- Mode `3` calls F-937bd44c9b0f with the same argument positions.
- Any other mode calls F-4fc89ec41a6d with `4` and `102`, without invoking either population dependency.

For either recognized mode, the population result must be strictly positive. Zero and negative results terminate the transformation without an explicit error-reporting call at this site.

A positive population result permits F-3eaa60da10c7 to import the buffer into the input temporary. Import must return nonzero.

The imported value is then compared with the object field at `+0x10` through F-c0985d8666ae. Only a negative comparison result permits continuation. Zero or a positive result causes the explicit error-reporting call with `4` and `102`.

Thus equality is rejected, not accepted.

### 4. Prepare and select auxiliary state

After the comparison passes, the function reads the flags at `+0x3c`.

If bit `0x80` is clear, it reads auxiliary state at `+0x50`. When that state is zero, it calls F-8bb113c5b25d with the object and context. A zero return terminates processing.

The function then reads `+0x50` again and rereads the flags. These are fresh reads after any preparation call; the decision is not made solely from previously observed fields.

On this second decision:

- If bit `0x80` is clear and auxiliary state is still zero, the function reports error `(4, 102)`.
- If bit `0x80` is set and auxiliary state is zero, auxiliary processing is skipped.
- If auxiliary state is nonzero, auxiliary processing occurs regardless of bit `0x80`.

For present auxiliary state:

1. Call F-7eadd9e17dc6.
2. Compare its result with the 32-bit field at auxiliary-state offset `+0x10`.
3. If unequal, call F-22a808773769 with the object and context to obtain replacement state.
4. A zero replacement terminates processing.
5. A nonzero replacement is marked for later release by this function.
6. Call F-3959199a1859 with the input temporary, selected auxiliary state, and context.
7. Require a nonzero result.

If the discriminator matches, the existing object-held state is used without being marked for release by this function.

### 5. Select and invoke the object-provided operation

The flags are read again.

The operation at table offset `+0x14` is selected when either:

- Flag bit `0x20` is set; or
- Flag bit `0x20` is clear and all five fields at `+0x1c` through `+0x2c` are nonzero.

When bit `0x20` is clear, those five fields are examined in increasing offset order, stopping at the first zero. Later presence fields are not read after that zero.

The `+0x14` operation receives:

- Result temporary.
- Input temporary.
- Object address.

Otherwise, the operation at table offset `+0x18` is selected. It receives:

- Result temporary.
- Input temporary.
- The object field at `+0x18`.
- The object field at `+0x10`.
- Context.
- A final zero argument.

The operation-table address is obtained from the object field at `+0x08`. The available evidence establishes which arguments are supplied, but not a portable sequencing guarantee among the individual field reads used to form one call.

Either selected operation must return nonzero for processing to continue.

If auxiliary state was selected, F-6e62358648e3 is then called with the result temporary, that selected state, and the context. Its return must also be nonzero. With no selected auxiliary state, this call is skipped.

### 6. Export and prefix-fill the result

The function calls F-ae3bc1bfd2a8 on the result temporary and converts its return to a rounded byte count using the same arithmetic as the initial width calculation.

The export destination is:

- Output base, plus
- Nominal output width, minus
- Rounded result width.

F-29c531f09e4a is called with the result temporary and that destination.

Its signed return value then determines prefix filling. Starting at output offset zero, the function writes individual zero bytes in increasing address order while the offset is less than nominal width minus the export return value.

The zero writes therefore occur **after** the export call. The prefix length depends on the export return, not directly on the previously calculated result width.

No visible check establishes that:

- The rounded result width fits the nominal width.
- The export return is nonnegative.
- The export return equals the rounded result width.
- The export return is no greater than nominal width.

After the loop, the function sets its return value to the nominal byte width.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Except where stated otherwise, dependencies are assumed to return normally.

1. **Unavailable context.** If context acquisition returns zero, both temporary initializations have already occurred. No width lookup, allocation, or object operation follows. Result finalization precedes input finalization, and the return is `-1`.

2. **Unsupported mode after successful allocation.** With a nonzero context and allocated buffer, mode `2` causes error reporting with `(4, 102)`. Neither input-population dependency is called. Cleanup includes both buffer cleanup calls in their specified order.

3. **Equality with the reference.** If population and import succeed but comparison returns zero, the function reports `(4, 102)`. It does not prepare auxiliary state or invoke an object-provided operation.

4. **Preparation changes object state.** Suppose the initial flags have bit `0x80` clear and `+0x50` is zero. If preparation returns nonzero and installs state at `+0x50`, the subsequent read uses that installed state. The initial zero is not retained as the decision value.

5. **No auxiliary state permitted.** If bit `0x80` is set and `+0x50` is zero at the selection read, the discriminator call and both auxiliary numeric operations are skipped. Successful object operation can proceed directly to export.

6. **Presence-field short circuit.** With bit `0x20` clear, nonzero fields at `+0x1c` and `+0x20`, and zero at `+0x24`, the operation at table offset `+0x18` is selected. The presence checks do not read `+0x28` or `+0x2c`.

7. **Replacement cleanup after later failure.** If the auxiliary discriminator mismatches, replacement acquisition returns nonzero, and the input auxiliary operation then returns zero, the function returns `-1` after cleanup. The replacement is passed to F-3eadc90e0ec1 after temporary finalization.

8. **Ordinary right-aligned output.** Suppose the nominal width is eight bytes, the rounded result width is three bytes, and export writes three bytes and returns `3`. Export starts at output offset five. The function subsequently zeroes offsets zero through four and returns `8`.

9. **Export failure is not independently recognized.** If nominal width is eight and export returns `-1`, the visible prefix loop has a bound of nine, assuming representable arithmetic. It attempts nine zero writes and then assigns return value `8`. This is not a safe-input example; it demonstrates why an export-return contract is necessary.
