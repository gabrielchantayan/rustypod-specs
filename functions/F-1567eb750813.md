# F-1567eb750813

## Purpose

F-1567eb750813 waits for a shared reference cell to become nonzero, obtains a context reference through that cell, and invokes a primary dependency. Depending on the primary dependency’s signed result, it either returns directly or invokes an indirectly selected secondary dependency with a word read from the context.

The apparent intent is to wait for initialization and then attempt an operation with a fallback. “Initialization,” “operation,” and “fallback” are interpretations, not established meanings. The available static evidence establishes the accesses, calls, and branch structure, but not the application-level purpose of the objects involved.

This contract describes normal control flow. It does not establish that any dependency terminates, that referenced storage is valid, or that indirect dispatch returns.

## Behavior

### Waiting for a nonzero reference

At entry, the function obtains the address of the shared reference cell from global storage and retains that cell address for the polling sequence.

It reads the cell and compares its contents with zero. Each time the observed contents are zero, it invokes the wait dependency with two arguments, in order:

1. A zero-valued word.
2. A word whose value is 2.

After that dependency returns, the function reads the retained cell again.

Consequences of this structure:

- If the first cell read is nonzero, the wait dependency is not called.
- Each zero observation causes a wait-dependency invocation before the next poll.
- A returning wait dependency does not itself establish readiness; the cell is checked again.
- If the cell remains zero and every wait invocation returns, the function continues polling indefinitely.
- If the wait dependency does not return, further polling and all later work cease.
- The visible loop retains the original cell address. It does not visibly reacquire that address from global storage after each wait.

The values zero and 2 do not establish a duration, time unit, scheduler policy, or retry limit.

### Obtaining and retaining the context

After a poll observes a nonzero value, the function accesses the cell again to obtain the object base used for the next field read. It then reads the 32-bit field at byte offset 20 from that base and retains the resulting context reference.

The nonzero observation and the subsequent object-base read are distinct accesses. If another agent changes the cell between them, the object base used for the offset-20 read need not equal the value that ended the wait. There is no visible snapshot, lock, or second nonzero check protecting that transition.

No visible check verifies that:

- The shared cell address is valid.
- The object base obtained after polling is nonzero.
- The field at offset 20 is readable.
- The resulting context reference is nonzero or valid.

The retained context reference is used for both the primary call and, if selected, the later offset-4 access. The function does not visibly reacquire the context reference after the primary call.

### Primary operation

The primary dependency receives six values in this order:

1. The constant 1.
2. The retained context reference.
3. The function’s third explicit input.
4. The function’s fourth explicit input.
5. The incoming preserved-register value.
6. The incoming link or return-address value.

On the visible normal path, this call occurs once, after the wait has ended and the context reference has been obtained.

The dependency returns a value represented as a signed 32-bit integer. No other semantics for that result are established.

### Result-dependent dispatch

The branch tests whether the primary result, after subtraction of 1, is nonnegative.

For values where signed subtraction does not overflow, the behavior is established:

- Results from 1 through 2,147,483,647 cause an immediate normal return.
- Results from −2,147,483,647 through 0 select secondary dispatch.

This is not safely specified as “all positive results succeed; all nonpositive results fall back” without addressing the remaining boundary value.

For a primary result of −2,147,483,648, subtracting 1 exceeds the signed 32-bit range. Under fixed-width modulo-\(2^{32}\) subtraction, the result becomes 2,147,483,647 and the direct-return branch is selected. The supplied representation alone does not conclusively establish the underlying overflow behavior. This boundary is therefore **documented_only**, not an unconditional behavioral guarantee.

No loop retries the primary dependency after a nonpositive result. The visible alternatives are direct return and secondary dispatch.

### Secondary dispatch

When the result condition selects secondary dispatch, the function:

- Obtains a call target from globally supplied indirect-call storage.
- Reads one 32-bit word at byte offset 4 from the retained context reference.
- Invokes that target with the field value as its sole visible argument.
- Returns normally if the indirect invocation returns normally.

Both the target access and the offset-4 field access occur after the primary dependency returns. Their relative evaluation order is not established by the supplied evidence.

The primary dependency may change global storage or context contents. The caller does not visibly preserve the indirect target or the offset-4 field before making that call. Accordingly, the secondary invocation can observe changes made by the primary dependency, subject to the actual execution environment’s memory rules.

The retained context address itself is not refreshed. If the primary dependency invalidates the referenced storage, the later field read is not protected by a visible validity check.

## Acceptance examples

These are conditional contract examples, not reports of executed tests.

1. **Already nonzero, primary result 1.**  
   Assume valid referenced storage and normal dependency return. If the initial poll sees a nonzero cell and the primary dependency returns 1, no wait call occurs. The primary receives the retained context and the specified remaining inputs. The function returns without accessing the secondary argument field or invoking the indirect dependency.

2. **Two zero observations before readiness.**  
   If successive poll observations are zero, zero, and nonzero, exactly two wait invocations occur before context acquisition. Each receives 0 and 2. This example assumes each invocation returns and that the later object-base read remains valid.

3. **Primary result zero.**  
   With a valid retained context and valid indirect target, a primary result of zero selects secondary dispatch. The secondary dependency receives the word read at context offset 4. If it returns, the enclosing function returns.

4. **Negative result without overflow.**  
   A primary result of −1 selects secondary dispatch. A result of −2,147,483,647 also selects that path because subtracting 1 produces the representable value −2,147,483,648.

5. **Maximum positive result.**  
   A result of 2,147,483,647 selects direct return. No secondary invocation occurs on that normal path.

6. **Minimum signed result.**  
   A result of −2,147,483,648 is **documented_only**. With modulo-\(2^{32}\) subtraction, it selects direct return. That outcome requires confirmation of the execution-level arithmetic semantics.

7. **Primary changes the secondary argument.**  
   Suppose the primary dependency changes the retained context’s offset-4 word from one value to another and returns zero. If the storage remains valid and the write is visible, the subsequent secondary argument read obtains the changed value.

8. **Primary changes the shared reference cell.**  
   If the primary changes the shared cell to reference another object, secondary dispatch still uses the previously retained context. It does not reacquire the context through that cell.

9. **Cell remains zero indefinitely.**  
   If every poll sees zero and each wait call returns, neither context acquisition nor the primary call occurs. The function does not return normally through its visible paths.

10. **Cell changes between readiness and acquisition.**  
    A nonzero poll does not guarantee that the following object-base read returns the same value. If the cell becomes zero during that interval, no visible revalidation prevents the offset-20 access from using that new value.
