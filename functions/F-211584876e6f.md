# F-211584876e6f

## Purpose

F-211584876e6f performs a conditional whole-structure reset or a sequence of cursor-driven operations on a container-like object. It writes a 32-bit value to a caller-supplied output slot and returns a packed 64-bit result.

The established behavior is structural: comparisons select a reset path or an iterative path; dependencies perform the underlying operations. Interpreting the operation as “erase a range” is **inferred intent**, not an established semantic contract. The supplied material does not establish what the dependencies compare, destroy, advance, or remove.

The reset path is selected only when two dependency results are nonzero and a container field is nonzero. The iterative path stops only when its comparison dependency returns exactly `1`. These are different acceptance rules.

## Interface

### Inputs

The function receives four arguments:

1. **Output slot** — an address at which the function writes one 32-bit word.
2. **Container address** — a 32-bit address-like value used to access the container fields described below.
3. **Cursor address** — an address passed to dependencies and, during each iteration, read as a location containing one 32-bit word.
4. **Endpoint word** — an opaque 32-bit argument passed to F-f69853ed0279. Its meaning and whether it represents an address are not established.

The supplied representation uses 32-bit integers and four-byte words. Values recovered from 32-bit fields are also used as addresses. This contract describes that 32-bit address model; it does not establish portability to a wider-pointer environment.

### Accessed layout

The function directly accesses these byte offsets:

| Base | Offset | Width | Established use |
|---|---:|---:|---|
| Container address | `0x10` | 32 bits | Supplies an address referred to here as the header address |
| Container address | `0x14` | 32 bits | Tested for zero and cleared on the reset path |
| Header address | `0x04` | 32 bits | Passed to a dependency, then cleared on the reset path |
| Header address | `0x08` | 32 bits | Initially copied into a temporary comparison word; later assigned the header address on the reset path |

“Header” is a descriptive label, not proof of a particular data structure. The field at container offset `0x14` may be a count, but the function establishes only its nonzero test and eventual zero assignment.

### Output and return value

The output slot is written before the first dependency call. Further writes depend on the chosen path.

The return value is a 64-bit concatenation of two 32-bit words:

- The upper word occupies bits 63–32.
- The lower word occupies bits 31–0.

This is bit concatenation, not signed extension. The packed words need not equal the final contents of the output slot.

On the reset path:

- The upper word is the header address read after the reset writes.
- The lower word is the original output-slot address retained by the function.

On the iterative path:

- The upper word is a mutable saved container word, initially the container address.
- The lower word is a mutable saved work word, initially the output-slot address.

F-2c2ff0c4df62 receives addresses of both saved words and may change them. Their meanings after that call are not established independently of that dependency.

### Preconditions and failure model

For normal completion, every direct memory access reached on the selected path must be valid, and every dependency must return normally with state suitable for the accesses that follow.

There are no explicit null checks, bounds checks, allocation checks, or structural validation checks. There is no explicit error return or rollback path. Invalid addresses, dependency failures, and malformed structures have no defined recovery behavior in the supplied material.

No disjointness guarantee between arguments and accessed structure fields is shown. Aliasing can therefore affect later reads. Stable header and container interpretations require additional conditions; they must not be assumed merely from the field labels.

## Behavior

### Initial output and comparison setup

Before calling any dependency, the function:

1. Reads the word at container offset `0x10` and writes it into the output slot.
2. Reads the header address again from container offset `0x10`.
3. Reads the word at offset `0x08` from that header and copies it into a temporary 32-bit word.
4. Initializes the saved work word to the output-slot address, the saved container word to the container address, and another temporary word to the cursor address.

The second read of container offset `0x10` is significant. If the initial output write aliases relevant container storage, the value used for the next dereference can differ from the value initially loaded.

The function then calls F-f69853ed0279 with:

- First argument: the cursor address.
- Second argument: the address of the temporary word copied from header offset `0x08`.

If this call returns zero, the whole-structure reset test ends immediately and execution proceeds to the iterative path.

### Conditional whole-structure reset

If the first comparison result is nonzero, the function reads container offset `0x10` again and places that header address into a temporary word. It then calls F-f69853ed0279 with:

- First argument: the endpoint word.
- Second argument: the address of that temporary header-address word.

Only if this second call returns nonzero does the function read container offset `0x14` for the reset decision.

The reset path requires both:

- A nonzero result from the second call.
- A nonzero word at container offset `0x14`.

The field is not tested for positivity. Any nonzero 32-bit pattern satisfies this local test.

If the reset conditions hold, the function calls F-00705c9d7d4d with:

- The original container address.
- The current word at offset `0x04` of the header currently obtained from container offset `0x10`.

After that dependency returns, the function performs these writes in order:

1. Assigns the current header address to header offset `0x08`.
2. Writes zero to header offset `0x04`.
3. Assigns the current header address to header offset `0x0C`.
4. Writes zero to container offset `0x14`.
5. Reads container offset `0x10` and writes that word to the output slot.

The header address is obtained again for subsequent accesses rather than preserved once across the dependency and all reset writes. A dependency-induced change to container offset `0x10` can therefore redirect the reset writes. Aliasing among the accessed fields can also influence later operations.

The function then returns immediately. It does not enter the iterative path or call F-7d84ed08254e or F-2c2ff0c4df62 on this path.

With a stable, nonoverlapping header layout, the direct reset writes leave header offsets `0x08` and `0x0C` pointing to that header, header offset `0x04` equal to zero, and container offset `0x14` equal to zero. Whether this represents a valid empty container depends on contracts not supplied here.

### Iterative path

The iterative path is reached whenever the reset conditions do not all hold.

Before each loop body, the function calls F-f69853ed0279 with:

- First argument: the original cursor address.
- Second argument: the endpoint word.

The body executes unless this call returns exactly `1`.

Consequently:

- `1` terminates the loop.
- `0` enters the body.
- Any other returned value also enters the body.

Each body performs the following observable sequence:

1. Reads one 32-bit word from the cursor address and retains that word.
2. Calls F-7d84ed08254e with the cursor address.
3. Replaces the saved work word with the word retained before that call.
4. Calls F-2c2ff0c4df62 with:
   - The address of the saved container word.
   - The original container address.
   - The address of the saved work word.
5. Reads the saved container word and writes it to the output slot.
6. Repeats the loop comparison.

The word supplied through the saved work word is the cursor contents observed **before** F-7d84ed08254e runs. A change to cursor contents by that dependency does not replace the already captured word for the current F-2c2ff0c4df62 call.

The original container argument remains the second argument to F-2c2ff0c4df62 on every iteration. Changes to the separate saved container word do not replace that argument.

When the loop comparison returns exactly `1`, the function returns the current saved container word as the upper return word and the current saved work word as the lower return word. It performs no additional output-slot write at loop exit.

If the loop executes zero times, the return words remain their initial values: the container address above the output-slot address. The output slot retains the initial header-address write, subject to any intervening dependency side effects.

There is no explicit iteration limit or local progress check. Termination depends on dependency behavior and reachable state.

## Side effects

### Direct effects

The function directly:

- Writes the output slot before any dependency call.
- Reads container and header fields used for comparison and path selection.
- On the reset path, writes the four structural fields listed above and writes the output slot again.
- On each iterative body, reads the cursor word and writes the output slot after F-2c2ff0c4df62 returns.
- Provides dependencies with addresses of temporary words, including mutable saved return words.

These writes are not transactional. No restoration is shown if a later dependency or memory access fails.

### Dependency effects and ownership

No direct allocation or deallocation primitive appears in this function. That does not establish that its dependencies neither allocate nor release storage.

In particular:

- F-00705c9d7d4d may affect memory reachable from its arguments; its ownership behavior is unknown.
- F-7d84ed08254e receives the cursor address and may change cursor state.
- F-2c2ff0c4df62 receives writable access to both saved return words.
- F-f69853ed0279 must not be assumed pure solely because its results control branches.

No preservation guarantee for global state is established for any dependency. Relevant container fields are reread after calls, so externally visible mutation may affect later behavior.

Pointers to temporary words are valid during their containing invocation. This function does not establish permission for a dependency to retain and later dereference those pointers after return.

## Acceptance examples

The following are conditional acceptance scenarios, not executed tests. Unless stated otherwise, they assume valid, nonoverlapping storage, normal dependency returns, and no additional dependency mutations.

### Immediate iterative termination

Given a header address `H`:

- The first F-f69853ed0279 call returns `0`.
- The first loop-condition call returns `1`.

Expected behavior:

- The output slot receives `H` once.
- Neither loop-body dependency is called.
- The upper return word is the original container address.
- The lower return word is the output-slot address.

This distinguishes the output contents from the packed return words.

### Reset selection accepts noncanonical nonzero results

Given:

- The first reset comparison returns `2`.
- The second reset comparison returns `−1`.
- Container offset `0x14` contains `7`.

Both comparison results satisfy their reset tests. Expected behavior includes one F-00705c9d7d4d call, the ordered reset writes, a final output write, and no loop-condition call.

### Zero field prevents reset

Given both reset comparisons return nonzero but container offset `0x14` contains zero, F-00705c9d7d4d is not called. Execution proceeds to the loop condition rather than returning immediately.

### A nonzero loop result need not terminate

Given the first loop-condition result is `2`, one body executes. If the next loop-condition result is `1`, execution then terminates.

Treating every nonzero comparison result as loop termination would violate the established behavior.

### Cursor capture precedes cursor operation

Suppose the cursor initially contains word `A`, and F-7d84ed08254e changes it to `B`. The saved work word supplied by address to F-2c2ff0c4df62 initially contains `A`, not `B`.

If F-2c2ff0c4df62 then writes `R` to the saved container word and `S` to the saved work word, the output slot receives `R`. If the next condition terminates the loop, the return value has upper word `R` and lower word `S`.

### Reset follows a changed header address

Suppose F-00705c9d7d4d changes container offset `0x10` to a different valid header address. The subsequent reset writes use the header address reread after that call, not necessarily the one used to obtain the dependency’s second argument.
