# F-5998249a2681

## Purpose

F-5998249a2681 returns a 64-bit value selected by flags in a caller-supplied record. Its visible behavior includes direct retrieval, a conversion-like arithmetic path, preparation through dependencies, zero-valued failure results, and exceptional indirect transfers.

**Established static evidence:** record accesses, flag precedence, explicit dependency arguments, fixed-width arithmetic, configuration reads, and the visible return expressions.

**Inferred intent:** the arithmetic resembles conversion from a two-word floating-point representation to a signed 64-bit integer, with truncation and saturation. That interpretation is not a complete numeric-format contract.

**Unresolved behavior:** processor-condition handling, large-shift semantics, external values, exceptional transfer destinations, and a stack-output relationship. These limitations remain **documented_only**.

No runtime tests have been performed.

## Behavior

### Dispatch and precedence

The function first reads the 16-bit flags at offset 28. That captured value selects the path:

1. Bit `0x0004`: direct return.
2. Otherwise, bit `0x0008`: conversion-like processing.
3. Otherwise, any bit in mask `0x0012`: preparation.
4. Otherwise: return zero.

Thus, `0x0004` overrides both conversion and preparation flags, and `0x0008` overrides preparation flags. No subsequent record-flag read is visible.

### Direct return

The function reads the 32-bit word at offset 0, then the word at offset 4, and returns their low/high concatenation.

No dependency call or direct write is visible on this path. The incoming third and fourth arguments do not supply this result.

### Conversion entry and condition gate

The function reads the low input word at offset 8, then the high input word at offset 12. These captured words are used throughout the visible arithmetic.

It calls F-11ed8242c40c with the captured low word, captured high word, and values from two external word locations designated **G-bound-first** and **G-bound-second**. The supplied representation does not establish an ordering between those two external reads.

A carry-condition test then determines whether F-c6bfc9d0fb36 is called with the captured input words. A second carry-condition test follows:

- Clear: return `0x8000000000000000`.
- Set: continue to arithmetic.

The carry condition is not represented as an ordinary dependency return value. Its producer and lifetime are unresolved. The second test must not be assumed to observe the same state as the first, particularly when the intervening dependency is called.

No reload of the record’s numeric words is visible after these calls. Dependency changes to those record fields therefore do not replace the captured arithmetic operands.

### Fixed-width arithmetic preparation

For this description:

- **Low** is the captured unsigned 32-bit low word.
- **High** is the captured 32-bit high word.
- **Fragment** is signed High arithmetically shifted right by 20.
- **Lower** is Low shifted left by 11, retaining 32 bits.
- **Upper** combines High shifted left by 11 with Low logically shifted right by 21, retaining 32 bits.

Fragment ranges from −2048 through 2047. It is a signed high-word fragment, not an established unbiased exponent.

When Fragment is nonzero, bit 31 of Upper is set. If Fragment is −2048, bit 31 is subsequently cleared. Lower is unaffected by these bit changes.

Word shifts, combinations, complements, and negations operate on 32-bit results. Arithmetic used for classification is interpreted modulo \(2^{32}\), rather than as an unbounded signed multiplication.

### Negative-fragment shift result

For negative Fragment, the candidate distance is:

\[
D=-962-\text{Fragment}.
\]

This path returns a shifted result only when:

- Fragment is at most −963; or
- Fragment is −962, Lower is zero, and Upper is `0x80000000`.

The second case permits distance zero. Other negative fragments fall through to classification.

For an eligible input, distances greater than 79 are replaced by 80. The function constructs a two-word logical-shift result and then returns its 64-bit two’s-complement negation. Negation of the high word includes the borrow required when the shifted low word is nonzero.

Under logical-shift semantics that yield zero for 32-bit operands shifted by at least 32, this is a right shift of the Upper:Lower pair followed by negation. The function does not visibly round discarded bits away from zero.

### Nonnegative-fragment shift result

For nonnegative Fragment, the candidate distance is:

\[
D=1086-\text{Fragment}.
\]

The shift-return path is eligible for Fragment from 0 through 1085 inclusive. Fragment 1086 is excluded because the candidate distance is zero. Larger fragments also fail eligibility.

Eligible distances greater than 79 are replaced by 80. The function returns the shifted pair without negation.

### Exact word construction and shift limits

Both shift paths use the same construction before any negative-path negation:

- Start the low result with Lower logically shifted right by the selected distance.
- For distances below 32, combine it with Upper shifted left by \(32-D\).
- At distance 32, combine it with Upper shifted right by zero.
- Above 32, combine it with Upper logically shifted right by \(D-32\).
- The high result is Upper logically shifted right by the selected distance.

Individual shift counts are reduced to their low eight bits. The zero-distance negative exception consequently includes an Upper left shift by 32 in the visible word construction.

This is not enough to prescribe every result without target shift semantics. In particular, zeroing large shifts and masking counts modulo 32 produce different results. The paired-word interpretation is conditional on compatible target behavior; it is not an unconditional replacement for the visible operations.

### Saturation classification

When neither shift path returns, the function forms:

\[
\text{Class}=(2\times\text{High}+[\text{Low}\ne0])\bmod 2^{32}.
\]

The bracket contributes one when Low is nonzero and zero otherwise. Class is compared as an unsigned 32-bit value.

When Class is at most `0xffe00000`, the result is:

| Signed interpretation of High | Result |
|---|---|
| Nonnegative | `0x7fffffffffffffff` |
| Negative | `0x8000000000000000` |

The visible subdivision between values below `0xffe00000` and equality produces the same result.

Describing this as saturation is consistent with the arithmetic, but identifying particular floating-point categories requires evidence not supplied here.

### Exceptional configuration reads and transfers

Stable opaque aliases distinguish the relevant external locations:

| Alias | Visible role |

| **G-transfer-first** | Initially captured first transfer argument in one low-nibble-8 branch. |
| **G-transfer-shared** | Initially captured second argument in that branch; also read by the low-nibble-9 clear-bit branch. |
| **G-transfer-alternate** | Replacement second argument when the low-nibble-8 branch observes bit `0x10` set. |

These names identify locations, not known values or meanings.

First, G-config is read and masked with `0x0f`. This captured low nibble selects the branch. Later configuration tests use additional reads; no single configuration snapshot is established.

**Selected low nibble 10**

1. Reread G-config and test `0x40`.
2. Prepare one argument: zero if clear, or `0x80000000` if set.
3. Perform the unresolved transfer.

**Selected low nibble 8**

1. Reread G-config and test `0x40`.
2. If set, transfer with two explicit zero arguments. No reads of the three transfer-data locations are visible in this subcase.
3. If clear, read G-transfer-first and capture its value for the first argument.
4. Read G-transfer-shared and capture its value for the second argument.
5. Only after both external data reads, reread G-config and test `0x10`.
6. If that bit is clear, transfer with the two captured values.
7. If that bit is set, replace the first argument with zero, read G-transfer-alternate for the second argument, and transfer with that pair.

Both initial data reads occur even when the later `0x10` test causes their values to be discarded. The argument-selection outcome must not be used to omit those established reads or reorder them after that test.

1. Reread G-config and test `0x100000`.
2. If clear, read G-transfer-shared and transfer with zero followed by that value. This is the same external location initially supplying the second argument in the low-nibble-8 sequence.
3. If set, reread G-config again to construct the second argument. Shift that newly read word left by 15, retain 32 bits, complement all 32 bits, then shift left by one and retain 32 bits. Transfer with first argument 8 and that computed second argument.

The configuration value used in the final expression need not equal the value used for the preceding bit test.

The visible representation supplies no explicit arguments to the unresolved transfer.

## Side effects

The only visible direct persistent write is the preparation-path 16-bit flag update. It preserves the initially observed bits and adds `0x0002`. No rollback is visible after either nonzero status.

The update uses the initial flag snapshot, not a fresh read immediately before writing. No atomic read-modify-write or synchronization guarantee is established.

External reads are part of the visible behavior, including discarded reads in the low-nibble-8 branch. Repeated G-config reads are not interchangeable with a single cached value. The material does not independently establish volatile access semantics or a concurrency model.

## Acceptance examples

These are conditional contract examples, not executed tests.

1. **Direct precedence.** Flags `0x000c`, offset 0 equal to `0x89abcdef`, and offset 4 equal to `0x01234567` produce `0x0123456789abcdef`. Conversion dependencies are not selected.

2. **No selected path.** Flags zero produce zero without visible payload reads or dependency calls.

3. **Persistent preparation update.** Initial flags `0x0010` cause a write of `0x0012` before F-98085658bfd4. That dependency receives original flags `0x0010`. A nonzero status returns zero without direct rollback.

4. **Preparation short-circuit and late read.** If the first status is zero and the second is nonzero, extraction is skipped. If both are zero, an offset-20 change made by either call is observable by the subsequent extraction call.

5. **Carry rejection.** A clear second carry test returns `0x8000000000000000`, without reaching the later arithmetic or exceptional transfer.

6. **Positive and negative limits.** Conditional on passing the gate, High `0x43e00000` with Low zero yields `0x7fffffffffffffff`; High `0xc3e00000` with Low zero yields `0x8000000000000000`.

7. **Distance 32.** Conditional on eligible input and zero-producing logical shifts at counts of at least 32, the shifted pair is Upper in the low word and zero in the high word, before any negative-path negation.

8. **Discarded reads remain required.** Suppose the exceptional path selects nibble 8, the subsequent `0x40` test is clear, and the later `0x10` test is set. The visible order is G-transfer-first, G-transfer-shared, G-config, then G-transfer-alternate. The final arguments are zero and the alternate value; the first two reads still occur.

9. **Shared location identity.** If nibble 9 is selected and its `0x100000` test is clear, the second transfer argument comes from G-transfer-shared—the same location read second in example 8—not from G-transfer-alternate.

10. **Repeated configuration observation.** If nibble 9 is selected and its bit test is set, the second argument uses a further G-config read. It is not necessarily computed from the word that selected nibble 9 or the word that passed the bit test.
