# F-634a31ef9eb5

## Purpose

F-634a31ef9eb5 performs a lockstep comparison of two traversal states using two opaque dependencies. Each comparison round processes the first state, obtains one integer result, processes the second state, and obtains another integer result.

The function stops at the first unequal result pair and returns their arithmetic difference. If a round produces two zero results, it returns zero. Equal nonzero results cause another round.

A zero-valued input is replaced with a value read from a shared default location before comparison begins.

This establishes a comparison protocol, not a particular data interpretation. The supplied evidence does not establish that the inputs identify strings, that results represent characters, or that the comparison implements any named encoding, collation, or ordering standard.

## Behavior

### 1. Resolve the initial states

Initialization examines the first input before the second input.

1. If the first input is zero, the function reads the shared default location and substitutes the value obtained.
2. If the second input is zero, the function reads that same location and substitutes the value obtained.
3. The resolved values initialize their respective local state slots.

These are separate conditional reads, not an established single snapshot reused for both inputs. When both inputs are zero, two reads occur in first-input, then second-input order.

A substituted value is not checked again. If a default read yields zero, zero becomes the corresponding state-slot value and processing still proceeds.

No dependency call occurs during this initialization sequence. Whether an external actor can change the shared default between reads is not established.

### 2. Execute a comparison round

At least one round executes. There is no initial equality shortcut and no initial termination check.

Every round has this dependency-call order:

1. Call F-d3922c7fe0ec with the address of the first state slot.
2. Call F-5afffd4d8a24 with no explicit arguments and retain its integer result as the first result.
3. Call F-d3922c7fe0ec with the address of the second state slot.
4. Call F-5afffd4d8a24 with no explicit arguments and retain its integer result as the second result.

The return value of F-d3922c7fe0ec, if it has one, is not used by the visible caller. Its changes to the addressed slot may affect later rounds.

Each subsequent round reuses the same two state slots with whatever contents remain after preceding calls. The function does not reconstruct either slot from the original input.

The first result is obtained before the second slot is processed. Conversely, the second result is obtained after that processing. This ordering is significant if the dependencies communicate through shared state.

### 3. Decide whether to return or continue

The function first compares the two results for inequality.

- If they differ, it returns the first result minus the second result.
- If they are equal and the first result is nonzero, another round begins.
- If they are equal and the first result is zero, it returns zero.

Because equality has already been established on the final branch, testing the first result for zero also establishes that the second result is zero.

A zero result on only one side is therefore a mismatch, not a successful termination condition. Likewise, equal nonzero results do not cause an immediate zero return.

The result is not normalized to a three-valued comparison indicator. For example, a first result of 9 and second result of 4 produce 5, not merely 1, provided the arithmetic is representable.

### 4. Termination and exceptional behavior

There is no visible round limit, input-length bound, cycle detector, or progress check.

The function may continue indefinitely if the dependencies repeatedly produce equal nonzero results. It may also fail to complete if a dependency does not return.

There is no visible handling for dependency faults, exceptions, invalid state values, or arithmetic failures. The source provides no basis for promising recovery, a particular error return, or rollback of earlier side effects.

## Acceptance examples

These examples are conditional behavioral checks, not runtime observations. They assume the dependencies return normally and produce the stated results.

### Immediate equal-zero termination

For any initialized states, if the first round yields 0 and 0:

- Both state-update calls and both result calls occur.
- The function returns 0.
- No second round occurs.

### Immediate nonzero mismatch

If the first round yields 12 and 5:

- The complete first-round call sequence occurs.
- The function returns 7.
- No further state processing occurs.

This distinguishes arithmetic difference from sign-only comparison.

### Zero on only one side

If a round yields 0 and 3, the function returns −3. If it yields 3 and 0, it returns 3.

Neither case takes the equal-zero termination path.

### Equal nonzero prefix

If successive rounds yield the pairs (6, 6), (11, 11), and (0, 0), the function executes three complete rounds and returns 0.

The equality of the first pair does not permit an early return.

### Later mismatch

If successive rounds yield (6, 6) and (4, 10), the function returns −6 after the second round. State changes from the first round remain in effect during the second.

### Default substitution

If only the first input is zero, exactly one default read is required during initialization, and its value initializes only the first state slot.

If both inputs are zero, two separate default reads occur. If those reads yield different values, the two slots begin with different values. No equality of their starting states is guaranteed.

If a default read yields zero, processing still begins; there is no repeated substitution or immediate error return.

### Identical nonzero inputs

Identical nonzero inputs do not bypass the dependencies. The first round still executes fully. A zero return is conditional on dependency results, not guaranteed solely by input equality.

### Arithmetic boundary

Under a separately established signed 32-bit model, results of 2,147,483,647 and −1 require subtraction outside that type’s positive range. The supplied evidence does not establish the returned value or failure behavior for this case. It is documented_only rather than an asserted wrapping example.
