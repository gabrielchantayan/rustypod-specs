# F-13da0922e36d

## Purpose

F-13da0922e36d conditionally scans an indexed object for the first entry whose leading integer value is nonzero. If such an entry is found, it adjusts that value by eight, passes the result to F-2f5be72a6835, adjusts the returned integer by negative eight, and passes that result to F-feee9156a257.

The supplied static representation marks the final dependency as non-returning. Consequently, there are two ordinary return conditions: the initial activation test fails, or the bounded scan finds no qualifying entry. A successful selection instead reaches a terminal dependency call, provided the intervening operations complete.

The business meaning of the entries, the two eight-unit adjustments, and the terminal operation is not established. In particular, the evidence does not establish that this function destroys an object, releases storage, throws an exception, or terminates a process.

## Interface

### Input

The function accepts one pointer to an integer-indexed object. No explicit result value is returned.

The following object locations participate in the behavior:

| Location | Role | Interpretation |
|---|---|---|
| Integer position 0 | Dispatch reference | Supplies the base used to locate an indirectly invoked function. |
| Integer position 1 | Scan bound | Captured once and used as a signed upper bound. |
| Integer position 4 | Activation value | Converted to a character-sized value and compared with zero. |

Under the apparent 32-bit integer layout, these positions begin at byte offsets 0, 4, and 16, respectively. The supplied representation is consistent with a 32-bit address model, but it does not independently establish the original ABI, pointer width, endianness, or character signedness.

The input pointer is not checked for nullness, alignment, or accessibility. At minimum, the activation location must be readable even when the function will return immediately. An active invocation also requires the bound location to be readable. Dispatch-related storage is needed only if the captured bound permits at least one iteration.

### Indirect indexed operation

For every visited index, the function:

- Obtains the dispatch base from integer position 0 of the input object.
- Obtains an indirect callable target from a location 64 bytes beyond that base.
- Invokes that target with the original object pointer and the current index.
- Treats its result as a pointer to an integer-bearing entry.

The target’s identity is not supplied. This contract therefore calls it the **indexed-entry dependency**, without assigning it an invented opaque function ID.

Each returned entry pointer must support a read of its first integer. A null entry pointer is not treated as an empty entry: the pointer itself is dereferenced without a preceding check.

### Output and completion

There is no explicit scalar return value.

An ordinary return occurs when:

- The activation conversion yields zero; or
- The captured signed bound is nonpositive; or
- Every visited entry has a zero first integer.

If a nonzero entry is selected, the function proceeds to the two named dependencies. The static representation identifies the final call as non-returning; the mechanism and externally visible outcome of that non-return are unknown.

## Behavior

### Activation gate

The first decision reads integer position 4 and converts that integer to the representation’s character type. The function returns immediately if the converted value is zero.

This is a character-conversion test, not a comparison of the entire integer with zero. Under an eight-bit truncating character model, an integer whose low eight bits are zero fails this gate even if its remaining bits are nonzero. An integer whose converted character is nonzero passes it regardless of whether that character is interpreted as positive or negative.

The representation does not establish character width or all language-level conversion rules. The low-eight-bit interpretation is therefore conditional on the expected eight-bit target model, not an unconditional portable-language claim.

When this gate fails, the scan bound and dispatch reference are not needed by the visible body, and no dependency is called.

### Bound capture

After the activation gate passes, integer position 1 is read into a local scan bound. The starting index is zero.

The bound is captured once. It is not reloaded between iterations. A dependency that changes the object’s bound field does not, by that change alone, alter the bound already governing this invocation.

The comparison between the bound and the index is signed. A bound of zero or a negative bound produces an immediate ordinary return without invoking the indexed-entry dependency.

For a positive bound, the candidate indices are zero through one less than the captured bound, in ascending order.

### Indexed scan

Before each attempted lookup, the function checks whether the current index has reached the captured bound. It returns when that condition holds.

Otherwise, it obtains and invokes the indexed-entry dependency using the current dispatch reference. The dispatch reference is not captured alongside the bound: its source location is consulted for each attempted lookup. Thus, if an earlier dependency call changes that location, a later iteration can use a different dispatch base or target.

After the indexed-entry dependency returns, the first integer at its returned pointer is tested:

- A zero value causes the index to advance by one and the scan to continue.
- A nonzero value ends the scan immediately and selects that entry.
- An invalid returned pointer has no explicit recovery path in this function.

The function does not inspect later indices after selecting an entry. It does not aggregate values, count nonzero entries, or process all qualifying entries.

Under the apparent signed 32-bit model, the loop’s index increment does not itself require signed overflow. Even with the largest positive bound, the final unsuccessful increment reaches that bound; the next comparison ends the scan before another increment.

### Selected-entry processing

Once an entry passes the nonzero test, its first integer supplies the argument for further processing.

The visible representation uses the entry’s first integer both for the selection test and again for the argument calculation. These are separate source-level uses. There is no intervening dependency call between them, but the evidence does not establish volatile access, atomicity, concurrent-access legality, or an exact count of machine-level loads.

The subsequent sequence is:

1. Add eight to the selected entry’s first integer.
2. Call F-2f5be72a6835 with the adjusted value.
3. Subtract eight from that dependency’s returned integer.
4. Call F-feee9156a257 with the second adjusted value.

These are integer-valued adjustments in the supplied representation. They are not scaled array indexing. If the integers encode addresses on the intended target, the apparent address displacement is eight bytes.

The first adjustment does not establish anything about the second dependency’s result. In particular, the result of F-2f5be72a6835 need not equal its argument. The two adjustments cannot be canceled across that call.

Neither adjustment has a visible range check. Under a signed 32-bit interpretation:

- Adding eight is representable only when the selected value is no greater than 2,147,483,639.
- Subtracting eight is representable only when the returned value is at least −2,147,483,640.

The representation alone does not establish whether out-of-range cases wrap according to machine arithmetic, are invalid under the original language semantics, or reflect imperfect recovered typing. A defined-behavior contract must either constrain these operands to representable ranges or obtain additional arithmetic evidence.

### Terminal handoff

F-feee9156a257 is called only after F-2f5be72a6835 returns a usable result.

The final call is annotated as non-returning in the supplied static evidence. No continuation, cleanup, additional iteration, or ordinary return after that call is visible. If the dependency unexpectedly returns, the function’s subsequent behavior is not established.

## Side effects

The visible body contains no explicit writes to the input object, an entry, or global storage. It does not explicitly allocate or release memory.

That absence does not make the function side-effect-free:

- The indexed-entry dependency can act on the original object and other state.
- F-2f5be72a6835 may have side effects beyond producing its result.
- F-feee9156a257 may change state before its non-returning outcome.
- Any dependency may alter globals or storage reachable through its inputs unless another contract says otherwise.

No ownership transfer is established. Passing an integer that may encode an address does not prove that the recipient acquires, retains, borrows, or releases the associated storage. Likewise, this function does not visibly release the entry pointer returned by the indexed-entry dependency; whether a release is required is unknown.

The logical order of the visible operations is significant:

- Activation is checked before the bound is captured.
- The bound is captured before any indexed lookup.
- Each lookup completes before its returned entry is inspected.
- Each zero-entry inspection precedes the next lookup.
- The first qualifying entry is selected before F-2f5be72a6835 is called.
- F-2f5be72a6835 returns before its result is adjusted and supplied to F-feee9156a257.

This is an ordering contract for the supplied representation, not evidence of memory barriers or inter-thread synchronization.

## Acceptance examples

These are conditional contract examples, not observed runtime results. Unless stated otherwise, they assume valid readable storage, normal returns from dependencies preceding the terminal call, and representable arithmetic.

1. **Inactive object.**  
   If the activation conversion yields zero, the function returns without calling any dependency. A nonzero full-width activation integer does not contradict this outcome if its character conversion is zero.

2. **Active object with a negative bound.**  
   With a nonzero converted activation value and a captured bound of −1, the function returns without dispatching index zero. The signed bound is not reinterpreted as a large unsigned count.

3. **Active object with a zero bound.**  
   No indexed lookup occurs. The visible body does not require a usable dispatch target on this path.

4. **All entries empty.**  
   With a captured bound of three and zero first integers returned for indices zero, one, and two, exactly those three lookups occur in that order. The function then returns without calling either named dependency.

5. **First qualifying entry wins.**  
   With a bound of four, zero at index zero, and 100 as the first integer at index one, only indices zero and one are looked up. F-2f5be72a6835 receives 108. If it returns 240, F-feee9156a257 receives 232.

6. **Negative nonzero values qualify.**  
   If the first visited entry contains −16, it is selected. F-2f5be72a6835 receives −8. Selection does not require a positive value or a validated address.

7. **Bound mutation does not shorten the captured scan.**  
   If the captured bound is three and the first indexed call changes the object’s bound field to zero while returning a zero entry, the next attempted index is still one. This assumes the mutation does not otherwise invalidate the object or control flow.

8. **Dispatch mutation can affect later lookups.**  
   If the first lookup changes the object’s dispatch reference and returns a zero entry, the next lookup obtains its target using the updated reference. This contrasts with the once-captured bound.

9. **Invalid entry pointer is not an empty result.**  
   If an indexed call returns a null pointer, this function attempts to inspect storage through it. It has no explicit branch that treats null as zero-valued entry content; the resulting fault or language-level behavior is outside the established contract.

10. **Terminal behavior remains dependency-defined.**  
    Reaching F-feee9156a257 establishes that the adjusted argument is handed off. It does not establish process exit, exception propagation, object destruction, or any particular externally visible termination mechanism.
