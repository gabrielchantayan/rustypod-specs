# F-d23d87bb8769

## Purpose

F-d23d87bb8769 performs an alias-sensitive sequence of memory publications, narrow writes, and dependent address traversals. It then exposes a partially initialized local region to an entry-supplied callable, invokes F-cdec09f5d432, and reaches a terminal sequence involving a helper and a result-derived callable.

No application-level purpose, conventional data structure, or ownership-transfer protocol is established. Organized propagation of linked state is **inferred intent**, not a guaranteed object model.

This contract describes **established static evidence** from the supplied representation. Execution-model questions and dependency behavior that cannot be resolved from that evidence are marked **documented_only**. No runtime tests have been performed.

## Behavior

### Publication, retention, and aliasing

The main sequence contains eighteen **exchanges**. Each exchange starts with the same ordered obligations:

1. A forwarded word is acquired from the current source at offset 0x44.
2. The current anchor is published to its own offset 0x54.
3. The replacement source is evaluated once, establishing the exchange’s cursor.
4. A second evaluation supplies the word published at the recipient’s offset 0x44.
5. The forwarded word is stored at the cursor’s offset 0x14.

The two replacement evaluations have different roles. Subsequent cursor-dependent operations use the first value; recipient publication uses the second. Their equality is not established. Nor is it established whether the representation corresponds to two physical loads.

For exchange 01, the source and recipient are the initial read base and initial recipient. Thereafter the source is the preceding cursor, including any expressly described descent. Recipients arise from the dependent reads described below.

These obligations are alias-sensitive. A store may affect a later source evaluation, dependent read, or local slot. No read may be treated as an entry snapshot merely because its address expression resembles an earlier one. Repeated effects remain distinct even when their nominal addresses and payloads match.

Before exchange 01, a short containing the initial recipient’s low 16 bits is written at the sum of the initial displacement and initial read base.

### Early transport and recipient selection

The anchor remains unchanged through exchange 08.

**Exchanges 01–02 establish retained payloads and followed recipients.** In exchange 01, after the common publication sequence and doubled-anchor byte write, the input-base word at 0x64 and anchor word at 0x44 are sampled before the signed short at anchor plus cursor. The sampled anchor word is followed through offset 0x14 to obtain the next recipient.

Exchange 01 also places the forwarded byte at input-base offset 0x15, places the entry payload at cursor offset 0x24, retains cursor offset 0x74, and copies the earlier input sample’s byte to cursor offset 0x0d. The input byte write precedes the recipient-following read; the cursor word store precedes the 0x74 read.

Exchange 02 reuses that input byte at anchor offset 0x11, samples anchor offset 0x44 and the signed short, and again writes the forwarded byte at input-base offset 0x15 before following the anchor sample through offset 0x14. The earlier 0x74 payload is stored at the new cursor’s offset 0x24 before a fresh 0x74 word is retained. The input base then replaces cursor offset 0x14. Subsequent byte writes place the input base at anchor offset 0x11 and the cursor at recipient offset 0x09.

For both exchanges, the closing short contains the selected recipient and is addressed by the signed-short sample plus the current cursor.

**Exchanges 03–06 change how recipients are obtained.**

### Probe observations, root acquisition, and anchor changes

Exchange 07 samples probe offset 0x64 after the doubled-anchor byte write, followed by anchor offset 0x44 and the signed short at anchor plus cursor. The forwarded word, used as an address, receives the anchor at offset 0x54. The probe sample’s byte is written at anchor offset 0x11.

The sampled anchor-offset-0x44 destination then receives the cursor at offset 0x44. Only afterward is signed-short-result offset 0x44 read as the next probe address. Cursor offset 0x14 selects the next recipient. The probe-derived anchor byte write is repeated before the closing short.

Exchange 08 obtains a **root** from offset 0x44 of a newly read signed-short result, after its doubled-anchor byte write. The root is also stored in a local slot. Cursor offset 0x14 selects the next recipient; the latest probe’s offset-0x64 word supplies anchor offset 0x11. Root offset 0x04 is sampled before cursor offset 0x74. The former sample is stored at anchor offset 0x54.

The exchange-08 closing short is exceptional: its address is twice the anchor plus cursor, not signed-short result plus cursor.

Exchange 09 uses the retained root-offset-0x04 byte at anchor offset 0x11, then samples root offset 0x64, anchor offset 0x44, and the signed short. Root offset 0x54 receives the retained exchange-08 cursor-offset-0x74 word. Cursor offset 0x14 selects a new anchor, whose offset 0x0d receives the cursor byte. The closing short still uses the old anchor’s signed-short sample and old anchor-offset-0x44 payload. That payload becomes the next recipient.

Exchange 10 uses exchange 09’s root sample byte at the new anchor’s offset 0x11. After sampling anchor offset 0x44 and the signed short, it repeats the root-offset-0x54 store. Cursor offset 0x14 selects another anchor, which receives the cursor byte at offset 0x0d. The cursor then descends through the forwarded word’s offset 0x14.

The retained exchange-08 word, now used as an address, receives the root at offset 0x54. The closing short uses the earlier signed-short sample plus the descended cursor, with the sampled previous-anchor-offset-0x44 word as payload.

Next, cursor offset 0x14 receives the link. A fresh retained-target-offset-0x44 read supplies cursor offset 0x0d’s byte. New-anchor offset 0x0d receives the link byte, followed by the closing short containing the link.

Exchange 17 begins with the previous root sample byte at anchor offset 0x11, then samples root offset 0x64, a new link at anchor offset 0x44, and the signed short. The forwarded word receives the anchor at offset 0x54. A byte with no established earlier definition is then written at anchor offset 0x11.

The new link receives the cursor at offset 0x44 before signed-short-result offset 0x14 selects the next anchor. Link self-publication and a second sum-address store follow. This store has the same retained-target payload but uses exchange 17’s independently acquired first replacement value and forwarded word. Exchange 18 uses exchange 17’s root sample byte at anchor offset 0x11, then reads the last link and signed short. Two word stores publish that signed-short result to its own offset 0x54. They alternate with two stores of the anchor byte at cursor offset 0x11. All four effects remain distinct.

### Product-dependent continuation

The last signed-short result multiplied by the last link selects successive word reads through offsets 0x44, 0x74, and 0x14, yielding a selected node. That node’s offset-0x14 word is saved before the slot is overwritten with the doubled anchor.

The saved word’s offset-0x14 word, multiplied by the signed-short operand, forms a **first product base**. A signed-short self-publication at offset 0x54 precedes writing the saved word’s byte at cursor offset 0x11. First-product-base offset 0x74 supplies a **late word**, also saved locally.

Multiplying the first product base by the signed-short operand forms a **second product base**. Another signed-short self-publication precedes a cursor-offset-0x11 write whose byte payload has no established earlier definition.

The remaining observation constraints are:

- Second-product-base offset 0x44 is read before root offset 0x74.
- Cursor offset 0x64 receives the late word, then cursor offset 0x09 receives the first sample’s byte.
- Second-product-base offset 0x44 is reloaded; its byte is written at that base’s offset 0x11.
- Another signed-short self-publication precedes a late-word byte write at twice the second product base plus 0x11.
- A word is read at signed-short operand times second product base plus 0x44, before root offset 0x14 supplies the final destination base.
- The root-offset-0x74 sample’s byte goes to late-word offset 0x01.
- Final-destination offsets 0x11 and 0x09 receive, respectively, the product-selected word’s byte and doubled-second-product-base byte.

The repeated offset-0x44 observations are not interchangeable.

## Acceptance examples

These are conditional static consequences, not executed tests.

1. **Different replacement values:** if an exchange’s first replacement evaluation yields one address and its second yields another, the first determines the cursor and its offset-0x14 store. The second is published at recipient offset 0x44.

2. **Initial overlap:** if the initial short write overlaps the first forwarded-word source, the forwarded-word read occurs after that mutation. An implementation using the pre-write word would not preserve the represented ordering.

3. **Signed addressing:** a short encoding −2 contributes −2 rather than 65534. A character containing 0xff may contribute −1 or 255; choosing either interpretation requires resolving character signedness.

4. **Exceptional closing address:** exchange 08 closes at twice the anchor plus cursor. Substituting the usual signed-short-result-plus-cursor address changes the contract.

5. **Independent sum stores:** exchanges 16 and 17 each use their own first replacement evaluation and forwarded word. Their equal retained-target payload does not imply equal destinations.

6. **Retention versus reload:** selected-node offset 0x14 is preserved as a value before overwrite. In contrast, the later repeated second-product-base-offset-0x44 read may observe intervening aliased writes.

7. **Partial local preparation:** no zero value is guaranteed for an unlisted local slot. Listed preparation writes also do not override intervening alias effects or dependency mutations.

8. **Post-call acquisition:** if F-opaque-01 changes the separate external source and returns, F-cdec09f5d432 receives the subsequently evaluated value, not an entry snapshot.

9. **Terminal interaction:** if progression reaches F-opaque-02, both operands are supplied. If it returns and progression continues as represented, its result determines a callable invoked without explicit arguments. Neither successful invocation nor a helper trap is independently established.
