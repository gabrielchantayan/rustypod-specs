# F-133067dd521d

## Purpose

F-133067dd521d updates one of two 32-bit fields in a caller-provided memory object, marks the object through a 16-bit flag field, invokes F-49743e74136c, and stores that dependency’s 32-bit result in the object.

The selector determines which arithmetic field is updated. Exactly two selector values choose the field at byte offset 304; every other value chooses the field at byte offset 300.

The meanings of the arithmetic fields, flag bits, and dependency result are not established. Descriptions such as “position,” “dirty flag,” or “timestamp” would be inferred intent, not supported interface guarantees.

This contract describes behavior supported by the supplied static representation. No runtime tests have been performed.

| Input | Represented type and width | Role |

| Selector | 32-bit integer | Chooses the arithmetic field |

The selector is compared by exact equality. Values 1 and 256 select the same field. The representation does not support interpreting the selector as a bitmask, a Boolean, or an enumeration restricted to those two values.

## Behavior

### Field selection

The selected arithmetic field is determined as follows:

- Selector 1: offset 304.
- Selector 256: offset 304.
- Every other selector value: offset 300.

The supplied representation repeats the same selection condition for the read and write. Because the selector is a by-value input and there is no intervening dependency call, both accesses select the same field.

Negative selectors, zero, and values containing bit 256 alongside other bits all use offset 300 unless the complete value is exactly 1 or exactly 256.

### Ordered direct effects

The supported logical order is:

1. Read the selected 32-bit arithmetic field.
2. Add the 32-bit adjustment and write the result to that same field.
3. Read the 16-bit flag field at offset 0 and write it back with every bit in the upper byte set.
4. Invoke F-49743e74136c with no explicit arguments.
5. If the dependency returns normally, write its four-byte result at offset 8.
6. Return without an explicit value.

This is the order expressed by the supplied static representation. It does not establish processor-level atomicity, synchronization, or an exact bus-access trace.

### Arithmetic update

Only one arithmetic field is directly updated. The other arithmetic field is neither directly read nor directly written by this function.

For additions whose mathematical result is within the signed 32-bit range, the selected field receives that result. The adjustment may be positive, zero, or negative; there is no visible clamping or rejection of negative values.

No overflow detection, saturation, or error reporting is shown. Overflow behavior needs qualification:

- A fixed-width 32-bit machine addition ordinarily retains the low 32 bits of the sum.
- The supplied representation expresses the operation using signed integers, for which source-language overflow rules may differ.
- No instruction-level evidence or execution result is provided to resolve that distinction.

Accordingly, behavior for an out-of-range signed sum is **documented_only**, not an unconditional modular-arithmetic guarantee.

### Flag update

The flag operation sets bits 8 through 15 and preserves bits 0 through 7 as read at the flag-update stage.

For example, a flag value of 0x12A5 becomes 0xFFA5. A value already equal to 0xFFA5 remains equal to 0xFFA5.

“Upper byte” refers to numeric bit significance. The supplied material does not establish target byte order, so it does not establish which addressed byte contains those bits.

The flag read occurs after the arithmetic-field write. The function does not capture the flag value at entry.

### Dependency-result update

F-49743e74136c is called after both the arithmetic update and flag update. Consequently, those direct writes have occurred before control enters the dependency.

The four-byte value returned by a normal dependency return is stored at offset 8 without a visible comparison, conversion, or validity check. All four bytes of that destination field are replaced; its previous value is not directly read.

No special dependency-result value is treated as an error in the supplied representation.

## Side effects

The function’s direct memory effects are limited to:

- One 32-bit update at either offset 300 or offset 304.
- One 16-bit update at offset 0.
- One 32-bit replacement at offset 8 after a normal dependency return.

This list does not bound the dependency’s effects. F-49743e74136c may have access to global state, shared state, or aliases of the object. Its behavior is not supplied.

Therefore:

- The unselected arithmetic field is unchanged **by the caller’s direct operations**, but cannot be promised unchanged across the dependency call.
- The flag has its upper eight bits set immediately before the dependency call, but its final value is not guaranteed if the dependency can modify it.
- The arithmetic update is completed before the dependency call, but the dependency may subsequently overwrite that field.
- A dependency write to offset 8 during its execution is followed by this function’s replacement of that field if the dependency returns normally and the object remains writable.

The operation is not presented as transactional. If the dependency does not return normally, there is no shown rollback of the earlier arithmetic and flag writes. The final result-field write is then not reached through the represented normal path.

No locking or atomic read-modify-write operation is shown. Concurrent access requires external rules not established here.

## Acceptance examples

These are conditional acceptance criteria derived from the supplied representation, not observed test results. Unless stated otherwise, assume valid storage, representable signed arithmetic, a normally returning dependency, and no dependency changes to the object.

### Selector 1 chooses offset 304

Given:

- Selector: 1.
- Adjustment: 7.
- Field at offset 300: 90.
- Field at offset 304: 20.
- Flags: 0x12A5.
- Dependency result: 0x12345678.

- Offset 304: 27.
- Flags: 0xFFA5.
- Offset 8: 0x12345678.

The dependency is invoked after offset 304 and the flags have been updated.

### Selector 256 has the same selection behavior

Given selector 256, adjustment −9, and a value of 20 at offset 304, the selected field becomes 11. The field at offset 300 is not directly accessed.

### Selection uses exact equality

Given selector 257, adjustment 4, a value of 10 at offset 300, and a value of 80 at offset 304:

- Offset 300 becomes 14.
- Offset 304 remains 80 under the stated dependency assumptions.

The presence of the 256 bit in selector 257 does not select offset 304.

### Zero adjustment does not skip later effects

Given adjustment zero:

- The selected field’s value remains numerically unchanged.
- The represented read and write of that field still occur.
- The flags are still updated.
- The dependency is still invoked.
- Its result is still written at offset 8 after normal return.

### Low flag bits are preserved at the update stage

Given flags 0x003C, the direct flag update produces 0xFF3C. Given flags 0xFF3C, it produces the same value.

These criteria concern the direct flag update, not preservation against later dependency effects.

### Dependency mutation affects the final state

If the dependency changes the flags to 0x0000 and then returns normally, the caller does not subsequently reapply the upper-bit mask. The flags may therefore finish as 0x0000.

If the dependency writes a value to offset 8 and then returns a different four-byte value, the caller’s subsequent store replaces the dependency-written value with the returned value.

### Overflow remains conditional

Given a selected field equal to the maximum signed 32-bit value and adjustment 1, this contract does not unconditionally require the minimum signed 32-bit value. That outcome requires confirmation of wrapping machine arithmetic. No saturation or explicit overflow error is shown.
