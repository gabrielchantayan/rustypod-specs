# F-36ced77103d2

## Purpose

F-36ced77103d2 performs an in-place, callback-directed partitioning operation on a range of 32-bit words. For ranges of at least 17 words, it either delegates to F-e97908f97bd2 or selects a pivot, partitions the range, processes the right partition recursively, and then continues with the left partition.

The structure suggests a sorting-related operation with a small-range cutoff and an alternate processing path. That intent is inferred, not a complete behavioral guarantee. In particular:

- Ranges of 16 or fewer words are left unprocessed by this function.
- One pivot-selection branch invokes the callback with only one explicit argument.
- The right recursive call receives the unchanged control value; only subsequent left-side processing halves it.
- Correctness and termination depend on callback behavior and valid memory access conditions not enforced here.

This contract describes the supplied static evidence. It does not establish that the function independently sorts its entire input.

### Range layout and arithmetic

Words occupy four bytes each. There is no visible element header, stride parameter, allocation descriptor, or separate length.

The size calculation converts both endpoint addresses to signed integer form, subtracts the start address from the end address, and shifts the result right by two bits. The resulting signed value is compared against 17.

For an ordinary, aligned range whose byte difference is representable in the relevant signed arithmetic, this corresponds to its number of four-byte words. The source does not establish portable behavior for address truncation, signed subtraction overflow, or right-shifting a negative value. Those cases must not be silently treated as ordinary mathematical range-length calculations.

The midpoint used for pivot selection is the start plus half the calculated word count. Since pivot selection occurs only when that count is at least 17, midpoint division is over a positive value and rounds down.

### Callback interface

Most visible invocations supply two 32-bit word values. These are values read from the range, not addresses of the slots containing them.

The callback result is interpreted as a signed integer only to distinguish zero from nonzero. Positive and negative nonzero results take the same branches. A conventional negative/zero/positive three-way comparison contract is therefore not interchangeable with a Boolean ordering predicate.

One invocation supplies only the midpoint word as an explicit argument. The callback’s true ABI, any implicit arguments, and any meaning of an absent second argument are unknown.

## Behavior

### 1. Initial cutoff and delegation

Each processing pass first calculates the signed word count.

If that count is less than 17, the function returns immediately. This test precedes the control-value test. Consequently, a short range with a zero control value does not invoke F-e97908f97bd2.

If the count is at least 17 and the control value is zero, the function invokes F-e97908f97bd2 with five arguments, in this order:

1. Current range start.
2. Current range end.
3. Current range end again.
4. Integer zero.
5. The callback.

It then returns. There is no subsequent partitioning or cleanup visible in this function after that dependency returns. Its return value, if any, is not used.

### 2. Pivot selection

For a range of at least 17 words and a nonzero control value, three candidate positions are identified:

- **First:** the range start.
- **Middle:** the start plus the rounded-down half-count.
- **Last:** the word immediately before the exclusive end.

The function chooses one candidate through the following callback decision tree. “Zero” and “nonzero” refer to the callback result, not to the candidate word.

| First callback: first, middle | Next callback and result | Further callback and result | Chosen candidate |
|---|---|---|---|
| Zero | First, last: nonzero | None | First |
| Zero | First, last: zero | Middle, last: nonzero | Last |
| Zero | First, last: zero | Middle, last: zero | Middle |
| Nonzero | Middle only: nonzero | None | Middle |
| Nonzero | Middle only: zero | First, last: nonzero | Last |
| Nonzero | Middle only: zero | First, last: zero | First |

The “middle only” invocation is a material interface irregularity. The supplied source does not support replacing it with an assumed two-argument comparison.

Candidate positions are established before these calls, but candidate values are not all captured in advance. Values used for later callback invocations are read when those invocations are reached. If the callback changes the underlying range through other accessible state, subsequent invocations can observe those changes.

After selection, the function reads the selected slot into a local 32-bit pivot value. Scanning then uses this captured value. Later changes to the selected slot do not automatically change the pivot value supplied to scan callbacks.

### 3. Partition scanning

The left scan position begins at the range start. The right scan position begins at the exclusive end.

The repeated scanning behavior is:

- The callback receives the current left-slot value and the captured pivot.
- A nonzero result advances the left position by one word and begins another left-side comparison.
- A zero result starts or resumes a rightward-side search performed by moving the right position backward.

For the right-side search, the right position is decremented by one word **before** its word is read. The callback then receives the captured pivot followed by the current right-slot value. A nonzero result repeats the decrement-and-compare process.

Once that callback returns zero, the function compares the two positions:

- If the right position is at or before the left position, partition scanning stops.
- Otherwise, their current words are exchanged, the left position advances by one word, and scanning continues.

There is no boundary check before a left-slot read and no boundary check before a right-side decrement and read. The crossing check occurs only after a right-side comparison has returned zero.

Consequently, even reaching the opposite scan position does not by itself stop a scan. A callback that keeps returning nonzero can cause out-of-range accesses.

### 4. Exchange ordering

For an exchange between distinct left and right positions, the visible memory operations occur in this order:

1. Read the current left word into temporary storage.
2. Read the current right word.
3. Write that right word to the left slot.
4. Write the saved left word to the right slot.

The callback is not invoked between these exchange operations.

These are the slot contents at exchange time, after the preceding callbacks. The function does not reuse the earlier comparison’s left-slot value as the saved exchange value.

The exchange uses raw 32-bit copies. No element-specific copy, destruction, ownership transfer, or reference-counting operation is visible.

### 5. Right processing, then left continuation

When partition scanning stops, the current left position becomes the split point.

The function first recursively processes the half-open range from the split point to the current exclusive end. That call receives:

- The unchanged control value.
- The same callback.

Only after that recursive call returns does the current invocation:

- Divide its control value by two using signed integer division.
- Replace its exclusive end with the split point.
- Repeat processing for the resulting left range.

Thus, right-side processing occurs before left-side continuation. The control value is not decremented or halved before the right recursive call.

For positive control values, repeated left continuations eventually reach zero. Negative values are not rejected; signed division by two moves them toward zero with truncation toward zero. Neither observation establishes termination of the entire operation, because right recursion retains the original control value and partition progress depends on callback behavior.

- Exactly 17 valid writable words.
- A nonzero control value.
