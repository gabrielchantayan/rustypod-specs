# F-d27c6768073e

## Purpose

F-d27c6768073e conditionally constructs a four-word value from object-associated state and an input position, then passes that value to F-6d16652f2d03.

Two construction modes are visible:

- **Ordinary mode:** copy a four-word value from an associated object and request an adjustment based on the input’s displacement from a stored lower bound.
- **Adjusted mode:** combine an associated value, arithmetic-helper results, and a dynamically obtained reference position. Apply a different adjustment on either side of an unsigned threshold, with a one-unit modification to the third word below that threshold.

The interpretation of the four-word values as geometry, ranges, or another domain-specific structure is not established. Likewise, the arithmetic helpers’ mathematical meanings are not available. This contract describes their observable invocation and the surrounding control flow without assigning them unverified semantics.

There is no explicit return value. Normal completion includes both early exits and completion after calling F-6d16652f2d03. No status or error code is produced.

- The second and fourth words are copied without an established numeric interpretation.

### Preconditions

The receiver must be readable wherever an executed path accesses it. There is no receiver-null check.

Each nonzero associated-object pointer must designate readable storage covering the offsets actually used. The associated-object pointer is checked for zero only at initial eligibility; later reads reload it without repeating that check.

The secondary-object pointer is checked before each of its two possible snapshot operations. A zero value invokes F-a817d8d58c10 rather than returning an error.

Adjusted mode additionally requires a usable dispatch-table pointer and callable entry. Neither is validated locally.

These are path-dependent requirements. An ineligible invocation need not access the secondary object or dispatch table.

## Behavior

### 1. Eligibility and initial snapshot

Eligibility is evaluated in this order, with short-circuit behavior:

1. Read the associated-object pointer at receiver offset `0xEC`. If zero, return.
2. Read the lower bound at `0x100`. If it is greater than the position under signed 32-bit comparison, return.
3. Read the upper bound at `0x104`. If the position is greater than or equal to it under signed 32-bit comparison, return.

Thus the position must lie in the signed half-open interval from the lower bound through, but excluding, the upper bound. An empty or reversed interval admits no position.

For an eligible invocation, the function reads the secondary-object pointer at `0x34`. If zero, it calls F-a817d8d58c10, which is represented as nonreturning.

Otherwise, it copies the secondary object’s four words at offsets `0xD0` through `0xDC` into a temporary value, in ascending offset order.

It then:

1. Reloads the associated-object pointer.
2. Calls F-b01436b9ce2b with the address at associated-object offset `0x80`.
3. Calls F-870c4fcf7295 with:
   - the initial secondary snapshot’s third word minus its first word;
   - the result from F-b01436b9ce2b.

The recovered call interface exposes a primary result and an auxiliary result from F-870c4fcf7295. The first primary result is not used. The auxiliary result participates in mode selection.

This arithmetic-helper call occurs even if flag `0x1` will subsequently cause an ordinary-mode early return.

### 2. Mode selection

After those calls, the function reads the flags at receiver offset `0x124`.

Adjusted mode is selected only when both conditions hold:

- Flag `0x20000` is set.
- The first F-870c4fcf7295 auxiliary result is nonzero.

Otherwise, ordinary mode is selected. The auxiliary-result test is needed only when `0x20000` is set.

These flags are read after the preceding helper calls. They are not an entry-time snapshot.

### 3. Ordinary mode

Ordinary mode rereads the flags and returns immediately if flag `0x1` is set.

If that flag is clear, the function:

1. Reloads the associated-object pointer.
2. Copies its four words at offsets `0x80` through `0x8C` into a temporary value.
3. Rereads the lower bound from receiver offset `0x100`.
4. Calls F-d156b0b83eb3 with:
   - a pointer to that temporary value;
   - zero as the second argument;
   - an adjustment equal to the position minus the newly read lower bound, multiplied by the snapshot’s third word minus its first word.
5. Calls F-6d16652f2d03 with the receiver and the same temporary-value pointer.

The value passed to F-6d16652f2d03 is the temporary after F-d156b0b83eb3 returns. The body does not establish how that helper transforms it.

The lower bound used here can differ from the bound used for eligibility if an intervening dependency changes receiver state.

### 4. Adjusted mode setup

Adjusted mode does not apply the ordinary-mode early return for flag `0x1`.

It first repeats the associated-value lookup:

1. Reload the associated-object pointer.
2. Call F-b01436b9ce2b with the address at its `0x80` offset.
3. Call F-870c4fcf7295 again, using the original secondary snapshot’s third-minus-first difference and this new helper result.

The first and second F-b01436b9ce2b calls are independent. Their results must not be assumed equal.

Using the second arithmetic invocation’s primary and auxiliary outputs, the function then:

1. Calls F-d7be9cfb4000 with the auxiliary output and the primary output minus one.
2. Replaces that call’s result with one if it is zero; otherwise retains it.
3. Calls F-d7be9cfb4000 again with the recovered auxiliary value and the retained, nonzero result.
4. Retains this second call’s result as an **unsigned 32-bit threshold**.

The nonzero substitution applies to the first F-d7be9cfb4000 result only. There is no corresponding substitution for the threshold.

Next, the function reloads the secondary-object pointer. If it is now zero, F-a817d8d58c10 is invoked. Otherwise, another four-word secondary snapshot is taken. This second snapshot has no visible subsequent contribution to the value construction, but its reads and null check remain part of the observed behavior.

The function then reloads the associated-object pointer and snapshots its four words at offsets `0x80` through `0x8C`.

Finally, it resolves and invokes the dispatch-table entry at `0x1A8`, passing the receiver. The returned 32-bit integer is the **reference position**.

### 5. Adjusted mode position handling

The function subtracts the reference position from the input position and stores the result in a 32-bit unsigned quantity, the **displacement**.

It then interprets that displacement as signed. If this signed interpretation is negative, the function returns without calling F-d156b0b83eb3 or F-6d16652f2d03 on this path.

This is a sign test of the resulting 32-bit displacement, not a separately expressed comparison between the original position and reference position. Overflow and out-of-range mathematical differences therefore require attention.

If the sign test permits continuation:

1. Copy the previously captured associated snapshot into the output temporary.
2. Call F-d156b0b83eb3 on that temporary, with zero as its second argument and an adjustment equal to the reference position multiplied by the associated snapshot’s third-minus-first difference.
3. Form an increment by adding that difference to the retained nonzero result of the first F-d7be9cfb4000 call.
4. Compare the displacement with the threshold using unsigned comparison.

If the displacement is **strictly less than** the threshold:

- Call F-d156b0b83eb3 with adjustment equal to displacement multiplied by the increment.
- After that call returns, increment the temporary’s third word by one.
- Call F-6d16652f2d03 with the receiver and this temporary.

Otherwise:

- Call F-d156b0b83eb3 with adjustment equal to threshold multiplied by the increment.
- Call it again with adjustment equal to displacement minus threshold, multiplied by the original associated snapshot’s third-minus-first difference.
- Call F-6d16652f2d03 with the receiver and this temporary.

At equality, the latter branch is selected. Its second adjustment has a zero displacement factor, but the helper call still occurs. There is no explicit third-word increment in that branch.
