# F-cd8715b81e4f

## Purpose

F-cd8715b81e4f conditionally updates three fields of a caller-supplied object. It checks a 32-bit request against an object-resident bound, then takes one of three paths:

- Reject the request, with no explicit object writes.
- Reset the destination fields for an admitted zero request.
- For an admitted positive request, prepare an offset, commit a position, compute and store a two-word quantity, and invoke final processing.

“Position,” “offset,” “bound,” and “quantity” describe the observed data flow. Their domain meanings and units are not established.

The supplied representation constructs a 64-bit return. Its low word is a constant or a result from final processing. Its high word comes from temporary storage that is initialized only on positive-request paths. The complete return therefore has no established meaningful value on rejection before preparation or on the zero-request path.

## Interface

### Inputs and preconditions

The function receives:

1. An object address represented by a 32-bit address-like argument.
2. A 32-bit request bit pattern.

Admission uses signed 32-bit comparisons, despite the request’s unsigned representation.

The function performs no explicit validation of the object address, accessible extent, alignment, lifetime, or concurrent access. Every location actually reached must support the corresponding access for execution to proceed normally. Dependency-specific requirements are additional and unknown.

### Referenced object fields

Offsets are byte offsets from the supplied object address.

| Offset | Width | Observed role |
|---|---:|---|
| `+0x08` | 32 bits | Admission bound; the saved value also supplies a fallback argument. |
| `+0x0C` | 32 bits | Base position, read on reset or after offset preparation. |
| `+0x18` | 32 bits | Factor read twice during common arithmetic argument construction. |
| `+0x20` | 32 bits | Committed position destination. |
| `+0x24` | 32 bits | Operand read after the first common arithmetic call, then retained for a later multiplication. |
| `+0x50` | 32 bits | Low word of the stored quantity. |
| `+0x54` | 32 bits | High word of the stored quantity. |
| `+0x5D` | 8 bits | Mode selector, potentially read twice. |
| `+0x600` | 32 bits | Factor read twice during fallback argument construction. |

This is a partial layout, not a declaration of the complete object. Access to `+0x600` is required only on fallback paths. Dependencies may access other storage.

### Return words

| Path | Low 32 bits | High 32 bits |
|---|---|---|
| Admission rejection | `3` | Uninitialized temporary word; no defined value established. |
| Admitted zero request | `0` | Uninitialized temporary word; not the copied base position. |
| Nonzero result from mode-specific preparation | `3` | Current temporary offset word, initialized to zero before the call and writable by that dependency. |
| Common completion | Low result word from F-be470d4919c3 | Current temporary position word after that call. |

The high word on common completion normally reflects the committed position, but that correspondence requires that subsequent activity not alter the temporary word. The supplied code does not establish pointer-retention restrictions for dependencies that receive its address.

Whether external callers consume the full 64-bit return or only its low word is **documented_only**.

## Behavior

### Admission

For a request with its high bit set, the signed interpretation is negative. The function rejects it without an explicit object-field read and without calling a dependency.

For every nonnegative request, the function reads the bound at `+0x08`. It admits the request only when the request is strictly less than the bound in signed 32-bit ordering.

The equality check excludes the upper boundary even though the subsequent relational check permits equality. Together they establish:

- A zero bound admits no request.
- A bound with its high bit set admits no nonnegative request.
- A positive bound admits zero and positive requests strictly below it.
- Negative requests are always rejected.

Rejection produces low return word `3`, with no explicit object writes. The temporary word supplying the high return word has not been initialized on this path.

### Admitted zero request

An admitted zero request bypasses mode selection and all dependencies.

After the admission-bound read, the explicit object accesses occur in this order:

1. Read the 32-bit base at `+0x0C`.
2. Write that value to `+0x20`.
3. Write zero to `+0x50`.
4. Write zero to `+0x54`.

The low return word is zero. The high return word remains uninitialized.

This path does not read either factor, read `+0x24`, or invoke final processing.

### Positive-request temporary state and mode selection

For an admitted positive request, the function initializes temporary storage containing:

- A 32-bit offset word set to zero.
- A 32-bit word containing the supplied object address.
- A writable 32-bit request word set to the original request.

The supplied representation places these words consecutively, with the object-address word between the other two. This establishes their placement in that representation, not a public structure contract or permission to access beyond an individual argument.

Mode selection proceeds as follows:

1. Read the byte at `+0x5D`.
2. If that read is zero, call F-cded3bb79772.
3. Otherwise, read `+0x5D` again.
4. If the second read is one, call F-06ae3f4eacd9.
5. Otherwise, use fallback preparation.

Each mode-specific dependency receives the object address, the address of the temporary offset word, and the address of the writable request word.

With stable memory, mode zero selects F-cded3bb79772, mode one selects F-06ae3f4eacd9, and all other modes select fallback. With differing reads, selection follows the actual observations: a nonzero first read followed by zero selects fallback, not the mode-zero dependency.

A zero dependency result permits common completion. Any nonzero result maps to low return word `3`, regardless of its particular value. There are no subsequent explicit object writes by this function on that failure path. The temporary offset supplies the high return word, including any change made by the dependency.

### Fallback preparation

Fallback uses the original admitted positive request and performs two separate 32-bit reads of `+0x600`.

For the first read, interpret the factor as unsigned and multiply it by the unsigned request, producing a 64-bit product. That product supplies the low argument word and the initial high argument word.

The second factor read participates in a high-word correction. The correction multiplier is the request’s signed arithmetic right shift by 31 bits: zero for a nonnegative request and all-one bits for a negative request.

Fallback is reached only with the original admitted positive request, so this multiplier is zero. Consequently:

- Both factor accesses appear in the supplied representation.
- The second factor value contributes zero to the constructed high argument word, even if it differs from the first.
- The first factor read determines the product.

The function calls F-1e0edc6e0bc9 with:

1. The product’s low word.
2. The corrected high word, which here equals the product’s high word.
3. The admission bound saved from `+0x08`.
4. Zero.

The low 32 bits of the dependency’s result replace the temporary offset word. Higher result bits are discarded for this purpose. There is no result-status check.

The function itself does not modify the writable request word on fallback. This does not establish that dependency side effects or interfering activity cannot affect accessible state.

### Common completion: position

After successful mode-specific preparation or fallback, the function:

1. Reads the base at `+0x0C`.
2. Adds it to the current temporary offset.
3. Retains the resulting 32-bit word in that temporary.
4. Writes the word to `+0x20`.

At the fixed-width data-flow level, the addition retains the low 32 bits. No overflow check is present.

The base read occurs after preparation. Any dependency change to that field before this read affects the committed position.

### Common completion: first arithmetic argument pair

The function next constructs a two-word arithmetic operand using the current writable request and two separate reads of `+0x18`.

Let:

- \(R\) be the unsigned interpretation of the current 32-bit request word.
- \(A\) be the first unsigned factor read from `+0x18`.
- \(B\) be the second unsigned factor read from `+0x18`.
- \(P = R \times A\), computed as a 64-bit unsigned product.

The low argument word is the low word of \(P\). The high argument word is:

- The high word of \(P\), if the request’s high bit is clear.
- The high word of \(P\) minus \(B\), retained modulo \(2^{32}\), if its high bit is set.

The first factor read constructs the product; the second is used for the high-word correction. They must not be treated as one established snapshot.

If both reads yield the same factor, the pair is equivalent to multiplying the signed interpretation of the request by that unsigned factor and retaining 64 bits. If the request is nonnegative, the second factor does not affect the pair, even when the reads differ.

If the request’s high bit is set and the reads differ, signed multiplication by one factor is not a valid general description. The pair instead represents:

\[
R \times A - B \times 2^{32} \pmod {2^{64}}.
\]

A mode-specific dependency can introduce this negative-request case by modifying the writable request word. The function does not repeat admission checks afterward.

The resulting low and high words are passed to F-1e0edc6e0bc9, followed by `1000` and zero.

### Common completion: second arithmetic call and stored quantity

After the preceding arithmetic call returns, the function reads the unsigned word at `+0x24`.

It calls F-1e0edc6e0bc9 again with:

1. The preceding result’s low word.
2. The preceding result’s high word.
3. The newly read `+0x24` word.
4. Zero.

No local guard excludes a zero operand.

The function retains the `+0x24` value read before this call. It multiplies the returned 64-bit result by that retained unsigned value, keeping the low 64 bits, and writes:

1. The product’s low word to `+0x50`.
2. The product’s high word to `+0x54`.

The high-word calculation includes both the carry from multiplying the returned low word and the contribution from the returned high word. It is not merely a 32-bit product widened after truncation.

A dependency change to `+0x24` during the second call does not, by itself, change the retained multiplier.

### Final processing

After all three destination writes, the function calls F-be470d4919c3 with the object address and `1`.

Its low result word becomes the function’s low return word. The temporary position word supplies the high return word after the call.

There is no explicit rollback based on the final result. Conversely, the destination values immediately before final processing are not guaranteed to remain in the object afterward: final processing has no supplied mutation contract.

## Side effects

The function’s explicit object writes are confined to `+0x20`, `+0x50`, and `+0x54` on reset or common completion.

Admission rejection has no explicit object writes. Preparation failure has no subsequent explicit object writes by this function, but preparation may already have changed the object or temporary storage.

The function contains no explicit allocation, release, ownership transfer, or reference-count operation. No equivalent restriction is established for any dependency. In particular, dependencies are not assumed to preserve globals, retain object validity, or refrain from releasing memory.

Temporary addresses are passed to mode-specific dependencies. Retention and asynchronous use are unspecified. These temporaries do not provide an established lifetime beyond the invocation.

The destination updates are separate writes, not an established atomic transaction. Position is written before quantity; the low quantity word is written before the high word. Concurrency safety, visibility guarantees, and synchronization requirements are unknown.

## Acceptance examples

These are conditional static expectations, not runtime-tested results.

1. **Negative request.** For request `0xFFFFFFFF`, expect low return word `3`, no explicit object access, and no dependency call. Do not assert the high return word.

2. **Upper boundary.** With bound `7` and request `7`, expect a bound read followed by rejection. No mode read or destination write occurs.

3. **Zero bound.** Bound zero and request zero cause rejection, not reset.

4. **Eligible reset.** With bound `7`, request zero, and base word \(B\), expect writes of \(B\), zero, and zero to `+0x20`, `+0x50`, and `+0x54`, respectively, in that order. Expect low return word zero, no dependency call, and no defined high return word.

5. **Signed bound.** Bound `0x80000000` and request `1` cause rejection because the bound is negative in the signed comparison.

6. **Preparation failure.** With bound `10`, request `4`, and a first mode read of zero, suppose F-cded3bb79772 writes offset `12` and returns nonzero. Expect low return word `3`, high word `12`, and no common-completion writes by this function.

7. **Changed factor reads.** Suppose successful preparation changes the request word to `0xFFFFFFFF`. If the subsequent `+0x18` reads yield `2` and then `3`, the first common arithmetic call receives low word `0xFFFFFFFE` and high word `0xFFFFFFFE`, followed by `1000` and zero. It does not receive the signed product of negative one and two.

8. **Conditional numeric fallback.** Suppose all three arithmetic calls perform unsigned integer division on their two-word operands. Also suppose there is no interfering mutation; those calls preserve the object fields and temporary state relevant to subsequent execution; and the supplied storage remains valid. With stable fallback mode, bound `10`, request `4`, both `+0x600` reads equal to `100`, base `1000`, both `+0x18` reads equal to `1000`, and `+0x24` equal to `3`, expect:
   - Fallback offset `40`.
   - A write of `1040` to `+0x20`.
   - First common arithmetic result `4`.
   - Second common arithmetic result `1`.
   - Writes of `3` and zero to `+0x50` and `+0x54`.

   These destination values describe the state written before F-be470d4919c3. They describe the state after that call only if it also preserves those fields and no interference occurs.

9. **Final result without rollback.** If final processing returns low word `9`, that word is propagated after the destination writes. Its possible interpretation as failure does not trigger explicit rollback. Its own mutations remain unconstrained.

## Uncertainties

The following remain **documented_only**:

- The external meaning of the complete return, especially its uninitialized high word on early paths.
- Status meanings, field units, and complete object invariants.
- Arithmetic dependency semantics and exceptional cases.
- Dependency mutation, ownership, pointer retention, and lifetime contracts.
- External byte order for interpreting the split quantity.
- Original-language guarantees concerning signed overflow and representation artifacts.
- Whether differing mode or factor reads can occur in supported use.
- Concurrent-access validity and memory-order guarantees.

Separate factor accesses are established in the supplied representation. Their significance in a particular execution is not. Equal-read assumptions are required for the general signed-product interpretation when the writable request is negative.
