# F-2e174d695555

## Purpose

F-2e174d695555 describes a sequence of indirect dependency calls interleaved with byte and 32-bit memory accesses. It propagates selected dependency results, stores an explicit input twice, performs selector-directed byte updates, and repeatedly clears memory. The supplied representation ends at a bad-instruction termination marker rather than a normal return.

No application-level purpose is established. Initialization, record linking, device control, and state reset are possible interpretations, not contractual meanings.

This contract describes the supplied static representation conditionally: an operation occurs only if execution reaches it and preceding operations permit continuation. Warnings about bad instruction data and overlapping global symbols prevent treating the representation as independently validated executable behavior.

## Interface

### Explicit and implicit inputs

The displayed interface has two opaque 32-bit explicit inputs:

- **First input:** no direct consumption is visible.
- **Payload:** written unchanged to two 32-bit destinations.

The first input is not proven irrelevant to dependencies. An unresolved calling convention may expose incoming machine state beyond the displayed arguments.

Four additional incoming values are used without visible initialization:

- An unsigned 32-bit **initial argument**, shifted right by three for the first call.
- An unsigned 32-bit **bit source**, supplying the first byte written.
- An **initial selector base**, used for a byte read at displacement one.
- A **target seed**, used to derive the first indirect call target.

Memory contents, dependency results, and a later secondary machine-register output are further inputs to execution.

### Result and termination

No normal return or return value is visible. After the last dependency sequence, the representation reaches a bad-instruction termination marker. Whether this corresponds to an exception, emulator stop, process termination, or an incomplete representation is unknown.

There is no visible error status, recovery branch, rollback, or cleanup path.

### Widths and address notation

This contract uses the following address expressions:

| Name | Address |
|---|---:|
| Word slot indexed by \(x\) | \(4x+0x14\) |
| Record slot indexed by \(x\) | \(16x+0x14\) |
| Clear slot indexed by \(x\) | \(4x+0x44\) |
| Byte-selected slot for \(b\) | \(b+0x11\) |

These expressions do not imply an enclosing allocation, object, or hidden base pointer.

A byte access transfers eight bits. A word access transfers 32 bits. Byte selectors are unsigned and range from 0 through 255; their selected destinations therefore range from 0x11 through 0x110. Byte stores retain the low eight bits of their values.

Unsigned arithmetic is 32-bit, with reduction modulo \(2^{32}\). Unsigned right shifts insert zeros. The consumed results **J**, **W**, and **Y**, defined below, are unsigned 32-bit values. Most other named scalar dependency results are represented as signed 32-bit values; one result is represented as 64 bits.

Signed multiplication, signed left shifts, and signed address additions require care. The representation does not establish portable behavior for signed overflow or negative signed left operands. Some unsigned products are subsequently retained in signed address holders, introducing a further unresolved interpretation when the unsigned result exceeds the signed range. Machine-width wrapping must not be assumed for every expression.

Endianness, alignment requirements, and address-space validity are unknown.

## Behavior

### Reading convention

A **five-call span** means five consecutive indirect dependency invocations:

- Its first call receives the stated arguments.
- Its remaining four calls have no explicit arguments shown.
- A named span result is the fifth call’s result.

An omitted explicit argument list does not establish that registers, stack contents, or other machine state are unavailable to a dependency. Intermediate call results have no visible direct consumer unless identified below.

All unresolved calls use the opaque dependency reference **F-U0001**. This is a documentation bucket, not an assertion of shared target identity.

The letters below identify retained values for this contract only. Operations within each phase follow the stated order.

### 1. Initial selector and payload placement

The first five-call span receives the initial argument shifted right by three. Its first target depends on the incoming target seed. Let its result be **A**.

The routine reads a byte at initial selector base + 1 and retains it as **selector**. It then writes a byte to the byte-selected slot for selector. The stored value is the low byte of bit source shifted right by 22: input bits 22–29 survive, while bits 30–31 do not.

A five-call span receives A shifted left by two; its result is not directly consumed. The payload is then stored in the word slot indexed by selector.

The next five-call span receives four arguments: selector three times, followed by selector shifted right by one. Its result is **B**. The payload is stored in the word slot indexed by B.

The two payload writes are separate effects with dependency calls between them. Their destinations may coincide.

### 2. Initial scaled-value propagation

The following ordered spans and writes establish the next retained values:

| Span’s first arguments | Result | Direct effect after the span |
|---|---|---|
| \(4B\) | **C** | Store \(4C\) in the record slot indexed by C. |
| \(4C\) | **D** | Store \(4C\), not \(4D\), in the word slot indexed by D. |
| \(4D\) | **E** | Retain \(4E\) as unsigned **scaled-E**, then store it in the record slot indexed by E. |

A separate call receives scaled-E. A following call with no explicit arguments supplies a 32-bit value to another five-call span. Let that span’s result be **F**. The word slot indexed by F receives:

\[
(\text{scaled-E}\mathbin{\&}0x3fffffff)\gg1.
\]

The mask precedes the shift; an unmasked right shift is not equivalent.

A five-call span receiving \(4F\) produces **G**. The record slot indexed by G receives \(4G\).

Only afterward, the routine reads an unsigned word from the word slot indexed by G. That word, shifted right by three, is the first argument of a five-call span producing **H**. The word slot indexed by H receives the retained value \(4G\).

The record-slot write and subsequent word-slot read use different address scaling. They are not generally accesses to the same location.

A five-call span receiving \(4H\) produces unsigned result **J**.

### 3. Selector state and derived byte updates

The retained selector is stored as a word at:

\[
(\text{selector}\gg3)\times0x80000+0x24.
\]

The index before multiplication ranges from 0 through 31.

Two further retained quantities are derived from J:

- **Record base:** the 32-bit product \(16J\), retained in a signed address holder.
- **Masked half:** the unsigned value \((J\mathbin{\&}0x3fffffff)\gg1\), at most 0x1fffffff.

A five-call span receives record base and J shifted left by two. Its result is not directly consumed. Selector is then stored as a word at record base + 0x24.

A word read at record base + 0x74 supplies the first argument of a five-call span producing **K**. After that span, a fresh byte read at record base + 1 selects a destination. The routine writes the low byte of:

\[
(J\mathbin{\&}0x3fffffff)\gg20.
\]

This byte can be zero. In particular, J equal to zero produces a zero byte.

A separate call receives K shifted left by two. The next no-explicit-argument call supplies a word to a five-call span producing **L**. The routine then rereads the byte at record base + 1 and clears its selected byte slot. This fresh read need not select the destination of the preceding byte write.

A five-call span receives L shifted left by two; its result is not directly consumed. Afterward:

- The byte at masked half + 0x0f is cleared.
- **Secondary base** is formed from masked half multiplied by 0x400 using unsigned 32-bit arithmetic, then retained in a signed address holder.
- A byte read at secondary base + 1 selects another byte slot to clear.

The unsigned multiplication can wrap. The later signed interpretation and address addition remain subject to the width qualifications above.

### 4. Retained selectors and repeated word clears

A dependency receives K shifted left by 23 three times, followed by K shifted left by 25. A no-explicit-argument call supplies a word to a five-call span producing **M**.

The routine freshly reads a byte at secondary base + 1, retains it as **saved selector**, and clears its selected byte slot.

A five-call span receives M shifted left by two. Its result is not directly consumed. After it finishes, the routine clears:

1. The word at saved selector + 0x44.
2. The word at absolute address 0x24.

The saved selector is not reread after that span. Its word destination uses the byte captured before the intervening calls, and uses no multiplication by four.

The next dependency chain contains, in order:

- A call receiving zero, 0x98, secondary base, and 0x98.
- A no-explicit-argument call supplying a word.
- A call receiving that word.
- Another no-explicit-argument call supplying a word.
- A five-call span receiving the latest word.

Let the final result be **N**. The routine clears the clear slot indexed by N, then clears the word at absolute address 0x24 again.

A five-call span receiving \(4N\) produces a 64-bit result. Its low and high 32-bit halves are retained separately. A dependency receives the low half interpreted as signed 32-bit and shifted left by two.

After that call, the routine clears the word at twice the saved high half, interpreted as signed 32-bit, plus 0x44. It then clears the word at absolute address 0x24 a third time.

A subsequent dependency receives zero, a secondary machine-register output associated with the preceding dependency, and that output shifted left by two. This output is not established to equal the saved high half.

After one no-explicit-argument call whose result is not directly consumed, a five-call span receives:

\[
(\text{masked half}\mathbin{\&}0x3fffff)\ll7.
\]

Let its result be **O**. The clear slot indexed by O is cleared, followed by a fourth explicit word clear at absolute address 0x24.

These four absolute-address resets remain separate observable writes even if they all store the same value.

### 5. Zero payloads and later propagation

A five-call span receiving \(4O\) produces **P**. A separate dependency receiving P shifted left by two produces **Q**. The word slot indexed by Q is cleared.

A five-call span then receives Q three times, followed by:

\[
(\text{masked half}\mathbin{\&}0x3fffff)\ll7.
\]

Its result is **R**, whose word slot is cleared.

The next spans and effects are:

| Span’s first argument | Result | Direct effect after the span |
|---|---|---|
| \(4R\) | **S** | Store \(4S\) in the record slot indexed by S. |
| \(4S\) | **T** | Store \(4S\) in the word slot indexed by T. |
| \(4T\) | **U** | Store \(4U\) in the record slot indexed by U. |

A separate dependency receives \(4U\) and \(16U\). A no-explicit-argument call then supplies a word to a five-call span whose first call receives that word and:

\[
(\text{masked half}\mathbin{\&}0x3fffff)\ll4.
\]

Let its result be **V**. The word slot indexed by V receives:

\[
(\text{masked half}\mathbin{\&}0x3fffff)\times0x80.
\]

This unsigned value is at most 0x1fffff80 and equals the masked left shift by seven used earlier.

### 6. Final selector-directed writes

A five-call span receiving \(4V\) produces unsigned result **W**.

**Final base** is formed by unsigned 32-bit multiplication of masked half by 0x4000000, then retained in a signed address holder. A byte read at final base + 1 selects a byte slot, which receives the low byte of W shifted left by two.

A dependency receives W shifted left by two. A no-explicit-argument call supplies a word to a five-call span producing **X**.

The routine rereads the byte at final base + 1. Its selected slot receives the low byte of:

\[
(W\mathbin{\&}0x3fffffff)\gg20.
\]

W remains the source for this write; X does not replace it.

A five-call span receiving X shifted left by two produces unsigned result **Y**. Another fresh byte read at final base + 1 is retained, and its selected byte slot receives the low byte of \(4Y\).

A dependency receives that retained selector, zero-extended to 32 bits. A no-explicit-argument call supplies a word to a five-call span producing **Z**.

The next selector comes from a byte read at \(8Y+1\), using unsigned 32-bit arithmetic. Its selected byte slot receives the low byte of:

\[
(Y\mathbin{\&}0x3fffffff)\gg20.
\]

A final five-call span receives Z shifted left by two. Its result is not directly consumed. The bad-instruction termination marker follows.

## Side effects

Direct effects comprise the ordered dependency calls, byte and word reads, and byte and word writes described above.

No direct allocation, release, ownership transfer, synchronization operation, or resource-management protocol is established. No such behavior may be inferred from an opaque call.

Dependencies are not known to preserve memory, globals, registers, or resource ownership. Consequently:

- Fresh selector reads remain distinct from retained selectors.
- Reads following calls cannot be replaced with earlier observations.
- Repeated clears cannot be collapsed across intervening dependencies.
- Byte slots, word slots, record slots, and absolute address 0x24 may alias.
- A direct write may itself affect a later selector read if their addresses overlap.

The word at saved selector + 0x44 can be unaligned. Neither alignment nor an ordinary-memory interpretation is guaranteed for any destination.

If execution stops during a dependency or memory operation, later effects are not required. No compensating actions are visible.

## Acceptance examples

These are conditional static expectations, not executed tests. Each assumes execution reaches the relevant operations and all required accesses and arithmetic are supported.

1. **Initial bit extraction.** With selector 0x25 and bit source 0xabc00000, the initial byte destination is 0x36 and the stored byte is 0xaf.

2. **Payload placement.** Selector 0x25 selects word address 0xa8. The stored 32-bit payload is unchanged.

3. **Mask before shifting.** Scaled-E equal to 0xc0000004 produces a stored masked value of 2, not 0x60000002.

4. **Different address scaling.** G equal to 2 selects record address 0x34 for the write and word address 0x1c for the subsequent read. The read need not retrieve the written value.

5. **Zero-valued byte update.** With J equal to zero and the post-K selector read yielding 3, the preceding byte write stores zero at 0x14. It is still a byte write; it is not guaranteed nonzero or omitted.

6. **Fresh selector before clearing.** If that first selector read yields 3 and the later read yields 9, the byte write targets 0x14 while the clear targets 0x1a. Dependency changes or aliasing may explain the difference.

7. **Saved selector across calls.** A saved selector of 7 selects word address 0x4b after the intervening span, regardless of subsequent changes to secondary base + 1.

8. **Unsigned product wrap.** With masked half equal to 64, final base’s unsigned product is zero. Its selector address is therefore 1.

9. **Intermediate byte values remain observable.** If the first three final-phase reads select the same slot, it receives the low byte of \(4W\), then the extracted byte from W, then the low byte of \(4Y\). Dependencies between those writes may observe intermediate states.

10. **Partial execution.** If a dependency never returns, subsequent writes and the final termination marker are not required to occur.
