## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Initial input forwarding.** If the first three indirect calls return normally, the first receives the original 32-bit input, the second receives the first result, and the third receives the second result. Replacing this chain with direct forwarding of the original input does not preserve the represented dataflow.

2. **Eighteen-bit mask boundary.** If the first relevant low half is `0x0003FFFF`, its masked-and-shifted argument is `0x003FFFF0`. If it is `0x00040000`, that argument is zero.

3. **Truncating shift composition.** Under 32-bit shift semantics, shifting the retained eleven-bit-shifted value left by thirty-one bits produces zero for every original input.

4. **Signed recovery is not identity.** Under arithmetic-right-shift semantics, an original value of `0x04000000`, shifted left by five and then right by five, produces `0xFC000000`, not the original value.

5. **Low-bit-derived zeros.** The four-bit-shifted retained value always has its bottom four bits clear. Masking it with three produces zero regardless of the dependency’s return value.

6. **Final address boundaries.** If the final transformed result’s top twelve bits are zero, the attempted halfword destination is address zero. If they are 4095, the destination is 5118.

7. **Potential misalignment.** If those top twelve bits equal one, the attempted destination is address one. The evidence provides no alignment correction or alternate path.

8. **Conditional reachability.** If an earlier dependency does not return, later coprocessor operations and the final store are not established to occur.
