# F-b34c238242d2

## Purpose

F-b34c238242d2 performs staged initialization of a mutable record. It writes an initial marker, resolves two optional services, invokes two setup dependencies, and conditionally publishes names, flags, bounds, and metrics.

**Established behavior:** full metadata publication requires both setup dependencies to return zero and the signed selector to equal zero. A negative selector returns zero after successful setup without this publication. A positive selector is rejected only after successful setup.

**Inferred intent:** the service identifiers, name processing, and metric fields suggest initialization of a font-face record. This interpretation does not establish an external structure definition or any dependency’s behavior.

Initialization is not transactional. Earlier writes and dependency effects are not undone on failure.

## Behavior

### 1. Initial marker and service caches

The first direct record write stores `1` at `0x00`.

The function then reads `0x88`. If it is zero, it:

1. Reads the pointer at `0x60` and the 32-bit lookup context at offset `4` in that pointed-to object.
2. Calls F-36f29e709002 with that context and the service identifier `"psaux"`.
3. Stores the returned 32-bit value at `0x88`, including a zero result.

Next, it reads `0x140`. If that value is zero, it independently obtains the context through the then-current pointer at `0x60`, calls F-36f29e709002 with `"pshinter"`, and stores the result at `0x140`.

A nonzero cache suppresses its corresponding lookup and direct cache assignment. A zero lookup result is not an immediate error.

The second cache read and context lookup occur after any first lookup call. Neither cache contents nor the nested context may be assumed preserved by that dependency.

### 2. Setup and selector handling

F-e40a3ceddab2 receives the first argument and zero. A nonzero result ends execution with that result.

On zero, F-5d8371a1f72d receives the record pointer and original signed selector. A nonzero result ends execution with that result.

Only after both return zero is the selector classified:

- **Negative:** return zero without full metadata publication.
- **Zero:** perform the remaining publication steps, then return zero.
- **Positive:** call F-4457a9a44a68 with an invalid-face-index diagnostic, then return `6`.

Thus setup errors take precedence over positive-selector rejection. Negative-selector success does not imply that either setup dependency was skipped or side-effect-free.

### 3. Initial metadata and names

Full publication starts with this ordering:

1. Read `0x128` and write its 32-bit value to `0x10`.
2. Read the first unknown 32-bit global and capture its value.
3. Write zero to `0x24`.
4. Write zero to `0x04`.
5. Write the captured global value to `0x08`.
6. Read the byte at `0xBC`.
7. If that byte is nonzero, read the second unknown global and overwrite `0x08` with its value.

The first global read precedes both clearing writes. The value written at step 5 is the captured value, not a fresh global read. Preservation of that global across the intervening record writes is not assumed.

The function next reads the primary family pointer at `0xB0`, publishes it at `0x14`, and sets `0x18` to the static `"Regular"` string.

If the captured primary family pointer is null, the fallback at `0x8C` is tested. A nonzero fallback is read for assignment to `0x14`. This branch does not attempt full-name matching, even when a full name exists.

If the captured primary family pointer is nonnull, the function reads `0xAC`. A nonnull full-name pointer permits suffix matching.

#### Suffix matching

Matching is byte-oriented and case-sensitive. Only ASCII space and hyphen have special handling.

The full-name byte is examined first. A zero byte ends matching without selecting a style suffix. Otherwise:

- Equal full-name and family-name bytes advance both positions.
- On unequal bytes, a space or hyphen in the full name advances only the full-name position.
- Otherwise, a space or hyphen in the family name advances only the family position, and the same full-name position is retried.
- Otherwise, the family position is checked again for its terminator. A zero at this check causes the current full-name position to be published at `0x18`; a nonzero byte leaves `"Regular"` unchanged. Matching then stops.

Under stable string contents, this accepts a family prefix while ignoring intervening spaces and hyphens. It then selects the first nonseparator suffix after that prefix.

An exact match leaves `"Regular"`. So does a full name containing only spaces or hyphens after the matched family. An ordinary mismatch before the family terminator also leaves `"Regular"`.

A selected suffix is not copied or normalized. Its remaining bytes, including trailing separators, remain part of the published string.

### 4. Flags

The function clears `0x0C`, reads the 32-bit value at `0xB8`, and writes `1` to `0x0C` if that input is nonzero.

If the weight pointer at `0xB4` is nonzero, an unmapped comparison dependency is called with the weight pointer and an unknown static token.

- A zero result qualifies for setting bit value `2`.
- A nonzero result triggers a second comparison, using a newly read weight pointer from `0xB4` and `"Black"`.
- A zero second result also qualifies for setting bit value `2`.
- A nonzero second result causes no additional direct flag write.

When qualified, the function reads the then-current `0x0C`, ORs it with `2`, and writes it back. It does not necessarily OR against the value established before the comparison calls.

The first successful comparison suppresses the second. The second call does not repeat the original nonnull guard. A dependency that changes `0xB4` can therefore change the pointer passed to the second call, including making it null.

### 5. Bounds, independent captures, and metrics

The function clears `0x1C`, then `0x20`.

The following reads, writes, and captures occur in order:

1. Read `0xC4` as a signed 32-bit value, arithmetically shift right by 16, and write the result to `0x34`.
2. Independently read `0xC8` as signed 32-bit, arithmetically shift right by 16, and write the result to `0x38`.
3. Read `0xC8` again. Capture its upper 16 bits, interpreted as signed 16-bit, for the later metric at `0x48`.
4. Read `0xCC`, add `65535` using 32-bit modular arithmetic, logically shift right by 16, and write the result to `0x3C`.
5. Read `0xD0`, perform the same modular addition and logical shift, and write the result to `0x40`.
6. Read `0xD0` again. Repeat the modular addition and logical shift, then narrow the result to signed 16-bit for the later metric at `0x46`.

The capture from `0xC8` occurs **after writing `0x38` but before writing `0x3C` and `0x40`**. The capture from `0xD0` occurs **after writing `0x40`**, using a separate source read and calculation. It neither reads `0x40` nor reuses the earlier calculated output.

Consequently, equality between a published bound and its corresponding captured metric requires stable relevant source values across those distinct reads.

The signed right shifts preserve the sign. The modular additions and logical shifts for `0xCC` and `0xD0` must not be replaced by unbounded arithmetic or signed ceiling division. Overflow wraps before shifting.

The function next tests the 16-bit field at `0x44`. If its bits are zero, it writes `1000`; otherwise it leaves the field unchanged.

It then writes:

1. The captured metric derived from the second `0xD0` read to `0x46`.
2. The captured metric derived from the second `0xC8` read to `0x48`.

F-d7be9cfb4000 is called with the unsigned 16-bit value then read at `0x44`, multiplied by `12`, and a second argument of `10`. The product ranges from zero through `786420` and fits in 32 bits.

The helper result is narrowed to signed 16-bit. Separately, the captured metric destined for `0x46` minus the captured metric destined for `0x48` is calculated as signed 32-bit arithmetic. Its range is `-65535` through `65535`. These are the captured values, not fresh reads of the published metric fields.

The narrowed helper result is written to `0x4A`. If it is less than that signed 32-bit difference, the difference is narrowed to 16 bits and overwrites `0x4A`.

This is a signed comparison followed by potentially wrapping storage, not an unrestricted mathematical maximum.

Finally, the function reads 16 bits at `0xBE` and writes them to `0x50`, then reads 16 bits at `0xC0` and writes them to `0x52`. Both source reads occur after the metric helper returns.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless specified otherwise, storage is valid, relevant values remain stable, dependencies return normally, and full-publication examples have selector zero with both setup results zero.

1. **Cached services:** If both service caches are nonzero when checked, neither lookup occurs. The initial marker is nevertheless written before setup.

2. **Unresolved lookup:** If the auxiliary lookup returns zero, zero is stored at `0x88`; processing continues to the hinter cache and setup.

3. **Error precedence:** If the selector is positive but F-e40a3ceddab2 returns `9`, the result is `9`. Neither the second setup call nor the invalid-index diagnostic occurs.

4. **Second setup failure:** If the first setup succeeds and F-5d8371a1f72d returns `11`, the result is `11`, regardless of selector sign.

5. **Negative selector:** Selector `-1` with successful setup returns zero without this function’s full metadata publication.

6. **Positive selector:** Selector `1` with successful setup invokes the diagnostic dependency and returns `6`.

7. **Captured global ordering:** If the first global read yields `V`, the subsequent zero writes to `0x24` and `0x04` precede storing `V` at `0x08`. Even if those writes affect that global through storage aliasing, the initial store to `0x08` uses the earlier captured `V`. A nonzero `0xBC` can subsequently replace it.

8. **Fallback family:** A null primary family and nonnull fallback publish the fallback family pointer and leave style as `"Regular"`; no full-name matching occurs.

9. **Suffix extraction:** Family `"Example Sans"` and full name `"Example-Sans Bold"` select the existing `"Bold"` suffix. Family `"Example"` and full name `"Exemplar Bold"` leave `"Regular"`.

10. **Independent metric reads:** The read supplying the captured `0x48` metric follows the `0x38` write and precedes both later bound writes. The read supplying the captured `0x46` metric follows the `0x40` write. Acceptance must not substitute reads of the output fields for either capture.

11. **Unsigned wrap:** A stable source of `0xFFFFFFFF` at `0xCC` produces zero at `0x3C`: the modular sum is `65534`, whose logical right shift by 16 is zero.

12. **Scale default:** A zero scale becomes `1000`, and the helper receives `12000` and `10`.

13. **Metric placement and narrowing:** With stable `0xC8 = 0x80000000` and `0xD0 = 0x7FFF0000`, `0x48` receives signed `-32768` and `0x46` receives signed `32767`. Their difference is `65535`, greater than every signed 16-bit helper result. The final height bits are therefore `0xFFFF`, interpreted as signed 16-bit `-1`.
