# F-e3037e3e9815

## Purpose

F-e3037e3e9815 selects between a bulk operation followed by ordered reset writes and an iterative sequence of cursor-based operations. It publishes values through caller-provided storage and returns a 64-bit value composed of two 32-bit words.

**Established static behavior:**

- Publish a context-derived anchor before calling any dependency.
- Select the bulk path only when two successive probe results and a subsequently read context field are all nonzero.
- Otherwise, compare the cursor location with the boundary token until the comparison returns exactly 1.
- For each entered iteration, capture the cursor word, invoke a cursor operation, invoke a per-element operation, and publish an address-exposed scratch word.
- Construct the return value from path-dependent upper and lower 32-bit components.

**Inferred intent:** The anchor-relative fields, self-reference writes, and alternative processing paths resemble an anchored-container operation with a bulk reset optimization. The supplied body does not establish a public container model, element-destruction contract, or ownership protocol.

Dependency IDs identify call-site roles only. They do not establish equality, cursor advancement, destruction, or deallocation semantics.

### Temporary storage and return value

Two addressable 32-bit scratch words supply the iterative return components:

- The **upper scratch** initially contains the context address.
- The **lower scratch** initially contains the output-location address.

Both addresses are passed to the per-element dependency. Their contents may therefore change through that call and, if retained and shared, through later dependency calls while the storage remains live.

The return value is the unsigned bit-pattern composition:

**upper component × 2³² + lower component**.

This composition has a 64-bit result; it is not a 32-bit multiplication or addition. No sign extension of either component is established.

On the iterative path, the components are the scratch contents after the terminating comparison returns. On the bulk path, the upper component is the anchor captured immediately before the final output publication, and the lower component is the output-address-initialized lower scratch.

The return is not established to represent a status, pointer, or public aggregate. Output-memory contents and return components are separate observables.

## Behavior

### Initial publication

The function reads context +16 and writes that anchor word to the output location before invoking any dependency.

It then reads context +16 again and reads the word at +8 of that newly selected anchor. That word becomes an addressable temporary snapshot for the first probe.

The second anchor read occurs after the initial output write. Consequently, output aliasing can affect the anchor selected for the snapshot or the snapshot’s source field. The initially published anchor is not a guaranteed invocation-wide anchor.

Both return-component scratch words are initialized before the first dependency call.

### First probe

F-356e3995b10d receives:

1. The original cursor location.
2. The address of the temporary snapshot obtained from anchor +8.

Its 32-bit result uses a zero/nonzero predicate:

- Zero skips the second probe and proceeds to the iterative path.
- Any nonzero result permits the second probe.

The second argument addresses temporary storage, not the anchor’s +8 field. A write through that argument changes the snapshot, not inherently the original field.

The call may affect other state. Nothing supplied guarantees preservation of context +16, context +20, cursor storage, anchor storage, or globals.

### Second probe and eligibility read

If the first result is nonzero, the function rereads context +16 into another addressable temporary snapshot.

F-356e3995b10d then receives:

1. The original boundary token.
2. The address of that anchor snapshot.

Only when the second result is nonzero does the function read context +20 for the bulk decision. A zero second result skips that eligibility read.

The bulk path is selected exactly when:

- The first result is nonzero.
- The second result is nonzero.
- The context +20 word read after both calls is nonzero.

The value before either probe does not establish the eligibility value afterward. For example, a probe may clear context +20 while returning nonzero.

Neither probe result must equal 1 to select the bulk path. No count, range-length, or specific nonzero eligibility value is checked.

If bulk selection fails, the iterative path performs a fresh comparison. Neither probe result substitutes for that loop-head comparison.

### Bulk operation

After bulk selection, the function reads context +16 and obtains the word at +4 of that anchor.

It invokes F-368b8853b2e9 with:

1. The original context address.
2. The obtained anchor +4 word.

The dependency’s direct return value is unused. Its argument reflects the anchor selected for this pre-call read, not necessarily the initially published anchor or either probe snapshot.

### Ordered bulk reset

After the bulk dependency returns normally, these stores occur in order:

| Order | Direct write |
|---:|---|
| 1 | Store an anchor word read from context +16 into +8 of an anchor selected through context +16. |
| 2 | Store zero into +4 of an anchor selected through context +16. |
| 3 | Store an anchor word read from context +16 into +12 of an anchor selected through context +16. |
| 4 | Store zero into context +20. |

The function does not cache one anchor for the whole reset. The self-reference stores each require context +16 reads for destination selection and stored value. Their relative evaluation order within an individual store is not established by the supplied representation; the order between the listed stores is established.

If the bulk dependency changes context +16, subsequent reset accesses use post-call reads. Aliasing can also make one reset write affect later anchor selection.

After the four stores, the function reads context +16 again, captures that word, and writes it to the output location. The captured word becomes the upper return component. The lower return component remains the lower scratch initialized to the output-location address.

There are no loop comparisons or iterative operations on this path.

The reset is an ordered access trace, not an unconditional final-state guarantee. In particular, the final publication may overwrite context +20 if the output location aliases that field.

### Iterative loop

At every loop head, F-356e3995b10d receives the original cursor location and boundary token.

The loop terminates only when the 32-bit result is **exactly 1**. Every other bit pattern enters the body, including zero, 2, and the all-ones pattern.

Each entered iteration performs the following ordered actions:

1. Read and capture the current 32-bit word at the cursor location.
2. Invoke F-59fbf5893c3b with the original cursor location.
3. Replace the lower scratch with the captured word.
4. Invoke F-e72900ff36e8 with the upper-scratch address, original context address, and lower-scratch address.
5. Copy the current upper scratch to the output location.
6. Return to the loop-head comparison.

The lower scratch supplied to the per-element call therefore contains the cursor word captured **before** the cursor-operation call. It is not obtained by rereading the cursor afterward.

The upper scratch is not reinitialized between iterations. The lower scratch is replaced on each entered iteration, after the cursor-operation call and before the per-element call.

The direct return values of both body dependencies are unused.

### Scratch exposure and termination

F-e72900ff36e8 receives both return-component scratch addresses. No supplied dependency contract prevents it from retaining and sharing those addresses for use during later calls in this invocation.

Consequently:

- A subsequent comparison or cursor-operation call may alter exposed scratch storage through shared dependency state.
- A terminating result of 1 establishes control-flow termination, not preservation of either scratch word.
- The iterative return uses both scratch words after the terminating comparison returns.
- The upper return component may differ from the last value published to the output location.
- The lower return component need not equal the last captured cursor word or the value left by the last per-element call.

There is no output publication after the terminating comparison.

If no iteration is entered, neither return-component scratch address has been passed to a dependency by this invocation. The represented return components remain the initialized context address and output-location address. The initial anchor publication still occurred.

## Acceptance examples

These are conditional static examples, not executed tests. Each requires valid reached accesses, normally returning dependencies, and no external interference beyond the stated effects.

### Immediate iterative termination

Suppose the first probe returns zero and the first loop comparison returns exactly 1.

The initial anchor is published. No second probe, bulk operation, cursor operation, or per-element operation occurs. The return components are the context address and output-location address, respectively.

### Non-1 loop result

Suppose bulk selection fails and a loop comparison returns 2.

The body executes. The cursor word is captured before F-59fbf5893c3b and installed in the lower scratch after that call. F-e72900ff36e8 receives its address. Treating 2 as a terminating truth value would violate the represented behavior.

### Bulk reset with independent storage

Suppose both probes return nonzero and the subsequent eligibility read is nonzero. Let A be the anchor read for the bulk-operation argument. Suppose further that:

- The bulk dependency preserves context +16 as A.
- Context fields, A’s accessed fields, and output storage are nonoverlapping.
- No further modification changes context +16 during reset.

The reset leaves A +8 and A +12 containing A, A +4 containing zero, and context +20 containing zero. The final output publication contains A. The return components are A and the output-location address.

The initial publication need not have contained A: either probe could previously have changed the anchor.

### Output aliasing eligibility: bulk selection established

Suppose:

- The output location is exactly context +20.
- Context +16 initially contains a nonzero anchor A.
- A’s accessed fields do not overlap the context fields.
- Both probes return nonzero and preserve context +16 and context +20.
- The bulk dependency preserves context +16 as A.

The initial publication writes A into context +20. Because both probes preserve that field, the eligibility read after the probes observes nonzero A and selects the bulk path.

Reset writes zero to context +20. The final publication then writes A to that same location. Thus context +20 is nonzero at return despite having been cleared during reset. The upper return component is A.

Preservation by the bulk dependency alone would not establish these conclusions; the probes precede both eligibility selection and bulk execution.

### Output aliasing eligibility: probe defeats selection

Use the same output alias and initial nonzero anchor A. Suppose the first probe clears context +20 while returning nonzero, and the second probe returns nonzero without restoring that field.

The eligibility read observes zero. The iterative path is selected, despite both probe results being nonzero and the initial publication having written A into eligibility storage.

No bulk operation or reset follows from those assumptions. Subsequent iterative behavior depends on fresh loop-comparison results.

### Anchor replacement during the bulk operation

Suppose bulk selection is established. F-368b8853b2e9 replaces context +16 with a different valid anchor B. Assume independent storage and no subsequent anchor changes.

The dependency’s second argument came from the pre-call anchor’s +4 field. Reset writes target B. The final output publication and upper return component contain B.

### Publication differing from return

Suppose one iteration occurs. F-e72900ff36e8 writes A and B into the upper and lower scratch words and retains both addresses.

The following publication writes A. Suppose the next comparison uses those retained addresses to write C and D, then returns 1.

No further output publication occurs. The return components are C and D, not necessarily A and B.
