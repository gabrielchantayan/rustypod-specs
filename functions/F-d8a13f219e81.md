# F-d8a13f219e81

## Purpose

F-d8a13f219e81 conditionally converts a caller-supplied mutable record between two representations. Bit 0x200 of a 32-bit flag word identifies the current representation. A separate 32-bit selector determines which representation is requested.

The established behavior comprises:

- Transforming a 64-byte payload using bytewise affine arithmetic.
- Calling one of two opaque dependencies.
- Multiplying five numeric metadata words by global values.
- Updating the representation bit only after a dependency returns zero.
- Destructively overwriting the record payload before one dependency call, without rollback on failure.
- Overwriting a local 64-byte buffer before every normal return.

“Export” denotes the clear-flag, nonzero-selector conversion; “import” denotes the set-flag, zero-selector conversion. These are descriptive labels, not established meanings of the underlying data. Neither the transformations nor the overwrites establish encryption, secure erasure, or resource destruction.

## Behavior

### Selection and success classification

For flag memory that remains stable during selection:

| Representation bit | Selector | Selected action |
|---|---|---|
| Clear | Zero | No conversion. |
| Clear | Nonzero | Export through F-56719562bce6. |
| Set | Zero | Import through F-17ddceb1746d. |
| Set | Nonzero | No conversion. |

Selection does not use a single explicit flag snapshot. The function first reads the flag to determine whether import is selected. If it does not take that branch, it reads the flag again when deciding whether to export. The table therefore assumes agreement between relevant reads. No synchronization or concurrent-mutation semantics are established.

Each dependency result is treated as an unsigned 32-bit value. Exactly zero permits the corresponding success sequence. Every nonzero value, including 1 and 0xFFFFFFFF, prevents that sequence. The function does not expose the result to its caller.

Every normally returning path ends with the local-buffer overwrite described below. Faults, interruptions, and dependencies that do not return are not covered by that normal-return guarantee.

### Export: clear flag and nonzero selector

#### Payload preparation

The function reads all 64 record payload positions and places transformed bytes in the local payload buffer. For an input byte represented by the integer \(x\), the stored output is:

\[
(-75x + 36) \bmod 256.
\]

Interpreting the source byte as signed or unsigned does not change the resulting low eight bits.

Traversal depends on the address comparison:

- If the record address is at or below the local-buffer address, positions are processed from 63 down to 0.
- Otherwise, positions are processed from 0 up to 63.

At each position, the source byte is read before the corresponding destination byte is written. This direction choice is established; an overlap-management purpose is inferred.

#### Destructive record overwrite

After payload preparation, and before collecting record metadata or calling F-56719562bce6, the function overwrites record payload positions 63 down to 0.

Let \(A\) be the numeric address of the local overwrite counter. For the \(j\)-th byte, where \(j\) ranges from 0 through 63, define:

\[
q_j = (A+j) \bmod 256.
\]

The byte stored at record offset \(63-j\) is:

\[
((q_j+17)(q_j \mathbin{\mathrm{XOR}} 186)) \bmod 256.
\]

The address sequence advances by one byte per output byte, not by the size of the counter. The pattern is address-dependent rather than a fixed fill.

At completion, the transformed payload is in local storage, while the original record payload has been overwritten. This occurs even if the subsequent dependency reports failure.

#### Metadata preparation and dependency call

The function reads the scalar word at offset 68 first, then the scalar word at offset 64.

It then prepares five local numeric words from record offsets 72, 76, 80, 84, and 88, in that order. Each is multiplied by the export global. The supplied static representation contains a separate export-global reference for each of these five products; it does not capture one shared multiplier.

The relative evaluation order of the global read and record-word read within an individual product is not established. The products use 32-bit signed operands in the supplied representation; out-of-range products require the qualification in **Uncertainties**.

F-56719562bce6 receives these arguments, in order:

1. Address of record offset 92.
2. Address of the local 64-byte transformed payload.
3. Scalar value read from offset 68.
4. Scalar value read from offset 64.
5. Address of the five local numeric words.

If the dependency returns zero, the function reads the then-current flag word, sets bit 0x200, and writes the resulting 32-bit word back to offset 100.

If the dependency returns nonzero, the function performs no flag write of its own. It does not restore the record payload or reverse any dependency effects.

### Import: set flag and zero selector

#### Dependency call

F-17ddceb1746d receives these arguments, in order:

1. The 32-bit value read from record offset 92.
2. Address of the local 64-byte payload buffer.
3. Address of the first scalar metadata slot, initially zero.
4. Address of the second scalar metadata slot, initially zero.
5. Address of the five local numeric slots.

The payload and numeric slots have not been initialized before this call. To support defined consumption on a zero result, the dependency must supply all 64 payload bytes and all five numeric values subsequently read. An untouched scalar slot retains its initial zero value.

A nonzero result skips all direct record installation described below. The function proceeds to its final local-buffer overwrite. Effects of the dependency itself remain unknown.

#### Successful payload installation

After a zero result, the function first clears record bytes 92, 93, 94, and 95, in that order. This is four byte writes, not evidence of releasing or destroying a resource.

It then transforms the local payload into the record. For a local input byte represented by \(y\), the stored record byte is:

\[
(-99y-20) \bmod 256.
\]

Exactly 64 payload positions are processed:

- From 63 down to 0 when the local-buffer address is at or below the record address.
- From 0 up to 63 otherwise.

Each input read precedes its corresponding output write.

The import and export byte transformations are algebraic inverses modulo 256 for corresponding unchanged bytes. That relationship does not establish what either dependency does to payload contents.

#### Successful metadata installation and multiplier reads

After payload installation, the function writes the first scalar local word to record offset 68, then the second scalar local word to offset 64.

It next reads the import global **twice**, with distinct uses:

| Read | Use |
|---|---|
| First read | Saved for the products written to offsets 76, 80, 84, and 88. |
| Second read | Used for the product written to offset 72 only. |

The first read occurs after both scalar metadata writes. The second read occurs as part of preparing the product stored at offset 72, after the first read and before that store. The product stores then occur in increasing offset order: 72, 76, 80, 84, 88.

Consequently, the first numeric field uses the **second** observed import-global value; the remaining four fields use the **first** observed value. A claim that all five use the same multiplier requires the additional assumption that the two reads agree.

Both reads occur after F-17ddceb1746d returns. No preservation of the import global across the call is assumed. The exact evaluation order between the second global read and the first local numeric read within their product is not established.

Finally, the function reads the current flag word, clears bit 0x200, and writes the resulting word to offset 100. Unrelated flag bits are preserved relative to this late read, not necessarily relative to branch selection.

### Final local-buffer overwrite

Every normal path overwrites all 64 bytes of the local payload buffer, including paths with no conversion and paths with a nonzero dependency result.

The overwrite uses the same address-derived byte formula described for the export record overwrite. Its address sequence restarts at the local counter, and destination positions run from 63 down to 0.

This operation does not restore record data, overwrite the scalar or numeric metadata slots, or establish removal of any copies retained elsewhere.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **No conversion requested from a clear flag.**  
   With stable flag memory, bit 0x200 clear, and selector zero, neither dependency is called. The function makes no direct record writes. The final local-buffer overwrite still occurs.

2. **Nonzero selectors are equivalent.**  
   With stable flag memory and bit 0x200 set, selectors −1 and 1 both select no conversion. Neither magnitude nor sign changes this outcome.

3. **Export payload transformation.**  
   With export selected, an original payload byte of zero produces a corresponding local byte of 36. The record payload is overwritten before F-56719562bce6 receives that local buffer.

4. **Export failure remains destructive.**  
   If F-56719562bce6 returns 1, the original record payload is not restored, and this function performs no flag-setting write. Dependency mutations may remain.

5. **Import transformation and clearing order.**  
   If F-17ddceb1746d returns zero with a local payload byte of 36, the corresponding record byte becomes zero. The four offset-92-field byte clears precede payload installation.

6. **High-bit status is failure.**  
   A dependency result of 0xFFFFFFFF prevents export flag setting or import output installation, respectively. It is not interpreted as a negative success value.

7. **Late flag preservation.**  
   If a dependency changes an unrelated flag bit and returns zero, that change is preserved if present at the subsequent flag read. The export update sets only 0x200; the import update clears only 0x200.

8. **Different import-global observations.**  
   Suppose all five local numeric outputs are 3, the first import-global read yields 4, and the second yields 5. Offset 72 receives 15; offsets 76, 80, 84, and 88 each receive 12. If both reads instead yield 4, all five receive 12. These products avoid signed overflow.

9. **Scalar defaults on successful import.**  
   If the import dependency returns zero, provides complete payload and numeric outputs, but leaves both scalar slots untouched, offsets 68 and 64 receive zero.
