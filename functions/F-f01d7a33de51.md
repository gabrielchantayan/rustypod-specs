# F-f01d7a33de51

## Purpose

F-f01d7a33de51 repeatedly performs an ordered sequence of indirect calls, 32-bit memory writes, byte writes, and value transformations. The supplied representation has an unconditional back edge and no normal return.

No application-level purpose is established. In particular, the evidence does not justify describing this operation as allocation, initialization, serialization, reference counting, or cleanup. Its observable contract is an indefinitely repeated sequence of call and memory effects, conditional on every intervening operation completing.

The contract below distinguishes explicit operations from unresolved execution details. It does not assume that indirect dependencies preserve memory, validate addresses, or manage ownership.

## Behavior

### Widths, arithmetic, and access conventions

For describing bit-level behavior, this contract uses a **32-bit word interpretation**: arithmetic retains the low 32 bits, and unsigned right shifts insert zero bits. This is directly supported for explicitly unsigned operations. Applying it to signed address arithmetic and signed left shifts is conditional on the target execution model; those cases remain documented uncertainties.

A **word slot** means the address obtained by multiplying a selected value by four and adding `0x14`. A **wide-stride slot** uses a multiplier of sixteen instead. These names describe address calculations, not proven array or object layouts.

Several writes use another pattern:

1. Read an unsigned byte from a computed location ending in offset `1`.
2. Use that byte as an absolute address contribution.
3. Add `0x11` and write one byte there.

This is not an established pointer dereference through a full-width pointer. The intervening value is explicitly only eight bits. Its resulting write address is between `0x11` and `0x110`, inclusive, under ordinary integer interpretation.

Similarly, a captured byte later determines a 32-bit write address between `0x14` and `0x113`. Such accesses need not be aligned.

Every explicitly represented byte write retains only the low eight bits of its value. Word stores retain 32 bits.

### Call ordering and interpretation

Indirect calls occur throughout the sequence, including many whose displayed argument lists are empty and whose results are unused. Those calls remain observable and must not be removed merely because their results are unused.

An empty displayed argument list does not establish a complete machine-level calling convention. Likewise, a displayed 64-bit result may represent a paired-register result rather than a single application-level integer.

The phases below follow represented execution order. Intervening dependencies may change memory. Consequently, a value read again after calls cannot be substituted with an earlier read unless external dependency contracts justify that substitution.

### 1. Initial propagation and control-byte writes

The first indirect call receives the first, second, and third inputs. After four additional calls, a returned index selects a word slot, and the first input is stored there. A following call receives four times that index.

Four further calls produce another index. Four times this second index becomes the **initial scaled value**. The function:

- Stores the initial scaled value at the second index’s wide-stride slot.
- Derives an **initial byte base** by multiplying the second index by `0x40000000`.
- Calls a dependency with three copies of the initial scaled value.

After another four calls, a third index selects a word slot. The initial scaled value is stored there, and a following dependency receives four times the third index.

Four more calls produce an **initial selector**. The fourth input is then written, in order, to:

- The initial byte base plus `0x11`.
- The initial byte base plus `1`.

A dependency receives the initial selector shifted left by two bits. A following call produces a 32-bit value that is passed to another dependency.

After four further calls, the same two byte writes are repeated in the same order. They are not redundant in the behavioral contract: intervening dependencies may have changed either location.

A subsequent call receives four times the most recently returned index.

Under 32-bit word arithmetic, the initial byte base can have only four values: zero, `0x40000000`, `0x80000000`, or `0xC0000000`.

### 2. Selector-derived read and initial byte-addressed updates

Four calls produce a new index, retained here as the **first retained index**. Its wide-stride slot receives the third index shifted left by 31 bits. Under word arithmetic, the stored value depends only on the third index’s least significant bit.

Next, the function reads a 32-bit word from:

- Address `0x14` plus bits 20–29 of the initial selector.

This address lies between `0x14` and `0x413`, inclusive, and is not necessarily word-aligned.

A dependency receives four times the first retained index. Another call returns a value retained as the **payload seed**. The next dependency receives the selector-derived word shifted right by 22 bits and then left by 28 bits. Under word arithmetic, the surviving result is bits 22–25 of the loaded word placed in bits 28–31.

Four calls produce an index whose word slot is cleared with a 32-bit zero. A following dependency receives four times that index.

After four more calls produce a **byte payload**, the function reads the byte at initial byte base plus `1`. It writes the low byte of four times the byte payload to the resulting byte-selected address plus `0x11`.

A dependency then receives four times the byte payload. A later dependency receives a preceding call’s 32-bit result together with the byte payload shifted left by 30 bits.

After four more calls:

- The byte at initial byte base plus `1` is read again and captured.
- Bits 20–27 of the byte payload are stored at captured byte plus `0x11`.
- A dependency receives four times the latest returned index.

After another four calls, four times the payload seed is stored as a 32-bit word at captured byte plus `0x14`.

This final word store uses the previously captured byte. It does not reread the byte-selection location after the intervening calls.

### 3. Global-derived update and first paired-result sequence

The function reads the represented 32-bit global after the preceding word store and before the next call. This is a value snapshot; subsequent changes to the global do not change the captured value.

A dependency receives four times the first retained index. Four subsequent calls produce a represented 64-bit result. Four times its low word becomes the **first pair scale**.

The function rereads the byte at initial byte base plus `1`, then writes the low byte of the global snapshot shifted right by 22 bits to byte-selected address plus `0x11`. The stored byte therefore contains original global bits 22–29.

A dependency receives the paired result’s high word. Another dependency subsequently receives a preceding 32-bit result and the first pair scale shifted left by 28 bits.

Four further calls precede another byte-selected write, this time of zero. The selector byte at initial byte base plus `1` is read again.

A following dependency receives four times the latest returned index. Four more calls produce an index, and a dependency receives two copies of four times that index.

### 4. First scaled word propagation

Four calls produce a **first payload index**. The function stores four times that index at:

- Address `0x14` plus the first pair scale multiplied by `0x1000`.

A dependency receives the first pair scale shifted left by 14 bits.

Four further calls produce another index. Its word slot receives the same stored payload, followed by a call receiving four times that destination index.

After four additional calls produce a represented 64-bit result:

- Four times its low word becomes the **second pair scale**.
- A byte is read at address `1` plus the first pair scale multiplied by `0x4000`.
- Bits 20–27 of the first payload value are written at that byte plus `0x11`.

A dependency receives the new paired result’s high word. A subsequent 32-bit call result is passed onward.

Another dependency returns a represented 64-bit result whose low and high words are explicitly forwarded as two arguments. Two further calls follow.

The next byte-selected zero write reads its selector at address `1` plus the second pair scale multiplied by `0x10000000`.

Under word arithmetic, that selector address can only be `1`, `0x40000001`, `0x80000001`, or `0xC0000001`.

### 5. Repeated zero writes and second scaled payload

A dependency receives four times the latest returned index. Four calls then produce the **second payload index**.

The function reads a selector byte at address `1` plus four times the second pair scale and writes zero at selector plus `0x11`. This selector address is reused later, but its byte is reread each time.

A dependency receives the second pair scale shifted left by ten bits. Another dependency subsequently receives a preceding 32-bit result and the payload seed shifted left by 28 bits.

After four calls, the function again reads the selector byte at address `1` plus four times the second pair scale and writes zero at selector plus `0x11`.

A dependency receives four times the latest returned index. Four calls follow. Then:

- The **second payload** is formed by shifting the second payload index left by 14 bits.
- That value is stored at address `0x14` plus the second payload index multiplied by `0x4000`.
- A dependency receives the second payload index shifted left by 16 bits.

After another call, a dependency receives the second payload shifted left by 28 bits and an unresolved auxiliary register value. Under 32-bit word arithmetic, the first of these arguments is necessarily zero, because the payload already has fourteen low zero bits. The second argument is not established as zero or as any earlier explicit result.

Four calls produce an index whose word slot receives the second payload. A dependency receives four times that destination index.

### 6. Final propagation and loop-state replacement

Four calls produce a **final retained index**. The selector byte at address `1` plus four times the second pair scale is reread. Bits 20–27 of the second payload are written at selector plus `0x11`.

A dependency receives the second payload index shifted left by 26 bits. Another dependency subsequently receives a preceding 32-bit result and the final retained index shifted left by 30 bits.

A dependency returns a represented 64-bit value. Its low and high words are passed as two explicit arguments to the next dependency. Two calls follow.

The selector at address `1` plus four times the second pair scale is reread, and zero is written at selector plus `0x11`.

A dependency receives four times the latest returned index. Four calls produce the **final payload index**.

Four times the final payload index is stored at address `0x14` plus the final retained index multiplied by `0x4000`.

The next dependency receives four arguments:

- The final retained index multiplied by `0x1000`.
- A second copy of that same value.
- The final retained index shifted left by 14 bits.
- Four times the final payload index.

Four calls produce another index. Its word slot receives four times the final payload index, followed by a dependency receiving four times that destination index.

Four final calls produce the **next-iteration index**. The function then:

- Replaces the first input with four times that index.
- Replaces the fourth input with zero.
- Stores the replacement first input at the next-iteration index’s wide-stride slot.
- Replaces the second and third inputs with the replacement first input.
- Repeats unconditionally.

Thus, from the second iteration onward, the first three explicit arguments passed at the loop head are equal, and the fourth-input byte writes use zero. The loop-head target selection also uses the link value established at the end of the preceding iteration rather than the original incoming link.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Repeated input-byte writes.** If execution reaches both pairs of initial byte writes with fourth input `0xA5`, each pair writes `0xA5` first at initial byte base plus `0x11`, then at initial byte base plus `1`. Calls between the pairs remain observable.

2. **Selector-byte rereading.** If a dependency changes a selector byte from `3` to `9` between two rereads, the corresponding byte-selected writes target `0x14` and `0x1A`, respectively. An implementation that caches the earlier selector would not preserve the represented behavior.

3. **Captured selector exception.** If the captured selector is `3`, the later payload-seed word store targets `0x17`, even if intervening calls change the original selector location.

4. **Narrowing a scaled byte payload.** If the byte payload is `0x00000043`, its first byte-selected store writes `0x0C`, the low byte of four times that value.

5. **Selector-derived word address.** Initial selectors `0x00000000` and `0xFFF00000` select read addresses `0x14` and `0x413`. Top selector bits outside the masked range do not affect this address.

6. **Global snapshot extraction.** If the global read returns `0xFFFFFFFF`, the later global-derived byte write stores `0xFF`, regardless of subsequent global changes.

7. **Forced-zero argument.** Under 32-bit word arithmetic, shifting the second payload left by 28 bits yields zero for every second payload index. This says nothing about the accompanying unresolved register argument.

8. **Loop transition.** If the final returned index is `7`, the next iteration receives `28` as each of its first three explicit loop-head arguments, uses zero for its fourth-input writes, and is preceded by a 32-bit store of `28` at address `0x84`.
