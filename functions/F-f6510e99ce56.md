# F-f6510e99ce56

## Purpose

F-f6510e99ce56 updates a four-word position descriptor using a signed movement argument and returns the original descriptor address.

The established behavior combines the requested movement with an existing position relative to a stored base, obtains a signed adjustment through opaque dependencies, and selects one of two update paths:

- A zero adjustment updates only the current-position word directly.
- A nonzero adjustment moves a stored table-entry address, loads a new base through that address, refreshes an upper-bound-like word, and computes a new current position.

The layout and arithmetic suggest movement through a segmented collection of four-byte elements. That is inferred intent, not an established container contract. In particular, neither dependency is established to return a segment capacity or perform division.

## Interface

### Inputs

The function accepts:

1. **A descriptor address.** The visible interface treats this as a pointer to signed integer storage. The function accesses four consecutive four-byte words.
2. **A movement value.** A signed integer used in element-scaled arithmetic.

The contract uses the following names for the descriptor’s byte offsets:

| Byte offset | Contract name | Visible use |
|---|---|---|
| 0 | Current | Read as the existing position and overwritten with the result |
| 4 | Base | Read in the initial relative-position calculation; replaced on a nonzero adjustment |
| 8 | Limit | Replaced on a nonzero adjustment |
| 12 | Entry | Treated as an address of a table entry; advanced on a nonzero adjustment |

Current, Base, Limit, and Entry are semantic labels for this document, not proof of a particular data structure.

### Widths and representation

The supplied representation uses four-byte integer words and four-byte scaling. Address-like values are carried in integer words and converted back into pointers. This supports a 32-bit address-word interpretation, but the supplied material does not independently establish the complete target ABI.

The arithmetic includes:

- Subtraction of the Current and Base words.
- A right shift by two bit positions.
- Addition of the movement value.
- Signed comparison against zero.
- Multiplication by four.
- Multiplication of an adjustment by a dependency result.
- Negation of a dependency result.

These operations must not be silently widened in a behavioral reconstruction. Conversely, the supplied representation alone does not justify a universal wraparound rule for signed overflow. Examples below stay within representable signed 32-bit ranges.

### Output

The return value is the original descriptor address, not the updated Current value or a newly allocated object.

No explicit status result, error code, or alternate return address appears in the visible body.

### Access preconditions

For ordinary completion:

- The descriptor must support the word reads and writes actually performed.
- On the nonzero-adjustment path, the computed table-entry address must support a four-byte read.
- Every invoked dependency must return normally for execution to reach the final write and return.
- Arithmetic and pointer conversions must have defined behavior under the actual execution model.

The function contains no explicit null check, bounds check, alignment check, or validation of descriptor consistency. It also contains no visible requirement that Current fall between Base and Limit.

## Behavior

### 1. Form a combined position value

Before invoking a dependency, the function reads Current and Base and forms a combined value:

\[
P = M + ((C_0-B_0)\mathbin{\text{>>}}2)
\]

Here, \(M\) is the movement argument, and \(C_0\) and \(B_0\) are the values used by the initial reads.

The shift applies to the subtraction result, not to Base alone. It is a shift operation, not established division. For negative differences or nonmultiples of four, replacing it with division may change behavior.

The two initial field reads occur before the first dependency invocation. Their relative evaluation order is not established by the supplied expression.

Once formed, \(P\) is retained for later calculations. The function does not recompute it from descriptor fields after dependency calls.

### 2. Obtain a signed adjustment

The sign of \(P\) selects the dependency sequence.

#### When \(P\) is nonnegative

1. Invoke **F-dc364b41daca** and retain its four-byte result.
2. Invoke **F-d7be9cfb4000** with:
   - First argument: \(P\).
   - Second argument: the retained result.
3. Use the signed result of that invocation as the adjustment \(A\).

#### When \(P\) is negative

1. Invoke **F-dc364b41daca** and retain its result for the second argument of a later call.
2. Invoke **F-dc364b41daca** again.
3. Form the first argument to **F-d7be9cfb4000** as:

\[
(\text{second result}-P)-1
\]

4. Invoke **F-d7be9cfb4000** with that value and the first retained result.
5. Negate its signed result to obtain \(A\).

The two calls to F-dc364b41daca on this path are distinct and ordered. Their results need not match. The first result remains the second argument to F-d7be9cfb4000 even if the second call changes shared state.

The subtraction, subtraction of one, and final negation each have their own representability constraints. In particular, negation of the minimum signed 32-bit value is an unresolved arithmetic edge.

### 3. Handle a zero adjustment

If \(A=0\), the function reads Current again, after the preceding dependency calls, and computes:

\[
C_{\text{new}}=C_{\text{read after calls}}+4M
\]

It then writes this result to Current and returns the descriptor address.

Consequences:

- The calculation uses the movement argument \(M\), not the combined position \(P\).
- The Current value used here can differ from the initial Current value if a dependency changed accessible state.
- The visible body does not write Base, Limit, or Entry on this path.
- It does not dereference Entry on this path.
- Dependency side effects are not excluded by these statements.

### 4. Handle a nonzero adjustment

If \(A\ne0\), the visible operations occur in this order.

#### Advance Entry

The function reads Entry after the adjustment-producing calls, adds \(4A\), interprets the result as a table-entry address, and writes that address back to Entry.

Thus, the table-address calculation uses the Entry value available at this stage, not an Entry value captured before the dependencies.

#### Load and replace Base

After updating Entry, the function reads one four-byte word through the computed table-entry address and writes that word to Base.

The write to Entry precedes the indirect read. This matters if the computed table-entry address aliases descriptor storage. The function does not visibly prohibit such aliasing.

The indirect read uses the computed address retained by the function. It is not described as a fresh lookup through Entry.

#### Replace Limit

After writing Base, the function:

1. Invokes F-dc364b41daca.
2. Reads Base.
3. Computes Base plus four times that invocation’s result.
4. Writes the computed value to Limit.

The Base read occurs after the dependency returns. It therefore need not equal the value just loaded from the table if the dependency can alter the descriptor.

No visible check ensures that Limit is greater than or equal to Base.

#### Compute the new Current

After writing Limit, the function:

1. Invokes F-dc364b41daca again.
2. Reads Base again.
3. Computes:

\[
C_{\text{new}}=B_{\text{latest}}+4(P-A R)
\]

Here, \(R\) is the result of this final invocation, and \(B_{\text{latest}}\) is the Base value read after it returns.

The two calls used for Limit and Current are separate. Their results are not interchangeable, and the Base reads associated with them can observe different values.

Finally, the function writes \(C_{\text{new}}\) to Current and returns the original descriptor address.

## Side effects

### Direct writes

On the zero-adjustment path, the visible body performs one descriptor write:

1. Current.

On the nonzero-adjustment path, the visible body writes:

1. Entry.
2. Base.
3. Limit.
4. Current.

There is no rollback. If an indirect access or dependency fails after an earlier write, the visible body provides no mechanism to restore the old descriptor.

For example, an invalid computed table-entry address is accessed only after Entry has already been replaced.

### Dependency calls

The number of visible calls depends on both the sign of \(P\) and whether \(A\) is zero:

| Condition | F-dc364b41daca calls | F-d7be9cfb4000 calls |
|---|---:|---:|
| \(P\ge0,\ A=0\) | 1 | 1 |
| \(P<0,\ A=0\) | 2 | 1 |
| \(P\ge0,\ A\ne0\) | 3 | 1 |
| \(P<0,\ A\ne0\) | 4 | 1 |

These are direct call counts from this function. They do not include any calls made inside dependencies.

### Ownership and lifetime

The visible body does not explicitly allocate or release memory. It overwrites the descriptor in place and does not return a new descriptor.

That observation does not establish that dependencies preserve ownership, retain no references, or perform no allocation or release. Their implementations and lifetime contracts are unknown. Successful completion requires that storage subsequently accessed by this function remain valid.

There is no visible synchronization or atomic-update protocol. The sequence must not be treated as an indivisible descriptor update.

## Acceptance examples

These are conditional contract examples, not executed tests. They assume signed 32-bit representability, valid memory, four-byte word addressing, normal dependency returns, and no dependency side effects unless stated otherwise.

### Zero adjustment with positive movement

Initial Current is 104, Base is 100, and movement is 2.

The combined value is 3. F-dc364b41daca returns 8, and F-d7be9cfb4000 receives first argument 3 and second argument 8. Suppose it returns zero.

Expected visible outcome:

- Current becomes 112.
- Base, Limit, and Entry receive no direct writes.
- The descriptor address is returned.

### Nonzero positive adjustment

Initial Current is 104, Base is 100, Entry is 1000, and movement is 9.

The combined value is 10. Suppose the first dependency returns 8 and F-d7be9cfb4000 returns 1. Suppose the word at address 1004 contains 200, and both later F-dc364b41daca calls return 8.

Expected direct effects, in order:

1. Entry becomes 1004.
2. The word at address 1004 is read.
3. Base becomes 200.
4. Limit becomes 232.
5. Current becomes 208.
6. The original descriptor address is returned.

### Negative combined position with distinct dependency results

Initial Current equals Base, movement is −1, and Entry is 1000. Therefore \(P=-1\).

Suppose the first two F-dc364b41daca results are 8 and 10. F-d7be9cfb4000 must receive first argument 10 and second argument 8. Suppose it returns 1, making \(A=-1\).

If the word at address 996 contains 300 and the two later results are both 8:

- Entry becomes 996.
- Base becomes 300.
- Limit becomes 332.
- Current becomes 328.

The example demonstrates that the first two dependency results have different roles.

### Different results for Limit and Current

Use the positive-adjustment example, but let the two later F-dc364b41daca results be 8 and 6 respectively.

With Base remaining 200:

- Limit becomes 232.
- Current becomes 216.

A reconstruction that reuses the Limit-related result for Current would not satisfy this contract.

### Dependency mutation before the zero-adjustment update

Suppose initial Current is 104, Base is 100, and movement is 2. The combined value is initially 3.

If a dependency changes Current to 500 before the zero-adjustment branch reads it, and the adjustment is zero, the final Current is 508—not 112. This outcome is conditional on such mutation being possible; the dependency’s actual ability to do so is unknown.
