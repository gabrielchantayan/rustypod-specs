# F-76972786a69f

## Purpose

F-76972786a69f selects between two observable actions on a supplied receiver:

- If either of two checks reports a nonzero result, invoke the receiver’s operation at virtual-table byte offset `0xB8`, passing the value `0x10`.
- If both checks report zero, obtain another object, use its operation at virtual-table byte offset `0x4C` to select a text address, construct or prepare a value through F-9b9c1c7483f4, deliver that value to the original receiver’s operation at virtual-table byte offset `0x11C`, and invoke F-8a5aadac202f afterward.

Every path that reaches the function’s ordinary return produces the 32-bit value `1`. This return value does not distinguish the two actions or establish that an underlying operation succeeded.

The apparent intent is to choose an exit-related action, possibly involving a main menu or extras destination. That interpretation comes from text-anchor naming in the supplied representation. The established behavior is the branching, argument flow, and dispatch sequence; destination semantics and exact text contents are not established.

## Behavior

### 1. Establish local argument cells

Before either check, the function copies the third and fourth argument values into distinct local 32-bit cells.

These cells are passed by address only on the path where both checks return zero. Their addresses designate storage local to this invocation. The body does not establish a right for dependencies to retain and later dereference those addresses after the invocation ends.

These copies are local initialization, not writes through the caller’s third or fourth argument values. The values themselves may encode pointers or handles, but this function does not explicitly interpret them that way.

### 2. Run the first check

The function reads the receiver’s 32-bit field at byte offset `0xB0` and passes that value to F-ce1760b0e2d3.

Its result is tested for equality to zero:

- A nonzero result selects the operation at receiver virtual-table offset `0xB8`.
- A zero result permits the second check.

The result is not restricted to Boolean encodings. Any nonzero 32-bit result, including a negative value under a signed interpretation, selects the nonzero branch.

### 3. Conditionally run the second check

The second check is skipped entirely when the first check returns nonzero.

When the first check returns zero, the receiver field at byte offset `0xB0` is read again. The function adds `0x2C` to this newly read value and passes the resulting 32-bit quantity to F-748a75efd9e8.

The addition is an increment of 44 in the represented address/value domain. It is not an addition of 44 array elements to the receiver. No explicit overflow or address-validity guard surrounds it.

The second read is significant. The function does not retain the first field value for this calculation. If F-ce1760b0e2d3 changes the field, directly or indirectly, the second check receives an argument based on the changed value.

The second check’s result is also compared with zero:

- Nonzero selects the receiver operation at virtual-table offset `0xB8`.
- Zero selects the text-selection and delivery path.

### 4. Execute the nonzero-check action

If either check returns nonzero, the function resolves the operation at byte offset `0xB8` through the original receiver’s virtual table and invokes it with:

1. The original receiver.
2. The value `0x10`, represented as the integer value 16.

There is no explicit use of this operation’s return value.

On this path, the function does not explicitly call:

- F-76b1c50b12f7;
- the secondary object’s operation at offset `0x4C`;
- F-9b9c1c7483f4;
- the original receiver’s operation at offset `0x11C`;
- F-8a5aadac202f.

After the selected operation returns normally, the function returns `1`.

The virtual-table resolution occurs after the checks. The supplied body does not establish that the checks preserve the receiver’s virtual-table pointer or dispatch targets.

### 5. Obtain the selector result

If both checks return zero, the function calls F-76b1c50b12f7 without explicit arguments.

It then invokes the operation at virtual-table byte offset `0x4C` on the returned object, passing:

1. That returned object.
2. A value read from a global data location.

The global value’s meaning, initialization, and exact declared width are not established by the supplied representation. Its use as an argument is established.

The global read belongs to this stage, after the two checks and the call to F-76b1c50b12f7. The body does not establish a relative evaluation order between that global read and the virtual-table reads needed to prepare this same indirect call.

The indirect operation’s result determines which text address is selected:

- Zero selects text address A.
- Nonzero selects text address B.

### 6. Select the text address

Text address A is one byte beyond a named text anchor whose name suggests an exit-to-main-menu message. Text address B is the starting address of a different named text anchor whose name suggests an exit-to-extras message.

The one-byte displacement for A is part of the established pointer selection. It must not be silently replaced with the anchor’s starting address.

The supplied representation does not expose the underlying bytes at either address. Consequently, this contract does not assert:

### 7. Prepare and deliver the value

The function calls F-9b9c1c7483f4 with three arguments, in this order:

1. Address of the local cell initialized from the fourth argument.
2. The selected text address.
3. Address of the local cell initialized from the third argument.

Both local cells are passed by address. Any mutation permitted by the dependency’s own contract can therefore affect their contents.

The returned value is then passed to the original receiver’s operation at virtual-table byte offset `0x11C`, together with the original receiver.

There is no explicit validity check on the returned value before delivery. The body does not compare it with zero or substitute another value.

The receiver’s dispatch target for delivery is resolved after F-9b9c1c7483f4 returns. A contract must not assume that earlier calls preserved receiver state or its virtual table.

This is the same local cell whose address was the first argument to F-9b9c1c7483f4. Its contents at this point may differ from the original fourth argument.

There is no corresponding explicit call on the local cell initialized from the third argument.

After F-8a5aadac202f returns normally, the function returns `1`.

These examples are conditional acceptance criteria derived from static evidence. They are not runtime observations.

### First check blocks the both-zero path

- F-748a75efd9e8 is not called.
- The receiver operation at `0xB8` receives `0x10`.
- No text preparation, delivery, or final local-cell operation is explicitly performed.

### Second check selects the same action

- The second check receives the current field value plus `0x2C`.
- The receiver operation at `0xB8` receives `0x10`.
- The selector object is not requested.
- Ordinary completion returns `1`.

### Mutation between field reads is visible

Suppose the field initially contains `0x1000`, and the first check changes it to `0x2000` before returning zero.

Provided the operations are valid under the execution environment, the second check must receive `0x202C`, not `0x102C`.

This example distinguishes the established reread from an implementation that caches the initial field value.

- F-8a5aadac202f is called afterward on the fourth-argument local cell.

### Preparation changes the fourth-argument cell
