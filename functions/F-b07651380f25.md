# F-b07651380f25

## Purpose

F-b07651380f25 processes a sentinel-terminated sequence of fixed-size records and emits a variable-length representation into caller-supplied storage. It maintains progress through a caller-owned, 32-bit cursor and invokes an external dependency once for each nonterminal record.

The directly established behavior is byte-oriented serialization followed by a dependency call. The meaning of the emitted byte values, the record fields, and the dependency’s operation is not established.

For stable, nonoverlapping inputs and a dependency that leaves the cursor unchanged, each record advances the cursor by either nine or ten bytes. Only the first six or seven bytes are written directly by this function. The final three-byte advance follows the dependency call; it does not itself establish that those three bytes were initialized.

## Interface

The function accepts five arguments and returns no explicit value.

| Argument | Representation | Contract |
|---|---|---|
| Reserved argument | 32-bit value | Not read or forwarded by the shown body. |
| Output base | 32-bit address-bearing value | Used with the current cursor to form output addresses. |
| Cursor reference | Pointer to a 32-bit integer | Read and updated repeatedly. Represents an offset relative to the output base. |
| Record sequence | Pointer to storage traversed in eight-byte steps | Supplies a 16-bit selector and a 32-bit payload per record. A zero payload terminates processing. |
| Tail-selection flag | 32-bit integer | Zero selects one dependency argument; any nonzero value selects another. |

### Record layout

Each eight-byte record has the following layout:

| Byte offset | Width | Interpretation |
|---|---:|---|
| 0 | 16 bits | Selector; only its low eight bits are emitted. |
| 2 | 16 bits | Not explicitly accessed as a field. |
| 4 | 32 bits | Payload and termination field. |

The payload is tested as a full 32-bit value. A record whose payload equals zero is a terminator, regardless of its selector or otherwise unused bytes.

For a nonterminal record, the payload is subsequently interpreted as an unsigned 32-bit value for comparison with 255. The emitted payload consists of either its low eight bits or its low sixteen bits.

### External state

The function accesses three global values:

- A template address, used to read individual bytes.
- A default tail argument.
- An alternate tail argument.

These are descriptive names, not claims about their application-level meaning.

### Preconditions

For ordinary successful execution:

- Every record reached during traversal must support the accesses described below.
- The sequence must eventually provide a zero-payload terminator if normal return is required.
- The cursor reference must support repeated 32-bit reads and writes.
- All computed output addresses must support the corresponding byte writes.
- The template address used for each read must identify accessible storage.
- The external dependency must accept its three supplied arguments and return if subsequent processing is expected.

No output capacity, record count, or template length is supplied. The function performs no explicit bounds or null checks.

Alignment requirements, address overflow behavior, and behavior on invalid memory depend on the target execution environment. They are not defined here as recoverable errors.

## Behavior

### Termination and traversal

At each loop test, including the final test:

1. The template-address global is loaded into a per-iteration snapshot.
2. The current record’s 32-bit payload field is read.
3. A zero payload ends processing immediately.

Thus, even an immediately terminating sequence causes a read of the template-address global. It does not cause a template-byte read, an output write, a cursor update, or a dependency call.

After a nonterminal record finishes, the record pointer advances by eight bytes. The next record is tested only after the dependency call and the following cursor increment.

The initial nonzero test does not permanently capture the payload for the rest of the iteration. The function reads that field again later.

### Direct writes and cursor updates

The following sequence preserves the observable ordering of the separate operations in the supplied body. It does not impose an additional evaluation order on address and value calculations within a single assignment.

1. **First template-derived output byte.**  
   The cursor is read and retained for the first two destination addresses. A byte at offset 1 from the template address obtained through another read of the template-address global is written at output base plus that retained cursor.

2. **Second template-derived output byte.**  
   A byte at offset 2 from the template-address snapshot captured at the loop test is written at the next output address.

3. **First cursor update.**  
   The cursor is read again. Two is added, and the result is stored through the cursor reference.

4. **Next two template-derived writes.**  
   Using the cursor value read immediately before that update, bytes at template offsets 3 and 4 from the per-iteration snapshot are written at output offsets two and three relative to that saved value.

5. **Selector write.**  
   The current record’s 16-bit selector is read. Its low eight bits are written at output base plus the cursor’s current value plus one.

   With ordinary nonoverlapping storage, this overwrites the just-written template-offset-4 byte. That intermediate template read and output write still occur.

6. **Second cursor update.**  
   The cursor is read again, two is added, and the result is stored. The pre-update cursor value is retained for the following marker destination.

7. **Payload classification and marker write.**  
   The current record’s payload is read as an unsigned 32-bit value. This read determines both the marker and the short-versus-long branch:
   - Values at most 255 select marker byte `0x95`.
   - Values greater than 255 select marker byte `0x96`.

   The marker is written at output base plus the cursor value retained immediately before the second update, plus two.

8. **Low payload byte.**  
   The payload field is read again. Its low eight bits are written at output base plus the cursor’s current value plus one.

9. **Optional high payload byte and cursor completion.**
   - If the classification read was greater than 255, the payload field is read again. Bits 8 through 15 are written at output base plus the cursor’s current value plus two. The cursor is then read, increased by three, and the result is stored.
   - Otherwise, the cursor is read, increased by two, and the result is stored. There is no high-payload-byte write.

The branch decision remains based on the classification read even if later payload reads produce different values.

The terminator check is also separate from classification. With overlapping storage or external mutation, a record that initially passed the nonzero test can later classify as zero and still be emitted.

### Dependency invocation and final cursor advance

After storing the cursor value that completes the directly emitted portion:

1. The default tail-argument global is read.
2. If the tail-selection flag is nonzero, the alternate tail-argument global is also read and replaces the selected value.
3. F-000000000001 is invoked with:
   - Output base plus the cursor value just computed for the directly emitted portion.
   - The selected tail argument.
   - The integer value 3.
4. After the dependency returns, the cursor is read again, three is added, and the result is stored.

The final increment uses the cursor value present after the dependency returns. It does not necessarily use the pre-call cursor value.

The body does not use a return value from the dependency.

### Ordinary final byte layout

Under all of these conditions:

- The cursor, records, output, and relevant global/template storage do not overlap in a behavior-changing way.
- Those values remain stable except for this function’s intended output and cursor writes.
- The dependency returns without changing the cursor.

Let the starting cursor be \(s\), the selector be \(q\), and the nonzero payload be \(v\).

| Output offset relative to \(s\) | Final directly written value |
|---|---|
| 0 | Template byte at offset 1 |
| 1 | Template byte at offset 2 |
| 2 | Template byte at offset 3 |
| 3 | Low eight bits of \(q\) |
| 4 | `0x95` if \(v \leq 255\); otherwise `0x96` |
| 5 | Low eight bits of \(v\) |
| 6 | Bits 8–15 of \(v\), only when \(v > 255\) |

The dependency receives output base plus \(s+6\) for the short form or output base plus \(s+7\) for the long form. The cursor finishes at \(s+9\) or \(s+10\), respectively.

This table describes the final direct-write result, not the complete write trace. In particular, the template byte at offset 4 is written before the selector replaces it.

## Side effects

### Memory and state

The function directly:

- Reads the template-address global at every loop test and again for the first template-byte write.
- Reads template bytes at offsets 1 through 4.
- Reads each reached record’s payload, and reads the selector for processed records.
- Writes individual output bytes.
- Repeatedly reads and writes the caller-owned cursor.
- Reads the default tail argument for every processed record, and additionally reads the alternate argument when the flag is nonzero.
- Calls F-000000000001 once per processed record.

The dependency may have additional effects. None are established by this body.

### Ownership

The body performs no explicit allocation, release, or ownership transfer. It does not directly retain the supplied pointers in persistent storage.

That observation does not establish whether the dependency retains its arguments, modifies shared state, or releases memory. No such guarantee may be inferred.

### Partial completion and errors

There is no explicit error result, rollback, or cleanup path.

If a memory access fails or the dependency does not return normally, earlier writes and cursor changes may already be visible. The function supplies no transactional guarantee.

Insufficient destination capacity is not detected by this body. Likewise, an absent terminator does not produce a defined “end of input” error.

### Aliasing

No explicit non-aliasing check exists. The detailed operation order matters when storage overlaps:

- An output write can change a payload before a later payload read.
- A cursor store can change bytes subsequently read as input.
- A dependency can alter the cursor before the final increment.
- Earlier output writes can affect later template or global reads when addresses overlap.

The ordinary layout and cursor totals are conditional consequences, not unconditional guarantees under arbitrary aliasing.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence. No runtime tests have been performed.

### Immediate terminator

Given a first record with a zero 32-bit payload:

- The function returns without processing that record.
- The cursor remains unchanged.
- No output bytes are directly written.
- F-000000000001 is not called.
- The loop-test template-address global read still occurs.

### Short form

Given stable template bytes, starting cursor 20, selector `0x12AB`, payload 255, and a following terminator:

- The selector byte emitted at relative offset 3 is `0xAB`.
- Relative offset 4 contains `0x95`.
- Relative offset 5 contains `0xFF`.
- The dependency receives output base plus 26 and third argument 3.
- If the dependency leaves the cursor unchanged, the final cursor is 29.

### Long-form boundary

With payload 256 under the same stability assumptions:

- Relative offset 4 contains `0x96`.
- Relative offsets 5 and 6 contain `0x00` and `0x01`.
- The dependency receives output base plus the starting cursor plus seven.
- If the dependency preserves the cursor, the total cursor increase is ten.

### Values wider than the emitted payload

With payload `0x00010000`:

- The record is nonterminal.
- The unsigned comparison selects the long form.
- The emitted payload bytes are both zero.
- No direct write preserves payload bits 16 through 31.

With payload `0xFFFFFFFF`, the long form is selected and both emitted payload bytes are `0xFF`.

These cases demonstrate that representation length depends on the full 32-bit value, while the emitted payload retains at most sixteen bits.

### Tail selection and dependency-modified cursor

For a zero flag, only the default tail-argument global supplies the second call argument.

For any nonzero flag, the default global is read first and the alternate global supplies the second call argument.

If the dependency returns with cursor value 100, the following cursor store sets it to 103, provided the addition is representable. The pre-call cursor does not determine that final increment.

### Multiple records

For stable payloads 1, 256, and then 0, and a cursor-preserving dependency:

- Exactly two dependency calls occur.
- The cursor increases by nineteen.
- The terminator produces no emitted representation.
