# F-e09925a5c841

## Purpose

No domain-level purpose is established. Address patterns and field-like offsets do not establish allocation, serialization, device access, interpretation, or object construction. ## Behavior

### Widths, notation, and ordering

Byte accesses transfer eight bits. Word accesses transfer 32 bits. A byte store retains the low eight bits of its value.

The relationships below use the following notation:

- \(W_s(x)\) denotes a word address formed as \(s x + 0x14\).
- “Scaled by four” denotes multiplication by four or a left shift by two, as represented.
- A selector-mediated byte store reads an unsigned selector byte from a specified address, then writes one byte at the numeric address \(selector + 0x11\).

A selector-mediated destination is therefore between \(0x11\) and \(0x110\). It is not relative to the selector’s storage address. A retained selector used for a word store at \(selector + 0x14\) instead selects an address between \(0x14\) and \(0x113\).

Arithmetic simplifications involving overflow are conditional on 32-bit bit-pattern semantics: results retain their low 32 bits. Several expressions use signed representations, so exact overflowing multiplication and signed-left-shift behavior remains unresolved without instruction-level evidence. Unsigned right shifts and byte narrowing have the widths stated above.

Dependency identifiers are opaque call-site labels. They do not establish distinct underlying functions. Within each group, calls occur in increasing numeric order. “No explicit arguments” does not mean a dependency cannot observe other machine state.

\[
((\text{F-I05 result} \mathbin{\&} 0x3fffffff) \gg 20) + 0x14.

The **next fourth argument** is the F-W05 result shifted left by 14. A word store writes it at

\[
(\text{F-W05 result} \ll 14) + 0x14.

The same value becomes the next iteration’s auxiliary value.

F-Z01 receives the F-W05 result shifted left by 16. F-Z02 has no explicit arguments. F-Z03 receives the next fourth argument shifted left by 28, followed by the unresolved register-derived argument. Under low-32-bit arithmetic, its first argument is zero: the next fourth argument already has its bottom 14 bits clear.

1. Its result is scaled by four to form the next first argument.
2. A 32-bit store writes the next fourth argument at the next first argument plus \(0x14\).

## Side effects

Explicit stores are either eight-bit or 32-bit stores. No explicit allocation, release, synchronization, cleanup, or ownership transfer is established.

Addresses may alias each other, selector storage, global storage, or memory accessed by dependencies. Accordingly:

- Fresh selector reads remain distinct observable accesses.
- A retained selector must not be replaced with a later lookup.
- Repeated stores across dependencies are not redundant merely because their values match.
- The global snapshot is taken at its stated position; later global changes do not alter the retained value.
- Dependency calls and explicit accesses retain their represented relative order.

No dependency is assumed to preserve globals, avoid memory mutation, return normally, or preserve ownership and lifetime.

If a call does not return or an access faults, earlier side effects may already have occurred. No recovery or rollback is represented. In particular, the final word store occurs after F-Z07 and before the next opening call; failure at that store leaves the completed tail calls in the execution history without establishing another iteration.

## Acceptance examples

These are conditional static consequences, not executed tests. Arithmetic examples assume low-32-bit semantics where necessary.

1. **Byte narrowing.** With fourth argument \(0x3ff00000\), the opening extracted field is \(0x3ff\), and the stored byte is \(0xff\).

2. **Fresh selector lookup.** If the opening selector is 3, the first byte destination is \(0x14\). If an intervening dependency changes that selector to 9, the later zero-byte store targets \(0x1a\).

3. **Retained selector.** If the selector captured before F-O01 is 7, the following selector-based word store starts at \(0x1b\), even if those dependencies change the selector’s storage.

4. **Zero-derived address.** A zero result selecting \(W_4\) produces address \(0x14\). No null-like guard intervenes. Continued execution requires that access to succeed.

5. **Persistent-base truncation.** Third-index values differing only above bit one produce the same persistent base under 32-bit truncation.

6. **Snapshot retention.** If a dependency changes global storage after the explicit global read, the later snapshot-derived byte still uses the earlier read value.

7. **Final-store ordering and progression.** Suppose calls and accesses through F-Z07 succeed, F-Z07 returns 3, and the next fourth argument is \(0x4000\). The next explicit memory operation is a 32-bit store of \(0x4000\) at \(0x20\), because the returned value is first scaled to 12. If this final store also succeeds, execution reaches the next F-A01 call with first argument 12; it does not return normally. If the store faults, that next call is not reached.

8. **Boundary argument truncation.** F-Z03’s first explicit argument is zero under 32-bit truncation, regardless of the F-W05 result. Its second argument remains unresolved.
