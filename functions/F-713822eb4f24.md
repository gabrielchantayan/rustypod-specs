# F-713822eb4f24

## Purpose

F-713822eb4f24 derives a discrete level from an unsigned quantity and a globally addressed 16-bit adjustment. It publishes the level, reports one level predicate to a dependency, and conditionally updates a second state byte and requests further processing.

Established behavior consists of:

- Selecting one of **1, 4, 5, 6, or 7**.
- Performing two preparatory calls.
- Publishing the selected level through a freshly read global state base.
- Classifying a byte through an earlier capture of that state base.
- Either returning early or writing the selected level to the captured state’s second byte.
- Submitting a temporary two-word payload.
- Conditionally polling a byte and dispatching a final call.

“Adjustment,” “state,” “readiness,” and “dispatch” are descriptive labels. An interpretation involving level-change notification or suppression is plausible but does not establish domain semantics.

## Behavior

### Adjustment reads and arithmetic

The function first evaluates the global adjustment/context base and reads the unsigned 16-bit field at offset 4. This first value is widened to 32 bits and retained.

It independently evaluates the global base again and reads the offset-4 field to decide whether that second value is less than 32,768. These are distinct field expressions, each using its own evaluation of the global base. They need not address the same allocation if the global changes.

If the second value is below 32,768, the function adds the **first** value to the input quantity.

Otherwise, it compares the input quantity with **65,536 minus the first value**:

- If the input is smaller, it selects level 1 directly.
- If the input is at least that amount, it evaluates the global base again and performs a third unsigned 16-bit field read. It forms an unsigned additive adjustment equivalent to **the third value minus 65,536**, modulo \(2^{32}\), and adds it to the input.

The quantity addition is unsigned 32-bit arithmetic. It wraps modulo \(2^{32}\); it does not saturate. The initial subtraction from 65,536 ranges from 1 through 65,536 because the first read is an unsigned 16-bit value.

Under a stable global base and stable adjustment field, the encoding behaves like a signed 16-bit adjustment:

- 0–32,767 add that nonnegative amount.
- 32,768–65,535 subtract 32,768–1.
- If the magnitude of a negative adjustment exceeds the input, level 1 is selected without threshold evaluation.

That interpretation is conditional. With changing bases or field contents, the first read supplies one arithmetic value, the second chooses the branch, and a possible third supplies the additive adjustment. They must not be collapsed into one signed read.

### Threshold selection

If the arithmetic reaches threshold selection, the resulting unsigned quantity determines the level:

| Adjusted quantity | Level |
|---|---:|
| 0–99 | 1 |
| 100–199 | 4 |
| 200–499 | 5 |
| 500–999 | 6 |
| 1,000–4,294,967,295 | 7 |

The comparisons occur in descending order: greater than 999, greater than 499, greater than 199, then greater than 99.

No path selects 0, 2, or 3.

### Context capture and preparation

After selecting the level, the function:

1. Reads and retains the current adjustment/context base as a 32-bit value.
2. Calls F-89ae823a3c51 with the object address plus 96.
3. Saves the opaque incoming 32-bit machine-state value in temporary storage.
4. Calls F-c979b3c48e40 without explicit arguments.

The context-base capture is independent of the earlier adjustment-field evaluations. It can therefore differ from every base used for those reads.

The selected level is not recomputed after either preparatory call. Neither dependency is assumed to preserve globals or pointed-to storage.

### Separate state capture and publication

After both preparatory calls return, the function performs two distinct evaluations of the global state base:

1. It captures the current base for later offset-1 accesses.
2. It independently reads the global base again and writes the selected level as one byte at offset 0 of that second base.

These accesses must not be modeled as using one necessarily identical pointer. If the global changes between the evaluations, publication at offset 0 and subsequent classification or updating at offset 1 can address different allocations.

The function then calls F-fa1e7c5a0d15 with the predicate **selected level greater than 3**:

- False for level 1.
- True for levels 4, 5, 6, and 7.

The offset-0 write precedes this call. The captured base for offset-1 accesses is not refreshed afterward.

### Classification and the early-return condition

After F-fa1e7c5a0d15 returns, the function reads byte offset 1 through the captured state base. It explicitly converts that byte through a plain-character interpretation and then to a signed 32-bit integer before passing it to F-c39b71dff8cc.

The character conversion and the later comparison against −1 are separate operations with separate type uncertainties:

- For the **classifier argument**, signed plain-character semantics would map byte patterns 128–255 to negative values. Unsigned plain-character semantics would pass values 128–255 as nonnegative integers.
- For the **later comparison**, the byte is read through the underlying one-byte storage type without the explicit character conversion. Its signedness and integer promotion must be established independently.

The classifier’s unsigned 32-bit result is compared exactly with the predicate **selected level greater than 4**:

| Selected level | Matching classifier result |
|---|---:|
| 1 or 4 | 0 |
| 5, 6, or 7 | 1 |

A result of 2 or any other value does not match.

Only when this comparison matches does the function read state offset 1 again and compare that later read with −1. It returns immediately if the later value compares unequal to −1.

The supplied material does not define the underlying one-byte storage type sufficiently to resolve that comparison unconditionally:

- Under a conventional **unsigned 8-bit storage type promoted to signed 32-bit integer**, every possible read is 0–255 and therefore unequal to −1. A matching classifier result always permits early return, including when the byte pattern is 255.
- Under a **signed 8-bit storage type promoted with sign preservation**, the byte pattern 255 becomes −1. In that case, this byte prevents early return even when the classifier result matches.

Plain-character signedness alone cannot choose between these outcomes.

The classifier may modify the captured state storage before the conditional reread. Changes to the global state base do not redirect that reread, because the function continues using the captured base.

### Conditional second-byte write and request

If the early-return condition is not satisfied, the function writes the selected level as one byte to offset 1 of the captured state base.

It then prepares contiguous temporary storage with this layout:

The meaning of 4 is unknown. The established eight-byte payload layout does not establish that this argument is a byte count.

### Request result, polling, and dispatch

Immediately after F-f864d4b0c549 returns, the function captures the current readiness base. This capture occurs for both zero and nonzero request results.

A **zero result** skips readiness-byte reads, polling calls, and final dispatch. It is not established to mean failure or success. This function performs no explicit rollback, but the preceding dependencies may have modified state storage; persistence of earlier written values is not guaranteed.

A **nonzero result** causes the function to:

- Extract the low eight bits of the first payload word as it exists after the request call.
- Read the byte at offset 2 of the captured readiness base.
- For each zero readiness read, call an additional external dependency with arguments 0 and 1, then read readiness again.
- Once a readiness read is nonzero, call F-b4c8a64376c1 with the extracted value, widened to 32 bits, and a second argument of 0.

Extraction occurs before polling. Later payload changes during polling do not cause re-extraction.

The readiness check is a zero/nonzero test, so character signedness does not change which byte patterns permit dispatch. The readiness base is not refreshed during the loop.
