# F-d1a8da728928

## Purpose

F-d1a8da728928 validates selected fields of a 32-bit input word and incrementally updates a caller-supplied state object. It returns a 32-bit status value: **0** for completion or **3** for a rejected field.

Validation and mutation are interleaved. A return value of 3 does **not** imply that the state object is unchanged. Depending on the rejected field, the function may already have written a one-byte mode value and a four-byte constant.

The field arrangement and numeric outputs suggest an audio-header interpretation. That interpretation is inferred intent, not an established requirement. The contract below uses bit positions and state offsets without requiring a particular media format.

## Behavior

### 1. Check the leading eleven bits

Bits 31 through 21 must all be 1. Equivalently, the unsigned input shifted right by 21 must equal 2047.

If this check fails:

- Return 3.
- Perform no state-object access.
- Perform no access to the two external words shown in this function.

This check does not validate any lower bits.

### 2. Decode and write the mode

After the leading-bit check succeeds, bits 20 through 19 determine the next action:

| Bits 20:19 | Action |
|---|---|
| `00` | Write one byte with value 2 at `+0x30`. |
| `01` | Return 3 without writing the mode byte. |
| `10` | Write one byte with value 1 at `+0x30`. |
| `11` | Write one byte with value 0 at `+0x30`. |

A rejected `01` encoding causes no state writes in this invocation.

For each accepted encoding, the mode-byte write happens before the next validation check. Consequently, a later rejection can leave this byte changed.

### 3. Check bits 18 through 17

Bits 18 through 17 must encode `01`.

Any other encoding returns 3 immediately. In that case, the mode byte written in the previous step remains changed, but this invocation has not yet written any four-byte state field.

If the encoding is accepted, write the four-byte value 3 at `+0x34`.

This write occurs before validating the next field.

### 4. Check and select using bits 11 through 10

Bits 11 through 10 select a base value:

| Bits 11:10 | Selection |
|---|---|
| `00` | External word A |
| `01` | External word B |
| `10` | The numeric value 32000 |
| `11` | Reject with status 3 |

For the rejected `11` encoding:

- The mode byte has already been written.
- The four-byte value 3 has already been written at `+0x34`.
- This invocation has not yet written `+0x18`, `+0x10`, `+0x1C`, or `+0x24`.
- Neither external word is accessed by the displayed selection logic.

For accepted selections, the supplied representation shows the following external accesses:

1. Read external word A.
2. If the selection is not `00`, also read external word B.
3. Store the selected value at `+0x18`.

Thus, selection `10` shows reads of both external words before using the literal value 32000. External word B is also read for selection `01`; external word A is read first even though its value is not selected.

These are accesses established by the supplied representation. Whether every such read corresponds to a distinct physical load in the executable is not established, particularly because volatility and machine instructions are not supplied.

### 5. Read the mode back and conditionally reduce the stored value

After writing the selected base value at `+0x18`, read the byte at `+0x30`.

The next behavior depends on the value actually read:

| Mode byte read | Effect on `+0x18` |
|---|---|
| 1 | Read the four-byte value as unsigned, shift right by one bit, and write the result back. |
| 2 | Read the four-byte value as unsigned, shift right by two bits, and write the result back. |
| Any other value | Do not perform a reduction read or write at `+0x18`. |

Unsigned right shifts discard low bits and introduce zero bits at the high end. For ordinary numeric values, these operations implement division by 2 or 4 with downward truncation. They are not signed division.

Under ordinary, noninterfered execution, the mode byte read here is the value written earlier:

- Input mode `00` produces a two-bit reduction.
- Input mode `10` produces a one-bit reduction.
- Input mode `11` produces no reduction.

The explicit read-back matters. The function does not simply reuse a computed mode value. If the byte has changed through external interference or an unusual storage arrangement, the subsequent behavior follows the value read, not necessarily the original input encoding.

### 6. Write the output category

Bits 7 through 6 determine the four-byte value written at `+0x10`:

| Bits 7:6 | Stored value |
|---|---:|
| `11` | 1 |
| `00`, `01`, or `10` | 2 |

None of these four encodings is rejected.

This write occurs after selection and any reduction of the value at `+0x18`.

### 7. Write the final fixed and mode-dependent values

Using the mode byte previously read in step 5:

- If that byte was 0, the output quantity is 1152.
- Otherwise, the output quantity is 576.

Write the four-byte value 16 at `+0x1C`, then write the chosen output quantity at `+0x24`.

Return 0.

The mode byte is not reread for this final choice. In particular, an unexpected nonzero byte produces 576 even if it did not trigger a reduction at `+0x18`.
