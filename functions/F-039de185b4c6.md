# F-039de185b4c6

## Purpose

The supplied static representation describes an indefinitely repeating sequence of indirect calls, byte writes, word writes, and one explicit global-word read. It does not establish an application-level purpose.

The observable contract is therefore a state-transition contract, not a claim that this function initializes, allocates, serializes, or manages a particular object.

No normal return or loop-exit condition is present in the supplied representation. Execution can nevertheless stop or diverge inside a dependency, or fail on an instruction or memory access. Such outcomes are not handled locally.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Low-byte input handling.** If the fourth input is 0x123456ab and the initial calls return, the first two direct byte writes store 0xab, first at Base + 0x11 and then at Base + 1.

2. **Absolute byte-derived addressing.** If a relevant byte read yields 0x7f, the following byte-derived store targets address 0x90. It does not target Base + 0x90. If that address is inaccessible, successful continuation is not guaranteed.

3. **Cached versus fresh address selection.** If Cached-byte is 0x20 and F-C08 subsequently changes B(Base + 1), the following direct word write still targets 0x34. Later fresh reads may select different addresses.

4. **Truncation of a shifted byte value.** If Payload is 0x00000041, the step-2 byte store receives 0x04, the low byte of its left shift by two.

5. **Masked extraction.** If Payload is 0xffffffff, T(Payload) is 0xff. Although the intermediate masked shift yields 0x3ff, the byte write discards its upper two bits.

6. **Shifted-out argument.** Second-word is J-value shifted left by 14. Consequently L(Second-word, 28) is zero under the stated 32-bit model, regardless of J-value. The associated dependency call still occurs.

7. **Restricted next Base.** Under the 32-bit model, L(S-value, 30) is one of 0, 0x40000000, 0x80000000, or 0xc0000000. The two trailing byte writes use that resulting Base.

8. **No transactional failure behavior.** If a dependency fails after earlier stores have succeeded, no local rollback is shown. The supplied representation does not define a recovery result.

9. **Continued execution.** If all calls return and all accesses succeed, completion of step 10 starts another iteration rather than returning to the caller.
