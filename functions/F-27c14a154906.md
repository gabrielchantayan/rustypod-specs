# F-27c14a154906

## Purpose

F-27c14a154906 requests a record from F-928c667e2a08 using an object-associated context and a 32-bit selector. If the returned record has discriminator 1, 2, or 3, it publishes a one-byte discriminator and a four-byte payload to caller-provided storage.

The established normal return values are:

- **0:** an accepted record was returned and both output stores completed.
- **6:** the lookup returned a null reference or a record with an unsupported discriminator.

A null object or an initially zero context causes a call to F-540af0155702. This call receives a string-labelled argument and values read from two global data locations. The global values are not established as immutable constants.

The diagnostic path is not itself a status-return path. If F-540af0155702 returns, execution continues toward the lookup, including another access to the object’s context field.

The semantic meanings of the selector, context, discriminator categories, and payload are not established. A compact tagged-result operation is inferred intent, not an independently established interface meaning.

## Behavior

### Initial object and context check

The function first tests whether the object reference is null.

- If it is null, the initial context-field read is skipped and the diagnostic path is selected.
- If it is non-null, the function reads the four-byte field at object offset 140. A zero value selects the diagnostic path; a nonzero value bypasses it.

The initial context value is used for this decision. It is not reused as the lookup argument.

### Diagnostic argument acquisition and invocation

On the diagnostic path, after the initial object/context check and before invoking F-540af0155702, the function obtains argument values from two global data locations.

The diagnostic invocation has three argument positions:

1. A string-labelled argument.
2. A value read from one global data location.
3. A value read from a different global data location.

The second and third argument positions identify which global supplies each argument. They do **not** establish which global is read first. The supplied representation does not specify the relative evaluation order of those two reads.

The global values are runtime inputs to this invocation, not established immutable diagnostic constants. Their contents, meanings, and declared widths are not independently recoverable from the supplied function representation. The complete contents and exact type of the string-labelled argument are also not established.

No direct read of either diagnostic global is present on the path that bypasses the diagnostic call.

There is no explicit local return or termination immediately after F-540af0155702. Its behavior determines whether execution continues. No assumption is made that it preserves globals, the context field, other reachable memory, or resource ownership.

### Lookup after the check

If execution continues, the function reads the four-byte context field at object offset 140 and calls F-928c667e2a08 with:

- That newly read context value.
- The original 32-bit selector.

This context read is separate from the initial check read.

Consequences include:

- A non-null object whose initial context is nonzero has its context field read twice before lookup.
- If the diagnostic returns after changing a valid object’s context, the later read supplies the changed value.
- If a valid object’s context remains zero after the diagnostic returns, lookup receives zero. There is no second diagnostic check.
- If the original object reference is null and the diagnostic returns, execution proceeds to the context-field access using that null input. No safe recovery or normal return is established for this continuation.

The lookup argument is therefore determined by the later read, not by the value that selected or bypassed the diagnostic.

### Lookup result classification

If F-928c667e2a08 returns a null reference, the function returns **6** without directly writing output.

For a non-null result, the function reads the four-byte discriminator at record offset 4.

- Values **1**, **2**, and **3** are accepted.
- Every other 32-bit value produces return value **6**, with no direct output store and no local payload read.

Acceptance uses the complete four-byte discriminator, not its low byte. A discriminator of 257 is unsupported despite having the same low byte as 1.

Signed interpretation does not change the accepted set: only the three exact positive values are accepted.

### Publishing an accepted record

For any accepted discriminator, the established local memory-operation order is:

1. Store the accepted discriminator as one byte at output offset 0.
2. Read the four-byte payload at record offset 12.
3. Store that payload at output offset 4.
4. Return **0**.

All accepted discriminator values fit exactly in one byte. The narrowing store therefore preserves their values.

The payload undergoes no visible validation or semantic conversion. Its signedness and interpretation as a number, reference, or other encoding remain unknown.

Publication is not established as atomic or transactional. The discriminator store precedes both the payload read and payload store. An invalid access or interruption after that first store may leave output partially updated without a successful return. The representation supplies no rollback behavior.

All explicit field displacements are fixed byte offsets: 140 for context, 4 and 12 within the record, and 0 and 4 within output. There is no length-derived arithmetic, loop, or variable-size copy.
