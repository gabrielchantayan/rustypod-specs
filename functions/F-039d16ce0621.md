# F-039d16ce0621

## Purpose

F-039d16ce0621 performs a two-stage lookup or resolution operation using an object obtained through a caller-provided reference slot. An initially sampled mode byte determines whether the first result is accepted unconditionally or examined for a populated field.

When the sampled mode is zero, a missing first result or a zero field within that result triggers a second resolver. If that resolver also returns zero, the function requests diagnostic reporting. A negative supplied length is replaced by the result of a length-related dependency only on this final failure path.

The diagnostic’s identifiable text concerns a missing collation sequence. This supports an interpretation of the operation as collation resolution, but the underlying record types, lookup rules, and registration behavior are not established here.

This contract describes behavior visible in the supplied static source. No runtime tests have been performed.

### Output

The function returns an integer-sized value:

- The first resolver’s value when the sampled mode is nonzero.
- The first resolver’s nonzero value when the sampled mode is zero and the word at result offset `0x0C` is nonzero.
- Otherwise, the second resolver’s value, including zero.

Nonzero resolver results are used as addresses in one branch. Their ownership and precise type are unknown.

On the final failure path, the function returns zero if the diagnostic dependency returns normally. It does not return the diagnostic dependency’s result.

## Behavior

### Initial sampling and first resolution

Before calling a dependency, the function obtains:

1. The working object address from the reference slot.
2. The mode byte from working-object offset `0x80`.
3. A second byte through the pointer chain beginning at working-object offset `0x08`, continuing through intermediate-record offset `0x14`, and ending at further-record offset `0x59`.

The working object address and mode are retained as local values. The pointer-chain reads needed to obtain the second byte occur after the mode read and before the first dependency call.

The function then calls F-4a95613e1504 with five arguments, in this positional order:

1. Retained working object address.
2. Byte obtained through the pointer chain.
3. Original opaque four-byte value.
4. Original signed length or selector.
5. Retained mode byte.

The byte at `0x59` is represented as a one-byte value without an established signed interpretation. The mode is represented as a plain character. Its zero/nonzero classification is unambiguous, but its promoted numeric value for bytes `0x80`–`0xFF` depends on character signedness and the calling convention.

### Nonzero sampled mode

When the retained mode is nonzero, the function returns the first resolver’s result without further inspection.

In particular:

- A zero first result is returned without invoking the second resolver.
- A nonzero first result is not dereferenced by this function.
- No length-related or diagnostic dependency is invoked by this function.

This decision uses the mode sampled before the first call. A dependency changing the object’s mode byte does not cause the function to reread it or select a different branch.

### Zero sampled mode

When the retained mode is zero, the first result is assessed as follows:

- A zero result triggers the second resolver without a result-record read.
- A nonzero result causes an integer-sized word to be read at result offset `0x0C`.
- A nonzero word at that offset causes the first result to be returned.
- A zero word at that offset triggers the second resolver.

The result-field read occurs after the first resolver returns. It therefore observes memory at that time, rather than a value sampled before the call.

Only zero versus nonzero matters for the field. The function neither validates a particular nonzero value nor dereferences that field.

### Second resolution

When required, F-dd82aab5ab38 receives four arguments:

1. Retained working object address.
2. First resolver’s result, including zero where applicable.
3. Original opaque four-byte value.
4. Original signed length or selector.

The second resolver is called both for an absent first result and for a nonzero first result whose inspected field is zero.

Its return value replaces the first result for all subsequent behavior and for the final return.

A nonzero second result is returned immediately, without inspecting its offset `0x0C` or any other field. The acceptance rule for second-stage results is therefore less restrictive than the rule applied to first-stage results under zero mode.

- A negative supplied value causes F-1cb585febd84 to be called with the original opaque value.
- The signed integer returned by that dependency becomes the diagnostic’s length-like argument. No range check, clamping, or second normalization is visible.

2. A fixed diagnostic-format argument concerning a missing collation sequence.

The function performs fixed-offset address calculations but no visible length multiplication, buffer-size computation, or result-count arithmetic. ## Side effects

### Direct effects

No direct memory writes, allocation, deallocation, or ownership transfer are visible in F-039d16ce0621 itself.

Its direct memory reads are limited to:

- The reference slot.
- The working object’s mode byte.
- The three reads forming the additional-byte pointer chain.

The reference slot is not reread after the initial object-address load. Thus, if a dependency changes the slot, a later second resolver still receives the original object address. The diagnostic dependency, however, receives the slot’s address and may observe its then-current contents.

The function does not visibly release a first result that is replaced by a second result or abandoned after failure. This absence of a release call is not evidence of either a leak or retained caller ownership.
