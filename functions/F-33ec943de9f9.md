## Behavior

### Arithmetic and conversion rules

F-U001 through F-U069 are opaque, document-local call-site IDs. Different IDs do not prove different implementations.

The represented model uses signed and unsigned 32-bit integers and eight-bit bytes:

- Unsigned right shifts insert zeros.
- Unsigned multiplication, addition, and left shifts reduce modulo \(2^{32}\).
- Signed multiplication, left shifts, and address additions are not automatically modular.
- Converting an integer into an access address introduces separate mapping, alignment, permission, and pointer-interpretation requirements.

F-U045 and F-U057 provide unsigned 32-bit results. Index results and results used in signed shifts are represented as signed 32-bit integers. Uninterpreted forwarded results remain 32 bits.

Byte-source reads produce unsigned values from 0 through 255. Byte-store destinations use **plain character type**, whose signedness is not established. A conversion outside that type’s representable range is not established to truncate to eight bits. With a signed plain character type, such conversion may have an implementation-defined outcome.

For conditional byte-pattern descriptions below, the **modulo-preserving byte model** means that the platform’s character conversions and stored representation are established to produce the low eight bits of the converted value. This is an additional condition, not a conclusion from byte width.

Every phase requires the preceding calls and accesses to complete. No rollback is represented.

## Acceptance examples

These are conditional static-review examples, not executed tests. They assume valid execution, returning dependencies, completing conversions, and accessible addresses except where uncertainty is the subject.

3. **Retained value provenance.** If F-U023 returns 3 and F-U028 returns 5, the corresponding stores write 12 at `0x44`, then retained value 12 at `0x28`. The later stored value is not 20.

4. **Unsigned reduction.** Shift word `0x00010000` produces `0x2000` after the right shift. Multiplication by `0x80000` yields zero modulo \(2^{32}\). Signed conversion is exact, making the first byte-source integer 1.

5. **Signed-conversion boundary.** Shift word `0x00008000` produces unsigned product `0x80000000`. That product is established; its signed conversion and resulting address are **documented_only**.

Under the modulo-preserving byte model, the first character store has pattern `0xE0`. Without that model, this pattern is not guaranteed. The second extraction produces integer `0x23`, which is representable in either signed or unsigned eight-bit plain character type.

7. **Extraction exceeding one byte.** If F-U045 returns `0x30000000`, the second extraction produces `0x300` before character conversion. Its stored pattern is `0x00` under the modulo-preserving byte model; that pattern is not unconditional.

8. **Observable rereads.** If the first three source reads yield 2, 7, and 9, their destinations are `0x13`, `0x18`, and `0x1A`. Reusing the first loaded value violates the represented sequence.

9. **Two-stage character conversion.** If F-U057 returns 64, its initial character conversion is exact. Multiplication produces 256. Under the modulo-preserving byte model, assignment stores pattern `0x00`; the out-of-range assignment conversion must not be omitted.

10. **Loaded-byte argument.** If the third read yields `0xFE`, F-U058 receives 254, and the store destination is `0x10F`. The stored character does not replace the argument.

11. **Final-source wrap.** If F-U057 returns `0x20000006`, the fourth byte-source integer is `0x31`, using unsigned reduction. Character-conversion uncertainty does not change this source calculation.
