# F-ceefe1106140

## Purpose

The supplied static representation describes a long, apparently straight-line sequence of indirect calls, 8-bit and 32-bit memory accesses, and 32-bit bit manipulations. It does not establish a higher-level operation such as allocation, serialization, initialization, or device control.

The representation explicitly reports invalid instruction data and ends at an invalid-instruction termination marker. Consequently, this contract specifies the **conditional behavior of the represented sequence**, not a verified executable implementation. Its observations apply only where instruction recovery, calling conventions, memory accessibility, and dependency returns are valid.

The most prominent represented effects are:

- Copying low bytes of words into byte-addressed locations.
- Writing scaled, masked, or shifted dependency results into computed addresses.
- Using bytes read from memory as indices into the absolute address range `0x11`–`0x110`.
- Writing directly to absolute addresses `0x0D` and `0x11`.
- Passing derived values through numerous unknown dependencies.
- Reaching an invalid-instruction marker rather than a demonstrated normal return.

No domain-specific purpose is established.

## Behavior

### Reading the sequence

Opaque IDs `F-d001` through `F-d131` identify external **call occurrences**, in order. They do not assert that all targets are distinct functions. Target identity, aliasing between targets, and implementations are unavailable.

A range of calls described as taking “no explicit arguments” means that the representation supplies none; it does not prove that the actual dependencies consume no register or global inputs. Except where a result is named below, primary results are not visibly consumed by the represented continuation.

All arithmetic below is subject to the width qualifications in the interface.

### 1. Entry read and first indexed transfer

The function reads **InitialWord** from `M32(EntryBase + 0x74)`, then writes `byte(InitialWord)` to `M8(EntryBase + 1)` before calling any dependency.

The subsequent order is:

- `F-d001` receives InitialWord.
- `F-d002`, with no explicit arguments, supplies **FirstValue**.
- `F-d003` receives FirstValue and `InitialWord >> 2`.
- `F-d004` through `F-d007` have no explicit arguments; the last supplies **FirstIndex**.

The derived **FirstAddress** is four times FirstIndex. The function reads **CopiedWord** from `M32(FirstAddress + 0x74)`, then writes its low byte to `M8(FirstAddress + 1)`.

`F-d008` receives FirstAddress. Calls `F-d009` through `F-d012` follow without explicit arguments. Secondary result state associated with this boundary supplies **SecondaryIndex**.

The function writes CopiedWord to `M32(4 × SecondaryIndex + 0x14)`, then calls `F-d013` with SecondaryIndex.

CopiedWord remains the earlier captured word; this store does not reread its source after the intervening calls.

### 2. Entry-bit extraction and scaled storage

Define **EntrySlice** as `EntryBits >> 22`, an unsigned value in `0`–`1023`.

`F-d014` supplies **SecondValue**. `F-d015` receives:

1. SecondValue;
2. `(EntrySlice & 0x1FF) << 21`;
3. the same shifted value again.

Calls `F-d016` through `F-d019` follow without explicit arguments; the last supplies **SecondIndex**.

The function writes `word(EntrySlice << 23)` to `M32(4 × SecondIndex + 0x14)`. It calls `F-d020` with four times SecondIndex.

Calls `F-d021` through `F-d024` follow; the last supplies **Seed**. Before masking Seed, the function writes `word(4 × Seed)` to `M32(16 × Seed + 0x14)`.

Define:

- **MaskedSeed** as `Seed & 0x3FFFFFFF`;
- **SeedQuarter** as `MaskedSeed >> 2`;
- **SeedScale** as `word(4 × Seed)`.

`F-d025` receives MaskedSeed.

### 3. Root-derived word and byte writes

The function writes, in order:

1. `byte(RootEight)` to `M8(InitialWord + 1)`;
2. `word(BranchValue << 2)` to `M32(RootEight + 0x34)`.

`F-d035` receives `word(BranchValue << 2)`. `F-d036` supplies **ThirdValue**, which is passed to `F-d037`.

Calls `F-d038` through `F-d041` follow; the last produces a represented 64-bit result, **PairOne**.

The function then writes:

1. `byte(RootEight)` to `M8(BranchBase + 1)`;
2. PairOne’s high half to `M32(RootEight + 0x34)`.

Thus the second word write targets the same represented address as the earlier BranchValue-derived word. Intervening dependencies may observe or modify that address.

`F-d042` receives PairOne’s low half shifted left by two.

The function rereads `M8(ObjectBase + 1)`, then writes `byte((FinalValue & 0x3FFFFFFF) >> 20)` to that freshly indexed address plus `0x11`.

Calls `F-d118` through `F-d121` follow; the last supplies **TailIndex**. The function reads a byte from `M8(word(FinalScale × 0x400) + 1)` and writes zero to the indexed address plus `0x11`.

Calls `F-d123` through `F-d126` follow; the last supplies **LastIndex**. The function repeats the byte read at `word(FinalScale × 0x400) + 1` and the resulting indexed zero write. The byte is reread after the intervening calls.

`F-d127` receives `word(LastIndex << 2)`. Calls `F-d128` through `F-d131` follow without explicit arguments. The represented sequence then terminates at invalid instruction data.

## Side effects

The direct memory effects are exactly those ordered above, conditional on reaching each operation. No transactional behavior, rollback, synchronization, or error recovery is visible.

Important aliasing consequences:

- Different computed addresses may coincide.
- A byte store may affect a later 32-bit read, depending on address overlap and byte order.
- Repeated stores remain separately observable; intervening calls prevent treating them as redundant.
- Byte-indexed stores target `0x11` through `0x110`.
- The first BranchBase-derived indexed store can target `0x11` through `0x410`.
- The SmallIndex-derived store targets `7` through `0x406`.
- ByteBase is even and ranges from `0` through `510`.

These ranges do not establish that the accesses are valid. On a conventional protected process, low addresses may be inaccessible; in another memory map they could represent ordinary memory or mapped hardware. The supplied evidence does not select an environment.

There is no established allocation, release, ownership transfer, resource lifetime, or buffer capacity. Unknown dependencies may have such effects. Passing an address-like value does not prove that a dependency borrows or owns memory.

## Acceptance examples

These are conditional static acceptance examples, not executed tests.

1. **Initial byte truncation.** If InitialWord is `0x12345678`, the first represented store writes `0x78` at EntryBase plus one. `F-d001` receives the complete `0x12345678`, and `F-d003` later receives `0x048D159E` as its second explicit argument.

2. **Entry-slice width distinction.** If EntryBits is `0xFFFFFFFF`, EntrySlice is `0x3FF`. The duplicated shifted arguments to `F-d015` are each `0x3FE00000`. Under 32-bit shift-result truncation, the later EntrySlice-derived word store contains `0xFF800000`. These operations use different effective subsets of EntrySlice.

3. **Masking does not precede every use.** If Seed is `0xC0000001`, MaskedSeed is `1`, while SeedScale is `4` under 32-bit truncation. The earlier store address uses the original Seed scaled by sixteen, not the masked value.

4. **Captured versus reread byte.** If the first FrameBase byte read yields `2`, its indexed store targets `0x13`. If dependencies change that byte to `7` before the later capture, the zero write targets `0x18`, and ByteBase becomes `14`.

5. **Full word versus retained byte.** If RetainedValue is `0x12345678`, RetainedByte is `0xCF`, while the later full-word transfer stores `0x02468ACF`. The word transfer must not be reduced to the byte value.

6. **Low-address overwrite ordering.** The represented write of CapturedByte to absolute `0x0D` occurs before `F-d079`. The `0xC0` overwrite occurs after `F-d086` returns. Dependencies between those points may observe or change that address.

7. **Repeated final clears.** If the two final byte reads yield different indices, the two zero stores target different addresses. A conforming interpretation must retain both reads and both writes.

8. **Interrupted execution.** If a dependency does not return or an access faults, later operations are not established as occurring. No normal error result or rollback is specified.
