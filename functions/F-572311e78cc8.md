# F-572311e78cc8

## Purpose

F-572311e78cc8 derives two 32-bit output values from a packed input word and a context record. It rejects one selector value, otherwise obtains a base quantity, combines that quantity with context data, invokes F-d7be9cfb4000, and writes a final adjusted result.

The established behavior is numeric and memory-oriented. The source does not establish units, application-level meanings, or the semantic role of the dependency. Descriptions such as “base quantity,” “selector,” and “adjustment bit” identify observable roles, not inferred domain concepts.

The function has two visible normal return values:

- **3:** the packed selector is rejected; no context or output memory is accessed.
- **0:** both output stores and the dependency call have completed.

There is no visible validation or recovery for invalid addresses, invalid table selection, arithmetic problems, or dependency failure.

## Behavior

### 1. Selector extraction and immediate rejection

The selector is the value of bits 12–15 of the packed word, ranging from 0 through 15.

If it is 15, the function immediately returns 3:

- No context field is read.
- No table base or table element is read.
- Neither output address is dereferenced.
- F-d7be9cfb4000 is not called.

Bit 9 and the remaining input bits cannot override this rejection.

### 2. Base-quantity selection

For selector zero, the base quantity is the constant **128,000**. This path does not read the table-selection byte, the table-addressing field, or either global table base.

For selectors 1 through 14:

1. The function reads the global base for the nonzero-byte table.
2. It reads the context byte at +0x30.
3. If that byte is zero, it instead reads and uses the other global table base.
4. It reads the signed 32-bit field at +0x34 for table addressing.
5. It reads one 32-bit table element and multiplies that element by 1,000.

For a mathematical value \(r\) read from +0x34 and selector \(s\), the table element’s byte displacement from the selected base is:

\[
60r + 4s - 60.
\]

This formula describes the address calculation when the intermediate arithmetic is representable and the resulting address is valid. It does not establish a permitted range for \(r\), table dimensions, or behavior for overflowing address arithmetic.

The stride is 60 bytes, equivalent to fifteen 32-bit elements. That structure is suggested by the addressing calculation; no independently validated table schema is supplied.

The context byte is tested only for zero versus nonzero. Values such as 1 and 255 select the same base.

### 3. First output store and adjustment extraction

The function writes the selected base quantity to the first output address.

It then derives an adjustment from bit 9 of the packed input:

- Bit 9 clear: adjustment is 0.
- Bit 9 set: adjustment is 1.

This extraction depends on shifting a 32-bit value and interpreting the resulting sign bit through a signed right shift. Under the arithmetic right-shift interpretation expressed by the supplied source, no other packed-input bit contributes to this adjustment.

### 4. Intermediate product

After the first store, the function reads the first output value back from memory. It also reads the unsigned 32-bit context field at +0x24 and shifts that field right by three.

Thus, for ordinary unsigned values, the context-derived multiplier is:

\[
\left\lfloor \frac{\text{field at +0x24}}{8} \right\rfloor,
\]

with a range of 0 through 536,870,911.

The function multiplies that quantity by the reread first output value. Because the context-derived factor is unsigned, the visible expression performs a 32-bit unsigned multiplication before the product is held with a signed interpretation. The retained product bit pattern is the low 32 bits.

The first output is genuinely reread; the contract must not replace this with an assumption that the previously calculated quantity remains unchanged in memory. In particular, aliasing with context storage can affect subsequent reads.

The relative evaluation order between the first-output read and the +0x24 read is not established by the supplied expression. Both occur after the first output store and before the following branch test.

### 5. Scaling decision and dependency invocation

The function reads the signed 32-bit context field at +0x34 again.

- If this read equals exactly 1, final scaling by four is selected.
- Otherwise, no final scaling is selected.

This is a separate read from the one used for table addressing. On the selector-zero path, it is the first read of +0x34. If earlier output writes alias this field, the scaling decision can differ from the value used during table lookup.

The function reads the 32-bit context field at +0x18 and invokes F-d7be9cfb4000 with:

1. The 32-bit intermediate product.
2. The 32-bit value read from +0x18.

There is one dependency invocation on every path that reaches normal completion. The branch does not select a different dependency; it selects the arithmetic performed after that dependency returns.

The dependency’s returned 32-bit value is interpreted as signed for the following operations.

### 6. Final adjustment, second store, and return

After the dependency returns:

- Add the saved zero-or-one adjustment to its result.
- If the earlier +0x34 branch test selected scaling, multiply that sum by four.
- Write the resulting 32-bit value to the second output address.
- Return 0.

The addition precedes the multiplication. In the scaling branch, setting bit 9 therefore changes the final mathematical result by four, not by one, provided the relevant signed arithmetic remains representable.

There are no further context reads in this caller after the dependency returns. Consequently, dependency changes to context fields do not retroactively change the already-selected branch or the saved adjustment. Dependency changes to output memory can still be observable, subject to the final second-output store.
