# F-eb0844e8e085

## Purpose

F-eb0844e8e085 searches a descriptor structure for a target, accumulates a candidate object address, and records conflicts between results.

Two branches are selected through dependency-mediated classification:

- A **single-link branch** either searches a linked descriptor or attempts to accept the current object.
- A **collection branch** visits eight-byte entries, computes child object addresses, and either accepts a child or recursively searches its descriptor.

The apparent purpose is ambiguity detection across inheritance-like paths. That interpretation is inferred; neither the descriptor domain nor the dependencies’ semantic contracts is established.

The function returns a 32-bit value explicitly set to zero or one. One indicates an accepted result under the executed checks, not necessarily a nonzero candidate. Zero does not imply unchanged outputs or cleared state.

## Interface

### Arguments

The ten arguments occur in this order:

| Argument | Width and role |
|---|---|
| Object address | Nullable 32-bit address used to calculate child addresses. |
| Candidate slot | Address of a readable/writable 32-bit candidate address. Zero means no existing candidate for candidate-conflict checks. |
| Current descriptor | 32-bit address of the descriptor being examined. |
| Target descriptor | 32-bit descriptor address or identity used in exact and dependency-mediated comparisons. |
| Search policy | Unsigned 32-bit value; only bits 0 and 1 are explicitly examined. |
| Conflict slot | Address of a readable/writable 32-bit integer. Any nonzero value counts as conflict. |
| Path eligibility | Unsigned 32-bit value carried through the search. |
| Identity slot | Address of a readable/writable 32-bit value used when merging recursive collection results. |
| Match-kind slot | Address of readable/writable byte-sized storage. Values zero, one, and two receive explicit treatment. |
| Eligibility slot | Address of readable/writable unsigned 32-bit storage holding result eligibility. |

The function does not validate pointer accessibility, storage sizes, recursion depth, or collection bounds.

### Descriptor layout

The supplied representation establishes these byte offsets and widths:

| Location | Meaning |
|---|---|
| Descriptor + 8 | 32-bit linked-descriptor address, used by the single-link branch. |
| Descriptor + 12 | 32-bit signed entry count, used by the collection branch. |
| Descriptor + 16 | Beginning of the collection entries. |
| Entry + 0 | 32-bit child-descriptor address. |
| Entry + 4 | 32-bit packed metadata. |

Entries have an eight-byte stride. Metadata contains:

- Bit 0: indirect-address selection.
- Bit 1: eligibility propagation.
- Bits 8–31: signed displacement.
- Bits 2–7: not explicitly tested.

The displacement is obtained by interpreting the metadata as signed 32-bit and arithmetically shifting right by eight. Its range is −8,388,608 through 8,388,607.

Two **distinct global storage locations** supply category-comparison operands. Their stored values are not established as distinct, immutable, or safe to cache across calls.

### Preconditions and ownership

Ordinary execution requires accessible storage for every actual read and write, valid object-relative lookups, representable collection bounds, and terminating recursion within available stack resources.

No allocation, release, or ownership transfer is explicit in this function. Caller-provided storage remains externally supplied; dependency ownership behavior is unknown.

Supported behavior for overlapping slots, overlap with descriptors, concurrent mutation, invalid addresses, arithmetic overflow, and cyclic descriptors is not established. These conditions are documented_only rather than validated or silently assigned safe behavior.

## Behavior

### Classification and global-read timing

The function first calls F-e3253cb77678 with the current descriptor. **After that call returns**, it reads the value from the first category-global location and supplies that value, together with the classifier result, to F-061c2693b838.

A nonzero predicate result selects the single-link branch. No second classification or second-category-global read occurs on this path.

Only when the first predicate returns zero does the function:

1. Call F-e3253cb77678 again with the current descriptor.
2. Read the second category-global value after this second classifier call.
3. Call F-061c2693b838 with the new classifier result and that newly read value.

A nonzero second predicate selects the collection branch. Otherwise the function returns zero without explicit writes to the five output slots.

These are separate classifier calls and separately timed global reads. A classifier or predicate may mutate either global; the function does not establish a common snapshot.

### Single-link search

The linked descriptor at offset 8 is read and compared with the target.

If unequal, F-f4ffd1965bfa is invoked twice in order. The first invocation has no explicit argument in the supplied representation; the second explicitly receives the target. Their 32-bit results are compared.

If those results differ, the linked descriptor is **read again after both calls** and used for recursive search. All other arguments are passed through unchanged.

- Recursive zero returns zero immediately.
- Recursive nonzero is followed by a conflict-slot read. Zero conflict produces one; nonzero conflict produces zero.

If the initial descriptor comparison succeeds, or the two dependency results are equal, the function instead attempts acceptance of the current object.

Acceptance requires:

- Candidate zero or equal to the current object address.
- Match kind not equal to two.
- Conflict zero.

The checks are short-circuited in that order. The candidate may be read again to test equality when its first observed value was nonzero.

On acceptance, writes occur in this order:

1. Match kind becomes one.
2. Eligibility receives the full incoming 32-bit path-eligibility value.
3. Candidate receives the current object address.

The function returns one. Identity is not explicitly written.

On rejection, conflict is written as one, then candidate as zero, and the function returns zero. Match kind, identity, and eligibility are not explicitly reset.

### Collection bounds and traversal

After collection classification succeeds, the function derives two early-return permissions from policy bits 0 and 1. A clear bit permits early return for the corresponding entry-addressing category.

Traversal begins at descriptor offset 16. At each iteration’s bound check, the count at descriptor offset 12 is read again. The calculated end address is the descriptor address plus 16 plus eight times that count. The function returns its accumulated success indication when the current entry address is at or beyond this end.

The accumulator begins at zero. Successful acceptance or merge sets it to one; later conflicts can still return zero. Otherwise traversal advances by eight bytes.

For a valid ordinary layout, a zero count returns zero without reading entry contents. The count is not captured once for the entire traversal. Overflow and invalid pointer-ordering cases have no established portable outcome.

### Initial entry snapshot and child-address calculation

For each visited entry, the function first captures its metadata word. Three later decisions use this **initial captured metadata**:

- Child-address calculation.
- Normalized child eligibility.
- Selection of the policy bit for early return.

If the incoming object address is zero, the child address is zero. Neither an object-header read nor an indirect-adjustment read occurs.

For a nonzero object:

- With captured bit 0 clear, child address is the object address plus the captured signed displacement.
- With captured bit 0 set, the function first reads a 32-bit address from the beginning of the object. It then reads a signed 32-bit adjustment at that address plus the captured displacement, and adds the adjustment to the original object address.

There are no bounds checks. These reads precede descriptor matching, so an entry that ultimately does not match can still trigger indirect memory accesses.

Child eligibility is normalized to zero or one. It is one exactly when incoming path eligibility is nonzero and captured metadata bit 1 is set.

### Matching an entry

After computing the child address and eligibility, the function reads the entry’s child descriptor and compares it with the target.

Exact equality selects direct acceptance without the paired F-f4ffd1965bfa calls. Otherwise those calls occur in the same order as in the single-link branch: first without an explicit argument, then with the target.

Equal returned values select direct acceptance. Unequal returned values select recursive search.

The initially compared child descriptor is not necessarily the descriptor later passed to recursion.

### Direct collection acceptance

Direct acceptance checks:

1. Whether a nonzero candidate differs from the previously computed child address.
2. If necessary, whether a **fresh entry-metadata read** has bit 0 set while the existing match kind is one.
3. If necessary, whether conflict is nonzero.

The checks short-circuit. Rejection writes conflict one, then candidate zero, and returns zero.

On acceptance, the function reads entry metadata **again** to select the new match kind: one if that read’s bit 0 is clear, two if set. Writes then occur in this order:

1. Selected match kind.
2. Child eligibility computed from the initial metadata.
3. Child address computed from the initial metadata.

Identity is not explicitly written.

Thus address calculation, rejection, kind assignment, and early-return selection need not observe the same indirect flag. In particular, dependency calls between the initial metadata capture and acceptance can change the rejection and assignment observations without changing the already computed address or eligibility.

With stable metadata, the rule is asymmetric: an indirect entry rejects an existing kind-one result, but a direct entry does not reject an existing kind-two result solely because of that kind.

### Recursive collection search

Before recursion, the function initializes a 32-bit temporary identity to zero and then a separate 32-bit temporary kind-storage word to zero.

The recursive call receives:

- The previously computed child address.
- Shared candidate and conflict slots.
- A **fresh child-descriptor read after the comparison calls**.
- Unchanged target and policy.
- Previously normalized child eligibility.
- Addresses of the temporary identity and temporary kind storage.
- The shared eligibility slot.

The kind-storage address is supplied as byte-addressed match-kind storage. Its interpretation after recursion is addressed below.

Following recursive zero, the function reads conflict. Nonzero conflict returns zero; otherwise traversal continues without a successful-result merge.

Following recursive nonzero, conflict is likewise read first. Nonzero conflict returns zero immediately.

If conflict is zero, identity fallback is evaluated:

- Only if temporary identity is zero does the function reread the enclosing entry’s metadata.
- If this fresh metadata read has bit 0 set, it rereads the entry’s child descriptor and stores that descriptor as temporary identity.

These observations occur after recursion. They need not match either the initial entry observations or the descriptor actually passed to recursion.

### Recursive kind conversion and merge

After recursion, the function converts the **entire 32-bit temporary kind-storage value** to a character-sized value. It does not explicitly reload only the byte at the storage’s starting address.

This converted value is used for kind compatibility and, on acceptance, written to the caller’s match-kind byte.

A merge conflicts exactly when all of these hold:

- Caller match kind is nonzero.
- Converted recursive kind and caller kind are not both two.
- Caller identity is zero or differs from the final temporary identity.

These conditions short-circuit; caller kind and identity can be read more than once.

Merge rejection writes only conflict one and returns zero. It does not explicitly clear candidate or restore recursive changes.

A compatible merge writes:

1. Converted recursive kind to the caller’s match-kind byte.
2. Temporary identity to the caller’s identity slot.

The success accumulator becomes one. Candidate and eligibility retain the recursive call’s effects.

The conversion is not unconditionally equivalent to taking the byte written by recursion. On a little-endian representation, if only the starting byte was changed and the remaining bytes stayed zero, written values one and two produce the corresponding whole-word values. On a big-endian representation, the same starting-byte writes produce whole-word values 0x01000000 and 0x02000000 instead. Under low-eight-bit narrowing, those would convert to zero. Target byte order and the applicable out-of-range character-conversion rule are not supplied.

### Early-success policy

After direct acceptance or a compatible recursive merge, the success accumulator becomes one and the function reads the shared eligibility slot.

If eligibility is zero, traversal continues.

If eligibility is nonzero:

- Captured initial bit 0 clear selects policy bit 0.
- Captured initial bit 0 set selects policy bit 1.
- A clear selected policy bit returns one immediately.
- A set selected policy bit continues traversal.

Policy bits suppress early return; they do not exclude matching entries.

For recursive results, eligibility comes from shared storage after recursion, while the policy selector still comes from the enclosing entry’s initial metadata—not its later rereads or the merged match kind.

## Side effects

Explicit caller-state writes affect five slots:

| Slot | Explicit effects |
|---|---|
| Candidate | Accepted address; zero on single-link or direct-entry rejection; potentially retained on merge conflict. |
| Conflict | One on detected conflict; never explicitly cleared. |
| Identity | Updated on compatible recursive collection merge. |
| Match kind | One, two, or the converted recursive temporary-word value. |
| Eligibility | Full incoming eligibility for single-link acceptance; normalized initial-entry eligibility for direct collection acceptance; recursive effects otherwise. |

There is no rollback. A failure can preserve earlier successful writes, recursive writes, or an existing nonzero conflict value.

Read/write order matters if storage overlaps. The logical slot descriptions do not establish independent storage, and no supported aliasing contract is supplied.

Dependencies may mutate descriptors, globals, or reachable state, allocate or release memory, or have other effects. Their contracts are unknown. The explicit rereads described above must not be replaced conceptually with cached observations.

## Acceptance examples

These examples assume valid accessible memory and the stated dependency behavior. Unless mutation is part of the example, relevant storage remains stable.

1. **Unrecognized descriptor.** Both category predicates return zero. Return is zero, with no explicit output-slot writes by this invocation.

2. **Category-global mutation.** The first classifier changes the first category-global value. The first predicate receives that changed value, not a value captured before classification. If it returns zero, the second classifier runs before the second global is read.

3. **Single-link eligibility width.** Direct acceptance is reached with candidate zero, kind zero, conflict zero, and incoming eligibility seven. Return is one; writes are kind one, eligibility seven, then the object address.

4. **Single-link kind conflict.** Candidate equals the object address, but kind is two. Conflict becomes one, candidate becomes zero, and return is zero.

5. **Null object success.** A collection entry matches with object zero, candidate zero, conflict zero, and no kind incompatibility. No object-relative lookup occurs. Candidate can remain zero while the function returns one.

6. **Negative displacement.** A stable direct entry encodes −4 and matches. For valid arithmetic and memory, the accepted child address is four bytes before the object address.

7. **Changed metadata after address calculation.** Initial metadata is direct and eligible. Comparison calls select direct acceptance but change metadata to indirect. With candidate zero, kind zero, and conflict zero, acceptance can store kind two while retaining the direct-address calculation. If policy is two, early return uses clear bit 0 from the initial direct classification, not set bit 1.

8. **Changed recursive descriptor.** The initially compared child descriptor does not match. Comparison results differ, and those calls replace the entry’s child descriptor. Recursion receives the replacement descriptor read after the calls.

9. **Post-recursion identity fallback.** Recursion succeeds with zero temporary identity and no conflict. If the enclosing metadata now reads indirect, fallback uses the child descriptor read at that later time.

10. **Policy exposes later conflict.** A first eligible direct entry succeeds. Clear policy bit 0 returns one immediately. Set bit 0 continues, allowing a later incompatible candidate to set conflict and return zero.

11. **Merge conflict preserves candidate.** Recursion succeeds and leaves a candidate. Caller kind is nonzero, the kinds are not both two, and caller identity is zero. Merge writes conflict one and returns zero without explicitly clearing candidate.

12. **Byte-order-dependent recursive kind.** Recursion writes two only to the temporary word’s starting byte. With little-endian storage and other bytes zero, the converted kind is two. With big-endian storage and low-eight-bit narrowing, it is zero. The two executions can therefore take different compatibility paths.
