# F-359c673cd26d

## Purpose

F-359c673cd26d constructs a two-block result from two 32-bit input values and publishes a reference to that result through a caller-supplied output location.

The constructed result consists of:

- A 32-byte payload containing zero-filled regions, a fixed byte, and bytewise transformations of the two inputs.
- A 12-byte descriptor containing the payload address, a sampled 32-bit global value, and a zero field.

The function returns a 32-bit status. Its normal construction path returns zero. Other paths return values read from global status locations.

**Established static evidence:** the supplied representation establishes the requested block sizes, conditional calls, byte transformations, descriptor layout, publication order, and status-selection behavior.

**Inferred intent:** the dependencies appear to provide allocation and release services, and the descriptor appears to associate a payload with existing state. Their actual contracts are unavailable. These interpretations do not establish ownership, allocation guarantees, or the meaning of the global values.

## Interface

### Inputs

The function accepts three arguments:

1. **First input word:** a 32-bit value. Every bit contributes to the payload through four independently transformed bytes.
2. **Second input word:** another 32-bit value, transformed identically.
3. **Output location:** either a null pointer or the address of storage to receive one 32-bit descriptor reference.

The first two arguments are treated as unsigned 32-bit bit patterns for byte extraction. No signed numerical interpretation is required.

A null output location is handled explicitly. A non-null output location is not otherwise validated. In particular, the function does not establish that it is writable, correctly aligned, or separate from other relevant storage.

### Output and return value

The return value is 32 bits wide.

On normal completion of the construction path:

- The output location receives the address of the 12-byte descriptor.
- The function returns zero.

On paths that do not reach publication:

- There is no direct write to the output location by this function.
- The return value comes from one of two global 32-bit status locations.

For this contract, those locations are called:

- **Null-output status:** used when the output location is null.
- **Construction-failure status:** sampled after the first resource request and, on a later failure path, sampled again after the release-like call.

A third global 32-bit location, called the **association value**, supplies the descriptor’s middle field.

These labels describe use, not established application meaning. The static evidence does not establish that either status location contains a nonzero value. Consequently, a zero return alone does not prove that construction occurred.

### Preconditions for normal completion

For the successful path to complete without a memory fault:

- The first dependency result must designate at least 32 writable bytes.
- The second dependency result must designate at least 12 writable bytes.
- The output location must support the final 32-bit reference write.
- The relevant global locations must be readable.
- The referenced storage must remain usable through all intervening calls and writes.
- The target must support the represented 32-bit address and field operations.

The function does not check these conditions beyond the explicit zero-result checks described below.

## Behavior

### 1. Null output location

If the output location is null:

- The function reads the null-output status.
- It returns that value.
- Neither dependency is called.
- No payload, descriptor, or output-location write is performed.

The first two input words do not affect this path.

### 2. First resource request

For a non-null output location, the function calls F-d33f6d597e5d with a size argument of 32.

After that call returns, the function reads the construction-failure status. This read occurs even if the returned resource reference is nonzero and construction later succeeds.

If the first result is zero:

- The function returns the construction-failure status already sampled.
- It does not make the second resource request.
- It does not call F-5e3309c9d083.
- It makes no direct write to the output location.

Because the status is read after the dependency returns, changes made by that dependency can affect the returned value.

### 3. Second resource request

If the first result is nonzero, the function calls F-d33f6d597e5d again, this time with a size argument of 12.

The supplied representation uses an unusual comparison-and-arithmetic expression to classify this second result. Under its represented flat, unsigned 32-bit address ordering, the expression accepts every nonzero address:

- Address zero is rejected.
- Address one is accepted.
- Addresses greater than one are accepted.

Thus, the acceptance condition is not an address-range, alignment, or accessibility check. The actual machine-level interpretation of this recovered pointer comparison remains documented_only.

If the second result is rejected:

1. The function calls F-5e3309c9d083 with the first result.
2. After that call returns, it reads the construction-failure status again.
3. It returns this newer value.

The earlier status sample does not determine this branch’s final return value. A change to the status location during either the second request or the release-like call can therefore affect the result.

On this branch, the function performs no direct payload initialization, descriptor initialization, or output publication.

### 4. Payload initialization

If both resource results are accepted, the function initializes the first block.

The direct writes occur in this order:

1. Thirty-two one-byte zero writes, in increasing offset order from 0 through 31.
2. Three additional zero-byte writes at offsets 12, 13, and 14, in that order.
3. A byte value of 12 at offset 15.
4. Four transformed bytes from the first input at offsets 16 through 19.
5. Four transformed bytes from the second input at offsets 20 through 23.

The repeated zero writes at offsets 12 through 14 are part of the represented write sequence, even though they do not change the final ordinary-memory contents.

The resulting 32-byte payload layout is:

| Byte offsets | Width | Final contents |
|---|---:|---|
| 0–11 | 12 bytes | Zero |
| 12–14 | 3 bytes | Zero |
| 15 | 1 byte | `0x0C` |
| 16–19 | 4 bytes | Transformed first input, most-significant input byte first |
| 20–23 | 4 bytes | Transformed second input, most-significant input byte first |
| 24–31 | 8 bytes | Zero |

### 5. Input-byte transformation

Each input word is divided into four bytes, starting with bits 31–24 and ending with bits 7–0.

Each byte is independently multiplied by −89, with only the low eight bits retained. Equivalently, the stored byte is:

\[
T(b) = (167b) \bmod 256
\]

There is no carry between adjacent bytes. The operation is not a multiplication of the complete 32-bit input word.

Interpreting an extracted byte as signed or unsigned does not change its final low-eight-bit result. The payload’s byte order is established by the individual byte writes and does not depend on native endianness.

### 6. Descriptor initialization and publication

After all payload writes, the function reads the association value.

It then performs three 32-bit descriptor writes in order:

| Descriptor offset | Width | Value |
|---|---:|---|
| 0 | 4 bytes | Address of the 32-byte payload |
| 4 | 4 bytes | Association value sampled after payload initialization |
| 8 | 4 bytes | Zero |

These are native 32-bit field stores. The supplied evidence does not establish their byte order in memory.

After all three descriptor fields have been written, the function writes the descriptor address to the caller’s output location and returns zero.

The association value is sampled after both dependency calls and after payload initialization. It is not captured at function entry. The function therefore does not require either dependency to preserve that global value.

The function performs no direct global writes. Aliasing can nevertheless make a payload, descriptor, or output write affect a global location.

## Side effects

### Dependency calls

The possible dependency-call sequences are:

| Condition | Call sequence |
|---|---|
| Null output location | No calls |
| First request returns zero | F-d33f6d597e5d with 32 |
| First accepted, second rejected | F-d33f6d597e5d with 32; F-d33f6d597e5d with 12; F-5e3309c9d083 with the first result |
| Both accepted | F-d33f6d597e5d with 32; F-d33f6d597e5d with 12 |

The dependencies’ internal reads, writes, callbacks, resource changes, and failure mechanisms are unknown.

### Memory publication and ownership

On the normal successful path, the function leaves both returned blocks unreleased and publishes only the descriptor reference. The payload is reachable through its first field.

This establishes a reference relationship, not an ownership policy. The evidence does not establish:

- Whether either block is newly allocated.
- Whether the blocks are independent.
- Whether ownership transfers to the caller.
- Whether the association value is a borrowed reference, owned reference, integer, or other state.
- Which operation must eventually dispose of a successfully published result.

On second-request failure, the function passes the first result to F-5e3309c9d083. It does not establish that this call actually releases memory.

### Aliasing and partial completion

The described final layouts assume non-overlapping, ordinary writable storage.

If either block overlaps the other block, the output location, or a global location, later writes can overwrite earlier data or alter a subsequently sampled global value. No protective copy or overlap check is present.

The publication write is the last direct memory write, but no synchronization primitive, atomic-publication guarantee, or concurrency protocol is established.

There is no represented recovery path for an invalid nonzero resource reference, an invalid output location, a memory fault, or a dependency that does not return. A fault during initialization can leave partially written storage.

A consumer cannot infer successful publication from the return value alone unless an external contract guarantees suitable nonzero failure statuses.
