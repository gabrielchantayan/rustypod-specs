# F-3afbc7e59533

## Purpose

F-3afbc7e59533 describes a partially recovered operation that interleaves 30 indirect calls with one word-sized memory write and four byte-sized memory writes. The byte destinations are selected by reading bytes from computed addresses. Two call results supply the data used in those byte writes.

The available static evidence does not establish an application-level purpose. In particular, it does not establish that these accesses represent a device protocol, a serializer, a table update, or ordinary object storage.

The visible sequence ends at an invalid-instruction boundary. Normal completion, recovery, and behavior beyond that boundary are not established. This contract therefore specifies the visible prefix and its conditional behavior, not a guaranteed successful invocation.

## Interface

### Explicit and implicit inputs

The recovered interface has no explicit parameters and no declared return value. It nevertheless depends on entry context and external state:

- **Entry context word:** an incoming value used both as the payload of the first memory write and as the basis of an address calculation.
- **Entry link state:** an incoming value used to calculate the target of the first indirect call.
- **Call results:** selected indirect calls return values subsequently used as data, addresses, or arguments.
- **Memory:** four byte reads supply destination selectors.
- **Execution environment:** the indirect-call targets and computed memory addresses must be executable or accessible as appropriate for execution to continue.

The entry context word and entry link state are not formal parameters established by the recovered signature. Their calling convention and valid ranges are unknown.

### Widths and interpretation

The visible representation distinguishes:

- Unsigned 8-bit byte reads.
- 8-bit byte writes.
- A signed integer category used for several address calculations and intermediate call results.
- An unsigned integer category used for the two principal data results.
- A four-byte uninterpreted result passed between pairs of calls.

A 32-bit integer and address model is consistent with this representation and is used below to explain bit fields. The supplied material does not independently establish the complete target ABI, pointer width, endianness, or signed-overflow semantics. Wraparound-dependent cases are therefore not unconditional requirements.

Byte writes retain only the low eight bits of their calculated values. The first memory write is word-sized in the recovered representation; its byte order is unspecified.

### Outputs and completion

There is no established returned value or status code.

Observable outputs consist of:

1. The direct memory writes described below.
2. The arguments and ordering of the indirect calls.
3. Any effects performed by those callees, which remain unknown.
4. The terminal invalid-instruction boundary, if execution reaches it.

There is no visible allocation, deallocation, ownership transfer, or explicit resource-release operation. That observation does not constrain what the unknown callees may do.

## Behavior

### Dependency notation

The opaque dependency IDs F-D01 through F-D30 identify call positions in this contract. They are analytical labels, not recovered symbols or proof of distinct function identities. Multiple positions could ultimately resolve to the same implementation.

All ordering below is conditional on each preceding call returning and each preceding memory operation completing. No dependency is assumed to preserve global state, memory, resources, or execution context beyond what the visible continuation itself requires.

### Initial call and word write

1. Invoke F-D01 through a target derived from entry link state plus 4,094 address units. No explicit argument is shown.
2. Interpret its result as the integer used to select a word destination.
3. Write the entry context word to the address obtained by multiplying that result by four and adding 20.
4. Invoke F-D02 with the result multiplied by four, without the additional 20.
5. Invoke F-D03, F-D04, and F-D05, in that order, with no explicit arguments shown.
6. Invoke F-D06 and retain its unsigned result as the **first data word**.

The word write precedes F-D02. There is no visible range check, alignment check, null check, or validation of the F-D01 result.

Multiplication and addition here use the recovered integer operations. For inputs that overflow their signed intermediate representation, the supplied evidence does not establish a portable arithmetic interpretation.

### First byte write and first forwarding pair

Form the **context-derived base** by multiplying the entry context word by 524,288.

Then perform these operations in order:

1. Read an unsigned byte from the context-derived base plus one.
2. Zero-extend that selector byte and add 17 to obtain the destination address.
3. Write the low eight bits of the first data word shifted left by two to that destination.
4. Invoke F-D07 with the first data word shifted left by two as the full integer argument.
5. Invoke F-D08 and retain its four-byte result.
6. Invoke F-D09 with that result.
7. Invoke F-D10, F-D11, and F-D12, in order.
8. Invoke F-D13 and retain its integer result.

The stored byte and the F-D07 argument differ in width. The memory write truncates to eight bits; the call receives the full shifted word under the working 32-bit model.

The selector is an unsigned byte, not a pointer-sized value loaded from memory. Consequently, the destination selected by this read is numerically between 17 and 272 inclusive.

### Second byte write

After F-D13 returns:

1. Read a fresh unsigned byte from the context-derived base plus one.
2. Add 17 to that newly read selector to obtain the destination.
3. Mask the first data word to its low 30 bits, shift the masked value right by 20, and store its low eight bits at the destination.
4. Invoke F-D14 with the F-D13 result shifted left by two.
5. Invoke F-D15, F-D16, and F-D17, in order.
6. Invoke F-D18 and retain its unsigned result as the **second data word**.

The second selector read is not replaced by the earlier selector. Intervening callees, or the first byte write itself when addresses alias, may have changed that memory.

The value written in this phase is exactly bits 20 through 27 of the first data word. Although the mask retains bits 28 and 29 before the right shift, those bits are discarded by the final byte truncation.

The first data word remains the source of this write. The F-D13 result is used only for the subsequent shifted call argument in the visible sequence.

### Third byte write and second forwarding pair

After F-D18 returns:

1. Read an unsigned byte from the context-derived base plus one again.
2. Retain this selector for both the destination calculation and the next call argument.
3. Write four times the low byte of the second data word, truncated to eight bits, at the selector plus 17.
4. Invoke F-D19 with the retained selector zero-extended to an unsigned integer.
5. Invoke F-D20 and retain its four-byte result.
6. Invoke F-D21 with that result.
7. Invoke F-D22, F-D23, and F-D24, in order.
8. Invoke F-D25 and retain its integer result.

For the stored byte, multiplying the low byte by four and truncating is equivalent to taking the low eight bits of the second data word shifted left by two.

F-D19 receives the selector, not the second data word, the calculated destination, or the stored byte. The selector is not reread after the store. This distinction matters when the destination aliases the selector’s source address.

### Fourth byte write and terminal calls

After F-D25 returns:

1. Multiply the second data word by eight and add one to obtain a new selector-source address.
2. Read an unsigned byte from that address.
3. Add 17 to the selector to obtain the destination.
4. Mask the second data word to its low 30 bits, shift right by 20, and store the low eight bits at that destination.
5. Invoke F-D26 with the F-D25 result shifted left by two.
6. Invoke F-D27, F-D28, F-D29, and F-D30, in order.
7. Reach the reported invalid-instruction boundary.

This final selector source is derived from the second data word, not from the entry context word. Its write value is bits 20 through 27 of the second data word.

Under the working 32-bit unsigned model, multiplying the second data word by eight and adding one is modular arithmetic. Whether the resulting address is mapped or usable is a separate environmental condition.

The signed left shifts used for the F-D14 and F-D26 arguments are not assigned portable behavior for negative operands or signed-overflow cases by this contract.

## Side effects

### Direct memory access order

Excluding all accesses made inside dependencies, the visible memory sequence is:

| Order | Access |
|---|---|
| 1 | Write the entry context word to the word destination derived from F-D01 |
| 2 | Read a selector at the context-derived base plus one |
| 3 | Write the first data word’s low shifted byte at selector plus 17 |
| 4 | Reread a selector at the context-derived base plus one |
| 5 | Write bits 20–27 of the first data word at selector plus 17 |
| 6 | Reread a selector at the context-derived base plus one |
| 7 | Write the second data word’s low shifted byte at selector plus 17 |
| 8 | Read a selector at eight times the second data word plus one |
| 9 | Write bits 20–27 of the second data word at selector plus 17 |

Calls separate these accesses as specified in the behavior section. The table does not imply that they are consecutive machine-level operations.

### Aliasing and persistence

All four byte destinations fall within the numeric range 17–272. They may coincide with each other, a selector source, or other accessible state.

There is no visible preservation or restoration of overwritten contents. If a write changes a later selector source, the later read observes the changed value unless another actor changes it first.

No transactional boundary or rollback is visible. If execution stops midway, earlier effects are not visibly undone. Unknown dependencies may add further persistent effects.

No explicit error branch, retry, synchronization mechanism, or cleanup path is shown. Fault handling by the surrounding environment is undocumented.

## Acceptance examples

These examples are conditional static consequences, not executed tests. Each assumes the relevant addresses are accessible, preceding calls return, and arithmetic stays within the stated interpretation.

### Initial word placement

If F-D01 returns 3:

- The initial word destination is address 32.
- The stored word is the entry context word.
- F-D02 receives 12.
- The write occurs before F-D02 is invoked.

This example does not specify the byte order of the stored word.

### First data word: byte versus full argument

If the first data word is 0x12345678 and the first selector is 0x20:

- The first byte destination is 0x31.
- The stored byte is 0xE0.
- F-D07 receives 0x48D159E0 under the working 32-bit interpretation.

If the next selector is also 0x20, the second byte write targets 0x31 and stores 0x23, overwriting the earlier 0xE0.

### Selector changes between reads

If the first selector is 0x20, but an intervening dependency changes the selector-source byte to 0x40 before the second read:

- The first destination is 0x31.
- The second destination is 0x51.

Caching the initial selector for both writes would violate the visible behavior.

### Retained selector passed to F-D19

Suppose the third selector is 0x40 and the second data word is 0x00123003:

- The third destination is 0x51.
- The stored byte is 0x0C.
- F-D19 receives 0x40.

Neither 0x51 nor 0x0C is the required visible argument to F-D19.

### Final selector uses a different base

For the same second data word, the final selector-source address is 0x00918019.

If that address contains 0x7F:

- The final destination is 0x90.
- The final stored byte is 0x01.

The selector byte at the context-derived base does not determine this final destination.

### Aliasing affects later reads

Suppose the entry context word is zero, so the first three selector reads use address 1. If the initial word write begins at address 0, its word-sized footprint includes address 1 under the working four-byte model.

The later selector must reflect the memory state after that write and intervening calls. An implementation may not treat the selector as an immutable entry-time input. Its exact value in this example depends on byte order and subsequent effects.

### Interrupted execution

If F-D08 does not return, the visible prefix has already performed the initial word write, the first byte write, and the F-D07 call. No later direct write is required, and no rollback is established.
