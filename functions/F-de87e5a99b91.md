# F-de87e5a99b91

## Purpose

F-de87e5a99b91 performs an ordered transformation of global and indirectly addressed memory, then invokes an indirectly selected destination. It has no represented explicit arguments or result.

The established behavior is the sequence of memory accesses, width conversions, address calculations, and final invocation described below. Repeated offsets suggest record construction and linkage maintenance, but that is **inferred intent**, not an established application-level purpose.

Address-bearing values can originate from bytes, signed halfwords, shifted words, and arithmetic on other addresses. This contract does not imply that those values identify valid objects.

### Widths and descriptive names

A **byte**, **halfword**, and **word** occupy 8, 16, and 32 bits respectively. Byte and halfword stores retain the low 8 or 16 bits. Signed-halfword values widen to signed 32-bit values. Byte-derived addresses explicitly described as unsigned lie between 0 and 255.

The following names describe retained values, not live aliases for global storage:

- **Primary:** the entry word read from global location 0xa8.
- **Secondary:** the separately captured entry word from another global root slot, whose numeric location is not established.
- **Anchor:** a later word read from global 0xa8, plus 0x6e.
- **Scaled base:** secondary multiplied by 0x20.

Other descriptive names below identify values captured at particular reads. They do not authorize replacing later reads with earlier values.

Global labels identify storage, not necessarily disjoint fields. Overlapping global symbols are explicitly indicated by the supplied material. Widths of incompletely typed reset fields remain unresolved; receiving zero does not establish a word-sized store.

For the address calculations below, signed right shifts are those represented for signed 32-bit operands. Their target-level behavior, overflow rules, and excessive-count behavior remain **documented_only**.

## Behavior

The following phases preserve the represented order of observable accesses. Arithmetic descriptions do not imply additional memory reads. Unless a reread is specified, a descriptive name denotes its retained value.

### 1. Entry capture, clearing, and initial traversal

The primary is captured before the secondary. The routine then clears, in order: the byte at global 0x11, a reset-associated field, and fields associated with globals 0x46, 0x66, and 0x54.

It rereads global 0xa8 to form the anchor, then clears fields associated with 0x48 and 0x4a, the byte at 0x42, and the field associated with 0x44.

The early secondary-root accesses are independent of the retained secondary:

1. The secondary-root global slot is reread to form and retain an address at offset 0x74. The word at that address is **not yet read**.
2. The root slot is reread to locate a word at offset 4. That word’s low half is stored in the halfword global at 0x62.
3. The root slot is reread again for another word read at offset 4. That word’s high half is stored in the halfword global at 0x64.
4. Global byte 0x43 receives the anchor’s low byte.
5. Another root-slot reread locates the word at offset 0x54 that receives 0x2e.
6. Only now is the retained offset-0x74 slot dereferenced. A further word read at offset 0x64 of its result selects the first region.

Thus intervening writes can change the roots, either offset-4 source, or the retained pointer slot’s contents.

The first region’s word at offset 0x34 is cleared. A signed halfword at twice that region’s address is widened into primary offset 0xa2; retained-secondary offset 0x54 then receives the anchor.

A word read at primary offset 0xd2 selects a second region. Its offset 0x34 is cleared, its doubled-address signed halfword is read, and that widened result replaces primary offset 0xa2. Secondary offset 0x54 again receives the anchor.

### 2. Current record and nested updates

Primary offset 0xd2 is reread, selecting the **current record**, and that same value is written back to the slot. The subsequent order is:

- Primary offset 0x83 receives the anchor’s low byte.
- Current-record offset 0x11 receives that byte.
- Current-record offset 0x14 is read, retaining the **nested region**.
- Secondary offset 0x11 receives the second signed-halfword result’s low byte.
- Current-record offset 0 receives the secondary’s low byte; offset 0x44 receives the anchor; offset 0x74 receives the secondary.

The nested region’s offset 0x78 supplies the **linked region**; its offset 0x39 supplies an unsigned byte. The link is written back unchanged. Secondary offset 0x54 receives the retained signed-halfword result, linked offset 0x54 receives nested plus 0x34, and nested offset 0x45 receives the signed-halfword result’s low byte. Nested offset 0x78 then receives a **second** unchanged-value store.

A word is read at an address formed by shifting the signed secondary left 4, shifting that result right 24, and adding 0x60. After this read:

- The nested byte is copied to nested offset 0x4d, zero-extended into linked offset 0x74, and copied to nested offset 0x45.
- Linked offset 9 receives the unspecified incoming byte.
- A halfword at linked plus nested plus 0x34 receives the secondary’s low half.
- Secondary offset 0x14 is read and retained as the **old child**.
- Secondary offset 0x34 receives nested plus 0x34.
- The separate global-addressed byte at offset 5 is read.
- Linked offset 0x15 receives the old child’s low byte.
- Old-child offset 0x11 receives twice the earlier table word’s low byte, truncated to a byte.

Secondary offset 0x14 then receives primary plus 0x9c. A signed halfword at secondary plus linked is read and widened into primary offset 0xd0. **After** that lookup and store, secondary offset 0x54 receives primary plus 0x9c.

### 3. Scaled-base selection and repeated updates

- Construction offset 9 receives the retained signed byte.
- A word at construction plus table-word value receives the secondary.
- Secondary offset 0x0d receives the construction address’s low byte.
- A halfword at twice the construction address receives the table word’s low half.

Offset 0xd6 is reread. Scaled offset 0x86 receives scaled base plus 0x72. A fresh read of scaled offset 0xb6 selects a region whose offset 0x54 receives the newly selected construction address. Construction offset 0x15 is cleared, and a halfword at displacement plus construction receives the sign-extended signed byte, truncated to 16 bits.

Scaled offsets 0x7b and 0xc6 are written again. Offsets 0xb6 and 0xd6 are then independently reread, in that order. Scaled offset 0x86 again receives scaled plus 0x72; the new offset-0xb6 region’s offset 0x54 receives the new construction address. New-construction offset 0x15 receives the previous construction address plus one, truncated to a byte. Its displacement-addressed halfword receives the retained signed byte. The ensuing links use scaled plus 0xe4: scaled offset 0x138 and linked offset 0x14 receive it. A distinct word store uses the **retained signed byte itself as an address**, at offset 0x54, and writes the latest offset-0xb6 region plus 0x34.

Scaled offset 0xf1 receives the linkage address’s low byte. Scaled offset 0x128 is read and copied to offset 0x118; scaled-successor offset 0x54 receives the linkage address. The copied region’s offset 0x14 receives 0xa6.

## Acceptance examples

These are conditional static criteria, not executed tests.

- **Early root aliasing:** if clearing a global changes the secondary-root slot, the later root rereads use its changed contents. Accesses explicitly based on retained secondary still use the entry value.
- **Deferred dereference:** if the 0x2e store changes the retained offset-0x74 slot’s contents, the subsequent dereference observes that change. The slot address was already formed.
- **Split source values:** if the low-half global store changes the next offset-4 source or its root, the high half may originate from a different word or address.
- **Record-read ordering:** if current-record offset 0x14 aliases a later record store, the nested region is the value read before those stores, not the final field contents.
- **Signed propagation:** under signed eight-bit character semantics, a selected byte 0x80 becomes −128 in its word store and 0xff80 in subsequent halfword stores.
- **Truncation:** an anchor of 0x123456ab contributes 0xab to byte stores and the full value to word stores.
- **Low-address access:** a source byte 0xfe produces address 254 directly, not a pointer loaded from address 254.
- **Current global halves:** if intervening writes modify global halves 0x48 or 0x46, their current values form the combined root.
- **Valid shift counts:** if the relevant table word is 0x00000100, its first shift-by-8 result is 1, the next count is 1, and the retained result is 0. The later shift count is then 0. Intervening accesses still occur in the stated order.
- **Final aliasing:** the transfer-base offset-0x82 store occurs before the final signed-halfword lookup and can affect that lookup through aliasing. The offset-0xc2 store occurs afterward.
- **Nonreturning dependency:** if the final target does not return, no normal completion of this routine is represented.
