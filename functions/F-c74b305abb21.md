## Acceptance examples

These examples are conditional static consequences, not observed executions. They assume valid reached accesses and normally returning dependencies.

1. **Updated D1.** If F-bfade2068003 changes D1’s global location, with no intervening change before its read, F-398e0e9a318a receives the updated value—not an entry-time snapshot.

3. **Conditional D3 read.** If F-038bd7fcc91f returns nonzero, D3 is not read and B is not prepared. If it returns zero after changing D3, F-c266c50918ae receives the value subsequently read from that location.

4. **First check failure.** A nonzero F-038bd7fcc91f result causes A-only failure cleanup and return `0`. No count or entry access occurs.

5. **Setup short circuit.** A nonzero F-aa9d0af98dd1 result prevents F-56ffc99ff66d. A nonzero result from either setup check prevents iteration and the final state operation. Cleanup visits B, then A, and returns `0`.

6. **Nonpositive count.** Captured counts of `0` and `-1` both request no entries. If the final state operation returns zero, principal success follows; a negative count is not treated as a large unsigned count.

7. **Stable entries.** For count three and stable entry values zero, nonzero, zero, all three indices are requested. Only index one invokes F-9ef1ccf2e050. If that call and the final operation return zero, the function returns `1`.

8. **Changed entry between evaluations.** If the first entry evaluation is nonzero but the second yields zero, F-9ef1ccf2e050 is still called, with zero as its first argument. 9. **Zero first evaluation.** If the first entry evaluation is zero, no second evaluation or processing call occurs for that index.

10. **Mid-sequence failure.** For count four, a nonzero processing status at index one prevents requests for indices two and three and prevents the final operation. Failure cleanup returns `0`.

11. **Final failure.** A nonzero F-77aa48fed92a result returns `0` after cleanup even if all entries completed. The explicit success-only byte clearing does not occur.

12. **Success ordering and count mutation.** Principal success includes both F-f0952e578836 calls in their specified positions. Separately, a dependency’s change to the stored count after capture does not itself change the captured bound.
