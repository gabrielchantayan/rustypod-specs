# F-3a548392a5a0

## Purpose

F-3a548392a5a0 looks up a record by an exact unsigned 32-bit key in a caller-supplied object. It returns a record pointer on a match, or null if an initial eligibility dependency rejects the operation or the selected lookup procedure finds no match.

Two lookup representations are visible:

- A cached pointer index, selected when an object control byte is zero.
- A singly linked chain, selected when the control byte is nonzero or index initialization encounters an explicitly detected failure condition.

An indexed miss does **not** trigger linked-chain lookup. The chain is a bypass or initialization-failure fallback, not a second search after an indexed miss.

The indexed section is bracketed by two dependency calls receiving the same captured object-field value. Synchronization is a plausible purpose, but no synchronization guarantee is established by the supplied body.

## Interface

### Inputs and object layout

The function takes an object address represented by a 32-bit address-bearing argument and an unsigned 32-bit lookup key. All key bits participate in equality; zero has no special treatment.

The function directly accesses these object fields:

| Byte offset | Width | Observed role |
|---|---:|---|
| 6 | 1 byte | Zero selects the indexed section; nonzero selects the chain. |
| 12 | 4 bytes | Linked-chain head pointer. |
| 2512 | 4 bytes | Value captured for the indexed entry and exit dependencies. |
| 2516 | 4 bytes | Cached-index pointer, including the destination of the initialization-result store. |

These accesses do not establish a complete object type. Valid storage is required for every access actually reached. In particular, eligibility rejection occurs before any direct object access by this function; it does not establish whether the eligibility dependency itself accesses related state.

### Record layout

| Byte offset | Width | Observed role |
|---|---:|---|
| 0 | 4 bytes | Next pointer during chain traversal. |
| 12 | 4 bytes | Unsigned key used by either lookup procedure. |

Indexed search does not directly inspect record links. Chain traversal does not require an index.

### Index layout

The index consists of 4-byte words:

- The first word is interpreted as a signed 32-bit count.
- Subsequent words contain record pointers.
- Entry zero is at index-base offset 4.
- Each selected record must permit a 4-byte key read at record offset 12.

Neither the count nor the allocation size, entry pointers, or ordering is validated.

Reliable indexed lookup requires sufficiently sized, accessible storage, representable arithmetic, and appropriately ordered, stable search data. Nondecreasing unsigned key order is an inferred requirement of the search strategy, not an enforced condition.

### Additional global input

When preparing the post-initialization call to F-b4b5aa4c2f83, the function reads an opaque value from a program global for the third argument.

The supplied body does not establish that global’s declaration, width, meaning, or immutability. Earlier dependencies may affect its value; preservation must not be assumed.

### Output and ownership

The result is a 32-bit record pointer value or null. A successful lookup returns a pointer obtained from the selected representation, without copying or constructing a record.

Null does not distinguish eligibility rejection, indexed absence, chain absence, or failed initialization followed by chain absence.

No ownership transfer, retention, or lifetime guarantee is established. In particular, an indexed result is selected before the exit dependency runs. Returning that pointer value does not prove that the pointed-to record remains valid after the dependency or after return.

## Behavior

### Eligibility and representation selection

The first operation is a call to F-cd52fcefba54 with no explicit arguments. Its 32-bit result is tested against zero:

- Zero causes immediate null return.
- Nonzero allows lookup to continue.

The function then reads the object control byte at offset 6. Consequently, representation selection uses its value after the eligibility dependency has returned.

A nonzero control byte selects chain traversal directly. This branch does not directly read the object fields at offsets 2512 or 2516 and does not invoke the indexed entry or exit dependencies.

A zero control byte selects the indexed section. The control byte is not subsequently rechecked.

### Indexed entry and cache observation

On entering the indexed section, the function:

1. Reads the 4-byte value at object offset 2512.
2. Captures that value for later use.
3. Calls F-338d16f9ce72 with the captured value.
4. Reads the cache slot at object offset 2516.

The entry dependency’s return value is not used. No failure branch based on that return value appears.

The cache decision therefore reflects the slot after this dependency returns. A cache present before the call may have been replaced or cleared. The exit dependency later receives the captured value, not a fresh read of object offset 2512.

### Lazy initialization

If the observed cache slot is nonnull, initialization and post-initialization processing are skipped.

If the slot is null, F-f16e3e6dbf6b is called with the object address. After it returns, its pointer result is stored into the cache slot, including when the result is null. This store overwrites any cache-slot value that dependency may itself have installed.

A null initialization result causes the function to:

- Skip F-b4b5aa4c2f83.
- Call F-1333331b2da1 with the captured value.
- Enter chain traversal.

For a nonnull initialization result, the function prepares and invokes F-b4b5aa4c2f83 with:

| Argument | Source |
|---|---|
| First | Address 4 bytes beyond the returned index pointer. |
| Second | First 4-byte word read through that returned pointer. |
| Third | Opaque value read from a program global while preparing this call. |
| Fourth | Zero. |

The global read occurs on this nonnull-initialization branch, after the initialization dependency and cache-result store, before F-b4b5aa4c2f83 is invoked. It is not a value captured before the preceding dependencies. The supplied representation does not establish a relative evaluation order among the argument preparations.

The return value of F-b4b5aa4c2f83 is not tested. Instead, the function checks the object’s cache slot after that call:

- Null causes the exit dependency call followed by chain traversal.
- Nonnull permits indexed search.

The function subsequently obtains the search index pointer from the cache slot. Thus, the pointer used to prepare F-b4b5aa4c2f83 and the pointer used for searching need not be identical. A replacement cache can be searched.

These are separate source-level cache accesses, not a demonstrated atomic snapshot. Behavior under concurrent mutation between them remains undocumented.

### Indexed search

Search begins by reading the signed 32-bit count from the selected index. The lower bound starts at zero; the upper bound is the count minus one.

While the signed difference between the upper and lower bounds exceeds one, the function computes a midpoint by signed addition followed by division by two. The represented division truncates toward zero. For valid nonnegative bounds with representable arithmetic, this is the usual lower integer midpoint.

Each midpoint iteration has distinct source-level reads:

1. The midpoint index entry is read to obtain a record pointer for the equality test.
2. The 32-bit key at that record’s offset 12 is read and compared with the requested key.
3. If equal, the midpoint index entry is read again to obtain the pointer selected for return.
4. If unequal, the midpoint index entry is instead read again to obtain a record pointer for the ordering comparison, and that record’s key is read.

The second key read on inequality is therefore not necessarily through the same pointer used by the equality test. Likewise, the pointer selected on equality comes from a separate entry read, not necessarily from the pointer whose key matched.

For stable data, the equality branch selects the matching midpoint record. On inequality, ordering is unsigned:

- If the requested key is less than the key read for ordering, the upper bound becomes the midpoint.
- Otherwise, the lower bound becomes the midpoint.

No coherent-result guarantee follows when entries or keys change between these reads.

Once the interval spans at most two positions, the function performs a final scan in increasing position order:

- If the current position exceeds the upper bound, the selected result is null.
- Otherwise, the entry pointer at that position is loaded and the position is advanced.
- The key is then read through that loaded pointer.
- Equality selects that pointer; inequality continues the scan.

Unlike a midpoint equality hit, a final-scan hit does not reload the index entry to obtain the result pointer.

On either a hit or a miss, F-1333331b2da1 is called with the captured value before the function returns the selected pointer or null. Search does not restart after that dependency, and an indexed miss never falls back to the chain.

Duplicate keys do not imply first-entry preference across the whole index. A matching midpoint is selected immediately. Only the final scan prefers the earlier position within its remaining interval.

### Chain traversal

Chain traversal begins by reading the head pointer at object offset 12. For initialization-failure fallback, this read occurs after F-1333331b2da1 returns and therefore can observe changes made by that dependency.

For each current pointer:

- Null produces null return.
- Otherwise, the record key at offset 12 is read.
- Equality returns the current pointer.
- Inequality causes the next pointer at record offset 0 to be read and traversal continues.

The matching record’s next pointer is not read by this function. In a stable, terminating chain with duplicate keys, the first encountered match is returned.

There is no cycle detection, traversal limit, or pointer validation. A reachable cycle without a match can prevent termination.

## Side effects

### Direct writes and external effects

The only direct object write established by the body is the 4-byte initialization-result store at offset 2516. It occurs even for a null result.

There are no direct record-field writes or explicit deallocation operations in this body. This does not establish that dependencies avoid allocation, deallocation, mutation, or other externally visible effects.

### Observable ordering

Significant ordering relationships include:

- Eligibility dependency before the control-byte read.
- Capture of the indexed-call value before the entry dependency.
- Entry dependency before the first cache observation.
- Initialization dependency before the cache-result store.
- That store before nonnull-result post-initialization processing.
- The global argument read during preparation of the post-initialization call, not before initialization.
- Post-initialization call before its cache-null check.
- Separate midpoint entry reads for testing and selection or ordering.
- Indexed result selection before the exit dependency.
- Exit dependency before fallback’s chain-head read.

For normal control flow, every entered indexed section reaches the exit dependency before returning or falling back. Direct chain selection invokes neither member of the pair. No balancing behavior is established for faults or abnormal dependency exits.

The shared argument and placement suggest an acquire/release-like role, but mutual exclusion, visibility, reentrancy, blocking behavior, and record lifetime are unknown. No dependency is assumed to preserve object fields or globals unless an example explicitly imposes that condition.

## Acceptance examples

These are conditional static examples, not executed tests.

For indexed examples, cache conditions are stated **after F-338d16f9ce72 returns**, unless initialization is being described. Relevant cache observations, entries, counts, and keys must remain stable during the specified search. Storage and arithmetic must be valid, and dependencies must return normally. A returned pointer value is not a guarantee of record validity after F-1333331b2da1.

1. **Eligibility rejection.** If F-cd52fcefba54 returns zero, the result is null. This function directly reads no object field and invokes no later dependency.

2. **Direct chain selection.** After eligibility succeeds, a nonzero control byte selects a stable chain with keys 4, 9, and 12. Requesting 9 returns the second record. No cache is consulted and neither indexed bracketing dependency is called.

3. **Empty chain.** If chain traversal begins with a null head, it returns null.

4. **Single-entry cache after entry.** After the entry dependency returns, the cache slot contains and continues to identify an index with count one and one stable record. A matching key selects that entry’s pointer; another key selects null. The exit dependency runs before either result is returned. No chain lookup occurs, and post-exit record validity is not implied.

5. **Zero-entry cache after entry.** After the entry dependency returns, the stable cache has count zero. The upper bound becomes minus one, and no index entry or record key is read. The exit dependency runs and the result is null.

6. **Unsigned ordering.** After entry, a stable index contains unsigned keys 1, 2147483648, and 4294967295 in that order. Requesting 4294967295 selects the third entry’s pointer. Signed key ordering would not describe the comparison used.

7. **Null initialization result.** The cache is null after entry, and initialization returns null. The function stores null, skips post-initialization processing, calls the exit dependency, and only then reads the chain head.

8. **Global changed before post-initialization processing.** Initialization returns a nonnull index after changing the program global used for the third post-initialization argument. If nothing changes that global before its argument read, the call receives the changed value, not an assumed constant or pre-entry value.

9. **Cache cleared during post-initialization processing.** Initialization returns a nonnull pointer, but the subsequent dependency leaves the cache null. The function calls the exit dependency and traverses the chain rather than searching the initialization pointer.

10. **Indexed miss despite a chain match.** After entry, a stable, valid, unsigned-ordered index lacks the requested key. Even if a linked chain contains it, indexed search selects null, calls the exit dependency, and returns null without reading the chain head.

11. **Duplicate midpoint.** After entry, a stable five-entry index has the requested key at its middle entry and at an earlier entry. The first midpoint equality test succeeds. The midpoint entry is read again, and its stable pointer value is selected. The exit dependency precedes return; no first-duplicate or post-exit validity guarantee follows.

12. **Replacement cache.** Initialization returns one index, used to prepare the post-initialization call. That dependency leaves a different valid index in the cache slot, which remains stable through subsequent observations and search. The replacement is searched, not the original initialization result.
