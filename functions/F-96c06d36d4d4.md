# F-96c06d36d4d4

## Purpose

F-96c06d36d4d4 populates caller-provided storage with 256 consecutive 32-bit words. Each word combines two dependency results with two copies of its entry number using bitwise exclusive OR.

**Established static behavior:** Entry numbers range from 0 through 255. For each entry, F-5900d04b98e5 is invoked before F-9614069590c8, and both invocations precede the routine’s destination write. Processing proceeds in increasing entry order. The visible body contains no validation, allocation, explicit error report, or recovery path.

**Inferred intent:** The output resembles a lookup table. Neither its application nor a mathematical relationship between the dependencies is established.

The output is not unconditionally a concatenation of four independent bytes. In particular, the second dependency result is used without an eight-bit restriction and can alter any part of the output word.

## Behavior

### Observable sequencing

The routine processes exactly 256 entries if all calls, calculations, and stores complete normally. Dependency return values do not select a shorter processing range.

For each entry, the dependency invocation order is F-5900d04b98e5 followed by F-9614069590c8. Both receive the entry number as a numeric value between 0 and 255. The visible eight-bit reduction of that argument does not change its value anywhere in the processing range. It also does not establish an eight-bit physical calling-convention argument.

The destination write for an entry occurs after both dependency results for that entry have been obtained. That write precedes the dependency invocations for the following entry. Consequently, a normally completing execution contains 256 invocations of each dependency and 256 direct destination word writes, interleaved by entry rather than grouped by dependency.

No invocation uses entry number 256.

The first dependency’s returned value remains the first contribution for the current entry after the second dependency returns. The routine does not invoke the first dependency again to obtain that contribution.

### Meaning of an output word

Under a 32-bit bit-vector interpretation, each word has four exclusive-OR contributions:

| Contribution | Positions affected |
|---|---|
| Low eight bits of the first dependency result | Bits 24–31 |
| Entry number | Bits 16–23 |
| Entry number | Bits 8–15 |
| Entire 32-bit second dependency result | Bits 0–31 |

Bit 0 denotes the least significant bit of the numeric word. These positions do not specify memory byte order.

The first dependency result is represented as signed. Its use in the upper-byte contribution involves a signed operation whose validity cannot be assumed for every possible result. The table above describes the intended 32-bit bit-vector interpretation; it is not a guarantee of portable behavior for every signed input.

Within that interpretation:

- Higher bits of the first result do not contribute to the stored word.
- The second result is not narrowed to its low byte.
- Overlapping set bits cancel under exclusive OR.
- There is no addition or carry propagation between contributions.
- Existing destination contents do not participate in the calculation.

If the second result fits in eight bits, the numeric word can be described, from most significant byte to least significant byte, as the first result’s low byte, the entry number, the entry number, and the second result. Without that restriction, the second result may change any of those four bytes.

### State-sensitive dependency behavior

The dependency calls are not established to be pure, deterministic, or independent.

The first invocation for an entry may change state that the second invocation observes. Either dependency may observe effects from earlier entries, including destination words already written. Results for a particular numeric argument therefore need not be identical across separate executions.

Although the destination address is not passed directly to either dependency, that does not establish isolation from destination storage. A dependency could access the same storage through other state. It could also allocate memory, release memory, or invalidate storage. None of those possibilities is resolved by the visible caller.

There is no direct destination-content read in this routine. Reads performed inside a dependency remain possible.
