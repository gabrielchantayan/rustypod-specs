# F-1e04c0483912

## Behavior

### 1. Initial call chain and first 32-bit write

The routine first invokes F-d001 with the explicit input argument. Its target is formed from the incoming link value plus `0xffe`.

It then invokes F-d002, F-d003, and F-d004 in that order, with no explicit arguments represented. F-d005 follows and supplies \(R_1\).

The routine forms:

\[
P=\operatorname{low}_{32}(4R_1)
\]

It then performs a 32-bit write at the address represented by:

\[
\operatorname{low}_{32}(P+0x14)
\]

The stored value is:

\[

\]

This write occurs before F-d006. Its value is at most `0x000fffff`, because the shift discards the low 12 bits of a 32-bit unsigned value.

F-d006 receives \(P\).

### 2. Second 32-bit write and three-argument call

F-d007, F-d008, and F-d009 execute in order. F-d010 then supplies \(R_2\).

The routine forms:

\[
Q=\operatorname{low}_{32}(4R_2)
\]

It writes the 32-bit value \(Q\) to the address represented by:

\[
\operatorname{low}_{32}(16R_2+0x14)
\]

The address uses sixteen times the result; the stored value uses four times the result. These are distinct calculations.

F-d011 then receives three represented arguments, in order:

1. \((P \mathbin{\&} 0x3f) \ll 14\)
2. \(Q\)
3. \(\operatorname{low}_{32}(R_1 \ll 30)\)

Under the 32-bit interpretation, the first argument depends only on bits 0–3 of \(R_1\), positioned into argument bits 16–19. Its bits 14 and 15 are zero because \(P\) is a multiple of four.

The third argument retains only bits 0–1 of \(R_1\), positioned into bits 30–31.

### 3. Third 32-bit write

### 4. First byte lookup and byte write

Define the byte-read address:

\[
L=\operatorname{low}_{32}(R_1 \times 0x10000000+1)
\]

Under the low-32-bit interpretation, this address depends only on bits 0–3 of \(R_1\). Its low 28 bits are `1`.

The routine reads one unsigned byte from \(L\), producing \(B_1\), and then writes one byte to:

\[
B_1+0x11
\]

The stored byte is:

\[
\operatorname{low}_{8}(R_4 \ll 2)
\]

Thus, this store uses bits 0–5 of \(R_4\), shifted into byte bits 2–7. The stored byte’s low two bits are zero.

Because \(B_1\) is zero-extended from one byte, the destination lies between `0x11` and `0x110`, inclusive. The loaded byte is used as a small absolute address component, not as a pointer loaded at pointer width. No additional base is represented.

F-d021 then receives:

1. \(\operatorname{low}_{32}(R_4 \ll 2)\)
2. The same 32-bit shifted value
3. \(\operatorname{low}_{32}(R_4 \ll 4)\)

Its represented target construction uses an offset of `0xfec`; the other displayed offset-based call constructions use `0xffe`.

### 5. Forwarded result and second byte lookup

The routine then reads an unsigned byte from \(L\) again, producing \(B_2\). This is a fresh read, not reuse of \(B_1\).

\[

\[

\mathbin{\text{logical-right-shift}}20\right)
