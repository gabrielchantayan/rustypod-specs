# F-3729fe1392c3

## Purpose

F-3729fe1392c3 conditionally issues a left segment, a right segment, and zero or more middle segments using dependency-provided resources and four-word coordinate records.

**Established static behavior:** the function prepares temporary storage through dependency calls, evaluates two gates and a signed span comparison, conditionally publishes four object fields, constructs segment records, and issues rendering-like calls. Every ordinary return path ends with a final dependency call on the temporary storage.

**Inferred intent:** horizontal three-part rendering with repeated or clipped middle segments. The dependency implementations are unavailable; actual drawing, clipping, context initialization, and context-state restoration are not established.

No runtime tests have been performed.

## Interface

### Input and return

The function accepts one object address and has no explicit return value or error result.

The representation uses 32-bit object words. No input-pointer validation is visible. The caller must provide valid storage for all accesses reached on the executed path, including associated-object and dispatch-table dereferences.

### Local storage and record notation

The function supplies a 68-byte temporary area to several dependencies. Its internal format is not interpreted directly.

Coordinate-like records consist of four consecutive 32-bit words, described here as:

**(horizontal start, vertical start, horizontal end, vertical end)**

These names reflect their arithmetic use, not a proven external type. A horizontal span is the third word minus the first word. Vertical words are copied without visible coordinate arithmetic.

There are no visible checks for coordinate ordering, positive dimensions, alignment, resource validity, or arithmetic range. Horizontal calculations and comparisons use the signed 32-bit interpretation shown by the supplied representation. Overflow behavior is unresolved; this contract does not impose saturation, wrapping, or rejection.

Pointers to local records are passed to dependencies. Their mutation, retention, and ownership contracts are unavailable.

## Behavior

### 1. Unconditional preparation and initial gate

The following calls occur in order:

1. F-a4c26c2b4842 receives the 68-byte temporary area.
2. F-7fa874cbac7a receives the object and that area.
3. F-960363c07b32 receives the object and four-word output storage.
4. F-2adbf0d1a289 receives the object and supplies a zero/nonzero result.

If the result is zero, execution proceeds directly to F-282eebd7c413 with the temporary area.

If nonzero, the four words supplied through F-960363c07b32 are copied to another local record. That copy is not subsequently consumed by the visible segment path. The query remains unconditional and cannot be treated as removable: its other effects are unknown.

### 2. Associated-object gate and strict span comparison

After a nonzero initial gate, the function reads object offset `0x0B4`. Zero skips the remaining conditional work.

For a nonzero value, the sequence is:

1. F-41f58d472b76 receives the object.
2. F-d06d54bfd78a receives the temporary area and an opaque static value.
3. A fresh read of `0x0B4` supplies the associated-object argument to F-756b664b4a2c, which also receives four-word output storage.
4. Another read of `0x0B4` supplies an address from which four words are copied, in offset order `0x80`, `0x84`, `0x88`, `0x8C`.

The earlier nonzero check does not validate later values. Intervening dependencies may change the object field; the measurement call and subsequent four-word read need not use the same associated object. There is no repeated null check.

The function compares:

- the signed span between associated-object offsets `0x80` and `0x88`; and
- the signed span between the first and third output words from F-756b664b4a2c.

Further work occurs only if the associated-object span is **strictly smaller**. Equal or larger spans skip destination publication and all segment calls.

### 3. Optional embedded-region operation and indirect call

When the strict comparison succeeds, the function tests the low eight bits of the word at `0x578`.

If nonzero:

1. F-2318d06eb0b2 receives the embedded address at `0x2DC`.
2. A local word is set to zero.
3. The object word at `0x52C` is read.
4. If that word is zero, an indirect dependency receives the object and a zero argument.

The indirect target is obtained from byte offset `0xA0` in the dispatch table addressed by the object’s first word. No validation of either address is visible.

The zeroed local word is later overwritten before any visible use. It is not an established output or communication mechanism.

If the low-eight-bit test is zero, both the embedded-region call and this indirect-call branch are skipped. In particular, the `0x52C` read belonging to this branch does not occur.

### 4. Destination publication and resource queries

F-96217f78e268 receives four-word output storage followed by the object. Its resulting words are copied into object offsets `0x2E8`, `0x2EC`, `0x2F0`, and `0x2F4`, in that order.

These writes occur before resource queries and segment calls. No later rollback or clearing of these fields is visible.

Resource lookup uses an opaque global table-pointer location with an important distinction:

- The function first reads that global pointer and retains its value locally.
- The first F-c24767c70ad0 call obtains resource entry zero through **another read of the global pointer**, followed by a read of entry zero through that newly obtained pointer.
- The second query reads entry one through the retained pointer.
- The third query reads entry two through the retained pointer.

Each query receives separate four-word output storage as its first argument and the resource value as its second argument.

Consequently, the first query can use a table different from the retained table. The visible sequence does not require the two global-pointer reads to agree.

The resulting records are called the **left**, **middle**, and **right resource records**, respectively. Their spans are third word minus first word.

Later segment calls read resource entries through the retained table pointer: entry zero for the left segment, entry two for the right segment, and entry one for every middle segment. These entries are not permanently snapshotted by the queries. A changed table entry can therefore make a segment call use a resource different from the one whose record was queried.

### 5. Saved value and zero-valued call

After the three resource queries:

1. F-da61fe335489 receives the temporary area and returns a 32-bit value, which is saved.
2. F-33ca0546dba1 receives the temporary area and zero.

After normal completion of segment processing, F-33ca0546dba1 receives the temporary area and the saved value.

The calls and saved-value flow are established. Interpretation as reading, temporarily replacing, and restoring context state is **inferred intent**, not an established dependency effect.

### 6. Left and right segments

The left segment is issued first.

Its source record copies all four words of the left resource record. Its destination record has:

- horizontal start equal to the destination’s horizontal start;
- horizontal end equal to that start plus the left resource span;
- vertical words copied from the destination record.

Before the segment call, the function:

1. Reads object offset `0x52C` into a local 32-bit word.
2. Calls F-fd2727fb15fa with that local word’s address.
3. Calls F-eb34c4d75211, obtaining a one-byte value.
4. Calls F-945301cd184f with retained-table entry zero, the temporary area, source-record address, destination-record address, and that byte.

The right segment follows. The same local source and destination record storage is reconstructed for this segment.

The right source copies all four words of the right resource record. The destination ends at the destination record’s horizontal end and begins one right resource span earlier. Its vertical words are copied from the destination record.

A fresh `0x52C` read and fresh calls to F-fd2727fb15fa and F-eb34c4d75211 precede F-945301cd184f using retained-table entry two.

No visible logic clips either cap to the destination or prevents overlap. A narrow or reversed destination does not itself suppress these calls once the earlier gates have passed.

### 7. Middle-record initialization

After the right segment call, the function establishes:

- **middle end:** destination horizontal end minus right resource span;
- **initial middle position:** destination horizontal start plus left resource span.

Separate source and destination records are prepared for the middle loop.

The middle source record is initialized with:

- horizontal start zero;
- vertical start from the **middle resource record’s second word**;
- horizontal end zero;
- vertical end from the **middle resource record’s fourth word**.

The middle destination record is initialized with zero horizontal words and vertical words copied from the destination record.

These vertical words are initialized **once before the loop**, even if the loop subsequently has no iterations. They are not refreshed inside the loop.

### 8. Middle-loop reconstruction, calls, and advancement

The loop is entered only while the current middle position is strictly less than the middle end.

For each iteration, before any segment-related dependency call:

- The middle source horizontal start is reset to zero.
- A tentative destination horizontal end is formed by adding the middle resource span to the current position.
- If the middle end is less than or equal to the tentative end, the selected end is the middle end.
- The source horizontal end becomes the selected destination span.
- The destination horizontal start becomes the current position.
- The destination horizontal end is the selected end.

The function then reads `0x52C` into a fresh local word, calls F-fd2727fb15fa with its address, calls F-eb34c4d75211, and calls F-945301cd184f using retained-table entry one and the middle source and destination record addresses.

**Only the horizontal words are reconstructed each iteration.** Neither record’s vertical words are reassigned within the loop. Mutations to those words by a dependency can therefore persist into subsequent iterations. Both initial source vertical words originate from the middle resource record; there is no visible left-resource vertical pairing.

After the call sequence, the position advances by:

**the middle destination record’s horizontal end minus its horizontal start, using their values after the calls.**

Thus, dependency mutation of destination horizontal words can alter progress. The next iteration reconstructs those words, but only after their post-call values have already affected advancement.

Under unchanged-record assumptions and non-overflowing arithmetic, a positive middle span gives forward progress and a possibly shortened final segment. A zero middle span with a nonempty region gives zero progress. Negative spans are not rejected and need not converge.

### 9. Ordinary completion

After normal loop completion, F-33ca0546dba1 receives the temporary area and saved 32-bit value.

F-282eebd7c413 then receives the temporary area. It also receives that area on every earlier ordinary skip path.

No exception handling or failure unwinding is visible. Neither the saved-value call nor finalization is guaranteed after a fault, nonreturning dependency, abnormal control transfer, or nonterminating loop.

## Acceptance examples

These are conditional static examples, not executed tests. Numerical examples assume valid storage, normally returning dependencies, stable relevant inputs, no relevant record mutation, and signed arithmetic within range.

1. **Initial gate zero.**  
   The four preparation/query/gate calls occur, followed by F-282eebd7c413. There are no associated-object accesses, destination writes, or segment calls.

2. **Associated-object field zero.**  
   After a nonzero initial gate, a zero `0x0B4` value skips F-41f58d472b76 and all subsequent conditional processing.

3. **Equal spans.**  
   Associated coordinates 10–50 and measured coordinates 100–140 both have span 40. The strict comparison fails. Destination publication and resource queries do not occur.

4. **Low-byte enable.**  
   With earlier gates satisfied, `0x00000100` at `0x578` skips the embedded-region operation. `0x00000101` enables it. The indirect call then depends on the subsequent `0x52C` read being zero.

5. **Full and shortened middle segments.**  
   For destination `(10, 20, 110, 40)` and left, middle, and right spans 8, 30, and 12, segment destinations are issued in this order:
   - Left: `(10, 20, 18, 40)`.
   - Right: `(98, 20, 110, 40)`.
   - Middle: `(18, 20, 48, 40)`.
   - Middle: `(48, 20, 78, 40)`.
   - Middle: `(78, 20, 98, 40)`.

   Middle source horizontal ranges are 0–30, 0–30, and 0–20. If the middle resource’s vertical words are 6 and 26, those are the source vertical words initially and, absent mutation, throughout.

6. **Persistent vertical mutation.**  
   Suppose an early middle segment call changes the middle source vertical end to 29 and destination vertical start to 22. If later dependencies leave those words unchanged, later middle calls receive 29 and 22 respectively. Per-iteration horizontal reconstruction does not reset them.

7. **Post-call horizontal advancement.**  
   A middle destination initially spanning 18–48 is changed by the call sequence to 18–43. The running position advances by 25, not 30.

8. **Overlapping caps.**  
   Destination 0–10 and cap spans of 8 produce left 0–8 and right 2–10. The middle loop is skipped.

9. **Zero middle span.**  
   An empty middle region skips the loop. A nonempty region with zero middle span and unchanged records repeatedly issues zero-span middle calls without progress.

10. **Different table-pointer reads.**  
    If the retained pointer denotes table A but the fresh global-pointer read denotes table B, the left resource query uses B’s entry zero. The other queries and all segment resource reads use A.
