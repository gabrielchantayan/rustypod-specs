# F-d0783c6d6764

## Purpose

Any other value triggers object resolution, an indirect callback, temporary-value preparation, and a final dependency invocation associated with the text “SelectCompilation.”

The returned Boolean reports whether the initially read value differed from −1. It does **not** establish that the final operation succeeded, that a selection changed, or that memory allocation succeeded.

The semantic meaning of the selected value, the final operation, and the temporary representations remains undocumented.

## Behavior

### Sentinel decision

The first relevant operation reads the four-byte value at object offset `0xD4` and retains it for subsequent use.

If the value is −1:

- No dependency is called.
- The address at object offset `0xB4` is not passed to a dependency.
- No active-path local object is prepared or cleaned up.
- The function returns false.

All other 32-bit values take the active path. There is no visible restriction to nonnegative values: zero, positive values, and negative values other than −1 are forwarded to the indirect callback.

### Object resolution and callback

On the active path, the following order is established:

1. F-eb24201e389b receives the address of the four-byte resolution-handle region and the address at object offset `0xB4`.
2. F-e38e6836b640 receives the resolution-handle address. Its return is treated as an object pointer.
3. F-24edd96d1422 receives the resolution-handle address.
4. The function dereferences the returned object pointer to obtain a dispatch-table address, then obtains an indirect call target from byte offset `0x22C` within that table.
5. The indirect dependency receives the 24-byte callback-result destination, the resolved object pointer, and the initially captured selection value.

The cleanup-like call in step 3 occurs **before** the resolved object is dereferenced for dispatch. Correct execution therefore requires that the returned pointer remain usable across that call. The supplied body does not establish why it remains valid, whether another owner exists, or whether the cleanup-like dependency actually releases ownership.

No check is made for a null resolved pointer, a null dispatch table, or an unusable indirect target. The callback’s return value, if any, is not visibly used. Later calls rely on the callback-result storage.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests.

### Sentinel suppresses the operation

Given a valid initial field read yielding −1, the required result is false. No listed dependency may be invoked on that path, regardless of the contents at offset `0xB4`.

### Zero is an active selection value

Given an initial field value of zero and dependencies that complete normally with usable results, the indirect callback receives zero. The complete preparation, final invocation, and cleanup sequence occurs, and the function returns true.

### Other negative values are not rejected

Given an initial field value of −2, the function must not treat it as the sentinel or reject it through a local range check. It is forwarded to the indirect callback. Whether that callback accepts it is a dependency-level question.

### Later field changes do not change this invocation’s decision

### Shared context is not an entry-time snapshot

### Cleanup ordering is observable
