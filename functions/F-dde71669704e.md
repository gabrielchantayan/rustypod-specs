## Behavior

### Empty traversal

The current position initially equals the initial-position argument.

The function compares the current position with the end before making the first dependency call. If they are equal, it returns normally without invoking F-8000adeb8fc3.

This applies to any equal pair of representable values. There is no separately established restriction excluding zero, negative values, or values that would be invalid as addresses.

### Nonempty traversal

Whenever the current position differs from the end:

1. F-8000adeb8fc3 is invoked with that current position as its sole shown argument.
2. Only after the invocation returns normally does the current position advance by 28.
3. The updated position is compared with the end before another invocation is made.

These are observable sequencing requirements. Calls occur serially; the body does not batch them or initiate a later call before an earlier one returns.

For a finite traversal of \(N\) calls, provided the arithmetic involved is valid, the dependency receives the mathematical sequence

\[
S,\ S+28,\ S+56,\ \ldots,\ S+28(N-1),
\]

and the end equals \(S+28N\), where \(S\) is the initial position. The end itself is excluded from that sequence.

The constant increment is 28 numerical units. Calling those units bytes requires an address interpretation that the body alone does not prove.

### Exact equality rather than bounds checking

Termination depends only on equality. There is no visible check that:

- The initial position is less than the end.
- The distance to the end is divisible by 28.
- An increment remains within a valid region.
- An increment avoids an arithmetic boundary.

Consequently, an end value lying numerically between two successive positions is not treated as reached. A conventional “process until the next record would exceed the boundary” interpretation would not match the supplied behavior.

### Arithmetic and termination boundaries

The evidence shows integer addition by 28 but does not independently resolve the underlying machine’s overflow semantics. Two cases must remain distinct.

**Without overflow:** If the end is the initial position plus a nonnegative multiple of 28, and every intermediate addition is valid, the function makes exactly that multiple’s number of calls. If equality cannot be reached before an arithmetic boundary, the supplied body provides no alternate termination mechanism.

**Conditional 32-bit wrapping interpretation:** If positions are 32-bit bit patterns and addition wraps modulo \(2^{32}\), the position sequence repeats after

\[
2^{32}/\gcd(28,2^{32})=2^{30}
\]

increments. Under that interpretation, an end is reachable exactly when it has the same residue modulo 4 as the initial position. A reachable end is encountered after between zero and \(2^{30}-1\) calls. An unreachable end is never encountered through this traversal alone.

That modular analysis is conditional, not a claim that signed overflow is defined or that execution has been observed to wrap. Ordinary signed-integer language semantics and machine-level wrapping semantics must not be silently conflated.
