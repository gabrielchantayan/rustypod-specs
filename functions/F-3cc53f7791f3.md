### Widths and notation

A **byte** is eight bits; a **word** is 32 bits. A represented 64-bit result has low and high 32-bit halves. A byte store retains only the low eight bits.

A **selector write through a base** means an unsigned byte read at that base plus 1, followed by a byte write at the selector’s numeric value plus 17. Its destination is consequently within addresses 17–272, not within the original base’s surrounding storage.

Unsigned 32-bit computations truncate to 32 bits. Logical right shifts are identified below. Some address computations and shifts have represented signed intermediates; statements about their wrapping behavior are conditional on a 32-bit machine interpretation, not portable signed-arithmetic guarantees.

When a sequence is described as several calls “beginning with” particular arguments, those arguments belong to its first call. A sequence’s result is its last call’s result unless otherwise specified. Other argument lists are not shown; this does not establish that those calls receive no machine-level arguments.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Input truncation.** For first argument `0xA5C3127E`, the first selector write stores `0x7E`; the later input-derived write stores `0x97`.

2. **Fresh lookup.** An initial selector of 4 directs the first write to address 21. If intervening calls change that selector to 9, the subsequent fresh lookup directs its write to address 26.

3. **Direct write precedes lookup.** An early result of `0x123456AB` supplies byte `0xAC` after shifting left by two. The direct fourth-argument-plus-15 store precedes the following selector read and can affect it through aliasing.

4. **Byte width remains decisive.** Masking `0x3FFFFFFF` to 30 bits and shifting right by 20 produces `0x3FF`; the byte store writes `0xFF`.

5. **Scaled input does not always vanish.** Under wrapping arithmetic, fourth argument 1 gives transformed input 256 and a 524,288-scaled base of `0x08000000`. Fourth argument 32 gives that scaled base zero.

6. **Retained lookup.** Changing stage 2’s selector source after its retained read does not redirect the later word read at retained selector plus 116.

7. **Overwrite visibility.** A call between the two stage-5 plus-52 stores may observe the first word. Both stores remain required.

8. **Terminal call count.** After stage 9’s final four-argument call, four additional call events precede the fresh selector-zero write. Five events follow that write. Inserting a fifth call before the write changes the observable trace.

9. **Word versus byte.** Stage 9’s retained-value-right-shift store writes 32 bits, even though stage 7 also used that value to produce a byte.

10. **No success inference.** The final displayed call does not establish normal return or a success result.
