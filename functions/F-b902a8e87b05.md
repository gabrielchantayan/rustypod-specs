# F-b902a8e87b05

## Purpose

F-b902a8e87b05 is a state-driven wrapper around F-8ba1b02d05d0. It prepares three integer inputs using a captured scale, retains three opaque input words and a fourth integer input, conditionally invokes the dependency, and transforms its return value into the wrapper’s eventual result.

The supplied representation establishes the control flow and data relationships, but not the values or external meanings of the controlling global words. Consequently, it does not establish that a particular invocation reaches the dependency, terminates, or returns a particular numeric value.

This contract distinguishes:

- **Established behavior:** operations and dependencies directly represented in the supplied material.
- **Inferred intent:** the interpretation of the function as a scaling or adaptation wrapper.
- **Documented-only unknowns:** arithmetic overflow semantics, global values, dependency behavior, and environmental constraints not supplied.

## Behavior

### Entry state

The captured scale is read before the initial selector.

The function initializes the following local state to zero:

- The current result.
- Three integer working values associated initially with inputs 1, 5, and 3.
- A retained fourth integer.
- Three retained opaque words.

These zero initial values matter. The control flow can invoke the dependency before any input preparation has occurred.

The captured scale is not refreshed later, including after a dependency call. Changes to the corresponding global during execution do not change the value already captured by this invocation.

### Control evaluation

Every control evaluation performs these operations in the represented order:

1. Read the live coefficient into a local snapshot.
2. Read the selector increment and add it to the current selector.
3. Dispatch using the adjusted selector.

The dispatch has three outcomes:

- **Adjusted selector 0:** perform input preparation, then evaluate control again.
- **Adjusted selector 1:** perform one dependency invocation and its result processing, then evaluate control again.
- **Adjusted selector 2:** return the current result.
- **Any other adjusted selector:** perform input preparation, then evaluate control again.

The preparation selector is therefore not dispatched directly when read. It first undergoes another selector-increment addition.

Each new control evaluation replaces the coefficient snapshot, including evaluations that lead to preparation or immediate return. Only a snapshot belonging to an evaluation that selects the dependency path is used to transform a dependency result.

### Input preparation

Preparation replaces the local working state as follows:

- The first working integer becomes the captured scale multiplied by input 1.
- The third-input-position working integer becomes the captured scale multiplied by input 5.
- The second-input-position working integer becomes the captured scale multiplied by input 3.
- The current selector becomes a fresh read of the preparation selector.
- The retained fourth integer becomes input 7.
- The retained opaque words become inputs 2, 6, and 4 in the storage order represented; their dependency positions remain 8, 7, and 6 respectively.

For clarity, the three working integers are referred to below as the **first**, **third**, and **second** working integers according to their original integer-input roles, not according to argument position.

Preparation does **not** reset the current result. A dependency result can therefore survive subsequent preparation and be returned later without another dependency invocation.

Repeated preparation replaces prior working values with products of the original inputs and the entry-captured scale. It does not cumulatively multiply the previous working values.

### Dependency invocation

When the adjusted selector is 1, the function prepares one call to F-8ba1b02d05d0.

The following steps precede that call:

1. Read the live coefficient again and multiply it by the current first working integer. Retain this product for dependency argument 5.
2. Read the live multiplier and compute its product with the captured scale and the retained fourth integer. Replace the first working integer with this product.
3. Read the live multiplier again and multiply it by the current third working integer. Replace that working integer with this product.
4. Read the live multiplier a third time and multiply it by the current second working integer to form dependency argument 2.

The dependency receives eight nominally 32-bit arguments:

| Dependency position | Value |
|---|---|
| 1 | Updated third working integer. |
| 2 | Third live-multiplier read multiplied by the current second working integer. |
| 3 | Literal zero. |
| 4 | Updated first working integer: the product involving the retained fourth integer. |
| 5 | Fresh live-coefficient read multiplied by the first working integer as it existed before step 2. |
| 6 | Retained input 4. |
| 7 | Retained input 6. |
| 8 | Retained input 2. |

The coefficient snapshot taken during control evaluation is not the read used for argument 5. Those are separate reads and must not be treated as interchangeable without an environmental stability guarantee.

Likewise, the three live-multiplier reads are separate. The supplied representation does not justify replacing them with one cached value.

The wrapper does not expose an ordering requirement among argument evaluations beyond the explicit work already completed before the call. In particular, it should not be treated as specifying a general left-to-right calling convention.

### Processing the dependency result

After F-8ba1b02d05d0 returns normally:

1. Its return value is multiplied by the coefficient snapshot from the selecting control evaluation and by the entry-captured scale.
2. This transformed value replaces the current result.
3. The same transformed value replaces the second working integer.
4. The post-call selector is read and becomes the current selector.
5. Control evaluation resumes.

The coefficient used here is the pre-call snapshot, not a fresh post-call read. The post-call selector, by contrast, is read after the dependency has returned and after result processing.

A dependency call may alter globals. Such alterations may affect later global reads, but do not retroactively alter already captured local values.

### Consecutive dependency calls without preparation

Preparation is not mandatory between calls. If control selects another dependency invocation immediately:

- The first working integer already contains the previous fourth-integer product. The next argument 5 uses that value, not the original scaled input 1.
- The third working integer already contains the previous multiplier product and is multiplied again.
- The second working integer contains the previous transformed result. The next argument 2 uses that result, not the original scaled input 3.
- The retained fourth integer and opaque words remain unchanged.

If no preparation has ever occurred, these retained values and working integers are initially zero. Subject to defined arithmetic, the first such dependency call receives eight zero-valued arguments regardless of the caller’s seven input values.

### Arithmetic boundaries

The supplied representation uses nominally 32-bit signed integer operations for selectors, products, working values, and the return value. It does not establish wider accumulation, saturation, checked arithmetic, or explicit overflow reporting.

Products involving three factors must not be assumed to use an unbounded mathematical intermediate. An intermediate product can overflow even when a later multiplication by zero would yield zero mathematically.

Overflow behavior is **documented_only**: the supplied material does not resolve whether the applicable executable or language-level contract requires modular wraparound or some other treatment of signed overflow. Numeric acceptance examples below use values whose intermediate additions and products fit signed 32-bit range.
