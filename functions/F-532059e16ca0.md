# F-532059e16ca0

## Purpose

F-532059e16ca0 updates a destination word array by adding bits selected from two source word arrays. For each processed word, a bit is added when it is set in the first source and clear in the second source. Existing destination bits are retained.

The function returns a one-byte indication of whether any processed destination word changed.

The destination’s leading 32-bit field determines the number of words processed. The corresponding leading fields of the source objects are not consulted. Although the layout suggests a bitset operation, the function does not validate bitset lengths, enforce matching source sizes, or mask unused bits in a final partial word.

These are static observations from the supplied representation, not runtime-verified behavior.

## Behavior

### Selecting the processing extent

The function reads the destination’s leading field once, before processing any data words.

Let the field’s bit pattern, interpreted as an unsigned 32-bit value, be \(H\). The number of processed words is:

\[
W=\left((H+31)\bmod 2^{32}\right)\mathbin{\mathrm{div}}32
\]

The division is an unsigned right shift by five bits, equivalent to rounding down after the wrapped addition.

For nonnegative signed 32-bit extents, this is the usual number of 32-bit words needed to contain that many bits:

- Extent 0 selects no words.
- Extents 1 through 32 select one word.
- Extents 33 through 64 select two words.
- The largest positive signed 32-bit extent selects 67,108,864 words.

The formula is not a validated size conversion. In particular:

- Signed extents from −31 through −1 select no words because adding 31 wraps into the range 0 through 30.
- Signed extent −32 selects 134,217,727 words.
- No signed extent is explicitly classified as an error.
- The maximum selected count is 134,217,727 words.

The initially read extent controls the entire traversal. The destination header is not reread to determine whether another iteration should occur.

### Updating the selected words

Words are processed in ascending order, starting at offset 4 and continuing in four-byte increments.

For each selected position, the replacement destination word is the bitwise union of:

1. The destination word read for the replacement calculation.
2. Bits present in the first source word but absent from the second source word.

For stable memory, this can be expressed as:

\[
\text{replacement}
=
\text{destination}
\;\mathrm{OR}\;
\left(\text{first source}\;\mathrm{AND}\;\mathrm{NOT}_{32}(\text{second source})\right)
\]

Consequences for each bit position are:

- An existing destination bit remains set.
- A clear destination bit becomes set only if the first source has that bit set and the second source has it clear.
- A set exclusion bit prevents the first source from adding that bit.
- A set exclusion bit does not clear a bit already present in the destination.

The replacement is compared with the destination word, and a difference contributes to the accumulated change indication. The replacement is then stored into the destination.

Every selected destination word is assigned, including words whose replacement equals their previous value. Detecting an earlier change does not stop traversal or skip later comparisons or writes.

### Change indication

The accumulated indication starts at zero. Once any comparison detects a difference, it remains one through the rest of the operation.

Under stable-memory assumptions, the return value is therefore one exactly when at least one selected destination word acquires at least one new set bit.

The function does not report:

- The number of changed words.
- The number of newly set bits.
- Which source contributed a bit.
- Whether unprocessed storage differs between the objects.

### Partial final words

The function processes complete 32-bit words. It does not mask the final word according to the extent’s remainder modulo 32.

For example, an extent of 1 still allows any of the 32 bits in the first destination data word to be added. Treating positions beyond the nominal extent as irrelevant or requiring them to remain zero would be a caller-side invariant, not behavior enforced here.

### Access ordering and overlap

The established traversal order is increasing word position. A destination store for one position occurs before processing proceeds to the next position.

Within a position, the replacement must be computed before it is compared and stored. The supplied expression does not establish a left-to-right order among the source reads and the destination read used to compute that replacement.

The supplied representation also includes a destination read in the comparison after replacement calculation. It does not establish whether generated machine code performs a separate physical load for that comparison or reuses an earlier value. Exact bus transactions, volatile-memory behavior, and concurrent-access semantics are not established.

There is no whole-array snapshot. If a destination write changes storage that a later source access will read, that later access uses the storage as it then exists. Shifted overlap can therefore propagate an earlier result into a later calculation.

Under stable memory:

- If the first source and second source are the same storage, they contribute no new bits.
- If the first source is exactly the destination, no new bits are added.
- If the second source is exactly the destination, the result at each position is the union of the original destination word and the first source word.

These exact-alias observations do not imply snapshot semantics for partially overlapping ranges.

## Side effects

Aliasing qualifies that statement: a destination write can also alter memory visible through a source address when the ranges overlap.

There is no visible allocation, deallocation, ownership transfer, callback, or dependency invocation. The supplied body contains no explicit global-state access. It does not establish any broader guarantees about the surrounding execution environment.

The function exposes no separate error result. Zero means “no detected change,” not “invalid input.” Invalid addresses, insufficient storage, unsupported alignment, or invalid address arithmetic are outside the demonstrated successful-call behavior; the supplied representation does not define their outcome or provide recovery.

The data operations are ordinary word reads and writes. Atomicity, synchronization, and transactional rollback are not established. In particular, no mechanism is visible for undoing earlier destination writes if a later access cannot complete.
