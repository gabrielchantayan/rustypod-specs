# F-4fa17f5395a5

## Purpose

F-4fa17f5395a5 describes a state-dependent sequence of narrow memory stores, repeated state-field writes, global zeroing, and eleven dependency invocations. The supplied representation ends at an invalid-instruction boundary rather than an explicit normal return.

The established contract is the ordering of these operations, their represented widths, their address and value calculations, and their explicit call arguments. A higher-level purpose—such as initialization, reset handling, device control, or decoding—is not established.

This document distinguishes three evidence levels:

- **Established static evidence:** operations, constants, widths, and ordering recoverable from the supplied representation.
- **Inferred interpretation:** machine-level interpretations not independently established by an ABI or execution trace.
- **documented_only:** unresolved behavior recorded without supplying a guessed implementation contract.

All behavior below is conditional on execution reaching the relevant operation. The supplied representation warns about invalid instruction data and overlapping global symbols. No runtime tests have been performed.

## Behavior

### 1. Initial stores

The initial 16-bit stored value is the low 16 bits of the entry address.

The function performs these operations in order:

1. Store that value as two bytes at the entry address.
2. Repeat the same two-byte store at the same address.
3. Store the same value as two bytes at twice the entry address.
4. Store the 32-bit state word at the state base plus 20 bytes.

The duplicate stores are separately represented operations. Their equivalence in ordinary RAM does not justify collapsing their observable access sequence: device mappings, instrumentation, and faults may distinguish them.

No explicit read of the previous contents of these destinations appears.

The doubled-address calculation and state-field address calculation use signed 32-bit forms in the representation. Their behavior outside the applicable arithmetic range is not independently established. Modular 32-bit address arithmetic is an inference, not an unconditional guarantee.

### 2. Initial dispatch and first result

F-D01 is invoked indirectly through a target calculated as the dispatch base plus `0x00000FFE`.

Its explicit arguments, in order, are:

1. The entry address shifted left by five bit positions.
2. The unchanged second explicit input.
3. The entry address plus the dispatch base.

The shift and addition are represented through signed 32-bit expressions. Negative operands, signed overflow, and conversion of the resulting numeric target to an executable address require an execution model not supplied here.

If F-D01 returns, F-D02 is invoked through the statically computed target `0x089112E9`. No explicit arguments are shown. Its 64-bit represented result supplies the first low and high words.

“No explicit arguments” does not imply absence of inputs through registers, stack state, globals, or other ambient state.

### 3. First result-dependent stores

From the low word returned by F-D02:

- The destination retains bits 0–26 and then shifts them right by three positions. Equivalently, result bits 3–26 become destination bits 0–23.
- The 16-bit stored value consists of result bits 3–18.

Bits are numbered from zero at the least significant bit. The destination is therefore between `0x00000000` and `0x00FFFFFF`, inclusive. It need not be aligned: result bit 3 becomes the destination’s least significant bit.

The represented value calculation includes a 32-bit unsigned left shift before the right shift. Bits shifted out of that 32-bit intermediate do not reappear. After final narrowing, the stored value is exactly the low 16 bits of the derived destination.

The operations are:

1. Store the derived 16-bit value at the derived destination.
2. Repeat that two-byte store.
3. Assign zero to the zeroed global, at its unspecified width.
4. Store the 32-bit state word at the state base plus 20 bytes.

### 4. Second dispatch and second result

F-D03 is invoked through the statically computed target `0x089112EB`.

Its explicit arguments are:

1. Zero.
2. The high 32-bit word returned by F-D02, represented through a signed 32-bit conversion.
3. `0x089102ED`.

The third argument is an established numeric value. It also serves as the base of the represented target calculation: adding `0x00000FFE` yields `0x089112EB`. Its semantic role is unknown; it is not established as a valid data pointer, executable pointer, or continuation address.

If F-D03 returns, F-D04 is invoked through target `0x08911351`, with no explicit arguments shown. Its result is represented as 64 bits.

### 5. Second result-dependent stores

The low word returned by F-D04 undergoes the same extraction as the first result:

- Destination bits 0–23 come from low-word bits 3–26.
- The stored 16-bit value comes from low-word bits 3–18.

The function performs, in order:

1. A two-byte store at the derived destination.
2. An identical two-byte store at the same destination.
3. Zeroing of the zeroed global.
4. A four-byte store of the state word at the state base plus 20 bytes.

The same destination range, possible misalignment, and low-16-bits relationship apply.

### 6. Third dispatch and third result

F-D05 is invoked through the statically computed target `0x08911353`.

Its explicit arguments are:

1. Zero.
2. The high 32-bit word returned by F-D04, represented through a signed 32-bit conversion.
3. `0x08910355`.

The third argument is also the base of this target calculation: adding `0x00000FFE` yields `0x08911353`. Its numeric value is established; its semantic purpose remains unknown.

If F-D05 returns, F-D06 is invoked through target `0x089113B9`, with no explicit arguments shown. Its result is represented as 64 bits.

### 7. Third result-dependent stores

The third result uses a different destination extraction:

- The destination is the low 32-bit word shifted logically right by eight positions.
- The stored value is bits 8–23 of the 64-bit result, retained as 16 bits.

Those value bits lie entirely within the low word. The high word does not contribute to either this destination or this stored value.

The destination ranges from zero through `0x00FFFFFF`. It need not be aligned: low-word bit 8 becomes destination bit 0. The stored value again equals the destination’s low 16 bits.

The function performs:

1. A two-byte store of the derived value at the derived destination.
2. The same two-byte store again.
3. Zeroing of the zeroed global.

There is no represented state-field store between this third global zeroing and F-D07.

### 8. Final call sequence

2. The high word returned by F-D06, converted through a signed 32-bit expression and decreased by 612.
3. `0x0000004B`, or 75.
4. Zero.

The subtraction is represented as signed 32-bit arithmetic. Behavior when it falls outside that signed range is **documented_only**; wrapping must not be assumed without an execution model.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Each assumes that earlier operations complete and the required accesses and calls are supported.

### Initial duplicate stores

For an entry address of `0x00001234`, the first three stores are:

1. Value `0x1234` at `0x00001234`.
2. Value `0x1234` at `0x00001234` again.
3. Value `0x1234` at `0x00002468`.

Each is two bytes. The state-field store follows before F-D01.

### First and second extraction

If F-D02 or F-D04 returns low word `0x01234568`, the corresponding destination is `0x002468AD`, and the stored value is `0x68AD`.

Two stores occur at that odd address. The function does not align or reject it.

Low words `0x01234568` and `0xF9234568` produce identical stores in these phases because bits 27–31 are discarded. This equivalence does not constrain high words or dependency side effects.

### Dispatch values and targets

If F-D02 returns high word `0x12345678`, F-D03 receives:

- Zero.
- `0x12345678`.
- `0x089102ED`.

Its represented target is `0x089112EB`.

If F-D04 returns high word `0x23456789`, F-D05 receives zero, `0x23456789`, and `0x08910355`, at represented target `0x08911353`.

The third arguments are not replaced with the computed targets.

### Third extraction and high-word independence

If F-D06 returns low word `0x12345678`, the function stores `0x3456` twice at `0x00123456`.

Changing only the high word does not change these stores. It changes the input to F-D07’s second-argument arithmetic.

### Final arithmetic

For an F-D06 high word of 1,000, F-D07 receives the argument sequence `0xFFFFFF1C`, 388, 75, and zero, through represented target `0x08910BB3`.

This example stays within signed 32-bit range and does not resolve overflow behavior.

### Zero destination and maximum destination

A zero low word produces destination zero and stored value zero in all three result-processing phases. There is no represented null-address rejection.

A low word of `0xFFFFFFFF` produces destination `0x00FFFFFF` and value `0xFFFF` in all three phases. A two-byte store begins there; the destination bound is not a guarantee that the entire access remains below `0x01000000`.

If a store faults, subsequent operations are not established as occurring.
