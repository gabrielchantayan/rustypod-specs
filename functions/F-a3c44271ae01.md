# F-a3c44271ae01

## Purpose

F-a3c44271ae01 replaces a target record’s association and four-byte payload, derives a numeric field from the associated record, and conditionally inserts the target into an indexed linked structure.

The established contract is the ordering of dependency calls and memory accesses. Interpreting the association as a parent, the numeric field as a depth, and the indexed structure as depth-specific lists is inferred intent, not an established domain requirement.

The operation is not transactional. Dependencies run before the association and payload are replaced. Conditional insertion follows those replacements. No validation, rollback, or explicit error result is visible.

## Interface

### Inputs and result

| Input | Representation | Established use |
|---|---|---|
| Target address | 32-bit address-valued argument | Identifies the record read and modified. |
| Association address | 32-bit address-valued argument | Passed to F-2609ef4ae406, stored in the target, and used to read a four-byte numeric field. |
| Payload | Four opaque bytes | Stored at target offset `0x18`, without visible interpretation. |

No return value is specified. Normal return does not distinguish insertion from skipped insertion.

Neither address is checked for nullness, alignment, accessibility, object identity, or layout compatibility. A zero association address does not mean “clear association without further access”: if execution reaches the numeric-field update, a read at association address plus `0x08` is attempted.

### Accessed record fields

| Offset | Width | Established use |
|---|---:|---|
| `0x08` | 4 bytes | Numeric field; replaced using the associated record’s corresponding field, then reread to derive an index. |
| `0x0c` | 4 bytes | Link field cleared in the target during insertion; written in the record selected by the final link read. |
| `0x10` | 4 bytes | Link field receiving the selected table entry; later read separately for a nonzero test and, conditionally, a destination calculation. |
| `0x14` | 1 byte | Bit 0 gates insertion and is set during insertion. |
| `0x18` | 4 bytes | Payload destination. |
| `0x1c` | 4 bytes | Existing association tested before replacement; then receives the association argument. |

These accesses do not establish complete record sizes, allocation boundaries, padding, or byte order.

The associated record requires a readable four-byte field at offset `0x08` when that read occurs. A record selected for the final link repair requires a writable four-byte field at offset `0x0c`.

### Shared-state indirection

A global pointer variable identifies a four-byte shared slot. The function reads that global pointer variable twice before the first dependency call:

- The first pointer value is retained for a later slot-content read.
- The second pointer value locates the slot whose contents supply the first dependency’s first argument.

These are distinct reads of the global pointer variable. The two slot addresses are equal only if that variable has the same value at both reads.

After the dependency phase and the record replacements, the function reads the slot at the **retained first address**. That slot’s then-current contents become the table base for possible insertion. It does not reread the global pointer variable to choose that later slot.

## Behavior

### Initial shared-state reads and dependency calls

The established access and call order is:

1. Read the global pointer variable and retain the resulting slot address.
2. Read the same global pointer variable again.
3. Read four bytes from the slot identified by the second pointer read.
4. Call F-03b9616af95f with those slot contents as the first argument and the target address as the second.
5. Call F-2609ef4ae406 with the association address.
6. Read four bytes at target offset `0x1c`.
7. If that value is nonzero, call F-029930293dcb with no explicit arguments.

The first retained slot address does not supply the first dependency’s argument unless the two global pointer reads identify the same slot.

The association test occurs after the first two calls. Either dependency may therefore affect whether F-029930293dcb is called. The test does not necessarily observe the association present on entry.

No old association value is explicitly passed to F-029930293dcb. Its call cannot be specified as releasing that association solely from this evidence.

No dependency return value controls a visible decision. The remaining behavior is conditional on those calls returning normally. Their internal failure or non-returning behavior is unknown.

### Association, payload, and numeric-field replacement

After the dependency phase, the function performs these accesses in order:

1. Write the association address to target offset `0x1c`.
2. Write the four-byte payload to target offset `0x18`.
3. Read four bytes at association offset `0x08`.
4. Add one and write the four-byte result to target offset `0x08`.

The associated numeric field is not captured on entry. It is read after both preceding stores, so overlapping storage can affect the value observed.

Self-association is not rejected. When the target and association identify the same record, and no other relevant storage overlaps or changes, the numeric field is incremented from its value at the time of the read.

### Later shared-state read and insertion gate

The function next:

1. Reads four bytes from the slot at the address retained by the **first** global pointer read.
2. Retains those contents as the prospective table base.
3. Rereads the target numeric field at offset `0x08`.
4. Subtracts one to form a 32-bit candidate index.

The slot-content read occurs even if insertion is subsequently skipped.

Changing the global pointer variable during a dependency does not by itself redirect this later read. Changing the contents of the retained slot can change the table base. Earlier direct stores can also affect those contents if storage overlaps.

The candidate is interpreted as signed 32-bit for the numeric gate:

- A negative candidate skips insertion without reading the target flag byte for this gate.
- A nonnegative candidate causes a read of the byte at target offset `0x14`. Insertion proceeds only if bit 0 is clear.

Bits 1 through 7 do not determine whether insertion proceeds.

Under 32-bit wrapping arithmetic, with stable non-overlapping storage, the increment followed by decrement makes the candidate’s bit pattern equal to the associated numeric field’s previously read bit pattern. This is a conditional arithmetic relationship, not an entry-time snapshot guarantee.

A negative candidate is not reported as an error. The earlier calls and replacements are not undone.

### Conditional insertion

When the candidate is nonnegative and the observed flag bit is clear, the selected table entry is four bytes at the retained table base plus four times the candidate.

The insertion accesses occur in this order:

1. Write zero to target offset `0x0c`.
2. Read the selected four-byte table entry.
3. Write that value to target offset `0x10`.
4. Write the target address into the selected table entry.
5. Read the byte at target offset `0x14`, set bit 0, and write the resulting byte back.
6. Read four bytes at target offset `0x10` for a nonzero test.
7. Only if that test is nonzero, read four bytes at target offset `0x10` **again**.
8. Use the value from this second read as an address and write the target address at its offset `0x0c`.

The flag update preserves bits 1 through 7 as observed by the update’s own read. It does not restore them from the earlier gate read.

The two final link reads have different roles. The first decides whether the final write is attempted. The second determines the write destination. The tested value is not preserved as the destination address.

Consequently, if external mutation changes the link between these reads, the write may address a different record from the one that passed the test. A second value of zero is not checked again; the represented destination would then be address `0x0c`, subject to address semantics and access validity.

Under conventional, disjoint list invariants and without intervening mutation, the target becomes the selected head, its previous link becomes zero, its next link identifies the former head, and a nonzero former head receives the target as its previous link. Those conditions are necessary for this conventional interpretation.

### Skipped insertion

If the numeric gate fails or flag bit 0 is already set, the function performs none of the insertion-phase stores.

It does not directly clear the link fields, replace a table entry, set the flag, or repair another record on that path. Dependency effects remain unconstrained.

An already-set membership bit does not prevent association, payload, or numeric-field replacement. It also does not prevent the later shared-slot read.

### Widths and arithmetic limits

Numeric fields, table entries, and represented addresses are four bytes. The flag access is one byte.

The signed gate treats candidate bit patterns `0x00000000` through `0x7fffffff` as nonnegative, and `0x80000000` through `0xffffffff` as negative.

Under a 32-bit wrapping interpretation:

- Incrementing `0xffffffff` produces zero; decrementing that result produces candidate `0xffffffff`, which skips insertion.
- Incrementing `0x7fffffff` produces `0x80000000`; decrementing that result produces candidate `0x7fffffff`, which passes the numeric gate.
- Scaling the candidate by four can exceed the 32-bit address range. For example, candidate `0x40000000` has a scaled displacement of zero modulo \(2^{32}\).

No upper-bound, allocation-size, or address-overflow check is visible. Passing the signed gate does not establish a valid table entry.

The supplied representation does not independently establish portable signed-overflow behavior or complete machine address and fault semantics. Wrapping boundary examples are conditional on that arithmetic interpretation.

## Side effects

### Direct memory effects

On normally completed paths, the function directly replaces the target association, payload, and numeric field.

During insertion it additionally writes:

- The target’s two link fields.
- The target flag byte.
- One selected table entry.
- A previous-link field at the address obtained by the second final link read, if the first final link read was nonzero.

The final destination is not unconditionally the former table head. Aliasing or intervening mutation can distinguish those addresses.

The function visibly performs no allocation, deallocation, locking, memory barrier, or explicit ownership operation.

### Dependency effects and lifetime requirements

Dependency implementations are unknown. They must not be assumed to preserve records, globals, slot contents, table entries, or allocation lifetimes.

The evidence does not establish whether association replacement retains an object, transfers ownership, borrows storage, or releases a previous resource. The payload’s ownership significance is likewise unknown.

Normal completion requires every access to be valid when performed, including accesses through the retained slot address after dependencies return. Retaining an address does not demonstrate that its storage remains alive.

### Partial updates and concurrency

No recovery sequence is visible. A fault during the associated numeric-field read can occur after the target association and payload have already been replaced.

Insertion exposes intermediate ordering: the table entry is replaced before the membership flag is set and before the final previous-link repair.

No synchronization guarantee is established. The separate initial global pointer reads and separate final link reads must not be collapsed into single snapshots when describing the listing. This observation does not establish that unsynchronized concurrent mutation is safe or supported.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, dependencies return normally without changing relevant memory, all accesses are valid, storage does not overlap, the global pointer is stable across its two initial reads, and no external mutation occurs.

### Empty selected entry

Given an associated numeric field of 3, a clear target membership bit, and a zero table entry at index 3:

- The association and payload are replaced.
- The target numeric field becomes 4.
- Candidate 3 selects entry 3.
- Both target links become zero.
- Entry 3 becomes the target address.
- Flag bit 0 becomes set.
- The final link test observes zero, so no second final link read or other-record write occurs.

### Existing head

Given the same numeric values and an entry identifying another valid record:

- The target next link receives that record’s address.
- The table entry receives the target address.
- The final link test is nonzero.
- The separate destination read obtains the same address under the stability assumptions.
- That record’s previous link receives the target address.

The other record’s next link is not directly written.

### Membership already set

With a nonnegative candidate and flag byte `0x81`, association, payload, and numeric updates still occur, but insertion is skipped.

With flag byte `0x80` instead, insertion proceeds and the flag becomes `0x81`, assuming no intervening change. The high bit does not inhibit insertion.

### Negative and signed-boundary candidates

Under 32-bit wrapping arithmetic:

- Associated value `0xffffffff` produces target numeric value zero and candidate `0xffffffff`. Insertion is skipped without a gate read of the flag.
- Associated value `0x7fffffff` produces target numeric value `0x80000000` and candidate `0x7fffffff`. A clear membership bit permits an insertion attempt, but valid table addressing is not established.

Neither case produces an explicit error result.

### Two different initial slot addresses

Suppose the first global pointer read identifies slot A, while the second identifies slot B:

- F-03b9616af95f receives the contents read from slot B.
- The later table-base read uses slot A.
- Equality of A’s and B’s contents is not required.

If a dependency subsequently redirects the global pointer to slot C, that change alone does not redirect the later read away from A. If it changes A’s contents, those changed contents are observed by the later read.

### Separate final link reads

If the first final link read yields a nonzero address A, but the second yields address B, the previous-link write uses B, not A.

If the first read yields zero, no second read or previous-link write occurs. If the first is nonzero and the second is zero, no second null check prevents the attempted write at offset `0x0c` from zero. Access validity and failure behavior remain separate preconditions and unknowns.

### Dependency-modified association

If the target association is initially zero but either of the first two dependencies makes it nonzero, F-029930293dcb is called. If those calls leave it zero, that call is omitted.

### Self-association

If target and association addresses are identical and the numeric field initially contains 5, the association becomes self-referential, the numeric field becomes 6, and candidate 5 governs insertion. No self-association rejection occurs.
