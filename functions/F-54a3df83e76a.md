# F-54a3df83e76a

## Purpose

F-54a3df83e76a conditionally searches an inclusive signed-integer interval. Admission depends on two preliminary observations being unequal. If admitted, the function returns the first visited candidate whose dynamically selected operation produces the requested integer value.

Ordinary rejection and ordinary unsuccessful exhaustion return −1. A successful match at candidate −1 also returns −1; the interface provides no separate success indicator.

Preliminary processing is required even for an empty interval. Consequently, returning −1 without evaluating a candidate does not imply an absence of dependency calls or external effects.

**Established static evidence:** unequal captured observations admit the search; candidates are visited in ascending order; the upper endpoint is inclusive; operation selection occurs separately for each visit; matching uses exact integer equality; a match returns immediately.

**Inferred intent:** lookup of a candidate associated with a requested value in a supplied context. The application meanings of the context, candidates, and values are not established.

All normal-completion requirements below assume valid reached accesses, supported arithmetic, and normally returning dependencies. No runtime tests have been performed.

### Search and exact matching

An admitted search visits the inclusive interval from the lower endpoint through the upper endpoint, in ascending unit steps.

If the lower endpoint exceeds the upper endpoint, no candidate is visited and normal completion returns −1. This interval check does not bypass preliminary processing.

Each visited candidate has a separate call to F-56a66efac853. Its argument is the context-derived address at displacement 756, not the admission integer previously read there. The candidate is not an explicit argument to this provider.

The returned object supplies the dispatch-base value and callable entry for that visit. The selected operation receives that object and the current candidate. Its consumed integer result must equal the requested value exactly to constitute a match. A merely nonzero result, equal sign, or approximate value is insufficient.

A match returns the current candidate immediately. There is no candidate advancement or subsequent provider call on that successful path. Thus the returned candidate is the earliest match in the actual ascending visit sequence. This does not establish what an unvisited operation would have returned under different state.

Provider objects and callable entries are not cached across visits by this function. Repeated provider calls may return the same object, different objects, or objects selecting different operations.

Admission observations are not directly repeated during searching. Nevertheless, provider calls and selected operations may change context storage, globals, dispatch information, or other reachable state. Such effects may influence later visits. No dependency is assumed to preserve globals.

### Exhaustion and arithmetic boundaries

Every nonmatching visit requires candidate advancement, including a nonmatch at the upper endpoint. Ordinary exhaustion therefore requires an increment followed by a candidate value greater than the upper endpoint.

For an upper endpoint below the applicable signed maximum, the immediate successor of that endpoint is representable in the same signed range. Subject to the other validity conditions, a final nonmatch can therefore lead to ordinary exhaustion and result −1.

A nonmatch at the signed maximum is different: the required mathematical successor is outside the signed range. The supplied evidence does not establish the execution semantics of that arithmetic. Undefined signed overflow would leave subsequent behavior unspecified; wrapping arithmetic could permit further visits rather than exhaustion. Neither wrapping nor a particular overflow response is established here.

A match at the signed maximum returns without that increment and does not encounter this particular overflow boundary.
