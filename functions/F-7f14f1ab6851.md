# F-7f14f1ab6851

## Purpose

F-7f14f1ab6851 compares two memory regions over a caller-supplied byte count. With valid, stable input memory, it returns zero when all requested bytes match. Otherwise, it returns the first differing byte from the first region minus the corresponding byte from the second region, treating both bytes as unsigned values.

The routine uses four-byte equality checks when both starting addresses are four-byte aligned and the requested count is at least four. It uses individual byte comparisons to determine the returned difference.

This is a bounded binary comparison, not a string comparison. A zero-valued byte is ordinary data and does not terminate comparison.

These conclusions describe the supplied static representation. No runtime tests have been performed.

## Interface

### Inputs

The function accepts three arguments:

- **First region:** an address from which bytes may be read.
- **Second region:** an address from which bytes may be read.
- **Byte count:** an unsigned count of bytes to compare.

The supplied representation uses unsigned byte loads, an unsigned count, and a signed integer return type. Its address-alignment calculation converts addresses to an unsigned integer and examines the low two bits.

The apparent target model has eight-bit bytes and 32-bit integers. Under that model:

- The count ranges from 0 through 4,294,967,295.
- A four-byte comparison reads 32 bits from each region.
- Each individual byte is extended to an unsigned 32-bit value before subtraction.
- The returned byte difference ranges from −255 through +255 under the intended signed interpretation.

These widths are supported by the supplied representation, but no independent ABI or executable evidence accompanies it.

### Output

For stable, readable input regions under the apparent target model:

- **Zero:** every byte within the requested count is equal.
- **Negative:** the first differing byte in the first region is smaller.
- **Positive:** the first differing byte in the first region is larger.

The magnitude is the arithmetic byte difference, not merely a normalized ordering indicator. For example, comparing byte values 0 and 255 produces −255 under the intended return interpretation.

The subtraction is represented as unsigned arithmetic followed by return through a signed integer interface. Negative results therefore rely on the target’s unsigned-to-signed conversion behavior. The expected two’s-complement interpretation is clear, but is not independently verified here.

### Preconditions

For a nonzero count, both regions must provide readable memory throughout the requested range. The routine does not validate addresses or lengths.

For the normal comparison contract, the contents must remain stable during the call. The four-byte path rereads its final examined block, so changing memory can alter both control flow and subsequent read locations.

The regions may overlap: the routine performs no explicit writes to either region and does not require distinct storage. Each accessed location must still be valid for the actual load width.

A zero count causes no region-data reads. Consequently, usable backing storage is not required merely to obtain the zero-count result. Whether particular pointer representations, including null pointers, are admissible at the external language or ABI boundary is not independently established.

No ownership is transferred. The routine neither retains the supplied addresses nor explicitly allocates or releases storage.

## Behavior

### Choosing the comparison path

The four-byte path is selected only when both conditions hold:

1. The count is greater than three.
2. Both starting addresses have their low two bits clear.

Thus, a count of exactly four does not by itself select a four-byte comparison. Either unaligned address sends the operation directly to byte comparison.

For counts from zero through three, the routine does not enter the four-byte path.

The routine does not first consume bytes to bring an unaligned address into alignment. If either starting address is unaligned, comparison proceeds byte by byte for the requested range.

### Four-byte equality scanning

On the aligned path, the routine compares one four-byte block from each region.

For a block reported equal:

- Both working addresses advance by four bytes.
- The remaining count decreases by four.
- Another four-byte block is examined only if more than three bytes remain.

For a block reported unequal:

- The remaining count is not reduced for that block.
- The block’s starting addresses are retained for possible bytewise comparison.
- Four-byte scanning stops.

Four-byte values are used only to establish equality. Their signed ordering does not determine the result. Consequently, the normal first-differing-byte result does not depend on interpreting a four-byte block in little-endian or big-endian order.

### Repeated check of the final four-byte block

After four-byte scanning stops, the routine evaluates equality of the last examined block again.

In the supplied representation, this is a second pair of four-byte dereferences, not simply reuse of the earlier comparison result.

- If the repeated check reports inequality, both working addresses are set back to the beginning of that last block.
- If it reports equality, the working addresses remain advanced past that block.

The remaining count is not adjusted by this repeated check.

With stable memory, this produces the expected behavior:

- An unequal block is revisited byte by byte.
- Equal blocks remain consumed.
- A final remainder of one to three bytes is compared after the equal blocks.
- If equal blocks exhaust the count, the function returns zero.

The repeated check matters for mutable or side-effecting memory. It is not an atomic snapshot operation.

### Zero remaining count

After the optional four-byte phase, a remaining count of zero returns zero immediately.

When the original count was zero, this occurs without any data access.

When the four-byte phase reduces the count to zero, its repeated final-block check has already occurred before this return. A zero remainder therefore does not mean that the last block is read only once.

### Bytewise comparison

The bytewise phase compares bytes in increasing address order.

Each compared byte from the first region is treated as unsigned, as is the corresponding byte from the second region. The function stops at the first observed difference and returns their subtraction.

If a compared pair is equal, comparison continues until the remaining requested bytes have been consumed.

The bytewise phase is organized around pairs of byte comparisons:

- With an even remaining count, it begins with the first byte of a pair.
- With an odd remaining count, it begins at the second comparison position of that structure, effectively handling one leading byte before any complete pairs.

This organization does not skip an input byte. Under stable-memory conditions, it compares exactly the requested sequence unless a difference ends comparison earlier.

### Odd counts and unsigned wraparound

For an odd remaining count, the routine increments the count before consuming the leading byte, then decreases it by two after an equal comparison.

Under 32-bit unsigned arithmetic, an incoming remaining count of 4,294,967,295 wraps to zero when incremented. If the leading byte is equal, the subsequent subtraction by two wraps to 4,294,967,294, allowing the paired comparisons to continue.

Thus, the temporary wraparound does not itself establish an immediate zero-result bug. Completing such a comparison still requires valid readable ranges and address arithmetic over the full requested extent. Those address-space conditions are not guaranteed by the routine.

## Side effects

### Explicit state changes

The supplied body contains:

- No writes to either input region.
- No explicit global-state reads or writes.
- No allocation or deallocation.
- No retained input addresses.
- No calls to other functions.

Address advancement and count changes are internal working-state changes. They do not modify caller-held pointer variables or the original count argument.

### Observable reads

For ordinary stable memory, the read pattern is:

- **Zero count:** no region-data reads.
- **Unaligned input:** byte reads in increasing offset order, stopping at the first difference or the requested limit.
- **Aligned input with at least four bytes:** four-byte equality reads, a repeated equality read of the last examined block, and any necessary byte reads afterward.

A four-byte comparison can access bytes later than the first differing byte. For example, a difference at the first byte of an aligned block does not prevent the initial four-byte loads from also reading the other three bytes of that block.

The supplied representation explicitly captures the first byte operand before the second in each bytewise comparison. It does not establish an operand evaluation order between the two dereferences within a four-byte inequality expression.

These are source-facing access properties. The exact number, ordering, and width of machine transactions require executable or target-specific evidence, particularly because the accesses are not marked volatile.

### Invalid and changing memory

There is no explicit error return for inaccessible memory, invalid address arithmetic, or incompatible access semantics. Such conditions may fault or fall outside the applicable execution model.

If the memory changes between the initial and repeated checks of a four-byte block, the routine can advance or rewind its working addresses inconsistently with the remaining count:

- An initially unequal block that becomes equal can leave the addresses advanced while its bytes remain included in the count.
- An initially equal block that becomes unequal can cause already-consumed bytes to be revisited while the count remains reduced.

The first case can lead to reads beyond the originally requested range. The stable-memory comparison contract must not be extended to concurrent mutation or memory-mapped devices without additional evidence.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not reported test results. Unless otherwise stated, they assume eight-bit bytes, 32-bit arithmetic, valid stable memory, and the expected signed interpretation of the result.

### Empty comparison

With count zero, the result is zero and neither region’s contents are read.

This condition applies regardless of whether the two addresses are equal. Admissibility of the address representations themselves remains an external precondition.

### Single-byte equality

With count one and byte value 128 in both regions, the result is zero.

Only that byte participates in comparison. A following byte is outside the requested range.

### Unsigned byte ordering

With count one, first-region byte 128, and second-region byte 127, the result is +1.

With first-region byte 0 and second-region byte 255, the result is −255 under the expected signed return interpretation. The value 255 is not treated as a negative byte.

### Earliest difference controls the result

For three-byte regions containing:

- First region: 7, 20, 250.
- Second region: 7, 23, 0.

The result is −3. The third-byte difference does not affect the result because the second byte differs first.

### Zero bytes do not terminate comparison

For three-byte regions containing:

- First region: 0, 0, 5.
- Second region: 0, 0, 9.

The result is −4, not zero.

### Aligned four-byte match

With both addresses four-byte aligned, count four, and equal contents, the result is zero.

The supplied representation checks the four-byte block in the scanning phase and checks that same block again before returning.

### Aligned four-byte mismatch

With both addresses aligned and count four, a differing block is subsequently examined byte by byte from the block’s beginning.

If the first three byte pairs are equal and the fourth bytes are 200 and 150, the result is +50. The four-byte integer ordering is not the returned result.

### Equal block followed by a tail

With aligned addresses and count seven, equal first four bytes are consumed through the four-byte path. The last three bytes are then compared bytewise.

A difference at offset five determines the result; a difference at offset six is not reached afterward.

### Unaligned comparison

With count eight and either address unaligned, the four-byte path is not selected. If all eight byte pairs match, the result is zero.

No alignment-seeking prefix is performed.

### Shared storage

If both arguments identify the same stable readable range, the result is zero for every valid requested count. No separate-storage requirement is present.
