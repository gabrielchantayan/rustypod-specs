# F-3394ad38386a

## Purpose

F-3394ad38386a removes every occurrence of a specified 32-bit value from a contiguous sequence, shortens the sequence’s recorded logical extent, and then invokes F-08cbce22fb03 over a descending set of internal positions.

The directly visible removal phase is stable: retained values remain in their original relative order immediately before the dependency calls. That ordering is not guaranteed on return because the dependency receives access to the sequence storage and its behavior is not supplied.

The final descending traversal is consistent with bottom-up heap construction or repair. This is inferred intent, not an established postcondition. Neither a heap property nor any other final ordering can be specified without the dependency’s contract.

## Interface

### Inputs

The function has three arguments:

1. **Sequence descriptor address.** An address identifying a record containing at least four 32-bit words.
2. **Removal value.** A 32-bit integer compared for equality with sequence elements.
3. **Incoming scratch value.** A 32-bit integer whose incoming value does not affect the visible behavior. During the initial search, it is replaced locally by examined element values. It is not returned or written back to its caller.

The descriptor has the following visible layout under the represented 32-bit address model:

| Byte offset | Width | Visible role |
|---|---:|---|
| 0 | 32 bits | Address of the first sequence element |

| 12 | 32 bits | Opaque value passed to F-08cbce22fb03 |

The word at offset 8 must not be described as a capacity field on the available evidence. The word at offset 12 must likewise not be assigned a particular type or semantic role beyond its observed forwarding to the dependency.

Sequence elements are four bytes wide. Traversal advances in four-byte increments. Equality with the removal value concerns the complete 32-bit element value; signedness does not change this equality test.

There is no return value and no explicit success or failure result.

Observable results are memory changes:

## Behavior

### 1. Capture the initial range and find the first match

The function first reads the descriptor’s logical-end address, then its begin address.

It searches from the begin address toward that captured end address:

- Before each element read, it checks whether the current address equals the captured end.
- If not at the end, it reads the current 32-bit element.
- It stops at the first element equal to the removal value.
- Otherwise, it advances by four bytes and continues.

An empty range causes no element read during this search. If the removal value is absent, the search reaches the captured end.

No element is written during the search.

### 2. Compact retained values after the first match

If a match was found, that position becomes the first available destination. Examination resumes at the following element, not at the matched element itself.

For each subsequent element up to the captured end:

- An element equal to the removal value is skipped.
- Any other element is copied to the current destination.
- The destination then advances by four bytes.

The visible access pattern for a retained element after the first match includes a read for the comparison and a further read as the value being copied. The destination write follows those reads. A matching element in this phase is read for comparison but is not copied.

For an ordinary non-overlapping descriptor and stable sequence:

- Elements before the first match are left untouched.
- Every retained element after the first match moves toward the beginning.
- The destination remains earlier than the examined source.
- Retained elements preserve their original relative order.
- The final destination identifies the new logical end.

If no match was found, there is no compaction pass and no element write by this phase.

### 3. Perform the visible range-finalization operations

After compaction, the function rereads the descriptor’s current logical-end field. It also rereads the begin field to decide whether the current descriptor is nonempty.

For an ordinary stable descriptor, the reread end equals the initially captured end. Under that condition, an intervening range-copy loop has no iterations. A subsequent loop advances a cursor to the recorded end without reading or writing sequence elements.

For a nonempty descriptor, the function writes its logical-end field using a 32-bit byte-address adjustment:

- It obtains the byte difference between the initially captured end and the compaction destination.
- It masks that difference with `0xfffffffc`.
- It subtracts the masked quantity from the descriptor’s then-current end value.
- It stores the resulting 32-bit value back into the end field.

For valid four-byte element ranges, the difference is already a multiple of four, so the mask does not change it. If the initial sequence contains \(N\) elements and \(R\) match the removal value, the ordinary result is:

\[
\text{new end} = \text{begin} + 4(N-R).
\]

Important boundary cases:

- **Initially empty:** no end-field write occurs in this phase.
- **Nonempty, no matches:** the end field is still assigned, but its stored value is unchanged.
- **All elements match:** the end field becomes equal to the begin field.
- **Some elements match:** the end field becomes the compaction destination.

The extra loops are not a general guarantee of correctness if descriptor fields change during processing. In particular, differing captured and reread boundaries can cause additional element copies or cursor traversal. No synchronization or recovery behavior is visible.

### 4. Read the post-removal descriptor state

After the range-finalization phase, the function reads:

1. The begin address.
2. The opaque word at descriptor offset 12.
3. The logical-end value used to derive the element count.

It obtains the count by subtracting the begin address from the end value and shifting the resulting 32-bit quantity right by two.

For a valid, nonnegative, four-byte-aligned extent, this is exactly division of the byte length by four. It is not an independent check that the addresses form a valid sequence.

The begin address, count, and opaque word are then retained locally for the dependency traversal. This function does not refresh those three values between dependency calls.

### 5. Invoke the dependency in descending position order

If the derived signed count is at most one, no dependency call occurs.

For a count \(N>1\), the first position is:

\[
\left\lfloor \frac{N-2}{2} \right\rfloor.
\]

The function invokes F-08cbce22fb03 at that position and then at every smaller position through zero, inclusive.

Each invocation receives, in order:

1. The retained begin address.
2. The current position.
3. The retained element count.
4. The 32-bit element currently stored at that position.
5. The retained opaque descriptor word.

The element supplied as the fourth argument is read anew for each invocation. Consequently, an earlier dependency call can affect the element value supplied to a later call.

For an ordinary valid count, the number of dependency calls is \(\lfloor N/2\rfloor\).

The call at position zero occurs before termination of the traversal. There is no further direct descriptor or element processing after the last dependency invocation.
