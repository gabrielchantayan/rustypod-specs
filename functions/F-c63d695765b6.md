# F-c63d695765b6

## Purpose

F-c63d695765b6 searches a sequence of candidate records at 36-byte intervals. Before examining each candidate, it obtains a signed bound from F-fd477cd1a249. If that bound permits examination, it reads an integer field at byte offset 24. The first candidate whose field is nonzero is passed to F-4042d12a1376, and its zero-based index is returned.

If the current bound is less than or equal to the current index, the function invokes its exit dependency and returns −1 without reading that candidate’s field.

The selection predicate is **nonzero**, not positive. Negative field values qualify.

The search has a finite index limit even when the bound changes. Because the index advances only when a representable signed bound exceeds it, the index cannot overflow. Address arithmetic and storage validity are separate concerns and can fail before that limit is reached.

The selected-record dependency receives the candidate address, 36, and zero. Those arguments do not establish that it clears, releases, reserves, or otherwise transforms the record.

## Interface

**Explicit inputs:** None.

**Implicit inputs:**

- A shared location containing an integer-represented base address.
- Each signed bound returned by F-fd477cd1a249.
- The integer selection field of each candidate actually examined.
- State accessed or changed by the dependencies.

**Output:** A signed integer with two normal outcomes:

- **−1:** The latest bound is less than or equal to the current index.
- **A nonnegative index:** That candidate’s field was observed to be nonzero, F-4042d12a1376 was called for it, and the exit dependency returned.

The return value does not report the result of the selected-record operation. Results from the entry, selected-record, and exit dependencies are not inspected.

## Behavior

### Entry and base capture

F-4c6d30ac2311 is called first, without explicit arguments.

After it returns, the index is initialized to zero and the shared base value is read once. That captured value becomes the first candidate address.

The ordering is significant:

- The entry dependency can change the base value before capture.
- Subsequent changes to the shared base location do not cause a reload.
- Capturing the base does not preserve the allocation or freeze the memory it identifies.

No dependency is assumed to preserve the shared location, candidate contents, or storage lifetime.

### Bound query before each field read

F-fd477cd1a249 is called before every possible candidate-field read.

Its result is compared with the current index using a signed comparison:

- If the bound is less than or equal to the index, F-cc60a532ba6c is called, followed by return of −1.
- If the bound is greater than the index, the candidate’s field at offset 24 is read.

The bound is queried again after every zero-valued candidate. It is not captured once as a fixed search limit.

Consequently, a later bound can stop the search earlier or permit more examinations than an earlier bound would have permitted. A negative or zero initial bound stops the search before any candidate-field read.

This comparison provides only a control-flow condition. A sufficiently large bound does not establish that the corresponding candidate exists.

### Zero-valued candidate

When the permitted field read produces zero:

1. The index increases by one.
2. The candidate address advances by 36 bytes.
3. The next bound query occurs.

No selected-record operation occurs for that candidate. The function performs no direct record write on this path.

The address advance occurs before the next bound query. Thus, a later bound that would stop the search does not prevent the preceding address-addition operation from being evaluated.

For a valid arithmetic progression, candidate index **k** has starting address equal to the captured base plus **36k** bytes. Its field is at the captured base plus **36k + 24** bytes. These formulas describe the sequence; they do not establish that the necessary storage exists.

### Nonzero candidate

When the field is nonzero, the search stops at that candidate. F-4042d12a1376 is called with these ordered arguments:

1. The current candidate’s starting address.
2. The integer value 36.
3. The integer value zero.

After that dependency returns, F-cc60a532ba6c is called. Once the exit dependency returns, the selected index is returned.

There is no subsequent field read, no search of a later candidate, and no inspection of the selected-record dependency’s result.

The returned index identifies the candidate whose field was observed to be nonzero. It does not certify the candidate’s state after either subsequent dependency.

### Finite index progression

Index overflow is unreachable through the established progression.

The index starts at zero. An increment occurs only after a bound greater than the current index has been returned and the candidate’s field has been read as zero. Since every bound is at most M, any increment starts from an index at most M − 1. Its result is therefore at most M and remains representable.

If the index reaches M, every representable bound is less than or equal to it. The next bound query must take the exhaustion path. The field of candidate M cannot be read, and the index cannot advance beyond M.

Subject to returning dependencies, valid accesses, and valid address arithmetic:

- A changing or increasing bound cannot sustain an unbounded search.
- At most M candidate fields can be read, at indices zero through M − 1.
- At most M index increments can occur.
- At most M + 1 bound queries can occur.
- The largest possible selected index is M − 1.

These are mathematical upper bounds on control flow, not evidence that the address representation or allocation can support a traversal that long. Address limitations may prevent such a traversal much earlier.

For a fixed positive bound **B**, if all permitted fields are zero, exactly B fields are read and a further bound query at index B causes exhaustion. No field at index B is read.

### Address arithmetic remains a separate risk

The proof that the index does not overflow does not establish that address arithmetic is safe.

Both the field-address addition of 24 bytes and candidate advancement by 36 bytes require valid arithmetic. The address holder is represented as an integer, and the excerpt provides no overflow checks or recovery path.

In particular, the candidate address advances after the last zero-valued candidate even if the following bound query would immediately return exhaustion. That advance itself must be valid; preventing the next field read does not retroactively make it safe.

Dependency non-return, invalid memory accesses, and invalid address arithmetic remain separate reasons normal completion is not guaranteed. None requires or implies index overflow.

## Side effects

The established order of externally relevant operations is:

1. Call F-4c6d30ac2311.
2. Read the shared base location once.
3. Call F-fd477cd1a249 for the current index.
4. Read the current candidate’s selection field only if the signed bound permits it.
5. After a zero field, advance the index and candidate address, then repeat the bound query.
6. After a nonzero field, call F-4042d12a1376 with the candidate address, 36, and zero.
7. Call F-cc60a532ba6c before either normal return.

No direct write to the shared base or candidate storage appears in the function. Dependency calls may nevertheless modify either.

There is no explicit allocation or deallocation. Passing an address to F-4042d12a1376 does not establish ownership transfer, retention, release, or a guarantee of non-retention.

The captured address is retained independently of later changes to the shared base location. Its underlying storage is not guaranteed to remain available. For example, a bound-query dependency could change the field that is about to be read or invalidate the storage. Such preservation and lifetime guarantees must come from outside this function.

F-cc60a532ba6c is called on both normal exit paths. There is no visible mechanism guaranteeing its invocation after an invalid access, invalid arithmetic, or a dependency that fails to return.

No thread-safety, atomicity, or synchronization guarantee follows solely from the call sequence.
