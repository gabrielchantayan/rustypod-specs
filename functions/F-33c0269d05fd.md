# F-33c0269d05fd

## Purpose

F-33c0269d05fd constructs a null-terminated byte string in caller-provided storage from two source sequences. It takes up to eight bytes from the first source and, only if at least one first-source byte was accepted, inserts a period and takes up to three bytes from the second source. Each source scan stops at its own limit, a null byte, or an ASCII space, whichever is encountered first.

After construction, the function removes exactly one trailing period, if present, and writes the terminating null byte. It returns the original destination pointer.

The limits and separator suggest an intended short-name formatting operation. That interpretation is inferred intent, not an additional contract: the function does not validate filenames, normalize case, reject punctuation, or interpret paths.

The interface has three pointer arguments, in this order:

1. **Destination:** writable storage receiving the constructed string.

The return value is the destination pointer supplied by the caller, unchanged in identity. There is no separate status result, length result, allocation result, or error indicator.

- `0x00`: null.

The separator is `0x2E`, an ASCII period. Other byte values are copied without transformation. This includes tabs, line breaks, additional periods, path separators, and bytes with their high bit set. No encoding validation or multibyte-character boundary handling is established.

The component limits are eight bytes and three bytes, not character counts in a variable-width encoding.

## Behavior

### Leading-component selection

The function begins by reading the first byte of the first source, before writing anything to the destination.

If that byte is null or ASCII space, the leading component is empty. The function skips both separator insertion and the entire second-source scan, writes a null byte at the start of the destination, and returns the destination pointer.

Otherwise, it copies the byte into the destination and continues forward, accepting at most eight bytes. For each accepted byte, the source read precedes the corresponding destination write.

A null or space terminates the scan without being copied. The function does not skip that delimiter, resume after it, or inspect later bytes in the same source.

After accepting eight bytes, it proceeds without inspecting a ninth byte. A delimiter immediately after the eighth byte is therefore not read.

### Separator and trailing-component selection

If the leading component contains at least one accepted byte, the function writes one period immediately after it.

That separator write occurs before any second-source read. Consequently, when the second source aliases the separator location, the second-source scan sees the newly written period rather than the previous contents of that location.

The function then accepts up to three bytes from the second source. The stopping rules match those of the first source: a null byte or ASCII space ends the scan without being copied; reaching three accepted bytes ends it without reading a fourth byte.

The separator is initially written even when the second source immediately terminates. It is removed by the later trailing-period rule in that case.

### Final trailing-period adjustment

After the component scans, the function identifies the end of the bytes it has constructed.

If that end is beyond the destination start, it reads the immediately preceding destination byte. If the byte is a period, the final endpoint moves backward by one byte.

This removes exactly one final period. It is not a loop and does not strip a run of periods.

The rule applies to the final constructed byte regardless of its origin:

- If no second-source byte was accepted, it removes the inserted separator.
- If the accepted second-source bytes end in a period, it removes that copied period instead.
- It does not then reconsider the newly exposed final byte.

The function writes a null byte at the adjusted endpoint and returns the original destination pointer.

### Output length and bounds

For non-overlapping inputs, let:

- **B** be the number of first-source bytes accepted, from zero through eight.
- **E** be the number of second-source bytes accepted, from zero through three, when that scan occurs.

The resulting visible length is:

- Zero when **B** is zero.
- **B** when **B** is positive and **E** is zero.
- **B + 1 + E** when **E** is positive and its last accepted byte is not a period.
- **B + E** when **E** is positive and its last accepted byte is a period.

The largest visible result is twelve bytes, followed by a null byte.

For a particular execution, less than thirteen bytes may suffice. The caller must nevertheless account for every actual write, including the temporary separator, rather than only the final visible string length. For example, an empty second component causes the separator location to be written first as a period and later as null.

### Overlapping storage

The function does not stage either source in separate storage and does not establish snapshot semantics.

Its observable access order is:

1. Read a first-source byte.
2. If accepted, write that byte to the next destination position.
3. Repeat until a delimiter or the eight-byte limit.
4. If any first-source byte was accepted, write the separator.
5. Read a second-source byte.
6. If accepted, write that byte to the next destination position.
7. Repeat until a delimiter or the three-byte limit.
8. Read the final constructed byte when the constructed region is nonempty.
9. Write the final null terminator.

With overlap, earlier destination writes can alter source bytes that have not yet been read. The component limits still bound the scans, but the result need not equal formatting two snapshots taken at entry.

Destination equality with the first-source start supports the straightforward in-place leading copy: each accepted first-source byte is read before that same location is written. Other overlap arrangements require reasoning from the ordered accesses above. There is no general overlap-safety guarantee.

## Side effects

The established side effects are reads from the source regions and writes to the destination region.

- Copies accepted bytes into consecutive destination locations.
