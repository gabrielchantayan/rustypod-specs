# F-5524fc4d0914

## Purpose

F-5524fc4d0914 scans an indexed collection associated with a caller-supplied base address. It returns a 32-bit unsigned index selected by a fixed priority scheme and may increment certain negative per-entry values during the scan.

The selection priorities are:

1. Return the first entry that satisfies an immediate-return condition.
2. Otherwise, choose the smallest eligible unsigned value among entries whose category byte is exactly zero.
3. Otherwise, choose the smallest eligible unsigned value among entries whose category byte is exactly one.
4. Otherwise, choose a qualifying entry whose negative signed value was incremented during this call.
5. Otherwise, return zero.

An immediate return stops further traversal but does not undo earlier increments.

The apparent role of the negative-value branch is to advance entries toward zero while retaining a fallback selection. That interpretation is inferred intent, not an established description of the surrounding application.

## Interface

**Input:** One address-bearing argument identifying the base of a readable, and conditionally writable, memory region.

**Output:** One 32-bit unsigned integer. Normally this is an entry index. Zero is also the unconditional default, including when the collection is empty. There is no separate success flag or error result.

The visible memory layout is:

| Offset from supplied base | Width | Interpretation |
|---|---:|---|
| `0x468` | 32 bits | Unsigned entry count |
| `0x480 + 0x3c × index` | 32 bits | Entry value, interpreted as signed or unsigned according to the branch |
| `0x484 + 0x3c × index` | 8 bits | Category byte |
| `0x485 + 0x3c × index` | 8 bits | Nonzero-enabled byte |
| `0x4a4 + 0x3c × index` | 8 bits | Negative-value update selector |

The record stride is `0x3c` bytes, or 60 bytes. The first listed entry value is at base offset `0x480`. These offsets establish the accessed fields, not a complete record definition.

The following preconditions are required for defined, reliable use:

The source does not validate these conditions. It exposes no null-pointer check, buffer-size argument, bounds-error return, or memory-fault recovery.

## Behavior

### Traversal and termination

Traversal starts at index zero and advances in ascending index order.

Before processing each entry, the function reads the unsigned count at offset `0x468`. If the current index is greater than or equal to that count, traversal ends and the accumulated candidates determine the result.

Consequently:

- A count of zero returns zero without accessing entry fields.
- With stable memory, entries are considered from zero through count minus one.
- The count is read repeatedly rather than captured once at entry.
- An immediate-return condition prevents any access to later entries through this traversal.

The function maintains three candidate classes internally: a category-zero candidate, a category-one candidate, and an updated-negative fallback. These candidates do not themselves alter caller memory.

### Negative-value update branch

For each entry, the update-selector byte at offset `0x4a4` within its indexed layout is examined first.

If that byte is exactly one, the entry value is read as a signed 32-bit integer. If that signed value is negative, this entry takes the negative-value update branch:

- Its signed value is increased by one.
- The resulting value is compared against the best updated-negative value seen so far.
- The incremented value is written back to the same 32-bit field.
- The category and nonzero-enabled bytes are not examined for this entry.

The initial comparison threshold for this fallback is signed negative thirteen. A candidate replaces the current fallback only when its incremented value is strictly greater than the current threshold.

With stable memory, this means:

- An original value of negative thirteen increments to negative twelve and can become the fallback.
- An original value of negative fourteen increments to negative thirteen but does not qualify against the initial threshold.
- More negative values are still incremented, although they may never become candidates.
- An original value of negative one increments to zero and is eligible for this fallback.
- Equal incremented values retain the earlier candidate.

Every value entering this branch is negative. Incrementing it by one therefore cannot overflow a signed 32-bit integer: the resulting range is negative 2,147,483,647 through zero.

An entry that reaches zero through this branch does **not** trigger an immediate return during that visit. Immediate-return processing belongs to the other branch.

If the update-selector byte is anything other than exactly one, the signed-negative test is skipped. A nonzero selector value such as two is not equivalent to one.

### Immediate-return branch

An entry enters ordinary selection processing when either:

- Its update-selector byte is not exactly one; or
- That byte is exactly one, but its signed entry value is nonnegative.

The function then reads the nonzero-enabled byte at offset `0x485`.

If that byte is zero, the function immediately returns the current index. In this case, ordinary selection does not read the entry value after reading the enabled byte.

If the enabled byte is nonzero, the entry value is read as a 32-bit unsigned quantity. A value of zero also causes an immediate return of the current index.

These conditions take precedence over all previously accumulated candidates. They also take precedence over examining the category byte for the current entry.

A negative 32-bit bit pattern can reach ordinary selection when the update-selector byte is not one. In that case it is ranked as an unsigned value, not as a negative number.

### Category selection

Ordinary processing continues only when the nonzero-enabled byte is nonzero and the unsigned entry value is nonzero.

The category byte at offset `0x484` then determines eligibility:

- Exactly one: eligible for the category-one candidate.
- Exactly zero: eligible for the category-zero candidate.
- Any other byte value: eligible for neither category.

Each category retains the index having its smallest eligible unsigned value. Replacement uses a strict less-than comparison, so equal values retain the earlier index.

Both categories begin with a comparison threshold of `0xffffffff`, the maximum 32-bit unsigned value. An entry whose unsigned value equals `0xffffffff` therefore does not establish or replace a category candidate. This remains true even if it is the only entry in that category.

The two categories are ranked independently. Category zero has final priority over category one regardless of their relative values.

### Final selection

When traversal reaches the current count without an immediate return:

1. Return the category-zero candidate if one exists.
2. Otherwise, return the category-one candidate if one exists.
3. Otherwise, return the updated-negative fallback if one was established.
4. Otherwise, return zero.

For a stable, nonempty collection, zero may be either a genuine selected index or the default when no entry qualifies. The return value alone does not distinguish those cases.

## Side effects

The only explicit writes are increments to entry values that take the negative-value update branch.

Each such write occurs while its entry is visited, before traversal advances. All completed increments remain visible even if a later entry causes an immediate return.

There is no transactional rollback and no second pass that updates unvisited entries.

The visible logical read/write order is:

1. Read the current count.
2. If the index is in range, read the update-selector byte.
3. If the selector equals one, read the value for the signed-negative test.
4. If negative, read the value again for the increment, select any fallback replacement, and write the incremented value.
5. Otherwise, read the nonzero-enabled byte.
6. If enabled, read the unsigned value.
7. Unless returning immediately, inspect the category and update the appropriate internal candidate.

The category is tested for exact equality to one first. If that test fails, the supplied representation tests it again for equality to zero. The signed-negative branch also contains distinct value reads for its condition and its increment.

These are source-level access relationships, not a guarantee of exact physical load counts or bus ordering. No volatile, atomic, or synchronization semantics are established.

The function contains no visible allocation, deallocation, external call, or ownership transfer. The input memory remains caller-provided; the source establishes only the conditional writes described above.

## Acceptance examples

The examples below are conditional static expectations, not executed tests. Unless stated otherwise, memory is valid and stable, entry indices are zero-based, and ordinary entries have a nonzero enabled byte.

### Empty collection

Given a count of zero:

- The result is zero.
- No entry field is read or written.

### Immediate return preserves earlier updates

Given three entries:

- Entry zero has update selector one and signed value negative two.
- Entry one takes ordinary processing and has an enabled byte of zero.
- Entry two would otherwise be eligible.

Expected behavior:

- Entry zero is written with negative one.
- The result is one.
- Entry two is not visited.

### Incrementing to zero is not an immediate return

Given:

- Entry zero has update selector one and signed value negative one.
- Entry one is an ordinary category-one entry with value seven.

Expected behavior:

- Entry zero becomes zero.
- Traversal continues past entry zero.
- The result is one because the category-one candidate outranks the updated-negative fallback.

### Category zero outranks a smaller category-one value

Given:

- Entry zero is an ordinary category-one entry with value two.
- Entry one is an ordinary category-zero entry with value one hundred.

Expected result: one.

The category-zero priority is applied before comparing candidates across categories; there is no global minimum across both categories.

### Strict comparison preserves the first equal candidate

Given two ordinary category-zero entries with value nine, at indices zero and one:

- The result is zero.
- The later equal value does not replace the earlier candidate.

### Maximum unsigned values do not establish candidates

Given two ordinary category-zero entries, both with value `0xffffffff`, and no other qualifying entries:

- Neither establishes a category-zero candidate.
- The result is the default zero.
- No entry value is written.

Returning zero here does not prove that entry zero was eligible.

### Updated-negative threshold boundary

Given two entries that both take the negative-value update branch:

- Entry zero starts at negative fourteen.
- Entry one starts at negative thirteen.

Expected behavior:

- Entry zero becomes negative thirteen but does not establish the fallback.
- Entry one becomes negative twelve and establishes the fallback.
- With no category candidates, the result is one.

### A zero ordinary value overrides earlier candidates

Given:

- Entry zero is an ordinary category-zero entry with value five.
- Entry one takes ordinary processing and has unsigned value zero.

Expected result: one, immediately.

The earlier category-zero candidate does not prevent this return.

### Noncanonical bytes have distinct meanings

Given one entry with update selector two, nonzero-enabled byte two, category two, and nonzero value:

- It does not take the negative-value update branch.
- It is enabled for ordinary value processing.
- It belongs to neither category.
- In the absence of other qualifying entries, the result is the default zero.
