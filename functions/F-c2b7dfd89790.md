# F-c2b7dfd89790

## Purpose

F-c2b7dfd89790 conditionally extracts a sequence of fixed-size records from an interior range identified by an initial parsing operation.

When the initial result has classification byte 3, the function temporarily replaces two fields in a caller-supplied context, repeatedly invokes the parsing dependency, and copies eligible records into a capacity-limited destination. It continues processing eligible records after destination capacity is exhausted. At termination, it publishes the result of a separate arithmetic dependency and restores the two context fields it saved.

When the initial classification is not 3, no extraction loop or arithmetic call occurs. The result location receives an initial all-bits-one value, but the initial parsing dependency may still change caller-visible state.

The interpretation of the records as tokens, and of the selected range as the contents of a container or delimited construct, is inferred intent rather than an established semantic contract.

## Interface

The function has four arguments and no direct return value:

| Argument | Established representation | Role |
|---|---|---|
| Context | Pointer to storage accessed in 32-bit words | Passed to the parsing dependency; words at byte offsets 0 and 8 are also read and written directly |
| Destination | Pointer to 32-bit words | Receives records of three consecutive words, totaling 12 bytes per record |
| Capacity | Signed 32-bit integer in the supplied representation | Determines the destination limit used for conditional record copying |
| Result location | Pointer to a writable 32-bit object | Receives an initial sentinel and, on the classification-3 path, the arithmetic dependency’s result |

The relevant context layout is:

| Byte offset | Width | Direct use |
|---|---:|---|
| 0 | 32 bits | Current-position-like value, read as unsigned for loop comparison |
| 4 | 32 bits | No direct access by this function |
| 8 | 32 bits | Limit-like value, read as unsigned for loop comparison |

The context’s complete size and other fields are unknown. The parsing dependency may access more than the two fields directly used here.

The initial parsing result is held in temporary storage. The function consumes:

- A signed 32-bit value at offset 0.
- A signed 32-bit value at offset 4.
- A classification byte at offset 8.

Each subsequent parsing result occupies three 32-bit words. All three words are copied when a record is retained. Eligibility is determined by the low eight bits of its third word, not by whether that entire word is zero.

The record fields’ semantic meanings are not established. In particular, no ownership-bearing interpretation of either of the first two words is justified.

For ordinary, non-overlapping use, the caller must provide:

- Context storage accessible to this function and to F-85e566545ec7.
- A writable result word.
- Sufficient destination storage for every record the capacity permits this function to copy.
- Alignment and pointer validity appropriate to the target.
- Values for which the required address arithmetic and signed arithmetic are defined.

There are no explicit null, alignment, extent, or capacity checks.

## Behavior

### Initial result and probe

The first direct observable action is a 32-bit write of `0xffffffff` to the result location.

The function then invokes F-85e566545ec7 with the context and temporary output storage. It inspects the classification byte at offset 8 in that output.

If the byte is not exactly 3:

- Processing ends.
- The destination receives no direct writes from this function.
- F-870c4fcf7295 is not called.
- No context fields are restored by this function.
- The result remains the sentinel unless aliasing or effects of F-85e566545ec7 have changed that storage.

The initial probe is therefore not established to be observationally read-only.

### Selecting the temporary range

If the classification byte is 3, the function saves context words at offsets 0 and 8, in that order. These are their values **after** the initial dependency call, not their values at function entry.

It then writes:

1. The initial result’s first signed 32-bit value plus one into context offset 0.
2. The initial result’s second signed 32-bit value minus one into context offset 8.

These adjustments suggest exclusion of two boundary positions, but that interpretation is not required to describe the established behavior.

The additions and subtractions are expressed as signed 32-bit arithmetic in the supplied representation. Inputs at the signed overflow boundaries are not assigned a portable wraparound meaning by this contract. Writing the results into unsigned context words does not, by itself, resolve overflow in the preceding signed expression.

### Iteration and record eligibility

A logical destination position starts at the destination base.

Each iteration proceeds in this order:

1. Read the current context values at offsets 0 and 8.
2. Compare them as unsigned 32-bit values.
3. If the value at offset 0 is not strictly less than the value at offset 8, stop without making another parsing call.
4. Otherwise, invoke F-85e566545ec7 with the current context and temporary record storage.
5. Inspect the low eight bits of the temporary record’s third 32-bit word.
6. If those bits are zero, stop without copying that record and without advancing the logical destination position.
7. Otherwise, conditionally copy the record and advance the logical destination position by 12 bytes.

The comparison is repeated using the context’s then-current values. The parsing dependency may have changed either field during the preceding iteration.

There is no second range check between the parsing call and acceptance of its output. A record with a nonzero eligibility byte can therefore be processed even if that parsing call moves the context to or beyond its limit. The next iteration’s comparison determines whether another parsing call occurs.

A record whose third word is nonzero but whose low eight bits are zero terminates processing.

### Capacity-limited copying

For every eligible record, the function compares the current logical destination position against a limit formed from the destination base and three times the capacity, measured in 32-bit words.

If the logical destination position is below that limit, the function writes the record in this order:

1. First 32-bit word.
2. Second 32-bit word at the next word position.
3. Third 32-bit word at the following word position.

The logical destination position advances by three words whether or not those writes occur.

For nonnegative capacities and valid arithmetic and pointer operations, this means:

- The first capacity-many eligible records are copied.
- Later eligible records are processed but not copied.
- Capacity exhaustion does not stop parsing.
- No terminator record is appended.
- Unused destination storage is not cleared.
- A zero capacity suppresses direct record writes but does not suppress the initial probe or subsequent parsing of eligible records.

These statements do not make arbitrary negative capacities or arbitrarily large record counts safe. The signed multiplication used to form the capacity limit and the repeated pointer advances require separate validity.

### Final result and restoration

After the extraction loop ends, the function forms a byte displacement between the logical destination position and the destination base. The supplied representation converts the addresses to 32-bit signed integers before subtracting them.

It calls F-870c4fcf7295 with:

- That computed displacement as the first argument.
- The integer value 12 as the second argument.

The returned 32-bit value is written to the result location.

The function then restores:

1. Context word at offset 0.
2. Context word at offset 8.

The restored values are those saved after the initial probe. Restoration does not cover any other context fields, global state, or dependency side effects.

Although the arithmetic call strongly suggests conversion of a byte displacement into a record count, its actual arithmetic behavior is not supplied. The established output is the dependency’s returned value, not an independently guaranteed quotient.

Restoration is shown only on normal control flow. There is no established cleanup guarantee if a dependency fails to return normally or an invalid memory access interrupts execution.

## Side effects

Direct effects are limited to:

- Initializing the result word.
- Temporarily overwriting two context words on the classification-3 path.
- Writing retained records to destination storage.
- Publishing the arithmetic dependency’s return value.
- Restoring the two saved context words.

Indirect effects of both dependencies remain possible. Neither dependency is established to preserve globals, preserve unrelated context fields, avoid I/O, or avoid allocation and release.

The function itself shows no explicit allocation, deallocation, or retention of a supplied pointer beyond the call. Copying the three record words does not establish a deep copy or transfer of ownership. If those words encode references, their lifetime and ownership rules are documented_only.

Aliasing matters because the direct writes have a fixed order:

- A result location overlapping the context can modify the context before the first parsing call.
- Destination writes overlapping context fields can affect subsequent range comparisons or dependency behavior.
- The final result write precedes restoration; an overlapping restoration write can replace the published result.
- Restoring the two context fields can replace data previously copied into overlapping destination storage.

No overlap detection or alternate overlap-handling path is present. The simple record-extraction interpretation assumes disjoint caller-visible regions; overlapping calls must instead be evaluated using the actual access order and dependency behavior.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Unless stated otherwise, they assume disjoint valid storage, defined arithmetic and pointer operations, fully initialized dependency outputs, and dependencies that return normally.

1. **Initial classification differs from 3.**  
   The function initializes the result to all bits one and makes one parsing call. It performs no direct destination writes and does not invoke the arithmetic dependency. Any context mutation by that parsing call remains.

2. **The adjusted range is empty.**  
   The initial classification is 3, but the adjusted context position is greater than or equal to the adjusted limit under unsigned comparison. No extraction call occurs. F-870c4fcf7295 receives displacement zero and divisor argument 12. Its return value is published, followed by restoration of the post-probe context values.

3. **The first extraction result has a zero eligibility byte.**  
   The adjusted range initially permits a parsing call. That call returns a record whose third word has low eight bits zero. No record is copied and the displacement remains zero. Other bits of the third word do not change this outcome.

4. **Two records fit and a third does not.**  
   Capacity is two, and three eligible records are produced before termination. The first two records are copied in order. The third is not copied, but the logical destination position still advances. The arithmetic dependency receives displacement 36 and second argument 12. If that dependency is separately established to perform ordinary division for these inputs, the published result is three rather than two.

5. **Zero capacity with eligible records.**  
   Capacity is zero and two eligible records precede termination. No direct destination writes occur. Both records contribute to the displacement, so the arithmetic dependency receives 24 and 12. Capacity does not cause early termination.

6. **A parsing step reaches the range limit.**  
   The pre-call position is below the limit. The parsing dependency returns an eligible record while changing the position to equal the limit. That record is still eligible for copying and displacement advancement. Assuming no further relevant mutation, the next comparison stops extraction without another parsing call.

7. **The initial probe changes context.**  
   Entry context values differ from those left by the initial probe. On a classification-3 path, normal restoration reinstates the post-probe values, not the entry values. Changes to other context fields are not directly reversed.

## Uncertainties

The following are documented_only:

- The semantic meaning of classification 3 and of each record field.
- Whether the initial result’s first two fields denote positions, addresses, or another coordinate system.
- The relationship between the initial classification byte and the low byte of subsequent third words on the target’s byte ordering.
- The arithmetic semantics of F-870c4fcf7295.
- Error conventions and nonlocal failure behavior of either dependency.
- Dependency ownership, allocation, release, and global-state effects.
- Valid behavior for null pointers, negative capacities, overlapping regions, arithmetic overflow, invalid pointer comparisons, or out-of-object pointer advances.
- A general termination guarantee.

No explicit status distinguishes destination exhaustion from successful complete storage. No explicit malformed-input error is generated here. The all-bits-one initialization is an established bit pattern; interpreting it as a particular signed error code requires an external interface contract.

## Evidence

Established static evidence consists solely of the supplied function representation and opaque dependency mapping. It supports the 32-bit word accesses, 12-byte record stride, branch conditions, direct operation order, dependency call sites, and limited restoration behavior described above.
