# F-e834a90b0fa4

## Purpose

F-e834a90b0fa4 conditionally performs a setup sequence, makes several calls, repeatedly writes and polls memory, calls F-29405a9c1b17 after the polling condition becomes nonzero, performs two publication writes, and calls F-880399f1f568.

This is a contract for the behavior expressed by the supplied static representation. An application-level purpose is not established. An initialization-and-polling interpretation is plausible but remains inferred intent.

The representation depends on incoming processor state beyond its nine nominal arguments. It also reports invalid instruction data and ends at a truncated-flow marker. No successful return path is established. The endpoint does not, by itself, prove that an executable implementation intentionally traps.

## Behavior

### Widths and arithmetic

The representation uses 32-bit integer values and address calculations, with explicitly 16-bit and 8-bit memory accesses. The loaded pointer is represented as 32 bits. A 16-bit store retains the low 16 bits of its supplied value.

Unsigned right shifts introduce zeros. Signed right shifts are expressed as arithmetic right shifts. Negative signed shifts, signed overflow, and excessive shift counts must not be silently assigned portable semantics.

Several address calculations contain signed multiplication or signed left shift. Low-32-bit machine arithmetic is a possible interpretation, but the supplied representation does not independently establish that interpretation for every expression. Numerical examples below avoid those cases or state their conditions.

### Conditional setup

A clear incoming overflow condition bypasses all setup-only operations.

When the condition is set, the represented order is:

1. Subtract 60 from the incoming unsigned setup value using 32-bit unsigned arithmetic, then shift right by eight. Retain the result for deriving the first loop-write seed.
2. Invoke F-000000000001 at the target formed from the incoming link-like state plus `0xFFE`.
3. Invoke F-000000000002 at the statically expressed target `0x085700F5`. Its represented signed 32-bit return controls subsequent setup addressing.
4. Add 49 to that return and multiply by two. Call the result the setup displacement.
5. Store a zero halfword at `0x002CFFB0` plus the setup displacement.
6. Read a signed halfword at twice the quantity obtained by subtracting 80 from the setup displacement.
7. Sign-extend that halfword to 32 bits, reinterpret it as unsigned, and shift right by 29. The result is zero for a nonnegative halfword and seven for a negative halfword.
8. Derive the first loop-write seed by interpreting the retained shifted setup value as signed and shifting it right by a count equal to its low eight bits.
9. Invoke F-000000000003 at `0x085700F9`. Its three represented arguments are the sign-derived result shifted left by 14, that result shifted left by 13, and a global 32-bit value read for this call.
10. Replace the link-like state with `0x0856F143`.
11. Invoke F-000000000004 at `0x0857013D`.
12. Read the setup address/value global into argument 2.
13. Store a halfword through the setup address/value global plus ten bytes, using the low 16 bits of that global as the stored value.
14. Replace argument 1 with zero and argument 3 with argument 2 shifted left by eight.

The retained unsigned setup value after the initial shift is between zero and `0x00FFFFFF`; its signed interpretation is therefore nonnegative. Its low-eight-bit shift count can nevertheless exceed 31. Behavior for those excessive counts remains unresolved.

The setup global appears in multiple read expressions: the capture into argument 2 and the address/value expressions of the halfword store. The representation does not justify replacing all those accesses with a single cached read. Nor does it establish an order between the store’s address and value evaluations. If those reads observe the same word, the store writes that word’s low 16 bits at that word plus ten.

The replacement of argument 3 uses the value already captured into argument 2. It is not expressed as a new global read.

### Common calls and pointer reads

After setup, or immediately when setup is bypassed:

1. Capture the current argument 3 for the subsequent pointer-slot read.
2. Invoke F-000000000005 with current arguments 1 and 2.
3. Invoke F-000000000006 at the statically expressed target `0x08570185`.
4. Read a 32-bit pointer from the captured argument-3 address plus 64 bytes.
5. Read a signed halfword through that pointer.
6. Invoke F-000000000007 at the statically expressed target `0x08570189`, with two values derived from the pointer and halfword.

F-000000000005 has two distinct target cases:

- **Setup bypassed:** incoming link-like state plus `0xFFE`.
- **Setup executed:** `0x0856F143 + 0xFFE`, giving `0x08570141`.

The second case follows from the explicit replacement before F-000000000004. It is the target expressed by the representation, not an independent guarantee about undocumented machine-register preservation across that call.

For F-000000000007, the first argument is derived by adding the pointer’s signed 32-bit numeric interpretation to the sign-extended halfword, shifting the sum right by 31, reinterpreting the result as unsigned, shifting right by 20, and then shifting left by 24.

For a nonoverflowing sum under the expressed arithmetic-shift interpretation, the first argument is:

- Zero when the sum is nonnegative.
- `0xFF000000` when the sum is negative.

The second argument is the pointer’s signed numeric interpretation shifted right by 28.

These operations use an address as signed numerical data. No validation precedes the pointer-slot read or the dereference.

### Polling loop

The representation explicitly assigns zero to an arithmetic temporary before F-000000000007 and does not assign that call’s return to it. On this literal reading:

- The initial polling-address state is current argument 3 multiplied by `0x02000000`.
- The first argument passed to F-000000000008 is zero.
- The initial loop-write displacement is the selected incoming or setup-derived seed shifted left by nine.

The loop executes at least once. Each iteration has this visible order:

1. Store a zero halfword at 4096 times the current loop-write displacement, plus 30 bytes.
2. Invoke F-000000000008 at its fixed code-label target, passing the current loop argument.
3. Set the loop-write displacement to zero.
4. Read an unsigned halfword at four times the current polling-address state, plus 28 bytes. Retain it as the next loop argument and, if this iteration terminates the loop, as the base for the later byte read.
5. Read an unsigned halfword at the dependency’s secondary-output address plus 20 bytes. Double it to obtain the next polling-address state.
6. Read an unsigned halfword again at that secondary-output address plus 20 bytes. Repeat the loop if this second value is zero; otherwise exit.

The two offset-20 reads are separate observable accesses. They must not be collapsed into a single read. Their values may differ.

After the first iteration, the explicit displacement reset makes every later loop write target address 30 on the literal representation. This low address is retained as expressed behavior, not repaired into an assumed object field.

The halfword read at the scaled polling address becomes the next F-000000000008 argument when another iteration occurs. It does not supply the next polling-address state; that state comes from doubling the first offset-20 read.

The doubled halfword ranges from zero through 131070 and fits in 32 bits. No timeout, iteration bound, wait operation, or failure return is shown. Repeated zero termination reads produce unbounded iteration if all calls and accesses continue to complete.

### Final calls and publications

After a nonzero termination read:

1. Read an unsigned byte at the retained polling halfword plus 26 bytes.
2. Invoke F-29405a9c1b17 with:
   - Argument 5.
   - Argument 6 shifted logically right by 28, yielding 0 through 15.
   - The doubled first offset-20 read from the terminating iteration.
   - The byte just read.
3. Read the final publication global as a 32-bit value.
4. Store a halfword at eight times argument 8 plus 52 bytes. The stored value is the low 16 bits of eight times argument 8.
5. Store the captured publication global as 32 bits at eight times argument 9 plus 116 bytes.
6. Invoke F-880399f1f568 with the represented signed 32-bit return from F-29405a9c1b17 shifted left by 20.
7. Reach the invalid-instruction/truncated-flow endpoint.

The retained polling halfword is zero-extended. Its byte-read address therefore ranges from 26 through 65561 under the represented address model.

The final shift by 20 is a signed left-shift expression. Arbitrary negative or excessive return values cannot be assigned wrapping behavior without further evidence.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, preceding calls return, accesses complete, and arithmetic stays within its established range.

1. **Setup bypass and dynamic target.** With overflow clear and incoming link-like state `0x1000`, no setup-only call or write occurs. F-000000000005 targets `0x1FFE` and receives original arguments 1 and 2.

2. **Setup replacement and fixed common target.** With overflow set, setup explicitly replaces link-like state with `0x0856F143` before F-000000000004. The represented common call subsequently targets `0x08570141`, irrespective of the original link-like value. F-000000000001 still uses the original value plus `0xFFE`.

3. **Fixed setup targets.** On a setup execution that reaches all setup calls, F-000000000002, F-000000000003, and F-000000000004 have expressed targets `0x085700F5`, `0x085700F9`, and `0x0857013D`, respectively. Their bodies remain unknown.

4. **Setup sign extraction.** A nonnegative setup halfword produces zero for the first two F-000000000003 arguments. A negative setup halfword produces `0x0001C000` and `0x0000E000`.

5. **Upper-nibble extraction.** Argument 6 equal to `0xA1234567` produces second argument 10 for F-29405a9c1b17. Changing only its lower 28 bits does not change that argument.

6. **Distinct polling reads.** First and second offset-20 reads of three and one terminate the loop and supply six as the third F-29405a9c1b17 argument. The second read’s value is not the value doubled.

7. **Zero payload with termination.** Offset-20 reads of zero and one terminate the loop with third argument zero.

8. **Continuation despite a nonzero first read.** Offset-20 reads of three and zero repeat the loop with next polling-address state six. If that next iteration reaches its scaled polling read, the read address is 52.

9. **Subsequent low-address write.** After any zero termination read, the next iteration begins with a zero halfword write at address 30. Failure of that write prevents guaranteeing the iteration’s later call and reads.

10. **Publication ordering and values.** Argument 8 equal to two produces a halfword write of 16 at address 68. Argument 9 equal to three produces a 32-bit write at address 140. The halfword write precedes the word write, and both precede F-880399f1f568.

11. **Post-call global observation.** If F-29405a9c1b17 changes the publication global before returning, the subsequent read observes the post-call storage state, not a value cached before the call.

12. **Unambiguous final shift.** If F-29405a9c1b17 returns one, F-880399f1f568 receives `0x00100000`, provided the intervening reads and writes complete.
