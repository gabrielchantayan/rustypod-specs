# F-cfc16b345f50

## Purpose

F-cfc16b345f50 checks a request against a context’s current owner, admits selected request forms, constructs a 2,048-byte temporary event region, and conditionally submits it through F-c6c589453fa8. One selector-4 branch instead constructs a 20-byte notification and invalidates the context owner.

The established behavior is a selector-driven transformation with ordered checks, dependency calls, and explicit state writes. “Event,” “preparation,” and “invalidation” describe observable roles; they do not establish a protocol or subsystem meaning.

Ordinarily reached cleanup calls F-09ba55c206ac for a nonzero request address, then calls F-feee9156a257, which is annotated nonreturning. Internal status selections therefore are not established as caller-observable returns on those paths.

## Interface

### Arguments and representation

The function has two address-valued arguments represented by 32-bit integers:

| Argument | Established fields |
|---|---|
| Context | 32-bit current owner at offset 0x2d4; synchronization-related address at offset 0x2dc; selector-4 state at offsets 0x304–0x307 |
| Request | 32-bit payload address at offset 8; unsigned 16-bit declared payload length at offset 0x0c; unsigned 16-bit selector at offset 0x10 |

Payload byte accesses are unsigned 8-bit accesses. Selector and length are widened to 32 bits without sign extension. Address calculations and relevant working arithmetic use the supplied 32-bit representation.

The request is dereferenced before its address is tested for zero. A null request is not a supported status-query mechanism.

Additional inputs include dependency results, a saved external mode byte, and a shared 32-bit field. Dependency-mediated reads are not defined by this function.

### Status and completion

The internal status begins at 11. Admission changes it to 62. Accepted ordinary processing changes it to zero; optional preparation may replace zero with its nonzero result. Selector-4 invalidation selects 19.

These values describe internal state. For a nonzero request reaching cleanup, the annotated nonreturning final call prevents an ordinary return. The representation contains a return for a zero request address, but earlier unconditional request dereferences prevent treating that as a supported normal path.

### Preconditions

Normal execution requires accessible request, context, external-state, and payload storage for the accesses actually performed. No general pointer, allocation-size, alignment, ownership, or concurrency validation is established.

Declared payload length is a branch input, not proof of accessible allocation size. Unknown dependency behavior may require additional storage or impose additional preconditions.

## Behavior

### Initial observations and ordered checks

The function first reads the request’s payload address, selector, and declared length, in that order. These captured values are used subsequently rather than reloading the request fields.

It then performs these calls and observations in order:

1. F-5f5f14cedda3 receives the request address and supplies the derived owner.
2. An external-object accessor is called. F-1bc5bcdc9cca receives that result plus offset 4 and the derived owner, supplying a classification.
3. The accessor is called again; the byte at its result plus 0xd9 is saved as the mode.
4. The accessor is called again. F-9266831caef7 receives that result plus offset 4 and zero, supplying a required lookup result.
5. F-76ed42657cca receives the derived owner.

The three accessor calls are distinct. Their results need not identify the same object.

After the owner-related predicate call, initial validation short-circuits in this exact order:

1. Read the shared 32-bit field at offset 4 of the externally referenced shared object. If zero, invoke F-a817d8d58c10.
2. Only if that field was nonzero, read the context owner. If it differs from the derived owner, invoke F-a817d8d58c10.
3. Only after owner equality, test the saved required lookup result. If zero, invoke F-a817d8d58c10.

F-a817d8d58c10 is annotated nonreturning. In particular, a zero shared field suppresses the initial context-owner read. All earlier dependency calls have already occurred.

### Admission

The exclusive selector bound is 25, except that it becomes 5 when F-76ed42657cca returned nonzero and the saved classification is none of 0x46, 0x1da, or 0xd000.

F-59599f67673b is then called. Admission checks short-circuit in this order:

1. If readiness is zero, take cleanup without rereading the context owner.
2. Otherwise, reread the context owner; mismatch takes cleanup.
3. Otherwise, compare the captured unsigned selector with the exclusive bound; an out-of-range selector takes cleanup.
4. Otherwise, test the captured payload address for zero; zero takes cleanup.

These failures retain internal status 11. The payload-null test is not reached when an earlier admission check fails.

After admission, status becomes 62 and the internal event code is initialized to 25. An unidentified dependency receives the temporary event-region address and size 2,048. The function then writes the selector’s low byte at event offset 0. The dependency’s initialization effect is unknown; it does not establish zero-filled storage.

The internal event code is separate storage; no explicit operation places it into the event region.

F-64e2dfdd4a5d and F-c25a2fcc75b5 have decoding-like uses, but their reads, byte order, and transformations are not established. Selector 2 instead contains a direct 16-bit load; no byte-order conversion is shown.

For selector 9, lengths below 2 reject without reading the count. Otherwise, the unsigned count byte is read and the length equation is checked. Arithmetic is 32-bit; the largest required length is 2,042.

For each accepted entry, in ascending order, F-c25a2fcc75b5 receives the entry address and then that address plus 4. Each result is stored before the next call. The two 32-bit destinations begin at event offset 8 and advance eight bytes per entry. Count zero performs no entry calls. Count 255 ends at event offset 2,047; the loop’s eight-bit-masked increment does not wrap before termination.

### Selector 4: state update versus invalidation

After F-64e2dfdd4a5d returns, the function reads payload byte 2 and constructs the three translated bytes. It compares the **full 32-bit helper result**, not merely the stored low 16 bits, with 0x0200.

Only a full result of 0x00000200 combined with a third byte of zero selects ordinary processing. Before that processing, the function:

1. Sets event code 3.
2. Writes the result’s low 16 bits to context offset 0x304.
3. Writes the captured third byte to offset 0x306.
4. Writes byte value 1 to offset 0x307.

These writes precede optional preparation. No explicit rollback is performed afterward. Dependencies, including preparation, may themselves modify the context.

Every other result or third-byte combination selects invalidation:

1. Obtain an external object.
2. Call F-62d1a359629f with its offset-4 subobject and a current-owner read.
3. Call F-1bc5bcdc9cca with the same subobject and another current-owner read; store its result at notification offset 12.
4. Set notification offset 4 to 32-bit value 0x10 and offset 0 to byte value 3.
5. Read the current owner into notification offset 8; place the saved lookup result at offset 16.
6. Call F-a6e52da0a17c with another current-owner read and that lookup result.
7. Call F-c6c589453fa8 with arguments 0, 0, notification address, and 20.
8. Select status 19, overwrite the context owner with 0x7fffffff, and proceed to cleanup.

Notification bytes 1–3 are not explicitly assigned. Owner reads are distinct and may observe different values if dependencies modify state. This branch does not perform ordinary event submission.

### Selectors 12 and 13: structured processing

After requiring length 28, the function calls F-efea2fb7ef8f with the payload address and 1 if the saved mode is zero. It then directly reads the payload’s current first byte into event offset 4.

The remaining ordered operations are:

1. Call F-f7b0e1ed845e with the payload address.
2. If its 32-bit result is nonzero, obtain a 32-bit temporary from F-0e78d391116e. Invoke an unidentified dependency with destination event offset 5, source address of that temporary, and the nonzero result as length argument. Then store F-da62c29c744d’s 32-bit result at event offset 8.
3. Store the low byte returned by F-8be9f2bb538e at event offset 12.
4. Call F-f8236aa3e7c8.
5. If its 32-bit result is nonzero, replace the 32-bit temporary with F-559b0236e438’s result. Invoke the same unidentified dependency with destination event offset 13, source address of the temporary, and this result as length argument. Then store F-f8d6fb10a8e1’s 32-bit result at event offset 16.

7. Obtain a final 32-bit length from F-4e7604290e11.

The named extraction dependencies receive the payload address. Their internal reads and effects remain unknown.

The final length is accepted exactly when its unsigned 32-bit difference from 10 is at most 16: values 10 through 26 inclusive. Rejection occurs after the earlier calls and explicit writes.

On acceptance, F-656bfc1f57ae supplies a source-address value. The function stores the final length’s low byte at event offset 21, then invokes the unidentified dependency with destination event offset 22, that source-address value, and the final length.

These are established address-and-length calls, **not established byte-copy effects**. Under ordinary copying semantics, the first two calls could overread the four-byte temporary or overwrite adjacent event fields because no bounds checks constrain their nonzero lengths. Negative signed representations are not explicitly rejected either. Actual access and overwrite behavior remain dependent on the unidentified contract.

### Accepted ordinary processing

The function selects status zero and initializes two 32-bit scratch values to 0xffffffff and zero.

With saved mode zero, it compares the low 16 bits of the event code with 25:

- If below 25, call F-704f99fd5e22 with the context, derived owner, address of the first scratch value, and event-code address.
- A nonzero result becomes the status and suppresses ordinary submission.
- Otherwise, invoke an unidentified synchronization-related dependency at context offset 0x2dc, call F-c6c589453fa8 with arguments 9, 0, event address, and 2,048, then invoke a second synchronization-related dependency at the same context offset.

With saved mode nonzero, submit directly without preparation or those synchronization-related calls.

Code 25 skips preparation but not the mode-zero synchronization sequence. Selectors 13 and 24 retain that code. Selector 0 also skips preparation when its captured code is at least 25.

## Side effects

Explicit persistent writes are the selector-4 context-state writes and alternate-branch owner overwrite. Other direct writes construct temporary records and scratch state.

No dependency is assumed to preserve globals, context, request, payload, or temporary storage. Checks do not establish atomicity across subsequent calls.

Normally reached cleanup with a nonzero request calls F-09ba55c206ac before the nonreturning F-feee9156a257. Neither call placement nor naming establishes release, retention, or ownership transfer.

Submission addresses refer to temporary storage. Whether F-c6c589453fa8 consumes synchronously, copies, or retains those addresses is documented_only. No persistent allocation or explicit lifetime extension is established.

## Acceptance examples

These are conditional static criteria, not executed tests. Unless specified otherwise, assume accessible storage, successful initial checks, nonzero readiness, owner equality, and the broad selector bound.

- **Shared field zero:** earlier dependency calls occur, but the initial context-owner read is suppressed; invoke F-a817d8d58c10.
- **Readiness zero:** do not perform the admission-stage owner reread; reach cleanup with status 11.
- **Selector 2, length 2:** directly load and store 16 bits. With mode zero, call preparation; submit only if it returns zero.
- **Selector 2, length 3:** reject with status 62 and no ordinary submission.
- **Selector 9, count zero, length 2:** accept without entry-helper calls.
- **Selector 9, count 255, length 2,042:** issue 510 entry-helper calls and store their results through the event region’s final byte.
- **Selector 9, count 2, length 17:** reject; required length is 18.
- **Selector 4, full result 0x00000200 and third byte zero:** perform the context-state writes before preparation. If preparation fails, this function performs no explicit rollback; resulting field values remain dependent on preparation’s effects.
- **Selector 4, full result 0x00010200 and third byte zero:** take invalidation despite the stored low 16 bits being 0x0200.
- **Selector 4, full result 0x00000200 and third byte one:** submit the notification before explicitly overwriting the owner; omit ordinary submission.
- **Structured final length 9 or 27:** reject after earlier structured effects. For length 10 or 26, issue the final address-and-length call; do not infer copied contents without that dependency’s contract.
- **Selector 12 versus 13, mode zero:** accepted selector 12 invokes preparation with code 11; selector 13 skips preparation with code 25.
- **Restricted bound, selector 6:** reject before its translation helper is called.
