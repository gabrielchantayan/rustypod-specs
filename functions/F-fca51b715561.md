# F-fca51b715561

## Purpose

F-fca51b715561 compares values selected from two memory regions, subject to an unsigned 32-bit limit. It returns zero when the compared values remain equal through the limit or reach a shared selected zero. Otherwise, it returns a value derived from the first unequal selected pair.

An initial optimization can skip equal four-byte words when both starting addresses are four-byte aligned. Skipping also requires an arithmetic detector, dependent on an external datum, to permit it.

**Inferred intent:** a bounded, zero-terminated byte-string comparison with aligned word-at-a-time acceleration.

**Established limitation:** ordinary bounded string-comparison semantics are conditional. The external detector value is not supplied, byte order is not independently established, and the final comparison phase is represented using word dereferences with low-eight-bit selection. This contract therefore distinguishes selected values from the complete memory accesses that obtain them.

## Interface

### Inputs and result

The represented interface has:

| Item | Meaning |
|---|---|
| First address | Starting location in the first input region |
| Second address | Starting location in the second input region |
| Limit | Unsigned 32-bit comparison bound |
| Result | Signed 32-bit return value |

Both addresses are represented as pointers to unsigned four-byte words. The word-oriented phase advances them by four bytes per successful skip. The final phase advances them by one byte per successful nonzero equality.

The limit is measured in single-byte comparison positions, not words. A word skip consumes four positions.

The final phase selects the low eight bits of each dereferenced value. If those dereferences are literal four-byte loads:

- On a little-endian target, the selected value is the byte at the current address.
- On a big-endian target, it is the byte three positions beyond the current address.

Neither actual instruction widths nor target byte order are supplied independently.

### Preconditions

Normal completion requires all accesses actually performed to be valid, including:

- Readability of both input regions at every accessed location.
- Any alignment required by the actual load instructions.
- Valid address arithmetic for every pointer advance.
- Readability of the external detector datum whenever its evaluation is reached.

The function does not check these conditions.

A zero limit requires no readable input storage on the visible execution path: neither input is dereferenced.

For a positive limit, providing exactly that many bytes of storage is not necessarily sufficient. A four-byte load used to select one byte can read three bytes beyond that selected position. The final phase may therefore require readable backing storage beyond the nominal comparison bound.

No ownership is transferred. No allocation or release operation appears. The inputs are read but not written by this body. The supplied material does not establish synchronization or concurrent-mutation rules.

## Behavior

### Alignment and phase selection

The function combines 32-bit integer representations of the two starting addresses and tests their bottom two bits.

- If both addresses are divisible by four, it attempts the word-oriented phase.
- Otherwise, it proceeds to the remaining-limit check and then, if needed, the final comparison phase.

There is no preliminary byte comparison to align the addresses. An unaligned start bypasses word-oriented comparison for the entire invocation.

The initial alignment calculation does not dereference either input.

### Word-oriented phase

A word comparison is attempted only when the remaining limit is at least four. For a smaller remaining limit, this phase performs no input-word comparison and does not evaluate the detector.

For each eligible comparison, the visible access order is:

1. Read a four-byte word from the first region.
2. Read a four-byte word from the second region.
3. Compare the two word values.

If the words differ, the function leaves this phase without advancing either address or reducing the limit. The final phase begins at the same addresses, so it rereads those regions rather than extracting its result from the already loaded word pair.

If the words are equal, the function evaluates the detector using the word read from the first region.

Let \(W\) denote that word, \(D_s\) the external datum observed for subtraction, and \(D_m\) the external datum observed for mask construction. A skip is permitted when:

\[
\bigl(((W-D_s)\bmod 2^{32}) \mathbin{\&} \mathord{\sim}W\bigr)
\mathbin{\&}
\bigl((D_m \ll 7)\bmod 2^{32}\bigr)
=0.
\]

The complement is within the 32-bit word width. Subtraction wraps modulo \(2^{32}\); bits shifted beyond that width are discarded.

The two external-datum references occur in separate represented evaluations: subtraction first, mask construction second. The supplied material does not establish whether the executable uses separate loads, reuses a value, or can observe different values between those references.

If the detector permits the skip:

- Both current addresses advance by four bytes.
- The remaining limit decreases by four.
- The function considers another word-oriented comparison.

If the detector rejects the skip, neither address nor the limit changes, and the final phase starts at the current addresses.

A successful skip is based on equality of the values already read. It does not guarantee that either region remains unchanged afterward.

### Detector interpretation

With a stable detector datum of `0x01010101`, the arithmetic detects whether a 32-bit word contains any zero byte:

- Equal words without zero bytes may be skipped.
- An equal word containing a zero byte is not skipped.

That datum value is an assumption, not supplied static evidence.

Other values can change which equal words are skipped. In particular, a stable datum of zero permits every equal word to be skipped, including words containing zero bytes. The function can then continue beyond a shared zero and return a later difference.

The equality requirement remains in force regardless of detector value: unequal loaded words are never skipped by this phase.

### Remaining-limit check

After the optional word-oriented phase, a remaining limit of zero returns zero immediately.

This includes:

- An initially zero limit.
- A positive limit exhausted by successful four-byte skips.

No final-phase input read occurs in either case.

### Final comparison phase

This phase begins only with a nonzero remaining limit.

Each iteration obtains values in this visible order:

1. Dereference the first current address and retain its low eight bits.
2. Dereference the second current address and retain its low eight bits.
3. Determine whether comparison continues.

The second-region read occurs even when the selected first value is zero.

Continuation requires both:

- The selected first value is nonzero.
- The two selected values are equal.

Therefore:

- Unequal values stop comparison.
- A first selected zero stops comparison, including when the second selected value is also zero.
- A second selected zero paired with a nonzero first value stops comparison as an inequality.

After a successful nonzero equality, the remaining limit decreases by one and both addresses advance by one byte. These updates also occur when that equality consumes the last remaining position. Another iteration occurs only if the reduced limit is nonzero.

After a mismatch or first selected zero, those updates do not occur.

The function does not reenter the word-oriented phase after entering this phase.

### Bounds and arithmetic

The visible limit management does not underflow:

- Four is subtracted only when at least four remain.
- One is subtracted only during an iteration entered with a positive limit.

Address validity is separate from limit arithmetic. The function does not detect address-space boundary crossings or invalid pointer arithmetic. The final-phase advances use a signed 32-bit address conversion in the supplied representation; behavior at problematic address boundaries is not established.

### Return value

After final-phase comparison, the result is formed from:

**selected first value minus selected second value.**

Each operand is between 0 and 255. The subtraction is represented in unsigned 32-bit arithmetic, followed by conversion to the signed return type.

Under conventional 32-bit signed conversion, this produces the exact mathematical difference in the range −255 through 255:

- Zero for equal selected values.
- A negative value when the first is smaller.
- A positive value when the first is larger.

It is not restricted to −1, 0, and 1.

For example, selected values 2 and 255 produce −253 under that conversion. The supplied material does not independently specify the rule for an unsigned subtraction result outside the signed range.

If the limit expires after successful nonzero equalities, the last selected pair is equal, so the returned difference is zero.

## Side effects

### Reads and rereads

The function can read the same locations more than once:

- Unequal words are reread by the final phase.
- Equal words rejected by the detector are reread by the final phase.
- If final-phase dereferences are actual four-byte reads, successive one-byte advances produce overlapping reads.

The body provides no snapshot guarantee. Changes between the word reads and final-phase rereads can change the eventual selected values and result.

A completed read can encompass bytes beyond a selected zero or beyond the last selected position allowed by the limit. Statements about positions “not compared” do not establish that their storage was physically unread.

No later iteration occurs after a final-phase mismatch or first selected zero.

## Acceptance examples

These are conditional consequences of the static representation, not runtime test results. All accesses mentioned are assumed valid. Negative numerical results assume conventional 32-bit signed conversion.

### Zero limit

With a limit of zero, the result is zero regardless of address alignment.

Neither input is dereferenced, and the external detector datum is not evaluated.

### Aligned start with a limit below four

With aligned addresses and a limit of three, no word comparison or detector evaluation occurs.

If the selected pairs are 65/65, 66/66, and 67/67, the result is zero. A fourth selected pair is not compared.

With the same alignment and a zero limit, no final-phase comparison occurs either.

### Unaligned immediate difference

Assume at least one starting address is unaligned, the limit is positive, and the first selected values are 65 and 67.

The word-oriented phase is bypassed. Both selected values are obtained, the result is −2, and no second iteration occurs.

### Limit exhaustion after nonzero equalities

Assume an unaligned start, a limit of three, and selected sequences that remain stable during the reads:

- First region: 65, 66, 67, 88.
- Second region: 65, 66, 67, 89.

The result is zero. The fourth selected pair is not compared.

This does not establish that the fourth storage byte is unread; an earlier word-width access may encompass it.

### First selected value is zero

With a positive limit and initial selected values 0 and 255, both regions are read for that iteration. The result is −255, and comparison stops immediately.

If both selected values are zero, the result is zero. No later selected pair is compared.

### Equal aligned word without zero

Assume:

- Both starting addresses are four-byte aligned.
- The limit is four.
- The loaded words are equal and contain no zero byte.
- The detector datum remains `0x01010101` throughout its evaluation.

One word is read from each region. The detector permits the skip, the limit becomes zero, and the function returns zero without final-phase reads.

### Equal aligned word containing zero

Assume:

- Both starting addresses are four-byte aligned.
- The limit is **at least four**.
- The loaded words are equal and contain a zero byte.
- The detector datum remains `0x01010101` throughout its evaluation.

The word comparison occurs, and the detector prevents a skip. The final phase begins at the original addresses.

Additionally assume a little-endian target and that both input regions remain unchanged through the final-phase rereads. Equal bytes preceding the first zero are then compared in increasing address order. The zero pair terminates comparison with result zero. Later selected bytes are not compared.

Without unchanged contents during those rereads, the earlier word equality does not establish subsequent equal pairs or a shared zero. With a limit below four, no word comparison or detector evaluation occurs at all.

### Aligned unequal words

Assume aligned addresses and a limit of at least four. The loaded words differ.

The word-oriented phase consumes no positions. The final phase rereads from the same addresses. Its result follows the selected values observed during those rereads, stopping at an inequality, a first selected zero, or limit exhaustion—not from subtraction of the original complete words.

### Detector allowing a skip across zero

Assume aligned addresses, a limit of eight, and a stable detector datum of zero.

The first loaded words are equal and contain a zero byte. They are skipped. At the next addresses, assume the loaded words differ and the subsequent final-phase reads select 65 and 66.

The result is −1. The earlier shared zero does not terminate this execution because its word was skipped.
