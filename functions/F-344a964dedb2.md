# F-344a964dedb2

## Purpose

F-344a964deddedb2 selects an addressed record using a base input and an 80-byte index stride. It reads a one-byte gate and conditionally calls F-502c68bf367d. It then either:

- Returns **3** without directly copying a record field; or
- Copies a four-byte source field into a four-byte destination field and returns **0**.

The dependency is called only when the initially observed gate byte is zero. A nonzero dependency result selects return value 3. A zero dependency result selects the same copy-and-return-0 continuation used when the gate is nonzero.

On the dependency-call path, initialization of a local four-byte object is sequenced **before** the candidate-field read used as a dependency argument. Both occur before the dependency receives control.

These are structural behaviors established by the supplied body. Application-level meanings such as success, failure, restoration, or resource release are not established.

## Behavior

### Address selection and initial observation

The function forms the selected address from the first two inputs, using an index multiplier of 80. It then reads the gate byte at offset `0x1284`.

The gate decision compares that byte with zero. It does not distinguish among nonzero byte values or test a particular bit. A gate value of `0x01` and one of `0xff` therefore select the same branch; character signedness does not change whether either value is zero.

This gate read precedes the explicit candidate-field and copy-source-field reads. The function does not read either four-byte field before making the gate decision.

### Nonzero gate: copy without calling the dependency

When the initially observed gate byte is nonzero, F-502c68bf367d is not called.

The function reads four bytes from the copy-source field at offset `0x1244`, writes that value into the candidate field at offset `0x125c`, and returns 0.

The source read supplies the value for the destination write. The destination’s previous contents do not affect whether the write occurs. A write is still part of this path when source and destination values are already equal.

There is no explicit initialization of the dependency-facing local object on this path. The third input has no observed use.

### Zero gate: ordered preparation and dependency call

When the initially observed gate byte is zero, the function prepares one call to F-502c68bf367d.

The established preparation order is:

1. A local four-byte object is initialized from the fourth input.
2. The candidate field at offset `0x125c` is read as a four-byte value.
3. F-502c68bf367d receives control with the prepared arguments.

Initialization of the local object is sequenced before evaluation of the dependency-call expression. The candidate-field read belongs to that later expression. Consequently, the local initialization precedes the candidate-field read, not merely entry into the dependency.

This does not establish an otherwise unnecessary total order among evaluations of the original scalar inputs and the local object’s address within the call expression. The material ordering is that the local object is initialized before the candidate argument is read, and both are ready before the call begins.

F-502c68bf367d receives these arguments, in order:

| Argument position | Value supplied |
|---|---|
| First | Original first input |
| Second | Original second input |
| Third | Four-byte value read from the candidate field |
| Fourth | Address of the initialized local four-byte object |

The candidate value is passed by value. The fourth argument addresses local storage containing a copy of the fourth input; it is not an explicit pointer to the candidate field.

The dependency is invoked at most once during an invocation of this function.

### Nonzero dependency result

If F-502c68bf367d returns a nonzero integer, the function returns 3.

This continuation performs no explicit copy-source-field read and no explicit candidate-field write. It also performs no subsequent read of the local four-byte object.

These limits apply to this function’s direct operations. They do not establish that the dependency left the record, global state, allocation state, or other resources unchanged.

### Zero dependency result

If F-502c68bf367d returns zero, the function reads the copy-source field after the call, writes the observed four-byte value into the candidate field, and returns 0.

The source value is not captured before the dependency call. If the dependency changes that field and the subsequent access remains valid, the copy uses the post-call value.

The function does not repeat the gate test. A dependency-induced change to the gate does not change the selected continuation.

The copy uses the previously computed selected address. There is no new record-selection calculation after the dependency returns.

The local four-byte object is not read after the call. A dependency modification to that object is not explicitly copied into either record field and does not directly determine this function’s return value.
