# F-f2366995da9f

## Purpose

F-f2366995da9f traverses a linked structure, conditionally selects an existing candidate, and otherwise delegates an operation to F-b1e11d250a75. It publishes a 32-bit result word followed by a one-byte disposition flag.

The established outcomes on normal completion are:

- **Flag 0:** the result word identifies the selected candidate; F-b1e11d250a75 was not called.
- **Flag 1:** F-b1e11d250a75 was called; the result word is copied from its local output slot.

Ordered-tree insertion with optional duplicate suppression is **inferred intent**, not an established guarantee. This function does not directly allocate a node, change tree links, or verify that delegation changed the structure. Flag 1 records delegation, not successful insertion.

This contract describes the supplied static representation. In particular, separately expressed memory reads remain separate observations; their values are not assumed equal merely because they use the same address.

## Interface

### Arguments and result

The function receives:

1. **Result-storage address:** writable storage for a four-byte word at offset 0 and a one-byte flag at offset 4.
2. **Container address:** the base address for the fields below.
3. **Supplied value token:** an opaque 32-bit value passed to dependencies. This function does not directly dereference it.

There is no explicit return value.

The representation uses 32-bit words, integer address expressions, and pointer-valued fields consistent with a 32-bit address model. The exact machine ABI, calling convention, and byte order are documented_only.

| Result offset | Width | Meaning |
|---|---:|---|
| 0 | 4 bytes | Selected candidate address or delegated output word |
| 4 | 1 byte | 0 for candidate selection; 1 for delegation |
| 5 onward | Unspecified | Not directly written by this function |

There is no caller-visible result initialization on entry. On normal completion, the four-byte result is written before the flag byte. These writes do not constitute an atomic publication protocol.

Pointer fields are represented as four-byte values. “Parent,” “child,” “header,” and “boundary” describe their observed roles. Calling the two children “left” and “right,” or the boundary “leftmost,” requires an ordered-tree interpretation not proved here.

### Preconditions

Normal completion requires:

- Readable container and header fields at every actual access.
- Readable node fields along the paths selected by the actual sequence of observations.
- Writable result storage covering offsets 0 through 4.
- Dependencies that return normally and meet the memory requirements of their arguments.
- A structure and comparison behavior under which all traversals terminate.

A null initial search-node pointer is handled. A null header pointer, invalid parent chain, cyclic traversal, or invalid candidate is not converted into a reported error.

No non-aliasing rule is established. Result storage may overlap the container or nodes unless an external contract forbids it; final publication would then overwrite overlapping bytes. Dependency aliasing restrictions are documented_only.

## Behavior

### Initial search

The function starts with a comparison-result state equal to 1.

It reads the container’s header pointer and then that header’s field at offset 0x04 to obtain the initial search node. It subsequently reads the container’s header pointer again and retains this second value as the initial terminal candidate.

These are separate header-pointer reads. The initial search node and initial terminal candidate can therefore originate from different header observations.

For each nonnull search node:

- Two local scratch/output words are cleared.
- F-31a0b2b5649a is called with the container-relative address at 0x19, the supplied value token, and the current node’s data address at 0x10, in that order.
- The current node becomes the terminal candidate.
- A child pointer is read after the dependency returns:
  - A zero comparison result selects offset 0x0c.
  - Any nonzero comparison result selects offset 0x08.

The selected pointer becomes the next search node. Only zero versus nonzero matters; negative results do not receive a distinct interpretation.

The child read occurs after the comparison call. If the dependency changes that child field and leaves the node valid, the subsequent traversal observes the post-call field value rather than a previously captured link.

When search ends, the terminal candidate is the last visited node. If no node was visited, it remains the separately loaded header address and the comparison-result state remains 1.

### Mode selection

Only after search ends does the function read the byte at container offset 0x18.

- **Nonzero:** proceed directly to ordinary delegation.
- **Zero:** perform candidate checking.

Search is not skipped in nonzero mode. A dependency’s changes to the mode during search can affect the later mode observation.

### Candidate checking in zero mode

The checked candidate initially equals the terminal candidate.

If the final search comparison result is zero, navigation is skipped and the function performs the final candidate comparison.

If that result is nonzero, the function reads the container’s header pointer again, then reads that header’s boundary pointer at offset 0x08.

If the terminal candidate equals this boundary pointer, boundary delegation occurs immediately. There is no navigation and no final candidate comparison.

Otherwise, navigation selects the candidate as described below.

### Special navigation condition

The function first reads the byte at terminal-candidate offset 0x00.

If this byte is zero, it reads the terminal candidate’s parent-like pointer at offset 0x04 and then that object’s parent-like pointer at offset 0x04. If the resulting pointer equals the terminal candidate, the selected candidate is read from terminal-candidate offset 0x0c.

If the byte is nonzero, those two parent-link reads are skipped. If the byte is zero but the two-link result differs from the terminal candidate, ordinary navigation follows.

The special path does not validate that its selected offset-0x0c pointer is nonnull.

### Ordinary navigation: two distinct first-child reads

Ordinary navigation first reads terminal-candidate offset 0x08 and retains that pointer for possible descendant traversal.

It then reads terminal-candidate offset 0x08 **again**. This second observation alone determines the navigation branch:

- **Second observation null:** perform parent climbing.
- **Second observation nonnull:** perform descendant traversal using the pointer retained from the first observation.

The second observation does not replace or validate the retained pointer.

Consequently, if the two observations differ:

- A nonnull retained pointer followed by a null branch observation causes parent climbing. The retained child is not traversed.
- A null retained pointer followed by a nonnull branch observation enters descendant traversal with a null selected node. The ensuing node-field access has no protective null check.

Describing this decision as a single child-pointer test would lose behavior present in the supplied representation.

### Parent climbing

Parent climbing begins from the terminal candidate.

For each step, the function reads the current node’s parent-like pointer at offset 0x04 and selects that parent as the candidate. It then reads the selected parent’s field at offset 0x08 and compares it with the node just climbed from.

If they are equal, climbing continues from that parent. Otherwise, climbing ends with that parent selected.

No parent-pointer null check or cycle detection is performed. A sentinel arrangement that makes these accesses valid is an external structural requirement.

### Descendant traversal: retained and branch-controlling links

Descendant traversal begins with the pointer retained by the **first** terminal offset-0x08 read.

At each selected descendant:

- Its offset-0x0c pointer is read and retained as the possible next descendant.
- Its offset-0x0c pointer is read **again** to decide whether traversal continues.
- A null second observation ends traversal with the current descendant selected.
- A nonnull second observation continues traversal using the pointer retained from the first observation.

The second observation is not substituted for the retained pointer.

With stable relevant fields and a finite valid chain, this selects the last node reached through successive offset-0x0c links before a null link. That familiar description is conditional on stability.

When the two reads differ:

- A nonnull retained link followed by a null branch observation stops at the current node without following the retained link.
- A null retained link followed by a nonnull branch observation continues with a null selected node, leading to an unchecked field access.
- Two different nonnull observations cause traversal to follow the first, not the second.

No retry, reconciliation, synchronization, or snapshot mechanism is shown. These rules describe the static read sequence; they do not establish safe behavior under concurrent modification.

### Final candidate comparison

Unless boundary delegation was taken, zero mode clears the ordinary-delegation output slot and another local scratch word, then calls F-31a0b2b5649a with:

1. The container-relative address at 0x19.
2. The selected candidate’s data address at 0x10.
3. The supplied value token.

The last two arguments are reversed relative to search calls.

A zero result causes publication of the selected candidate address with flag 0. A nonzero result causes ordinary delegation.

Zero is not independently established to mean equality. Duplicate suppression follows only under a suitable external comparison contract.

### Delegation and publication

Both delegation paths call F-b1e11d250a75 with:

1. A local 32-bit output-slot address.
2. The container address.
3. Zero.
4. The original terminal candidate from search.
5. The supplied value token.

The fourth argument remains the original terminal candidate even when navigation selected a different candidate for final comparison.

After the dependency returns, the local output word is copied into caller result offset 0, followed by flag 1 at offset 4. The dependency’s direct return value is not used.

The output-slot initialization differs by path:

| Path | Established initialization before delegation |
|---|---|
| Boundary delegation after at least one search node | Its slot was cleared during search |
| Boundary delegation without search nodes | Its slot is not shown initialized |
| Ordinary delegation after a final candidate comparison | Its slot was cleared before that comparison |
| Ordinary delegation in nonzero mode after search nodes | Its slot was cleared during search |
| Ordinary delegation in nonzero mode without search nodes | Its slot is not shown initialized |

The two delegation paths use different local output slots. A meaningful delegated result therefore depends on the dependency’s output contract, especially where its slot has not been initialized. The function does not check whether the dependency wrote the slot.

## Side effects

### Direct effects

The function directly writes local scratch storage and the five-byte caller result layout. It directly reads the container, header, and node fields described above.

It performs no direct allocation, release, payload copy, or tree-link update.

Address calculations use fixed offsets. No overflow checks are shown. Valid execution requires the resulting addresses to designate the intended objects; portable wraparound behavior for invalid addresses is not established.

### Dependency effects and ownership

Neither dependency is established as pure or as preserving globals, container contents, node links, or object lifetimes.

The supplied value token is forwarded without an explicit ownership transfer, retention operation, or release by this function. Whether dependencies copy, consume, retain, allocate, or release related storage is documented_only.

If a dependency invalidates an object later accessed by this function, normal completion is not established. The post-comparison search-child read is one such later access.

### Errors and partial execution

There is no explicit error result, validation branch, recovery path, or allocation-failure handling.

Invalid memory, malformed links, nonterminating navigation, or a dependency that does not return normally can prevent completion. No completed result pair is promised in those cases.

Result publication is ordered but not atomic. An observer could see the new four-byte result with a previous flag value. No thread-safety or memory-ordering guarantee is established.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Selection without navigation.**  
   If search ends with comparison result zero, mode is zero, and the final comparison returns zero, publish the terminal candidate with flag 0. Do not call F-b1e11d250a75.

2. **Delegation after a different candidate is checked.**  
   If navigation selects a candidate different from the terminal candidate and the final comparison returns nonzero, compare using the selected candidate’s data address but delegate using the original terminal candidate as the fourth argument.

3. **Nonzero mode.**  
   If the mode byte is nonzero when read, search still occurs normally. Afterward, omit boundary lookup and final candidate comparison and perform ordinary delegation.

4. **Boundary shortcut.**  
   If mode is zero, the final search result is nonzero, and the terminal candidate equals the freshly obtained boundary pointer, perform boundary delegation without navigation or final comparison.

5. **Empty search.**  
   If the initial search node is null, no search comparison occurs. With zero mode and a boundary pointer equal to the retained header, boundary delegation receives that retained header as its fourth argument. Its output slot is not shown initialized before the call.

6. **Special navigation.**  
   If the terminal byte is zero and following two parent-like links returns to the terminal candidate, select its offset-0x0c pointer. Do not enter ordinary child traversal.

7. **First-child observations disagree: stop using the retained child.**  
   If ordinary navigation first reads child A at terminal offset 0x08 and then reads null from that field, parent climbing must follow. A is not traversed.

8. **First-child observations disagree: unchecked null traversal.**  
   If the first offset-0x08 observation is null and the second is nonnull, descendant traversal begins with the retained null pointer. The representation contains no intervening check that makes this a valid traversal.

9. **Descendant observations disagree: early stop.**  
   If a selected descendant’s first offset-0x0c read yields B and its second yields null, traversal ends at the selected descendant. B is not selected next.

10. **Descendant observations disagree: first value controls advancement.**  
    If the first offset-0x0c read yields B and the second yields a different nonnull C, traversal advances to B, assuming B remains valid. If the first instead yields null, continuation leads to an unchecked null-node access.

11. **Stable descendant chain.**  
    If the ordinary first-child reads agree and all subsequent offset-0x0c pairs agree, a finite valid chain ending in null selects its last node.

12. **Non-Boolean comparison result.**  
    A search result of −1 selects offset 0x08, just as 1 does. A final result of −1 causes delegation.
