# F-73d099a86adb

## Purpose

F-73d099a86adb constructs a sign-adjusted, scaled division result through one of two dependency paths. It first converts the first two input words to unsigned magnitudes, selects a computation according to the numerator magnitude, and finally applies the sign indicated by the original inputs.

**Inferred intent:** division of signed values with a scale factor of 65,536, using a half-divisor adjustment before division. This is consistent with a rounded fixed-point quotient, but the exact quotient, rounding, overflow, and error behavior depend on functions whose implementations are not supplied.

**Established behavior:** a zero divisor bypasses all dependencies and selects the positive sentinel `0x7FFFFFFF` before final sign adjustment. The function does not establish general saturation behavior for nonzero divisors.

This contract distinguishes the wrapper’s directly established operations from dependency-dependent results.

## Behavior

### 1. Magnitude preparation

The function examines the first input as a signed 32-bit value.

- If its sign bit is clear, its magnitude word is unchanged.
- If its sign bit is set, its magnitude word is the unsigned 32-bit negation of the original word.

It performs the same operation independently on the second input.

These are unsigned-word negations, not conversions to a wider signed type. Consequently:

- `0xFFFFFFFF` produces magnitude `1`.
- `0x80000000` produces magnitude `0x80000000`.
- The minimum signed input is not rejected and is not clamped to `0x7FFFFFFF`.

The original input words remain relevant to the final sign decision. Magnitude preparation does not replace that decision with one based on dependency outputs.

### 2. Zero-divisor selection

If the second magnitude word is zero, the function selects `0x7FFFFFFF` as its provisional result.

For 32-bit modular negation, only an original second input of zero produces this zero magnitude. No arithmetic dependency is called on this branch.

The selected sentinel is still subject to final sign adjustment. Thus, zero-divisor handling is not an unconditional return of the same positive sentinel.

### 3. Nonzero-divisor preparation

For a nonzero divisor magnitude, the function prepares two words:

1. A high component obtained by interpreting the first magnitude word as signed and shifting it right arithmetically by 16 bits.
2. A half-divisor word obtained by interpreting the second magnitude word as signed and shifting it right arithmetically by one bit.

The signed interpretation matters at the boundary value `0x80000000`.

For ordinary nonnegative magnitude words, the half-divisor is the integer floor of half the magnitude. For divisor magnitude `0x80000000`, however, the arithmetic right shift produces `0xC0000000`, not `0x40000000`.

Similarly, the high component for numerator magnitude `0x80000000` is `0xFFFF8000`, not `0x00008000`.

The function selects the narrow path only when the prepared high component is zero.

Under the 32-bit interpretation, this gives the following path boundary:

- Numerator magnitudes from `0` through `65,535` take the narrow path.
- Numerator magnitudes from `65,536` upward take the wide path, including `0x80000000`.

### 4. Narrow computation path

The function forms a 32-bit word from:

- the first magnitude multiplied by 65,536; and
- the prepared half-divisor added to that product.

The multiplication and addition retain a 32-bit result. No wider intermediate is established by the supplied expression. Overflow therefore must not be silently replaced by an unlimited-precision calculation in a behavioral model.

Before calling the dependency, the function overwrites four temporary word-sized locations, in this order, with:

1. the original first input;
2. the original second input;
3. the third input;
4. the fourth input.

These are local storage writes, not writes through caller-provided pointers. Their addresses are not explicit arguments to this path’s dependency. The source establishes the copies but does not establish an externally visible purpose for them.

The function then calls **F-d7be9cfb4000** with two word-sized values:

1. the scaled-and-adjusted word;
2. the divisor magnitude word.

Its return value becomes the provisional result.

The wrapper performs no explicit range check, division check, or result correction between this dependency’s return and the final sign adjustment.

### 5. Wide computation path

The function prepares a low component by shifting the first magnitude word left by 16 bits and retaining the low 32 bits. It also writes zero to a separate temporary word.

It then calls **F-bc5079bc5666** with three address arguments:

1. the address of the temporary holding the low component;
2. the address of the temporary holding the half-divisor;
3. the same address supplied as the first argument.

The first and third address arguments therefore alias exactly. Any implementation or substitute for this dependency must account for that aliasing.

The call is used for its effects on temporary storage; no return value is consumed.

After this call returns, the function obtains the high and low component values from their temporary storage and calls **F-643f64d6dc60** with:

1. the then-current high component;
2. the then-current low component;
3. the divisor magnitude.

The return value of F-643f64d6dc60 becomes the provisional result.

The distinction between pre-call and post-call component values is important. The source does not justify treating the high component as immutable across F-bc5079bc5666. The apparent adjacent-word layout could allow that dependency to operate on a multiword value.

Likewise, the half-divisor is prepared before the call, but this wrapper does not directly read it again afterward.

### 6. Final sign adjustment

After either computation path, or after zero-divisor selection, the function examines the sign bit of the bitwise exclusive-or of the two original input words.

- Equal sign bits leave the provisional result unchanged.
- Different sign bits negate the provisional result.

This is a sign-bit rule. It is not a test that the provisional result is positive, nor is it a correction for a dependency’s overflow behavior.

For a provisional result of zero, negation leaves zero. For `0x80000000`, 32-bit machine negation retains the same bit pattern. The source expression alone does not establish portable language-level behavior for signed negation of the minimum signed integer; the retained-bit-pattern result is the machine-width interpretation, not a separately verified runtime observation.

The final word is returned as a signed 32-bit result.
