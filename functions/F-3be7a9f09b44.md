# F-3be7a9f09b44

## Purpose

F-3be7a9f09b44 dispatches a numeric operation against a caller-supplied object, optionally performs a guarded preliminary sequence, and then obtains a separate result through a common final dependency call.

The function exposes two distinct outputs:

- A 32-bit return value indicating whether the operation matched a recognized dispatch path.
- A 32-bit value written through a caller-supplied output pointer after dispatch completes.

Recognition does not establish that an operation changed state or succeeded. Several recognized paths deliberately perform no branch-specific action for some payloads and still return one.

The apparent role is an operation or event dispatcher. That interpretation is inferred; the established contract is the selection, call ordering, bounds checks, and final output write described below.

## Behavior

### 1. Guarded preliminary sequence

Before examining the operation, the function reads the flags word through the shared flags base.

If its least significant bit is set, the preliminary sequence is skipped. F-b255b26284e6 is not called in that case.

If that bit is clear:

1. F-b255b26284e6 is called with the shared guard argument.
2. If its signed 32-bit result is zero, no further preliminary calls occur.
3. If its result is nonzero:
   - F-398e0e9a318a is called with the shared context value and the address of the designated shared storage slot.
   - Its opaque 32-bit result becomes the first argument to F-804adc29bbfb. The other two arguments come from the two additional shared values, in their established argument positions.
   - F-d08d3ca17b81 is called with the shared guard argument as obtained for that call.

Dispatch begins only after this sequence returns normally.

The guard does not depend on whether the operation will later be recognized. An unmatched operation can therefore trigger all preliminary calls.

There is no direct flag update in the function. Whether the preliminary sequence implements initialization, locking, notification, or something else is unknown.

### 2. Dispatch precedence

Let the threshold denote the shared 32-bit value used for dispatch comparison.

Selection has this precedence:

1. Equality between the operation and the threshold is checked first.
2. If unequal, the function compares the operation and threshold using signed ordering.
3. Only operation values in the selected lower or upper partition are checked against the fixed numeric operation values.

Consequently, the fixed values are not unconditional cases. Their reachability depends on the threshold:

| Operation | Additional condition for its fixed-value path |
|---|---|
| 0x568c | Operation is signed-less-than the threshold. |
| 0x5696 | Operation is signed-less-than the threshold. |
| 0x5697 | Operation is signed-less-than the threshold. |
| 0x56d3 | Operation is signed-greater-than the threshold. |
| 0x56d4 | Operation is signed-greater-than the threshold. |

If the threshold equals any fixed operation value, the threshold-equality path wins instead.

The preliminary dependencies run before threshold-dependent dispatch. Their effects on shared state must not be assumed absent.

### 3. Threshold-equality path

When the operation equals the threshold, the operation is recognized.

The function reads the unsigned 32-bit bound at object offset +0x34 and compares the payload against it using unsigned ordering.

If the payload is strictly below the bound:

1. F-caaa02637cf0 receives the address at object offset +0x2c and the unchanged payload.
2. Its opaque 32-bit return value is passed to F-2973ca21b889, together with the object address and the shared context value.

If the payload equals or exceeds the bound, both calls are skipped.

Either outcome proceeds to finalization with recognition value one. A rejected index is not reported as an unrecognized operation.

### 4. Lower-partition fixed operations

These paths are available only when the operation is signed-less-than the threshold.

**Operation 0x568c**

F-85098f97b7c8 is called with the object address, unchanged unsigned payload, and shared context value. No local payload check is performed.

**Operation 0x5696**

F-099da7dc06a0 is called with the object address. Its opaque 32-bit result is then supplied to F-54cdb17624e5, together with the object address, unchanged payload, and shared context value.

The context argument for the latter call is obtained after F-099da7dc06a0 returns. No preservation of shared state by that dependency is assumed.

**Operation 0x5697**

The payload selects among three behaviors:

- Zero: call F-334a1c1d8f28 with the object address and shared context value.
- One: call F-e8a51cc3cc3b with the same argument roles.
- Any other unsigned 32-bit value: perform no branch-specific call.

All three outcomes are recognized and proceed to finalization with return value one.

Any other operation in this lower partition is unrecognized.

### 5. Upper-partition fixed operations

These paths are available only when the operation is signed-greater-than the threshold.

**Operation 0x56d3**

The function reads the unsigned bound at object offset +0x34.

If the payload is strictly below that bound:

1. F-caaa02637cf0 receives the address at object offset +0x2c and the unchanged payload.
2. F-a3cfe0288813 receives the object address, the lookup result, the shared context value, and a final 32-bit zero argument.

If the payload is outside the bound, both calls are skipped.

The operation remains recognized in either case.

**Operation 0x56d4**

The function performs this sequence:

1. Call F-9d0ecc5f6adf with no arguments.
2. Read the opaque 32-bit field at object offset +0xa8.
3. Call F-c0b020cd3882 with the first dependency’s result and that field value.
4. Call F-1f62160dfd52 with the shared context value, the second dependency’s result, and the payload incremented by one.

The increment uses unsigned 32-bit arithmetic. A payload of 0xffffffff becomes zero. There is no local saturation, overflow rejection, or upper-bound check.

The object field read occurs after F-9d0ecc5f6adf returns. The function therefore does not establish that the field has its entry-time value.

Any other operation in this upper partition is unrecognized.

### 6. Common finalization

Every dispatch path that completes normally, recognized or not, reaches the same final sequence:

1. Call F-ecd1af0519f9 with the shared context value obtained for this call.
2. Write its opaque 32-bit result through the output address.
3. Return the recognition value.

The output store occurs after all preliminary and branch-specific dependencies have returned. The function does not initialize the output word earlier.

If any dependency fails to return normally, this function establishes neither the final output store nor a returned recognition value.

## Acceptance examples

These are conditional static expectations, not executed tests. They assume valid accessed storage and normal dependency returns.

1. **Guard short-circuit:** If the flags low bit is set, F-b255b26284e6 and the other preliminary dependencies are not called. Dispatch and finalization still occur.

2. **Guard predicate rejection:** If the flags low bit is clear and F-b255b26284e6 returns zero, only that preliminary call occurs. The operation is still dispatched.

3. **Unknown operation:** If the operation differs from the threshold and matches no reachable fixed case, the function calls F-ecd1af0519f9, stores its result, and returns zero. The preliminary sequence remains independently applicable.

4. **Threshold operation with valid index:** If the operation equals the threshold, the bound is three, and the payload is two, F-caaa02637cf0 receives index two. Its result is passed to F-2973ca21b889. Finalization follows, and the return value is one.

5. **Exclusive bound:** With the same operation and bound three, payload three skips both indexed-path dependencies. Finalization still occurs, and the return value remains one. A zero bound rejects every possible unsigned payload.

6. **Recognized selector with no action:** With threshold 0x56a0, operation 0x5697, and payload two, neither selector dependency is called. The return value is one, not zero.

7. **Partition matters:** With threshold 0x5600 and operation 0x568c, the lower-partition fixed case is unreachable. The operation is unmatched and returns zero after finalization.

8. **Equality shadows a fixed case:** With threshold and operation both 0x56d4, the indexed threshold-equality path applies. The three-dependency chain otherwise associated with 0x56d4 does not run.

9. **Unsigned wraparound:** With threshold 0x56a0, operation 0x56d4, and payload 0xffffffff, F-1f62160dfd52 receives zero as its third argument.

10. **Late field read:** For reachable operation 0x56d4, if F-9d0ecc5f6adf changes the field at +0xa8, F-c0b020cd3882 receives the field value read after that change, not a value captured before the call.
