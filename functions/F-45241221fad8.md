# F-45241221fad8

## Purpose

F-45241221fad8 performs an equality-gated update of a stored 32-bit value, with dependency calls and indirect notifications surrounding the update.

If the stored value equals the requested value, the function returns without entering the update sequence. Otherwise, it prepares a mutable three-word record, calls F-a062a6eb1219, captures two low-byte baselines, writes the requested value, optionally calls F-6d03eb593399, issues an initial indirect notification, and calls F-a062a6eb1219 again. Two subsequent comparisons can each cause an additional notification.

“Selection,” “identifier,” and “notification” are interpretations of the apparent role, not established domain semantics. The established behavior is the ordered sequence of accesses, calls, assignment, and comparisons described below.

## Interface

The function has four inputs and no represented return value.

| Input | Representation | Use |
|---|---|---|
| Object | Pointer to storage addressed in four-byte words | Provides the stored value, flag, embedded-region address, and indirect-dispatch information |
| Requested value | Signed 32-bit integer | Compared with and explicitly assigned to the stored field; also initializes the first temporary word |
| First auxiliary value | Unsigned 32-bit integer | Initializes the second temporary word |
| Second auxiliary value | Unsigned 32-bit integer | Initializes the third temporary word |

There is no explicit success result, error result, or indication that the update sequence ran.

### Accessed object layout

Offsets below are byte offsets from the object base, derived from the four-byte word indexing in the supplied representation.

| Offset | Established use |
|---|---|
| `0x000` | Read to locate the indirect-dispatch table |
| `0x0C0` | Address passed to F-6d03eb593399 when the flag condition holds |
| `0x0EC` | A 32-bit word is read and converted to character width for a zero test |
| `0x288` | Stored 32-bit value: read for comparisons and call arguments, and explicitly written once on the update path |

Indirect calls select an entry at byte offset `0x58` from the table reference obtained through the object’s first word.

These accesses do not establish the complete object size, class, field types, or embedded-region extent.

### Mutable temporary record

The function initializes three consecutive 32-bit temporary words:

| Record offset | Initial content |
|---|---|
| `0x00` | Requested value |
| `0x04` | First auxiliary value |
| `0x08` | Second auxiliary value |

The supplied representation exposes these words as a mutable 12-byte record beginning at the first word. Both calls to F-a062a6eb1219 receive the same starting address. The words are initialized once, not independently for each call.

The first word carries the requested value’s 32-bit representation. The remaining words are unsigned 32-bit values. The function later masks the second and third words with `0xFF`, producing unsigned comparison values between 0 and 255.

## Behavior

### Equality gate

The function reads the stored field at `0x288` and compares it with the requested value.

If equal, it returns. That path does not initialize the temporary record, write the stored field, read the flag or notification globals, or invoke any dependency or indirect target.

The auxiliary values do not influence the gate.

If unequal, execution proceeds through the update sequence. The comparison does not establish a cached old value for later use: the first dependency’s argument is expressed as another read of the stored field.

### First dependency call and baseline capture

The function initializes the temporary record from the three non-object inputs, then calls F-a062a6eb1219 with:

1. The stored field read from object offset `0x288`.
2. The temporary record’s starting address.

The first argument precedes this function’s explicit assignment, but it must not be treated as an immutable copy of the value used by the equality gate.

After the call returns, the function captures:

- The second temporary word masked with `0xFF`.
- The third temporary word masked with `0xFF`.

The second-word baseline is captured before the third-word baseline.

Both baselines come from the record after the first dependency call. They are not necessarily the low bytes of the original auxiliary inputs. Mutations of any record word by F-a062a6eb1219 are not discarded or reset before the second call.

### Explicit assignment and optional embedded-region call

The function writes the original requested value to object offset `0x288`.

This write does not obtain its value from the temporary record. A dependency’s change to the first temporary word therefore does not, by itself, change the assigned value.

The function then reads the word at object offset `0x0EC`, converts it to character width, and compares that converted value with zero.

- If the converted value is nonzero, it calls F-6d03eb593399 with the address at object offset `0x0C0`.
- Otherwise, it skips that call.

The flag condition is not a full-width nonzero test. A nonzero 32-bit field can take the zero branch if its character conversion yields zero. The exact conversion behavior depends on target character properties that are not supplied.

The explicit stored-value assignment precedes both the flag test and the optional call. No preservation of fields, globals, or other reachable state across that call is established.

### Token capture and initial indirect notification

Two global locations participate in notification arguments:

- A token global, whose contents are captured for possible later notifications.
- A separate global supplying the initial notification’s additional argument.

After the optional embedded-region call, the function reads the token global and saves that 32-bit value locally.

It then issues the initial indirect call through dispatch-table offset `0x58`. The displayed arguments are:

1. The object.
2. A new reference to the token global.
3. A reference to the separate global.

The initial call’s second argument is **not expressed as the saved token**. The supplied representation contains a token capture followed by another reference to that global in the initial call.

Accordingly, the saved token and the initial call’s token argument have distinct read provenance. They can be described as equal only under conditions that keep the token global unchanged across the relevant accesses. The source does not establish a relative evaluation order between the initial call’s two global-valued arguments. It also does not establish their evaluation order relative to resolving the indirect target.

The saved token remains the value used explicitly by later conditional calls. A subsequent change to its source global does not refresh that saved value.

### Second dependency call

After the initial indirect call returns, the function invokes F-a062a6eb1219 again with:

1. A fresh read of the stored field at object offset `0x288`.
2. The same temporary-record address passed to the first call.

The record is not reinitialized. Changes made during the first call remain available unless intervening behavior changes them.

The stored-value argument is not necessarily the original request. For example, an intervening call may change the object field after the explicit assignment. The second dependency receives the value read at its own argument evaluation.

The original low-byte baselines are not recaptured after the assignment, optional call, or initial notification.

### Conditional notifications

After the second dependency returns, the function performs two conditional checks in this order:

1. Compare the third temporary word’s current low eight bits with the third-word baseline.
2. Compare the second temporary word’s current low eight bits with the second-word baseline.

Each inequality causes a separate indirect call through the object’s dispatch-table entry at `0x58`. Each such call has two displayed arguments:

1. The object.
2. The saved token captured before the initial notification.

There are zero, one, or two conditional notifications. If both occur, the third-word notification occurs first.

The second-word comparison occurs after the third-word notification, if that notification is taken. Its result is not captured in advance. If an intervening callee can validly affect the temporary record, its effects can therefore influence the second comparison.

Each notification resolves dispatch through the object again. The function does not retain one indirect target for all notifications, so changes to dispatch state can affect later target selection.

Only low-eight-bit differences matter. Changes exclusively outside those bits do not satisfy either comparison.

Direct effects established by the supplied body are:

- Reads of the stored field, flag field, dispatch information, and notification globals.
- Initialization and later inspection of invocation-local temporary storage.
- One explicit write of the requested value to the stored field on the update path.
- Ordered dependency calls and indirect calls.

Assuming all called operations return normally:

| Path | F-a062a6eb1219 calls | F-6d03eb593399 calls | Indirect calls |

These are direct call-site counts, not counts of any nested or reentrant calls.

The function shows no allocation, release, ownership transfer, rollback, locking, or explicit error handling. Callees may have effects not represented here; their absence cannot be assumed.

The temporary record has invocation-local lifetime. Passing its address does not establish ownership transfer or a right to use that storage after the invocation ends. Whether a dependency retains the address is unknown.

The final stored value need not equal the requested value. Subsequent calls can potentially alter it, and the function performs no restoring assignment.

## Acceptance examples

These are conditional static acceptance scenarios, not executed tests. Unless an example says otherwise, all callees return normally and leave other relevant state unchanged.

1. **Equal values suppress all work.**  
   If the stored value and request are both 17, the function returns without a stored-field write or any dependency or indirect call. Different auxiliary values do not change that result.

2. **Unequal values without low-byte changes.**  
   With stored value 17, request 18, a flag conversion yielding zero, and unchanged comparison bytes across the two dependency calls, the call sequence is first dependency, initial indirect call, second dependency. The write of 18 occurs between the first dependency and the initial indirect call. No conditional notification occurs.

3. **The first dependency defines the baselines.**  
   If the first auxiliary input is 1 but the first dependency changes the second record word to 7, the baseline is 7. If the second dependency leaves that word at 7, that word causes no notification.

4. **High-bit changes are ignored.**  
   A compared word changing from `0x123400AA` at baseline capture to `0xFFFF00AA` at its final comparison does not trigger a notification: both masked values are `0xAA`.

5. **Both comparisons can notify.**  
   If both low bytes differ from their baselines, and the first conditional notification leaves the second comparison’s outcome unchanged, two conditional notifications occur. The third-word notification precedes the second-word notification.

6. **Record mutation does not replace the request.**  
   If the first dependency changes the first temporary word from 18 to 99, the explicit object assignment still writes 18. The second dependency sees the record containing 99 unless intervening behavior changes it.

7. **An intervening field change affects the second dependency.**  
   If the initial notification changes the stored field from 18 to 42, the second dependency receives 42 as its first argument.

8. **The initial token argument is a separate access.**  
   Suppose the saved-token read yields T. The initial call’s token argument comes from a later reference to the token global, not from that saved value. If a valid execution environment permits an intervening update so that this reference yields U, the initial call receives U while any conditional calls receive T. This example does not establish that such an update mechanism exists.

9. **A notification cannot refresh the saved token.**  
   If the saved token is T and the initial notification changes the token global to U, later conditional notifications still receive T.

10. **The initial global arguments have no specified relative read order.**  
    An acceptance check must not require the token argument’s global read to precede the additional argument’s global read, or the reverse. Neither ordering is established by the supplied representation.
