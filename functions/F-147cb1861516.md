# F-147cb1861516

## Purpose

The established behavior is an initialization sequence followed by an unconditional loop. Each iteration makes ordered indirect calls, performs byte-selector reads and byte writes, writes 32-bit values to scaled addresses, reads a 32-bit value from a derived address, and captures a global value in a 32-bit unsigned temporary.

The global’s declaration is absent. Its storage width, actual access width, and any conversion involved in producing the 32-bit captured value are not established.

No normal return, exit condition, bounds check, or explicit error handling is visible. No application-level purpose is established. Address scaling and recurring offsets do not establish an object layout, device interface, or allocation scheme.

This contract describes the supplied static representation. Every later operation is conditional on execution reaching it, preceding calls returning, and preceding accesses succeeding. It does not assign behavior to unresolved dependencies.

### Contract notation

The following symbols are descriptive notation, not implementation identifiers:

- \(W(x)\): the low 32 bits of \(x\).
- \(L_k(x)=W(x\,2^k)\).
- \(E(x)=((x\mathbin{\&}\text{0x3fffffff})\gg20)\), evaluated as an unsigned bit extraction.
- \(R_n\): the final scalar result consumed from iteration stage \(n\).
- \(\operatorname{low}_n,\operatorname{high}_n\): the low and high 32-bit halves of a displayed 64-bit result.
- **Control**: the carried third input.
- **Route**: the carried fourth input.
- **Base**: initially the incoming base.
- **Selector write at \(a\)**: read an unsigned byte at \(a\), then write one byte at the numeric value of that byte plus 17.

All byte stores retain the low eight bits of their specified value. Unless explicitly saved, each selector is read afresh.

Address expressions below use 32-bit wrapping notation. The representation contains signed shifts and multiplications whose portable language semantics do not justify unconditional wrapping. Consequently, the formulas and arithmetic examples describe the apparent 32-bit machine interpretation; executable arithmetic, pointer formation, and address-width behavior remain verification prerequisites.

### Initialization

The five initialization calls execute in order. The first receives the first explicit input; the remaining four have no explicit arguments displayed. The fifth supplies a 64-bit result.

After those calls, the function:

1. Reads one unsigned byte at the incoming base plus 1.
2. Uses that byte’s zero-extended numeric value as an address component.
3. Writes the incoming byte at that component plus 17.

The first loop iteration receives two carried arguments: the initialization result’s low half shifted left by two, and its high half.

The initial indirect target depends on incoming control-address state. Most later targets are formed from fixed address expressions. Stage 01’s first-call target expression differs between the first and subsequent iterations; target identity across those occurrences is not established.

### Width and arithmetic consequences

Under the stated 32-bit interpretation:

- Stage 11’s first argument is zero. \(V\) already contains a left shift by 14; shifting it left by another 28 discards all original bits.
- Stage 24’s stored value is either zero or `0x80000000`, determined by the low bit of \(R_{20}\).
- \(H\) is one of zero, `0x40000000`, `0x80000000`, and `0xc0000000`.
- \(E(x)\) ranges from 0 through 1023. Storing its low byte retains only bits 20–27 of \(x\).
- Stage 24’s derived word-read address ranges from 20 through 1043 inclusive. Alignment is not guaranteed.
- A selector-derived byte-write address ranges from 17 through 272. The saved-selector word-write address ranges from 20 through 275.
- Stage 26’s argument retains only bits 22–25 of \(M\), relocated to bits 28–31.
- Stage 31’s byte value retains bits 22–29 of the captured 32-bit \(G\). This does not establish which bits or bytes of the underlying global storage produced \(G\).

## Side effects

### Access order, overlap, and capture

The ordered accesses are part of the contract, not merely their final memory values. Repeated zero writes and repeated selector reads remain separate operations.

No disjointness is established between selector locations, selector-derived destinations, scaled word locations, or the global’s storage. A word write may overlap a later selector read. A selector write may modify another selector. Dependencies may modify, invalidate, or release storage between accesses.

Stage 30 uses the selector saved at stage 29 despite five intervening calls. It does not reread \(H+1\) for its word store. Stages 31 and 33 do reread that location.

The global is read into the 32-bit unsigned temporary after stage 30’s word store and before stage 31’s calls. Stage 31 derives its byte value from this captured temporary. A subsequent change to the global does not, by itself, replace the captured value.

That ordering does not establish the global’s read granularity, the number of underlying machine accesses, or any conversion used to obtain \(G\). Atomicity of the global capture is also unknown.

Byte order is unspecified. Outcomes involving overlapping word and byte accesses therefore depend on the target memory model.

### Carried state

After a completed iteration:

- Control is the result captured at stage 25.
- Route is the scaled low half captured at stage 31.
- Base is four times that updated Route, modulo 32 bits under the arithmetic interpretation.
- Both carried call arguments equal the scaled stage-34 result.
- Memory and external effects persist unless subsequently changed.

The incoming initialization byte has only one explicit store in the visible body.

## Acceptance examples

These are conditional static consequences, not executed tests. Each assumes the relevant calls return, preceding accesses succeed, and the stated arithmetic interpretation applies.

1. **Initialization selection.** If the initialization selector read yields 7 and the incoming byte is `0xab`, the initialization byte store targets address 24 and writes `0xab`, after all five initialization calls.

2. **Scaled word store.** If Route is 3 and \(R_1=5\), stage 01 stores the 32-bit value 20 at address 12308.

3. **Byte truncation.** If a selector-write value has \(E(x)=1023\), the written byte is 255. The selector’s value, not \(x\), determines the destination.

4. **Discarded argument bits.** For every 32-bit \(R_6\), stage 11’s first argument is zero. Its second argument still depends on unresolved secondary-result behavior.

5. **Saved selector.** If stage 29 captures \(S=9\), stage 30’s word store targets address 29 even if its intervening calls change the byte at \(H+1\) to 40. Stage 31’s fresh selector read can observe 40 if no subsequent operation changes it.

6. **Potentially unaligned read.** If \(R_{21}=\text{0x00100000}\), stage 24 attempts its 32-bit read at address 21. The visible body performs no alignment check; success depends on the target.

7. **Captured global-derived value.** If the stage-30 global assignment produces the 32-bit unsigned temporary value \(G=\text{0x00400000}\), stage 31’s selector write stores byte 1. A global modification during stage 31 does not change this result merely by changing the global. This example specifies the captured value, not the global’s storage contents, width, or read conversion.

8. **Continuation.** After stage 34 completes, execution proceeds to stage 01 again with two equal carried arguments. No visible successful-return case exists.
