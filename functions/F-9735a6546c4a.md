# F-9735a6546c4a

## Purpose

F-9735a6546c4a is a state-driven operation that conditionally inspects a descriptor, invokes one of two descriptor-dependent dependencies, passes retained values to another dependency, invokes a cleanup-like dependency, transforms results, and returns a 32-bit value.

“Acquisition,” “processing,” and “cleanup” describe inferred roles, not established dependency contracts. The evidence does not establish allocation, successful acquisition, ownership transfer, consumption, or release.

External words determine dispatch, comparisons, scaling, and transitions. Their contents are unavailable. The contract therefore establishes conditional state behavior, not a guaranteed state sequence, supported descriptor types, success convention, or termination.

## Interface

### Arguments

The function accepts:

1. **An opaque 32-bit value**, retained for possible use as the second argument to F-024bfae588f9.
2. **A 32-bit integer**, retained for possible use as that dependency’s fourth argument. A later state can replace the installed fourth argument with the acquired-data value.
3. **A descriptor address**, retained separately and installed for inspection only by state 1.

The installed descriptor address initially equals zero. Merely supplying a valid third argument does not make it available to state 5 before installation.

No explicit null, alignment, bounds, descriptor-size, or discriminator validation is visible.

### Descriptor layout

The represented layout uses four-byte words and 32-bit address interpretation.

| Byte offset | Conditional interpretation |
|---|---|
| 0 | 32-bit discriminator |
| 4 | Opaque 32-bit argument to either acquisition-like dependency |
| 8 | 32-bit address of a nested sequence, used on the first acquisition path |
| 12 | 32-bit quantity scaled on the first acquisition path |
| 16 | 32-bit quantity scaled on the second acquisition path |

The first acquisition path reads the first word of the nested sequence and passes an address four bytes beyond its base. The required extent and permissions beyond that first word are unknown.

The descriptor’s offset-8 word is used separately to obtain the nested first-word address and the address passed to the dependency. The representation does not establish a single cached pointer value shared by these uses.

Only conditionally accessed words need be readable for a particular path. The second acquisition path does not visibly use the nested address; the first does not visibly read offset 16.

### Return value and arithmetic

The explicit return is a 32-bit integer. It may be the initialized zero, an external fallback value, a scaled dependency result, a transformed earlier result, or a rescaled saved result.

No universal success or error interpretation is established.

Arithmetic must preserve the represented 32-bit behavior. Dispatch subtraction, sums, products, complement, exclusive-or, and candidate selection are not unbounded integer operations. Explicit signed right shifts are arithmetic shifts. Reproducing represented machine arithmetic requires the relevant low 32 bits; portable signed-overflow semantics are not established by the supplied representation.

## Behavior

### Initialization and dispatch-entry reads

The invocation initializes the acquired-data slot, auxiliary slot, current result, saved result, installed descriptor address, installed opaque argument, installed fourth processing argument, and several working values to zero. Other control and working words receive external initial values. The original arguments remain separately retained.

**Every dispatch iteration first reads an external scaling word, then reads the external dispatch base used for case selection.** This scaling read is unconditional, including when the selected case immediately returns. It is not deferred until a dependency requires scaling.

Dispatch uses the 32-bit difference between the current control value and the newly read dispatch base. Differences 0 through 7 have explicit cases; difference 3 and every unmatched difference share behavior.

The following names distinguish two recurring external locations:

- **Scaling word:** the location read at every dispatch entry.
- **Result-multiplier word:** another location used in result and argument products.

A snapshot denotes a value already read into internal state, not an assertion that the external location remains unchanged. Other external operands are distinct unless an explicit relationship is stated below.

### State 1: install arguments and update control state

This state installs the first input as the opaque processing argument and the second input as the fourth processing argument.

The meaningful order is:

1. Compute the next control value from a retained control word exclusive-ored with an external operand.
2. Invoke F-870c4fcf7295 using a working value plus an external operand.
3. After that call, read an external XOR operand and update one retained control word; retain the helper’s secondary output as a working value.
4. Invoke F-870c4fcf7295 using a different working value plus another external operand.
5. After the second call, read another XOR operand and update a different retained control word.
6. Install the retained descriptor address.
7. Read two external values into working/control state, and retain the second helper’s secondary output.

Both helper calls receive 2,147,483,647 as their second argument. The first next-control calculation precedes both calls; it is not recomputed using later external contents.

No descriptor contents are read here.

### State 5: inspect and select acquisition behavior

Entry first clears the acquired-data slot, then reads and retains the installed descriptor’s discriminator. The auxiliary slot is not cleared.

Three F-870c4fcf7295 calls follow, each with second argument 2,147,483,647. Their first arguments are working values plus external operands. Relevant interleaving is:

- After the first call, an external XOR operand is read to update one control word, and the first secondary output updates working state.
- After the second call, two external XOR operands update two other control words, and the second secondary output updates working state.
- After the third call, the function reads, in order: the result-multiplier word, the scaling word, an external control-word assignment, and an external working-value assignment.

The scaling read after the third call **replaces the dispatch-entry scaling snapshot** for subsequent result scaling in this state. The result-multiplier snapshot is also taken after that helper, before either acquisition dependency.

The discriminator remains the value read before all three helpers.

#### First comparison and acquisition path

The first condition adds the retained discriminator to a newly read external comparison offset and tests whether the 32-bit sum is zero.

If true, F-29c9eb24f817 receives:

1. An external 32-bit value.
2. The address of the acquired-data slot.
3. The address of the auxiliary slot.
4. Descriptor word at offset 4.
5. The nested sequence’s first word, multiplied by an external length-scale word and a read of the scaling word.
6. Descriptor word at offset 12, multiplied by an external length-scale word and a read of the scaling word.
7. An address four bytes beyond a base obtained from descriptor offset 8.

The external scale reads used in these arguments are separate from the retained result-scaling snapshot. A total order among reads within the argument list is not established.

After F-29c9eb24f817 returns, the function **reads the result-multiplier word again**. Its primary result is multiplied by that post-call multiplier and by the post-third-helper scaling snapshot twice.

Thus this path does not use the pre-acquisition result-multiplier snapshot for result scaling. The two occurrences of the scaling factor do use the same retained value.

A retained control word exclusive-ored with an external operand determines the next control value. The third helper’s secondary output becomes a working value, and dispatch resumes without the common transition helper.

#### First comparison fails

Before evaluating the second condition, the function reads an external fallback transition operand, selects a working transition value, reads an external fallback result, and retains the third helper’s secondary output.

The second condition then adds the same retained discriminator to **a fresh read of the external comparison offset** and compares that sum with a separately read external comparison value.

The first sum is not reused. The two offset reads need not agree. The evidence establishes that the fallback reads occur between the conditions, but does not establish a total ordering between operands within the second comparison.

If the second condition matches, F-57598f835995 receives:

1. The address of the acquired-data slot.
2. Descriptor word at offset 4.
3. The address of the auxiliary slot.
4. Descriptor word at offset 16, multiplied by fresh argument-time reads of the result-multiplier word and scaling word.

After this dependency returns, another external operand and a retained working value select the transition inputs. Its primary result is multiplied by **the result-multiplier snapshot captured after the third helper**, and by the replacement scaling snapshot twice. No post-acquisition reread of the result-multiplier word participates in this result scaling.

If neither comparison matches, neither acquisition dependency is called. The externally loaded fallback result remains current.

Both the second acquisition path and the unmatched path finish through the common transition operation described below.

### State 0: select using acquired-data value

Before calling any helper, this state captures whether the acquired-data slot is nonzero and copies its value into the fourth processing argument.

It then:

- Calls F-870c4fcf7295 with a working value plus an external operand.
- Reads an external XOR operand to update a control word and retains that call’s secondary output.
- Calls the helper twice more, using another working value minus separate external operands.

All three calls have second argument 2,147,483,647. The second secondary output supplies the nonzero transition candidate; the third supplies the zero candidate.

Selection uses the condition captured before the calls. Neither that condition nor the copied fourth argument is recomputed afterward. A numeric nonzero value does not establish valid storage, ownership, or acquisition success.

### State 2: invoke processing-like dependency

F-024bfae588f9 receives:

1. The auxiliary slot multiplied by **a separate, argument-time read of the scaling word**.
2. The installed opaque processing argument.
3. The acquired-data slot.
4. The installed fourth processing argument.

After the dependency returns, the function reads the result-multiplier word. The current result becomes the dependency result multiplied by that post-call multiplier and by the **dispatch-entry scaling snapshot twice**. The saved result receives the same value.

Consequently, the first argument’s scaling read and the result’s scaling snapshot are distinct read epochs. A dependency-induced change to external storage does not retroactively change the captured scaling factor.

The next control value is derived from a retained control word and an external XOR operand. The fourth argument remains history-dependent: it can be the original second input, the acquired-data value copied by state 0, or its initialized zero if installation has not occurred.

### State 3 and unmatched dispatch differences: transform result

This behavior computes two products from the current result:

- One uses the result-multiplier word directly.
- The other uses an XOR involving reads of that word, with one operand interpreted as signed and shifted right by 28 bits.

The selection bit is one exactly when bit 31 of both product bit patterns is clear; otherwise it is zero. Repeated external references are reads, not a promise that all multiplier values agree.

The current result is separately multiplied by a read of the result-multiplier word and a read of the scaling word. This scaling read is not replaced by the dispatch-entry snapshot. The transformed result is also saved.

A control-word XOR occurs before two F-870c4fcf7295 calls. These use subtraction-derived first arguments and the usual second argument. After the calls, another control-word XOR occurs. Two XOR-derived transition candidates are combined using the previously computed selection bit; the secondary outputs update working values.

The predicate must not be replaced with “result is zero,” “result is negative,” or “dependency succeeded.”

### State 4 and the common transition

State 4 calls F-5e3309c9d083 with the acquired-data value, without a visible nonzero guard.

Only after that call does it read its external transition operand and select a retained working value. The common transition calls F-870c4fcf7295 with the selected working value minus the selected operand, and with second argument 2,147,483,647. The secondary output becomes the next control value.

The acquired-data slot is not visibly cleared after F-5e3309c9d083. Repeated visits can therefore pass the same value again.

### States 6 and 7

State 6 multiplies the saved result by an external factor to produce the current result, then derives the next control value from a retained control word and an external XOR operand.

State 7 returns the current result immediately. It performs no additional dependency call or cleanup, but the unconditional dispatch-entry scaling and dispatch-base reads have already occurred.

## Side effects

Direct external-data operations are reads. Direct descriptor and nested-sequence operations are also reads; no direct write into either is visible.

The acquisition dependencies receive addresses of two internal 32-bit slots and can update them. The function does not establish whether either dependency retains those addresses. Their storage belongs to the invocation; post-return validity is not established.

The acquired-data slot is cleared on every entry to state 5. The auxiliary slot is initialized only once and can retain a dependency-written value across repeated visits.

There is no explicit allocation operation. Passing the acquired-data value to other dependencies establishes neither ownership transfer nor release.

Dependencies have no established preservation guarantee. They may change externally read storage or other reachable memory. Accordingly:

- Post-call reads cannot be substituted with earlier reads of the same location.
- Captured values remain distinct from later external contents.
- The retained discriminator is not reread after the three helpers.
- Argument evaluation does not establish a total order among multiple reads within a single call expression.

No local exception handling, invalid-address recovery, rollback, timeout, or guaranteed cleanup-on-return is visible.

## Acceptance examples

These are conditional static requirements, not runtime observations.

1. **Immediate return:** If initial dispatch selects state 7, the returned value is zero. Initialization reads, the dispatch-entry scaling read, and the dispatch-base read still occur. No descriptor read or dependency call occurs.

2. **Processing changes scaling storage:** Suppose state 2 captures scaling value 3 at dispatch entry, its argument-time read observes 5, and processing returns 7. If the post-call multiplier read observes 2, the first argument uses auxiliary times 5, while result scaling yields 126 modulo the represented width.

3. **First acquisition changes multiplier storage:** Suppose state 5 captures multiplier 2 and replacement scaling value 3 after its third helper. If F-29c9eb24f817 returns 7 and the subsequent multiplier read observes 5, the current result becomes 315, not 126.

4. **Second acquisition changes multiplier storage:** Under the same snapshots, if F-57598f835995 returns 7, its result scales to 126 even if that dependency changes the external multiplier to 5. Its fourth argument uses separate argument-time reads.

5. **Comparison offset changes:** If the retained discriminator is 10, the first offset read is zero, the second offset read is 2, and the second comparison value is 12, the first condition fails and the second matches. The discriminator is not reread.

6. **Both tests could match:** A true first condition selects F-29c9eb24f817 without evaluating the second condition. The alternative acquisition is not called on that visit.

7. **Neither comparison matches:** Neither acquisition dependency runs; the fallback result and common transition apply. Immediate return is not established.

8. **Captured nonzero choice:** If state 0 starts with a nonzero acquired-data value, it copies that value and selects the nonzero candidate using its pre-helper condition. This does not establish that processing follows.

9. **Zero cleanup:** Reaching state 4 with zero still invokes F-5e3309c9d083 with zero. Its outcome is documented_only.

10. **Unreadable installed descriptor:** Reaching state 5 without readable descriptor storage has no established local recovery or defined error return.
