# F-45f54b47fb45

## Purpose

F-45f54b47fb45 conditionally transfers an object-resident record into caller-provided storage and returns the object’s final status byte.

The supplied static body establishes three paths:

- A nonzero status observed after an unconditional dependency call bypasses further processing.
- A zero status permits setup, optional preparation, and three ordered checks. The first nonzero check result causes a direct status-byte write of 3.
- Three zero check results permit a fixed-layout transfer followed by two object-resident flag writes.

Both rejection and successful transfer are followed by final dependency processing. The nonzero-status bypass omits that processing.

The return value is a fresh status-field observation, not an independently computed success indicator. A successful transfer does not directly clear the status field. Dependency effects can therefore make the returned status differ from the apparent outcome of the checks.

## Behavior

### Unconditional entry call and status gate

The first operation is a call to F-d3d627eaec9e with the output address. Its result is not visibly used. The supplied body does not establish that this dependency initializes or writes output.

After that call returns, the function reads object byte 0x6A8.

If the observed byte is nonzero:

- No further dependency is called by this body.
- No direct output transfer occurs.
- No direct object-field write occurs.
- Object byte 0x6A8 is read again, and that second observation is returned.

The entry dependency can affect the gate through any effects it has on object storage, including effects through an aliased output address. Consequently, the bypass path does not guarantee unchanged output or unchanged object storage.

The gate and return are separate observations. The body does not establish that their values must agree if storage changes between them.

### Zero-status setup

The supplied body then contains two distinct reads of the same external 32-bit global:

1. A first observation is retained for final processing.
2. A separate observation supplies the second argument to F-1a5cca324bde.

F-1a5cca324bde receives the acquisition result, the second global observation, and two zero arguments.

The body does not substitute the retained observation for the second read. Although no visible dependency call separates the two reads, equality of their values is not an established requirement. The retained first observation is not refreshed before final processing.

### Optional preparation

- If this byte is zero, optional preparation is omitted, and offset 0x1C is not read for this gate.
- If the byte is nonzero, the 32-bit field at 0x1C is read.

### Ordered checks and rejection

The checks interpret their 32-bit results only as zero or nonzero. A negative nonzero value rejects just as a positive nonzero value does.

| Dependency | Dispatch-table offset | Explicit arguments shown | Result handling |
|---|---:|---|---|
| D-01 | 0x08 | Selected target object; object address plus 0x58 | Zero continues; nonzero rejects |
| D-02 | 0x18 | None shown | Zero continues; nonzero rejects |
| D-03 | 0x10 | Selected target object; 32-bit field at object offset 0x458 | Zero permits transfer; nonzero rejects |

The checks short-circuit. D-02 is omitted when D-01 rejects. D-03 is omitted when either earlier check rejects. The field at 0x458 is read for D-03 only when both earlier checks return zero.

On rejection, the function writes byte value 3 to object offset 0x6A8. It omits the transfer and both successful-path flag writes, then proceeds to final processing.

Dispatch selection is evaluated at the individual call sites, rather than captured once for all three checks. An earlier dependency’s changes to offset 0x61C or dispatch storage can therefore affect later calls. The body does not establish a detailed evaluation order among the separate reads forming a single indirect call.

D-02 has no explicit arguments in the supplied representation. This does not establish a complete argument-free calling convention or exclude implicit call state.

There is no second status gate after setup or preparation. A dependency’s change of status to a nonzero value does not independently prevent transfer if all three checks return zero.

- The gate and all three checks return zero.

- Source contents remain stable throughout the transfer.
- D-04 transfers exactly the requested bytes without conversion or unrelated effects.
