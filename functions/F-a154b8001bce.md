# F-a154b8001bce

## Purpose

F-a154b8001bce processes a two-component composition request using a mutable context, displacement arguments, and two character-code arguments. It resolves both character codes to nonnegative component identifiers, then follows one of two modes:

- **Descriptor mode:** requests capacity through a dependency, writes selected fields of two descriptors, and publishes associated output metadata.
- **Callback mode:** invokes a preparation dependency, processes the first component, installs displacement state, and processes the second component. Selected context state is restored only after the second callback succeeds.

The apparent purpose is glyph composition. That interpretation does not establish complete rendering semantics or equivalence between the modes.

Two descriptor-mode values come from **distinct 32-bit global storage reads**, not established constants. Their values and mutability are unknown. Their read timing is part of the contract.

This document describes static evidence only. No runtime tests have been performed.

### Global inputs

Two distinct global storage locations are relevant only in descriptor mode:

- **Global slot A:** read as a 32-bit value immediately after F-d0804a542462 returns, before its result is checked. On reservation success, the low 16 bits of the captured value become the first descriptor’s 16-bit field.
- **Global slot B:** read as a 32-bit value after the descriptor writes and the output-object writes at `0x80` and `0x84`. Its value is written immediately to output-object offset `0x48`.

Neither location is established as immutable. Neither value is captured at function entry. Dependency effects or preceding potentially aliasing writes may affect the value observed at its read.

### Preconditions and arithmetic

The function first adds the entry value at context offset `0x30` to the horizontal-displacement argument. Later, on either processing path, it subtracts the horizontal adjustment from that retained sum.

Both operations use signed 32-bit operands. Results are established when the addition and any subsequently executed subtraction are representable in signed 32 bits. There is no visible range check, saturation, or explicit overflow handling. Behavior outside that domain is **documented_only**, not a promised wraparound contract.

Required references, writable storage, global slots, and callback addresses must be valid when accessed. The function does not visibly validate them. In particular, descriptor mode requires global slot A to be readable even when the reservation dependency returns an error.

## Behavior

### Entry capture and availability

The first visible context access reads the 32-bit field at `0x30`. The function adds that value to the horizontal-displacement argument and retains the result.

It then reads the availability field at `0x55C`.

If availability is zero:

1. F-4457a9a44a68 receives an operation-identifying diagnostic argument.
2. F-4457a9a44a68 receives an unavailable-information diagnostic argument.
3. The function returns `0xA0`.

No character-code resolution, mode-byte read, reservation, or component callback occurs on this path. The initial horizontal read and addition have already occurred. Diagnostic return values are ignored.

The exact diagnostic strings are not established by the supplied representation.

### Character-code resolution and mode selection

With nonzero availability, the function invokes F-f2b46abfb8ea twice:

1. Context and first character code.
2. Context and second character code.

The second call occurs even if the first result is negative. The first result is retained across the second call.

Both results are interpreted as signed 32-bit identifiers. Zero is valid; either negative result causes an error. On that error, the function sends the operation-identifying diagnostic and then an invalid-character-code diagnostic through F-4457a9a44a68, returning `0xA0`.

Lookup effects are not rolled back.

Only after both identifiers pass does the function read the byte at context offset `0x52`. Thus, lookup-induced changes can affect the selected mode. Availability is not checked again.

The retained horizontal sum still uses the entry read from `0x30`; it is not recomputed from lookup-modified state.

### Descriptor mode: references and reservation

For a nonzero mode byte, the function:

1. Reads the output-object reference from context offset `0x08`.
2. Reads an address-bearing field at output-object offset `0x9C`.
3. Dereferences that address to obtain a descriptor-container address.
4. Calls F-d0804a542462 with the container and integer `2`.
5. Reads 32 bits from global slot A.
6. Checks the reservation result.

A nonzero reservation result is returned unchanged. **The global-slot-A read still occurs on this failure path.** There are no subsequent direct descriptor or publication writes, and global slot B is not read.

The output-object and container addresses are captured before reservation and reused afterward. The function does not reload them from the context or output-object reference chain. Safe continuation requires those captured addresses to remain usable.

### Descriptor mode: record writes

After a zero reservation result, the function reads the descriptor-storage address from container offset `0x50`.

The following writes occur in order, relative to that storage address:

| Order | Offset | Width | Value |
|---:|---:|---:|---|
| 1 | `0x00` | 32 bits | First resolved identifier |
| 2 | `0x04` | 16 bits | Low 16 bits of the captured global-slot-A value |
| 3 | `0x08` | 32 bits | Zero |
| 4 | `0x0C` | 32 bits | Zero |
| 5 | `0x20` | 32 bits | Second resolved identifier |
| 6 | `0x24` | 16 bits | `2` |
| 7 | `0x28` | 32 bits | Retained horizontal sum minus horizontal adjustment |
| 8 | `0x2C` | 32 bits | Vertical-displacement argument |

The descriptor starts are separated by 32 bytes. This establishes spacing, not the complete descriptor layout.

Within the two-record span, the function does not explicitly initialize bytes `0x06–0x07`, `0x10–0x1F`, `0x26–0x27`, or `0x30–0x3F`. Their contents depend on prior storage state and dependency behavior.

The first descriptor’s 16-bit value comes from the already completed global-slot-A read. Later writes do not trigger a reread of that slot.

### Descriptor mode: publication

After the eight descriptor writes, the function performs this sequence:

1. Write 32-bit value `2` to output-object offset `0x80`.
2. Read 32 bits from container offset `0x30`.
3. Write that value to output-object offset `0x84`.
4. Read 32 bits from global slot B.
5. Write that value to output-object offset `0x48`.
6. Write 32-bit value `2` to container offset `0x4C`.
7. Return zero.

The global-slot-B read is therefore later than both the descriptor writes and the publication writes at `0x80` and `0x84`. Its value is not established to match entry state or state immediately after reservation.

The read from container offset `0x30` is likewise performed after preceding writes. The supplied evidence does not establish non-aliasing between these objects and global storage. Where aliasing exists, earlier writes may affect later reads.

The value published at output-object offset `0x84` is not established to equal the descriptor-storage address obtained from container offset `0x50`.

### Callback mode: preparation and first component

For a zero mode byte, the function reads context offset `0x0C` and passes the 32-bit value to F-90cd2aa8d620. It does not test a return value from that call.

It then reads the callback address from context offset `0x5D0` and invokes the selected target with the context and first resolved identifier.

A nonzero callback result is returned immediately. At that point, the function has not yet saved restoration state or performed its explicit displacement writes. Preparation and callback effects remain.

### Callback mode: second component and restoration

After a zero first-callback result, the function saves current context values in this order:

1. `0x38`
2. `0x3C`
3. `0x30`
4. `0x34`

These are post-first-callback snapshots, not entry snapshots.

It then writes, in order:

1. Zero to `0x30`.
2. Zero to `0x34`.
3. Retained horizontal sum minus horizontal adjustment to `0x28`.
4. Vertical-displacement argument to `0x2C`.

The function reads the callback address at `0x5D0` again and invokes that target with the context and second resolved identifier. The target may differ from the first invocation’s target.

If the second callback returns nonzero, that result is returned immediately. No success-path restoration or clearing occurs.

If it returns zero, the function writes:

1. Zero to `0x28`.
2. Saved value to `0x38`.
3. Saved value to `0x3C`.
4. Saved value to `0x30`.
5. Saved value to `0x34`.
6. Zero to `0x2C`.

It then returns zero. Initial values at `0x28` and `0x2C` are never saved; success clears rather than restores them.

## Side effects

Descriptor mode directly modifies selected descriptor fields and four output/container publication fields. It also reads both global slots on success, but only global slot A on reservation failure. No direct write to either global slot is explicitly designated; writes through potentially aliasing storage remain possible.

Callback mode directly changes six context fields after the first callback succeeds. On successful completion, `0x28` and `0x2C` are zero, while `0x30`, `0x34`, `0x38`, and `0x3C` regain their post-first-callback values.

Failure is not atomic:

- Lookup effects survive identifier rejection.
- Reservation effects may survive reservation failure.
- Preparation and callback effects survive callback failure.
- Second-callback failure skips all restoration writes.

On second-callback failure, the installed displacement values are not guaranteed to remain: the callback may have modified them.

No direct allocation, release, reference-count operation, or ownership transfer is established. Dependencies may manage storage or mutate globals, references, and context state. Their preservation and ownership behavior must not be assumed.

The described ordering is sequential behavior, not a guarantee of atomic publication, synchronization, or thread safety.

## Acceptance examples

These are conditional specification examples, not executed tests. They assume valid accessed storage and representable arithmetic.

1. **Unavailable information.** With availability zero, the entry horizontal contribution is read and added before two diagnostics and return `0xA0`. No lookup occurs.

2. **First identifier rejected.** With lookup results `-1` and `7`, both lookups occur before the diagnostic pair and return `0xA0`. No mode-specific work follows.

3. **Zero identifiers accepted.** Results `0` and `0` pass validation. The post-lookup mode byte selects subsequent behavior.

4. **Descriptor displacement.** With entry contribution `20`, horizontal displacement `7`, horizontal adjustment `5`, and vertical displacement `-3`, successful descriptor mode writes `22` and `-3` into the second descriptor’s displacement fields. The first descriptor’s explicitly written displacement fields are zero.

5. **Reservation error still reads global state.** With reservation result `9`, the function reads global slot A and then returns `9`. It performs no direct descriptor or publication writes and does not read global slot B.

6. **Reservation changes global slot A.** If reservation changes slot A to `0x1234ABCD` and returns zero, and that value remains until the subsequent read, the first descriptor receives `0xABCD` in its 16-bit field. An earlier value is irrelevant.

7. **Late global-slot-B observation.** If a preceding write aliases slot B, the subsequent slot-B read observes the resulting storage state under the stated sequential ordering. For example, if slot B is exactly the 32-bit location at output-object offset `0x80`, the write of `2` there precedes the slot-B read, so `2` is then written at output-object offset `0x48`.

8. **Post-callback restoration snapshot.** If the first callback changes `0x30–0x3C` and succeeds, the saved values are those changed values. Second-callback success restores them, not entry values.

9. **Second callback fails.** With second-callback result `12`, the function returns `12` without restoration. If that callback leaves the displacement fields untouched, they retain the installed values.

10. **Callback replacement.** If the first callback replaces the address at `0x5D0` and succeeds, the second invocation uses the replacement address.

- Complete object layouts and initialization requirements.

Inferred intent is two-component composition through either stored descriptors or direct callbacks. Complete rendering behavior and equivalence between modes are not established.
