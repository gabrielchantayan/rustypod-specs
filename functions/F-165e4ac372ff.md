# F-165e4ac372ff

## Purpose

F-165e4ac372ff converts a dependency-provided, zero-terminated byte sequence into a signed integer using decimal fields, colon-separated base-60 accumulation, and final multiplication by 1,000.

The established behavior is permissive, not validating. ASCII digits contribute to the current decimal field. ASCII colons commit fields into a base-60 accumulator. Every other nonzero byte is ignored without separating digits or terminating traversal.

**Inferred intent:** the factors 60 and 1,000 suggest conversion of a time-like quantity into milliseconds. The interface does not establish units, a required number of fields, or conventional ranges for individual fields.

The arithmetic has distinct signed and unsigned stages. Decimal-field multiplication is signed, but the following byte addition and ASCII-offset adjustment are unsigned. This distinction matters both for ordinary inputs and for inputs near the signed range boundary.

## Behavior

### Dependency call and initial state

The function first calls F-44362605ab79 once, passing only the second argument. No sequence byte is read before the call returns.

Parsing starts at the returned address with two signed 32-bit numeric quantities initialized to zero:

- the **committed accumulator**, containing fields already ended by colons;
- the **current field**, containing the decimal accumulation since the latest colon.

These names describe internal parsing state, not caller-visible storage.

### Traversal and byte classification

Each iteration reads one byte at the current address and widens its unsigned value.

| Byte value | Treatment | Effect |
|---|---|---|
| 0x00 | Terminator | Stop traversal and calculate the return value. |
| 0x30–0x39 | ASCII digit | Update the current decimal field. |
| 0x3A | ASCII colon | Combine the committed accumulator with the current field, then clear the current field. |
| Any other nonzero value | Ignored | Leave both numeric quantities unchanged. |

After processing a nonzero byte, the read position advances by one byte. Processing of that byte precedes the next byte read.

A colon does not also undergo decimal-digit accumulation. The zero terminator is read but is not processed as field content. No byte after the first zero byte is read by this function.

### Decimal fields

Within the ordinary representable range, each digit multiplies the current field by ten and adds the digit’s value.

Digits are collected in encounter order. Ignored bytes do not interrupt that collection: `1x2` contributes the field value 12, not separate values 1 and 2.

There is no explicit limit on field width and no requirement that a field be less than 60. Only the literal colon byte separates fields.

Other syntax has no special interpretation:

- `-` does not negate a value.
- `+` does not introduce a sign mode.
- `.` does not introduce a fractional component.
- Spaces and other nonzero whitespace do not separate fields.
- Non-ASCII bytes do not become digits through locale or encoding interpretation.

Each such byte is ignored unless it is zero, which terminates traversal.

### Colon-separated accumulation

For a colon, the committed accumulator is multiplied by 60, the current field is added, and the current field is reset to zero. Both the multiplication and addition are signed operations.

At the terminator, the function performs another signed base-60 combination of the committed accumulator and current field, then multiplies that result by 1,000.

For decimal fields \(f_0, f_1, \ldots, f_k\), separated by \(k\) colons, the ordinary mathematical result is:

\[
1000\sum_{j=0}^{k} f_j60^{k-j}.
\]

This expression applies only under the representability conditions above; it does not imply arbitrary-precision arithmetic.

Empty fields contribute zero:

- A leading colon commits an initial zero.
- A trailing colon leaves an empty final field, so termination applies another factor of 60.
- Repeated colons introduce empty intermediate fields, each retaining the corresponding base-60 position.

Consequently, trailing or repeated colons are not merely discarded formatting.

### Integer widths and arithmetic conversions

The supplied model distinguishes:

- 8-bit unsigned sequence bytes;
- a 32-bit unsigned widened byte value;

#### Decimal-field multiplication

The current field is first multiplied by 10 as a signed operation.

If that multiplication exceeds the signed 32-bit range, its outcome is not established by this contract. Later unsigned operations do not make an overflowing signed multiplication safe.

#### Unsigned additions and ASCII adjustment

The signed product is then combined with the widened unsigned byte. Under the arithmetic conversions represented by the source, that addition is unsigned. The subsequent addition of the negative ASCII offset is also unsigned.

In the 32-bit unsigned domain:

- the offset \(-48\) is represented as \(2^{32}-48\), or 4,294,967,248;
- both additions are evaluated modulo \(2^{32}\);
- unsigned wraparound at these stages is defined arithmetic, not signed-addition overflow.

For example, the first digit `7` begins with a signed product of zero. Adding its byte value gives unsigned 55. Adding the unsigned representation of \(-48\) yields 7 modulo \(2^{32}\). This ordinary digit conversion therefore uses unsigned modular arithmetic even though its resulting field value is small.

When the signed product is nonnegative and representable, these unsigned operations produce the expected decimal update modulo \(2^{32}\). There is no separate signed addition of the digit value at this stage.

#### Assignment back to signed field storage

The unsigned result is assigned back to the signed current field.

If that result is at most 2,147,483,647, the assigned value is representable and the ordinary decimal interpretation is preserved.

If the result is larger, the conversion back to signed storage is a separate unresolved behavior. It must not be described as signed-addition overflow or assumed to produce a particular negative value.

For example, while processing the last digit of `2147483648`:

- the preceding field is 214,748,364;
- its signed multiplication by 10 produces 2,147,483,640, which is representable;
- the unsigned byte addition and offset adjustment produce 2,147,483,648;
- that value is outside the signed field’s positive range.

Thus this input reaches an out-of-range unsigned-to-signed assignment without requiring overflow in that particular decimal multiplication. No complete return value is specified for it.

#### Base-60 operations and scaling

The following operations remain signed:

- multiplying the committed accumulator by 60 at a colon;
- adding the current field at a colon;
- multiplying the committed accumulator by 60 at termination;
