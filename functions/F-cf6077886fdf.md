# F-cf6077886fdf

## Purpose

F-cf6077886fdf conditionally sends a 32-bit selection value to a receiver associated with an object. It obtains that value through one of three paths:

- A request field, when a preliminary comparison succeeds.
- An unsigned item index, when an item found during enumeration satisfies the comparison.
- The all-ones value `0xFFFFFFFF`, when a separate request predicate returns nonzero.

Some paths perform no selection call.

**Inferred intent:** the operation appears to reconcile a requested item with an object’s current contents, using a request-associated value for comparison and a numeric field as a preferred selection. The supplied evidence does not establish the domain meaning of the compared values, the request predicate, or the all-ones selection. Those meanings are not contractual.

This specification describes the visible control flow, argument values, memory accesses, and temporary-object lifecycle. Dependency internals remain unknown.

## Behavior

### 1. Establish temporary lifetime

The first visible operation calls F-b02b795a8319 with the address of an outer temporary.

That temporary remains live through the operation. On every explicit normal-return path, F-ee5919ca4be6 is eventually called on it.

### 2. Attempt the preliminary comparison only for a positive numeric field

If the initial signed field is at least one, the function performs a preliminary comparison before considering the shared fallback path.

The visible sequence is:

1. Invoke dispatch entry `0x148` with temporary output storage and the object, with no explicit index argument in the supplied representation.
2. Call F-46f0b3cb316e with:
   - A destination beginning four bytes into the initialized outer temporary.
   - A source beginning four bytes into the dispatch output.
3. Copy the 32-bit word at output offset `0x0C` into outer-temporary offset `0x0C`.
4. Destroy the dispatch output through F-ee5919ca4be6.
5. Construct a comparison temporary from the outer temporary’s `+0x04` region using F-b9acea4b06ad.
6. Obtain a 32-bit value from that comparison temporary using F-44362605ab79.
7. Construct another comparison temporary from request offset `0x04` using F-b9acea4b06ad.
8. Pass the request-derived temporary and the obtained value to F-4a902fecdea3.
9. Destroy the request-derived comparison temporary, then the outer-derived comparison temporary, using F-289ec4311c64.

The copy operation in step 3 is a distinct raw-word transfer. The source and destination extents used by F-46f0b3cb316e are not established; they must not be inferred solely from the adjacent field offsets.

The preliminary comparison is successful **only when F-4a902fecdea3 returns exactly zero**.

If successful:

- Read request offset `0x0C` again.
- Read the receiver from object offset `0x40`.
- Call F-5d764b99602e with that receiver and the newly read request word.
- Destroy the outer temporary and return.

No request predicate or enumeration-count query is performed on this successful path.

If unsuccessful, continue to the shared fallback path. The outer temporary, including the content populated during this preliminary attempt, remains live until final cleanup.

### 3. Evaluate the shared fallback predicate

The shared fallback path is reached when either:

- The initial signed numeric field is less than one; or
- The preliminary comparison returned nonzero.

The function:

1. Constructs a temporary from request offset `0x04` using F-b9acea4b06ad.
2. Calls F-6d70e45e29c9 on that temporary.
3. Destroys the temporary using F-289ec4311c64.
4. Branches on the returned value.

A nonzero result causes the function to:

- Read the receiver at object offset `0x40`.
- Call F-5d764b99602e with that receiver and `0xFFFFFFFF`.
- Destroy the outer temporary and return.

The exact predicate meaning is unknown. “Nonzero” must not be replaced with “empty,” “invalid,” or another domain-specific interpretation without additional evidence.

A zero result causes enumeration.

### 4. Enumerate and select the first matching index

The function calls dispatch entry `0x114` with the object and captures an unsigned 32-bit count.

It then visits unsigned indices in ascending order, beginning at zero and stopping before the captured count. The count is not queried again.

For each index:

1. Invoke dispatch entry `0x148` with item-output storage, the object, and the current index.
2. Construct an item-derived comparison temporary from item-output offset `0x04`, using F-b9acea4b06ad.
3. Obtain a 32-bit value from that temporary using F-44362605ab79.
4. Construct a request-derived comparison temporary from request offset `0x04`, using F-b9acea4b06ad.
5. Call F-4a902fecdea3 with the request-derived temporary and the obtained value.
6. Destroy the request-derived temporary.
7. Destroy the item-derived temporary.

If the comparison result is zero:

1. Read the receiver at object offset `0x40`.
2. Call F-5d764b99602e with that receiver and the current index.
3. Destroy the item output using F-ee5919ca4be6.
4. Stop enumeration.

If the comparison result is nonzero, destroy the item output and continue with the next index.

After enumeration ends, destroy the outer temporary and return.

There is no selection call when the count is zero or when every visited comparison returns nonzero. In particular, failure to find a match does not cause an all-ones selection.

### 5. Integer boundaries

The comparison-return handling reduces exactly to a zero test:

- `0` succeeds.
- `1` fails.
- Every unsigned value greater than `1` fails, including `0xFFFFFFFF`.

The intermediate subtraction visible in the supplied representation does not make larger nonzero values acceptable.

The initial signed request-field test treats:

- `0x00000001` through `0x7FFFFFFF` as positive.
- Zero and all negative signed values as bypassing the preliminary attempt.

Enumeration uses an unsigned count. If the count is `0xFFFFFFFF`, eligible indices range from zero through `0xFFFFFFFE`. The index reaches the count and terminates without requiring wraparound.

No visible check requires a successfully forwarded request word to be below the enumeration count. That count is not even obtained on a successful preliminary path.

## Acceptance examples

These are conditional static acceptance cases, not runtime observations. Unless stated otherwise, assume dependencies return normally and do not mutate relevant inputs.

1. **Positive request, preliminary success.**  
   The initial signed request field is `7`; the preliminary comparison returns zero. Exactly one selection call receives the current receiver and `7`. Neither the fallback predicate nor the count query is called.

2. **Request word changes before forwarding.**  
   The initial signed field is `7`, but a dependency changes it to `0xFFFFFFFF` before the successful path rereads it. The selection call receives `0xFFFFFFFF`. The caller does not reapply the positive-field condition.

3. **Positive request, preliminary failure, nonzero predicate.**  
   The preliminary comparison returns `1`; the fallback predicate returns nonzero. The selection value is `0xFFFFFFFF`, and enumeration does not occur.

4. **Nonpositive request, first enumerated match.**  
   The initial signed field is zero; the fallback predicate returns zero; the captured count is four. Comparison results at indices zero, one, and two are respectively `5`, `1`, and `0`. The selection value is `2`; index three is not fetched.

5. **No match.**  
   The predicate returns zero and all enumerated comparison results are nonzero. No selection call occurs. Every produced item output and the outer temporary are finalized.

6. **Empty enumeration.**  
   The predicate returns zero and the count is zero. No indexed output is requested and no selection call occurs.

7. **Negative signed field.**  
   The field contains `0x80000000`. The preliminary attempt is skipped because its signed interpretation is negative. Subsequent behavior depends on the fallback predicate and, if needed, enumeration.

8. **Large nonzero comparison result.**  
   A comparison returns `0xFFFFFFFF`. It is a failure, not a match. During enumeration, the item is finalized and scanning continues.

9. **Selection changes the item’s context.**  
   On an enumerated match, F-5d764b99602e runs before item-output finalization. Any implementation whose observable behavior depends on that lifetime must preserve this order.
