# F-d23c6f7d70c9

## Purpose

F-d23c6f7d70c9 performs two sequential notification checks on a mutable object.

The first check depends on a temporary 24-byte region and a predicate applied to an interior region of the object. The second compares an initially obtained signed value with a reference field read later in the invocation. A representable absolute difference greater than 999 triggers two dependency calls, an indirect notification, and an update of the reference field.

The qualifying second path reads its global payload source **twice**. The first read is retained for the indirect notification. The second read supplies an argument to F-069a1d444a2d. These values need not be equal.

These are structural descriptions of the supplied static evidence. The application meanings of the values, predicates, notifications, and threshold are unknown. Initialization, population, and finalization are inferred roles for the temporary-related calls, not established resource-management guarantees.

## Behavior

### 1. Obtain and retain the comparison value

The first operation is an indirect call through the complete object’s table entry at byte offset `0x17C`. The complete-object pointer is its explicit argument.

The signed 32-bit result is retained for the rest of this invocation. It is used by the interior-region predicate, the later threshold calculation, and the possible reference-field write.

No later call refreshes this value. Changes to object state during callbacks do not replace the retained result.

### 2. Prepare the temporary region

The function supplies a 24-byte automatic temporary region to F-ba5a4c1e0746 together with two zero arguments.

After that call returns, it resolves the complete object’s table entry at byte offset `0x15C` and invokes it with the object and temporary address.

The evidence establishes the storage size and argument flow, but not the temporary’s layout or contents. In particular:

- The two zero arguments do not prove that the 24 bytes become zero-filled.
- The first dependency is not proved to create an empty object.
- The subsequent indirect call is not proved to be a read-only query.
- Neither call establishes an ownership-transfer rule.

The population dispatch occurs after F-ba5a4c1e0746 returns. Earlier calls can therefore affect the dispatch state used at this site; no preservation guarantee is supplied.

### 3. Evaluate the first notification condition

F-a2c64bafa8a6 receives the temporary address. Only whether its integer result is zero or nonzero matters.

If it returns zero, the interior-region predicate and the first notification are skipped.

If it returns nonzero, F-a108b83869b3 receives:

- The object address advanced by `0x088` bytes.
- The signed value retained from the initial indirect call.

Only whether this second result is zero or nonzero matters. A zero result suppresses the first notification without suppressing the later threshold check.

When both results are nonzero, the function invokes the interior receiver’s table entry at byte offset `0x14`. The receiver is the object address advanced by `0x014` bytes. The other explicit argument is a four-byte value read from the first global notification source.

The first-source read occurs on this notification path, after the predicate calls. The evidence does not establish the relative evaluation order of that argument read and the dispatch-related reads within the same call expression.

There is no direct reference-field write in this branch. Called dependencies may nevertheless change the reference, dispatch state, globals, or other accessible state.

### 4. Read the reference and evaluate the threshold

After the first-check processing, including any first notification, the function reads the signed four-byte reference at object offset `0x990`.

It calculates the retained initial value minus this newly read reference. If that signed result is negative, it negates the result. The resulting signed value is compared strictly against 999.

For arithmetic that remains representable in signed 32 bits, this implements an absolute-difference test:

- Magnitudes from 0 through 999 do not qualify.
- A magnitude of 1000 qualifies.
- Larger representable magnitudes qualify.

The comparison does not use an entry-time snapshot of the reference. Earlier dependencies can change the field before this read and thereby change the threshold outcome.

#### Arithmetic boundary

The signed 32-bit range is −2,147,483,648 through 2,147,483,647.

Subtraction can exceed this range even when both operands are individually valid signed 32-bit values. Negation is also unrepresentable when the subtraction result is −2,147,483,648.

The supplied evidence does not establish an overflow policy. Consequently, the contract does not promise mathematical absolute-difference behavior for those cases. Wrapping, trapping, saturation, or portable language-level behavior must not be assumed.

### 5. Execute the qualifying threshold path

When the threshold comparison succeeds, the following sequence occurs:

1. F-74a693cd8577 receives the complete-object pointer.
2. After it returns, the function reads the second global notification source and retains that four-byte value for the later notification.
3. The function separately reads the same global source again, supplying this second value to F-069a1d444a2d together with the complete-object pointer.
4. After F-069a1d444a2d returns, the function invokes the interior receiver’s table entry at byte offset `0x14`, passing the interior pointer, the value retained from the **first** read, and an explicit zero.
5. After that notification returns, the function writes the initially retained signed value to the reference field at object offset `0x990`.

The two source reads are distinct in the supplied body. No intervening dependency call is shown between them, but source stability is not established. Their values are equal only if the source yields the same value at both reads.

F-74a693cd8577 can affect both reads because both occur after it returns. A change during F-069a1d444a2d cannot replace the notification payload: that payload was retained before the call. Such a change also cannot retroactively alter the argument already supplied to that dependency.

The second notification’s target is resolved after F-069a1d444a2d returns. Changes to the interior receiver’s dispatch state during that dependency can affect the selected target.

The reference write follows the notification. If intervening dependencies changed the reference, this direct write replaces that value with the result retained from the initial call. The function does not recompute the comparison or obtain another initial value before writing.

### 6. Pass the temporary to the final dependency

After either threshold outcome, F-4e292a3dd745 receives the temporary address. The function then returns.

On the qualifying path, this call occurs after the reference write. The direct store therefore does not guarantee the reference’s final value at function return: the final dependency may have independent access to the object or globals.

The body shows no explicit recovery or exceptional-cleanup mechanism. This final call is established for ordinary control flow that reaches it, not for faults, nonreturning calls, or exceptional transfers that bypass it.
