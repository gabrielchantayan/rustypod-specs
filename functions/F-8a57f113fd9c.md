# F-8a57f113fd9c

## Purpose

F-8a57f113fd9c conditionally delivers an input value through two independently configured callback paths associated with a state object.

The first path obtains a derived value, passes it to a callback, and then passes that same value to a post-callback dependency. The second path obtains a working handle, supplies the input to it, evaluates it under a global-dependent mode, conditionally invokes another callback, and then passes the working handle to a final dependency.

The paths are ordered, not interchangeable. Failure to obtain a nonzero value in the first enabled path terminates the entire operation and prevents the second path from being considered.

These are established control-flow properties. Descriptions such as “derived value,” “working handle,” and “mode” are neutral labels, not claims about the underlying data type or application purpose.

## Interface

### Inputs

The function takes three arguments:

| Argument | Observed representation | Role |
|---|---|---|
| State address | 32-bit address-bearing value | Base address used to read callback fields, callback context, and nested metadata. |
| Input value | Opaque 32-bit value | Forwarded unchanged to dependencies. It may represent an address, but this function does not directly dereference it. |
| Extent | Signed 32-bit integer | Forwarded as an extent-like argument. Any negative initial value requests replacement through F-1cb585febd84. |

The function has no explicit return value.

### Observed state layout

Offsets are byte offsets from the state address. Only the listed fields are established; the complete object layout is unknown.

| Offset | Observed width | Use |
|---|---:|---|
| `0x08` | 32 bits | Address of an intermediate metadata object. |
| `0xBC` | 32 bits | First callback address; zero disables that path at its initial check. |
| `0xC0` | 32 bits | Second callback address; zero disables that path at its check. |
| `0xC4` | 32 bits | Opaque context passed to either callback. |

The metadata argument supplied to either callback is obtained through this chain:

1. Read the 32-bit address at state offset `0x08`.
2. Read the 32-bit address at offset `0x14` within that intermediate object.
3. Read one byte at offset `0x59` within the resulting object.

The established payload width of this metadata is eight bits. Its meaning, signed interpretation, and machine-level argument extension are not established.

### Callback interfaces

The first callback receives, in order:

1. The 32-bit context from state offset `0xC4`.
2. The state address.
3. The metadata byte.
4. The nonzero 32-bit result obtained from F-7129d6a8d912.

The second callback receives, in order:

1. The 32-bit context from state offset `0xC4`.
2. The state address.
3. The metadata byte.

No callback return value is consumed.

### Preconditions

For each path actually reached:

- Required state fields and nested metadata must be readable.
- A callback address used for invocation must identify a callable target with a compatible calling convention.
- Arguments supplied to each dependency must satisfy that dependency’s requirements.
- State and metadata needed after a dependency or callback must remain valid until their later reads occur.

The function does not check these conditions comprehensively. In particular, it does not validate the state address, either nested metadata address, callback signatures, or the input value.

## Behavior

### Extent resolution precedes callback checks

The function first examines the signed 32-bit extent.

- If the initial extent is nonnegative, it is retained unchanged.
- If the initial extent is negative, F-1cb585febd84 is called with the input value. Its result replaces the extent used in subsequent dependency calls.

All negative initial values take this same branch; the behavior is not restricted to a particular negative sentinel.

There is exactly one resolution attempt. The replacement is not checked for negativity or any other range condition. A replacement that is still negative is forwarded onward as the effective extent.

Resolution occurs even if both callback fields subsequently read as zero. Consequently, disabling both callbacks does not necessarily make the invocation dependency-free.

### First callback path

After extent resolution, the function reads the first callback field at state offset `0xBC`.

If that field is zero, the first path is skipped and processing proceeds to the second callback check.

If it is nonzero:

1. F-7129d6a8d912 is called with the state address, input value, and effective extent, in that order.
2. Its 32-bit result is compared with zero.
3. If the result is zero, the function returns immediately. Neither first-callback invocation nor F-94cb53877c15 occurs, and the second callback field is not checked.
4. If the result is nonzero, the first callback is invoked with the four arguments specified in the interface.
5. After that callback returns normally, F-94cb53877c15 is called with the same result value originally obtained from F-7129d6a8d912.
6. After that dependency returns normally, processing proceeds to the second callback check.

The initial nonzero test does not establish that the callback address is preserved across F-7129d6a8d912. The callback invocation uses the state’s callback field again. Likewise, the context and metadata used for invocation are read after F-7129d6a8d912 returns; they are not established snapshots from function entry.

The source does not specify a relative evaluation order among the callback target expression and its argument expressions. It establishes that they are evaluated for the invocation after the preceding dependency returns, not a particular order among those reads.

### Second callback path

The second callback field at state offset `0xC0` is checked only after the first path has been skipped or completed without its early return.

If the field is zero, the function finishes without entering this path.

If the field is nonzero:

1. F-57e7ed96facd is called with the state address.
2. Its opaque 32-bit result is retained as the working handle.
3. F-df71e640897e is called with five arguments, in this order:
   - The working handle.
   - The effective extent.
   - The input value.
   - The constant `1`.
   - The constant `0`.
4. After that call returns, the function reads a byte through the supplied global reference.
5. A zero byte selects mode `3`; any nonzero byte selects mode `2`.
6. F-21f3f42d1b03 is called with the working handle and selected mode.
7. If its result is nonzero, the second callback is invoked with the three arguments specified in the interface.
8. Whether that result is zero or nonzero, F-c70de8d2b40e is called with the working handle after the intervening operations return normally.

There is no explicit zero check on the working handle before it is supplied to the later dependencies.

The global byte is read after F-df71e640897e returns. Its value at function entry does not determine the selected mode if an earlier call changes it.

The second callback’s address, context, and metadata are evaluated for the callback invocation after F-21f3f42d1b03 returns. They are not captured by the initial second-path enable check. No second null check is shown before invocation.

### Interaction between paths

The second path is governed by state as observed after all completed first-path calls. Therefore, effects of F-7129d6a8d912, the first callback, or F-94cb53877c15 can affect whether and how the second path runs.

In particular:

- The first path can enable or disable the second path by changing its callback field.
- It can change the context or metadata subsequently passed to the second callback.
- It can affect the global byte later used to choose the mode.
- A zero result from F-7129d6a8d912 suppresses the second path altogether, regardless of its callback field.

These consequences follow from the order of accesses. They do not assert that any dependency actually makes such changes.

## Side effects

No direct assignment to state fields, nested metadata, or the global byte is shown. Observable effects can nevertheless occur through dependencies and callbacks.

The established ordering constraints are:

- Optional extent resolution precedes both callback-field checks.
- First-path preparation precedes the first callback.
- The first callback precedes F-94cb53877c15.
- Completed first-path processing precedes the second callback-field check.
- Working-handle acquisition precedes input submission.
- Input submission precedes the global-byte read.
- The global-byte read and mode selection precede F-21f3f42d1b03.
- F-21f3f42d1b03 precedes any second-callback invocation.
- Any second-callback invocation precedes F-c70de8d2b40e.

### Ownership and lifetime

The function passes the first path’s nonzero result to both the first callback and F-94cb53877c15. It passes the second path’s working handle to several dependencies and finally to F-c70de8d2b40e.

This does not establish ownership transfer, borrowing rules, allocation, reference counting, or destruction. In particular:

- F-94cb53877c15 is not established to free the first result.
- F-c70de8d2b40e is not established to release the working handle.
- Either callback’s right to retain its arguments is unknown.
- Preservation of globals, state, input storage, and metadata by dependencies is unknown.

The callback and dependency contracts must be compatible with the later operations shown here. No automatic recovery from an incompatible lifetime change is present.

### Errors and abnormal completion

There is no explicit error status returned to the caller.

The function treats:

- A zero first-path preparation result as an immediate-return condition.
- A zero second-path evaluation result as a reason to omit only the second callback.

Other failure semantics are not established. No handler or guaranteed-finalization mechanism is shown for a dependency or callback that fails to return normally. The post-callback dependencies are therefore guaranteed by the shown control flow only on normal return from the preceding operations.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes valid memory, compatible callees, and normal returns unless otherwise stated.

### Both paths disabled

Given a nonnegative extent and both callback fields zero when checked:

- No listed dependency is called.
- Neither callback is invoked.
- The function returns without an explicit result.

With a negative initial extent instead, F-1cb585febd84 is called first, even if both callback fields remain zero afterward.

### First-path preparation returns zero

Given a nonzero first callback field and a zero result from F-7129d6a8d912:

- The first callback is not invoked.
- F-94cb53877c15 is not called.
- The second callback field is not checked.
- The function returns.

This remains true if the second path would otherwise be enabled.

### First path completes

Given an effective extent of zero, a nonzero first callback field, and a nonzero preparation result:

- Zero is forwarded unchanged as the extent.
- The first callback receives the preparation result as its fourth argument.
- F-94cb53877c15 receives that same result after the callback returns.
- The second path is then considered using the state visible at that time.

There is no special zero-extent bypass.

### Second path omits its callback

Given a disabled first path, an enabled second path, and a zero result from F-21f3f42d1b03:

- The working handle is obtained and supplied to F-df71e640897e.
- A mode is selected from the subsequently read global byte.
- The second callback is omitted.
- F-c70de8d2b40e still receives the working handle.

### Mode selection observes a late change

If F-df71e640897e changes the global byte from zero to nonzero before returning, and no other change intervenes, mode `2` is passed to F-21f3f42d1b03. Conversely, a zero byte when read selects mode `3`.

### Negative replacement extent

Given a negative initial extent and a negative replacement from F-1cb585febd84, the replacement is forwarded to any reached extent-consuming dependency. No second resolution, clamp, or rejection occurs.

### First path changes second-path availability

If the first callback returns after setting the second callback field to zero, and F-94cb53877c15 leaves that field zero, the second path is skipped. If the field instead becomes nonzero and remains so until its check, the second path is entered.
