# F-99df93d78ce1

## Purpose

F-99df93d78ce1 processes one input line against mutable record-loading state. Established behavior includes prefix dispatch, capacity declaration, record insertion, encoding tracking, metric updates, bitmap allocation and decoding, and glyph/font termination.

A line-oriented bitmap-font parser is the inferred purpose. This interpretation does not establish unavailable dependency semantics, table contents, or ownership rules.

This contract is based on static evidence only. No runtime tests have been performed. Unresolved behavior remains documented_only.

## Interface

### Inputs and result

The five inputs are:

1. A 32-bit input address.
2. A signed 32-bit input length.
3. A 32-bit value passed to some diagnostics as a line identifier.
4. An additional 32-bit value without subsequent use in the supplied body.
5. An address of mutable parser state.

The result is a 32-bit status:

| Status | Established local meaning |
|---|---|
| 0 | Normal local completion, ignored content, or handled condition |
| 3 | Unrecognized non-bitmap input, or converted encoding above 65535 unsigned |
| 179 | Required declaration prefix absent |
| 180 | Encoding line without glyph-start flag |
| 181 | Scalable-width line without encoding flag |
| 182 | Bitmap start without bounding-box flag |
| 183 | Computed bitmap allocation size above 65535 unsigned |
| Other | Propagated comment, tokenization, or allocation status |

Zero does not establish complete, valid, or retained glyph data.

## Behavior

### Ordering, snapshots, and record selection

Before the first comparison, the function captures the font address from parser offset 32, then captures that font’s memory-management context. Most font operations continue using this captured font.

Exceptions reload the parser’s font address:

- Comment processing receives the reloaded font.
- Bitmap-start stride calculation obtains its factor through the reloaded font.
- Row masking obtains its factor through the reloaded font.

Dependencies may change shared state. Allocation context, record storage, and bitmap factor can consequently refer to different font objects.

Immediately after the encoding-prefix comparison, the global conversion-table pointer is read, **before the comparison result is tested**. This read occurs on matching encoding lines and on paths subsequently handling metrics or bitmap rows.

If encoding does not match, record selection occurs before checking bitmap mode or comparing metric prefixes:

- Current encoding exactly **0xffffffff** selects the captured font’s secondary array and count.
- Every other value selects its primary array and count, including other signed-negative encodings.
- The selected address is array address plus 36 times the 32-bit count-minus-one, with 32-bit address arithmetic.

This address remains fixed through later comparisons, tokenization, conversions, diagnostics, width calculations, and allocation. Changes to arrays, counts, or current encoding do not retarget it.

Later field reads are not generally snapshots. Flag updates normally incorporate flags present after preceding calls.

### Dispatch and flags

Comments have first priority, followed by the declaration gate. Once declaration flag 32 is set, dispatch order is:

1. `ENDFONT`.
2. `ENDCHAR`.
3. Suppression of discarded-glyph content.
4. `STARTCHAR`.
5. `ENCODING`, followed by the conversion-table pointer read.
6. Bitmap-row handling if bitmap mode is active.
7. Metric and bitmap-start recognition.

F-7f14f1ab6851 performs fixed-length comparisons; zero selects a match. No local delimiter or end-of-line requirement follows a prefix.

### Comments and declaration

A seven-byte `COMMENT` match selects input offset seven. If that byte is nonzero, one additional byte is skipped regardless of whitespace. The length is reduced by seven or eight, without rejecting negative results. F-4b1fb2933e65 receives the reloaded font, suffix address, and adjusted length; its result is returned directly.

Without flag 32, other input must match `CHARS` over five bytes. Failure diagnoses and returns 179.

A matching declaration is tokenized. On success, the first argument is converted in base 10. Its 32-bit result is stored in captured-font primary capacity and parser declared count. Zero leaves declared count zero but replaces capacity with 64.

Allocation requests that capacity in 36-byte units. The returned address is installed before status inspection. Only success sets flag 32; earlier writes are not rolled back.

### Terminators and glyph start

A seven-byte `ENDFONT` match calls F-4d426a8054f4 with the captured font’s current primary array, count, record size 36, and an unavailable callback-like value. Its result is not propagated. Flag 1 is then cleared. No secondary-array processing or completeness check is visible.

A seven-byte `ENDCHAR` match resets current encoding to zero and clears flags 64 through 2048 inclusive. It leaves other flags unchanged and does not check row completion.

After these checks, content is suppressed when flag 64 is set, current encoding is exactly 0xffffffff, and secondary retention is zero. This also suppresses a new `STARTCHAR`; comments and terminators retain priority.

A nine-byte `STARTCHAR` match:

- Passes the captured context and pending address to F-bf7242c98d06, then clears the pending address.
- Tokenizes, returning on failure.
- Applies F-d8cb7bd4f85b to token state with argument 1.
- Obtains a value and length through F-b5b46a5f106f with delimiter 32.
- Requests length plus one bytes, installing the returned address before checking status.
- On success, invokes an unidentified external dependency with that address, extracted value, and length plus one, then sets flag 64.

The unidentified dependency is not established to copy bytes or write a terminator. Its result is ignored. Glyph start does not clear stale metric or bitmap flags.

### Encoding and insertion

An eight-byte `ENCODING` match requires flag 64; otherwise it diagnoses and returns 180. The conversion-table pointer has already been read.

After tokenization, F-3f754031ddf9 converts the first argument in base 10. The result is stored as current encoding before unsigned comparison with 65535. Larger values return 3.

Thus all 32-bit negative representations are stored and rejected, including 0xffffffff. The following signed-negative branch does not establish accepted direct negative encodings. Rejected values can affect later calls if the caller continues.

For an accepted encoding, the presence word is at parser offset 40 plus four times encoding divided by 32; the bit is encoding modulo 32. A clear bit is set. An existing bit optionally diagnoses, replaces current encoding with 0xffffffff, and sets the captured font’s modification indicator to 1.

Insertion then uses the **signed sign test**, distinct from later exact-sentinel record selection:

- Nonnegative current encoding uses the primary array. Equality of count and capacity triggers growth by 64 records. The returned address is installed before status checking; capacity increases only after success. Count increments before the record’s pending address and current encoding are written.
- Negative current encoding uses the secondary path. With retention disabled, F-bf7242c98d06 receives the pending address, which is then cleared. With retention enabled, equality of count and capacity triggers growth by four. The returned address is installed before status checking. The record receives the pending address and previous secondary count as its index; count then increments.

Successful completion clears the pending address and both high warning flags, then sets flag 128. These writes establish movement of an address reference, not ownership transfer guarantees.

### Metrics and correction bookkeeping

These branches use the previously selected record address.

`SWIDTH`, compared over six bytes, requires flag 128. Failure diagnoses and returns 181. Successful tokenization and conversion store the first argument’s low 16 bits as scalable width and set flag 256.

`DWIDTH`, six bytes, has no encoding prerequisite. It stores the converted first argument’s low 16 bits as device width. If flag 256 is absent, an optional diagnostic precedes F-8f41f510c86c. Arguments include stored device-width bits, an unavailable constant, and the 32-bit product of captured-font fields 20 and 16. The result’s low 16 bits become scalable width. Flag 512 is set.

The bounding-box prefix is an unavailable three-byte literal; `BBX` is inferred. Four conversions successively store width, height, horizontal offset, and vertical offset, truncated to 16 bits.

Derived values retain 16 bits:

- Ascent: unsigned stored height plus the full converted vertical offset.
- Descent: negation of truncated vertical offset.
- Horizontal extent: unsigned stored width plus unsigned horizontal-offset bit pattern.

Signed 16-bit comparisons update maximum ascent, descent, and extent, and minimum/maximum horizontal offset. Latest extent is overwritten independently. These updates precede width synthesis and correction.

Without flag 512, device width becomes stored bitmap width after an optional diagnostic. Nonzero options offset 0 enables scalable-width recomputation. A differing 16-bit result is stored before correction bookkeeping.

Correction bookkeeping uses **current encoding exactly equal to 0xffffffff**, not a general negative test:

- Otherwise, read the selected record’s 32-bit encoding. Interpret it as signed for an **arithmetic right shift by five** to obtain the primary word index.
- For the exact sentinel, subtract one from the captured font’s current secondary count in 32-bit arithmetic. Treat the result as unsigned and **logically right shift by five** for the secondary word index.
- In either case, the bit position is the low five bits of the corresponding encoding/index value.
- The word address is captured font plus 132 plus four times word index; the secondary case additionally adds 8192. Address arithmetic is 32-bit.
- The chosen word is read and OR-written with the selected bit.

A negative primary record encoding can therefore address before the primary bitmap. A zero secondary count wraps to 0xffffffff before its logical shift; it does not simply select the preceding word.

Current encoding chooses correction bookkeeping, whereas the earlier snapshot chooses the metric target. Dependency mutations can make these disagree. Correction sets flag 4096 and modification indicator 1. Bounding-box completion sets flag 1024.

### Bitmap start and rows

`BITMAP`, six bytes, requires flag 1024; failure diagnoses and returns 182.

Stride uses unsigned 16-bit width and the factor from the reloaded font. Their 32-bit product plus seven is interpreted signed and arithmetically shifted right three. It is not universally a nonnegative mathematical ceiling division.

Stride is stored before validation. Total size is unsigned stored height times stride, retaining 32 bits. Unsigned totals above 65535 diagnose and return 183. Otherwise the low 16 bits are stored as allocation size. Allocation uses the captured context; its returned bitmap address is installed before status checking. Success resets row index and sets flag 2048.

In bitmap mode, input reaching this stage is row data, not a metric command. If unsigned row index is below unsigned stored height:

- Destination starts at bitmap address plus the 32-bit stride–row-index product.
- The number of input bytes is twice stride, retaining 32 bits.
- Each iteration performs an unsigned destination-byte read before the update expression.
- Input bytes are read unsigned and select entries through the captured conversion-table pointer.
- Each table entry is read as **plain char**, then promoted for arithmetic. The supplied evidence does not establish whether plain char is signed on the target.
- The destination update adds the promoted entry to 16 times the current unsigned destination byte, then truncates to eight bits.
- After each completed pair except the final pair, destination advances and the next byte is explicitly zeroed.

No additional evaluation order among reads within the update expression is established.

For fixed promoted lookup results, two completed updates eliminate the initial destination byte’s direct accumulator contribution modulo 256. This does **not** prove independence if destination writes affect subsequent input or table reads through aliasing.

If stored width is nonzero, the mask-table pointer is loaded, the current destination byte is read, and that byte is AND-written with the mask indexed by the low three bits of width times a freshly loaded bitmap factor.

Masking also occurs for zero stride: decoding executes zero iterations, but nonzero width still causes a read-modify-write at the row address.

Trailing classification examines input at offset twice stride. ASCII `0` qualifies explicitly; otherwise a nonzero plain-char table entry qualifies. The first qualifying excess-column condition optionally diagnoses, sets flag 0x40000000, and sets modification indicator 1. Row index then increments using its then-current value.

When row index is already at least height, decoding, masking, and trailing classification are skipped. The first excess row optionally diagnoses and sets flag 0x80000000 and modification indicator 1. Row index does not increment.

## Acceptance examples

Conditional static cases only; dependencies succeed and do not mutate unrelated state unless specified.

1. **Zero declaration:** Conversion to zero leaves declared count zero, sets capacity 64, and requests 64 records. Flag 32 is set only after allocation succeeds.

2. **Font replacement:** If the initial comparison replaces parser font A with B and reports a comment match, comment processing receives B; the previously captured context came from A.

3. **Rejected negative, subsequent selection:** Conversion to 0xfffffffe stores that value and returns 3. A later metric path selects the primary array, not secondary, provided state remains otherwise suitable. Exactly 0xffffffff selects secondary.

4. **Primary correction:** With non-sentinel current encoding and selected-record encoding 0xfffffffe, arithmetic shifting produces word index −1. Correction ORs bit 30 at captured-font offset 128, not in secondary bookkeeping.

5. **Secondary correction underflow:** With sentinel current encoding and secondary count zero, the index value wraps to 0xffffffff. Its logical word index is 0x07ffffff; correction targets captured font plus 0x20002080, modulo 32-bit addressing, and selects bit 31.

6. **Plain-char distinction:** A table byte 0xff promotes to −1 if plain char is signed, or 255 if unsigned. With destination byte zero, either truncates to 255 after this single update; the promoted arithmetic value is nevertheless different and is not established by the supplied target evidence.

7. **Fixed-result pair:** If successive promoted lookup results remain 10 and 11, a completed pair yields 171 before masking, regardless of the initial destination byte. This assumes those results remain fixed despite destination writes; overlapping input or table storage can invalidate that premise.

8. **Zero stride:** Width 1, height 1, factor zero, and successful zero-size allocation returning accessible storage produce no decoding iterations. The row still masks that storage byte, classifies input offset zero, and increments row index.

9. **Size boundary:** Computed unsigned total 65535 reaches allocation; 65536 returns 183 after stride storage and before allocation.

10. **Premature termination:** `ENDCHAR` resets encoding and clears glyph-progress flags even if expected rows are missing.
