# F-599631f2aae1

## Purpose

F-599631f2aae1 converts one unsigned 32-bit input value into a variable-length sequence of one through six bytes. With a non-null destination, it writes the sequence when the supplied capacity is sufficient. With a null destination, it reports the required sequence length without writing memory and without consulting the supplied capacity.

The byte format resembles historical UTF-8, including five- and six-byte forms. It is **not a strict modern UTF-8 encoder**: the established behavior includes surrogate values, values above U+10FFFF, and six-byte encodings. In the six-byte form, input bit 31 is discarded, so the mapping is not one-to-one across the full unsigned 32-bit input domain.

These conclusions follow from static inspection of the supplied function body. No runtime tests have been performed.

## Behavior

### Capacity handling and sequence selection

A null destination selects length-query behavior. In this case, the function uses an effective capacity of six bytes regardless of the supplied capacity, including zero or negative capacities.

For a non-null destination:

- Capacity less than one causes an immediate failure return.
- Otherwise, the value determines a required length.
- If capacity is smaller than that required length, the function returns failure without writing any destination bytes.
- If capacity is sufficient, the function writes exactly the selected sequence and returns its length.

The required length is determined by unsigned comparisons:

| Value range, inclusive | Required bytes |
|---|---:|
| 0x00000000–0x0000007F | 1 |
| 0x00000080–0x000007FF | 2 |
| 0x00000800–0x0000FFFF | 3 |
| 0x00010000–0x001FFFFF | 4 |
| 0x00200000–0x03FFFFFF | 5 |
| 0x04000000–0xFFFFFFFF | 6 |

Capacity does not alter sequence selection. In particular, the function does not substitute a longer representation when capacity is too small, emit a prefix, or return a required length on capacity failure.

There is no rejection based on Unicode scalar-value rules or a maximum representable value below 0xFFFFFFFF.

### Byte layout

Let input bits be numbered 0 through 31, with bit 0 least significant. In the descriptions below, a selected bit group retains its internal order and is placed in the low bits of the output byte. Each fixed prefix occupies the remaining high bits.

| Length | Output bytes, in increasing destination offset |

Thus, every non-leading byte lies between 0x80 and 0xBF inclusive. Leading-byte ranges are 0x00–0x7F, 0xC2–0xDF, 0xE0–0xEF, 0xF0–0xF7, 0xF8–0xFB, and 0xFC–0xFD for the respective selected lengths.

The two-byte range starts at 0xC2 because the selection threshold excludes values below 0x80 from that form.

### Integer-width consequences

The supplied representation performs the relevant shifts on unsigned 32-bit values. Left shifts therefore retain only the low 32 bits before subsequent right shifts.

This matters especially for six-byte output:

- The first byte contains input bit 30, not bit 31.
- The remaining bytes contain input bits 0 through 29.
- Input bit 31 affects selection of the six-byte branch but is absent from its payload.

For inputs already in the six-byte range, two values differing only in bit 31 produce identical output. For example, 0x04000000 and 0x84000000 both produce FC 84 80 80 80 80.

Length selection nevertheless uses the full unsigned input. Consequently, clearing bit 31 can change the selected length. For example, 0x80000000 produces six bytes, while zero produces one byte; they are not identical complete encodings despite having the same low 31 bits.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed test results. Hexadecimal output lists bytes in increasing destination offset.

### Query behavior

- With a null destination, value 0x7F returns 1 even if capacity is negative.
- With a null destination, value 0x800 returns 3 even if capacity is zero.
- With a null destination, value 0xFFFFFFFF returns 6 regardless of capacity.
- Each query performs no destination access.

### Capacity boundaries and unchanged storage

Given valid destination storage initialized to distinguishable sentinel bytes:

- Value 0x7F with capacity zero returns 0xFFFFFFFF and leaves the storage unchanged.
- Value 0x80 with capacity one returns 0xFFFFFFFF and leaves the storage unchanged.
- Value 0x80 with capacity two writes C2 80 and returns 2.
- Value 0x4000000 with capacity five returns 0xFFFFFFFF and leaves the storage unchanged.
- Value 0x4000000 with capacity six writes FC 84 80 80 80 80 and returns 6.
- Any non-null destination with negative capacity returns 0xFFFFFFFF without writing, including when the value is zero.
- Extra capacity does not cause extra writes. With value 0x41 and capacity six, only the first byte becomes 41.
