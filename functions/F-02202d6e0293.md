# F-02202d6e0293

## Purpose

F-02202d6e0293 conditionally transfers one 16-bit memory value, evaluates entry-state-dependent conditions, and enters a repeating sequence of two indirect calls followed by software interrupt `0x5B`.

No application-level purpose is established. The supplied representation does not support identifying this operation as a parser, allocator, device driver, or ordinary callable service.

The principal behavioral distinction is between:

- An initial transfer enabled when the low eight bits of an entry-state word are zero.
- A much narrower memory-modifying path that requires a numerically zero stack anchor and zero entry link address under the 32-bit interpretation described below.
- The repeating call-and-interrupt sequence, reached without the later conditional stores shown in the supplied representation.

The function has no explicit result and no represented normal-return path.

## Behavior

### Initial transfer

The low eight bits of the control word select whether the initial memory transfer occurs.

If those bits are nonzero, the function performs no initial data-memory read or write.

If those bits are zero, the function:

- Reads one unsigned 16-bit value from the entry source address.
- Writes that value to the address formed by adding the displacement word to the source address, with 32-bit wraparound.

The read precedes the write. The destination calculation uses bytes, not 16-bit elements.

A revised working source address is also formed as:

**source address + displacement word − adjustment word**, modulo \(2^{32}\).

This revised address participates in later conditions. Forming it does not itself read memory.

The transfer is not a range copy. It is one halfword read and one halfword write. Source and destination may coincide. If they coincide, the represented behavior still includes a read followed by a write of the value read.

A fault during this transfer can prevent all subsequent behavior. No rollback or local recovery is represented.

### Reduction of the conditional paths

The supplied representation contains several long chains of conditions. They should not be interpreted as independently selectable features.

Under the stated 32-bit model, multiplication of the control word by \(2^{24}\) produces zero exactly when the control word’s low eight bits are zero. On that path:

- The control word’s bit `0x40` is necessarily clear.
- Multiplication by \(2^{25}\) also produces zero.
- Every variable shift reached through the subsequent zero-result chain has a zero shift count.
- The carry state entering the auxiliary-word addition is false.

These constraints sharply reduce the reachable behavior.

The narrow memory-modifying path is reached only when all of the following hold:

1. The control word’s low eight bits are zero.
2. The entry link address is zero.
3. The stack anchor is zero.
4. The comparison word equals the displacement word.
5. The adjustment word equals the revised working source address.
6. The auxiliary word is zero.
7. Twice the displacement word is zero modulo \(2^{32}\).

The last condition permits only displacement `0x00000000` or `0x80000000`.

These are arithmetic reachability conditions, not a claim that such an execution environment is valid or conventional. In particular, the zero stack anchor and zero link address are unusual requirements.

If these conditions do not all hold, the narrow memory-modifying operation does not occur, and the address basis used for the first call remains the entry link address.

### Narrow memory-modifying operation

When the preceding conditions hold, the function performs a halfword operation through the zero link address.

Two 16-bit reads from that link address contribute independently:

- One supplies a zero-extended destination address.
- One supplies a value to which `0x000F` is added.

The resulting value is written as 16 bits to the selected destination.

The supplied representation does not establish which of the two reads occurs first. Both precede the resulting store. If reads have device side effects or another agent changes memory, the two observed values need not agree.

For ordinary stable memory, if the halfword at address zero is \(h\), this operation writes:

- Destination: the 32-bit zero extension of \(h\).
- Value: \((h + 15) \bmod 2^{16}\).

The link-derived address basis remains zero on this path. An additional represented machine-state field is assigned zero. The architectural meaning of that field is not established.

This operation follows the initial transfer. Consequently, the initial write can change the value subsequently read at address zero if the addresses alias.

### Later conditional stores are unreachable under this model

After the narrow operation, the next conditional sequence cannot progress to its later subtraction and store stages:

- Progress first requires a derived address to be zero.
- The following required comparison instead produces the numeric value two, because a pointer to a 16-bit item has been advanced by one item.

Without the narrow operation, that sequence is not enabled at all.

Therefore, under the stated arithmetic interpretation, the later represented pointer-pair stores and final signed-halfword-derived stores are not observable behavior of this function. They do not create additional reachable memory requirements.

This is a static reachability conclusion, not a runtime observation.

### Repeating call-and-interrupt sequence

After the conditional processing, the function enters a loop with no represented exit.

The first iteration uses a call address equal to:

**entry link address + `0x00000EB6`**, modulo \(2^{32}\).

The offset is `0xEB6`, not `0x75B` bytes: the represented addition advances a pointer measured in 16-bit elements.

The first call receives three explicit 32-bit argument values, in order:

1. `0x00000000`
2. `0x00000000`
3. `0xFFFFFFA5`

The third value has signed 32-bit interpretation −91. The callee’s actual parameter types are unknown.

If that call returns, a second indirect call is made at numeric address `0x0857A94B`. No explicit arguments are represented for this second call.

If the second call returns, the function invokes software interrupt `0x5B`.

If execution resumes after the interrupt, the loop changes its address basis to `0x083D4CC2`. Every subsequent iteration therefore uses first-call target `0x083D5B78`, followed by the same second call and interrupt.

The function does not inspect an explicit return value from either call.

The infinite-loop structure does not guarantee endless execution: a memory fault, invalid instruction target, nonreturning callee, or interrupt handler can prevent continuation.

## Acceptance examples

These are conditional static acceptance examples. No runtime tests have been performed.

### Low control byte is nonzero

Given a control word with low byte `0x01`, a valid link-derived first-call target, and returning dependencies:

- No direct data-memory transfer occurs before the calls.
- The first target is the entry link address plus `0xEB6`.
- The explicit arguments are zero, zero, and `0xFFFFFFA5`.
- The fixed second call and interrupt follow in that order.
- After interrupt resumption, the next first-call target is `0x083D5B78`.

### Ordinary initial transfer

Given a zero low control byte, source address `0x00001000`, displacement `6`, and a source halfword of `0x1234`:

- The function reads 16 bits at `0x00001000`.
- It writes `0x1234` at `0x00001006`.
- With a nonzero link address, the narrow operation is not reached.
- The call sequence follows if all required execution targets are valid.

The destination is not `0x0000100C`; the displacement is in bytes.

### Self-overlapping initial transfer

Given a zero low control byte and zero displacement:

- The source and destination addresses coincide.
- A halfword read precedes a halfword write to that same address.
- Device-backed memory may therefore observe both accesses even if the stored numeric value is unchanged.

### Narrow-path wraparound

Assume an environment where address zero is accessible, all narrow-path conditions hold, and the initial transfer does not change the halfword at address zero.

If that halfword is `0xFFF8`:

- The destination selected by the narrow operation is `0x0000FFF8`.
- The written halfword is `0x0007`.
- The later represented pointer-pair and signed-halfword stores remain unreachable.
- The first call target is `0x00000EB6`.

### Nonreturning dependency

If the first indirect callee does not return, neither the second call nor the interrupt is reached for that iteration. The loop does not impose a separate recovery mechanism.
