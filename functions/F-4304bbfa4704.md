# F-4304bbfa4704

## Purpose

F-4304bbfa4704 clears two fields in a caller-supplied object, conditionally performs setup, constructs a temporary descriptor, and conditionally invokes processing dependencies. On normal completion, it returns a 64-bit composition of three descriptor fields in their final state.

Setup ends with a 32-bit write whose destination and value depend on external expressions with omitted declarations. The destination width is established; the external operand read widths, address-addition scaling, and value conversion are not.

Processing is selected by three ordered conditions: a dependency result, an explicitly byte-sized object field, and a comparison of an externally addressed, dereferenced value against zero. The final condition’s target type and access width are unresolved. Its expression also does not establish a separate load from a pointer-storage object: an external array declaration could instead supply an address through array-to-pointer conversion.

“Setup,” “descriptor,” and “processing” describe structural roles. Their application-level meanings are inferred rather than established.

## Behavior

### Initial state changes

Before any dependency call, the function writes zero to object offset 0xB4, then writes zero to offset 0xB5, then reads offset 0xB9.

A zero value at 0xB9 selects setup. Any nonzero value skips it.

Both initial writes occur regardless of later gate outcomes. There is no explicit restoration. Dependencies may subsequently modify those fields, so their final contents are not guaranteed to remain zero.

### External setup assignment

After both handle-consuming setup calls return, the function performs a 32-bit destination write:

- The destination comes from adding 0xE0 to G-setup-base under the base expression’s omitted type, then using the result as a 32-bit destination address.
- The assigned value comes from G-setup-value.

The 32-bit destination access does not establish either external operand’s read width. Addition by 0xE0 is not established as a byte displacement: a pointer-typed base could impose element scaling. The stored representation depends on the omitted right-hand type and its applicable conversion.

Neither operand is visibly captured at function entry. Earlier dependencies may change relevant external state before this operation. The relative evaluation order of the destination-base and value expressions is not established.

There is no explicit invalid-address, overflow, conversion-error, or recovery path.

### Descriptor construction

After setup completes or is skipped, the function initializes descriptor fields in offset order: 0, 2, 4, 8, and 12.

Descriptor offset 0 shares storage with setup offset 48. Thus, descriptor construction replaces the earlier 16-bit zero there with the first argument’s low half. That setup zero is not a persistent descriptor flag.

The descriptor derives its address-related initial values from the original first argument. Changes to object memory during setup do not by themselves replace that argument.

### Ordered processing gate

After descriptor construction, F-3fac671648b8 is called with no explicit arguments.

Processing requires all three conditions to pass, in order:

1. F-3fac671648b8 returns a nonzero 32-bit result.
2. The subsequently read 8-bit object field at 0xA0 equals zero.
3. The value obtained by dereferencing G-gate-source compares unequal to zero.

Short-circuiting establishes the following direct evaluation behavior:

- A zero dependency result suppresses both subsequent condition evaluations.
- A nonzero object field at 0xA0 suppresses evaluation of the external dereference condition.
- If the first two conditions pass, the external dereference is evaluated. A result comparing equal to zero rejects processing; a result comparing unequal to zero selects it.

The final condition’s dereferenced type and access width are not supplied. Its zero comparison does not narrow the access to one byte.

Evaluation of G-gate-source is also declaration-dependent. A stored-pointer declaration can entail a pointer-object load; an array declaration can supply an address without such a load. Accordingly, this contract does not require a separate pointer-storage read followed by a target read.

No explicit target-validity check precedes the dereference. Earlier dependencies may affect the object field, a stored pointer if one exists, or the target contents. Gate rejection does not undo setup or the initial writes. Suppression here concerns this function’s direct condition evaluation, not accesses that dependencies might independently perform.

### Selected processing

When all gate conditions pass:

1. The signed 32-bit value at object offset 0x34 is read and retained.
2. F-e57b05520b65 receives the descriptor address and two copies of the first-argument-plus-0x80 address.
3. If the retained object-field value is nonzero, F-ee8733a08210 receives the descriptor address and that retained value plus 0xD0.
4. F-ffe0d92c57b7 receives the original first argument.
5. If its 32-bit result is nonzero, F-c9b5d17d8d1e receives that result and the descriptor address.
6. Under the same nonzero-result condition, F-4d037ecf0f82 receives the same retained result and descriptor address.

The object-field read occurs before F-e57b05520b65. A later mutation of that field does not replace the retained value or change whether the optional call is selected. Negative nonzero values also select that call, subject to valid arithmetic and dependency preconditions.

F-ffe0d92c57b7 is invoked once. Both final consumers use its retained result. The second consumer is not conditional on the first consumer’s return value.

The descriptor is not rebuilt between consumers. Mutations by earlier consumers may affect later consumers and the final return composition; actual mutations are unknown.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes valid reached accesses, valid relevant arithmetic, satisfied dependency preconditions, and normal dependency completion.

1. **Immediate gate rejection.**  
   If object offset 0xB9 is nonzero and F-3fac671648b8 returns zero, setup is skipped. Both initial zero writes occur. This function evaluates neither the object condition at 0xA0 nor the external dereference condition.

2. **Setup precedes later rejection.**  
   If offset 0xB9 is zero and the first gate result is later zero, the complete setup sequence still occurs, including the external 32-bit destination write.

3. **External setup values are not entry snapshots.**  
   If setup dependencies change the relevant external state and that state remains stable during operand evaluation, the assignment uses the resulting state. Its destination scaling and stored-value conversion remain declaration-dependent.

4. **Object rejection suppresses the external condition.**  
   If the first gate result is nonzero but offset 0xA0 contains a nonzero byte, the external dereference condition is not evaluated. An otherwise invalid external target is not directly accessed by this condition on that path.

5. **Reached external target compares equal to zero.**  
   If the first two conditions pass and the valid dereferenced value compares equal to zero, processing is skipped. This case requires storage appropriate for the unresolved target type, not merely one readable byte.

6. **Alternative external declarations.**  
   If G-gate-source is a pointer object, evaluating the reached condition may load that pointer and then access its target. If it is an array, address conversion can avoid a pointer-object load. Either declaration remains consistent with the supplied expression; neither establishes the target access width.

7. **Zero retained object field.**  
   With the complete gate satisfied and offset 0x34 read as zero, F-e57b05520b65 runs, F-ee8733a08210 is skipped, and F-ffe0d92c57b7 still runs.

8. **Mutation after retention.**  
   If offset 0x34 is read as nonzero and F-e57b05520b65 subsequently clears it, the optional dependency still receives the originally retained value plus 0xD0.

9. **One lookup controls both final consumers.**  
   A nonzero result from F-ffe0d92c57b7 selects both final consumers in order with the same retained value, regardless of the first consumer’s return value.

10. **Return follows descriptor state.**  
    If a consumer changes descriptor offset 4 and that field is not changed again, its final 32-bit value supplies return bits 32–63. If all return-contributing fields remain unchanged, the initial composition described in the interface is returned.
