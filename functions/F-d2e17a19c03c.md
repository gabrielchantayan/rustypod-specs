# F-d2e17a19c03c

## Purpose

The supplied static representation describes an indefinitely repeating routine that interleaves indirect calls with byte-sized and 32-bit memory accesses. It carries selected call results and memory-derived values forward into later addresses, stored values, and call arguments.

No application-level purpose is established. In particular, the evidence does not establish that the routine implements initialization, device control, object management, serialization, or a conventional dispatch loop. Those interpretations would require additional evidence.

The contract below distinguishes:

- **Established static evidence:** operations and ordering explicitly represented in the supplied material.
- **Conditional interpretation:** numerical consequences under a 32-bit machine-word model.
- **documented_only unknowns:** entry-state requirements, indirect dependency behavior, memory validity, and other properties not established by the material.

The visible body has no normal return and no explicit termination condition. Continued iteration requires every encountered call and memory access to complete.

## Behavior

Each iteration executes the same visible sequence of calls and memory operations, then starts another iteration without an explicit test.

The ordering below is the represented execution order, conditional on all preceding operations completing. It is not an atomic transaction. An indirect dependency may inspect or modify memory between any two listed accesses separated by calls.

### Entry calls and first update

Two indirect calls precede the first explicit memory write. The first target depends on the incoming control-address state; the second is formed from a fixed anchor in the supplied representation.

The routine then:

1. Writes \(S_2(P)\) as a 32-bit word at \(A+20\).
2. Reads the global word into \(G\).
3. Makes a call with \(Q\) as its visible argument.
4. Makes three further calls with no explicit arguments shown.
5. Obtains a 64-bit result from another call, defining \(X\) from its low word.

The next memory operation reads a byte at \(B+1\), zero-extends it, adds 17, and writes \(\operatorname{byte}(G \mathbin{\gg}22)\) at that resulting address.

This is byte-derived addressing, not a pointer-sized load. The resulting byte-store address is between 17 and 272 inclusive.

The high word of the paired result is passed to a dependency. A subsequent call supplies a word that is passed to another dependency together with \(S_{28}(X)\). After three more calls, another dependency result is obtained.

The routine then:

- Re-reads the byte at \(B+1\).
- Writes zero at the newly calculated byte-derived address.
- Passes four times the latest result to a dependency.

The re-read matters: intervening dependencies may have changed the selector byte.

### First paired word update

A later result is passed, scaled by four, in both visible argument positions of a call. Following another call sequence, a result defines \(Y\).

The next operations are:

| Order | Memory effect or visible argument |
|---|---|
| 1 | Store \(Y\) as a word at \(4096X+20\). |
| 2 | Call a dependency with \(S_{14}(X)\). |
| 3 | Obtain another dependency result, here called the first index. |
| 4 | Store the same captured \(Y\) at four times that index, plus 20. |
| 5 | Call a dependency with four times that index. |

The second store is not a reload or a copy from the first destination. It uses the retained value \(Y\). The destinations may alias.

### Second paired result and byte clearing

Another 64-bit dependency result defines \(Z\). Before forwarding that result’s high word, the routine:

- Reads a byte at \(16384X+1\).
- Uses that byte, zero-extended and increased by 17, as a write address.
- Stores \(\operatorname{byte}((Y \mathbin{\&} 0x3fffffff)\mathbin{\gg}20)\).

A later single-word result is passed onward. Another 64-bit result is then obtained and forwarded as two separate 32-bit arguments, low half first and high half second.

Following further calls, a result is obtained and the routine:

1. Reads a byte at \(S_{28}(Z)+1\).
2. Writes zero at the byte-derived address, increased by 17.
3. Passes four times the latest result to a dependency.

A subsequent call sequence produces \(H\). The routine then reads a byte at \(4Z+1\), writes zero at that byte-derived address plus 17, and calls a dependency with \(S_{10}(Z)\).

Later, one call result is forwarded with \(S_{28}(P)\) as the second visible argument. Another result is obtained; the byte at \(4Z+1\) is read again, its derived destination is cleared again, and the latest result multiplied by four is passed onward.

These separate clears cannot be collapsed into one operation: calls intervene, and both selector contents and observable memory behavior may differ.

### Second paired word update

Define \(V=S_{14}(H)\). The routine:

1. Stores \(V\) at \(16384H+20\).
2. Calls a dependency with \(S_{16}(H)\).
3. Executes another call.
4. Calls a dependency with \(S_{28}(V)\) and an additional register-derived argument.
5. Obtains an index through further calls.
6. Stores the retained \(V\) at four times that index, plus 20.
7. Calls a dependency with four times that index.

Under 32-bit modular arithmetic, \(S_{28}(V)\) is zero because \(V\) already contains a 14-bit left shift. This is a conditional arithmetic consequence, not evidence that the call or its other argument can be removed.

A later dependency produces \(J\). The routine reads the selector byte at \(4Z+1\) and writes:

\[
\operatorname{byte}((V \mathbin{\&} 0x3fffffff)\mathbin{\gg}20)
\]

to the derived address plus 17.

A call then receives \(S_{26}(H)\). Another call result is forwarded together with \(S_{30}(J)\). A later 64-bit result is forwarded as low and high word arguments.

After another result is obtained, the routine again reads the selector at \(4Z+1\), clears its derived destination, and passes four times the latest result onward.

### Third paired word update

1. Defines a retained word \(T=4N\).
2. Causes \(T\) to be stored at \(16N+20\).
3. Is followed by a call with \(T\) in three visible argument positions.
4. Is followed by further calls producing an index.
5. Causes the retained \(T\) to be stored at four times that index, plus 20.
6. Is followed by a call with four times that index.

The two updates use independently obtained results; they are not necessarily updates to the same location.

The result used for the second update also establishes the new carried base:

\[
B_{\text{next}}=S_{30}(N).

Under the 32-bit model, this base is restricted to four possible values. That restriction does not establish that any resulting address is valid.

### Direct clears and final word operations

Let the index used for the second update’s companion store be \(M\). A later dependency returns a word \(U\).

The routine writes zero directly to:

1. \(B_{\text{next}}+17\).
2. \(B_{\text{next}}+1\).

These are direct addresses, not byte-derived addresses. The store at offset 17 precedes the store at offset 1.

A dependency is called with \(S_2(U)\). Following additional calls, another result is obtained. The same two direct byte clears occur again, in the same order, before four times that result is passed onward.

A further dependency result, \(W\), then determines:

- The next iteration’s fourth argument: \(Q_{\text{next}}=4W\).
- A word-store address: \(16W+20\).

The word stored there is \(S_{31}(M)\). Under modular arithmetic it is either zero or the top-bit-only word, according to the low bit of \(M\).

Next, the routine reads a 32-bit word from:

\[
((U \mathbin{\&} 0x3fffffff)\mathbin{\gg}20)+20.
\]

This address lies between 20 and 1043 inclusive before any environment-specific access restrictions. The expression does not enforce word alignment.

The routine calls a dependency with \(Q_{\text{next}}\), obtains \(P_{\text{next}}\) from another dependency, and passes the shifted expression

S_{28}(\text{loaded word}\mathbin{\gg}22)

to another call.

After further calls, a new index is obtained. The routine stores a zero word at four times that index, plus 20, then calls a dependency with four times the index.

### Final byte updates and repetition

A later dependency returns a word \(E\). The routine:

1. Reads the byte at \(B_{\text{next}}+1\).
2. Writes \(\operatorname{byte}(S_2(E))\) at the byte-derived address plus 17.
3. Calls a dependency with \(S_2(E)\).
4. Obtains another result and forwards it with \(S_{30}(E)\).
5. Executes additional calls and obtains another result.

\[

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Third-argument scaling.** If \(P=3\), the first word store has value 12 at \(A+20\), provided execution reaches it and the access is valid.

2. **Unsigned byte-derived address.** If a selector read returns 255, its derived byte-write address is 272, not an address based on sign-extending 255.

3. **Re-read after calls.** If the selector initially contains 2 and a dependency changes it to 7 before the later clear, the corresponding writes target addresses 19 and 24. Caching the first selector would violate the represented behavior.

4. **Global snapshot.** If \(G=0xffc00000\), the first byte-derived write stores 255. Changing the global after its snapshot does not change that captured value.

5. **Carried word value.** If \(Y=20\), both stores in the first paired word update write 20, even if a dependency modifies the first destination before the second store.

6. **Top-bit-only store.** Under 32-bit modular arithmetic, the late \(S_{31}(M)\) store writes zero for even \(M\) and \(0x80000000\) for odd \(M\).

7. **Zero selector is not persistent.** The direct clear of \(B_{\text{next}}+1\) does not guarantee that the final derived store targets address 17. Intervening dependencies may change that byte.

8. **Non-returning dependency.** If any dependency does not return, the contract does not require subsequent writes or another iteration.
