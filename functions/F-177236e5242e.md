## Behavior

### Dependency-call conventions

Dependencies are identified by opaque call-site IDs as defined under **Dependencies**.

A **four-call tail** means four consecutive indirect calls with no displayed arguments. Where a following operation consumes a primary result, it uses the fourth call’s result. Earlier primary results are not explicitly consumed by this caller. One specified tail instead exposes a secondary-register value after its fourth call.

A **supplier/consumer pair** means a call with no displayed arguments followed by a call receiving that supplier’s primary 32-bit result.

“No displayed arguments” does not mean “no effective inputs.” Dependencies may observe registers, globals, or memory not described by their displayed argument lists.

The following phases occur in order. A phase is reached only if preceding calls return and preceding accesses complete.

### Unconditional loop

Before the loop, a dependency receives twice the initial loop component. A call with no displayed arguments supplies the initial **loop-carried value**.

Each iteration has two call groups separated by an explicit read-and-clear operation:

- The opening dependency receives the loop-carried value and the current loop component logically shifted right by eight. A four-call tail follows.
- The retained second byte-source address is reread. Zero is stored at seventeen plus the resulting unsigned byte.
- A dependency receives the preceding tail result shifted left by two. A second four-call tail produces the iteration’s final primary result.

For the next iteration, the loop-carried value becomes that final result shifted left by two. The loop component becomes that same result shifted left by twenty-six.

There is no displayed exit condition, and the second byte-source address is not recomputed from the loop’s new results.

The opening call’s second argument is necessarily zero on the first iteration because the initial loop component is at most 31. On later iterations, assuming 32-bit bit-pattern shifts, it equals the preceding final result’s low six bits shifted left by eighteen.

The opening call target uses different represented address state on the first iteration than on subsequent iterations. Target identity must not be assumed constant across that transition.

## Side effects

Every indexed byte write performs a fresh unsigned-byte read. An implementation matching this contract must not cache the destination derived from an earlier read.

- Word-store destinations.
- Either retained byte-source address.

1. **First visible effect.**

2. **Seed-derived overwrite.**  
   With seed 2 and first input 7, the earlier seed-derived store writes 7 at address 36. The later overwrite writes 16 at the same address. Dependency effects between these stores remain unconstrained.

3. **Unsigned third-input shift.**  
   Third input `0xffffffff` contributes `0x01ffffff` as the fourth argument of the four-argument call.

4. **Secondary-derived argument is scaled once.**  
   If the observed secondary-register value is 1, the secondary-derived word is `0x01000000`. It is stored at address `0x04000014`, and the following dependency receives `0x01000000` unchanged. A second multiplication by \(2^{24}\) is inconsistent with the represented call.

5. **Saved destination survives the three-argument call.**  
   If the result before that call is 2, the preceding word destination is address 52. The later overwrite stores 32 at address 52, regardless of the intervening tail’s primary result, provided the represented retained value remains available.

6. **Fresh indexed reads.**  
   If a retained source address contains byte 10 at one read and byte 20 at the next, those read-derived destinations are 27 and 37. Reusing 27 for both is inconsistent with the explicit reads.

7. **Byte truncation.**  
   If the first byte-source result is 65, its shifted low-byte store writes 4, not 260.

8. **Direct-store aliasing.**  
   If the direct store and the following indexed clear resolve to the same destination, that destination receives the direct byte first and zero second. The indexed destination must still be calculated from the intervening fresh read.

9. **Loop argument transition.**  
   The first opening call’s second argument is zero. Under 32-bit bit-pattern shifts, a later argument derived from preceding final result 3 is `0x000c0000`.
