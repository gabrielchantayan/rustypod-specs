# F-c062018ec9e8

## Purpose

F-c062018ec9e8 performs a comparison-directed search through linked records, then either publishes a candidate position or calls F-e5b879aada3e and publishes a word obtained from its result storage.

The output comprises a 32-bit value and a one-byte flag:

- **Flag 0:** the function publishes the candidate position without calling F-e5b879aada3e.
- **Flag 1:** F-e5b879aada3e was called and returned; the function publishes the first word of the storage supplied to that dependency.

Flag 1 does not independently establish successful insertion, allocation, or structural mutation.

An ordered-tree insertion operation with an optional uniqueness check is inferred intent. The explicit zero/nonzero decisions, memory accesses, and dependency calls below remain the contract regardless of that interpretation.

## Interface

The function receives three arguments:

| Argument | Established representation and use |
|---|---|
| Result destination | Address of writable storage. Receives a 32-bit word at byte offset 0, followed by a one-byte flag at byte offset 4. |
| Structure address | A 32-bit address used for field access and forwarded to dependencies. |
| Operation argument | An opaque 32-bit quantity forwarded unchanged as a comparison operand and to F-e5b879aada3e. |

The function has no established meaningful machine-level return value. Its specified result is written through the result destination.

Bytes beyond result offset 4 are not directly written. No clearing of padding is established.

### Preconditions and arithmetic

Normal completion requires valid storage for every executed access, dependencies that return normally, and link topology that terminates the selected walks. A null initial traversal link is supported. The structure, header, result destination, and links otherwise have no explicit validity checks.

Pointer-valued fields, copied result words, and the operation argument are 32-bit quantities in the supplied representation. Comparison and boundary-helper results are tested as 32-bit integers for zero versus nonzero; their signs do not affect branching.

Address formation uses fixed byte offsets. No overflow or address-range checks are shown. Behavior outside the represented address model is not established.

Aliasing restrictions are unknown. Final result writes can alter structure or record storage if the destination overlaps it. Dependency access to aliased storage can also affect subsequent reads.

## Behavior

### Initial state and descent

The remembered comparison outcome starts at 1.

The function reads the structure’s header pointer and then that header’s offset-4 link to obtain the initial traversal position. It separately rereads the structure’s header pointer to establish the remembered position. These are distinct accesses, not one cached header read.

For each non-null traversal position, the following order is established:

1. Two distinct 32-bit local scratch words are set to zero: the word later used for early insertion results, then the word later used for common insertion results.
2. F-b5e582db3504 is called with the structure address plus 0x19, the operation argument, and the current record address plus 0x10, in that order.
3. The current record becomes the remembered position.
4. The next traversal position is read from the current record:
   - Comparison result zero: offset 0x0c.
   - Comparison result nonzero: offset 8.

The selected link is read after the comparison returns. Changes made by that dependency can therefore affect the next step.

Descent ends at a null traversal position. If any record was visited, the remembered position and outcome come from the final visit. Otherwise, the remembered position is the separately loaded header and the outcome remains 1.

There is no traversal bound or cycle detection.

### Mode selection

After descent, the function reads the byte at structure offset 0x18.

- Any nonzero value selects common insertion directly.
- Zero selects candidate processing.

This is a post-descent read. Changes to the mode during comparison calls can affect the decision.

### Candidate setup and boundary helper

In zero mode, a writable local candidate cursor is initialized from the remembered position.

If the remembered comparison outcome is zero, boundary handling and link adjustment are skipped.

If it is nonzero, the function:

1. Reloads the header pointer from structure offset 0x10.
2. Reads that header’s offset-8 link into the common-result scratch word, replacing its previous contents.
3. Calls F-4cec57b703f5 with the address of the candidate cursor and the address of that scratch word.

The helper can change either supplied local object. Subsequent reads use the applicable post-call contents; preservation is not assumed.

A nonzero helper result selects **early insertion** immediately. A zero result selects the following candidate adjustment.

### Candidate adjustment after a zero helper result

The function reads the marker byte of the post-helper candidate.

If the marker is zero, it reads the candidate’s offset-4 link, then offset 4 of that linked record. If the second link equals the candidate, the function replaces the candidate with its offset-0x0c link and completes adjustment.

This special case takes precedence over ordinary offset-8 traversal. It can be selected even when the candidate’s offset-8 link is non-null.

If the special case is not selected, the function first fetches the candidate’s offset-8 link, then **separately rereads** that same field for a null test.

- **The second read is null:** the first fetched value is not used for traversal. The function reads the candidate’s offset-4 link and begins climbing.
- **The second read is non-null:** the function begins the other walk using the value from the first read, not the value from the null-test read.

On the climbing path, each step reads the prospective parent’s offset-8 link and compares it with the current candidate. It then replaces the candidate with that parent regardless of the comparison outcome. Equality causes another climb through offset 4; inequality ends adjustment. No null-parent guard is shown.

On the other path, each iteration:

- Replaces the candidate with the previously fetched link.
- Fetches the candidate’s offset-0x0c link for possible use as the next position.
- Separately rereads that offset-0x0c field to decide whether to continue.

A null second read ends adjustment at the current candidate. A non-null second read causes another iteration using the first fetched value.

With stable, agreeing reads, this path follows offset 8 once and then follows offset 0x0c to a terminal record. Without that condition, the fetched position and the continuation decision can disagree. In particular, a non-null test does not establish that the separately fetched next position is non-null.

The overall adjustment resembles predecessor selection, including a sentinel-specific case. That interpretation is conditional on record invariants.

### Candidate comparison and existing-position return

Every zero-mode path that has not taken early insertion proceeds to a reversed-operand comparison.

Before calling F-b5e582db3504, the function clears an additional 32-bit local word and then resets the common-result scratch word to zero. The additional word has no subsequent explicit read in the supplied body.

The comparison arguments are:

1. Structure address plus 0x19.
2. Candidate record address plus 0x10.
3. Original operation argument.

Thus, the operand roles are reversed relative to descent.

If the result is zero, the function writes the candidate cursor’s 32-bit value to result offset 0 and then writes flag 0 at offset 4. No insertion dependency is called.

The candidate cursor is read for output after the comparison returns. Because its address was supplied to the boundary helper on applicable paths, mutation through a retained pointer is not excluded. Without such mutation, the published candidate is the one used to form the comparison operand.

A nonzero comparison result selects common insertion. Neither zero nor nonzero alone establishes equality or ordering under a conventional three-way comparator.

### Early and common insertion

Both insertion paths call F-e5b879aada3e with:

1. Writable result-scratch address.
2. Original structure address.
3. A 32-bit literal zero.
4. Remembered descent position.
5. Original operation argument.

The fourth argument is not replaced by an adjusted candidate.

The paths differ in their result storage:

| Path | Supplied scratch word and established initialization |
|---|---|
| Early insertion | Uses the early-result word. Each descent iteration cleared it before comparison. With no descent visits, no initialization of this word is established before the insertion call. |
| Common insertion, nonzero mode | Uses the common-result word. Each descent iteration cleared it before comparison. With no descent visits, no initialization of this word is established before the insertion call. |
| Common insertion after candidate comparison | Uses the common-result word, explicitly reset to zero immediately before that comparison. |

These are initialization events, not guarantees that the contents remain zero. Intervening dependencies may change accessible storage.

In particular, the boundary helper has received the common-result word’s address. Resetting that word before candidate comparison does not revoke a retained pointer: the comparison dependency could subsequently change it through dependency-shared state. The helper may likewise retain the candidate cursor address.

After F-e5b879aada3e returns, the function copies the supplied scratch word to result offset 0, then writes flag 1 at offset 4. It performs no success check.

An insertion dependency need not write the word for the copied result to be defined: leaving a previously initialized, unchanged word alone can publish zero. Conversely, an unwritten word without established initialization does not have a meaningful value established by this body.

## Side effects

### Direct writes and ordering

On every normally completing result path, the caller-visible writes occur in this order:

1. One 32-bit result write.
2. One one-byte flag write.

This is not an atomic publication mechanism and establishes no synchronization guarantee.

The body directly updates local scratch storage and candidate storage, but contains no direct structure-field or record-link update. Container mutation, allocation, release, balancing, or ownership transfer, if any, occurs through dependencies.

### Dependency-mediated effects

Dependencies receive structure-associated addresses, record-associated addresses, the operation argument, and selected writable local storage.

Their complete write footprints and retention behavior are unknown. The contract does not assume preservation of globals, links, mode, comparison state, or ownership. Nor does it assume that local addresses supplied to a dependency cease to be reachable immediately after that call returns.

The separate traversal and adjustment reads described above must therefore not be collapsed into stable-memory behavior without an additional assumption. No concurrent-access safety is established.

### Errors and abnormal completion

There is no explicit structured error output, rollback, allocation-failure branch, or insertion-status validation.

If a dependency does not return normally, the final result writes may not be reached. Partial dependency effects are not rolled back here.

An insertion dependency returning without writing result storage is not necessarily erroneous: the published word depends on its established initial value and any intervening mutations. Empty-descent paths identified above lack such initialization for their selected insertion word.

Invalid addresses, nonterminating cycles, and malformed sentinel or parent relationships are not translated into structured errors.

The function directly releases neither the operation argument nor a returned position. That absence does not establish whether dependencies consume, retain, copy, allocate, or release anything.

## Acceptance examples

These are conditional static scenarios, not executed tests. They assume valid accesses, terminating topology, and no unstated mutation affecting the described outcome.

1. **Empty descent, nonzero mode.**  
   The initial link is null. No comparison or boundary call occurs. Common insertion receives the remembered header. Its scratch word has no established initialization; if the dependency writes a word, that word is published with flag 1.

2. **Visited descent, unchanged insertion scratch.**  
   At least one record is visited, mode is nonzero, and dependencies leave the common-result word unchanged after its last clear. If F-e5b879aada3e also leaves it unchanged, the result is zero with flag 1.

3. **Existing position without adjustment.**  
   Mode is zero and the last descent comparison returned zero. No boundary helper runs. If the reversed comparison returns zero, the candidate address is published with flag 0.

4. **Early insertion after boundary handling.**  
   Mode is zero, the remembered outcome is nonzero, and the boundary helper returns nonzero. No adjustment or reversed comparison occurs. With at least one descent visit and no intervening change to the early-result word, an insertion dependency that leaves it unchanged produces zero with flag 1. With no visits, that word has no established initialization.

5. **Ordinary adjustment returns a terminal record.**  
   The boundary helper returns zero, the sentinel-special branch is not selected, both offset-8 reads agree on a non-null link, and subsequent paired offset-0x0c reads agree. Adjustment follows offset 8 and then offset 0x0c to a terminal record. If the reversed comparison returns zero and leaves the cursor unchanged, that terminal address is published with flag 0.

6. **Sentinel-special branch overrides offset 8.**  
   The marker is zero and the offset-4 link of the offset-4-linked record equals the candidate. Adjustment selects the candidate’s offset-0x0c link even if offset 8 is non-null.

7. **Adjusted candidate is not the insertion anchor.**  
   Adjustment changes the candidate, then the reversed comparison returns nonzero. Common insertion receives the remembered descent position, not the adjusted candidate.

8. **Reset does not prevent later scratch mutation.**  
   The boundary helper retains the common-result address. Before candidate comparison, that word is reset to zero. If the comparison subsequently changes it through retained access, returns nonzero, and insertion leaves it unchanged, the changed word is published with flag 1.

9. **Disagreeing adjustment reads.**  
   The first ordinary offset-8 fetch is non-null but the second read is null. The function selects climbing; it does not traverse the first fetched link.

10. **Negative comparison result.**  
    A negative nonzero descent result selects offset 8, exactly as a positive nonzero result does.

11. **Output padding.**  
    Without dependency or aliasing effects on the destination, bytes beyond offset 4 retain their previous contents.
