# F-46a321bb7881

## Purpose

F-46a321bb7881 selects an address within a caller-supplied memory region, copies five four-byte fields from that selected address into a caller-supplied destination, and then writes the byte value 4 into the selected region.

The established behavior is a sequence of memory transfers followed by a one-byte mutation. The supplied evidence does not establish the semantic meaning of the fields or of the value 4. Interpreting the final write as a status transition is plausible intent, not a demonstrated application-level contract.

The operation is not an isolated snapshot copy. Each source field is read immediately before its corresponding destination write. If the source and destination overlap, earlier writes can change the values read later.

The supplied representation declares all three inputs as integer values in a 32-bit addressing model. The first and third inputs are nevertheless used as addresses. No explicit lengths, capacity values, ownership indicators, or error-output parameters are present.

The function has no explicit return value. Its externally visible results are its memory writes and any effects of accessing the supplied addresses.

## Behavior

### Selection

Before any destination transfer, the function reads the four-byte selector at B + 4 + 4 × I.

It uses that selector together with the index and base address to calculate S:

**S = B + 56 × I + 28 × Q**

The scales are significant:

- The selector lookup advances by four bytes per index.
- The index contribution to S advances by 56 bytes per index.
- The selector contribution to S advances by 28 bytes per selector unit.

The evidence does not establish a table length, a permissible selector range, or a guarantee that S lies inside the same allocation as B. In particular, it does not establish that the selector has only two possible values merely because 56 is twice 28.

The selected address is calculated once. Later changes to the selector’s storage do not cause the function to select a new address.

### Ordered transfers

After selecting S, the function performs these transfers in order:

1. Read four bytes at S + 12, then write that value at D + 4.
2. Read four bytes at S + 16, then write that value at D + 8.
3. Read four bytes at S + 24, then write that value at D + 16.
4. Read four bytes at S + 28, then write that value at D + 20.
5. Read four bytes at S + 32, then write that value at D + 24.

These are opaque four-byte transfers. No arithmetic, comparison, conversion, validation, or interpretation of the copied values is shown.

The reads do not all occur before the writes. Consequently, a specification that first captures all five original source values and then writes them would be incorrect for some overlapping layouts.

### Final mutation

After the fifth destination write, the function writes the byte value 4 at S + 8.

This final operation is narrower than the field transfers. It does not directly replace four bytes beginning at S + 8.

The function does not inspect the previous byte value. No conditional branch depends on it, and no transition restriction is enforced. If this location is a status field, the visible behavior is an unconditional assignment rather than a checked state transition.

### Aliasing

No overlap test is present. Observable results must therefore account for overlap whenever the underlying accesses remain valid.

Important cases include:

- **Destination overlaps a later source field.** An earlier destination write can replace a value before the function reads it.
- **Destination overlaps the selector.** The selector has already been read and S calculated, so overwriting the selector does not redirect the remaining transfers.
- **Destination overlaps S + 8.** The final byte write can change part of a value just copied to the destination.
- **Destination fields coincide with their source fields.** The function still performs the reads and writes, followed by the final byte mutation.

Descriptions of “untouched destination bytes” apply only to the listed direct destination writes. The separate write at S + 8 can affect a destination byte through aliasing.

### Arithmetic boundaries

The supplied representation uses integer-valued inputs and intermediate address arithmetic associated with a 32-bit target. Products by 4, 56, and 28 can exceed a signed 32-bit range.

The evidence does not establish a portable overflow policy. It is therefore not justified to promise either mathematical unbounded arithmetic or defined modulo behavior for every input. The successful-execution contract is clearest for inputs whose calculations remain representable and whose resulting addresses are valid.

Negative indices and selectors are not rejected by any visible check. Their usability depends on the arithmetic interpretation and on the resulting memory accesses; absence of validation is not evidence that such inputs are supported.

## Acceptance examples

The following examples are conditional acceptance criteria derived from the static evidence. They have not been executed. Unless stated otherwise, all addresses and accesses are valid, arithmetic is representable, and no concurrent modification occurs.

### 1. Non-overlapping transfer

Given I = 0 and a selector value of 0 at B + 4, S equals B.

Suppose the four-byte source values at S + 12, S + 16, S + 24, S + 28, and S + 32 are respectively A, B₁, C, E, and F. If the destination does not overlap the accessed source or selector storage, completion must leave:

- D + 4 containing A.
- D + 8 containing B₁.
- D + 16 containing C.
- D + 20 containing E.
- D + 24 containing F.
- The byte at S + 8 equal to 4.

The function does not directly write destination offsets 0–3 or 12–15.

### 2. Independent index and selector contributions

Given I = 1 and selector value 2 at B + 8, S must equal B + 112, because the two contributions are 56 and 56 bytes.

The source accesses must use offsets relative to B + 112. Treating the selector as an absolute address, or using a 56-byte selector stride, would not satisfy this behavior.

### 3. Overlap propagates earlier writes

Let D equal S + 12. Before copying begins, let the source values at S + 12, S + 16, S + 24, S + 28, and S + 32 be A, B₁, C, E, and F.

The first transfer writes A into S + 16. The second transfer therefore reads A rather than the original B₁.

The third transfer writes C into S + 28. The fourth consequently reads C and writes it into S + 32, causing the fifth transfer also to read C.

The five destination fields must consequently contain A, A, C, C, and C in transfer order. A result based on all five original source values would incorrectly impose snapshot semantics.

### 4. Final mutation overlaps a copied field

Let D equal S + 4. The first copied field is written at S + 8.

After all five field transfers, the final mutation must set the byte at address S + 8 to 4. Thus, the final four-byte field at D + 4 need not equal the value originally copied there.

Which numeric significance that byte has depends on byte order; the address-level requirement does not.

### 5. Existing final-byte value does not control copying

If the byte at S + 8 already equals 4, the five transfers still occur. If it initially has another value, the transfers likewise occur and the byte is overwritten with 4 afterward. No visible early exit depends on this byte.
