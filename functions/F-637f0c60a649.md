# F-637f0c60a649

## Purpose

F-637f0c60a649 performs a state-dependent operation on a mutable object and returns no explicit value.

Two active paths are established:

- Initial state **0 or 5** enters a preparation path. It writes state **3**, conditionally calls an object dependency, obtains an address from another dependency, writes two 32-bit values through that address, processes a retained context reference, and conditionally invokes an indirect callback.
- Initial state **1 or 2** enters a query-and-submit path. It writes state **3 or 4**, respectively, performs gated dependency calls, and may submit a signed 16-bit result through another indirect callback.

Every other initial state byte returns without an explicit write or dependency call.

These are operational descriptions. State meanings, initialization, allocation, registration, and the domain meaning of the submitted number are not established.

## Behavior

### Initial dispatch and state writes

### Preparation path

For entry state 0 or 5, the function rereads the state byte and then writes **3**. Subsequent decisions use the reread value, not the newly written value:

- If the reread value is 0, call F-06ba2757defe with the object and continue.
- If it is 3, return.
- If it is 5 or 6, continue without that call.
- Otherwise, return.

Thus, with a stable state byte, entry state 0 calls F-06ba2757defe and entry state 5 does not. The second read remains part of the observable access sequence; it must not be replaced by an assumption that both reads agree.

For a continuing preparation path, the sequence is:

1. Call F-76b7ec0cf6ba and retain its result as the context reference.
2. Read the object’s 32-bit field at offset 28 and retain that value.
3. Call F-8157a180d901 with the integer argument **12**.
4. Treat the returned value as an address and write a 32-bit zero at offset 0.
5. Write the captured object value at offset 4 of the same address.
6. Call F-bf0b7433249b with the retained context reference.
7. Call F-583c269a6d82 with that same reference.
8. Read the context’s 32-bit field at offset 32 and retain it as a record reference.
9. Call F-9813035c7ce7 with arguments **1** and that record reference.
10. Return unless its signed 32-bit result is **−1**.
11. On −1, load the indirect target from G-06 and read the 32-bit value at record offset 4 for the callback argument. Invoke D-01 and return.

The target load and record-offset-4 read occur after F-9813035c7ce7 returns −1. Their relative ordering is not established by the supplied expression.

The offset-28 read occurs after F-06ba2757defe, if that call occurs, and after F-76b7ec0cf6ba. It occurs before F-8157a180d901. Consequently, changes made by the first two dependencies affect the captured value, while later changes to the object do not replace that captured value.

- Two 32-bit words through the address returned by F-8157a180d901 on a continuing preparation path.

There is no established ownership transfer for the object, returned address, context, or nested records. No explicit release is shown. This proves neither a leak nor correct lifetime management: F-8157a180d901 may or may not allocate, and other dependencies’ memory-management behavior is unknown.

There is no explicit failure status or rollback. Invalid references, an unwritable returned address, or invalid callback targets have no established recovery behavior. A first-query zero or second-query low-component zero is an early-return condition. A result of −1 from F-9813035c7ce7 selects a callback rather than propagating an error.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Inactive state:** Initial state 6, like state 3 or 4, returns without a state write or dependency call.

2. **Stable state 0:** State 3 is written before F-06ba2757defe. The offset-28 read follows both that call and F-76b7ec0cf6ba. No initialization postcondition is implied.

3. **Stable state 5:** State 3 is written, F-06ba2757defe is skipped, and the continuing preparation sequence executes.

4. **Captured copy:** If offset 28 contains bit pattern 0x12345678 when read, the address returned by F-8157a180d901 receives zero at offset 0 and 0x12345678 at offset 4, even if that dependency changes the object field.

5. **Preparation callback:** A result other than −1 from F-9813035c7ce7 skips D-01. On −1, a target installed in G-06 by that dependency is the subsequently loaded target.

6. **First-query failure:** With initial state 2 and first-query result zero, state 4 has already been written, but none of the three following object calls occurs.

7. **Second-query failure:** A zero low component from the second query skips flag reads, numeric processing, and final submission after all three object calls have occurred.

8. **Zero flag:** F-c9e0501fef5b receives zero; the signed field is not read. The submitted signed value is determined by F-c9e0501fef5b, not directly by the flag.

9. **Zero signed field:** With a nonzero flag and signed field zero, F-29b7066c265c receives 0x3f800000. G-01 through G-04 are not read on this route.

10. **Live operands:** Changes to G-01/G-02 during F-9e5e664c8ae7 and to G-05 during F-29b7066c265c are visible to the subsequent operand reads.

11. **Repeated lower reads:** If the computed result is 8, the retained G-03 candidate is 5, and its comparison read is 10, the selected result is 5. G-04 is not read.

12. **Stable boundaries:** With stable signed boundaries 5 and 10, results at either boundary select that boundary, and a result of 8 remains 8.

13. **Final target and sign:** If F-c9e0501fef5b supplies low 16 bits 0xffff, D-03 receives −1 as its widened second argument. If D-02 changes G-07, the subsequent target load observes that location after the call.
