# F-77303ea85faa

## Purpose

F-77303ea85faa writes three consecutive 32-bit words to a destination using two 32-bit words at a source.

For non-overlapping, stable storage, the resulting destination words are the first source word, the second source word, and the first source word again. That description is insufficient when the regions overlap: the first source word is read twice, with two destination writes between those reads. Consequently, the third destination word can reflect a change caused by an earlier destination write.

The established behavior is an ordered sequence of word accesses. The intended meaning of the three-word result is unknown.

## Behavior

### Ordered accesses

The supplied body establishes the following order of accesses:

1. Read the 32-bit word at source offset 4 and retain that value.
2. Read the 32-bit word at source offset 0.
3. Write the value from the immediately preceding read to destination offset 0.
4. Write the value retained from the initial read to destination offset 4.
5. Read the 32-bit word at source offset 0 again.
6. Write the value from that final read to destination offset 8.
7. Return without a result value.

There are three source-read occurrences and three destination-write occurrences. The first source word is read twice; the second source word is read once.

This ordering describes the operations expressed by the supplied body. It is not a guarantee of six separately observable hardware transactions. Compiler transformations, machine instruction selection, memory attributes, and the execution environment are not provided.

### Stable, non-overlapping storage

If source and destination do not overlap, and no external agent changes the source during execution:

- Destination offset 0 receives the initial word at source offset 0.
- Destination offset 4 receives the initial word at source offset 4.
- Destination offset 8 receives the initial word at source offset 0.
- Source contents remain unchanged by this function.

The destination's prior contents are not consulted. No destination read is expressed.

### Overlapping storage

No non-overlap check appears in the supplied body. Overlap must therefore be analyzed using the access order rather than by treating the source as a two-word snapshot.

The second source word is retained before any destination write. A later write that changes its original storage does not change the retained value used for destination offset 4.

The first source word is different: its second read occurs after the writes to destination offsets 0 and 4. If either earlier write changes the storage subsequently read as the first source word, the final destination word reflects that later read.

For ordinary word-aligned overlap:

- If destination and source are identical, the result is the original first word, the original second word, and the original first word.
- If destination begins four bytes before source, the write to destination offset 4 replaces the first source word with the retained second source word. The final read therefore obtains that second-source value.
- If destination begins four bytes after source, the first write replaces the second source word. This does not affect the retained value used by the second write, or the first source word used by the final read.

These are consequences of the stated sequence, conditional on the accesses being valid. They do not establish that arbitrary overlapping or misaligned regions are permitted by every relevant language or platform rule.
