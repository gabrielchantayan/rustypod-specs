# F-325faf1ba418

## Purpose

F-325faf1ba418 records the low byte of a requested mode, executes one of two mode-dependent sequences, conditionally updates a pending-state byte and invokes a related dependency, then executes a common sequence of indirect object dispatches.

Branch selection compares the **full 32-bit mode argument with 1**, not the byte recorded in the object. Arguments that produce the same stored byte can therefore select different branches.

The meanings of the modes, stored bytes, external flag, and common-dispatch values are not established. Terms such as “status” and “pending” below identify fields; they do not establish application-level semantics.

This contract describes the supplied static representation. It does not establish runtime behavior beyond that evidence, particularly where the final indirect transfer and indirect-call interfaces remain unresolved.

The function receives:

- A primary-object address.
- A 32-bit integer mode argument.

The supplied representation uses 32-bit addresses and four-byte integer words. All offsets below are byte offsets from the primary-object address.

| Offset | Width | Established use |
|---|---:|---|
| `0x000` | 32 bits | Address of the primary object’s dispatch table. |

The contents and semantic types of these values are unknown. A represented 32-bit transfer alone does not establish whether a value is an address, identifier, coordinate, or other scalar.

## Behavior

### Initial recording and branch selection

The first visible operation writes the mode argument’s low eight bits to `0x4CD`.

The original 32-bit argument then selects the branch:

- Exactly 1 selects the first branch.
- Every other value selects the second branch.

The write occurs before every dependency call. A later failure or non-return does not undo it.

### Mode exactly equal to 1

The represented sequence is:

1. Invoke F-15643c36365d.
2. Obtain a dispatch table from its returned object and invoke the entry at byte offset `0x3C`.
3. Invoke F-416575e983b4 with the first branch-specific opaque value.
4. Read the secondary-object address from primary-object offset `0x430`.
5. Obtain that secondary object’s dispatch table and invoke its entry at byte offset `0xC0`.
6. Write the query result’s low byte to primary-object offset `0x4CE`.
7. Evaluate the external flag, query result, and possibly pending byte to determine whether to invoke F-5c99899bb6ce.

The secondary-object field is read after the preceding calls. Its entry-time value is not necessarily the value used.

The query result is represented as an **unsigned 32-bit value**. The function distinguishes:

- Whether that full value is zero.
- The low byte written to `0x4CE`.

A result of 256, for example, is nonzero for gating purposes but stores zero at `0x4CE`.

#### Flag and pending-byte gate

The representation contains two separate reads of the external flag.

The first flag read determines whether the pending byte is read:

- If the first flag value is nonzero and the full query result is nonzero, read `0x4CF` as an unsigned byte. Its zero-extended value becomes the working condition value.
- Otherwise, do not read `0x4CF` for this gate. The working condition value remains the full query result.

The next gating expression reads the external flag again. F-5c99899bb6ce is invoked with the primary object only when:

- This second flag value is nonzero.
- The original full query result was nonzero.
- The working condition value is nonzero.

The original query-zero decision remains distinct from the working condition value, even when that working value has been replaced by the pending byte.

If the flag remains stable across both reads, this reduces to requiring a nonzero flag, nonzero full query result, and nonzero pending byte. Without a stability assumption, that simplification is not equivalent to the represented accesses.

In particular, if the first flag read is zero but the second is nonzero, a nonzero query result can permit F-5c99899bb6ce without a local pending-byte read.

#### Conditional update

If the gate fails, F-5c99899bb6ce is skipped, and no local pending-byte write or F-09d363f7f1ec call occurs on this branch.

If the gate passes:

- A zero return from F-5c99899bb6ce skips the local pending-byte write and F-09d363f7f1ec.
- A nonzero return causes a zero byte to be written to `0x4CF`, followed by F-09d363f7f1ec with the primary object.

The branch then reaches the common sequence if all invoked operations return.

“No local pending-byte write” does not imply that the pending byte retains its entry-time value. Earlier dependencies may have changed it.

### Mode other than 1

The represented sequence is:

1. Invoke F-15643c36365d.
2. Obtain a dispatch table from its returned object and invoke the entry at byte offset `0x40`.
3. Invoke F-416575e983b4 with the second branch-specific opaque value.
4. Read the byte at primary-object offset `0x4CE` and test it for zero.

If that byte is zero:

- Skip F-baabc64698a1.
- Perform no local write to `0x4CF`.
- Skip F-09d363f7f1ec.
- Continue to the common sequence.

If the byte is nonzero, invoke F-baabc64698a1 with the primary object:

- On a zero return, write zero to `0x4CF`, skip F-09d363f7f1ec, and continue to the common sequence.
- On a nonzero return, write one to `0x4CF`, invoke F-09d363f7f1ec with the primary object, and continue to the common sequence.

This branch does not directly write `0x4CE`. Its test occurs after preceding calls, so the tested value need not equal the byte present at function entry.

#### Separate captures and argument reads

A is captured before dispatch 1. Dispatch 1 nevertheless obtains its A argument through a separate read of the same external storage. Dispatches 2, 3, 6, and 7 use the captured A.

D is captured after dispatch 2. Dispatch 3 nevertheless obtains its D argument through a separate read of D’s external storage. Dispatch 4 and the subtraction used by dispatch 5 use the captured D.

There is no intervening call between either capture and its corresponding argument reread. That does not establish equality if the storage can change independently. The representation must not be contracted into a single A read or a single D read.

Conversely, changes to the external storage after capture do not replace the represented captured values. In particular, a change to D’s external storage by dispatch 3, dispatch 4, or F-d7185491b9c5 does not change the D capture used by dispatch 5.

#### Dispatch resolution and arithmetic

The primary object’s dispatch table and slot are consulted again for successive dispatches. The sequence is not established as seven calls to one entry-point address cached at the start.

The D capture is represented as a signed 32-bit integer for the subtraction by 3. Its numerical result is established when representable in that width. The supplied representation does not establish wraparound or other overflow behavior when the capture is below −2,147,483,645.

The first dispatch also has apparent additional arguments: a separately represented dispatch-entry address and register-derived values. Their intentional interface status is unknown. The principal-argument table does not discard this uncertainty or assert a complete calling convention.

These writes are ordered with the calls as described and are not transactional. No restoration is visible if a later operation fails or does not return.

## Acceptance examples

These are conditional static acceptance cases, not runtime results. Unless stated otherwise, accesses are valid, dependencies return normally, and callees do not introduce additional changes relevant to the example.

1. **Truncation does not select the branch.**  
   Mode 257 writes 1 to `0x4CD` but selects the branch using slot `0x40`, because the full argument is not 1.

2. **Zero query result.**  
   With mode 1 and query result zero, `0x4CE` receives zero. The local gate does not read `0x4CF`, and F-5c99899bb6ce is skipped regardless of the flag values.

3. **Nonzero query with a zero low byte.**  
   With mode 1 and query result 256, `0x4CE` receives zero. Stable nonzero flag values and a nonzero pending byte permit F-5c99899bb6ce.

4. **Stable zero flag.**  
   With mode 1, a nonzero query result, and both flag reads zero, the pending byte is not locally read and F-5c99899bb6ce is skipped.

5. **Changing flag values.**  
   With mode 1, a nonzero query result, first flag read zero, and second flag read nonzero, no local pending-byte read occurs. F-5c99899bb6ce is invoked because the working condition still holds the nonzero query result.

6. **Successful mode-1 conditional operation.**  
   If its gate passes and F-5c99899bb6ce returns nonzero, zero is written to `0x4CF` before F-09d363f7f1ec is invoked.

7. **Other-mode stored-byte gate.**  
   If `0x4CE` is zero when tested, both conditional dependencies are skipped and no local pending-byte write occurs. If it is nonzero, F-baabc64698a1 returning zero produces pending byte zero without F-09d363f7f1ec; returning nonzero produces pending byte one followed by that call.

8. **D capture differs from dispatch 3’s argument.**  
   Suppose D’s capture reads 10, but an independently occurring storage change makes the separate dispatch-3 read yield 20. Dispatch 3 receives 20, dispatch 4 receives captured 10, and dispatch 5 receives 7. Whether such an external change is possible is unresolved; equality must not be assumed without storage stability.

9. **Later D changes do not replace the capture.**  
   If D is captured as 10 and F-d7185491b9c5 later changes its external storage to 40, dispatch 5 still receives 7 for the subtraction argument.

10. **Arithmetic boundary remains unresolved.**  
    A D capture of −2,147,483,645 yields the representable result −2,147,483,648. A smaller capture crosses the signed lower boundary; this contract does not prescribe wrapping or another outcome.
