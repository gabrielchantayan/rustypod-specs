# F-2c45d971e29e

## Purpose

F-2c45d971e29e performs two ordered delimiter-processing passes over a value obtained from a caller-supplied object. Each successful delimiter pair causes construction of a temporary descriptor, an operation on the caller’s object using that descriptor and a global argument, and a cleanup-related call.

The first pass uses two fixed, externally stored search patterns. The second pass uses the numeric character values `0x3C` and `0x3E`, conventionally `<` and `>`.

**Established behavior:** the routine identifies candidate boundaries through dependencies and forwards calculated positions to other dependencies. It does not itself read matched text, move text, or directly write the caller’s object.

**Inferred intent:** the routine appears intended to process or remove marked regions, first using a special delimiter pair and then using angle brackets. Actual removal, replacement, parsing rules, and ownership effects are not established without the dependency contracts.

The original pointer, rather than merely the initially loaded value, is subsequently passed to F-fa3abcde8103 for every successfully identified pair.

## Behavior

### 1. Capture the working value

The routine reads the initial 32-bit value through the input pointer, adds 36, and calls F-826f25835f54 with that result.

The returned 32-bit value is retained and reused by both passes. The routine does not explicitly reacquire it after any later operation on the caller’s object.

Consequently, any dependency-induced relocation or invalidation must be accounted for by the dependency contracts or by a caller-side invariant. This routine provides no visible refresh mechanism.

### 2. Measure the first-pass closing pattern

Before either search pass, the routine counts bytes in the fixed first-pass closing pattern until it encounters a zero byte.

The count:

- Starts at zero.
- Excludes the terminating zero byte.
- Is calculated once.
- Is retained for all first-pass endpoint calculations.

This scan occurs even if neither pass will ultimately find a complete pair.

An empty closing pattern produces a count of zero. An inaccessible or unterminated pattern has no defined recovery path in the visible routine. A pattern too long for the signed counter introduces an arithmetic issue not resolved by the supplied evidence.

The closing-pattern storage is subsequently passed to the search dependency. The routine does not copy it or remeasure it between iterations. If a dependency changes that storage, later searches may observe changed contents while endpoint calculations still use the original measured length.

### 3. Process first-pass pattern pairs

The carried search position starts at zero.

Before attempting a first-pass opening-pattern search, the routine requires the carried position to be nonnegative. It then calls F-a21141daa905 with:

- The retained working value.
- The fixed opening-pattern address.
- The carried position.

The returned value replaces the carried position. If it is exactly `-1`, the first pass ends.

For any other return value, the routine calls F-a21141daa905 again with:

- The same retained working value.
- The fixed closing-pattern address.
- The newly returned opening position plus one.

If this closing search returns `-1`, the first pass ends without constructing or processing a descriptor for that opening.

For a successful closing search, the routine calculates an endpoint by adding the previously measured closing-pattern length to the closing-search result. It then performs, in order:

1. A call to F-f762c9d297ce with the temporary workspace address, the numeric argument 20, the opening position, and the calculated endpoint.
2. A read of the global 32-bit argument and a call to F-fa3abcde8103 with the original input pointer, the temporary workspace address, and that global value.
3. A call to F-289ec4311c64 with the address 12 bytes into the temporary workspace.

The next first-pass opening search uses the same carried opening position. The routine does not explicitly advance it to the closing position, to the calculated endpoint, or by one.

**Progress consequence:** successful completion depends on dependency behavior or changing search results. If searches repeatedly return the same pair and the processing operation leaves subsequent searches unchanged, the routine can repeat indefinitely.

### 4. Carry the first pass’s position into the second pass

There is no position reset between passes.

The starting position for the second pass depends on how the first pass ended:

- If the opening-pattern search returned `-1`, the second pass begins with `-1`.
- If a closing-pattern search returned `-1`, the second pass begins with the opening position associated with that failed closing search.
- If the first pass completed a body with a negative opening result other than `-1`, the next first-pass nonnegative guard prevents another iteration, and that negative position reaches the second pass.

The routine therefore does not establish that the second pass scans the retained value from its beginning.

### 5. Process second-pass angle-character pairs

The second pass calls F-a4621b603aad with:

- The retained working value.
- Character value `0x3C`.
- The carried position.

Unlike the first pass, it does not first require the carried position to be nonnegative.

The result replaces the carried position. A result of exactly `-1` ends the routine’s search work.

Otherwise, the routine calls F-a4621b603aad with:

- The retained working value.
- Character value `0x3E`.
- The opening result plus one.

If this closing search returns `-1`, the pass ends without processing that opening.

For a successful pair, the routine calculates the endpoint as the closing result plus one. It then performs the same three-call construction, object-operation, and cleanup sequence used by the first pass.

The next opening-character search again starts at the carried opening position, without an explicit increment.

A conventional half-open interval interpretation would include the closing `>` character. That interpretation remains conditional on F-f762c9d297ce interpreting its last two arguments as start and exclusive end.

### 6. Finish

After the second pass terminates, the routine returns without an explicit result.

There is no visible final release of the retained working value, rollback, aggregate success indication, or report of an unmatched delimiter.
