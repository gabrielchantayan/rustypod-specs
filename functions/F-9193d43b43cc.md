# F-9193d43b43cc

## Purpose

F-9193d43b43cc describes a condition-dependent sequence of software-interrupt requests and coprocessor operations, followed by an explicit invalid-instruction termination marker.

The supplied representation does not establish a conventional application-level purpose. In particular, it does not establish that the interrupt numbers identify services, that the coprocessor operations transfer ordinary application data, or that the terminal marker represents an intentional shutdown.

This contract distinguishes three levels of confidence:

- **Established static evidence:** operations, operands, conditions, and ordering explicitly present in the supplied representation.
- **Inferred intent:** possible architectural interpretations that are not sufficient to define behavior.
- **Unknown or documented_only:** behavior requiring instruction bytes, execution-mode information, handler definitions, or other unavailable evidence.

The representation reports invalid instruction data and truncated control flow. Consequently, the sequence below is a contract for the supplied static representation, not proof that a processor can execute the entire sequence as shown.

## Behavior

### Condition classes

The sequence uses three conditions:

- **Primary condition:** Z is true, or N differs from V.
- **Equality condition:** N equals V.
- **Nonzero condition:** Z is false.

Their combinations are:

| Z | N compared with V | Primary condition | Equality condition | Nonzero condition |
|---|---|---:|---:|---:|
| True | Equal | True | True | False |
| True | Different | True | False | False |
| False | Equal | False | True | True |
| False | Different | True | False | True |

The primary condition is not the complement of the equality condition. When Z is true and N equals V, both conditions hold, so both the primary-condition sequences and the address-bearing operations are selected.

The supplied representation repeatedly refers to the same incoming condition values. It contains no explicit updates to those values. Whether actual interrupts or coprocessor instructions would change processor flags or other context is not established.

### Ordered operation sequence

The following order is established by the supplied representation. Later stages are reachable only if earlier selected operations permit continuation.

#### 1. Initial conditional sequence

When the primary condition is true, the represented order is:

- One software-interrupt request with immediate value `0x1ddf1d`.
- A coprocessor transfer with selector fields `(6, 7, 7)` and Context C in both represented context-operand positions.
- One software-interrupt request with immediate value `0x1ddf1d`.
- One software-interrupt request with immediate value `0x1dcebc`.
- Eleven further consecutive software-interrupt requests with immediate value `0x1ddf1d`.

These are separate operations. The representation provides no basis for coalescing repeated interrupts or treating them as a single request.

When the primary condition is false, this entire sequence is replaced by one coprocessor transfer with selector fields `(15, 5, 0)` and context operands Context C followed by Context D.

The architectural meanings and operand directions of these transfers are unknown.

#### 2. Earlier conditional address-bearing operation

When N equals V, a coprocessor long-load operation is represented with:

- Selector value `5`.
- Context A.
- An address expression formed from Base A plus `0x260`, equivalent to decimal 608.

This stage follows either outcome of the initial conditional sequence.

When N differs from V, the operation is absent.

#### 3. Intermediate primary-condition interrupts

When the primary condition is true, four consecutive software-interrupt requests use immediate value `0x1ddf1d`.

When the primary condition is false, none of these four requests is selected.

#### 4. Independent nonzero-condition interrupt

When Z is false, one software-interrupt request uses immediate value `0x1edf1d`.

This decision is independent of whether N equals V. In particular, this request occurs on both nonzero-condition paths, including the path that selects the alternative coprocessor transfers.

When Z is true, this request is absent.

#### 5. Later conditional sequence

When the primary condition is true, the represented order is:

- Seven consecutive software-interrupt requests with immediate value `0x1cdf1c`.
- A coprocessor transfer with selector fields `(15, 7, 0)` and Context C in both represented context-operand positions.
- One software-interrupt request with immediate value `0x1cdefc`.
- One software-interrupt request with immediate value `0x1dcebb`.
- Ten consecutive software-interrupt requests with immediate value `0x1ddf1d`.

When the primary condition is false, this entire sequence is replaced by one coprocessor transfer with selector fields `(15, 5, 0)` and context operands Context B followed by Context D.

The alternative transfer here differs from the initial alternative transfer: it uses Context B where the earlier operation uses Context C.

#### 6. Later conditional address-bearing operation

When N equals V, another coprocessor long-load operation is represented with:

- Selector value `5`.
- Context A.
- An address expression formed from Base B plus `0x25c`, equivalent to decimal 604.

This operation uses a different base input and a different displacement from the earlier long-load operation.

When N differs from V, the operation is absent.

#### 7. Final primary-condition interrupts

When the primary condition is true, four consecutive software-interrupt requests use immediate value `0x1cdf1c`.

When the primary condition is false, none of these four requests is selected.

#### 8. Terminal marker

All represented paths converge on an invalid-instruction termination marker.

There is no represented ordinary return after that marker. The actual processor outcome—such as an exception, termination, or execution beyond an incorrectly recovered boundary—is documented_only.

### Arithmetic and layout constraints

The two address expressions are independent. The displacement `0x260` applies only to Base A; `0x25c` applies only to Base B.

Both displacements are divisible by four. This does not establish alignment of either resulting address, because neither base has an established alignment.

The representation does not establish:

- The machine address width.
- Whether address addition wraps, traps, or is merely an imperfect representation of instruction address generation.
- Signed-overflow behavior.
- The quantity of data accessed by a “long” coprocessor load.
- Endianness, memory structure, or field layout.
- Whether either operation updates its base register.

A specification consumer must not infer a 32-bit memory transfer merely from the four-byte width of Context A.

No explicit ordinary memory stores are represented. This does not establish that execution is free of memory writes: interrupt handlers and coprocessor operations may perform them.

## Acceptance examples

These are conditional static trace examples, not runtime test results. Each assumes that preceding operations permit continuation.

### Z false, N equals V

The primary condition is false.

The selected sequence consists of the initial alternative transfer using Context C and Context D; the earlier long-load operation at Base A plus 608; the `0x1edf1d` interrupt; the later alternative transfer using Context B and Context D; the later long-load operation at Base B plus 604; and the terminal marker.

None of the primary-condition interrupt groups is selected.

This example distinguishes the two alternative transfers and verifies that the nonzero-condition interrupt is not nested inside the primary condition.

### Z true, N equals V

Both the primary and equality conditions are true.

Both primary-condition sequences, both four-interrupt groups, and both long-load operations are selected in their specified order. The `0x1edf1d` interrupt is absent.

An interpretation that omits the long-load operations merely because the primary condition is true does not match the representation.

### Z true, N differs from V

The primary condition is true, but the equality and nonzero conditions are false.

All primary-condition groups are selected. Neither long-load operation nor the `0x1edf1d` interrupt is selected.

Changing the base inputs must not introduce either address-bearing operation into this represented path.

### Z false, N differs from V

The primary and nonzero conditions are true; the equality condition is false.

All primary-condition groups are selected. The `0x1edf1d` interrupt occurs after the intermediate group of four `0x1ddf1d` requests and before the later conditional sequence. Neither long-load operation is selected.

### Earlier operation does not resume

If an interrupt transfers control permanently, this contract does not require any subsequent request, load, transfer, or terminal marker to execute.

It would be incorrect to report a complete runtime trace solely because later operations appear in the supplied representation.
