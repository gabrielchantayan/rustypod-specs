# F-990b0b0a7d55

## Purpose

F-990b0b0a7d55 coordinates indirect dependency invocations around a narrow memory update and a two-word payload. Its externally relevant behavior comprises:

- An initial 16-bit write through an address obtained from a dependency.
- Construction and submission of a payload containing two 32-bit words.
- Conditional dispatch using a value obtained from another dependency.
- An alternative continuation that accesses two low-address globals and obtains a replacement payload.
- Either an explicit return following dispatch or a control-flow boundary identified as invalid instruction data.

No application-level purpose is established. In particular, the evidence does not identify the payload as a particular object, message, numeric quantity, or ownership-bearing resource.

This contract describes established static behavior and explicitly conditional interpretations. It does not establish that the represented routine is a complete or correctly decoded executable interface.

## Behavior

### Initial memory update and payload acquisition

The first dependency interaction is F-IND-01. Its target depends on the incoming link-derived quantity. Its 32-bit result is used as an address base, not checked as a status code.

The routine writes the base quantity’s low 16 bits at displacement 52 from that returned address. No null, bounds, or success check is represented before the write. This establishes only the two-byte update, not the type or extent of a containing object.

F-IND-02 is invoked after that update. Its result supplies the initial payload’s lower word.

The signed 16-bit read occurs after F-IND-02 returns. Its address depends on the base-plus-offset calculation. The resulting value is sign-extended into the initial payload’s upper word.

Consequently, this read is not an entry-time snapshot. It can observe changes made by the initial write when the regions overlap, and it can observe changes made by F-IND-02. No non-aliasing or dependency-preservation guarantee is established.

Address calculations involve represented 32-bit quantities, including signed arithmetic. The evidence does not provide a complete rule for overflow, truncation, or conversion into executable or data addresses. A contract for ordinary valid addresses must not silently extend to overflowing cases by choosing wrapping or checked arithmetic.

### Payload submission and branch outcomes

The initial payload is submitted to F-IND-03A. Any replacement payload is submitted to F-IND-03B. Their represented target calculations differ, so they are distinct dependency sites; equivalence of their actual destinations or effects is not established.

After each payload submission, F-IND-04 is invoked. Its signed 32-bit result is retained for possible dispatch.

The continuation is governed by two decisions:

| Decision point | Condition | Observable continuation |
|---|---|---|
| Dispatch decision after F-IND-04 | Carry is nonzero and zero is zero | Invoke F-IND-05 with the shifted result; return if that invocation returns normally. |
| Otherwise | Dispatch condition is false | Invoke F-IND-06 before considering the remaining exit condition. |
| Exit decision after F-IND-06 | Zero is zero and the negative and overflow bytes are equal | Reach the invalid-instruction boundary. |
| Otherwise | Exit condition is false | Enter the replacement-payload path. |

Conditions in this table refer to the state applicable at each decision. They do not assert that dependencies preserve real machine flags.

F-IND-05 receives a one-bit left shift of F-IND-04’s represented signed 32-bit result. For a nonnegative result whose doubled value fits in signed 32 bits, the argument is that doubled value. The evidence does not establish portable behavior for negative operands or results exceeding the signed range. A low-32-bit machine-shift interpretation is therefore not an unconditional acceptance rule.

F-IND-05 is an unresolved transfer represented as an invocation. Its actual transfer kind, calling convention, and ability to return are unknown. The routine’s explicit return is reachable only if this transfer returns normally.

The other represented exit reaches an invalid-instruction boundary. No particular exception, signal, halt, or further destination is established.

### Replacement-payload path

The repeat path uses an ordering comparison between a stack-relative address and the address-like value `0xFFFFFFBF`. Under the unsigned address-order interpretation suggested by the representation:

- A stack-derived address at or below that threshold selects 124.
- A stack-derived address above that threshold selects 125.

That selected value is F-IND-07’s first explicit argument. Its second is obtained from the global beginning at `0x0000005F`; its third is 55.

The global read must occur before F-IND-07 begins because its value supplies an argument. The read width, signedness, and argument conversion are not established.

The represented repeat-path condition assignments clear carry, zero, negative, and overflow before F-IND-07. The comparison can yield only zero or one; neither outcome makes the represented carry calculation true or causes signed overflow in the associated addition by 124.

If F-IND-07 returns normally, the routine assigns 62 to the global beginning at `0x00000049`. The assignment’s width and affected byte range remain unresolved.

F-IND-08 is invoked after that assignment. Its represented 64-bit result becomes the replacement payload, with lower and upper words subsequently submitted to F-IND-03B.

This ordering makes the global assignment observable before F-IND-08 executes. It does not guarantee that F-IND-08 leaves the assigned storage unchanged.

### Conditional bound on repetition

Under a literal condition-state interpretation in which intervening dependencies do not alter the four represented indicators, a replacement pass cannot dispatch: carry and zero are both clear. After F-IND-06, the remaining exit condition succeeds because zero is clear and negative equals overflow.

That interpretation allows at most one replacement payload and two payload submissions.

This is not an unconditional executable-level termination guarantee. The available evidence does not establish actual flag production or preservation across indirect transfers. No stronger repetition bound is claimed.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. They assume valid reached targets and accesses, defined address calculations, and normal dependency returns wherever continuation is described.

### Narrow update and signed payload word

Suppose the base quantity’s low 16 bits are `0xFEDC`. The initial destination receives that 16-bit pattern; higher bits of the base quantity do not enter the write.

If the later read observes `0x8001` and F-IND-02 returns `0x12345678`, F-IND-03A receives:

- First word: `0x12345678`.
- Second word: `0xFFFF8001`.

The read value is the value observed after F-IND-02, not necessarily the value present on entry.

### Immediate dispatch

If carry is nonzero and zero is zero at the dispatch decision, and F-IND-04 returns 7, F-IND-05 receives 14.

F-IND-06 and both repeat-path global accesses are not reached. Normal return from F-IND-05 leads to routine return.

### Immediate invalid-instruction boundary

If dispatch is not selected, F-IND-06 returns, and the subsequent state has zero clear and identical negative and overflow byte values, the invalid-instruction boundary is reached. F-IND-07 and F-IND-08 are not invoked.

Negative and overflow values of 1 and 2 do not satisfy the equality requirement merely because both are nonzero.

### Replacement payload and global ordering

If dispatch is not selected and the exit condition is false after F-IND-06, the repeat path is reached.

F-IND-07 receives the global value read before its invocation. After it returns, the assignment of 62 precedes F-IND-08.

If F-IND-08 supplies lower word 9 and upper word `0xABCDEF01`, F-IND-03B receives those exact word patterns. The upper word is neither narrowed nor sign-extended again.

This case does not establish that only one byte changes at `0x00000049`.

### Stack-order boundary and conditional termination

Under unsigned address ordering, a stack-derived address equal to `0xFFFFFFBF` selects first argument 124 for F-IND-07. Address `0xFFFFFFC0` selects 125.

For either selection, the represented repeat-path condition assignments clear all four indicators. If subsequent dependencies preserve that condition state, the replacement pass invokes F-IND-06 and then reaches the invalid-instruction boundary without dispatching.

## Evidence

Established static evidence supports the dependency order, explicit 16-bit accesses, signed extension, two-word payload layout, branch predicates, repeat-path condition assignments, global references, and represented termination points.

The distinction between F-IND-03A and F-IND-03B follows from different represented target calculations. It does not prove different implementations.

The all-clear repeat-path condition state follows from the comparison’s two possible outcomes and the bounded addition associated with overflow detection. Its effect on later executable decisions remains conditional on flag preservation.

The supplied representation reports invalid instruction data, an unrecovered indirect transfer represented as an invocation, and overlapping global symbols. Those limitations constrain conclusions about complete control flow and memory layout.

The global assignment has no supplied storage declaration or explicit access-width evidence. Neither its value nor its symbol establishes a one-byte footprint.
