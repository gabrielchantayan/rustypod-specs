# F-7357eb3df321

## Purpose

The supplied static representation describes a routine that performs a sequence of raw memory writes, invokes two dependencies, performs additional writes, and reaches a boundary marked as invalid instruction data. It does not establish a higher-level purpose, a successful return path, or a conventional error-reporting mechanism.

The observable contract is therefore a **conditional memory-and-call trace**, not a validated initialization, allocation, or cleanup API. Execution of each later operation depends on earlier memory accesses succeeding and both dependencies returning normally.

The representation explicitly warns about invalid instruction data and overlapping global symbols. Its interpretation as a coherent executable routine is uncertain. The behavior below records what the supplied representation expresses without treating the apparent invalid-instruction boundary as proof of a particular hardware exception.

## Behavior

### Arithmetic model and notation

For describing addresses, let:

- **P** be the destination address interpreted as a 32-bit quantity.
- **I** be the unsigned 32-bit index.
- **R** be the incoming signed register value.
- **T** be the represented signed result of subtracting seven from R.
- **Q** be T arithmetically shifted right by eleven bits.
- **B** be Q multiplied by 32 and interpreted as a 32-bit address quantity.
- **U** be the unsigned 32-bit sum of I and Q.
- **W** be twice U, reduced to 32 bits.

The representation uses signed arithmetic for some intermediate expressions and unsigned arithmetic for others. Unsigned addition, multiplication, and left shifts in the described 32-bit domain discard high bits. Signed overflow is not independently resolved by the supplied evidence. Examples below avoid it.

Arithmetic right shift is the interpretation expressed for signed T. For non-overflowing values, Q corresponds to division by 2048 rounded toward negative infinity. A right shift by 31 yields zero for nonnegative T and negative one for negative T.

No byte order is established. Descriptions of 16-bit and 32-bit writes specify values and widths, not their byte encoding.

### Ordered initial writes

The first represented memory operation writes the 16-bit value to P.

The destination address then drives two 32-bit writes:

1. The value corresponding to P multiplied by 32 is written at that same computed address.
2. That same value is written at the address corresponding to P multiplied by 64.

Under a 32-bit address interpretation, address products retain their low 32 bits. The first argument’s pointed-to contents are not read to obtain these addresses.

Next, the representation assigns zero to the global objects associated with addresses `0x28` and `0x40`, in that order. The excerpt does not expose those objects’ declared widths. The warning about overlapping symbols prevents treating them as independent storage objects.

These operations precede both dependency calls. They are not conditional on either call succeeding.

### Index-derived writes

The representation then performs these operations in order:

1. Writes W as a 32-bit value at address B plus `0x28`.
2. Writes W as a 32-bit value at address W itself.
3. Writes a 16-bit value at an address formed by clearing U’s highest bit, shifting the result right by 17 bits, and adding eight.

The value in the third write is W logically shifted right by 18 bits, narrowed to 16 bits.

The third write has useful static bounds:

- Its address lies between `0x8` and `0x4007`, inclusive.
- Its value lies between `0x0000` and `0x3FFF`, inclusive.
- Its address is not guaranteed to be aligned for a 16-bit write.

Clearing U’s highest bit affects only this address calculation. It does not modify U for the earlier computation of W.

No non-aliasing guarantee exists. A later write may overwrite part or all of an earlier write, including the destination or either global-associated location. The specified order matters whenever ranges overlap.

### First dependency invocation

The routine reads a byte at an address obtained by:

- Taking the bitwise exclusive OR of B and I.
- Multiplying that result by 512 in the represented 32-bit unsigned domain.

The byte is interpreted through a plain character type and converted to an integer for the call. The signedness of that character type is not established. Bytes below `0x80` have the same resulting value under either interpretation; bytes at or above `0x80` do not.

The first dependency target is obtained through a pointer-sized entry at an address formed from the incoming link-related value plus `0xA84`. This dependency is designated **F-INDIRECT-01** for this contract. That designation is an opaque reference, not a recovered identity.

Both the target lookup and the byte read occur before invocation. Their relative read order is not established by the supplied call expression.

F-INDIRECT-01 receives the converted byte value. Its return value is treated as a pointer to writable 16-bit storage. The routine immediately writes zero through that pointer.

There is no visible null check, status check, size check, or alignment check. A null return does not select a separate failure path; it leads directly to a write at address zero.

### Second dependency invocation

The returned pointer is then passed to **F-INDIRECT-02**, a second opaque dependency reference.

Its represented target address is `0x0897F9D8`, obtained by clearing the low two bits of a fixed address value and adding `0x604`.

The 16-bit zero write occurs before this call. No result from this second dependency is subsequently consumed in the visible representation.

Nothing establishes that this call releases memory, takes ownership, preserves globals, or leaves the pointed-to storage unchanged.

### Writes following the calls

If both calls return normally, the representation continues with these operations:

1. Write the 16-bit value `0xF484` at the address obtained by arithmetically shifting T right by four bits.
2. Write a 32-bit zero at the address obtained by shifting I left by three bits.
3. Form a sign-derived pointer from T shifted right by 31 bits.
4. Write the low eight bits of that sign-derived value through that pointer.
5. Store that pointer through the stack-derived destination, using a represented 32-bit pointer-sized write.
6. Write the low 16 bits of the sign-derived value at the pointer plus `0x34` bytes.

For nonnegative T, these last operations involve:

- A byte write of zero at address zero.
- A stored pointer value of zero.
- A 16-bit zero write at address `0x34`.

For negative T, a conventional 32-bit address interpretation gives:

- A byte write of `0xFF` at address `0xFFFFFFFF`.
- A stored pointer value of `0xFFFFFFFF`.
- A 16-bit write of `0xFFFF` at address `0x33`, if pointer addition wraps in the target address domain.

These addresses are not automatically valid. The representation does not guard them. Faulting at any earlier operation prevents the later operations from occurring.

## Acceptance examples

These examples are conditional static expectations, not executed tests.

### Initial destination write

Given valid storage at P and a supplied value of `0x1234`, the first represented write stores `0x1234` in a 16-bit object at P.

A later fault does not imply that this first write was undone.

### Zero index and zero adjusted register value

Given R equal to seven and I equal to zero, T, Q, B, U, and W are all zero.

Subject to successful preceding accesses:

- A 32-bit zero is written at `0x28`.
- A 32-bit zero is written at address zero.
- A 16-bit zero is written at address eight.
- The dependency argument byte is read from address zero.

The writes at `0x28` and zero here are the index-derived writes; the earlier global-associated zero assignments also occur.

### Negative adjusted register value

Given R equal to six and I equal to one:

- T is negative one.
- Q is negative one.
- B is `0xFFFFFFE0` under a 32-bit interpretation.
- U and W are zero.
- The index-derived 32-bit write at B plus `0x28` targets address eight under wrapping address arithmetic.
- The following 16-bit write also targets address eight.

The later 16-bit write therefore overlaps the earlier 32-bit write. If execution reaches the sign-derived tail, its byte write targets `0xFFFFFFFF`, not zero.

### Unsigned doubling boundary

Given Q equal to zero and I equal to `0x80000000`:

- U is `0x80000000`.
- W is zero because doubling discards the high bit.
- The 16-bit address calculation clears U’s high bit and targets address eight.
- The 16-bit value written there is zero.

This behavior is wrapping arithmetic, not saturation.

### Returned pointer ordering

If F-INDIRECT-01 returns a valid pointer K, the 16-bit object at K receives zero before F-INDIRECT-02 is invoked with K.

If F-INDIRECT-01 does not return normally, neither that zero write nor the second call is established to occur.

### Character signedness boundary

If the byte read for F-INDIRECT-01 is `0x7F`, its integer argument is 127.

If the byte is `0xFF`, the argument may be negative one or 255 depending on plain-character signedness. The supplied evidence does not choose between them.
