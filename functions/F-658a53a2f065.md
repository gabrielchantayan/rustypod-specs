# F-658a53a2f065

## Purpose

F-658a53a2f065 conditionally prepares a descriptor for a resolved object, then processes an input description list through nested cleanup calls, accounting updates, and an allocation-release-related sequence.

**Established static behavior:** an initial environment status gates resolution and preparation. A resolved object undergoes ordered eligibility checks. An eligible object can cause descriptor allocation, early publication, record-array allocation, transformation calls, normalization, and additional preparation calls. Normally returning paths converge on list cleanup.

**Inferred intent:** preparation for adding a column to a table. Diagnostic references support this interpretation. Neither completion of a schema change nor successful copying of existing records is established.

## Behavior

### Preparation gate, resolution, and rejection

A nonzero initial environment status skips preparation.

Otherwise, F-3747d6ba198f receives the context, zero, list word `0x0c`, list word `0x08`, and the fourth argument. A null result proceeds to cleanup without an additional diagnostic from this body.

For a nonnull result, checks occur in this order:

1. A nonzero byte at target `0x39` selects the virtual-table-related diagnostic reference.
2. Otherwise, a nonzero word at target `0x18` selects the view-related reference.
3. Otherwise, descriptor construction proceeds.

A rejection calls F-2022b0f73f3b with context and the selected reference, then proceeds to cleanup. The first rejection has precedence when both fields are nonzero.

The references suggest restrictions on altering virtual tables and adding columns to views. Exact diagnostic bytes, punctuation, termination, and delivery are not established.

### Descriptor allocation and early publication

For an eligible target, F-49f750c2c596 receives the captured environment and target `0x4c`. Its 32-bit return is retained as a selection index.

F-f053f140662a then receives the environment and an 80-byte request. A null return leads to cleanup without an explicit descriptor publication or explicit status assignment by this body.

For a nonnull return, the observable sequence is:

1. Store the allocated pointer at context `0x180`.
2. Write one at descriptor `0x1c`.
3. Read the target’s signed count and store it at descriptor `0x04`.
4. Request record-array storage through F-f053f140662a.
5. Store that return at descriptor `0x08`.
6. Read target `0x00` and pass it with the environment to F-8ad0042eaec1.
7. Store the returned value at descriptor `0x00`.
8. Test the reread descriptor `0x08` and the retained transformation return.

Publication precedes both subsequent dependencies. Either may alter context `0x180`. Later accesses through the locally retained descriptor pointer do not reread the context’s published pointer. Continued publication is therefore not guaranteed.

For the captured signed count \(n\), the array request is represented by:

\[
20\left(8\operatorname{trunc}_{0}\left(\frac{n-1}{8}\right)+8\right).
\]

Division truncates toward zero. For positive counts without intermediate overflow, this rounds capacity up to a multiple of eight 20-byte records. Exact multiples of eight receive no extra group. Zero requests 160 bytes.

The expression uses signed 32-bit arithmetic. Negative counts are not rejected; for example, a count of minus one also produces 160 absent other effects. Signed overflow and the interpretation of unsafe request values are unresolved.

### Failure after transformation

The local failure branch is taken if descriptor `0x08`, reread after transformation, is zero, or the retained return from F-8ad0042eaec1 is zero.

On this branch, the body writes byte value one at captured-environment `0x1e` and proceeds to cleanup. It performs no explicit unpublication, rollback, or release of the descriptor.

The array-request return alone does not determine this branch. The intervening transformation may replace descriptor `0x08`, changing either a null or nonnull result before the test. Conversely, the second condition uses the retained transformation return, not a reread of descriptor `0x00`; changing that field cannot compensate for a zero return.

Neither the failure branch nor normal return guarantees that context `0x180` still contains the pointer originally published. Allocation, transformation, and cleanup dependencies may alter it.

### Nested list cleanup

Preparation paths whose dependencies return normally converge on cleanup. A null list returns immediately.

For a nonnull list, cleanup visits records at increasing addresses with a 48-byte stride. Each iteration makes the seven calls in the interface table, in the listed order.

Each field is read for its own call. Earlier dependencies may change arguments observed by later calls. Zero values are passed without filtering. No record fields are explicitly cleared.

The signed 16-bit list count is reread for every loop condition. An initially zero or negative count admits no records. Dependency-induced count changes may shorten or extend traversal.

### Outer accounting

Let \(A\) be the list address minus the 32-bit displacement read four bytes before the list. Let \(s\) be the 32-bit quantity read at \(A-8\).

The accounting sequence makes distinct observations of a global pointer:

1. The final cleanup-loop condition captures the pointer used later for the high-word destination at `0x3c`.
2. A subsequent observation supplies the low-word source at `0x38`; its value is retained.
3. Another supplies the high-word source address at `0x3c`; its contents are not yet read.
4. Another supplies the low-word destination at `0x38`, where the retained low word minus \(s\) is stored.
5. Only then is the retained high-word source address read, adjusted, and written through the pointer captured by the final loop condition.

These observations need not identify one object. In particular, the low-word write can alias and affect the subsequent high-word source read.

The low result is modulo \(2^{32}\). The high adjustment subtracts the sum of:

- The arithmetic sign contribution of \(s\), zero or minus one.
- The unsigned borrow from comparing the retained low word with \(s\).

With a stable accounting object and suitable nonaliasing layout, this corresponds to subtracting a sign-extended 32-bit quantity from a two-word value. It is not unconditionally subtraction of an unsigned quantity.
