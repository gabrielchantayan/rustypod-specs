# F-fc9213b68354

## Purpose

F-fc9213b68354 applies a length-and-reference-byte gate to an input buffer, then conditionally compares input bytes against two transformed nine-byte patterns. Recognition causes a 32-bit state write and three ordered dependency calls sharing one local temporary-storage address.

The first pattern selects subtype 1 and writes 16. The second pattern selects subtype 2 and writes 20. If both match, both writes occur, and subtype 2 takes precedence for the calls.

The dependencies’ semantic roles are unknown. Their ordering and arguments do not establish that they construct, deliver, store, initialize, or destroy a result.

This contract describes static evidence only. No runtime tests have been performed.

The routine receives two machine-level arguments:

- **Record address:** points to storage accessed through 32-bit fields.
- **Input-descriptor address:** a 32-bit address representation used to access a count and an input-buffer address.

The supplied representation uses 32-bit words and addresses and one-byte characters. All offsets below are in bytes.

### Return value

The result is 32 bits:

| Path | Returned value |
|---|---|
| Initial length mismatch or reference-byte gate failure | A fresh read of the shared default |
| Reference gate passes, but neither pattern is recognized | The default captured near entry |
| A pattern is recognized and all three dependencies return normally | Zero |

Zero is not established as an exclusive success indicator: the shared default may itself be zero. Dependency return values do not affect the demonstrated result.

### Preconditions

Normal execution requires every address actually accessed on the selected path to be valid, with appropriate readability or writability.

In particular:

- The record and descriptor must expose their accessed fields.
- Input and reference storage must cover every byte actually examined.
- Each table address read must designate storage covering the corresponding accessed position.
- A recognition-state destination must permit a 32-bit write.
- Dependencies must accept their arguments and the 104-byte local temporary region.

The reference length is not a general bound on later input reads. The second pattern can become eligible even when the initial computed length is less than nine. Such a path still requires input positions zero through eight to be readable if comparison reaches them.

No explicit null checks, buffer bounds checks, allocation checks, or object-type checks appear. Non-overlap and immutability are not established preconditions imposed by this routine; callers may require them externally.

## Behavior

### Entry reads and two distinct scale observations

The routine performs these entry operations in order:

1. Captures the shared default return value.
2. Reads and saves the shared scale value.
3. Computes the initial length using a **separate read of the shared scale** and a read of the descriptor count.

The saved scale is not the scale operand used by the initial multiplication. It is retained for the later second-pattern eligibility multiplication.

No ordering is established between the scale read and the count read within the initial multiplication. Both belong to that multiplication, after the earlier scale capture.

Consequently, an unchanged descriptor count does not guarantee equal initial and later products. The two scale observations may differ.

### Initial arithmetic and length gate

The initial multiplication uses signed 32-bit operands in the supplied representation. Its result is placed in an unsigned 32-bit length.

For a product representable as a signed 32-bit integer, the subsequent unsigned interpretation is established. A negative representable product becomes its corresponding unsigned 32-bit value. Merely storing the result as unsigned does not establish the behavior of an overflowing signed multiplication.

The routine compares the computed length with the record’s 32-bit reference length through a 32-bit difference tested against zero. The equality condition is equality of the two 32-bit values.

If they differ:

- No input, reference, or pattern bytes are examined.
- No recognition-state write occurs.
- No dependency is called.
- The shared default is read again and returned.

### Reference-byte gate

When lengths agree, the routine examines positions in ascending order, starting at zero, while the index is less than the computed unsigned length.

For each position:

1. It reads the input-buffer address from the descriptor and captures the input byte at that position.
2. It accesses the reference-buffer address through the record and compares the reference byte with the captured input byte.
3. If they differ, it makes a second reference-byte access at the same position and compares that value with the same captured input byte.

A mismatch on both reference comparisons fails the gate and returns a fresh read of the shared default.

If the first reference comparison differs but the second agrees, the loop stops and the gate succeeds immediately. Remaining reference positions are not examined.

The second comparison does not recapture the input byte. The reference address is accessed through its record field in the repeated expression; a single permanent snapshot of that address is not established.

With stable ordinary buffers, this gate is an exact comparison over the computed length. A computed length of zero passes without input or reference byte reads when the reference length is also zero. Embedded zero bytes have no special significance.

These are accesses expressed by the supplied static representation, not a guarantee of hardware access counts or safe concurrent mutation.

### First-pattern comparison

The first pattern is eligible only if the initial computed unsigned length equals nine.

The routine examines up to nine positions, zero through eight, in ascending order. At each examined position:

1. It reads the current input-buffer address through the descriptor and captures the input byte.
2. It reads the first-pattern-table address from shared storage.
3. It accesses the table byte at that address plus the current position.
4. It multiplies the table character value by −27 and converts the product to a one-byte character.
5. It compares the captured input character with the transformed character.

The shared table-address read and the table-byte read are distinct accesses. No entry snapshot of the table address is established. Different positions may therefore use different table bases if shared storage changes.

The repeated equality condition on a mismatch uses already captured character values; it does not cause another input, table-address, or table-byte read. Under those captured values, a mismatch rejects the pattern and stops its comparison.

If all nine positions agree, subtype 1 is selected. The routine then reads the associated-object address from record offset 48 and writes the 32-bit value 16 at associated-object offset 1300.

This write occurs before the second eligibility multiplication and before any second-table address or byte reads.

On the demonstrated byte-oriented interpretation, the transformed byte is the low eight bits of the product. Exact language-level rules for out-of-range conversion to plain character remain platform-dependent.

### Second-pattern eligibility and comparison

After the first-pattern stage, whether it matched, failed, or was ineligible, the routine rereads the descriptor count. It multiplies that count by the scale saved near entry.

This multiplication does not reread the shared scale. It is tested against nine as a signed arithmetic result in the supplied representation.

Thus the two pattern eligibility decisions depend on different observations:

- First-pattern eligibility uses the initial length, computed with the later entry-time scale read.
- Second-pattern eligibility uses a fresh count read and the earlier saved scale.

A first-pattern state write can alter later observations through aliasing. For example, it can change the descriptor count, the descriptor’s input-buffer address, or the shared second-table address if the write destination overlaps that storage. The saved scale itself is already a local captured value.

When the second product equals nine, the routine examines positions zero through eight in ascending order. At each examined position:

1. It reads the current input-buffer address through the descriptor and captures the input byte.
2. It reads the second-pattern-table address from shared storage.
3. It reads the table byte at that address plus the position.
4. It multiplies the table character value by 121 and converts the product to a one-byte character.
5. It compares the captured character values.

The second-table address is read separately at every examined position, not captured at entry or at the start of the pattern check. All such reads occur after any first-pattern state write.

A mismatch rejects the second pattern. Its repeated mismatch condition uses the same captured character values and introduces no additional memory read.

If all nine positions agree, the routine reads the associated-object address from the record, writes the 32-bit value 20 at offset 1300, and selects subtype 2.

### Recognition precedence

The resulting behavior is:

| First pattern | Second pattern | Explicit writes | Subtype |
|---|---|---|---|
| Not recognized | Not recognized | None | No dependency calls |
| Recognized | Not recognized | 16 | 1 |
| Not recognized | Recognized | 20 | 2 |
| Recognized | Recognized | 16, then 20 | 2 |

Each write uses the associated-object address read for that write. They are not guaranteed to target the same location if the record field changes or is affected through aliasing.

When neither pattern is recognized, the routine returns the entry-captured default.

### Ordered dependency calls

Recognition causes these calls, in order:

1. **F-ed485a8933da:** receives the local temporary-region address and the selected subtype, 1 or 2.
2. **F-c20ae87ac99e:** receives the record’s current 32-bit words at offsets 0 and 4, followed by the same temporary-region address.
3. **F-0b6f5f32b71e:** receives the current associated-object address plus 1304, followed by the same temporary-region address.

The temporary region contains 104 bytes. This routine does not explicitly initialize it before the first call.

The second call’s record fields are read after the first call returns. The third call’s associated-object address is read after the second call returns. No dependency is assumed to preserve record fields, globals, or other reachable memory.

The relative evaluation order of the second call’s individual argument reads is not established.

No dependency return value is inspected. After all three calls return normally, the routine returns zero.

## Side effects

### Direct writes

The demonstrated direct nonlocal writes are the 32-bit recognition-state values 16 and 20 at associated-object offset 1300.

The intermediate write of 16 is observable in the stated operation sequence even when a later write of 20 targets the same address. Neither write is deferred until dependency processing succeeds.

The routine does not directly assign to input bytes, reference bytes, descriptor fields, table storage, or shared default and scale storage. This is not a non-aliasing guarantee: a recognition-state write may overlap such storage.

### Ownership and lifetime

The 104-byte temporary region has invocation-local automatic lifetime. All three dependencies receive its address.

No explicit allocation, deallocation, ownership transfer, reference-count operation, or cleanup operation is demonstrated in this routine. Whether dependencies initialize the region, retain its address, release represented resources, or require subsequent destruction is unknown.

The third dependency’s first argument identifies associated-object offset 1304, not the state field at offset 1300.

### Errors and interruption

There is no explicit recoverable-error protocol for invalid accesses or dependency failure. Dependency return values are ignored.

A fault or non-returning dependency can prevent later calls and the final return. Earlier recognition-state writes are not rolled back by any demonstrated path. No atomicity or transaction guarantee is established.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless stated otherwise, assume stable, valid, non-overlapping storage; representable signed products; target-compatible byte conversions; and normally returning dependencies.

1. **Length rejection.**  
   If the initial product is nine and the reference length is eight, the routine performs no byte comparisons, state writes, or dependency calls. It returns a fresh shared-default read.

2. **Persistent reference mismatch.**  
   If lengths agree but a captured input byte differs from both reference accesses at that position, the gate fails. Even an otherwise matching pattern cannot bypass this failure.

3. **Reference changes between comparisons.**  
   If the first reference access differs from the captured input byte and the second agrees, the gate succeeds immediately. Later reference positions are skipped.

4. **Stable empty input.**  
   If both scale observations and the count produce zero, and the reference length is zero, the gate passes without byte reads. Neither pattern is eligible. The entry-captured default is returned.

5. **Different scale observations enable only the second pattern.**  
   Suppose the saved scale is three, the separate initial scale read is two, and the unchanged count is three. The initial length is six. If six reference bytes agree, the first pattern is skipped, but the second product is nine. If all nine second-pattern bytes match, the routine writes 20, calls the dependencies with subtype 2, and returns zero. The input must cover nine bytes despite the six-byte reference gate.

6. **Different scale observations disable the second pattern.**  
   Suppose the saved scale is two, the initial scale read is three, and the count remains three. The initial length is nine, but the second product is six. A matching first pattern writes 16 and leads to subtype-1 calls; the second table is not accessed.

7. **Only the first pattern matches.**  
   With both products nine and a passing reference gate, a first-pattern match followed by a second-pattern mismatch writes only 16. The calls use subtype 1.

8. **Both patterns match.**  
   If both transformed tables match all nine input positions, the routine writes 16 and then 20. With a stable associated-object address, the second write replaces the first at the same location. The calls use subtype 2.

9. **First write changes the second table selection.**  
   If the first recognition-state destination overlaps the shared second-table address, the write of 16 occurs before that address is read for the second comparison. Subsequent table-byte accesses use the resulting address values. Normal completion additionally requires those addresses to be valid; validity is not implied.

10. **No recognized pattern.**  
    If the reference gate passes but both eligible patterns fail, there are no state writes or dependency calls. The routine returns the entry-captured default, not a fresh default read.

11. **Dependency changes later arguments.**  
    If F-ed485a8933da changes record offset 0, the second call receives the changed value. If F-c20ae87ac99e changes record offset 48, the final call uses the changed address plus 1304.

12. **Interrupted processing.**  
    If 16 has been written and the first dependency does not return, neither later call nor a zero return is guaranteed. No rollback is demonstrated.
