# F-ed1edd420578

## Purpose

F-ed1edd420578 conditionally invokes a state-adjustment dependency, links the resulting selected object into a secondary chain, and drains a primary chain through two dependency calls per removed entry. It returns a 64-bit value combining the original state-object address with a 32-bit result.

The observable control flow distinguishes two cases:

- If the state’s initial selection field is zero, the function performs no dependency calls or state writes and returns the second argument in the high half of its result.
- If that field is nonzero, the function invokes F-da1b2f2cbf9f, performs the secondary-chain writes, and drains the primary chain. The high half of the result then comes from a mutable 32-bit working value initially populated from the selection field.

“Selection,” “primary chain,” and “secondary chain” are descriptive labels for the observed accesses. Their application-level meanings are not established.

The address width follows from the supplied 32-bit field accesses, address use, and result concatenation. The evidence does not establish a portable host-language interface or the machine-level calling convention.

### Return value

The return is a 64-bit bit-vector with:

- Bits 31–0: the original state-address bit pattern.
- Bits 63–32: the selected 32-bit result described below.

Equivalently, interpreting both halves as unsigned bit patterns, the returned value is the high half multiplied by \(2^{32}\), plus the low half. This is bit concatenation, not sign extension of the high half and not arithmetic addition of a signed second argument to an address.

On normal completion:

- Zero initial selection: the high half is the second argument’s 32-bit bit pattern.
- Nonzero initial selection: the high half is the working selection value read during the terminating primary-chain check.

There is no explicit success flag, error return, or status translation.

## Behavior

### 1. Initial selection check

The function reads the 32-bit selection field at state offset +16 and places its value in a working location.

If this value is zero, the function skips all remaining state manipulation and dependency calls. It returns the original state address in the low half and the second argument in the high half.

Consequences of this branch:

- The primary-chain head is not read.
- The secondary-chain head is not read.
- The fourth argument is not exposed to a dependency.
- No selected-object field is read.
- A nonempty primary chain, by itself, does not trigger draining.

The state address must still support the initial read at offset +16.

### 2. Preparation and invocation of F-da1b2f2cbf9f

For a nonzero initial selection address, the function reads four bytes at that address plus eight. It copies that value into a second temporary location and copies the fourth argument into a third temporary location.

It then calls F-da1b2f2cbf9f with four arguments, in this order:

1. Address of the temporary containing the fourth argument.
2. Original state address.
3. Address of the temporary containing the value read at initial-selection offset +8.
4. Address of the working selection value.

These are writable address arguments in the observed interface. The dependency can therefore affect the working selection value and the two other exposed temporary values. It can also affect state storage through the supplied state address.

The function does not subsequently inspect the first or third temporary as an explicit result. It does use the working selection value later.

No return value from F-da1b2f2cbf9f is consumed. Its state and memory effects, rather than its return value, determine subsequent behavior.

### 3. Secondary-chain update

After F-da1b2f2cbf9f returns normally, the function rereads the selection field at state offset +16. It does not use the original selection address or the working selection value as a substitute for this reread.

Using the newly read address, it:

1. Reads the current 32-bit secondary head at state offset +4.
2. Stores that value at offset +12 of the newly selected object.
3. Stores the newly selected object’s address into state offset +4.

The selected address used for both writes is the value captured immediately after the dependency returns. The function does not reread state offset +16 between those writes.

There is no zero check on this post-dependency address. Normal completion therefore requires that it support the four-byte write at offset +12. An initially nonzero selection does not guarantee this if F-da1b2f2cbf9f changes the state.

The old secondary head is not dereferenced by this function.

### 4. Primary-chain draining

After the secondary-chain update, the function repeatedly checks the primary head at state offset +0.

Each check reads the current head address and refreshes the prospective high-half return value from the working selection location. This refresh also occurs on the final check that observes a zero head.

For each nonzero head, the function performs the following observable operations:

1. Reads the entry’s successor from entry offset +0.
2. Writes that successor into state offset +0.
3. Reads the entry’s fields at offsets +8 and +4.
4. Calls F-ff1bdc376dcd with the offset +8 value as its first argument, the offset +4 value as its second argument, and a 32-bit zero as its third argument.
5. After that call returns, calls F-ff1bdc376dcd again with the entry address as its first argument, the 32-bit value one as its second argument, and a 32-bit zero as its third argument.
6. Rechecks the current state head rather than continuing from a privately retained successor.

The source establishes the positions of the two entry fields in the first dependency’s argument list. It does not establish the relative evaluation order of the reads at offsets +8 and +4.

The head advancement precedes both dependency calls. Thus, at entry to either call, the function has already removed the current entry from the primary head position.

The second call uses the saved entry address. This function does not reread the entry’s fields after the first call returns.

Dependency mutations can affect subsequent iterations. In particular, the next iteration follows whatever value is then present at state offset +0, not necessarily the successor written before the calls.

### 5. Completion

When a primary-head check observes zero, the function returns the original state address together with the working selection value sampled during that check.

The selected-object address used for secondary linking and the high-half return value can differ: they come from distinct storage locations after F-da1b2f2cbf9f returns.

There is no explicit loop bound, cycle detection, rollback, or recovery path.

## Side effects

### Direct writes

On the zero-selection path, the function performs no direct writes to caller-visible state.

On the nonzero-selection path, it directly:

- Writes the prior secondary-head value into the post-dependency selected object at offset +12.
- Replaces the state’s secondary head with that object’s address.
- Replaces the state’s primary head once per processed entry, before invoking either per-entry dependency call.

The function also writes temporary storage, including storage exposed to F-da1b2f2cbf9f.

### Ownership and lifetime

The two calls per primary entry suggest an intent to dispose of an entry-associated resource and then the entry itself. That is inferred intent, not an established ownership contract.

The evidence does not establish that F-ff1bdc376dcd:

- Frees either argument.
- Treats its second argument as a count, size, or ownership flag.
- Preserves state storage or global state.
- Returns normally.
- Leaves the entry allocated after its first invocation.

This function performs no direct allocation or deallocation. Any release of memory or resources depends on dependency behavior.

The temporary addresses passed to F-da1b2f2cbf9f refer to storage belonging to this invocation. Their validity beyond the invocation is not established. A dependency retaining those addresses requires a separate lifetime contract.

### Validity and aliasing requirements

Normal execution requires valid storage for every reached read and write, plus the preconditions of both dependencies.

For a nonzero primary entry, its successor and two argument fields must remain readable through argument evaluation for the first per-entry call.

No distinctness checks are present. If selected objects, entries, and state fields overlap, writes can alter values used later. In particular, the secondary-link writes occur before the first primary-head read and can therefore affect the traversal under aliasing.

No synchronization or concurrency guarantees are visible. Concurrent mutation and dependency-mediated mutation must not be treated as interchangeable: the source expressly permits state changes through dependency calls, but provides no established concurrent-access contract.

## Acceptance examples

These are conditional contract examples derived from static evidence, not executed tests.

### Zero selection with a nonempty primary chain

Given a readable state whose selection field is zero, regardless of the primary-head value:

- Neither dependency is called.
- The primary chain is not inspected or drained.
- No state write occurs.
- The high result half equals the second argument’s bit pattern.
- The low result half equals the original state address.

For example, a second argument with bit pattern `0xFFFFFFFF` produces that exact high half, without sign-extending it over the low half.

### Nonzero selection and an empty primary chain

Assume F-da1b2f2cbf9f returns normally, leaves a valid selected-object address in the state, and leaves the primary head zero after the secondary-link writes.

Then:

- F-da1b2f2cbf9f is called once.
- The current secondary head is stored into the selected object’s offset +12.
- The selected address becomes the state’s secondary head.
- F-ff1bdc376dcd is not called.
- The high result half is the working selection value at the terminating head check.

### Dependency produces different linking and return values

Assume F-da1b2f2cbf9f leaves one address in the state selection field and a different 32-bit value in the working selection location.

Then the address in the state selects the object linked into the secondary chain. The working value supplies the high result half, provided it is unchanged through the terminating check. The two values need not match.

### Two-entry primary chain with preserving dependencies

Assume the primary chain contains two valid entries followed by zero, the secondary-link writes do not overlap that chain, and both dependencies return normally without further relevant mutations.

Then:

- The first entry is unlinked before either of its two calls.
- Its field-based call precedes its address-based call.
- The second entry is processed in the same order.
- Four F-ff1bdc376dcd calls occur.
- The final primary head is zero.

### Dependency redirects traversal

Assume a per-entry dependency changes the state’s primary head to another valid entry.

The next check uses that replacement head. The function does not force traversal to continue at the previously read successor. Termination remains conditional on eventually observing a zero head.
