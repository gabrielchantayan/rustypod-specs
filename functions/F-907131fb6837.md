# F-907131fb6837

## Purpose

F-907131fb6837 performs an ordered sequence of indirect calls, derives word-sized values from their results, modifies memory through computed and absolute addresses, and finishes with an unresolved indirect transfer.

The available static evidence does not establish an application-level purpose. Descriptions such as allocator, formatter, initializer, serializer, or container operation would add unsupported semantics. Constants that coincide with character encodings are specified as numeric values, not as evidence of text output.

This contract distinguishes:

- **Established static evidence:** access widths, value relationships, and ordering visible in the supplied representation.
- **Inferred intent:** possible interpretations that are not acceptance requirements.
- **documented_only:** behavior that remains unresolved.

All acceptance examples are conditional obligations. No runtime tests have been performed.

### Widths and layouts

A byte is 8 bits, a halfword is 16 bits, and a word is 32 bits. Paired call results are represented as 64 bits with separately consumed low and high 32-bit halves.

Byte stores retain the low 8 bits. Unsigned byte reads yield values from 0 through 255. Halfword stores affect two bytes; word stores affect four. These widths are not interchangeable even when their numeric operands match.

Computed addresses are expressed using 32-bit quantities. A wider address model is not established.

## Behavior

### Indirect-call phase

An extensive straight-line indirect-call phase precedes the direct memory updates. No visible conditional branch selects among these calls.

The first target is derived by adding `0xFFE` to incoming continuation-related state and receives two zero arguments. Later targets are derived from execution-location-related values using the same displacement. A display without explicit arguments does not establish that a target has no implicit inputs or side effects.

Early paired results contribute low words shifted left by 8 and high words shifted left by 14. A subsequent four-argument call consumes a shifted low word, an unshifted high word, a shifted high word, and a differently shifted low word. Some transformed results remain live across intervening calls and are shifted again before reuse.

Later arguments include literal zeros, returned words, paired-result halves, extracted unsigned fields, duplicated transformed values, and additional register results whose conventions are unresolved.

Call order is part of the observable behavior. A call cannot be removed merely because its displayed result is unused: its target may modify memory, globals, devices, or execution state consumed later.

### Arithmetic and field extraction

The following unsigned relationships are established:

- Masking with `0xFFFFFF`, then shifting right by 8, extracts original bits 8–23: a 16-bit value.
- Masking with `0x3FFFF`, then shifting right by 11, extracts bits 11–17: a 7-bit value.
- Masking with `0x1FFFF`, then shifting right by 4, extracts bits 4–16: a 13-bit value.
- Masking with `0xFFFFFF`, then shifting right by 12, extracts bits 12–23: a 12-bit value.
- Shifting a word left by 8, masking with `0x7FFF`, then shifting right by 6 yields a multiple of four between 0 and 508.

Repeated transformations consume already transformed 32-bit values. They must not be interpreted as unbounded arithmetic. Under truncating 32-bit semantics, sufficiently large cumulative left shifts discard all original bits.

Several retained quantities are explicitly assigned zero. Subsequent shifts of those quantities remain zero within the displayed value flow; intervening calls alone do not establish replacement values.

Some shifts and multiplications operate on signed operands. Exact overflowing signed arithmetic is **documented_only** without the underlying instruction semantics. The final signed right shift also leaves unresolved how negative operands and large shift counts behave.

### Entry into direct memory mutation

The following descriptive roles identify values, not objects or source-level identifiers:

- **Packed base:** an earlier paired result’s low word shifted left by 25.
- **Scaled base:** an earlier returned word multiplied by `0x2000000`.
- **Selector:** the bounded multiple-of-four extraction described above.
- **Small base:** twice the selector.
- **Final pair:** the last paired result before direct stores begin.

The transition stores the packed base at offset 20 from the final pair’s high word. It then writes that high word’s low byte at packed-base offset 9, stores the scaled base at offset 84 from the final pair’s low word multiplied by 256, and overwrites packed-base offset 9 with the packed base’s low byte.

The next access ordering is significant:

- A zero word is stored at scaled-base offset 20.
- A byte is read from scaled-base offset 5.
- A zero word is stored at small-base offset 20.
- The captured byte is stored, zero-extended, at scaled-base offset 52.
- The word at scaled-base offset 20 is read back.

Under ordinary memory semantics, without external mutation, this read-back is zero. A potentially overlapping small-base store writes only zeros, and scaled-base offsets 20 and 52 designate disjoint word ranges. Ordinary aliasing among these intervening stores does not explain a nonzero result.

Device semantics or external mutation can invalidate that zero guarantee. The contract therefore distinguishes ordinary-memory reasoning from unconditional runtime guarantees.

After the read-back, another zero word is stored at small-base offset 20, followed by two byte stores at small-base offset 21 using the captured read-back word’s low byte.

### Linked and scaled updates

The next region mixes memory-loaded addresses, selector-derived addresses, and fixed globals.

It reads the byte at absolute address `0x05`, writes a byte to absolute address `0x01`, and uses the byte read at `0x05` as an address base. It updates byte fields at offsets 9, 13, 17, and 21 and word fields at offsets 20, 36, 52, 68, and 84.

Additional addresses are loaded from offsets 4, 100, and 116. Unsigned bytes read at offset 5 also serve as bases for word reads at offset 116. Such byte-derived addressing is not evidence of a bounded array or valid allocation.

The region includes repeated writes to identical destinations and repeated reads of apparently identical locations. Each read observes the location at its own access time. Equality with an earlier read is not guaranteed.

Scaling factors of two, four, and eight contribute both addresses and stored values. A word is written to absolute address `0x54`, and a byte is written to absolute address `0x15`. A subtraction of decimal 150 contributes to later scaled addresses; no bounds check or underflow guard is visible.

## Acceptance examples

These examples have not been executed.

### Extraction and widths

For an unsigned consumed word of `0x12ABCDEF`, masking with `0xFFFFFF` and shifting right by 8 yields `0xABCD`.

A byte-store operand of `0x12345678` stores `0x78`. A word store of `0x3A` affects four bytes and is not equivalent to its byte-width counterpart.

### Ordinary-memory zero read-back

If the transition region accesses ordinary memory without external mutation, the scaled-base offset-20 read-back is zero. An overlapping small-base zero store does not provide a counterexample.

A nonzero result requires conditions beyond those displayed ordinary stores, such as device behavior or external mutation.

### Global load before absolute store

If the store at `0x60` can affect the fixed global supplying the repeated-update base, the repeated updates still use the value captured before that store. Reloading afterward changes the contract.

### Final opening order

If the `0x3A` byte destination overlaps a later offset-20 or offset-4 capture, that capture observes the applicable intervening write. The payload-base offset-116 capture precedes the write and retains its earlier value.

### Separate reads of `0x67`

If successive reads of `0x67` yield `0x12`, `0x34`, and `0x56`, then `0x21` receives `0x12`, and the two subsequent secondary-base offset-9 stores receive `0x34` and `0x56`, respectively.

The offset-68 word read must occur before the first of these byte reads. Reusing the originally assigned byte fails this condition.

### Partial failure and retained arguments

If an access faults after an earlier store succeeds, restoration is not required.

If execution reaches the final target, its third displayed argument is the earlier offset-20 capture, not a reload of the final contents of that location.
