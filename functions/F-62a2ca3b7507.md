# F-62a2ca3b7507

## Purpose

F-62a2ca3b7507 conditionally refreshes two slots associated with a caller-supplied context.

For each slot, an enabled entry and a nonzero associated source address cause the function to:

- Copy six individual bytes from the source into entry-relative storage.
- Record the associated source address in a context field.
- Set a one-byte result using a classification byte and, conditionally, F-1354d5aae716.
- Store the signed maximum of two 32-bit source fields.

A disabled entry or zero source address instead clears the recorded address and one-byte result. It does not clear the stored maximum or the six destination bytes.

This is an established description of the supplied static evidence, not a claim about application-level meaning. Terms such as “slot,” “source,” and “classification” describe structural roles; their domain semantics are unknown.

## Interface

### Argument and return

The function accepts one address-valued argument identifying a context. The supplied representation uses a 32-bit integer for that argument and for stored addresses. The contract below uses that 32-bit address model.

The function has no explicit return value. It reports no status, error code, or failure detail.

The context argument itself is not checked for zero or validity. Its field at offset `0x40` is accessed unconditionally.

## Behavior

### Initial gate and processing order

The function first reads the 32-bit entry-storage base field at context offset `0x40`.

If that field is zero, it returns immediately. It does not clear either slot, read either source-address field, or call F-1354d5aae716.

If the field is nonzero, the function processes slot 0 and then slot 1, with no additional slots.

The initial nonzero value is only a gate. The function reloads the entry-storage base when beginning slot processing and during later destination accesses. It does not preserve one base address for the entire operation.

Consequently, if a dependency or overlapping storage changes the base field, later accesses can use a different base. A later zero base is not handled by returning through the initial gate.

### Slot eligibility

For each slot, the function obtains the slot base using the current entry-storage base and the slot’s `0x24` stride offset. It reads the enabled byte at slot-relative offset `0x20`.

If that byte is zero, the function takes the inactive path without reading that slot’s source-address field for eligibility.

If that byte is nonzero, the function reads the slot’s 32-bit source-address field from the context. The active path is taken only if that address is also nonzero.

Any nonzero enabled-byte value qualifies. Eligibility is not restricted to the byte value `1`.

Eligibility is determined once per slot. Subsequent changes to the enabled byte do not cause the slot to be reclassified during the same iteration.

### Inactive path

A disabled entry or zero source address produces two explicit writes, in this order:

1. Zero the slot’s 32-bit recorded-source field.
2. Zero the slot’s one-byte result flag.

There is no explicit write to the slot’s stored maximum or to its six destination bytes on this path.

The preservation statement concerns direct writes. If context and entry storage overlap, clearing one of these context fields may also affect another logical field through aliasing.

### Active-path byte transfers

The function performs six byte transfers in the following order:

| Transfer order | Source offset | Slot-relative destination offset |
|---:|---:|---:|
| 1 | `0x107` | `0x3F` |
| 2 | `0x108` | `0x40` |
| 3 | `0x104` | `0x3C` |
| 4 | `0x105` | `0x3D` |
| 5 | `0x106` | `0x3E` |
| 6 | `0x0C` | `0x41` |

These are individual 8-bit transfers, not a single contiguous block copy.

The first transfer uses the source address already obtained for eligibility and the slot base already obtained for the enabled-byte check.

Each later transfer rereads both the entry-storage base and the slot’s source-address field. Thus, earlier writes can affect later transfers if the relevant storage overlaps. The function does not snapshot all six source bytes before writing any destination byte.

The static evidence establishes the ordering of the six transfers. It does not establish a portable ordering between independent address-field reads within a single transfer expression.

### Recording and classification

After the byte transfers, the function reads the global classification displacement.

It then rereads the slot’s source-address field and writes that 32-bit value into the recorded-source field.

Next, it reads one classification byte at the address formed from:

- The previously read global displacement.
- Another read of the slot’s current source address.

The recorded address and the address used for classification are therefore not guaranteed to be identical under aliasing or external mutation.

If the classification byte equals `1` or `2`, the function calls F-1354d5aae716 once, with no explicit arguments shown. A nonzero 32-bit result from that dependency selects a result flag of `1`; a zero result selects `0`.

For every other classification byte, the dependency is not called and the result flag is `0`.

The selected flag is written as one byte to context offset `0x80` or `0x81`, according to the slot. A qualifying classification does not itself guarantee a flag of `1`.

### Signed maximum

After writing the result flag, the function reads:

1. A signed 32-bit value at offset `0x04` from the slot’s current source.
2. A signed 32-bit value at offset `0x08` from the slot’s current source.

The source-address field is reread for each access. These reads occur after any dependency call and after the result-flag write.

The function stores the greater value in the slot’s 32-bit maximum field. The comparison is signed. If the two values are equal, the common value is stored.

There is no addition, subtraction, saturation, or unsigned comparison involved in selecting this maximum.

After slot 0 completes, slot 1 begins. Slot 1 can observe changes made during slot 0, including changes made by F-1354d5aae716.

## Side effects

The function’s explicit writes are limited to:

- Up to six destination bytes per active slot.
- One recorded-source field per processed slot.
- One result flag per processed slot.
- One stored maximum per active slot.

The function does not explicitly allocate, release, retain, or destroy storage. Copying a source address into a recorded-source field does not establish ownership transfer or reference-count behavior.

F-1354d5aae716 may have additional effects. The evidence does not establish that it preserves context fields, source objects, entry storage, globals, or memory lifetime.

The operation is not transactional. Byte transfers and the recorded-source write precede the dependency call. The result-flag write precedes the maximum reads. If execution fails during a later access or inside the dependency, earlier writes may already have occurred. No rollback is visible.

No concurrency guarantees are established. Repeated reads are behaviorally significant, but they do not establish atomicity, volatility, locking, or support for unsynchronized concurrent mutation.

## Acceptance examples

These examples are conditional consequences of the static evidence, not results of executed tests. Unless stated otherwise, assume valid, suitably aligned, nonoverlapping storage and no mutation except the function’s described writes.

### Zero entry-storage base

Given a context whose field at `0x40` is zero:

- The function returns without processing either slot.
- Existing recorded-source fields, result flags, and maxima remain unchanged.
- F-1354d5aae716 is not called.

### Disabled slot preserves its previous maximum

Given a nonzero entry-storage base and a slot whose enabled byte is zero:

- Its recorded-source field becomes zero.
- Its result flag becomes zero.
- Its stored maximum and six destination bytes retain their previous values.
- Its source-address field need not be valid as a source-object address, because this path does not dereference it.

The context and enabled-byte access must still be valid.

### Enabled slot with a zero source address

Given a nonzero enabled byte and a zero source address:

- The inactive-path writes occur.
- No source-byte copy, classification read, maximum read, or dependency call occurs for that slot.
- The enabled byte itself is not cleared.

### Active copy with a nonqualifying classification

Suppose source bytes at `0x104` through `0x108` are respectively `0x11`, `0x22`, `0x33`, `0x44`, and `0x55`, and the byte at `0x0C` is `0x66`.

For an enabled slot with a stable nonzero source address:

- Destination offsets `0x3C` through `0x41` become `0x11`, `0x22`, `0x33`, `0x44`, `0x55`, and `0x66`.
- The actual write order is `0x3F`, `0x40`, `0x3C`, `0x3D`, `0x3E`, then `0x41`.
- The recorded-source field receives the source address.
- If the classification byte is `3`, the result flag becomes zero and the dependency is not called.

### Signed comparison

For an active slot whose source values at `0x04` and `0x08` are `-7` and `-2`, the stored maximum becomes `-2`.

For values `-1` and `1`, it becomes `1`. Treating the fields as unsigned would not satisfy this behavior.

### Qualifying classification

For classification byte `1` or `2`:

- A dependency result of zero produces flag `0`.
- Any nonzero dependency result, including a negative 32-bit result, produces flag `1`.

If the dependency changes the source-address field and leaves it pointing to valid storage, the subsequent maximum reads use the newly observed address rather than an assumed pre-call snapshot. If it invalidates required storage, normal completion is not guaranteed.
