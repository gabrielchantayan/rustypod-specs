# F-d565fa1d4719

## Purpose

F-d565fa1d4719 coordinates flag updates, mutable argument staging, context acquisition, status-dependent arithmetic, two downstream call groups, and a 32-bit return value.

The static evidence establishes individual actions and their internal ordering. It does not establish a complete execution path: action selection depends on unavailable global values. Actions may be skipped, repeated, or reached before their apparent prerequisites. Termination is not established.

An initialization or resource-processing purpose is inferred from the call patterns, not established as application semantics. In particular, the two downstream groups are not identified as success and failure paths.

## Behavior

### Entry and dispatch

Entry captures a global flag base and a global initial dispatch state, saves the four inputs, and initializes working state and return storage to zero. The automatic buffer is not visibly initialized.

At each dispatch iteration, three globals are read in this order:

1. An auxiliary global later used by the `0x400` write action and one comparison action.
2. An auxiliary global later used by the `0x100` write and working-state preparation actions.
3. An auxiliary global later used by the `0x200` write and default comparison actions.

Call these the first, second, and third iteration snapshots. The current staged fourth-position value is also captured at iteration entry.

The selector combines the dispatch state with another global. Recognized selectors choose the actions described below. An unrecognized selector executes the default comparison action; it does not inherently return or reject the request. Several recognized actions only update the dispatch state.

Subsequent states depend on other globals, flag predicates, marker values, or arithmetic sign selection. Missing global contents prevent establishing the initial action, full transitions, reachability, repetition, or termination. Descriptions below are conditional on the corresponding action executing.

### Mutable state and input provenance

The following conceptual state names describe behavior, not source identifiers:

- **Arithmetic staging:** initially zero; input staging writes the product involving argument 2. Both status-arithmetic actions overwrite it with an arithmetic result.
- **Fourth-position staging:** initially zero; input staging writes argument 4. Both comparison actions overwrite it with a global snapshot.
- **Transferred arithmetic:** initially zero; a transfer action copies the current arithmetic staging.
- **Transferred fourth-position value:** initially zero; that transfer action copies the current fourth-position staging.
- **Working word:** initially zero; used by a status-producing call and the return-product action.

Thus, transferred arithmetic is not invariantly derived from argument 2, and the transferred fourth-position value is not invariantly argument 4. Their provenance depends on the last staging write before transfer. Repeating a transfer can replace previously input-derived values with arithmetic results or global snapshots.

The input-staging action sets two comparison markers to one and zero, retains argument 1 as a payload and argument 3 as third-position staging, tests flag `0x80`, computes argument 2 times a global into arithmetic staging, and places argument 4 into fourth-position staging.

The transfer action copies third-position staging, independently reads a global into base-related staging, separately reads that same global source to compute its value plus 128, and copies the two mutable staging words into their transferred slots.

A further preparation action:

- Sets the working word to another global multiplier times transferred arithmetic.
- Copies the base-related staging into the comparison operand.
- Saves the transferred third-position value in auxiliary storage.
- Retains the second iteration snapshot as an auxiliary argument.
- Copies the current offset-related staging into another context argument.

These actions do not prove that input staging occurred first.
