# F-c839d081f221

## Purpose

F-c839d081f221 rewrites an indexed control word according to a quantity extracted from that word. If the quantity is nonzero, it calculates a value using a context input and an effective stride, then combines that value with the quantity and a forced flag bit. A nonzero adjustment request additionally enables a subtractive update through a separate external base.

If the extracted quantity is zero, the function writes a full zero control word and performs none of the stride, context-input, or adjustment accesses.

The index-zero case has special stride and prior-value rules. It is not equivalent to substituting zero into the nonzero-index rules.

These operations are established by the supplied static representation. Domain interpretations such as position, length, channel, or completion status are not established.

## Interface

The function accepts three integer-shaped arguments and has no explicit return value.

| Argument | Meaning |
|---|---|
| Context address | Address used to locate the context input on the nonzero-quantity branch. |
| Index | Selects an offset within each externally based region and within the context; also selects the index-zero special case. |
| Adjustment request | Zero disables adjustment. Any nonzero value enables it when the extracted quantity is nonzero. |

The contract uses the 32-bit integer model indicated by the supplied representation: selected words are four bytes, unsigned data calculations retain 32 bits, and signed context and adjustment inputs contribute their 32-bit patterns to unsigned arithmetic. Exact ABI details and machine address width are not independently established.

### Memory roles and address expressions

The function refers to three externally supplied base values:

- **Control base:** used separately for the initial control read and the subsequent control write.
- **Stride base:** used for the stride read on the nonzero-quantity branch.
- **Adjustment base:** used separately in the adjustment destination expression and adjustment input expression.

The context address comes from the first argument, not an external base.

| Access role | Address expression at that use |
|---|---|
| Control read | Control base evaluated for the read, plus Index × 32 bytes |
| Control write | Control base evaluated for the write, plus Index × 32 bytes |
| Stride read | Stride base evaluated for the read, plus Index × 32 bytes |
| Adjustment read | Adjustment base evaluated for the input expression, plus Index × 32 bytes |
| Adjustment write | Adjustment base evaluated for the destination expression, plus Index × 32 bytes |
| Context input read | Context address + Index × 4 bytes + 56 bytes |

Each selected-word access is four bytes. The 32-byte spacing does not establish the layout or purpose of intervening storage.

These expressions do **not** establish that the external bases are captured once on entry. Referring to an external base at multiple expression sites also does not establish a corresponding number of physical loads.

### Preconditions

For the ordinary arithmetic contract, every reached address calculation must be valid, and every reached selected-word access must have the required readability or writability.

- Both branches require a readable control-read target and a writable control-write target.
- A nonzero quantity additionally requires a readable stride target and context input.
- A nonzero quantity with adjustment enabled additionally requires a readable adjustment-input target and a writable adjustment-destination target.
- The zero-quantity branch does not access the stride, context input, or adjustment targets.

Storage supplying the external base values must also be available as required by their evaluations. This requirement is separate from accessibility of the selected words.

For a **fixed-address interpretation**, each external base must have the same effective value at all relevant evaluations during the invocation. In particular, selected-word writes must not change storage supplying a base that will be evaluated subsequently. Under this stability precondition, the control read and write address the same word, and the adjustment read and write address the same word.

No bounds checks, index validation, pointer validation, or explicit alignment handling are shown. Negative indices are not rejected, but are valid only where their address calculations and resulting accesses are valid. ## Behavior

### Data arithmetic and extraction

Bit zero is the least significant bit of a 32-bit word. Unsigned right shifts are logical.

Define:

- **Original control:** the value obtained by the initial control read.
- **Quantity:** the extracted ten-bit quantity.
- **Base input:** the 32-bit value obtained from the context input.
- **Computed value:** the result of the stride-and-base calculation.
- **Prior component:** selected low bits of the original control, used only for the optional adjustment result.

The extraction is:

**Quantity = (Original control >> 19) AND 0x3FF**

The possible values are 0 through 1023. The wider mask in the supplied representation has this effective result after the shift: original bits 19 through 28 contribute, while original bits 29 through 31 do not.

Data addition, subtraction, and multiplication below retain the low 32 bits. This rule is separate from address-expression validity.

### Initial read and zero-quantity branch

The function evaluates the control-read address expression and reads the original control.

If the quantity is zero, it evaluates the control-write address expression and writes a full four-byte zero, then returns.

This clears all bits at the write destination. It is not a masked field update.

There is no stride read, context-input read, or adjustment access on this branch, even if the adjustment request is nonzero. The control base is nevertheless referenced again for the write. Describing this as clearing the originally read word requires the fixed-address precondition.

### Nonzero-quantity calculation

For a quantity from 1 through 1023, the function next evaluates the stride address expression and reads the stride word.

The stride read occurs even when the index is zero and the loaded value will not affect the result.

| Index condition | Effective stride |
|---|---|
| Index equals zero | 64 |
| Index is nonzero | Loaded stride word AND 0x7FF |

For a nonzero index, the effective stride is therefore between 0 and 2047.

The function reads the context input and calculates:

**Computed value = Base input + Effective stride × (Quantity − 1), modulo 2³²**

The quantity is nonzero on this branch, so Quantity − 1 ranges from 0 through 1022.

The product alone fits within 32 bits:

- Nonzero index: maximum 2047 × 1022 = 2,092,034.
- Zero index: maximum 64 × 1022 = 65,408.

Adding the base input can wrap. A context input interpreted as negative by the signed read contributes its corresponding 32-bit pattern to this unsigned calculation.

The prior component is:

| Index condition | Prior component |
|---|---|
| Index equals zero | Original control AND 0x7F |
| Index is nonzero | Original control AND 0x7FFFF |

This component derives from the saved original control, not a later control read. In the index-zero case, the seven-bit reduction occurs after the control write in the supplied sequence; it is a local calculation, not another memory access.

### Control replacement

The function evaluates the control-write address expression and writes:

**Replacement control = Computed value OR (Quantity << 19) OR 0x20000000**

This combines values by bitwise OR. It does not first restrict the computed value to a payload field.

Consequently:

- Bit 29 is always set.
- Set bits from the shifted quantity remain set.
- Computed-value bits can set additional positions within the quantity field.
- Computed-value bits 30 and 31 are retained.
- The computed value is not restricted to 19 bits, or to seven bits for index zero.

Extracting the quantity field from the replacement therefore need not recover the original quantity.

The destination uses the control base as evaluated for this write, rather than an explicitly retained address from the initial read.

### Optional adjustment

After the control write, an adjustment request of zero causes return without evaluating the adjustment address expressions or accessing their selected words.

For any nonzero request, the function obtains an adjustment input through one adjustment-base expression and writes through a separate destination expression. The written value is:

**Adjustment output = Read adjustment value − (Computed value − Prior component), modulo 2³²**

Equivalently:

**Adjustment output = Read adjustment value + Prior component − Computed value, modulo 2³²**

The displacement uses the computed value before quantity and flag bits are ORed into the control replacement.

The destination-address expression and the right-hand-side expressions have no established relative evaluation order in the supplied representation. In particular, the adjustment destination address may be evaluated before or after evaluation of the adjustment input address and its read. The adjustment input must be obtained before the resulting value is stored, but that does not determine when the destination base is evaluated.

Under stable adjustment-base values, this is a read-modify-write of one selected word. Without that precondition, the input and output addresses are not guaranteed to coincide.

The magnitude and sign of a nonzero adjustment request do not otherwise affect the calculation.

## Side effects

### Selected-word access sequence

The following table describes the selected data operations in the static representation. It does not count base-value loads or specify physical memory transactions.

| Branch | Selected-word operations |
|---|---|
| Zero quantity | Read control; write zero through the control-write expression |
| Nonzero quantity, adjustment disabled | Read control; read stride; read context input; write replacement control |
| Nonzero quantity, adjustment enabled | Read control; read stride; read context input; write replacement control; read adjustment input; write adjustment output |

External-base evaluation is a separate concern:

1. The initial control read uses its own control-base expression.
2. The nonzero branch uses a stride-base expression.
3. Either branch subsequently uses another control-base expression for its write.
4. Enabled adjustment uses two adjustment-base expressions, without an established relative evaluation order between the destination expression and the right-hand-side expressions.

The control write precedes the adjustment assignment, including its base evaluations.

### Aliasing and base-storage overlap

Under stable bases, if the adjustment address equals the control-write address, the adjustment read observes the replacement control just written, assuming ordinary sequential storage without intervening external changes. The adjustment write then replaces that packed value.

Likewise, a stride or context input aliasing the control target is read before the control replacement is written.

These fixed-address conclusions do not extend automatically to overlap with **storage supplying an external base**. For example, a control write may overwrite storage supplying the adjustment base. The later adjustment expressions can then use the changed base rather than its entry value. This is a synchronous consequence of the function’s own write; asynchronous modification is not required.

An adjustment write may itself alter base-supplying storage if its destination overlaps that storage. There is no subsequent selected-word operation shown after that write, but the changed storage remains externally visible.

The representation does not justify physical load counts, bus ordering, atomicity, or concurrent-memory guarantees.

### Ownership and failures

No allocation, deallocation, ownership transfer, or retention operation is shown. The context argument is used for reading; aliasing may nevertheless allow writes through other roles to affect the same storage.

No explicit error return, validation failure path, rollback, synchronization, or recovery mechanism is present. A failure during adjustment occurs after the control write in the represented sequence; no undo operation is shown. Actual fault behavior is not established.

## Acceptance examples

These are conditional deductions from static evidence, not executed tests. Except for the explicit base-storage-overlap example, assume valid address arithmetic, valid accesses, stable external bases, ordinary sequential memory, and no external changes. Regions are disjoint unless stated otherwise.

### Zero quantity clears the control word

Given original control **0xE0000005** and a nonzero adjustment request, the quantity is zero.

The control word becomes zero. No stride, context-input, or adjustment word is accessed. Both the initial read and the zero write have their own control-base expression; stability makes their selected address equal.

### Nonzero index masks the stride

Given:

- Index: 2.
- Original control: **0x00180014**.
- Stride word: **0xFFFFF809**.
- Context input: 100.
- Adjustment disabled.

The quantity is 3, the prior component is 20, and the effective stride is 9.

The computed value is 100 + 9 × 2 = 118. The control word becomes **0x20180076**. No adjustment address expression is evaluated.

### Adjustment subtracts the displacement

Using the preceding inputs, but enabling adjustment with an initial adjustment value of 1000:

- Displacement: 118 − 20 = 98.
- Control replacement: **0x20180076**.
- Adjustment output: 902.

The control write precedes the adjustment operation.

### Index zero uses special rules

Given:

- Index: zero.
- Original control: **0x00100185**.
- Context input: 1000.
- Adjustment input: 2000.
- Adjustment enabled.

The quantity is 2. The stride word is read, but the effective stride is 64 regardless of its value.

The computed value is 1064. The prior component is 5, not 389.

The control replacement is **0x20100428**. The adjustment output is 2000 − (1064 − 5) = **941**.

### Computed bits can enlarge the packed quantity

Given a nonzero index, quantity 1, context input **0x00100000**, and adjustment disabled, the stride word is still read. Its contribution is zero because Quantity − 1 is zero.

The replacement is **0x20180000**. Its extracted quantity is 3, not 1.

### Base-input addition can wrap

Given a nonzero index, original control **0x00100000**, effective stride 1, and context input **0xFFFFFFFF**, the quantity is 2 and the computed value wraps to zero.

With adjustment disabled, the replacement is **0x20100000**.

### Stable control and adjustment aliases observe the replacement

Given:

- Stable bases selecting the same control and adjustment address.
- That shared word does not overlap base-supplying storage.
- Nonzero index.
- Original control: **0x00080000**.
- Context input: 10.
- Adjustment enabled.

The quantity is 1 and the prior component is zero. The first write is **0x2008000A**. The adjustment reads that replacement and subtracts 10, leaving **0x20080000**.

### A control write can redirect later adjustment

Suppose the control-write destination overlaps storage supplying the adjustment base, and the replacement changes that base from an old value to a new value.

If subsequent base evaluations observe the new value and all resulting accesses are valid, the adjustment expressions use the new base. They are not required to use the entry base.

If both adjustment-base evaluations observe that same new value, the adjustment read and write select the same newly addressed word. If they observe different values, a same-address read-modify-write cannot be asserted. The destination-versus-input evaluation order remains unspecified.
