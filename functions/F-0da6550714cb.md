# F-0da6550714cb

## Purpose

F-0da6550714cb selects between two behaviors using an unsigned 32-bit selector:

- For selectors 0 through 22, it obtains an initial object from F-9d0ecc5f6adf and traverses a linked sequence of objects. Each visited object receives an indirect callback with a shared context value, a selector-specific value, and a pointer to local result storage. Traversal stops when a callback returns nonzero or the sequence ends. The function returns the first word of the result storage.
- For selectors 23 through 4,294,967,295, it returns a value selected from global state without obtaining or traversing objects.

The callback’s return value controls traversal; it is not the function’s returned value. The callback-writable result storage supplies the return value on the traversal path.

This contract describes static evidence from the supplied representation. It does not establish the application-level meaning of the selector, objects, context, table values, or returned integer.

## Interface

### Inputs

The function has two arguments:

1. **Opaque first argument:** a 32-bit value. The supplied body does not read it, forward it to a dependency, or use it to choose a path.
2. **Selector:** an unsigned 32-bit integer. The branch comparison is unsigned and uses the exclusive upper bound 23.

Consequently, a selector with the bit pattern `0xFFFFFFFF` takes the global-value path. It is not treated as a negative index into the selector table.

### Output

The function returns a 32-bit integer:

- On the traversal path, the returned value is the first 32-bit word of local result storage.
- On the global-value path, the returned value comes from a global structure field or a fallback global value.

No restriction to Boolean values, nonnegative values, or a particular error-code range is established. A nonzero callback return does not imply that the function itself returns nonzero.

## Behavior

### Path selection

The first decision is whether the unsigned selector is less than 23.

The first argument has no visible effect on either path.

### Selectors 0 through 22

#### Initial acquisition and argument capture

The function first calls F-9d0ecc5f6adf with no explicit arguments. Its returned value is interpreted as an object pointer, which may be null.

After that call returns, the function:

1. Loads a shared 32-bit context value from global state.
2. Loads one 32-bit value from the selector table at the selected eight-byte stride.
3. Initializes the first word of local result storage to zero.

This order matters. Changes made by F-9d0ecc5f6adf to the subsequently read global state can affect the captured context or table value. Their values are not established before that dependency runs.

The context and selector-specific value are captured once. Subsequent callbacks receive those captured values; the function does not reload them for each object.

A null initial object does not bypass the context or table load. Both loads and result initialization occur before the null check that prevents callback execution.

#### Callback invocation

For each non-null current object, the function obtains an indirect callback through the object’s dispatch-table pointer, using the dispatch-table entry at byte offset 100.

The callback receives four arguments, in this order:

1. The current object pointer.
2. The captured 32-bit context value.
3. The captured 32-bit selector-specific value.
4. A pointer to the first word of local result storage.

The supplied representation treats the callback return as a 32-bit integer and compares it with zero.

The first result word is initialized once, before traversal. It is not reset between callbacks. A later callback can therefore observe a value left by an earlier callback, subject to the callback’s own behavior.

The local storage contains two 32-bit words in the supplied representation, but only the first is explicitly initialized or returned. The second word’s initial value is not established. No assertion that the callback may safely use both words follows merely from their presence in local storage.

#### Continuation and stopping

After each callback returns:

- **Nonzero callback return:** traversal stops immediately. The current object’s next pointer is not read by this function.
- **Zero callback return:** the function reads the next-object pointer at offset 20 of the current object and makes that pointer current.
- **Null current object:** traversal stops without another callback.

The next pointer is read after the callback, not before it. A callback that changes that link can change the remainder of the traversal. A callback that invalidates the current object and then returns zero leaves the subsequent link read without an established validity guarantee.

The function does not cache the next pointer in advance, detect cycles, or impose an iteration limit. A cyclic sequence can prevent completion if every callback returns zero and leaves traversal within the cycle.

#### Returned result

After traversal stops, the function returns the first result word as it then exists.

Consequences include:

- A null initial object produces zero, assuming the preceding reads complete normally.
- A callback can write a nonzero result and return zero; traversal continues while retaining that result until another write changes it.
- A callback can return nonzero without writing the result; the function then returns the existing result, potentially zero.
- Exhausting the sequence does not force the result back to zero.
- The callback return is used only for its zero/nonzero distinction.

### Selectors 23 and above

This path does not call F-9d0ecc5f6adf, read the selector table, or invoke traversal callbacks.

The supplied representation performs two reads of the 32-bit field at offset 4 from a global structure base:

1. It reads the field and retains that first value as a candidate result.
2. It reads the field again and compares this second value with zero.

If the second read is zero, it reads and returns the fallback global value. Otherwise, it returns the retained first value.

With stable global state, this amounts to returning the structure field when it is nonzero, or the fallback when the field is zero.

The two reads must not be silently collapsed into a single-read guarantee in this contract. If differing reads are observable in a supported execution environment, the first read supplies the candidate while the second controls fallback selection. The supplied material does not establish concurrency, synchronization, volatile-access semantics, or whether two distinct physical reads occur in the executable.

## Acceptance examples

These are conditional acceptance scenarios derived from static evidence, not executed tests.

1. **Null initial object:** Given selector 0 and a null return from F-9d0ecc5f6adf, the context and selected table value are still read. No callback runs, and the function returns zero.

2. **Immediate stop without a result write:** Given one valid initial object whose callback returns 1 without modifying the result word, the function returns zero. It does not read that object’s next pointer.

3. **Immediate stop with an independent result:** Given a callback that writes −7 to the first result word and returns 4, the function returns −7. The value 4 is not forwarded as the function result.

4. **Result retained across continuation:** Given a first callback that writes 12 and returns zero, followed by a second callback that leaves the result unchanged and returns nonzero, the function returns 12.

5. **Sequence exhaustion after a write:** Given a callback that writes 12, returns zero, and leaves its next pointer null, the function returns 12 after reading that null link.

6. **Post-callback link selection:** Given a callback that replaces its object’s next pointer and returns zero, traversal follows the replacement link rather than a pre-callback snapshot.

7. **Captured arguments remain captured:** Given a callback that changes the shared context global or the selected table entry, later callbacks still receive the values captured before traversal. This does not constrain other effects of those global changes.

8. **Upper in-range selector:** Selector 22 loads the table word beginning at byte offset 176 and takes the traversal path.

9. **First out-of-range selector:** Selector 23 takes the global-value path. With a stable structure field of 8, it returns 8; with a stable field of zero and fallback −2, it returns −2.

10. **Maximum unsigned selector:** Selector 4,294,967,295 takes the global-value path and performs no selector-table indexing.

11. **Differing global-field reads:** If the execution environment permits the first field read to yield 6 and the second to yield zero, fallback selection follows the second read. If the first yields zero and the second yields 6, the retained candidate returned is zero.
