# F-9d77872f5a93

## Purpose

F-9d77872f5a93 marks a caller-provided record with discriminator 3, obtains a destination address through two dependencies, installs that address in the record, and conditionally transfers source data to the destination.

The apparent intent is to construct a record referring to separately stored, zero-terminated byte data. That interpretation is **inferred intent**, not an unconditional guarantee. The supplied representation does not establish the dependencies’ contracts, destination capacity, normal detection constant, target byte order, or all arithmetic semantics needed for conventional string copying.

**Established static evidence:** the function has no explicit return value, status result, or separate error-reporting channel. A null destination suppresses copying but does not undo the discriminator or pointer-field writes.

## Behavior

### Source selection and dependency boundary

When the source argument is null, the default-source address is captured before the discriminator write. Otherwise, the supplied address is selected without reading the default-source slot.

The discriminator write precedes the call to F-1cb585febd84. Consequently, if the record aliases source storage, that write can change what the dependency observes.

F-1cb585febd84 receives the selected source address once. Its signed 32-bit result is increased by one, and that expression is supplied to F-fab3799b3190. There is no special treatment for a negative result and no explicit overflow check.

For a result below the signed 32-bit maximum, the increment is representable in the shown type. At the maximum, the increment exceeds that type’s range. The supplied representation does not establish a defined source-language result for this case; wraparound must not be assumed. The second dependency’s parameter type and treatment of negative or otherwise unsuitable arguments are unknown.

After F-fab3799b3190 returns normally, the destination address is installed in the record. The function then captures the detection global as a signed 32-bit value. Both dependency calls and the pointer-field write therefore precede that capture.

Neither dependency is established to preserve the source, record, globals, or object lifetimes. In particular, the value captured from the detection global can reflect dependency side effects or an aliasing pointer-field write.

### Null destination

A zero low half of the second dependency’s result produces a null destination. The function still installs that null address and reads the detection global, but performs no direct copying reads or destination writes.

The aligned detection arithmetic is not evaluated on this branch. A negative or otherwise problematic detection value therefore does not, by itself, cause a shift-related problem when the destination is null.

A nonzero upper half of the dependency result does not enable copying. There is no retry, alternate discriminator, rollback, or explicit failure status.

### Transfer-path selection

For a non-null destination, both source and destination must have their low two address bits clear to select the aligned path. Any other combination selects the alternate path.

This distinction is only a branch condition. It does not establish object validity, sufficient capacity, non-overlap, or support for the represented memory accesses.

### Aligned transfer and detection

The aligned path examines source data in complete 32-bit unsigned words. Each source-word read precedes detection and any corresponding destination write.

The detection rule combines three 32-bit quantities:

- The source word minus the captured detection value, after conversion of that value to unsigned form.
- The bitwise complement of the source word.
- The captured detection value shifted left by seven positions.

A word is selected for terminal byte emission when these three quantities share at least one set bit. Otherwise, the entire word is transferred, and the next word is examined four bytes farther along both buffers.

The arithmetic distinctions are material:

- The subtraction is unsigned and therefore modulo \(2^{32}\).
- The left shift is applied to the signed detection value before its result participates in the surrounding unsigned operations.
- The bitwise combination does not short-circuit. An otherwise zero component does not prevent evaluation of the shift.

Under signed-shift semantics requiring a nonnegative operand and a signed-representable mathematical result, the shift is defined only for detection values from 0 through `0x00ffffff`, inclusive. Negative values and larger positive values do not acquire defined truncating behavior merely because the surrounding expression uses unsigned quantities.

The exact language or machine semantics governing that shift are not supplied. Outcomes requiring truncation outside the stated signed-safe range remain **documented_only** unless independently established.

The detector is not independently proven to recognize zero bytes for an arbitrary captured value. In particular, the function contains no validation that the global holds a suitable detection constant.

### Terminal byte emission

Once an aligned word is selected, the remaining output is derived from that already loaded word. There are no further source reads in this phase.

Subject to the target’s character-conversion behavior, emission proceeds from the least-significant byte toward the most-significant byte. Each emitted byte advances the destination by one. A zero byte is included in the output and ends emission. After a nonzero byte, the remaining unsigned word is shifted right by eight positions before the next byte is obtained.

This phase is not restricted to four output bytes. If the selected word has four nonzero bytes, those bytes are emitted, followed by a fifth byte of zero after the remaining word has become zero. This outcome is reachable for some detection values; it must not be excluded merely because ordinary zero-byte detection would normally select a word containing a terminator.

The record’s destination field retains the original installed address. The function does not replace it with the final transfer position.

### Alternate transfer

The alternate path processes up to two output bytes per iteration, but it is not established as a byte-read-only implementation.

Its first source access is represented as a 32-bit unsigned dereference followed by conversion to a character. That character is written to the destination. A zero character ends the transfer immediately after this write.

If the first character is nonzero, the next source byte is read and written to the next destination byte. A zero second character ends the transfer; otherwise, processing continues two bytes farther along both buffers.

The first destination write precedes the second source-byte read. This ordering can affect results for overlapping storage.

Under little-endian low-byte extraction, the first converted character corresponds to the byte at the current source address. Neither that byte order nor all character-narrowing behavior is supplied as an unconditional target guarantee.

The represented first access can occur at an address that is not four-byte aligned. Whether it corresponds to an actual word-sized machine access, and whether such an access is supported, remain unresolved. The detection value is not used by this path after capture.

## Side effects

1. Conditional default-source lookup.
2. Discriminator write.
3. Call to F-1cb585febd84.
4. Call to F-fab3799b3190 with the incremented result.
5. Destination-pointer installation.

These are ordering claims about the supplied representation, not synchronization guarantees or a hardware memory-ordering specification.

Within aligned copying, each full-word source read precedes its detection and possible full-word destination write. Terminal emission uses only the captured word. Within alternate copying, the first output write precedes the optional second source read.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. They assume valid record storage and normal dependency returns unless a case states otherwise.

### Null destination despite a negative detector

Suppose the second dependency returns a result whose low 32 bits are zero and whose upper half is nonzero. Suppose the detection global contains a negative value.

The record receives a null destination, and the detection global is read. There are no direct copy reads or writes and no evaluation of the signed detection shift. The upper result half does not change this outcome.

### Default source remains selected

For a null source argument, the default-source address is captured before the discriminator write and passed to F-1cb585febd84.

If a dependency later changes the default-source slot, the function does not perform a new lookup. Copying, if reached, still uses the originally selected address. Changes to the storage at that address can nevertheless affect the copied data.

### Conventional aligned terminator under additional semantics

Assume aligned buffers, little-endian byte order, conventional low-byte character conversion, sufficient storage, and a detection value of `0x01010101`. Also assume independently established 32-bit truncating semantics for the left shift.

For source bytes “A”, “B”, “C”, zero, terminal emission writes those four bytes in that order.

The additional shift premise is essential. The detection value exceeds the signed-safe range described above, so the supplied signed representation alone does not establish this outcome.

### Terminal emission without a source zero

Assume aligned buffers, little-endian interpretation, adequate readable and writable storage, and detection value 3. Let the first source word be `0x01010201`, representing bytes 1, 2, 1, 1.

The detector selects that word even though all four bytes are nonzero. Terminal emission writes bytes 1, 2, 1, 1, then zero. It performs no additional source read and no full-word destination write for this word.

This demonstrates why neither “copies through the first source zero” nor “emits at most four terminal bytes” is an unconditional contract.

### Alternate-path early termination

Assume the alternate path, little-endian low-byte extraction, and validity of every represented access.

If the first extracted character is “A” and the following source byte is zero, output is “A” followed by zero. If the first extracted character is zero, only that zero is written during the iteration.

The initial source access remains word-typed in the supplied representation. These cases do not establish that only one or two source bytes are accessed.

### Zero detection value

For aligned buffers and detection value zero, the shift is defined and detection never selects a word for terminal emission.

The function continues full-word transfers while accesses and address operations remain valid, regardless of zero bytes in the source. This is not a guarantee of indefinitely valid execution.
