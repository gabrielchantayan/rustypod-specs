## Behavior

### Conditional dispatch

The control input selects between two paths according to whether it equals zero. No particular bit, positive range, or equality with 1 is tested.

If the control input is zero, the function skips both dispatch reads and the indirect invocation.

If the control input is nonzero, the represented operations occur in this order:

1. Read the initial integer word through the object input.
2. Use that word as the dispatch base and add a byte displacement of 280.
3. Read the callable entry at the resulting location.
4. Invoke that entry with the object input as its sole explicitly represented argument.

The displacement is 280 bytes, not 280 entries. If entries and pointers are four bytes wide, the same displacement corresponds to zero-based slot 70. That slot interpretation is conditional on the layout; the byte displacement is directly established.

The representation does not supply the arithmetic width or overflow behavior needed to characterize an invalid or wrapping dispatch address. Normal-execution examples therefore require a valid resolved entry location rather than assuming address wrapping is meaningful.

The selected target’s return value is not used. If it returns normally, execution continues to the fixed dependency sequence. There is no represented callback-success condition.
