# F-b4209d504f85

## Purpose

F-b4209d504f85 counts byte groups in a zero-terminated byte sequence, subject to an optional limit on where a group may begin.

The grouping resembles a permissive multibyte-character count: a byte in the range `C0`–`FF` is grouped with every immediately following byte in `80`–`BF`. Other nonzero bytes each form a group when encountered at a group boundary. The function does not establish that the sequence is valid UTF-8 or that a group represents a Unicode character.

The limit is not a strict read boundary. The function reads a candidate byte before deciding whether its address is below the limit, and continuation-byte scanning can proceed beyond that limit.

## Interface

**Inputs**

1. **Sequence address.** An address from which individual bytes are read. The function has no explicit null-address check.
2. **Limit operand.** Although represented as a pointer-typed argument in the supplied material, this operand is interpreted through a signed integer conversion, not dereferenced:
   - A nonnegative converted value specifies a byte displacement from the original sequence address.
   - A negative converted value selects the address sentinel `FFFFFFFF` instead of a relative endpoint.

**Output**

A signed integer containing the number of completed groups.

An immediate zero byte produces zero. A nonzero byte at an address that is not strictly below the selected endpoint also produces zero if no earlier group has been counted.

**Widths and representation**

The supplied representation uses 8-bit bytes, an integer conversion consistent with a signed 32-bit value, and an address sentinel consistent with a 32-bit address space. Under that model:

- Values `00000000`–`7FFFFFFF` select relative-limit behavior.
- Values `80000000`–`FFFFFFFF`, when converted to signed 32-bit integers as represented, select sentinel behavior.
- The sentinel is an address value, not an additional relative length.

These are properties of the supplied representation. The exact binary calling convention and language-level rules for pointer conversion and pointer ordering are not independently established.

**Preconditions for a defined, normal return**

The sequence address and every subsequently accessed address must be readable. This includes:

- The first address, even when the relative limit is zero.
- An address at or beyond a relative endpoint if execution reaches it.
- All bytes inspected while consuming continuation bytes.
- The first byte following a run of continuation bytes.

Address arithmetic, address comparisons, and the signed result must remain within the target’s defined operating domain. The available evidence does not specify recovery from invalid memory access, address overflow, or result overflow.

No ownership transfer is established. The function neither releases nor retains the supplied storage.

## Behavior

### Endpoint selection

The function selects its endpoint before scanning.

For a nonnegative converted limit operand, the endpoint is the original sequence address plus that many bytes. Thus, a limit of one ordinarily allows a group to begin only at the first byte.

For a negative converted operand, the endpoint is the absolute sentinel address `FFFFFFFF`. The supplied negative value does not become a negative displacement. All operands classified as negative take the same endpoint-selection path.

The sentinel path is effectively open-ended for ordinary low-address buffers, but it is not an abstract unlimited-length operation. The endpoint comparison remains present.

### Group eligibility and termination

At each prospective group boundary, the function first reads the byte at the current address.

- If that byte is zero, scanning ends without counting it.
- Otherwise, the current address must be strictly below the endpoint for another group to be processed.
- If the address is equal to or beyond the endpoint, scanning ends without counting the byte just read.

The byte read therefore precedes the endpoint decision. A relative limit of zero prevents groups from being counted, but does not prevent the initial memory read.

A zero byte terminates the scan even if it is located beyond a relative endpoint and was reached by continuation scanning. It is never itself counted.

### Group formation

An eligible nonzero byte starts one group. The current address first advances by one byte.

The treatment of subsequent bytes depends on the group’s starting byte:

| Starting byte | Group extent |
|---|---|
| `01`–`7F` | The starting byte only |
| `80`–`BF` | The starting byte only |
| `C0`–`FF` | The starting byte plus every immediately following byte in `80`–`BF` |

For a starting byte in `C0`–`FF`, subsequent bytes are inspected until the first byte outside `80`–`BF` is found. That stopping byte is not consumed as part of the group.

The count increases once after the group’s continuation scan, if any, finishes. Scanning then resumes from the first unconsumed address.

Consequently:

- A continuation-range byte encountered at a group boundary counts separately.
- A byte in `C0`–`FF` counts as one group even if no continuation byte follows.
- There is no prescribed maximum number of continuation bytes in one group.
- Continuation consumption is not checked against the endpoint.
- A group that begins below the endpoint is counted in full even when consuming its continuation bytes moves the current address beyond the endpoint.

### Read ordering and repeated reads

For stable ordinary memory, repeated reads usually have no effect on the returned count. Their ordering matters for memory safety and potentially for memory-mapped or concurrently modified storage.

The established access pattern is:

- A prospective group’s first byte is read before its endpoint eligibility is checked.
- For a `C0`–`FF` starting byte, each following continuation candidate is read before deciding whether to advance past it.
- The first non-continuation byte following such a group is read once to end continuation consumption.
- That same address is read again when considering the next group, including when it is already at or beyond the endpoint.
- If this stopping byte is zero, it is likewise read during continuation inspection and again during the next termination check.

No stable-snapshot or atomic-scan guarantee is established. The deterministic examples below assume the accessed bytes do not change during the call.

### Character-validation limits

The grouping rule does not validate an encoding. In particular, the function does not:

- Reject isolated continuation bytes.
- Require a particular number of continuation bytes for a given leading byte.
- Reject leading bytes `C0`, `C1`, or `F5`–`FF`.
- Detect overlong encodings, surrogate encodings, or values outside the Unicode range.
- Decode a code point.

Calling the result a character count is therefore an interpretation of likely intent, not a general behavioral guarantee.

## Acceptance examples

All examples assume stable readable memory, the 32-bit interpretation described above, and no address or count overflow. Byte values are hexadecimal. A positive relative limit is measured from the first listed byte.

### Empty sequence

**Bytes:** `00`  
**Limit:** zero, a positive value, or a negative-classified operand.

**Expected result:** `0`.

The first byte is read. Its zero value stops the scan without counting a group.

### Zero limit does not count or protect the first address

**Bytes:** `41 00`  
**Limit:** zero.

**Expected result:** `0`.

The function reads `41`, then rejects its address because it equals the relative endpoint. This example requires the first address to be readable despite the zero limit.

### Ordinary single-byte groups

**Bytes:** `41 42 43 00`  
**Limit:** two.

**Expected result:** `2`.

The first two bytes each form a group. The function also reads `43` at the endpoint before stopping; it does not count that byte.

### Continuation bytes without a leading byte

**Bytes:** `80 BF 41 00`  
**Limit:** three.

**Expected result:** `3`.

Each nonzero byte is a separate group. A byte in `80`–`BF` does not consume following continuation bytes when it starts a group.

### Multibyte-shaped group

**Bytes:** `E2 82 AC 41 00`  
**Limit:** four.

**Expected result:** `2`.

The first three bytes form one group because `E2` starts continuation consumption. `41` forms the second group.

### Group extending beyond the endpoint

**Bytes:** `C2 80 41 00`  
**Limit:** one.

**Expected result:** `1`.

The first group begins below the endpoint and consumes `80`, even though that byte is at the endpoint. The function reads `41` to end continuation consumption, then reads it again before rejecting its address as beyond the endpoint.

This is not a read bounded to one byte.

### Arbitrarily long continuation run

**Bytes:** `FF 80 BF 80 BF 41 00`  
**Limit:** six.

**Expected result:** `2`.

The `FF` byte and all four continuation-range bytes form one group. The function imposes no encoding-derived limit on that run. `41` forms the second group.

### Leading byte with no continuation

**Bytes:** `C0 41 00`  
**Limit:** two.

**Expected result:** `2`.

`C0` forms one group even though the next byte is not a continuation byte. No malformed-input error is produced.

### Zero immediately after a leading byte

**Bytes:** `E0 00`  
**Limit:** one.

**Expected result:** `1`.

The zero byte is inspected to terminate continuation consumption, then inspected again to terminate the outer scan. The incomplete encoding-shaped group still counts.

### Negative-classified operand

**Bytes:** `41 42 00`  
**Limit operand:** any representation classified as negative by the signed conversion.

**Expected result:** `2`, provided the sequence lies below the sentinel and all accesses are valid.

The magnitude of the negative value does not shorten or extend the scan relative to another negative-classified value.
