# F-7c73e97e8565

## Purpose

F-7c73e97e8565 traverses an object through a caller-supplied handle, using a requested offset to choose between descending through a fixed-size header and skipping by a decoded length. Each selected record causes a length-update dependency call. Normal completion also causes a count-update dependency call for the most recently remembered selection, provided its remembered offset is nonzero.

“Object,” “record,” “header,” “length,” “count,” and “extent” describe inferred roles. The supplied evidence does not establish an external format or the dependencies’ actual memory operations.

The function returns either zero or the 32-bit pattern `0xffffffce`. Rejection is not transactional: earlier dependency calls are not undone, and rejection bypasses the final count update. Whether earlier calls’ effects remain in storage depends on behavior outside this function.

## Interface

The function takes four arguments:

| Input | Established use |
|---|---|
| Object handle | Address of a location containing a 32-bit object base address. Read after the extent dependency returns; read again when a final count update is required. |
| Requested offset | Unsigned 32-bit traversal target. Zero is normalized to 12. Some comparisons subsequently interpret its bits as signed 32-bit. |
| Length adjustment | Signed 32-bit input whose bit pattern participates in the selected record’s 32-bit length calculation. |
| Count adjustment | Signed 32-bit input added during the final count calculation. Only the adjusted low 16 bits affect the final writer argument. |

The observable adjustment calculations use 32-bit results, including wraparound. Neither adjustment is validated.

The result is:

- `0x00000000` on a normal completion path.
- `0xffffffce` on an explicit traversal rejection. Its signed 32-bit interpretation is −50; no symbolic error classification is established.

A zero result does not establish that the requested offset was reached. Traversal can also finish because the traversal value becomes zero.

### Widths and accessed layout

The supplied representation uses 32-bit integer-held addresses and 32-bit offset calculations. Address arithmetic must not be replaced by unbounded arithmetic when describing its behavior. Validity of the resulting addresses is a precondition for the reached operations, not a guarantee made by this function.

The established relative locations are:

| Address basis | Displacement | Use |
|---|---:|---|

Dependency ownership, retention, physical access widths, alignment requirements, synchronization, and memory-management behavior are unknown. ## Behavior

### Immediate completion

A requested offset of zero is normalized to 12.

If the normalized target is 12, the function returns zero without dereferencing the handle or calling any dependency. Both adjustments are ignored. This path exercises no object-storage validity requirement within the function itself.

### Initialization

For every other target, the observable initialization order is:

1. Call F-48d3618d091a with the handle and retain its 32-bit result as the extent.
2. Load the object base from the handle.
3. Establish the initial record address at base plus 12.
4. Call F-c19b4c0cb7f7 twice at base plus 26.
5. Assemble the initial traversal value from those two results.

The logical offset begins at 12. The active skip counter and remembered selected-record offset begin at zero.

The two-call traversal-value assembly takes:

- Bits 0–7 of the first result into output bits 8–15.
- Bits 8–15 of the second result into output bits 0–7.

All other bits are discarded. The traversal value is therefore in the range 0 through 65,535.

If both results are identical, this assembly reverses their low two bytes. They are nevertheless separate calls, and neither stable results nor ordinary memory-read behavior is established.

An initial traversal value of zero bypasses the loop and returns zero without either writer call.

### Loop-entry checks

An iteration is entered only while the traversal value is nonzero.

Before testing whether the target has been reached, the function rejects if either condition holds:

- The unsigned 32-bit result of extent minus 20 is less than the current logical offset.
- The signed 32-bit interpretation of the requested offset is less than the signed 32-bit interpretation of the current logical offset.

Either rejection returns `0xffffffce`.

Extent subtraction wraps modulo \(2^{32}\). An extent below 20 is not automatically rejected: its subtraction result is a large unsigned value.

Only after both checks pass does equality between the logical offset and requested offset terminate traversal normally. Target equality therefore does not bypass the entry checks.

These comparisons do not establish the validity of a whole decoded record span or of every forthcoming dependency address.

### Length observations and selection

If the current logical offset differs from the target, the function calls F-c223c8c1cf8e four times at the current record address, in order. It assembles a 32-bit decision length as follows:

| Output bits | Source |
|---|---|
| 24–31 | First result, bits 0–7 |
| 16–23 | Second result, bits 8–15 |
| 8–15 | Third result, bits 16–23 |
| 0–7 | Fourth result, bits 24–31 |

Identical results would produce a four-byte reversal of the common 32-bit value. The function does not establish that the results are identical.

The decision length is added to the current logical offset modulo \(2^{32}\). The selected-record branch is taken exactly when the requested offset is unsigned-less-than that wrapped sum.

Equality with the computed end takes the skip branch. Overflow does not cause a separate rejection. This strict arithmetic comparison is not proof of containment within valid storage.

### Selected-record branch

After the selection decision, the function performs these operations in order:

1. Call F-c223c8c1cf8e four more times at the current record address and assemble a new length using the same four-result rule.
2. Call F-c19b4c0cb7f7 twice at current record address plus 14.
3. Assemble and replace the traversal value using the two-result rule.
4. Set the active skip counter to one.
5. Add the length adjustment to the newly assembled length modulo \(2^{32}\).
6. Reverse the four bytes of that adjusted 32-bit result.
7. Call F-38272e1956e5 with the current record address and the reversed value.
8. Advance the record address and logical offset by 20.
9. Remember the pre-advance logical offset as the most recently selected offset.

The decision length and update length come from different groups of four calls. A dependency that returns changing values can therefore cause selection based on one length and a writer argument based on another.

The traversal-value calls and assembly occur before the length-writer call. A newly assembled traversal value of zero does not suppress that writer call or the 20-byte advance; it prevents the next loop iteration.

Every selection replaces the remembered offset, traversal value, and active skip counter. No explicit stack of enclosing selections is maintained.

### Skip branch and counter rejection

If the strict selection comparison fails, F-c223c8c1cf8e is called four more times at the current record address. These independent results determine the advance length through the same four-result assembly.

If the active skip counter is zero, counter rejection is disabled and the counter remains zero.

Otherwise, let:

- \(k\) be the counter before this skip.
- \(t\) be the current traversal value.
- \(n=(k+1)\bmod 2^{32}\).
- \(d=(k-t)\bmod 2^{32}\).
- \(O\) indicate signed 32-bit overflow when subtracting the signed interpretation of \(t\) from the signed interpretation of \(n\).

The counter becomes \(n\). Rejection occurs exactly when:

- \(n\ne t\); and
- the sign bit of \(d\) equals \(O\).

The sign test uses the old-counter difference, but the overflow indicator uses the incremented-counter difference. An ordinary signed comparison is not an equivalent general replacement.

For ordinary small values without signed overflow, the condition rejects when \(k\ge t\). This is only a restricted simplification.

Counter rejection occurs after all four length-reread calls and before advancing either the record address or logical offset. It returns `0xffffffce`, bypassing the final count update.

Without rejection, both positions advance by the independently reread length using 32-bit arithmetic. The traversal value is not decremented.

### Final count update

Normal loop completion occurs either through target equality or because the traversal value is zero.

If the remembered selected-record offset is zero, the function returns zero without a final count update. Zero is the sentinel; the function does not maintain a separate “selection occurred” flag.

For a nonzero remembered offset, the final sequence is:

1. Load the object base from the handle again.
2. Add the remembered offset to that newly loaded base.
3. Call F-c19b4c0cb7f7 twice at that address plus 14.
4. Form a 32-bit intermediate from the first result shifted left eight bits, combined with bits 8–15 of the second result shifted into bits 0–7.
5. Add the count adjustment modulo \(2^{32}\).
6. Reverse the adjusted low two bytes, discarding higher bits.
7. Call F-192d46d1d024 with the field address and that constructed value.
8. Return zero if the dependency returns normally.

Unlike traversal-value assembly, this intermediate does not mask the first result to one byte before shifting. Higher bits can enter the intermediate, but cannot affect the final argument beyond its adjusted low 16 bits.

The final writer argument is between zero and 65,535. That range establishes the argument value, not the dependency’s physical write width.

The second handle load is significant. Intervening dependencies may change the stored base, so the final field address need not refer to the storage traversed earlier.

## Side effects

Except for normalized target 12, execution begins with one extent-dependency call, a handle load, and two initial traversal-value calls.

Subsequent effects depend on traversal:

- Each selection issues one length-writer call after its length rereads and traversal-value calls.
- Each skip performs independent length rereads, even when counter rejection follows.
- Normal completion with a nonzero remembered offset reloads the handle, performs two count-field calls, and issues one count-writer call.
- Zero adjustments do not suppress writer calls.
- The retained extent is never refreshed.

Traversal addresses derive from the initially loaded base; the final count address derives from the later handle load.

Explicit rejection performs no local rollback and no final count-writer call. Earlier writer calls remain part of the execution history. Persistent field contents are not guaranteed: the writers’ actual effects and subsequent dependencies’ preservation behavior are unknown.

There is no explicit handler for dependency failures, traps, exceptions, or nonlocal exits. The evidence does not establish that such events produce either documented return value.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Except for immediate completion, assume reached addresses are valid and dependencies return normally.

1. **Requested offset zero or 12.**  
   Expect zero with no dependency calls or handle loads, regardless of either adjustment.

2. **Initial traversal value zero.**  
   For another target, expect the extent call, handle load, and two initial field calls. If they assemble to zero, expect zero without either writer call, even though the target was not reached.

3. **Initial extent rejection.**  
   With nonzero initial traversal value and extent 31, extent minus 20 equals 11. Initial logical offset 12 fails the first entry check. Expect `0xffffffce` before any length-reader call.

4. **Small extent wraps.**  
   With extent 19, extent minus 20 is `0xffffffff`. This check alone does not reject logical offset 12. Storage validity and subsequent behavior remain separate conditions.

5. **Selection followed by target equality.**  
   Let the target be 32, the initial decision length be 40, and the entry checks pass. Since \(32<12+40\), expect four additional length calls, two traversal-value calls, and then the length-writer call. Traversal advances to 32 and remembers offset 12. If the replacement traversal value is nonzero and the next entry checks pass, equality ends traversal. The final count address is the newly loaded base plus 26.

6. **Zero traversal value after selection.**  
   Under the preceding selection conditions, let the selected record’s traversal-value calls assemble to zero. The length-writer call and advance still occur. No next entry check occurs, and the final count-update sequence is reached.

7. **Exact end selects the skip branch.**  
   With current offset 12, target 32, and decision length 20, strict selection fails. If the reread advance length is 20 and the counter is inactive, traversal advances to 32. A nonzero traversal value and passing next-entry checks allow normal completion without either writer, because no selection was remembered.

8. **Immediate rejection after an earlier length writer.**  
   Suppose a selected-record branch loads and assembles a nonzero traversal value, calls the length writer, and then advances. If the immediately following entry check rejects, expect `0xffffffce`, no dependency calls between the writer’s return and that rejection, no local rollback, and no final count-writer call. The earlier writer call is established; retained field contents additionally depend on its actual effects and absence of external modification.

9. **Low-16-bit count wraparound.**  
   If the final count intermediate has low 16 bits equal to 65,535 and the count adjustment is one, expect final writer argument zero, regardless of the intermediate’s higher bits.

10. **High-bit target rejection.**  
    With target `0x80000000` and nonzero initial traversal value, the signed target comparison rejects against initial logical offset 12. Expect `0xffffffce` before length-reader calls.

11. **Small-value counter threshold.**  
    With traversal value two and active counter one, a skip increments the counter to two without counter rejection. If another skip is reached with unchanged traversal value and counter two, it rejects after its four length-reread calls and before advancing.
