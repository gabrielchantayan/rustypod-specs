# F-4ad4b6147e98

## Purpose

F-4ad4b6147e98 modifies a word-oriented context and emits 20 bytes derived from its first five words. It completes a selected block word using externally sourced bytes, optionally processes an intermediate block, installs two context-derived terminal words, processes the final block, and serializes five resulting words in most-significant-byte-first order.

The layout is consistent with finalization of a block-based, 160-bit digest: sixteen 32-bit block words, two terminal length-like words, and a twenty-byte result. This is **inferred intent**, not an established algorithm identification. Neither the external byte values nor the transformation performed by F-b83fed55b80b is established.

On normal completion, the function clears the context’s position word and returns the 32-bit value 1. No checked error-reporting interface is visible.

## Interface

### Arguments and result

The function accepts:

- An **output address**, identifying storage for twenty byte writes.
- A **context address**, identifying mutable 32-bit words.

Every visible normal return produces the 32-bit value 1.

Context words are numbered from zero. Word numbers describe 32-bit accesses; byte offsets are relative to the context address.

| Context words | Byte offsets | Observed role |
|---|---:|---|
| 0–4 | 0–19 | Read after the final dependency call and serialized |
| 5 | 20–23 | Copied into block word 15 |
| 6 | 24–27 | Copied into block word 14 |
| 7–22 | 28–91 | Sixteen-word block supplied to the dependency |
| 23 | 92–95 | Position information, read twice initially and cleared last |

Block numbering starts at context word 7. Block words 14 and 15 are therefore context words 21 and 22.

A 96-byte context covers the direct context accesses for stable positions from 0 through 63. This does not establish the dependency’s complete storage requirements. Required alignment and native context byte order remain unknown. Output byte order is explicit.

### External address source

The function obtains byte-source addresses from an external address expression. That expression is evaluated once or twice depending on the position remainder. Its storage, initialization, pointer width, mutability, and stability are not established.

The external address must not be treated as one base captured for the entire operation. In particular:

- Remainder 0 uses two address evaluations, with the first external byte read between them.
- Remainder 1 uses one address evaluation.
- Remainders 2 and 3 use two address evaluations, but only one of the resulting addresses supplies byte reads.

The external bytes are unsigned eight-bit values. Their contents are unknown; no particular padding sequence is established.

### Preconditions

For ordinary memory-safe use:

- The output permits twenty byte writes.
- The context permits the direct reads and writes described below.
- Each external address evaluation can be performed, and every byte location actually read is accessible.
- The dependency accepts the context address, the block address, and the numeric argument 1.
- The position reads are stable and decode to a block word index from 0 through 15.

No null checks, size checks, overlap checks, or position-range validation are visible. Invalid inputs are not converted into a defined failure result.

## Behavior

### Position decoding

The function first reads context word 23 and retains its low two bits as a remainder from 0 through 3. It then reads context word 23 again, interprets that read as a signed 32-bit value, and shifts it right by two bits with sign propagation to obtain the selected block-word index.

These are distinct reads, in that order. For a stable position from 0 through 63, they produce the ordinary remainder and quotient on division by four.

For arbitrary 32-bit input, the signed index ranges from −536,870,912 through 536,870,911. Increasing it by one does not overflow signed 32-bit arithmetic. That fact does not make the resulting memory accesses valid.

If the two position reads differ, the remainder and index can describe different positions. The evidence establishes no synchronization or supported concurrent-modification protocol.

### External address evaluations and byte assembly

The selected word is assembled as a 32-bit value. Each external byte is widened without sign extension, shifted into its designated byte position, and combined using bitwise OR.

For nonzero remainders, the existing selected block word is read **before any external address evaluation**. Its bits remain part of the assembled value. External bytes do not replace or clear previously set bits.

The address evaluations and byte reads differ by remainder:

| Remainder | Initial value | Address evaluations | Byte reads and contributions, in order |
|---:|---|---:|---|
| 0 | Zero; no existing block-word read | Two | Read through the first evaluated address into bits 31–24. Then evaluate the address expression again; read offsets 1, 2, and 3 from that second address into bits 23–16, 15–8, and 7–0. |
| 1 | Existing selected word | One | After the existing-word read, evaluate the address expression once. Read offsets 0, 1, and 2 from that address into bits 23–16, 15–8, and 7–0. |
| 2 | Existing selected word | Two | After the existing-word read, evaluate the address expression twice. Only the second captured address supplies bytes: offsets 0 and 1 contribute to bits 15–8 and 7–0. |
| 3 | Existing selected word | Two | After the existing-word read, evaluate the address expression twice. After the second evaluation, read one byte through the first captured address into bits 7–0. |

For remainder 0, the first byte read precedes the second address evaluation. The remaining three byte reads all follow that second evaluation.

For remainder 2, no byte is read through the first captured address. For remainder 3, no byte is read through the second captured address; evaluating it nevertheless precedes the byte read through the first address.

If repeated address evaluations produce the same value, the bytes read are consecutive bytes beginning at that value: four, three, two, or one byte for remainders 0, 1, 2, or 3 respectively. Without that stability condition, remainder 0 can combine its first byte from one address with its remaining bytes from another. Remainder 2 selects its two-byte source using the second evaluation; remainder 3 retains the first evaluation for its single-byte source.

All contributing external bytes are read before the assembled word is stored. For example, with remainder 2, an existing word of 0x123400F0 and contributing bytes 0x56 and 0x0F produce 0x123456FF, not 0x1234560F.

The function then writes the assembled value to the selected block word, before any dependency call.

### Intermediate-block decision and clearing

The next block-word index is one greater than the selected index.

When the next index is less than 15:

- No intermediate dependency call occurs.
- Block words from that next index through 13 are cleared in increasing index order, if the range is nonempty.

Thus, selected index 12 clears word 13, while selected index 13 clears no words at this stage.

When the next index is at least 15:

- If it is also less than 16, the block word at that next index is cleared.
- F-b83fed55b80b is called with the context address, the block address, and 1.
- After the call returns, block words 0 through 13 are cleared in increasing index order.

For ordinary positions, selected index 14 therefore clears block word 15 before the intermediate call. Selected index 15 performs no such pre-call clearing.

The intermediate dependency may change context or external state. No preservation guarantee is established.

### Installing the terminal words

After the branch-specific clearing, the function performs two full-width copies in this order:

1. Read context word 6 and write it to block word 14.
2. Read context word 5 and write it to block word 15.

No byte swapping, length computation, increment, or validation is visible.

If an intermediate call occurred, these reads use the context values present after that call. They are not entry-time snapshots.

### Final dependency call

The function calls F-b83fed55b80b with the context address, the address of block word 0, and the numeric value 1.

This call occurs on every normally progressing execution. No dependency result is examined.

Ordinary selected indices 0 through 13 produce one call overall. Indices 14 and 15 produce an intermediate call followed by this final call.

### Output serialization

After the final call returns, context words 0 through 4 are processed in increasing order.

For each word, the function reads the complete 32-bit value and then writes four output bytes in increasing output-address order:

- Bits 31–24.
- Bits 23–16.
- Bits 15–8.
- Bits 7–0.

Context word 0 supplies output offsets 0–3; word 4 supplies offsets 16–19.

The five words are not captured together before output begins. The read of each subsequent word occurs after the preceding four-byte output group has been written. Within one group, all four bytes derive from the already-read word.

### Final reset and return

After all twenty output-byte writes, the function writes zero to context word 23 and returns 1.

The reset does not precede either the final dependency call or serialization. If execution does not reach this point, no reset guarantee is established.

## Side effects

### Direct writes

For ordinary valid positions, direct writes affect:

- The selected block word.
- Block words cleared by the chosen branch.
- Block words 14 and 15 during terminal-word installation.
- Twenty output bytes.
- Context word 23, cleared last.

No direct write to the external address source is visible. Its evaluations and the external byte reads are nevertheless part of the observed access sequence.

The dependency can introduce additional changes. Its write footprint, global accesses, memory ownership effects, and allocation behavior are unknown.

The function does not explicitly erase the full context or its first five words. The final dependency may alter block storage, so the block’s final contents cannot be inferred solely from the values prepared before that call.

### Aliasing

No overlap rejection is visible.

Output overlapping the context can affect serialization: an earlier output group can overwrite a context word before that later word is read. Writes within one group do not change the captured value used for the remaining bytes of that same group.

Output overlapping context word 23 can subsequently be overwritten by the final zero reset. Accordingly, the final output region need not contain an independent serialization of the five post-call context words.

The relationship between the external address source, its referenced bytes, and writable storage is unknown. The specified evaluation sequence must not be replaced with an assumption that one immutable external base is used.

A disjoint output buffer avoids direct output/context interactions, but does not establish the dependency’s aliasing or global-state guarantees.

### Ownership and errors

No direct allocation, release, ownership transfer, or retained-pointer operation is visible. This does not establish that F-b83fed55b80b retains no pointers or releases no memory.

There is no visible rollback, recovery, or explicit error status. Return value 1 establishes only that execution reached the normal return, not that a separately defined digest computation succeeded.
