# F-bf7ef8288463

## Purpose

F-bf7ef8288463 combines byte payloads with existing destination bytes using bitwise OR. It performs an unconditional masked update at an entry-supplied destination, then processes a count-controlled sequence of destination rows separated by a signed stride.

The initial update differs from subsequent-row processing: its payload is supplied at entry, its shift comes from an explicit input, and it consumes no source byte. It occurs before any count-based termination decision.

Subsequent rows consume a continuous source stream. Each row performs unmasked whole-byte updates, followed by a masked update when its width has a nonzero remainder after division by eight.

Established properties:

- Each destination update preserves bits already set in that byte.
- A zero or negative count does not suppress the initial update.
- A positive width divisible by eight causes no trailing masked-byte access.
- Destination stride does not introduce source padding.
- A row-base advance occurs before every termination decision, including the decision that returns.
- The initial destination can overlap subsequent destinations or source bytes. Its effect must be included when determining later results.

**Inferred intent:** the operation is consistent with composition of packed data into strided rows. No particular image format, bit orientation, clipping convention, or public drawing interface is established.

## Behavior

### Masked updates

A masked update performs these byte-level operations:

1. Logically shift the unsigned 32-bit mask word right by the selected amount.
2. Retain the low eight bits of that shifted result.
3. AND the eight-bit payload with that mask byte.
4. OR the contribution into the destination’s existing byte and store the result.

The payload itself is not shifted. The full mask word participates before narrowing; narrowing the mask word before shifting is not equivalent.

For the initial update, the shift amount is the low eight bits of the explicit initial-shift input. Inputs of 1 and 257 therefore select the same amount. Effective amounts from zero through 31 have the ordinary defined meaning for an unsigned 32-bit right shift. Results for effective amounts from 32 through 255 remain **documented_only**.

For a subsequent row’s trailing update, the shift amount is the residual width, between one and seven.

A zero contribution still follows the represented destination read-and-write path; it is not a reason to omit the access.

### Initial update and row selection

The initial destination is updated before any count decrement, row-base advance, or source-byte read.

Afterward, each row-selection boundary proceeds in this order:

- Decrement the signed 32-bit remaining count by one.
- Advance the row base by the signed destination stride.
- Select that advanced base as the destination position and reload the repeated width.
- Return if the decremented count is less than one.
- Otherwise, process the selected row.

The terminating boundary does not dereference the newly selected destination, but it still performs the preceding address calculation.

For an entry count \(N \geq 1\), provided arithmetic and memory accesses are valid:

- One initial masked update occurs.
- Exactly \(N-1\) subsequent rows are processed.
- Exactly \(N\) row-base advances occur, including the final advance before return.

An entry count of one therefore performs only the initial update, followed by one decrement and one row-base advance.

An entry count of zero or a negative value other than the minimum signed 32-bit integer likewise performs the initial update, then one decrement and advance before returning. Such a count does not request a no-op.

Decrementing the minimum signed 32-bit integer exceeds the established defined-arithmetic range. Neither wrapping nor a particular failure is promised.

### Destination locations

Let \(B\) be the initial row base and \(S\) the signed stride. Subsequent row \(j\), numbered from one, starts at:

\[
B+jS
\]

This expresses the displacement sequence, not permission to use arbitrary mathematical addresses.

Bytes within each processed row are visited in increasing address order. A negative stride changes the direction between row starts, not the direction within a row. Zero stride makes all subsequent rows start at the same address.

The initial destination is not excluded from this sequence. If it aliases a subsequent destination, its update contributes to that byte’s value before subsequent-row processing begins. Later rows may also revisit bytes changed by earlier rows.

### Width and byte processing

For a repeated width \(W\) in the range 1 through 2,147,483,647, define:

\[
q=\left\lfloor W/8\right\rfloor,\qquad r=W\bmod 8
\]

Each subsequent row processes \(q\) complete bytes. For each complete byte, one source byte is ORed into the corresponding destination byte without applying the mask word.

If \(r\) is nonzero, one additional source byte is consumed for a trailing masked update. Its mask byte is the low eight bits of the mask word shifted right by \(r\).

Thus each positive-width row consumes and updates:

\[
q+\begin{cases}
1,&r\ne0\\
0,&r=0
\end{cases}
\]

bytes. This counts operations, not necessarily distinct addresses.

A width of eight performs one complete-byte update and no trailing update. A width of ten performs one complete-byte update and one trailing update with shift two.

The whole-byte loop subtracts eight using unsigned 32-bit arithmetic. That loop is entered only while the current width’s signed interpretation exceeds seven. For a participating positive width, subtraction therefore reaches a residual from zero through seven without unsigned underflow.

A width of zero causes no subsequent-row byte accesses. Values from hexadecimal 80000000 through FFFFFFFF have a negative signed interpretation in the represented comparisons and also cause no subsequent-row byte accesses. Row-selection boundaries, count decrements, and base advances still occur.

### Source continuity

The source stream has no separate row stride or padding.

After a row containing only complete bytes, the next row starts with the source byte immediately following the last complete byte consumed. After a row containing a trailing update, the next row starts immediately after that trailing source byte. Rows with no byte operations consume nothing.

Before reading a trailing source byte, the operation forms and saves the source position one byte beyond it. That calculation must be valid even if no later source read occurs.

The entry-supplied initial payload is not fetched from the source stream. Nevertheless, the initial destination write can change a future source value if the two locations alias.

## Side effects

### Access order

The unconditional initial destination read-modify-write precedes every source read and every count-based termination decision.

For each complete-byte update:

- The source and current destination bytes are read to determine the result.
- Their relative read order is not established.
- The destination result is stored before advancing the destination position.
- The source position then advances before another transfer.

For a trailing update:

- The source position one byte ahead is formed and saved.
- The trailing source byte is read.
- The destination read-modify-write uses that saved payload.

At each row-selection boundary, count decrement precedes base advancement, and destination selection and width reload precede the termination test.

These are ordering properties of the supplied representation, not hardware synchronization guarantees. Atomicity, volatile semantics, device-memory behavior, and inter-thread ordering are not established. The updates must not be treated as atomic OR operations.

### Aliasing and accumulated destination contents

No source snapshot is created. A destination write can change a source byte that has not yet been read, including through the initial update.

Destination updates also accumulate. If the initial destination aliases a later destination, that later update uses the value resulting from the initial update and any intervening writes. If rows overlap, a later row similarly uses the destination contents left by earlier processing.

Consequently, an expected destination value cannot generally be computed from its entry value plus only the subsequent-row source bytes. The initial contribution must also be included whenever its address aliases that destination.

The operation provides no overlap-independent copying guarantee. Preservation of already-set destination bits does not imply preservation of unread source contents.

## Acceptance examples

These examples are conditional deductions from static evidence, not observed executions. Unless stated otherwise, all required accesses and address calculations are valid, arithmetic is defined, and memory is not concurrently modified.

For examples describing subsequent-row destination contents, the stated starting values are measured **immediately after the unconditional initial update**. Thus those conditions already account for any alias between the initial destination and those bytes. Source values are the values actually available when read; absent an explicit aliasing example, intervening writes are assumed not to change them.

### Zero count still updates the initial destination

Given an initial destination byte of hexadecimal 80, initial payload 3C, mask word 000000FF, initial shift zero, and remaining count zero:

- The initial destination becomes BC.
- The count is decremented to negative one.
- One row-base advance occurs before return.
- No source byte is read, and the advanced destination is not dereferenced.

### Width ten uses one complete byte and one trailing byte

Given remaining count two, repeated width ten, and mask word 000000FF, exactly one subsequent row is processed.

If its destination bytes are 80 and 40 immediately after the initial update, and its source bytes are 12 and E5, the resulting destination bytes are 92 and 65.

The first update is an unmasked OR. The trailing update uses shift two, producing mask byte 3F; E5 AND 3F contributes 25 to destination 40.

Two source bytes are consumed. A second count decrement and base advance occur before return. These results do not apply if an unaccounted initial update changed either stated starting destination value.

### Exact-byte rows consume contiguous source bytes

Given remaining count three and repeated width eight, two subsequent rows each consume one source byte.

Suppose their destination addresses are distinct, both destination bytes contain zero immediately after the initial update, and the source bytes read are 01 and 02. The destination bytes become 01 and 02 respectively.

No trailing destination byte is accessed, and no third source byte is fetched. Distinct destination addresses are required for these two separate final values; with zero stride, the contributions would accumulate at one address instead.

### The full mask word affects the trailing contribution

Given remaining count two, repeated width one, mask word 00000100, and a source byte FF, exactly one subsequent trailing update occurs.

If its destination byte is zero immediately after the initial update, the final byte is 80. Shifting the full mask word right by one yields a low byte of 80.

If that destination instead contains 01 after the initial update, the final byte is 81. The trailing operation preserves the existing bit; it does not replace the destination with the masked source.

### High-bit widths perform no subsequent byte updates

Given remaining count three and repeated width 80000001, the initial masked update occurs, but neither selected subsequent row consumes a source byte or performs a destination-byte update.

Three count decrements and three row-base advances occur, including the terminating boundary. Any destination change caused by the initial update remains part of the final memory state.

### Zero stride includes the initial contribution

Suppose the initial destination equals the initial row base and initially contains 00. Use initial payload 80, mask word 000000FF, initial shift zero, count three, width eight, and stride zero. The separate source bytes are 01 and 04 and are not changed by destination writes.

The initial update changes the shared destination to 80. Both subsequent rows target that same byte, producing 81 and then 85. The accepted final value is **85**, not 05.

A final value of 05 is instead conditional on that shared destination containing 00 immediately after the initial update, with the same subsequent source bytes and no other contributions.

### Initial aliasing can change a future source value

Suppose the initial destination aliases the first source byte, initially zero. Initial payload 01, mask word 000000FF, and initial shift zero change it to 01.

With count two and width eight, the subsequent row reads 01 from that source position. If its separate destination contains zero after the initial update, it becomes 01. Using the original source value of zero would violate the established ordering.

### Large effective initial shifts remain unresolved

Initial shift 257 selects effective shift one. Initial shift 32 selects effective shift 32, but no particular mask or destination result is established for that case.
