# F-f040c60c1676

## Purpose

F-f040c60c1676 transforms two 32-bit words into one 32-bit result. Most paths construct the result directly using classification, rounding, and bit packing. One exceptional classification instead dispatches through an address derived from incoming execution context.

The direct-result paths resemble a conversion from a wider floating-point representation to a narrower representation, including signed zero, overflow encodings, and round-to-nearest behavior. That interpretation is inferred intent, not an established interface requirement. The contract below specifies word-level behavior without requiring either input to be a valid floating-point value.

The exceptional dispatch depends on shared data and incoming machine state not represented by the two explicit arguments. This prevents the function as a whole from being specified as a pure two-input numerical conversion.

## Interface

### Explicit inputs and output

- **First word:** an unsigned 32-bit value.
- **Second word:** an unsigned 32-bit value.
- **Result:** an unsigned 32-bit value, either constructed locally or returned by an unresolved indirect dependency.

Neither explicit input is dereferenced. The supplied evidence does not identify either input as an address, buffer, owned object, or resource handle.

Bit numbering is zero-based, with bit 31 the most significant bit. All masks, shifts, additions, and complements below operate on 32-bit words. Additions discard carry beyond bit 31 unless a separate carry condition is explicitly described. Right shifts of the explicit inputs are logical.

Where a signed comparison is specified, the word is interpreted as a signed two’s-complement 32-bit value. This distinction is material to the early-zero result.

### Additional execution inputs

Exceptional dispatch uses:

- An incoming return-link value. Its bottom two bits are cleared to form the indirect transfer address.
- The low bit of an incoming status quantity.
- A shared control word.
- Three shared 32-bit data words, named here **data A**, **data B**, and **data C**.

These descriptive data names are not source identifiers. The evidence does not establish their values, initialization, mutability, alignment, storage ownership, or concurrency properties.

The indirect dependency is designated **F-indirect-01**. This is a document-local opaque identifier for an unresolved target, not a claim that the target has been identified.

### Preconditions

For direct-result paths, the supplied evidence imposes no input-value precondition.

For an exceptional dispatch to complete normally:

- The masked incoming return-link address must support the observed control transfer.

The evidence does not establish a complete calling convention for that transfer. In particular, the apparent argument counts below describe the supplied representation, not independently verified ABI signatures.

## Behavior

### 1. Initial classification

Retain bit 31 of the second word as the **sign field**.

Form a classification word by XORing:

- The second word with bit 31 cleared.
- The second word shifted left by one bit, discarding the bit shifted out.

Select the **ordinary path** if either of these classification masks is nonzero:

- `0x7f000000`
- `0x00e00000`

Otherwise select the **special path**.

The first word does not affect this initial choice.

### 2. Ordinary path: range adjustment

Clear bit 31 of the second word, add `0xc8000000`, and retain the low 32 bits. Interpret this adjusted word as signed for the next comparison.

If it is less than `0x00100000`, return `0x00000000` immediately.

This result is positive zero regardless of the retained sign field. No rounding or exceptional dispatch occurs on this path.

The signed comparison must not be replaced with an unsigned comparison. For example, an adjusted word whose high bit is set satisfies the signed less-than test even though its unsigned value is large.

### 3. Ordinary path: rounding

For an input that passed the range check, inspect the first word.

Rounding occurs exactly when:

- Bit 28 is set; and
- Either at least one of bits 0 through 27 is set, or bit 29 is set.

When rounding occurs:

1. Determine whether the original first word is greater than `0xdfffffff` as an unsigned value.
2. Add `0x20000000` to the first word, retaining only 32 bits.
3. Increment the adjusted word by one if the unsigned comparison in step 1 was true.

When rounding does not occur, leave both words unchanged for subsequent packing.

The condition involving bit 29 follows from the supplied signed arithmetic test: masking bit 29, multiplying by four, subtracting `0x40000000`, and interpreting the result as signed produces a nonnegative value exactly when bit 29 was set.

The visible effect is consistent with rounding a retained field to nearest, resolving exact halfway cases toward an even retained low bit. That numerical interpretation is inferred; the bit conditions above are the established requirement.

### 4. Ordinary path: overflow and result packing

After any rounding adjustment, compare the adjusted word against `0x0fefffff`.

If it is greater, return:

- The retained sign field OR `0x7f800000`.

Otherwise return the bitwise OR of:

- The retained sign field.
- The adjusted word shifted left by three bits.
- The possibly rounded first word shifted right by 29 bits.

The shifted first word contributes exactly three low result bits. A carry from rounding the first word is represented separately by the increment to the adjusted word.

Although the adjusted value is represented as signed in the supplied evidence, any value that passes the earlier signed range check lies between `0x00100000` and `0x47ffffff` before rounding. A possible increment does not cross the signed boundary. Thus the later overflow comparison does not have a reachable signed-versus-unsigned ambiguity.

### 5. Special path: zero and directly returned encodings

If bit 20 of the second word is clear:

- Return `0x00000000` if the first word is nonzero or any bit other than bit 31 of the second word is nonzero.
- Otherwise return the retained sign field.

Thus the two all-zero-magnitude input pairs preserve the second word’s sign, while other inputs taking this branch collapse to positive zero.

If bit 20 is set, inspect the remaining payload:

- If the first word is zero and bits 0 through 19 of the second word are all zero, return the second word AND `0xff8fffff`.
- Otherwise enter exceptional dispatch.

The direct mask result is specified literally. It is not permissible to substitute an assumed canonical special-value encoding.

No shared control or data read is visible before exceptional dispatch is selected.

### 6. Exceptional dispatch

Initialize the default first argument value to zero. Read the shared control word and select a mode using its low four bits.

Subsequent control-word tests are separate accesses in the supplied representation. The contract does not assume they observe the same value as the initial mode selection.

All transfers described below use F-indirect-01 at the incoming return-link address with bits 0 and 1 cleared. If the target returns normally, return its 32-bit result without visible postprocessing.

#### Mode 10

Read the control word and test bit 6.

- Bit 6 clear: transfer with one apparent argument, `0x00000000`.
- Bit 6 set: transfer with one apparent argument, `0x80000000`.

No shared data A, B, or C read is visible on this branch.

#### Mode 8

Read the control word and test bit 6.

If bit 6 is set, transfer with two apparent arguments:

1. `0x00000000`
2. `0x00000000`

If bit 6 is clear:

1. Read data A.
2. Read data B.
3. Read the control word and test bit 4.
4. If bit 4 is clear, transfer with the previously read data A and data B, in that order.
5. If bit 4 is set, replace the first argument with zero, read data C for the second argument, and transfer with those replacement arguments.

The reads of data A and data B precede the bit-4 decision in the supplied representation. They are not eliminated from this behavioral description merely because their values can subsequently be replaced.

#### Mode 9

Read the control word and test bit 20.

If bit 20 is clear, transfer with two apparent arguments:

1. `0x00000000`
2. Data B

Otherwise, read the control word and test the mask `0x00070000`.

If none of those three bits is set, transfer with three apparent arguments:

1. `0x30000000`
2. Data B
3. `0x30000000` OR the incoming status low bit shifted to bit 27

The third argument is therefore either `0x30000000` or `0x38000000`.

If at least one masked bit is set, transfer with two apparent arguments:

1. `0x00000008`
2. A newly read control word shifted left by 15 bits, complemented across 32 bits, then shifted left by one bit

Both shifts discard bits outside the 32-bit word. The final second argument has bit 0 clear. The control value used for this argument need not equal a value observed by an earlier test.

#### Other modes

Transfer to F-indirect-01 with no explicit arguments shown in the supplied representation.

This does not establish that argument registers are cleared, that the target receives no contextual state, or that the target has a zero-argument ABI.
