## Behavior

### Initial gate and bound capture

The first explicit input access reads slot 4 for character conversion.

If the converted value is zero, the function returns immediately. It does not directly read the bound, read the dispatch integer, resolve a target, inspect an entry, or call F-feee9156a257.

Otherwise, it reads slot 1 and retains that signed value as the traversal bound. The index begins at zero.

Neither the gate nor the bound is reread. Later dependency changes to those input fields therefore do not alter the captured bound or trigger another gate decision. This does not imply that dependencies preserve those fields or any other storage.

### Eligibility and traversal order

Before each possible indirect call, the function compares the current index with the captured bound using signed ordering.

When the captured bound is less than or equal to the index, the function returns. Otherwise, that index is eligible for dispatch.

Consequences:

- A negative bound permits no indirect calls.
- A zero bound permits no indirect calls.
- A positive bound permits indices from zero through one less than the bound, subject to earlier interruption.
- An index equal to the bound is never dispatched.
- Eligible indices are visited in increasing order without skipping an index on the normal zero-result path.

These statements are conditional on reached arithmetic, accesses, and dependency calls completing as required.

### Dispatch-location arithmetic

For each eligible index, the function reads slot 0 as a signed integer. It adds decimal 64 to that value in the signed integer type. Only after that addition is the result converted to a pointer type used to obtain the indirect target.

This is not established merely as pointer-relative addressing by 64 bytes. The distinction matters in two ways:

1. **Signed representability.** Under literal signed-integer semantics, the sum must be representable in that integer type for defined evaluation of the addition. A valid-looking machine address does not remove this requirement.
2. **Pointer interpretation.** Even a representable integer sum does not establish that its conversion produces a valid, aligned, readable dispatch location.

For a signed type whose largest value is its maximum, the addition is representable when the slot-0 value is no greater than that maximum minus 64. Adding positive 64 does not create a lower-bound overflow for a value already representable in that type.

The evidence does not establish that the executable instead uses wrapping machine-address arithmetic, unsigned arithmetic, or a particular pointer reconstruction rule. Those possibilities remain **documented_only** pending ABI or instruction evidence.

After conversion, the resulting location is used to obtain the callable target. The representation does not establish a complete dispatch-table layout, a conventional table slot number, or a pointer width.

### Target resolution and call

Dispatch resolution occurs inside the traversal, not once before it.

For each eligible index, the function:

- Reads the current dispatch integer from slot 0.
- Performs the signed addition and pointer conversion described above.
- Obtains the indirect target through that location.
- Invokes the target with the original input pointer and current index.

A prior indirect call may change slot 0 or the storage from which the target is obtained. A later iteration can therefore resolve a different target. No preservation guarantee is established for either dispatch field or dispatch storage.

### Returned-value inspection

When an indirect call returns normally, its result is interpreted as an integer pointer. The function immediately reads the leading integer through that pointer.

There is no explicit check for nullness, a sentinel pointer, an error status, or sufficient readable extent before this access.

If the leading integer is zero, the index is increased by one and eligibility is checked again.

If the leading integer is nonzero:

- Traversal stops.
- The index is not incremented.
- No later index is dispatched.
- F-feee9156a257 is invoked without explicit arguments.
- No explicit release or other ownership operation precedes that invocation.

Positive and negative nonzero integers select the same branch.

The result pointer is not explicitly saved for later iterations. This establishes neither its ownership nor its validity after the immediate read.

### Traversal arithmetic

The bound and index use the signed integer type shown in the representation.

The increment is reached only after an eligible index produces a zero leading value. Eligibility requires the index to be strictly less than the captured bound.

For any positive bound representable in that same type, the final necessary increment changes one less than the bound into the bound. The next eligibility check returns. Traversal arithmetic therefore does not require signed overflow, even when the bound is the largest representable positive value.

This conclusion concerns the index only. It does not validate the separate dispatch addition, pointer conversions, memory accesses, or dependency behavior.
