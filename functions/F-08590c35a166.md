# F-08590c35a166

## Purpose

F-08590c35a166 performs a conditional two-stage inquiry and maps selected result bits to a 32-bit return value. Each stage permits one retry after an external call with argument 1000. The second stage is reached only when bit 0 of the first stage’s inspected value is set.

Established behavior comprises the inquiry selectors, writable-slot handling, retry sequence, diagnostic calls, bit-test precedence, and return constants. A device-status interpretation is inferred intent only. The semantic meanings of the selectors, bits, and return codes are not established.

This contract describes normal control flow when dependencies return. It does not assume that dependencies preserve globals, leave exposed storage unchanged, or implement any particular ownership policy.

## Interface

### Arguments and result

The function accepts four 32-bit arguments and returns a 32-bit value.

| Argument position | Established use |
|---|---|
| First | Not read by the supplied function body. |
| Second | Not read by the supplied function body. |
| Third | Initializes the first local unsigned 32-bit inquiry slot. |
| Fourth | Initializes the second local unsigned 32-bit inquiry slot. |

The third and fourth arguments are input values, not caller-supplied output addresses. Both slots are initialized before the first inquiry. Initialization preserves all 32 bits; it does not narrow either value to a byte.

The function passes each slot’s address to F-03fd77b56fa0:

- Selector 15 is paired with the first slot.
- Selector 9 is paired with the second slot.

The storage consists of two separate 32-bit objects. Their relative addresses, adjacency, alignment beyond what valid access requires, and surrounding storage layout are not contractual.

F-03fd77b56fa0 supplies a 32-bit status. Exactly zero selects the unsuccessful-attempt path. Every nonzero pattern selects the successful-attempt path, including a pattern interpreted as negative by a signed 32-bit interpretation. The slot’s value and the returned status serve different purposes: the status controls retrying; the slot supplies bits for subsequent decisions.

### Return values

The following conditions describe normal completion. Slot conditions refer to values actually inspected, not necessarily initial arguments or values reported by an earlier dependency call.

| Result | Condition |
|---|---|
| `0x00000000` | A selector-15 attempt returns nonzero, and the subsequent first-slot test finds bit 0 clear. |
| `0x00000059` | Either stage receives zero status on both of its attempts. |
| `0x0000004C` | The second stage succeeds, and classification finds bit 0 set. |
| `0x0000004F` | Classification finds bit 0 clear and bit 6 set. |
| `0x0000004D` | Classification finds bits 0 and 6 clear and bit 1 set. |
| `0x0000004E` | Classification finds bits 0, 6, and 1 clear and at least one of bits 2 and 5 set. |
| `0x00000051` | Classification finds none of bits 0, 6, 1, 2, or 5 set. |

No other normal return value is established.

### Preconditions and lifetime

Valid execution requires dependency accesses to be compatible with the supplied objects’ sizes and lifetimes. Passing a writable slot address establishes neither the dependency’s actual access width nor permission to access adjacent storage.

The slots exist only during this invocation. The body performs no allocation, release, or explicit ownership transfer. Whether a dependency retains a slot address is unknown; the function does not enforce non-retention.

## Behavior

### First-stage inquiry and retry

After initializing both slots, the function invokes F-03fd77b56fa0 with selector 15 and the first slot’s address.

A nonzero status proceeds directly to the first-slot bit test. Zero status instead causes a call to the unmapped external dependency with argument 1000. After that call returns, the function makes one further selector-15 inquiry using the same first-slot address.

There is no caller-side reinitialization before this retry. Any value left by the first attempt remains available unless an intervening action changes it. In particular, the delay-associated call is not established to preserve the slot. An inquiry dependency could retain the address, and effects reachable through another dependency are not known.

If the retry returns zero, the function supplies a first-stage failure-message reference to F-1b7fa166ef25. After that diagnostic call returns, the function returns `0x00000059`. It does not inspect the first slot or attempt selector 9 on this path.

Following either nonzero selector-15 status, the function tests bit 0 of the first slot’s then-current value:

- Clear: return `0x00000000`.
- Set: begin the selector-9 stage.

Other first-slot bits do not affect this decision. For example, a value of 2 does not enable the second stage merely because it is nonzero.

A write of 1 by the initial unsuccessful attempt does not, by itself, guarantee progression after a nonwriting successful retry. Progression depends on the actual post-retry value. Retention of that written 1 additionally requires that no intervening action change the first slot.

### Second-stage inquiry and retry

The second slot was initialized before the first stage; it is not initialized again when the second stage begins.

The function invokes F-03fd77b56fa0 with selector 9 and the second slot’s address. A nonzero status advances to value reporting. A zero status causes the external call with argument 1000, followed by one retry with selector 9 and the same second-slot address.

The caller does not restore the fourth argument’s value before retrying. Values written during unsuccessful attempts can therefore affect subsequent behavior, subject to intervening changes.

If the second selector-9 attempt also returns zero, the function supplies a second-stage failure-message reference to F-1b7fa166ef25 and then returns `0x00000059`. This path performs neither successful-value reporting nor classification.

A nonzero inquiry status does not establish that the dependency replaced the slot contents. If it does not write, subsequent processing uses the value actually remaining in the slot. That may be its initial value, a value from an unsuccessful attempt, or another value produced by intervening effects.

### Successful second-stage reporting

After a nonzero selector-9 status, the function evaluates the second slot masked with `0x000000FF` and supplies that result, together with a value-reporting message reference, to F-1b7fa166ef25.

The numeric argument is a 32-bit masked value in the inclusive range 0–255. The operation neither modifies the slot nor narrows its stored representation.

Reporting occurs before classification. The reported numeric argument is determined before the diagnostic call; classification occurs after that call returns. Therefore, equality between the reported byte and the subsequently classified low byte requires noninterference with the second slot during the diagnostic call. Such noninterference is not established by the dependency contract.

### Classification and precedence

After successful-value reporting returns, classification applies these priorities:

| Priority | Relevant condition | Result |
|---|---|---|
| Highest | Bit 0 set | `0x0000004C` |
| Next | Bit 0 clear; bit 6 set | `0x0000004F` |
| Next | Bits 0 and 6 clear; bit 1 set | `0x0000004D` |
| Next | Higher-priority bits clear; either bit 2 or bit 5 set | `0x0000004E` |
| Default | All tested bits clear | `0x00000051` |

The mask `0x00000024` selects bits 2 and 5. Either bit suffices; both are not required.

Bits 3, 4, 7, and 8–31 do not directly influence classification. They may appear in the stored value, but the decision masks exclude them. Diagnostic reporting includes bits 0–7 and excludes bits 8–31.

No dependency call occurs between these classification decisions. The supplied body supports ordered logical inspections; it does not establish a machine-level memory-read count or a concurrency model for asynchronous changes.

The decisions use bitwise masks and zero comparisons. There is no arithmetic accumulation, signed ordering, or overflow-dependent result.

## Side effects

### Direct effects

The body initializes the two local slots and exposes their addresses through inquiry calls. It contains no direct write to caller-provided output storage or global storage and no explicit dynamic allocation or deallocation.

This is a statement about the body, not a guarantee about transitive effects of dependencies.

### External interaction bounds

Assuming all called dependencies return normally, one invocation performs:

- Between one and four calls to F-03fd77b56fa0.
- Between zero and two calls to the unmapped external dependency.
- Either zero or one call to F-1b7fa166ef25.

Each external call with argument 1000 occurs after the first zero status of its own stage and before that stage’s retry. There is no such call after a second zero status.

The diagnostic alternatives are mutually exclusive:

- First-stage success with bit 0 clear: no diagnostic.
- Exhausted retries in either stage: one stage-associated failure diagnostic.
- Successful second stage: one value diagnostic.

The body does not inspect any diagnostic return value.

## Acceptance examples

These are conditional consequences of static control flow, not executed tests. Dependencies are assumed to return normally. Successful-second-stage examples assume that the value-reporting diagnostic does not change the second slot before classification. Additional preservation conditions are explicit where retention across calls matters.

| Scenario | Required behavior |
|---|---|
| Selector 15 returns nonzero, and the first slot is 2 when inspected. | Return `0x00000000`; no selector-9 call, delay-associated call, or diagnostic. |
| Selector 15 returns zero on both attempts. | Two selector-15 calls with one intervening external call of 1000; one first-stage failure diagnostic; return `0x00000059`. |
| Selector 15 returns zero, then nonzero; its inspected slot is 1. Selector 9 succeeds with slot value 0. | One delay-associated call; value diagnostic argument 0; return `0x00000051`. |
| Both stages return zero initially and nonzero on retry; the first-stage inspected value enables stage two, and the second-stage value is `0x40`. | Four inquiry calls, two intervening calls of 1000, diagnostic argument 64, and return `0x0000004F`. |
| The first stage enables stage two; selector 9 returns zero twice. | One second-stage call of 1000; one second-stage failure diagnostic; return `0x00000059`; no value diagnostic. |
| Successful second-slot value is `0x43`. | Report 67; return `0x0000004C`, because bit 0 outranks the other tested bits. |
| Successful second-slot value is `0x42`. | Report 66; return `0x0000004F`, because bit 6 outranks bit 1. |
| Successful second-slot value is `0x26`. | Report 38; return `0x0000004D`, because bit 1 outranks bits 2 and 5. |
| Successful second-slot value is `0x04` or `0x20`. | Report 4 or 32 respectively; return `0x0000004E` in either case. |
| Successful second-slot value is `0xFFFFFF98`. | Report 152; return `0x00000051`, because all classified bits are clear. |

**Retry retention with explicit preservation.** Suppose the first selector-15 attempt writes 1 and returns zero, the intervening external call leaves the first slot unchanged, and the retry returns nonzero without writing. Provided no other action changes that slot before its bit test, the inspected value remains 1 and selector 9 is reached. The third argument is not restored between attempts.

**Retry retention without preservation.** Under the same initial write and nonwriting retry, suppose instead that the intervening dependency changes the first slot to 2 through an already-retained address, and nothing changes it afterward. The first-slot test finds bit 0 clear, so the function returns `0x00000000` without a selector-9 call. This example is conditional on that dependency behavior; the body neither establishes nor rules it out.

**Unwritten second slot.** If selector 9 succeeds without writing, and no dependency or other action has changed the second slot since initialization, reporting and classification use the fourth argument’s value.

**Diagnostic interference.** If reporting evaluates a second-slot value of `0x40`, it supplies numeric argument 64. If the diagnostic then changes that slot to 1 before returning, classification returns `0x0000004C`, assuming valid accesses and no subsequent change. The reported byte does not bind the later result.
