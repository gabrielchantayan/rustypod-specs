# F-4a8b238c5db4

## Purpose

F-4a8b238c5db4 dispatches a one-byte command through an object obtained from F-b7af80e829ec. A 16-bit field in the command descriptor gates dispatch. Supported commands invoke different virtual operations, sometimes consult their results, and return a 32-bit outcome.

One command delegates to F-d266e8cfbbe8 and can update a 32-bit field in the caller-supplied context. Another command reads a context byte and passes a derived Boolean value to a virtual operation.

The established behavior is dispatch and result mapping. The domain meanings of the commands, object, context fields, and numeric outcomes are unknown. Descriptions such as “success,” “unsupported,” or “busy” would be inferred intent, not established semantics.

## Interface

### Inputs and result

The supplied representation exposes four 32-bit arguments:

| Argument | Established use |
|---|---|
| Context address | Forwarded to F-d266e8cfbbe8. Used as the base for a byte read at offset `0x2EC` and a 32-bit write at offset `0x2F4`, on particular command paths. |
| Descriptor address | Used as the base for a 16-bit field at offset `0x0C` and a 32-bit pointer field at offset `0x08`. |
| Third argument | Copied into a 32-bit temporary. That temporary is reset before its address is passed to F-d266e8cfbbe8. |
| Fourth argument | Copied into another 32-bit temporary. That temporary is also reset before its address is passed to F-d266e8cfbbe8. |

The function returns a 32-bit value. Normal completed paths return `0`, `2`, or `4`, except command `1`, which propagates the 32-bit result from F-d266e8cfbbe8.

The third and fourth incoming values do not affect any established dispatch decision, dependency argument, context write, or normal return value. Their initial copies are overwritten before the temporaries are passed to a dependency.

### Relevant layouts

| Storage | Offset | Access |
|---|---:|---|
| Descriptor | `0x0C` | 16-bit field, interpreted as a signed short and compared with `1` |

## Behavior

### Entry sequence and gate

The established sequence is:

1. Read the descriptor’s 16-bit field at offset `0x0C`.
2. Initialize the default result to `4` and copy the third and fourth arguments into temporary 32-bit storage.
3. Call F-b7af80e829ec and retain its returned object pointer.
4. Compare the previously read 16-bit value with `1`.
5. If it differs from `1`, return `4`.

F-b7af80e829ec is therefore called even when the descriptor field prevents command processing. A change to that field during the dependency call does not change the captured value used by this gate.

If the gate permits processing, call the retrieved object’s virtual entry at offset `0x108`. Retain its 32-bit result for commands `5` and `6`. This call also occurs for every other command reaching dispatch, although those commands do not use its result.

Next, read the descriptor’s command pointer at offset `0x08`. If it is null, call F-a817d8d58c10. The supplied static representation marks that call as non-returning. No normal result from F-4a8b238c5db4 is established for this path.

For a non-null pointer, the command selection uses a further read of the descriptor’s pointer field and then reads the pointed-to byte. The null check does not establish a permanently cached command pointer. No synchronization or atomic snapshot is provided.

### Command behavior

Each sequence below begins after the common entry sequence.

| Command byte | Established operations and result |
|---:|---|
| `0` | Perform no further dispatch call. Return `4`. |
| `1` | Call virtual entry `0xAC`, ignoring its result. Zero both temporary 32-bit words. Call F-d266e8cfbbe8 with the context address, the address of the temporary corresponding to the fourth argument, and then the address of the temporary corresponding to the third argument. Retain its 32-bit return value. If the low byte of the third-argument temporary equals `2`, call virtual entry `0xF8` and write its 32-bit result to context offset `0x2F4`. Return the retained result from F-d266e8cfbbe8. |
| `2` | Call virtual entry `0xA8`, ignoring its result. Return `0`. |
| `3` | Call virtual entry `0xC0` with the object and a 32-bit argument of `3`. Ignore its result and return `0`. |
| `4` | Call virtual entry `0xC4` with the object and a 32-bit argument of `3`. Ignore its result and return `0`. |
| `5` | If the earlier result from entry `0x108` is zero, return `4`. Otherwise call entry `0xB0` with the object and `1`. If that result is nonzero, return `0`. If it is zero, call entry `0x114`: return `2` if this final result is zero, otherwise return `0`. |
| `6` | Apply the same decision structure as command `5`, using entry `0xB4` for the call with argument `1`, and entry `0x118` for the fallback call. |
| `7` | Call entry `0xB8`, ignoring its result. Then call entry `0x11C`. Return `0` if the second result is zero; return `2` if it is nonzero. |
| `8` | Call entry `0xC0` with the object and `1`. Return `2` for a zero result, otherwise `0`. |
| `9` | Call entry `0xC4` with the object and `1`. Return `2` for a zero result, otherwise `0`. |
| `10` | Execute the multi-stage sequence below. |
| `11` | Call entry `0x10C`. If its result is nonzero, call entry `0xAC`, ignoring that call’s result. Then call entry `0x110`. Return `2` if this final result is zero, otherwise `0`. |
| Any other byte | Perform no further dispatch call. Return `4`. |

The result mapping for command `7` is deliberately distinct: its final nonzero result produces `2`. Commands `5`, `6`, `8`, `9`, `10`, and `11` produce `2` when their respective final tested result is zero.

### Command 10

Command `10` has the following ordered behavior:

1. Call virtual entry `0x110`.
2. If its 32-bit result is nonzero, call entry `0xAC`. Ignore the latter result.
3. Call entry `0x120`, whose result is represented as 64 bits.
4. Test the low 32 bits of that result against zero.
5. If the low 32 bits are nonzero:
   - Read the context byte at offset `0x2EC`.
   - Derive the 32-bit value `1` when the byte equals `2`, or `0` otherwise.
   - Call entry `0x28` with the object and that derived value.
   - Zero the temporary associated with the third argument.
   - Call entry `0xA4` with the object, the 32-bit bit pattern `0xFFFFFFFF`, and a 32-bit zero.
6. Call entry `0x10C`, irrespective of the low-half test.
7. Return `2` if this final result is zero; otherwise return `0`.

The high 32 bits of the entry `0x120` result are extracted into intermediate result storage, but do not determine the eventual normal return. They are superseded by later processing.

No semantic interpretation of `0xFFFFFFFF` is established. It is the all-ones 32-bit argument; interpreting it as signed `−1`, an identifier, or a sentinel would require the callee’s contract.

## Side effects

### Direct memory effects

The only established direct write into caller-provided storage is the command `1` write at context offset `0x2F4`.

That write occurs only when the low byte of the temporary associated with the third argument equals `2` after F-d266e8cfbbe8 returns. The other 24 bits do not affect this condition.

The stored value is the 32-bit result of virtual entry `0xF8`, not the return value of F-d266e8cfbbe8. The write follows the call to entry `0xF8`. It is not conditional on F-d266e8cfbbe8 returning zero or any other particular outcome.

Command `10` directly reads context offset `0x2EC` only when the low 32 bits returned by entry `0x120` are nonzero.

There are no established direct writes to the descriptor or command storage.

### Indirect effects and ordering

All dependency calls may have additional effects that are unknown here. In particular, this contract does not assume that they preserve globals, leave the descriptor or context unchanged, retain the same virtual table, or preserve object lifetime.

The retrieved object pointer is retained across calls. Subsequent virtual operations resolve through that object’s table as shown by the supplied representation; there is no established snapshot of all target entries before dispatch.

For command `1`, the temporary addresses become available to F-d266e8cfbbe8. The caller supplies temporary storage, not an explicit heap allocation or ownership transfer. Whether the dependency retains those addresses is unknown; validity after this function returns is not established.

There is no visible allocation, release, reference-count adjustment, rollback, retry, or cleanup operation in this function. That observation does not establish memory ownership or exclude such operations inside dependencies.

If a dependency fails to return, later calls, direct writes, and normal return values on that path do not occur.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. They assume valid reached memory, returning dependencies unless stated otherwise, and no unspecified intervening mutation.

1. **Gate rejection still obtains the object.**  
   Given an initial 16-bit descriptor field of `0`, F-b7af80e829ec is called and the function returns `4`. No virtual entry is called, and the command pointer is not read.

2. **Changing the gate after its initial read does not reopen dispatch.**  
   Given an initially captured field value other than `1`, a change to the descriptor by F-b7af80e829ec does not alter the return of `4`.

3. **Null command handling follows the common virtual call.**  
   Given a captured field value of `1` and a null command pointer when checked, entry `0x108` is called before F-a817d8d58c10. No normal return is specified.

4. **Unsupported command preserves the default outcome.**  
   Given command byte `255`, the common entry `0x108` call occurs, no command-specific virtual call occurs, and the result is `4`.

5. **Command 1 tests one byte, not a full word.**  
   If F-d266e8cfbbe8 leaves the relevant temporary with value `0x12345602`, the call to entry `0xF8` and the context write occur. With value `0x00000200`, they do not.

6. **Command 1 preserves its dependency result.**  
   If F-d266e8cfbbe8 returns `7` and sets the tested low byte to `2`, and entry `0xF8` returns `0x89ABCDEF`, the context field receives `0x89ABCDEF` and this function returns `7`.

7. **Command 5 can stop at either earlier decision.**  
   If entry `0x108` returned zero, neither entry `0xB0` nor entry `0x114` is called, and the result is `4`. If the earlier result is nonzero and entry `0xB0` returns nonzero, entry `0x114` is skipped and the result is `0`.

8. **Command 7 uses its distinct result polarity.**  
   After entry `0xB8`, a nonzero result from entry `0x11C` produces `2`; a zero result produces `0`.

9. **Commands 3 and 8 treat the same entry differently.**  
   Command `3` passes `3` to entry `0xC0` and returns `0` regardless of that call’s result. Command `8` passes `1` and maps a zero result to `2`.

10. **Command 10 ignores a nonzero high half for its conditional block.**  
    If entry `0x120` returns a nonzero high half and a zero low half, there is no direct context-byte read and neither entry `0x28` nor entry `0xA4` is called. Entry `0x10C` still determines the final result.

11. **Command 10 derives an exact equality flag.**  
    With a nonzero low half from entry `0x120`, context byte `2` causes argument `1` to entry `0x28`; any other byte causes argument `0`. Entry `0xA4` follows, then entry `0x10C`.
