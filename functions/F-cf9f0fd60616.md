# F-cf9f0fd60616

## Purpose

F-cf9f0fd60616 conditionally performs an associated-object operation, clears two object fields, and then performs an ownership-sensitive state transition whose final step may be delegated to another function.

The established contract consists of access widths, dependency calls, ordering constraints, conditional writes, and returned statuses. “Owner,” “count,” “mode,” and “release” are descriptive interpretations of the observed operations. They do not establish synchronization, resource reclamation, or a particular object type.

The operation is not transactional. A nonzero return may occur after dependency effects and direct field clears. No rollback is visible.

## Behavior

### Entry and associated-object operation

The function computes the address at base +8 and passes it to an entry dependency whose opaque ID is not supplied. No result from that call is visibly tested.

After the entry dependency returns, the function reads the 32-bit word at +108.

If that word is zero, associated-object processing is skipped. Otherwise, F-194cdec98e23 is called with base +4.

If this first result is zero, associated-object processing ends. If it is nonzero, the following sequence occurs:

1. F-194cdec98e23 is called a second time with base +4.
2. F-06393bd37aa5 receives the second result as its first argument and base +76 as its second argument.
3. F-194cdec98e23 is called a third time with base +4.
4. F-a732e198fd4e is called with no explicit arguments.

The first accessor-like result controls entry into this sequence. The second result supplies the argument to F-06393bd37aa5; it is not checked for zero. The third result has no explicit consumer in the supplied body.

These calls must not be collapsed into a single cached lookup. Their results may differ, and each dependency may have effects. Whether the third result has significance through an implicit calling convention remains unresolved.

### Unconditional field clears

After the associated-object branch, the function writes:

1. A 32-bit zero at +68.
2. A 32-bit zero at +72.

These stores occur whether the +108 gate is zero, the first F-194cdec98e23 result is zero, or the full associated-object sequence runs. They precede all later normal return paths.

The function does not directly clear +108.

### Embedded-address check and global comparison

The previously computed address at base +8 is then checked for null. If it is null, the function returns 26 without performing the embedded-word/global comparison.

For a nonnull address, the function compares:

- The 32-bit word at base +8.
- A 32-bit value read from global storage at this comparison.

Both comparison operands are obtained after the preceding calls and the stores at +68 and +72. Their relative read order is not established.

It then calls F-196812b4b122. Only after that call returns does it read the 32-bit field at +12 and compare it with the dependency result.

### Selected decrement behavior

When the ownership comparison succeeds, the captured mode selects the next action.

Decrement behavior is selected exactly when bits 4 and 5 of the 16-bit snapshot form the value 2: bit 5 is set and bit 4 is clear. Bits 0–3 and 6–15 do not affect this selection.

For any other mode, the function proceeds directly to final release without reading the count for a decrement.

For the selected mode, it reads the 16-bit field at +26 through a signed 16-bit interpretation, subtracts one, narrows the result back to 16 bits, writes it to +26, and tests that narrowed result for zero.

There is no visible positive-count check, saturation, or underflow rejection. In the represented narrowing behavior:

- An initial bit pattern of 0x0002 becomes 0x0001.
- An initial bit pattern of 0x0001 becomes 0x0000.
- An initial bit pattern of 0x0000 becomes 0xFFFF.

The subtraction requires no signed 32-bit overflow: even decrementing the minimum signed 16-bit value remains within signed 32-bit range. The boundary concern is narrowing back to 16 bits; target-specific language guarantees for that conversion are not independently supplied.

If the stored 16-bit result is nonzero, the function returns zero without directly clearing +12 or calling F-259d2fe281b0. If it is zero, final release follows.

2. Write a 32-bit zero at +12.
3. Call F-259d2fe281b0 with base +28.

## Acceptance examples

These are conditional consequences of static evidence, not executed tests. Unless a case says otherwise, assume valid storage, normal dependency returns, and no dependency changes to fields relevant to that case.

1. **Associated-object gate disabled.**  
   If +108 is zero after the entry dependency, none of F-194cdec98e23, F-06393bd37aa5, or F-a732e198fd4e is called. The +68 and +72 clears still occur.

2. **First accessor-like result is zero.**  
   With +108 nonzero and the first F-194cdec98e23 result zero, exactly one such call occurs. The function then performs the unconditional clears.

3. **Results are not interchangeable.**  
   If the first accessor-like result is nonzero and the second is zero, F-06393bd37aa5 receives zero. A third accessor-like call and then F-a732e198fd4e still follow.

4. **Earlier dependency changes the global.**  
   Suppose an earlier dependency changes the global from one value to another, and no later effect changes it again. The comparison uses the value read at comparison time, not the value that existed at function entry. Delegation depends on equality with that later value.

5. **An unconditional clear aliases the global.**  
   If global storage is exactly the 32-bit destination at +68, the clear leaves it zero before comparison, assuming valid accesses and no intervening modification. The comparison is therefore against zero. This is conditional on aliasing, not a claim that aliasing occurs.

6. **Comparison match and delegated nonzero result.**  
   If the embedded word and global read compare equal and F-621dae46a146 returns −7, the function returns −7. Both unconditional clears have already occurred; no ownership query follows.

7. **Comparison mismatch.**  
   If the compared values differ, F-621dae46a146 is not called. Ownership processing follows directly.

8. **Ownership mismatch.**  
   If the +12 value read after F-196812b4b122 differs from its result, the function returns 5 without a direct count update or final-release call.

9. **Selected mode, count two.**  
   With matching ownership and count 2, the count becomes 1 and the function returns zero. There is no direct owner clear or F-259d2fe281b0 call.

10. **Selected mode, count one.**  
    The decrement writes zero, final release writes zero again, +12 is cleared, and F-259d2fe281b0 determines the return value.

11. **Selected mode, count zero.**  
    The count becomes 0xFFFF. The function returns zero without final release under the represented narrowing behavior.

12. **Other mode.**  
    With matching ownership and a mode outside the selected pattern, final release occurs regardless of the existing count. If F-259d2fe281b0 returns 9, the function returns 9 after the direct clears.

13. **Mode changes during the ownership query.**  
    A change to +22 by F-196812b4b122 does not alter the captured mode decision. A change to +12 can alter the ownership comparison because that field is read afterward.
