# F-4b9449c1ba9e

## Purpose

F-4b9449c1ba9e describes an alias-sensitive transformation of memory, followed by arithmetic-dependent addressing and dependency interactions. Its contract concerns mixed-width accesses, retained values, fresh observations, and the order in which writes can influence later reads.

Sixteen recurring transfer boundaries organize the behavior. These boundaries do not imply transactions, independent objects, ownership transfer, or a recognized data structure.

Two byte writes use values with no established initialization. Behavior beyond either use is therefore conditional: the supplied representation describes a continuation, but does not establish that execution can validly reach it.

## Interface

### Inputs and observable results

The explicit inputs are a signed 32-bit **entry address** and an opaque 8-bit **opening byte**.

Incoming execution state additionally provides:

- Signed 32-bit address-bearing values called **directory**, **initial region**, and **recurring region**.
- An opaque 32-bit **opening word**.
- An incoming callable, designated **F-01**.

Sixteen external 32-bit **routing sources** participate, one per transfer. Their contents are read as address-bearing data, not invoked by those transfers.

Another external source supplies the first argument to **F-cdec09f5d432**. Its width is unknown.

No value result is specified. Observable results consist of memory changes and dependency interactions.

### Widths and validity conditions

Offsets are hexadecimal byte offsets. A **word** is 32 bits; a **halfword** is 16 bits. A **character** access occupies one byte but retains unresolved character signedness and conversion rules.

Selectors and the later arithmetic factor are signed halfwords promoted to signed 32-bit values. When a selector is used as an address, its promoted numerical value is used directly.

Opaque-byte stores and character stores must remain distinct. In particular, a character read subsequently used as an address may promote to a negative value.

Address arithmetic uses the represented signed 32-bit operations. Validity of addition, multiplication, and left shift is a precondition where required by the execution model. Later narrowing does not repair an invalid earlier operation. Multiplication by two and left shift by one are distinct operations.

Every reached access requires a valid address conversion, accessible storage, sufficient extent and lifetime, suitable permissions, and any required alignment. No checks establish these conditions. Byte order and actual alias relationships are unknown.

## Behavior

### Transfer terminology and shared guarantees

Each transfer has a **replacement**, a signed **selector**, a **payload region**, a **publication region**, and an **outgoing recipient**. Its captured payload is a word.

The transfer boundary has this ordering:

- A halfword conversion of the replacement is installed at the installation address.
- Payload-region word 0x44 is captured.
- Publication-region word 0x54 receives the publication-region address.
- The routing source supplies the retained outgoing recipient.
- A subsequent observation of that source supplies replacement word 0x44.
- Outgoing-recipient word 0x14 receives the captured payload.

Ordinarily, the installation address is payload region plus selector. Transfer 7 instead uses twice the recurring region plus its incoming recipient.

Installation can change the captured payload through overlap. Publication cannot revise an already captured payload. Likewise, the replacement-content write cannot change the already retained outgoing recipient. These are ordering guarantees, not atomicity guarantees.

For every transfer after the first, **incoming recipient** and **incoming payload** mean the preceding transfer’s retained recipient and captured word. They are not refreshed from their previous storage.

### Opening and early-transfer ordering

**Transfer 1.** The selector is retained before entry byte 0x15 receives the opening byte. Replacement acquisition follows that store. Thus an overlapping opening store can affect the replacement but not the selector.

Initial word 0x24 receives the opening word before initial word 0x74 is retained as **opening upper content**. Before installation, initial word 0x14 receives the entry address, recurring character offset 0x11 receives the entry address’s character conversion, and replacement character offset 0x09 receives the initial address’s character conversion, in that order.

**Transfer 2.** Recurring character offset 0x11 first receives the recurring address shifted left once and then character-converted. Between selector and replacement acquisition, entry character offset 0x09 receives incoming payload. After replacement acquisition, a fresh entry-word-0x64 observation supplies recurring character offset 0x11.

**Transfer 3.** The same shifted-recurring preparation precedes a retained entry-word-0x64 observation. Replacement and selector acquisition follow. Before installation, opening upper content reaches entry word 0x54; recurring then reaches incoming-recipient character offset 0x09; incoming recipient reaches replacement character offset 0x0D.

**Transfer 4.** The entry-word-0x64 value retained in transfer 3 supplies recurring character offset 0x11. Following replacement and selector acquisition, incoming-recipient character offsets 0x01 and 0x0D receive incoming recipient and opening upper content respectively. Replacement character offset 0x09 then receives incoming recipient.

**Transfer 5.** Shifted-recurring preparation precedes selector acquisition. Before replacement acquisition, selector-as-address word 0x44 establishes the **first support address**. A fresh entry-word-0x64 observation supplies recurring character offset 0x11 afterward.

All character destinations above receive character conversions of the stated values.

### Support state and the addressable anchor

**Transfer 6.** Following shifted-recurring preparation, first-support word 0x64 is retained. Recurring word 0x44 then supplies an auxiliary address before selector acquisition.

Before replacement acquisition, incoming-payload word 0x54 receives recurring; recurring byte 0x11 receives an opaque-byte conversion of the retained support observation; auxiliary word 0x44 receives incoming recipient; and a fresh selector-as-address-word-0x44 observation establishes the **second support address**, in that order. The same retained support byte is stored again at recurring offset 0x11 after replacement acquisition and before installation. It is not reread from support storage.

**Transfer 7.** After shifted-recurring preparation and selector acquisition, selector-as-address word 0x44 initializes an addressable local **anchor slot**, at local offset 0x34. Replacement acquisition follows.

Second-support word 0x64 then supplies recurring character offset 0x11. The current anchor’s word 0x04 is retained as **low-field content**, followed by incoming-recipient word 0x74 as **upper marker**. Low-field content reaches recurring word 0x54 before the exceptional installation. Shared publication subsequently replaces that word with recurring. After delivery, low-field content supplies recurring character offset 0x11.

The **current anchor** always means the slot’s current contents. Indirect writes overlapping the slot may change it.

### Working-region transfers

**Transfer 8.** Current-anchor word 0x64 is retained before replacement and selector acquisition. Current-anchor word 0x54 then receives upper marker, before working selection. Selected-working character offset 0x0D receives incoming recipient before installation. After delivery, selected-working character offset 0x11 receives the retained anchor observation.

**Transfer 9.** Replacement and selector acquisition precede the upper-marker store to current-anchor word 0x54. Working selection and its incoming-recipient character store at offset 0x0D occur before payload redirection through incoming-payload word 0x14. Upper-marker word 0x54 then receives current anchor before installation. The selected working and redirected payload need not coincide.

**Transfers 10–12.** Each begins by storing a character conversion of working shifted left once at working offset 0x11. Selector acquisition precedes the replacement-character read.

### Final transfer pair

Transfer 15 starts with shifted-previous-working preparation at character offset 0x11. Both transfers then retain current-anchor word 0x64 before replacement and selector acquisition.

Transfer 16 has an additional preselection window. Incoming-payload word 0x54 receives previous working; previous-working byte 0x11 consumes the **first unresolved-origin byte**; replacement word 0x44 receives incoming recipient. Working selection occurs afterward.

Following working selection, both transfers share these ordered preparation constraints:

- Replacement word 0x54 receives replacement.
- The word at incoming recipient plus incoming payload receives cross-region content.
- Incoming-recipient word 0x14 receives replacement.
- A fresh cross-region-content-word-0x44 observation supplies incoming-recipient character offset 0x0D.
- Selected-working character offset 0x0D receives replacement.

After delivery, the retained anchor observation reaches selected-working offset 0x11: character-converted in transfer 15, opaque-byte-converted in transfer 16. This later assignment does not initialize the byte already consumed during transfer 16.

### Arithmetic-dependent continuation

Final-working word 0x44 supplies a retained signed **seed**. The signed halfword at final working plus final recipient supplies the promoted **factor**.

Factor-as-address word 0x54 receives the factor five times. These repeated publications have distinct intervening effects:

| Interval | Behavior before the next publication |
|---|---|
| First to second | Final-recipient opaque-byte offset 0x11 receives character-converted final working. |
| Second to third | A character store repeats that value; destination traversal, overwrite, and late-region selection occur. |
| Third to fourth | Final-recipient character offset 0x11 receives old content; the late-payload slot is initialized; the further product is formed. |
| Fourth to fifth | The second unresolved byte is consumed; product observations and recipient updates occur. |

Destination traversal begins at factor multiplied by seed. Its word 0x44 supplies an address; that address’s word 0x74 supplies another address; the latter’s word 0x14 supplies the **resolved destination**.

Resolved-destination word 0x14 is retained as **old content**, then overwritten with final working shifted left once. Old-content word 0x14 is freshly observed only afterward. Factor multiplied by that observation selects the **late region**. Aliasing can therefore make the overwrite affect late-region selection.

After the third publication and the old-content character store, late-region word 0x74 initializes an addressable **late-payload slot**, at local offset 0x108. The **further product** is factor multiplied by late region, not by the slot’s contents.

After the fourth publication, final-recipient byte 0x11 consumes the **second unresolved-origin byte**. Further-product word 0x44 is then retained, followed by current-anchor word 0x74 as **terminal upper content**. Current late payload supplies final-recipient word 0x64; the retained product observation supplies final-recipient character offset 0x09. A fresh further-product-word-0x44 observation then supplies further-product character offset 0x11.

After the fifth publication, an opaque-byte conversion of current late payload reaches twice further product plus 0x11. The word at factor multiplied by further product plus 0x44 supplies **final content**, before current-anchor word 0x14 supplies a **common base**.

The final character destinations are, in order:

| Destination | Value |
|---|---|
| Current late payload + 0x01 | Terminal upper content |
| Common base + 0x11 | Final content |
| Common base + 0x09 | Twice further product |

The last value is arithmetic data, not another dereference. “Current late payload” includes any intervening modification of its addressable slot.

## Acceptance examples

These are conditional static criteria, not executed tests. They require valid accesses, admissible arithmetic and conversions, and continuation to the relevant boundary.

- **Opening overlap:** If entry byte 0x15 overlaps directory word 0x14, replacement acquisition observes post-write storage; the first selector remains retained.
- **Capture:** Installation overlapping payload word 0x44 can change delivery. Publication after capture cannot revise the captured value.
- **Routing:** A replacement-content write overlapping routing storage cannot redirect the recipient already retained.
- **Exceptional address:** Transfer 7 installs at twice recurring plus incoming recipient, even when ordinary payload-plus-selector addressing differs.
- **Signed selector:** A selector of −2 makes transfers 15–16 select working from numerical address 0x12.
- **Character promotion:** Character bits 0xFF produce replacement-word-0x44 address 0x43 if promoted to −1, or 0x143 if promoted to 255.
- **Support retention:** Transfer 6 repeats its retained support byte despite intervening changes to the support word.
- **Fresh observation:** An overlapping resolved-destination overwrite can affect the later observation selecting the late region.
- **Local layout:** With stable anchor 0x2000 and admissible shifts, local words 0x10 and 0x34 become 0x20000 and 0x200000. Neither operation targets numerical address 0x2034.
- **Unresolved bytes:** Treating either unresolved-origin byte as zero or as a valid arbitrary input is not justified.
- **Conditional calls:** Non-return from F-01 prevents later preparation. A trapping F-02 does not establish an F-03 invocation.
