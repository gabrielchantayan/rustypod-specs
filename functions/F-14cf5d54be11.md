# F-14cf5d54be11

## Purpose

F-14cf5d54be11 performs a staged, object-mediated lookup followed by a bounded search for a two-part key. A successful matching-record path issues three 32-bit result writes, invokes a cleanup-shaped dependency, and returns zero.

The established behavior includes:

- Obtaining a context word through an indirect object operation.
- Calling a setup dependency before using a working buffer address.
- Making a status-returning object operation, then comparing a buffer header against a value read from global storage.
- Decoding a header field to calculate the position for a second status-returning object operation.
- Examining at most twelve records, accepting each record’s type according to conditionally read global values.
- Stopping at the first matching key pair, including when that match subsequently fails decoding.
- Decoding the matching record’s value field twice on the successful path; only the first invocation has a checked status.

The function requires appropriate buffer contents when it inspects them. It does not establish which dependency produces or initializes those contents.

The interpretation as a keyed lookup over a staged representation is inferred intent. The data’s domain, field meanings, and ownership model remain unresolved.

## Interface

### Arguments

| Argument | Representation | Established use |
|---|---|---|
| Object reference | Pointer to an object with a 32-bit first word identifying an operation table | Supplies indirect operations at table byte offsets `0x2c` and `0x0c`. |
| Base position | Signed 32-bit integer | Passed unchanged to the first status-returning operation and used in two position calculations. |
| Primary key | Unsigned 32-bit integer | Compared against a record’s 32-bit primary key. |
| Secondary key | Unsigned 32-bit integer | Compared against a zero-extended 16-bit record field. |
| Position destination | Pointer to a 32-bit integer | Receives the calculated matching-record position. |
| Value destination | Pointer to a 32-bit word | Receives the repeated value decode’s low word. |
| Flags destination | Pointer to an unsigned 32-bit integer | Receives a logical right shift of a record field. |

Before invoking dependencies, the function initializes an eight-byte working area with the primary key followed by the secondary key, each occupying four bytes. Subsequent operations treat the first word of that area as a buffer address. Comparisons continue to use the original key arguments, not the potentially changed working-area words.

### Return value

| Return | Established condition |
|---|---|
| `0` | The successful path issued all three result writes and the final dependency returned. |
| `7` | All twelve candidates passed their respective type checks but none matched both keys. |
| `32` | Header comparison, checked decoding, or a candidate’s type check failed. |
| A nonzero status from either operation at table offset `0x0c` | Returned unchanged after the cleanup-shaped call. |

A propagated status may itself equal `7` or `32`; those numbers do not uniquely identify a failure branch.

### Preconditions

The function contains no explicit checks for null pointers, valid operation tables, buffer bounds, alignment, output writability, or pointer overlap.

Defined progress through a path requires valid storage and callable operations for every access that path reaches. The supplied representation does not establish byte order or exact alignment requirements. It also supplies no ownership guarantee for the working buffer.

The result destinations need to be writable only when reached on the successful path. That observation is not a guarantee that dependencies cannot access them indirectly.

## Behavior

### State references and retained values

Three global 32-bit storage locations participate in comparisons. This contract names them:

- **Header reference:** compared against the header marker.
- **First type reference:** checked first for every candidate.
- **Second type reference:** checked only when the first type comparison fails.

Their numeric contents, immutability, and stability are not established. They are reads of global state, not proven fixed constants or a captured permitted-type set.

Each indirect invocation resolves its operation through the object’s then-current first word. The operation table is not captured once at entry.

Likewise, buffer-address expressions use the working area’s first word at their respective points. In contrast, the candidate address captured after a successful type check is retained for key reads and later matching-record value and flags reads. Changing the working area’s first word does not retarget those retained-address accesses.

The context word, original arguments, and a successfully decoded matching-record position contribution are retained values rather than fresh reads from global storage.

### Initialization and first operation

The function initializes the two working words with the original keys.

It then resolves the object operation at table offset `0x2c` through the object’s current first word and invokes it with the object reference alone. Its returned 32-bit word becomes the context value.

Next, F-d9e0ae06e54d receives:

1. The working-area address.
2. The retained context word.

Its implementation is unavailable. Later accesses require the first working word to function as a buffer address, but the setup call’s allocation, initialization, and ownership behavior are not established.

The function then resolves the operation at table offset `0x0c` afresh and invokes it with:

1. The object reference.
2. The original base position.
3. The buffer address read from the first working word for this call.
4. The integer `1`.

A nonzero status causes a call to F-cc6f52873d53 with the working-area address, followed by return of that status unchanged. No header inspection follows.

### Header comparison and decoding

After a zero status, the function compares:

- A 32-bit field at byte offset `0x100` from the buffer address used for that access.
- The 32-bit value read from the header-reference global.

The comparison does not establish an immutable marker value. The supplied expression also does not establish the relative evaluation order of these two comparison operands.

If the values differ, the function invokes F-cc6f52873d53 and returns `32`.

If they match, the function reads the word at buffer offset `0x104`, using the first working word for that access, and passes the field value and retained context to F-d7be9cfb4000.

The supplied representation exposes this result as a low 32-bit decoded value and an upper 32-bit status-bearing part. A nonzero upper part causes cleanup and return `32`.

With a zero upper part, the next operation position is:

**base position + decoded header low word + 1**

This is a 32-bit integer calculation in the supplied representation. There is no explicit overflow, carry, range, or sign check. Results requiring signed-overflow interpretation have no stronger portable guarantee here.

### Second operation

The function resolves the object operation at offset `0x0c` again through the object’s then-current first word. It passes the object, calculated position, the buffer address read from the working area for this invocation, and `1`.

Consequently, dependencies between the two status-returning calls may change either the selected operation or the buffer address supplied to it. The earlier operation table and buffer argument are not reused as captured state.

A nonzero result is propagated unchanged after F-cc6f52873d53. A zero result starts the search without another header check.

### Candidate layout and search order

Candidates have a stride of `0x28` bytes, or 40 bytes. Candidate indexes range from zero through eleven.

| Record byte offset | Width | Use |
|---|---:|---|
| `0x00` | 32 bits | Type discriminator |
| `0x04` | 32 bits | Primary key |
| `0x08` | 16 bits | Secondary key |
| `0x0c` | 32 bits | Encoded position contribution |
| `0x10` | 32 bits | Encoded value |
| `0x18` | 32 bits | Flags source |

No interpretation is established for unaccessed bytes.

For each candidate, the function first reads the type discriminator from the current working buffer address plus the candidate displacement. It then compares that retained discriminator against the first type-reference global.

If the first comparison succeeds, the second type-reference global is not read for that candidate. If it fails, the second global is read and compared against the same retained discriminator. Failure of both comparisons terminates the function with cleanup and return `32`.

Thus type acceptance depends on the global values observed for that candidate. Values accepted for an earlier candidate do not establish what will be accepted later.

After a successful type check, the function forms and retains a candidate address using the working area’s first word and the candidate displacement. It reads the 32-bit primary key at that retained address plus `0x04`.

Only when the primary key equals the original primary-key argument does it read the 16-bit secondary key at retained address plus `0x08`. That field is zero-extended and compared against the entire unsigned 32-bit secondary-key argument. An argument greater than `65535` cannot match.

A key mismatch advances to the next candidate. A mismatch at index eleven causes cleanup and return `7`; index twelve is not inspected.

### First matching record

The first candidate matching both keys ends the search. Later candidates cannot recover from a decoding failure on that match.

For its position contribution, the function reads the word at current working-buffer address plus candidate displacement plus `0x0c` and calls F-d7be9cfb4000 with that word and the context. This position-field address is expressed through the working area again; it is distinct from the retained-address rule for subsequent value and flags reads.

A nonzero upper result causes cleanup and return `32`. Otherwise, the decoded low word is retained.

The function then reads the word at retained candidate address plus `0x10` and invokes F-d7be9cfb4000 with that word and the context. A secondary result channel is checked for zero. A nonzero value causes cleanup and return `32`. The exact ABI for that channel is unresolved.

If both checked decodes pass, the function performs these actions in order:

1. Writes **base position + retained position contribution + 1** to the position destination.
2. Rereads the value word at retained candidate address plus `0x10`.
3. Invokes F-d7be9cfb4000 again with that word and the context.
4. Writes this invocation’s low 32-bit result to the value destination.
5. Reads the unsigned 32-bit flags source at retained candidate address plus `0x18`.
6. Writes that source shifted logically right by nine bits to the flags destination.
7. Invokes F-cc6f52873d53 with the working-area address.
8. Returns zero.

The repeated decode’s status is not checked. Its low result, not the earlier checked decode’s low result, supplies the value output.

The flags shift has no additional mask. Its result ranges from zero through `0x007fffff`.

## Side effects

### Calls and mutable state

F-d9e0ae06e54d and F-cc6f52873d53 receive the working-area address. Their implementations and retention behavior are unknown. In particular, the contract does not assume that the setup dependency stops accessing that area after returning.

Other dependencies may consequently change the first working word before a later buffer-address use. Such changes affect later reloads but do not replace the retained candidate address used for value and flags accesses.

No dependency is assumed to preserve global comparison values, object-table state, buffer contents, output storage, or other reachable state. Determinism is not established.

F-cc6f52873d53 is called once on every represented explicit return path. This is a cleanup-shaped call pattern, not proof that it releases memory or transfers ownership. Faults, nonreturning calls, exceptions, and nonlocal exits are outside that return-path statement.

### Output visibility and aliasing

Failure paths issue no direct writes through the three result arguments. Dependencies may nevertheless change those locations.

Successful direct writes occur in position, value, flags order. They are not atomic as a group. Overlapping destinations can overwrite earlier results.

If a destination aliases record storage, the position write can change the value word before its repeated read. Earlier writes or decoder effects can also change the flags source before it is read. The final cleanup-shaped call occurs after publication and is not known to preserve the outputs.

### Access extent

The header fields occupy offsets through `0x107`. With a stable buffer base, candidate eleven’s flags field occupies offsets `0x1d0` through `0x1d3`.

These are access extents, not evidence of allocation size. Header-stage and record-stage contents need not represent one immutable buffer layout.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless an example states otherwise, assume valid storage, returning dependencies, stable relevant buffer contents, and non-overlapping destinations preserved by cleanup.

1. **Initial operation failure.** If the first status-returning operation returns `-5`, cleanup is called and `-5` is returned. No header read or direct result write follows.

2. **Header mismatch at inspection.** If the header field is `A` and the header-reference read yields a different value `B`, the result is `32` after cleanup. Neither value is assumed permanent.

3. **Header mutation before inspection.** If an earlier call changes the header-reference global from `A` to `B`, a subsequently inspected header containing `B` passes when the comparison observes `B`; the former value `A` is irrelevant.

4. **Short-circuited type reference.** If a candidate’s loaded discriminator is `T` and the first type-reference read yields `T`, its type passes without reading the second reference. If the first yields another value, acceptance requires the second read to yield `T`.

5. **Candidate-specific acceptance.** A discriminator accepted at candidate zero need not pass at candidate one. If candidate one’s discriminator differs from both reference values observed for its comparisons, the function returns `32`, even if later keys would match.

6. **Fresh indirect resolution.** If a dependency changes the object’s first word before the second status-returning invocation, that invocation uses offset `0x0c` in the newly referenced table, assuming it remains valid.

7. **Fresh buffer argument.** If header decoding changes the first working word from buffer `A` to buffer `B`, the second status-returning operation receives `B`, not the address supplied to the first operation.

8. **Retained matching address.** If a matching record is captured in buffer `A`, then its position decoder changes the first working word to buffer `B`, subsequent value and flags field reads still use the captured record in `A`.

9. **Ordinary position arithmetic.** With base `100`, accepted header decode `4`, and accepted matching-record position decode `9`, the second operation receives position `105`, and the position write contains `110`.

10. **Secondary-key boundary.** With secondary argument `65536`, no 16-bit secondary field matches. If all twelve candidates pass their individually observed type comparisons, exhaustion returns `7`.

11. **First match fails.** If candidate two matches both keys but its position decode has nonzero checked status, the function returns `32`; candidate three is not examined.

12. **Repeated decode governs output.** If the checked value decode yields low word `20` with zero status, while the repeated decode yields low word `21` with nonzero status, the value write is `21` and no new checked failure occurs.

13. **Flags and search boundary.** A flags source of `0xffffffff` yields `0x007fffff`. A match at index eleven can succeed; a key mismatch there returns `7` without reading index twelve.
