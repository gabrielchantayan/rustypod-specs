The supplied static representation establishes no higher-level operation such as allocation, serialization, device initialization, or object construction. Its repeated offsets and bit shifts are insufficient to identify an object model or data format.

## Behavior

### Interpretation and notation

The following descriptive names identify values by their role in the trace; they do not imply source-level objects.

- **Word** means a represented 32-bit access; **byte** means an 8-bit access.
- **Scale4(value)** means multiplication by four or a two-bit left shift, as applicable.
- **LowByte(value)** means the low eight bits written by a byte store.
- **Extract(value)** means: retain the low 30 bits, then shift right by 20. Its range is 0–1023 before byte truncation.
- A **byte-selected write** means: read an unsigned byte at a stated selector address, add 17 to that byte’s value, and write at the resulting address.

Addresses are computed directly. In particular, a byte-selected write targets an address from 17 through 272; the selector is not a full-width pointer read.

The arithmetic below describes the represented dataflow. Where signed multiplication or signed left shifts overflow, exact executable behavior is `documented_only`: the supplied representation does not establish a portable signed-arithmetic contract. Under a 32-bit bit-vector interpretation, intermediate values and addresses retain their low 32 bits. That interpretation must not be silently substituted for verified machine semantics.

## Acceptance examples

These are conditional static expectations, not executed tests.

1. **Initial argument propagation.** If the second argument is 12, the first index is 3, and execution reaches the first store, the represented operation writes the 32-bit value 12 at address 32.

2. **Byte truncation.** If the first byte-update value is 65 and the freshly read selector byte is 7, its scaled byte write stores 4 at address 24. The full scaled value, 260, is still supplied to the subsequent call.

3. **Unsigned selector range.** If a selector read returns 255, the selected byte-write address is 272, not an address obtained by sign-extending the selector.

4. **Saved selector versus fresh selector.** If the selector saved during the second early byte update is 9, a later callee changing that selector to 40 does not redirect the word store based on the saved value: its represented destination remains 29. Later explicitly fresh reads may instead observe 40.

5. **Global snapshot.** If a callee changes the global after its explicit read, the subsequent global-derived byte value still depends on the captured word, not a second global read.

6. **Extraction width.** If Extract produces 1023, a byte store retains 255. The computed table-read address using the same extraction rule would be 1043, without word-index scaling.

7. **Iteration transition.** If the final result is 5, completion sets the second and third arguments to 20, sets the fourth argument to zero, writes 20 at address 100, and repeats. It does not return success.

8. **Interrupted execution.** If an indirect call does not return, later direct writes are not reached. Earlier writes are not visibly undone.
