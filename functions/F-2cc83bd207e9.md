### Arithmetic and narrowing

Explicit byte accesses operate on eight bits, halfword accesses on sixteen, and word accesses on thirty-two. Stores at smaller widths retain the corresponding low bits. Explicit unsigned byte loads used as words are zero-extended.

**[INFERENCE]** Under 32-bit bit-vector semantics, left shifts and multiplication discard bits beyond bit 31. Consequently:

- Left shift by eight followed by logical right shift by eight retains only the original low 24 bits.
- Successive left shifts by 28 and 28 yield zero.
- Successive left shifts by 30 and seven yield zero.
- A value shifted left by sixteen has a zero low halfword.

These are conditional arithmetic consequences, not permission to use overflowing signed arithmetic in an arbitrary implementation language. Exact signed-overflow behavior and address wrapping are **documented_only**.

A terminal-region signed right shift takes its count from the low byte of a derived address value. Counts can exceed 31. Count handling and signed right-shift semantics require target evidence.

## Acceptance examples

These examples are conditional static checks, not executed tests.

### Input forwarding and truncation

If F-D001 is reached, its represented argument equals the first input’s full 32-bit value.

Under 32-bit bit-vector semantics, third input 3 produces 96 at both sites consuming its five-bit shift. Input 0x08000000 produces zero at those positions.

### Compact-base upper boundary

If the relevant result’s low seven bits are all set, the shifted-and-masked intermediate can be 0x7F00. The extraction becomes 0x1FC, and the compact base becomes **0x3F8**. Rejecting that value as outside a 0x3F0 bound would contradict the conditional arithmetic.

### Unsigned widening and overlap

A byte 0xE2 read from scaled-base offset 5 produces a word payload 0x000000E2, not 0xFFFFFFE2.

Clearing compact-base offset 0x14 and subsequently writing a nonzero byte at offset 0x15 does not generally leave the containing word zero. Byte order determines the changed bits.

### Capture ordering around 0x3A

If the 0x3A write overlaps the later paired-base offset-0x14 read, that capture can reflect the write. The earlier 0xA9 and literal-base offset-0x74 captures cannot reflect it merely through that later write.

### Fresh reads at 0x67

If an intervening derived-address write aliases 0x67 and changes its stored value, the next read from 0x67 must use the then-current storage value. Reusing the initially captured 0xA9 low byte is not equivalent.

### Root capture and failure

If the 0x60 write overlaps root storage, subsequent root-relative operations still use the root captured before that write.

If an earlier required access fails, neither rollback nor eventual invocation of F-D002 is guaranteed.
