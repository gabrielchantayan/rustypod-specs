# F-f97c3956611e

## Purpose

F-f97c3956611e conditionally obtains a subordinate receiver, performs an operation that can update a 32-bit working word, and optionally publishes that word and an earlier auxiliary result through caller-supplied output pointers.

Two preliminary calls gate all subsequent work. If the gate passes, the function performs the main operation regardless of whether either optional output pointer is present. A nonzero main-operation result triggers a transformation through F-d33f6d597e5d and then an additional external call.

The returned word is initially zero. On the path containing the transformation, it becomes the transformation’s return value. The return value of the final external call is not used.

This describes established control flow and data movement. The meanings of the gate predicates, auxiliary result, working word, and main-operation result are not established. In particular, this contract does not assign success, error, allocation, handle, or ownership meanings to those values.

## Interface

### Inputs and outputs

The function accepts four arguments:

| Argument | Role | Established representation |
|---|---|---|
| Primary receiver | Required receiver used for indirect dispatch | Pointer to an object whose first field supplies a dispatch-table address |
| Working-word output | Optional destination for the final working word | Null or a writable pointer to one 32-bit word |
| Auxiliary output | Optional destination for an auxiliary call result | Null or a writable pointer to one 32-bit word |
| Initial word | Initial value of the working word | Uninterpreted 32-bit word |

The function returns an uninterpreted 32-bit word.

The working word is local storage initialized from the initial word before the first indirect call. The main-operation dependency receives its address and can therefore update it.

No output buffer length, ownership token, or explicit error destination is supplied.

### Dispatch layout

The receiver’s first field is used to locate a dispatch table. The observed entries are selected by byte offset:

| Receiver | Dispatch-table byte offset | Role |
|---|---:|---|
| Primary receiver | 8 | First gate predicate |
| Primary receiver | 12 | Second gate predicate |
| Primary receiver | 36 | Subordinate-receiver provider |
| Subordinate receiver | 44 | Auxiliary-result operation |
| Subordinate receiver | 60 | Main operation |

These offsets are byte offsets, not method indices. The function resolves the relevant table and entry when making each call; it does not establish that two provider calls return the same subordinate receiver.

The supplied representation uses 32-bit integer and word values. A four-byte pointer and dispatch-entry model is consistent with that representation and layout, but the source alone does not establish a complete platform ABI.

### Preconditions

For a path to complete normally:

- The primary receiver and the dispatch entries reached on that path must be valid for their uses.
- Each subordinate receiver actually used must support its immediately following dispatch.
- A non-null output pointer must be valid for a 32-bit store when that store occurs.
- The main operation must be able to access the supplied working-word address during its call.
- Each invoked dependency must return normally for execution to reach the next step.

The function performs no explicit validation of receiver pointers, subordinate-receiver pointers, dispatch entries, or non-null output destinations.

A null optional output pointer is supported. A null primary receiver is not explicitly supported.

## Behavior

### 1. Initialize the result and working word

Before invoking dependencies, the function establishes:

- A return word equal to zero.
- A working word equal to the supplied initial word.

There is no arithmetic transformation, masking, scaling, or narrowing of the initial word in this initialization.

### 2. Evaluate the gate in short-circuit order

The first gate predicate is called with the primary receiver.

If its result is nonzero:

- The second predicate is not called.
- No subordinate receiver is requested.
- Neither output is explicitly written.
- The function returns zero.

If the first predicate returns zero, the second gate predicate is called with the primary receiver.

If the second predicate returns zero:

- No subordinate receiver is requested.
- Neither output is explicitly written.
- The function returns zero.

Only the combination “first result zero, second result nonzero” enters the operation body.

Predicate results are used only for zero-versus-nonzero decisions. Negative values, where represented as signed 32-bit results, satisfy the nonzero condition.

The second dispatch occurs after the first dependency returns. Changes made by the first dependency to receiver state or dispatch state can therefore affect the second call.

### 3. Optionally obtain and publish the auxiliary result

This step occurs only after the gate passes and only when the auxiliary-output pointer is non-null.

The function:

1. Calls the subordinate-receiver provider on the primary receiver.
2. Uses that returned receiver for the auxiliary-result operation.
3. Supplies two zero-valued arguments after that receiver.
4. Stores the operation’s 32-bit result through the auxiliary-output pointer.

The store happens before the provider call used for the main operation.

When the auxiliary-output pointer is null, this entire step is skipped. The provider and auxiliary-result operation are not called for this step.

The auxiliary result is not tested, transformed, or used as the function’s return value.

### 4. Obtain a receiver and perform the main operation

After the optional auxiliary step, the function calls the subordinate-receiver provider again.

This provider call is unconditional once the gate has passed, including when both output pointers are null.

The returned receiver is used for the main operation. Its arguments, after the receiver, are:

- A value of one.
- A value of zero.
- The address of the working word.

The main operation returns a 32-bit result interpreted by this function as a signed integer for storage, but only compared against zero. Every nonzero bit pattern takes the same subsequent branch.

The main operation can modify the working word through its address. This function does not require a nonzero main-operation result before using or publishing the resulting working word.

Consequently, a zero main-operation result does not imply that the working word still equals the initial word.

### 5. Conditionally transform and invoke the external operation

If the main-operation result is zero, this step is skipped and the return word remains zero.

If the main-operation result is nonzero:

1. F-d33f6d597e5d is called with the working word as observed for that call.
2. Its 32-bit return value becomes the function’s return word.
3. The unresolved external dependency is called with three arguments, in order:
   - That transformation result.
   - The nonzero main-operation result.
   - The working word as observed for the external call.

The external dependency’s return value, if any, does not determine this function’s returned word.

There is no nonzero check on the transformation result. A transformation result of zero still leads to the external call.

The working word used as the transformation input and the working word supplied to the external call are separate observations. They ordinarily coincide if intervening dependencies do not modify the working storage through an accessible alias. Equality is not guaranteed by this function.

The source establishes the ordering between these calls. It does not establish an evaluation order among the arguments within the external call.

### 6. Optionally publish the final working word

After the main operation and any conditional transformation and external call, the function checks the working-word output pointer.

If that pointer is non-null, the function stores the working word through it.

This store occurs:

- Only on the gate-passing path.
- Whether the main-operation result was zero or nonzero.
- After the auxiliary-output store, if one occurred.
- After the external call, if one occurred.

The function then returns its return word.

### Aliasing consequences

The two output pointers are not required by any explicit check to be distinct.

If they designate the same writable word and the function completes the gate-passing path normally, the working-word store occurs after the auxiliary-result store and replaces it. Dependencies may observe or modify that location between the two stores.

Output pointers are also not checked for overlap with receiver or dispatch state. If an auxiliary-output store changes state needed for later dispatch, the subsequent calls use the state then present. This function does not protect later dispatch by retaining an earlier receiver-table snapshot.

These observations describe sequencing, not a guarantee that arbitrary aliasing is valid. An alias that destroys a required receiver or callable entry can prevent normal completion.

## Side effects

### Direct memory effects

The function directly performs the following data writes:

- Initialization and subsequent use of its local working storage.
- One 32-bit auxiliary-output store, when the gate passes and that output pointer is non-null.
- One 32-bit working-word output store, when the gate passes and that output pointer is non-null.

There is no direct caller-output store on a gate-rejected path.

That does not imply an absence of side effects: gate predicates are invoked before rejection, and their effects are unknown.

### Dependency effects

All invoked dependencies may have effects not shown in the supplied source. The function establishes no preservation guarantee for globals, receiver state, output memory, resource state, or other shared state across those calls.

In particular:

- The two provider calls need not return identical receivers.
- The first provider call or auxiliary operation can affect the later main-operation path.
- A dependency may alter caller-visible output storage before or after this function’s own store to that storage.
- The main operation receives a pointer to local working storage. Whether it retains that pointer is unknown.

The working storage is available during this invocation. The function does not establish a valid lifetime for accessing it after return.

### Ownership and resource management

No direct allocation or explicit release is visible.

The provider’s returned receivers are used for dispatch without a visible retain, release, or transfer annotation. Their ownership is therefore unknown.

The meanings of the working word and transformation result are also unknown. Their passage to other dependencies does not establish that they represent pointers or resources, or that ownership is transferred or released.

### Errors and abnormal termination

There is no explicit exception handler, retry, rollback, or error conversion.

A zero return can arise from gate rejection, a zero main-operation result, or a zero transformation result on a path that did invoke the external dependency. It is not an unambiguous failure indicator.

If a dependency does not return normally, later output stores and the normal return are not established.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Each assumes valid memory and normal dependency returns.

### Gate rejected by the first predicate

Given a nonzero first predicate result, the function must return zero without calling the second predicate, either provider occurrence, the auxiliary operation, the main operation, the transformation, or the external dependency.

It must perform neither direct output store.

### Gate rejected by the second predicate

Given a zero first predicate result and a zero second predicate result, both predicates must run in that order. The function must then return zero without requesting a subordinate receiver or directly writing either output.

### Zero main result with an updated working word

Given a passing gate, no auxiliary-output pointer, and a main operation that changes the initial word from 10 to 20 and returns zero:

- Exactly one provider call occurs.
- Neither the transformation nor the external dependency is called.
- A present working-word output receives 20.
- The function returns zero.

This distinguishes the main result from the working-word value.

### Nonzero main result with a zero transformation result

Given a passing gate, a main result of −1, a working word of 30, and a transformation result of zero:

- The transformation receives 30.
- The external dependency is still called.
- Its first two arguments are zero and −1.
- Its third argument is 30 if no intervening effect changes the working word.
- The function returns zero.

### Both outputs omitted

Given a passing gate and two null output pointers, the main operation must still run. The auxiliary operation must not run. A nonzero main result must still trigger the transformation and external call.

### Shared output destination

Given a passing gate, both outputs pointing to the same valid word, an auxiliary result of 40, and a final working word of 50, the function directly stores 40 first and 50 later.

On normal completion, the shared destination contains 50, assuming no later independent modification.

### Distinct provider results

Given an enabled auxiliary output and provider calls returning different valid receivers, the auxiliary operation must use the first receiver and the main operation must use the second. Receiver identity must not be assumed stable.
