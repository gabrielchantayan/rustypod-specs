# F-4307d17c122d

## Purpose

F-4307d17c122d modifies a word array in place. The first word participates in determining how many payload words are processed and receives the final metadata. An unsigned displacement determines a whole-word offset and a residual bit count.

Two behaviors are established:

- With no residual bits, payload words are moved to higher positions without scaling, and the vacated low positions are cleared.
- With 1 through 31 residual bits, adjacent bit fragments are combined, configurable factors scale the payload, and one additional high word is written and examined when determining the final metadata.

A residual count of **1 uses the fragment-transforming behavior**, including its scaling factors, extra high-word access, and dependency-derived metadata.

The operation resembles displacement of a signed multiword integer. That is **inferred intent**, not a representation guarantee. Neither the configuration values nor the dependency result are established to be signs or unit factors.

## Interface

### Arguments and result

The function accepts:

1. An unsigned displacement.
2. A pointer to writable signed-integer storage.

There is no return value, capacity argument, or explicit error result. Results are observable through storage modifications and any effects of F-a6b5d842289c.

The supplied operations divide the displacement into:

- A whole-word offset **q**, obtained by discarding its lowest five bits.
- A residual count **r**, consisting of those five bits.

Under the nominal 32-bit unsigned model, these equal division by 32 and remainder modulo 32. Consequently, q ranges from 0 through 134,217,727, and r ranges from 0 through 31.

The contract below uses that nominal 32-bit model. Independent ABI confirmation of integer widths and alignment is unavailable.

### Array layout and required storage

Position 0 is the metadata word. Positions 1 onward are payload words. Position numbers refer to consecutive signed-integer elements, not byte offsets.

Let **n** be the captured source count described below. For positive n and ordinary valid arithmetic, accessible storage must extend through:

| Residual count | Highest accessed position |
| --- | --- |
| 0 | n + q |
| 1 through 31 | n + q + 1 |

The residual-bit case requires the extra position even when that word is zero and excluded from the final metadata.

No capacity is checked. Neither the entry metadata nor the final metadata provides an independently verified allocation bound.

### Configuration observations

Four global integer locations contribute five observations:

| Observation | Role |
| --- | --- |
| Saved count factor | First observation of the count-factor location; retained for whole-word metadata calculation. |
| Counting factor | Second observation of that same location; determines the captured source count. |
| Storage factor | Scales fragment-derived output words. |
| Payload factor | Scales input payload words and participates in the highest-word check. |
| Metadata factor | Scales the final metadata. |

The two count-factor observations are distinct. Their equality requires stability; it is not guaranteed by the access pattern.

The saved count factor is obtained before the expression containing the counting-factor observation and entry metadata read. The relative order of those latter two reads is not established.

The storage factor, payload factor, and metadata factor are obtained after F-a6b5d842289c returns, in that order. No evidence establishes that any factor is nonzero, positive, a sign, or the inverse of another factor.

### Captured count

The function multiplies the counting factor by the entry metadata using signed arithmetic and takes the magnitude of that product. This produces n before the dependency call.

A representable product and representable magnitude are required. In particular, negating the minimum signed value is not established as a valid way to obtain its magnitude.

Changes made by the dependency do not cause n to be recalculated.

## Behavior

### Entry observations and zero-count behavior

Before deciding whether any payload processing is required, the function:

- Obtains both count-factor observations and derives n from the entry metadata.
- Calls F-a6b5d842289c with the original pointer.
- Obtains the storage, payload, and metadata factors.

These are source-level ordering relationships, not synchronization guarantees or promises about physical memory transactions.

If n is less than 1, there are no direct array writes. Under valid magnitude arithmetic, this is the zero-count case.

The dependency and all three post-call configuration observations still occur. Thus, zero captured count does **not** guarantee unchanged storage or external state. A dependency change that makes the metadata nonzero does not override the captured zero count.

For positive n, residual count 0 selects whole-word movement; every residual count from 1 through 31 selects fragment transformation.

### Whole-word movement: residual count 0

The payload result is an upward displacement by q positions:

- Original payload position j becomes position q + j, for positions 1 through n.
- Positions 1 through q become zero.

Here, “original” means the payload available after the dependency returns, not necessarily the payload supplied at function entry.

The observable access order is descending. Position n is read and copied first, followed by successively lower source positions. All copies precede low-word clearing, which proceeds from position q down to position 1.

This order preserves unread payload during ordinary overlapping upward movement within the array. Payload values are copied without either the storage factor or payload factor being applied.

When q is zero, each payload position is still read and written back to itself. Zero displacement is therefore not a no-write operation.

#### Whole-word metadata

After payload movement and clearing, position 0 is read to determine the sign of its signed product with the saved count factor. A negative product selects a negative displacement contribution; otherwise, the contribution is positive.

Position 0 is then read again for the metadata calculation. The two reads are distinct:

- The first chooses the displacement contribution’s sign.
- The second supplies the metadata operand.

If both reads observe the same value M, the ordinary mathematical result before final scaling is the saved count factor times M, increased by q for a nonnegative sign-test product or decreased by q for a negative sign-test product. The metadata factor scales that result, and the resulting value is stored at position 0.

This description has an important arithmetic qualification. The displacement contribution and its addition to the signed metadata product use unsigned arithmetic. A negative contribution is formed by unsigned negation. The unsigned sum is then converted to a signed intermediate before signed multiplication by the metadata factor.

Accordingly, the mathematical description is conditional on those conversions and arithmetic operations yielding the stated representable result. It does not establish portable behavior for an unsigned intermediate outside the signed range.

This path uses the **saved count factor**, not the later counting-factor observation. The dependency’s returned integer does not determine this path’s metadata.

### Fragment transformation: residual counts 1 through 31

This path transforms n payload words and writes an additional high word. Let **m = n + q** under valid indexing assumptions.

For each source position j, consider the signed product of the payload factor and that source word. Its unsigned 32-bit representation is the input bit pattern for the transformation. The signed multiplication must be valid before conversion; conversion does not repair signed overflow.

Each such pattern contributes:

- Its low fragment, shifted left by r and limited to 32 bits, to destination position q + j.
- Its high fragment, obtained by an unsigned right shift of 32 − r, to destination position q + j + 1.

Where fragments meet, they are combined by bitwise OR. There is no contribution from a nonexistent source below position 1. The highest output position, m + 1, receives only the high fragment from source position n.

Every combined output pattern is multiplied by the storage factor using unsigned arithmetic, with reduction modulo 2³² in the nominal model. The resulting unsigned value is assigned to signed storage. Values outside the signed range require target-specific conversion rules.

Both shift counts lie strictly between 0 and 32:

- At r = 1, the left shift is 1 and the right shift is 31.
- At r = 31, the left shift is 31 and the right shift is 1.

No shift by 0 or 32 occurs on this path.

#### Access and write ordering

Source payload positions are consumed from n down through 1. Each source read precedes the corresponding write one position above its displaced position. The descending traversal protects unread sources during ordinary in-place upward displacement.

Payload destinations are written in a continuous descending order:

1. Positions m + 1 down through q + 2 receive the combined fragments.
2. Position q + 1 receives the remaining low fragment, scaled by the storage factor.
3. Positions q down through 1 receive zero.

The remaining-fragment store occurs even when its value is zero. When q is zero, it targets position 1 and there are no subsequent low-word clearing stores.

Thus, positions m + 1 down through 1 are all written. The extra high word is not merely a possible overflow allocation: its write is unconditional for positive n on this path.

#### Highest-word check and metadata

After all payload writes, position m + 1 is read. Its signed product with the payload factor is tested against zero:

- A zero product selects length m.
- A nonzero product selects length m + 1.

This is a **product-zero test**, not an unconditional direct test of the stored word. Its signed multiplication must itself remain valid.

Only this highest word is examined. There is no repeated removal of additional zero words. If the highest word is excluded, its stored value remains in memory.

The selected length is multiplied by the dependency’s returned integer using signed arithmetic. That result is multiplied by the metadata factor, also using signed arithmetic, and stored at position 0.

This metadata rule applies to r = 1 as well as r = 2 through 31. It does not use the saved count factor or reread position 0 to determine a sign.

### Arithmetic and indexing boundaries

The supplied operations mix signed and unsigned arithmetic:

- Count derivation, input scaling, highest-word checking, and final metadata scaling use signed multiplication.
- Fragment shifts and storage-factor multiplication use unsigned arithmetic.
- The residual path forms n + q with unsigned participation and converts it to a signed working index.
- Subsequent residual-path index calculations include signed increments and decrements.

Ordinary behavior therefore requires valid pointer arithmetic, suitable conversion results, and representable signed calculations. In particular, the residual path needs a representable working index and its additional high position.

Signed overflow is not established wrapping behavior. Out-of-range unsigned-to-signed conversions remain **documented_only** without target-specific rules.

There is no transactional boundary or rollback mechanism. The function supplies no explicit failure result for partially completed effects.

The function contains no explicit assignment directed at a configuration location. However, no non-aliasing contract is supplied. Array writes therefore cannot be assumed incapable of overlapping configuration storage or other externally visible objects.

## Acceptance examples

These are conditional analytical examples, not observed executions.

Unless overridden, assume 32-bit words, adequate storage, valid arithmetic and conversions, stable observations, all configuration factors equal to 1, and a dependency that changes no state and returns 1. Payload lists run from position 1 upward.

### One residual bit

With displacement 1, metadata 2, and payload **3, 4**:

- The residual-bit path writes positions 3, 2, and 1 as **0, 8, 6**, respectively.
- The highest-word product is zero.
- Final metadata is **2**.

The resulting payload through position 3 is **6, 8, 0**. The extra high word is written even though excluded from the selected length.

### Whole-word and combined displacement

With metadata 2 and payload **3, 4**:

| Displacement | Resulting payload through highest written position | Final metadata |
| --- | --- | --- |
| 32 | 0, 3, 4 | 3 |
| 33 | 0, 6, 8, 0 | 3 |

The first case copies without payload scaling. The second uses fragment transformation with one residual bit.

For displacement 0 with the same entry state, positions 2 and 1 are still read and rewritten, followed by the metadata store. The unchanged numerical result does not imply an absence of writes.

### Nonunit factors at one residual bit

With displacement 1, metadata 1, and payload **3**, instead assume payload factor 2, storage factor 3, metadata factor 2, and dependency result −1.

The scaled input pattern is 6. Position 2 receives zero; position 1 receives 36. The selected length is 1, and final metadata is **−2**.

This distinguishes the one-bit case from an unscaled copy and demonstrates its use of the dependency result.

### Distinct count-factor observations

Suppose the saved count factor is 1, the counting factor is 2, entry metadata is 2, and displacement is 32. With four accessible payload words and no dependency changes:

- Four source words are copied.
- Position 1 is cleared.
- Final metadata is **3**.

The copied count comes from the second observation; whole-word metadata uses the first.

### Dependency mutation

With entry metadata 2 and displacement 32, suppose the dependency changes metadata to 5 without invalidating storage.

Exactly two source words are still copied. If both later metadata reads observe 5, final metadata is **6**.

If instead the captured count was zero, a dependency change to positive metadata would not trigger payload processing or a direct metadata store.

### Highest contribution and limited trimming

With displacement 2, metadata 1, and payload **1,073,741,824**, positions 2 and 1 receive **1** and **0**. The highest-word product is nonzero, so final metadata is **2**.

With displacement 2, metadata 2, and payload **0, 0**, positions 3 through 1 all receive zero. Only position 3 is checked, so final metadata remains **2**, not zero.
