# F-720e0dce02c6

## Purpose

F-720e0dce02c6 computes a bounded count from two unsigned 32-bit input words interpreted as the low and high halves of one unsigned 64-bit quantity.

The established result is the number of seven-bit groups needed to cover that quantity, with two qualifications:

- The result is at least **1**, including for an input quantity of zero.
- The result is capped at **9**, including when ten seven-bit groups would otherwise be needed.

This is a characterization of the supplied static evidence, not a claim about a particular encoding format. The function does not produce encoded bytes, inspect a buffer, or establish how another component uses the count.

## Interface

**Inputs**

| Position | Contract |
|---|---|
| First argument | Unsigned 32-bit word representing bits 0–31 of the combined quantity. |
| Second argument | Unsigned 32-bit word representing bits 32–63 of the combined quantity. |

For description, let \(L\) be the first argument and \(H\) the second. Their combined unsigned value is:

\[
V=L+2^{32}H.
\]

This numerical composition does not specify memory endianness. The interface supplies two scalar words, not an eight-byte memory object.

**Output**

The function returns a signed 32-bit integer whose reachable values are exactly **1 through 9**.

The complete result contract is:

\[
R=\min\left(9,\ \max\left(1,\left\lceil
\frac{\operatorname{bitlength}(V)}{7}
\right\rceil\right)\right),
\]

where \(\operatorname{bitlength}(0)=0\).

Equivalently, the function returns the smallest integer \(k\) from 1 through 8 for which \(V<2^{7k}\), if such an integer exists. Otherwise, it returns 9.

**Preconditions**

There are no visible content restrictions on either input word. Every pair of unsigned 32-bit values has a defined result under the arithmetic model described here.

The interface does not require:

- A nonzero input.
- A normalized high word.
- A valid pointer or an accessible buffer.
- Any initialized external state.
- A relationship between the two words beyond their role in the combined quantity.

The 32-bit word model is supported by the supplied unsigned and signed operations, the cross-word shift distance, and the four-byte signed-overflow predicate. Behavior under a different source-language integer-width model is not established.

## Behavior

### Seven-bit reduction

The function repeatedly reduces the combined quantity by seven bits. Each reduction is a logical right shift of the full 64-bit quantity, implemented using its two 32-bit halves.

Within each reduction, the low half is updated first. Its new value combines:

- The previous low half shifted right by seven bits.
- Bits transferred from the previous high half into the upper seven positions of the low half.

The high half is then shifted right by seven bits.

The low-half calculation uses the high half from **before** that high half is updated. This ordering is essential to the combined-value interpretation. With unsigned 32-bit shift semantics, bits outside the destination word are discarded; the two contributions to the new low half occupy disjoint bit positions.

Consequently, after \(k\) reductions, the pair represents:

\[
\left\lfloor\frac{V}{2^{7k}}\right\rfloor.
\]

All right shifts affecting the input words are logical, not sign-extending. An input with its most significant bit set is still treated as an unsigned quantity.

### Counting and termination

At least one reduction occurs before the function returns. The count starts at zero and increases once per reduction.

The continuation decision is made after the reduction. For the reachable states:

- If the reduced quantity is zero, the function stops.
- If the reduced quantity is nonzero and fewer than nine reductions have occurred, the function continues.
- After the ninth reduction, the function stops even if the reduced quantity is still nonzero.

Thus zero and values from 1 through 127 all return 1. The function does not return zero for an empty or zero-valued input.

The ninth-reduction limit is an actual behavioral boundary, not merely a consequence of exhausting all 64 input bits. Nine reductions remove 63 bits. If the original quantity is at least \(2^{63}\), one bit remains after the ninth reduction, but the function still returns 9.

### Signed operations in the termination condition

The supplied evidence includes both a signed interpretation of the updated low word and a signed-subtraction-overflow predicate. Neither introduces an additional result case for reachable inputs.

The signed interpretation of the low word is initially considered only when the updated high word is zero. However:

- When the updated pair is nonzero, the continuation-related condition is replaced by the count-limit condition.
- When the updated pair is zero, the updated low word is zero, so its signed-negative test is false.

A nonzero reduced low word with its highest bit set therefore does not cause special termination.

The signed-overflow predicate concerns subtracting 9 from the incremented count. Reachable incremented counts are 1 through 9. Their differences from 9 are −8 through 0, all representable in signed 32-bit arithmetic. The overflow predicate is consequently false on every reachable iteration.

The other count-related subtraction also remains within signed 32-bit range. There is no reachable signed counter overflow, wraparound, or unbounded loop.
