# F-b91e7e595d6f

## Purpose

F-b91e7e595d6f coordinates a preparation step, an eligibility check, retrieval of a 32-bit flag word, a conditional change to one flag bit, and an attempted write of the resulting low byte.

Its result is a 64-bit value containing two independently meaningful 32-bit fields:

- The upper field contains the function’s local flag word as observed when constructing the result.
- The lower field contains either zero, the constant 14, or a value supplied by F-10684331fba7.

The supplied static representation establishes this control flow and bit-level behavior. It does not establish the domain meaning of the flags, the object being operated on, or the status values. Descriptions such as “eligibility,” “retrieval,” and “write” identify roles in this function, not independently verified dependency semantics.

### Explicit flag transformation

If F-b017a01be022 returns nonzero, the function replaces the local flag word according to the original third input.

If the third input is zero:

- The replacement is the current flag word bitwise-ANDed with `0x000000FD`.
- Bit 1 is cleared.
- Bits 0 and 2 through 7 retain their current values.
- Bits 8 through 31 are cleared.

If the third input is nonzero:

- The replacement is the current flag word bitwise-ANDed with `0x000000FF`, then bitwise-ORed with `0x00000002`.
- Bit 1 is set.
- The other low-byte bits retain their current values.
- Bits 8 through 31 are cleared.

Both branches perform a full 32-bit replacement. The zero-input branch does **not** merely clear bit 1 while preserving the upper 24 bits.

This operation uses the flag word present after F-b017a01be022 returns, not necessarily the original second input. Its branch condition uses the original third input, rather than rereading the working-storage entry initialized from that input.

There is no addition, subtraction, or arithmetic overflow in this transformation. The masks are applied at 32-bit width.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. Unless stated otherwise, assume dependencies return normally and do not modify the flag word except for an explicitly described retrieval write.

1. **Initial rejection preserves the input flag value under the stated assumptions.**  
   Given a second input of `0x12345678` and a zero initial-check result, the return pair is **(`0x12345678`, `0x0000000E`)**. No retrieval, write attempt, or fallback-result call occurs. The no-explicit-argument form of F-289ec4311c64 is invoked before return.

2. **Zero third input clears bit 1 and discards upper bits.**  
   Suppose retrieval returns nonzero and leaves the flag word as `0x89ABCDEF`. With a zero third input, the replacement is `0x000000ED`. If the write attempt returns nonzero, its numeric flag argument is `0xED`, and the return pair is **(`0x000000ED`, `0x00000000`)**.

3. **Negative third input uses the set-bit branch.**  
   Suppose the third input is −1 and successful retrieval leaves `0x12345680`. The replacement is `0x00000082`. A nonzero write result yields **(`0x00000082`, `0x00000000`)**. There is no special treatment for the sign.

4. **Retrieval failure need not preserve the original flag word.**  
   Suppose retrieval changes the flag word to `0xDEADBEEF` but returns zero, and F-10684331fba7 returns `0x00000035`. The return pair is **(`0xDEADBEEF`, `0x00000035`)**. Neither flag transformation nor write attempt occurs.

5. **Write failure does not restore the flag word.**  
   Suppose successful retrieval leaves `0xFFFFFF00`, the third input is nonzero, the write attempt returns zero, and the fallback value is `0x00000007`. The return pair is **(`0x00000002`, `0x00000007`)**. No retry or restoration is visible.

6. **A zero fallback value is distinguishable only by execution history.**

7. **Later observable changes affect the returned upper field.**
