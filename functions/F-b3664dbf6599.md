# F-b3664dbf6599

## Purpose

F-b3664dbf6599 coordinates an operation on two inputs and a caller-supplied destination. It selects a dependency path using the inputs’ 32-bit fields at byte offset +12.

- When exactly one input field is zero, it calls F-782bee8991b2 with the original argument order.
- When both fields are zero or both are nonzero, it performs a signed size/capacity decision, applies a continuation gate, compares the inputs through F-c0985d8666ae, and calls F-e3b26f245f4c with comparison-selected ordering.
- After either operation dependency returns nonzero, it writes exactly 0 or 1 to the destination’s field at +12 and returns 1.

The continuation gate is significant: its initial value is the original destination argument. Only an insufficient-capacity call replaces that value with the return from F-08bc2fc94856. Consequently, the capacity/comparison path can return 0 without calling any dependency when the destination argument is zero and the preceding capacity read completes with sufficient capacity.

The structure suggests signed arithmetic over separately represented magnitudes. That is inferred intent, not an established numerical contract.

**Return 1** requires both:

- The subsequent direct destination flag store completes.

### Capacity/comparison path: size selection

When both initial flags belong to the same zero/nonzero class, the function uses the ordered pair established above.

It selects the maximum of the inputs’ +4 fields using signed 32-bit comparisons. For stable field values, this is the ordinary signed maximum, independent of the ordered pair.

The supplied representation references input size fields repeatedly during this selection. It does not establish snapshot semantics for changing fields or a portable count and instruction-level ordering of physical reads.

The destination’s +8 field is then compared with the selected size value using a signed 32-bit comparison:

- Destination capacity **less than** the selected size triggers F-08bc2fc94856.
- Capacity **equal to or greater than** the selected size bypasses that dependency.

There is no visible nonnegativity validation, unsigned conversion, added allowance, or minimum-capacity adjustment. No size addition or multiplication is performed by this wrapper.

### Capacity/comparison path: continuation gate

Before the capacity decision, the continuation gate holds the original destination argument.

If capacity is insufficient, F-08bc2fc94856 is called with no explicit arguments shown, and its result replaces the gate. If capacity is sufficient, no replacement occurs.

The resulting behavior is:

| Capacity decision | Gate tested for nonzero | Zero gate | Nonzero gate |
|---|---|---|---|
| Sufficient; dependency skipped | Original destination argument | Return 0 | Continue |
| Insufficient; dependency called | F-08bc2fc94856 return value | Return 0 | Continue |

A zero gate stops execution before F-c0985d8666ae, F-e3b26f245f4c, or this function’s final flag store.

A nonzero capacity-dependency result is only permission to continue. It is **not** adopted as a replacement destination address. All later uses of the destination retain the original argument.

There is no direct post-call capacity reread or validation that storage became sufficient. Thus, if the original destination argument is zero, a nonzero capacity-dependency return still allows comparison and operation delegation with that zero destination argument.

Conversely, with sufficient capacity and an original destination argument of zero, the gate fails even though no capacity dependency was called. This occurs only after the destination +8 read has already completed.

### Comparison and operation order

After a nonzero continuation gate, F-c0985d8666ae receives the selected ordered pair:

- Both initial flags zero: left, then right.
- Both initial flags nonzero: right, then left.

Its return is interpreted as signed 32-bit:

| Comparison result | Input order passed to F-e3b26f245f4c | Flag after operation success |
|---|---|---:|
| Negative | Reverse of comparison-call order | 1 |
| Zero or positive | Same as comparison-call order | 0 |

F-e3b26f245f4c receives the original destination argument first, followed by those ordered inputs.

If F-e3b26f245f4c returns zero, the function returns 0 without its own final flag store. Otherwise, it writes the selected 32-bit flag at destination +12 and returns 1.

Comparison equality has no separate normalization branch. A zero comparison result follows the same ordering and flag rule as a positive result.

## Acceptance examples

These examples are static, conditional consequences, not executed tests. They assume completing memory accesses and returning dependencies. Field values are stable unless stated otherwise.

1. **Mixed flags, left zero.** Left flag is 0 and right flag is 7. F-782bee8991b2 receives the original argument order. A nonzero return causes flag 0 to be stored and the function to return 1. No direct capacity check or continuation-gate test occurs.

2. **Mixed flags, right zero.** Left flag is −3 and right flag is 0. A nonzero F-782bee8991b2 result causes flag 1 and return 1. The negative flag is simply nonzero.

3. **Direct-operation failure.** Exactly one flag is zero and F-782bee8991b2 returns zero. The function returns 0 without its own flag store. Dependency mutations are not rolled back.

4. **Sufficient capacity and negative comparison.** Both flags are zero, sizes are 3 and 5, capacity is 5, and the destination argument is nonzero. F-08bc2fc94856 is skipped. Comparison receives left then right. A negative comparison reverses that order for F-e3b26f245f4c; operation success produces flag 1.

5. **Both flags nonzero.** Left flag is 2 and right flag is 9. After capacity and gate acceptance, comparison receives right then left. A zero or positive comparison preserves that order; operation success produces flag 0.

6. **Insufficient capacity, failed gate.** Both flags select the capacity/comparison path, sizes are 4 and 8, and capacity is 7. If F-08bc2fc94856 returns zero, the function returns 0 without comparison, operation delegation, or its own flag store.

7. **Successful capacity gate retains the destination.** Under the preceding size conditions, a nonzero F-08bc2fc94856 result permits continuation. That result is not used as a destination address, and capacity is not directly checked again.

8. **Zero destination, sufficient capacity.** Both flags select the capacity/comparison path and the original destination argument is zero. If the destination +8 read completes and indicates sufficient capacity, F-08bc2fc94856 is skipped. The gate remains zero, so the function returns 0 without comparison, operation delegation, or its own flag store.

9. **Zero destination, successful capacity dependency.** With an original destination argument of zero, suppose the earlier reads complete and indicate insufficient capacity. If F-08bc2fc94856 returns nonzero, comparison proceeds. Subsequent F-e3b26f245f4c delegation still receives destination zero. Completion and store validity require additional assumptions not established here.

10. **Zero destination on the direct path.** Exactly one flag is zero and the destination argument is zero. F-782bee8991b2 is still called with that destination. There is no wrapper-level zero-address rejection on this path.

11. **Signed boundaries.** With sizes −2 and −1, the selected signed maximum is −1. Capacity 0 is sufficient. With a nonzero destination, the gate permits comparison without a capacity dependency call. This specifies branching, not validity of negative-sized objects.

12. **Equality boundaries.** Capacity equal to the selected maximum bypasses F-08bc2fc94856, but continuation still requires a nonzero original destination. A comparison result of zero takes the nonnegative branch and produces flag 0 after operation success.
