# F-82ab31f0118d

## Purpose

F-82ab31f0118d performs an in-place memory fill over a caller-supplied destination. It returns no value.

Two details distinguish its established behavior from an unconditional, conventional byte-fill contract:

- The element count is interpreted as signed for the initial size decision and the final byte-writing loop. Under the 32-bit interpretation described below, counts with the high bit set cause no destination writes.
- Larger positive counts use aligned word stores. The stored word is formed from the entire third argument, not from its low byte alone. Consequently, arbitrary third-argument values can produce different destination bytes depending on alignment and count.

**Inferred intent:** the routine appears intended as an optimized byte-fill operation, with byte stores around an aligned word-writing phase. That intent does not justify narrowing its observable behavior to repeated low-byte writes for every possible third argument.

## Behavior

### 1. Interpret the count for path selection

The initial decision compares the count’s signed interpretation with 16.

Under the 32-bit model:

- Counts from 0 through 16 bypass the alignment and word-writing phases.
- Counts from 17 through 2,147,483,647 enter those phases.
- Counts from 2,147,483,648 through 4,294,967,295 have a negative signed interpretation. They bypass those phases and also fail the later positive-count test, so they produce no destination writes.

The function does not reject a high-bit-set count with an error. It simply reaches its return without performing a fill.

### 2. Small positive counts use byte stores only

For counts from 1 through 16, the function writes consecutive bytes starting at the supplied destination.

Each byte receives the low eight bits of the fill value. The destination advances by one byte after each store, and the remaining count decreases by one.

This path does not first align the destination. Destination alignment therefore does not change the sequence of values written on this path.

A count of zero produces no stores.

### 3. Larger positive counts first align the destination

For counts from 17 through 2,147,483,647, the function first examines the destination address modulo four.

If the address is not four-byte aligned, it writes individual bytes until the next four-byte boundary. Each such store uses the low eight bits of the fill value.

The number of prefix bytes is:

| Initial address modulo four | Prefix byte stores |
|---|---:|
| 0 | 0 |
| 1 | 3 |
| 2 | 2 |
| 3 | 1 |

Each prefix store reduces the remaining count by one. Because this phase is entered only for counts above 16, alignment cannot exhaust the count under the stated model.

The prefix stores occur at increasing addresses. No word store precedes them.

### 4. The aligned body uses a full-width pattern

After alignment, the function writes four bytes at a time while the remaining count exceeds three.

Each word store writes the same 32-bit pattern, formed by taking the bitwise OR of:

- The fill value.
- The fill value shifted left by eight bits.
- The fill value shifted left by sixteen bits.
- The fill value shifted left by twenty-four bits.

Shifts and the resulting pattern are evaluated within the unsigned 32-bit model. Bits shifted beyond that width do not appear in the stored result.

This construction does **not** first mask the fill value to eight bits.

Let the fill value’s bytes, ordered from least significant to most significant, be \(b_0, b_1, b_2, b_3\). The resulting pattern has these bytes in increasing order of numerical significance:

| Pattern byte | Value |
|---|---|
| Least significant | \(b_0\) |
| Next | \(b_0 \mathbin{\mathrm{OR}} b_1\) |
| Next | \(b_0 \mathbin{\mathrm{OR}} b_1 \mathbin{\mathrm{OR}} b_2\) |
| Most significant | \(b_0 \mathbin{\mathrm{OR}} b_1 \mathbin{\mathrm{OR}} b_2 \mathbin{\mathrm{OR}} b_3\) |

If the fill value is between 0 and 255 inclusive, its upper three bytes are zero. All four pattern bytes then equal its low byte, regardless of endianness.

For other fill values, the pattern can contain differing bytes. The same fill value may therefore yield different byte sequences on the small-count and larger-count paths.

After each word store, the destination advances by four bytes and the remaining count decreases by four.

### 5. The final remainder uses byte stores

Once fewer than four bytes remain, the function writes the remainder individually.

Each remainder byte receives the low eight bits of the original fill value, not a byte selected from the word pattern.

The stores proceed in increasing address order. For a successful larger-count operation, the logical write sequence is therefore:

1. Zero to three prefix byte stores.
2. Consecutive aligned four-byte stores.
3. Zero to three trailing byte stores.

The resulting covered interval is exactly the requested destination range. The routine neither intentionally writes before its beginning nor beyond its end.

For an eligible positive count \(N\), let \(p\) be the prefix length from the alignment table. The word-store count is \(\lfloor(N-p)/4\rfloor\), and the trailing-byte count is \((N-p)\bmod 4\).

## Acceptance examples

These are conditional acceptance examples derived from static evidence. They are not runtime test results.

### Zero count

- The fill value has no effect.

### Small count ignores upper fill bits

Given a valid destination, a count of three, and a fill value of `0x08040201`:

- The three destination bytes become `01 01 01`.
- No word-pattern store occurs.
- The destination’s alignment does not change these three values.

### Threshold at sixteen

Given a valid four-byte-aligned destination, count 16, and fill value `0x08040201`:

- All sixteen bytes become `01`.
- The aligned word phase is not selected.

The threshold is strictly greater than 16, not greater than or equal to 16.

### Aligned larger count with upper fill bits

Given a valid four-byte-aligned destination, count 17, and fill value `0x08040201`:

- The word pattern is `0x0F070301`.
- Four consecutive word stores cover the first sixteen bytes.
- A final byte store writes `01` at offset 16.

On a little-endian target, each word contributes the address-ordered sequence `01 03 07 0F`.

On a big-endian target, each word contributes `0F 07 03 01`.

These differing byte sequences are conditional on target endianness; neither endianness is established by the supplied material.

### Unaligned larger count

Given a valid destination whose address is congruent to one modulo four, count 17, and fill value `0x08040201`:

- Offsets 0 through 2 receive prefix byte stores of `01`.
- Three word stores cover offsets 3 through 14 using pattern `0x0F070301`.
- Offsets 15 and 16 receive trailing byte stores of `01`.

Thus changing only destination alignment can change the placement of bytes other than `01`.

### Conventional byte-valued fill

Given a valid destination, count 19, and fill value `0xA5`:

- All nineteen bytes become `A5`.
- Alignment changes the mix of byte and word stores, but not the final byte values.

### High-bit-set count

Under the stated signed 32-bit interpretation, a count of `0x80000000` or `0xFFFFFFFF` produces no destination writes.

Such inputs do not request a successful fill of a very large unsigned-sized region under this contract.
