# F-6944981dc714

## Purpose

F-6944981dc714 conditionally retrieves one byte from an address derived from a caller-supplied object and a value processed by dependency F-9c4fe7643018.

The function first delegates to F-9c4fe7643018. A zero dependency result produces a zero return byte without performing the subsequent object-header or selected-byte reads. A nonzero dependency result causes the function to read the object’s current first 32-bit word, combine it with a dependency-writable position value, and return the byte at the resulting address.

This is a description of established static behavior, not a claim that the address calculation is safe or that the returned byte has a particular semantic meaning. The apparent intent is a conditional lookup using a translated position. The meanings of the object, position, and constant displacement are not established.

### Output

The result is one 8-bit value:

- Zero if F-9c4fe7643018 returns zero.
- The selected memory byte if F-9c4fe7643018 returns any nonzero value.

The output is a raw byte. The evidence does not establish a signed-character interpretation, text encoding, Boolean normalization, or wider return-value extension convention.

## Behavior

### Dependency invocation

Before invoking the dependency, the function establishes:

- A result byte initially equal to zero.
- A private 32-bit position slot initially equal to the second argument.

It then invokes F-9c4fe7643018 with five arguments in this positional order:

1. The object address.
2. The address of the private position slot.
3. Opaque value A.
4. Opaque value B.
5. The same object address supplied in the first position.

This positional order describes the dependency interface. It does not establish a machine-level argument evaluation order, register assignment, or stack layout.

The dependency’s return is tested as a signed 32-bit value for equality to zero. Only zero versus nonzero matters. Negative values take the same subsequent path as positive values.

The private position slot is writable by the dependency. The function uses its value after the dependency returns, whether that value is unchanged or has been replaced.

### Zero dependency result

If the dependency returns zero:

- The function returns the initially established zero byte.
- It does not perform the subsequent read of the object’s first word.
- It does not perform the selected-byte read.

These statements apply to accesses performed directly by F-6944981dc714 after the call. They do not constrain accesses, mutations, or failures inside the dependency.

In particular, a zero dependency result does not prove that the object was untouched. It also does not make an otherwise invalid object address safe to supply: the dependency receives that address before the result is available.

### Nonzero dependency result

If the dependency returns nonzero, the function uses three values:

- The originally supplied object address, as an address base.
- The current value of the private position slot after the dependency returns.
- The signed 32-bit word currently stored at the object address.

The target byte address is described mathematically as:

**object base + (post-call position − post-call first word) + 13 bytes**

The constant displacement is decimal 13. It is a byte displacement, not thirteen 32-bit elements.

The function reads exactly one byte at the selected address and returns that byte without an explicit transformation.

The first-word read occurs after the dependency call. Consequently, if the dependency modifies that word and returns nonzero, the modified word participates in address selection. The function does not retain a pre-call snapshot of the word.

Likewise, a dependency modification of the selected byte can affect the returned result. There is no pre-call snapshot of that byte.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes that the dependency returns normally and that all accesses needed by the described path are valid.

### Zero result prevents the final lookup

Suppose the dependency returns zero after changing both the private position slot and the object’s first word.

The required result is zero. F-6944981dc714 performs neither its post-call first-word read nor its selected-byte read. Dependency side effects remain possible; there is no rollback.

### Equal position and first word

Suppose the dependency returns nonzero, leaves the private position at 40, and the post-call first word is also 40.

The difference is zero, so the selected address is 13 bytes after the object base. If that byte contains hexadecimal A7, the returned byte is hexadecimal A7.

### Updated position controls the lookup

Suppose the initial position is 100, but the dependency replaces the private position with 108 and returns nonzero. The post-call first word is 100.

The selected address is 21 bytes after the object base: the difference of 8, plus the fixed displacement of 13. The initial position does not independently determine the lookup after the dependency has changed the copy.

### Updated first word controls the lookup

Suppose the post-call position is 108. The object’s first word was 100 before the call but becomes 104 during the dependency call, which returns nonzero.

The selected address is 17 bytes after the object base, not 21. The post-call first word is authoritative for this calculation.

### Negative dependency result still selects a byte

Suppose the dependency returns negative one.

The function takes the nonzero path. It does not convert that result into a zero return or treat it as a separately handled error.

### Negative difference is not rejected

Suppose the post-call position is 7 and the post-call first word is 10.

The mathematical displacement is 10 bytes after the object base: a difference of negative 3, plus 13. If the address arithmetic has the intended representation and the accesses are valid, that byte is returned.

### Zero selected byte is indistinguishable from the zero-result path

Suppose the dependency returns nonzero and the selected byte contains zero.

The function returns zero, exactly as it does when the dependency returns zero. The return byte alone cannot identify which path occurred.
