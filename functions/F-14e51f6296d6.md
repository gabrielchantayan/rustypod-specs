# F-14e51f6296d6

## Purpose

F-14e51f6296d6 coordinates scanning of a bounded byte region using two context-supplied callbacks. It counts qualifying occurrences of a fixed 17-byte marker and dispatches recognized slash-prefixed names through a global table.

The established behavior is orchestration. The supplied body does not establish the callbacks’ lexical rules, the table’s names, or the operations performed by dispatch.

The result is the context’s 32-bit status word at exit. The function initially clears that word. Dependencies may subsequently modify it, and each dispatch result explicitly replaces it.

## Interface

### Arguments and representation

The function receives four arguments:

1. **Owner reference.** Passed unchanged to F-f3e5a887c66a. A signed 32-bit field at byte offset 300 is also read when a marker comparison succeeds.
2. **Mutable context reference.** Provides addresses, callbacks, status, and a marker counter.
3. **Region start.** Initial byte address.
4. **Region extent.** A signed 32-bit quantity added to the start to obtain a fixed end address.

The visible representation uses four-byte context words, including words containing addresses. This contract therefore describes the apparent 32-bit address-and-word model. Original source-language pointer types and overflow rules are not fully established.

| Context word | Byte offset | Role |
|---|---:|---|
| 0 | 0 | Mutable current address |
| 2 | 8 | Published region end |
| 3 | 12 | Status and returned value |
| 7 | 28 | First callback address |
| 8 | 32 | Second callback address |
| 24 | 96 | Marker counter |

Each callback receives only the context reference as its visible argument. Its return value is ignored.

A separate global location contains the dispatch-table base address. Table entries occupy seven 32-bit words, a 28-byte stride. An entry’s first word contains its name address; a zero name address terminates traversal. The other six words are not interpreted directly by this function.

### Outputs and ownership

The function returns the four-byte contents of context word 3. It does not normalize that value or provide a separate error classification.

The context is modified in place. No direct allocation, release, ownership transfer, or retention beyond the call is visible. Dependency ownership behavior remains unknown.

### Preconditions

Safe execution requires:

- Valid owner and context storage for every reached access.
- Callable addresses in callback slots when invoked.
- Meaningful address arithmetic for the region end and intermediate offsets.
- Readable candidate bytes, table entries, and table names whenever accessed.
- A table traversal that reaches a null name or a match without leaving valid storage.
- Dependencies that leave subsequently accessed storage valid.

There is no visible validation of these requirements. A zero byte does not terminate the region scan. Negative extents, invalid addresses, arithmetic wraparound, and absent callback progress do not produce dedicated local errors.

## Behavior

### Initialization and retained bounds

The function computes the fixed end from the supplied start and extent. It then writes, in order:

1. The start into context word 0.
2. The fixed end into context word 2.
3. Zero into context word 3.

Context word 24 is not initialized.

The fixed end is retained independently of context word 2. Dependency changes to the published end do not change the bound used by this invocation.

A local scan position initially equals the supplied start. At the beginning of every iteration, the function writes that position into context word 0. Thus the initial current-address write is repeated before the first callback.

### First callback and marker-scan bound

Each entered iteration loads and invokes the callback currently in context word 7.

There is no preceding empty-region or status check. In particular, the first callback runs when start equals end.

After that callback, the function reads context word 0 and chooses a marker-scan limit:

- If the current address is below the fixed end, the limit is that address minus 17 bytes.
- Otherwise, the limit is the fixed end minus 18 bytes.

The scan examines candidates strictly below this limit. A candidate equal to the limit is excluded.

The starting position is the retained local scan position, not the callback-produced current address. Consequently, this scan is not simply a search over every position at which 17 bytes would fit.

### Marker processing

Candidates advance one byte at a time. At each reached candidate:

1. Read its first byte.
2. Only if that byte is `%`, invoke F-fca51b715561 with the candidate address, the fixed marker reference, and length 17.
3. Only if the dependency returns zero, read the owner’s signed 32-bit field at byte offset 300.
4. Only if that field is strictly positive, increment context word 24.

The owner field is read separately for each successful comparison. It is not cached at entry. A nonzero comparison result suppresses that owner-field read.

Successful comparisons do not skip the remaining marker bytes. The next candidate remains the following byte.

The scan limit is retained throughout this scan, including across comparison calls. Changes to context word 0 during those calls do not alter the current scan’s limit or local candidate progression. They can affect the subsequent end check.

The counter update is a four-byte increment without an overflow check, saturation, or associated status assignment. Under ordinary 32-bit machine-word arithmetic, incrementing the all-ones value produces zero. The original source-language overflow contract is not established.

### Post-scan end check

After the marker scan, the function reloads context word 0.

If this address is at or beyond the retained fixed end, the function exits and returns the current status. The second callback is not invoked.

This reload matters: a below-end address immediately after the first callback does not ensure that the second callback will run. Intervening marker-comparison calls may change the context address.

If the reloaded address is below the fixed end, it is retained as the token-start address. The function then loads and invokes the callback currently in context word 8.

### Second callback and status check

After the second callback, the function reloads context word 0 and checks:

1. Whether that address is at or beyond the fixed end.
2. Only if it is below the end, whether context word 3 is nonzero.

Either condition causes exit before slash inspection. When the address has reached the end, the status test is bypassed, although the status word is still read to obtain the eventual return value.

A nonzero status from the first callback is not an immediate stop condition. It does not prevent the marker scan or, if the post-scan address remains below the end, the second callback. Any intervening dependency may change that status.

### Slash inspection and global-table read

If neither exit condition applies, the function reads the byte at the retained token-start address, captured before the second callback.

A non-slash byte bypasses table processing. The global table-base location is not read on that path.

For a slash byte, the following ordering applies:

1. Form the address two bytes beyond the retained token start.
2. If that address is strictly below the fixed end, calculate the name start as one byte beyond the slash and calculate the apparent name length from that name start to the address returned through context word 0 by the second callback. Also form the length-minus-one eligibility quantity.
3. **Load the global dispatch-table base address.**
4. Evaluate the combined fixed-end-margin and length eligibility gate.

Thus every path that recognizes the retained token-start byte as a slash performs the global table-pointer read, even if the margin or length gate subsequently fails. The read is not conditional on successful eligibility.

The name-length calculation itself is conditional on sufficient fixed-end margin. When that margin fails, the combined gate fails without using the uncomputed length.

Under ordinary unsigned 32-bit address-shaped arithmetic, the length gate requires length minus one to be less than 21. With sensible, nonwrapping token boundaries, eligible lengths are therefore 1 through 21 inclusive. Zero underflows and fails; 22 also fails.

No trailing delimiter is independently subtracted. The second callback’s convention for its resulting address determines which bytes constitute the candidate name.

### Table traversal

If both eligibility conditions succeed, traversal begins at the retained table base.

The global base is loaded once for this lookup. A dependency changing the global pointer during traversal does not redirect the ongoing lookup. This retention does not snapshot the table: each visited entry’s name address and the relevant name bytes are read during traversal.

For each entry:

1. Read the entry’s first word.
2. If the name address is zero, stop without dispatch.
3. Otherwise, read and compare the candidate’s first byte and the table name’s first byte.
4. Only when those bytes match, invoke F-1cb585febd84 with the table-name address.
5. Only when its result equals the retained candidate length, compare the remaining bytes, starting at index 1.
6. Stop the byte comparison at the first mismatch or after the candidate length is covered.

Comparisons are byte equality checks with no visible case conversion or normalization. For a one-byte candidate, matching first bytes and the reported length suffice; no remaining-byte comparison is required.

The table-name address loaded for an entry is retained across its length call. Mutating the entry’s name-address word during that call does not replace that retained address for the current comparison. Mutations to name bytes or subsequently visited entries may still affect later reads.

A failed match advances the entry address by 28 bytes. The function does not reload the global base when advancing.

### Matching dispatch and continuation

A full match invokes F-f3e5a887c66a with:

- The original owner reference.
- The context reference.
- The matching entry’s address.

Its returned 32-bit value is immediately stored in context word 3, replacing any status written internally by the dispatcher.

A nonzero returned value causes immediate exit. A zero return ends the table lookup without considering later matching entries.

If processing has not exited, the function reloads context word 0 and adopts that address as the next iteration’s local scan position. This occurs after dispatch when dispatch was reached.

There is no independent progress check or iteration limit. Nor is there a general status check at the bottom or beginning of an iteration. For example, a name-length dependency’s status write does not itself stop traversal or prevent entry into the next iteration.

## Side effects

### Direct accesses and mutations

The function directly:

- Initializes context words 0, 2, and 3 in that order.
- Rewrites context word 0 at every iteration start.
- Reads callback slots when their calls are reached.
- Reads candidate bytes during marker scanning and name matching.
- Reads the owner field only after a zero marker-comparison result.
- Increments context word 24 for qualifying markers.
- Reads the global dispatch-table pointer on every slash-inspection path, before the combined eligibility gate.
- Reads table-entry contents and table-name bytes during traversal.
- Stores dispatch results into context word 3.
- Reads context word 3 for the return value.

Failed eligibility performs the global base read but does not traverse table entries.

### Dependency effects and validity

No dependency is assumed pure or assumed to preserve globals, context fields, counters, callback slots, table data, or owner data.

In particular:

- Marker-comparison calls can affect the post-scan address and status.
- Name-length calls can change the global table pointer without redirecting the retained traversal base.
- Table contents may change even though the traversal base is retained.
- A dispatcher can change the address used for the next iteration.
- A dependency may allocate or release memory; this function’s visible calls do not establish its ownership rules.

Safe continuation requires all later accesses to remain valid. Passing a reference alone is not evidence of ownership transfer.

The described access ordering is the ordering visible in the supplied body. It does not establish atomic, volatile, synchronization, concurrent-access, or reentrancy guarantees.

## Acceptance examples

These examples are conditional consequences of static evidence, not executed tests. They assume valid storage and nonwrapping address arithmetic.

1. **Empty region still calls the first callback.**  
   If start equals end and the first callback leaves the current address unchanged, initialization and the first callback occur. The marker scan has no candidates, the post-scan end check exits, and the second callback does not run.

2. **First-callback status does not immediately stop processing.**  
   Suppose the first callback writes nonzero status and leaves the current address below the fixed end. If the address remains below the end through the entire marker scan, the second callback runs. If the nonzero status survives all intervening calls, including that callback, and its resulting address remains below the end, the later status check exits before slash inspection.

3. **A marker dependency can suppress the second callback.**  
   Suppose a reached marker-comparison call changes context word 0 to the fixed end. Even if the first callback originally left it below the end, the post-scan reload observes the new address and exits without the second callback.

4. **Counting requires all predicates.**  
   An examined `%` candidate increments the counter only when F-fca51b715561 returns zero and the subsequently read owner field is positive. A nonzero comparison result prevents the owner-field read; a zero or negative owner field prevents the increment.

5. **Marker limits are exclusive.**  
   When the first callback leaves an address below the fixed end, a candidate exactly 17 bytes before that address is excluded. A candidate 18 bytes before it is examined if the local scan start does not lie after it.

6. **Reaching the end suppresses slash inspection.**  
   If the second callback leaves the current address equal to the fixed end, the function exits without reading the retained token-start byte or loading the global table base.

7. **Failed slash margin still reads the global pointer.**  
   If slash inspection succeeds but token start plus two equals the fixed end, the function loads the global table base and then skips traversal. Candidate length is not calculated on this path.

8. **Failed length eligibility still reads the global pointer.**  
   Given sufficient fixed-end margin, a calculated length of 22 fails eligibility under the unsigned interpretation. The global base is nevertheless read before that failure prevents traversal.

9. **Eligible lengths include both endpoints.**  
   With all other gates satisfied, lengths 1 and 21 can reach traversal. Lengths 0 and 22 cannot under the stated unsigned interpretation.

10. **Changing the global base does not redirect a lookup.**  
    Suppose F-1cb585febd84 replaces the global table pointer while examining an entry that ultimately fails to match. The next entry remains 28 bytes after the current entry in the retained traversal, not the first entry of the replacement table. Mutations to that next entry’s contents can still affect its processing.

11. **The first match dispatches once.**  
    With multiple matching entries, only the first encountered match is dispatched. A zero dispatch result ends the lookup; later matches are not tried.

12. **Dispatch return replaces status and controls immediate exit.**  
    If dispatch writes one status value but returns another, the returned value is stored. Nonzero exits immediately; zero permits continuation using the latest context word 0.
