# F-63a4b63555dc

## Purpose

F-63a4b63555dc conditionally selects a payload address from an indexed record. On one successful path, it writes that address to caller-provided output storage and conditionally increments a preceding header field. On the other, it obtains a storage base through a dependency, writes an adjusted destination address to the output, and invokes another dependency with that destination and a freshly read source address.

Initial ineligibility or either failed bound comparison delegates handling to F-9b9c1c7483f4.

“Payload,” “header,” “sharing,” and “duplication” describe inferred roles. The established contract is the sequence of reads, comparisons, arithmetic, writes, and dependency calls below. Complete ownership and dependency semantics are unknown.

This specification rests on static evidence only. No runtime tests have been performed.

## Interface

The function accepts four inputs and has no explicit return value or local status result.

| Input | Representation and use |
|---|---|
| Output slot | Address of storage receiving a 32-bit address-bearing word on either successful selection path. Also passed to certain dependencies. |
| Descriptor | Address of storage containing a 32-bit object-address word followed by a control region. |
| Requested index | Unsigned 32-bit integer used in comparisons and, conditionally, an index transformation. |
| Auxiliary value | Opaque 32-bit value forwarded to dependencies. |

The supplied representation establishes 32-bit signed integers, unsigned integers, and address-bearing words. It does not establish portability to other pointer or integer widths.

### Accessed layout

Offsets are in bytes.

| Location | Established access |
|---|---|
| Descriptor, offset 0 | 32-bit object-address word, read initially and reloaded on later paths. |
| Descriptor, offset 4 | Unsigned one-byte control value, initially read only when the first object-address word is nonzero. |
| Descriptor, offsets 4–7 | Signed 32-bit control word, read after the first bound check passes and converted to plain character type. |
| Object, offset 20 | 32-bit collection-address word. |
| Collection | Indexed records with a 40-byte stride. |
| Selected record, offset 16 | 32-bit payload-address word. |
| Payload, offset −12 | Signed 32-bit header field, tested against −1 and conditionally incremented. |
| Payload, offset −4 | Opaque 32-bit size-like word, saved for dependency arguments. |

No access to the payload-associated word at offset −8 is established.

The initial control-byte read and later control-word read are distinct operations. The later comparison is based on conversion of an entire word to plain character type, not an explicitly repeated byte load. Its correspondence to the byte at offset 4 depends on target representation and conversion rules.

### Preconditions and storage requirements

Every location actually accessed on the executed path must support the represented access width, address interpretation, and any target-required alignment. Directly modified storage must be writable.

In particular:

- The descriptor’s initial word must always be readable.
- A nonzero initial object requires the control byte to be readable.
- Passing the first bound check requires all four bytes of the later control-word access to be readable.
- Successful record selection requires the relevant object, collection, record, payload, and header locations to be readable.
- The output slot must support a 32-bit write on a successful path.
- A header field that is incremented must support a 32-bit write.

Defined execution under ordinary signed-arithmetic rules additionally requires that the signed calculations described below do not overflow. Integer-to-pointer interpretation and out-of-range unsigned-to-signed conversion remain target-dependent.

The function does not establish storage validity, collection capacity, allocation success, or consistency between a payload and its size-like word. It explicitly handles an initial zero object-address word, but does not generally validate addresses.

No enforced non-aliasing condition is visible. Output writes and dependency effects can change storage that is subsequently reread.

## Behavior

### Initial eligibility and first bound

The function first reads the descriptor’s object-address word.

If that word is zero, it calls F-9b9c1c7483f4 with the output-slot address and auxiliary value, then returns. The initial control byte is not read, and neither bound query occurs.

Otherwise, it reads the unsigned byte at descriptor offset 4. If that byte is zero, it takes the same fallback without calling the bound-query dependency.

For a nonzero object word and nonzero control byte, the first call to F-e84094e554a6 has seven visible arguments, in this order:

1. Initially loaded object address.
2. Initially loaded control byte, zero-extended and represented as a pointer-like argument.
3. Requested index.
4. Auxiliary value.
5. Descriptor address.
6. Requested index again.
7. Auxiliary value again.

This is the visible call form, not an independently verified dependency signature.

The returned value is treated as unsigned 32-bit. The requested index must be less than or equal to it. Equality permits continuation; a larger index causes fallback.

### Control conversion and effective index

After the first comparison passes, the function reads the signed 32-bit word at descriptor offset 4, converts it to plain character type, and compares the converted value with 2.

If equal, the effective index is twice the requested index plus one. Multiplication and addition use unsigned 32-bit arithmetic, wrapping modulo \(2^{32}\).

Otherwise, the effective index remains the requested index.

This read occurs after the first dependency call. Therefore, a dependency mutation can change the transformation decision. The initial nonzero-byte condition is not checked again.

The full word must be readable even if only part of its value determines the converted character. On a target with little-endian words and conversion retaining the low eight bits, the condition corresponds to the byte at offset 4 being 2. That equivalence is conditional, not a target-independent guarantee.

### Second bound and captured distinguished address

The function reloads the descriptor’s object-address word and calls F-e84094e554a6 with that word as its sole visible argument.

There is no renewed eligibility check. This call still occurs if the reloaded word has become zero.

After that call returns, the function reads a global address value used to recognize a distinguished header-field location. This global read precedes the second bound comparison, including when the comparison fails.

The second result is treated as unsigned 32-bit. The effective index must be less than or equal to it. Equality permits selection; a larger value causes fallback.

Neither query result is established to mean a count, capacity, or last valid index. Their established role is to supply inclusive comparison bounds.

### Record and payload selection

After the second comparison passes, the function:

- Reloads the descriptor’s object-address word again.
- Reads the collection-address word at object offset 20.
- Computes the selected record using the effective index and a 40-byte stride.
- Reads the payload-address word at selected-record offset 16.
- Reads the signed header field at payload offset −12.

The selection object can differ from the object supplied to either query. The collection is not read until both comparisons have passed.

The arithmetic distinctions are significant:

| Calculation | Established arithmetic |
|---|---|
| Twice the requested index plus one | Unsigned 32-bit, modulo \(2^{32}\). |
| Effective index multiplied by 40 | Unsigned 32-bit, modulo \(2^{32}\). |
| Collection-address word plus record offset | Unsigned 32-bit addition under the represented operand conversions, followed by assignment to a signed 32-bit address-bearing value. |
| Object address plus 20 | Signed 32-bit arithmetic. |
| Selected-record address plus 16 | Signed 32-bit arithmetic. |
| Payload address minus 12 or minus 4 | Signed 32-bit arithmetic. |
| Returned storage base plus 12 | Signed 32-bit arithmetic. |
| Header increment | Signed 32-bit addition. |

An out-of-range unsigned record address converted to a signed word has target-dependent interpretation. Signed overflow is not established as wrapping. The function provides no explicit overflow checks.

### Existing-payload path

If the initially tested header field is not −1, the function:

1. Writes the selected payload address to the output slot.
2. Forms the address of the header field at payload offset −12.
3. Compares that address with the previously captured distinguished global address.
4. If the addresses differ, rereads the header field, adds one, and writes the result back.
5. Returns.

The comparison is between addresses, not header values.

If the addresses match, only the increment is suppressed. The output write still stores the selected payload address—not the header value and not the header-field address.

The output write precedes the increment’s read. If the output slot aliases the header field, the increment uses the newly written value rather than necessarily using the value that selected this path. Consequently, the final contents of the output slot need not remain the selected payload address under such aliasing.

The increment is not visibly atomic. It has no established unconditional wraparound behavior.

### Obtained-storage path

If the initially tested header field equals −1, the function:

1. Reads and saves the opaque 32-bit word at payload offset −4.
2. Calls F-fe78e25e82ff with the output-slot address and the saved word twice.
3. Adds 12 to the returned signed 32-bit address-bearing value.
4. Writes that adjusted address to the output slot.
5. Rereads the payload-address word at offset 16 of the already selected record.
6. Calls D-01 with the adjusted destination address, the reread source address, and the saved word.
7. Returns.

D-01 is an opaque identifier for the external dependency lacking a supplied mapped function ID.

Record selection is not repeated after F-fe78e25e82ff. Its effects, or an aliased output write, can change the selected record’s payload-address field before the source reread.

The size-like argument remains the word saved from the original payload. The function does not check that it matches the reread source, nor repeat the original header test.

The destination passed to D-01 is calculated from the returned base, not obtained by rereading the output slot. There is no visible allocation-failure check, local header initialization, or local header increment on this path.

### Fallback

Initial ineligibility or either failed bound comparison calls F-9b9c1c7483f4 with the output-slot address and auxiliary value, then returns.

No direct local output write precedes fallback. Dependencies already called on that path may nevertheless have changed output storage or other state.

Fallback does not establish that the output becomes null, unchanged, empty, released, or otherwise valid.

## Side effects

Established direct effects are:

- Path-dependent reads from descriptor, global, object, record, and payload-header storage.
- A 32-bit output write on either successful selection path.
- A conditional header-field read-modify-write on the existing-payload path.
- The dependency calls described above.

The function does not read the previous output value before replacing it and performs no visible local release.

Sharing and separate-storage duplication are inferred intent. The source does not establish who owns or releases the resulting address, whether a dependency disposes of previous output contents, or whether obtained storage has an initialized header.

Dependencies are not assumed to preserve globals, descriptor contents, records, output storage, or other reachable memory. The distinguished address is captured after the second query. Mutations before that read can affect the comparison; later changes to the global do not replace the captured value.

Final output contents are not guaranteed solely by the local assignment: aliasing or later dependency effects may modify the same storage.

No locking, atomic increment, rollback, or cleanup for interrupted execution is visible. Concurrent access and overlapping copy-like regions have no established handling.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. Unless stated otherwise, dependencies return normally, required accesses and arithmetic are valid, and storage remains stable except for the specified effects.

1. **Zero initial object.**  
   A zero initial object-address word causes fallback without reading the control byte or calling either bound query.

2. **Zero initial control byte.**  
   A nonzero initial object and zero control byte cause fallback before the first query. The later four-byte control read does not occur.

3. **First inclusive boundary.**  
   Requested index 7 and first result 7 permit continuation. First result 6 causes fallback before the control-word read and second query.

4. **Different control-access widths.**  
   If the initial object word and control byte are readable but some remaining byte in descriptor offsets 4–7 is inaccessible, a passing first comparison reaches an access whose precondition is unmet. The later access is not reduced to a byte read.

5. **Transformed index.**  
   Requested index 3 becomes effective index 7 when the later control word converts to character value 2. The second comparison and record selection both use 7.

6. **Dependency-mutated control.**  
   A nonzero initial control byte permits the first query. If that query changes the word so its converted character is 2, transformation occurs regardless of the initial byte’s different nonzero value.

7. **Unsigned transformation wrap.**  
   Requested index 2,147,483,648 becomes effective index 1 when the first bound permits it and the converted control equals 2. This does not imply wrapping signed address arithmetic.

8. **Second inclusive boundary.**  
   Effective index 5 and second result 5 permit selection; result 4 causes fallback. In both cases, the distinguished global address is read after the query and before the comparison.

9. **Ordinary increment.**  
   A selected payload with header value 4 and a header-field address different from the captured distinguished address has its payload address written to output and its header incremented to 5, provided the output does not alias that header.

10. **Distinguished header-field address.**  
    Suppose the selected payload address is 4096, its header field is at 4084 with value 4, and the captured distinguished address is 4084. With disjoint output storage, the output receives **4096**, while the header remains **4**. Neither 4 nor 4084 is stored in the output by this path.

11. **Output aliases the incremented header.**  
    Suppose the payload address is 4096, its header initially contains 4, the output slot is that header field, and its address is not distinguished. The output assignment first writes 4096 there. The subsequent increment reads 4096 and writes 4097. The final aliased output/header value is 4097.

12. **Changed source after storage acquisition.**  
    An original header of −1 and size-like word 24 cause F-fe78e25e82ff to receive the output address and 24 twice. If it returns a usable base and changes the selected record’s payload address, the output receives base plus 12. D-01 receives that destination, the changed source, and the original saved word 24.

13. **Destination overflow.**  
    A returned signed base for which adding 12 exceeds the signed 32-bit range does not establish a wrapped destination. Such behavior remains unresolved.

## Evidence

Established static evidence consists of the supplied function representation’s access widths and offsets, short-circuit eligibility checks, repeated descriptor reads, word-to-character conversion, unsigned comparisons, arithmetic operand types, visible dependency arguments, and ordering of reads, writes, and calls.

In particular, the existing-payload path assigns the selected payload address to output before comparing the header-field address with the captured distinguished address. An address match suppresses only the increment.

Reference counting, storage allocation, and copying are inferred intent, not additional guarantees. No runtime execution or tests have been performed.
