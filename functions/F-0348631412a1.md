## Behavior

### Initial and repeated writes

The first four-byte write stores the doubled secondary at second-argument offset `0x54`.

The next three writes establish the recurring byte and value destinations:

- The primary character value is written as one byte at global-base offset `0x19`.
- A one-byte conversion of the global base is written at primary-base offset `0x11`.
- The second argument is written as four bytes at global-base offset `0x34`.

A finite, unconditional repeated phase follows. Each repetition writes the doubled secondary as four bytes at doubled-primary offset `0x54`, then writes the primary character byte at global-base offset `0x19`, then the retained global-base byte at primary-base offset `0x11`, and finally the doubled primary as four bytes at global-base offset `0x34`.

These are repeated accesses, not merely a description of the eventual contents. Eliminating repetitions is not trace-equivalent where accesses are observable, faults occur, or storage aliases.

No data-dependent termination is visible in this phase. Its exact repetition count has not been independently enumerated in this contract and remains **documented_only**. This is a limitation of the contract’s certified multiplicity, not evidence that the represented sequence has an unknown runtime loop bound.

### Early snapshots and fixed-address byte result

After the repeated phase, the function reads four bytes from fixed address `0xA9`, then four bytes at doubled-secondary offset `0x74`. Both values are retained for later use.

A one-byte result is then written to fixed address `0x3A`. Its computation uses twice the promoted primary character value plus numeric constant `0x30`, followed by assignment to the one-byte destination.

The intermediate arithmetic must not be described unconditionally as unsigned low-byte arithmetic. For example, a primary low byte of `0xF0` conventionally represents:

- `240` under an unsigned eight-bit character interpretation, producing `528`, or `0x210`, before narrowing.
- `-16` under a signed eight-bit character interpretation with the corresponding bit pattern, producing `16`, or `0x10`, before narrowing.

Under low-eight-bit destination narrowing, both produce final byte `0x10`. The representation does not establish textual formatting or a character-encoding purpose.

Next, four-byte snapshots are taken from secondary-base offset `0x14` and primary-base offset `0x04`, in that order.

### Byte distribution and secondary snapshot

The next group of writes distributes retained bytes and the secondary base. In order:

- Secondary-base offset `0x0D` receives the primary character byte.
- Primary-base offset `0x08` receives byte `0x6C`.
- Primary-base offsets `0x0D` and `0x09` receive the retained global-base byte, in that order.
- Secondary-base offset `0x54` receives the secondary base as four bytes.
- Fixed address `0x67` receives a one-byte conversion of the snapshot from `0xA9`.

A four-byte signed value is then read from secondary-base offset `0x44`. After that read, the byte at fixed address `0x67` is read and written to fixed address `0x21`. This is a fresh memory read, not guaranteed reuse of the previously calculated byte.

### Overlapping-width updates

The snapshot from secondary-base offset `0x44` supplies a character-converted byte at primary-base offset `0x10`, followed by its full four-byte value at global-base offset `0x54`.

That signed snapshot is then right-shifted by the primary base’s low eight bits. A character conversion of the result is written at secondary-base offset `0x01`. The shift count ranges from 0 through 255; the representation does not establish portable behavior for counts of 32 or greater. Right-shifting a negative signed value also requires execution-model clarification.

Global-base offset `0x54` is subsequently overwritten with the primary base as four bytes. Both writes to that destination belong to the visible sequence.

A four-byte read from primary-base offset `0x40` follows. Subsequent writes occur in this order:

- The earlier primary-base offset `0x04` snapshot goes to global-base offset `0x74`.
- The just-read primary-base offset `0x40` value goes to primary-base offset `0x10`.
- The secondary base goes to global-base offset `0x44`.
- A fresh byte read from fixed address `0x67` goes to primary-base offset `0x09`.
- The primary character byte goes to secondary-base offset `0x09`.

Except for the two explicitly described byte writes, these are four-byte writes. In particular, the four-byte write beginning at primary-base offset `0x10` covers the earlier one-byte output at that same offset without removing that earlier access from the trace.

The described order is the static representation’s access order. Atomicity, memory barriers, concurrency guarantees, and external visibility rules are not established.

### Ordinary disjoint storage

### Signedness-sensitive intermediate arithmetic

Assume the primary base’s low byte is `0xF0` and character conversion preserves that bit pattern.

With an unsigned eight-bit character interpretation, the promoted calculation for fixed address `0x3A` is \(240 \times 2 + 48 = 528\), or `0x210`.

With a conventional signed eight-bit character interpretation, the character value is `-16`, and the promoted calculation is \(-16 \times 2 + 48 = 16\), or `0x10`.

Under low-eight-bit destination narrowing, the stored byte is `0x10` in both cases. Neither intermediate result is unconditional across both interpretations.

### Unused explicit input

Given identical memory, implicit state, and other explicit input, changing only the first argument changes no visible expression in the supplied body. This does not settle undocumented calling-convention effects.

### Retained snapshot

This condition concerns the actual read-time value, not necessarily entry memory.

### Intermediate writes remain observable

### Fresh fixed-address reads

### Invalid derived destination

### Shift boundary
