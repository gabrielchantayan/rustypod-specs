# F-c826609a57a6

## Purpose

F-c826609a57a6 conditionally updates an object that selects an active target, obtains an identity and position through a callback, maintains a cached record index, and may submit a record or a shortened remainder. It may also request another update through a two-call scheduling protocol.

The established behavior is indexed-record processing with conditional submission and scheduling. Interpreting positions as time, records as events, or scheduling arguments as delays in particular units is inferred intent, not an established contract.

The function returns no value. Observable results are dependency calls, direct object-field writes, temporary-record contents passed to submission, and scheduling requests. Several paths return without scheduling.

## Interface

### Object input

The sole explicit input represents an object address in a signed 32-bit argument. Observed addresses, handles, indices, and position words are 32 bits wide.

There is no explicit validation of the object address, alignment, accessible extent, callback address, or dependency inputs. The caller must provide usable storage and callable dependencies for the path taken.

### Callback outputs

The indirect callback receives two addresses:

- Storage beginning with two adjacent 32-bit identity words.
- Storage for an unsigned 32-bit position.

Its return is tested for zero versus nonzero. On success, both identity words and the position are consumed. Although only the address of the first identity word is explicitly passed, the adjacent second word is subsequently read.

The function does not initialize these outputs before calling. Successful processing therefore requires the callback to initialize all three consumed words. No opaque function ID or complete ABI is supplied for this callback.

### Fetched records

Fetches populate temporary storage with these observed fields:

| Record offset | Width | Observed role |
|---|---:|---|
| +0x04 | 32 bits | Zero/nonzero field tested on selected paths |
| +0x14 | Unsigned 32 bits | Start position |
| +0x18 | Signed 32-bit storage | Extent used in unsigned arithmetic |

The complete record layout and required buffer extent are unknown. No fetch status is checked. Dependencies must populate the fields subsequently consumed.

Although the extent occupies signed storage, adding it to the unsigned start, or subtracting an unsigned elapsed difference from it, uses unsigned 32-bit arithmetic. Writing an adjusted extent back to signed storage can require an out-of-range conversion.

## Behavior

### Entry and target selection

The enable byte is read first. Zero returns immediately without dependency calls or direct object writes.

Otherwise:

1. F-8b2d02fa1959 supplies a source handle. Zero returns immediately.
2. F-ac356e5603c7 is called; its result is unused.
3. F-78443a7fbacd selects the target field: zero selects +0x1C; nonzero selects +0x20.
4. The selected value is written to +0x24. If that selected value is zero, processing returns after the write.

The nonzero source handle is retained for subsequent source operations. F-5126e2cd0d6c queries its kind. Any result other than 4 bypasses the callback and record processing and schedules argument 1000.

### Callback and identity processing

For source kind 4, the callback is invoked. A zero result returns without position transformation, subsequent direct identity or cache writes, or scheduling by this function.

On success, F-d7be9cfb4000 transforms the callback position using literal argument 10. Its result becomes the unsigned 32-bit position used below.

F-149f181e8f52 is called with the active target. If nonzero, F-c06671f4822e receives the active target and transformed position. The active-target field is reread for the latter call; it is not an immutable snapshot of the earlier selection.

The second callback identity word is compared with the cached second word first. The first words are compared only if the second words match. Any mismatch causes these direct writes, in order:

1. Cached index becomes −1.
2. First cached identity word is replaced.
3. Second cached identity word is replaced.

A mismatch enters initial index resolution. An unchanged identity also enters initial resolution when the cached index is −1.

### Initial index resolution

F-766473d455b3 supplies a signed count. Exactly zero returns without scheduling; negative counts are not universally rejected here.

Otherwise, F-aa715dc026b7 receives the source and transformed position. Its signed result is written to the cached index.

- Result −1 schedules argument 1000.
- Every other result, including other negative values, is passed to F-e9cd4e4f4802 to fetch a record.

After the fetch, target state is queried through F-149f181e8f52. If nonzero, F-e80a10193bb8 supplies an unsigned target position.

A target position strictly below the fetched record start immediately selects difference-based scheduling. This branch does **not** compare the target position with the transformed position. A target position equal to or before the transformed position therefore still schedules.

Otherwise, the record start is selected:

- Start strictly greater than the transformed position schedules from that start.
- Start at or before the transformed position enters cached-record processing.

A target position equal to the record start follows the record-start branch.

### Cached-record validation and continuity

Cached-record processing first queries another signed count. The cached index is read after that call. If the count is less than or equal to that index, the function writes −1 to the cache and returns without scheduling.

Otherwise, it fetches the cached record and separately looks up the transformed position through F-aa715dc026b7.

The lookup is locally continuous when it equals any of:

- The cached index.
- The cached index plus one.
- −1.

All other results are discontinuous. Cache reads used for classification occur after the lookup call, so dependency mutation can affect classification.

There is no general rejection of cached indices below −1 before fetching. The signed index-plus-one operation has no explicit overflow protection.

### Locally continuous processing

For a record whose start is at or before the transformed position, submission is considered only if the position is strictly below the unsigned start-plus-extent endpoint.

This is a start-inclusive, end-exclusive test using a modulo-\(2^{32}\) endpoint, not an unbounded mathematical interval. Endpoint wraparound can prevent submission even when a nonwrapping interpretation would include the position.

When the interval test succeeds, F-308975d8cf2d is called with the receiver at +0x7C. Nonzero permits submission:

- If the record starts strictly before the transformed position, its temporary extent is reduced by the unsigned elapsed difference, then its temporary start is replaced by the transformed position.
- If the starts are equal, neither field is adjusted.
- F-42e3910e1654 receives the current active target and the temporary record address.

The field at record +0x04 is not tested on this submission path.

Whether submission succeeds, is gated off, or is excluded by the interval endpoint, a record starting at or before the transformed position proceeds to cache advancement.

For a record starting after the transformed position, the cache is not advanced. The scheduling candidate is the record start unless a nonzero target-state query enables a strictly earlier unsigned target position.

On this future-record path:

- Lookup −1 and an unsigned candidate-minus-position difference strictly greater than 100 select argument 1000.
- Otherwise, difference-based scheduling is used.

A difference of exactly 100 produces 1001. A candidate below the transformed position can make the unsigned subtraction wrap and trigger the fallback when the lookup is −1.

### Discontinuous processing

For a discontinuous lookup result greater than zero, the immediately preceding record is fetched.

Submission requires all of:

- A nonzero field at record +0x04.
- Transformed position strictly below the unsigned start-plus-extent endpoint.
- A nonzero result from F-308975d8cf2d, called with the receiver at +0x7C and the predecessor index.

There is no explicit requirement that the transformed position be at or after this predecessor’s start.

If permitted, the temporary extent is reduced by unsigned position-minus-start, then the start is replaced by the transformed position. F-42e3910e1654 receives the active target and adjusted temporary record.

A position before the predecessor start can therefore cause wrapped subtraction and extent adjustment; the missing lower-bound test must not be supplied implicitly.

Submission, rejection, or a discontinuous result of zero or a negative value other than −1 all proceed to cache advancement.

### Cache advancement

The function reads the cached index immediately before replacing it with the lookup result.

If the previous value differs from the lookup result, no increment occurs. If equal:

1. The source count is queried.
2. The cached index is reread, incremented, and written.
3. If the incremented index is below that count, its record is fetched.
4. A zero +0x04 field in that fetched record causes a direct cache write of −1.

The increment uses the cache value present after the count call, not necessarily the lookup result just written. If the incremented index is at or beyond the count, no validation fetch occurs at this stage.

If the resulting cache is not −1, another count is queried. When the cache read after that call is below the count, its record is fetched and scheduling is considered:

- An enabled target position strictly below the record start schedules immediately, without comparing against the transformed position.
- Otherwise, a record start at or after the transformed position schedules from that start. Equality is included.

If neither choice schedules, the count is queried again. A cache still below that count causes a return without scheduling or another direct cache write.

Otherwise, **terminal handling** occurs:

- Nonzero target state causes a target-position query and scheduling using the terminal arithmetic described below.
- Zero target state causes no scheduling.
- In either case, the function then directly writes −1 to the cached index.

When terminal scheduling occurs, invalidation is **after both scheduling calls return**.

If advancement instead reaches the **invalid-cache continuation**, target state is queried. Nonzero selects target-position-based scheduling; zero selects argument 1000. This continuation performs no further direct cached-index write. Dependencies may therefore change the cache without a subsequent reset by this function.

### Arithmetic and scheduling protocol

Each scheduling action calls, in order:

1. F-6904f7699031 with the receiver at +0x30 and the scheduling argument.
2. F-ec4cfa552cce with the same receiver.

Neither return value is checked. Scheduling normally ends the invocation; terminal handling additionally invalidates the cache afterward.

Two arithmetic forms must be distinguished.

**Nonterminal difference-based scheduling.** The selected position difference is calculated using unsigned 32-bit subtraction, then assigned to signed 32-bit storage. Multiplication by 10 and addition of 1 subsequently operate on that signed value.

Consequently:

- Subtraction wraps modulo \(2^{32}\).
- An unsigned difference above the signed range requires an out-of-range conversion whose result is not established here.
- Signed multiplication or addition can overflow.
- A universally modulo-\(2^{32}\) final result is not established for these paths.

The invalid-cache continuation additionally stores the target-position result in signed 32-bit storage before subtraction. Mixed signed/unsigned subtraction still produces an unsigned difference, which is then assigned to signed storage before multiplication.

**Terminal scheduling.** The target-position result is first assigned to signed 32-bit storage. The scheduling expression then directly subtracts the unsigned transformed position from that signed value, multiplies by 10, and adds 1.

Because the subtraction includes the unsigned position, the subtraction, multiplication, and addition all use unsigned 32-bit arithmetic. These operations wrap modulo \(2^{32}\); **this expression does not incur signed multiplication or addition overflow**.

The preceding assignment of an unsigned target-position result to signed storage remains a distinct uncertainty when that result exceeds the signed range. Given the stored signed value, however, the subsequent terminal arithmetic is unsigned and modular. Any further interpretation imposed by the scheduling dependency’s parameter ABI is not established.

No path establishes saturation or clamping.

## Side effects

Direct persistent writes are limited to the active target, cached index, and two cached identity words. Temporary records may be modified before submission.

Dependencies and the callback may mutate object fields, globals, source contents, or external state. No preservation guarantees are supplied. Repeated target, count, and cache reads must not be collapsed into assumptions of stable state.

There is no explicit allocation, release, rollback, or exception handler. No dependency result is visibly treated as owned allocated storage.

Submitted addresses refer to temporary record storage. The function does not establish whether F-42e3910e1654 copies the record, borrows it during the call, retains embedded pointers, or retains the supplied address. Long-term ownership transfer cannot be inferred.

Early returns preserve preceding effects. Invalid memory, unsupported indices, incomplete callback outputs, unhandled dependency failures, and nonreturning calls have no established recovery contract.

## Uncertainties

The following remain **documented_only**:

- Domain meanings and units of positions, extents, factor 10, and scheduling arguments.
- The transformation performed by F-d7be9cfb4000.
- Complete object and record layouts, buffer requirements, callback ABI, and scheduling-parameter interpretation.
- Meaning of record +0x04 and submission-gate results beyond zero/nonzero.
- Dependency mutation, reentrancy, errors, and nonreturning behavior.
- Record copying, borrowing, retention, and ownership.
- Out-of-range unsigned-to-signed conversions, including stored differences, adjusted extents, and target-position assignments.
- Signed multiplication/addition overflow on nonterminal difference-based scheduling paths, and signed index-increment overflow.
- Validity and meaning of negative counts or indices other than −1.

Terminal scheduling’s subtraction, multiplication, and addition are **not** included in the signed-overflow uncertainty: they use unsigned 32-bit arithmetic. Its preceding target-position-to-signed assignment remains unresolved for out-of-range values.

F-308975d8cf2d is observed with receiver-only and receiver-plus-index calls. A single normalized signature is not established.

## Evidence

Established static evidence consists of field accesses, operand widths and signedness, branch conditions, direct write order, dependency-call order, and temporary-record adjustments in the supplied function representation.

The terminal scheduling expression combines a signed stored target position with an unsigned transformed position before multiplication. This establishes unsigned arithmetic for that subtraction and its subsequent multiplication and addition. Nonterminal paths instead assign the difference to signed storage before multiplying; their arithmetic contract is distinct.

The initial strictly-earlier target branch has no current-position guard. The invalid-cache continuation has no final direct cache write. Terminal handling explicitly invalidates the cache after any scheduling calls return.

Scheduling and remaining-record terminology express inferred intent only. Prior prose and reviewer feedback are not independent behavioral evidence.
