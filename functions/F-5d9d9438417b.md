# F-5d9d9438417b

## Purpose

F-5d9d9438417b updates fields in a caller-supplied mutable object from an associated record, invokes three dependencies, and conditionally constructs a compact, dot-separated name.

The apparent intent is to expose an eight-byte primary name and a three-byte suffix as a conventional display name. That interpretation is inferred from field widths, space handling, and separator insertion. The record format and the meanings of the other fields are not established.

The return value has two materially different forms:

- If the object byte at offset `0x0D` is nonzero after the dependency calls, the function returns that byte’s unsigned numeric value, from 1 through 255, represented as a pointer.
- Otherwise, it constructs a terminated name beginning at object offset `0x0D` and returns the address of that field.

The first form is not a return of the existing name’s address. Consumers must not assume every nonzero result is a dereferenceable string pointer.

### 5. Invoke associated-record processing

The dependency’s return value is not used. Its changes to object storage, descriptor storage, record storage, or global state cannot be ruled out.

### 6. Inspect the branch-controlling byte

Only after all preceding operations does the function read object offset `0x0D`.

If that byte is nonzero, it is interpreted as an unsigned eight-bit quantity. The function immediately returns its numeric value converted to a pointer representation. It performs no direct name-construction writes on this branch.

This is not an entry-time cache check: all preceding dependency calls and field transfers have already occurred. The byte inspected may have been modified by a dependency.

### 7. Construct the name when the byte is zero

When object offset `0x0D` is zero, construction begins at that same offset.

The primary component is read from the object base. It contributes at most eight bytes. Reading stops at the first zero byte or ASCII space byte, `0x20`. The stopping byte is not copied.

Every other byte is copied without case conversion, character classification, or encoding validation. A dot inside the primary component is ordinary data during this copy.

A separator dot is appended only if at least one primary byte was copied.

Only in that case is the suffix examined. The suffix begins at object offset `0x009` and contributes at most three bytes. Its copying likewise stops before the first zero byte or ASCII space.

After component processing, the function checks the last emitted byte, if any. If it is a dot, the output position moves back by exactly one byte. A zero terminator is written at the resulting position.

Consequences include:

- An empty primary component suppresses the suffix entirely.
- An empty suffix causes the inserted separator to be removed.
- Space ends a component; subsequent non-space bytes in that component are ignored.
- Trailing-dot removal is a single-byte operation, not repeated trimming.
- A dot copied as suffix data can be the byte removed.
- Maximum construction writes occupy 13 bytes: eight primary bytes, one separator, three suffix bytes, and one terminator, spanning offsets `0x0D` through `0x19`.

The function then returns the address of object offset `0x0D`.

## Acceptance examples

These examples are conditional static expectations, not runtime observations. Name-construction examples assume execution reaches the construction phase with the stated bytes and with object offset `0x0D` equal to zero.

1. **Full-width components.**  
   Primary bytes `ABCDEFGH` and suffix bytes `XYZ` produce `ABCDEFGH.XYZ`, followed by a zero terminator. The returned address is object offset `0x0D`.

2. **Space-padded components.**  
   Primary bytes beginning `REPORT` followed by a space, and suffix bytes `TXT`, produce `REPORT.TXT`. Bytes after the first primary space are irrelevant to construction.

3. **Empty suffix.**  
   Primary bytes beginning `REPORT` followed by a stopping byte, and a suffix beginning with zero or space, produce `REPORT`. The inserted separator is removed.

4. **Empty primary with nonempty suffix.**  
   A primary field beginning with zero or space produces an empty string even if the suffix is `TXT`. The suffix is not copied.

5. **Embedded space, not general trimming.**  
   A primary field beginning `AB CD` produces primary text `AB`. It does not produce `ABCD` or preserve the internal space.

6. **Only one final dot removed.**  
   Primary text `A` and suffix bytes consisting of three dots produce `A...`: construction first emits four dots after `A`, then removes the final one.

7. **Primary trailing dot retained when suffix is empty.**  
   Primary text `A.` with an empty suffix produces `A.`. The extra separator is the one removed; the primary’s dot remains.

8. **Nonzero byte bypasses construction.**  
   If the byte read at offset `0x0D` after F-575c870e8340 returns is `0x41`, the result is the pointer representation of unsigned numeric value 65. It is not the address of the name field. Earlier calls and field transfers still occur.

9. **Unsigned interpretation.**  
   If that byte is `0xFF`, the returned numeric pointer value is 255, not a sign-extended negative value.

10. **Dependency changes affect later observations.**  
    If an earlier dependency changes the descriptor’s first word, F-575c870e8340 receives the changed word, provided the retained descriptor address remains valid. Changing only the descriptor’s second word does not replace the record-address value already captured at entry.
