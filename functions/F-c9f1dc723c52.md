# F-c9f1dc723c52

## Purpose

F-c9f1dc723c52 obtains a 32-bit value through one of three paths selected by a 16-bit field in a caller-supplied object:

- Selector 3 uses one or two dependency calls and assembles a 12-bit result.
- Selector 8 delegates result production to a separate dependency.
- Every other selector uses a retrieval dependency followed by a conversion dependency.

The function returns a 64-bit quantity containing a success indicator in its low 32 bits and a separate working value in its high 32 bits. On success, it also writes the result through the caller’s output pointer. On dependency-reported failure, it skips that final output write.

The high half of the return is not necessarily the original input index. In two selector-3 cases, a dependency receives writable access to the working value used for that high half.

The selector-3 path is consistent with extraction of packed 12-bit values. That interpretation is inferred intent; the established contract is the arithmetic and call behavior below.

## Interface

### Inputs

The interface has three arguments:

1. **Object address.** A 32-bit address representation identifying an object whose selector is read at byte offset `0x6c`.
2. **Index.** An unsigned 32-bit integer. The full unsigned range is accepted by the visible arithmetic; no explicit range validation occurs.
3. **Output address.** A pointer to storage for a 32-bit unsigned result.

The visible representation uses 32-bit integer words and 32-bit pointer-valued storage. The object’s full layout, valid index range, alignment requirements, and dependency-specific preconditions are not supplied.

### Relevant object layout

| Offset | Width | Use |
|---|---:|---|
| `0x6c` | 16 bits | Selector compared with 3 and, if necessary, 8 |

No other object field is directly accessed by this function. Dependencies receive the object address and may access additional state.

### Output write

When execution reaches the success exit, the function performs one direct 32-bit write through the output address.

- Selector 3 produces a value between 0 and 4095 inclusive.
- Selector 8 writes whatever 32-bit result remains in its result slot after its dependency returns successfully.
- Other selectors write the 32-bit return value of the conversion dependency.

The output address must be valid and writable whenever that final store is reached. A path that returns early does not directly dereference it. Dependencies may nevertheless impose additional requirements, particularly because its address representation initializes a working slot on the general and selector-3 paths.

### Return value

Treat the return as a 64-bit bit pattern:

- Low 32 bits: zero for a dependency-reported failure, one for success.
- High 32 bits: the current contents of a 32-bit working slot.

That working slot initially contains the input index. Only the selector-3 cases with index remainder 1 or 2 explicitly pass its address to a dependency.

Although the supplied interface labels the return as a signed 64-bit quantity, status is encoded in the low word rather than by the sign of the whole return. A high word with its top bit set makes the signed interpretation negative even on success.

## Behavior

### Initialization and dispatch

Before dispatch, the function establishes:

- A 32-bit result slot initialized to zero.
- A 32-bit return-high slot initialized to the index.
- A pointer-sized working slot initialized to the output address representation.

It reads the 16-bit selector at object offset `0x6c`.

- If the selector is 3, it takes the packed-value path.
- Otherwise, it reads the selector again and compares it with 8.
- A second-read value of 8 selects the dedicated path.
- Any other second-read value selects the general path.

The source therefore expresses one selector read for the selector-3 path and two for the other dispatch paths. It does not explicitly cache a single selector value. This distinction can matter if the field can change asynchronously or has special read semantics; neither such use nor its validity is established.

### Selector 8: dedicated result dependency

The function calls F-9a0e9b802ac6 with:

1. The object address.
2. The original index.
3. The address of the zero-initialized 32-bit result slot.

If the dependency returns zero, the function returns failure without its final output store.

If the dependency returns nonzero, the function writes the result slot to the output address and returns success.

There is no additional validation of the result. In particular, a nonzero dependency return without a write to the result slot leads to an output of zero, provided no other action has changed that slot.

The return-high slot is not explicitly supplied to this dependency. Its intended direct dataflow therefore remains the original index. This is not a general guarantee about arbitrary dependency side effects or invalid memory accesses.

### Other selectors: retrieval followed by conversion

The function calls F-6801f4e9392e with:

1. The object address.
2. The original index.
3. The address of the working slot initially containing the output address.
4. A zero-valued fourth argument.

A zero return causes immediate failure. The conversion dependency is not called, and the final output store is skipped.

A nonzero return causes a call to F-d3e7acd8693d with the address of that same working slot. Its 32-bit return value becomes the result.

The function then stores that result through the output address and returns success. It does not interpret any particular conversion result as an error. A conversion result of zero is therefore compatible with a successful overall return.

The working slot is supplied by address, not by passing its contents as a direct data pointer argument. The dependencies’ interpretation of that slot is not established here.

### Selector 3: address calculation

Let the index be the unsigned 32-bit input.

The function determines:

- A remainder equal to the index’s low two bits, yielding exactly 0, 1, 2, or 3.
- A first retrieval position equal to the low 16 bits of three times the index, shifted right by two bits.

The multiplication is unsigned 32-bit arithmetic. Masking to 16 bits occurs before the right shift. This is not equivalent in general to dividing the unrestricted product by four.

The first retrieval position is in the inclusive range 0 through 16383.

The function calls F-6801f4e9392e with:

1. The object address.
2. The first retrieval position.
3. The address of the working slot initially containing the output address.
4. Zero.

A zero return produces immediate failure.

A nonzero return leads to one of four extraction cases. The retrieval dependency’s writes determine the working word subsequently examined. The function does not require, check, or establish that a successful dependency actually replaced the entire word.

### Byte terminology

The extraction cases distinguish two operations:

- **Numeric low byte:** the low eight bits of a 32-bit word.
- **Storage byte one:** the byte at offset one in that word’s storage representation.

These are not interchangeable descriptions of endianness. On a little-endian representation, storage byte one is numeric bits 8 through 15. The supplied material does not independently establish the target’s endianness.

The formulas below preserve that distinction.

### Remainder 0

No second retrieval occurs.

The result consists of:

- The numeric low byte of the first working word in result bits 0 through 7.
- The low nibble of that word’s storage byte one in result bits 8 through 11.

The other result bits are zero.

The return-high slot remains initialized to the index through the visible direct operations.

### Remainder 1

The function makes a second call to F-6801f4e9392e at the first retrieval position plus one.

For this second call, the writable destination is the return-high slot, not the first working word. That slot still contains the original index when supplied to the dependency.

A zero return causes failure, using the current contents of that slot as the return’s high word. Any write the dependency made before returning zero can therefore affect the failure return.

On a nonzero return, the result is:

- The high nibble of the first working word’s storage byte one in result bits 0 through 3.
- The numeric low byte of the second retrieval’s destination word in result bits 4 through 11.

The current second-retrieval destination word also becomes the high half of the successful return.

### Remainder 2

The second retrieval has the same position and destination-slot arrangement as remainder 1. A zero return has the same early-failure behavior.

On success, the first working word is shifted right logically by eight bits. The result is then assembled from:

- Original numeric bits 8 through 15 of the first working word in result bits 0 through 7.
- The low nibble of the second retrieval’s destination word in result bits 8 through 11.

The second retrieval’s destination word supplies the high half of the return.

The second retrieval position cannot overflow its visible arithmetic: adding one to a first position in 0 through 16383 yields 1 through 16384.

### Remainder 3

No second retrieval occurs.

The function retains the first working word’s storage byte one and replaces that storage byte with the word’s numeric low byte. The modification affects only the function’s local working storage.

The resulting output is equivalent to:

- The high nibble of the original numeric low byte in result bits 0 through 3.
- The original storage byte one in result bits 4 through 11.

The return-high slot remains initialized to the index through the visible direct operations.

### Common success and failure exits

All successful paths converge on a direct 32-bit output store, followed by construction of the 64-bit return with low word one.

Dependency-reported failure paths omit that store and return with low word zero.

The function does not roll back dependency effects. “No final output store” does not guarantee that the output location or any other memory remained unchanged: a dependency may have independent access to it.

## Side effects

Established direct effects are limited to:

- Reading the object’s selector field.
- Initializing and modifying local working storage.
- Calling the selected dependencies in the stated order.
- Writing one 32-bit result through the output address on success.

No direct allocation, deallocation, persistent object-field update, or global write is visible.

This does not establish purity of the overall operation. The dependencies may mutate the object, globals, indirect memory, or resources. Their implementations are unavailable here.

The local working slots are passed by address for use during dependency calls. Whether a dependency retains those addresses is unknown. No safe post-return use of those local addresses is established.

There is no visible ownership transfer, release operation, or cleanup protocol. In particular, the pointer-like initial contents of the working slot do not establish that either retrieval or conversion owns or frees the referenced memory.

## Acceptance examples

These examples are conditional specifications derived from the supplied static evidence, not executed tests. They assume valid memory, normal dependency returns, and no unspecified interference.

1. **Dedicated-path success.** If selector 8 is observed on the second selector read, the index is 10, and F-9a0e9b802ac6 writes 42 and returns nonzero, the output becomes 42. The return has high word 10 and low word 1.

2. **Dedicated-path failure.** Under the same dispatch, if that dependency returns zero, the function performs no final output store. The return has high word 10 and low word 0, assuming the dependency does not otherwise affect the return-high storage.

3. **General-path zero result.** If neither selected comparison matches and retrieval succeeds, a conversion return of zero produces an output of zero and a successful low return word of 1.

4. **First retrieval failure.** On selector 3, if the first retrieval returns zero, there is no second retrieval and no conversion call. The function performs no final output store.

5. **Remainder 0 extraction.** Assuming little-endian working-word storage, index 0 selects retrieval position 0. If retrieval supplies `0x00000ABC`, the output is `0xABC`; the return has high word 0 and low word 1.

6. **Remainder 1 extraction.** Under the same byte-order assumption, index 1 selects positions 0 and 1. If the first word is `0x0000D000` and the second word is `0x123456AB`, both retrievals succeeding, the output is `0xABD`. The return high word is `0x123456AB`, not 1.

7. **Remainder 2 extraction.** Index 2 selects positions 1 and 2. If the first word is `0x0000AB00` and the second word is `0x0000000C`, the output is `0xCAB`. The return high word is `0x0000000C`.

8. **Remainder 3 extraction.** Assuming little-endian storage, index 3 selects only position 2. A first word of `0x0000ABCD` yields output `0xABC` and return high word 3.

9. **Failure after a second-slot write.** For remainder 1 or 2, if the second retrieval writes `0x87654321` to its destination and then returns zero, the low return word is zero and the high word is `0x87654321`. The function still omits its final output store.

10. **Masked position arithmetic.** Index 65536 produces first retrieval position 0, not 49152. Its low two bits are zero, so only one retrieval occurs on selector 3.
