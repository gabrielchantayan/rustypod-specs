### Outputs and completion

No return value is declared. Observable outputs consist of dependency invocations, memory accesses, and the final indirect transfer.

2. A word read late in execution from a loaded base plus 0x64.

A return is represented after the transfer. Whether the target returns normally, does not return, or uses a different effective calling convention is **documented_only**.

### Widths and arithmetic

The visible memory operations use 8-bit bytes, 16-bit halfwords, and 32-bit words. Address-like values and most arithmetic intermediates are represented as 32-bit quantities. Some dependency results are represented as 64-bit aggregates.

For an aggregate, the low component is bits 0–31 and the high component is bits 32–63. Logical aggregate shifts by 34, 36, and 44 positions select the high component shifted right by two, four, and twelve positions respectively. These are not oversized shifts of a 32-bit operand.

Masks select low fields of widths including 24, 22, 21, 20, 19, 18, 17, 16, 15, 14, 13, 12, and 11 bits. Mask placement matters: selecting bits before a shift is not generally equivalent to selecting bits afterward.

Under a 32-bit bit-vector interpretation, left shifts discard high bits. Successive left shifts by 28 positions therefore leave zero, and selecting the low sixteen bits immediately after a sixteen-position left shift also yields zero. Such information loss does not justify deleting surrounding dependency calls.

Signed-looking shifts and multiplications may exceed signed 32-bit ranges. Their exact executable overflow behavior is **documented_only**; type annotations alone do not establish it. Numerical examples below state when they assume 32-bit bit-vector arithmetic.

One late right shift operates on a signed-looking loaded word and uses the low eight bits of a computed base as its count. The count can exceed 31. Both oversized-count behavior and the executable interpretation of the signed-looking operation remain **documented_only**.

## Acceptance examples

These are conditional criteria, not executed tests.

- **Input forwarding:** With valid entry state and an observable first target, its first two represented arguments equal the supplied 32-bit inputs in order.

- **Unsigned byte contribution:** If an unsigned byte read yields 0xff, its word-valued contribution is 255, not −1. Adding 0x74 therefore uses 255 as the byte contribution.

- **Width preservation:** The three 0x3a publications retain their byte, halfword, and word widths. Three byte writes are not equivalent.

- **Ordered overwrites:** An access observer at the adjusted offset-0x20 location sees word values 0x20, 0x2f, the freshly read zero-extended byte, and 0x20, in that order.

- **Early fixed ordering:** The fixed-address-5 read precedes the fixed-address-1 write. The fixed-address-0x54 word write and fixed-address-0x15 byte write occur later among the linked updates, not before that read.

- **Publication-base capture:** If the fixed-address-0x60 store affects the global base-word location through the environment’s memory semantics, the publication region still uses the value captured before that store; no reload is represented.

- **Final aliasing:** If the fixed-address-0x3a write overlaps either later capture, that capture observes memory after the byte write. A pre-write snapshot is not equivalent.

- **Fresh 0x67 observations:** If the three post-write reads of fixed address 0x67 return 0x11, 0x22, and 0x33, their respective destinations receive those bytes. Substituting the initially written byte for all three fails this criterion.

- **Truncation:** Under 32-bit bit-vector arithmetic, shifting 0x01000001 left by eight yields 0x00000100. A byte publication from 0x12345678 writes only 0x78.

- **Partial failure:** A fault after completed stores does not require rollback or a structured return value.

- **Final transfer:** On reaching the final target, its arguments use their designated captures. Later contents at the original addresses are not substituted by additional reads.
