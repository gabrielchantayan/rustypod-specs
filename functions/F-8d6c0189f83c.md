## Behavior

Every operation described here is ordered as it appears in the supplied representation. Dependency calls between stores must not be omitted or treated as harmless: they may modify memory, alter external state, or fail to return.

For readability, a “four-call group” means four successive indirect calls with no explicit arguments shown, retaining the ordinary return value of the fourth where stated. It does not mean the calls have no implicit inputs or side effects, or that they invoke the same target.

Names introduced below identify values in this contract, not source identifiers or memory fields.

### Byte-store destination selection

Several subsequent stores use a two-stage access:

1. Read one unsigned byte at address \(B+1\).
2. Zero-extend that byte.
3. Add 17 to obtain the destination address.
4. Write one byte there.

Each occurrence performs a fresh selector read. The destination therefore lies between addresses 17 and 272 inclusive, but it need not remain the same across occurrences.

The selector is not a word-sized pointer load. No intervening dependency may be assumed to preserve the selector byte.

### Unconditional loop

The loop executes at least once if reached. Each iteration has this order:

1. Invoke a dependency with \(L\) and \(Q \mathbin{\gg} 8\).
2. Execute a four-call group, retaining its final result.
3. Read the selector byte at \(S\) and write zero to the selector value plus 17.
4. Invoke the next dependency with four times the retained result, reduced to 32 bits.
5. Execute another four-call group, retaining its final result as \(V\).
6. Set the next loop-carried values to \(\operatorname{word}(4V)\) and \(\operatorname{word}(V \times 2^{26})\).

No condition tests memory, a return code, or a counter to exit this loop.

Initially, \(Q\) is between 0 and 31, so the first loop call’s second explicit argument is zero. On later iterations, that argument is drawn from the high-shifted loop result and can be nonzero.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **First-store ordering.** If entry is valid, the word store of \(A\) at \(4A+20\) occurs before the first indirect call. A model that postpones it until after that call does not match the represented order.

2. **Unsigned third-input shift.** If \(C=\text{0x80000000}\), its explicitly forwarded shifted value is \(\text{0x01000000}\), not a sign-extended negative quantity.

3. **Byte truncation.** If \(X=\text{0x12345678}\), the first selected byte store writes \(\text{0xe0}\). The later selected store derived from the same \(X\) writes \(\text{0x23}\).

4. **Selector mutation.** If successive reads at \(B+1\) yield 3 and 200, their destination addresses are 20 and 217. Reusing the first selector value would not match the represented accesses.

5. **Low-word arithmetic.** If \(E=\text{0x100}\), both shifted products in step 9 reduce to zero under the stated low-word model, giving a zero word store at address 20. This is conditional on that arithmetic model and a valid access.

6. **Initial loop argument.** For any 32-bit \(W\), the initial \(Q\) is at most 31. Therefore the first loop call receives zero as its second explicit argument.

7. **Later loop argument.** If an iteration’s final result is 1, the next iteration uses \(L=4\) and \(Q=\text{0x04000000}\); its second explicit argument is \(\text{0x00040000}\).

8. **No normal completion.** If every dependency returns and every memory access succeeds indefinitely, the represented routine continues looping rather than returning a success indication.
