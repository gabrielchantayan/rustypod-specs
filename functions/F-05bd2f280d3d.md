# F-05bd2f280d3d

## Purpose

F-05bd2f280d3d processes a mutable descriptor according to an unsigned selector. Selectors 0–4 update selector-specific object storage through dependencies and invoke object callbacks. Selector 5 conditionally updates object and shared state, then performs a finalization sequence.

“Descriptor,” “control region,” “update region,” “snapshot destination,” and “commit region” identify observable roles, not established domain meanings. The evidence does not identify these regions as ordinary memory, device registers, or another interface.

On normal completion, the function returns the 32-bit value `0x00000000` for selectors 0–5 and `0xffffffff` for every other selector. Descriptor normalization and an initial dependency call occur even for unsupported selectors.

## Interface

### Arguments and result

The represented interface has four arguments:

| Argument | Representation and role |
|---|---|
| Object reference | Address of writable object-associated storage. The first 32-bit word supplies a dispatch-table address. |
| Selector | Unsigned 32-bit value. Only 0–5 have supported paths. |
| Descriptor reference | Address of a mutable structure with the fields below. |
| Auxiliary value | Opaque 32-bit value, retained for an additional selector-5 callback argument unless replaced on the nonpositive-extent branch. |

The result is a 32-bit bit pattern, not an established dependency-success report. Dependency and callback results are generally ignored, except for the two arithmetic-helper results used on one selector-5 path.

There is no visible validation of references, storage extents, alignment, dispatch entries, or dependency results. There is no visible fault recovery.

### Shared references and validity

Four shared references participate:

- **Control region:** byte accesses at `0`, `1`, `2`, and `8`; word accesses at `0x10`, `0x14`, and `0x30`.
- **Update region:** word accesses at offsets specified below.
- **Snapshot destination:** passed to F-2686267b3746; a subsequently obtained destination receives a byte clear at offset `5`.
- **Commit region:** accessed through two separate reads of its shared reference during finalization.

The control-region base is captured before normalization. The update-region base is captured after the initial dependency returns. Subsequent accesses through these captured bases do not re-read their shared references.

No non-aliasing relationship among the descriptor, object, or shared regions is established. An earlier write can therefore affect a later read if their storage overlaps. References must remain valid throughout their actual use; ownership and retention by dependencies are unknown.

## Behavior

### Common entry sequence

The function first captures the control-region base. It then performs four conditional descriptor normalizations in order:

1. Read word `0x08`; if it equals `0xffffffff`, read word `0x10` and write that value to `0x08`.
2. Read word `0x0c`; if it equals `0xffffffff`, read word `0x14` and write that value to `0x0c`.
3. Read word `0x28`; if it equals `0xffffffff`, read word `0x10` and write that value to `0x28`.
4. Read word `0x2c`; if it equals `0xffffffff`, read word `0x14` and write that value to `0x2c`.

Each replacement source is read when needed, rather than captured collectively at entry. Normalization is not repeated after dependencies run.

Next, the function reads the word at control offset `0x30` and supplies it to F-570d5ddce076. Its result is unused. After that call returns, the function captures the update-region base and dispatches on the selector.

For selectors 0–3, operations occur in this order:

2. Call F-019e779587ab with the object and descriptor byte `0x3c`.
3. Invoke dispatch offset `0x30` with the object, selector, and descriptor words `0x18`, `0x1c`, `0x10`, and `0x14`, in that argument order.
4. Invoke dispatch offset `0x24` with the object, selector, and address of descriptor offset `0x40`.

Later calls obtain their descriptor arguments after earlier calls return. Earlier values are not guaranteed to remain unchanged.

### Selector 5: change detection

Read control byte `8` through the captured control base.

If it is nonzero, take the update path without performing the comparison chain or directly replacing that byte with `1`.

If it is zero, compare the following pairs in order. Continue only while comparisons match:

| Object offset | Descriptor offset | Comparison |
|---:|---:|---|
| `0x1bc` | `0x28` | Word equality |
| `0x1c0` | `0x2c` | Word equality |
| `0x1a4` | `0x10` | Word equality |
| `0x1a8` | `0x14` | Word equality |
| `0x1b4` | `0x20` | Word equality |
| `0x1b8` | `0x24` | Word equality |
| `0x1ac` | `0x18` | Word equality |
| `0x1b0` | `0x1c` | Word equality |
| `0x19c` | `0x08` | Word equality |
| `0x1a0` | `0x0c` | Word equality |
| `0x1d0` | `0x3c` | Low byte of an object word versus descriptor byte |

The last comparison reads an object word but compares only its low eight bits. It does not require full-word equality.

If every comparison matches, skip the update path and proceed to finalization. Otherwise, write byte value `1` to control offset `8`, then take the update path.

Changes outside this comparison set do not independently cause an update. Finalization still runs when all comparisons match.

### Selector 5: update prefix

Perform these operations in order:

1. Call F-2686267b3746 with object offset `0x194` and the descriptor.
2. Read descriptor `0x28` and write it to update offset `0x4c`.
3. Read descriptor `0x2c` and write it to update offset `0x50`.
4. Read descriptor `0x28` again and write it to control offset `0x10`.
5. Read descriptor `0x2c` again and write it to control offset `0x14`.
6. Read object byte `0x1e5`. If nonzero, write zero to descriptor words `0x10`, `0x14`, `0x18`, and `0x1c`, in that order.
7. Read descriptor `0x20`, shift it left four bits, and write the word result to update offset `0x44`.
8. Read descriptor `0x18` and write it to update offset `0x54`.
9. Read descriptor `0x1c` and write it to update offset `0x58`.
10. Read descriptor `0x24` and write it to update offset `0x48`.

These are separate reads and writes. In particular, the target-like fields written to control storage are read again rather than reused from the preceding update-region writes.

### Selector 5: extent decision and arithmetic

After the update prefix, read descriptor word `0x10` once and retain that 32-bit value.

- If its signed 32-bit interpretation is nonpositive, select the nonpositive branch without reading descriptor `0x14` for this decision.
- If its signed interpretation is positive, read descriptor word `0x14` for the decision. Select the positive branch only if that second value is also signed-positive.

Thus, “both extents positive” describes the values sampled for this decision, not a continuing invariant over descriptor storage.

**Nonpositive branch**

Read and retain the following trailing values: control byte `2`, zero-extended; descriptor byte `0x30`, zero-extended; descriptor word `0x34`; and descriptor word `0x38`.

Call F-007ca869e9c9 with arguments in this order:

1. Descriptor word `0x28`.
2. Descriptor word `0x2c`.
3. Control byte `1`.
4. Control byte `0`.
5. The retained, zero-extended control byte `2`.
6. The retained, zero-extended descriptor byte `0x30`.
7. The retained descriptor word `0x34`.
8. The retained descriptor word `0x38`.

The representation establishes byte-valued inputs for control offsets `1` and `0`; it does not independently establish their external ABI extension rules.

This branch makes no direct writes to update offsets `0x5c`, `0x60`, `0x64`, or `0x68`. Dependencies and aliasing may still affect those locations.

**Positive branch**

Perform the following sequence:

1. Write the **retained first extent value** to update offset `0x5c`. Do not re-read descriptor `0x10` for this write.
2. Read descriptor word `0x14` again and write that newly read value to update offset `0x60`. Do not reuse its decision-time value.
3. Call F-870c4fcf7295 with descriptor `0x28` shifted left twelve bits and a fresh read of descriptor `0x10`.
4. Treat the returned value as signed 32-bit, shift it right three bits, and write the word result to update offset `0x64`.
5. Call F-870c4fcf7295 with descriptor `0x2c` shifted left twelve bits and a fresh read of descriptor `0x14`.
6. Treat that returned value as signed 32-bit, shift it right four bits, and write the word result to update offset `0x68`.

The write to `0x5c` can affect the subsequent descriptor `0x14` read if storage aliases. Likewise, helper inputs need not equal decision-time extents. The first helper and the intervening result write may affect inputs to the second helper.

The helper’s operation is unknown; its use does not establish division. Shifts are 32-bit operations, not unbounded multiplication or mathematical division. Overflow and negative-shift semantics remain qualified under Uncertainties.

After either branch, invoke dispatch offset `0x58` with the object, descriptor words `0x08` and `0x0c`, and descriptor byte `0x3c`.

### Selector 5: finalization

Finalization runs whether or not the update path ran:

1. Invoke dispatch offset `0x24`.
2. Read the shared snapshot-destination reference and call F-2686267b3746 with that destination and the descriptor.
3. Read control byte `8` through the captured control base.
4. If nonzero, perform the conditional commit sequence below.
5. Read the shared snapshot-destination reference again and clear byte `5` at that destination.
6. Return zero.

For selector 5, dispatch offset `0x24` visibly receives eight arguments: the object, selector, descriptor-tail address `0x40`, a callback-address value obtained from dispatch offset `0x24`, and four retained values.

Ordinarily, the final four values are the original object reference, selector, descriptor reference, and auxiliary argument. On the nonpositive branch, they instead contain the retained control byte `2`, descriptor byte `0x30`, descriptor word `0x34`, and descriptor word `0x38`. The actual callback ABI and significance of these extra arguments remain documented_only.

**Conditional commit sequence**

When the final control-byte read is nonzero:

1. Clear control byte `8`.
2. Read-modify-write update word `0`, setting bit 0.
3. Read the shared commit-region reference and retain that base for the later three read-modify-writes.
4. Separately read the shared commit-region reference again; write word value `7` at offset zero of this second destination.
5. Using the base retained in step 3, perform three separate read-modify-writes at byte offset `0x10003c`: set bit 0, then bit 1, then bit 2.

The two commit-reference reads are distinct and ordered. Their resulting addresses are neither required to differ nor guaranteed to remain equal. The destination of the write of `7` is not substituted for the retained base used by the three later accesses.

Each read-modify-write reads the word anew and sets its specified bit. These operations are not a single combined write.

## Acceptance examples

These are conditional static scenarios, not executed tests. They assume valid storage and returning dependencies. Preservation and aliasing conditions are explicit.

1. **Unsupported selector still normalizes.** With selector 6, descriptor `0x08` and `0x28` initially all-one bits, and `0x10` remaining 20 during normalization, both sentinel fields become 20. F-570d5ddce076 runs before the return of `0xffffffff`.

2. **Selector-specific order.** Selector 2 supplies object offset `0xa4` to F-2686267b3746, then invokes F-019e779587ab, dispatch `0x30`, and dispatch `0x24`. Selector 4 uses object offset `0x144` and omits F-019e779587ab.

3. **Unchanged selector 5.** If control byte `8` is zero and all comparisons match, the update path and dispatch `0x58` are skipped. Dispatch `0x24`, the snapshot call, and the final snapshot-byte clear still occur. No commit occurs if the final control-byte read remains zero.

4. **Short-circuited extent decision.** If the first extent read yields `0xffffffff`, its signed value is −1. The nonpositive branch is selected without reading descriptor `0x14` for that decision.

5. **Aliasing changes the second write.** Suppose decision-time extents are 3 and 7, and update offset `0x5c` aliases descriptor `0x14`. The positive branch writes retained value 3 to `0x5c`, thereby changing descriptor `0x14` to 3. The following fresh read writes 3, not the decision-time 7, to update offset `0x60`.

6. **Object flag clears extents.** If object byte `0x1e5` is nonzero after the object-state call, the four specified descriptor words are cleared in order. If intervening writes do not change those extents through aliasing, the later decision takes the nonpositive branch.

7. **Positive arithmetic results.** If the positive branch runs and the helper returns 64 and then 128, update offsets `0x64` and `0x68` receive 8 and 8, respectively. This does not prescribe the helper’s calculation.

8. **Separate commit destinations.** If the first commit-reference read yields address A and the second yields address B, the write of `7` targets B, while all three bit-setting operations target A plus `0x10003c`. This remains the rule when A and B are equal.
