# F-811a25bdbe21

## Purpose

F-811a25bdbe21 examines a word-addressed structure for a nonzero unsigned 32-bit query and returns a 32-bit Boolean result.

Three representations are selected by structure contents:

- A compact representation tests a query-selected bitmap bit.
- A table representation probes words until it observes either zero or the query.
- A hierarchical representation selects another structure and transforms the query before repeating the examination.

“Membership,” “table,” and “hierarchical” describe inferred intent. The established contract is the observable selection, arithmetic, reads, dependency calls, and return behavior below. The supplied evidence does not establish a complete storage format, valid dependency-result ranges, or termination for arbitrary inputs.

**Structure pointer.** The first input identifies storage accessed as unsigned 32-bit words, with byte reads on the compact path. A null pointer is accepted and returns 0. Every non-null structure reached must provide readable storage for the accesses actually selected.

Stored child addresses occupy one 32-bit word. The compact address expression also uses a 32-bit integer representation of the structure address. These operations support a target-specific 32-bit address interpretation, not a portable wider-address-space interface. **Query.** The second input is an unsigned 32-bit value. Zero is rejected, but a non-null structure’s first word is read and compared before that rejection.

Traversal replaces both inputs internally: a selected stored address becomes the current structure pointer, and a dependency-derived value becomes the current query.

## Behavior

### Ordered entry checks

Each examination, including one reached through hierarchy traversal, begins with these source-level observations:

1. A null current pointer returns 0 without a structure read.
2. The first 32-bit word is read and compared unsigned with the current query. A smaller word returns 0.
3. A zero current query returns 0.
4. The first word is read again for comparison with 4001.

A first word below 4001 selects the compact path. A value of 4001 or greater selects a noncompact path, which reads the word at offset 8:

- Zero selects table probing.
- Nonzero selects hierarchical traversal.

The compact path does not consult offset 8.

The two first-word expressions are distinct in the supplied body. No consistent snapshot or synchronization is established. This description records source-level access order; it does not establish volatile semantics, compiler-level load counts, or a supported concurrent-mutation interface.

### Compact representation

After the guards accept a nonzero query, the compact path selects a bit using one-based query numbering:

- The byte displacement is the unsigned query minus 1, divided by 8 with the fractional part discarded.
- The bit position is the query minus 1, modulo 8.
- One byte is read at the structure address plus 12 plus that displacement.
- A set selected bit returns 1; a clear selected bit returns 0.

Bit numbering within each byte proceeds from least significant to most significant. Query 1 selects bit 0 at offset 12; query 8 selects bit 7 at offset 12; query 9 selects bit 0 at offset 13.

The subtraction cannot underflow because zero has already been rejected. The bit position is between 0 and 7.

With stable header contents, the guards constrain a compact-path query to 1–4000. The largest selected displacement is then 499, and the largest selected byte offset is 511. That bound is conditional on the two first-word observations agreeing.

The function returns immediately after the bit test. This path makes no dependency call.

### Table representation

The table path calls **F-d7be9cfb4000** with two explicitly visible values:

- The current query multiplied by 37, reduced modulo \(2^{32}\).
- 125.

A secondary 32-bit result channel supplies the initial probe index. The evidence does not establish that this is a remainder or that its value lies in 0–124.

#### Address formation

For every table read, **3 is added to the current index using unsigned 32-bit arithmetic before word addressing**. Thus the selected word number is:

\[
(\text{index}+3)\bmod 2^{32}.
\]

For indices 0–124, this selects words 3–127, corresponding to byte offsets 12–508. Describing all accesses merely as entries beginning at offset 12 would omit the index-addition wraparound.

In particular:

| Initial index | Selected word number | Selected byte offset |
|---|---:|---:|
| 0xFFFFFFFD | 0 | 0 |
| 0xFFFFFFFE | 1 | 4 |
| 0xFFFFFFFF | 2 | 8 |

An out-of-range initial index may therefore select header storage, not merely storage beyond the apparent table. Other large word numbers may require invalid or unprovided storage. The unsigned index addition is established; it does not make the subsequent pointer calculation or memory access valid.

The initial index is not normalized before its first use.

#### Probe observations and advancement

At each selected word, the function first reads and compares the value with zero. Zero returns 0 immediately.

If that test does not return, the selected word is read again and compared with the current query. Equality returns 1. The two comparisons are separate source-level reads, not an established snapshot.

After a nonzero, nonmatching observation, the index is incremented modulo \(2^{32}\). If the incremented unsigned value exceeds 124, it is replaced with zero. Probing then continues.

For an initial index in 0–124, this advances sequentially and wraps from 124 to zero. There is no probe counter or full-table exhaustion check. Stable nonzero entries, none equal to the query, cause indefinite probing.

The post-probe increment and range check do not protect the initial access. The addition of 3 used for addressing and the addition of 1 used for advancement are distinct unsigned operations.

### Hierarchical representation

This path calls **F-d7be9cfb4000** with the current query minus 1 as the single explicitly visible argument. The subtraction is unsigned 32-bit arithmetic and cannot underflow because the query is nonzero.

The consumed result has 64 bits, divided into low and high 32-bit portions.

**Child selection.** The low portion is converted to signed 32-bit integer form and has 3 added before it is used as a word index. The selected word’s 32-bit contents become the next structure pointer.

This is not the unsigned table-index calculation. Under the intended signed interpretation, a low portion representing −3 selects word 0, −2 selects word 1, and −1 selects word 2. More negative values can address before the structure base.

The signed addition can overflow for positive converted values greater than 2147483644. The supplied evidence does not establish a portable result at that boundary. Out-of-range unsigned-to-signed conversion also requires a target interpretation; the examples above are conditional on the intended two’s-complement interpretation.

**Query transformation.** The high portion is likewise converted to signed 32-bit integer form. The expression adds 1 in signed arithmetic and then assigns the result to the unsigned 32-bit query.

For a representable signed addition, assignment converts the signed result to unsigned modulo \(2^{32}\). This is **not an unconditional unsigned increment**:

- High portion 0 produces next query 1.
- Under the intended two’s-complement interpretation, 0xFFFFFFFF becomes −1; adding 1 gives 0, so the next query is 0.
- Under that interpretation, 0x80000000 becomes −2147483648; adding 1 and converting to unsigned gives 0x80000001.
- High portion 0x7FFFFFFF becomes the largest signed 32-bit integer. Adding 1 exceeds the signed range. The supplied evidence does not establish whether the execution model wraps, rejects, or otherwise handles this case. Its transformed query remains documented_only.

The selected child-address word is read before the next query assignment. The function then repeats the entry checks using the new pointer and query.

A null child is rejected without dereferencing it. A non-null child paired with a transformed query of zero still has its first word read before zero-query rejection. Invalid non-null addresses are not validated. There is no depth limit, cycle detection, or established progress invariant.

## Acceptance examples

These are static, conditional consequences, not executed tests. Unless stated otherwise, selected storage is readable and stable, dependency execution does not invalidate it, and address calculations are supported by the target.

1. **Null structure.** Any query returns 0 without a structure read or dependency call.

2. **Bound rejection.** A first observed word of 20 with query 21 returns 0 before representation selection.

3. **Zero query.** A non-null readable structure with query 0 has its first word read for the bound comparison, then returns 0 without a dependency call.

4. **Compact bit selection.** With first word 100 and query 1, byte value 1 at offset 12 yields 1; byte value 2 yields 0. Query 8 instead selects bit 7 there, and query 9 selects bit 0 at offset 13.

5. **Representation threshold.** For an accepted nonzero query, stable first word 4000 selects the bitmap without reading offset 8. Stable first word 4001 selects a noncompact path and reads offset 8.

7. **Table probe wrap.** Initial index 124 selects word 127. After a nonzero mismatch, the next index is zero, selecting word 3.

8. **Wrapped table address reaches the bound word.** Let the first word and query both be 5000, offset 8 be zero, and the dependency supply 0xFFFFFFFD. Adding 3 wraps to word index 0. The stable first word matches the query, so the result is 1.

9. **Other wrapped header reads.** Initial index 0xFFFFFFFE selects the word at offset 4; zero there returns 0. Initial index 0xFFFFFFFF selects offset 8; if that selector remains zero after the dependency call, the first probe returns 0.

10. **No full-table rejection.** With an initial index in 0–124 and all 125 apparent entries permanently nonzero and unequal to the query, probing continues indefinitely.

12. **All-ones high portion.** Under the intended signed interpretation, high portion 0xFFFFFFFF converts to −1, and signed addition produces zero. A selected non-null readable child has its first word read before return 0. This zero is not produced by unsigned addition wraparound.
