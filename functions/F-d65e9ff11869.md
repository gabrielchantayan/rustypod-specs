# F-d65e9ff11869

## Purpose

Exactly one represented path returns normally: it returns the fifth explicit argument unchanged. Other paths reach undecodable boundaries or continue through traversal without a demonstrated normal exit. An undecodable boundary is a limit of the supplied representation, not evidence of an intentional trap or a particular runtime failure.

This contract describes established operations and their ordering. It does not guarantee that the recovered control flow faithfully represents an executable.

## Behavior

### Entry selection

If the first argument is nonzero, the routine reads a halfword at entry-address offset 12, retains its low byte, and zero-extends that byte to replace the fourth argument. This is a 16-bit read followed by truncation, not a demonstrated byte read.

The routine adds the third address value and effective fourth value. It retains the wrapped sum and separately determines unsigned carry and signed overflow.

The first region is selected when unsigned carry is absent **or** the wrapped sum is zero. The second region requires carry and a nonzero wrapped sum.

### No-carry-or-zero region

The decisions occur in this order:

1. A signed-nonnegative sum reaches an undecodable boundary.
2. Otherwise, signed addition overflow causes a normal return of the fifth argument.
3. Otherwise, execution continues.

Thus, continuation establishes a negative sum and no signed addition overflow.

The routine reads a word at effective-fourth offset 12, then a word at offset 8. It doubles the latter modulo \(2^{32}\). Call this doubled value the current **arithmetic state**.

#### Nonnegative arithmetic state

2. Store its low halfword at arithmetic-state address plus 44.
3. Call F-48831087d0ac with the arithmetic state shifted right arithmetically by 15.
4. Store its represented 16-bit result at third-address offset 16.
5. Read G0 and capture that value for a later destination-word store.
6. Read G0 again, independently, and use this second value as the base of a byte read at offset 3.
7. Write five consecutive words to the stack-supplied destination:

The “halfword-address value” is a 32-bit address-like state value, not a claim that its contents have already been read.

2. Stores the low byte of the global-derived state at the current halfword-address value.
3. Reaches an undecodable boundary.

No nonzero check protects the second store.

Otherwise, the iteration:

2. Sets the arithmetic state to the current traversal address shifted right arithmetically by 15.
3. Sets the update’s address operand to current traversal address minus 100.
4. Records signed overflow from that subtraction.
5. Reaches an undecodable boundary if the global-derived state is zero.

- Set the current halfword-address value to the bitwise OR of the dependency result’s low word and the working third address.

## Acceptance examples

These are conditional static consequences, not executed tests. Memory examples require valid accesses and returning dependencies.

1. **Immediate boundary:** First argument zero, third value 1, and fourth value 1 produce sum 2 without carry. The first undecodable boundary is reached without dereferencing those two addresses.

2. **Normal return:** First argument zero, third value `0x70000000`, and fourth value `0x10000000` produce `0x80000000`, no unsigned carry, and signed overflow. The result is exactly the fifth argument.

3. **Zero sum:** Third value `0xffffffff` plus fourth value 1 wraps to zero with carry. The first region is selected, but its nonnegative-sum condition reaches a boundary rather than returning.

4. **Replacement width:** With first argument nonzero and entry-offset-12 halfword `0xab34`, the effective fourth value is `0x34`. The access remains a halfword read.

5. **Independent G0 reads:** On the nonnegative-arithmetic path, if the first G0 read yields address A and the second yields address B, the fourth destination word receives A, while the byte comes from B plus 3. No equality requirement may be imposed.

6. **Negative-path update:** If the entry address is `0x2000` and the offset-26 halfword is 3, the shared update writes word value 24 using the intervening call’s secondary register as its offset. Its call-argument-state read occurs at `0x2000`, not at `0x1f9c`.

7. **Mutable traversal argument:** If an update’s address operand is A and the word read at A is B, the next F-indirect-07 call, if reached before another replacement, receives B as its second argument. Reads at A plus 8, 12, 16, and 20 occur after that assignment.

8. **Tail shift distinction:** For arithmetic state `0x80000000`, the first tail-read address is `0xfffff044`, while the later unsigned-shift negation is `0xfffff000`. The byte at working-third offset 24 comes from the current paired value, not from the arithmetic state.
