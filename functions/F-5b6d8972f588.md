## Acceptance examples

These are conditional review criteria, not executed tests.

1. **Initial saved argument.** If the scaled-argument call occurs before any update to its saved second argument, that argument is zero.

2. **Conditional first-scalar provenance.** If argument installation computes the accumulator, the saving operation follows without an intervening accumulator replacement, and the saved argument is not subsequently replaced, the scaled call uses **B** times that first-scalar-derived accumulator. Removing those path conditions invalidates the provenance claim.

3. **Scalar-derived unit-call argument.** If the scalar-derived operation completes and the unit-argument call follows without replacement of the shared third-argument value, that call receives the operation’s first product. This requires defined arithmetic; the second product uses separate global reads.

4. **Cleared saved value propagation.** If scalar-derived clearing is the latest saved-working-value update when the scaled-argument call completes its state updates, the accumulator and carried value both become zero.

5. **Mutable scalar propagation.** If F-4c6691984003 changes the referenced second scalar, a later scalar-derived operation uses its then-current local value, subject to any intervening mutations.

6. **Defined scaled publication.** If **B** is two, **A** is three, and the published local is seven, the scaled output store writes 42. This example assumes those values at the relevant points and no interfering effects. If a signed intermediate overflows, no low-32-bit acceptance result is established.

7. **No direct publication.** If execution returns without reaching an output-store site, this procedure performs no direct output write. Dependency-induced writes remain a separate possibility.

8. **Fresh record load.** If a dependency changes the +0 record word and execution later reaches another call site, that site uses its own record load, not an established entry snapshot.

9. **Null and repeated-store boundaries.** A null output is not established as safe merely because a presence flag exists. If several valid output stores execute, all occur; the last determines the final value only absent subsequent aliasing or external effects.
