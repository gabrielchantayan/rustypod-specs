# F-966d28012ce4

## Purpose

The supplied static representation describes a procedure that interleaves indirect dependency calls with byte-sized and 32-bit memory writes. Dependency results are repeatedly scaled into addresses, stored as values, or used to select byte locations through another byte read.

A higher-level purpose—such as object construction, serialization, allocation, or device control—is not established. The apparent record offsets do not establish a valid data structure.

**Evidence limitation:** the representation explicitly reports invalid instruction data and truncated control flow. This contract therefore distinguishes the represented execution prefix from a verified executable implementation. It does not establish that the entire prefix is reachable, that the recovered call signatures are correct, or that execution returns normally.

### 2. Initial byte and scaled-word writes

2. Store W(4R) as a word at S + 52.

## Side effects

### Memory

The represented prefix contains:

- 32-bit stores at computed addresses with offsets 20, 36, and 52.
- Byte stores at computed addresses with offsets 1, 7, and 13.
- Byte-selector-directed stores into addresses 17 through 272.
- Direct byte stores to absolute addresses 13 and 17.
- Explicit byte reads used to select destinations.
- Explicit word reads used as subsequent bases or arguments.

These address patterns do not establish record types, bounds, pointer validity, or disjoint storage. Stores can overlap one another or memory later read. In particular, absolute addresses 13 and 17 can overlap computed destinations.

A word written earlier must not be assumed to survive a dependency call. Likewise, a repeated selector read must not be replaced with a cached value.

## Acceptance examples

These are conditional trace criteria, not results of executed tests.

### Full-width and byte-width input use

If C is 0x123456AB and the relevant stores are reached, its byte stores contribute 0xAB, while the word store at P + 20 contributes all 32 bits, 0x123456AB. A contract that describes all uses as byte-only is insufficient.

### Early overwrite ordering

If R is 5, the first word written at S + 52 is 20. If high(T) is 0x11223344, that location is subsequently written with 0x11223344.

Acceptance requires two ordered writes with the intervening dependency calls, not merely the final value.

### Logical shift before byte truncation

If A is 0xFFFFFFFF, A logically shifted right by two is 0x3FFFFFFF. The stage-5 byte contribution is 0xFE under the stated 32-bit interpretation.

This does not establish that the destination E + 7 is valid.

### Fresh selector reads

If Q + 1 contains 2 during stage 5, the associated destination is address 19. If dependencies change Q + 1 to 9 before stage 6, stage 6 clears address 26 and retains D = 9.

A cached selector that instead clears address 19 would violate the represented ordering.

### Captured selector versus later memory changes

Once stage 6 captures D = 9, stage 7 uses M = 18 even if later dependencies change Q + 1. The later byte destination M + 13 is therefore 31.

This differs from operations that explicitly reread a selector.

### Repeated final clears

If the first final selector read yields 4 and the second yields 7, the two zero writes target addresses 21 and 24. They must not be merged into a single clear.

### Failure before completion

If F-0806 does not return, the later explicit word store at B2 + 36 is not required to occur. No rollback of already completed writes is established.
