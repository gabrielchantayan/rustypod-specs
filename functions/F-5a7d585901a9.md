# F-5a7d585901a9

## Purpose

F-5a7d585901a9 constructs a temporary four-word state from data located 16 bytes beyond its input address, computes a displacement through opaque dependencies, updates the selected state, and returns the first 32-bit word of a final dependency-produced result.

The observed arithmetic uses a 12-byte unit for position calculations and a 4-byte unit for advancing through a table of addresses.

**Inferred intent:** the state resembles a segmented iterator, and the operation resembles moving back by one 12-byte element, possibly crossing a segment boundary. This interpretation is not an established contract: the arithmetic dependencies and state-construction dependency have no supplied implementations.

The established contract is therefore the sequence of calls, state accesses, arithmetic, and result extraction described below—not an unconditional promise to decrement an iterator.

The initial source address is formed by adding 16 bytes to that value. The function does not directly inspect any other portion of the input object. The amount of storage read at that address is determined by F-3430dd28b407 and is unknown.

The displayed interface represents the input as a signed 32-bit integer. Its use as an address does not establish portability to a wider address space.

This word is obtained from the first word of a final 16-byte local result area after calling F-3430dd28b407 with that area as its destination. It is not the return value of that dependency call.

## Behavior

### 1. Construct the working descriptor

The function first calls F-3430dd28b407 with:

- the first 16-byte staging area as destination; and
- the address obtained by adding 16 to the input as source.

That call’s return value is ignored.

It then calls F-3430dd28b407 again with:

- the second 16-byte staging area as destination; and
- the first staging area as source.

The second call’s return value is retained as the descriptor address.

These are separate, ordered calls. The second call uses the first staging area itself, regardless of the address returned by the first call.

Nothing in the supplied evidence establishes that either call is a plain copy, that exactly 16 bytes are read or written, or that either call preserves unrelated state.

### 2. Obtain an adjusted displacement

The function reads the descriptor words at offsets 0 and 4 and forms their difference.

It calls F-870c4fcf7295 with:

- that difference as the first argument; and
- the value 12 as the second argument.

The returned 32-bit value is treated as a signed value and decreased by one. The resulting value is the **adjusted displacement** used in the remaining calculations.

The two descriptor reads precede this call. Their relative evaluation order is not established.

The evidence does not establish that F-870c4fcf7295 performs division. Any interpretation of the adjusted displacement as an element index depends on that dependency’s actual behavior.

### 3. Derive a signed table displacement

The function branches on whether the adjusted displacement is negative.

#### Nonnegative adjusted displacement

The function:

1. calls F-478e80b97aec once;
2. calls F-d7be9cfb4000 with the adjusted displacement as its first argument and that dependency result as its second argument; and
3. uses the latter call’s signed 32-bit result as the **table displacement**.

#### Negative adjusted displacement

The function:

1. calls F-478e80b97aec once and retains its 32-bit result for the second argument of F-d7be9cfb4000;
2. calls F-478e80b97aec a second time;
3. subtracts the adjusted displacement and then one from the second result;
4. calls F-d7be9cfb4000 with that computed quantity as its first argument and the **first** F-478e80b97aec result as its second argument; and
5. negates the signed result to obtain the table displacement.

The two calls to F-478e80b97aec must not be treated as interchangeable or consolidated. Their results may differ, and either call may have observable effects.

There is no evidence that F-d7be9cfb4000 performs division, floor division, or remainder computation. The explicit negation in the negative branch does not prove that the resulting table displacement is negative.

### 4. Select an in-segment or table-crossing update

The next branch tests whether the table displacement is exactly zero.

#### Zero table displacement

The function reads the descriptor word at offset 0 and subtracts 12 to form the new current-position value.

It performs no direct writes to descriptor offsets 4, 8, or 12 on this branch.

The current-position read occurs **after** all calls used to derive the table displacement. If those calls modified the descriptor through aliases or other accessible state, this read observes the resulting value rather than the value used in the earlier difference.

#### Nonzero table displacement

The function performs these actions in order:

1. Reads the descriptor word at offset 12.
2. Advances that address by four times the signed table displacement.
3. Writes the advanced address back to descriptor offset 12.
4. Reads one 32-bit word from the advanced address.
5. Writes that word to descriptor offset 4.
6. Calls F-478e80b97aec.
7. Reads descriptor offset 4, adds 12 times the latest dependency result, and writes the result to descriptor offset 8.
8. Calls F-478e80b97aec again.
9. Reads descriptor offset 4 and computes the new current-position value as the base plus 12 times the difference between:
   - the adjusted displacement; and
   - the table displacement multiplied by this second dependency result.

The write to offset 12 occurs before the selected table-entry read. Consequently, an invalid table address is not detected before that descriptor update.

The two F-478e80b97aec calls in this branch are distinct. The first contributes to the offset-8 value; the second contributes to the final current-position calculation. Their results need not match each other or any earlier result.

The reads of offset 4 in steps 7 and 9 occur after the corresponding dependency calls. The function does not preserve the originally selected base value across those calls.

### 5. Commit and extract the result

After either update branch, the function writes the newly computed current-position value to descriptor offset 0.

It then calls F-3430dd28b407 with:

- the final 16-byte result area as destination; and
- the descriptor address as source.

The call’s return value is ignored.

The function returns the first 32-bit word of the final result area. There is no explicit cleanup of the staging areas, descriptor, selected table storage, or returned value.

## Acceptance examples

These are conditional acceptance cases derived from the supplied static evidence. They are not runtime test results. Each numerical case assumes valid storage, representable arithmetic, and no dependency side effects except those explicitly stated.

### Zero table displacement

Suppose F-870c4fcf7295 returns 6, producing an adjusted displacement of 5. Suppose F-d7be9cfb4000 then returns zero, and descriptor offset 0 contains 120 when the zero branch reads it.

### Positive table displacement

Suppose:

- the adjusted displacement is 7;
- the table displacement is 1;
- descriptor offset 12 contains address 2000;
- the 32-bit word at address 2004 is 1000; and
- the two subsequent F-478e80b97aec calls each return 4.

The function must write:

1. 2004 to descriptor offset 12;
2. 1000 to offset 4;
3. 1048 to offset 8; and
4. 1036 to offset 0.

### Distinct results in the negative branch

Suppose the adjusted displacement is −1. If the first two F-478e80b97aec calls return 4 and 6 respectively, F-d7be9cfb4000 must receive first argument 6 and second argument 4.

If that call returns 1, the table displacement must be −1. Substituting the first dependency result for the second would violate the observed behavior.

### Different results during a crossing

Suppose the adjusted displacement is 7, the table displacement is 1, and the selected base is 1000. If the two subsequent F-478e80b97aec results are 4 and 5, respectively:

- offset 8 must receive 1048;
- offset 0 must receive 1024.

The function must not reuse the first result in the second calculation.

### Mutation between descriptor reads

Suppose table displacement is zero and a dependency changes descriptor offset 0 from 120 to 240 before the zero branch reads it.

The new current-position value must be 228, not 108. The earlier read used to form the initial difference does not freeze this field.

Likewise, on a crossing branch, a dependency-induced change to offset 4 must be reflected in the base read immediately after that call.

### Adjusted-displacement boundary

If F-870c4fcf7295 returns 1, the adjusted displacement is zero and the nonnegative branch applies.

If it returns 0, the adjusted displacement is −1 and the negative branch applies. That branch requires two initial F-478e80b97aec calls, even if the eventual table displacement is zero.
