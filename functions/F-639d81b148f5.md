# F-639d81b148f5

## Purpose

F-639d81b148f5 performs a short, state-dependent sequence of dependency calls against an address-bearing input. It reads a one-byte field to decide whether to obtain a secondary address and inspect a two-byte entry field. A nonzero entry field causes one additional dependency call whose return value is ignored.

On every normally completing path, the function returns the 32-bit value zero.

The established behavior is the call sequence, address relationships, conditional reads, and constant return value. The meanings of the object, its fields, and the dependency operations are not established. In particular, the paired calls on the same interior address are not sufficient evidence that the function acquires and releases a lock or manages ownership.

## Interface

### Inputs

The function accepts two values represented as 32-bit integers in the supplied source representation:

- **Object address:** Used as an address base for two dependency arguments and one direct byte read. Denote this value by **B**.
- **Entry selector:** Used to calculate the location of a two-byte field relative to an address returned by a dependency. Denote this value by **I**.

Although the first input has an integer representation, its observable use is address-like. No object type, allocation size, alignment guarantee, or ownership transfer is established.

The selector is represented as a signed integer. There is no explicit check for a negative value, no comparison against an entry count, and no range validation.

### Output

The normal return value is a 32-bit zero. The return value does not distinguish:

## Behavior

### Initial call and flag observation

The function forms the interior address B + 116 and passes it to F-4a19e3742733.

Only after that call returns does the function read the byte at B + 100. Consequently, the branch depends on the byte’s value after F-4a19e3742733 has executed, not necessarily on its value at function entry.

The function compares this byte with zero:

- A zero byte selects the entry-inspection path.
- Any nonzero byte selects the shorter path.

Whether the byte is interpreted as signed or unsigned does not affect this zero comparison.

The function then calls F-fd58bea73663 with the same interior address used for the initial call. This call occurs on both flag outcomes. The flag has already been read and the branch selected before this call occurs.

There is no visible second flag read. If F-fd58bea73663 changes the flag, that change does not revise the branch already selected.

### Nonzero-flag path

If the observed flag is nonzero:

1. F-fd58bea73663 is called with B + 116.
2. No call to F-702f08e79f1a is made.
3. No selector-derived two-byte field is read.
4. The function returns zero.

On this path, the selector does not participate in any visible address calculation or memory access.

### Zero-flag path

If the observed flag is zero, the function calls F-fd58bea73663 with B + 116 before obtaining or inspecting the entry address.

It then calls F-702f08e79f1a with B + 44. The returned 32-bit value is used as an address base, R.

The function reads a two-byte quantity at R + 12 × I + 26 and compares it with zero.

- If the quantity is zero, there is no further visible dependency call.
- If the quantity is nonzero, F-702f08e79f1a is called again with B + 44.

The second call is a distinct invocation. Its return value is discarded. The function does not compare the two returns, repeat the field read, or use the second return as an address.

The function then returns zero.

### Required sequencing

The visible sequence is significant:

1. F-4a19e3742733 receives B + 116.
2. The flag at B + 100 is read.
3. F-fd58bea73663 receives B + 116.
4. Only on the zero-flag path, F-702f08e79f1a receives B + 44.
5. A two-byte field derived from that call’s return and the selector is read.
6. Only when that field is nonzero, F-702f08e79f1a receives B + 44 again.
7. The function returns zero.

Moving the flag read before the first call, moving the entry read before F-fd58bea73663, or eliminating the optional second invocation would not preserve the established behavior when dependencies have side effects.
