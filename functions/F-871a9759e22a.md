# F-871a9759e22a

## Purpose

F-871a9759e22a performs a position-addressed read through either a memory-backed path or a callback-backed path. It rejects a starting offset that is at or beyond the stream’s declared size. For an accepted starting offset, it obtains a transfer count, records the starting offset plus that count as the stream’s current position, and reports whether the count is smaller than the requested count.

The established behavior is count-based, not transactional:

- An invalid starting offset produces status **85**.
- A completed read path reporting fewer bytes than requested also produces status **85**.
- A completed read path reporting at least the requested count produces status **0**.
- A short read still updates the current-position field.
- A callback result greater than the requested count is accepted rather than rejected or clamped.

The apparent intent is a stream read operation with an exact-count success criterion. The embedded implementation establishes the control flow and arithmetic, but it does not establish the behavior of the external transfer helper, callback implementations, or diagnostic dependency.

## Interface

### Arguments

The function takes four arguments:

| Argument | Representation | Meaning |
|---|---|---|
| Stream reference | Pointer to a record containing 32-bit fields | Supplies declared size, backing address or callback, and writable position state |
| Starting offset | Unsigned 32-bit value | Absolute position from which the operation is requested |
| Destination | 32-bit argument value | Forwarded unchanged to the selected transfer mechanism; apparently a destination address |
| Requested count | Unsigned 32-bit value | Number of bytes requested |

The function returns a 32-bit status value. Its explicit return values are **0** and **85**, with **85** also expressible as **0x55**. It does not return the transferred count directly.

No argument validation establishes that the stream reference, destination, backing address, or callback target is usable.

### Stream record layout

The following byte offsets are relevant under the supplied 32-bit field model:

| Byte offset | Width | Established use |
|---|---:|---|
| 0 | 32 bits | Backing-address value used on the memory-backed path |
| 4 | 32 bits | Declared size, interpreted as unsigned for the initial bounds comparison |
| 8 | 32 bits | Current-position field written after a transfer mechanism returns |
| 20 | 32 bits | Callback target; zero selects the memory-backed path |

This is a partial layout, not a complete record definition. The meanings of fields at other offsets are unknown. The wrapper does not explicitly access the intervening fields, but dependencies may do so.

The current-position field is not read to choose the starting position. The supplied starting offset controls the operation independently of the previous position.

### Preconditions

For a defined, normally returning execution:

- The stream reference must permit the field accesses reached on the selected path.
- An accepted read path must eventually permit a 32-bit write at byte offset 8.
- A nonzero callback target must be callable under the expected argument and return-value convention.
- The external transfer mechanism must accept the arguments supplied to it.
- Dependencies reached during the operation must return normally for the wrapper’s later effects and status return to occur.

These are operational requirements, not checks implemented by this function. In particular, the wrapper does not check destination capacity, backing-storage capacity, pointer validity, callback validity, or ownership.

## Behavior

### 1. Starting-offset validation

The function first reads the declared-size field and interprets it as an unsigned 32-bit value. It compares that size with the unsigned starting offset.

If the starting offset is **greater than or equal to** the declared size:

1. It invokes F-4457a9a44a68 with an invalid-start diagnostic selector and the starting offset.
2. If that dependency returns normally, the function returns status **85**.

This branch does not explicitly inspect the callback field, invoke a transfer mechanism, or write the current-position field.

The validation is independent of the requested count. Consequently:

- A zero-byte request at exactly the declared end is rejected.
- A zero-byte request beyond the declared end is rejected.
- A declared size of zero rejects every possible starting offset, including zero.
- The diagnostic dependency may itself have effects; absence of an explicit position write does not establish that the record remains unchanged.

If the starting offset is strictly smaller than the declared size, execution proceeds to transfer-path selection.

### 2. Transfer-path selection

The function examines the callback field at byte offset 20.

- A zero callback value selects the memory-backed path.
- A nonzero callback value selects the callback-backed path.

There is no fallback from one path to the other after the selected dependency returns. In particular, a callback reporting a short count does not trigger a memory-backed retry.

### 3. Memory-backed path

The memory-backed path obtains a remaining-length value by subtracting the starting offset from the declared-size field. The size field is read again for this computation; the wrapper does not explicitly preserve the size value used by the initial validation.

The transfer count is the smaller of:

- The requested count.
- The remaining-length value.

The subtraction and count comparison use unsigned 32-bit arithmetic. With stable record contents, the earlier validation ensures that this remaining length is positive. If the size field changes between its reads, that reasoning need not hold; the wrapper performs no further bounds validation.

The function then invokes F-UNRESOLVED-01 with three arguments, in this order:

1. The destination argument.
2. The backing-address value plus the starting offset.
3. The selected transfer count.

The address calculation is a byte-valued address addition, not multiplication of the starting offset by the record-field width. Within the supplied 32-bit model, its result is represented at 32-bit width; no overflow check is present.

The return value of F-UNRESOLVED-01 is ignored. The selected transfer count remains the count used for the later position update and status decision.

The call shape suggests a byte-copy operation. However, the supplied material does not establish that dependency’s identity, exact copying semantics, overlap rules, fault behavior, or ownership effects. Therefore, an unconditional guarantee that destination bytes were copied successfully would exceed the available evidence.

A selected transfer count of zero does not bypass the helper call.

### 4. Callback-backed path

The function invokes the callback designated by the stream record with four arguments, in this order:

1. The stream reference.
2. The starting offset.
3. The destination argument.
4. The requested count.

The requested count is passed unchanged. It is not reduced to the declared bytes remaining after the starting offset.

The callback’s return value is used as an unsigned 32-bit transfer count. The wrapper does not:

- Clamp it to the requested count.
- Clamp it to the remaining declared size.
- Treat any particular bit pattern as a separate callback error code.
- Verify that it corresponds to bytes actually placed in the destination.

The callback-field test and callback invocation are separate field uses in the supplied expression structure. No atomicity, locking, or concurrent-modification guarantee is established.

The callback receives the stream reference and may modify the record. If it returns normally, the wrapper subsequently writes its own computed current position. Thus, any position value written by the callback is overwritten by that explicit wrapper write, assuming the record remains writable and valid.

### 5. Position update

After either transfer mechanism returns normally, the function writes the following value to the current-position field:

**starting offset + transfer count, reduced to 32 bits**

There is no overflow check, saturation, or clamp to the declared size.

This write occurs before the short-read comparison and before any short-read diagnostics. It occurs for:

- Full-count results.
- Short-count results.
- Zero-count results.
- Callback results greater than the requested count.
- Results whose addition to the starting offset wraps around.

The count used here is the selected bounded count on the memory-backed path, or the callback’s returned count on the callback-backed path.

### 6. Completion status and diagnostics

After updating the current position, the function compares the unsigned transfer count with the requested count.

If the transfer count is smaller:

1. It invokes F-4457a9a44a68 with a read-failure context diagnostic.
2. It invokes F-4457a9a44a68 again with a short-read diagnostic selector, followed by the requested count and the obtained count.
3. If both calls return normally, it returns status **85**.

Otherwise it returns status **0**, without these short-read diagnostic calls.

This is a strict less-than test. Equality succeeds, and an excessive callback count also succeeds.

The position update precedes both short-read diagnostics. A diagnostic dependency can therefore observe that write if it accesses the same record through some available reference. Its own behavior is unknown and may change the state again.

## Side effects

### Explicit wrapper effects

The explicit effects are:

- Reads of the relevant stream fields.
- One invocation of the selected transfer mechanism for an accepted starting offset.
- One 32-bit position write after that invocation returns.
- One diagnostic invocation on the invalid-start branch.
- Two diagnostic invocations, in order, after a short transfer.

No explicit allocation, release, retry, rollback, or restoration appears in the wrapper.

### Indirect effects and ownership

The absence of explicit allocation or release does not establish that dependencies allocate nothing or release nothing. Their global-state, I/O, synchronization, and ownership behavior is unknown.

The function establishes no ownership transfer for the stream, destination, or backing storage. It also establishes no preservation guarantee for these objects across dependency calls.

Destination aliasing is not checked. If the destination overlaps the stream record, backing storage, or another dependency-visible object, the transfer mechanism’s effects may influence subsequent execution. The wrapper’s own position write still occurs at its designated point if execution reaches it with a valid writable record.

### Failure and partial completion

Status **85** does not imply absence of effects:

- An invalid-start diagnostic may have side effects.
- A short transfer may already have modified the destination.
- A short transfer has already caused the wrapper’s position write before diagnostics begin.

No recovery path is shown for a dependency that faults, fails to return, or transfers control elsewhere. The stated return statuses apply only when execution reaches the explicit return.

## Acceptance examples

These are conditional consequences of the static behavior, not executed tests. Each assumes usable storage and normally returning dependencies unless stated otherwise.

### Invalid starting offset

With declared size **64**, starting offset **64**, and requested count **0**:

- The function invokes the invalid-start diagnostic.
- It does not explicitly select or invoke a transfer mechanism.
- It does not explicitly write the position field.
- It returns **85** if the diagnostic returns.

The same result applies to any larger unsigned starting offset.

### Memory-backed full request

With stable declared size **100**, starting offset **20**, requested count **30**, and a zero callback field:

- The helper receives a count of **30** and a source address equal to backing address plus **20**.
- After the helper returns, the position field is written as **50**.
- No short-read diagnostics occur.
- The function returns **0**.

Actual destination contents depend on F-UNRESOLVED-01.

### Memory-backed request crossing the declared end

With stable declared size **100**, starting offset **90**, requested count **20**, and a zero callback field:

- The helper receives a count of **10**.
- The position field is written as **100**.
- The two short-read diagnostics occur in their stated order, with requested count **20** and obtained count **10** supplied to the second.
- The function returns **85**.

The wrapper does not perform a second transfer for the missing ten bytes.

### Valid zero-byte request

With stable declared size **100**, starting offset **25**, and requested count **0**:

- The selected transfer mechanism is still invoked.
- On the memory-backed path, the helper receives count **0**.
- If the resulting count is zero, the position becomes **25** and status is **0**.

A callback is not required by this wrapper to return zero merely because zero was requested.

### Callback short count

With declared size **100**, starting offset **20**, requested count **10**, and callback result **4**:

- The callback receives the original requested count **10**.
- The wrapper writes position **24**.
- It invokes both short-read diagnostics.
- It returns **85**.

Any callback-written position is superseded by the wrapper’s write if execution reaches that point normally.

### Callback excessive count

With declared size **100**, starting offset **90**, requested count **20**, and callback result **30**:

- The initial starting-offset check passes.
- The callback receives count **20**, despite only ten declared bytes remaining.
- The wrapper writes position **120**.
- It returns **0**, without short-read diagnostics.

### Position wraparound

With declared size **4,294,967,295**, starting offset **4,294,967,294**, requested count **2**, and callback result **3**:

- The starting offset passes validation.
- The position addition wraps to **1** at 32-bit width.
- The callback count is not smaller than the request.
- The function returns **0**.
