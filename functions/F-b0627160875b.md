# F-b0627160875b

## Purpose

The function also submits a numeric status to F-038b46411c0c after releasing the resources it explicitly acquired. This status is distinct from the return value.

**Established behavior:** the function performs ordered dependency calls, checks handles and object fields, invokes an operation only when eligibility checks pass, and performs path-dependent cleanup.

**Inferred intent:** the initial acquisition and its paired final call resemble entry to and exit from a protected context. The intermediate values resemble parent and child object handles. These descriptions are explanatory labels, not established locking or ownership guarantees.

## Behavior

The function starts with a zero return result and a zero status.

It calls F-91c65c9d4f51 without arguments and interprets the result as a signed integer:

- Zero and positive results both proceed.

### 2. Prepare the lookup inputs

F-658f097ae4e8 receives, in order:

1. The primary 260-byte region.
2. The secondary 256-byte region.
3. The auxiliary 4-byte region.
4. The caller’s opaque input.

Any nonzero result permits the next phase. Negative values are not treated specially.

### 3. Resolve and validate the parent handle

- A zero result selects status **13** and proceeds directly to context cleanup.
- A nonzero result becomes the parent handle.

The function then calls F-e135feff4093 with the parent handle:

- A zero result selects status **13**.
- A nonzero result permits a call to F-3dacd4ff9d73 with the same parent handle.

F-3dacd4ff9d73 must return zero for processing to continue. A nonzero result selects status **13**.

These checks are short-circuited: F-3dacd4ff9d73 is not called when F-e135feff4093 returns zero. If either check rejects the parent, F-f84fe67ebb58 is not called.

Once a nonzero parent handle has been obtained, it is passed to F-66819ba2201a on every established normal path through the remainder of the function.

### 4. Resolve the child handle

After the parent checks pass, F-f84fe67ebb58 receives five arguments:

1. Zero.
2. The parent handle.
3. The secondary region.
4. The auxiliary region.
5. Zero.

A zero result selects status **2**. Only the parent requires object cleanup on this path.

A nonzero result becomes the child handle and is subsequently passed to F-d51dfd79b768.

### 5. Check child eligibility

F-d51dfd79b768 receives the child handle.

A nonzero result selects status **13**, suppresses the field-based checks, and prevents the operation call.

A zero result enables direct reads through the child handle. The accessed layout is:

| Location | Access | Meaning established here |
|---|---|---|
| Child address plus 4 bytes | 32-bit address-bearing value | Address of a subordinate record |
| Subordinate record plus 36 bytes | Signed 32-bit integer | Eligibility threshold field |
| Subordinate record plus 11 bytes | One byte | Eligibility flag field |

The subordinate-record address is read from the child before reading the signed threshold field.

Eligibility then follows these rules:

- If the signed threshold field is **2 or greater**, reject the child with status **13**.
- If the signed threshold field is **less than 2**, inspect the flag byte.
- For that lower range, the child is eligible only if none of the bits selected by hexadecimal mask **0x19** are set.

The selected flag bits are bits 0, 3, and 4. Other bits do not affect this test.

The signed comparison matters: negative threshold values belong to the “less than 2” range. There is no separate lower-bound check.

When the flag byte is needed, the supplied access structure reads the subordinate-record address from the child again before reading the byte. No dependency call occurs between the threshold-field read and the flag read. The function does not explicitly snapshot or validate the subordinate record.

For a threshold value of 2 or greater, the flag byte is not read.

Its return value becomes the function’s eventual return value:

- Zero selects status **28**.
- Any nonzero value leaves status **0**.

There are no retries or additional checks of the operation result.

### 7. Clean up and report

1. F-66819ba2201a with the child handle.
2. F-66819ba2201a with the parent handle.
3. F-591e5dd605b9 with the initial acquisition result.
4. F-038b46411c0c with the selected status.

The returns from these cleanup and reporting calls are ignored. They do not replace the saved operation result.

No exception handling, nonlocal-exit handling, or recovery from an invalid memory access is established.

## Acceptance examples

These examples are conditional predictions from static evidence, not executed tests. Unless stated otherwise, they assume dependencies return normally and all required memory accesses are valid.

1. **Negative acquisition:** If F-91c65c9d4f51 returns −1, the function returns zero immediately. No context-entry, object, cleanup, or status-reporting call follows.

2. **Zero acquisition is accepted:** If acquisition returns zero and preparation then returns zero, the function enters with acquisition value zero, exits with that same value, submits status 2, and returns zero.

3. **First parent check rejects:** Given successful preparation and a nonzero parent, a zero result from F-e135feff4093 suppresses the second parent check and child lookup. The parent is cleaned up before context exit and status 13 submission.

4. **Child lookup fails:** With both parent checks satisfied, a zero child result produces status 2. The parent is cleaned up; no child precheck or operation occurs.

5. **Child precheck rejects:** A nonzero result from F-d51dfd79b768 prevents subordinate-record reads and the operation. Child cleanup precedes parent cleanup, followed by context exit and status 13.

6. **Threshold upper boundary:** With a zero child precheck result and threshold 2, the child is rejected regardless of the flag byte. The flag byte is not read.

7. **Negative threshold:** With threshold −1 and flag byte zero, the child passes the field checks. A negative threshold alone is not grounds for rejection.

8. **Selected flag bit:** With threshold 1 and flag byte 0x08, the child is rejected with status 13. With the same threshold and flag byte 0x02, the field checks pass.

9. **Zero operation result:** For an eligible child, an operation result of zero leads to child cleanup, parent cleanup, context exit, status 28 submission, and a zero return.

10. **Negative nonzero operation result:** For an eligible child, an operation result of −7 leads to the same cleanup order, status 0 submission, and a return of −7.
