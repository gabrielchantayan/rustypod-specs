# F-8440c6b71f4c

## Purpose

F-8440c6b71f4c selects a signed 32-bit value, writes it into a context field, and passes that value through a construction-and-submission sequence.

Inputs between −32767 and +32767, inclusive, are used unchanged. Inputs below or above that interval are replaced by values read from two distinct global locations. These replacements are not necessarily the interval endpoints: their contents are not established by the supplied evidence.

The selected value is written to the context before either downstream construction call. The final submission uses a separate context field, read after those calls.

A plausible intent is to update a setting and notify another component. The setting’s meaning, message format, and recipient’s role are not established.

### 2. Read replacement state and select the value

The lower-replacement global is read after the context dependency returns and before the input-range decision.

Selection follows these rules:

| Input condition | Additional replacement-global read | Selected value |
|---|---|---|
| Input < −32767 | None | Previously read lower replacement |
| −32767 ≤ input ≤ +32767 | Upper replacement is read | Original input |
| Input > +32767 | Upper replacement is read | Upper replacement |

The upper-replacement read therefore occurs for every input that is not below −32767, including inputs that ultimately retain their original value.

This read distinction is part of the visible source-level access order. It does not establish that the globals are volatile, memory-mapped, atomic, or synchronized.

Replacement values are used without further range checks. If either replacement lies outside −32767 through +32767, that out-of-range replacement is still selected.

There is no visible 16-bit conversion, saturation arithmetic, absolute-value operation, or negation. The range boundaries affect selection, not storage width.

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Unless stated otherwise, assume valid context storage, normally returning dependencies, and no dependency mutation of the relevant state.

1. **Lower boundary retained.**  
   With input −32767, the function reads both replacement globals but writes −32767 to context offset +32. The construction call receives a payload address whose first four bytes represent −32767.

2. **Upper boundary retained.**  
   With input +32767, the function reads both replacement globals and writes +32767. The upper replacement does not replace this boundary value.

3. **−32768 uses the lower replacement.**  
   With input −32768 and lower replacement −120, the function writes −120 and supplies that selected value as the four-byte payload. It does not read the upper-replacement global on this path.

4. **Input above the interval uses the upper replacement.**  
   With input +32768 and upper replacement 250, the function writes 250. The lower-replacement global is nevertheless read before the upper replacement.

5. **Replacement is not clamped.**  
   With input below −32767 and lower replacement −90000, the selected value is −90000. No second range check reduces it to −32767.

6. **Late construction-parameter read.**  
   If F-0a77364c41cc changes the construction-parameter global and returns normally, F-afb630a7107c receives the value read after that change.

7. **Late target read.**  
   If the context target initially contains one value and F-afb630a7107c changes it to another, the final dependency receives the later value.

8. **No caller-side rejection of a construction result.**  
   If F-0a77364c41cc returns a zero-valued result normally, this function passes it to F-afb630a7107c without checking it. Whether that argument is valid remains dependency-defined.

9. **Write precedes downstream failure.**  
   If F-0a77364c41cc fails to return after the context write, that write has already occurred. No later submission or rollback is established.
