# F-bfa8d5524d41

## Purpose

F-bfa8d5524d41 conditionally stores a supplied 32-bit value into one of two record fields, sets a flag in the supplied object, invokes a direct dependency, optionally invokes an indirect callback, and finally sets a flag in an object obtained through another indirect call.

The first matching record has priority. Neither a missing match nor a skipped optional callback prevents the later operations on a normal execution path.

This contract describes behavior visible in the supplied static representation. It does not assign domain meanings to the records, flags, callbacks, or returned object. No runtime tests have been performed.

## Interface

### Inputs

The function receives two explicit inputs:

- **Object address:** the base address of a mutable, word-oriented object.
- **Supplied value:** a 32-bit integer whose bit pattern may be written into one selected field of that object.

No explicit length, ownership indicator, error-output address, or allocation context is supplied.

### Output

The function has no explicit return value. Its observable results consist of memory changes and dependency calls.

Normal return is reached only after the final indirect call returns and the subsequent flag update completes. The representation provides no alternate success result or locally generated error result.

### Width and layout model

The supplied representation supports a 32-bit word and address model. Under that model, the following byte offsets are relative to the input object’s base:

| Byte offset | Width or interpretation | Use |
|---|---|---|
| `0x00` | Pointer-sized dispatch-table reference | Resolves the final indirect call |
| `0x34` | Pointer-sized reference stored in a word | Null-tested and used to resolve the optional callback |
| `0x48` | 32-bit flag word | Updated by setting bit `0x20` |
| `0x60` | 32-bit discriminator | First record’s matching condition |
| `0x64` | 32-bit value field | First possible destination for the supplied value |
| `0x78` | 32-bit discriminator | Second record’s matching condition |
| `0x7C` | 32-bit value field | Second possible destination for the supplied value |
| `0x80` | Address within the input object | Passed as the second argument to F-6d16652f2d03 |
| `0xA0` | Word converted to a character-sized value | Controls the optional callback |

These offsets describe accesses, not a complete object definition. In particular, the extent and internal layout of the region beginning at `0x80` are unknown.

The indirect-call layouts are:

- The reference obtained from offset `0x34` points to storage whose first pointer-sized element identifies a dispatch table. A callable entry is obtained at byte offset `0x128` in that table.
- The input object’s first pointer-sized element identifies another dispatch table. A callable entry is obtained at byte offset `0x5C` in that table.
- The final indirect call returns a value used as an address. A 32-bit word at byte offset `0x48` from that address is subsequently updated.

The exact target ABI, byte order, alignment requirements, and character-conversion rules are not independently established. The byte offsets above depend on the evidenced 32-bit word model; they are not a claim of portability to another data model.

### Preconditions

For a normal execution:

- The input object must support every read and write reached on the selected path.
- The selected indirect-call entries must be valid callable targets with compatible calling conventions.
- The final indirect call must return an address supporting a readable and writable 32-bit word at offset `0x48`.
- Dependencies must leave any storage used afterward valid for those subsequent accesses, or replace relevant references with valid ones.

There is no visible null check for the input object, its primary dispatch-table reference, the final callable entry, or the final returned address.

## Behavior

### 1. Select at most one value destination

The first discriminator, at input-object offset `0x60`, is examined first.

Its 32-bit value is compared with `0x80000004` after clearing bit `0x20`. Consequently, precisely these two 32-bit discriminator patterns match:

- `0x80000004`
- `0x80000024`

Other bits remain significant. This is an equality test after masking, not a test merely for the presence of selected bits.

If the first discriminator matches, the supplied value is written to offset `0x64`. The second discriminator is not examined as part of this selection.

Only if the first discriminator does not match is the second discriminator, at offset `0x78`, examined under the same rule. If it matches, the supplied value is written to offset `0x7C`.

If neither discriminator matches, neither destination receives a direct write from this selection step.

The supplied value is copied without visible range checking, normalization, arithmetic, or interpretation. Negative values and values with the high bit set are not treated specially.

“At most one destination” applies to this function’s initial selection step. Dependencies may subsequently modify either destination.

### 2. Set the input object’s flag

After the selection step, the function reads the 32-bit flag word at input-object offset `0x48` and writes it back with bit `0x20` set.

At this immediate write:

- Bit `0x20` becomes one.
- Every other bit retains its value from the flag-word read.
- An already-set bit remains set.

This update occurs whether or not either discriminator matched. It precedes the direct dependency call.

The operation is a read-modify-write, not a visible atomic operation. No synchronization or protection against concurrent modification is established.

### 3. Invoke the direct dependency

The function calls F-6d16652f2d03 with two explicit arguments, in this order:

1. The original input-object address.
2. The address at byte offset `0x80` within that object.

The second argument is an interior address, not the word stored at that location and not a separately constructed copy.

Any return value from this dependency is unused by the visible caller.

No preservation guarantee is available for this dependency. It may alter object fields subsequently read, change other memory or global state, or fail to return. Its name and invocation do not establish ownership or lifetime behavior.

### 4. Conditionally invoke the first indirect dependency

After F-6d16652f2d03 returns, the function tests the reference at input-object offset `0x34`.

- If the reference is null, the optional callback is skipped. The character-sized condition at offset `0xA0` is not evaluated on this path.
- If the reference is nonnull, the word at offset `0xA0` is converted to a character-sized value and compared with zero.
- If that converted value is nonzero, the callback is skipped.
- If that converted value is zero, the callback target is resolved through the reference at offset `0x34`, using its first dispatch-table reference and the entry at table offset `0x128`.

The resulting indirect function, designated **F-indirect-1** in this contract, is invoked with no explicit arguments shown in the supplied representation. Its return value, if any, is unused.

The tested condition is the converted character-sized value, not necessarily the entire 32-bit word. On an ordinary 8-bit, low-order truncation interpretation, a word such as `0x00000100` converts to zero and therefore permits the callback. That interpretation remains conditional on the target’s conversion rules; it is not evidence of a direct one-byte memory load at the lowest address.

The callback decision uses state read after F-6d16652f2d03 returns. It is not based on a snapshot taken before that call.

### 5. Invoke the final indirect dependency

After the optional callback completes or is skipped, the function resolves the entry at byte offset `0x5C` in the input object’s primary dispatch table.

That indirect function, designated **F-indirect-2**, is called with the original input-object address as its one explicit argument.

This resolution occurs after the preceding calls. The contract therefore does not assume the dispatch-table reference or its entries still have their entry-time values.

The return value is used as an address. There is no visible null check, status check, or address adjustment other than the field offset used next.

### 6. Set the returned object’s flag

At byte offset `0x48` from the returned address, the function reads a 32-bit word and writes it back with bit `0x40` set.

At this immediate write:

- Bit `0x40` becomes one.
- Every other bit retains its value from the corresponding read.

The function then returns without an explicit result.

The returned address need not be distinct from the original input object. If it identifies the input object, the two flag updates target the same word at different times. Dependency effects between those writes still matter.

## Side effects

The directly visible writes, in execution order, are:

1. Optionally, one supplied-value write to input-object offset `0x64` or `0x7C`.
2. A flag-word write at input-object offset `0x48`, setting `0x20`.
3. After the dependency calls, a flag-word write at offset `0x48` from the address returned by F-indirect-2, setting `0x40`.

The direct call and indirect calls may have additional effects not specified here.

No direct allocation, deallocation, copying of an entire object, ownership transfer, or resource release is visible. This does not establish that dependencies avoid those actions.

There is no visible rollback. If a dependency fails, does not return, or leaves an invalid reference for a later access, earlier writes are not explicitly undone.

The ordering above describes source-level operations on the normal path. It does not establish atomicity, inter-thread visibility guarantees, volatile-access semantics, or an exact machine-level load count.

## Acceptance examples

These examples are conditional static acceptance criteria, not reported executions. Unless stated otherwise, all required references are valid and dependencies return normally.

### First-record priority

Given:

- First discriminator: `0x80000024`.
- Second discriminator: `0x80000004`.
- Supplied value: `0x12345678`.

The initial selection writes `0x12345678` to offset `0x64`. It does not inspect the second discriminator or write offset `0x7C` during selection. The input flag update and subsequent calls still occur.

### Second-record fallback

Given:

- First discriminator: `0x80000005`.
- Second discriminator: `0x80000004`.

The first comparison fails because bit `0x01` is not ignored. The second comparison succeeds, and the supplied value is written to offset `0x7C`.

### No matching record

Given discriminators `0x00000004` and `0x80000044`, neither matches. No selected-value write occurs. Bit `0x20` is nevertheless set in the input flag word before F-6d16652f2d03 is called.

### Null optional reference

If offset `0x34` contains null when read after F-6d16652f2d03 returns, F-indirect-1 is skipped without evaluating the character-sized condition. F-indirect-2 is still called on the normal path.

### Dependency-controlled callback eligibility

Suppose the optional reference is initially null, but F-6d16652f2d03 installs a valid nonnull reference and leaves the converted condition equal to zero. The callback is eligible to run because the relevant state is read after that dependency returns.

Conversely, an initially nonnull reference does not guarantee invocation if the dependency replaces it with null.

### Final flag preservation

If the flag word read from the returned object is `0x00000081`, the final write produces `0x000000C1`. This example concerns the value at the final read, not the object’s value before earlier dependencies execute.

### Aliased input and returned object

If F-indirect-2 returns the original input-object address, and no dependency changes its flag word, an initial flag value of zero becomes `0x20` before F-6d16652f2d03 and `0x60` at completion.

Without the no-intervening-change condition, `0x60` is not guaranteed.

### Invalid returned address

If F-indirect-2 returns an address that cannot support the final flag access, the representation provides no graceful failure path. An acceptance requirement for a particular error code, exception, or recovery action would be unsupported.
