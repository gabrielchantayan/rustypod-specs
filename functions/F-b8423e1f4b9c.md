## Behavior

### Bound calculation

The wrapper first derives a comparison limit by subtracting one from the initial extent using an unsigned 32-bit expression. For that comparison, subtraction is modulo \(2^{32}\).

It compares this limit with the requested bound using unsigned ordering:

- If the limit is less than or equal to the requested bound, the wrapper selects the initial extent minus one as the forwarded bound.
- Otherwise, it preserves the requested bound.

For an initial extent from 1 through 2,147,483,647, this is equivalent to forwarding the smaller of the requested bound and the initial extent minus one. Equality takes the replacement branch but does not change the numeric bound.

This ordinary positive-extent interpretation must not be generalized to all signed inputs without accounting for their representations:

- With initial extent zero, the comparison limit is 4,294,967,295. The branch is taken only when the requested bound is also 4,294,967,295. In that case, minus one converts to the same unsigned value. Thus the requested bound is effectively unchanged for every requested bound when the initial extent is zero.
- With initial extent minus one, the comparison limit is 4,294,967,294. A requested bound of 4,294,967,295 is reduced to 4,294,967,294; smaller requested bounds remain unchanged.
- With the minimum signed 32-bit initial extent, the unsigned comparison limit is 2,147,483,647. If the replacement branch is taken, the signed-form subtraction shown for the replacement exceeds the signed 32-bit range. The supplied representation does not establish the execution semantics of that overflow case.

The unsigned comparison’s arithmetic is established. A fully defined signed-overflow policy is not.

It then invokes F-4dae6fdf8946 once, passing, in order:

1. The opaque 32-bit value.
2. The destination address.
3. The selected unsigned 32-bit bound.

### Final zero-byte store

The wrapper performs no intervening check that the resulting field value:

- Is no greater than the selected bound.

A negative field value therefore directs the final store before the supplied destination base, subject to address arithmetic and accessibility. A field value equal to the initial extent directs the store at that offset, not at the preceding byte.

The wrapper does not restore the initial extent, clamp the dependency’s result, or use the selected bound as a fallback offset.

If the zero-byte store aliases the field’s own storage, or another permitted mechanism changes that storage between the reads, equality is not guaranteed.

No caller-visible success or failure classification is established for the returned integer. Negative values are not specially recognized as errors.
