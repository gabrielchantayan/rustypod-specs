# F-6df2e5b659f3

## Purpose

F-6df2e5b659f3 processes an indexed record in a mutable expression collection. It computes masks, annotates compact operand metadata, conditionally reverses expression operands, requests insertion of related expressions, and sometimes recursively processes returned indices.

**Established static evidence:** the supplied representation establishes the field accesses, branch conditions, dependency calls, and write ordering described below.

**Inferred intent:** the masks appear to describe dependencies; expression construction appears to support decomposition or normalization. Domain meanings are not established.

**Unknown:** dependency implementations, allocation behavior, ownership, and expression semantics are unavailable. In particular, an insertion request does not establish allocation or a distinct record. A returned index may identify the input record, and a transformed expression may alias its source.

## Interface

The function accepts:

1. An opaque 32-bit context value, forwarded to recursive calls and F-ef01475697c1.
2. A pointer to a mutable collection descriptor.
3. An unsigned 32-bit record index.

There is no explicit return value.

The descriptor fields used are:

| Offset | Width | Observed role |
|---|---:|---|

The owner’s first 32-bit field provides an environment pointer. The environment byte at +30 is an error/stop indicator.

Records have a 40-byte stride:

### Preconditions and arithmetic

Accessed pointers, fields, table entries, and record storage must be valid. No general bounds, capacity, alignment, recursion-depth, or null checks are visible.

Pointers and record-address arithmetic are represented with 32-bit values. Index multiplication and address addition therefore require attention to 32-bit wraparound; no overflow rejection is visible. Parent writes retain only the input index’s low 16 bits. Some compact values and temporary parent indices are interpreted as signed 16-bit values.

The function caches the owner, environment, analysis context, source-expression pointer, and target-record pointer. Dependencies are not assumed to preserve these objects or their backing storage. A **cached target** below means the retained address, not necessarily the record at the descriptor’s latest array base. Refreshes occur only at identified sites.

Otherwise, the function locates the target, captures its expression and analysis context, and performs these operations in order:

2. The expression’s tag byte is read **after that call** and retained.
3. The first mask is established according to that captured tag:
   - For 0x40, call F-7183fcb6e0d1 on expression +16, then F-92ede6886f09 on expression +56, and store their 64-bit union.
   - For 0x41, write zero to the first mask’s low word, then high word.
   - Otherwise, call F-f175fb000823 on expression +12 and store its result.
4. F-f175fb000823 analyzes the source expression itself.
5. The current 16-bit expression flags at +2 are read. If bit 0 is set, F-1b7c3eab96db receives expression +52. Its result is unioned into the second-mask result; that result minus one, modulo \(2^{64}\), becomes the auxiliary mask.

Next, a global tag-table base is read unconditionally. Its cached value is later used for the two tag-0x3F lookups, if that path executes. No table extent is established beyond those accesses.

### Direct versus structural handling

Direct handling requires:

- A captured tag in \(\{0x40,0x41,0x44,0x45,0x46,0x47,0x48\}\).
- No overlap between the initial operand mask and the first mask currently read through the cached target.

Otherwise, structural handling occurs.

Structural dispatch rereads the source tag to check 0x3F and, if that fails, rereads it to check 0x3C. These reads can differ from the captured tag because intervening dependencies may mutate the expression. Other structural tags receive no special processing here.

- Separately read and transform source +8.

- Save both operands’ 16-bit flags.
- Exchange their 32-bit +4 fields, writing the second operand first.
- Transfer saved flag bit 0x0100 in each direction, preserving the other bits read for each write.

  ((t-0x45)\mathbin{\mathrm{xor}}2)+0x45 \pmod{256}.

The first mask comes from the original operand analysis, not fresh analysis.

## Acceptance examples

These are conditional static expectations, not executed tests. Accesses and dependency outputs must remain valid.

1. **Entry stop:** A nonzero entry error byte prevents indexed-record access, mask analysis, and the global tag-table-base read.

2. **Tag timing:** If the first analysis call changes the source tag to 0x41, the captured tag selects a zero first mask. Later mutations may affect structural dispatch without changing captured-tag eligibility.

3. **Table timing:** Replacing the global tag-table base during the first tag-0x3F recursion does not redirect the second lookup. Mutating its second byte at the cached base can affect that lookup.

4. **Direct boundary:** Captured tag 0x48 with disjoint masks permits direct handling; 0x49 does not. Mask overlap prevents direct handling even for 0x44.

5. **Reversal record alias:** With a nonzero input index, if reversal insertion returns that same index, processing does not reject it. The selected record and refreshed target may coincide. Parent, marker, flag, compact metadata, and mask writes then affect the same record. No allocation or record distinctness follows.

6. **Independent expression alias:** Even if insertion returns another index, transformation may return the original expression pointer. Reversal can consequently mutate the cached source expression. A selected tag of 0x49 is still remapped by the greater-than-0x44 rule.

7. **Empty selection:** If consolidation reaches accumulation with no selected records, the retained operand remains zero and is passed to F-1a5398bcc6b3.

8. **Auxiliary wraparound:** If F-1b7c3eab96db returns zero, the auxiliary mask becomes all ones. Normal final augmentation sets both first-mask words to all ones at the cached target address.

9. **Relocation:** If an inactive detector relocates storage and no later path refreshes the target, final augmentation still accesses the cached address. Its validity is an external precondition.

10. **Recognition and truncation:** Values 10 and 11 pass the numeric recognition gate; 12 does not. Input index 65537 produces parent value 1 wherever a parent write occurs.
