# F-85b0197c610c

## Purpose

F-85b0197c610c performs ordered, conditional dispatch on a receiver and a record. It can invoke an initial special-case handler, exactly one of two primary handlers, and a final receiver-associated handler. A nonzero result from any handler immediately becomes the function’s result. If no invoked handler returns nonzero, the function returns zero.

The dispatch decisions depend on numeric fields in the record, one optionally referenced record, and one field in the receiver. Some decisions occur after dependency calls and therefore can observe changes made by those calls.

This is a static behavioral contract. The supplied evidence establishes numeric comparisons, memory accesses, dispatch locations, and result propagation. It does not establish application-level meanings for the numeric values or handler results.

## Interface

### Inputs

The function takes two arguments:

- **Receiver:** an address of a structure whose first word provides access to a table of callable entries. A separate receiver field at byte offset 0x50 participates in the final dispatch condition.
- **Record:** a 32-bit integer argument used as a memory address. Fields at byte offsets 0x04 and 0x08 participate in dispatch.

No separate length, ownership flag, context argument, or error-output argument is visible.

The supplied representation uses 32-bit integer values and a 32-bit address model. The following layout describes the accesses shown, not a complete declaration of either structure.

| Object | Byte offset | Width | Observed use |

The dispatch table contains callable entries at byte offsets 0x0E0, 0x10C, 0x110, and 0x124. These are byte offsets from the table address, not entry numbers.

The receiver’s comparison field is 20 four-byte words from its base: 20 × 4 = 80 bytes, or 0x50. ### Output

The output is a 32-bit integer:

- A handler’s nonzero result is returned unchanged.
- Zero is returned if all invoked handlers return zero.

No nonzero value is normalized to one. Negative and positive nonzero handler results are equally sufficient to terminate processing. Results from F-468ee00d626a are different: they select whether a handler is called and are not returned directly.

For normal completion, every access actually reached must be valid:

- The record discriminator must be readable at each point where it is inspected.

There are no visible null checks, range checks, or recovery paths for invalid addresses or invalid call targets. Validity requirements are path-dependent: fields unused by a particular path need not be read by this function.

## Behavior

### 1. Optional initial special-case dispatch

The function first reads the record’s discriminator at offset 0x04.

If this value is not 0x08, it skips the initial special-case stage. In particular, it does not call F-468ee00d626a on this path.

If the value is 0x08, it calls F-468ee00d626a with the record address as its only visible argument.

- If that dependency returns anything other than 0x6E, no initial special-case handler is invoked.
- If it returns exactly 0x6E, the function resolves the receiver’s dispatch-table entry at offset 0x124 and calls it with the receiver and record.

A nonzero result from the 0x124 handler is returned immediately. A zero result allows processing to continue.

The discriminator is not rechecked between the call to F-468ee00d626a and the decision to invoke the 0x124 handler. Consequently, if F-468ee00d626a changes the discriminator but returns 0x6E, that handler is still invoked.

### 2. Mandatory primary dispatch on every continuing path

If the function has not already returned, it reads the record discriminator again. This is a fresh read, not reuse of the initial value.

This stage chooses exactly one primary handler:

- If the discriminator is 0x16, the function reads the 32-bit value at record offset 0x08 as an address. It then reads the secondary discriminator at offset 0x04 from that referenced address.
  - A secondary discriminator of 0x2A selects the receiver-table entry at offset 0x10C.
  - Any other secondary value selects the entry at offset 0x110.
- If the record discriminator is anything other than 0x16, the function selects the entry at offset 0x110 without performing the referenced-record reads.

After making this selection, the function resolves the selected entry from the receiver’s current dispatch table and calls it with the receiver and original record address. It does not pass the referenced-record address as the record argument.

A nonzero primary-handler result is returned immediately. A zero result allows processing to continue.

The alternate primary handler is not a retry or fallback after a zero result. Once either 0x10C or 0x110 has been selected and called, this stage is complete.

### 3. Conditional final dispatch

After a primary handler returns zero, the function again reads the original record’s discriminator.

If the discriminator is not 0x0F, it returns zero without reading the final comparison fields.

If the discriminator is 0x0F:

1. It reads the 32-bit value at record offset 0x08.
2. It reads the receiver’s 32-bit field at offset 0x50.
3. It compares those values for exact equality.

If they differ, the function returns zero.

If they are equal, the function resolves the receiver-table entry at offset 0x0E0 and calls it with the receiver and original record address.

- A nonzero result is returned unchanged.
- A zero result leads to a zero function result.

There is no subsequent dispatch stage.

### Ordering and mutable state

The distinction between stages is externally significant:

- The initial discriminator read precedes any dependency call.
- F-468ee00d626a, when invoked, completes before the initial special-case handler is resolved.
- The primary discriminator read occurs after all initial-stage calls that actually occur.
- The referenced-record reads, when required, precede resolution of the primary handler.
- The final discriminator read occurs after the primary handler returns zero.
- The final comparison fields are read before the final handler is resolved.

A dependency may change the record, the receiver, a dispatch table, or other state. Nothing in this function restores earlier values or requires dependencies to preserve them.

For example, a primary handler selected using discriminator 0x16 can return zero after changing that discriminator to 0x0F. The final stage then follows the 0x0F path using the state present after that handler returns.

The evidence establishes this source-level sequencing. It does not establish atomic accesses, synchronization, or behavior under concurrent mutation.

   The discriminator is 0x16, but the referenced discriminator is not 0x2A. F-indirect-0110 is selected. F-indirect-010C is not attempted, even if F-indirect-0110 returns zero.

5. **Matching final association.**
