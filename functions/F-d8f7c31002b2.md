# F-d8f7c31002b2

## Purpose

The available static representation describes an operation that interleaves indirect calls with two word-sized stores and two byte-sized stores. Its application-level purpose is not established.

The observable structure is:

- Store the explicit input at an address calculated from that same input.
- Obtain another address index from an indirect call and store the original input again.
- Obtain a 32-bit value from another indirect call.
- Write two different byte projections of that value to addresses selected by byte reads from hidden state.
- Continue making indirect calls, forwarding selected results and one previously read byte.
- Reach a boundary at which the supplied representation cannot recover further execution.

The function is therefore not adequately described as a pure transformation of its explicit argument. Its behavior also depends on incoming machine state, accessible memory, indirect-call targets, and effects of those calls.

This contract describes the visible execution prefix. It does not establish a successful completion path or the intended behavior beyond the unrecovered boundary.

## Behavior

The dependency identifiers below are document-local opaque references. They distinguish visible call sites; they do not establish that the targets are separate implementations.

### 1. Initial store and first calls

The first visible operation is a 32-bit store of the input to the address:

\[
20 + 4 \times \text{input}
\]

No memory read or dependency call is shown before this store.

The function then invokes **F-000000000001**. Its target is calculated from the link-derived base plus 4094. Three arguments are explicitly visible:

1. The context word logically shifted right by 12 bits.
2. The original input.
3. The context word shifted left by 2 bits.

The right shift uses the unsigned context word. Under 32-bit shift semantics, the left shift retains the low 32 bits and discards overflow.

Calls to **F-000000000002**, **F-000000000003**, and **F-000000000004** follow in that order. No explicit arguments or consumed results are shown for those calls.

Next, **F-000000000005** is invoked. Its result supplies a second store index. The function stores the original input as a 32-bit word at:

\[
20 + 4 \times \text{second store index}
\]

This is a separate store even if its address equals the first store’s address.

The function then calls **F-000000000006**, explicitly passing four times the second store index. No other use of that index is visible.

### 2. Acquisition of the projection word

Calls to **F-000000000007**, **F-000000000008**, and **F-000000000009** occur in order.

The next call, **F-000000000010**, produces a value represented as an unsigned 32-bit word. This document calls that result the **projection word**.

The function calculates the projection word shifted left by two bits. It then:

1. Reads one unsigned byte from the address one byte beyond the context word’s address value.
2. Adds 17 to the byte’s numerical value.
3. Writes the low eight bits of the shifted projection word to that resulting address.

The destination is selected by the byte’s value. It is not an address calculated by adding 17 directly to the context word.

Because the selector is an unsigned byte, the destination lies between addresses 17 and 272 inclusive. This range describes the arithmetic; it does not establish that these low addresses are usable memory.

The written byte is:

\[
(4 \times \text{projection word}) \bmod 256
\]

Only bits 0 through 5 of the projection word affect this byte. Its lowest two bits are always zero.

### 3. Calls between the byte stores

After the first byte store, **F-000000000011** is invoked with three explicitly shown arguments:

1. The projection word shifted left by 2.
2. The same shifted value.
3. The projection word shifted left by 4.

Under 32-bit machine semantics, these arguments are truncated to 32 bits.

The target construction for this call differs from the surrounding fixed-offset calls: its displayed target offset is 4076 rather than 4094. Whether that difference has a higher-level meaning is unknown.

Next:

- **F-000000000012** returns a 32-bit payload.
- **F-000000000013** receives that payload as an explicitly shown argument.
- **F-000000000014**, **F-000000000015**, and **F-000000000016** are invoked in order.
- **F-000000000017** is invoked and returns a value retained for a subsequent scaled argument.

No transformation of the payload between **F-000000000012** and **F-000000000013** is visible. The payload’s type, ownership, and meaning are not established.

### 4. Second selector read and second byte store

After **F-000000000017** returns, the function reads the byte at context-word-plus-one again.

This is a fresh memory read, not reuse of the selector obtained before **F-000000000011**. The intervening dependencies may have changed that memory. The first byte store may also alias the selector location for some context values.

The newly read byte is retained as the **saved selector**.

The second byte destination is:

\[
17 + \text{saved selector}
\]

The stored value is the low eight bits of:

\[
(\text{projection word} \mathbin{\&} \texttt{0x3fffffff}) \gg 20
\]

The mask removes bits 30 and 31, and the unsigned right shift produces at most ten significant bits. The byte store then discards all but eight bits. Consequently, the stored byte is exactly bits 20 through 27 of the projection word.

This second store need not target the same address as the first. Equality depends on the two selector reads returning the same value.

### 5. Final visible calls

After the second byte store:

1. **F-000000000018** receives the result from **F-000000000017**, shifted left by two bits.
2. **F-000000000019** is invoked.
3. **F-000000000020** is invoked.
4. **F-000000000021** is invoked.
5. **F-000000000022** is invoked and supplies another result.
6. **F-000000000023** receives that result shifted left by two bits and the saved selector widened to an unsigned integer.
7. **F-000000000024** is invoked.

The selector passed to **F-000000000023** is the byte captured before the second byte store. It is not visibly reread after the intervening calls.

The supplied representation then ends at an unrecovered instruction boundary. No further behavior is established.

- The second word store writes 3 at address 40.
- **F-000000000006** receives 20.

A trace reversing these two stores would not match the visible ordering.

### Byte projections with an unchanged selector

- Both byte stores target address 24.
- The first writes `0xE0`.
- The second writes `0x23`.
- The saved selector later passed to **F-000000000023** is 7.

Immediately after the second store, that location contains `0x23`, unless another effect occurs concurrently.

### Selector modified between reads

If the first selector read returns 7 and the second returns 9:

- The first byte store targets address 24.
- The second targets address 26.
- **F-000000000023** receives selector argument 9.

An implementation that caches the first selector for both stores would not match this case.

- **F-000000000011** receives `0xFFFFFFFC`, `0xFFFFFFFC`, and `0xFFFFFFF0`.
