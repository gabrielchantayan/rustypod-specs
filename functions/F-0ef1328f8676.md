# F-0ef1328f8676

## Purpose

F-0ef1328f8676 performs an ordered, cleanup-like operation on a supplied object and returns the original object address on normal completion.

Its established behavior comprises:

- Two 32-bit reads from separately identified global locations, each followed by a write of the value read to the object’s first 32-bit word.
- Conditional processing of resource fields.
- Four calls receiving addresses of embedded regions.
- Acquisition of a 32-bit context, followed by one or two calls using that context.

The header transitions and ordering suggest layered object cleanup. This is **inferred intent**, not an established destruction or ownership contract. The supplied body does not establish that the object, its embedded regions, or its referenced resources are freed.

The two header values are **not established constants**. Each is obtained from its respective global location when the corresponding assignment executes.

## Behavior

### Initial global read and header write

Before checking an object selector or invoking a dependency, the function reads the 32-bit contents of the first header-source global and writes that value to offset 0 of the object.

This is a read of global data followed by an object-memory write, not an established assignment of an immutable constant. The body provides no semantic validation of the value read.

### Initial resource-processing phase

The function reads the selector byte at offset 88.

If that first read equals zero, it reads the 32-bit field at offset 140 and tests it against zero:

- If the gate value is zero, this phase makes no F-88503fb8bb83 calls.
- Otherwise, it makes three calls, with second arguments drawn from offsets 116, 124, and 128, in that order.

Each call’s first argument comes from offset 140. The resource at offset 128 is loaded after the second call returns, before the final call.

If the first selector read is nonzero, the function reads the selector byte again:

- If the second read is not exactly 1, this phase makes no resource calls.
- If it equals 1, the function tests the field at offset 140 against zero.
- A zero gate skips resource processing.
- A nonzero gate produces two F-88503fb8bb83 calls, with second arguments drawn from offsets 116 and 120, in that order.

The resource at offset 120 is loaded after the first call returns, before the final call.

The gate read does not capture offset 140 for the entire phase. That field is read again for successive call arguments. Earlier calls may change it, and the function does not repeat the nonzero gate before every call. Consequently, a later call may receive zero as its first argument despite the phase having started with a nonzero gate.

Likewise, resource fields are not captured as an entry-time collection. Later reads occur after earlier calls. A zero resource value at offsets 116, 120, 124, or 128 does not independently suppress a reached call.

The static representation establishes these cross-call read boundaries. It does not establish a portable order between independent argument reads for a single call.

### First pair of embedded-region calls

After the initial resource phase, including when that phase makes no calls, the function invokes:

1. F-a600efb7b035 with the object address plus 144 bytes.
2. F-eb4bfcfcd9fa with the object address plus 152 bytes, after the preceding call returns.

These arguments are addresses within the object, not values loaded from those offsets.

### Second global read and header write

After both embedded-region calls return, the function reads the 32-bit contents of the second header-source global and immediately writes the value read to offset 0.

This read occurs at this point in the sequence. The function does not establish that the second global was sampled at entry or before the preceding calls. Any earlier dependency that changes its contents can therefore affect the second header assignment.

No dependency call appears between this global read and its corresponding object-header write.

### Context acquisition

There is no explicit zero or validity check on the result. This retained context is used by the following F-b095584f3a1f calls; it is not reacquired between them.

The enable flag, later selector, and associated object fields are examined after context acquisition. Earlier dependencies, including F-1780a335331b, may affect the values subsequently read.

- Zero skips the optional call without requiring a selector read at offset 8.
- Any nonzero byte causes the selector at offset 8 to be examined.

When enabled, F-b095584f3a1f receives:

1. The retained 32-bit context.
2. The 32-bit field at offset 36.
3. The third explicit input.
4. The fourth explicit input.

2. The 32-bit field at offset 56.
3. The third explicit input.

## Side effects

### Direct memory accesses

The function directly performs two object-memory writes, both 32-bit writes at offset 0:

1. The value read from the first header-source global, before all dependency calls.
2. The value read from the second header-source global, after the calls using offsets 144 and 152 and before context acquisition.

The two associated global reads occur separately at those execution points. No direct write to either header-source global is shown.

No resource field, enable flag, or selector is explicitly cleared. The second header assignment is the last direct object write shown, but dependencies called afterward may modify the object. Its value is therefore not guaranteed to remain at return.

### Initial calls skipped

A stable selector of 0 or 1 with a zero gate produces no F-88503fb8bb83 calls. A stable selector outside 0 and 1 also produces none, regardless of the gate.

### Optional later processing

A nonzero enable byte and selector 2, 3, or 4 produce two F-b095584f3a1f calls: first using offset 36, then offset 56, with the same retained context.

A zero enable byte produces only the offset-56 call and does not require reading offset 8. A nonzero enable byte with selector 1 also produces only the offset-56 call.

### Mutation between resource calls

With initial selector 0 and a nonzero gate, suppose the first resource call changes offset 140 to zero. The second and third calls are still reached; they may receive zero as their first argument.

If the optional later call changes offset 56, the unconditional later call uses the subsequently read value, not a required entry-time snapshot.

### Global-read timing

Suppose the first header-source global contains value A when its read occurs. The initial header write stores A before any dependency call.

Suppose the second header-source global initially contains B, but the call involving offset 152 changes it to C before returning, with no further change before the second global read. The second header write stores C, not B.

An implementation that unconditionally substitutes B captured at entry would not satisfy this behavior.

### Equal global contents and final header state

If both globals yield the same 32-bit value, the body still performs both assignments at their specified points. Distinct global sources do not require unequal header values.

If a dependency after the second assignment changes offset 0, the function does not explicitly restore the assigned value. Acceptance therefore does not require the second header value to remain at return.
