## Behavior

### Original-state observations

Before either pair is transformed, the function derives and retains:

1. The second argument shifted right by one and stored as unsigned.
2. The fourth argument shifted right by one as unsigned.

These retained values represent the original arguments. Subsequent pair transformations do not replace them.

The first shift is applied to a signed input. Under an arithmetic signed right shift, a negative second argument produces a shifted value that remains negative when interpreted as signed. The second shift is unsigned and therefore logical.

Under the 32-bit model, bit 30 of either retained value equals bit 31 of its corresponding original argument, regardless of the fill bits used by the signed shift. Consequently, final sign selection uses the original sign-position bits, not the signs of transformed arguments.

### First-pair transformation

The first pair is transformed only if the retained shifted second argument, interpreted as signed, is negative.

With 32-bit two’s-complement integers and arithmetic signed right shift, this condition is equivalent to the original second argument being negative. Without that shift convention, the equivalence is not established.

When the condition holds:

- The function first records whether the original first argument is nonzero.
- It replaces the first argument with its signed arithmetic negation.
- It replaces the second argument with the negation of the sum of its original value and the recorded nonzero indicator.

The indicator contributes zero when the original first argument is zero and one otherwise. It is established before the first argument is negated.

The second-word calculation uses unsigned arithmetic because the indicator is explicitly converted to unsigned before addition. Under the 32-bit model, the sum and its negation wrap modulo \(2^{32}\). The resulting unsigned value is then assigned to a signed argument slot. A value outside the signed range requires the implementation’s unsigned-to-signed conversion behavior.

Under the conventional two’s-complement bit-pattern interpretation, the transformation is two-word negation:

- If the low word is zero, the high word is negated without an additional adjustment.
- If the low word is nonzero, the high-word calculation includes an additional one before negation.

This is not independent negation of both words. The low-word nonzero indicator is necessary to obtain the two-word result.

If the transformation condition is false, both words of this pair remain unchanged for delegation.

### Second-pair transformation

The second pair is transformed if the original fourth argument, converted to signed, is negative.

Under the conventional 32-bit conversion behavior, this tests whether the original fourth argument has bit 31 set.
