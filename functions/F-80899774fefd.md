# F-80899774fefd

## Purpose

F-80899774fefd implements an ordered dispatch chain over a receiver and an event-like record. It optionally performs a preliminary notification, optionally invokes a first handler, invokes one of two alternative handlers, and conditionally invokes a final handler.

The first handler that returns a nonzero result terminates the chain, except that the preliminary notification’s result does not control dispatch. If no result-producing handler returns a nonzero value, the function returns zero.

The record’s discriminator and associated data are read again between stages. Consequently, a dependency that changes reachable state can affect later routing during the same invocation. The behavior is not equivalent to selecting all handlers from a single snapshot of the original input.

“Receiver,” “record,” “discriminator,” and “handler” are descriptive terms. Their application-level meanings are not established by the supplied static evidence.

## Interface

### Inputs

The function accepts two arguments:

- **Receiver:** an address of structured, mutable storage. Some words are treated as data; its first word is treated as a pointer to a function table.
- **Record:** an address of structured storage containing a discriminator and a second field whose interpretation depends on that discriminator.

Both arguments are passed unchanged to each result-producing indirect dependency that is invoked.

The preliminary dependency, F-4fd087f2325e, instead receives the receiver and a character-width conversion of a receiver field.

### Represented widths and layout

The supplied representation uses integer-sized fields and integer-valued addresses. This contract describes its apparent 32-bit layout: four-byte integer fields, four-byte stored pointers, and four-byte return values. These are properties of the represented interface, not independently verified ABI facts.

All offsets below are byte offsets.

| Storage | Offset | Use |
|---|---:|---|
| Receiver | 0 | Pointer to a function table |
| Receiver | 80 | Comparison value for the final dispatch condition |
| Receiver | 260 | Integer value converted to character width for F-4fd087f2325e |
| Record | 4 | Discriminator |
| Record | 8 | Pointer or comparison value, depending on the discriminator |
| Nested record | 4 | Subtype value, when the discriminator is 22 |

For discriminator 22, the field at record offset 8 is treated as an address. The nested subtype is read at offset 4 from that address.

For discriminator 15, the field at record offset 8 is used directly as a value for comparison with the receiver field at offset 80. No nested dereference is performed for that comparison.

The receiver’s function table supplies indirect call targets at these byte offsets:

| Table offset | Role |
|---:|---|
| 292 | Optional first result-producing handler |
| 268 | Alternative handler selected for subtype 42 |
| 272 | Alternative handler selected for all other routing cases |
| 224 | Optional final handler |

These are table offsets, not dependency identities.

### Output

The function returns an integer:

- The exact nonzero result from the first result-producing handler that returns nonzero; or
- Zero if all invoked result-producing handlers return zero.

A nonzero value is propagated without normalization. The evidence does not establish that it is a Boolean, an error code, or a success code. Negative and positive nonzero results both terminate dispatch.

### Preconditions

Every address actually dereferenced must designate accessible storage of the required size. Every invoked function-table entry must identify a callable target with a compatible interface.

There are no explicit null checks, bounds checks, table checks, or recovery branches. Storage need only support the accesses reached on the selected path, but record offset 4 and a receiver function-table lookup are reached on every normally completing invocation.

## Behavior

### 1. Preliminary notification

The function first reads the discriminator at record offset 4.

If it is not 22, this stage performs no nested read and makes no preliminary call.

If it is 22, the function:

- Reads the pointer at record offset 8.
- Reads the nested subtype at offset 4 from that pointer.
- Subtracts hexadecimal 2500 from that subtype and compares the result with 2.

If the comparison succeeds, the function reads the integer at receiver offset 260, converts it to the represented character type, and invokes F-4fd087f2325e with the receiver and the converted value.

For an ordinary, non-overflowing 32-bit calculation, subtype hexadecimal 2502, or decimal 9474, satisfies this condition. That value is also the matching value under modulo-32-bit subtraction. The supplied representation does not establish the arithmetic semantics for signed-overflow cases generally.

The conversion to character width matters. The dependency does not receive the full receiver integer. The character width, signedness, and promotion rules are not independently established. Under an eight-bit character interpretation, the low eight bits are retained; whether a retained high bit produces a negative argument depends on character signedness and calling conventions.

No return value from F-4fd087f2325e is inspected. After that call returns normally, dispatch continues.

### 2. Optional first handler

The function reads record offset 4 again. It does not reuse the discriminator from the preliminary stage.

If the new discriminator is 22, it again reads the pointer at record offset 8 and the subtype at nested offset 4.

Only when this newly read subtype is zero does it:

- Read the receiver’s function-table pointer.
- Load the target at table offset 292.
- Invoke that target with the receiver and record.

If the handler returns nonzero, that result is returned immediately. No alternative handler or final handler is then invoked.

If the handler returns zero, dispatch continues. If the discriminator or subtype does not qualify, this handler is skipped.

Changes made by F-4fd087f2325e can therefore enable or disable this stage. The earlier subtype comparison does not freeze later routing.

### 3. Alternative-handler selection

Unless an earlier result-producing handler has returned nonzero, the function reads record offset 4 again.

If the discriminator is 22, it reads the pointer at record offset 8 and then the nested subtype at offset 4.

The function selects:

- The target at table offset 268 when these current reads show discriminator 22 and subtype 42.
- The target at table offset 272 in every other case.

It then reads the receiver’s current function-table pointer, loads the selected target, and invokes it with the receiver and record.

Exactly one of these two handlers is invoked on any path that reaches this stage and completes the call normally.

If its result is nonzero, the function immediately returns that exact result. Otherwise, it proceeds to the final condition.

A subtype of zero may therefore cause two result-producing calls: the offset-292 handler first, followed by the offset-272 handler if the first returns zero. The second selection is based on fresh reads, so a mutation by the first handler may instead select offset 268.

### 4. Optional final handler

After the selected alternative handler returns zero, the function reads record offset 4 again.

If the discriminator is not 15, it returns zero without reading either comparison field for this stage.

If the discriminator is 15, it reads:

1. The value at record offset 8.
2. The value at receiver offset 80.

If those values differ, it returns zero.

If they are equal, it reads the receiver’s current function-table pointer, loads the target at table offset 224, and invokes it with the receiver and record.

A nonzero result is returned unchanged. A zero result leads to a zero return from F-80899774fefd.

The discriminator and comparison values used here are observed after the alternative handler returns. An alternative handler can therefore make this stage eligible even when the original record did not have discriminator 15.

## Side effects

### Direct effects

The supplied body contains no explicit writes to the receiver, record, nested record, function table, or global storage. Its direct operations consist of reads, comparisons, arithmetic, target selection, calls, and returning a value.

It contains no explicit allocation, deallocation, ownership transfer, or resource-release operation.

### Dependency-mediated effects

Dependencies may have effects not visible in this body. No preservation guarantee is established for:

- Receiver contents or its function-table pointer.
- Record contents or its nested pointer.
- Nested subtype storage.
- Global state.
- Allocation state, lifetimes, or ownership.

In particular, a dependency cannot be assumed to leave later reads equivalent to the original input. The function re-reads both routing fields and the receiver’s function-table pointer at later stages.

If a dependency invalidates storage that a later stage dereferences, the supplied evidence provides no safe continuation or recovery guarantee. Caller and dependency lifetime obligations remain undocumented.

### Ordering and termination

For a normally executing invocation, the possible call order is:

1. F-4fd087f2325e, if initially eligible.
2. The offset-292 handler, if eligible after the preliminary stage.
3. Exactly one of the offset-268 and offset-272 handlers, unless an earlier handler returned nonzero.
4. The offset-224 handler, if eligible after the alternative handler returned zero.

Each stage occurs at most once. There is no explicit loop or retry.

Abnormal dependency behavior, such as nonreturning execution or a memory fault, is not handled by an explicit mechanism in this body.

## Acceptance examples

These examples are conditional static expectations, not executed tests. Unless stated otherwise, addresses are valid, calls return normally, and dependencies do not mutate routing fields.

1. **Ordinary discriminator.**  
   With discriminator 7, the preliminary notification and offset-292 handler are skipped. The offset-272 handler is invoked. If it returns zero, the function returns zero without invoking the final handler.

2. **Nested subtype 42.**  
   With discriminator 22 and nested subtype 42, the offset-268 handler is selected. The offset-272 handler is not invoked. A return value of −3 is propagated unchanged, and no final condition is evaluated.

3. **Nested subtype zero, early completion.**  
   With discriminator 22 and nested subtype zero, the offset-292 handler is invoked. If it returns 9, the function returns 9 without invoking either alternative handler.

4. **Nested subtype zero, continued dispatch.**  
   With the same input, if the offset-292 handler returns zero and leaves routing unchanged, the offset-272 handler is invoked next. If it also returns zero, the function returns zero because the final discriminator remains 22.

5. **Preliminary notification.**  
   With discriminator 22 and nested subtype decimal 9474, F-4fd087f2325e is invoked with the character-converted receiver field. If it leaves routing unchanged, the offset-292 handler is skipped and the offset-272 handler is selected. The preliminary call’s return value does not determine the function result.

6. **Mutation after notification.**  
   Under the preceding initial condition, suppose F-4fd087f2325e changes the nested subtype to zero. The next stage observes zero and invokes the offset-292 handler. Initial subtype 9474 does not prevent that later call.

7. **Mutation after the first handler.**  
   Start with discriminator 22 and subtype zero. Suppose the offset-292 handler returns zero after changing the subtype to 42. The alternative stage invokes the offset-268 handler, not the offset-272 handler.

8. **Final handler eligibility.**  
   With discriminator 15, suppose the offset-272 handler returns zero and record offset 8 equals receiver offset 80. The offset-224 handler is invoked. Its nonzero result is propagated; its zero result produces zero.

9. **Final comparison mismatch.**  
   With discriminator 15 and unequal comparison fields after the alternative handler returns zero, the offset-224 handler is skipped.

10. **Mutation into the final condition.**  
    Start with discriminator 7. Suppose the offset-272 handler changes the discriminator to 15, makes the comparison fields equal, and returns zero. The final handler is invoked because eligibility is evaluated after that mutation.

11. **Early result prevents later reads.**  
    If the selected alternative handler returns 5, the function returns 5 without reading the final discriminator or comparison fields.
