## Behavior

### Arithmetic interpretation

Unsigned right shifts are logical. In particular, masking by \(0x3fffffff\) removes the two highest bits before subsequent extraction.

Byte writes retain only the low eight bits of the supplied value. Therefore:

- Writing a value shifted left by two retains only its original lowest six bits, moved into byte positions 2–7.
- Writing \((x \mathbin{\&} 0x3fffffff) \gg 20\) retains original bits 20–27. The intermediate has up to ten bits, but the destination has only eight.

Several address and value expressions are represented using signed 32-bit intermediates, including multiplication and left shifts. Overflow behavior is not established by the supplied material. Examples below that require wrapping are explicitly conditional on modulo-\(2^{32}\) machine arithmetic; they are not claims about portable signed arithmetic.

### Dependency boundaries

Indirect calls occur between most accesses. Some return values determine later addresses or data; others are ignored by the displayed body. Ignoring a return value does not establish absence of side effects.

The ordering below preserves the visible memory operations and the significant value-producing dependency boundaries. It does not authorize combining repeated stores, moving accesses across calls, or assuming that memory remains unchanged during intervening calls.

For readability, four snapshots are named by their roles:

- **Primary word snapshot:** a word read during the first scaled-address phase.
- **Secondary word snapshot:** a later word read from another scaled address.
- **Byte-pair result:** a later dependency result used for two selected byte writes.
- **Tail-byte result:** the next relevant dependency result used before entry into the repeating tail.

These names describe values, not source identifiers or persistent fields.

### Entry and first selected-byte pair

1. The first visible operation writes the implicit entry payload as a four-byte word at the implicit entry base plus \(0x14\). This precedes the first indirect call.

2. The first indirect call receives the first explicit input. Subsequent indirect calls produce a result used as a scale factor. The routine writes the same entry payload at four times that result plus \(0x14\), then passes the scaled result to another call.

3. A later dependency result supplies the first selected-byte pair. The selector address is \((\text{first input} \gg 8)+1\). The first selected destination receives the low byte of that result shifted left by two.

4. After intervening calls, the selector is read again. The selected destination receives the low byte of the original pair result, masked by \(0x3fffffff\) and shifted right by 20.

The two writes use the same selector-address expression, not necessarily the same destination. A dependency or an aliasing write may change the selector byte between them.

### Unconditional repeating tail

The represented tail executes at least once if reached.

Each iteration:

- Begins with a call receiving the carried argument and a logically right-shifted control value.
- Executes further indirect calls.
- Re-reads the selector at the address established in step 30 and writes zero to the selected destination.
- Passes another dependency result shifted left by two to a call, followed by more calls.
- Obtains the result that supplies the next carried argument, shifted left by two, and the next control value, shifted left by 26.

The loop has no represented exit condition.

The second argument of the first iteration is zero: its initial control value is at most 31 before shifting right by eight. In subsequent iterations, that argument depends on the preceding result’s left shift by 26 followed by logical right shift by eight.

The selector address used for the repeated zero writes remains based on the saved tail-byte result. The selected destination may nevertheless change because the selector byte is read anew each iteration.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Repeated third-input store.** If the third input is 128, the computed word destination is \(0x18\). If the fixed-global snapshot converts to \(0x12345678\), both represented stores use that saved value, even if a dependency changes the global between them.

2. **Selected-byte truncation.** If a byte-pair result is \(0x12345678\), the first byte value is \(0xe0\), and the later byte value is \(0x23\). If the selector remains 5, both destinations are \(0x16\). If it changes between accesses, the destinations may differ.

3. **Fresh selector semantics.** If a selector first reads 0 and later reads 255, the corresponding selected writes target \(0x11\) and \(0x110\). An implementation that caches the first destination would violate the represented behavior.

4. **Store-before-read aliasing.** If the scale factor for the primary snapshot is zero, both its preparatory word store and subsequent word read address \(0x14\). With ordinary accessible memory and no intervening mutation, the snapshot is zero.

5. **Access width remains significant.** If the primary snapshot is \(0xff000000\), the later top-byte word store writes the 32-bit value 255, not merely a byte.

6. **Direct tail destination.** A primary snapshot below \(0x80000000\) selects direct byte address \(0x1c\); one at or above that threshold selects \(0x1d\).

7. **Tail continuation.** If all calls return and all accesses succeed, the tail continues indefinitely and performs one fresh selector read and selected zero write per iteration. There is no successful normal return to assert.
