# F-86760b6b36bf

## Purpose

F-86760b6b36bf produces a 32-bit Boolean result by selecting one bit from a mutable 32-bit word. The selected bit and the request value passed to a dependency depend on the upper 16 bits of an earlier dependency result.

The established behavior is:

- Capture the incoming value of the machine register designated `r3` into a temporary 32-bit word.
- Obtain a 32-bit selector from F-a6e77b5dfc20.
- Invoke five further dependencies in a fixed order, including one that receives the address of the temporary word.
- Return bit 0 of that word when the selector’s upper half is hexadecimal `0011`; otherwise return bit 2, shifted down to bit 0.

On a normal return, the result is exactly zero or one.

The sequence suggests a mode-dependent query followed by extraction of a flag. That interpretation is inferred intent, not an established description of the dependencies or of the flag’s meaning.

## Behavior

### Input capture and selector acquisition

The incoming register value is copied into the temporary word before the first dependency call.

F-a6e77b5dfc20 is then invoked. Its result is retained as a 32-bit unsigned selector. Subsequent branch decisions use this captured result; the function does not query the selector dependency again.

The selector test is an unsigned right shift by 16 bits followed by comparison with hexadecimal `0011`. Equivalently, the special branch applies to selector values from hexadecimal `00110000` through `0011FFFF`, inclusive.

The low 16 bits do not affect branch selection. The comparison concerns the complete upper 16-bit field, not an individual bit or only the highest byte.

### Final extraction

| Captured selector’s upper 16 bits | Selected bit | Result |
|---|---|---|
| Hexadecimal `0011` | Bit 0, least significant bit | The word masked with one |
| Any other value | Bit 2 | The word masked with four, then shifted right by two |

The masks and shifts operate on unsigned 32-bit values. There is no sign extension, arithmetic right shift, multiplication, addition, or overflow-dependent behavior in the visible extraction. Bits other than the selected bit do not affect the result.

### Observable ordering constraints

The established local order is:

- Capture the entry word.
- Obtain and retain the selector.
- Invoke the two dependencies preceding F-b3e2a11b7207.
- Invoke F-b3e2a11b7207 with the selected request and temporary-word address.

Consequently, an equivalent implementation cannot generally move extraction ahead of the final two calls without additional dependency guarantees.

### Ownership and lifetime

## Acceptance examples

These are conditional acceptance criteria derived from static evidence, not executed tests. Each assumes all dependencies return normally and the stated word value is present at final extraction.

### Special selector range

If the selector is hexadecimal `00110000`, F-b3e2a11b7207 receives decimal 75 as its first explicit argument.

- Final word hexadecimal `00000001`: return one.
- Final word hexadecimal `00000004`: return zero.
- Final word hexadecimal `FFFFFFFF`: return one.

The same branch applies to selector hexadecimal `0011FFFF`. Changing only the selector’s low 16 bits does not change the request or selected bit.

### Ordinary selector range

If the selector is hexadecimal `00100000`, F-b3e2a11b7207 receives decimal 18 as its first explicit argument.

- Final word hexadecimal `00000001`: return zero.
- Final word hexadecimal `00000004`: return one.
- Final word hexadecimal `FFFFFFFB`: return zero, because bit 2 is clear despite the other set bits.

Selector hexadecimal `00120000` also takes this branch. The special range has no inclusive extension into either neighboring upper-half value.

### Input preservation case

Suppose the incoming word is hexadecimal `00000004` and all dependencies leave that temporary word unchanged.

- A selector with upper half hexadecimal `0011` produces zero.
- Any other upper half produces one.

This case establishes why the incoming register value cannot be dismissed merely because the function has no declared parameters.

### Replacement case

Suppose the incoming word is zero, but F-b3e2a11b7207 replaces it with hexadecimal `00000005`, and it remains unchanged until extraction.

Both branches return one, although they use different requests and inspect different bits.

### Late modification case

If dependency-mediated effects change the temporary word after F-b3e2a11b7207 returns but before extraction, acceptance is determined by the value at extraction. A checker must not assume that only the explicitly pointer-bearing call can influence that value unless a separate dependency contract establishes that restriction.
