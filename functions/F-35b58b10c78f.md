# F-35b58b10c78f

## Purpose

The established behavior is an unconditional loop of indirect calls, explicitly sized memory accesses, arithmetic transformations, an implicit frame-base adjustment, and a software-breakpoint operation. The supplied representation contains no normal return, termination condition, checked error result, or recovery branch.

Application-level intent is unknown. Terms such as “selector,” “record pointer,” and “frame-like base” below distinguish observed roles; they do not establish data types, valid objects, or a higher-level service.

The contract describes the visible sequence conditionally: each later operation requires earlier calls and accesses to complete, and execution must resume after the breakpoint. It does not establish that a complete iteration is reachable.

## Interface

### Explicit interface

- No explicit arguments are shown.
- No explicit return value is produced.
- No normal completion path is shown.

### Implicit inputs and persistent state

Execution consumes:

- An incoming 32-bit link-like value used to construct the first indirect-call target.
- An implicit 32-bit frame-like address base.
- An incoming register-held 32-bit contribution used in a late byte-store address.
- Two global locations containing 32-bit values used as address bases.
- Memory at fixed, frame-relative, selector-derived, and result-derived addresses.
- Ordinary and secondary results from indirect dependencies.
- The environment’s handling of a software breakpoint with operand `0x92`.

The first global address base is sampled early in each iteration; the second is sampled after the breakpoint. Neither global is assumed stable across dependency calls.

The loop visibly changes the frame-like base and link-like state. The frame-like base is decreased by `0xF4` during each completed iteration, with no visible restoration. Near the iteration’s end, the link-like value is assigned `0x08712031` **before** the final argument load.

## Behavior

### Dependency notation and ordering

**F-000000000001** through **F-000000000037** are opaque, specification-local call-site IDs in encounter order. They do not establish 37 distinct functions.

The first target is constructed by adding `0xFFE` to the link-like value. Initial entry therefore depends on incoming state. Following an iteration that reaches the link assignment, this calculation uses `0x08712031`. The other target constructions use fixed numeric bases and displacements.

An omitted argument list means that no explicit arguments are shown, not that the dependency lacks implicit inputs. No dependency is assumed to preserve globals, pointed-to memory, or ownership.

### 1. Initial calls and early stores

Each iteration begins as follows:

1. Invoke **F-000000000001** with two zero arguments.
2. Invoke **F-000000000002**.
3. Invoke **F-000000000003**.
4. Read the first global address base and retain the sampled value.
5. Invoke **F-000000000004**.
6. Invoke **F-000000000005**, obtaining a pair-valued result.
7. Invoke **F-000000000006** with the pair’s low 32-bit portion and a value formed from its high and low portions plus a zero byte contribution. The signed-addition qualification appears under arithmetic boundaries.
8. Store the 8-bit secondary result associated with **F-000000000006** at the sampled first global base plus `0x11`.
9. Invoke **F-000000000007**.
10. Store a zero byte at that same sampled base plus `0x15`.
11. Invoke **F-000000000008**.
12. Store its ordinary 16-bit result at its secondary 32-bit destination base plus `0x0C`.
13. Invoke **F-000000000009**, obtaining another pair-valued result.

There is **one visible store associated with F-000000000008**. Its ordinary result supplies the halfword value, while its secondary result supplies the address base. These are two result roles, not two writes.

The first global is not reloaded for either early byte store. Changes to its storage by intervening dependencies do not replace the already sampled base.

### 2. Saved pair, frame accesses, and breakpoint

Using the pair from **F-000000000009**, execution proceeds in this order:

1. Store a zero halfword at the pair’s high portion plus `0x2C`.
2. Store the low portion, interpreted as unsigned and logically shifted right by 26, as a word at the frame-like base plus `0x26C`. The stored value is between 0 and 63.
3. Invoke **F-000000000010**.
4. Read and retain a 32-bit address base from the frame-like base plus `0x320`.
5. Invoke **F-000000000011**.
6. Invoke **F-000000000012**.
7. Store the saved low portion, shifted left by two as an unsigned 32-bit value, at the retained base plus `0x54`.
8. Invoke **F-000000000013**, **F-000000000014**, **F-000000000015**, **F-000000000016**, and **F-000000000017**, in that order.
9. Read an unsigned halfword from fixed address `0x21C48994`. Retain it as the first selector.
10. Invoke **F-000000000018**.
11. Read a word from the frame-like base plus `0x280`, and pass it to **F-000000000019**.
12. Execute the software-breakpoint operation with operand `0x92`.

The selector read precedes **F-000000000018**. The frame-relative argument read follows it. These reads cannot be exchanged across the dependency on an assumption that it preserves memory.

The address base sampled at frame offset `0x320` remains the destination base for step 7 even if dependencies change the memory from which it was read.

7. Invoke **F-000000000029**.
8. Store the retained zero-extended halfword as a word at the record pointer plus `0x54`.

10. Store the same retained value as a word at the record pointer plus `0x64`.

The link assignment precedes the final argument read. If that read faults, the visible sequence has already assigned the fixed link-like value, but has not invoked **F-000000000037**.

The final read is not generally a reload of the record field written in step 19: its base is the scaled high portion, not the record pointer. Those addresses may coincide, but no equality is established.

### Arithmetic boundaries

Unsigned halfword loads yield values from 0 through 65,535. Consequently:

- Four times the second selector is at most 262,140.
- Five times the second selector is at most 327,675.
- The selector-indexed word-store address ranges from `0x74` through `0x40070`.
- The two record word stores of the retained halfword contain values from 0 through 65,535.

Halfword stores retain only the low 16 bits.

The low portion from **F-000000000009** is explicitly treated as unsigned for both shifts. Its left shift by two therefore discards bits beyond the 32-bit width; it is not an unresolved signed-shift case.

Other operations have different qualifications:

- Construction of the second argument to **F-000000000006** adds two signed 32-bit interpretations before adding an unsigned zero contribution. That later contribution does not resolve overflow in the preceding signed addition.
- The result of **F-000000000019** is shifted as a signed 32-bit value.
- The late pair’s low portion is shifted left by six as a signed 32-bit value.
- The late pair’s high portion is multiplied by four as a signed 32-bit value.
- Several address additions and the frame-base decrement also use signed 32-bit expressions.

Exact behavior outside representable signed arithmetic, including negative signed left shifts, is **documented_only** without instruction-level evidence. No universal wrapping rule is established.

The late byte destination uses unsigned 32-bit arithmetic because its retained halfword operand has already been widened to an unsigned word. Its address sum is therefore reduced modulo \(2^{32}\) in the supplied representation.

## Side effects

A completed iteration contains 37 indirect invocations, 15 explicit stores, and one software-breakpoint operation.

The explicit stores comprise three byte stores, five halfword stores, and seven word stores. Their order is specified above; dependencies may perform additional accesses between them.

## Acceptance examples

These are conditional static examples, not executed tests. They assume execution reaches the described operations and that relevant accesses and arithmetic are valid.

1. **Saved global base.** If the first global is sampled as `0x1000`, and **F-000000000004** changes its storage to `0x2000`, the early byte stores still target `0x1011` and `0x1015`. The latter stores zero.

2. **One store, two result roles.** If **F-000000000008** supplies ordinary result `0xBEEF` and secondary base `0x3000`, its associated operation is one halfword store of `0xBEEF` at `0x300C`.

3. **Unsigned pair shifts.** If the low portion from **F-000000000009** is `0x84000003`, the frame-offset `0x26C` store receives 33. The later unsigned left-shift store receives `0x1000000C`.

4. **Pointer truncation.** If the second global base is `0x12345678` and **F-000000000019** returns 3, the associated halfword store targets `0x12345684` and stores `0x5678`.

5. **Unsigned widening and retained data.** If the halfword read through **F-000000000028** is `0xFFFF`, both record word stores receive 65,535. **F-000000000030** occurs between them; changing the original halfword there does not change the retained value.

6. **Byte sampling before mutation.** If the byte at five times the second selector is `0xA7`, a subsequent modification by **F-000000000034** does not change the saved byte used by the destination store.

7. **Breakpoint interruption.** If execution does not resume after the breakpoint, no post-breakpoint operation from that iteration is reached.

8. **Final-read fault ordering.** If **F-000000000036** returns and the final word read faults, the link-like state has already been assigned `0x08712031`. **F-000000000037** has not been invoked.

9. **Repeated frame movement.** If the represented frame-base assignment corresponds directly to execution state and arithmetic remains valid, the next iteration begins with that base `0xF4` lower. No restoration is visible.
