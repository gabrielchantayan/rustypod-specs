# F-9f44c2525d7c

## Purpose

F-9f44c2525d7c selects a context-associated entry whose primary or alternate identity equals a supplied target identity. It then optionally compares auxiliary information, performs an auxiliary state-change sequence when those comparisons succeed, and attempts a final operation using a separately acquired transient value.

The visible return classes are:

- **0:** classification rejection, context-resolution failure, or an unavailable auxiliary comparison record.
- **1:** the final operation returns a signed status of at least one.
- **0xFFFFFFFF:** auxiliary mismatch, zero transient-value acquisition result, or final-operation status below one.

These are established control-flow distinctions, not a general error enumeration. Every explicitly shown normal return follows working-area cleanup.

The interpretation as selection, optional reconciliation, and a final operation is inferred intent. The field accesses, dependency calls, branch conditions, and return mappings below are the stronger static evidence.

## Behavior

### Initialization and classification

Before reading the classification descriptor, the function passes a 16-byte local working area to F-99497b78e41d. The result used for early failure returns is initially zero.

Classification proceeds through a short-circuited two-call gate:

- The field at classification offset 0x10 is read and passed to F-2eb743f270d1.
- A result of **0x16** permits processing immediately.
- Otherwise, the same descriptor field is read again and passed to F-2eb743f270d1 again.
- Only a second result of **0x18** permits processing.

This is not equivalent to making one call and accepting either constant. The repeated read and call can observe different state.

Rejection invokes F-4fc89ec41a6d with the two visible arguments **0x21, 0x71**, then cleans up the working area through F-990a2f44da95 and returns zero. No request-descriptor field is read on this path.

### Target identity and context traversal

After classification acceptance, the function reads request offset 0x08, reads the 32-bit value through that address, and passes that value to F-2eb743f270d1. The returned value becomes the target identity retained for traversal and later auxiliary processing.

Target acquisition occurs before testing whether the initial context is zero.

For each current context:

- Zero context causes the two-argument diagnostic, cleanup, and return zero.
- Otherwise, F-2200228f531d receives the context and selector **0x208**.
- A zero result causes the same failure.
- A nonzero result is passed to F-a5253d33ff6f with selector **0x78**, zero, and the address of a local entry-pointer output.
- F-a5253d33ff6f’s return value is ignored. Its entry-pointer output is read instead.
- A zero entry pointer causes the same diagnostic, cleanup, and zero return.

The entry-pointer output is not visibly initialized before use or reset between traversal iterations. Correct output production is therefore a dependency obligation, not something guaranteed by this function.

For a nonzero entry pointer, the function obtains the identity-pair address and reads the primary identity. A primary match selects the entry without reading the alternate identity. Otherwise, the alternate identity is read and compared.

If neither identity matches, F-4a2b7d2440e4 receives the nonzero context-resolution result from that iteration. Its return becomes the next context.

After selection, F-ef3ab54e3806 receives the working area and selected entry pointer. Auxiliary processing begins only after that call returns.

### Auxiliary bypass and comparison

The function reads request offset 0x0C once at this stage.

- Zero bypasses auxiliary processing.
- A nonzero value is passed to F-10b760faca36.
- A zero result from F-10b760faca36 also bypasses auxiliary processing.

Both bypasses proceed to final-operation preparation. The predicate’s zero result is not an error.

When auxiliary processing is enabled, a separate 32-bit auxiliary-output slot is initialized to zero. F-0b1e8b902739 then receives:

- The working area.
- A 36-byte local buffer.
- The address of a distinct 32-bit comparison-value slot.

The comparison-value slot is not visibly initialized beforehand. The zero initialization applies to the auxiliary-output slot, not this comparison slot.

Next, F-4eb72f649fc8 receives the retained auxiliary value. A zero result causes the two-argument diagnostic, working-area cleanup, and return zero. F-0b1e8b902739 has already run on this path.

For a nonzero comparison-record pointer:

1. Its first 32-bit word is compared with the local comparison value.
2. Only if equal is the record’s word at offset 8 read and passed, with the 36-byte buffer, to F-7f14f1ab6851.
3. A zero result from that comparison dependency is required for acceptance.

Either comparison failure invokes F-4fc89ec41a6d with **0x21, 0x71, 0x65, zero, zero**, then cleans up and returns **0xFFFFFFFF**. The diagnostic value **0x65** is not returned.

### Final operation

The function first reads the operation-parameter address from request offset 0x14. It then calls F-82d6fbbbf739 with the operation argument.

If the result is zero:

- The operation-parameter object’s fields are not read.
- Neither F-116022434716 nor F-55d57b266fd4 is called.
- No diagnostic is issued on this branch.
- Working-area cleanup occurs.
- The return is **0xFFFFFFFF**.

For a nonzero result, F-116022434716 receives, in argument-position order:

1. The working area.
2. The operation-parameter word at offset 8.
3. The operation-parameter word at offset 0.
4. The nonzero result from F-82d6fbbbf739.

The parameter address is captured before acquisition, but its referenced fields are read afterward. Their values are not entry-time snapshots.

F-55d57b266fd4 then receives the same nonzero transient value. Only after that call returns is the saved final-operation status tested:

- Signed status **below 1** invokes the diagnostic with **0x21, 0x71, 0x69, zero, zero**, then produces **0xFFFFFFFF** after cleanup.

The diagnostic value **0x69** is not returned.

## Acceptance examples

These are conditional expectations derived from static evidence, not executed tests.

1. **Immediate classification acceptance.** A first classification result of 0x16 permits processing without a second classification read or call.

2. **Repeated classification matters.** A first result of 0x18 does not alone accept. If the second result is not 0x18, classification fails. Conversely, a different first result followed by 0x18 accepts.

3. **Zero initial context.** After accepted classification, target acquisition still occurs before the zero context causes the two-argument diagnostic and return zero.

4. **Primary match short-circuits.** If the primary identity equals the target, the alternate identity is not read and no next-context call is made.

5. **Alternate match.** If only the alternate identity equals the target, the entry is selected without advancing the context.

6. **Auxiliary bypass.** Zero auxiliary input, or a zero predicate result for nonzero input, skips auxiliary comparison and state-change calls while retaining eligibility for the final operation.

7. **Missing comparison record.** If F-4eb72f649fc8 returns zero, F-0b1e8b902739 has already run. The function diagnoses and returns zero, not all ones.

8. **First comparison mismatch.** If the record’s first word differs from the comparison value, the offset-8 read and second comparison call are skipped. Diagnostic 0x65 precedes cleanup and return 0xFFFFFFFF.

9. **Nonlocal state changed before acquisition.** Suppose the nonlocal datum has one value before the auxiliary state-change sequence and F-e3ef981e414f changes it to another. If no further change intervenes and the eventual read yields the latter value, that value is supplied to F-211bb2c8ea63. An earlier snapshot is not substituted.

10. **Zero auxiliary output.** If F-211bb2c8ea63 leaves the auxiliary-output slot zero, F-2cfb687bb8ab still receives zero. If the slot remains zero afterward, F-5990a26eaaa3 also receives zero.

11. **Transient acquisition failure.** A zero result from F-82d6fbbbf739 produces 0xFFFFFFFF without a diagnostic on that branch. The parameter address has been read, but its referenced fields have not.

12. **Signed final-status boundary.** Status 1 succeeds. Status 0 or 0x80000000 fails with diagnostic 0x69. In all three cases, F-55d57b266fd4 runs before status interpretation, and working-area cleanup follows.
