# F-87c09191bebe

## Purpose

F-87c09191bebe examines selected positions numbered 0 through 12 against a requested state. Its established behavior consists of ordered dependency calls, conditional object lookup and indirect invocation, and one of two normal 32-bit results:

- **1:** Traversal finishes without encountering an early-return or failure condition. This includes an empty selection.
- **0:** At a selected position, lookup is required, lookup produces a non-null object, and an indirectly selected operation returns the unsigned value 0 or 1.

Three conditions instead lead to F-a817d8d58c10, identified by the supplied static evidence as non-returning: an initially disallowed requested state, a queried state greater than 2, or a null lookup result.

These results describe control flow, not established application semantics. Neither “valid” nor “invalid” is an established interpretation.

Processing does not use one stable acquisition result throughout. An opaque acquisition dependency is called separately for each selected position and again when that position requires lookup. The evidence does not establish what the acquired values represent.

## Behavior

### Entry gate

The requested state is compared with 3 using signed comparison before any mask processing or explicit dependency invocation.

- Requested state less than 3: begin traversal.
- Requested state 3 or greater: invoke F-a817d8d58c10.

An empty selection mask does not bypass this gate.

### Selection and traversal order

Positions are considered in increasing order, beginning at 0 and ending at 12.

At each position, the matching mask bit determines whether external processing occurs. An unselected position produces no explicit dependency call and advances traversal.

The traversal counter is represented as unsigned 32-bit. Its update retains only the low eight bits. During reachable execution, the update advances values 0 through 12 to values 1 through 13; it never reaches an eight-bit wraparound. Reaching 13 ends traversal with return value 1.

The single-bit mask test uses only shift counts 0 through 12. Bits 13 through 31 cannot select any processed position.

### Acquisition and queried state

For each selected position reached, the function performs this sequence:

1. Invoke F-U01 to acquire an opaque value represented as signed 32-bit.
2. Add 4 to that value.
3. Pass the adjusted value as the argument to F-f82bb660a2ac.
4. Interpret the returned state as signed 32-bit.

No position argument is explicitly passed to F-f82bb660a2ac. The visible evidence does not explain whether the queried state is position-dependent through external state or other mechanisms.

The addition is established; an address derivation is not. Exact behavior when the signed addition exceeds its representable range is not established by the supplied representation. The contract does not impose portable signed wrapping.

The queried state controls processing as follows:

| Queried signed state | Action |
|---|---|
| Greater than 2 | Stop traversal and invoke F-a817d8d58c10. |
| Equal to 0 | Skip lookup and advance. |
| Equal to the requested state | Skip lookup and advance. |
| Otherwise | Perform lookup for the current position. |

The greater-than-2 check occurs before the equality-based lookup decision.

Negative states are not rejected merely for being negative. A negative queried state matching the requested state skips lookup. A different negative queried state requires lookup.

Each selected position gets a new acquisition and state query. No previous queried state is visibly reused.

### Lookup

When lookup is required, F-U01 is invoked a second time. The function adds 4 to this newly acquired signed 32-bit value and supplies the adjusted value to F-9266831caef7.

The other explicit lookup argument is the current position, converted through a character-sized representation and then to a signed integer. Reachable positions are only 0 through 12, so this conversion preserves their numeric values regardless of plain-character signedness.

The two acquisitions at one position need not produce equal values. The function performs no equality check, reconciliation, or retry. The state query receives the first adjusted value; lookup receives the second.

Lookup results are handled as follows:

- **Null:** Stop traversal and invoke F-a817d8d58c10.
- **Non-null:** Read the object’s first word and proceed to indirect invocation.

The function does not visibly validate a non-null object beyond the null check.

### Indirect invocation

For a non-null lookup result, the explicit memory-read order is:

1. Read the first 32-bit word at the object location.
2. Read a callable target at byte displacement 16 from the table base represented by that word.
3. Invoke that target.

No explicit call arguments are shown. The supplied representation does not settle whether the actual calling convention supplies a receiver or other hidden inputs.

The result is interpreted as unsigned 32-bit:

- **0 or 1:** Immediately return 0.
- **2 through 4,294,967,295:** Continue traversal.

Thus, the all-ones word is a continuing result, not a negative result under this comparison.

The low-result branch includes a position-dependent alternative return of 1 for a position greater than 12. That alternative is unreachable in the established traversal: indirect invocation occurs only at positions 0 through 12. An indirect result of 0 or 1 at position 12 therefore returns 0.

### Completion and stopping

Return value 1 means that traversal passed all thirteen possible positions without an earlier stopping event. Selected positions may pass because their state is zero, their state matches the request, or their indirect operation returns at least 2.

Processing stops immediately upon:

- A low indirect result: normal return of 0.
- A queried state greater than 2: invocation of F-a817d8d58c10.
- A null lookup result: invocation of F-a817d8d58c10.

Later selected positions receive no explicit processing after such a stop.

## Side effects

The visible body performs no explicit write to caller-provided memory, returned object storage, table storage, or global storage. Counter updates and intermediate assignments are local computation.

This does **not** establish that the function is pure. Any invoked dependency may change external state, including globals, objects, allocations, or state consulted by later calls.

For a selected position requiring lookup, the visible order is:

**First acquisition → add 4 → state query → second acquisition → add 4 → lookup → object-word read → table-target read → indirect invocation.**

For a position whose queried state skips lookup, only the first acquisition, arithmetic, and state query occur before traversal advances.

There is no explicit allocation, retain, release, destruction, or cleanup operation in this function. A returned object is used without a visible ownership-transfer protocol. The evidence does not establish whether lookup or indirect invocation allocates, retains, consumes, modifies, or releases anything.

In particular:

- Dependencies are not assumed to preserve globals.
- The acquisition result is not assumed to identify memory.
- Lookup is not assumed to return owned or borrowed storage under any particular convention.
- The indirect operation is not assumed to leave the object alive.
- No explicit object read occurs after the indirect operation at that position.

An invalid non-null object, invalid table base, or incompatible call target is not redirected to the null-lookup failure path by any visible check. Such conditions lie outside the established normal-result behavior.

## Acceptance examples

These are conditional static acceptance scenarios, not executed tests. Unless stated otherwise, required arithmetic, memory accesses, and calls complete validly, and dependencies return as specified.

1. **Empty selection.** With requested state 2 and mask 0, return 1 without explicit dependency calls.

2. **Only high bits selected.** With requested state 0 and only mask bits 13 through 31 set, return 1 without explicit dependency calls.

3. **Entry failure precedes selection.** With requested state 3 and mask 0, invoke F-a817d8d58c10. Do not acquire a value or query a state first.

4. **Negative requested state admitted.** With requested state −1 and mask 0, return 1.

5. **Arithmetic forwarding without address assumptions.** With only position 4 selected, let F-U01 return 100. F-f82bb660a2ac receives 104. If it returns zero, lookup is skipped and the function returns 1. This scenario requires no assumption that either 100 or 104 denotes an address.

6. **Matching state.** With requested state 2, only position 4 selected, and queried state 2, skip lookup and return 1.

7. **Two distinct acquisitions.** With requested state 1 and only position 4 selected, let the first acquisition return 100 and the query receiving 104 return 2. Let the second acquisition return 200. Lookup receives 204 and position 4. If lookup is non-null and the indirect result is 2, traversal completes with return 1. No equality requirement relates the acquired values.

8. **Negative queried-state distinction.** With requested state −1, a queried state of −1 skips lookup. A queried state of −2 requires lookup. Neither value triggers the greater-than-2 failure.

9. **Low result at the final position.** With only position 12 selected, a state requiring lookup, a non-null lookup result, and indirect result 1, return 0—not 1.

10. **Unsigned upper boundary.** Under lookup conditions, indirect result 4,294,967,295 continues traversal. If no later position stops processing, return 1.

11. **Excessive queried state.** If a selected position’s query returns 3, invoke F-a817d8d58c10 without a second acquisition or lookup for that position.

12. **Null lookup.** If required lookup returns null, invoke F-a817d8d58c10 without reading the object word, reading a table target, or invoking the indirect operation.

13. **Ordered stopping.** With positions 1 and 9 selected, an indirect result of 0 at position 1 returns 0 before any acquisition or query for position 9.
