# F-39fbee30785f

## Purpose

F-39fbee30785f coordinates a conditional load into a caller-supplied output object. Its established responsibilities are:

- Optionally invoke a preliminary dependency.
- Apply admission checks.
- Acquire access through an owner-provided callback.
- Prepare temporary context storage.
- Invoke a principal-loading dependency.
- Conditionally publish or adjust output state.
- Apply a final flag update on eligible main-path attempts.

Glyph loading and outline processing are inferred intent, not independently established interfaces.

The operation is not transactional. Dependencies can run before a later rejection, and a principal-load error does not undo output initialization or prevent the final conditional flag update.

## Interface

### Arguments and return value

The interface uses four 32-bit arguments.

| Argument | Meaning established at this boundary |
|---|---|
| Subject | Address of an object containing admission and final-update metadata. |
| Output | Address of an object containing owner and loader references and writable result fields. |
| Item | Opaque 32-bit value forwarded to selected dependencies. |
| Flags | Unsigned 32-bit mask controlling preliminary processing, admission, main-path prohibition, and the final update. |

The result is a 32-bit integer.

| Condition | Result |
|---|---|
| Preliminary dependency returns zero | Zero, immediately |
| Admission byte is zero while flag `0x1` is clear | `0x24` |
| Admission passes and flag `0x4000` is set | `6` |
| Acquisition callback returns nonzero | That callback result, after a diagnostic call |
| Principal-loading dependency runs | Its result |

A zero result does not establish that principal loading occurred.

## Behavior

### Initial reads and preliminary processing

The function first reads Subject `+0x70`, then captures the owner address from Output `+0x04`.

F-e96ce1a07361 receives all four original arguments only when:

- The captured Subject word differs from `0xffffffff`.
- Flag `0x8` is clear.

A zero result causes immediate return of zero. Admission, acquisition, direct output initialization, and principal loading do not follow.

A nonzero preliminary result is discarded as a return candidate; processing continues.

The initial owner address remains the owner reference used for the later adjustment gate. A preliminary dependency may change Output `+0x04`, but that does not replace this captured address. The contents of the captured owner are not snapshotted: its `+0xb0` field is read later.

### Admission and main-path prohibition

If flag `0x1` is clear, the function reads Subject `+0x6c` as an unsigned byte. Zero causes return of `0x24`.

If flag `0x1` is set, this admission-byte read is skipped.

After admission passes, flag `0x4000` is checked. If set, the function returns `6`.

The precedence is therefore:

1. Preliminary zero-result short circuit.
2. Admission-byte rejection, when enabled.
3. Main-path prohibition.
4. Acquisition and loading.

### Acquisition setup

On the main path, the function rereads Output `+0x04`. This owner may differ from the initially captured owner. It then reads and retains the 32-bit resource value from the reread owner’s `+0x68`.

F-U01 receives the temporary-context address and the integer `0xb8`, decimal 184. The call is consistent with initialization, but its actual memory effects are unresolved. In particular, zeroing all 184 bytes is not an established guarantee.

After F-U01 returns:

- The acquisition callable is obtained from the main-path owner’s `+0x1f8`.
- The selector is read from the first 32-bit word of G-selector-data.
- The callback receives the main-path owner, that selector value, the previously captured resource value, and zero.

The selector is a data read, not an immediate constant. F-U01 can affect the value subsequently observed there. The resource value, by contrast, was captured before F-U01 and is not reread for this call.

The relative order of fetching the callback address and reading the selector is not independently established by the supplied representation. Both occur after F-U01 and before callback entry.

If the callback returns nonzero, F-4457a9a44a68 receives the address G-selector-data plus four, namely `0x08081650`. This is an address into the same object whose first word supplied the selector, not the selector value itself. The diagnostic dependency’s result is ignored, and the callback’s result is returned.

No direct output initialization, principal loading, or final conditional bit update follows acquisition failure. Dependency effects remain possible.

### Successful acquisition and context preparation

After a zero acquisition result:

1. F-b03b1199772e receives the captured resource value. Its 32-bit result is stored at context `+0x54`.
2. The loader handle is obtained through two address reads: Output `+0x9c` supplies a pointer, and the pointed-to 32-bit word supplies the handle.
3. F-1cc54a4c66f8 receives that handle.
4. The function explicitly populates the following context fields:

| Context offset | Width | Assigned content |
|---|---:|---|
| `+0x00` | 32 bits | Main-path owner address |
| `+0x04` | 32 bits | Subject address |
| `+0x08` | 32 bits | Output address |
| `+0x0c` | 32 bits | Obtained loader-handle address |
| `+0x10` | 32 bits | Original Flags |
| `+0x18` | 32 bits | Captured resource value |

The earlier store at `+0x54` is distinct from these later assignments. No general preservation guarantee is inferred for intervening dependencies.

A 32-bit adjustment quantity at context `+0x44` is examined on one successful-load branch. This function does not explicitly initialize that field. Its eventual value depends on F-U01 and any subsequent context mutation.

### Output initialization and principal loading

After context preparation, the function performs these operations in order:

1. Reads G-initial-discriminator and writes the obtained 32-bit value to Output `+0x48`.
2. Writes zero to Output `+0x80`.
3. Writes zero to Output `+0x7c`.
4. Calls F-2c9ace2640db with the context address, original Item, and zero.

The global discriminator read occurs after the preparation dependencies. It is not a value captured at entry.

The principal-loading result becomes the eventual return value of this path. A nonzero result skips successful-load publication and completion, but the final conditional update still remains eligible. No rollback is performed.

### Successful-load publication

Only when F-2c9ace2640db returns zero does the function compare Output `+0x48` with a fresh read of G-comparison-discriminator.

The comparison global is read after principal loading, so mutations by that dependency can determine the selected branch. It is not an entry-time constant.

**Equal values**

The function:

1. Reads the current context-held loader handle’s `+0x2c` word and writes it to Output `+0x80`.
2. Reads the current context-held loader handle’s `+0x30` word and writes it to Output `+0x84`.

The handle is taken from context `+0x0c`, not guaranteed to remain the originally obtained value after principal loading.

F-U02 and the adjustment dependency are not called on this branch.

**Unequal values**

The function calls F-U02 with:

- Destination argument: Output `+0x6c`.
- Source argument: the current context-held loader handle plus `0x14`.
- Third argument: `0x14`, decimal 20.

This establishes argument values, not a proven 20-byte copy. The helper’s actual reads, writes, access granularity, and overlap behavior remain unresolved.

After F-U02 returns, the function explicitly reads Output `+0x7c`, clears bit `0x200` using the 32-bit mask `0xfffffdff`, and writes the result back.

It then reads the unsigned 16-bit field at `+0xb0` of the owner captured at entry. If bit `0x2` is clear, it examines context `+0x44`. If that quantity is nonzero, F-074238b57126 receives Output `+0x6c` and the 32-bit negation of the quantity.

The adjustment quantity is not examined for this condition when owner bit `0x2` is set.

**Completion**

After either successful-publication branch, F-4dff4d3e7c26 receives the context address and original Item. Its result does not replace the principal-loading result.

### Final conditional update

After principal loading and, on success, after completion:

- If original flag `0x1` is clear, Subject `+0x0e` is read as an unsigned 16-bit value.
- If that value is below `0x18`, Output `+0x7c` is read, bit `0x100` is set, and the result is written back.

This can occur after a principal-load error. It does not occur after the preliminary short circuit, local rejections, or acquisition failure.

The update uses the field values present at this late point, including any changes made by completion.

## Side effects

Established direct output writes are limited to:

- Initialization of `+0x48`, `+0x80`, and `+0x7c`.
- Conditional publication to `+0x80` and `+0x84`.
- Conditional read-mask-write operations on `+0x7c`.

F-U02 may introduce additional writes, but their extent is not established. If it performs the inferred 20-byte copy, the destination range would be Output `+0x6c` through `+0x7f`, including `+0x7c`. Only under that additional condition does the subsequent mask modify a field overwritten by that copy.

Output `+0x84` is not directly cleared before loading. Its prior value can remain unless a dependency changes it or the equal-discriminator success branch replaces it.

The function directly reads, but does not directly write, the three identified global-data locations. Dependencies may mutate them or other accessible state. The selector and the two discriminator values must be considered separately at their respective read times.

No explicit allocation, release, ownership transfer, or resource cleanup is established. F-1cc54a4c66f8 must not be classified as releasing or resetting the loader without further evidence.

Temporary context storage is exposed by address to dependencies. Retention is unknown; no valid post-return use of that temporary storage is established.

## Acceptance examples

These are conditional static acceptance cases, not executed tests.

1. **Preliminary short circuit.** The preliminary gate permits the call and F-e96ce1a07361 returns zero. Expected: return zero without admission, acquisition, or direct output initialization. The initial Subject and owner reads have already occurred.

2. **Rejection precedence.** Preliminary processing does not short-circuit; flag `0x1` is clear; the admission byte is zero; flag `0x4000` is set. Expected: `0x24`, not `6`.

3. **Admission bypass.** Preliminary processing does not short-circuit; flags `0x1` and `0x4000` are set. Expected: return `6` without the admission-byte read.

4. **Selector timing.** F-U01 changes the first word of G-selector-data from value A to value B. Expected: acquisition receives B. If acquisition fails, diagnostics receives the address of the same object plus four, not A or B.

5. **Acquisition failure.** The callback returns a particular nonzero 32-bit result. Expected: diagnostics, then that result; no direct pre-load resets or final flag update.

6. **Initialization-global timing.** A preparation dependency changes G-initial-discriminator. Expected: Output `+0x48` receives its later value when initialization occurs, not a presumed fixed value.

7. **Comparison-global timing.** Principal loading succeeds and changes G-comparison-discriminator. Expected: branch selection uses the post-load global value and the then-current Output discriminator.

8. **Principal-load error.** Acquisition succeeds, principal loading fails, flag `0x1` is clear, and the final Subject halfword is `0x17`. Expected: skip publication and completion, set Output `+0x7c` bit `0x100`, and return the principal-load error. A halfword of `0x18` does not trigger this update.

9. **Equal-discriminator success.** The post-load comparison is equal. Expected: publish the two loader words in order, then call completion; do not call F-U02 or adjustment.

10. **Unequal-discriminator success.** Expected: call F-U02 with the three specified arguments, then explicitly clear Output `+0x7c` bit `0x200`. Adjustment requires both a clear initial-owner bit `0x2` and a nonzero context quantity. A 20-byte destination overwrite is an additional expectation only if F-U02’s copy semantics are independently established.

11. **Owner replacement.** Preliminary processing replaces Output `+0x04`. Expected: acquisition uses the replacement owner; the adjustment gate later reads the original owner’s current `+0xb0` field.
