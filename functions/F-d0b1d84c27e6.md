# F-d0b1d84c27e6

## Purpose

F-d0b1d84c27e6 transforms a writable, word-array-backed object using another object’s words, several global scaling values, and an optional call to F-4f8dc40081ad. It overwrites destination words, replaces the destination’s count field, and returns a status together with the destination address.

The arithmetic resembles a scaled, multiword subtraction followed by a low-word adjustment and removal of high zero words. That interpretation is **inferred intent**, not an established numerical contract. The global values, object representation, and dependency behavior are not supplied. The established contract is the word-level behavior below.

No allocation, deallocation, capacity check, or general input validation is visible in this function.

## Behavior

### Arithmetic conventions

The carry calculations explicitly operate on unsigned 32-bit values. For those calculations:

- Addition retains the low 32 bits.
- A carry is one when the mathematical sum exceeds \(2^{32}-1\), otherwise zero.
- Negation and subtraction used to construct those unsigned operands are understood by their resulting 32-bit patterns.

Let \(M=2^{32}\). The word formulas below describe low-32-bit results. Some surrounding expressions are presented as signed multiplication, negation, or index arithmetic. Their overflow behavior is not independently established; the formulas do not authorize arbitrary overflowing inputs as portable, defined executions.

### 1. Capture initial state

Before processing words, the function captures:

1. The read factor.
2. The source count.
3. A terminal word bound equal to the count factor multiplied by that captured source count.

The carry accumulator starts at zero.

The captured source count is later written to the destination count field. It is not reread from the source for that assignment.

### 2. Process words covered by the destination count

The first traversal begins at word index zero. Before each iteration, its index is compared, as a signed value, against:

\[
\text{current count factor}\times\text{current destination count}.
\]

This bound is reevaluated rather than captured once. Under ordinary nonaliasing execution without external mutation, it is stable; the implementation itself does not enforce that stability.

For each visited index:

1. Read the destination word and multiply it by the initially captured read factor. Form the 32-bit value equal to the negation of that product minus one.
2. Read the source word at the same index and multiply it by the same captured read factor.
3. Add those two 32-bit values, retaining their sum and carry.
4. Add the incoming carry accumulator to the retained sum, again retaining the low 32 bits and a carry.
5. Replace the carry accumulator with the sum of the two carry indicators.
6. Store the low 32 bits of the write factor multiplied by the retained result into the destination word.

Equivalently, if \(a\) and \(b\) are the scaled source and destination word patterns and \(c\) is the incoming accumulator:

\[
t=(-b-1)\bmod M,\qquad s=(t+a)\bmod M,
\]

\[
r=(s+c)\bmod M.
\]

The outgoing accumulator is the carry from \(t+a\), plus the carry from \(s+c\). The stored word is the write-factor-scaled value of \(r\).

The accumulator is therefore a 32-bit quantity computed as a sum of indicators, not a value that this contract assumes is always Boolean.

The destination-side read is expressed before the source-side read, and both precede the destination-word write. Exact ordering among operand reads inside a single expression is not established.

### 3. Process the remaining source extent

The next traversal starts from a freshly computed product of the current count factor and current destination count. It does not simply reuse the first traversal’s ending index.

Its terminal bound is the source-derived bound captured at entry.

At every condition evaluation—including the evaluation that terminates this traversal—the function reloads the read factor and retains that value for subsequent use.

For each visited index:

1. Read and scale the source word using the current read factor.
2. Subtract one from that product to obtain a 32-bit intermediate.
3. Add the incoming carry accumulator.
4. Set the outgoing accumulator to:
   - one if the scaled source product is nonzero, otherwise zero;
   - plus the carry from the addition in step 3.
5. Store the write-factor-scaled result in the destination word.

This traversal does not read the old destination word.

The final carry accumulator is not directly returned or checked after the traversals.

### 4. Replace the destination count and adjust word zero

After both traversals, the destination count is overwritten with the source count captured at entry.

The function then reads destination word zero and multiplies it by the read factor retained from the final condition evaluation of the second traversal.

Two paths follow:

- **Sentinel product:** If the product compares equal to signed negative one, the function calls F-4f8dc40081ad with the destination object.
  - A nonzero dependency result causes immediate return with status one.
  - A zero result continues to the trimming stage.
  - This caller does not perform the alternative low-word adjustment on this path.
- **Other product:** The function writes destination word zero as the write factor multiplied by one plus the scaled word-zero product, then continues.

Thus the special-case comparison concerns the **scaled product**, not necessarily a raw stored word of all one bits.

The destination count has already been changed when the dependency is called. The dependency can therefore observe that count and all preceding word writes.

### 5. Trim high scaled-zero words

Unless the dependency caused an early return, the function scans downward from the captured source-derived terminal bound.

It considers the highest candidate word first, but stops before inspecting index zero. A candidate counts as zero when its product with the retained read factor equals zero. This is not necessarily equivalent to its stored bits being zero.

For a positive terminal bound:

- A nonzero scaled word at the highest candidate retains the full bound.
- High scaled-zero words reduce the retained extent.
- If all inspected words at indices one and above are scaled-zero, the retained extent is one.
- Word zero is not consulted by this trimming scan.

The destination count is then overwritten again:

\[
\text{retained extent}\times\text{current result-count factor}.
\]

For a terminal bound of one or less, no high-word read occurs in this stage, provided the initial decrement itself is valid. The retained extent remains that terminal bound; there is no general clamp to one for zero or negative bounds.

The function returns status zero after this count write.

## Side effects

### Destination mutation

Visible mutations occur in this order:

1. Word writes during the first traversal.
2. Word writes during the second traversal.
3. Destination count replaced by the captured source count.
4. Either a dependency call or a word-zero adjustment.
5. On the continuing path, destination count replaced by the scaled retained extent.

Words above the retained extent are not cleared by the trimming stage. Earlier writes remain in storage even if the final count excludes them.

The status-one path skips both the trimming scan and the final count replacement. It does not roll back any earlier mutation.

### Aliasing and mutable state

No alias checks are visible.

If source and destination words overlap, later reads may observe earlier writes. If word storage overlaps either object header or a global factor, writes may also alter later bounds, addresses, factors, or counts. Such cases cannot be treated as equivalent to independent input snapshots.
