## Behavior

### Leading discriminator

The function first compares the bytes at offset 0.

If they differ, it returns 0. No later field is examined on that path.

If they match, the left leading byte is tested against zero. For stable input storage, matching zero bytes therefore return 1 immediately. All bytes beyond offset 0 are irrelevant to that result.

Matching nonzero leading bytes enter the remaining comparison sequence. The zero test does not apply to any later byte.

### Ordered field comparisons

After the nonzero leading-byte case, the comparison proceeds in this order:

1. The bytes at offset 1.
2. The 32-bit values beginning at offset 4.
3. The 32-bit values beginning at offset 12.
4. The 32-bit values beginning at offset 8.
5. The bytes at offset 16.
6. The bytes at offset 17.
7. The final values derived from the bytes at offset 18.

A mismatch prevents progression to later fields. The integer-sized comparison order is therefore **4, 12, 8**, not increasing address order.

For example, a mismatch in the field beginning at offset 12 prevents examination of the field beginning at offset 8. A mismatch at offset 1 prevents all three integer-sized comparisons.

The function does not read offsets 2 or 3 in the supplied representation. Differences confined to those offsets do not affect its decision, provided all required accesses remain valid.

### Final comparison

After equality through offset 16, the representation forms references to the two bytes at offset 17.

It then:

- Compares the offset-17 bytes.
- If they match, reads both offset-18 bytes and converts each through an integer value to a pointer value.
- Compares the offset-17 bytes again.
- Returns 1 only if that second comparison matches and the pointer-valued quantities being compared are equal.

With stable storage, matching offset-17 bytes cause the final pointer-valued quantities to be derived from offset 18. The converted pointers are compared for equality; they are not dereferenced, returned, stored into the input records, or released.

On a target where the conversion preserves distinctions among all possible promoted character values, this final condition is equivalent to equality of the offset-18 bytes. That equivalence is conditional: the representation uses pointer conversion and pointer equality rather than a direct byte comparison.

With stable storage, an offset-17 mismatch returns 0 without reading offset 18.

### Stable-input acceptance condition

Subject to valid accesses and the conversion qualification above, acceptance occurs when either:

- Both leading bytes are zero; or
- Both leading bytes are equal and nonzero, and all examined fields match.

For the second case, the examined storage consists of offsets 1, 4–15, 16, 17, and 18. Offsets 2 and 3 are excluded.

The three 32-bit comparisons establish equality of the corresponding integer values. Under ordinary 32-bit integer storage, this is equivalent to equality of the four bytes in each field. No byte-order interpretation of a larger aggregate is required.
