# F-4733a63bfc45

## Behavior

### Initial field capture

Before calling either dependency, the function reads four bytes beginning at record byte offset 12 and places that value in temporary storage local to this invocation.

The read is unconditional: it occurs even when F-271eefe0efc5 will subsequently return zero. No visible null check, bounds check, tag check, or validity check precedes it.

The temporary is a copy, not an alias to the original record field. Consequently, a write through the temporary’s address does not by itself write back to the original record location. Aliasing through other addresses or dependency behavior could still affect that record; those possibilities are not resolved by this function.

### First dependency call

F-271eefe0efc5 is invoked with:

1. The object’s interior address at byte offset 84 under the represented layout.
2. The address of the initialized four-byte temporary.

Passing the temporary’s address makes that storage available to the dependency. The supplied function does not declare the dependency’s argument read-only, so the dependency may read or modify it according to its own contract.

After the dependency returns, the function does not inspect the temporary again. A dependency-written value therefore has no visible role in this function’s subsequent branch or return value. This does not make such writes impossible or globally irrelevant: the dependency’s other effects remain unknown.

The dependency’s result is tested against zero. All represented nonzero integer results take the same branch. No distinction is made between positive and negative values.

### Zero-result path

If F-271eefe0efc5 returns zero, the function performs no indirect call and proceeds to its normal return of 1.

On this path, the supplied function does not read the object’s leading dispatch-table reference or the entry at table offset 88. This is a statement about this function’s visible operations, not about accesses F-271eefe0efc5 might perform internally.

### Nonzero-result path

If F-271eefe0efc5 returns nonzero, the function obtains an indirect call target using the object:

- It reads the dispatch-table reference from the beginning of the object.
- It obtains the callable entry at byte offset 88 from that table.
- It invokes that target with the original object address as its first argument and a value obtained from a referenced global storage location as its second argument.

These dispatch accesses occur after F-271eefe0efc5 returns. The function does not visibly capture the dispatch-table reference before that dependency call. Therefore, changes made by the dependency to the object’s dispatch metadata can affect which indirect target is used.

The second indirect-call argument is also supplied from global storage on this branch, after the first dependency returns. Its type, width, meaning, and ownership are not established by the supplied representation. It must not be assumed to be a constant, pointer, message identifier, or resource handle.

The relative order of the global-value read and the dispatch-target reads is not established by the expression alone. Their ordering relative to the earlier dependency call is established: they belong to the subsequent nonzero branch.

The indirect call’s return value is not used. If that call returns normally, the enclosing function returns 1.

## Acceptance examples

These are conditional contract examples, not executed tests.

1. **Zero suppresses dispatch.**  
   Given valid record storage and a first dependency that returns zero normally, the function supplies that dependency with the captured field value through temporary storage, makes no subsequent indirect call, and returns 1.

2. **Any nonzero result enables dispatch.**  
   Given valid dispatch metadata, a first dependency result of either 1 or a represented negative nonzero integer causes the selected indirect call. If that call returns normally, the enclosing function returns 1.

3. **Temporary mutation does not establish writeback.**  
   Given a first dependency that changes only the four-byte temporary through its second argument, the function performs no copy of that changed value back to record offset 12. Its branch still depends on the dependency’s return value.

4. **Post-dependency dispatch state matters.**  
   Given a first dependency that validly replaces the object’s dispatch-table reference and returns nonzero, dispatch uses the reference available after that dependency returns, rather than a reference visibly saved beforehand.

5. **Post-dependency global state matters.**  
   Given a first dependency that changes the referenced global value and returns nonzero, the second call receives the value subsequently read from that global location, assuming no intervening interference.

6. **Callback return does not determine the enclosing return.**  
   Given a selected indirect target that returns normally, different callback return values do not change the enclosing normal return of 1.

7. **An unreadable record field is not bypassed by a later zero result.**  
   The record-field read precedes the first dependency call. A prediction that the dependency would return zero does not eliminate the initial accessibility requirement.
