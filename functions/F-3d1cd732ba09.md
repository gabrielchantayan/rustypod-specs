# F-3d1cd732ba09

## Purpose

F-3d1cd732ba09 conditionally invokes two update operations on an input object. Both operations use values captured from an associated object before either operation is considered. The function returns the first two captured words, packed into a 64-bit result.

Each update has its own selector-and-flag gate. When selected, an update receives the difference between two captured 32-bit words. A nonzero difference additionally causes a call to F-163aa6442bb1; twice that call’s adjustment is added before the update is invoked.

A geometry interpretation—two origins, two endpoints, and two dimensions—is consistent with this structure but remains **inferred intent**. The established contract concerns word values, field offsets, read order, conditions, arithmetic, dependency calls, and result packing. It does not establish coordinate units or identify the updates as particular property setters.

The subtraction and addition operate on 32-bit storage whose signedness is not established. The adjustment is held in explicitly signed 32-bit storage before multiplication by two. These distinctions do not establish executable overflow behavior.

## Interface

### Input and accessible layout

The sole argument is represented as a 32-bit integer used as the address of a **primary object**. This is an address-bearing interface in the supplied representation, not evidence of a portable pointer type.

The function may read these primary-object fields:

| Byte offset | Width | Role |
|---|---:|---|
| `0xA4` | 32 bits | Associated-object address; zero selects an all-zero snapshot |
| `0x68` | 32 bits | Preferred selector for the first update |
| `0x6C` | 32 bits | Flags accompanying that selector |
| `0x50` | 32 bits | Alternative selector for the first update |
| `0x54` | 32 bits | Flags accompanying that selector |
| `0x74` | 32 bits | Preferred selector for the second update |
| `0x78` | 32 bits | Flags accompanying that selector |
| `0x5C` | 32 bits | Alternative selector for the second update |
| `0x60` | 32 bits | Flags accompanying that selector |

When the associated-object address is nonzero, four 32-bit words are read relative to that address:

| Byte offset | Contract label | Use |
|---|---|---|
| `0x98` | First origin word | First subtraction operand; low return word |
| `0x9C` | Second origin word | Second subtraction operand; high return word |
| `0xA0` | First endpoint word | Starting value for the first update |
| `0xA4` | Second endpoint word | Starting value for the second update |

“Origin” and “endpoint” are descriptive labels for operand roles, not established field types. The snapshot and difference storage are width-defined but have no established signedness.

### Result

On normal completion, the function returns a 64-bit concatenation:

- Bits 31–0 are the saved first origin word.
- Bits 63–32 are the saved second origin word.

Packing preserves both 32-bit patterns. It does not sign-extend the first origin into the upper half. This specifies result bit positions, not a memory serialization or byte order.

The returned value does not contain either endpoint, either computed update value, or a dependency status. If the initially read associated-object address is zero, the normal result is zero.

### Preconditions and failure boundary

For normal completion, the primary address and all fields actually read must be accessible. A nonzero associated-object address must permit the four snapshot reads. Short-circuited fields need not be read by this function, although dependencies may have separate access requirements.

There is no explicit primary-address null check and no validation of a nonzero associated address. Alignment, address-arithmetic limits, mapping requirements, and dependency preconditions are **documented_only**.

The function exposes no explicit error result or recovery protocol. Normal completion also requires every invoked dependency to return normally.

## Behavior

### 1. Capture the associated-object values

The first object-field read obtains the associated-object address from primary offset `0xA4`.

If it is zero, all four snapshot words become zero. The function does not attempt any associated-object field read on that path. A missing associated object does not itself disable either update gate.

Otherwise, the function reads the associated object in this order:

1. First origin word at `0x98`.
2. Second origin word at `0x9C`.
3. First endpoint word at `0xA0`.
4. Second endpoint word at `0xA4`.

The associated address is not reloaded for these reads or later phases. The captured origin and endpoint words are not refreshed after dependency calls.

These are ordered individual reads, not an established atomic snapshot. Concurrent changes could affect which combination of values is captured; no synchronization is visible.

### 2. Evaluate the first update gate

The first update is selected if either selector-and-flag pair qualifies:

- The selector at `0x68` equals zero and the flags at `0x6C` contain bit `0x20`.
- The selector at `0x50` equals zero and the flags at `0x54` contain bit `0x20`.

The read order is significant:

- Read the selector at `0x68`.
- Read `0x6C` only if that selector is zero.
- If this pair qualifies, skip both alternative fields.
- Otherwise, read the selector at `0x50`.
- Read `0x54` only if that selector is zero.

The flag condition tests whether the mask result is nonzero. Other flag bits are irrelevant to this gate. A flag word containing additional bits still qualifies when `0x20` is present.

If neither pair qualifies, the function makes no first-phase dependency calls. Even when both pairs would qualify, there is only one first-phase update.

### 3. Perform the first selected update

A selected first phase subtracts the saved first origin word from the saved first endpoint word, with the result held in 32-bit storage.

If that result equals zero:

- F-163aa6442bb1 is not called for this phase.
- F-065fd89ae7c4 is called with the primary-object address and a zero second argument.

If the result is nonzero:

- F-163aa6442bb1 is called with the primary-object address.
- Its returned adjustment is held in explicitly signed 32-bit storage.
- That adjustment is multiplied by two.
- The product is added to the difference, with the updated value held in 32-bit storage.
- F-065fd89ae7c4 is called with the primary-object address and the resulting value.

The adjustment decision uses the difference **before** adjustment. There is no subsequent positivity check or final-zero check. If adjustment produces zero under the applicable arithmetic behavior, the update still occurs.

### 4. Evaluate and perform the second update

Only after the first phase and its invoked dependencies return does the function evaluate the second gate.

The second update is selected if either of these pairs qualifies:

- Selector `0x74` equals zero and flags `0x78` contain bit `0x20`.
- Selector `0x5C` equals zero and flags `0x60` contain bit `0x20`.

The ordered, short-circuited reads are `0x74`, conditionally `0x78`, then—only if the preferred pair fails—`0x5C`, conditionally `0x60`.

A selected second phase subtracts the saved second origin word from the saved second endpoint word. A zero result is passed directly to F-d25031d00f00. A nonzero result causes a fresh call to F-163aa6442bb1, multiplication of its signed 32-bit adjustment by two, and addition to the difference before invoking F-d25031d00f00.

Both dependencies receive the primary-object address as their first argument. The adjustment from the first phase is never reused.

The second gate reads current primary-object fields, not values captured before the first phase. First-phase dependency effects can therefore change whether the second update runs. In contrast, second-phase arithmetic continues to use the initially captured second origin and endpoint.

### 5. Return the saved origin words

After both phases complete normally, the function packs the two saved origin words into the result.

Changes to object fields during dependencies do not cause a new read for return construction. This does not imply that dependencies preserve object or global state; the return simply uses the saved words.

### Arithmetic boundaries

The evidence establishes 32-bit snapshot storage, difference storage, and adjusted-value storage. It does **not** establish signed subtraction or signed addition for those values.

The adjustment temporary is explicitly signed and 32 bits wide. Its multiplication by two is represented as signed-integer multiplication. That fact does not determine the signedness of the surrounding subtraction or addition, nor the executable’s behavior when an intermediate exceeds a representable range.

No explicit widening to 64 bits, saturation, bounds check, or overflow branch appears in the arithmetic path. Consequently:

- Ordinary nonnegative examples whose differences, doubled adjustments, and sums fit signed 32-bit range can be described without choosing between signed and unsigned interpretations.
- High-bit-set operands require care: their signed numerical interpretation is not established merely by their storage width.
- Wrapping, trapping, or another overflow consequence must not be asserted from this evidence.
- Negative adjustments are representable in the signed adjustment temporary, but this alone does not define mixed-operand addition semantics.

Overflow and out-of-range arithmetic behavior remain **documented_only**.

Dependencies may write object or global state, allocate or release resources, retain addresses, or have other externally visible effects. None of those behaviors is established or excluded here.

When both phases are selected and both differences are nonzero, the dependency order is:

1. F-163aa6442bb1 for the first update.
2. F-065fd89ae7c4.
3. F-163aa6442bb1 for the second update.

These are conditional examples derived from static evidence, not executed tests. They assume valid required accesses and normal dependency returns. Unless otherwise stated, arithmetic values are nonnegative and all intermediate mathematical results fit signed 32-bit range.

### Short-circuit reads

The selector at `0x68` is zero and flags `0x6C` contain `0x20`.

The first gate does not read `0x50` or `0x54`. If instead the selector at `0x68` were nonzero, it would skip reading `0x6C` and proceed to the alternative selector.

Flags equal to `0x60` qualify when paired with a zero selector; flags equal to `0x40` do not.

### Mutation between phases

A first-phase dependency changes the second-phase gate fields.

The second phase evaluates those later field values. If a dependency also changes the associated-object endpoint fields, those changes do not replace the saved operands used by this invocation.

This example assumes the dependency leaves subsequent required accesses valid; its ability to do so is not guaranteed here.

### Return words with high bits set

Both gates fail. The saved first origin pattern is `0xFFFFFFFF`, and the saved second origin pattern is `0x80000000`.

The result is `0x80000000FFFFFFFF`. No signed interpretation of either word is needed for this packing example.

### Nonzero difference adjusted to zero

Conditionally, if a nonzero difference and the adjustment produce a final 32-bit value of zero under the applicable arithmetic behavior, both the adjustment call and the selected update call occur.

This is a control-flow guarantee, not a specification of unresolved signedness or overflow behavior.
