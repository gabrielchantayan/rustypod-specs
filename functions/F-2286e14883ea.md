# F-2286e14883ea

## Purpose

F-2286e14883ea conditionally performs drawing-like operations for an object and its associated content. It prepares a temporary context, obtains geometry, and evaluates a gate. If processing continues, it submits a narrow rectangle and passes the object’s stored rectangle to a dependency. Associated content can trigger a secondary rectangle, additional dependency calls, and four explicit object-field writes.

A scrollbar-like purpose is **inferred intent**, based on orientation-sensitive geometry, relative extents, and proportional sizing. Rendering semantics are not established. The contract below describes observable accesses, arithmetic, calls, and state changes without assigning undocumented meanings to dependencies.

The function returns no value. Its results are dependency effects, conditional stored-rectangle updates, and an indirect callback on qualifying paths.

## Interface

### Object argument

The sole argument is an object address. The supplied representation uses 32-bit integer words and 32-bit address-bearing fields. No argument validation or explicit error result is visible.

| Object byte offset | Width | Established use |
|---|---:|---|
| `0x000` | 32 bits | Address of the table containing the final callback. |
| `0x048` | 32 bits | Flags; bit `0x02000000` enables proportional sizing. |
| `0x0B4` | 32 bits | Associated-content address, reloaded at distinct stages. |
| `0x0C0` | 32 bits | Zero/nonzero selector between two opaque global values. |
| `0x0D0` | 32 bits | Active-axis start when orientation is not 1. |
| `0x0D4` | 32 bits | Active-axis start when orientation is 1. |

Only orientation value 1 selects the alternate axis. The word-to-character reads and the later byte read are separate accesses; their equivalence depends on representation and intervening mutation.

Associated content is directly read at byte offsets `0x80`, `0x84`, `0x88`, and `0x8C`, each as a 32-bit component.

### Temporary records and global values

The function supplies dependencies with a 68-byte temporary context. Its internal layout is unknown.

Geometry records contain four consecutive 32-bit components, designated:

1. First-axis start.
2. Second-axis start.
3. First-axis end.
4. Second-axis end.

These labels identify component pairing, not coordinate units or endpoint inclusion. Distinct records hold initial geometry, track geometry, helper-produced content geometry, directly read content geometry, secondary geometry, and a transformed secondary copy.

Three distinct global locations provide opaque 32-bit values, designated **A**, **B**, and **C**. They are loaded values, not established constants. Separate loads from one location are not guaranteed to agree.

### Preconditions and ownership

Normal completion requires every reached object field, content field, callback-table entry, and temporary-record access to be valid for its use. Passing an initial content null check does not guarantee that later content-address reloads remain nonzero.

The function directly allocates or releases no memory. Dependency ownership, pointer retention, resource acquisition, resource release, and mutation guarantees are unknown. In particular, passing a temporary record’s address does not establish that the dependency stops using that address upon return.

## Behavior

### Context preparation and gate

The initial call order is:

1. F-a4c26c2b4842 receives the temporary context.
2. F-7fa874cbac7a receives the object and context.
3. F-960363c07b32 receives the object and an initial-geometry output address.
4. F-2adbf0d1a289 receives the object and returns a zero/nonzero gate result.

A zero gate result leads directly to F-282eebd7c413 on the context, followed by return. Track processing, stored-rectangle processing, content checking, and the callback do not occur.

Initial geometry acquisition therefore occurs even when the gate rejects further processing.

### Track construction

After a nonzero gate result, the function samples flag bit `0x02000000` at object offset `0x048`. This retained Boolean controls later proportional sizing; the flag is not refreshed.

The initial geometry’s then-current four components are copied into a separate track record. F-e84807520bd9 receives that writable record and numeric arguments 1 and 1. Its transformation is unknown.

The function next reads orientation through word-to-character conversion:

- **Orientation 1:** The track’s second-axis start and end receive object fields `0x0D4` and `0x1A0`. The midpoint of the transformed first-axis endpoints is calculated using signed addition followed by signed division by 2. The first-axis start becomes midpoint minus 1, then the first-axis end becomes midpoint plus 2.
- **Other orientations:** The track’s first-axis start and end receive fields `0x0D0` and `0x19C`. The midpoint of the transformed second-axis endpoints is calculated similarly. The second-axis start becomes midpoint minus 1, then the second-axis end becomes midpoint plus 2.

For representable signed arithmetic, division truncates toward zero. The resulting narrow-axis endpoint difference is 3; a three-pixel rendered width is not established.

The subsequent order is:

1. Load A.
2. Call F-d06d54bfd78a with the context and that loaded value.
3. Call F-a7cb9e140c0e with the context and writable track-record address.
4. Call F-ca73cb512206 with the stored-rectangle address at object offset `0x274`.

The track record’s address has escaped. Its later components are not guaranteed to match those originally submitted.

F-ca73cb512206 is not established to clear, reset, invalidate, or preserve the stored rectangle.

### Content acquisition and in-place geometry normalization

The function reads the content address at `0x0B4`. If zero, it finalizes the context through F-282eebd7c413 and returns. Track submission and F-ca73cb512206 have already occurred; the callback does not occur.

After a nonzero initial content check:

1. Load B.
2. Read the selector at `0x0C0`.
3. If the selector is nonzero, load C and replace the selected value with C.
4. Call F-d06d54bfd78a with the context and selected value.
5. Reload the content address at `0x0B4`.
6. Call F-756b664b4a2c with that address and a writable helper-geometry output record.
7. Reload the content address at `0x0B4` again.
8. Read four words from this last address at offsets `0x80`, `0x84`, `0x88`, and `0x8C`, in ascending offset order.

B is loaded even when C replaces it. There is no new null check before the geometry call or direct reads. The helper-call argument and the later direct-read address need not identify the content that passed the initial check, or even the same content as each other.

The function then performs another word-to-character orientation read.

**If this read equals 1, the helper-produced geometry record is modified in place:**

1. Its first component is overwritten with its second component.
2. Its third component is overwritten with its fourth component.
3. Only afterward is the reference extent calculated from the resulting third component minus the resulting first component.

The second and fourth components are not explicitly overwritten in this step. These are actual writes to the same record whose address was supplied to F-756b664b4a2c, not merely a choice of operands. No dependency call intervenes between the two writes. A later dependency could observe the modified record through a retained address; retention and observation remain unknown.

For orientation 1, the direct extent uses the directly read fourth component minus the second component. For other orientations, the helper record receives neither normalization write, the reference extent uses its third component minus its first component, and the direct extent uses the directly read third component minus the first component.

The reference extent is calculated before the direct extent. Both are signed 32-bit arithmetic results used in signed comparisons. Neither must be positive.

### Secondary eligibility and sizing

Secondary processing occurs when the direct extent is signed-less-than the reference extent, or the previously sampled proportional flag is set. Otherwise, processing proceeds to the callback without secondary drawing or the four explicit stored-rectangle writes.

On entry to secondary processing, the initial geometry’s then-current components are copied into a separate secondary record. The function then reads one byte at `0x26C` and retains it for this branch.

Byte value 1 selects start/end fields `0x0D4` and `0x1A0`; other values select `0x0D0` and `0x19C`. The start is read before the end.

With proportional sizing disabled, the selected end becomes start plus 5. The threshold is not read, and no span cap is applied.

With proportional sizing enabled:

- The selected end-minus-start difference is computed and stored as an unsigned 32-bit **available span**.
- If the reference extent is less than 1, the candidate is zero and F-870c4fcf7295 is skipped.
- If the reference extent is positive, F-870c4fcf7295 receives the product-derived first operand and the reference extent as its second operand.

For the multiplication, the direct extent is converted to unsigned 32-bit because the available span is unsigned. The first argument contains the low 32 bits of their unsigned product. Negative direct extents therefore contribute their unsigned representations.

F-870c4fcf7295’s returned bits become the candidate. Its internal division, rounding, signedness, and error behavior are unknown.

The threshold at `0x2AC` is read after candidate selection or the arithmetic-helper call:

- If the candidate interpreted as signed 32-bit is below the signed threshold, the end becomes start plus 5.
- Otherwise, if the available span interpreted as signed 32-bit is below the candidate interpreted as signed 32-bit, the candidate is replaced by the available-span bits.
- The end then becomes start plus candidate.

The cap comparison is signed despite unsigned storage. The candidate-based addition is unsigned 32-bit addition, retaining its low 32 bits. The five-unit fallback is not the threshold and is not capped afterward.

The subtraction producing the available span is a signed expression before unsigned storage. That storage does not resolve overflow in the preceding subtraction.

### Position, drawing, and stored rectangle

The previously calculated extents determine displacement:

- Equal extents select zero without calling F-d7be9cfb4000.
- Unequal extents cause F-d7be9cfb4000 to be called without explicit arguments; its return supplies displacement.

The displacement source is unknown. The extents are not recalculated after intervening dependencies.

Using the retained orientation byte, the secondary rectangle receives:

- Active-axis endpoints equal to the selected start and end, each shifted by displacement.
- Perpendicular endpoints taken from the track record’s then-current corresponding components, expanded outward by 1.

For orientation 1, component writes occur in first, second, third, fourth order. Otherwise, they occur in second, fourth, first, third order.

The subsequent sequence is:

1. Load B again.
2. Call F-d06d54bfd78a with the context and this loaded value.
3. Call F-a7cb9e140c0e with the context and writable secondary-record address.
4. Copy the secondary record’s then-current four components into distinct temporary storage.
5. Call F-e84807520bd9 on that copy with arguments 1 and 1.
6. Load A again.
7. Call F-ccb5d9751852 with the context and this loaded value.
8. Call F-823eeffc4aa6 with the context and transformed-copy address.
9. Read and store the secondary record’s components to object offsets `0x274`, `0x278`, `0x27C`, and `0x280`, respectively, in that order.

The final transformation directly targets the distinct copy, not the secondary record. However, dependencies can mutate records through supplied or retained addresses. The copied values and final stored values are therefore not guaranteed to equal the originally constructed rectangle.

### Callback and finalization

Every normally continuing path with a nonzero gate and successful initial content check reaches the indirect callback, whether or not secondary processing occurs.

The function reads the table address from object offset `0x000`, obtains the callable entry at table byte offset `0x138`, and invokes it with the object and context. Its return value is unused.

F-282eebd7c413 then receives the context. Every visible normal exit performs this finalization call; exceptional cleanup is not established.

## Side effects

Direct writes include temporary-record construction, the conditional in-place helper-geometry normalization, and the four conditional stored-rectangle stores. Dependencies may perform additional writes.

Significant ordering constraints include:

- Initial geometry acquisition precedes the gate.
- Track submission precedes stored-rectangle processing and the content check.
- B is loaded before the selector, even when C replaces it.
- Content addresses are reloaded after both relevant dependencies.
- All four direct content-component reads precede the second word-to-character orientation read.
- For orientation 1, helper-record first-component replacement precedes third-component replacement; both precede reference-extent calculation.
- Secondary copying follows its writable submission call.
- The later A load follows transformed-copy processing.
- Explicit stored-component reads occur after the remaining secondary dependencies.

A is loaded for track processing and again during secondary processing. B is loaded after the successful content check and again before secondary submission. C is loaded only for a nonzero selector. Dependencies are not established to preserve these global locations.

The function mixes retained values with later reads. The proportional flag, calculated extents, branch-local orientation byte, and selected active-axis coordinates are retained. Other accesses occur later. An immutable entry-snapshot interpretation would change behavior.

There is no explicit retry, rollback, validation error, or failure result. Partial dependency effects and state changes can precede an invalid access or dependency failure.

## Acceptance examples

These are conditional criteria, not executed tests. Arithmetic examples assume accessible memory, normal dependency returns, representable signed arithmetic, and stable relevant values unless mutation is specified.

1. **Rejected gate.** Context preparation and initial geometry acquisition occur before a zero gate result. Finalization follows without track submission, content checking, or callback.

2. **Absent content.** A nonzero gate followed by an initially zero content address still permits track submission and F-ca73cb512206 first. Content geometry, callback, and explicit four-word rectangle storage are skipped.

3. **Content changes after checking.** If F-d06d54bfd78a changes the content field to zero after the initial check, F-756b664b4a2c receives zero from the reload. No intervening rejection occurs.

4. **Global selection.** With a nonzero selector, B is read before the selector, C afterward, and the selected C value is passed to F-d06d54bfd78a.

5. **In-place alternate-axis normalization.** Suppose the helper record is `(10, 20, 70, 120)` and the subsequent word-to-character orientation read equals 1. After direct content reads, the first component becomes 20, then the third becomes 120. The record is now `(20, 20, 120, 120)`, and the reference extent is 100. A later dependency retaining that address can observe this normalized record if no intervening mutation changes it.

6. **No normalization for other orientations.** With that same helper record and orientation 0, neither component replacement occurs. The reference extent is 60.

7. **Equal extents without proportional sizing.** Reference and direct extents of 100 skip secondary processing. Callback and finalization still occur.

8. **Fixed length.** Reference extent 100, direct extent 40, proportional sizing disabled, and selected start 10 produce end 15 before displacement. Threshold and available span do not alter this length.

9. **Unsigned product boundary.** With proportional sizing enabled, reference extent 2, direct extent −1, and available span 2, F-870c4fcf7295 receives first-operand bits `0xFFFFFFFE`. Its return is not inferred.

10. **Threshold and cap.** Candidate 20, span 80, and threshold 10 select length 20. Threshold 30 instead selects length 5. Candidate 120 with threshold 10 selects span 80 through the signed cap. A fallback length 5 remains 5 even when the span is 3.

11. **Nonpositive reference extent.** With proportional sizing enabled and reference extent zero, the arithmetic helper is skipped. Candidate zero is compared with the threshold; a positive threshold selects the five-unit fallback.

12. **Equal extents with proportional sizing.** The flag forces secondary processing. Displacement is zero, and F-d7be9cfb4000 is skipped.

13. **Mutation and distinct copies.** A secondary-component change made by F-a7cb9e140c0e is observed by the subsequent copy. If later dependencies preserve the secondary record, that changed value is stored. Transforming only the distinct copy does not itself alter the secondary record, but retained-address mutation remains possible.
