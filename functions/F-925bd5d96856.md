# F-925bd5d96856

## Purpose

F-925bd5d96856 performs an ordered series of direct memory updates using one explicit 32-bit argument and three additional incoming machine-state values. It then invokes an unresolved indirect target with four arguments.

The established behavior is memory manipulation and indirect dispatch. The supplied material does not establish a higher-level purpose, object model, application protocol, or valid calling context. In particular, the repeated writes do not establish array initialization: their destination addresses do not advance.

This contract describes the visible static operations, conditional on the supplied representation accurately describing executable behavior. It does not certify that the representation is complete or that the function can execute successfully for arbitrary inputs.

## Interface

### Inputs

The visible interface contains one explicit argument:

- **Argument value:** a 32-bit integer. Its bit pattern is written to memory and is also used as an address base for a four-byte read at offset `0x74`.

Three additional incoming values are used without visible initialization. For this contract, they are named:

- **Primary base:** a 32-bit value represented as unsigned. It participates in address calculations, byte truncations, doubling, and a shift-count calculation.
- **Secondary base:** a 32-bit value used as an address base and as a source of low-byte data.
- **Tertiary base:** a 32-bit value used as an address base and stored as a four-byte value.

These are contract labels, not additional parameters established by the visible interface. Their origin, calling convention, and required relationship to the explicit argument are unknown.

## Behavior

### Repeated publication prefix

The function begins with a finite, visibly repeated sequence of four writes. Each repetition has the same destinations and data:

| Position within each repetition | Width | Destination | Stored value |
|---|---:|---|---|
| First | 4 bytes | Twice the primary base, plus `0x54` | Argument value |
| Second | 1 byte | Secondary base plus `0x19` | Low byte of primary base |
| Third | 1 byte | Primary base plus `0x11` | Low byte of secondary base |
| Fourth | 4 bytes | Secondary base plus `0x34` | Twice the primary base |

The doubling of the unsigned primary value is 32-bit modular arithmetic. Its high bit may be discarded; no overflow rejection is visible.

There is no address progression, intervening memory read, call, or condition in this repeated prefix. It must not be characterized as writing successive records. Repeated stores may matter for device memory, tracing, faults, or overlapping destinations even when ordinary memory ends with the same bytes after every complete repetition.

The exact number of repetitions is not independently enumerated in this contract. It is not a variable count controlled by an input in the visible representation.

### Initial captures and fixed-address updates

After the repeated prefix, the function captures a four-byte value from fixed address `0xA9`, then captures a four-byte value from the argument address plus `0x74`.

It next writes a byte at fixed address `0x3A`. The byte is the low eight bits of twice the primary base’s low byte plus `0x30`. This arithmetic is not evidence of decimal conversion or a printable-character guarantee.

Only after that fixed-address write does the function capture:

1. The word at tertiary base plus `0x14`.
2. The word at primary base plus `0x04`.

These captured words retain the values read at those points, even if subsequent writes alter their source locations.

The following updates then occur in order:

- The low byte of the primary base is written at tertiary base plus `0x0D`.
- Byte `0x6C` is written at primary base plus `0x08`.
- The secondary base’s low byte is written at primary base plus `0x0D`, then at primary base plus `0x09`.
- The tertiary base is written as a word at tertiary base plus `0x54`.
- The low byte of the previously captured fixed-address word is written at fixed address `0x67`.

The function then reads the word at tertiary base plus `0x44`. This becomes the **captured control word**.

Next, it reads the byte currently at fixed address `0x67` and writes that byte at fixed address `0x21`. This is a read of the then-current storage, not a guarantee that the byte still equals the earlier captured word’s low byte.

### Primary and secondary state updates

The captured control word supplies three related updates, in this order:

- Its low byte is written at primary base plus `0x10`.
- The full word is written at secondary base plus `0x54`.
- A shifted form supplies a byte written at tertiary base plus `0x01`.

For the third update, the visible operation is a signed right shift of the captured control word, with the count taken from the low eight bits of the primary base. The byte result and exceptional shift cases require target-specific interpretation; see **Uncertainties**.

The word at secondary base plus `0x54` is then overwritten with the primary base itself. Thus the captured control word’s earlier word store is transient, but is still part of the visible access sequence.

After that overwrite, the function reads the word at primary base plus `0x40`. It subsequently:

- Writes the earlier capture from primary base plus `0x04` to secondary base plus `0x74`.
- Writes the newly read word from primary base plus `0x40` at primary base plus `0x10`.
- Writes the tertiary base at secondary base plus `0x44`.
- Reads the current byte at fixed address `0x67` and writes it at primary base plus `0x09`.
- Writes the primary base’s low byte at tertiary base plus `0x09`.
- Writes the original four-byte capture from fixed address `0xA9` at primary base plus `0x44`.

The four-byte write at primary base plus `0x10` covers offsets `0x10` through `0x13`. It therefore overwrites the earlier byte at offset `0x10` and the prefix’s byte at offset `0x11`, unless other aliasing changes the relevant observations.

Next, the word at primary base plus `0x54` is read and retained as the **linked base**. The current byte at fixed address `0x67` is again read and written at primary base plus `0x09`. This repeated byte update is not safely replaceable by reuse of an earlier read when aliasing or external mutation is possible.

The low byte of the earlier argument-relative capture is written at linked base plus `0x0D`. The saved word originally read from tertiary base plus `0x14` is then written at tertiary base plus `0x54`.

Only after these writes does the function read the word at primary base plus `0x14`, retaining it as the **linked-byte source**.

It then writes:

- The argument-relative capture’s low byte at tertiary base plus `0x11`.
- The linked base’s low byte at primary base plus `0x09`.
- The full linked base at primary base plus `0x44`.

These operations replace some earlier values, but do not erase their access history.

### Linked writes and indirect dispatch

The function reads the word at tertiary base plus `0x04`, retaining it as the **node base**.

At twice the node base it writes the two-byte value `0x0065`. It then reads the word at node base plus `0x64`, retaining that word as the **dispatch value**.

The following operations intervene before the remaining reads:

- The low byte of the linked-byte source is written at linked base plus `0x11`.
- The four-byte value `100`, equivalently `0x00000064`, is written at linked base plus `0x54`.

The function next reads the word at node base plus `0x74`, retaining it as the **dispatch payload**, then reads the word at tertiary base plus `0x64`, retaining it as the **destination base**.

The final direct writes are ordered as follows:

1. The node base’s low byte is written at tertiary base plus `0x09`.
2. The dispatch value is written as a word at destination base plus `0x54`.
3. The destination base is written as a word at twice the dispatch value.

The unresolved indirect target is then invoked with these four visible argument values, in order:

| Argument position | Value |
|---|---|
| First | `0x72`, decimal 114 |
| Second | Dispatch value |
| Third | Saved word originally read from tertiary base plus `0x14` |
| Fourth | Dispatch payload read from node base plus `0x74` |

The target address, its acquisition, and its valid range are not established. No direct memory update after the invocation is visible. Return from F-925bd5d96856 is conditional on the target returning normally.

## Acceptance examples

These examples are conditional static expectations, not executed tests.

### Ordinary disjoint writable memory

Assume all accesses are valid, all relevant regions are disjoint except for explicitly shared offsets, there is no external mutation, and F-UNRESOLVED returns without modifying them.

Under those conditions:

- Each prefix repetition uses the same four destinations.
- Secondary base plus `0x34` receives twice the primary base modulo \(2^{32}\).
- Secondary base plus `0x54` first receives the captured control word and later receives the primary base.
- Tertiary base plus `0x54` first receives the tertiary base and later receives the saved word from offset `0x14`.
- Primary base plus `0x44` first receives the fixed-address capture and later receives the linked base.
- Primary base plus `0x09` ultimately receives the linked base’s low byte before dispatch.
- F-UNRESOLVED receives `114`, the dispatch value, the saved tertiary-relative word, and the dispatch payload.

These are pre-dispatch results unless the stated callee assumption also holds.

### Byte truncation

If the primary base’s low byte is `0xF0`, the fixed-address byte calculation produces `0x10` at address `0x3A`, assuming execution reaches that write successfully. It does not produce a two-byte result and does not reject the value as nonnumeric.

### Unsigned doubling

If the primary base is `0x80000020`, its doubled 32-bit value is `0x00000040`. Consequently, the prefix’s first destination is address `0x00000094`, and its fourth stored word is `0x00000040`, conditional on valid addressing.

This example establishes modular arithmetic, not the validity of those addresses.

### Overwritten stores remain observable

A memory trace that omits the captured-control-word store at secondary base plus `0x54` merely because the primary base overwrites it later does not preserve the visible access sequence.

Similarly, the word write at primary base plus `0x10` cannot be treated as leaving the preceding byte writes within that word intact.

### Aliasing and failures

If a direct destination overlaps a later read location, the later read must reflect the applicable intervening memory effects rather than an assumed entry-time snapshot.

If the argument-relative read is invalid, the repeated prefix precedes that failure. An all-or-nothing interpretation is unsupported.

For a shift count of 32 or greater, this contract supplies no portable expected result. Such a case requires target-specific evidence.
