# F-2b0887df26a7

## Purpose

F-2b0887df26a7 traverses a zero-terminated sequence of 16-bit units, identifies nonempty spans separated by the unit value 0x0020, and delegates each span to F-159eff45b707. It accumulates the dependency’s results, with two exceptions:

- A dependency result of zero terminates processing immediately and makes the whole invocation return zero, discarding any accumulated result.
- A dependency result of exactly 1000 for the first span is replaced by the value read from a global location before accumulation.

Only 0x0020 is a separator. The visible behavior does not establish general whitespace handling, character decoding, numeric parsing, or any particular meaning for the accumulated result.

This contract describes the supplied static representation. No runtime tests have been performed.

## Interface

### Inputs

The function receives four arguments:

| Position | Representation | Established use |
|---|---|---|
| 1 | Opaque 32-bit value | Forwarded unchanged in dependency argument positions 1 and 5. |
| 2 | Opaque 32-bit value | Forwarded unchanged in dependency argument positions 2 and 6. |
| 3 | Pointer to 16-bit units | Supplies the sequence to scan. Its original address is also forwarded to every dependency invocation. |
| 4 | Opaque 32-bit value | Forwarded unchanged in dependency argument position 8. |

The first, second, and fourth arguments are not visibly interpreted or dereferenced by this function. They may encode pointers or other values, but their meanings are unknown.

The third argument must identify readable storage containing a reachable zero-valued 16-bit terminator for ordinary completion without a dependency-directed early return. There is no explicit length, bounds check, null-pointer check, or recovery path for invalid storage.

The supplied representation uses a signed 16-bit element type. Sign does not affect classification here: zero terminates the sequence, 0x0020 separates spans, and every other representable unit belongs to a span. Values with their high bit set are not excluded.

### Output

The function returns a signed integer represented as 32 bits in the supplied interface. Its result is either:

- Zero because a dependency invocation returned zero;
- Zero because there were no spans;
- Or the accumulated contributions from all processed spans, subject to the arithmetic uncertainty described below.

Zero does not uniquely identify failure. A successfully completed traversal can also produce zero through substitution or arithmetic cancellation.

### Dependency call layout

For each nonempty span, F-159eff45b707 receives eight arguments in this order:

| Position | Value |
|---|---|
| 1 | Original first input |
| 2 | Original second input |
| 3 | Address of the span’s first 16-bit unit |
| 4 | Span length, counted in 16-bit units |
| 5 | Original first input again |
| 6 | Original second input again |
| 7 | Original sequence address, not the current span address |
| 8 | Original fourth input |

The span length is represented by a signed integer of the same apparent 32-bit width as the result and accumulator. It is a unit count, not a byte count.

## Behavior

### Sequence classification

The function recognizes exactly two distinguished unit values:

- **0x0000:** end of sequence.
- **0x0020:** separator.

All other units are span content. Tabs, line feeds, carriage returns, nonbreaking spaces, and other whitespace-like values are not separators unless their actual stored unit is 0x0020.

Leading separators are skipped. Consecutive separators do not produce empty dependency calls. Trailing separators are scanned, but do not produce a dependency call or contribute to the result.

The function does not decode multibyte or multi-unit character encodings. In particular, the supplied evidence does not establish Unicode validation or surrogate-pair handling. A span length measures stored 16-bit units regardless of their interpretation.

### Traversal and call ordering

The accumulator begins at zero. The initial scan position is the original sequence address.

Before processing a scan position, the function reads the unit there. A zero at that position causes immediate return of the current accumulator.

For a nonzero position, the function skips consecutive 0x0020 units, stopping at either a nonseparator or the terminator. It then measures the following run of nonzero, nonseparator units. That measurement determines both the span boundary and the length passed to F-159eff45b707.

The dependency is called only if this measured length is nonzero. Calls occur in left-to-right span order. The function finishes handling one dependency result before scanning for the next span.

The scan position retained across a dependency invocation is the address where measurement stopped: the separator or terminator following the measured span. The function does not move that position past the boundary before making the call.

Consequently, a span is not terminated or copied for the dependency. Its following separator remains in the input, and the dependency must use the supplied length if it requires an exact span boundary.

### Dependency result handling

A dependency result of zero has priority over every other result rule:

- Processing stops immediately.
- No further span is scanned or delegated.
- The accumulated value is not returned.
- The global replacement value is not read for that result.

For a nonzero dependency result, the function determines whether the first-span replacement applies. If it does not apply, the result itself is added to the accumulator.

No other visible result value is treated as an error. Negative dependency results are added just as positive ones are, provided the resulting arithmetic is representable.

### First-span replacement

A flag is initially enabled and is cleared after the first nonterminal traversal cycle. In an ordinary, unmodified sequence containing at least one span, that cycle processes the first span, even if it follows leading separators.

If the dependency returns exactly 1000 while the flag remains enabled, the function reads a global replacement value and uses it as that span’s contribution.

Important consequences:

- Leading separators do not prevent replacement on the first span.
- A result of 1000 for any later span contributes 1000 directly.
- The replacement value is read after the dependency returns, not at function entry.
- If the replacement value is zero, zero is accumulated; this does not trigger the dependency-zero early return.
- If the replacement value is negative, it is added as a negative contribution.
- The function does not visibly cache the global before the dependency call.

An input consisting only of separators reaches the terminator without a dependency call and returns zero. The flag’s subsequent state has no effect on that ordinary case.

### Arithmetic and limits

Span lengths start at zero and increase by one for each included 16-bit unit. Contributions are added to an initially zero signed accumulator.

The supplied representation uses signed integer arithmetic, but it does not establish the overflow behavior of the original executable or a replacement implementation. This contract therefore does not promise wrapping, saturation, trapping, or rejection when a span length or accumulated sum exceeds the signed 32-bit range.

For behavior established without an overflow assumption:

- Every measured span length must fit in a signed 32-bit integer.
- Every accumulated sum must remain between −2,147,483,648 and 2,147,483,647.
- The global replacement must have a well-defined conversion to the contribution type.

Pointer traversal must also remain within valid readable storage. There is no visible mechanism for detecting an unterminated or excessively long sequence safely.

## Side effects

### Direct effects

The function directly reads:

- The input’s 16-bit units during classification and measurement;
- The global replacement location, but only for a first-span dependency result of exactly 1000.

It does not visibly write into the input, replace separators with terminators, allocate a span buffer, allocate other memory, or release memory.

Its accumulator, scan positions, length, and first-cycle flag are internal state.

### Indirect effects and ownership

F-159eff45b707 receives addresses into the caller’s storage, including both the current span address and the original sequence address. Any effects performed by that dependency remain observable even if a later dependency result causes this function to return zero. There is no rollback.

No ownership transfer or retention policy is established by the visible caller. In particular, this contract does not assume that the dependency:

- Leaves the sequence unchanged;
- Leaves globals unchanged;
- Avoids retaining the supplied addresses;
- Allocates or frees memory;
- Preserves storage reachable through the opaque arguments.

The caller itself performs no visible cleanup after dependency calls.

### Read ordering and mutable input

Scanning reads a unit to test for termination before testing it for separator membership. Some positions are read repeatedly, including across phase boundaries. The visible access pattern is not a one-read snapshot of the sequence.

The dependency receives a span address and a length calculated before its invocation. After it returns, traversal resumes using the saved boundary address, whose contents are read again. Therefore:

- A dependency change to the global replacement location can affect first-span replacement.
- A change at the saved boundary can alter whether traversal terminates, skips separators, or begins another span.
- A terminator observed during measurement is not irrevocably accepted before the dependency returns.
- Previously scanned span content is not generally rescanned merely because the dependency changes it.

These observations establish sensitivity to mutation, not a concurrency or synchronization guarantee. Unsynchronized concurrent changes, volatile-device semantics, and storage invalidation are not defined by the supplied evidence.
