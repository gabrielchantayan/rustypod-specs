# F-15b9a69ca099

## Purpose

F-15b9a69ca099 performs two 16-bit memory reads, selects a sequence of memory writes according to whether its second explicit input is zero, and returns its fifth explicit input unchanged as a 64-bit value.

The zero-input path is not a conventional null-pointer guard: the function attempts a read at an address derived from the second input **before** checking that input for zero. Consequently, the zero-input path can execute only if that earlier read and the other prerequisite accesses complete.

The available static evidence establishes address calculations, data widths for the explicitly typed memory accesses, and branch-dependent write order. It does not establish the application-level purpose of the affected storage.

## Behavior

### Initial reads

Before evaluating the branch condition, the function performs these reads in the displayed order:

1. It reads 16 bits from the second input’s address plus 4 bytes.
2. It reads 16 bits from base state plus 40 bytes.

Both reads are unsigned. Each resulting value therefore lies between 0 and 65,535 inclusive.

The second read is widened to a 32-bit unsigned value. That widened value becomes the data for the primary write on the nonzero-input path and the secondary write on the zero-input path.

The first read is performed even when the second input is nonzero and its value will not subsequently contribute to a write. An implementation that removes this read would not preserve the access behavior shown by the supplied representation, particularly where an access can fault or has externally visible effects.

This ordering is the order established by the supplied body. It is not independent proof of instruction-level ordering, volatile semantics, or ordering guarantees against other execution agents.

### Nonzero second input

If the second explicit input is not zero, the function:

- Writes the zero-extended value from the base-relative halfword as a 32-bit word at base state plus 48 bytes.
- Returns the fifth explicit input.

No assignments to global slots A through E are shown on this path. The input-relative halfword has nevertheless already been read.

The primary write stores a full 32-bit value. It is not a 16-bit update preserving the destination’s other two bytes.

### Zero second input

If the second explicit input is zero, both initial reads must already have completed. Under ordinary flat byte-address interpretation, the first read was therefore attempted at address 4.

The function then performs the following storage operations in the displayed order:

1. Assigns base state minus 5 to global slot A.
2. Reads global slot A’s value and assigns that value multiplied by 256 to global slot B.
3. Writes the zero-extended value from the base-relative halfword as a 32-bit word at base state plus 59 bytes.
4. Assigns the zero-extended input-relative halfword to global slot C.
5. Assigns base state to global slot D.
6. Assigns auxiliary state to global slot E.
7. Writes the 32-bit value 141 to the primary destination, whose address is formed from base state shifted left by 8 bits, then offset by 48 bytes.

It then returns the fifth explicit input.

The multiplier 256 and the shift by 8 are related numerically, but they participate in different operations. The global-slot calculation reads slot A after its assignment. The primary-destination calculation uses base state directly, not slot A.

The secondary destination is at offset 59, rather than an aligned offset such as 60. That distinction is material. For a word-aligned base, this is an unaligned 32-bit access.

### Arithmetic boundaries

## Side effects

### Reads and writes

- One 32-bit primary-destination write.

The zero-input path additionally includes:

- Five global assignments.
- A read of global slot A for the multiplication.
- One 32-bit secondary-destination write.

No memory-clearing operation, allocation, release, ownership transfer, callback, or explicit synchronization operation is shown.

### Aliasing and overlapping storage

The supplied material warns that global symbols can overlap other storage symbols. The locations of global slots A through E are not given, so this contract does not assume that they are disjoint.

Neither does it assume that the global slots, initial read locations, and explicit write destinations are mutually disjoint.

The two halfword values are captured before any branch-dependent write. Later writes do not cause those initial reads to be repeated. In contrast, the value used to calculate global slot B is obtained through global slot A after the assignment to A.

Overlapping destinations can make the final memory image depend on write order. For example, the final primary write can overwrite bytes written earlier on the zero-input path. Exact consequences require concrete addresses, global widths, byte order, and access semantics.

### Faults and partial effects

- Failure of the second read occurs before any displayed write.
- Failure of the secondary write on the zero-input path can occur after assignments to global slots A and B.
- Failure of the final primary write can occur after all earlier zero-path assignments.

These are ordering consequences, not guarantees about a particular platform’s exception delivery or memory-transaction behavior.

- Assign 1,047,296 to global slot B.
