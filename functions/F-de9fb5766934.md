# F-de9fb5766934

## Purpose

F-de9fb5766934 performs a fixed progression of indirect calls, computed-address word writes, saved word reads, and selector-controlled byte writes, followed by an unconditional loop of further calls and byte writes.

No application-level purpose is established. The computed addresses do not establish arrays, records, device registers, or a communication protocol. Terms such as “word slot” and “record slot” below distinguish address formulas only.

This contract describes the supplied static representation, not independently verified executable behavior. That representation reports invalid instruction data, removed unreachable regions, and overlapping global symbols. All behavioral conclusions are subject to those limitations.

### Implicit inputs

### Outputs and completion

The represented return type is void. There is no represented normal return, status result, or explicit error report.

If execution reaches the final loop and every access and dependency invocation continues completing, it does not return. Faults, traps, nonreturning dependencies, and dependency-driven control transfers have no represented local recovery path.

### Widths and notation

A **word** is 32 bits; a **byte** is 8 bits. A byte write retains only the low eight bits of its value.

For an integer selection value \(x\):

- **Word-slot address:** \(4x+0x14\).
- **Record-slot address:** \(16x+0x14\).

A **selector operation** reads an unsigned byte from its specified selector address and uses that byte plus `0x11` as the destination address. Its destination range is therefore `0x11` through `0x110`, inclusive.

These formulas do not imply allocated storage or ownership. Unsigned 32-bit calculations truncate to 32 bits where required by their represented types. Unsigned right shifts are logical. Calculations involving represented signed results—including multiplication and left shifts—require additional care: wrapping 32-bit machine arithmetic is a conditional interpretation, not an independently established language-level guarantee. Examples relying on it are identified below.

Endianness, alignment requirements, pointer conversion rules, and the memory map are unknown.

## Behavior

### 1. Entry and initial word writes

Before invoking any dependency, the routine writes the first input shifted right by seven to the word slot selected by that same, unshifted input.

The first indirect target is the incoming link-register value plus `0xFFE`. Its four explicitly represented arguments, in order, are:

1. First input.
2. First input.
3. Third input.
4. First input.

After intervening calls, a primary result selects another word slot. That slot receives the first input shifted right by seven. The following dependency receives four times the selecting result.

The two word writes are separated by dependency invocations; they are not an atomic pair.

### 2. First selector-controlled byte pair

A later primary result is retained for two byte values. The selector address for this pair is:

\[
(\text{first input}\gg8)+1.
\]

The routine reads the selector and writes the low byte of four times the retained result to the selected destination. A following call receives that four-times-result quantity.

After intervening calls, the routine rereads the selector at the same address. The second byte value is:

\[
\operatorname{low8}((\text{retained result}\mathbin{\&}0x3FFFFFFF)\gg20).
\]

This value still comes from the original retained result. A newer call result instead supplies a four-times-result argument to the next dependency.

The two selector reads may yield different destinations. Neither read may be replaced by the other.

### 3. Absolute-memory snapshot

After further calls, the routine reads the object at absolute address `0x3C` and converts its value to an unsigned word. The source object’s width and extension behavior are unresolved.

The destination for two subsequent word writes is:

\[
4(\text{third input}\gg7)+0x14.
\]

The captured value is written there, then passed to a dependency. Calls intervene before the same saved value is written to the same destination again. There is no represented second read of `0x3C`.

After the repeated write, the next dependency receives four times an intervening primary result, not necessarily four times the captured memory value.

### 4. First record-slot write and earlier snapshot

A subsequent result selects a record slot and a word slot. The routine writes four times that result to the record slot, then reads a word from the word slot. The retained word is the **earlier snapshot**.

The write precedes the read. If the addresses alias, the read observes memory after that write, subject to the unresolved memory-access model.

A dependency then receives, in order:

- Sixteen times the selecting result.
- Four times the selecting result.
- The selecting result shifted left by 26.
- Four times the selecting result again.

The left-shift-derived quantity is retained as an unsigned word for later logical right shifts.

Subsequent calls include two return-and-forward sequences. After additional calls, the original record slot is rewritten with its original four-times-result value. A newer primary result supplies the four-times-result argument to the following call; it does not replace the saved rewrite value.

### 5. Second snapshot and shifted rewrite

Another primary result selects a record slot and word slot. Four times that result is written to the record slot before the word slot is read. This read produces the **second snapshot**.

The retained left-shift-derived quantity is logically shifted right by seven during this phase. A dependency receives two equal arguments, each four times the selecting result. Return-and-forward calls follow.

The routine later writes the second snapshot shifted right by eight to the previously selected word slot. This is derived from the saved read, not a fresh read. The next dependency receives four times a newer result.

### 6. Earlier-snapshot-derived word operations

The following progression remains ordered:

- A new result selects a record slot, which receives four times that result.
- A dependency receives the earlier snapshot shifted right by 16.
- After calls, the corresponding word slot receives four times its original selecting result.
- Another result selects a record slot, which receives four times that result.
- A dependency receives sixteen times this result.
- Return-and-forward calls include one receiving an opaque returned value and the earlier snapshot shifted right by 16.
- The record slot is rewritten with its original four-times-result value.

A further result selects another record slot, again receiving four times the result. The retained left-shift-derived quantity undergoes a second logical right shift by seven.

The routine forms the **snapshot-derived offset**:

\[
8(\text{earlier snapshot}\gg8).
\]

This uses the entire 24-bit shifted value, not one extracted byte.

A dependency receives four times the current selecting result and the snapshot-derived offset. Forwarding calls follow, including a call also receiving the earlier snapshot shifted right by 16. The word at the snapshot-derived offset plus `0x14` then receives the saved four-times-result value.

Another record-slot write follows. A dependency receives:

1. The snapshot-derived offset.
2. The same offset.
3. The earlier snapshot shifted right by 16.
4. The retained left-shift-derived quantity shifted right by another seven.

After further calls, the snapshot-derived destination receives the offset itself.

### 7. Additional register result and later word writes

A later dependency supplies an additional register result distinct from any established primary-return relationship.

That register result determines a value scaled by \(2^{24}\) and a destination scaled by \(2^{26}\), plus `0x14`. The value is written before the next call, which receives that saved value. After further calls, a newer primary result selects a word slot that receives the same saved \(2^{24}\)-scaled value.

Further progression is:

- A record slot receives four times a new selecting result.
- A dependency receives that four-times-result quantity.
- Return-and-forward calls intervene.
- A word slot selected by a newer result receives the earlier saved four-times-result quantity.
- Another record slot receives four times a new result; its four-times-result quantity is retained separately.
- Further forwarding calls occur.
- A newer result selects a word slot that receives the earlier snapshot shifted right by 24.

The snapshot’s top byte is also retained separately.

Another result selects a record slot. Its initial value is four times that result. A dependency receives sixteen times the result twice, followed by the earlier snapshot shifted right by 23. After intervening calls, that same record slot is rewritten with sixteen times the result, rather than its initial four-times value.

### 8. Earlier selector base and final byte writes

The **earlier selector base** is formed from the separately retained four-times-result quantity from the preceding phase:

\[
(\text{retained four-times quantity}\mathbin{\&}0x7FFFFFFF)\gg7.
\]

The selector address is this base plus one.

A subsequent unsigned primary result supplies another byte pair. The routine:

- Reads this selector and writes the low byte of four times the result.
- Invokes a dependency with three equal arguments, all carrying that four-times-result bit pattern.
- Performs intervening calls.
- Rereads the selector and writes the low byte of the original result masked with `0x3FFFFFFF` and shifted right by 20.

A newer result supplies a four-times-result argument to the following dependency.

After additional calls, a still later unsigned result supplies a **direct-byte result**. Its four-times value is retained as the **direct-byte scaling**. The routine writes its low byte directly to:

\[
(\text{earlier snapshot}\gg31)+0x1C.
\]

This destination is `0x1C` or `0x1D`.

Immediately afterward, without an intervening dependency call, the routine rereads the earlier selector at the earlier selector base plus one and writes zero to the selected destination. The direct byte write can affect that subsequent read if their addresses alias.

Subsequent calls include one receiving the earlier snapshot shifted right by 31, and another receiving:

\[
(\text{direct-byte result}\mathbin{\&}0x3FFFFFFF)\gg6.
\]

After more calls, the earlier selector is reread and its selected destination is zeroed again.

### 9. Loop selector and entry

A later unsigned primary result establishes the initial **loop quantity**:

\[
(\text{result}\mathbin{\&}0x3FFFFFFF)\gg25.
\]

It lies between zero and 31 inclusive.

The **loop-selector address** is:

\[
1024(\text{direct-byte scaling})+1.
\]

The operand is specifically the retained four-times value of the later result that supplied the direct write at `0x1C` or `0x1D`. It is **not** the earlier retained quantity used to form the masked-and-shifted earlier selector base. The multiplication by 1024 uses a represented signed intermediate; overflow and address interpretation remain conditional.

Before loop entry, the routine reads the loop selector and zeroes its selected destination. A dependency receives twice the initial loop quantity. The next dependency supplies the initial **carried first argument directly**, without a represented multiplication by four.

### 10. Unconditional loop

Each iteration begins with a dependency receiving:

1. The carried first argument.
2. The current loop quantity logically shifted right by eight.

Calls follow. A primary result is obtained, then the routine rereads the loop selector at the address defined above and writes zero to its currently selected destination. The following dependency receives four times that intermediate primary result.

Further calls produce the iteration’s final primary result. For final result \(r\), the next iteration uses:

\[
\text{carried first argument}=4r,
\qquad
\text{loop quantity}=r\ll26.
\]

These transformations involve represented signed arithmetic before the loop quantity is held as an unsigned word. Under a wrapping 32-bit bit-pattern interpretation, the next iteration’s arguments are:

\[
\operatorname{low32}(4r),
\qquad
(r\mathbin{\&}63)\times2^{18}.
\]

The first iteration’s second argument is necessarily zero because its initial loop quantity is at most 31. Later carried first arguments are scaled by four; only the initial carried value comes directly from the pre-loop dependency.

No conditional exit is represented. The loop-selector address retains its saved operand, but its selected byte is reread before every loop zero write.

## Acceptance examples

These are conditional static examples, not executed tests. They require valid accesses and returning dependencies where continuation is described.

1. **Initial ordering.** With first input `0x80`, the first word write stores `1` at `0x214`, before the first dependency call.

2. **Byte-pair values and selector rereading.** A retained first-pair result of `0x12345678` produces bytes `0xE0` and `0x23`. Selector reads of `0x20` and `0x30` select destinations `0x31` and `0x41`.

3. **Saved absolute-memory value.** With third input `0x100`, both snapshot writes target `0x1C`. If the captured conversion yields `0x11223344`, both writes use that value even if a dependency changes `0x3C` between them.

4. **Write-before-read aliasing.** If the first record-selecting result is zero, its record and word addresses both equal `0x14`. With ordinary coherent memory, the record write of zero precedes the earlier-snapshot read, which therefore reads zero.

5. **Selector boundaries.** Selector bytes `0x00` and `0xFF` select `0x11` and `0x110`, respectively.

6. **Direct destination and loop-selector operand.** The earlier snapshot’s top bit selects direct destination `0x1C` or `0x1D`. If the later direct-byte result is `1`, its retained scaling is `4`, and the loop-selector address is `0x1001`. This address does not come from the earlier masked selector base.

7. **Loop-carried transition.** The first iteration’s second argument is zero. Under wrapping 32-bit bit-pattern arithmetic, an iteration ending with primary result `1` causes the next iteration to receive first argument `4` and second argument `0x00040000`.

8. **Loop selector mutation.** If successive loop-selector reads yield `0x10` and `0x20`, their zero writes target `0x21` and `0x31`. Caching the earlier selector value would contradict the represented reads.

9. **Noncompletion.** If all operations continue completing after loop entry, the routine does not return. Returning after a fixed iteration count would contradict the represented control flow.
