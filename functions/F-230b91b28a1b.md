# F-230b91b28a1b

## Purpose

F-230b91b28a1b traverses a linked structure using a supplied 32-bit value, then either publishes a candidate address or delegates production of a result word to F-758158eeac40.

The externally written result consists of a 32-bit word followed by a one-byte disposition:

- **0:** the existing-candidate path was selected; F-758158eeac40 was not called.
- **1:** F-758158eeac40 returned normally, and its output-storage contents were copied to the result.

Flag 1 does not independently establish insertion, allocation, or success. Flag 0 does not independently establish key equality or guarantee that the published address equals the address previously passed to candidate extraction.

The structure and traversal are consistent with ordered-tree insertion and predecessor selection. Those semantic interpretations remain inferred intent; the established behavior is the memory access and dependency-call contract below.

## Interface

### Arguments

1. **Result storage address.** Writable storage with:
   - Offset **0:** a 32-bit result word.
   - Offset **4:** an 8-bit disposition flag.

   These writes require five accessible bytes. No direct write to offsets 5–7 is established.

2. **Context address.** The function uses these context-relative locations:

   | Offset | Width or use | Role |
   |---|---|---|
   | 0x10 | 32-bit address-bearing field | Header-like node address |
   | 0x18 | 8-bit field | Mode, tested against zero |
   | 0x19 | Address formation | First argument to F-31a0b2b5649a |

   The storage extent and representation expected at offset 0x19 belong to the dependency’s undocumented contract.

3. **Supplied value.** An opaque 32-bit value forwarded to dependencies. Whether it represents a key, address, or other token is not established.

### Node representation

Address-bearing fields in the supplied representation are 32 bits wide. This is not a contract for arbitrary host-native pointer widths.

| Node offset | Access | Observed role |
|---|---|---|
| 0 | 8-bit read | Marker for a special predecessor case |
| 4 | 32-bit read | Parent-like link; initial root-like link in the header |
| 8 | 32-bit read | First traversal link; boundary value in the header |
| 0x0c | 32-bit read | Second traversal link |
| 0x10 | Address formation | Operand passed during search comparison |

These roles do not establish a complete node layout or balancing scheme.

### Results and preconditions

There is no explicit scalar return value. On normal completion, the function writes the result word first and the flag byte second. Publication is not atomic.

Valid memory is required for every access actually reached, including accesses through links or temporary contents modified by dependencies. Parent traversal must terminate in a valid arrangement. No input validation, cycle detection, null-link recovery, or dependency-error translation is visible.

Result storage is not initialized at entry. If execution does not reach publication, it need not contain a new result.

No explicit alias check separates result storage from context or node storage. Overlap can make the result-word write modify structural state before the flag write. A safe overlapping-storage contract is not established.

## Behavior

### Initial reads and search

The function reads the header address from context offset 0x10 and then reads the starting node from that header’s offset 4. It separately rereads context offset 0x10 to initialize a retained attachment address. These are distinct header reads.

A remembered comparison result starts as nonzero.

For each non-null search node:

1. Two distinct 32-bit temporary words are cleared to zero. One is reserved for early boundary delegation; the other later serves as boundary storage and ordinary delegated-output storage.
2. F-31a0b2b5649a receives:
   - The address at context offset 0x19.
   - The original supplied value.
   - The address at the current node’s offset 0x10.
3. The current node becomes the retained attachment address.
4. The comparison result selects the next link:
   - **Zero:** offset 0x0c.
   - **Nonzero:** offset 8.

The selected child field is read after the comparison call, so dependency changes to that field can affect descent.

Only zero versus nonzero matters. Negative and positive nonzero results select the same branch; a conventional three-way comparator cannot be assumed.

Descent ends when the selected address is null. The attachment remains the last visited node, or the separately loaded header if no node was visited. For an empty descent, neither temporary word has been initialized by the loop, and the remembered comparison remains nonzero.

### Mode selection

After descent, the function reads context offset 0x18.

- **Nonzero:** proceed directly to ordinary delegation.
- **Zero:** initialize a candidate temporary with the retained attachment address and perform the checks below.

The mode is not captured at entry. Earlier comparison calls can therefore influence it by modifying accessible context storage.

### Boundary decision

If the remembered search comparison is zero, boundary handling and predecessor adjustment are skipped.

Otherwise, the function:

1. Rereads the header address from context offset 0x10.
2. Reads the 32-bit word at that header’s offset 8 into the shared boundary/ordinary-output temporary.
3. Calls F-0c3ebe6e88e3 with the address of the candidate temporary and the address of that shared word.

Both arguments expose writable temporary storage.

A **nonzero** boundary result selects early delegation immediately. No candidate extraction or final comparison occurs.

A **zero** boundary result selects predecessor adjustment using the candidate temporary’s then-current contents. The dependency may have changed that candidate.

The exposed storage remains alive throughout this invocation’s remaining execution. Without dependency contracts forbidding retention or subsequent mutation, later dependencies may use escaped addresses to change either temporary before publication or ordinary delegation.

### Predecessor adjustment

This adjustment occurs only after a nonzero search result and a zero boundary result.

The function reads the candidate’s one-byte marker. If it is zero, it follows the candidate’s offset-4 link and reads offset 4 from the linked node. If that resulting address equals the candidate, the candidate is replaced with its offset-0x0c link, and adjustment ends.

Otherwise, ordinary link traversal applies:

- The candidate’s offset-8 link is read into a traversal address.
- Offset 8 is read again to decide whether to take the parent-climbing path.
- If the second read is null, traversal starts from the candidate’s offset-4 link. At each step, the prospective parent’s offset-8 link is compared with the candidate. The candidate is updated to that parent even when the comparison is false. Climbing continues only while the comparison is true.
- If the second offset-8 read is non-null, traversal uses the address obtained by the first read. At each reached node, that node becomes the candidate. Offset 0x0c is read to obtain the next address and is read again to decide whether to continue.

The repeated field reads are not a single snapshot. Under stable storage they implement the expected link traversal; concurrent or other asynchronous mutation has no coherent-snapshot guarantee.

There are no protective null checks before all parent-chain dereferences. Invalid arrangements can cause invalid access or nontermination rather than an error result.

Calling this operation “predecessor selection” is conditional on structural invariants not supplied here.

### Candidate extraction and final comparison

After candidate selection, F-25ee6ab13ffc receives the candidate address as read at that call. Its 32-bit result becomes an operand to F-31a0b2b5649a:

1. Address at context offset 0x19.
2. Value returned by F-25ee6ab13ffc.
3. Original supplied value.

This operand order differs from descent. Descent supplies the original value followed by a node-relative address; the final comparison supplies an extracted value followed by the original value.

If the final comparison is **zero**, the function rereads the candidate temporary, writes its current contents as the result word, then writes flag **0**.

Consequently, the published address is not unconditionally the extraction argument or the candidate produced by predecessor adjustment. If the boundary dependency exposed the candidate address to other dependencies, F-25ee6ab13ffc or the final F-31a0b2b5649a call could modify that storage before publication.

If the final comparison is **nonzero**, the function takes ordinary delegation.

A zero final comparison is not independently proof of equality. An equivalence interpretation requires a suitable comparison contract and valid search invariants.

### Delegation and output-word initialization

Every delegation calls F-758158eeac40 with:

1. Address of a 32-bit temporary output word.
2. Context address.
3. Literal zero.
4. Retained attachment address.
5. Original supplied value.

The attachment argument is independent of the candidate temporary. Boundary mutation, predecessor adjustment, and later candidate mutation do not replace it.

There are two output-storage paths:

| Delegation path | Initialization and reuse of supplied output storage |
|---|---|
| Early delegation after a nonzero boundary result | Uses the separate early-output word. It was cleared during every search iteration, but was not initialized if descent was empty. It is not the word passed to the boundary dependency. |
| Ordinary delegation without a boundary call | Uses the shared word. It was cleared during every search iteration, but was not initialized if descent was empty. |
| Ordinary delegation after a zero boundary result | Uses the same shared word previously initialized from header offset 8 and exposed to F-0c3ebe6e88e3. It is not cleared again. Its contents can include boundary changes and later changes through the escaped address. |

The loop clears occur **before** each search comparison, not immediately before delegation. The established initialization must not be elevated into a general guarantee against undocumented dependency mutation.

After F-758158eeac40 returns, the function copies the supplied output word’s then-current contents to result offset 0, then writes flag **1** at offset 4. It does not require or check a distinct success status.

If the dependency leaves its output word unchanged:

- A nonempty, no-boundary path can publish the loop-initialized zero, subject to intervening mutation.
- An early boundary path after nonempty descent can likewise publish the separately initialized zero.
- Ordinary delegation after a zero boundary result can publish the retained boundary-word contents, including mutations.
- A path supplying an uninitialized word has no reliable result-word value established by this function.

## Side effects

Direct external writes by this function are the 32-bit result store and subsequent one-byte flag store. No explicit allocation, deallocation, node-link update, or resource release is visible.

Dependencies may modify accessible state. Relevant sequencing includes:

- Search comparisons precede child-link reads.
- All search calls precede the mode read.
- Boundary handling precedes candidate traversal and extraction.
- Extraction and final comparison precede the existing-result candidate read.
- Delegation precedes reading and publishing its output storage.

The candidate and shared boundary/output temporary addresses are valid during the remainder of this invocation, including subsequent dependency calls. Their exposure is not limited to the duration of the boundary call. No dependency is assumed to discard those addresses, preserve their contents, or refrain from sharing them while the storage remains live.

Retention beyond this invocation’s return is not supported by the temporary-storage lifetime. The supplied function does not establish a safe post-return use contract.

No rollback or explicit synchronization is visible. A dependency that changes state and then fails to return normally can leave those changes in place without result publication.

## Acceptance examples

These are conditional acceptance cases derived from static evidence, not executed tests. Unless stated otherwise, memory is valid, traversals terminate, dependencies return normally, and no additional mutation occurs beyond that described.

### Empty descent and early boundary delegation

The starting link is null, mode is zero, and the boundary result is nonzero.

- No search comparison or loop clearing occurs.
- Boundary handling initializes the shared word from header offset 8.
- Early delegation receives the separate, uninitialized output word.
- Its attachment argument is the separately loaded header address.
- If the dependency writes a defined output, that word is published with flag 1.
- If it leaves the word unchanged, no reliable result word is established.

The header-derived shared word is not the output word used on this path.

### Nonempty descent and ordinary delegation without a boundary call

Descent visits at least one node, and the mode byte is nonzero when read.

- Both temporary output words were cleared before the last search comparison.
- No boundary dependency or extraction call occurs.
- Ordinary delegation receives the shared word and the last visited node as attachment.
- If intervening dependencies have not changed that word and F-758158eeac40 leaves it unchanged, the published result is zero with flag 1.

For empty descent under the same mode, the ordinary output word instead lacks initialization.

### Zero last search comparison

Mode is zero and the last search comparison is zero.

- Boundary handling and predecessor adjustment are skipped.
- Extraction receives the retained attachment address.
- A zero final comparison publishes the candidate temporary’s current address with flag 0.
- A nonzero final comparison selects ordinary delegation using the shared word initialized during descent.

### Shared boundary storage survives into ordinary delegation

The header-offset-8 word is a particular 32-bit value. The boundary dependency replaces it with another value and returns zero. The final comparison returns nonzero.

Ordinary delegation receives that same storage without another clearing. If no later dependency changes it and F-758158eeac40 leaves it unchanged, the replacement value is published with flag 1.

If extraction or final comparison changes it through an escaped address, the later value is instead the input content observed by delegation.

### Candidate changes after extraction

The boundary dependency returns zero and retains the candidate-storage address. After predecessor adjustment, extraction receives address **A**. Through the escaped address, extraction or final comparison changes the candidate temporary to **B**, and the final comparison returns zero.

The result word is **B**, followed by flag 0. It is not required to be **A** or the predecessor-adjustment result. Any delegated alternative would still use the retained attachment address.

### Nonzero comparison and publication order

A negative nonzero search result selects offset 8, just as a positive nonzero result does.

On every normal publication path, the 32-bit result store precedes the one-byte flag store. No atomic five-byte publication or direct write beyond offset 4 is established.
