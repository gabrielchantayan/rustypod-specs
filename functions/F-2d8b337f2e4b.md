# F-2d8b337f2e4b

## Purpose

F-2d8b337f2e4b specifies a machine-state-dependent operation controlled by two incoming condition flags. Depending on those flags, it transforms an unsigned input word, reads a word from a computed address, or issues a coprocessor request followed by a software-interrupt request.

The supplied static evidence does not establish a complete, normally returning operation. Its local flow ends at an invalid-instruction boundary. This contract therefore defines selected operations, operand relationships, and ordering constraints—not a successful completion result.

**Established evidence:** the flag-dependent operations, their relative order, the represented operand types, and the absence of an explicit returned value.

**Inferred intent:** the operation appears to participate in machine-specific coprocessor or exception handling. No particular platform service or application purpose is established.

**Unknown behavior:** instruction-level shift semantics, external-operation effects, fault handling, and the runtime meaning of the terminal boundary remain **documented_only**.

## Behavior

### Flag-selected modes

The following table defines the four combinations without implying that any combination completes normally.

| Incoming zero condition | Incoming carry condition | Selected behavior |
|---|---|---|
| Clear | Clear | The input supplies the value for the coprocessor operand calculation. The coprocessor and software-interrupt requests are selected. |
| Clear | Set | An ordinary word read is selected using the input as the address offset. The loaded word, rather than the read address, supplies the value for the coprocessor operand calculation. The two external requests are selected. |

### Transformation semantics

In transformation mode, the operation retains only bits shared by the original input and a shifted form of the signed shift source.

The shift distance comes from the original input’s low byte. It is not recalculated from a transformed value, and it is not established to be reduced to five bits.

Within the determinate domain described above, the shifted value has an unambiguous nonnegative 32-bit representation. Its intersection with the original input becomes the working word used by any selected read.

A zero count is significant but does not justify ignoring the signed operand. With a nonnegative source, shifting by zero leaves the source unchanged, so the intersection is well defined. A negative source with a zero count is not assigned a result under the ordinary signed-left-shift interpretation used to delimit this contract.

Counts from 32 through 255, negative sources, and results outside the stated representable range remain **documented_only**. The contract does not substitute zero, mask the distance, or reinterpret a negative source as unsigned to manufacture a result.

These restrictions concern what can safely be concluded from the supplied representation. They do not establish how an underlying processor instruction behaves for those operands.

### Ordinary memory-read semantics

When the incoming carry condition is set, the operation requests one unsigned word read.

The address is obtained by subtracting the current working word from the base quantity. Because the working word is unsigned in the represented model, the calculation uses the base’s corresponding 32-bit unsigned bit pattern and wraps modulo \(2^{32}\).

The offset is therefore:

- The original input when the incoming zero condition is clear.
- The transformed word when the zero condition is set and that transformation is determinate.
- Unresolved when the selected transformation has no established result.

A successful read replaces the working word with the loaded unsigned value. It does not preserve the computed read address as the value for the later coprocessor operand.

The access is a four-byte word read under the represented model. Neither byte order nor byte-by-byte access order is established. Atomicity and special treatment of device memory are also unspecified.

No local null check, bounds check, alignment check, alternate access, retry, or recovery branch is represented. A numerically defined address is not evidence that the access is valid.

The selected read address is therefore hexadecimal `3000`. After a successful read, no coprocessor or interrupt request is selected.
