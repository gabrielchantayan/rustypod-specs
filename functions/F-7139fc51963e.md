# F-7139fc51963e

## Purpose

F-7139fc51963e performs a flag-controlled configuration sequence through a three-argument dependency and, for selected flags, modifies a shared 16-bit field.

The established behavior is a sequence of argument construction, shared-memory accesses, and dependency invocations. The configuration’s physical meaning is unknown. In particular, selector values are not established as register addresses, the second dependency argument is not established as a write mask, and the external operation receiving the value 100 is not established as a delay.

The function returns a 32-bit zero after the sequence completes normally. It does not inspect dependency return values or report configuration failures through its return value.

## Interface

### Input

One unsigned 32-bit flag word.

The following bits independently affect execution:

| Input bit | Established effect |
|---|---|
| `0x00000001` | Enables two initial dependency calls and a later external operation followed by two more dependency calls; selects the full `0x003C` value for selector `0x19`. |
| `0x00000002` | Adds `0x01E0` to the 16-bit configuration value and ORs `0x0060` into a shared field. |
| `0x00000004` | Adds `0x0198` to the 16-bit configuration value, adds `0x0100` to a separate configuration value, and ORs `0x0018` into the shared field. |
| `0x00000008` | Adds `0x0030` to the value passed for selector `0x19`. |
| `0x00000010` | Adds `0x0180` to the 16-bit configuration value. |
| `0x00000200` | Reads the shared field, initializes it to `0x0060` if zero, and incorporates its value together with `0x0180` into the 16-bit configuration value. |

“Adds” in this table means bitwise OR, not arithmetic addition.

All other input bits are untested individually. Nevertheless, they affect the whole-word zero comparison: an input containing only an otherwise unrecognized bit behaves differently from zero.

### Output

No output buffer or caller-provided memory address is supplied. Observable outputs are the dependency calls, any effects produced by those dependencies, and conditional writes to shared memory.

## Behavior

### 1. Establish local configuration values

The function constructs three local values:

- A selector-`0x18` value, held as an unsigned 32-bit quantity:
  - `0x0008` when the entire input word is zero.
  - Zero when the input word is nonzero.
- A selector-`0x1A` value, held as an unsigned 16-bit quantity, initially zero.
- A selector-`0x19` value, held as an unsigned 32-bit quantity, initially zero.

These are per-invocation values, not shared configuration caches.

### 2. Perform the optional initial calls

If input bit `0x00000001` is set, invoke F-2cf379ad0812 twice, in this order:

| Order | Argument 1 | Argument 2 | Argument 3 |
|---|---:|---:|---:|
| First | `0` | `0x0080` | `0x0080` |
| Second | `1` | `0x0180` | `0x0180` |

After those calls, set the selector-`0x19` local value to `0x003C`.

The shared base address used by later captured-base accesses is obtained after these calls. Consequently, a base-address change caused by either call can affect the later accesses. The function does not establish that this dependency preserves the global address or the pointed-to storage.

### 3. Capture the shared base and process field-related flags

The function obtains a captured copy of the global base address even when no input flag will cause a field access.

It then processes the following conditions in the listed order.

#### Input bit `0x00000002`

Set the 16-bit selector-`0x1A` value to `0x01E0`.

Read the shared 16-bit field, OR its value with `0x0060`, and write the resulting 16-bit value back.

This branch refers directly to the global base-address value rather than solely using the captured base. The source contains separate global-base references for the read and write expressions. It does not establish their relative address-evaluation order or make them an atomic operation.

With a stable global base and no intervening field modification, the effect is to set field bits `0x0060` while preserving every other field bit.

#### Input bit `0x00000004`

OR `0x0198` into the 16-bit selector-`0x1A` value.

OR `0x0100` into the 32-bit selector-`0x18` value.

Using the captured base, read the shared 16-bit field, OR its value with `0x0018`, and write the result back to the same field location.

With stable memory, this sets field bits `0x0018` without clearing other bits.

When both `0x00000002` and `0x00000004` are set, the `0x0060` update precedes the `0x0018` update. If both accesses address the same stable field, the combined update is an OR with `0x0078`.

#### Input bit `0x00000008`

OR `0x0030` into the selector-`0x19` value.

If bit `0x00000001` was also set, this does not change the already selected value `0x003C`.

#### Input bit `0x00000010`

OR `0x0180` into the 16-bit selector-`0x1A` value.

This condition alone does not read or write the shared field.

#### Input bit `0x00000200`

Using the captured base, read the shared 16-bit field and compare it with zero. The comparison is expressed through a signed 16-bit read, but only zero versus nonzero matters: a field with its high bit set is still nonzero.

If the field is zero, write the 16-bit value `0x0060` to it.

Then read the field again and OR both that value and `0x0180` into the selector-`0x1A` value.

Important consequences:

- The field is read again after the zero check and any initialization write.
- The incorporated value is the later read, not necessarily the value observed by the zero check.
- Earlier updates for input bits `0x00000002` and `0x00000004` occur before this zero check.
- Under stable conditions, either earlier update makes the field nonzero, preventing the default `0x0060` write.
- All 16 field bits can affect the selector-`0x1A` argument. They are not restricted to the `0x01FC` value later supplied as the dependency’s second argument.

### 4. Submit the selector-`0x19` value

Invoke F-2cf379ad0812 with:

| Argument 1 | Argument 2 | Argument 3 |
|---:|---:|---:|
| `0x19` | `0x003C` | Constructed selector-`0x19` value |

The third argument is:

- `0x003C` if input bit `0x00000001` is set.
- Otherwise `0x0030` if input bit `0x00000008` is set.
- Otherwise zero.

All direct field accesses described above occur before this invocation.

### 5. Perform the optional intermediate external sequence

If input bit `0x00000001` is set:

1. Invoke F-external-01 with arguments `0` and `100`.
2. Invoke F-2cf379ad0812 with arguments `(0, 0x0080, 0)`.
3. Invoke F-2cf379ad0812 with arguments `(1, 0x0180, 0x0100)`.

F-external-01 is a document-local opaque identifier for the external dependency whose mapped identifier was not supplied.

The established contract is the call and its position in the sequence. The meaning and units of 100 are unknown.

There are no further direct shared-field reads after this sequence begins. Dependency-induced memory changes therefore do not cause the already constructed local configuration values to be recomputed.

### 6. Perform the unconditional final sequence

Invoke F-2cf379ad0812 four times, in this exact order:

| Order | Argument 1 | Argument 2 | Argument 3 |
|---|---:|---:|---:|
| First | `5` | `0x0008` | `0x0008` |
| Second | `0x1A` | `0x01FC` | Constructed 16-bit selector-`0x1A` value |
| Third | `0x18` | `0x0108` | Constructed selector-`0x18` value |
| Fourth | `5` | `0x0008` | `0` |

Then return zero.

Without input bit `0x00000001`, normal execution makes five calls to F-2cf379ad0812. With that bit set, it makes nine such calls and one call to F-external-01.

### Width and arithmetic constraints

All local flag combinations use bitwise OR; no arithmetic addition or multiplication is present.

The selector-`0x1A` value remains 16 bits. Its constants and field input all fit within that width, so these combinations do not discard bits beyond the field’s 16-bit range.

The selector-`0x19` value can only be zero, `0x0030`, or `0x003C`.

The selector-`0x18` value is:

- `0x0008` for an entirely zero input.
- `0x0100` for a nonzero input with bit `0x00000004` set.
- Zero for any other nonzero input.

It cannot become `0x0108`: the condition selecting the initial `0x0008` value excludes every set input bit.

## Side effects

### Direct effects

The function conditionally writes the shared 16-bit field:

- Bit `0x00000002`: one read-modify-write using OR value `0x0060`.
- Bit `0x00000004`: one read-modify-write using OR value `0x0018`.
- Bit `0x00000200`: a write of `0x0060` only if the zero-check read finds zero.

The read-modify-write branches still contain a write when the requested bits were already set. Likewise, the zero-initialization branch’s subsequent field read is a distinct access.

These accesses are not established as atomic, synchronized, or volatile hardware transactions. Concurrent modification, aliasing, or memory-mapped side effects could invalidate a simple single-snapshot interpretation.
