# F-4841e1d4297a

## Purpose

F-4841e1d4297a describes a visible execution fragment that interleaves 32 indirect dependency calls with three 32-bit memory stores and two byte-oriented read/write sequences.

The fragment scales values returned by dependencies, uses some scaled values as addresses, passes others as arguments, and accesses a low-address byte location selected through an unsigned byte read. No application-level purpose, data-structure meaning, or successful completion behavior is established.

The supplied static representation ends at an invalid-instruction boundary. It does not establish a normal return. This contract therefore covers the visible prefix and its ordering, conditional on execution reaching each operation.

**Established static evidence:** call order, explicit argument expressions, selected returned values, memory access widths, and the terminal invalid-instruction indication.

**Inferred intent:** some returned values may act as indices or encoded fields. That interpretation is not required by the observable operations.

**Unknown:** actual dependency behavior, calling convention details, memory validity, and execution beyond the visible boundary. No runtime tests have been performed.

## Interface

### Entry and exit

The apparent interface has no declared parameters and no declared return value. It nevertheless depends on ambient machine state:

- An incoming return-link value participates in computing the first indirect call target.
- An incoming register-carried 32-bit value supplies the payload of the first explicit store.
- Subsequent indirect call targets are formed from embedded code-location anchors and fixed offsets.
- Dependencies may observe additional machine state not expressed as explicit arguments.

Thus, “no declared parameters” does not mean that behavior is independent of entry state.

There is no established normal exit. The visible prefix reaches an invalid-instruction boundary after the last dependency call, if all preceding operations complete. Whether that produces a processor exception, emulator stop, process termination, or some other outcome is unknown.

The representation distinguishes:

For describing arithmetic, **W(x)** means the low 32 bits of x. This is the natural fixed-width interpretation of the displayed operations, not independently verified instruction semantics. The representation also uses signed integer expressions in places where overflow or left shifts would be problematic under a literal source-language interpretation. It must not be treated as a portable source-language implementation.

The following semantic labels identify values, not source identifiers:

- **B:** result of F-D08.
- **C:** result of F-D13.
- **D:** unsigned 32-bit result of F-D18.
- **E:** unspecified 32-bit result of F-D20.

## Behavior

### 1. Acquire the first value and perform the first store

1. Call F-D01, then F-D02, then F-D03. None has explicit arguments in the supplied representation.
2. Retain the 32-bit result of F-D03 as A.
3. Form S = W(4A).
4. Store P as a 32-bit value at address W(S + 0x14).
5. Call F-D04 with S as its one explicit argument.

The first call target depends on incoming return-link state plus 0xFFE. Later targets in this phase are derived from embedded code anchors plus 0xFFE. The static representation does not establish that these targets are valid.

The first store precedes F-D04. There is no visible bounds, null, alignment, or permission check.

### 2. Acquire a second value and perform the second store

6. Call F-D05, F-D06, and F-D07, in that order, without explicit arguments.
7. Call F-D08 without explicit arguments and retain its result as B.
8. Form T = W(4B).
9. Store T as a 32-bit value at address W(16B + 0x14).
10. Call F-D09 with these three explicit arguments, in order:
   - (S AND 0x3F) shifted left by 14 bits;
   - T;
   - W(A shifted left by 30 bits).

The first argument depends only on the low six bits of S. Under fixed-width scaling, S has two zero low bits, so that argument can take only the values 0x00000, 0x10000, …, 0xF0000.

The third argument retains only A’s low two bits, positioned in bits 31–30. It must not be interpreted as an unrestricted multiplication result.

### 3. Acquire a third value and perform the third store

11. Call F-D10, F-D11, and F-D12, in that order, without explicit arguments.
12. Call F-D13 without explicit arguments and retain its result as C.
13. Store the previously computed T as a 32-bit value at address W(4C + 0x14).
14. Call F-D14 with W(4C) as its one explicit argument.

The payload of this store comes from B, not C. C selects the store location and the argument supplied to F-D14.

No dependency behavior is known to preserve the earlier stores. The fragment establishes that those writes occur; it does not establish their persistence across intervening calls.

### 4. Acquire a fourth value and perform the first byte read/write sequence

15. Call F-D15, F-D16, and F-D17, in that order, without explicit arguments.
16. Call F-D18 without explicit arguments and retain its unsigned 32-bit result as D.
17. Form U = W(4D).
18. Read one unsigned byte at address W(A × 0x10000000 + 1).
19. Add 0x11 to the zero-extended byte value and use the result as a destination address.
20. Store the low eight bits of U at that destination.
21. Call F-D19 with three explicit arguments:
   - U;
   - U again;
   - W(D shifted left by 4 bits).

The selector is a byte value, not a pointer-sized value loaded from memory. Its range is 0 through 255, so this destination address ranges from 0x11 through 0x110 inclusive.

Under fixed-width arithmetic, the selector-source address depends only on A’s low four bits. The multiplication does not establish a valid object base or ordinary array layout.

F-D19 has a target computed with an offset of 0xFEC, unlike the 0xFFE offset shown for the other target computations. No semantic reason for this difference is established.

### 5. Pass through a returned value, then perform a fresh selector read

22. Call F-D20 without explicit arguments and retain its 32-bit result as E.
23. Call F-D21 with E as its one explicit argument.
24. Call F-D22, F-D23, and F-D24, in that order, without explicit arguments.
25. Call F-D25 without explicit arguments and retain its result as G.
26. Read another unsigned byte from address W(A × 0x10000000 + 1).
27. Retain this second selector value.
28. Store the low eight bits of ((D AND 0x3FFFFFFF) shifted right by 20 bits) at address “second selector + 0x11.”
29. Call F-D26 with W(G shifted left by 2 bits) as its one explicit argument.

The second selector is a fresh memory read. It must not be replaced by the first selector’s value: intervening dependencies, aliased explicit stores, or external activity may have changed the location.

The expression used for this byte payload first produces a value of up to ten bits. Truncation to the stored byte means that the effective payload is bits 27–20 of D. Bits 29–28 do not survive the byte store.

The value retained for later use is the second selector, not the first selector and not the byte payload.

### 6. Make the final calls and reach the visible boundary

30. Call F-D27, F-D28, and F-D29, in that order, without explicit arguments.
31. Call F-D30 without explicit arguments and retain its result as H.
32. Call F-D31 with two explicit arguments:
   - W(H shifted left by 2 bits);
   - the second selector, zero-extended from its byte value.
33. Call F-D32 without explicit arguments.
34. Reach the invalid-instruction boundary shown by the supplied representation.

There is no explicit selector read between F-D26 and F-D31. Therefore, absent an unmodeled disruption of retained execution state, F-D31 receives the saved second selector even if intervening dependencies modify the selector’s memory location.

These accesses may alias. No disjointness between locations is established. If explicit writes overlap, their order matters. If dependencies access the same memory, their intervening effects also matter.

The record supplies no atomicity, volatility, synchronization, or transaction guarantee. It shows no rollback if a later call or access fails.

### Ownership and resource state

No explicit allocation, deallocation, reference-count update, ownership transfer, or resource release is visible. This does not imply that dependencies lack such effects.

In particular:

- E is passed onward as an opaque 32-bit value; it is not established to be an owned pointer.

### Errors

There is no explicit error-result check, status propagation, retry, fallback, or cleanup path in the visible prefix.

A dependency that fails to return prevents later operations from occurring. An invalid call target or memory access may likewise interrupt execution. The resulting platform behavior is unknown. The terminal invalid-instruction indication is not evidence of an intentional application-level error protocol.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests. They assume valid targets and memory, returning dependencies, and the fixed-width interpretation described above.

### Ordinary scaling and argument formation

Given A = 3, B = 5, and C = 7:

- The first store writes P at 0x20.
- The second store writes 20 at 0x64.
- The third store writes 20 at 0x30.
- F-D04 receives 12.
- F-D09 receives 0x30000, 20, and 0xC0000000.
- F-D14 receives 28.

A contract that writes 28 as the third store’s payload would be incorrect: that store retains the payload derived from B.

### Different selectors on the two reads

Given D = 0x12345678, a first selector of 0x20, and a second selector of 0x40:

- The first byte store writes 0xE0 at address 0x31.
- F-D19 receives 0x48D159E0 twice, followed by 0x23456780.
- The second byte store writes 0x23 at address 0x51.
- F-D31 later receives 0x40 as its second explicit argument.

This remains the required sequence when a dependency causes the selector to change between reads. Reusing the first selector would not match the visible behavior.

### Selector boundaries

A selector of zero selects destination address 0x11. A selector of 255 selects 0x110. These are arithmetic consequences, not evidence that either address is writable.

### Aliased word stores

Given B = 0 and C = 0, both the second and third stores write zero at address 0x14. Both stores remain separate observable operations, with dependency calls between them. They cannot be collapsed on the assumption that the location remains unchanged.

### Nonreturning dependency

If F-D18 does not return, neither selector read nor either byte store is reached. Earlier stores may already have occurred. No rollback is visible.
