# F-040a8473d14b

## Purpose

The supplied representation describes a stateful routine that performs a long ordered sequence of indirect calls, interleaved with derived-address memory writes, before entering an unconditional loop.

No application-level purpose is established. In particular, the evidence does not establish that this routine implements a collection, serializer, allocator, device protocol, or initialization procedure. The repeated scaling and fixed offsets are observable arithmetic patterns, not sufficient evidence of an object model.

This contract distinguishes:

- **Established static evidence:** operations and ordering explicitly present in the supplied representation.
- **Inferred interpretation:** a plausible 32-bit machine-level interpretation of arithmetic and addresses.
- **documented_only:** unresolved behavior, including dependency identity, calling conventions, and the reliability of recovered control flow.

The representation carries warnings about invalid instruction data and removed unreachable regions. Accordingly, this is a contract for the displayed execution path, not a claim that the original executable necessarily follows that path.

### Byte selection and byte writes

2. Adding 17 to that byte’s numeric value.

Each displayed selected-byte store performs a fresh selector read. It is not permissible to substitute an earlier selector value merely because the same selector address is used: intervening dependencies or earlier writes may change it.

The byte phase proceeds as follows:

2. Invoke a dependency with Sample 12 shifted left by two in all three displayed argument positions.
3. Invoke a no-argument producer, pass its result to a consumer, and make four further no-argument calls, obtaining Sample 13.
4. Re-read the selector byte and write the low eight bits of the unsigned quantity formed by clearing the top two bits of Sample 12 and shifting right by twenty.
5. Invoke a dependency with Sample 13 shifted left by two. Four no-argument calls produce Sample 14.
6. Write the low eight bits of Sample 14 shifted left by two at the address obtained from Seed shifted right by twenty-three, plus 28.
7. Re-read the selector byte and write zero at its selected-byte destination.
8. Invoke a dependency with Seed shifted right by twenty-three, then invoke a no-argument dependency.
9. Invoke another dependency with the unsigned quantity formed by clearing the top two bits of Sample 14 and shifting right by six.
10. Four no-argument calls produce Sample 15.
11. Re-read the selector byte and write zero at its selected-byte destination.
12. Invoke a dependency with Sample 15 shifted left by two. Four no-argument calls produce Sample 16.

Steps 6 and 7 are separate stores, in that order, without an intervening displayed call. They can nevertheless alias.

The direct address in step 6 ranges from 28 through 539 inclusive because Seed is unsigned and 32 bits wide.

### Transition to the loop

After Sample 16 is produced:

- Clear its top two bits and shift right by twenty-five, producing an initial loop quantity in the range 0 through 31.
- Read a byte at the address formed by multiplying the retained Sample 14-left-shifted-by-two value by 1024, then adding one.
- Write zero at that byte’s numeric value plus 17.
- Invoke a dependency with twice the initial loop quantity.
- Invoke a no-argument dependency whose result becomes the initial carried call value.

The selector address used here differs from Selector base plus one. The resulting zero-write destination still lies between 17 and 272.

### Unconditional loop

Every displayed iteration contains this ordered behavior:

- Invoke a dependency with the carried call value and the current loop quantity shifted right by eight.
- Make four no-argument calls; retain the last result.
- Re-read the loop selector byte and write zero at its numeric value plus 17.
- Invoke a dependency with the retained result shifted left by two.
- Make four no-argument calls; retain the last result.
- Set the next carried call value to that last result shifted left by two.
- Set the next loop quantity to that last result shifted left by twenty-six.

There is no displayed exit condition, iteration bound, return, or delay.

The first iteration’s second argument is necessarily zero because the initial loop quantity is at most 31. Under 32-bit shift semantics, subsequent loop quantities depend only on the low six bits of the last result, and their right-shift-by-eight arguments have their low eighteen bits clear.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests.

1. **Third-argument truncation.** If execution reaches the four-argument dependency and earlier dependencies return normally, a third explicit argument of 16,383 contributes zero to its fourth argument. A value of 16,384 contributes one. The intermediate seven-bit shift must not be mistaken for the final value.

2. **Repeated seed-derived destination.** If accesses are valid, event 3 writes four times Sample 1 at eight times Seed plus 20. Event 5 later writes eight times Seed at that same calculated address. The contract requires both events, not just the latter final value.

3. **Repeated Sample 10 destination.** If Sample 10 is three and arithmetic is representable, event 12 writes 12 at address 68; event 13 later writes 48 there. Dependencies occur between those writes.

4. **Selector reload.** If the selector byte is five at the first selected-byte write, that write targets address 22. If a dependency changes it to nine before the next selected-byte write, that later write targets address 26.

5. **Byte truncation.** If Sample 12 is 127, the first selected-byte write stores 252. If Sample 12 is 128, it stores zero. Only the low eight bits are written.

6. **Distinct extraction from Sample 12.** If Sample 12 is 1,048,576, the later selected-byte write derived by masking and shifting right twenty stores one. It is not a repetition of the first shifted-left byte.

7. **Initial loop argument.** Whatever unsigned 32-bit value Sample 16 contains, the first loop iteration’s second displayed argument is zero.

8. **Loop continuation.** If all dependencies return and accesses succeed, completion of an iteration starts another iteration. No sample value provides a displayed normal exit.

9. **Early failure.** If the initial four-byte store faults, the first dependency is not reached on the displayed path. No local recovery or alternate return is shown.
