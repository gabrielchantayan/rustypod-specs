# F-486b0a337262

## Purpose

The established behavior is the control flow and explicit accesses described below. “Event,” “channel,” “completion,” and “acknowledgement” are descriptive roles, not established hardware semantics. In particular, writing a pending or status register does not establish which hardware bits subsequently remain set.

## Behavior

### 1. Save the mask and inspect an active transfer

The first visible register access reads and saves the event mask at `0x18`.

The routine then reads the transfer-active byte. If nonzero, it selects a supplied status-table offset using selector bit 7 and reads a status word at that offset plus `0x20` times the selector’s low seven bits.

The bank test and index extraction are separate selector accesses; they need not observe one stable selector value.

If the status word has bit 0 set, the routine:

1. Clears the transfer-active byte.
2. Writes exactly `0x00100000` to the pending-event register.

This is a whole-word write, not an explicit software read-modify-write.

### 2. Process pending bit 20

The routine reads the pending-event register and tests bit 20.

If set, it reads the transfer-active indicator. Only if that read is zero does it need to read the companion-work indicator. If either condition reports nonzero work:

1. It calls F-adc5296da4e0.
2. After the call, it reads selector bit 7 to choose bank offset `0xB00` when clear or `0x900` when set.
3. It reads a selected 32-bit channel word, ORs it with the helper’s 32-bit result, and writes the result to a selected channel word.

The index is obtained from the selector’s low seven bits. The source and destination address expressions contain separate selector accesses. Therefore, equality of their indices requires a stable selector; the representation does not establish one atomic selector snapshot. The bank decision is made after the helper.

Whether or not the helper runs, the bit-20 branch ends by writing exactly `0x00100000` to the pending-event register.

If bit 20 is clear, this entire branch is skipped.

### 3. Gate the main phase

The routine obtains current pending-event and event-mask values and tests their bitwise intersection.

If the intersection is zero, it returns without installing the service mask, scanning channels, restoring the entry mask, or invoking the final deferred-processing dependency. Earlier transfer and bit-20 actions may already have occurred.

The gate uses fresh register values, not the saved entry mask.

### 4. Process bit 31 and install the service mask

Inside the main phase, the routine rereads the pending-event register and tests bit 31.

Only when that bit is set does it:

1. Write 1 to the special-event byte.
2. Write exactly `0x80000000` to the pending-event register.

The gate need not have opened because of bit 31 specifically.

Next, the routine reads initial-service status at `0xB08`. Of this saved value, only bit 3 controls a later alignment-related indicator.

It then writes an externally supplied 32-bit service-mask value to the event-mask register. This write occurs even if initial service is subsequently skipped.

### 5. Process initial service using distinct status reads

The initial-service status accesses are separate observations with different purposes:

1. **Before service-mask installation:** the saved status supplies the later bit-3 decision.
2. **After service-mask installation:** a fresh status read tests bits 0 and 3 to decide whether initial service runs.
3. **After setting aggregate work:** another fresh status read supplies the bit-0 boolean.
4. **For status write-back:** a further fresh status read supplies the value masked with `0x9`.

If the second read has neither bit 0 nor bit 3 set, this phase performs no initial-service count or indicator updates and does not call F-8a70d554f44a.

Otherwise, the routine performs these operations in order:

1. Writes 1 to the aggregate-work byte.
2. Reads initial-service status again and retains whether bit 0 is set.
3. Reads occupancy at `0xB10`, retains its low seven bits, and computes the 32-bit modular count.
4. Reads initial-service status again, masks that value with `0x9`, and writes the result to `0xB08`.
5. Stores the computed count.
6. If the retained bit-0 boolean is true, writes 1 to the bit-0 initial-service indicator.
7. If bit 3 of the **pre-mask-installation** status was set, the count is nonzero, and its low three bits are zero, writes 1 to the alignment-related indicator.
8. Calls F-8a70d554f44a.

These decisions may disagree without contradiction. Entry into initial service does not establish the later bit-0 boolean, and the entry-test read does not supply the alignment-related bit-3 decision. The write-back value comes from neither of those reads.

### 6. Capture channel-event information

The routine reads the channel-event register and clears bit 16 in its captured value.

If the resulting value is zero, both channel scans are skipped. Otherwise:

- A separate channel-event read supplies the low eight pending bits.
- Bits 17–31 of the earlier captured value supply upper-channel events.
- Captured bits 8–15 can cause entry into channel processing but do not directly select any scanned channel.
- Captured bit 16 is excluded.

The low and upper scans therefore need not reflect the same register observation.

### 7. Scan low channels

Pending low indices are processed in ascending order, 0–7.

For each selected index, the routine reads the corresponding status word and writes the same captured value back to that status address. All subsequent status-bit decisions for that channel use the value read before write-back.

The routine then reads the low-channel active byte. If it is nonzero, it compares the selector’s low seven bits with the current index. Selector bit 7 does not affect this comparison.

#### Ordinary path

This path applies when the active byte is zero or the index comparison fails.

First, the routine tests the outstanding-channel descriptor. The nonzero test and low-seven-bit comparison use separate descriptor reads. If the first reports nonzero, the subsequent low bits match the current index, and captured channel status has bit 4 or bit 5 set, it:

1. Writes exactly `9` to register `0x810`.
2. Reads the word at `0x900 + 0x20 × index` and writes it back ORed with `0x84000000`.
3. Clears the outstanding-channel descriptor.
4. Writes 1 to the outstanding-channel completion byte.

Independently, if captured channel status has bit 0 set, it:

1. Reads the channel configuration word.
2. If configuration bits 18 and 19 are both set, writes that captured word back with bit 27 set.
3. Writes 1 to the aggregate-work byte.
4. Writes 1 to this low-channel completion entry.

Both sets of actions can occur for one channel, in that order.

#### Selected active path

This path applies when the active byte is nonzero and the selector’s low seven bits match the current index.

If neither captured status bit 0 nor bit 4 is set, no further action occurs for that channel.

Otherwise:

1. If bit 4 is set, call F-5c256682e106.
2. Call F-627c2cdb2924.
3. If its result is nonzero, write 1 to aggregate work, then 1 to this low-channel completion entry, then read, increment, and store the byte completion counter.

A zero result causes none of those three explicit updates. Dependency effects remain possible.

This path does not perform ordinary-path descriptor processing or configuration updates. Its eligibility uses captured channel status even if the first dependency changes registers or shared state.

### 8. Scan upper channels

The upper pending set is derived from the earlier captured channel-event value shifted right by 16. Its bit 0 has already been excluded.

Selected indices 1–15 are processed in ascending order. For each:

1. Read the upper-channel status word.
2. Write that same captured word back.
3. If its captured bit 0 is set, write 1 to aggregate work and then 1 to the corresponding upper-channel completion entry.

There is no explicit selected-channel helper path, descriptor handling, configuration update, or completion-counter increment in this scan.

### 9. Restore the mask or request deferred processing

The final decision preserves several distinct byte reads.

First, the routine reads the deferred-processing byte.

If it is zero:

1. Read the special-event byte unconditionally into an intermediate value.
2. Read the aggregate-work byte.
3. Only if aggregate work is zero, read the special-event byte again.

The restoration predicate requires aggregate work to read zero and the **second** special-event read to report zero. The first special-event read does not supply that predicate. It still occurs when aggregate work is nonzero and prevents restoration; the second read then does not occur.

If the deferred-processing byte was nonzero, these special-event and aggregate-work reads are skipped.

Only when the restoration predicate succeeds does the routine read the pending-event register and intersect it with the saved entry mask:

- Zero intersection: write the saved entry mask to the event-mask register.
- Nonzero intersection: take the deferred path.

Every other final condition also takes the deferred path:

1. Write 1 to the deferred-processing byte.
2. Read the 32-bit deferred-processing argument.
3. Call F-123f7368c2e2 with that value.

An already-nonzero deferred byte does not suppress the call. No explicit mask restoration occurs on the deferred path.

## Acceptance examples

These are conditional static expectations, not executed tests. They assume accessible storage, returning dependencies where needed, and the stated values at each relevant access.

1. **Closed main gate.** A zero current pending/mask intersection skips the entire main phase. Earlier transfer and bit-20 actions remain possible.

2. **Transfer completion.** A nonzero transfer-active read followed by selected status bit 0 causes the byte clear before the `0x00100000` pending write. The next pending value depends on register semantics.

3. **Bit 31 absent.** If the main phase runs but its bit-31 test is clear, that branch performs neither the special-event assignment nor the `0x80000000` pending write.

4. **Saved bit 3 does not start service.** A pre-mask status of `0x8` followed by an entry-test status of zero skips initial service and F-8a70d554f44a.

5. **Fresh bit-0 decision.** Suppose the pre-mask status is zero, the entry-test status is `0x8`, the post-aggregate status is `0x1`, and occupancy is 56. The count is 8 and the bit-0 indicator is written. The alignment-related indicator is not written because saved pre-mask bit 3 was clear.

6. **Independent write-back.** If initial service runs and the write-back status read is `0xA`, the status write is `0x8`, regardless of the earlier status values.

7. **Unsigned underflow.** Occupancy 65 produces count `0xffffffff`. Occupancy 72 produces `0xfffffff8`; that second value meets the nonzero, low-three-bits-zero condition when saved pre-mask bit 3 is set.

8. **Ordinary completion.** Captured status bit 0 and configuration bits 18–19 both set cause the configuration write with bit 27 set, followed by aggregate and completion assignments.

9. **Selected helper declines.** Captured bit 4 causes F-5c256682e106 before F-627c2cdb2924. A zero result from the latter produces no explicit completion assignments or counter increment on this path.

10. **Counter wrap at the actual increment.** If the counter reads 255 immediately before its increment, **after both applicable helper calls and the aggregate/completion writes**, the stored byte is 0. A value of 255 before entering the path is insufficient because those intervening operations may change or alias it.

11. **Distinct final special-event reads.** With deferred processing zero, aggregate work zero, first special-event read 1, second special-event read 0, and final pending/entry-mask intersection zero, the entry mask is restored. The first special-event value does not veto restoration.

12. **Aggregate work blocks restoration.** With deferred processing zero and aggregate work nonzero, the first special-event read still occurs, the second does not, and the deferred path runs.

13. **Excluded channel bit.** A channel-event capture containing only bit 16 skips both scans. A capture containing only bits 8–15 enters channel processing but selects no channel if the separate low-byte read is zero.
