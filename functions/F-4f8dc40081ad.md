# F-4f8dc40081ad

## Purpose

F-4f8dc40081ad conditionally modifies a word-based object in place. A transformed header selects initialization, positive-direction propagation, negative-direction propagation, or rejection.

**Established static behavior:** the function reads configuration words, checks a transformed header, and updates a bounded prefix of addressed data words. The positive path can append one word and replace the header. The negative path does not explicitly replace the header.

**Inferred intent:** the structure resembles incrementing a signed, multiword value whose header and data use configurable multiplicative encodings. The supplied evidence does not establish those encodings, their invertibility, word significance, or numerical normalization rules. This interpretation is not an unconditional mathematical guarantee.

The explicit result is a 32-bit status word:

- **1:** the initial signed magnitude comparison rejects the transformed header. No object stores occur.
- **0:** an ordinary completion path is reached, including initialization, propagation, and termination at the data extent.

Status zero does not independently establish representation validity, sufficient allocation capacity, or successful execution of any particular mathematical operation.

### Configuration and arithmetic notation

| Label | Observed role |
|---|---|
| A | Header transformation multiplier |
| B | Header replacement multiplier |
| C | Data replacement multiplier |
| D | Data transformation multiplier |

These are role labels, not claims that A and B, or C and D, are mathematical inverses.

The function first reads and retains configuration values in this order:

1. D
2. C
3. B
4. A

It subsequently reads **global A again** for the initial header multiplication. This second read is distinct from the retained A value.

The contract distinguishes:

- **Retained A, B, C, D:** the values captured by the four ordered entry reads.
- **Fresh A:** the value obtained by the additional A read used to transform the initial header.
- **T:** fresh A multiplied by the initial header, reduced to a 32-bit word under the arithmetic model below.
- **M:** T if T has nonnegative signed interpretation; otherwise the 32-bit negation of T.

The positive-extension calculation uses **retained A**, not fresh A. The two reads need not be treated as equal unless configuration stability is an explicit assumption.

For the operational descriptions and conditional examples:

- Arithmetic results retain their low 32 bits.
- Signed interpretation treats a word as a two’s-complement 32-bit integer.
- Unsigned comparisons interpret the same word in the range zero through \(2^{32}-1\).
- Products, additions, and subtractions use this word-arithmetic model unless stated otherwise.

The supplied representation supports this model but does not independently establish the original language’s overflow guarantees or all target execution semantics. Overflow-dependent consequences are conditional on this model.

## Behavior

### Initial transformation and rejection

After retaining D, C, B, and A, the function obtains fresh A and reads the initial header to form T. Their relative read order within that multiplication is not established by the supplied representation.

It computes M and compares **signed M** with 28:

- If signed M is greater than 28, it returns 1.
- Otherwise, processing continues according to T.

Rejection occurs before every object store and every data-address-field or data-word access.

For ordinary transformed headers, this rejects positive and negative magnitudes greater than 28. It is not an unsigned magnitude bound. Under the stated arithmetic model, T equal to `0x80000000` negates to the same word. Signed M remains negative and therefore passes the comparison.

### Initialization when T is zero

A zero T selects initialization:

1. Global B is read again, and that value is stored in the header.
2. Global C is read again, and that value is stored in data word zero.
3. The function returns 0.

These stores use the reread B and C values, not their retained entry values.

The header store precedes the first-data-word store. The address field used for that data store is accessed after the header store. The relative order of the address-field read and the C read within the data-store expression is not independently established.

T being zero does not require the original header to be zero. Fresh A may be zero, or a nonzero product may reduce to zero under word arithmetic.

### Positive transformed header

A positive T that passes the initial check has M between 1 and 28.

Processing starts at data-word index zero. Each reached word undergoes the following observable transformation:

- Its current value is read.
- Retained D multiplies that value, and one is added, producing a 32-bit intermediate result.
- Retained C multiplies that intermediate result.
- The resulting word is stored at the current indexed data position.

After the store, the processed-word count increases. If it has reached M, word traversal stops. Otherwise:

- A zero intermediate result causes processing to continue at the next index.
- A nonzero intermediate result stops processing.

The continuation test examines the result **before multiplication by retained C**. A zero stored word is not sufficient to propagate.

After traversal stops, the function checks the last intermediate result:

- If it is nonzero, no explicit header replacement or additional-word store occurs.
- If it is zero, the function writes retained C at the next data-word index, then replaces the header.

The replacement header is:

\[
\text{retained B}\times
\left(\text{retained A}\times\text{current header}+1\right)
\]

with word arithmetic.

The header in this expression is read again at extension time. It is not a saved copy of the initial header. The A value is the retained entry value, not fresh A.

For disjoint storage without external mutation, extension occurs only after all M processed words yield zero intermediate results. The appended word is then at index M. The appended-word store precedes the header read and replacement, so aliasing from that store can affect the header value used in the calculation.

The function returns 0.

### Negative transformed header

A negative T that passes the initial check also begins at data-word index zero.

For each reached word:

- Its current value is read.
- Retained D multiplies it, producing a 32-bit intermediate value.
- One is subtracted from that intermediate value.
- Retained C multiplies the subtraction result.
- The resulting word is stored at the current indexed data position.

The replacement is therefore:

\[
\text{retained C}\times
\left(\text{intermediate value}-1\right)
\]

It is **not** retained C times the intermediate value, followed by subtraction of one. Subtraction occurs before multiplication by retained C.

The extent decision is determined before the store, but termination at that extent occurs only after the current word has been stored:

- If the processed-word count has reached or exceeded signed M, the function returns 0 immediately after the store.
- Otherwise, a zero intermediate value causes processing to continue.
- A nonzero intermediate value ends propagation and leads to return 0.

The continuation test uses the intermediate value before subtraction and multiplication by retained C.

This path does not explicitly append data, replace the header, reduce the extent, or normalize a zero result. Header changes are nevertheless possible if a data store aliases the header.

For T equal to `0x80000000`, signed M is negative. The function processes word zero once, then returns 0 at the extent decision. It does not attempt a traversal of approximately two billion words.

## Side effects

### Access ordering

The established ordering constraints are:

- Retained configuration reads occur in the order D, C, B, A.
- A separate global A read participates in the initial header multiplication after those four reads.
- The initial rejection check precedes all object stores and data accesses.
- Initialization rereads B for the header store, then rereads C for the first-data-word store.
- Each reached propagation word is read before its replacement is stored.
- Positive extension stores the additional word before reading and replacing the header.
- Negative extent termination occurs after the current word’s replacement store.

The function does not retain one data-base address for the entire operation. Address-field accesses occur again for data accesses. A store overlapping that field can redirect later accesses.

The evidence does not establish a complete ordering between independent operands inside a single expression. These constraints are not a volatile-access specification or synchronization protocol.

### Mutation bounds

For disjoint storage, without external mutation:

- Rejection leaves the object unchanged.
- Initialization replaces the header and first data word.
- Positive processing replaces a contiguous prefix of data words and may append one word and replace the header.
- Negative processing replaces a contiguous prefix without explicitly replacing the header.
- Data words beyond the last processed or appended index are untouched.

A replacement store may write the value already present.

### Aliasing and configuration changes

No disjointness checks are visible among the object fields, data storage, and global configuration storage.

Consequences include:

- A data store can change the header used by positive extension.
- The appended-word store can itself change that header before the extension calculation reads it.
- A store overlapping the address field can change later data addresses.
- The initialization header store can affect the subsequent C reread if those locations overlap.
- Changes to global configuration do not retroactively change retained values.

The initial transformation uses fresh A, while positive extension uses retained A. Equating them requires a stability assumption; merely identifying both reads with the same global location is insufficient.

No synchronization is visible. Defined behavior under concurrent changes, asynchronous updates, or device-memory semantics remains **documented_only**.

### Errors and partial effects

The initial guard is the only explicit source of status 1. There is no explicit allocation failure, invalid-address status, or rollback path.

If a later access faults, earlier stores may already have occurred. Whether such failures trap, terminate execution, or have another effect is outside the supplied evidence. They must not be represented as an additional defined status return.

## Acceptance examples

These are conditional consequences of the static operations, not runtime observations. Unless otherwise stated, assume valid disjoint storage, stable configuration, word arithmetic, and A, B, C, and D all equal to one.

### Rejection without data access

For a header of 29 or −29:

- Signed M is 29.
- The result is 1.
- No object store occurs.
- The address field and data storage are not accessed.

The header and configuration reads must still be valid.

### Initialization

For a zero header:

- The header becomes one.
- Data word zero becomes one.
- No later data word is accessed.
- The result is 0.

With other configuration values, initialization stores the reread B and C values, not necessarily the retained values.

### Positive termination without propagation

For header two and first data word seven:

- Data word zero becomes eight.
- Data word one is not accessed.
- The header remains two.
- The result is 0.

### Positive propagation and extension

For header two and data words `0xFFFFFFFF` and four:

- Word zero becomes zero.
- Word one becomes five.
- No additional word is written.
- The header remains two.

If both initial words are `0xFFFFFFFF`, and a third word is writable:

- Both processed words become zero.
- Word two becomes one.
- The header becomes three.
- The additional-word store precedes the header replacement.

Both cases return 0.

### Negative propagation

For header −2 and data words zero and five:

- Word zero becomes `0xFFFFFFFF`.
- Its intermediate value was zero, so propagation continues.
- Word one becomes four.
- The header remains −2.
- The result is 0.

For header −1 and first data word zero, only word zero is processed. It becomes `0xFFFFFFFF`, and no second word is accessed.

### Negative multiplication follows subtraction

Assume stable A, B, and D equal one, C equals two, header −1, and first data word five:

- The intermediate value is five.
- Subtracting one gives four.
- Multiplying by C gives eight.
- Data word zero becomes eight, **not nine**.
- The header remains −1, no second word is accessed, and the result is 0.

For the same configuration with first data word zero, the replacement is `0xFFFFFFFE`: subtraction produces `0xFFFFFFFF`, then multiplication by two retains the low 32 bits.

### Minimum signed transformed value

For header `0x80000000`:

- The signed magnitude comparison does not reject.
- Exactly one negative-path word is processed.
- No second word is accessed.
- The result is 0.

### Stored zero does not require propagation

Assume A, B, and D equal one, C equals zero, header two, and first data word seven:

- The positive intermediate result is eight.
- The replacement is zero.
- Processing stops because the intermediate result was nonzero.
- No second word is accessed, and the header remains two.

### Distinct A reads

Conditionally, if the execution environment permits retained A to be two and fresh A to be one, with retained B, C, and D equal to one, an initial header of one and first data word `0xFFFFFFFF` produce:

- T equal to one, selecting one-word positive processing.
- Word zero replaced by zero.
- An appended word equal to one.
- A replacement header equal to three, using retained A.

Using fresh A for extension would instead yield two and would not match the supplied operations. This example does not establish a supported mechanism for changing A between reads.
