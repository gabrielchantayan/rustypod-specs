# F-14a62729627b

## Purpose

F-14a62729627b writes a variable-length representation of an unsigned 64-bit quantity into caller-supplied storage. It returns a 64-bit result containing both a byte count and an additional 32-bit value.

The established behavior has two branches:

- When any of the quantity’s highest eight bits is set, it writes exactly nine bytes.
- Otherwise, it constructs between one and eight bytes in temporary storage, modifies one bit of that storage, and copies the constructed bytes to the destination in reverse order.

**Inferred intent:** this is a most-significant-group-first variable-length integer encoder. On a little-endian target, the shorter representation uses seven payload bits per byte, with bit 7 marking every byte except the last. The nine-byte representation uses seven payload bits in each of its first eight bytes and all eight bits of its final byte.

The byte count is not the entire return value. The upper 32 bits are observable and branch-dependent; they must not be discarded from a full behavioral contract.

## Interface

The function accepts four scalar arguments, in this order:

| Argument | Recovered width and role |
|---|---|
| Destination | A 32-bit address-like value identifying writable storage |
| Auxiliary word | An unsigned 32-bit value used to initialize temporary storage and to form the upper return word |
| Low word | The low 32 bits of the quantity being represented |
| High word | The high 32 bits of the quantity being represented |

Let the unsigned input quantity be:

**V = low word + 2³² × high word.**

This definition combines the two input words mathematically. It does not require a native 64-bit input load.

The result is an unsigned 64-bit value:

**result = count + 2³² × upper result word.**

- **count** occupies bits 0–31 and is between 1 and 9.
- **upper result word** occupies bits 32–63 and is defined separately for each branch below.
- The result is a scalar value, not an owned memory object.

The destination must provide at least the selected number of writable bytes. Nine writable bytes suffice for every input. There is no capacity argument, destination validation, allocation, or reported buffer-too-small condition.

For the ordinary behavior described here, destination writes must not interfere with active temporary storage or execution state. No useful overlapping-storage guarantee is established.

## Behavior

### Arithmetic and branch selection

The input words are treated as unsigned 32-bit quantities. Right shifts are logical. Left-shifted contributions are combined within 32-bit words; bits beyond that width are discarded.

The branch condition examines the high word with the mask **0xFF000000**:

- A nonzero result selects the nine-byte branch.
- A zero result selects the one-to-eight-byte branch.

Equivalently, the nine-byte branch is selected precisely when **V ≥ 2⁵⁶**.

The auxiliary word does not affect this selection, the count, or the intended encoded payload. It does affect the upper return word.

### Nine-byte branch

This branch does not use the temporary reversal procedure.

The destination accesses occur in this exact order:

1. Write the low eight bits of V to destination offset 8.
2. Write destination offsets 7, 6, 5, 4, 3, 2, 1, and 0, in that descending order.

For offsets 0 through 7, each byte contains seven payload bits and has bit 7 set. In final destination order:

| Destination offset | Payload bits from V | Bit 7 |
|---|---|---|
| 0 | 63 through 57 | Set |
| 1 | 56 through 50 | Set |
| 2 | 49 through 43 | Set |
| 3 | 42 through 36 | Set |
| 4 | 35 through 29 | Set |
| 5 | 28 through 22 | Set |
| 6 | 21 through 15 | Set |
| 7 | 14 through 8 | Set |
| 8 | 7 through 0 | Unmodified payload bit |

The final byte is not restricted to seven bits. Its high bit can be either zero or one.

The returned count is 9. The upper result word is exactly the original auxiliary word. Thus the complete result is:

**2³² × auxiliary word + 9.**

The branch’s byte layout does not depend on the byte order used to store a 32-bit word.

### One-to-eight-byte branch: established storage operations

This branch constructs bytes in temporary storage before writing the destination.

The recovered temporary layout consists of consecutive 32-bit storage words initialized from the auxiliary word, low word, and high word, in that order. Generated bytes begin at byte offset 0 of the first word. This branch generates at most eight bytes, so it can reach into the second word but does not need the third word for its generated-byte range.

The number of generated bytes, **n**, is the smallest positive integer such that:

**V < 2⁷ⁿ.**

Because this branch requires V < 2⁵⁶, n is between 1 and 8. Zero still generates one byte.

Construction proceeds from the least significant seven-bit group toward the most significant group. Each generated byte initially has bit 7 set. After every generated-byte write, the current first 32-bit temporary word is captured as a scalar value. The final such capture supplies the upper return word before its final mask.

After construction finishes:

1. Bit 7 of the first temporary **word**, considered numerically, is cleared.
2. Temporary bytes are read in descending offset order, starting at offset n − 1 and ending at offset 0.
3. Each read byte is written to the next ascending destination offset, starting at offset 0.
4. The count returned in the low result word is n.
5. The captured temporary word is masked with **0xFFFFFF7F** and returned in the upper result word.

The mask clears bit 7 of the upper result word. It does not alter any count bit.

This distinction between a numeric word operation and a byte operation matters: the supplied material does not independently establish target byte order.

### One-to-eight-byte branch on a little-endian target

On a little-endian target, clearing numeric bit 7 of the first temporary word clears bit 7 of temporary byte offset 0. That byte contains V’s least significant seven-bit group and becomes the last destination byte after reversal.

Under that condition, destination bytes have the following properties:

- The most significant seven-bit group is written first.
- Every destination byte except the last has bit 7 set.
- The last byte has bit 7 clear.
- The representation uses the minimum positive number of seven-bit groups.
- Zero is represented by the single byte **00**.

The upper result word is not simply the auxiliary word and is not generally a function of V alone.

To describe it precisely, let each generated byte be its seven-bit payload with bit 7 set. On little-endian storage:

- The first generated byte replaces bits 0–7 of the auxiliary word.
- The second, if present, replaces bits 8–15.
- The third, if present, replaces bits 16–23.
- The fourth, if present, replaces bits 24–31.
- Later generated bytes do not change this first word.
- Finally, bit 7 is cleared.

For fewer than four generated bytes, untouched higher bytes of the auxiliary word remain in the upper result word. For four or more generated bytes, no auxiliary-word byte remains there.

### Byte-order limitation

The numeric mask is not, by itself, evidence that temporary byte offset 0 is modified on every target.

For example, with conventional big-endian word storage, numeric bit 7 belongs to byte offset 3. Clearing that bit would not generally clear the continuation bit of the last output byte. Accordingly, the little-endian encoding interpretation is conditional; the underlying temporary-write, word-mask, and reverse-copy behavior is the established contract.

## Side effects

### Destination memory

On successful execution with valid storage:

- Exactly the selected count of destination bytes is written.
- No destination byte outside offsets 0 through count − 1 is explicitly written.
- No destination byte is explicitly read.
- Existing destination contents do not contribute to the representation.

Write order differs by branch:

- **Nine bytes:** offset 8 first, followed by offsets 7 down to 0.
- **One through eight bytes:** offsets 0 through n − 1, ascending, after temporary construction and masking.

These sequences can matter if execution faults partway through or if destination writes have externally visible effects. The supplied evidence does not establish device-memory suitability, synchronization, or atomicity.

### Temporary state

The shorter branch writes temporary bytes, captures the first temporary word during construction, clears a bit of that word, and reads temporary bytes during the final copy.

No explicit global state access, external function call, allocation, deallocation, or ownership transfer is visible.

### Invalid inputs and failures

Invalid destination addresses, insufficient writable storage, address-range wraparound, or interference with active storage have no defined recovery path in the supplied material. No error status or partial-write count is returned for such failures. The function does not check for them before beginning its writes.

The destination remains caller-owned. Nothing establishes permission for the function to release or retain it beyond the call.

### Nine-byte threshold

For V = 2⁵⁶:

- The nine-byte branch is selected.
- Final destination bytes are **80 C0 80 80 80 80 80 80 00**.
- Offset 8 is written first.
- The remaining writes occur at offsets 7 down to 0.
- The upper result word equals the auxiliary word without masking.

This threshold example distinguishes the nine-byte layout from a nine-group, seven-payload-bit representation.

For V = 2⁶⁴ − 1, all nine destination bytes are **FF**. The final byte’s high bit remains set because all eight of its bits are payload.

### Zero is not an empty representation

For V = 0 and a valid destination, one byte is written. Returning count zero or leaving the destination untouched would not satisfy the established behavior.
