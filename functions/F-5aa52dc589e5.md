# F-5aa52dc589e5

## Purpose

F-5aa52dc589e5 performs an alias-sensitive transformation of indirectly addressed storage, prepares selected fields of an outgoing region, and attempts an external continuation. No application-level purpose is established.

Its principal behavioral constraints concern **capture timing, access width, and write order**. Values used as payloads also become addresses or arithmetic operands. A captured value survives later changes to its source; a fresh observation must reflect intervening effects.

Two bytes are consumed without represented prior initialization. The contract therefore describes conditional static relationships, not a guarantee of defined execution or successful completion.

| Second argument | Opaque 32-bit value | No represented use |
| Third argument | Signed 32-bit integer | Displacement for the initial halfword destination |

The first argument addresses fields at byte offsets +0x09, +0x54, and +0x64. There is no validation separating its address and data interpretations.

No result value or ordinary successful-return path is established.

### Inherited inputs and storage

The representation also depends on:

- Three signed 32-bit address-bearing values, termed **primary**, **secondary**, and **original work**.
- An opaque 32-bit **inherited payload**.
- An inherited callable target.
- Sixteen ordered external word sources used during the transformation.
- An additional external word source read during the continuation.
- Stack-associated storage termed the **outgoing region**.

**Current work** initially equals original work. Later work changes do not redirect accesses explicitly tied to original work.

Two outgoing fields participate before outgoing preparation:

| Byte offset | Role |
|---:|---|
| +0x34 | **Retained selection**, repeatedly observed as an address-bearing word |
| +0x108 | **Late selection**, established during the final arithmetic-dependent phase |

These fields are storage, not immutable parameters. Indirect writes may overlap them. References to their current contents must be distinguished from previously captured contents.

### Widths and execution conditions

Explicit memory accesses occupy one, two, or four bytes. Narrowing a four-byte observation afterward does not reduce its readability requirement.

Address-forming halfwords are signed 16-bit values promoted to signed 32-bit values. Character observations occupy one byte; their promotion depends on character signedness. Negative character-derived addresses are consequently possible.

Address arithmetic, additions, and multiplications are represented using signed 32-bit values. Defined signed arithmetic requires representable results; modular overflow is not established. Left shifts require valid operands as well as representable results. In particular, representable doubling does not make left-shifting a negative signed value valid.

Execution requires suitable storage, permitted alignment, meaningful integer-to-address conversions, valid arithmetic, and compatible callable targets. Bounds checks, recoverable errors, and fault-to-status conversion are not represented.

## Behavior

### Capture and delivery invariants

The transformation contains sixteen **delivery events**, numbered here solely to identify relationships between effects. They are not calls or atomic transactions.

Each event has a provider, work participant, replacement base, external word source, and recipient. Four ordering constraints apply:

- The provider’s +0x44 word is captured before the work participant receives its own address at +0x54.
- The recipient is selected from the external source after that self-address write.
- The replacement base’s +0x44 word receives an external-source value before payload delivery.
- The captured provider word is delivered to recipient +0x14.

Replacement cannot alter an already captured payload, and it does not cause recipient reselection.

The representation separately references the external source for recipient selection and replacement data. No represented store separates those references. Stable ordinary memory therefore supplies equal values, but an exact physical load count, volatile semantics, or asynchronous modification model is not established.

The initial provider is secondary. Thereafter the preceding recipient normally supplies the provider, with three exceptions:

| Event | Exceptional provider selection |
|---:|---|
| 9 | Through +0x14 of the payload captured for event 8 |
| 13 | Through +0x74 of the payload captured for event 12 |
| 14 | Through +0x74 of a separately captured current-work +0x44 word |

Replacement bases have independent capture histories. Event 1 uses primary. Events 2–4 use separately captured original-work fields; events 5–7 use saved recipient +0x14 words. Events 8–9 use work +0x44 captures, events 10–12 use promoted character observations, and events 13–16 again use work +0x44 captures.

These rules permit extensive overlap. A self-address write can change the subsequent external-source observation. A replacement can affect later events without changing its own captured recipient or payload.

### Initial effects and original-work relationships

The initial writes have this strict order: secondary +0x14 receives the first argument as a word; original work +0x11 receives its byte conversion; primary +0x09 receives a byte conversion of secondary; and secondary displaced by the third argument receives a halfword conversion of primary.

Only afterward is secondary +0x44 captured for event 1.

Early halfword addressing generally involves two distinct accesses. A signed halfword is observed at the sum of original work and a recipient. That promoted value then contributes to a recipient-relative halfword destination. It must not be treated as a displacement loaded directly from the eventual destination.

The early data relationships include:

- Event 1’s payload supplies first-argument +0x09.
- First-argument +0x64 is observed independently between events 1–2, 2–3, and 4–5. The middle observation remains saved across event 3.
- A saved original-work +0x14 word supplies both halfword data and event 2’s replacement base.
- Separately captured original-work +0x44 words supply address-bearing byte destinations, halfword data, and replacement bases.
- The inherited payload supplies the complete word at first-argument +0x54 and, separately, a byte at recipient 3 +0x0D.
- Recipient 2 +0x09 receives a byte conversion of original work. Recipient 3 +0x01 receives its own byte conversion.
- Captured original-work-derived addresses receive recipient-derived bytes at +0x0D and +0x09.

Original work +0x11 is updated repeatedly between these observations. Some updates derive from original work shifted left once; others use saved word conversions. Their position relative to halfword observations matters under overlap.

After event 4, a word selected at +0x44 relative to a signed-halfword-derived base is retained for a later +0x64 observation. Recipient 4 +0x14 independently supplies halfword data and event 5’s replacement base.

Between events 5–6, **one four-byte observation supplies two separate writes** of the same byte to original work +0x11. Between those writes, a captured original-work +0x44 address receives recipient 5 at +0x44, and further selections are observed. The saved event-5 payload also receives original work at +0x54 before the first equal-byte write. Neither equal values nor repeated destinations permit deleting an effect from the contract.

### Retained selection and independent work changes

After event 6, retained selection is established from a +0x44 word selected through a signed-halfword-derived base.

The following observations remain distinct: recipient 6 +0x14, a previously selected address’s +0x64 word, retained-selected +0x04, and recipient 6 +0x74.

Retained-selected +0x04 is a **four-byte observation**. Its complete value is stored at original work +0x54; its saved byte conversion is used after event 7. The intervening event-7 self-address write does not invalidate that saved conversion.

The halfword destination in this interval is recipient 6 plus **twice original work**, not recipient 6 plus the preceding signed-halfword value. The saved recipient-6 +0x14 word supplies both its data and event 7’s replacement base.

The saved recipient-6 +0x74 word has several independent uses:

- Two distinct writes to retained-selected +0x54.
- An address-bearing +0x54 destination receiving the then-current retained selection.
- A byte later written at recipient 9 +0x1D.

The two retained-selected writes occur on opposite sides of event 8. Their destinations depend on the retained selection observed for each use, not necessarily its initial value.

Work selection is independent of provider selection. Recipient 7 +0x14 selects event 8’s work participant; recipient 8 +0x14 selects the participant used for events 9–12. Each newly selected participant can receive a recipient-derived +0x0D byte before its delivery event.

Changing work does not refresh an already captured displacement or replacement base. Event 8 still uses the original-work +0x44 capture obtained earlier. Event 9 uses its exceptional provider selection while retaining a displacement obtained before that selection.

### Character-dependent addressing and shared payload

Three intervals obtain characters from addresses combining a signed-halfword result with a saved forwarding payload. Each promoted character supplies halfword data and an address-bearing replacement base. Character-derived +0x0D destinations also occur.

Character signedness therefore affects both stored values and access destinations.

A retained-selected +0x64 observation supplies an entire word to +0x54 relative to a signed-halfword-derived base. Other retained-selected +0x64 observations supply separately saved bytes. These observations are neither width-equivalent nor interchangeable.

Recipient 10 +0x64 establishes a **shared payload**, distinct from retained-selected observations. Before event 12, this payload is stored at recipient 11 +0x44. A character-relative byte write and a displaced halfword write intervene before that field is captured. Consequently, event 12’s payload need not equal the shared payload.

Before event 13, provider selection through saved-payload +0x74 and work selection through old-work +0x14 are independent. A captured old-work +0x44 word supplies a byte destination, halfword data, and replacement base.

Before event 14, a saved forwarding address receives recipient-derived data at +0x15, and recipient +0x44 receives that forwarding value. Provider selection instead follows +0x74 through the separately captured work +0x44 word. The previously obtained displacement still applies.

### Sum-addressed writes and missing byte initialization

The intervals preceding events 15 and 16 each store the shared payload as a word at the sum of a recipient and a saved forwarding payload.

Each sum-addressed write precedes replacement of recipient +0x14. Replacing that field does not change the saved sum operand. Each interval separately observes shared-payload-relative +0x44 to obtain a byte for recipient +0x0D.

Both intervals select new work through +0x14 relative to a signed-halfword-derived base. A separately captured old-work +0x44 word supplies:

- A +0x54 destination receiving that word itself.
- The new work participant’s +0x0D byte.
- Displaced halfword data.
- The following replacement base.

Before the second work change, the saved forwarding address receives old work at +0x54. Old work +0x11 then receives a byte without represented prior initialization, before the captured old-work +0x44 address receives the recipient at +0x44.

That byte is assigned only after event 16, using an earlier retained-selected +0x64 observation, and is then written to the new work participant. The later assignment does not initialize the earlier consumption retroactively.

### Final arithmetic-dependent selection

After event 16, current-work +0x44 is captured. A signed halfword observed at current work plus the final recipient becomes both a **multiplier** and an independent address-bearing base.

Two multiplicative paths must remain distinct:

- Multiplying the multiplier by the captured work word initiates successive word selections through +0x44, +0x74, and +0x14.
- The resulting participant’s old +0x14 word is saved before that field receives current work shifted left once. A subsequent multiplication uses a +0x14 observation through the **saved old word**, not through the replacement.

The latter multiplication establishes an intermediate base. Its +0x74 word establishes late selection. Multiplying the intermediate base by the multiplier establishes the **product-derived base**.

Five writes of the multiplier to multiplier-relative +0x54 occur during this phase. The first two are interleaved with two writes of the current-work byte conversion to final-recipient +0x11. Further self-address writes precede the saved-old-word byte, the second prematurely consumed byte, and the later twice-product-derived byte effect. Intervening alias-sensitive accesses prevent collapsing these writes.

Final-recipient +0x11 thus receives four ordered writes: two current-work conversions, the saved-old-word conversion, and a byte without represented prior initialization.

The remaining capture constraints are:

- Product-derived +0x44 and retained-selected +0x74 are captured before final-recipient +0x64 receives the current late-selection word.
- Final-recipient +0x09 uses the saved product-derived capture.
- Product-derived +0x11 uses a fresh +0x44 observation after those recipient writes.
- The fifth multiplier-relative self-address write precedes observation of late selection for the byte at twice the product-derived base plus +0x11.
- A further word is captured at +0x44 relative to multiplier times product-derived base before final participant selection through retained-selected +0x14.
- Late-selection-relative +0x01 receives the saved retained-selected +0x74 byte before the final selected participant receives +0x11 and then +0x09.
- Those last two bytes derive respectively from the further product-dependent capture and twice the product-derived base.

The second prematurely consumed byte is assigned from late selection only after its earlier use.

## Acceptance examples

These are conditional static acceptance criteria, not executed tests or claims of defined whole-invocation reachability.

1. **Initial overlap:** With a third argument of +0x44, the initial halfword write overlaps secondary +0x44. Event 1’s capture must reflect that preceding write according to the applicable byte order.

2. **Capture lifetime:** Overwriting a provider after capture does not change the payload already scheduled for delivery. A later fresh capture may observe the overwrite.

3. **External-source overlap:** A work self-address write overlapping an external source can affect recipient selection. A later replacement overlapping that source cannot reselect the already captured recipient.

4. **Width and signed addressing:** A four-byte observation later narrowed still requires four readable bytes. Halfword pattern 0xFFFF contributes −1. Character pattern 0x80 contributes −128 with signed eight-bit characters or 128 with unsigned characters, affecting destinations as well as data.

5. **Repeated writes:** The two original-work +0x11 writes between events 5–6 reuse one saved byte. They remain separate effects despite equal data.

6. **Independent histories:** A work change does not redirect the halfword destination based on twice original work. Replacing a participant’s +0x14 does not redirect the later lookup through its saved old word.

7. **Full-word preservation:** A designated retained-selected +0x64 observation of 0x12345678 supplies that complete word to the signed-halfword-derived +0x54 destination, not merely 0x78.

8. **Forwarding freshness:** The shared-payload store at recipient 11 +0x44 does not guarantee that event 12 captures the same value when intervening writes overlap that field.

9. **Partial outgoing preparation:** With stable retained selection 0x1234, stable late selection 0x7000, valid shifts, and no interference, +0x10 and +0x24 receive 0x12340; copies of shifted +0x34 receive 0x123400; late-selection copies receive 0x7000. Unlisted bytes are not initialized by this preparation.

10. **Call-boundary freshness:** If F-unresolved-1 changes the additional external source and returns, the later observation determines F-cdec09f5d432’s first argument, subject to the intervening outgoing writes.

11. **Missing initialization and termination:** Neither prematurely consumed byte may be substituted with zero or its later assigned value. A nonreturning dependency prevents subsequent interactions. Return from both principal calls reaches the trap-associated sequence, not a documented successful return.
