## Behavior

### Arithmetic, conversions, and memory layout

The representation contains 8-bit, 16-bit, and 32-bit memory accesses. Narrow stores select the low-width representation of their source values. Endianness and the precise language-level handling of out-of-range signed narrowing conversions are not independently established.

Several arithmetic categories must remain distinct:

1. **Unsigned 32-bit address addition.** Argument 4 plus `0x0E` is computed using unsigned 32-bit arithmetic. The result wraps modulo \(2^{32}\) before pointer conversion. This arithmetic is defined even when the addition crosses the unsigned maximum. Whether the resulting pointer is meaningful, aligned, or writable is a separate unknown.

2. **Unsigned shift and negation.** The late right shift of Argument 4 is logical and produces an unsigned 32-bit quotient from `0` through `8191`. Unary negation also occurs in unsigned 32-bit arithmetic. Its result is zero when the quotient is zero; otherwise it is \(2^{32}\) minus that quotient. The possible unsigned results are therefore zero or values from `0xFFFFE001` through `0xFFFFFFFF`.

3. **Subsequent unsigned-to-signed conversion.** That unsigned negation result is assigned to a signed 32-bit retained value, called the “negative index” below. For nonzero quotients, the unsigned result exceeds the signed 32-bit maximum. Its conversion is **documented_only** unless the execution environment’s conversion rule is supplied. Under a rule mapping these unsigned bit patterns to their corresponding two’s-complement signed values, the negative index equals the mathematical negative of the quotient and lies from `-8191` through `0`. That range is conditional, not an unconditional property of the unsigned negation.

4. **Early signed conversion and shift.** The early address calculation first converts Argument 4 to signed 32 bits, then shifts right by 19. For inputs above the signed maximum, the conversion requires an environment-specific rule. Right shifting a negative signed value likewise requires specified execution semantics. This is distinct from the later unsigned shift.

5. **Other signed arithmetic.** Signed address additions, subtraction, the stack word’s left shift, and its later multiplication by eight do not receive a blanket modulo-\(2^{32}\) interpretation. Overflow and invalid signed-shift cases remain unresolved.

The apparent 32-bit address model does not establish actual pointer representation, address-space permissions, or access alignment.

### Zero-destination continuation

When the first result-derived destination is zero, continuation occurs only after the preceding store through address zero has completed.

The represented sequence is:

1. Convert Argument 4 to signed 32 bits, shift that signed value right by 19, add `0x44`, and read a 32-bit word at the resulting address.
2. Write the byte value `4` at Argument 3 plus `0x18`.
3. Subtract Argument 3 from the word just read. Retain the signed 32-bit difference.
4. Write Argument 3 narrowed to a byte at the signed interpretation of the first result’s high 32-bit portion plus `5`.
5. Invoke F-00cd69d10a06.
6. Invoke F-indirect-03 at the target represented by `0x083FDD85 + 0xC8A`, obtaining the second represented 64-bit result.
7. Add `0x0E` to Argument 4 using unsigned 32-bit addition, convert that wrapped result to a pointer, and write the difference narrowed to 16 bits there.
8. Write the low byte of the second result’s low portion at the signed interpretation of that portion plus `0x15`.
9. Read a 32-bit word at the difference plus `0x44`.
10. Invoke F-ae8d1f6d3d67 with three visible arguments:
    - The stack word shifted left by three.
    - The second result’s high 32-bit portion converted to signed 32 bits.

11. Write the low byte of the word read in step 9 at the sum of the signed interpretation of the second result’s low portion, `0xBE`, and the register value exposed after F-ae8d1f6d3d67.
