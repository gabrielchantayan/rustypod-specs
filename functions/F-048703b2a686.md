# F-048703b2a686

## Purpose

F-048703b2a686 conditionally populates a buffer of 16-byte records in two passes:

1. Generate position and length fields from sequential input positions, segment repetition counts, and fixed or per-record lengths.
2. Directly initialize the first record’s timing-like field to zero, then populate subsequent timing-like fields using accumulated increments and F-870c4fcf7295.

“Position,” “length,” and “timing-like” describe observed use, not established application semantics.

A preliminary dependency selects between population and an early branch that invokes an indirect callback. The two branches return different packed 64-bit results.

The function does not establish input validity, allocation capacity, ownership, dependency purity, or termination. Descriptor reads are partly live rather than universally snapshotted; aliasing and dependency mutation can therefore affect traversal.

## Interface

### Arguments and representation

The visible interface accepts:

- An object reference.
- An uninterpreted 32-bit auxiliary word, used only in the early-return result.

The supplied representation uses 32-bit integer fields and 32-bit address values. It does not establish an equivalent layout for wider native pointers.

### Output records

F-4eab532db66c returns the address retained as the output base. No capacity accompanies that address in the visible interface.

| Offset within each 16-byte record | Direct behavior |
|---|---|
| `0x00` | Not written. |
| `0x04` | Generated position, written as 32 bits. |
| `0x08` | Selected length, written as 32 bits. |
| `0x0C` | Zero or a 32-bit result from F-870c4fcf7295. |

The output base is not refreshed after dependency calls.

### Result

The return value is a packed 64-bit word:

- Preliminary result zero: auxiliary word in the upper 32 bits, `3` in the lower 32 bits.
- Population completes: snapshotted unsigned total position count in the upper 32 bits, zero in the lower 32 bits.

The normal result does not report the generated-record count, consumed-position count, or number of timing-field writes.

## Behavior

### Preliminary branch

The function reads object offset `0x1BC` and passes that word to F-db0662b8cd7c.

If the result is zero, it:

1. Reads the object’s dispatch-table address.
2. Reads the callable entry at dispatch-table offset `0x24`.
3. Invokes that entry with the object reference.
4. Returns the early-branch packed result.

This branch directly accesses neither the population descriptors nor the output buffer. Effects of the preliminary dependency and callback remain unconstrained.

A nonzero result selects population. The indirect callback is not explicitly invoked on that path.

### Initial snapshots and output acquisition

After the preliminary dependency returns nonzero, the function captures these values in order:

1. Target record count from the length descriptor.
2. Fixed length from the length descriptor.
3. Unsigned total position count from the position-list descriptor.

It then rereads object offset `0x1BC` and calls F-4eab532db66c.

These two reads of `0x1BC` are distinct. The second need not equal the value passed to F-db0662b8cd7c.

The three captured population values remain unchanged for the first pass even if the output-address dependency mutates their backing fields. The total-position snapshot also supplies the normal return’s upper half. Other addresses and fields are read later as described below.

### First-pass segment selection

The generated-record count, consumed-position count, and segment index begin at zero.

The first pass continues while the generated-record count is less than the snapshotted target, using a signed comparison. This test occurs only between complete segment iterations.

At the start of each reached segment iteration, the function reads the current segment-descriptor address and its signed segment count. It compares the next segment index with that count minus one:

- When a following segment exists according to this comparison, it reads the current segment-array address, then the current boundary and following boundary. Their difference determines the span.
- Otherwise, the span is the snapshotted total position count minus the consumed-position count.

The resulting 32-bit span is used as a signed loop bound.

Boundary values do not directly select an input-array index. Positions are consumed sequentially, starting at the consumed-position count. For a non-final segment, only the difference between adjacent boundaries determines how many positions are visited.

The span is retained for that segment iteration. Later output aliasing does not cause it to be recomputed.

### First-pass base positions and live repetition bounds

For each base-position iteration whose index is less than the span:

1. Read the object’s current position-list descriptor address.
2. Read that descriptor’s current position-array address.
3. Read the base position at the consumed-position count plus the within-span index.
4. Retain that base position and reset its position offset and repetition index to zero.

The base position is read even if the subsequent repetition count permits no repetitions.

**Before every repetition-condition evaluation, including the terminating evaluation, the function rereads:**

1. The object’s segment-descriptor address.
2. That descriptor’s segment-record-array address.
3. The current segment’s signed repetition count.

It compares the current repetition index against this newly read count. The count is not captured once per segment or once per base position.

Consequently, an output write that aliases the descriptor pointer, record-array pointer, or repetition-count field can affect the very next repetition check. Changing a pointer can also redirect that check or make its access invalid. The next check still occurs after a repetition has brought the generated-record count to or beyond the first-pass target.

### First-pass record writes

For each admitted repetition:

- A nonzero snapshotted fixed length supplies the selected length, including when negative.
- Otherwise, the function reads the current length-descriptor address and its current per-record-length-array address, then selects the entry indexed by the generated-record count.

The selected length is obtained before either output write.

The function then:

1. Writes the retained base position plus its current offset to the current record’s `0x04` field.
2. Advances the generated-record count.
3. Adds the selected length to the retained position offset.
4. Writes the selected length to that same record’s `0x08` field.
5. Advances the repetition index before reevaluating the live repetition bound.

The position write precedes the length write. Both use values already selected for that repetition; aliasing does not retroactively change the selected length or retained base position.

Each new base position starts with offset zero. In variable-length mode, the length-array index nevertheless continues across all generated records.

After the base-position loop, the function adds the span to the consumed-position count and advances the segment index.

### First-pass target and progress limits

There is no target check inside either the base-position loop or repetition loop. A segment can generate more records than requested, and the output allocation must cover actual generation rather than merely the target.

There is also no independent segment-index limit. Zero or negative spans and repetition counts can prevent record generation without satisfying the outer target condition. A negative span skips base-position processing but is still added to the consumed-position count.

A positive target therefore does not establish progress, bounded traversal, or valid accesses.

### Timing-like field initialization

After the first pass ends, the function directly writes zero to output record zero at offset `0x0C`.

This write occurs even when a zero or negative initial target skipped all position and length generation.

It then reads object offset `0x134` and calls F-870c4fcf7295 with that word and `100`. The 32-bit result is retained as the second argument for subsequent transformation calls.

The zero write precedes this call. Neither that call nor subsequent calls are established to preserve the output buffer, so the initialization does not establish record zero’s final value.

### Increment-run traversal

The cumulative increment starts at zero, and the next output-record index starts at one.

For every outer run-condition evaluation, including termination, the function rereads the object’s increment-run-descriptor address and that descriptor’s signed run count.

For every repetition-condition evaluation, including termination, it rereads the increment-run-descriptor address, its record-array address, and the current run’s signed repetition count.

For each admitted repetition:

1. Reread the increment-run descriptor and its record-array address, then read the current run’s increment.
2. Add that increment to the signed 32-bit cumulative value.
3. Reread the object’s length-descriptor address and its current target count.
4. If the next output-record index is less than that current target, call F-870c4fcf7295 with the cumulative value and retained initial result.
5. On normal return from that call, advance the output-record index and write the returned 32-bit word to the selected record’s `0x0C` field.

The eligibility test precedes the transformation call and is not repeated before the write. A dependency-induced target change during that call does not cancel the already selected write.

The cumulative increment advances even when no write is eligible. Run traversal does not stop merely because the current target has been reached. Dependency mutations and aliased output writes can affect later descriptor reads, bounds, increments, and eligibility decisions.

If too few eligible repetitions occur, some timing-like fields remain directly unwritten. Timing eligibility is not constrained by how many position/length records the first pass generated.

### Completion

After run traversal, the function returns the normal packed result. It performs no reconciliation among generated records, timing writes, consumed positions, or the current target.

## Side effects

### Direct writes and ownership

Direct writes are limited to output-record offsets `0x04`, `0x08`, and `0x0C`. The visible body makes no explicit assignment to an object descriptor field and performs no explicit allocation or release.

This does not establish that descriptors or input arrays remain unchanged. The retained output address may alias them, and dependencies may mutate shared memory.

No ownership transfer is established. Allocation, retention, release, invalidation, and lifetime effects inside dependencies are documented_only.

### Validity requirements and errors

For a defined, terminating execution, external contracts must provide:

- Valid storage for every descriptor and array element actually reached, including live terminating-condition reads.
- A writable output buffer, including record zero’s timing-like field even for a nonpositive initial target.
- Capacity for first-pass overshoot and every eligible timing write.
- Sufficient per-record lengths in variable-length mode.
- Segment and run data that permit valid, terminating traversal.
- Arithmetic and address calculations valid for the execution environment.

No visible null check protects the returned output address. No explicit validation rejects malformed counts, boundaries, lengths, addresses, or insufficient capacity.

The preliminary zero/nonzero decision is the only explicit alternative result selection. Other dependency failures are not visibly translated into separate error results.

### Integer behavior

Counts, indices, base positions, selected lengths, position offsets, and cumulative increments use 32-bit operations. Principal loop comparisons are signed.

The total-position count is unsigned. Boundary subtraction and total-position subtraction involve unsigned 32-bit arithmetic; their results are subsequently used as signed spans. The precise conversion of an out-of-range unsigned result to a signed span is not established as a portable rule.

No explicit checks protect:

- Signed count adjustments or index increments.
- Position and cumulative-increment additions.
- Span conversion or boundary ordering.
- Multiplication by the 4-, 8-, 12-, and 16-byte strides.
- Address additions.

Negative nonzero fixed lengths select fixed-length mode. Negative base positions and increments are not explicitly rejected.

The contract does not replace these operations with unbounded mathematical arithmetic or assume that every signed overflow wraps. Behavior outside valid arithmetic and address ranges is documented_only.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless an example specifies aliasing, assume valid non-aliasing memory, stable input descriptors and arrays, in-range arithmetic, normal dependency returns, and no dependency mutation of the output buffer.

### Preliminary zero result

If F-db0662b8cd7c returns zero and the auxiliary word is `0x11223344`:

- The indirect callback is invoked once with the object.
- Neither F-4eab532db66c nor F-870c4fcf7295 is directly called.
- The return pattern is `0x1122334400000003`.

This does not constrain effects performed by the callback.

### Fixed and variable lengths

With target four, fixed length three, one segment repeating twice, total position count two, and base positions ten and twenty, the position/length writes are:

- `(10, 3)`
- `(13, 3)`
- `(20, 3)`
- `(23, 3)`

The normal return is `0x0000000200000000`.

With fixed length zero and per-record lengths `2, 5, 7, 1`, the pairs instead are:

- `(10, 2)`
- `(12, 5)`
- `(20, 7)`
- `(27, 1)`

The position offset resets for the second base position; the length-array index does not.

### Target overshoot

With target three, one final segment spanning two base positions, and stable repetition count two, four records are generated before the target is checked again. Stopping after three would not match the observed behavior.

### Aliased live repetition bound

Suppose target and fixed length are both one, the final segment spans one base position, and its repetition count initially equals three.

Allow one deliberate alias: the current segment’s repetition-count field occupies exactly output record zero’s length-field address. All other relevant storage remains valid and unaffected.

The first repetition writes length one into that shared word. On the next repetition-condition evaluation, the function rereads the descriptor address, array address, and count. The repetition index is now one and the newly read bound is one, so repetition stops.

Exactly one position/length record is generated. Capturing the initial count of three would produce a different result.

### Timing accumulation

With timing target four and runs consisting of two increments of five followed by one increment of seven:

- The function directly writes zero to record zero’s timing-like field before any F-870c4fcf7295 call.
- Following the initial call, subsequent calls receive cumulative first arguments `5`, `10`, and `17`.
- Their returned words are directly written to records one, two, and three.

Under the stated output-preservation assumption, record zero remains zero. Without that assumption, only the direct zero write and its ordering are established.

A fourth repetition with target still four accumulates its increment but causes no further transformation call or timing write.

### Nonpositive initial target

With initial target zero and a nonzero preliminary result:

- Position and length generation is skipped.
- Output acquisition still occurs.
- Record zero’s timing-like field is directly written as zero.
- The initial F-870c4fcf7295 call still occurs.

If the timing target remains zero, run repetitions cause no per-record transformation calls, although their increments are still accumulated.
