## Behavior

### Dependency notation

F-D01 through F-D27 are opaque dependency identifiers for call groups. Numbered suffixes identify call positions within a group, not independently resolved implementations. Different occurrences may resolve to the same underlying function.

Three recurring call structures are used below:

- **Four-call result group:** four calls without explicit arguments; only the fourth ordinary result is subsequently consumed.
- **Five-call handoff:** one call receiving the stated arguments, followed by a four-call result group. The fifth call supplies the group result.
- **Nine-call preparation:** an initial call receiving the stated arguments; a call without explicit arguments producing a word; a call consuming that word; another call without explicit arguments producing a word; a call consuming the second word and any stated extra argument; then a four-call result group.

An unused ordinary result does not imply an effect-free call. “Without explicit arguments” describes the representation only; live registers or other implicit inputs may still matter.

Every call is an ordering boundary. No dependency is assumed to preserve globals, relevant memory, or resources.

### Entry and initial calls

The first direct effect is a 32-bit store of the incoming payload at:

\[
4 \times \text{second argument} + 0x14.
\]

The function then reads a 32-bit word from the incoming address-bearing state plus `0x14`. This captured value is the **entry word**. Later entry-derived values use this snapshot, not a fresh read.

F-D01 is a nine-call preparation. Its initial arguments, in order, are:

1. Four times the second argument.
2. The second argument.
3. The original third argument.
4. The second argument again.

Neither consuming call in this group has an additional explicit argument.

After F-D01, the incoming payload is stored again at the initial address. F-D02 then performs a five-call handoff receiving four times the F-D01 result. Its result is the **first index**.

### Selector-mediated byte writes

A selector-mediated write comprises two distinct accesses:

1. Read an unsigned byte at the specified selector location.
2. Write a byte at the zero-extended selector value plus `0x11`.

The destination therefore ranges from `0x11` through `0x110`. It is not generally the selector location. Every described occurrence rereads the selector.

Initially, the selector location is the first selector base plus one. The following events occur in order:

| Stage | Required behavior |
|---|---|
| First selector write | Store the low byte of the F-D20 result shifted left by two through the selector. |
| F-D21 | Seven calls: an initial call receiving that shifted result three times; a no-explicit-argument call producing a word; a call consuming that word; then a four-call result group. |
| Second selector write | Store the low byte of `(F-D20 result & 0x3fffffff) >> 20` through a fresh selector read. |
| F-D22 | Five-call handoff receiving the F-D21 result shifted left by two. |
| Direct byte write | Store the low byte of the F-D22 result shifted left by two at `(entry word >> 31) + 0x1c`. |
| Selector clearing | Reread the first selector and write zero at its selected destination. |
| F-D23 | Seven calls: an initial call receiving `entry word >> 31`; a call without explicit arguments; a call receiving `(F-D22 result & 0x3fffffff) >> 6`; then a four-call result group. |
| Repeated selector clearing | Reread the first selector and write zero at its selected destination. |
| F-D24 | Five-call handoff receiving the F-D23 result shifted left by two. |

The direct byte-write destination is exactly `0x1c` or `0x1d`, according to the entry word’s most significant bit.

A **later selector location** is derived from the F-D22 result shifted left by two, multiplied by `0x400`, then increased by one. This address calculation retains the signed-arithmetic uncertainty already described.

The **initial loop quantity** is:

\[
(\text{F-D24 result} \mathbin{\&} 0x3fffffff) \gg 25.
\]

It ranges from zero through 31.

Before the loop, the later selector is read and zero is written at its selected destination. F-D25.1 then receives twice the initial loop quantity. F-D25.2 has no explicit arguments and supplies the initial **carried result**.

### Unconditional loop and target transition

The loop executes at least once if reached.

F-D26.1 has a represented target-address transition independent of its changing arguments:

| Invocation | Represented target address |
|---|---|
| First loop iteration | `0x08833787` |
| Every subsequent iteration reached through the loop tail | `0x088337c5` |

The first target uses target-address state established immediately before loop entry, before F-D25.2. The loop tail replaces that state with the value selecting the subsequent target. These are distinct represented addresses; the evidence does **not** establish that they resolve to different underlying functions.

Each iteration contains these ordered effects:

1. F-D26 performs a five-call handoff. F-D26.1 receives the carried result and the current loop quantity logically shifted right by eight, using the iteration-appropriate target above.
2. The later selector location is reread, and zero is stored at its selected destination.
3. F-D27 performs a five-call handoff initially receiving the F-D26 result shifted left by two.
4. The next carried result is the F-D27 result shifted left by two.
5. The next loop quantity is the F-D27 result shifted left by 26.
6. Execution repeats without an explicit exit condition.

The loop-tail target state is replaced before the final call of F-D27; it selects F-D26.1 on the next iteration. The later selector address remains derived from the earlier F-D22 result and is not recomputed from the carried result.

On the first iteration, F-D26.1 necessarily receives zero as its second explicit argument. Later values depend on the loop-tail arithmetic and dependency results.
