# F-0065f3f52141

## Purpose

F-0065f3f52141 repeatedly invokes indirect dependencies and modifies memory using global values, dependency results, narrow selectors, and implicit machine state. Each iteration contains a software breakpoint. No normal return or loop-termination condition is represented.

The established contract is an ordered set of calls and memory effects. Application-level purpose is unknown: the evidence does not identify an initialization routine, device protocol, object model, or ownership scheme.

Everything after a dependency invocation, memory access, or breakpoint is conditional on that operation completing and permitting continuation. The unconditional loop does not establish that execution actually completes even one iteration.

## Interface

### Entry and completion

There are no declared explicit parameters and no declared ordinary return value. Inputs nevertheless include:

- Two 32-bit global storage locations, identified here as global A at `0x087120b4` and global B at `0x08712120`.
- An implicit frame-base-like value used for word accesses and subsequently decreased.
- An implicit register-like value contributing to a late byte destination.

- Memory reached through these values, fixed addresses, and dependency results.
- Implicit dependency outputs not represented as ordinary return values.

There is no represented validation of these inputs.

### Widths and interpretation

Direct memory operations have widths of 8, 16, or 32 bits. Addresses and the arithmetic values used to construct them are represented as 32-bit quantities.

Three dependency results are represented as 64-bit values. Each is consumed as separate low and high 32-bit words; this does not establish a native 64-bit calling convention or a semantic relationship between the words.

Unsigned 16-bit reads are zero-extended for subsequent wider use. Narrow writes retain the destination-width portion of their source. In particular, converting a retained address-like value to a halfword does not preserve the entire address.

The two shifts of the second paired result’s low word are explicitly unsigned: right by 26 bits and left by two bits. Other arithmetic includes signed-looking shifts, additions, and multiplications. Their low-32-bit machine interpretation is useful for conditional examples, but exact overflow behavior is **documented_only**, not established independently of the supplied representation.

Byte order, alignment requirements, access atomicity, and memory-region permissions are unknown.

A continuing execution requires valid indirect call targets, valid memory accesses, and compatible dependency behavior. These are operational prerequisites, not checks performed by this function.

No assumption is made that a dependency preserves globals, implicit registers, frame state, memory, or ownership. Statements below about retained values describe the supplied static data flow; they are not independent calling-convention guarantees.

## Behavior

### Ordering model

F-D01 through F-D37 are opaque identifiers assigned to call occurrences in execution order within one iteration. Their numeric order specifies their relative invocation order. They do not imply 37 distinct implementations: some targets may coincide.

F-D01 receives two explicit zero arguments. Its target depends on incoming control-address-like state during the first iteration. Near the end of an iteration, that state is assigned a fixed value, making subsequent F-D01 targets fixed under the represented data flow. Equality between the first target and later targets is not established.

All other displayed call targets are constructed from fixed numeric values. “No explicit arguments” means none are displayed; it does not exclude implicit machine-state inputs.

### Initial globally based updates

Global A is read after F-D03 and before F-D04. Its value is retained as the base for two later byte writes.

F-D05 supplies the first paired result. F-D06 receives its low word as one argument and a high-word-plus-low-word sum as the other; the additional byte term shown in that sum is zero. After F-D06, an auxiliary byte output is written at offset `0x11` from the retained global-A base.

F-D07 separates that write from a zero-byte write at offset `0x15` from the same base. Neither store rereads global A. A dependency’s change to global A therefore does not itself redirect these stores in the represented data flow.

F-D08 supplies a 16-bit ordinary result. That result is written at offset `0x0c` from an auxiliary address available after the call. The auxiliary address is not established to be the ordinary return value, an owned allocation, or related to global A.

### Second paired result and frame-derived destination

F-D09 supplies the second paired result. Before F-D10, a zero halfword is written at its high word plus `0x2c`, followed by a word write at frame offset `0x26c`. The latter contains its low word logically shifted right by 26, so the stored value is between 0 and 63.

After F-D10, a destination base is read from frame offset `0x320`. Following F-D11 and F-D12, the second paired result’s low word, shifted left by two, is written at offset `0x54` from that retained base. The unsigned shift discards the original top two bits.

These operations do not shift the complete 64-bit result. The high word supplies an address for one write; the low word independently supplies two transformed values.

### First selector and breakpoint boundary

After F-D13 through F-D17, an unsigned halfword is read at address `0x21c48994`. F-D18 follows that read.

A word at frame offset `0x280` is then read and passed to F-D19. Breakpoint `0x92` occurs after F-D19 and before all remaining memory effects in the iteration.

If execution resumes, the F-D19 result is scaled by four for a later address. A word is read at the first selector plus `0x44`; this word becomes a retained base for several late stores.

The selector is the zero-extended halfword itself. No additional table base or pointer reconstruction is represented. Thus its associated word reads may address low memory.

### Global-B-dependent halfword update

F-D20 precedes F-D21, whose 32-bit result becomes the first argument to F-D22. The second argument is a word read at the first selector plus `0x04`, after F-D21 and before F-D22.

Global B is read after F-D22 and before F-D23. Following F-D23, a halfword is written to the retained global-B value plus four times F-D19’s result. The written bits are the low 16 bits of the retained global-B value.

The same retained global value contributes both destination and payload. Its storage location is not reread for the store, even though F-D23 intervenes. The write width remains 16 bits despite the 32-bit address construction.

### Fixed-address read and second selector

After F-D24, a word is read at address `0x2218`. This address follows from logically shifting `0x21c48960` right by 18 bits, multiplying the result by four to obtain `0x21c4`, and adding `0x54`.

F-D25 supplies a destination address. A halfword containing `0x21c4` is written at that destination plus `0x04`, before F-D26.

After F-D26 and F-D27, an unsigned halfword is read at offset `0x34` from the base previously read at `0x2218`. This is the second selector. It is retained before F-D28 and later used directly in address arithmetic, not as an index into the object from which it was read.

### Third paired result and frame-state transition

F-D28 supplies the third paired result. Its low word is first written at frame offset `0x258`. An unsigned halfword is then read at its high word plus `0x14`.

Before F-D29, the represented frame-base-like state decreases by `0xf4`. A word containing the third result’s low word is also written at four times the second selector plus `0x74`.

The frame-relative write uses the frame value before the decrement. There is no represented compensating increment before the loop repeats. Under an interpretation in which this is persistent 32-bit machine state and intervening execution does not otherwise alter it, frame-relative addresses move downward by `0xf4` per iteration. Whether this is an actual stack adjustment is unresolved.

The third result additionally supplies two retained arithmetic values: its low word shifted left by six, and its high word multiplied by four. Unlike the earlier explicitly unsigned shifts, these operations require caution about the target environment’s signed-arithmetic interpretation.

### Final writes and byte transfer

The halfword read through the third result’s high word is zero-extended to 32 bits. After F-D29 it is written at offset `0x54` from the retained base obtained through the first selector. After F-D30 it is written again at that base plus `0x64`. The writes are separate and have an intervening dependency call.

Following F-D31, a halfword containing the low 16 bits of that retained base is written to an address combining the third result’s low word shifted left by six with an auxiliary address output. No ordinary-return-value interface for that auxiliary output is established.

After F-D32 and F-D33, one byte is read at five times the second selector. F-D34 intervenes before the byte is written to a destination comprising:

- The zero-extended halfword read through the third result’s high word.
- The implicit register-like input.
- An additional offset of `0x19`.

The byte source is not reread after F-D34. The destination calculation does not use the second selector.

After F-D35, four times the third result’s high word is written as a word at retained-base offset `0x44`. F-D36 follows. The fixed control-address-like value for the next iteration is then established.

Finally, a word is read at four times the third result’s high word plus `0x44` and passed to F-D37. This read is not necessarily from the location of the preceding word store: the store uses the retained base, whereas the read uses the scaled high word. The next iteration begins if F-D37 returns normally.

## Acceptance examples

These are conditional static examples, not executed tests.

1. **Two independent unsigned shifts.** If F-D09’s low word is `0xfc000003`, the frame-offset-`0x26c` write contains `63`, and the later destination-offset-`0x54` write contains `0xf000000c`.

2. **Narrow global-dependent payload.** If global B reads as `0x12345678` and F-D19 returns `3`, the halfword destination is `0x12345684` and the payload is `0x5678`, assuming valid memory and continued execution.

3. **Selectors are not reconstructed pointers.** If the second selector is `7`, its word-write destination is `0x90`, and the later byte source is address `35`. No unrepresented base is added.

4. **Zero extension matters.** If the halfword read through F-D28’s high word is `0xffff`, the two full-width writes at retained-base offsets `0x54` and `0x64` contain `0x0000ffff`, not `0xffffffff`.

5. **An intervening global mutation does not redirect a retained base.** If global A initially supplies one base and F-D04 subsequently changes global A, the two initial byte stores still use the previously read base under the represented data flow.

6. **Byte transfer observes the earlier read.** If F-D34 changes the source byte after it was read, the destination receives the earlier byte, provided continuation preserves the state needed for the represented transfer.

7. **Breakpoint continuation is conditional.** If breakpoint `0x92` does not resume this function, none of the post-breakpoint reads, writes, or dependency invocations occur on that execution.

8. **Wrapping arithmetic is conditional evidence.** If F-D05’s low word is `0xffffffff` and its high word is `2`, F-D06’s second argument is `1` under low-32-bit wrapping addition. This example does not independently establish the target’s signed-overflow semantics.
