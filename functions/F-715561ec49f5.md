# F-715561ec49f5

No application-level purpose is established. The arithmetic may suggest packed values or encoded addresses, but the evidence does not establish serialization, allocation, decoding, device access, or object initialization.

## Behavior

### Ordering and call-sequence terminology

All described calls and direct memory operations retain their displayed order. Calls may observe or modify memory; repeated stores and repeated byte reads must not be collapsed.

The following descriptions identify sequence shapes, not dependency identities:

- **Result-forwarding pair:** a call with no displayed arguments produces a primary result, which is supplied to the immediately following call. Additional arguments are identified where present.
- **Four-call acquisition:** four successive calls with no displayed arguments; the fourth call’s primary result is consumed.
- **Five-call transfer:** a call receiving the specified value, followed by four calls with no displayed arguments. Ordinarily the fifth call’s primary result is consumed. The secondary-result case below is an explicit exception.

“No displayed arguments” does not establish absence of machine-level inputs. Likewise, an unused primary result does not establish absence of other outputs or effects.

The function then reads an unsigned word from the inherited read base plus 20. If this address overlaps the preceding store, the read occurs after that store; its value depends on the actual overlap, byte order, and memory behavior.

The first indirect call receives the first and second arguments, in that order. Its target is derived from the inherited control-address value by adding 3810.

Two result-forwarding pairs follow, then a four-call acquisition. Before forwarding the acquisition result, the function stores the previously read word shifted right by eight at the second argument plus 20. It does not reread that word after the intervening calls.

Four times the acquisition result begins a five-call transfer. Its final primary result is the **first index**. The function stores four times this index at sixteen times the index, plus 20.

A five-call transfer then begins with the seed shifted right by eight. After its final call, but before forwarding its result, the function stores four times the first index at four times that index, plus 20. This destination differs from the preceding sixteen-times-index destination.

Four times the latest transfer result begins another five-call transfer. Its final result is the **second index**. The function stores four times the second index at sixteen times that index, plus 20.

A five-call transfer begins with the payload. At four times its final primary result, plus 20, the function stores the same payload.

Four times that result begins another five-call transfer. Its final result is the **fifth index**. Four times the fifth index is stored at sixteen times that index, plus 20.

Four times the acquisition result begins a five-call transfer. Its final result is the **sixth index**. The function retains four times this index as the **retained word** and stores it at sixteen times the sixth index, plus 20.

A call receives the retained word. Two result-forwarding pairs and a four-call acquisition follow. The function stores the seed shifted right by sixteen at four times the acquisition result, plus 20.

Four times that acquisition result begins another five-call transfer. Its final result is the **seventh index**. Four times the seventh index is stored at sixteen times that index, plus 20.

The next call receives:

After store 1, a call receives four times the first byte-source word in all three displayed argument positions. A result-forwarding pair and a four-call acquisition follow before the fresh lookup and store 2.

Four times that acquisition result begins a five-call transfer. Its final unsigned result is the **second byte-source word**. Store 3 follows, then the fresh lookup and store 4, with no intervening dependency call between those two stores.

A call then receives the seed shifted right by twenty-three. One further call with no displayed arguments follows. Another call receives the second byte-source word masked with 0x3fffffff and shifted right by six. A four-call acquisition follows before the fresh lookup and store 5.

This separate lookup address is retained for the loop. Its contents are not cached.

### Unconditional loop

A call receives twice the initial loop field. A following call with no displayed arguments produces the initial **carried result**.

Each iteration then performs the following ordered interactions:

- A call receives the carried result and the current loop field shifted right by eight.
- A four-call acquisition follows.
- The function rereads the separate lookup byte and stores zero at the byte value plus 17.
- Four times the acquisition result begins a five-call transfer.
- Four times that transfer’s final primary result becomes the next carried result.
- That same final result shifted left by twenty-six becomes the next loop field.

The first carried result is used without the four-times scaling applied to subsequent carried results.

The represented target for the first loop-head call differs from the target used on subsequent iterations. Identical argument shapes must not be taken as proof of identical callees.

The first iteration’s second argument is necessarily zero: its loop field is at most 31. On later iterations, that argument is the preceding transfer result’s low six bits shifted left by eighteen, under the stated 32-bit model.

There is no visible termination condition.

## Acceptance examples

These are conditional arithmetic and ordering checks, not runtime observations.

1. **Entry aliasing.** If the first word-store address exactly equals the following word-read address, and memory behaves as ordinary coherent storage, the read obtains the just-stored entry word. The later right-shifted store derives from that captured read, not a reread after dependency calls.

2. **Third-argument shift.** With a third argument of 0xffffffff, the fourth argument of the later four-argument call is 0x0003ffff. Using only one seven-bit shift would not match the displayed behavior.

3. **Distinct word layouts.** For a first index of 3, the initial indexed store writes 12 at address 68. The later store associated with that same first index writes 12 at address 32. Both stores are required.

4. **Secondary-result arithmetic.** For a secondary result of 0x40, multiplication by \(2^{24}\) produces 0x40000000. Multiplication by \(2^{26}\) wraps to zero. The resulting store writes the word 0x40000000 at address 20, provided that address is writable.

5. **Byte narrowing.** For a first byte-source word of 0x3ff00000, masking and shifting right by twenty produces 0x3ff. Store 2 writes 0xff, discarding the intermediate value’s upper two bits.

6. **Fresh lookup selection.** If the lookup byte is 2 for one access and an intervening dependency changes it to 9, the corresponding destinations are 19 and 26. Caching the earlier byte would violate the represented read ordering.

7. **Seventh-index overwrite.** For a seventh index of 3, the earlier store writes 12 at address 68. After the intervening calls, the later store writes 48 at that address.

8. **Loop arguments.** An initial loop field of 31 still supplies zero as the first iteration’s second argument. If a later transfer result is 0x41, the next carried result is 0x104 and the next loop-head second argument is 0x00040000.

9. **Access counts and continuation.** If execution completes the prefix and one loop iteration without faults or dependency diversion, direct accesses total 18 word stores, seven byte stores, one word read, and six byte reads. Execution then continues rather than returning success.
