# F-b087d25b0445

## Purpose

F-b087d25b0445 conditionally appends bytes from a descriptor-selected source to an inline destination buffer, writes a zero-byte terminator, and updates the destination’s recorded length.

The admission check compares an unsigned 32-bit expression against 201. Under ordinary nonnegative, nonoverflowing inputs whose relevant fields remain unchanged, this permits a resulting payload length of at most 199 bytes. The apparent intent is to maintain a terminated buffer with a 200-byte data area. That capacity is inferred intent, not an allocation size established by the supplied evidence.

The operation is a byte append, not a string append: source zero bytes are copied and counted. No source terminator is sought.

## Interface

| Input | Required interpretation |
|---|---|
| Destination address | Address of a writable object beginning with a 32-bit length field. Inline byte storage begins four bytes after this address. |
| Descriptor address | Address of an object with a 32-bit count-like field at byte offset 4 and a 32-bit source-address field at byte offset 8. No access to offset 0 is shown. |

The destination’s length field supplies the starting byte index into the inline storage. It is not the object’s allocation size.

Two global storage locations also participate:

- **Scale global:** a 32-bit integer used in calculating the number of bytes to append.
- **Rejection-result global:** a 32-bit value returned when the admission check fails.

- On the rejected path, it returns the value read from the rejection-result global.

The evidence does not establish that the rejection-result global is nonzero. Return value zero therefore does not, by itself, unambiguously prove that an append occurred.

## Behavior

### 1. Capture a scale value

The function first reads the scale global and retains that value for use by the copying loop.

The admission expression separately references the scale global. The retained scale and the scale used for admission must not be assumed equal if that global can change between accesses.

No explicit synchronization is shown. This description does not establish language-level support for concurrent mutation.

### 2. Evaluate admission

The admission expression combines:

- The scale global as referenced by the admission expression.
- The descriptor’s 32-bit count field.
- The destination’s current 32-bit length.
- An unsigned addition of one.

The resulting unsigned 32-bit value must be strictly less than 201 for execution to continue to the append path.

For stable, nonnegative values without intermediate signed overflow, the rule is:

**existing length + scale × descriptor count + 1 < 201**

The extra one reserves a position for the terminator under the inferred buffer-layout intent.

This rule is not equivalent to a general bounds check:

- It does not inspect the actual destination allocation.
- It does not reject negative operands explicitly.
- It does not inspect source allocation size.
- It does not establish that later reads will return the same values.
- It does not independently check the starting destination index.

The supplied expression performs signed multiplication and signed addition before its final unsigned addition. The unsigned comparison is established; the original-language semantics of overflowing signed intermediates are not. Conclusions that depend on signed overflow are therefore documented_only rather than portable guarantees.

Within a 32-bit wrapping interpretation, unsigned addition can also make a large or negative-derived total appear small. The admission test must not be treated as proof of memory safety for such inputs.

### 3. Reject without destination writes

If admission fails, the function reads the rejection-result global and returns that value.

No payload write, terminator write, or destination-length update appears on this path. The source-address field is not needed on this path.

The rejection result is read when rejection is taken; it is not a value captured at entry.

### 4. Establish the destination cursor

After admission succeeds, the function reads the destination length again and uses that value as its local destination cursor.

Consequently, the cursor used for writing is not necessarily the length that participated in admission. Aliasing, external mutation, or other changes to observable memory could make these reads differ.

### 5. Copy bytes using a repeatedly evaluated bound

The source-byte index starts at zero.

Before each prospective iteration, including the first and the final terminating check, the function reads the descriptor count field and forms a product with the scale value retained at entry. That product is interpreted as an unsigned 32-bit loop bound.

While the current unsigned source index is below that bound, the function:

- Reads the source-address field from descriptor offset 8.
- Reads one byte at that address plus the current source index.
- Writes that byte to the destination’s inline storage at the current destination cursor.
- Advances the destination cursor by one and the unsigned source index by one.

The source byte is read before its corresponding destination byte is written. No whole-source snapshot is made.

Two consequences are material:

1. **The count field is not captured once.** A change to that field can shorten or extend the operation relative to its initially apparent count.
2. **The source address is not captured once.** Different iterations can read through different source addresses if the descriptor field changes.

The loop uses the entry-time scale snapshot, whereas admission uses a separate scale-global reference. Admission and copying therefore need not use the same product.

With stable fields, nonnegative operands, and representable arithmetic, the function copies exactly the product of the retained scale and descriptor count. With changing fields or overlapping storage, the actual copy count is determined by the successive loop-bound evaluations.

### 6. Terminate and commit the length

When the loop ends, the function performs these writes in order:

1. Writes a zero byte at the destination inline-storage position selected by the final local cursor.
2. Writes the final cursor value into the destination’s 32-bit length field.

It then returns zero.

The recorded length counts copied bytes but excludes the terminator. A copied zero byte still contributes to that length.

The length update is deferred until copying and termination complete. A fault or interruption during copying can therefore leave changed payload bytes with the old recorded length. A fault after the terminator write but before the length write can leave a terminated payload with an uncommitted length.

No rollback behavior is shown.

### Zero-byte append

If the first loop-bound evaluation is zero, the loop performs no source-byte read and does not read the descriptor’s source-address field.

The accepted path still:

- Writes a zero byte at the starting cursor.
- Writes that cursor into the length field.
- Returns zero.

Thus an accepted zero-byte append is not a write-free operation.

### Overlap and aliasing

No nonoverlap restriction is enforced, and no overlap-safe copying mechanism is shown.

Copying proceeds forward, one byte at a time. If an earlier destination write changes a source byte needed by a later iteration, that later read observes the changed byte under ordinary sequential memory behavior.

More extensive aliasing can affect control or final state:

- Payload writes can change the descriptor count or source-address field if those objects overlap.
- Payload writes can change global storage if the destination overlaps it.
- A terminator written into the length field can subsequently be overwritten by the final length update.
- A starting cursor outside the intended data area can direct writes into the header or unrelated storage.

These are consequences of the accesses shown, not supported normal-use conventions.

### Accepted zero-byte operation

### Forward-overlap propagation

Given a zero destination length, scale 1, count 3, and a source beginning one byte before the destination data area, suppose that preceding byte contains a value called X.

If every access remains valid, the first iteration writes X into destination index 0. The next source read then reads that newly written byte, and the following iteration does likewise. All three copied destination bytes become X.

This distinguishes the operation from snapshot-based or overlap-preserving copying.

### Zero-valued rejection result
