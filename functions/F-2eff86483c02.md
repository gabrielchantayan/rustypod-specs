# F-2eff86483c02

## Purpose

F-2eff86483c02 conditionally replaces an object's backing region, transfers its current contents, and rebases stored positions onto the replacement region.

The established behavior is a sequence of eligibility checks, dependency calls, and field updates. Its apparent intent is to support replacement by either a caller-supplied region or a newly allocated region, while retaining relative positions within the data. Allocation, ownership-policy adjustment, content transfer, and possible disposition of the previous region are delegated operations; their complete semantics are not established here.

There are three normal return paths:

- When both the replacement address and requested extent are zero, return the object address without inspecting the object.
- When an eligibility check fails, return zero without proceeding to replacement.
- Otherwise, complete the replacement sequence and return the object address.

The function does not establish that a successful return means allocation, transfer, or previous-region disposition succeeded. It does not inspect status results from those operations.

## Interface

### Inputs

The interface has four 32-bit inputs:

| Input | Interpretation established by use |
|---|---|
| Object address | Address of a writable object containing fields through byte offset `0x2b`. Also returned on the no-op and completed-replacement paths. |
| Replacement address | Address supplied for the replacement region. Zero selects the allocation path whenever the operation is not the all-zero no-op. |
| Requested extent | Signed 32-bit value used in the eligibility comparison, passed to the allocation dependency when applicable, and stored in the object on completion. |
| Auxiliary word | An uninterpreted 32-bit value copied into local storage. The address of that local storage may be passed to a dependency associated with the previous region. |

The pointer-like inputs and object fields occupy 32 bits in the supplied representation. This does not establish portability to a wider address model.

### Return value

The return value is a 32-bit word interpreted as:

- Zero following an eligibility rejection.
- The original object-address input following the no-op or completed-replacement path.

A zero object-address input therefore makes return-value interpretation ambiguous: the all-zero no-op returns zero without performing an eligibility rejection.

No exception, fault, or nonlocal-exit contract is supplied for the dependencies.

### Preconditions

Except for the all-zero no-op, the object must support every access reached on the selected path. Valid storage must remain available despite intervening dependency calls.

For a normally completing replacement, the caller and dependencies must collectively provide:

- A replacement region suitable for the external transfer operation.
- A source region suitable for the transfer operation at the time its source address is read.
- Arithmetic and address values valid under the target execution model.
- Any required alignment, overlap, allocation, and lifetime conditions of the dependencies.

The function itself does not validate these conditions.

## Behavior

### 1. No-op selection

The function first examines the replacement-address and requested-extent inputs.

If both are zero, it returns the object-address input immediately. On this path:

- No object field is read or written.
- No dependency is called.
- The auxiliary word has no observable use within this function.
- A null or otherwise unusable object address is not dereferenced.

A zero extent alone does not select this path when the replacement address is nonzero.

### 2. Eligibility check

For every other input combination, the function creates a local 32-bit copy of the auxiliary word and calls F-14a841015476 with the object address.

It compares the requested extent with the result of that call using a signed 32-bit less-than comparison.

If the requested extent is smaller, the function immediately returns zero. In particular, the eligibility-flags field is not read by this function on that rejection path.

Otherwise, it reads the field at offset `0x04`. If bit `0x00000008` is clear, it returns zero.

These rejection paths perform no direct object writes. They are not guaranteed to leave the object unchanged, because F-14a841015476 has already executed and its side effects are unknown.

There is no independent nonnegative-extent check. A negative requested extent can pass the signed comparison if the first query result is no greater than it and the required flag is set.

### 3. Snapshot and second query

After eligibility succeeds, the function:

1. Reads and saves the 32-bit field at offset `0x10`.
2. Calls F-14a841015476 again with the object address.
3. Retains this second result for both the transfer call and the new primary-limit calculation.

The first and second query results serve different purposes. The first controls eligibility; the second controls subsequent work. The function does not compare them or repeat the capacity check.

Consequently, the function does not independently ensure that the second result fits within the requested extent.

The flags snapshot is taken before the second query. Later changes to the field at offset `0x10` do not change whether the previous-region dependency will be invoked.

### 4. Replacement selection and preparation

The function records whether the original replacement-address input was zero.

If it was zero, it calls F-871e64ddc6de with:

- The requested extent.
- A second argument of zero.

The returned 32-bit value becomes the replacement address. No explicit null-result check follows.

The function then calls F-cf4f89824645 with:

- The object address.
- A Boolean indicating whether allocation was selected.

That Boolean reflects the original replacement-address input, not whether allocation returned a nonzero address.

F-cf4f89824645 executes before the source backing-region address is read for transfer. Its side effects may therefore affect the source used in the next step.

### 5. Transfer and conditional previous-region handling

The function calls the external transfer dependency, identified here as F-U1, with three arguments:

1. The selected replacement address.
2. The backing-region address read from offset `0x08` after F-cf4f89824645 returns.
3. The second result from F-14a841015476.

F-U1's result, if any, is ignored.

The call shape is consistent with transferring a region from source to destination. Its precise contract—including count units, overlap handling, treatment of negative values, and partial-failure behavior—is not supplied.

If bit `0x00000001` was set in the saved flags snapshot, the function next calls F-6c292b887399 with:

- The address of the local auxiliary-word copy.
- The backing-region address freshly read from offset `0x08`.

The backing-region field is read again for this call. It is not guaranteed to equal the source address previously passed to F-U1 if an intervening dependency changed the object.

F-6c292b887399 executes before this function overwrites the backing-region field. Its result is ignored. The local auxiliary word is not subsequently used by this function.

### 6. Primary state replacement

After transfer and any conditional previous-region call, direct writes occur in this order:

1. Write the replacement address to offset `0x08`.
2. Write the requested extent to offset `0x0c`.
3. Read the current primary base from offset `0x20`.
4. Write the replacement address to offset `0x20`.
5. Read the primary position at offset `0x24`, subtract the saved primary base, add the replacement address, and write the result to offset `0x24`.
6. Add the second query result to the replacement address and write the result to offset `0x28`.

Thus, the primary position preserves its displacement from the primary base as those fields exist at this stage. The preserved displacement is not necessarily the one present at function entry: prior dependencies may have changed either field.

The calculation uses 32-bit operands and destinations. No range, overflow, underflow, or position-within-region check is visible. Exact behavior when signed arithmetic exceeds its representable range requires target-level information beyond the supplied representation.

### 7. Optional secondary rebasing

The function calls F-7febad47082c with the object address after the primary updates.

If that call returns zero, this function performs no secondary-field writes.

If it returns nonzero, the function:

1. Reads the current secondary base at offset `0x14`.
2. Reads the current backing-region address at offset `0x08` and writes it to offset `0x14`.
3. Rebases the secondary position at offset `0x18` by subtracting the saved secondary base and adding a fresh read of offset `0x08`.
4. Copies the current primary limit at offset `0x28` into offset `0x1c`.

These values are read after F-7febad47082c returns. Its possible mutations must not be ignored: the secondary updates are not unconditionally based on the replacement address and limit previously written by this function.

The function then returns the original object-address input.

## Side effects

### Memory and state

Direct object writes occur only after the transfer and conditional previous-region operation. The primary field group is updated first; the secondary group is updated only after a nonzero result from F-7febad47082c.

The function provides no rollback. A dependency failure, memory fault, or nonlocal exit can leave effects from earlier dependencies or earlier field writes in place.

Intermediate state can include:

- Transfer or previous-region processing completed while the object's backing address still has its prior value.
- A replaced backing address and extent while position fields remain unrevised.
- Updated primary fields before the optional secondary decision.

No synchronization or atomic replacement guarantee is established.

### Ownership and lifetime

Allocation selection is explicit, but ownership transfer is not fully specified.

- A zero replacement address selects F-871e64ddc6de.
- F-cf4f89824645 receives the allocation-selection Boolean.
- The saved bit at offset `0x10` controls F-6c292b887399.

These facts do not establish that F-cf4f89824645 sets an ownership bit, that F-6c292b887399 frees memory, or that caller-supplied storage becomes owned by the object.

F-6c292b887399 receives an address into this function's local storage. That storage does not have an established lifetime beyond the call to F-2eff86483c02. Retention by the dependency would require a separate lifetime contract.

### Error handling

The only explicit rejection conditions are:

- Requested extent is signed-less-than the first query result.
- Eligibility bit `0x00000008` is clear.

There is no visible handling for allocation failure, transfer failure, previous-region handling failure, arithmetic overflow, or invalid addresses.

## Acceptance examples

These examples are conditional specifications, not runtime observations.

1. **All-zero no-op.** Given replacement address zero and requested extent zero, the result is exactly the supplied object address. No dependency calls or object accesses occur, even if the object address is zero.

2. **Signed-size rejection.** Given requested extent 15 and first query result 16, the result is zero. The function does not read the eligibility flags or make the second query. Effects of the first query remain possible.

3. **Flag rejection.** Given requested extent 16, first query result 16, and eligibility bit clear when read, the result is zero. No allocation, preparation, transfer, or direct field write follows.

4. **Caller-supplied region.** Assume a replacement address of `0x2000`, requested extent 64, both query results 12, required eligibility bit set, and dependencies that preserve relevant fields except for the transfer itself. If the primary base is `0x1000` and primary position is `0x1005`, completion writes backing address and primary base `0x2000`, extent 64, primary position `0x2005`, and primary limit `0x200c`. F-871e64ddc6de is not called.

5. **Allocated region.** Under the same stable-state assumptions, a zero replacement address and nonzero requested extent select F-871e64ddc6de. If it returns `0x3000`, that address is used for transfer and primary rebasing. F-cf4f89824645 receives true.

6. **Changed query result.** If the first query returns 8, requested extent is 8, and the second query returns 12, eligibility can pass. The transfer receives 12, and the primary limit uses replacement address plus 12. No second capacity rejection occurs.

7. **Snapshot-controlled processing.** If the saved flags word has bit `0x00000001` set and a later dependency clears that bit in the object, F-6c292b887399 is still called. Conversely, setting the bit only after the snapshot does not select that call.

8. **Secondary rebasing.** Assuming F-7febad47082c returns nonzero without altering the relevant fields, secondary base `0x4000` and position `0x4003` become replacement address and replacement address plus 3. The secondary limit becomes the primary limit. A zero result causes no direct secondary writes.

9. **Unchecked null allocation.** If allocation returns zero and subsequent operations return normally, no explicit rejection intervenes: zero is passed as the replacement destination and later stored. Whether those subsequent operations can safely return is unknown.
