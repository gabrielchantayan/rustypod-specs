# F-ca2785896f7f

## Purpose

F-ca2785896f7f coordinates construction of a result in externally supplied storage, tests that result, and conditionally performs a second construction attempt followed by two virtual operations.

The established behavior is an ordered sequence of dependency calls and explicit memory writes. The meanings of the constructed values, the result-test predicate, and the final virtual operations are not established. In particular, a nonzero predicate result selects further processing; it must not automatically be described as failure, emptiness, or invalidity.

The function has no explicit return value. Its observable results are writes through a dependency-provided storage pointer and whatever effects its dependencies perform.

## Interface

The function accepts four arguments:

| Argument | Established representation | Established use |
|---|---|---|
| A | 32-bit opaque value | Passed unchanged to F-603a53835f04, followed by three zero arguments. |
| B | Pointer to storage containing at least one 32-bit word | Passed to both construction dependencies. On the final branch, its first word supplies the object reference for virtual dispatch. |
| C | Pointer to a virtual-dispatch object | Used immediately to invoke the virtual entry at byte offset 8. That operation’s return value initializes a local context cell. |
| D | 32-bit opaque value | Copied into a local working-value cell before the initial virtual call. The cell is subsequently passed by address to construction and post-copy dependencies. |

The supplied representation uses 32-bit scalar words, 16-bit halfwords, and a 32-bit pointer model. These are properties of the supplied static representation, not a portable ABI promise.

The function creates two relevant local cells:

- A context cell, initially containing C and then replaced by the return value of the initial virtual call.
- A working-value cell, initially containing D.

Both cells are passed by address to dependencies. The function therefore exposes writable local state, rather than merely passing the cells’ current values.

A separate result-storage pointer is returned by F-603a53835f04. On every path that reaches the first construction result, the function writes four bytes through that pointer as two ordered 16-bit stores.

## Behavior

### 1. Initialize local state and obtain context

Before invoking any dependency, the function initializes the context cell from C and the working-value cell from D.

It then invokes the virtual entry at byte offset 8 through C, passing C as the receiver. The returned 32-bit value replaces the context cell.

The original C value is not used for another explicit dispatch by this function. Later context operations receive the address of the replacement cell.

The virtual operation’s concrete identity, return semantics, and side effects are unknown. Its result is used without a visible validity check.

### 2. Obtain result storage

The function calls F-603a53835f04 with:

1. A;
2. zero;
3. zero;
4. zero.

The returned value is treated as a pointer to writable 16-bit elements. The same captured pointer is retained for all explicit result stores, both predicate calls when applicable, and the final virtual operation when applicable.

This storage acquisition occurs before either context-reading dependency. It is not deferred until a construction attempt has succeeded.

The visible body does not determine whether this operation allocates storage, returns existing storage, exposes a view, or transfers ownership.

### 3. Read two context-derived values

The function performs two calls in this order:

1. F-70eba184e9ab receives the address of the context cell and the selector value 2. Its 32-bit return value is retained as the first extracted value.
2. F-65eb7f572de2 receives the address of that same context cell and the selector value 7. Its unsigned 32-bit return value is retained as the second extracted value.

The second call operates after all effects of the first call. Because both receive the context cell by address, the first may change the context observed by the second. The visible function neither restores the original context nor takes a separate context snapshot for each call.

The selectors are established numeric arguments. Their semantic meanings are unknown.

The two returned values are captured once. They are not recomputed if a later construction attempt or virtual operation changes the context or other state.

### 4. Perform the first construction attempt

The function calls F-5d7410a76c21 with:

1. the address of the working-value cell;
2. B;
3. the value 1.

The working-value cell contains D before this call unless an earlier dependency has changed relevant state through an otherwise unknown mechanism. The explicit interface gives this construction dependency the opportunity to replace or modify that cell.

After the call returns, the function publishes the cell’s current 32-bit contents into the retained result storage using two stores:

1. The low 16 bits are written at byte offset 0.
2. The high 16 bits are written at byte offset 2.

The first store precedes the second. The body does not perform an explicit single 32-bit publication. Therefore, the static contract does not provide an atomic-update guarantee.

These statements describe halfword values and offsets. Interpreting the resulting four bytes as a native 32-bit value additionally depends on the target’s byte order.

### 5. Perform post-copy processing, then test the result

After both halfword stores, the function calls F-9b718979506d with the address of the working-value cell.

Only after that call returns does it invoke F-ec61551795ee with the retained result-storage pointer.

The order is significant:

- The result-storage copy precedes F-9b718979506d.
- The predicate follows F-9b718979506d.
- The function does not explicitly recopy the working-value cell between those calls.

F-9b718979506d must not be assumed to release memory, preserve the cell, or leave shared state unchanged. Its address-taking interface and placement are established; its semantics are not.

If F-ec61551795ee returns zero, F-ca2785896f7f returns immediately. The second construction dependency and both final virtual operations are skipped.

Any nonzero return selects the next stage. No distinction among different nonzero values is visible.

### 6. Conditionally perform the second construction attempt

After a nonzero first predicate result, the function calls F-cd7148663427 with:

1. the address of the same working-value cell;
2. B;
3. the complete first extracted 32-bit value;
4. the complete second extracted unsigned 32-bit value.

The working-value cell is not visibly reinitialized from D before this call. It contains whatever remains after the first construction dependency and F-9b718979506d.

The full second extracted value is supplied here. Truncation to 16 bits occurs only in a later virtual call.

Following this second construction call, the function repeats the publication sequence:

1. Write the current working value’s low 16 bits at result-storage byte offset 0.
2. Write its high 16 bits at byte offset 2.
3. Call F-9b718979506d with the working-value cell’s address.
4. Call F-ec61551795ee with the retained result-storage pointer.

If this second predicate returns zero, the function returns without either final virtual operation.

The first result is thus explicitly overwritten before the second predicate. There is no visible rollback if later processing does not complete.

### 7. Conditionally perform two final virtual operations

If the second predicate is also nonzero, the function performs two virtual calls in order.

First, it obtains the receiver through the first 32-bit word at B and invokes that receiver’s virtual entry at byte offset 0x10. The explicit arguments after the receiver are:

- the first extracted 32-bit value;
- the second extracted value masked with 0xffff.

The mask produces a numeric value in the inclusive range 0 through 65,535. This is low-bit retention, not saturation or a range check. For example, 0x12345678 becomes 0x5678.

After the first virtual call returns, the function again obtains a receiver through B and invokes the virtual entry at byte offset 0x68. Its explicit argument after the receiver is the retained result-storage pointer.

The receiver is not captured once for both operations. If the first operation changes the object reference stored through B, the second operation uses the subsequently observed reference.

No explicit return values from these final virtual operations are used. The function then returns.

## Side effects

### Direct effects established by the body

The function:

- Reads C’s virtual-dispatch information for the initial call.
- Publishes one 32-bit working value as two ordered 16-bit stores.
- Repeats that publication at the same retained pointer only if the first predicate is nonzero.
- On the final branch, reads through B for each of two separate virtual dispatches.
- Passes addresses of mutable local cells to dependencies.

No direct write through B is visible in the function body. Dependencies receiving B may nevertheless modify its referenced storage.

### Dependency-mediated effects

All invoked dependencies may have additional effects not specified by the supplied body. In particular, this contract does not assume that they:

- Preserve global state.
- Preserve the context or working-value cells.
- Preserve the object reference reachable through B.
- Allocate, retain, transfer, or release ownership.
- Leave aliased result storage unchanged.

There are no visible non-aliasing checks. If result storage overlaps memory reachable through B or through another dependency, explicit stores and dependency effects may interact. The independent-storage case must not be generalized into an unconditional non-aliasing guarantee.

### Errors and incomplete execution

There is no explicit error return, exception handler, rollback, or compensating action. If a dependency fails to return normally, the visible function provides no additional recovery behavior.

For example, both result halfwords have already been written when the following F-9b718979506d invocation begins. Failure during that call does not have a visible rollback path.

## Acceptance examples

These are conditional static acceptance examples, not executed tests. They assume valid memory and normally returning dependencies.

### First predicate stops processing

Suppose the first construction dependency leaves 0x12345678 in the working-value cell, and the first predicate returns zero.

Required behavior:

- Store 0x5678 at result-storage byte offset 0.
- Then store 0x1234 at byte offset 2.
- Invoke F-9b718979506d before the predicate.
- Do not call F-cd7148663427.
- Do not perform either final virtual operation.

The post-copy dependency may have additional effects; the example specifies the explicit stores, not an unconditional final byte snapshot.

### Second construction replaces the first result

Suppose the first predicate is nonzero, the second construction leaves 0xa1b2c3d4 in the working-value cell, and the second predicate is zero.

Required behavior:

- Execute both construction dependencies.
- Publish the second value at the same retained storage pointer, low halfword 0xc3d4 first and high halfword 0xa1b2 second.
- Perform a post-copy call and predicate for each publication.
- Skip both final virtual operations.

### Final-stage width distinction

Suppose the extracted values are 0x89abcdef and 0x12345678, and both predicates are nonzero.

Required behavior:

- F-cd7148663427 receives 0x89abcdef and the full 0x12345678.
- The virtual operation at offset 0x10 receives 0x89abcdef and the masked value 0x5678.
- The virtual operation at offset 0x68 follows and receives the retained result-storage pointer.

### Context mutation between reads

Required behavior:

- The function does not restore the initial virtual call’s returned context first.

### Receiver replacement between final operations

- Reusing a receiver cached before the offset-0x10 call would not match the visible behavior.
