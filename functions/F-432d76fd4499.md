# F-432d76fd4499

## Purpose

The available static representation describes a routine that performs a fixed sequence of address-derived memory accesses and ends at an invalid-instruction boundary. It exposes no ordinary result value.

The established behavior is a mixture of pointer chasing, stores of truncated addresses, writes to low numerical addresses, and updates to global storage. There is insufficient evidence to identify a legitimate application-level purpose. In particular, the representation does not establish that this is an initializer, a reset routine, or a coherent callable function.

**Evidence status:** the supplied representation explicitly reports bad instruction data, truncated control flow, and overlapping global symbols. This contract therefore distinguishes the represented access sequence from assumptions needed to interpret it as executable machine behavior. No runtime tests have been performed.

## Interface

### Explicit interface

The represented interface has no explicit parameters and no return value. It does not reach an ordinary return in the supplied body.

### Implicit entry state

The representation consumes three values whose initialization is outside the visible body:

| Contract name | Represented width | Use |
|---|---:|---|
| **Seed** | 32 bits, unsigned | Address arithmetic, bit extraction, and stored values |
| **Fragment** | 16 bits, signed | Construction of a two-byte global value |
| **Payload** | 32 bits | First memory write |

These names describe entry-state values, not declared arguments. Their physical locations, calling convention, and validity requirements are unknown. Calling the routine solely according to its apparent zero-argument signature does not establish meaningful values for them.

### Address and value model

The access descriptions below use the represented 8-, 16-, and 32-bit widths. Pointer values are represented as 32-bit quantities.

For clarity, derived addresses are described using a **32-bit wrapping interpretation**: arithmetic retains the low 32 bits, and narrowing stores retain the low 8 or 16 bits. This is a reconstruction assumption, not proof of the target machine’s execution semantics. Some displayed arithmetic uses signed intermediates; the supplied material does not establish overflow behavior, unaligned-access behavior, or valid pointer provenance.

The following entry-state and derived quantities are used:

- **Base address:** Seed shifted right by 22, numerically between 0 and 1,023.
- **Page address:** Seed multiplied by 4,096.
- **Lookup address:** twice the sum of:
  - bits 26–27 of Seed, interpreted as a number from 0 through 3; and
  - Seed multiplied by negative 16.
- **Object address:** obtained through two successive 32-bit pointer reads beginning at the lookup address.
- **Scaled object address:** Object address multiplied by 256.
- **Index:** bits 20–29 of the bitwise intersection of Seed shifted left by six and the scaled object address. Equivalently, mask that intersection with `0x3FFFFFFF`, then shift right by 20. Index is between 0 and 1,023.

The two object-pointer reads, and all accesses through derived addresses, require readable or writable target storage if execution is to reach the terminal boundary. The routine performs no visible validation of these requirements.

## Behavior

### Ordered access contract

The following sequence is the observable order established by the supplied representation. Each operation is reached only if preceding operations complete. Memory aliases must be honored; a later read is not necessarily a read of entry-state memory.

1. **Write Payload to the base address.**  
   Store 32 bits at the address obtained by shifting Seed right by 22.

2. **Write the page address to itself.**  
   Store the 32-bit page-address value at the page address.

3. **Write the page address at a second derived location.**  
   Starting at the base address, use a 32-bit-element index equal to Seed multiplied by 1,024, and store the page-address value there.

   Under the wrapping interpretation, the resulting destination is the base address plus the page address. This is a separate store even when it aliases an earlier destination.

4. **Read the object address through two levels of indirection.**  
   Read a 32-bit pointer at the lookup address. Then read another 32-bit value at the address supplied by that first pointer. The second value becomes the object address.

   Both reads occur after the first three writes. Those writes can therefore affect either pointer read if their storage overlaps.

5. **Store the truncated object address into an object-relative field.**  
   Write the low 16 bits of the object address at object address plus `0x38`.

6. **Form the scaled object address.**  
   Multiply the object address by 256. This creates an address value; it does not read the memory located there.

7. **Update a two-byte global.**  
   Construct a 16-bit value with:
   - a low byte equal to the low eight bits of Seed shifted left by four; and
   - a high byte obtained by narrowing Fragment shifted left by two to 16 bits, then taking that quantity’s upper byte.

   Under a bit-vector interpretation, the high byte is bits 6–13 of Fragment’s 16-bit representation.

   This defines the numerical 16-bit value. Its byte order in memory is not established by the supplied material.

8. **Write a constant byte through the scaled object address.**  
   Store `0x78` at the scaled object address.

9. **Store the scaled object address at a fixed displacement from itself.**  
   Write a 32-bit pointer value equal to the scaled object address at that address plus `0x08526A78`.

   The displacement is part of the represented address calculation. It must not be treated as evidence that the destination is the same storage as the two-byte global.

10. **Compute Index.**  
    Compute the bounded index described in the Interface section from the retained Seed and scaled object address. No memory read is required for this calculation.

11. **Read a global byte pointer, then use its pointed-to byte as an address.**  
    Read the pointer held by the byte-pointer global. Read one byte through that pointer. Zero-extend the byte to an address between 0 and 255, then store the 16-bit value twice Index at that address.

    This is not a store through the global’s pointer itself: the byte reached through that pointer supplies the final numerical destination address.

12. **Write an index-derived address to itself.**  
    At address Index multiplied by 16, store the 32-bit value Index multiplied by 16.

13. **Read another pointer.**  
    Read a 32-bit pointer at address Index multiplied by eight. Call this the **record address**.

14. **Write the truncated record address into a record-relative field.**  
    At record address plus `0x30`, store the low 16 bits of the record address.

15. **Clear the first two bytes of the record.**  
    Store a 16-bit zero at the record address.

16. **Write a record-relative 32-bit constant.**  
    At record address plus `0x1600`, store the 32-bit value `0x00001600`.

    The displacement is `0x1600` bytes because the represented pointer arithmetic advances `0xB00` elements of two bytes each.

17. **Reread one byte from the pointer-table location.**  
    Read an unsigned byte at address Index multiplied by eight. This is a fresh read, not an extraction from the pointer value obtained in step 13.

    Intervening writes can have changed the byte at this address. Its value is therefore not guaranteed to equal any byte of the earlier pointer read.

18. **Use that byte to select a 256-byte-spaced destination.**  
    Multiply the byte read in step 17 by 256 to obtain the **byte destination**. Store the byte itself at that destination.

19. **Overwrite the same byte destination from another location.**  
    Read one byte at address Index multiplied by 128, then write it at the byte destination.

    The first store remains part of the contract. If the source of this second store aliases the byte destination, the read observes the value written in step 18.

20. **Clear the reset-associated global.**  
    Assign zero to the global identified as reset-associated in the supplied representation.

    The displayed assignment establishes the zero value, but not the storage width or the global’s architectural role.

21. **Write a final truncated address value.**  
    At address Index multiplied by 512, plus `0x38`, store the low 16 bits of Index multiplied by 512.

22. **Reach the invalid-instruction boundary.**  
    The representation terminates at an operation reporting bad instruction data. No ordinary return or continuation is shown.

### Arithmetic boundaries

Index’s bound provides several exact ranges independent of wrapping:

- Twice Index is between 0 and 2,046 and fits in the 16-bit store.
- Index multiplied by eight is between 0 and 8,184.
- Index multiplied by 16 is between 0 and 16,368.
- Index multiplied by 128 is between 0 and 130,944.
- Index multiplied by 512 is between 0 and 523,776.
- The byte destination is one of the 256 multiples of 256 from 0 through 65,280.

The final stored value is deliberately narrower than its source calculation. For example, Index equal to 128 makes Index multiplied by 512 equal to 65,536, whose low 16 bits are zero. The corresponding destination remains 65,536 plus `0x38`; destination calculation is not narrowed to 16 bits.

## Acceptance examples

These are conditional static acceptance cases, not executed tests. Each assumes the relevant accesses succeed and uses the 32-bit wrapping interpretation where necessary.

### Initial store ordering with zero Seed

With Seed equal to zero:

- The base address and page address are both zero.
- The first three writes all target address zero.
- Payload is written first, followed by two 32-bit zero writes.
- The subsequent first pointer read also occurs at address zero.

For ordinary memory with no intervening external modification, that pointer read therefore obtains zero. The next pointer read is again at address zero and also obtains zero. An interpretation that reads the original entry-state pointer at address zero would violate the represented ordering.

This example does not assert that address zero is accessible on the actual target.

### Construction of the two-byte value

If Fragment’s 16-bit representation is `0x1234` and Seed’s low byte is `0xAB`, the constructed global value is `0x48B0`:

- Fragment shifted left twice and narrowed to 16 bits gives `0x48D0`; its upper byte is `0x48`.
- The low eight bits of Seed shifted left four are `0xB0`.

This example specifies a numerical value, not a memory byte order.

### Maximum Index

If Seed and the scaled object address have all bits 20–29 set in the required intersection, Index is 1,023.

Consequently:

- The 16-bit value in step 11 is 2,046.
- The self-addressed 32-bit store in step 12 targets 16,368 and stores 16,368.
- The final store targets 523,832 and stores `0xFE00`.

These consequences depend on execution reaching those operations.

### Record-table aliasing

If the record address read in step 13 equals Index multiplied by eight, step 15 clears the first two bytes at the location from which that pointer was read.

For ordinary memory, absent another overlapping modification, the byte reread in step 17 is then zero. The byte destination becomes address zero. Reusing a byte cached from the earlier pointer value would not satisfy the contract.

### Source and destination aliasing during the byte copy

If the byte read in step 17 is one, the byte destination is 256. If Index is two, the later source address is also 256.

Step 18 first writes one to address 256. Step 19 then reads that same location and writes the observed one back. It does not copy the value that address 256 held before step 18.

### Failure before the terminal boundary

If the first write faults, the represented sequence provides no basis for claiming that any later write, global clear, or terminal operation occurs. There is no visible compensating action.
