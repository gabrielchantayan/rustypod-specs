# F-0b15473377c2

## Purpose

F-0b15473377c2 is a nonterminating, call-driven state transformation. It repeatedly invokes unresolved dependencies, derives addresses and values from their results, performs byte and 32-bit memory accesses, and carries selected results into the next iteration.

The supplied static representation establishes the sequence of direct memory operations and the explicitly represented arguments to dependency calls. It does not establish a domain-level purpose such as allocation, device configuration, decoding, or synchronization. Such interpretations are not part of this contract.

There is no visible return, termination condition, input validation, or error-recovery path. Completion of one iteration leads directly to another iteration.

## Interface

### Explicit inputs

The represented interface has four arguments:

| Position | Width | Established use |
|---|---:|---|
| First | 32 bits | Passed to the first dependency invocation; replaced before subsequent iterations. |
| Second | 32 bits | Passed to the first dependency invocation; replaced before subsequent iterations using an unresolved secondary result. |
| Third | 32 bits | No explicit read in the supplied body. |
| Fourth | 32 bits | Initially contributes to a byte value; replaced with an internally computed value before the next iteration. |

The first argument is presented as signed, the fourth as unsigned, and the middle arguments as unspecified 32-bit values. These annotations do not establish the actual external calling convention.

### Additional entry state

The body also consumes state not represented by the four explicit arguments:

- A 32-bit working base, initially used to locate a selector byte.
- A 32-bit working value, initially written to memory and later shifted for a dependency argument.
- A link-like entry value that determines the first indirect call target.
- A secondary call-result value used to supply the second argument of the next iteration.
- A directly read 32-bit global word.

The working base and working value are explicitly replaced near the end of each iteration. Their initial values are undocumented prerequisites.

The first indirect target depends on the incoming link-like value plus a fixed displacement of 4094. The body assigns a replacement link-like value before the next iteration. Thus the first iteration and later iterations need not select that call target in the same way.

### Output and completion

There is no normal return value. Observable outputs are:

- Dependency invocations.
- Direct byte and 32-bit memory writes.
- Direct memory reads, including selector reads and a global-word read.
- State carried between iterations.
- Any additional effects of dependencies.

An execution fault, a dependency that does not return, or externally imposed termination may prevent subsequent operations. No handling for these cases is visible.

### Width and address conventions

For describing the represented bit operations, let:

- `scale(value, n)` mean the low 32 bits of the value multiplied by \(2^n\).
- `field(value)` mean bits 20 through 27, interpreted as an unsigned byte.
- `selected(base)` mean: read one unsigned byte at address `base + 1`, then use that byte, zero-extended, as an address base.

A selected-byte write therefore targets `selected(base) + 17`, not `base + 17`. The resulting target lies between addresses 17 and 272.

These conventions describe 32-bit bit-vector behavior. The representation also contains signed arithmetic and signed shifts whose exact source-language semantics are not independently established. Machine-level wrapping, alignment, and fault behavior remain platform prerequisites, not portable language guarantees.

## Behavior

The following phases execute in order within every iteration, provided all preceding calls and accesses complete.

“No explicit arguments” means that the supplied representation shows none. It does not prove that the actual dependency ignores register state or other hidden inputs.

### 1. Initial calls and first two word writes

The first dependency receives the current first and second explicit arguments. Four further calls with no explicit arguments follow; the fourth supplies a 32-bit result, called the **first index** here.

The function writes the current working value as a 32-bit word at:

\[
20 + \operatorname{scale}(\text{first index},2).
\]

It then invokes a dependency with the scaled first index. Four further no-explicit-argument calls follow, the last supplying the **second index**. Define the **second scale** as the second index multiplied by four.

Next, the function:

1. Reads the selector at the current working base plus one.
2. Writes `field(fourth argument)` to the selected byte address.
3. Invokes a dependency with the working value shifted left by 12.
4. Makes a no-explicit-argument call.
5. Passes that call’s 32-bit result and the second scale shifted left by 28 to another dependency.
6. Makes a call represented as producing 64 bits.
7. Passes its low and high 32-bit halves to another dependency, in that order.
8. Makes two more no-explicit-argument calls, retaining the last result as the **third index**.
9. Re-reads the selector at the working base plus one and clears the newly selected byte.

The selector is not cached across this sequence. Intervening dependencies can change which byte is cleared.

The scaled third index is passed to a dependency. Four no-explicit-argument calls then produce a **fourth index**. Define the **fourth scale** as that index multiplied by four.

A 32-bit write stores the fourth scale at:

\[
20 + \operatorname{scale}(\text{second scale},12).
\]

The next dependency receives, in order:

- The second scale shifted left by 10.
- The same value again.
- The second index shifted left by 14.
- The fourth scale.

### 2. Repeated scaled-index writes

Four no-explicit-argument calls produce a **fifth index**. The fourth scale is written at `20 + scale(fifth index, 2)`, after which a dependency receives `scale(fifth index, 2)`.

Four more calls produce a **sixth index**. Define the **sixth scale** as that index multiplied by four. The function writes the sixth scale at `20 + scale(sixth index, 4)`. A dependency then receives three identical arguments, each equal to the sixth scale.

Four more calls produce a **seventh index**. The sixth scale is written at `20 + scale(seventh index, 2)`, followed by a dependency receiving the scaled seventh index.

Four more calls produce an **eighth index**. Define:

- The **eighth scale** as the eighth index multiplied by four.
- The **quadrant base** as the eighth index shifted left by 30.

The eighth scale is written at `20 + scale(eighth index, 4)`. A dependency receives the eighth scale three times.

Four more calls produce a **ninth index**. The eighth scale is written at `20 + scale(ninth index, 2)`, followed by a dependency receiving the scaled ninth index.

Under 32-bit wrapping, the quadrant base can only be zero, \(2^{30}\), \(2^{31}\), or \(3 \times 2^{30}\). It is not an unrestricted pointer.

### 3. Two pairs of direct byte clears

Four no-explicit-argument calls produce an unsigned **tenth result**.

The function directly clears two bytes, in this order:

1. `quadrant base + 17`.
2. `quadrant base + 1`.

These accesses do not use selector indirection.

A dependency receives the tenth result shifted left by two. A no-explicit-argument call follows, and its result is passed to another dependency.

Four more no-explicit-argument calls produce an **eleventh index**. The function repeats the same direct clears, again writing `quadrant base + 17` before `quadrant base + 1`. A dependency receives the eleventh index shifted left by two.

The repeated clears remain distinct observable writes. They cannot be collapsed merely because the values and addresses match.

### 4. Lookup read and publication of a high-bit value

Four no-explicit-argument calls produce a **twelfth index**. Define the **twelfth scale** as that index multiplied by four.

The function writes the ninth index shifted left by 31 to:

\[
20 + \operatorname{scale}(\text{twelfth index},4).
\]

It then performs a 32-bit memory read at:

\[
20 + ((\text{tenth result} \mathbin{\&} \texttt{0x3fffffff}) \gg 20).
\]

The offset is between zero and 1023. It is not multiplied by four and therefore need not be word-aligned.

A dependency receives the twelfth scale. A no-explicit-argument call supplies a **retained result**. The next dependency receives the lookup word shifted right by 22 and then left by 28.

Four no-explicit-argument calls produce a **thirteenth index**. The function writes a zero 32-bit word at `20 + scale(thirteenth index, 2)`, then calls a dependency with that scaled index.

### 5. Selector-based byte updates and cached-selector word write

Four no-explicit-argument calls produce an unsigned **fourteenth result**.

The function reads the selector at `quadrant base + 1` and writes the low byte of the fourteenth result shifted left by two at the selected byte address. It then:

1. Calls a dependency with the fourteenth result shifted left by two.
2. Makes a no-explicit-argument call.
3. Passes that result and the fourteenth result shifted left by 30 to another dependency.
4. Makes four no-explicit-argument calls, retaining the final **fifteenth index**.

The selector at `quadrant base + 1` is read again and cached. The function writes `field(fourteenth result)` at the cached selector plus 17.

A dependency receives the fifteenth index shifted left by two. Four no-explicit-argument calls follow. Their explicit return values are not used in the next direct write.

The retained result from the preceding phase, shifted left by two, is written as a 32-bit word at the cached selector plus 20. This word-write address uses the cached selector even if intervening calls change the selector in memory.

Immediately afterward, the function reads the global 32-bit word. This is a fresh read at this point, not an entry snapshot.

### 6. Global-derived byte update and further scaled writes

A dependency receives the twelfth scale. Four no-explicit-argument calls follow, the last represented as producing 64 bits. Define the **tail scale** as its low half shifted left by two.

The function freshly reads the selector at `quadrant base + 1` and writes the low byte of the global word shifted right by 22 to the selected byte address.

The following calls occur:

1. A dependency receives the high half of the 64-bit result.
2. A no-explicit-argument call supplies a value.
3. Another dependency receives that value and the tail scale shifted left by 28.
4. Four no-explicit-argument calls supply a **sixteenth index**.

The selector at `quadrant base + 1` is read again, and the selected byte is cleared. A dependency receives the sixteenth index shifted left by two.

Four no-explicit-argument calls supply a **seventeenth index**. A dependency receives two identical arguments, each the seventeenth index shifted left by two.

Four further calls supply an **eighteenth index**. Define the **tail word** as the eighteenth index shifted left by two.

The function writes the tail word at `20 + scale(tail scale, 12)`. A dependency receives the tail scale shifted left by 14.

Four more calls supply a **nineteenth index**. The tail word is written at `20 + scale(nineteenth index, 2)`, followed by a dependency receiving that scaled index.

### 7. Final selector operations and next-iteration state

Four no-explicit-argument calls supply another represented 64-bit result. Define the **final scale** as its low half shifted left by two.

The function reads a selector at:

\[
1 + \operatorname{scale}(\text{tail scale},14)
\]

and writes `field(tail word)` at that selector plus 17.

A dependency receives the high half of the 64-bit result. A no-explicit-argument call follows, and its result is passed to another dependency. Another call produces 64 bits; its low and high halves are passed together to the following dependency.

Two no-explicit-argument calls then supply a **twentieth index**. The function reads the selector at `1 + scale(final scale, 28)` and clears the selected byte. A dependency receives the twentieth index shifted left by two.

Four more calls supply a **twenty-first index**. Define:

- The **next working base** as the final scale multiplied by four.
- The **final index scale** as the twenty-first index multiplied by four.

The function reads the selector at the next working base plus one and clears its selected byte. It then calls a dependency with the final scale shifted left by 10, makes a no-explicit-argument call, and passes that result together with the retained result shifted left by 28 to another dependency.

Four more calls supply a **twenty-second index**. The selector at the next working base plus one is read again, and its selected byte is cleared again. A dependency receives the twenty-second index shifted left by two.

Four further no-explicit-argument calls follow. Their explicit returns do not determine the final direct write.

The **next working value** is the twenty-first index shifted left by 14. It is written at:

\[
20 + \operatorname{scale}(\text{final index scale},12).
\]

A dependency receives the final index scale shifted left by 14. One more no-explicit-argument call occurs.

The next iteration uses:

- The next working base.
- The next working value.
- That same next working value as the fourth argument.
- The fourth argument shifted left by 28 as the first argument.
- An unresolved secondary result as the second argument.
- The internally replaced link-like value for selecting the initial call target.

Under the 32-bit model, the next first argument is necessarily zero: its source already has its lowest 14 bits clear before the additional 28-bit shift.

## Side effects

All direct memory accesses are externally significant unless the execution environment establishes otherwise. Addresses may overlap each other, selector storage, or dependency-managed state. No disjointness guarantee is visible.

Byte stores truncate to eight bits. Word stores occupy four bytes. Byte order is undocumented. Several computed word addresses may be unaligned.

Dependencies occur between many related reads and writes. Their effects must not be omitted when interpreting repeated selector reads, repeated clears, or apparent write restoration. In particular:

- A later zero write is not proof of cleanup of the originally written byte.
- A selector cleared earlier can be changed again by dependencies before a later read.
- Cached selectors and freshly read selectors have different observable behavior.
- The global read can observe changes made by any preceding dependency.

No explicit allocation, release, ownership transfer, locking, or rollback is established. Passing a value that resembles an address does not establish ownership. Dependencies may have additional memory or resource effects.

## Dependencies

All visible dependency calls are indirect and unresolved.

For contract purposes, each invocation site may be identified as **F-EXT-〈ordinal〉**, where the ordinal is its position in the iteration’s call sequence. These are opaque call-site identifiers, not recovered function identities. Different sites may invoke the same function; one dynamically selected site may invoke different functions across executions.

Established dependency interactions include:

- Calls with no explicit arguments.
- Calls receiving one, two, three, or four explicit 32-bit arguments.
- Results represented as 32-bit values.
- Results represented as 64-bit values and subsequently split into low and high halves.

## Acceptance examples

These examples are conditional static acceptance criteria, not observed executions.

1. **Initial field truncation.** If the fourth argument is `0x3ff00000`, the first selector-based store writes `0xff`. The masked extraction initially yields ten bits; conversion to one byte discards its upper two bits.

2. **Fresh selector versus cached selector.** If a selector read yields 7, the corresponding byte write targets address 24. If a dependency changes that selector to 9 before a later fresh read, the later selected-byte write targets address 26. The cached-selector word write in phase 5 instead retains its earlier selector.

3. **Lookup address is not a word index.** If the tenth result is `0x00100000`, the lookup read starts at address 21, not address 24. Success depends on the environment permitting that four-byte read.

4. **Quadrant calculation.** If the eighth index has low two bits equal to 2, the quadrant base is `0x80000000` under 32-bit wrapping. The two direct clear addresses are then `0x80000011` and `0x80000001`, in that order.

5. **Repeated writes are preserved.** Even if no dependency changes memory, both pairs of direct clears in phase 3 occur. A consumer observing writes must not see them reduced to one pair.

6. **No guaranteed progress past a call.** If a dependency never returns, no later direct access in that iteration is required. No timeout or fallback is visible.

7. **No normal completion.** If every call and memory access succeeds indefinitely, the function continues iterating rather than returning a status.
