# F-9ed95c690cc1

## Purpose

F-9ed95c690cc1 selects a record for a requested unsigned identifier, derives a byte interval using one of five supported encodings, and delegates processing of that interval to F-82ff5174f9ee.

Selection has two levels:

1. Find the first top-level range containing the requested identifier.
2. Interpret the selected range’s format to obtain a start displacement and an end displacement.

Most locally detected failures return the 32-bit value **6**. Successful interval construction does not itself establish overall success: the function returns the result of F-82ff5174f9ee unchanged.

The apparent intent is to resolve an indexed resource within a bounded binary structure. Resource semantics and the meanings of the downstream operation selector and trailing arguments are not established.

## Interface

### Inputs

The function accepts four arguments:

| Position | Width and interpretation |
|---|---|
| 1 | A 32-bit address identifying a readable context structure. The context is also passed to both dependencies. |
| 2 | An unsigned 32-bit requested identifier. |
| 3 | An opaque 32-bit value forwarded to F-82ff5174f9ee. |
| 4 | An opaque 32-bit value forwarded to F-82ff5174f9ee. |

The first argument is used as an address, not merely as an integer token. No null-pointer validation is visible.

### Context fields

The function reads these fields relative to the context address:

| Byte offset | Width | Use |
|---|---:|---|
| 0x1C | 32 bits | Addend used to locate the top-level range table. |
| 0x20 | 32 bits, treated as signed for the loop count | Number of top-level range entries. |
| 0x24 | 32 bits | Other addend used to locate the top-level range table. |
| 0x28 | 32-bit pointer | Upper address bound used by local checks and passed to F-2790da281ffe. |

The initial table address is the sum of the fields at 0x24 and 0x1C. The evidence does not establish their independent meanings or the byte order of these native context fields.

The serialized structures reached through that address use explicit **big-endian** decoding for 16-bit and 32-bit numbers.

### Return value

The return value is 32 bits:

- **6** for the local failure conditions described below.
- Otherwise, exactly the value returned by F-82ff5174f9ee.

A return value of 6 cannot distinguish a local rejection from a downstream return of the same value.

### Preconditions and arithmetic domain

A safe invocation requires readable context fields and readable backing storage for every address actually accessed. The visible checks are upper-bound checks; they do not establish that an address is above the beginning of an allocation.

Serialized displacements, counts, identifier arithmetic, products, and interval endpoints are represented in 32-bit arithmetic. Overflow is not explicitly rejected. Address calculations must therefore not be interpreted as unbounded mathematical arithmetic.

A nonnegative top-level count and nonwrapping address calculations are useful safety preconditions, not validations performed by this function.

## Behavior

### 1. Locate and scan the top-level table

The function obtains the table address, entry count, and upper bound from the context. It checks whether the address immediately after the nominal table—table address plus eight times the count—is at or below the upper bound.

If this check fails, it returns 6 without scanning entries.

Each top-level entry occupies eight bytes:

| Relative offset | Width | Meaning |
|---|---:|---|
| 0 | 16 bits | Inclusive lower identifier bound. |
| 2 | 16 bits | Inclusive upper identifier bound. |
| 4 | 32 bits | Selected-block displacement relative to the beginning of the entire top-level table. |

Entries are examined in storage order. For each entry, the lower bound is decoded first. The upper bound is needed only if the requested identifier is not below that lower bound.

The first entry satisfying both inclusive comparisons is selected. Its block displacement is added to the **original table address**, not to the address of the matching entry.

There is no fallback to later entries if processing the selected entry fails. Overlapping ranges therefore have first-match precedence, including when the first matching range leads to an invalid or unsupported block.

If no entry matches, the function returns 6. A zero count also returns 6 without reading an entry.

Because top-level bounds are 16-bit but the requested identifier is 32-bit, a request greater than 65,535 cannot match a normally traversed entry. The request is not narrowed to 16 bits for comparison.

### 2. Read the selected block header

The selected block must have at least eight bytes available under the upper-bound comparison. Otherwise, the function returns 6.

Its header is:

| Relative offset | Width | Meaning |
|---|---:|---|
| 0 | 16 bits | Encoding selector. |
| 2 | 16 bits | Opaque selector passed to F-82ff5174f9ee. |
| 4 | 32 bits | Base displacement later added to the derived start displacement. |

After the eight-byte availability check, the opaque selector bytes and base-displacement bytes are captured before dispatch on the encoding selector.

Encoding 0 and every encoding other than 1 through 5 return 6.

For the descriptions below:

- **ordinal** means requested identifier minus the selected top-level lower bound.
- **start** and **end** are the derived unsigned 32-bit interval endpoints.
- Availability checks allow equality with the upper bound: an address immediately after the checked region may equal that bound.

### 3. Encoding 1: adjacent 32-bit endpoints

The endpoint location is eight bytes after the block start, plus four times the ordinal.

The function requires eight bytes beginning at that location. It reads:

- A big-endian 32-bit start endpoint.
- The immediately following big-endian 32-bit end endpoint.

Consecutive ordinals therefore use overlapping endpoint pairs: one ordinal’s end occupies the same serialized position as the next ordinal’s start.

Equal endpoints return 6. Decreasing endpoints also return 6 through the common interval check.

### 4. Encoding 2: fixed-width interval by ordinal

The function first requires at least 20 bytes from the block start.

It reads a big-endian 32-bit stride at block offset 8. It initializes a cursor to block offset 12 and calls F-2790da281ffe with:

1. The original context.
2. A writable reference to that cursor.
3. The captured upper bound.
4. The value 1.

Any nonzero dependency return is converted to local return value 6.

On a zero dependency return, the interval is computed using 32-bit arithmetic:

- Start is stride multiplied by the ordinal.
- End is start plus stride.

The dependency’s returned cursor is not subsequently used on this encoding path.

This path does not reject equal endpoints separately. A zero stride can consequently produce a zero-length downstream call. A wrapped multiplication is not itself an error; only the final unsigned comparison of end against start is applied.

### 5. Encoding 3: adjacent 16-bit endpoints

The endpoint location is eight bytes after the block start, plus two times the ordinal.

The function requires four bytes beginning at that location. It reads two adjacent big-endian 16-bit endpoints and widens each to an unsigned 32-bit value.

As with encoding 1, neighboring ordinals share an endpoint position.

Equal endpoints return 6. Decreasing endpoints return 6 through the common interval check.

### 6. Encoding 4: keyed endpoint records

The function requires at least 12 bytes from the block start and reads a big-endian 32-bit record count at offset 8.

The record area begins at offset 12. Before scanning, the function requires the address at record-area start plus four times the count plus four to be at or below the upper bound.

Each searchable record begins four bytes after the previous record:

| Offset from a record’s start | Width | Use |
|---|---:|---|
| 0 | 16 bits | Identifier to compare with the full 32-bit request. |
| 2 | 16 bits | Start endpoint if this record matches. |
| 6 | 16 bits | End endpoint if this record matches. |

Thus, the end endpoint for a matching record occupies the endpoint position associated with the following four-byte slot. The availability check includes an extra four bytes beyond the counted searchable records.

Records are searched in order. The first exact identifier match supplies the endpoints. Duplicate identifiers do not cause a later match to be considered.

A zero record count or exhaustion without a match returns 6. Equal endpoints are permitted on this path. Decreasing endpoints return 6.

### 7. Encoding 5: fixed-width interval by identifier-list position

The function first requires at least 24 bytes from the block start.

It reads a big-endian 32-bit stride at block offset 8, initializes a cursor to block offset 12, and calls F-2790da281ffe with the same argument pattern used by encoding 2.

A nonzero dependency return causes return value 6.

After a zero return, the function reads a big-endian 32-bit list count at the dependency-updated cursor. There is **no visible independent bounds check before this four-byte read**.

It then checks that the address immediately after the count and the declared number of two-byte identifiers is at or below the captured upper bound.

The list is scanned sequentially using big-endian 16-bit identifiers compared against the full 32-bit request. The first matching list position determines the interval:

- Start is the zero-based matching position multiplied by the stride.
- End is start plus the stride.

A zero count or an absent identifier returns 6. The cursor advances past each identifier examined, including a matching identifier.

Duplicate identifiers select their first list position. Equal endpoints are permitted. Arithmetic wrap is not independently rejected.

### 8. Common interval dispatch

After an encoding supplies endpoints, the function rejects the interval if end is less than start in an unsigned comparison.

Otherwise, it calls F-82ff5174f9ee with:

1. The original context.
2. The captured 16-bit opaque selector, supplied in the dependency’s argument representation.
3. The captured 32-bit base displacement plus start.
4. End minus start.
5. The original third argument.
6. The original fourth argument.

The base-plus-start addition has no visible overflow check. The interval length is derived from the endpoints; there is no local validation that the downstream byte interval lies within a resource or allocation.

The dependency’s return value becomes the function’s return value.

## Side effects

The function visibly reads context fields, table entries, block headers, format-specific payloads, and dependency-selected data. It writes its own temporary state, including the cursor that F-2790da281ffe can update.

No direct write to the supplied context or serialized backing storage is shown. No direct allocation or release is shown.

These observations do **not** establish that the complete operation is read-only:

- Both dependencies receive the context.
- F-2790da281ffe receives a writable cursor reference.
- F-82ff5174f9ee receives the opaque third and fourth arguments.
- Dependency effects on globals, shared memory, ownership, allocation, and release are unknown.

Header values captured before a helper call are used for later dispatch. Subsequent encoding-5 reads use the helper-updated cursor and observe memory as it exists after that call. The function does not reload the context’s upper-bound field after the helper returns.

A local failure after F-2790da281ffe has run does not imply absence of side effects. No rollback is visible.

## Acceptance examples

These examples are conditional on readable memory, nonwrapping address calculations unless stated otherwise, and dependencies behaving as specified in each example. They describe expected behavior from static evidence, not executed tests.

1. **Inclusive range boundaries.** A top-level range from 100 through 103 is eligible for requests 100 and 103. Requests 99 and 104 do not select it.

2. **First matching range controls failure.** Two ranges contain request 101. If the first selects encoding 0, the function returns 6 without trying the second range.

3. **Encoding 1 interval.** A selected range begins at 100, and request 102 identifies an endpoint pair containing 40 and 55. If the block base displacement is 1,000, downstream dispatch receives displacement 1,040 and length 15.

4. **Encoding-dependent empty interval.** Endpoints 12 and 12 cause rejection under encoding 1 or 3. The same endpoints obtained through encoding 4 permit a downstream call with length zero.

5. **Encoding 2 zero stride.** If F-2790da281ffe returns zero and stride is zero, start and end are both zero. The function calls F-82ff5174f9ee with the block base displacement and length zero.

6. **Encoding 4 overlapping layout.** If a matching record contains identifier 77 and start 9, and the 16-bit value six bytes after that record’s start is 21, request 77 yields start 9 and end 21. The intervening 16-bit value at offset 4 is not the end endpoint.

7. **Encoding 5 first duplicate.** If the post-helper list is 8, 12, 8 and stride is 6, request 8 selects position zero, not position two. The interval is 0 through 6.

8. **Helper rejection.** A nonzero F-2790da281ffe result causes return 6 and prevents downstream dispatch. Effects already produced by that dependency are not undone.

9. **Unsigned wrap in fixed-width intervals.** With stride 0x80000000 and ordinal one in encoding 2, start is 0x80000000 and end wraps to zero. The final end-before-start check rejects the interval.

10. **Wrapped product without rejection.** With that same stride and ordinal two, start wraps to zero and end is 0x80000000. The common interval comparison does not reject it solely because the product wrapped.

11. **Downstream status propagation.** If a valid interval reaches F-82ff5174f9ee and it returns 17, this function returns 17. If it returns 6, the externally visible result is also 6.

## Uncertainties

The following are **documented_only**:

- Context and resource ownership, lifetime, alignment requirements, and concurrency rules.
- Native byte order of the context fields.
- The meanings of the opaque selector and trailing arguments.
- Dependency side effects, memory-preservation guarantees, and ownership transfers.
- Whether F-2790da281ffe guarantees that encoding 5’s subsequent count read is safe.
- Whether external validation guarantees nonnegative counts and nonwrapping arithmetic.
- Behavior for invalid addresses, wrapped pointer calculations, or malformed negative top-level counts. These are not established as clean return-6 cases.

The top-level count is treated as signed and decremented until zero, rather than explicitly checked for positivity. A negative value must not be interpreted as an empty table.

The table-relative displacement and indexed interval formats suggest a resource lookup mechanism. That is inferred intent, not an established semantic requirement.
