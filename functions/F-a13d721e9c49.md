# F-a13d721e9c49

## Purpose

The established behavior is a fixed-order sequence of indirect calls, scalar transformations, memory accesses, and a global-slot assignment. The function captures words from computed addresses, distributes selected values to other computed addresses, performs two byte-selector-based writes, clears two locations, and finally calls address zero.

No domain-level purpose is established. The supplied representation does not establish that the addresses identify objects, array elements, hardware registers, or ordinary process memory. Initialization, allocation, serialization, and cleanup are therefore not established purposes.

This contract distinguishes:

- **Established static evidence:** explicit operations, widths, arguments, and ordering in the supplied representation.
- **Conditional arithmetic interpretation:** 32-bit machine arithmetic used to describe expressions whose signed arithmetic or address conversion requires confirmation.
- **documented_only unknowns:** behavior not determined by the supplied representation.

No runtime tests have been performed.

The represented interface has no explicit parameters and no explicit return value. It nevertheless consumes incoming machine state:

The origin and validity of the incoming state are not established. In particular, the representation does not prove that this entry point supports ordinary standalone invocation.

### Widths and arithmetic

The visible memory accesses comprise 8-bit byte accesses, 32-bit word accesses, and one final 16-bit store. Two call results are represented as 64-bit values and separated into low and high 32-bit components.

Within this contract:

- A **word** is 32 bits.
- A **byte** is 8 bits; selector bytes are unsigned.
- A **low byte** consists of bits 0–7.
- Scaling by four means shifting left by two or multiplying by four, as represented at the relevant operation.
- Logical right shifts insert zeros.
- A mask of `0x3FFFFFFF` clears the upper two bits of a 32-bit value.
- A mask of `0xFFFFFFFC` clears its lower two bits.

Where necessary, address arithmetic and left shifts are interpreted conditionally as 32-bit bit-vector operations, retaining the low 32 bits. This is not a claim that signed overflow, signed left shifts, or integer-to-pointer conversions have fully defined language-level behavior. The caveat also applies to calculating **Entry link + 0xFFE**.

### Outputs and completion

There is no explicit returned data value. Observable outputs are the dependency interactions, direct memory writes, and Supervisor slot assignment.

The final call targets address zero and receives three explicit zero arguments. A normal return is represented afterward, but is reachable only if that call returns. Whether address zero is callable, traps, or has environment-specific significance is documented_only.

4. Write V’s low byte at that destination.

For all 32-bit W values, the selector address is in **1–512**, inclusive. The destination address is in **17–272**, inclusive. The selector access reads a byte, not a pointer-sized value.

### 6. Second selector-based byte write

The two selector reads occur at different times, with intervening calls. They are not an entry-time snapshot. Earlier writes or intervening dependency effects can alter the byte observed by the second selector read.

## Side effects

### Direct memory effects

Excluding dependency-internal effects, the function performs:

- Two word reads followed by low-byte copies at their respective base-plus-1 addresses.
- Two full-word stores of captured W.
- One full-word store of scaled E.
- One full-word zero store.
- Two full-word stores of scaled G.
- One Global base slot read and a later word read through its captured value.
- Two selector-byte reads and two corresponding byte writes derived from captured V.
- One Supervisor slot assignment.
- One final byte clear and one final 16-bit clear.

These effects are ordered, not transactional. A fault or nonreturning call can leave a completed prefix visible. No rollback is represented.

The supplied global declarations are incomplete, and the representation warns of overlapping global symbols. Exact global storage widths and overlaps are therefore not established merely by the slot names.

Captured scalar values remain the values used by the explicit subsequent operations; their original memory sources are not implicitly reread. Conversely, selector bytes and V must be read at their specified points, not moved into an earlier snapshot.

The representation establishes operation order, not a complete concurrency, atomicity, volatility, or hardware memory-ordering contract.

### Ownership and failures

## Acceptance examples

These are conditional static obligations, not executed tests. Each assumes earlier operations complete and no unspecified dependency activity changes the relevant conditions.

1. **Entry-link target offset.** If Entry link is `0x1000`, F-c001 targets `0x1FFE`. Calling Entry link itself would omit the established offset. Under the conditional 32-bit wrapping interpretation, Entry link `0xFFFFF002` instead produces target zero.

2. **Low-byte copy.** If the first word read yields `0x123456AB`, the store at Entry base plus 1 writes the single byte `0xAB`, not the whole word.

3. **Different destination scales.** If C is 3 and D is 5, the two W stores target addresses 68 and 40, respectively.

4. **Captured source value.** If W is captured as `0x11223344`, later dependency mutation of its original source to zero does not change either explicit W store.

5. **Packing and truncation.** With A equal to `0x12345678`, P is `0x48D159E0` and F-c018 receives `0x56780000` under the 32-bit interpretation.

6. **Split result.** If F-c045’s low half is 3 and high half is 5, T is 12. The first T store writes 12 at address 40, and F-c046 receives 12, 5, 12, 12.

7. **Global sampling and aliasing.** If Saved base is captured as `0x1000`, a later Global base slot change to `0x2000` does not redirect the V read. If I scaled by four plus 20 equals `0x1014`, the second T store precedes the V read at that same address.

8. **First selector.** If W is `0x01800000`, its selector address is 4. If that byte is 200 and V’s low byte is `0xAB`, address 217 receives `0xAB`.

9. **Second selector and final halfword.** If J is `0xC0200000`, the second selector address is 2. If its byte is 7 and V is `0xABCDEF01`, address 24 receives `0xAF`. The later halfword clear targets address 16,384; J’s upper two bits do not affect either calculation.

10. **Selector overlap.** If the first selector-based write modifies the second selector’s location, the later selector read observes the modified byte unless another intervening effect changes it.

11. **Nonreturning dependency.** If F-c072 does not return, the Supervisor slot assignment, both final clearing stores, and F-c073 are not reached.
