# F-f0180a239fce

## Purpose

F-f0180a239fce computes the full product of two unsigned, four-word integers and writes an eight-word result.

Under the 32-bit word interpretation supported by the supplied arithmetic, each input represents a 128-bit unsigned integer, and the output represents their exact 256-bit unsigned product. Words are ordered by increasing significance: word zero contains the least significant 32 bits.

This mathematical contract requires input contents to remain stable throughout the operation, including freedom from output writes that change subsequently read input words. The function does not snapshot either operand before writing the result. Overlapping input and output storage can therefore change the values used during the calculation.

The supplied material establishes a fixed, unrolled arithmetic operation. It does not establish a broader numeric API, allocation policy, concurrency protocol, or error-reporting convention.

## Interface

The function receives three address arguments, in this order:

| Argument | Role | Required accessible extent |
|---|---|---|
| Destination | Storage for the result | Eight writable words |
| Left operand | First unsigned integer | Four readable words |
| Right operand | Second unsigned integer | Four readable words |

The function has no return value. Its result is communicated exclusively through destination writes.

For this contract, let \(W=2^{32}\). The input values are:

\[
A=\sum_{i=0}^{3} A_i W^i,\qquad
B=\sum_{i=0}^{3} B_i W^i.
\]

Each \(A_i\) and \(B_i\) is an unsigned word in the range zero through \(W-1\). For stable inputs, the result words satisfy:

\[
A B=\sum_{i=0}^{7} D_i W^i,\qquad 0\le D_i<W.
\]

The destination occupies 32 bytes, and each operand occupies 16 bytes, under the 32-bit word model. Successive words are four bytes apart.

This is a word-significance layout, not an independently established byte-endianness requirement. How a word’s bytes are arranged in memory depends on the execution environment.

### Preconditions

For the ordinary multiplication guarantee:

- All three addresses must designate valid storage for their required extents.
- Storage must satisfy the execution environment’s alignment and access requirements for a word.
- Both operands must remain unchanged until their final reads.
- Destination writes must not modify operand words that the function will subsequently read.
- No external writer may change operand contents during the operation.

Disjoint destination and input ranges provide the straightforward way to satisfy the overlap condition. The two input ranges may coincide: the function does not write through either input argument, so using the same stable operand for both inputs computes a square.

Destination contents need not be initialized. No destination value is read as part of the arithmetic.

The supplied declaration does not establish a calling convention, register assignment, or binary ABI beyond the three address arguments and absence of a returned value.

## Behavior

### Numeric result

With stable inputs and valid storage, the function overwrites all eight destination words with the exact product. There is no truncation to the input width, saturation, signed interpretation, or separate overflow result.

Every pair of input words contributes once. A product \(A_iB_j\) contributes at significance \(W^{i+j}\). Carries from lower significance positions are incorporated into subsequent positions.

The largest possible input product is:

\[
(W^4-1)^2=W^8-2W^4+1.
\]

It fits in eight words. No ninth result word is required.

### Word multiplication and carries

The supplied arithmetic divides each input word into a low 16-bit half and a high 16-bit half. Each half is in the range zero through 65,535.

A product of two such halves is at most:

\[
65{,}535^2=4{,}294{,}836{,}225,
\]

which fits in an unsigned 32-bit word. The sum of two cross-products can exceed that width. The function explicitly accounts for this overflow when constructing the high word of a word-pair product.

For each pair of input words, the calculation derives:

- The low 32 bits of their product.
- The high 32 bits of their product.
- Carry corrections caused by overflowing cross-product additions.
- Carry corrections caused by assembling the low product word.

The larger multiplication also accounts for overflow when accumulating contributions from different word pairs. Some intermediate carry information can exceed a single Boolean carry; it is retained for the next result positions.

This description relies on 32-bit machine-word arithmetic with logical right shifts for unsigned values and low-word retention on overflowing word operations. The supplied text contains signed intermediate declarations as well as unsigned ones; its portability limitations are documented under **Uncertainties**.

### Input-read and output-write progression

The function does not read all inputs before beginning output. Instead, it interleaves operand reads with destination writes.

The following table gives the complete order of word-pair contributions. Within a row, pairs are processed from left to right. The indicated destination write occurs after the operand reads and arithmetic for that row, and before any operand reads in the next row.

| Next destination word written | Operand pairs read and processed since the preceding write |
|---|---|
| \(D_0\) | \(A_0,B_0\) |
| \(D_1\) | \(A_0,B_1\); \(A_1,B_0\) |
| \(D_2\) | \(A_2,B_0\); \(A_1,B_1\); \(A_0,B_2\) |
| \(D_3\) | \(A_0,B_3\); \(A_1,B_2\); \(A_2,B_1\); \(A_3,B_0\) |
| \(D_4\) | \(A_3,B_1\); \(A_2,B_2\); \(A_1,B_3\) |
| \(D_5\) | \(A_2,B_3\); \(A_3,B_2\) |
| \(D_6\) | \(A_3,B_3\) |
| \(D_7\) | No additional input reads |

In each pair except the final \(A_3,B_3\) pair, the supplied expression order obtains:

1. The right word’s high half.
2. The left word’s low half.
3. The right word’s low half.
4. The left word’s high half.

For the final pair, that order is instead:

1. The left word’s low half.
2. The left word’s high half.
3. The right word’s high half.
4. The right word’s low half.

Each half extraction is expressed as a read of the containing word, followed by a shift or mask. The supplied representation therefore contains repeated word reads rather than one complete operand snapshot. This source-level order matters when describing overlap; it does not independently establish an exact hardware load trace for nonvolatile memory.

There are eight destination assignments, in increasing index order. No higher-index destination word is written early.

### Overlap behavior

The routine contains no overlap check and no alternate in-place path.

When destination storage overlaps an input, an earlier destination write may change a word needed by a later pair in the table. Later reads then use the changed storage, rather than necessarily using the operand value that existed on entry.

Consequently:

- Arbitrary in-place multiplication is not guaranteed.
- Swapping left and right operands preserves the mathematical result for stable inputs, but need not preserve behavior for overlapping storage.
- Some particular overlaps or values may happen to produce the entry-value product. Such success does not establish general overlap support.
- The established access progression, rather than an entry-time operand snapshot, governs overlap-sensitive behavior.

No error or rejection is generated merely because ranges overlap.

### Boundary cases

Zero, one, and words with their top bit set all follow the same arithmetic path.

There is no sign bit in the numeric interpretation. In particular, a word with value `80000000` in hexadecimal contributes a positive value of \(2^{31}\) at its word position.

A zero product still causes all eight destination words to be assigned. The routine does not leave the upper half untouched or preserve preexisting destination contents.
