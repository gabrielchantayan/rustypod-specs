# F-7e6b0b596491

## Purpose

F-7e6b0b596491 performs address-derived memory writes and dependency calls along two represented paths:

- An exceptional path modifies calculated addresses and global storage, invokes a computed dependency, and returns if that invocation completes normally.
- A general path initializes storage and enters repeated processing. It updates a cursor, consumes dependency results, performs overlapping writes, and may execute a software breakpoint. No normal return from this path is represented.

No application-level purpose is established. An allocator, decoder, device-initialization, or dispatching role would be inferred intent rather than a contractual guarantee.

This contract describes static evidence, not verified executable behavior. Access validity, arithmetic behavior outside defined ranges, and dependency behavior remain material conditions.

## Interface

### Explicit arguments

| Argument | Represented width/type | Use |
|---|---|---|
| First | Signed 32-bit integer | Added to an incoming signed addend; its low byte is written on the exceptional path. |
| Second | Pointer to 32-bit words | Receives the initial sum at offset 0 and, on the general path, the original third argument at byte offset 4. |
| Third | Unsigned 32-bit integer | Supplies masks, initial addresses, and processing state. Its working replacement later changes. |
| Fourth | 32-bit value | No explicit use is represented. |
| Fifth | Signed 32-bit integer | Participates in a general-path signed address calculation. |

There is no explicit return value.

### Additional incoming state

Execution also depends on state not initialized within the routine:

- **Selector:** unsigned 32-bit branch-control value.
- **Cursor:** pointer to 32-bit words, later replaced by pointers read from memory.
- **Context base:** signed 32-bit quantity used as an address.
- **Incoming addend:** signed 32-bit integer.
- **Dispatch offset:** signed 32-bit quantity used to calculate the exceptional call target.

The explicit arguments alone therefore do not determine behavior.

### Widths and arithmetic

The representation uses 32-bit pointers and integer words. Explicit byte, halfword, word, and wide accesses are respectively 8, 16, 32, and 64 bits. Decomposition of a 64-bit result into upper and lower 32-bit components is numerical; it does not establish memory byte order.

Unsigned 32-bit arithmetic reduces modulo \(2^{32}\). Narrow stores retain the represented low byte or halfword. These rules do **not** make signed arithmetic wrap.

In particular:

- The initial addition is signed before assignment to unsigned storage.
- Several address calculations use signed addition, multiplication, or left shifts.
- F-D01’s first argument uses signed multiplication after a pointer-to-signed-integer conversion.
- F-D06’s lower result is converted to signed 32-bit form before multiplication; only the product’s assignment is unsigned.
- Signed right-shift behavior and out-of-range signed conversions are not established.
- A later right shift by 32 has no established result for the represented 32-bit operand.

Descriptions below are conditional on the relevant operations having established semantics. No general low-32-bit wrapping rule overrides these qualifications.

## Behavior

### Initial write and branch selection

The routine adds the first argument to the Incoming addend using signed 32-bit addition. The result is assigned to unsigned 32-bit storage as the **initial sum**, then written at the second argument’s offset 0.

If the signed addition overflows, the representation does not establish a wrapped initial sum or subsequent behavior.

The exceptional path requires both:

1. Selector bit 31 is set.
2. Twice the Selector, calculated as unsigned 32-bit arithmetic, is nonzero.

Otherwise execution takes the general path. In particular, Selector `0x80000000` takes the general path because doubling it produces zero.

### Exceptional path

Define:

- **Doubled address:** the unsigned doubled Selector.
- **Derived address:** Doubled address advanced by initial sum bytes.
- **Masked address:** original third argument bitwise-ANDed with the 32-bit representation of Derived address.

Pointer arithmetic and pointer conversions remain subject to the unresolved address-model conditions.

The observable sequence is:

1. Store the low byte of the first argument at Doubled address.
2. Store the low halfword of Context base at Cursor plus 2 bytes.
3. Store Derived address as a 32-bit pointer at Derived address plus `0x40`.
4. Store the low halfword of Derived address at Derived address.
5. Form the unsigned expression Selector times `0x20`, plus `0x11`; assign it to a signed 32-bit address/value quantity. Store that quantity as a word at its corresponding address. An out-of-range conversion to signed form is not independently specified.
6. Shift Masked address left by one using unsigned arithmetic, convert the result to signed 32-bit form, and right-shift that signed value by 10. Use the result as a halfword address.
7. Store the low halfword of that address at itself.
8. Repeat the same halfword store at the same address.
9. Store halfword `0x0050` at Masked address plus 2.
10. Assign `0xF430` to the fixed storage object beginning at `0x000000FD`.
11. Assign `0x0897F430` to the symbolic **reset destination**.
12. Assign zero to a separate symbolic global.
13. Read another symbolic global, convert its value to unsigned 32-bit form, and interpret the converted value as an address.
14. Store word `0x0897F430` at that address.
15. Evaluate the arguments and invoke F-D01 at Dispatch offset plus `0x0897F314`.

The global read in step 13 has no supplied storage declaration establishing its width or signedness. Conversion to unsigned 32-bit form is explicit; whether that conversion extends, truncates, or leaves the width unchanged is unknown.

F-D01 receives:

1. The address from step 13 advanced by four 32-bit elements, equivalently 16 bytes, **then converted to signed 32-bit integer form, then multiplied as a signed integer by `0x01000000`**.
2. Zero.
3. `0x5000`.
4. `0x56`.

The first argument is not specified as a modulo-\(2^{32}\) product. Once the signed conversion is established, multiplication is representable only when that signed operand lies between −128 and 127 inclusive. Outside that range, signed multiplication overflows and this representation establishes no resulting argument or subsequent behavior. Pointer advancement and conversion introduce their own unresolved conditions.

The target addition also uses the signed Dispatch offset and is not unconditionally wrapping arithmetic.

If argument evaluation and the invocation complete normally, the routine returns without an explicit value.

The two identical halfword stores remain distinct operations; equality of their values does not authorize collapsing their observable accesses.

### General-path initialization

The general path performs these stores in order:

1. Store word `0x40` at Context base plus `0x28`.
2. Store Context base as a word at Context base plus `0x2C`.
3. Convert Cursor to signed 32-bit form, add the fifth argument, and add 8. Store that calculated signed value as a word at twice that value, with the doubling also signed.
4. Store the original third argument at the second argument’s byte offset 4.
5. Store the low byte of **Working quantity** at **Primary destination** plus 20.

The context additions and step 3’s signed operations are subject to overflow and conversion uncertainties.

The initialized processing state is:

| State | Initial value |
|---|---|
| Running value | Initial sum bitwise-ANDed with original third argument |
| Working quantity | Original third argument times 8, minus 2, using unsigned 32-bit arithmetic |
| Step/sample state | Original third argument times `0x02000000`, unsigned |
| Working third value | Original third argument shifted left by 28, unsigned |
| Primary destination | Original third argument times `0x01000000`, unsigned |
| Secondary destination | Same initial address as Primary destination |
| Call anchor | `0x08BFED9A` |

The original third argument is stored before its working replacement is established. Aliasing can make these stores affect later reads.

### Re-entry writes

The general path enters a block also reachable after extended processing:

1. Store byte zero at Primary destination.
2. Store the low halfword of Working quantity at Primary destination.
3. Store Working third value as a word at Primary destination.
4. Add Step/sample state to Running value using unsigned arithmetic.
5. Store the updated Running value as a word at Secondary destination.

Initially both destinations are equal, so the four stores begin at the same address and have overlapping widths.

After this block, the next F-D02 argument is zero.

### Each processing pass

At pass entry, save the low byte of Step/sample state. This snapshot precedes F-D02 and the cursor sample.

The pass then:

1. Invokes F-D02 at Call anchor plus `0xA1E`, with the current call argument.
2. Splits its 64-bit result into lower and upper 32-bit components.
3. Stores the low halfword of the lower component at the address represented by that component.
4. Calculates Working quantity times `0x40` using unsigned arithmetic, then stores that word at the address equal to the calculated value.
5. Reads a 32-bit word through Cursor. This sample replaces Step/sample state.
6. Stores the low halfword of Cursor address plus 4 at Working quantity plus 4.
7. Converts F-D02’s upper component to signed 32-bit form, adds `0x50`, reads a 32-bit pointer there, and replaces Cursor with that pointer.
8. Invokes F-D03 without explicit arguments.
9. Invokes F-D04 without explicit arguments.
10. Invokes F-D05 with the sampled word.
11. Sets Call anchor to `0x0897EDF1` and invokes F-D06 with the sampled word logically shifted right by 3.
12. Uses F-D06’s upper component as Primary destination.
13. Converts F-D06’s lower component to signed 32-bit integer form, multiplies that signed value by `0x20`, and assigns the signed product to unsigned 32-bit storage, called **Product**.
14. Stores Product as a word at the address equal to Product.
15. Compares Product with `0x14` as unsigned 32-bit values.

The word store in step 4 is self-addressed and independent of F-D02’s lower result except through incidental equality or aliasing. Both stores preceding the cursor sample can affect that sample. The halfword store in step 6 can affect the subsequent replacement-pointer read.

**Product is not an unconditional wrapped multiplication.** Signed multiplication is representable for signed operands from −`0x04000000` through `0x03FFFFFF`, inclusive. Outside that interval, its result and all dependent stores and branches are unresolved.

When the signed multiplication is representable, conversion of its result to unsigned form is established. Product is then a multiple of 32, so the unsigned below-`0x14` condition is equivalent to Product being zero. This does not establish zero for overflowing products.

If Product is below `0x14`, another pass begins with call argument zero, without the re-entry writes:

- Working quantity is unchanged.
- Step/sample state retains the sampled word.
- The next saved byte comes from that sampled word.
- Call anchor remains `0x0897EDF1`.

### Extended processing

If an established Product is at least `0x14`, execution continues:

1. Store Working quantity as a word at Product plus `0x58`.
2. Store the low halfword of the replaced Cursor at Working quantity plus `0x0E`.
3. Replace Step/sample state with Working quantity shifted left by 2 using unsigned arithmetic.
4. Read the symbolic **upper-field source**. Combine its represented 24-bit contribution as bits 31–8 with the saved pass-entry byte as bits 7–0. Assign the complete 32-bit result to the reset destination.
5. Invoke F-D07 with unsigned Cursor address logically shifted right by 2.
6. Set Call anchor to `0x0897EE1D`.
7. Invoke F-D08 without explicit arguments.

The reset assignment is a source read followed by a full 32-bit write. It is not an in-place byte store and does not automatically preserve the destination’s existing upper bytes. Physical source-read width and source/destination overlap are undocumented.

F-D08’s upper component becomes Secondary destination; its lower component supplies a wide-store address. The routine then:

1. Converts that lower address to signed 32-bit form, multiplies it by 2 using signed arithmetic, and stores the saved byte at the resulting address.
2. Stores the low byte of the upper component at the lower-component address plus 8.
3. Stores Primary destination as a word at twice Running value, calculated unsigned.
4. Stores F-D08’s complete 64-bit result at the lower-component address.

If these operations complete:

1. Convert Primary destination to signed 32-bit form, shift it left by 2, and assign the result to Running value.
2. Convert Cursor to signed 32-bit form, shift it left by 8, and assign the result to Working quantity.
3. Store three consecutive words at Primary destination:
   - Offset 0: Step/sample state.
   - Offset 4: updated Working quantity.
   - Offset 8: Cursor address.
4. Replace Working third value with Step/sample state times `0x100`, using unsigned arithmetic.
5. Evaluate a signed Cursor left shift by 31, followed by a signed right shift by 32, conversion to unsigned 32-bit form, and logical right shift by 20.
6. Set Primary destination to zero.

The signed shifts in steps 1, 2, and 5 do not acquire unsigned wrapping semantics from their later assignments. Step 5’s shift by 32 has no established result.

Conditionally, if that expression yields zero, control returns to the re-entry block. Its first operation is then a byte store at address zero. Secondary destination remains F-D08’s upper component.

Conditionally, if it yields nonzero:

1. Store the expression value as a word at Working third value plus `0x20`.
2. Set Call anchor to `0x08790D52`.
3. Set the next call argument to signed Working third value right-shifted by 29.
4. Execute a software breakpoint with immediate value 4.
5. If execution resumes, convert Secondary destination to signed 32-bit form, right-shift it by 18, and assign that result to Working quantity.
6. Begin another processing pass without re-entry writes.

No general-path normal return is represented.

## Side effects

The routine writes caller-designated storage, calculated addresses, fixed storage, and symbolic globals. Addresses may be zero, low, unaligned, overlapping, or invalid; the representation supplies no validation.

Observable ordering includes:

- Initial output before branch-specific accesses.
- Distinct repeated and overlapping writes.
- Cursor sampling after the two post-F-D02 stores.
- Cursor replacement after the intervening halfword store.
- Upper-field source reading during extended processing, after earlier dependencies.
- Argument evaluation before F-D01 invocation.

Some global storage overlaps smaller symbols, but the complete alias map is absent. Dependencies may modify globals or other memory before subsequent reads. No global-preservation or ownership guarantee is supplied.

There is no explicit error return or recovery path. Invalid accesses, unresolved arithmetic, nonreturning calls, or breakpoint handling can prevent further established progress. Fault delivery, breakpoint resumption, concurrency, and atomicity are undocumented.

## Acceptance examples

These are conditional static consequences, not executed tests. Accesses and preceding operations must complete, and any stated conversion assumptions must hold.

1. **Initial ordering.** First argument 3 and Incoming addend 5 produce an initial word store of 8 at output offset 0 before branch-specific writes.

2. **Selector boundary.** Selector `0x80000000` selects the general path. Selector `0x80000001` selects the exceptional path and first attempts a byte store at address 2.

3. **Independent self-addressed store.** With original third argument 1, Working quantity is 6. If F-D02’s lower component is `0x2000`, the pass stores a halfword there, then word `0x180` at address `0x180`.

4. **Full reset assignment.** If the upper-field source contributes `0x123456` when read and the saved byte is `0xAB`, the complete assigned reset value is `0x123456AB`, independently of the destination’s prior upper bytes unless aliasing affects the source read.

5. **Defined zero-product short cycle.** If F-D06’s lower component converts to signed zero, Product is zero. The routine attempts a word store at zero and, if it completes, takes the short cycle. If the cursor sample was `0x123456AB`, the next pass saves byte `0xAB`.

6. **Overflow is not a wrapped-product example.** F-D06 lower component `0x08000000` has signed value 134,217,728. Multiplication by 32 mathematically produces 4,294,967,296, outside signed 32-bit range. The representation therefore establishes neither a zero Product, a null store, nor a short cycle.

7. **Representable negative product.** If the lower component converts to signed −1, multiplication produces −32 without overflow. Assignment to unsigned 32-bit storage produces `0xFFFFFFE0`; the subsequent unsigned comparison selects extended processing if the intervening store completes.

8. **F-D01’s signed argument order.** If the converted global address is `0x60`, advancing by 16 bytes yields `0x70`, and conversion yields signed 112, the first argument is `0x70000000`. This example additionally requires valid pointer advancement and all earlier accesses.

9. **F-D01 argument overflow.** If the converted global address is `0x1000`, the preceding word store targets `0x1000`. If advancement and conversion yield signed `0x1010`, multiplication by `0x01000000` overflows. No wrapped first argument or ensuing invocation is established.

10. **Conditional continuation and return.** A zero result under separately supplied semantics for the unresolved shift leads to a byte store at zero on re-entry. Separately, if exceptional-path argument evaluation is established and F-D01 returns normally, this routine returns.
