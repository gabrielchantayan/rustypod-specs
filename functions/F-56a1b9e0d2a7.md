# F-56a1b9e0d2a7

## Purpose

F-56a1b9e0d2a7 performs an ordered sequence of indirect dependency invocations, indexed memory writes, bit-field extraction, selected-byte updates, and global assignments. Its last visible action before a represented return is an indirect invocation targeting address zero.

No application-level purpose is established. The evidence does not justify interpreting the operation as object initialization, container maintenance, supervisor dispatch, or resource release.

This contract distinguishes:

- **Established static evidence:** represented accesses, operand widths, transformations, and ordering.
- **Inferred intent:** possible interpretations that impose no additional requirements.
- **documented_only unknowns:** matters not resolved by the supplied representation.

All behavior below is conditional on execution reaching the relevant operation. No runtime tests have been performed.

## Interface

### Explicit and implicit inputs

The represented interface has two 32-bit explicit inputs and no declared return value.

- The first input has no explicit body-level use.
- The second input is the sole visible argument to the first dependency invocation.
- No success result, error result, or output structure is declared.

The body additionally consumes two incoming register-derived words, incoming link state, secondary register outputs from dependencies, ordinary dependency results, and mutable memory. These are material execution inputs even though the represented signature does not express them.

One incoming word supplies the first indexed write. The other is treated as unsigned and shifted right by 22 for subsequent uses. Incoming link state determines the first dependency target.

The calling convention, validity of these implicit inputs, and completeness of the represented entry boundary are **documented_only**.

### Widths and arithmetic

Words are represented as 32 bits, bytes as 8 bits, and the final halfword store as 16 bits. **Three dependency results are represented as 64-bit values and split into low and high 32-bit halves:**

1. A result whose halves are forwarded alongside a previously captured word shifted right by 23.
2. A result whose low half is shifted left by two and stored using its high half as an index.
3. A result whose halves control late dependency arguments, a selected-byte access, and the final halfword destination.

These three results are distinct observations, not repeated interpretations of one result.

Unsigned right shifts are logical. Byte writes retain only the low eight bits of their source. Thus a 32-bit word shifted right by 22 can produce ten significant bits, but storing that result as a byte discards its upper two bits.

Unsigned 32-bit left shifts retain a 32-bit result. Several other scalings and left shifts instead operate on represented signed values. Negative operands, signed overflow, and nonrepresentable signed shifts do not have a portable behavior established here.

Endianness, address-space width, alignment, effective-address wrapping, and access-fault behavior are **documented_only**.

## Behavior

### Execution conditions

The visible body contains no conditional branches or loops. If dependencies return and memory accesses succeed, the following phases occur in order.

Intervening dependency calls remain observable operations. Grouping them as staging calls below does not authorize removing them, moving memory accesses across them, or assuming that they preserve globals or addressed storage.

Except for the first and final calls, targets are formed from locally established code references and displacements. Similar-looking sites are not proven to share a callee.

### 1. Initial indexed writes and the first G-A snapshot

The initial dependency receives the second explicit input. A subsequent dependency produces a 32-bit result, which is forwarded to another dependency. Further staging calls lead to a returned index.

The first incoming register-derived word is written to `4 × returned index + 20`. **After this write**, G-A is read and its 32-bit value retained. A dependency then receives the index multiplied by four, followed by more staging calls.

A secondary register output supplies another index. The second incoming register-derived word is shifted logically right by 22, and that extracted value is written as a full 32-bit word to `4 × secondary index + 20`.

The retained G-A snapshot is shifted logically right by 23. The next dependency receives four visible arguments, in order:

- The secondary index.
- That same index again.
- The G-A snapshot shifted right by 23.
- The incoming word shifted right by 22.

The G-A snapshot is therefore neither an entry-time read nor a read performed after this second indexed write.

### 2. Repeated extracted-word storage and zero writes

Another producer result is forwarded through a dependency, followed by staging calls and a returned index. The previously extracted incoming-word value is written to `4 × returned index + 20`.

A dependency receives that index multiplied by four. After further calls, a new secondary index selects a 32-bit zero write at `4 × secondary index + 20`. The next dependency receives this secondary index without scaling.

A further producer/forwarder sequence and staging calls yield another returned index. A 32-bit zero is written to `4 × returned index + 20`.

This latter zero is statically determined by shifting the original G-A snapshot right by 23 and then shifting that unsigned result right by 23 again. No original 32-bit bit survives both shifts. The intervening calls nevertheless remain required.

Immediately after that zero write, a 32-bit word is read at:

`((secondary index & 0x1FFFFFFF) >> 19) + 20`.

The secondary index here is the one used for the preceding secondary-index zero write, not the newly returned index. This read precedes the next dependency invocation, which receives the newly returned index multiplied by four.

### 3. Selected-byte updates and captured secondary state

Following additional staging calls, the word just read is shifted logically right by 22. The byte at absolute address 1 is read as an unsigned selector. The low byte of the shifted word is written to `selector + 17`.

A dependency then receives a secondary output repeated three times, followed by a fourth argument of zero. Subsequent calls include a call with an explicit zero argument.

After another returned index is obtained, the body reads a selector byte at `4 × extracted word + 1`, where “extracted word” is the word shifted right by 22 above. Zero is written to that selector’s unsigned value plus 17. A dependency then receives the newly returned index shifted left by two.

More staging calls produce another index, whose left-shift-by-two value is passed twice to a dependency. A later 32-bit producer result is captured and forwarded. After the following call, the low-byte cell is read again, and zero is written to its unsigned value plus 17.

A secondary register-derived value is then captured for later shifts. The next dependency receives that captured value three times.

The low-byte-cell observation in this phase is distinct from the earlier read of address 1. Dependencies and intervening writes may change its value.

### 4. First G-B assignment and word-to-byte transfers

A new producer result is forwarded together with the earlier captured producer result shifted logically right by 23. Following staging calls and a returned index, the low-byte cell is read once more. Its unsigned value is retained as a base, and zero is written to `retained base + 17`.

Further calls include a single scaled-index argument and, later, duplicated scaled-index arguments. A new 32-bit dependency result is captured and assigned to G-B. The next dependency receives that same captured result; it is not obtained by rereading G-B.

After another call, a word is read at `retained base + 116`, and its low byte is written to `retained base + 1`. The retained base remains the earlier selector value even if the low-byte cell has since changed.

A dependency receives the captured secondary value from phase 3 shifted left by 11. The **first 64-bit result** is then obtained. Its low half, high half, and the captured value assigned to G-B shifted logically right by 23 are passed to the next dependency, in that order.

Following staging calls, a returned index is multiplied by four. A word at that scaled base plus 116 is read, and its low byte is written to the same base plus 1. A dependency receives the scaled base.

After further calls, another index is returned and its left-shift-by-two value retained. Independently, the word at the **previous** scaled base plus 116 is read again, and its low byte is again written to that previous base plus 1.

These are distinct reads separated by dependency calls. Equality of their values is not established.

The next dependency receives:

- The captured secondary value shifted left by 12.
- The newly retained scaled index.
- That same scaled index again.
- The new unscaled index shifted left by 18.

### 5. Full-word propagation, links, and the second G-A snapshot

Further result-producing, forwarding, and staging calls yield an index that is multiplied by four. A 32-bit word at that base plus 116 is read and retained in full. Its low byte is also written to that base plus 1.

The scaled base is passed to a dependency. After subsequent calls, the retained full word is written to `16 × next returned index + 20`.

A dependency then receives the retained scaled index from phase 4, logically shifted right by two and then shifted left by 16. Following more producer/forwarder and staging calls, the retained full word is written again, now to `4 × next returned index + 20`. That index multiplied by four is passed onward.

Further calls yield another index. Its left-shift-by-two value is written to:

`(retained scaled index from phase 4 & 0xFFFFFFFC) + 20`.

The just-written value is then passed twice to a dependency. Another producer/forwarder sequence and staging calls yield a returned index selecting a 32-bit zero write at `4 × index + 20`. The index multiplied by four is passed onward.

After more calls, the **second 64-bit result** is obtained. Its low half is treated as a signed 32-bit operand for a left shift by two. That shifted value is written to `4 × high half + 20`, with the high half represented as a signed index.

G-A is read again **after this write and before the next dependency invocation**. This second snapshot is independent of the first.

The next dependency receives four arguments:

- The shifted low half.
- The high half.
- The shifted low half again.
- The shifted low half once more.

After staging calls, the same shifted low-half value is written to `4 × next returned index + 20`. A 32-bit word is then read at `second G-A snapshot + 20`.

The body retains this word for the final selected-byte updates. It does not reread G-A to obtain that address.

### 6. Final selected-byte updates and terminal sequence

The latest returned index multiplied by four is passed to a dependency. Following staging calls, the **third 64-bit result** is obtained, and both halves are retained.

The full word retained in phase 5 is shifted logically right by 23. One is added to form a byte-read address. The byte read there is an unsigned selector; its value plus 17 selects a destination receiving the low byte of the word read through the second G-A snapshot.

The next dependency receives the third result’s high half three times and its unsigned low half shifted left by two as the fourth argument.

A producer result is forwarded, and staging calls yield another index. Before that index is passed onward, a second selector byte is read at:

`((third result’s low half & 0x3FFFFFFF) >> 21) + 1`.

Its unsigned value plus 17 selects a byte destination. That destination receives the low byte of the word read through the second G-A snapshot, after that word is shifted logically right by 22.

Further calls use a single shifted index and later a duplicated shifted index. Additional calls include a producer result forwarded to another dependency. A final dependency then supplies an 8-bit result and a secondary register-derived byte pointer.

The terminal direct effects occur in this order:

1. Zero is written through that secondary byte pointer.
2. The three-byte G-C operand is consumed and combined with the final byte result: G-C supplies the upper 24 bits, and the result supplies the lower eight bits. The resulting 32-bit value is assigned to G-B.
3. A 16-bit zero is written at `(third result’s low half & 0x3FFFFFFF) >> 7`.
4. Address zero is invoked as a function target with three visible zero arguments.

A return is represented after this last invocation. Reachability depends on whether the address-zero invocation is valid and returns.

## Side effects

Direct effects comprise 32-bit writes, byte writes, a 16-bit write, and the two assignments to G-B. Dependencies occur between many of these effects and may themselves modify memory or execution state.

No disjointness is established among computed addresses, global storage, low memory, and secondary-output pointers. Therefore:

- Indexed destinations may coincide.
- A byte write may alter a later selector or word source.
- Global assignments may affect overlapping storage.
- The secondary-pointer clear precedes consumption of G-C and can affect it if storage overlaps.
- The final halfword write follows the G-B composition and can overwrite overlapping storage.

The final G-B assignment is not necessarily the last modification of its physical storage.

There is no visible rollback, bounds check, null check, error translation, or recovery branch. If execution stops, a completed prefix of direct effects may remain visible.

No allocation or deallocation operation is explicitly identified in the body. This does not establish that dependencies avoid allocation, retention, ownership transfer, or release. Ownership, lifetime, synchronization, and reentrancy are **documented_only**.

## Acceptance examples

These are conditional static obligations, not executed tests. They assume the relevant dependencies return and the required accesses and arithmetic are valid.

1. **Explicit input use.** Changing only the first explicit input creates no new explicit body-level use of it. The first invocation still visibly receives the second input. This is not a proof that hidden calling-convention inputs are independent of the first input.

2. **Repeated shift.** For every unsigned 32-bit first G-A snapshot, shifting right by 23 twice yields zero. The corresponding phase-2 indexed write stores a full 32-bit zero.

3. **Extraction and truncation.** If the phase-2 word read yields `0xFFC00000`, its right shift by 22 is `0x3FF`. The phase-3 byte write stores `0xFF`. The later selector read based on that extraction uses address `4 × 1023 + 1`, or 4093.

4. **Fresh selector observations.** If address 1 contains 4 for one read and an intervening dependency changes it to 9, a later read selects address 26, not address 21.

5. **Byte copy versus retained word.** A source word of `0x12345678` produces a byte write of `0x78`. Where phase 5 subsequently propagates the retained full word, it writes `0x12345678`, not `0x78`.

6. **First wide result.** If the first 64-bit result has low half `0x11223344` and high half `0x55667788`, those two 32-bit patterns are forwarded in that order, followed by the earlier G-B-assigned value shifted right by 23.

7. **Second wide result.** If the second result has low half 3 and high half 5, the first associated indexed write stores 12 at address 40. After the second G-A read, the next dependency receives 12, 5, 12, and 12.

8. **Third wide result.** If the third result has low half 256 and high half 7, its associated four-argument call receives 7, 7, 7, and 1024. Its later selector read uses address 1, and its final halfword destination is address 2.

9. **G-A resampling.** If the second G-A snapshot is 1000, the late word source is address 1020 regardless of the first snapshot, subject to intervening effects on that source.

10. **Final composition.** If the G-C operand observed after the secondary-pointer clear is numerically `0x123456` and the final byte result is `0xAB`, G-B is assigned `0x123456AB`. Physical byte order remains platform-dependent.

11. **Terminal dispatch.** If preceding operations complete, address zero is invoked with three zero arguments. A fault is possible but not established solely by the numeric target.
