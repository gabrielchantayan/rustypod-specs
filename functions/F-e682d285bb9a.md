# F-e682d285bb9a

## Purpose

F-e682d285bb9a transfers six consecutive 32-bit words from an indirectly referenced record into a destination object, retrieves one 32-bit word from each of two indexed tables into a caller-supplied output area, and then transfers control through a function pointer stored in the destination object.

The established behavior is an ordered sequence of memory accesses followed by indirect dispatch. The six-word transfer is not established as an atomic snapshot. The two table accesses are separate operations, with the first output write occurring before the second table pointer is read.

The meanings of the copied words, the relationship between the two tables, and the purpose of the dispatched routine are unknown.

## Behavior

### Record selection

The routine first reads the record reference from destination offset +0x004. Subsequent record-relative accesses use that selected address.

The destination’s record-reference field is not visibly reread. Changing that field later does not, by itself, redirect this invocation’s remaining record-relative accesses.

### Six-word transfer

The first four source words are sampled in a non-address-order sequence:

1. The words at record offsets +0x1B4, +0x1B8, and +0x1BC are read, in that order, and retained.
2. The word at +0x1B0 is read and written to destination offset +0x570.
3. The three retained words are written to destination offsets +0x574, +0x578, and +0x57C, respectively.

The remaining pair is handled separately:

1. The word at record offset +0x1C4 is read and retained.
2. The word at +0x1C0 is read and written to destination offset +0x580.
3. The retained word is written to destination offset +0x584.

For stable, nonoverlapping storage, the resulting correspondence is straightforward: the six words beginning at record offset +0x1B0 appear at destination offset +0x570 in the same order.

For overlapping or externally changing storage, that final-state description is insufficient. The sampling order matters:

- The second, third, and fourth words are sampled before the first destination write.
- The fifth and sixth words are not sampled until after the first four destination writes.
- The sixth word is sampled before the fifth word.

Consequently, an early destination write may affect a later source read if their addresses overlap. Previously retained words are not reread.

All six destination writes precede either indexed-table read.

### Indexed outputs

After the six-word transfer:

1. The first table address is read from record offset +0x1A4.
2. A four-byte entry is read at that address plus four times the index.
3. That entry is written to output offset +0x000.
4. The second table address is read from record offset +0x1A8.
5. A four-byte entry is read at that address plus four times the same index.
6. That entry is written to output offset +0x004.

The routine does not visibly read both table pointers in advance. In particular, the first output write occurs before the second table pointer is read. If that write overlaps the second pointer field, the second lookup uses the resulting field contents.

Neither an entry count nor a bounds check is visible. There is no explicit rejection of negative indices. On an execution model where the calculation is defined, a negative index selects an address before the table base; whether that address is valid is a separate question.

The expression “four times the index” describes the visible scaling operation, not an assurance of unbounded integer arithmetic. Extreme values may encounter signed-arithmetic or address-width limits. The supplied material does not establish a portable overflow or wraparound contract.

### Indirect dispatch

After both output writes, the routine reads the dispatch target at destination offset +0x5DC and transfers control through it.

The target is therefore selected after all eight direct writes. An overlapping output write can affect target selection.

The recovered call expression shows no explicit arguments. This is not sufficient evidence that the actual target takes no arguments: register state, stack state, calling convention, and implicit inputs are not established.
