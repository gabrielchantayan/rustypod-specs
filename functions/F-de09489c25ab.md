# F-de09489c25ab

## Purpose

F-de09489c25ab resolves a name-bearing expression against a chain of contexts. It searches ordinary sources, conditionally searches a two-name special namespace, recognizes an implicit-column name, and considers expression aliases.

Observable behavior includes expression-field writes, dependency calls, usage-word updates, diagnostics, and context-counter increments. Resolution is not transactional: failure or ambiguity can leave mutations in place.

“Column,” “source,” and “alias” describe inferred database-resolution intent. The contract below distinguishes explicit behavior from dependency-defined effects and unresolved target semantics.

## Interface

The function accepts six arguments and returns a 32-bit value:

1. **Owner pointer.** Its first 32-bit word supplies an environment pointer. Offset `0x188` supplies an optional special-namespace pointer.
2. **Additional 32-bit argument.** No direct use is established.
3. **Qualifier input.** Passed to a name-producing dependency.
4. **Terminal-name input.** Passed to that dependency; the quoted-name escape also reads its first 32-bit word as a pointer and dereferences one byte.
5. **Initial context pointer.** Starts the context chain and supplies the explicit error-counter destination.
6. **Mutable expression pointer.** Receives field writes and is passed to an unidentified external dependency.

Three initial calls to F-e7c4e7dd076d produce handles termed **outer qualifier**, **inner qualifier**, and **terminal name**. The first visibly receives only the environment; the other two additionally receive arguments 3 and 4 respectively. Argument 2’s relationship to the outer qualifier is **documented_only**.

### Results

| Result | Established condition |
|---|---|
| `0` | The internal binding count is exactly one at successful completion, or the quoted-name escape applies. |
| `1` | Ordinary completion occurs without exactly one binding, including disabled resolution. |
| `2` | A matching alias is rejected by the aggregate-permission check. |

A result of `0` does not establish that an unidentified dependency copied or validated the expression.

**Context:** source-list pointer at `0x04`, alias-list pointer at `0x08`, 32-bit reference and error counters at `0x0c` and `0x10`, aggregate-permission byte at `0x14`, and enclosing-context pointer at `0x20`.

**Source list:** signed 16-bit count at its start; entries begin at `0x08`, with 48-byte stride. Entry-relative fields are explicit source name at `0x08`, descriptor pointer at `0x0c`, associated-object control word at `0x10`, source identifier at `0x18`, and two usage words at `0x28` and `0x2c`.

**Table-like descriptor:** name at `0x00`, signed 32-bit column count at `0x04`, column-array pointer at `0x08`, distinguished index at `0x0c`, and identifier at `0x4c`. Column records have 20-byte stride, with name at `0x00`, metadata at `0x0c`, and attribute byte at `0x12`.

**Special namespace:** shared descriptor pointer at `0x00`, source identifiers at `0x04` and `0x08`, and corresponding 32-bit usage words at `0x0c` and `0x10`. Identifier `-1` disables that entry.

**Alias list:** signed 32-bit count at `0x00` and record-array pointer at `0x0c`. Records have 12-byte stride, with expression pointer at `0x00` and optional alias name at `0x04`.

## Behavior

### Initialization and gate

The environment, initial context, and initial zero binding/candidate counts are retained before searching. The three name-producing calls occur before the gate byte at environment offset `0x1e` is tested.

If the gate is nonzero, searching, diagnostics, and usage marking are bypassed. Ordinary cleanup still runs, and the result is `1`. This path does not explicitly initialize the expression’s source identifier.

If the gate is zero, source identifier `0x24` is first set to all-one bits.

### Ordinary source search

A non-null current context is searched while the binding count is zero. Its source-list pointer is captured for that traversal. Each visited entry supplies a descriptor pointer; F-49f750c2c596 is called with the environment and descriptor identifier before qualification, including when no inner qualifier exists.

Qualification is established as follows:

- No inner qualifier: the entry is eligible.
- Explicit entry name present: F-e6db2171781a compares it with the inner qualifier. The outer qualifier is not separately tested.
- Otherwise: the descriptor name must be nonzero and compare equal to the inner qualifier. If the outer qualifier is present, an environment-derived name, selected using F-49f750c2c596’s result, must also compare equal to it.

Comparison result zero selects equality branches. Encoding and comparison semantics are unknown.

Each eligible source increments the candidate count, which persists across contexts. The first candidate supplies a provisional expression source identifier, retained descriptor identifier, and selected ordinary-entry pointer even without a matching column.

Columns are searched in increasing index order. Only the first equal column name in each source is processed. A match:

1. Reads that index’s metadata using the descriptor’s then-current column-array pointer.
2. Increments the 32-bit binding count.
3. Writes the source identifier and retains the descriptor identifier.
4. Writes the index, substituting `-1` if it equals the descriptor’s distinguished index.
5. Reads and writes the attribute byte.
6. Unless expression flag `0x0100` is set, calls F-4a95613e1504 and stores its result at `0x04`.
7. Selects the current ordinary entry.

F-4a95613e1504 receives the environment, a byte obtained through nested environment pointers, captured column metadata, all-one bits, and zero. No result-validation branch is visible.

Scanning continues across sources after a match. Later matches can overwrite fields and increase ambiguity.

### Cached and reread search state

Neither ordinary nor special column search uses one coherent array snapshot:

- The name-traversal pointer is captured from the column-array pointer before the column loop and advances by 20 bytes after each unsuccessful comparison.
- The signed column count is reread for loop tests.
- After an equal comparison, the descriptor’s column-array pointer is reread for metadata and again for the attribute access.
- Metadata is captured before F-4a95613e1504; its result is then written to the expression.

Consequently, a comparison dependency that replaces the array pointer can cause the matched name to come from the captured array while metadata and attributes come from the replacement array. These accesses retain the same numeric column index, not necessarily the same underlying record.

The ordinary source count is also reread during traversal and during the following-entry availability check. It is not a traversal-wide snapshot. The captured source-list pointer is not automatically refreshed from the context after each dependency call.

These distinctions are established access behavior. Dependencies are not assumed to preserve the referenced memory.

### Following-entry suppression

After an ordinary column match, if another entry remains according to the reread count, the following entry is skipped when either:

- bit `0x04` is set in the byte at current-entry-relative offset `0x45`; or
- a non-null auxiliary descriptor at relative offset `0x50` contains a name equal to the terminal name.

The auxiliary descriptor has an array pointer at `0x00` and signed count at `0x04`; names are accessed at eight-byte stride. Its count and array pointer are read during this comparison loop.

Suppression advances past one additional source entry. Its higher-level meaning is **documented_only**.

### Special namespace

After ordinary searching yields no binding, the special namespace is considered only when the outer qualifier is absent and the inner qualifier is present.

The first enabled entry whose fixed embedded name compares equal is selected, with priority given to the first entry. The fixed names’ text is unavailable. Selection writes the expression source identifier before checking whether the shared descriptor is non-null.

A non-null shared descriptor supplies the retained descriptor identifier, contributes one candidate, and is searched using the cached-versus-reread behavior above. A match sets the binding count to one, writes position and attribute, conditionally obtains metadata, and writes the shared descriptor pointer to expression offset `0x3c`.

The selected special usage word is updated from the **original array index**, even if the expression position became `-1`. The represented operation shifts signed integer one by the index’s low eight bits, combines that result with zero for indices below 32 or an all-one word otherwise, and ORs it into the existing word.

For indices 0–30, this establishes the corresponding bit contribution. Index 31 involves a signed shift into the sign bit; counts of at least 32 introduce further shift-width uncertainty. Target semantics are **documented_only**. The all-one operand for indices at least 32 does not independently justify unconditional saturation when the shift itself is unresolved.

Special matching does not clear a previously selected ordinary entry. Such an entry can therefore still participate in later ordinary usage processing and final associated-object assignment.

### Implicit-column fallback

If no binding exists and exactly one candidate has accumulated, F-56e7529314e4 receives the terminal handle. A nonzero result establishes one binding, writes position `-1`, and writes attribute 100.

The source identifier, retained descriptor identifier, and selected-entry state are not independently reconstructed. They are whatever earlier candidate and special-namespace processing left behind.

### Alias fallback

If still unresolved, a non-null alias list is searched only when the inner qualifier is absent. The first nonzero alias name comparing equal is selected.

When the current permission byte is zero and the referenced expression has 16-bit flag `0x0002`, the function reports “misuse of aliased aggregate” through F-2022b0f73f3b, supplying the matched alias handle. It then passes the terminal handle to F-94cb53877c15 and returns `2`. Ordinary cleanup and the explicit error-counter increment do not occur.

Otherwise:

- F-1a5398bcc6b3 receives the environment and returns a pointer. No source-expression argument is visible.
- If the destination has flag `0x0100`, its metadata is written to the returned object and that object’s corresponding flag is set.
- Destination payload `0x1c` is passed to F-94cb53877c15 if flag word `0x20` has bit 0 set.
- Destination payload `0x14` is then passed if the subsequently read flag word `0x18` has bit 0 set.
- The unidentified external dependency receives the destination expression, returned pointer, and `0x44`.
- The returned pointer is passed to F-94cb53877c15.

The external call’s effects are unknown. Neither an exact byte copy nor replacement of the destination expression is established.

The function then records one binding, clears the selected ordinary-entry pointer, and jumps to terminal-handle disposal and successful completion, bypassing ordinary normalization. The retained descriptor identifier is not explicitly reset.

### Context traversal and completion

After unsuccessful fallbacks, the enclosing-context pointer is read and searching repeats. Candidate state persists; traversal stops once the binding count is nonzero or the current context is null.

With zero bindings and no inner qualifier, the function dereferences the terminal-name input as described above. If the reached byte is `0x22`, it passes only the terminal handle to F-94cb53877c15 and returns `0`, bypassing diagnostics, ordinary cleanup, usage processing, and reference increments.

Otherwise, a binding count other than one reports “no such column” for zero or “ambiguous column name” for nonzero. Formatting selection depends on qualifier presence. The visible diagnostic call supplies the owner, selected format, error-description handle, and one selected name handle; additional formatting arguments are not established. The initial context’s error counter is then incremented.

Before ordinary cleanup, a nonnegative stored expression position and non-null selected ordinary entry trigger F-5bbdce2c8eb3 with arguments `1`, `0`, and the position clamped to 63. Its returned low word is ORed into entry offset `0x28`, then its high word into `0x2c`. The dependency’s return is not established as a single-bit mask. This processing can occur after an ambiguity diagnostic.

Ordinary cleanup calls F-94cb53877c15 for outer then inner handles, calls F-841dc33ee157 for expression `0x08` and clears it, repeats for `0x0c`, then writes operation `0x95`. The terminal handle is passed to F-94cb53877c15 afterward.

For exactly one binding, including accepted aliases:

1. F-0ce6e03f9d03 receives the owner, expression, retained descriptor identifier, and current context’s then-read source-list pointer.
2. If a selected ordinary entry exists and its then-read `0x10` word is zero, its descriptor pointer is written to expression `0x3c`.
3. Reference counters increment from the initial context through the resolving context, inclusive. Each next link is read as propagation proceeds.
4. The function returns `0`.

Other ordinary completions return `1`.

## Side effects

Explicit writes affect the expression, source usage words, special usage words, and context counters. They are not rolled back on errors.

Alias-path writes through F-1a5398bcc6b3’s result precede the unidentified external call. What that call subsequently changes remains unknown.

F-94cb53877c15 and F-841dc33ee157 are disposal-like by usage, not proven ownership transfers. Normal cleanup submits all three converted handles; alias completion and both early-return paths visibly submit only the terminal handle. Payload-disposal calls depend on destination flags. These asymmetries do not establish leaks, shared ownership, or safe release.

Unknown dependencies can mutate memory later reread by this function. Call ordering and explicit caching, rather than assumed purity, determine the contract.

## Acceptance examples

These are conditional static expectations, not executed tests. Except where stated, dependencies are assumed to return normally without disrupting the relevant memory.

1. **Unique ordinary match:** One unsuppressed match records source and position, conditionally obtains metadata, normalizes the operation, invokes successful-binding notification, increments applicable reference counters, and returns `0`. Ordinary usage storage receives the two words returned by F-5bbdce2c8eb3.

2. **Ambiguity:** Two unsuppressed ordinary matches produce count two. Later writes can replace earlier expression fields. The ambiguity diagnostic and initial error-counter increment occur. Usage processing can still affect the later selected entry. Result: `1`.

3. **Distinguished ordinary index:** The stored position becomes `-1`; ordinary usage processing is skipped because its signed position test fails.

4. **Ordinary index 80:** Position remains 80 unless distinguished. F-5bbdce2c8eb3 receives `1`, `0`, `63`; its returned words are ORed into usage storage. Setting bit 63 specifically requires a dependency contract not supplied here.

5. **Special index 5:** The corresponding special usage word gains bit 5 under the represented arithmetic, even when distinguished-index substitution writes position `-1`.

6. **Special indices 31 or 40:** The shift’s target semantics remain unresolved. Neither a portable bit-31 result nor unconditional all-one saturation is an acceptance requirement established by this source.

7. **Changed array during comparison:** If a comparison replaces the descriptor’s column-array pointer and returns equality, metadata and attribute accesses use subsequent pointer reads, not necessarily the array supplying the compared name.

8. **Accepted alias:** Subject to valid returned storage, the explicit flag preservation and payload calls occur, followed by the unidentified three-argument call and returned-pointer disposal. Successful completion follows with ordinary normalization bypassed. Destination replacement is not guaranteed.

9. **Forbidden aggregate alias:** The diagnostic occurs and result is `2`; ordinary normalization and explicit error-counter increment are absent.

10. **Disabled resolution or quoted escape:** A nonzero gate produces ordinary cleanup and result `1`. An eligible unresolved quoted name instead returns `0` after terminal-handle disposal, bypassing ordinary cleanup.

## Uncertainties

The following are **documented_only**:

- Dependency internals, ownership, comparison rules, allocation failures, and global preservation.
- Argument 2’s role and the first conversion call’s complete interface.
- How alias-object acquisition relates to the matched expression.
- The unidentified external dependency’s memory effects.
- F-5bbdce2c8eb3’s returned mask semantics.
- Special-namespace shifts involving the sign bit or excessive counts.
- Fixed namespace names and suppression metadata’s semantic meaning.

Valid pointers, accessible traversed records, and a consistent finite context chain are preconditions. Selective null checks do not establish general null safety: unresolved diagnostics dereference the initial context, and successful propagation requires reaching the resolving context.

Binding count is unsigned 32-bit; candidate and traversal arithmetic is predominantly signed 32-bit, with a signed 16-bit source count. Counter overflow, invalid address arithmetic, concurrent changes, cycles, and invalid dependency-returned pointers are not safely handled by visible checks. No broader defined behavior is claimed for those cases.
