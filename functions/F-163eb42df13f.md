# F-163eb42df13f

### Fixed suffix position and separator scanning

After a prefix result of 3, F-2a4c402ba617 is called. It returns a reference through which the function obtains a classification-table base.

The scan starts exactly ten bytes after the adjusted prefix start, irrespective of how much input the prefix dependency actually consumed:

- Without a skipped minus: original input address plus 10.
- With a skipped minus: original input address plus 11.

For each scan position, the input byte is treated as an unsigned value from 0 through 255. That value selects a one-byte classification-table entry. The scan advances by one byte when either:

- Bit 0 of the selected entry is set; or
- The input byte equals 0x54, uppercase “T”.

The classification test precedes the explicit uppercase-“T” test. The latter is evaluated only when classification bit 0 is clear. The supplied expression reads the input byte again for that second test; it is not a promise to reuse a single captured byte throughout the iteration.

The classification accessor is called once. The table base is read through its returned reference during successive condition evaluations, rather than being explicitly captured once for the entire scan. In the supplied target representation, that base is obtained through a 32-bit integer access; the selected classification entry is read as one byte.

The scan stops at the first position for which both conditions are false. It has no explicit end-of-input check or iteration limit. In particular:

- A zero byte stops scanning only if its classification bit 0 is clear.
- Lowercase “t”, value 0x74, has no unconditional separator treatment.
- Repeated qualifying bytes are skipped without a fixed maximum count.

These rules establish the accesses and branch conditions, not the safety of concurrent mutation or unsupported aliasing.
