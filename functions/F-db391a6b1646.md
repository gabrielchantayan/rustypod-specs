# F-db391a6b1646

## Purpose

F-db391a6b1646 is a parameterless routine that interleaves unresolved indirect calls with explicit word, byte, and halfword memory accesses. It extracts fields from register-derived words, writes computed locations, uses selector bytes to choose byte destinations, copies low bytes from word values, publishes shared output state twice, and ultimately attempts a call through numeric address zero.

No application-level purpose is established. The repeated offsets do not, by themselves, establish objects, arrays, allocation, serialization, or a dispatch protocol.

This contract describes static evidence only. Every operation is conditional on earlier calls returning and earlier memory accesses completing. No runtime tests have been performed.

## Interface

### Explicit interface

- No explicit parameters.
- No declared return value.
- No explicit status or error-reporting channel.
- A normal return is represented only after the final address-zero call returns.

### Implicit inputs and shared output state

The visible computation consumes:

- Incoming link-register-derived state used to form the first indirect target.
- Two unexplained unsigned 32-bit register values used after the first two calls.
- Ordinary call results and additional-register outputs, including indices, words, an apparent byte result, three apparent 64-bit results, and a final byte pointer.
- Memory read through computed addresses, including low numeric addresses.
- A shared word designated **G-base**, whose sampled value later supplies an address base.
- A three-byte shared component designated **G-upper**, sampled for the terminal composite publication.

**G-control is shared output state, not an established implicit input.** The body contains two explicit word writes to G-control and no explicit read of its previous value. Dependencies or aliased accesses could read its storage, but those possibilities do not establish an unconditional dependency on its incoming contents.

There are six explicit selector-byte reads: four computed-address reads and two direct reads at address 1. The first computed address necessarily equals 1. Therefore, reaching all six operations entails at least three separate explicit reads at address 1. The other three computed reads can also select address 1.

### Widths and arithmetic

A byte is 8 bits, a halfword 16 bits, and a word 32 bits. Each apparent 64-bit result is divided into low and high 32-bit portions. Byte stores retain only the low eight bits.

The following notation describes address relationships:

- \(R(x)=4x\).
- \(S(x)=4x+20\).
- \(T(x)=16x+20\).

These formulas do not establish array bounds, object layouts, alignment, or accessibility. A word access covers four bytes; a halfword access covers two.

Unsigned right shifts are logical. Operations explicitly performed on unsigned 32-bit values retain 32-bit results; in particular, unsigned left shifts discard bits beyond bit 31. Some index multiplication, address addition, and left shifts instead use represented signed-word expressions. Their overflow behavior, pointer conversion, and relationship to machine address wrapping remain unresolved. Mathematical address ranges below apply where the bounded expressions themselves establish them.

### Preconditions and failures

Successful completion requires all executed targets and memory accesses to be usable, including low-address accesses, potentially unaligned accesses, and the terminal address-zero call.

No explicit bounds checking, alignment checking, ownership checking, recovery branch, or rollback is represented. A fault or non-returning dependency can leave earlier writes observable.

## Behavior

### Initial extraction and indexed word writes

The first indirect target depends on incoming link state. A second unresolved call occurs before the routine uses two register-derived unsigned words, designated **Seed-A** and **Seed-B**.

The routine derives:

- **Extract-A**: Seed-A shifted right by 22, in the range 0–1023.
- **Extract-B**: Seed-B shifted right by 23, in the range 0–511.

An additional-register output supplies **Index-A**. Extract-A is written as a word at \(S(\text{Index-A})\). The next dependency receives Index-A twice, followed by Extract-B and Extract-A.

A subsequent word result is forwarded to another dependency. Later calls supply **Index-B**. Extract-A is written at \(S(\text{Index-B})\), followed by a dependency receiving \(R(\text{Index-B})\).

Extract-B is also shifted right by another 23 bits. This **Double-Extract** is necessarily zero: Extract-B has at most nine significant bits. Its retained value later supplies a selector-read address.

### Zero publications and the first packed word

Further calls supply an unsigned additional-register value, **Index-C**. A zero word is stored at \(S(\text{Index-C})\), then a dependency receives Index-C.

After another result-forwarding step and intervening calls, **Index-D** is obtained. The routine writes Double-Extract, therefore zero, at \(S(\text{Index-D})\).

Before calling the dependency that receives \(R(\text{Index-D})\), it reads and retains **Packed-A** from:

\[
20+((\text{Index-C}\mathbin{\&}\texttt{0x1fffffff})\gg19).
\]

The starting address ranges from 20 through 1043 inclusive. It is not rounded to a word boundary and can be unaligned.

### First two selector-directed stores

After further calls, **Field-A** is formed by shifting Packed-A right by 22. Field-A ranges from 0 through 1023.

The first selector byte is read at Double-Extract + 1, necessarily address 1. If its unsigned value is **Selector-A**, the routine stores Field-A’s low byte at \(17+\text{Selector-A}\). The stored bits are Packed-A bits 29–22; bits 31–30 do not survive byte truncation.

The next dependency receives the same additional-register word three times and zero as its fourth explicit argument. Later calls include one explicitly receiving zero.

Another call supplies an index. Before the dependency consuming that index shifted left by two, the routine:

- Reads a selector byte at \(4\text{Field-A}+1\).
- Writes zero at 17 plus that selector.

This second selector-read address ranges from 1 through 4093 in steps of four. It equals 1 exactly when Field-A is zero. Every selector-directed destination ranges from 17 through 272.

### Two direct reads at address 1

Further calls supply an index whose left-shift-by-two value is passed twice to a dependency. A following call returns **Result-A**, which is forwarded to another dependency.

After another call, the routine directly reads the byte at address 1 and writes zero at 17 plus that fresh value. This is the second necessarily address-1 selector observation overall, and the first syntactically direct one.

An additional-register word is retained as **Shift-Seed** and passed to a dependency. A subsequent call result is forwarded together with Result-A shifted right by 23.

After intervening calls and another returned index, the routine directly reads address 1 again. This value is retained as **Byte-Base**, and zero is written at \(17+\text{Byte-Base}\). The next dependency receives the new index shifted left by two.

These address-1 reads are separate observations. Neither the earlier value nor an assumed stable memory byte substitutes for a later read. Subsequent uses of Byte-Base use its retained value.

### First G-control write and Byte-Base copy

A later dependency receives another scaled index twice. Its successor returns **Result-B**.

The routine writes Result-B as a word to G-control, then calls a dependency with Result-B. This publication does not explicitly read or incorporate G-control’s previous contents.

After another call, the routine reads a word at Byte-Base + 116 and stores that word’s low byte at Byte-Base + 1. Since Byte-Base is an unsigned byte:

- The word-read starting address is 116–371.
- The byte-write address is 1–256.

When Byte-Base is zero, this copy writes address 1.

The next dependency receives Shift-Seed shifted left by 11. A following call supplies the first apparent 64-bit result. Its successor receives the low 32-bit portion, high 32-bit portion, and Result-B shifted right by 23, in that order.

### Repeated copy at one retained base

Further calls return **Index-E**. Its four-times value is retained as **Base-E**. The routine reads a word at Base-E + 116, writes its low byte at Base-E + 1, then calls a dependency with Base-E.

Later calls return **Index-F**. Its represented left shift by two is assigned to an unsigned 32-bit value, **Base-F**.

Before the next multi-argument call, the routine repeats the copy using **Base-E**, not Base-F. It freshly reads Base-E + 116 and writes the resulting low byte at Base-E + 1. Dependency effects or aliasing can make this second read differ from the first.

The following dependency receives, in order:

1. Shift-Seed shifted left by 12.
2. Base-F.
3. Base-F again.
4. Index-F shifted left by 18.

The signed-source shifts involved here do not establish a portable overflow model.

### Payload capture and full-word distribution

Several calls follow, including two result-forwarding steps. A later returned **Index-G** supplies **Base-G**, its four-times value.

The routine reads and retains the entire word at Base-G + 116 as **Payload**. It writes Payload’s low byte at Base-G + 1, then calls a dependency with Base-G.

Later calls return **Index-H**. Payload is written as a full word at \(T(\text{Index-H})\), using a scale of sixteen rather than four.

The following dependency receives:

\[
(\text{Base-F}\gg2)\ll16.
\]

Both operations act on retained unsigned 32-bit Base-F. The right shift discards its bottom two bits before the left shift, and the final result is 32 bits. This expression must not be unconditionally replaced by Index-F shifted left by sixteen.

After additional calls and forwarding steps, **Index-I** is returned. Payload is written as a full word at \(S(\text{Index-I})\), followed by a dependency receiving \(R(\text{Index-I})\).

The earlier byte copy does not truncate the retained Payload used by either word store.

### Link publication and another zero word

More calls return **Index-J**. Its represented left shift by two is retained as **Link-A**.

Link-A is written as a word at:

\[
(\text{Base-F}\mathbin{\&}\texttt{0xfffffffc})+20.
\]

The following dependency receives Link-A twice. Further calls include two result-forwarding steps.

A later **Index-K** selects \(S(\text{Index-K})\). A zero word is stored there, then a dependency receives \(R(\text{Index-K})\).

### Second paired result and G-base snapshot

A second apparent 64-bit result supplies **Pair-Low** and **Pair-High**. **Link-B** is formed by interpreting the low portion through a represented signed-word operation and shifting it left by two.

The visible order is:

- Write Link-B at \(S(\text{Pair-High})\), with Pair-High used as a signed index.
- Read G-base and retain its word value as **Saved-Base**.
- Call a dependency with Link-B, Pair-High, Link-B, and Link-B.

After further calls return **Index-L**, Link-B is written at \(S(\text{Index-L})\). The routine then reads a word at Saved-Base + 20 as **Packed-B**, before calling the dependency receiving \(R(\text{Index-L})\).

The snapshot preserves the base value, not the contents of the addressed memory. A subsequent G-base change does not redirect this read; a change to memory at Saved-Base + 20 before the read can change Packed-B.

### Final computed selectors

A third apparent 64-bit result supplies unsigned 32-bit **Final-Low** and a high word, **Final-High**.

The fifth selector byte is read at:

\[
(\text{Payload}\gg23)+1.
\]

This address ranges from 1 through 512. Packed-B’s low byte is written at 17 plus that selector.

The next dependency receives Final-High three times, followed by Final-Low shifted left by two. This last shift is an unsigned 32-bit operation.

After intervening calls, a forwarding step, and another returned index, the sixth selector byte is read at:

\[
((\text{Final-Low}\mathbin{\&}\texttt{0x3fffffff})\gg21)+1.
\]

This address also ranges from 1 through 512. The routine writes the low byte of Packed-B shifted right by 22 at 17 plus the selector. The stored value comprises Packed-B bits 29–22.

This store precedes the dependency consuming the latest index shifted left by two.

### Terminal operations

Further calls include a dependency receiving a newly returned index shifted left by two twice, a call without explicit arguments, and a call through a differently derived target whose word result is forwarded.

A final apparent byte-returning call supplies **Final-Byte** and an additional-register byte pointer. The remaining visible order is:

1. Write a zero byte through that pointer.
2. Read the three-byte G-upper component.
3. Write G-control as a word containing Final-Byte in bits 7–0 and G-upper in bits 31–8.
4. Write a zero halfword at:
   \[
   (\text{Final-Low}\mathbin{\&}\texttt{0x3fffffff})\gg7.
   \]
5. Attempt a call through numeric address zero with three explicit zero arguments.

The halfword starting address ranges from zero through 8,388,607 and can be unaligned. The pointer store can affect the subsequently sampled G-upper if their storage overlaps.

The final G-control value is assembled from G-upper and Final-Byte, not from an explicit read of G-control’s prior word. No recovery is represented if any terminal operation fails.

## Side effects

## Acceptance examples

These are conditional static expectations, not executed tests. Relevant calls must return and accesses must succeed.

1. **G-control is not an explicit prior-value input.** Holding Result-B, Final-Byte, and the sampled G-upper value fixed makes the two explicit G-control stores fixed, regardless of its incoming word. This example additionally requires that changing that incoming word does not alter dependencies or aliased reads.

2. **Three necessary address-1 observations.** The first computed selector reads address 1, and the two direct selector reads read it again. They remain distinct observations even if they return identical bytes.

3. **All six selectors at address 1.** If Field-A is zero, Payload is below \(2^{23}\), and masked Final-Low is below \(2^{21}\), the remaining computed selector addresses also equal 1.

4. **Fresh selector values.** If the first selector observation returns 2 and the later first direct observation returns 7, their destinations are 19 and 24. The first stores Field-A’s low byte; the later store writes zero.

5. **Extraction and truncation.** Seed-B equal to `0xffffffff` produces Extract-B equal to 511 and Double-Extract equal to zero. Packed-A equal to `0xffffffff` produces Field-A equal to 1023, whose byte publication is `0xff`.

6. **Unaligned packed read.** Index-C equal to `0x00080000` selects starting address 21 for the Packed-A word read, without alignment rounding.

7. **Repeated source observation.** If the two Base-E word reads return `0x11223344` and `0x55667788`, the corresponding byte stores write `0x44` and `0x88`.

8. **Payload width preservation.** Payload equal to `0xabcdef12` supplies `0x12` to its byte copy and `0xabcdef12` to both subsequent Payload word stores.

9. **Snapshot and terminal composition.** Changing G-base after its snapshot does not change the saved address base. If G-upper is `0x123456` when sampled and Final-Byte is `0xab`, the terminal G-control store writes `0x123456ab`.

10. **Zero terminal destination.** Final-Low equal to zero selects address zero for the halfword store. No guard prevents that access or the following address-zero call.
