# F-0496b13d546e

## Purpose

F-0496b13d546e conditionally processes a small byte payload associated with a context and an input record. Processing is gated by an identifier match, a non-null payload address, and a dependency result. Two accepted format combinations produce a packed 32-bit value and a selector. Depending on that selector and a further dependency result, the function invokes a three-call sequence around a submission operation.

The function also has a special state transition for one two-byte payload form: when the payload’s second byte is 3 and a context flag is exactly 1, it invokes an additional dependency and clears the flag.

These are structural descriptions, not established domain meanings. The supplied evidence does not establish whether the payload represents a protocol message, command, notification, or another application object.

The normal non-null-record path ends with a cleanup-like call followed by a call marked non-returning. Consequently, the apparent integer result is not an ordinarily observable return value on that path.

## Behavior

### Entry reads and gates

After capturing the two format-associated record fields and the payload address, the function establishes the initial outcome value of 11.

It then evaluates three gates in order, with short-circuit behavior:

1. The context identifier at offset 0x2d0 must equal the record identifier.
2. The captured payload address must be non-null.
3. F-674d3df9cb1e must return a nonzero result.

F-674d3df9cb1e is not called if either earlier gate fails. If any gate fails, no payload byte is read by the processing logic, and execution proceeds to the final record-handling sequence.

The format fields and payload pointer are captured before F-674d3df9cb1e is called. Changes made by that dependency to the record therefore do not cause those fields to be reloaded. The payload contents are read afterward and may reflect intervening changes.

When all gates succeed, the internal outcome becomes 62. The function accepts exactly two combinations of the narrowed format fields.

### Accepted combination A: format value zero, companion value two

The low 16 bits of the record word at offset 16 must be zero. The low 16 bits of the word at offset 12 must equal 2. Upper 16-bit portions of those words do not affect these comparisons.

The function:

1. Reads payload byte 1 and zero-extends it into a 32-bit selector.
2. Constructs a 32-bit packed value from payload bytes 0 and 1.

For payload bytes \(b_0\) and \(b_1\), interpreted as unsigned values from 0 through 255:

\[
\text{packed value} = b_0 \times 65536 + b_1 \times 256.
\]

Thus the low eight bits and the high eight bits of the resulting 32-bit value are zero. This formula specifies the numeric value independently of the byte order used when that value is stored in memory.

The representation uses payload byte 1 in both selector extraction and packed-value construction. It does not establish a single atomic snapshot of both bytes or an exact evaluation order between all reads within the packed expression. Stable payload storage is required for the simple formula to describe one coherent pair of input bytes.

#### Selector-3 state transition

If the selector is exactly 3, the function reads the context flag at offset 0x2fc. Only a flag value of exactly 1 triggers the special sequence:

1. Invoke a dependency whose opaque ID is not supplied.
2. Add 4 to its returned address-like value.
3. Read the context word at offset 0x2d4.
4. Invoke F-4944ce526800 with four arguments: the adjusted address, that context word, 6, and 0.
5. Write zero to the context flag at offset 0x2fc.

The flag write occurs only after both dependencies return normally. The selector remains 3; clearing the flag does not change the selector.

A flag value other than 1 is not cleared by this branch. If the selector is not 3, the flag is not read by this branch.

The evidence supplies no bounds or validity check for the returned address plus 4.

### Accepted combination B: format value two, companion value one

The low 16 bits of the record word at offset 16 must equal 2. The low 16 bits of the word at offset 12 must equal 1.

The function sets the selector to 1 and constructs the packed value from payload byte 0:

\[
\text{packed value} = b_0 \times 256 + 2.
\]

The upper 16 bits of this value are zero. No second payload byte is read by this branch, and the selector-3 state transition cannot occur.

### Rejected combinations

Every other combination of the narrowed format fields skips further processing and reaches final record handling with internal outcome 62.

In particular:

- Format zero requires companion value 2.
- Format two requires companion value 1.
- Any other low-16-bit format value is rejected.

No payload-byte read occurs in these rejected branches after the entry gates.

### Processing decision after an accepted combination

- One to the bit pattern 0xffffffff.
- One to zero.

It also sets the internal outcome to zero.

It then tests the selector after conversion to an unsigned 16-bit value. The selector constructed here is always between 0 and 255, so this narrowing does not change it.

- **Selector greater than 3:** skip F-704f99fd5e22 and execute the submission sequence.
- **Selector from 0 through 3:** call F-704f99fd5e22 with the context address, a freshly read context word from offset 0x2d4, and addresses of the two initialized local objects and the selector, in the order described under Dependencies.

If F-704f99fd5e22 returns zero, execute the submission sequence. If it returns nonzero, skip that sequence.

The dependency receives writable addresses. The function does not subsequently inspect the contents of those three local objects. The dependency’s return value, rather than any visible post-call selector value, controls whether submission occurs.
