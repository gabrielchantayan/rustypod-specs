# F-f743557f3d20

## Purpose

F-f743557f3d20 computes and stores two ordered endpoint positions for a span whose length is supplied by a dependency. It centers that span around the average of two input coordinates, adds a caller-supplied displacement, and may adjust the result relative to a 64-unit grid.

The adjustment depends on:

- A context flag.
- One flag bit from each endpoint record.
- Whether the mode argument equals exactly 1.
- The span length returned by the dependency.
- The positions of the proposed span boundaries within the grid.

When the context flag is clear at the final adjustment stage, the adjustment is limited to the inclusive range −14 through +14. The function then assigns the two span boundaries according to the relative order of the input coordinates.

**Established behavior:** coordinate arithmetic, dependency invocation, grid-relative adjustment, and two output stores.

**Inferred intent:** positioning a span while controlling how its boundaries fall within 64-unit cells. The evidence does not establish a domain-specific interpretation such as pixels, glyphs, or physical units.

## Behavior

### 1. Select a threshold before invoking the dependency

The function first reads the context flag field.

If bit `0x04` is set, the threshold is 64. Endpoint flag reads for threshold selection are skipped.

Otherwise, the threshold is:

| Endpoint bit-0 condition | Mode equals 1 | Any other mode |
|---|---:|---:|
| Both endpoint bits set | 55 | 49 |
| At least one endpoint bit clear | 61 | 59 |

In this threshold-selection stage, the first endpoint’s flag byte is inspected first. If its bit 0 is clear, inspection of the second endpoint’s flag byte is unnecessary and is skipped.

This threshold is retained across the dependency call. It is not recomputed if the dependency changes the context or endpoint flags.

### 2. Obtain the span length

The function invokes F-0b7cac069844 once with:

1. The context argument.
2. The unchanged mode argument.
3. The second endpoint coordinate minus the first endpoint coordinate.
4. The complete first endpoint flag byte.
5. The complete second endpoint flag byte.

The result is used as a signed 32-bit span length, denoted here by \(L\).

The coordinate and flag reads used to form these arguments occur before the call. Their relative evaluation order is not established by the supplied representation. In particular, the endpoint flags supplied to the dependency are read separately from any reads used to choose the threshold.

The function does not reject, normalize, or report an error for a zero or negative dependency result.

### 3. Calculate the provisional start

After the dependency returns, the function reads both input coordinates again. Let those values be \(x_1\) and \(x_2\), and let \(D\) be the displacement.

The provisional start \(B\) is:

\[
B = D + \operatorname{trunc}\left(\frac{x_1+x_2}{2}\right)
      - \operatorname{trunc}\left(\frac{L}{2}\right).
\]

The two divisions are separate. Combining them into a single division can change the result for odd or negative operands.

The provisional end is \(B+L\). Define:

- \(r\): low-six-bit residue of \(B\).
- \(e\): low-six-bit residue of \(B+L\).
- \(d=64-r\): distance from the start residue to the next grid boundary.

Thus \(r\) and \(e\) are each in 0–63, while \(d\) is in 1–64. At an already aligned start, \(d\) is 64 rather than zero.

The initial adjustment is zero.

### 4. Determine the grid-relative adjustment

Let \(T\) be the previously selected threshold.

#### An aligned provisional boundary

If either \(r=0\) or \(e=0\), the adjustment remains zero. This takes precedence over every length-dependent rule below.

#### Length at or below the threshold

When \(L \leq T\), with neither boundary aligned:

- If \(L \leq e\), the adjustment is zero.
- Otherwise, if \(e<d\), the adjustment is \(-e\).
- Otherwise, the adjustment is \(d\).

An exact tie between the two boundary distances therefore selects the positive adjustment \(d\).

For an ordinary non-overflowing calculation, a zero or negative length takes the zero-adjustment case because \(e\) cannot be negative.

#### Length above the threshold

When \(L>T\), the function first applies a threshold-dependent exclusion.

If \(T<64\) and

\[
\max(r,\ 64-r,\ e,\ 64-e)\geq T,
\]

the adjustment remains zero.

Otherwise, define a comparison quantity \(q\) from the length’s remainder on division by 64. Since this branch requires \(L>T\) and every possible threshold is positive, \(L\) is positive here.

- If that remainder is below 32, use the remainder as \(q\). If either \(d\leq q\) or \(e\leq q\), the adjustment remains zero.
- If the remainder is at least 32, use \(q=64-T\). There is no corresponding distance rejection in this case.

For cases that reach candidate selection, the first candidate is:

\[
A =
\begin{cases}
d-T, & T-d \leq d-q,\\
d-q, & \text{otherwise}.
\end{cases}
\]

The second candidate is:

\[
C =
\begin{cases}
q-e, & e-q \leq T-e,\\
T-e, & \text{otherwise}.
\end{cases}
\]

The chosen adjustment is \(A\) when \(|A|\leq|C|\), and \(C\) otherwise. Equal magnitudes favor the first candidate.

These rules include meaningful boundary distinctions:

- A length exactly equal to \(T\) follows the shorter-length rules.
- A remainder exactly equal to 32 follows the \(q=64-T\) case.
- A distance exactly equal to \(q\) causes rejection in the remainder-below-32 case.
- Candidate comparisons include equality.

### 5. Apply the final context-dependent limit

The function reads the context flag field again after determining the adjustment.

If bit `0x04` is clear on this second read, the adjustment is clamped to the inclusive range \([-14,+14]\). Otherwise, it is left unchanged.

The first and second context reads serve different purposes:

- The first chooses the threshold.
- The second controls clamping.

A dependency-induced change to the context bit can therefore produce a threshold selected under one flag state and clamping performed under another. The function does not enforce a consistent snapshot.

The adjusted start \(S\) is the provisional start plus the final adjustment.

### 6. Assign outputs according to current coordinate order

The function reads the endpoint coordinates again and compares them as signed 32-bit integers.

If the first coordinate is strictly less than the second:

- The first output receives \(S\).
- The second output receives \(S+L\).

Otherwise, including equal coordinates:

- The first output receives \(S+L\).
- The second output receives \(S\).

The first output is always stored before the second output.

Subject to representable arithmetic and distinct output storage, the assigned boundaries differ by \(L\), with their endpoint assignment determined by the final coordinate comparison. A negative \(L\) does not cause an additional swap or validation step.
