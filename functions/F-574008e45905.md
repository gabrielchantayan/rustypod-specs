# F-574008e45905

## Purpose

F-574008e45905 conditionally assigns a two-byte classification to a target object and then sets a one-byte marker. Its second input selects the classification through an ordered decision process involving shared configuration and several fixed numeric selectors.

If the selector is not recognized by the branch that applies, the operation returns without resolving a target or writing object fields. For a recognized selector, a zero target input requests target resolution through F-bb50a072e902.

**Established behavior:** selection precedes target resolution; successful selection produces exactly three explicit byte stores, with the marker written last.

**Inferred intent:** the two adjacent bytes encode a category and subcategory, while the marker announces a changed or valid state. Their application-specific meanings are not established.

### Shared inputs

Two shared integer values participate in selection:

- **Threshold:** tested first for equality with the selector and, if equality fails, used in a signed less-than comparison.
- **Adjustment:** added to the selector only when the selector is greater than the threshold used for that comparison.

Their initial values, mutability, synchronization, and relationship to one another are unknown. They are not arguments to F-574008e45905.

The threshold appears in two separate expressions. The evidence does not establish an atomic snapshot spanning both expressions, nor whether those expressions correspond to distinct physical memory loads. ## Behavior

### 1. Select a classification before accessing the target

The operation first determines whether the selector denotes a recognized classification. The target input does not affect this selection.

The decision order is significant:

1. Test whether the selector equals the threshold.
2. If not equal, test whether the threshold is less than the selector using signed ordering.
3. If the selector is greater, use the adjustment-based selection rules.
4. Otherwise, use the fixed-selector rules.

The adjustment-based and fixed-selector branches are mutually exclusive. Failure to recognize a value in the adjustment-based branch does not fall through to fixed-selector handling.

### 2. Threshold equality

If the selector equals the threshold in the first test, select:

- First component: 2.
- Second component: 0.

This result takes precedence over all fixed numeric selectors. For example, a selector numerically equal to 0x31204 produces the equality result if the threshold also equals 0x31204; it does not produce the fixed-selector result.

The adjustment is not used on this path.

### 3. Selector greater than threshold

If the equality test fails and the signed ordering test finds the selector greater than the threshold, add the shared adjustment to the selector. Classify the resulting adjusted value as follows:

| Adjusted value | First component | Second component |
|---|---:|---:|
| 0 | 5 | 5 |
| 0x0F | 5 | 4 |
| 0xF0 | 5 | 3 |

Any other adjusted value causes an immediate return, without target resolution or explicit target writes.

These comparisons apply to the adjusted value, not to the original selector. The original selector has no fixed-selector interpretation after entry into this branch.

The addition is integer-width arithmetic, not eight-bit arithmetic. No evidence supports truncating the adjusted value to a byte before comparison. For example, a result of 0x10F is not equivalent to 0x0F.

The excerpt does not settle overflow behavior for signed addition. It does not show an explicit overflow check, saturation, or error path. Inputs whose mathematical sum is representable in the apparent signed 32-bit model are covered without that ambiguity. Behavior outside that range is **documented_only** pending authoritative machine-level or execution-model evidence.

### 4. Fixed-selector branch

If the first equality test fails and the subsequent signed ordering test does not find the selector greater than the threshold, recognize only the following original selector values:

| Original selector | First component | Second component |
|---|---:|---:|
| 0x23140 | 2 | 1 |
| 0x31204 | 0 | 2 |
| 0x31240 | 2 | 2 |
| 0x32104 | 0 | 0 |

Any other value causes an immediate return without target resolution or explicit target writes.

With a stable threshold, this branch is reached only for selectors below the threshold. If the threshold can change between its two uses, the narrower established condition is that the first equality test failed and the second comparison did not report the selector as greater.

The shared adjustment is not used on this branch.

### 5. Resolve the target only after recognition

Once a classification has been selected:

- A nonzero target input is used directly.
- A zero target input causes one call to F-bb50a072e902, with no explicit arguments. Its returned value is used as the target base address.

There is no second selection pass after the dependency returns. The pair being committed is the pair selected before that call. A dependency-induced change to the threshold or adjustment is not shown causing reclassification.

No null check or validity check is performed on the returned target. There is no retry, fallback target, or explicit failure handling.

### 6. Commit the result

After target selection, the explicit stores occur in this order:

1. Write the first classification component at offset 0x54.
2. Write the second classification component at offset 0x55.
3. Write the byte value 1 at offset 0x24.

Existing values at these offsets are overwritten without being read. The marker is assigned 1; it is not toggled, incremented, or combined with its prior contents.

No conditional store avoidance is shown. A successful invocation performs the stores even if the target already contains the selected bytes and marker value.

This ordering is the order represented by the supplied body. It does not establish hardware memory barriers, cross-thread publication guarantees, or atomicity of the three-store update.

## Side effects

On a recognized path that reaches the stores, F-574008e45905 explicitly modifies three individual bytes. It does not explicitly read target contents or clear other fields.

The update is not transactional. If an address fault or another execution failure occurs during the stores, the excerpt provides no rollback. Earlier stores may already have taken effect before a later store fails.

A marker value of 1 therefore cannot, by itself, establish that this invocation completed: the marker might already have been 1 before entry.

## Acceptance examples

These examples are conditional behavioral expectations derived from static evidence. **No runtime tests have been performed.** Unless stated otherwise, assume a stable threshold, representable arithmetic, ordinary writable target memory, and normal completion.

### Equality takes precedence

Given a threshold of 0x31204 and a selector of 0x31204, the target receives:

- 2 at offset 0x54.
- 0 at offset 0x55.
- 1 at offset 0x24.

The fixed-selector pair of 0 and 2 does not apply because equality is checked first.

### Fixed selectors below the threshold

Given a threshold of 0x40000, the fixed selectors produce these pairs:

| Selector | Pair at offsets 0x54 and 0x55 |
|---|---|
| 0x23140 | 2, 1 |
| 0x31204 | 0, 2 |
| 0x31240 | 2, 2 |
| 0x32104 | 0, 0 |

Each recognized case writes the marker value 1 last. The adjustment does not affect these outcomes.

### All three adjusted outcomes

Given a threshold of 10 and an adjustment of −20:

| Selector | Adjusted value | Selected pair |
|---|---:|---|
| 20 | 0 | 5, 5 |
| 35 | 15 | 5, 4 |
| 260 | 240 | 5, 3 |

Each selector is greater than the threshold, so adjustment-based selection applies.

### No byte truncation during selection

Given a threshold of 10, an adjustment of zero, and a selector of 0x10F, the adjusted value is unrecognized. The operation returns without explicit target writes. It does not treat the low byte, 0x0F, as the adjusted selector.

### No fallback to fixed selection

Given a threshold of zero, an adjustment of zero, and a selector of 0x23140, the greater-than branch applies. Its adjusted value matches none of the three accepted adjusted values.

The operation returns without writes, despite 0x23140 appearing in the fixed-selector table.

### Rejection avoids target resolution

Given a threshold of 100 and a selector of 50, the fixed-selector branch rejects the selector. A zero target input does not cause F-bb50a072e902 to be called.

### Deferred target resolution

Given any recognized selector and a zero target input, F-bb50a072e902 is called before the explicit stores. If it returns a valid writable target and completes normally, the preselected pair is written there, followed by the marker.

Any other effects of that call remain outside this example’s guarantees.

### Invalid target on a recognized path

Given a recognized selector and an invalid nonzero target, the operation attempts the stores without invoking F-bb50a072e902 or validating the address. A platform fault is possible; no successful update or rollback is guaranteed.
