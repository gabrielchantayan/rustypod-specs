# F-11bd3a21366b

## Purpose

F-11bd3a21366b performs an ordered operation on a nullable descriptor. It forwards selected table-entry words to a dependency, forwards the current table address, updates global accounting storage, and conditionally updates context accounting and invokes additional dependencies.

“Teardown,” “allocation accounting,” and “finalization” are inferred intent. The established behavior is the accesses, arithmetic, writes, and calls described below. Dependency calls do not establish memory release, ownership transfer, preservation of globals, or continued validity of supplied storage.

The function has no return value. Null input returns immediately. Header-validation failure reaches a dependency designated as non-returning, after earlier calls and accounting writes have already occurred.

The global high-word adjustment contains target-dependent signed conversion and right-shift behavior. Its interpretation as part of a conventional 64-bit subtraction is conditional, not an unconditional portable guarantee.

## Interface

**Input:** one descriptor address, possibly null.

**Output:** no return value.

The supplied representation uses 32-bit addresses and 32-bit integer words. The descriptor bound and the index returned by F-09dcb55e8e0a are signed 32-bit values. The two metadata indices are unsigned 16-bit values. All offsets are byte offsets.

### Descriptor and table

| Offset from descriptor | Width | Use |
|---|---:|---|
| −4 | Signed 32 bits | Displacement used to recover a base address |
| 0 | 32 bits | Table address |
| +4 | Signed 32 bits | Iteration bound |

The table has an eight-byte entry stride. For each visited entry, this function directly reads only its first four-byte word. It does not directly read the second word.

The **recovered base** is the descriptor address, converted to the represented signed address-sized integer, minus the displacement at descriptor offset −4.

### Metadata associated with the recovered base

| Offset from recovered base | Width | Use |
|---|---:|---|
| −16 | Unsigned 32 bits | Header used for validation and masked accounting amounts |
| −12 | Unsigned 16 bits | First context-accounting index |
| −10 | Unsigned 16 bits | Second context-accounting index |
| −8 | Unsigned 32 bits | Global-accounting adjustment amount |

The amount at offset −8 is read even when the recovered base equals address value 8. The header and metadata-index accesses are skipped on that distinguished-base path.

### Preconditions and ownership

Every reached access must address valid storage of the required width, including accesses after dependencies return. Relevant arithmetic and address conversions must support the execution being considered. The function supplies no general pointer, alignment, capacity, index-range, or ownership validation.

No non-aliasing or exclusive-ownership requirement is established. If destinations overlap metadata, descriptor fields, other counters, or global selectors, the ordered accesses determine the result; the fields cannot be treated as independent snapshots.

Dependencies may mutate or invalidate reachable storage. Normal continuation requires that storage used afterward remain valid. Their names and call positions do not establish ownership or preservation guarantees.

## Behavior

### 1. Null input

A null descriptor returns immediately. No descriptor fields, accounting storage, or context selector are accessed, and no dependency is called.

### 2. Visit table entries

For non-null input, a signed 32-bit iteration position starts at zero. Each loop condition rereads the signed bound at descriptor offset +4.

While the position is less than the current bound, the function:

1. Reads the current table address from descriptor offset 0.
2. Reads the four-byte word at the table address plus eight times the current position.
3. Passes that word to F-94cb53877c15.
4. Advances the position by one before evaluating the next condition.

Neither the bound nor the table address is captured once for the whole loop. Changes made by F-94cb53877c15 can affect subsequent iterations. An initially zero or negative bound produces no entry calls.

Entry words are forwarded without null checking, deduplication, or interpretation. The eight-byte stride does not imply two calls per entry.

The position scaling and table-address addition appear as signed integer arithmetic in the supplied representation. Executions requiring signed overflow or invalid address formation have no established portable behavior.

### 3. Forward the table address

After iteration ends, the function rereads descriptor offset 0 and passes the resulting table address to F-94cb53877c15.

This call occurs even when the loop visited no entries or the table address is zero. It uses the field’s current value, which need not equal any table address used during iteration.

The function does not directly clear the descriptor, table address, bound, or table entries.

### 4. Update global accounting

The global accounting pointer is observed separately for different parts of this update. The represented sequence is:

1. Read and retain the global accounting pointer.
2. Compare the original descriptor argument with null again.
3. Read the displacement at descriptor offset −4 and compute the recovered base.
4. Read the unsigned 32-bit adjustment amount at recovered-base offset −8.
5. Reread the global accounting pointer and load the low word at offset +56.
6. Reread the global accounting pointer and retain the address at offset +60 for the high-word load.
7. Reread the global accounting pointer and store the adjusted low word at offset +56.
8. Read the high word through the address retained in step 6.
9. Store the adjusted high word at offset +60 through the pointer retained in step 1.

The later null comparison follows the initial pointer observation. The body does not reassign the descriptor argument, so this comparison does not establish another ordinary null-input path.

Let \(A\) be the captured unsigned adjustment amount, \(L\) the captured unsigned low word, and \(b\) equal one when \(L<A\), otherwise zero. The low result is:

\[
L'=(L-A)\bmod 2^{32}.
\]

The high result must be described separately from any inferred signed interpretation of \(A\). The adjustment expression:

- Converts \(A\) to signed 32-bit.
- Right-shifts that signed result by 31 positions.
- Combines the shift result with the unsigned borrow.
- Subtracts that combined adjustment from the high-word value using unsigned 32-bit arithmetic.

If the conversion and shift complete with signed shift result \(s\), and \(H\) is the high-word value converted to unsigned 32-bit, the stored high result is:

\[
H'=\bigl(H-\operatorname{unsigned32}(s)-b\bigr)\bmod 2^{32}.
\]

For \(A\leq\texttt{0x7fffffff}\), the signed conversion is representable, the shift result is zero, and the high adjustment subtracts only the borrow.

For \(A\geq\texttt{0x80000000}\), the supplied source alone does not establish a portable signed conversion result. An out-of-range conversion is target-dependent and can involve an implementation-defined signal. If the conversion produces a negative value, its signed right shift is also target-dependent.

**Conditional sign-bit rule:** if the target converts a top-bit-set amount to the corresponding negative signed 32-bit value and right-shifts negative values arithmetically, then \(s=-1\). Under those assumptions, a top-bit-set amount makes the high result equal the high word plus one minus the borrow. Without those assumptions, that rule is not established.

**Conditional combined interpretation:** if those conversion and shift assumptions hold, all four global-pointer observations select the same object, and overlapping storage does not interfere with the stated accesses, the low and high writes together subtract the sign-extended signed 32-bit interpretation of \(A\), modulo \(2^{64}\). This is not an unconditional subtraction of an unsigned amount or an unconditional portable 64-bit interpretation.

The high word is read after the low-word store. If storage overlaps, that store can affect the high source. If the pointer observations differ, the low load, low store, high load, and high store can concern different objects. In particular, the earliest pointer observation selects the high destination, not necessarily its source.

No overflow, underflow, saturation, or rollback check accompanies these writes. The recovered-base calculation also involves represented signed address arithmetic; portable behavior for an unrepresentable conversion or overflowing subtraction is not established.

### 5. Select the context

After both global-accounting writes, the function calls F-2fd8826557a4 without explicit arguments. Its return value is unused.

Only after that call does the function read the selected context address through a separate global context selector. That address is retained for subsequent operations.

F-2fd8826557a4 may therefore affect context selection. The global-accounting update has already occurred when it is called.

### 6. Handle the distinguished base

If the recovered base equals address value 8, the function returns after context selection.

This path skips header validation, context-accounting updates, and the remaining dependencies. It does not skip table processing, the amount read, either global-accounting write, F-2fd8826557a4, or context selection.

In the represented address model, the earlier amount read is then at address zero. Any normal-completion example for this path must assume that this access is valid; the distinguished-base check does not protect it.

### 7. Validate the header

For a recovered base other than 8, the function retains the header address at recovered-base offset −16.

Validation fails when:

- The first unsigned 32-bit header read is zero; or
- The first read is nonzero and a subsequent header read has bit 0 set.

The second read is conditional on the first being nonzero. These checks do not validate one immutable captured value.

Failure calls F-a817d8d58c10 without explicit arguments. The supplied material designates this dependency as non-returning. No normal continuation after that call is established.

Validation occurs after table processing, both global-accounting writes, F-2fd8826557a4, and context selection. There is no rollback.

### 8. Update context accounting

After validation passes, the function calls F-c0fc6d033caa with the retained context address.

After that call, the following updates occur in order:

1. Read the unsigned 16-bit index at recovered-base offset −12 and form its indexed context position.
2. Reread the header and capture its value masked with `0x3ffffffc`.
3. Subtract that captured amount from the word at context offset \(548+4\times\text{first index}\).
4. Subtract the same amount from the word at context offset 780.
5. Read the unsigned 16-bit index at recovered-base offset −10 and form its indexed context position.
6. Subtract the captured amount from the word at context offset \(224+4\times\text{second index}\).
7. Subtract the captured amount from the word at context offset 544.
8. Call F-09dcb55e8e0a without explicit arguments.
9. Use its signed 32-bit result as an index and decrement the signed word at context offset \(784+4\times\text{returned index}\).
10. Decrement the signed word at context offset 912.
11. Reread the header and use its value masked with `0x3ffffffc` to reduce the word at context offset 8.
12. Call F-cc6c9b4a0f68 with the retained context and retained header address.
13. Call F-e586bff64fb7 with the retained context.
14. Return.

Each destination’s current value is used when its update is reached. Overlapping destinations accumulate effects in this order. For the offset-8 update, the header and destination value are both read for that update; no relative ordering between those two operand reads is required by the supplied expression.

The mask removes the lowest two and highest two bits. Its result is a multiple of four between zero and `0x3ffffffc`, inclusive. The first four amount-based updates share one captured amount. The offset-8 update uses a fresh header value after F-09dcb55e8e0a and both decrements.

The two metadata indices are zero-extended before scaling. Their scaled values range from zero through 262140. This does not establish valid context capacity.

The dependency-selected index is signed. Negative values are not rejected or converted to nonnegative indices. Its scaling and address additions appear as signed 32-bit arithmetic; normal portable interpretation requires representable arithmetic and a valid resulting access.

Amount-based word subtractions produce unsigned 32-bit modular results. The two counter decrements use signed 32-bit arithmetic; decrementing the minimum signed value has no established portable result.

The retained context address is reused throughout. Changing the global selector later does not itself retarget these operations. Dependencies may nevertheless mutate or invalidate the retained storage.

## Side effects

Directly established effects are:

- One F-94cb53877c15 call for each visited entry word, followed by one call for the reread table address.
- Two ordered global-accounting writes, potentially using different source and destination objects.
- F-2fd8826557a4 followed by context selection.
- Conditional context-accounting writes and subsequent dependency calls.
- F-a817d8d58c10 on header-validation failure.

There are no direct writes clearing the descriptor, table, bound, or header. Aliasing with accounting destinations can nevertheless modify such storage.

The function does not independently establish any memory release or ownership transfer. No transaction, rollback, synchronization, or reentrancy guarantee is established. Interpreting the context-bracketing calls as locking and unlocking is inferred intent only.

## Acceptance examples

These are conditional static expectations, not executed tests. Unless otherwise stated, they assume valid reached accesses, representable signed arithmetic, applicable target conversions, returning dependencies, and no unmentioned mutations or overlapping effects.

1. **Null descriptor.** There are no dependency calls or accounting accesses.

2. **Negative bound.** A stable bound of −1 produces no entry calls. The current table address is still passed once to F-94cb53877c15 before accounting proceeds.

3. **Two stable entries.** With bound two, F-94cb53877c15 receives the words at table offsets 0 and 8, then the table address. This function does not directly read the words at offsets 4 and 12.

4. **Mutable bound and table address.** If the first entry call changes the bound from two to one, iteration ends at the next condition. If that call also changes the table address, the final table-address call receives the changed address.

5. **Ordinary borrow.** With a stable accounting pointer, non-overlapping storage, amount one, low word zero, and high word five, the low result is `0xffffffff` and the high result is four. This amount requires no out-of-range signed conversion.

6. **Top-bit-set amount under explicit target assumptions.** With amount `0xffffffff`, low word ten, and high word five, the low result is eleven. If conversion of that amount produces signed −1 and shifting −1 right by 31 produces −1, the high result is five. Without those target assumptions, the high result is not established as five: if conversion and shift complete, it follows the formula in Behavior §4 using the actual shift result. The source alone does not guarantee normal completion of the conversion on every target.

7. **Different global-pointer observations.** If the initial save selects object A, the low-load observation selects B, the high-address observation selects C, and the low-store observation selects D, the low value comes from B and is written to D. The high value is read from C after that write, and its adjusted result is written to A. This is conditional on those observations occurring; the body does not establish a mechanism that produces them.

8. **Zero header.** A zero first header read calls F-a817d8d58c10 without the bit-test read. Earlier calls and global-accounting writes remain performed.

9. **Fresh header amount.** If the first captured masked amount is `0x24` and F-09dcb55e8e0a changes the header so its later masked amount is `0x44`, the first four amount-based updates subtract `0x24`, while the context-offset-8 update subtracts `0x44`.

10. **Negative returned index.** A return of −1 from F-09dcb55e8e0a targets context offset 780. If that word initially held 100 and the captured amount was four, the earlier amount subtraction leaves 96 and the later decrement leaves 95.

11. **Distinguished base.** Recovered base 8 skips header validation and context accounting. It still requires the earlier amount read at address zero, global-accounting updates, F-2fd8826557a4, and context selection.
