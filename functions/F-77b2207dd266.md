# F-77b2207dd266

## Purpose

F-77b2207dd266 copies a 32-bit global word into the first word of a caller-supplied object, obtains an associated address through F-fd7c65715716, and conditionally updates linked state and processes records from a list.

The function returns a 64-bit value assembled from two 32-bit components:

- The low component is the retained result of F-fd7c65715716 minus 32 bytes.
- The high component is the final contents of a local upper-result slot. That slot initially contains the second input. The conditional path overwrites it with a selected-record address and exposes its address to F-3e95f52e82a5.

The initial object write may resemble installation of object metadata, and the record-processing sequence may resemble cleanup. These are inferred intentions only. The supplied evidence establishes neither a constant metadata value nor resource-release or ownership semantics.

## Interface

### Inputs

The function accepts four inputs:

| Input | Representation | Established use |
|---|---|---|
| Object address | Address of storage containing 32-bit words | Receives a write at byte offset 0. The address advanced by 32 bytes is passed to F-fd7c65715716. |
| Initial upper-result value | 32 bits, represented as a signed integer | Copied into the local upper-result slot. Supplies the high return component if that slot remains unchanged. |
| Initial working value | 32 bits | Copied into a local working slot. The conditional path overwrites this slot before exposing its address to F-3e95f52e82a5. |
| Auxiliary value | 32 bits | Copied into a local auxiliary slot whose address is exposed to F-3e95f52e82a5 on the conditional path. |

No signed comparison or signed interpretation of the second input is used by the visible function. Its contribution to the result is its 32-bit representation.

The third and fourth inputs have no established scalar meaning. Their representations could encode values, addresses, or other state; the function does not establish which.

### Global input

The function reads a 32-bit global word and copies the value obtained into the object’s first word.

The evidence identifies a particular global storage location, not a fixed literal. Its numerical contents, mutability, initialization, and semantic role are **documented_only**. Different invocations need not observe the same value.

### Result

Call the 32-bit address-bearing result of F-fd7c65715716 the **anchor**, and call the anchor minus 32 bytes the **associated base**.

The returned value is 64 bits wide:

| Result bits | Contents |
|---|---|
| 31–0 | The 32-bit representation of the associated base |
| 63–32 | The contents of the local upper-result slot when the result is assembled |

The components are concatenated. The low component is not sign-extended into the high component.

The high component is not necessarily the last value explicitly assigned to that slot by this function or by F-3e95f52e82a5. If the slot remains reachable through a pointer retained by that dependency, subsequent dependency calls may alter it before return.

### Storage and arithmetic requirements

The visible representation uses four-byte words and 32-bit address-bearing values. All offsets in this contract are byte offsets.

Normal completion requires storage sufficient for the accesses actually reached, including:

- A readable global word and a writable word at the object address.
- An object-derived argument acceptable to F-fd7c65715716 at object address plus 32.
- Readable associated-state fields reached through the returned anchor.
- Writable chain and list fields on the conditional path.
- Readable record fields and writable selected-record storage as described below.

The function does not validate these conditions. A zero selected-record field is an explicit branch condition; a zero anchor is not explicitly rejected.

The evidence contains signed-looking intermediate representations and address arithmetic, but it does not establish a portable overflow rule. The low return component is 32 bits wide; whether an overflowing intermediate address calculation traps, wraps, or has another consequence is **documented_only**. Successful examples below assume valid derived addresses without relying on overflow.

## Behavior

### 1. Global read, object write, and local initialization

The visible sequence begins with:

1. Reading the 32-bit global word.
2. Writing the value obtained into the object’s first 32-bit word.
3. Initializing the upper-result, working, and auxiliary local slots from the second, third, and fourth inputs, respectively.
4. Calling F-fd7c65715716.

The object write is unconditional and precedes every dependency invocation. No branch tests the global value, and no later direct read of that global is visible.

The function therefore copies the value observed by this read; it does not establish that the source remains unchanged afterward. No general non-aliasing guarantee between the object, global storage, and associated records is supplied.

### 2. Associated-state lookup and branch

F-fd7c65715716 is called once with the object address advanced by eight four-byte words, or 32 bytes.

The function retains its returned anchor. The following associated-state locations are then relevant:

| Associated-base offset | Anchor displacement | Width | Behavioral role |
|---|---|---|---|
| +4 | −28 | 32 bits | List-head slot |
| +8 | −24 | 32 bits | Chain-state slot |
| +20 | −12 | 32 bits | Selected-record slot |

These names describe uses, not complete types or allocation boundaries.

The function reads the selected-record slot and compares its contents with zero.

If the observed value is zero:

- All conditional preparation, chain updating, and list processing are skipped.
- Neither F-3e95f52e82a5 nor F-ff1bdc376dcd is invoked.
- The function itself does not read the list-head or chain-state contents.
- It proceeds to assemble the result.

In particular, a nonzero list head does not independently enable processing.

### 3. Preparation for F-3e95f52e82a5

If the selected-record test is nonzero, the function performs further selected-record reads rather than retaining the tested value for every use.

The visible order is:

1. Reread the selected-record slot to obtain a record address.
2. Read the 32-bit word at offset 8 from that address.
3. Replace the local working slot with that word.
4. Reread the selected-record slot.
5. Replace the local upper-result slot with this latest address.
6. Invoke F-3e95f52e82a5.

The initial working input is therefore copied locally but overwritten before the address of its slot is passed to this dependency.

F-3e95f52e82a5 receives four addresses, in order:

| Argument | Address supplied | Contents immediately before invocation |
|---|---|---|
| First | Local auxiliary slot | Fourth input |
| Second | Associated list-head slot | Current associated list-head contents |
| Third | Local working slot | Word read at offset 8 of the selected address used for that access |
| Fourth | Local upper-result slot | Most recently read selected-record address |

The function does not use this dependency’s return value.

There is no additional nonzero check between the initial branch test and the selected-record dereference. If those reads can observe changing state, a nonzero test alone does not guarantee that the address used for the offset-8 read is valid.

The three local slots are writable storage exposed to the dependency. The visible caller subsequently reads the upper-result slot for return, but does not directly inspect the working or auxiliary slot again.

### 4. Chain update after F-3e95f52e82a5

After the dependency returns, the function:

1. Rereads the selected-record slot and retains that address for this update.
2. Reads the chain-state slot.
3. Writes the chain-state value into the selected record at offset 12.
4. Writes the retained selected-record address into the chain-state slot.

Under stable, non-overlapping storage, this places the previous chain-state value in the selected record’s offset-12 field and replaces the chain state with that record’s address.

The record used here need not be the record tested earlier, the record whose offset-8 field was read, or the value currently held in the upper-result slot.

There is no second nonzero check after F-3e95f52e82a5. If that dependency clears the selected-record slot, the function still proceeds toward the offset-12 write using the reread zero address. No cancellation behavior is established.

If fields overlap, the ordered accesses still govern, but the usual linked-chain interpretation may not apply.

### 5. List processing

After the chain update, the function repeatedly reads the associated list-head slot.

A zero head ends processing. Each nonzero head is treated as a record address with these visible fields:

| Record offset | Width | Use |
|---|---|---|
| 0 | 32 bits | Next-record address |
| 4 | 32 bits | Second argument of the first processing call |
| 8 | 32 bits | First argument of the first processing call |

For each observed nonzero head, the function:

1. Retains the current record address.
2. Reads its offset-0 next-record value.
3. Writes that value into the list-head slot.
4. Obtains the record’s offset-8 and offset-4 values.
5. Calls F-ff1bdc376dcd with the offset-8 value, the offset-4 value, and zero.
6. Calls F-ff1bdc376dcd with the retained record address, one, and zero.
7. Reads the list-head slot again to determine whether another iteration occurs.

The head update precedes both processing calls and the argument-field reads for the first call. The relative order of the offset-8 and offset-4 reads is not established.

The second call uses the retained record address. The caller performs no further field read from that record between the first and second calls. This does not establish that the second dependency invocation is safe if the first invocation invalidates the record.

The loop follows the current list-head contents, not a saved snapshot of the original list. Dependency mutations can add records, replace the head, cause revisits, or end processing.

### 6. Return assembly

When the conditional path is skipped or the loop terminates, the function assembles the 64-bit result.

The low component uses the retained anchor minus 32 bytes. There is no second lookup.

The high component uses the upper-result slot’s final contents. The function does not refresh it from the selected-record slot after F-3e95f52e82a5.

A retained pointer to this local slot could make it reachable during later F-ff1bdc376dcd calls. Consequently, the value present immediately after F-3e95f52e82a5 is not guaranteed to survive until return.

## Side effects

### Direct memory effects

The function directly performs:

- One global-word read followed by a write of that value to the object’s first word.
- Conditional reads of associated state and record fields.
- A conditional write to the selected record’s offset-12 word.
- A conditional write to the chain-state slot.
- One list-head write for each processed head.

It also initializes and updates local slots and exposes three of their addresses to F-3e95f52e82a5.

No direct allocation or explicit release is visible. No write is rolled back by visible caller logic if a later access or dependency call fails.

### Ownership and pointer lifetime

The paired processing calls are consistent with payload processing followed by descriptor processing, but resource release and ownership transfer are not established.

The exposed local slots remain within this invocation’s lifetime during later loop calls. Pointer retention by F-3e95f52e82a5 is unknown and must not be assumed absent. Use after this function returns is not supported by their local-storage lifetime.

No dependency is assumed to preserve globals, associated storage, or any local slot reachable through a retained pointer.

### Errors and termination

There is no explicit error return, bounds check, null-object check, cycle detector, or recovery path.

A failure to return from a dependency prevents subsequent operations. For example, if the first processing call does not return, the head has already been updated, but the second processing call is not reached.

A cyclic list or dependency-driven reinsertion can prevent termination. Invalid addresses can cause invalid accesses; the environment’s resulting behavior is **documented_only**.

## Acceptance examples

The following are conditional static acceptance criteria, not runtime observations.

### Global value copied before lookup

Suppose the global read yields a particular 32-bit pattern and all reached accesses are valid.

The object’s first word receives that pattern before local initialization and F-fd7c65715716. A later change to the global does not cause this function to repeat the copy.

If separate invocations observe different global patterns, each copies its own observed pattern. No constant-value expectation applies.

### Zero selected-record slot

Suppose the selected-record test observes zero after F-fd7c65715716 returns.

The global-to-object copy has occurred. No chain update or list processing follows, even if the associated list is nonempty. The high return component is the second input’s copied bit pattern, and the low component is the associated base.

### Selected record and empty list

Suppose the conditional path is enabled, the post-dependency selected-record address is valid, fields do not overlap, and the list is empty after the chain update.

The selected record’s offset-12 field receives the old chain-state value, and the chain-state slot receives the reread selected-record address. No F-ff1bdc376dcd call occurs.

### Two stable records

Suppose the conditional path reaches a two-record acyclic list, fields do not overlap, and dependencies leave its links and head unchanged.

Each record is removed from the head before its two processing calls. Its field-based call precedes its record-address call. Exactly four F-ff1bdc376dcd invocations occur, followed by a head read observing zero.

### Distinct return and chain-update values

Suppose F-3e95f52e82a5 writes one value into the upper-result slot and leaves a different valid address in the selected-record slot.

The chain update uses the selected-record address reread immediately after the call. If no later mutation of the upper-result slot occurs, the return’s high component is the value written there by F-3e95f52e82a5.

If that dependency retained the slot pointer and a later processing call changes the slot, the high component instead uses its final contents at return. Neither equality with the chain-update address nor preservation of the dependency’s initial write is required.

### Cleared selected-record slot

Suppose F-3e95f52e82a5 clears the selected-record slot.

The caller does not treat this as cancellation. It proceeds toward writing at offset 12 from the reread zero address. Normal completion is not guaranteed.
