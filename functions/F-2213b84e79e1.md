# F-2213b84e79e1

## Purpose

F-2213b84e79e1 conditionally requests an operation on a resource associated with a caller-supplied state object. Before requesting that operation, it consults a count-like dependency result and may search indexed values in descending index order for the requested value or an insertion position.

Three principal outcomes are visible:

- An initial indexed lookup reports failure: return −50 without directly updating the state object.
- A lookup within the descending search produces an exact match: return zero without invoking the final operation or directly updating the state object.
- Otherwise, clear two state bytes, invoke the final operation, and, only if that operation returns zero, record successful state changes.

“Count,” “search,” and “insertion position” describe the apparent roles of values. The meanings of the resource, indexed values, and final operation are not independently established. In particular, a zero return does not distinguish an existing match from successful completion of the final operation.

## Behavior

### 1. Normalize the request and obtain the count-like value

If the requested value is zero, replace it with one. All later comparisons, dependency arguments, and any successful stored request use this normalized value.

Next:

1. Read the four-byte resource field at offset 24.
2. Call F-0104b49ee457 with the captured resource, a zero argument, and the shared selector.
3. Initialize the selected position to zero.

The result of F-0104b49ee457 is tested as a signed integer.

If it is zero or negative, no indexed lookup is performed. The function proceeds to the final-operation path with position zero. A negative result is not directly returned as an error.

### 2. Perform the initial indexed lookup

If the count-like result is positive, call F-e155b614573e with:

- The captured resource.
- A zero argument.
- The shared selector.
- The full positive count-like result as the index.
- An address for a local four-byte lookup output.

If this call returns zero, return −50 immediately. No state-object writes by F-2213b84e79e1 occur on this path.

Any nonzero return is accepted for this initial call. The visible function does not require a positive return or otherwise interpret its magnitude.

The lookup output is then compared with the normalized request using signed comparison:

- If the request is greater than the output, do not enter the descending search. Continue to the final operation with position zero.
- If the request is less than or equal to the output, enter the descending search.

The lookup output is not visibly initialized before the first call. Its validity therefore depends on the dependency’s output-writing behavior.

### 3. Search in descending index order

The search begins at the original positive count-like result. It calls F-e155b614573e again at that index, even though the initial lookup used the same index.

Consequently, an initial output equal to the request does not itself cause the exact-match return. The repeated lookup must produce equality for that path to be taken.

For each visited positive index:

- Call F-e155b614573e with the resource, zero, shared selector, current index, and the same local output location.
- Ignore this call’s return value.
- Read the local output and compare it with the normalized request.
- If the output is less than the request, select the signed-16-bit narrowed value of current index plus one, stop searching, and proceed to the final operation.
- Otherwise, if the output equals the request, return zero immediately.
- Otherwise, decrement the index using the visible signed-16-bit narrowing operation and continue only if the resulting index is positive.

If the search terminates without equality and without finding an output below the request, the selected position remains zero.

Only the return from the initial lookup is checked. A later zero return neither produces −50 nor prevents use of the output storage. If a later call leaves that storage unchanged, the comparisons use its retained contents. If no valid value has ever been written, behavior depends on indeterminate local storage and cannot be specified as a reliable result.

### 4. Clear state and invoke the final operation

Every path reaching the final operation performs these direct writes, in order:

1. Write zero to the byte at offset 44.
2. Write zero to the byte at offset 58.

Then call F-19e9375c0de5 with eight arguments, in this order:

1. Captured resource.
2. Zero.
3. Shared selector.
4. Normalized request.
5. Selected position.
6. Zero.
7. Zero.
8. Address of state-object offset 52.

If the dependency returns nonzero, return that value without performing the success-update sequence.

The two preceding clears are not rolled back. Other effects of the dependency, including writes through the supplied address or changes through other aliases, are not undone by the visible function.

### 5. Record success

If F-19e9375c0de5 returns zero, perform these direct accesses in order:

1. Write the normalized request as four bytes at offset 48.
2. Write one to the byte at offset 44.
3. Write the selected position’s low 16 bits at offset 56.
4. Write zero to the byte at offset 58.
5. Write `0xffffffff` as four bytes at offset 60.
6. Read the four-byte field at offset 20, add one, and write the result back.
7. Write one to the byte at offset 16.

Return zero.

The offset-20 read occurs after the dependency call and after the preceding success writes. It does not use a counter value captured before the dependency. If the dependency changes that field, the subsequent increment uses the changed value.

### Integer-width boundaries

The count-like result is initially handled as a signed 32-bit integer. The first indexed lookup and the first search lookup therefore receive the full positive result; there is no initial 16-bit truncation.

The visible search arithmetic narrows the decremented index, and the selected index-plus-one value, to signed 16-bit range. Under that interpretation:

- Decrementing 1 produces 0 and ends the search.
- Selecting the position after index 32,767 produces −32,768.
- Decrementing an initial index of 32,769 produces −32,768 and ends the search after its first search iteration.

The selected position is passed to the final dependency as the resulting signed value and later stored in a two-byte field.

The reconstructed arithmetic uses intermediate operations for this narrowing. Exact machine behavior at arithmetic extremes is not independently verified. Counter overflow at offset 20 is likewise not given a checked-error path; its precise overflow semantics remain documented only.

## Side effects

Its direct state-object effects depend on the path:

| Path | Direct state-object effects |
|---|---|
| Initial lookup returns zero | None. |
| Search lookup produces an exact match | None. |

## Acceptance examples

These examples are conditional static expectations, not results of executed tests. Unless stated otherwise, dependency outputs are valid, arithmetic remains within the illustrated ranges, and dependencies do not independently modify the state object or selector.

1. **Zero request with no indexed entries.**  
   Given a request of zero and a count-like result of zero, no indexed lookup occurs. The final dependency receives request one and position zero. If it returns zero, offset 48 becomes one and the complete success-update sequence occurs.

2. **Negative count-like result.**  
   Given a count-like result of −7, the function does not propagate −7. It calls the final dependency with position zero after clearing offsets 44 and 58.

3. **Initial lookup failure.**  
   Given a positive count-like result and an initial lookup return of zero, the function returns −50. It does not invoke the final dependency or directly clear either state byte.

4. **Exact match requires the repeated lookup.**  
   Given request 10, count 3, and an initial output of 10, the function performs another lookup at index 3. If that second output is 10, it returns zero without direct state-object writes or a final-operation call.

5. **Position after a lower value.**  
   Given request 15, count 3, initial output 30, and search outputs 30 at index 3, 20 at index 2, and 10 at index 1, the selected position is 2. The final dependency receives request 15 and position 2.

6. **Request exceeds the initial output.**  
   Given request 40 and initial output 30, the search is skipped. The selected position remains zero; the function does not independently choose count plus one.

7. **Ignored search failure.**  
   Given request 15 and an initial successful output of 20, suppose a search call returns zero without changing that output. The function still compares 20 against 15 and continues according to the index transition. It does not return −50 because of that later zero return.

8. **Final-operation failure preserves the clears.**  
   If the final dependency returns 9, the function returns 9. Its direct writes are the preceding clears of offsets 44 and 58; it does not perform the success counter increment or success stores.

9. **Signed position boundary.**  
   Under the described signed-16-bit narrowing, if the search finds a lower value at index 32,767, the selected position passed to the final dependency is −32,768, not positive 32,768.
