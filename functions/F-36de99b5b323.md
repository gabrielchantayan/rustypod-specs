### 1. Entry store and initial calls

Only after that store does the function invoke:

1. F-000000000001, with the explicit 32-bit input.
2. F-000000000002, with no explicit arguments.
3. F-000000000003, with no explicit arguments.
4. F-000000000004, with no explicit arguments.
5. F-000000000005, with no explicit arguments.

The fifth call produces a result represented as 64 bits. Its low and high 32-bit halves have different roles:

- The low half is converted to a signed 32-bit value and shifted left by two to produce the **scaled payload**.
- The high half is converted to a signed 32-bit value and used as the **first word index**.

The scaled payload is stored as 32 bits at an address formed by multiplying the first word index by four and adding `0x14`.

The global base slot is then read. This read occurs **after** the first indexed word store and **before** the sixth dependency call. The resulting base is retained for a later read; the global slot is not explicitly reread.

### 2. Second indexed store and word snapshot

The function invokes F-000000000006 with four explicit arguments, in this order:

1. scaled payload;
2. first word index;
3. scaled payload;
4. scaled payload.

It then invokes F-000000000007, F-000000000008, and F-000000000009, each without explicit arguments.

F-000000000010 is invoked next, also without explicit arguments. Its result is treated as a signed 32-bit **second word index**.

The function stores the same scaled payload at the second word index multiplied by four, plus `0x14`.

It then performs a 32-bit read from the previously retained global base plus `0x14`. The value read becomes the **word snapshot** used for both later byte writes.

This ordering is significant:

- Calls between the global-base read and the word read can affect the memory eventually read.
- A dependency changing the global base slot does not, by itself, change the already retained base.
- The second indexed store occurs before the word snapshot is read, so aliasing can make that store determine the snapshot.
- Subsequent changes to the source word do not explicitly refresh the retained snapshot.

### 3. Second two-word result and first byte write

F-000000000011 receives one argument: the second word index multiplied by four, without the additional `0x14`.

The function then invokes F-000000000012, F-000000000013, F-000000000014, and F-000000000015, with no explicit arguments.

F-000000000015 supplies another result represented as 64 bits:

- Its low 32 bits become the **address-selection word**, treated as unsigned.
- Its high 32 bits become an opaque **forwarded word**.

After that call returns, the function reads an unsigned byte at the entry byte-source base plus one. It adds `0x11` to that byte value and writes the low eight bits of the word snapshot to the resulting address.

Thus this byte-write destination lies from `0x11` through `0x110`, inclusive, under ordinary nonwrapping address arithmetic. It is selected by a byte value, not by treating that byte as an offset from the entry byte-source base.

F-000000000016 is then called with four arguments:

1. forwarded word;
2. forwarded word;
3. forwarded word;
4. address-selection word shifted left by two.

The fourth argument is an unsigned 32-bit shift. Its upper two input bits are discarded.

### 4. Forwarded result and second byte write

F-000000000017 is called without explicit arguments. Its 32-bit result is passed directly to F-000000000018.

The function next invokes F-000000000019, F-000000000020, F-000000000021, and F-000000000022, each without explicit arguments. The last of these supplies a signed 32-bit result used after the next byte write.

The second byte-write destination is selected in two stages:

1. Mask the address-selection word to retain its low 30 bits, shift right by 21, and add one. This selects a byte-read address from `1` through `512`.
2. Read an unsigned byte there and add `0x11`. This selects a byte-write address from `0x11` through `0x110`.

These examples are conditional static acceptance criteria, not executed tests. They assume required calls return and required accesses are valid.

### Snapshot timing

Suppose the retained global base identifies a word initially containing one value, but an intervening dependency changes that word before the snapshot read. The snapshot must reflect the value at the later read, not at the earlier global-base read.

If a dependency changes only the global base slot, subsequent reading still uses the previously retained base.

If the first selector byte is `0x20`, the first byte-write destination is `0x31`. That destination is independent of the entry byte-source base once the selector byte has been read.
