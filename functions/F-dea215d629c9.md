# F-dea215d629c9

## Purpose

F-dea215d629c9 conditionally invokes two dependencies, then processes a linked structure through repeated head reads, head overwrites, and two dependency calls per selected node. It returns a 64-bit value containing the object’s 32-bit address representation in the lower half and a selected 32-bit value in the upper half.

The first read of the object’s field at byte offset 16 selects the path:

- **Zero:** no dependency calls or head accesses occur. The second input supplies the upper result half.
- **Nonzero:** three writable local slots are prepared, F-dd2bd4d58d3f and F-ed8a42419d63 are invoked in that order, and linked-structure processing begins. The upper result half is sampled from one of the exposed local slots during the terminating head check.

Each processing iteration overwrites the object’s head with the selected node’s successor before making either per-node call. This operation does **not** unconditionally remove the selected node from the head position: a self-linked node supplies its own address as the successor. Aliasing can also make the head overwrite change the node fields subsequently read as call arguments.

Cleanup or disposal is a plausible intent, not an established ownership contract.

The supplied representation uses 32-bit field values and address representations. The second input is represented as a 32-bit integer, but no signed comparison or arithmetic is performed on it. Its bit pattern is preserved when selected for the result.

### Output

The function returns a 64-bit concatenation:

| Result bits | Contents |
|---|---|
| 31–0 | Object argument’s 32-bit address representation |
| 63–32 | Selected 32-bit upper result |

The operation concatenates bit patterns; it does not numerically add the inputs. A high bit in the upper value does not alter the lower half.

On the zero path, the selected upper value is the second input.

On the nonzero path, the selected upper value is sampled from the exposed result slot during the loop condition that observes a zero head. Before returning, the function writes the selected upper value back into that local slot and constructs the result. There are no subsequent dependency calls.

## Behavior

### Initial capture and zero path

The first visible object access reads the 32-bit field at offset 16 into the result slot. The function also selects the second input as the provisional upper result.

If the captured field value is zero, the function skips all conditional work:

- No second or third offset-16 read occurs.
- No associated storage is accessed.
- The head is neither read nor written.
- No dependency is called.

The fallback value is written into the result slot before return. The returned lower half remains the object argument’s address representation.

An invalid or populated head does not affect this path because the head is not inspected.

### Nonzero-path preparation

A nonzero first capture selects the longer path.

The function reads the object’s offset-16 field again. This second value, not the first capture, supplies the address for a 32-bit read at byte displacement 8. The value obtained initializes the associated-value slot.

The second address is not checked for zero. If the first read is nonzero and the second is zero, the function still attempts the displacement-8 access through the second value. It does not return to the zero path or substitute the first capture.

Next, the function initializes the fourth-input slot from the fourth input. It then invokes F-dd2bd4d58d3f with:

1. Address of the fourth-input slot.
2. Object address.
3. Address of the associated-value slot.
4. Address of the result slot.

The dependency receives three distinct writable local addresses. Their initial values come from different sources even when their bit patterns happen to match.

Copying a source field into a local slot does not make the two storage locations identical. A dependency write through a local-slot address does not, by that fact alone, write the original source field. The object argument separately exposes object state to the dependency.

### Second dependency call

After F-dd2bd4d58d3f returns normally, the function reads the object’s offset-16 field a third time and invokes F-ed8a42419d63 with:

1. Object address.
2. Value obtained by that third read.
3. A 32-bit zero.

The second argument is not taken from either earlier capture or from the exposed result slot.

The initial branch is not reconsidered. If F-dd2bd4d58d3f clears offset 16, the second dependency is still called, with zero as its second argument.

The return values of both setup dependencies are ignored.

### Head selection and result sampling

Head processing begins only after F-ed8a42419d63 returns. No earlier head read is visible.

Each loop condition performs the following ordered observations:

1. Read the object’s head.
2. Sample the result slot into the selected upper result.
3. Determine whether the selected head is zero.

A zero head terminates processing. The result-slot sample from that same condition supplies the upper return half.

A nonzero head selects a node for the following iteration. The selected address is retained for that iteration’s node accesses and second per-node call.

### Per-node operations

For each selected node, the function:

- Reads the node’s successor at offset 0.
- Writes that successor into the object’s head.
- Reads the selected node’s offset-8 and offset-4 fields as arguments to F-ff1bdc376dcd.
- Calls F-ff1bdc376dcd with those values, in that positional order, followed by zero.
- Calls F-ff1bdc376dcd again with the selected node address, one, and zero.
- Returns to a fresh head check.

The head overwrite precedes both argument-field reads and both calls. The relative order of the offset-4 and offset-8 reads is not established by the supplied representation.

Consequently, the first per-node call receives the node field values **at their actual read times after the head overwrite**, not necessarily their values when the node was selected. If either field aliases the object’s head, the overwrite can change its value without any dependency mutation.

The overwrite establishes only that the head receives the successor read from the node. It does not establish that:

- The new head differs from the selected node.
- The selected node becomes unreachable.
- The remaining structure is shorter.
- The iteration makes progress toward termination.

For a self-linked node, the head is written with the selected node’s own address. A later dependency can nevertheless change the head and allow termination.

The second per-node call receives the originally selected node address even if the first call changes the head. No further direct field read from that node occurs between the two calls or after the first call within that iteration.

The next iteration selects its node from a new object-head read. It does not continue using a privately retained successor. Dependency-driven replacement, clearing, or reinsertion of the head therefore affects subsequent processing.

### Completion and arithmetic

On the nonzero path, the result slot initially contains the first offset-16 capture. F-dd2bd4d58d3f can change it through its fourth argument. Later changes are not excluded because the supplied evidence does not establish that exposed addresses are forgotten or unreachable by later dependencies.

The terminating condition samples the slot, and the final local write restores that selected sample to the result slot before concatenation.

No count increment, size calculation, or signed ordering operation is visible. Field displacements are byte offsets. Address validity and behavior outside the valid target address space are not established; no overflow check is visible.

## Side effects

### Direct effects

On the zero path, the only object access is the initial offset-16 read. Local state is initialized and the selected fallback is written to the result slot before return.

On the nonzero path, direct effects include:

- Three separate offset-16 reads, with the third occurring after F-dd2bd4d58d3f.
- One associated-storage read through the second offset-16 value.
- Initialization and exposure of three writable local slots.
- The two setup dependency calls.
- A head read and result-slot sample at each loop condition.
- A successor read and head overwrite for each selected node.
- Node argument-field reads after each head overwrite.
- Two F-ff1bdc376dcd calls per selected node.
- A final write of the selected upper result into the result slot.

The function does not directly target offset 16 for a write or explicitly clear node fields. However, a head write can also change other named fields when their storage overlaps the head. Statements about write destinations therefore do not imply non-aliasing.

For valid, finite, acyclic storage with no mutations other than this function’s head advances, processing eventually observes a zero head. Without those conditions, termination is not guaranteed.

## Acceptance examples

These examples are conditional consequences of static evidence, not executed tests. Continuation beyond an access or call assumes that operation completes normally.

1. **Zero gate with an arbitrary head.**  
   If the first offset-16 read is zero and the second input is `0x89ABCDEF`, the upper return half is `0x89ABCDEF`. No head access, associated-storage access, or dependency call occurs.

2. **Different first and second captures.**  
   If the first offset-16 read yields nonzero address A and the second yields B, the associated-value slot is initialized from B at displacement 8. The result slot initially contains A. Readability at A plus 8 does not satisfy the access requirement at B plus 8.

3. **Second capture becomes zero.**  
   A nonzero first capture followed by a zero second capture still leads to the attempted displacement-8 access through zero. There is no fallback branch. No particular fault outcome is asserted.

4. **Result slot and object field diverge.**  
   If F-dd2bd4d58d3f writes `0x11223344` through its fourth argument and writes `0x55667788` to the object’s offset-16 field, the third field read supplies `0x55667788` to F-ed8a42419d63, absent intervening mutation. If the result slot remains unchanged through the terminating sample, the upper return half is `0x11223344`.

5. **First dependency clears the object field.**  
   If F-dd2bd4d58d3f clears offset 16, F-ed8a42419d63 is still called with zero as its second argument. Head processing follows if that call returns normally.

6. **Empty head after setup.**  
   If the first head check observes zero, no per-node calls occur. The result-slot value sampled immediately after that head read supplies the upper return half.

7. **One disjoint node.**  
   Assume the object and selected node occupy disjoint storage, the node’s successor is zero, its offset-4 value is 7, its offset-8 value is `0x12340000`, and no dependency or external action mutates those fields before their reads. The head is overwritten with zero. The per-node calls receive respectively (`0x12340000`, 7, 0) and (selected node address, 1, 0).

8. **Head overwrite aliases a node argument field.**  
   Suppose the selected node is at `0x12340000` and the object is at `0x12340008`. The node’s offset-8 field is therefore the object’s head and initially contains `0x12340000`. Let the node’s successor be zero and its offset-4 field contain 7. The head overwrite changes the node’s offset-8 field to zero before it is read. Without any intervening mutation, the first per-node call receives (0, 7, 0), and the second receives (`0x12340000`, 1, 0).

9. **Self-linked node with dependency-assisted termination.**  
   If the selected node’s successor is its own address, the head overwrite leaves that node as head. If a per-node dependency subsequently clears the head and no later mutation reverses that change, the next condition observes zero and processing terminates. Without such a change, repeatedly observing the same self-link need not terminate.

10. **Head replacement during the first per-node call.**  
    If that call replaces the head with another valid node, the second call still receives the originally selected node address. The next condition reads the replacement head.

11. **High-bit upper result.**  
    A selected upper value of `0xFFFFFFFF` occupies bits 63–32 exactly. The lower half remains the object argument’s 32-bit address representation.
