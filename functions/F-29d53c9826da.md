# F-29d53c9826da

## Purpose

The low bit of a flags argument selects the padding side:

- Bit clear: spaces precede the string.

The function does not return a byte count or an error indication. Its directly established output consists of calls to F-bcb8529decd8. Whether those calls write a buffer, update a stream, or perform another operation is unknown.

The supplied representation establishes byte-oriented processing, not character-aware formatting. String length, field width, padding, and the emission limit are measured in individual nonzero byte elements. No encoding validation, multibyte decoding, or display-column calculation is present.

## Behavior

### Source selection and complete length scan

The function selects the caller’s source address unless it is null, in which case it selects the fixed fallback.

It then scans the selected string from its first byte to the first zero byte. No emission occurs during this scan. The initial length is the number of nonzero byte elements preceding that zero.

This scan occurs before padding calculation and before any emission-limit check. Even if the limit is zero or negative, the selected string must still be scanned.

The scan index is represented as a signed 32-bit integer. Behavior when that index cannot represent the string length is not established. A supported, well-defined use must keep the terminating scan within representable indexing arithmetic and valid storage.

### Padding calculation

The initial padding demand is the requested field width minus the scanned string length. A negative result is replaced with zero.

For representable arithmetic, this means:

- Width greater than string length requests the difference in spaces.
- Width equal to or below string length requests no spaces.
- A negative width requests no spaces, provided the subtraction itself remains representable.

The low flags bit then determines the side of the padding. With that bit clear, the demand remains positive and is used before the string. With that bit set, the demand is negated and is used after the string.

Only the low bit is tested. Other flag bits have no direct effect in the supplied body.

The subtraction precedes the negative-result clamp. An extreme negative width can therefore make the subtraction unrepresentable even though a mathematical “maximum with zero” would produce zero. The supplied evidence does not establish overflow behavior; wrapping, saturation, and rejection must not be assumed.

For representable subtraction and a representable nonnegative length, the clamped padding demand is between zero and the largest signed 32-bit value. Negating that range is representable.

### Leading-space phase

If padding is positive, the function emits space values while both conditions hold:

- Leading padding remains.
- The number of emission calls already made is less than the signed limit.

Each iteration makes one dependency call with value 32, reduces the remaining positive padding by one, and increments the emission count by one.

Leading spaces consume the same emission allowance as string bytes. A limit smaller than the requested leading padding can therefore prevent every string byte from being emitted.

If the dependency returns normally, its return value is ignored. There is no visible error check, retry, or rollback.

### String phase

After the leading-space phase, the function traverses the selected string again from its beginning. It does not emit from a saved copy and does not use the initially scanned length as a fixed traversal bound.

Before each possible string emission, the function:

- Reads the current source byte to test whether it is zero.
- If it is nonzero, checks whether the emission count is below the limit.

The source-byte test precedes the limit check. Thus, reaching this phase can read the current source byte even when no emission allowance remains.

When both tests permit emission, the source byte is read for the dependency argument, one dependency call is made, the emission count increases by one, and the source address advances by one byte.

A zero byte is a terminator and is never passed as a string emission by this body. For an unchanged source, traversal stops at its first terminator or when the emission limit prevents another call.

The initial scan and this second traversal serve different purposes:

- The initial scan determines padding.
- The second traversal determines the string values actually supplied to the dependency.

If intervening dependency activity changes the source, the emitted bytes and termination point may differ from those used to compute padding. The function does not recompute the padding demand.

### Trailing-space phase

If padding is negative, the function emits space values after the string phase while both conditions hold:

- Negative padding remains.
- The emission count is below the signed limit.

Each iteration emits value 32, moves the remaining padding one step toward zero, and increments the emission count.

If the string exhausts the limit, no trailing spaces are emitted. If the string remains stable and ends before the limit, trailing spaces fill the available allowance up to the originally computed padding amount.

### Stable-input result

Under valid, representable arithmetic, normal dependency returns, and an unchanged readable source, the behavior can be summarized as follows:

- Construct the conceptual sequence of string bytes and requested padding, placing padding on the side selected by the low flags bit.
- If the limit is positive, emit at most that many values from the beginning of the sequence.
- If the limit is zero or negative, make no emission calls.

This summary describes emitted values only. It does not remove the complete initial scan or the source read performed before the string-phase limit check.

For a stable source, the full conceptual sequence has a length equal to the greater of the string length and requested field width. A width smaller than the string length does not truncate the string; only the emission limit truncates output.
