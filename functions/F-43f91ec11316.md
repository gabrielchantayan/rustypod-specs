# F-43f91ec11316

## Purpose

F-43f91ec11316 attempts an ordered sequence of unresolved indirect calls, transforms represented result channels, and then performs mixed-width memory mutations through computed and small absolute addresses. A final unresolved indirect transfer receives four explicit arguments.

No application-level purpose is established. Recurring offsets, self-references, and constants resembling characters do not establish object initialization, container management, text output, or a protocol.

This contract distinguishes:

- **Established static evidence:** represented operations, widths, data dependencies, and access order.
- **[INFERENCE]:** interpretations not established by those operations.
- **documented_only:** behavior left unresolved rather than assigned an unsupported guarantee.

All progress descriptions are conditional on preceding calls and accesses completing normally. No runtime tests have been performed.

## Behavior

### Ordered indirect-call phase

The opening phase is a long straight-line sequence of indirect calls without a visible conditional branch or loop. After the entry-state-derived target, targets are formed from embedded code-location values plus 0xFFE.

The initial call receives the first input and the transformed fourth input. Two calls follow; the latter supplies a represented 64-bit result. Its low 32-bit portion is shifted left by eight for a later call. Its high portion supplies further shifted arguments.

The remaining call phase repeatedly uses:

- Low 32-bit result portions shifted left by eight.
- Unchanged or shifted high 32-bit portions.
- Values duplicated across argument positions.
- Explicit zero arguments.
- Masked unsigned fields followed by shifts.
- Secondary machine-result channels whose dependency contracts are unavailable.

Calls with no displayed arguments or unused displayed results remain attempted calls, not established no-ops. Dependencies can change shared state, fail to return, fault, or transfer control elsewhere.

The represented 64-bit containers do not independently establish application-level 64-bit return values. Their correspondence to machine result channels is **documented_only**. This contract does not supply a complete call-by-call trace or resolve every secondary result channel.

### Widths and arithmetic

Most intermediates are represented as 32 bits; some call results occupy 64-bit containers. Byte, halfword, and word accesses use eight, 16, and 32 bits respectively. Narrow stores retain the corresponding low bits. Unsigned byte values stored as words are zero-extended.

Masks select fields of several widths, including one bit and widths from 11 through 22 bits, plus 24 bits. These are value-field widths, not storage extents.

Under a **conditional 32-bit machine-bitvector interpretation**:

- A left shift by 25 retains only the original low seven bits.
- Shifting that already narrowed result left by seven yields zero.
- Multiplication by 0x02000000 has the same low-32-bit result as a left shift by 25.
- A left shift by 16 produces a zero low halfword.
- Byte narrowing retains the low eight bits.
- Unsigned extraction from a 64-bit container by right shifts of 34, 36, and 44 yields at most 30, 28, and 20 bits respectively.

The extraction counts are 34, 36, and 44. Some extractions use a previously captured result rather than the most recent call result.

These deductions do not establish portable signed-overflow or signed-shift semantics. Signed multiplication, successive shifts, address scaling, additions, subtractions, and variable shifts require target semantics before executable equivalence can be claimed. No saturation or checked arithmetic is visible.

### Initial direct-memory effects

The following names describe captured values, not object types:

- **Scaled base:** an earlier call result multiplied by 0x02000000.
- **Packed base:** another result shifted left by 25.
- **Narrow-derived base:** twice the field obtained by masking a shifted result with 0x7FFF and shifting right by six.
- **Final result pair:** the low and high 32-bit portions from the last call before direct mutation.

The initial effects are ordered as follows: a word containing the packed base is stored at high-result offset 0x14; the high result’s low byte is stored at packed-base offset 9; the scaled base is stored as a word at offset 0x54 from 256 times the low result; and the packed base’s low byte is stored again at packed-base offset 9.

The next region clears scaled-base offset 0x14, reads an unsigned byte at scaled-base offset 5, and clears narrow-derived-base offset 0x14. It stores the zero-extended byte at scaled-base offset 0x34, then reads the word at scaled-base offset 0x14. Another clear at narrow-derived-base offset 0x14 precedes two consecutive byte stores at its offset 0x15, both using the read-back word’s low byte.

That read-back remains an actual observation. It is not unconditionally zero: preceding computed accesses can alias, and memory observation semantics are unresolved.

### Cross-linked memory effects

Loaded words and bytes subsequently supply more addresses. Recurring word offsets include 4, 0x14, 0x24, 0x34, 0x44, 0x54, 0x64, and 0x74. Byte accesses include offsets 1, 5, 9, 0x0D, 0x11, and 0x15. Established relationships include:

- A value-derived byte is written at scaled-base offset 0x11 and later replaced by an explicit zero. The earlier byte need not be nonzero.
- A word at an offset-0x54 location is captured before that location is overwritten.
- Offset-0x74 loads supply bases for later offset-0x54 writes.

- An address-derived low byte is stored at absolute address 0x15.

Repeated expressions containing loads do not establish that only one read occurs. Repeated addresses do not establish unchanged contents.

A later word loaded through a byte-derived address supplies the **link value**. The function represents three separate stores of numeric value 0x3A, in this order:

| Order | Width | Destination |
|---|---:|---|
| First | 8 bits | Four times the link value. |

In particular, a zero link value makes the byte and halfword destination addresses both zero. Other link values or address-arithmetic behavior can also produce overlap. No non-aliasing precondition is established.

A subsequent computed word destination receives 0x20, then 0x2F, then a zero-extended byte read at offset 4 of its computed base, then 0x20 again. That byte read occurs after the first two stores.

### Captured global base and repeated writes

The earlier saved word determines a fourfold value. Subtracting 0x96 produces the **reduced value**; four times the reduced value is the **repeated-region base**. Four times the captured link value is the **linked base**, and twice that link value is the **doubled-link base**.

After the final computed 0x20 word store described above, the function captures a global word supplying another base. Only afterward does it store the word 0x20 at absolute address 0x60.

Repeated-region accesses use the captured global-supplied base, not a reload after the 0x60 store. This distinction holds even if that store overlaps the global word.

## Side effects

### Unsigned byte expansion

If scaled-base offset 5 yields byte 0xE7, the subsequent word store at scaled-base offset 0x34 receives 0x000000E7, not a sign-extended value.

### Aliasing stores of 0x3A

If the captured link value is zero and low-address accesses are valid, the ordered stores are:

- An eight-bit store of 0x3A at address 0.
- A 16-bit store of 0x003A at address 0.
- A 32-bit store of 0x0000003A at address 0x20.

The first two destinations coincide. Acceptance must not require three distinct addresses or discard the first store because a wider store follows.

If the link value is eight under ordinary nonwrapping arithmetic, the byte destination is 0x20, while both the halfword and word destinations start at 0x40. Their different widths remain significant.

Neither example fixes byte order or guarantees that such link values are reachable in a real invocation.

### Captured global base

If the global-base read captures an address and the following absolute-0x60 store changes its source storage, repeated accesses still use the captured address. Reloading afterward is not equivalent.

### Reads after the 0x3A write

If the absolute-0x3A byte store overlaps either subsequent computed word read, acceptance uses the word observed after that write, not an earlier snapshot.

### Three reads at 0x67
