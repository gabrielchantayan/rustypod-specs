# F-5ef10d079522

## Purpose

F-5ef10d079522 conditionally selects a one-based entry from a context, obtains a signed transfer amount bounded by a caller-supplied limit, and optionally invokes a transfer-like dependency. It returns a 32-bit status and can report a 32-bit amount through an optional output pointer.

The established behavior is the validation, selection, dependency-call sequence, and memory access pattern described below. Interpreting the operation as “copy entry data into a caller buffer” is inferred intent: the implementation of the transfer dependency is not provided, so its direction, effects, and handling of unusual amounts remain unknown.

A significant exceptional case exists: if the entry-check dependency rejects an entry, the function returns an error but can still write an amount that was never initialized by this function.

## Interface

### Inputs

The function has five arguments:

| Argument | Representation | Established use |
|---|---|---|
| Context | 32-bit address-valued argument | Passed to three dependencies and used as the base of fixed-offset memory accesses. |
| Selection | Signed 32-bit integer | Zero has a special successful-return path. Positive values select entries using one-based indexing. |
| Transfer target | 32-bit address-valued argument | If nonzero, passed as the second argument to F-70a021fc7c24. A zero value suppresses that call. |
| Amount output | Optional pointer to a 32-bit integer | If nonnull, receives zero immediately on entry and, on the entry-processing path, receives a later amount value. |
| Amount limit | Signed 32-bit integer | Compared with the selected entry’s signed amount; the smaller signed value is selected. |

No optionality is established for the context or for pointers reached through it. A nonzero transfer target is not validated locally.

### Return value

The return value is a 32-bit word:

- `0x00000000`: the context dependency accepted the context and either the selection was zero or entry checking succeeded.
- `0xFFFFFFCE`: the context dependency rejected the context, the selection was outside the permitted range, or entry checking failed.

Interpreted as a signed 32-bit integer, `0xFFFFFFCE` is −50. No specific symbolic error name is established.

The function does not inspect the return value of the transfer dependency. A zero result therefore does not independently establish that a requested transfer completed successfully.

### Context and entry layout

Only the following locations are established:

| Location | Accessed representation | Meaning established by use |
|---|---|---|
| Context byte offset `0x08` | 32-bit pointer to a location containing another 32-bit pointer | Indirection used to obtain the entry-table base. |
| Context byte offset `0x10` | 32-bit pointer to a location containing another 32-bit pointer | Indirection used to obtain the data base for the transfer call. |

This layout does not establish the full size of the context, ownership of either pointer-indirection object, the size of the table, or the size of the data region.

## Behavior

### Initial output write and context check

If the amount-output pointer is nonnull, the function first writes a 32-bit zero through it. This precedes every dependency call and every explicit context-field read performed by this function.

The function then invokes F-0aff6a5050f5 with the context.

- A zero result causes immediate return of `0xFFFFFFCE`.
- A nonzero result permits selection handling.

There is no local null-context check before this call. Whether a null context is rejected safely depends on F-0aff6a5050f5.

The initial output write is not rolled back. If that output aliases context storage or other input storage, the write can affect subsequent behavior.

### Selection handling

Once the context-check result is nonzero:

1. A selection of zero returns zero immediately.
2. A negative selection returns `0xFFFFFFCE`.
3. A positive selection is compared against the signed 32-bit value read from context offset `0x1C`.
4. A positive selection greater than that value returns `0xFFFFFFCE`.
5. A positive selection no greater than that value enters entry processing.

Selection zero does not cause the count field to be read. Negative selections also fail without reading that field.

A nonpositive count admits no positive selection. Selection zero nevertheless succeeds if context checking succeeds, regardless of the count.

On these early-return paths, this function makes no later amount-output write. The initial zero is not necessarily the final observed value: the context-check dependency can have unknown effects, including effects on aliased or otherwise accessible storage.

### Entry processing

For an accepted positive selection, the function invokes F-efaaaab570a3 with the context. Its return value is ignored.

Only after that call returns does the function obtain the entry-table base through the indirection rooted at context offset `0x08`. Consequently, the table used is the one visible after that dependency returns, not necessarily the one present during the earlier selection check.

The selected entry is located at the table base plus eight times the selection, minus eight bytes. The function passes the selected entry’s address to F-88337f8f5d95.

The table count is not checked again after F-efaaaab570a3. No local operation establishes that the table still contains as many entries as the count previously indicated.

### Entry-check failure

If F-88337f8f5d95 returns zero:

- The result becomes `0xFFFFFFCE`.
- The successful-path entry-amount read and transfer call are skipped.
- F-2a517f9b9ef3 is invoked with the context.
- If the amount-output pointer is nonnull, a final 32-bit write is performed through it.
- The error result is returned.

The value used for that final output write has not been initialized on this path in the supplied representation. It is shown as surviving register state rather than a defined amount.

Accordingly, the failure contract does **not** promise zero, the entry amount, the amount limit, or any other deterministic output value. The final write can overwrite the initial zero. Its precise value is `documented_only` pending additional evidence.

### Entry-check success

If F-88337f8f5d95 returns nonzero, the function reads the signed 32-bit amount at selected-entry offset `4`.

This read occurs after entry checking. If that dependency changes the entry, the amount read reflects the resulting storage.

The selected amount is the signed minimum of:

- the entry amount; and
- the caller’s amount limit.

This is not a nonnegative clamp. Negative values remain negative, and neither input is rejected merely for being negative.

If the transfer target is zero, the transfer call is skipped. The selected amount is still retained for the later output write.

If the transfer target is nonzero, F-70a021fc7c24 is invoked with:

1. The address formed by adding the selected entry’s first 32-bit word to the data base obtained through context offset `0x10`.
2. The transfer target.
3. The selected 32-bit amount.

The selected entry’s first word and the data-base indirection are used after successful entry checking. Their relative read order within construction of the first argument is not established by the supplied expression.

A selected amount of zero does not suppress the transfer call. A negative selected amount also does not suppress it. How the dependency interprets those bit patterns is unknown.

After the optional transfer call returns, the function invokes F-2a517f9b9ef3 with the context. Its return value is ignored.

If the amount-output pointer is nonnull, the function then writes the selected amount through it. The function returns zero.

## Acceptance examples

These examples are conditional static expectations, not runtime test results. Unless stated otherwise, memory is valid, dependencies return normally, and they do not change the relevant storage.

1. **Rejected context.**  
   With a nonnull amount-output pointer, the function writes zero, calls F-0aff6a5050f5, and receives zero. It returns `0xFFFFFFCE`; no other dependency is called.

2. **Zero selection.**  
   If context checking succeeds and selection is zero, the function returns zero. It does not read the count, look up an entry, or call the four later dependencies.

3. **Invalid selection bounds.**  
   With a count of 3, selection −1 fails without a count read, while selection 4 fails after reading the count. Both return `0xFFFFFFCE` and skip entry processing.

4. **Ordinary bounded amount.**  
   With selection 2, a count of at least 2, an entry amount of 100, and an amount limit of 40, successful entry checking selects amount 40. The selected entry is eight bytes after the table base. For a nonzero target, F-70a021fc7c24 receives the constructed data address, that target, and amount 40. F-2a517f9b9ef3 precedes the final output write of 40. The result is zero.

5. **Null transfer target.**  
   With entry amount 12 and amount limit 50, successful entry checking selects 12. A zero transfer target suppresses only F-70a021fc7c24. Finalization still occurs, the optional amount output receives 12, and the result is zero.

6. **Zero and negative amounts.**  
   An entry amount of 12 with limit 0 selects 0. The same entry with limit −3 selects −3. With a nonzero target, both cases invoke the transfer dependency using the selected 32-bit value. This does not establish that the dependency safely accepts either value.

7. **Rejected entry with output enabled.**  
   After accepted context and selection checks, entry checking returns zero. The transfer is skipped, finalization occurs, and the result is `0xFFFFFFCE`. The amount-output location receives a final value that is not defined by the supplied function body; requiring it to remain zero would contradict the visible path.

8. **Post-preparation table state.**
