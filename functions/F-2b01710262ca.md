### Numerical result contract

The final dependency’s unsigned result is transformed before conversion to the signed function result.

For a supported selected position, let its positional weight be the corresponding power of two. The transformation has the following externally distinguishable properties:

- Changing only the selected bit of the final dependency result does not change the unsigned numerical result.
- Contributions strictly above the selected position remain unchanged.
- The numerical contribution strictly below the selected position is increased by one less than the positional weight.
- That increase can carry into the selected output position.

A range-based description avoids treating the transformation as a requirement to clear or fill individual output bits:

1. Partition the unsigned input range into consecutive blocks whose size is twice the positional weight.
2. Within each block, corresponding positions in its lower and upper halves produce the same result.
3. As the position within either half increases, the result increases by the same amount.
4. A block’s possible results run from its starting value plus one less than the positional weight through its starting value plus twice the positional weight minus two.

This is a mathematical characterization of input/output behavior, not a required implementation procedure.

Equivalently, when the selected input bit is absent, the unsigned result exceeds the final dependency result by one less than the positional weight. When that bit is present, the unsigned result is one less than the final dependency result. The selected **output** bit is not required to be clear.

At position zero, the behavior reduces to rounding the final dependency result downward to an even number. That description is insufficient for higher positions.
