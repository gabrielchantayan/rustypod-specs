# F-865078615961

## Purpose

F-865078615961 prepares and submits an operation through one of two paths:

- **Direct path:** forwards a selector and a 32-bit value to a submission dependency without constructing a record.
- **Record path:** allocates a record containing a 28-byte header, a reference to caller-supplied data, and a trailing region passed to a copy-like external dependency; then submits the record through its pointer.

A zero submission result ends processing. A nonzero submission result triggers an additional context lookup and notification call.

This is a static behavioral contract. It describes observable operations in the supplied representation, not a validated application-level interpretation. In particular, the meanings of the selector, header constants, submission result, and notification are not established.

## Behavior

The captured value is retained across intervening calls and supplied to the submission dependency. It is not visibly reloaded immediately before submission.

An internal pointer holder is initially set to A4. In the record path it is replaced with the allocator result. The direct path does not submit the address of this holder.

### Direct path: A6 equals zero

2. Calls F-c5a232e4455b with that value and the constant 12.
3. Calls F-afb630a7107c with six explicit arguments:

The direct-path static value is used when preparing the submission call, after the preceding dependency calls. Its value must not be assumed identical to an entry-time value if those dependencies can modify the corresponding storage.

No allocation, explicit deallocation, header construction, or external copy-like call occurs in the direct path. A4, A5, and A7 do not affect any explicit operation in that path.

## Side effects

### Memory

The record path explicitly allocates storage and writes a 28-byte header. It passes the trailing address to another dependency, which may modify that region according to its own contract.

A4 is retained as a pointer value in the header. The supplied function neither duplicates the referenced data nor explicitly releases it. No ownership transfer of A4 can be established from this body.

The direct path performs no explicit caller-memory access.

### Allocation lifetime

The visible lifetime rules are:

- Null allocation: invoke the represented nonreturning failure dependency.
- Zero record-submission result: explicitly invoke F-5e3309c9d083 on the current pointer-holder value.
- Nonzero record-submission result: no explicit release by this function.

The absence of an explicit release after nonzero submission does not establish who owns the allocation. F-afb630a7107c, the completion dependencies, or another component may retain, consume, release, or otherwise affect it. Their behavior is undocumented here.

Likewise, the zero-result release cannot be assumed safe merely from its presence: whether submission already released storage or changed the pointer holder depends on the unknown submission contract.

### Static state and dependency effects

The body contains static-value reads but no explicit static-value writes. Called dependencies may have additional effects on memory, globals, synchronization, scheduling, or external state. No preservation guarantee is available.

The order of static-value capture matters:

- The submission descriptor is captured before branch-specific calls.
