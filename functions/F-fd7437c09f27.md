# F-fd7437c09f27

## Purpose

F-fd7437c09f27 conditionally performs two ordered, selector-driven operations that can write individual bytes into a caller-designated destination. It then invokes F-876f4b90d114 with the original first and second arguments and returns the 32-bit value 1, provided all preceding operations return normally.

The second argument enables or disables both conditional stages. Each enabled stage prepares an opaque value from working storage initialized from the third and fourth arguments, obtains a zero/nonzero decision, and performs a release-like call. A nonzero decision enables preparation of another opaque value from working storage initialized from the first and second arguments. A dependency supplies the byte written by that stage.

**Established behavior:** the possible direct writes target destination offsets 0xB0 and 0xB1, in that order. The function does not derive its return value from the decisions, written bytes, or final dependency result.

**Inferred intent:** these may be two independently selected destination properties. Neither their meanings nor the meaning of the prepared values is established.

**Status: documented_only.** This contract describes supplied static evidence. Dependency implementations, resource contracts, and runtime observations are unavailable.

## Interface

The function accepts four 32-bit arguments and returns a 32-bit value.

| Input | Established uses |
|---|---|
| First argument | Destination base for the two possible direct byte writes; initial value of one addressable working-storage location; first argument to F-876f4b90d114. |
| Second argument | Zero/nonzero enable condition; initial value of another addressable working-storage location; second argument to F-876f4b90d114. |
| Third argument | Initial value of working storage used in both stages’ check preparation. |
| Fourth argument | Initial value of separate working storage used in both stages’ check preparation. |

These uses do not establish higher-level argument types. In particular, the second argument is not proven to be a Boolean, length, pointer, or handle. Every nonzero 32-bit value enables processing; the condition is not a positive-value test.

### External state

Two global values are read:

- A selector-structure base, used to locate 32-bit selector fields at byte offsets 0x0C and 0x10.
- An opaque context, supplied to decision-making and byte-producing dependencies.

The selector-base global is read once at entry, even when processing is disabled. When processing is enabled, it is read separately again to obtain the first check’s selector. Those two base reads need not produce the same value.

After first check preparation, the context global is read into retained storage. It is then read separately for the first decision call. Later context arguments use the retained value rather than a fresh global read.

### Memory and width requirements

The working-storage locations, prepared-value results, selectors, and normal return value are 32 bits. The decision result is tested as a 32-bit zero/nonzero value. Each direct destination store is exactly one byte, consuming the byte-sized result exposed by F-cf946f91e683.

For any reached selector access, the corresponding base plus field offset must designate readable storage for a 32-bit selector. For each reached destination store:

- Offset 0xB0 must be writable for the first stage.
- Offset 0xB1 must be writable for the second stage.

These requirements apply independently. A skipped write does not require writable storage for that direct access, although dependency requirements remain unknown.

The address calculations belong to the supplied 32-bit address-oriented representation. The evidence does not define a portable overflow policy, signed-overflow behavior, pointer-provenance model, or alignment rule. Valid use therefore requires the reached base-plus-offset addresses to be meaningful and accessible under the actual execution environment. No wrapping-address fallback is established.

## Behavior

### Entry and working-storage lifetime

The function retains the selector-structure base read at entry. It also initializes four distinct, addressable 32-bit working-storage locations from the original arguments.

The working locations are used in two pairs:

- Check preparation supplies the fourth-argument working location first and the third-argument working location third.
- Update preparation supplies the second-argument working location first and the first-argument working location third.

The selector is the middle argument in each preparation call.

The same locations are reused throughout the invocation without visible reinitialization. Changes made through their addresses can therefore affect later preparations. For example, changes to the fourth-argument working location during the first stage can remain present during second-stage check preparation.

These working copies are distinct from the original arguments used by the function for its enable condition, destination address calculations, and final call. Mutation of a working copy does not itself redirect the function’s later explicit stores or replace its final arguments.

### Disabled processing

If the original second argument is zero, both stages are skipped.

On this path:

- The entry-time selector-base global read still occurs.
- No selector field is read by either stage.
- No context-global read is performed by the conditional processing.
- No preparation, decision, byte-producing, or release-like dependency is called.
- Neither direct destination-byte store occurs.
- F-876f4b90d114 receives the original first and second arguments.
- The function returns 1 if final processing returns normally.

This path does not guarantee an unchanged destination. F-876f4b90d114 has an unknown side-effect contract.

### First-stage check

With a nonzero original second argument, the first stage proceeds in this order:

1. It reads the selector-base global again and obtains the 32-bit selector at offset 0x0C through that newly read base.
2. It calls F-9b9c1c7483f4 with the fourth-argument working-storage address, that selector, and the third-argument working-storage address.
3. After preparation returns, it reads the context global and retains that value for subsequent context arguments.
4. It separately reads the context global for the first call to F-8094c3d72052, which also receives the preparation result.
5. It calls F-8a5aadac202f with the fourth-argument working-storage address.
6. It acts on the zero/nonzero decision returned by F-8094c3d72052.

The retained context and the context supplied to this first decision are separate observations. They ordinarily agree if the global remains unchanged, but equality is not established.

The release-like call occurs regardless of whether the decision is zero. The update decision is acted on only after that call returns. The decision is not recomputed afterward.

### First-stage optional update

A zero first decision skips the first update.

For a nonzero first decision:

- The function reads the selector at offset 0x0C through the **entry-time retained base**.
- F-9b9c1c7483f4 receives the second-argument working-storage address, that selector, and the first-argument working-storage address.
- F-cf946f91e683 receives the retained context and the new preparation result.
- The supplied byte is written at offset 0xB0 from the original first argument.
- F-8a5aadac202f receives the second-argument working-storage address.

The first check and its optional update need not use the same selector-structure base: the check uses the separately reread global base, while the update uses the entry-time base. Even if those bases agree, the selector field is read again and its contents may differ.

The byte is not normalized to zero or one. The destination store precedes the update’s release-like call.

### Second-stage check and optional update

The second stage runs after the first stage finishes, regardless of whether the first decision was zero or nonzero, assuming all preceding operations return normally.

Its check uses:

- The selector at offset 0x10 through the retained entry-time base.
- The same fourth- and third-argument working locations used for the first check.
- The context retained after first check preparation.

F-9b9c1c7483f4 prepares the check value. F-8094c3d72052 receives that result and the retained context. F-8a5aadac202f then receives the fourth-argument working-storage address, before the decision is acted upon.

A zero decision skips the second update. For a nonzero decision:

- The selector at offset 0x10 is read again through the retained entry-time base.
- F-9b9c1c7483f4 receives the second-argument working-storage address, that selector, and the first-argument working-storage address.
- F-cf946f91e683 receives the retained context and preparation result.
- Its byte result is written at offset 0xB1 from the original first argument.
- F-8a5aadac202f receives the second-argument working-storage address.

Neither stage reads the existing destination bytes to decide whether to update them.

### Completion and abnormal termination

After disabled processing or completion of both enabled stages, F-876f4b90d114 receives the original first and second arguments. Its result is unused. Normal completion then returns 1.

There is no visible validation failure result, rollback, or transaction boundary. A later failure to return normally can leave an earlier byte store already performed. The static evidence establishes neither exception handling nor guaranteed cleanup during abnormal control transfer.

## Side effects

The function’s explicit destination modifications are limited to the two conditional byte stores. Dependencies may perform additional modifications; preservation of other bytes is not guaranteed.

Observable ordering includes:

- Entry-time selector-base capture precedes the enabled-stage accesses.
- First check preparation precedes both context-global observations.
- Each decision call precedes its associated check release-like call.
- That release-like call precedes any corresponding update preparation.
- Each direct byte store precedes the corresponding update release-like call.
- First-stage processing precedes second-stage processing.
- Final processing follows all normally completed conditional work.

Global capture does not freeze the referenced structures. Later selector-field reads use current contents at the retained base. Conversely, replacing the selector-base global does not redirect those later reads.

After the first decision’s separate context-global read, the function does not refresh the context for subsequent calls. Dependencies may change the global without changing the already retained value. They may also mutate objects referenced by that value; retaining a value does not establish immutability of its referent.

No direct allocation, deallocation, synchronization, logging, or external I/O is established. Dependency effects remain unknown.

Working-storage addresses are exposed to dependencies. The release-like call receives the first working-storage address used for the corresponding preparation, not the preparation result. This pairing does not prove allocation ownership, destruction semantics, or pointer-retention permission. No separate explicit release-like call is shown for the other working location in each pair; this does not establish that it owns no resources.

## Acceptance examples

These are conditional static-contract examples, not executed tests. Except where otherwise stated, all reached accesses are valid and all invoked dependencies return normally.

### Disabled processing

With a zero second argument, the entry-time selector-base read occurs, but neither selector field is accessed by a stage. Only F-876f4b90d114 is invoked among the listed dependencies. It receives the original first argument and zero. The function returns 1.

An unchanged destination is not an acceptance requirement because final processing may modify it.

### Both decisions are zero

With processing enabled and both decisions zero, each stage performs preparation, decision, and its check release-like call. Neither update preparation nor byte-producing call occurs. Neither explicit destination store occurs. Final processing runs, followed by return value 1.

### Only the second decision is nonzero

The first stage performs no explicit destination store. The second stage writes its supplied byte at offset 0xB1 and then performs its update release-like call. There is no direct store at offset 0xB0.

### Both decisions are nonzero

The first supplied byte is stored at offset 0xB0 before second-stage preparation begins. The second supplied byte is stored at offset 0xB1 before final processing.

A decision with any nonzero 32-bit representation enables its update. A byte result of 0xA5 produces a store of 0xA5, not 1.

### Different selector-base observations

Suppose the entry-time selector-base read yields one valid structure, while the separate read for the first check yields another valid structure.

The first check obtains its offset-0x0C selector from the second structure. Its optional update obtains its selector from the entry-time structure. Both second-stage selector accesses also use the entry-time structure.

This example is conditional on differing observations being possible in the environment. It does not establish a synchronization model or a dependency call between the two base reads.

### Different context observations

Suppose the context capture after first check preparation observes one value, while the separate global read for the first decision observes another.

The first decision receives the latter value. The first optional byte-producing call, second decision, and second optional byte-producing call receive the retained former value.

No dependency call is shown between these two context reads; this example does not claim that a dependency directly causes their difference during that interval.

### Mutation and partial completion

If a dependency changes an offset-0x10 selector before a later access through the retained base, that later access uses the changed field contents.

If the first byte is stored and a later call fails to return normally, the function provides no established rollback or normal return value.
